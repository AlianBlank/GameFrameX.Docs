# How to Configure Ad Unit IDs (Multi-Platform)

The `AdvertisementComponent` has built-in ad unit ID fields for 6 platforms. At runtime, it automatically selects the corresponding ID based on the current build platform and writes it to `AdUnitId`, with no need for branching code.

## Prerequisites

- The `com.gameframex.unity.advertisement` package is installed.
- An `AdvertisementComponent` exists in the scene (added via the menu `GameFrameX/Advertisement`).
- A concrete ad manager that implements `IAdvertisementManager` has been selected (specified in the Inspector's `Component Type` field).

## Steps

1. **Open the AdvertisementComponent Inspector**
   Select the GameObject with `AdvertisementComponent` attached in the scene. The Inspector will display three field groups by section: "Debug Mode", "Config", and "Ad Unit ID (Legacy)".

2. **Fill in the ad unit IDs for each platform**
   Under the "Ad Unit ID (Legacy)" heading, fill in the IDs obtained from each platform's ad backend:

   | Inspector Display Name | Serialized Field | Target Platform |
   |------------------------|------------------|----------------|
   | Android 广告位ID | `m_adUnitIdAndroid` | `UNITY_ANDROID` |
   | IOS 广告位ID | `m_adUnitIdiOS` | `UNITY_IOS` |
   | WebGL 广告位ID | `m_adUnitIdWebGL` | Standard browser `UNITY_WEBGL` |
   | WebGL 微信 广告位ID | `m_adUnitIdWebGLWeChat` | WeChat Mini Game (macro `ENABLE_WECHAT_MINI_GAME`) |
   | WebGL 抖音 广告位ID | `m_adUnitIdWebGLDouYin` | Douyin Mini Game (macro `ENABLE_DOUYIN_MINI_GAME`) |
   | WebGL 快手 广告位ID | `m_adUnitIdWebGLKuaiShou` | Kuaishou Mini Game (macro `ENABLE_KUAISHOU_MINI_GAME`) |

   The field definitions in the source code can be found at [AdvertisementComponent.cs#L47-L57](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57), and the Inspector display names at [AdvertisementComponentInspector.cs#L26-L31](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L26-L31).

3. **Understand how IDs are selected at runtime**
   During the `Awake` phase, the component uses preprocessor directives to select the ID per platform and writes it to the `AdUnitId` property:

   ```csharp
   AdUnitId =
   #if UNITY_WEBGL
   #if ENABLE_WECHAT_MINI_GAME
       m_adUnitIdWebGLWeChat
   #elif ENABLE_DOUYIN_MINI_GAME
       m_adUnitIdWebGLDouYin
   #elif ENABLE_KUAISHOU_MINI_GAME
       m_adUnitIdWebGLKuaiShou
   #else
       m_adUnitIdWebGL
   #endif
   #elif UNITY_ANDROID
       m_adUnitIdAndroid
   #elif UNITY_IOS
       m_adUnitIdiOS
   #else
       string.Empty
   #endif
       ;
   ```
   Source: [AdvertisementComponent.cs#L99-L117](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)

   Selection priority: WebGL Mini Game macros → generic WebGL → Android → iOS. Platforms that don't match return an empty string.

4. **Confirm the config object used at initialization**
   During the component's `Start`, if `Config` is not null, it calls `IAdvertisementManager.Initialize(config)` (see [AdvertisementComponent.cs#L120-L126](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)). The specific ad unit ID is read from `AdUnitId` internally by each manager implementation.

## Common Variations

- **Specify ID via code at runtime (deprecated)**  
  You can call `Initialize(string adUnitId, bool isDebug = false)`, but this overload is marked `[Obsolete("Use Initialize(AdvertisementConfig) instead.")]`. New code should use the `Initialize(AdvertisementConfig)` config-object approach instead.
- **Configure different WebGL Mini Game channels separately**  
  WeChat/Douyin/Kuaishou IDs are stored independently, so there's no need to manually write channel prefixes in the same string. As long as the corresponding macro is enabled at compile time, the component will automatically pick the correct one.
- **Carry ad unit IDs via a `Config` subclass**  
  When the manager selected for `Component Type` declares `[AdvertisementConfigAttribute(typeof(YourConfig))]`, the Inspector will dynamically render fields based on that Config type (see [AdvertisementComponentInspector.cs#L127-L139](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L127-L139)). You can add platform fields directly in the Config subclass to replace the 6 legacy `m_adUnitIdXxx` fields.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| `AdUnitId` is an empty string | The current build platform has no matching `#if` branch (e.g., desktop Standalone) | When a desktop platform needs ads, provide a default value in the Config subclass, or set `AdUnitId` manually in code |
| WeChat Mini Game reads `WebGL 广告位ID` | The compile macro `ENABLE_WECHAT_MINI_GAME` is not enabled | Enable the corresponding Mini Game platform support in "Project Settings → Player → WebGL → Publishing Settings" |
| The 6 ad unit ID fields are not visible in the Inspector | Hidden via `HideInInspector` in code or a custom editor | Make sure you are using the default Inspector `GameFrameX/Advertisement/AdvertisementComponentInspector` |
| A warning is emitted when calling `Initialize(string, bool)` | That overload is marked `[Obsolete]` | Switch to `Initialize(AdvertisementConfig)` and put the ID in the Config subclass |

## Verification

1. Fill in non-empty IDs for each target platform in the Inspector (placeholder strings are fine for self-check).
2. Switch the Build Target (Android, iOS, WebGL) and build each one. After running, use `Debug.Log(adComponent.AdUnitId)` to check whether the output matches that platform's ID.
3. For WebGL Mini Games: build separately in the WeChat DevTools / Douyin DevTools to confirm that the corresponding macros are enabled and the correct field values are read.

## Background (Optional)

`AdvertisementComponent` consolidates platform branching into a single `Awake` call, exposing only a single `AdUnitId` value at runtime to simplify how downstream ad managers handle IDs. The `AdvertisementConfig` base class only exposes `isDebug`; platform-specific parameters are defined by each manager in the Config subclass specified via `[AdvertisementConfigAttribute]`, coexisting with these 6 legacy platform fields.
