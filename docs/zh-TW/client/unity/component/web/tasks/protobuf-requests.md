# Protocol Buffers 請求使用方式

使用 `WebManager` 提供的 `GetProtoBuf` / `PostProtoBuf` 泛型方法，即可使用 protobuf-net 訊息物件傳送 HTTP 請求，並直接取得反序列化後的回應物件。訊息型別必須實作 `IExtensible`,並以 `ProtoContract`/`ProtoMember` 標記。

## 前置條件

- 已安裝 `com.gameframex.unity.web` 套件，場景中存在 `WebComponent` 並持有 `IWebManager`(`WebManager`)實例。
- 訊息型別已依 protobuf-net 規則標記(`ProtoContract` + `ProtoMember`),且必須符合 `class, IExtensible` 泛型約束。

## API 快速參考

| 方法 | 簽章 | 說明 |
|------|------|------|
| `GetProtoBuf` | `Task<T> GetProtoBuf<T>(string url) where T : class, IExtensible;` | 以 GET 取得 protobuf 訊息並反序列化為 `T` |
| `PostProtoBuf` | `Task<T> PostProtoBuf<T>(string url, IExtensible requestData) where T : class, IExtensible;` | 將請求主體序列化為 protobuf 後以 POST 傳送，並將回應反序列化為 `T` |

來源： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L196-L198)

## 操作步驟

1. 定義 protobuf 請求/回應訊息類別，欄位以 `[ProtoMember(n)]` 指定編號：

```csharp
[ProtoContract]
public class UserResponse
{
    [ProtoMember(1)]
    public string UserName { get; set; }

    [ProtoMember(2)]
    public string Email { get; set; }
}
```

來源： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L116-L124)

2. 在業務程式碼中呼叫 `PostProtoBuf`(或 `GetProtoBuf`),對回傳的 Task 使用 `await` 即可取得回應物件：

```csharp
public async Task<UserResponse> GetUserProtoBufAsync(string userId)
{
    var request = new UserRequest { UserId = userId };
    return await webManager.PostProtoBuf<UserResponse>(
        "https://api.example.com/user/protobuf",
        request
    );
}
```

來源： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L126-L133)

3. 視需要加入錯誤處理。例如可攔截逾時與網路 IO 例外：

```csharp
try
{
    return await webManager.GetToString(url);
}
catch (WebException ex) when (ex.Status == WebExceptionStatus.Timeout)
{
    Debug.LogError("请求超时: " + ex.Message);
    return null;
}
catch (IOException ex)
{
    Debug.LogError("网络IO错误: " + ex.Message);
    return null;
}
```

來源： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L138-L154)

## 常見變化

- **自訂請求標頭**：protobuf 請求使用 `WebBinaryData` 的 `Header` 字典，傳送時會將各個項目寫入請求標頭(在原生平台寫入 `request.Headers`,在 WebGL 平台呼叫 `SetRequestHeader`)。請參閱 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L104-L110) 與 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L140-L146)。
- **WebGL 平台**：相同 API 在 `UNITY_WEBGL` 下會使用 `UnityWebRequest` + `UploadHandlerRaw` 上傳位元組，在其他平台則使用 `HttpWebRequest` 寫入請求串流。請參閱 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L83-L101)。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 送出請求後回應遲遲未返回 | protobuf 請求會先進入等待佇列，由 `UpdateBinary` 每幀從佇列取出處理。若 `WebManager` 未更新(元件處於停用狀態)，或已傳送的請求數達到 `MaxConnectionPerServer`,請求就會持續等待 | 確認 `WebComponent` 正常運作且 `WebManager` 處於更新狀態，並適當設定並行上限 |
| 反序列化結果的欄位為空 | 訊息型別缺少 `[ProtoContract]` / `[ProtoMember(n)]` 標記，或型別不符合 `class, IExtensible` 約束 | 為請求/回應型別加上 protobuf-net 特性(Attribute)標記 |
| 伺服器解析失敗 | 請求的 `Content-Type` 固定為 `application/octet-stream`,伺服器必須以 protobuf 二進位格式解析 | 請讓伺服器以二進位 protobuf 而非文字格式處理 |

## 驗證

- 呼叫 `PostProtoBuf` 後，若輸出回應物件的欄位(例如 `response.UserName`)能取得伺服器回傳值，即表示請求與反序列化成功。
- 發生網路錯誤時會拋出例外(原生平台為 `HttpWebRequest` 相關例外，WebGL 平台為以 `unityWebRequest.error` 包裝的 `Exception`),可藉此確認失敗原因。

## 背景

protobuf 請求在框架內部以「Binary 請求」方式處理。呼叫 `GetProtoBuf`/`PostProtoBuf` 時，請求會被包裝為 `WebBinaryData` 並進入 `m_WaitingBinaryQueue`,每幀 `UpdateBinary` 會在並行數未達上限時從佇列取出請求並呼叫 `MakeBinaryBytesRequest` 傳送，回應位元組則包裝為 `WebBufferResult` 以完成回呼。相關實作請參閱 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L17-L55)。
