# 기획 설정 테이블(Tables)을 읽고 쓰는 방법

이 페이지를 다 읽으면 GameFrameX의 모든 기획 설정 테이블(`TbAchievementConfig`, `TbItemConfig`, `TbSoundsConfig`, `TbLocalization`)의 통합 진입점인 `TablesComponent`, 그리고 설정 테이블에서 읽기, 기본 키 조회, 순회, 조건 검색, 참조 해석에 이르는 완전한 작성 방법을 익힐 수 있습니다.

## 사전 조건

- 프로젝트에서 `GameFrameX.Config` 어셈블리를 참조하고, 해당하는 기획 설정 테이블 파일을 생성했어야 합니다.
- `ConfigComponent`를 구성하여 `TablesComponent.Init`의 인자로 준비해 둡니다.
- `Func<string, Task<JsonElement>>` 타입의 로더를 준비합니다(일반적인 구현은 로컬 파일 또는 원격에서 JSON 데이터를 받아 `JsonElement`로 파싱하는 방식입니다).

## 작업 단계

### 1. 초기화 및 모든 설정 테이블 비동기 로드

`TablesComponent`는 각 테이블을 병렬로 로드하며, 로드가 완료되면 자동으로 `Refresh()`를 호출하여 내부적으로 `PostInit()`와 `ResolveRef()`(테이블 간 참조 해석용)를 트리거합니다.

```csharp
using GameFrameX.Config;
using System.Text.Json;
using System.Threading.Tasks;

// 호출하는 쪽에서 구현합니다. 예: 리소스 이름에 따라 JSON 내용을 반환
async Task<JsonElement> Loader(string name)
{
    var bytes = await File.ReadAllBytesAsync($"Configs/{name}.json");
    return JsonDocument.Parse(bytes).RootElement.Clone();
}

var configComponent = new ConfigComponent();
var tables = new TablesComponent();
tables.Init(configComponent);
await tables.LoadAsync(Loader);
```

로드가 완료되면 `tables.TbAchievementConfig`, `tables.TbItemConfig`, `tables.TbSoundsConfig`, `tables.TbLocalization`를 통해 각 테이블에 접근할 수 있습니다.

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L56)

### 2. 기본 키로 단일 데이터 읽기

모든 테이블은 `BaseDataTable<T>`를 기반으로 하며, 정수 기본 키와 문자열 기본 키 두 가지 인덱싱 방식을 지원합니다. 읽기 실패 시 기본 반환값은 `null`입니다.

```csharp
// 정수형 기본 키 읽기
var item = tables.TbItemConfig[1001];
if (item != null)
{
    Console.WriteLine(item.Name);
}

// long형 기본 키 읽기(기본 키가 long으로 정의된 경우 사용)
var ach = tables.TbAchievementConfig[100001L];

// 문자열 기본 키 읽기(주로 로컬라이제이션 테이블에서 사용)
var loc = tables.TbLocalization["ui.btn.confirm"];
```

`this[id]`는 내부적으로 `TryGet(id, out var v) ? v : null`이며, 찾지 못해도 예외를 던지지 않습니다.

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L110-L180)

### 3. TryGet으로 안전하게 가져오고 "미적중" 구분하기

설정 누락 때문인지 비즈니스 로직 때문인지 구분할 수 없는 채로 `null`을 받고 싶지 않다면, `TryGet`로 `bool` 반환값을 얻을 수 있습니다:

```csharp
if (tables.TbSoundsConfig.TryGet(2005, out var sound))
{
    // sound는 유효한 데이터입니다
}
else
{
    // 설정 누락, 기획자에게 테이블 보완 요청
}
```

문자열 키에도 마찬가지로 `TryGet(string id, out T value)` 오버로드가 있으며, 시그니처는 `IDataTable<T>` 인터페이스에서 확인할 수 있습니다.

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L138-L141)

### 4. 순회, 통계 및 조건 쿼리

`BaseDataTable<T>`는 LINQ 스타일의 자주 쓰는 작업을 제공하며, 내부적으로 `DataList`를 기반으로 구현됩니다:

| 작업 | 메서드 시그니처 | 용도 |
|------|---------|------|
| 개수 가져오기 | `int Count { get; }` | 캐시에 적중되어 여러 번 호출해도 중복 계산 없음 |
| 첫 번째 가져오기 | `T FirstOrDefault { get; }` | 정렬 후 첫 번째 항목 가져오기 |
| 마지막 가져오기 | `T LastOrDefault { get; }` | 정렬 후 마지막 항목 가져오기 |
| 전체 배열 | `T[] All { get; }` / `T[] ToArray()` / `List<T> ToList()` | 복사본 하나 얻기 |
| 조건으로 하나 조회 | `T Find(Func<T, bool> func)` | 찾지 못하면 `null` 반환 |
| 조건으로 여러 건 조회 | `T[] FindListArray(Func<T, bool> func)` / `List<T> FindList(...)` | 배열 또는 리스트 얻기 |
| 순회하며 실행 | `void ForEach(Action<T> func)` | 순회하면서 처리 |
| 프로젝션 최대/최소 | `Tk Max<Tk>(Func<T, Tk>)` / `Tk Min<Tk>(...)` | 특정 필드의 최댓값/최솟값 가져오기 |

다음은 전형적인 "타입별로 아이템 찾기" 예시입니다:

```csharp
// Type == 2(소모품을 의미한다고 가정)인 모든 아이템 찾기
var consumables = tables.TbItemConfig.FindListArray(x => x.Type == 2);
Console.WriteLine($"消耗品数量:{consumables.Length}");

// 모든 보상 설정에서 Id 최댓값 집계
var maxRewardId = tables.TbAchievementConfig.Max(x => x.Id);
```

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L189-L329)

### 5. 테이블 새로 고침(핫 업데이트)

기획 테이블을 다시 로드해야 할 때는 `LoadAsync`를 다시 호출하면 됩니다:

```csharp
await tables.LoadAsync(Loader); // 각 테이블을 병렬로 다시 로드하고 Refresh()를 트리거함
```

`Refresh()`는 `PostInit()`와 `ResolveRef()`를 차례로 실행하여 테이블 간 참조를 다시 구축합니다.

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L73)

## 일반적인 변형

### 로컬라이제이션 다국어 읽기

`TbLocalization`는 `GameFrameX.Config.Local` 네임스페이스에 속하며, 문자열 키로 인덱싱되고 사용법은 다른 테이블과 완전히 동일합니다:

```csharp
var key = "ui.title.home";
if (tables.TbLocalization.TryGet(key, out var loc))
{
    Console.WriteLine(loc.Content);
}
```

### 로더 다시 초기화

`Init`는 먼저 `configComponent.RemoveAllConfigs()`를 호출해 기존 등록을 정리하므로, 데이터 소스 전체를 교체할 때는 다시 `Init`한 뒤 `LoadAsync`를 호출하기만 하면 됩니다.

```csharp
tables.Init(newConfigComponent);
await tables.LoadAsync(newLoader);
```

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

## 흔한 실수

- **`LoadAsync`가 완료되기 전에 읽기**: `TbAchievementConfig` 등의 속성은 `LoadAsync` 이전에는 기본 참조이므로, 기본값에서 데이터를 가져오면 `null` 또는 빈 컬렉션이 반환됩니다. 반드시 `await tables.LoadAsync(Loader);`를 실행하세요.
- **정수형과 long형 기본 키 혼동**: 기본 키가 `long`으로 정의된 경우 `int` 오버로드로 전달하면 암시적 변환이 일어나지만 오버플로가 발생할 수 있습니다. 기본 키가 `int`로 정의된 경우에도 `long` 오버로드를 사용하지 마세요. 의미가 일치하지 않습니다.
- **테이블 간 참조 미갱신**: `PostInit()` / `ResolveRef()`는 `Refresh()`에 의해 트리거되므로, 커스텀 시나리오에서 `LoadAsync`를 우회하면 참조 필드가 `null`일 수 있습니다.
- **문자열 키를 인덱스로 접근할 때 철자 오류**: `this[string id]`는 찾지 못하면 조용히 `null`을 반환하므로, 먼저 `TryGet`으로 한 번 확인하는 것이 더 안전합니다.
- **`BaseDataTable`이 노출하는 `LongDataMaps` / `StringDataMaps`를 직접 수정**: 이들은 `protected`이지만, 리플렉션으로 수정하면 이후 핫 업데이트의 멱등성이 깨질 수 있으므로, `LoadAsync`를 다시 수행하는 경로를 사용해야 합니다.

## 배경(선택 사항)

`TablesComponent`는 설정 테이블 생성기가 자동으로 생성합니다(`<auto-generated>` 헤더). 이것은 각 `Tb*` 테이블을 `ConfigComponent`에 등록하고, 로드가 완료되면 `Refresh()`로 참조 해석을 완료합니다. `BaseDataTable<T>`는 검색, 순회, 조건 쿼리, 집계 등의 공통 기능을 기반 클래스로 추출하며, 각각의 구체적인 테이블은 자체 JSON 파싱과 기본 키 매핑만 담당합니다.

`ConfigComponent`의 전체 구성에 대해서는 `GameFrameX.Config` 네임스페이스의 관련 소스 코드를 참고하세요. 각 `Tb*` 테이블의 필드 정의는 기획 설정 테이블 생성기가 Excel/JSON 데이터에 따라 자동 생성합니다.
