# How to Configure and Use Entity Groups

An Entity Group is the container and object pool unit for entity instances: every entity must belong to an existing entity group when displayed, and the entity group determines its mount parent node, object pool capacity, and recycling strategy. After completing the tasks on this page, you will be able to declare groups in the Inspector, dynamically add groups at runtime, and query/manage entities by group.

## Prerequisites

- `EntityComponent` is attached in the scene (in the `GameFrameX.Entity.Runtime` namespace), and `BaseComponent` and `EventComponent` are ready — otherwise `Base component is invalid.` / `Event component is invalid.` will be printed at startup.
- `EntityComponent.Start` creates the `Entity Instances` root node and entity helper on its own, so no manual hierarchy setup is required.

## Steps

### 1. Declare entity groups in the Inspector (recommended)

`EntityComponent`'s `m_EntityGroups` is a serializable array where each element contains 5 fields, with default values as follows:

| Inspector Field | Type | Default Value | Description |
|------|------|--------|------|
| `m_Name` | string | `null` | Entity group name, the unique key at runtime; must not be empty |
| `m_InstanceAutoReleaseInterval` | float | `60f` | Interval in seconds at which the instance object pool automatically releases releasable objects |
| `m_InstanceCapacity` | int | `16` | Instance object pool capacity |
| `m_InstanceExpireTime` | float | `60f` | Expiration time in seconds for objects in the instance object pool |
| `m_InstancePriority` | int | `0` | Instance object pool priority |

```csharp
[Serializable]
private sealed class EntityGroup
{
    [SerializeField] private string m_Name = null;

    [SerializeField] private float m_InstanceAutoReleaseInterval = 60f;

    [SerializeField] private int m_InstanceCapacity = 16;

    [SerializeField] private float m_InstanceExpireTime = 60f;

    [SerializeField] private int m_InstancePriority = 0;
```
> Source: [EntityComponent.EntityGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.EntityGroup.cs#L40-L51)

After you fill in the groups one by one in the Inspector (e.g., `Player`, `Monster`, `Effect`), the `Start` phase automatically iterates over and registers them; a failed registration only prints the warning `Add entity group '{0}' failure.` and continues with the next entry, without interrupting startup.

```csharp
for (int i = 0; i < m_EntityGroups.Length; i++)
{
    var entityGroup = m_EntityGroups[i];
    if (entityGroup == null)
    {
        continue;
    }

    if (!AddEntityGroup(entityGroup.Name, entityGroup.InstanceAutoReleaseInterval, entityGroup.InstanceCapacity, entityGroup.InstanceExpireTime, entityGroup.InstancePriority))
    {
        Log.Warning("Add entity group '{0}' failure.", entityGroup.Name);
        continue;
    }
}
```

### 2. Dynamically add entity groups at runtime

When you need to create groups on demand in code, call `EntityComponent.AddEntityGroup`. Of the two overloads, the simple version only requires the name and the auto-release interval; the remaining parameters are taken from the component's `DefaultCapacity` (default `512`), `DefaultExpireTime` (default `3600f`), and `DefaultPriority`.

```csharp
var entityComponent = GameEntry.GetComponent<EntityComponent>();

// Simple version: capacity/expire time/priority use the component's default values
entityComponent.AddEntityGroup("Monster", 60f);

// Full version: explicitly specify object pool parameters
entityComponent.AddEntityGroup("Effect", 30f, 64, 30f, 10);
```
> Sources: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L252-L287), [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L72-L74)

Key behavior points of `AddEntityGroup` (from the implementation):

1. If a group with the same name already exists, it directly returns `false` (idempotent; no duplicate group is created).
2. It creates the group helper via `m_EntityGroupHelperTypeName` (default `GameFrameX.Entity.Runtime.DefaultEntityGroupHelper`) or `m_CustomEntityGroupHelper`; if creation fails, it prints `Can not create entity group helper.` and returns `false`.
3. The helper GameObject is named `Entity Group - {group name}`, attached under `m_InstanceRoot`, with `localScale` set to `Vector3.one`.
4. Finally, it delegates to `IEntityManager.AddEntityGroup(...)` to complete the registration.

```csharp
if (m_EntityManager.HasEntityGroup(entityGroupName))
{
    return false;
}

EntityGroupHelperBase entityGroupHelper = Helper.CreateHelper(m_EntityGroupHelperTypeName, m_CustomEntityGroupHelper, EntityGroupCount);
if (entityGroupHelper == null)
{
    Log.Error("Can not create entity group helper.");
    return false;
}

entityGroupHelper.name = Utility.Text.Format("Entity Group - {0}", entityGroupName);
Transform transform = entityGroupHelper.transform;
transform.SetParent(m_InstanceRoot);
transform.localScale = Vector3.one;

return m_EntityManager.AddEntityGroup(entityGroupName, instanceAutoReleaseInterval, instanceCapacity, instanceExpireTime, instancePriority, entityGroupHelper);
```
> Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L269-L286)

### 3. Query groups and manage entities within a group

```csharp
// Check before creating the group to avoid relying on return value semantics
if (!entityComponent.HasEntityGroup("Monster"))
{
    entityComponent.AddEntityGroup("Monster", 60f);
}

IEntityGroup group = entityComponent.GetEntityGroup("Monster");
int count = group.EntityCount;              // Number of entities in the group
group.InstanceCapacity = 32;                // Adjust pool capacity at runtime
group.InstanceAutoReleaseInterval = 30f;    // Adjust the auto-release interval

// Get entities by asset name/ID
IEntity one = group.GetEntity("Assets/Res/Monster/Slime.prefab");
IEntity[] all = group.GetAllEntities();
```

## Common Variants

### Custom group helper (changing entity mounting/grouping behavior)

The group helper determines the parent node of entity instances: the default entity helper executes `transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform)` when creating an entity, so all entities in the same group are attached under that group's `Entity Group - {name}` node.

```csharp
public override IEntity CreateEntity(object entityInstance, IEntityGroup entityGroup, object userData)
{
    ...
    Transform transform = gameObject.transform;
    transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform);
```
> Source: [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L69-L79)

To customize, inherit from `EntityGroupHelperBase` (which itself is a `MonoBehaviour` implementing `IEntityGroupHelper`), then either change `m_EntityGroupHelperTypeName` in the Inspector to the fully qualified name of your type, or assign the implementation to the `m_CustomEntityGroupHelper` field.

```csharp
public abstract class EntityGroupHelperBase : MonoBehaviour, IEntityGroupHelper
```

### Global default object pool parameters

If you don't want to fill in capacity/expire time for each group individually, just use the simple `AddEntityGroup(name, interval)` and change the default values uniformly in code:

```csharp
entityComponent.DefaultCapacity = 256;      // Default is 512
entityComponent.DefaultExpireTime = 1800f;  // Default is 3600f
```

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| Throws `GameFrameworkException("Entity group name is invalid.")` | The passed-in `entityGroupName` is empty or whitespace; `AddEntityGroup` / `GetEntityGroup` / `HasEntityGroup` all validate this | Make sure every group's `m_Name` is filled in in the Inspector, and that code passes a non-empty string |
| `Add entity group '{0}' failure.` appears in the console | A group with the same name already exists, or the group helper failed to be created | Use `HasEntityGroup` to check for duplicates first; verify that `m_EntityGroupHelperTypeName` is a loadable fully qualified type name |
| `Can not create entity group helper.` appears in the console | The helper type name is misspelled, the type was stripped, or `m_CustomEntityGroupHelper` is not assigned | Use the default value `GameFrameX.Entity.Runtime.DefaultEntityGroupHelper`, or assign your custom helper directly to `m_CustomEntityGroupHelper` |
| An error reports the group does not exist when showing an entity | Groups are registered in `EntityComponent.Start`; calling entity display too early (e.g., in another component's `Awake`) fails to find the group | Move group creation/entity display calls to a flow after `Start`, or call `AddEntityGroup` yourself before displaying |
| Entities are attached to the wrong parent node / hierarchy is messy | The custom entity helper does not set the parent node according to the group helper | Follow `DefaultEntityHelper.CreateEntity` and use the transform of `entityGroup.Helper` as the parent node |

## Background (optional)

Groups are the partitioning unit of entity object pools: `EntityManager` creates an independent instance pool for each group, and capacity, expire time, priority, and auto-release interval all take effect per group. Therefore, placing entities with similar lifecycle characteristics (effects vs characters) into different groups can significantly reduce unnecessary loading and recycling.
