# 依入口載入熱更(Main / Entry / GateWay / Heart)

GameFrameX.Server 把「依入口載入熱更」拆成四個 partial 類別檔案，統一繼承 `AppStartUpBase` 並以 `AppStartUpHotfixGame` 作為 partial 容器:`Main` 負責業務伺服器網路層與訊息分發、`Entry` 負責首啟/重載與全域元件啟用、`GateWay` 負責閘道連線與心跳、`Heart` 負責用戶端心跳回覆。

## 入口檔案一覽

| 入口 partial | 檔案 | 觸發場景 |
|---|---|---|
| Main | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs` | `AppStartUpHotfixGame.StartAsync()`、`RunServer()`、`OnConnected`/`OnDisconnected`/`PackageHandler`、`StopAsync` |
| Entry | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs` | `OnLoadSuccess(setting, reload)`(首啟與重載)、`Stop(message)` |
| GateWay | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs` | 與閘道伺服器建立 TCP 連線、斷線重連、心跳維持、訊息上行 |
| Heart | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByHeart.cs` | 用戶端心跳訊息 `ReqHeartBeat` 的解析與 `NotifyHeartBeat` 回覆 |

四個檔案透過 C# `partial class` 機制合成同一個 `AppStartUpHotfixGame`,無需額外註冊。

## 啟動順序(程式碼中可直接對照)

1. `Entry.OnLoadSuccess(AppSetting setting, bool reload)` —— 取得 `AppSetting`,判定是否熱重載。
   - `reload == true`:`ActorManager.ClearAgent()` 後直接傳回。
   - `reload == false`:走完整首啟流程。
2. `Entry.Init(setting.ServerType, setting)` —— 初始化框架基礎設施。
3. `Entry.RunServer()` → `Main.StartAsync()` —— 啟動 SuperSocket 伺服器端，裝配壓縮/解壓縮、HTTP 處理器與所有 TcpHandler。
4. `Entry` 啟動 `QuartzTimer.Start()`、`GlobalTimer.Start()` 與 `ComponentRegister.ActiveGlobalComponents()`。
5. `Main.PackageHandler` 收到用戶端訊息時：心跳訊息轉交 `Heart.ReplyHeartBeat`,業務訊息經 `HotfixManager.GetTcpHandler` 分發。

來源:[AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L37-L60) 與 [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L43-L65)。

## 各入口職責

### Main — 網路層與訊息分發

`StartAsync()` 啟動網路服務並載入 HTTP 處理器：

```csharp
public override async Task StartAsync()
{
    await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
        new DefaultMessageCompressHandler(),
        new DefaultMessageDecompressHandler(),
        HotfixManager.GetListHttpHandler(),
        HotfixManager.GetHttpHandler);
}
```

來源:[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L45-L52)

`RunServer(bool reload = false)` 每次都會 `ConfigComponent.Instance.LoadConfig()`;`reload` 時清理 Actor 後直接傳回，否則進入 `StartAsync()`。

`PackageHandler` 中先將 `NetworkMessagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat` 的訊息分流給 `ReplyHeartBeat`,其餘依 `MessageId` 派發：

```csharp
if (messagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat)
{
    ReplyHeartBeat(netWorkChannel, (MessageObject)messagePackage.DeserializeMessageObject());
    return;
}
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
```

來源:[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L113-L135)

`OnConnected` 中透過 `SessionManager.Count()` 與 `Setting.MaxClientCount` 控制最大線上人數;`OnDisconnected` 通知 `RoomComponentAgent.MarkPlayerDisconnected`。

### Entry — 首啟 / 重載

`OnLoadSuccess` 是熱更框架呼叫的入口，負責區分「熱重載」與「首次啟動」：

```csharp
public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
{
    if (reload)
    {
        ActorManager.ClearAgent();
        return true;
    }

    Init(setting.ServerType, setting);
    await RunServer();
    await QuartzTimer.Start();
    GlobalTimer.Start();
    await ComponentRegister.ActiveGlobalComponents();
    return true;
}
```

來源:[AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L39-L54)

`Stop(message)` 直接轉發到 `Main.StopAsync(message)`,作為熱更框架的停止回呼。

### GateWay — 與閘道通訊

檔案內含 `AsyncTcpSession _gatewayClient`、`_gateWayReconnectionTimer` 與 `_gateWayHeartBeatTimer`,在斷線時由 `_gateWayReconnectionTimer` 觸發重連，每次成功投遞訊息後 `_gateWayHeartBeatTimer.Reset()` 重置心跳計時器。

`SendToGatewayMessage` 是上行到閘道的統一通道：連線已建立時呼叫 `_gatewayClient.TrySend(span)` 投遞訊息。

### Heart — 用戶端心跳回覆

`PackageHandler` 把心跳交給 `ReplyHeartBeat`,在 partial 檔案裡建構 `NotifyHeartBeat` 並寫回通道：

```csharp
if (messageObject is ReqHeartBeat req)
{
    netWorkChannel.UpdateReceiveMessageTime();
    NotifyHeartBeat notifyHeartBeat = MessageObjectPoolHelper.Get<NotifyHeartBeat>();
    notifyHeartBeat.Timestamp = TimerHelper.UnixTimeMilliseconds();
    notifyHeartBeat.UniqueId = req.UniqueId;
    await netWorkChannel.WriteAsync(notifyHeartBeat);
}
```

來源:[AppStartUpHotfixGameByHeart.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByHeart.cs#L43-L52)

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 熱重載後舊業務邏輯仍在執行 | `OnLoadSuccess` 中 `reload == true` 分支忘記呼叫 `ActorManager.ClearAgent()` | 保持現有 `ClearAgent()` 呼叫，確保舊的 Actor 快取被清空 |
| 用戶端一直斷線、`NotifyServerFullyLoaded` 後被踢 | `Setting.MaxClientCount` 限制生效，新連線超過上限 | 在 `appsettings.json` 中調高 `MaxClientCount`,或排查異常連線 |
| `找不到[xxx][yyy]对应的handler` 日誌 | `messagePackage.Header.MessageId` 沒在 `HotfixManager` 註冊 | 在對應熱更模組的 Handler 註冊表裡補齊 `MessageId` |

## 背景(可選)

四個檔案依「職責」而非「階段」拆分是為了讓 Main 的網路層與 Entry 的生命週期各佔一個 partial,GateWay / Heart 這種橫切關注點也獨立成檔案；所有 partial 合併為同一個 `AppStartUpHotfixGame` 後，基底類別 `AppStartUpBase` 與 `IHotfixBridge` 在編譯期只需要一個型別入口，降低了熱更框架的耦合面。
