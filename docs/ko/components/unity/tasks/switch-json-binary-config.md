# JSON과 바이너리 구성 간 전환 방법

GameFrameX에서 `Hotfix/Config/Generate/Tables/` 아래의 테이블 데이터 클래스(LuBan 도구로 생성됨)는 `SimpleJSON.JSONNode`를 역직렬화 진입점으로 사용하며, 런타임에는 `TablesComponent`가 각 테이블을 `ConfigComponent`에 등록합니다. 이 페이지에서는 "JSON 구성"과 "바이너리 구성" 두 가지 소스 간 전환 방식을 설명합니다.

## 사전 조건

- `Packages/manifest.json`에서 GameFrameX scoped registry를 통해 `com.gameframex.unity.json.simplejson`을 도입해야 합니다([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/README.zh-CN.md#L40-L80) 참조).
- 프로젝트에 `Assets/Hotfix/Config/Generate/Tables/TablesComponent.cs`가 존재해야 하며, LuBan 도구를 통해 `ItemConfig`, `AchievementConfig`, `SoundsConfig` 등의 테이블 클래스가 생성되어 있어야 합니다([ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86) 참조).
- 런타임 프레임워크 패키지 `com.gameframex.unity.config`가 설치되어 있어야 하며, `ConfigComponent`와 `BaseDataTable<T>`를 제공해야 합니다([link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28) 참조).

## 작업 단계

1. 테이블 클래스의 역직렬화 생성자 시그니처를 확인합니다. 생성기가 출력한 모든 테이블 클래스는 `SimpleJSON.JSONNode`를 받는 생성자를 제공하여 JSON을 테이블 객체로 역직렬화합니다.

```csharp
// 출처:LuBan 생성 코드
public ItemConfig(JSONNode _buf)
{
    { if(!_buf["id"].IsNumber) { throw new SerializationException(); }  Id = _buf["id"]; }
    { if(!_buf["Name"].IsString) { throw new SerializationException(); }  Name = _buf["Name"]; }
    // ... 나머지 필드 생략
    PostInit();
}

public static ItemConfig DeserializeItemConfig(JSONNode _buf)
{
    return new Tables.ItemConfig(_buf);
}
```

출처: [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86)

2. `TablesComponent`에서 각 테이블을 `ConfigComponent`에 등록합니다. 기본 구현에서 모든 테이블은 `TbXxxConfig.LoadAsync()`로 비동기 로드되며, 테이블 이름을 키로 등록됩니다([TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L52-L70) 참조).

```csharp
m_ConfigComponent.RemoveAllConfigs();
var loadTasks = new System.Collections.Generic.List<System.Threading.Tasks.Task>();
loadTasks.Add(TbItemConfig.LoadAsync());
m_ConfigComponent.Add(nameof(Tables.TbItemConfig), TbItemConfig);
```

3. JSON 구성 소스로 전환(기본方案). 기존 생성 코드를 변경하지 않고, 데이터를 JSON 파일로 내보내 LuBan에 로드하기만 하면 됩니다. 생성기가 생성한 `DeserializeXxxConfig(JSONNode)`는 JSON 텍스트를 직접 받아들이므로, 런타임에는 추가 변환이 필요하지 않습니다.

4. 바이너리 구성 소스로 전환(성능 우선方案). 핫업데이트 패키지 또는 첫 패키지 내에 바이너리 데이터만 제공되는 경우, 먼저 로드 진입점에서 바이너리 스트림을 `JSONNode`로 디코딩한 다음 동일한 `DeserializeXxxConfig` 경로를 거쳐 다운스트림 테이블 클래스를 변경하지 않도록 합니다. 예:

```csharp
using SimpleJSON;
using System.Text;

// bytes가 YooAsset에서 가져온 바이너리 구성 패키지라고 가정
JSONNode node = JSON.Parse(Encoding.UTF8.GetString(bytes));
var item = Tables.ItemConfig.DeserializeItemConfig(node);
```

핵심 포인트: 역직렬화 진입점은 여전히 `DeserializeXxxConfig(JSONNode)`이므로, JSON과 바이너리의 전환은 "로드 단계에서 데이터 형태를 JSONNode로 정규화하는 것"과 동일합니다. 테이블 클래스 자체는 다시 생성할 필요가 없습니다.

5. 런타임에 `ConfigComponent.GetConfig<T>()`로 구성을 가져옵니다. 기반이 JSON이든 바이너리든, 테이블 이름이 `TablesComponent.Add`에서 이미 등록되어 있다면 비즈니스 레이어의 호출 방식은 변경되지 않습니다.

```csharp
var itemConfig = GameFrameX.Config.Runtime.ConfigComponent.Instance
    .GetConfig<Tables.ItemConfig>();
```

## 일반적인 변형

- **핫업데이트 단계에서 플랫폼별 전환**:Android 플랫폼 첫 패키지는 바이너리 압축 패키지를 사용하여 패키지 크기를 줄이고, iOS 플랫폼 또는 개발 기간에는 JSON을 사용하여 문제 해결을 용이하게 합니다. `TablesComponent.Init` 전에 플랫폼별로 로드 소스를 선택하여 얻은 `JSONNode`를 `DeserializeXxxConfig`에 전달하기만 하면 됩니다.
- **로컬라이제이션 구성**:이미 생성된 테이블(예: `TbLocalization`)은 완전히 동일한 등록 흐름을 따르며, [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L70)의 `m_ConfigComponent.Add(nameof(Local.TbLocalization), TbLocalization)`을 참조하세요.

## 일반적인 오류

- **생성된 테이블 클래스 직접 수정**:생성기는 `Assets/Hotfix/Config/Generate/Tables/*.cs`를 덮어쓰므로, 모든 사용자 정의 로직은 `partial` 분할 클래스 또는 비즈니스 레이어에 두어야 합니다.
- **필드 이름 수정 후 재생성 누락**:`_buf["xxx"]`의 필드 이름은 대소문자를 구분합니다(`id`는 소문자, `Name`은 대문자, `description`은 소문자 주의). 필드가 일치하지 않으면 `SerializationException`이 발생합니다([ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L74) 참조).
- **`m_ConfigComponent.Add` 호출 잊어버림**:`LoadAsync()`만 호출하고 테이블 이름을 등록하지 않으면 `GetConfig<T>()`가 null을 반환합니다. 등록 흐름은 [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L69)를 참조하세요.
- **HybridCLR AOT 트리밍 문제**:비제네릭 리플렉션 대상을 새로 추가한 경우 `ConfigComponent`/`BaseDataTable<T>`가 link.xml에 보존되어 있는지 확인해야 합니다([link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28) 참조).

## 배경(선택 사항)

LuBan 테이블 생성기의 결과물은 통일되게 `SimpleJSON.JSONNode`를 역직렬화 진입점으로 사용하며, 이 단계에서 "데이터가 JSON에서 왔는지 바이너리에서 왔는지"의 차이를 로드 레이어에서 수렴합니다. `TablesComponent`는 각 테이블을 `ConfigComponent`에 등록하는 역할을 담당하고, 비즈니스 레이어는 통일되게 `ConfigComponent.GetConfig<T>()`를 통해 데이터를 가져오므로 데이터 소스 전환에 소비자를 수정할 필요가 없습니다. LuBan 생성기와 구성 파이프라인의 전체 위치는 프로젝트 내 `Assets/Hotfix/Config/Generate/`를 참조하세요.
