# 呼び出しても反応がない:パラメータ空警告クイックリファレンス

購入・消費などのインターフェースを呼び出した後に「何の反応もない」(決済ダイアログが表示されない、イベントが発火しない)場合、通常は渡されたパラメータが空または null であることが原因です。`PaymentComponent` は入口の時点でこれを遮断し、Warning ログを 1 件出力するだけで直接 `return` するため、リクエスト自体がまったく送信されていません。下表と照らし合わせてログ内の該当する警告原文を見つければ、どのパラメータが渡されていないかを特定できます。

## クイック診断

| 症状(ログ原文) | 発生箇所/原因 | 修正 |
|------|------|------|
| `Product ID is null or empty.` | `Buy` / `BuyInApp` / `BuySubs` の呼び出し時に `productId`(または `PurchaseParams.ProductId`)が null または空文字列 | ストア管理画面で設定された実際の商品 ID/SKU を渡す。下記「修正手順 1」を参照 |
| `Order ID is null or empty.` | `Buy` / `BuyInApp` / `BuySubs` の呼び出し時に `orderId`(または `PurchaseParams.OrderId`)が null または空文字列 | 事前に自社サーバーで注文番号を生成してから購入を開始する。「修正手順 2」を参照 |
| `Purchase token is null or empty.` | `ConsumePurchase(purchaseToken)` の呼び出し時に購入トークンが空 | `OnQueryPurchasesResult` / `OnPurchaseSuccess` のイベント引数から実際の `PurchaseToken` を取り出してから消費する。「修正手順 3」を参照 |
| `Purchase params is null.` | `Buy(PurchaseParams)` の呼び出し時にパラメータオブジェクト全体が null | `PurchaseParams` のサブクラスで構築して値を設定してから渡す。「修正手順 2」を参照 |
| `Pay Manager is invalid.`(Fatal) | `Awake` 内で `GameFrameworkEntry.GetModule<IPaymentManager>()` が null を返す。プラットフォーム実装クラスが正しくロードされていない | `PaymentComponent` の Inspector 上のプラットフォームコンポーネントタイプフィールドと、対応するチャネルパッケージが導入済みかを確認する。「修正手順 4」を参照 |

上記の警告はいずれも `Log.Warning` の後すぐに `return` するだけで、例外をスローせず、`OnPurchaseFailed` も発火しません ―― だからこそ「呼び出しても反応がない」という現象になります。Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L259)。

## 修正手順

### 1. Product ID が空

商品 ID はストア管理画面で設定された SKU と完全に一致している必要があります(大文字・小文字の区別、前後のスペースに注意)。`PurchaseParams` のサブクラスで構築することを推奨します:

```csharp
// ProductId は構築後も検証対象であり、空の場合は同様に Warning を出力して直接 return する
var param = new SomeChannelPurchaseParams(productId: "coin_pack_100", orderId: orderNo, productType: PaymentProductType.InApp);
paymentComponent.Buy(param);
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

調査のポイント:

- 設定テーブル/サーバーから商品 ID を読み込む場合は、まず実際の値を出力して空でないことを確認します:`Debug.Log($"[{productId}]");`
- `offerToken`、`customData` といった「null 許容のデフォルト引数」の位置に入れ違った値を渡していないか確認してください。
- `Buy(PurchaseParams)` の検証順序は、パラメータオブジェクト null → `ProductId` 空 → `OrderId` 空 の順です。どのログが先に出るかを見れば特定できます。

### 2. Order ID が空、またはパラメータオブジェクトが null

`OrderId` は自社サーバーの注文番号であり、購入検証で使用されるため、空は許可されません。`PurchaseParams` は抽象基底クラス(`public abstract class PurchaseParams`)で、直接 `new` することはできず、必ず各チャネルのサブクラスを使用する必要があります。3 つのフィールド(`ProductId`、`OrderId`、`ProductType`)はコンストラクタで値を設定します:

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

よくある落とし穴:

- 注文番号を非同期インターフェースで生成している間に、コールバック前に購入ボタンが押されてしまう ―― コールバックの中で購入ボタンを有効化するようにしてください。
- 旧インターフェースの `BuyInApp` / `BuySubs` / `Buy(string, PaymentProductType, ...)` には `[Obsolete("请使用 Buy(PurchaseParams) 替代")]` が付いていますが、検証の動作は同一のため、移行時も同様に `productId`、`orderId` が空でないことを保証する必要があります。

### 3. Purchase token が空(購入の消費が反応しない)

`ConsumePurchase` は空でない `purchaseToken` のみを受け付けます:

```csharp
public void ConsumePurchase(string purchaseToken)
{
    if (string.IsNullOrEmpty(purchaseToken))
    {
        Log.Warning("Purchase token is null or empty.");
        return;
    }

    _paymentManager.ConsumePurchase(purchaseToken);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L152)

正しい方法は、`OnPurchaseSuccess` または `OnQueryPurchasesResult` イベントを購読し、`PaymentEventArgs` から実際のトークンを取得してから消費を呼び出すことです。

### 4. Pay Manager is invalid(Fatal)

`PaymentComponent.Awake` はプラットフォームに応じて実装クラスのタイプ(`m_componentAndroidType`、`m_componentIOSType`、`m_componentWebGLType`、`m_componentPCType`、`m_componentMacType`)を選択し、それ以外のプラットフォームでは `DefaultPaymentManager` にフォールバックします。`GetModule<IPaymentManager>()` が null を返す場合は `Log.Fatal("Pay Manager is invalid.")` が出力されます。以下を確認してください:

- Inspector 上のプラットフォームタイプ文字列が壊されていないか(デフォルトは例えば `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`)。
- 対応するチャネルパッケージがプロジェクトにインポート済みか(タイプが存在しない場合、`Utility.Assembly.GetType` の解決に失敗します)。
- 現在の実行プラットフォームがいずれかの `UNITY_*` ブランチに該当するか。該当しない場合は `DefaultPaymentManager` の空実装が使用され、決済自体も反応しなくなります。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 検証

- 呼び出しの前に Unity Console で Warning をフィルターし、上の表のいずれのログも出力されなくなったことを確認します。
- パラメータが有効な場合、呼び出しは `_paymentManager.Buy(...)` / `ConsumePurchase(...)` まで進みます。その後 `OnPurchaseSuccess` / `OnPurchaseFailed` イベントを購読して、決済フローが実際に発火したことを確認できます(イベントは [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64) で透過的に転送されます)。
- `IsReady()` で決済システムの準備ができていることを確認してから購入エントリーを表示すると、「反応しない」系の誤報の多くを回避できます。
