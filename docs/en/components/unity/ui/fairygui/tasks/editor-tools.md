# Using the Editor Tools (Package Component Inspector and Texture Import)

This package ships with two editor tools: `FairyGUIPackageComponentInspector` provides continuous refreshing for the Inspector of the `FairyGUIPackageComponent` component; `UITextureAssetPostprocessor` automatically unifies import settings when UI textures are imported. Both take effect as soon as the package is installed—no manual setup required.

## Prerequisites

- The package (`com.gameframex.unity.ui.fairygui`) has been installed into the Unity project, and the `Editor/` directory is recognized by Unity as an editor assembly along with the package.
- The texture postprocessor is controlled by the macro `ENABLE_UI_FAIRYGUI`; it is only compiled and takes effect when this macro is defined. When the macro is not defined, no import logs appear in the Unity console—this is expected behavior, not a malfunction.

## Steps

### 1. Viewing the FairyGUIPackage Component in the Inspector

1. In the scene, select the GameObject that has `FairyGUIPackageComponent` attached (the component menu path is `GameFrameX/FairyGUIPackage`).
2. Unity automatically uses the package's custom Inspector to render the properties panel—no manual action required.
3. The only additional behavior of this Inspector is that it repaints the panel every frame, ensuring that runtime data (such as the status of loaded packages) is visible in real time:

```csharp
[CustomEditor(typeof(FairyGUIPackageComponent))]
internal sealed class UIFairyGUIPackageComponentInspector : GameFrameworkInspector
{
    public override void OnInspectorGUI()
    {
        base.OnInspectorGUI();
        Repaint();
    }
}
```

### 2. Making UI Textures Follow the Automatic Import Rules

`UITextureAssetPostprocessor` checks the asset path each time a texture enters the import process. As long as the path contains `Assets/{BundlesPath}/UI` (`BundlesPath` comes from `Utility.Asset.Path.BundlesPath`, and `PathHelper.Combine` handles the concatenation), it forcibly applies the following settings:

| Property | Forced Value | Notes |
|----------|---------------|-------|
| `textureImporter.textureType` | `TextureImporterType.Default` | Only written when the current value is not Default, to avoid unnecessary dirty flags |
| `textureImporter.mipmapEnabled` | `false` | Only turned off when currently true |
| `textureImporter.alphaSource` | `TextureImporterAlphaSource.FromInput` | Written unconditionally |
| `textureImporter.alphaIsTransparency` | `true` | Written unconditionally |

```csharp
internal sealed class UITextureAssetPostprocessor : AssetPostprocessor
{
    void OnPreprocessTexture()
    {
        if (assetPath.Contains(PathHelper.Combine(Utility.Asset.Path.BundlesPath, "UI")))
        {
            TextureImporter textureImporter = (TextureImporter)assetImporter;
            if (textureImporter.textureType != TextureImporterType.Default)
            {
                textureImporter.textureType = TextureImporterType.Default;
            }

            if (textureImporter.mipmapEnabled)
            {
                textureImporter.mipmapEnabled = false;
            }

            textureImporter.alphaSource = TextureImporterAlphaSource.FromInput;
            textureImporter.alphaIsTransparency = true;
        }
    }
}
```

Source: [UITextureAssetPostprocessor.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Editor/UITextureAssetPostprocessor.cs#L39-L60)

To have a texture follow this rule, simply place it in the UI asset directory:

1. Confirm that the project's asset root directory name matches `Utility.Asset.Path.BundlesPath` (the default is the Bundles directory convention).
2. Place the texture into any subdirectory under `Assets/<BundlesPath>/UI/`.
3. Right-click the texture and choose **Reimport** (or modify it directly to trigger a reimport), and the importer will automatically apply the settings in the table above.

## Common Variants

- **Applying the same settings manually**: Textures whose paths do not contain `UI` will not be processed. To achieve the same result, manually set Texture Type to Default, disable Generate Mip Maps, set Alpha Source to From Input, and check Alpha Is Transparency in the Inspector.
- **Atlases coexisting with the Sprite type**: Atlas textures exported by FairyGUI should remain inside the UI directory so the postprocessor takes over; Sprite atlas assets are recommended to be placed outside the UI directory to avoid being rewritten to the Default type.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| Texture import settings never change | The macro `ENABLE_UI_FAIRYGUI` is not defined, so the entire postprocessor class is not compiled | Define the macro in Player Settings / csproj, then reimport |
| Texture import settings unchanged even though the macro is defined | The texture path does not contain `Assets/<BundlesPath>/UI` | Move the texture into the UI asset directory and Reimport |
| Mipmap unexpectedly disabled | The texture is located inside the UI directory; this is the postprocessor's forced behavior | If mipmaps are needed, move the texture out of the UI directory |
| Inspector panel "keeps repainting" | `Repaint()` is called in `OnInspectorGUI` | This is expected behavior; see the code above, which is used for real-time display of runtime data |

## Background

`FairyGUIPackageComponent` is this package's runtime package management component (a `GameFrameworkComponent` subclass, menu `GameFrameX/FairyGUIPackage`). Internally it maintains two dictionaries, `m_UILoadedPackages` and `m_UIPackageLoading`, which handle package loading, caching, and concurrent deduplication; the Inspector's continuous repainting exists precisely to make these runtime states visible in the editor. For the component's own load/unload usage, see [FairyGUIPackageComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPackageComponent.cs#L45-L56).
