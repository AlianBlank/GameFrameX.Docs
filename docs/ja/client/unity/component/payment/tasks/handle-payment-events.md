# 支払い結果イベントの処理方法

`PaymentComponent` で 4 つの支払いイベント（購入成功、購入失敗、購入履歴照会結果、購入消費結果）を購読し、コールバック内で `PaymentEventArgs.ResultCode` に基づいて処理を振り分け、`PurchaseToken` を使って消費を完了します。すべての API は [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64) と [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66) で定義されています。

## 前提条件

- シーンに GameFrameX ルートオブジェクトが存在し、`PaymentComponent` がアタッチされていること（メニュー `GameFrameX/Payment`。このコンポーネントを使用するには `GameFrameXPaymentCroppingHelper` も同時に存在する必要があります）。
- `Init()` を呼び出して支払いマネージャーを初期化し、`IsReady()` が `true` を返してから購入を開始します：

```csharp
// シグネチャ：public void Init(bool isDebug = false, bool isClientVerify = true)
// シグネチャ：public bool IsReady()
paymentComponent.Init(isDebug: false, isClientVerify: true);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115)

## 操作手順

1. `PaymentComponent` の参照を取得します（例：GameFrameX モジュールのエントリ経由）。
2. ゲーム起動時にイベントを購読し、破棄時にそれと対称に購読解除します（`PaymentComponent` は内部の `IPaymentManager` に直接透過します）：

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseSuccess += OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed += OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult += OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult += OnConsumePurchaseResult;

// 終了/破棄時
paymentComponent.OnPurchaseSuccess -= OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed -= OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult -= OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult -= OnConsumePurchaseResult;
```

イベントのコンポーネント上での実際の宣言は次の通りです（`add`/`remove` はそのままマネージャーへ転送されます）：

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}

public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L64)

3. コールバック内で `ResultCode` に基づいて分岐処理を行い、`PaymentEventArgs` のフィールドからデータを取得します：

```csharp
private void OnPurchaseSuccess(object sender, PaymentEventArgs e)
{
    // e.ProductId / e.OrderId / e.PurchaseToken / e.PurchaseData / e.CustomData
}

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    switch (e.ResultCode)
    {
        case PaymentResultCode.Cancelled:
            // ユーザーが自発的にキャンセル、通常はサイレントに処理
            break;
        case PaymentResultCode.NetworkError:
        case PaymentResultCode.ServiceUnavailable:
            // 後でもう一度試すよう案内を表示
            break;
        case PaymentResultCode.ItemAlreadyOwned:
        case PaymentResultCode.VerifyFailed:
        default:
            // e.ErrorMessage を表示または報告に使用
            break;
    }
}
```

4. 単発商品（消費型）の付与に成功した後、コールバック内の `PurchaseToken` で `ConsumePurchase` を呼び出して購入を消費します。その結果も同様に `OnConsumePurchaseResult` イベントで返されます：

```csharp
// シグネチャ：public void ConsumePurchase(string purchaseToken)
paymentComponent.ConsumePurchase(e.PurchaseToken);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L133-L152)

| 値 | 意味 |
|------|------|

## よくあるバリエーション

- **補填/購入の復元**：`QueryPurchases(PaymentProductType)` を呼び出した後、`OnQueryPurchasesResult` を監視し、`ResultCode == PaymentResultCode.Success` の過去の注文を一つずつ付与して `ConsumePurchase(e.PurchaseToken)` を実行します。
- **結果コードのみが必要な場合**：`OnPurchaseSuccess` と `OnPurchaseFailed` はどちらも同じ `PaymentEventArgs` 構造を持っており、失敗時はさらに `ErrorMessage` を利用します。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| ログに `You are using DefaultPaymentManager which is a stub...` と表示される | Editor/非モバイルプラットフォームでスタブ実装にフォールバックし、イベントが発火しない | チャネル実装（Google/Apple など）を組み込むか、実機で検証する |
| ログに `Pay Manager is invalid.` と表示される | マネージャーモジュールが正しくロードされていない | `PaymentComponent` とストリッピング補助コンポーネントが揃っているか確認する |
| ログに `Purchase token is null or empty.` と表示される | `ConsumePurchase` の呼び出しで空のトークンを渡した | コールバックで返される `e.PurchaseToken` を使用する |

上記の警告/エラーの原文は [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L48) と [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L152) に由来します。

## 検証

- 購読後に `Buy(new PurchaseParams(...))` を一度実行し、`OnPurchaseSuccess` または `OnPurchaseFailed` が少なくとも一度は発火すること、また `e.ProductId`・`e.OrderId` が実行時のパラメータと一致することを確認します。
- `ConsumePurchase` の呼び出し後、`OnConsumePurchaseResult` が返ってきて `ResultCode == PaymentResultCode.Success` であることを確認します。

## 背景

`PaymentComponent` は薄いラッパーです。4 つのイベントは `add`/`remove` アクセサーを通じてプラットフォーム実装へ直接転送されます（Android は `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`、iOS/macOS は `Apple.Runtime.ApplePaymentManager`、WebGL/PC にはそれぞれ対応する実装があり、その他のプラットフォームは `DefaultPaymentManager` のスタブへフォールバックします）。そのためイベント処理ロジックはプラットフォーム非依存で、コンポーネント層でまとめて購読するだけで済みます。
