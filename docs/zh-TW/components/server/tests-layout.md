## 執行測試

### 前置條件

- 已安裝 .NET SDK（版本與各受測專案的 `TargetFramework` 相符）。
- 儲存庫根目錄具備可還原的 NuGet 來源。

### 步驟

1. 還原相依套件並進入測試目錄：

```bash
dotnet restore Tests/GameFrameX.Tests/GameFrameX.Tests.csproj
cd Tests/GameFrameX.Tests
```

2. 執行所有測試：

```bash
dotnet test --nologo
```

3. 依名稱篩選以執行單一測試類別（例如僅執行 `LNumberFixTest`）：

```bash
dotnet test --filter "FullyQualifiedName~LNumberFixTest"
```

4. 啟用覆蓋率收集：

```bash
dotnet test --collect:"XPlat Code Coverage"
```

報告預設輸出至 `TestResults/<guid>/coverage.cobertura.xml`。

### 常用變化

| 情境 | 指令片段 |
|------|------|
| 詳細記錄輸出 | `dotnet test --logger "console;verbosity=detailed"` |
| 僅執行指定命名空間 | `dotnet test --filter "FullyQualifiedName~GameFrameX.Tests.NetWork.Kcp"` |
| 以偵錯模式執行 | `dotnet test -c Debug` |
| 排除整合測試 | `dotnet test --filter "FullyQualifiedName!~Integration"` |

## 測試撰寫範例

測試類別繼承自一般類別，使用 `[Fact]` 標記測試案例，並以 `Assert.*` 進行斷言。以下是取自 `Tests/GameFrameX.Tests/LNumberFixTest.cs` 的實際片段：

```csharp
using GameFrameX.Utility;
using Xunit;

namespace GameFrameX.Tests
{
    public class LNumberFixTest
    {
        [Fact]
        public void TestCreateNegativeNumbers()
        {
            var negativeNumber = LNumber.Create(-123, -4567);

            Assert.True(negativeNumber.Raw < 0, "Raw value should be negative");
            Assert.True((double)negativeNumber < 0, "Double value should be negative");
            Assert.Equal(-124, negativeNumber.Floor);
            Assert.Equal(-123, negativeNumber.Ceiling);
            Assert.Equal(-123, (long)negativeNumber);
        }
    }
}
```

## 常見錯誤

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| `error NU1605: Detected package downgrade` | 解決方案根目錄未還原至統一版本 | 在儲存庫根目錄執行 `dotnet restore`，而非僅在測試目錄執行 |
| `Could not load file or assembly 'GameFrameX.Core'` | 受測專案尚未建置 | 先以 `dotnet build` 建置整個解決方案，再執行 `dotnet test` |
| 測試探索數量為 0 | 缺少 `xunit.runner.visualstudio` 或 `Microsoft.NET.Test.Sdk` | 檢查 csproj 中的 PackageReference 是否被註解或刪除 |
| `coverlet` 未產生任何輸出 | 未指定 `--collect` 參數 | 加上 `--collect:"XPlat Code Coverage"` |
| `MongoDb` 測試連線失敗 | 本機沒有執行中的 MongoDB 執行個體 | 測試前先啟動 MongoDB，或執行 `docker run -p 27017:27017 mongo` |

## 驗證

- `dotnet test` 以結束代碼 0 結束，並輸出 `Passed: <N>, Failed: 0, Skipped: 0`。
- `coverage.cobertura.xml` 產生於 `TestResults/` 目錄下，且檔案大小不為零。
- IDE（Rider / Visual Studio）中的測試總管顯示與各目錄一一對應的測試套件。
