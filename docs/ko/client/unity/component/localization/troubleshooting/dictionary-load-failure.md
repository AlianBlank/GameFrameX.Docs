# 사전 로드 실패(LoadDictionaryFailureEventArgs) 시 대처 방법

현지화 사전 리소스 로드에 실패하면 프레임워크가 `LoadDictionaryFailureEventArgs` 이벤트를 발생시킵니다. 이 이벤트는 세 개의 필드를 가지고 있습니다 — `DictionaryAssetName`(실패한 사전 리소스 이름), `ErrorMessage`(오류 메시지), `UserData`(로드 요청 시 전달된 사용자 정의 데이터). 문제 해결 시 이 세 필드를 먼저 읽으면 "리소스 이름 구성 오류"인지 "리소스 누락/로드 예외"인지 파악할 수 있습니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| `ErrorMessage`가 리소스가 존재하지 않음/찾을 수 없음을 표시함 | 사전 리소스가 생성되지 않았거나 리소스 패키지에 포함되지 않음 | 아래 [해결 단계 1]에 따라 리소스가 로드 가능한지 확인 |
| `DictionaryAssetName`이 비어 있거나 예상과 다름 | 로드 호출 시 잘못된 리소스 이름이 전달됨 | 아래 [해결 단계 2]에 따라 호출부에서 전달한 리소스 이름 재확인 |
| `UserData`가 비어 있어 어느 로드가 실패했는지 구분할 수 없음 | 로드 요청 시 사용자 정의 데이터를 전달하지 않음 | 아래 [해결 단계 3]에 따라 로드 호출부에 식별용 객체 전달 |
| 이벤트가 한 번도 트리거되지 않고 성공 이벤트도 없음 | 이벤트가 구독되지 않았거나 로드 프로세스가 시작되지 않음 | 아래 [해결 단계 4]에 따라 구독 및 로드 호출 확인 |

필드 설명(이벤트 클래스의 실제 정의에서 발췌):

| 속성 | 타입 | 생성 시 기본값 | 설명 |
|------|------|--------------|------|
| `DictionaryAssetName` | `string` | `null` | 로드에 실패한 사전 리소스 이름 |
| `ErrorMessage` | `string` | `null` | 오류 메시지(구체적인 텍스트는 하위 로드 체인에서 반환됨) |
| `UserData` | `object` | `null` | 사용자 정의 데이터 |

## 해결 단계

### 1. ErrorMessage로 리소스 로드 가능 여부 확인

이벤트 콜백에서 세 필드를 출력하고 먼저 `ErrorMessage`의 구체적인 내용을 확인합니다. 리소스가 존재하지 않는다는 내용이라면 `DictionaryAssetName`에 해당하는 사전 리소스가 생성되지 않았거나 패키지에 포함되지 않은 것이므로, 코드를 수정하는 대신 해당 리소스의 생성/패키징 구성을 확인하세요.

```csharp
private void OnLoadDictionaryFailure(object sender, GameEventArgs e)
{
    var args = (LoadDictionaryFailureEventArgs)e;
    UnityEngine.Debug.LogError(
        $"사전 로드 실패: {args.DictionaryAssetName}, 오류: {args.ErrorMessage}");
}
```

Source: [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L36-L58)

참고: 구독/해제 인터페이스는 GameFrameX 이벤트 컴포넌트에서 제공하며, 구독 시 `LoadDictionaryFailureEventArgs.EventId`를 이벤트 식별자로 사용합니다. 콜백 매개변수 타입은 `GameEventArgs`이며, 해당 이벤트 타입으로 강제 캐스팅한 후 필드를 읽습니다(이벤트 기본 클래스와 `using GameFrameX.Event.Runtime;`은 모두 해당 이벤트 클래스 파일의 실제 참조에서 가져온 것입니다).

### 2. DictionaryAssetName의 출처 재확인

`DictionaryAssetName`의 값은 로드 요청 시 전달된 `dataAssetName`과 동일합니다(아래 `Create` 팩토리 메서드 참조). 따라서 "이름이 맞지 않는" 경우 로드를 호출한 해당 코드 라인으로 돌아가 전달된 리소스 이름 문자열을 확인하세요(대소문자, 경로 접두사 및 접미사에 유의).

```csharp
public static LoadDictionaryFailureEventArgs Create(string dataAssetName, string errorMessage, object userData)
{
    LoadDictionaryFailureEventArgs loadDictionaryFailureEventArgs = ReferencePool.Acquire<LoadDictionaryFailureEventArgs>();
    loadDictionaryFailureEventArgs.DictionaryAssetName = dataAssetName;
    loadDictionaryFailureEventArgs.ErrorMessage = errorMessage;
    loadDictionaryFailureEventArgs.UserData = userData;
    return loadDictionaryFailureEventArgs;
}
```

Source: [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L87-L102)

### 3. UserData로 여러 로드 구분

같은 프레임에서 여러 사전을 로드하는 경우 `DictionaryAssetName`만으로는 호출 지점을 파악하기에 부족할 수 있습니다. 로드를 요청할 때마다 식별 가능한 `userData`(예: 호출자 객체 또는 열거형 마커)를 전달하면, 실패 이벤트에서 그대로 돌려받아 어느 호출이 실패했는지 확인할 수 있습니다.

### 4. 이벤트가 실제로 구독되었는지, 로드가 실제로 시작되었는지 확인

실패 이벤트도 성공 이벤트(`LoadDictionarySuccessEventArgs`)도 발생하지 않는다면 먼저 다음을 확인하세요:

1. 이벤트 리스너가 구독되어 있는지(`LoadDictionaryFailureEventArgs.EventId`를 식별자로 사용);
2. 사전 로드 호출이 실제로 실행되는지(호출 전후에 로그를 추가하여 확인 가능);
3. 사용 중인 어셈블리가 스트리핑되지 않았는지 — 본 컴포넌트는 `GameFrameXLocalizationCroppingHelper`를 통해 타입을 명시적으로 보존하므로, 스트리핑 구성을 커스터마이즈한 경우 `LoadDictionaryFailureEventArgs`가 제외되지 않도록 해야 합니다:

```csharp
_ = typeof(ILocalizationManager);
_ = typeof(LoadDictionaryFailureEventArgs);
_ = typeof(LoadDictionarySuccessEventArgs);
```

## 검증

- 사전 로드를 다시 트리거한 후 실패 콜백이 더 이상 호출되지 않거나, 콘솔에 출력하던 실패 로그가 더 이상 나타나지 않습니다.
- 해당 사전 리소스에 대해 `LoadDictionarySuccessEventArgs`(성공 이벤트, 필드는 `DictionaryAssetName`, `Duration`, `UserData`)가 발생하면 로드 체인이 복구된 것입니다.
- `LocalizationComponent`에서 현지화 텍스트를 다시 읽으면 사전의 항목을 가져올 수 있습니다.

로드 성공/진행 이벤트와 현지화 컴포넌트의 전반적인 사용법에 대해서는 저장소의 중국어 안내 문서 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.zh-CN.md#L311-L313)를 참조하세요.

## 배경

이 이벤트는 `GameEventArgs`를 상속하며, 인스턴스는 `ReferencePool` 참조 풀에서 획득하고(`ReferencePool.Acquire<LoadDictionaryFailureEventArgs>()`), `Clear()`에서 세 필드를 `null`로 재설정한 뒤 풀로 반납됩니다. 따라서 콜백에서 이벤트 객체 자체를 캐시하지 말고 필드 값만 읽거나 복사해야 하며, 이벤트가 디스패치된 후 객체는 재사용됩니다.
