# luban.conf 的理解與修改方法

`luban.conf` 是 GameFrameX.Config 的主設定檔。它向 Luban 工具鏈指示要在何處讀取 Excel、使用哪些資料/程式碼目標，以及要將產出輸出至哪個目錄。修改此檔案後，只要執行 `gen-*.bat` / `gen-*.sh`,即可依照新規則產生用戶端與伺服器的程式碼。

## 前置條件

- 已複製 [GameFrameX/GameFrameX.Config](https://github.com/GameFrameX/GameFrameX.Config) 儲存庫，且根目錄中存在 `luban.conf`。
- 已安裝 .NET 執行階段(用於執行 `Tools/Luban.exe`)。
- 已理解 `groups`(用戶端/伺服器的資料群組)、`targets`(產生目標)、`commands`(要執行的命令)這 3 個頂層概念。

## 頂層欄位概觀

| 欄位 | 作用 | 典型值 |
|------|------|--------|
| `groups` | 將表格依「用戶端/伺服器」分組，並在產生時以群組為單位進行篩選 | `c`(用戶端)、`s`(伺服器) |
| `schemaFiles` | Luban 要載入的 schema 項目(`Defines`、`__tables__` 等) | 參考下方程式碼區塊 |
| `dataDir` | Excel 資料的根目錄 | `Excels` |
| `targets` | 產生目標的集合。每個目標對應一組程式碼/資料產出 | `server`、`client`、`all` |
| `toolPath` | Luban.dll 的相對路徑 | `/../Config/Tools/Luban.dll` |
| `UNITY_ASSETS_PATH` | Unity 專案 Assets 目錄的絕對路徑(執行時範本) | 保持空白。腳本執行時會被替換 |
| `SERVER_PATH` | 伺服器專案根目錄的絕對路徑(執行時範本) | 保持空白。腳本執行時會被替換 |
| `commands` | 每個產生命令對應 1 個 target,並包含命令列引數與選項 | 參考下方程式碼區塊 |

出處： [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L95)

## 主要欄位分段解說

### 1. groups:資料的分配方式

`groups` 決定各表格屬於「用戶端」「伺服器」或「兩端共用」中的哪一種。`default: true` 表示該群組中的所有表格預設都會成為產生命令的對象。

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

出處： [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

> 各表格屬於哪個群組，是透過 Excel 內的 `__xxx__` 標記欄位來表示。這裡僅定義「存在哪些群組名稱」。

### 2. schemaFiles:要載入的定義

`schemaFiles` 是 Luban 載入 schema 所需的項目。順序不限，但下列 4 行為必填:`Defines`(內建型別目錄)、`__tables__.xlsx`(表格清單)、`__beans__.xlsx`(複合結構)、`__enums__.xlsx`(列舉型別)。

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

出處： [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

### 3. targets:產生目標的定義

每個 target 是「一組資料 + 一組產出」的具名套件。`topModule` 是產生的命名空間，`manager` 是進入點類別名稱(執行時以 `TablesComponent` 或 `Tables` 單例載入)。

```json
"targets": [
    { "name": "server", "manager": "TablesComponent", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "manager": "TablesComponent", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "manager": "Tables",         "groups": ["c","s"], "topModule": "cfg" }
]
```

出處： [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L35-L61)

### 4. commands:要執行的產生命令

`commands` 是實際傳遞給 `Luban.exe` 的命令列陣列。每筆記錄對應 1 個 `target`,並以 `active: true/false` 切換啟用/停用。`%UNITY_ASSETS_PATH%` 與 `%SERVER_PATH%` 是佔位符，產生腳本會在呼叫前將其替換為絕對路徑。

```json
"commands": [
    {
        "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
        "target": "server", "active": true
    },
    {
        "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate",
        "target": "client", "active": true
    }
]
```

出處： [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

常用選項：

- `--dataTarget json | bin` ―― 資料的儲存格式。`json` 可讀性高，`bin` 體積較小。
- `--codeTarget cs-simple-json | cs-dotnet-json | cs-bin` ―― 產生的 C# 載入程式碼風格。用戶端使用 `cs-simple-json`,伺服器使用 `cs-dotnet-json`,啟用二進位格式時使用 `cs-bin`。
- `--validationFailAsError true` ―― 驗證失敗時不只發出警告，而是立即視為錯誤。
- `--xargs outputDataDir=...` / `--xargs outputCodeDir=...` ―― 資料與程式碼產出的輸出目錄。支援 `%SERVER_PATH%`、`%UNITY_ASSETS_PATH%` 佔位符。

## 常見變化

### 新增群組(例如：多語言子用戶端)

在 `groups` 陣列中新增 1 個項目。此時，請別忘了在表格標頭的 `__xxx__` 欄位為對應表格加上新的群組名稱。

```json
{ "names": ["c"], "default": true },
{ "names": ["s"], "default": true },
{ "names": ["c_cn"], "default": true }
```

出處： [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

### 切換 JSON 與二進位產出

將對應 command 中的 `--dataTarget json --codeTarget cs-simple-json`(或 `cs-dotnet-json`)替換為 `--dataTarget bin --codeTarget cs-bin`,並將 `active` 設為 `true`。

### 修改輸出目錄

直接修改 `commands[].command` 中的 `outputDataDir` / `outputCodeDir`。若想重複使用腳本中統一的路徑，請保留 `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` 佔位符不變。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 執行 `gen-*.bat` 時顯示 `ToolPath not found` | `toolPath` 的相對路徑寫法錯誤，或儲存庫中不存在 `Tools/Luban.dll` | 維持預設的 `/../Config/Tools/Luban.dll`,且不要移動 `Tools/` 目錄 |
| 產生的程式碼找不到命名空間 | `targets[].topModule` 拼字錯誤。用戶端與伺服器的 `topModule` 必須不同 | 用戶端為 `Hotfix.Config`,伺服器為 `GameFrameX.Config`。請依自身的命名空間修改 |
| 用戶端專案未產生程式碼 | 用戶端 target 的 `groups` 未包含此表格所屬的群組 | 在 `targets[client].groups` 中加入對應的群組名稱，或調整表格的 `__xxx__` 欄位 |
| `commands` 中的 `active` 全部為 `false` | 所有命令皆已停用 | 將要執行的命令改為 `true` |
| 佔位符 `%UNITY_ASSETS_PATH%` 未被替換 | 未透過 `gen-*.bat` / `gen-*.sh`,而是直接雙擊執行 `Luban.exe` | 請從儲存庫內附的產生腳本執行。腳本會進行佔位符替換 |

## 背景(選讀)

`luban.conf` 的 schema 由 Luban 工具鏈所規範，欄位含義與 Luban 官方相同。本儲存庫額外擴充了 `toolPath`、`UNITY_ASSETS_PATH`、`SERVER_PATH`、`commands[].active` 這 4 個欄位，用於在 GameFrameX 的工作流程中，透過 `gen-*.bat` / `gen-*.sh` 統一控制產生命令與佔位符替換。
