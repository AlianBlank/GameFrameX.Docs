# 元件無法新增或重複掛載怎麼辦

遇到 `CoroutineComponent` 新增失敗、新增後立刻被移除、或在 Inspector 中出現「Can't add component」等情況時，通常與 Unity 重複掛載限制、`[DisallowMultipleComponent]` 特性或 GameFrameX 框架自動掛載流程有關。本頁提供常見症狀的快速定位與修復方法。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `AddComponent<CoroutineComponent>()` 後出現 `Can't add component ... because a MonoBehaviour is already attached` 錯誤 | 同一 GameObject 已存在該元件，`CoroutineComponent` 標有 `[DisallowMultipleComponent]` | 見下方「先移除再新增」小節 |
| 手動 AddComponent 後，場景重新載入或切換場景後元件消失 | 沒有走 GameFrameX 框架流程，該元件並非由框架的 `GameFrameXAutoComponent` 掃描器掛載 | 見下方「由框架自動掛載」小節 |
| iOS / IL2CPP 打包後執行階段找不到 `CoroutineComponent` 類型 | 被 Unity 連結器剝離掉了 | 見下方「打包後遺失」小節 |
| `CoroutineComponent` 出現在場景中多個 GameObject 上，看起來「重複掛載」 | 每個 GameObject 上各掛一份是允許的；實際的重複只在「同一 GO」上才會被拒絕 | 見下方「區分『多 GO』與『同 GO 重複』」小節 |

## 修復步驟

### 先移除再新增(同 GO 重複掛載)

`CoroutineComponent` 在原始碼中標註了 `[DisallowMultipleComponent]`,這是 MonoBehaviour 內建特性，禁止在同一 GameObject 上掛載多份。

```csharp
// 報錯: Can't add component 'CoroutineComponent' because a MonoBehaviour is already attached.
// 修復: 先移除已有的,再新增,或者直接複用已有的引用
if (gameObject.TryGetComponent<CoroutineComponent>(out var exist))
{
    // 已有的就直接使用,不要重複 AddComponent
}
else
{
    exist = gameObject.AddComponent<CoroutineComponent>();
}
```

來源： [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L15)

### 由框架自動掛載

一般情況下，**不要**在業務程式碼裡手動 `AddComponent<CoroutineComponent>()`,而是由 GameFrameX 框架透過 `[GameFrameXAutoComponent(-6500)]` 特性在框架啟動時自動掛載到框架入口 GameObject 上。元件會在 `Awake()` 內部設定 `IsAutoRegister = false`,表示不參與執行階段的二次註冊流程。

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Coroutine")]
[GameFrameXAutoComponent(-6500)]
public class CoroutineComponent : GameFrameworkComponent
{
    protected override void Awake()
    {
        IsAutoRegister = false;
        base.Awake();
    }
}
```

來源： [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L110)

如果一定要手動掛載，請確保：
1. GameObject 處於啟用狀態。
2. 目前沒有其他同名元件實例(見上一節)。
3. 在能取得 `GameFrameworkComponent` 基底類別所在的宿主 GameObject 上掛載，避免與框架實例重複。

### 打包後遺失

IL2CPP / iOS 連結器可能會剝離掉未被明確引用的 MonoBehaviour 類型。原始碼裡用一個空的 `MonoBehaviour` 搭配 `[Preserve]` 來防止類型被刪除：

```csharp
[Preserve]
public class GameFrameXCoroutineCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(CoroutineComponent); // 強制保留 CoroutineComponent
    }
}
```

來源： [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

修復：
1. 確認場景中存在掛著 `GameFrameXCoroutineCroppingHelper` 的 GameObject(或程式碼中明確引用過 `CoroutineComponent`)。
2. Unity Player Settings → Managed Stripping Level 在 iOS 上不要設為比 `Low` / `Medium` 更激進的層級，否則需要額外設定 `link.xml`,將命名空間 `GameFrameX.Coroutine.Runtime` 排除在外。

### 區分「多 GO」與「同 GO 重複」

- **多 GO 上各掛一份**(例如每個 UI 面板各掛一份)：這是合法的，各自管理各自的協程。
- **同一 GO 上掛兩份**：會出現 `Can't add component` 錯誤，見上方處理方式。

如果你以為框架「重複掛載」了多個實例，可以在 Hierarchy 裡搜尋 `Coroutine`,確認它們確實在不同的 GameObject 上；若全部在同一個 GO 上，只保留一份就夠了。

## 驗證

修復後用以下方式確認：

1. 在 Unity Console 中不再出現 `Can't add component` 錯誤。
2. 進入 Play Mode 後，能在 Hierarchy 裡看到框架入口 GameObject 上的 `CoroutineComponent`(標有 `GameFrameX/Coroutine` 選單名稱)。
3. 呼叫 `StartCoroutine` 後協程能正常執行，`StopCoroutine(IEnumerator)` 使用同一引用能成功停止——這表示元件已正確掛載並被框架接管。
