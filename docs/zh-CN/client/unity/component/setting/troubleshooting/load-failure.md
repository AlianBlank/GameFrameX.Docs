# 配置加载失败怎么办

当 `SettingComponent.Start()` 中 `m_SettingManager.Load()` 返回 `false` 时，控制台会输出 `Load settings failure.`，说明配置加载流程失败。本页帮助你快速定位失败原因并修复。

## 快速诊断

| 症状（日志原文） | 原因 | 修复 |
|------|------|------|
| `Setting manager is invalid.` | `ISettingManager` 模块未注册，或 GameFramework 未启动 | 见 [模块未注册](#模块未注册-setting-manager-is-invalid) |
| `Can not create setting helper.` | `SettingHelper` 的类型名配置错误、程序集未打入运行时、或自定义 Helper 类找不到 | 见 [Helper 创建失败](#helper-创建失败-can-not-create-setting-helper) |
| `Load settings failure.` | `ISettingHelper.Load()` 实现返回 `false`（读取 / 反序列化失败） | 见 [Load 实现返回 false](#load-实现返回-false-load-settings-failure) |
| `Setting helper is invalid.` 异常 | 在调用 `Load()` / `Save()` 前没有先 `SetSettingHelper()` | 见 [未设置 Helper 抛异常](#未设置-helper-抛异常-setting-helper-is-invalid) |
| 平台小游戏存储无数据 | PlayerPrefs / 小游戏存储后端为空，没有可加载内容 | 见 [存储后端为空](#存储后端为空) |

## 模块未注册（Setting manager is invalid）

`SettingComponent.Awake()` 通过 `GameFrameworkEntry.GetModule<ISettingManager>()` 获取管理器。若返回 `null`，会打印 `Setting manager is invalid.` 并直接 return，后续 `Start()` 不会再触发 Load。

修复步骤：

1. 确认场景中存在 `GameFrameX.Runtime.GameFrameworkEntry`（或其等价启动组件），框架入口必须先于 `SettingComponent` 启动。
2. 确认 `SettingManager` 模块在框架的程序集列表中（它位于 `Runtime/Setting/Setting/SettingManager.cs`，命名空间 `GameFrameX.Setting.Runtime`），未被打入包外。
3. 若使用自定义 GameFramework 启动流程，需要把 `SettingManager` 加入到启动模块列表。

## Helper 创建失败（Can not create setting helper）

`SettingComponent.Awake()` 调用 `Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper)`；若返回 `null`，打印 `Can not create setting helper.`。

```csharp
// 来源：Runtime/Setting/SettingComponent.cs#L87-L92
SettingHelperBase settingHelper = Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper);
if (settingHelper == null)
{
    Log.Error("Can not create setting helper.");
    return;
}
```

修复步骤：

1. 在 Inspector 上检查 `SettingComponent` 的 `Setting Helper Type Name`，默认值是 `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`。
2. 如果使用了自定义 Helper，确认自定义类继承自 `SettingHelperBase`（`Runtime/Setting/SettingHelperBase.cs#L43`），并且类型全名（含命名空间）拼写一致。
3. 确认自定义 Helper 所在的程序集包含在 Player / 小游戏的运行时构建中，没有被剥离。
4. 如果改用 `m_CustomSettingHelper` 字段注入，需把它拖到 Inspector 上，并保证场景中只有一个 `SettingComponent`。

## Load 实现返回 false（Load settings failure）

当 Helper 创建成功，但 `Load()` 内部失败时，`SettingComponent.Start()` 打印 `Load settings failure.`：

```csharp
// 来源：Runtime/Setting/SettingComponent.cs#L102-L108
private void Start()
{
    if (!m_SettingManager.Load())
    {
        Log.Error("Load settings failure.");
    }
}
```

`SettingManager.Load()` 内部仅委托给当前 Helper：

```csharp
// 来源：Runtime/Setting/Setting/SettingManager.cs#L145-L150
public bool Load()
{
    EnsureSettingHelper();
    return m_SettingHelper.Load();
}
```

按 Helper 类型分别处理：

- **PlayerPrefsSettingHelper**：`Load()` 永远返回 `true`（[来源](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L86-L89)）。若你看到这条错误，请先确认当前真正生效的 Helper 类不是自定义实现。
- **自定义 Helper**：在 `Load()` 中逐项排查文件是否存在、读取权限、反序列化异常；建议增加详细日志确认失败步骤。
- **小游戏平台 Helper**（WeChat / DouYin / KuaiShou / Alipay）：通过 `SettingStorageBackendFactory.Create()` 获取 `ISettingStorageBackend`，确认目标平台宏已定义、对应 SDK 已被正确接入。

## 未设置 Helper 抛异常（Setting helper is invalid）

`SettingManager` 在未调用 `SetSettingHelper()` 时调用 `Load()` / `Save()` / `GetAllSettingNames()` 会抛 `GameFrameworkException("Setting helper is invalid.")`：

```csharp
// 来源：Runtime/Setting/Setting/SettingManager.cs#L130
throw new GameFrameworkException("Setting helper is invalid.");
```

仅在你绕过 `SettingComponent`、直接 new `SettingManager` 时可能遇到。修复方法：先调用 `SetSettingHelper(yourHelper)`，再调用 `Load()`；或者直接使用 `SettingComponent`，它会在 `Awake()` 内自动注入。

## 存储后端为空

`PlayerPrefsSettingHelper` 通过 `SettingStorageBackendFactory.Create()` 懒加载 `ISettingStorageBackend`。如果工厂返回 `null` 或平台 SDK 未初始化，调用 `GetString` / `SetString` 等接口会抛异常，从而被 `Load()` / `Save()` 透传为 `false`。

修复步骤：

1. 检查对应平台宏是否启用（`UNITY_WEBGL`、小游戏平台宏等）。
2. 确认平台 SDK 在 `Awake()` / `Start()` 之前已初始化完成。
3. 在 `PlayerPrefsSettingHelper` 之前注入测试用 `ISettingStorageBackend`，可参考 `SetStorageBackendForTests(...)` 的用法。

## 验证

完成修复后，按以下顺序验证：

1. 启动游戏，控制台不再出现 `Load settings failure.` 或上文列出的错误日志。
2. 调用 `SettingComponent.GetAllSettingNames()` 能正常返回（PlayerPrefs 实现始终返回空数组，属于预期）。
3. 使用 `SettingComponent.Save()` 后，重启游戏，调用 `HasSetting(name)` / `GetString(name)` 能读回之前写入的值。
4. 若仍有异常，保留完整堆栈信息，并确认问题不是出在 `SettingHelperBase` 派生的具体类上。
