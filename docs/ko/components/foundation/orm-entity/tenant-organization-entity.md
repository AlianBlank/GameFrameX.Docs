# 테넌트/조직 격리 엔티티 기본 클래스를 사용하는 방법

`EntityTenantOrganizationBase`(또는 그 제네릭 버전)를 상속하면 엔티티에 다중 테넌트 격리 및 조직 격리 기능을 동시에 부여할 수 있습니다. 자동으로 `TenantId` 및 `CreateOrganizationId` 필드를 포함하고, `ITenantIdFilter` 및 `IOrganizationIdFilter` 인터페이스를 구현하여, ORM 필터와 함께 테넌트/조직별로 데이터를 자동으로 필터링할 수 있습니다.

## 사전 조건

- NuGet 패키지가 설치되어 있어야 합니다: `GameFrameX.Foundation.Orm.Entity`
- ORM 프레임워크에 테넌트 컨텍스트(현재 `TenantId`)와 조직 컨텍스트(현재 `CreateOrganizationId`)가 구성되어 있어야 필터가 자동으로 주입될 수 있습니다
- 데이터베이스 테이블에 `TenantId`, `CreateOrganizationId` 열이 존재해야 합니다(Nullable `long?`)

## 작업 단계

1. **엔티티 클래스가 `EntityTenantOrganizationBase<TKey>`를 상속하도록 합니다**. 기본 키 타입을 지정합니다(보통 `long` 또는 `Guid`). 엔티티는 자동으로 `TenantId`, `CreateOrganizationId` 두 개의 nullable `long?` 속성을 얻습니다.

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L44-L55)

2. **(선택 사항) 엔티티에 `[TenantTable]` 특성을 표시합니다**. ORM은 이를 기반으로 테넌트 격리 기능을 활성화합니다: 테넌트 필터 자동 주입, 테넌트 식별자 강제 기록, 테넌트 간 접근 차단.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
}
```

Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L63-L72)

3. **비제네릭 버전을 사용합니다(기본 키가 기본 클래스에서 결정될 때)**. `EntityBase`가 이미 기본 기본 키 타입을 제공하는 경우, `TKey`를 지정하지 않고 `EntityTenantOrganizationBase`를 직접 상속할 수 있습니다.

```csharp
public class GameArea : EntityTenantOrganizationBase
{
    public string AreaName { get; set; }
    public bool IsActive { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L64-L76)

4. **필요에 따라 테넌트 및 조직 필드를 기록합니다**. ORM 인터셉터는 추가/조회 시 현재 컨텍스트로 `TenantId`와 `CreateOrganizationId`를 자동으로 덮어씁니다. 수동 제어가 필요한 경우 비즈니스 코드에서 값을 할당할 수 있습니다.

```csharp
var order = new GameOrder
{
    OrderNo      = "O-20260101-0001",
    Amount       = 99.5m,
    CreatedTime  = DateTime.UtcNow,
    // TenantId와 CreateOrganizationId는 컨텍스트에 의해 자동으로 채워짐
};
```

## 일반적인 변형

| 시나리오 | 기본 클래스 선택 | 설명 |
|------|----------|------|
| 테넌트 격리만 필요하고 조직은 구분하지 않음 | `EntityTenantBase<TKey>` | `ITenantIdFilter` 상속, `CreateOrganizationId` 필드 없음 |
| 조직 격리만 필요 | 사용자 정의 엔티티가 `IOrganizationIdFilter` 구현 | `CreateOrganizationId`만 노출 |
| 테넌트 + 조직 격리 모두 필요 | `EntityTenantOrganizationBase<TKey>` | 이 페이지에서 소개 |
| 기본 키 타입이 프레임워크 기본값에 의해 결정됨 | `EntityTenantOrganizationBase`(비제네릭) | `TKey`를 명시적으로 전달하지 않음 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 쿼리 결과에 다른 테넌트/조직 데이터가 포함됨 | 필터가 활성화되지 않았거나 컨텍스트에 `TenantId`/`CreateOrganizationId`가 주입되지 않음 | ORM 전역 필터 등록 확인; 모든 요청에 테넌트/조직 컨텍스트가 설정되어 있는지 확인 |
| 작성 시 `TenantId`가 항상 `null` | 엔티티 클래스가 동시에 전역 테이블로 표시되었거나 인터셉터 순서 문제 | 테넌트 엔티티에 동시에 `[SystemTable]`를 표시하지 말 것; `[TenantTable]`만 표시 |
| 상속 후 `CreateOrganizationId` 필드를 찾을 수 없음 | 실수로 `EntityTenantBase`(테넌트만)를 상속함 | `EntityTenantOrganizationBase` 또는 그 제네릭 버전 사용 |
| 열 이름이 일치하지 않음 | 테이블 구조에 `TenantId` 또는 `CreateOrganizationId` 열이 없음 | 데이터베이스 마이그레이션에서 해당 nullable `bigint` 열 추가 |

## 배경(선택 사항)

`EntityTenantOrganizationBase`는 `EntityTenantBase`(`TenantId` + `ITenantIdFilter` 제공)도 상속하고 `IOrganizationIdFilter`(`CreateOrganizationId` 제공)도 구현합니다. 두 필터 인터페이스는 ORM 계층에서 인식되며, 쿼리에 자동으로 `WHERE TenantId = ? AND CreateOrganizationId = ?` 조건을 추가하고, 추가 시 두 필드를 자동으로 채웁니다. `[TenantTable]`은 테이블 수준 스위치로, ORM에 이 테이블이 테넌트 격리를 활성화한다고 알려주며, `[SystemTable]`(전역 공유)과 상호 배타적입니다.

다중 테넌트 격리의 전체 설계에 대해서는 《테넌트 격리 엔티티 기본 클래스를 사용하는 방법》을 참조하십시오.
