# What to Do When Command-Line Argument Parsing Fails

When `OptionsBuilder` or `CommandLineArgumentConverter` throws an `ArgumentException` or `ArgumentAlreadyException` while parsing command-line arguments, required-option validation fails, or property value types are incorrect, use the diagnostic table on this page to locate the root cause and fix it.

## Quick Diagnosis

| Symptom (Exception Message / Behavior) | Cause | Fix |
|----------------------|------|------|
| `ArgumentException` in the style of `Argument cannot contain null`, with parameter name `args` | The `args` array contains `null` elements (this should not happen with `Main` entry parameters, but manual construction may introduce them) | See [Remove null from args](#fix-1-remove-null-elements-from-args) |
| `ArgumentException` wrapping "Error while processing arguments: ..." | An exception thrown by another branch of the parsing flow, wrapped by the outer `catch` in `ConvertToStandardFormat` | Inspect `ex.InnerException.Message` and map it to the specific sub-problem; see [Fix 2](#fix-2-investigate-inner-exceptions-during-argument-processing) |
| Process crashes or fields keep default values when required options are not assigned | Required arguments are missing and `skipValidation: true` was not passed | Use `skipValidation` to skip validation, or supply the required arguments; see [Fix 3](#fix-3-supply-required-arguments-or-skip-validation) |
| The same key is assigned twice; the later assignment does not take effect or throws `ArgumentAlreadyException` | The same option is passed repeatedly, or an environment variable conflicts with a same-named command-line key | See [Fix 4](#fix-4-resolve-duplicate-arguments-or-environment-and-command-line-conflicts) |
| A boolean field receives a string other than `"true"`/`"false"` | In `BoolArgumentFormat.Flag` mode, the next token that looks like a value is consumed/unrecognized as a boolean | Pass `--flag=true` explicitly, or switch `BoolArgumentFormat`; see [Fix 5](#fix-5-boolean-argument-parsing-errors) |
| A negative number (e.g., `--offset=-3`) is recognized as an "option key" and the next argument is mistakenly taken as its value | When `IsNegativeNumber` has identified a negative number, `IsOptionToken` returns `false`, but negative-number expressions with spaces may be misjudged | Write the value in the `--offset=-3` form and avoid appending another value after the negative number; see [Fix 6](#fix-6-parsing-errors-with-negative-numbers-and-values-containing-spaces) |
| The value after the key-value pair `--key=` is lost and the field keeps its default value | An empty-string value is treated as "no value" and the next item is skipped | To keep an empty value, use `--key=""` or keep `EnsurePrefixedKeys=true` so that `--key=` lands correctly |

## Fix Steps

### Fix 1: Remove null Elements from args

`ConvertToStandardFormat` throws an `ArgumentException` immediately when it detects `arg == null`:

```csharp
// CommandLineArgumentConverter.ConvertToStandardFormat
if (arg == null)
{
    throw new ArgumentException(LocalizationService.GetString(LocalizationKeys.Exceptions.ArgsCannotContainNull), nameof(args));
}
```

Fix: filter them out before the call:

```csharp
using GameFrameX.Foundation.Options;

var cleanArgs = (args ?? Array.Empty<string>())
    .Where(a => a != null)
    .ToArray();

var options = OptionsBuilder.Create<MyOptions>(cleanArgs);
```

> Source: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L188-L194)

### Fix 2: Investigate Inner Exceptions During Argument Processing

The outer `catch` of `ConvertToStandardFormat` wraps and rethrows any non-`ArgumentException` exception:

```csharp
catch (Exception ex)
{
    throw new ArgumentException(
        LocalizationService.GetString(LocalizationKeys.Exceptions.ProcessingError, ex.Message),
        ex);
}
```

Investigation steps:

1. Catch the outer `ArgumentException` and read `ex.InnerException` to get the real stack trace.
2. If `InnerException` is an `ArgumentAlreadyException`, go to [Fix 4](#fix-4-resolve-duplicate-arguments-or-environment-and-command-line-conflicts).
3. If `InnerException` is reflection/type-conversion related (e.g., `InvalidCastException`, `FormatException`), it usually means the command-line value string cannot be converted to the target property type — check the types of the corresponding fields on `MyOptions` against the passed values.

> Source: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L219-L227)

### Fix 3: Supply Required Arguments or Skip Validation

The second parameter of `OptionsBuilder.Create<TOptions>(args, skipValidation)` controls whether required-option validation is skipped. During development/debugging, or in scenarios where the process should not exit, you can:

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.Create<MyOptions>(args, skipValidation: true);
```

If skipping is not acceptable for your business logic, make sure every option marked as "required" has been passed:

- Use `OptionsDebugger.PrintParsedOptions(opts)` to print the parsing result and check whether the properties have the expected values.
- Note that environment variables act as an "implicit source" that fills in fields, so "seemingly missing command-line arguments" may actually be environment variables taking effect.

> Source: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L67)

### Fix 4: Resolve Duplicate Arguments or Environment and Command-Line Conflicts

Duplicate same-named keys trigger an `ArgumentAlreadyException`:

```csharp
// ArgumentAlreadyException.Throw
public static void Throw(string message)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(message, nameof(message));
    throw new ArgumentAlreadyException(message);
}
```

Fixes:

- At the command-line level: merge duplicate options and make sure the same logical key appears only once.
- Command line vs environment variables: use `OptionsBuilder.CreateFromArgsOnly<TOptions>(args)` to explicitly disable environment variables, avoiding confusing behavior when same-named keys are overwritten:

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);
```

### Fix 5: Boolean Argument Parsing Errors

Under `BoolArgumentFormat.Flag` (the default), `AttachValueIfPresent` skips the next token if it is recognized as a boolean literal, preventing the `true` in a form like `--verbose true` from being mistakenly consumed as the value of `--verbose`:

```csharp
if (BoolFormat == BoolArgumentFormat.Flag && BooleanParser.IsBooleanValue(nextArg))
{
    return currentIndex + 1;
}
```

If you really want to assign a boolean value to a string/collection-type field, use the key=value form instead:

```bash
# Don't do this (the boolean will be skipped)
myapp --mode true

# Do this instead
myapp --mode=true
```

> Source: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L336-L344)

### Fix 6: Parsing Errors with Negative Numbers and Values Containing Spaces

`IsOptionToken` already exempts negative numbers:

```csharp
private static bool IsOptionToken(string value)
{
    if (string.IsNullOrEmpty(value)) return false;
    if (!value.StartsWith("-")) return false;
    return !IsNegativeNumber(value);
}
```

However, when `EnsurePrefixedKeys=true`, a negative-number token misrecognized as a "non-option" gets a `--` prefix added by `NormalizeKey`:

```csharp
return EnsurePrefixedKeys ? "--" + arg : arg;
```

Therefore, when passing negative numbers, it is recommended to use an explicit prefix or the key=value form:

```bash
# Recommended: the key=value form will not be rewritten
myapp --offset=-3

# Not recommended: may be rewritten to -- -3 or misrecognized as an option
myapp offset -3
```

String values containing spaces are automatically double-quoted by `AppendTokenWithQuotingIfNeeded`; when parsing from a `string[]`, the input is already split by spaces and needs no extra handling; when rebuilding the command line from a single string (`ToCommandLineString`), quotes are added automatically.

> Source: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L347-L365)

## Verification

Verify that the problem is resolved in the following order:

1. Use `OptionsBuilder.CreateWithDebug<TOptions>(args)` to print the parsing result and confirm the final value of each property.
2. Wrap the failure path with `OptionsBuilder.TryCreate<TOptions>(args, out var result, out var error)`: on failure it returns a default instance and exposes the message via `error`, without crashing the process.
3. Watch `ex.InnerException` in the debugger to confirm the root cause has been identified (especially sub-exceptions such as `ArgumentAlreadyException` and `FormatException`).
