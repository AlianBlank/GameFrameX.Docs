# 부모-자식 계층 관계를 구축하는 방법

`AttachEntity` 시리즈 메서드를 통해 기존 엔티티를 다른 엔티티 아래에 부착할 수 있으며, 프레임워크는 부모-자식 매핑을 기록하고, `Transform` 부모-자식 관계를 자동으로 동기화하며, `EntityLogic`의 `OnAttached` / `OnDetached` 콜백을 트리거합니다.

## 사전 조건

- 부모 엔티티와 자식 엔티티가 모두 `ShowEntity` 또는 `CreateEntity`로 생성 완료되어 표시된 상태여야 합니다.
- `GameFrameX.Entity.Runtime.EntityComponent`가 마운트되어 있고 `GameEntry.Entity`를 통해 접근할 수 있어야 합니다.
- 자식 엔티티의 루트 `Transform`(즉, 해당 `EntityLogic`이 있는 GameObject)이 부모에 의해 제어되는 객체가 됩니다.

## 작업 단계

### 1. 엔티티 ID를 통해 부모-자식 관계 설정

```csharp

GameEntry.Entity.AttachEntity(childEntityId, parentEntityId);
```

### 3. 부모 Transform 및 부착 데이터 지정

자식 엔티티를 부모 엔티티의 루트 Transform이 아닌 특정 노드(예: 무기 소켓)에 부착해야 할 때, `parentTransform` 및 `userData`를 사용하는 오버로드를 사용하고, `AttachToEntity`를 통해 생성 시 한 번에 바인딩합니다:

```csharp
GameEntry.Entity.AttachToEntity(
    childEntityId, parentEntityId,
    "WeaponSocket01",   // 부모 엔티티의 자식 노드 이름
    userData: payload); // 사용자 정의 데이터
```

여기서 `AttachEntityInfo`는 부모 `Transform`과 사용자 데이터를 저장합니다:

```csharp
public class AttachEntityInfo : IReference
{
    public Transform ParentTransform { get; }
    public object    UserData       { get; }
}
```

### 4. 부모 엔티티에서 부착 이벤트 수신

`EntityLogic.OnAttached`를 재정의하면 자식 엔티티가 언제 부착되었는지 알 수 있으며, `userData`는 그대로 전달됩니다:

```csharp
protected internal override void OnAttached(EntityLogic childEntity, Transform parentTransform, object userData)
{
    base.OnAttached(childEntity, parentTransform, userData);
    Debug.Log($"child {childEntity.Id} attached under {parentTransform.name}");
}
```

## 부모-자식 관계 해제

부모 엔티티의 `EntityLogic`에서 `OnDetached`를 재정의합니다. 프레임워크는 자식 엔티티가 바인딩 해제될 때 이 메서드를 호출하며, 원래 `userData`를 전달합니다:

```csharp
protected internal override void OnDetached(EntityLogic childEntity, object userData)
{
    base.OnDetached(childEntity, userData);
    // 참조 반환, 드라이버 정지 등의 정리 로직
}
```

## 일반적인 변형

- **생성 시 직접 부착**: `AttachToEntity`를 사용하여 `ShowEntity`와 동일한 흐름에서 부모 엔티티 ID, 부모 노드 이름 및 `userData`를 지정하여 `AttachEntity`를 다시 호출하지 않도록 합니다.
- **부모 변경**: `AttachEntity(child, newParent)`를 다시 호출하면 프레임워크가 이전 부모 엔티티 바인딩 관계를 덮어씁니다.
- **런타임 일괄 조회**: `GetChildEntities(parentEntityId)`를 통해 자식 엔티티 배열을 가져온 후 순회하여 처리합니다.

## 일반적인 오류

- **부모-자식이 먼저 ShowEntity 없이 Attach**: 부모와 자식 엔티티는 모두 로드되어 표시된 상태여야 하며, 그렇지 않으면 Null 참조 예외가 발생합니다.
- **엔티티 그룹 Helper의 Transform 오용**: `AttachToEntity`의 `parentTransform`은 엔티티 그룹의 루트 노드가 아니라 부모 엔티티 아래의 자식 `Transform` 이름(예: 소켓)입니다.
- **OnAttached 재정의 잊기**: 부모-자식 부착 성공 콜백이 부모 엔티티의 `EntityLogic`에서 재정의되지 않으면 "로직이 트리거되지 않음"이라는 잘못된 인상이 발생할 수 있습니다. 기본 구현은 비어 있습니다.
- **부모-자식 순환 부착**: 조부모를 자식 아래에 부착하면 무한 콜백 체인이 발생하므로 계층 구조가 단방향이 되도록 보장해야 합니다.

## 배경(선택 사항)

프레임워크는 내부적으로 자식 엔티티를 단위로 `AttachEntityInfo`(`ParentTransform` + `UserData`)를 기록하며, 부모-자식 매핑과 `Transform.SetParent`은 `EntityManager`에서 유지됩니다. `OnAttached` / `OnDetached`는 `EntityLogic`에서 `protected internal virtual`로 노출되며, 런타임에 필요한 훅만 재정의하면 됩니다.
