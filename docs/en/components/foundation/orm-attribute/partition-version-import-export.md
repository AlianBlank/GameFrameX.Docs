# How to Declare Partition Tables / Version Control / Import Export

By adding the three attributes `PartitionTableAttribute`, `VersionControlAttribute`, and `ImportExportAttribute` to an entity class, you can declare at once whether the database table supports partitioning, whether version management is enabled, and whether it participates in the import/export process. This page provides minimal copy-ready examples along with the most common variants.

## Prerequisites

- Reference the `GameFrameX.Foundation.Orm.Attribute` namespace;
- The entity class must contain properties with the same names as the fields declared in the attributes (e.g., partition key, version field, etc.);
- The actual DDL is generated by the upper-layer ORM/migration tools based on the attributes; this document only covers how to declare them.

## Steps

### 1. Declare a Partition Table

Add `PartitionTableAttribute` to the entity class, and pass the partition key field and partition type into the constructor. For hash partitioning, you can specify `PartitionCount`; for range partitioning, you can specify `Interval`.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[PartitionTable("CreateDate", PartitionType.Range, PartitionInterval.Monthly)]
public class OrderHistory
{
    public int Id { get; set; }
    public int UserId { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreateDate { get; set; }  // Partition key
}
```

Source: [PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L63-L91)

Optional properties: `AutoCreatePartition` (default `true`), `RetentionDays` (default `0`, meaning retained permanently), `PartitionValues` (fill in for list partitioning), `PartitionCount` (default `4`, used for hash partitioning).

```csharp
[PartitionTable("UserId", PartitionType.Hash, PartitionCount = 16)]
public class UserActivity
{
    public long Id { get; set; }
    public int UserId { get; set; }
    public string Activity { get; set; }
    public DateTime Timestamp { get; set; }
}
```

Source: [PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L82-L89)

### 2. Declare Version Control

Add `VersionControlAttribute` to the entity class, pass the version field name into the constructor, and optionally specify the version strategy. The entity must contain a version field property with the same name.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[VersionControl("Version", VersionStrategy.Optimistic)]
public class Document
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }
    public int Version { get; set; }  // Version number field
    public DateTime LastModified { get; set; }
    public string LastModifiedBy { get; set; }
}
```

Source: [VersionControlAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/VersionControlAttribute.cs#L63-L74)

Optional properties: `EnableHistory` (default `false`), `HistoryTableName`, `MaxHistoryVersions` (default `0`, meaning unlimited), `ConflictHandling` (default `ThrowException`), `AutoUpdateVersion` (default `true`), `ComparisonMode` (default `Increment`).

When you need to keep historical versions, set `EnableHistory` to `true` and optionally specify the history table name:

```csharp
[VersionControl("RowVersion", VersionStrategy.Timestamp, EnableHistory = true)]
public class UserProfile
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
    public byte[] RowVersion { get; set; }
}
```

Source: [VersionControlAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/VersionControlAttribute.cs#L76-L83)

### 3. Declare Import Export

Add `ImportExportAttribute` to the entity class, and pass the supported formats and import/export direction into the constructor.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[ImportExport(ImportExportFormat.Excel, ImportExportDirection.Bidirectional)]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

(The code example is based on the public constructor `ImportExport(ImportExportFormat, ImportExportDirection)` of `ImportExportAttribute`.)

## Common Variants

| Scenario | Usage | Description |
|------|------|------|
| List partitioning | `PartitionTable("Region", PartitionType.List)` plus `PartitionValues = "North,South,East,West"` | Partition by a predefined list of values |
| Export only | `ImportExport(ImportExportFormat.Csv, ImportExportDirection.ExportOnly)` | Disables the import entry point |
| Import only with validation | `ImportExport(ImportExportFormat.Excel, ImportExportDirection.ImportOnly, ValidateOnImport = true)` | Performs field validation on import |
| All three attributes combined | Apply `PartitionTable` + `VersionControl` + `ImportExport` on the same entity | For large table + concurrency + data exchange scenarios |

Both `PartitionTableAttribute` and `VersionControlAttribute` have `AllowMultiple = false`, so each can only be declared once on the same class; `ImportExportAttribute` likewise only allows a single declaration.

## Common Errors

- **Partition key or version field does not exist**: The entity class has no property with the same name as `PartitionKey` / `VersionField`, so migration or runtime validation will fail. Add the field first, then apply the attribute.
- **Hash partitioning with `PartitionCount <= 0`**: The constructor throws `ArgumentOutOfRangeException` with the message `Partition count must be positive.`. You must pass in a positive integer.
- **Passing `null` or whitespace to `partitionKey` / `versionField`**: This triggers `ArgumentNullException` or `ArgumentException.ThrowIfNullOrWhiteSpace`; pass constant strings directly.
- **Forgetting to fill in `PartitionValues` for list partitioning**: List partitioning requires an explicit declaration of the value set; otherwise, the partition boundaries cannot be determined.
- **Version field type mismatch with the strategy**: For example, `VersionStrategy.Timestamp` requires the field to be `byte[]` or `DateTime`, while `Optimistic` requires `int/long`; mixing them up will cause version comparison failures.
