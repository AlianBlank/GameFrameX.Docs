# エンティティコントラクト検証に失敗した場合の対処方法

`EntityContractValidator.Validate<T>()` が空でないリストを返す場合、または実行時に ORM がインターフェースプロパティの不一致を報告する場合、エンティティクラスが実装しているインターフェース（例：`IEntity`、`IVersionedEntity`、`IAuditableEntity`）のコントラクトを満たしていないことを意味します。このページでは、エラーメッセージに基づいて問題の特定と修正方法を説明します。

## 迅速な診断

| 症状（`Reason` テキストの一部） | 根本原因 | 修正方法 |
|------|------|------|
| `Property 'XXX' not found on type 'YYY'` | エンティティクラスにインターフェースが必要なプロパティがない | エンティティクラスに同名・同型のプロパティを追加する |
| `Property 'XXX' type mismatch: expected 'A', actual 'B'` | プロパティの型がインターフェース宣言と一致しない | プロパティの型をインターフェース要求の型（または Null 許容互換型）に変更する |
| `Property 'XXX' is missing a getter` | プロパティが `set` のみで宣言され、`get`（または `private get`）がない | public な getter を追加する |
| `Property 'XXX' is missing a setter` | プロパティに `get` しかなく、`set`（または `private set`）がない | public な setter を追加する |
| `Property 'XXX' has multiple declarations on type 'YYY' (possible 'new' keyword shadowing)` | `new` キーワードで継承されたインターフェースプロパティを隠蔽している | `new` を削除するか、単一のプロパティに統合する |
| `Validate(null)` を呼び出すと `ArgumentNullException` がスローされる | `Type` に null が渡された | null 以外のエンティティ型を渡す |

## 修正手順

### 1. プロパティの欠落

インターフェースが特定のフィールド（例：`IVersionedEntity.Version`）を要求しているのに、エンティティクラスで宣言されていないケースです。エンティティクラスに対応するプロパティを追加してください：

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class Player : IVersionedEntity
{
    public long Version { get; set; } // インターフェースが要求するプロパティを補完
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118)

### 2. 型の不一致

インターフェースは `DateTime` を宣言しているのに、エンティティが `DateTimeOffset` や `string` になっているケースです。型をインターフェース要求の型に戻してください。インターフェースが値型の場合、エンティティは対応する `Nullable<T>` を使用でき、検証ツールは `Nullable.GetUnderlyingType` で互換性を判定します。

```csharp
public interface IAuditableEntity
{
    DateTime CreatedAt { get; set; }
}

public class Order : IAuditableEntity
{
    public DateTime CreatedAt { get; set; } // 型は一致させる必要がある。DateTime? でも可
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

### 3. getter / setter の欠落

ORM は読み取りと書き込みの両方を必要とすることがよくあります。アクセサを補完してください：

```csharp
public DateTime UpdatedAt { get; set; } // get と set はどちらも public 必須
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144)

### 4. `new` キーワードによる隠蔽

基底クラスから継承したプロパティが `new` で再宣言され、`GetProperty` が複数のマッチにヒットして `AmbiguousMatchException` が発生するケースです。`new` を削除して単一のプロパティに統合してください：

```csharp
// 誤り：new キーワードによる隠蔽
public new long Version { get; set; }

// 正解：基底クラスの宣言をそのまま使用
// （new 宣言全体を削除するか、override / 明示的な接口実装を使用）
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108)

### 5. 自動検証の呼び出し

アプリケーション起動時または単体テストで検証ツールを呼び出し、違反項目をまとめて出力します：

```csharp
using GameFrameX.Foundation.Orm.Entity;

var violations = EntityContractValidator.Validate<Player>();
foreach (var v in violations)
{
    Console.WriteLine($"{v.InterfaceType.Name}.{v.PropertyName}: {v.Reason}");
}
```

返される `EntityContractViolation` には 3 つのフィールドが含まれます：`InterfaceType`、`PropertyName`、`Reason`。

## 検証

修正後、再度 `Validate<T>()` を呼び出します：

- 返される `IList<EntityContractViolation>` の長さが 0 であれば、すべてのコントラクトが満たされています。
- それでも空でない項目が返される場合は、上記の診断表で `Reason` を照合し、リストが空になるまで修正を続けてください。

## 検証ツールがチェックしないもの

`EntityContractValidator` はインターフェースで明示的に宣言されたプロパティのみを検証します：

- インターフェースが他のインターフェースから継承したプロパティは、`Type.GetInterfaces()` を通じて検証対象に含まれます。
- フィールド（`public int Foo;`）、静的メンバー、プライベートメンバーはチェックされません。
- インターフェース自体がプロパティ構文でそのメンバーを宣言している場合にのみ検証されます。メソッドで表現された契約は対象外です。
