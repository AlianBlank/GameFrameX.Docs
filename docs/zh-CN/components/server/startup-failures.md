# 启动失败/数据库连接异常怎么办

服务在启动阶段崩溃、或日志里出现 Mongo 连接错误时,通常是 `--DataBaseUrl` / `--DataBaseName` 配置错误、Mongo 容器未就绪、或网络/认证不通过。本页帮助你快速定位并修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动日志含 `connection refused` / `No connection could be made` | Mongo 端口不可达或地址写错 | 检查 `--DataBaseUrl` 主机与端口 |
| 启动日志含 `Authentication failed` / `authSource` 错误 | 认证源或账号密码不匹配 | 修正连接串 `?authSource=...` 与凭据 |
| 启动日志含 `Database name cannot be empty` 或库缺失提示 | 未传 `--DataBaseName` 或库名拼错 | 补齐 `--DataBaseName=xxx` |
| 容器启动顺序异常:Game 先于 Mongo | `depends_on` 未等 healthcheck 通过 | 使用 `condition: service_healthy` 等待 Mongo |
| 本地连接 docker 内 Mongo 失败 | 端口未对外暴露或暴露端口写错 | 对照 `docker-compose.yml` 的 `ports` 映射 |

## 修复步骤

### 1. 核对 `--DataBaseUrl` 与 `--DataBaseName`

启动参数必须显式传入数据库连接串与库名。`docker-compose.yml` 中的默认值如下:

```yaml
command:
  - "--DataBaseUrl=mongodb://mongo:27017/?authSource=admin"
  - "--DataBaseName=gameframex"
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L36-L37)

本地直连 docker 内 Mongo,使用 `mongodb://localhost:37017/?authSource=admin`(对应 compose 文件 `37017:27017` 的端口映射)。多服版使用 `localhost:47017` 与 `gameframex_multi`。

```yaml
ports:
  - "37017:27017"
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L7-L7)

```yaml
ports:
  - "47017:27017"
```

Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L23-L23)

### 2. 等待 Mongo 健康检查通过

Game 与 Social 服务必须等待 Mongo `healthcheck` 通过后再启动。compose 中已通过 `condition: service_healthy` 约束,不要改成 `service_started`。

```yaml
depends_on:
  mongo:
    condition: service_healthy
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L21-L23)

健康检查命令使用 `ping` 验证可达:

```yaml
healthcheck:
  test: [ "CMD", "mongosh", "--quiet", "--eval", "db.runCommand({ ping: 1 }).ok" ]
  interval: 5s
  timeout: 3s
  retries: 20
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L9-L12)

手动验证 Mongo 状态:

```bash
docker exec -it gfx-mongo mongosh --quiet --eval "db.runCommand({ ping: 1 }).ok"
# 期望输出: 1
```

### 3. 检查数据卷与持久化

多服版将 Mongo 数据挂在 `./running-multi/mongo:/data/db`,若宿主机目录权限不足或磁盘已满,Mongo 会反复重启,导致 Game 连接抖动。

```yaml
volumes:
  - "./running-multi/mongo:/data/db"
```

Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L30-L31)

确保目录可写并有足够空间:

```bash
ls -ld ./running-multi/mongo
df -h ./running-multi/mongo
```

### 4. 修正认证源

默认未启用账号密码,使用 `?authSource=admin` 仅作为管理库标识;若你的 Mongo 开启了 `mongod --auth`,需要在 URL 中追加凭据,并把 `authSource` 改为实际的认证库(常见是 `admin`)。

```bash
# 启用认证的连接串样例
--DataBaseUrl=mongodb://user:password@mongo:27017/?authSource=admin
```

## 验证

完成修复后,按以下顺序确认:

1. 查看 Mongo 健康状态:`docker ps`,确认 `STATUS` 列含 `(healthy)`。
2. 重启 Game 服务:`docker compose up -d --force-recreate game`,观察日志不再出现 Mongo 异常。
3. 进入 Mongo 容器校验库已创建:`docker exec -it gfx-mongo mongosh --quiet --eval "show dbs"`,应能看到 `gameframex` 或 `gameframex_multi`。
4. 如仍失败,采集启动日志(`docker logs gfx-game | tail -200`)对照诊断表继续排查。

## 常见错误

- **使用容器内部主机名访问本地数据库**。在宿主机直接跑客户端时,`--DataBaseUrl` 中的 `mongo` 主机无法解析,需改为 `localhost` 或宿主机 IP。
- **改了端口映射忘了同步 URL**。修改 `ports` 后,`--DataBaseUrl` 中的端口也要同步,否则 Game 仍按旧端口连。
- **`depends_on` 只写 `service_started`**。这只会等容器进程启动,不等待 Mongo 完成初始化,会反复出现瞬时连接失败。
- **Mongo 重启后 Game 不自动重连**。默认 `restart: unless-stopped`,Game 需要手动 `docker compose restart game` 才能再次连上。
