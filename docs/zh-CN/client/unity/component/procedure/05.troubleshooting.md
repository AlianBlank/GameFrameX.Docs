# 常见问题

本文档汇总了在使用 GameFrameX Procedure 流程管理组件时可能遇到的常见问题、错误及其解决方案。

## 概述

Procedure 流程管理组件是基于 Game Framework 的有限状态机（FSM）实现的游戏流程管理系统。在集成和使用过程中，开发者经常会遇到配置错误、依赖缺失、类型解析失败等问题。本文档旨在帮助开发者快速定位和解决这些问题。

## 依赖问题

### FSMComponent 未正确配置

**症状**: 游戏启动后无响应或报 `Procedure manager is invalid.` 错误

**原因**: ProcedureComponent 依赖 `IProcedureManager` 模块，该模块需要通过 `GameFrameworkEntry` 获取。如果 FSMComponent 未正确初始化，可能导致模块获取失败。

**解决方案**:
1. 确保场景中已添加 `FSMComponent` 组件
2. 确认 `GameFrameworkEntry` 已正确初始化所有必需模块
3. 检查 GameFramework 的初始化顺序，确保先初始化基础组件

> Source: [ProcedureComponent.cs#L64-L68](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L64-L68)

---

### 缺少必要的 GameFramework 组件

**症状**: 运行时出现 NullReferenceException 或模块获取失败

**原因**: GameFramework 是一套完整的组件体系，Procedure 组件依赖多个底层模块

**解决方案**:
1. 确保已安装 GameFrameX 核心库
2. 检查项目是否包含以下依赖:
   - `GameFrameX.Fsm.Runtime` - 有限状态机模块
   - `GameFrameX.Runtime` - 核心运行时模块

## 配置问题

### 流程类型名称配置错误

**症状**: 控制台显示 `Can not find procedure type '{0}'.` 错误

**原因**: `m_AvailableProcedureTypeNames` 数组中配置的流程类型名称与实际类名不匹配

**解决方案**:
1. 检查 Inspector 面板中的 `Available Procedure Type Names` 配置
2. 确保类型名称使用完整的类名（包括命名空间）
3. 流程类必须继承自 `ProcedureBase`

```csharp
// 正确示例
namespace MyGame.Procedure
{
    public class ProcedureLaunch : ProcedureBase
    {
        // 流程实现
    }
}
```

配置时填入: `MyGame.Procedure.ProcedureLaunch`

> Source: [ProcedureComponent.cs#L76-L81](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L76-L81)

---

### 入口流程未设置

**症状**: 控制台显示 `Entrance procedure is invalid.` 错误

**原因**: `m_EntranceProcedureTypeName` 未设置或设置的值不在 `m_AvailableProcedureTypeNames` 列表中

**解决方案**:
1. 在 Inspector 面板中设置 `Entrance Procedure Type Name`
2. 确保入口流程名称与 `Available Procedure Type Names` 中的某个流程完全匹配
3. 入口流程是游戏启动后第一个执行的流程

> Source: [ProcedureComponent.cs#L90-L100](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L90-L100)

---

### 流程数组为空

**症状**: 启动时无任何流程执行，或出现数组越界错误

**原因**: `m_AvailableProcedureTypeNames` 未配置或为空

**解决方案**:
1. 在 ProcedureComponent 的 Inspector 面板中，至少添加一个流程类型
2. 建议至少包含以下基础流程:
   - 启动流程 (ProcedureLaunch)
   - 热更新流程 (ProcedureCheckVersion)
   - 登录流程 (ProcedureLogin)
   - 游戏流程 (ProcedureGame)

## 类型解析问题

### 程序集类型获取失败

**症状**: `Utility.Assembly.GetType()` 返回 null，导致流程创建失败

**原因**:
1. 类型名称拼写错误
2. 流程类未编译到程序集中
3. 使用了错误的程序集配置

**解决方案**:
1. 确认流程类已正确编译
2. 使用完整的类型名称（包括命名空间）
3. 对于混淆后的代码，确保相关程序集配置正确

```csharp
// 错误的类型名称
m_AvailableProcedureTypeNames = new[] { "ProcedureLaunch" };

// 正确的类型名称
m_AvailableProcedureTypeNames = new[] { "GameFrameX.Procedure.Runtime.ProcedureLaunch" };
```

> Source: [ProcedureComponent.cs#L83-L88](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L83-L88)

---

### 流程实例创建失败

**症状**: `Can not create procedure instance '{0}'.` 错误

**原因**:
1. 流程类缺少无参构造函数
2. 构造函数抛出异常
3. 流程类的构造函数访问了尚未初始化的系统

**解决方案**:
1. 确保流程类具有无参构造函数
2. 不要在构造函数中访问 ProcedureManager 或其他 GameFramework 组件
3. 使用 `OnInit`、`OnEnter` 等生命周期方法进行初始化

```csharp
// 推荐: 在 OnEnter 中进行初始化
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 在这里进行初始化操作
    }
}
```

## 运行时问题

### 流程管理器未初始化

**症状**: 调用 `CurrentProcedure` 或 `CurrentProcedureTime` 时抛出异常 `You must initialize procedure first.`

**原因**: 在 ProcedureManager 初始化完成之前访问了相关属性

**解决方案**:
1. 确保在 `Start()` 方法执行完毕后再访问流程管理器
2. 使用协程或事件系统等待初始化完成

```csharp
// 错误示例: 在 Awake 中立即访问
private void Awake()
{
    var current = CurrentProcedure; // 会抛出异常
}

// 正确示例: 在协程中等待
private IEnumerator Start()
{
    yield return new WaitForEndOfFrame();
    var current = CurrentProcedure; // 现在可以正常访问
}
```

> Source: [ProcedureManager.cs#L48-L55](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L48-L55)

---

### 流程切换失败

**症状**: 调用 `StartProcedure<T>()` 后流程未切换

**原因**:
1. 指定的流程类型未在初始化时注册
2. FSM 状态机已被销毁
3. 流程切换逻辑存在死循环

**解决方案**:
1. 确保要切换的目标流程在 `m_AvailableProcedureTypeNames` 中
2. 检查是否有代码在流程切换时立即切回原流程
3. 使用调试日志确认切换调用是否执行

> Source: [ProcedureManager.cs#L116-L124](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L116-L124)

---

### 流程状态方法未被调用

**症状**: 自定义的 `OnEnter`、`OnUpdate`、`OnLeave` 等方法未被执行

**原因**: 流程类未正确继承 `ProcedureBase`，或方法未正确重写

**解决方案**:
1. 确保流程类继承自 `ProcedureBase`
2. 使用 `override` 关键字重写父类方法
3. 调用 `base.OnEnter()` 等方法以确保父类逻辑执行

```csharp
// 正确示例
public class ProcedureLogin : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner); // 必须调用
        // 自定义逻辑
    }
}
```

> Source: [ProcedureBase.cs#L31-L35](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L31-L35)

## 调试技巧

### 启用调试日志

在开发过程中，可以添加详细的日志输出来帮助定位问题:

```csharp
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        Debug.Log("进入 ProcedureLaunch 流程");
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        Debug.Log($"ProcedureLaunch 已运行 {procedureOwner.CurrentStateTime:F2} 秒");
    }
}
```

### 检查流程状态

可以使用 `ProcedureComponent` 提供的方法检查流程状态:

```csharp
// 检查是否存在指定流程
bool hasLogin = procedureComponent.HasProcedure<ProcedureLogin>();

// 获取当前流程
ProcedureBase current = procedureComponent.CurrentProcedure;

// 获取流程持续时间
float duration = procedureComponent.CurrentProcedureTime;
```
