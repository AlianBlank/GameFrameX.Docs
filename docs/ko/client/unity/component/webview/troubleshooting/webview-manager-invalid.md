# 시작 시 “Web View manager is invalid” 오류가 발생하는 경우

이 오류는 `WebViewComponent.Awake()`에서 발생합니다: `GameFrameworkEntry.GetModule<IWebViewManager>()`가 `null`을 반환했으며, 이는 프레임워크에 `IWebViewManager`를 구현한 구체적인 모듈이 등록/로드되지 않았음을 의미합니다. 이 오류가 발생하면 WebView 컴포넌트는 `Initialize()`를 호출하지 않으며, 이후 `Show` / `Hide` 등의 호출은 모두 null 참조가 됩니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 시작 시 `Log.Fatal("Web View manager is invalid.")` 출력 | `GameFrameworkEntry.GetModule<IWebViewManager>()`가 `null`을 반환함, 구체적인 구현 모듈이 로드되지 않음 | 프로젝트에 `BaseWebViewManager`의 구체적인 구현 모듈이 존재하는지 확인, [수정 단계 1](#수정-단계) 참조 |
| 이후 `Show(url)` 호출 시 `NullReferenceException` 발생 | 이전 단계 실패 후 `_webViewManager`가 `null`로 유지되어 컴포넌트가 초기화를 건너뜀 | 먼저 위의 Fatal을 해결하세요, [검증](#검증) 참조 |
| Inspector에서 컴포넌트의 구현 타입 드롭다운이 비어 있음 | 구현 타입이 선택되지 않았거나 해당 어셈블리가 프로젝트에 컴파일되지 않음 | [수정 단계 2](#수정-단계) 참조 |

## 수정 단계

### 1. 프로젝트에 `IWebViewManager`의 구체적인 구현이 있는지 확인

본 저장소는 추상화 계층만 제공합니다: `BaseWebViewManager`는 추상 클래스이며 어떠한 플랫폼 구현도 포함하지 않습니다(디렉터리에는 `BaseWebViewManager`, `IWebViewManager`, `WebViewComponent` 등만 존재). 구체적인 구현은 함께 제공되는 런타임 모듈에서 제공해야 합니다:

```csharp
public abstract partial class BaseWebViewManager : GameFrameworkModule, IWebViewManager
{
    public abstract void Initialize();
    public abstract void Show(string url);
    public abstract void MakeFullScreen();
    public abstract void ExecuteJavaScript(string javaScript);
    public abstract void Hide();
}
```

Source: [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39)

문제 해결 방법: 프로젝트 내에서 `: BaseWebViewManager`를 전역 검색하여 최소 하나의 비추상 파생 클래스가 존재하는지 확인합니다. 없다면 해당 런타임 구현 패키지를 설치/추가한 후 다시 시도하세요.

### 2. 컴포넌트의 구현 타입이 선택되었는지 확인

`WebViewComponent`는 `Awake()`에서 리플렉션을 통해 구현 타입을 해석한 후 인터페이스 모듈을 가져옵니다:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IWebViewManager);
base.Awake();
if (!IsRuntimeComponentReady)
{
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L30)

`componentType`의 값은 Inspector에서 제공되며, 에디터 스크립트는 `IWebViewManager`를 구현한 모든 타입을 드롭다운 목록에 채웁니다:

```csharp
internal sealed class WebViewComponentInspector : ComponentTypeComponentInspector
{
    ...
    RefreshComponentTypeNames(typeof(IWebViewManager));
}
```

Source: [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L14-L19)

절차: `WebView` 컴포넌트가 부착된 게임 오브젝트를 선택하고 Inspector에서 구현 타입이 비어 있지 않은지 확인합니다. 비어 있다면 해당 어셈블리가 현재 빌드 대상에 컴파일되지 않았다는 의미입니다(플랫폼 구현 패키지가 특정 플랫폼만 지원하는 경우 흔히 발생). 수정한 후 씬을 저장하고 다시 실행하세요.

### 3. 런타임 어셈블리가 컴파일에 포함되는지 확인

본 패키지의 어셈블리 정의는 `Runtime/GameFrameX.WebView.Runtime.asmdef`와 `Editor/GameFrameX.WebView.Editor.asmdef`입니다. Unity Console에 이 두 어셈블리(또는 구현 모듈 어셈블리)에 대한 컴파일 오류가 있는지 확인하세요. 컴파일에 실패하면 `GetModule`이 구현을 가져올 수 없어 동일한 Fatal이 발생합니다.

## 검증

1. Play 모드에 다시 진입하여 Console에 더 이상 `Web View manager is invalid.` Fatal 로그가 나타나지 않는지 확인합니다.
2. 전체 호출 체인을 한 번 실행하여 페이지가 정상적으로 열리는지 확인합니다:

```csharp
var webView = GameObject.FindObjectOfType<GameFrameX.WebView.Runtime.WebViewComponent>();
webView.Show("https://example.com");
```

## 배경

`WebViewComponent`는 `GameFrameworkComponent`로서 자체적으로는 어떠한 WebView 로직도 구현하지 않으며, `Awake()`에서 `GameFrameworkEntry`로부터 `IWebViewManager` 모듈을 가져와 호출을 전달(`Show`, `MakeFullScreen`, `ExecuteJavaScript`, `Hide`)하는 역할만 담당합니다. 추상화와 구현의 분리는 인터페이스 계층과 각 플랫폼 구현을 독립적으로 패키징할 수 있음을 의미합니다. 구현 모듈이 누락되면 모듈을 가져오는 단계에서 실패하고 이 페이지의 Fatal 로그가 출력됩니다.
