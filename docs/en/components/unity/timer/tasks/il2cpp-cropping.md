# IL2CPP/AOT Builds: Preventing Types from Being Stripped

This package includes built-in double protection against managed code stripping for IL2CPP/AOT builds: all core types (`TimerComponent`, `TimerManager`, `ITimerManager`) are annotated with `[UnityEngine.Scripting.Preserve]`, and a `GameFrameXTimerCroppingHelper` cropping helper class is additionally provided to explicitly reference these types. After properly importing this package, no additional configuration is required—the types will not be stripped.

## Prerequisites

- The project has this package installed (`com.gameframex.unity.timer`).
- The target platform uses the IL2CPP scripting backend in Player Settings (this mechanism has no side effects on the Mono backend, so it can be kept).

### 2. Confirm that the cropping helper class is built with the package

The `Runtime/GameFrameXTimerCroppingHelper.cs` file in the package is the second line of defense against stripping. Both the class and its methods carry `[Preserve]`, and `Start()` uses `typeof` to explicitly reference all core types, leaving static reference roots for the stripper:

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Timer.Runtime
{
    [Preserve]
    public class GameFrameXTimerCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(TimerComponent);
            _ = typeof(ITimerManager);
            _ = typeof(TimerManager);
        }
    }
}
```

Source: [GameFrameXTimerCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/GameFrameXTimerCroppingHelper.cs#L1-L17)

This file is located in the package's `Runtime` directory and is automatically included in the build with the package; there is no need to manually attach it to a scene.

### 3. Build and verify

1. Switch to the IL2CPP backend and perform an actual platform build (entering Play mode alone cannot verify stripping issues).
2. Confirm that types are retained in the build output, using either of the following:
   - Search for `GameFrameX.Timer` in the build report/stripping logs and confirm there are no "stripped"-related removal records;
   - Run the built package and confirm that the timer component initializes correctly and can execute calls such as `AddTimer`.

## Common Variants

- **Other reflection-dependent types in your project being stripped**: You can replicate the helper class pattern above in your own project code—create a new `MonoBehaviour` with `[Preserve]` and use `typeof` in `Start()` to reference the types that need to be kept. This is a common Unity anti-stripping technique, and this package's `GameFrameXTimerCroppingHelper` is a ready-made example of this pattern.
- **Build failure after raising the stripping level**: If the project sets High/Medium stripping levels, `[Preserve]` and the `typeof` reference roots remain effective; no separate adjustments are needed for the timer types.

| Symptom | Cause | Fix |

## Background

IL2CPP's managed code stripping removes types that are "unreferenced" in static analysis. This package's types are often loaded through framework reflection and the automatic component mechanism, so their static reference chains are incomplete and they are easily misjudged as removable. The `[Preserve]` attribute directly tells the stripper to keep the targets, and the cropping helper class further uses `typeof` to provide compile-time-visible reference roots; the combination of both guarantees that types are retained under any stripping level.
