# 設定項目解析異常發生時的處理方法

當 `GameFrameX.Setting` 在載入或取得設定時拋出例外、回傳預設值，或 `Load()` 回傳 `false` 時，通常表示底層儲存檔案損毀、Helper 未設定，或鍵名無效。本頁將針對各種異常現象，說明快速診斷與修復方法。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | `SettingManager` 未設定 `ISettingHelper`,或傳入了 `null` | 先將具象 Helper(預設的 `DefaultSettingHelper` 或 `PlayerPrefsSettingHelper`)實例化，再呼叫 `SetSettingHelper` |
| `GameFrameworkException: Setting name is invalid.` | `settingName` 為 `null` 或空字串 | 在呼叫 `HasSetting / GetBool / GetInt / GetFloat / GetString` 等方法前，先確認 `settingName` 不為空 |
| 啟動日誌顯示 `Load settings failure with exception '{0}'.` | 設定檔 `GameFrameworkSetting.dat` 不存在、損毀，或權限不足 | 刪除損毀的檔案或復原權限後重新初始化。詳情請參考下方「修復步驟」 |
| 啟動日誌顯示 `Save settings failure with exception '{0}'.` | 設定目錄為唯讀、磁碟已滿，或路徑無效 | 確認 `FilePath` 所指向位置的可寫入性，並重新指定 `Application.persistentDataPath` |
| 取得的值總是型別的預設值(`false / 0 / 0f / null`) | 鍵名拼字錯誤，或新版本尚未寫入該鍵 | 使用 `GetAllSettingNames()` 列舉所有鍵進行確認，或先呼叫指定了 `defaultValue` 的多載方法 |

## 修復步驟

### 1. Helper 未設定導致的 `Setting helper is invalid`

`SettingManager` 在每次讀寫前都會呼叫 `EnsureSettingHelper()`,若 `m_SettingHelper` 為 `null`,便會拋出此例外。

Source: [SettingManager.cs#L47-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L47-L61)

```csharp
private void EnsureSettingHelper()
{
    if (m_SettingHelper == null)
    {
        throw new GameFrameworkException("Setting helper is invalid.");
    }
}
```

修復方法：

1. 建立繼承自 `SettingHelperBase` 的 Helper 實例(框架已內建 `DefaultSettingHelper`、`PlayerPrefsSettingHelper`)。
2. 透過 `GameFrameworkEntry.GetModule<ISettingManager>().SetSettingHelper(helper)` 進行注入。
3. `SetSettingHelper(null)` 本身也會拋出相同例外，因此務必傳入非 null 的 Helper。

Source: [SettingManager.cs#L126-L134](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L126-L134)

### 2. 設定檔解析失敗(`Load settings failure`)

`DefaultSettingHelper.Load()` 以 try/catch 包裹反序列化處理，所有例外都會被轉換為日誌並回傳 `false`。雖然不會拋出例外，但設定項目會回復為空集合。

Source: [DefaultSettingHelper.cs#L126-L146](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L126-L146)

```csharp
public override bool Load()
{
    try
    {
        if (!File.Exists(m_FilePath))
        {
            return true;
        }

        using (FileStream fileStream = new FileStream(m_FilePath, FileMode.Open, FileAccess.Read))
        {
            m_Serializer.Deserialize(fileStream);
            return true;
        }
    }
    catch (Exception exception)
    {
        Log.Warning("Load settings failure with exception '{0}'.", exception);
        return false;
    }
}
```

修復方法：

1. **檔案不存在**：首次啟動屬正常情況，無需處理。若業務上需要預設值，可在 `Load()` 回傳 `false` 後呼叫 `SetBool/SetInt/...` 將其寫回。
2. **檔案標頭不一致**:`DefaultSettingSerializer` 的 `Header` 為 `{'G','F','S'}`,若檔案被其他程式修改，解析即會失敗。請刪除該 `GameFrameworkSetting.dat` 後重新啟動。

Source: [DefaultSettingSerializer.cs#L41-L67](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingSerializer.cs#L41-L67)
3. **磁碟/權限問題**：確認 `FilePath`(由 `Application.persistentDataPath` 等派生)所指向的目錄可讀寫。在 Windows / macOS 上，請確認檔案是否遭防毒軟體隔離。

### 3. 鍵名為空導致的 `Setting name is invalid`

`HasSetting / RemoveSetting` 會在 `EnsureSettingName` 中進行驗證。

Source: [SettingManager.cs#L55-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L55-L61)

```csharp
private void EnsureSettingName(string settingName)
{
    if (string.IsNullOrEmpty(settingName))
    {
        throw new GameFrameworkException("Setting name is invalid.");
    }
}
```

修復方法：從設定中心取得鍵名時進行 `string.IsNullOrEmpty` 驗證，或使用 `GetString(name, defaultValue)` / `GetInt(name, defaultValue)` 等指定預設值的多載方法，以避免因空鍵引發例外。

### 4. 儲存失敗(`Save settings failure`)

`Save()` 同樣以 try/catch 包裹，發生例外時會回傳 `false`,並輸出 `Save settings failure with exception '{0}'.`。

Source: [DefaultSettingHelper.cs#L156-L170](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L156-L170)

修復方法：

1. 確認 `FilePath` 已完成初始化(Helper 會於 `SetFilePath` 或初始化時設定)。
2. 確認目標目錄的寫入權限。`FileMode.Create` 需要寫入權限。
3. 擷取 `Log.Warning` 輸出中包含的 `IOException`、`UnauthorizedAccessException` 等具體例外，並據此進行處理。

## 驗證

請依下列順序確認問題已解決：

1. `GameFrameworkEntry.GetModule<ISettingManager>().Load()` 回傳 `true`,且啟動日誌不再出現 `Load settings failure` / `Save settings failure`。
2. `GetAllSettingNames()` 回傳的陣列包含所有預期的鍵。可透過 `HasSetting("your.key")` 確認特定鍵是否存在。
3. 寫入一次設定(`SetInt("score", 100)` → `Save()`),在結束並重新啟動後，`GetInt("score")` 仍會回傳 100。
4. 確認在傳入 `SetSettingHelper(null)` 或空鍵名等情況下，例外路徑會如預期拋出 `GameFrameworkException`,而不會被吞掉。
