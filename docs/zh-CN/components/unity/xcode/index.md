# 工作原理：构建后处理与配置合并流程

iOS 构建完成后，`PostProcessBuildHelper.OnPostProcessBuild`（回调优先级 `888`）会自动收集工程内**所有**名为 `XCodeConfig.json` 的文件，深度合并为一份最终配置（含渠道专属覆盖），再分两个阶段把配置写入生成的 Xcode 工程。整个过程无需手动干预，只要把配置文件放进工程任意目录即可。

## 配置发现与合并

流程按以下顺序执行：

1. `SettingLoader.LoadSettingsData("XCodeConfig.json")` 扫描工程内全部 TextAsset，按文件名（不区分大小写）精确匹配 `XCodeConfig.json`，结果按路径排序保证合并顺序确定。
2. 逐个读取并 `HashtableFromJson()` 解析，再通过 `finalConfig.Merge(table)` 深度递归合并到同一个 `Hashtable`。
3. 若存在渠道标识，加载 `XCodeConfig.{channel}.json` 并**最后合并**，因此渠道配置优先级最高。
4. 合并结果为空则直接跳过后续设置。

关键代码（通用配置合并部分）：

```csharp
var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

if (jsonPaths.Count == 0)
{
    LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
    return;
}

Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    if (table == null)
    {
        LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
        continue;
    }
    finalConfig.Merge(table);
}
```

## 渠道配置

## 两阶段应用流程

合并完成后，配置分两个阶段写入 Xcode 工程（[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)）：

**第一阶段：写入 PBXProject（project.pbxproj）**

1. 读取 `Unity-iPhone.xcodeproj/project.pbxproj` 为 `PBXProject`。
2. 对 **Unity-iPhone 主 target** 应用 `finalConfig["unityMain"]`（`Run(...)`，见下节）。
3. 对 **UnityFramework target** 应用 `finalConfig["unityFramework"]`。
4. `SetSigning` 设置签名（仅主 target），读取 `signing` 节点。
5. `SetupSwiftBridging` 设置 Swift 桥接，键 `swiftBridging` **缺省即视为开启**。
6. 写回 project.pbxproj。

**第二阶段：应用其他配置**

1. `RunPlist` 写 Info.Plist（`plist` 节点）。
2. `RunEnvironmentVariables` 设置启动环境变量（`environmentVariables`）。
3. `RunArgument` 设置启动参数（`launcherArgs`）。
4. `SetCapabilities` 设置 Capabilities（仅主 target），bundleId 取自 `signing.bundleId`。
5. 由于 Capabilities 通过 `ProjectCapabilityManager` 独立写盘，代码会**重新读取** project.pbxproj 以保留其修改。
6. `RunLocalization` 应用本地化（`localizations`）。
7. PodFile：若 `podfile` 键指定了完整 Podfile 则复制并重写 source；否则走旧路径，把 `unityMain.pods` / `unityFramework.pods` 逐行注入到 `Unity-iPhone` 与 `UnityFramework` 两个 target 块。
8. 最后执行 `pod install`，键 `podInstall` **缺省即视为执行**，配置 `false` 可跳过。

## Run()：target 级配置的八项子任务

`Run` 是第一阶段的核心，对单个 target 依次应用以下内容（对应 `unityMain` / `unityFramework` 下的各字段）：

| 顺序 | 方法 | 配置键 | 作用 |
|------|------|--------|------|
| 1 | `SetBuildProperties` | `properties` | 构建属性 |
| 2 | `SetFrameworks` | `frameworks` | 框架 |
| 3 | `SetLibs` | `libs` | 系统库 |
| 4 | `RunCopyFiles` | `files` | 复制文件 |
| 5 | `CopyFolders` | `folders` | 复制文件夹 |
| 6 | `SetFilesCompileFlag` | `filesCompileFlag` | 文件编译标记 |
| 7 | `AddOtherLinkFlag` | `otherLinkerFlag` | Linker Flag |
| 8 | `AddRunPathSearchPaths` | `runPathSearchPaths` | Run Path Search Paths |

```csharp
static void Run(PBXProject pbxProject, string targetGuid, string mainTargetGuid, Hashtable hashtable, string path)
{
    SetBuildProperties(pbxProject, targetGuid, hashtable.Get<Hashtable>("properties"));
    SetFrameworks(pbxProject, targetGuid, hashtable.Get<Hashtable>("frameworks"));
    SetLibs(pbxProject, targetGuid, hashtable.Get<Hashtable>("libs"));
    RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
    CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
    SetFilesCompileFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("filesCompileFlag"));
    AddOtherLinkFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("otherLinkerFlag"));
    AddRunPathSearchPaths(pbxProject, targetGuid, hashtable.Get<Hashtable>("runPathSearchPaths"));
}
```

## 顶层配置键一览

最终合并配置的顶层节点及其消费方式（均来自 [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L152)）：

| 键 | 类型 | 应用位置 | 说明 |
|----|------|----------|------|
| `unityMain` | object | Unity-iPhone target | 主 target 的 `Run()` 八项子任务 |

| `localizations` | array | 工程 | `RunLocalization` |
| `podSource` | array | Podfile | `RunPodfile` / `EnsurePodfileExists` |
| `podfile` | string | Podfile | 指定完整 Podfile 路径，命中后走新路径 |
| `podInstall` | bool | — | 缺省视为 `true`；`false` 跳过 `pod install` |

## 合并顺序与覆盖规则

优先级从低到高，后合并的覆盖先合并的（深合并，相同键以新值为准）：

1. 工程内所有 `XCodeConfig.json`（按排序后的路径顺序逐个合并）；
2. `XCodeConfig.{channel}.json` 渠道专属配置（最后合并，优先级最高）。

因此想让某渠道覆盖某个字段，把该字段写进渠道文件即可，无需改动通用配置。
