# 使用扩展方法简化 Unity API

GameFrameX 提供了大量针对 Unity 内置类型（`GameObject`、`Transform`、`Vector2/3/4`、`Component` 等）的扩展方法,直接在原类型上挂载新行为,让你写更少的样板代码就能完成常见操作。本页按类型列出最常用的扩展方法并给出可直接复制的示例。

所有扩展方法都位于 `GameFrameX.Runtime` 命名空间,文件顶部加上即可使用全部扩展。

### 2. 在 `GameObject` / `Component` 上操作

`GetOrAddComponent`、`DestroyComponent` 是最常见的两个组件级扩展。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class Player : MonoBehaviour
{
    private Rigidbody _rigidbody;

    void Awake()
    {
        // 不存在则自动添加,存在则直接返回
        _rigidbody = gameObject.GetOrAddComponent<Rigidbody>();
    }

    void OnDisable()
    {
        // 销毁指定类型的组件
        gameObject.DestroyComponent<Rigidbody>();

        // 或从 Component 自身调用,销毁同 GameObject 上同类型组件
        _rigidbody.DestroyComponent();
    }
}
```

### 3. 在 `Transform` 上查找与单轴赋值

`FindChildName` 支持深度优先查找任意层级的子节点;`SetPositionX/Y/Z` 用于只改某一轴的世界坐标,避免读出整组再写回。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class Enemy : MonoBehaviour
{
    public Transform weaponSlot;

    void Start()
    {
        // 深度查找名为 "WeaponSocket" 的子节点
        var socket = transform.FindChildName("WeaponSocket");
        if (socket != null)
        {
            weaponSlot = socket;
        }

        // 仅修改世界坐标的 X 轴
        transform.SetPositionX(10f);
    }
}
```

### 4. 在 `Vector2 / Vector3 / Vector4` 之间转换

不同 UI 与物理调用对向量类型有不同偏好,使用 `ToVector2 / ToVector3 / ToVector4` 一行搞定维度切换。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class CameraShake : MonoBehaviour
{
    public Vector3Int gridPos;

    void Update()
    {
        // Vector3Int → Vector3
        Vector3 worldPos = gridPos.ToVector3();

        // Vector3 (x, y, z) → Vector2 (x, z),忽略 Y
        Vector2 topDown = worldPos.ToVector2();

        // Vector3 → Vector4,w 默认 0
        Vector4 homogeneous = worldPos.ToVector4();
    }
}
```

### 5. 字符串快速比较与判空

`EqualsFast` 逐字符从尾部向前比较,避免 `string.Equals` 在部分平台上的额外开销;`IsNotNull` / `IsNull` 是 `ObjectExtension` 提供的对象判空扩展。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class NameTag : MonoBehaviour
{
    public string targetName = "Player";

    void Update()
    {
        // 快速比较两个字符串是否相等
        if (transform.name.EqualsFast(targetName))
        {
            Debug.Log("匹配");
        }

        // 判空,等价于 != null,但不调用 Unity 的重载 ==
        if (this.IsNotNull())
        {
            // ...
        }
    }
}
```

## 常见错误

- **忘了 `using GameFrameX.Runtime;`** — 扩展方法必须可见才能被调用;若 IDE 报红先检查命名空间。
- **`gameObject.DestroyComponent()` 不带泛型** — 该方法仅在 `Component` 自身调用时返回同类型组件并销毁;对 `GameObject` 必须传泛型 `DestroyComponent<T>()`。
- **`FindChildName` 与 `Transform.Find` 混淆** — `Transform.Find` 只能找直接子节点;需要跨层级查找时用 `FindChildName`。
- **`EqualsFast` 在两个 null 上返回 true** — 与 `string.Equals` 行为一致,但要注意它不做文化区域(locale)敏感比较,本地化场景仍应使用 `string.Equals`。

## 背景(可选)

扩展方法在 C# 中通过 `this T self` 修饰符挂载到已有类型上,IL 层会编译为普通静态方法。GameFrameX 把 Unity 常用样板(如 `GetComponent` + `AddComponent`、`Find` 深度搜索、向量维度转换)都封装成了扩展,既保留静态调用零分配的优点,又获得了链式写法与 IDE 智能提示。所有扩展类都标记了 `[UnityEngine.Scripting.Preserve]`,确保 IL2CPP / 代码裁剪后仍可用。
