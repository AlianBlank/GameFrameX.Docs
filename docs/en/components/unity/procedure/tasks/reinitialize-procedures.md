# How to Reset the Procedure Component

This document describes how to destroy the current procedure state machine at runtime and reinitialize it with a new procedure array, completing "clear + rebuild" in a single call. It introduces two entry points for `ReinitializeProcedures` and the correct usage.

## Prerequisites

- The procedure component instance has been obtained via `GameEntry.GetComponent<ProcedureComponent>()`
- At least one procedure class that inherits from `ProcedureBase` has been defined
- The framework has completed initialization (whether `m_ProcedureFsm` exists or not is acceptable)

## Steps

1. **Build a new procedure array**: instantiate all procedure objects to be registered into the new state machine.

   ```csharp
   var procedures = new ProcedureBase[]
   {
       new LaunchProcedure(),
       new LoginProcedure(),
       new GameProcedure(),
   };
   ```

2. **Specify the entrance procedure**: choose one from the same group of procedures as the entrance procedure.

   ```csharp
   var entrance = procedures[1]; // LoginProcedure
   ```

3. **Call the reset method**: execute the reset through the procedure component. The framework will first destroy the old state machine, then rebuild it with the new array.

   ```csharp
   ProcedureComponent procedureComponent = GameEntry.GetComponent<ProcedureComponent>();
   procedureComponent.ReinitializeProcedures(procedures, entrance);
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

4. **(Optional) Start the entrance procedure**: if you need to enter the procedure immediately, call `StartProcedure`.

   ```csharp
   procedureComponent.StartProcedure(entrance.GetType());
   ```

## Common Variants

### Use the Procedure Manager Directly

If you don't use the `ProcedureComponent` wrapper, you can call `ReinitializeProcedures(params ProcedureBase[] procedures)` directly at the manager level. The signature only accepts a procedure array and does not include the entrance procedure setting.

```csharp
m_ProcedureManager.ReinitializeProcedures(new ProcedureBase[]
{
    new LaunchProcedure(),
    new LoginProcedure(),
});
```

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L260-L271)

### Destroy Only (Without Rebuilding)

If you only want to clear existing procedures without rebuilding, use `DestroyProcedures()`:

```csharp
procedureComponent.DestroyProcedures();
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L107-L111)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Throws `GameFrameworkException("Procedures is invalid.")` | The length of the passed `procedures` array is 0 | Pass at least one `ProcedureBase` instance |
| `OnDestroy` of the old procedure does not fire after reset | The old procedure reference is still held externally, so the state machine destruction callback is not executed | Do not cache `ProcedureBase` instances externally for an extended period |
| `CurrentProcedure` throws an exception after the call | `StartProcedure` was not called after the rebuild | Call `StartProcedure` after the reset to specify the entrance |
| `NullReferenceException` | `ProcedureComponent` is not registered with the framework | Ensure `ProcedureComponent` is mounted and enabled in the scene |

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L264-L270)

## Background (Optional)

The internal sequence of `ReinitializeProcedures` is: first call `DestroyProcedures()` to destroy the old state machine, then validate that the new array is not empty, and finally use `m_FsmManager.CreateFsm(this, procedures)` to rebuild the FSM. The `ProcedureComponent` wrapper additionally stores `m_EntranceProcedure` on top of this, for subsequent `StartProcedure` calls.
