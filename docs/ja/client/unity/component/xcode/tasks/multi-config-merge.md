# マルチモジュール設定ファイルのマージ

各モジュールごとの iOS ビルド設定を 1 つの `XCodeConfig.json` として記述しておけば、フレームワークが Xcode プロジェクトのエクスポート後に、同名の設定ファイルすべて（チャネル専用設定を含む）を自動的にスキャン・マージし、そのマージ結果を Xcode プロジェクトへ一括で書き込みます。手作業で大きな設定ファイルにまとめ直す必要はなく、ファイルをスキャン可能な場所に置くだけで済みます。

## 前提条件

- Unity プロジェクトに本パッケージが導入済みであること（Editor アセンブリ `GameFrameX.Xcode.Editor`）。
- ビルドターゲットが iOS であること：マージ処理全体は `#if UNITY_IOS` 内にあり、その他のプラットフォームではそのまま返ります。

## 操作手順

1. 各モジュールに対して 1 つの `XCodeConfig.json` を作成し、そのモジュールが関心を持つフィールドのみを記述します。フレームワークは `SettingLoader.LoadSettingsData("XCodeConfig.json")` によって、一致するすべてのファイルのパス一覧をスキャンします（[SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58) を参照）。
2. iOS ビルドを実行します。ビルド完了後、Unity のコールバックが自動的に実行され、設定の読み込みとマージが始まります：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        //設定ファイルを読み込む
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 一致するファイルが 1 つも見つからない場合はそのまま返す
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }

        // すべての設定ファイルの内容をマージする
        Hashtable finalConfig = new Hashtable();
        foreach (var jsonPath in jsonPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
            string json = File.ReadAllText(jsonPath);
            Hashtable table = json.HashtableFromJson();
            if (table == null)
            {
                LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
                continue;
            }

            // 拡張メソッドを使用して Hashtable をマージする
            finalConfig.Merge(table);
        }
```

出典: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L49)

3. （任意）チャネル専用設定を用意します。フレームワークは `SettingLoader.GetChannel()` で現在のチャネルを取得し、`XCodeConfig.{channel}.json` をロードして最後にマージします。そのためチャネル設定の優先度は最も高く、通常設定の同名フィールドを上書きします：

```csharp
// チャネル専用設定をマージ（優先度が最も高く、最後にマージして上書きされる）
string channel = SettingLoader.GetChannel();
if (!string.IsNullOrEmpty(channel))
{
    var channelPaths = SettingLoader.LoadChannelSettingsData("XCodeConfig.json", channel);
    if (channelPaths.Count > 0)
    {
        LogHelper.Log($"[MergeConfig] 检测到渠道: {channel}，正在合并渠道配置...");
        foreach (var channelPath in channelPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并渠道配置: {channelPath}");
            string channelJson = File.ReadAllText(channelPath);
            Hashtable channelTable = channelJson.HashtableFromJson();
            if (channelTable == null)
            {
                LogHelper.Error($"{channelPath} 解析失败, 跳过合并");
                continue;
            }

            finalConfig.Merge(channelTable);
        }
    }
    else
    {
        LogHelper.Log($"[MergeConfig] 未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json");
    }
}
```

出典: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)

4. Console の出力を確認します。マージ対象の各ファイルには `[MergeConfig] 正在合并配置: <路径>`（チャネル設定の場合は `[MergeConfig] 正在合并渠道配置: <路径>`）が出力されるため、これをもとにどのファイルがマージに参加したかを確認できます。

## マージ可能なトップレベル設定フィールド

マージ結果は以下のキーに従って適用されます（キー名は `finalConfig.Get<...>(...)` の実際の取得値に基づきます。どのモジュールも、自分が使用するキーのみを提供すれば十分です）：

| キー | 型 | 適用動作 |
|----|------|----------|
| `unityMain` | Hashtable | Unity メイン Target に適用：`properties`、`frameworks`、`libs`、`files`、`folders`、`filesCompileFlag`、`otherLinkerFlag`、`runPathSearchPaths`（および旧式の `pods`） |
| `unityFramework` | Hashtable | 同上。UnityFramework Target に適用 |
| `signing` | Hashtable | 署名設定。メイン Target にのみ設定される。その `bundleId` は Capabilities で使用される |
| `swiftBridging` | bool | Swift ブリッジングのオン/オフ。省略時は有効とみなされる |
| `plist` | Hashtable | Info.Plist に書き込む |
| `environmentVariables` | Hashtable | 起動時の環境変数 |
| `launcherArgs` | ArrayList | 実行時の起動引数 |
| `capabilities` | Hashtable | Capability 設定。メイン Target にのみ設定される |
| `localizations` | ArrayList | ローカライズリソース |
| `podSource` | ArrayList | Podfile の source ソース |
| `podfile` | string | 完全な Podfile の設定パス。コピー成功後は新しいパスが使用される |
| `podInstall` | bool | Podfile 処理後に `pod install` を実行するかどうか。省略時は有効とみなされる |

出典: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L89-L156)

## よくあるバリエーション

- **あるモジュールの JSON 解析に失敗してもビルドを完了したい場合**：1 つのファイルの解析失敗では `Error` ログを出力して `continue` するだけで、全体の処理は中断されません。残りのファイルは引き続きマージされます。
- **`pod install` を実行したくない場合**：（マージに参加するいずれかの）設定に `"podInstall": false` を記述します。詳細は [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L151-L156) を参照。
- **Swift ブリッジングを無効にしたい場合**：`"swiftBridging": false` を記述します。このキーを記述しない場合はデフォルトで有効になります。詳細は [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101) を参照。

## よくあるエラー

| 症状（ログ原文） | 原因 | 修正方法 |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | スキャン結果が空で、どのモジュールも設定を提供していない | `LoadSettingsData` でスキャンできる `XCodeConfig.json` が少なくとも 1 つ存在することを確認する |
| `<路径> 解析失败, 跳过合并` | そのファイルの内容が有効な JSON ではなく、`HashtableFromJson()` が null を返す | そのファイルの JSON 構文を修正する。当該ファイルはスキップされ、残りのファイルは通常どおりマージされる |
| `合并后的配置为空，跳过设置` | すべてのファイルが解析に失敗した、または内容が空 | JSON を 1 つずつ確認する。`[MergeConfig] 正在合并配置:` のログからマージに参加したファイル一覧を照合する |
| `[MergeConfig] 未找到渠道 [...] 的专属配置文件 XCodeConfig.[...].json` | チャネルが設定されているが、チャネル専用ファイルが存在しない | 必要に応じて `XCodeConfig.{渠道}.json` を作成する。作成しなくても通常設定の適用には影響しない |

出典: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L28-L83)

## 検証

- Console に `[MergeConfig] 正在合并配置: ...` が出力され、参加するすべてのファイルが列挙されます。チャネルが設定されている場合は `[MergeConfig] 检测到渠道: <渠道>` と対応するチャネルのマージログが出力されます。
- 続いて `[PBXProject] 正在应用最终合并配置...` と `[OtherSettings] 正在应用最终合并配置...` が出力されれば、マージ結果がプロジェクトに書き込まれたことを示します。
- エクスポートされた Xcode プロジェクトを開き、Target のビルド属性、フレームワーク/ライブラリ、Info.Plist、Podfile などがマージ後の期待値どおりであるかを確認します。

## 背景

マージは `Hashtable.Merge()` 拡張メソッドによってファイルごとに重ね合わせて行われ、後からマージされたものが先にマージされたものを上書きするため、読み込み順序がそのまま優先順序になります。チャネル設定は最後にマージされるため、優先度が最も高くなります。処理全体では `Get<Hashtable>(...)` の取得値に対して null 許容の考慮がされているため、各モジュールは必要なキーのみを記述すればよく、完全な構造を提供する必要はありません。
