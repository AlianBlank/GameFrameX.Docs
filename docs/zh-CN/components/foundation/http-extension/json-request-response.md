# 如何发送 JSON 请求体并解析响应

使用 `HttpClientJsonExtension` 的 `PostJsonAsync / PutJsonAsync / PatchJsonAsync / SendJsonAsync` 等扩展方法,即可在一步内发送 JSON 请求体并把响应反序列化为目标类型;若想自己掌控状态码或读取原始响应体,改用 `*ResponseAsync` 系列方法,再通过 `HttpClientResponse.As<T>()` 反序列化。

## 前置条件

- 引用 NuGet 包 `GameFrameX.Foundation.Http.Extension`(`GameFrameX.Foundation.Http.Normalization` 用于统一的 JSON 响应包装)。
- 已创建或注入 `HttpClient` 实例(推荐通过 `IHttpClientFactory` 管理生命周期)。
- .NET 6+(`HttpClientJsonExtension` 依赖 `System.Net.Http.Json.JsonContent`)。

## 操作步骤

### 1. 直接拿到强类型响应(最常用)

`PostJsonAsync<TRequest, TResponse>` 会把请求对象序列化为 JSON、POST 到目标地址,并把成功响应(2xx)反序列化为 `TResponse`。非成功状态会抛 `HttpClientRequestException`,内部携带状态码、请求 URI 和响应体。

```csharp
using System.Net.Http;
using System.Threading.Tasks;
using GameFrameX.Foundation.Http.Extension;

var httpClient = new HttpClient { BaseAddress = new System.Uri("https://api.example.com") };

var request = new CreateOrderRequest
{
    Sku = "SKU-001",
    Quantity = 2
};

CreateOrderResponse? response = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request);

System.Console.WriteLine(response?.OrderId);
```

```csharp
public sealed class CreateOrderRequest
{
    public string Sku { get; set; }
    public int Quantity { get; set; }
}

public sealed class CreateOrderResponse
{
    public string OrderId { get; set; }
    public string Status { get; set; }
}
```

### 2. 自定义 JSON 序列化、Header、超时与重试

通过 `HttpClientRequestOptions` 注入 `JsonSerializerOptions`、请求头、超时和重试策略;扩展方法会自动在请求/响应/重试时触发回调,便于打日志或埋点。

```csharp
using System.Text.Json;
using GameFrameX.Foundation.Http.Extension;

var options = new HttpClientRequestOptions
{
    Timeout = System.TimeSpan.FromSeconds(10),
    JsonSerializerOptions = new JsonSerializerOptions
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase
    }
};
options.Headers["Authorization"] = "Bearer xxx";
options.Retry.MaxRetries = 3;
options.OnResponse = e =>
    System.Console.WriteLine($"[{e.Attempt}] {e.Method} {e.RequestUri} -> {(int)e.StatusCode}");

var result = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    options);
```

`HttpClientRetryOptions` 默认在 `RequestTimeout / TooManyRequests / InternalServerError / BadGateway / ServiceUnavailable / GatewayTimeout` 上触发重试,基础退避 100ms × `BackoffFactor=2` 指数递增;POST/PATCH 默认不重试,需要时设置 `AllowNonIdempotentRetry = true`。

### 3. 拿到原始响应(状态码 + Body + Header)

当需要根据状态码分支、或读取错误体后再决定如何反序列化时,使用 `*ResponseAsync` 系列。`HttpClientResponse.As<T>()` 使用与请求相同的 `JsonSerializerOptions` 解析 Body。

```csharp
using GameFrameX.Foundation.Http.Extension;

var resp = await httpClient.PostResponseAsync<CreateOrderRequest>(
    HttpMethod.Post,
    "/orders",
    request);

System.Console.WriteLine($"status={resp.StatusCode} attempt={resp.Attempt}");

if (!resp.IsSuccessStatusCode)
{
    // 失败也拿到 Body,便于统一报错
    System.Console.WriteLine($"error body: {resp.Body}");
    return;
}

CreateOrderResponse? ok = resp.As<CreateOrderResponse>();
System.Console.WriteLine(ok?.OrderId);

// 显式断言成功,失败时抛 HttpClientRequestException
resp.EnsureSuccessStatusCode();
```

### 4. 发送任意方法 + JSON 请求体

`SendJsonAsync<TRequest, TResponse>(HttpMethod method, …)` 是底层入口,其它 POST/PUT/PATCH 重载都委托给它,可用于自定义方法或第三方 WebHook。

```csharp
var result = await httpClient.SendJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    HttpMethod.Post,
    "https://api.example.com/orders",
    request);
```

### 5. 没有请求体的 JSON 调用

GET/DELETE/OPTIONS 等无 Body 的场景,使用 `GetJsonAsync<TResponse>`、`DeleteJsonAsync<TResponse>` 等单类型参数重载即可。

```csharp
OrderList? list = await httpClient.GetJsonAsync<OrderList>("/orders?status=open");
```

## 常见变体

### 统一响应包装 `IHttpJsonResult`

很多后端使用 `{ code, message, data }` 风格返回值,可用 `GameFrameX.Foundation.Http.Normalization` 中的 `IHttpJsonResult<T>` / `HttpJsonResultHelper`,让扩展自动校验 `code` 字段并把 `data` 取出。

```csharp
using GameFrameX.Foundation.Http.Normalization;

var resp = await httpClient.PostJsonAsync<CreateOrderRequest, HttpJsonResult<CreateOrderResponse>>(
    "/orders",
    request);

HttpJsonResult<CreateOrderResponse> ok = HttpJsonResultHelper.EnsureSuccess(resp);
CreateOrderResponse data = ok.Data;
```

### 取消令牌

所有扩展方法都支持 `CancellationToken`,与 ASP.NET Core 的 `HttpContext.RequestAborted` 直连即可。

```csharp
var resp = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    cancellationToken: HttpContext.RequestAborted);
```

## 常见错误

- **`url` 传 null 或空串**:`SendJsonAsync` 内部 `ArgumentException.ThrowIfNullOrWhiteSpace(url, nameof(url))`,会立即抛 `ArgumentException`。
- **反序列化失败**:`SendJsonAsync` 在非 2xx 时抛 `HttpClientRequestException`;若返回 200 但 Body 不是合法 JSON,`As<T>` 会抛 `System.Text.Json.JsonException`。
- **POST/PATCH 不会自动重试**:默认 `AllowNonIdempotentRetry=false`,如需对写接口重试,显式打开该开关或确认对端是幂等的。
- **`HttpClientRequestOptions` 复用时 `JsonSerializerOptions` 被覆盖**:该属性是 `set` 而不是 init,每次发送前请确认传入的是期望的实例。
- **响应体被截断显示在异常消息里**:`HttpClientJsonExtension` 内部 `ResponseSummaryLimit = 1024`,完整原文始终在 `HttpClientRequestException.ResponseBody`(通过 `*ResponseAsync` 拿到 `HttpClientResponse.Body`)。

## 背景(可选)

`HttpClientJsonExtension` 内部用 `JsonContent.Create(request, options: options.JsonSerializerOptions)` 构造请求体,所有方法走同一条 `ExecuteCoreAsync` 重试/超时通道,再由 `Selector`(强类型方法抛状态码异常、`*ResponseAsync` 透传 `RawResponse`)分支出两种结果。这是同一份代码同时支持「直接拿对象」和「先看状态码」两种用法。
