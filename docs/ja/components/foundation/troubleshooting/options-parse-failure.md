# コマンドライン引数の解析に失敗した場合の対処法

`OptionsBuilder` または `CommandLineArgumentConverter` を使用してコマンドライン引数を解析する際に `ArgumentException`、`ArgumentAlreadyException`、必須オプションの検証失敗、属性値の型不一致などが発生した場合は、本ページの診断表に従って根本原因を特定し、修正してください。

## クイック診断

| 症状（エラーメッセージ/現象） | 原因 | 修正方法 |
|----------------------|------|------|
| `Argument cannot contain null` 形式の `ArgumentException`、パラメータ名 `args` | `args` 配列に `null` 要素が含まれている（`Main` の引数では通常発生しませんが、手動で構築した場合に入り込む可能性があります） | [args から null を除去する](#修正-1args-から-null-要素を除去する) を参照 |
| `ArgumentException` にラップされた "パラメータ処理中にエラーが発生しました: ..." | 解析処理内の他の分岐で例外が発生し、`ConvertToStandardFormat` の外側 `catch` でラップされた | `ex.InnerException.Message` を確認し、具体的なサブ問題に対応付ける；[修正 2](#修正-2パラメータ処理中の内部例外を調査する) を参照 |
| 必須オプションが未割り当ての場合にプロセスがクラッシュする、またはフィールドがデフォルト値になる | 必須パラメータが不足しており、`skipValidation: true` も渡されていない | `skipValidation` で検証をスキップするか、必須パラメータを補完する；[修正 3](#修正-3必須パラメータを補完するか検証をスキップする) を参照 |
| 同じキーが 2 回代入され、後の値が反映されない、または `ArgumentAlreadyException` がスローされる | 同じオプションが重複して渡されている、または環境変数とコマンドラインで同名キーが衝突している | [修正 4](#修正-4引数の重複または環境変数とコマンドラインの衝突を解決する) を参照 |
| ブール型のフィールドに `"true"/"false"` 以外の文字列が入る | `BoolArgumentFormat.Flag` モードで、値のよう見える次のトークンがブール値として消費される/認識されない | 明示的に `--flag=true` を渡すか、`BoolArgumentFormat` を切り替える；[修正 5](#修正-5ブール引数の解析異常) を参照 |
| 負数（例：`--offset=-3`）が「オプションキー」として認識され、次の引数を値として誤って扱う | `IsNegativeNumber` で負数として認識されている場合、`IsOptionToken` は `false` を返すが、スペースを含む負数の表現は誤判定される可能性がある | 値を `--offset=-3` の形式で記述し、負数の後に値を続けて追加しないようにする；[修正 6](#修正-6負数とスペースを含む値の解析異常) を参照 |
| キーと値のペア `--key=` の後ろの値が失われ、フィールドがデフォルト値になる | 空文字列の値が「値なし」と見なされ、次の項目がスキップされる | 空値を保持したい場合は `--key=""` を使用するか、`EnsurePrefixedKeys=true` を維持して `--key=` を正常に処理できるようにする |

## 修正手順

### 修正 1：args から null 要素を除去する

`ConvertToStandardFormat` は `arg == null` を検出するとすぐに `ArgumentException` をスローします：

```csharp
// CommandLineArgumentConverter.ConvertToStandardFormat
if (arg == null)
{
    throw new ArgumentException(LocalizationService.GetString(LocalizationKeys.Exceptions.ArgsCannotContainNull), nameof(args));
}
```

修正方法：呼び出し前にフィルタリングします：

```csharp
using GameFrameX.Foundation.Options;

var cleanArgs = (args ?? Array.Empty<string>())
    .Where(a => a != null)
    .ToArray();

var options = OptionsBuilder.Create<MyOptions>(cleanArgs);
```

> 出典：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L188-L194)

### 修正 2：パラメータ処理中の内部例外を調査する

`ConvertToStandardFormat` の外側 `catch` は、`ArgumentException` 以外の例外をラップして再スローします：

```csharp
catch (Exception ex)
{
    throw new ArgumentException(
        LocalizationService.GetString(LocalizationKeys.Exceptions.ProcessingError, ex.Message),
        ex);
}
```

調査手順：

1. 外側の `ArgumentException` をキャッチし、`ex.InnerException` を読み取って実際のスタックトレースを取得する。
2. `InnerException` が `ArgumentAlreadyException` の場合は、[修正 4](#修正-4引数の重複または環境変数とコマンドラインの衝突を解決する) に進む。
3. `InnerException` がリフレクション/型変換関連（例：`InvalidCastException`、`FormatException`）の場合、通常はコマンドライン値の文字列为目标的属性类型に変換できないことが原因です。`MyOptions` の対応するフィールドの型と渡された値を確認してください。

> 出典：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L219-L227)

### 修正 3：必須パラメータを補完するか検証をスキップする

`OptionsBuilder.Create<TOptions>(args, skipValidation)` の 2 番目のパラメータは、必須オプションの検証をスキップするかどうかを制御します。開発/デバッグ段階、またはプロセスを終了させたくないシナリオでは、次のように使用できます：

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.Create<MyOptions>(args, skipValidation: true);
```

ビジネスロジック上スキップできない場合は、「必須」とマークされたすべてのオプションが渡されていることを確認する必要があります：

- `OptionsDebugger.PrintParsedOptions(opts)` を使用して解析結果を出力し、各属性が予期した値かどうかを確認する。
- 環境変数は「暗黙的なソース」としてフィールドを補完するため、「コマンドラインを渡していないように見える」場合でも、実際には環境変数が有効になっている可能性があることに注意してください。

> 出典：[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L67)

### 修正 4：引数の重複または環境変数とコマンドラインの衝突を解決する

同じ名前のキーの重複は `ArgumentAlreadyException` をトリガーします：

```csharp
// ArgumentAlreadyException.Throw
public static void Throw(string message)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(message, nameof(message));
    throw new ArgumentAlreadyException(message);
}
```

修正方法：

- コマンドラインレベル：重複するオプションをマージし、同じ論理キーが一度だけ出現するようにする。
- コマンドラインと環境変数：`OptionsBuilder.CreateFromArgsOnly<TOptions>(args)` を使用して環境変数を明示的に無効化し、同名キーが上書きされたときのロジックの混乱を避ける：

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);
```

> 出典：[ArgumentAlreadyException.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ArgumentAlreadyException.cs#L69-L73)、[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L103-L107)

### 修正 5：ブール引数の解析異常

`BoolArgumentFormat.Flag`（デフォルト）モードでは、`AttachValueIfPresent` はブールリテラルとして認識される次のトークンをスキップし、`--verbose true` のような記述で `true` が `--verbose` の値として誤って扱われるのを防ぎます：

```csharp
if (BoolFormat == BoolArgumentFormat.Flag && BooleanParser.IsBooleanValue(nextArg))
{
    return currentIndex + 1;
}
```

ブール値を文字列/コレクション型のフィールドに代入したい場合は、キーと値のペア形式を使用してください：

```bash
# このようにしないでください（ブール値がスキップされます）
myapp --mode true

# このようにしてください
myapp --mode=true
```

> 出典：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L336-L344)

### 修正 6：負数とスペースを含む値の解析異常

`IsOptionToken` はすでに負数の例外処理を行っています：

```csharp
private static bool IsOptionToken(string value)
{
    if (string.IsNullOrEmpty(value)) return false;
    if (!value.StartsWith("-")) return false;
    return !IsNegativeNumber(value);
}
```

ただし、`EnsurePrefixedKeys=true` の場合、「非オプション」として誤認識された負数のトークンは `NormalizeKey` によって `--` プレフィックスが追加されます：

```csharp
return EnsurePrefixedKeys ? "--" + arg : arg;
```

したがって、負数を渡す場合は明示的にプレフィックスを付けるか、キーと値のペア形式を使用することをお勧めします：

```bash
# 推奨：キーと値のペアは書き換えられません
myapp --offset=-3

# 非推奨：`-- -3` に補完されるか、オプションとして誤認識される可能性があります
myapp offset -3
```

スペースを含む文字列値は `AppendTokenWithQuotingIfNeeded` によって自動的に二重引用符が追加されます。`string[]` から解析に入る時点ではすでにスペースで分割されているため、追加の処理は必要ありません。単一の文字列からコマンドラインを再構築する場合（`ToCommandLineString`）、引用符が自動的に追加されます。

> 出典：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L347-L365)

## 検証

次の順序で問題が解決されたことを確認してください：

1. `OptionsBuilder.CreateWithDebug<TOptions>(args)` を使用して解析結果を出力し、各属性の最終値を確認する。
2. `OptionsBuilder.TryCreate<TOptions>(args, out var result, out var error)` を使用して失敗パスをラップする：失敗した場合はデフォルトインスタンスを返し、`error` を通じてメッセージを取得でき、プロセスはクラッシュしません。
3. デバッガーで `ex.InnerException` を観察し、根本原因が特定されていることを確認する（特に `ArgumentAlreadyException` や `FormatException` などのサブ例外）。

> 出典：[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L149-L184)
