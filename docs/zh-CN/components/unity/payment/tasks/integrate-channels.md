# 接入平台渠道

在 `PaymentComponent` 上配置各平台的实现类型字符串,框架会在启动时按平台自动实例化对应的渠道 `PaymentManager`(Google / Apple / WebGL / PC),业务代码只面向 `IPaymentManager` 编程;要接入自有渠道,继承 `BasePaymentManager` 并把类型名填进 Inspector 即可。

## 前置条件

- 已安装本支付核心包(`GameFrameX.Payment.Runtime`)。
- 场景中已挂载 `PaymentComponent`,它会通过 `RequireComponent` 自动带上 `GameFrameXPaymentCroppingHelper`。
- 目标平台的渠道实现包已安装(见下文"渠道类型对照表",各渠道实现分布在对应命名空间的独立包中)。

## 操作步骤

1. 在场景对象上添加组件:菜单路径为 `GameFrameX/Payment`(来源于 `AddComponentMenu`):

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
{
    private IPaymentManager _paymentManager;
    [SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
    [SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
    [SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
    [SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
    [SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L28)

2. 安装目标平台对应的渠道实现包(包名与下表命名空间一致,例如 Google 渠道位于 `GameFrameX.Payment.Google.Runtime`)。

3. 确认渠道类型名与实际安装的实现一致;如需替换为自有实现,直接在 Inspector 中修改对应平台的类型字符串。

4. 启动后框架按平台宏自动选择实现:

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

| 平台宏 | Inspector 字段 | 默认实现类型 |
|--------|----------------|--------------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` |

## 接入自有渠道

1. 继承 `BasePaymentManager`(它已实现 `GameFrameworkModule, IPaymentManager`,并内置四个事件的 `Raise*` 触发方法),补齐抽象成员:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    /// <summary>
    /// 购买成功事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;

    /// <summary>
    /// 购买失败事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;

    /// <summary>
    /// 查询购买记录结果事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

    /// <summary>
    /// 消耗购买结果事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    protected void RaisePurchaseFailed(PaymentEventArgs e)
    {
        OnPurchaseFailed?.Invoke(this, e);
    }

    protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
    {
        OnQueryPurchasesResult?.Invoke(this, e);
    }

    protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
    {
        OnConsumePurchaseResult?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);
}
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L67)

其余抽象成员 `IsReady()`、`SetPredefinedProductIds(List<string>, List<string>)`、`QueryPurchases(PaymentProductType)`、`ConsumePurchase(string)`、`BuyInApp`/`BuySubs`/`Buy`(已标记 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`)与推荐使用的 `Buy(PurchaseParams)` 均需在子类中实现,完整签名见 [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L69-L137)。

2. 如渠道需要额外购买参数,继承 `PurchaseParams` 扩展字段(源码注释:"各渠道可继承并扩展自有字段"):

```csharp
/// <summary>
/// 购买参数基类，各渠道可继承并扩展自有字段
/// </summary>
public abstract class PurchaseParams
{
    /// <summary>产品ID或SKU</summary>
    public string ProductId { get; set; }

    /// <summary>订单ID</summary>
    public string OrderId { get; set; }

    /// <summary>产品类型</summary>
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

3. 把你的实现类全名(含命名空间)填入 `PaymentComponent` 对应平台的 Inspector 字段,运行后用 `IsReady()` 验证渠道是否初始化成功。

## 常见变体

- **替换 Android 渠道为自有 SDK**:保持 `m_componentAndroidType` 字段不变,把值改为你的实现类全名(含命名空间),重新打包即可,无需改动 `PaymentComponent` 代码。
- **Mac 与 iOS 共用 Apple 渠道**:默认配置已如此——`m_componentIOSType` 与 `m_componentMacType` 均指向 `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`。
- **编辑器/未支持平台**:命中 `#else` 分支时使用本包内置的 `DefaultPaymentManager` 作为兜底,便于在编辑器中跑通业务流程。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` 返回 null,通常是渠道实现类名写错或对应程序集未编译 | 核对 Inspector 中平台类型字符串与实际类全名、命名空间是否一致,并确认渠道实现包已安装 |
| `Utility.Assembly.GetType(componentType)` 拿不到类型 | 类型名与程序集中的全名不匹配(拼写/命名空间错误) | 在渠道实现包中确认 `namespace` 与类名后,填入完整全名如 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` |
| 编辑器里调用购买无响应 | 命中 `#else` 分支,使用 `DefaultPaymentManager` 兜底实现 | 切换到真机/目标平台构建验证,或接入自定义渠道实现 |
| `Log.Warning("Product ID is null or empty.")` / `"Order ID is null or empty."` | 旧版 `BuyInApp`/`BuySubs`/`Buy(productId, ...)` 传入了空 `productId` 或 `orderId` | 传入有效值,或改用推荐的 `Buy(PurchaseParams)` 重载 |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93)(Fatal 日志位置);其余警告消息见 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L163-L204)

> 说明:`BuyInApp`、`BuySubs`、`Buy(productId, productType, orderId, ...)` 均已标记 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`,新接入请直接使用 `Buy(PurchaseParams)`([IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112))。

## 背景

`PaymentComponent` 在 `Awake` 中根据编译宏确定 `componentType`,再经 `Utility.Assembly.GetType` 反射得到 `ImplementationComponentType`,并以 `IPaymentManager` 作为接口类型注册到 `GameFrameworkEntry`,随后通过 `GameFrameworkEntry.GetModule<IPaymentManager>()` 取得实例。这样业务层只依赖接口,渠道实现通过 Inspector 字符串在运行时注入,实现"一套业务代码、多平台渠道"的切换方式。关于支付组件的整体架构与完整 API,见框架概述页与 API 参考页。
