# 購入履歴の照会と購入の消費方法

`PaymentComponent` を通じて `QueryPurchases(PaymentProductType productType)` を呼び出すと、現在のアカウントの未消費の購入履歴を取得できます。結果は `OnQueryPurchasesResult` イベントコールバックで返されます。`PurchaseToken` を取得した後、`ConsumePurchase(string purchaseToken)` を呼び出して消費を完了すると、その結果は `OnConsumePurchaseResult` イベントコールバックで返されます。両方とも非同期で戻り値はなく、イベントを通じてのみ結果を取得できます。

## 前提条件

- シーンに `GameFrameX/Payment` コンポーネント（`PaymentComponent`）が追加されており、プラットフォームに応じて対応する `IPaymentManager` の実装が自動的にバインドされていること。
- `Init(bool isDebug = false, bool isClientVerify = true)` を呼び出して初期化が完了しており、`IsReady()` が `true` を返した後に照会を開始すること。

## API 一覧

| 名称 | シグネチャ | 説明 |
|------|------|------|
| 購入履歴の照会 | `void QueryPurchases(PaymentProductType productType)` | 製品タイプごとに未消費の購入履歴を照会 |
| 購入の消費 | `void ConsumePurchase(string purchaseToken)` | 購入トークンで購入を1件消費 |
| 照会結果イベント | `event EventHandler<PaymentEventArgs> OnQueryPurchasesResult` | 照会完了（失敗を含む）時に発火 |
| 消費結果イベント | `event EventHandler<PaymentEventArgs> OnConsumePurchaseResult` | 消費完了（失敗を含む）時に発火 |
| 準備完了かどうか | `bool IsReady()` | 決済システムの初期化が完了しているかどうか |

以上のシグネチャは `IPaymentManager` で定義されています：

```csharp
/// <summary>
/// 購入履歴照会結果イベント
/// </summary>
event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

/// <summary>
/// 購入消費結果イベント
/// </summary>
event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

/// <summary>
/// 購入履歴を照会する
/// </summary>
/// <param name="productType">製品タイプ</param>
[UnityEngine.Scripting.Preserve]
void QueryPurchases(PaymentProductType productType);

/// <summary>
/// 購入を消費する
/// </summary>
/// <param name="purchaseToken">購入トークン</param>
[UnityEngine.Scripting.Preserve]
void ConsumePurchase(string purchaseToken);
```

## 操作手順

1. 照会と消費の2つの結果イベントを購読します。`PaymentComponent` 上のイベントは内部の `IPaymentManager` に直接転送されます：

```csharp
public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult
{
    add { _paymentManager.OnQueryPurchasesResult += value; }
    remove { _paymentManager.OnQueryPurchasesResult -= value; }
}

public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult
{
    add { _paymentManager.OnConsumePurchaseResult += value; }
    remove { _paymentManager.OnConsumePurchaseResult -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L48-L64)

2. 初期化して準備完了を確認した後、製品タイプに応じて照会を開始します：

```csharp
paymentComponent.Init(isDebug: false, isClientVerify: true);

if (paymentComponent.IsReady())
{
    // 製品タイプ（アプリ内課金 / サブスクリプション）ごとに現在のアカウントの未消費の購入履歴を照会
    paymentComponent.QueryPurchases(productType);
}
```

3. `OnQueryPurchasesResult` コールバックで結果を読み取ります。成功時、各レコードのトークンは `PaymentEventArgs.PurchaseToken` に格納されています：

```csharp
private void OnQueryPurchasesResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"查询购买记录失败: {e.ResultCode} {e.ErrorMessage}");
        return;
    }

    // 元の購入データ（JSON 形式）。サーバー検証に渡すことが可能
    // e.PurchaseData / e.ProductId / e.OrderId / e.PurchaseToken / e.CustomData
}
```

`PaymentEventArgs` の全フィールド：

```csharp
public sealed class PaymentEventArgs : EventArgs
{
    public string ProductId { get; set; }      // 製品ID
    public string OrderId { get; set; }        // 注文ID
    public string PurchaseToken { get; set; }  // 購入トークン
    public PaymentResultCode ResultCode { get; set; } // 決済結果コード
    public string ErrorMessage { get; set; }   // エラーメッセージ
    public string PurchaseData { get; set; }   // 元の購入データ（JSON形式）
    public string CustomData { get; set; }     // カスタムデータ
}
```

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

4. （サーバー検証通過後）照会で取得したトークンを使って購入を消費し、`OnConsumePurchaseResult` で結果を確認します：

```csharp
paymentComponent.ConsumePurchase(e.PurchaseToken);

private void OnConsumePurchaseResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"消耗购买失败: {e.ResultCode} {e.ErrorMessage}");
        return;
    }
    // 消費済み。アイテムの付与／再付与が可能
}
```

## よくあるバリエーション

- **切断再接続・補填処理**：起動時またはフォアグラウンド復帰時にまず `QueryPurchases` で `OnQueryPurchasesResult` が返す未消費レコードを走査し、検証を通過したものから1件ずつ `ConsumePurchase` を行えば、未処理注文の再付与を完了できます。
- **サブスクリプション商品**：サブスクリプション系の購入も同じく `QueryPurchases` で照会しますが、通常は `ConsumePurchase` による消費は行いません（「消費」のセマンティクスは一回限りの消耗型商品が対象です）。消費するかどうかはチャネルの実装に従います。
- **サーバー検証**：`Init` 時に `isClientVerify` を `false` に設定した場合は、コールバック内の `PurchaseData` と `PurchaseToken` を自社サーバーに送信して検証してから消費してください。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| 呼び出し後にコールバックが一切発生しない | `OnQueryPurchasesResult` / `OnConsumePurchaseResult` を購読せずに呼び出している | 先にイベントを購読してから照会／消費を呼び出す |
| ログに `Pay Manager is invalid.` が出力される | プラットフォームに対応する `IPaymentManager` 実装クラスが見つからない、またはバインドされていない | `PaymentComponent` 上の各プラットフォーム実装クラス名と、対応するチャネルパッケージが導入されているか確認 |
| 照会／消費コールバックの `ResultCode` が `Failed` または `NetworkError` | チャネルサービスに未接続、またはネットワーク異常 | 後ほど再試行。`NetworkError` の場合はネットワーク復旧後に再照会 |
| 消費失敗 `ItemNotOwned` | トークンに対応する購入がすでに消費済み、または存在しない | `QueryPurchases` で最新トークンを再取得し、古い値を再利用しない |
| `VerifyFailed` | 購入検証が通らなかった（クライアントまたはサーバー検証の失敗） | 検証ロジックとクレデンシャルを確認し、検証通過後に消費する |

`PaymentResultCode` のすべての値：`Success`、`Failed`、`Cancelled`、`NetworkError`、`ServiceUnavailable`、`ItemAlreadyOwned`、`ItemNotOwned`、`VerifyFailed`、`Unknown`。

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L14-L25)

## 検証

- `QueryPurchases` が `OnQueryPurchasesResult` を1回発火し、かつ `ResultCode == PaymentResultCode.Success` であること。
- `ConsumePurchase(token)` が `OnConsumePurchaseResult` を1回発火し、かつ `ResultCode == PaymentResultCode.Success` であること。
- 同じ製品タイプを再度照会した際、消費済みのレコードが返されないこと。

## 背景

`PaymentComponent` は `Awake` 内でコンパイルプラットフォームに応じて実装クラスを選択します（Android は `GooglePaymentManager`、iOS/Mac は `ApplePaymentManager`、WebGL/PC にはそれぞれ対応する実装があり、その他のプラットフォームは `DefaultPaymentManager` にフォールバックします）。その後、`GameFrameworkEntry.GetModule<IPaymentManager>()` を通じてインスタンスを取得します。イベントとメソッドはすべてこのインスタンスへの直接転送です。`BasePaymentManager` の `RaiseQueryPurchasesResult` / `RaiseConsumePurchaseResult` が、各チャネル実装の結果を上記のイベントへディスパッチします。決済システム全体の構造については、概要ページを参照してください。
