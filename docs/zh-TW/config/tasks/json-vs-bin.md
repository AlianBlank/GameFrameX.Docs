# JSON 與 BIN 輸出格式的選擇方法

Luban 支援 **JSON** 與 **BIN** 兩種資料輸出格式，每種格式分別對應不同的程式碼範本。本頁面將協助您根據用戶端/伺服器、執行時效能、可讀性等需求，快速從兩者中做出選擇，並說明如何切換至對應的生成腳本與設定項目。

## 一句話總結

- 伺服器(C# / .NET):預設為 `JSON`,若追求極致載入速度則切換為 `BIN`。
- 用戶端(Unity):開發/偵錯階段使用 `JSON`,正式發佈版本強烈建議使用 `BIN`。
- 輸出格式與程式碼範本為一對一對應，變更格式時必須同時修改 `--dataTarget` 與 `--codeTarget`。

## 兩種格式的比較表

| 項目 | JSON | BIN |
|------|------|-----|
| 資料檔案的可讀性 | 純文字，可直接在編輯器/git 中查看 | 二進位格式，沒有工具或執行環境便無法讀取 |
| 檔案大小 | 較大(包含引號、縮排、欄位名稱) | 精簡(欄位以精簡方式序列化，不含欄位名稱) |
| 載入/解析速度 | 較慢(執行時需解析字串) | 快速(以 `MemoryStream` 直接讀取) |
| Git diff/合併 | 容易處理，衝突也容易解決 | 難以處理，衝突基本上只能整檔替換 |
| 對應的程式碼範本 | `cs-dotnet-json`(伺服器端)、`cs-simple-json`(用戶端) | `cs-bin`(伺服器與用戶端共用) |
| 驗證嚴格程度 | 預設 | 透過 `--validationFailAsError true` 啟用 |
| 適用場景 | 開發期、伺服器、偵錯、熱更新的階段性發佈 | 用戶端正式版、對啟動/記憶體敏感的場景 |

來源設定請參考 [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94) 的 `commands` 區段。

## 操作步驟：輸出格式的選擇與切換

### 1. 確認目前生效的格式

開啟 `luban.conf`,在 `commands` 陣列中找到想要生成的目標(server 或 client),並確認其 `active` 欄位：

- `active: true` → 目前生效的指令。
- `active: false` → 備用指令，需要手動啟用。

儲存庫中預設啟用的是 JSON:

```json
{
  "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

來源:[luban.conf#L66-L94](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

### 2. 使用生成腳本快速切換

儲存庫根目錄提供了 4 組生成腳本，無需修改 `luban.conf` 即可直接執行：

| 目標 | JSON | BIN |
|------|------|-----|
| Server | `gen-server-json.bat` / `gen-server-json.sh` | `gen-server-bin.bat` / `gen-server-bin.sh` |
| Client | `gen-client-json.bat` / `gen-client-json.sh` | `gen-client-bin.bat` / `gen-client-bin.sh` |

例如切換至 **伺服器 BIN** 時：

```bat
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

來源:[gen-server-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.bat#L1)

切換至 **用戶端 BIN** 時：

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

來源:[gen-client-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.bat#L1)

### 3. 修改 luban.conf 將目標指令設為 active

若想在 IDE/外掛程式層級預設輸出 BIN(例如：正式發佈的管線)，請將對應 `BIN` 指令的 `active` 改為 `true`,並將 `JSON` 指令的 `active` 改為 `false`:

```json
{
  "command": "--target server --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

來源:[luban.conf#L78-L87](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L78-L87)

注意：若指定 `--validationFailAsError true`,BIN 格式在驗證失敗時會直接報錯而非僅發出警告。建議在正式環境中保留此設定。

## 常見變體

### 變體 A:伺服器 JSON(預設)

適用於本機開發與伺服器端熱更新。生成物可直接進行 `git diff`,也支援文字搜尋。

```bat
dotnet.exe ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

來源:[gen-server-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-json.bat#L1)

### 變體 B:用戶端 JSON(預設)

適用於 Unity 用戶端的偵錯階段。會將 `*.json` 匯出至 `Assets/Bundles/Config`,程式碼範本為 `cs-simple-json`。

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

來源:[gen-client-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1)

### 變體 C:用戶端 BIN(發佈建議)

程式碼範本統一為 `cs-bin`,資料為精簡的二進位格式，可更節省 Unity 端載入時的記憶體與 IO。

```sh
dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate
```

來源:[luban.conf#L83-L87](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L83-L87)

## 常見錯誤

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 執行時出現 `dataTarget/codeTarget 不匹配` 錯誤 | 只修改了 `--dataTarget`,未修改 `--codeTarget` | 兩者必須成對使用(json↔cs-dotnet-json/cs-simple-json、bin↔cs-bin/cs-dotnet-bin/cs-dotnet-bin) |
| 無法直接開啟 BIN 檔案查看內容 | 選擇了 bin 卻期待能像 json 一樣瀏覽 | 應以對應的 `cs-bin` 範本載入，不應嘗試以文字方式解析 |
| 修改了 luban.conf 卻未生效 | 一直執行舊的腳本 | 直接執行 `gen-*-bin.*` 腳本，或將 `commands` 內目標指令的 `active` 改為 `true` |
| 用戶端發佈後啟動變慢 | 用戶端仍在使用 JSON | 切換至 `gen-client-bin.*`,並將 BIN 指令的 `active` 設為 `true` |
| 伺服器熱更新設定後的錯誤難以定位 | 伺服器使用 BIN 但未啟用驗證 | 在 BIN 指令中加入 `--validationFailAsError true` |

## 背景(選讀)

JSON 與 BIN 的差異，本質上是 **可讀性 / 大小 / 解析速度** 之間的取捨。由於 Luban 將資料序列化(`--dataTarget`)與程式碼生成範本(`--codeTarget`)分離，因此同一份資料可以以不同的執行時形式處理——開發期維持 JSON、正式期切換為 BIN,是 GameFrameX 建議的階段性做法。
