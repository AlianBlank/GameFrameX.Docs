# How to Fill In the Header and Field Types

The first 4 rows of every data table (located in `Excels/Tables/`) are a fixed "header", used to tell the tool which fields the table has and what type each field is. Below is a guide to what to fill in row by row, and which field types are available.

## Prerequisites

- A data table has already been created under `Excels/Tables/` (see "How to Name Your Tables" for naming rules).
- The `.xlsx` file is opened with Excel / WPS / Numbers.

## Steps

1. **Confirm the position of the first 4 rows**: Rows 1–4 of each table are the header; data is filled in starting from row 5.
2. **Fill in row 1 `##var`**: Starting from column 2, write one English **field name** per cell (e.g., `id`, `name`, `price`); these names become the property names in the generated code.
3. **Fill in row 2 `##type`**: Corresponding one-to-one with the field names, write the **type** of each field (see the table below for available types).
4. **Fill in row 3 `##group`**: Field grouping; it can usually be left empty.
5. **Fill in row 4 `##`**: Write a description in Chinese here; it is for humans only and does not affect the generated results.
6. **Fill in real data starting from row 5**: One value per cell, written according to the types in the `##type` row.

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L97-L131)

It looks like this when filled in (item table example):

| ##var   | id    | name     | price |
|---------|-------|----------|-------|
| ##type  | int   | text     | int   |
| ##group |       |          |       |
| ##      | Item ID | Item Name | Price |
| (Data)  | 10001 | diamond  | 10    |

> The first cell of these four rows (`##var`, `##type`, `##group`, `##`) are fixed markers and must be written exactly as shown — do not replace them with other words.

## Common Field Types

| Type        | Meaning                                              | Data Example             |
|-------------|------------------------------------------------------|--------------------------|
| `int`       | Integer                                              | `10001`                  |
| `long`      | Large integer                                        | `9999999999`             |
| `float`     | Decimal number                                       | `1.5`                    |
| `double`    | High-precision decimal                               | `3.14159`                |
| `bool`      | Yes/No                                               | `true` / `false`         |
| `string`    | Plain text (not translated)                          | `icon_diamond`           |
| `text`      | Localized text (fill in a key; the text is in `Local/`) | `diamond`             |
| `vec2`      | 2D coordinate, two floats separated by commas        | `1.0,2.0`                |
| `vec3`      | 3D coordinate, three floats separated by commas      | `1.0,2.0,3.0`            |
| `vec4`      | 4D coordinate, four floats separated by commas       | `1.0,2.0,3.0,4.0`        |
| Enum name   | A type defined in `__enums__.xlsx`                   | `ItemType`               |
| Bean name   | A struct defined in `__beans__.xlsx`                 | `Reward`                 |

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L212-L223), [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml#L2-L36)

> `vec2/vec3/vec4` are mapped to `UnityEngine.Vector2/3/4` on the client and `System.Numerics.Vector2/3/4` on the server, so both ends can use them directly.

## Common Variants

**1. Field names in Chinese? Not allowed**
Field names must be in English (the `##var` row); otherwise code generation fails with the error *"Chinese table names/field names are not supported"*.

**2. Want localized text**
Set `##type` to `text`, fill the data cell with a key (e.g., `diamond`), then write `diamond = 钻石/钻石/ダイヤ…` in the localization table under `Excels/Local/`. The difference between `text` and `string`: `text` gets translated, `string` does not.

**3. Want to use enums / structs**
First define the types in `Excels/__enums__.xlsx` or `__beans__.xlsx`, then write the defined names directly in the `##type` row (e.g., `ItemType`, `Reward`).

**4. Want a field to be client-only or server-only**
Add a group marker to the table file name (`c` = client, `s` = server); the fields themselves are unchanged, and the whole table is only exported to the corresponding side.

## Common Mistakes

| Symptom                                                   | Cause                                            | Fix                                                       |
|-----------------------------------------------------------|--------------------------------------------------|-----------------------------------------------------------|
| Code generation reports *"Chinese table names/field names are not supported"* | Field names in the `##var` row were written in Chinese | Change field names to English; put the Chinese descriptions in row 4 `##` |
| A `text` field shows the raw key in game (e.g., `diamond`) | Translations for the corresponding languages were not configured in `Excels/Local/` | Translate the key into each language in the localization table |
| Code generation reports an error for a `vec3` field       | Extra spaces or semicolons were filled in        | Strictly use English commas as separators: `1.0,2.0,3.0`  |
| `##var` / `##type` misspelled (e.g., `##vars`)            | Header markers must be written exactly as specified | Correct to `##var`, `##type`, `##group`, `##`             |
| Data is filled in starting from row 1                      | The header was overwritten by data               | Move the data down to start at row 5; the first 4 rows must be the header |## Background (Optional)

When reading `.xlsx` files, the tool only looks at the first 4 header rows to decide which fields to generate; `##var` determines the property names, `##type` determines the C# type and read/write behavior, and `##` serves only as a comment and is not involved in generation. The cross-platform mapping of built-in types such as `vec2/vec3/vec4` is controlled by [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml), so you only fill in simple numbers in Excel, and the server/client code gets real structs such as `Vector3`.
