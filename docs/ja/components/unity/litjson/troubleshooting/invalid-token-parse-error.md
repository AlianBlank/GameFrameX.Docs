# Invalid token 解析例外が発生した場合の対処方法

LitJSON が JSON 文字列を解析する際に認識できない字句要素(`ParserToken`)に遭遇すると、`"Invalid token '{0}' in input string"` というメッセージを持つ `JsonException` をスローします。このページでは、この例外の根本原因を迅速に特定し、修正する方法を説明します。

## クイック診断

| 症状(例外メッセージ) | 原因 | 修正 |
|----------------|------|------|
| `Invalid token 'X' in input string`(トークンが単一文字の場合) | JSON 内に予期しない文字が存在する(未エスケープの引用符、コメント、末尾のカンマなど) | 不正な文字を削除またはエスケープし、JSON 仕様に準拠させます |
| `Invalid token 'X' in input string`(トークンが数字の場合) | 数値リテラルの記述が誤っている(`1.`、`0x1A`、余計な記号など) | 数値形式を修正し、10 進数のみを使用します(オプションの小数点と指数を付けることが可能) |
| `Invalid token 'True' / 'False' / 'Null'` | ブール値または null が PascalCase(例:`True`)で記述されている | JSON が要求するすべて小文字の `true` / `false` / `null` に変更します |
| `Invalid token 'CharSeq'` | 文字列内に不正な文字が存在する(対になっていないエスケープ文字、制御文字など) | 文字列のエスケープを確認します。一般的な有効なエスケープは `\" \\ \/ \b \f \n \r \t \uXXXX` です |
| `Invalid token 'End'` または解析の途中終了 | JSON が途中で途切れている——括弧/引用符が閉じられていない | エディタで欠落した `{` `}` `[` `]` `"` を補完します |

例外メッセージのテンプレートは以下のように定義されており、中括弧の内容は Lexer 段階の `ParserToken` 列挙値です:

```csharp
// Runtime/JsonException.cs
internal JsonException(ParserToken token) :
    base(string.Format(
             "Invalid token '{0}' in input string", token))
{
}
```

ソース: [JsonException.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonException.cs#L51-L55)

## 修正手順

### 1. エラー発生箇所の文字位置を特定する

例外内のトークン(単一文字の場合)を元の JSON 文字列と照合することで、最初の不正な文字を特定できます。LitJSON の `JsonReader` は左から右へスキャンし、最初に認識できない文字に遭遇した時点で例外をスローします。

```csharp
// Runtime/JsonReader.cs
TableAddCol(parse_table, ParserToken.ArrayPrime, '[',
            (int)ParserToken.Value,
            (int)ParserToken.ValueRest,
            ']');
```

ソース: [JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs#L266-L274)

### 2. よくある不正な文字を修正する

以下の書き方は標準 JSON ではいずれも不正で、LitJSON は直接 `Invalid token` をスローします:

- シングルクォート文字列 `'foo'` —— ダブルクォート `"foo"` に変更する必要があります
- コメント `// xxx` または `/* xxx */` —— JSON はコメントをサポートしないため、削除する必要があります
- 末尾のカンマ `{ "a": 1, }` —— カンマの後には必ず要素が続く必要があります
- PascalCase のブール値/null 値 `True` / `False` / `Null` —— `true` / `false` / `null` である必要があります
- 未エスケープの制御文字や裸の改行 —— 文字列内部の改行は `\n` でエスケープする必要があります

### 3. よくある不正な数値を修正する

`ParserToken.Number` が引き起こす `Invalid token` は、通常、数値形式の問題です。有効な数値は 10 進数でなければならず、オプションの小数点と指数を付けることができます:

- 有効:`0`、`-1`、`3.14`、`-2.5e10`、`1.0E+3`
- 不正:`1.`(小数点の後に数字がない)、`01`(先頭のゼロ)、`0x1A`(16 進数)、`NaN`、`Infinity`、`+1`(余計な記号)、`1,000`(桁区切りのカンマ)

### 4. 最小再現ケースで検証する

修正後、最小限の実行可能なコード断片で JSON が正しく解析できることを確認します:

```csharp
using GameFrameX.LitJSON.Runtime;

string json = "{\"name\":\"litjson\",\"v\":1}";
JsonData data = JsonMapper.ToObject(json);
Debug.Log(data["name"]); // 出力: litjson
Debug.Log(data["v"]);    // 出力: 1
```

それでも `Invalid token` が発生する場合は、例外メッセージ内のトークン値と、元の文字列の断片(エラー発生位置の前後数文字を含む)を上流のデータ提供元にフィードバックしてください。

## 検証

1. Unity Editor の Console で修正後の JSON 解析コードを実行し、`JsonException` がスローされなくなったことを確認します。
2. オンライン JSON 検証ツール(例:jsonlint.com)で入力文字列を検証し、"Valid JSON" の結果を得ます。
3. JSON がネットワークや外部ファイルから取得される場合は、try/catch を追加して `e.Message` を出力すると、具体的なエラー発生位置の特定に役立ちます:

```csharp
try
{
    var data = JsonMapper.ToObject(rawJson);
}
catch (JsonException e)
{
    Debug.LogError($"解析に失敗しました:{e.Message}");
}
```
