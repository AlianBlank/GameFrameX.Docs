# HMAC-SHA256/HMAC-SHA512 사용 방법

`HmacSha256Helper` 또는 `HmacSha512Helper`의 정적 메서드를 호출하면 몇 줄의 코드로 키가 포함된 메시지 인증 코드(Base64 문자열)를 얻을 수 있으며, `Verify` 시리즈 메서드를 사용하여 고정 시간 비교 방식으로 안전하게 서명을 검증할 수 있습니다. 두 도우미는 문자열, 바이트 배열 및 스트림(동기/비동기) 세 가지 오버로드를 제공합니다.

## 사전 조건

- 프로젝트 대상 프레임워크가 `System.Security.Cryptography`의 `HMACSHA256` / `HMACSHA512`를 지원해야 합니다(.NET 6+에서는 `HMACSHA256.HashData` 권장).
- 네임스페이스 `GameFrameX.Foundation.Hash`를 포함합니다.
- UTF-8로 인코딩된 키 문자열을 준비합니다(SHA-256 블록 크기에 맞추려면 길이 ≥ 32바이트 권장).

## 작업 단계

### 1. 문자열에 대한 HMAC-SHA256 계산

```csharp
using GameFrameX.Foundation.Hash;

string message = "hello world";
string key = "my-secret-key";
string signature = HmacSha256Helper.Hash(message, key);
// signature은 Base64 문자열이며, 길이는 44자로 고정됩니다(32바이트)
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L60-L66)

### 2. 바이트 배열에 대한 HMAC-SHA512 계산

```csharp
using System.Text;
using GameFrameX.Foundation.Hash;

byte[] message = Encoding.UTF8.GetBytes("payload");
byte[] key = Encoding.UTF8.GetBytes("another-secret-key");
string signature = HmacSha512Helper.Hash(message, key);
// signature은 Base64 문자열이며, 길이는 88자로 고정됩니다(64바이트)
```

Source: [HmacSha512Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha512Helper.cs#L24-L29)

### 3. 스트림에 대한 비동기 HMAC-SHA256

```csharp
using GameFrameX.Foundation.Hash;

using FileStream fs = File.OpenRead("data.bin");
byte[] key = Encoding.UTF8.GetBytes("my-secret-key");
string signature = await HmacSha256Helper.HashAsync(fs, key, cancellationToken);
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L94-L103)

### 4. 고정 시간 비교로 서명 검증

타이밍 공격을 방지하려면 검증 시 반드시 `Verify`를 사용해야 하며, `==`로 직접 문자열을 비교해서는 안 됩니다.

```csharp
using GameFrameX.Foundation.Hash;

bool ok = HmacSha256Helper.Verify("hello world", "my-secret-key", signature);
```

## 일반적인 변형

| 시나리오 | 권장 메서드 |
|------|---------|
| 짧은 메시지(JSON, URL 매개변수) | `Hash(string, string)` |
| 알려진 바이트 버퍼(예: 프로토콜 패킷) | `Hash(byte[], byte[])` |
| 대용량 파일 또는 네트워크 스트림 | 동기: `Hash(Stream, byte[])`; 비동기 컨텍스트: `HashAsync` |
| 인터페이스 서명 검증 | 해당 `Verify(...)` 시리즈를 사용하여 타이밍 공격 방지 |
| 더 높은 보안이 필요한 경우 | `HmacSha512Helper`를 선택하여 64바이트 출력 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `ArgumentNullException: message` | `null` 문자열을 전달함 | 사전에 null 검사를 수행하거나 빈 문자열을 자리 표시자로 사용 |
| 클라이언트와 서버의 서명이 일치하지 않음 | 인코딩이 일치하지 않음(한쪽에서 GBK/ASCII 사용) | 전체链路에서 UTF-8을 일관되게 사용 |
| `Verify`가 항상 `false`를 반환함 | `==`로 직접 Base64 문자열 비교를 시도하여 길이가 다른 경우 | `Verify(...)`를 사용하여 고정 시간 비교 수행 |
| 성능 병목 | 대용량 파일에 대해 `HMACSHA256`을 반복적으로 인스턴스화 | 키를 재사용하고 인스턴스는 한 번만 생성 |

## 배경 지식 (선택 사항)

- 출력은 항상 Base64이므로 HTTP Header, URL 또는 JSON에서 전송하기 편리합니다. 16진수가 필요한 경우 직접 `Convert.FromBase64String` 후 `BitConverter`를 사용할 수 있습니다.
- `Verify`는 내부적으로 `HashHelper.FixedTimeEqualsBase64`을 사용하며, 직접 문자열 동등성 비교와 다르기 때문에 부채널 공격 위험을 줄일 수 있습니다.
- `HashData`는 .NET 6+의 단회 호출 정적 API입니다. 스트림 버전은 여전히 `HMACSHA256/512` 인스턴스를 사용하여 `ComputeHash(Stream)` 및 `ComputeHashAsync`를 지원합니다.
