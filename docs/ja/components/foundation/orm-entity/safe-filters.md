# ソフト削除/有効化フィルターインターフェースの使用方法

エンティティで `ISafeDeletedFilter` と `ISafeEnabledFilter` を有効にすると、フレームワークは基底エンティティ `EntityBase` 内で自動的にソフト削除フィールド(`IsDeleted`、`DeleteTime`、`DeleteId`)と有効化/無効化フィールド(`IsEnabled`)を提供し、「論理削除」と「有効化状態」の統一管理を実現します。

## 前提条件

- 名前空間 `GameFrameX.Foundation.Orm.Entity` を参照する(`EntityBase`、`EntityBase<TKey>` を提供)。
- 名前空間 `GameFrameX.Foundation.Orm.Entity.Filter` を参照する(フィルターインターフェースを提供)。
- エンティティクラスは `EntityBase` または `EntityBase<TKey>` を継承する。フレームワーク基底クラスはすでにデフォルトで `ISafeDeletedFilter` と `ISafeEnabledFilter` を実装しているため、手動での実装追加は不要です。

## 操作手順

1. 業務エンティティに `EntityBase` を継承させると、ソフト削除と有効化フィルターのフィールドを同時に取得できます。

```csharp
using GameFrameX.Foundation.Orm.Entity;
using GameFrameX.Foundation.Orm.Entity.Filter;

public class SysUser : EntityBase
{
    public string UserName { get; set; } = string.Empty;
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L46)

2. エンティティクラスには以下のソフト削除フィールドが自動的に含まれており、直接使用できます:

| フィールド | 型 | デフォルト値 | 意味 |
|------|------|--------|------|
| `IsDeleted` | `bool?` | `false` | ソフト削除フラグ:`true` 削除済み、`false` 未削除、`null` 未設定(未削除として処理) |
| `DeleteTime` | `long?` | `null` | 削除時間(タイムスタンプ) |
| `DeleteId` | `long?` | `null` | 削除者 Id |

```csharp
// ユーザーを削除としてマーク
sysUser.IsDeleted = true;
sysUser.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
sysUser.DeleteId = currentUserId;
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L120-L138)

3. 有効化フィルター(`ISafeEnabledFilter`)も基底クラス `EntityBase` で同時に実装されており、エンティティの有効化状態を記録するために使用されます。

4. リポジトリ層でクエリを実行する際、フィルタリングフィールド `IsDeleted = false` によって削除済みデータを除外し、ソフト削除クエリを実現します:

```csharp
// 例:未削除のユーザーリストをクエリ
var users = await dbContext.Set<SysUser>()
    .Where(u => u.IsDeleted == false || u.IsDeleted == null)
    .ToListAsync();
```

5. 削除操作は物理削除を行わず、`IsDeleted` の変更に変更してください:

```csharp
public void SoftDelete(SysUser user, long operatorId)
{
    user.IsDeleted = true;
    user.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
    user.DeleteId = operatorId;
}
```

## よくあるバリエーション

- ジェネリック主キー基底クラス `EntityBase<TKey>` を使用する場合(例: `EntityBase<long>`)、ソフト削除と有効化フィールドは引き続き自動的に含まれます。
- 主キー型をカスタマイズしたい場合は、`EntityBase<TKey>` を継承してジェネリックパラメータを指定してください:

```csharp
public class SysRole : EntityBase<long>
{
    public string RoleName { get; set; } = string.Empty;
}
```

- 監査フィールドなしで選択フィルターのみを使用したい場合は、`EntitySelectBase` を継承できます(`EntityBase` を基盤に `ISelectFilter` を追加実装していますが、`IsDeleted` などのソフト削除フィールドも引き続き含まれます)。

Source: [EntitySelectBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntitySelectBase.cs#L45-L45)

## よくあるエラー

- 物理削除の誤用:`EntityBase` を継承したエンティティに対して ORM の `Remove`/`Delete` を呼び出すと、ソフト削除フラグをバイパスしてデータが実際に消えてしまいます。`IsDeleted = true` の書き換えに統一してください。
- クエリで `IsDeleted` フィルターの漏れ:`Where(u => u.IsDeleted == false)` を付けないと、削除済みレコードも同時に取得されます。リポジトリ層でフィルター条件を強制的に追加してください。
- `IsDeleted` が `bool` ではなく `bool?` だと誤解する:フレームワークは nullable ブールを使用し、デフォルトは `false` です。新規エンティティで明示的に代入しない場合は「未削除」として処理されます。手動で `null` を設定した場合も同様に未削除と見なされます。
