# イベントの購読と配信

イベントプール `EventPool<T>` を使用すると、任意のモジュールが「文字列 ID + イベント引数」の形式でイベントを購読・配信できます。メインスレッドでのキュー実行による配信(`Fire`)と、即時同期配信(`FireNow`)の両方がサポートされています。

## 前提条件

- カスタムイベント引数は `BaseEventArgs` を継承し、一意な文字列 `Id`(イベント種別を識別するため)を実装する必要があります。
- `EventPool` モジュールから `EventPool<T>` インスタンスを取得または作成します。本チュートリアルでは `EventPool<MyEventArgs>` を取得済みである前提です。
- 呼び出し側はゲームループ内で `EventPool<T>.Update(elapseSeconds, realElapseSeconds)` を呼び出す必要があります。さもないと `Fire` キュー内のイベントは配信されません。

## 手順

1. イベント引数クラスを定義し、`BaseEventArgs` を継承して一意な `Id` を実装します。

   ```csharp
   public class PlayerHpChangedEventArgs : BaseEventArgs
   {
       public string PlayerId { get; set; }
       public int NewHp { get; set; }

       public override string Id => "PlayerHpChanged";
   }
   ```

   Source: [BaseEventArgs.cs](/Runtime/Base/EventPool/BaseEventArgs.cs#L43-L54)

2. イベントを購読します。モジュール初期化時に `Subscribe` を呼び出し、文字列のイベント ID と `EventHandler<T>` コールバックをイベントプールに登録します。

   ```csharp
   eventPool.Subscribe("PlayerHpChanged", OnPlayerHpChanged);

   void OnPlayerHpChanged(object sender, PlayerHpChangedEventArgs e)
   {
       Debug.Log($"{e.PlayerId} HP -> {e.NewHp}");
   }
   ```

   `EventHandler<T>` のシグネチャは `EventPool<T>` の型パラメータから決まります。

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

3. イベントを配信します。メインスレッドで `Fire` を呼び出すとイベントがキューに追加され、次回 `Update` 時にすべての購読者へコールバックされます。別スレッドからの `Fire` も安全です。

   ```csharp
   var args = ReferencePool.Acquire<PlayerHpChangedEventArgs>();
   args.PlayerId = "p_001";
   args.NewHp = 80;
   eventPool.Fire(this, args);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L304-L314)

4. イベントプールを駆動します。毎フレーム `Update` を駆動することで `Fire` されたノードが消費されます。ノード処理後は `ReferencePool.Release` で返却されます。

   ```csharp
   void Update()
   {
       eventPool.Update(0f, Time.deltaTime);
   }
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L113-L121)

5. 適切なタイミングで購読を解除し、オブジェクトが破棄された後もイベントプールにコールバックが保持されることを防ぎます。

   ```csharp
   eventPool.Unsubscribe("PlayerHpChanged", OnPlayerHpChanged);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L245-L281)

## よくあるバリエーション

- **即時同期配信**:メインスレッドでキューイングが不要な場合は `FireNow` を呼び出します。イベントは現在の呼び出しスタックですべての購読者に即時配信されますが、スレッドセーフではありません。

  ```csharp
  eventPool.FireNow(this, args);
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L325-L336)

- **デフォルトハンドラの設定**:`SetDefaultHandler` でフォールバックコールバックを登録できます。特定のイベント ID に購読者がいない場合に呼び出されます。

  ```csharp
  eventPool.SetDefaultHandler((sender, e) => Debug.Log($"未処理イベント:{e.Id}"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L290-L293)

- **イベントプールモードによる購読ルールの制御**:`EventPool<T>` のコンストラクタに `EventPoolMode` を渡すことで、複数の購読者や重複する購読者を許可するかを設定できます。

  | モード | 動作 |
  |------|------|
  | `EventPoolMode.Default` (0) | 購読者が必ず存在し、かつ1つだけである必要がある |
  | `EventPoolMode.AllowNoHandler` (1) | 購読者がいないイベントを許可する |
  | `EventPoolMode.AllowMultiHandler` (2) | 同一イベント ID に複数の購読者の登録を許可する |
  | `EventPoolMode.AllowDuplicateHandler` (4) | 同じコールバックの重複登録を許可する(`AllowMultiHandler` と併用が必要) |

  複数のフラグはビット単位で組み合わせることができます。例: `EventPoolMode.AllowMultiHandler | EventPoolMode.AllowDuplicateHandler`

  Source: [EventPoolMode.cs](/Runtime/Base/EventPool/EventPoolMode.cs#L43-L77), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

- **購読数のクエリ**:`EventHandlerCount` または `Count(id)` で購読者数を取得できます。デバッグや UI 表示に利用できます。

  ```csharp
  Debug.Log(eventPool.EventHandlerCount);
  Debug.Log(eventPool.Count("PlayerHpChanged"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L82-L91), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L164-L175)

## よくあるエラー

| エラー | 現象 | 対処 |
|------|------|------|
| `handler` が `null` で `Subscribe`/`Unsubscribe`/`Check` を呼び出した | `GameFrameworkException("Event handler is invalid.")` がスローされる | 登録前にコールバックがインスタンスメソッドまたは静的デリゲートであることを確認し、`null` を渡さない |
| `Fire` したイベントに購読者がおらず、かつモードで `AllowNoHandler` が有効になっていない | "not allow multi handler." がスローされる、またはデフォルトハンドラでフォールバックされる | コンストラクタで必要に応じて `EventPoolMode.AllowNoHandler` を追加する |
| `Update` を呼び出してキューを消費していない | イベントが「消失」したように見える | ゲームループで毎フレーム `eventPool.Update(...)` が駆動されるようにする |
| オブジェクト破棄後に `Unsubscribe` していない | イベント発火時に破棄済みオブジェクトへコールバックされ、NullReferenceException が発生する | `OnDestroy`/`OnDisable` で `Unsubscribe` を呼び出す |

## 背景(オプション)

`EventPool<T>` は内部で `ConcurrentQueue<EventNode>` を用いて `Fire` されたイベントを一時保存し、`Update` 内で取り出して `GameFrameworkMultiDictionary<string, EventHandler<T>>` を通じて配信します。`_cachedNodes` は「イベント処理中に安全に購読解除を行う」ために使用されます。`Fire` はスレッドセーフで(次のフレームのメインスレッドで配信される)、`FireNow` は即時同期配信で、遅延に敏感だが呼び出しスレッドの安全性を保証できるシナリオに適しています。
