# 画像読み込みが null を返す場合の対処法

`LoadImageAsync` を呼び出して `null` が返ってきた場合、画像の読み込みに失敗したことを意味します。以下に現象ごとによくある原因、切り分け方法、修正手順を記載します。

## クイック診断

| 症状（ログ原文） | 原因 | 修正方法 |
|------------------|------|----------|
| `ImageCache: url is null or empty.` | 渡された URL が空文字列または `null` | 呼び出し前に URL をチェックし、有効なアドレスを渡す |
| `ImageCache: url must start with http:// or https://. url: {0}` | URL が `http://` または `https://` で始まっていない | URL のプロトコルヘッダを修正する |
| `ImageCache: download failed. url: {0}` | リモートサーバーに到達できない、404、またはネットワーク制限 | ネットワークとアドレスを確認する。詳細は後述「ダウンロード失敗」を参照 |
| `Download manager is invalid.`（起動時の致命ログ） | `IDownloadManager` モジュールがインストールされていない | `Download` コンポーネントを登録する |
| `ImageCache manager is invalid.`（起動時の致命ログ） | コンポーネントが `GameFrameworkEntry` に登録されていない | フレームワークの手順に従ってコンポーネントを追加する |
| ログが何も出力されず `null` が返る | キャッシュファイルが破損している / `Texture2D.LoadImage` が失敗 | キャッシュをクリアして再試行。詳細は後述を参照 |

## 修正手順

### URL が無効

`LoadImageAsync` は、URL が空であるか `http(s)://` で始まらない場合、直接 `null` を返し、対応する警告ログを出力します。

```csharp
// 間違った書き方
await component.LoadImageAsync(null);                 // 空
await component.LoadImageAsync("ftp://example.com/a.png"); // プロトコル誤り
await component.LoadImageAsync("/local/path/a.png");   // ローカルパスは無効

// 正しい書き方
await component.LoadImageAsync("https://example.com/a.png");
```

出典: [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

### 起動時にモジュールが不足

`ImageCacheComponent.Awake` は `IImageCacheManager` と `IDownloadManager` を取得します。どちらかが欠けていると `Fatal` ログを出力して早期に return し、その後のすべての読み込みが `null` を返します。

```csharp
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
// ...
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
```

修正方法：

1. シーンの `GameFramework` ノードの下に `ImageCache` コンポーネントを追加する（メニュー `GameFrameX/Image Cache`）。
2. 同時に `Download` コンポーネントを追加し、`Download Component` フィールドが `IDownloadManager` を実装した具象クラスを指していることを確認する。
3. シーンを再起動し、コンソールに上記の `Fatal` ログが表示されないことを確認する。

出典: [ImageCacheComponent.cs#L37-L65](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L37-L65)

### ダウンロード失敗

WebGL 以外のプラットフォームでは、ディスクキャッシュにヒットしない場合 `IDownloadManager.AddDownload` を呼び出します。ダウンロードが失敗すると `DownloadFailure` イベントが発生し、メソッドは `ImageCache: download failed. url: {0}` を書き出して `null` を返します。

```csharp
private async Task<Texture2D> LoadImageDiskCacheAsync(string url, CancellationToken cancellationToken)
{
    // ...
    var downloadSuccess = await tcs.Task;
    if (!downloadSuccess)
    {
        Log.Warning("ImageCache: download failed. url: {0}", url);
        return null;
    }
    // ...
}
```

切り分け順序：

1. ブラウザまたは `curl` で直接その URL にアクセスし、200 が返り画像バイトストリームが返ってくることを確認する。
2. ランタイムのサンドボックスの権限を確認する（iOS ATS、Android ネットワーク権限、WebGL CORS）。
3. WebGL プラットフォームにはディスクキャッシュがないため、ブラウザは直接 `UnityWebRequestTexture.GetTexture` で取得します。失敗時のログは `ImageCache: download failed. url: {0}, error: {1}` です。クロスドメインと HTTPS の設定を優先的に確認してください。
4. すでにダウンロード済みであるにもかかわらず再度失敗する場合は、`RemoveCache(url)` を呼び出してから再試行する。

出典: [ImageCacheManager.cs#L97-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L97-L171)

### キャッシュファイルの破損 / デコード失敗

ダウンロードは成功したが、その後の読み込みやデコードが失敗した場合、メソッドは静かに `null` を返し、専用の警告ログは出力されません。

```csharp
var buffer = FileHelper.ReadAllBytes(cachePath);
if (buffer == null || buffer.Length == 0)
{
    return null;
}

var texture = new Texture2D(1, 1, TextureFormat.RGBA32, false, false);
if (!texture.LoadImage(buffer))
{
    Object.Destroy(texture);
    return null;
}
```

修正方法：

1. `RemoveCache(url)` または `ClearCache()` を呼び出してローカルキャッシュをクリアし、再読み込みする。
2. Inspector で `CachePath` が書き込み可能であり、ディスクに空きがあることを確認する（`MaxDiskSize` で回収がトリガーされた場合、古いファイルが削除される可能性がある）。
3. リモートから返されているのが本当に PNG / JPG のバイトストリームであり、HTML エラーページではないことを確認する。

出典: [ImageCacheManager.cs#L152-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L152-L171)

### キャンセルトークンによるトリガー

呼び出し元から渡された `CancellationToken` によってキャンセルがトリガーされた場合、メソッドは `null` を返し、失敗ログは書き出しません。

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return null;
}
```

`await` の後にも必ず `cancellationToken.IsCancellationRequested` を再チェックし、「キャンセルされた」を「読み込み失敗」として扱わないようにしてください。

出典: [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149)

## 検証

1. コンソールに `ImageCache: ...` 警告や `Fatal` ログが表示されない。
2. `LoadImageAsync` が空でない `Texture2D` を返し、UI / `Sprite` にバインドして正常に表示できる。
3. 2 回目の読み込みではコンソールでネットワークリクエストがトリガーされず、`Config.CachePath` の下に URL の MD5 で名前付けされたキャッシュファイルが存在する。
