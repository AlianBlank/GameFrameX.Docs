# 監視メトリクスとヘルスチェックを有効化する方法

このページの設定を完了すると、サービスは自動的に `/health`(完全なヘルスステータス)と `/alive`(プロセスの生存性)の 2 つの HTTP エンドポイントを公開し、組み込みの MongoDB ヘルスチェックと ASP.NET Core のデフォルトヘルスチェックが有効になります。`AddServiceDefaults` を通じてサービス全体にワンタッチで組み込まれます。

## 前提条件

- .NET 8+ ASP.NET Core プロジェクト(本フレームワークはデフォルトで .NET 9 を使用)
- `Program.cs` で `WebApplication.CreateBuilder()` と `builder.Build()` を呼び出していること
- サービス内で `GameFrameX.AppHost.ServiceDefaults` パッケージを参照していること(フレームワークのデフォルト参照)

## 操作手順

### 1. Program.cs でサービスのデフォルト値を登録する

`AddServiceDefaults` は OpenTelemetry、ログ、メトリクス、HTTP 復元性などのインフラを同時に設定し、ヘルスチェックもこのステップで一括で有効化されます。

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.AddServiceDefaults();
```

Source: [GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346)

### 2. ヘルスチェックエンドポイントを公開する

`MapDefaultEndpoints` は `/health` と `/alive` の 2 つのエンドポイントを登録します。`/health` はすべてのチェックが成功することを要求し、`/alive` は `live` タグが付いたチェックのみが成功することを要求します。

```csharp
var app = builder.Build();
app.MapDefaultEndpoints();
app.Run();
```

Source: [GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435)

### 3. デフォルトエンドポイントを検証する

サービス起動後にアクセス:

| エンドポイント | 用途 | 成功時のレスポンス |
|------|------|---------|
| `/health` | 完全なヘルスチェック(依存関係を含む) | `Healthy` |
| `/alive` | プロセスの生存性 | `Healthy` |

プロセスの生存性プローブのみが必要な場合は、`/alive` を使用できます。これは MongoDB などのダウンストリームコンポーネントに依存しません。

## MongoDB ヘルスチェックを有効化する

フレームワークには `MongoDbHealthCheck` が組み込まれており、DI コンテナに `IMongoClient` を登録し、`AddMongoDbHealthCheck` を呼び出すだけで `/health` エンドポイントに自動的に組み込まれます。

### 1. MongoDB クライアントを登録する

```csharp
builder.Services.AddSingleton<IMongoClient>(sp =>
    new MongoClient(builder.Configuration.GetConnectionString("MongoDb")));
```

### 2. ヘルスチェックを登録する

```csharp
builder.Services.AddHealthChecks()
    .AddMongoDbHealthCheck();
```

Source: [GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99)

### 3. チェック動作の説明

`MongoDbHealthCheck` は内部的に `ListDatabaseNamesAsync` 経由で接続をプローブし、連続失敗カウンターを使用してフラッピングを回避します:

| 連続失敗回数 | 返却ステータス | 意味 |
|--------------|---------|------|
| 0(データベースリストあり) | `Healthy` | 接続は正常、失敗カウンターはゼロにリセット |
| 1 ~ 4 | `Degraded` | 一時的に利用不可、リトライ可能 |
| ≥ 5 | `Unhealthy` | 連続失敗がしきい値を超過、不健康とマーク |

## よくあるバリエーション

- **生存プローブのみを公開する**:一部の Kubernetes デプロイでは `/alive` のみが必要です。MongoDB などのダウンストリームチェックの登録を省略し、`AddServiceDefaults` のデフォルトの生存チェックを直接使用できます。
- **カスタムチェックを追加する**:`IHealthCheck` を実装し、`.AddCheck("my-check", new MyHealthCheck())` を呼び出して既存の `IHealthChecksBuilder` にマウントします。
- **外部ヘルスプローブ**:`/health` をロードバランサーや APM のプローブ URL として使用します。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `/health` にアクセスすると 404 が返される | `app.MapDefaultEndpoints()` が呼び出されていない | `app.Run()` の前に `app.MapDefaultEndpoints();` を追加する |
| `/health` が常に `Unhealthy` を返す | MongoDB 接続文字列のエラー、またはサービスが起動していない | `ConnectionStrings:MongoDb` の設定を確認し、MongoDB に到達可能であることを確認する |
| MongoDB の偶発的なフラッピングによりステータスが頻繁に切り替わる | デフォルトのしきい値(連続 5 回失敗)が厳しすぎる | `appsettings.json` で `MongoDbHealthCheckOptions` を調整するか、`Degraded` を許容するように変更する |
| 生存性のみを確認し依存関係を確認したくない | `/alive` と `/health` が区別されていない | `/alive` エンドポイントを使用するか、カスタムチェックに `tags: new[] { "live" }` を追加する |

## 背景

ヘルスチェックは `Microsoft.Extensions.Diagnostics.HealthChecks` に基づいており、フレームワークは `AddServiceDefaults` を通じて `self` チェック(タグは `live`)をデフォルトで登録し、コンテナオーケストレーションシステムで「プロセスがまだ生きているか」と「トラフィックを受け入れられるか」を区別するために 2 つのエンドポイントパスを公開します。

テレメトリと OpenTelemetry の全体的な統合については、『サービスのデフォルト値とテレメトリ』を参照してください。
