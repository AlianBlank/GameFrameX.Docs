# 实现玩家奖励(Reward)模块

本页面说明如何在玩家 Actor 上使用 `RewardGrantComponentAgent.GrantAsync` 统一发放奖励,涵盖调用前置条件、请求/结果结构、路由规则与幂等账本行为。

## 前置条件

- 目标玩家 Actor 已上线,`RewardGrantComponent` 由框架按 `[ComponentType(GlobalConst.ActorTypePlayer)]` 自动挂载,无需手动注册。
- 已存在 `TbItemConfig` 道具表配置(`GameFrameX.Config.Tables`),普通道具路由会用 `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)` 校验 `ItemId` 是否存在。
- 调用方位于能解析玩家 Actor 的服务端上下文(例如热更新层 `GameFrameX.Hotfix.Logic.Player.Reward` 命名空间下的代码)。
- `BagComponentAgent` 已就绪,普通道具发放最终会调用 `BagComponentAgent.UpdateChanged(...)` 写背包(在线 push notify,离线只持久化)。

## 操作步骤

1. **构造 `RewardGrantRequest`。** `RoleId` 必须是目标玩家的 `ActorId`,`SourceType` / `SourceId` / `TraceId` 三者共同唯一,共同组成幂等键 `RoleId:SourceType:SourceId:TraceId`。`Rewards` 是要下发的条目列表。

   ```csharp
   using GameFrameX.Apps.Player.Reward.Entity;

   var request = new RewardGrantRequest
   {
       RoleId    = playerActorId,
       SourceType = RewardSourceType.Mail,            // 业务来源,禁止 None
       SourceId  = $"mail:{mailId}:attachment:{attachmentId}",
       TraceId   = Guid.NewGuid().ToString("N"),      // 唯一追踪号
       Rewards   = new List<RewardItem>
       {
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1001, Count = 5 },
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1002, Count = 1 },
       },
   };
   ```
   Source: [RewardGrantRequest.cs#L41-L67](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L41-L67)

2. **通过组件代理调用 `GrantAsync`。** 入口为 `RewardGrantComponentAgent.GrantAsync`,标注了 `[Service]`,可被同 Actor 内其他代理组件或上层业务直接 await。

   ```csharp
   using GameFrameX.Hotfix.Logic.Player.Reward;

   var agent = await ActorManager.GetComponentAgent<RewardGrantComponentAgent>(playerActorId);
   var result = await agent.GrantAsync(request);
   ```
   Source: [RewardGrantComponentAgent.cs#L51-L91](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L51-L91)

3. **读取 `RewardGrantResult`。** `Items` 给出逐项成功/失败与错误码;`AllSuccess` 表示是否全部成功;`ErrorCode` 是整体聚合码(`Ok` / `PartialSuccess` / 首个失败项错误码)。

   ```csharp
   if (result.AllSuccess)
   {
       // 全部奖励已写入背包或幂等命中
   }
   else
   {
       foreach (var item in result.Items)
       {
           if (!item.Success)
           {
               // item.ErrorCode 取值见 OperationStatusCode
           }
       }
   }
   ```
   Source: [RewardGrantRequest.cs#L72-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L72-L89)

4. **按需扩展路由。** 一期仅 `RewardType.NormalItem` 真正落地(写 `BagState`),其他类型(HiddenItem / MonthCard / LifetimeCard / VipPoint / Equity 等)在 `DispatchAsync` 中返回 `OperationStatusCode.Unsupported`,不会污染普通背包。新增类型时,在 `DispatchAsync` 的 `switch` 分支中加入对应的子路由实现即可。
   Source: [RewardGrantComponentAgent.cs#L96-L172](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L96-L172)

## 常见变体

- **运营补偿 / 兑换码 / 活动奖励:** 业务来源不同时,只需要换 `SourceType` 与 `SourceId` 的拼接方式,`GrantAsync` 是唯一的资产发放入口,不要直接绕过它写背包。
- **离线玩家发奖:** `BagComponentAgent.UpdateChanged(channel, ...)` 在 `channel` 为空时只持久化、不推送 notify,业务侧无需额外分支。
- **请求携带扩展字段:** `RewardItem.ExtraData` 是预留字段,当前发放流程不解析,但会随幂等账本原样持久化,后续路由可读取。

## 常见错误

| 症状 | 原因 | 规避 |
|------|------|------|
| 整笔请求 `ErrorCode = Unsupported` | `RewardType` 不在已实现路由(除 `NormalItem` 外均不支持) | 一期只发普通道具;扩展前先在 `DispatchAsync` 补路由 |
| 单项 `ErrorCode = InvalidReward` | `RewardItem.Count <= 0` | 调用前校验 `Count > 0` |
| 单项 `ErrorCode = NotFound` | `ItemId` 在 `TbItemConfig` 不存在 | 配置表先建表,再在策划填表 |
| 整笔 `ErrorCode = Unprocessable` | 背包组件更新失败(`bagState.IsNull()`) | 检查 `BagComponentAgent` 与玩家 Actor 状态 |
| 重复发奖 | 幂等键 `RoleId:SourceType:SourceId:TraceId` 不唯一 | 同一笔业务保持三字段稳定,需要重试时直接复用 `TraceId` |
