# How to Listen for Application Pause and Focus Changes

With this package, you can listen for Unity's `OnApplicationPause` and `OnApplicationFocus` callbacks in non-MonoBehaviour systems, so you can perform operations such as pausing music, saving progress, and refreshing focus UI when the application enters the background or returns to the foreground.

## Prerequisites

- The `com.gameframex.unity.mono` package is installed, version ≥ 1.1.4.
- The project has the `GameFrameX.Event.Runtime` event system introduced (this package depends on it).

## Steps

### 1. Subscribe via the Event System (Recommended)

The event system approach offers the strongest decoupling, suitable for scenarios where business logic is distributed across multiple managers.

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Mono.Runtime;

private void OnFocusChanged(object sender, GameEventArgs e)
{
    var args = (OnApplicationFocusChangedEventArgs)e;
    if (args.IsFocus)
    {
        // Application returned to the foreground
    }
    else
    {
        // Application entered the background
    }
}

private void OnPauseChanged(object sender, GameEventArgs e)
{
    var args = (OnApplicationPauseChangedEventArgs)e;
    if (args.IsPause)
    {
        // Application was paused by the system
    }
    else
    {
        // Application resumed from pause
    }
}

// Subscribe
GameFrameXEntry.GetModule<EventComponent>().Subscribe(OnApplicationFocusChangedEventArgs.EventId, OnFocusChanged);
GameFrameXEntry.GetModule<EventComponent>().Subscribe(OnApplicationPauseChangedEventArgs.EventId, OnPauseChanged);
```

Event Ids are identified through `OnApplicationFocusChangedEventArgs.EventId` / `OnApplicationPauseChangedEventArgs.EventId`.

### 2. Listen Directly via the Mono Component

If your logic is written in a MonoBehaviour-derived class, or if you want to receive the original Unity callbacks, you can attach this package's Mono bridge component and add listener methods.

```csharp
private void OnApplicationFocus(bool isFocus)
{
    // isFocus: true means entering the foreground, false means entering the background
}

private void OnApplicationPause(bool isPause)
{
    // isPause: true means paused by the system, false means resumed from pause
}

// Register
monoComponent.AddOnApplicationFocusListener(OnApplicationFocus);
monoComponent.AddOnApplicationPauseListener(OnApplicationPause);

// Remove when no longer needed
monoComponent.RemoveOnApplicationFocusListener(OnApplicationFocus);
monoComponent.RemoveOnApplicationPauseListener(OnApplicationPause);
```

## Event Parameter Reference

| Event Class | Field | Meaning |
|--------|------|------|
| [OnApplicationFocusChangedEventArgs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationFocusChangedEventArgs.cs#L40-L87) | `bool IsFocus` | true means the application gained focus (returned to the foreground), false means it lost focus (entered the background) |
| [OnApplicationPauseChangedEventArgs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationPauseChangedEventArgs.cs#L40-L88) | `bool IsPause` | true means paused by the system, false means resumed |

Both event classes inherit from `GameEventArgs` and are acquired from the reference pool through `ReferencePool.Acquire<T>()`. After use, they are reclaimed uniformly by the framework.

## Common Variants

- **Only care about background/foreground switching**: Only subscribe to `OnApplicationFocusChangedEventArgs`. `IsFocus=false` is equivalent to switching to the background.
- **Distinguishing between pause and loss of focus**: On mobile, locking the screen typically triggers `OnApplicationPause=true`; popping up a system-level dialog typically only triggers `OnApplicationFocus=false`. Subscribe to both events when you need to handle them separately.
- **Constructing event objects**: The framework internally uses `OnApplicationPauseChangedEventArgs.Create(bool)` / `OnApplicationFocusChangedEventArgs.Create(bool)`. The business side generally does not need to construct them manually.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Listener method is never called | `Subscribe` / `AddOnApplicationFocusListener` was not called | Explicitly register once during module initialization |
| Event is received but `IsFocus` is always `false` | The `EventId` of the two events were swapped when subscribing | Note that the `Focus` event returns `IsFocus`, and the `Pause` event returns `IsPause` |
| Triggered multiple times | Both the Mono component listener and the event system subscription are attached, so the same signal goes through two paths | Choose one, or add business-level deduplication at the dispatch point |
| Removing the listener is invalid | A different method reference was passed when removing | `Add` / `Remove` must pass in the same `Action` / method reference |

## Background (Optional)

`OnApplicationPause` and `OnApplicationFocus` are callbacks provided by the Unity engine on MonoBehaviour. This package forwards them as GameFrameX event bus messages, enabling pure C# systems (without `MonoBehaviour` derivation) to respond to application lifecycle changes. Event instances are reused through the reference pool to reduce GC.
