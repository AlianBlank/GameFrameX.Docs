# 心跳丢失告警怎么办

当 `NetworkMissHeartBeatEventArgs` 事件反复触发、或 `MissHeartBeatCount` 持续增长时,说明心跳包在间隔时间内未能送达。本页帮助你快速判断是间隔配置、应用焦点还是连接质量导致的丢失,并给出对应的修复与验证方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 每个心跳周期都触发 `NetworkMissHeartBeatEventArgs` | `HeartBeatInterval` 设置过小,小于一次往返延迟 | 调大心跳间隔(见"调整心跳间隔") |
| 应用切后台/失焦后集中出现心跳丢失 | 失焦时心跳发送被暂停,恢复焦点后集中补发 | 检查焦点相关心跳配置(见"失焦心跳策略") |
| 心跳丢失次数达到上限后连接被关闭 | 达到允许的最大丢失次数,通道主动断开 | 核对丢失次数上限与网络质量 |
| 偶发丢失后自行恢复,无需重连 | 单次网络抖动,`Reset` 会清零计数 | 无需处理,仅需监控告警频率 |

## 心跳丢失如何上报

每次判定心跳丢失时,框架通过事件系统抛出 `NetworkMissHeartBeatEventArgs`,事件编号为 `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs`。事件携带两个字段:

```csharp
public sealed class NetworkMissHeartBeatEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(NetworkMissHeartBeatEventArgs).FullName;

    public override string Id
    {
        get { return EventId; }
    }

    /// <summary>获取网络频道。</summary>
    public INetworkChannel NetworkChannel { get; private set; }

    /// <summary>获取心跳包已丢失次数。</summary>
    public int MissCount { get; private set; }

    public static NetworkMissHeartBeatEventArgs Create(INetworkChannel networkChannel, int missCount)
    {
        NetworkMissHeartBeatEventArgs networkMissHeartBeatEventArgs = ReferencePool.Acquire<NetworkMissHeartBeatEventArgs>();
        networkMissHeartBeatEventArgs.NetworkChannel = networkChannel;
        networkMissHeartBeatEventArgs.MissCount = missCount;
        return networkMissHeartBeatEventArgs;
    }
}
```

Source: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L41-L87)

处理该事件时,用 `NetworkChannel` 判断是哪条命名连接出问题,用 `MissCount` 判断丢失的累计程度。

## 修复步骤

### 1. 订阅事件并确认丢失来源

在初始化网络组件后订阅心跳丢失事件,先拿到 `NetworkChannel` 与 `MissCount`,再决定后续动作:

```csharp
// 订阅心跳丢失事件(事件 Id 为 NetworkMissHeartBeatEventArgs.EventId)
GameEntry.Event.AddListener(NetworkMissHeartBeatEventArgs.EventId, OnMissHeartBeat);

private void OnMissHeartBeat(object sender, GameEventArgs e)
{
    var args = (NetworkMissHeartBeatEventArgs)e;
    UnityEngine.Debug.LogWarning($"[网络] {args.NetworkChannel.Name} 心跳丢失,累计 {args.MissCount} 次");
}
```

> 说明:事件对象来自 `ReferencePool`,框架在派发完成后会调用 `Clear()` 将 `NetworkChannel` 与 `MissCount` 清零,因此务必在回调内取值,不要缓存事件对象。

### 2. 调整心跳间隔

心跳由通道主循环驱动:每帧调用 `ProcessHeartBeat(realElapseSeconds)`,累加 `HeartBeatState.HeartBeatElapseSeconds`,到达间隔后发送一次心跳。若 `HeartBeatInterval` 小于客户端到服务器的一次往返时间,几乎每个周期都会判丢。诊断与修复:

1. 记录客户端到服务器的 RTT(可用 Ping 或业务层测量)。
2. 将心跳间隔设置为 RTT 的 3–5 倍以上。
3. 注意 `HeartBeatInterval` 已做负值校验,不要传入负数(见 CHANGELOG 中"HeartBeatInterval 添加负值校验"一条)。

心跳间隔的流逝时长与丢失计数都保存在 `HeartBeatState` 中:

```csharp
public sealed class HeartBeatState
{
    private float _heartBeatElapseSeconds;
    private int _missHeartBeatCount;

    /// <summary>心跳间隔时长</summary>
    public float HeartBeatElapseSeconds { get; set; }

    /// <summary>心跳丢失次数</summary>
    public int MissHeartBeatCount { get; set; }

    /// <summary>重置心跳数据=>保活</summary>
    public void Reset(bool resetHeartBeatElapseSeconds)
    {
        if (resetHeartBeatElapseSeconds)
        {
            _heartBeatElapseSeconds = 0f;
        }

        _missHeartBeatCount = 0;
    }
}
```

Source: [NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L39-L82)

### 3. 排查失焦心跳策略

本包的 README 明确支持"心跳包机制(支持应用获得/失去焦点时发送配置)"。移动端切后台时 Unity 主循环可能被节流甚至暂停,导致心跳无法按间隔发出,回前台后集中报丢失。排查要点:

| 检查项 | 建议做法 |
|--------|----------|
| 失焦时是否继续发心跳 | 若业务允许,失焦时停止发送,回焦后调用 `HeartBeatState.Reset(true)` 清零计数再恢复 |
| 回焦点后的计数 | 先重置再恢复发送,避免旧计数直接触发关闭逻辑 |
| 与服务器约定 | 服务端对失焦客户端放宽心跳超时阈值 |

> CHANGELOG 中已有"修正应用获得焦点时心跳包的默认行为"与"将 ProcessHeartBeat 中 Close 调用移到锁外,避免嵌套锁死锁风险"两项修复,若遇到旧版本失焦后误判丢失或心跳处理卡死,请先升级到较新版本。

### 4. 排查通道关闭逻辑

心跳处理位于通道主循环中,每帧依次执行 `ProcessHeartBeat(realElapseSeconds)` 与 `ProcessReceivedMessage()`。当累计丢失达到上限时会关闭通道;若该关闭逻辑在你使用的版本中出现卡死,请升级到已将 `Close` 调用移出锁的版本。升级后再次观察是否仍会在心跳丢失后挂起。

## 验证

- 在事件回调中打印 `MissCount`:正常网络下应长期为 0;偶发 +1 后被 `Reset` 清零属正常抖动。
- 将心跳间隔临时调成 1 秒并在弱网下测试,确认告警频率随间隔增大而明显下降。
- 切后台 30 秒再回前台,确认无集中告警且连接保持可用(必要时通过 `Reset` 清零计数)。
- 观察连接日志:心跳丢失达到上限时应触发通道关闭与断线事件,而不是卡死或无限告警。
