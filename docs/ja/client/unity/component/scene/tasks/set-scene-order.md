# シーケンの優先度設定とアクティブシーンの切り替え方法

`SceneComponent.SetSceneOrder` を通じて、読み込み済み/読み込み中のシーンに数値を割り当てると、フレームワークは調整のたびに自動的に最大値のシーンを Unity のアクティブシーン(`SceneManager.SetActiveScene`)に設定し、`ActiveSceneChangedEventArgs` イベントを発行します。Additive モードで複数シーンが共存する場合に、どのシーンを論理的なメインシーンとするかを正確に制御する際によく使用されます。

## 前提条件

- プロジェクトに GameFrameX のシーンコンポーネント(`[AddComponentMenu("GameFrameX/Scene")]` の `SceneComponent`)と YooAsset のリソース管理が組み込まれていること。
- シーンのリソースパスは `Assets/` で始まり、`.unity` で終わる必要があります(フレームワークが検証し、そうでない場合は `Scene asset name '{0}' is invalid.` を出力します)。
- `SetSceneOrder` を呼び出す前に、そのシーンは「読み込み中」または「読み込み済み」の状態である必要があります。そうでない場合、フレームワークは `Scene '{0}' is not loaded or loading.` を出力し、今回の設定を無視します。
- 切り替え結果を監視したい場合は、`ActiveSceneChangedEventArgs` イベントを登録する必要があります(《シーンの読み込みとアンロード方法》を参照)。

## 操作手順

1. **シーンコンポーネントを取得**。`GameEntry` にアクセスできる任意のスクリプト内で:

```csharp
using GameFrameX.Scene.Runtime;

var sceneComponent = GameEntry.GetComponent<SceneComponent>();
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L49-L50)

2. **Additive モードでシーンを読み込む**。アクティブシーンの切り替えは複数の読み込み済みシーンの共存に依存するため、通常は `LoadSceneMode.Additive` を使用します:

```csharp
await sceneComponent.LoadScene(
    "Assets/Scenes/Battle.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L294-L322)

3. **シーンに優先度を割り当てる**。数値が大きいほど優先度が高くなります。同じ数値の場合は `m_SceneOrder`(`SortedDictionary<string,int>`)の列挙順で勝敗が決まります:

```csharp
// Battle を最高優先度に設定し、アクティブシーンとして切り替えられるようにする
sceneComponent.SetSceneOrder("Assets/Scenes/Battle.unity", 100);

// HUD シーンをさらに読み込み、優先度を下げる
await sceneComponent.LoadScene(
    "Assets/Scenes/HUD.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
sceneComponent.SetSceneOrder("Assets/Scenes/HUD.unity", 10);
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L352-L381)

4. **アクティブシーン切り替えイベントを購読**(オプション、切り替え後に UI やカメラを更新したり、メインカメラの参照を再配布したりするために使用):

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Scene.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    ActiveSceneChangedEventArgs.EventId,
    (sender, args) =>
    {
        var e = (ActiveSceneChangedEventArgs)args;
        UnityEngine.Debug.Log($"Active: {e.ActiveSceneName} (prev: {e.LastActiveSceneName})");
        sceneComponent.RefreshMainCamera(); // Camera.main を再取得
    });
```

Source: [ActiveSceneChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/ActiveSceneChangedEventArgs.cs)

## よくあるバリエーション

**順序調整が即座に反映される**:`SetSceneOrder` は内部の `RefreshSceneOrder()` を呼び出し、優先度が最も高い読み込み済みのシーンをアクティブに設定します。新しいシーンがまだ `isLoaded==false` の非同期ウィンドウ中である場合、フレームワークは `RefreshSceneOrderWhenLoadedCo` コルーチンを起動し、次のフレームまで待ってからアクティブにします。

**アクティブな候補がない場合**:`m_SceneOrder` が空であるか、登録されているすべてのシーンがまだ読み込み中の場合、フレームワークはアクティブシーンを GameFramework 自身のシーン(`m_GameFrameworkScene`)にフォールバックします。

**複数シーンが同順位**:2 つのシーンの優先度が同じ場合、列挙順が後ろのものが優先されます(`RefreshSceneOrder` は `>` で比較した後に上書きするため)。

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| `SetSceneOrder` を呼び出したが反映されず、ログに `Scene '{0}' is not loaded or loading.` と表示される | シーンが「読み込み中」でも「読み込み済み」でもない状態 | 先に `await LoadScene(...)` を行ってから順序を設定する |
| パスが間違っており、ログに `Scene asset name '{0}' is invalid.` と表示される | リソース名が `Assets/` で始まらないか、`.unity` で終わっていない | プロジェクトの完全な相対アセットパスを使用する |
| `ArgumentException: sceneHandle.IsValid` のような例外がスローされる | YooAsset の `await` の完了タイミングが Unity シーンの `isLoaded==true` より早い | フレームワークは `RefreshSceneOrder` 内部ですでにコルーチンを使って次のフレームまで遅延しているため、手動でリトライする必要はない |
| 連続して `SetSceneOrder` を呼び出すことで、古いコルーチンがまだ動作している | フレームワークはすでに古いコルーチンを `StopCoroutine` してから新しいものを起動している | 手動で管理する必要はない。ただし、カスタムロジックで他のアクティブ化方法と混在させる場合は、フレームワークとの競合を避ける必要がある |
| アクティブシーンの切り替え後も `Camera.main` が古いカメラを指している | 切り替えは Scene のみを変更し、新しいカメラを自動的に探さない | `sceneComponent.RefreshMainCamera()` を呼び出すか、`ActiveSceneChangedEventArgs` を購読して更新する |

## 背景(オプション)

`m_SceneOrder` は `SortedDictionary<string, int>` であり、キーを `Ordinal` で比較します。`RefreshSceneOrder` はこれを反復して最大値を選択し、プライベートメソッド `SetActiveScene(...)` を呼び出してシーンを Unity の `SceneManager.SetActiveScene` に渡し、`m_EventComponent.Fire(this, ActiveSceneChangedEventArgs.Create(...))` を通じてイベントを発行します。Single モードでは YooAsset/Unity がアクティブシーンを自動的に管理するため、フレームワークは対象 Scene のハンドルが無効であることを検出すると、今回の設定を直接スキップし、非同期ウィンドウ中に `ArgumentException` がスローされるのを防ぎます。
