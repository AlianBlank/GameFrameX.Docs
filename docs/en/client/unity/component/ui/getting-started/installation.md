# Installation and Configuration

After integrating the `com.gameframex.unity.ui` package into your Unity project and completing the minimal usable configuration, you can open your first UI form through `UIComponent`.

## Prerequisites

| Item | Requirement |
|------|------|
| Unity | 2019.4 or later ([package.json](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/package.json#L7)) |
| Package dependencies | Installed automatically along with this package; no need to add manually: `com.gameframex.unity`, `com.gameframex.unity.asset`, `com.gameframex.unity.event`, `com.gameframex.unity.localization`, `com.gameframex.unity.tuyoogame.yooasset`, `com.gameframex.unity.cysharp.unitask` |
| Existing GameFrameX framework entry in the project | Requires `GameEntry` to be accessible; the UI component is registered by the framework at startup |

## Steps

### Method 1: Unity Package Manager (Recommended)

1. Open Unity and select `Window → Package Manager` from the top menu.
2. Click the `+` in the top-left corner and select `Add package from git URL`.
3. Paste the URL below and confirm:

   ```
   https://github.com/gameframex/com.gameframex.unity.ui.git
   ```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/README.zh-CN.md#L36-L43)

### Method 2: Directly Edit manifest.json

Add the following to the project's `Packages/manifest.json`:

```json
{
  "dependencies": {
    "com.gameframex.unity.ui": "https://github.com/gameframex/com.gameframex.unity.ui.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/README.zh-CN.md#L47-L55)

After saving, Unity will automatically pull this package and all its dependencies.

### Method 3: Local Installation

1. Download or clone this repository.
2. Place the repository root directory into your project's `Packages/` folder (it can be renamed; Unity will identify it by `package.json`).
3. Switch back to Unity and wait for compilation to finish.

## Configure scopedRegistries (Recommended, Speeds Up Dependency Resolution)

Since this package and its dependencies are all published on GameFrameX's own UPM registry, it is recommended to add a scoped registry in `Packages/manifest.json`. Unity will pull packages starting with `com.gameframex.*` from this registry first:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.ui": "2.11.2"
  }
}
```

> `scopes` controls which packages go through this registry; only packages starting with `com.gameframex` will be fetched from here, so other sources will not be affected.

## Verify the Installation

After installation, do the following three things to confirm the pipeline works:

1. In the Console, confirm the GameFrameX UI package is imported successfully with no errors.
2. Confirm the UI component is accessible in code:

   ```csharp
   var ui = GameEntry.UI; // Should not be null
   ```

3. Run a smoke test with a synchronous open API:

   ```csharp
   int serialId = GameEntry.UI.OpenUIForm("UI/MainMenu", "Normal");
   ```

   The return value is `serialId`; a non-zero value generally indicates success; failure will trigger `OpenUIFormFailureEventArgs`.

## Common Variations

- **Pin to a stable version**: Write the dependency as `"com.gameframex.unity.ui": "2.11.2"` (locked) rather than using the git URL directly; this helps teams avoid inconsistencies caused by main branch drift.
- **Using FairyGUI at the same time**: This package is a UI-framework-agnostic form management layer; the FairyGUI adapter comes from other GameFrameX sub-packages—just add them as needed, and do not mix the same `uiFormAssetName`.
- **Offline/intranet environments**: Method 3 (local installation) is the most reliable; first download the repository (including submodules), then place it into `Packages/`.

## Common Errors

| Symptom | Possible Cause | Solution |
|------|----------|----------|
| `GameEntry.UI` is null | The UI component is not registered, usually because the underlying `com.gameframex.unity` core package was not installed properly | Confirm that `com.gameframex.unity` exists in `Packages/manifest.json` and its version is not lower than `2.5.1` |
| Opening a UI immediately reports assets not found | No asset in YooAsset corresponds to the `uiFormAssetName` | First create assets such as `UI/MainMenu` in the YooAsset asset management, and confirm the package name can be resolved |
| Package Manager gets stuck halfway through installation | `scopedRegistries` is not configured, so the default npm channel is used | Add `scopedRegistries` to `manifest.json` (see above), or switch to Method 3 (local installation) |
| Version incompatibility error | Unity version is below 2019.4 | Upgrade Unity; the minimum version declared in this package's [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/package.json#L7) is `2019.4` |

## Background (Optional)

This package itself only contains form management (open/close/grouping/lifecycle/events); all underlying capabilities—asset loading, event bus, localization, UniTask asynchrony, and YooAsset integration—are provided by other sub-packages within the GameFrameX ecosystem. During installation, these dependencies are automatically brought in per the `dependencies` in `package.json`; no manual management is needed.
