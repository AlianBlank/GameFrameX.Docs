# 如何調整物件池容量與回收策略

UI 框架將介面實例交由 `IObjectPoolManager` 管理,透過 `UIComponent` 上的若干欄位即可調整容量、自動回收/釋放間隔、到期時間。完成本頁設定後，即可控制介面實例物件池能快取多少個 UI、隔多久掃描一次回收。

## 前置條件

- 專案已整合 `GameFrameX.ObjectPool`(`UIComponent.cs` 第 33 行 `using GameFrameX.ObjectPool;`)。
- 場景中存在掛載 `UIComponent` 的 GameObject,並已將 `m_UIManager.SetObjectPoolManager(...)` 注入完畢(`UIComponent.cs` 第 504 行 `SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>())`)。
- 關於 UI 元件與物件池管理器的整體裝配，詳見《如何初始化 UI 模組》。

## 操作步驟

1. **在 Inspector 中調整容量與策略欄位**。選取帶有 `UIComponent` 的 GameObject,在 Inspector 中可以直接看到以下序列化欄位並修改預設值：

| 欄位名稱 | 預設值 | 說明 |
|--------|--------|------|
| `m_InstanceCapacity` | `16` | 介面實例物件池容量上限 |
| `m_InstanceExpireTime` | `60` 秒 | 池內物件閒置超過該秒數即視為可釋放 |
| `m_InstanceAutoReleaseInterval` | `60` 秒 | 自動掃描/釋放間隔 |
| `m_RecycleInterval` | `60` 秒 | 自動回收可回收物件的間隔 |
| `m_EnableAutoReleaseUIForm` | `false` | 是否啟用自動回收 |

欄位定義範例：

```csharp
[SerializeField] private float m_InstanceAutoReleaseInterval = 60f;
[SerializeField] private int   m_InstanceCapacity          = 16;
[SerializeField] private float m_InstanceExpireTime        = 60f;
[SerializeField] private int   m_RecycleInterval           = 60;
[SerializeField] private bool  m_EnableAutoReleaseUIForm   = false;
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L107-L141)

2. **執行期透過屬性動態調整**。`UIComponent` 將上述欄位暴露為公開屬性，執行時修改數值會同時回寫至序列化欄位並傳送至 `m_UIManager`:

```csharp
// 調整容量、到期時間、自動釋放/回收間隔
uiComponent.InstanceCapacity           = 32;   // 容量
uiComponent.InstanceExpireTime         = 120f; // 到期秒數
uiComponent.InstanceAutoReleaseInterval = 30f; // 自動釋放間隔
uiComponent.RecycleInterval            = 30;  // 回收間隔
uiComponent.EnableAutoReleaseUIForm    = true; // 開啟自動回收
```

屬性實作：

```csharp
public int   InstanceCapacity            { get => m_UIManager.InstanceCapacity;             set => m_UIManager.InstanceCapacity            = m_InstanceCapacity            = value; }
public float InstanceExpireTime          { get => m_UIManager.InstanceExpireTime;           set => m_UIManager.InstanceExpireTime          = m_InstanceExpireTime          = value; }
public float InstanceAutoReleaseInterval { get => m_UIManager.InstanceAutoReleaseInterval;  set => m_UIManager.InstanceAutoReleaseInterval = m_InstanceAutoReleaseInterval = value; }
public int   RecycleInterval             { get => m_UIManager.RecycleInterval;              set => m_UIManager.RecycleInterval             = m_RecycleInterval             = value; }
public bool  EnableAutoReleaseUIForm     { get => m_EnableAutoReleaseUIForm;                set => m_EnableAutoReleaseUIForm = value; }
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L322-L359)

3. **關閉自動回收開關(可選)**。若希望手動控制回收，將 `EnableAutoReleaseUIForm` 設為 `false`,計時器就不會再觸發自動掃描，只在顯式呼叫 `CloseUIForm` 時將實例歸還至池中。

4. **儲存並驗證**。重新啟動場景或重新進入 Play Mode,在 Inspector 確認欄位值已生效；在 Profiler 中觀察 `UI Form Instance Pool` 的容量，確認未超過 `InstanceCapacity`。

## 常見變體

- **分階段調校**：上線前在編輯器將 `m_InstanceCapacity` 調高(如 32),便於壓力測試峰值；正式版本透過 `InstanceCapacity` 動態下調，降低常駐記憶體。
- **頻繁開啟/關閉的高頻介面**(例如 Toast、Tips):將 `InstanceExpireTime` 設小(如 10 秒)，讓閒置物件儘快被釋放，避免佔用池容量。
- **重量級介面**(角色面板、商城)：將 `m_InstanceCapacity` 調至 1~2,`InstanceExpireTime` 調大(如 300 秒)，保留快取以便重複使用。
- **完全關閉自動回收**：將 `m_EnableAutoReleaseUIForm = false`,由業務自行決定何時回收(常用於過場劇情期間)。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 修改欄位後不生效 | 執行期只修改屬性未寫回 `m_UIManager`,或未啟用 `EnableAutoReleaseUIForm` | 確認 `m_EnableAutoReleaseUIForm = true`,並透過屬性(非欄位)賦值 |
| 池中物件很快被清空，介面開啟緩慢 | `InstanceExpireTime` 或 `InstanceAutoReleaseInterval` 過小 | 將 `InstanceExpireTime` 調至 60 秒以上，`InstanceAutoReleaseInterval` 調至 30 秒以上 |
| 記憶體持續上升 | `InstanceCapacity` 過大且 `InstanceExpireTime` 過長 | 調小 `InstanceCapacity`,並縮短 `InstanceExpireTime` |
| 頻繁 GC | `RecycleInterval` 過小，計時器反覆觸發 | 將 `RecycleInterval` 調至 30~60 秒 |

## 背景(可選)

`UIComponent` 內部會將設定同時傳送至 `m_UIManager` 與序列化欄位，目的是讓執行期的變動在 Editor 中也能被序列化保留。`IObjectPoolManager` 負責具體的物件池策略(到期回收、定時釋放)，UI 模組只負責傳遞參數與開關；修改 `m_InstancePriority` 這類未公開欄位不會生效。
