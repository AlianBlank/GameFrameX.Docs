# 逆シリアル化時にフィールドが失われたり空になったりする場合の対処法

`JsonMapper.ToObject<T>` を呼び出した後、ターゲット型の一部のフィールド値が `null`、`0`、空文字列、またはデフォルト値になっている場合、通常はフィールドのマッピングルールまたは JSON テキスト自体の不一致が原因です。このページでは、よくある原因と対応する修正方法を紹介します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| JSON に存在するフィールドが逆シリアル化後にデフォルト値になる | フィールド名の大文字・小文字が JSON と一致しない | 下記「フィールド名の大文字・小文字の不一致」を参照 |
| プライベートフィールドや `private set` のみのプロパティが逆シリアル化後に空になる | LitJson はデフォルトで `public` メンバーにマッチする | 下記「非公開フィールドが書き込まれない」を参照 |
| ディクショナリ/リストが逆シリアル化後に空になるが、JSON には実際にデータがある | 非ジェネリックインターフェースを使用した、またはターゲット型が `IDictionary<TKey,TValue>` / `IList<T>` ではない | 下記「コンテナー型の不一致」を参照 |
| 数値フィールドが逆シリアル化後に `0` になるが、JSON では文字列になっている | JSON 内の数値に引用符が付いている | 下記「JSON テキスト自体の引用符の過不足」を参照 |
| 一部のフィールドは正しいが、一部のフィールドが失われる | JSON テキストが不正または切り詰められている | 下記「JSON テキストが不正」を参照 |
| どのフィールドも書き込まれないが、例外はスローされない | ターゲット型は `JsonData` だが、オブジェクトのメンバーとしてアクセスしている | 下記「`JsonData` と厳密な型の混用」を参照 |

## 修正手順

### フィールド名の大文字・小文字の不一致

LitJson は JSON キーと C# メンバーをマッチングする際、デフォルトでは大文字・小文字を区別しない方式で読み取ります。ただし、JSON のフィールド名と C# のフィールド名のスペルが完全に一致しない場合(例えば `userId` vs `UserId`、またはスペルミス)、そのフィールドは書き込まれません。

修正方法：JSON 内のキーと C# のプロパティ名のスペルが一致するようにしてください。JSON を変更できない場合は、カスタムエクスポーター/インポーターのマッピングを使用するか、`JsonData` を使用してキー名から直接値を取得してください。

### 非公開フィールドが書き込まれない

LitJson はデフォルトでは、公開されたインスタンスのプロパティ/フィールドのみを読み取ります。データ型のフィールドが `private` や `internal` として宣言されている場合、またはプロパティに `private set` しかない場合、逆シリアライザーはそれらを無視し、型のデフォルト値が保持されます。

修正方法：逆シリアル化が必要なフィールド/プロパティを `public` に変更するか、それらに `public` のアクセサーを提供してください。

```csharp
public class PlayerData
{
    // public にする必要があります。そうでない場合、ToObject<PlayerData> では書き込まれません
    public int id;
    public string name;
}
```

出典： [Runtime/JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs#L1248-L1356)

### コンテナー型の不一致

LitJson は配列/オブジェクトを厳密な型に逆シリアル化する際、ターゲット型が `IList<T>` / `IDictionary<TKey, TValue>` のようなジェネリックインターフェースを実装していること、または `RegisterImporter` で登録された型マッピングにマッチすることを要求します。フィールドの型が通常のクラス(例えばカスタムの `MyList`)である場合、JSON 配列はスキップされ、そのフィールドは空のままになります。

修正方法：フィールドの型を `List<T>`、`Dictionary<string, T>` などの組み込みコンテナーに変更するか、カスタムコンテナーに対応するインターフェースを実装して `RegisterImporter` で登録してください。

### JSON テキスト自体の引用符の過不足

よくある間違い：数値を文字列として書く(例えば `"score": "100"`)、または文字列を裸のリテラルとして書く(例えば `"name": foo`)ことです。LitJson は自動変換しないため、このようなフィールドは黙って無視されるか、`JsonException` がスローされます。

修正方法：任意の JSON オンライン検証ツールでテキストが有効であることを確認してください。数値には引用符を付けず、文字列には必ず二重引用符を付け、フィールド名にも必ず二重引用符を付けてください。

### JSON テキストが不正

よくある原因：ファイルの読み取りが不完全(ネットワークによる切断、バイト順の乱れ、BOM 未処理)、余分なカンマ、シングルクォートの文字列。JSON のパースが途中で失敗した場合、一部のフィールドがまったく読み取られていない可能性がありますが、`ToObject<T>` は「部分的な成功」とはならず、直接例外をスローします。

修正方法:`ToObject<T>` を呼び出す前に、`JsonReader` で先頭と末尾を順番に確認し、入力が UTF-8 文字列であり、BOM が除去されていることを確認してください。

### `JsonData` と厳密な型の混用

`JsonMapper.ToObject(string)`(ジェネリックなし)が返すのは `JsonData` であり、「思っている」ようなクラスではありません。`JsonData` は文字列キーでアクセスします。例えば `data["name"]` のようにアクセスします。`data.name` に直接アクセスしても期待する値は得られません。

修正方法:`ToObject<T>`(厳密な型)または `ToObject()`(`JsonData` を返す)を明確に使い分け、混用しないでください。

```csharp
// 厳密な型
PlayerData p = JsonMapper.ToObject<PlayerData>(json);

// 弱い型
JsonData d = JsonMapper.ToObject(json);
string name = (string)d["name"];
```

出典： [Runtime/JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs#L1280-L1356)

## 検証

1. `JsonMapper.ToObject(json)`(`JsonData` を返す)でツリー全体を出力し、JSON テキストに期待するキーがあることを確認します。
2. 次に、`JsonMapper.ToObject<T>(json)` でターゲット型に逆シリアル化し、フィールドごとに照合します。
3. それでもフィールドが見つからない場合は、一時的にターゲット型を `JsonData` に変更し、JSON 内のキーが実際に何なのかを確認します。これにより、「JSON に存在しない」場合と「C# フィールド名の不一致」場合をすぐに区別できます。
