# How to Initialize Resource Packages and Select a Runtime Mode

After completing the tasks on this page, you will be able to select an appropriate runtime mode through `AssetComponent` in GameFrameX and initialize one or more YooAsset resource packages for subsequent resource loading.

## Prerequisites

- `GameFrameX.Asset` has been installed (includes the dependency on YooAsset).
- A GameFrameX entry exists in the scene with `AssetComponent` attached (added in the Inspector via `[AddComponentMenu("GameFrameX/Asset")]`, see [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L17-L20)).
- For online / mini-game modes, you need to prepare the primary download address (`host`) and the fallback download address (`fallbackHostServer`).

## Runtime Modes Overview

`AssetComponent.GamePlayMode` is the enumeration `EPlayMode`, which determines how the file system is constructed and how resource packages are initialized: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L23-L45).

| Mode | Applicable Scenario | File System / Notes |
|------|---------------------|---------------------|
| `EditorSimulateMode` | Debugging inside the editor only, uses simulated build results | Built via `EditorSimulateModeHelper.SimulateBuild`, no network download |
| `OfflinePlayMode` | Standalone / pure local package (resources shipped with the build) | `CreateDefaultBuildinFileSystemParameters` |
| `HostPlayMode` | Online runtime, resources downloaded on demand from a remote server | Uses `hostServerURL` + `fallbackHostServerURL` |
| `WebPlayMode` | WebGL / mini-games (Douyin, WeChat, Kuaishou, etc.) | Automatically selects the corresponding mini-game file system based on macros; WebGL is forced to use this mode |

Mode selection and parameter construction logic can be found in [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L18-L47).

## Steps

1. In the Inspector, select `Game Play Mode` for `AssetComponent` (except for `EditorSimulateMode`, this field takes effect in non-editor environments; under WebGL it is forcibly switched to `WebPlayMode`, see [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L66-L73)).
2. After `GameEntry` starts, `AssetComponent.Awake` automatically calls `_assetManager.SetPlayMode(GamePlayMode)`, and `Start` calls `_assetManager.Initialize()` ([AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L84-L91)). This step creates the YooAsset main file system and requires no additional code.
3. In your own initialization code, call `InitPackageAsync` to create a YooAsset `ResourcePackage` for each resource package (default package / sub-packages) and initialize it. The signature can be found at [IAssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L72-L72):

```csharp
using GameFrameX.Asset.Runtime;
using UnityEngine;

public class AssetBootstrap : MonoBehaviour
{
    private async void Start()
    {
        var asset = GameEntry.GetComponent<AssetComponent>();

        // Default resource package (uses the constant name AssetComponent.BuildInPackageName == "DefaultPackage")
        bool ok = await asset.InitPackageAsync(
            AssetComponent.BuildInPackageName,
            hostServerURL: "https://cdn.example.com/game/{appVersion}",
            fallbackHostServerURL: "https://cdn2.example.com/game/{appVersion}",
            isDefaultPackage: true);

        if (!ok)
        {
            Debug.LogError("Failed to initialize the default resource package");
            return;
        }

        // Other sub-packages (optional)
        await asset.InitPackageAsync(
            "SkinPackage",
            hostServerURL: "https://cdn.example.com/skin/{appVersion}",
            fallbackHostServerURL: "https://cdn2.example.com/skin/{appVersion}",
            isDefaultPackage: false);
    }
}
```

The call entry and the default package name constant can be found at [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L57-L57) and [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L104-L120).

4. Observe the returned `Task<bool>`: `true` indicates that the resource package has been initialized successfully, and you can continue with subsequent loading logic.

## Common Variations

- **Editor debugging**: Without modifying code, simply set `Game Play Mode` to `EditorSimulateMode` in the Inspector; after running, `Awake` will forcibly change it to `HostPlayMode` on non-editor platforms ([AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L66-L69)).
- **WebGL / Mini-games**: When the target platform is WebGL, `Awake` forcibly uses `WebPlayMode` ([AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L70-L73)). The mini-game branch selects the corresponding file system for Douyin, WeChat, or Kuaishou based on macros such as `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_WECHAT_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` ([AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L85-L120)).
- **Switching modes at runtime**: You can assign a value to `AssetComponent.GamePlayMode` at runtime, which will trigger `_assetManager.SetPlayMode(value)` ([AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L34-L44)).

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| Log output `Asset manager is invalid.` | GameFrameX has not registered the `IAssetManager` implementation | Confirm that the assembly containing `AssetComponent` is loaded, and that the registration of `GameFrameworkEntry.GetModule<IAssetManager>()` has not been disabled ([AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L82)) |
| Error when starting in online mode | `hostServerURL` or `fallbackHostServerURL` is left empty | Explicitly pass the CDN URL in `InitPackageAsync`, and keep it consistent with the build version placeholder `{appVersion}` |
| Abnormal startup in mini-game mode | The corresponding macro (such as `ENABLE_WECHAT_MINI_GAME`) is not enabled | Enable the target mini-game platform macro in the project settings, then rebuild and run ([AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L85-L120)) |
| Returns `false` after calling `InitPackageAsync` | The resource package already exists, or the remote manifest version does not match | Check whether the same package is being initialized repeatedly, or confirm that the remote version number matches the build output |

## Background (Optional)

Resource initialization is divided into two layers: `AssetComponent.Awake/Start` is responsible for the global YooAsset main file system and the current `PlayMode`; `InitPackageAsync` creates a `ResourcePackage` by package name and selects the corresponding YooAsset initialization parameters based on `PlayMode` in `CreateInitializationOperationHandler` ([AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L18-L47)).
