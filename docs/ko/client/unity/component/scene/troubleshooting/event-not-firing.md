# 로드 또는 언로드 이벤트가 트리거되지 않을 때 대처 방법

`SceneComponent.LoadScene` / `UnloadScene`을 호출한 후 `LoadSceneSuccess`, `LoadSceneFailure`, `UnloadSceneSuccess`, `UnloadSceneFailure`, `LoadSceneUpdate` 이벤트 중 어느 하나도 수신되지 않는 경우, 이 페이지에 따라 항목별로 점검하세요.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 로드/언로드 전 과정에서 이벤트 콜백이 전혀 없음 | `EventComponent`가 `GameEntry`에 등록되지 않았거나, 씬 컴포넌트 시작 시 `Event component is invalid.`가 출력됨 | `GameEntry`에 `EventComponent`가 부착되어 있고 `SceneComponent`보다 먼저 초기화되는지 확인 |
| `LoadSceneUpdate`만 수신되지 않음 | `SceneComponent`의 `Enable Load Scene Update Event` 체크가 해제됨 | Inspector에서 `Enable Load Scene Update Event`를 체크하거나, Prefab에서 `m_EnableLoadSceneUpdateEvent`를 다시 `true`로 설정 |
| `LoadSceneFailure`는 수신되지만 `UserData`가 null임 | 로드 실패가 `YooAsset` 핸들을 얻기 전에 발생함 | `sceneAssetName`이 `Assets/`로 시작하는지, 패키징 매니페스트에 존재하는지 확인. 자세한 내용은 아래 참조 |
| 이벤트는 수신되지만 비즈니스 측 handler가 실행되지 않음 | `Subscribe` 시 `EventId`를 잘못 작성했거나, 구독이 `Awake` 이전에 발생함 | `typeof(...).FullName`을 `EventId`로 사용하고, 구독 시점이 `GameEntry` 시작 이후인지 확인 |
| 동일한 씬을 반복 로드할 때 두 번째에 `LoadSceneSuccess`가 수신되지 않음 | 첫 번째 성공 후 해당 씬이 이미 `LoadedScenes`에 추가되어, 다시 `LoadScene`하면 YooAsset 동기 경로를 사용함 | "일반적인 변형" 섹션 참조 |

## 수정 단계

### 1. SceneComponent가 부착 및 시작되었는지 확인

`SceneComponent`는 `Awake`에서 씬 관리자와 이벤트 컴포넌트를 검사하며, 하나라도 없으면 `Fatal`을 출력하고 바로 `return`하므로 이후 모든 이벤트가 분배되지 않습니다:

```csharp
// Runtime/Scene/SceneComponent.cs
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IGameSceneManager);
    base.Awake();
    _gameSceneManager = GameFrameworkEntry.GetModule<IGameSceneManager>();
    if (_gameSceneManager == null)
    {
        Log.Fatal("Scene manager is invalid.");
        return;
    }
    // ... 이벤트 구독
    m_GameFrameworkScene = UnityEngine.SceneManagement.SceneManager.GetSceneAt(GameEntry.GameFrameworkSceneId);
    if (!m_GameFrameworkScene.IsValid())
    {
        Log.Fatal("Game Framework scene is invalid.");
        return;
    }
}
```

출처: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L79-L113)

작업:
1. 진입 씬의 GameFramework 루트 노드를 선택하여 `Scene Component`가 존재하는지 확인합니다(메뉴 경로 `GameFrameX/Scene`).
2. 실행 후 Console을 확인하여 `Scene manager is invalid.`, `Game Framework scene is invalid.` 등의 치명적 로그가 있는지 확인합니다.
3. 하나라도 나타나면 `SceneComponent`가 구독을 완료하지 못한 것이므로 반드시 먼저 해결해야 합니다.

### 2. EventComponent가 부착되어 있는지 확인

`Start` 단계에서 `EventComponent`를 다시 검증하며, 없으면 `Fatal`을 출력하고 바로 `return`합니다. 이때 이벤트 구독은 이미 `_gameSceneManager`에 걸려 있지만 더 이상 상위 계층으로 `Fire`되지 않습니다:

```csharp
// Runtime/Scene/SceneComponent.cs
private void Start()
{
    BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
    if (baseComponent == null)
    {
        Log.Fatal("Base component is invalid.");
        return;
    }

    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event component is invalid.");
        return;
    }
    // ...
}
```

출처: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L115-L139)

작업: GameFramework 루트 노드에 `Event Component`를 추가하고, 해당 우선순위가 `SceneComponent`보다 빠르도록 보장합니다(`SceneComponent`의 `GameFrameXAutoComponent` 우선순위는 `-4000`이며, [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L48) 참조).

### 3. 비즈니스 측에서 이벤트를 올바르게 구독

이벤트는 `EventComponent.Fire`를 통해 분배되며, 구독 측은 반드시 해당 `EventArgs` 타입의 `EventId`(즉, `typeof(...).FullName`)를 사용해야 합니다:

```csharp
// Runtime/EventArgs/LoadSceneSuccessEventArgs.cs
public sealed class LoadSceneSuccessEventArgs : GameEventArgs { /* ... */ }

// Runtime/EventArgs/LoadSceneFailureEventArgs.cs
public static readonly string EventId = typeof(LoadSceneFailureEventArgs).FullName;
```

출처: [LoadSceneSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneSuccessEventArgs.cs#L40-L41), [LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs#L46)

구독 예시(`GameFrameX.Event.Runtime.EventComponent`의 표준 API 사용):

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    LoadSceneSuccessEventArgs.EventId,
    OnLoadSceneSuccess);

private void OnLoadSceneSuccess(object sender, GameEventArgs e)
{
    var args = (LoadSceneSuccessEventArgs)e;
    // args.SceneAssetName / args.Duration / args.UserData
}
```

자주 겪는 실수:

| 잘못된 작성법 | 결과 |
|----------|------|
| 문자열 리터럴로 `LoadSceneSuccessEventArgs.EventId`를 잘못 쓰거나 공백을 빠뜨림 | 이벤트를 영원히 수신할 수 없음 |
| `Subscribe<LoadSceneSuccessEventArgs>(handler)` 오버로드를 사용하지만 타입이 `EventId`를 공개하지 않음 | 컴파일 시점에 오류 발생 또는 런타임에 조용히 실패 |
| 구독을 정적 생성자 또는 도메인 초기화에 작성하여 이벤트 트리거보다 늦음 | 이번 콜백을 놓침 |

### 4. LoadSceneUpdate가 스위치로 꺼져 있는지 확인

`SceneComponent`는 기본적으로 `LoadSceneUpdate`를 구독하지만, 해당 필드는 Inspector에서 비활성화할 수 있습니다:

```csharp
// Runtime/Scene/SceneComponent.cs
[SerializeField] private bool m_EnableLoadSceneUpdateEvent = true;
if (m_EnableLoadSceneUpdateEvent)
{
    _gameSceneManager.LoadSceneUpdate += OnLoadGameSceneUpdate;
}
```

출처: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L63-L97)

`LoadSceneUpdate`만 누락되는 경우, 씬의 `Scene Component`를 선택하고 `Enable Load Scene Update Event`를 체크합니다.

### 5. SceneAssetName이 유효한지 확인

`HasScene`은 `Assets/`로 시작하지 않는 이름을 거부합니다:

```csharp
// Runtime/Scene/SceneComponent.cs
public bool HasScene(string sceneAssetName)
{
    if (string.IsNullOrEmpty(sceneAssetName))
    {
        Log.Error("Scene asset name is invalid.");
        return false;
    }
    if (!sceneAssetName.StartsWith("Assets/", StringComparison.Ordinal) ||
        // ...
        )
    {
        Log.Error("Scene asset name '{0}' is invalid.", sceneAssetName);
        return false;
    }
    // ...
}
```

출처: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L271-L295)

잘못된 이름을 전달하면 `LoadSceneFailure`로 처리되며, 오류 메시지는 일반적으로 `Scene asset name 'xxx' is invalid.`입니다.

### 6. 하위 YooAsset 핸들 상태 확인

`GameSceneManager`는 `YooAsset.SceneHandle`을 통해 성공/실패를 전달하며, 핸들 생성에 실패하면 `m_LoadingSceneAssetNames`에 들어가지 않으므로 당연히 후속 이벤트가 발생하지 않습니다:

```csharp
// Runtime/Scene/Scene/GameSceneManager.cs
private readonly Dictionary<string, YooAsset.SceneHandle> m_LoadedSceneAssetNames;
private readonly Dictionary<string, SceneHandleData> m_LoadingSceneAssetNames;
private readonly Dictionary<string, YooAsset.SceneHandle> m_UnloadingSceneAssetNames;
```

출처: [GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L59-L61)

오류가 발생한 씬에서 `SceneComponent.GetLoadingSceneAssetNames()`와 `GetUnloadingSceneAssetNames()`를 호출했을 때 반환값이 비어 있으면, 애초에 비동기 큐에 들어가지 않은 것이므로 이벤트가 트리거되지 않는 것입니다 — 5단계로 돌아가 리소스 이름을 확인하세요.

## 검증

위 단계를 완료한 후, 아래 표에 따라 확인하세요:

| 검증 항목 | 기대 결과 |
|--------|------|
| Console에 `Scene manager is invalid.` 등 Fatal이 없음 | 예 |
| 비즈니스 측 `LoadSceneSuccessEventArgs` 콜백이 트리거되고, `SceneAssetName`이 요청 값과 동일함 | 예 |
| `LoadSceneFailure`는 일부러 잘못된 이름을 전달할 때만 트리거되며, `ErrorMessage`를 포함함 | 예 |
| `LoadSceneUpdate` 진행률이 0→1로 연속 트리거되고, 최종적으로 `LoadSceneSuccess`에 도달함 | 예 |
| `UnloadSceneSuccess`가 직접 `UnloadScene`을 호출한 후 트리거됨 | 예 |

개별 이벤트만 누락된 경우 "빠른 진단" 대조표로 돌아가 구체적인 행을 찾아보세요. 모든 이벤트가 누락되고 Fatal 로그도 없다면, `EventComponent`가 부착되지 않았거나 구독 시점이 너무 이른 것이라고 거의 확정할 수 있습니다.
