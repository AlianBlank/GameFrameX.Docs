# プレイヤーインベントリ（Bag）モジュールの実装

このタスクが完了すると、利用可能なプレイヤーインベントリコンポーネントが得られます。アイテムの追加、削除、使用、およびインベントリ全データの照会をサポートし、Actor 状態による自動永続化、アイテム変更時のクライアントへの能動的プッシュを行います。

## 前提条件

- フレームワークの Actor/Component 体系の構築が完了しており、`StateComponent`、`StateComponentAgent` の基本的な使い方を理解していること。
- アイテム設定テーブル `TbItemConfig` が `ConfigComponent` に登録済みであること（コード内で `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(itemId, out _)` によりアイテム存在を検証）。
- クライアント/サーバーが ProtoBuf プロトコル `Proto/_0100_Bag.cs` に基づいて `ReqBagInfo`、`RespBagInfo`、`ReqAddItem`、`RespAddItem`、`ReqRemoveItem`、`RespRemoveItem`、`ReqUseItem`、`RespUseItem`、`NotifyBagInfoChanged`、`NotifyBagItem` などのメッセージ型を生成済みであること。

### 3. Hotfix 層での BagComponentAgent の実装

`GameFrameX.Hotfix/Logic/Player/Bag/BagComponentAgent.cs` で `StateComponentAgent<BagComponent, BagState>` を継承し、「追加 / 削除 / 使用 / 照会」の 4 つのコアメソッドを実装します。すべてのメソッドは、まず `ConfigComponent` でアイテム存在を検証し、その後状態を変更して `OwnerComponent.WriteStateAsync()` で永続化します。

```csharp
using GameFrameX.Apps.Player.Bag.Component;
using GameFrameX.Apps.Player.Bag.Entity;
using GameFrameX.Config;
using GameFrameX.Config.Tables;

namespace GameFrameX.Hotfix.Logic.Player.Bag;

public class BagComponentAgent : StateComponentAgent<BagComponent, BagState>
{
    public async Task<BagState> UpdateChanged(INetWorkChannel netWorkChannel, Dictionary<int, long> itemDic)
    {
        var bagState = OwnerComponent.State;
        var notifyBagInfoChanged = new NotifyBagInfoChanged();
        foreach (var item in itemDic)
        {
            var notifyBagItem = new NotifyBagItem() { ItemId = item.Key };
            if (bagState.List.TryGetValue(item.Key, out var value))
            {
                value.Count += item.Value;
                notifyBagItem.Count = value.Count;
                notifyBagItem.Value = item.Value;
            }
            else
            {
                bagState.List[item.Key] = new BagItemState() { Count = item.Value, ItemId = item.Key };
                notifyBagItem.Count = item.Value;
                notifyBagItem.Value = item.Value;
            }

            notifyBagInfoChanged.ItemDic[item.Key] = notifyBagItem;
        }

        // netWorkChannel が空の場合はオフライン付与:インベントリの永続化のみ行い、クライアントには通知しない
        if (netWorkChannel != null)
        {
            await netWorkChannel.WriteAsync(notifyBagInfoChanged);
        }

        await OwnerComponent.WriteStateAsync();
        return bagState;
    }
}
```

public async Task OnAddBagItem(INetWorkChannel netWorkChannel, ReqAddItem message, RespAddItem response)
{

    {

        {
            response.ErrorCode = (int)OperationStatusCode.NotFound;
            return;
        }

    {
        response.ErrorCode = (int)OperationStatusCode.Unprocessable;

### 5. 照会ロジックの実装

`OnReqBagInfoAsync` は状態内のアイテムリストを応答メッセージの `Dictionary<int, long>(ItemId -> Count)` に変換し、クライアントが一度に完全なインベントリを取得できるようにします。

```csharp
public async Task OnReqBagInfoAsync(INetWorkChannel netWorkChannel, ReqBagInfo message, RespBagInfo response)
{
    var bagState = OwnerComponent.State;
    if (bagState.IsNotNull())
    {
        response.ItemDic = bagState.List.ToDictionary(x => x.Key, x => x.Value.Count);
    }

    await Task.CompletedTask;
}
```

## よくあるバリエーション

- **オフライン報酬**:`UpdateChanged(netWorkChannel: null, itemDic)` を呼び出します。`netWorkChannel` が `null` の場合はクライアントへのプッシュをスキップし、永続化のみを行います。メール添付やログイン報酬などの統一的な報酬付与インターフェースに適しています。
- **アイテム使用による消費**:`OnUseBagItem` 内で数量が 0 になった場合、直接 `bagState.List` から該当アイテムを削除し、`value.Count` を 0 にリセットします。同時に `NotifyBagInfoChanged` でクライアントにプッシュします。
- **削除の検証**:`OnRemoveBagItem` はアイテム数量不足の場合に `OperationStatusCode.Unprocessable` を直接返し、アイテムが存在しない場合は `OperationStatusCode.NotFound` を返します。

## よくあるエラー

- **コンポーネント未登録**:`BagComponent` は `[ComponentType(GlobalConst.ActorTypePlayer)]` で注釈付けされている必要があります。さもないとプレイヤー Actor にこのコンポーネントがマウントされず、`OwnerComponent.State` からデータを取得できません。
- **設定テーブル未設定**:`OnAddBagItem` / `OnRemoveBagItem` / `OnUseBagItem` はすべて `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)` でアイテムを検証します。アイテムが未設定の場合は直接 `NotFound` を返し、状態は書き込まれません。
- **オフライン報酬時にネットワークチャネルを渡した**:オンラインで見るべきでない変化をクライアントが受信してしまい、データ同期異常を引き起こします。オフラインシナリオでは `null` を渡す必要があります。
- **控除後に永続化を忘れた**:`bagState.List` を変更するすべての分岐で `await OwnerComponent.WriteStateAsync();` を呼び出す必要があります。さもないと状態はメモリ上にのみ存在し、プロセス再起動後に失われます。

## 背景（オプション）

- `BagComponent` は `StateComponent<BagState>` であり、Actor フレームワークがシリアライズと永続化を担当します。Hotfix 層の `BagComponentAgent` は `OwnerComponent` を通じて `BagState` インスタンスを取得し、その場で変更します。
- アイテムの追加 / 使用後、サーバーは能動的に `WriteAsync(notifyBagInfoChanged)` で変更増分をクライアントにプッシュし、クライアントのポーリングを回避します。
