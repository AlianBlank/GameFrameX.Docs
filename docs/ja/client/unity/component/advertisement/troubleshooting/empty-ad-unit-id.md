# 広告枠 ID が空の場合の対処法

`BaseAdvertisementManager.Initialize` が空の文字列または `null` の広告枠 ID を受け取ると、広告 SDK はリクエストを拒否し、失敗をコールバックします。このページでは、「広告枠 ID が空です」の原因を迅速に特定し、再生を復旧する方法を説明します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| Inspector の「Android/IOS/WebGL 広告枠ID」フィールドが空になっている | `AdvertisementComponent` の対象プラットフォームに対応する `m_adUnitId*` シリアライズフィールドが入力されていない | Inspector で対象プラットフォームの広告枠 ID を入力する |
| 実行時に `ArgumentNullException: config` が発生する | `Initialize(AdvertisementConfig)` の呼び出し時に `null` を渡している | Inspector またはコードで正しく設定された `AdvertisementConfig` インスタンスを渡す |
| 旧 API である `Initialize(string, bool)` が `null`/空文字列を受け取る | `adUnitId` 引数に値が設定されていない状態で `string.Empty` パスを直接呼び出している | 呼び出し前に、 `adUnitId` に広告プラットフォームの管理画面で生成された実際の ID を設定する |
| 複数プラットフォームのうち 1 つだけ入力しており、他のプラットフォームで広告が取得できない | 対象プラットフォームの分岐にある `m_adUnitId*` が空になっている | ビルドプラットフォームを切り替える際に、すべてのプラットフォームの広告枠 ID を確認して補完する |

広告枠 ID は広告プラットフォームの管理画面で作成します。コンポーネントはフィールドを保持するだけで、デフォルトのサンプル値は提供しません。

## 修正手順

### 1. Inspector に広告枠 ID を入力する

`AdvertisementComponent` がアタッチされたゲームオブジェクトで、公開先のプラットフォームに応じて対応するフィールドに入力します。未公開のプラットフォームは空欄のままで構いませんが、対象プラットフォームに影響を与えないようにする必要があります。

- Android 広告枠ID
- IOS 広告枠ID
- WebGL 広告枠ID
- WebGL WeChat 広告枠ID
- WebGL Douyin 広告枠ID
- WebGL Kuaishou 広告枠ID

Source: [AdvertisementComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L26-L56)

### 2. コードから正しい初期化エントリポイントを呼び出す

`Initialize(AdvertisementConfig config)` オーバーロードを優先的に使用してください。旧版の `Initialize(string adUnitId, bool debug)` には `[Obsolete]` が設定されています。渡された `config` が `null` の場合、`ArgumentNullException(nameof(config))` が即座にスローされます。

```csharp
var config = ScriptableObject.CreateInstance<YourAdvertisementConfig>();
config.adUnitId = "your_real_ad_unit_id";
config.isDebug = false;
GameFrameX.Advertisement.Runtime.BaseAdvertisementManager.Initialize(config);
```

Source: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L112-L134)

### 3. null 値によって内部の `string.Empty` フォールバックがトリガーされることを避ける

実装では、`null` または `DefaultAdvertisementConfig` 以外の種類の設定を空の文字列にフォールバックします。SDK が空の ID を受け取ると必ず失敗するため、`Initialize` に渡す前に、構成オブジェクト内の `adUnitId` が設定済みであることを確認する必要があります。

```csharp
// BaseAdvertisementManager.Initialize(AdvertisementConfig) 内部
var defaultConfig = config as DefaultAdvertisementConfig;
Initialize(defaultConfig != null ? defaultConfig.adUnitId : string.Empty, config.isDebug);
```

Source: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L127-L128)

## 検証

1. 再度パッケージ化して対象プラットフォームで実行し、ログに「ad unit id is empty」や「invalid ad unit id」などのエラーが表示されなくなったことを確認します。
2. 広告プラットフォームのテストモード（コンポーネントの `是否是测试模式` フィールド）でテスト広告を取得できれば、ID が有効になっていることを示します。
3. 別の公開プラットフォームに切り替える前に、そのプラットフォームの分岐にある `m_adUnitId*` フィールドが空でないことを確認してから、広告リクエストをトリガーします。
