# 在 UI 中嵌入模型、粒子與骨骼動畫

使用 FairyGUI 的 `GoWrapper` 將任意 `GameObject`（3D 模型、粒子系統、骨骼動畫等）包裝為顯示物件後，連接到 UI 的空白圖形元件，即可在不使用額外攝影機或 RenderTexture 的情況下，讓其參與 FairyGUI 的階層結構、遮擋（occlusion）與排序。

## 前置條件

- 專案中必須已匯入此 FairyGUI 套件（`Runtime/Core/GoWrapper.cs` 所屬的組件）。
- 準備一個在 UI 畫面上作為佔位符使用的**空白圖形（Graph）**元件。也可以先在程式碼中繪製透明矩形作為佔位符。FairyGUI 本身在 `GWindow` 中也是這麼做的：

```csharp
GGraph graph = _dragArea as GGraph;
if (graph != null && graph.shape.isEmpty)
    graph.DrawRect(_dragArea.width, _dragArea.height, 0, Color.clear, Color.clear);
```

來源：[GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L159-L161)

## 操作步驟

1. 將要顯示的 `GameObject`（模型、粒子預製件、骨骼動畫宿主等）實例化。
2. 建立 `GoWrapper` 完成包裝後，將包裝結果設定到空白圖形元件上：

```csharp
GameObject model = Instantiate(modelPrefab);
GoWrapper wrapper = new GoWrapper(model);   // 建立時即完成包裝
holder.SetNativeObject(wrapper);            // holder 是 UI 的空白圖形 GGraph
```

`GoWrapper(GameObject go)` 的實際簽章如下，建立時預設**不會**複製材質：

```csharp
public GoWrapper(GameObject go) : this()
{
    SetWrapTarget(go, false);
}
```

來源：[GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L47-L54)

3. 若材質與其他物件共享，或材質需要進行 UI 特有的處理，請以會複製材質的模式設定包裝物件：

```csharp
/// 設定包裝物件。若原本已有包裝物件，設定新的包裝物件時，舊的包裝物件只會移除參考而不會被銷毀，請注意這一點。
/// 物件所包含的所有材質皆不會複製。若材質已處於共用狀態，可能會影響其他物件。若希望自動複製，請設定為 SetWrapTarget(target, true)。
public GameObject wrapTarget
{
    get { return _wrapTarget; }
    set { SetWrapTarget(value, false); }
}

public void SetWrapTarget(GameObject target, bool cloneMaterial)
```

來源：[GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L56-L77)

4. 包裝的內部實作會將目標物件附加為自身的子物件並快取渲染器。非 Canvas 物件的大小會設為 0，是否顯示則由渲染器本身決定：

```csharp
if (_wrapTarget != null)
{
    _wrapTarget.transform.SetParent(this.cachedTransform, false);
    _canvas = _wrapTarget.GetComponent<Canvas>();
    if (_canvas != null)
    {
        _canvas.renderMode = RenderMode.WorldSpace;
        _canvas.worldCamera = StageCamera.main;
        _canvas.overrideSorting = true;

        RectTransform rt = _canvas.GetComponent<RectTransform>();
        rt.pivot = new Vector2(0, 1);
        rt.position = new Vector3(0, 0, 0);
        this.SetSize(rt.rect.width, rt.rect.height);
    }
    else
    {
        CacheRenderers();
        this.SetSize(0, 0);
    }

    SetGoLayers(this.layer);
}
```

來源：[GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L92-L114)

5. 需要每幀對包裝物件做額外處理時，可訂閱 `onUpdate`；需要完全掌控材質替換邏輯時，則可提供 `customCloneMaterials` / `customRecoverMaterials` 委派：

```csharp
public event Action<UpdateContext> onUpdate;
public Action<Dictionary<Material, Material>> customCloneMaterials;
public Action customRecoverMaterials;
```

來源：[GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L16-L18)

## 常見變體

- **UGUI Canvas 嵌入**：`SetWrapTarget` 偵測到目標帶有 `Canvas` 時，會自動切換為 `RenderMode.WorldSpace`、指定 `StageCamera.main`，並依 RectTransform 尺寸執行 `SetSize`，因此可將 UGUI 面板直接嵌入 FairyGUI。
- **需要點擊偵測的 3D 物件**：儲存庫中提供多種命中測試實作，可依需求與 `GoWrapper`（繼承自 `DisplayObject`）的命中區域搭配使用：[ColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/ColliderHitTest.cs)、[MeshColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/MeshColliderHitTest.cs)、[PixelHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/PixelHitTest.cs)。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 共享材質的其他物件顏色被意外改變 | 包裝時直接使用了 `sharedMaterial` | 使用 `SetWrapTarget(target, true)` 複製材質 |
| 變更包裝物件後，先前的模型仍持續顯示 | `SetWrapTarget` 只移除參考，並**不會銷毀**先前的物件 | 變更目標前先自行 `Destroy` 先前的物件 |
| 模糊等依 Layer 套用的效果無法正確作用於包裝物件 | 包裝物件及其子物件必須與 UI 使用相同的 Layer | `GoWrapper` 已在 `_SetLayerDirect` 中遞迴設定 Layer，請確認外部程式碼沒有再次變更 |
| 骨骼動畫/粒子未更新渲染或發生渲染遺漏 | 內部渲染器快取未更新 | 重新設定包裝目標，或呼叫 `CacheRenderers()` 重新快取（呼叫位置參見上方 92-114 行） |

`_SetLayerDirect` 的遞迴 Layer 處理（依原始碼註解，這是為了在 `GoWrapper` 中使用模糊效果）：

```csharp
override internal void _SetLayerDirect(int value)
{
    gameObject.layer = value;
    if (_wrapTarget != null)// 此 if 語句是為了在 GoWrapper 中使用模糊效果
    {
        _wrapTarget.layer = value;
        foreach (Transform tf in _wrapTarget.GetComponentsInChildren<Transform>(true))
        {
            tf.gameObject.layer = value;
        }
    }
}
```

來源：[GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L117-L128)

## 背景

`GoWrapper` 繼承自 `DisplayObject`（宣告請參閱 [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L8-L12)）。此類別會建立名為 `GoWrapper` 的宿主 `GameObject`，透過 `SetParent` 將包裝目標附加至 `cachedTransform` 之下，並快取目標的所有 `Renderer`（結構 `RendererInfo` 包含 `renderer`、`materials`、`sortingOrder`，詳見 [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L27-L32)）。如此一來，一般 3D 內容即可納入 FairyGUI 的顯示列表與批次/排序體系。先前的 `supportStencil` 旗標已標記為 `[Obsolete]`，樣板緩衝區處理現已自動執行，無需手動設定。
