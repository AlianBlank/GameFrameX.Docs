# 如何为无人处理的事件设置默认处理器

调用 `EventComponent.SetDefaultHandler` 注册一个 `EventHandler<GameEventArgs>` 回调后,任何被 `Fire` / `FireNow` 抛出但没有订阅者的事件都会落入这个回调,而不是被静默丢弃——常用于打日志、报警或做漏网事件统计。

## 前置条件

- 场景中已存在挂载 `EventComponent` 组件的物体(事件功能已启用)。
- 已了解基本的事件订阅/抛出用法。

## 操作步骤

1. 编写一个签名为 `EventHandler<GameEventArgs>` 的回调方法,内部读取 `e.Id` 即可拿到事件编号:

```csharp
void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L145-L150)

2. 在初始化阶段(如 `Start` 或模块入口)调用 `SetDefaultHandler` 注册:

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L144-L145)

3. 抛出一个无人订阅的事件进行验证:

```csharp
// 快捷方式:不需要自定义事件参数,内部用 EmptyEventArgs.Create(eventId) 包装
eventComponent.Fire(this, "level_up");
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`Fire` 是线程安全的延迟分发——即使在工作线程抛出,回调也会在下一帧主线程执行;若希望默认处理器立即被调用,改用 `FireNow`(立即分发,仅限主线程)。

## 常见变体

| 需求 | 做法 |
|------|------|
| 替换默认处理器 | 再次调用 `SetDefaultHandler(newHandler)` 覆盖旧的回调 |
| 取消默认处理器 | 调用 `SetDefaultHandler(null)`,此后无人订阅的事件重新变为静默丢弃 |
| 带自定义参数的事件走兜底 | `eventComponent.Fire(this, LevelUpEventArgs.Create(5))`,回调中可把 `e` 向下转型为具体参数类型 |
| 排查是谁抛的事件 | 在回调内记录 `sender`(事件发送者)与 `e.Id` 一起上报 |

## 常见错误

- **回调签名不匹配**:`SetDefaultHandler` 只接受 `EventHandler<GameEventArgs>`,写成 `Action<string>` 或针对具体参数类型的处理器会编译失败。应先在具体处理器中处理已订阅事件,默认处理器统一收 `GameEventArgs`。
- **忘记默认处理器只兜底"无订阅者"的事件**:如果该 `Id` 已有任何订阅者,事件会正常分发给订阅者,不会进入默认处理器。不要把默认处理器当作全局事件监听器使用。
- **误用 `FireNow` 于工作线程**:`FireNow` 立即分发且非线程安全,在子线程调用会带来未定义行为;子线程请使用 `Fire`。
- **默认处理器内部抛异常**:回调在事件分发主流程中执行,异常会中断分发;回调内做好异常捕获。

## 背景

`EventComponent.SetDefaultHandler` 只是一层转发,内部调用 `m_EventManager.SetDefaultHandler(handler)`,后者再把回调交给底层事件池(`m_EventPool.SetDefaultHandler`)。分发时若某个事件编号没有匹配的处理器,事件池会转而调用默认处理器,从而实现"未处理事件兜底"。
