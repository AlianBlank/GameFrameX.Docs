# 엔티티, 코루틴, 사운드, 씬 및 Mono 관리 사용법

`GameFrameX`는 `GameApp` 정적 파사드를 통해 엔티티, 코루틴, 사운드, 씬, Mono 등 각 런타임 하위 시스템 컴포넌트를 지연 로딩 방식으로 노출합니다. 각 하위 시스템은 `GameEntry.GetComponent<T>()`로 가져오는 컴포넌트 인스턴스에 대응하며, 사용 시 코드에서 `GameApp.{하위시스템명}`에 접근하기만 하면 됩니다. 이 페이지에서는 이러한 하위 시스템의 연결 방식과 일반적인 사용법을 설명합니다.

## 사전 조건

1. `com.gameframex.unity.entry` 패키지가 설치되어 있고, 씬에 `GameEntry` 런처가 마운트되어 있어야 합니다.
2. Package Manager를 통해 각 하위 시스템에 해당하는 런타임 패키지를 설치했습니다:
   - `com.gameframex.unity.entity`(엔티티)
   - `com.gameframex.unity.coroutine`(코루틴)
   - `com.gameframex.unity.sound`(사운드)
   - `com.gameframex.unity.scene`(씬)
   - 내장 Mono 관리자는 entry 패키지와 함께 제공됩니다
3. 프로젝트에 해당 활성화 매크로가 정의되어 있습니다: `ENABLE_GAME_FRAME_X_ENTITY`, `ENABLE_GAME_FRAME_X_COROUTINE` 등(각 컴포넌트 소스 코드는 `#if`로 보호되며, 매크로가 없으면 관련 필드가 컴파일되지 않습니다. 아래 "자주 발생하는 오류" 참조).

## 작업 단계

### 1. GameApp을 통해 하위 시스템 접근

모든 하위 시스템은 `GameApp` 클래스에서 `public static {컴포넌트 클래스} {하위시스템명}` 형식으로 노출되며, 처음 접근할 때 `GameEntry.GetComponent<T>()`를 통해 생성되고 캐시됩니다. 수동으로 `new`하거나 등록할 필요가 없습니다.

```csharp
using GameFrameX.Runtime;

public static partial class GameApp
{
    public static EntityComponent Entity
    {
        get
        {
            if (_entity == null)
            {
                _entity = GameEntry.GetComponent<EntityComponent>();
            }
            return _entity;
        }
    }

    private static EntityComponent _entity;
}
```

Source: [Runtime/GameApp.Entity.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Entity.cs#L36-L55)

코루틴 컴포넌트도 완전히 동일한 패턴을 사용합니다:

```csharp
using GameFrameX.Runtime;
using GameFrameX.Coroutine.Runtime;

public static partial class GameApp
{
    public static CoroutineComponent Coroutine
    {
        get
        {
            if (_coroutine == null)
            {
                _coroutine = GameEntry.GetComponent<CoroutineComponent>();
            }
            return _coroutine;
        }
    }

    private static CoroutineComponent _coroutine;
}
```

Source: [Runtime/GameApp.Coroutine.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Coroutine.cs#L36-L55)

호출 예시:

```csharp
// 엔티티
var entityComponent = GameApp.Entity;

// 코루틴
var coroutineComponent = GameApp.Coroutine;
```

### 2. 엔티티(Entity) 사용 시 핵심 사항

`GameApp.Entity`로 `EntityComponent`를 가져온 후, 프레임워크에서 제공하는 엔티티 생성, 조회, 파괴 인터페이스를 사용할 수 있습니다. 엔티티의 라이프사이클은 `EntityComponent`가 통일적으로 관리하며, 일반적으로 `Entity` 기본 클래스 및 `EntityLogic` 로직 스크립트와 함께 사용됩니다. 자세한 인터페이스 시그니처는 `EntityComponent` 소스 코드를 기준으로 하며, 본 리포지토리에는 그 구현이 직접 포함되어 있지 않으므로 `com.gameframex.unity.entity` 패키지 내 문서를 참조해야 합니다.

### 3. 코루틴(Coroutine) 사용 시 핵심 사항

`GameApp.Coroutine`으로 `CoroutineComponent`를 가져와 모든 비 MonoBehaviour 컨텍스트에서 코루틴 작업을 시작할 수 있습니다. 코루틴 컴포넌트는 내부적으로 Unity의 `Coroutine` 메커니즘을 래핑하여, 비 Mono 클래스에서도 지연, 프레임 분할 작업을 안전하게 시작할 수 있습니다. 호출 진입점은 일반적으로 다음과 같은 형태입니다:

```csharp
GameApp.Coroutine.StartCoroutine(MyRoutine());

GameApp.Coroutine.StopCoroutine(handle);
```

구체적인 오버로드는 `CoroutineComponent` 소스 파일을 기준으로 합니다.

### 4. 사운드(Sound) 사용 시 핵심 사항

사운드 하위 시스템도 동일한 정적 파사드 진입점을 사용합니다. 리포지토리의 `Runtime/GameApp.Sound.cs`는 `#if` 가드를 통해 `GameApp.Sound`를 제공하며, `SoundComponent` 인스턴스를 반환합니다. 자주 사용하는 작업으로는 BGM 재생, 효과음 재생, 일시 정지/재개, 볼륨 설정 등이 있으며, 구체적인 API는 `SoundComponent` 구현을 기준으로 합니다.

```csharp
// 참고용 예시: 실제 시그니처는 SoundComponent 참조
GameApp.Sound.PlayMusic(musicId);
GameApp.Sound.PlaySound(soundId);
```

### 5. 씬(Scene) 사용 시 핵심 사항

`Runtime/GameApp.Scene.cs`도 마찬가지로 `GameApp.Scene`를 통해 `SceneComponent`를 노출합니다. 이 컴포넌트를 통해 씬을 로드 및 언로드하고, 현재 로드된 씬 리소스 정보를 가져올 수 있습니다. 일반적인 흐름: 씬 리소스 이름 전달 → 비동기 로드 트리거 → 로드 완료 후 마운트 및 활성 씬 전환.

```csharp
// 참고용 예시
GameApp.Scene.LoadScene("MainCity", onComplete: () => { /* 씬 진입 완료 */ });
```

### 6. Mono 관리 사용 시 핵심 사항

`Mono` 관리자는 비 MonoBehaviour 클래스에서 `Mono`와 유사한 기능(폴링, 코루틴, 타이머 등)을 얻기 위해 사용되며, `GameApp.Coroutine`과 함께 작동합니다. `GameApp`의 Mono 관련 속성을 통해 직접 가져올 수 있으며, 이후 `Update`/`OnDestroy` 등의 라이프사이클 훅을 호출할 때 `MonoBehaviour`를 상속할 필요가 없습니다.

## 일반적인 변형

- **크로스 플랫폼 트리밍**: 각 `GameApp.*.cs`는 `#if ENABLE_GAME_FRAME_X_{NAME}` 조건부 컴파일을 사용하므로, 프로젝트의 `csc.rsp` 또는 `Player Settings`에서 필요에 따라 하위 시스템을 활성화/비활성화할 수 있습니다. 비활성화하면 해당 `GameApp.{Name}` 필드가 사라집니다.
- **의존성 주입 확장**: 정적 파사드를 사용하고 싶지 않다면 `GameEntry.GetComponent<EntityComponent>()` 등을 직접 호출하여 원본 컴포넌트 참조를 가져올 수 있으며, 두 방식은 동등합니다.
- **일부 하위 시스템의 네이밍 차이**: 일부 버전에서는 `MonoManager`가 아닌 `Mono`로 명명되는 경우가 있으므로, 현재 런타임 패키지 버전의 소스 코드를 기준으로 하십시오.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GameApp.Entity` / `GameApp.Coroutine` 등의 속성이 존재하지 않음 | 해당 하위 시스템 패키지가 설치되지 않았거나 `ENABLE_GAME_FRAME_X_ENTITY` / `ENABLE_GAME_FRAME_X_COROUTINE` 등의 매크로가 정의되지 않음 | Package Manager에서 해당 패키지를 설치하고, 프로젝트의 `csc.rsp` 또는 `Scripting Define Symbols`에 매크로 정의를 추가 |
| 호출 시 `null` 반환 또는 NullReferenceException 발생 | 씬에 `GameEntry`가 마운트되지 않았거나, 하위 시스템이 `GameEntry`에 컴포넌트로 등록되지 않음 | 시작 씬에 `GameEntry` 프리팹을 추가하고 Inspector에서 대상 컴포넌트가 체크되어 있는지 확인 |
| 코루틴이 실행되지 않음 | `StartCoroutine` 호출 시 전달한 메서드가 `IEnumerator`를 반환하지 않거나, `Mono` 컨텍스트가 파괴된 후 호출됨 | 메서드 시그니처를 확인하고, 이미 파괴된 객체에서 코루틴을 시작하지 않도록 주의 |
| 사운드/씬 인터페이스를 찾을 수 없음 | 하위 시스템 패키지가 현재 entry 패키지와 일치하는 버전으로 업그레이드되지 않음 | 해당 런타임 패키지를 업그레이드하거나, 대상 버전의 `SoundComponent` / `SceneComponent` 실제 시그니처를 참조 |

## 배경(선택 사항)

`GameApp`는 `partial class`이며, 각 하위 시스템은 `Runtime/GameApp.{Name}.cs` 파일 하나에 대응하고, 각각 `#if`로 보호되어 서로 결합되어 있지 않습니다. 그 목적은 필요에 따라 패키지 크기를 줄이는 것입니다. 모든 컴포넌트는 `GameEntry.GetComponent<T>()`의 지연 로딩 패턴으로 가져오며, 처음 접근 시 `GameEntry`가 인스턴스화하여 `GameApp`의 private 정적 필드에 캐시하고, 이후 호출에서는 캐시된 값을 직접 반환합니다. 이를 통해 전역 유일성을 보장함과 동시에 모듈 로드 순서 문제도 방지할 수 있습니다.
