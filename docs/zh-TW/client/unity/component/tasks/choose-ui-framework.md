# 如何在 FairyGUI 與 UGUI 之間選擇與切換

GameFrameX 透過兩個獨立的 UI 適配套件同時支援 FairyGUI 和 UGUI,業務程式碼只需在產生階段選擇適配層，執行階段透過腳本巨集(`ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI`)隔離產物即可在同一專案中並存或切換。

## 前置條件

專案已透過 Unity Package Manager 引入下列套件(詳見 [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L36-L38)):

| 套件名稱 | 版本 | 用途 |
|------|------|------|
| `com.gameframex.unity.ui` | 2.11.0 | UI 基礎框架(開啟/關閉/事件) |
| `com.gameframex.unity.ui.fairygui` | 3.4.2 | FairyGUI 適配層 |
| `com.gameframex.unity.ui.ugui` | 2.6.0 | UGUI 適配層 |
| `com.gameframex.unity.fairygui.unity` | 5.3.4 | FairyGUI 編輯器執行階段 |
| `com.unity.ugui` | 1.0.0 | Unity 內建 UGUI |

> FairyGUI 相依套件 `FairyGUI` 由 `com.gameframex.unity.fairygui.unity` 提供，無需額外單獨安裝。

## 選擇建議

| 情境 | 建議方案 | 原因 |
|------|----------|------|
| 美術已用 FairyGUI 編輯器產出大量 `.fui` 資源 | FairyGUI | 直接沿用現有套件，欄位類型為 `GComponent` / `GTextField` 等 |
| 團隊熟悉 Unity 原生工作流程，使用 Prefab + Canvas | UGUI | 欄位類型為 `UnityEngine.UI.Text` / `InputField`,符合 Unity 直覺 |
| 需要兩套介面並存(例如主介面用 UGUI、活動彈出視窗用 FairyGUI) | 同時啟用 | 透過不同目錄下的產生程式碼隔離即可 |
| 從零開始、希望最快上手 | UGUI | 不依賴 FairyGUI 編輯器，直接拖曳 Prefab |

## 操作步驟：在編譯產物中選擇方案

1. 在 `Project Settings` → `Player` → `Scripting Define Symbols` 中加入(或移除)對應巨集：

   ```
   ENABLE_UI_FAIRYGUI   // 啟用 FairyGUI 適配
   ENABLE_UI_UGUI       // 啟用 UGUI 適配
   ```

2. FairyGUI 產生程式碼範例 —— 類別繼承 `FUI`,透過 `UIPackage.CreateObject` 建立：

   ```csharp
   // 來源:Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs
   #if ENABLE_UI_FAIRYGUI
   public sealed partial class UIAnnouncement : FUI
   {
       public const string UIPackageName = "UILogin";
       public const string UIResName     = "UIAnnouncement";
       public const string URL           = "ui://f011l0h9aneks9g";

       public GComponent self { get; private set; }
       public GTextField  m_TextTitle { get; private set; }
   }
   #endif
   ```

   Source: [UIAnnouncement.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs#L3-L29)

3. UGUI 產生程式碼範例 —— 類別繼承 `UGUI`,透過 `[SerializeField] [UGUIElementProperty]` 公開節點：

   ```csharp
   // 來源:Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs
   #if ENABLE_UI_UGUI
   [OptionUIConfig(null, "Assets/Bundles/UI/UILogin")]
   public sealed partial class UILogin : UGUI
   {
       [SerializeField] [UGUIElementProperty("UserName")]
       private UnityEngine.UI.InputField UserName;
       public UnityEngine.UI.InputField m_UserName => UserName;
   }
   #endif
   ```

   Source: [UILogin.UI.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs#L3-L46)

4. 執行 UI Launcher 時，框架會根據目前啟用的巨集自動找到對應的產生類別(`FUI` 或 `UGUI`)並開啟面板。無需在業務層硬編碼。

## 常見變體

- **兩套 UI 並存**：同時定義兩個巨集，FairyGUI 產物放在 `Assets/Hotfix/UI/FairyGUI/`,UGUI 產物放在 `Assets/Hotfix/UI/UGUI/`,框架按類別名稱比對。
- **執行階段動態切換**：不建議在同一建置包內透過巨集切換。若需 A/B 測試，改為產出兩個建置，各自只啟用一個巨集。
- **只保留一套**：刪除另一套目錄下的產生程式碼 + 移除對應巨集即可。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 開啟 UI 時擲回 `TypeInitializationException`,找不到類別 | 未在 `Scripting Define Symbols` 加入對應巨集，產生程式碼被 `#if` 整段剔除 | 加入 `ENABLE_UI_FAIRYGUI` 或 `ENABLE_UI_UGUI` |
| FairyGUI 套件載入失敗，資源顯示粉紅色 | 未安裝 `com.gameframex.unity.fairygui.unity` 或 FairyGUI 編輯器未匯出 | 重新匯入套件並確認 `.fui` 套件位址 `ui://...` 與 `UIPackageName` 一致 |
| UGUI 節點全部為 `null` | Prefab 路徑與 `[OptionUIConfig]` 中 `Assets/Bundles/UI/...` 不相符 | 重新產生 UI 程式碼，或在 `OptionUIConfig` 中修正路徑 |

## 驗證

1. 編譯專案，Console 不應出現 `TypeLoadException` / `MissingMethodException`。
2. 啟動後開啟任意一個範例面板(如 `UILogin`),能看到對應方案下的控制項。
3. 切換巨集後再次編譯，確認面板類型從 `FUI` 子類別變為 `UGUI` 子類別(或反之)。

## 背景(選用)

兩個適配套件提供相同語意的 `Open` / `Close` / `Show` 流程，差別只在節點綁定方式：FairyGUI 透過 `GObject` 反射套件內元件，UGUI 透過 `UGUIElementProperty` 特性反射 Prefab 上的 `GameObject`。業務程式碼只面向基底類別 `FUI` / `UGUI` 撰寫程式，不直接依賴欄位類型。
