# How to Understand the Naming Convention and Abbreviation Mapping (Component / FUI / GUI)

`GameApp` is the static facade class of Game Frame X, mapping `GameApp.{Name}` to `GameEntry.GetComponent<{Name}Component>()`. Understanding the naming rules allows you to directly access any built-in component via `GameApp.XXX` without consulting the documentation.

## Naming Mapping Rules

The vast majority of components follow the straightforward rule of "removing the `Component` suffix"; only `FUI` and `GUI` are abbreviation exceptions.

| GameApp Property | Equivalent Call | Type |
|---|---|---|
| `GameApp.Event` | `GameEntry.GetComponent<EventComponent>()` | Regular mapping |
| `GameApp.UI` | `GameEntry.GetComponent<UIComponent>()` | Regular mapping |
| `GameApp.Asset` | `GameEntry.GetComponent<AssetComponent>()` | Regular mapping |
| `GameApp.FUI` | `GameEntry.GetComponent<FairyGUIComponent>()` | Abbreviation exception (FUI=FairyGUI) |
| `GameApp.GUI` | `GameEntry.GetComponent<UGUIComponent>()` | Abbreviation exception (GUI=uGUI) |

## Abbreviation Exceptions Explained

`FUI` and `GUI` are historical abbreviations for two UI subsystems. They retain a compact capitalized form that is inconsistent with the "removing the `Component` suffix" rule, so pay special attention when using them:

- **FUI** → `FairyGUIComponent` (a UI component based on the FairyGUI solution; the fairygui dependency has been removed per [CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6))
- **GUI** → `UGUIComponent` (a UI component based on Unity's native UGUI, defined in `GameApp.GUI.cs` and controlled by the compilation macro `ENABLE_GAME_FRAME_X_L_UGUI`)

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
public static partial class GameApp
{
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }
            return _gui;
        }
    }
}
#endif
```

Source: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

## How to Use

Follow these steps to use the mapping in your own scripts:

1. **Confirm the name**: First look up `GameApp.{Name}` in the mapping table in [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L32-L38) to find the corresponding `*Component` type.
2. **Regular components**: Simply write `GameApp.Event`, `GameApp.UI`, `GameApp.Asset`, etc.
3. **UI components**: The UI subsystem comes in two variants; choose `GameApp.FUI` (FairyGUI) or `GameApp.GUI` (UGUI) depending on the engine solution.
4. **Enable the macro as needed**: `GameApp.GUI` only exists when the `ENABLE_GAME_FRAME_X_L_UGUI` compilation macro is enabled; `GameApp.FUI` depends on the FairyGUI package, and the property stops working once that dependency is removed.

```csharp
// Regular mapping examples
var evt = GameApp.Event;
var asset = GameApp.Asset;

// UI subsystems: choose one based on the engine solution
var fairygui = GameApp.FUI;   // FairyGUIComponent (requires the FairyGUI package)
var ugui = GameApp.GUI;       // UGUIComponent (requires the ENABLE_GAME_FRAME_X_L_UGUI macro)
```

## Common Errors

| Symptom | Cause | Fix |
|---|---|---|
| `GameApp.FUI` fails to compile as "undefined" or returns null | The fairygui dependency has been removed ([CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6)) | Switch to `GameApp.GUI` or install the FairyGUI package |
| `GameApp.GUI` is inaccessible | Missing the compilation macro `ENABLE_GAME_FRAME_X_L_UGUI` | Add the macro to Scripting Define Symbols in Player Settings |
| Mistakenly treating `GameApp.FUI` as `UIComponent` | `FUI` is `FairyGUIComponent`; `UI` is the actual `UIComponent` | Distinguish between the two UI subsystems: use `GameApp.UI` for general-purpose UI, and `GameApp.FUI`/`GameApp.GUI` for engine-specific UI |
| Misusing names like `GameApp.GameApp` | Property names are the component names with `Component` removed, not the original component names | Follow the "XxxComponent → Xxx" rule, e.g., `AssetComponent → Asset` |

## Background

`GameApp` is organized across multiple files as a C# `partial class`, with each component corresponding to a `GameApp.{Name}.cs` file. Internally, lazily-loaded static fields cache the result of the first call, and subsequent accesses return the cached value directly, avoiding repeated lookups. The `FUI` and `GUI` abbreviations are retained for compatibility with legacy code and to shorten UI call paths. If new code does not need to distinguish between engine solutions, prefer the general-purpose `GameApp.UI` (`UIComponent`).
