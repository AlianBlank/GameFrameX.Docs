# Purchase Failure and Result Code Quick Reference

When the purchase callback `OnPurchaseFailed` (or `OnQueryPurchasesResult` / `OnConsumePurchaseResult`) fires, `PaymentEventArgs.ResultCode` provides a `PaymentResultCode` enum value used to pinpoint the cause of the failure. This page summarizes all result codes, recommended handling for each, and how to correctly subscribe to the callbacks to obtain this information.

## Quick Diagnosis

| Symptom (ResultCode / Behavior) | Cause | Fix |
|------|------|------|
| `Success` | Purchase succeeded | Deliver the item in `OnPurchaseSuccess`; for one-time products, remember to call `ConsumePurchase` |
| `Failed` | Generic channel failure; see `ErrorMessage` for details | Print `ErrorMessage` and `PurchaseData`, then investigate based on the channel's error codes |
| `Cancelled` | User actively cancelled on the payment screen | Do not show an error prompt; handle it silently |
| `NetworkError` | Device network unavailable | Prompt the user to retry; call `Buy` again once the network recovers |
| `ServiceUnavailable` | Channel payment service unavailable (e.g., the store is not ready) | Use `IsReady()` to confirm the payment system is ready first, then retry later |
| `ItemAlreadyOwned` | Product already owned and not consumed (duplicate purchase of a one-time product) | Run `QueryPurchases` to retrieve the `PurchaseToken`, execute `ConsumePurchase`, then purchase again |
| `ItemNotOwned` | Attempted to consume a product that is not yet owned | Complete the purchase first; do not call `ConsumePurchase` with a non-existent `PurchaseToken` |
| `VerifyFailed` | Purchase verification failed (related to `isClientVerify` in `Init`) | In a server-side verification setup, set `isClientVerify` to `false`; check the server-side signature verification logic |
| `Unknown` | The channel returned an unmapped result | Rely on `ErrorMessage` and `PurchaseData` (raw JSON) for manual analysis |

The result codes are defined as follows, 9 in total:

```csharp
public enum PaymentResultCode
{
    Success,
    Failed,
    Cancelled,
    NetworkError,
    ServiceUnavailable,
    ItemAlreadyOwned,
    ItemNotOwned,
    VerifyFailed,
    Unknown,
}
```

## Getting the Complete Error Information

The callback parameter `PaymentEventArgs` carries the following fields; print all of them when troubleshooting:

| Field | Type | Description |
|------|------|------|
| `ProductId` | `string` | Product ID |
| `OrderId` | `string` | Order ID |
| `PurchaseToken` | `string` | Purchase token (used when consuming/querying) |
| `ResultCode` | `PaymentResultCode` | Payment result code |
| `ErrorMessage` | `string` | Error message |
| `PurchaseData` | `string` | Raw purchase data (JSON format) |
| `CustomData` | `string` | Custom data passed in at purchase time |

## Fix Steps

### Subscribe to the Purchase Failure Callback

The three result events (`OnPurchaseSuccess` / `OnPurchaseFailed` / `OnQueryPurchasesResult` / `OnConsumePurchaseResult`) are declared on `IPaymentManager`, and `PaymentComponent` forwards them to the internal `_paymentManager` via event wrappers:

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L42-L46)

Business-layer subscription example:

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseFailed += OnPurchaseFailed;

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    UnityEngine.Debug.LogError(
        $"[Payment] Failed ProductId={e.ProductId} ResultCode={e.ResultCode} " +
        $"ErrorMessage={e.ErrorMessage} PurchaseData={e.PurchaseData}");
}
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L19-L36)

### `ItemAlreadyOwned`: Retry After Consuming

If a one-time product (the consumable type of `PaymentProductType`) is delivered but not consumed, the next purchase will return this result code:

1. Call `QueryPurchases(PaymentProductType)` to query the purchase records;
2. Extract the `PurchaseToken` in the `OnQueryPurchasesResult` callback;
3. Call `ConsumePurchase(e.PurchaseToken)` to complete consumption;
4. Initiate `Buy(purchaseParams)` again.

Related signatures (defined in `IPaymentManager`, with abstract implementations in `BasePaymentManager`):

```csharp
void QueryPurchases(PaymentProductType productType);
void ConsumePurchase(string purchaseToken);
```

Sources: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L52-L63)

### `VerifyFailed`: Check the Verification Mode

The second parameter of `Init` determines the verification method:

```csharp
/// <param name="isClientVerify">Whether to perform client-side verification of a successful purchase. If strong online verification is used, this is not needed — set it to false to perform server-side verification</param>
void Init(bool isDebug = false, bool isClientVerify = false);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

Pass `false` when using server-side verification so that the server verifies the signature, avoiding false `VerifyFailed` reports caused by client-side verification failures.

### `ServiceUnavailable`: Confirm Readiness

Call `bool IsReady()` before purchasing; if not ready, the channel side has not finished initializing, and the purchase will fall into `ServiceUnavailable`. Additionally, `SetPredefinedProductIds` must be called before initialization; otherwise the preloaded cache will not take effect:

```csharp
void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

## Verification

- Trigger a cancelled purchase (tap Cancel in the sandbox environment) and confirm the callback receives `Cancelled` with no exception logs;
- Attempt to purchase an already-owned, unconsumed product again and confirm `ItemAlreadyOwned` is returned; after calling `ConsumePurchase`, the purchase can be completed normally;
- The `ErrorMessage` / `PurchaseData` printed in `OnPurchaseFailed` is complete and can be reconciled against the channel's backend console.

## Background

Each channel implementation inherits from `BasePaymentManager` and uniformly raises result events through the four protected methods such as `RaisePurchaseFailed`, so the `PaymentEventArgs` structure is consistent across all channel callbacks:

```csharp
protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}
```
