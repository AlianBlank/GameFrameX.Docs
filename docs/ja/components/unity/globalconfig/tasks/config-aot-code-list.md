# AOT コードリストの設定方法

`GlobalConfigComponent` 上で `AOTCodeList` フィールドを設定すると、フレームワークはそれをアセンブリリストとして解析し、hybridclr などのホット更新ソリューションが実行時にメタデータを補完するためにロードします。設定完了後、`AOTCodeLists` プロパティを通じて実際のアセンブリ配列を取得できます。

## 前提条件

- プロジェクトに `com.gameframex.unity.globalconfig` パッケージがインストールされていること。
- プロジェクトのシーンに `GlobalConfigComponent` がアタッチされた GameObject が存在すること（`GameFrameX` フレームワークのエントリーポイントによって自動的に作成されます）。

## 操作手順

1. Hierarchy 内で `GlobalConfigComponent` がアタッチされた GameObject を選択し、Inspector で **補足アセンブリリスト** フィールド（AOTCodeList）を見つけます。
2. そのフィールドに JSON 文字列を入力します。配列の各要素はロード対象の AOT アセンブリ名です（通常は `HybridCLR` の `AOTMetadataLoader` と組み合わせて使用します）。
3. コンパイル完了後、Inspector 下部の読み取り専用の **補足メタデータリスト** に解析されたアセンブリ配列が表示されます（setter がデシリアライズ時に設定します）。
4. 実行時のコードはその配列を直接読み取り、`RuntimeApi.LoadMetadataForAOTAssembly` に渡すことができます。

## フィールド対照

| Inspector 名 | フィールド名 | 型 | 読み書き | 役割 |
|----------------|--------|------|------|------|
| 補足アセンブリリスト | `m_aotCodeList` | `string` | 読み書き | JSON 文字列、ソース永続化のエントリ |
| 補足メタデータリスト | `m_aotCodeLists` | `List<string>` | 読み取り専用 | 解析後のアセンブリ名リスト |
| 生データ | `m_originalData` | `string` | 読み取り専用 | リモートから返された生のレスポンス |

フィールド定義は `GlobalConfigComponent` にあります:

```csharp
[SerializeField] private string m_aotCodeList = string.Empty;

[SerializeField] private List<string> m_aotCodeLists = new List<string>();

public List<string> AOTCodeLists
{
    get { return m_aotCodeLists; }
}

public string AOTCodeList
{
    get { return m_aotCodeList; }
    set
    {
        m_aotCodeList = value;
        try
        {
            m_aotCodeLists = Utility.Json.ToObject<List<string>>(value);
        }
        catch (Exception e)
        {
            Log.Error(e);
        }
    }
}
```

## 実行時の読み取り

`GlobalConfigComponent` シングルトンには `GameEntry` 経由でアクセスできます:

```csharp
var aotList = GameEntry.GlobalConfig.AOTCodeLists;
foreach (var asm in aotList)
{
    // hybridclr に渡す: RuntimeApi.LoadMetadataForAOTAssembly(...)
}
```

リモートインターフェース `ResponseGlobalInfo.AOTCodeList` も同様に JSON 文字列で、レスポンス受信後にコンポーネントに代入することができます。コンポーネントの setter が自動的にデシリアライズします:

```csharp
public class ResponseGlobalInfo
{
    public string CheckAppVersionUrl { get; set; }
    public string CheckResourceVersionUrl { get; set; }
    public string AOTCodeList { get; set; }
    public string Content { get; set; }
}
```

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `AOTCodeList` 設定後も `AOTCodeLists` が空のまま | JSON の形式が無効で、`Utility.Json.ToObject` が例外を投げ `Log.Error` に吸収されている | コンソールで `Log.Error` 出力を確認し、JSON を修正する（二重引用符、カンマ、角括弧に注意） |
| 実行モードで編集できない | Inspector がプレイ時に全体的に無効化されている | プレイモードを終了してから修正する |
| 変更後にリストが更新されない | setter は代入時にのみ解析するため、`m_aotCodeList` を直接変更しても再解析されない | `AOTCodeList` プロパティに再代入するか、Inspector を再起動する |

## 背景

`AOTCodeList` が文字列で `AOTCodeLists` が `List<string>` となっている設計は、シリアライズフィールドを基本型に保ち（Inspector 編集とネットワーク伝送を容易にする）、同時に実行時に JSON をデシリアライズして利用可能なリストにするためです。`m_aotCodeLists` フィールドは読み取り専用で、外部が setter を迂回して JSON 検証をバイパスすることを防ぎます。
