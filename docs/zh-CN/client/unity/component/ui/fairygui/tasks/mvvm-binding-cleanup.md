# MVVM 绑定与事件自动清理

在 FairyGUI 界面里使用 `BindableProperty<T>` 做数据绑定时,只需调用一个扩展方法 `ClearWithGObjectDestroyed`,即可把事件清理挂到 `GObject` 的 `onRemovedFromStage` 上——当 GObject 离开显示列表(含销毁)时自动执行 `bindableProperty.Clear`,不必再手写注销逻辑,避免事件残留与内存泄漏。

## 前置条件

- 已安装 `com.gameframex.unity.fairygui` 包(见 README 依赖表:`com.gameframex.unity` 1.1.1、`com.gameframex.unity.ui` 1.0.0 等)。
- `BindableProperty<T>` 来自 GameFrameX 核心包,命名空间为 `GameFrameX.Runtime`;扩展方法本身位于 `GameFrameX.UI.FairyGUI.Runtime`。
- 界面类继承自 `FUI`(它暴露 `GObject` 属性,见 [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L43-L53))。

## 操作步骤

1. 在界面/逻辑类中创建绑定属性,例如 `BindableProperty<int>`、`BindableProperty<string>` 等,并订阅其事件完成数据绑定。

2. 拿到与该界面生命周期一致的 `GObject` 后,调用扩展方法注册自动清理:

```csharp
// GObject 销毁时自动注销事件
myProperty.ClearWithGObjectDestroyed(gObject);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L123-L128)

3. 之后正常关闭/销毁界面即可,无需再手动反订阅绑定属性事件。

扩展方法的完整实现如下(整个机制只有一行注册):

```csharp
[UnityEngine.Scripting.Preserve]
public static void ClearWithGObjectDestroyed<T>(this BindableProperty<T> bindableProperty, GObject gObject)
{
    gObject.onRemovedFromStage.Add(bindableProperty.Clear);
}
```

Source: [BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L52-L56)

## 常见变体

- **在 FUI 子类中绑定**:继承 `FUI` 的界面可以直接用自身的 `GObject` 作为生命周期锚点,例如在绑定初始化处调用 `myProperty.ClearWithGObjectDestroyed(GObject);`,界面销毁时事件随之清空。
- **泛型任意**:该方法是泛型扩展,`BindableProperty<int>`、`BindableProperty<string>` 等任意 `T` 都可直接调用,无需为每种类型单独写清理代码。

## 常见错误

| 症状 | 原因 | 规避方法 |
|------|------|----------|
| 界面销毁后绑定事件仍被触发、对象无法回收 | 忘记调用 `ClearWithGObjectDestroyed`,订阅残留在绑定属性上 | 每次订阅绑定属性事件后,立即用同一 GObject 调用一次该扩展方法 |
| `NullReferenceException` | 传入的 `gObject` 为 null(界面尚未创建 GObject 就调用) | 确保在 GObject 初始化完成后再调用;`FUI.Visible` 的实现也表明 `GObject` 可能为 null([FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L135-L149)) |
| 事件在"看起来还没销毁"时被清空 | 触发钩子是 `onRemovedFromStage`(离开显示列表),而不仅仅是销毁;任何把对象移出显示列表的操作都会触发 `Clear` | 若会把 GObject 动态从显示列表移除又复用,请在重新加入显示列表后重新绑定并再次调用本方法 |

## 验证

- 关闭界面后修改绑定属性的值,确认不再有任何 UI 回调被触发。
- 在 `Clear` 生效前后用内存分析器(如 Unity Memory Profiler)对比,确认界面相关对象可被回收。

## 背景

该机制刻意做得极简:利用 FairyGUI `GObject.onRemovedFromStage` 事件,把 `BindableProperty.Clear` 作为回调注册进去([BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L55))。绑定属性本身属于 GameFrameX 核心包(`GameFrameX.Runtime` 命名空间),UI 层只负责在其与 GObject 生命周期之间建立"销毁即清理"的关联。方法上标注了 `[UnityEngine.Scripting.Preserve]` 以防代码裁剪移除。
