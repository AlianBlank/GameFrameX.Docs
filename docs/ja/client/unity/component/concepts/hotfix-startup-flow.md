# 仕組み：Hotfix エントリと起動フロー

Hotfix の起動はフレームワーク内の [`HotfixHelper`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs) が担当します。これはランタイム時に AOT DLL と Hotfix DLL を読み込み、規定されたエントリ型とメソッドを特定し、リフレクションを通じて Hotfix コードの初期化をトリガーします。アプリケーション層は [`ApplicationHotfixLauncher`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs) を介して、このロジックを起動パイプラインの `IHotfixLauncher` インターフェースに適合させます。

## 起動エントリ一覧

| エントリ | 型 | 役割 |
|------|------|------|
| `HotfixHelper.StartHotfix()` | `async void` | デフォルトオプションでトリガーし、戻り値を破棄 |
| `HotfixHelper.StartHotfixAsync(StartupOptions)` | `async UniTask<HotfixLaunchResult>` | 非同期で読み込み、起動結果を返す |
| `ApplicationHotfixLauncher.StartAsync(StartupOptions)` | `UniTask<HotfixLaunchResult>` | `IHotfixLauncher` アダプター。`HotfixHelper.StartHotfixAsync` に転送 |

デフォルトパラメータ（`options == null` またはフィールドが空の場合に有効）：

| フィールド | デフォルト値 |
|------|--------|
| `HotfixAssemblyName` | `Unity.Hotfix` |
| `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` |
| `HotfixEntryMethodName` | `Main` |

## 起動手順

1. `HotfixHelper.StartHotfixAsync(options)` を呼び出すと、メソッドは `try/catch` で囲まれた内部実装 `StartHotfixInternalAsync` に入ります。
2. 最終的な `assemblyName` / `entryTypeName` / `entryMethodName` を解決します。欠損値のデフォルトはそれぞれ `Unity.Hotfix`、`Hotfix.HotfixLauncher`、`Main` です。
3. マクロ `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR` に応じて読み込みパスを選択します：
   - **HybridCLR 有効（かつ Editor 以外）**：`AOTGenericReferences.PatchedAOTAssemblyList` をイテレートし、各 AOT DLL を `GameApp.Asset.LoadAssetAsync<UnityEngine.Object>` で読み込み、`RuntimeApi.LoadMetadataForAOTAssembly` を呼び出します。その後、`Unity.Hotfix.dll` を読み込み `Assembly.Load` を実行します。
   - **Editor または HybridCLR 無効**：直接 `RunNative` に進み、`Utility.Assembly.GetType` でリフレクション呼び出しを行います。
4. リフレクションがターゲットの型とメソッドを見つけたら `method.Invoke(null, null)` を実行し、Hotfix 層が制御を取得します。
5. 成功時は `HotfixLaunchResult.Succeed()` を返します。例外が発生した場合は `Log.Error` で記録し、`HotfixLaunchResult.Fail(e.Message)` を返します。

重要なコード：

```csharp
public static async void StartHotfix()
{
    await StartHotfixAsync(null);
}
```

```csharp
public static async UniTask<HotfixLaunchResult> StartHotfixAsync(StartupOptions options)
{
    try
    {
        await StartHotfixInternalAsync(options);
        return HotfixLaunchResult.Succeed();
    }
    catch (Exception e)
    {
        Log.Error(e);
        return HotfixLaunchResult.Fail(e.Message);
    }
}
```

アプリケーション層のアダプターが同じフローを起動パイプラインに接続します：

public sealed class ApplicationHotfixLauncher : IHotfixLauncher

    public UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)

    }
}

## 重要な読み込みパス

| 段階 | 呼び出し | 説明 |
|------|------|------|
| AOT メタデータ読み込み | `RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet)` | HybridCLR モードでは、すべての AOT DLL を事前に読み込む必要があります。そうしないと Hotfix コードの汎用共有が失敗します |
| Hotfix DLL 読み込み | `Assembly.Load(assemblyDataHotfixDll, null)` | バイト配列をランタイムアセンブリとして読み込みます |
| エントリのリフレクション | `assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | リフレクションで引数なしの静的エントリを呼び出します |
| ネイティブフォールバック | `Utility.Assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | HybridCLR 以外のモードでは、読み込まれた AppDomain からエントリ型を検索します |

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `entryType` が `null` で、リフレクション時に `NullReferenceException` が発生 | 渡された `HotfixEntryTypeName` が DLL 内の型と一致しない、または `Unity.Hotfix.dll` がリソースにパッケージされていない | `options.HotfixEntryTypeName` が DLL の名前空間/クラス名と完全に一致していることを確認し、`Utility.Asset.Path.GetCodePath("Unity.Hotfix.dll")` がリソースに解決できるかをチェック |
| 汎用メソッド呼び出しで `MissingMethodException` または `TypeLoadException` が発生 | HybridCLR モードで `AOTGenericReferences.PatchedAOTAssemblyList` 内の AOT DLL が読み込まれていない | `ENABLE_GAME_FRAME_X_HYBRID_CLR` マクロが有効かを確認し、`AOTGenericReferences` が生成され、パッケージに含まれていることを確認 |
| Editor で `Unity.Hotfix` アセンブリが読み込めない | `StartHotfixInternalAsync` が Editor で `Utility.Assembly.GetAssemblies()` をイテレートし、大文字小文字を区別する名前に一致しない | `StartupOptions.HotfixAssemblyName` に正しい名前を明示的に渡すか、アセンブリ名 `Unity.Hotfix` が DLL と一致していることを確認 |
| `StartHotfix()` が例外をスローしてもエラーのコールバックがない | `StartHotfix` は `async void` であり、例外はログに書き込まれるだけ | 代わりに `StartHotfixAsync(options)` を使用して `HotfixLaunchResult` を受け取り、`Succeed` / `Fail` フィールドを確認する |
