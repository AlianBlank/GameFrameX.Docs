# 호출해도 반응 없음: 파라미터 빈 값 경고 빠른 조회

구매, 소비 등의 인터페이스를 호출한 후 "아무런 반응이 없을 때"(결제창이 뜨지 않음, 이벤트가 트리거되지 않음)는 보통 전달된 파라미터가 비어 있거나 null이기 때문입니다. `PaymentComponent`는 진입점에서 이를 차단하고 Warning 로그 하나만 출력한 후 바로 `return`하므로, 요청 자체가 전송되지 않습니다. 아래 표에서 로그에 해당하는 경고 원문을 찾으면 어떤 파라미터가 전달되지 않았는지 파악할 수 있습니다.

## 빠른 진단

| 증상(로그 원문) | 트리거 위치/원인 | 수정 |
|------|------|------|
| `Product ID is null or empty.` | `Buy` / `BuyInApp` / `BuySubs` 호출 시 `productId`(또는 `PurchaseParams.ProductId`)가 null 또는 빈 문자열 | 스토어 백오피스에 구성된 실제 상품 ID/SKU를 전달, 아래 "수정 단계 1" 참조 |
| `Order ID is null or empty.` | `Buy` / `BuyInApp` / `BuySubs` 호출 시 `orderId`(또는 `PurchaseParams.OrderId`)가 null 또는 빈 문자열 | 먼저 자체 서버에서 주문 번호를 생성한 후 구매를 시작, "수정 단계 2" 참조 |
| `Purchase token is null or empty.` | `ConsumePurchase(purchaseToken)` 호출 시 구매 토큰이 비어 있음 | `OnQueryPurchasesResult` / `OnPurchaseSuccess` 이벤트 파라미터에서 실제 `PurchaseToken`을 꺼낸 후 소비, "수정 단계 3" 참조 |
| `Purchase params is null.` | `Buy(PurchaseParams)` 호출 시 파라미터 객체 전체가 null | `PurchaseParams` 하위 클래스로 생성하고 값을 할당한 후 전달, "수정 단계 2" 참조 |
| `Pay Manager is invalid.`(Fatal) | `Awake`에서 `GameFrameworkEntry.GetModule<IPaymentManager>()`가 null을 반환, 플랫폼 구현 클래스가 올바르게 로드되지 않음 | `PaymentComponent` Inspector의 플랫폼 컴포넌트 타입 필드와 해당 채널 패키지가 도입되었는지 확인, "수정 단계 4" 참조 |

위 경고는 모두 `Log.Warning` 후 즉시 `return`하며, 예외를 throw하지 않고 `OnPurchaseFailed`도 트리거하지 않습니다 —— 따라서 증상이 "호출해도 반응 없음"으로 나타납니다. 출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L259).

## 수정 단계

### 1. Product ID가 비어 있을 때

상품 ID는 스토어 백오피스에 구성된 SKU와 완전히 일치해야 합니다(대소문자 구분, 앞뒤 공백 주의). `PurchaseParams` 하위 클래스로 생성하는 것을 권장합니다:

```csharp
// ProductId는 생성 후에도 여전히 검증되며, 비어 있으면 동일하게 Warning을 출력하고 바로 return함
var param = new SomeChannelPurchaseParams(productId: "coin_pack_100", orderId: orderNo, productType: PaymentProductType.InApp);
paymentComponent.Buy(param);
```

출처: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

점검 포인트:

- 설정 테이블/서버에서 상품 ID를 읽어오는 경우, 먼저 실제 값을 출력하여 비어 있지 않은지 확인: `Debug.Log($"[{productId}]");`
- `offerToken`, `customData` 같은 "선택적 기본 파라미터"의 위치를 잘못 전달하지 않았는지 확인.
- `Buy(PurchaseParams)`의 검증 순서는: 파라미터 객체 null → `ProductId` 빈 값 → `OrderId` 빈 값. 로그에서 어느 것이 먼저 출력되는지 보면 위치를 파악할 수 있습니다.

### 2. Order ID가 비어 있거나 파라미터 객체가 null일 때

`OrderId`는 자체 서버의 주문 번호로, 구매 검증에 사용되므로 비어 있으면 안 됩니다. `PurchaseParams`는 추상 기반 클래스(`public abstract class PurchaseParams`)이므로 직접 `new`할 수 없으며, 각 채널의 하위 클래스를 사용해야 합니다; 세 필드(`ProductId`, `OrderId`, `ProductType`)는 생성자를 통해 값을 할당합니다:

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

출처: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

흔히 겪는 함정:

- 주문 번호가 비동기 인터페이스로 생성되는데, 콜백 전에 구매 버튼이 이미 눌림 —— 콜백 안에서 구매 버튼을 활성화하세요.
- 구버전 인터페이스 `BuyInApp` / `BuySubs` / `Buy(string, PaymentProductType, ...)`에는 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`가 표시되어 있지만, 검증 동작은 동일하므로 마이그레이션 시에도 `productId`, `orderId`가 비어 있지 않도록 해야 합니다.

### 3. Purchase token이 비어 있을 때(구매 소비가 반응 없음)

`ConsumePurchase`는 비어 있지 않은 `purchaseToken`만 받습니다:

```csharp
public void ConsumePurchase(string purchaseToken)
{
    if (string.IsNullOrEmpty(purchaseToken))
    {
        Log.Warning("Purchase token is null or empty.");
        return;
    }

    _paymentManager.ConsumePurchase(purchaseToken);
}
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L152)

올바른 방법은 `OnPurchaseSuccess` 또는 `OnQueryPurchasesResult` 이벤트를 구독하고, `PaymentEventArgs`에서 실제 토큰을 받은 후 소비를 호출하는 것입니다.

### 4. Pay Manager is invalid(Fatal)

`PaymentComponent.Awake`는 플랫폼에 따라 구현 클래스 타입(`m_componentAndroidType`, `m_componentIOSType`, `m_componentWebGLType`, `m_componentPCType`, `m_componentMacType`)을 선택하며, 나머지 플랫폼은 `DefaultPaymentManager`로 폴백합니다. `GetModule<IPaymentManager>()`가 null을 반환하면 `Log.Fatal("Pay Manager is invalid.")`를 출력합니다. 확인 사항:

- Inspector의 플랫폼 타입 문자열이 손상되지 않았는지 확인(기본값 예: `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`);
- 해당 채널 패키지가 프로젝트에 임포트되었는지 확인(타입이 존재하지 않으면 `Utility.Assembly.GetType` 해석이 실패함);
- 현재 실행 플랫폼이 특정 `UNITY_*` 분기에 포함되는지 확인. 그렇지 않으면 `DefaultPaymentManager` 빈 구현으로 진행되어 결제 자체도 반응이 없습니다.

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 검증

- 호출을 시작하기 전에 Unity Console에서 Warning을 필터링하여, 위 표의 로그가 더 이상 나타나지 않는지 확인합니다.
- 파라미터가 유효하면 호출은 `_paymentManager.Buy(...)` / `ConsumePurchase(...)`까지 계속 진행되며, 이후 `OnPurchaseSuccess` / `OnPurchaseFailed` 이벤트를 구독하여 결제 체인이 실제로 트리거되었는지 확인할 수 있습니다(이벤트는 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64)에서 전달됨).
- `IsReady()`로 결제 시스템이 준비되었는지 확인한 후 구매 진입점을 표시하면, 다수의 "반응 없음"류 오탐을 피할 수 있습니다.
