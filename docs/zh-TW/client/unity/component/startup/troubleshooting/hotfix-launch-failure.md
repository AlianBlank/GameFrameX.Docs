# 熱修復啟動返回失敗時該怎麼辦

本頁面涵蓋的情況包括:`IHotfixLauncher.StartAsync` 返回的 `HotfixLaunchResult` 標記為失敗，或啟動流程在 `ProcedureGameLauncherState` 中觸發 `StartupFailedEventArgs`。

## 快速診斷

| 症狀 | 原因 | 修正 |
|------|------|------|
| `HotfixLaunchResult.IsSuccess == false`,日誌顯示找不到組件 | `StartupOptions.HotfixAssemblyName` 與實際編譯產物不一致 | 檢查 Inspector 欄位值，並確保與建置腳本輸出的 dll 一致 |
| `HotfixLaunchResult.IsSuccess == false`,日誌顯示找不到進入點類型 | `HotfixEntryTypeName` 拼字或命名空間錯誤 | 確認類型完整名稱(含命名空間)，並與 dll 反編譯結果比對 |
| 收到 `StartupFailedEventArgs`,結果為 `FailedProcedureName == "ProcedureGameLauncherState"` | 熱修復啟動器擲出例外或返回失敗 | 在 `IHotfixLauncher` 實作中使用 try/catch,並在填入 `ErrorMessage` 後返回失敗結果 |
| 流程在 `ProcedureGameLauncherState` 停滯，無法繼續 | `IHotfixLauncher` 未注入至 BlackBoard | 在呼叫 `StartupRunner` 之前執行 `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, ...)` |
| 收到 `StartupFailedEventArgs`,但 `ErrorMessage` 為空字串 | 業務實作未依規約填入 `ErrorMessage` | 啟動器失敗時明確指派 `HotfixLaunchResult.ErrorMessage` |

關於 `HotfixLaunchResult` 與 `StartupFailedEventArgs` 的欄位定義，請參閱下方參考表。

## 修正步驟

### 1. 確認 StartupOptions 設定

熱修復進入點三要素(組件名稱 / 進入點類型完整名稱 / 進入點方法名稱)透過 `StartupOptions` 注入，只要有任一項目不一致，`StartAsync` 即會返回失敗：

```csharp
// StartupOptions.cs 的預設值
public string HotfixAssemblyName = "Unity.Hotfix";
public string HotfixEntryTypeName = "Hotfix.HotfixLauncher";
public string HotfixEntryMethodName = "Run"; // 請參照 StartupOptions.cs 的欄位宣告
```

請確認 `StartupOptions` 資產中這三個項目的值，與熱修復專案的編譯輸出及 IL2CPP/HybridCLR 載入清單一致。來源:[StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L33-L40)

### 2. 訂閱 StartupFailedEventArgs

訂閱啟動失敗事件，以便將 `ProcedureGameLauncherState` 中發生的失敗訊息顯示給玩家：

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(StartupFailedEventArgs.EventId, e =>
{
    var args = (StartupFailedEventArgs)e;
    // args.FailedProcedureName / args.FailedUrl / args.ErrorMessage
});
```

事件觸發位置統一由 `StartupProcedureUtility.NotifyFailure` 呼叫，除了 UI 提示文字之外，還會再觸發一次 `StartupFailedEventArgs`。來源:[StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L160-L170),[StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L40-L60)

### 3. 確保 IHotfixLauncher 實作返回結構化的失敗結果

`IHotfixLauncher` 合約規定：**無論成功或失敗都必須返回 `HotfixLaunchResult`,且不得擲出例外**。實作端必須攔截所有例外，並將其放入 `ErrorMessage`:

```csharp
public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    try
    {
        // 載入 + 透過反射呼叫進入點方法
        return HotfixLaunchResult.Success();
    }
    catch (Exception ex)
    {
        return HotfixLaunchResult.Failure(ex.Message);
    }
}
```

來源:[IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L8-L16),[HotfixLaunchResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/HotfixLaunchResult.cs#L1-L40)

### 4. 確認 IHotfixLauncher 已注入 BlackBoard

`ProcedureGameLauncherState` 透過 FSM BlackBoard 讀取 `IHotfixLauncher`。若缺少注入，流程將停滯於該 Procedure。注入規約如下：

```csharp
// 定義於 BlackBoardKeys 的常數
public const string StartupHotfixLauncher = "__startup_hotfix_launcher__";
```

啟動器在建立 FSM 時，必須呼叫 `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, hotfixLauncher)`。來源:[BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs#L19-L23),[StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L80-L100)

## 參考：相關類型欄位

| 類型 | 欄位 / 成員 | 說明 |
|------|-------------|------|
| `IHotfixLauncher.StartAsync(StartupOptions)` | 返回 `UniTask<HotfixLaunchResult>` | 熱修復載入進入點，成功/失敗均返回結果且不擲出例外 |
| `HotfixLaunchResult.IsSuccess` | `bool` | true 表示載入及啟動成功 |
| `HotfixLaunchResult.ErrorMessage` | `string` | 失敗時的錯誤說明，成功時應為空 |
| `HotfixLaunchResult.Success()` / `.Failure(msg)` | 靜態工廠 | 產生成功或失敗結果 |
| `StartupFailedEventArgs.EventId` | `string` | 完整名稱 `"GameFrameX.Startup.Runtime.Events.StartupFailedEventArgs"` |
| `StartupFailedEventArgs.Create(procedureName, url, errorMessage)` | 靜態方法 | 由 `StartupProcedureUtility` 觸發，應於失敗的 Procedure 內呼叫 |
| `BlackBoardKeys.StartupHotfixLauncher` | `string` | 在 FSM 中儲存 `IHotfixLauncher` 實例的 key |

## 驗證

完成上述修正後，請逐項確認：

1. `HotfixLaunchResult.IsSuccess == true` 且 `ErrorMessage` 為空。
2. 不再觸發 `StartupFailedEventArgs`(或 `FailedProcedureName` 變更為其他故障點，不再是 `ProcedureGameLauncherState`)。
3. 後續流程進入遊戲主場景，且 `StartupCompletedEventArgs` 正常觸發。
