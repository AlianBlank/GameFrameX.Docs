# 如何加载并使用配置表(配置中心)

本页讲解如何在 GameFrameX.Unity 中加载并使用由 LuBan 工具生成、托管在 `Hotfix.Config` 程序集下的配置表数据。配置表以 `TbXxxConfig` 形式提供,通过 `TablesComponent` 统一初始化后,即可按 `Id` 或字符串键查询条目。

## 前置条件

- 已通过 LuBan 编辑器扩展生成配置表代码(默认输出目录 `Assets/Hotfix/Config/Generate/`)。
- 项目中已引入 `GameFrameX.Config.Runtime` 与 `SimpleJSON` 运行时依赖。
- 业务侧约定配置表的资源加载方式(本地 StreamingAssets / 远程 CDN),并提供 `Func<Task<JSONNode>>` 给到 `TbXxxConfig` 构造函数。

## 操作步骤

1. 确认配置表的实体类与表类已生成。每张表对应两个文件:实体类 `XxxConfig`(字段 + 构造 + `Deserialize`)与表类 `TbXxxConfig`(继承 `BaseDataTable<XxxConfig>`)。

   示例:`AchievementConfig` 实体类定义在 [AchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L16-L50),表容器在 [TbAchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L60)。`TbAchievementConfig` 继承 `BaseDataTable<Tables.AchievementConfig>`,并通过构造函数注入 `_loadFunc`。

   ```csharp
   // Source: Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L38
   public partial class TbAchievementConfig : BaseDataTable<Tables.AchievementConfig>
   {
       private readonly System.Func<System.Threading.Tasks.Task<JSONNode>> _loadFunc;
       public TbAchievementConfig(System.Func<System.Threading.Tasks.Task<JSONNode>> loadFunc)
       {
           _loadFunc = loadFunc;
       }
       public override async System.Threading.Tasks.Task LoadAsync()
       {
           var jsonNode = await _loadFunc();
           StringDataMaps.Clear();
           DataList.Clear();
           foreach(var _ele in jsonNode.Children)
           {
               Tables.AchievementConfig _v;
               { if(!_ele.IsObject) { throw new SerializationException(); }
                 _v = Tables.AchievementConfig.DeserializeAchievementConfig(_ele); }
               DataList.Add(_v);
               LongDataMaps.Add(_v.Id, _v);
               StringDataMaps.Add(_v.Id.ToString(), _v);
           }
           PostInit();
       }
   }
   ```

2. 为每张表提供 `loadFunc`,内部从本地/远程资源读取 JSON,反序列化为 `JSONNode`。

   ```csharp
   // loadFunc 示例:从 StreamingAssets 异步读取并解析 JSON
   Func<Task<JSONNode>> loadAchievement = async () =>
   {
       var text = await File.ReadAllTextAsync(
           Path.Combine(Application.streamingAssetsPath, "AchievementConfig.json"));
       return JSON.Parse(text);
   };

   var tbAchievement = new TbAchievementConfig(loadAchievement);
   await tbAchievement.LoadAsync();
   ```

3. 把所有 `TbXxxConfig` 注册到 `TablesComponent`,由其统一管理加载、跨表引用解析(`ResolveRef`)与多语言键翻译(`TranslateText`)。

   ```csharp
   // 把表实例加入 TablesComponent 并执行初始化
   var tables = new TablesComponent();
   tables.Add(tbAchievement);   // 其他 TbXxxConfig 同理
   await tables.InitAsync();    // 内部按依赖顺序调用各表 LoadAsync + ResolveRef
   ```

4. 在业务代码中按 `Id` 或键查询数据。`BaseDataTable<T>` 提供 `LongDataMaps`、`StringDataMaps` 与 `DataList` 三个集合,直接通过键读取即可。

   ```csharp
   // 实体类暴露的字段示例(只读属性)
   // Source: Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L51-L80
   var row = tables.Achievement.Get(1001);   // LongDataMaps["1001"]
   var nameKey = row.Name;                   // 多语言 Key
   var conditions = row.AchievementUnlockCondition;  // List<int>
   ```

5. 处理跨表引用与多语言:在所有表 `LoadAsync` 完成后,调用 `ResolveRef(tables)` 让条目解析其他表的引用;再调用 `TranslateText(translator)` 完成 `xxx_Localization_Key` 的本地化。

   ```csharp
   // Source: TbAchievementConfig.cs#L40-L54
   tbAchievement.ResolveRef(tables);
   tbAchievement.TranslateText((key, defaultText) => Localization.Get(key) ?? defaultText);
   ```

## 常见变体

- **本地资源 vs 远程资源**:`loadFunc` 内可分别实现 `Application.streamingAssetsPath` 读取或 `UnityWebRequest.Get` 下载,只要最终返回 `JSONNode` 即可。
- **多语言键**:`AchievementConfig` 在构造时会把多语言字段复制到 `Name_Localization_Key`、`AchievementContent_Localization_Key`、`LockText_Localization_Key`,通过 `TranslateText` 回调替换。
- **扩展类型映射**:枚举与外部类型可在 [ExternalTypeUtil.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Extension/ExternalTypeUtil.cs) 中登记,供 LuBan 反序列化时引用。

## 常见错误

- **JSON 字段类型不匹配**:`Deserialize` 会在类型不符时抛出 `SerializationException`(`AchievementConfig.cs` 第 31-36 行的断言)。检查 Excel/JSON 导出脚本与实体类字段类型是否一致。
- **忘记调用 `ResolveRef`**:跨表引用字段会保持默认/空值,务必在所有表 `LoadAsync` 完成后再调用。
- **重复 `LoadAsync`**:未先 `Clear()` 会导致 `LongDataMaps`/`StringDataMaps` 重复键,生成代码已在开头调用 `Clear()`,但手动复用 `loadFunc` 时仍需注意。
- **直接修改生成文件**:`XxxConfig.cs` 与 `TbXxxConfig.cs` 顶部都有 `<auto-generated>` 标记,改动会在下次生成时被覆盖,自定义逻辑应放到 `partial` 的另一部分文件中。

## 背景(可选)

LuBan 是与 GameFrameX 配套的 Excel→JSON→C# 代码生成工具:Excel 定义表结构,工具产出 JSON 数据文件与上面这种 `BeanBase` / `BaseDataTable<T>` 形式的实体+容器代码。`TablesComponent` 充当配置中心,在启动阶段统一加载、解析引用,并按需触发本地化,使业务侧只面向强类型对象编程。
