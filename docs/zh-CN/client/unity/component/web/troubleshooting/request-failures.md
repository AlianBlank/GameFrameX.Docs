# 请求失败或超时怎么办

请求失败或超时时,`WebManager` 会把异常抛回 `await` 调用处:超时表现为 `TimeoutException`,其余表现为 `WebException` 或 `IOException`。最常见的原因是超时时间过短(默认仅 5 秒)、并发请求超过上限在队列中排队,以及服务端/网络本身的问题。

## 快速诊断

| 症状(异常/现象) | 原因 | 修复 |
|------|------|------|
| `TimeoutException`,消息来自 `WebException` | 请求耗时超过 `Timeout`(默认 5 秒) | [调大超时时间](#1-调大超时时间) |
| 请求迟迟不发出、整体变慢 | 同时进行的请求超过 `MaxConnectionPerServer`(默认 8),多余请求在 `m_WaitingNormalQueue` 排队 | [提高并发上限](#2-提高并发上限) |
| `WebException`(Status 非 Timeout) | HTTP 协议错误(404/500)、DNS 解析失败、连接被拒绝 | 核对 URL 与服务端状态,开启日志查看响应 |
| `IOException` | 读取响应流时连接中断(网络波动、服务端提前断开) | 检查网络后重试 |
| 控制台看不到请求/响应内容 | 未开启日志编译宏 | [开启收发日志](#3-开启收发日志定位问题) |
| HTTPS 证书报错 | 证书校验失败 | WebGL/`UnityWebRequest` 路径已由 `DefaultBypassCertificate` 绕过;非 WebGL 平台检查系统时间与证书链 |

## 修复步骤

### 1. 调大超时时间

`WebManager` 构造时默认 `Timeout = 5f`(秒),并发上限默认 8。如果你的接口响应较慢(如上传大文件、弱网环境),先调大超时:

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// 获取或设置超时时间(秒)
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L43-L60)

在自己的代码里设置(两种方式等价,`Timeout` 会同步更新 `RequestTimeout`):

```csharp
webManager.Timeout = 30f;
// 或
webManager.RequestTimeout = TimeSpan.FromSeconds(60);
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L236-L237)

设置后,底层两条请求路径都会生效:WebGL 走 `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds`([WebManager.cs L218](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L218)、[WebManager.Binary.cs L97](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L97)),非 WebGL 走 `request.Timeout = (int)RequestTimeout.TotalMilliseconds`([WebManager.cs L259](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L259)、[WebManager.Binary.cs L131](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L131))。

### 2. 提高并发上限

`WebManager.Update` 每帧只在上送列表小于 `MaxConnectionPerServer` 时才出队一个等待请求,超出并发的请求会一直排在 `m_WaitingNormalQueue` 里,表现为"卡住不发出":

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    lock (m_StringBuilder)
    {
        if (m_SendingNormalList.Count < MaxConnectionPerServer)
        {
            if (m_WaitingNormalQueue.Count > 0)
            {
                var webJsonData = m_WaitingNormalQueue.Dequeue();

                if (webJsonData.UniTaskCompletionStringSource != null)
                {
                    MakeJsonStringRequest(webJsonData);
                }
                else
                {
                    MakeJsonBytesRequest(webJsonData);
                }

                m_SendingNormalList.Add(webJsonData);
            }
        }

        UpdateBinary(elapseSeconds, realElapseSeconds);
    }
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L75-L101)

需要更高并发时设置:

```csharp
webManager.MaxConnectionPerServer = 16;
```

属性定义见 [WebManager.cs L65](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L65)。

### 3. 开启收发日志定位问题

发送与响应日志受编译宏控制,包内提供了 `WebLogScriptingDefineSymbols` 用于切换。开启后可以看到实际请求的 URL、Header、Form 与响应内容(或异常消息):

```csharp
#if ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
    Log.Debug($"Web Response: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)} \n Content: {content}");
#endif
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L286-L288)

可用编译宏:`ENABLE_GAMEFRAMEX_WEB_SEND_LOG`(发送)、`ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`(接收),相关脚本见 [WebLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/WebLogScriptingDefineSymbols.cs)。

### 4. 在调用侧正确捕获异常

超时会被统一转换为 `TimeoutException` 抛出,其他失败保留原始 `WebException` / `IOException`。按下面的顺序 catch 即可区分超时与其他错误:

```csharp
try
{
    WebStringResult result = await webManager.GetToString(url);
}
catch (TimeoutException)
{
    // 超时:调大 Timeout / RequestTimeout 后重试
}
catch (WebException e)
{
    // HTTP/网络错误:检查 URL、DNS、服务端状态
    Debug.LogError(e.Message);
}
catch (IOException e)
{
    // 响应流中断:多为网络波动,可重试
    Debug.LogError(e.Message);
}
```

超时转换与异常分发逻辑(非 WebGL 路径,WebGL 之外的 Binary 路径在 [WebManager.Binary.cs L164](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L164) 中处理方式相同):

```csharp
catch (WebException e)
{
    // 捕获超时异常
    if (e.Status == WebExceptionStatus.Timeout)
    {
        webJsonData.UniTaskCompletionStringSource.SetException(new TimeoutException(e.Message));
        return;
    }
    webJsonData.UniTaskCompletionStringSource.SetException(e);
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L305)

调用方示例(README 中的推荐写法)也按 `WebExceptionStatus.Timeout` 分支处理超时,见 [README.md L145-L148](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L145-L148)。

## 常见错误

- **误以为默认超时是 30 秒**:README 的配置示例标注了"默认:30 秒",但 `WebManager` 构造函数实际写死 `Timeout = 5f`,见 [WebManager.cs L46](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L46)。接口响应超过 5 秒就会被判超时。
- **只 catch `Exception`**:这样会丢失"超时"与其他错误的区分;先 catch `TimeoutException` 再 catch `WebException`/`IOException`。
- **一次发起大量请求后怀疑丢请求**:并发超过 `MaxConnectionPerServer` 的请求不会丢,只是留在队列中,每帧最多出队一个,等待即可或调大上限。
- **在 WebGL 平台排查 `HttpWebRequest` 行为**:WebGL 只走 `UnityWebRequest` 分支,超时单位是秒(`TotalSeconds`),与原生平台的毫秒(`TotalMilliseconds`)路径不同,见 [WebManager.cs L217-L218](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L217-L218) 与 [WebManager.cs L258-L259](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L258-L259)。

## 验证

- 将 `Timeout` 调到足够大(例如 30 秒)后重发同一个请求,若仍失败且异常为 `WebException`,基本可排除超时,转向检查 URL 与服务端。
- 开启 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`,在日志中确认请求确实发出、URL/Header/Form 与预期一致。
- 并发场景下对比 `m_SendingNormalList` 与 `MaxConnectionPerServer`:调大上限后请求不再长时间停留队列,可确认是并发排队导致。

## 背景

`WebManager` 每帧从等待队列取请求,按平台选择实现:WebGL 用 `UnityWebRequest`(证书由 `DefaultBypassCertificate` 直接放行,见 [DefaultBypassCertificate.cs L39-L45](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/DefaultBypassCertificate.cs#L39-L45)),其他平台用 `HttpWebRequest`。两条路径都读取同一个 `RequestTimeout` 值,只是单位不同(秒 vs 毫秒)。请求完成或失败后会从发送列表移除并归还引用池,不会造成队列泄漏。
