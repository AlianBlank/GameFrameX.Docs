# 界面打开失败怎么办

调用 `UIManager` 打开 FairyGUI 界面后没有出现界面，或抛出异常 / 触发 `OpenUIFormFailure` 事件。失败点几乎都在三处：资源路径或包名拼接不对、UI 包未正确加载、界面脚本类型与组件不匹配。先对照下方诊断表定位，再按对应修复步骤处理。

## 快速诊断

| 症状（日志/现象原文） | 原因 | 修复 |
|------|------|------|
| `GameFrameworkException: Load UI form failure, asset name 'XXX', error message '...'` 且未注册失败事件处理器时抛出 | UI 包资源加载失败：路径错误、包未打进 Bundles、YooAsset 报错 | 见下方「修复步骤 1：核对资源路径与包名规则」 |
| 触发了 `OpenUIFormFailure` 事件但代码不崩 | 加载失败但你注册了 `OpenUIFormFailureEventHandler`，错误被转为事件回调 | 见「修复步骤 2：注册失败事件拿到真实错误」 |
| `Can not create UI form in UI form helper.` | `IUIFormHelper.CreateUIForm` 返回 null：界面脚本类型（`uiFormType`）与组件资源不匹配或未注册 | 见「修复步骤 3：检查界面类型与组件名」 |
| `Open UI form info is invalid.` | `OpenUIFormInfo` 引用被提前释放/复用池异常，通常是外部混用了内部流程 | 检查是否绕过 `UIManager` 公开 API 直接调用了内部方法 |
| `Log.Error("加载资源失败 Unknown file type: " + assetName + " extension: " + extension)` | FairyGUI 依赖资源扩展名不被识别（非 `_fui`/贴图等已知类型） | 检查发布出的资源文件是否完整、扩展名是否被改动 |
| 界面"打开"了但拿到的实例不刷新、事件不响应 | 单例模式下命中了已打开的同名实例，直接复用返回 | 见「修复步骤 4：理解单例打开行为」 |

## 修复步骤

### 修复步骤 1：核对资源路径与包名规则

打开界面时，框架按以下规则从 `uiFormAssetPath` 与界面类型名推导所有地址（见 `UIManager.InnerLoadUIFormAsync`）：

- `uiFormAssetName` = 界面类型名 `uiFormType.Name`（**必须与 FairyGUI 编辑器中导出的组件名一致**）；
- `assetPath` = `uiFormAssetPath/uiFormAssetName`；
- `packageName` = `uiFormAssetPath` 中最后一个 `/` 之后的部分；若路径中没有 `/`，则整个路径就是包名；
- 走 Bundles 加载时，实际加载的资源是 `uiFormAssetPath/packageName_fui`。

```csharp
var uiFormAssetName = uiFormType.Name;
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);

var lastIndexOfStart = uiFormAssetPath.LastIndexOf("/", StringComparison.OrdinalIgnoreCase);
// 如果路径中没有 /，则整个路径作为包名（适用于 Resources 目录下的简单路径）
var packageName = lastIndexOfStart >= 0 ? uiFormAssetPath.Substring(lastIndexOfStart + 1) : uiFormAssetPath;
// 检查UI包是否已经加载过
var hasUIPackage = FairyGuiPackage.Has(packageName);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L127-L136)

排查要点：

1. 确认 `uiFormAssetPath` 末段目录名与 FairyGUI 发布的包名一致（例如路径 `Assets/Bundles/UI/MainUI` 推出包名 `MainUI`）。
2. 确认界面类名（`uiFormType.Name`）与组件名完全一致，大小写敏感。
3. 走 Bundles 时确认存在 `<uiFormAssetPath>/<packageName>_fui` 资源；当包名与界面名不同，框架会用 `uiFormAssetPath/packageName` 重新拼路径再追加 `_fui`：

```csharp
// 不一致则重新拼接路径
string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
await FairyGuiPackage.AddPackageAsync(newPackagePath);
...
newAssetPackagePath += "_fui";
// 从包中加载
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L163-L178)

4. 如果 `assetPath` 中不包含 `Utility.Asset.Path.BundlesDirectoryName`（默认 Bundles 目录名），框架会按 **Resources 模式**同步加包，此时确认该路径在 Resources 下真实存在：

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // 从Resources 中加载
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

### 修复步骤 2：注册失败事件拿到真实错误

加载失败最终进入 `LoadAssetFailureCallback`。错误消息格式固定为：

```text
Load UI form failure, asset name '{0}', error message '{1}'.
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L358-L368)

关键行为分两种情况：

- 已订阅 `OpenUIFormFailureEventHandler`：错误包装为 `OpenUIFormFailureEventArgs` 触发事件，方法返回 null，不抛异常；
- 未订阅：直接 `throw new GameFrameworkException(appendErrorMessage)`，异常冒泡到你的调用处。

排查时建议先订阅失败事件，把 `errorMessage` 打到日志里，其中的 YooAsset/资源错误信息就是根因。

### 修复步骤 3：检查界面类型与组件名

`InternalOpenUIForm` 中，若 `IUIFormHelper.CreateUIForm` 返回 null 会抛出：

```csharp
IUIForm uiForm = m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData);
if (uiForm == null)
{
    throw new GameFrameworkException("Can not create UI form in UI form helper.");
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L211-L217)

该异常同样会触发 `OpenUIFormFailure` 事件（携带 `exception.ToString()`）后重新抛出。检查：

1. 传入的 `uiFormType` 是否是已注册/可创建的 `FUI` 子类；
2. 组件在包内是否存在同名导出；
3. 若在 `OnOpen`/`BindEvent`/`LoadData` 阶段抛异常，同样走失败事件 + rethrow 路径（见 [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L264-L273)）。

### 修复步骤 4：理解单例打开行为

单例模式打开的界面，命中已打开实例时直接复用并聚焦，不会重新加载：

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L84)

若"打开"后表现异常，先用 `GetUIForm(uiFormAssetName)` 检查是否是旧实例；正在加载中的同名界面会复用同一个加载 Task，不会重复加载。运行中 UI 元素路径查不到时另见 `FairyGUIPathFinderHelper` 的报错：`error uiPath : can not found ui by this path :{path}` 与 `Invalid UI path: child not found`（[Runtime/FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L141-L191)）。

## 验证

1. 重新调用打开 API，确认返回的 `IUIForm` 不为 null 且 `SerialId > 0`；
2. 观察是否触发 `OpenUIFormSuccess` 事件（[Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L255-L260)），同时不再出现 `Load UI form failure` 日志；
3. 失败事件回调不再被触发，控制台无 `GameFrameworkException`。
