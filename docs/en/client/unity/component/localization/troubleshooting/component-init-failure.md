# What to do about "Localization manager is invalid / Base component is invalid"

These two Fatal logs come from `LocalizationComponent`'s `Awake()` and `Start()` respectively: the first is printed when `Awake()` fails to obtain the localization manager module via `GameFrameworkEntry.GetModule<ILocalizationManager>()`, and the second when `Start()` fails to find the Base component via `GameEntry.GetComponent<BaseComponent>()`; the component then simply does a `return` and localization stops working. In the vast majority of cases the cause is either "the localization implementation assembly was not compiled with the package / was cropped out" or "the GameFrameX base components are missing from the scene" — work through the diagnostic table below item by item to recover.

## Quick Diagnosis

| Symptom (console message) | Location | Cause | Fix |
|------|------|------|------|
| `Localization manager is invalid.` | `Awake()`, module retrieval failed | The assembly containing the localization module implementation (e.g. `LocalizationManager`) was not compiled into the project, or was removed by the GameFrameX cropping configuration | See [Fix Step 1: Verify the implementation assembly exists](#step-1-verify-the-implementation-assembly-exists) below |
| `Base component is invalid.` | `Start()`, failed to get the Base component | `BaseComponent` is missing from the GameFrameX root object in the scene, or the component is lost (Missing Script) due to script compilation errors | See [Fix Step 2: Add the missing BaseComponent](#step-2-add-the-missing-basecomponent) below |
| `Event component is invalid.` | `Start()` | The same root object is missing `EventComponent` | Add it the same way as in Step 2 |
| `Setting component is invalid.` | `Start()` | The same root object is missing `SettingComponent` | Add it the same way as in Step 2 |
| `Can not create localization helper.` | `Start()` | The default helper type pointed to by `m_LocalizationHelperTypeName`, `GameFrameX.Localization.Runtime.DefaultLocalizationHelper`, does not exist, or the custom Helper type name is wrong | See [Fix Step 3: Verify the localization Helper](#step-3-verify-the-localization-helper) below |

## Fix Steps

### Step 1: Verify the implementation assembly exists

`LocalizationComponent.Awake()` retrieves the module by interface type:

```csharp
m_LocalizationManager = GameFrameworkEntry.GetModule<ILocalizationManager>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L216)

A null return from `GetModule` means the concrete implementation class of `ILocalizationManager` (`LocalizationManager`) was never registered with `GameFrameworkEntry`, usually because the implementation assembly containing it did not participate in compilation. Check the following in order:

1. Open the Unity Console and clear all **compiler errors** first — when compilation errors exist, Unity skips compiling some assemblies, and module registration is lost accordingly; this is the most common trigger.
2. Confirm that the runtime asmdef (`GameFrameX.Localization`) under this package's `Runtime` directory has been imported and not removed; this package's component is declared with `[RequireComponent(typeof(GameFrameXLocalizationCroppingHelper))]`, so if Missing Script appears in the Inspector, the runtime assembly is missing or failed to compile.
3. If the project has GameFrameX's component cropping / module removal mechanism enabled, confirm the localization module has not been cropped out.

### Step 2: Add the missing BaseComponent

The basis for the `Base component is invalid.` verdict is the lookup in `Start()`:

```csharp
BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227)

1. On the same GameFrameX root object in the scene that has `LocalizationComponent` attached, confirm that `BaseComponent` is present (as well as `EventComponent` and `SettingComponent`, which `Start()` also depends on).
2. If the Inspector shows "Missing (Mono Script)", the corresponding script did not compile or its assembly is missing — go back to Step 1 to clear the compilation errors.
3. Do not manually scatter these components across multiple objects; `GameEntry.GetComponent<T>()` expects them on the framework entry.

### Step 3: Verify the localization Helper

`Start()` then creates the Helper from the serialized fields, printing `Can not create localization helper.` on failure:

```csharp
LocalizationHelperBase localizationHelper = Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper);
if (localizationHelper == null)
{
    Log.Fatal("Can not create localization helper.");
    return;
}
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L254)

In the `LocalizationComponent` Inspector, check `m_LocalizationHelperTypeName`; its default value is the fully qualified type name:

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73)

If you have switched to a custom Helper, either drag a reference into the `m_CustomLocalizationHelper` field, or make sure `m_LocalizationHelperTypeName` is a fully resolvable type name in the "Namespace.ClassName, AssemblyName" form.

## Verification

1. Re-enter Play mode; the Fatal logs listed above, such as `Localization manager is invalid.` and `Base component is invalid.`, no longer appear in the Console.
2. A normal, complete run of `Start()` initializes the language: in non-editor mode, when `Language == UnknownLocalization` it automatically adopts `SystemLanguage` and finally sets `DefaultLanguage` (see [LocalizationComponent.cs lines 261-272](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L272) for the source). You can use `LocalizationComponent.Language`, `DefaultLanguage`, and `DictionaryCount` to assert that the component is ready.
3. Call one of the string lookup APIs (e.g. the `GetLocalizedString`/`GetRawString` family); if it returns a string rather than an empty one, this confirms the entire pipeline has initialized successfully.
