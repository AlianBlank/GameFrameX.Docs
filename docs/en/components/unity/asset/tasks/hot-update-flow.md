# How to Do Hot Updates: Version Check, Manifest Update, and Patch Download

Hot updates are driven by the 5 states defined in the `EPatchStates` enum: `UpdateStaticVersion` (update static asset version) → `UpdateManifest` (update patch manifest) → `CreateDownloader` (create downloader) → `DownloadWebFiles` (download remote files) → `PatchDone` (patch process complete). This task connects "start patch → subscribe to state changes → fail and roll back → enter main flow", so you can run the complete hot update chain in your business code.

## Prerequisites

- The `AssetComponent` instance has been obtained through `GameEntry` from `GameFrameX.Runtime` (for framework entry, see "Quick Start").
- The remote server has been deployed according to YooAsset's directory structure: the `{platform}/{version}/{packageName}` under the root directory must contain files like `GameVersion.txt`, `{packageName}_PatchManifest_{version}.bytes`, `{packageName}_StaticVersion_{version}.bytes`, etc.
- Event types like `AssetPatchStatesChangeEventArgs` in the project need to be preserved (the code already has `[UnityEngine.Scripting.Preserve]` to avoid being stripped).

## Steps

### 1. Subscribe to the Patch State Change Event

Subscribe to `AssetPatchStatesChangeEventArgs` through the `GameFrameX` event bus. A callback will be received whenever the next state is entered, which can be used to refresh the progress bar UI.

```csharp
GameEntry.Event.Subscribe(AssetPatchStatesChangeEventArgs.EventId, OnPatchStatesChange);

private void OnPatchStatesChange(object sender, GameEventArgs e)
{
    var args = (AssetPatchStatesChangeEventArgs)e;
    // args.PackageName: the name of the asset package currently being updated
    // args.CurrentStates: EPatchStates enum (see table below)
    Debug.Log($"[{args.PackageName}] Entered phase: {args.CurrentStates}");
}
```

Source: [AssetPatchStatesChangeEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchStatesChangeEventArgs.cs#L18-L46)

### 2. Subscribe to "Found Files to Update" and "Download Progress" Events (Optional but Recommended)

These two events are used to display on the UI "how many files need to be downloaded in total" and "which one is currently being downloaded / total size".

| Event EventId | Event Argument | Trigger Timing | Key Fields |
|---|---|---|---|
| `AssetFoundUpdateFilesEventArgs.EventId` | `AssetFoundUpdateFilesEventArgs` | After CreateDownloader, before DownloadWebFiles | Total number of files to download, total size |
| `AssetDownloadProgressUpdateEventArgs.EventId` | `AssetDownloadProgressUpdateEventArgs` | During each file download | Current progress, downloaded/total size, remaining size |

### 3. Subscribe to Failure Events and Handle Rollback

Any failure during the hot update process will throw the corresponding event argument, which needs to be handled for retry or degradation at the subscription:

```csharp
GameEntry.Event.Subscribe(AssetStaticVersionUpdateFailedEventArgs.EventId, OnStaticVersionFailed);
GameEntry.Event.Subscribe(AssetPatchManifestUpdateFailedEventArgs.EventId, OnManifestFailed);
GameEntry.Event.Subscribe(AssetWebFileDownloadFailedEventArgs.EventId, OnFileDownloadFailed);
```

Source: [AssetStaticVersionUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetStaticVersionUpdateFailedEventArgs.cs) · [AssetPatchManifestUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchManifestUpdateFailedEventArgs.cs#L10-L25) · [AssetWebFileDownloadFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetWebFileDownloadFailedEventArgs.cs)

### 4. Start the Hot Update Process

Call the update entry provided by `AssetComponent` (please refer to the current `Runtime/Asset/AssetComponent.cs` in the repository for the actual signature). A complete patch session will enter the following five states in order:

```csharp
// Call once during the Boot phase (after GameEntry starts)
var assetComponent = GameEntry.GetComponent<AssetComponent>();
assetComponent.UpdatePackages(); // Fetch version number → compare manifest → create downloader → download → callback PatchDone
```

After triggering, the event bus will broadcast in order:
1. `EPatchStates.UpdateStaticVersion` —— Compare the remote `GameVersion.txt` with the local cached version.
2. `EPatchStates.UpdateManifest` —— Fetch `{packageName}_PatchManifest_{version}.bytes` and diff with the local manifest.
3. `EPatchStates.CreateDownloader` —— Construct the downloader required by events like `AssetDownloadProgressUpdateEventArgs`.
4. `EPatchStates.DownloadWebFiles` —— Actually download the diff files; `AssetDownloadProgressUpdateEventArgs` is called back once per file.
5. `EPatchStates.PatchDone` —— The process ends, and it's safe to enter the main scene.

Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L32)

## Common Variants

| Scenario | Approach |
|---|---|
| Skip checks and use local assets directly | Call the "local only" initialization overload of `AssetComponent`, which doesn't enter `UpdatePackages` at all |
| Update only a single asset package | Control the scope before `UpdatePackages` via switches like `SetForceUpdateAllPackageVersions(true)` |
| Resumable download | The event `AssetDownloadProgressUpdateEventArgs` retains the number of downloaded bytes; when `UpdatePackages` is called again, the framework will automatically resume the unfinished files |

## Common Errors

| Symptom | Possible Cause | Workaround |
|---|---|---|
| `EPatchStates.PatchDone` is never triggered | Event not subscribed or subscribed EventId is misspelled | Use `typeof(AssetPatchStatesChangeEventArgs).FullName` as the EventId, don't write the string manually |
| No response halfway through download | `AssetDownloadProgressUpdateEventArgs` is not subscribed, the downloader may be waiting on the main thread | Give the downloader a separate async context; display progress on the UI |
| Remote manifest 404 | The server has not deployed `{packageName}_PatchManifest_{version}.bytes` | Re-upload using the framework's built-in upload tool (see YooAsset official Builder); the event `AssetPatchManifestUpdateFailedEventArgs` will carry error information |
| Static version file download failed | Server is missing `{platform}/GameVersion.txt` or cache directory is read-only | Check write permissions on `Application.persistentDataPath`; listen to `AssetStaticVersionUpdateFailedEventArgs` |

## Background (Optional)

`EPatchStates` abstracts YooAsset's entire patch lifecycle into 5 enum values. The framework layer is only responsible for throwing `AssetPatchStatesChangeEventArgs` to the `GameFrameX` event bus when state transitions occur, and the business side decouples by subscribing to the EventId. In this way, UI, network retry, and degradation strategies can be replaced without intrusion, while the main patch flow remains stable.
