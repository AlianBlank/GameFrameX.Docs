# 实现玩家宠物(Pet)模块

玩家宠物(Pet)模块以组件形式挂载在玩家 Actor 上,负责保存宠物的运行时状态并响应宠物相关事件;本节带你从空模块开始,落出一个可注册、可扩展的宠物组件骨架。

## 前置条件

- 已创建玩家 Actor(`ActorType = GlobalConst.ActorTypePlayer`)。
- 已引入 `GameFrameX.Core.Abstractions.Attribute`、`GameFrameX.Utility.Setting`、`GameFrameX.Core.Components`。
- 了解框架的 `StateComponent<TState>` 与 `StateComponentAgent<TComponent, TState>` 双层结构(Apps 层定义与状态,Hotfix 层编写逻辑)。

## 常见变体

- **响应获得宠物事件**:在 `PetComponentAgent` 中添加私有异步方法处理 `EventId.GotNewPet`,并通过嵌套 `EventListener<T>` 类订阅事件(参考 [PetComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Pet/PetComponentAgent.cs#L8-L28) 中的注释示例)。
- **跨组件调用**:在 `PetComponentAgent` 内通过 `ActorManager.GetComponentAgent<ServerComponentAgent>()` 获取其他组件代理,例如读取世界等级以决定宠物属性。
- **宠物数据字段**:直接在 `PetState` 中添加可序列化属性(如宠物 ID、等级、经验),框架会自动参与存盘与缓存。

## 常见错误

- **Agent 命名空间不一致**:`PetComponentAgent` 当前所在命名空间是 `GameFrameX.Hotfix.Logic.Role.Pet`,而 Apps 层是 `GameFrameX.Apps.Player.Pet.*`,复制粘贴示例时务必保留各自的命名空间,避免框架反射失败。
- **忘记加 `[ComponentType]`**:`PetComponent` 没有标注 `ActorTypePlayer` 时,不会被挂载到玩家 Actor 上,运行期表现为宠物功能完全无效。
- **把业务逻辑写在 Apps 层**:Apps 层会在打包时进入主程序集,无法热更新;所有可变逻辑必须放在 Hotfix 层的 `PetComponentAgent`。

## 背景(可选)

`PetComponent` 走的是框架的"组件 + 状态 + 代理"三件套:`StateComponent<TState>` 仅声明状态归属与生命周期,真实业务运行在 `StateComponentAgent<TComponent, TState>` 中,二者通过泛型参数配对;`[ComponentType]` 决定该组件被框架注册到哪一类 Actor 上。
