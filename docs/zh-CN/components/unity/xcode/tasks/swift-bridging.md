# 启用 Objective-C/Swift 混编桥接

在 `XCodeConfig.json` 中把 `swiftBridging` 设为 `true`（或保持缺省——该配置**默认开启**），构建 iOS 工程后 GameFrameX 会自动生成 Swift 桥接文件与桥接头文件，并设置 `SWIFT_VERSION=5.0` 与 `SWIFT_OBJC_BRIDGING_HEADER`，全程无 Xcode 弹窗，可直接用于 CI。

## 前置条件

- 已在工程中引入 GameFrameX Xcode Config 包，并按《XCodeConfig.json 配置总览》完成基础配置（本包在 iOS 构建时自动执行后处理，无需手动调用任何 API）。
- 构建目标为 iOS 平台（相关代码位于 `#if UNITY_IOS` 块内）。

## 操作步骤

1. 打开工程根目录（或模块目录）下的 `XCodeConfig.json`，将 `swiftBridging` 设为 `true`：

   ```json
   {
     "swiftBridging": true
   }
   ```

   > 该键可省略——省略时视为 `true`（默认开启）。判定逻辑见下方源码：

   ```csharp
   // 设置 Swift 桥接（默认开启）
   bool swiftBridging = !finalConfig.ContainsKey("swiftBridging") || finalConfig.Get<bool>("swiftBridging");
   SetupSwiftBridging(project, project.GetUnityMainTargetGuid(), project.GetUnityFrameworkTargetGuid(), path, swiftBridging);
   ```

   Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101)

2. 在 Unity 中执行 iOS 构建（File → Build Settings → Build），后处理阶段会自动完成：

   - 在生成的 Xcode 工程根目录创建 `gameframex_swift_bridging.swift`（不存在时写入，内容为 `import Foundation`，文件头标注 `DO NOT EDIT`）；
   - 创建 `Unity-iPhone-Bridging-Header.h` 桥接头文件；
   - 将 `.swift` 文件加入 UnityFramework target 编译，将桥接头文件加入工程；
   - 为主 target 与 UnityFramework target 设置 `SWIFT_VERSION = 5.0`，并为主 target 设置 `SWIFT_OBJC_BRIDGING_HEADER = Unity-iPhone-Bridging-Header.h`。

   核心实现：

   ```csharp
   proj.AddFileToBuild(frameworkTargetGuid, proj.AddFile(swiftFile, SwiftBridgingFileName, PBXSourceTree.Source));
   proj.AddFile(bridgingHeaderFile, SwiftBridgingHeaderName, PBXSourceTree.Source);

   proj.SetBuildProperty(mainTargetGuid, "SWIFT_VERSION", "5.0");
   proj.SetBuildProperty(mainTargetGuid, "SWIFT_OBJC_BRIDGING_HEADER", SwiftBridgingHeaderName);

   proj.SetBuildProperty(frameworkTargetGuid, "SWIFT_VERSION", "5.0");

   LogHelper.Log("[SwiftBridging] Swift bridging header configured");
   ```

   Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L37-L45)

3. 验证结果：打开生成的 `.xcodeproj`，选中 **Unity-iPhone** target → Build Settings：
   - `SWIFT_VERSION` 显示 `5.0`；
   - `SWIFT_OBJC_BRIDGING_HEADER` 显示 `Unity-iPhone-Bridging-Header.h`；
   - Unity Console 输出 `[SwiftBridging] Swift bridging header configured`。

## 常见变体

- **关闭混编桥接**：显式写 `"swiftBridging": false`。`SetupSwiftBridging` 开头有 `if (!enabled) return;`，关闭后不会创建任何文件、不设置任何 Swift 构建属性。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L12-L14)
- **在桥接头中暴露 Objective-C 头**：桥接头文件只在不存在时生成、之后不会被覆盖（`File.Exists` 判断），你可以直接在生成的 `Unity-iPhone-Bridging-Header.h` 中追加 `#import`，重复构建不会丢失你的修改。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L27-L35)
- **多模块协作**：多个 `XCodeConfig.json` 会被深度递归合并，最终以合并后的 `swiftBridging` 值生效；未在任一配置中写明时默认为 `true`。
  Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L100)

## 常见错误

- **Xcode 中未看到 Swift 文件 / `SWIFT_OBJC_BRIDGING_HEADER` 为空**：多半是配置合并后 `swiftBridging` 被某份 `XCodeConfig.json` 显式设为 `false`。检查所有参与合并的配置文件。
- **改了桥接头文件内容又"消失"了**：检查是否重新生成了 Xcode 工程目录（Unity 覆盖导出会重建目录）。桥接头只在文件不存在时写入，建议把自定义 `#import` 放到不会被覆盖的稳定位置或由你自己的脚本注入。
- **Swift 语法报错 / 版本不符**：本包固定写入 `SWIFT_VERSION = 5.0`，不要手工在工程里改回旧版本值，重复构建会被再次覆盖为 5.0。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L40-L43)

## 背景

该功能仅作用于 **Unity-iPhone（主）target 与 UnityFramework target**：Swift 文件被加入 UnityFramework target 编译，`SWIFT_OBJC_BRIDGING_HEADER` 只设置在主 target 上。与在 Xcode 中手动新建 Swift 文件时弹出的"是否创建桥接头"对话框不同，此流程完全由后处理脚本完成，因此 CI 环境下无人值守构建也不会被弹窗阻塞。
