# パーティションテーブル / バージョン管理 / インポートエクスポートの宣言方法

エンティティクラスに `PartitionTableAttribute`、`VersionControlAttribute`、`ImportExportAttribute` の 3 つの特性を追加することで、データベーステーブルがパーティションをサポートするかどうか、バージョン管理を有効にするかどうか、インポートエクスポートフローに参加するかどうかを一度に宣言できます。このページでは、直接コピーして使用できる最小例と最も一般的なバリエーションをいくつか紹介します。

## 前提条件

- `GameFrameX.Foundation.Orm.Attribute` 名前空間を参照する;
- エンティティクラスには、特性で宣言されたフィールドと同名のプロパティ（パーティションキー、バージョンフィールドなど）を含める必要がある;
- 実際の DDL は、上層 ORM / マイグレーションツールが特性に基づいて生成するため、このドキュメントでは宣言方法のみを説明する。

## 操作手順

### 1. パーティションテーブルの宣言

エンティティクラスに `PartitionTableAttribute` を追加し、コンストラクタにパーティションキーフィールドとパーティションタイプを渡す。ハッシュパーティションには `PartitionCount` を指定でき、レンジパーティションには `Interval` を指定できる。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[PartitionTable("CreateDate", PartitionType.Range, PartitionInterval.Monthly)]
public class OrderHistory
{
    public int Id { get; set; }
    public int UserId { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreateDate { get; set; }  // 分区键
}
```

Source: [PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L63-L91)

オプション属性:`AutoCreatePartition`(デフォルト `true`)、`RetentionDays`(デフォルト `0` は永久保持を意味する)、`PartitionValues`(リストパーティション時に指定)、`PartitionCount`(デフォルト `4`、ハッシュパーティション用)。

```csharp
[PartitionTable("UserId", PartitionType.Hash, PartitionCount = 16)]
public class UserActivity
{
    public long Id { get; set; }
    public int UserId { get; set; }
    public string Activity { get; set; }
    public DateTime Timestamp { get; set; }
}
```

Source: [PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L82-L89)

### 2. バージョン管理の宣言

エンティティクラスに `VersionControlAttribute` を追加し、コンストラクタにバージョンフィールド名を渡し、必要に応じてバージョン戦略を指定する。エンティティには同名のバージョンフィールドプロパティを含める必要がある。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[VersionControl("Version", VersionStrategy.Optimistic)]
public class Document
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }
    public int Version { get; set; }  // 版本号字段
    public DateTime LastModified { get; set; }
    public string LastModifiedBy { get; set; }
}
```

Source: [VersionControlAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/VersionControlAttribute.cs#L63-L74)

オプション属性:`EnableHistory`(デフォルト `false`)、`HistoryTableName`、`MaxHistoryVersions`(デフォルト `0` は無制限を意味する)、`ConflictHandling`(デフォルト `ThrowException`)、`AutoUpdateVersion`(デフォルト `true`)、`ComparisonMode`(デフォルト `Increment`)。

履歴バージョンを保持する必要がある場合は、`EnableHistory` を `true` に設定し、履歴テーブル名を指定できる:

```csharp
[VersionControl("RowVersion", VersionStrategy.Timestamp, EnableHistory = true)]
public class UserProfile
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
    public byte[] RowVersion { get; set; }
}
```

### 3. インポートエクスポートの宣言

エンティティクラスに `ImportExportAttribute` を追加し、コンストラクタに対応するフォーマットとインポートエクスポートの方向を渡す。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[ImportExport(ImportExportFormat.Excel, ImportExportDirection.Bidirectional)]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

(コード例は `ImportExportAttribute` の公開コンストラクタ `ImportExport(ImportExportFormat, ImportExportDirection)` に基づいている。)

## よくあるバリエーション

| シナリオ | 記述方法 | 説明 |
|------|------|------|
| リストパーティション | `PartitionTable("Region", PartitionType.List)` に `PartitionValues = "North,South,East,West"` を追加 | 事前定義された値リストでパーティション分割 |
| エクスポートのみ | `ImportExport(ImportExportFormat.Csv, ImportExportDirection.ExportOnly)` | インポートエントリを閉じる |
| インポートのみ、かつ検証を有効化 | `ImportExport(ImportExportFormat.Excel, ImportExportDirection.ImportOnly, ValidateOnImport = true)` | インポート時にフィールド検証を実行 |
| 3 つの特性を重ねる | エンティティに `PartitionTable` + `VersionControl` + `ImportExport` を同時に記述 | 大規模テーブル + 並行処理 + データ交換のシナリオ |

`PartitionTableAttribute` と `VersionControlAttribute` はどちらも `AllowMultiple = false` で、同じクラス上ではそれぞれ 1 回のみ宣言可能。`ImportExportAttribute` も同様に 1 回のみ許可される。

## よくあるエラー

- **パーティションキーまたはバージョンフィールドが存在しない**:エンティティクラスに `PartitionKey` / `VersionField` と同名のプロパティがないと、マイグレーションまたは実行時の検証が失敗する。まずフィールドを追加してから特性を追加する。
- **ハッシュパーティションの `PartitionCount <= 0`**:コンストラクタが `ArgumentOutOfRangeException` をスローし、`Partition count must be positive.` と表示される。正の整数を渡す必要がある。
- **`partitionKey` / `versionField` に `null` または空白を渡す**:`ArgumentNullException` または `ArgumentException.ThrowIfNullOrWhiteSpace` がトリガーされるため、定数文字列を直接渡す。
- **リストパーティションで `PartitionValues` の指定を忘れる**:リストパーティションは値コレクションを明示的に宣言する必要があり、そうでないとパーティション境界を確定できない。
- **バージョンフィールドのタイプと戦略が一致しない**:例えば `VersionStrategy.Timestamp` に対応するフィールドは `byte[]` または `DateTime` であるべきで、`Optimistic` には `int/long` が対応する。混在させるとバージョン比較が失敗する。
