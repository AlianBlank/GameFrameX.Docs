# How to Distribute Application State Through the Event Bus

Through GameFrameX's built-in `OnApplicationFocusChangedEventArgs` and `OnApplicationPauseChangedEventArgs`, you can subscribe to and distribute application focus and pause state change events in the Unity Mono module without building your own event bus.

## Prerequisites

- The `GameFrameX.Runtime` assembly has been referenced, and make sure `using GameFrameX.Runtime;` is in place (the namespace is subject to the source code).
- There is already a `MonoBehaviour` entry point for registering and unregistering subscriptions.

## Steps

1. Declare subscription callbacks in the MonoBehaviour. The signatures must match `EventHandler<TEventArgs>`.

   ```csharp
   using GameFrameX.Runtime;
   using UnityEngine;

   public class AppStateListener : MonoBehaviour
   {
       private void OnEnable()
       {
           GameFrameXEntry.Event.Subscribe(
               OnApplicationFocusChangedEventArgs.EventId,
               OnFocusChanged);
           GameFrameXEntry.Event.Subscribe(
               OnApplicationPauseChangedEventArgs.EventId,
               OnPauseChanged);
       }

       private void OnDisable()
       {
           GameFrameXEntry.Event.Unsubscribe(
               OnApplicationFocusChangedEventArgs.EventId,
               OnFocusChanged);
           GameFrameXEntry.Event.Unsubscribe(
               OnApplicationPauseChangedEventArgs.EventId,
               OnPauseChanged);
       }

       private void OnFocusChanged(object sender, GameFrameXEventArgs e)
       {
           var args = (OnApplicationFocusChangedEventArgs)e;
           Debug.Log($"Focus changed: hasFocus={args.HasFocus}");
       }

       private void OnPauseChanged(object sender, GameFrameXEventArgs e)
       {
           var args = (OnApplicationPauseChangedEventArgs)e;
           Debug.Log($"Pause changed: isPaused={args.IsPaused}");
       }
   }
   ```

   Source: [OnApplicationFocusChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationFocusChangedEventArgs.cs#L1-L40), [OnApplicationPauseChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationPauseChangedEventArgs.cs#L1-L40)

2. Set the `EventId` (integer) on your custom `EventArgs` to serve as the unique key for subscription and publishing.

   ```csharp
   public class MyAppStateEventArgs : GameFrameXEventArgs
   {
       public static readonly int EventId = typeof(MyAppStateEventArgs).GetHashCode();
       public string State { get; set; }
   }
   ```

3. Fire the event through `GameFrameXEntry.Event`:

   ```csharp
   GameFrameXEntry.Event.Fire(this, new MyAppStateEventArgs { State = "Ready" });
   ```

## Common Variations

- To share the same application state broadcast across multiple MonoBehaviours, simply have each one `Subscribe`/`Unsubscribe` accordingly. The event bus will route by `EventId` to all subscribers.
- Forward to a custom `EventArgs` within the `UnityEngine` callbacks `OnApplicationPause`/`OnApplicationFocus` to distinguish engine callbacks from business layer logic.

## Common Errors

- **Unpaired `Unsubscribe`**: Unregister in `OnDisable` instead of `OnDestroy` to avoid still receiving events after the script has been deactivated.
- **Casting without type checking**: `e` is `GameFrameXEventArgs`; you must first cast with `(T)e` before accessing specific fields, otherwise an `InvalidCastException` will be thrown.
- **Hand-written `EventId` is not unique**: Use `typeof(T).GetHashCode()` directly to avoid different types colliding on the same ID.

## Background

`OnApplicationFocusChangedEventArgs` and `OnApplicationPauseChangedEventArgs` are event argument types provided by the repository under `Runtime/EventArgs/`. They encapsulate the `HasFocus`/`IsPaused` state fields and are used to interface with the `GameFrameXEntry.Event` event bus. The event bus itself is defined in the `GameFrameX.Runtime` assembly; this repository only contributes these event arguments.
