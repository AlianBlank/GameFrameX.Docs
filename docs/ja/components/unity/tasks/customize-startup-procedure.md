# Startup フローにカスタム Procedure を組み込む方法

`ApplicationStartupEntry` で `StartupRunner.Run` を呼び出すと、フレームワークは `startupOptions.ProcedureSettings` に設定された順に各 Procedure を順次実行します。このページでは、カスタム Procedure を新規作成してこの起動チェーンに組み込む方法を説明します。

## 前提条件

- `Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs` の起動エントリーポイントが存在すること。
- プロジェクトに `GameFrameX.Startup.Runtime`(`StartupRunner`、`ProcedureBase`、`IStartupUIHandler` を提供)が導入済みであること。
- `startupOptions` アセットが `ApplicationStartupEntry` のインスペクタにアタッチされていること。

## 操作手順

1. **カスタム Procedure クラスの新規作成**:`ProcedureBase` を継承し、`OnEnter` / `OnLeave` を実装します(必要に応じて `OnUpdate` をオーバーライド)。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   namespace GameFrameX.Startup.Application
   {
       /// <summary>
       /// カスタム起動フロー:リモートアカウントサービスへのログインとプレイヤーの基本データの読み込み。
       /// </summary>
       public sealed class ProcedureLogin : ProcedureBase
       {
           protected override async UniTask OnEnter(ProcedureContext context)
           {
               // フローに入る:起動時に実行したいロジックをここに記述
               await LoginRemoteServiceAsync();
           }

           protected override UniTask OnLeave(ProcedureContext context)
           {
               // フローを離れる:リソースや状態をクリーンアップ
               return UniTask.CompletedTask;
           }

           private UniTask LoginRemoteServiceAsync()
           {
               // ビジネス側で実装
               return UniTask.CompletedTask;
           }
       }
   }
   ```

   Source: [ApplicationStartupUIHandler.cs](Assets/Scripts/Framework/Procedure/ApplicationStartupUIHandler.cs#L1-L87)

2. **Procedure を `StartupOptions` に登録**。`startupOptions.ProcedureSettings` リストに実行順に従って `ProcedureLogin` を追加します(クラス名または型識別子はフレームワークの規約と一致している必要があり、通常は `Type` またはリソースキーです)。

3. **(オプション)カスタム起動 UI**。起動中に UI のヒント表示を更新する必要がある場合は、`IStartupUIHandler` を実装してエントリーポイントで渡します:

   ```csharp
   var result = await StartupRunner.Run(
       startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   `IStartupUIHandler` が必ず実装する必要があるメンバー:`StartAsync(uiResName)`、`SetTipText(text)`、`SetProgress(progress, sizeInfo)`、`SetProgressUpdateFinish()`、`ShowUpgradeAsync(upgradeInfo)`、`Dispose()`。

   Source: [ApplicationStartupEntry.cs](Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L14-L55)

4. **失敗時の処理**。`StartupRunner.Run` は `StartupResult` を返すので、`Success`、`FailedProcedureName`、`FailedUrl`、`ErrorMessage` フィールドでどの Procedure が失敗したかを判定し、ログに記録します:

   ```csharp
   if (!result.Success)
   {
       Log.Error($"Startup failed. Procedure: {result.FailedProcedureName}, Url: {result.FailedUrl}, Error: {result.ErrorMessage}");
   }
   ```

## よくあるバリエーション

| シーン | 方法 |
|------|------|
| ログ追加やイベント計測のみを行いたい | `OnEnter` / `OnLeave` をオーバーライドし、内部で `Log.Info` を呼ぶだけ、IO は行わない。 |
| 非同期でネットワーク結果を待つ必要がある | `OnEnter` で `UniTask` を返し、内部でネットワーク/リソース読み込みメソッドを `await` する。 |
| 起動 UI に FairyGUI / UGUI を使用する | フレームワークは `ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI` によって `LauncherUIResName` を自動的に切り替えるため、Procedure 内で処理する必要はない。 |

## よくあるエラー

- **`startupOptions` が未代入**:起動エントリーポイントは `Log.Error("StartupOptions is not assigned.")` を出力した後、直接 return するため、Procedure はすべて実行されません。
- **`OnLeave` の実装忘れ**:`OnEnter` が「起動中」状態に入ったままになっていると、後続のフローが正しいコンテキストを取得できない可能性があります。少なくとも `UniTask.CompletedTask` を返してください。
- **Procedure の順序が誤っている**:ログイン/リソース検証をホットアップデートより前に配置すると、ホットアップデート失敗時にプレイヤーのコンテキストを取得できなくなります。「初期化 → ホットアップデート → ビジネス検証 → メインシーンへ」の順序で配置してください。

## 背景(オプション)

`StartupRunner.Run` はフレームワークの起動チェーンの統一エントリーポイントであり、`StartupOptions`、UI ハンドラ、ホットフィックスランチャーの 3 つを受け取ります。`startupOptions.ProcedureSettings` が Procedure チェーンのトポロジと実行順序を決定するため、組み込み作業，实际上は宣言的な設定であり、`StartupRunner` の内部コードを変更するものではありません。
