# ホットフィックスランチャーの接続方法（IHotfixLauncher）

`IHotfixLauncher` インターフェースを実装することで、起動フローがリソースパッチ完了後にあなたのホットフィックスソリューション（HybridCLR、ILRuntime、自社開発ソリューションなど）を呼び出せるようになります。アセンブリのロード方法とホットフィックスエントリへの遷移はアプリケーション層で決定します。

## 前提条件

- 起動フローが正しく初期化されていること（起動フロー接続ドキュメントを参照）。
- `StartupOptions` 設定アセットが準備され、`HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` が入力されていること。
- `GameFrameX.Startup.Runtime` 名前空間と `Cysharp.Threading.Tasks` が導入されていること。

## インターフェース契約

`IHotfixLauncher` は非同期メソッドを1つだけ公開しており、成功・失敗にかかわらず必ず `HotfixLaunchResult` を返す必要があります。例外を直接スローしないでください。

```csharp
using Cysharp.Threading.Tasks;

namespace GameFrameX.Startup.Runtime
{
    /// <summary>
    /// ホットフィックス起動インターフェース。アプリケーション層で実装します。パッケージ内では具体的なホットフィックスソリューション（HybridCLR / その他）にバインドしません。
    /// </summary>
    public interface IHotfixLauncher
    {
        UniTask<HotfixLaunchResult> StartAsync(StartupOptions options);
    }
}
```

## 操作手順

1. アプリケーションプロジェクト配下に新しいクラス（例：`MyHotfixLauncher`）を作成し、`IHotfixLauncher` を実装します。
2. `StartAsync` 内で `options` に基づいてホットフィックス DLL/アセンブリを読み込み、リフレクションでエントリメソッドを呼び出します（`HotfixLaunchResult.Succeed()` または `HotfixLaunchResult.Fail(message)` を構築して返します）。
3. `StartAsync` 内で例外をスローしないでください。失敗時は `HotfixLaunchResult.Fail("エラーメッセージ")` を構築して返します。起動フレームワークはこれに基づいて失敗ブランチを実行し、`StartupFailedEventArgs` を発行します。
4. `MyHotfixLauncher` インスタンスを起動マネージャーに注入します（通常は `StartupManager` の注入インターフェースまたは `GameObject` へのドラッグ＆ドロップ設定）。これによりフレームワークのデフォルトの Launcher を上書きします。
5. 起動フローを実行します。Patch フェーズがすべて完了すると、フレームワークが自動的に `StartAsync` を呼び出します。

using GameFrameX.Startup.Runtime;

public sealed class MyHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        try
        {
            // 1) ホットフィックスアセンブリをロード（例：HybridCLR / YooAsset / 自社開発 loader を使用）

            // 2) リフレクションでホットフィックスエントリへ遷移

            //    var entryMethod = entryType.GetMethod(options.HotfixEntryMethodName);

            await UniTask.Yield();
            return HotfixLaunchResult.Succeed();

        catch (System.Exception ex)

## よくあるバリエーション

- **HybridCLR ソリューション**：`StartAsync` 内で `HybridCLR.RuntimeApi.LoadDllFromMemory` を使って DLL をロードし、`System.Reflection.Assembly` のリフレクションでエントリメソッドを呼び出します。
- **純リソースホットフィックス（DLL なし）**：`Resources.Load<GameObject>` でプレハブを直接ロードして `Instantiate` します。エントリロジックではリフレクションのステップを省略できます。
- **初期化フェーズを伴うソリューション**：ホットフィックスフレームワークが非同期初期化（ダウンロードや検証など）を必要とする場合は、`StartAsync` 内で `await` して完了後に `Succeed` を返します。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| 起動時のクラッシュやブラックアウト | `StartAsync` が未キャッチの例外をスローした | キャッチして `HotfixLaunchResult.Fail(message)` を返すように変更する |
| `Success=true` が返るがゲームがメインシーンに入らない | エントリメソッド名/タイプ名の誤り | `StartupOptions` の `HotfixEntryTypeName` / `HotfixEntryMethodName` が DLL 内のものと完全に一致しているか確認する |
| Patch フェーズから先に進まない | カスタム `IHotfixLauncher` が注入されておらず、フレームワークがデフォルトの空実装を使用している | 起動マネージャーで独自の実装クラスに置き換える |

## 検証

- 起動フローを実行し、Patch 完了後にホットフィックスエントリに入るかを確認します。
- ユニットテストは `IHotfixLauncherContractTests` を参考にできます。成功実装は `result.Success == true` を返し `ErrorMessage` が空文字列であること、失敗実装は `result.Success == false` を返し `ErrorMessage` が渡された例外メッセージと等しいことをアサートします。

## 背景（任意）

`IHotfixLauncher` はパッケージが意図的に公開している拡張ポイントです。パッケージ内では「Patch 完了 → Launcher 呼び出し → 結果取得」というプロトコルのみを定義しており、具体的なホットフィックスソリューションにはバインドしないため、HybridCLR などのサードパーティパッケージとの強い結合を避けられます。
