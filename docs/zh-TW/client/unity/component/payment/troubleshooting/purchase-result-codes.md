# 購買失敗與結果碼速查

當購買回呼 `OnPurchaseFailed`（或 `OnQueryPurchasesResult` / `OnConsumePurchaseResult`）觸發時，`PaymentEventArgs.ResultCode` 會給出一個 `PaymentResultCode` 列舉值，用於定位失敗原因。本頁彙整全部結果碼、對應處置建議，以及如何正確訂閱回呼取得這些資訊。

## 快速診斷

| 症狀（ResultCode / 現象） | 原因 | 修復 |
|------|------|------|
| `Success` | 購買成功 | 在 `OnPurchaseSuccess` 中發貨；一次性商品記得呼叫 `ConsumePurchase` |
| `Failed` | 通路通用失敗，詳情見 `ErrorMessage` | 輸出 `ErrorMessage` 與 `PurchaseData`，按通路錯誤碼排查 |
| `Cancelled` | 使用者在支付介面主動取消 | 不要彈出錯誤提示，靜默處理即可 |
| `NetworkError` | 裝置網路不可用 | 提示重試，等待網路恢復後重新 `Buy` |
| `ServiceUnavailable` | 通路支付服務不可用（如商店未就緒） | 先 `IsReady()` 確認支付系統就緒，稍後重試 |
| `ItemAlreadyOwned` | 商品已擁有且未消耗（一次性商品重複購買） | `QueryPurchases` 查回 `PurchaseToken` 後執行 `ConsumePurchase`，再重新購買 |
| `ItemNotOwned` | 尚未擁有該商品就嘗試消耗 | 先完成購買，勿對不存在的 `PurchaseToken` 呼叫 `ConsumePurchase` |
| `VerifyFailed` | 購買驗證失敗（與 `Init` 的 `isClientVerify` 相關） | 伺服器驗證方案下將 `isClientVerify` 設為 `false`；檢查伺服器端驗簽邏輯 |
| `Unknown` | 通路回傳了未映射的結果 | 依賴 `ErrorMessage` 與 `PurchaseData`（原始 JSON）人工分析 |

結果碼定義如下，共 9 個：

```csharp
public enum PaymentResultCode
{
    Success,
    Failed,
    Cancelled,
    NetworkError,
    ServiceUnavailable,
    ItemAlreadyOwned,
    ItemNotOwned,
    VerifyFailed,
    Unknown,
}
```

## 取得完整錯誤資訊

回呼參數 `PaymentEventArgs` 攜帶以下欄位，排查時全部輸出：

| 欄位 | 類型 | 說明 |
|------|------|------|
| `ProductId` | `string` | 產品 ID |
| `OrderId` | `string` | 訂單 ID |
| `PurchaseToken` | `string` | 購買權杖（消耗/查詢時使用） |
| `ResultCode` | `PaymentResultCode` | 支付結果代碼 |
| `ErrorMessage` | `string` | 錯誤訊息 |
| `PurchaseData` | `string` | 原始購買資料（JSON 格式） |
| `CustomData` | `string` | 購買時傳入的自訂資料 |

## 修復步驟

### 訂閱購買失敗回呼

三個結果事件（`OnPurchaseSuccess` / `OnPurchaseFailed` / `OnQueryPurchasesResult` / `OnConsumePurchaseResult`）在 `IPaymentManager` 上宣告，`PaymentComponent` 以事件包裝器形式轉發到內部的 `_paymentManager`：

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L42-L46)

業務層訂閱範例：

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseFailed += OnPurchaseFailed;

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    UnityEngine.Debug.LogError(
        $"[Payment] 失败 ProductId={e.ProductId} ResultCode={e.ResultCode} " +
        $"ErrorMessage={e.ErrorMessage} PurchaseData={e.PurchaseData}");
}
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L19-L36)

### `ItemAlreadyOwned`：消耗後重試

一次性商品（`PaymentProductType` 的消耗型）發貨後未消耗，下次購買會得到該結果碼：

1. 呼叫 `QueryPurchases(PaymentProductType)` 查詢購買記錄；
2. 在 `OnQueryPurchasesResult` 回呼中取出 `PurchaseToken`；
3. 呼叫 `ConsumePurchase(e.PurchaseToken)` 完成消耗；
4. 重新發起 `Buy(purchaseParams)`。

相關簽名（定義於 `IPaymentManager`，由 `BasePaymentManager` 抽象實作）：

```csharp
void QueryPurchases(PaymentProductType productType);
void ConsumePurchase(string purchaseToken);
```

Sources: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L52-L63)

### `VerifyFailed`：檢查驗證模式

`Init` 的第二個參數決定驗證方式：

```csharp
/// <param name="isClientVerify">是否執行客戶端驗證購買成功，如果是強連線驗證。不需要開啟，設定為false，進行伺服器驗證</param>
void Init(bool isDebug = false, bool isClientVerify = false);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

採用伺服器驗證時傳入 `false`，由伺服器端驗簽，避免客戶端驗證失敗誤報 `VerifyFailed`。

### `ServiceUnavailable`：確認就緒狀態

購買前先呼叫 `bool IsReady()`；未就緒時通路端未初始化完成，會落入 `ServiceUnavailable`。另外 `SetPredefinedProductIds` 必須在初始化之前呼叫，否則預載入快取不生效：

```csharp
void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

## 驗證

- 觸發一次取消購買（沙箱環境點擊取消），確認回呼收到 `Cancelled` 且無異常日誌；
- 對已擁有未消耗的商品再次購買，確認得到 `ItemAlreadyOwned`，執行 `ConsumePurchase` 後可正常重新購買；
- `OnPurchaseFailed` 中輸出的 `ErrorMessage` / `PurchaseData` 內容完整，可與通路後台對帳。

## 背景

各通路實作繼承 `BasePaymentManager`，統一透過 `RaisePurchaseFailed` 等四個受保護方法觸發結果事件，因此所有通路回呼的 `PaymentEventArgs` 結構一致：

```csharp
protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}
```
