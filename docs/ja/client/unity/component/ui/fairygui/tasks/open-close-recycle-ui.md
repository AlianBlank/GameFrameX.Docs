# UIフォームのオープン、クローズとリサイクル

本ページでは、FairyGUI 版 `UIManager` の UIフォームライフサイクルの使用方法について説明します:開き方(シングルトン重複排除とインスタンスプール再利用を含む)、閉じた後のリサイクル方法、およびリサイクルが破棄と同一ではない場合の注意点。外部向けのオープン/クローズのエントリーポイントは GameFrameX.UI パッケージの `BaseUIManager` を継承しており、本リポジトリ(プラグイン)は `InnerOpenUIFormAsync` と `RecycleUIForm` をオーバーライドすることで FairyGUI の具体的な実装を実現しています。

## 前提条件

- シーンに `FairyGUIPackageComponent` コンポーネントが既に存在していること。`UIManager.SetResourceManager` はアセットマネージャーを設定する際に `GameEntry.GetComponent<FairyGUIPackageComponent>()` を実行し、`GameFrameworkGuard.NotNull` で検証を行い、欠落している場合は直接例外をスローします:

```csharp
public override void SetResourceManager(IAssetManager assetManager)
{
    base.SetResourceManager(assetManager);
    FairyGuiPackage = GameEntry.GetComponent<FairyGUIPackageComponent>();
    GameFrameworkGuard.NotNull(FairyGuiPackage, nameof(FairyGuiPackage));
}
```

Source: [UIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs#L87-L92)

- リサイクル間隔には下限があります:コンストラクター内で `m_RecycleInterval` が 10 未満の場合は 10(秒)に強制的に設定されます。つまり、UIフォームのインスタンスはプール内に最低 10 秒保持された後に初めて、実際に解放される可能性があります。
- UIフォームのロジッククラスは `FUI`(`UIForm` を継承)を継承しており、`GObject` プロパティを通じて FairyGUI オブジェクトにアクセスします。

## 操作手順:UIフォームを開く

1. UIフォームのオープンを非同期でリクエストします。`InnerOpenUIFormAsync` はすべてのオープンリクエストの集約点であり、シグネチャは以下の通りです:

```csharp
protected override async Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L64-L64)

2. このUIフォームの型がシングルトンオープンモード(`UseSingletonOpenMode(uiFormType)`)を有効にしている場合、既に開いていればそのまま再利用して再フォーカスし、読み込み中であれば同じタスクを待機するため、重複してインスタンス化されることはありません:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }

    foreach (var value in m_LoadingUIForms)
    {
        if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
        {
            return await value.Task;
        }
    }
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L85)

3. シングルトン分岐に該当しない場合、まずインスタンスプールからの取得を試みます(`m_InstancePool.Spawn(uiFormAssetName)`)。取得できた場合は、新しいシリアル番号で `InternalOpenUIForm` を直接呼び出してオープンを完了し、アセット読み込みを一切経由しません:

```csharp
var uiFormInstanceObject = m_InstancePool.Spawn(uiFormAssetName);

if (uiFormInstanceObject != null)
{
    // プール再利用時も新しいリクエストシリアル番号を割り当て、毎回のオープンリクエストを監視可能にします。
    int serialId = ++m_Serial;
    return InternalOpenUIForm(serialId, uiFormAssetPath, uiFormAssetName, uiFormType, uiFormInstanceObject.Target, pauseCoveredUIForm, false, 0f, userData, isFullScreen);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L87-L94)

4. プールにも存在しない場合は `InnerLoadUIFormAsync` に入ります:アセットパスからパッケージ名を切り出し、FairyGUI パッケージがまだ読み込まれていない場合はソースに応じて読み込みます——`Resources` ディレクトリは `FairyGuiPackage.AddPackageSync(assetPath)` で同期読み込み、Bundle パスは `FairyGuiPackage.AddPackageAsync` で非同期読み込みした後、`_fui` サフィックス付きのUIフォームアセットを読み込みます:

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Resources から読み込む
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

5. 読み込み成功後は `LoadAssetSuccessCallback` がコールバックされてUIフォームのインスタンスを生成します。読み込み失敗時は `LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo)` が呼び出され、エラー情報は `assetHandle.LastError` から取得されます。

## 操作手順：クローズとリサイクル

UIフォームを閉じると、最終的に本リポジトリでオーバーライドされた `RecycleUIForm` が呼び出されます。その完全なロジックは以下の通りです:`uiForm.OnRecycle()` を呼び出した後、`Handle` に対応する GameObject から `DisplayObjectInfo` を取得し、`GComponent` を取り出してインスタンスプールに返却します。`isDispose == true` の場合にのみ、追加で `ReleaseObject` を呼び出して実際に破棄します:

```csharp
protected override void RecycleUIForm(IUIForm uiForm, bool isDispose = false)
{
    uiForm.OnRecycle();
    var formHandle = uiForm.Handle as GameObject;
    if (!formHandle)
    {
        return;
    }

    var displayObjectInfo = formHandle.GetComponent<DisplayObjectInfo>();
    if (!displayObjectInfo)
    {
        return;
    }

    var component = displayObjectInfo.displayObject.gOwner as GComponent;
    if (component == null)
    {
        return;
    }

    m_InstancePool.Unspawn(component);
    if (isDispose)
    {
        m_InstancePool.ReleaseObject(component);
    }
}
```

Source: [UIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Close.cs#L53-L79)

ポイント:

| パラメーター | 動作 |
|------|------|
| `isDispose = false`(デフォルト) | `Unspawn` でインスタンスプールに返却し、オブジェクトは保持され、次回オープン時に直接再利用されます |
| `isDispose = true` | 返却後にさらに `ReleaseObject` で破棄・解放します |
| `Handle` が GameObject ではない / `DisplayObjectInfo` が欠落 / `gOwner` が `GComponent` ではない | `OnRecycle()` の呼び出しのみで早期リターンし、プールには入りません |

## よくあるバリエーション:表示・非表示アニメーション

UIフォームクラス `FUI` は `Show` / `Hide` をオーバーライドしており、FairyGUI オブジェクトをハンドラーに渡してアニメーションを再生します。アニメーションを再生するかどうかは `EnableShowAnimation` / `EnableHideAnimation` とアニメーション名 `ShowAnimationName` / `HideAnimationName` で制御され、ハンドラーが null の場合は直接完了コールバックを呼び出します:

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}

public override void Hide(IUIFormHideHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableHideAnimation, HideAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

Source: [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L74-L105)

もう一つのよくあるバリエーションは、パッケージ名とUIフォームアセット名が一致しないケースです:この場合は `PathHelper.Combine(uiFormAssetPath, packageName)` でパッケージパスを再構築してから `AddPackageAsync` を行い、その後ろに `_fui` を連結してUIフォームアセットを読み込みます。詳細は [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L158-L178) を参照してください。

## よくあるエラー

- **UIフォームのオープン時に `FairyGuiPackage` が null であることを示すガード例外がスローされる**:`FairyGUIPackageComponent` がアタッチまたは初期化されていません。先にシーン/エントリーポイントでこのコンポーネントを追加してから `SetResourceManager` を呼び出してください。
- **オープンに失敗したが詳細が確認できない**:Bundle モードでの失敗原因は `assetHandle.LastError` から取得され、`LoadAssetFailureCallback` で終了します。トラブルシューティング時は、パスに `BundlesDirectoryName` が示す Bundle ディレクトリ名が含まれていること、およびパッケージ名がアセットパスから正しく切り出せることを確認してください。
- **クローズ後にメモリが減少しない**:デフォルトの `isDispose = false` ではインスタンスプールへの返却のみが行われ、インスタンスはプール内に最低 `m_RecycleInterval`(下限 10 秒)保持されます。これは予期された動作です。確実に破棄したい場合は `isDispose: true` でリサイクルしてください。
- **同じUIフォームを頻繁に開閉すると重複インスタンスが発生する**:このUIフォームの型が `UseSingletonOpenMode` を有効にしているか確認してください。無効の場合は毎回プール/読み込みフローを経由し、複数のインスタンスの同時存在が許容されます。

## 検証

- オープン後、返された `IUIForm` を通じて `GObject` が `FUI.GObject` に設定されているかを確認します。シングルトンUIフォームを再度開いた場合は同じインスタンスが返され、`RefocusUIForm` がトリガーされるはずです。
- クローズ後、UIフォームのインスタンスがプールから再び `Spawn` で再利用できること(デフォルトパス)、または `isDispose: true` を指定した場合は再利用できないこと(破棄パス)を確認します。
- アニメーションパスの検証:`Show`/`Hide` の完了コールバック `complete` が必ず呼び出される必要があります。そうでない場合、上位のフローは先に進みません。

## 背景

オープンフローは三段階のショートサーキットで構成されます:シングルトン重複排除 → インスタンスプール再利用 → 非同期読み込み。`m_LoadingUIForms` リストは進行中の読み込みタスクを記録して並行リクエストをマージし、毎回のオープン(プール再利用を含む)で新しい `m_Serial` シリアル番号が観測用に割り当てられます。リサイクルパスでは、`FUI.InternalSetVisible` は可視性のみを変更しイベントを発行せず、実際のインスタンスの返却/破棄はすべて `RecycleUIForm` 内で `GComponent` と `m_InstancePool` に基づいて行われます。
