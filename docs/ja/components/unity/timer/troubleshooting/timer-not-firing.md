# タイマーが発火しない、またはクエリが -1 を返す場合の対処法

タイマーがコールバックされない、または `GetRemaining` / `GetElapsed` / `GetRepeatLeft` が `-1` を返す場合、通常は以下のいずれかに該当します:コールバックが null のため `Add` が即座に失敗して 0 を返す、タイマーを `Add` した直後でまだ `Update` によって `_items` に反映されていない、繰り返し回数を使い切ったまたは既に `Remove` されている、`Pause` された後に `Resume` されていない、`Scaled` モードで `Time.timeScale` が 0。本ページでは症状別に診断表と対応する修正手順を示します(以下の例では、`TimerManager` / `ITimerManager` のインスタンスを既に保持しており、Unity 側では `TimerComponent` を経由して同名のメソッドが転送されるものと仮定します)。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `Add` が 0 を返し、コンソールに `timer callback is null, {interval},{repeat}` が出力される | `callback` パラメータが null のため、登録が拒否された | コールバックが空でないことを確認してから登録する。詳細は[修正 1](#1-add-が-0-を返すコールバックが-null)を参照 |
| `Add` 直後に `GetRemaining`/`GetElapsed`/`GetRepeatLeft` をクエリすると -1 が返る | タイマーはまだ `_toAdd` キューにあり、次回の `Update` の最後になって初めて `_items` に反映される | 1 フレーム待ってからクエリするか、先に `Exists(id)` で判定する。詳細は[修正 2](#2-add-直後にクエリすると--1-が返るタイマーがまだ-update-で反映されていない)を参照 |
| `AddOnce` が 1 回発火した後にクエリすると -1 が返る | `repeat` が 0 まで減った時点でタイマーが削除され `_ids` から除去されるため。正常な動作 | 再度発火させたい場合は改めて `Add` する。詳細は[修正 3](#3-繰り返し回数を使い切ったまたは既に-remove-されている)を参照 |
| `Exists(id)` が true なのにいつまでも発火しない | 以前に `Pause(id)` を呼び出して `Resume` していない、または `Scaled` モードかつ `Time.timeScale = 0` | `Resume(id)` を呼び出す、またはデフォルトの `Unscaled` に変更する。詳細は[修正 4](#4-pause-後に再開されていない)、[修正 5](#5-scaled-モードかつ-timetimescale-が-0)を参照 |
| 同一コールバックで 2 つ目のタイマーを登録すると、1 つ目の計時が「ゼロからやり直し」になる | コールバックデリゲートがディクショナリのキーであり、重複して `Add` するとその場でリセットされる(`Elapsed = 0`) | タイマーごとに独立したコールバック/ラムダを使用する。詳細は[修正 6](#6-同一コールバックの重複登録により計時がリセットされる)を参照 |
| あるコールバックが例外をスローした後、後続のコールバックがすべて実行されない | `TimerManager.CatchCallbackExceptions` がデフォルトで `false` のため、例外がそのままスローされ、この周回のディスパッチが中断される | `true` に設定して問題のコールバックを特定する。詳細は[修正 7](#7-コールバックの例外が後続のコールバックを飲み込む)を参照 |

## 修正手順

### 1. `Add` が 0 を返す:コールバックが null

`Add` の完全なシグネチャと失敗時の分岐は以下の通りです。`callback == null` の場合は警告を出力して 0 を返すだけで、この ID が発火することは決してありません:

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
{
    lock (Locker)
    {
        if (callback == null)
        {
            Debug.LogWarning("timer callback is null, " + interval + "," + repeat);
            return 0;
        }
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L225)

登録後、まず戻り値を検証します:

```csharp
int id = timerManager.Add(1f, 0, OnTick);
if (id == 0)
{
    // コールバックが null のため登録に失敗した。ここでこの id を保持し続けるべきではない
}
```

### 2. `Add` 直後にクエリすると -1 が返る:タイマーがまだ `Update` で反映されていない

新しいタイマーはまず `_toAdd` に入り、`Update` の最後になって初めて `_items` に反映されます。一方、クエリメソッドは `_items` 内に削除されていないエントリが見つかった場合にのみ有効な値を返し、それ以外は -1 を返します:

```csharp
public float GetRemaining(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return -1f;
        }

        if (_items.TryGetValue(callback, out var t) && !t.Deleted)
        {
            // ...残り時間を返す
        }

        // Timer is in _toAdd (not yet flushed)
        return -1f;
    }
}
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L552-L575)

反映は `Update` の最後のステップで行われるため、「登録したフレーム内でそのままクエリ」すると必ず -1 になります:

```csharp
if (_toAdd.Count > 0)
{
    var enumerator = _toAdd.GetEnumerator();
    while (enumerator.MoveNext())
    {
        _items.Add(enumerator.Current.Key, enumerator.Current.Value);
    }

    enumerator.Dispose();
    _toAdd.Clear();
}
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L153-L163)

**修正方法**：クエリを次のフレームに移してください(コルーチンの `yield return null`、または別の毎フレーム実行されるコールバックに配置)。あるいは先に `Exists(id)` を判定してください——このメソッドは `_toAdd` と `_items` の両方をチェックし、「まだ反映されていない」タイマーに対して true を返します。

### 3. 繰り返し回数を使い切った、または既に `Remove` されている

`repeat > 0` のタイマーは発火のたびにデクリメントされ、0 になると削除としてマークされます。削除時に ID が `_ids` から除去されるため、以降の ID によるクエリはすべて -1 を返します。`AddOnce` は内部的には `repeat = 1` であり、1 回の発火で破棄されます。`repeat = 0` は無限繰り返しを意味します。

```csharp
if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)

**修正方法**：これは設計上の動作であり、バグではありません。周期的に発火させたい場合は `repeat = 0` を渡してください。ワンショットのタスク終了後に -1 になるのは正常であり、古い ID を再利用せず、改めて `Add` して新しい ID を取得してください。

### 4. `Pause` 後に再開されていない

`Pause(id)` は `IsPaused = true` を設定します。以降、`Update` は即座に `continue` し、時間は蓄積されず、コールバックも発火しませんが、タイマー自体は `_items` に残ります(`Exists(id)` は引き続き true)。`Resume(id)` は `IsPaused` を false に戻し、計時を再開します:

```csharp
if (timerItem.IsPaused)
{
    continue;
}
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L75-L78)

**修正方法**:`Resume(id)` を呼び出してください。`Pause` だけを行い `Resume` しないコードパスがないか確認してください。Inspector やログを使用して、現在一時停止中のタイマーが存在しないか確認できます。

### 5. `Scaled` モードかつ `Time.timeScale` が 0

時間源は `TimeScaleMode` に基づいて選択され、デフォルトは `Unscaled`(`timeScale` の影響を受けない)です。登録時に `TimerTimeScale.Scaled` を渡した場合、ゲームの一時停止時(`Time.timeScale = 0`)には delta が 0 となり、タイマーは永遠に発火条件に到達しません:

```csharp
// Select time source based on TimeScaleMode
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L80-L81)

**修正方法**：UI や切断時の再接続など、一時停止中も動作する必要があるロジックは、デフォルトの `Unscaled` のまま `timeScale` パラメータを渡さないでください。ゲームの一時停止に追従すべきものにのみ `TimerTimeScale.Scaled` を渡してください。

### 6. 同一コールバックの重複登録により計時がリセットされる

内部ではコールバックデリゲートがディクショナリのキーとして使用されます。既に存在するコールバックに対して再度 `Add` しても新しいタイマーは作成されず、その場でリセットされ(`Elapsed = 0`)、古い ID が再利用されます——典型的な症状は「1 つ目のタイマーがなぜか最初から計時し直す」ことです:

```csharp
// Re-add existing callback: update in-place
if (_items.TryGetValue(callback, out var t))
{
    UpdateTagIndex(t, tag);
    t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete);
    t.Elapsed = 0;
    t.Deleted = false;
    t.IsPaused = false;
    return t.Id;
}
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L236)

**修正方法**：同一オブジェクト上の複数のタイマーには、それぞれ独立したメソッドまたはラムダを使用してください(各ラムダは異なるデリゲートインスタンスです)。パラメータを更新したい場合は、この「再登録でリセットされる」動作を意図的に利用することもできます。

### 7. コールバックの例外が後続のコールバックを飲み込む

コールバックはロックの外でまとめてディスパッチされます。`TimerManager.CatchCallbackExceptions` はデフォルトで `false` であり、あるコールバックがスローした例外はこの周回の for ループを中断し、同じフレームの後続のコールバックはすべて実行されません。これを `true` に設定すると、例外をキャッチして `Timer callback error > {message}` だけを出力するようになります:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

出典： [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L172-L186)

**修正方法**：トラブルシュート期間中は `TimerManager.CatchCallbackExceptions = true` に設定し、警告を観察して例外をスローしているコールバックを特定してください。根本原因を修正した後は、例外を飲み込まないようデフォルトに戻すことをお勧めします。

## 検証

上記の修正を行った後、以下の項目を順に確認してください:

1. `Add` が 0 以外の ID を返し、かつ `Exists(id)` が true であること(登録成功、「まだ反映されていない」段階も含む)。
2. 1 フレーム待ってから `GetRemaining(id)` / `GetElapsed(id)` をクエリすると、-1 を返さず、値が時間の経過とともに進むこと。
3. `interval` に到達するとコールバックが呼び出されること。`GetRepeatLeft(id)` が 0 を返す場合は無限繰り返し、その他の正の数は残り回数を表します。
4. `Pause(id)` の後は `GetElapsed(id)` が増加しなくなり、`Resume(id)` の後に再び増えること。
5. `TimerManager.CatchCallbackExceptions = true` に設定しても `Timer callback error >` の警告が出ないこと。例外をスローしているコールバックが存在しないことを意味します。
