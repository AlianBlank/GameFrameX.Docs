# 타이머 상태 조회: 남은 시간, 경과 시간 및 남은 횟수

타이머 ID로 `GetRemaining` / `GetElapsed` / `GetRepeatLeft`를 호출하면 현재 상태를 조회할 수 있으며, `IsPaused` / `Exists`와 함께 사용하면 타이머가 살아있는지 또는 일시정지 중인지 추가로 판단할 수 있습니다. 세 가지 조회 인터페이스는 타이머가 존재하지 않을 때 통일되게 `-1`을 반환합니다.

## 사전 조건

- 씬에 사용 가능한 `TimerComponent`가 이미 있어야 합니다(내부적으로 `ITimerManager`의 동명 메서드를 래핑합니다).
- 타이머 생성 시 반환된 타이머 ID(`Add` 계열 메서드의 반환 값)를 보유하고 있어야 합니다.

## 조회 인터페이스 개요

| 메서드 | 시그니처 | 반환 값 |
|------|------|--------|
| 남은 시간 | `float GetRemaining(int id)` | 남은 초; 타이머가 존재하지 않으면 `-1` 반환 |
| 경과 시간 | `float GetElapsed(int id)` | 누적된 초; 타이머가 존재하지 않으면 `-1` 반환 |
| 남은 횟수 | `int GetRepeatLeft(int id)` | 남은 반복 횟수(`0`은 무한 루프를 의미); 타이머가 존재하지 않으면 `-1` 반환 |
| 일시정지 여부 | `bool IsPaused(int id)` | 일시정지 중이면 `true`, 그렇지 않으면 `false` |
| 존재 여부 | `bool Exists(int id)` | 살아있으면 `true`, 그렇지 않으면 `false` |
| 태그 조회 | `bool HasTag(string tag)` | 해당 태그에 하나 이상의 타이머가 존재하면 `true` |

위 시그니처는 인터페이스 정의와 컴포넌트 래퍼 계층에서 가져왔습니다:

```csharp

float GetElapsed(int id);
int GetRepeatLeft(int id);
```

## 작업 단계

1. 타이머를 생성하고 반환된 ID를 저장합니다(예: `Add` 계열 등록 호출에서 반환된 `int id = ...`).
2. UI 또는 로직을 갱신해야 하는 시점에, 보유한 `TimerComponent` 인스턴스를 통해 조회 메서드를 호출합니다:
   - 카운트다운 표시에는 `GetRemaining(id)` 사용;
   - 진행 바 채우기에는 `GetElapsed(id)` 사용(총 시간과 나누면 진행도를 얻을 수 있음);
   - 횟수 표시에는 `GetRepeatLeft(id)` 사용.
3. 매번 조회하기 전에 `Exists(id)`로 타이머가 아직 존재하는지 확인하는 것이 좋습니다——타이머가 트리거 완료 후 제거되면 조회는 `-1`만 반환합니다.
4. 타이머가 `Pause`/`PauseByTag`로 일시정지되었을 수 있다면, `IsPaused(id)`로 "일시정지 중"과 "종료됨"을 구분합니다.
5. UI에서는 `-1`을 "타이머가 더 이상 존재하지 않음"으로 처리하여 음수가 직접 표시되지 않도록 합니다.

## 일반적인 변형

- **일괄 일시정지 후 조회**: 동일한 태그의 타이머 그룹에 `PauseByTag(tag)`를 호출하면, `GetRemaining`은 감소하지 않고(일시정지 중에는 시간이 누적되지 않음), `IsPaused`는 `true`를 반환합니다. 재개에는 `ResumeByTag(tag)`를 사용합니다.
- **무한 루프 타이머**: `GetRepeatLeft`가 `0`을 반환하면 무한 루프를 의미하며, 이를 "종료됨"으로 간주해서는 안 됩니다.
- **async/await 시나리오**: 상태를 조회하는 대신 직접 대기하려면 `WaitForSecondsAsync(seconds, cancellationToken)` 등의 비동기 메서드를 사용할 수 있습니다. [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L224)를 참조하세요.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GetRemaining`이 `-1` 반환 | 타이머가 이미 제거됨(트리거 완료, `Remove`/`RemoveByTag` 호출 이력, 또는 ID 오기) | 먼저 `Exists(id)`로 확인; 타이머 다시 등록 |
| 남은 시간이 "움직이지 않음" | 타이머가 일시정지 상태 | `IsPaused(id)` 확인, 필요시 `Resume(id)` |
| `GetRepeatLeft`가 `0`을 반환하지만 콜백이 계속 트리거됨 | `0`은 무한 루프를 의미하며 종료가 아님 | 존재 여부는 횟수가 아닌 `Exists(id)`로 판단 |
| 음수가 표시됨 | `-1`을 초 단위로 직접 렌더링함 | UI 계층에서 `-1`을 "종료됨/존재하지 않음"으로 매핑 |

## 검증

유닛 테스트 저장소에 `GetRemaining_ReturnsCorrectValue` 등의 테스트 케이스가 이미 있습니다([UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L619)). Unity Test Runner에서 실행하여 조회 동작을 확인할 수 있습니다. 직접 검증할 때는 5초 타이머를 등록한 뒤 연속된 두 프레임에서 `GetElapsed`를 읽으면 증가해야 하고, `GetRemaining`은 감소해야 합니다.

## 배경 (선택)

내부적으로 각 타이머는 `TimerManager`의 private `Timer` 클래스에 기록되며, 여기서 `Elapsed` 필드는 경과 시간을 지속적으로 누적합니다. 조회 인터페이스는 이 내부 데이터를 기반으로 남은 값을 계산합니다([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L21-L22)). `TimerComponent`는 `ITimerManager`의 얇은 래퍼 계층일 뿐이므로, 두 진입점의 조회 결과는 동일합니다.
