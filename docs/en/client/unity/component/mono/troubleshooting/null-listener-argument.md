# What to do when the log reports "fun is invalid." or ArgumentNullException

When you see `fun is invalid.` in the log while calling the `AddXxxListener` / `RemoveXxxListener` series of methods on `MonoComponent`, or when you catch an `ArgumentNullException` in your test code, it means **a `null` callback was passed in**. This page provides quick troubleshooting and fix methods.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Runtime log shows `fun is invalid.` | The `Action` passed to `AddXxxListener` / `RemoveXxxListener` is `null`; after the internal `Log.Fatal`, it returns directly and the listener does not take effect | Assign a real method or `lambda` to the callback variable, then check with `?.` before passing it |
| Unit test throws `ArgumentNullException` | The underlying `_monoManager` of the same set of interfaces throws an exception for `null`, verifying that "passing null will inevitably fail" | Same cause as above; change to passing a non-null callback |
| Startup reports `Mono manager is invalid.` | In `MonoComponent.Awake`, `_monoManager == null`; the framework module is not registered | See "Fix Step 2" below |
| Startup reports `Event manager is invalid.` | In `MonoComponent.Start`, `m_EventComponent == null`; the event component is not attached | See "Fix Step 2" below |

## Fix Steps

### 1. When the callback is null, check for null before passing it in

`MonoComponent` performs an `if (fun == null)` check on every `Add*Listener` / `Remove*Listener`. After triggering, it only logs a `Fatal` message and does not perform any subscribe/unsubscribe action — it will not throw automatically — but the behavior will not occur.

Source: [MonoComponent.cs#L147-L171](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L147-L171)

```csharp
public void AddLateUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddLateUpdateListener(fun);
}
```

How to fix: Perform a null check before passing in, or use the null-coalescing operator to provide a default empty implementation, for example:

```csharp
Action<float, float> onLate = null;
if (onLate != null)
{
    GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener(onLate);
}

// Or use a lambda placeholder
GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener((dt, fdt) => { /* your logic */ });
```

### 2. Startup phase reports "Mono manager is invalid." or "Event manager is invalid."

These two log messages come from the initialization phase of `MonoComponent` itself, not from a null callback, but from the framework module/component not being ready.

```csharp
protected override void Awake()
{
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}

private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs#L52-L76](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76)

How to fix:

1. Check whether the scene has a module entry component that implements `IMonoManager`, or whether the corresponding assembly is included in the Player Settings' `Scripting Define Symbols` / assembly definition.
2. Attach `EventComponent` to the `GameEntry` prefab in GameFramework, and make sure its execution order is earlier than `MonoComponent`.

### 3. All listener methods involved

The following methods in `MonoComponent.cs` all follow the same pattern of "pass null → `fun is invalid.` log → return". You can check them together when troubleshooting:

`AddUpdateListener` / `RemoveUpdateListener`, `AddFixedUpdateListener` / `RemoveFixedUpdateListener`, `AddLateUpdateListener` / `RemoveLateUpdateListener`, `AddDestroyListener` / `RemoveDestroyListener`, `AddOnApplicationFocusListener` / `RemoveOnApplicationFocusListener`, `AddOnApplicationPauseListener` / `RemoveOnApplicationPauseListener`, `AddOnApplicationQuitListener` / `RemoveOnApplicationQuitListener`, `AddDrawGizmosListener` / `RemoveDrawGizmosListener`.

## Verification

After fixing, use the following methods to confirm the issue is resolved:

1. **Runtime**: Rerun the game and observe that the log no longer shows `fun is invalid.`, `Mono manager is invalid.`, `Event manager is invalid.`.
2. **Callback triggered**: Print a `Debug.Log` inside the callback body. After entering the corresponding lifecycle (such as `Update`, `LateUpdate`), you can see the log, indicating that the subscription is successful.
3. **Unit tests**: Cases like `Assert.Throws<ArgumentNullException>(() => _manager.AddUpdateListener(null))` in `Tests/UnitTests.cs` in the repository are used to verify the contract that **passing null will inevitably fail**; business code should pass in a real delegate.
