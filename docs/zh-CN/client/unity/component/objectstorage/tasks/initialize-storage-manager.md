# 如何初始化对象存储管理器

通过 `ObjectStorageUploadFactory.Create<T>` 创建并初始化一个对象存储上传管理器实例,完成后即可调用 `UploadFile` / `UploadDirectory` 等接口上传文件。

## 前置条件

- 已安装 `com.gameframex.unity.objectstorage` 包。
- 已引入一个实现 `IObjectStorageUploadManager` 的具体类型(本包只提供抽象基类 `BaseObjectStorageUploadManager`,具体云厂商实现需单独引入)。
- 已准备好四项参数:`accessKey`、`secretKey`、`bucketName`,以及可选的 `endpoint`。

## 操作步骤

1. 在代码中加入命名空间引用:

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13)

2. 调用 `ObjectStorageUploadFactory.Create<T>` 静态方法,传入泛型参数(实现类)与四项凭据。工厂内部会调用 `Activator.CreateInstance<T>()` 并自动执行 `Init`,无需手动初始化:

   ```csharp
   // 假设已引入某个具体实现,例如 MyCloudUploader : IObjectStorageUploadManager
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create<MyCloudUploader>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: "https://oss-cn-hangzhou.aliyuncs.com" // 选填,部分对象存储无需该值
   );
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. 如需自定义远端保存路径,调用 `SetSavePath`(注意传入路径不要以目录分隔符结尾,基类会自动去掉尾部斜杠):

   ```csharp
   manager.SetSavePath("uploads/build/v1");
   ```

   Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

4. 完成以上步骤后,管理器即处于"已初始化"状态,可直接调用 `UploadFile` 或 `UploadDirectory` 执行上传。

## 常见变体

- 不使用工厂,自行 `new` 一个实现类并手动调用 `Init`:

  ```csharp
  var manager = new MyCloudUploader();
  manager.Init("ak", "sk", "bucket", "endpoint");
  ```

  `Init` 的签名来自接口 `IObjectStorageManager`,`endpoint` 为可空参数,默认 `null`。

  Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L13)

- 直接继承 `BaseObjectStorageUploadManager` 实现自定义上传逻辑:仅需重写 `Init`、`UploadDirectoryInternal` 与 `UploadFileInternal` 三个 `protected`/ `public abstract` 方法。

  Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L10-L34)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `Create<T>` 编译报错,提示 `T` 不满足约束 | 泛型 `T` 未实现 `IObjectStorageUploadManager` | 传入具体上传管理器类(继承自 `BaseObjectStorageUploadManager` 或直接实现接口) |
| `SetSavePath` 后路径被截断 | 传入路径以目录分隔符结尾 | 基类会自动去掉尾部 `Path.DirectorySeparatorChar`,无需手动处理,但要保证传入有效目录名 |
| 上传时仍以默认路径为准 | 创建实例后忘记调用 `SetSavePath` | 在上传前显式设置 `BucketSavePath` |

## 背景(可选)

`ObjectStorageUploadFactory.Create<T>` 在内部一次性完成 `new` 与 `Init` 调用,目的是避免调用方遗漏初始化步骤。`endpoint` 在不同云厂商之间含义不同,接口以可选参数形式兼容。
