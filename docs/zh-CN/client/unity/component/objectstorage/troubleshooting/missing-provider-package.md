# 找不到具体存储提供方包怎么办

`com.gameframex.unity.objectstorage` 仅定义对象存储的抽象接口与工厂，**不包含**任何云厂商的具体实现。当你想要接入阿里云 OSS、AWS S3、腾讯云 COS 等具体服务时，需要单独安装对应的「对象存储提供方包」，找不到时按本页步骤排查。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 想上传到 OSS/S3/COS，但本仓库没有对应实现类 | 本包只提供抽象，需要单独的提供方包 | 安装 `com.gameframex.unity.objectstorage.aliyunoss`（或对应厂商）包 |
| `Activator.CreateInstance<T>()` 报 `MissingMethodException` 或找不到类型 | 没引入实现包，泛型参数对应的类不存在 | 引入对应提供方包，确保实现了 `IObjectStorageUploadManager` 的类已编译 |
| Package Manager 里搜不到提供方包 | 没配置 scopedRegistries，Unity 不会从 GameFrameX 注册表解析 | 在 `manifest.json` 中补 `scopedRegistries`，见下文 |
| 已经按 Git URL 添加，但 Unity 报「无法解析依赖」 | `scopes` 未覆盖 `com.gameframex`，或依赖名拼错 | 检查 `scopes` 数组包含 `com.gameframex`，依赖名精确匹配 |

## 修复步骤

### 1. 确认本包只提供抽象

README 已明确说明：本包定义了 `IObjectStorageUploadManager` 接口与 `BaseObjectStorageUploadManager` 抽象基类，并提供 `ObjectStorageUploadFactory` 静态工厂，**服务商特定的实现以独立包的形式提供**。

```csharp
// 仅依赖本包时，工厂无法工作——没有可实例化的具体类型
public static IObjectStorageUploadManager Create<T>(
    string accessKey, string secretKey, string bucketName, string endpoint = null)
    where T : IObjectStorageUploadManager
{
    var manager = Activator.CreateInstance<T>();  // T 必须由提供方包提供
    manager.Init(accessKey, secretKey, bucketName, endpoint);
    return manager;
}
```

Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

### 2. 配置 scopedRegistries（包管理器安装方式）

打开 Unity 项目的 `Packages/manifest.json`，添加 GameFrameX 注册表与依赖：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.objectstorage": "1.1.0"
  }
}
```

注意 `scopes` 必须包含 `com.gameframex`，否则 Unity 不会从该注册表解析依赖。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/README.zh-CN.md#L41-L60)

### 3. 安装具体的提供方包

在 [GameFrameX 文档站](https://gameframex.doc.alianblank.com) 或 GitHub 组织下查找以 `com.gameframex.unity.objectstorage.` 开头的提供方包，例如：

| 厂商 | 包名（示例） |
|------|-------------|
| 阿里云 OSS | `com.gameframex.unity.objectstorage.aliyunoss` |
| 其它 | 在文档站「对象存储」分类下查找最新支持的厂商列表 |

把对应包名追加到 `dependencies`：

```json
"dependencies": {
  "com.gameframex.unity.objectstorage": "1.1.0",
  "com.gameframex.unity.objectstorage.aliyunoss": "x.y.z"
}
```

### 4. 用工厂创建具体实例

安装提供方包后，调用 `ObjectStorageUploadFactory.Create<T>()` 时把泛型参数替换为该包中实现 `IObjectStorageUploadManager` 的具体类。

```csharp
using GameFrameX.ObjectStorage.Editor;

// 由提供方包提供，例如 AliyunOssUploadManager
IObjectStorageUploadManager uploader =
    ObjectStorageUploadFactory.Create<AliyunOssUploadManager>(
        accessKey: "your-access-key",
        secretKey: "your-secret-key",
        bucketName: "your-bucket",
        endpoint: "oss-cn-hangzhou.aliyuncs.com");

uploader.SetSavePath("remote/folder/");
uploader.UploadFile("Assets/Builds/pc.zip");
```

Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L1-L22)

### 5. 找不到提供方包时的退路：自行实现

如果目标厂商暂无官方提供方包，可继承 `BaseObjectStorageUploadManager` 自行实现 `Init` / `UploadDirectoryInternal` / `UploadFileInternal`，再用工厂创建：

```csharp
using GameFrameX.ObjectStorage.Editor;

public sealed class MyVendorUploadManager : BaseObjectStorageUploadManager
{
    public override void Init(string accessKey, string secretKey,
                              string bucketName, string endpoint = null)
    {
        // 初始化 SDK 客户端
    }

    protected override void UploadDirectoryInternal(string localDirectory)
    {
        // 遍历目录并上传
    }

    protected override bool UploadFileInternal(string localFilePathAndName)
    {
        // 单文件上传实现
        return true;
    }
}
```

Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L5-L35)

## 验证

1. 在 `manifest.json` 中保存提供方包依赖后，回到 Unity，等包管理器解析完成，控制台无红色报错。
2. 写一行 `Activator.CreateInstance<YourUploadManager>()` 测试代码，能成功执行不抛 `MissingMethodException`。
3. 调用 `UploadFile` 返回 `true`，并在云厂商控制台看到新对象出现。
