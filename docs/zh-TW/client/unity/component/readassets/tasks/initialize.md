# 初始化與根路徑取得

本頁說明 `BlankReadAssets` 如何初始化，以及如何在不同平台上讀取 `Root` 路徑。框架會在第一次呼叫任何 API 時自動完成初始化。在大多數情況下，您不需要手動呼叫。只有當您需要在呼叫其他 API 之前取得根路徑時，才需要明確進行初始化。

## 前置條件

- 已透過 Unity Package Manager 匯入 `com.gameframex.unity.readassets`。
- 專案中存在 `Assets/StreamingAssets/` 目錄，且待讀取的資源已放置於其中。
- 已加入 `using GameFrameX.ReadAssets.Runtime;`。

## 步驟

1. **直接讀取根路徑（自動初始化）**。框架內部使用 `EnsureInitialized()` 來保護延遲載入，在第一次存取 `Root` 時自動呼叫 `Initialize()`。在 Android 平台上，實作會切換為 `ApkImpl`；在 Editor、Standalone、iOS、WebGL 等其他平台上，則使用 `LooseFilesImpl`。

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    string root = BlankReadAssets.Root;
    UnityEngine.Debug.Log("StreamingAssets Root = " + root);
    ```

    來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L46-L54)

2. **手動呼叫無參數初始化**。此多載使用 `Application.dataPath` 和 `Application.streamingAssetsPath` 作為初始化參數。

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    BlankReadAssets.Initialize();
    string root = BlankReadAssets.Root;
    ```

    來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L56-L61)

3. **使用自訂路徑初始化**。在測試或外部資源目錄的情境中，傳入任意的 `dataPath` 和 `streamingAssetsPath`。

    ```csharp
    BlankReadAssets.Initialize(
        dataPath: "/path/to/your/project",
        streamingAssetsPath: "/path/to/your/project/Assets/StreamingAssets");
    ```

    來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L63-L68)

4. **在非 Android 平台上，`Root` 取自 `streamingAssetsPath`**。LooseFilesImpl 會將傳入的 `streamingAssetsPath` 轉換為絕對路徑、替換反斜線、移除結尾斜線，然後指派給 `s_root`。

    ```csharp
    // LooseFilesImpl.Initialize 中的實作
    s_root = Path.GetFullPath(streamingAssetsPath).Replace('\\', '/').TrimEnd('/');
    ```

    來源：[BlankReadAssets.LooseFilesImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L17-L20)

5. **在 Android 平台上，`Root` 為 APK 路徑**。ApkImpl 會將 `dataPath` 指派給 `s_root`，並在找不到內容時回退到 `base.apk`；在補丁覆蓋（patch overlay）情境中，`s_root` 為 `pram-shadow-files` 目錄。

    ```csharp
    // ApkImpl.Initialize 中的實作
    s_root = dataPath;
    ```

    來源：[BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

## 常見變化

- **在 Editor 中指定外部 APK 檔案進行讀取**。僅在 `UNITY_EDITOR` 下可用，允許在編輯器中模擬 Android 壓縮 APK 路徑的存取。

    ```csharp
    BlankReadAssets.InitializeWithExternalApk("/path/to/your.apk");
    string root = BlankReadAssets.Root;
    ```

    來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

- **在 Editor 中使用外部 StreamingAssets 目錄**。與 InitializeWithExternalApk 搭配使用；停用 ApkMode 後，仍會以目錄形式讀取。

    ```csharp
    BlankReadAssets.InitializeWithExternalDirectories(
        dataPath: "/path/to/project",
        streamingAssetsPath: "/path/to/project/Assets/StreamingAssets");
    ```

    來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

- **停用延遲載入並提前完成初始化**。在某些情境中（例如應用程式啟動後立即檢查檔案是否存在），您可能會希望在呼叫其他 API 之前完成初始化。可以明確呼叫無參數的 `Initialize()`。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `Root` 是空字串或異常路徑 | 在 Android 上，未等待 APK 路徑就先進行讀取，而 ApkImpl 的 `s_root` 取決於 `dataPath` | 使用 `BlankReadAssets.Initialize()` 讓框架以 `Application.dataPath` 完成初始化，或先存取任一 API 以觸發 `EnsureInitialized` |
| 在 Editor 中將 APK 當作目錄來遍歷 | 未呼叫 `InitializeWithExternalApk` | 明確呼叫 `InitializeWithExternalApk(apkPath)` 以切換至 ApkImpl |
| 使用自訂路徑時出現 `ArgumentNullException` | `dataPath` 或 `streamingAssetsPath` 傳入了 null | 檢查上游設定，避免向 `Initialize(string, string)` 傳入 null 值 |

## 背景（選讀）

平台實作會在編譯時期透過 `using BlankReadAssetsImpl = ...` 靜態別名進行切換，確保不同的目標平台呼叫不同的 `Initialize`。`EnsureInitialized()` 與 `s_initialized` 靜態旗標共同確保初始化只會發生一次，所有後續的讀取 API 都會重複使用第一次呼叫的結果。這就是為什麼可以從任何地方安全地存取 `Root`。
