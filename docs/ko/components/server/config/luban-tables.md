# Luban 설정 테이블과 TablesComponent 로딩 사용하기

`TablesComponent`는 GameFrameX.Config에서 Luban 도구로 자동 생성된 설정 테이블 컨테이너로, 런타임에 모든 `.json` 설정 테이블을 `ConfigComponent`에 로드하고 테이블 간 참조 관계를 분석하는 역할을 합니다. 이 페이지를 읽고 나면 서버 또는 클라이언트 시작 시 모든 Luban 테이블을 한 번에 로드하고, 필요에 따라 개별 항목에 접근할 수 있습니다.

## 사전 조건

- Luban 도구로 `GameFrameX.Config` 프로젝트를 생성했으며, 산출물에 `TablesComponent.cs`와 `Tables/*.cs`, `Local/*.cs`가 포함되어 있어야 합니다.
- 프로젝트가 `GameFrameX.Core.Abstractions`을(를) 참조하고 있어야 합니다(`ConfigComponent`와 `BeanBase` 제공).
- Luban에서 내보낸 JSON 파일(`tables_tbxxx`, `local_tblocalization` 등 네이밍 규칙)을 준비하고, `loader` 콜백이 읽을 수 있는 위치(로컬 파일, AssetBundle, 원격 다운로드 모두 가능)에 배포합니다.

## 작업 단계

1. **설정 관리자 인스턴스화**. `ConfigComponent` 내부에 이미 `TablesComponent`가 생성되어 있으므로 그대로 사용하면 됩니다:

   ```csharp
   var configComponent = new ConfigComponent();
   var tables = configComponent.Tables; // private 속성, 아래의 Init을 통해 주입 필요
   ```

   출처: [ConfigComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/ConfigComponent.cs#L14-L19)

2. **`Init` 호출하여 `ConfigComponent` 주입**. 이 단계에서는 테이블 등록 진입점을 `ConfigComponent`에 넘기고, 이후 `Add` 시 테이블을 통합 컨테이너에 기록합니다:

   ```csharp
   tables.Init(configComponent);
   ```

   출처： [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

3. **`loader` 콜백 제공 및 비동기 로딩**. `loader`는 테이블 이름을 받아 해당 테이블 JSON의 `JsonElement`를 반환합니다. 모든 테이블이 병렬로 로드되며, 완료 후 자동으로 `Refresh`가 참조를 분석합니다:

   ```csharp
   await tables.LoadAsync(async tableName =>
   {
       var json = await File.ReadAllTextAsync($"Configs/{tableName}.json");
       return JsonDocument.Parse(json).RootElement.Clone();
   });
   ```

   출처： [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L56)

4. **개별 테이블 및 항목 읽기**. 로딩 완료 후 `TablesComponent`의 강타입 속성을 통해 구체적인 테이블 객체를 가져옵니다. 예를 들어:

   ```csharp
   var itemConfig = tables.TbItemConfig;
   var oneItem = itemConfig.Get(1001); // Luban이 생성한 인덱스/조회 메서드
   ```

   `TablesComponent`가 현재 노출하는 테이블 속성: `TbLocalization`, `TbAchievementConfig`, `TbItemConfig`, `TbSoundsConfig`.

   출처: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L18-L21)

5. **(선택 사항) 핫 업데이트 시나리오에서 재로딩**. `LoadAsync`를 다시 호출하기 전에 `Init`은 필요하지 않습니다. `loader`가 각 테이블의 최신 JSON을 다시 읽고, `Refresh()`가 `PostInit`과 `ResolveRef`를 다시 실행하여 이전 참조 관계를 덮어씁니다.

## 일반적인 변형

- **원격 다운로드 + 로컬 캐시**: `loader`를 「먼저 로컬 캐시를 조회하고, 미스 시 HTTP로 요청하며, 다운로드 후 디스크에 저장하고 JSON을 분석하는」 방식으로 구현하면 Luban 테이블이 CDN 핫 업데이트를 지원할 수 있습니다.
- **AssetBundle에서 읽기**: 클라이언트에서 `loader`를 `Resources.LoadAsync<TextAsset>(tableName).Result.text`로 교체하면 되며, 함수 시그니처만 유지하면 `TablesComponent`를 수정할 필요가 없습니다.
- **일부 테이블 지연 로딩**: 시작 시 로드할 필요가 없는 테이블을 `LoadAsync`에서 주석 처리하고(주석 처리된 코드는 생성 파일에 보존되어 있음), 비즈니스 측에서 필요할 때 `new TbXxx(...)`로 로드하도록 변경합니다.

## 일반적인 오류

- **테이블 JSON을 찾을 수 없음**: `loader`가 예외를 던지면 `Task.WhenAll`이 실패하고 전체 `LoadAsync`가 예외를 던집니다. 파일 이름이 `tables_xxx` / `local_xxx` 접두사를 엄격히 따르는지 확인하세요.
- **참조 분석 실패**: `Refresh()` 내부에서 각 테이블의 `ResolveRef(this)`를 호출합니다. `PostInit` 또는 `ResolveRef`에서 아직 로드되지 않은 테이블에 접근하면 null 참조가 발생하므로, 관련된 모든 테이블이 `LoadAsync`를 거치도록 보장해야 합니다.
- **`Init` 중복 호출**: `Init`을 다시 호출하면 `RemoveAllConfigs()`가 다시 실행되어 이미 로드된 테이블 참조가 비워지므로, 일반적으로 리셋 시나리오에서만 사용합니다.
- **생성 파일 수정**: `TablesComponent.cs`와 `Tables/*.cs` 상단에 모두 `// <auto-generated>`가 표시되어 있으며, 수동으로 수정한 내용은 다음 번 Luban 재생성 시 덮어써집니다.

## 배경(선택 사항)

`TablesComponent`는 Luban `gen_cs_server_json` / `gen_cs_client_json` 템플릿의 산출물입니다. 각 테이블은 하나의 `BeanBase` 하위 클래스(예: [`ItemConfig`](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Tables/ItemConfig.cs#L15-L76))에 대응하며, 생성자는 `JsonElement`에서 필드를 역직렬화하고, `ResolveRef`는 테이블 간에 `xxx_ref` 필드를 구체적인 행 객체에 다시 연결하는 데 사용됩니다.
