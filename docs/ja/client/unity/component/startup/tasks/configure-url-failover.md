# URL プライマリ/バックアップ failover 戦略の設定方法

`UrlFailoverRunner.ExecuteAsync` を使用すると、一連の URL を順番にプライマリ/バックアップ切替し、各 URL に対して最大 N 回のリトライを行うことができます。このページでは、そのままコピーして実行できる最小限の使用方法、パラメータの意味、およびよくある落とし穴を紹介します。

## 前提条件

- プロジェクトに `com.gameframex.unity.startup` パッケージがインストールされ、`GameFrameX.Startup.Runtime` 名前空間が参照されていること。
- ビジネス側で `Func<string, UniTask<UrlAttemptResult>>` デリゲートを実装し、単一の URL に対して実際のリクエスト(GET/POST など)を送信し、レスポンスに応じて `UrlAttemptResult.Succeed()` または `UrlAttemptResult.Fail(errorMessage)` を返すこと。
- `Cysharp.Threading.Tasks` と `UniTask` の非同期機構が導入済みであること(`using Cysharp.Threading.Tasks;`)。

## 操作手順

1. **URL リストを準備する**。候補 URL を「プライマリ—バックアップ—バックアップ…」の順序で `IReadOnlyList<string>` に格納します。実行時には配列のインデックス順に順番に試行されます。

2. **単一 URL 試行デリゲートを実装する**。各 URL に対して 1 回リクエストを送信し、HTTP ステータスコードまたはビジネスコードに基づいて成功または失敗の結果を返します。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;
   using UnityEngine.Networking;

   UniTask<UrlAttemptResult> TryFetchAsync(string url)
   {
       return UniTask.RunOnThreadPool(async () =>
       {
           using var req = UnityWebRequest.Get(url);
           await req.SendWebRequest();
           if (req.result == UnityWebRequest.Result.Success)
           {
               return UrlAttemptResult.Succeed();
           }
           return UrlAttemptResult.Fail(req.error ?? "unknown error");
       });
   }
   ```

   Source: [UrlAttemptResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlAttemptResult.cs#L6-L27)

3. **`UrlFailoverRunner.ExecuteAsync` を呼び出す**。URL リスト、各 URL の最大試行回数、リトライ間隔(ミリ秒)、および前のステップで作成したデリゲートを渡します。

   ```csharp
   using System.Collections.Generic;
   using System.Threading;
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   public async UniTask<UrlFailoverResult> RunAsync(CancellationToken ct = default)
   {
       var urls = new[] { "https://api-primary.example.com", "https://api-backup.example.com" };

       return await UrlFailoverRunner.ExecuteAsync(
           urls,
           maxAttemptsPerUrl: 3,
           retryDelayMs: 500,
           attempt: TryFetchAsync,
           onProgress: (url, attempt, total) =>
               UnityEngine.Debug.Log($"try {attempt}/{total} -> {url}"),
           cancellationToken: ct);
   }
   ```

   Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L14-L43)

4. **返された `UrlFailoverResult` を処理する**。成功時はビジネスデータを使用し、失敗時は `FailedUrl` と `ErrorMessage` に基づいて、フォールバックロジックを実行するかテレメトリとして報告するかを判断します。

   ```csharp
   var result = await RunAsync(this.GetCancellationTokenOnDestroy());
   if (!result.Success)
   {
       UnityEngine.Debug.LogError($"all URLs failed. last={result.FailedUrl}, err={result.ErrorMessage}");
       return;
   }
   ```

   Source: [UrlFailoverResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverResult.cs#L6-L30)

## よくあるバリエーション

- **同期的な書き方(単体テストでよく見られる)**。デリゲートを `UniTask.FromResult(...)` を即座に返すように書くだけで、待機は不要です。

  ```csharp
  var result = await UrlFailoverRunner.ExecuteAsync(
      new[] { "http://a", "http://b" },
      maxAttemptsPerUrl: 2,
      retryDelayMs: 0,
      attempt: url => UniTask.FromResult(
          url == "http://b" ? UrlAttemptResult.Succeed() : UrlAttemptResult.Fail("down")));
  ```

  Source: [UrlFailoverRunnerTests.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Tests/Runtime/UrlFailoverRunnerTests.cs#L63-L85)

- **リトライせず、プライマリ/バックアップ切替のみ行う**。`maxAttemptsPerUrl` を `1`、`retryDelayMs` を `0` に設定すると、「1 回失敗したらすぐに次の URL へ切り替わる」動作となり、遅延はありません。

  ```csharp
  await UrlFailoverRunner.ExecuteAsync(urls, maxAttemptsPerUrl: 1, retryDelayMs: 0, attempt: TryFetchAsync);
  ```

  Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L68-L71)

- **プログレスコールバック付き**。`onProgress(url, attempt, total)` は各試行の前に発火し、`attempt` は `1` からカウントされるため、UI のプログレスバーを駆動するのに便利です。

  Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L57-L57)

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 同期的に `ArgumentNullException` がスローされる、パラメータ名は `urls` | URL リストに `null` を渡した | 少なくとも `new string[0]` 以外のリストを渡すこと。空の配列は `ArgumentException` をスローします |
| 同期的に `ArgumentException` がスローされる、"URL list must contain at least one URL." と表示される | 空の配列 `new string[0]` を渡した | 少なくとも 1 つの URL を含めること |
| 同期的に `ArgumentException` がスローされる、"Max attempts per URL must be greater than zero." と表示される | `maxAttemptsPerUrl < 1` | 各 URL の試行回数を ≥ 1 に設定すること |
| 同期的に `ArgumentException` がスローされる、"Retry delay must be zero or greater." と表示される | `retryDelayMs < 0` | `0` または正の整数に設定すること |
| 同期的に `ArgumentNullException` がスローされる、パラメータ名は `attempt` | 試行デリゲートに `null` を渡した | `attempt` に有効な `Func<string, UniTask<UrlAttemptResult>>` を渡すこと |
| すべての URL が失敗したとき、ビジネス側は `result.Success == false` を受け取るが、`FailedUrl` が空文字列 | どの URL でも失敗パスが呼び出されなかった(ほとんど発生しない)、またはすべての失敗が握りつぶされた | デリゲート内で常に `UrlAttemptResult.Fail(...)` を返しているかを確認すること |

これらのパラメータ制約を検証する実装は、`UrlFailoverRunner.ExecuteAsync` の入口にあります。

## 背景(オプション)

`UrlFailoverRunner` は静的ユーティリティクラスであり、「URL の順序 × 各 URL の試行回数」の 2 層ループで実行されます。外側のループは `urls` を順に走査し、内側のループでは 1 つの URL に対して渡された `attempt` デリゲートを、成功するか `maxAttemptsPerUrl` を使い切るまで繰り返し呼び出します。いずれかの URL が成功すると、直ちに `UrlFailoverResult.Succeed()` を返し、以降の URL は試行しません。すべての URL のすべてのリトライが失敗した場合にのみ、最後に失敗した URL とエラーメッセージを含む `UrlFailoverResult.Fail(...)` を返します。`retryDelayMs > 0` の場合、同一 URL の 2 回の試行の間に `UniTask.Delay` で待機します。`maxAttemptsPerUrl == 1` の場合は待機もリトライも行いません。
