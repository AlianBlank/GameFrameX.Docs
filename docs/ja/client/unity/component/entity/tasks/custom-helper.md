# Helper をカスタマイズしてデフォルト実装を置き換える方法

`EntityHelperBase` と `EntityGroupHelperBase` の派生クラスをカスタマイズすることで、エンティティのインスタンス化・生成・解放のロジックを引き継ぐことができます。`EntityComponent` では、リフレクションによる型名（`m_EntityHelperTypeName` / `m_EntityGroupHelperTypeName`）と、Inspector への直接ドラッグ＆ドロップ（`m_CustomEntityHelper` / `m_CustomEntityGroupHelper`）という 2 つの置き換え方法が提供されています。

## 前提条件

- GameFrameX Entity コンポーネントパッケージがインストール済みで、シーン内で `EntityComponent` を見つけられること。
- C# の継承と Unity の `MonoBehaviour` の基本的な使い方を理解していること。
- カスタム Helper クラスは、リフレクションで読み込み可能なアセンブリに配置する必要があります（コードトリミングツールによって削除されないようにするため）。

## 操作手順

1. **カスタムエンティティ Helper クラスを新規作成**し、`EntityHelperBase` を継承して 3 つの抽象メソッドを実装します。

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;
using UnityEngine;
using YooAsset;

namespace MyGame.Entity
{
    public class MyEntityHelper : EntityHelperBase
    {
        public override object InstantiateEntity(object entityAsset)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return null;
            }
            return handle.InstantiateSync();
        }

        public override IEntity CreateEntity(object entityInstance, IEntityGroup entityGroup, object userData)
        {
            var go = entityInstance as GameObject;
            if (go == null)
            {
                Log.Error("Entity instance is invalid.");
                return null;
            }
            go.transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform);
            return go.GetOrAddComponent<Entity>();
        }

        public override void ReleaseEntity(object entityAsset, object entityInstance)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return;
            }
            handle.Release();
            Destroy((Object)entityInstance);
        }
    }
}
```

出典: [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L41-L101)

2. **（任意）カスタムエンティティグループ Helper クラスを新規作成**し、`EntityGroupHelperBase` を継承します。この基底クラス自体には抽象メンバーがないため、必要に応じて子オブジェクト管理のロジックを追加するだけで十分です。

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

namespace MyGame.Entity
{
    public class MyEntityGroupHelper : EntityGroupHelperBase
    {
        // ここでエンティティグループノードの管理を拡張します
    }
}
```

出典: [EntityGroupHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityGroupHelperBase.cs#L39-L41)

3. **シーン内で `EntityComponent` を開き、置き換え方法を選択します（どちらか一方）**：

   - **方式 A（リフレクションによる型名）**：`Entity Helper Type Name` または `Entity Group Helper Type Name` フィールドを、名前空間を含む完全なクラス名に変更します。例：`MyGame.Entity.MyEntityHelper`。
   - **方式 B（Inspector での直接ドラッグ＆ドロップ）**：上記の Helper を実装した `MonoBehaviour` プレハブを `Custom Entity Helper` または `Custom Entity Group Helper` フィールドにアタッチします。

```csharp
// EntityComponent の関連フィールド宣言
[SerializeField] private string m_EntityHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityHelper";
[SerializeField] private EntityHelperBase m_CustomEntityHelper = null;

[SerializeField] private string m_EntityGroupHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityGroupHelper";
[SerializeField] private EntityGroupHelperBase m_CustomEntityGroupHelper = null;
```

出典: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L62-L68)

4. **シーンを実行して検証します**。`EntityComponent.Start()` は以下の優先順位で Helper を生成します。まず Inspector 上の `m_CustomEntityHelper` に値が設定されているかを確認し、未設定の場合は `m_EntityHelperTypeName` を使って `Helper.CreateHelper` によるリフレクション生成を行い、それでも空の場合は `Can not create entity helper.` とエラーを出します。

```csharp
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
}
```

出典: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L171-L175)

## よくあるバリエーション

| ケース | 手法 |
|------|------|
| エンティティグループノードのアタッチ方法のみを置き換えたい | `EntityGroupHelperBase` を派生させ、`EntityHelperBase` はデフォルト実装のまま使用する |
| Helper 内で Unity のライフサイクルにアクセスしたい | 基底クラスが継承している `MonoBehaviour` のメソッド（`Awake/OnEnable/...`）をそのまま使用する |
| アセンブリのトリミングによってリフレクションに失敗する | `link.xml` または `[Preserve]` 属性でカスタム Helper クラスを保持する（[GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L6-L24) の保持方法を参考）|

## よくあるエラー

| エラー現象 | 原因 | 修正 |
|----------|------|------|
| 起動ログに `Can not create entity helper.` と出力される | リフレクション用の型名が空またはスペルミスがあり、かつ `CustomEntityHelper` がドラッグされていない | 型名に名前空間が含まれていることを確認する。例：`MyGame.Entity.MyEntityHelper` |
| カスタム Helper 内の `Awake` が発火しない | Inspector ドラッグではなくリフレクション生成のパスが使われている | 方式 B に変更して Helper を `m_CustomEntityHelper` フィールドにアタッチするか、`CreateEntity` 内で自分で `Instantiate` を呼び出して関連付ける |
| `ReleaseEntity` 後もオブジェクトが実際には破棄されない | オーバーライド時に `Object.Destroy` の呼び出しが漏れている | `ReleaseEntity` の末尾で `Destroy((Object)entityInstance)` を呼び出す |
| リリースビルドで `MissingReferenceException` が発生する | カスタムクラスがコードトリミングされた | `[Preserve]` 属性を付与するか、`link.xml` に記述する |

## 背景（任意）

`EntityComponent` の組み込みフィールドはデフォルトで `DefaultEntityHelper` / `DefaultEntityGroupHelper` を指しており、その内部では YooAsset の `AssetHandle` に依存してインスタンス化と解放を行っています（[DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L48-L100) を参照）。カスタム Helper が存在する意義は、フレームワークを変更せずに、Addressables、独自のリソースパイプライン、オブジェクトプール付きのインスタンス化方式などへ置き換えられるようにすることです。
