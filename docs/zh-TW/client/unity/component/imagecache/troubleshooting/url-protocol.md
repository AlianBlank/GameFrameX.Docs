# URL 通訊協定驗證失敗時的處理方法

呼叫 `LoadImageAsync` 時，若傳入的 URL 不是以 `http://` 或 `https://` 開頭，元件會直接拒絕載入，並在主控台輸出警告。此次呼叫會回傳 `null`，且不會觸發下載或快取流程。

## 快速診斷

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 主控台輸出 `ImageCache: url must start with http:// or https://. url: ...`，且 `LoadImageAsync` 回傳 `null` | URL 缺少通訊協定前綴，或協定並非 http/https（例如：`ftp://`、`file://`、`data:`、相對路徑、`www.example.com/x.png` 等） | 在 URL 字串前補上 `http://` 或 `https://` |
| URL 看起來正確但驗證失敗 | URL 前後包含多餘的空白、換行或不可見字元 | 呼叫前使用 `Trim()` 移除開頭與結尾的空白 |
| URL 通過驗證但載入失敗 | URL 協定有效，但資源無法使用、網路不通或伺服器回傳錯誤 | 請參閱下方的「通過驗證後仍載入失敗」章節 |

## 修正步驟

### 1. URL 缺少通訊協定前綴

驗證邏輯僅接受 `http://` 與 `https://` 兩種前綴。其他協定或原始網域名稱皆會被拒絕。

```csharp
// 無效 —— 原始網域名稱會被拒絕
string bad1 = "www.example.com/img.png";
string bad2 = "example.com/img.png";

// 有效
string good1 = "http://www.example.com/img.png";
string good2 = "https://www.example.com/img.png";
```

來源：[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L78-L82)

### 2. URL 開頭或結尾有多餘空白

`StartsWith` 驗證會區分大小寫，且不會自動去除空白，因此若開頭有空白，前綴比對將會失敗。建議在呼叫前明確執行 `Trim`。

```csharp
string rawUrl = "  https://example.com/img.png  ";
string url = rawUrl.Trim();

var tex = await ImageCacheComponent.Instance.LoadImageAsync(url);
```

### 3. URL 通過驗證但載入失敗

驗證僅檢查協定前綴，並不會驗證資源是否實際可下載。若日誌中未出現 "url must start with ..." 訊息，請依照以下順序確認。

- 主控台輸出 `ImageCache: url is null or empty.` —— 傳入的字串為 `null` 或空字串。請指定有效的 URL。
- 主控台輸出下載失敗事件（`DownloadFailure`）—— 伺服器回傳 404/403、網路逾時或跨網域限制。請檢查伺服器狀態與 HTTPS 憑證。
- WebGL 平台：通過驗證後會呼叫 `LoadImageWebGLAsync`，由瀏覽器負責快取。若瀏覽器回報 CORS 錯誤，伺服器必須回傳正確的跨網域標頭。

來源：[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## 驗證

1. 在呼叫前，透過列印或中斷點確認 URL 以 `http://` 或 `https://` 開頭，且開頭與結尾沒有空白。
2. 執行 `LoadImageAsync` 後，若回傳非空的 `Texture2D`，且主控台未顯示 "url must start with" 警告，即表示驗證通過且載入成功。
3. 若仍回傳 `null`，請對照上方的診斷表確認日誌關鍵字，以找出具體的失敗階段。
