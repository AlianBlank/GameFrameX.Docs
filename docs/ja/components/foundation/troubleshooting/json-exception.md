# JSON シリアル化例外とデシリアル化失敗の対処方法

`JsonHelper.Serialize`、`Deserialize`、`TryDeserialize` が例外をスローしたり、`false` を返したり、予期しない結果を返したりした場合は、本ページの診断表で対応する症状を見つけ、具体的な例外メッセージに基づいて修復手順を選択してください。`JsonHelper` が提供する `Try*` API と `JsonHelperError` は、例外をスローせずにエラー分類を伝えるため、問題の特定にはまずこちらを使用してください。

## 修復手順

### 修復 1:引数が null または空文字列

`JsonHelper` の `Serialize` / `Deserialize` / `TryDeserialize` はすべて最初のパラメータ検証を行います。`Serialize` は `obj` が null の場合、直接 `ArgumentNullException` をスローします。`Deserialize` は `json` が null / 空 / 純粋な空白の場合、`ArgumentNullException` または `ArgumentException` をスローします。`TryDeserialize` は例外をスローせず、`false` を返し、付随する `JsonHelperError` を提供します。

```csharp
using GameFrameX.Foundation.Json;

// デシリアル化時にまず文字列を検証
if (string.IsNullOrWhiteSpace(json))
{
    return; // または業務例外をスロー
}

var user = JsonHelper.Deserialize<User>(json);
```

```csharp
using GameFrameX.Foundation.Json;

// 推奨:例外のオーバーヘッドを避けるために TryDeserialize を使用する
if (JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    // 成功
}
else if (error.Kind == JsonHelperErrorKind.InvalidInput)
{
    // 引数が不正
}
```

### 修復 2:JSON は有効だがターゲット型と一致しない

典型的な症状:`JsonException` には `The JSON value could not be converted to <type>` または `is not a valid value for <type>` が含まれます。一般的な原因は以下の通りです:

- フィールドは `int` だが JSON では文字列 `"123"`( `AllowReadingFromString` を有効にしていない場合は失敗します。`DefaultOptions` では既に有効化されています)。
- フィールドは `DateTime` だが JSON では `"2024-01-01T00:00:00Z"` でタイムゾーンが一致しない。
- フィールドは `Guid` だが JSON では空文字列または引用符が欠落している。
- 多態型:JSON はサブクラスだが、親クラスのフィールドに `[JsonDerivedType]` メタデータがない。

修復の推奨事項:

1. `JsonHelper.DefaultOptions`(既に `PropertyNameCaseInsensitive`、`AllowReadingFromString`、`AllowNamedFloatingPointLiterals`、`AllowTrailingCommas` を有効化)を使用していることを確認する。
2. 疑わしい JSON を `JsonHelper.Deserialize<Dictionary<string, object>>(json)` に個別に貼り付けて、構文が有効かどうかを検証する。
3. `DateTime`/`Guid`/`decimal` のような問題が発生しやすいフィールドは、DTO に明示的に `[JsonConverter]` を付けるか、文字列形式が正しいことを確認する。
4. 多態型には `[JsonDerivedType(typeof(SubType), "sub")]` を追加し、JSON に `"$type"` フィールドを含める。

```csharp
// 多態型の例
[JsonPolymorphic(TypeDiscriminatorPropertyName = "$type")]
[JsonDerivedType(typeof(Dog), "dog")]
[JsonDerivedType(typeof(Cat), "cat")]
public abstract class Animal { public string Name { get; set; } }

public class Dog : Animal { public string Breed { get; set; } }
```

### 修復 3:列挙値またはプロパティ名の一致

`JsonHelper.DefaultOptions` には `JsonStringEnumConverter` が組み込まれており、列挙型を文字列としてシリアル化します(例えば `"Active"` で `0` ではない)。カスタム `JsonSerializerOptions` を作成し、このコンバータを追加しなかった場合、列挙型は数値として書き出されます。

同様に、`DefaultOptions` は `PropertyNameCaseInsensitive = true` と `PropertyNamingPolicy = null`(プロパティ名を維持)に設定されています。自分で options を new した場合、これら 2 つのスイッチはデフォルトで false となり、JSON のフィールド名と `PascalCase` で厳密に一致するようになります。

修復:

- 必ず `JsonHelper.DefaultOptions` または `JsonHelper.CreateDefaultOptions()` を通じて設定を生成する。
- `DefaultOptions` に `PropertyNamingPolicy` を再度設定しないでください。設定すると書き込み側で大文字小文字が変更されます。

```csharp
using GameFrameX.Foundation.Json;

// 推奨される書き方
var opts = JsonHelper.CreateDefaultOptions();
var json = JsonHelper.Serialize(obj, opts);

// デシリアル化にも DefaultOptions または CreateDefaultOptions() を使用する
var restored = JsonHelper.Deserialize<MyDto>(json, opts);
```

### 修復 4:循環参照

直接 `System.Text.Json.JsonSerializer.Serialize` を呼び出すと、デフォルトで `InvalidOperationException`(`A possible object cycle was detected`)がスローされます。`JsonHelper.DefaultOptions` は既に `ReferenceHandler = ReferenceHandler.IgnoreCycles` が設定されており、循環参照に遭遇すると `$ref` のようなプレースホルダとして直接スキップされます。

修復:必ず `JsonHelper` のエントリポイントを介してシリアル化し、迂回して直接 `JsonSerializer.Serialize(obj)` を呼び出さないでください。

```csharp
using GameFrameX.Foundation.Json;

// 正しい:循環参照は自動的に処理される
var json = JsonHelper.Serialize(order); // order -> user -> orders -> ...

// 間違い:InvalidOperationException がスローされる
var raw = System.Text.Json.JsonSerializer.Serialize(order);
```

### 修復 5:NaN / Infinity などの特殊な浮動小数点値

JSON が Python(`json.dumps(... allow_nan=True)`)または JavaScript から来ている場合、`NaN` / `Infinity` / `-Infinity` が含まれている可能性があります。`System.Text.Json` はデフォルトで `JsonException` をスローします。`JsonHelper` の `Deserialize<T>` では保護処理が行われており、例外をキャッチした後、`PreprocessSpecialFloatingPointValues` を呼び出して文字列を前処理し、再試行します。

コードが `JsonHelper` を介さずに直接 `JsonSerializer.Deserialize` を呼び出していたり、解析後に他のフラグメントをさらに `Deserialize` する場合、例外は再発します。`JsonHelper.Deserialize<T>(json)` を統一して使用してください。

```csharp
using GameFrameX.Foundation.Json;

// Python の出力: NaN / Infinity は JsonHelper によって自動的に処理される
var json = "{\"x\": NaN, \"y\": Infinity}";
var obj = JsonHelper.Deserialize<MyDto>(json); // 例外はスローされない
```

### 修復 6:フィールドが無視されるまたはデフォルト値にデシリアル化される

考えられる原因:

- プロパティが `private set` / `init` で `[JsonInclude]` がない。
- プロパティが `required` だが JSON にフィールドが欠落している。
- プロパティが `record` の主コンストラクタパラメータだが、`[JsonConstructor]` がない。
- プロパティに `[JsonIgnore]` が付与されている。
- フィールドが辞書 / コレクションだが JSON は配列(またはその逆)。

修復:DTO のプロパティが書き込み可能で、リフレクションで読み取り可能であることを確認する。不変型には `[JsonConstructor]` を追加する。業務フィールドに `[JsonIgnore]` を付けない。

### 修復 7:TryDeserialize を使用したエラー特定

`TryDeserialize` は決して例外をスローせず、`JsonHelperError` を介して以下を伝えます:

| `Kind` | 意味 | 推奨処理 |
|--------|------|----------|
| `None` | エラーは発生していない | 正常パス |
| `InvalidInput` | JSON 自体に構文エラーがある、null、空文字列、または options が null | 引数を確認し、`JsonSerializer.Deserialize<JsonElement>` で JSON 構文を検証する |
| `TypeMismatch` | JSON は有効だが、フィールドの型が一致しない | [型の不一致](#修復-2json-は有効だがターゲット型と一致しない) に移動 |
| `Serialization` | シリアル化フェーズが失敗(オブジェクト→JSON) | DTO にシリアル化できないメンバー(ポインタ、COM オブジェクトなど)がないか確認する |
| `Unknown` | 未分類のエラー、通常はランタイムのその他の例外 | `ExceptionType` と `Message` を確認し、`Path` / `LineNumber` で問題を特定する |

`JsonHelperError` は `Path`、`LineNumber`、`BytePositionInLine` も提供しており、JSON の具体的な位置を直接特定できます:

```csharp
using GameFrameX.Foundation.Json;

if (!JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    Console.WriteLine($"Kind={error.Kind}, Type={error.ExceptionType.Name}");
    Console.WriteLine($"Message={error.Message}");
    Console.WriteLine($"Path={error.Path}, Line={error.LineNumber}, Pos={error.BytePositionInLine}");
}
```

### 修復 8:ストリームとバイト配列の操作

`SerializeAsync(Stream, ...)` は、`stream` が null の場合、`ArgumentNullException`(`ArgumentNullException.ThrowIfNull(stream, nameof(stream))`)をスローします。書き込み先のストリームが既に `Dispose` されている場合も同様に失敗します。

```csharp
using System.IO;
using GameFrameX.Foundation.Json;

await using var ms = new MemoryStream();
await JsonHelper.SerializeAsync(ms, user); // OK
var bytes = ms.ToArray();

// FileStream を使用する場合、まずディレクトリの存在と書き込み可能性を確認する
await using var fs = File.Create("user.json");
await JsonHelper.SerializeAsync(fs, user);
```

## 検証

以下の順序で問題が解決されたことを確認します:

1. `TryDeserialize` が `true` を返し、`error.Kind == JsonHelperErrorKind.None` である。
2. デシリアル化されたオブジェクトのフィールド値が JSON の文字列/数値と一致する(出力して確認できます)。
3. シリアル化してからデシリアル化した結果が同じオブジェクトである(`JsonHelper.Serialize(obj) → JsonHelper.Deserialize<T>(...) == obj` の主要フィールドが等しい)。
4. 失敗する可能性のある引数(空文字列、異常な JSON、NaN を含む文字列)に対してそれぞれテストし、例外がスローされないことを確認する。

それでも失敗する場合は、`JsonHelperError` の `Path`、`LineNumber`、`Message` をチケットに貼り付けてください。問題を迅速に特定できます。
