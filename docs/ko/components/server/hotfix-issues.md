# 핫업데이트 로드 실패 또는 버전 불일치 시 대처 방법

서버를 시작하거나 핫업데이트가 트리거될 때 핫업데이트 DLL(`GameFrameX.Hotfix.dll`)의 로드, 버전 검증 또는 실행 초기화가 실패하면, 일반적으로 프로세스가 바로 종료되거나, 로그에 예외가 발생하거나, 클라이언트/관리 페이지에 버전 불일치 알림이 표시됩니다. 이 페이지에서는 일반적인 증상에 대한 빠른 대조표와 복구 절차를 제공합니다.

## 빠른 진단

| 증상 | 원인 | 복구 |
|------|------|------|
| `ArgumentException: dllPath` 또는 `hotfixDllName` 이 빈 값으로 예외 발생 | 전달된 `dllPath` 또는 `hotfixDllName` 이 빈 문자열임 | 기본값으로 파라미터를 전달, 자세한 내용은 "복구 절차-경로 및 파일명" 참조 |
| `GameFrameX.Hotfix.dll` 을 찾을 수 없고 파일이 존재하지 않다는 알림 표시 | DLL 이 실행 디렉터리에 복사되지 않았거나, 버전 디렉터리와 실제 디렉터리가 일치하지 않음 | DLL 을 `dllVersion/dllPath` 에 해당하는 디렉터리에 배치 |
| 로드 시 `OnLoadSuccess` 가 false 반환 | 핫업데이트 브리지 구현의 초기화 실패(의존 서비스 미시작, 설정 누락 등) | 시작 순서와 `AppSetting` 의 완전성 확인 |
| 클라이언트에 "버전 불일치" 알림 표시 | `dllVersion` 파라미터가 가리키는 디렉터리의 DLL 이 프레임워크 버전과 일치하지 않음 | 동일한 소스 코드로 핫업데이트 프로젝트를 재컴파일한 후 DLL 교체 |
| 핫업데이트 후 이전 모듈이 여전히 참조되어 클래스를 찾을 수 없음 | 리로드 중 이전 모듈이 동시 요청에 적중되어 에이전트 타입이 전환됨 | `DoingHotfix=false` 가 된 후 부하 테스트를 진행하거나 로그 분석 |
| 서비스 재시작 시 간헐적으로 `HotfixAssembly` 가 비어 있음 | 시작 순서에서 `LoadHotfix` 이전에 `HotfixManager.HotfixAssembly` 를 호출함 | 먼저 `LoadHotfix` 를 호출한 후 어셈블리에 접근하는지 확인 |

## 복구 절차

### 경로 및 파일명

`HotfixManager.LoadHotfix` / `LoadHotfixModule` 은 `dllPath`, `hotfixDllName` 에 대해 빈 값 검증을 수행하며, `dllVersion` 이 비어 있는지 여부에 따라 실제로 로드할 하위 디렉터리를 결정합니다.

- 기본 파라미터: `dllPath="hotfix"`, `hotfixDllName="GameFrameX.Hotfix.dll"`, `dllVersion=""`.
- `dllVersion` 이 비어 있지 않으면 `dllPath` 를 무시하고 버전 번호 하위 디렉터리 기준으로 DLL 을 로드합니다.

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
public static bool LoadHotfix(AppSetting setting,
    string dllVersion = "",
    string dllPath = "hotfix",
    string hotfixDllName = "GameFrameX.Hotfix.dll")
{
    ArgumentException.ThrowIfNullOrEmpty(dllPath, nameof(dllPath));
    ArgumentException.ThrowIfNullOrEmpty(hotfixDllName, nameof(hotfixDllName));
    // ...
    var path = Path.Combine(Environment.CurrentDirectory,
        string.IsNullOrEmpty(dllVersion) ? dllPath : $"{dllVersion}",
        hotfixDllName);
    var hotfixModule = new HotfixModule(path);
    var reload = _module != null;
    var success = hotfixModule.Init(reload);
    if (!success) { return false; }
    _module = hotfixModule;
    return true;
}
```

Source: [HotfixManager.cs#L95-L116](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L95-L116)

조치:

1. 실행 디렉터리에 실제로 `hotfix/GameFrameX.Hotfix.dll`(또는 `<dllVersion>/GameFrameX.Hotfix.dll`)이 존재하는지 확인합니다.
2. `dllPath` 를 수동으로 빈 문자열로 전달하지 마세요. 버전 디렉터리를 사용하는 경우 `dllVersion` 을 버전 문자열로 설정하고 기본 `dllPath` 는 유지합니다.
3. DLL 이름을 커스터마이징하는 경우 `hotfixDllName` 이 빌드 산출물과 일치하는지 확인합니다.

### 버전 번호와 DLL 불일치

`dllVersion` 이 가리키는 디렉터리의 DLL 이 프레임워크 호스트 버전과 맞지 않으면, "로드는 되지만 동작이 비정상"이거나 인터페이스 시그니처 불일치로 인한 `MissingMethodException` 이 발생할 수 있습니다.

1. 이전 버전 디렉터리를 삭제하고, 현재 `main` 브랜치 기반의 `GameFrameX.Hotfix` 프로젝트를 다시 컴파일합니다.
2. 새 DLL 을 대상 `dllVersion` 디렉터리(예: `1.0.0/GameFrameX.Hotfix.dll`)에 복사하여 호스트 프로세스가 가리키는 버전 번호와 일치시킵니다.
3. 서버를 시작하고 로그에서 `ReloadTime` 이 갱신되었는지 확인합니다(새 모듈이 초기화되었음을 의미).

`ReloadTime` 은 `LoadHotfixModule` 내부에서 갱신됩니다:

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
private static async Task<bool> Load(HotfixModule newModule, AppSetting setting, bool reload)
{
    ReloadTime = TimerHelper.GetNowWithUtc();
    if (reload)
    {
        // ... 이전 모듈은 10분 지연 후 Unload
    }
    _module = newModule;
    if (_module.HotfixBridge != null)
    {
        return await _module.HotfixBridge.OnLoadSuccess(setting, reload);
    }
    return true;
}
```

### `OnLoadSuccess` 가 false를 반환하는 경우

핫업데이트 브리지 인터페이스는 로드 성공 후 `OnLoadSuccess` 를 호출하며, `false` 를 반환하면 로드 실패로 간주합니다.

```csharp
// GameFrameX.Core/Hotfix/IHotfixBridge.cs
Task<bool> OnLoadSuccess(AppSetting setting, bool reload);
```

Source: [IHotfixBridge.cs#L45](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/IHotfixBridge.cs#L45)

조치:

1. `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`(또는 `ByMain` / `ByHeart`)를 열어 `OnLoadSuccess` 의 구현을 확인하고, 첫 단계에서 실패한 의존성을 파악합니다.
2. 해당 구현이 의존하는 서비스(예: 데이터베이스, Redis, HTTP 등록)가 호출 전에 이미 초기화를 마쳤는지 확인합니다.
3. `OnLoadSuccess` 내에서 각 단계에 더 상세한 로그를 추가하고, 핫업데이트를 다시 한 번 트리거한 뒤 추가된 로그를 통해 실패 지점을 파악합니다.

### 리로드 중의 동시 요청

`HotfixManager` 는 리로드 시 이전 모듈을 최대 10분간 캐시하며, 그 기간 동안 이전/새 모듈은 "요청이 어느 어셈블리에서 왔는지"에 따라 각각 라우팅됩니다. 이전 모듈이 이미 `Unload` 되었다면 에이전트 조회가 실패합니다.

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
if (reload)
{
    var oldModule = _module;
    DoingHotfix = true;
    var oldModuleHash = oldModule.GetHashCode();
    OldModuleMap.TryAdd(oldModuleHash, oldModule);
    _ = Task.Run(async () =>
    {
        await Task.Delay(TimeSpan.FromMinutes(10));
        OldModuleMap.TryRemove(oldModuleHash, out _);
        oldModule.Unload();
        DoingHotfix = !OldModuleMap.IsEmpty;
    });
}
```

Source: [HotfixManager.cs#L158-L172](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L158-L172)

조치:

1. 핫업데이트 트리거 후 10분 이내에는 서버를 재시작하거나 이전 모듈이 의존하는 인터페이스에 대한 대규모 부하 테스트를 피하세요.
2. 로그에 "Agent/Component type not found" 가 나타나면, 요청이 이전 모듈 어셈블리(이전 DLL 잔존)에서 왔는지 새 모듈 어셈블리에서 왔는지 확인합니다.
3. 이전 `hotfix` 디렉터리가 전체 교체되었는지 확인하여 `Environment.CurrentDirectory` 하위에 DLL 이 여러 개 존재하지 않도록 합니다.

## 검증

1. 서버를 시작했을 때 로그에 `ReloadTime` 이 기록되고 예외가 없으면 새 모듈이 적용된 것입니다.
2. `HotfixManager.GetAgent<T>(...)` 와 `GetComponentType(...)` 를 한 번 호출하여 새 모듈의 에이전트가 정상적으로 해석되는지 확인합니다.
3. 리로드 시나리오에서 `DoingHotfix` 플래그를 관찰합니다. 처음에는 `true` 여야 하며, 10분 후 `false` 로 돌아가고 이전 모듈이 해제됩니다.
4. 클라이언트/관리 페이지의 버전 번호가 `dllVersion` 하위 디렉터리와 일치하며, 정상적으로 로그인 및 메시지 송수신이 가능한지 확인합니다.
