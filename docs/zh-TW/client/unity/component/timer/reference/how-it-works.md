# 工作原理:執行緒安全更新迴圈與物件池

`TimerManager` 在每幀 `Update` 中以一個全域鎖(`Locker`)依序完成「掃描活動計時器 → 回收到期項 → 合併新增項」三段式更新；所有到期回呼先收集到 `_pendingCallbacks`,在鎖外統一執行，避免回呼裡再呼叫 Add/Remove 造成死結；被移除的 `TimerItem` 不銷毀，而是清空參考後推回 `Stack<TimerItem>` 物件池重複使用。

## 核心資料結構速查

| 成員 | 真實型別/預設值 | 作用 |
|------|-----------------|------|
| `_items` | `Dictionary<Action<object>, TimerItem>` | 活動計時器表，**以回呼委派為 key**(同一回呼只能有一個計時器) |
| `_toAdd` | `Dictionary<Action<object>, TimerItem>` | 待合併的新增計時器,`Add()` 先寫入這裡，幀末併入 `_items` |
| `_toRemove` | `List<TimerItem>` | 待回收項，Update 中統一清理 |
| `_pool` | `Stack<TimerItem>`,初始容量 100 | `TimerItem` 物件池，回收再利用 |
| `_pendingCallbacks` | `List<(Action<object> Callback, object Param)>` | 本幀到期回呼快取，鎖外執行 |
| `_ids` | `Dictionary<int, Action<object>>` | 計時器 ID → 回呼 的索引 |
| `_tags` | `Dictionary<string, List<int>>` | 標籤 → ID 清單 的分組索引 |
| `_nextId` | `int`,從 1 遞增 | ID 分配器 |
| `Locker` | `static readonly object` | 全域鎖物件，所有讀寫路徑共用 |
| `CatchCallbackExceptions` | `static bool`,預設 `false` | 為 `true` 時回呼例外會被吞掉並僅列印警告 |

## 每幀更新迴圈

`Update(float elapseSeconds, float realElapseSeconds)` 繼承自 `GameFrameworkModule`,每幀被框架驅動一次，整個狀態掃描在 `lock (Locker)` 內完成：

1. **跳過已刪除與已暫停項**:`Deleted` 的項進入 `_toRemove`;`IsPaused` 的項跳過累計但仍留在 `_items`。
2. **按時間縮放模式選擇時間來源**:`TimerTimeScale.Scaled` 使用 `elapseSeconds`,否則使用 `realElapseSeconds`。
3. **逐幀計時器**(interval <= 0)不累計時間，該幀直接觸發。
4. **一般計時器**累計 `Elapsed`,`Elapsed >= Interval` 時減去 `Interval` 並併入 `_pendingCallbacks`。
5. **重複次數扣減**:`Repeat > 0` 時每次觸發 `Repeat--`,減到 0 標記 `Deleted` 並進入 `_toRemove`。
6. **回收**：走訪 `_toRemove`,觸發 `OnComplete`,從 `_items`/`_ids`/`_tags` 移除，歸還物件池。
7. **合併**：將 `_toAdd` 併入 `_items` 並清空。

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    lock (Locker)
    {
        if (_items.Count > 0)
        {
            var enumerator = _items.GetEnumerator();
            while (enumerator.MoveNext())
            {
                var timerItem = enumerator.Current.Value;
                if (timerItem.Deleted)
                {
                    _toRemove.Add(timerItem);
                    continue;
                }

                // Paused timer: skip elapsed accumulation but remain in _items
                if (timerItem.IsPaused)
                {
                    continue;
                }

                // Select time source based on TimeScaleMode
                float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L58-L81)

時間累計與觸發判定(`Elapsed` 餘量超過 0.03 秒會被鉗制到 0,防止卡頓後連發)：

```csharp
timerItem.Elapsed += delta;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}

timerItem.Elapsed -= timerItem.Interval;
if (timerItem.Elapsed < 0 || timerItem.Elapsed > 0.03f)
    timerItem.Elapsed = 0;

if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}

if (timerItem.Callback != null)
{
    _pendingCallbacks.Add((timerItem.Callback, timerItem.Param));
}
```

## 回呼在鎖外執行(執行緒安全的關鍵)

`_pendingCallbacks` 的執行在 `lock` 區塊**之外**。這是刻意設計：回呼內部如果再呼叫 `Add`/`Remove`/`Exists`(它們各自會 `lock (Locker)`),在鎖內執行將直接死結——C# 的 `lock`/Monitor 對同一執行緒可重入，但真正的風險在於長時間持有鎖阻塞其他執行緒(如非同步/背景執行緒的續體)。把回呼移到鎖外後，回呼裡可以安全地增刪計時器。

```csharp
// Execute callbacks outside lock to avoid blocking other threads
if (_pendingCallbacks.Count > 0)
{
    for (int i = 0; i < _pendingCallbacks.Count; i++)
    {
        var (callback, param) = _pendingCallbacks[i];
        if (CatchCallbackExceptions)
        {
            try
            {
                callback(param);
            }
            catch (Exception e)
            {
                Debug.LogWarning("Timer callback error > " + e.Message);
            }
        }
        else
        {
            callback(param);
        }
    }

    _pendingCallbacks.Clear();
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L166-L190)

注意：回呼執行時若拋出例外且 `CatchCallbackExceptions == false`(預設),例外會向上傳播,`_pendingCallbacks` 不會清空——後續幀該清單會繼續被附加，可能重複執行同一批回呼。建議在遊戲初始化時把 `TimerManager.CatchCallbackExceptions = true` 開啟。

## 物件池：GetFromPool / ReturnToPool

`TimerItem` 是私用巢狀類別，取用時優先從 `_pool` 彈出並重置全部執行狀態欄位，池空才 `new`;歸還時清空所有委派與參數參考後推回，防止物件滯留(Object Retention)。

```csharp
private TimerItem GetFromPool()
{
    TimerItem t;
    if (_pool.Count > 0)
    {
        t = _pool.Pop();
        t.Deleted = false;
        t.Elapsed = 0;
        t.IsPaused = false;
        t.PausedElapsed = 0;
        t.TimeScaleMode = TimerTimeScale.Unscaled;
        t.Tag = null;
        t.OnComplete = null;
    }
    else
    {
        t = new TimerItem();
    }

    return t;
}

private void ReturnToPool(TimerItem t)
{
    t.Callback = null;
    t.Param = null;
    t.Tag = null;
    t.OnComplete = null;
    _pool.Push(t);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L623-L652)

歸還入口有兩處，均在鎖內呼叫：

| 歸還時機 | 位置 | 觸發 `OnComplete`? |
|----------|------|---------------------|
| Update 回收到期/刪除項(`Repeat` 用盡或標記 `Deleted`) | `Update` 內 `_toRemove` 清理迴圈 | 是,`i.OnComplete?.Invoke()` 在歸還前呼叫 |
| `Remove(callback)` 命中還在 `_toAdd`、尚未合併的項 | `Remove(Action<object>)` | 是，先 `t.OnComplete?.Invoke()` 再歸還 |

## Add 的三條路徑

`Add(...)` 在 `lock` 內按以下順序處理，同一次呼叫可能命中不同分支：

| 順序 | 條件 | 行為 |
|------|------|------|
| 1 | `callback == null` | 列印警告 `timer callback is null, {interval},{repeat}`,傳回 `0` |
| 2 | 回呼已在 `_items` | **就地更新**:`Set(...)` 重設參數、`Elapsed = 0`、清除 `Deleted/IsPaused`,傳回原 `Id` |
| 3 | 回呼已在 `_toAdd` | 同樣就地更新，傳回原 `Id` |
| 4 | 全新回呼 | `_nextId++` 分配 ID,`GetFromPool()` 取物件，寫入 `_toAdd`/`_ids`/`_tags`,傳回新 `Id` |

```csharp
int id = _nextId++;
t = GetFromPool();
t.Id = id;
t.Interval = interval;
t.Repeat = repeat;
t.Callback = callback;
t.Param = callbackParam;
t.Tag = tag;
t.TimeScaleMode = timeScale;
t.OnComplete = onComplete;
_toAdd[callback] = t;
_ids[id] = callback;
AddToTagIndex(t);
return id;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L260)

由於 key 是回呼委派本身，**對同一個 lambda/方法重複 `Add` 不會產生第二個計時器**，而是重置已存在的那個——包括把 `Elapsed` 歸零和解除暫停。

## Remove 的兩段式

`Remove(callback)` 命中 `_toAdd` 時直接刪除並歸還物件池(該計時器從未進入掃描迴圈)；命中 `_items` 時只做 `t.Deleted = true` 延遲標記，實際回收發生在下一幀 `Update` 的 `_toRemove` 清理迴圈。`Remove(int id)` 同理：先經由 `_ids` 查到回呼，再走相同邏輯。

```csharp
public void Remove(Action<object> callback)
{
    lock (Locker)
    {
        if (_toAdd.TryGetValue(callback, out var t))
        {
            _toAdd.Remove(callback);
            _ids.Remove(t.Id);
            RemoveFromTagIndex(t);
            t.OnComplete?.Invoke();
            ReturnToPool(t);
            return;
        }

        if (_items.TryGetValue(callback, out t))
        {
            t.Deleted = true;
        }
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L324-L343)

## Shutdown 行為

`Shutdown` 在鎖內清空 `_toRemove`、`_toAdd`、`_items`、`_ids`、`_tags`、`_pendingCallbacks`——注意**不歸還物件到 `_pool`、不觸發任何 `OnComplete`**,元件銷毀後池物件隨管理器一起釋放。

## 外層元件與驅動方式

`TimerComponent` 是 Unity 端的 `GameFrameworkComponent`,`Awake` 中透過 `GameFrameworkEntry.GetModule<ITimerManager>()` 取得 `TimerManager` 實例，自身全部 API 僅做一行轉發。真正的每幀驅動來自框架基底類別 `GameFrameworkModule` 對 `Update` 的呼叫,`TimerComponent` 上掛有 `[GameFrameXAutoComponent(-5000)]` 決定其自動註冊順序。

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");
        return;
    }
}
```
