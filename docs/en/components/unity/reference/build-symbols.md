# Build Macros and Conditional Compilation Symbols Reference

This page summarizes the **build macros / conditional compilation symbols** actually used by the GameFrameX framework in source code, Assembly Definitions, and Unity Player Settings, and explains each symbol's effective platforms, where it is defined, and how to enable or detect it in a project.

> Any symbol prefixed with `UNITY_` is automatically injected by the Unity engine; framework custom symbols (such as `ENABLE_GAME_FRAME_X_HYBRID_CLR`) are automatically injected via the `asmdef`'s `versionDefines`.

## Symbol Quick Reference

| Symbol | Scope | Definition Source | Purpose |
|------|--------|----------|------|
| `UNITY_EDITOR` | Editor assembly | Auto-injected by Unity | Code blocks that take effect only in the editor |
| `UNITY_ANDROID` | Android platform | Auto-injected by Unity | Android platform-specific logic |
| `UNITY_IOS` | iOS platform | Auto-injected by Unity | iOS platform-specific logic |
| `UNITY_STANDALONE` | Standalone platforms (Win/Mac/Linux) | Auto-injected by Unity | Desktop-specific logic |
| `UNITY_2018_1_OR_NEWER` | Version detection | Auto-injected by Unity | Version compatibility branches |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` | Assemblies with HybridCLR hot update enabled | `versionDefines` (detects the `com.code-philosophy.hybridclr` package) | Controls code paths related to HybridCLR integration |

> For the complete list of Unity platform/version macros, see the official Unity documentation (runtime symbols do not appear in source code, but are recognized automatically by the compiler).

## Framework Custom Symbol: ENABLE_GAME_FRAME_X_HYBRID_CLR

This symbol is currently the **only** custom macro at the framework level that is injected via the `asmdef`'s `versionDefines`. When the `com.code-philosophy.hybridclr` package is installed in the project, Unity automatically injects this macro into the `GameFrameX.Startup.Application` assembly, thereby enabling code paths related to HybridCLR hot updates.

```json
{
    "name": "GameFrameX.Startup.Application",
    "references": [
        "GameFrameX.Runtime",
        "HybridCLR.Runtime",
        "HybridCLRData"
    ],
    "versionDefines": [
        {
            "name": "com.code-philosophy.hybridclr",
            "expression": "",
            "define": "ENABLE_GAME_FRAME_X_HYBRID_CLR"
        }
    ]
}
```

Source: [Unity.Startup.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Unity.Startup.asmdef#L33-L39)

### Usage Example

```csharp
using UnityEngine;

namespace GameFrameX
{
    public static class HotUpdateGate
    {
        public static bool IsHotUpdateSupported
        {
            get
            {
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
                return true;
#else
                return false;
#endif
            }
        }
    }
}
```

### Verifying That the Macro Is in Effect

In Unity, run the menu **Window → General → Test Runner**, or read it via reflection in any script:

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
    Debug.Log("HybridCLR is enabled; hot update code will go into the hot update assemblies.");
#else
    Debug.LogWarning("HybridCLR is not enabled; Startup will run in AOT mode.");
#endif
```

If the output contains the text *HybridCLR is enabled*, it means `ENABLE_GAME_FRAME_X_HYBRID_CLR` has been successfully injected.

## Practical Usage of Platform Macros

### Android Platform-Specific Settings

`ProjectSettingEditor.cs` disables the safe area restriction on the Android platform and writes a team ID placeholder; on non-Android platforms, this branch is stripped out by the compiler.

```csharp
public override void OnInspectorGUI()
{
    base.OnInspectorGUI();
    PlayerSettings.assemblyVersionValidation = false;
#if UNITY_ANDROID
    PlayerSettings.Android.renderOutsideSafeArea = true;
#endif
#if UNITY_IOS
    PlayerSettings.iOS.appleDeveloperTeamID = "XXXXXX";
#endif
}
```

Source: [ProjectSettingEditor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/ProjectSettingEditor/ProjectSettingEditor.cs#L28-L52)

### Version Compatibility Branches

`AutoCopySymbolsPostprocessor.cs` uses `UNITY_2018_1_OR_NEWER` to block out the 32-bit x86 architecture handling logic (Android x86 builds have not been supported since Unity 2018.1).

```csharp
#if UNITY_2018_1_OR_NEWER

#else
    if ((PlayerSettings.Android.targetArchitectures & AndroidArchitecture.X86) > 0)
    {
        var dir = CopySymbols(symbolsDir, abi_x86);
        GenerateAllSymbols(dir);
    }
#endif
```

Source: [AutoCopySymbolsPostprocessor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/AutoCopySymbolsPostprocessor.cs#L46-L54)

## Platform-Level Assembly Isolation

`includePlatforms` / `excludePlatforms` control whether an assembly participates in the build for the corresponding platforms; **no** additional macros are needed.

| Assembly | includePlatforms | Effect |
|--------|------------------|------|
| `Unity.Editor` | `["Editor"]` | Editor builds only; not included in player packages |
| `Unity.Startup` / `Unity.HotFix` / `HybridCLRData` | `[]` (all) | Participates in builds for all platforms |

Source: [Unity.Editor.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/Unity.Editor.asmdef#L11-L13)

## Common Mistakes

| Symptom | Cause | Fix |
|------|------|------|
| x86 lib files remaining on Android devices | The outdated pre-`UNITY_2018_1_OR_NEWER` code path is active | Upgrade Unity to 2018.1+ so the macro correctly strips out x86 handling |
| HotFix assembly not included in the build | Obsolete macros such as `UNITY_HOTFIX` are misused | Use the modern HybridCLR-injected `ENABLE_GAME_FRAME_X_HYBRID_CLR` or configure `includePlatforms` |
| Player package still contains Editor tooling code | The `Unity.Editor` assembly's `includePlatforms` is not set to `Editor` | Explicitly declare `"includePlatforms": ["Editor"]` in the `.asmdef` |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` is never defined | The HybridCLR package is not installed or the package name is misspelled | Verify in the Package Manager that `com.code-philosophy.hybridclr` is installed, and check that `versionDefines.name` in the `asmdef` is spelled consistently |

## Adding Custom Build Macros

1. Open the corresponding `.asmdef` and add `defineConstraints` or `versionDefines` at the root level (for package-management-controlled definitions).
2. For global effect (not controlled by package management), use **Edit → Project Settings → Player → Other Settings → Scripting Define Symbols**.
3. Reference them in C# code using the standard `#if SYMBOL_NAME ... #endif` syntax; at build time, Unity automatically strips out non-matching branches based on the current target platform.
