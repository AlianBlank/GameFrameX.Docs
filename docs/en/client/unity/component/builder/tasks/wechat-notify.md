# How to Push WeCom (Enterprise WeChat) Notifications

After the build completes, the framework pushes the build result to a specified group via a WeCom group bot Webhook, including key information such as resource version, platform, channel, and build time. This page explains how to enable and configure the notification.

## Prerequisites

- A group bot has been added to the WeCom group, and its Webhook Key has been obtained (Bot details page → "Copy Webhook Address", the string after `key=`).
- You are familiar with the basic usage of Unity command line arguments (in the `-xxx value` form).

## Steps

1. **Prepare the Webhook Key**

   On the WeCom group bot details page, find an address like `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`, and copy the content after `key=`.

2. **Pass the Key to the Build Command Line**

   When calling `Builder.BuildAsset`, add the `-WeChatBotKey <YourKey>` argument. The framework will parse it into `BuilderOptions.WeChatBotKey` and use it to send notifications after the resource build completes.

   ```bash
   -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
   -WeChatBotKey 693axxx6-7aoc-4bc4-97c0-0d2cxxxxxxab
   ```

   Source: [Editor/Builder.BuildParamsParse.cs#L131-L135](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L131-L135)

3. **Framework Automatically Triggers the Notification**

   When the build finishes, if `WeChatBotKey` has been passed in, `WeChatNotifyWorkHelper.Run` will be called to send a markdown message to the WeCom Webhook. An example message is as follows:

   ```
   ### Game Resource Version Update
   > Time: 2024-05-20 10:30:00
   > Resource Version: 1.0.0
   > Game Version: 1.0.0
   > Game Package Name: com.example.game
   > Resource Package Name: DefaultPackage
   > Resource Platform: Android
   > Channel: default
   > Resource Language: default
   ```

   The actual method called:

   ```csharp
   WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
   ```

   Source: [Editor/Builder.BuildAsset.cs#L139](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L139)

4. **Key Snippets of the Interface Implementation**

   ```csharp
   var url = $"https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key={builderOptions.WeChatBotKey}";

   var markdownContent = $"### Game Resource Version Update\n> Time:{DateTime.Now:yyyy-MM-dd HH:mm:ss}\n> Resource Version:{buildParameters.PackageVersion}\n> Game Version:{UnityEngine.Application.version}\n> Game Package Name:{UnityEngine.Application.identifier}\n> Resource Package Name:{buildParameters.PackageName}\n> Resource Platform:{buildParameters.BuildTarget.ToString()}\n> Channel:{builderOptions.ChannelName}\n> Resource Language:{builderOptions.Language}";
   var payload = new
   {
       msgtype = "markdown",
       markdown = new { content = markdownContent }
   };
   var stringContent = new StringContent(JsonConvert.SerializeObject(payload), Encoding.UTF8, "application/json");
   var httpResponseMessage = httpClient.PostAsync(url, stringContent).GetAwaiter().GetResult();
   var response = httpResponseMessage.Content.ReadAsStringAsync().GetAwaiter().GetResult();
   Debug.Log(response);
   ```

## Common Variations

- **Build only, no notification**: Do not pass `-WeChatBotKey`. `WeChatBotKey` defaults to an empty string, and no requests will be sent.
- **Modify the notification content**: The notification content is hardcoded in `WeChatNotifyWorkHelper.Run`. To add or remove fields, directly modify the `markdownContent` string.
- **Modify the push URL or message type**: The current implementation hardcodes the WeCom webhook with `msgtype=markdown`. To switch to DingTalk/Feishu or other `msgtype`, you need to modify both `payload` and `url`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| No messages received in the group | `-WeChatBotKey` not passed, or Key copied incorrectly (common: extra spaces, missing suffix) | Re-copy all characters after `key=` in the bot's Webhook address, and ensure the command line argument is complete |
| Console prints a JSON response with non-zero `errcode` | Key has expired, or the bot has been deleted | Recreate the bot in the WeCom group, and update the Key in the command line |
| Garbled Chinese characters or emojis showing as question marks in the notification | Not a Key issue; typically related to encoding on the bot receiving end | Check the WeCom client version, or use plain text in `markdownContent` |
| Exception printed by `Debug.LogException` but the build still succeeds | Network unreachable or timeout (timeout is 30 seconds) | Check the network connectivity of the build machine, or increase `httpClient.Timeout` |

## Background

The framework only calls `WeChatNotifyWorkHelper.Run` once at the end of the resource build (`BuildAsset`) flow, and it only actually sends a request when `WeChatBotKey` is passed in; the timeout is 30 seconds, exceptions are caught by `try/catch` and output via `Debug.LogException`, and will not interrupt the build.
