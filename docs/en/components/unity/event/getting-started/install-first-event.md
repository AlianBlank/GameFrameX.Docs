# Install and Run Your First Event

This page walks you through the entire process from scratch: install the `com.gameframex.unity.event` package → add the `EventComponent` component → define an event argument class → subscribe → fire an event → see the callback printout in the Console. Just copy everything as-is and it will work.

## Prerequisites

- Unity 2019.4 or above (see the README badge for details).
- The GameFrameX runtime base package has been imported into your project (`EventComponent` inherits from `GameFrameworkComponent` and references the `GameFrameX.Runtime` namespace).
- This package itself has no other dependencies.

## Steps

### 1. Install the Package

Choose either of the following methods to edit the Unity project's `Packages/manifest.json`:

**Option A: Scoped Registry (Recommended)**

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.event": "1.1.1"
  }
}
```

`scopes` controls which packages are resolved through this registry; only packages starting with `com.gameframex` will be fetched from this registry.

**Option B: Direct Git URL Dependency**

```json
{
   "com.gameframex.unity.event": "https://github.com/gameframex/com.gameframex.unity.event.git"
}
```

Alternatively, in Unity's `Packages Manager`, use the `Git URL` method to add the address `https://github.com/gameframex/com.gameframex.unity.event.git`, or download the repository directly and place it into the project's `Packages` directory for automatic detection.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L40-L69)

### 2. Add the EventComponent Component

`EventComponent` is the Unity entry point of the event system. It is added via the component menu **Component → GameFrameX → Event** (the menu path is defined by `[AddComponentMenu("GameFrameX/Event")]`). It carries the `[GameFrameXAutoComponent(-7000)]` attribute and is created automatically during the full GameFrameX startup flow; manually attaching it to any persistent GameObject works just as well. In `Awake`, the component obtains the manager instance via `GameFrameworkEntry.GetModule<IEventManager>()`; on failure, it prints `Log.Fatal("Event manager is invalid.")` and stops working.

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L77)

### 3. Define an Event Argument Class

Each event is carried by a class inheriting from `GameEventArgs`, identified by a string `Id`:

```csharp
public class LevelUpEventArgs : GameEventArgs
{
    public override string Id => "level_up";
    public int Level { get; private set; }

    public static LevelUpEventArgs Create(int level)
    {
        var args = ReferencePool.Acquire<LevelUpEventArgs>();
        args.Level = level;
        return args;
    }

    public override void Clear()
    {
        base.Clear();
        Level = 0;
    }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L75-L94)

`GameEventArgs` is an abstract base class in the `GameFrameX.Event.Runtime` namespace (inheriting from `BaseEventArgs`); custom events must derive from it:
[GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L30-L40)

### 4. Subscribe to and Fire an Event

Create a new test script and attach it to the scene. The callback signature is fixed as `void(object sender, GameEventArgs e)`, i.e., `EventHandler<GameEventArgs>`:

```csharp
using GameFrameX.Event.Runtime;
using UnityEngine;

public class FirstEventDemo : MonoBehaviour
{
    private EventComponent m_EventComponent;

    private void Start()
    {
        m_EventComponent = GetComponent<EventComponent>();
        if (m_EventComponent == null)
        {
            m_EventComponent = FindObjectOfType<EventComponent>();
        }

        // Subscribe: automatically subscribes when not present; safe to call repeatedly
        m_EventComponent.CheckSubscribe("level_up", OnLevelUp);

        // Fire the event: deferred mode, callback on the main thread next frame
        m_EventComponent.Fire(this, LevelUpEventArgs.Create(5));
    }

    private void OnLevelUp(object sender, GameEventArgs e)
    {
        var args = (LevelUpEventArgs)e;
        Debug.Log($"升级到 {args.Level} 级");
    }

    private void OnDestroy()
    {
        // Safely unsubscribe if present; does nothing if the handler doesn't exist
        m_EventComponent.CheckUnsubscribe("level_up", OnLevelUp);
    }
}
```

Sources: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L95-L131) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L96-L128)

### 5. Verify

Run the scene; the Console should print `升级到 5 级`. Note that `Fire` is deferred dispatch — the event callback happens on the **next frame** after it is fired. If you don't see the log in the current frame, wait one frame before checking.

## Common Variants

**Immediate Dispatch `FireNow`**: The event is dispatched synchronously and immediately, but it is **not thread-safe**; only call it from the main thread.

```csharp
m_EventComponent.FireNow(this, LevelUpEventArgs.Create(5));
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

**Quick Fire Without Custom Arguments**: When no data needs to be carried, use a string event ID directly; an `EmptyEventArgs` is created internally:

```csharp
m_EventComponent.Fire(this, "level_up");
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

**Default Handler Fallback**: Set a fallback callback for events with no subscribers; commonly used to troubleshoot "event fired but nobody received it" issues:

```csharp
m_EventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

Sources: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L133-L140) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L142-L151)

**Statistics**: `Count(id)` queries the number of handlers for a single event, while `EventHandlerCount` / `EventCount` query global counts.
Sources: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) · [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L87)

## Common Errors

| Symptom | Cause | How to Avoid |
|------|------|----------|
| Console shows `Event manager is invalid.` (Fatal) | The component failed to obtain the manager via `GameFrameworkEntry.GetModule<IEventManager>()`, usually because the GameFrameX runtime base package is not ready | First confirm that the GameFrameX runtime package is installed and properly initialized, then attach `EventComponent` |
| No callback in the same frame after `Fire` | `Fire` is deferred dispatch; the event callback occurs on the main thread on the next frame after firing | This is expected behavior; use `FireNow` when an immediate synchronous callback is required |
| Abnormal behavior after firing an event from a worker thread | `FireNow` was called from a non-main thread | Worker threads must only use `Fire` (thread-safe) |
| Event arguments contain stale data | The custom event argument class forgot to override `Clear()` to reset fields, leaving old values behind when pooled instances are reused | Follow the example in Step 3 and reset each field one by one in `Clear()` |
| The same callback gets subscribed multiple times | `Subscribe` is called in multiple places without an existence check | Use `CheckSubscribe` (subscribes only when absent) / `CheckUnsubscribe` (unsubscribes only when present), or call `Check` first before acting |
