# Opening, Closing, and Recycling UI Forms

This page explains the UI form lifecycle usage of the FairyGUI version of `UIManager`: how to trigger opening (including singleton deduplication and instance pool reuse), how to recycle after closing, and what to watch out for when recycling does not mean destruction. The external open/close entry points are inherited from `BaseUIManager` in the GameFrameX.UI package; this repository (plugin) implements the FairyGUI specifics by overriding `InnerOpenUIFormAsync` and `RecycleUIForm`.

## Prerequisites

- The `FairyGUIPackageComponent` component already exists in the scene. When setting the asset manager, `UIManager.SetResourceManager` executes `GameEntry.GetComponent<FairyGUIPackageComponent>()` and validates it with `GameFrameworkGuard.NotNull`; if it is missing, an error is thrown directly:

```csharp
public override void SetResourceManager(IAssetManager assetManager)
{
    base.SetResourceManager(assetManager);
    FairyGuiPackage = GameEntry.GetComponent<FairyGUIPackageComponent>();
    GameFrameworkGuard.NotNull(FairyGuiPackage, nameof(FairyGuiPackage));
}
```

Source: [UIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs#L87-L92)

- The recycle interval has a lower bound: in the constructor, if `m_RecycleInterval` is less than 10, it is forcibly set to 10 (seconds); that is, a UI form instance stays in the pool for at least 10 seconds before it can actually be released.
- UI form logic classes inherit from `FUI` (which inherits from `UIForm`) and access FairyGUI objects through the `GObject` property.

## Steps: Opening a UI Form

1. Request to open a UI form asynchronously. `InnerOpenUIFormAsync` is the convergence point for all open requests, with the signature:

```csharp
protected override async Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L64-L64)

2. If singleton open mode is enabled for this UI form type (`UseSingletonOpenMode(uiFormType)`), an already-opened form is reused directly and refocused, and a form still loading waits on the same task—no duplicate instantiation occurs:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }

    foreach (var value in m_LoadingUIForms)
    {
        if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
        {
            return await value.Task;
        }
    }
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L85)

3. If the singleton branch is not hit, it first attempts to retrieve from the instance pool (`m_InstancePool.Spawn(uiFormAssetName)`); on a hit, it completes the opening directly via `InternalOpenUIForm` with a new serial number, bypassing asset loading entirely:

```csharp
var uiFormInstanceObject = m_InstancePool.Spawn(uiFormAssetName);

if (uiFormInstanceObject != null)
{
    // Pool reuse also allocates a new request serial number, ensuring every open request is observable.
    int serialId = ++m_Serial;
    return InternalOpenUIForm(serialId, uiFormAssetPath, uiFormAssetName, uiFormType, uiFormInstanceObject.Target, pauseCoveredUIForm, false, 0f, userData, isFullScreen);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L87-L94)

4. If the pool also has none, it enters `InnerLoadUIFormAsync`: the package name is extracted from the asset path, and if the FairyGUI package is not yet loaded, it is loaded according to its source—the `Resources` directory is loaded synchronously with `FairyGuiPackage.AddPackageSync(assetPath)`; Bundle paths are loaded asynchronously with `FairyGuiPackage.AddPackageAsync`, then the UI form asset with the `_fui` suffix is loaded:

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Load from Resources
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

5. On a successful load, the `LoadAssetSuccessCallback` is invoked to create the UI form instance; on failure, it goes through `LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo)`, with the error message coming from `assetHandle.LastError`.

## Steps: Closing and Recycling

Closing a UI form eventually calls `RecycleUIForm`, overridden in this repository. Its complete logic: trigger `uiForm.OnRecycle()`, then get `DisplayObjectInfo` from the GameObject corresponding to `Handle`, and after obtaining the `GComponent`, return it to the instance pool; only when `isDispose == true` does it additionally `ReleaseObject` to truly destroy:

```csharp
protected override void RecycleUIForm(IUIForm uiForm, bool isDispose = false)
{
    uiForm.OnRecycle();
    var formHandle = uiForm.Handle as GameObject;
    if (!formHandle)
    {
        return;
    }

    var displayObjectInfo = formHandle.GetComponent<DisplayObjectInfo>();
    if (!displayObjectInfo)
    {
        return;
    }

    var component = displayObjectInfo.displayObject.gOwner as GComponent;
    if (component == null)
    {
        return;
    }

    m_InstancePool.Unspawn(component);
    if (isDispose)
    {
        m_InstancePool.ReleaseObject(component);
    }
}
```

Source: [UIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Close.cs#L53-L79)

Key points:

| Parameter | Behavior |
|------|------|
| `isDispose = false` (default) | `Unspawn` returns it to the instance pool; the object is retained and reused directly on the next open |
| `isDispose = true` | After returning it, `ReleaseObject` destroys and releases it |
| `Handle` is not a GameObject / missing `DisplayObjectInfo` / `gOwner` is not a `GComponent` | Returns early after only calling `OnRecycle()`, not pooled |

## Common Variants: Show and Hide Animations

The UI form class `FUI` overrides `Show` / `Hide`, handing the FairyGUI object to a handler to play animations; whether animations are played is controlled by `EnableShowAnimation` / `EnableHideAnimation` and the animation names `ShowAnimationName` / `HideAnimationName`; when the handler is null, the completion callback is invoked directly:

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}

public override void Hide(IUIFormHideHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableHideAnimation, HideAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

Source: [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L74-L105)

Another common variant is when the package name and the UI form asset name do not match: in that case, the package path is reassembled via `PathHelper.Combine(uiFormAssetPath, packageName)` before `AddPackageAsync`, then `_fui` is appended to load the UI form asset; see [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L158-L178) for details.

## Common Errors

- **A guard exception is thrown when opening a UI form because `FairyGuiPackage` is null**: `FairyGUIPackageComponent` is not attached or initialized. Add the component in the scene/entry point first, then call `SetResourceManager`.
- **Open fails but no details are visible**: In Bundle mode, the failure reason comes from `assetHandle.LastError` and finishes with `LoadAssetFailureCallback`; when troubleshooting, confirm that the path contains the Bundle directory name indicated by `BundlesDirectoryName` and that the package name can be correctly extracted from the asset path.
- **Memory does not drop after closing**: By default, `isDispose = false` only returns the instance to the pool, and the instance stays in the pool for at least `m_RecycleInterval` (lower bound of 10 seconds). This is expected behavior; recycle with `isDispose: true` when destruction is truly needed.
- **Duplicate instances appear when frequently opening and closing the same UI form**: Confirm that the UI form type has `UseSingletonOpenMode` enabled; when not enabled, every open goes through the pool/loading flow, and multiple simultaneous instances are allowed.
## Verification

- After opening, use the returned `IUIForm` to check whether `GObject` has been attached to `FUI.GObject`; opening a singleton form a second time should return the same instance and trigger `RefocusUIForm`.
- After closing, confirm that the UI form instance can be `Spawn`ed from the pool again for reuse (default path), or is no longer reusable after `isDispose: true` (destruction path).
- Animation path verification: the `Show`/`Hide` completion callback `complete` must be invoked; otherwise the upstream flow will not continue.

## Background

The open flow has three levels of short-circuiting: singleton deduplication → instance pool reuse → async loading. The `m_LoadingUIForms` list records in-progress load tasks to merge concurrent requests, and every open (including pool reuse) allocates a new `m_Serial` serial number for observability. On the recycle path, `FUI.InternalSetVisible` only changes visibility without firing events; the actual instance return/destruction is all concentrated in `RecycleUIForm`, completed based on `GComponent` and `m_InstancePool`.
