# What to Do When Build Configuration Does Not Take Effect

When the build settings, Plist, signing, or Capabilities you wrote in `XCodeConfig.json` are not reflected in the exported Xcode project, it is usually because: the configuration file was not found, JSON parsing failed, values were overwritten by another same-name configuration or a channel configuration, or the values were written to the wrong target node. This page walks you through locating and fixing each issue based on log clues.

The entry point for all configuration is `OnPostProcessBuild` in [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L25). It runs at the `[PostProcessBuild(888)]` priority and only for `BuildTarget.iOS`, and the entire file sits under `#if UNITY_IOS` conditional compilation; all internal exceptions are swallowed by `Debug.LogException`, **the build will not fail — it will simply skip silently**, so the first thing to do is check the Unity Console.

## Quick Diagnosis

| Symptom (Console log / Xcode project behavior) | Cause | Fix |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` (no XCodeConfig-related configuration files found, skipping settings) | The file name is not exactly `XCodeConfig.json`, the file was not imported by Unity as a TextAsset, or the current build is not for the iOS platform | See [Fix 1: Confirm the Configuration File Can Be Found](#fix-1-confirm-the-configuration-file-can-be-found) |
| `{jsonPath} 解析失败, 跳过合并` (failed to parse {jsonPath}, skipping merge) | Invalid JSON format (trailing commas, single quotes, comments, etc.) | See [Fix 2: Validate JSON Syntax](#fix-2-validate-json-syntax) |
| `合并后的配置为空，跳过设置` (merged configuration is empty, skipping settings) | All found files were empty or failed to parse | Same as above, and confirm the file actually has content |
| Configuration took effect but with wrong values | Multiple `XCodeConfig.json` files exist in the project; they are `Merge`d one by one in path order, **later merges overwrite earlier ones** | See [Fix 3: Investigate Same-Name File Overwrites](#fix-3-investigate-same-name-file-overwrites) |
| A configuration only takes effect / does not take effect on certain channels | The channel file `XCodeConfig.{channel}.json` is merged last and has the highest priority; the channel value comes from the `-channel` argument or the EditorPrefs key `XCodeBuild_Channel` | See [Fix 4: Check Channel Configuration and Residual Channels](#fix-4-check-channel-configuration-and-residual-channels) |
| Items under `properties` are not written to Build Settings | The configuration was placed at the top level instead of under the `unityMain` / `unityFramework` nodes, or was not organized into the three `"="` / `"+"` / `"-"` sub-tables | See [Fix 5: Confirm the Key Structure](#fix-5-confirm-the-key-structure) |
| A red exception stack trace in the Console | Runtime exceptions such as type mismatches (e.g., treating an array as an object); once caught, the entire post-processing is aborted | See [Fix 6: Read the Exception Stack Trace](#fix-6-read-the-exception-stack-trace) |
| Capabilities took effect but build properties were lost | Capabilities are written to disk independently by `ProjectCapabilityManager` and can be lost if another plugin rewrites `project.pbxproj` afterward (this tool mitigates this by re-reading) | See [Fix 7: Rule Out Overwrites by Higher-Priority Plugins](#fix-7-rule-out-overwrites-by-higher-priority-plugins) |

## Fix Steps

### Fix 1: Confirm the Configuration File Can Be Found

The loading logic is in [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58-L77): it iterates over all `t:textasset` assets and matches only files whose **file name is exactly** `XCodeConfig.json` (case-insensitive), regardless of the directory they are in.

1. Confirm the file name is exactly `XCodeConfig.json` (not `XCodeConfig.json.txt`, `xcodeconfig.json.bak`).
2. Confirm the file has been imported by Unity: select it in the Project window — the Inspector should show it as a Text Asset; a `.meta` file with the same name should exist in the directory.
3. Confirm it is an iOS build: `OnPostProcessBuild` returns directly when `target != BuildTarget.iOS` (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L17-L20)).
4. Confirm the current platform macro satisfies `#if UNITY_IOS` — if the project has never been switched to the iOS platform, the contents of the entire assembly will not be compiled.

### Fix 2: Validate JSON Syntax

Each file is parsed with `json.HashtableFromJson()`; on failure it outputs `解析失败, 跳过合并` (parse failed, skipping merge) and continues (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L39-L45)). The parser is a lightweight implementation that does not support comments, trailing commas, or single-quoted strings. Check the file with any JSON validator (such as the JSON language service in VS Code), paying attention to which `{jsonPath}` is printed in the error log.

### Fix 3: Investigate Same-Name File Overwrites

The tool collects **all** files named `XCodeConfig.json` in the project and merges them one by one after sorting (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L34-L49)):

```csharp
Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    ...
    finalConfig.Merge(table);
}
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L35-L49)

1. Search the Console for `[MergeConfig] 正在合并配置:` (merging configuration); the log lists the path and order of every file participating in the merge.
2. If a third-party plugin ships its own `XCodeConfig.json`, its same-name keys merged afterward will overwrite your values — delete it, rename it (a renamed file no longer participates in the merge), or move your own values into a channel file (channel files are merged last).

### Fix 4: Check Channel Configuration and Residual Channels

The channel identifier is read in this order: command-line argument `-channel` → EditorPrefs key `XCodeBuild_Channel` → null (see [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)):

```csharp
public static string GetChannel()
{
    var args = Environment.GetCommandLineArgs();
    for (int i = 0; i < args.Length - 1; i++)
    {
        if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
        {
            return args[i + 1];
        }
    }

    string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
    if (!string.IsNullOrEmpty(editorChannel))
    {
        return editorChannel;
    }

    return null;
}
```

Source: [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)

1. The channel file must be named `XCodeConfig.{channel}.json` (e.g., `XCodeConfig.ioschina.json`), see [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111).
2. Channel files are merged last and have the highest override priority — if you find that "expected values were changed", first check whether a channel file was matched; the Console prints `[MergeConfig] 检测到渠道: {channel}` (channel detected) and `[MergeConfig] 正在合并渠道配置: {path}` (merging channel configuration).
3. **EditorPrefs persist across projects and sessions**. A channel previously set with `SetChannel("xxx")` still takes effect on the next build, causing an unwanted channel configuration to be merged. To clear it: pass an empty string to delete the key (see [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51)).

```csharp
GameFrameX.Xcode.Editor.SettingLoader.SetChannel(null); // Or pass an empty string to clear the residual channel
```

Source: [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51)

### Fix 5: Confirm the Key Structure

The first phase reads only a fixed set of top-level keys and dispatches them to their targets, see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L126):

| Top-Level Key | Write Target | Description |
|------|---------|------|
| `unityMain` | UnityMain (main) target | properties / frameworks / libs / files / folders / filesCompileFlag / otherLinkerFlag / runPathSearchPaths / pods |
| `unityFramework` | UnityFramework target | Same as above |
| `signing` | Main target | Signing; also reads `bundleId` for Capabilities |
| `plist` | Info.plist | See `RunPlist` |
| `environmentVariables` | Scheme environment variables | See `RunEnvironmentVariables` |
| `launcherArgs` | Scheme launch arguments (array) | See `RunArgument` |
| `capabilities` | Main target | Capabilities |
| `localizations` | Project (array) | Localization resources |
| `podfile` / `podSource` | Podfile | Full Podfile path / list of source addresses |
| `swiftBridging` | bool, default true | Swift bridging |
| `podInstall` | bool, default true | Whether to automatically run `pod install` |

Inside `properties`, entries are processed through three sub-tables: `"="` (direct set), `"+"` (append to list), and `"-"` (remove from list) (see [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L57)):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}
```

Source: [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L20-L25)

Common mistakes: putting `properties` at the top level instead of under `unityMain.properties`; writing list values that belong in `"+"` into `"="`; inconsistent key casing (Hashtable keys are case-sensitive).

### Fix 6: Read the Exception Stack Trace

The entire flow is wrapped in `try/catch`; exceptions are only logged with `Debug.LogException` and do not interrupt the build (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L158-L161)). If an exception appears in the Console, all configuration **after** the exception point will not execute — for example, if an exception is thrown before `plist`, then `capabilities`, `podfile`, and `pod install` are all skipped. Locate the specific key from the stack trace; it is usually a type mismatch (an object written as an array, or a string written as a number).

### Fix 7: Rule Out Overwrites by Higher-Priority Plugins

This tool runs at `[PostProcessBuild(888)]`, later than most post-processing (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L15)). If your other plugins have callbacks with a priority greater than 888, or they edit `project.pbxproj` / Info.plist directly without basing their edits on the content this tool wrote to disk, they will overwrite the configuration. Also note: Capabilities are written to disk independently via `ProjectCapabilityManager`, and this tool re-reads `project.pbxproj` afterward before continuing to write Localizations (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L121-L123)); make sure no third-party code rewrites the project file after that.

## Verification

1. Run an iOS build again; the Console should show the following in order:
   - `[MergeConfig] 正在合并配置: {path}` (merging configuration) for each participating file;
   - If a channel is set: `[MergeConfig] 检测到渠道: {channel}` (channel detected);
   - `[PBXProject] 正在应用最终合并配置...` and `[OtherSettings] 正在应用最终合并配置...` (applying the final merged configuration...);
   - No red exceptions.
2. Open `Unity-iPhone.xcodeproj/project.pbxproj` in the export directory, search for the build property name you set, and confirm the value has been updated.
3. Check the keys and values written to `Info.plist` by the `plist` node.
4. In Xcode, select the main target; the Signing & Capabilities tab should show the items configured by `capabilities`; `project.entitlements` should contain the corresponding entries.
