# XOR 簡易加密與解密的使用方式

`XorHelper` 提供了基於互斥或（XOR）運算的輕量級加密與解密工具。由於使用相同的金鑰對資料進行兩次 XOR 運算即可還原原始資料，因此適合用於設定檔或記憶體中臨時位元組串流的簡易混淆。注意：此方式並非密碼學上安全的做法，請勿用於需要保密性的場景。

## 前置條件

- 參考 NuGet 套件 `GameFrameX.Foundation.Encryption`（或直接參考 `GameFrameX.Foundation.Encryption/XorHelper.cs`）。
- 使用 `using GameFrameX.Foundation.Encryption;` 引入命名空間。

## 操作步驟

### 1. 最簡單的加密與解密

呼叫 `XorHelper.GetXorBytes(byte[], byte[])` 執行一次 XOR 運算，再以相同金鑰呼叫一次即可完成解密。兩次呼叫完全對稱，沒有加密 / 解密方法的區別。

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

var keyBytes = Encoding.UTF8.GetBytes("MySecretKey123");
var dataBytes = Encoding.UTF8.GetBytes("Hello, World! 这是一个测试字符串。");

// 加密
var encrypted = XorHelper.GetXorBytes(dataBytes, keyBytes);
// 解密（以相同金鑰再次呼叫）
var decrypted = XorHelper.GetXorBytes(encrypted, keyBytes);

Console.WriteLine(Encoding.UTF8.GetString(decrypted)); // 輸出原文
```

Source: [XorHelper.cs#L133-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L133-L144)

### 2. 選擇「就地修改」版本以節省記憶體

如果後續不需要保留輸入陣列的原始內容，可以使用 `GetSelfXorBytes` 直接改寫輸入陣列，無需另行配置新的位元組串流。

```csharp
var dataBytes = Encoding.UTF8.GetBytes("payload");
var keyBytes = Encoding.UTF8.GetBytes("key");

// 直接在 dataBytes 上執行 XOR，不回傳新陣列
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
// 再次呼叫以還原
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
```

Source: [XorHelper.cs#L158-L169](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L158-L169)

### 3. 僅加密資料開頭的 220 個位元組（高速模式）

若想對較大的位元組串流（例如協定封包標頭）進行輕量級混淆，但不想遍歷整個陣列，可以使用 `GetQuickXorBytes` / `GetQuickSelfXorBytes`。這些方法僅對開頭 `QuickEncryptLength`（預設 220）個位元組進行 XOR，之後的部分則保持原始值不變。

```csharp
var buffer = new byte[1024];           // 協定標頭 + 後續的承載資料
var key = Encoding.UTF8.GetBytes("k");

// 僅混淆開頭 220 個位元組，後續位元組保持不變
var encrypted = XorHelper.GetQuickXorBytes(buffer, key);
// 還原時也僅處理開頭 220 個位元組
var restored = XorHelper.GetQuickXorBytes(encrypted, key);
```

### 4. 僅加密陣列中的一部分範圍

使用帶有 `startIndex` 與 `length` 參數的多載方法，可以僅對指定範圍進行 XOR。適合「僅混淆開頭 / 中間某部分」之類的場景。

```csharp
var data = new byte[] { 1, 2, 3, 4, 5, 6, 7, 8 };
var key  = Encoding.UTF8.GetBytes("MySecretKey123");

// 僅加密從索引 2 開始的 4 個位元組
var result = XorHelper.GetXorBytes(data, 2, 4, key);
// data[0..2] 與 data[6..8] 不會被修改
```

## 常用方法速查表

| 方法 | 是否配置新陣列 | 加密範圍 | 適用場景 |
|------|----------------|----------|----------|
| `GetXorBytes(bytes, code)` | 有 | 整個陣列 | 一般的加密與解密、需要保留原文 |
| `GetSelfXorBytes(bytes, code)` | 無（就地修改） | 整個陣列 | 不需要原文、節省一次配置 |
| `GetQuickXorBytes(bytes, code)` | 有 | 開頭 220 個位元組 | 大型標頭的快速混淆 |
| `GetQuickSelfXorBytes(bytes, code)` | 無 | 開頭 220 個位元組 | 大型標頭的就地快速混淆 |
| `GetXorBytes(bytes, startIndex, length, code)` | 有 | 指定範圍 | 僅混淆開頭 / 中間部分 |
| `GetSelfXorBytes(bytes, startIndex, length, code)` | 無 | 指定範圍 | 僅對開頭 / 中間部分進行就地混淆 |

## 常見變體

### 金鑰比資料長 / 短 / 單一字元的金鑰

XOR 演算法對金鑰長度沒有限制，無論長短都能正確地加密與解密。測試中涵蓋了單一字元、3 位元組、14 位元組、34 位元組等各種金鑰，只要金鑰不為空，即可透過往返運算還原。

Source: [XorHelperTests.cs#L82-L116](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Encryption/XorHelperTests.cs#L82-L116)

### 字串的往返轉換

只需將字串直接以 `Encoding.UTF8.GetBytes` 傳入，再以 `Encoding.UTF8.GetString` 取回結果，適合用於設定檔中的敏感欄位。

## 常見錯誤

| 錯誤做法 | 現象 | 正確做法 |
|----------|------|----------|
| 將 `GetXorBytes` 的回傳值當作新陣列再次修改 | 混淆範圍會偏移 | 使用 `GetXorBytes` 的回傳值，或明確執行 `Array.Copy` 後再傳遞給 `GetSelfXorBytes` |
| 將 `Array.Empty<byte>()` 傳入 `code` | 會擲回 `ArgumentException("KeyArrayCannotBeEmpty")` | 使用至少 1 個位元組以上的金鑰 |
| 以 `GetQuickXorBytes` 處理 220 個位元組以內的完整資料時，誤以為其後的部分也會被加密 | 資料後半部保持原始狀態 | 若需要加密整份資料，請使用 `GetXorBytes` |
| `startIndex + length` 超過陣列長度 | 會擲回 `ArgumentOutOfRangeException` | 事先驗證 `startIndex + length <= bytes.Length` |
| 將其用作帳號密碼 / 傳輸金鑰 | 透過已知明文攻擊即可輕易破解 | 僅用於防止偶然讀取的混淆，需要保密的場景請使用正式的對稱加密演算法 |

## 背景（可選）

XOR 運算本質上滿足 `(A ^ K) ^ K == A`，因此可以使用相同的介面進行加密與解密。`QuickEncryptLength = 220` 是針對協定標頭場景設定的經驗值，是安全性與效能之間的折衷方案。所有公開方法都會先執行 `ArgumentNullException.ThrowIfNull` 與 `code.Length == 0` 驗證，帶有 offset / length 的多載方法還會驗證 `startIndex + length <= bytes.Length`。
