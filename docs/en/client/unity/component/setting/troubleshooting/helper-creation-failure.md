# What to Do When Helper Creation Fails

When `SettingComponent` fails to call `Helper.CreateHelper` during the `Awake` phase, the error log `Can not create setting helper.` appears in the Unity console, after which all configuration reads and writes fail because no Helper is attached. This page provides common causes and troubleshooting steps.

## Quick Diagnosis

| Symptom / Log | Cause | Fix |
|---|---|---|
| `Can not create setting helper.` and `m_CustomSettingHelper == null` | The `m_SettingHelperTypeName` spelling is incorrect, the namespace does not match, or the assembly containing the Helper type was stripped by IL2CPP/Managed Stripping | Check the fully qualified name according to the "Incorrect custom type name" section; for the built-in `PlayerPrefsSettingHelper`, see the "Code stripping causes the type to be lost" section |
| `Can not create setting helper.` and `m_CustomSettingHelper != null` | The custom Helper class does not inherit from `SettingHelperBase`, is not a `MonoBehaviour`, or lacks a parameterless constructor | Correct the inheritance and namespace according to the "Invalid custom Helper class" section |
| The error is still logged when `m_CustomSettingHelper != null` | The `Custom Setting Helper` field contains a disabled or missing script (the script is missing or its GUID is invalid) | Reattach a valid custom Helper asset, or leave `Custom Setting Helper` empty in the Inspector |
| `Can not create setting helper.` does not appear in the console, but subsequent `Save/Load` behavior is abnormal | `Awake` has not finished, or `SettingComponent` is not in the scene | Ensure that `SettingComponent` exists in the scene and is not destroyed in the same frame |

## Troubleshooting Steps

### 1. Incorrect custom type name or type not found

`SettingComponent` uses reflection to create a Helper by default from the fully qualified type name string `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`; if the string is incorrect, `Helper.CreateHelper` returns `null`.

Select the GameObject with `SettingComponent` in the scene and enter the correct fully qualified name in the `Setting Helper Type Name` field in the Inspector. See the default value below:

```csharp
[SerializeField] private string m_SettingHelperTypeName = "GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper";
```

Source: [SettingComponent.cs#L52](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52)

The namespace must match `using GameFrameX.Setting.Runtime;`; if you write your own Helper subclass, change the string to `YourNamespace.YourHelperClassName`.

### 2. Invalid custom Helper class

If you directly specify a Helper instance through `m_CustomSettingHelper`, the class must meet the following requirements:

- Inherit from `SettingHelperBase`; see [SettingComponent.cs#L43](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L43) for the abstract base class definition.
- Be a `MonoBehaviour` subclass, because `Helper.CreateHelper` calls `gameObject.AddComponent<T>()`.
- Have `[UnityEngine.Scripting.Preserve]` on the class or be referenced elsewhere, otherwise it may be stripped in IL2CPP builds.

Minimal valid example:

```csharp
using GameFrameX.Setting.Runtime;
using UnityEngine;

namespace MyGame.Settings
{
    [UnityEngine.Scripting.Preserve]
    public sealed class MySettingHelper : SettingHelperBase
    {
        public override int Count => 0;
        public override bool Load() => true;
        public override bool Save() => true;
        public override string[] GetAllSettingNames() => System.Array.Empty<string>();
        public override void GetAllSettingNames(System.Collections.Generic.List<string> results) { }
        public override bool HasSetting(string settingName) => false;
        public override bool RemoveSetting(string settingName) => false;
        public override bool GetBool(string settingName, bool defaultValue) => defaultValue;
        // Remaining Get/Set overloads are omitted; see PlayerPrefsSettingHelper
    }
}
```

After creating the custom Helper, drag the prefab into the `Custom Setting Helper` field in the Inspector so that `SettingComponent` uses it first:

```csharp
[SerializeField] private SettingHelperBase m_CustomSettingHelper = null;
```

Source: [SettingComponent.cs#L54](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L54)

### 3. Code stripping causes the type to be lost

Even if `m_SettingHelperTypeName` is completely correct, enabling `Managed Stripping Level > Low` during the build or using IL2CPP linking may cause the framework's Helper classes to be stripped if they are not referenced during static analysis.

The repository provides an empty `GameFrameXSettingCroppingHelper` to "pin" references to all Helper types in release builds:

```csharp
[UnityEngine.Scripting.Preserve]
public class GameFrameXSettingCroppingHelper : MonoBehaviour
{
    [UnityEngine.Scripting.Preserve]
    private void Awake()
    {
        _ = typeof(DefaultSetting);
        _ = typeof(DefaultSettingHelper);
        _ = typeof(DefaultSettingSerializer);
        _ = typeof(PlayerPrefsSettingHelper);
        _ = typeof(SettingComponent);
        _ = typeof(SettingHelperBase);
        _ = typeof(ISettingHelper);
    }
}
```

Source: [GameFrameXSettingCroppingHelper.cs#L41-L58](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/GameFrameXSettingCroppingHelper.cs#L41-L58)

Note that `SettingComponent` includes `[RequireComponent(typeof(GameFrameXSettingCroppingHelper))]`, so this Helper node is created automatically when `SettingComponent` is added. **Do not delete** this child object manually, as doing so breaks the `typeof(...)` reference chain in `Awake`, and the types may still be stripped.

If you add a custom Helper subclass, be sure to add `_ = typeof(YourHelperClass);` to this stripping list, or set `Managed Stripping Level` to `Low`/disabled under Project Settings → Player → Other Settings.

### 4. Accessing Setting before Awake

`SettingComponent.Awake` creates the Helper and calls `m_SettingManager.SetSettingHelper(settingHelper)`, after which `m_SettingManager.Load()` is executed in `Start`. If another script calls the `GameFramework.Setting.*` API in its `Awake`, the Helper has not yet been installed, resulting in "Helper creation failed" or read/write errors.

Fix: Move all Setting access to `Start` or later, or use `MonoBehaviour.Start` → `yield return null` in your own script before reading settings.

## Verification

After applying the steps above, perform the following three checks:

1. Start the scene and confirm that the console no longer prints `Can not create setting helper.` and does not print `Setting manager is invalid.` either.
2. Select the GameObject with `SettingComponent` in the Hierarchy. You should see a child object named `SettingHelper` (created by `settingHelper.name = "SettingHelper";`; see [SettingComponent.cs#L94](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L94)).
3. Run the unit test `PlayerPrefsSettingHelper_BoolUsesIntStorage` and others to verify that `SetBool/GetBool/HasSetting` all hit the persistent backend; see [UnitTests.cs#L11-L21](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Tests/UnitTests.cs#L11-L21).
