# 状態間でデータを共有する方法 (Variable)

`Fsm<T>` に組み込まれている `SetData` / `GetData` メソッドを使い、文字列を Key として `Variable` インスタンスを保存・取得することで、任意の 2 つの `FsmState<T>` 間でランタイムデータを安全に渡すことができます。

## 前提条件

- `FsmComponent.CreateFsm<T>`  finite state machine has been created and at least two states have been registered.
- The state class inherits from `FsmState<T>` and can access the FSM via the `fsm` parameter in `OnEnter` / `OnUpdate` / `OnExit`.
- The shared data type must inherit from `Variable` (built-in or custom).

## 操作手順

1. **共有データの型を確認する**:フレームワークはデータが `Variable` から派生していることを要求します。これは FSM がオブジェクトプール (`ReferencePool`) を使って `Variable` インスタンスを再利用し、GC を回避するためです。

   ```csharp
   // 整数の進捗を共有 (0~100)
   public sealed class ProgressVar : Variable
   {
       private int m_Value;
       public int Value
       {
           get => m_Value;
           set => m_Value = value;
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L46)

2. **状態 A でデータを書き込む**:`SetData<TData>(name, data)` を呼び出します。同じ名前のデータを再度書き込むと、古いインスタンスは自動的に `ReferencePool` に回収されます。

   ```csharp
   public class LoadingState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = new ProgressVar { Value = 0 };
           fsm.SetData("Progress", progress);
       }

       protected override void OnUpdate(IFsm<MyOwner> fsm, float elapseSeconds, float realElapseSeconds)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress != null)
           {
               progress.Value += 1; // Value を直接変更。再度 Set する必要なし
           }
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L497-L500)

3. **状態 B でデータを読み取る**:強い型付けの `GetData<TData>(name)` を使って派生クラスのインスタンスを直接取得します。キーが存在しない場合や型が一致しない場合は `null` を返します。

   ```csharp
   public class PlayState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress == null)
           {
               // ステートマシンがこのデータを持っていないため、必要に応じてフォールバック
               return;
           }
           fsm.Owner.Ui.ShowProgress(progress.Value);
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

4. **不要になったデータをクリーンアップする**:`RemoveData(name)` を呼び出すと、データオブジェクトはオブジェクトプールに回収されます。

   ```csharp
   fsm.RemoveData("Progress");
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L535)

## よくあるバリエーション

| シナリオ | 使い方 | 備考 |
|------|------|------|
| 正確な型は不明で、存在のみを確認したい | `fsm.GetData("Progress")` は `Variable` 基底クラスを返す | [Fsm.cs#L469](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488) を参照 |
| 複数の状態で同じキーを繰り返し上書きする | `SetData` を直接再度呼び出す | 古いインスタンスは自動的に `ReferencePool.Release` される ([Fsm.cs#L521-L524](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L521-L524)) |
| 共有データに GC 再利用を要求しない | 任意の `Variable` サブクラスを渡せる | フレームワークは基底クラスが `Variable` であることのみを強制する。フィールドは自由 |

## よくあるエラー

| エラー現象 | 原因 | 修正方法 |
|----------|------|------|
| `name` に空文字列を渡すと `GameFrameworkException("Data name is invalid.")` がスローされる | API は `name` が空でないことを要求する | 定数または列挙型を key として使用する |
| `GetData<TData>` が `null` を返し、NRE が発生する | その Key が一度も書き込まれていない、または型が一致しない | 書き込み側で `SetData` した後に読み取るか、まず `GetData(name)` で存在を確認する |
| 同じ名前のデータを繰り返し `new` するとメモリが増加する | `Variable` オブジェクトを再利用していない | 同じインスタンスを再利用し、内部フィールドのみを変更する。必要な場合のみ `SetData` で上書きする |
| FSM 破棄後に `GetData` にアクセスする | FSM はすでに破棄されている | `OnExit` 内で参照をクリーンアップし、`IFsm<T>` ハンドルをキャッシュしない |

## 背景 (オプション)

`m_Datas` は `Dictionary<string, Variable>` であり、`Fsm<T>` によって最初の `SetData` 呼び出し時に必要に応じて作成されます ([Fsm.cs#L515-L518](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L515-L518))。同じ名前のキーを上書きする時には `ReferencePool.Release` を呼び出してプールに回収されるため、`Variable` は参照プールプロトコルを実装しなければなりません (`Variable` を継承することで自動的に付属します)。
