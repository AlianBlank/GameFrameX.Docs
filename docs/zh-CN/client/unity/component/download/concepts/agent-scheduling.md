# 多代理调度与任务生命周期

下载管理器通过 `TaskPool<DownloadTask>` 同时维护多个下载代理(`DownloadAgent`),所有提交的任务会按优先级排队、被空闲代理领取、并在统一的轮询循环里推进。本页说明代理如何被创建与调度,以及任务在生命周期中经历的各个状态与事件。

## 快速开始

1. 启动组件时,通过 `DownloadComponent` 注册若干下载代理辅助器(每个辅助器对应一个独立代理,可并行下载):

```csharp
// AddDownloadAgentHelper 会 new DownloadAgent(helper) 并 m_TaskPool.AddAgent(agent)
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
```

Source: [DownloadManager.cs#L204-L213](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L204-L213)

2. 调用 `AddDownload(...)` 提交任务,任务会进入 `TaskPool` 的等待队列,等待空闲代理领取:

```csharp
int serialId = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/pkg.zip",
    downloadUri:  "https://example.com/pkg.zip",
    tag:         "asset",
    priority:    0);
```

Source: [DownloadManager.cs#L269-L296](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L269-L296)

3. 框架模块每帧调用 `DownloadManager.Update`,内部把更新转发给任务池,代理领取任务后调用 `IDownloadAgentHelper.Download` 开始传输,并在过程中触发 `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` 事件。

```csharp
// DownloadManager.Update -> m_TaskPool.Update(elapseSeconds, realElapseSeconds)
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_TaskPool.Update(elapseSeconds, realElapseSeconds);
    m_DownloadCounter.Update(elapseSeconds, realElapseSeconds);
}
```

## 代理调度

下载管理器在 `AddDownloadAgentHelper` 时为每一个辅助器创建独立的 `DownloadAgent`,并通过 `TaskPool<DownloadTask>.AddAgent` 注册。`TaskPool` 负责维护代理集合与等待队列,只把任务分配给处于空闲状态的代理。

代理集合中的关键统计量与队列状态都通过 `DownloadManager` 暴露,可在 UI 或调试面板中直接读取:

| 名称 | 来源属性 | 含义 |
|------|----------|------|
| 总代理数 | `TotalAgentCount` | 已被注册的下载代理总数 |
| 空闲代理数 | `FreeAgentCount` | 当前未承载任务的代理数 |
| 工作代理数 | `WorkingAgentCount` | 正在下载中的代理数 |
| 等待任务数 | `WaitingTaskCount` | 已入队但尚未被领取的任务数 |
| 当前速度 | `CurrentSpeed` | 由 `DownloadCounter` 计算的瞬时速度(MB/s) |
| 暂停标志 | `Paused` | 暂停会让代理停止领取新任务 |

Source: [DownloadManager.cs#L86-L142](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L86-L142)

调度方向一览:

1. 注册代理:`AddDownloadAgentHelper` → `new DownloadAgent(helper)` → `m_TaskPool.AddAgent(agent)`。
2. 提交任务:`AddDownload` → 构造 `DownloadTask.Create` → 写入任务池等待队列。
3. 领取任务:每帧 `TaskPool.Update` 把等待队列里优先级最高的任务交给一个空闲代理,代理随后调用 `IDownloadAgentHelper.Download(downloadUri, userData)`。
4. 释放代理:代理完成(成功或失败)后,自身被标记为空闲,任务池可在下一轮继续派发其他等待任务。

> 关于 `TaskPool<T>` 内部的优先级比较与等待队列实现,见 GameFrameX 运行时源码;本组件只负责提供 `DownloadTask` 与 `DownloadAgent` 实现。

## 任务生命周期

每个下载任务都是 `DownloadManager.DownloadTask`,继承自 `TaskBase`,通过 `ReferencePool.Acquire<DownloadTask>()` 创建,并在 `Clear()` 时归还对象池。任务有以下状态:

| 状态枚举值 | 取值 | 说明 |
|------------|------|------|
| `DownloadTaskStatus.Todo` | 0 | 已入队、等待代理领取 |
| `DownloadTaskStatus.Doing` | 1 | 已被代理领取,正在传输 |
| `DownloadTaskStatus.Done` | 2 | 下载完成、文件落盘 |
| `DownloadTaskStatus.Error` | 3 | 下载失败(超时、网络错误等) |

Source: [DownloadManager.DownloadTaskStatus.cs#L39-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTaskStatus.cs#L39-L60)

`DownloadTask` 携带的关键字段:

| 字段 | 类型 | 含义 |
|------|------|------|
| `SerialId` | `int` | 通过 `s_Serial` 自增分配,每次 `Create` 都 `++s_Serial` |
| `DownloadPath` | `string` | 下载完成后文件的存放路径 |
| `DownloadUri` | `string` | 原始下载地址 |
| `FlushSize` | `int` | 缓冲区写入磁盘的临界大小(由管理器默认值覆盖) |
| `Timeout` | `float` | 下载超时秒数(由管理器默认值覆盖) |
| `Priority` | `int` | 任务优先级,数值越大越靠前 |
| `Tag` | `string` | 任务标签,可按标签批量查询 `TaskInfo` |
| `UserData` | `object` | 透传给 `IDownloadAgentHelper.Download` 的自定义数据 |

Source: [DownloadManager.DownloadTask.cs#L39-L130](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs#L39-L130)

### 生命周期阶段

1. **入队**:调用 `AddDownload` 重载进入完整参数版本后,由 `DownloadTask.Create(downloadPath, downloadUri, tag, priority, flushSize, timeout, userData)` 创建任务,初始状态为 `Todo`,并立即进入 `TaskPool` 的等待队列。
2. **派发**:`TaskPool.Update` 把任务交给一个空闲 `DownloadAgent`,代理在 `OnDownloadAgentStart` 回调里将任务状态切换为 `Doing`,并打开本地 `FileStream`。
3. **进行中**:代理持续接收 `IDownloadAgentHelper` 的 `DownloadAgentHelperUpdateBytesEventArgs` / `UpdateLength`,累计 `m_DownloadedLength` 与 `m_SavedLength`,当 `m_WaitFlushSize` 达到 `FlushSize` 时落盘,同时按周期更新 `m_WaitTime` 用于超时判定。
4. **完成 / 失败**:成功时触发 `DownloadAgentSuccess`,失败(包括超时)时触发 `DownloadAgentFailure`,代理关闭流、清理状态,任务状态置为 `Done` 或 `Error`,等待 `TaskPool` 自动归还对象池。
5. **资源回收**:`Clear()` 把任务字段重置为 `Todo`/空值,再由 `ReferencePool.Release` 放回池中,等待下一次 `Create` 复用。

## 关键 API 速查

| 名称 | 签名 | 说明 |
|------|------|------|
| `DownloadManager.AddDownloadAgentHelper` | `void AddDownloadAgentHelper(IDownloadAgentHelper downloadAgentHelper)` | 注册一个下载代理,辅助器不能为 `null`,否则构造时抛出 `GameFrameworkException("Download agent helper is invalid.")` |

| `DownloadManager.GetAllDownloadInfos` | `TaskInfo[]` | 获取所有当前任务的信息 |

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 所有任务一直停留在 `WaitingTaskCount > 0`、`WorkingAgentCount = 0` | 没有调用 `AddDownloadAgentHelper`,任务池里没有任何代理 | 在组件启动阶段按需添加至少一个 `IDownloadAgentHelper`(UnityWebRequest / WWW 实现) |
| 启动组件时立即抛出 `Download agent helper is invalid.` | 传入 `null` 或对象被提前释放 | 保证传入的是有效实例,且不会被外部提前 `Dispose` |
| 任务长时间处于 `Doing` 后被标记失败 | `Timeout` 设置过短,或在弱网环境下 `FlushSize` 太大导致缓冲未落盘 | 通过 `DownloadManager.Timeout` / `DownloadManager.FlushSize` 调整,或使用 `AddDownload` 重载逐任务覆盖 |
| 已注册多个辅助器但并发数仍为 1 | 重复注册了同一个辅助器实例导致代理共享底层连接 | 每个 `UnityWebRequestDownloadAgentHelper`/`WWWDownloadAgentHelper` 实例只调用一次 `AddDownloadAgentHelper` |

## 背景(可选)

下载管理器是 `GameFrameworkModule`(`Priority = 5`),在 `Update` 中把调度权完全交给 `TaskPool<DownloadTask>`,本类只负责:

- 维护一份下载代理清单(通过 `AddDownloadAgentHelper` 注入)。
- 把每次 `AddDownload` 转换为 `DownloadTask.Create(...)` 并交给任务池。
- 监听代理的四个事件 (`Start/Update/Success/Failure`) 并对外暴露成统一的事件回调。
- 借助 `DownloadCounter` 把所有代理的字节增量折算成统一的瞬时下载速度。

任务对象(`DownloadTask`)本身由 `ReferencePool` 托管,代理(`DownloadAgent`)实现 `ITaskAgent<DownloadTask>` 与 `IDisposable`,这两个抽象是它与 `TaskPool` 对接的契约,也是与 GameFrameX 运行时任务调度子系统保持一致的地方。
