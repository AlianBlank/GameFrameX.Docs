# 로컬라이제이션 문구가 적용되지 않을 때 어떻게 해야 하나요

`Excels/Local/` 에 다국어 항목을 추가하거나 수정했는데 런타임에서 새 문구가 보이지 않는 경우, 일반적으로 **Luban이 해당 로컬라이제이션 테이블을 스캔하지 못했거나**, **코드 생성 시 로컬라이제이션 매개변수를 포함하지 않았기 때문**입니다. 이 페이지에서는 일반적인 증상과 빠른 수정 방법을 제시합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 시작 후 번역문 대신 Key(예: `Text_001`)만 보임 | 로컬라이제이션 파일이 LuBan에 로드되지 않음 | 생성 명령에 `-x l10n.textFile.path=./Excels/Local/` 이 포함되어 있는지 확인 |
| 새로 추가한 `L-Localization-*.xlsx` 가 적용되지 않음 | 파일명이 `L-Localization-` 접두사와 일치하지 않거나 `Excels/Local/` 에 배치되지 않음 | `L-Localization-<분류>.xlsx` 로 이름을 변경하고 `Excels/Local/` 디렉토리에 배치 |
| `Localization.xlsx` 생성 후에도 필드 누락 오류가 발생함 | `luban.conf` 에 `localizationFileName` 이 설정되지 않았거나 철자가 틀림 | 해당 target의 command에 `"localizationFileName": "Localization.xlsx"` 추가 |
| 언어 전환 후에도 원본 언어 문구가 표시됨 | 런타임 코드가 로컬라이제이션 테이블을 다시 로드하지 않음 / 재생성이 트리거되지 않음 | 이전 생성 결과물을 삭제하고 `gen-client-json.sh`(또는 해당 .bat)을 다시 실행 |
| 클라이언트 패키징 후 원격 문구가 빈 문자열임 | JSON 데이터 디렉토리(예: `Bundles/Config`)가 갱신되지 않음 | `gen-client-bin.sh` 을 다시 실행하여 생성된 JSON이 `outputDataDir` 를 덮어쓰도록 함 |

## 수정 단계

### 1. 로컬라이제이션 파일 위치 및 이름 확인

로컬라이제이션 파일은 반드시 `Excels/Local/` 디렉토리에 위치해야 하며, `L-Localization-` 로 시작해야 합니다. 저장소 예시에는 이미 3개의 로컬라이제이션 파일이 포함되어 있습니다:

- `Excels/Local/L-Localization-UI.xlsx`
- `Excels/Local/L-Localization-成就.xlsx`
- `Excels/Local/L-Localization-文本.xlsx`

새로 추가하는 모든 로컬라이제이션 파일은 동일한 명명 규칙을 따라야 합니다.

### 2. 생성 명령에서 로컬라이제이션 활성화

저장소에 포함된 `gen-client-json.sh` 는 이미 로컬라이제이션 관련 매개변수를 명시적으로 전달하고 있습니다:

```bash
dotnet ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json \
  --xargs outputDataDir=../Unity/Assets//Bundles/Config \
  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
  --xargs tableImporter.name=gameframex \
  -x l10n.provider=gameframex \
  -x l10n.textFile.keyFieldName=key \
  -x l10n.textFile.path=./Excels/Local/ \
  --conf ./Luban.conf
```

출처: [gen-client-json.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.sh#L1-L1)

명령에 `-x l10n.textFile.path=./Excels/Local/` 또는 `-x l10n.provider=gameframex` 가 없다면, 추가한 후 다시 생성하면 됩니다.

### 3. `luban.conf` 에 `localizationFileName` 선언

`luban.conf` 에서는 로컬라이제이션 데이터를 생성하는 target에 `localizationFileName` 필드를 추가해야 합니다(기본 이름은 `Localization.xlsx`):

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

### 4. 재생성 및 결과물 덮어쓰기

- 클라이언트 JSON: `gen-client-json.sh`(또는 `gen-client-json.bat`), 결과물은 `%UNITY_ASSETS_PATH%/Bundles/Config` 에 저장됩니다.
- 클라이언트 바이너리: `gen-client-bin.sh`, 결과물은 마찬가지로 `Bundles/Config` 이지만 출력 형식은 `cs-bin` 입니다.
- 서버: 서버 측은 현재 로컬라이제이션이 필요하지 않습니다(`server` target에는 `localizationFileName` 이 없음). 서버에 다국어 지원이 꼭 필요하다면 `client` 의 작성 방식을 참고하여 `localizationFileName` 필드를 추가하면 됩니다.

### 5. 테이블 헤더 및 `keyFieldName` 확인

`-x l10n.textFile.keyFieldName=key` 는 로컬라이제이션 테이블에 `key` 라는 이름의 컬럼이 반드시 있어야 함을 의미합니다. 테이블 헤더의 컬럼명이 `key` 가 아니면(예: `Key` 또는 `ID` 로 작성한 경우) 읽기에 실패합니다. 처리 방법: Excel에서 첫 번째 컬럼명을 `key` 로 변경하거나, 생성 명령에서 `keyFieldName` 을 테이블의 실제 컬럼명으로 변경하세요.

## 검증

1. 해당 생성 스크립트를 다시 실행하고, 명령의 `active: true` 설정이 비활성화되지 않았는지 확인합니다.
2. 생성 디렉토리(예: `Bundles/Config` 또는 `%SERVER_PATH%/Server.Config/Json`)에 `Localization.xlsx` 와 그 파생 데이터가 생성 및 갱신되었는지 확인합니다.
3. 런타임 코드에서 `key` 로 로컬라이제이션을 읽을 때, 언어 전환 후 빈 문자열이나 원본 언어가 아닌 해당 번역문을 반환해야 합니다.
4. 여전히 `key` 자체만 보인다면 로컬라이제이션 데이터가 로드되지 않은 것입니다. 2단계의 명령에 `-x l10n.textFile.path` 가 포함되어 있는지, 그리고 `Excels/Local/` 아래에 실제로 `L-Localization-*.xlsx` 파일이 있는지 다시 확인하세요.
