# プレイヤー属性(Attribute)モジュールの実装

プレイヤー属性(Attribute)モジュールは、「最終値スロット + 派生スロット」に基づく統一された計算式を提供します。基本値、加算、第一層パーセンテージ、最終加算、最終パーセンテージの5つのスロットを変更することで最終属性を取得します。このページでは、業務におけるプレイヤー属性の初期化、変更、読み取り方法を説明します。

## 前提条件

- `GameFrameX` のコンポーネント / Agent パターンに精通しており、`PlayerAttributeComponent` と `PlayerAttributeComponentAgent` の関係を理解していること。
- イベントバスを理解し、`AttributeChangedEventArgs` のリスナーを登録する方法を知っていること。

## 属性スロットと計算式

各最終属性(`AttributeType.Life` など)は5つの数値スロットに対応し、オフセットは `AttributeSlotKind` によって定義されます。パーセンテージ基数 `PercentBase = 10000` は 100% を表します。

| スロット | オフセット | 用途 |
|------|------|------|
| Final | 0 | 最終値スロット、编号は主编号と等しい |
| Base | 10000 | 基本値スロット、設定・レベル・初期化から取得 |
| Add | 20000 | 加算修正 |
| Pct | 30000 | 第一層パーセンテージ修正(基数は 10000) |
| FinalAdd | 40000 | 最終加算修正 |
| FinalPct | 50000 | 最終パーセンテージ修正(基数は 10000) |

再計算式は `AttributeCore.CalculateFinal` によって提供されます:

```csharp
public static long CalculateFinal(long baseValue, long addValue, long pctValue, long finalAddValue, long finalPctValue)
{
    checked
    {
        var firstLayer = (baseValue + addValue) * (PercentBase + pctValue) / PercentBase;
        return (firstLayer + finalAddValue) * (PercentBase + finalPctValue) / PercentBase;
    }
}
```

Source: [AttributeCore.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/AttributeCore.cs#L120-L127)

## 操作手順

### 1. プレイヤーエンティティに属性コンポーネントをアタッチする

`PlayerAttributeComponent` は既に `[ComponentType(GlobalConst.ActorTypePlayer)]` でアノテーションされており、プレイヤーエンティティ作成時に自動的にアタッチされるため、手動での登録は不要です。

```csharp
[ComponentType(GlobalConst.ActorTypePlayer)]
public sealed class PlayerAttributeComponent : StateComponent<PlayerAttributeState>
{
}
```

Source: [PlayerAttributeComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/Component/PlayerAttributeComponent.cs#L38-L40)

### 2. 最終属性の書き込みと再計算

`PlayerAttributeComponentAgent` の変更エントリを通じて派生スロットを変更した後、`AttributeCore.RecalculateFinal` を使用して最終値を再計算し、対応する Final スロットに書き込みます。`TryGetFinalAttribute` は派生スロットから所属する最終属性を逆引きします。

```csharp
var state = await agent.GetState();
var attributes = state.Attributes;

// Life の Base スロットを変更
var baseKey = AttributeCore.GetSlotAttribute(AttributeType.Life, AttributeSlotKind.Base);
attributes[baseKey] = 100;

// Life の最終値を再計算
attributes[AttributeType.Life] = AttributeCore.RecalculateFinal(attributes, AttributeType.Life);
```

Source: [AttributeCore.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/AttributeCore.cs#L46-L109)

### 3. 属性変更イベントをリッスンする

`AttributeChangedEventArgs` を購読して属性変更に応答します(`PlayerAttributeChangedEventListener` などの具体的なリスナーで処理されます)。イベントは変更された属性编号と新しい値を運びます。

```csharp
public class AttributeChangedEventArgs : EventArgs
{
    public AttributeType AttributeType { get; }
    public long OldValue { get; }
    public long NewValue { get; }
}
```

Source: [AttributeChangedEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/EventData/AttributeChangedEventArgs.cs)

### 4. 初期デフォルト値を使用する

プレイヤーが初回ログインする際、`PlayerInitialAttributeDefaults` が提供する初期化データを使用して Base スロットを入力し、初回の再計算をトリガーして初期最終属性を取得します。

## 一般的なバリエーション

- **パーセンテージ加成**:装備 / Buff は `Pct` または `FinalPct` スロットのみを変更し、最終値を直接計算する必要はありません。プレイヤーがオフラインになった際に対応する修正を削除するだけです。
- **エンティティ横断の属性集約**:複数のソース(プレイヤー + ペット + 装備)を統合して計算する必要がある場合は、それぞれで属性辞書を維持し、最終読み取り箇所で `AttributeCore.RecalculateFinal` を呼び出して統一します。
- **一括再計算**:複数の最終属性が同時に変化する場合、既知の最終属性(`AttributeCore.IsFinalAttribute` が true を返す 9 つの列挙値)を反復処理し、それぞれ `RecalculateFinal` を呼び出します。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `ArgumentOutOfRangeException: 既知の最終属性を渡す必要があります。` | 最終属性でない属性や派生スロットを `RecalculateFinal` に直接渡した | `IsFinalAttribute` が true を返す属性に対してのみ再計算を呼び出す |
| `ArgumentOutOfRangeException: 既知の属性数値スロットを渡す必要があります。` | `AttributeSlotKind` に未定義のカスタム値が渡された | 6つの組み込み列挙値のみの使用に限定する |
| 最終属性が常に 0 になる | 派生スロットが欠落しているが再計算がトリガーされていない | 派生スロットを変更した後、必ず `RecalculateFinal` を呼び出し、`Final` スロットに書き戻す |
| パーセンテージ加成の結果が 100 倍ずれる | `0.5` を Pct スロットに直接書き込んだ | Pct / FinalPct スロットは基数 `10000` を使用し、50% は `5000` を書き込む |

## 背景(オプション)

属性编号の設計上、10000 / 20000 / 30000 などの固定オフセットでスロットを区別しているため、任意の派生スロットから `value % PercentBase` で所属する最終属性を逆引きでき、変更イベントを統一的に処理できます。`PercentBase = 10000` は浮動小数点の精度問題を回避するだけでなく、プランナーが「万分比」で数値を設定する際にも便利です。
