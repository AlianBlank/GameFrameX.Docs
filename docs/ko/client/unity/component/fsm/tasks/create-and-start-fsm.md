# FSM 생성 및 시작 방법

`FsmComponent`를 통해 지정된 Owner를持有的 유한 상태 머신을 생성하고, 상태 인스턴스를 전달한 후 `Start<TState>()`를 호출하여 폴링을 시작하면 게임에서 엔티티 동작을 구동할 수 있습니다. 이 페이지에서는 상태 정의부터 실행 시작까지의 완전한 최소 경로를 제공합니다.

## 사전 조건

- `com.gameframex.unity.fsm` 패키지가 설치되어 있어야 합니다.
- `FsmComponent`가 부착된 GameObject가 씬에 존재해야 합니다(컴포넌트에는 `[GameFrameXAutoComponent(-6000)]`이 있으며, 프레임워크 시작 시 자동으로 등록됩니다).
- `FsmState<T>`를 상속하는 상태 클래스가 최소 하나 이상 정의되어 있어야 합니다(상태 정의에 대해서는 《FsmState 정의 방법》 참조).

## 작업 단계

1. `FsmComponent` 인스턴스를 가져옵니다.

   ```csharp
   var fsmComponent = GameEntry.GetComponent<FsmComponent>();
   ```

2. `CreateFsm<T>`를 호출하여 상태 머신을 생성하고, Owner와 모든 초기 상태 인스턴스를 전달합니다.

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
   ```

   `FsmComponent.CreateFsm<T>(T owner, params FsmState<T>[] states)`의 소스 코드 정의는 [FsmComponent.cs#L197-L208](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L197-L208)에 있으며, 내부적으로 `IFsmManager.CreateFsm`으로 전달됩니다.
   동일한 Owner에 대해 `name`을 가진 오버로드를 사용하여 여러 개의 공존 인스턴스를 생성할 수도 있습니다:

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm<Player>("Combat", player, new IdleState(), new AttackState());
   ```

3. `Start<TState>()`를 호출하여 FSM을 첫 번째 상태로 진입시킵니다.

   ```csharp
   fsm.Start<IdleState>();
   ```

   `Start<TState>()`은 대상 상태의 `OnEnter`를 트리거하고, 다음 프레임부터 매 프레임 `OnUpdate`를 호출합니다.
   `Start` 인터페이스 정의는 [IFsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsm.cs)를 참조하세요.

4. 임의의 상태 내부에서 `ChangeState<TState>(fsm)`을 통해 상태를 전환합니다.

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

## 일반적인 변형

| 시나리오 | 호출 방식 |
|------|----------|
| 동일한 Owner에 여러 개의 독립적인 FSM이 필요한 경우 | `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)`를 사용하고 `name`으로 구분 |
| 런타임에 새 상태 추가 | `fsm.AddState(new JumpState())` |
| 런타임에 상태 제거(현재 상태일 수 없음) | `fsm.RemoveState<IdleState>()` |
| 현재 상태 종료 및 데이터 초기화 후 재시작 | `fsm.Reset(); fsm.Start<IdleState>();` |
| `GameApp`을 통한 빠른 접근(`com.gameframex.unity.entry` 필요) | `IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());` |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Log.Fatal("FSM manager is invalid.")` | `Awake` 단계에서 `IFsmManager` 구현을 가져오지 못함, 일반적으로 프레임워크 초기화 순서 문제 | `FsmComponent`가 프레임워크 루트 GameObject에 부착되어 있는지 확인하고, GameFrameX 프레임워크 컴포넌트가 비즈니스 스크립트보다 먼저 초기화되도록 보장 |
| `Start<TState>()`에서 "상태가 존재하지 않음" 오류 | `CreateFsm` 시 해당 상태를 전달하지 않았거나, 이후 `RemoveState`를 호출함 | `CreateFsm`의 `params FsmState<T>[] states`에 추가하거나, `Start` 전에 `AddState`를 호출 |
| FSM이 구동되지 않음 / `OnUpdate`가 트리거되지 않음 | `FsmComponent`의 `FixedUpdate`는 `m_FsmManager`가 비어 있지 않은 것에 의존함; 컴포넌트가 부착되지 않았거나 비활성화된 경우 Update가 실행되지 않음 | 씬에 활성화된 `FsmComponent`가 존재하는지 확인 |
| `CreateFsm`이 동일한 Owner에 대해 이미 존재하는 인스턴스를 반환함 | 동일한 Owner + 동일한 name일 때 기존 FSM을 재사용 | 다른 `name`으로 구분하거나, 먼저 `DestroyFsm`을 호출한 후 생성 |

## 검증

- `IdleState.OnEnter`에서 로그를 출력하면, 씬 실행 시 즉시 한 번 출력되는 것을 확인할 수 있습니다.
- `IdleState.OnUpdate`에서 로그를 출력하면, 씬 실행 시 매 프레임 출력되며 이는 `FsmComponent.FixedUpdate`가 폴링을 구동하고 있음을 나타냅니다.
- `fsm.IsRunning`을 호출하면 `true`여야 합니다; `fsm.CurrentState`를 호출하면 방금 `Start`한 상태 타입이 반환되어야 합니다.
