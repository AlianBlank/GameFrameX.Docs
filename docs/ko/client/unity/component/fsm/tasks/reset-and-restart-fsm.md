# FSM 재설정 및 재시작 방법

`Start<TState>()`을 통해 현재 상태를 재설정하고 지정된 상태에서 FSM에 다시 진입합니다. 완전히 파괴해야 할 때만 `Clear()`를 사용합니다. 프레임워크에는 `Reset`이라는 이름의 메서드가 없습니다.所谓所谓 "재설정"은 다시 `Start`하는 것이고, "재시작"은 파괴 후 재구축입니다.

## 전제 조건

- `FsmManager`를 통해 `IFsm<T>`가 생성되어 현재 FSM 참조를 가져올 수 있습니다.
- 상태 집합 `FsmStateCount > 0`이며, 대상 상태 유형이 FSM에 등록되어 있어야 합니다(`HasState<TState>()`로 검증).

## 작업 단계

### 1. 초기 상태로 재설정(일반적 사용)

`Fsm<T>.Start`는 `IsRunning == true`일 때 `GameFrameworkException("FSM is running, can not start again.")`을 던지므로([Fsm.cs#L272-L277](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L277)), "재설정" 방법은 먼저 placeholder 상태로 전환한 다음 초기 상태를 `Start`하는 것입니다. 가장 간단한 placeholder 상태는 동일한 상태로 다시 전환하여 `OnLeave`를 트리거하고 `CurrentStateTime`을 0으로 초기화한 다음 `Start`를 호출하는 것입니다.

```csharp
// owner is the current holder reference
void ResetToInitial(IFsm<MyOwner> fsm, MyOwner owner)
{
    if (fsm == null || fsm.IsDestroyed) return;

    // Enter an equivalent state to trigger OnLeave and clear the timer
    if (fsm.HasState<IdleState>())
    {
        fsm.Start<IdleState>();
        fsm.Start<IdleState>();
    }
}
```

출처: [Fsm.cs#L272-L288](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L288)

### 2. 재시작(완전 파괴 + 재구축)

완전한 재설정에는 모든 상태, 소유자, 데이터를 비우기 위해 `Clear()`를 호출해야 하며([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265)), 그 다음 `FsmManager.CreateFsm`을 통해 재구축하고 `Start`합니다.

```csharp
// Get manager and owner
var fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());

fsm.Start<IdleState>();
// ... 이후 전체 재시작을 원할 경우:
GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>().DestroyFsm(fsm);
fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());
fsm.Start<IdleState>();
```

`Clear()` 내부는 먼저 `m_CurrentState.OnLeave(this, true)`를 호출하고, 그 다음 모든 상태를 순회하며 `OnDestroy`를 호출하며, `m_CurrentState`를 `null`로, `m_CurrentStateTime`을 `0`으로, `m_IsDestroyed`를 `true`로 설정합니다([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265)).

## 일반적인 변형

- **임의의 상태로 재설정**: 1단계의 `IdleState`를 대상 `TState`로 교체합니다.前提 조건은 `HasState<TState>()`이 `true`를 반환하는 것입니다.
- **데이터만 재설정하고 상태는 변경하지 않음**: 사용자 데이터 딕셔너리를 비우고 현재 상태를 유지하며 계속 실행합니다([Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs)의 `m_Datas` 비우기 방식 참고).
- **Editor에서 상태 관찰**: Inspector는 `fsm.CurrentStateName`과 `CurrentStateTime`을 표시합니다. 상태 이름이 `null`이면 실행되지 않음을 의미합니다([FsmComponentInspector.cs#L72](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Editor/Inspector/FsmComponentInspector.cs#L72)).

## 일반적인 오류

| 현상 | 원인 | 수정 |
|------|------|------|
| `FSM is running, can not start again.` 던짐 | `IsRunning == true`일 때 직접 `Start` 호출 | 먼저 `IsRunning`을 `false`로 변경(다른 상태로 전환 후 다시 전환하거나 먼저 `Clear` 후 `CreateFsm`) |
| `FSM 'X' can not start state 'Y' which is not exist.` 던짐 | `TState`가 FSM에 등록되지 않음 | 호출 전에 `fsm.HasState<TState>()`로 검증하고, 누락된 경우 FSM 재구축 |
| `State type 'X' is invalid.` 던짐 | `FsmState<T>` 파생 클래스가 아닌 `Type` 전달 | `stateType`이 현재 FSM의 해당 `FsmState<T>`를 상속하는지 확인 |
| `Start` 후 상태가 변경되지 않음 | 동일한 상태로 `Start`를 반복하여 "이미 실행 중"으로 판단되기 전의 첫 번째 `Start`가 이미 적용됨 | 앞서 설명한 "동일 상태로 한 번 전환 후 다시 전환" 방법을 우회하거나 새 FSM 생성 |

## 배경(선택 사항)

`Start`는 `m_CurrentState`를 직접 덮어쓰고 `OnEnter`를 호출하므로 "자체로 재설정"은 무효로 보이지만, 실제로 적용되는 것은 `OnLeave(..., true)`와 `m_CurrentStateTime = 0f`의 부작용입니다. 완전한 파괴는 참조 풀 `ReferencePool`을 거치며, `Fsm<T>.Clear` 구현을 참조하십시오.
