# 如何自訂 Helper 以取代預設實作

透過建立繼承自 `EntityHelperBase` 與 `EntityGroupHelperBase` 的自訂衍生類別，您可以接管實體的實例化、建立與釋放邏輯;`EntityComponent` 提供兩種替換方式：反射型別名稱(`m_EntityHelperTypeName` / `m_EntityGroupHelperTypeName`)以及直接在 Inspector 中拖曳(`m_CustomEntityHelper` / `m_CustomEntityGroupHelper`)。

## 前置條件

- 已安裝 GameFrameX Entity 套件，且可在場景中找到 `EntityComponent`。
- 熟悉 C# 繼承以及 Unity `MonoBehaviour` 的基本用法。
- 自訂 Helper 類別必須放置在可透過反射載入的組件中(以避免被程式碼裁剪工具剔除)。

## 步驟

1. **建立自訂實體 Helper 類別**，繼承自 `EntityHelperBase`,並實作三個抽象方法。

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;
using UnityEngine;
using YooAsset;

namespace MyGame.Entity
{
    public class MyEntityHelper : EntityHelperBase
    {
        public override object InstantiateEntity(object entityAsset)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return null;
            }
            return handle.InstantiateSync();
        }

        public override IEntity CreateEntity(object entityInstance, IEntityGroup entityGroup, object userData)
        {
            var go = entityInstance as GameObject;
            if (go == null)
            {
                Log.Error("Entity instance is invalid.");
                return null;
            }
            go.transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform);
            return go.GetOrAddComponent<Entity>();
        }

        public override void ReleaseEntity(object entityAsset, object entityInstance)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return;
            }
            handle.Release();
            Destroy((Object)entityInstance);
        }
    }
}
```

來源:[DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L41-L101)

2. **(選用)建立自訂實體群組 Helper 類別**，繼承自 `EntityGroupHelperBase`;此基底類別本身沒有任何抽象成員，因此只需依需求加入子物件管理邏輯即可。

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

namespace MyGame.Entity
{
    public class MyEntityGroupHelper : EntityGroupHelperBase
    {
        // 在此擴充實體群組節點管理
    }
}
```

來源:[EntityGroupHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityGroupHelperBase.cs#L39-L41)

3. **在場景中開啟 `EntityComponent`,選擇一種替換方式(兩者擇一)**:

   - **方式 A(反射型別名稱)**：將 `Entity Helper Type Name` 或 `Entity Group Helper Type Name` 欄位更改為完整類別名稱(包含命名空間)，例如 `MyGame.Entity.MyEntityHelper`。
   - **方式 B(直接在 Inspector 拖曳)**：將實作上述 Helper 的 `MonoBehaviour` 預製物件附加至 `Custom Entity Helper` 或 `Custom Entity Group Helper` 欄位。

```csharp
// EntityComponent 的相關欄位宣告
[SerializeField] private string m_EntityHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityHelper";
[SerializeField] private EntityHelperBase m_CustomEntityHelper = null;

[SerializeField] private string m_EntityGroupHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityGroupHelper";
[SerializeField] private EntityGroupHelperBase m_CustomEntityGroupHelper = null;
```

來源:[EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L62-L68)

4. **執行場景進行驗證**。`EntityComponent.Start()` 會依照下列優先順序建立 Helper:首先檢查 Inspector 上的 `m_CustomEntityHelper` 是否已被指派；若未指派，則使用 `m_EntityHelperTypeName` 並透過 `Helper.CreateHelper` 以反射方式建立 Helper;若結果仍為 null,則會記錄 `Can not create entity helper.`。

```csharp
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
}
```

來源:[EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L171-L175)

## 常見變化

| 情境 | 做法 |
|----------|----------|
| 僅替換實體群組節點掛載策略 | 從 `EntityGroupHelperBase` 衍生,`EntityHelperBase` 保持使用預設實作 |
| 需要在 Helper 內存取 Unity 生命週期 | 直接使用繼承自基底類別的 `MonoBehaviour` 方法(`Awake/OnEnable/...`) |
| 組件裁剪導致反射失敗 | 在 `link.xml` 中保留自訂 Helper 類別，或使用 `[Preserve]` 特性(請參考 [GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L6-L24) 中的保留做法) |

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|---------|-------|-----|
| 啟動時日誌顯示 `Can not create entity helper.` | 反射型別名稱為空或拼寫錯誤，且未拖入 `CustomEntityHelper` | 確認型別名稱包含命名空間，例如 `MyGame.Entity.MyEntityHelper` |
| 自訂 Helper 中的 `Awake` 未觸發 | 使用了反射建立路徑，而非 Inspector 拖曳 | 改用方式 B 將 Helper 附加至 `m_CustomEntityHelper` 欄位，或在 `CreateEntity` 中手動呼叫 `Instantiate` 以建立關聯 |
| `ReleaseEntity` 之後物件實際上未被銷毀 | 覆寫時遺漏了 `Object.Destroy` 的呼叫 | 在 `ReleaseEntity` 結尾呼叫 `Destroy((Object)entityInstance)` |
| 發行組建中出現 `MissingReferenceException` | 自訂類別被程式碼裁剪剔除 | 加上 `[Preserve]` 標註，或將其加入 `link.xml` |

## 背景(選讀)

`EntityComponent` 的內建欄位預設指向 `DefaultEntityHelper` / `DefaultEntityGroupHelper`,其內部依賴 YooAsset 的 `AssetHandle` 來完成實例化與釋放(請參閱 [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L48-L100))。自訂 Helper 的目的是讓您能夠在不修改框架的情況下，將其替換為 Addressables、自行開發的資產管線，或帶有物件池的實例化方案。
