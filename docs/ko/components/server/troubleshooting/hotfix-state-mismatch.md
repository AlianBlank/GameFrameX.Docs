# 핫업데이트 후 플레이어 데이터 또는 Actor 상태가 비정상일 때 대처 방법

핫업데이트는 `IHotfixBridge` 브리지 인터페이스를 통해 상태 계층(Apps)의 호출을 로직 계층(Hotfix)으로 전달합니다. 브리지 구현이 올바른 어셈블리에 위치하지 않거나, 핫업데이트 후 이전 버전 DLL이 언로드되지 않으면 플레이어 데이터 불일치, Actor 상태 혼란 등의 문제가 발생합니다. 이 페이지에서는 오류 메시지에서 직접 수정 지점까지 찾아가는 경로를 안내합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 컴파일 시 `GFX0004: Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not 'Y'` 오류 발생 | `IHotfixBridge` 구현 클래스가 `GameFrameX.Hotfix` 어셈블리가 아닌 곳에 위치함 | 브리지 클래스를 `GameFrameX.Hotfix` 프로젝트로 이전(아래 "수정 단계 1" 참조) |
| 핫업데이트 후 플레이어 데이터 유실, 속성이 기본값으로 되돌아감 | 핫업데이트 어셈블리가 교체되지 않아 상태 계층이 여전히 구버전 브리지를 호출함 | `bin/` 하위의 이전 DLL을 정리하고 핫업데이트를 다시 트리거(아래 "수정 단계 2" 참조) |
| Actor가 호출을 수신하지만 메서드 버전이 불일치함(일부 호출은 새 로직, 일부는 이전 로직으로 실행됨) | AppDomain에 여러 개의 `IHotfixBridge` 구현이 잔존함 | 전체 프로젝트에 `IHotfixBridge` 구현이 하나만 있고 `GameFrameX.Hotfix`에 위치하도록 보장(아래 "수정 단계 3" 참조) |
| 런타임에 `HotfixHandler` 리플렉션을 찾지 못한다는 오류 발생 | 마커 클래스가 삭제되었거나 네임스페이스가 변경됨 | `GameFrameX.Hotfix.HotfixHandler` 정적 클래스를 유지하고 이름을 변경하지 마십시오 |

## 수정 단계

### 1. 브리지 클래스는 반드시 `GameFrameX.Hotfix` 어셈블리에 위치해야 합니다

아키텍처 분석기는 컴파일 시점에 `IHotfixBridge` 구현 위치를 검증하며, 규칙 위반 시 곧바로 `GFX0004` 오류를 발생시킵니다:

```csharp
// GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs
private static readonly DiagnosticDescriptor SDescriptor = new DiagnosticDescriptor(
    "GFX0004",
    "IHotfixBridge must be defined in GameFrameX.Hotfix",
    "Type '{0}' implements IHotfixBridge and must be defined in assembly '{1}', not '{2}'",
    ArchitectureAnalyzerConstants.Category,
    DiagnosticSeverity.Error,
    true);
```

Source: [HotfixBridgeAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs#L22-L28)

수정 방법:

1. 솔루션에서 오류가 발생한 구현 클래스가 포함된 `.cs` 파일을 엽니다.
2. 해당 파일을 `GameFrameX.Hotfix/StartUp/` 디렉터리로 이동하고, `.cs` 파일 상단의 네임스페이스를 `GameFrameX.Hotfix.StartUp`로 변경합니다.
3. 파일 상단에 `internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge`가 포함되어 있는지 확인합니다(기존 진입점 참조).
4. 솔루션을 다시 빌드하여 `GFX0004` 오류가 사라졌는지 확인합니다.

### 2. 핫업데이트 DLL이 실제로 교체되도록 하기

상태 계층(Apps)이 로직 계층(Hotfix)을 호출하는 것은 전적으로 `IHotfixBridge`에 의존합니다. 이전 버전 DLL이 언로드되지 않으면 플레이어 데이터 직렬화/역직렬화에 이전 스키마가 사용되어 "핫업데이트 후 상태 비정상"처럼 보이게 됩니다. 수정 단계:

1. 실행 중인 모든 GameFrameX.Server 프로세스를 중지합니다.
2. 서비스 출력 디렉터리의 `GameFrameX.Hotfix.dll`(및 해당 `.pdb`)과 `hotfix/` 리소스 디렉터리를 삭제합니다.
3. 새로 컴파일한 `GameFrameX.Hotfix.dll`을 핫업데이트 디렉터리로 복사합니다. 버전 번호는 현재 온라인 버전보다 커야 합니다.
4. 서비스를 시작하고 핫업데이트 프로세스를 한 번 트리거한 뒤, 로그에서 로드된 DLL 버전 번호를 확인합니다.
5. 테스트 계정으로 로그인하여 브리지 호출이 포함된 작업을 트리거하고, 데이터가 올바르게 저장되는지 확인합니다.

### 3. 전체 프로젝트에 `IHotfixBridge` 구현을 하나만 유지

여러 클래스가 `IHotfixBridge`를 구현하고 있는 경우(예: 신구 버전 공존), Actor가 무작위로 그중 하나에 바인딩되어 상태 계층에서 보는 메서드 버전과 로직 계층이 불일치하게 됩니다. 수정 단계:

1. 전체 프로젝트에서 `: IHotfixBridge`를 검색하여 구현이 한 곳에만 있는지 확인합니다:

   ```bash
   grep -rn "IHotfixBridge" --include="*.cs"
   ```

2. 여러 곳에서 발견되면 `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGame*.cs`에 있는 구현을 유지하고 나머지는 삭제하거나 병합합니다.
3. 다시 컴파일하여 `GFX0004`가 "중복 정의"를 보고하지 않는지 확인합니다.

### 4. `HotfixHandler` 마커 클래스를 삭제하지 마십시오

`HotfixHandler`는 빈 클래스이지만 리플렉션 진입점 역할을 담당하며, 삭제하면 핫업데이트 엔진이 마커를 찾지 못하게 됩니다:

```csharp
// GameFrameX.Hotfix/HotfixHandler.cs
namespace GameFrameX.Hotfix;

/// <summary>
/// 이 클래스 문서는 핫업데이트 마커 처리에 사용됩니다. 삭제하면 안 됩니다. 리플렉션 호출에 사용됩니다.
/// </summary>
public static class HotfixHandler
{
}
```

Source: [HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8)

로그에 "`HotfixHandler`를 찾을 수 없음" 또는 "리플렉션 마커 누락"이 나타나면 위 코드와 같이 빈 클래스를 `GameFrameX.Hotfix` 프로젝트에 다시 추가하면 됩니다.

## 검증

수정 완료 후 다음 순서대로 검증합니다:

1. 솔루션을 컴파일하여 `GFX0004` 오류뿐 아니라 다른 `GFX####` 오류도 없는지 확인합니다.
2. 서비스를 시작하고 시작 로그에서 핫업데이트 모듈이 로드한 DLL 버전 번호가 로컬 빌드 버전과 일치하는지 확인합니다.
3. 테스트 계정으로 로그인하여 `IHotfixBridge` 메서드를 호출하는 비즈니스 로직을 하나 트리거하고(예: 로그인, 메일 수령, 속성 수정), 데이터베이스 기록이 예상과 일치하는지 확인합니다.
4. 핫업데이트를 한 번 시뮬레이션하여(DLL 교체) 3단계를 반복하고, 핫업데이트 전후 동작이 일치하며 데이터가 되돌아가지 않는지 확인합니다.

## 배경

`IHotfixBridge`는 상태 계층(Apps)과 로직 계층(Hotfix) 사이의 유일한 호출 통로입니다. 아키텍처 분석기(`HotfixBridgeAssemblyAnalyzer`)는 핫업데이트 시 전체 교체가 가능하도록 구현을 `GameFrameX.Hotfix` 어셈블리로 제한하며, 상태 계층은 인터페이스 참조만 보유하므로 교체 과정이 플레이어에게 노출되지 않습니다. 브리지가 손상되거나 이전 DLL이 잔존하면 Actor와 플레이어 데이터에 "새 로직으로 쓰고 새로 읽기" 또는 "신구 혼용"과 같은 불일치 현상이 나타나며, 본 절차는 이 두 가지 근본 원인을 중심으로 구성되어 있습니다.
