# Protobuf POST 요청을 보내고 응답을 받는 방법

Unity 씬의 `WebProtoBuffComponent`에서 `await WebComponent.Post<TResponse>(url, request)`를 호출하면 `MessageObject` 요청을 protobuf 바이너리로 직렬화하여 HTTP POST로 전송하고, 서버가 반환한 바이트를 타입이 지정된 `TResponse`(`MessageObject + IResponseMessage`)로 역직렬화할 수 있습니다.

## 사전 조건

- Package Manager를 통해 `com.gameframex.unity.web.protobuff`를 설치했습니다(scoped registry `https://gameframex.upm.alianblank.uk`, scope는 `com.gameframex`). 그리고 `dependencies`에 다음을 추가합니다:

```json
{
  "dependencies": {
    "com.gameframex.unity.web.protobuff": "1.1.3"
  }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L97-L103)

- 프로젝트에 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 컴파일 매크로가 정의되어 있어야 하며, 그렇지 않으면 `WebProtoBuffComponent.Post<T>`가 컴파일에 포함되지 않습니다:

```csharp
#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
        public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
        {
            return m_WebProtoBuffManager.Post<T>(url, message);
        }
#endif
```

출처: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

- 요청 메시지는 `GameFrameX.Network.Runtime.MessageObject`를 상속합니다. 응답 메시지는 `MessageObject`를 상속하고 `GameFrameX.Network.Runtime.IResponseMessage`를 구현해야 합니다.
- Unity 씬에 `WebProtoBuffComponent`가 추가되어 있어야 하며(Inspector 메뉴 `GameFrameX/Web ProtoBuff`), 이 컴포넌트는 동시에 `GameFrameXWebProtoBuffCroppingHelper`가 존재해야 합니다.

## 작업 단계

1. 씬에 `WebProtoBuffComponent`를 추가하고, 필요에 따라 Inspector에서 타임아웃 시간(`Timeout`, 단위: 초, 기본값 5)을 설정합니다:

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;

public float Timeout
{
    get { return m_WebProtoBuffManager.Timeout; }
    set { m_WebProtoBuffManager.Timeout = m_Timeout = value; }
}
```

출처: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L57-L71)

2. 비즈니스 코드에서 `using GameFrameX.Web.ProtoBuff.Runtime;`을 사용합니다.
3. 요청 메시지 객체를 생성하고 `await`로 `Post<T>`를 호출합니다:

```csharp
using GameFrameX.Web.ProtoBuff.Runtime;

// 요청을 전송하고 결과를 기다립니다
LoginResponse response = await WebComponent.Post<LoginResponse>(url, request);
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L106-L112)

4. 요청이 큐에 들어간 후 `WebProtoBuffManager`가 `Update`에서 `MaxConnectionPerServer`에 따라 하나씩 전송하며, `Content-Type`은 `application/x-protobuf`로 고정됩니다:

```csharp
private const string ProtoBufContentType = "application/x-protobuf";
```

출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L29-L32)

## 일반적인 변형

- **비 WebGL 플랫폼**: `HttpWebRequest`를 사용하며, 타임아웃은 밀리초(`(int)RequestTimeout.TotalMilliseconds`)로 지정하고, POST 본문은 `request.ContentLength = postData.Length` 설정 후 요청 스트림에 기록합니다:

```csharp
HttpWebRequest request = WebRequest.CreateHttp(webData.URL);
request.Method = webData.IsGet ? WebRequestMethods.Http.Get : WebRequestMethods.Http.Post;
request.Timeout = (int)RequestTimeout.TotalMilliseconds; // 요청 타임아웃 시간 설정
request.ContentType = ProtoBufContentType;
byte[] postData = webData.SendData;
request.ContentLength = postData.Length;
using (Stream requestStream = request.GetRequestStream())
{
    await requestStream.WriteAsync(postData, 0, postData.Length);
}
```

출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L120-L131)

- **WebGL 플랫폼**: 대신 `UnityEngine.Networking.UnityWebRequest`를 사용하며, POST는 `UploadHandlerRaw`로 바이너리 본문을 담아 보내고 `completed` 콜백에서 Task를 완료합니다:

```csharp
var asyncOperation = unityWebRequest.SendWebRequest();
asyncOperation.completed += (asyncOperation2) =>
{
    try
    {
        m_SendingProtoBufList.Remove(webData);
        if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)
        {
            webData.Task.TrySetException(new Exception(unityWebRequest.error));
            return;
        }

        webData.Task.SetResult(new WebBufferResult(webData.UserData, unityWebRequest.downloadHandler.data));
    }
    finally
    {
        unityWebRequest.Dispose();
        ReferencePool.Release(webData);
    }
};
```

출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L99-L118)

## 일반적인 오류

- **`Post<T>` 컴파일 실패 / 존재하지 않음**: `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 매크로가 정의되지 않아 메서드 전체가 `#if` 블록 안에 있습니다.
- **`Fatal: Web manager is invalid.`**(`Log.Fatal("Web manager is invalid.")`): `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()`가 null을 반환합니다. GameFramework 초기화 순서를 확인하세요.
- **요청이 한참 동안 전송되지 않음**: `WebProtoBuffManager.UpdateProtoBuf`는 `m_SendingProtoBufList.Count < MaxConnectionPerServer`일 때만 새 요청을 큐에서 꺼내므로, 동시 연결이 가득 차면 이후 요청은 대기 큐에 머무르게 됩니다.
- **서버가 415 반환 / 파싱 실패**: 클라이언트의 `Content-Type`은 `application/x-protobuf`로 고정되어 있으므로, 서버는 JSON이나 폼이 아닌 protobuf 바이너리로 처리해야 합니다.
- **응답 역직렬화 예외**: `T`는 `MessageObject`와 `IResponseMessage` 제네릭 제약 조건을 동시에 만족해야 하며, 서버가 실제로 반환하는 proto 메시지 구조와 일치해야 합니다.

## 배경

`WebProtoBuffComponent`는 `IWebProtoBuffManager`의 얇은 래퍼일 뿐입니다. `WebProtoBuffManager`(partial 클래스)는 `m_WaitingProtoBufQueue`(용량 256)와 `m_SendingProtoBufList`(용량 16)를 관리하며, 매 프레임 `UpdateProtoBuf`에서 요청을 큐에서 꺼내 `MessageObject`를 바이트로 직렬화하고 플랫폼별 HTTP 클라이언트로 전송합니다(WebGL은 `UnityWebRequest`, 기타 플랫폼은 `HttpWebRequest`). 응답 바이트 배열은 최종적으로 `WebBufferResult`로 래핑되어 타입이 지정된 `IResponseMessage`로 역직렬화됩니다. 패키지 전체에 대한 설명은 저장소의 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md)를 참조하세요.
