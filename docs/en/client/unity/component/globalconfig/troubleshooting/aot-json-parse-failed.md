# What to Do When AOT Code List JSON Parsing Fails

When assigning a value to `GlobalConfigComponent.AOTCodeList` at runtime, if the string is not a valid JSON array format, `GlobalConfigComponent` will fail to deserialize it via `Utility.Json.ToObject<List<string>>(value)` and call `Log.Error(e)` to log the exception, causing `AOTCodeLists` to remain empty and AOT metadata supplementation to fail. This page explains common causes and fixes.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Console outputs `Log.Error` with JSON parsing exception, but the `AOTCodeList` string has been written | The string is not a valid JSON array | Rewrite it in `[ "A", "B" ]` format, see "Fix JSON Format" below |
| `AOTCodeLists` is always an empty list, but no error is reported | Empty string or setter not triggered | Assign a non-empty JSON array string to the field |
| `MissingMethodException` or `TypeLoadException` occurs under IL2CPP/iOS | `AOTCodeLists` did not parse out type/assembly names, supplementary metadata was not generated | Fill in the complete JSON in the Inspector's "Supplementary Assembly List", and confirm HybridCLR/IL2CPP is in effect |
| Contains Chinese comma `,` or single quotes `'…'` | JSON requires double quotes + half-width commas | Change the string to standard JSON |
| Multi-line, comments, trailing commas | JSON does not support comments or trailing commas | Change to a single-line, strictly valid string array |

## Fix Steps

### 1. Confirm Target Format

The setter in the source code directly deserializes into `List<string>`, so the field must be a JSON representation of a **string array**. Valid example:

```json
["GameFrameX.Runtime","GameFrameX.GlobalConfig.Runtime"]
```

Source location:

```csharp
public string AOTCodeList
{
    get { return m_aotCodeList; }
    set
    {
        m_aotCodeList = value;
        try
        {
            m_aotCodeLists = Utility.Json.ToObject<List<string>>(value);
        }
        catch (Exception e)
        {
            Log.Error(e);
        }
    }
}
```

Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L64-L79)

### 2. Fix JSON Format

Select the GameObject with `GlobalConfigComponent` attached in the Inspector, find the **"Supplementary Assembly List"** field (`m_aotCodeList`), and change the content to a strict JSON array:

- Must start with `[` and end with `]`
- Elements must be wrapped in **double quotes**, single quotes are not allowed
- Elements separated by a **half-width comma** plus a space
- Do not write comments, do not leave trailing commas, do not add `;` at the end

The correspondence between field names in the Inspector and serialized properties is as follows:

| Inspector Display Name | Serialized Field | Type |
|------------------|-----------|------|
| Supplementary Assembly List | `m_aotCodeList` | `string` (raw JSON) |
| Supplementary Metadata List | `m_aotCodeLists` | `List<string>` (parsed, runtime read-only) |

Source: [GlobalConfigComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Editor/Inspector/GlobalConfigComponentInspector.cs#L13-L14)

### 3. Ensure Format When Setting via Code

If a remote-delivered configuration is assigned to `AOTCodeList`, validate it first with `Utility.Json.ToObject<List<string>>` before writing, to avoid pushing dirty backend data into the setter:

```csharp
var raw = "[\"GameFrameX.Runtime\",\"GameFrameX.GlobalConfig.Runtime\"]";
globalConfig.AOTCodeList = raw; // Internal try/catch, failure will Log.Error
```

The setter in the source code already wraps the parsing exception in a `try/catch` and calls `Log.Error`, so it **will not throw upward** — but the exception will be logged, and `AOTCodeLists` will keep its original value. This is the key observation point for troubleshooting "parsing failure".

Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L70-L78)

### 4. Confirm AOT Metadata Supplementation Chain

The strings in the `AOTCodeLists` need to correspond one-to-one with the assembly names that HybridCLR (or similar AOT tools) in the project require to be supplemented. If the list parses successfully but `MissingMethodException` still occurs at runtime, the problem lies with the AOT toolchain itself, not the JSON parsing step.

## Verification

1. After modifying **"Supplementary Assembly List"** in the Inspector, confirm that **"Supplementary Metadata List"** immediately shows the same number of entries as the JSON.
2. Search for `Log.Error` or `Json` keywords in the Editor console to confirm there is no parsing exception output.
3. After building for IL2CPP/AOT target platforms (iOS, WebGL, etc.) and launching, check whether the original `MissingMethodException` has disappeared.

## Background (Optional)

`AOTCodeList` and `AOTCodeLists` are designed as a dual-field pair of "source JSON string + parsed cached list". The setter swallows parsing exceptions and only logs them to avoid dirty configuration disrupting business initialization — the trade-off is that failures are easily overlooked, so you need to confirm via logs and whether the "Supplementary Metadata List" is populated.
