# 如何在兩種存取方式之間做選擇：GameApp 與 GameEntry

GameFrameX 提供了兩種存取框架元件的方式：`GameEntry` 是元件容器的底層入口（由 `GameFrameX.Runtime` 套件提供），而 `GameApp` 則是本儲存庫在 `GameEntry` 之上構建的「靜態外觀」（static facade），將常用元件以屬性的形式對外暴露。簡單來說：業務程式碼呼叫 `GameApp.XXX`，而 `GameApp` 內部會將所有呼叫路由到 `GameEntry.GetComponent<XXXComponent>()`。

## 前置條件

- 已安裝 `com.gameframex.unity.entry`（本儲存庫）
- 已安裝 `com.gameframex.unity.runtime`，因為 `GameEntry` 型別定義於 `GameFrameX.Runtime` 命名空間之下

```csharp
using GameFrameX.Runtime; // 提供 GameEntry
// GameApp 位於全域命名空間中，不需要 using 指示詞
```

來源：[Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L32-L34)

## 兩種存取方式的比較

| 維度 | `GameEntry` | `GameApp` |
|------|-------------|-----------|
| 命名空間 | `GameFrameX.Runtime`（外部套件） | 全域命名空間（本儲存庫） |
| 型別 | 提供元件容器的靜態類別 | `static partial class`，每個元件一個檔案 |
| 呼叫形式 | `GameEntry.GetComponent<T>()` | `GameApp.<PropertyName>` |
| 典型用途 | 註冊自訂元件、按需取得任意元件 | 快速存取常用元件 |

`GameApp` 的屬性 getter 實作只是對 `GameEntry.GetComponent<T>()` 的簡單封裝，並將結果快取在私有的靜態欄位中：

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }
    private static BaseComponent _base;
}
```

來源：[Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

## 選擇建議

1. **日常業務開發優先使用 `GameApp`**
   - 程式碼更簡短、可讀性更好：`GameApp.Base`、`GameApp.Mono`。
   - 無需記住元件的具體型別名稱；IDE 自動補全會列出當前套件中已封裝的元件。
   - 一旦命中快取，就只是讀取欄位，開銷幾乎為零。

2. **存取本儲存庫未封裝的元件時，直接使用 `GameEntry`**
   - 例如，您建立了自訂的 `MyComponent` 並將其註冊到框架後，就只能使用 `GameEntry.GetComponent<MyComponent>()`。
   - 在跨套件/跨模組邊界編寫程式碼時，優先使用 `GameEntry`，以避免對 `GameApp` 產生硬性依賴。

3. **註冊新元件時，兩邊各需修改一處**
   - 透過 `GameEntry.RegisterComponent<T>()` 註冊後，若希望業務端能以 `GameApp.My` 這樣的屬性形式存取，請在本儲存庫中新增一個 `GameApp.My.cs` partial 檔案，並按照上方的範本封裝一個 getter 與一個快取欄位。

## 操作指南：新增一個 `GameApp` 屬性

1. 在 `Runtime/` 下新增 `GameApp.My.cs`（必須使用 `partial`，且與 `GameApp` 位於相同的命名空間）。

```csharp
public static partial class GameApp
{
    public static MyComponent My
    {
        get
        {
            if (_my == null)
            {
                _my = GameEntry.GetComponent<MyComponent>();
            }
            return _my;
        }
    }

    private static MyComponent _my;
}
```

2. 在框架啟動流程中使用 `GameEntry.RegisterComponent<MyComponent>()` 註冊該元件。
3. 之後業務端只需呼叫 `GameApp.My.DoSomething()` 即可。

來源：範本參考 [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `GameApp.Base` 回傳 `null` / 擲出例外 | 框架尚未完成啟動，或對應元件未透過 `RegisterComponent` 註冊 | 檢查啟動流程是否呼叫了 `RegisterComponent<BaseComponent>`；在熱更新/重啟場景下注意時機 |
| 編譯錯誤：`GameEntry` 不存在 | 缺少 `using GameFrameX.Runtime;` | 在檔案頂部加上 `using GameFrameX.Runtime;` |
| 找不到 `GameApp.Mono` 等屬性 | 您未使用 `com.gameframex.unity.entry` 套件，或套件版本過舊、未包含對應的 partial 檔案 | 將本套件升級至最新版本 |
| 自訂的 `GameApp.My` 回報 `missing partial` 錯誤 | 新檔案未宣告 `public static partial class GameApp` | 加上 `partial` 關鍵字，並使用與現有 `GameApp` 相同的類別名稱 |

## 背景說明（選讀）

`GameEntry` 維護著一個元件字典（`RegisterComponent` / `GetComponent<T>()`），是框架元件的「容器根」。`GameApp` 本身不做任何實際工作；它只是取得常用元件並將其快取在靜態欄位中，讓呼叫端省去撰寫泛型參數與輸入類別名稱的麻煩。兩種存取方式引用的是相同的元件實例。
