# 热更启动返回失败怎么办

当 `IHotfixLauncher.StartAsync` 返回的 `HotfixLaunchResult` 标记为失败,或启动流程在 `ProcedureGameLauncherState` 中触发 `StartupFailedEventArgs` 时,就是本页要处理的情况。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `HotfixLaunchResult.IsSuccess == false`,日志提示找不到程序集 | `StartupOptions.HotfixAssemblyName` 与实际编译产物不匹配 | 确认 Inspector 字段值,保证与打包脚本输出 dll 一致 |
| `HotfixLaunchResult.IsSuccess == false`,日志提示找不到入口类型 | `HotfixEntryTypeName` 拼写或命名空间错误 | 检查类型全名(含命名空间),与 dll 反编译结果核对 |
| 监听 `StartupFailedEventArgs`,`FailedProcedureName == "ProcedureGameLauncherState"` | 热更 launcher 抛出异常或返回失败 | 在 `IHotfixLauncher` 实现里 try/catch,填充 `ErrorMessage` 后返回失败结果 |
| 流程卡在 `ProcedureGameLauncherState` 不前进 | `IHotfixLauncher` 没注入 BlackBoard | 在 `StartupRunner` 调用前 `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, ...)` |
| 收到 `StartupFailedEventArgs` 但 `ErrorMessage` 为空字符串 | 业务实现未按约定填 `ErrorMessage` | launcher 失败时显式赋值 `HotfixLaunchResult.ErrorMessage` |

`HotfixLaunchResult` 与 `StartupFailedEventArgs` 的字段定义见下文参考表。

## 修复步骤

### 1. 核对 StartupOptions 配置

热更入口三件套(程序集名 / 入口类型全名 / 入口方法名)由 `StartupOptions` 注入,只要任一项对不上,`StartAsync` 就会返回失败:

```csharp
// 来自 StartupOptions.cs 默认值
public string HotfixAssemblyName = "Unity.Hotfix";
public string HotfixEntryTypeName = "Hotfix.HotfixLauncher";
public string HotfixEntryMethodName = "Run"; // 见 StartupOptions.cs 字段声明
```

确认 `StartupOptions` 资产里这三项的值与热更工程编译输出、IL2CPP/HybridCLR 加载列表保持一致。Source: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L33-L40)

### 2. 监听 StartupFailedEventArgs

订阅启动失败事件,把 `ProcedureGameLauncherState` 抛出的失败消息显示给玩家:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(StartupFailedEventArgs.EventId, e =>
{
    var args = (StartupFailedEventArgs)e;
    // args.FailedProcedureName / args.FailedUrl / args.ErrorMessage
});
```

事件触发位置由 `StartupProcedureUtility.NotifyFailure` 统一调用,会在 UI 提示文本之外再 fire 一次 `StartupFailedEventArgs`。Source: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L160-L170),[StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L40-L60)

### 3. 让 IHotfixLauncher 实现返回结构化失败

`IHotfixLauncher` 契约规定**成功或失败都要返回 `HotfixLaunchResult`,不抛异常**。实现侧务必把所有异常 catch 后塞进 `ErrorMessage`:

```csharp
public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    try
    {
        // 加载 + 反射调用入口方法
        return HotfixLaunchResult.Success();
    }
    catch (Exception ex)
    {
        return HotfixLaunchResult.Failure(ex.Message);
    }
}
```

Source: [IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L8-L16),[HotfixLaunchResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/HotfixLaunchResult.cs#L1-L40)

### 4. 确认 IHotfixLauncher 已注入 BlackBoard

`ProcedureGameLauncherState` 通过 FSM BlackBoard 读取 `IHotfixLauncher`。如果注入缺失,流程会卡在该 Procedure。注入约定如下:

```csharp
// BlackBoardKeys 中定义的常量
public const string StartupHotfixLauncher = "__startup_hotfix_launcher__";
```

启动器在创建 FSM 时必须 `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, hotfixLauncher)`。Source: [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs#L19-L23),[StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L80-L100)

## 验证

完成上述修复后,逐项确认:

1. `HotfixLaunchResult.IsSuccess == true`,且 `ErrorMessage` 为空。
2. `StartupFailedEventArgs` 不再被触发(或 `FailedProcedureName` 已切换到其他故障点,不再是 `ProcedureGameLauncherState`)。
3. 后续流程推进到游戏主场景,`StartupCompletedEventArgs` 正常 fire。
