# 如何配置本地化多语言(text 字段)

在 Excel 配置表里,把字段类型声明为 `text`,就能把这一列接入 `TbLocalization` 多语言表;运行时根据 key 取回当前语言的真实文案,实现同一份配置多语言切换。

## 前置条件

- 已安装 .NET SDK(Luban 工具的运行依赖)。
- 仓库根目录存在 `Excels/Local/` 目录,用于放置 `L-` 前缀的多语言文件。
- 已经会跑生成脚本(`gen-client-json.sh` / `gen-server-json.sh` 等),生成后会在 `Hotfix/Config/Generate` 或 `Server.Config/Config` 产出 `TbLocalization` 类。

## 操作步骤

1. **把字段类型声明为 `text`**。在任意业务表(如成就表、道具表)的 `##type` 行,把字段类型写成 `text`,而不是 `string`。`text` 表示该列填的是 key,运行时再去多语言表里查真实文案;`string` 则直接作为原文使用,不会翻译。

   示例:成就表的 `name` 与 `achievement_content` 字段都用 `text` 类型,只填一个 key:

   | ##var | id | image | name | achievement_content |
   |-------|----|-------|------|---------------------|
   | ##type | int | int | text | text |
   | ##group | | | | |
   | ## | ID | 图标 id | 成就 Key | 成就内容 Key |
   | | 900001 | 101 | achievement_001 | achievement_001_desc |

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L227-L232)

2. **理解 `text` 与 `string` 的区别**。`text` 是需要参与本地化的多语言文案(填的是 key);`string` 是不会翻译的纯文本(直接写内容)。如果把需要翻译的字段误写成 `string`,运行时拿到的是原始字符串,不会出现翻译。

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L223)

3. **准备多语言 Excel 文件**。仓库已经在 `Excels/Local/` 下提供了三份示例,它们都会被合并成同一个 `TbLocalization` 表:

   | 多语言分类 | 文件 | 内容 |
   |------------|------|------|
   | 多语言-成就 | `Excels/Local/L-Localization-成就.xlsx` | 成就文案 |
   | 多语言-文本 | `Excels/Local/L-Localization-文本.xlsx` | 通用文案 |
   | 多语言-UI | `Excels/Local/L-Localization-UI.xlsx` | UI 文案 |

   多个 `L-Localization-*.xlsx` 只要英文部分一致(`Localization`),就自动合并:

   ```
   L-Localization-成就.xlsx    ┐
   L-Localization-文本.xlsx    ├→ 合并成一个 TbLocalization
   L-Localization-UI.xlsx      ┘
   ```

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L199), [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L250-L254)

4. **按模块拆分多语言表(可选)**。当文案量大时,按成就、UI、文本等模块拆成多个 `L-Localization-XXX.xlsx`,英文名前缀保持 `L-Localization` 即可,中文部分可自由命名(工具不会解析)。

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L256)

5. **确认生成命令里打开了 `localizationFileName`**。`luban.conf` 中,客户端的 `client` target 命令带有 `"localizationFileName": "Localization.xlsx"`,没有这一项就不会生成 `TbLocalization`。

   ```json
   {
     "localizationFileName": "Localization.xlsx",
     "command": "--target client --dataTarget json --codeTarget cs-simple-json ...",
     "target": "client",
     "active": true
   }
   ```

   Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

6. **运行生成脚本**。Windows 双击 `gen-client-json.bat`;Mac/Linux 执行 `sh gen-client-json.sh`。生成完成后,业务表中的 `text` 字段就被映射到 `TbLocalization` 上,可在运行时按 key 取当前语言文案。

## 常见变体

- **按客户端/服务端分组**:在多语言文件英文名后加 `c-` 或 `s-`(例如 `L-Localization-c-UI.xlsx`)即可只让对应端拿到。
- **新增自定义多语言文件**:只要放在 `Excels/Local/` 下、英文名前缀是 `L-Localization`,就会被自动并入 `TbLocalization`。
- **按条数拆分大表**:与普通表一样,用相同英文名 + 不同中文名(如 `L-Localization-UI-1.xlsx`、`L-Localization-UI-2.xlsx`)即可,工具会自动合并。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 运行时取到的文案是 key 字面量 | `##type` 写成了 `string` 而不是 `text` | 把字段类型改为 `text` |
| 找不到生成的 `TbLocalization` | `luban.conf` 里 `client` target 命令缺 `localizationFileName` | 按上面步骤 5 在命令 JSON 里补上 |
| 表格英文名含中文 | 工具要求英文名不能出现中文,否则直接报错 | 把 `L-本地化-成就.xlsx` 改为 `L-Localization-成就.xlsx` 这种形式 |
| 文案没生效,只看到 key | `L-Localization-*.xlsx` 没放在 `Excels/Local/` 目录下 | 移动文件到 `Excels/Local/`,然后重新跑生成脚本 |

## 背景(可选)

`text` 字段本质上是引用 `TbLocalization` 的 key,所有 `L-Localization-*.xlsx` 会被合并成同一张多语言表;`string` 则跳过翻译,直接以原始字符串使用。`localizationFileName` 在 `luban.conf` 中是开启客户端多语言生成的开关。
