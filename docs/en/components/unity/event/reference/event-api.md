# EventComponent / IEventManager API Quick Reference

This page collects all public APIs exposed by the GameFrameX.Event event module: the scene component `EventComponent` and its underlying interface `IEventManager`, including actual signatures, event argument base classes, and thread safety notes, so you can look them up directly by table.

## Getting the Component

`EventComponent` is a Unity component attached to the scene (menu path `GameFrameX/Event`, `[DisallowMultipleComponent]`, component priority -7000). In `Awake`, it obtains the event manager via `GameFrameworkEntry.GetModule<IEventManager>()`, after which all public methods are forwarded directly to that manager. Everyday business code only needs to use `EventComponent`; there is no need to create your own `IEventManager` implementation.

## EventComponent Public API

| Name | Signature | Description |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | Gets the total number of event handlers |
| EventCount | `int EventCount { get; }` | Gets the number of events |
| Count | `int Count(string id)` | Gets the number of event handlers for the specified event ID |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | Checks whether the specified event has already subscribed to this handler |
| CheckSubscribe | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | Subscribes only if not already subscribed, avoiding duplicate subscriptions |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | Unsubscribes an event handler |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | Checks and unsubscribes; does nothing if the handler does not exist |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | Sets the default event handler (fallback when there are no subscribers) |
| Fire | `void Fire(object sender, GameEventArgs e)` | Fires an event; thread-safe, callbacks on the main thread, dispatched the next frame |
| Fire (overload) | `void Fire(object sender, string eventId)` | Creates an `EmptyEventArgs` with `eventId` and fires it; internally calls `GameFrameworkGuard.NotNullOrEmpty` to validate non-emptiness |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | Fires an event in immediate mode; not thread-safe, dispatched immediately |

Source: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L171)

Note that `CheckSubscribe` is a convenience method exclusive to `EventComponent` (not on the interface): it first calls `Check`, and only calls the underlying `Subscribe` if not already subscribed.

```csharp
if (!Check(id, handler))
{
    m_EventManager.Subscribe(id, handler);
}
```

## IEventManager Interface Members

`EventComponent` does not expose a forwarding method for `Subscribe`; low-level subscription is done uniformly through the interface (the component layer provides `CheckSubscribe` instead). The interface is defined as follows:

| Name | Signature | Description |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | Gets the number of event handlers |
| EventCount | `int EventCount { get; }` | Gets the number of events |
| Count | `int Count(string id)` | Gets the number of event handlers for the specified event ID |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | Checks whether the event handler exists |
| Subscribe | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | Subscribes an event handler |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | Unsubscribes an event handler |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | Checks and unsubscribes; does nothing if the handler does not exist |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | Sets the default event handler |
| Fire | `void Fire(object sender, GameEventArgs e)` | Fires an event; thread-safe, callbacks on the main thread, the event is dispatched the frame after it is fired |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | Fires an event in immediate mode; not thread-safe, the event is dispatched immediately |

Source: [Runtime/Event/IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L38-L105)

Differences from `EventComponent` at a glance:

- `EventComponent.CheckSubscribe(id, handler)` corresponds to the "check-then-subscribe" version of `IEventManager.Subscribe(id, handler)`.
- `EventComponent.Fire(object sender, string eventId)` is a string overload exclusive to the component, equivalent to `Fire(sender, EmptyEventArgs.Create(eventId))`.
- On initialization failure, the component logs `Log.Fatal("Event manager is invalid.")`.

Source: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

## Choosing Between Fire and FireNow

| Scenario | Usage | Reason |
|------|------|------|
| Firing events from a worker thread / async task | `Fire(sender, e)` | Thread-safe, callbacks are guaranteed to execute on the main thread, but dispatch is deferred to the next frame |
| Need synchronous callback execution on the main thread | `FireNow(sender, e)` | Dispatched immediately; not thread-safe, do not call from worker threads |
| Only need to trigger a signal with no additional data | `Fire(sender, eventId)` | The component overload automatically creates an `EmptyEventArgs` (internally via the reference pool) |

The above thread semantics come from the comments in two places in the source code: `Fire` "This operation is thread-safe; even if fired from a non-main thread, event handlers are guaranteed to be called back on the main thread, but the event is dispatched the frame after it is fired"; `FireNow` "This operation is not thread-safe, and the event is dispatched immediately".
