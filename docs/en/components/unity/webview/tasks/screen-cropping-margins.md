# How to Handle Display Area Cropping and Margins (Notch Screen Adaptation)

This page explains how to handle the WebView's display area cropping and margins under the com.gameframex.unity.webview component, to prevent content from being obscured by the notch. **A note upfront: no direct implementation details for cropping/margins were found in the current repository's source code.** Cropping adaptation for this component is actually handled by the native layer of the underlying gree/unity-webview plugin; this repository only provides the Unity-side facade interfaces (fullscreen/show/hide) and does not expose any cropping, margin, or Safe Area related parameters. Below are the APIs actually available in the current source code and the boundaries of their usage in notch-screen scenarios.

## Prerequisites

- The Unity project has imported the GameFrameX runtime (com.gameframex.unity) and the WebView component.
- A GameFramework component object with `WebViewComponent` attached exists in the scene (component menu path: `Game Framework/WebView`).

## Steps

1. In the Unity scene, add `WebViewComponent` via the menu `Component > Game Framework > WebView` (this component is marked with `[DisallowMultipleComponent]`; only one can be attached per GameObject).

2. After initialization is complete, use `Show` to open the page. The component itself calls `_webViewManager.Initialize()` in `Start()` to complete initialization:

```csharp
/// <summary>
/// Show the WebView
/// </summary>
/// <param name="url">The url to load</param>
public void Show(string url)
{
    _webViewManager.Show(url);
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L51-L58)

3. If the WebView needs to fill the entire screen (on notch screens it is usually presented fullscreen, with the native layer handling the safe area itself), call `MakeFullScreen`:

```csharp
/// <summary>
/// Fullscreen
/// </summary>
public void MakeFullScreen()
{
    _webViewManager.MakeFullScreen();
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L60-L66)

4. When inset margins are needed within the page, you can use `ExecuteJavaScript` to inject CSS into the page to achieve visual margins (e.g., adding padding to `body`); this is the only "margin" approach available in the current source code:

```csharp
/// <summary>
/// Execute JavaScript
/// </summary>
/// <param name="javaScript">JavaScript code</param>
public void ExecuteJavaScript(string javaScript)
{
    _webViewManager.ExecuteJavaScript(javaScript);
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L68-L75)

5. After adaptation is complete, use `Hide` to dismiss the WebView:

```csharp
/// <summary>
/// Hide
/// </summary>
public void Hide()
{
    _webViewManager.Hide();
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L77-L83)

## Common Variants

| Variant | Approach |
|------|------|
| Non-fullscreen WebView with margins | In the current source code, `IWebViewManager` only exposes `Show` / `MakeFullScreen` / `ExecuteJavaScript` / `Hide`, with no SetMargins-style interface; you need to extend it in a custom subclass of `BaseWebViewManager` (see "Background" below) |
| Page content avoiding the notch | Inject CSS `env(safe-area-inset-*)` padding via `ExecuteJavaScript` |
| Quick fullscreen | Call `MakeFullScreen()` directly and let the underlying native layer determine the display area |

Full interface signature reference (`IWebViewManager` is the sole contract of this component):

```csharp
public interface IWebViewManager
{
    void Initialize();
    void Show(string url);
    void MakeFullScreen();
    void ExecuteJavaScript(string javaScript);
    void Hide();
}
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Initialization aborts immediately, with `Web View manager is invalid.` in the logs | `GameFrameworkEntry.GetModule<IWebViewManager>()` returns null | Check that the runtime assembly implementing `BaseWebViewManager` has been included in the build (in AOT/stripping scenarios, `GameFrameXWebViewCroppingHelper` keeps the type linked, see Background) |
| No response when calling `Show` | If the manager is not ready in `WebViewComponent.Awake`, `Start()` returns directly | Make sure the component completes initialization on the same GameObject before calling, or check `IsRuntimeComponentReady` |
| Content obscured by the notch but no cropping parameters found | This repository's source code does not provide cropping/margin APIs | Inject CSS via `ExecuteJavaScript`, or extend a `BaseWebViewManager` subclass to hook into the underlying plugin's SetMargins |

## Background

This component is GameFrameX's facade wrapper around the underlying WebView plugin: the abstract base class `BaseWebViewManager` only declares five abstract methods — `Initialize` / `Show` / `MakeFullScreen` / `ExecuteJavaScript` / `Hide` — and contains no cropping or margin fields; cropping and safe area adaptation are handled by the underlying native plugin (e.g., gree/unity-webview's `SetMargins`), and no code calling it is found in this repository. Although [GameFrameXWebViewCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/GameFrameXWebViewCroppingHelper.cs#L11-L23) in the repository has "Cropping" in its name, its implementation is merely a `_ = typeof(...)` type reference (used to keep the type linked during code stripping) and has nothing to do with display area cropping — do not misuse it.

For the overall structure of the WebView component, see "Introduction to the WebView Component".
