# XCodeConfig.json 設定フィールド早見表

本ページでは `XCodeConfig.json` の全設定フィールドの型、デフォルト値および設定値の説明をまとめており、表を直接参照して記入できます。設定ファイルは必ず `XCodeConfig.json` という名前にする必要があり、プロジェクト内の任意の場所に配置可能で、複数ファイルの共存に対応しています(ビルド時に自動的に深くマージされます)。対応するデータ構造の定義については [XcodeConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XcodeConfig.cs#L11-L48) を参照してください。

## トップレベルフィールド

```json
{
  "swiftBridging": true,
  "signing": {},
  "plist": {},
  "environmentVariables": {},
  "launcherArgs": [],
  "podSource": [],
  "podfile": "",
  "podInstall": true,
  "localizations": [],
  "capabilities": {},
  "unityFramework": {},

}
```

| フィールド | 型 | 説明 |

## unityFramework / unityMain

両者は構造が完全に同一で、それぞれ UnityFramework と Unity-iPhone の 2 つの target に作用します:

```json
{
  "libs": { "+": [], "-": [] },
  "frameworks": { "+": [], "-": [] },
  "properties": { "=": {}, "+": {}, "-": {} },
  "files": {},
  "folders": {},
  "filesCompileFlag": {},
  "otherLinkerFlag": {},
  "runPathSearchPaths": {},
  "pods": {}
}
```

出典:[README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L117-L129)

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `libs` | object:`{"+" : [], "-" : []}` | システムライブラリの追加・削除。例:`libz.tbd`;`+` で追加、`-` で削除 |
| `frameworks` | object:`{"+" : [], "-" : []}` | システム Framework の追加・削除。例:`WebKit.framework` |
| `properties` | object:`{"=" : {}, "+" : {}, "-" : {}}` | ビルドプロパティ。`=` で上書き設定、`+` で追記(配列は既存リストに連結)、`-` で削除 |
| `files` | object | ファイルのコピー。キー = Unity プロジェクト内のファイルパス(`Assets` と同じ階層)、値 = Xcode プロジェクト内のコピー先相対パス;コピー先が既に存在する場合は先に削除してからコピー |
| `folders` | object | フォルダのコピー。`.framework` と `.bundle` を自動認識;コピー先が既に存在する場合はエラーになります |
| `filesCompileFlag` | object | キー = Xcode プロジェクト内のファイルパス、値 = 設定するコンパイルフラグ(例:`-fobjc-arc`) |
| `otherLinkerFlag` | object | リンカフラグ(例:`{"OTHER_LDFLAGS": ["-ObjC"]}`);値は文字列または配列をサポートし、配列を推奨(複数設定のマージが容易になるため) |
| `runPathSearchPaths` | object | ランタイム検索パス(例:`{"LD_RUNPATH_SEARCH_PATHS": ["@executable_path/Frameworks"]}`);同様に配列形式を推奨 |
| `pods` | object | この target の CocoaPods 依存関係。キー = pod 名、値 = バージョン制約;空の値は `pod 'Name'` を、空でない値は `pod 'Name', 'Value'` を生成;同名の pod は自動的にスキップされます |

出典:[README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L131-L239)

`properties` の追加・削除・変更の例：

```json
{
  "properties": {
    "=": { "ENABLE_BITCODE": "NO" },
    "+": { "OTHER_CFLAGS": ["-flag1", "-flag2"] },
    "-": { "UNUSED_FLAG": [""] }
  }
}
```

出典:[README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L160-L173)

`pods` は Podfile 内の対応する target コードブロック(`target 'Unity-iPhone' do` または `target 'UnityFramework' do`)にそれぞれ注入されます:

```json
{
  "unityFramework": {
    "pods": {
      "FirebaseAnalytics": "",
      "FBSDKLoginKit": "~> 14.0"
    }
  },
  "unityMain": {
    "pods": {
      "SomePod": "~> 1.0"
    }
  }
}
```

## signing — コード署名

Unity-iPhone(メイン)target のみに作用し、すべてのフィールドを省略できます:

```json
    "codeSignStyle": "Automatic",
```

| フィールド | 型 | 説明 |

## swiftBridging — Swift ブリッジングヘッダーファイル

Unity-iPhone(メイン)target のみに作用します。デフォルトは `true` で、Swift ファイルとブリッジングヘッダーを自動作成し、Xcode のポップアップが表示されないため CI 環境に適しています;`false` に設定すると無効になります。有効にすると `gameframex_swift_bridging.swift` と `Unity-iPhone-Bridging-Header.h` が作成され、`SWIFT_VERSION` が `5.0` に設定され、`SWIFT_OBJC_BRIDGING_HEADER` が構成されます。

## localizations — ローカライズ

`.lproj/InfoPlist.strings` を自動生成し、Xcode プロジェクトに追加します:

```json
{
  "localizations": [
    {
      "languageCode": "en",
      "validMap": [
        { "key": "CFBundleDisplayName", "value": "My Game" }
      ]
    },
    {
      "languageCode": "zh-Hans",
      "validMap": [
        { "key": "CFBundleDisplayName", "value": "我的游戏" }
      ]
    }
  ]
}
```

出典:[README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L325-L345)

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `languageCode` | string | ISO 639-1 言語コード;簡体字中国語は `zh-Hans`、繁体字中国語は `zh-Hant` を使用 |
| `validMap` | array | キーと値のペアの配列。各項目は `key` と `value` を含む |

よく使用される言語コード:`en`、`zh`、`ja`、`ko`、`es`、`fr`、`de`、`it`、`pt`(`pt-BR`/`pt-PT`)、`ru`、`ar`、`hi`、`tr`、`vi`、`th`、`id`;その他は `code-Region` の組み合わせで指定可能です(例:`en-GB`、`fr-CA`)。

## 複数設定のマージ

プロジェクト内に複数の `XCodeConfig.json` を配置できます(例：各モジュールがそれぞれ管理)。ビルド時に自動的に検出され、深い再帰マージが行われます:

```json
{
  "unityFramework": {
    "pods": {
      "FirebaseAnalytics": ""
    }
  }
}
```

```json
{
  "unityFramework": {
    "pods": {
```

## 間違いやすいポイント

- 設定ファイル名は必ず `XCodeConfig.json` である必要があります。その他の名前は認識されません。
- `otherLinkerFlag` と `runPathSearchPaths` の値は文字列と配列の両方をサポートしますが、配列形式を推奨します。そうすることで複数設定のマージ時に正しくマージされます。
- `folders` のコピー時、コピー先パスが既に存在するとエラーになります;`files` の場合は先に削除してからコピーされます。
- C# 側では `XcodeConfigData` のフィールド名が `library`(JSON では `libs`)、`XcodeConfigCapabilities` の iCloud フィールド名が `iCloudKeyValueStorage` / `iCloudDocuments`(JSON では `iCloud.keyValueStorage` / `iCloud.iCloudDocument`)となっており、両者を混同しないでください。
