# How to Safely Dispatch Events from a Child Thread

Calling `Fire` (rather than `FireNow`) from a child thread (such as a network thread, Task, or async callback) dispatches events safely: the operation is thread-safe, the event is queued, and the event handler is guaranteed to be invoked on the main thread on the next frame, so you can safely access Unity APIs inside the handler.

## Prerequisites

- An object with `EventComponent` attached already exists in the scene (or `EventManager` has already been obtained through the module system).
- Event subscription (`Subscribe` / `CheckSubscribe`) is completed on the main thread first; the child thread is only responsible for `Fire`.

## Steps

1. Subscribe to the event on the main thread (e.g., in `Awake`/`Start`) through the reference to the `EventComponent` in the scene. An event dispatched by `Fire` will not throw an error even if it has no handler (the event pool is created in `AllowNoHandler | AllowMultiHandler` mode):

```csharp
private void Start()
{
    // CheckSubscribe: subscribes only if not already subscribed, avoiding duplicate registration
    eventComponent.CheckSubscribe(DownloadFinishedEventArgs.EventId, OnDownloadFinished);
}

private void OnDownloadFinished(object sender, GameEventArgs e)
{
    // Events dispatched via Fire are guaranteed to be invoked on the main thread, so Unity objects can be manipulated directly
    Debug.Log("下载完成");
}
```

The actual implementation of `CheckSubscribe` (subscribes only if not already subscribed):

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

2. Call the thread-safe `Fire` from the child thread to dispatch the event (the following illustrates the usage; see the source excerpt at the end of this step for the actual `EventComponent` interface). The event is dispatched on the main thread on the **next frame** after being raised:

```csharp
// Child thread code (e.g., Task.Run / network library callback); eventComponent is a reference to the EventComponent in the scene
Task.Run(() =>
{
    byte[] data = DownloadFromNetwork(); // time-consuming operation
    eventComponent.Fire(this, EmptyEventArgs.Create(DownloadFinishedEventArgs.EventId));
});
```

`EventComponent.Fire` provides two overloads; the overload that dispatches by event ID internally uses `EmptyEventArgs.Create(eventId)` and validates that the ID is not null or empty:

```csharp
public void Fire(object sender, GameEventArgs e)
{
    m_EventManager.Fire(sender, e);
}

public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L147-L161)

3. When you need to carry custom data, define a custom argument type that inherits from `GameEventArgs`, fill in the data on the child thread, and raise it with `Fire` (the following illustrates the usage; `EmptyEventArgs` is the built-in no-argument event in the repository, and custom argument classes are implemented in the same way):

```csharp
public class DownloadFinishedEventArgs : GameEventArgs
{
    public const string EventId = "Download.Finished";
    public byte[] Data { get; set; }
}

// Dispatch from the child thread:
eventComponent.Fire(this, new DownloadFinishedEventArgs { Data = data });

// Read it in the main-thread handler:
private void OnDownloadFinished(object sender, GameEventArgs e)
{
    var args = (DownloadFinishedEventArgs)e;
    UseBytes(args.Data);
}
```

`GameEventArgs` is an abstract base class open for inheritance, located in the `GameFrameX.Event.Runtime` namespace:

```csharp
public abstract class GameEventArgs : BaseEventArgs
{
}
```

## Common Variants

| Scenario | Approach |
|------|------|
| Notification only, no data | `Fire(sender, eventId)` string overload, which internally uses `EmptyEventArgs.Create(eventId)` to construct an empty argument |
| Directly holds `IEventManager` | `IEventManager.Fire(object sender, GameEventArgs e)`, consistent with the component wrapper's behavior |
| Event stays on the main thread and must take effect in the same frame | Use `FireNow`, but **never call it from a child thread** (see below) |

## Common Mistakes

| Mistake | Consequences and How to Avoid |
|------|-----------|
| Calling `FireNow` from a child thread | `FireNow` is **not thread-safe**; it dispatches immediately on the calling thread, so handlers execute on the child thread and may crash Unity. Always use `Fire` on child threads. The source comments explicitly state this: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L167-L175) |
| Expecting `Fire` to take effect in the same frame | Events dispatched via `Fire` are not delivered until the next frame after being raised; logic that depends on same-frame timing (e.g., reading state immediately) must be changed to run after the handler callback |
| Calling `Subscribe`/`Unsubscribe` from a child thread | Subscription table operations have no thread-safety guarantee; add and remove handlers only on the main thread |
| Passing an empty string as the event ID | `GameFrameworkGuard.NotNullOrEmpty` inside `Fire(sender, eventId)` throws a validation exception immediately |

## Background

`EventManager` is a `GameFrameworkModule` (priority 7). `Fire` puts the event into an internal `EventPool<GameEventArgs>` queue; every frame, the module calls `m_EventPool.Update(elapseSeconds, realElapseSeconds)` in the main-thread `Update` to drain the queue and invoke handlers — this is where "raised on a child thread, invoked on the main thread, dispatched on the next frame" comes from. See [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L76-L92) and [IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L93-L104) for the relevant implementation.
