# ゲームルーム(Room)モジュールの実装

Room モジュールは、サーバー上のルーム一覧管理、プレイヤーの参加/退出、切断処理、ルームの定時メンテナンスを担当します。本ページのステップに従うことで、既存の GameFrameX プロジェクトに組み込み、独自の Room ビジネスを拡張できます。

## 前提条件

- `GameFrameX.Server` プロジェクトのローカルビルドと起動が完了していること。
- Player モジュールが存在すること。Room は `PlayerRoleId` でプレイヤーと関連付けます。
- Actor パターンに精通していること:`RoomComponent` は `GlobalConst.ActorTypeServer` にバインドされ、リクエストは `ReqXxxHandler` を通じて対応する `RoomComponentAgent` のメソッドに入ります。

### 4. 作成/参加/退出リクエストを実装する

`RoomComponentAgent` は `OnCreateRoomAsync`、`OnJoinRoomAsync`、`OnLeaveRoomAsync` などのエントリを公開し、検証、状態の書き込み、ブロードキャストを完了します。

```csharp
public async Task OnCreateRoomAsync(long roleId, ReqCreateRoom request, RespCreateRoom response)
{
    if (!CheckRoleId(roleId, response)) return;
    if (!TryGetRule(request.GameType, response, out var rule)) return;
    if (!TryResolvePlayerCount(request.MinPlayerCount, request.MaxPlayerCount,
            rule, response, out var min, out var max)) return;

    var now = TimerHelper.UnixTimeSeconds();
    var roomId = State.NextRoomId++;
    var room = new RoomState
    {
        RoomId = roomId,
        Name = string.IsNullOrWhiteSpace(request.Name) ? $"{rule.DefaultNamePrefix}{roomId}" : request.Name.Trim(),
        GameType = request.GameType,
        OwnerRoleId = roleId,
        Status = RoomStatus.Waiting,
        MinPlayerCount = min,
        MaxPlayerCount = max,
        Round = 1,
        CreatedTime = now,
        UpdatedTime = now,
    };
    room.PlayerIds.Add(roleId);
    State.Rooms[roomId] = room;
    State.PlayerRoomMap[roleId] = roomId;

    response.Room = await ToMessageAsync(room);
    await OwnerComponent.WriteStateAsync();
    await NotifyRoomChangedAsync(room, RoomChangeType.Created);
}
```

Source: [RoomComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L86-L140)

`OnJoinRoomAsync` は、ルームが満員でなく `Waiting`/`Ready` 状態のときにプレイヤーを参加させます。人数が `MinPlayerCount` に達すると、ルームの状態は `Ready` に切り替わり、状態が書き戻され、変更がブロードキャストされます。([RoomComponentAgent.cs#L142-L196](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L142-L196))

### 5. 定時メンテナンスタスクを起動する

`Active()` 内で Cron 式を使って `RoomMaintenanceTimer` を登録し、10 秒ごとにタイムアウトした切断プレイヤーと閉鎖済みルームをクリーンアップします。

```csharp
public override async Task<bool> Active()
{
    var isContinue = await base.Active();
    if (isContinue)
    {
        WithCronExpression<RoomMaintenanceTimer>("0/10 * * * * ? *");
    }
    return isContinue;
}
```

### 6. 切断/再接続イベントを組み込む

`[Service]` 属性でマークされたメソッドを通じて、Player モジュールが切断時に呼び出せるようにします。タイムスタンプを記録するだけで、すぐにはキックしません。実際の削除はメンテナンスタスクの期限到達後に行われます。

```csharp
[Service]
public virtual Task MarkPlayerDisconnected(long roleId)
{
    if (roleId <= 0 || !TryGetActiveRoom(roleId, out _)) return Task.CompletedTask;
    State.DisconnectedPlayerTimeMap[roleId] = TimerHelper.UnixTimeSeconds();
    return OwnerComponent.WriteStateAsync();
}
```

## よくあるバリエーション

- 新しいゲームタイプの追加:`RoomRuleMap` にエントリを追加し、同時に `GameType` 列挙とプロトコルフィールドを拡張します。
- ルーム観戦:`RoomState.PlayerIds` 以外の `SpectatorIds` リストを再利用し、`OnJoinRoomAsync` でリクエストパラメータに応じて区別します。
- ルームオーナー移行:`LeaveRoom` でルームオーナーの退出を検出し、`OwnerRoleId` をリスト内の最初の在室プレイヤーに引き継ぎます。
- プライベートルーム:`RoomState` に `PasswordHash` フィールドを追加し、`OnJoinRoomAsync` のエントリで検証します。

## よくあるエラー

- `OwnerComponent.WriteStateAsync()` の呼び忘れ:状態がメモリ内のみで有効になり、再起動後に失われます。
- ルームが `Playing` に入った後も参加を許可してしまう:`OnJoinRoomAsync` では `Status` が `Waiting`/`Ready` のみであることが既に検証されています。新しいプレイ方法を追加する際は、この判断をバイパスしないでください。
- 新しいルームを作成する前に古いルームを閉じない:まず `CloseRoomAsync(activeRoom, RoomChangeType.Closed)` を呼び出す必要があります。さもないと `State.PlayerRoomMap` に一対多のマッピングが発生します。
- 切断時にすぐにキックする:代わりに `MarkPlayerDisconnected` を呼び出して時刻を記録し、`RoomMaintenanceTimer` にクリーンアップを任せます。

## 背景(オプション)

`RoomComponent` は Actor モデルを通じてサーバーインスタンスにバインドされ、すべてのルーム操作は同じ Actor のシリアルキューに入り、`RoomListState` の同時変更を回避します。`NotifyRoomChangedAsync` はイベントバスを通じて購読者(ロビー、チャット、フレンド)にブロードキャストします。具体的なイベントタイプは `RoomChangeType` 列挙で区別されます。
