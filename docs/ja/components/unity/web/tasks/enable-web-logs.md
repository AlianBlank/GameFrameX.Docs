# リクエストログの有効化と Inspector の使用方法

Unity のメニューバー `GameFrameX/Scripting Define Symbols` 配下の「开启Web发送/接收日志打印」にチェックを入れてスクリプトの再コンパイルを待つと、`WebManager` が送信する各 HTTP リクエストと受信したレスポンスが `Log.Debug` として Console に出力されます。また、`WebComponent` をアタッチした GameObject を選択すると、Inspector にリクエストタイムアウトを調整するための 0–120 秒の `Timeout` スライダーが追加で表示されます。

## 前提条件

- プロジェクトに `com.gameframex.unity.web` パッケージがインストール済みであり、Web コンポーネントの初期化が完了していること。
- Console パネルのログレベルで Debug ログの表示が許可されていること。そうでない場合、マクロを有効にしても出力は表示されません。

## 操作手順：リクエストログの有効化

1. Unity 上部メニューの `GameFrameX/Scripting Define Symbols` を開きます。
2. 必要に応じて以下のメニュー項目をクリックします（クリックすると即時に有効になり、マクロは現在の Build Target の Scripting Define Symbols に書き込まれます）。

| メニュー項目 | 機能 | 書き込まれるマクロ |
|------|------|---------|
| `Enable Web Send Logs(开启Web发送日志打印)` | 各リクエストの URL、Header、Form を出力 | `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` |
| `Disable Web Send Logs(关闭Web发送日志打印)` | 送信ログマクロを削除 | — |
| `Enable Web Receive Logs(开启Web接收日志打印)` | 各レスポンスの URL、Header、Form、Content を出力 | `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` |
| `Disable Web Receive Logs(关闭Web接收日志打印)` | 受信ログマクロを削除 | — |

3. Unity がスクリプトを再コンパイルするのを待ちます（右下のスピナーの回転が終わるまで）。
4. 任意の Web リクエストを発行すると（例：`WebManager` の Get/Post インターフェース）、Console に `Web Request: ...` や `Web Response: ...` といった形式の Debug ログが表示されます。

メニュー項目の裏側の実装は、マクロ定義の追加・削除です：

```csharp
public static class WebLogScriptingDefineSymbols
{
    public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG";
    public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_SEND_LOG";

    [MenuItem("GameFrameX/Scripting Define Symbols/Enable Web Send Logs(开启Web发送日志打印)", false, 451)]
    public static void EnableNetworkSendLogs()
    {
        ScriptingDefineSymbols.AddScriptingDefineSymbol(EnableNetworkSendLogScriptingDefineSymbol);
    }
}
```

Source: [Editor/WebLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/WebLogScriptingDefineSymbols.cs#L40-L61)

マクロを有効にすると、`WebManager` 内の対応するコードセグメントがパッケージにコンパイルされ、ログの内容はリクエスト/レスポンスの URL、Header、Form、およびレスポンスの Content になります（エラー発生時は Content にエラーメッセージが入ります）：

```csharp
#if ENABLE_GAMEFRAMEX_WEB_SEND_LOG
    Log.Debug($"Web Request: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)}");
#endif
```

if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)

## 操作手順：WebComponent Inspector の使用

1. Hierarchy で `WebComponent` コンポーネントがアタッチされた GameObject を選択します。
2. Inspector パネルの下部に `Timeout` スライダーが表示され、値の範囲は 0–120 です。
3. スライダーをドラッグします：
   - **実行モード（Play Mode）**：ランタイムオブジェクトの `t.Timeout` に直接書き込まれ、以降のリクエストに即時に反映されます。
   - **非実行モード**：シリアライズされたプロパティ `m_Timeout` に書き込まれ、シーン/ prefab とともに保存されます。

```csharp
[CustomEditor(typeof(WebComponent))]
internal sealed class WebComponentInspector : ComponentTypeComponentInspector
{
    public override void OnInspectorGUI()
    {
        base.OnInspectorGUI();
        serializedObject.Update();

        WebComponent t = (WebComponent)target;
        float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
        if (timeout != m_Timeout.floatValue)
        {
            if (EditorApplication.isPlaying)
            {
                t.Timeout = timeout;
            }
            else
            {
                m_Timeout.floatValue = timeout;
            }
        }

        serializedObject.ApplyModifiedProperties();
    }
}
```

Source: [Editor/Inspector/WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/Inspector/WebComponentInspector.cs#L7-L37)

> `WebComponentInspector` は `ComponentTypeComponentInspector` を継承しているため、Inspector にはコンポーネント上の `IWebManager` 実装タイプを選択するドロップダウン（`RefreshComponentTypeNames(typeof(IWebManager))`）も同時に保持されます。

## よくあるバリエーション

- **リクエストのみを確認しレスポンスは見ない**：`Enable Web Send Logs` のみをクリックします。2 つのマクロは相互に独立しており、任意に組み合わせることができます。
- **マクロの手動管理**：`Project Settings → Player → Scripting Define Symbols` に直接 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG;ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` を入力することもでき、メニュー操作と同じ効果が得られます。
- **タイムアウトの動作**：`Timeout` スライダーで書き込まれた値は、`WebManager` 内で秒（WebGL）またはミリ秒（非 WebGL）単位でリクエストに適用されます。詳細は `Runtime/Web/WebManager.cs` の `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;` と `request.Timeout = (int)RequestTimeout.TotalMilliseconds;` を参照してください。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| メニューをクリックしても Console に `Web Request/Web Response` ログが表示されない | Console パネルで Debug レベルのログがフィルタリングされている | Console 右上のフィルターで Debug/Info にチェックを入れる |
| ログが一部のプラットフォームでのみ表示される | マクロは Build Target ごとに有効になるため、プラットフォーム切り替え後に再度チェックが必要 | プラットフォーム切り替え後にメニュー項目を再度実行する |
| スライダーを変更しても古いタイムアウトでリクエストが発行される | 非 Play モードでの変更は `m_Timeout` にのみ書き込まれるため、再度 Play に入るかシーンを保存する必要がある | Play モードで調整する、またはシーンを保存してから再度 Play に入る |
| ログ内容に `Form`/`Header` が含まれない | 当該リクエスト自体がフォームやリクエストヘッダーを伴っていない | 呼び出し元が渡す header/form パラメータを確認する |

## 検証

1. `GameFrameX/Scripting Define Symbols → Enable Web Send Logs` を実行した後、任意の GET リクエストを発行します。
2. Console に `Web Request: {URL} \n Header: ... \n Form: ...` が表示されれば送信ログが有効になっています。レスポンス受信後に `Web Response: ... \n Content: ...` が表示されれば受信ログが有効になっています。
3. Play モードで Inspector の `Timeout` スライダーをドラッグしてリクエストを発行し、ログ内のリクエスト所要時間やタイムアウト例外がそれに応じて変化するかを確認します。

## 背景

リクエストログは、条件付きコンパイルマクロ `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` で `Log.Debug` 呼び出しをラップしています。マクロを無効にすると該当コードはコンパイル成果物にまったく含まれないため、正式リリースパッケージにパフォーマンスのオーバーヘッドが残ることはありません。これが、メニューの切り替え時にスクリプトの再コンパイルが 1 回発生する理由です。Inspector 側の `Timeout` スライダーは、`EditorGUILayout.Slider` によって Play と非 Play の 2 つの書き込みパスを切り分け、ランタイムでの動的調整とシーンのシリアライズが互いに干渉しないようにしています。
