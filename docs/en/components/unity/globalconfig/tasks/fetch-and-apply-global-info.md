# How to Fetch and Write Global Configuration from the Server

This guide explains how to use `GlobalConfigComponent` to pull global configuration (JSON) from the server, deserialize it into `ResponseGlobalInfo`, and write it into the component so other game modules can read fields such as `HostServerUrl`, `CheckAppVersionUrl`, and `AOTCodeLists`.

## Prerequisites

- The `com.gameframex.unity.globalconfig` package is installed, and the `GameFrameX/Global Config` component exists in the scene.
- The server provides an HTTP endpoint that returns JSON whose structure can map to the `ResponseGlobalInfo` fields.
- An available HTTP/WebRequest utility exists in the project (this guide uses `UnityWebRequest` in the example).

## Steps

1. Get a reference to the component. The component inherits from `GameFrameworkComponent` and can be obtained via `GameEntry.GetComponent<GlobalConfigComponent>()`.

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   var cfg = GameEntry.GetComponent<GlobalConfigComponent>();
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L13-L14)

2. Construct the request body `RequestGlobalInfo`. It inherits from `RequestBase`, which provides common fields such as language, platform, package name, and channel out of the box. Extend as needed.

   ```csharp
   var req = new RequestGlobalInfo
   {
       Language    = "zh-CN",
       AppVersion  = Application.version,
       Platform    = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel     = "default",
       SubChannel  = string.Empty,
   };
   ```

   Source: [RequestGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGlobalInfo.cs#L6-L8), [RequestBase.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestBase.cs#L6-L37)

3. Send an HTTP request and read the JSON text. It is recommended to use a coroutine with `UnityWebRequest`.

   ```csharp
   string url = "https://your-server/global-info";
   string json = null;

   using (var www = UnityEngine.Networking.UnityWebRequest.Post(url, JsonUtility.ToJson(req)))
   {
       www.SetRequestHeader("Content-Type", "application/json");
       yield return www.SendWebRequest();

       if (www.result == UnityEngine.Networking.UnityWebRequest.Result.Success)
       {
           json = www.downloadHandler.text;
       }
       else
       {
           Debug.LogError(www.error);
       }
   }
   ```

4. Save the JSON string as the original data. The component provides `SetOriginalData(string)`. Passing `null` will throw `ArgumentNullException`, so handle defensively.

   ```csharp
   cfg.SetOriginalData(json);
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L126-L134)

5. Deserialize the JSON into `ResponseGlobalInfo`, then call `SetGlobalConfig(...)` to write it into the component. Similarly, passing `null` will throw `ArgumentNullException`.

   ```csharp
   var info = JsonUtility.FromJson<ResponseGlobalInfo>(json);
   cfg.SetGlobalConfig(info);
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L160-L168)

6. Read and use the global information. Subsequent modules can access the data through properties such as `cfg.GlobalInfo`, `cfg.HostServerUrl`, `cfg.CheckAppVersionUrl`, and `cfg.AOTCodeLists`. `AOTCodeLists` is automatically deserialized from the `AOTCodeList` string into a `List<string>`.

   ```csharp
   string host        = cfg.HostServerUrl;          // Optional override value issued by the server
   string checkApp    = cfg.GlobalInfo.CheckAppVersionUrl;
   var   aotList      = cfg.AOTCodeLists;           // List<string>
   string rawSnapshot = cfg.OriginalData;           // Retained original JSON
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L56-L120), [ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L6-L27)

## Common Variations

- **Local offline cache**: First read `cfg.OriginalData` to get the previously saved JSON. If the new request fails, reuse the old value to avoid blocking on the network every startup.
- **Request with retries**: Wrap step 3 in a `for (int i = 0; i < 3; i++)` retry loop. Fall back to the local cache only after all attempts fail.
- **Extending request fields**: If the server requires additional parameters (such as a server ID), create `class MyRequest : RequestGlobalInfo { public string ServerId; }`. The field will automatically be serialized along with the JSON.

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| `SetOriginalData(null)` throws `ArgumentNullException` | Passing a null reference | Check `json != null` before calling; on failure, retain the old value or write an empty string |
| `SetGlobalConfig(null)` throws `ArgumentNullException` | Deserialization result is null (empty string or invalid JSON) | First check with `string.IsNullOrEmpty`; on failure, record a log and abort writing |
| `cfg.AOTCodeLists` is empty | The `AOTCodeList` field is not a valid JSON array string | Use the `["A","B"]` format when writing; the component internally falls back to `Log.Error` if deserialization fails |

## Background (Optional)

`GlobalConfigComponent` is a `GameFrameworkComponent` with `IsAutoRegister = false` to disable automatic registration. It must be explicitly obtained by `GameEntry` via `GetComponent<T>()`. It maintains two states simultaneously: the "original JSON cache" and the "deserialized result". The former is used for local fallback, while the latter is used by business modules to read individual fields. `AOTCodeList` is parsed into a cached `List<string>` during `set` to avoid repeated deserialization on each access.
