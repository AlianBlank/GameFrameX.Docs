# 플레이어 속성(Attribute) 모듈 구현

플레이어 속성(Attribute) 모듈은 「최종값 슬롯 + 파생 슬롯」 기반의 통합 계산 공식을 제공하며, 기초값, 덧셈, 1차 백분율, 최종 덧셈, 최종 백분율 다섯 개의 슬롯을 수정하여 최종 속성을 얻습니다. 이 페이지에서는 비즈니스에서 플레이어 속성을 초기화, 수정 및 읽는 방법을 설명합니다.

## 사전 조건

- `GameFrameX`의 컴포넌트 / Agent 패턴에 익숙하고, `PlayerAttributeComponent`와 `PlayerAttributeComponentAgent`의 관계를 이해하고 있어야 합니다.
- 이벤트 버스에 대해 이해하고 있으며, `AttributeChangedEventArgs` 리스너를 등록하는 방법을 알고 있어야 합니다.

## 속성 슬롯과 계산 공식

각 최종 속성(`AttributeType.Life` 등)은 5개의 수치 슬롯에 대응하며, 오프셋은 `AttributeSlotKind`로 정의되고, 백분율 기준값 `PercentBase = 10000`은 100%를 나타냅니다.

| 슬롯 | 오프셋 | 용도 |
|------|------|------|
| Final | 0 | 최종값 슬롯, 번호가 주 번호와 동일 |
| Base | 10000 | 기초값 슬롯, 설정, 레벨 또는 초기화에서 가져옴 |
| Add | 20000 | 덧셈 수정 |
| Pct | 30000 | 1차 백분율 수정(기준값 10000) |
| FinalAdd | 40000 | 최종 덧셈 수정 |
| FinalPct | 50000 | 최종 백분율 수정(기준값 10000) |

재계산 공식은 `AttributeCore.CalculateFinal`이 제공합니다:

```csharp
public static long CalculateFinal(long baseValue, long addValue, long pctValue, long finalAddValue, long finalPctValue)
{
    checked
    {
        var firstLayer = (baseValue + addValue) * (PercentBase + pctValue) / PercentBase;
        return (firstLayer + finalAddValue) * (PercentBase + finalPctValue) / PercentBase;
    }
}
```

출처: [AttributeCore.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/AttributeCore.cs#L120-L127)

열거형과 슬롯 정의는 다음과 같습니다:

```csharp
public enum AttributeType
{
    None = 0,
    Life = 1, PhysicalAttack = 2, MagicAttack = 3,
    PhysicalDefense = 4, MagicDefense = 5,
    Critical = 6, CriticalDamage = 7, Precision = 8, Block = 9,
    // ... 파생 슬롯은 주 번호 + AttributeSlotKind 오프셋을 사용
}

public enum AttributeSlotKind
{
    Final = 0, Base = 10000, Add = 20000,
    Pct = 30000, FinalAdd = 40000, FinalPct = 50000
}
```

## 작업 단계

### 1. 플레이어 엔티티에 속성 컴포넌트 장착

`PlayerAttributeComponent`는 이미 `[ComponentType(GlobalConst.ActorTypePlayer)]`로 표시되어 있어, 플레이어 엔티티 생성 시 자동으로 장착되므로 수동 등록이 필요 없습니다.

```csharp
public sealed class PlayerAttributeComponent : StateComponent<PlayerAttributeState>

}
```

출처: [PlayerAttributeComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/Component/PlayerAttributeComponent.cs#L38-L40)

### 2. 최종 속성 기록 및 재계산

`PlayerAttributeComponentAgent`의 변경 진입점을 통해 파생 슬롯을 수정한 후, `AttributeCore.RecalculateFinal`로 최종값을 다시 계산하고 해당 Final 슬롯에 기록합니다. `TryGetFinalAttribute`는 파생 슬롯으로부터 소속 최종 속성을 역추론합니다.

```csharp
var state = await agent.GetState();
var attributes = state.Attributes;

// Life의 Base 슬롯 수정
var baseKey = AttributeCore.GetSlotAttribute(AttributeType.Life, AttributeSlotKind.Base);
attributes[baseKey] = 100;

// Life 최종값 재계산
attributes[AttributeType.Life] = AttributeCore.RecalculateFinal(attributes, AttributeType.Life);
```

출처: [AttributeCore.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/AttributeCore.cs#L46-L109)

### 3. 속성 변경 이벤트 수신

속성 변화에 대응하기 위해 `AttributeChangedEventArgs`를 구독합니다(`PlayerAttributeChangedEventListener` 등의 구체적인 리스너가 처리). 이벤트는 변경된 속성 번호와 새 값을 담고 있습니다.

```csharp
public class AttributeChangedEventArgs : EventArgs
{
    public AttributeType AttributeType { get; }
    public long OldValue { get; }
    public long NewValue { get; }
}
```

출처: [AttributeChangedEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/EventData/AttributeChangedEventArgs.cs)

### 4. 초기 기본값 사용

플레이어가 처음 로그인할 때 `PlayerInitialAttributeDefaults`가 제공하는 초기화 데이터로 Base 슬롯을 채운 뒤, 첫 재계산을 트리거하여 초기 최종 속성을 얻습니다.

## 일반적인 변형

- **퍼센트 보너스**: 장비 / Buff는 `Pct` 또는 `FinalPct` 슬롯만 수정하며, 최종값을 직접 계산할 필요가 없습니다. 플레이어가 로그아웃할 때 해당 수정치를 제거하면 됩니다.
- **엔티티 간 속성 집계**: 여러 출처(플레이어 + 펫 + 장비)를 병합하여 계산해야 하는 경우, 각자 속성 사전을 하나씩 유지하고 최종 읽기 지점에서 `AttributeCore.RecalculateFinal`을 통합 호출하면 됩니다.
- **일괄 재계산**: 여러 최종 속성이 동시에 변할 경우, 알려진 최종 속성(`AttributeCore.IsFinalAttribute`가 true를 반환하는 9개 열거형 값)을 순회하며 `RecalculateFinal`을 각각 호출하면 됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| `ArgumentOutOfRangeException: 必须传入已知最终属性。` | 최종 속성이 아니거나 파생 슬롯을 `RecalculateFinal`에 직접 전달함 | `IsFinalAttribute`가 true를 반환하는 속성에 대해서만 재계산 호출 |
| `ArgumentOutOfRangeException: 必须传入已知属性数值槽。` | `AttributeSlotKind`에 정의되지 않은 커스텀 값 전달함 | 6개의 내장 열거형 값으로 제한 |
| 최종 속성이 항상 0임 | 파생 슬롯이 누락되었지만 재계산이 트리거되지 않음 | 파생 슬롯을 하나라도 수정한 후에는 반드시 `RecalculateFinal`을 호출하고 `Final` 슬롯에 다시 기록해야 함 |
| 퍼센트 보너스 결과가 100배 차이남 | `0.5`를 Pct 슬롯에 직접 기록함 | Pct / FinalPct 슬롯은 기준값 `10000`을 사용하며, 50%는 `5000`으로 기록 |

## 배경(선택 사항)

속성 번호 설계에서는 10000 / 20000 / 30000 등의 고정 오프셋으로 슬롯을 구분하여, 임의의 파생 슬롯이 `value % PercentBase`를 통해 소속 최종 속성을 역추론할 수 있으므로 변경 이벤트를 통합 처리하기 편리합니다. `PercentBase = 10000`은 부동 소수점 정밀도 문제를 피할 수 있을 뿐만 아니라, 기획자가 「만분율」로 수치를 설정하기에도 편리합니다.
