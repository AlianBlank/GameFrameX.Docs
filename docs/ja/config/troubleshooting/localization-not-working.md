# ローカライズテキストが反映されない場合の対処法

`Excels/Local/` に多言語エントリを追加・変更したのに、実行時に新しいテキストが表示されない場合、通常は **Luban が対応するローカライズテーブルをスキャンできていない**、または **コード生成時にローカライズパラメータが指定されていない** ことが原因です。本ページでは、よくある症状と迅速な修正手順を紹介します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 起動後に翻訳文ではなく Key(例:`Text_001`)のみが表示される | ローカライズファイルが LuBan にロードされていない | 生成コマンドに `-x l10n.textFile.path=./Excels/Local/` が含まれていることを確認する |
| 新しく追加した `L-Localization-*.xlsx` が反映されない | ファイル名が `L-Localization-` プレフィックスに一致していない、または `Excels/Local/` に配置されていない | `L-Localization-<分類>.xlsx` にリネームして `Excels/Local/` ディレクトリに配置する |
| `Localization.xlsx` を生成した後もフィールド不足のエラーが発生する | `luban.conf` の `localizationFileName` が未設定またはスペルミス | 対応する target の command に `"localizationFileName": "Localization.xlsx"` を追加する |
| 言語を切り替えた後もソース言語のテキストが表示される | ランタイムコードがローカライズテーブルを再ロードしていない / 再生成がトリガーされていない | 古い生成物を削除し、`gen-client-json.sh`(または対応する .bat)を再実行する |
| クライアントをパッケージ化した後、リモートテキストが空文字列になる | JSON データディレクトリ(例:`Bundles/Config`)が更新されていない | `gen-client-bin.sh` を再実行し、生成された JSON で `outputDataDir` を上書きする |

## 修正手順

### 1. ローカライズファイルの場所と命名を確認する

ローカライズファイルは `Excels/Local/` ディレクトリに配置し、`L-Localization-` で始まる必要があります。リポジトリのサンプルには既に 3 つのローカライズファイルが含まれています:

- `Excels/Local/L-Localization-UI.xlsx`
- `Excels/Local/L-Localization-成就.xlsx`
- `Excels/Local/L-Localization-文本.xlsx`

新しく追加するローカライズファイルも、同様の命名規則に従ってください。

### 2. 生成コマンドでローカライズを有効にする

リポジトリ付属の `gen-client-json.sh` には、既にローカライズ関連のパラメータが明示的に渡されています:

```bash
dotnet ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json \
  --xargs outputDataDir=../Unity/Assets//Bundles/Config \
  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
  --xargs tableImporter.name=gameframex \
  -x l10n.provider=gameframex \
  -x l10n.textFile.keyFieldName=key \
  -x l10n.textFile.path=./Excels/Local/ \
  --conf ./Luban.conf
```

出典:[gen-client-json.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.sh#L1-L1)

コマンドに `-x l10n.textFile.path=./Excels/Local/` や `-x l10n.provider=gameframex` が含まれていない場合は、追加して再生成してください。

### 3. `luban.conf` に `localizationFileName` を宣言する

`luban.conf` では、ローカライズデータを生成する target に `localizationFileName` フィールド(デフォルト名 `Localization.xlsx`)を追加する必要があります:

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

出典:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

### 4. 再生成して生成物を上書きする

- クライアント JSON:`gen-client-json.sh`(または `gen-client-json.bat`)。生成物は `%UNITY_ASSETS_PATH%/Bundles/Config` に出力されます。
- クライアントバイナリ:`gen-client-bin.sh`。生成先は同じく `Bundles/Config` ですが、出力形式は `cs-bin` です。
- サーバー:サーバーは現在ローカライズを必要としません(`server` target には `localizationFileName` がありません)。サーバー側で多言語を有効にする必要がある場合は、`client` の記述を参考に `localizationFileName` フィールドを追加してください。

### 5. テーブルヘッダーと `keyFieldName` を確認する

`-x l10n.textFile.keyFieldName=key` は、ローカライズテーブルに `key` という名前の列が必要であることを意味します。テーブルヘッダーの列名が `key` でない場合(例:`Key` や `ID` と記述している場合)、読み込みに失敗します。対処方法：Excel で先頭列の名前を `key` に変更するか、生成コマンドの `keyFieldName` をテーブルの実際の列名に変更してください。

## 検証

1. 対応する生成スクリプトを再実行し、`active: true` の設定が無効化されていないことを確認します。
2. 生成ディレクトリ(例:`Bundles/Config` や `%SERVER_PATH%/Server.Config/Json`)に `Localization.xlsx` とその派生データが生成・更新されているかを確認します。
3. ランタイムコードで `key` を指定してローカライズテキストを取得し、言語切り替え後には空文字やソース言語ではなく、対応する翻訳文が返されることを確認します。
4. それでも `key` 自体しか表示されない場合は、ローカライズデータがロードされていないことを意味します。手順 2 のコマンドに `-x l10n.textFile.path` が含まれているか、および `Excels/Local/` 配下に実際に `L-Localization-*.xlsx` が存在するかを確認してください。
