# 复制文件与文件夹到 Xcode 工程

本页说明如何在 Xcode 构建后处理配置中,把本地文件或整个文件夹复制进生成的 Xcode 工程,并自动加入 Build 列表、搜索路径。你只需在 Xcode 配置文件(JSON)的 `files` 与 `folders` 字段里写"源路径 → 目标路径"映射,构建时会自动执行复制。

## 前置条件

- Unity 工程已切换到 iOS 平台(实现都在 `#if UNITY_IOS` 之下)。
- 已完成 Xcode 构建后处理的基础接入:`PostProcessBuildHelper` 会在构建回调中读取合并后的配置并调用 `Run`。

## 操作步骤

1. 打开你的 Xcode 构建后处理配置文件,找到目标 target 的配置节点(如 `unityMain` / `unityFramework` 对应的哈希表)。
2. 在该节点下添加 `files` 字段,Key 为源文件路径(相对于 Unity 工程根目录,即 `Environment.CurrentDirectory`),Value 为目标路径(相对于生成的 Xcode 工程目录):

```json
{
  "files": {
    "Assets/Plugins/iOS/NativeCode.mm": "Libraries/NativeCode.mm",
    "Assets/Plugins/iOS/MySDK.framework": "Frameworks/MySDK.framework"
  }
}
```

3. 需要复制整个文件夹时,添加 `folders` 字段,同样以"源路径 → 目标路径"映射:

```json
{
  "folders": {
    "Assets/Plugins/iOS/NativeFolder": "Libraries/NativeFolder"
  }
}
```

4. 触发一次 iOS 构建。构建结束后,`Run` 会按顺序执行复制:先 `RunCopyFiles` 处理 `files`,再 `CopyFolders` 处理 `folders`:

```csharp
// 复制文件
RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
// 复制文件夹
CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L173-L176)

5. 在 Xcode 工程中确认:文件已出现在对应目标路径,并已被 `AddFileToBuild` 加入目标 target 的 Build 列表;控制台会输出 `copy file {src} -> {des}` 日志。

## 复制行为细节

复制并不是简单拷贝,以下行为来自源码实现,配置时需要知道:

| 行为 | 说明 |
|------|------|
| 目标目录自动创建 | `CopyFolder` 会先删除已存在的同名目录/文件,再 `Directory.CreateDirectory` 重建后递归复制 |
| 覆盖已有文件 | 单文件复制使用 `File.Copy(src, des, true)`,同名文件会被覆盖 |
| 忽略隐藏与垃圾文件 | 文件名以 `.` 开头、`.gitkeep`、`.DS_Store` 会被跳过,不复制也不加入 Build |
| 自动加入 Build | 文件通过 `proj.AddFile` + `proj.AddFileToBuild` 加入工程 |
| 自动加搜索路径 | 复制 `.framework` / `.xcframework` 自动加 `FRAMEWORK_SEARCH_PATHS`;`.h` 自动加 `HEADER_SEARCH_PATHS`;`.a` 自动加 `LIBRARY_SEARCH_PATHS`,前缀为 `$PROJECT_DIR` |
| bundle 同时加入主 target | `folders` 中以 `.bundle` 结尾的项,除目标 target 外还会通过 `AddFileToBuild(mainTargetGuid, fileGuid)` 加入 Unity 主 target |
| 文件夹整体作为 framework | `folders` 的目标路径以 `.framework` / `.xcframework` / `.bundle` / `.a` 结尾时,整个目录被当作单个库文件加入构建,不再递归展开 |

文件复制的核心实现:

```csharp
private static void CopyFile(PBXProject proj, string targetGuid, string xcodePath, string src, string des)
{
    bool needCopy = IsNeedCopy(src);
    if (needCopy)
    {
        File.Copy(src, des, true);
        proj.AddFileToBuild(targetGuid, proj.AddFile(des, des.Replace(xcodePath + "/", ""), PBXSourceTree.Absolute));
        AutoAddSearchPath(proj, xcodePath, targetGuid, des);
        Debug.Log("copy file " + src + " -> " + des);
    }
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L42-L52)

文件夹递归复制的核心实现(先清空目标再重建):

```csharp
private static void CopyFolder(string srcPath, string dstPath)
{
    if (Directory.Exists(dstPath))
    {
        Directory.Delete(dstPath, true);
    }

    if (File.Exists(dstPath))
    {
        File.Delete(dstPath);
    }

    Directory.CreateDirectory(dstPath);

    foreach (var file in Directory.GetFiles(srcPath))
    {
        if (IsNeedCopy(Path.GetFileName(file)))
        {
            File.Copy(file, Path.Combine(dstPath, Path.GetFileName(file)));
        }
    }

    foreach (var dir in Directory.GetDirectories(srcPath))
    {
        CopyFolder(dir, Path.Combine(dstPath, Path.GetFileName(dir)));
    }
}
```

## 常见变体

- **复制 SDK / 静态库**:把 `.framework`、`.xcframework`、`.a` 放进 `folders`,目标路径直接写成 `Frameworks/xxx.framework`。框架会被加入 Link Binary With Libraries 并自动补搜索路径(`AddFrameworkToProject(targetGuid, root, false)`),`.a` 静态库只加入链接阶段。
- **复制资源 bundle**:`folders` 中以 `.bundle` 结尾的目录会同时加入 Unity 主 target 与 UnityFramework target,适合需要随包分发的资源。
- **只想把文件放进工程不参与编译的细节调整**:复制完成后,可通过同级的 `filesCompileFlag` 配置设置编译标记,该步骤在复制之后执行(`SetFilesCompileFlag`)。

## 常见错误

| 问题 | 原因 | 规避 |
|------|------|------|
| 复制后 Xcode 里找不到文件 | 源路径写成了绝对路径或相对层级不对 | `files`/`folders` 的 Key 是相对 Unity 工程根目录的路径,运行时会 `Path.Combine(Environment.CurrentDirectory, key)` |
| 某些文件始终没被复制 | 命中了 `IsNeedCopy` 的排除规则 | 文件名以 `.` 开头、`.gitkeep`、`.DS_Store` 会被直接跳过,改名或移出 |
| 每次构建后目标目录内容"丢失" | `CopyFolder` 会先 `Directory.Delete(dstPath, true)` 清空目标目录 | 不要把其他内容手动放进 `folders` 配置的目标目录 |
| 单文件复制报目标已存在异常未生效 | 实际不会,单文件复制带 `overwrite: true` | 若仍失败,检查目标目录是否存在同名文件夹(会被当作目录处理) |
| framework 链接报找不到 | 未走自动搜索路径逻辑 | 确认以 `.framework` / `.xcframework` / `.a` 结尾,`AutoAddSearchPath` 只对这三种后缀生效 |

## 背景

复制发生在 Xcode 工程生成之后:`PostProcessBuildHelper` 读取 PBXProject 与合并配置,`Run` 依次处理 properties、frameworks、libs、files、folders 等;`CopyFolders` 额外接收 `mainTargetGuid`,是为了让 `.bundle` 能同时挂到 Unity 主 target 上。文件路径均基于 `PBXSourceTree`,framework/静态库用 `Source`,单文件用 `Absolute`。
