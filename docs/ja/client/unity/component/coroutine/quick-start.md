# クイックスタート:インストールして最初のコルーチンを起動する

このガイドでは、GameFrameX コルーチンパッケージを Unity プロジェクトに組み込み、「起動→停止→フレーム末尾のコールバック」という 3 つの最もよく使われるインターフェースを実行します。このコンポーネントは Unity のネイティブコルーチンの薄いラッパーであり、内部で `ConcurrentDictionary` を使って起動済みのすべてのコルーチンを追跡し、停止し忘れによるぶら下がり参照を回避します。

## 前提条件

- Unity 2017.1 以降(テストターゲットは Unity 2019.4)
- 正常に開くことができる Unity プロジェクト
- プロジェクトに `com.gameframex.unity.runtime` がインストール済み(本コンポーネントはその `GameFrameworkComponent` を継承しています)

## インストール

以下のいずれかの方法でパッケージをプロジェクトに追加します:

1. **Scoped Registry 経由(推奨)** —— `Packages/manifest.json` を編集し、`scopedRegistries` に GameFrameX レジストリを追加して依存関係を宣言します:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.coroutine": "1.0.3"
     }
   }
   ```

2. **Git URL 経由** —— `dependencies` の下に直接記述します:

   ```json
   "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
   ```

3. **Package Manager 経由** —— `Add package from Git URL` を使用し、上記のリポジトリアドレスを入力します。

4. **手動配置** —— リポジトリ全体をプロジェクトの `Packages/` ディレクトリにコピーすると、Unity が自動的に認識します。

## 操作手順

1. **CoroutineComponent インスタンスを取得します。** このコンポーネントには `[DisallowMultipleComponent]` と `[GameFrameXAutoComponent(-6500)]` 属性が付いているため、通常は GameFrameX フレームワークによって `GameFrameworkEntry` がアタッチされた GameObject に自動登録されます。手動で行う方法は次のとおりです:

   ```csharp
   var coroutineComponent = gameObject.AddComponent<GameFrameX.Coroutine.Runtime.CoroutineComponent>();
   ```

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L21)

2. **コルーチンメソッドを記述します。** コルーチンのシグネチャは `IEnumerator` を返す必要があり、内部で `yield return` を使って進行を制御します:

   ```csharp
   IEnumerator HelloCoroutine()
   {
       Debug.Log("Hello");
       yield return null;            // 1 フレーム待機
       Debug.Log("Next frame");
   }
   ```

3. **コルーチンを起動します。** `StartCoroutine` を呼び出し、後で停止できるよう返されたイテレータインスタンスを保存します:

   ```csharp
   IEnumerator routine = HelloCoroutine();
   coroutineComponent.StartCoroutine(routine);
   ```

   注意:追跡ディクショナリへの書き込みを保証するため、`new` キーワードで基底クラスのメソッドを隠しているため、必ず `CoroutineComponent` 型の参照経由で `StartCoroutine` を呼び出してください。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

4. **単一のコルーチンを停止します(オプション)。** 起動時に保存した同じ `IEnumerator` インスタンスを渡します:

   ```csharp
   coroutineComponent.StopCoroutine(routine);
   ```

   このオーバーロードは最初にディクショナリ内を検索して対応する `UnityEngine.Coroutine` を見つけ、停止後にディクショナリから削除します。見つからない場合は `base.StopCoroutine(enumerator)` にフォールバックします。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

5. **すべてのコルーチンを停止します(オプション)。** シーン切り替えやロジックのリセット時に呼び出します:

   ```csharp
   coroutineComponent.StopAllCoroutines();
   ```

   実装は最初にディクショナリで追跡しているコルーチンを 1 つずつ停止してディクショナリをクリアし、その後 `base.StopAllCoroutines()` を呼び出して追跡されていないコルーチンの後始末を行います。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

6. **フレーム末尾コールバック(オプション)。** 現在のフレームのレンダリングがすべて完了した後に処理を行いたい場合(例:スクリーンショット、レポート送信)には、次のように使用します:

   ```csharp
   coroutineComponent.WaitForEndOfFrameFinish(() =>
   {
       Debug.Log("End of frame");
   });
   ```

   内部では再利用可能な `WaitForEndOfFrame` の使い捨てオブジェクトを再利用しており、呼び出しごとに GC アロケーションが発生しません。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

## よくあるバリエーション

- **`UnityEngine.Coroutine` オーバーロードで停止する**:Unity が返したコルーチンハンドルだけを保持している場合は、`StopCoroutine(UnityEngine.Coroutine coroutine)` オーバーロードを使用します。内部でディクショナリを逆順に走査して対応するイテレータを見つけてクリーンアップします。
- **`WaitForEndOfFrameFinish` のコールバック内で例外を投げないでください**:フレーム終了前に `StopCoroutine` でそのコルーチンが停止された場合、コールバックは実行されないため、防衛的に null チェックを行う必要はありません。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `StartCoroutine` 後、ディクショナリに見つからない | `MonoBehaviour.StartCoroutine` を呼び出しており、`CoroutineComponent.StartCoroutine` ではない | 必ず `CoroutineComponent` 型の参照経由で呼び出し、`new` で隠されたバージョンが使われるようにする |
| `StopCoroutine` が効かない | **再生成された** `IEnumerator`(例:`HelloCoroutine()` を再度呼び出したもの)を渡している | 起動時に保存した同じ `IEnumerator` インスタンスを再利用する。ディクショナリは参照等価性をキーとしているため |
| `StopAllCoroutines` 後にもコルーチンが動いている | 通常の `MonoBehaviour.StopAllCoroutines()` を呼び出している | `CoroutineComponent.StopAllCoroutines()` を呼び出し、追跡辞書も確実にクリアする |
| フレーム末尾コールバックがトリガされない | コールバックが実行される前に `StopCoroutine`/`StopAllCoroutines` が呼ばれた | コールバックで行うロジックを次のフレームに移すか、`yield return new WaitForEndOfFrame()` の完了を待ってから判定する |
