# エンティティのビジネスロジック(EntityLogic)を定義する方法

`EntityLogic` 基底クラスを継承してライフサイクルメソッドをオーバーライドすることで、Unity の `MonoBehaviour` を GameFrameX のエンティティ管理システムに組み込み、表示/非表示/更新/親子アタッチなどのコールバックを自動的に取得できます。

## 前提条件

- `com.gameframex.unity.entity` パッケージがインストール済みであること(『クイックスタート』を参照)。
- プレハブ(Prefab)に `Entity` コンポーネントが付いている必要があります。`EntityLogic` サブクラスのスクリプトは同じ GameObject にアタッチします。

## 操作手順

1. **スクリプトを作成して `EntityLogic` を継承する**。ファイル名はクラス名と一致させる必要があり、`Assets/Scripts/` 配下の任意の場所に配置します。

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
   }
   ```

   出典:[Runtime/Entity/EntityLogic.cs#L35-L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L35-L40)

2. **ライフサイクルメソッドをオーバーライドする**。`EntityLogic` は 7 つの `protected internal virtual` コールバックを提供しており、必要に応じてオーバーライドできます。基底クラスの動作を維持するため、`base` メソッドの呼び出しを忘れないでください。

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
       protected internal override void OnInit(object userData)
       {
           base.OnInit(userData);
           // コンポーネント参照などを初期化
       }

       protected internal override void OnShow(object userData)
       {
           base.OnShow(userData);
           // エンティティ表示時に呼び出される
       }

       protected internal override void OnHide(bool isShutdown, object userData)
       {
           base.OnHide(isShutdown, userData);
           // エンティティ非表示時に呼び出される
       }

       protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
       {
           base.OnUpdate(elapseSeconds, realElapseSeconds);
           // 毎フレームの更新ロジック
       }
   }
   ```

   出典:[Runtime/Entity/EntityLogic.cs#L110-L198](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L110-L198)

3. **スクリプトをプレハブにアタッチする**。Unity エディタでプレハブを開き、`PlayerEntity` コンポーネントを `Entity` コンポーネントと同じ GameObject にドラッグします(または任意の子オブジェクトにアタッチしても、`GetComponentInChildren` によって `Entity` から見つけることができます)。

4. **`EntityComponent` を通じてエンティティを表示する**。`EntityLogic` はエンティティの表示時にフレームワークによって自動的にインスタンス化されるため、ビジネス側は `ShowEntityAsync<T>` を呼び出すだけで済みます。

   ```csharp
   var entityComponent = GameEntry.GetComponent<EntityComponent>();

   IEntity entity = await entityComponent.ShowEntityAsync<PlayerEntity>(
       entityId: 1,
       entityAssetName: "Assets/Prefabs/Player.prefab",
       entityGroupName: "PlayerGroup"
   );
   ```

   出典:[README.zh-CN.md#L99-L145](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/README.zh-CN.md#L99-L145)

## オーバーライド可能なライフサイクルメソッド

| メソッド | 発生タイミング | 備考 |
|------|----------|------|
| `OnInit(object userData)` | エンティティの初回初期化時 | `Transform` のキャッシュ、元の `Layer` の保存、`Entity` 参照の取得 |
| `OnShow(object userData)` | エンティティが表示状態に入る時 | フレームワークが自動的に `Available` を `true` に設定し、`Visible = true` を設定します |
| `OnHide(bool isShutdown, object userData)` | エンティティが非表示にされる時 | `isShutdown=true` はマネージャーのシャットダウンによってトリガーされたことを示します。フレームワークは元の `Layer` を復元します |
| `OnUpdate(float, float)` | 表示状態の毎フレーム | パラメータは論理経過秒と実経過秒です |
| `OnRecycle()` | エンティティがオブジェクトプールに返却される時 | 外部リソース参照の解放に使用 |
| `OnAttached` / `OnAttachTo` | 子エンティティがこのエンティティにアタッチされる時 | デフォルトで `CachedTransform.SetParent(parentTransform)` が設定されます |
| `OnDetached` / `OnDetachFrom` | 子エンティティがデタッチされる時 | デフォルトで `Transform` を元の親ノードに戻します |
| `InternalSetVisible(bool)` | 可視性が変更される時 | デフォルトでは `gameObject.SetActive(visible)` を呼び出します。オーバーライドして切り替えロジックをカスタマイズできます |

出典:[Runtime/Entity/EntityLogic.cs#L110-L208](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L110-L208)

## よく使用するプロパティ

| プロパティ | 型 | 説明 |
|------|------|------|
| `Entity` | `Entity` | 関連付けられたエンティティコンポーネントの参照 |
| `Name` | `string` | `gameObject.name` の読み書き |
| `Available` | `bool` | エンティティが利用可能かどうか。`OnShow`/`OnHide` によって制御されます |
| `Visible` | `bool` | エンティティが可視かどうか。利用不可の状態で代入すると `Log.Warning("Entity '{0}' is not available.", Name)` が出力されます |
| `CachedTransform` | `Transform` | キャッシュされた `Transform`。初回の `OnInit` 時に代入されます |

## よくある間違い

- **`base` を呼び出していない**。基底クラスの `OnInit` は `Transform` をキャッシュして元の `Layer` を保存し、`OnShow` は `Available=true` を設定し、`OnHide` は `Layer` を復元します。`base` を省略すると、可視性・レイヤー・子ノードの状態に異常が発生します。
- **ライフサイクル外で `Available` にアクセスする**。エンティティが未表示の場合、`Available` は `false` であり、この状態で `Visible` に書き込むと基底クラスによってブロックされ、警告が出力されてロジックは実行されません。
- **`EntityLogic` サブクラスを直接 `new` する**。プレハブにアタッチされ、`EntityComponent` がオブジェクトプールを通じて作成する必要があります。手動で `new` すると、フレームワークのイベント配信とオブジェクトプールの回収が回避されてしまいます。

## 背景(任意)

`EntityLogic` は、`partial` な `EntityManager` を通じて、表示/非表示/回収時に対応する `protected internal` 仮想メソッドをトリガーします。これにより、ビジネスクラスはオブジェクトプール、リソースロード、レイヤー管理を意識する必要がありません。すべてのメソッドのアクセス修飾子は `protected internal` であり、同一アセンブリ内または `EntityManager` から明示的に呼び出された場合にのみトリガーされることを意味し、ビジネスコード内で手動で呼び出すべきではありません。
