# 通常のリソースの読み込みと解放方法(同期 / 非同期)

このドキュメントでは、`AssetComponent`(または下層の `AssetManager`)を使ってパスから通常のリソース(Prefab、Texture2D、TextAsset など)を読み込み、返された `AssetHandle` からオブジェクトを取得し、使用後に正しく解放することで、リソースがメモリに常駐することを回避する方法を説明します。

## 前提条件

- アセットパッケージの初期化が完了していること。パッケージの初期化は `InitPackageAsync` で行われ、定義は以下のとおりです:

```csharp
public Task<bool> InitPackageAsync(string packageName, string hostServerURL, string fallbackHostServerURL, bool isDefaultPackage = false)
```

> ソース: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L65-L98)

- パッケージ名が指定されていない場合、解放インターフェースはデフォルトパッケージ `DefaultPackageName` / `ConstDefaultPackageName` を使用します。
- シーンに `AssetComponent` がアタッチされていること(すべての読み込みインターフェースを内部の `_assetManager` に転送します)。

## 操作手順

### 1. 非同期読み込み(推奨)

リソースパスを渡し、`await` で `AssetHandle` を取得し、`AssetObject` を使ってオブジェクトを取り出します。非同期インターフェースには 4 つのオーバーロードがあります:

```csharp
public Task<AssetHandle> LoadAssetAsync(string path)
public Task<AssetHandle> LoadAssetAsync<T>(string path) where T : UnityEngine.Object
public Task<AssetHandle> LoadAssetAsync(string path, Type type)
public Task<AssetHandle> LoadAssetAsync(AssetInfo assetInfo)
```

> ソース: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L283-L399)

呼び出し例(ジェネリック版オーバーロードが最もよく使われ、リソースの型を直接制約できます):

```csharp
// Prefab を非同期で読み込み、インスタンス化する
var handle = await assetComponent.LoadAssetAsync<GameObject>("Assets/Res/Prefabs/Player.prefab");
var go = UnityEngine.Object.Instantiate((GameObject)handle.AssetObject);
```

> ソース: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L324-L327)

### 2. 同期読み込み

初期化フローや起動時の小さなリソースには同期インターフェースを使用できます。戻り値は `Task` ではなく、直接 `AssetHandle` です:

```csharp
public AssetHandle LoadAssetSync(string path)
public AssetHandle LoadAssetSync<T>(string path) where T : UnityEngine.Object
public AssetHandle LoadAssetSync(string path, Type type)
public AssetHandle LoadAssetSync(AssetInfo assetInfo)
```

> ソース: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L491-L547)

```csharp
var handle = assetComponent.LoadAssetSync<TextAsset>("Assets/Res/Config/level.txt");
var text = ((TextAsset)handle.AssetObject).text;
```

> ソース: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L544-L547)

### 3. 使用後の解放

解放には 3 つの粒度があり、手元にあるものに応じて選択します:

```csharp
// A. リソースパスのみ知っている場合(デフォルトパッケージ)
assetComponent.UnloadAsset("Assets/Res/Prefabs/Player.prefab");

// B. 複数パッケージのシナリオで、パッケージ名を指定
assetComponent.UnloadAsset("MyPackage", "Assets/Res/Prefabs/Player.prefab");

// C. ハンドルを保持している場合
assetComponent.UnloadAssetHandle(handle);
```

> ソース: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L766-L795)

パス指定でのアンロードは内部的に `TryUnloadUnusedAsset` を呼び出します。つまり「未参照のリソースのアンロードを試みる」ということです。参照されている場合は実際にはアンロードされません:

```csharp
public void UnloadAsset(string assetPath)
{
    GameFrameworkGuard.NotNull(assetPath, nameof(assetPath));
    var package = YooAssets.GetPackage(DefaultPackageName);
    package.TryUnloadUnusedAsset(assetPath);
}
```

> ソース: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L100-L124)

### 4. 一括回収(シーン切り替え時)

```csharp
// 現在未参照のリソースをアンロードする(デフォルトパッケージ、packageName に null を渡すとデフォルトパッケージを使用)
assetComponent.UnloadUnusedAssetsAsync();

// そのパッケージのすべてのリソースを強制的に回収する(使用中のオブジェクトがないことを確認する必要があります)
assetComponent.UnloadAllAssetsAsync("MyPackage");
```

> ソース: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L126-L163)

## 一般的なバリエーション

| ニーズ | 使用するインターフェース | 戻り値の型 |
|------|-----------|---------|
| リソースを 1 つだけ取得したい、非同期 | `LoadAssetAsync<T>(string path)` | `Task<AssetHandle>` |
| リソースを 1 つだけ取得したい、同期 | `LoadAssetSync<T>(string path)` | `AssetHandle` |
| 型を実行時にのみ決定できる | `LoadAssetAsync(string path, Type type)` / `LoadAssetSync(string path, Type type)` | `Task<AssetHandle>` / `AssetHandle` |
| 既に `AssetInfo` がある場合 | `LoadAssetAsync(AssetInfo)` / `LoadAssetSync(AssetInfo)` | `Task<AssetHandle>` / `AssetHandle` |
| リソースパッケージ内のすべてのオブジェクトを読み込む | `LoadAllAssetsAsync<T>(string path)` / `LoadAllAssetsSync<T>(string path)` | `Task<AllAssetsHandle>` / `AllAssetsHandle` |
| サブアセットオブジェクト(アトラス内の Sprite など)を読み込む | `LoadSubAssetsAsync(string path)` / `LoadSubAssetsSync(string path)` | `SubAssetsHandle` |
| 生のファイル(バイナリ/テキスト原文)を読み込む | `LoadRawFileAsync(string path)` / `LoadRawFileSync(string path)` | `Task<RawFileHandle>` / `RawFileHandle` |
| シーンを読み込む | `LoadSceneAsync(string path, LoadSceneMode sceneMode, bool activateOnLoad = true)` | `Task<SceneHandle>` |

> ソース: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L228-L290), [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L329-L413), [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L417-L489), [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L551-L584)

### 読み込み前にダウンロードが必要か判定する

リモートリソースがまだダウンロードされていない場合、直接読み込むとダウンロード待ちが発生して処理がブロックされます。先に確認できます:

```csharp
if (assetComponent.IsNeedDownload("Assets/Res/Prefabs/Boss.prefab"))
{
    // 先にダウンロード/更新フローを実行してから読み込む
}
```

### 特定型用の便利インターフェース

リポジトリでは、よく使われる Unity 型のために個別の分部クラスファイル(`AssetComponent.Prefab.cs`、`AssetComponent.Sprite.cs`、`AssetComponent.Texture2D.cs`、`AssetComponent.TextAsset.cs`、`AssetComponent.AudioClip.cs`、`AssetComponent.Material.cs`、`AssetComponent.Shader.cs` など)が分かれています。ハンドルではなく直接 strongly-typed なオブジェクトを取得したい場合は、これらのファイル内のインターフェースを優先的に確認してください。

## よくある間違い

| 間違った方法 | 結果 | 正しい方法 |
|---------|------|---------|
| `path` に `null` を渡す | 下層の `GameFrameworkGuard.NotNull(assetPath, nameof(assetPath))` で例外がスローされる | 呼び出し前にパスが空でないことを確認する |
| パッケージが初期化されていない状態で読み込み/解放を行う | `YooAssets.GetPackage(...)` でパッケージが取得できない | 先に `await InitPackageAsync(...)` の成功を待ってから読み込む |
| 複数パッケージのリソースを解放する際にパッケージ名を渡し忘れる | `DefaultPackageName` が使用され、対象のリソースが実際には解放されない | `UnloadAsset(packageName, assetPath)` のオーバーロードを使用する |
| `UnloadAsset` が必ず即座にメモリを解放すると期待する | 下層は `TryUnloadUnusedAsset` であり、参照されている場合は解放されない | 先にインスタンス化されたオブジェクトを破棄/参照を解除してから解放し、必要に応じて `UnloadUnusedAssetsAsync()` を呼び出す |
| メインスレッドのゲームで同期読み込みを多用する | フレーム落ちが発生する | 実行中はすべて `LoadAssetAsync` を使用し、同期は起動/初期化時のみ使用する |
| `handle` を直接リソースオブジェクトとして使用する | 型が一致しない | `handle.AssetObject` を使用して対象の型にキャストする |
| 使用中のパッケージに対して `UnloadAllAssetsAsync` を呼び出す | 参照中のオブジェクトが失われ、テクスチャが紫になる | シーン切り替え時など、未参照が確認できた場合のみ呼び出す |

## 背景(オプション)

非同期インターフェースは内部的に `TaskCompletionSource` を使用して YooAssets の `Completed` コールバックを `Task` にブリッジしているため、直接 `await` できます。これが、読み込みインターフェースがすべて裸のオブジェクトではなくハンドル(`AssetHandle` など)を返す理由でもあります。ハンドルは参照カウントを保持しており、解放はそれに依存します。
