# iOS 建置後 Info.plist 通路未寫入或被跳過

若匯出的 Xcode 專案之 `Info.plist` 內沒有 `channel` 金鑰，或執行階段 `BlankGetChannel.GetChannelName()` 持續回傳 `default`，常見原因如下：`PostProcessBuildHandler` 被排除於 `#if UNITY_IOS` 條件編譯之外、建置目標並非 `BuildTarget.iOS`，或是 plist 中已存在 `channel` 金鑰而處理常式依設計跳過。本文件將依症狀引導您找出原因並修正。

## 快速診斷

| 症狀（編輯器主控台 / 匯出的專案） | 原因 | 修正 |
|------|------|------|
| 完全沒有 `配置渠道成功` 或 `已有渠道` 日誌，且 plist 中沒有 `channel` 金鑰 | 編輯器目前的作用中平台不是 iOS，導致整個 `PostProcessBuildHandler` 被排除在 `#if UNITY_IOS` 之外而未參與編譯 | 切換至 iOS 平台後重新建置（參見步驟 1） |
| 日誌顯示 `已有渠道,跳过设置=>xxx` | `Info.plist` 中已存在 `channel` 金鑰（較早執行的其他 `PostProcessBuild` 回呼或範本已寫入），處理常式偵測到後便不覆寫 | 參見步驟 2 |
| 建置目標為 tvOS / visionOS | `OnPostProcessBuild` 中若 `target != BuildTarget.iOS` 會立即 `return`，因此會主動跳過 tvOS/visionOS 建置 | 參見步驟 3 |
| Editor 日誌中出現例外堆疊，但建置仍成功且 plist 未寫入 | `Run()` 中發生的例外僅以 `Debug.LogException(e)` 記錄，不會中斷建置 | 參見步驟 4 |
| `channel` 金鑰已寫入，但值恆為 `default` | 寫入的值為常數 `const string channelValue = "default";`，並非動態通路名稱 | 參見步驟 5 |

## 修正步驟

### 1. 確認編輯器建置目標是否為 iOS

整個處理常式檔案以 `#if UNITY_IOS` 包裹，並在回呼內部再次過濾目標平台：

```csharp
#if UNITY_IOS
        [PostProcessBuild(99)]
        public static void OnPostProcessBuild(BuildTarget target, string path)
        {
            if (target != BuildTarget.iOS)
            {
                return;
            }

            try
            {
                Run(path);
            }
            catch (Exception e)
            {
                Debug.LogException(e);
            }
        }
#endif
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L1-L29)

操作：請在 **File → Build Settings** 中將作用中平台切換為 iOS 後執行建置。切換後指令碼必須重新編譯，回呼才會被註冊並生效。

### 2. `channel` 金鑰已存在而被跳過

```csharp
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L36-L48)

此邏輯**僅在金鑰不存在時**才寫入，既有的值一律保留。處理方式有兩種：

1. 若既有的值不正確：請確認是否有其他 `PostProcessBuild` 回呼先行寫入了 `channel`。此回呼的順序為 `99`，順序值較小的回呼會先執行。請調整回呼順序，或刪除對方的寫入邏輯。
2. 若既有的值正確：無需處理。這是為了避免覆寫外部通路打包工具所寫入之值的刻意冪等（idempotent）行為。

### 3. tvOS / visionOS 建置被跳過

執行階段層支援 tvOS/visionOS（透過原生呼叫讀取 plist），但建置後處理僅處理 `BuildTarget.iOS`。若是 tvOS/visionOS：

- 請手動在匯出的 Xcode 專案之 `Info.plist` 中新增 `channel` 金鑰，或
- 在自家的建置指令碼中，對 `BuildTarget.tvOS` 等目標執行類似的 plist 寫入邏輯。

### 4. 建置時發生例外但 plist 未寫入

`OnPostProcessBuild` 會攔截所有例外並僅以 `Debug.LogException(e)` 輸出，因此建置不會失敗，plist 也不會寫入。`Run()` 內常見的觸發點：

- `File.ReadAllText(plistPath)` 擲回 `FileNotFoundException`：`path` 參數是建置輸出目錄，可能是 Xcode 專案未生成或路徑錯誤；
- `plist.ReadFromString` 擲回解析例外：plist 已被其他工具損壞。

操作：請在 Unity Console 中搜尋與 `PostProcessBuildHandler` 相關的堆疊，修正 `path` 所指的建置輸出目錄後重新建置。

### 5. 寫入的值固定為 `default`

```csharp
const string channelKey = "channel";
const string channelValue = "default";
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L33-L34)

寫入的值是編譯時期常數 `"default"`，並不會讀取目前通路。因此，此處理常式的角色是**後備（fallback）寫入**，用以確保 `Info.plist` 至少存在 `channel` 金鑰。實際的通路名稱應由自家的通路打包流程寫入或覆寫 `channel` 金鑰。若金鑰已存在，後備邏輯會主動讓位（參見步驟 2）。

## 驗證

請依下列順序確認修正是否已生效：

1. Unity 建置完成後，Console 會顯示 `配置渠道成功=>default`（或 `已有渠道,跳过设置=>xxx`）。
2. 開啟匯出的 Xcode 專案後，`Info.plist` 中會存在以下內容：

```xml
<key>channel</key>
<string>default</string>
```

此鍵值對格式即為執行階段原生介面所讀取的格式。詳見 [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26) 中的註解說明。

3. 請在實機上執行並呼叫 `BlankGetChannel.GetChannelName()` 來驗證回傳值。iOS 會透過 `DllImport("__Internal")` 呼叫原生的 `getChannelName`，並啟用快取：

```csharp
#elif UNITY_IOS || UNITY_TVOS || UNITY_VISIONOS
        channelName = getChannelName(channelKey);
#endif
        ChannelCache[channelKey] = channelName;
        return channelName;
```

Source: [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L136-L141)

請注意：`GetChannelName(string channelKey = "channel", string defaultValue = "default")` 的預設值同樣為 `"default"`，因此若讀取通路金鑰失敗，會直接回傳 `default`，外觀上與「plist 未寫入」的現象相同。請先依步驟 2 確認 plist 中的金鑰確實存在，再檢查執行階段的讀取。
