# 事件收不到或回呼未觸發

當 `EventComponent.Subscribe(DownloadXxxEventArgs.EventId, ...)` 訂閱後，下載開始、更新、成功、失敗四類回呼從未觸發，或僅觸發其中一部分時，請依本頁診斷表排查。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 四類事件全部未觸發 | 未將 `EventComponent` 注入到 `DownloadComponent`，或 `DownloadComponent` 未掛載 | 見下文「檢查 EventComponent 與 DownloadComponent」 |
| `EventId` 寫錯 / 使用了字串字面值 | 不同 `*EventArgs` 類別的 `EventId` 由 `typeof(...).FullName` 產生，拼字錯誤將無法匹配 | 見下文「使用 EventId 常數而非字串」 |
| 訂閱成功，但實際下載沒有發生 | `AddDownload` 傳入參數的 `downloadPath` / `downloadUri` 為空，或被 `Paused = true` 卡住 | 見下文「確認任務真正進入下載佇列」 |
| 只能收到 Start，收不到 Success / Failure | `DownloadAgentHelperCount` 設為 0，或 `m_CustomDownloadAgentHelper` 未指派 | 見下文「代理池未啟動」 |
| 收到 `OnDownloadSuccess` 後 `args.SerialId` 不匹配 | 在回呼中把所有下載任務當成同一個處理；或訂閱時尚未儲存 serialId | 見下文「按 SerialId 區分任務」 |
| 協程退出 / 場景切換後回呼遺失 | 訂閱綁定的物件被銷毀但未 `Unsubscribe`；或新場景重新 `Subscribe` 多次 | 見下文「訂閱生命週期管理」 |

## 修復步驟

### 檢查 EventComponent 與 DownloadComponent

事件鏈路依賴兩個元件同時存在。`DownloadComponent` 內部只持有一個 `EventComponent` 參考，啟動時注入，缺少則事件永遠不會派發。

```csharp
var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
var eventComponent = GameEntry.GetComponent<EventComponent>();
if (downloadComponent == null || eventComponent == null)
{
    Debug.LogError("請確認 DownloadComponent 與 EventComponent 都已掛載到 GameEntry");
}
```
[Runtime/Download/DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L62) 中 `DownloadComponent` 是 `[GameFrameXAutoComponent(-4000)]` 自動註冊元件；`EventComponent` 來自 `com.gameframex.unity.event` 相依套件（見 [package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json)）。

### 使用 EventId 常數而非字串

所有 `*EventArgs` 的 `EventId` 由 `typeof(...).FullName` 產生，直接使用靜態欄位最穩妥：

```csharp
eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComponent.Subscribe(DownloadStartEventArgs.EventId, OnDownloadStart);
eventComponent.Subscribe(DownloadUpdateEventArgs.EventId, OnDownloadUpdate);
```
四個事件參數類別原始碼：
- [DownloadSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadSuccessEventArgs.cs#L39-L42)
- [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L40-L42)

不要手寫 `"GameFrameX.Download.Runtime.DownloadSuccessEventArgs"` 之類的字串；命名空間或類別名稱一旦變更就會無法匹配。

### 確認任務真正進入下載佇列

`AddDownload` 回傳 `int serialId`，只有任務真正派發到代理才會觸發 Start，完成才會觸發 Success/Failure。先列印 serialId 並輪詢狀態以確認：

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);
Debug.Log($"serialId={serialId}");

TaskInfo info = downloadComponent.GetDownloadInfo(serialId);
Debug.Log($"status={info?.Status}, currentLength={info?.CurrentLength}");
```
如果 `info == null` 或 `Status` 一直是 `Waiting`，先檢查 `downloadComponent.Paused` 是否為 `true`。

### 代理池未啟動

代理數為 0、或者自訂 Helper 為空但 `m_DownloadAgentHelperTypeName` 指向一個不存在的型別，會導致任務堆積在等待佇列、永遠不會有回呼：

- 檢查 Inspector 上 `Download Agent Helper Count` ≥ 1（預設 3，見 [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60)）。
- 自訂 Helper 時，要嘛填寫 `m_CustomDownloadAgentHelper`，要嘛確保 `m_DownloadAgentHelperTypeName` 是有效的型別名稱；兩者不能同時為空。

### 按 SerialId 區分任務

回呼是全模組廣播的，不區分任務。一定要用 `args.SerialId` 與自己儲存的 serialId 對比：

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);

void OnDownloadSuccess(object sender, GameEventArgs e)
{
    var args = (DownloadSuccessEventArgs)e;
    if (args.SerialId == serialId)
    {
        // 是我這次發起的任務
    }
}
```
原始碼範例見 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/README.zh-CN.md#L113-L126)。

### 訂閱生命週期管理

`EventComponent.Subscribe` 註冊的是強式參考回呼，持有 `this`。訂閱物件銷毀後，事件佇列裡仍殘留懸空參考，新場景 `Subscribe` 多次還會重複觸發。建議：

1. 在 `OnDestroy` / `OnDisable` 中呼叫 `eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess)`。
2. 全域只訂閱一次，放到常駐管理器中，不要放在每次 `Start()` 都執行一次的腳本裡。

## 驗證

按上述步驟修完後，跑一次小檔案下載，在所有回呼中加入 `Debug.Log`：

```csharp
void OnDownloadStart(object sender, GameEventArgs e) =>
    Debug.Log($"Start serialId={(e as DownloadStartEventArgs).SerialId}");

void OnDownloadUpdate(object sender, GameEventArgs e) =>
    Debug.Log($"Update {((DownloadUpdateEventArgs)e).CurrentLength}");

void OnDownloadSuccess(object sender, GameEventArgs e) =>
    Debug.Log($"Success {(e as DownloadSuccessEventArgs).DownloadPath}");

void OnDownloadFailure(object sender, GameEventArgs e) =>
    Debug.LogError($"Failure {(e as DownloadFailureEventArgs).ErrorMessage}");
```

一般情況下，Start → 若干 Update → Success 四類事件都會依順序列印一次，Failure 只在出錯時列印。
