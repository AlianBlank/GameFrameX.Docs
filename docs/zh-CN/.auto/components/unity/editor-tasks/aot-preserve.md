# 使用 AOT 保留配置与校验

通过 Unity 菜单 `GameFrameX/HybridCLR Generate AOT Preserve` 一键生成 `link.xml`、引用汇总代码与按类型拆分的引用代码文件,并通过校验执行器在 CI 中确保生成文件始终与最新配置一致,避免 HybridCLR 热更新时缺失 AOT 元数据。

## 前置条件

- 项目已安装 HybridCLR(运行时依赖热更新 AOT 元数据)。
- 已为 `IAotPreserveSettingsProvider` 提供自定义实现,或在默认实现下放置好配置入口(默认实现位于 [IAotPreserveSettingsProvider.cs](/Editor/AotPreserve/IAotPreserveSettingsProvider.cs))。
- Unity 编辑器已打开工程,且对 `Assets/Generated/` 目录具备写入权限。

## 操作步骤

1. **触发生成**。在 Unity 编辑器顶部菜单中选择 `GameFrameX > HybridCLR Generate AOT Preserve`,会调用 `AotPreserveGenerator.GenerateAndWrite()`,并把日志输出到控制台。

   菜单入口实现见 [AotPreserveMenu.cs#L20-L25](/Editor/AotPreserve/AotPreserveMenu.cs#L20-L25):

   ```csharp
   [MenuItem(AotPreserveConstants.MenuPath)]
   public static void Generate()
   {
       AotPreserveGenerator.GenerateAndWrite();
       Debug.Log("Hotfix AOT preserve files generated under " + AotPreserveConstants.GeneratedDirectory);
   }
   ```

2. **查看生成路径**。生成根目录默认为 `Assets/Generated/AotPreserve`,核心产物路径由常量统一管理,见 [AotPreserveConstants.cs#L17-L65](/Editor/AotPreserve/AotPreserveConstants.cs#L17-L65):

   | 产物 | 路径常量 | 实际路径 |
   |------|----------|----------|
   | `link.xml`(托管代码 stripping 保留) | `LinkXmlPath` | `Assets/Generated/AotPreserve/link.xml` |
   | 引用汇总代码 | `ReferencesPath` | `Assets/Generated/AotPreserveReferences.cs` |
   | 按类型拆分引用文件名前缀 | `ReferenceTypeFilePrefix` | `AotPreserveReference_<TypeName>.cs` |
   | 生成代码所属 asmdef | `GeneratedAsmdefPath` | `Assets/Generated/AotPreserve.Generated.asmdef` |
   | 生成报告 Markdown | `ReportPath` | `Assets/Generated/AotPreserve/aot_preserve_report.md` |

3. **在 CI 中调用校验**。CI 或单元测试可直接调用 `AotPreserveValidationRunner.ValidateGeneratedFiles()`,当文件缺失或过期时会抛出 `InvalidOperationException`,异常消息聚合全部错误,见 [AotPreserveValidationRunner.cs#L20-L27](/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27):

   ```csharp
   public static void ValidateGeneratedFiles()
   {
       var errors = AotPreserveGenerator.ValidateGeneratedFiles();
       if (errors.Length > 0)
       {
           throw new InvalidOperationException(string.Join("\n", errors));
       }
   }
   ```

4. **错误处理**。生成过程出错时(例如配置无效、写入失败),`GenerateAndWrite()` 会抛出 `InvalidOperationException`,提示以 `"Hotfix AOT preserve generation failed:\n"` 开头并逐行列出错误,见 [AotPreserveGenerator.cs#L72-L78](/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L78);写入磁盘失败时还会抛出 `IOException` 或 `UnauthorizedAccessException`。

## 常见变体

- **程序化触发**:不需要菜单点击时,可在编辑器脚本里直接调用 `AotPreserveGenerator.GenerateAndWrite()`。
- **纯构建(不写盘)**:在自定义流水线里只想预览产物时,使用 `AotPreserveGenerator.Build()` 得到 `AotPreserveBuildResult`(含 `LinkXml`、`ReferencesCode`、`GeneratedAsmdef`、`Report`、`ReferenceFiles`、`Errors`),见 [AotPreserveGenerator.cs#L29-L61](/Editor/AotPreserve/AotPreserveGenerator.cs#L29-L61)。
- **自定义配置提供者**:实现 `IAotPreserveSettingsProvider` 并通过 `AotPreserveSettingsProviderResolver` 注入,可覆盖默认配置的来源。

## 常见错误

- **菜单点击后控制台报 `Hotfix AOT preserve generation failed: ...`**:说明 `Build()` 返回的 `AotPreserveBuildResult.Errors` 非空,通常是 `IAotPreserveSettingsProvider` 配置不合法或分析阶段失败;按异常消息逐条修复并重新生成。
- **CI 中校验抛 `InvalidOperationException` 且列出多条错误**:表示 `link.xml`、引用代码或 `asmdef` 与当前分析结果比对不一致;运行一次菜单生成即可刷新。
- **`UnauthorizedAccessException`**:检查 `Assets/Generated/AotPreserve/` 目录的写入权限,以及 `Assets/Generated/AotPreserve.Generated.asmdef` 是否被其他进程锁定。
- **生成文件缺失**:手动删除 `Assets/Generated/AotPreserve` 后未重新触发菜单——执行一次菜单生成即可重建整套产物。

## 背景(可选)

生成入口 `AotPreserveGenerator.GenerateAndWrite()` 会先调用 `AotPreserveAnalyzer.Analyze()` 汇总需要保留的类型,再分别产出 `link.xml`(用于托管 stripping 时的程序集级保留)、聚合与按类型拆分的引用代码(用于在运行时显式触发 AOT 元数据加载),以及一份 `aot_preserve_report.md` 报告用于审计;`ValidateGeneratedFiles()` 通过比对最新分析结果来检测文件是否过期。
