# 如何触发事件：Fire、FireNow 与无参数事件

在 GameFrameX.Event 中触发事件只需调用 `EventComponent` 上的 `Fire`（线程安全、下一帧主线程回调）、`FireNow`（立即同步分发）或 `Fire(sender, eventId)`（无需自定义事件参数的快捷方式）三者之一。本文给出三种用法的完整步骤、适用场景与常见坑。

## 前置条件

- 场景中已存在 GameFrameX 入口，`EventComponent` 随框架自动挂载（组件菜单为 `GameFrameX/Event`，见 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)）。
- 已经有人订阅了对应的事件 ID，否则触发后无人接收（可配合默认处理器兜底，见下文"常见变体"）。

## 操作步骤

1. 获取事件组件引用（挂在你的 MonoBehaviour 上或从框架入口获取）：

   ```csharp
   using GameFrameX.Event.Runtime;

   private EventComponent eventComponent;
   // 在 Awake/Start 中：
   // eventComponent = GameEntry.GetComponent<EventComponent>();
   ```

2. 准备事件参数类（继承 `GameEventArgs`，提供 `Create` 工厂与 `Clear`/回收约定）：

   ```csharp
   public class LevelUpEventArgs : GameEventArgs
   {
       public int Level { get; private set; }
       public static LevelUpEventArgs Create(int level) { /* ... */ }
   }
   ```

3. 延迟模式触发（默认推荐，线程安全）——事件在抛出后的下一帧于主线程回调：

   ```csharp
   eventComponent.Fire(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L124-L128)

   对应的组件 API 签名：

   ```csharp
   // 抛出事件，这个操作是线程安全的，即使不在主线程中抛出，
   // 也可保证在主线程中回调事件处理函数，但事件会在抛出后的下一帧分发。
   public void Fire(object sender, GameEventArgs e)
   {
       m_EventManager.Fire(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L150)

4. 立即模式触发（仅在主线程使用）——事件立刻同步分发，调用返回前处理器已执行完：

   ```csharp
   eventComponent.FireNow(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L130-L134)

   ```csharp
   // 抛出事件立即模式，这个操作不是线程安全的，事件会立刻分发。
   public void FireNow(object sender, GameEventArgs e)
   {
       m_EventManager.FireNow(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

5. 触发完成后可观察分发结果。三种方式对比：

   | API | 分发时机 | 线程安全 | 典型用途 |
   |-----|---------|---------|---------|
   | `Fire(object, GameEventArgs)` | 下一帧、主线程 | 是 | 默认选择；子线程/异步任务中抛事件 |
   | `FireNow(object, GameEventArgs)` | 立即、同步 | 否 | UI 点击等主线程即时响应、需要读到"事件已处理完"的后续状态 |
   | `Fire(object, string)` | 下一帧、主线程 | 是 | 无参数通知（内部用 `EmptyEventArgs` 包装） |

## 常见变体

**无参数事件（快捷方式）**：不想为一次性通知定义参数类时，直接传字符串 ID，组件内部会用 `EmptyEventArgs.Create(eventId)` 包装后再走 `Fire`，并先对 `eventId` 做非空校验：

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

```csharp
eventComponent.Fire(this, "level_up");
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L136-L140)

**子线程触发**：在线程池、Task 或网络回调中抛事件时必须用 `Fire`，它会保证回调发生在主线程（下一帧），因此回调里可以直接访问 Unity API。

**无人订阅时兜底**：触发一个没有订阅者的 ID 不会报错，但可设置默认处理器用于排查"事件发了没人接"：

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L142-L151)（API 位于 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L133-L140)）

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `Fire` 之后当帧读不到处理结果 | `Fire` 是延迟分发，下一帧才回调 | 当帧需要结果时改用 `FireNow` |
| 子线程里调用 `FireNow` 后回调行为异常 | `FireNow` 不是线程安全的 | 子线程一律用 `Fire` |
| 触发后处理器内拿到的数据不对/为空 | 参数对象被回收复用或未正确 `Create` | 每次触发都调用参数类的 `Create(...)`，不要缓存旧实例 |
| 事件发了没有任何反应 | 目标 ID 无人订阅 | 用 `eventComponent.Check(id, handler)` 或 `Count(id)` 排查，必要时设置默认处理器观察 |
| `Fire(sender, eventId)` 抛参数校验异常 | `eventId` 为 null 或空字符串 | 保证传入非空的字符串 ID（`GameFrameworkGuard.NotNullOrEmpty` 校验） |

## 验证

- 在处理器内打日志确认收到事件：`Debug.Log($"升级到 {args.Level} 级")`（示例见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L102-L106)）。
- 用统计属性交叉检查：`eventComponent.EventHandlerCount` / `eventComponent.EventCount` / `eventComponent.Count("level_up")`（见 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) 与 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L153-L159)）。

## 背景

`EventComponent` 只是薄封装，实际逻辑在 `IEventManager`（`EventManager`）里；`Fire` 借助事件池的队列在下一帧主线程统一分发，因此线程安全；`FireNow` 跳过队列直接同步调用处理器。关于事件订阅与取消订阅，见《如何订阅与取消订阅事件》。
