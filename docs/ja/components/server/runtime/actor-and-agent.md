# Actor / ComponentAgent を使用した並行タスクのスケジューリング

Actor は「プレイヤー/シーン/グローバル」などの業務エンティティをシングルスレッドで直列実行するスケジューリングユニットとしてラップします。ComponentAgent は Actor 上の再利用可能な業務コンポーネントであり、すべてのエンティティ間呼び出しは `ActorManager` を介して取得されるため、ロックを回避しデータの一貫性を保証します。このページでは、ComponentAgent を取得して呼び出し、並行タスクをスケジューリングする方法を説明します。

## 前提条件

- GameFrameX Actor フレームワークが統合されており、ランタイム環境で `ActorManager` にアクセスできること。
- `ComponentAgent<TComponent>` または `StateComponentAgent<TComponent, TState>` を継承したコンポーネント Agent がすでに存在すること。
- 業務エンティティが `ActorId`（`long` 型）を保持していること。`ActorId` を持たないグローバル Agent の呼び出しには `GetComponentAgent<T>()` を使用します。

## 操作手順

1. Actor にアクセスできる任意の場所から、`ActorManager` を介して対象コンポーネント Agent を取得します。

```csharp
// グローバル共有コンポーネント(ActorId 次元なし)
var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
await serverComp.RemoveOnlineRole(ActorId);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L46-L53)

2. 特定のプレイヤーのコンポーネントを操作する場合、プレイヤーの `ActorId` を第二引数として渡すと、フレームワークが対応する Actor の直列キューにルーティングします。

```csharp
var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
await attributeComponentAgent.InitializeDefaultsSilent();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L77-L78)

3. 同じ Actor 配下の複数の Agent を直列にスケジューリングする場合、業務順序に従って `await` で呼び出すだけで、フレームワークが同じ Actor 内の呼び出しを直列実行することを保証します。

```csharp
// すべて同一のプレイヤー ActorId に乗るので、順序通り直列実行される
var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
await mailAgent.SyncAsync();

var bagAgent = await ActorManager.GetComponentAgent<BagComponentAgent>(playerState.Id);
await bagAgent.SomeBusiness();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L91-L92)

4. Agent の作業が完了したら、Actor への参照を保持している箇所で自動回収を設定し、常駐を避けます。

```csharp
// ログアウト後に自動回収される
SetAutoRecycle(true);
QuartzTimer.Remove(ScheduleIdSet);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L50-L52)

## よくあるバリエーション

| シーン | 書き方 | 説明 |
|------|------|------|
| グローバルシングルトンコンポーネント | `await ActorManager.GetComponentAgent<T>()` | `ActorId` を渡さず、プロセスレベルの共有 Agent を取得 |
| プレイヤー固有コンポーネント | `await ActorManager.GetComponentAgent<T>(actorId)` | フレームワークが `actorId` で対応するプレイヤー Actor にルーティング |
| ルーム/シーンコンポーネント | `await ActorManager.GetComponentAgent<RoomComponentAgent>()` | 通常はグローバル Agent であり、内部でルームキーでインデックス化 |

## よくあるエラー

- `new T()` で直接 Agent を作成する：Agent は `ActorManager` によって作成・管理される必要があり、手動でインスタンス化すると直列キューと回収メカニズムを迂回します。
- `ActorId` を保持していない場所でプレイヤー固有 Agent を呼び出す：対応する Actor が見つからないためエラーがスローされます。グローバルコンポーネントには引数なしの `GetComponentAgent<T>()` を使用してください。
- プレイヤーのログアウト時に `SetAutoRecycle(true)` の呼び出しを忘れる：Agent が常駐し続け、キューとタイマーリソースを占有します（[PlayerComponentAgent.OnLogout](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L45-L53) を参照）。

## 背景（オプション）

Actor モデルは「同一プレイヤー/シーンへの並行アクセス」を直列メッセージキューに変換し、ComponentAgent は Actor にマウントされた業務ユニットです。`ActorManager` はコンポーネントのライフサイクルと Actor 間のルーティングを同時に担うため、ログインフローにおけるすべての初期化操作が単一の `await` チェーン内でロックなしに完了できます。
