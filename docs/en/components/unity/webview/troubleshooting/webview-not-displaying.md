# What to Do When the Web Page Does Not Display or the Display Area Is Offset

When no web page appears on screen after calling `WebViewComponent.Show(url)`, or the web page appears but the display area is offset or does not fill the screen, use the quick diagnosis table on this page to locate the cause and follow the corresponding fix steps. This component is a wrapper around [gree/unity-webview](https://github.com/gree/unity-webview) and only supports Android and iOS platforms; always rely on real devices/emulators when troubleshooting.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Running in Unity Editor or on PC platform, no web page appears after `Show()` | The underlying gree/unity-webview only provides native Android/iOS support; Editor/desktop platforms will not render a native WebView | Run and verify on a real Android/iOS device or emulator |
| Calling `Show()` throws `NullReferenceException`, and the log contains `Web View manager is invalid.` | The scene is missing the `WebViewComponent`, or the runtime implementation package is not installed, causing `GetModule&lt;IWebViewManager&gt;()` to return null | Add the `Game Framework/WebView` component to the scene and confirm the dependency is installed |
| The web page displays, but the area is offset, not full screen, or only occupies a corner of the screen | Only `Show(url)` was called, without calling `MakeFullScreen()` afterward to correct the display area | Call `MakeFullScreen()` after `Show(url)`, see Fix Step 3 |
| The web view control appears but the content is blank | The URL is inaccessible, certificate issues, or the page's own JS errors | Switch to a URL that is known to work (such as the framework documentation site) to rule out URL problems |
| The web page area is misaligned after device rotation | The underlying WebView does not recalculate the area after rotation, and the wrapper layer does not handle this automatically | Call `MakeFullScreen()` once more after rotating to trigger a re-fill of the screen |

## Fix Steps

### 1. Confirm You Are Running on a Supported Platform

This package's `Features` is explicitly labeled "Android and iOS platform support"; rendering is performed by the underlying native WebView. Calling `Show()` on Editor or Standalone platforms will not show any visible web page — this is not a malfunction.

Verification: build to a real Android/iOS device or emulator and call `Show(url)` again.

### 2. Confirm the WebViewComponent Exists in the Scene and the Manager Initialized Successfully

`WebViewComponent` is the framework component placed in the scene (menu path `Game Framework/WebView`). It obtains the manager module in `Awake()` and logs a fatal message when it cannot be retrieved:

```csharp
_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L32-L37)

If `_webViewManager` is null, the subsequent `Start()` will not execute `Initialize()`, and `Show()` will directly throw a `NullReferenceException` when forwarding internally:

```csharp
private void Start()
{
    if (_webViewManager == null)
    {
        return;
    }

    _webViewManager.Initialize();
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L40-L48)

Fix actions:

1. Add the `Game Framework/WebView` component to the startup scene (the component is marked with `[DisallowMultipleComponent]`; only one is needed per scene).
2. Confirm that the dependency package `com.gameframex.unity` (≥ 1.0.0) is installed via the `manifest.json` method.
3. After startup, check the log to confirm that `Web View manager is invalid.` no longer appears.

### 3. Call MakeFullScreen() After Showing to Correct the Display Area

The four APIs exposed by the wrapper layer are `Show(string url)`, `MakeFullScreen()`, `ExecuteJavaScript(string javaScript)`, and `Hide()`. When the area is offset or not full screen, add a `MakeFullScreen()` call after `Show`:

```csharp
using GameFrameX.WebView.Runtime;
using UnityEngine;

public class Example : MonoBehaviour
{
    void Start()
    {
        var webView = FindObjectOfType<WebViewComponent>();
        webView.Show("https://gameframex.doc.alianblank.com");
        webView.MakeFullScreen(); // Fill the screen, correcting the display area
    }
}
```

Sources: [README.md](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/README.md#L104-L116) · [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L55-L66)

Note: this wrapper does not expose positioning parameters such as margins or custom rectangles; for fine-grained control of the display area, you need to use the underlying [gree/unity-webview](https://github.com/gree/unity-webview) directly.

### 4. Rule Out URL and Page Issues When the Content Is Blank

First switch to a URL that is known to be accessible (for example, `https://gameframex.doc.alianblank.com`) to verify. To inject scripts into the page to assist with troubleshooting, you can use `ExecuteJavaScript`:

```csharp
webView.ExecuteJavaScript("console.log('probe from unity');");
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L72-L75)

## Verification

1. Build and run on an Android/iOS device.
2. Confirm the console has no `Web View manager is invalid.` log, and calling `Show(url)` does not throw a null reference.
3. The web page appears on the device screen and loads the target site's content.
4. After calling `MakeFullScreen()`, the web page fills the entire screen with no residual offset on any edge; rotate the screen and call `MakeFullScreen()` once more to confirm the area realigns.
5. Calling `Hide()` hides it normally, and calling `Show(url)` again brings it back normally.

## Background

`WebViewComponent` is a thin wrapper over GameFrameworkComponent: it obtains the manager via `GameFrameworkEntry.GetModule&lt;IWebViewManager&gt;()` in `Awake()` and calls its `Initialize()` in `Start()`; `Show/MakeFullScreen/ExecuteJavaScript/Hide` each forward to `IWebViewManager` in a single line. `BaseWebViewManager` is merely an abstract base class that defines this set of interfaces as abstract methods; the actual native rendering is done by gree/unity-webview in platform-specific subclasses — this is also the root cause of why no web page is visible on Editor/desktop platforms and why this package does not provide fine-grained area control.

- For the abstract interfaces, see [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs) and [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs)
