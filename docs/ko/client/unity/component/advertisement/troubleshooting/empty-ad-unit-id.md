# 광고 슬롯 ID가 비어 있을 때怎么办

`BaseAdvertisementManager.Initialize`이 빈 문자열이나 `null`의 광고 슬롯 ID를 받으면, 광고 SDK가 요청을 거부하고 실패 콜백을 반환합니다. 이 페이지는 "광고 슬롯 ID가 비어 있음"의 원인을 빠르게 파악하고 재생을 복구하는 데 도움을 줍니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Inspector의 "Android/IOS/WebGL 광고 슬롯 ID" 필드가 비어 있음 | `AdvertisementComponent`의 해당 플랫폼 `m_adUnitId*` 직렬화 필드가 작성되지 않음 | Inspector에서 해당 플랫폼의 광고 슬롯 ID를 작성 |
| 실행 시 `ArgumentNullException: config` 오류 발생 | `Initialize(AdvertisementConfig)` 호출 시 `null`을 전달함 | Inspector 또는 코드를 통해 올바르게 채워진 `AdvertisementConfig` 인스턴스를 전달 |
| 기존 인터페이스 `Initialize(string, bool)`이 `null`/빈 문자열을 받음 | `adUnitId` 매개변수가 할당되지 않아 `string.Empty` 경로로 직접 호출됨 | 호출 전에 `adUnitId`에 광고 플랫폼 백엔드에서 생성된 실제 ID를 할당 |
| 멀티 플랫폼 중 하나만 작성되어 다른 플랫폼에서 광고를 가져오지 못함 | 대상 플랫폼 분기의 `m_adUnitId*`가 비어 있음 | 빌드 플랫폼을 전환할 때 모든 플랫폼의 광고 슬롯 ID를 동기화하여 확인 및 보완 |

광고 슬롯 ID는 광고 플랫폼 백엔드에서 생성됩니다. 컴포넌트는 필드만 보유하며 기본 예제 값을 제공하지 않습니다.

## 수정 단계

### 1. Inspector에서 광고 슬롯 ID 작성

`AdvertisementComponent`가 부착된 게임 오브젝트에서 게시 플랫폼에 따라 해당 필드를 작성하세요. 게시하지 않는 플랫폼은 비워 둘 수 있지만 대상 플랫폼에 영향을 주어서는 안 됩니다.

- Android 광고 슬롯 ID
- IOS 광고 슬롯 ID
- WebGL 광고 슬롯 ID
- WebGL WeChat 광고 슬롯 ID
- WebGL Douyin 광고 슬롯 ID
- WebGL Kuaishou 광고 슬롯 ID

Source: [AdvertisementComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L26-L56)

### 2. 코드를 통해 올바른 초기화 진입점 호출

`Initialize(AdvertisementConfig config)` 오버로드를 우선적으로 사용하세요. 구버전 `Initialize(string adUnitId, bool debug)`는 `[Obsolete]`로 표시되어 있습니다. 전달된 `config`가 `null`이면 즉시 `ArgumentNullException(nameof(config))`가 발생합니다.

```csharp
var config = ScriptableObject.CreateInstance<YourAdvertisementConfig>();
config.adUnitId = "your_real_ad_unit_id";
config.isDebug = false;
GameFrameX.Advertisement.Runtime.BaseAdvertisementManager.Initialize(config);
```

Source: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L112-L134)

### 3. null 값이 내부 `string.Empty` 폴백을 트리거하지 않도록 방지

구현에서는 `null`이거나 `DefaultAdvertisementConfig` 타입이 아닌 설정을 모두 빈 문자열로 폴백합니다. SDK가 빈 ID를 받으면 반드시 실패하므로, `Initialize`에 전달하기 전에 설정 객체의 `adUnitId`가 반드시 할당되어 있어야 합니다.

```csharp
// BaseAdvertisementManager.Initialize(AdvertisementConfig) 내부
var defaultConfig = config as DefaultAdvertisementConfig;
Initialize(defaultConfig != null ? defaultConfig.adUnitId : string.Empty, config.isDebug);
```

Source: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L127-L128)

## 검증

1. 다시 패키징하여 대상 플랫폼에서 실행하고, 로그에 "ad unit id is empty" 또는 "invalid ad unit id" 류의 오류가 더 이상 나타나지 않는지 확인합니다.
2. 광고 플랫폼의 테스트 모드(컴포넌트의 `테스트 모드 여부` 필드)에서 테스트 광고를 가져올 수 있다면 ID가 적용된 것입니다.
3. 다른 게시 플랫폼으로 전환할 때 먼저 해당 플랫폼 분기의 `m_adUnitId*` 필드가 비어 있지 않은지 확인한 후 광고 요청을 트리거합니다.
