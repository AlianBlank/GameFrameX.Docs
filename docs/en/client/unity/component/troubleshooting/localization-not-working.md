# What to Do When Localized Text Doesn't Take Effect

When you call `GameApp.Localization.GetString(key)` or look up multilingual text via FairyGUI/UI components but still get the old language string, the Key itself, or an empty value, it means the localization data was not populated according to the current `GameApp.Localization.Language`. This page provides common causes, corresponding diagnostic methods, and fix steps.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Calling `GetString(key)` returns the Key string itself | The `Key` field in the config table is empty or not generated | Check whether the `key` column in `local_tblocalization.json` is filled in, and regenerate the config code |
| Text doesn't change after switching `Language` | `TranslateText()` was not called, or was called in the wrong order | In the startup flow, first call `Config.GetConfig<TbLocalization>()`, then call `TranslateText()` |
| `SerializationException` thrown during `AddRawString` | The config table JSON doesn't match the generated `Localization` fields | Re-export `local_tblocalization.json` with LuBan, and confirm all 15 language fields are present |
| Some languages (e.g., Thai, Indonesian) are always empty | That language branch is not handled in the `switch`, or the field is empty in the table | Fill in the corresponding language column in `local_tblocalization.json`, or add a branch in the `Localization.cs` generator |
| All localized strings are in English after running | `DefaultLanguage == English` and `Language` is not in a switch branch | Confirm that `GameApp.Localization.Language` hits one of the branches above, or extend the fallback logic of the default branch |

## Fix Steps

### 1. Confirm that the startup flow calls `TranslateText`

`TranslateText()` is responsible for writing the multilingual fields from the `TbLocalization` table into the underlying dictionary according to the current language; skipping it means you won't get any values.

```csharp
// 1. Remove the source data
GameApp.Localization.RemoveAllRawStrings();
// 2. Load data from the config table
var tbLocalization = GameApp.Config.GetConfig<TbLocalization>();
// 3. Populate the data
tbLocalization.ForEach(localization =>
{
    if (localization.Key.IsNullOrWhiteSpace())
    {
        return;
    }
    // ... switch GameApp.Localization.Language ...
    GameApp.Localization.AddRawString(localization.Key, value);
});
```

Source: [HotfixLauncher.cs#L66-L164](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L66-L164)

Note: Rows with a blank Key will simply `return` and won't be written into the dictionary. Go back to the config table and fill in the Key.

### 2. Verify that the current language is covered in a switch branch

The generated `Localization` entity has 15 language fields in total, and the launcher matches them one by one according to the `LocalizationCode` enum. Unmatched languages fall into `default` and will only get English when `DefaultLanguage == English`; otherwise they remain `string.Empty`.

```csharp
case LocalizationCode.ChineseSimplified:
    value = localization.ChineseSimplified;
    break;
case LocalizationCode.English:
    value = localization.English;
    break;
// ... ChineseTraditionalTW / HK / French / German / Italian / Japanese /
//     Korean / Portuguese* / Spanish* / Thai / Vietnamese / Russian / Indonesian
default:
{
    if (GameApp.Localization.DefaultLanguage == LocalizationCode.English)
    {
        value = localization.English;
    }
}
    break;
```

Source: [HotfixLauncher.cs#L82-L161](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L82-L161)

If your target language is not among the branches above (e.g., you added Arabic), you need to:

1. Add the corresponding column in the LuBan table `local_tblocalization.json`.
2. Regenerate `Localization.cs` so the new field is included in the constructor and JSON parsing.
3. Append a `case` to the switch in `HotfixLauncher.TranslateText` to map the field to `value`.

### 3. Check that the config table and generated code are in sync

The generated `Localization` constructor performs a string-type validation on every field; a missing field will cause deserialization to throw `SerializationException`, making the entire table fail to load.

```csharp
public Localization(JSONNode _buf)
{
    { if(!_buf["key"].IsString) { throw new SerializationException(); }  Key = _buf["key"]; }
    { if(!_buf["ChineseSimplified"].IsString) { throw new SerializationException(); }  ChineseSimplified = _buf["ChineseSimplified"]; }
    { if(!_buf["English"].IsString) { throw new SerializationException(); }  English = _buf["English"]; }
    // ... The remaining 12 languages are validated in the same way
}
```

Source: [Localization.cs#L38-L59](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Local/Localization.cs#L38-L59)

Fix: Open `local_tblocalization.json` in the LuBan editor, confirm that the 15 language field names (ChineseSimplified, ChineseTraditional, English, Japanese, Korean, Thai, Indonesian, French, German, Russian, Italian, PortuguesePortugal, Spanish, Vietnamese) as well as the `key` column all exist and are strings, then regenerate the code.

### 4. Force-refresh the UI after switching languages

Simply changing `GameApp.Localization.Language` will not re-read the configuration; you need to run `TranslateText()` again to overwrite the old values in the dictionary. A common approach is to call this method in the language-switch event, then broadcast `OnLanguageChanged` to the UI layer.

## Verification

Confirm the issue is resolved in the following order:

1. Run the game and confirm in the console that `tbLocalization` has more than 0 rows and that no `SerializationException` occurs.
2. Temporarily call `GameApp.Localization.GetString("some Key from your config table")` in a script and use a breakpoint to confirm it returns the string for the current `Language` rather than the Key itself.
3. Open a text node that uses a Key via the FairyGUI/UGUI localization component, and check the displayed value at runtime.
4. Switch `GameApp.Localization.Language = LocalizationCode.English` (or another language), call `TranslateText()` again, and confirm once more that the UI text updates with the switch.

## Common Mistakes

- Editing `local_tblocalization.json` directly but forgetting to click LuBan's "Generate Code", causing the field names in the runtime code to mismatch and deserialization to fail silently.
- `TranslateText()` is written to be called in `Awake`, but `GameApp.Config` hasn't finished initializing at that point, causing `GetConfig<TbLocalization>()` to return null.
- Keys in the table use Chinese characters or strings containing spaces; while legal, callers can easily mistype the Key. It is recommended to consistently use English letters, numbers, and underscores.
- Relying on the English fallback in the `default` branch while `DefaultLanguage` is not `English`, which will leave some languages displayed as empty strings.
