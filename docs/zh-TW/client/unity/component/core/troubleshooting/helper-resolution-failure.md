# Helper 類型找不到或建立失敗怎麼辦

當程式碼裡呼叫 `Helper.Create` 拿到 `null`、或反射載入時報 `cannot find Helper type` / `missing type` 時,通常意味著對應 Helper 類別在建置時被裁剪,或命名空間/組件引用沒配齊。本頁提供按症狀定位與修復的方法。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `Helper.Create<XXHelper>()` 拋 `GameFrameworkException: ...` | 該 Helper 的 `Create` 工廠未註冊或工廠未找到建構函式 | 用反射檢查該類別是否有無參建構函式,見 [修復 1](#修復-1-找不到無參建構函式) |
| iOS/Android IL2CPP 建置後某些 API 報 `MissingMethodException` 或 `TypeLoadException` | 程式碼裁剪(Code Stripping)把 Helper 類型剔除了 | 在場景裡掛 `GameFrameXCroppingHelper` 或用 `link.xml` 保留,見 [修復 2](#修復-2-建置後被裁剪) |
| `typeof(GameFrameX.Runtime.DoTweenHelper)` 編譯報錯 | 沒有安裝對應插件,巨集未啟用 | 啟用巨集或移除引用,見 [修復 3](#修復-3-選用模組的輔助類別) |
| 編輯器擴充找不到 `HotFixAssemblyDefinitionHelper` 等類型 | 命名空間錯誤或 Editor 組件未編譯 | 檢查 `Editor/` 目錄和 asmdef,見 [修復 4](#修復-4-editor-輔助類別) |
| 自訂 Helper 子類別拋 `not registered` | 未呼叫 `Helper.Create` 或 `Register` | 按框架約定的工廠模式註冊,見 [修復 5](#修復-5-自訂-helper) |

## 修復 1:找不到無參建構函式

`Helper` 類別的所有具體實作(例如 `DefaultLogHelper`、`DefaultCompressionHelper`、`DefaultTextHelper`、`DefaultVersionHelper`)都要求提供**無參建構函式**,因為 `Helper.Create<T>()` 走的是反射 `Activator.CreateInstance`。

1. 檢查你的 Helper 子類別:

```csharp
// 錯誤範例 — Helper.Create<MyHelper>() 會失敗
public class MyHelper : ILogHelper
{
    public MyHelper(string name) { /* ... */ }
}

// 正確範例
public class MyHelper : ILogHelper
{
    public MyHelper() { }
    // ...
}
```

2. 在 Unity Console 中確認拋出的例外原文是否為 `GameFrameworkException`,例外內通常包含類型全名。

3. 修復後重新觸發 `Helper.Create<MyHelper>()` 呼叫驗證。

原始碼中具體 Helper 類型清單見 [GameFrameXCroppingHelper.cs#L21-L60](Runtime/GameFrameXCroppingHelper.cs#L21-L60)。

## 修復 2:建置後被裁剪

`Runtime/GameFrameXCroppingHelper.cs` 的存在就是為了防止 IL2CPP/AOT 建置時把框架內部類型剪掉,所有引用都透過 `typeof()` 表達。執行時(非編輯器)必須保證這個腳本在場景裡被實例化:

1. 在首個啟動場景裡,新建一個空 `GameObject`,掛上 `GameFrameXCroppingHelper` 元件,設為 `DontDestroyOnLoad`。

```csharp
// 啟動腳本中
var go = new GameObject("GameFrameXCroppingHelper");
go.AddComponent<GameFrameXCroppingHelper>();
DontDestroyOnLoad(go);
```

2. 如果使用 HybridCLR / ILRuntime 等熱更方案,需要把這些類型加入主包 AOT 組件的 `link.xml`:

```xml
<linker>
  <assembly fullname="GameFrameX.Runtime" preserve="all"/>
</linker>
```

3. 在 Build Settings 裡確認該腳本不會在 Stripping 時被剔除(可暫時關閉 Managed Stripping 驗證)。

來源參考: [GameFrameXCroppingHelper.cs#L1-L12](Runtime/GameFrameXCroppingHelper.cs#L1-L12)。

## 修復 3:選用模組的輔助類別

`DoTweenHelper` 被 `#if ENABLE_GAME_FRAME_X_DO_TWEEN` 包裹([GameFrameXCroppingHelper.cs#L9-L11](Runtime/GameFrameXCroppingHelper.cs#L9-L11))。如果你沒引入 DOTween 插件卻啟用了該巨集,或者反過來:

| 情況 | 處理 |
|------|------|
| 沒用 DOTween 卻啟用了 `ENABLE_GAME_FRAME_X_DO_TWEEN` | 關閉巨集,或刪除對 `DoTweenHelper` 的引用 |
| 用了 DOTween 但沒啟用巨集 | 在 `Project Settings → Player → Scripting Define Symbols` 新增 `ENABLE_GAME_FRAME_X_DO_TWEEN` |
| 用其他選用插件(如 YooAsset、HybridCLR) | 查閱對應插件文件,在巨集未啟用時不要 `typeof()` 這些 Helper |

## 修復 4:Editor 輔助類別

倉庫裡 `Editor/` 目錄下有一批 `*Helper.cs`(如 `BuildHotfixHelper.cs`、`BuildPostProcessHelper.cs`、`MiniGameDefineSymbolHelper.*.cs`),它們只在 Editor 組件可用:

1. 確認腳本在 `Editor/` 資料夾下,或對應的 `.asmdef` 標記了 `includePlatforms: ["Editor"]`。
2. **不要**在執行時代碼裡 `using` 或 `typeof()` 這些類型——發布包找不到就會報錯。
3. 如果你新增了一個平台的小遊戲(`InternationalMiniGames` / `DomesticMiniGames` / `GamePlatforms`),需要新增或補全對應平台的 `MiniGameDefineSymbolHelper.<Platform>.cs`。

來源參考: [Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs](Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs)、[Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs](Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs)。

## 修復 5:自訂 Helper

框架裡的 `Helper` 是一個靜態門面類別([Runtime/Helper/Helper.cs#L44](Runtime/Helper/Helper.cs#L44)),`Helper.Create<T>()` 會按約定查找 `T.Create()` 或同名工廠方法。如果你的自訂 Helper 找不到:

1. 確認實作了約定的工廠方法:

```csharp
public class MyJsonHelper : IJsonHelper
{
    public static IJsonHelper Create()
    {
        return new MyJsonHelper();
    }

    private MyJsonHelper() { } // 私有建構,只能透過 Create 拿到實例
}
```

2. 在 `GameEntry` 啟動後,把回傳的實例註冊到框架:

```csharp
Utility.Json.IJsonHelper json = MyJsonHelper.Create();
GameEntry.RegisterHelper(json);
```

3. 編輯器下加中斷點,在 `Helper.Create<T>` 裡確認是否走到了你自訂的分支。

## 驗證

完成以上修復後,按以下步驟確認問題已解決:

1. **編輯器**:進入 Play 模式,所有 `Helper.Create` 呼叫應不再拋例外。
2. **IL2CPP 真機**:打包 Player,在目標裝置上啟動,Console 不再出現 `MissingMethodException` / `TypeLoadException`。
3. **反射掃描**:用反射列出 `GameFrameX.Runtime` 組件中的所有 `*Helper` 類型,確認數量與 [GameFrameXCroppingHelper.cs#L21-L165](Runtime/GameFrameXCroppingHelper.cs#L21-L165) 清單一致。
4. **裁剪報告**:開啟 IL2CPP 的 `Strip Engine Code` 輸出,在 `Library/Il2cppBuildCache` 中確認目標類型不在裁剪清單。
