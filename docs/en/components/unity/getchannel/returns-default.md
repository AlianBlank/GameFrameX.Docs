# What to Do When Getting the Channel Always Returns default

When `BlankGetChannel.GetChannelName()` cannot read the channel configuration on the target platform, it returns the default value `"default"` of the `defaultValue` parameter. This symptom almost always stems from one of the following: the `channel` key is missing from the current platform's configuration source, the key name does not match, or the result of the first read has been cached statically. The API signature is as follows:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L97-L98)

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Returns `default` on Editor / PC / WebGL / consoles | `Assets/Resources/application_config.txt` does not exist, or has no `channel=` line | Create `application_config.txt` under `Assets/Resources/` and write `channel=xxx` |
| Created/modified `application_config.txt` but it still returns `default` | The static cache `ChannelCache` has already cached `default` and will not re-read within this session | Exit Play mode to trigger a Domain Reload, or restart Unity before testing again |
| Android device returns `default` | `<meta-data android:name="channel" .../>` is not written inside the main launcher Activity, or the key name is not `channel` | Move the `meta-data` inside the main launcher `<activity>` tag in AndroidManifest.xml |
| iOS device returns `default` | The post-build processing script automatically wrote `"default"` when the `channel` key was missing in Info.plist | Write the `channel` key in advance before the build / in a higher-priority post-process step |
| Returns `unknown` instead of `default` on iOS | The key is missing in Info.plist; the iOS native implementation returns `"unknown"` | Add the `channel` key to Info.plist |
| Getting custom keys such as `sub_channel` returns `default` | The passed-in `channelKey` does not match the key name in the configuration file | Verify the key name and write the configuration with the correct key |

## Fix Steps

### 1. Editor / PC / WebGL: Check application_config.txt

These platforms read via `Resources.Load<TextAsset>("application_config")`; the file must be located at `Assets/Resources/application_config.txt`, with one `key=value` per line:

```text
channel=editor_cn_test
sub_channel=test
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L106-L121)

Note the parsing rules (from source code `L110-L119`):

- Lines are split on `\n` / `\r` / `\r\n`; empty lines are ignored;
- Each line is split on `=` and **must produce more than 1 segment**; lines like `channel` (no `=`) are discarded entirely;
- Whitespace around the key and value is trimmed with `Trim()`, so writing `channel = abc` still reads `abc`.

### 2. Rule Out Static Cache Interference

The result is written into the static dictionary `ChannelCache`; the second call within the same session goes directly to the cache. Pay special attention: when `textAsset == null` (the file does not exist), `default` is written into the cache, and even if the file is added afterwards, it will not be re-read:

```csharp
if (ChannelCache.TryGetValue(channelKey, out var value))
{
    return value;
}
// ...
var textAsset = Resources.Load<TextAsset>("application_config");
if (textAsset != null)
{
    // Parse and populate ChannelCache
}
else
{
    ChannelCache[channelKey] = defaultValue;  // Cache default when the file is not found
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L100-L125)

Before verifying in the Editor whether the configuration takes effect, exit Play mode first (to trigger a Domain Reload) or restart Unity, then enter Play to test. The same applies on Android / iOS: after modifying the manifest or plist, you need to rebuild; it will not refresh automatically within the process.

### 3. Android: Put meta-data Inside the Main Launcher Activity

Android reads via a JNI call to the static method `GetChannel` of `com.alianhome.getchannel.MainActivity`, and the key name defaults to `channel`:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

Add the following inside the **main launcher Activity tag** in `AndroidManifest.xml` (not under `<application>`):

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

Checkpoints:

- The key name must be `android:name="channel"`, matching the `channelKey` passed in on the C# side; to read other keys, pass `GetChannelName("your_key_name")` when calling.
- The custom manifest approach (custom `Assets/Plugins/Android/AndroidManifest.xml`) must match the template Unity is currently using; confirm that it is still inside the main Activity after being packed into the APK.

### 4. iOS / tvOS / visionOS: Check Info.plist

On the iOS side, the native `getChannelName` is called via `DllImport("__Internal")` to read the `channel` key from Info.plist:

```csharp
[DllImport("__Internal")]
private static extern string getChannelName(string channelKey);
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L47-L48)

The native implementation returns `"unknown"` when the key is not found (rather than `default` on the C# side):

```objc
NSString * channel_value =  [dict objectForKey:channel_name_String];
if (channel_value != nil) {
    return StringToCharArray(channel_value);
}
channel_value = @"unknown";
return StringToCharArray(channel_value);
```

Source: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

The `channel` key in the package is written automatically by the `PostProcessBuild(99)` post-build processing. It writes **only when the key does not exist**, and the written value is fixed as `"default"`. Therefore, iOS builds produced directly with this package's default pipeline will get `default` — this is by design:

```csharp
const string channelKey = "channel";
const string channelValue = "default";

string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

To get the real channel, do one of the following:

1. Write a `PostProcessBuild` handler whose `callbackOrder` is less than `99` to write the real channel into Info.plist first; this package then detects the key already exists and skips it (log output `已有渠道,跳过设置=>`, i.e. "channel already exists, setting skipped");
2. Or modify Info.plist directly on the build output and re-sign.

In Info.plist, the value should be of the String type:

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)

## Verification

1. After completing the configuration as described above, restart the application (or restart Unity and enter Play);
2. Call it and print the result early at startup (before any channel read):

```csharp
string channel = BlankGetChannel.GetChannelName();
Debug.Log("channel = " + channel);
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

3. On Android, view the output with `adb logcat | grep channel`; on iOS, check the Xcode console; if the iOS post-build processing takes effect during packaging, the build log will contain `配置渠道成功=>` ("channel configured successfully") or `已有渠道,跳过设置=>` ("channel already exists, setting skipped");
4. If the output is the value you wrote in the configuration, the fix is complete; if it is still `default`, go back to the "Quick Diagnosis" table and re-check the configuration source and cache item by item for each platform.
