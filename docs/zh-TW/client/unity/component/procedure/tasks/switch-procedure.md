# 如何在流程之間切換

流程切換是透過 `IProcedureManager.StartProcedure` 完成的。在遊戲中的任何地方(流程類別內、外部系統、UI 按鈕回呼),只要擁有 `ProcedureComponent.Procedure`,就可以呼叫它。本頁提供從取得管理器到完成切換的最小可執行步驟。

## 前置條件

- 已建立多個繼承自 `ProcedureBase` 的流程類別(例如 `ProcedureLogin`、`ProcedureMain`)。
- `ProcedureComponent` 已掛載到場景中,並且已在 Inspector 的 `Available Procedure Type Names` 中填入流程型別名稱。
- 已瞭解整體架構,請參閱「總覽」。

## 步驟

### 1. 取得流程管理器

透過 `ProcedureComponent` 的 `Procedure` 屬性取得 `IProcedureManager`:

```csharp
using GameFrameX.Procedure.Runtime;
using UnityEngine;

ProcedureComponent procedureComponent = GameFrameX.Runtime.GameFrameworkEntry.GetComponent<ProcedureComponent>();
IProcedureManager procedureManager = procedureComponent.Procedure;
```

來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L70-L74)

### 2. 在目前流程的 `OnUpdate` 中發起切換

最常見的切換方式:在流程輪詢期間偵測到條件成立時呼叫 `StartProcedure`。管理器會觸發目前流程的 `OnLeave` 以及目標流程的 `OnEnter`。

```csharp
using GameFrameX.Procedure.Runtime;

public class ProcedureLogin : ProcedureBase
{
    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);

        if (登入完成的條件滿足)
        {
            procedureOwner.Owner.StartProcedure<ProcedureMain>();
        }
    }
}
```

`IProcedureManager.StartProcedure` 的兩個多載定義可見於 [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L64-L73)。其底層會叫用狀態機的狀態轉移。

### 3. 在外部程式碼中切換

切換不一定需要發生在流程內部。遊戲中任何持有 `IProcedureManager` 參考的地方都可以呼叫:

```csharp
using GameFrameX.Procedure.Runtime;

procedureManager.StartProcedure(typeof(ProcedureMain));
// 或泛型版本
procedureManager.StartProcedure<ProcedureMain>();
```

泛型版本的來源簽章:

```csharp
public interface IProcedureManager
{
    void StartProcedure<T>() where T : ProcedureBase;
    void StartProcedure(Type procedureType);
}
```

來源:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L60-L73)

### 4. 驗證切換是否成功

切換後,讀取 `CurrentProcedure` 與 `CurrentProcedureTime`,確認新流程已生效且計時器已重設為 0。單元測試中的做法可作為參考:

```csharp
m_ProcedureManager.Initialize(m_FsmManager, new ProcedurePreload(), new ProcedureMain());
m_ProcedureManager.StartProcedure<ProcedurePreload>();

Assert.IsNotNull(m_ProcedureManager.CurrentProcedure);
Assert.IsInstanceOf<ProcedurePreload>(m_ProcedureManager.CurrentProcedure);
Assert.AreEqual(0f, m_ProcedureManager.CurrentProcedureTime);
```

來源:[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L153-L173)

## 常見變化

### 僅查詢,不切換

在切換之前,可以使用 `HasProcedure` 確認目標已註冊,避免在狀態機內部拋出例外:

```csharp
if (procedureManager.HasProcedure<ProcedureMain>())
{
    procedureManager.StartProcedure<ProcedureMain>();
}
```

來源:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L78-L89)

### 不切換,僅取得已註冊的實例

有時你只想讀取目前的流程實例進行條件檢查,而不進行切換:

```csharp
ProcedureBase main = procedureManager.GetProcedure<ProcedureMain>();
```

來源:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L94-L105)

## 常見錯誤

- **過早呼叫**:在流程管理器 `Initialize` 之前呼叫任何方法都會拋出例外。單元測試 `CurrentProcedure_BeforeInitialize_Throws` 與 `HasProcedure_BeforeInitialize_Throws` 驗證了這一點,請參閱 [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L96-L128)。請確保在 `StartProcedure` 之前已完成 `Initialize`。
- **目標流程未註冊**:`StartProcedure` 要求流程已透過 `Initialize(..., params ProcedureBase[] procedures)` 或 `ReinitializeProcedures` 註冊。可以事先使用 `HasProcedure<T>()` 進行檢查。
- **在 `OnEnter` / `OnInit` 內切換**:在狀態機初始化階段呼叫 `StartProcedure` 可能與其自身生命週期衝突。建議將其放在 `OnUpdate` 中,或使用外部驅動。

## 背景說明(選讀)

`ProcedureComponent` 持有 `m_ProcedureManager`。啟動時,它會根據 Inspector 中設定的 `m_AvailableProcedureTypeNames` 以反射方式建立流程實例,並依序呼叫 `StartProcedure`。之後,`m_EntranceProcedure` 會成為初始流程。切換期間,底層狀態機會執行 `OnLeave`/`OnEnter` 轉移。當 `m_UseStartupRunner = true` 時,元件本身不再呼叫 `Initialize`,而是改由 `ApplicationStartupEntry` + `StartupRunner.Run` 接管,以避免重複 `Initialize`。
