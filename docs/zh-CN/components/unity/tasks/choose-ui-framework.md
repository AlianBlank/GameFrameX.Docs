# 如何在 FairyGUI 与 UGUI 之间选择与切换

GameFrameX 通过两个独立的 UI 适配包同时支持 FairyGUI 和 UGUI,业务代码只需在生成阶段选择适配层,运行时通过脚本宏(`ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI`)隔离产物即可在同一项目中并存或切换。

## 前置条件

工程已通过 Unity Package Manager 引入下列包(见 [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L36-L38)):

| 包名 | 版本 | 作用 |
|------|------|------|
| `com.gameframex.unity.ui` | 2.11.0 | UI 基础框架(打开/关闭/事件) |
| `com.gameframex.unity.ui.fairygui` | 3.4.2 | FairyGUI 适配层 |
| `com.gameframex.unity.ui.ugui` | 2.6.0 | UGUI 适配层 |
| `com.gameframex.unity.fairygui.unity` | 5.3.4 | FairyGUI 编辑器运行时 |
| `com.unity.ugui` | 1.0.0 | Unity 内置 UGUI |

> FairyGUI 依赖包 `FairyGUI` 由 `com.gameframex.unity.fairygui.unity` 提供,无需额外单独安装。

## 选择建议

| 场景 | 推荐方案 | 原因 |
|------|----------|------|
| 美术已用 FairyGUI 编辑器产出大量 `.fui` 资源 | FairyGUI | 直接复用现有包,字段类型为 `GComponent` / `GTextField` 等 |
| 团队熟悉 Unity 原生工作流,使用 Prefab + Canvas | UGUI | 字段类型为 `UnityEngine.UI.Text` / `InputField`,符合 Unity 直觉 |
| 需要两套界面并存(例如主界面用 UGUI、活动弹窗用 FairyGUI) | 同时启用 | 通过不同目录下的生成代码隔离即可 |
| 从零起步、希望最快上手 | UGUI | 不依赖 FairyGUI 编辑器,直接拖 Prefab |

## 操作步骤:在编译产物中选择方案

1. 在 `Project Settings` → `Player` → `Scripting Define Symbols` 中加入(或移除)对应宏:

   ```
   ENABLE_UI_FAIRYGUI   // 启用 FairyGUI 适配
   ENABLE_UI_UGUI       // 启用 UGUI 适配
   ```

2. FairyGUI 生成代码示例 —— 类继承 `FUI`,通过 `UIPackage.CreateObject` 创建:

   ```csharp
   // 来源:Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs
   #if ENABLE_UI_FAIRYGUI
   public sealed partial class UIAnnouncement : FUI
   {
       public const string UIPackageName = "UILogin";
       public const string UIResName     = "UIAnnouncement";
       public const string URL           = "ui://f011l0h9aneks9g";

       public GComponent self { get; private set; }
       public GTextField  m_TextTitle { get; private set; }
   }
   #endif
   ```

   Source: [UIAnnouncement.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs#L3-L29)

3. UGUI 生成代码示例 —— 类继承 `UGUI`,通过 `[SerializeField] [UGUIElementProperty]` 暴露节点:

   ```csharp
   // 来源:Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs
   #if ENABLE_UI_UGUI
   [OptionUIConfig(null, "Assets/Bundles/UI/UILogin")]
   public sealed partial class UILogin : UGUI
   {
       [SerializeField] [UGUIElementProperty("UserName")]
       private UnityEngine.UI.InputField UserName;
       public UnityEngine.UI.InputField m_UserName => UserName;
   }
   #endif
   ```

   Source: [UILogin.UI.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs#L3-L46)

4. 运行 UI Launcher 时,框架会根据当前激活的宏自动找到对应的生成类(`FUI` 或 `UGUI`)并打开面板。无需在业务层硬编码。

## 常见变体

- **两套 UI 并存**:同时定义两个宏,FairyGUI 产物放在 `Assets/Hotfix/UI/FairyGUI/`,UGUI 产物放在 `Assets/Hotfix/UI/UGUI/`,框架按类名匹配。
- **运行时动态切换**:不推荐在同一构建包内通过宏切换。若需 A/B 测试,改为出两个构建,各自只启用一个宏。
- **只留一套**:删除另一套目录下的生成代码 + 移除对应宏即可。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 打开 UI 时报 `TypeInitializationException`,类未找到 | 未在 `Scripting Define Symbols` 加入对应宏,生成代码被 `#if` 整段剔除 | 加入 `ENABLE_UI_FAIRYGUI` 或 `ENABLE_UI_UGUI` |
| FairyGUI 包加载失败,资源显示粉色 | 未安装 `com.gameframex.unity.fairygui.unity` 或 FairyGUI 编辑器未导出 | 重新导入包并确认 `.fui` 包地址 `ui://...` 与 `UIPackageName` 一致 |
| UGUI 节点全部为 `null` | Prefab 路径与 `[OptionUIConfig]` 中 `Assets/Bundles/UI/...` 不匹配 | 重新生成 UI 代码,或在 `OptionUIConfig` 中修正路径 |

## 验证

1. 编译工程,Console 不应出现 `TypeLoadException` / `MissingMethodException`。
2. 启动后打开任意一个示例面板(如 `UILogin`),能看到对应方案下的控件。
3. 切换宏后再次编译,确认面板类型从 `FUI` 子类变为 `UGUI` 子类(或反之)。

## 背景(可选)

两个适配包提供相同语义的 `Open` / `Close` / `Show` 流程,差别只在节点绑定方式:FairyGUI 通过 `GObject` 反射包内组件,UGUI 通过 `UGUIElementProperty` 特性反射 Prefab 上的 `GameObject`。业务代码只面向基类 `FUI` / `UGUI` 编程,不直接依赖字段类型。
