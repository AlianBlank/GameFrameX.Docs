# How to Configure a Scoped Registry and Import Components On Demand

By declaring the `GameFrameX` scoped registry in `Packages/manifest.json`, you can have the Unity Package Manager resolve all packages starting with `com.gameframex`, and then pick which components to import based on your project's needs.

## Prerequisites

- Unity 2019.4 or higher (with built-in Package Manager support for scoped registries).
- A `Packages/manifest.json` file exists in the project root directory (automatically generated by Unity when creating a project).

## Steps

1. Open `Packages/manifest.json` in the project root directory, and add the GameFrameX registry to the `"scopedRegistries"` array at the end of the file (if the array already exists, simply append a new entry):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L72)

2. In the `"dependencies"` section of the same file, first add the core runtime package `com.gameframex.unity` (all other components depend on it):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

3. Add dependencies for other components as needed, such as asset management, UI, networking, procedure management, etc. A complete example of the `dependencies` section is shown below (excerpted from this repository's `Packages/manifest.json`):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0",
    "com.gameframex.unity.asset": "3.1.0",
    "com.gameframex.unity.config": "1.2.0",
    "com.gameframex.unity.coroutine": "1.1.0",
    "com.gameframex.unity.entity": "2.4.5",
    "com.gameframex.unity.entry": "1.3.0",
    "com.gameframex.unity.event": "1.3.0",
    "com.gameframex.unity.fsm": "1.2.0",
    "com.gameframex.unity.network": "2.6.10",
    "com.gameframex.unity.procedure": "1.4.0",
    "com.gameframex.unity.sound": "1.3.0",
    "com.gameframex.unity.ui": "2.11.0",
    "com.gameframex.unity.ui.fairygui": "3.4.2"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

4. After saving the file, return to the Unity editor. The Package Manager will automatically fetch the newly added registry and dependencies; once the list has finished refreshing, you will see all available packages under the `GameFrameX - Scoped Registry` category on the left side.

5. Use the [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) page or the [GameFrameX UPM Registry](https://gameframex.upm.alianblank.uk) as the authoritative source for version numbers; simply replace placeholder versions such as `"1.11.0"` or `"2.0.0"` with the actual target version.

## Common Variations

- **Adding via the Unity editor**: On the `Edit ▸ Project Settings ▸ Package Manager ▸ Scoped Registries` page, click `+` and fill in `Name=GameFrameX`, `URL=https://gameframex.upm.alianblank.uk`, `Scopes=com.gameframex`. After saving, the result is identical to editing `manifest.json` directly.
- **Using multiple registries simultaneously**: `scopedRegistries` is an array, so you can list multiple objects side by side. This repository declares both GameFrameX and `package.openupm.com` (for the `io.sentry` scope) at the same time:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    },
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["io.sentry"]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L80)

- **Installing third-party components directly via Git URL**: For packages not published to UPM (such as HybridCLR), you can fill in the Git address directly in `dependencies`, bypassing the scoped registry:

```json
{
  "dependencies": {
    "com.code-philosophy.hybridclr": "https://gitee.com/focus-creative-games/hybridclr_unity.git"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L3-L3)

- **Importing only the minimal set**: Simply remove the dependencies you don't need. GameFrameX components are split in a modular fashion with no mandatory coupling; keeping only `com.gameframex.unity` and `com.gameframex.unity.entry` still works and starts up normally.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Package Manager reports `Unable to find package com.gameframex.unity` | `scopedRegistries` is not declared, or `scopes` was written as `com.gameframex.unity` | Add `scopes: ["com.gameframex"]` to `scopedRegistries` |
| Package downloads but the `assembly definition` cannot find the namespace | Only `com.gameframex.unity` was imported without `com.gameframex.unity.entry`, or a submodule is missing | Add the missing `com.gameframex.unity.*` dependencies and confirm that `com.gameframex.unity.entry` is included |
| Editor keeps getting stuck at "Resolving packages" | Multiple registries have overlapping `scopes`, triggering duplicate resolution | Make sure each scoped registry's `scopes` do not overlap, e.g., GameFrameX uses `com.gameframex`, OpenUPM uses `io.sentry` |
| `dll` missing after upgrading to a new version | `dependencies` is still pinned to an old version, and the new version restructured the package layout | Review the migration notes on [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases), then update all version numbers together |

## Background (Optional)

Scoped registry is an official Unity Package Manager mechanism introduced in 2019.3: it connects private/public npm-style UPM registries to your project via URL + namespace scopes (`scopes`), without affecting official packages or existing dependencies. This repository hosts all `com.gameframex.*` packages on a self-hosted UPM registry at `https://gameframex.upm.alianblank.uk`, so as long as the scope matches, the Package Manager can resolve the corresponding tarball by version.
