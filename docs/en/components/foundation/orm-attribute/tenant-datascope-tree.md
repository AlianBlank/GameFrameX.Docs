# How to Declare Tenant/Data Scope/Tree Entities

By declaring the metadata for "tenant isolation, row-level data scope, and tree structure" on entity classes via three dedicated attributes `[TenantTable]`, `[DataScope]`, and `[TreeEntity]`, the ORM layer can automatically recognize and enable the corresponding capabilities, without hand-writing filter conditions in every repository.

## Prerequisites

- The `GameFrameX.Foundation.Orm.Attribute` namespace has been referenced.
- Entity fields use public properties (attributes read property names), and field names must match the attribute parameters.

## Steps

### 1. Declare a Tenant-Isolated Table

Add `[TenantTable]` to the class. The entity must include a `TenantId` field; the ORM will automatically inject filtering and assignment based on the current tenant context.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder
{
    public long Id { get; set; }
    public long TenantId { get; set; }   // Tenant identifier
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L83-L94)

### 2. Declare Row-Level Data Scope

Add `[DataScope("AnchorField")]` to the class, and set `DefaultScope` and `DepartmentField` as needed. The constructor parameter `scopeField` is required; a nullable value will throw `ArgumentNullException`.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[DataScope("CreatedUserId", DefaultScope = DataScope.Self)]
public class GameOrder
{
    public long Id { get; set; }
    public long CreatedUserId { get; set; }  // Data scope anchor
    public string OrderNo { get; set; }
}

[DataScope("CreatedUserId",
    DefaultScope = DataScope.Department,
    DepartmentField = "CreatedDeptId")]
public class GamePlayer
{
    public long Id { get; set; }
    public long CreatedUserId { get; set; }
    public long CreatedDeptId { get; set; }
}
```

The `DataScope` enum supports: `All`, `Department`, `DepartmentAndChild`, `Self`, `Custom`. Source: [DataScopeAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L111-L114) and the enum definition [DataScopeAttribute.cs#L123-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L123-L164)

### 3. Declare a Tree-Structured Entity

Add `[TreeEntity("ParentId")]` to a self-referencing tree entity, and use optional properties to describe the materialized path, level, sort order, and child collection.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TreeEntity(
    ParentIdField = "ParentId",
    PathField = "Path",
    LevelField = "Level",
    SortField = "Sort",
    ChildrenField = "Children")]
public class SysDept
{
    public long Id { get; set; }
    public long? ParentId { get; set; }   // Parent node
    public string Path { get; set; }      // Materialized path, e.g. "1.5.12"
    public int Level { get; set; }        // Level (root is 1)
    public int Sort { get; set; }         // Sort order among siblings
    public string Name { get; set; }
    public List<SysDept> Children { get; set; }
}
```

The constructor parameter `parentIdField` is required; passing `null` throws `ArgumentNullException`. Source: [TreeEntityAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TreeEntityAttribute.cs#L124-L127)

## Common Variants

- **Stacking the three attributes**: The same entity can carry multiple attributes at once, e.g., tenant business table + data scope + department tree structure, controlling isolation, permissions, and tree queries respectively.
- **Marking only the subtree field**: When you only need lazy loading of the child collection, setting `ChildrenField` alone is sufficient; the remaining `PathField`/`LevelField`/`SortField` can be `null`.
- **Department and subordinate departments**: Use `DepartmentField` together with `DefaultScope = DataScope.DepartmentAndChild`, which is suitable for data viewing in multi-level organizations.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `[DataScope]` or `[TreeEntity]` throws `ArgumentNullException` | A `null` string was passed to the constructor parameter | Ensure the parameter passed is not `null`, e.g., `[DataScope("CreatedUserId")]` |
| Data scope filtering not taking effect | Anchor field name does not match the entity property name | Ensure `ScopeField` strictly matches the property name (case-sensitive) |
| Tree query returns the entire table | `ParentIdField` not set or `[TreeEntity]` missing | Declare explicitly with `[TreeEntity("ParentId")]` |
| `[TenantTable]` misused on a system-level table | A tenant table was written as a globally shared table | Use `[TenantTable]` for tenant isolation; for globally shared tables, see the system table attribute (out of scope for this document) |

## Background

`[TenantTable]` marks that "each row belongs to a tenant"; queries/inserts automatically include tenant conditions. `[DataScope]` layers "role-visible scope" on top of the tenant basis. `[TreeEntity]` describes the parent-child structure within the entity, facilitating recursion and materialized path retrieval. The three are orthogonal and can be used individually or in combination according to business needs.
