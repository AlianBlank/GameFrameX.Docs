# 5분 안에 첫 번째 설정표 로드하기

이 페이지를 따라 하면 5분 안에 GameFrameX Config 설정표 패키지를 설치하고, Unity에서 `ConfigComponent`를 통해 첫 번째 설정표를 로드하여 읽을 수 있습니다.

## 사전 조건

- Unity 2019.4 이상
- 프로젝트에 `com.gameframex.unity` (GameFrameX 코어 프레임워크)가 이미 도입되어 있어야 합니다
- 의존성: `com.gameframex.unity.asset`, `com.gameframex.unity.event`
- `GameFrameworkEntry`를 마운트할 씬 오브젝트 (GameFrameX 진입 컴포넌트)

## 작업 단계

### 1. 설정표 패키지 설치

Unity 프로젝트 루트 디렉토리의 `Packages/manifest.json`을 편집하여 GameFrameX scoped registry를 추가하고, `dependencies`에 설정표 패키지를 선언합니다 (권장 방식, 이후 업데이트 버전을 해석할 수 있음):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.config": "1.1.5"
  }
}
```

Source: [README.zh-CN.md](/src/README.zh-CN.md#L36-L51)

네트워크가 scoped registry에 접근할 수 없는 경우, Git URL을 사용하여 직접 설치할 수 있습니다. `dependencies`에 다음을 추가하세요:

```json
{
  "com.gameframex.unity.config": "https://github.com/gameframex/com.gameframex.unity.config.git"
```

Source: [README.zh-CN.md](/src/README.zh-CN.md#L56-L61)

설치가 완료되면 Unity가 패키지 목록을 새로 고치므로, Package Manager에서 `com.gameframex.unity.config`를 확인할 수 있습니다.

### 2. 씬에 진입 컴포넌트와 설정 컴포넌트 마운트하기

씬에 `GameFrameworkEntry`가 존재하는지 확인하세요 (또는 `com.gameframex.unity.entry`를 통해 시작). `ConfigComponent`는 특성을 통해 프레임워크에 자동 등록되므로 수동으로 추가할 필요가 없습니다:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Config")]
[GameFrameXAutoComponent(-5000)]
public sealed class ConfigComponent : GameFrameworkComponent
```

Source: [ConfigComponent.cs](/src/Runtime/Config/ConfigComponent.cs#L46-L49)

GameFrameX가 시작되면 `Awake()`가 자동으로 내부 `IConfigManager`를 생성하므로 직접 new할 필요가 없습니다.

### 3. GameEntry를 통해 ConfigComponent를 가져와 설정 로드하기

`GameEntry.GetComponent<ConfigComponent>()`를 사용하여 전역 컴포넌트를 가져오고, `LoadConfig`를 호출하여 첫 번째 표를 로드합니다:

```csharp
// 표준 방식: GameEntry를 통해 (com.gameframex.unity.entry에 의존하지 않음)
var configComponent = GameEntry.GetComponent<ConfigComponent>();
configComponent.LoadConfig("ConfigPath");
```

Source: [README.zh-CN.md](/src/README.zh-CN.md#L66-L70)

> 팁: `ConfigPath`는 설정표 리소스의 로드 키이며, 프로젝트의 리소스 관리 규약에 따라 결정됩니다. 구체적인 경로는 프로젝트实际情况에 따라 교체해 주세요.

### 4. 설정표 구현 및 읽기

설정 데이터 타입은 `IDataTable` 인터페이스를 구현해야 하며, 프레임워크는 타입 이름을 키로 사용하여 관리합니다. 그런 다음 `GetConfig<T>`를 사용하여 읽습니다:

```csharp
public class MyConfigTable : IDataTable
{
    // 필드 및 읽기 로직
}

[Preserve]
public T GetConfig<T>() where T : IDataTable
{
    var configName = GetTypeName<T>();
    var config = m_ConfigManager.GetConfig(configName);
    if (config != null)
    {
        return (T)config;
    }
    return default;
}
```

Source: [ConfigComponent.cs](/src/Runtime/Config/ConfigComponent.cs#L117-L128)

읽기 예시:

```csharp
var table = configComponent.GetConfig<MyConfigTable>();
if (table != null)
{
    // table의 데이터 사용
}
```

### 5. 성공 / 실패 콜백 등록 (선택 사항)

프레임워크 이벤트를 통해 로드 결과를 구독합니다:

| 이벤트 | 용도 |
|------|------|
| `LoadConfigSuccessEventArgs` | 설정 로드 성공 시 트리거됨 |
| `LoadConfigFailureEventArgs` | 설정 로드 실패 시 트리거됨 |
| `LoadConfigUpdateEventArgs` | 설정 핫 업데이트 시 트리거됨 |

구독 방식은 GameFrameX의 `GameEntry.GetComponent<EventComponent>()` 표준 패턴을 따릅니다.

## 일반적인 변형

- **타입 키를 통한 로드**: `HasConfig<T>()` / `RemoveConfig<T>()`를 사용하여 존재 여부를 판단하고 제거합니다. 키는 `typeof(T).Name`입니다:

```csharp
[Preserve]
public bool HasConfig<T>() where T : IDataTable
{
    var configName = GetTypeName<T>();
    return m_ConfigManager.HasConfig(configName);
}
```

Source: [ConfigComponent.cs](/src/Runtime/Config/ConfigComponent.cs#L138-L143)

- **런타임 동적 설정 추가**: `Add(configName, dataTable)`를 호출하여 이미 구성된 `IDataTable`을 관리자에 등록합니다:

```csharp
configComponent.Add("MyConfig", myDataTableInstance);
```

Source: [ConfigComponent.cs](/src/Runtime/Config/ConfigComponent.cs#L181-L185)

- **모든 설정 비우기**: `RemoveAllConfigs()`는 타입 매핑과 모든 표 항목을 동시에 비웁니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Log.Fatal("Config manager is invalid.")` | `Awake()`에서 `GameFrameworkEntry.GetModule<IConfigManager>()`를 통해 관리자를 가져올 수 없음 | `com.gameframex.unity`가 설치되어 있는지 확인하고, `ConfigComponent`가 프레임워크에서 정상적으로 초기화되었는지 확인 |
| `GetConfig<T>()`가 `default`를 반환 | 표가 아직 로드되지 않았거나 이름이 일치하지 않음 | `LoadConfig`에 올바른 리소스 키가 전달되었는지 확인; 데이터 타입이 `IDataTable`을 구현하는지 확인 |
| 편집기에서 `GameFrameX/Config` 메뉴를 찾을 수 없음 | 패키지가 올바르게 가져오기되지 않음 | Unity를 재시작하거나 Package Manager에서 `com.gameframex.unity.config`를 다시 해석 |

## 배경 (선택 사항)

`ConfigComponent`는 `[GameFrameXAutoComponent(-5000)]`을 통해 GameFrameX 시작 시 자동으로 등록되며, 우선순위가 낮아 다른 리소스/이벤트 컴포넌트가 먼저 준비될 수 있도록 합니다. 내부적으로 타입 매핑을 `ConcurrentDictionary<Type, string>`에 캐시하며, 키는 `typeof(T).Name`으로 매번 리플렉션으로 이름을 가져오는 것을 방지합니다. 모든 표 항목은 `IConfigManager`에 의해 통합 관리되며 멀티스레드 안전합니다.
