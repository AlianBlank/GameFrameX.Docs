# Plugin Introduction

GameFrameX Procedure workflow management component is one of the core modules of the Unity game framework, specifically used for managing game workflow states. This component is implemented based on Finite State Machine (FSM), providing a complete game workflow lifecycle management solution.

## Overview

The Procedure workflow management component is mainly used for organizing and controlling the overall workflow logic of the game. In game development, typical game workflows include: startup workflow (Loading), main menu workflow (Menu), game workflow (Game), pause workflow (Pause), and settlement workflow (Settlement). This component helps developers modularize these complex workflow logics, making game state transitions clearer, more controllable, and easier to maintain.

The core design concept of this component is to treat each game workflow as a state in the finite state machine, managed through a unified interface. This design pattern not only simplifies the workflow switching logic but also provides developers with rich hook methods, allowing them to insert custom logic at various lifecycle stages of the workflow.

As a core submodule of the GameFrameX framework, the Procedure component depends on FSMComponent (Finite State Machine component) to implement the underlying state management functionality. Developers can create custom procedures by inheriting the `ProcedureBase` class and register them with the workflow manager.

## Architecture Design

This component adopts a layered architecture design, from top to bottom: Unity Component Layer, Procedure Management Layer, Finite State Machine Layer. This layered design ensures clear responsibilities and low coupling between layers, facilitating expansion and maintenance.

### Core Component Description

**ProcedureComponent** is the entry point of the entire workflow system. It is a Unity Component mounted on a GameObject in the scene. This component is responsible for initializing all available workflows when the game starts and automatically switching to the entrance workflow. Through the Inspector panel, developers can configure the available workflow type names array and the entrance workflow type name.

**IProcedureManager** defines the standard interface for the workflow manager, containing core operations such as getting the current workflow, initializing the workflow manager, starting workflows, checking workflow existence, and getting workflows. All workflow management-related functionality is provided externally through this interface.

**ProcedureManager** is the concrete implementation class of the IProcedureManager interface. Internally, it uses a finite state machine to manage all workflow states. Developers usually do not need to operate this class directly but use it indirectly through ProcedureComponent or the IProcedureManager interface.

**ProcedureBase** is the base class for all custom procedures. It inherits from FsmState<IProcedureManager>. Developers need to create subclasses inheriting from ProcedureBase to implement specific workflow logic. The base class provides lifecycle hook methods such as OnInit, OnEnter, OnUpdate, OnFixedUpdate, OnLeave, and OnDestroy.

### Working Principle

When the game starts, ProcedureComponent obtains the IProcedureManager module instance in the Awake method. Then in the Start method, it iterates through all configured available workflow types, creates Procedure instances through reflection, and finds the entrance workflow. Finally, it calls the Initialize method of the workflow manager to initialize the finite state machine and calls the StartProcedure method to start the entrance workflow.

Once a workflow starts, it enters the managed state of the finite state machine. Each workflow executes according to its lifecycle hook sequence: OnInit (Initialize) → OnEnter (Enter) → OnUpdate/OnFixedUpdate (Polling) → OnLeave (Leave) → OnDestroy (Destroy). Developers can write their respective business logic in these hooks.

## Core Concepts

### Workflow (Procedure)

A workflow represents an independent state or stage in the game. Each workflow should have a clear responsibility, for example, loading resources, displaying menus, processing game logic, etc. Workflows can switch to each other, and corresponding lifecycle hook methods are triggered during switching.

### Entrance Workflow

The entrance workflow is the first workflow to execute after the game starts. In the ProcedureComponent Inspector panel, it can be configured through the m_EntranceProcedureTypeName property. This workflow is usually the loading workflow or main menu workflow.

### Workflow Manager

The workflow manager is responsible for managing all registered workflows, including workflow creation, initialization, switching, and destruction operations. It internally uses a finite state machine to implement these functions and provides a unified interface for upper-layer calls.

### Finite State Machine (FSM)

The finite state machine is the underlying implementation of the entire workflow system. Each workflow is considered a state in the finite state machine, and transitions between states are managed uniformly by the state machine. This design makes workflow switching logic simple and reliable.

## Dependencies

The Procedure component depends on the following GameFrameX core modules:

| Dependency Module | Description | Role |
|---------|------|------|
| FSMComponent | Finite State Machine Component | Provides finite state machine creation and management functionality |
| GameFrameworkEntry | Framework Entry | Provides module registration and get functionality |
| GameFrameworkComponent | Component Base Class | Provides component initialization and configuration functionality |

Before using the Procedure component, ensure these dependency components are correctly configured in the project. The GameFrameX framework will automatically process dependencies between modules. Developers only need to add the corresponding components in the Unity scene.

## Getting Started

1. Create an empty GameObject in the Unity scene
2. Add ProcedureComponent component to this GameObject
3. Configure available workflow types and entrance workflow in the Inspector panel
4. Create custom procedure classes inheriting from ProcedureBase
5. Add the custom procedure class names to the available workflow list
6. Run the game, the system will automatically start the Entrance Procedure
