# 親子階層関係の構築方法

`AttachEntity` シリーズのメソッドを使用すると、既存のエンティティを別のエンティティの下にアタッチできます。フレームワークは親子マッピングを記録し、`Transform` の親子関係を自動的に同期し、`EntityLogic` 上の `OnAttached` / `OnDetached` コールバックを発火させます。

## 前提条件

- 親エンティティと子エンティティは、いずれも `ShowEntity` または `CreateEntity` で作成済みであり、表示済みの状態であること。
- `GameFrameX.Entity.Runtime.EntityComponent` がアタッチされており、`GameEntry.Entity` から取得できること。
- 子エンティティのルート `Transform`(つまりその `EntityLogic` が存在する GameObject)が、親に制御される対象となります。

## 操作手順

### 1. エンティティ ID で親子関係を構築する

```csharp
// 子エンティティ childEntityId を parentEntityId の下にアタッチする
GameEntry.Entity.AttachEntity(childEntityId, parentEntityId);
```

ソースコード:[EntityComponent.cs#L756-L765](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L756-L765)

### 2. エンティティオブジェクトでアタッチする

```csharp
Entity childEntity = GameEntry.Entity.GetEntity(childEntityId);
Entity parentEntity = GameEntry.Entity.GetEntity(parentEntityId);
GameEntry.Entity.AttachEntity(childEntity, parentEntity);
```

### 3. 親の Transform とアタッチデータを指定する

子エンティティをルート `Transform` ではなく、親エンティティの特定のノード(例：武器の取り付けポイント)にアタッチする必要がある場合は、`parentTransform` と `userData` を持つオーバーロードを使用し、`AttachToEntity` によって作成時に一度にバインドします:

```csharp
GameEntry.Entity.AttachToEntity(
    childEntityId, parentEntityId,
    "WeaponSocket01",   // 親エンティティの子ノード名
    userData: payload); // カスタムデータ
```

`AttachEntityInfo` は親 `Transform` とユーザーデータを保持します:

```csharp
public class AttachEntityInfo : IReference
{
    public Transform ParentTransform { get; }
    public object    UserData       { get; }
}
```

ソースコード:[AttachEntityInfo.cs#L38-L78](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/AttachEntityInfo.cs#L38-L78)

### 4. 親エンティティでアタッチイベントを受け取る

`EntityLogic.OnAttached` をオーバーライドすることで、子エンティティがいつアタッチされたかを知ることができます。`userData` はそのまま渡されます:

```csharp
protected internal override void OnAttached(EntityLogic childEntity, Transform parentTransform, object userData)
{
    base.OnAttached(childEntity, parentTransform, userData);
    Debug.Log($"child {childEntity.Id} attached under {parentTransform.name}");
}
```

## 親子関係の解除

親エンティティの `EntityLogic` で `OnDetached` をオーバーライドします。フレームワークは子エンティティのバインドが解除される際にこのメソッドをコールバックし、元の `userData` を渡します:

```csharp
protected internal override void OnDetached(EntityLogic childEntity, object userData)
{
    base.OnDetached(childEntity, userData);
    // 参照の返却、駆動の停止などのクリーンアップ処理
}
```

## よくあるバリエーション

- **作成時に直接親を設定**:`AttachToEntity` を使えば、`ShowEntity` と同じ一連のフローの中で親エンティティ ID、親ノード名、`userData` を指定でき、`AttachEntity` をもう一度呼び出す必要がありません。
- **親の変更**：再度 `AttachEntity(child, newParent)` を呼び出すと、フレームワークは以前の親エンティティとのバインド関係を上書きします。
- **実行時の一括照会**:`GetChildEntities(parentEntityId)` で子エンティティの配列を取得した後、ループで処理します。

## よくあるエラー

- **親子を先に ShowEntity せずに Attach する**:親子エンティティはいずれもロード済みで可視の状態でなければなりません。そうでない場合、null 参照例外がスローされます。
- **エンティティグループ Helper の Transform の誤用**:`AttachToEntity` の `parentTransform` は親エンティティ配下のサブ `Transform` の名前(取り付けポイントなど)であり、エンティティグループのルートノードではありません。
- **OnAttached のオーバーライド忘れ**：親子のアタッチ成功時のコールバックを親エンティティの `EntityLogic` でオーバーライドしないと、「ロジックが発火しない」という錯覚が生じます。デフォルト実装は空です。
- **親子の循環アタッチ**:祖父母エンティティを子の下にアタッチすると無限コールバックチェーンが発生します。階層は必ず単方向にしてください。

## 背景(任意)

フレームワーク内部では、子エンティティ単位で `AttachEntityInfo`(`ParentTransform` + `UserData`)を記録します。親子マッピングと `Transform.SetParent` は `EntityManager` が管理します。`OnAttached` / `OnDetached` は `EntityLogic` に `protected internal virtual` として公開されており、実行時に必要なフックのみをオーバーライドすればよいようになっています。
