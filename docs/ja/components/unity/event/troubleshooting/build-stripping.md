# ビルド後にイベント型がストリッピングされて無効になる場合の対処方法

Editor では正常に動作するのに、IL2CPP でビルドした後（特に Managed Stripping Level を Medium/High に設定した場合）にイベントを発火してもコールバックが呼ばれない、または型名のリフレクションでイベント型を取得できない——これはほぼすべて、マネージドコードのストリッピングによって「文字列/リフレクションからのみ参照される」イベント型が削除されたことが原因です。本モジュールのコア型は `GameFrameXEventCroppingHelper` と `[Preserve]` によって保護済みですが、独自のカスタム `EventArgs` 型は以下の説明に従って保護を補う必要があります。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `Fire` 後に購読したコールバックが実行されない（Editor では正常） | カスタムイベントの `EventArgs` 型がストリッピングされ、`Type.FullName` を解決できない | 手順 1：カスタムイベントクラスに `[Preserve]` を追加する |
| `Utility.Assembly.GetType(componentType)` で実装型を取得できず、コンポーネントの初期化に失敗する | 実装型が文字列からのみ参照され、linker によって削除される | 手順 2：ストリッピング保護 Helper がシーン/アセンブリに存在するか確認する |
| 初回パッケージ/ホットアップデートのアセンブリ内のイベント型がすべて丸ごと無効になる | アセンブリ全体がストリッピングされる | 手順 3：`link.xml` でアセンブリを丸ごと保持する |
| 一つひとつ調査したくない | すばやく利用可能な状態に復旧したいだけ | 手順 4：Managed Stripping Level を下げる |

## 修正手順

### 1. カスタムイベントクラスに `[Preserve]` を追加する（推奨）

モジュールのイベント基底クラス自体がこの方法で保護されています。これに倣って、各カスタムイベントクラスに属性を追加します：

```csharp
namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// ゲームロジックイベントの基底クラス。
    /// </summary>
    [UnityEngine.Scripting.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

出典： [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

イベント ID は型の完全修飾名文字列に依存しています（例えば `EmptyEventArgs` は内部で `typeof(EmptyEventArgs).FullName` を `_eventId` として使用）。型がストリッピングされると購読と発火の ID が一致しなくなるため、型が削除されないことを保証しなければなりません。[EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L15-L21) を参照してください。

### 2. モジュール付属のストリッピング保護 Helper が有効かを確認する

モジュールには参照保護コンポーネントが組み込まれており、ビルド時にこのアセンブリがコンパイルに参加している限り、コア型がストリッピングされることはありません：

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Event.Runtime
{
    [Preserve]
    public class GameFrameXEventCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(EventManager);
            _ = typeof(EventComponent);
            _ = typeof(GameEventArgs);
            _ = typeof(IEventManager);
        }
    }
}
```

出典： [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs#L1-L18)

調査時には次の 2 点を確認してください：

1. `GameFrameX.Event.Runtime` アセンブリが丸ごと削除されていないこと（手順 3 のフォールバック対策を参照）。
2. 自分で追加した型は上記の参照リストに含まれていないため、引き続き手順 1 に従って個別に `[Preserve]` を追加する必要があります。

また、`EventComponent` は初期化時に `Utility.Assembly.GetType(componentType)` で文字列から実装型を解決しており、この処理はストリッピングの影響を最も受けやすい箇所です。[EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L67-L69) を参照してください。

### 3. `link.xml` でアセンブリを丸ごと保持する（フォールバック）

`Assets` 配下の任意の場所（例えば `Assets/StreamingAssets` 以外の通常のディレクトリ）に `link.xml` を新規作成し、ランタイムアセンブリを丸ごと保持するとともに、カスタムイベントが含まれるアセンブリも追加します：

```xml
<linker>
  <assembly fullname="GameFrameX.Event.Runtime" preserve="all"/>
  <!-- カスタムイベント型が含まれるアセンブリ。asmdef 名に従って記入してください -->
  <assembly fullname="YourGame.Logic" preserve="all"/>
</linker>
```

アセンブリ名はリポジトリ内の asmdef に準拠します：ランタイムアセンブリのファイルは `Runtime/GameFrameX.Event.Runtime.asmdef`、エディター用アセンブリは `Editor/GameFrameX.Event.Editor.asmdef` です。

### 4. Managed Stripping Level を下げる

`Project Settings → Player → Other Settings → Optimization → Managed Stripping Level` を `Minimal` または `Low` に設定すると、ストリッピングの強度が下がり、「文字列参照が削除される」問題の大半は解消されます。その代わりパッケージサイズが大きくなるため、根本原因がストリッピングかどうかをすばやく検証する目的でのみ使用することをお勧めします。

## 検証

1. 実機向けに再ビルドします（Editor ではストリッピングが発生しないため、実際のビルドで検証する必要があります）。
2. シーン内でイベントを購読して `Fire` し、コールバックが実行されることを確認します。
3. イベントカウント用インターフェースでプログラムによる検証も可能です：`EventManager` は `EventHandlerCount`、`EventCount` プロパティと `Count(string id)` メソッドを提供しており、購読に成功すると対応する ID のハンドラー数は 0 より大きくなるはずです。[EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L54-L65) と [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L98-L102) を参照してください。

## 背景

本モジュールのイベントは「型の完全修飾名文字列」を ID としており、購読、発火、コンポーネント実装の解決はすべて文字列/リフレクションの経路を通ります。IL2CPP のマネージド linker は静的に可視な参照しか追跡できず、これらの動的な参照は認識できないため、関連する型を「未使用」と判定して削除します。`[Preserve]` 属性と `link.xml` は、いずれも linker に対して「この型は必ず保持する」ことを宣言する標準的な手段であり、`GameFrameXEventCroppingHelper.Start` 内の明示的な `typeof(...)` 参照も同様の原理です。
