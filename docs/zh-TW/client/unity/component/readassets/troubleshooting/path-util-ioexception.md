# PathUtil 擲出 IOException:Invalid path: double dot error / Invalid characters

呼叫 `PathUtil.NormalizeRelativePath` 時，若傳入的相對路徑包含越界的 `..` 區段或非法字元，將會擲出 `System.IO.IOException`。常見訊息有兩種:`Invalid path: double dot error (before N)` 與 `Invalid characters`。

## 快速診斷

| 症狀(原始例外訊息) | 根本原因 | 修正方式 |
|---|---|---|
| `Invalid path: double dot error (before <N>)` | 已到達「虛擬根 `/`」之後，仍嘗試再用 `..` 往上一層 | 移除多餘的 `../`,確保路徑不會超出進入點的根目錄 |
| `Invalid characters` | 路徑包含被 `IsValidCharacter` 拒絕的字元(`\"`、`<`、`>`、`\|`、控制字元 `<32`、`:`、`*`、`?`) | 移除或替換非法字元 |

兩種例外皆來自 `Runtime/PathUtil.cs` 中的 `NormalizeRelativePath`。

## 修正步驟

### 1. 處理 `Invalid path: double dot error`

觸發條件：解析過程中，`..` 試圖越過已完成正規化的「根 `output`」。原始碼片段：

```csharp
// Runtime/PathUtil.cs#L107-L112
else if ( state == NormalizeState.PrevDoubleDot )
{
    if ( output.Length == 1 )
    {
        throw new System.IO.IOException("Invalid path: double dot error (before " + i + ")");
    }
    ...
}
```

也就是說，當目前累積的輸出只剩下開頭的根斜線時又出現 `..`,便會直接擲出例外。

修正方式：

1. 列印傳入的相對路徑，定位「最後一個」有問題的 `..`。
2. 計算實際可上溯的層數(等於路徑前綴中非 `..` 區段的數量)，並移除多餘的 `../`。
3. 若呼叫端使用 `Path.Combine` 將絕對路徑與包含 `../` 的相對路徑串接，請改用 `PathUtil.CombineSlash`,或先呼叫 `NormalizeRelativePath` 再進行串接。

```csharp
// 在使用 NormalizeRelativePath 之前,先將 ../ 縮減至合理範圍
var safe = relative.Replace("..\\", "").Replace("../", "");
var normalized = PathUtil.NormalizeRelativePath(safe);
```

`NormalizeRelativePath` 也支援開頭與結尾以雙引號包裹的形式：原始碼中若偵測到開頭與結尾皆為 `"`,會在解析前自動剝除(`Runtime/PathUtil.cs#L93-L97`)。請勿將此視為繞過非法字元的「逃生門」——以下類型的例外仍會被擲出。

### 2. 處理 `Invalid characters`

觸發條件：路徑包含 `IsValidCharacter` 不允許的字元：

```csharp
// Runtime/PathUtil.cs#L173-L180
public static bool IsValidCharacter(char c)
{
    if (c == '\"' || c == '<' || c == '>' || c == '|' || c < 32 || c == ':' || c == '*' || c == '?')
    {
        return false;
    }
    return true;
}
```

原始碼中擲出例外之處：

```csharp
// Runtime/PathUtil.cs#L159-L162
if (!IsValidCharacter(relative[i]))
{
    throw new System.IO.IOException("Invalid characters");
}
```

修正方式：

1. 在呼叫 `NormalizeRelativePath` 之前，先過濾或替換上述 8 類字元。可直接重複利用現有的檢查：

```csharp
// 呼叫端先自行檢查,避免直接撞上 IOException
foreach (var ch in relative)
{
    if (!PathUtil.IsValidCharacter(ch))
    {
        // 回報錯誤或替換
        throw new ArgumentException($"Illegal character: {ch}");
    }
}
```

2. Windows 風格的磁碟機代號(`C:`,冒號)會被視為非法字元。若路徑來自使用者輸入或外部資源名稱，建議先進行白名單驗證。
3. 若屬於萬用字元情境，請改用 `PathUtil.WildcardToRegex`(參見 `Runtime/PathUtil.cs#L183-L186`);它只接受 `*` 與 `?` 作為中繼字元。其他非法字元會被 `Regex.Escape` 逸出，不會在此觸發 IOException。

## 驗證

修正後，讓 `NormalizeRelativePath` 正常回傳：

```csharp
// 合法路徑:回傳正規化結果,不應擲出例外
var ok = PathUtil.NormalizeRelativePath("a/b/../c");   // -> "/a/c"
var ok2 = PathUtil.NormalizeRelativePath("\"a/b\"");   // 自動剝除引號 -> "/a/b"

// 仍屬非法的反例,用於確認異常路徑仍可被攔截
try
{
    PathUtil.NormalizeRelativePath("../a");
    PathUtil.NormalizeRelativePath("a:b");
}
catch (System.IO.IOException ex)
{
    Debug.LogWarning(ex.Message); // 應看到 double dot / Invalid characters
}
```

若兩種例外皆未擲出，表示問題已解決。

## 背景說明(選讀)

`NormalizeRelativePath` 內部將路徑視為以 `/` 開頭的相對虛擬根，逐字元掃描，並維護四個狀態:`PrevSlash / PrevDot / PrevDoubleDot / NothingSpecial`(`Runtime/PathUtil.cs#L11-L17`);`..` 的實作方式是回退已寫入的區段，一旦回退到只剩根斜線，即視為越界。非法字元會在寫入(`Append`)之前以白名單檢查——兩種例外便是在此時觸發。
