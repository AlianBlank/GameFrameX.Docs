# StreamingAssets 파일 읽기 (바이트/텍스트/스트림)

`BlankReadAssets` 정적 클래스에서 제공하는 `System.IO` 스타일 API를 통해 통일되고 스레드 안전한 방식으로 `StreamingAssets` 하위의 임의의 파일을 직접 읽습니다. 바이트, 텍스트, 행 단위, 스트림 네 가지 읽기 방식을 지원하며, APK 압축 해제 없이 Android APK 내부의 파일도 읽을 수 있습니다.

## 사전 조건

- Package Manager를 통해 `com.gameframex.unity.readassets` 패키지를 도입 (자세한 내용은 `README.zh-CN.md`의 「설치」 챕터 참조)
- 대상 파일이 Unity 프로젝트의 `Assets/StreamingAssets/` 디렉터리에 배치되어 있음
- WebGL 플랫폼은 지원되지 않음

## 작업 단계

### 1. 모든 바이트 읽기 (적용 시나리오: 이미지, 설정 바이너리, 커스텀 데이터 파일)

```csharp
using GameFrameX.ReadAssets.Runtime;

// 한 번에 메모리에 로드, 용량이 작은 파일에 적합
byte[] data = BlankReadAssets.ReadAllBytes("Config/settings.bin");
```

`path` 매개변수는 `StreamingAssets` 루트 디렉터리의 상대 경로입니다 (예: `"Config/settings.bin"`). `null`을 전달하면 `ArgumentNullException`이 발생하고, 빈 문자열을 전달하면 `ArgumentException`이 발생합니다.

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L198-L211)

### 2. 스트림 방식으로 읽기 (적용 시나리오: 대용량 파일, 증분 파싱, `Stream` 호환 라이브러리)

```csharp
using (Stream stream = BlankReadAssets.OpenRead("Levels/level1.dat"))
{
    // 일반적인 System.IO.Stream 처럼 사용
    byte[] buffer = new byte[4096];
    int read = stream.Read(buffer, 0, buffer.Length);
}
```

`OpenRead`는 `System.IO.Stream`을 반환하며, Android 플랫폼에서는 내부적으로 APK에서 압축 해제하여 읽습니다. 반환된 스트림의 `Dispose`는 호출자가 처리해야 합니다.

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L133-L146)

### 3. 모든 텍스트 읽기 (적용 시나리오: JSON, TXT, XML, CSV 등 플레인 텍스트 설정)

```csharp
string json = BlankReadAssets.ReadAllText("Config/app-config.json");
MyConfig config = JsonUtility.FromJson<MyConfig>(json);
```

`ReadAllText`는 내부적으로 `OpenText`(UTF-8 `StreamReader`로 감싸진)를 호출하며, 다 읽은 후 한 번에 해제됩니다.

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L167-L173)

### 4. 행 단위로 읽기 (적용 시나리오: 로그, 테이블, TXT 사전)

```csharp
string[] lines = BlankReadAssets.ReadAllLines("Localization/zh-CN.txt");
foreach (var line in lines)
{
    Debug.Log(line);
}
```

반환값은 줄 바꿈 문자가 제거된 문자열 배열이며, 파일 끝의 빈 줄은 포함되지 않습니다.

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L176-L190)

### 5. `StreamReader`만 가져오기 (인코딩 제어 또는 커스텀 읽기가 필요한 경우)

기본 동작이 요구 사항을 충족하지 않는 경우, `OpenText`를 사용하여 `StreamReader`를 얻어 직접 처리할 수 있습니다:

```csharp
using (var sr = BlankReadAssets.OpenText("Data/big.csv"))
{
    string header = sr.ReadLine();
    while (!sr.EndOfStream)
    {
        string row = sr.ReadLine();
        // 각 행 처리
    }
}
```

## 일반적인 변형

- **읽기 전 존재 여부 확인**: `FileExists(path)`로 미리 확인하여 파일이 없을 때 예외 분기로 들어가는 것을 피합니다.
- **디렉터리 파일 열거**: `GetFiles(path, searchPattern, searchOption)`을 사용하며, 와일드카드와 재귀 검색을 지원합니다.
- **AssetBundle 읽기**: `LoadAssetBundle` / `LoadAssetBundleAsync`를 사용하며, 내부적으로 APK 오프셋에 따라 리소스를 찾습니다.
- **에디터에서 APK 읽기 테스트**: `InitializeWithExternalApk(apkPath)`를 호출하여 APK 모드로 전환합니다.
- **크로스 스레드 호출**: 모든 API는 스레드 안전하므로 작업 스레드에서 직접 호출할 수 있습니다.

```csharp
// 특정 디렉터리의 모든 XML 열거
string[] xmls = BlankReadAssets.GetFiles("Config", "*.xml", SearchOption.TopDirectoryOnly);

// StreamingAssets의 모든 XML을 재귀적으로 열거
string[] allXmls = BlankReadAssets.GetFiles("/", "*.xml", SearchOption.AllDirectories);
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L214-L230)

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `ArgumentNullException("path")` 발생 | `path`에 `null`을 전달함 | 빈 문자열이 아닌 값을 전달하고, 사용 전 null 검사 수행 |
| `ArgumentException("Empty path", "path")` 발생 | `path`가 빈 문자열임 | 유효한 상대 경로를 전달 |
| 파일을 찾을 수 없음 예외 발생 | 상대 경로 오기 또는 파일명 대소문자가 StreamingAssets의 실제와 일치하지 않음 | `FileExists`로 사전 검증; Android에서는 소문자 및 ASCII 문자만 사용 |
| WebGL 플랫폼에서 컴파일 오류 발생 | 본 라이브러리는 WebGL을 지원하지 않음 | PC/Mobile/Console 플랫폼으로 전환하거나 직접 `UnityWebRequest`를 사용하여 구현 |
| `GetFiles`가 빈 배열을 반환 | `StreamingAssets` 디렉터리가 존재하지 않거나 경로 오타 | 먼저 `DirectoryExists`로 디렉터리 검증 |## 배경 (선택 사항)

- 임의의 API를 처음 호출할 때, 라이브러리는 자동으로 `BlankReadAssets.Initialize()`를 호출하여 플랫폼별 초기화를 완료하므로 수동으로 처리할 필요가 없습니다. Android에서는 내부적으로 ZIP 중앙 디렉터리를 통해 `StreamingAssets` 파일을 찾으므로 APK 전체를 디스크에 압축 해제하지 않습니다; 다른 플랫폼에서는 파일 시스템을 직접 사용합니다.
- 모든 읽기 진입점(`ReadAllBytes`, `OpenRead`, `OpenText` 등)은 결과를 받기 전에 `EnsureInitialized()`를 호출하므로 임의의 스레드에서 호출하는 것이 안전합니다.
- 라이브러리의 설치 방법 및 플랫폼 지원에 대해서는 《README.zh-CN.md》를 참조하세요.
