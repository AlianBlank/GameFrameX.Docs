# 启动时出现 "Web manager is invalid." 致命日志怎么办

这条 Fatal 日志出自 `WebProtoBuffComponent.Awake()`：当 `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` 返回 `null` 时打印，表示 Web ProtoBuff 管理器模块没有被成功获取（未注册或实现类型被裁剪）。组件随即 `return`，后续所有 Web 请求调用都会失效。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动即打印 `Web manager is invalid.`，之后调用 `Post` 等接口抛 `NullReferenceException` | `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` 返回 `null`，管理器实现未注册到框架入口 | 见下方修复步骤 1 |
| 构建包（真机/裁剪后）才出现该日志，编辑器正常 | 托管代码裁剪把 `WebProtoBuffManager` 实现类裁掉了 | 见下方修复步骤 2 |
| 手动删除了物体上的 `GameFrameXWebProtoBuffCroppingHelper` | 该 Helper 通过 `typeof` 引用管理器类型，用于防止链接器裁剪 | 见下方修复步骤 3 |
| 调用 `Post<T>` 时提示方法不存在 | 未启用 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 宏（该宏只影响 `Post<T>`，与 Fatal 日志本身无关） | 见下方修复步骤 4 |

## 修复步骤

日志的判定代码如下，可用于对照排查：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IWebProtoBuffManager);
    base.Awake();
    m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
    if (m_WebProtoBuffManager == null)
    {
        Log.Fatal("Web manager is invalid.");
        return;
    }

    m_WebProtoBuffManager.Timeout = m_Timeout;
}
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L77-L90)

1. **确认管理器实现类可达**。`WebProtoBuffManager`（位于 `Runtime/Web/WebProtoBuffManager.cs`，命名空间 `GameFrameX.Web.ProtoBuff.Runtime`）是 `IWebProtoBuffManager` 的实现，`GetModule` 依赖 `GameFrameworkEntry` 所在的 GameFrameX 运行时基础包完成注册。确认项目中已正确安装 GameFrameX 基础运行时包，且本包的程序集编译无报错（Console 无红色编译错误）。
2. **降低/关闭托管裁剪**。在 Unity 的 `Player Settings → Managed Stripping Level` 中调低裁剪等级，或为本包程序集配置保留规则，确保 `WebProtoBuffManager` 不被裁掉。
3. **保留防裁剪 Helper**。`WebProtoBuffComponent` 通过 `[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]` 强制依赖该 Helper，它持有对本包全部关键类型的引用：

```csharp
[Preserve]
public class GameFrameXWebProtoBuffCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(WebProtoBuffComponent);
        _ = typeof(IWebProtoBuffManager);
        _ = typeof(WebProtoBuffManager);
    }
}
```

Source: [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs#L6-L16)

   不要手动删除场景中物体上的 `GameFrameXWebProtoBuffCroppingHelper` 组件。
4. **按需启用网络宏**。如需使用 Protocol Buffer 请求，在 `Scripting Define Symbols` 中加入 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`，否则 `Post<T>` 不会被编译进组件（见 `WebProtoBuffComponent.cs` 第 92 行的 `#if` 条件）。

## 验证

- 重新进入 Play 模式（或重新构建），Console 中不再出现 `Web manager is invalid.` Fatal 日志。
- 组件 Inspector 中修改 `Timeout`（默认 `5f` 秒）能正常生效——它直接读写 `m_WebProtoBuffManager.Timeout`。
- 启用宏后，`WebProtoBuffComponent.Post<T>(url, message)` 可被正常调用。
