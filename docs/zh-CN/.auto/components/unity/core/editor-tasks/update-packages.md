# 批量更新项目依赖

通过 `UpdateAllPackageHelper` 一键批量更新 `Packages/manifest.json` 中所有以 `.git` 结尾的 Git 依赖,免去手动逐个操作的繁琐流程。

## 前置条件

- 项目根目录存在 `Packages/manifest.json`,且其中包含至少一个 `*.git` 形式的依赖地址。
- 已通过 Unity 打开本工程。
- Git 命令在系统 PATH 中可用(UPM 的 `Client.Add` 会调用本地 Git 拉取远端)。

## 操作步骤

### 方式一:菜单一键批量更新

1. 在 Unity 编辑器顶部菜单选择 `GameFrameX → Update All Packages(更新所有git包)`。
2. 弹出确认框 `是否更新所有包?` 后点 **是**。
3. 工具会读取 `Packages/manifest.json`,把所有以 `.git` 结尾的依赖加入更新队列,并显示可取消的进度条。
4. 更新完成后,**重启 Unity** 让 UPM 应用变更。

入口实现见 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L20-L32):

```csharp
[MenuItem("GameFrameX/Update All Packages(更新所有git包)", false, 2000)]
public static void UpdatePackages()
{
    var result = EditorUtility.DisplayDialog("更新包提示", "是否更新所有包?\n 更新完成之后需要[重启、重启、重启]Unity", "是", "否");
    if (result)
    {
        var manifestPath = Path.Combine(Application.dataPath, "..", "Packages", "manifest.json");
        UpdatePackagesFromManifest(manifestPath);
    }
}
```

### 方式二:在 Package Manager 窗口内更新到指定版本

1. 打开编辑器窗口 `GameFrameX → Package Manager`。
2. 在列表中选择要更新的包,在工具栏中点击 **Update To Version**。
3. 工具会改写该包的 URL,把 `#<version>` 后缀拼接好,并通过 `UpdateAllPackageHelper.UpdatePackages(name, url)` 立即触发更新流程。

实现见 [PackageManagerWindow.cs](/src/Editor/PackageManager/PackageManagerWindow.cs#L233-L274):

```csharp
saveManifest.Dependencies[dependency.Key] = url;
UpdateAllPackageHelper.UpdatePackages(packageName, url);
continue;
...
UpdateAllPackageHelper.StartUpdate();
AssetDatabase.Refresh();
```

工具栏入口见 [PackageManagerWindow.ToolBar.cs](/src/Editor/PackageManager/PackageManagerWindow.ToolBar.cs#L60-L70),点击按钮直接调用 `UpdateAllPackageHelper.UpdatePackages()`。

### 方式三:代码层调用

如果要在自定义编辑器脚本里复用同一套逻辑,直接调用两个静态方法即可:

```csharp
using GameFrameX.Editor;

// 入队单个 Git 依赖
UpdateAllPackageHelper.UpdatePackages("com.gameframex.runtime", "https://example.com/repo.git");

// 真正开始拉取(从队列里依次 Client.Add)
UpdateAllPackageHelper.StartUpdate();
```

签名定义见 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L34-L42):

```csharp
/// <summary>
/// 更新指定包
/// </summary>
/// <param name="packageName">包名</param>
/// <param name="packageUrl">包地址</param>
public static void UpdatePackages(string packageName, string packageUrl)
{
    PackagesToUpdate.Enqueue((packageName, packageUrl));
}
```

## manifest 扫描与队列填充逻辑

`UpdatePackages()` 会调用私有方法 `UpdatePackagesFromManifest` 解析 `manifest.json`,只把以 `.git` 结尾的依赖入队,其余形式的版本号/本地路径会被忽略。见 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L44-L64):

```csharp
foreach (var package in dependencies)
{
    string packageName = package.Key;
    string packageUrl = package.Value.ToString();
    if (packageUrl.EndsWith(".git"))
    {
        UpdatePackages(packageName, packageUrl);
    }
}
StartUpdate();
```

## 常见变体

| 场景 | 做法 |
|------|------|
| 只想更新某一个包到固定版本 | 打开 Package Manager 窗口,使用 Update To Version 功能(自动拼接 `#<tag>`) |
| 只想批量更新但保留版本号 | 确保 manifest.json 中 URL 形如 `https://.../repo.git#v1.2.0`,UPM 会拉取该 tag |
| 想从代码里扩展更新更多来源 | 自行入队更多 `(name, url)` 后调用 `StartUpdate()` |

## 常见错误

- **更新后控制台报错**:进度条被取消会导致队列被 `PackagesToUpdate.Clear()` 清空,见 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L92-L99);若需要继续,重新触发菜单。
- **manifest.json 改动后未生效**:菜单提示明确要求 **重启、重启、重启 Unity**,否则 UPM 缓存未刷新。
- **依赖不是 `.git` 地址被忽略**:例如 `file:./...` 或 OpenUPM 链接会被跳过,需要用 Package Manager 窗口的 Update To Version 处理。
- **`Client.Add` 调用频率过快**:队列实现 `Queue<(name, url)>` 串行处理,避免并发请求异常。

## 背景(可选)

`UpdateAllPackageHelper` 内部用 `AddRequest` + `EditorApplication.update` 事件驱动进度,逐个包调用 `UnityEditor.PackageManager.Client.Add`,并通过 `EditorUtility.DisplayCancelableProgressBar` 给出可取消的进度反馈。所有状态(`_addRequest`、`PackagesToUpdate`、`_allPackagesCount`、`_updatingPackagesIndex`)都是 `static` 字段,跨调用保持,适合多次入队后一次性启动。
