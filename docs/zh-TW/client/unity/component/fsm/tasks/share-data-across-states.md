# 狀態間資料共享方法 (Variable)

透過 `Fsm<T>` 內建的 `SetData` / `GetData` 方法，以字串作為 Key 來儲存與取得 `Variable` 實例，即可在任意兩個 `FsmState<T>` 之間安全地傳遞執行階段資料。

## 前置條件

- 必須已透過 `FsmComponent.CreateFsm<T>` 建立有限狀態機，並至少註冊兩個狀態。
- 狀態類別必須繼承 `FsmState<T>`,以便在 `OnEnter` / `OnUpdate` / `OnExit` 中透過 `fsm` 參數存取 FSM。
- 要共享的資料型別必須繼承 `Variable`(內建或自訂皆可)。

## 操作步驟

1. **確認共享資料型別**：框架要求資料必須衍生自 `Variable`。這是因為 FSM 會透過物件池(`ReferencePool`)重複使用 `Variable` 實例，以避免 GC。

   ```csharp
   // 共享整數進度 (0~100)
   public sealed class ProgressVar : Variable
   {
       private int m_Value;
       public int Value
       {
           get => m_Value;
           set => m_Value = value;
       }
   }
   ```

   來源:[Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L46)

2. **在狀態 A 寫入資料**：呼叫 `SetData<TData>(name, data)`。再次寫入同名資料時，先前的實例會自動被回收到 `ReferencePool`。

   ```csharp
   public class LoadingState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = new ProgressVar { Value = 0 };
           fsm.SetData("Progress", progress);
       }

       protected override void OnUpdate(IFsm<MyOwner> fsm, float elapseSeconds, float realElapseSeconds)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress != null)
           {
               progress.Value += 1; // 直接修改 Value,無需再次 Set
           }
       }
   }
   ```

   來源:[Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L497-L500)

3. **在狀態 B 讀取資料**：使用強型別的 `GetData<TData>(name)` 直接取得衍生類別的實例。若 Key 不存在或型別不符，則會回傳 `null`。

   ```csharp
   public class PlayState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress == null)
           {
               // 狀態機中沒有該筆資料,可視需求進行備援處理
               return;
           }
           fsm.Owner.Ui.ShowProgress(progress.Value);
       }
   }
   ```

   來源:[Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

4. **不再需要時清理資料**：呼叫 `RemoveData(name)` 即可將資料物件回收到物件池。

   ```csharp
   fsm.RemoveData("Progress");
   ```

   來源:[Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L535)

## 常見變化

| 情境 | 用法 | 備註 |
|------|------|------|
| 不清楚確切型別，僅確認是否存在 | `fsm.GetData("Progress")` 回傳 `Variable` 基底類別 | 參考:[Fsm.cs#L469](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488) |
| 多個狀態重複覆寫同一個 Key | 直接再次呼叫 `SetData` | 先前的實例會自動被 `ReferencePool.Release` 回收 ([Fsm.cs#L521-L524](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L521-L524)) |
| 共享資料不需要 GC 重複使用 | 可傳入任意 `Variable` 子類別 | 框架僅強制基底類別必須為 `Variable`,欄位可自由使用 |

## 常見錯誤

| 錯誤現象 | 原因 | 解決方法 |
|----------|------|------|
| 以空字串作為 `name` 傳入，導致擲回 `GameFrameworkException("Data name is invalid.")` | API 要求 `name` 不可為空 | 使用常數或列舉作為 key |
| `GetData<TData>` 回傳 `null` 而發生 NRE | 該 Key 從未被寫入，或型別不符 | 在寫入端執行 `SetData` 後再讀取，或先以 `GetData(name)` 確認是否存在 |
| 重複對同名資料 `new`,導致記憶體增加 | 未重複使用 `Variable` 物件 | 重複使用同一實例，僅修改內部欄位;必要時才以 `SetData` 覆寫 |
| FSM 銷毀後仍存取 `GetData` | FSM 已被銷毀 | 在 `OnExit` 內清理參考，且勿快取 `IFsm<T>` 控制代碼 |

## 背景 (選用)

`m_Datas` 為 `Dictionary<string, Variable>`,`Fsm<T>` 會在首次呼叫 `SetData` 時視需要建立 ([Fsm.cs#L515-L518](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L515-L518))。由於覆寫同名 Key 時會呼叫 `ReferencePool.Release` 將其回收至池中，因此 `Variable` 必須實作參考池協定 (繼承 `Variable` 即已包含)。
