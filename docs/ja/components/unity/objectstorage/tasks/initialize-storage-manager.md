# オブジェクトストレージマネージャーの初期化方法

`ObjectStorageUploadFactory.Create<T>` を通じてオブジェクトストレージアップロードマネージャーのインスタンスを作成し、初期化します。完了後、`UploadFile` / `UploadDirectory` などのインターフェースを呼び出してファイルをアップロードできます。

## 前提条件

- `com.gameframex.unity.objectstorage` パッケージがインストールされていること。
- `IObjectStorageUploadManager` を実装する具象型が導入されていること(本パッケージでは抽象基底クラス `BaseObjectStorageUploadManager` のみを提供しており、具体的なクラウドベンダーの実装は別途導入する必要があります)。
- 4つのパラメータを準備していること:`accessKey`、`secretKey`、`bucketName`、および任意の `endpoint`。

## 操作手順

1. コードにネームスペースの参照を追加します:

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13)

2. 静的メソッド `ObjectStorageUploadFactory.Create<T>` を呼び出し、ジェネリックパラメータ(実装クラス)と4つの資格情報を渡します。ファクトリ内部で `Activator.CreateInstance<T>()` が呼び出され、自動的に `Init` が実行されるため、手動で初期化する必要はありません:

   ```csharp
   // 假设已引入某个具体实现,例如 MyCloudUploader : IObjectStorageUploadManager
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create<MyCloudUploader>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: "https://oss-cn-hangzhou.aliyuncs.com" // 选填,部分对象存储无需该值
   );
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. リモートの保存パスをカスタマイズする必要がある場合は、`SetSavePath` を呼び出します(渡すパスはディレクトリ区切り文字で終わらないよう注意してください。基底クラスが末尾のスラッシュを自動的に削除します):

   ```csharp
   manager.SetSavePath("uploads/build/v1");
   ```

   Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

4. 上記の手順が完了すると、マネージャーは「初期化済み」状態になり、直接 `UploadFile` または `UploadDirectory` を呼び出してアップロードを実行できます。

## よくあるバリエーション

- ファクトリを使用せず、自分で実装クラスを `new` して手動で `Init` を呼び出す場合:

  ```csharp
  var manager = new MyCloudUploader();
  manager.Init("ak", "sk", "bucket", "endpoint");
  ```

  `Init` のシグネチャはインターフェース `IObjectStorageManager` に由来し、`endpoint` はnull許容パラメータで、デフォルトは `null` です。

  Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L13)

- `BaseObjectStorageUploadManager` を直接継承してカスタムアップロードロジックを実装する:`Init`、`UploadDirectoryInternal`、`UploadFileInternal` の3つの `protected`/ `public abstract` メソッドをオーバーライドするだけです。

  Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L10-L34)

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `Create<T>` のコンパイルエラー、`T` が制約を満たしていないと表示される | ジェネリック `T` が `IObjectStorageUploadManager` を実装していない | 具体的なアップロードマネージャークラスを渡す(`BaseObjectStorageUploadManager` を継承するか、インターフェースを直接実装) |
| `SetSavePath` 後にパスが切り詰められる | 渡すパスがディレクトリ区切り文字で終わっている | 基底クラスが末尾の `Path.DirectorySeparatorChar` を自動的に削除するため、手動で処理する必要はありませんが、有効なディレクトリ名を渡してください |
| アップロード時にデフォルトパスが使用される | インスタンス作成後に `SetSavePath` の呼び出しを忘れている | アップロード前に明示的に `BucketSavePath` を設定する |

## 背景(オプション)

`ObjectStorageUploadFactory.Create<T>` は内部で `new` と `Init` の呼び出しを一度に完了させ、呼び出し側が初期化ステップを忘れるのを防ぐことを目的としています。`endpoint` はクラウドベンダーによって意味が異なるため、インターフェースはオプションのパラメータとして互換性を確保しています。
