# 日志报 "fun is invalid." 或 ArgumentNullException 怎么办

当你在调用 `MonoComponent` 的 `AddXxxListener` / `RemoveXxxListener` 系列方法时,日志中看到 `fun is invalid.` 字样,或在测试代码中捕获到 `ArgumentNullException`,都表示**传入了 `null` 回调**。本页给出快速定位和修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 运行日志出现 `fun is invalid.` | 传给 `AddXxxListener` / `RemoveXxxListener` 的 `Action` 为 `null`,内部 `Log.Fatal` 后直接 `return`,监听未生效 | 给回调变量赋一个真实方法或 `lambda`,再用 `?.` 判断后再传 |
| 单元测试抛出 `ArgumentNullException` | 同一组接口的底层 `_monoManager` 会对 `null` 抛出异常,验证了"传 null 必然失败" | 与上一条同因,改为传非 null 回调 |
| 启动时报 `Mono manager is invalid.` | `MonoComponent.Awake` 中 `_monoManager == null`,框架模块未注册 | 见下方"修复步骤 2" |
| 启动时报 `Event manager is invalid.` | `MonoComponent.Start` 中 `m_EventComponent == null`,事件组件未挂载 | 见下方"修复步骤 2" |

## 修复步骤

### 1. 回调为 null 时,先判空再传入

`MonoComponent` 对每个 `Add*Listener` / `Remove*Listener` 都做了 `if (fun == null)` 校验,触发后只记录 `Fatal` 日志并不做任何订阅/取消订阅动作,不会自动抛出 — 但行为不会发生。

Source: [MonoComponent.cs#L147-L171](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L147-L171)

```csharp
public void AddLateUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddLateUpdateListener(fun);
}
```

修复方式:在传入前先做 null 检查,或使用空合并运算符给一个默认空实现,例如:

```csharp
Action<float, float> onLate = null;
if (onLate != null)
{
    GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener(onLate);
}

// 或使用 lambda 占位
GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener((dt, fdt) => { /* 你的逻辑 */ });
```

### 2. 启动阶段报 "Mono manager is invalid." 或 "Event manager is invalid."

这两条日志来自 `MonoComponent` 自身的初始化阶段,不是回调为 null 引起,而是框架模块/组件未就绪。

```csharp
protected override void Awake()
{
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}

private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs#L52-L76](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76)

修复方式:

1. 检查场景中是否挂有实现了 `IMonoManager` 的模块入口组件,或对应的程序集是否被打入 Player Settings 的 `Scripting Define Symbols` / 程序集定义里。
2. 在 GameFramework 的 `GameEntry` 预制体上挂上 `EventComponent`,并确认其执行顺序早于 `MonoComponent`。

### 3. 涉及的全部监听器方法

以下方法在 `MonoComponent.cs` 中都遵循"传 null → `fun is invalid.` 日志 → return"的相同模式,排查时可一并检查:

`AddUpdateListener` / `RemoveUpdateListener`、`AddFixedUpdateListener` / `RemoveFixedUpdateListener`、`AddLateUpdateListener` / `RemoveLateUpdateListener`、`AddDestroyListener` / `RemoveDestroyListener`、`AddOnApplicationFocusListener` / `RemoveOnApplicationFocusListener`、`AddOnApplicationPauseListener` / `RemoveOnApplicationPauseListener`、`AddOnApplicationQuitListener` / `RemoveOnApplicationQuitListener`、`AddDrawGizmosListener` / `RemoveDrawGizmosListener`。

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs)

## 验证

修复后用以下方式确认问题已解决:

1. **运行时**:重新运行游戏,观察日志不再出现 `fun is invalid.`、`Mono manager is invalid.`、`Event manager is invalid.`。
2. **回调触发**:在回调体内打一条 `Debug.Log`,进入对应生命周期(如 `Update`、`LateUpdate`)后能看到日志,说明订阅成功。
3. **单元测试**:仓库 `Tests/UnitTests.cs` 中的 `Assert.Throws<ArgumentNullException>(() => _manager.AddUpdateListener(null))` 等用例用于验证**传 null 必然失败**这一契约;业务代码中应该传入真实委托。
