# JsonHelper를 사용하여 직렬화 및 역직렬화하는 방법

`JsonHelper`는 `GameFrameX.Foundation.Json` 네임스페이스 아래에 캡슐화된 정적 도우미로, 동일한 설정을 사용하여 임의의 객체와 JSON을 상호 변환할 수 있도록 도와줍니다: 기본적으로 `null` 무시, 순환 참조 무시, 열거형은 문자열로 읽기/쓰기, 중국어 / Emoji 이스케이프하지 않으며, 내장된 `NaN` / `Infinity` 호환 처리를 포함합니다.

## 작업 단계

### 1. 설정 선택

`JsonHelper`에는 두 개의 읽기 전용 설정이 내장되어 있어 바로 사용할 수 있습니다:

| 설정 | 필드 | 적용 시나리오 |
|------|------|----------|
| 기본 (압축) | `JsonHelper.DefaultOptions` | 네트워크 전송, 로그, 저장 |
| 포맷 (들여쓰기 및 줄바꿈 포함) | `JsonHelper.FormatOptions` | 디버그 출력, 설정 파일 |
| 사용자 정의 가변 복사본 | `JsonHelper.CreateDefaultOptions()` / `JsonHelper.CreateFormatOptions()` | 기본 설정을 기반으로 조정 |

### 2. 객체를 JSON 문자열로 직렬화

```csharp
var user = new { Name = "张三", Age = 18, Role = UserRole.Admin };

// 기본 설정 (압축)
string json = JsonHelper.Serialize(user);

// 포맷 설정 (들여쓰기 포함)
string pretty = JsonHelper.SerializeFormat(user);

// 사용자 정의 설정
var options = JsonHelper.CreateDefaultOptions();
options.WriteIndented = true;
string custom = JsonHelper.Serialize(user, options);
```

- `Serialize(object obj)` 및 `Serialize(object obj, JsonSerializerOptions options)`는 가장 자주 사용되는 두 개의 진입점입니다. `obj`가 `null`이면 `ArgumentNullException`이 발생합니다.
- 열거형은 기본적으로 **문자열**로 출력됩니다 (`Role: "Admin"`), 숫자가 아닙니다.
- `null` 필드는 자동으로 무시되며, `"Name": null`이 나타나지 않습니다.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L221-L246)

### 3. UTF-8 바이트 배열 또는 스트림으로 직렬화

```csharp
// 바이트 배열 (직접 저장 / HTTP body 전송에 적합)
byte[] bytes = JsonHelper.SerializeToUtf8Bytes(user);
byte[] bytesFormat = JsonHelper.SerializeToUtf8BytesFormat(user);

// 비동기 스트림 쓰기
using var ms = new MemoryStream();
await JsonHelper.SerializeAsync(ms, user);
```

- `SerializeToUtf8Bytes`는 기본적으로 압축 형식이고, `SerializeToUtf8BytesFormat`은 포맷 설정을 사용합니다.
- `SerializeAsync<T>(Stream, T, JsonSerializerOptions?, CancellationToken)`은 기본적으로 `DefaultOptions`를 사용하며, `stream`은 `null`일 수 없습니다.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L333-L356)

### 4. JSON 문자열을 객체로 역직렬화

```csharp
const string payload = "{\"name\":\"张三\",\"age\":18,\"role\":\"Admin\"}";

var restored = JsonHelper.Deserialize<User>(payload);

// 사용자 정의 설정 사용
var restored2 = JsonHelper.Deserialize<User>(payload, options);

// 스트림에서 비동기 읽기
using var input = new MemoryStream(bytes);
var restored3 = await JsonHelper.DeserializeAsync<User>(input);
```

- `Deserialize<T>(string json)`은 내부적으로 `null`, 빈 문자열, 순수 공백 문자열에 대해 `ArgumentException`을 발생시키므로, 호출 전에 먼저 검증해야 합니다.
- JSON에 `NaN` / `Infinity`이 포함된 경우, 메서드가 자동으로 전처리한 후 재시도하므로 수동으로 이스케이프할 필요가 없습니다.
- 속성명 매칭은 **대소문자를 구분하지 않으며**, `Name`과 `name`을 동시에 호환할 수 있습니다.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L406-L421)

### 5. 예외를 발생시키지 않는 Try 버전 (입력의 유효성을 확신할 수 없는 시나리오에서 권장)

```csharp
if (!JsonHelper.TryDeserialize<User>(payload, out var user, out var error))
{
    Console.WriteLine($"역직렬화 실패: {error.Kind} - {error.Message} (path={error.Path})");
}
```

- `TryDeserialize<T>` / `TrySerialize` 시리즈는 `bool`을 반환하고, 실패 시 `out JsonHelperError`를 통해 `Kind`(`InvalidInput` / `TypeMismatch` / `Serialization` / `Unknown`), `Path`, `LineNumber`, `BytePositionInLine`을 제공합니다.
- 기본 설정의 `TryDeserialize<T>(string, out T)`은 `NaN` / `Infinity`가 나타날 때도 자동으로 전처리한 후 재시도합니다.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L749-L807)

## 일반적인 변형

- **AOT / 소스 생성 고성능 경로**: `JsonTypeInfo<T>`를 통해 직렬화 / 역직렬화를 호출하면, 트리밍 및 AOT 시나리오에서 리플렉션 없이 사용할 수 있습니다:

  ```csharp
  string json = JsonHelper.Serialize(user, MyJsonContext.Default.User);
  var restored = JsonHelper.Deserialize<User>(payload, MyJsonContext.Default.User);
  ```

- **사용자 정의 부동 소수점 처리**: 기본 설정에는 `SpecialFloatingPointConverter` 등의 변환기가 이미 등록되어 있어, `"NaN"`, `"Infinity"` 문자열 리터럴을 직접 전달해도 성공적으로 역직렬화할 수 있습니다.
- **BOM 쓰기 / 사용자 정의 Encoder**: `CreateDefaultOptions()`를 호출한 후 `Encoder`에 새 값을 할당하면 되며, 다른 기본 동작에는 영향을 주지 않습니다.
- **외부 입력에 대한 내결함성 역직렬화**: `TryDeserialize<T>(string, out T, out JsonHelperError)`를 우선 사용하고, `JsonHelperError`를 받은 후 폴백方案을 결정하세요.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `ArgumentNullException: obj (Parameter 'obj')` | `Serialize(null)` / `SerializeAsync(stream, null, …)` 호출 | 호출 전에 `obj is null` 검사를 수행하거나 `TrySerialize`로 전환 |
| `ArgumentException: json (Parameter 'json')` | `Deserialize`가 `null`, 빈 문자열 또는 순수 공백을 받음 | 먼저 `string.IsNullOrWhiteSpace`로 판단하거나 `TryDeserialize`를 사용 |
| `JsonException` 그리고 `error.Kind == InvalidInput` | JSON 텍스트가 유효하지 않음 (따옴표 누락, 후행 쉼표 시나리오는 `AllowTrailingCommas=true`이지만 여전히 형식 오류가 발생할 수 있음) | 업스트림 로그 확인; `JsonHelperError`에 내장된 `Path` / `LineNumber`로 위치 파악 가능 |
| 열거형 필드 역직렬화 후 숫자가 됨 | 비즈니스 코드에서 직접 `JsonSerializerOptions`를 new 했으며, `JsonStringEnumConverter`를 등록하지 않음 | `JsonHelper.DefaultOptions` 또는 `CreateDefaultOptions()`를 직접 사용하고, 기본 options를 new 하지 말 것 |

## 배경 (선택 사항)

`DefaultOptions`는 `DefaultIgnoreCondition = WhenWritingNull`, `ReferenceHandler.IgnoreCycles`, `JsonStringEnumConverter`, `AllowReadingFromString | AllowNamedFloatingPointLiterals` 등의 조합을 통해 비즈니스 코드가 `null` 필드, 순환 참조, 열거형 의미에 거의 신경 쓰지 않도록 합니다. 중국어 / Emoji가 이스케이프되지 않는 것은 프로젝트 내의 `UnicodeJsonEncoder`에 의존합니다. 두 설정은 정적 생성자에서 `MakeReadOnly(true)`로 동결되어 런타임에 실수로 변경되는 것을 방지합니다. 호출자가 사용자 정의가 필요한 경우 반드시 `CreateDefaultOptions()`를 사용하여 가변 복사본을 가져와야 합니다.
