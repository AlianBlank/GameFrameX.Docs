# 如何在 Unity / .NET 中读取生成的配置

按照本页步骤，你可以在 Unity 客户端或 .NET 服务端的代码里直接读取由 `gen-client-*` / `gen-server-*` 脚本生成的配置数据，整个过程无需手写解析代码。

## 前置条件

- 已经按文档要求在 `Excels/Tables/` 里准备好 Excel 表（命名规则见下文）。
- 已经执行过生成脚本，Unity 项目下已经存在 C# 类（如 `TbItemConfig`、`TbAchievementConfig`）以及数据文件。
- 引入 `Tables` 容器类的命名空间（默认在生成路径的根命名空间下）。

## 操作步骤

1. 在 `Excels/Tables/` 目录创建/确认 Excel 文件名遵循 `字母-英文名-中文名.xlsx` 规则，例如：

   ```
   D-ItemConfig-道具表-道具-1001.xlsx
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L94-L96)

2. 执行生成脚本（Windows 双击 `.bat`，Mac/Linux 用 `sh`），跑完会在 Unity 项目下生成 C# 类与数据文件：

   ```bash
   # 客户端 (Unity)
   sh gen-client-json.sh
   # 或 gen-client-bin.sh

   # 服务端 (.NET)
   sh gen-server-bin.sh
   # 或 gen-server-json.sh
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L136-L141)

3. 在代码中通过 `tables` 容器拿到对应表，按主键 `Get(id)` 查询单条记录：

   ```csharp
   // 拿到 id 为 10001 的道具
   var item = tables.TbItemConfig.Get(10001);

   // 道具名会自动变成当前语言（比如中文显示「钻石」）
   Debug.Log(item.Name);
   Debug.Log(item.Price); // 10
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L152-L159)

4. 在工具生成的代码里，类名遵循 `Tb英文名` 规则，下表是本仓库现有 Excel 与生成类名的对应关系：

   | Excel 文件名 | 生成的 C# 类名 |
   |--------------|---------------|
   | `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
   | `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
   | `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |
   | `L-Localization-成就.xlsx` | `TbLocalization` |

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L194-L199)

## 常见变体

- **拆分大表**：如果一张表数据特别多（上千条），只需**英文名相同**、中文名任意区分，工具会自动合并为同一张表。例如 `D-ItemConfig-道具表.xlsx` 与 `D-ItemConfig-道具表-1001.xlsx` 会合并成 `TbItemConfig`。
- **只给一端用**：在英文名与中文名中间加分组标记 `c`（只客户端）或 `s`（只服务端），不加则两端都生成。
  - `D-ItemConfig-c-道具表.xlsx` → 只有客户端用到 `TbItemConfig`
  - `D-ItemConfig-s-道具表.xlsx` → 只有服务端用到 `TbItemConfig`
- **数据类型选用**：`text` 是会走多语言翻译的字段（填 key，实际文字在 `Local/` 里），`string` 是原样不翻译的普通字符串。

## 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| 找不到 `tables.TbXxx` 类 | 没跑生成脚本，或 Excel 文件名英文段没填 | 跑 `gen-client-json.sh` / `gen-client-bin.sh`，确认文件名里有合法英文段 |
| 工具报错 `不支持中文表名` | 文件名的英文段写了中文 | 把那段改成纯英文，例如 `ItemConfig` 而非 `道具表` |
| `Get(id)` 返回 null | id 不在该表数据里 | 先用 `tables.TbXxx.GetAll()` 或直接读全部数据确认 id 是否存在 |
| 字段值是 key 而不是翻译后的文字 | 字段类型用了 `string` 而不是 `text` | 把表头第 2 行的类型从 `string` 改成 `text`，再重新生成 |

## 背景(可选)

`tables` 是 Luban 生成的总容器，每个 `TbXxx` 表对应一张 Excel；`text` 类型字段在读取时会经过当前语言的本地化映射，因此需要在 `Excels/Local/` 里配齐各语种的 key 翻译。
