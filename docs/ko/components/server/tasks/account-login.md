# 계정 로그인 구현(Account / Login 흐름)

이 페이지에서는 클라이언트가 시작하는 계정 로그인 메시지를 연결하여, `ReqPlayerLogin` 진입부터 캐릭터 데이터 저장까지의 최소한의 흐름을 완성하는 방법을 안내합니다. 완료 후 클라이언트는 `RespPlayerLogin`을 받고 게임 비즈니스에 진입하게 됩니다.

## 사전 조건

- `GameFrameX.Server` 게이트웨이와 센터 서버가 배포되어 있고, Actor 타입 `ActorTypeServer`를 사용할 수 있습니다.
- 데이터베이스에 `PlayerState` 테이블이 존재하며, 기본 키 필드는 `Id`입니다(로그인 메시지는 `Id`로 조회).
- 클라이언트가 `ReqPlayerLogin` 메시지를 보낼 수 있고, `RespPlayerLogin`을 받을 수 있습니다.
- 다음 네임스페이스를 참조했습니다: `GameFrameX.Apps.Account.Login.Component`, `GameFrameX.Apps.Account.Login.Entity`, `GameFrameX.Apps.Player.Player.Entity`, `GameFrameX.Monitor.Player`.

## 작업 단계

1. **센터 서버에 로그인 컴포넌트 등록**. `LoginComponent`는 `[ComponentType(GlobalConst.ActorTypeServer)]`를 통해 `ActorTypeServer`에 바인딩되어 계정/캐릭터 로그인을 담당하는 컴포넌트 역할을 합니다.

   ```csharp
   [ComponentType(GlobalConst.ActorTypeServer)]
   public sealed class LoginComponent : StateComponent<LoginState>
   {
       protected override bool IsCreateDefaultState { get; set; } = false;
   }
   ```

   Source: [GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L36-L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L36-L41)

2. **캐릭터 ID로 플레이어 조회 구현**. `LoginComponent`에 `OnPlayerLogin(ReqPlayerLogin)`을 노출하고, 내부에서 `GameDb.FindAsync<PlayerState>`를 사용하여 기본 키로 조회합니다. 매번 호출하기 전에 먼저 로그인 카운터를 기록합니다.

   ```csharp
   public async Task<PlayerState> OnPlayerLogin(ReqPlayerLogin reqLogin)
   {
       MetricsPlayerHelper.LoginCounterOptions.Inc();
       return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
   }
   ```

   Source: [GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47)

3. **Agent 작성으로 바인딩 및 전달 완료**. `LoginComponentAgent.OnPlayerLogin`은 다음을 담당합니다: 컴포넌트를 호출하여 플레이어를 조회하고, 플레이어 `Id`를 `NetWorkChannel`(키 이름 `GlobalConst.ActorIdKey`)에 기록한 다음, `ActorManager`를 통해 플레이어 Actor의 `PlayerComponentAgent`를 가져와 로그인을 실제 플레이어 컴포넌트에 넘깁니다.

   ```csharp
   public async Task OnPlayerLogin(INetWorkChannel workChannel, ReqPlayerLogin reqLogin, RespPlayerLogin response)
   {
       var playerState = await OwnerComponent.OnPlayerLogin(reqLogin);
       if (playerState == null)
       {
           //캐릭터를 찾을 수 없나요?
           return;
       }

       // 플레이어 ID 바인딩
       workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id);
       var playerComponentAgent = await ActorManager.GetComponentAgent<PlayerComponentAgent>(playerState.Id);
       await playerComponentAgent.OnPlayerLogin(workChannel, playerState, response);
   }
   ```

   Source: [GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58)

4. **메시지 핸들러 등록**. `ReqPlayerLoginHandler`는 `[MessageMapping(typeof(ReqPlayerLogin))]`으로 표시되고, `GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>`을 상속하며, `ActionAsync`에서 요청을 Agent에 직접 전달합니다.

   ```csharp
   [MessageMapping(typeof(ReqPlayerLogin))]
   internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
   {
       protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
       {
           await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
       }
   }
   ```

   Source: [GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L34-L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L34-L41)

5. **클라이언트에서 로그인 전송**. 클라이언트는 `ReqPlayerLogin` 프로토콜(`Id` 포함)에 따라 요청을 보내고 `RespPlayerLogin` 반환을 기다립니다. 이후 비즈니스 메시지는 플레이어 Actor에서 처리할 수 있습니다.

## 일반적인 변형

- **HTTP 로그인 진입점**: 저장소에는 HTTP 요청을 동일한 로그인 체인으로 변환하는 `GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs`가 있습니다. 프론트엔드가 TCP가 아닌 HTTP를 사용해야 할 때 직접 사용할 수 있습니다.
- **비활성화된 예제 코드**: `GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs`는 현재 전체가 `/* … */`로 주석 처리되어 있으며, 이전 버전 `ReqLogin` 구현의 참고 자료입니다. 실제 연동 시에는 `ReqPlayerLogin` 체인을 사용하십시오.

## 일반적인 오류

- **`playerState == null` 시 바로 반환**: 이 경우 `response`가 할당되지 않아 클라이언트가 계속 대기하거나 시간 초과됩니다. 반드시 Agent에서 비즈니스 프로토콜에 따라 `response`에 오류 코드를 기록하거나 명확한 예외를 발생시키십시오.
- **`workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id)` 누락**: 이후 메시지가 플레이어 Actor로 라우팅되지 않아 플레이어가 비즈니스 푸시를 받을 수 없습니다.
- **`IsCreateDefaultState = false`와 `PlayerState` 누락**: 플레이어가 처음 로그인하고 데이터베이스에 기록이 없을 때는 `OnPlayerLogin`에서 먼저 `PlayerState`를 생성해야 하며, 그렇지 않으면 항상 `null`을 반환합니다.

## 배경(선택)

- `LoginComponent`는 `ActorTypeServer`로 표시되어 있어, 로그인 로직이 센터 서버 Actor에서 실행되며 특정 플레이어 Actor와 결합되지 않음을 나타냅니다.
- `LoginComponentAgent`는 상태 컴포넌트 에이전트로, Actor 간 메시지를 `LoginComponent`로 수렴시킨 후 플레이어 ID에 따라 해당 `PlayerComponentAgent`로 전달하는 역할을 합니다.
