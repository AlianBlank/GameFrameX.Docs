# 시작 프로세스가 ProcedureLauncherState에서 멈추는 경우怎么办 → 어떻게 해야 하나요

`StartupRunner.RunAsync`가 이미 시작 체인을 `ProcedureLauncherState`까지 진행시켰지만, 화면이 나타나지 않고 프로세스가 `ProcedureGetGlobalInfoState`로 전환되지 않는 경우(전체 시작 Promise가 영원히 `Pending` 상태), 문제는 거의 대부분 FSM 블랙보드 데이터, UI 리소스 또는 `WebComponent` 초기화에 있습니다. 이 페이지에서는 빠른 진단과 해당 수정 단계를 제공합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 시작 후 검은 화면이 나오고, 로그에서 `ProcedureLauncherState` 진입만 보이며 `ChangeState<ProcedureGetGlobalInfoState>`가 실행되지 않음 | `BlackBoardKeys.StartupOptions` 또는 `BlackBoardKeys.StartupUIHandler`가 비어 있어 `OnEnter`가 조기 `return`함 | 아래 "수정 1: FSM 블랙보드 데이터 누락" 참조 |
| 시작 화면이 잠깐 나타났다 사라지거나 아예 나타나지 않고 시작 페이지에서 멈춤 | `IStartupUIHandler.StartAsync`가 예외를 throw하거나 중단됨 | 아래 "수정 2: UI Handler 시작 실패" 참조 |
| Launcher 단계까지 시작될 때 콘솔에 `WebComponent` 관련 Null 참조 오류 발생 | `GameEntry.GetComponent<WebComponent>()`가 `null`을 반환, Web 모듈이 등록되지 않음 | 아래 "수정 3: WebComponent 미등록" 참조 |
| 프로세스가 멈추고 `OnEnter`에 한 번도 진입하지 않음 | `procedureManager.StartProcedure<ProcedureLauncherState>()` 이전에 FSM에 데이터가 올바르게 주입되지 않았거나, `StartupOptions.LauncherUIResName` 경로 오류 | 아래 "수정 4: LauncherUIResName 리소스 경로 오류" 참조 |
| 시작 체인이 Launcher까지만 실행되고 `UniTaskCompletionSource`에 SetResult가 되지 않음 | 후속 Procedure가 Launcher 이후에 `SetResult`를 담당하며, Launcher 자체는 상태만 전환함 | 아래 "수정 5: 후속 Procedure 완료 대기" 참조 |

## 수정 단계

### 수정 1: FSM 블랙보드 데이터 누락

`ProcedureLauncherState.OnEnter`는 FSM 블랙보드에서 `StartupOptions`와 `IStartupUIHandler`를 읽으며, 둘 중 하나라도 `null`이면 메서드가 바로 `return`되어 상태를 전환하지도 않고 오류도 발생하지 않습니다:

```csharp
// 출처: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var options = optionsBox.Value as StartupOptions;
var uiHandler = uiHandlerBox.Value as IStartupUIHandler;

if (options == null || uiHandler == null)
{
    return; // 바로 종료되어 프로세스가 멈추고, 예외는 발생하지 않음
}
```

`StartupRunner.RunAsync`가 `StartProcedure<ProcedureLauncherState>`를 호출하기 전에 실제로 null이 아닌 `options`와 `uiHandler`를 전달했는지 확인하세요:

```csharp
// 출처: Runtime/Startup/StartupRunner.cs
procedureFsm.SetData(BlackBoardKeys.StartupOptions, optionsBox);
procedureFsm.SetData(BlackBoardKeys.StartupUIHandler, uiHandlerBox);
```

직접 시작 체인을 구성한 경우(`StartupRunner`를 사용하지 않은 경우), `StartProcedure<ProcedureLauncherState>()`를 호출하기 전에 동일한 key로 데이터를 주입해야 합니다. [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs)를 참조하세요.

### 수정 2: UI Handler 시작 실패

`OnEnter`는 `await uiHandler.StartAsync(options.LauncherUIResName)` 지점에서 실제로 UI 로드 완료를 기다립니다. `IStartupUIHandler` 구현에서 예외가 발생하면 예외가 `async void`에 의해 삼켜져 프로세스가 멈추고, 중단되는 경우(예: Addressables 리소스가 준비되지 않음)에도 마찬가지로 다음 상태로 전환되지 않습니다.

점검 순서:

1. 커스텀 `IStartupUIHandler.StartAsync` 진입점에 `try/catch`를 추가하여 최소한 예외를 로그에 출력하고, 실제로 예외가 발생하는지 확인하세요.
2. Editor에서 임시로 `LauncherUIResName`을 존재가 확인된 Prefab/Asset으로 지정하여 리소스 경로 오류를 배제하세요.
3. `UniTaskCompletionSource`를 사용한 경우, `StartAsync` 내부에서 `TrySetResult`가 호출되는지, `await`가 누락되지 않았는지 확인하세요.

### 수정 3: WebComponent 미등록

`ProcedureLauncherState`는 상태 전환 전에 `WebComponent`에서 Header를 읽고 써야 합니다. 모듈이 등록되지 않으면 `GameEntry.GetComponent<WebComponent>()`가 `null`을 반환하고, 다음 줄의 `webComponent.RemoveBaseHeader(...)`에서 즉시 NRE가 발생합니다:

```csharp
// 출처: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var webComponent = GameEntry.GetComponent<WebComponent>();
webComponent.RemoveBaseHeader(StartupProcedureUtility.GameFrameXApiKeyHeader);
// ...
```

`GameEntry`의 모듈 등록 프로세스에서 `WebComponent`가 컴포넌트 테이블에 추가되었는지, 그리고 런타임 호출 순서가 `StartupRunner.RunAsync` 실행보다 빠른지 확인하세요.

### 수정 4: LauncherUIResName 리소스 경로 오류

`options.LauncherUIResName`은 유효한 UI 프리팹 또는 리소스 주소를 가리켜야 합니다. 리소스가 존재하지 않으면 대부분의 `IStartupUIHandler` 구현은 능동적으로 실패하지 않고 "리소스 로드 대기" 무한 루프에 빠집니다. 검증 방법:

1. `StartupOptions` 생성 시 `LauncherUIResName`을 출력하여 Addressables Groups / Resources 디렉터리의 실제 키와 대조하세요.
2. 먼저 `EPlayMode.EditorSimulateMode` + 존재가 확인된 리소스로 시작 프로세스를 한 번 실행하여 빌드/그룹화 문제를 배제하세요.

### 수정 5: 후속 Procedure 완료 대기

`ProcedureLauncherState` 자체의 책임은 "시작 UI 로드 → 다음 상태로 전환"뿐이며, `UniTaskCompletionSource.SetResult`를 호출하지 않습니다. 관찰한 "멈춤"이 실제로 `StartupRunner.RunAsync`가 반환한 `UniTask<StartupResult>`가 계속 `Pending` 상태인 것이라면, `ProcedureGetGlobalInfoState` 및 후속 Procedure가 최종 성공/실패 시 `StartupProcedureUtility.GetCompletionSource(fsm).TrySetResult(...)`를 실행하는지 확인하세요.

[StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs)의 `GetCompletionSource` 구현을 참조하여 가져온 것이 `StartupRunner`가 `BlackBoardKeys.StartupCompletionSource`에 주입한 바로 그 `UniTaskCompletionSource`인지 확인하세요.

## 검증

수정 후 아래 순서대로 체인이 원활한지 확인하세요:

1. 시작 후 로그에서 `ProcedureLauncherState.OnEnter` 진입이 보이고, 직후 `ProcedureGetGlobalInfoState.OnEnter`도 진입하는지 확인하세요. 전자만 보이면 안 됩니다.
2. `StartupRunner.RunAsync`가 반환한 `UniTask<StartupResult>`가 합리적인 시간(보통 몇 초) 내에 완료되는지, 계속 `Pending` 상태에 머무르지 않는지 확인하세요.
3. 콘솔에 더 이상 `WebComponent` Null 참조 또는 UI 리소스 로드 실패 오류가 발생하지 않는지 확인하세요.
4. 커스텀 `IStartupUIHandler`를 사용한 경우, 중단점으로 `StartAsync`가 `LauncherUIResName`에 해당하는 리소스가 준비된 후 반환되는지, 반환 후 호출 스택이 `ProcedureLauncherState`의 `ChangeState<ProcedureGetGlobalInfoState>`로 돌아가는지 확인하세요.
