# 按标签批量管理定时器

用 `Add()` 创建定时器时传入 `tag` 字符串,之后即可用 `PauseByTag` / `ResumeByTag` / `RemoveByTag` / `HasTag` 四个方法一次操作同标签下的全部定时器,而不必逐个持有定时器 ID。

## 前置条件

- 场景中已存在 `TimerComponent` 组件(菜单路径 `GameFrameX/Timer`),它在 `Awake` 中通过 `GameFrameworkEntry.GetModule<ITimerManager>()` 拿到管理器。

## 操作步骤

1. 用 `Add()` 创建定时器,并把分组名传给第 5 个参数 `tag`。`tag` 默认为 `null`,只有显式传入的定时器才会进入该标签分组:

```csharp
using System;
using GameFrameX.Timer.Runtime;
using UnityEngine;

public class BattleScene : MonoBehaviour
{
    TimerComponent _timer;

    void Start()
    {
        // Add(interval, repeat, callback, callbackParam, tag, ...)
        _timer.Add(1f, 0, OnEnemyTick, null, "Battle");    // 每秒刷新,无限重复
        _timer.Add(5f, 10, OnBuffRefresh, null, "Battle"); // 每 5 秒一次,共 10 次
        _timer.Add(30f, 1, OnBossRoar, null, "Battle");    // 30 秒后触发一次
    }

    void OnEnemyTick(object param) { /* ... */ }
    void OnBuffRefresh(object param) { /* ... */ }
    void OnBossRoar(object param) { /* ... */ }
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

2. 需要整组暂停时调用 `PauseByTag`,暂停期间不累积时间:

```csharp
_timer.PauseByTag("Battle"); // 例如:打开暂停菜单时
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L152-L155)

3. 恢复时调用 `ResumeByTag`,从暂停处继续累积:

```csharp
_timer.ResumeByTag("Battle"); // 例如:关闭暂停菜单时
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L161-L164)

4. 分组结束时调用 `RemoveByTag` 一次性移除全部成员:

```csharp
_timer.RemoveByTag("Battle"); // 例如:战斗结束时统一清理
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L170-L173)

5. 用 `HasTag` 判断该标签下是否还有活跃定时器,再做后续逻辑:

```csharp
if (_timer.HasTag("Battle"))
{
    Debug.Log("战斗计时器仍在运行");
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L180-L183)

标签相关方法一览:

| 方法 | 签名 | 说明 |
|------|------|------|
| `PauseByTag` | `void PauseByTag(string tag)` | 暂停该标签下所有未删除的定时器 |
| `ResumeByTag` | `void ResumeByTag(string tag)` | 恢复该标签下所有定时器 |
| `RemoveByTag` | `void RemoveByTag(string tag)` | 移除该标签下所有定时器 |
| `HasTag` | `bool HasTag(string tag)` | 该标签下存在至少一个定时器时返回 `true` |

以上方法同时定义在 `ITimerManager` 接口与 `TimerComponent` 上,二者行为一致。

## 常见变体

- **只执行一次的任务也要归组**:`AddOnce` 与 `AddUpdate` 没有提供 `tag` 参数;若需要按标签管理,改用 `Add(interval, 1, callback, param, tag)` 等价实现单次触发。
- **按 ID 精确操作单个成员**:`Add()` 的返回值是定时器 ID,可配合 `Pause(int id)` / `Resume(int id)` / `Remove(int id)` / `IsPaused(int id)` 单独控制组内某一项,参见 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L105-L146)。

## 常见错误

- **标签传成了 `null` 或空串**:`Add` 的 `tag` 参数默认 `null`,漏传时定时器不会进入任何分组,后续 `PauseByTag` 等调用对其无效,但不会报错——调用一个没有成员的标签是安全的空操作。
- **以为 `RemoveByTag` 会触发 `onComplete`**:标签操作走的是与 `Remove(id)` 相同的移除路径([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)),只做移除,不要依赖其中的完成回调做场景切换等关键逻辑。
- **在回调内直接 `RemoveByTag` 当前标签**:实现中先把 ID 集合拷贝到临时列表再逐个移除以避免遍历中修改集合,因此可以安全在回调内调用;但仍建议把移除推迟到回调返回后,保持逻辑清晰。

## 背景

`TimerManager` 内部用 `_tags`(`tag -> ID 集合`)记录分组,`TimerItem` 上保存 `Tag` 字符串;所有标签操作都在 `lock (Locker)` 内完成,保证多线程下安全。`PauseByTag` 只对未删除的项生效并置 `IsPaused = true`,`ResumeByTag` 则无条件清除暂停标记,`HasTag` 只要 `ids.Count > 0` 即返回 `true`。关于定时器模块的整体结构,见《定时器组件概述》。
