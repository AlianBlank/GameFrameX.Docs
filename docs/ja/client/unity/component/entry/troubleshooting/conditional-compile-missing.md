# 条件コンパイルによって特定のサブシステムが使用できなくなった場合の対処法

`GameApp` 上の特定のサブシステム(`Network`、`GUI`、`Entity`、`Download` など)のプロパティにアクセスできない、「`GameApp` に XXX の定義が含まれていません」というエラーが表示される、または呼び出し時に null 参照エラーが発生する場合、通常は対応する条件コンパイルマクロが不足していることが原因で、`GameApp.XXX.cs` ファイル全体がコンパイル時に `#if … #endif` によって丸ごと除外されているだけで、実際にその API が存在しないわけではありません。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GameApp.Network`、`GameApp.GUI`、`GameApp.Entity` などのプロパティが見つからず、IDE で赤い波線が表示される | 対応する `ENABLE_GAME_FRAME_X_XXX` マクロが定義されておらず、`GameApp.XXX.cs` 全体が `#if … #endif` によって除外されている | *Project Settings → Player → Scripting Define Symbols* で不足しているマクロを追加するか、対応するサブモジュールパッケージをインストールする |
| `GameApp.XXX` を呼び出したときに返されるコンポーネントが `null` になる、またはメソッド呼び出しで `NullReferenceException` が発生する | マクロは定義済みでプロパティも存在するが、基盤となるコンポーネントが `GameEntry` に登録されていない | `GameEntry.RegisterComponent` のフローを確認し、対応する Runtime パッケージがインストールされ、起動していることを確認する |
| プラットフォーム(iOS/Android/Editor など)を切り替えた後に特定のサブシステムが突然使用できなくなる | 一部のマクロがプラットフォーム別のコンパイルに含まれている、またはマクロが特定のプラットフォーム向けにのみ定義されている | マクロが `UNITY_IOS`、`UNITY_ANDROID` などのプラットフォームマクロと連動して変化していないか確認する |

## 修正手順

### 1. 使用しているサブシステムを確認する

各サブシステムは `Runtime/GameApp.<Name>.cs` ファイルに対応しており、ファイルの先頭と末尾は同じマクロで囲まれています。以下は、リポジトリに現在存在するサブシステムと対応するマクロです:

| サブシステム | ファイル | 条件コンパイルマクロ |
|--------|------|------------|
| ネットワーク Network | `Runtime/GameApp.Network.cs` | `ENABLE_GAME_FRAME_X_NETWORK` |
| GUI(UGUI) | `Runtime/GameApp.GUI.cs` | `ENABLE_GAME_FRAME_X_L_UGUI` |
| エンティティ Entity | `Runtime/GameApp.Entity.cs` | `ENABLE_GAME_FRAME_X_ENTITY` |
| ダウンロード Download | `Runtime/GameApp.Download.cs` | `ENABLE_GAME_FRAME_X_DOWNLOAD` |
| グローバル設定 GlobalConfig | `Runtime/GameApp.GlobalConfig.cs` | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` |
| 広告 Advertisement | `Runtime/GameApp.Advertisement.cs` | `ENABLE_GAME_FRAME_X_ADVERTISEMENT` |
| Apple ログイン AppleLogin | `Runtime/GameApp.AppleLogin.cs` | `ENABLE_GAME_FRAME_X_APPLE_LOGIN` |
| Facebook ログイン | `Runtime/GameApp.FaceBookLogin.cs` | `ENABLE_GAME_FRAME_X_FACEBOOK_LOGIN` |
| Google ログイン | `Runtime/GameApp.GoogleLogin.cs` | `ENABLE_GAME_FRAME_X_GOOGLE_LOGIN` |
| QQ ログイン | `Runtime/GameApp.QQLogin.cs` | `ENABLE_GAME_FRAME_X_QQ_LOGIN` |
| WeChat ログイン | `Runtime/GameApp.WeChatLogin.cs` | `ENABLE_GAME_FRAME_X_WECHAT_LOGIN` |
| アプリ内課金 | `Runtime/GameApp.Payment.cs` | `ENABLE_GAME_FRAME_X_PAYMENT` |
| Mono ビヘイビア | `Runtime/GameApp.Mono.cs` | `ENABLE_GAME_FRAME_X_MONO` |
| Web ProtoBuf | `Runtime/GameApp.Web.ProtoBuff.cs` | `ENABLE_GAME_FRAME_X_WEB_PROTO_BUFF` |

> 命名には特例が 1 つあります:GUI サブシステムのマクロは `ENABLE_GAME_FRAME_X_GUI` ではなく、`ENABLE_GAME_FRAME_X_L_UGUI`(`L_` プレフィックス付き)です。表に記載されているマクロ名をそのまま追加してください。

### 2. Scripting Define Symbols に不足しているマクロを追加する

`Edit → Project Settings → Player` を開き、*Other Settings → Configuration → Scripting Define Symbols* に、前のステップで調べたマクロを追加します。複数のマクロはセミコロン `;` で区切ります。

```text
ENABLE_GAME_FRAME_X_NETWORK;ENABLE_GAME_FRAME_X_L_UGUI;ENABLE_GAME_FRAME_X_ENTITY
```

追加後、IDE に戻ってスクリプトの再コンパイルを一度実行します(`Assets → Reimport` または Editor の再起動)。これで IDE の赤い波線が消えます。

### 3. 対応する Runtime パッケージがインストール済みであることを確認する

マクロは単なるスイッチであり、実際の型(`NetworkComponent`、`UGUIComponent` など)は各サブモジュールの Runtime アセンブリから提供されます。以下は、マクロが有効になった場合にのみコンパイル対象となる `GameApp.Network.cs` で、`GameFrameX.Network.Runtime` に依存していることがわかります:

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Network.Runtime;
using GameFrameX.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// ネットワークコンポーネントを取得します。
    /// </summary>
    public static NetworkComponent Network
    {
        get
        {
            if (_network == null)
            {
                _network = GameEntry.GetComponent<NetworkComponent>();
            }

            return _network;
        }
    }

    private static NetworkComponent _network;
}
#endif
```

Source: [Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L56)

GUI サブシステムも同様です:

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
using GameFrameX.Runtime;
using GameFrameX.LUGUI.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// UIコンポーネントを取得します。
    /// </summary>
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }

            return _gui;
        }
    }

    private static UGUIComponent _gui;
}
#endif
```

Source: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

マクロを追加しても `NetworkComponent` / `UGUIComponent` などの型が見つからないというエラーが出る場合は、対応するサブモジュールパッケージが UPM/Package Manager 経由でインストールされていないことを意味します。`Window → Package Manager` を開いて対応するパッケージをインストールしてください。

### 4. 起動時にコンポーネントが `GameEntry` に登録されていることを確認する

`GameApp.XXX` の内部はすべて `GameEntry.GetComponent<XXXComponent>()` であるため、起動フローの中でこのコンポーネントが登録されている必要もあります。`GetComponent` が `null` を返す場合は、`GameEntry` の `RegisterComponent` 呼び出しチェーンに対応するコンポーネントを追加してください。

## 検証

1. IDE で `GameApp.Network`、`GameApp.GUI` などのプロパティが赤く表示されなくなる。
2. 実行時に `GameApp.Network` を呼び出しても `null` が返されなくなり、メソッド呼び出しで `NullReferenceException` がスローされなくなる。
3. 異なるターゲットプラットフォーム(Editor、iOS、Android)間でコンパイルを切り替えても、使用しているサブシステムがすべてのプラットフォームで利用可能である。
