# 打包后事件类型被裁剪失效怎么办

在 Editor 里运行正常，但用 IL2CPP 打包（尤其是开启 Managed Stripping Level Medium/High）后，事件触发没有回调、或通过类型名反射拿不到事件类型——这几乎都是托管代码裁剪把"只被字符串/反射引用"的事件类型删掉了。本模块核心类型已由 `GameFrameXEventCroppingHelper` 与 `[Preserve]` 保护，你自己的自定义 `EventArgs` 类型需要按下文补齐保护。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `Fire` 后订阅的回调不执行，Editor 下正常 | 自定义事件 `EventArgs` 类型被裁剪，`Type.FullName` 无法解析 | 步骤 1：给自定义事件类加 `[Preserve]` |
| `Utility.Assembly.GetType(componentType)` 拿不到实现类型，组件初始化失败 | 实现类型只被字符串引用，被 linker 裁掉 | 步骤 2：确认裁剪保护 Helper 存在于场景/程序集 |
| 首包/热更程序集里所有事件类型整体失效 | 整个程序集被裁剪 | 步骤 3：用 `link.xml` 全量保留程序集 |
| 不想逐个排查 | 仅想快速恢复可用 | 步骤 4：降低 Managed Stripping Level |

## 修复步骤

### 1. 给自定义事件类加 `[Preserve]`（推荐）

模块的事件基类本身就是这么保护的，仿照它给每个自定义事件类加特性：

```csharp
namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// 游戏逻辑事件基类。
    /// </summary>
    [UnityEngine.Scripting.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

事件 ID 依赖类型全名字符串（例如 `EmptyEventArgs` 内部使用 `typeof(EmptyEventArgs).FullName` 作为 `_eventId`），类型一旦被裁剪，订阅与触发的 ID 就对不上了，所以必须保证类型不被删。参见 [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L15-L21)。

### 2. 确认模块自带的裁剪保护 Helper 生效

模块内置了一个引用保护组件，打包时只要该程序集参与编译，核心类型就不会被裁剪：

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Event.Runtime
{
    [Preserve]
    public class GameFrameXEventCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(EventManager);
            _ = typeof(EventComponent);
            _ = typeof(GameEventArgs);
            _ = typeof(IEventManager);
        }
    }
}
```

Source: [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs#L1-L18)

排查时确认两点：

1. `GameFrameX.Event.Runtime` 程序集没有被整体裁掉（见步骤 3 的兜底方案）。
2. 你自己新增的类型不在上面的引用列表里，仍需按步骤 1 单独加 `[Preserve]`。

另外 `EventComponent` 在初始化时用 `Utility.Assembly.GetType(componentType)` 按字符串解析实现类型，这一步对裁剪最敏感，参见 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L67-L69)。

### 3. 用 `link.xml` 全量保留程序集（兜底）

在 `Assets` 下任意位置（例如 `Assets/StreamingAssets` 之外的普通目录）新建 `link.xml`，把运行时程序集整体保留，并把你的自定义事件所在程序集也加进来：

```xml
<linker>
  <assembly fullname="GameFrameX.Event.Runtime" preserve="all"/>
  <!-- 你的自定义事件类型所在程序集，按 asmdef 名称填写 -->
  <assembly fullname="YourGame.Logic" preserve="all"/>
</linker>
```

程序集名以仓库中的 asmdef 为准：运行时程序集文件为 `Runtime/GameFrameX.Event.Runtime.asmdef`，编辑器程序集为 `Editor/GameFrameX.Event.Editor.asmdef`。

### 4. 降低 Managed Stripping Level

`Project Settings → Player → Other Settings → Optimization → Managed Stripping Level` 调到 `Minimal` 或 `Low`，裁剪力度下降后多数"字符串引用被删"的问题会消失。代价是包体变大，建议仅用于快速验证根因是否为裁剪。

## 验证

1. 重新打真机包（Editor 不触发裁剪，必须用实际构建验证）。
2. 在场景里订阅一个事件并 `Fire`，确认回调执行。
3. 也可用事件计数接口做程序化验证：`EventManager` 提供 `EventHandlerCount`、`EventCount` 属性与 `Count(string id)` 方法，订阅成功后对应 ID 的处理器数量应大于 0。参见 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L54-L65) 与 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L98-L102)。

## 背景

本模块的事件以"类型全名字符串"为 ID，订阅、触发、组件实现解析都经过字符串/反射路径；IL2CPP 的托管 linker 只追踪静态可见引用，看不到这些动态引用，于是判定相关类型"未使用"并删除。`[Preserve]` 特性与 `link.xml` 都是向 linker 声明"此类型必须保留"的标准手段，`GameFrameXEventCroppingHelper.Start` 里的显式 `typeof(...)` 引用同理。
