# マルチエージェントスケジューリングとタスクライフサイクル

ダウンロードマネージャーは `TaskPool<DownloadTask>` を通じて複数のダウンロードエージェント(`DownloadAgent`)を同時に管理し、送信されたすべてのタスクは優先度順にキューイングされ、アイドル状態のエージェントに引き取られ、統一されたポーリングループ内で進行します。このページでは、エージェントがどのように作成・スケジューリングされるか、およびタスクがライフサイクルの中で経由する各状態とイベントについて説明します。

## クイックスタート

1. コンポーネント起動時に、`DownloadComponent` を通じて複数のダウンロードエージェントヘルパーを登録します(各ヘルパーは独立したエージェントに対応し、並行ダウンロードが可能です):

```csharp
// AddDownloadAgentHelper は new DownloadAgent(helper) および m_TaskPool.AddAgent(agent) を行います
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
```

Source: [DownloadManager.cs#L204-L213](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L204-L213)

2. `AddDownload(...)` を呼び出してタスクを送信すると、タスクは `TaskPool` の待機キューに入り、アイドル状態のエージェントによる引き取りを待ちます:

```csharp
int serialId = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/pkg.zip",
    downloadUri:  "https://example.com/pkg.zip",
    tag:         "asset",
    priority:    0);
```

Source: [DownloadManager.cs#L269-L296](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L269-L296)

3. フレームワークモジュールは毎フレーム `DownloadManager.Update` を呼び出し、内部で更新をタスクプールに転送します。エージェントがタスクを引き取った後、`IDownloadAgentHelper.Download` を呼び出して転送を開始し、処理中に `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` イベントを発生させます。

```csharp
// DownloadManager.Update -> m_TaskPool.Update(elapseSeconds, realElapseSeconds)
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_TaskPool.Update(elapseSeconds, realElapseSeconds);
    m_DownloadCounter.Update(elapseSeconds, realElapseSeconds);
}
```

## エージェントのスケジューリング

ダウンロードマネージャーは `AddDownloadAgentHelper` の際に各ヘルパーごとに独立した `DownloadAgent` を作成し、`TaskPool<DownloadTask>.AddAgent` を通じて登録します。`TaskPool` はエージェントのコレクションと待機キューの管理を担当し、アイドル状態にあるエージェントにのみタスクを割り当てます。

エージェントコレクションの主要な統計量とキュー状態はすべて `DownloadManager` を通じて公開されており、UI やデバッグパネルで直接読み取ることができます:

| 名称 | ソースプロパティ | 意味 |
|------|----------|------|
| 総エージェント数 | `TotalAgentCount` | 登録済みのダウンロードエージェントの総数 |
| アイドルエージェント数 | `FreeAgentCount` | 現在タスクを担っていないエージェント数 |
| ワーキングエージェント数 | `WorkingAgentCount` | ダウンロード中のエージェント数 |
| 待機タスク数 | `WaitingTaskCount` | キューに入ったがまだ引き取られていないタスク数 |
| 現在速度 | `CurrentSpeed` | `DownloadCounter` によって計算される瞬間速度(MB/s) |
| 一時停止フラグ | `Paused` | 一時停止するとエージェントは新しいタスクの引き取りを停止します |

Source: [DownloadManager.cs#L86-L142](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L86-L142)

スケジューリングの流れの概要：

1. エージェント登録:`AddDownloadAgentHelper` → `new DownloadAgent(helper)` → `m_TaskPool.AddAgent(agent)`。
2. タスク送信:`AddDownload` → `DownloadTask.Create` を構築 → タスクプールの待機キューに書き込み。
3. タスク引き取り：毎フレーム `TaskPool.Update` が待機キュー内の最も優先度の高いタスクをアイドル状態のエージェントに渡し、エージェントはその後 `IDownloadAgentHelper.Download(downloadUri, userData)` を呼び出します。
4. エージェント解放：エージェントは完了(成功または失敗)後、自身がアイドルとしてマークされ、タスクプールは次のラウンドで他の待機タスクを引き続き割り当てることができます。

> `TaskPool<T>` 内部の優先度比較と待機キューの実装については、GameFrameX ランタイムのソースコードを参照してください。本コンポーネントは `DownloadTask` と `DownloadAgent` の実装の提供のみを担当します。

## タスクライフサイクル

各ダウンロードタスクは `DownloadManager.DownloadTask` であり、`TaskBase` を継承し、`ReferencePool.Acquire<DownloadTask>()` を通じて作成され、`Clear()` の際にオブジェクトプールに返却されます。タスクには以下の状態があります:

| 状態列挙値 | 値 | 説明 |
|------------|------|------|
| `DownloadTaskStatus.Todo` | 0 | キューに入り、エージェントの引き取り待ち |
| `DownloadTaskStatus.Doing` | 1 | エージェントに引き取られ、転送中 |
| `DownloadTaskStatus.Done` | 2 | ダウンロード完了、ファイルがディスクに書き込まれた |
| `DownloadTaskStatus.Error` | 3 | ダウンロード失敗(タイムアウト、ネットワークエラーなど) |

Source: [DownloadManager.DownloadTaskStatus.cs#L39-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTaskStatus.cs#L39-L60)

`DownloadTask` が持つ主要なフィールド:

| フィールド | 型 | 意味 |
|------|------|------|
| `SerialId` | `int` | `s_Serial` による自動インクリメントで割り当てられ、毎回の `Create` で `++s_Serial` される |
| `DownloadPath` | `string` | ダウンロード完了後のファイルの保存パス |
| `DownloadUri` | `string` | 元のダウンロードアドレス |
| `FlushSize` | `int` | バッファをディスクに書き込む臨界サイズ(マネージャーのデフォルト値で上書きされる) |
| `Timeout` | `float` | ダウンロードタイムアウト秒数(マネージャーのデフォルト値で上書きされる) |
| `Priority` | `int` | タスクの優先度。数値が大きいほど前に配置される |
| `Tag` | `string` | タスクタグ。タグによる `TaskInfo` の一括クエリが可能 |
| `UserData` | `object` | `IDownloadAgentHelper.Download` にそのまま渡されるカスタムデータ |

Source: [DownloadManager.DownloadTask.cs#L39-L130](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs#L39-L130)

### ライフサイクルの各段階

1. **エンキュー**:`AddDownload` のオーバーロードが完全パラメータ版に入った後、`DownloadTask.Create(downloadPath, downloadUri, tag, priority, flushSize, timeout, userData)` によってタスクが作成され、初期状態は `Todo` となり、即座に `TaskPool` の待機キューに入ります。
2. **ディスパッチ**:`TaskPool.Update` がタスクをアイドル状態の `DownloadAgent` に渡します。エージェントは `OnDownloadAgentStart` コールバック内でタスク状態を `Doing` に切り替え、ローカルの `FileStream` を開きます。
3. **進行中**：エージェントは `IDownloadAgentHelper` の `DownloadAgentHelperUpdateBytesEventArgs` / `UpdateLength` を継続的に受信し、`m_DownloadedLength` と `m_SavedLength` を累積します。`m_WaitFlushSize` が `FlushSize` に達するとディスクに書き込み、同時に周期的に `m_WaitTime` を更新してタイムアウト判定に使用します。
4. **完了 / 失敗**：成功時には `DownloadAgentSuccess` が、失敗時(タイムアウトを含む)には `DownloadAgentFailure` が発生します。エージェントはストリームを閉じ、状態をクリーンアップし、タスク状態は `Done` または `Error` に設定され、`TaskPool` によるオブジェクトプールへの自動返却を待ちます。
5. **リソース回収**:`Clear()` はタスクのフィールドを `Todo`/空の値にリセットし、その後 `ReferencePool.Release` によってプールに戻され、次回の `Create` での再利用を待ちます。

| 名称 | シグネチャ | 説明 |
|------|------|------|

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| すべてのタスクが `WaitingTaskCount > 0`、`WorkingAgentCount = 0` のまま止まる | `AddDownloadAgentHelper` が呼ばれておらず、タスクプールにエージェントが1つもない | コンポーネント起動段階で必要に応じて少なくとも1つの `IDownloadAgentHelper`(UnityWebRequest / WWW 実装)を追加する |
| コンポーネント起動時に直ちに `Download agent helper is invalid.` がスローされる | `null` が渡されたか、オブジェクトが早期に解放された | 有効なインスタンスを渡すこと、かつ外部から早期に `Dispose` されないことを保証する |
| タスクが長時間 `Doing` のままになった後、失敗としてマークされる | `Timeout` の設定が短すぎる、または弱いネットワーク環境で `FlushSize` が大きすぎてバッファがディスクに書き込まれない | `DownloadManager.Timeout` / `DownloadManager.FlushSize` で調整するか、`AddDownload` のオーバーロードでタスクごとに上書きする |
| 複数のヘルパーを登録したのに並行数が依然として 1 | 同じヘルパーインスタンスを重複して登録したため、エージェントが基盤の接続を共有している | 各 `UnityWebRequestDownloadAgentHelper`/`WWWDownloadAgentHelper` インスタンスにつき `AddDownloadAgentHelper` を1回だけ呼び出す |

## 背景(オプション)

ダウンロードマネージャーは `GameFrameworkModule`(`Priority = 5`)であり、`Update` 内でスケジューリング権を完全に `TaskPool<DownloadTask>` に委譲します。このクラスは以下のみを担当します:

- ダウンロードエージェントのリストの管理(`AddDownloadAgentHelper` によって注入)。
- 各 `AddDownload` を `DownloadTask.Create(...)` に変換してタスクプールに渡すこと。
- エージェントの4つのイベント(`Start/Update/Success/Failure`)をリッスンし、統一されたイベントコールバックとして外部に公開すること。
- `DownloadCounter` を使用して、すべてのエージェントのバイト増分を統一された瞬間ダウンロード速度に換算すること。

タスクオブジェクト(`DownloadTask`)自体は `ReferencePool` によって管理され、エージェント(`DownloadAgent`)は `ITaskAgent<DownloadTask>` と `IDisposable` を実装します。これら2つの抽象化は `TaskPool` と対接するための契約であり、GameFrameX ランタイムのタスクスケジューリングサブシステムとの整合性を保つ部分でもあります。
