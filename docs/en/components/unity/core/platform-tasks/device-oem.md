# Switching Device Vendor Channels

Through the enable/disable items under the Unity editor menu `GameFrameX/Scripting Define Symbols/Device OEMs(设备厂商)`, you can switch the mini-game adaptation macro definitions for different device vendors (Huawei, OPPO, vivo, Xiaomi) for WebGL builds. Each time an option is enabled, the macros of other vendors are automatically disabled to avoid conflicts.

## Prerequisites

- The current build platform must be switched to **WebGL** (the menu item is wrapped by `#if UNITY_WEBGL` and will only appear on the WebGL platform).
- The framework version must include the following four scripts under the `Editor/MiniGame/DeviceOEMs` directory:
  - `MiniGameDefineSymbolHelper.Huawei.cs`
  - `MiniGameDefineSymbolHelper.OPPO.cs`
  - `MiniGameDefineSymbolHelper.Vivo.cs`
  - `MiniGameDefineSymbolHelper.Xiaomi.cs`

## Steps

1. In the Unity top menu, select **File → Build Settings**, switch the Platform to **WebGL**, and then close the Build Settings window.
2. In the Unity top menu, click **GameFrameX → Scripting Define Symbols → Device OEMs(设备厂商)**, and select the **Enable** item for the target vendor from the submenu. For example, to switch to Huawei mini-game, click:

   ```
   GameFrameX/Scripting Define Symbols/Device OEMs(设备厂商)/Enable Huawei Mini Game(开启[华为小游戏]适配)
   ```

3. Wait for the Console to show two log messages: `华为小游戏宏定义 [ENABLE_HUAWEI_MINI_GAME] 已经打开` and `华为小游戏宏定义 [HUAWEIMINIGAME] 已经打开`, indicating that the macros have been written to `scriptingDefineSymbols` in `ProjectSettings/ProjectSettings.asset`.
4. (Optional) Click the **Disable** item of the previously active vendor to verify the replacement took effect, for example, click **Disable OPPO Mini Game** under the same menu to check whether the macro has been removed.
5. After switching is complete, simply package with the WebGL platform to use the corresponding vendor's adaptation logic.

## Available Vendor Menu Items

| Vendor | Enable Menu Item | Enabled Macro Set | Priority |
|------|------------|-----------|--------|
| Huawei(华为) | Enable Huawei Mini Game | `ENABLE_HUAWEI_MINI_GAME`, `HUAWEIMINIGAME` | 3900 |
| Xiaomi(小米) | Enable Xiaomi Mini Game | `ENABLE_XIAOMI_MINI_GAME`, `XIAOMIMINIGAME` | 3800 |
| OPPO | Enable OPPO Mini Game | `ENABLE_OPPO_MINI_GAME`, `OPPOSMINIGAME` | 3700 |
| Vivo | Enable Vivo Mini Game | `ENABLE_VIVO_MINI_GAME`, `VIVOMINIGAME` | 3600 |

> Menu items with a larger priority number appear earlier in the menu; before enabling any vendor, the framework automatically calls `DisableOtherMiniGameScriptingDefineSymbols` to disable the macros of other vendors.

## Code Entry Point

Each vendor corresponds to a `partial` segment of `MiniGameDefineSymbolHelper`. The enable method is implemented as follows (using Huawei as an example):

```csharp
[MenuItem("GameFrameX/Scripting Define Symbols/Device OEMs(设备厂商)/Enable Huawei Mini Game(开启[华为小游戏]适配)", false, 3900)]
public static void EnableHuaweiMiniGame()
{
    DisableOtherMiniGameScriptingDefineSymbols(EnableHuaweiMiniGameScriptingDefineSymbol);

    foreach (var define in EnableHuaweiMiniGameScriptingDefineSymbol)
    {
        if (!ScriptingDefineSymbols.HasScriptingDefineSymbol(BuildTargetGroup.WebGL, define))
        {
            ScriptingDefineSymbols.AddScriptingDefineSymbol(define);
        }
        Debug.Log($"华为小游戏宏定义 [{define}] 已经打开");
    }
    EnableUnifiedMiniGameScriptingDefineSymbol();
}
```

## Common Variations

- **Temporarily reverting to non-mini-game WebGL**: Enter the same menu and click the corresponding vendor's **Disable …** item (e.g., `Disable Huawei Mini Game`) to remove all macros for that vendor; if all vendors have been disabled, `RefreshUnifiedMiniGameScriptingDefineSymbol` will also refresh the unified macros.
- **Batch switching via code**: You can directly call `MiniGameDefineSymbolHelper.EnableXXXMiniGame()` / `DisableXXXMiniGame()` in editor extensions without going through the menu.
- **Checking whether macros are in effect**: Open **Edit → Project Settings → Player → WebGL → Other Settings → Scripting Define Symbols** to confirm that the macros have been added or removed.

## Common Errors

- **Enable item not visible in the menu**: The current build platform is not WebGL, and the menu has been compiled out by `#if UNITY_WEBGL`. Switch to WebGL first before operating.
- **No log in Console after switching but macros haven't changed**: `ProjectSettings/ProjectSettings.asset` may be locked by version control or set to read-only. When the IDE prompts that saving fails, use operations within the editor instead of external modifications.
- **Enabling multiple vendors simultaneously causing compilation errors**: `DisableOtherMiniGameScriptingDefineSymbols` only executes when the menu is clicked. If you manually write multiple vendor macros in Project Settings, you need to ensure mutual exclusion in your own code, or click the Enable item again to let the menu flow clean them up for you.
- **Runtime platform after packaging is still PC**: Switching WebGL only affects the macro set and does not automatically change the Build Target output path. Confirm that WebGL is selected in Build Settings.
