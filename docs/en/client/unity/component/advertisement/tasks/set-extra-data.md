# How to Set Custom Extra Data

Call `IAdvertisementManager.SetExtraData(string key, string value)` to write key-value pair extension data before an ad is loaded. When the ad is loaded, these key-value pairs will be packaged into JSON and transparently passed to the server-side reward verification callback, used for business logic such as user identification and reward distribution matching.

## Prerequisites

- The `com.gameframex.unity.advertisement` package is installed, and `AdvertisementComponent` is attached in the scene.
- The advertisement manager has been initialized via `Initialize(AdvertisementConfig)`, and the extension data must be set **before the Load call**; otherwise, it will not be packaged into the request.

## Steps

1. **Get the Advertisement Manager Instance**

   Obtain the `IAdvertisementManager` of the current platform through `AdvertisementComponent`. All subsequent API calls go through this interface.

2. **Call SetExtraData Before Load**

   `SetExtraData` accepts a string key and a string value, and internally maintains a `Dictionary<string, string>` container; setting the same key repeatedly will overwrite the old value, and passing a `null` value will remove the key.

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   var mgr = GameFrameworkEntry.GetModule<IAdvertisementManager>();

   // Write the user identifier; the server can use it to match reward ownership
   mgr.SetExtraData("user_id", "10086");

   // Write the business tag
   mgr.SetExtraData("scene", "level_clear");

   // Passing null will remove the key
   mgr.SetExtraData("user_id", null);
   ```

   Source: [BaseAdvertisementManager.cs#L165-L189](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L165-L189)

3. **Load Ads by Platform**

   After Load is called, the manager will invoke the protected `SerializeExtraData()` to serialize the entire dictionary into JSON, and send it together with the Load request to the server. It returns `null` when there is no extra data.

   ```csharp
   // After Load, any changes made by SetExtraData will no longer be transparently passed
   mgr.Load(option);
   ```

   The implementation of `SerializeExtraData()` is as follows:

   ```csharp
   protected string SerializeExtraData()
   {
       if (ExtraData.Count == 0)
       {
           return null;
       }
       return Utility.Json.ToJson(ExtraData);
   }
   ```

   Source: [BaseAdvertisementManager.cs#L273-L282](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L273-L282)

4. **(Optional) Read Back After Loading**

   If a subclass needs to read back key-value pairs after verification, it can use the protected `GetExtraDataValue(string key)`, which returns `null` when the key does not exist.

   ```csharp
   // Only available in subclasses that inherit BaseAdvertisementManager
   var uid = GetExtraDataValue("user_id");
   ```

   Source: [BaseAdvertisementManager.cs#L292-L297](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L292-L297)

## Common Variants

- **Carry a Single Custom Data Segment During Play**: The `AdvertisementPlayOption.customData` field is used to transparently pass custom information during ad playback, and is an independent channel from the `extraData` field (which only takes effect during the Load phase).

  ```csharp
  var option = new AdvertisementPlayOption
  {
      OnSuccess = extra => { /* Reward distribution */ },
      customData = "level_id=42"
  };
  ```

  Source: [AdvertisementPlayOption.cs#L78-L84](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L78-L84)

- **Batch Key-Value Preset**: Write a batch of extension data at once when the game starts or after a successful login, and subsequent Load calls will automatically carry them.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The `extraData` received by the server is `null` | `SetExtraData` is called after the Load call; serialization happens inside Load, so subsequent writes will not enter the request | Place all `SetExtraData` calls before `Load` |
| The JSON received by the server is an empty object `{}` | No `SetExtraData` calls were made or all keys were removed by `null` values | Set at least one key-value pair; `SerializeExtraData()` returns `null` when the dictionary is empty |
| The set key does not take effect | The passed `key` is `null` or an empty string; `SetExtraData` returns directly | Ensure `key` is non-empty |
| Want to delete a key but it is still carried by the next Load | Used `SetExtraData(key, "")` to write an empty string, which will only be kept as an empty value | Use `SetExtraData(key, null)` to explicitly remove it |

## Background (Optional)

The extension data is stored in `BaseAdvertisementManager.ExtraData` (a protected `Dictionary<string, string>`), and is uniformly serialized into JSON by the framework during Load and transparently passed to the ad SDK's server-side reward verification callback; `AdvertisementPlayOption.extraData` is a field with the same name but a different purpose—the latter is only read during the Load phase, and writes made after loading are invalid.
