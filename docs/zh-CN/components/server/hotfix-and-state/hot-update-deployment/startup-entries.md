# 按入口加载热更(Main / Entry / GateWay / Heart)

GameFrameX.Server 把"按入口加载热更"拆成四个 partial 类文件,统一继承 `AppStartUpBase` 并以 `AppStartUpHotfixGame` 作为 partial 容器:`Main` 负责业务服务器网络层与消息分发、`Entry` 负责首启/重载与全局组件激活、`GateWay` 负责网关连接与心跳、`Heart` 负责客户端心跳回复。

## 入口文件一览

| 入口 partial | 文件 | 触发场景 |
|---|---|---|
| Main | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs` | `AppStartUpHotfixGame.StartAsync()`、`RunServer()`、`OnConnected`/`OnDisconnected`/`PackageHandler`、`StopAsync` |
| Entry | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs` | `OnLoadSuccess(setting, reload)`(首启与重载)、`Stop(message)` |
| GateWay | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs` | 与网关服务器建立 TCP 连接、断线重连、心跳维持、消息上行 |
| Heart | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByHeart.cs` | 客户端心跳消息 `ReqHeartBeat` 的解析与 `NotifyHeartBeat` 回复 |

四个文件通过 C# `partial class` 机制合成同一个 `AppStartUpHotfixGame`,无需额外注册。

## 启动顺序(代码中可直接对照)

1. `Entry.OnLoadSuccess(AppSetting setting, bool reload)` —— 拿到 `AppSetting`,判定是否热重载。
   - `reload == true`:`ActorManager.ClearAgent()` 后直接返回。
   - `reload == false`:走完整首启流程。
2. `Entry.Init(setting.ServerType, setting)` —— 初始化框架基础设施。
3. `Entry.RunServer()` → `Main.StartAsync()` —— 启动 SuperSocket 服务端,装配压缩/解压缩、HTTP 处理器与所有 TcpHandler。
4. `Entry` 启动 `QuartzTimer.Start()`、`GlobalTimer.Start()` 与 `ComponentRegister.ActiveGlobalComponents()`。
5. `Main.PackageHandler` 收到客户端消息时:心跳消息转交 `Heart.ReplyHeartBeat`,业务消息经 `HotfixManager.GetTcpHandler` 分发。

来源:[AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L37-L60) 与 [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L43-L65)。

## 各入口职责

### Main — 网络层与消息分发

`StartAsync()` 启动网络服务并装载 HTTP 处理器:

```csharp
public override async Task StartAsync()
{
    await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
        new DefaultMessageCompressHandler(),
        new DefaultMessageDecompressHandler(),
        HotfixManager.GetListHttpHandler(),
        HotfixManager.GetHttpHandler);
}
```

来源:[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L45-L52)

`RunServer(bool reload = false)` 每次都会 `ConfigComponent.Instance.LoadConfig()`;`reload` 时清理 Actor 后直接返回,否则进入 `StartAsync()`。

`PackageHandler` 中先将 `NetworkMessagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat` 的消息分流给 `ReplyHeartBeat`,其余按 `MessageId` 派发:

```csharp
if (messagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat)
{
    ReplyHeartBeat(netWorkChannel, (MessageObject)messagePackage.DeserializeMessageObject());
    return;
}
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
```

来源:[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L113-L135)

`OnConnected` 中通过 `SessionManager.Count()` 与 `Setting.MaxClientCount` 控制最大在线人数;`OnDisconnected` 通知 `RoomComponentAgent.MarkPlayerDisconnected`。

### Entry — 首启 / 重载

`OnLoadSuccess` 是热更框架调用的入口,负责区分"热重载"与"首次启动":

```csharp
public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
{
    if (reload)
    {
        ActorManager.ClearAgent();
        return true;
    }

    Init(setting.ServerType, setting);
    await RunServer();
    await QuartzTimer.Start();
    GlobalTimer.Start();
    await ComponentRegister.ActiveGlobalComponents();
    return true;
}
```

来源:[AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L39-L54)

`Stop(message)` 直接转发到 `Main.StopAsync(message)`,作为热更框架的停止回调。

### GateWay — 与网关通信

文件内含 `AsyncTcpSession _gatewayClient`、`_gateWayReconnectionTimer` 与 `_gateWayHeartBeatTimer`,在断线时由 `_gateWayReconnectionTimer` 触发重连,每次成功投递消息后 `_gateWayHeartBeatTimer.Reset()` 重置心跳计时器。

`SendToGatewayMessage` 是上行到网关的统一通道:连接已建立时调用 `_gatewayClient.TrySend(span)` 投递消息。

### Heart — 客户端心跳回复

`PackageHandler` 把心跳交给 `ReplyHeartBeat`,在 partial 文件里构造 `NotifyHeartBeat` 并写回通道:

```csharp
if (messageObject is ReqHeartBeat req)
{
    netWorkChannel.UpdateReceiveMessageTime();
    NotifyHeartBeat notifyHeartBeat = MessageObjectPoolHelper.Get<NotifyHeartBeat>();
    notifyHeartBeat.Timestamp = TimerHelper.UnixTimeMilliseconds();
    notifyHeartBeat.UniqueId = req.UniqueId;
    await netWorkChannel.WriteAsync(notifyHeartBeat);
}
```

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 热重载后旧业务逻辑仍在执行 | `OnLoadSuccess` 中 `reload == true` 分支忘记调用 `ActorManager.ClearAgent()` | 保持现有 `ClearAgent()` 调用,确保旧的 Actor 缓存被清空 |
| 客户端一直掉线、`NotifyServerFullyLoaded` 后被踢 | `Setting.MaxClientCount` 限制生效,新连接超过上限 | 在 `appsettings.json` 中调高 `MaxClientCount`,或排查异常连接 |
| `找不到[xxx][yyy]对应的handler` 日志 | `messagePackage.Header.MessageId` 没在 `HotfixManager` 注册 | 在对应热更模块的 Handler 注册表里补齐 `MessageId` |

## 背景(可选)

四个文件按"职责"而非"阶段"拆分是为了让 Main 的网络层与 Entry 的生命周期各占一个 partial,GateWay / Heart 这种横切关注点也独立成文件;所有 partial 合并为同一个 `AppStartUpHotfixGame` 后,基类 `AppStartUpBase` 与 `IHotfixBridge` 在编译期只需要一个类型入口,降低了热更框架的耦合面。
