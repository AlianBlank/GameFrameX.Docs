# 시작 완료 및 실패 이벤트 구독 방법

`StartupCompletedEventArgs`와 `StartupFailedEventArgs`를 통해 시작 프로세스가 완료되거나 실패할 때 알림을 받을 수 있으며, 씬 전환, 로딩 UI 해제, 지표 보고 또는 플레이어 재시도 안내 등에 활용할 수 있습니다.

## 사전 조건

- 프로젝트에 `GameFrameX.Startup.Runtime`이 이미 통합되어 있고, `GameEntry`를 통해 이벤트 컴포넌트 `EventComponent`를 가져올 수 있습니다.
- GameFrameX 이벤트 구독 패턴(`EventComponent.Subscribe`)에 익숙해야 합니다.

## 이벤트 ID 및 필드

| 이벤트 | EventId | 읽기 가능한 필드 | 트리거 시점 |
|------|---------|----------|----------|
| 시작 성공 | `typeof(StartupCompletedEventArgs).FullName` | 없음 | `ProcedureGameLauncherState`가 핫업데이트를 완료하고 UI를 Dispose한 후 |
| 시작 실패 | `typeof(StartupFailedEventArgs).FullName` | `FailedProcedureName`, `FailedUrl`, `ErrorMessage` | 어떤 Procedure에서든 네트워크 또는 비즈니스 실패로 프로세스가 중단될 때 |

`StartupFailedEventArgs.Create(procedureName, url, errorMessage)`는 `StartupProcedureUtility`에 의해 호출되며, `procedureName`은 실패가 발생한 Procedure의 상태 이름이고, `url`은 네트워크 실패가 아닌 경우 빈 문자열입니다.

## 작업 단계

### 1. 시작 성공 이벤트 구독

`GameEntry` 초기화가 완료된 후, 시작 프로세스가 시작되기 전에 `Subscribe`를 호출하고 핸들러를 `EventComponent`에 등록합니다:

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;
using GameFrameX.Startup.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupCompletedEventArgs.EventId,
    OnStartupCompleted);

static void OnStartupCompleted(object sender, GameEventArgs e)
{
    var args = e as StartupCompletedEventArgs;
    // 메인 씬 전환, 로그인 애니메이션 재생 등
}
```

`StartupCompletedEventArgs`에는 추가 필드가 없으므로 `Clear()`를 직접 호출하면 참조 풀로 반환됩니다.

소스: [StartupCompletedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupCompletedEventArgs.cs#L1-L38)

### 2. 시작 실패 이벤트 구독

실패 이벤트는 Procedure 이름, 마지막 실패 URL, 오류 설명을 담고 있어 UI 안내 및 보고에 적합합니다:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);

static void OnStartupFailed(object sender, GameEventArgs e)
{
    var args = (StartupFailedEventArgs)e;
    Debug.LogError($"启动失败 [{args.FailedProcedureName}] {args.FailedUrl} {args.ErrorMessage}");
    // 재시도 버튼 표시, 지표 보고
}
```

소스: [StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L1-L62)

### 3. 구독 해제

필요하지 않을 때 `Unsubscribe`를 호출하되 동일한 델리게이트 참조를 전달해야 합니다. 그렇지 않으면 `EventComponent`가 콜백을 계속 보유합니다.

```csharp
GameEntry.GetComponent<EventComponent>().Unsubscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);
```

## 일반적인 변형

- **실패만 모니터링하려는 경우**: `StartupFailedEventArgs.EventId`만 구독하고 성공 이벤트는 구독하지 않습니다.
- **동일한 콜백으로 성공/실패 처리**: `GameEventArgs e`에 대해 `is StartupCompletedEventArgs` / `is StartupFailedEventArgs` 분기로 판단합니다.
- **핫업데이트 계층에서 비즈니스 실패 판단**: `IHotfixLauncher.StartAsync`가 `Result.Success == false`를 반환하면 `ProcedureGameLauncherState`가 `CompleteFailure`를 호출하여 실패 이벤트를 트리거하고, `FailedProcedureName`을 `"ProcedureGameLauncherState"`로 고정하며 `FailedUrl`은 빈 문자열로 설정합니다.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 시작 완료 후 콜백이 트리거되지 않음 | 구독 시점이 너무 늦어 이벤트가 이미 Fire되었음 | `GameEntry` 시작 전 또는 엔트리 스크립트의 `Awake`에서 `Subscribe` 호출 |
| 실패 콜백에서 URL을 읽을 수 없음 | `StartupFailedEventArgs.FailedUrl`은 네트워크 관련 실패에만 값이 존재함 | `FailedProcedureName` + `ErrorMessage`로 폴백 안내 제공 |
| 콜백 수신 후 다시 구독하여 중복 트리거 발생 | 중복 제거를 하지 않았거나 두 번의 시작 모두에서 핸들러를 등록함 | `Unsubscribe` 후 다시 `Subscribe`하거나 `GameEntry` 재시작 시 일괄 정리 |
| 직접 `new StartupCompletedEventArgs()` 후 전송 | 이벤트는 프레임워크 내부에서 일괄적으로 Fire되므로 외부에서 트리거하면 안 됨 | 수동으로 Fire하지 말고 `EventComponent.Subscribe` 측에서만 소비 |

## 배경

두 이벤트는 모두 `StartupProcedureUtility.CompleteSuccess` / `CompleteFailure`에서 트리거됩니다:

- `CompleteFailure`는 `EventComponent.Fire(procedureOwner, StartupFailedEventArgs.Create(...))`를 호출합니다.
- `CompleteSuccess`는 `EventComponent.Fire(procedureOwner, StartupCompletedEventArgs.Create())`를 호출합니다.

이벤트 ID는 `typeof(X).FullName` 패턴을 따르며 GameFrameX 전체 제품군과 일관성을 유지합니다. 이벤트 객체는 참조 풀 `ReferencePool.Acquire`에서 획득하며, 프레임워크 내부에서 `Clear` 및 회수를 담당합니다.
