# What to Do When Compilation Fails Due to Uninstalled Dependent Sub-Packages

When `com.gameframex.unity.entry` references a sub-package (e.g., Network, UI, FairyGUI, Asset, Procedure, etc.) but that sub-package is not installed or has a version mismatch, the Unity console reports `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Xxx.Runtime' which is not in the project` or `The type or namespace name 'X' could not be found`, causing compilation to break. This page provides steps to locate the missing sub-package based on the error and restore compilation.

## Quick Diagnosis

| Symptom (console message) | Cause | Fix |
|---|---|---|
| `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Network.Runtime' which is not in the project.` | The `com.gameframex.unity.network` sub-package is not installed in the project | Install the corresponding dependency via Package Manager |
| `The type or namespace name 'GameApp' could not be found` | `com.gameframex.unity.entry` is not installed or was removed | Reinstall the entry package |
| Compilation error messages mention `GameFrameX.UI.Runtime`, `GameFrameX.Asset.Runtime`, `GameFrameX.FSM.Runtime`, etc., but these assemblies do not exist in the project | The corresponding optional sub-packages are missing (optional dependencies not installed) | Evaluate whether you need that subsystem; if not, remove references to it, otherwise install it |
| Sub-package installed but still reports `assembly references ... which is not in the project` | The sub-package version does not match the version range declared in `package.json` | Upgrade/downgrade the sub-package to the version required by the dependency list |
| Type-not-found errors only occur when a certain subsystem (e.g., ads, login) is enabled | The corresponding `versionDefines` macro is not enabled; the code is excluded by `#if` but the script is still loaded | Confirm that the macro is automatically injected once the sub-package is installed; if it still does not take effect, restart Unity and refresh Assets |

### 2. Install the Missing Sub-Package

Open Unity → `Window` → `Package Manager`, click the `+` button in the upper left corner → `Add package by name...`, then fill in the `name` and `version` from the table above and install. For example, to add Network:

1. Open Package Manager.
2. Select `Add package by name`.
3. Name: `com.gameframex.unity.network`, Version: `2.6.10`.
4. Click `Add` and wait for Unity to resolve and download.

After installation, Package Manager automatically writes to `Packages/manifest.json` and injects the corresponding `versionDefines` macros.

### 3. Handling Version Mismatches

The dependency versions specified in `package.json` are tested, compatible combinations. If you manually lock a lower/higher version, the assemblies referenced by the `asmdef` may not be found.

- Check the version of the corresponding package in `Packages/manifest.json` or `Packages/packages-lock.json`.
- Compare it with the `dependencies` field in `package.json` and align to the target version.
- If it is a Git URL reference (e.g., `com.gameframex.unity.network`), append `#2.6.10` to the URL to lock the tag.

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/package.json#L22-L42)

### 4. Simplified Approach When the Subsystem Is Not Needed

If you don't need a certain optional subsystem, you can avoid installing it while also preventing `GameFrameX.Entry.Runtime` from referencing the corresponding assembly. The specific approach is to stop triggering that path via `GameFrameX.Entry` in your own asmdef, or remove code references to that subsystem. `GameFrameX.Entry.Runtime.asmdef` automatically enables/disables code branches via `versionDefines` depending on whether the corresponding sub-package exists.

```text
Example: If you only use Procedure + UI + Network, just install
  com.gameframex.unity.procedure@1.4.0
  com.gameframex.unity.ui@2.11.0
  com.gameframex.unity.network@2.6.10
Other optional sub-packages (ads, login, analytics, XLua, etc.) do not need to be installed; the code is automatically stripped via macros.
```

### 5. Cleanup Steps If Errors Persist After Installation

1. Close Unity.
2. Delete `Library/ScriptAssemblies/` and `Library/PlayerScriptAssemblies/` in the project root directory.
3. Delete leftover caches related to the missing sub-packages under `Library/PackageCache/`.
4. Reopen Unity and wait for the initial import to complete.

After completion, the console should no longer show missing assembly messages.

## Verification

- No more `Assembly ... references ... which is not in the project` errors in the Unity Console.
- In `Window` → `Package Manager`, all sub-packages declared in `dependencies` show as `Installed`.
- In any script, `using GameFrameX.Entry.Runtime;` succeeds and static accessors such as `GameApp.Procedure` and `GameApp.Network` are accessible.

## Background (Optional)

The entry package `com.gameframex.unity.entry` centrally declares references to all subsystem assemblies via `GameFrameX.Entry.Runtime.asmdef`, and injects `ENABLE_GAME_FRAME_X_*` macros in `versionDefines` based on whether sub-packages exist, so that code sections of uninstalled sub-packages are excluded by `#if`, enabling on-demand compilation. The `dependencies` field of `package.json` is the single source of truth for version alignment — when compilation reports "assembly not found", check the versions here first rather than manually modifying the asmdef.
