# 전역 정보 인터페이스 가져오기 실패 시 대처 방법

시작 프로세스가 `ProcedureGetGlobalInfoState`에 진입한 후, 모든 `GlobalInfoUrls`에서 설정을 성공적으로 반환하지 못하고(사용 가능한 로컬 캐시도 없는 경우), `StartupFailedEventArgs`가 트리거되며 `ProcedureGetGlobalInfoState`가 실패 프로세스 이름으로 지정되어 시작이 종료됩니다. 이 문서에서는 일반적인 원인, 원인 파악 방법 및 해당 수정 방법을 설명합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 시작 시 즉시 `ArgumentException` 발생: `StartupOptions.GlobalInfoUrls must contain at least one URL.` | `StartupOptions.GlobalInfoUrls`가 `null` 또는 빈 배열임 | "수정 단계 1" 참조 |
| 프로세스가 전역 정보 요청을 건너뛰고 바로 `ProcedurePatchInit`으로 진입함 | `SkipRemoteStartupRequests = true`이거나 `GamePlayMode`가 `EditorSimulateMode` / `OfflinePlayMode`임 | "수정 단계 2" 참조 |
| 실패 이벤트 `StartupFailedEventArgs`에서 `procedureName = "ProcedureGetGlobalInfoState"`이고, UI에 `Loading... (n/total)`가 표시된 채 멈춤 | URL 장애 조치(failover)가 모두 실패함(네트워크/타임아웃/HTTP 오류/서버의 비성공 코드 반환) | "수정 단계 3" 참조 |
| 첫 번째 시도가 실패한 후에도 시작이 여전히 성공하며, UI에 `Using cached startup config...` 표시됨 | 이전에 성공한 결과가 `StartupNetworkCacheUtility`를 통해 캐시에 기록되어 있어, 이번에는 폴백 로직으로 진행함 | "수정 단계 4" 참조 |
| WebGL/싱글 플레이 환경에서 백엔드에 접근할 수 없어 시작이 네트워크 단계에서 멈춤 | 원격 시작 요청을 활성화하면 안 됨 | "수정 단계 2"의 `SkipRemoteStartupRequests` 사용법 참조 |

`procedureName`, `failedUrl`, `errorMessage` 세 필드는 [`StartupProcedureUtility.CompleteFailure`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L162-L167)에 의해 `StartupFailedEventArgs`에 기록되며, 정확한 원인 파악에 사용할 수 있습니다.

## 수정 단계

### 수정 단계 1: 빈 `GlobalInfoUrls`를 구성한 경우

`StartupRunner.Run`은 async 상태 머신에 진입하기 전에 동기적으로 검증합니다:

```csharp
// Runtime/Startup/StartupRunner.cs
if (options.GlobalInfoUrls == null || options.GlobalInfoUrls.Length == 0)
{
    throw new ArgumentException(
        "StartupOptions.GlobalInfoUrls must contain at least one URL.",
        nameof(StartupOptions.GlobalInfoUrls));
}
```

출처: [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L63-L68)

`StartupOptions` 에셋에 최소 한 개의 URL을 입력합니다:

```csharp
// Runtime/Startup/StartupOptions.cs
[Header("Network")] [Tooltip("전역 정보 인터페이스 URL 기본/보조 목록으로, 순서대로 시도합니다. 빈 배열은 구성 오류로 간주됩니다.")]
public string[] GlobalInfoUrls = new string[0];
```

출처: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### 수정 단계 2: 실행 환경에서 원격 요청을 보내면 안 되는 경우

`ProcedureGetGlobalInfoState.OnEnter`에는 세 개의 조기 종료 분기가 있으며, 그중 하나라도 충족되면 전역 정보 인터페이스를 건너뜁니다:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode)
{
    Debug.Log("Editor simulate mode, skip global info request.");
    ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
    return;
}

if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}

if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

출처: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L28-L48)

해당 처리:

| 시나리오 | 설정해야 할 값 | 비고 |
|------|--------|------|
| 에디터 시뮬레이션 모드 | `GamePlayMode = EPlayMode.EditorSimulateMode` | 에디터에서만 적용되며, 에디터가 아닌 환경에서는 `StartupRunner.NormalizeAssetPlayMode`가 `HostPlayMode`로 변경함 |
| 오프라인 모드 | `GamePlayMode = EPlayMode.OfflinePlayMode` | 바로 `ProcedurePatchInit`으로 진입하며, 더 이상 원격을 시도하지 않음 |
| WebGL 싱글 플레이 / 백엔드 없음 | `SkipRemoteStartupRequests = true` | 필드 설명은 [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31) 참조 |

### 수정 단계 3: URL 장애 조치 전체 실패

`GetGlobalInfoAsync`는 [`UrlFailoverRunner.ExecuteAsync`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L67-L92)를 통해 `GlobalInfoUrls`를 순서대로 시도하며, 각 URL당 내부적으로 최대 `MaxAttemptsPerUrl`회, 매 시도 간격은 `RetryDelayMs`밀리초입니다. HTTP 예외 또는 `responseGlobalInfo.IsSuccess == false`가 한 번이라도 발생하면 해당 시도는 실패로 간주됩니다:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var json = await GameEntry.GetComponent<WebComponent>().PostToString(url, jsonParams);
var responseGlobalInfo = json.Result.ToHttpJsonResultData<ResponseGlobalInfo>();
if (!responseGlobalInfo.IsSuccess)
{
    return UrlAttemptResult.Fail("Global info server returned code " + responseGlobalInfo.Code);
}
```

출처: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L75-L84)

다음 순서대로 점검합니다:

1. `StartupOptions`에 접근 가능한 URL을 최소 한 개 입력했는지 확인하고, "기본→보조" 순서로 배열합니다.
2. 브라우저/Postman에서 동일한 `jsonParams`(`StartupProcedureUtility.CreateHttpParams`로 생성)를 사용하여 해당 URL에 직접 `POST` 요청을 보내, 서버가 `IsSuccess == true`를 반환하는지 확인합니다.
3. `MaxAttemptsPerUrl`(기본값 3)과 `RetryDelayMs`(기본값 3000)가 너무 작아서 약한 네트워크 환경에서 시도 횟수가 조기에 소진되는지 확인합니다:

   ```csharp
   // Runtime/Startup/StartupOptions.cs
   public int MaxAttemptsPerUrl = 3;
   public int RetryDelayMs = 3000;
   ```
   출처: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L26-L28)

4. `IStartupHttpParamsProvider`에서 `PackageName` / `Channel` / `SubChannel` 등 공통 파라미터가 서버에서 올바르게 인식되는지 확인합니다. 누락 또는 오류로 인해 서버가 비성공 코드를 반환할 수도 있습니다.

### 수정 단계 4: 로컬 캐시 폴백 활성화

모든 URL이 실패하면 `GetGlobalInfoAsync`는 마지막으로 성공적으로 기록된 캐시를 읽어오려 시도합니다. 적중하면 시작을 계속 진행합니다:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (!result.Success)
{
    if (StartupNetworkCacheUtility.TryApplyCachedGlobalInfo())
    {
        uiHandler?.SetTipText("Using cached startup config...");
        ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
        return;
    }

    StartupProcedureUtility.CompleteFailure(
        procedureOwner,
        nameof(ProcedureGetGlobalInfoState),
        result.FailedUrl,
        result.ErrorMessage);
    return;
}
```

출처: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L94-L109)

- 캐시 키는 `GameFrameX.Startup.NetworkCache.GlobalInfo`이며, [`StartupNetworkCacheUtility`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupNetworkCacheUtility.cs#L23)가 관리합니다.
- 약한 네트워크 환경에서도 시작을 계속 진행하고 싶다면, 먼저 양호한 네트워크 환경에서 프로그램이 전체 프로세스를 한 번 실행하여 캐시를 기록하도록 한 뒤, 폴백 로직을 유지합니다.
- 캐시로 진행하는 대신 "네트워크 실패 시 즉시 오류를 보고"하기를 원한다면, 호출 측에서 `StartupResult`를 받았을 때 `ProcedureName == "ProcedureGetGlobalInfoState"`인지 명시적으로 판단하고 사용자에게 네트워크를 확인하도록 안내합니다.

## 검증

1. 앱을 다시 시작하여, 시작 프로세스가 더 이상 전역 정보 인터페이스 실패로 중단되지 않는지 확인합니다.
2. 시작 실패 시 `StartupFailedEventArgs`를 확인합니다: `procedureName`이 더 이상 `ProcedureGetGlobalInfoState`가 아니거나, 시작이 `Using cached startup config...` 경로를 통해 완료되어야 합니다.
3. `StartupOptions` 인스펙터([`StartupOptionsInspector`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Editor/StartupOptionsInspector.cs#L24-L66)가 드래그하여 정렬할 수 있는 UI 제공)에서 `GlobalInfoUrls`의 순서가 올바르고 빈 문자열이 없는지 확인합니다.
