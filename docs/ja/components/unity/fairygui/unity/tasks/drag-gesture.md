# ドラッグとジェスチャー操作

FairyGUI で UI コンポーネントにジェスチャー操作を追加する場合、`Runtime/Gesture/` ディレクトリ配下のジェスチャークラスを使用します:`SwipeGesture`(スワイプ)、`LongPressGesture`(長押し)、`PinchGesture`(ピンチによる拡大縮小)、`RotationGesture`(回転)。いずれも `EventDispatcher` を継承しており、イベントコールバックを通じてビジネスコードにジェスチャーデータを送出します。注意：本リポジトリでは、独立したドラッグジェスチャークラス(`DragGesture` や `DragDropManager` など)は**確認されていません**。ドラッグの要件がある場合は、コンポーネント(GObject)自体のドラッグインターフェースを参照してください。この部分は本ページで確認済みのソースコードの範囲外です。

## 前提条件

- 本パッケージが Unity プロジェクトにインポート済みであり、`Runtime/Gesture/` ディレクトリがパッケージと共にコンパイルされていること(`FairyGUI` 関連アセンブリ)。
- ジェスチャーのターゲットが FairyGUI の表示オブジェクト(例:`GComponent` 内のコンポーネント)であること。

2. ビジネススクリプトで対応するジェスチャーのインスタンスを構築し、ターゲットコンポーネントをホストとして設定します(コンストラクターの引数は対応するソースファイル内のコンストラクターの定義に従ってください)。

3. イベントコールバックでジェスチャーの開始/移動/終了を監視し、コールバック内でジェスチャーデータを読み取って UI またはロジックを更新します。各ジェスチャークラスのイベント定数名とコールバック引数の構造については、上の表のソースファイルを直接開いて確認してください——本ページのソースコード確認範囲は限られており、シグネチャを項目ごとに抜粋していないため、誤用を避けるためにここでは記述しません。

4. ジェスチャーが不要になったらインスタンスを解放し、コンポーネント破棄後もコールバックが発生し続けるのを防ぎます。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `DragGesture` / `DragDropManager` 型が見つからない | 本リポジトリの `Runtime/Gesture/` には上記 4 つのジェスチャークラスしかなく、検索してもドラッグクラスに一致するものはない | スワイプには `SwipeGesture` を使用;本格的な「持ち上げてドロップ」インタラクションは GObject のドラッグ関連インターフェースを確認してから使用すること |
| ジェスチャーが反応しない | ジェスチャーが正しいホストコンポーネントにバインドされていない、またはコンポーネントでタッチ操作が有効になっていない | 構築時に渡したターゲットコンポーネントを確認し、タッチイベントを受信できることを確認する |
| コールバック引数のフィールドを誤って使用 | イベントが保持するデータ構造は各ジェスチャーのソースファイルの定義に基づく | 対応するジェスチャーのソースファイルを開いてフィールドを確認してからコーディングする |

## 背景

ジェスチャークラスは `Runtime/Gesture/` 配下にあり、FairyGUI ランタイムの一部です。これらはマルチタッチ/ポインター入力を意味のあるイベント(スワイプ方向、ピンチ倍率、回転角度、長押し時間)に解析するため、ビジネス層はイベントを購読するだけでよく、自前で計算する必要はありません。ソースコード中にそのまま表示できる呼び出し例は見つからなかったため、本ページでは「クラス選択 → 構築 → 監視 → 解放」を実装の流れの主軸とし、シグネチャの詳細はソースファイルを唯一の根拠としています。
