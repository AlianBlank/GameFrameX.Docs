# イベントが受信できない、またはコールバックが発火しない

`EventComponent.Subscribe(DownloadXxxEventArgs.EventId, ...)` でサブスクライブした後、ダウンロードの開始・更新・成功・失敗の 4 種類のコールバックが一度も発火しない、または一部しか発火しない場合は、このページの診断表に従って調査してください。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 4 種類のイベントがすべて発火しない | `EventComponent` が `DownloadComponent` に注入されていない、または `DownloadComponent` がマウントされていない | 下記「EventComponent と DownloadComponent の確認」を参照 |
| `EventId` の書き間違い / 文字列リテラルを使用している | 各 `*EventArgs` クラスの `EventId` は `typeof(...).FullName` で生成されるため、スペルミスは一致しない | 下記「文字列ではなく EventId 定数を使用する」を参照 |
| サブスクライブは成功したが、実際にダウンロードが行われない | `AddDownload` の引数 `downloadPath` / `downloadUri` が空、または `Paused = true` で止まっている | 下記「タスクが実際にダウンロードキューに入ったことを確認」を参照 |
| Start しか受信できず、Success / Failure が受信できない | `DownloadAgentHelperCount` が 0 に設定されている、または `m_CustomDownloadAgentHelper` が未代入 | 下記「エージェントプールが起動していない」を参照 |
| `OnDownloadSuccess` 受信時に `args.SerialId` が一致しない | コールバック内ですべてのダウンロードタスクを同一のものとして処理している、またはサブスクライブ時に serialId をまだ保存していない | 下記「SerialId でタスクを区別する」を参照 |
| コルーチン終了 / シーン切り替え後にコールバックが失われる | サブスクライブしたオブジェクトが破棄されたが `Unsubscribe` されていない、または新しいシーンで `Subscribe` を複数回実行している | 下記「サブスクライブのライフサイクル管理」を参照 |

## 修正手順

### EventComponent と DownloadComponent の確認

イベントの伝達は両方のコンポーネントが同時に存在することに依存しています。`DownloadComponent` 内部は 1 つの `EventComponent` 参照のみを保持し、起動時に注入されます。欠けている場合、イベントは永遠にディスパッチされません。

```csharp
var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
var eventComponent = GameEntry.GetComponent<EventComponent>();
if (downloadComponent == null || eventComponent == null)
{
    Debug.LogError("DownloadComponent と EventComponent の両方が GameEntry にマウントされていることを確認してください");
}
```
[Runtime/Download/DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L62) では、`DownloadComponent` は `[GameFrameXAutoComponent(-4000)]` 自動登録コンポーネントであり、`EventComponent` は `com.gameframex.unity.event` 依存パッケージ由来です([package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json) を参照)。

### 文字列ではなく EventId 定数を使用する

すべての `*EventArgs` の `EventId` は `typeof(...).FullName` で生成されるため、静的フィールドを直接使用するのが最も確実です:

```csharp
eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComponent.Subscribe(DownloadStartEventArgs.EventId, OnDownloadStart);
eventComponent.Subscribe(DownloadUpdateEventArgs.EventId, OnDownloadUpdate);
```
4 つのイベント引数クラスのソースコード:
- [DownloadSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadSuccessEventArgs.cs#L39-L42)
- [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L40-L42)

`"GameFrameX.Download.Runtime.DownloadSuccessEventArgs"` のような文字列を手書きしないでください。名前空間やクラス名が変わると即座に不一致になります。

### タスクが実際にダウンロードキューに入ったことを確認

`AddDownload` は `int serialId` を返します。タスクが実際にエージェントにディスパッチされて初めて Start が発火し、完了して初めて Success/Failure が発火します。まず serialId を出力し、状態をポーリングして確認してください:

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);
Debug.Log($"serialId={serialId}");

TaskInfo info = downloadComponent.GetDownloadInfo(serialId);
Debug.Log($"status={info?.Status}, currentLength={info?.CurrentLength}");
```
`info == null` の場合、または `Status` がずっと `Waiting` の場合は、まず `downloadComponent.Paused` が `true` になっていないか確認してください。

### エージェントプールが起動していない

エージェント数が 0、またはカスタム Helper が空なのに `m_DownloadAgentHelperTypeName` が存在しない型を指している場合、タスクが待機キューに滞留し、コールバックが永遠に発生しません:

- Inspector で `Download Agent Helper Count` ≥ 1 を確認してください(デフォルトは 3、[DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60) を参照)。
- カスタム Helper を使用する場合は、`m_CustomDownloadAgentHelper` を入力するか、`m_DownloadAgentHelperTypeName` が有効な型名であることを保証してください。両方を同時に空にすることはできません。

### SerialId でタスクを区別する

コールバックはモジュール全体にブロードキャストされ、タスクを区別しません。必ず `args.SerialId` を自分で保存した serialId と比較してください:

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);

void OnDownloadSuccess(object sender, GameEventArgs e)
{
    var args = (DownloadSuccessEventArgs)e;
    if (args.SerialId == serialId)
    {
        // 今回自分が開始したタスクである
    }
}
```
ソースコードの例は [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/README.zh-CN.md#L113-L126) を参照してください。

### サブスクライブのライフサイクル管理

`EventComponent.Subscribe` が登録するのは強参照のコールバックで、`this` を保持します。サブスクライブしたオブジェクトが破棄された後も、イベントキューにはダングリング参照が残り、新しいシーンで `Subscribe` を複数回実行すると重複して発火します。以下を推奨します:

1. `OnDestroy` / `OnDisable` 内で `eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess)` を呼び出す。
2. グローバルで一度だけサブスクライブし、常駐マネージャーに配置する。`Start()` のたびに実行されるスクリプトには置かない。

## 検証

上記の手順で修正した後、小さなファイルのダウンロードを一度実行し、すべてのコールバックに `Debug.Log` を追加します:

```csharp
void OnDownloadStart(object sender, GameEventArgs e) =>
    Debug.Log($"Start serialId={(e as DownloadStartEventArgs).SerialId}");

void OnDownloadUpdate(object sender, GameEventArgs e) =>
    Debug.Log($"Update {((DownloadUpdateEventArgs)e).CurrentLength}");

void OnDownloadSuccess(object sender, GameEventArgs e) =>
    Debug.Log($"Success {(e as DownloadSuccessEventArgs).DownloadPath}");

void OnDownloadFailure(object sender, GameEventArgs e) =>
    Debug.LogError($"Failure {(e as DownloadFailureEventArgs).ErrorMessage}");
```

正常な場合、Start → いくつかの Update → Success の 4 種類のイベントが順番に一度ずつ出力され、Failure はエラー発生時のみ出力されます。
