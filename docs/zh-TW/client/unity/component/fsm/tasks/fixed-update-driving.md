# 如何在 FixedUpdate 中驅動 FSM

在 `FsmState<T>` 中覆寫 `OnFixedUpdate`，即可讓狀態機在 Unity 的物理幀（`FixedUpdate`）中運行。框架的 `FsmComponent` 會自動將 Unity 的 `FixedUpdate` 傳遞給所有已註冊的 FSM，因此無需手動呼叫。

## 前置條件

- 將 `FsmComponent` 附加到遊戲入口 GameObject 上（Add Component → `GameFrameX/FSM`）。框架會在 `Awake` 中取得 `IFsmManager`。
- 業務端已建立狀態機：`GameFrameworkFsm` 或 `FsmComponent.CreateFsm`。詳情請參閱 `FsmComponent.cs`。
- 已定義至少一個繼承自 `FsmState<T>` 的狀態類別。

## 操作步驟

1. 在狀態類別中覆寫 `OnFixedUpdate`，以接收物理幀的 `elapseSeconds` 與 `realElapseSeconds`。

```csharp
using GameFrameX.Fsm;

public class PlayerRunState : FsmState<Player>
{
    protected internal override void OnFixedUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // elapseSeconds 為 Time.fixedDeltaTime，realElapseSeconds 為 Time.fixedTime。
        var rb = fsm.Owner.GetComponent<Rigidbody>();
        rb.MovePosition(rb.position + fsm.Owner.MoveDirection * fsm.Owner.Speed * elapseSeconds);
    }
}
```

來源：[FsmState.cs#L75-L89](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L75-L89)

2. 建立狀態機時，將此狀態加入狀態集合，並讓 FSM 以該狀態啟動。

```csharp
var fsm = GameEntry.GetComponent<FsmComponent>().CreateFsm<Player>(
    owner: this,
    states: new FsmState<Player>[]
    {
        new PlayerIdleState(),
        new PlayerRunState(),
        new PlayerJumpState(),
    });

fsm.Start<PlayerRunState>();
```

3. 業務程式碼中不再需要撰寫 `Update`/`FixedUpdate` 的呼叫。`FsmComponent.FixedUpdate` 會將 `Time.fixedDeltaTime` 與 `Time.fixedTime` 傳遞給管理器：

```csharp
private void FixedUpdate()
{
    if (m_FsmManager == null) return;
    m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
}
```

來源：[FsmComponent.cs#L76-L84](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

4. 管理器層會對所有未被銷毀的 FSM 呼叫 `FixedUpdate`，最終路由至當前狀態的 `OnFixedUpdate`：

```csharp
public void FixedUpdate(float fixedDeltaTime, float fixedTime)
{
    // ...走訪 m_Fsms，對每個未被銷毀的 FSM 呼叫 FixedUpdate
}
```

來源：[FsmManager.cs#L110-L130](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L110-L130)

5. `Fsm<T>.FixedUpdate` 只會觸發當前狀態的回呼，其他狀態不會被執行：

```csharp
internal override void FixedUpdate(float elapseSeconds, float realElapseSeconds)
{
    m_CurrentStateTime += elapseSeconds;
    m_CurrentState.OnFixedUpdate(this, elapseSeconds, realElapseSeconds);
}
```

來源：[Fsm.cs#L682-L690](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L682-L690)

## 常見變體

- 若要在 `FixedUpdate` 中切換狀態，呼叫 `ChangeState<TState>()` 即可。切換時機應放在 `OnFixedUpdate` 內部，以避免與邏輯幀的 `OnUpdate` 相互干擾。
- 若也需要邏輯幀的行為，請覆寫 `OnUpdate`。兩個方法互不影響，會依照各自的幀率被呼叫。
- 將物理相關計算（施力、速度積分）放在 `OnFixedUpdate`，輸入回應與動畫參數放在 `OnUpdate`，時序會更加穩定。

## 常見錯誤

- **手動再次呼叫 `fsm.FixedUpdate(...)`**：`FsmBase.FixedUpdate` 是 `internal`，只能由管理器觸發。若業務端重複驅動，狀態會在一幀內推進兩次。
- **忘記呼叫 `Start<...>()`**：未啟動的 FSM 沒有 `CurrentState`，因此 `OnFixedUpdate` 不會被觸發，也不會發生錯誤。
- **在 `OnFixedUpdate` 中讀取 `Time.deltaTime`**：`elapseSeconds` 已固定為 `Time.fixedDeltaTime`，若讀取 `Time.deltaTime` 會引入邏輯幀的抖動。

## 背景（可選）

框架會將 Unity 的 `MonoBehaviour.FixedUpdate` 掛鉤到管理器，管理器再將物理幀時間廣播給所有 FSM。每個 FSM 只會將此回呼分派給當前的 `FsmState<T>`，從而實現「物理幀驅動 + 當前狀態回應」。`OnFixedUpdate` 與 `OnUpdate` 可以共存，前者由 `FsmComponent` 的 `FixedUpdate` 觸發，後者由 `Update` 觸發。兩者的參數含義不同，但呼叫進入點是對稱的。
