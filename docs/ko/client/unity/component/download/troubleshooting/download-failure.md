# 다운로드 실패 시 대처 방법: 오류 코드 및 콜백 문제 해결

`DownloadComponent`가 `DownloadFailureEventArgs` 또는 `DownloadAgentHelperErrorEventArgs`를 발생시키면 작업이 실패 상태입니다. 이 페이지는 오류 콜백의 필드를 기준으로 근본 원인을 빠르게 파악하고 수정하는 데 도움을 드립니다.

## 빠른 진단

| 증상(콜백 필드 값) | 근본 원인 | 한 줄 해결 방법 |
|---|---|---|
| `ErrorMessage`가 `"... 416 ..."`이며 `DeleteDownloading == true`(UnityWebRequest)이거나 `"416"`으로 시작(WWW) | HTTP 416 Range Not Satisfiable — 원격 서버가 요청한 바이트 범위를 지원하지 않음 | 아래 "416 Range 오류" 수정 단계 참조 |
| `ErrorMessage`가 비어 있지 않지만 416이 포함되지 않음 | 네트워크 계층 예외(타임아웃, DNS 실패, 연결 끊김, 프로토콜 오류 등) | 아래 "네트워크 계층 오류" 수정 단계 참조 |
| `DeleteDownloading == true`이고 `ErrorMessage`가 비어 있지 않음 | 작업이 작성한 파일을 삭제해야 하며 잔여 파일을 방지해야 함 | 아래 "실패 잔여 파일 정리" 수정 단계 참조 |
| 장시간 콜백이 없고 `WorkingAgentCount == TotalAgentCount` | 모든 Agent가 점유되어 새 작업이 대기 중 | 아래 "작업 멈춤" 수정 단계 참조 |

> 필드 정의는 [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L38-L88)와 [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L38-L116)를 참조하세요.

## 수정 단계

### 1. 실패 콜백 구독, 원본 정보 먼저 확보

`DownloadComponent.Awake` 이후의 이벤트 구독 위치에는 이미 `DownloadFailure`가 등록되어 있습니다. 처리 함수를 구현하고 이벤트 버스 또는 `IDownloadManager.DownloadFailure`를 통해 `DownloadFailureEventArgs`를 받기만 하면 됩니다:

```csharp
using GameFrameX.Download.Runtime;
using GameFrameX.Event.Runtime;

// 이벤트 버스를 통해 구독(권장, 컴포넌트와 결합 해제)
GameEntry.GetComponent<EventComponent>().Subscribe(
    DownloadFailureEventArgs.EventId,
    OnDownloadFailure
);

private void OnDownloadFailure(object sender, GameEventArgs e)
{
    var args = (DownloadFailureEventArgs)e;
    Debug.LogError($"[Download] FAIL serial={args.SerialId} path={args.DownloadPath} uri={args.DownloadUri} err={args.ErrorMessage} userData={args.UserData}");
}
```

출처: [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L80-L97)

### 2. 416 Range Not Satisfiable

이것은 프레임워크가 인식하는 "원격 서버가 이어받기 범위를 거부함" 신호입니다. 프레임워크의 판별 방식은 다음과 같습니다:

- UnityWebRequest 구현: `responseCode == 416`일 때 `DeleteDownloading = true`.
- WWW 구현: `error` 문자열이 `"416"`으로 시작할 때 `DeleteDownloading = true`.

출처: [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs#L44-L44) ; [UnityWebRequestDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/UnityWebRequestDownloadAgentHelper.cs#L240-L240) ; [WWWDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/WWWDownloadAgentHelper.cs#L248-L248)

수정 작업:

1. `DeleteDownloading == true`인 실패 콜백을 받은 후, 로컬에 남은 세그먼트 파일을 삭제합니다.
2. `DownloadComponent.AddDownload(url, tag, priority, userData)`를 다시 호출하면 프레임워크가 0부터 다시 다운로드합니다.
3. CDN/OSS가 `Range` 요청을 지원하지 않는다면 이어받기를 비활성화하거나 주소 계층에서 해당 파일 유형을 제외합니다.

### 3. 네트워크 계층 오류(타임아웃 / DNS / 연결 재설정)

`DownloadAgentHelperErrorEventArgs.ErrorMessage`는 Unity 네이티브 오류 문자열을 그대로 전달합니다. 예: `"Cannot resolve destination host"`, `"Request timeout"`, `"Connection failure"`.

수정 작업:

1. `DownloadComponent.Timeout`(기본 30초)을 필요에 따라 늘립니다. 예를 들어 공용 네트워크 파일을 60초로 변경: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60-L62) 참조.
2. 주소에 HTTPS가 필요한지, 프록시에 의해 차단되고 있는지 확인합니다.
3. 재시도 구현: `DownloadFailure` 콜백에서 동일한 URL의 다운로드 작업을 다시 큐에 넣습니다(재시도 횟수를 구분할 수 있도록 `UserData` 교체에 주의).

### 4. 실패 잔여 파일 정리

`DownloadAgentHelperErrorEventArgs.DeleteDownloading == true`이면 프레임워크가 로컬 분할 파일 정리를 권장합니다:

```csharp
private void OnAgentError(object sender, GameEventArgs e)
{
    var args = (DownloadAgentHelperErrorEventArgs)e;
    if (args.DeleteDownloading && !string.IsNullOrEmpty(localPath) && File.Exists(localPath))
    {
        File.Delete(localPath);
    }
}
```

출처: [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L67-L73)

### 5. 작업 멈춤(큐 적체)

장시간 `DownloadSuccess`를 받지 못하고 `DownloadFailure`도 트리거되지 않는다면, 보통 Agent가 가득 찬 경우입니다. 다음 속성을 모니터링하여 판단하세요:

| 속성 | 의미 |
|---|---|
| `DownloadComponent.TotalAgentCount` | 총 Agent 수, 기본 3 |
| `DownloadComponent.WorkingAgentCount` | 다운로드 중인 Agent |
| `DownloadComponent.WaitingTaskCount` | 대기 중인 작업 |
| `DownloadComponent.Paused` | 전역 일시 정지 여부 |

출처: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L78-L105)

수정:

1. Inspector에서 `Download Agent Helper Count`를 늘립니다.
2. 누군가 `DownloadComponent.Paused = true`로 설정한 뒤 복구하는 것을 잊지 않았는지 확인합니다.
3. `DownloadComponent.GetDownloadInfo(serialId)` / `GetDownloadInfos(tag)`로 현재 작업 상태를 확인합니다.

## 검증

다음 순서대로 문제가 해결되었는지 검증하세요:

1. 실패가 확실한 다운로드를 한 번 트리거하여(예: 잘못된 주소 입력 또는 고의로 네트워크 연결 끊기) `DownloadFailure` 콜백을 받는지, `ErrorMessage`가 예상과 일치하는지 확인합니다.
2. 416 시나리오에서는 콜백 후 로컬에 잔여 파일이 없는지, `AddDownload`를 다시 호출했을 때 전체 파일을 성공적으로 다운로드할 수 있는지 확인합니다.
3. 네트워크 타임아웃 시나리오에서는 `Timeout`을 줄여 한 번 재현한 다음, 새 타임아웃 값으로 성공할 때까지 재현합니다.
4. 일괄 다운로드를 한 번 실행하여 `WaitingTaskCount`가 합리적인 시간 내에 0이 되고 `FreeAgentCount`가 `TotalAgentCount`로 복구되는지 확인합니다.
