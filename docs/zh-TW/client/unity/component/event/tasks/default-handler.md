# 如何為無人處理的事件設定預設處理器

呼叫 `EventComponent.SetDefaultHandler` 註冊一個 `EventHandler<GameEventArgs>` 回呼後，任何被 `Fire` / `FireNow` 拋出但沒有訂閱者的事件都會落入這個回呼，而不是被靜默丟棄——常用於寫日誌、發出警報或進行漏網事件統計。

## 前置條件

- 場景中已存在掛載 `EventComponent` 元件的物件(事件功能已啟用)。
- 已瞭解基本的事件訂閱/拋出用法。

## 操作步驟

1. 撰寫一個簽章為 `EventHandler<GameEventArgs>` 的回呼方法，內部讀取 `e.Id` 即可取得事件編號：

```csharp
void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未處理的事件: {e.Id}");
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L145-L150)

2. 在初始化階段(如 `Start` 或模組入口)呼叫 `SetDefaultHandler` 註冊：

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L144-L145)

3. 拋出一個無人訂閱的事件進行驗證：

```csharp
// 捷徑:不需要自訂事件參數,內部用 EmptyEventArgs.Create(eventId) 包裝
eventComponent.Fire(this, "level_up");
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`Fire` 是執行緒安全的延遲分派——即使在工作執行緒拋出，回呼也會在下一幀的主執行緒執行；若希望預設處理器立即被呼叫，改用 `FireNow`(立即分派，僅限主執行緒)。

## 常見變體

| 需求 | 做法 |
|------|------|
| 替換預設處理器 | 再次呼叫 `SetDefaultHandler(newHandler)` 覆蓋舊的回呼 |
| 取消預設處理器 | 呼叫 `SetDefaultHandler(null)`,此後無人訂閱的事件重新變為靜默丟棄 |
| 帶自訂參數的事件走兜底 | `eventComponent.Fire(this, LevelUpEventArgs.Create(5))`,回呼中可將 `e` 向下轉型為具體參數型別 |
| 排查是誰拋出的事件 | 在回呼內記錄 `sender`(事件傳送者)並與 `e.Id` 一起上報 |

## 常見錯誤

- **回呼簽章不相符**:`SetDefaultHandler` 只接受 `EventHandler<GameEventArgs>`,寫成 `Action<string>` 或針對具體參數型別的處理器會編譯失敗。應先在具體處理器中處理已訂閱事件，預設處理器統一接收 `GameEventArgs`。
- **忘記預設處理器只兜底「無訂閱者」的事件**：如果該 `Id` 已有任何訂閱者，事件會正常分派給訂閱者，不會進入預設處理器。不要把預設處理器當作全域事件監聽器使用。
- **在工作執行緒誤用 `FireNow`**:`FireNow` 會立即分派且非執行緒安全，在子執行緒呼叫會產生未定義行為；子執行緒請使用 `Fire`。
- **預設處理器內部拋出例外**：回呼會在事件分派主流程中執行，例外會中斷分派；回呼內應做好例外捕捉。

## 背景

`EventComponent.SetDefaultHandler` 只是一層轉發，內部呼叫 `m_EventManager.SetDefaultHandler(handler)`,後者再把回呼交給底層事件池(`m_EventPool.SetDefaultHandler`)。分派時若某個事件編號沒有相符的處理器，事件池會轉而呼叫預設處理器，從而實現「未處理事件兜底」。
