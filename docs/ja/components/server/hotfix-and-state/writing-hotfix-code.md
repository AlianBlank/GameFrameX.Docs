# ホットアップデート可能なビジネスコードの作成（Hotfix 層の規範）

このドキュメントでは、`GameFrameX.Hotfix` アセンブリ内でホットリプレース可能なビジネスコードを作成し、フレームワークのブリッジおよび階層化の制約に従う方法について説明します。

## 前提条件

- `GameFrameX.Hotfix` アセンブリプロジェクトを作成済みであること（リポジトリ内の [GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj) を参照）。
- `GameFrameX.StartUp`、`GameFrameX.SuperSocket.*`、`GameFrameX.Apps.Common.Session` などの依存関係を参照していること。
- コンパイル時に `GameFrameX.Architecture.Analyzers` ルールセット（`GFX0004` など）が有効になっていること。

## Hotfix 層のコア規約

1. **ブリッジクラスは必ず `IHotfixBridge` を実装する**：ステータス層（Apps）とロジック層（Hotfix）間でブリッジする必要があるすべてのエントリクラスはこのインターフェースを実装する必要があり、クラスは `GameFrameX.Hotfix` アセンブリ内で定義する必要があります。`HotfixBridgeAssemblyAnalyzer` は `GFX0004` エラーでこのルールを強制します。
2. **エントリクラスには `partial` を使用する**：起動ライフサイクルが複数のファイル（`AppStartUpHotfixGameByEntry.cs`、`AppStartUpHotfixGameByMain.cs` など）に分散しているため、クラスは `partial` を維持する必要があります。そうしないと起動段階でコンパイルが失敗します。
3. **`HotfixHandler` マーカー型を維持する**：`HotfixHandler` は空の静的クラスであり、リフレクションで位置を特定するためにのみ使用されます。削除するとホットアップデート時にエントリが見つからなくなります。

## 操作手順

### ステップ 1：Hotfix アセンブリ内で起動ブリッジクラスを宣言する

`GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs` を新規作成または修正し、`partial` クラスを宣言して `IHotfixBridge` を実装します：

```csharp
using GameFrameX.StartUp;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge
{
    public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
    {
        if (reload)
        {
            ActorManager.ClearAgent();
            return true;
        }

        Init(setting.ServerType, setting);
        await RunServer();
        // 启动定时器
        await QuartzTimer.Start();
        GlobalTimer.Start();
        await ComponentRegister.ActiveGlobalComponents();
        return true;
    }

    public async Task Stop(string message = "")
    {
        await StopAsync(message);
    }
}
```

### ステップ 2：別のファイルでメッセージ配信とライフサイクルを拡張する

クラスが `partial` として宣言されているため、別のファイルで `StartAsync`、`PackageHandler`、`OnConnected`、`OnDisconnected`、`StopAsync` などのネットワークとライフサイクルのフックをオーバーライドできます：

```csharp
using GameFrameX.Apps.Common.Session;
using GameFrameX.SuperSocket.Connection;
using GameFrameX.SuperSocket.Server.Abstractions.Session;
using GameFrameX.SuperSocket.WebSocket.Server;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame
{
    public override async Task StartAsync()
    {
        await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
            new DefaultMessageCompressHandler(),
            new DefaultMessageDecompressHandler(),
            HotfixManager.GetListHttpHandler(),
            HotfixManager.GetHttpHandler);
    }

    protected override async ValueTask PackageHandler(IAppSession appSession, IMessage message)
    {
        if (message is NetworkMessagePackage messagePackage)
        {
            var netWorkChannel = SessionManager.GetChannel(appSession.SessionID);
            if (netWorkChannel.IsNull()) return;

            var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
            if (handler == null)
            {
                LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
                return;
            }

            try
            {
                await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
            }
            catch (Exception exception)
            {
                LogHelper.Fatal(exception);
            }
        }
    }

    public override async Task StopAsync(string message = "")
    {
        await base.StopAsync(message);
        await SessionManager.RemoveAll();
        await QuartzTimer.Stop();
        await ActorManager.AllFinish();
        await GlobalTimer.Stop();
        await ActorManager.RemoveAll();
    }
}
```

### ステップ 3：`HotfixHandler` マーカー型を削除しない

ホットアップデートフレームワークは、エントリマーカーとして `HotfixHandler` クラスをリフレクションで位置特定することに依存しています。メンバーを追加する必要はなく、そのまま保持してください：

```csharp
namespace GameFrameX.Hotfix;

/// <summary>
/// 该类文档用于处理热更新标记。不能删除。用于反射调用
/// </summary>
public static class HotfixHandler
{
}
```

Source: [HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8)

### ステップ 4：IHotfixBridge の実装が Hotfix アセンブリにあることを保証する

新しいブリッジ実装（例えば `MyHotfixBridge : IHotfixBridge`）を追加した場合、ファイルを `GameFrameX.Hotfix` プロジェクト内に配置する必要があります。そうしないと `HotfixBridgeAssemblyAnalyzer` が `GFX0004` を報告します：

```text
Type 'MyHotfixBridge' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not '<YourAssembly>'
```

Source: [HotfixBridgeAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs#L22-L44)

## よくあるバリエーション

- **ゲートウェイで起動**：`AppStartUpHotfixGameByGateWay.cs` でゲートウェイ側のオーバーライドを提供します。
- **ハートビートで起動**：`AppStartUpHotfixGameByHeart.cs` でハートビート側のオーバーライドを提供します。
- **リロードシナリオ（`reload == true`）**：`OnLoadSuccess` では `ActorManager.ClearAgent()` のみを呼び出して返し、ネットワークとグローバルコンポーネントを再初期化しないでください。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| コンパイル時に `Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix'` と報告される | `IHotfixBridge` の実装クラスが間違ったアセンブリに配置されている | そのクラスのファイルを `GameFrameX.Hotfix` プロジェクトに移動する |
| 起動時に「ホットアップデートエントリが見つからない」と報告される | `HotfixHandler` 静的クラスを誤って削除した | `public static class HotfixHandler {}` を再宣言する |
| `partial` エラーが発生し、`AppStartUpHotfixGame` の定義が見つからない | 新しいファイルで `partial` 修飾子の記述を忘れた | すべての部分クラスに `internal partial class AppStartUpHotfixGame` を追加する |
| ホットアップデート後に状態がクリアされない | `OnLoadSuccess(reload=true)` 分岐で `ActorManager.ClearAgent()` を呼び出していない | テンプレートに従って reload 分岐でまず Agent をクリアする |

## 背景（オプション）

`IHotfixBridge` はステータス層からロジック層を呼び出すためのブリッジ契約であり、その実装が `GameFrameX.Hotfix` アセンブリ内に存在することを制約します。これにより、ホットアップデート時にブリッジロジック全体を置き換えることが可能になります。アーキテクチャアナライザー `HotfixBridgeAssemblyAnalyzer` は `GFX0004` によりこのルールをコンパイル時に強制します。
