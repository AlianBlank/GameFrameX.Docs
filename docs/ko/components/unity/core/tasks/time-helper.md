# 시간 및 날짜 처리

`TimerHelper`는 프레임워크에서 제공하는 정적 시간 유틸리티 클래스로, partial class를 기반으로 여러 파일로 분할되어 Unix 타임스탬프, 시간대 설정, 일/월/주 단위의 시작/종료 및 차이 계산 등 일반적인 시나리오를 다룹니다. 이 문서에서는 바로 복사하여 사용할 수 있는 호출 방식을 제공합니다.

## 사전 조건

- 네임스페이스: `GameFrameX.Runtime`
- 대상 프로젝트에서 `GameFrameX.Runtime` 어셈블리를 참조함 ([GameFrameX.Runtime.asmdef](/Runtime/GameFrameX.Runtime.asmdef#L1-L20))
- 시간대 설정에는 .NET `TimeZoneInfo`가 필요합니다 (ID 문자열로 설정할 때 내부적으로 `TimeZoneInfo.FindSystemTimeZoneById` 호출)

## 작업 단계

### 1. 현재 시간 가져오기

필요에 따라 UTC 또는 로컬 시간을 가져옵니다. `GetNowWithUtc()`는 `DateTime.UtcNow`를 직접 반환하며, 로컬 시간은 `DateTime.Now`을 사용하거나 현재 시간대를 통해 변환합니다.

```csharp
using GameFrameX.Runtime;

// 현재 UTC 시간
DateTime utcNow = TimerHelper.GetNowWithUtc();

// 현재 UTC 시간 문자열, 기본값 "yyyy-MM-dd HH:mm:ss.fff K"
string utcStr = TimerHelper.CurrentDateTimeWithUtcFormat();

// 현재 UTC 시간의 HHmmss 정수 (예: 143045)
int utcInt = TimerHelper.CurrentTimeWithUtc();
```

Source: [TimerHelper.Current.UTC.cs](/Runtime/Time/TimerHelper.Current.UTC.cs#L21-L77)

### 2. Unix 타임스탬프 가져오기

정밀도에 따라 초 단위 또는 밀리초 단위를 선택합니다. 시간대 오프셋을 포함해야 하는 경우 `WithTimeZoneOffset` 변형을 사용합니다.

| 메서드 | 반환 | 설명 |
|------|------|------|
| `UnixTimeSeconds()` | `long` | 현재 UTC 시간의 초 단위 타임스탬프 |
| `UnixTimeMilliseconds()` | `long` | 현재 UTC 시간의 밀리초 단위 타임스탬프 |
| `UnixTimeSecondsWithTimeZoneOffset()` | `long` | UTC 타임스탬프 + 현재 시간대 오프셋 초 + `TimeOffsetSeconds` |
| `UnixTimeMillisecondsWithTimeZoneOffset()` | `long` | UTC 타임스탬프 + 현재 시간대 오프셋 밀리초 + `TimeOffsetMilliseconds` |

```csharp
long sec  = TimerHelper.UnixTimeSeconds();          // 초 단위
long ms   = TimerHelper.UnixTimeMilliseconds();     // 밀리초 단위
long sec2 = TimerHelper.UnixTimeSecondsWithTimeZoneOffset();
```

### 3. 시간대 설정 및 읽기

ID 문자열로 설정합니다 (예: `"China Standard Time"`, `"UTC"`). `TimeZoneInfo` 객체를 전달할 수도 있습니다. ID가 유효하지 않으면 메서드는 `false`를 반환하고 UTC로 폴백합니다.

```csharp
// ID로 설정
bool ok = TimerHelper.SetTimeZone("China Standard Time");

// TimeZoneInfo로 설정
TimerHelper.SetTimeZone(TimeZoneInfo.Utc);

// 현재 시간대 읽기
TimeZoneInfo tz = TimerHelper.CurrentTimeZone;
```

Source: [TimerHelper.cs](/Runtime/Time/TimerHelper.cs#L51-L100)

### 4. Unix 타임스탬프와 DateTime 상호 변환

타임스탬프(초/밀리초)를 `DateTime`으로 변환하거나 그 반대로 변환합니다. 변환은 `EpochUtc = 1970-01-01 00:00:00 UTC`를 기준으로 합니다.

```csharp
long ts = TimerHelper.UnixTimeSeconds();

// 방법 1: .NET 네이티브 API 사용
DateTime dt = DateTimeOffset.FromUnixTimeSeconds(ts).UtcDateTime;

// 방법 2: 프레임워크에서 제공하는 Ticks 값 사용
long ticks = TimerHelper.TimestampToTicks(ts);          // 초 -> Ticks
DateTime dt2 = new DateTime(ticks, DateTimeKind.Utc);

// 역방향: DateTime -> Unix 타임스탬프 (초)
long back = new DateTimeOffset(dt2).ToUnixTimeSeconds();
```

`TimestampToTicks`는 `-62135596800`에서 `253402300799` 초 범위를 허용하며, 범위를 벗어나면 `ArgumentOutOfRangeException("Timestamp is out of valid range")`이 발생합니다.

Source: [TimerHelper.Timestamp.cs](/Runtime/Time/TimerHelper.Timestamp.cs#L96-L105)

### 5. 일 / 주 / 월 단위의 시작/종료 및 차이

`Runtime/Time/` 아래에 파일별로 분할된 `Current`, `Day`, `Week`, `Month`, `Difference`, `Range`, `TimeOffset` 등의 그룹화된 메서드가 제공됩니다. 동일한 기능에 세 가지 세트가 있습니다: UTC, 로컬(Local), `CurrentTimeZone` 기준. 예를 들어:

- `TimerHelper.Day.cs` / `TimerHelper.Day.UTC.cs` / `TimerHelper.Day.TimeZone.cs`
- `TimerHelper.Month.cs` / `TimerHelper.Month.UTC.cs` / `TimerHelper.Month.TimeZone.cs`
- `TimerHelper.Week.cs`
- `TimerHelper.Difference.cs` / `TimerHelper.Difference.UTC.cs` / `TimerHelper.Difference.TimeZone.cs`
- `TimerHelper.Range.cs`
- `TimerHelper.TimeOffset.cs` / `TimerHelper.TimeOffset.UTC.cs` / `TimerHelper.TimeOffset.TimeZone.cs`

호출 시 파일명의 접미사에 맞춰 시나리오를 선택하면 됩니다 (`.UTC`는 UTC 사용, `.TimeZone`은 `CurrentTimeZone` 사용, 접미사 없음은 로컬 시간 사용).

## 일반적인 변형

- **시간대 오프셋을 포함한 타임스탬프**: 비즈니스 로직에서 "동팔구 시간대 시간"을 "UTC+0"으로 표시해야 할 때 `UnixTimeSecondsWithTimeZoneOffset()` / `UnixTimeMillisecondsWithTimeZoneOffset()`을 사용합니다. 이는 표준 UTC 타임스탬프에 `CurrentTimeZone`의 오프셋과 `TimeOffsetSeconds/Milliseconds`를 더합니다.
- **시간 형식 사용자 정의**: `CurrentDateTimeWithUtcFormat(string format)`에 .NET 표준 날짜 형식 문자열을 전달합니다 (예: `"yyyy/MM/dd"`, `"HH:mm"`).
- **지정된 시간을 타임스탬프로 변환**: `DateTimeToSecondsWithTimeZone(DateTime time)`은 임의의 `DateTime`을 받아 현재 시간대를 기준으로 계산합니다. `Kind == Unspecified`인 경우 `CurrentTimeZone`으로 해석합니다.

## 일반적인 오류

- **시간대 ID 오타**: `SetTimeZone(string)`은 ID가 유효하지 않을 때 예외를 발생시키지 않고 `false`를 반환한 후 UTC로 폴백합니다. 반드시 반환 값을 확인하여 조용한 폴백을 방지하세요.
- **타임스탬프 범위 초과**: `TimestampToTicks` / `TimestampMillisToTicks`는 `DateTime`의 유효 범위 내 값만 허용하며 (약 `-62135596800`에서 `253402300799` 초), `long.MaxValue`를 전달하면 `ArgumentOutOfRangeException`이 발생합니다.
- **`EpochLocal`과 `EpochUtc` 혼동**: `EpochLocal`은 항상 시스템 로컬 시간대를 기준으로 하며 `SetTimeZone`의 영향을 받지 않습니다. UTC 변환이 필요한 경우 `EpochUtc`를 사용하세요.
- **다중 스레드에서 시간대 변경**: `_currentTimeZone`은 가시성을 보장하기 위해 `volatile`로修饰되어 있지만, 전환 순간 스레드 간에 읽히는 시간대가 일치하지 않을 수 있습니다. 높은 빈도로 전환하는 경우 잠금을 고려하세요.

## 배경

`TimerHelper`는 `partial class`를 사용하여 동일한 이름의 클래스를 `Runtime/Time/` 아래 여러 파일로 분할하며, "능력 × 시간대"로 구성됩니다 — 능력 차원(Current / Timestamp / Day / Week / Month / Difference / Range / TimeZone)이 파일 접두사로, 시간대 차원(UTC / TimeZone / 기본 Local)이 파일 접미사로 사용됩니다. 모든 메서드는 Unity의 코드 스트립(trimming)을 방지하기 위해 `[Preserve]`로 표시되어 있습니다.
