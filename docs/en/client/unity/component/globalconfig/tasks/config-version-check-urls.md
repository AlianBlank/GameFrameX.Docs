# How to Configure the Application and Resource Version Check URLs

`GlobalConfig` returns the application version check URL and the resource version check URL through a server-delivered global configuration object. The front-end only needs to consume the two fields `CheckAppVersionUrl` and `CheckResourceVersionUrl` to initiate the corresponding version check requests.

## Prerequisites

- The `com.gameframex.unity.globalconfig` package has been installed and the entry component has been registered.
- The business side has deployed an interface that returns global information, and the interface JSON contains the `CheckAppVersionUrl` and `CheckResourceVersionUrl` fields.
- The client can access the host server address of that interface (see the `ResponseGlobalInfo.HostServerUrl` field).

## Steps

1. In the response JSON of the server's global information interface, ensure that both URL fields are returned, and that the field names exactly match the client model:

   ```json
   {
     "CheckAppVersionUrl": "https://your-cdn.example.com/api/app/version",
     "CheckResourceVersionUrl": "https://your-cdn.example.com/api/resource/version"
   }
   ```

2. After the client parses this JSON, directly read the two string properties of `ResponseGlobalInfo`. Both properties are of type `string`, with a default value of `null`.

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;

   var info = new ResponseGlobalInfo
   {
       CheckAppVersionUrl      = "https://your-cdn.example.com/api/app/version",
       CheckResourceVersionUrl = "https://your-cdn.example.com/api/resource/version",
       HostServerUrl           = "https://your-cdn.example.com",
       AOTCodeList             = "[]",
       Content                 = "{}"
   };
   ```

   Source: [Runtime/GlobalConfig/ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L1-L28)

3. Pass the obtained URLs to the application version check and resource version check modules respectively, and create the corresponding request objects:

   ```csharp
   // Application version check request
   var appVersionReq = new RequestGameAppVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAppVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAppVersion.cs)

4. The resource version check uses an independent request object, with the same basic fields such as platform, channel, and language:

   ```csharp
   var assetReq = new RequestGameAssetPackageVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs)

5. When processing the application version check request, the server returns `ResponseGameAppVersion`, which contains upgrade information such as `IsForce`, `IsUpgrade`, `AppDownloadUrl`, `UpdateAnnouncement`, and `UpdateTitle`:

   ```csharp
   public class ResponseGameAppVersion
   {
       public bool   IsForce           { get; set; }
       public string AppDownloadUrl    { get; set; }
       public bool   IsUpgrade         { get; set; }
       public string UpdateAnnouncement{ get; set; }
       public string UpdateTitle       { get; set; }
   }
   ```

   Source: [Runtime/GlobalConfig/ResponseGameAppVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGameAppVersion.cs#L1-L33)

## Common Variations

- **Shared URL**: If the application and resource version checks share the same gateway, you can have both URLs return the same address, and let the gateway route by path internally.
- **Gray Release with Separate Servers**: When different channels (`Channel`) use different URLs, the server side can return the corresponding address based on the `Channel` field in the request body, and the client code remains unchanged.

## Common Errors

- **Misspelled Field Names**: The interface field names must be `CheckAppVersionUrl` and `CheckResourceVersionUrl`, with capital first letters and camelCase naming. Otherwise, after `ResponseGlobalInfo` is deserialized, both properties will be `null`.
- **HTTPS Not Ready**: The URL must use HTTPS, otherwise it will be blocked by the default network policy on Android 9+.
- **Forgot to Configure the Host Address**: `CheckAppVersionUrl` only carries a relative path or subdomain. The actual entry point also requires `ResponseGlobalInfo.HostServerUrl`; otherwise the request will not be able to find the host.

## Background (Optional)

`ResponseGlobalInfo` is the simplest DTO defined by the GlobalConfig package. Its sole responsibility is to "tell the client the addresses". The package does not include a built-in HTTP client. The actual requests and caching are initiated by upper-level business modules based on `RequestGameAppVersion` / `RequestGameAssetPackageVersion`, and are decoupled from the global configuration, making it easy to integrate with different network stacks.
