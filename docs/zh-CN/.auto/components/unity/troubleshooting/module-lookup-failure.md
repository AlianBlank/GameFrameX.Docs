# 模块查找失败怎么办

调用 `GameFrameX.Runtime.GameFrameworkEntry.GetModule<T>()` 查找模块时，框架会按接口名通过反射定位实现类；查找过程会因为接口约束、命名规则、自动注册失败等原因抛 `GameFrameworkException`。本页按异常消息列出根因与修复步骤。

## 快速诊断

| 症状（异常消息原文） | 根因 | 修复 |
|---|---|---|
| `You must get module by interface, but 'X' is not.` | 泛型 `T` 不是接口，框架强制使用接口获取 | [改成传接口类型](#修复1-必须用接口获取) |
| `You must get a Game Framework module, but 'X' is not.` | 传入的接口未以 `GameFrameX.` 命名空间开头 | [修正命名空间](#修复2-命名空间必须以-gameframex-开头) |
| `Can not find Game Framework module type 'X.Y.Z'.` | 自动按命名约定查不到实现类，需要显式注册 | [调用 RegisterModule 或补上实现类](#修复3-找不到模块实现类) |
| `You must register module by interface, but 'X' is not.` | `RegisterModule` 的第一个参数传成了类 | [传入接口类型](#修复4-注册时第一个参数必须是接口) |
| `You must register module by Class and not Interface and Abstract, but 'X' is not.` | 第二个参数不是具体类（接口、抽象类或非类类型） | [传入具体实现类](#修复5-注册时第二个参数必须是具体类) |
| `Can not create module 'X'.` | 实现类缺少无参构造函数或 `Activator.CreateInstance` 失败 | [补齐无参构造函数](#修复6-实现类缺少无参构造函数) |

## 修复步骤

### 修复1 必须用接口获取

`GetModule<T>` 的第一件事就是判断 `typeof(T).IsInterface`，非接口直接抛错。

```csharp
// 错误：传实现类
var foo = GameFrameworkEntry.GetModule<FooImpl>();

// 正确：传接口
var foo = GameFrameworkEntry.GetModule<IFoo>();
```

Source: [GameFrameworkEntry.cs#L95-L120](/src/Runtime/Base/GameFrameworkEntry.cs#L95-L120)

### 修复2 命名空间必须以 `GameFrameX.` 开头

框架要求接口的 `FullName` 以 `GameFrameX.` 起始，否则抛第二条异常。

```csharp
// 错误：命名空间不在 GameFrameX 下
namespace MyGame { public interface IBar {} }

// 正确
namespace GameFrameX.Runtime { public interface IBar {} }
```

Source: [GameFrameworkEntry.cs#L104-L107](/src/Runtime/Base/GameFrameworkEntry.cs#L104-L107)

### 修复3 找不到模块实现类

查找实现类时，框架会按约定把接口名去掉前缀 `I` 后拼到同一命名空间去反射（如 `GameFrameX.Runtime.IFoo` → `GameFrameX.Runtime.Foo`）。失败则要求显式 `RegisterModule`。

```csharp
// 约定查找（同名空间下存在 Foo 类即可）
public class Foo : GameFrameworkModule, IFoo { /* ... */ }

// 或者显式注册：传入的第二个 Type 可以来自任意命名空间
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(MyGame.Modules.FooImpl));
```

调用入口在 `GetModule<T>` 内的 `Type.GetType(moduleName)` 逻辑，见 [GameFrameworkEntry.cs#L109-L119](/src/Runtime/Base/GameFrameworkEntry.cs#L109-L119)；注册逻辑见 [GameFrameworkEntry.cs#L153-L169](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L169)。

### 修复4 注册时第一个参数必须是接口

`RegisterModule` 第一行就校验 `interfaceType.IsInterface`。

```csharp
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(Foo));   // 正确
GameFrameworkEntry.RegisterModule(typeof(Foo), typeof(Foo));     // 抛异常
```

Source: [GameFrameworkEntry.cs#L153-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L163)

### 修复5 注册时第二个参数必须是具体类

要求 `implType.IsClass && !implType.IsInterface && !implType.IsAbstract`。

- 接口 → 抛 `by Class and not Interface ... is not.`
- 抽象类 → 抛同上
- 用具体类注册即可

Source: [GameFrameworkEntry.cs#L160-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L160-L163)

### 修复6 实现类缺少无参构造函数

`CreateModule` 使用 `Activator.CreateInstance(moduleType)` 实例化，找不到无参构造或构造抛错时会得到 `Can not create module 'X'.`。

```csharp
public class Foo : GameFrameworkModule
{
    public Foo() { }  // 必须保留一个可访问的无参构造函数
    protected internal override int Priority => 0;
    protected internal override void Update(float a, float b) { }
    protected internal override void Shutdown() { }
}
```

## 验证

- 在 `Awake` 或 `Start` 里捕获 `GameFrameworkException`：
  ```csharp
  try
  {
      var ui = GameFrameworkEntry.GetModule<IFooModule>();
  }
  catch (GameFrameworkException ex)
  {
      Debug.LogError(ex.Message);
  }
  ```
  不再抛出即表示注册与命名空间均正确。
- 控制台不再出现 `Can not find Game Framework module type` 字样，说明自动按约定查找成功；若仍查找失败，请确认程序集已编译进 Player Settings 且接口与实现类命名空间一致。
