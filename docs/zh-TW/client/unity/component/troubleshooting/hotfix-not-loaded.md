# 熱更新未生效 / DLL 未載入怎麼辦

當你在編輯器或真機上啟動 GameFrameX 時，如果熱更 DLL 沒有被載入、熱更入口方法未被呼叫，或者打出新包之後業務邏輯沒有任何變化，按本頁步驟排查即可。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 主控台完全沒有 `开始加载AOT DLL` / `开始加载程序集Hotfix` 日誌 | 未啟用 HybridCLR 巨集，走了 `RunNative` 分支 | 在 Player Settings → Scripting Define Symbols 新增 `ENABLE_GAME_FRAME_X_HYBRID_CLR`,並移除 `DISABLE_HYBRIDCLR` |
| 啟動時編輯器走的是載入 `Unity.Hotfix` 組件，但執行時 DLL 沒生效 | 真機走的是 AOT + 熱更 DLL 路徑，`AOTGenericReferences.PatchedAOTAssemblyList` 為空 | 在 HybridCLR Settings → `AOT Generic References` 中勾選泛型參考，執行 `HybridCLR/Compile DLL` 重新產生 |
| 日誌停在 `开始加载XXX.dll` 後擲出例外，提示找不到資源 | DLL 沒有打包進 AB 包，或者沒放到框架約定的目錄 | 用 `HybridCLR/Build DLL` 與框架的建置管線出包，確認 `Utility.Asset.Path.GetCodePath` 回傳的路徑能命中 |
| 日誌顯示 `EntryType=>method` 為 null,組件載入了但入口方法未執行 | `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` 與實際 DLL 不一致 | 透過 `StartupOptions` 顯式傳入正確名稱，或修改 `HotfixHelper` 中預設值(預設 `Unity.Hotfix` / `Hotfix.HotfixLauncher` / `Main`) |
| 真機載入熱更 DLL 之後仍然走舊邏輯 | 資源伺服器回傳了舊的 `AssetBundle` / 熱更 DLL 檔案 | 清理 CDN 快取並強制重新拉取最新出包 |

## 修復步驟

### 1. 確認編譯巨集與入口名稱

熱更邏輯被 `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR` 包住，只有滿足這兩個巨集定義才會真正載入 AOT DLL 與熱更 DLL。

[HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L5-L9) 中的關鍵程式碼：

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR
using System.Reflection;
using System.Linq;
using HybridCLR;
#endif
```

入口方法的預設值(不傳入 `StartupOptions` 時使用)定義在 [HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70):

```csharp
var assemblyName = options == null || string.IsNullOrEmpty(options.HotfixAssemblyName)
    ? "Unity.Hotfix"
    : options.HotfixAssemblyName;
var entryTypeName = options == null || string.IsNullOrEmpty(options.HotfixEntryTypeName)
    ? "Hotfix.HotfixLauncher"
    : options.HotfixEntryTypeName;
var entryMethodName = options == null || string.IsNullOrEmpty(options.HotfixEntryMethodName)
    ? "Main"
    : options.HotfixEntryMethodName;
```

請確認你的熱更 DLL 的組件名稱、入口類型、入口方法與這三個預設值完全相符。

### 2. 確認編輯器與執行時走的分支

[HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L72-L110) 中，編輯器會直接 `Run` 已載入的組件，真機才走 AOT DLL + 熱更 DLL 載入：

```csharp
if (ApplicationHelper.IsEditor)
{
    var assemblies = Utility.Assembly.GetAssemblies();
    foreach (var assembly in assemblies)
    {
        if (assembly.GetName().Name.Equals(assemblyName, StringComparison.OrdinalIgnoreCase))
        {
            Run(assembly, entryTypeName, entryMethodName);
            break;
        }
    }
    return;
}
```

也就是說：編輯器裡「改程式碼立刻生效」是正常的；真機測試才能驗證熱更 DLL 是否真的被載入。

### 3. 確認 AOT 泛型參考已產生

真機分支會按 `AOTGenericReferences.PatchedAOTAssemblyList` 載入 AOT 中繼資料：

```csharp
var aotDlls = AOTGenericReferences.PatchedAOTAssemblyList.ToArray();
foreach (var aotDll in aotDlls)
{
    var assetHandle = await GameApp.Asset.LoadAssetAsync<UnityEngine.Object>(
        Utility.Asset.Path.GetAOTCodePath(aotDll));
    var aotBytes = assetHandle.GetAssetObject<UnityEngine.TextAsset>().bytes;
    RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet);
}
```

如果列表為空，會跳過 AOT 中繼資料載入，後續 `Assembly.Load(hotfixDll)` 呼叫時就會因為缺少中繼資料而失敗。修復方法：在 HybridCLR 面板裡點擊 `Compile DLL` 讓 `AOTGenericReferences.PatchedAOTAssemblyList` 重新產生。

### 4. 確認熱更 DLL 資源能命中

熱更 DLL 透過 `Utility.Asset.Path.GetCodePath` 串接路徑，然後用資源系統載入：

```csharp
var assetHotfixDllPath = Utility.Asset.Path.GetCodePath(assemblyName + Utility.Const.FileNameSuffix.DLL);
var assetHotfixDllOperationHandle = await GameApp.Asset.LoadAssetAsync<UnityEngine.Object>(assetHotfixDllPath);
var assemblyDataHotfixDll = assetHotfixDllOperationHandle.GetAssetObject<UnityEngine.TextAsset>().bytes;
var hotfixAssembly = Assembly.Load(assemblyDataHotfixDll, null);
```

如果路徑對應的資源不在 AB 包裡，載入會擲出例外並被 `HotfixHelper.StartHotfixAsync` 攔截，以 `HotfixLaunchResult.Fail(e.Message)` 回傳：

```csharp
catch (Exception e)
{
    Log.Error(e);
    return HotfixLaunchResult.Fail(e.Message);
}
```

修復方法：確認建置管線確實把 `Unity.Hotfix.dll` 與 AOT DLL 打包進了對應的 AB,並清掉本機快取/CDN 快取。

### 5. 透過 `StartupOptions` 顯式指定入口

當你修改了熱更組件名稱或入口類別名稱時，透過 `StartupOptions` 顯式傳入，避免預設值不相符：

```csharp
var options = new StartupOptions
{
    HotfixAssemblyName = "Unity.Hotfix",
    HotfixEntryTypeName = "Hotfix.HotfixLauncher",
    HotfixEntryMethodName = "Main",
};
await HotfixHelper.StartHotfixAsync(options);
```

應用層入口由 [ApplicationHotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs#L22-L25) 配接至 `IHotfixLauncher`:

```csharp
public UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    return HotfixHelper.StartHotfixAsync(options);
}
```

## 驗證

1. 重新出包並清空本機 `AssetBundle` 快取目錄。
2. 啟動遊戲，觀察日誌依次出現 `开始加载AOT DLL`、`开始加载XXX.dll`、`加载程序集Hotfix 结束 Assembly ...`、`加载程序集Hotfix 结束 EntryType=>method`。
3. 修改 `Hotfix.HotfixLauncher.Main` 的邏輯後只重新打包熱更 DLL,在真機上驗證新邏輯生效即可。

## 背景(可選)

- 編輯器分支只執行 `Assembly.GetName().Name.Equals(...)` 匹配，因此只要專案裡存在 `Unity.Hotfix` 組件就一定會被載入。
- 真機分支依賴 `Utility.Asset.Path.GetCodePath` / `GetAOTCodePath` 的實作，這兩個工具方法決定 DLL 的實際資源路徑，具體設定請參閱框架建置管線文件。
- 載入例外被 `try/catch` 吞掉並透過 `HotfixLaunchResult.Fail` 暴露給呼叫方，所以啟動失敗不會讓處理程序崩潰，但也不會執行熱更邏輯。
