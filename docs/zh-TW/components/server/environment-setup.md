# 環境準備與本機建置

本節將引導您準備在本機執行 GameFrameX 伺服器所需的環境與工具，並完成首次建置，直到您能在主控台中看到伺服器啟動日誌為止。

## 前置條件

| 工具/元件 | 需求 | 備註 |
|----------|------|------|
| .NET SDK | 僅支援 .NET 10.0 SDK | 與 .NET 8/9 不相容 |
| 資料庫 | MongoDB 4.x 及以上版本 | 可安裝於本機或透過 Docker 啟動 |
| IDE | Visual Studio 2022 或 JetBrains Rider | 任何能識別 .NET 10 的編輯器皆可 |
| 選用 | Docker | 用於快速啟動 MongoDB 容器 |
| 選用 | Git | 複製儲存庫 |

> 以上版本需求來自專案 README 的「環境需求」章節（[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L168-L172)）。徽章中也明確標示了 `.NET-10.0`（[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L8)）。

## 操作步驟

1. **複製儲存庫並進入伺服器目錄**

   ```bash
   git clone https://github.com/GameFrameX/GameFrameX.git
   cd GameFrameX/Server
   ```

2. **還原 NuGet 相依套件**

   ```bash
   dotnet restore
   ```

   這將會在 `GameFrameX.AppHost` 等專案中拉取 `Aspire.Hosting.*` 等 NuGet 套件（[GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L9-L12)）。

3. **建置解決方案**

   ```bash
   dotnet build
   ```

   首次建置將編譯所有模組（包括熱修復層 `Hotfix` 與持久層 `Apps`），建置輸出將寫入各專案的 `bin/` 目錄。

4. **啟動 MongoDB**

   選擇以下其中一種方法：

   ```bash
   # 方法一：本機 mongod
   mongod --dbpath /path/to/data

   # 方法二：Docker
   docker run -d -p 27017:27017 --name mongo mongo:8.2
   ```

   啟動成功後，MongoDB 預設會監聽 `127.0.0.1:27017`。

5. **執行 Launcher 啟動伺服器**

   使用命令列引數指定服務類型與連接埠（詳情請參閱「啟動參數」參考頁面）：

   ```bash
   dotnet run --project GameFrameX.Launcher -- \
       --ServerType=Game \
       --ServerId=1000 \
       --OuterPort=29100 \
       --HttpPort=28080 \
       --DataBaseUrl=mongodb://127.0.0.1:27017 \
       --DataBaseName=gameframex
   ```

   上述命令對應 README 中提供的「最小啟動」路徑（[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L203-L210)）。

6. **驗證啟動**

   - 透過瀏覽器或 curl 存取 `http://localhost:28080/game/api/health`，預期會回傳健康狀態。
   - 檢查 Launcher 主控台中的日誌，確認 Actor 與網路監聽器已就緒。

## 常見變化

### 使用 Aspire AppHost 一鍵編排

儲存庫根目錄提供了 `GameFrameX.AppHost` 專案，該專案使用 `.NET Aspire` SDK 並參考了 MongoDB 元件（[GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19)）。只需按 F5 執行 AppHost，Aspire Dashboard 便會自動啟動 MongoDB 與 Launcher：

```bash
dotnet run --project GameFrameX.AppHost
```

### 在 IDE 中偵錯

在 Rider/VS 中，將 `GameFrameX.Launcher` 設為啟始專案，並將上述命令列引數貼到「執行設定 → 程式引數」中，即可透過中斷點對啟動流程進行偵錯。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `dotnet restore` 回報 `NETSDK1045`，表示未安裝 .NET 10 | 已安裝 .NET 8/9 但未安裝 .NET 10 | 安裝 [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) 並將其設為預設 SDK |
| 建置回報 `NU1605` / 套件衝突 | 子專案鎖定了不相容的傳遞相依套件 | 刪除 `bin/` 與 `obj/`，然後重新執行 `dotnet restore` |
| 啟動時回報 `MongoDB connection refused` | MongoDB 未啟動或連接埠被占用 | 確認 `mongod` 正在執行，或調整 `--DataBaseUrl` |
| 健康檢查 404 / 連接埠無回應 | `--HttpPort` 被占用或 `--OuterPort` 與現有程序衝突 | 變更連接埠後重新啟動 |

## 背景說明（選讀）

本專案基於 .NET 10 SDK + .NET Aspire 13.4.6 來編排本機相依服務（[GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19)）。Launcher（`GameFrameX.Launcher`）是實際承載 Actor 與網路監聽器的程序進入點，負責將命令列引數對應至 `StartupOptions`，再驅動 `GameFrameX.StartUp` 來啟動主機。

完整的執行階段設定項目清單，請參閱「啟動參數參考」。
