# SetActiveScene が ArgumentException をスローした場合の対処法

`SetActiveScene` を呼び出す際に、渡された `Scene` がまだ Unity に完全にロードされていないと、Unity は `ArgumentException` をスローします。本フレームワークは内部で捕捉し、降格処理（`Warning` を 1 件記録するだけ）を行っていますが、サブスクライバーやカスタムコードでは同じ根本原因に遭遇する可能性があります。以下に、場所の特定と修正手順を示します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| ログに `SetActiveScene failed (will be retried by Unity internally): Scene ... is not loaded.` が表示される | `Scene.isLoaded` がまだ `false` のときに `SetActiveScene` を呼び出した（典型的なケース：YooAsset の `await` 完了タイミングが Unity の実際のロード完了より早い） | シーンが実際に `isLoaded == true` になってからアクティブ化する、下記の「isLoaded を待機」を参照 |
| キャッシュされた `m_GameFrameworkScene` ハンドルをアクティブ化するが、そのシーンは既に Unity によってアンロードされている | 最初の Single ロード後、フレームワークのシーンがアンロードされ、キャッシュされたハンドルの `IsValid()` が `false` になっている | 再度 `GetSceneByName` でハンドルを取得してからアクティブ化する、下記の「ハンドルが無効」を参照 |
| コンソールに `ArgumentException: SceneManager.SetActiveScene ... is not loaded` がスローされる | カスタムコードが `SceneManager` を直接呼び出し、フレームワークの try/catch を迂回している | フレームワークのエントリーポイントを使用するか、自分で防御策を追加する、下記の「フレームワークを迂回した直接呼び出し」を参照 |
| 連続的にシーンを切り替える際、新旧のコルーチンが `SetActiveScene` の取り合いになる | 前回のリフレッシュコルーチンが停止されていないのに、新しいものが起動している | 新しいコルーチンを起動する前に `StopCoroutine` を呼ぶ、下記の「コルーチン競合」を参照 |

## 修正手順

### isLoaded を待機

フレームワークは `SceneComponent.SetActiveScene` ですでに `try/catch` で `ArgumentException` を捕捉していますが、自分で `LoadSceneSuccess` イベントを購読した後のコールバックでも遭遇する可能性があります。対象シーンの `isLoaded` を確認してから設定してください：

```csharp
var scene = UnityEngine.SceneManagement.SceneManager.GetSceneByName(sceneName);
if (scene.IsValid() && scene.isLoaded)
{
    UnityEngine.SceneManagement.SceneManager.SetActiveScene(scene);
}
```

現在のフレームでまだ `isLoaded` になっていない場合は、コルーチンを使って次のフレームまで遅延し、タイムアウトしてフレームワークのシーンにフォールバックするまで再試行してください。[SceneComponent.cs#L480-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L480-L509) の `RefreshSceneOrderWhenLoadedCo` 実装を参考にしてください。

### ハンドルが無効

キャッシュされた `Scene` ハンドルは、`Single` モードでは古いシーンと一緒に Unity によってアンロードされます。フレームワークは [SceneComponent.cs#L449-L457](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L449-L457) で `IsValid()` を使って防御しています：

```csharp
if (!activeScene.IsValid())
{
    // ハンドル失効時は設定をスキップする。新しい Single シーンのロード完了後、Unity 自身がアクティブ化する
    RefreshMainCamera();
    return;
}
```

自分のコードで `Scene` ハンドルを再利用する場合も、呼び出し前に同じく `IsValid()` を検証してください。そうでない場合は、再度 `GetSceneByName` で取得する必要があります。

### フレームワークを迂回した直接呼び出し

サブスクライバーのコールバック内で `UnityEngine.SceneManagement.SceneManager.SetActiveScene` を直接呼び出さないでください。フレームワークの例外吸収ロジックを迂回してしまいます。フレームワークのエントリーポイント（`GameSceneComponent.SetActiveScene` のようなメソッド）を優先的に使用してください。イベントコールバック内でアクティブシーンを切り替える必要がある場合は、自分で try/catch でラップし、上記の「isLoaded を待機」の判定に従ってください。

### コルーチン競合

連続して複数回シーンを切り替える際、前回のリフレッシュコルーチンを先に停止しないと、新旧のコルーチンが同一フレーム内で `SetActiveScene` を取り合い、`ArgumentException` がトリガーされます。フレームワークの修正パターンについては [SceneComponent.cs#L430-L435](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L430-L435) を参照してください：

```csharp
if (m_RefreshSceneOrderCo != null)
{
    StopCoroutine(m_RefreshSceneOrderCo);
    m_RefreshSceneOrderCo = null;
}
m_RefreshSceneOrderCo = StartCoroutine(RefreshSceneOrderWhenLoadedCo(maxSceneName));
```

`finally` ブロックでは、ハンドルを `null` にセットする（[SceneComponent.cs#L505-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L505-L509) を参照）ことを忘れないでください。これにより、次回 `RefreshSceneOrder` が古いコルーチンの実行中を誤判定するのを防ぎます。

## 検証

- ログに `ArgumentException: SceneManager.SetActiveScene ... is not loaded` がもう表示されないこと。
- ロードコールバックが返ってきた時点で `SceneManager.GetActiveScene()` が対象シーンと等しいこと。
- 連続して 2 回シーンを切り替えても、コンソールに `SetActiveScene failed` の警告が出ないこと。
