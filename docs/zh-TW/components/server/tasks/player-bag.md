# 實作玩家背包(Bag)模組

本任務完成後，你將得到一個可用的玩家背包元件：支援增加、移除、使用物品，以及查詢背包全部資料，且資料透過 Actor 狀態自動持久化，物品變更時主動推送用戶端。

## 前置條件

- 已完成框架的 Actor/Component 體系建置，了解 `StateComponent`、`StateComponentAgent` 的基本用法。
- 物品設定表 `TbItemConfig` 已透過 `ConfigComponent` 註冊(程式碼中透過 `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(itemId, out _)` 驗證物品存在)。
- 用戶端/伺服器端已基於 ProtoBuf 協定 `Proto/_0100_Bag.cs` 產生 `ReqBagInfo`、`RespBagInfo`、`ReqAddItem`、`RespAddItem`、`ReqRemoveItem`、`RespRemoveItem`、`ReqUseItem`、`RespUseItem`、`NotifyBagInfoChanged`、`NotifyBagItem` 等訊息型別。

### 3. 在 Hotfix 層實作 BagComponentAgent

在 `GameFrameX.Hotfix/Logic/Player/Bag/BagComponentAgent.cs` 中繼承 `StateComponentAgent<BagComponent, BagState>`,實作「增加 / 移除 / 使用 / 查詢」四個核心方法。所有方法都是先透過 `ConfigComponent` 驗證物品存在，再修改狀態並透過 `OwnerComponent.WriteStateAsync()` 持久化。

```csharp
using GameFrameX.Apps.Player.Bag.Component;
using GameFrameX.Apps.Player.Bag.Entity;
using GameFrameX.Config;
using GameFrameX.Config.Tables;

namespace GameFrameX.Hotfix.Logic.Player.Bag;

public class BagComponentAgent : StateComponentAgent<BagComponent, BagState>
{
    public async Task<BagState> UpdateChanged(INetWorkChannel netWorkChannel, Dictionary<int, long> itemDic)
    {
        var bagState = OwnerComponent.State;
        var notifyBagInfoChanged = new NotifyBagInfoChanged();
        foreach (var item in itemDic)
        {
            var notifyBagItem = new NotifyBagItem() { ItemId = item.Key };
            if (bagState.List.TryGetValue(item.Key, out var value))
            {
                value.Count += item.Value;
                notifyBagItem.Count = value.Count;
                notifyBagItem.Value = item.Value;
            }
            else
            {
                bagState.List[item.Key] = new BagItemState() { Count = item.Value, ItemId = item.Key };
                notifyBagItem.Count = item.Value;
                notifyBagItem.Value = item.Value;
            }

            notifyBagInfoChanged.ItemDic[item.Key] = notifyBagItem;
        }

        // netWorkChannel 為空表示離線發放:只持久化背包,不推送用戶端通知
        if (netWorkChannel != null)
        {
            await netWorkChannel.WriteAsync(notifyBagInfoChanged);
        }

        await OwnerComponent.WriteStateAsync();
        return bagState;
    }
}
```

```csharp
public async Task OnAddBagItem(INetWorkChannel netWorkChannel, ReqAddItem message, RespAddItem response)
{
    foreach (var item in message.ItemDic)
    {
        if (!ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(item.Key, out var itemConfigState))
        {
            response.ErrorCode = (int)OperationStatusCode.NotFound;
            return;
        }
    }

    var result = await UpdateChanged(netWorkChannel, message.ItemDic);
    if (result.IsNull())
    {
        response.ErrorCode = (int)OperationStatusCode.Unprocessable;
    }
}
```

### 4. 公開 RPC 處理器

在 `GameFrameX.Hotfix/Logic/Player/Bag/ReqBagInfoHandler.cs` 中透過 `MessageMapping` 特性把 `ReqBagInfo` 訊息路由到 `BagComponentAgent`,作為用戶端查詢背包的入口。其他訊息(`ReqAddItem` / `ReqRemoveItem` / `ReqUseItem`)以同樣方式撰寫 Handler 即可。

```csharp
[MessageMapping(typeof(ReqBagInfo))]
internal sealed class ReqBagInfoHandler : PlayerRpcComponentHandler<BagComponentAgent, ReqBagInfo, RespBagInfo>
{
    protected override async Task ActionAsync(ReqBagInfo request, RespBagInfo response)
    {
        try
        {
            await ComponentAgent.OnReqBagInfoAsync(NetWorkChannel, request, response);
        }
        catch (Exception e)
        {
            LogHelper.Fatal(e);
            response.ErrorCode = (int)OperationStatusCode.InternalServerError;
        }
    }
}
```

### 5. 實作查詢邏輯

`OnReqBagInfoAsync` 把狀態中的物品清單轉成回應訊息的 `Dictionary<int, long>(ItemId -> Count)`,供用戶端一次性拉取完整背包。

```csharp
public async Task OnReqBagInfoAsync(INetWorkChannel netWorkChannel, ReqBagInfo message, RespBagInfo response)
{
    var bagState = OwnerComponent.State;
    if (bagState.IsNotNull())
    {
        response.ItemDic = bagState.List.ToDictionary(x => x.Key, x => x.Value.Count);
    }

    await Task.CompletedTask;
}
```

## 常見變體

- **離線發獎**：呼叫 `UpdateChanged(netWorkChannel: null, itemDic)`。`netWorkChannel` 為 `null` 時跳過用戶端推送，只持久化，適合郵件附件、登入獎勵等統一獎勵發放介面。
- **使用物品消耗**:`OnUseBagItem` 中當數量扣到 0 時，直接從 `bagState.List` 移除該物品，並把 `value.Count` 重設為 0;同時透過 `NotifyBagInfoChanged` 推送給用戶端。
- **移除驗證**:`OnRemoveBagItem` 在物品數量不足時直接傳回 `OperationStatusCode.Unprocessable`,在物品不存在時傳回 `OperationStatusCode.NotFound`。

## 常見錯誤

- **未註冊元件**:`BagComponent` 必須用 `[ComponentType(GlobalConst.ActorTypePlayer)]` 標註，否則玩家 Actor 不會掛載該元件，`OwnerComponent.State` 取不到資料。
- **設定表未設定**:`OnAddBagItem` / `OnRemoveBagItem` / `OnUseBagItem` 都透過 `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)` 驗證物品，物品未設定會直接傳回 `NotFound`,不會寫入狀態。
- **離線發獎時傳入了網路通道**：會讓本不應在線上看到變化的用戶端收到推送，導致資料同步異常；離線場景應傳 `null`。
- **扣減後忘記持久化**：任何修改 `bagState.List` 的分支都必須呼叫 `await OwnerComponent.WriteStateAsync();`,否則狀態只存在記憶體中，處理序重新啟動後將遺失。

## 背景(選用)

- `BagComponent` 是 `StateComponent<BagState>`,由 Actor 框架負責序列化與持久化，Hotfix 層 `BagComponentAgent` 透過 `OwnerComponent` 取得 `BagState` 實例並就地修改。
- 增加 / 使用物品後，伺服器端主動 `WriteAsync(notifyBagInfoChanged)` 把變更增量推送給用戶端，避免用戶端輪詢。
