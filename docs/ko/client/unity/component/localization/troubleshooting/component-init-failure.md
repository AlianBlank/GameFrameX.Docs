# "Localization manager is invalid / Base component is invalid" 해결 방법

이 두 Fatal 로그는 각각 `LocalizationComponent`의 `Awake()`와 `Start()`에서 발생합니다. `Awake()`에서 `GameFrameworkEntry.GetModule<ILocalizationManager>()`로 로컬라이제이션 매니저 모듈을 가져오지 못하거나, `Start()`에서 `GameEntry.GetComponent<BaseComponent>()`로 Base 컴포넌트를 찾지 못할 때 출력되며, 이후 컴포넌트는 곧바로 `return`하기 때문에 로컬라이제이션 기능이 동작하지 않습니다. 대부분의 경우 "로컬라이제이션 구현 어셈블리가 패키지에 함께 컴파일되지 않음/크로핑됨" 또는 "씬에 GameFrameX 기본 컴포넌트 누락"이 원인이므로, 아래 진단 표에 따라 한 항목씩 점검하면 복구할 수 있습니다.

## 수정 단계

### 단계 1: 구현 어셈블리 존재 확인

`LocalizationComponent.Awake()`에서는 인터페이스 타입으로 모듈을 가져옵니다:

```csharp
m_LocalizationManager = GameFrameworkEntry.GetModule<ILocalizationManager>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L216)

`GetModule`이 null을 반환한다는 것은 `ILocalizationManager`의 구체적인 구현 클래스(`LocalizationManager`)가 `GameFrameworkEntry`에 등록되지 않았다는 의미이며, 일반적으로 해당 구현이 포함된 구현 어셈블리가 컴파일에 참여하지 않았기 때문입니다. 다음을 순서대로 확인하세요:

1. Unity Console을 열고 먼저 모든 **컴파일 오류(Compiler Error)**를 해결하세요. 컴파일 오류가 존재하면 Unity가 일부 어셈블리 컴파일을 건너뛰어 모듈 등록도 함께 유실되며, 이것이 가장 흔한 원인입니다.
2. 본 패키지의 `Runtime` 디렉터리에 있는 런타임 asmdef(`GameFrameX.Localization`)가 임포트되었고 제거되지 않았는지 확인하세요. 본 패키지의 컴포넌트는 `[RequireComponent(typeof(GameFrameXLocalizationCroppingHelper))]`로 선언되어 있으므로, Inspector에 Missing Script가 나타나면 런타임 어셈블리가 누락되었거나 컴파일에 실패한 것입니다.
3. 프로젝트에서 GameFrameX의 컴포넌트 크로핑/모듈 제거 메커니즘을 활성화한 경우, 로컬라이제이션 모듈이 제거되지 않았는지 확인하세요.

### 단계 2: BaseComponent 보완

`Base component is invalid.`의 판정 근거는 `Start()`의 다음 조회입니다:

```csharp
BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227)

1. 씬에서 `LocalizationComponent`가 부착된 것과 동일한 GameFrameX 루트 오브젝트에 `BaseComponent`가 존재하는지 확인하세요(`EventComponent`, `SettingComponent`도 `Start()`가 마찬가지로 의존하므로 함께 확인).
2. Inspector에 "Missing (Mono Script)"가 표시되면 해당 스크립트가 컴파일되지 않았거나 어셈블리가 누락된 것입니다. 단계 1로 돌아가 컴파일 오류를 해결하세요.
3. 이 컴포넌트들을 여러 오브젝트에 수동으로 분산 부착하지 마세요. `GameEntry.GetComponent<T>()`는 이들이 프레임워크 엔트리에 있을 것으로 기대합니다.

### 단계 3: 로컬라이제이션 Helper 확인

`Start()`에서는 이어서 직렬화 필드에 따라 Helper를 생성하며, 실패 시 `Can not create localization helper.`를 출력합니다:

```csharp
LocalizationHelperBase localizationHelper = Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper);
if (localizationHelper == null)
{
    Log.Fatal("Can not create localization helper.");
    return;
}
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L254)

`LocalizationComponent`의 Inspector에서 `m_LocalizationHelperTypeName`을 확인하세요. 기본값은 다음과 같은 전체 타입 이름입니다:

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73)

커스텀 Helper로 교체한 경우, `m_CustomLocalizationHelper` 필드에 참조를 드래그하여 넣거나, `m_LocalizationHelperTypeName`이 "네임스페이스.클래스명, 어셈블리명" 형식의 완전히 해석 가능한 전체 타입 이름이 되도록 하세요.

## 검증

1. Play 모드에 다시 진입하여 Console에 `Localization manager is invalid.`, `Base component is invalid.` 등 앞서 언급한 Fatal 로그가 더 이상 나타나지 않는지 확인합니다.
2. `Start()`가 정상적으로 완료되면 언어가 초기화됩니다. 에디터가 아닌 모드에서 `Language == UnknownLocalization`인 경우 자동으로 `SystemLanguage`를 채택하고 최종적으로 `DefaultLanguage`를 설정합니다(출처는 [LocalizationComponent.cs 261-272행](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L272) 참조). `LocalizationComponent.Language`, `DefaultLanguage`, `DictionaryCount`를 사용하여 컴포넌트가 사용 가능한 상태임을 확인할 수 있습니다.
3. 문자열 조회 인터페이스(예: `GetLocalizedString`/`GetRawString` 계열)를 한 번 호출했을 때 빈 값이 아닌 문자열이 반환되면 전체 체인이 성공적으로 초기화되었음을 확인할 수 있습니다.
