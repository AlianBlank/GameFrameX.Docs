# WebGL 平台不可用怎么办

`com.gameframex.unity.readassets` 在 WebGL 平台没有专用的实现分支,且 Unity WebGL 的运行时沙箱无法像本地磁盘或 APK 那样直接以同步方式打开 StreamingAssets 中的文件,因此该框架在 WebGL 平台**不被官方支持**。一旦你在 Build Target 切换为 WebGL 后调用 `BlankReadAssets` 的任意 API,会在编辑器或运行时遇到功能缺失或加载失败的情况。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 切换 Build Target 到 WebGL 后编译报 "WebGL is not supported" 相关警告,或在 WebGL 构建中读不到 StreamingAssets 文件 | 框架只针对 `UNITY_EDITOR`、`UNITY_ANDROID` 提供了专用实现分支,WebGL 与其他平台共用 `LooseFilesImpl`,且 WebGL 沙箱不支持同步 `File` I/O | 参考下方修复步骤切换方案 |
| 调用 `BlankReadAssets.ReadAllBytes / FileExists / LoadAssetBundle` 后返回空或抛 `FileNotFoundException` | WebGL 上 `LooseFilesImpl` 走的是 `Application.streamingAssetsPath`,但 `AssetBundle.LoadFromFile` 在 WebGL 必须改用 `UnityWebRequest` | 用 Unity WebGL 原生接口替代(见步骤 2) |
| 业务逻辑同时要支持 WebGL 与 Android,直接 `if (Application.platform == RuntimePlatform.WebGLPlayer)` 判断 | 框架没有为 WebGL 提供独立的读取路径 | 将 WebGL 分支单独调用 UnityWebRequest,其余平台继续使用 `BlankReadAssets`(见步骤 3) |

## 修复步骤

### 1. 在 WebGL Build 中改用 UnityWebRequest

WebGL 平台对文件的访问必须走 `UnityWebRequest`,这是 Unity 官方在 WebGL 后端唯一受支持的资产加载方式:

```csharp
using UnityEngine;
using UnityEngine.Networking;

public static class WebGLReadAssetsFallback
{
    public static UnityWebRequest ReadAllBytes(string relativePath)
    {
        // StreamingAssets 在 WebGL 上的 URL 形如 http(s)://host/StreamingAssets/xxx
        var url = System.IO.Path.Combine(Application.streamingAssetsPath, relativePath);
        return UnityWebRequest.Get(url);
    }
}
```

### 2. 用平台条件编译保留旧调用

在业务代码里用宏把 WebGL 排除掉,避免 WebGL 上调用到不支持的 API:

```csharp
#if !UNITY_WEBGL || UNITY_EDITOR
    using GameFrameX.ReadAssets.Runtime;
#endif

public byte[] LoadConfig(string path)
{
#if !UNITY_WEBGL || UNITY_EDITOR
    return BlankReadAssets.ReadAllBytes(path);
#else
    using (var req = WebGLReadAssetsFallback.ReadAllBytes(path))
    {
        req.SendWebRequest();
        while (!req.isDone) { }
        return req.downloadHandler.data;
    }
#endif
}
```

> 详见 `Runtime/BlankReadAssets.cs` 中按平台选择实现的写法:

```csharp
#if UNITY_EDITOR
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.EditorImpl;
#elif UNITY_ANDROID
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.ApkImpl;
#else
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.LooseFilesImpl;
#endif
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L11-L17)

### 3. 关于 AssetBundle 的额外说明

`BlankReadAssets.LoadAssetBundle` 内部调用 `AssetBundle.LoadFromFile`,而该 API 在 WebGL 上行为未定义。如果你需要在 WebGL 上加载 AssetBundle,必须改用 `UnityWebRequestAssetBundle.GetAssetBundle`。框架暂未提供 WebGL 等价实现,需要自行封装或去掉对该路径的依赖。

## 验证

- 在编辑器中把 Build Target 切到 WebGL,触发场景初始化逻辑,确认不再打印 "WebGL is not supported" 之外的运行时异常。
- 在 WebGL Build 中打开浏览器开发者工具,确认 `UnityWebRequest` 请求路径指向 `StreamingAssets` 下正确的相对文件,且响应 200。
- 业务路径改为:非 WebGL 走 `BlankReadAssets`,WebGL 走 `UnityWebRequest`,并在两条路径上各跑一遍同一份资源加载冒烟测试。

## 背景(可选)

仓库 README 在 Platform Notes 一节明确写到 "WebGL is not supported" 的同一句话,本框架并未提供 `UNITY_WEBGL` 的实现分支,其他非 Android 非 Editor 平台都会被映射到 `LooseFilesImpl`,该实现在物理磁盘上读取文件,无法满足 WebGL 沙箱的同步/异步 I/O 要求。
