# What to Do If UI Form Closing Is Not Triggered

After calling `CloseUIForm`, if the UI form does not close, `OnClose` is not triggered, or the `CloseUIFormComplete` event is not dispatched, it is usually because the passed-in serial number is invalid, the UI form is still loading, the panel itself has closing disabled, or the close callback is intercepted by the toggle that disables animated recycling. This page provides a diagnostic table for locating the cause by symptom, along with fix steps.

## Quick Diagnosis

| Symptom (Console/Behavior) | Cause | Fix |
|---|---|---|
| The log outputs `Can not find UI form '{serialId}'.` | The passed-in `serialId` is currently unavailable (already closed, never opened, or misspelled) | Use `GetAllLoadedUIForms()` to obtain the real `SerialId` and pass it in |
| The form appears not to disappear from the screen, but there is no error in the console | The form is still loading and has been merged into the loading queue's "close pending release" list | Wait for loading to complete so it is recycled automatically; or call `ReleaseAllLoadedUIForms()` in a later frame of the manager |
| `OnClose` is not called, but the event has already been triggered | The form has the `IsDisableClosing` flag set | Check whether the script ever called `SetDisableClosing(true)` and undo it before closing |
| Nothing happens after calling `CloseUIForm<T>` | The generic overload matches by `FullName` and fails to hit in multi-instance scenarios | Hold an `IUIForm` reference directly, or close via `serialId` instead |
| The form reappears after being closed | `IsDisableRecycling = true`: the instance is not recycled and goes straight back to the object pool | Check the `IsDisableRecycling` setting in configuration/scripts |
| The form does not disappear after the close animation finishes | When `EnableHideAnimation = true`, the `Hide` callback is not triggered | Check whether the custom `Hide` implementation correctly invokes the `Action onComplete` callback |

> The above error messages and conditional branches all come from [BaseUIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L79-L223).

## Fix Steps

### 1. Verify that the passed-in `serialId` or form reference is valid

`CloseUIForm(int serialId, ...)` first calls `GetUIForm(serialId)`; if the form cannot be found, it prints `Can not find UI form '{serialId}'.` and `return`s — **it does not throw an exception**. Prefer closing via a concrete reference instead:

```csharp
// Get the real SerialId from the return value of OpenUIForm
int serialId = GameEntry.UI.OpenUIForm("UIPrefabs/LoginForm");
// When it needs to be closed:
GameEntry.UI.CloseUIForm(serialId);
```

Alternatively, hold an `IUIForm` reference directly and call the close method on it, avoiding dependence on externally maintained IDs.

Source: [BaseUIManager.Close.cs#L94-L104](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L94-L104)

### 2. The form is still loading

If the target form is in the "loading" collection when the close method is called (`IsLoadingUIForm(serialId)` is true), the manager puts it into `m_UIFormsToReleaseOnLoad` and **returns directly — `OnClose` and the event callback will not be executed**. In this case, call `ReleaseAllLoadedUIForms()` later so the form is recycled as soon as the asynchronous load completes:

```csharp
GameEntry.UI.CloseUIForm(serialId);          // At this point it may only be enqueued, not actually closed
// Check again in Update
GameEntry.UI.ReleaseAllLoadedUIForms(false);  // Trigger the release again once loading completes
```

Source: [BaseUIManager.Close.cs#L161-L170](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L161-L170) and [BaseUIManager.Close.cs#L287-L299](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L287-L299)

### 3. Closing is disabled on the panel (`IsDisableClosing`)

The close logic checks this before dispatching the event:

```csharp
if (uiForm.IsDisableClosing)
{
    return;
}
```

If a script mistakenly leaves `SetDisableClosing(true)` in place (e.g., temporarily disabled during a dialog confirmation flow and never restored), `CloseUIForm` will **exit silently**. Restore it proactively before closing:

```csharp
uiForm.SetDisableClosing(false);
GameEntry.UI.CloseUIForm(uiForm);
```

Source: [BaseUIManager.Close.cs#L172-L175](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L172-L175)

### 4. The generic overload `CloseUIForm<T>` does not hit

`CloseUIForm<T>` matches using `typeof(T).FullName`, and only truly closes when `HasUIFormFullName` also hits. In multi-instance scenarios, it may be intercepted by the first matching instance and then `break` directly. It is recommended that business code hold its own `IUIForm` reference.

```csharp
// Recommended: use the interface instance directly
IUIForm form = ...;
GameEntry.UI.CloseUIForm(form, userData: null, isNowRecycle: true);
```

Source: [BaseUIManager.Close.cs#L130-L149](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L130-L149)

### 5. Event subscription not triggered

`CloseUIFormComplete` is a plain .NET event; you must first subscribe with `+=` to receive the callback when a form closes. The event arguments come from a reference pool and are automatically recycled after use, so business code must not cache `CloseUIFormCompleteEventArgs`:

```csharp
GameEntry.UI.CloseUIFormComplete += (sender, e) =>
{
    Debug.Log($"Close UI form: {e.UIFormAssetName}, SerialId={e.SerialId}");
};
```

Source: [BaseUIManager.Close.cs#L43-L57](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L43-L57) and [CloseUIFormCompleteEventArgs.cs#L43-L157](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/CloseUIFormCompleteEventArgs.cs#L43-L157)

### 6. Coordination between the close animation and recycling

If `EnableHideAnimation = true`, closing first calls `Hide(...)` and then invokes `OnClose` and `Refresh` inside the callback; if the custom `Hide` implementation forgets to call the passed-in `onComplete` callback, neither `OnClose` nor the event will be executed. The full chain of an animated close is:

```csharp
uiGroup.RemoveUIForm(uiForm, true);   // Mark as hidden
uiForm.Hide(m_UIFormHideHandler, () =>
{
    uiForm.OnClose(m_IsShutdown, userData);
    uiGroup.Refresh();
    if (isNowRecycle)
        RecycleUIForm(uiForm, true);
});
```

If you just want to destroy it immediately (including the GameObject), set `isNowRecycle` to `true`; the manager will synchronously call `RecycleUIForm`, skipping the recycling queue.

Source: [BaseUIManager.Close.cs#L180-L202](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L180-L202)

## Verification

1. After the close API is called, the log should **no longer** contain `Can not find UI form '{serialId}'.`.
2. The `CloseUIFormComplete` subscription function is triggered at least once; the `OnClose` lifecycle method is hit.
3. The next `GetAllLoadedUIForms()` call after closing no longer contains that `SerialId` (unless `IsDisableRecycling = true`).
4. Verify that `m_UIFormsBeingLoaded` and `m_UIFormsToReleaseOnLoad` are empty (`CloseAllLoadingUIForms` / `ReleaseAllLoadedUIForms` behave as expected).
