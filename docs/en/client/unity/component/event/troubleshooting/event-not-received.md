# What to Do When Events Are Not Received or Not Triggered

Subscribing to an event but never receiving the callback is usually caused by **a mismatch between the event id used for subscribing and firing**, **a misinterpretation of Fire's "next-frame dispatch" semantics**, or **a missing `EventComponent` in the scene**. Match your situation against the diagnostic table below, then follow the corresponding fix steps to locate the problem.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Callback never executes | The subscribed `id` is not the same string as the event id passed to `Fire` (typo, casing difference, one side using `typeof(X).FullName` while the other uses a hand-written literal) | Unify on a constant or `typeof(X).FullName`; see [Fix Step 1](#1-verify-the-event-id-matches-exactly) |
| Callback never executes, but the id is confirmed to match | The subscription happens after `Fire`; under `EventPoolMode.AllowNoHandler`, the event is silently dropped | `Subscribe` before `Fire`; see [Fix Step 2](#2-subscribe-before-firing-and-verify-the-subscription-succeeded) |
| Event is not received on the frame it is fired, only on the next frame | `Fire` is thread-safe but defers dispatch to the next frame; this is by design | If you need an immediate callback, switch to `FireNow`; see [Fix Step 3](#3-understand-fires-next-frame-dispatch-semantics) |
| Intermittent event loss | The object is destroyed on the same frame the event is fired / the game is paused, so `EventManager.Update` no longer runs and queued events are never dispatched | Avoid destroying the subscriber immediately after firing; or switch to `FireNow` |
| Console prints `Event manager is invalid.` and all events stop working | `EventComponent` is missing from the scene, so the `IEventManager` module cannot be obtained in `Awake` | Add the GameFrameX/Event component to the scene; see [Fix Step 4](#4-confirm-eventcomponent-exists-in-the-scene) |
| Calling `Fire(sender, "")` or passing a null event id throws an exception directly | Parameter validation by `GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId))` | Pass a non-empty event id string |
| Want to log unsubscribed events for troubleshooting | No default handler is set | Call `SetDefaultHandler` as a fallback; see [Fix Step 5](#5-use-a-default-handler-as-a-fallback-to-diagnose-events-with-no-subscribers) |
| Unsubscribing reports that the handler does not exist | `Unsubscribe` was passed a handler that was never subscribed | Use `CheckUnsubscribe` instead |

## Fix Steps

### 1. Verify the Event id Matches Exactly

The only criterion for matching `Subscribe` with `Fire` is the `string`-typed event id. When the two sides do not match, the event pool raises no error (`EventManager` is created with `EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler`), and the event is silently dropped:

```csharp
m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L46-L49)

Recommended practice: consolidate event ids into a single set of constants or `typeof(X).FullName`, and have both the subscribing and firing sides reference the same source. When using parameterless events, `Fire(sender, eventId)` internally creates an `EmptyEventArgs` and writes the id into it:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

Note that when an `EmptyEventArgs` is recycled, its id is reset to `typeof(EmptyEventArgs).FullName`; do not rely on the event argument object retaining a custom id after dispatch.

### 2. Subscribe Before Firing, and Verify the Subscription Succeeded

Events must be subscribed before they are fired. If you suspect a problem in the subscription chain, use `Count(id)` / `Check(id, handler)` to directly confirm the current state of the event pool:

```csharp
public int Count(string id)
{
    return m_EventManager.Count(id);
}

public bool Check(string id, EventHandler<GameEventArgs> handler)
{
    return m_EventManager.Check(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L98)

Repeated initialization can easily cause the same handler to be subscribed multiple times (`AllowMultiHandler` permits duplicate subscriptions, resulting in duplicate callbacks). The framework provides a duplicate-safe version:

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

Symmetrically, when unsubscribing a handler that might not exist, use `CheckUnsubscribe`, which simply skips the call when the handler is not present:

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L128-L131)

### 3. Understand Fire's "Next Frame" Dispatch Semantics

`Fire` is thread-safe, but after an event enters the queue, it is dispatched on the next frame inside `EventManager.Update`; `FireNow` dispatches immediately but is not thread-safe:

```csharp
/// Fires an event. This operation is thread-safe: even if the event is fired off the main thread, the event handler is guaranteed to be called back on the main thread, but the event will be dispatched on the frame after it is fired.
public void Fire(object sender, GameEventArgs e)
{
    m_EventPool.Fire(sender, e);
}

/// Fires an event in immediate mode. This operation is not thread-safe; the event is dispatched immediately.
public void FireNow(object sender, GameEventArgs e)
{
    m_EventPool.FireNow(sender, e);
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L158-L175)

Queued events are consumed by the per-frame polling:

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_EventPool.Update(elapseSeconds, realElapseSeconds);
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L81-L84)

From this, two diagnostic points follow:
1. Asserting on the same frame after `Fire` that the callback has already executed will fail — wait for the next frame or switch to `FireNow`.
2. If the subscribing object is destroyed immediately after the event is fired, or the game is paused so that `Update` stops running, queued events may never be dispatched.

### 4. Confirm EventComponent Exists in the Scene

`EventComponent` obtains the module in `Awake` via `GameFrameworkEntry.GetModule<IEventManager>()`; if this fails, it logs `Log.Fatal` and returns immediately, after which none of the event APIs are usable:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

Fix: Add the `GameFrameX/Event` component to the scene (`[AddComponentMenu("GameFrameX/Event")]`), and confirm that the initialization order satisfies the module priority (`EventManager.Priority` is 7).

### 5. Use a Default Handler as a Fallback to Diagnose Events with No Subscribers

After a default handler is set, every event without subscribers is routed to that callback, which is handy during troubleshooting for logging "event fired but handled by no one":

```csharp
public void SetDefaultHandler(EventHandler<GameEventArgs> handler)
{
    m_EventManager.SetDefaultHandler(handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L137-L140)

## Verification

1. Subscribe a handler that only logs, record `Count(eventId)`, and expect a return value ≥ 1.
2. After `Fire(sender, eventId)`, wait for the next frame (or use `FireNow` directly), and confirm the log output.
3. `Check(eventId, handler)` should return `true`; after calling `CheckUnsubscribe`, `Count(eventId)` should drop back to 0, and firing again should route the event to the default handler (if one is set).
4. In the editor, select the object with `EventComponent` attached, and observe the event and handler counts via the Inspector (`EventHandlerCount` / `EventCount`).
