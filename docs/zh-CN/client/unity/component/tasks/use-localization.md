# 如何添加和使用本地化多语言

按照本页步骤，你可以在 GameFrameX 中通过 `TbLocalization` 配置表 + `GameApp.Localization` 运行时组件，把界面中的硬编码字符串替换成基于 Key 的多语言文案，并在运行时按当前语言读取对应翻译。

## 前置条件

- 项目已经引入 `GameFrameX.Localization.Runtime` 包，并在 `HotfixLauncher.cs` 中 `using`。
- 本地化数据由 `Assets/Bundles/Config/local_tblocalization.json` 提供，并由工具生成 `Hotfix.Config.Local.TbLocalization` / `Local.Localization` 数据表类。
- 运行时的语言枚举为 `GameFrameX.Localization.Runtime.LocalizationCode`。

## 操作步骤

1. **在 `local_tblocalization.json` 中新增一条翻译条目**。`key` 是代码里查询用的唯一标识，后面每种语言字段都填写对应翻译。

```json
{
  "key": "ui_nav_voice",
  "ChineseSimplified": "音效设置",
  "ChineseTraditional": "音效設置",
  "English": "Sound Settings",
  "Japanese": "サウンド設定",
  "Korean": "사운드 설정",
  "Thai": "ตั้งค่าเสียง",
  "Indonesian": "Pengaturan Suara",
  "French": "Paramètres audio",
  "German": "Audioeinstellungen",
  "Russian": "Настройки звука",
  "Italian": "Impostazioni audio",
  "PortuguesePortugal": "Configurações de som",
  "Spanish": "Ajustes de sonido",
  "Vietnamese": "Cài đặt âm thanh"
}
```

Source: [local_tblocalization.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Bundles/Config/local_tblocalization.json#L36-L52)

2. **重新生成数据表代码**。表结构由 `TbLocalization.cs` 描述：每行对应一个 `Local.Localization` 对象，构造器接受一个 `Func<Task<JSONNode>> loadFunc` 用于异步加载 JSON。

Source: [TbLocalization.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Local/TbLocalization.cs#L17-L60)

3. **在启动流程中把翻译装填到运行时**。在 `HotfixLauncher.TranslateText()` 中：先 `RemoveAllRawStrings()` 清空旧数据，再用 `GameApp.Config.GetConfig<TbLocalization>()` 拿到表实例，按当前 `GameApp.Localization.Language` 选择对应语言列，写入运行时。

```csharp
GameApp.Localization.RemoveAllRawStrings();
var tbLocalization = GameApp.Config.GetConfig<TbLocalization>();
tbLocalization.ForEach(localization =>
{
    if (localization.Key.IsNullOrWhiteSpace()) return;

    var value = string.Empty;
    switch (GameApp.Localization.Language)
    {
        case LocalizationCode.ChineseSimplified:
            value = localization.ChineseSimplified; break;
        case LocalizationCode.ChineseTraditionalTW:
        case LocalizationCode.ChineseTraditionalHK:
            value = localization.ChineseTraditional; break;
        case LocalizationCode.English:
            value = localization.English; break;
        case LocalizationCode.Japanese:
            value = localization.Japanese; break;
        // ... 其他语言分支
        default:
            value = localization.English; break;
    }
    GameApp.Localization.AddRawString(localization.Key, value);
});
```

Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L66-L120)

4. **在游戏代码里通过 Key 获取文案**。使用 `GameApp.Localization.GetString(key)` 即可拿到当前语言下的文本，UI、提示、日志都可以直接用这个接口。

```csharp
var title = GameApp.Localization.GetString("ui_nav_voice");
Debug.Log(title);
```

5. **切换语言**。修改 `GameApp.Localization.Language` 后再次调用 `TranslateText()`，即可按新语言重新装填翻译，再调用 `GetString(key)` 即返回新语言文案。

## 常见变体

- **新增语言支持**：如果 `LocalizationCode` 中已有枚举但 `TbLocalization` 列没有对应字段，需在 `local_tblocalization.json` 添加列，并在 `TranslateText()` 的 `switch` 里加一个分支。
- **运行时动态翻译**：可以让翻译接口来自服务器下发或玩家自定义，`TranslateText` 函数式参数 `System.Func<string, string, string> translator` 可以直接注入自定义翻译函数，避免改 `switch`。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `GetString` 返回空 | 表里 `Key` 为空或不存在 | 在 `TranslateText()` 中保留 `IsNullOrWhiteSpace` 校验，并确认 JSON 中 `key` 唯一 |
| 切换语言后仍是旧文案 | 没重新调用 `TranslateText` | 改完 `Language` 后再调用一次装填流程 |
| 新语言分支返回空字符串 | `switch` 没覆盖该 `LocalizationCode` | 在 `default` 分支兜底为 `English` 或补齐分支 |
| 修改 JSON 后字段没出现 | 没重新生成 `TbLocalization` / `Localization` 数据类 | 重跑配置表生成工具 |

## 背景

`TbLocalization` 是一个 `BaseDataTable<Local.Localization>`，构造时接收 JSON 加载委托，`LoadAsync` 会清空旧数据后逐条反序列化；`TranslateText` 接受一个 `(原始文案, 目标语言) => 翻译结果` 的函数，可以把翻译逻辑下沉到外部（如在线翻译、人工翻译），当前 `HotfixLauncher.TranslateText` 用的是「按语言枚举读表」这种最直接的方式。
