# 테넌트/데이터 권한/트리형 엔터티 선언 방법

세 개의 전용 특성 `[TenantTable]`, `[DataScope]`, `[TreeEntity]`을 통해 "테넌트 격리, 행 수준 데이터 권한, 트리형 구조"의 메타데이터를 엔터티 클래스에 선언하면, ORM 계층이 자동으로 해당 기능을 식별하고 활성화하므로 각 리포지토리마다 필터 조건을 수동으로 작성할 필요가 없습니다.

## 사전 조건

- `GameFrameX.Foundation.Orm.Attribute` 네임스페이스를 참조해야 합니다.
- 엔터티 필드는 공개 속성을 사용해야 합니다 (특성은 속성 이름을 읽음). 필드 이름은 특성 매개변수와 일치해야 합니다.

## 작업 단계

### 1. 테넌트 격리 테이블 선언

클래스에 `[TenantTable]`을 추가하고, 엔터티에는 `TenantId` 필드가 포함되어야 합니다. ORM은 현재 테넌트 컨텍스트에 따라 자동으로 필터 및 할당을 주입합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder
{
    public long Id { get; set; }
    public long TenantId { get; set; }   // 租户标识
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

출처: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L83-L94)

### 2. 행 수준 데이터 권한 선언

클래스에 `[DataScope("앵커 필드")]`를 추가하고, 필요에 따라 `DefaultScope`와 `DepartmentField`를 설정합니다. 생성자 매개변수 `scopeField`는 필수이며, null일 경우 `ArgumentNullException`이 발생합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[DataScope("CreatedUserId", DefaultScope = DataScope.Self)]
public class GameOrder
{
    public long Id { get; set; }
    public long CreatedUserId { get; set; }  // 数据范围锚点
    public string OrderNo { get; set; }
}

[DataScope("CreatedUserId",
    DefaultScope = DataScope.Department,
    DepartmentField = "CreatedDeptId")]
public class GamePlayer
{
    public long Id { get; set; }
    public long CreatedUserId { get; set; }
    public long CreatedDeptId { get; set; }
}
```

`DataScope` 열거형 지원 항목: `All`, `Department`, `DepartmentAndChild`, `Self`, `Custom`. 출처: [DataScopeAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L111-L114) 및 열거형 정의 [DataScopeAttribute.cs#L123-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L123-L164)

### 3. 트리형 구조 엔터티 선언

자기 참조 트리형 엔터티에 `[TreeEntity("ParentId")]`를 추가하고, 선택적 속성을 통해 구체화된 경로, 계층, 정렬 및 자식 노드 컬렉션을 설명합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TreeEntity(
    ParentIdField = "ParentId",
    PathField = "Path",
    LevelField = "Level",
    SortField = "Sort",
    ChildrenField = "Children")]
public class SysDept
{
    public long Id { get; set; }
    public long? ParentId { get; set; }   // 父节点
    public string Path { get; set; }      // 物化路径，如 "1.5.12"
    public int Level { get; set; }        // 层级（根为 1）
    public int Sort { get; set; }         // 同级排序
    public string Name { get; set; }
    public List<SysDept> Children { get; set; }
}
```

생성자 매개변수 `parentIdField`는 필수이며, `null`을 전달하면 `ArgumentNullException`이 발생합니다. 출처: [TreeEntityAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TreeEntityAttribute.cs#L124-L127)

## 일반적인 변형

- **세 가지 특성叠加(중첩)**: 동일한 엔터티에 여러 특성을 동시에 적용할 수 있습니다. 예를 들어 테넌트 비즈니스 테이블 + 데이터 권한 + 부서 트리 구조로 각각 격리, 권한 및 트리형 쿼리를 제어할 수 있습니다.
- **서브트리 필드만 표시**: 자식 컬렉션을 지연 로딩만 하면 되는 경우, `ChildrenField`만单独 설정하면 됩니다. 나머지 `PathField`/`LevelField`/`SortField`는 `null`로 둘 수 있습니다.
- **부서 및 하위 부서**: `DepartmentField`를 `DefaultScope = DataScope.DepartmentAndChild`와 함께 사용하면 다단계 조직의 데이터 조회에 적합합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `[DataScope]` 또는 `[TreeEntity]`에서 `ArgumentNullException` 발생 | 생성자 매개변수에 `null` 문자열 전달 | 매개변수가 `null`이 아니도록 보장 (예: `[DataScope("CreatedUserId")]`) |
| 데이터 범위 필터가 적용되지 않음 | 앵커 필드 이름이 엔터티 속성 이름과 일치하지 않음 | `ScopeField`와 속성 이름이 정확히 일치하도록 보장 (대소문자 구분) |
| 트리형 쿼리가 전체 테이블을 반환 | `ParentIdField`가 설정되지 않았거나 `[TreeEntity]` 누락 | `[TreeEntity("ParentId")]`로 명시적으로 선언 |
| `[TenantTable]`이 시스템 수준 테이블에 잘못 사용됨 | 테넌트 테이블을 전역 공유 테이블로 작성 | 테넌트 격리는 `[TenantTable]` 사용; 전역 공유 테이블은 시스템 테이블 특성 참조 (본 문서 범위 외) |

## 배경

`[TenantTable]`은 "각 행이 특정 테넌트에 속함"을 나타내며, 쿼리/삽입 시 자동으로 테넌트 조건이 적용됩니다. `[DataScope]`는 테넌트 기반 위에 "역할可见 범위"를叠加하며, `[TreeEntity]`는 엔터티 내부의 부모-자식 구조를 설명하여 재귀 및 구체화된 경로 검색을 용이하게 합니다. 세 가지는 직교(orthogonal)하여 존재하며, 비즈니스 요구에 따라 단독 또는 조합하여 사용할 수 있습니다. 출처: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L36-L82), [DataScopeAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L36-L82), [TreeEntityAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TreeEntityAttribute.cs#L36-L58)
