# 작동 원리: 빌드 후 처리와 설정 병합 프로세스

iOS 빌드가 완료되면 `PostProcessBuildHelper.OnPostProcessBuild`(콜백 우선순위 `888`)가 프로젝트 내에서 `XCodeConfig.json`이라는 이름을 가진 **모든** 파일을 자동으로 수집하여 깊은 병합으로 최종 설정 하나로 합친 뒤(채널 전용 오버라이드 포함), 두 단계에 걸쳐 설정을 생성된 Xcode 프로젝트에 기록합니다. 전체 과정에 수동 개입은 필요 없으며, 설정 파일을 프로젝트 내 아무 디렉터리에나 넣어두기만 하면 됩니다.

## 트리거 시점

진입점은 Unity의 빌드 후 처리 콜백이며, iOS 플랫폼에서만 동작합니다:

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }
    ...
}
```

출처: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L20)

메서드 본문 전체는 `try/catch`로 감싸져 있으며, 예외는 `Debug.LogException(e)`로 출력되지만 **패키징을 중단하지 않습니다**([Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L158-L161)). 클래스 전체는 `#if UNITY_IOS` 조건부 컴파일 내에 위치합니다.

## 설정 탐색 및 병합

프로세스는 다음 순서로 실행됩니다:

1. `SettingLoader.LoadSettingsData("XCodeConfig.json")`가 프로젝트 내 모든 TextAsset을 스캔하여 파일명(대소문자 구분 없이)으로 `XCodeConfig.json`과 정확히 매칭하며, 결과는 경로 순으로 정렬되어 병합 순서가 확정적으로 보장됩니다.
2. 각 파일을 읽어 `HashtableFromJson()`으로 파싱한 뒤, `finalConfig.Merge(table)`를 통해 하나의 `Hashtable`에 깊이 재귀 병합합니다.
3. 채널 식별자가 존재하면 `XCodeConfig.{channel}.json`을 로드하고 **마지막에 병합**하기 때문에 채널 설정이 가장 높은 우선순위를 가집니다.
4. 병합 결과가 비어 있으면 이후 설정을 그대로 건너뜁니다.

핵심 코드(공통 설정 병합 부분):

```csharp
var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

if (jsonPaths.Count == 0)
{
    LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
    return;
}

Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    if (table == null)
    {
        LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
        continue;
    }
    finalConfig.Merge(table);
}
```

출처: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L49)

## 채널 설정

채널명은 `SettingLoader.GetChannel()`으로 가져옵니다. 명령줄 인자 `-channel`을 우선 사용하며, 없으면 EditorPrefs 키 `XCodeBuild_Channel`로 폴백합니다:

```csharp
var args = Environment.GetCommandLineArgs();
for (int i = 0; i < args.Length - 1; i++)
{
    if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
    {
        return args[i + 1];
    }
}
string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
if (!string.IsNullOrEmpty(editorChannel))
{
    return editorChannel;
}
return null;
```

출처: [Editor/SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)

채널 설정 파일명은 기본 이름에 채널명을 조합하여 생성되며, 즉 `XCodeConfig.{channel}.json`입니다([Editor/SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111)). 매칭되면 동일한 방식으로 `finalConfig`에 병합되며, 마지막에 병합되기 때문에 동일한 키는 공통 설정을 덮어씁니다. 매칭되지 않으면 로그만 출력할 뿐 오류가 발생하지 않습니다([Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L52-L77)).

## 두 단계 적용 프로세스

병합이 완료되면 설정은 두 단계에 걸쳐 Xcode 프로젝트에 기록됩니다([Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)):

**1단계: PBXProject(project.pbxproj)에 기록**

1. `Unity-iPhone.xcodeproj/project.pbxproj`를 `PBXProject`로 읽습니다.
2. **Unity-iPhone 메인 target**에 `finalConfig["unityMain"]`을 적용합니다(`Run(...)`, 다음 섹션 참조).
3. **UnityFramework target**에 `finalConfig["unityFramework"]`를 적용합니다.
4. `SetSigning`이 서명을 설정하며(메인 target만 해당), `signing` 노드를 읽습니다.
5. `SetupSwiftBridging`이 Swift 브리징을 설정하며, 키 `swiftBridging`은 **생략 시 활성화로 간주**됩니다.
6. project.pbxproj를 다시 기록합니다.

**2단계: 기타 설정 적용**

1. `RunPlist`가 Info.Plist를 기록합니다(`plist` 노드).
2. `RunEnvironmentVariables`가 런치 환경 변수를 설정합니다(`environmentVariables`).
3. `RunArgument`가 런치 인자를 설정합니다(`launcherArgs`).
4. `SetCapabilities`가 Capabilities를 설정합니다(메인 target만), bundleId는 `signing.bundleId`에서 가져옵니다.
5. Capabilities는 `ProjectCapabilityManager`를 통해 독립적으로 디스크에 기록되기 때문에, 코드는 그 변경 사항을 유지하기 위해 project.pbxproj를 **다시 읽습니다**.
6. `RunLocalization`이 현지화를 적용합니다(`localizations`).
7. PodFile: `podfile` 키에 전체 Podfile이 지정되어 있으면 복사하여 source를 다시 작성하고, 그렇지 않으면 기존 경로로 진행하여 `unityMain.pods` / `unityFramework.pods`를 `Unity-iPhone`과 `UnityFramework` 두 target 블록에 한 줄씩 삽입합니다.
8. 마지막으로 `pod install`을 실행하며, 키 `podInstall`은 **생략 시 실행으로 간주**되고, `false`로 설정하면 건너뛸 수 있습니다.

## Run(): target 단위 설정의 8가지 하위 작업

`Run`은 1단계의 핵심으로, 단일 target에 다음 내용을 순서대로 적용합니다(`unityMain` / `unityFramework` 아래의 각 필드에 해당):

| 순서 | 메서드 | 설정 키 | 역할 |
|------|------|--------|------|
| 1 | `SetBuildProperties` | `properties` | 빌드 속성 |
| 2 | `SetFrameworks` | `frameworks` | 프레임워크 |
| 3 | `SetLibs` | `libs` | 시스템 라이브러리 |
| 4 | `RunCopyFiles` | `files` | 파일 복사 |
| 5 | `CopyFolders` | `folders` | 폴더 복사 |
| 6 | `SetFilesCompileFlag` | `filesCompileFlag` | 파일 컴파일 플래그 |
| 7 | `AddOtherLinkFlag` | `otherLinkerFlag` | Linker Flag |
| 8 | `AddRunPathSearchPaths` | `runPathSearchPaths` | Run Path Search Paths |

```csharp
static void Run(PBXProject pbxProject, string targetGuid, string mainTargetGuid, Hashtable hashtable, string path)
{
    SetBuildProperties(pbxProject, targetGuid, hashtable.Get<Hashtable>("properties"));
    SetFrameworks(pbxProject, targetGuid, hashtable.Get<Hashtable>("frameworks"));
    SetLibs(pbxProject, targetGuid, hashtable.Get<Hashtable>("libs"));
    RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
    CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
    SetFilesCompileFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("filesCompileFlag"));
    AddOtherLinkFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("otherLinkerFlag"));
    AddRunPathSearchPaths(pbxProject, targetGuid, hashtable.Get<Hashtable>("runPathSearchPaths"));
}
```

출처: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L165-L183)

각 하위 작업은 동일한 디렉터리의 partial 클래스 파일에 각각 구현되어 있습니다. 예를 들어 `PostProcessBuildHelper.BuildProperties.cs`, `PostProcessBuildHelper.Frameworks.cs`, `PostProcessBuildHelper.Plist.cs`, `PostProcessBuildHelper.PodFile.cs`, `PostProcessBuildHelper.Capabilities.cs`, `PostProcessBuildHelper.Signing.cs` 등이 있습니다.

## 최상위 설정 키 한눈에 보기

최종 병합 설정의 최상위 노드와 그 사용 방식(모두 [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L152) 참조):

| 키 | 타입 | 적용 위치 | 설명 |
|----|------|----------|------|
| `unityMain` | object | Unity-iPhone target | 메인 target의 `Run()` 8가지 하위 작업 |
| `unityFramework` | object | UnityFramework target | 위와 동일하며 Framework target에 적용 |
| `signing` | object | 메인 target만 | `SetSigning`, `bundleId` 포함 |
| `swiftBridging` | bool | 메인 target + Framework | 생략 시 `true`로 간주 |
| `plist` | object | Info.Plist | `RunPlist` |
| `environmentVariables` | object | scheme | `RunEnvironmentVariables` |
| `launcherArgs` | array | scheme | `RunArgument` |
| `capabilities` | object | 메인 target만 | `SetCapabilities`, 독립적으로 디스크에 기록 |
| `localizations` | array | 프로젝트 | `RunLocalization` |
| `podSource` | array | Podfile | `RunPodfile` / `EnsurePodfileExists` |
| `podfile` | string | Podfile | 전체 Podfile 경로 지정, 매칭되면 새 경로로 진행 |
| `podInstall` | bool | — | 생략 시 `true`로 간주; `false`이면 `pod install` 건너뜀 |

## 병합 순서와 덮어쓰기 규칙

우선순위는 낮은 것에서 높은 것 순이며, 나중에 병합된 것이 먼저 병합된 것을 덮어씁니다(깊은 병합, 동일한 키는 새 값 기준):

1. 프로젝트 내 모든 `XCodeConfig.json`(정렬된 경로 순서대로 하나씩 병합);
2. `XCodeConfig.{channel}.json` 채널 전용 설정(마지막에 병합, 최우선순위).

따라서 특정 채널에서 어떤 필드를 덮어쓰게 하려면 해당 필드를 채널 파일에 써넣기만 하면 되고, 공통 설정은 변경할 필요가 없습니다.
