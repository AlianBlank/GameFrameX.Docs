# Logger 行為（LogOptions）設定方式

使用 `LogOptions`，可以集中控制日誌的輸出目標、層級、滾動策略，以及外部儲存（檔案、MongoDB、GrafanaLoki）的所有開關。閱讀本頁後，您只需幾行程式碼即可完成自訂設定。

## 前置條件

- 已參考 `GameFrameX.Foundation` 組件，且目標框架支援 .NET。
- 若要將日誌輸出至檔案，處理程序必須對 `AppDomain.CurrentDomain.BaseDirectory/data/<logPathName>` 具備寫入權限。
- 寫入 MongoDB 需要有可存取的 MongoDB 服務；寫入 GrafanaLoki 需要有可存取的 Loki 服務。
- 型別命名空間：`GameFrameX.Foundation.Logger`，主要型別：`LogOptions`、`RollingInterval`（Serilog）、`LogEventLevel`（Serilog.Events）。

## 設定項目一覽

| 屬性 | 型別 | 預設值 | 說明 |
|------|------|--------|------|
| `LogSavePath` | `string` | `<BaseDir>/data/logs` | 日誌檔案的絕對路徑。由建構函式串接 `logPathName` 產生 |
| `LogFileName` | `string` | `""`（預設名稱） | 日誌檔案名稱。為空時使用預設名稱 |
| `LogType` | `string` | `null` | 日誌產生來源的伺服器類型 |
| `LogTagName` | `string` | `""` | 用於日誌分類的標籤 |
| `IsWriteToFile` | `bool` | `true` | 是否輸出至檔案 |
| `IsConsole` | `bool` | `true` | 是否同時輸出至主控台 |
| `IsFileSizeLimit` | `bool` | `true` | 是否限制單一檔案的大小 |
| `FileSizeLimitBytes` | `int` | `100 * 1024 * 1024` | 單一檔案的上限位元組數。到達後即滾動 |
| `RetainedFileCountLimit` | `int?` | `31` | 保留的歷史日誌數量。`null` 表示無限制 |
| `RollingInterval` | `RollingInterval` | `Day` | 滾動間隔（Hour/Day/Month 等） |
| `LogEventLevel` | `LogEventLevel` | `Debug` | 最低輸出層級。低於此層級的日誌不會被記錄 |
| `IsWriteToMongoDb` | `bool` | `false` | 是否寫入 MongoDB |
| `MongoDbDatabaseUrl` | `string` | `mongodb://127.0.0.1:27017/gameserver?authSource=admin` | MongoDB 連線字串 |
| `MongoDbCappedMaxSizeMb` | `int` | `50` | MongoDB 固定大小集合（Capped Collection）的最大 MB |
| `MongoDbCappedMaxDocuments` | `int` | `50000` | MongoDB 固定大小集合（Capped Collection）的最大文件數 |
| `IsGrafanaLoki` | `bool` | `false` | 是否輸出至 GrafanaLoki |
| `GrafanaLokiUrl` | `string` | `http://localhost:3100` | Loki 服務位址 |
| `GrafanaLokiLabels` | `Dictionary<string,string>` | 空 | Loki 標籤 |
| `GrafanaLokiProperty` | `Dictionary<string,string>` | 空 | Loki 額外屬性 |
| `GrafanaLokiUserName` / `GrafanaLokiPassword` | `string` | `null` | Loki 驗證 |
| `GrafanaLokiCompressionEnabled` | `bool` | `true` | Loki 推送時是否啟用壓縮 |
| `GrafanaLokiBatchSizeLimit` | `int` | `1000` | 批次閾值。到達即推送 |
| `GrafanaLokiQueueLimit` | `int` | `100000` | 記憶體佇列上限。達到上限時丟棄日誌 |
| `GrafanaLokiPeriod` | `int`（秒） | `2` | 強制推送週期；若傳入 `<=0` 則回退為 2 |

屬性預設值與定義的參考來源：[LogOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L47-L289)。

## 操作步驟

1. **引入命名空間並建立執行個體**。預設執行個體可直接從 `LogOptions.Default` 使用。也可以使用 `CreateDefault()` 取得可個別修改的副本。

```csharp
using GameFrameX.Foundation.Logger;

// 直接重複使用預設設定（建議唯讀情境）
var defaults = LogOptions.Default;

// 取得可修改的副本
var options = LogOptions.CreateDefault();
options.LogTagName = "GameServer-01";
```

Source: [LogOptions.cs#L69-L82](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L69-L82)

2. **視需要調整輸出目標與檔案策略**。常見組合：停用檔案僅輸出至 Loki，或相反。

```csharp
var options = LogOptions.CreateDefault();

// 檔案策略
options.IsWriteToFile = true;
options.RollingInterval = RollingInterval.Day;   // 每日滾動
options.IsFileSizeLimit = true;
options.FileSizeLimitBytes = 50 * 1024 * 1024;   // 50MB
options.RetainedFileCountLimit = 14;             // 僅保留 14 天

// 主控台
options.IsConsole = true;

// 層級
options.LogEventLevel = LogEventLevel.Information;
```

Source: [LogOptions.cs#L243-L277](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L243-L277)

3. **連線 MongoDB**（選用）。

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToMongoDb = true;
options.MongoDbDatabaseUrl = "mongodb://user:password@192.168.1.100:27017/gameserver?authSource=admin";
options.MongoDbCappedMaxSizeMb = 200;
options.MongoDbCappedMaxDocuments = 100000;
```

若 `IsWriteToMongoDb=true`，則必須設定有效的 `MongoDbDatabaseUrl`。連線字串的格式請參考原始檔案中的範例。Source: [LogOptions.cs#L108-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L108-L145)

4. **連線 GrafanaLoki**（選用）。啟用 Loki 時，需要設定服務位址、標籤與驗證。調整批次參數可控制吞吐量與背壓。

```csharp
var options = LogOptions.CreateDefault();
options.IsGrafanaLoki = true;
options.GrafanaLokiUrl = "http://loki.internal:3100";
options.GrafanaLokiUserName = "loki";
options.GrafanaLokiPassword = "secret";
options.GrafanaLokiLabels["app"] = "gameserver";
options.GrafanaLokiLabels["env"] = "prod";
options.GrafanaLokiBatchSizeLimit = 2000;     // 累積 2000 筆後推送
options.GrafanaLokiQueueLimit = 200000;       // 記憶體佇列上限
options.GrafanaLokiPeriod = 5;                // 每 5 秒強制推送
options.GrafanaLokiCompressionEnabled = true;
```

注意：若向 `GrafanaLokiPeriod` 傳入 `<=0`，將強制回退為 2 秒。佇列滿時，新日誌會被丟棄（背壓保護）。Source: [LogOptions.cs#L168-L235](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L168-L235)

5. **將 `LogOptions` 傳遞給日誌元件的初始化入口點**。之後即可使用 `LogHelper.Info/Debug/...` 進行輸出。

```csharp
// 假設日誌入口點需要 LogOptions
LogHelper.Init(options);

LogHelper.Info("服务启动完成");
LogHelper.Debug("调试信息:玩家 {0} 进入副本", playerId);
```

> 呼叫入口點名稱請依您專案中參考的初始化方式為準（在本儲存庫中，`LogOptions` 類別本身不負責日誌通道的初始化）。

## 常見變化

- **區分多租戶／多伺服器的日誌**：設定 `LogType` 與 `LogTagName`。檔案路徑位於 `LogSavePath` 之下，可為每個伺服器分開目錄管理。
- **在建構函式中自訂根目錄**：使用 `new LogOptions("gateway-logs")` 時，日誌將放置於 `<BaseDir>/data/gateway-logs`。為空時回退為 `logs`。

```csharp
var options = new LogOptions("gateway-logs");
options.LogType = "Gateway";
options.LogTagName = "GW-01";
```

Source: [LogOptions.cs#L53-L61](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L53-L61)

- **停用檔案僅使用 Loki**：適合容器化部署，可集中彙整日誌。

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToFile = false;
options.IsConsole = false;
options.IsGrafanaLoki = true;
```

- **保留檔案數設為無限制**：`options.RetainedFileCountLimit = null;`。

## 常見錯誤

| 症狀／誤用 | 原因 | 修正方式 |
|----------|------|------|
| 日誌檔案未出現在預期目錄 | 誤以為 `LogSavePath` 的預設值是當前目錄 | 實際預設值為 `<AppDomain.BaseDirectory>/data/logs`。可透過建構函式引數 `logPathName` 調整 |
| 啟用 MongoDB 後寫入失敗 | `MongoDbDatabaseUrl` 未設定，或 MongoDB 未在監聽 | 依照原始檔案中的範例填入連線字串，並確認服務可用 |
| 幾乎不會推送至 Loki | `GrafanaLokiBatchSizeLimit` 與 `Period` 的值過大 | 調小批次閾值或 `Period`。若 `Period<=0` 則強制回退為 2 秒 |
| 磁碟使用量暴增 | `RetainedFileCountLimit` 未設定，或 `IsFileSizeLimit=false` | 設定適當的保留數量（如 14／31），並啟用單一檔案大小限制 |
| 對 `LogOptions.Default` 的修改未生效 | `Default` 是唯讀的靜態執行個體，且為所有地方共享 | 使用 `CreateDefault()` 取得獨立副本後再修改 |

## 背景（選用）

`LogOptions` 是 POCO（僅含屬性的物件），不會直接建構 Serilog 管線。實際使用這些開關的初始化邏輯存在於日誌入口點的實作中。在設計上，將「如何記錄」與「記錄到哪裡」分離。層級、滾動、壓縮是通用策略，而檔案／MongoDB／Loki 是可個別啟用的 sink。

關於整體日誌初始化與 `LogHelper` 的使用方式，請參閱《Logger 快速入門》。
