# IL2CPP ビルド後に UI 機能が異常になる場合の対処方法

IL2CPP でビルドした後、Unity のマネージドコードストリッピング(Managed Code Stripping)によって、FairyGUI 内のリフレクション/文字列でのみ参照されている型が削除され、UI が表示されない、コンポーネントが失われる、ボタンが反応しない、または logcat/Xcode コンソールに `NullReferenceException` や `TypeLoadException` などの例外が表示されることがあります。このページでは、調査と修正の手順を示します:`link.xml` の有効化の確認、`FairyGUICroppingHelper` を起動シーンにアタッチ、ストリッピングレベルの調整。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| ビルド後に UI が表示されない / 一部コンポーネントが空になる | マネージドコードストリッピングにより、静的に参照されていない型が削除された | `Runtime/link.xml` がパッケージに含まれていることを確認、[修正手順 1](#手順-1linkxml-がパッケージに含まれていることを確認) を参照 |
| コンソールに `FairyGUI.*` 型に関わる `NullReferenceException` / `TypeLoadException` が報告される | リフレクションで生成される型(UI パッケージのコンポーネントなど)がストリッピングされた | `FairyGUICroppingHelper` ストリッピング防止スクリプトをアタッチ、[修正手順 2](#手順-2fairyguicroppinghelper-を起動シーンにアタッチ) を参照 |
| Editor では正常、実機では異常；非同期でのアセットバンドル読み込みのコールバックが返らない | `AsyncCreationHelper` などのコールバック用の型がストリッピングされた | 同上、`FairyGUICroppingHelper.Start()` は `AsyncCreationHelper` を明示的に参照している |
| ストリッピングレベルが高すぎる(Medium/High)場合に問題が再現する | IL2CPP はデフォルトで、リフレクションでのみ使用されるアセンブリを除去する | Managed Stripping Level を下げるか `link.xml` を利用する、[修正手順 3](#手順-3managed-stripping-level-の調整) を参照 |

## 修正手順

### 手順 1:link.xml がパッケージに含まれていることを確認

本パッケージには `Runtime/link.xml` が同梱されており、`FairyGUI.Runtime` アセンブリ全体を `preserve="all"` に設定しています:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="FairyGUI.Runtime" preserve="all"/>
</linker>
```

出典: [Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/link.xml#L1-L4)

確認ポイント:

1. `Runtime/link.xml` がプロジェクト内に存在することを確認してください(Package Manager 経由でインストールした場合、パッケージに同梱されています)。
2. FairyGUI のソースコードを自分のプロジェクトにコピーしている場合は、`link.xml` の `fullname` が実際のアセンブリ名と一致していることを確認してください(アセンブリの `.asmdef` 名を参照)。名前が一致しない場合、このファイルは有効になりません。
3. ビルドログ内で `link.xml` を検索し、ビルド時にこの linker 記述が適用されたことを確認してください。

### 手順 2:FairyGUICroppingHelper を起動シーンにアタッチ

パッケージにはストリッピング防止スクリプト `FairyGUICroppingHelper` が用意されており、`Start()` 内ですべての FairyGUI 型を明示的に参照して、ストリッパーによる削除を防ぎます:

```csharp
/// <summary>
/// コード実行時にストリッピングによるエラーが発生するのを防止します。このスクリプトを起動シーンに追加してください。ロジックには一切影響しません
/// </summary>
[Preserve]
public class FairyGUICroppingHelper : MonoBehaviour
{
    [Preserve]
    void Start()
    {
        _ = typeof(FairyGUI.AlignType);
        _ = typeof(FairyGUI.Anymous_T);
        _ = typeof(FairyGUI.AsyncCreationHelper);
        // ...以下、順番にすべての FairyGUI 型を参照しています
```

出典： [Runtime/FairyGUICroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/FairyGUICroppingHelper.cs#L6-L17)

操作：起動(最初の)シーンに空の GameObject を新規作成し、`Add Component` で `FairyGUICroppingHelper` を追加するだけです。このスクリプトは実行ロジックには一切影響を与えず、型の保持のみを目的としています。

### 手順 3:Managed Stripping Level の調整

**Project Settings → Player → Other Settings → Optimization** で:

| ビルドターゲット | 設定項目 | 推奨値 |
|------------|--------|--------|
| Android | Managed Stripping Level | Low または Disabled(問題の切り分けにはまず Disabled に設定) |
| iOS | Managed Stripping Level | Low または Disabled |

設定を下げてから再ビルドしてください。`Disabled` では正常だがレベルを上げると異常になる場合は、依然として `link.xml` / `[Preserve]` による型の保持が必要であることを意味します。ストリッピングを恒久的に無効化するのではなく、まず手順 1 と 2 を優先的に実行してください。

## 検証

1. IL2CPP で再ビルドし、実機にインストールします。
2. 以前異常が発生した画面を表示し、UI が正常に表示されること、ボタン/非同期読み込みにコールバックがあることを確認します。
3. logcat(Android)または Xcode コンソール(iOS)で、`FairyGUI.*` に関連する `NullReferenceException` / `TypeLoadException` が発生しなくなったことを確認します。
4. ビルド出力の `IL2CPP` 生成ディレクトリ(例:`Temp/StagingArea/Data/Il2CppOutputDirectory`)で、以前欠落していた型名を検索し、ストリッピングされていないことを確認できます。
