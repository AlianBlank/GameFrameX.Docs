# 動作原理：コンポーネントの初期化とイベントディスパッチのフロー

`GameAnalyticsComponent` はシーンにアタッチされる Unity コンポーネントです。`Awake` で自動登録を無効化し、`OnEnable` で Inspector 上に設定された Provider リストを読み込み、リフレクションによって各 `IGameAnalyticsManager` をインスタンス化し、設定辞書を渡して初期化を完了します。以降、すべての送信呼び出し（`Event` / タイマー / 共通プロパティ）はこれらのマネージャーを巡回して逐一ディスパッチされ、初期化ガードと警告ログを伴います。本ページでは、この 2 つの経路の実際の実行順序とコード上の場所を説明します。

## 初期化フロー（アタッチから利用可能まで）

1. **コンポーネントのアタッチ**：`GameAnalyticsComponent` は `GameFrameworkComponent` を継承し、`[DisallowMultipleComponent]` と `[AddComponentMenu("Game Framework/GameAnalytics")]` を持つため、同一 GameObject には 1 つしかアタッチできません。
2. **`Awake` 段階**：マネージャーのリストを作成し、コンポーネントの自動登録を無効化（`IsAutoRegister = false`）してから、基底クラスの `Awake()` を呼び出します：

```csharp
protected override void Awake()
{
    m_GameAnalyticsManager = new List<IGameAnalyticsManager>();
    IsAutoRegister = false;
    base.Awake();
}

private void OnEnable()
{
    Init();
}
```

ソース: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L20-L30)

3. **`OnEnable` による `Init()` の呼び出し**：`Init()` は `m_IsInit` による冪等性の保護があり、重複呼び出しは即座に return されます。
4. **Provider の逐次処理**：シリアライズフィールド `m_gameAnalyticsComponentProviders`（Inspector で設定）を巡回し、各項目に対して以下を行います：
   - `ComponentType` が空白文字列の場合、そのエントリをスキップします。
   - `Utility.Assembly.GetType` によって型名から `System.Type` を解決し、解決に失敗した場合はエラーログを記録して `continue` します（エラー原文：`Can not find component type '{型名}'.`）。
   - `Activator.CreateInstance` によるリフレクションでインスタンスを生成し、それが `IGameAnalyticsManager` を実装していることを要求します。
   - Provider の `Setting` のキーと値のペアを `Dictionary<string, string>` として収集して `args` とし、`gameAnalyticsManager.Init(args)` を呼び出した後、`m_GameAnalyticsManager` リストに追加します。
5. **`m_IsInit = true` を設定**し、初期化が完了します。以降、すべてのイベント呼び出しが有効になります。

```csharp
public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }

            if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
            {
                Dictionary<string, string> args = new Dictionary<string, string>();
                foreach (var param in gameAnalyticsComponentProvider.Setting)
                {
                    args[param.Key] = param.Value;
                }

                gameAnalyticsManager.Init(args);
                m_GameAnalyticsManager.Add(gameAnalyticsManager);
            }
        }
    }

    m_IsInit = true;
}
```

ソース: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L47-L80)

6. **（任意）手動初期化**：`IsManualInit()` が `true` を返すマネージャー（例：ログイン後のチケットなど、実行時にしか取得できないパラメータを必要とするもの）に対しては、コンポーネントの初期化後に `ManualInit(extraArgs)` を呼び出して二次注入を行います：

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

## イベントディスパッチのフロー

`Event(string eventName)` を例にとると、毎回の送信は 4 つの層を経由します：

1. `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))`：イベント名が空の場合、即座にガード例外をスローします。
2. コンポーネントレベルのガード：`m_IsInit == false` の場合は黙って return します（コンポーネント未初期化のため、イベントは破棄されます）。
3. `m_GameAnalyticsManager` を巡回し、各マネージャーに対して `IsInit()` をチェックします。
4. マネージャーが初期化済みであれば同名のメソッドを呼び出して実際の送信を行い、そうでなければ警告 `GameAnalyticsManager is not init.` を出力してそのマネージャーをスキップします（他のマネージャーのディスパッチ継続には影響しません）。

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

ソース: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

`StartTimer` / `StopTimer` はまったく同じガードと警告ロジックを通ります（[GameAnalyticsComponent.cs#L160-L179](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179) と [#L221-L240](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L221-L240) を参照）。`PauseTimer` / `ResumeTimer` / `SetPlayerId` は非空ガードとコンポーネントレベルの `m_IsInit` チェックのみを行い、個々のマネージャーの `IsInit()` 判定は行いません。`Event` には 4 つのオーバーロードがあります：`Event(string)`、`Event(string, float)`、`Event(string, Dictionary<string, object>)`、`Event(string, float, Dictionary<string, object>)` で、ディスパッチ方式は同一です。

## ガードとログのクイックリファレンス

| 発動条件 | 動作 / ログ原文 | 場所 |
|------|------|------|
| Provider の `ComponentType` から型を解決できない | `Log.Error($"Can not find component type '{...}'.")`、その Provider をスキップ | `Init()` 内 |
| `eventName` が空/null | `GameFrameworkGuard.NotNullOrEmpty` がスロー | 各タイマー/イベントメソッドの先頭 |
| コンポーネント未初期化（`m_IsInit == false`） | 黙って return、エラーなし | すべてのディスパッチメソッド |
| あるマネージャーが未初期化（`IsInit() == false`） | `Log.Warning("GameAnalyticsManager is not init.")`、そのマネージャーをスキップ | `Event` / `StartTimer` / `StopTimer` |
| `SetPublicProperties` の key が空 | サブクラス内で即座に `return`、書き込まない | `BaseGameAnalyticsManager` |

## 共通プロパティの注入とディスパッチ

マネージャーの基底クラス `BaseGameAnalyticsManager` は `GameFrameworkModule` を継承しており（そのため各マネージャー自体もフレームワークモジュールであり、`Update` / `Shutdown` のライフサイクルフックを持ちます。基底クラスでは空実装です）、`m_PublicProperties` 辞書を保持しています：

- `SetPublicProperties(key, value)`：key が空なら即座に return、そうでなければ辞書に書き込みます。
- `ClearPublicProperties()`：辞書を空にした後、**直ちにデバイス情報を再注入します**。
- `GetPublicProperties()`：辞書のシャローコピーを返します。

```csharp
public virtual void ClearPublicProperties()
{
    m_PublicProperties.Clear();
    AddDeviceInfoToPublicProperties();
}
```

ソース: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L70-L74)

`AddDeviceInfoToPublicProperties()` は `protected virtual` で、デフォルトで注入される共通プロパティには以下が含まれます：デバイス（`device_id` / `device_model` / `device_type`）、システム（`os` / `system_language` / `current_culture`）、アプリ（`app_version` / `unity_version` / `platform`）、CPU とメモリ（`processor_type` / `processor_count` / `processor_frequency` / `system_memory_size`）、グラフィックス（`graphics_device_name` など 5 項目）、画面（`screen_width` / `screen_height` / `screen_dpi` / `screen_refresh_rate`）、および `Application.internetReachability` から導出される `network_type`（値は `No Network` / `Mobile Data` / `WiFi` / `Unknown`）。サブクラスはこれをオーバーライドしてプロパティを追加・削除できます。完全な実装は [BaseGameAnalyticsManager.cs#L88-L144](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L88-L144) を参照してください。

コンポーネント層の `GetPublicProperties()` は**最初の**マネージャーのプロパティ辞書のみを返します（巡回中の最初のヒットで即座に `return`）。複数の Provider が並存する場合は、リストの先頭にあるものが優先されます。

## カスタム Provider の接続ポイント

新しい分析プラットフォームを追加する場合、`IGameAnalyticsManager` を実装する必要があります（または `BaseGameAnalyticsManager` を直接継承して共通プロパティのロジックを再利用することも可能です）。インターフェースが要求する実装は以下の通りです：`Init(Dictionary<string, string>)`、`ManualInit(Dictionary<string, string>)`、`IsInit()`、`IsManualInit()`、共通プロパティの 3 点セット、`StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer`、4 つの `Event` オーバーロード、および `SetPlayerId`。完全なインターフェース定義は [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L46) を参照してください。その後、Inspector で実装クラスの型名を Provider リストに入力し、`Setting` のキーと値のペアを設定すれば、上記の初期化フローによって自動的にインスタンス化され、イベントディスパッチに組み込まれます。

## よくあるエラー

- **Provider を設定したのにイベントが一切送信されない**：まず Console に `Can not find component type '...'` が出ていないか確認してください――型名のスペルミスや、アセンブリがビルドに含まれていないことが原因で、その Provider はスキップされます。次に、実装クラスに引数なしのコンストラクタがあるかを確認してください（`Activator.CreateInstance` はデフォルトコンストラクタを使用します）。
- **`GameAnalyticsManager is not init.` 警告が繰り返し表示される**：コンポーネント層は初期化済み（`m_IsInit == true`）だが、あるマネージャー自身が `Init(args)` の後に内部状態を初期化済みに設定していないことを意味します。実装クラス側の問題であり、コンポーネントには関係ありません。
- **ログイン前に呼び出した `Event` が黙って破棄される**：コンポーネント未初期化の状態では、すべてのディスパッチメソッドが即座に `return` し、ログは出力されません。`OnEnable` が実行済みか、`Init()` が呼び出されたかを確認してください。
- **`ClearPublicProperties` を実行しても共通プロパティが「完全に消えない」**：これは設計上の動作です――空にした後はデバイス情報が自動的に再書き込みされるため、デバイス関連のフィールドは常に存在します。

## 背景

コンポーネントは `IsAutoRegister = false` によって、GameFrameX のコンポーネント自動登録メカニズムが先行して介入するのを防ぎ、初期化のタイミングが完全に `OnEnable` によって制御されることを保証しています。また「リフレクション + 型名文字列」で Provider をロードすることで、本パッケージは具体的なプラットフォーム SDK を一切参照せずにマルチプラットフォームの並列送信を設定でき、イベントは 1 回の呼び出しですべての初期化済みマネージャーへブロードキャストされます。
