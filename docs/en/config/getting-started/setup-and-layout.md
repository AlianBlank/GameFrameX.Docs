# Environment Setup and Directory Structure

This page walks you through preparing the runtime environment for GameFrameX.Config, understanding the repository's directory conventions, and completing the first successful run of the Luban configuration toolchain.

## Prerequisites

| Item | Requirement | Purpose |
|------|------|------|
| .NET SDK | 6.0 or later | Run `Tools/Luban.dll` (see `toolPath` in `luban.conf`) |
| Excel editor | Microsoft Excel / WPS / LibreOffice | Edit the xlsx files under `Excels/` |
| Unity project | For the client target (`Hotfix/Config/Generate`) | Receives the generated C# code and JSON data |
| Server project | For the server target (`Server.Config/Config`) | Receives the generated C# code and JSON data |

> The `*.bat` and `*.sh` scripts in the repository root already have the default paths `../Unity/Assets/` and `../Server/GameFrameX.Config/` written in, so the repository is usually placed side by side with the Unity/Server projects.

## Quick Start

1. Place the repository at the same level as the Unity project. The directory structure typically looks like this:

   ```
   parent/
   ├── GameFrameX.Config/      # Current repository
   │   ├── Luban.conf
   │   ├── Defines/
   │   ├── Excels/
   │   └── Tools/Luban.dll
   ├── Unity/                  # Unity project
   │   └── Assets/Hotfix/Config/Generate
   └── Server/                 # Server project
       └── GameFrameX.Config/
           ├── Json/
           └── Config/
   ```

2. Run the corresponding generation script for your operating system (the scripts are simply wrappers around `dotnet ./Tools/Luban.dll ...`):

   - Windows + JSON output: `gen-server-json.bat` / `gen-client-json.bat`
   - Windows + binary output: `gen-server-bin.bat` / `gen-client-bin.bat`
   - Linux/macOS: the corresponding `.sh` files

3. Fill in `UNITY_ASSETS_PATH` and `SERVER_PATH` in `luban.conf` as needed (when left empty, the script's default relative paths are used).

## Directory Structure

| Path | Purpose |
|------|------|
| `Luban.conf` | Luban main configuration: groups, schemas, data directory, generation commands |
| `Defines/` | bean/enum/table definitions in XML form (`builtin.xml` registers `vec2/vec3/vec4`) |
| `Excels/__tables__.xlsx` | Table registry (declares which xlsx files are configuration tables) |
| `Excels/__beans__.xlsx` | bean registry (complex data structures) |
| `Excels/__enums__.xlsx` | Enum registry |
| `Excels/Tables/` | The actual configuration tables (named `C-TableName-ChineseName.xlsx`) |
| `Excels/Local/` | Localization tables (`L-Localization-*.xlsx`) |
| `Tools/` | Contains `Luban.dll`, referenced by `toolPath` |
| `gen-*.bat` / `gen-*.sh` | Various generation entry scripts |

## Configuration Script (`Luban.conf` Overview)

[Luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L95) centrally manages schemas and generation commands. The key fields are as follows:

| Field | Meaning |
|------|------|
| `groups` | Groups (default: `c` for client, `s` for server) |
| `schemaFiles` | Registered schema files (`Defines`, `__tables__.xlsx`, etc.) |
| `dataDir` | Data root directory (`Excels`) |
| `targets` | Three output targets: `server` / `client` / `all`, using `GameFrameX.Config`, `Hotfix.Config`, and `cfg` respectively as the top-level namespace |
| `toolPath` | Relative path to Luban.dll |
| `commands` | The actual Luban command lines; `active` controls whether each one runs |

By default, `commands` provides two sets, JSON and bin (4 entries in total for client/server). Those with `active: false` can be enabled when needed. Example snippet:

```json
{
  "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

> `%UNITY_ASSETS_PATH%` and `%SERVER_PATH%` are declared at the top of `Luban.conf`; when left empty, the generation scripts fill them in with relative paths.
