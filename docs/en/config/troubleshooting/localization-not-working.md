# What to Do When Localization Text Doesn't Take Effect

When you add or modify multilingual entries in `Excels/Local/` but don't see the new text at runtime, it is usually because **Luban did not scan the corresponding localization table**, or **localization parameters were not included during code generation**. This page provides common symptoms and quick fix paths.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| After startup, only Keys (e.g., `Text_001`) are shown instead of translations | The localization file was not loaded by LuBan | Confirm the generation command includes `-x l10n.textFile.path=./Excels/Local/` |
| Newly added `L-Localization-*.xlsx` has no effect | The file name does not match the `L-Localization-` prefix, or the file was not placed in `Excels/Local/` | Rename it to `L-Localization-<category>.xlsx` and put it in the `Excels/Local/` directory |
| Field missing errors still occur after generating `Localization.xlsx` | `localizationFileName` is not configured or is misspelled in `luban.conf` | Add `"localizationFileName": "Localization.xlsx"` to the command of the corresponding target |
| Source language text is still displayed after switching languages | Runtime code did not reload the localization table / regeneration was not triggered | Delete old generated artifacts and re-run `gen-client-json.sh` (or the corresponding .bat) |
| Remote text is an empty string after the client is packaged | The JSON data directory (e.g., `Bundles/Config`) was not refreshed | Re-run `gen-client-bin.sh` so the generated JSON overwrites `outputDataDir` |

## Fix Steps

### 1. Confirm the Localization File Location and Naming

Localization files must be placed in the `Excels/Local/` directory and start with `L-Localization-`. The repository's example already includes 3 localization files:

- `Excels/Local/L-Localization-UI.xlsx`
- `Excels/Local/L-Localization-成就.xlsx`
- `Excels/Local/L-Localization-文本.xlsx`

Any newly added localization file must follow the same naming rule.

### 2. Enable Localization in the Generation Command

The `gen-client-json.sh` included in the repository already explicitly passes in the localization-related parameters:

```bash
dotnet ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json \
  --xargs outputDataDir=../Unity/Assets//Bundles/Config \
  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
  --xargs tableImporter.name=gameframex \
  -x l10n.provider=gameframex \
  -x l10n.textFile.keyFieldName=key \
  -x l10n.textFile.path=./Excels/Local/ \
  --conf ./Luban.conf
```

Source: [gen-client-json.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.sh#L1-L1)

If your command is missing `-x l10n.textFile.path=./Excels/Local/` or `-x l10n.provider=gameframex`, add them and regenerate.

### 3. Declare `localizationFileName` in `luban.conf`

In `luban.conf`, you need to add the `localizationFileName` field to the target that generates localization data (default name `Localization.xlsx`):

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

### 4. Regenerate and Overwrite Artifacts

- Client JSON: `gen-client-json.sh` (or `gen-client-json.bat`); artifacts land in `%UNITY_ASSETS_PATH%/Bundles/Config`.
- Client binary: `gen-client-bin.sh`; artifacts also go to `Bundles/Config`, but the output format is `cs-bin`.
- Server: The server currently does not need localization (the `server` target has no `localizationFileName`). If you truly need to enable multilingual support for the server, simply refer to the `client` configuration and add the `localizationFileName` field.

### 5. Check the Header and `keyFieldName`

`-x l10n.textFile.keyFieldName=key` means the localization table must have a column named `key`. If your header column name is not `key` (e.g., written as `Key` or `ID`), reading will fail. Solution: rename the first column to `key` in Excel, or change `keyFieldName` in the generation command to the actual column name in your table.

## Verification

1. Re-run the corresponding generation script and confirm that the `active: true` configuration has not been turned off.
2. Check whether the output directory (e.g., `Bundles/Config` or `%SERVER_PATH%/Server.Config/Json`) has generated and refreshed `Localization.xlsx` and its derived data.
3. Read localization by `key` in runtime code; after switching languages, it should return the corresponding translation rather than an empty string or the source language.
4. If you still only see the `key` itself, it means the localization data was not loaded — go back to step 2 and check whether the command includes `-x l10n.textFile.path`, and whether `L-Localization-*.xlsx` files actually exist under `Excels/Local/`.
