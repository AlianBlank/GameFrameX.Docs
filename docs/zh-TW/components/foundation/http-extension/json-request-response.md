# JSON 請求主體的傳送與回應解析方法

使用 `HttpClientJsonExtension` 的 `PostJsonAsync / PutJsonAsync / PatchJsonAsync / SendJsonAsync` 等擴充方法，即可在一個步驟內完成 JSON 請求主體的傳送，以及將回應反序列化為目標型別。若想自行控制狀態碼，或讀取原始回應主體，請使用 `*ResponseAsync` 系列方法，並以 `HttpClientResponse.As<T>()` 進行反序列化。

## 前置條件

- 參考 NuGet 套件 `GameFrameX.Foundation.Http.Extension`(`GameFrameX.Foundation.Http.Normalization` 用於統一 JSON 回應包裝器)。
- 已建立或已注入 `HttpClient` 執行個體(建議透過 `IHttpClientFactory` 管理生命週期)。
- .NET 6+(`HttpClientJsonExtension` 相依於 `System.Net.Http.Json.JsonContent`)。

## 操作步驟

### 1. 直接取得強型別回應(最常見)

`PostJsonAsync<TRequest, TResponse>` 會將請求物件序列化為 JSON、POST 至目標 URL,並將成功回應(2xx)反序列化為 `TResponse`。若狀態不是成功，會擲回 `HttpClientRequestException`,其中包含狀態碼、請求 URI 與回應主體。

```csharp
using System.Net.Http;
using System.Threading.Tasks;
using GameFrameX.Foundation.Http.Extension;

var httpClient = new HttpClient { BaseAddress = new System.Uri("https://api.example.com") };

var request = new CreateOrderRequest
{
    Sku = "SKU-001",
    Quantity = 2
};

CreateOrderResponse? response = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request);

System.Console.WriteLine(response?.OrderId);
```

```csharp
public sealed class CreateOrderRequest
{
    public string Sku { get; set; }
    public int Quantity { get; set; }
}

public sealed class CreateOrderResponse
{
    public string OrderId { get; set; }
    public string Status { get; set; }
}
```

### 2. 自訂 JSON 序列化、Header、逾時與重試

透過 `HttpClientRequestOptions` 注入 `JsonSerializerOptions`、請求標頭、逾時與重試策略。擴充方法會在請求/回應/重試時自動觸發回呼，方便進行日誌記錄與事件測量。

```csharp
using System.Text.Json;
using GameFrameX.Foundation.Http.Extension;

var options = new HttpClientRequestOptions
{
    Timeout = System.TimeSpan.FromSeconds(10),
    JsonSerializerOptions = new JsonSerializerOptions
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase
    }
};
options.Headers["Authorization"] = "Bearer xxx";
options.Retry.MaxRetries = 3;
options.OnResponse = e =>
    System.Console.WriteLine($"[{e.Attempt}] {e.Method} {e.RequestUri} -> {(int)e.StatusCode}");

var result = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    options);
```

`HttpClientRetryOptions` 預設會在 `RequestTimeout / TooManyRequests / InternalServerError / BadGateway / ServiceUnavailable / GatewayTimeout` 時觸發重試，基本退避為 100ms × `BackoffFactor=2` 的指數遞增。POST/PATCH 預設不會重試，必要時請設定 `AllowNonIdempotentRetry = true`。

### 3. 取得原始回應(狀態碼 + Body + Header)

若想依據狀態碼分支處理，或想先讀取錯誤主體再決定反序列化方式，請使用 `*ResponseAsync` 系列。`HttpClientResponse.As<T>()` 會使用與請求相同的 `JsonSerializerOptions` 來解析 Body。

```csharp
using GameFrameX.Foundation.Http.Extension;

var resp = await httpClient.PostResponseAsync<CreateOrderRequest>(
    HttpMethod.Post,
    "/orders",
    request);

System.Console.WriteLine($"status={resp.StatusCode} attempt={resp.Attempt}");

if (!resp.IsSuccessStatusCode)
{
    // 失敗時也能取得 Body,便於統一錯誤回報
    System.Console.WriteLine($"error body: {resp.Body}");
    return;
}

CreateOrderResponse? ok = resp.As<CreateOrderResponse>();
System.Console.WriteLine(ok?.OrderId);

// 明確斷言成功;失敗時會擲回 HttpClientRequestException
resp.EnsureSuccessStatusCode();
```

### 4. 傳送任意方法 + JSON 請求主體

`SendJsonAsync<TRequest, TResponse>(HttpMethod method, …)` 是基礎進入點，其他 POST/PUT/PATCH 多載全都委派至此。可用於自訂方法或第三方 WebHook。

```csharp
var result = await httpClient.SendJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    HttpMethod.Post,
    "https://api.example.com/orders",
    request);
```

### 5. 沒有請求主體的 JSON 呼叫

在 GET/DELETE/OPTIONS 等沒有 Body 的情境下，請使用 `GetJsonAsync<TResponse>`、`DeleteJsonAsync<TResponse>` 等單一型別參數的多載。

```csharp
OrderList? list = await httpClient.GetJsonAsync<OrderList>("/orders?status=open");
```

## 常見變化

### 統一回應包裝器 `IHttpJsonResult`

許多後端使用 `{ code, message, data }` 形式的回傳值；使用 `GameFrameX.Foundation.Http.Normalization` 的 `IHttpJsonResult<T>` / `HttpJsonResultHelper`,擴充功能即可自動驗證 `code` 欄位並取出 `data`。

```csharp
using GameFrameX.Foundation.Http.Normalization;

var resp = await httpClient.PostJsonAsync<CreateOrderRequest, HttpJsonResult<CreateOrderResponse>>(
    "/orders",
    request);

HttpJsonResult<CreateOrderResponse> ok = HttpJsonResultHelper.EnsureSuccess(resp);
CreateOrderResponse data = ok.Data;
```

### 取消權杖

所有擴充方法皆支援 `CancellationToken`,可直接與 ASP.NET Core 的 `HttpContext.RequestAborted` 串接。

```csharp
var resp = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    cancellationToken: HttpContext.RequestAborted);
```

## 常見錯誤

- **將 null 或空字串傳入 `url`**:`SendJsonAsync` 內部會執行 `ArgumentException.ThrowIfNullOrWhiteSpace(url, nameof(url))`,立即擲回 `ArgumentException`。
- **反序列化失敗**:`SendJsonAsync` 在非 2xx 時會擲回 `HttpClientRequestException`。即使回傳 200,若 Body 不是有效的 JSON,`As<T>` 會擲回 `System.Text.Json.JsonException`。
- **POST/PATCH 不會自動重試**：預設為 `AllowNonIdempotentRetry=false`。若寫入介面需要重試，請明確啟用此開關，或確認對端具備冪等性。
- **重複使用 `HttpClientRequestOptions` 時 `JsonSerializerOptions` 會被覆寫**：此屬性為 `set` 而非 `init`,請確認每次傳送時都傳入了預期的執行個體。
- **回應主體會被截斷後顯示於例外訊息**:`HttpClientJsonExtension` 內部為 `ResponseSummaryLimit = 1024`,完整原文一律位於 `HttpClientRequestException.ResponseBody`(即透過 `*ResponseAsync` 取得的 `HttpClientResponse.Body`)。

## 背景(選填)

`HttpClientJsonExtension` 內部使用 `JsonContent.Create(request, options: options.JsonSerializerOptions)` 建構請求主體，所有方法皆經由相同的 `ExecuteCoreAsync` 重試/逾時通道，之後再由 `Selector`(強型別方法會擲回狀態碼例外;`*ResponseAsync` 則透傳 `RawResponse`)分為兩種分支。如此一來，「直接取得物件」與「先確認狀態碼」兩種用法即可由同一份程式碼支援。
