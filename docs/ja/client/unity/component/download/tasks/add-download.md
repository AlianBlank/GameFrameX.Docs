# ダウンロードを追加して開始する

`DownloadComponent.AddDownload(...)` を使ってリモートファイルをダウンロードキューに追加すると、フレームワークが自動的にダウンロードエージェントをスケジュールしてダウンロードを完了し、イベントコールバックを通じて進捗・成功・失敗の結果を返します。

## 前提条件

- シーンに `DownloadComponent`(コンポーネントメニュー `GameFrameX/Download`)がアタッチされており、`GameFramework` とともに起動が完了していること。
- シーンに `EventComponent` がアタッチされていること。そうでない場合、ダウンロードの成功 / 失敗イベントを配信できません。
- `DownloadComponent` の `Download Agent Helper Count` が 0 より大きいこと。デフォルト値は 3 です。
- `downloadPath` のディレクトリに書き込み権限があること。

## 操作手順

1. `DownloadComponent` のインスタンスを取得します:

```csharp
var download = GameEntry.GetComponent<DownloadComponent>();
```

Source: [DownloadComponent.cs#L46-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L60)

2. `AddDownload` を呼び出してダウンロードタスクをキューに追加すると、タスクのシリアル番号 `serialId` が返されます:

```csharp
int serialId = download.AddDownload(
    downloadPath: Application.persistentDataPath + "/files/bundle.zip",
    downloadUri:   "https://example.com/bundle.zip",
    tag:           "Bundle",
    priority:      0,
    userData:      null);
```

Source: [DownloadComponent.cs#L379-L385](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L379-L385)

3. `EventComponent` のダウンロードイベントを購読してコールバックを取得します。イベント ID の定義は `Constant.cs` を参照してください:

```csharp
var eventComp = GameEntry.GetComponent<EventComponent>();
eventComp.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComp.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComp.Subscribe(DownloadUpdateEventArgs.EventId,   OnDownloadUpdate);
```

コールバック内では `e.SerialId` が、追加時に返された `serialId` と対応します。

4. ダウンロード結果を処理します。`DownloadSuccessEventArgs` / `DownloadFailureEventArgs` はどちらも `SerialId` を提供しており、これによってどのタスクが終了したかを判定できます。

## よくあるバリエーション

- **`Task<bool>` だけを取得したい場合**:`download.Download(downloadPath, downloadUri)` を使用します。内部では `AddDownload` + `TaskCompletionSource` がカプセル化されており、完了時に `Task` が `SetResult(true)` となり、失敗 / キャンセル時には `SetResult(false)` / `TrySetCanceled()` となります。
  Source: [DownloadComponent.cs#L306-L317](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L317)

- **tag / priority を渡さない場合**:2 つの引数を持つ `AddDownload(string downloadPath, string downloadUri)` をそのまま使用します。デフォルトは `tag = null`、`priority = 0` です。
  Source: [DownloadComponent.cs#L271-L274](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L274)

- **tag で一括管理する場合**:`GetDownloadInfos(tag)` で照会し、`RemoveDownloads(tag)` で一括キャンセルできます。

## よくあるエラー

- **`Log.Fatal("Download manager is invalid.")`**:シーンに `DownloadComponent` がアタッチされていない、または正しく Awake されていません。GameFramework の起動順序を確認してください。
- **`Log.Fatal("Event component is invalid.")`**:`EventComponent` が不足しているため、ダウンロードイベントを配信できません。
- **ダウンロードディレクトリに書き込み権限がない**:`Application.persistentDataPath` など Unity が提供する書き込み可能なパスを使用してください。`StreamingAssets` や `jar:file://` などの読み取り専用の場所には書き込まないでください。
- **エージェントがすべてビジーのとき新規タスクが待機し続ける**:タスクは空きエージェントができるまで待機キューに入ります。`FreeAgentCount` / `WaitingTaskCount` で監視できます。
  Source: [DownloadComponent.cs#L82-L105](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L82-L105)

## 背景

`DownloadComponent` は `Start` フェーズで `Download Agent Helper Count` の数に応じた数の `UnityWebRequestDownloadAgentHelper` を作成し(Inspector でカスタム実装に切り替え可能)、すべての並行ダウンロードはこれらの Helper 上でローテーションされます。`AddDownload` はキューに入れるだけで、実際の HTTP リクエストの発行とディスクへの書き込みは `DownloadManager` が次のフレームでスケジュールします。
