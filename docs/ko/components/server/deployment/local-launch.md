# quick_start-game.bat로 로컬에서 시작하기

`quick_start-game.bat`는 `GameFrameX.Launcher` 디렉터리에 있는 게임 서버 원클릭 시작 스크립트로, 실행하면 로컬에서 `ServerType=Game`인 게이트웨이 프로세스가 뜨고, 내장된 디스커버리 센터에 자동으로 연결되며 MongoDB 데이터베이스에 연결됩니다. 개발 단계에서 서비스가 정상적으로 구동되는지 빠르게 검증하는 데 적합합니다.

## 사전 조건

- Windows 시스템, .NET 10.0 SDK 또는 런타임이 설치되어 있어야 함(`TargetFramework=net10.0`)
- 이 저장소를 클론하거나 다운로드했고, `GameFrameX.Launcher`의 Release 빌드를 완료했으며, 산출물은 `bin\app\GameFrameX.Launcher.dll`에 위치해야 함
- 로컬 머신 `127.0.0.1`의 `21001` 포트를 `DiscoveryCenter`(디스커버리 센터)가 리슨할 수 있어야 하며, `29090/29100/29010/29110` 포트가 사용 중이지 않아야 함
- 네트워크에서 스크립트에 지정된 MongoDB Atlas 주소에 접근할 수 있어야 함(계정 `gameframex` / 비밀번호가 유효한지 확인 필요)

## 작업 단계

1. 명령줄을 열고 `GameFrameX.Launcher` 디렉터리로 이동합니다:

   ```bat
   cd GameFrameX.Launcher
   ```

2. 직접 더블클릭하거나 명령줄에서 `quick_start-game.bat`를 실행합니다:

   ```bat
   quick_start-game.bat
   ```

   스크립트가 실제로 호출하는 명령은 다음과 같습니다:

   ```bat
   start dotnet GameFrameX.Launcher.dll --ServerType=Game --ServerId=9000 --APMPort=29090 --InnerIp=127.0.0.1 --InnerPort=29100 --OuterIp=127.0.0.1 --OuterPort=29010 --MinModuleId=1 --MaxModuleId=9999 --WsPort=29110 --DiscoveryCenterIp=127.0.0.1 --DiscoveryCenterPort=21001 --HttpCode=inner_httpcode --DataBaseUrl="mongodb+srv://gameframex:f9v42aU9DVeFNfAF@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority" --DataBaseName=gameframex
   ```

   Source: [quick_start-game.bat](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/quick_start-game.bat#L1-L1)

3. 스크립트는 `start`를 통해 새 콘솔 창을 띄워 `GameFrameX.Launcher.dll`을 로드하며, 프로그램 진입점에서 `GameApp.Entry`를 호출하여 초기화를 완료합니다.

   ```csharp
   internal static class Program
   {
       private static async Task Main(string[] args)
       {
   #if DEBUG
           LogOptions.Default.IsConsole = true;
   #endif
           await GameApp.Entry(args, () =>
           {
               CacheStateTypeManager.Init();
               MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
           }, LogAction);
       }
   ```

   Source: [Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L5-L17)

4. 새로 뜬 콘솔 창에서 로그를 관찰합니다: APM, Inner, Outer, Ws 네 개 포트가 순서대로 리슨을 시작하고 오류 스택 트레이스가 없으면, 게임 서버가 로컬에서 성공적으로 시작된 것입니다.

## 시작 파라미터 설명

| 파라미터 | 값 | 의미 |
|------|-----|------|
| `--ServerType` | `Game` | 프로세스 유형이 게임 서버(게이트웨이)임 |
| `--ServerId` | `9000` | 현재 서버의 고유 번호 |
| `--APMPort` | `29090` | 애플리케이션 성능 관리/관리 포트 |
| `--InnerIp` / `--InnerPort` | `127.0.0.1` / `29100` | 내부 네트워크 통신 주소 |
| `--OuterIp` / `--OuterPort` | `127.0.0.1` / `29010` | 외부 클라이언트 접속 주소 |
| `--MinModuleId` / `--MaxModuleId` | `1` / `9999` | 메시지 모듈 ID 할당 범위 |
| `--WsPort` | `29110` | WebSocket 포트 |
| `--DiscoveryCenterIp` / `--DiscoveryCenterPort` | `127.0.0.1` / `21001` | 등록 센터 주소 |
| `--HttpCode` | `inner_httpcode` | HTTP 라우팅 코드 |
| `--DataBaseUrl` | Atlas 연결 문자열 | MongoDB 연결 주소 |
| `--DataBaseName` | `gameframex` | 데이터베이스 이름 |

## 일반적인 오류

- **`GameFrameX.Launcher.dll`을(를) 찾을 수 없음**: 아직 컴파일되지 않았거나 출력 디렉터리가 스크립트가 예상하는 `bin\app`이 아님을 의미합니다. `csproj`의 Release 구성은 `..\bin\app\`로 출력되므로, 먼저 해당 솔루션 루트 디렉터리에서 `dotnet build -c Release`를 실행하거나 `GameFrameX.Launcher` 디렉터리에서 빌드하십시오.

  Source: [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L20-L23)

- **`dotnet`은(는) 내부 또는 외부 명령이 아님**: .NET 10 SDK가 설치되지 않았거나, 설치 후 `dotnet.exe`가 PATH에 추가되지 않은 경우입니다.

- **`127.0.0.1:21001` 연결 실패**: 디스커버리 센터가 시작되지 않았습니다. `quick_start-game.bat`는 Game 서버만 띄우므로, 먼저 `DiscoveryCenter` 서비스를 별도로 시작한 후 이 스크립트를 실행해야 합니다.

- **MongoDB 연결 오류**: 스크립트에 계정 `gameframex`와 비밀번호가 하드코딩되어 있습니다. 해당 계정이 회수되었거나 네트워크가 제한된 경우, 스크립트의 `--DataBaseUrl`을 사용 가능한 연결 문자열로 변경해야 합니다.

## 배경

`GameFrameX.Launcher`는 Game 서버 진입점 역할과 빌드 산출물 위치(`bin\app\GameFrameX.Launcher.dll`) 역할을 모두 담당하며, 서로 다른 시작 파라미터를 전달함으로써 동일한 프로세스 모델을 재사용하여 다양한 유형의 서버를 띄울 수 있습니다. `quick_start-game.bat`는 자주 사용하는 Game 서버 파라미터를 하나의 `start dotnet ...` 명령으로 고정하여, 매번 수동으로 파라미터를 조합하는 번거로움을 없애줍니다.
