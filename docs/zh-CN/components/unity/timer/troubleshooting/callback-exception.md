# 回调抛出异常怎么办

当定时器回调内部抛出异常(如空引用、`InvalidOperationException`)时,默认行为是异常直接向上抛出,可能中断 `Update` 中后续回调的执行;将 `TimerManager.CatchCallbackExceptions` 设为 `true` 可让管理器捕获异常并降级为警告日志,不影响其余定时器继续运行。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 回调抛异常后控制台直接出现红色报错,后续定时器回调不执行 | `TimerManager.CatchCallbackExceptions` 保持默认值 `false`,异常原样向上传播 | 按下文步骤设为 `true`,再排查回调自身逻辑 |
| 控制台出现 `Timer callback error > {异常消息}` 警告 | `CatchCallbackExceptions = true` 时被捕获的异常,以 `Debug.LogWarning` 输出 | 警告内容即回调内真实异常,据此定位回调代码 |
| 测试中异常以 `TargetInvocationException` 形式抛出 | 通过反射调用 `Update` 时,未捕获的异常会被包成 `TargetInvocationException` | 属正常传播行为,非计时器缺陷;开启捕获或修复回调即可 |

## 修复步骤

### 1. 开启回调异常捕获

在游戏初始化阶段(设置回调之前)把静态开关打开:

```csharp
TimerManager.CatchCallbackExceptions = true;
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L204-L206)

该开关的默认值为 `false`:

```csharp
/// <summary>
/// 是否触发回调异常
/// </summary>
public static bool CatchCallbackExceptions = false;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L53-L56)

### 2. 了解捕获后的行为

开启后,管理器在执行回调时用 `try/catch` 包裹调用,捕获到异常只输出警告,不中断循环:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L190)

注意:所有回调都在锁外统一执行,单个回调异常被吞掉后,**同一帧内其余待执行回调仍会正常触发**。

### 3. 用测试复现两种模式的行为

仓库的单元测试演示了开关两种状态下的差异,可直接作为排查参照:

```csharp
[Test]
public void CatchCallbackExceptions_On_DoesNotThrow_OnException()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = true;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.DoesNotThrow(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Should catch exception silently");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}

[Test]
public void CatchCallbackExceptions_Off_ThrowsToCaller()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = false;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.Throws<TargetInvocationException>(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Exception should propagate through reflection as TargetInvocationException");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}
```

## 验证

- 开启开关后,构造一个会抛异常的回调(如 `_ => throw new InvalidOperationException("test")`)并注册定时器;
- 驱动 `Update` 推进时间,确认不再抛出未处理异常,控制台仅出现 `Timer callback error > test` 形式的黄色警告;
- 确认同一帧注册的其他定时器回调仍按预期执行;
- 生产环境建议始终关闭异常后**修复回调本身**,开关只用于隔离故障、避免单个回调拖垮整帧。

## 背景

回调统一在锁外的 `_pendingCallbacks` 队列中执行,这样做是为了避免业务回调长时间占用锁阻塞其他线程。正因为所有回调串行执行,任何一个未捕获异常都会终止整批回调,所以框架提供了这个全局开关做容错兜底。
