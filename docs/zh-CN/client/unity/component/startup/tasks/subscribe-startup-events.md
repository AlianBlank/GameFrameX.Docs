# 如何订阅启动完成与失败事件

通过 `StartupCompletedEventArgs` 与 `StartupFailedEventArgs`,你可以在启动流程跑完/失败时收到通知,用于跳转场景、释放加载 UI、上报埋点或提示玩家重试。

## 前置条件

- 项目已经接入 `GameFrameX.Startup.Runtime`,并通过 `GameEntry` 拿到事件组件 `EventComponent`。
- 熟悉 GameFrameX 事件订阅模式(`EventComponent.Subscribe`)。

## 事件 ID 与字段

| 事件 | EventId | 可读字段 | 触发时机 |
|------|---------|----------|----------|
| 启动成功 | `typeof(StartupCompletedEventArgs).FullName` | 无 | `ProcedureGameLauncherState` 跑完热更并 Dispose UI 后 |
| 启动失败 | `typeof(StartupFailedEventArgs).FullName` | `FailedProcedureName`、`FailedUrl`、`ErrorMessage` | 任一 Procedure 因网络或业务失败导致流程停止时 |

`StartupFailedEventArgs.Create(procedureName, url, errorMessage)` 由 `StartupProcedureUtility` 调用,`procedureName` 是失败所在的 Procedure 状态名,`url` 在非网络失败时为空字符串。

## 操作步骤

### 1. 订阅启动成功事件

在 `GameEntry` 初始化完成后、启动流程开始前调用 `Subscribe`,并把 handler 注册到 `EventComponent`:

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;
using GameFrameX.Startup.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupCompletedEventArgs.EventId,
    OnStartupCompleted);

static void OnStartupCompleted(object sender, GameEventArgs e)
{
    var args = e as StartupCompletedEventArgs;
    // 跳转主场景、播放登录动画等
}
```

`StartupCompletedEventArgs` 没有额外字段,直接 `Clear()` 即可归还引用池。

Source: [StartupCompletedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupCompletedEventArgs.cs#L1-L38)

### 2. 订阅启动失败事件

失败事件携带 Procedure 名、最后失败 URL、错误描述,适合做 UI 提示和上报:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);

static void OnStartupFailed(object sender, GameEventArgs e)
{
    var args = (StartupFailedEventArgs)e;
    Debug.LogError($"启动失败 [{args.FailedProcedureName}] {args.FailedUrl} {args.ErrorMessage}");
    // 显示重试按钮、上报埋点
}
```

Source: [StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L1-L62)

### 3. 取消订阅

在不需要时调用 `Unsubscribe`,传入同一个委托引用;否则 `EventComponent` 会一直持有回调。

```csharp
GameEntry.GetComponent<EventComponent>().Unsubscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);
```

## 常见变体

- **只想监听失败**:只订阅 `StartupFailedEventArgs.EventId`,不订阅成功事件。
- **同一回调处理成功/失败**:在 `GameEventArgs e` 上 `is StartupCompletedEventArgs` / `is StartupFailedEventArgs` 分支判断。
- **通过热更层判断业务失败**:`IHotfixLauncher.StartAsync` 返回 `Result.Success == false` 时,`ProcedureGameLauncherState` 会调用 `CompleteFailure` 触发失败事件,并把 `FailedProcedureName` 固定为 `"ProcedureGameLauncherState"`、`FailedUrl` 为空字符串。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动完成后回调没触发 | 订阅时机太晚,事件已经 Fire 过了 | 在 `GameEntry` 启动前或入口脚本 `Awake` 里就 `Subscribe` |
| 失败回调里读不到 URL | `StartupFailedEventArgs.FailedUrl` 仅在网络类失败时有值 | 用 `FailedProcedureName` + `ErrorMessage` 做兜底提示 |
| 收到回调后再次订阅导致重复触发 | 没有去重,或两次启动都注册了 handler | 在 `Unsubscribe` 后再 `Subscribe`,或在 `GameEntry` 重启时统一清理 |
| 直接 `new StartupCompletedEventArgs()` 然后发送 | 事件由框架内部统一 Fire,不应外部触发 | 不要手动 Fire;只在 `EventComponent.Subscribe` 端消费 |

## 背景

两个事件都在 `StartupProcedureUtility.CompleteSuccess` / `CompleteFailure` 中触发:

- `CompleteFailure` 调用 `EventComponent.Fire(procedureOwner, StartupFailedEventArgs.Create(...))`;
- `CompleteSuccess` 调用 `EventComponent.Fire(procedureOwner, StartupCompletedEventArgs.Create())`。

事件 ID 沿用 `typeof(X).FullName` 模式,与 GameFrameX 全家桶保持一致;事件对象从引用池 `ReferencePool.Acquire` 获取,框架内部会负责 `Clear` 与回收。
