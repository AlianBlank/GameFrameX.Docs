# 如何选择 JSON 还是 BIN 输出格式

Luban 同时支持 **JSON** 和 **BIN** 两种数据输出格式,并为每种格式配套不同的代码模板。本页帮你根据客户端/服务器、运行时性能、可读性等需求,在两者之间快速做出选择,并指引你切换对应的生成脚本与配置项。

## 一句话结论

- 服务器(C# / .NET):默认 `JSON`,追求极致加载速度时切换到 `BIN`。
- 客户端(Unity):开发/调试用 `JSON`,发布版本强烈推荐 `BIN`。
- 输出格式与代码模板一一对应,改格式时要同时改 `--dataTarget` 和 `--codeTarget`。

## 两种格式对照表

| 维度 | JSON | BIN |
|------|------|-----|
| 数据文件可读性 | 纯文本,可用编辑器/git 直接查看 | 二进制,需工具或运行时才能读 |
| 文件体积 | 较大(带引号、缩进、字段名) | 紧凑(字段紧凑序列化,无字段名) |
| 加载/解析速度 | 较慢(运行时解析字符串) | 快(直接 `MemoryStream` 读取) |
| Git diff/合并 | 友好,冲突易处理 | 不友好,冲突基本只能整文件替换 |
| 配套代码模板 | `cs-dotnet-json`(服务端)、`cs-simple-json`(客户端) | `cs-bin`(服务端与客户端共用) |
| 校验严格度 | 默认 | `--validationFailAsError true` 开启 |
| 适合场景 | 开发期、服务器、调试、热更灰度 | 客户端正式版、对启动/内存敏感的场景 |

源码配置见 [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94) 的 `commands` 段。

## 操作步骤:选择并切换输出格式

### 1. 确认当前激活的是哪种格式

打开 `luban.conf`,在 `commands` 数组里找到你要生成的目标(server 或 client),看 `active` 字段:

- `active: true` → 当前生效的命令。
- `active: false` → 备用命令,需要手动启用。

仓库里默认激活的是 JSON:

```json
{
  "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

Source: [luban.conf#L66-L94](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

### 2. 通过生成脚本快速切换

仓库根目录已经提供四对生成脚本,直接执行即可,无需修改 `luban.conf`:

| 目标 | JSON | BIN |
|------|------|-----|
| Server | `gen-server-json.bat` / `gen-server-json.sh` | `gen-server-bin.bat` / `gen-server-bin.sh` |
| Client | `gen-client-json.bat` / `gen-client-json.sh` | `gen-client-bin.bat` / `gen-client-bin.sh` |

例如切换到 **服务器 BIN**:

```bat
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

Source: [gen-server-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.bat#L1)

切换到 **客户端 BIN**:

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

Source: [gen-client-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.bat#L1)

### 3. 修改 luban.conf 把目标命令置为 active

如果你希望 IDE/插件层面默认产出 BIN(例如正式发布流水线),把对应 `BIN` 命令的 `active` 改为 `true`,并把 `JSON` 命令的 `active` 改为 `false`:

```json
{
  "command": "--target server --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

Source: [luban.conf#L78-L87](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L78-L87)

注意:`--validationFailAsError true` 会让 BIN 格式在校验失败时直接报错而非警告,正式环境建议保留。

## 常见变体

### 变体 A:服务器 JSON(默认)

适合本地开发与服务端热更。生成产物可直接 `git diff`、可文本搜索。

```bat
dotnet.exe ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

Source: [gen-server-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-json.bat#L1)

### 变体 B:客户端 JSON(默认)

适合 Unity 客户端调试阶段,导出 `*.json` 进 `Assets/Bundles/Config`,代码模板 `cs-simple-json`。

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

Source: [gen-client-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1)

### 变体 C:客户端 BIN(发布推荐)

代码模板统一为 `cs-bin`,数据为紧凑二进制,Unity 端加载更省内存和 IO。

```sh
dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate
```

Source: [luban.conf#L83-L87](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L83-L87)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 运行时报 `dataTarget/codeTarget 不匹配` | 只改了 `--dataTarget`,没改 `--codeTarget` | 二者必须配对(json↔cs-dotnet-json/cs-simple-json,bin↔cs-bin/cs-dotnet-bin/cs-dotnet-bin) |
| BIN 文件无法直接打开看内容 | 选择了 bin 后期望像 json 一样查看 | 用配套的 `cs-bin` 模板读取,不要尝试文本解析 |
| 改了 luban.conf 没生效 | 仍在跑旧脚本 | 直接跑 `gen-*-bin.*` 脚本,或在 `commands` 里把目标命令 `active` 改 `true` |
| 客户端发版后启动变慢 | 客户端仍在用 JSON | 切到 `gen-client-bin.*`,并把 BIN 命令 `active` 设为 `true` |
| 服务器热更配置后报错难定位 | 服务器用了 BIN 但没开校验 | 给 BIN 命令加 `--validationFailAsError true` |

## 背景(可选)

JSON 与 BIN 的差异本质上是 **可读性 / 体积 / 解析速度** 的三角权衡。Luban 把数据序列化(`--dataTarget`)和代码生成模板(`--codeTarget`)解耦,使得同一种数据可以用不同的运行时表示承载——开发期保留 JSON,正式期切到 BIN,是 GameFrameX 推荐的渐进式做法。
