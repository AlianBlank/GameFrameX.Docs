# 啟動相關問題與解決方案

本頁整理了 `ProcedureComponent` 啟動階段最常見的錯誤與例外狀況。修正方式依據 [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs) 與 [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs) 的實際行為提供。

## 快速診斷

| 症狀（主控台原始輸出） | 原因 | 修正方式 |
|------|------|------|
| `Procedure manager is invalid.` | 框架無法從 `GameFrameworkEntry` 取得 `IProcedureManager`，通常是因為場景中沒有掛載 `ProcedureComponent`，或其 `Awake` 尚未執行。 | 請參閱 [修正 1](#fix-1-procedure-manager-is-invalid) |
| `Available procedure type names is empty. Procedure auto start skipped.` | Inspector 中的 `Available Procedure Type Names` 陣列為空。 | 請參閱 [修正 2](#fix-2-available-procedure-type-names-is-empty) |
| `Can not find procedure type '{0}'.` | `Available Procedure Type Names` 中的型別名稱字串與目前組件中的任何 `Type` 都不相符。 | 請參閱 [修正 3](#fix-3-can-not-find-procedure-type) |
| `Can not create procedure instance '{0}'.` | 有找到型別名稱，但無法透過 `Activator.CreateInstance` 建立執行個體（抽象類別／缺少公用建構函式）。 | 請參閱 [修正 4](#fix-4-can-not-create-procedure-instance) |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` 未出現在 `Available Procedure Type Names` 中。 | 請參閱 [修正 5](#fix-5-entrance-procedure-is-invalid) |
| `You must initialize procedure first.` | 在 `Initialize` 之前呼叫了 `StartProcedure` / `HasProcedure` / `GetProcedure` / `CurrentProcedure` / `CurrentProcedureTime`。 | 請參閱 [修正 6](#fix-6-you-must-initialize-procedure-first) |
| `Procedures is invalid.` | 呼叫 `m_ProcedureManager.Initialize(..., procedures)` 時傳入了空陣列。 | 請參閱 [修正 7](#fix-7-procedures-is-invalid) |
| `Already exist FSM.` 啟動後重新進入場景 | 已啟用 `Use Startup Runner`，但 `ProcedureComponent` 的舊邏輯仍在執行，導致 `ApplicationStartupEntry` 重複初始化。 | 請參閱 [修正 8](#fix-8-already-exist-fsm) |

## 修正步驟

### 修正 1：Procedure manager is invalid

在 `ProcedureComponent.Awake` 中會執行：

```csharp
m_ProcedureManager = GameFrameworkEntry.GetModule<IProcedureManager>();
if (m_ProcedureManager == null)
{
    Log.Fatal("Procedure manager is invalid.");
    return;
}
```

排查步驟：

1. 確認場景中存在掛載了 `ProcedureComponent` 的 GameObject。元件選單路徑為 `GameFrameX/Procedure`。
2. 確認 `GameFrameworkEntry` 已正確初始化（其他 `GameFrameworkComponent` 執行個體也已掛載並執行過 `Awake`）。
3. 檢查是否有其他元件註冊了 `IProcedureManager` 的實作，導致介面被佔用——每個介面只允許一個實作。
4. 處理 IL2CPP／程式碼裁切（stripping）時，管理器類別上已宣告 `[Preserve]` 屬性。如果仍被裁切掉，請檢查您自己的 `link.xml` 是否涵蓋 `GameFrameX.Procedure.Runtime`。

### 修正 2：Available procedure type names is empty

在 `ProcedureComponent.Start` 中會檢查：

```csharp
if (m_AvailableProcedureTypeNames == null || m_AvailableProcedureTypeNames.Length <= 0)
{
    Log.Warning("Available procedure type names is empty. Procedure auto start skipped.");
    yield break;
}
```

修正方式：在 Inspector 的 `Available Procedure Type Names` 陣列中填入流程類別的完整名稱（命名空間 + 類別名稱），至少一項。

### 修正 3：Can not find procedure type

對應的程式碼：

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

修正方式：

1. 字串必須與 `Type.FullName` 完全一致，例如 `GameFrameX.Procedure.Runtime.ProcedureLaunch`。
2. 如果流程類別位於自訂組件中，請確認該組件已被載入（Build Settings → Player Settings → 即使未勾選「Disable Domain Reload」，也要確保程式碼已編譯進專案中）。
3. 這種情況最常發生在重新命名／移動命名空間後忘記同步 Inspector。變更類別名稱後，務必回到 Inspector 更新字串。

### 修正 4：Can not create procedure instance

對應的程式碼：

```csharp
procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

修正方式：確保流程類別為 `public`、具有公用的無參數建構函式，且既不是抽象類別也不是介面。`ProcedureBase` 的標準寫法如下：

```csharp
public sealed class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
    }
}
```

### 修正 5：Entrance procedure is invalid

在 `Start` 中會比對入口流程：

```csharp
if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

如果迴圈結束後 `m_EntranceProcedure` 仍為 `null`，就會輸出 `Entrance procedure is invalid.`。修正方式：將 `Entrance Procedure Type Name` 欄位設定為與 `Available Procedure Type Names` 中其中一項**完全相同**的值。

### 修正 6：You must initialize procedure first

當 `m_ProcedureFsm == null` 時，`ProcedureManager` 的多個成員會擲回這個例外，例如：

```csharp
public ProcedureBase CurrentProcedure
{
    get
    {
        if (m_ProcedureFsm == null)
        {
            throw new GameFrameworkException("You must initialize procedure first.");
        }
        return (ProcedureBase)m_ProcedureFsm.CurrentState;
    }
}
```

觸發條件：在 `Initialize` 之前呼叫了 `CurrentProcedure` / `CurrentProcedureTime` / `StartProcedure` / `HasProcedure` / `GetProcedure` 中的任何一個。

修正方式：

1. 預設情況下，`ProcedureComponent.Start` 會自動呼叫 `Initialize` + `StartProcedure`，因此不需要手動呼叫。
2. 如果您自己持有 `IProcedureManager` 並優先存取它，請先呼叫 `Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)`，再存取其他成員。
3. 啟用 `Use Startup Runner` 時，元件的 `Start` 不會自動啟動流程——此時由 `ApplicationStartupEntry` / `StartupRunner.Run` 負責初始化。請確保它確實有被執行。

### 修正 7：Procedures is invalid

在 `ProcedureManager.Initialize` 中會預先檢查：

```csharp
if (procedures.Length <= 0)
{
    throw new GameFrameworkException("Procedures is invalid.");
}
```

修正方式：不要傳入空陣列給 `Initialize`。請至少傳入一個 `ProcedureBase` 執行個體。

### 修正 8：Already exist FSM

當 `Use Startup Runner = true` 時，`ProcedureComponent.Start` 會立即結束：

```csharp
if (m_UseStartupRunner)
{
    yield break;
}
```

這個分支正是為了避免與 `ApplicationStartupEntry` + `StartupRunner.Run` 重複執行 `Initialize`，進而觸發 `Already exist FSM`（同一個 `IProcedureManager` 持有者被重複呼叫 `CreateFsm`）。

修正方式：兩者擇一使用——不要混用：

- 舊模式：`Use Startup Runner = false`，依賴 Inspector 陣列自動啟動。
- 新模式：`Use Startup Runner = true`，由 `ApplicationStartupEntry` 透過 `StartupRunner.Run` 接管啟動流程。

## 驗證

套用上述修正後，您可以透過以下方式確認問題已解決：

1. 重新進入播放模式（Play Mode）。主控台中不再出現對應的錯誤，且 `ProcedureComponent.CurrentProcedure` 不為 `null`。
2. 在第一個流程（例如 `ProcedureLaunch`）的 `OnEnter` 中加入一條日誌。確認日誌有輸出，表示 `StartProcedure` 確實已生效。
3. 在第二個流程中呼叫 `ChangeState<ProcedureXxx>()`，觀察狀態轉換是否符合預期，以驗證整個 FSM 已正確初始化。
4. 如果啟用了 `Use Startup Runner`，請確認 `ApplicationStartupEntry` 確實呼叫了 `StartupRunner.Run` 並傳入您的入口流程型別，否則流程永遠不會啟動（只有 `Awake` 會註冊管理器）。
