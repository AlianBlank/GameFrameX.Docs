# WebGL 平台 RemoveCache / ClearCache 无效怎么办

在 WebGL 平台上调用 `RemoveCache(url)` 或 `ClearCache()` 时不会真正清理任何缓存，只会输出一条警告日志，因为 WebGL 运行时无法直接访问本地文件系统。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 调用 `RemoveCache(url)` 后图片仍被命中 | WebGL 下图片由浏览器 HTTP 缓存，框架内无本地副本可删 | 改用浏览器侧缓存控制（URL 加版本号 / Cache-Control） |
| 调用 `ClearCache()` 后磁盘空间未变化 | WebGL 下不存在"磁盘缓存"概念，方法直接返回 | 改在浏览器侧清理；非 WebGL 平台才调用 `ClearCache` |
| 调用 `RemoveCache` / `ClearCache` 在 Console 看到警告 `ImageCache: RemoveCache is not supported on WebGL.` 或 `ImageCache: ClearCache is not supported on WebGL.` | WebGL 平台代码分支显式禁用该操作 | 调用前用 `#if !UNITY_WEBGL` 包裹，或改用浏览器侧方案 |

## 修复步骤

### 1. 确认平台分支是预期行为

源码中 `RemoveCache` 与 `ClearCache` 均通过 `#if UNITY_WEBGL` 直接返回警告：

```csharp
public void RemoveCache(string url)
{
    if (string.IsNullOrEmpty(url)) { return; }

#if UNITY_WEBGL
    Log.Warning("ImageCache: RemoveCache is not supported on WebGL.");
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    if (FileHelper.IsExists(cachePath))
    {
        FileHelper.Delete(cachePath);
    }
#endif
}

public void ClearCache()
{
#if UNITY_WEBGL
    Log.Warning("ImageCache: ClearCache is not supported on WebGL.");
#else
    if (!Directory.Exists(_config.CachePath)) { return; }
    FileHelper.CleanDirectory(_config.CachePath);
#endif
}
```

Source: [ImageCacheManager.cs#L196-L236](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L196-L236)

也就是说：WebGL 下 `RemoveCache` / `ClearCache` **不是失效**，而是源码层面被禁用。任何"清理本地缓存"的尝试都不会生效。

### 2. 在 WebGL 下避免调用这两个方法

如果你的代码会跨平台运行，用条件编译跳过调用即可：

```csharp
public void OnUserClickClearCache()
{
#if !UNITY_WEBGL
    GameFrameX.ImageCache.Runtime.ImageCacheManager.Instance.ClearCache();
#endif
}
```

### 3. 在 WebGL 下做"等价"清理

WebGL 平台图片由 `UnityWebRequestTexture` 加载，缓存由浏览器管理。要让"旧图"不再被命中，常见做法：

1. **URL 加版本号或哈希**：每次资源变更后改变 URL 查询参数（例如 `?v=2`），浏览器会把它当作新资源请求。
2. **服务器返回合适的 `Cache-Control` 头**，控制浏览器侧的失效时间。
3. **调用浏览器侧的 `Caching.ClearCache()`（浏览器自身存储清理 API）**——本组件不负责该路径。

### 4. 同时确认 `IsCached` 行为

WebGL 下 `IsCached(url)` 也永远返回 `false`，因为框架内部不持有缓存副本，不要用它判断 WebGL 上的命中状态：

```csharp
public bool IsCached(string url)
{
    if (string.IsNullOrEmpty(url)) { return false; }

#if UNITY_WEBGL
    return false;
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    return FileHelper.IsExists(cachePath);
#endif
}
```

## 验证

- 在 Editor 或 Standalone 平台调用 `ClearCache()` 后，缓存目录（`ImageCacheConfig.CachePath`）下的 PNG 文件应被清空。
- 在 WebGL 构建中调用 `ClearCache()`，Console 应出现 `ImageCache: ClearCache is not supported on WebGL.` 警告，且没有任何 IO 错误——说明走到了预期分支。
- 在 WebGL 中按修复步骤 3 改变 URL 查询参数后重新加载，确认浏览器拿到了新资源（旧图不再被命中）。

## 背景（可选）

WebGL 沙箱没有真正的"本地磁盘"概念，`System.IO` 在该平台被裁剪。`ImageCacheManager` 因此在 WebGL 分支直接走 `UnityWebRequestTexture`，把缓存交给浏览器；与之配套的 `IsCached` / `RemoveCache` / `ClearCache` 也都不持有可清理的本地副本，故全部走"返回 false / 输出警告"的早退路径。
