# 状態ライフサイクルフックリファレンス

このページでは、`FsmState<T>` が提供するすべてのライフサイクルコールバックメソッドについて、シグネチャ、触发时机(原文ママ)、一般的な用途をまとめています。すべてのフックは `Runtime/Fsm/FsmState.cs` で定義されており、デフォルトでは空のメソッドとなっているため、必要に応じてオーバーライドしてください。

## フック早見表

| フック | シグネチャ | 発火タイミング | 一般的な用途 |
|------|------|----------|----------|
| `OnInit` | `protected internal virtual void OnInit(IFsm<T> fsm)` | 状態が初めてステートマシンに追加されたときに 1 回呼ばれる | 一度きりのリソース準備、データキャッシュ、イベント購読 |
| `OnEnter` | `protected internal virtual void OnEnter(IFsm<T> fsm)` | その状態に入るときに呼ばれる | 入場アニメーションの再生、タイマーのリセット、ログの記録 |
| `OnUpdate` | `protected internal virtual void OnUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | ステートマシンのポーリング時に呼ばれる(毎フレーム) | 遷移条件の検出、時間の累積 |
| `OnFixedUpdate` | `protected internal virtual void OnFixedUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | ステートマシンの固定ポーリング時に呼ばれる | 物理関連のロジック |
| `OnLeave` | `protected internal virtual void OnLeave(IFsm<T> fsm, bool isShutdown)` | その状態から離れるときに呼ばれる、シャットダウン時は `isShutdown` が `true` | 一時的な状態のクリーンアップ、グローバル設定の復元 |
| `OnDestroy` | `protected internal virtual void OnDestroy(IFsm<T> fsm)` | 状態がステートマシンから削除されたとき、またはステートマシンが破棄されたときに呼ばれる | `OnInit` で保持していたリソースの解放 |

## 発火順序

通常の切り替えフローの呼び出し順序は次のとおり:`OnLeave(旧状態, false)` → `OnEnter(新状態)`。初めて状態を追加するときには `OnInit` も 1 回発火する。ステートマシンの破棄または状態の削除時に、`OnLeave(..., true)` → `OnDestroy` の順序で発火する。

```csharp
// ソース抜粋:Runtime/Fsm/Fsm.cs における状態切り替えの典型的なフロー
m_CurrentState.OnLeave(this, false);   // 旧状態が離れる
m_CurrentState = state;
m_CurrentState.OnEnter(this);          // 新状態が入る
```

```csharp
// ソース抜粋:Runtime/Fsm/Fsm.cs における状態の初回追加時の初期化
m_States.Add(stateType, state);
state.OnInit(fsm);
```

## 時間パラメータ

`OnUpdate` と `OnFixedUpdate` は 2 つの時間値を受け取ります:

| パラメータ | 型 | 意味 |
|------|------|------|
| `elapseSeconds` | `float` | 論理経過時間(秒単位)、タイムスケールの影響を受ける |
| `realElapseSeconds` | `float` | 実経過時間(秒単位)、タイムスケールの影響を受けない |

一時停止/スロー再生中も実時間で進行させたいロジック(例: UI カウントダウン)には `realElapseSeconds` を使用してください。

## 状態の切り替え

フック内部では、以下のメソッドを通じて他の状態への切り替えを要求できます:

```csharp
// ジェネリック版:実行時の型安全性
public void ChangeToState<TState>(IFsm<T> fsm) where TState : FsmState<T>

// 型版:stateType は FsmState<T> を継承している必要がある
protected void ChangeState(IFsm<T> fsm, Type stateType)
```

`ChangeState` を呼び出す際、`fsm` がすでに無効になっている場合は `GameFrameworkException("FSM is invalid.")` がスローされ、`stateType` が `null` の場合は `"State type is invalid."` が、型が一致しない場合は `"State type '{0}' is invalid."` がスローされます。

Source: [Runtime/Fsm/FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L163)

## 最小例

```csharp
using GameFrameX.Fsm.Runtime;

public sealed class IdleState : FsmState<Player>
{
    protected internal override void OnEnter(IFsm<Player> fsm)
    {
        // 待機状態に入る:アニメーションを再生し、タイマーをリセットする
        fsm.SetData<float>("StateEnterTime", Time.time);
    }

    protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // 遷移条件を検出する
        if (fsm.Owner.MoveInput.sqrMagnitude > 0.01f)
        {
            ChangeToState<MoveState>(fsm);
        }
    }

    protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
    {
        // 通常の切り替え時のみクリーンアップする。シャットダウン時はグローバルデータをリセットしない
        if (!isShutdown)
        {
            fsm.RemoveData("StateEnterTime");
        }
    }
}
```

## フック内部の制約について

すべてのフックは `protected internal` としてマークされており、派生クラスまたは同一アセンブリ内でのみオーバーライドできます。`OnEnter` 内で再度 `ChangeState` を呼び出してから直ちに別の副作用を発生させないでください。ステートマシンは切り替え時点で `OnLeave`/`OnEnter` を同期的に実行するため、順序に起因する副作用に注意してください。

ステートマシンがどのように駆動されるか(ポーリングエントリポイント)の詳細については、[Runtime/Fsm/FsmBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs) を参照してください。
