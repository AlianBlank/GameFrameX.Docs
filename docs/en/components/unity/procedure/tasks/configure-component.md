# How to Configure ProcedureComponent

`ProcedureComponent` is the entry component of the GameFrameX procedure system. It is responsible for registering `IProcedureManager`, collecting available procedure classes, and entering the specified entry procedure at startup. This page explains how to configure it in Unity so that the game starts running from the entry procedure as expected.

## Prerequisites

- The `GameFrameX.Procedure` assembly has been added to the project.
- A procedure class that inherits from [ProcedureBase](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L80) is ready (for example, the entry procedure `ProcedureLaunch`).
- A `GameFramework` prefab (containing `GameFrameXEntry` / `GameFrameworkEntry`) exists in the scene, used to host `GameFrameworkComponent` derived components.

## Steps

1. Mount the `GameFramework` prefab in the scene and use **Add Component → GameFrameX → Procedure** to add `ProcedureComponent`.

   The component properties are displayed visually in the Inspector via `ProcedureComponentInspector`:

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Procedure")]
   [GameFrameXAutoComponent(-1000)]
   public sealed class ProcedureComponent : GameFrameworkComponent
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L43-L46)

2. In the **Available Procedures** area of the Inspector, check all procedure classes that need to be enabled (must inherit from `ProcedureBase`). The Inspector automatically collects candidate types by reflecting `typeof(ProcedureBase)`:

   ```csharp
   m_ProcedureTypeNames = TypeHelper.GetRuntimeTypeNames(typeof(ProcedureBase));
   ```

   Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L162-L165)

3. Select the entry procedure in the **Entrance Procedure** dropdown. This value is written to the serialized field `m_EntranceProcedureTypeName`, and the entry instance is located by type matching at startup:

   ```csharp
   if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
   {
       m_EntranceProcedure = procedures[i];
   }
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L152-L155)

4. After entering Play mode, the component calls `Initialize` and `StartProcedure` in the `Start` coroutine:

   ```csharp
   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   yield return new WaitForEndOfFrame();
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

5. After running, you can see the current procedure in the **Current Procedure** field at the top of the Inspector:

   ```csharp
   EditorGUILayout.LabelField("Current Procedure", currentProcedureName);
   ```

   Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L83)

## Common Variations

- **Use StartupRunner to take over startup**: Check **Use Startup Runner** in the Inspector. In this mode, only `IProcedureManager` is registered in `Awake`; `Initialize` and `StartProcedure` are no longer called, and `ApplicationStartupEntry` takes over via `StartupRunner.Run`:

  ```csharp
  if (m_UseStartupRunner)
  {
      // Initialize and StartProcedure are taken over by ApplicationStartupEntry + StartupRunner.Run.
      // This component is only responsible for registering IProcedureManager in Awake,
      // avoiding duplicate Initialize reports of "Already exist FSM" with the new entry.
      yield break;
  }
  ```

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L122-L127)

  After checking, the Inspector displays a hint message and ignores the **Available Procedures** and **Entrance Procedure** configurations below:

  ```csharp
  EditorGUILayout.HelpBox("Procedure startup has been delegated to StartupRunner.Run. Available Procedures and Entrance Procedure configurations will be ignored.", MessageType.Info);
  ```

  Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L59)

- **Reinitialize procedures at runtime**: Call `ReinitializeProcedures` to destroy the existing state machine and re-initialize with a new procedure array. Commonly used for hot updates or custom startup sequences:

  ```csharp
  [Preserve]
  public void ReinitializeProcedures(ProcedureBase[] procedures, ProcedureBase entranceProcedure)
  {
      m_ProcedureManager.ReinitializeProcedures(procedures);
      m_EntranceProcedure = entranceProcedure;
  }
  ```

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

## Common Errors

| Symptom | Original Log | Cause and Fix |
|------|----------|-----------|
| Procedure does not start | `Available procedure type names is empty. Procedure auto start skipped.` | **Available Procedures** is empty in the Inspector. Check at least one procedure class before running. |
| Cannot create instance | `Can not find procedure type '{0}'.` | The type name is not in the runtime assembly. Confirm that the procedure class has been compiled and the namespace is complete. |
| Creation failed | `Can not create procedure instance '{0}'.` | The procedure class lacks a parameterless constructor or does not inherit from `ProcedureBase`. |
| No entry | `Entrance procedure is invalid.` | **Entrance Procedure** is not selected, or the selection is not in the **Available Procedures** list. |
| Startup reports duplicate FSM | Still triggered by the legacy `Initialize` path after enabling StartupRunner | Check whether two entries exist simultaneously (`ApplicationStartupEntry` and the legacy `ProcedureComponent.Start`), and keep only one. |

## Background (Optional)

`ProcedureComponent` obtains the procedure manager via `GameFrameworkEntry.GetModule<IProcedureManager>()` in `Awake`; it only proceeds when `IsRuntimeComponentReady` is `true`, thereby avoiding incorrect initialization in Editor mode. When `m_UseStartupRunner` is `false` (default), the `Start` coroutine builds `ProcedureBase` instances from the reflected type name array and starts with the matched entry procedure; when `true`, it only registers the module and fully delegates initialization and startup to `StartupRunner.Run`, avoiding the `Already exist FSM` error caused by duplicate `Initialize`.
