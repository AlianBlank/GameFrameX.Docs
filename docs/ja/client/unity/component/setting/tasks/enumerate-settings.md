# すべての設定項目を列挙する

`SettingManager` が提供するメソッドを使って、現在読み込まれているすべての設定項目名を一度に取得します。設定のデバッグ、エクスポート、一括検証、一括削除前のプレビューに使用します。

## 前提条件

- `SettingComponent.SetSettingHelper` で実装（`DefaultSettingHelper` や `PlayerPrefsSettingHelper` など）を注入済みであり、`Load()` を呼び出して設定の読み込みに成功していること。
- `SettingManager` インスタンスを取得できること。一般的な方法は `GameEntry` / `SettingComponent.SettingManager` プロパティから読み取ることです。

## 操作手順

1. `SettingManager` インスタンスを取得します。一般的なエントリポイントは `GameEntry.GetComponent<SettingComponent>().SettingManager`、または `SettingComponent` が公開する `GetSettingManager` の派生メソッドです。

2. `GetAllSettingNames()` を呼び出して、設定項目名の配列を直接取得します。

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingManager = GameEntry.GetComponent<SettingComponent>().SettingManager;
   string[] names = settingManager.GetAllSettingNames();

   foreach (var name in names)
   {
       UnityEngine.Debug.Log(name);
   }
   ```

   出典: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L140-L260),[ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L85-L95)

3. 既存のリストを再利用したい場合（GC を避けるため）、`List<string>` パラメータ付きのオーバーロードを使用します:

   ```csharp
   var results = new System.Collections.Generic.List<string>(settingManager.Count);
   settingManager.GetAllSettingNames(results);
   ```

   出典: [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L81-L92)

4. `HasSetting` と `RemoveSetting` を組み合わせることで、一括検証や一括削除が可能になります:

   ```csharp
   foreach (var name in settingManager.GetAllSettingNames())
   {
       if (name.StartsWith("tmp_") && settingManager.HasSetting(name))
       {
           settingManager.RemoveSetting(name);
       }
   }
   settingManager.Save();
   ```

   出典: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs)

## よくあるバリエーション

- **`List<string>` オーバーロードの使用**: ループ内で繰り返し列挙を呼び出す場合や、他の文字列コレクションと結合する場合、リスト付きのオーバーロードは重複した割り当てを避けられます。
- **プレフィックスによるフィルタリング**: LINQ や `StartsWith` と組み合わせてホワイトリスト/ブラックリストでフィルタリングします。例えば `ui_*` で始まるキーのみエクスポートするなど。
- **ランタイム列挙子の併用**: `DefaultSetting` と `PlayerPrefsSettingHelper` もそれぞれ `GetAllSettingNames()` の実装を提供します。マネージャーを経由せずデフォルト設定インスタンスに直接アクセスする場合、インターフェースシグネチャは同一です。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| 呼び出し時に `Setting helper is invalid.` が発生 | `SetSettingHelper` を呼び出していない、またはマネージャーがまだ初期化されていない | 起動時に `DefaultSettingHelper`/`PlayerPrefsSettingHelper` を注入する |
| 呼び出し時に `Setting name is invalid.` が発生 | 空文字列または `null` を渡した | 列挙で返された項目のみに二次アクセスし、手書きで空名を渡さない |
| 取得した配列が空 | `Load()` を呼び出していない、または読み込みに失敗した | まず `Load()` を呼び出して戻り値を確認し、その後列挙する |
| 変更が反映されない | `Save()` を呼び出していない | 削除/書き込み後に `settingManager.Save()` を呼び出す |

## 背景（任意）

`GetAllSettingNames` はインターフェース層で `string[]` と `List<string>` の 2 つのオーバーロードとして定義されており、具体的なストレージは `ISettingHelper` の実装に依存します（`DefaultSettingHelper` は `DefaultSetting` のメモリ辞書を使用し、`PlayerPrefsSettingHelper` は PlayerPrefs を使用します）。マネージャーは注入されたヘルパーへの呼び出しを転送するだけです。そのため、列挙の範囲は `Load()` 時に読み込まれたデータと完全に一致します。
