# Build Properties とリンカーフラグの設定

`XCodeConfig.json` の `unityMain` / `unityFramework` セクションに `properties`(Build Settings)と `otherLinkerFlag`(リンカーフラグ、例:`OTHER_LDFLAGS`)を記入すると、Unity が iOS プロジェクトをエクスポートした後、ビルド後処理によって生成された Xcode プロジェクトに自動的に書き込まれるため、手動で Xcode を開いて Build Settings を変更する必要はありません。

## 前提条件

- Unity が iOS プラットフォームに切り替え済みであること。
- プロジェクト内に `XCodeConfig.json` という名前の設定ファイルが存在すること(ファイル名は完全に一致している必要があります。後処理はこのファイル名でスキャンします);リポジトリ付属の [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) または [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json) をコピーしてリネームして使用できます。

## 操作手順

1. プロジェクト内に `XCodeConfig.json` を作成します(内容はリポジトリ付属のテンプレートとサンプルを参照)。

2. 対象の target を決定します:メインの実行可能ファイル Unity-iPhone は `unityMain` セクションに、動的ライブラリは `unityFramework` セクションに記述します。両セクションの構造は完全に同じです。

3. `properties` フィールドで Build Settings を変更します。3種類の演算子をサポートしています:

| 演算子 | 実際に呼び出される PBXProject API | 機能 |
|--------|---------------------------|------|
| `=` | `SetBuildProperty(targetGuid, key, value)` | 特定の Build Setting の値を直接上書きする |
| `+` | `UpdateBuildProperty(targetGuid, key, list, null)` | リスト型の Build Setting に値を追加する |
| `-` | `UpdateBuildProperty(targetGuid, key, null, list)` | リスト型の Build Setting から値を削除する |

   3種類の演算子の解析ロジック(`SetBuildProperties` からの抜粋):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}

Hashtable addTable = table.Get<Hashtable>("+");
// ... ArrayList から List<string> への変換は省略 ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), list, null);

Hashtable removeTable = table.Get<Hashtable>("-");
// ... ArrayList から List<string> への変換は省略 ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), null, list);
```

出典： [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L58)

4. 上の表の構造に従って JSON を記述します(キー `=`/`+`/`-` の下のキーと値がそれぞれ Build Setting の名前と値になります。`+`/`-` の値は配列でなければなりません):

```json
{
  "unityFramework": {
    "properties": {
      "=": { "ENABLE_BITCODE": "NO" },
      "+": { "OTHER_LDFLAGS": ["-lxml2"] },
      "-": { "OTHER_LDFLAGS": ["-ObjC"] }
    }
  }
}
```

5. `otherLinkerFlag` フィールドでリンカーフラグを追加します。`properties` と同じ階層に配置します。サンプルファイルでの実際の記述方法：

```json
"otherLinkerFlag": {
  "OTHER_LDFLAGS": ["-ObjC"]
}
```

出典： [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L152-L154)

   フラグは対応する Build Setting に1件ずつ追加されます(1件につき `AddBuildProperty` を1回呼び出し):

```csharp
foreach (DictionaryEntry kv in table)
{
    var keyStr = kv.Key.ToString().Trim();
    if (kv.Value is ArrayList list)
    {
        // 配列:1件ずつ AddBuildProperty
        foreach (var part in parts)
        {
            proj.AddBuildProperty(targetGuid, keyStr, part);
        }
    }
    else
    {
        // 文字列:直接 AddBuildProperty
        proj.AddBuildProperty(targetGuid, keyStr, kv.Value.ToString().Trim());
    }
}
```

出典： [PostProcessBuildHelper.OtherLinkFlag.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.OtherLinkFlag.cs#L15-L47)

6. iOS ビルドを実行します。`[PostProcessBuild(888)]` の `OnPostProcessBuild` は、すべての `XCodeConfig.json` を読み込んで1つの設定にマージし、`GetUnityMainTargetGuid()` と `GetUnityFrameworkTargetGuid()` に対して順番に設定を適用し、最後に `Unity-iPhone.xcodeproj/project.pbxproj` に書き戻します。

```csharp
Run(project, project.GetUnityMainTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityMain"), path);
Run(project, project.GetUnityFrameworkTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityFramework"), path);
```

出典： [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L104)

## よくあるバリエーション

- **配列でも単一文字列でも可**:`otherLinkerFlag` の値を配列(例:`["-ObjC", "-lxml2"]`)として記述すると1件ずつ追加され、単一の文字列として記述すると全体が1回で追加されます。両方の記述方法に対する処理ブランチがソースコードに存在します。
- **複数設定ファイルのマージ**:スキャンで見つかったすべての `XCodeConfig.json` は順番にマージされ、後からマージされたものが先にマージされたものを上書きします。チャネルが有効な場合(`SettingLoader.GetChannel()`)、`XCodeConfig.{channel}.json` が最後にマージされ、最も高い優先度を持ちます。
- **同一セクション内の他のフィールド**:`unityMain` / `unityFramework` セクション内には、`frameworks`、`libs`、`files`、`folders`、`filesCompileFlag`、`runPathSearchPaths` などのフィールドも同時に設定でき、同じ1回の `Run` で順番に適用されます。

## よくあるエラー

| 現象 / ログ原文 | 原因 | 修正 |
|-----------------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | ファイル名が `XCodeConfig.json` ではない、または配置場所がスキャン対象にならない | 正しいファイル名に変更し、スキャン可能な場所に配置する |
| `{jsonPath} 解析失败, 跳过合并` | JSON の構文エラー | JSON 検証ツールで修正してからビルドする |
| `合并后的配置为空，跳过设置` | すべてのファイルの解析に失敗 | 各設定ファイルの構文を確認する |
| `properties` / `otherLinkerFlag` を変更したのに Xcode に反映されない | フィールドが JSON の最上位に書かれている | これら2つのフィールドは `unityMain` または `unityFramework` セクション内に書く必要があります。`Run` はこの2つのセクションからのみ読み取ります |
| `+` / `-` の操作が反映されない | 値が文字列として書かれている | ソースコードは `i.Value as ArrayList` で読み取るため、文字列では空のリストになります。配列として書く必要があります |

## 背景

`properties` は最終的に `SetBuildProperty` / `UpdateBuildProperty` に、`otherLinkerFlag` は `AddBuildProperty` に対応します。いずれも Unity 標準搭載の `UnityEditor.iOS.Xcode.PBXProject` の標準インターフェースで、前者は上書きおよび追加・削除をサポートし、後者は追加のみを行うという違いがあります。全体のフローは `[PostProcessBuild(888)]` コールバックにフックされており、`target == BuildTarget.iOS` の場合のみ実行されます。
