# How to Understand and Modify luban.conf

`luban.conf` is the master configuration file for GameFrameX.Config: it tells the Luban toolchain where to read Excel files, which data/code targets to use, and where to place the generated output. After modifying this file, simply run `gen-*.bat` / `gen-*.sh` to generate client and server code according to the new rules.

## Prerequisites

- The [GameFrameX/GameFrameX.Config](https://github.com/GameFrameX/GameFrameX.Config) repository has been cloned, and `luban.conf` exists in the root directory.
- The .NET runtime is installed (used to run `Tools/Luban.exe`).
- Familiarity with the three top-level concepts: `groups` (client/server data grouping), `targets` (generation targets), and `commands` (commands to execute).

## Top-Level Fields Overview

| Field | Purpose | Typical Values |
|------|------|--------|
| `groups` | Groups tables by "client/server" and filters by group during generation | `c` (client), `s` (server) |
| `schemaFiles` | Schema entry points loaded by Luban (`Defines`, `__tables__`, etc.) | See code block below |
| `dataDir` | Root directory of Excel data | `Excels` |
| `targets` | Collection of generation targets, each corresponding to a set of code/data outputs | `server`, `client`, `all` |
| `toolPath` | Relative path to Luban.dll | `/../Config/Tools/Luban.dll` |
| `UNITY_ASSETS_PATH` | Absolute path to the Unity project's Assets directory (runtime template) | Leave empty; replaced when the script is executed |
| `SERVER_PATH` | Absolute path to the server project root directory (runtime template) | Leave empty; replaced when the script is executed |
| `commands` | Each generation command corresponds to a target, containing command-line arguments and switches | See code block below |

## Key Fields Explained Section by Section

### 1. groups: How Data Is Split

`groups` determines whether each table belongs to the "client", the "server", or is "shared by both". `default: true` means all tables in that group are consumed by generation commands by default.

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

> Which group a table belongs to is marked in Excel via the `__xxx__` marker column; this section only defines "which group names exist".

### 2. schemaFiles: Which Definitions Are Loaded

`schemaFiles` is the entry point for Luban to read schemas; the order doesn't matter, but all four entries are required: `Defines` (built-in type catalog), `__tables__.xlsx` (table list), `__beans__.xlsx` (complex structures), and `__enums__.xlsx` (enums).

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

### 3. targets: Generation Target Definitions

Each target is a named bundle of "a set of data + a set of generated output". `topModule` is the generated namespace, and `manager` is the entry class name (loaded at runtime via the `TablesComponent` or `Tables` singleton).

```json
"targets": [
    { "name": "server", "manager": "TablesComponent", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "manager": "TablesComponent", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "manager": "Tables",         "groups": ["c","s"], "topModule": "cfg" }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L35-L61)

### 4. commands: Which Generation Commands Are Executed

`commands` is an array of command lines actually passed to `Luban.exe`. Each record is bound to a `target` and can be toggled on or off via `active: true/false`. `%UNITY_ASSETS_PATH%` and `%SERVER_PATH%` are placeholders that the generation script replaces with absolute paths before invocation.

```json
"commands": [
    {
        "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
        "target": "server", "active": true
    },
    {
        "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate",
        "target": "client", "active": true
    }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

Common switches:

- `--dataTarget json | bin` — The on-disk data format; `json` is readable, `bin` is smaller in size.
- `--codeTarget cs-simple-json | cs-dotnet-json | cs-bin` — The style of generated C# loading code; use `cs-simple-json` for the client, `cs-dotnet-json` for the server, and `cs-bin` when binary is enabled.
- `--validationFailAsError true` — Validation failures raise errors directly instead of just warnings.
- `--xargs outputDataDir=...` / `--xargs outputCodeDir=...` — Output directories for data and code artifacts; supports `%SERVER_PATH%` and `%UNITY_ASSETS_PATH%` placeholders.

## Common Variants

### Adding a New Group (e.g., a Multi-Language Sub-Client)

Append an entry to the `groups` array, and remember to tag the corresponding tables with the new group name in the `__xxx__` column of the table headers.

```json
{ "names": ["c"], "default": true },
{ "names": ["s"], "default": true },
{ "names": ["c_cn"], "default": true }
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

### Switching Between JSON and Binary Output

Replace `--dataTarget json --codeTarget cs-simple-json` (or `cs-dotnet-json`) in the corresponding command with `--dataTarget bin --codeTarget cs-bin`, and set `active` to `true`.

### Changing Output Directories

Modify `outputDataDir` / `outputCodeDir` in `commands[].command` directly; to reuse the unified paths in the scripts, simply keep the `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` placeholders.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Running `gen-*.bat` reports `ToolPath not found` | The `toolPath` relative path is incorrect, or `Tools/Luban.dll` is not in the repository | Keep the default `/../Config/Tools/Luban.dll`; do not move the `Tools/` directory |
| Generated code cannot find the namespace | `targets[].topModule` is misspelled; the client/server `topModule` must be different | Client uses `Hotfix.Config`, server uses `GameFrameX.Config`; change them to your own namespaces |
| No code is generated in the client project | The client target's `groups` does not include the group this table belongs to | Add the corresponding group name in `targets[client].groups`, or adjust the table's `__xxx__` column |
| All `active` entries in `commands` are `false` | All commands are disabled | Change the one you need to execute to `true` |
| The placeholder `%UNITY_ASSETS_PATH%` is not replaced | `Luban.exe` was double-clicked directly instead of being invoked via `gen-*.bat` / `gen-*.sh` | Run through the repository's bundled generation scripts, which handle placeholder replacement |

## Background (Optional)

The schema of `luban.conf` is defined by the Luban toolchain, and the field meanings are consistent with official Luban; this repository extends it with four additional fields — `toolPath`, `UNITY_ASSETS_PATH`, `SERVER_PATH`, and `commands[].active` — used to uniformly orchestrate generation commands and placeholder replacement through `gen-*.bat` / `gen-*.sh` in the GameFrameX workflow.
