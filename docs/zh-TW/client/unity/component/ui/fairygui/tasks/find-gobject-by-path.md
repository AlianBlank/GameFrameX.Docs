# 依路徑查找 GObject

用 `FairyGUIPathFinderHelper.GetUIFromPath(path)` 可以在執行時依層級路徑（如 `GRoot/Group/MyButton`）直接取回 `GObject`，不必逐層 `GetChild`；反過來用 `gObject.GetUIPath()` 可以取得任意物件的完整路徑。

## 前置條件

- 引用命名空間 `FairyGUI` 與 `GameFrameX.UI.FairyGUI.Runtime`（該 Helper 位於 `GameFrameX.UI.FairyGUI.Runtime` 組件內）。
- 查找從 `GRoot.inst` 開始，目標物件必須已掛載到目前顯示列表（GRoot 之下）；未開啟/已銷毀的介面內的物件查不到。

## 操作步驟

1. （可選）先取得完整路徑。如果不確定層級名稱，對任意 `GObject` 呼叫擴充方法 `GetUIPath()` 印出路徑：

```csharp
using FairyGUI;
using GameFrameX.UI.FairyGUI.Runtime;

// 取得 GObject 的層級路徑，例如 "GRoot/UISynthesisScene/ContentBox/ListSelect/1990197248/icon"
string path = gObject.GetUIPath();
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L43-L57)

2. 用路徑字串解析物件，並對回傳值判空（找不到時方法內部已記錄錯誤日誌並回傳 `null`）：

```csharp
// 透過路徑解析 GObject
GObject obj = FairyGUIPathFinderHelper.GetUIFromPath("GRoot/Group/MyButton");
if (obj == null)
{
    // 路徑無效：Log 中會出現 "error uiPath : can not found ui by this path : ..."
    return;
}
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L117-L145)

路徑格式規則（由 `GetUIFromPath` 的解析邏輯決定）：

| 寫法 | 規則 |
|------|------|
| 分隔符號 | 以 `/` 分隔各級名稱 |
| `GRoot` 段 | 會被自動跳過，路徑寫不寫 `GRoot` 前綴效果相同 |
| 普通段 | 呼叫 `GComponent.GetChild(name)` 按名稱查找，需與編輯器中設定的物件名稱一致 |
| `$數字` 段 | 先按完整名稱 `GetChild` 查找；查不到時把 `$` 後的數字當作子索引，用 `GetChildAt(index)` 取 |
| 空佇列 | 傳空路徑時直接回傳根物件 `GRoot.inst` |

## 常見變體

- **按索引定位無命名的子物件**：路徑段寫成 `$索引`，例如 `"GRoot/MyList/$3"` 表示 `MyList` 的第 4 個子物件。索引越界或命中非元件節點會拋出例外並回傳 `null`：

```csharp
// 先嘗試按名字 "$3" 查找，失敗後按索引 GetChildAt(3) 查找
GObject item = FairyGUIPathFinderHelper.GetUIFromPath("GRoot/MyList/$3");
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L166-L187)

- **判斷物件是否位於某條路徑之下**：用 `SearchPathInclude`。路徑寫成 `all`（忽略大小寫）表示不匹配任何物件（回傳 `false`）：

```csharp
// 判斷 gObject 是否位於 "GRoot/Group/Panel" 這條路徑之下（支援 $索引 段）
bool inside = FairyGUIPathFinderHelper.SearchPathInclude("GRoot/Group/Panel", gObject);
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L218-L276)

## 常見錯誤

| 現象（Log.Error / 例外原文） | 根本原因 | 規避 |
|------|------|------|
| `error uiPath : can not found ui by this path :{path}, error : ...` | 路徑任一段解析失敗，方法攔截例外後回傳 `null` | 先用 `GetUIPath()` 印出真實路徑再複製 |
| `Invalid UI path: child not found` | 某一段名稱與實際子物件名稱不一致（大小寫、改名） | 核對編輯器中的物件名稱 |
| `Invalid UI path: index out of range` | `$索引` 超出 `numChildren` 範圍 | 檢查子物件個數 |
| `Invalid UI path: not a GComponent` | 路徑中間節點是普通 `GObject`（如圖片、文字），沒有子物件 | 中間段必須是元件節點 |
| 回傳 `null` 但沒有路徑報錯 | 目標物件未顯示在 GRoot 之下 | 確認介面已開啟且未關閉 |

例外拋出與攔截位置的原始碼對照：

```csharp
if (index < 0 || index >= o.numChildren)
{
    throw new Exception("Invalid UI path: index out of range");
}
...
if (child == null)
{
    throw new Exception("Invalid UI path: child not found");
}
...
throw new Exception("Invalid UI path: not a GComponent");
```

## 背景

`GetUIPath` 透過 `SearchParent` 從目標物件逐級向上收集 `name`，反轉後用 `/` 拼接，因此它輸出的路徑可直接回傳給 `GetUIFromPath` 還原同一物件。`GetUIFromPath` 則把路徑拆成佇列，跳過 `GRoot` 後從 `GRoot.inst` 開始逐段遞迴 `SearchChild`，全程不快取，每次呼叫都即時遍歷目前顯示樹。
