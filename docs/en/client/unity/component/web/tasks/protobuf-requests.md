# How to Use Protocol Buffers Requests

Using the `GetProtoBuf` / `PostProtoBuf` generic methods provided by `WebManager`, you can initiate HTTP requests with protobuf-net message objects and directly obtain the deserialized response object; message types must implement `IExtensible` and be annotated with `ProtoContract`/`ProtoMember`.

## Prerequisites

- The `com.gameframex.unity.web` package is installed, and a `WebComponent` exists in the scene holding an `IWebManager` (`WebManager`) instance.
- Message types are annotated according to protobuf-net rules (`ProtoContract` + `ProtoMember`) and satisfy the `class, IExtensible` generic constraint.

## API Quick Reference

| Method | Signature | Description |
|------|------|------|
| `GetProtoBuf` | `Task<T> GetProtoBuf<T>(string url) where T : class, IExtensible;` | GET a protobuf message and deserialize it as `T` |
| `PostProtoBuf` | `Task<T> PostProtoBuf<T>(string url, IExtensible requestData) where T : class, IExtensible;` | Serialize the request body as protobuf and POST it; the response is deserialized as `T` |

## Steps

1. Define the protobuf request/response message classes, with field numbers specified using `[ProtoMember(n)]`:

```csharp
[ProtoContract]
public class UserResponse
{
    [ProtoMember(1)]
    public string UserName { get; set; }

    [ProtoMember(2)]
    public string Email { get; set; }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L116-L124)

2. Call `PostProtoBuf` (or `GetProtoBuf`) in your business code; `await` the returned Task to get the response object:

```csharp
public async Task<UserResponse> GetUserProtoBufAsync(string userId)
{
    var request = new UserRequest { UserId = userId };
    return await webManager.PostProtoBuf<UserResponse>(
        "https://api.example.com/user/protobuf",
        request
    );
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L126-L133)

3. Wrap with error handling as needed, for example catching timeout and network IO exceptions:

```csharp
try
{
    return await webManager.GetToString(url);
}
catch (WebException ex) when (ex.Status == WebExceptionStatus.Timeout)
{
    Debug.LogError("Request timed out: " + ex.Message);
    return null;
}
catch (IOException ex)
{
    Debug.LogError("Network IO error: " + ex.Message);
    return null;
}
```

## Common Variants

- **Custom request headers**: protobuf requests use the `Header` dictionary of `WebBinaryData`; each entry is written to the request headers when sending (native platforms write to `request.Headers`, while the WebGL platform calls `SetRequestHeader`). See [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L104-L110) and [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L140-L146).
- **WebGL platform**: The same set of APIs switches to `UnityWebRequest` + `UploadHandlerRaw` for uploading bytes under `UNITY_WEBGL`, while other platforms use `HttpWebRequest` to write to the request stream. See [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L83-L101).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| No response ever arrives after the request is sent | protobuf requests first enter a waiting queue and are dequeued each frame by `UpdateBinary`; if `WebManager` is not being updated (component inactive) or the number of in-flight requests has reached `MaxConnectionPerServer`, the request will keep queuing | Ensure `WebComponent` is running properly, that `WebManager` is being updated, and set a reasonable concurrency limit |
| Deserialized result fields are empty | The message type is missing `[ProtoContract]` / `[ProtoMember(n)]` annotations, or the type does not satisfy the `class, IExtensible` constraint | Add the protobuf-net attribute annotations to the request/response types |
| Server fails to parse the request | The request `Content-Type` is fixed to `application/octet-stream`; the server must parse it as protobuf binary | Handle it as binary protobuf on the server side, not as a text format |

## Verification

- After calling `PostProtoBuf`, print the response object fields (e.g., `response.UserName`); if the values returned by the server can be retrieved, the request and deserialization succeeded.
- Exceptions are thrown when network errors occur (on native platforms, these are `HttpWebRequest`-related exceptions; on WebGL, it is an `Exception` wrapping `unityWebRequest.error`), which can be used to identify the cause of failure.

## Background

protobuf requests are handled internally by the framework as "Binary requests": after calling `GetProtoBuf`/`PostProtoBuf`, the request is wrapped as `WebBinaryData` and enters `m_WaitingBinaryQueue`; each frame, `UpdateBinary` dequeues requests while concurrency is below the limit and calls `MakeBinaryBytesRequest` to send them, and the response bytes are wrapped in a `WebBufferResult` to complete the callback. See [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L17-L55) for the relevant implementation.
