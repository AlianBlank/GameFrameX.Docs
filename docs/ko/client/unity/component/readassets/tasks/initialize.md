# 초기화 및 루트 경로 가져오기

이 페이지에서는 `BlankReadAssets`의 초기화 방법과 다양한 플랫폼에서 `Root` 루트 경로를 읽는 방법을 설명합니다. 프레임워크는 임의의 API가 처음 호출될 때 자동으로 초기화를 완료하므로 대부분의 경우 수동으로 호출할 필요가 없습니다. 다른 API 호출 이전에 루트 경로를 미리 가져와야 하는 경우에만 명시적으로 초기화해야 합니다.

## 사전 조건

- Unity Package Manager를 통해 `com.gameframex.unity.readassets`를 도입했습니다.
- 프로젝트에 `Assets/StreamingAssets/` 디렉터리가 존재하며, 읽을 리소스가 이미 배치되어 있습니다.
- `using GameFrameX.ReadAssets.Runtime;`을 추가했습니다.

## 작업 단계

1. **루트 경로를 직접 읽기(자동 초기화)**. 프레임워크 내부에서 `EnsureInitialized()`를 사용하여 지연 로딩을 보호하며, `Root`에 처음 접근할 때 자동으로 `Initialize()`를 호출합니다. Android 플랫폼에서는 구현이 `ApkImpl`로 전환되며, Editor, Standalone, iOS, WebGL 등의 플랫폼에서는 `LooseFilesImpl`이 사용됩니다.

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    string root = BlankReadAssets.Root;
    UnityEngine.Debug.Log("StreamingAssets Root = " + root);
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L46-L54)

2. **매개변수 없는 초기화를 수동으로 호출**. 이 오버로드는 `Application.dataPath`와 `Application.streamingAssetsPath`를 초기화 매개변수로 사용합니다.

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    BlankReadAssets.Initialize();
    string root = BlankReadAssets.Root;
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L56-L61)

3. **사용자 지정 경로를 사용하여 초기화**. 테스트 또는 외부 리소스 디렉터리 시나리오에서 임의의 `dataPath`와 `streamingAssetsPath`를 전달합니다.

    ```csharp
    BlankReadAssets.Initialize(
        dataPath: "/path/to/your/project",
        streamingAssetsPath: "/path/to/your/project/Assets/StreamingAssets");
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L63-L68)

4. **Android가 아닌 플랫폼에서 `Root`는 `streamingAssetsPath`에서 가져옵니다**. LooseFilesImpl은 전달받은 `streamingAssetsPath`를 절대 경로로 변환하고, 백슬래시를 바꾸고, 끝의 슬래시를 제거한 후 `s_root`에 할당합니다.

    ```csharp
    // LooseFilesImpl.Initialize의 구현
    s_root = Path.GetFullPath(streamingAssetsPath).Replace('\\', '/').TrimEnd('/');
    ```

    Source: [BlankReadAssets.LooseFilesImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L17-L20)

5. **Android 플랫폼에서 `Root`는 APK 경로입니다**. ApkImpl은 `dataPath`를 `s_root`에 할당하며, 콘텐츠를 찾지 못하면 `base.apk`로 폴백합니다. patch overlay 시나리오에서 `s_root`는 `pram-shadow-files` 디렉터리입니다.

    ```csharp
    // ApkImpl.Initialize의 구현
    s_root = dataPath;
    ```

    Source: [BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

## 일반적인 변형

- **Editor에서 외부 APK 파일을 지정하여 읽기**. `UNITY_EDITOR`에서만 사용할 수 있으며, 에디터에서 Android의 압축 APK 경로 액세스를 시뮬레이션할 수 있습니다.

    ```csharp
    BlankReadAssets.InitializeWithExternalApk("/path/to/your.apk");
    string root = BlankReadAssets.Root;
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

- **Editor에서 외부 StreamingAssets 디렉터리 사용**. InitializeWithExternalApk와 짝을 이루며, ApkMode를 끈 후에도 디렉터리 방식으로 읽습니다.

    ```csharp
    BlankReadAssets.InitializeWithExternalDirectories(
        dataPath: "/path/to/project",
        streamingAssetsPath: "/path/to/project/Assets/StreamingAssets");
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

- **지연 로딩을 끄고 초기화를 미리 완료**. 일부 시나리오(예: 애플리케이션 시작 후 즉시 파일 존재 확인)에서는 다른 API를 호출하기 전에 초기화를 완료하기를 원하며, 매개변수 없는 `Initialize()`를 명시적으로 호출할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Root`이 빈 문자열이거나 비정상 경로 | Android에서 APK 경로가 준비되기 전에 읽었으며, ApkImpl의 `s_root`은 `dataPath`에 의존합니다 | `BlankReadAssets.Initialize()`를 사용하여 프레임워크가 `Application.dataPath`로 초기화를 완료하도록 하거나, 임의의 API에 먼저 접근하여 `EnsureInitialized`를 트리거합니다 |
| Editor에서 APK을 디렉터리로 순회하려고 함 | `InitializeWithExternalApk`를 호출하지 않았음 | `InitializeWithExternalApk(apkPath)`을 명시적으로 호출하여 ApkImpl로 전환합니다 |
| 사용자 지정 경로에서 `ArgumentNullException` 발생 | `dataPath` 또는 `streamingAssetsPath`에 null을 전달했음 | 상위 구성을 확인하고 null 값이 `Initialize(string, string)`에 전달되지 않도록 합니다 |

## 배경(선택 사항)

플랫폼 구현은 `using BlankReadAssetsImpl = ...` 정적 별칭을 통해 컴파일 타임 조건으로 전환되어, 서로 다른 대상 플랫폼이 서로 다른 `Initialize`를 호출하도록 보장합니다. `EnsureInitialized()`와 `s_initialized` 정적 플래그가 함께 초기화가 한 번만 발생하도록 보장하며, 이후 모든 읽기 API는 첫 번째 결과를 재사용합니다. 이것이 바로 `Root`이 모든 위치에서 안전하게 액세스될 수 있는 이유입니다.
