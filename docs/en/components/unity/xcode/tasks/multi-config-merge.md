# Multi-Module Configuration File Merging

Write each module's iOS build configuration as a `XCodeConfig.json` file. After the Xcode project is exported, the framework automatically scans and merges all configuration files with the same name (including channel-specific configurations), then writes the merged result into the Xcode project in a single pass. You don't need to manually aggregate one large configuration—just place the file in a location that can be scanned.

## Prerequisites

- The Unity project has imported this package (Editor assembly `GameFrameX.Xcode.Editor`).
- The build target is iOS: the entire merging process is inside `#if UNITY_IOS`; other platforms return directly.

## Steps

1. Create a `XCodeConfig.json` for each module, containing only the fields that module cares about. The framework scans out the full list of matching file paths via `SettingLoader.LoadSettingsData("XCodeConfig.json")` (see [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58)).
2. Run an iOS build. After the build completes, a Unity callback executes automatically and begins reading and merging the configuration:

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        // Read the configuration files
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // If no matching files were found, return directly
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }

        // Merge the contents of all configuration files
        Hashtable finalConfig = new Hashtable();
        foreach (var jsonPath in jsonPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
            string json = File.ReadAllText(jsonPath);
            Hashtable table = json.HashtableFromJson();
            if (table == null)
            {
                LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
                continue;
            }

            // Merge the Hashtable using an extension method
            finalConfig.Merge(table);
        }
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L49)

3. (Optional) Provide channel-specific configuration. The framework obtains the current channel via `SettingLoader.GetChannel()`, then loads `XCodeConfig.{channel}.json` and merges it last, so channel configuration has the highest priority and overrides fields with the same name in the regular configuration:

```csharp
// Merge channel-specific configuration (highest priority, merged last to override)
string channel = SettingLoader.GetChannel();
if (!string.IsNullOrEmpty(channel))
{
    var channelPaths = SettingLoader.LoadChannelSettingsData("XCodeConfig.json", channel);
    if (channelPaths.Count > 0)
    {
        LogHelper.Log($"[MergeConfig] 检测到渠道: {channel}，正在合并渠道配置...");
        foreach (var channelPath in channelPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并渠道配置: {channelPath}");
            string channelJson = File.ReadAllText(channelPath);
            Hashtable channelTable = channelJson.HashtableFromJson();
            if (channelTable == null)
            {
                LogHelper.Error($"{channelPath} 解析失败, 跳过合并");
                continue;
            }

            finalConfig.Merge(channelTable);
        }
    }
    else
    {
        LogHelper.Log($"[MergeConfig] 未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json");
    }
}
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)

4. Check the Console output. Every merged file prints `[MergeConfig] 正在合并配置: <路径>` (channel configurations print `[MergeConfig] 正在合并渠道配置: <路径>`), which lets you confirm which files participated in the merge.

## Mergable Top-Level Configuration Fields

The merged result is applied according to the following keys (key names come from the actual values retrieved by `finalConfig.Get<...>(...)`; each module only needs to provide the keys it uses):

| Key | Type | Applied Action |
|----|------|----------|
| `unityMain` | Hashtable | Applied to the Unity main Target: `properties`, `frameworks`, `libs`, `files`, `folders`, `filesCompileFlag`, `otherLinkerFlag`, `runPathSearchPaths` (and the legacy `pods`) |
| `unityFramework` | Hashtable | Same as above, applied to the UnityFramework Target |
| `signing` | Hashtable | Signing configuration, set only on the main Target; its `bundleId` is used by Capabilities |
| `swiftBridging` | bool | Swift bridging switch; defaults to enabled when absent |
| `plist` | Hashtable | Written to Info.Plist |
| `environmentVariables` | Hashtable | Launch environment variables |
| `launcherArgs` | ArrayList | Launch arguments |
| `capabilities` | Hashtable | Capability settings, set only on the main Target |
| `localizations` | ArrayList | Localization resources |
| `podSource` | ArrayList | Sources for the Podfile's `source` |
| `podfile` | string | Path to a complete Podfile configuration; after a successful copy, the new path is used |
| `podInstall` | bool | Whether to run `pod install` after Podfile processing; defaults to enabled when absent |

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L89-L156)

## Common Variants

- **A module's JSON fails to parse but the build should still complete**: a single file's parse failure only logs an `Error` and `continue`s; it does not interrupt the overall process, and the remaining files continue to merge.
- **Do not want to run `pod install`**: set `"podInstall": false` in (any participating) configuration, see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L151-L156).
- **Disable Swift bridging**: set `"swiftBridging": false`; it is enabled by default when the key is absent, see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101).

## Common Errors

| Symptom (original log text) | Cause | Fix |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | The scan result is empty; no module provided a configuration | Confirm that at least one `XCodeConfig.json` exists that can be scanned by `LoadSettingsData` |
| `<路径> 解析失败, 跳过合并` | The file content is not valid JSON; `HashtableFromJson()` returned null | Fix the file's JSON syntax; that file is skipped while the remaining files merge normally |
| `合并后的配置为空，跳过设置` | All files failed to parse or were empty | Check each JSON file; verify the list of merged files against the `[MergeConfig] 正在合并配置:` log |
| `[MergeConfig] 未找到渠道 [...] 的专属配置文件 XCodeConfig.[...].json` | The channel is set but the channel-specific file is missing | Create `XCodeConfig.{渠道}.json` as needed; not creating it does not prevent the regular configuration from taking effect |

## Verification

- `[MergeConfig] 正在合并配置: ...` appears in the Console listing all participating files; when a channel is set, `[MergeConfig] 检测到渠道: <渠道>` appears along with the corresponding channel merge logs.
- `[PBXProject] 正在应用最终合并配置...` and `[OtherSettings] 正在应用最终合并配置...` appear afterward, indicating the merged result has been written into the project.
- Open the exported Xcode project and verify that the Target's build properties, frameworks/libraries, Info.Plist, Podfile, etc. match the post-merge expectations.

## Background

The merging is layered file by file based on the `Hashtable.Merge()` extension method; later merges override earlier ones, so the load order is the priority order, and channel configuration is merged last with the highest priority. The entire process is null-tolerant when reading values via `Get<Hashtable>(...)`, so each module only needs to write the keys it requires without providing the full structure.
