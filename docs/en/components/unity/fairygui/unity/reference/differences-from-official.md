# Differences from the Official FairyGUI

This package is the GameFrameX distribution of the official [FairyGUI-unity](https://github.com/fairygui/FairyGUI-unity) (UPM package name `com.gameframex.unity.fairygui.unity`). Building on the official code, it adds the pixelated rendering compile macro `ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED`, several GList/editor fixes, and completes the package description information per UPM conventions; the code namespace remains `FairyGUI`, so existing `using FairyGUI` references require no modification.

## Compile Macro Difference: ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED

This compile macro does not exist in the official FairyGUI-unity. Once it is defined in this package, FairyGUI's material system gains an additional `Pixelated` material variant flag:

| Affected Location | Official Behavior | This Package (with Macro Defined) |
|------------|----------|------------------|
| `MaterialFlags` enum | Ends at `ColorFilter = 32` | Adds `Pixelated = 64` |
| `MaterialManager.internalKeywords` | 6 built-in keywords | 7, appending `"PIXELATED"` |
| `MaterialManager.GetMaterial` | Generates materials based on the flags passed by the caller | Unconditionally `flags |= Pixelated`, i.e., the pixelated effect is enabled by default |

The differing code at the enum definition:

```csharp
namespace FairyGUI
{
    [Flags]
    public enum MaterialFlags
    {
        Clipped = 1,
        SoftClipped = 2,
        StencilTest = 4,
        AlphaMask = 8,
        Grayed = 16,
        ColorFilter = 32,
#if ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED
        Pixelated = 64
#endif
    }
```

Source: [MaterialManager.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/MaterialManager.cs#L6-L20)

Sources: [MaterialManager.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/MaterialManager.cs#L45-L51), [MaterialManager.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/MaterialManager.cs#L101-L109)

Usage: Add `ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED` in Unity's **Player Settings → Scripting Define Symbols** (or assembly defines) to enable it; when the macro is not defined, all three differences above revert to behavior identical to the official version. Note that once enabled, the variant keyword list of all FairyGUI materials will include `PIXELATED`.

## Input System Difference: FAIRYGUI_INPUT_SYSTEM

This package retains two touch-reading paths in [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L891-L902): when `FAIRYGUI_INPUT_SYSTEM` is defined, the new Input System's `Touch.activeTouches` / `Touch.screenPosition` is used; when not defined, it falls back to the legacy `Input.GetTouch`. If your project uses the new Input System, you must define this macro; otherwise touch (multi-finger) events will not be dispatched — this is also the direction of the change associated with issue [#1 "uTouch compatibility issue"](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/issues/1) in the CHANGELOG.

```csharp
#if FAIRYGUI_INPUT_SYSTEM
                foreach (Touch uTouch in Touch.activeTouches)
                {
                    Vector2 pos = uTouch.screenPosition;
                    int touchId = uTouch.touchId;
                ...
#else
                    Touch uTouch = Input.GetTouch(i);
```
