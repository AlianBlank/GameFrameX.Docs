# 處理建置期間的程式碼剝離

當您在玩家設定(Player Settings)中啟用**受管理的剝離層級(Managed Stripping Level)**(尤其是 High/Medium)或使用 IL2CPP 建置時，若出現 `NetworkComponent` 或網路事件類別遺失、`CreateNetworkChannel` 拋出 `MissingMethodException` / `TypeLoadException` 等問題，通常都是 Unity 的受管理程式碼剝離移除了未被靜態參考的類型/方法所致。本套件已為關鍵類型加上 `[UnityEngine.Scripting.Preserve]` 標註，因此在大多數情況下無需額外處理；實際會被剝離的，通常是您自己專案中透過反射/字串方式註冊的部分——只需按照下方步驟加上保護即可。

## 前置條件

- Unity 版本 2019.4 或更高(本套件 `package.json` 中宣告的最低版本)。
- 已安裝 `com.gameframex.unity.network`(目前版本 2.6.10)及其相依套件 `com.gameframex.unity`、`com.gameframex.unity.event` 與 `com.gameframex.unity.litjson`。
- 建置目標平台使用 IL2CPP,或已在玩家設定中啟用受管理的剝離層級(Low/Medium/High)。

## 步驟

1. 首先，確認本套件內建的保護是否已生效。本套件已為每個入口元件與公開 API 加上 `[UnityEngine.Scripting.Preserve]` 標註，例如 `NetworkComponent` 類別本身：

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Network")]
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkComponent : GameFrameworkComponent
   ```
   來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L42-L45)

   其公開方法(如 `CreateNetworkChannel`、`GetNetworkChannel`)同樣帶有 `[Preserve]`:

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   ```
   來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L176)

   網路事件參數類別也全部加上了 `[Preserve]` 標註(這些類別常透過事件系統以類型方式派發，因此很容易成為被剝離的目標)：

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkConnectedEventArgs : GameEventArgs
   ```
   來源:[NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L40-L41)

   `NetworkClosedEventArgs`、`NetworkErrorEventArgs`、`NetworkMissHeartBeatEventArgs`,以及 `NetworkManager.HeartBeatState` 的無參數建構函式也做了同樣處理(框架內部會透過反射建立狀態物件)：
   來源:[NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L43-L45)

2. 開啟 **Edit → Project Settings → Player → Other Settings → Optimization → Managed Stripping Level** 並檢查目前的剝離層級。如果只是零星缺少類型，可以先把層級降為 **Low(或 Minimal)** 並進行測試建置，確認問題確實是由剝離所造成。

3. 檢查**您自己專案中**被剝離的類型。以下是本套件無法代為保護的常見情況：
   - 您自行實作的 `INetworkChannelHelper` 衍生類別(用於傳送/接收的封包標頭與封包主體處理器)；
   - 您透過 `NetworkComponent` 註冊、但僅以字串/反射方式參考的訊息處理器；
   - 用於序列化的資料模型(例如 LitJSON 相關的 DTO)。

4. 對於上述您自己擁有的類型，建議優先為類別及其公開成員加上 `[UnityEngine.Scripting.Preserve]`(與本套件的做法一致)：

   ```csharp
   // 您專案中的使用範例:屬性的用法與套件中的 NetworkComponent 相同
   [UnityEngine.Scripting.Preserve]
   public sealed class MyNetworkChannelHelper : INetworkChannelHelper
   {
       ...
   }
   ```

5. 如果被剝離的類型很多，逐一加上屬性並不實際，可在專案的 `Assets/` 資料夾下建立 `link.xml` 以保留整個組件(這是 Unity 的官方機制；**本儲存庫並未內含 link.xml**,您需要在實際使用本套件的專案中自行建立)：

   ```xml
   <linker>
     <!-- 保留整個網路組件 -->
     <assembly fullname="GameFrameX.Network.Runtime" preserve="all"/>
     <!-- 保留您自己的業務/協定組件 -->
     <assembly fullname="YourAssemblyName" preserve="all"/>
   </linker>
   ```

6. 重新建置，在建置日誌中確認沒有 `MissingMethodException`/`TypeLoadException`,並依照下方「驗證」一節進行實機連線測試。

## 驗證

- 建置後，場景中掛載的 `NetworkComponent`(選單路徑 GameFrameX/Network)可正常建立；
- `CreateNetworkChannel` 回傳的頻道能完成連線，並收到 `NetworkConnectedEventArgs` 事件；
- 心跳邏輯正常運作(表示 `HeartBeatState` 未被剝離)，且在網路斷線時會收到 `NetworkMissHeartBeatEventArgs`/`NetworkErrorEventArgs`。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 建置時回報 `TypeLoadException`/`MissingMethodException`;在編輯器中卻一切正常 | 受管理剝離移除了僅透過反射參考的類型 | 調低受管理的剝離層級，或為受影響的類型加上 `[UnityEngine.Scripting.Preserve]` |
| 心跳狀態物件建立失敗 | `HeartBeatState` 的無參數建構函式被剝離(框架內部會透過反射建立它) | 套件本身已加上 `[Preserve]`;若您曾 fork/修改此檔案，請確認該屬性仍被保留 |
| 收不到 `NetworkConnectedEventArgs` 等網路事件 | 事件參數類別被剝離，導致事件系統無法將其還原序列化 | 套件本身已加上 `[Preserve]`;請檢查是否有 fork 覆寫了它們，或您自己的 EventArgs 缺少標註 |
| 您自己的 `INetworkChannelHelper` 衍生類別的方法遺失 | 您專案中的類型未被靜態參考 | 為您的 Helper 類別加上 `[Preserve]`,或撰寫 link.xml |
| 加入 link.xml 後仍被剝離 | 檔案不在 `Assets/` 之下，或 XML 格式不正確 | 確認路徑與 `assembly fullname` 拼寫無誤(組件名稱請參閱 asmdef) |

## 背景

使用 IL2CPP/高剝離層級建置時，Unity 會移除無法從受管理程式碼進入點靜態連到的類型與成員。網路框架大量採用「介面 + 反射 + 事件派發」的模式——例如透過 `INetworkManager` 介面尋找實作、透過事件系統以類型派發 `NetworkConnectedEventArgs` 等參數類別——這些參考對剝離器而言是不可見的。因此，本套件已在上述每個關鍵位置加上 `[UnityEngine.Scripting.Preserve]` 標註(見上方步驟 1 引用的原始碼)。它涵蓋了套件中的所有公開類型，但無法涵蓋您專案端透過反射註冊的類型；這部分需要您以相同的方式自行保護。
