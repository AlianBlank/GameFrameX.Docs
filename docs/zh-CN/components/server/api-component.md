# 公开 API 与组件注册速查

本页收录 GameFrameX 框架对外开放的核心 API、组件接口与组件注册相关约定,方便在编写业务模块时快速对照使用。

## 组件接口

| 名称 | 类型/签名 | 说明 |
|------|-----------|------|
| `IComponent` | `interface IComponent { IActor Actor { get; set; } }` | 组件基接口,所有自定义组件均需实现,持有其所属 Actor。 |
| `IComponentAgent` | `interface IComponentAgent : IWorker` | 组件代理接口,负责代理某个组件并对外提供异步调用入口。 |

## 组件代理公开成员

`IComponentAgent` 的关键成员如下表,实现或调用时直接对照:

| 成员 | 签名 | 说明 |
|------|------|------|
| `ActorId` | `long ActorId { get; }` | 当前 Agent 绑定的 Actor 唯一标识。 |
| `Owner` | `IComponent Owner { get; }` | Agent 所属父级组件实例。 |
| `OwnerType` | `ushort OwnerType { get; }` | 所有者组件的类型标识(ushort)。 |
| `SetOwner(IComponent)` | `void SetOwner(IComponent owner)` | 设置/变更组件所有者。 |
| `BeforeActivation` | `Task<bool> BeforeActivation()` | 激活前回调,返回 `bool` 表示是否继续。 |
| `Active` | `Task<bool> Active()` | 激活组件代理。 |
| `AfterActivation` | `Task<bool> AfterActivation()` | 激活后回调。 |
| `BeforeInActivation` | `Task<bool> BeforeInActivation()` | 反激活前回调。 |
| `Inactive` | `Task Inactive()` | 反激活并清理资源。 |
| `AfterInActivation` | `Task<bool> AfterInActivation()` | 反激活后回调。 |
| `GetComponentAgent(Type, bool)` | `Task<IComponentAgent> GetComponentAgent(Type agentType, bool isNew = true)` | 按类型获取或新建子 Agent。 |
| `GetComponentAgent<T>(bool)` | `Task<T> GetComponentAgent<T>(bool isNew = true) where T : IComponentAgent` | 泛型版本。 |

## 组件类型与生命周期约定

组件的激活流程按以下顺序串联,业务方在重写钩子方法时按需填充逻辑即可:

1. `BeforeActivation` —— 预处理,返回 `false` 可中止激活。
2. `Active` —— 真正执行初始化。
3. `AfterActivation` —— 初始化收尾。

反激活按相反方向:

1. `BeforeInActivation` —— 状态保存/资源释放。
2. `Inactive` —— 执行反激活。
3. `AfterInActivation` —— 清理确认。
