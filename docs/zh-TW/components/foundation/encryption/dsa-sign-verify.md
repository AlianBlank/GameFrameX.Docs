# DSA 簽章驗證的使用方法

`DsaHelper` 提供 DSA 數位簽章演算法的簽署與驗證功能。它使用 SHA256 作為雜湊演算法，金鑰以 XML 字串形式儲存。本頁說明從產生金鑰對、驗證單一字串簽章，到重複使用 `DsaHelper` 執行個體等一系列步驟。

## 前置條件

- 專案已參考 `GameFrameX.Foundation.Encryption` 套件。
- 目標框架為 .NET(支援 `System.Security.Cryptography.DSA`)。`DsaHelper` 內部使用 `DSA.Create()`,在 Windows / Linux / macOS 上皆可運作。
- 使用命名空間 `using GameFrameX.Foundation.Encryption;`。

## 操作步驟

### 1. 產生 DSA 金鑰對

呼叫 `DsaHelper.Make()` 可一次取得私鑰與公鑰的 XML 字串。分別透過索引鍵 `privatekey`、`publickey` 取出：

```csharp
using GameFrameX.Foundation.Encryption;

var keys = DsaHelper.Make();
string privateKey = keys["privatekey"]; // XML 私鑰
string publicKey  = keys["publickey"];  // XML 公鑰
```

Source: [DsaHelper.cs#L127-L140](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L127-L140)

### 2. 簽署字串資料(靜態方法)

將待簽署的字串與私鑰傳入 `SignData(string, string)`,即會回傳 Base64 編碼的簽章值。若私鑰格式不正確，將擲出 `CryptographicException`,並顯示 `"Invalid DSA private key."`。

```csharp
using GameFrameX.Foundation.Encryption;

string data = "hello world";
string signature = DsaHelper.SignData(data, privateKey); // 回傳 Base64 字串
```

簽章的實際流程:`Encoding.UTF8.GetBytes` → `DSA.SignData(..., HashAlgorithmName.SHA256)` → `Convert.ToBase64String`。

Source: [DsaHelper.cs#L189-L200](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L189-L200)

### 3. 驗證字串簽章(靜態方法)

將原始資料、Base64 簽章與公鑰傳入 `VerifyData(string, string, string)`。若回傳 `true` 表示簽章有效；若公鑰格式不正確或簽章無效，則回傳 `false`(不會擲出例外)：

```csharp
using GameFrameX.Foundation.Encryption;

bool ok = DsaHelper.VerifyData(data, signature, publicKey);
```

內部會呼叫 `DSA.VerifyData(..., HashAlgorithmName.SHA256)`,並攔截 `CryptographicException` 與 `XmlException` 後回傳 `false`。

Source: [DsaHelper.cs#L282-L287](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L282-L287)

### 4. 位元組陣列的直接簽署與驗證(選用)

若想避免字串/Base64 的編碼與解碼，也可使用 `byte[]` 多載。簽署時 `CryptographicException` 或 `XmlException` 會在內部被吸收並回傳 `null`,因此需要自行處理：

```csharp
using GameFrameX.Foundation.Encryption;

byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello world");
byte[] signedBytes = DsaHelper.SignData(payload, privateKey);     // 失敗時回傳 null
bool valid = DsaHelper.VerifyData(payload, signedBytes, publicKey); // 失敗時回傳 false
```

### 5. 重複使用 `DsaHelper` 執行個體(選用)

若在同一處理序內重複進行簽署/驗證，建議使用 `using` 搭配公鑰或私鑰來保留 `DsaHelper` 執行個體，以避免每次呼叫 `FromXmlString` 的額外開銷。執行個體方法會透過 `_dsa.SignData` / `_dsa.VerifyData` 執行，例外會直接向上層擲出：

```csharp
using GameFrameX.Foundation.Encryption;

using (var signer = new DsaHelper(privateKey))
{
    string signature = signer.SignData("hello world"); // Base64
}

using (var verifier = new DsaHelper(publicKey))
{
    bool ok = verifier.VerifyData("hello world", signature);
}
```

建構函式支援兩種多載：可傳入 `DSA` 執行個體或 XML 金鑰字串。傳入 null / 空字串時會分別擲出 `ArgumentNullException` / `ArgumentException`,XML 格式不正確時則會擲出 `CryptographicException`。

## 常見變化

- **結合執行個體簽署與靜態驗證(跨處理序傳輸情境)**：傳送端以 `new DsaHelper(privateKey).SignData(原文)` 取得 Base64 簽章並隨訊息一併傳送，接收端再以 `DsaHelper.VerifyData(原文, 署名, 公钥)` 進行驗證。
- **位元組資料流的簽署**：當資料本身即為位元組序列(例如已序列化的 protobuf)時，直接呼叫 `byte[]` 多載，略過 UTF-8 / Base64 的編碼與解碼。
- **金鑰由設定檔取得的情況**：將 `Make()` 的輸出以 XML 字串形式儲存至設定中心，於啟動時讀取後，直接傳入建構函式或靜態方法。

## 常見錯誤

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| `SignData(string, string)` 擲出 `CryptographicException: Invalid DSA private key.` | 私鑰字串並非有效的 DSA XML,或誤將公鑰當作私鑰傳入 | 確認傳入的是 `Make()["privatekey"]`。若 XML 已損毀，請重新產生 |
| `SignData(byte[], string)` 回傳 `null` | 私鑰格式不正確(`CryptographicException` 或 `XmlException` 已在內部被吸收) | 檢查金鑰的 XML。改用字串多載即可取得明確的例外資訊 |
| `VerifyData` 一律回傳 `false` | 公鑰/原始資料/簽章其中之一不一致(編碼方式、截斷、使用不同的金鑰對) | 確認原始資料一致使用 UTF-8 編碼、簽章未經重複 Base64 編碼，且簽署與驗證雙方使用對應的金鑰對 |
| `new DsaHelper(null)` 擲出 `ArgumentNullException` | 傳入了 null 的 `DSA` 執行個體或金鑰字串 | 建構前先驗證輸入值。XML 金鑰請先透過 `ArgumentException.ThrowIfNullOrEmpty` 處理後再傳入 |
| 在 macOS 上指定 2048 位元金鑰時失敗 | 平台的 DSA 實作對預設以外金鑰長度的支援有限 | 直接使用 `DsaHelper.Make()` 產生的預設長度金鑰對 |

## 背景(選用)

`DsaHelper` 內部統一使用 `DSA.Create()` 取代已淘汰的 `DSACryptoServiceProvider`,並在簽章雜湊中明確指定 `HashAlgorithmName.SHA256`,以避開 DSA 預設 SHA-1 的弱點。此類別實作 `IDisposable`,因此若長時間保留執行個體，請務必使用 `using` 釋放底層的非受控資源。DSA 僅能用於簽章驗證，無法用於加密與解密。
