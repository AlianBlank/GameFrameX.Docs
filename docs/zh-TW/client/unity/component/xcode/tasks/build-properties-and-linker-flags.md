# 設定 Build Properties 與連結器旗標

在 `XCodeConfig.json` 的 `unityMain` / `unityFramework` 段落下填寫 `properties`(Build Settings)與 `otherLinkerFlag`(連結器旗標，如 `OTHER_LDFLAGS`),Unity 匯出 iOS 專案後會由建置後處理自動寫入產生的 Xcode 專案，無需手動開啟 Xcode 修改 Build Settings。

## 前置條件

- Unity 已切換到 iOS 平台。
- 專案中存在名為 `XCodeConfig.json` 的設定檔(檔名必須一致，後處理按該檔名掃描)；可複製儲存庫自帶的 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) 或 [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json) 改名後使用。

## 操作步驟

1. 在專案中建立 `XCodeConfig.json`(內容參考儲存庫自帶範本與範例)。
2. 確定目標 target:主可執行程式 Unity-iPhone 寫在 `unityMain` 段，動態函式庫寫在 `unityFramework` 段，兩段結構完全相同。
3. 用 `properties` 欄位修改 Build Settings,支援三種運算子：

| 運算子 | 實際呼叫的 PBXProject API | 作用 |
|--------|---------------------------|------|
| `=` | `SetBuildProperty(targetGuid, key, value)` | 直接覆蓋某項 Build Setting 的值 |
| `+` | `UpdateBuildProperty(targetGuid, key, list, null)` | 向清單型 Build Setting 附加值 |
| `-` | `UpdateBuildProperty(targetGuid, key, null, list)` | 從清單型 Build Setting 移除值 |

   三種運算子的解析邏輯(節選自 `SetBuildProperties`):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}

Hashtable addTable = table.Get<Hashtable>("+");
// ... 省略 ArrayList 轉 List<string> ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), list, null);

Hashtable removeTable = table.Get<Hashtable>("-");
// ... 省略 ArrayList 轉 List<string> ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), null, list);
```

Source: [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L58)

4. 按上表結構寫 JSON(鍵 `=`/`+`/`-` 下的鍵值即為 Build Setting 名稱與值，`+`/`-` 的值必須是陣列)：

```json
{
  "unityFramework": {
    "properties": {
      "=": { "ENABLE_BITCODE": "NO" },
      "+": { "OTHER_LDFLAGS": ["-lxml2"] },
      "-": { "OTHER_LDFLAGS": ["-ObjC"] }
    }
  }
}
```

5. 用 `otherLinkerFlag` 欄位新增連結器旗標，與 `properties` 同層。範例檔案中的實際寫法：

```json
"otherLinkerFlag": {
  "OTHER_LDFLAGS": ["-ObjC"]
}
```

Source: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L152-L154)

   旗標會被逐條附加到對應的 Build Setting 上(每條呼叫一次 `AddBuildProperty`):

```csharp
foreach (DictionaryEntry kv in table)
{
    var keyStr = kv.Key.ToString().Trim();
    if (kv.Value is ArrayList list)
    {
        // 陣列:逐條 AddBuildProperty
        foreach (var part in parts)
        {
            proj.AddBuildProperty(targetGuid, keyStr, part);
        }
    }
    else
    {
        // 字串:直接 AddBuildProperty
        proj.AddBuildProperty(targetGuid, keyStr, kv.Value.ToString().Trim());
    }
}
```

Source: [PostProcessBuildHelper.OtherLinkFlag.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.OtherLinkFlag.cs#L15-L47)

6. 觸發 iOS 建置。`[PostProcessBuild(888)]` 的 `OnPostProcessBuild` 會讀取所有 `XCodeConfig.json` 合併為一份設定，依序對 `GetUnityMainTargetGuid()` 與 `GetUnityFrameworkTargetGuid()` 套用設定，最後寫回 `Unity-iPhone.xcodeproj/project.pbxproj`。

```csharp
Run(project, project.GetUnityMainTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityMain"), path);
Run(project, project.GetUnityFrameworkTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityFramework"), path);
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L104)

## 常見變體

- **陣列或單一字串均可**:`otherLinkerFlag` 的值寫成陣列(如 `["-ObjC", "-lxml2"]`)會逐條附加；寫成單一字串則整體新增一次，兩種寫法在原始碼中都有處理分支。
- **多份設定合併**：所有掃描到的 `XCodeConfig.json` 會按順序合併，後合併的覆蓋先合併的；若啟用了通路(`SettingLoader.GetChannel()`),`XCodeConfig.{channel}.json` 最後合併、優先順序最高。
- **同段其他欄位**:`unityMain` / `unityFramework` 段內還可同時設定 `frameworks`、`libs`、`files`、`folders`、`filesCompileFlag`、`runPathSearchPaths` 等欄位，由同一次 `Run` 依序套用。

## 常見錯誤

| 現象 / 日誌原文 | 原因 | 修復 |
|-----------------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 檔名不是 `XCodeConfig.json`,或所在位置無法被掃描到 | 改成正確檔名並放到可掃描位置 |
| `{jsonPath} 解析失败, 跳过合并` | JSON 語法錯誤 | 用 JSON 校驗工具修正後再建置 |
| `合并后的配置为空，跳过设置` | 所有檔案均解析失敗 | 檢查各設定檔語法 |
| 改了 `properties` / `otherLinkerFlag` 但 Xcode 裡沒生效 | 欄位寫在 JSON 頂層 | 這兩個欄位必須寫在 `unityMain` 或 `unityFramework` 段內，`Run` 只從這兩個段讀取 |
| `+` / `-` 操作不生效 | 值寫成了字串 | 原始碼以 `i.Value as ArrayList` 讀取，字串會得到空清單，必須寫成陣列 |

## 背景

`properties` 最終落到 `SetBuildProperty` / `UpdateBuildProperty`,`otherLinkerFlag` 落到 `AddBuildProperty`,都是 Unity 自帶 `UnityEditor.iOS.Xcode.PBXProject` 的標準介面，區別在於前者支援覆蓋與增刪，後者只做附加。整個流程掛在 `[PostProcessBuild(888)]` 回呼上，僅在 `target == BuildTarget.iOS` 時執行。
