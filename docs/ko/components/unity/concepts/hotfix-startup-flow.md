# 작동 원리: Hotfix 진입점과 시작流程

Hotfix 시작은 프레임워크 내의 [`HotfixHelper`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs)가 담당합니다: 런타임에 AOT DLL과 热更 DLL을 로드하고, 약속된 진입 타입과 메서드를 찾아 리플렉션을 통해 热更 코드를 초기화합니다. 애플리케이션 레이어는 [`ApplicationHotfixLauncher`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs)를 통해 이 로직을 시작 파이프라인의 `IHotfixLauncher` 인터페이스에适配합니다.

## 시작 진입점 목록

| 진입점 | 타입 | 역할 |
|------|------|------|
| `HotfixHelper.StartHotfix()` | `async void` | 기본 옵션으로 트리거하며 반환 결과는 무시 |
| `HotfixHelper.StartHotfixAsync(StartupOptions)` | `async UniTask<HotfixLaunchResult>` | 비동기 로드 후 시작 결과 반환 |
| `ApplicationHotfixLauncher.StartAsync(StartupOptions)` | `UniTask<HotfixLaunchResult>` | `IHotfixLauncher` 어댑터, `HotfixHelper.StartHotfixAsync`로 전달 |

기본 파라미터 (`options == null` 또는 필드가 비어 있을 때 적용):

| 필드 | 기본값 |
|------|--------|
| `HotfixAssemblyName` | `Unity.Hotfix` |
| `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` |
| `HotfixEntryMethodName` | `Main` |

## 시작 단계

1. `HotfixHelper.StartHotfixAsync(options)`를 호출하면 메서드는 `try/catch`로 감싸진 내부 구현 `StartHotfixInternalAsync`로 진입합니다.
2. 최종 `assemblyName` / `entryTypeName` / `entryMethodName`을 파싱하며, 기본값은 각각 `Unity.Hotfix`, `Hotfix.HotfixLauncher`, `Main`입니다.
3. 매크로 `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR`에 따라 로드 경로를 선택합니다:
   - **HybridCLR 활성화 (그리고 Editor가 아님)**: 먼저 `AOTGenericReferences.PatchedAOTAssemblyList`를 순회하며, 각 AOT DLL을 `GameApp.Asset.LoadAssetAsync<UnityEngine.Object>`로 로드하고 `RuntimeApi.LoadMetadataForAOTAssembly`를 호출합니다; 그다음 `Unity.Hotfix.dll`을 로드하고 `Assembly.Load`를 수행합니다.
   - **Editor 또는 HybridCLR 미활성화**: 바로 `RunNative`으로 진입하며, `Utility.Assembly.GetType` 리플렉션으로 진입점을 호출합니다.
4. 리플렉션으로 대상 타입과 메서드를 찾은 후 `method.Invoke(null, null)`을 실행하여 热更 레이어로 제어권을 넘깁니다.
5. 성공 시 `HotfixLaunchResult.Succeed()`를 반환합니다; 예외 발생 시 `Log.Error`로 기록하고 `HotfixLaunchResult.Fail(e.Message)`를 반환합니다.

핵심 코드:

```csharp
public static async void StartHotfix()
{
    await StartHotfixAsync(null);
}
```

```csharp
public static async UniTask<HotfixLaunchResult> StartHotfixAsync(StartupOptions options)
{
    try
    {
        await StartHotfixInternalAsync(options);
        return HotfixLaunchResult.Succeed();
    }
    catch (Exception e)
    {
        Log.Error(e);
        return HotfixLaunchResult.Fail(e.Message);
    }
}
```

## 주요 로드 경로

| 단계 | 호출 | 설명 |
|------|------|------|
| AOT 메타데이터 로드 | `RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet)` | HybridCLR 모드에서는 반드시 모든 AOT DLL을 먼저 로드해야 합니다. 그렇지 않으면 热更 코드에서 제네릭 공유가 실패합니다 |
| 热更 DLL 로드 | `Assembly.Load(assemblyDataHotfixDll, null)` | 바이트 배열을 런타임 어셈블리로 로드 |
| 진입점 리플렉션 | `assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | 리플렉션으로 매개변수 없는 정적 진입점을 호출 |
| 네이티브 폴백 | `Utility.Assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | HybridCLR가 아닌 모드에서 이미 로드된 AppDomain에서 진입 타입을 탐색 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `entryType`이 `null`이며 리플렉션 시 `NullReferenceException` 발생 | 전달된 `HotfixEntryTypeName`이 DLL 내부 타입과 일치하지 않거나, `Unity.Hotfix.dll`이 리소스에 포함되지 않음 | `options.HotfixEntryTypeName`이 DLL의 네임스페이스/클래스명과 완전히 일치하는지 확인; `Utility.Asset.Path.GetCodePath("Unity.Hotfix.dll")`가 리소스를 정상적으로 해석하는지 확인 |
| 제네릭 메서드 호출 시 `MissingMethodException` 또는 `TypeLoadException` 발생 | HybridCLR 모드에서 `AOTGenericReferences.PatchedAOTAssemblyList`의 AOT DLL이 로드되지 않음 | `ENABLE_GAME_FRAME_X_HYBRID_CLR` 매크로 활성화 여부 확인, `AOTGenericReferences`가 생성되어 패키지와 함께 배포되는지 확인 |
| Editor에서 `Unity.Hotfix` 어셈블리를 찾을 수 없음 | `StartHotfixInternalAsync`가 Editor에서는 `Utility.Assembly.GetAssemblies()`를 순회하며, 대소문자 구분에 따라 일치하지 않음 | `StartupOptions.HotfixAssemblyName`에 정확한 이름을 명시적으로 전달하거나, 어셈블리 이름 `Unity.Hotfix`가 DLL과 일치하는지 확인 |
| `StartHotfix()`에서 예외 발생 시 오류 콜백이 없음 | `StartHotfix`는 `async void`이므로 예외는 로그에만 기록됨 | `StartHotfixAsync(options)`를 사용하여 `HotfixLaunchResult`를 받고, `Succeed` / `Fail` 필드 확인 |
