# How to Handle Unity IL2CPP Managed Code Stripping

After enabling IL2CPP + Managed Code Stripping, `GameFrameX.LitJSON` protects its own types from being stripped through three complementary layers. This page explains how these mechanisms work together, and how to add protection when encountering `MissingMethodException` / `TypeLoadException` caused by stripping.

## Prerequisites

- Unity 2019.4 or higher (see [package.json](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/package.json#L5))
- `com.gameframex.unity.litjson` installed via Scoped Registry or Git URL (see README for details)
- Project uses the IL2CPP backend (enabled by default on release platforms such as Android/iOS)

## Steps

### 1. Confirm that stripping protection is enabled by default

The package includes three layers of protection built-in. **Most projects require no additional configuration**:

| Mechanism | Purpose | Source |
|------|------|------|
| `link.xml` | Declaratively retains all types within the namespace | Package-level filter file |
| `LitJsonCroppingHelper` | Touches critical types via `typeof()` at startup | `Runtime/LitJsonCroppingHelper.cs` |
| `[Preserve]` attribute | Marks reflection-sensitive constructors, property getters, and exporters | Various Runtime classes |

As long as an instance of `LitJsonCroppingHelper` is active in the scene, the third layer of protection will take effect in `Start()`.

### 2. Attach `LitJsonCroppingHelper` to the scene

Open any **first scene** (Bootstrap / Loading scene), create an empty GameObject and add the component `LitJson Cropping Helper`:

```csharp
// Actual implementation of Start() in Runtime/LitJsonCroppingHelper.cs
[Preserve]
public void Start()
{
    _ = typeof(ArrayMetadata);
    _ = typeof(Condition);
    _ = typeof(ExporterFunc);
    _ = typeof(ExporterFunc<>);
    _ = typeof(JsonIgnoreAttribute);
    _ = typeof(JsonPropertyAttribute);
    _ = typeof(FsmContext);
    _ = typeof(IJsonWrapper);
    _ = typeof(ImporterFunc);
    _ = typeof(ImporterFunc<,>);
    _ = typeof(JsonData);
    _ = typeof(JsonException);
    _ = typeof(JsonMapper);
    _ = typeof(JsonMockWrapper);
    _ = typeof(JsonReader);
    _ = typeof(JsonToken);
    _ = typeof(JsonType);
    _ = typeof(JsonWriter);
    _ = typeof(Lexer);
    _ = typeof(ObjectMetadata);
    _ = typeof(OrderedDictionaryEnumerator);
    _ = typeof(ParserToken);
    _ = typeof(PropertyMetadata);
    _ = typeof(UnityTypeBindings);
    _ = typeof(WrapperFactory);
    _ = typeof(WriterContext);
}
```

Source: [LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L23-L52)

Each `_ = typeof(...)` uses the C# 7.0 discard syntax, with the purpose of letting the IL2CPP linker consider these types "used" and therefore retain them.

### 3. Annotate your own reflection classes with `[Preserve]` (Optional)

When LitJson reads and writes custom POCOs through reflection, if a type has never been explicitly `new`'d in code, it may still be stripped. Simply add `[Preserve]` to your data class:

```csharp
using UnityEngine.Scripting;

[Preserve]
public class PlayerData
{
    public string Name;
    public int Level;
    public Vector3 Position;
}
```

### 4. Trigger an IL2CPP build and verify the binary

1. File → Build Settings → Switch platform to iOS or Android
2. Player Settings → Other Settings → Scripting Backend = `IL2CPP`, keep Managed Stripping Level at the default `High` or explicitly set to `Low`/`Medium` to retest
3. Build And Run
4. Run a deserialization on the device/emulator (such as `JsonMapper.ToObject<PlayerData>(text)`) and confirm there are no exceptions

## Common Variations

- **Code hot-update scenarios**: If using HybridCLR / ILRuntime, you need to place an additional link.xml in the host project for the hot-update DLL as well, otherwise LitJson types referenced by the hot-update code may still be stripped.
- **Addressables remote assets**: `AssemblyDefinition` loaded remotely at runtime is not constrained by the main project's link.xml; you need to place another one next to the remote assembly's own asmdef.
- **Not using `LitJsonCroppingHelper`**: You can manually write a link.xml to replace the third layer of protection (see the next section).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Runtime `MissingMethodException: void LitJson.JsonMapper::.cctor()` | `JsonMapper`'s cctor was stripped | Confirm that `LitJsonCroppingHelper` is attached to the scene and active |
| `TypeLoadException: Could not load type LitJson.Lexer` | `Lexer` type was stripped | Same as above, or add `[Preserve]` to your own data class |
| Still errors after applying `[Preserve]` | Using source-only `link.xml` but ignored by managed stripping | Place link.xml in the `Assets/` root directory or package root directory, not in a sub-layer such as `Assets/Plugins/` |
| iOS build does not trigger `Start()` | `LitJsonCroppingHelper` component is attached to an unloaded sub-scene | Attach it directly to the first scene, or call it manually in a custom `RuntimeInitializeOnLoadMethod` |

## Background (Optional)

LitJson makes extensive use of reflection (`JsonMapper.ToObject<T>` reads fields and writes setters via reflection). IL2CPP static analysis can only identify directly called code; reflection call chains cannot be traced, so types that have not been `new`'d will be stripped. The package adopts **triple protection**: link.xml as a whitelist, runtime `typeof` touch via `LitJsonCroppingHelper`, and `[Preserve]` annotation on reflection entry points—if any one layer fails, the other two still provide a safety net.

For the overall usage of LitJson, see [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md).
