# How to Use High-Performance Hashes Such as MurmurHash3/xxHash

`GameFrameX.Foundation.Hash` provides out-of-the-box APIs for two non-cryptographic high-performance hash algorithms, MurmurHash3 and xxHash. By directly calling static methods, you can compute 32/64/128-bit hash values for strings, byte arrays, and Types. They are commonly used in non-security scenarios such as hash table keys, bloom filters, and load-balancing sharding.

## Prerequisites

- The project's target framework must be .NET (the code uses BCL APIs such as `uint`/`ulong`/`ArgumentNullException.ThrowIfNull`).
- The project references the `GameFrameX.Foundation.Hash` assembly; the xxHash implementation depends on the NuGet package `Standart.Hash.xxHash`.

## Steps

### 1. Compute the MurmurHash3 of a String/Byte Array

`MurmurHash3Helper` provides two overloads, with a default seed of `27`:

```csharp
using GameFrameX.Foundation.Hash;

// String version: hashes after UTF-8 encoding; seed can be omitted (defaults to 27)
uint hash1 = MurmurHash3Helper.Hash("hello");
uint hash2 = MurmurHash3Helper.Hash("hello", seed: 1234u);

// Byte array version: explicitly specify length and seed
byte[] data = System.Text.Encoding.UTF8.GetBytes("hello");
uint hash3 = MurmurHash3Helper.Hash(data, (uint)data.Length, seed: 27u);
```

Source: [MurmurHash3Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/MurmurHash3Helper.cs#L62-L68)

### 2. Compute xxHash 32/64/128-bit Hashes

`XxHashHelper` provides `byte[]`, `string`, `Type`, and generic overloads, with return types of `uint`, `ulong`, and `uint128` respectively:

```csharp
using GameFrameX.Foundation.Hash;
using Standart.Hash.xxHash;

// 32-bit
uint h32 = XxHashHelper.Hash32("hello");
uint h32Type = XxHashHelper.Hash32<MyClass>();

// 64-bit
ulong h64 = XxHashHelper.Hash64("hello");

// 128-bit (returns uint128, containing high64 / low64)
uint128 h128 = XxHashHelper.Hash128("hello");
bool zero = XxHashHelper.IsDefault(h128); // returns true when both high64 and low64 are 0
```

> ⚠️ Note the naming: `Hash32(byte[])` returns `ulong` and `Hash32(string)` returns `uint` — these are the SDK's actual signatures, not typos.

Source: [XxHashHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/XxHashHelper.cs#L62-L100)

### 3. Use in Shard Keys / Hash Table Keys

When using user IDs, request IDs, player IDs, etc. as shard or hash table keys, you can feed the string directly without first converting it to bytes:

```csharp
// Select a shard based on the user ID
int shardIndex = (int)(MurmurHash3Helper.Hash(userId) % shardCount);

// Put the 64-bit hash into a hash bucket
ulong bucketKey = XxHashHelper.Hash64($"player:{playerId}");
```

## Common Variants

| Scenario | Recommended API | Return Type |
|------|---------|----------|
| Small data volumes, reproducible seed needed | `MurmurHash3Helper.Hash(str, seed)` | `uint` |
| High throughput, byte arrays, cross-language compatibility | `XxHashHelper.Hash32/64/128(buffer)` | `uint`/`ulong`/`uint128` |
| Stable hashing of type metadata (dispatch tables) | `XxHashHelper.Hash64<T>()` | `ulong` |
| Partial-length hashing (streaming/sharded data) | `XxHashHelper.Hash128(buffer, length)` | `uint128` |

## Common Mistakes

- **Using MurmurHash3 as a cryptographic hash**: MurmurHash3 is a non-cryptographic hash and cannot resist collision/pre-image attacks. Do not use it for passwords, tokens, or signatures.
- **Ignoring seed consistency**: The same data hashed with different `seed` values yields completely different results; if upstream and downstream need to agree, you must use the same seed (default `27`).
- **Confusing the return types of `Hash32(byte[])` and `Hash32(string)`**: The former returns `ulong` and the latter returns `uint` — this is a real difference in the SDK's signatures.
- **Passing `null`**: All overloads throw `ArgumentNullException`; use `??` as a fallback or validate in advance.
- **Using MD5/SHA-1 in security scenarios**: In the `HashAlgorithmKind` enum, `Md5` and `Sha1` are only suitable for compatibility and non-security verification; use `PasswordHashHelper` for password scenarios.

## Background (Optional)

MurmurHash3 is implemented in pure managed code in this SDK; its core is a 4-byte block loop + tail merging + final `Fmix32` avalanche mixing, and its typical applications are hash table keys and cache sharding. xxHash invokes a native implementation via the NuGet package `Standart.Hash.xxHash`, and its 32/64-bit throughput is significantly higher than the MD5/SHA family on most hardware; neither is a cryptographic algorithm, so any "tamper-proofing" use requires SHA-2/3 or HMAC.
