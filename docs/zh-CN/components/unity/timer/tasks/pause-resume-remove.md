# 暂停、恢复与移除定时器

对已经创建的定时器，`TimerManager` 提供按 ID 的 `Pause` / `Resume` / `Remove`、按标签的 `PauseByTag` / `ResumeByTag` / `RemoveByTag`，以及配套查询（`IsPaused`、`Exists`、`HasTag`、`GetRemaining` 等）。全部 API 定义在 `ITimerManager` 接口上，直接在拿到的 `ITimerManager` 实例上调用即可。

## 前置条件

- 项目已接入 GameFrameX Timer 组件，并持有 `ITimerManager` 实例（组件入口见 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs)）。
- 已通过 `Add` / `AddOnce` / `AddUpdate` 创建定时器，并保存了返回的 `int` 类型定时器 ID；或创建时指定了 `tag` 标签。

## 操作步骤

### 1. 暂停与恢复单个定时器

```csharp
ITimerManager timer; // 由 GameFrameX 组件获取

// interval=1 秒，repeat=0 表示无限重复
int id = timer.Add(1f, 0, obj => { /* 周期逻辑 */ });

timer.Pause(id);              // 暂停期间不累积时间
bool paused = timer.IsPaused(id);  // true

timer.Resume(id);             // 从暂停处继续累积时间，已积累的时间不丢失
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L74-L91)

### 2. 移除单个定时器

```csharp
timer.Remove(id);                        // 按 ID 移除
timer.Remove(new Action<object>(OnTick)); // 按回调移除

bool alive = timer.Exists(id);           // 移除后返回 false
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L48-L72)

`Remove(int id)` 内部先把 ID 映射到回调，再执行与 `Remove(Action<object>)` 相同的移除路径，因此两种移除方式效果一致：

```csharp
public void Remove(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return;
        }

        Remove(callback);
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L376-L387)

### 3. 按标签批量暂停、恢复与移除

创建定时器时传入 `tag`，之后可以整组操作，适合"场景切换时暂停战斗相关定时器"这类需求：

```csharp
int id = timer.Add(5f, 0, obj => { /* ... */ }, null, "battle");

timer.PauseByTag("battle");   // 暂停该标签下所有定时器
timer.ResumeByTag("battle");  // 恢复该标签下所有定时器
timer.RemoveByTag("battle");  // 移除该标签下所有定时器

bool anyLeft = timer.HasTag("battle"); // 标签下还有活跃定时器时为 true
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L93-L118)

`RemoveByTag` 内部会复制标签下的 ID 列表后逐个调用 `Remove(id)`，避免迭代中被修改：

```csharp
public void RemoveByTag(string tag)
{
    lock (Locker)
    {
        if (_tags.TryGetValue(tag, out var ids))
        {
            // Copy to avoid modification during iteration
            var idsCopy = new List<int>(ids);
            foreach (var id in idsCopy)
            {
                Remove(id);
            }
        }
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)

### 4. 验证状态

| API | 返回值 | 说明 |
|------|--------|------|
| `IsPaused(int id)` | `bool` | 暂停中返回 `true`；ID 不存在返回 `false` |
| `Exists(int id)` / `Exists(Action<object> callback)` | `bool` | 定时器存在且未删除返回 `true` |
| `HasTag(string tag)` | `bool` | 标签下至少存在一个定时器返回 `true` |
| `GetRemaining(int id)` | `float` | 剩余秒数；ID 不存在或尚未生效返回 `-1`；`interval <= 0` 或无限循环返回 `0` |
| `GetElapsed(int id)` | `float` | 已累积秒数；ID 不存在返回 `-1` |
| `GetRepeatLeft(int id)` | `int` | 剩余重复次数（`0` 表示无限）；ID 不存在返回 `-1` |

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L120-L142)

## 常见错误

- **对不存在或已移除的 ID 调用 `Pause` / `Resume` / `Remove`**：实现内部直接 `return`，不会抛异常，但也不会有任何效果；操作后用 `Exists(id)` 复核。
- **刚 Add 就立即 `Pause(id)` 可能不生效**：若定时器还停留在待加入队列（`_toAdd`）中，`Pause` 会在设置标志前直接返回，属于 no-op；待其进入活跃列表后再暂停即可。

  ```csharp
  // Timer in _toAdd (pending): also pausable
  if (_toAdd.ContainsKey(callback))
  {
      return;
  }
  ```

  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L404-L413)
- **`GetRemaining(id)` 返回 `-1` 不一定是异常**：ID 不存在、已被移除，或定时器尚未进入活跃列表时都返回 `-1`（见 `GetRemaining` 实现的返回路径）。
- **移除会触发 `onComplete`**：`Add(..., Action onComplete = null)` 的接口注释标明该回调在"定时器完成/移除时"触发，主动 `Remove` 时需预期它会被调用。
- **暂停 ≠ 移除**：暂停的定时器仍保留在管理器条目列表中，只是跳过时间累积，不释放；确定不再使用时应调用 `Remove`。

## 背景

`TimerManager` 内部为每个定时器维护一个条目（`Deleted`、`IsPaused`、`PausedElapsed` 等字段），更新循环中遇到 `IsPaused == true` 的条目会跳过已用时间累积但保留其在 `_items` 中，因此恢复后能从暂停处继续。所有暂停/恢复/移除操作均在 `lock (Locker)` 保护下执行，可在非主线程安全调用。
