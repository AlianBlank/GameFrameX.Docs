# 心跳遺失警示的處理方式

當 `NetworkMissHeartBeatEventArgs` 事件反覆觸發，或 `MissHeartBeatCount` 持續增加時，表示心跳封包未能在間隔時間內送達。本頁面協助您快速判斷遺失是由間隔設定、應用程式焦點狀態還是連線品質所造成，並提供對應的修復方式與驗證方法。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| `NetworkMissHeartBeatEventArgs` 在每個心跳週期都觸發 | `HeartBeatInterval` 設定過小，小於單次往返延遲 | 增加心跳間隔（參見「調整心跳間隔」） |
| 應用程式進入背景／失去焦點後心跳遺失集中出現 | 失去焦點時心跳傳送被暫停，恢復焦點後補送集中發生 | 檢查與焦點相關的心跳設定（參見「未聚焦時的心跳策略」） |
| 心跳遺失次數達到上限後連線被關閉 | 已達到允許的最大遺失次數，通道主動斷線 | 確認遺失次數上限與網路品質 |
| 偶發性遺失會自行恢復，無需重新連線 | 屬於單次網路抖動；`Reset` 會將計數歸零 | 無需處理；只需留意警示頻率 |

## 心跳遺失的回報方式

每次判定發生心跳遺失時，框架會透過事件系統拋出 `NetworkMissHeartBeatEventArgs`，事件 ID 為 `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs`。該事件包含兩個欄位：

```csharp
public sealed class NetworkMissHeartBeatEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(NetworkMissHeartBeatEventArgs).FullName;

    public override string Id
    {
        get { return EventId; }
    }

    /// <summary>取得網路通道。</summary>
    public INetworkChannel NetworkChannel { get; private set; }

    /// <summary>取得遺失的心跳封包數量。</summary>
    public int MissCount { get; private set; }

    public static NetworkMissHeartBeatEventArgs Create(INetworkChannel networkChannel, int missCount)
    {
        NetworkMissHeartBeatEventArgs networkMissHeartBeatEventArgs = ReferencePool.Acquire<NetworkMissHeartBeatEventArgs>();
        networkMissHeartBeatEventArgs.NetworkChannel = networkChannel;
        networkMissHeartBeatEventArgs.MissCount = missCount;
        return networkMissHeartBeatEventArgs;
    }
}
```

來源：[NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L41-L87)

處理此事件時，請使用 `NetworkChannel` 判斷是哪個具名連線發生問題，並使用 `MissCount` 判斷遺失的累積嚴重程度。

## 修復步驟

### 1. 訂閱事件並確認遺失來源

初始化網路元件後，訂閱心跳遺失事件，先取得 `NetworkChannel` 與 `MissCount`，再決定後續處理方式：

```csharp
// 訂閱心跳遺失事件（事件 Id 為 NetworkMissHeartBeatEventArgs.EventId）
GameEntry.Event.AddListener(NetworkMissHeartBeatEventArgs.EventId, OnMissHeartBeat);

private void OnMissHeartBeat(object sender, GameEventArgs e)
{
    var args = (NetworkMissHeartBeatEventArgs)e;
    UnityEngine.Debug.LogWarning($"[Network] {args.NetworkChannel.Name} heartbeat lost, {args.MissCount} losses cumulative");
}
```

> 注意：事件物件來自 `ReferencePool`。分派完成後，框架會呼叫 `Clear()` 重設 `NetworkChannel` 與 `MissCount`，因此務必在回呼內讀取數值，切勿快取事件物件。

### 2. 調整心跳間隔

心跳由通道的主迴圈驅動：每幀呼叫 `ProcessHeartBeat(realElapseSeconds)`，累加 `HeartBeatState.HeartBeatElapseSeconds`，達到間隔時間後即傳送一次心跳。若 `HeartBeatInterval` 小於用戶端到伺服器的往返時間，幾乎每個週期都會被判定為遺失。診斷與修復方式：

1. 記錄用戶端到伺服器的 RTT（可使用 Ping 或在業務層測量）。
2. 將心跳間隔設定為 RTT 的至少 3–5 倍。
3. 請注意 `HeartBeatInterval` 已加入負數值驗證，請勿傳入負數（參見 CHANGELOG 中的「HeartBeatInterval 增加負數值驗證」條目）。

心跳間隔的經過時間與遺失次數皆儲存於 `HeartBeatState`：

```csharp
public sealed class HeartBeatState
{
    private float _heartBeatElapseSeconds;
    private int _missHeartBeatCount;

    /// <summary>心跳間隔時長</summary>
    public float HeartBeatElapseSeconds { get; set; }

    /// <summary>心跳遺失次數</summary>
    public int MissHeartBeatCount { get; set; }

    /// <summary>重設心跳資料 => 保活</summary>
    public void Reset(bool resetHeartBeatElapseSeconds)
    {
        if (resetHeartBeatElapseSeconds)
        {
            _heartBeatElapseSeconds = 0f;
        }

        _missHeartBeatCount = 0;
    }
}
```

來源：[NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L39-L82)

### 3. 排查未聚焦時的心跳策略

本套件的 README 明確支援「心跳封包機制（支援應用程式取得／失去焦點時的傳送設定）」。當行動應用程式進入背景時，Unity 主迴圈可能被節流甚至暫停，導致心跳無法按間隔傳送，回到前景後便會集中回報遺失。排查重點：

| 檢查項目 | 建議做法 |
|--------|----------|
| 未聚焦時是否持續傳送心跳 | 若業務允許，未聚焦時暫停傳送，重新取得焦點後先呼叫 `HeartBeatState.Reset(true)` 將計數歸零再恢復 |
| 重新取得焦點後的計數 | 恢復傳送前先重設，避免舊計數直接觸發關閉邏輯 |
| 與伺服器的約定 | 伺服器對未聚焦的用戶端放寬心跳逾時臨界值 |

> CHANGELOG 中已包含兩項修復：「修復應用程式取得焦點時心跳封包的預設行為」與「將 ProcessHeartBeat 中的 Close 呼叫移至鎖外，避免巢狀鎖死結的風險」。若您在舊版本中遇到失去焦點後的誤判遺失或心跳處理卡死，請先升級至較新版本。

### 4. 排查通道關閉邏輯

心跳處理位於通道的主迴圈中，每幀依序執行 `ProcessHeartBeat(realElapseSeconds)` 與 `ProcessReceivedMessage()`。當累積遺失達到上限時會關閉通道；若您使用的版本中此關閉邏輯會卡死，請升級至已將 `Close` 呼叫移出鎖外的版本。升級後，再次觀察心跳遺失後是否仍會卡死。

## 驗證

- 在事件回呼中列印 `MissCount`：正常網路條件下應長期維持為 0；偶爾 +1 後被 `Reset` 歸零屬於正常抖動。
- 暫時將心跳間隔設為 1 秒並在弱網路環境下測試，確認警示頻率隨間隔增加而顯著下降。
- 切換至背景 30 秒後返回前景，確認沒有集中出現的警示且連線仍可使用（必要時透過 `Reset` 將計數歸零）。
- 觀察連線日誌：心跳遺失達到上限時，應觸發通道關閉與斷線事件，而非卡死或無止盡的警示。
