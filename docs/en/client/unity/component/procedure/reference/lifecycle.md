# Lifecycle Callbacks

`ProcedureBase` inherits from `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`. Per the finite state machine (FSM) convention, each procedure triggers a virtual method at the creation, enter, poll, leave, and destroy stages. These are the procedure's **lifecycle callbacks**. Subclasses can override them to hook in business logic.

## Callback Quick Reference

| Callback | Signature | Trigger Timing |
|------|------|----------|
| `OnInit` | `protected override void OnInit(IFsm<IProcedureManager> procedureOwner)` | When the state machine initializes (once per procedure instance) |
| `OnEnter` | `protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)` | When switching to this procedure |
| `OnUpdate` | `protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | Polled every frame (logical elapsed / real elapsed) |
| `OnFixedUpdate` | `protected override void OnFixedUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | Polled at fixed step |
| `OnLeave` | `protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)` | When leaving this procedure; `isShutdown=true` indicates the leave is triggered by state machine shutdown |
| `OnDestroy` | `protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)` | When the state machine is destroyed (once per procedure instance) |

All methods' default implementations are simply `base.Xxx(...)`, which can be overridden but **should retain the `base` call** to preserve base class behavior.

## Parameter Description

| Parameter | Meaning |
|------|------|
| `procedureOwner` | The state machine object holding this procedure, of type `IFsm<IProcedureManager>`. Through it, you can access the procedure manager (`procedureOwner.Owner`), switch procedures, etc. |
| `elapseSeconds` | Logical elapsed time (seconds) affected by time scale. |
| `realElapseSeconds` | Real elapsed time (seconds) unaffected by time scale. |
| `isShutdown` | When `true` in `OnLeave`, it indicates that this leave is caused by the state machine being shut down, rather than a normal switch. |

## Trigger Timing (Corresponding to Manager API)

| Manager Operation | Triggered Callback (on that procedure instance) |
|------------|----------------------------|
| `Initialize(fsmManager, procedures...)` | Each passed-in procedure calls `OnInit` in sequence |
| `StartProcedure<T>()` / `StartProcedure(Type)` | Target procedure calls `OnEnter`; if there is a current procedure, it calls `OnLeave(isShutdown=false)` first on the old procedure |
| State machine heartbeat (every frame) | Current procedure calls `OnUpdate` and `OnFixedUpdate` |
| `DestroyProcedures()` | Current procedure calls `OnLeave(isShutdown=true)`, then all registered procedures call `OnDestroy` in sequence |
| `ReinitializeProcedures(procedures...)` | Equivalent to first calling `DestroyProcedures()`, then re-`Initialize` with the new procedure array |

## Minimal Usage

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

public class MyProcedure : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // Initialize resources, caches, etc. required by this procedure
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // Launch UI, register events, etc. when entering this procedure
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner,
        float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        // Per-frame business logic (switch procedures via procedureOwner when conditions are met)
    }

    protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)
    {
        base.OnLeave(procedureOwner, isShutdown);
        // Clean up UI, unregister events
        // isShutdown == true indicates the state machine is being shut down as a whole
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // Release resources held by this procedure
    }
}
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| After overriding, forgetting `base.OnXxx(...)`, causing abnormal state machine internal state | The base class may maintain implicit behaviors such as state statistics and timers | Always call `base.OnXxx(...)` at the end of overrides |
| Calling `StartProcedure` to switch procedures inside `OnInit` | During the `Initialize` phase, the procedure has not yet called `OnEnter`; switching early will leave the state machine in an inconsistent state | Switch in `OnEnter` or a subsequent `OnUpdate` instead |
| Accessing other procedures on `procedureOwner` inside `OnDestroy` | The state machine's internal state is being reclaimed during the destroy phase | Cache cross-procedure references in `OnEnter`, and clean them up in `OnLeave` |
| Using `OnUpdate` for one-time initialization | `OnUpdate` is called every frame and will be triggered repeatedly | Place one-time logic in `OnInit` or `OnEnter` |
| Expecting `OnEnter` to be called on every `Initialize` | `OnInit` is the only one called during initialization; `OnEnter` is only called on state switches | Put startup logic in `OnEnter`, data preparation in `OnInit` |

## Verification Method

The repository provides unit tests covering lifecycle behavior. Assertions can be viewed in `Tests/UnitTests.cs`, for example:

```csharp
Assert.IsTrue(main.OnInitCalled, "OnInit should be called during Initialize");
Assert.IsTrue(main.OnEnterCalled, "OnEnter should be called during StartProcedure");
Assert.IsTrue(main.OnDestroyCalled, "OnDestroy should be called during Shutdown");
```
