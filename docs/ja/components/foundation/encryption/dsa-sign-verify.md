# DSA 署名検証の使い方

`DsaHelper` は DSA デジタル署名アルゴリズムの署名と検証機能を提供します。SHA256 をハッシュアルゴリズムとして使用し、鍵は XML 文字列形式で保存されます。このページでは、鍵ペアの生成、単一の文字列の署名検証から、`DsaHelper` インスタンスの再利用までの一連の手順を説明します。

## 前提条件

- プロジェクトが `GameFrameX.Foundation.Encryption` パッケージを参照していること。
- ターゲットフレームワークが .NET であること(`System.Security.Cryptography.DSA` をサポート)。`DsaHelper` は内部で `DSA.Create()` を使用しており、Windows / Linux / macOS のいずれでも動作します。
- 名前空間 `using GameFrameX.Foundation.Encryption;` を使用すること。

## 操作手順

### 1. DSA 鍵ペアの生成

`DsaHelper.Make()` を呼び出すと、秘密鍵と公開鍵の XML 文字列が一度に取得できます。キー名 `privatekey`、`publickey` でそれぞれ取り出します:

```csharp
using GameFrameX.Foundation.Encryption;

var keys = DsaHelper.Make();
string privateKey = keys["privatekey"]; // XML 秘密鍵
string publicKey  = keys["publickey"];  // XML 公開鍵
```

Source: [DsaHelper.cs#L127-L140](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L127-L140)

### 2. 文字列データの署名(静的メソッド)

署名対象の文字列と秘密鍵を `SignData(string, string)` に渡すと、Base64 エンコードされた署名値が返されます。秘密鍵の形式が不正な場合は `CryptographicException` がスローされ、`"Invalid DSA private key."` と表示されます。

```csharp
using GameFrameX.Foundation.Encryption;

string data = "hello world";
string signature = DsaHelper.SignData(data, privateKey); // Base64 文字列を返す
```

署名の実際のフロー:`Encoding.UTF8.GetBytes` → `DSA.SignData(..., HashAlgorithmName.SHA256)` → `Convert.ToBase64String`。

Source: [DsaHelper.cs#L189-L200](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L189-L200)

### 3. 文字列署名の検証(静的メソッド)

原文、Base64 署名、公開鍵を `VerifyData(string, string, string)` に渡します。`true` が返れば署名が有効、公開鍵の形式が不正または署名が無効な場合は `false` が返ります(例外はスローされません):

```csharp
using GameFrameX.Foundation.Encryption;

bool ok = DsaHelper.VerifyData(data, signature, publicKey);
```

内部では `DSA.VerifyData(..., HashAlgorithmName.SHA256)` を呼び出し、`CryptographicException` と `XmlException` をキャッチして `false` を返します。

Source: [DsaHelper.cs#L282-L287](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L282-L287)

### 4. バイト配列の直接署名検証(オプション)

文字列/Base64 のエンコード・デコードを避けたい場合は、`byte[]` のオーバーロードを使用することもできます。署名時に `CryptographicException` または `XmlException` は内部で吸収され `null` が返されるため、独自に処理する必要があります:

```csharp
using GameFrameX.Foundation.Encryption;

byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello world");
byte[] signedBytes = DsaHelper.SignData(payload, privateKey);     // 失敗時は null を返す
bool valid = DsaHelper.VerifyData(payload, signedBytes, publicKey); // 失敗時は false を返す
```

Source: [DsaHelper.cs#L153-L176](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L153-L176), [DsaHelper.cs#L246-L270](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L246-L270)

### 5. `DsaHelper` インスタンスの再利用(オプション)

同一プロセス内で繰り返し署名/検証を行う場合は、`using` を使って `DsaHelper` インスタンスを公開鍵または秘密鍵と共に保持し、毎回 `FromXmlString` を呼び出すオーバーヘッドを回避することをお勧めします。インスタンスメソッドは `_dsa.SignData` / `_dsa.VerifyData` を経由し、例外はそのまま上位にスローされます:

```csharp
using GameFrameX.Foundation.Encryption;

using (var signer = new DsaHelper(privateKey))
{
    string signature = signer.SignData("hello world"); // Base64
}

using (var verifier = new DsaHelper(publicKey))
{
    bool ok = verifier.VerifyData("hello world", signature);
}
```

コンストラクタは 2 種類のオーバーロードをサポートしています:`DSA` インスタンスまたは XML 鍵文字列を渡すことができます。null / 空文字列を渡すとそれぞれ `ArgumentNullException` / `ArgumentException` がスローされ、XML が不正な場合は `CryptographicException` がスローされます。

## よくあるバリエーション

- **インスタンス署名と静的検証の組み合わせ(プロセス間転送シナリオ)**:送信側は `new DsaHelper(privateKey).SignData(原文)` で Base64 署名を取得してメッセージと一緒に送信し、受信側は `DsaHelper.VerifyData(原文, 署名, 公钥)` で検証します。
- **バイトストリームの署名**:データ自体がバイト列(すでにシリアライズされた protobuf など)の場合は、`byte[]` オーバーロードを直接呼び出し、UTF-8 / Base64 のエンコード・デコードをスキップします。
- **鍵が設定ファイルから取得される場合**:`Make()` の出力を XML 文字列として設定センターに保存し、起動時に読み出して、コンストラクタまたは静的メソッドに直接渡します。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `SignData(string, string)` が `CryptographicException: Invalid DSA private key.` をスロー | 秘密鍵文字列が有効な DSA XML ではない、または公開鍵が誤って秘密鍵として渡されている | `Make()["privatekey"]` が渡されていることを確認する。XML が破損している場合は再生成する |
| `SignData(byte[], string)` が `null` を返す | 秘密鍵の形式が不正(`CryptographicException` または `XmlException` が内部で吸収されている) | 鍵の XML を確認する。文字列オーバーロードを使用すれば明確な例外情報が取得できる |
| `VerifyData` が常に `false` を返す | 公開鍵/原文/署名のいずれかが一致しない(エンコード、切り詰め、異なる鍵ペアの使用) | 原文が一貫して UTF-8 でエンコードされていること、署名が二重に Base64 されていないこと、署名と検証の両者が対応する鍵ペアを使用していることを確認する |
| `new DsaHelper(null)` が `ArgumentNullException` をスロー | null の `DSA` インスタンスまたは鍵文字列が渡された | 構築前に入力値を検証する。XML 鍵は `ArgumentException.ThrowIfNullOrEmpty` を通してから渡す |
| macOS で 2048 ビット鍵を指定すると失敗する | プラットフォームの DSA 実装がデフォルト以外の鍵サイズのサポートが限定的 | `DsaHelper.Make()` で生成されたデフォルトサイズの鍵ペアを直接使用する |

## 背景(オプション)

`DsaHelper` は内部で非推奨となった `DSACryptoServiceProvider` の代わりに `DSA.Create()` を統一的に使用し、署名ハッシュは明示的に `HashAlgorithmName.SHA256` を指定することで、DSA デフォルトの SHA-1 の弱点を回避しています。クラスは `IDisposable` を実装しているため、長時間インスタンスを保持する場合は必ず `using` で基盤となるアンマネージリソースを解放してください。DSA は署名検証にのみ使用でき、暗号化・復号には使用できません。
