# 快速上手：從零啟動 GameFrameX 伺服器

本頁帶你用最少步驟把 GameFrameX Server 跑起來：準備好 .NET 10 與 MongoDB,選一種啟動方式(Docker / 命令列 / Rider / Visual Studio),看到健康檢查與測試介面回傳正常即視為啟動成功。

## 前置條件

| 相依性 | 版本要求 |
| :--- | :--- |
| [.NET SDK](https://dotnet.microsoft.com/download) | 10.0+ |
| [MongoDB](https://www.mongodb.com/try/download/community) | 4.x+ |
| IDE(可選) | Visual Studio 2022 / JetBrains Rider / VS Code |
| Docker(可選) | 用於一鍵啟動或本機拉起 MongoDB |

原始碼根目錄見 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L1-L150)。

## 操作步驟

### 方式 1:Docker 一鍵啟動

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
docker compose up -d --build
```

適合不想在本機安裝 .NET 10 SDK 的使用者；Compose 會同時拉起 MongoDB 與伺服器容器。

### 方式 2:命令列本機啟動

1. 單獨啟動 MongoDB:

```bash
docker compose up -d mongodb
```

2. 編譯並從輸出目錄啟動 Launcher:

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
dotnet restore
dotnet build Server.sln
cd bin/app_debug
dotnet GameFrameX.Launcher.dll
```

`GameFrameX.Launcher.dll` 是框架的入口組件，對應專案檔見 [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L1-L41)。其中 `Debug` 設定的 `OutputPath` 為 `bin\app_debug`,`Release` 為 `bin\app`。

### 方式 3:JetBrains Rider 偵錯

1. 開啟 `Server.slnx`;如果 Rider 版本不支援 `.slnx`,再開啟 `Server.sln`。
2. 啟動 MongoDB:`docker compose up -d mongodb`。
3. 為 `GameFrameX.Launcher` 建立或編輯 `.NET Project` 執行設定。
4. `Working directory` 設定為 `$SolutionDir$/bin/app_debug`。
5. `Program arguments` 留空(預設設定見 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs))。
6. 點擊 Debug。如果 `bin/app_debug` 不存在，先執行一次 `dotnet build Server.sln`。

### 方式 4:Visual Studio 偵錯

1. 開啟 `Server.slnx`;如果 Visual Studio 版本不支援 `.slnx`,再開啟 `Server.sln`。
2. 將 `GameFrameX.Launcher` 設為啟動專案。
3. 啟動 MongoDB:`docker compose up -d mongodb`。
4. `Working directory` 設定為方案目錄下的 `bin\app_debug`。
5. `Command line arguments` 留空。
6. 按 F5 啟動偵錯。首次偵錯前若輸出目錄不存在，先 Build Solution。

## 常見變體

需要覆蓋預設設定(連接埠、資料庫連線等)時，在命令列附加啟動參數：

```bash
dotnet GameFrameX.Launcher.dll \
    --ServerId=1000 \
    --ServerType=Game \
    --IsEnableTcp=true \
    --InnerPort=29100 \
    --MetricsPort=29090 \
    --IsEnableHttp=true \
    --HttpPort=28080 \
    --IsEnableWebSocket=true \
    --WsPort=29110 \
    --HttpIsDevelopment=true \
    --MinModuleId=10 \
    --MaxModuleId=9999 \
    --TagName=GameFrameX \
    --DataBaseUrl="mongodb://localhost:27017" \
    --DataBaseName=gameframex
```

| 參數 | 含義 |
| :--- | :--- |
| `--ServerId` `--ServerType` | 伺服器唯一編號與類型(如 Game) |
| `--IsEnableTcp` `--InnerPort` | TCP 內網連接埠開關 |
| `--IsEnableHttp` `--HttpPort` `--HttpIsDevelopment` | HTTP 監聽與是否開發模式 |
| `--IsEnableWebSocket` `--WsPort` | WebSocket 監聽開關 |
| `--MetricsPort` | Prometheus 指標與健康檢查連接埠 |
| `--MinModuleId` `--MaxModuleId` | 業務模組 ID 區間 |
| `--TagName` | 啟動標籤，用於路由到 `AppStartUpGame` 等啟動器 |
| `--DataBaseUrl` `--DataBaseName` | MongoDB 連線字串與資料庫名稱 |

本機偵錯時**保持參數留空**即可，預設值在 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs` 中。

## 驗證部署

啟動成功後，透過下列端點確認服務正常：

| 端點 | 位址 | 說明 |
| :--- | :--- | :--- |
| 健康檢查 | `http://localhost:29090/health` | 服務健康狀態 |
| 指標監控 | `http://localhost:29090/metrics` | Prometheus 指標 |
| 測試介面 | `http://localhost:28080/game/api/test` | HTTP 連通性測試 |

三項中任意一項回傳正常即表示框架已正確拉起。

## 常見錯誤

| 症狀 | 原因 | 修復 |
| :--- | :--- | :--- |
| 啟動時回報 MongoDB 連線失敗 | 未啟動 MongoDB 或連線字串與資料庫名稱有誤 | 先 `docker compose up -d mongodb`,或調整 `--DataBaseUrl` `--DataBaseName` |
| Rider / VS 偵錯找不到 `bin/app_debug` | 首次建置未執行 | 先 `dotnet build Server.sln`,再啟動偵錯 |
| `Server.slnx` 無法開啟 | IDE 版本過舊 | 改用 `Server.sln` |
| 連接埠被佔用 | 預設 28080 / 29090 / 29100 / 29110 已被佔用 | 參照「常見變體」小節傳參覆蓋 |
| HTTP 測試介面 404 | 框架未啟用 HTTP 或連接埠設定衝突 | 確認 `--IsEnableHttp=true --HttpPort=28080` 與啟動器一致 |

## 背景(可選)

GameFrameX Server 採用 Actor 模型與狀態/邏輯分離：持久化資料在 `GameFrameX.Apps`,業務邏輯在 `GameFrameX.Hotfix`,可在不停機的情況下熱替換。啟動器 `AppStartUpGame` 透過 `[StartUpTag(GameServerConst.Game.Name)]` 與 `--TagName` 參數匹配，完成網路協定、元件代理與設定表的裝配。原始碼組織詳見 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L180-L260)。
