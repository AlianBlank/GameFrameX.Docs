# カスタム追加コンテンツの保存方法

`GlobalConfigComponent.Content` フィールドを使用することで、Inspector または実行時にカスタム追加コンテンツ文字列を永続化し、いつでも読み取りや変更を行うことができます。

## 前提条件

- `GlobalConfigComponent` をシーンに配置していること(メニュー `GameFrameX/Global Config` から追加可能)。

## 操作手順

1. Inspector の `附加内容` テキストボックスに文字列を直接入力します(複数行対応、デフォルトの高さ 120)。このフィールドはシーンにシリアライズされ、実行時には `Content` プロパティで読み取ります。

```csharp
// Runtime/GlobalConfig/GlobalConfigComponent.cs
[SerializeField] private string m_content = string.Empty;

public string Content
{
    get => m_content;
    set => m_content = value;
}
```

Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L81-L93)

2. 実行時にコードで設定または読み取ります:

```csharp
var component = UnityEngine.Object.FindObjectOfType<GameFrameX.GlobalConfig.Runtime.GlobalConfigComponent>();

// 追加コンテンツの設定
component.Content = "{\"key\":\"value\"}";

// 追加コンテンツの読み取り
string data = component.Content;
```

3. Inspector でこのフィールドを可視化する必要がある場合は、カスタムインスペクターが `m_content` を描画していることを確認してください:

```csharp
// Editor/Inspector/GlobalConfigComponentInspector.cs
m_Content = serializedObject.FindProperty("m_content");
...
EditorGUILayout.PropertyField(m_Content, m_ContentGUIContent, GUILayout.Height(120));
```

Source: [GlobalConfigComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Editor/Inspector/GlobalConfigComponentInspector.cs#L19-L38)

4. 追加コンテンツがサーバー応答から取得される場合、`ResponseGlobalInfo.Content` フィールドを介して受け渡し、その後コンポーネントに書き込むことができます:

```csharp
// Runtime/GlobalConfig/ResponseGlobalInfo.cs
public class ResponseGlobalInfo
{
    public string Content { get; set; }
}
```

Source: [ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L24-L26)

## よくあるバリエーション

- **JSON 文字列の保存**:`Content` を JSON コンテナとして使用し、自分で `JsonUtility.FromJson<T>` でデシリアライズします。
- **AOT アセンブリリストの保存**:追加コンテンツと同様に、`AOTCodeList`(文字列)または `AOTCodeLists`(`List<string>`)フィールドを使用します。後者は setter で自動的に解析されます。
- **サーバーからの書き込み**:`SetOriginalData(string)` で生の文字列を書き込みます。`null` を渡すと `ArgumentNullException` がスローされます。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `Content = null` 設定後に NullReferenceException が発生 | フィールド型が `string` で、null チェックがない | 書き込み前に非空であることを確認するか、自分で null のフォールバック処理を行う |
| `AOTCodeList` の解析失敗 | JSON 形式が正しくない | catch ブロックで `Log.Error(e)` の出力を確認し、JSON を修正する |
| 実行時に `Content` を変更しても反映されない | 再生モードでフィールドが無効化されている | エディタの再生中はフィールドが読み取り専用になるため、再生モードを終了してから変更する |

## 背景(オプション)

`Content` と `OriginalData` は独立した 2 つのチャネルです。`Content` は業務用のカスタム追加コンテンツ(Inspector で編集可能)に使用し、`OriginalData` はサーバーの生データ(コードでのみ書き込み可能)です。両方とも文字列であり、シリアライズ形式は呼び出し側で自由に決めることができます。
