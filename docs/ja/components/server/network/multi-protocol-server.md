# TCP / WebSocket / HTTP マルチプロトコル監視の有効化

GameFrameX.Server の起動エントリで必要に応じて TCP、WebSocket、HTTP の 3 種類のネットワーク監視を有効化し、同じ業務コードで異なるプロトコルエンドポイントを同時に提供します。これはマルチエンド融合(ネイティブ TCP、Web/H5、ミニプログラム、外部 HTTP API)によく使用されます。

## 前提条件

- [GameFrameX.Server](https://github.com/GameFrameX/GameFrameX.Server) のローカルビルドと基本設定が完了していること。
- 外部公開ポートが占有されておらず、対応する TCP ポートのファイアウォールが許可されていること(フレームワークのデフォルト監視ポートは以下の表を参照)。
- `GameFrameX.StartUp` 名前空間下の `AppStartUpGame` などの起動クラスの呼び出し順序を理解していること。

## 操作手順

1. 起動エントリファイル `GameFrameX.Launcher/StartUp/AppStartUpGame.cs` を開きます。フレームワークのプロトコル登録と起動フローはここに集約されています。

2. 業務ニーズに応じて、`AppStartUpGame` 内で `UseServer` または対応する拡張メソッドを呼び出し、同時に `tcpOptions`、`wsOptions`、`httpOptions` の 3 つの設定ノードを渡します。いずれかのノードが省略された場合、対応するプロトコルは無効になります。

3. 設定ファイル(デフォルトでは `App.Config.json` または環境変数による上書き)に以下の構造を記述します。フレームワークは起動時に自動的に `Enable*` スイッチに従って対応するプロトコルを監視するかどうかを判断します:

```json
{
  "Server": {
    "Tcp":    { "Enable": true,  "Host": "0.0.0.0", "Port": 30100 },
    "WebSocket": { "Enable": true, "Host": "0.0.0.0", "Port": 30101, "Path": "/" },
    "Http":   { "Enable": true,  "Host": "0.0.0.0", "Port": 30102 }
  }
}
```

4. `GameFrameX.Launcher` を起動すると、実行ログに `Tcp Server Started`、`WebSocket Server Started`、`Http Server Started` のようなメッセージが表示され、3 つのリンクが並行して監視されていることを示します。

5. 任意の業務コード内で `INetSession` または `HttpContext` を通じてメッセージを処理します。フレームワークは接続時のポート/パスに応じて自動的に対応するプロトコルチャネルにディスパッチするため、業務層でプロトコルを区別する必要はありません。

```csharp
// メッセージ処理の登録(TCP / WebSocket で共通)
[MessageHandler(MessageId.C2S_Login)]
public class C2S_LoginHandler : IMessageHandler
{
    public async Task HandleAsync(INetSession session, C2S_Login request)
    {
        // 業務ロジック
    }
}
```

## 一般的なバリエーション

- **TCP のみを有効化**:`Tcp.Enable` を `true` に設定し、他の 2 つを `false` に設定します。純粋なゲートウェイサーバーでよく使用されます。
- **WebSocket + HTTP の共存**:H5 ページには WebSocket を使用し、管理バックエンドやコールバック通知には HTTP を使用します。両方で同じプロセスと同一の Actor を共有します。
- **個別プロトコルの停止**:対応するノードの `Enable` を `false` に設定するだけで、コードの変更は不要です。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動時に `Address already in use` が出る | 複数プロトコルで同じポートを使用している、または他のプロセスに占有されている | 各プロトコルで異なる `Port` を使用し、OS ポートが空いていることを確認する |
| WebSocket クライアントが接続後すぐに切断される | `Path` またはサブプロトコルが一致していない | `Path` をクライアント URL と一致させる(例:`ws://host:port/`) |
| HTTP インターフェースが 404 を返す | `Enable*` 設定が注入されていない、またはコントローラーが不足している | `Http.Enable=true` を確認し、コントローラーが登録されていることを確認する |
| TCP は接続できるがメッセージを受信できない | 起動順序の問題で、業務 Actor が登録されていない | `AppStartUpHotfixGameByEntry` などが `AppStartUpGame` から順番に呼び出されていることを確認する |

## 背景(オプション)

`AppStartUpGame` は `GameFrameX.StartUp` が提供する統一エントリを通じてアプリケーションサーバーのプロトコルスタックを初期化し、同一のメッセージルーティングとセッション(`INetSession`)抽象を使用して 3 種類のプロトコルをサポートします。そのため、業務処理層(`Component/ServerComponent.cs` を参照)はメッセージインタラクションのみを対象としており、下層の伝送方式は意識する必要がありません。

全体の起動フローと `ServerComponent` に関する詳細については、《Server コンポーネント》を参照してください。
