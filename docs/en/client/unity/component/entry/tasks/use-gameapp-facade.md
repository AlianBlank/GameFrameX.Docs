# How to Use GameApp to Call Subsystems (Facade Layer Guide)

`GameApp` is a static facade class provided by GameFrameX that consolidates the subsystems scattered across components (Asset, Config, Event, Fsm, UI, Entity, Localization, etc.) into static properties. Business code no longer needs to repeatedly look them up via `GameEntry.GetComponent<T>()`; you can simply call `GameApp.Asset.xxx` directly.

## Prerequisites

- GameFrameX's `GameEntry` is installed and initialized; the framework creates each `Component` according to the `Enable` list at startup.
- For each subsystem you use, make sure the corresponding `ENABLE_GAME_FRAME_X_*` macro is enabled (each `GameApp.*.cs` file wraps the entire partial block in the macro); otherwise, the property will not be compiled in.
- Business code should not hold `Component` references; access them uniformly through `GameApp.xxx`.

## Steps

### 1. Get a subsystem via static properties

Each `GameApp.*.cs` file follows the same pattern: it holds a private static field internally, exposes a read-only static property, and on first access retrieves the corresponding `Component` from `GameEntry` and caches it.

```csharp
// Get the base component
var baseComp = GameApp.Base;

// Get the asset component (requires the ENABLE_GAME_FRAME_X_ASSET macro)
var asset = GameApp.Asset;

// Get the config component (requires the ENABLE_GAME_FRAME_X_CONFIG macro)
var cfg = GameApp.Config;

// Get the event component (requires the ENABLE_GAME_FRAME_X_EVENT macro)
var evt = GameApp.Event;
```

### 2. Call subsystem methods in business code

Once you have the property, simply call the corresponding `Component`'s methods. For example, the following demonstrates loading an asset, reading config, and subscribing to an event, all through `GameApp`:

```csharp
// Load an asset
GameApp.Asset.LoadAsset<GameObject>("Assets/Prefabs/Hero.prefab", prefab =>
{
    // Use the prefab ...
});

// Read config
var heroHp = GameApp.Config.GetInt("Hero_HP", 100);

// Subscribe to an event
GameApp.Event.Subscribe("OnPlayerLevelUp", payload =>
{
    // Handle the level-up event
});
```

> The API names above (LoadAsset / GetInt / Subscribe) come from the common public methods of their respective components; refer to the actual `Component` implementations in [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs), [GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs), and [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) for the exact signatures.

### 3. Trim unneeded subsystems via macro switches

Each subsystem in `GameApp` is wrapped in an `ENABLE_GAME_FRAME_X_<NAME>` compilation macro. If a project doesn't need a certain subsystem, turning off the corresponding macro prevents that property from being compiled in, effectively reducing package size and dependencies.

## Common Mistakes

- **Property not found / compile error that `GameApp` does not contain a definition for `xxx`**: Most likely the corresponding `ENABLE_GAME_FRAME_X_*` macro is not enabled, or the corresponding `GameApp.*.cs` was not compiled into the project. First enable the macro in `Scripting Define Symbols` or the `asmdef`.
- **Accessing properties before `GameEntry` has started**: `GameApp` retrieves components via `GameEntry.GetComponent<T>()`; if framework initialization is not yet complete, you will get `null`, and subsequent calls will throw a null reference. Make sure to access `GameApp.xxx` only after `GameEntry` has finished starting up.
- **Manually `new`-ing a `Component` instead of going through the facade**: `GameApp`'s static fields are a cache, consistent only with instances obtained via `GameEntry.GetComponent<T>()`; instances you `new` yourself will not be retrievable through the facade, resulting in two copies of out-of-sync state.
- **Holding static fields across scenes**: The fields in `GameApp` are currently process-level static caches, designed to be used for the lifetime of the process; do not attempt to reset them manually on scene switches.

## Background (Optional)

`GameApp` consists of multiple `partial class` files (each `Runtime/GameApp.*.cs` implements one subsystem property). It uniformly obtains component instances via lazy loading + `GameEntry.GetComponent<T>()`, preserving the global access capability of singleton components while avoiding boilerplate `GameEntry.GetComponent<T>()` calls scattered throughout the business layer — a typical application of the Facade pattern in this framework.
