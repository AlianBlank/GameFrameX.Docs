# 如何監聽語言變化事件並重新整理介面文字

將新語言賦予 `LocalizationComponent.Language` 時，元件會依序廣播三個語言變化事件；在介面腳本中訂閱其中之一(建議使用 `LocalizationLanguageChangeAfterEventArgs`),即可在回呼中取得新舊語言並重新整理介面文字。

## 前置條件

- 專案已啟用 GameFrameX 的 Localization 與 Event 元件。
- 場景中存在 `LocalizationComponent`:切換語言時會透過它依賴的 `SettingComponent` 將語言設定持久化，並透過 `EventComponent` 發送事件。

## 操作步驟

三個事件都攜帶相同的資料(`Language` 新語言、`OldLanguage` 舊語言)，按需選擇一個訂閱即可：

| 事件參數類別 | 發送順序 | 適用情境 |
|------|------|------|
| `LocalizationLanguageChangeBeforeEventArgs` | 1 | 切換流程中最先收到通知，適合在切換前做記錄/準備 |
| `LocalizationLanguageChangeEventArgs` | 2 | 通用語言變化事件 |
| `LocalizationLanguageChangeAfterEventArgs` | 3 | 切換完成通知，建議在此重新整理介面文字 |

三個事件在 `Language` 賦值器中同步、連續發送：

```csharp
set
{
    if (m_LocalizationManager.Language != value)
    {
        var oldLanguage = m_LocalizationManager.Language;
        m_LocalizationManager.Language = value;
        m_SettingComponent.SetString(nameof(LocalizationComponent) + "." + nameof(Language), value);
        m_SettingComponent.Save();
        var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
        var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
        var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
    }
}
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L155-L171)

### 1. 撰寫事件處理方法

回呼參數直接使用對應的事件參數類別，從中讀取新語言與舊語言：

```csharp
private void OnLanguageChanged(object sender, LocalizationLanguageChangeAfterEventArgs e)
{
    Debug.Log($"語言由 {e.OldLanguage} 切換為 {e.Language}");
    // 在這裡按 e.Language 重新取得文案,重新整理本介面的所有文字控制項
}
```

事件參數類別的 `Language` / `OldLanguage` 定義與 `EventId` 如下，`EventId` 即類型的完整名稱：

```csharp
[Preserve] public static readonly string EventId = typeof(LocalizationLanguageChangeAfterEventArgs).FullName;

[Preserve]
public string Language { get; private set; }   // 目前(新)語言

[Preserve]
public string OldLanguage { get; private set; } // 舊語言
```

Source: [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41-L67)

### 2. 註冊與取消監聽

事件透過 GameFrameX 的 Event 元件發送(`m_EventComponent.Fire(...)`)。使用 `EventId` 常數註冊監聽，並在介面銷毀/停用時取消訂閱，典型寫法：

```csharp
private void OnEnable()
{
    GameEntry.Event.AddListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}

private void OnDisable()
{
    GameEntry.Event.RemoveListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}
```

> 說明:`AddListener` / `RemoveListener` 的確切簽章以 com.gameframex.unity.event 套件為準；本儲存庫的本地化元件只負責用 `EventId`(類型完整名稱，即 `GameFrameX.Localization.Runtime.LocalizationLanguageChangeAfterEventArgs`)發送事件。

### 3. 切換語言觸發事件

為 `Language` 賦予一個與目前不同的語言值即可觸發全部三個事件：

```csharp
GameEntry.GetComponent<LocalizationComponent>().Language = "ChineseSimplified";
```

賦值的同時會自動將語言寫入設定(鍵名 `LocalizationComponent.Language`)並儲存，下次啟動時可讀回。

### 4. 在回呼中重新整理文字

在步驟 1 的回呼中，按 `e.Language`(或元件目前 `Language`)重新載入對應語言的文案並更新各文字控制項；也可以只重新整理與語言相關的控制項，無需重建介面。

## 驗證

- 切換語言後，步驟 1 回呼中的日誌應輸出舊語言與新語言；
- 將語言設定為與目前相同的值時，回呼**不會**被觸發(賦值器有 `!=` 判斷，見上文 Source 第 157 行)。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 切換語言後回呼未執行 | 監聽時使用的 ID 與事件實際 ID 不一致 | 統一使用事件類別自帶的常數 `LocalizationLanguageChangeAfterEventArgs.EventId`,不要手寫字串 |
| 回呼中讀到的語言是 `UnknownLocalization` | 未正確處理事件參數的參考池重複使用 | 回呼內即取即用 `e.Language` / `e.OldLanguage`,不要快取事件參數物件本身 |
| 反覆切換語言後收到重複事件 | 取消訂閱時機不對或重複註冊 | 在 `OnEnable` 註冊、`OnDisable` 取消訂閱，保證成對出現 |
| 設定相同語言後想重新整理文字但沒有反應 | 賦值器對相同值短路，不發送事件 | 需要強制重新整理時，在呼叫處自行觸發重新整理邏輯，或先設定為目標語言以外的值再切回 |

## 背景

三個事件參數類別均繼承 `GameEventArgs`,實例透過 `ReferencePool.Acquire<T>()` 取得(參考池重複使用)，因此不要長期持有事件參數物件。語言變化由 `LocalizationComponent.Language` 的 setter 統一驅動：先更新管理器語言並將設定持久化，再以「Before → Change → After」順序同步發送三個事件，監聽方無需區分時序差異，任選其一即可。
