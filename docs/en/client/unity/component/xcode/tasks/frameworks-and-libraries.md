# Adding and Removing System Frameworks and Libraries

By configuring the `frameworks` and `libs` nodes in the post-build processing configuration file (XcodePostProcessConfig.json), you can automatically add or remove system frameworks (`.framework`) and system libraries (`.tbd`) when the Xcode project is generated, without having to open Xcode and modify it manually.

## Prerequisites

- The Unity project has the com.gameframex.unity.xcode package installed.
- The platform has been switched to iOS (code under `#if UNITY_IOS` will only execute in that case).
- The post-build processing configuration file has been placed in the Unity project (at the same level as nodes such as `capabilities`, `unityFramework`, and `unityMain`).

## Steps

1. Open the post-build processing configuration file and locate the `unityFramework` or `unityMain` node (both have the same structure and correspond to the UnityFramework and Unity-iPhone targets in the Xcode project, respectively).
2. Fill in the `libs` and `frameworks` configuration, where the `"+"` array contains the items to add and the `"-"` array contains the items to remove:

```json
{
  "unityFramework": {
    "libs": { "+": ["libz.tbd"], "-": [] },
    "frameworks": {
      "+": ["WebKit.framework", "UserNotifications.framework"],
      "-": []
    }
  }
}
```

3. Run the iOS build in Unity. After the build finishes, the post-processing logic reads the above configuration and writes it into the generated Xcode project.
4. Open the generated `.xcodeproj` and verify the results in the target's **General → Frameworks and Libraries** (or Build Phases → Link Binary With Libraries).

## Common Variants

| Use Case | Configuration |
|------|----------|
| Link `libz.tbd` only for the UnityFramework target | Add `libz.tbd` to `unityFramework.libs."+"` |
| Add system frameworks to the main App target | Add e.g. `WebKit.framework` to `unityMain.frameworks."+"` |
| Remove frameworks linked by Unity by default | Write the framework name in the corresponding node's `"-"` array, e.g. `["UnityFramework.framework"]` |

## Implementation Entry Points

The writing of frameworks and libraries is handled by two partial files of `PostProcessBuildHelper`:

The `frameworks` node goes through `SetFrameworks`, which directly calls the Unity `PBXProject` API internally:

```csharp
private static void SetFrameworks(PBXProject proj, string targetGuid, Hashtable hashtable)
{
    if (hashtable != null)
    {
        if (hashtable["+"] is ArrayList addList)
        {
            foreach (string framework in addList)
            {
                proj.AddFrameworkToProject(targetGuid, framework, false);
            }
        }

        if (hashtable["-"] is ArrayList removeList)
        {
            foreach (string framework in removeList)
            {
                proj.RemoveFrameworkFromProject(targetGuid, framework);
            }
        }
    }
}
```

Source: [PostProcessBuildHelper.Frameworks.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Frameworks.cs#L15-L35)

The `libs` node goes through `SetLibs`, which mounts items under the `Frameworks/` group using the SDK-relative path `usr/lib/` and then links them:

```csharp
private static void AddLibToProject(PBXProject proj, string targetGuid, string lib)
{
    string fileGuid = proj.AddFile("usr/lib/" + lib, "Frameworks/" + lib, PBXSourceTree.Sdk);
    proj.AddFileToBuild(targetGuid, fileGuid);
}

private static void RemoveLibFromProject(PBXProject proj, string targetGuid, string lib)
{
    string fileGuid = proj.AddFile("usr/lib/" + lib, "Frameworks/" + lib, PBXSourceTree.Sdk);
    proj.RemoveFileFromBuild(targetGuid, fileGuid);
}
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| No changes in the Xcode project after configuration | The configuration was written at the wrong level; `libs`/`frameworks` must be inside `unityFramework` or `unityMain` | Move the node under the corresponding target configuration |
| `.tbd` library not linked, `Undefined symbols` error | The library name is incomplete | System libraries need the `.tbd` suffix, e.g. `libz.tbd` |
| Duplicate framework linking warnings | The same framework appears multiple times in `"+"`, or has already been added by another plugin | Remove duplicates from the `"+"` array; if necessary, write the duplicate items into `"-"` |
| Still not taking effect after adding | The configuration was modified for a different platform, or the build was not re-run | Confirm the iOS platform and rebuild |

## Verification

- Open the generated Xcode project, select the corresponding target, and check that the frameworks and libraries listed in `"+"` appear under **Build Phases → Link Binary With Libraries**.
- System libraries such as `libz.tbd` appear under the project's `Frameworks` group with the path `usr/lib/`.
- The project compiles without `Undefined symbols` linking errors.
