# HMAC-SHA256/HMAC-SHA512 の使用方法

`HmacSha256Helper` または `HmacSha512Helper` の静的メソッドを呼び出すことで、数行のコードでキー付きメッセージ認証コード（Base64 文字列）を取得し、`Verify` 系メソッドを使用して固定時間比較で安全に署名を検証できます。両者とも文字列、バイト配列、ストリーム（同期/非同期）の 3 組のオーバーロードを提供します。

## 前提条件

- プロジェクトのターゲットフレームワークが `System.Security.Cryptography` 内の `HMACSHA256` / `HMACSHA512` をサポートしていること（.NET 6+ では `HMACSHA256.HashData` の使用を推奨）。
- 名前空間 `GameFrameX.Foundation.Hash` を参照する。
- UTF-8 エンコードのキー文字列を用意する（SHA-256 のブロックサイズに合わせて、長さ ≥ 32 バイトを推奨）。

## 操作手順

### 1. 文字列に対して HMAC-SHA256 を計算する

```csharp
using GameFrameX.Foundation.Hash;

string message = "hello world";
string key = "my-secret-key";
string signature = HmacSha256Helper.Hash(message, key);
// signature は Base64 文字列で、長さは 44 文字固定（32 バイト）
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L60-L66)

### 2. バイト配列に対して HMAC-SHA512 を計算する

```csharp
using System.Text;
using GameFrameX.Foundation.Hash;

byte[] message = Encoding.UTF8.GetBytes("payload");
byte[] key = Encoding.UTF8.GetBytes("another-secret-key");
string signature = HmacSha512Helper.Hash(message, key);
// signature は Base64 文字列で、長さは 88 文字固定（64 バイト）
```

Source: [HmacSha512Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha512Helper.cs#L24-L29)

### 3. ストリームに対して非同期で HMAC-SHA256 を計算する

```csharp
using GameFrameX.Foundation.Hash;

using FileStream fs = File.OpenRead("data.bin");
byte[] key = Encoding.UTF8.GetBytes("my-secret-key");
string signature = await HmacSha256Helper.HashAsync(fs, key, cancellationToken);
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L94-L103)

### 4. 固定時間比較を使用して署名を検証する

タイミング攻撃を防ぐため、検証には必ず `Verify` を使用し、`==` で Base64 文字列を直接比較しないでください。

```csharp
using GameFrameX.Foundation.Hash;

bool ok = HmacSha256Helper.Verify("hello world", "my-secret-key", signature);
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L119-L125)

## よくあるバリエーション

| シナリオ | 推奨メソッド |
|------|---------|
| 短いメッセージ（JSON、URL パラメータ） | `Hash(string, string)` |
| 既知のバイトバッファ（プロトコルパケットなど） | `Hash(byte[], byte[])` |
| 大容量ファイルまたはネットワークストリーム | `Hash(Stream, byte[])` 同期；非同期コンテキストでは `HashAsync` |
| API 署名の検証 | 対応する `Verify(...)` 系を使用し、タイミング攻撃を回避する |
| より高いセキュリティが必要な場合 | `HmacSha512Helper` を選択し、出力は 64 バイト |

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| `ArgumentNullException: message` | `null` 文字列が渡された | あらかじめ null チェックを行うか、空文字列をプレースホルダーとして使用する |
| クライアントとサーバーの署名が一致しない | エンコーディングが一致していない（片方が GBK/ASCII を使用） | 全工程で UTF-8 に統一する |
| `Verify` が常に `false` を返す | `==` で Base64 文字列を直接比較し長さの差異がある | `Verify(...)` を使用して固定時間比較を行う |
| パフォーマンスのボトルネック | 大容量ファイルに対して `HMACSHA256` を繰り返しインスタンス化している | キーを再利用し、インスタンスは 1 回だけ作成する |

## 補足（オプション）

- 出力は常に Base64 であり、HTTP ヘッダー、URL、JSON での伝送に適しています。16 進数が必要な場合は、`Convert.FromBase64String` でデコード後に `BitConverter` を使用してください。
- `Verify` は内部的に `HashHelper.FixedTimeEqualsBase64` を使用しており、文字列の等価性直接比較とは異なり、サイドチャネル攻撃のリスクを低減できます。
- `HashData` は .NET 6+ の単発静的 API です。ストリームバージョンは引き続き `ComputeHash(Stream)` と `ComputeHashAsync` をサポートするために `HMACSHA256/512` インスタンスを使用します。
