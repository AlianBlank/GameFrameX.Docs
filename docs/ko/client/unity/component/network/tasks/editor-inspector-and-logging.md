# 네트워크 로그 활성화 및 Inspector 패널 사용

Unity 메뉴 `GameFrameX/Scripting Define Symbols`를 통해 송신/수신 로그 매크로를 활성화하면, 네트워크 컴포넌트가 콘솔에 각 송수신 메시지의 ID, 타입, JSON 내용을 출력합니다. 동시에 Play 모드에서 `NetworkComponent`가 부착된 오브젝트를 선택하면 Inspector 패널에서 각 네트워크 채널의 연결 상태, 송수신 패킷 수, 하트비트 진행 상황을 실시간으로 확인할 수 있으며, 한 번의 클릭으로 연결을 끊을 수도 있습니다.

## 사전 조건

- 프로젝트에 GameFrameX Network 패키지가 설치되어 있고, 씬에 `NetworkComponent`가 부착되어 있어야 합니다.
- 로그는 `Log.Debug`로 출력되므로, GameFrameX 로그 컴포넌트의 Debug 레벨 로그가 활성화되어 있는지 확인해야 합니다. 그렇지 않으면 콘솔에서 내용을 볼 수 없습니다.

## 작업 단계

### 1. 네트워크 로그 활성화/비활성화

1. Unity 상단 메뉴 바에서 `GameFrameX/Scripting Define Symbols` 그룹을 찾습니다.
2. 필요에 따라 아래 메뉴 항목을 클릭합니다(클릭하면 해당 매크로가 Player Settings의 Scripting Define Symbols에 기록되며, Unity가 자동으로 다시 컴파일합니다):

| 메뉴 항목 | 기능 | 해당 매크로 |
|------|------|--------|
| `Enable Network Send Logs(开启网络发送日志打印)` | 송신 메시지 출력 | `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Disable Network Send Logs(关闭网络发送日志打印)` | 송신 로그 비활성화 | `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` 제거 |
| `Enable Network Receive Logs(开启网络接收日志打印)` | 수신 메시지 출력 | `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |
| `Disable Network Receive Logs(关闭网络接收日志打印)` | 수신 로그 비활성화 | `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` 제거 |

메뉴 구현은 [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L67-L98)에서 제공되며, 매크로 상수 정의는 다음과 같습니다:

```csharp
public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG";
public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG";
public const string ForceEnableNetworkSendLogScriptingDefineSymbol = "FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET";
```

출처: [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L40-L44)

3. 활성화한 후 게임을 실행하면, 콘솔에 `发送消息 ID:[10001,0,xxxReq] 消息内容:{...}` 및 `收到消息 ID:[...] 消息内容:{...}` 형식의 로그가 출력됩니다. 실제 출력 로직은 다음과 같습니다:

```csharp
protected void DebugSendLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG
    var messageId = ProtoMessageIdHandler.GetReqMessageIdByType(messageObject.GetType());
    if (!IgnoreSendIds.Contains(messageId))
    {
        Log.Debug($"发送消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}

protected void DebugReceiveLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG
    var messageId = ProtoMessageIdHandler.GetRespMessageIdByType(messageObject.GetType());
    if (!IgnoreReceiveIds.Contains(messageId))
    {
        Log.Debug($"收到消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}
```

출처: [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L949-L969)

### 2. 로그 출력 제외 메시지 ID 설정

고빈도 메시지(예: 하트비트)는 콘솔을 가득 채울 수 있으므로, Inspector에서 이들을 로그 출력에서 제외할 수 있습니다:

1. 씬에서 `NetworkComponent`가 부착된 오브젝트를 선택합니다.
2. Inspector 패널에서 다음 두 필드를 찾습니다(**Play 모드가 아닐 때만 편집 가능**):
   - `Ignore Log Printing For Sent Message IDs`: 송신 측에서 제외할 메시지 ID 목록입니다.
   - `Ignore Log Printing Of Received Message IDs`: 수신 측에서 제외할 메시지 ID 목록입니다.
3. 출력하지 않을 메시지 ID를 입력하면 Play 모드 진입 시 즉시 적용됩니다. 목록에 해당하는 메시지는 위의 `Log.Debug`가 실행되지 않습니다.

코드에서 동적으로 설정해야 하는 경우, 채널 기반 클래스가 public 메서드를 제공합니다:

```csharp
public void SetIgnoreLogNetworkIds(List<int> sendIds, List<int> receiveIds)
{
    IgnoreSendIds = sendIds;
    IgnoreReceiveIds = receiveIds;
}
```

출처: [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L977-L982)

### 3. Inspector 패널로 런타임 상태 확인

1. Play 모드에 진입한 뒤, Hierarchy에서 씬의 `NetworkComponent` 오브젝트를 선택합니다.
2. Inspector 상단에 `Network Channel Count`가 표시되고, 그 아래 각 네트워크 채널별로 그룹이 표시되며 다음을 포함합니다:

| 패널 필드 | 의미 |
|------|------|
| 채널 이름 + `Connected`/`Disconnected` | 채널 이름과 연결 상태 |
| `Address Family` | 주소 체계(IPv4/IPv6 등) |
| `Local Address` / `Remote Address` | 로컬/원격 소켓 주소, 연결되지 않은 경우 `Unavailable` 표시 |
| `Send Packet` | `已发送包数 / 待发送包数` |
| `Miss Heart Beat Count` | 하트비트 누락 횟수 |
| `Heart Beat` | `已流逝时间 / 心跳间隔`(초, 소수점 둘째 자리) |
| `Disconnect` 버튼 | 해당 채널 연결 끊기 |

패널 그리기 핵심 코드는 다음과 같으며, `Disconnect` 버튼은 내부적으로 `Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError)`를 호출합니다:

```csharp
EditorGUILayout.LabelField(networkChannel.Name, networkChannel.Connected ? "Connected" : "Disconnected");
EditorGUILayout.LabelField("Address Family", networkChannel.AddressFamily.ToString());
EditorGUILayout.LabelField("Send Packet", Utility.Text.Format("{0} / {1}", networkChannel.SendPacketCount, networkChannel.SentPacketCount));
EditorGUILayout.LabelField("Miss Heart Beat Count", networkChannel.MissHeartBeatCount.ToString());
EditorGUILayout.LabelField("Heart Beat", Utility.Text.Format("{0:F2} / {1:F2}", networkChannel.HeartBeatElapseSeconds, networkChannel.HeartBeatInterval));
EditorGUI.BeginDisabledGroup(!networkChannel.Connected);
{
    if (GUILayout.Button("Disconnect"))
    {
        networkChannel.Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError);
    }
}
```

출처: [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L95-L123)

또한, Play 모드가 아닐 때 Inspector에서는 두 가지 실행 설정을 편집할 수 있습니다: `RPC Timeout Time In Milliseconds`(슬라이더 범위 3000–50000 밀리초)와 `Focus Send Heartbeat`입니다. Play 모드가 아닐 때 패널에는 설정 영역만 표시되고 `Available during runtime only.`라는 안내가 표시되며, 런타임 상태 영역은 렌더링되지 않습니다.

## 일반적인 변형

- **WebSocket 채널 강제**: 동일한 메뉴 그룹에 `Enable Force WebSocket(开启强制使用WebSocket网络)` / `Disable Force WebSocket(关闭强制使用WebSocket网络)`도 있으며, 매크로 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET`를 제어하여 네트워크를 강제로 WebSocket으로 사용하도록 합니다.
- **단방향 트래픽만 점검하고 싶을 때**: `Enable Network Receive Logs`만 켜고 Send를 끈 뒤, 수신 제외 목록으로 하트비트를 필터링하면 서버의 다운스트림 메시지만 확인할 수 있습니다.

## 자주 발생하는 오류

- **매크로를 켰는데 로그가 전혀 출력되지 않음**: 로그 레벨은 `Log.Debug`입니다. GameFrameX 로그 컴포넌트가 Debug 레벨을 차단하고 있거나, 메시지 ID가 제외 목록(`IgnoreSendIds`/`IgnoreReceiveIds`)에 포함된 경우 출력되지 않습니다.
- **Inspector에서 필드를 변경할 수 없음**: `RPC Timeout`, `Focus Heartbeat`, 두 개의 제외 목록은 Play 모드에서 비활성화됩니다(`EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode)`). Play 모드를 종료한 후 변경해야 합니다.
- **패널에서 채널 상태가 보이지 않음**: 런타임 상태는 Play 모드이면서 오브젝트가 씬 Hierarchy에 있을 때만 그려집니다. Play 모드가 아니거나 선택한 것이 Prefab 에셋인 경우 안내 메시지만 표시됩니다.
- **매크로가 적용되지 않음/컴파일 오류**: 매크로가 기록되면 Unity가 재컴파일을 트리거합니다. 그래도 로그가 출력되지 않으면 `Project Settings > Player > Scripting Define Symbols`에 매크로가 실제로 존재하는지 확인하세요(메뉴는 단지 추가/제거만 수행합니다).

## 배경

로그 스위치가 런타임 부울 스위치 대신 조건부 컴파일(`#if`)을 사용하는 이유는 로그를 껐을 때 오버헤드를 0으로 만들기 위함입니다. `Log.Debug` 전체와 JSON 직렬화가 빌드 결과물에 포함되지 않습니다. Inspector는 `[CustomEditor(typeof(NetworkComponent))]`가 적용된 `NetworkComponentInspector`가 제공하며, 매 프레임 `Repaint()`를 호출하여 런타임 데이터를 갱신하므로 Play 모드에서 데이터가 지속적으로 업데이트됩니다.
