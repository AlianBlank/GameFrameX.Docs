# 配置加载失败怎么办

當透過 `ConfigComponent` 註冊或讀取全域配置時,如果出現 `LoadConfigFailureEventArgs`(事件編號為 `LoadConfigFailureEventArgs` 的完整類別名稱),或呼叫 `GetConfig<T>()` 回傳 `default`/`null`,通常意味著底層 `ConfigManager` 未拿到配置資料。本頁幫助你快速定位原因並修復。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 日誌打印 `Config manager is invalid.` | `ConfigComponent.Awake` 時未取到 `IConfigManager` 實作 | 見 [ConfigManager 未注入](#configmanager-未注入) |
| `GetConfig<T>()` 回傳 `null` / `default(T)` | 資源載入成功但未透過 `Add` 註冊到管理器,或資源名與類別名不匹配 | 見 [未註冊到 ConfigComponent](#未註冊到-configcomponent) |
| 收到 `LoadConfigFailureEventArgs`,`ErrorMessage` 含 `IOException` / 解析失敗 | 配置二進位 / JSON 資源未產生或與程式碼不同步 | 見 [配置資源缺失或格式損壞](#配置資源缺失或格式損壞) |
| `HasConfig<T>()` 始終回傳 `false` | 取名鍵使用了區分大小寫比較(`StringComparer.Ordinal`) | 見 [配置名稱大小寫不匹配](#配置名稱大小寫不匹配) |

## 修復步驟

### ConfigManager 未注入

`ConfigComponent.Awake` 透過 `GameFrameworkEntry.GetModule<IConfigManager>()` 取得管理器實作。如果框架未註冊 `ConfigManager`,會立即記錄致命日誌並直接回傳,後續所有讀寫都無效。

[ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85) 中:

```csharp
protected override void Awake()
{
    m_ConfigNameTypeMap.Clear();
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IConfigManager);
    base.Awake();
    m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
    if (m_ConfigManager == null)
    {
        Log.Fatal("Config manager is invalid.");
        return;
    }
}
```

確認專案內已包含 `GameFrameX.Config.Runtime.ConfigManager` 程式集,並在引導階段先於業務程式碼觸發框架初始化(框架的 `[GameFrameXAutoComponent(-5000)]` 特性會保證它早於普通業務元件註冊)。

### 未註冊到 ConfigComponent

`ConfigComponent` 本身只負責「按名存取」,**不**負責載入資源。讀取配置前,必須把解析後的 `IDataTable` 明確塞進管理器:

```csharp
ConfigComponent.Instance.Add(typeof(MyConfig).Name, myDataTableInstance);
var cfg = ConfigComponent.Instance.GetConfig<MyConfig>();
```

[ConfigComponent.cs#L182-L185](/Runtime/Config/ConfigComponent.cs#L182-L185) 中:

```csharp
public void Add(string configName, IDataTable dataTable)
{
    m_ConfigManager.AddConfig(configName, dataTable);
}
```

如果跳過 `Add` 直接 `GetConfig<T>()`,`ConfigManager` 內部字典中無該鍵,回傳 `default`,並觸發 `LoadConfigFailureEventArgs`。

### 配置資源缺失或格式損壞

當你透過資源系統非同步載入二進位/JSON 並反序列化為 `IDataTable` 時,如果檔案不存在、版本不匹配或反序列化拋出例外,資源層會回呼失敗事件 `LoadConfigFailureEventArgs`,其欄位含義如下:

[LoadConfigFailureEventArgs.cs#L43-L65](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L43-L65) 中:

```csharp
public sealed class LoadConfigFailureEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(LoadConfigFailureEventArgs).FullName;

    public LoadConfigFailureEventArgs()
    {
        ConfigAssetName = null;
        ErrorMessage = null;
        UserData = null;
    }

    public override string Id { get { return EventId; } }
    public string ConfigAssetName { get; private set; }
    public string ErrorMessage    { get; private set; }
    public object UserData        { get; private set; }
}
```

排查要點:

1. 在訂閱事件時打印 `e.ConfigAssetName` 與 `e.ErrorMessage`,定位是哪個資源失敗;
2. 重新匯出/產生配置(確保 Excel/Lua/JSON 已重導,二進位已重新打包到 StreamingAssets 或 Addressables);
3. 如果配置結構體欄位有變動,確認已重新產生程式碼與資料表,舊二進位將無法反序列化。

### 配置名稱大小寫不匹配

`ConfigManager` 在構造字典時使用了 `StringComparer.Ordinal`,即**嚴格區分大小寫**且與文化無關:

[ConfigManager.cs#L58-L61](/Runtime/Config/ConfigManager.cs#L58-L61) 中:

```csharp
public ConfigManager()
{
    m_ConfigDatas = new ConcurrentDictionary<string, IDataTable>(StringComparer.Ordinal);
}
```

`ConfigComponent.GetTypeName<T>()` 用的是 `typeof(T).Name`,而你傳入的 `configName` 若大小寫不同則視為不同鍵。註冊與查詢時務必保持字串完全一致。

## 驗證

修復後,透過以下方式確認問題已解決:

1. `Log.Fatal("Config manager is invalid.")` 不再出現;
2. `HasConfig<T>()` 對目標類別回傳 `true`;
3. `GetConfig<T>()` 回傳非空實例,欄位值與源資料一致;
4. 訂閱 `LoadConfigFailureEventArgs.EventId`,不再收到任何失敗事件。

```csharp
GameFrameworkEvent.Get().Subscribe(LoadConfigFailureEventArgs.EventId, (sender, e) =>
{
    var args = (LoadConfigFailureEventArgs)e;
    Log.Error($"配置載入失敗: {args.ConfigAssetName} - {args.ErrorMessage}");
});
```
