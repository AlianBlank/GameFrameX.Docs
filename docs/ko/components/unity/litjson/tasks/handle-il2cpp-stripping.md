# Unity IL2CPP 관리 코드 스트리핑 대응 방법

IL2CPP + Managed Code Stripping을 활성화한 후, `GameFrameX.LitJSON`은 세 가지 상호 보완적인 메커니즘을 통해 자체 타입이 제거되지 않도록 보호합니다. 이 페이지에서는 이러한 메커니즘이 어떻게协同(협동)하여 동작하는지, 그리고 스트리핑으로 인한 `MissingMethodException` / `TypeLoadException`이 발생했을 때 보호를 보완하는 방법을 설명합니다.

## 사전 조건

- Unity 2019.4 이상 버전 ([package.json](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/package.json#L5) 참조)
- Scoped Registry 또는 Git URL 방식으로 `com.gameframex.unity.litjson` 설치 완료 (자세한 내용은 README 참조)
- 프로젝트에서 IL2CPP 백엔드 사용 (Android/iOS 등 출시 플랫폼은 기본적으로 활성화됨)

## 작업 단계

### 1. 스트리핑 보호가 기본적으로 활성화되어 있는지 확인

패키지에 이미 세 가지 보호가 내장되어 있으므로, **대부분의 프로젝트는 추가 설정이 필요하지 않습니다**:

| 메커니즘 | 역할 | 출처 |
|------|------|------|
| `link.xml` | 네임스페이스 내 모든 타입을 선언적으로 보존 | 패키지 레벨 필터 파일 |
| `LitJsonCroppingHelper` | 시작 시 `typeof()`를 통해 핵심 타입에 접근 | `Runtime/LitJsonCroppingHelper.cs` |
| `[Preserve]` 특성 | 리플렉션에 민감한 생성자, 속성 getter, Exporter에 표시 | 각 Runtime 클래스 |

`LitJsonCroppingHelper`의 인스턴스가 씬에서 활성화 상태로 존재하는 한, 세 번째 보호는 `Start()`에서生效(적용)됩니다.

### 2. `LitJsonCroppingHelper`를 씬에 부착

**첫 번째 씬**(Bootstrap / Loading 씬)을 열고, 빈 GameObject를 생성한 다음 `LitJson Cropping Helper` 컴포넌트를 추가합니다:

```csharp
// Runtime/LitJsonCroppingHelper.cs의 Start() 실제 구현
[Preserve]
public void Start()
{
    _ = typeof(ArrayMetadata);
    _ = typeof(Condition);
    _ = typeof(ExporterFunc);
    _ = typeof(ExporterFunc<>);
    _ = typeof(JsonIgnoreAttribute);
    _ = typeof(JsonPropertyAttribute);
    _ = typeof(FsmContext);
    _ = typeof(IJsonWrapper);
    _ = typeof(ImporterFunc);
    _ = typeof(ImporterFunc<,>);
    _ = typeof(JsonData);
    _ = typeof(JsonException);
    _ = typeof(JsonMapper);
    _ = typeof(JsonMockWrapper);
    _ = typeof(JsonReader);
    _ = typeof(JsonToken);
    _ = typeof(JsonType);
    _ = typeof(JsonWriter);
    _ = typeof(Lexer);
    _ = typeof(ObjectMetadata);
    _ = typeof(OrderedDictionaryEnumerator);
    _ = typeof(ParserToken);
    _ = typeof(PropertyMetadata);
    _ = typeof(UnityTypeBindings);
    _ = typeof(WrapperFactory);
    _ = typeof(WriterContext);
}
```

Source: [LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L23-L52)

각 `_ = typeof(...)`는 C# 7.0 discard 구문으로, IL2CPP 링커가 이러한 타입이 "사용되었다"고 인식하여 보존하도록 하는 것이 목적입니다.

### 3. 자신의 리플렉션 클래스에 `[Preserve]` 표시 (선택 사항)

LitJson이 리플렉션을 통해 커스텀 POCO를 읽고 쓸 때, 타입이 코드에서 명시적으로 new 되지 않았다면 여전히 제거될 수 있습니다. 데이터 클래스에 `[Preserve]`를 추가하면 됩니다:

```csharp
using UnityEngine.Scripting;

[Preserve]
public class PlayerData
{
    public string Name;
    public int Level;
    public Vector3 Position;
}
```

### 4. IL2CPP 빌드 트리거 및 바이너리 확인

1. File → Build Settings → 플랫폼을 iOS 또는 Android로 전환
2. Player Settings → Other Settings → Scripting Backend = `IL2CPP`, Managed Stripping Level은 기본값 `High` 유지 또는 명시적으로 `Low`/`Medium`으로 설정하여 재테스트
3. Build And Run
4. 디바이스/시뮬레이터에서 역직렬화를 한 번 실행(예: `JsonMapper.ToObject<PlayerData>(text)`), 예외가 없는지 확인

## 일반적인 변형

- **코드 핫업데이트 시나리오**: HybridCLR / ILRuntime를 사용하는 경우, 호스트 프로젝트의 핫업데이트 DLL에도 link.xml을 별도로 추가해야 합니다. 그렇지 않으면 핫업데이트 코드가 참조하는 LitJson 타입이 여전히 제거될 수 있습니다.
- **Addressables 원격 리소스**: 런타임에 원격에서 로드된 `AssemblyDefinition`은 메인 프로젝트의 link.xml 제약을 받지 않으므로, 원격 어셈블리 자체의 asmdef 옆에 별도로 추가해야 합니다.
- **`LitJsonCroppingHelper`를 사용하지 않는 경우**: 수동으로 link.xml을 작성하여 세 번째 보호를 대체할 수 있습니다 (다음 섹션 참조).

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| 런타임 `MissingMethodException: void LitJson.JsonMapper::.cctor()` | `JsonMapper`의 cctor가 제거됨 | `LitJsonCroppingHelper`가 씬에 부착되어 활성화되어 있는지 확인 |
| `TypeLoadException: Could not load type LitJson.Lexer` | `Lexer` 타입이 제거됨 | 위와 동일, 또는 자신의 데이터 클래스에 `[Preserve]` 추가 |
| `[Preserve]` 표시 후에도 여전히 오류 발생 | source-only `link.xml`을 사용했지만 관리 스트리핑에서 무시됨 | link.xml을 `Assets/` 루트 디렉터리 또는 패키지 루트 디렉터리에 배치 ( `Assets/Plugins/` 하위 폴더가 아닌 곳) |
| iOS 빌드에서 `Start()`가 트리거되지 않음 | `LitJsonCroppingHelper` 컴포넌트가 로드되지 않은 하위 씬에 부착됨 | 첫 번째 씬에 직접 부착하거나, 커스텀 `RuntimeInitializeOnLoadMethod`에서 수동으로 호출 |

## 배경 (선택 사항)

LitJson은 리플렉션을 광범위하게 사용합니다(`JsonMapper.ToObject<T>`는 리플렉션을 통해 필드를 읽고 setter를 씁니다). IL2CPP 정적 분석은 직접 호출되는 코드만 식별할 수 있으며, 리플렉션 호출 체인은 추적할 수 없으므로 `new` 되지 않은 타입은 제거됩니다. 패키지에서는 **삼중 보호**를 채택합니다: link.xml을 통한 화이트리스트, `LitJsonCroppingHelper`의 런타임 `typeof` 접근, `[Preserve]`를 통한 리플렉션 진입점 표시 — 어느 한 계층이失效(실패)해도 나머지 두 계층이 여전히 보완해 줍니다.

LitJson의 전반적인 사용 방법은 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md)를 참조하세요.
