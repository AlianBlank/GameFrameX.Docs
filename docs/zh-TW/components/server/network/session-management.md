# 管理用戶端工作階段(Session / 連線中斷)

GameFrameX 透過 `Session` 與 `SessionManager` 維護每個網路連線的工作階段狀態，包括登入後的角色繫結、頂號踢人、連線中斷清理等行為。讀完本頁你可以在登入、踢人、斷線等情境中正確地讀寫 Session,並接收 `EventId.SessionRemove` 事件以完成下線收尾。

## 前置條件

- 已引入 `GameFrameX.Apps.Common.Session` 命名空間(程式碼位於 [Session.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs) 與 [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs))。
- 已使用框架的 `AppStartUp` 介接協定，並透過 `IAppSession` 取得連線資訊。
- 玩家 Actor 已透過 `ActorManager` 註冊(否則 `GetByRoleId` 會回傳空)。

## 操作步驟

### 1. 在交握/登入成功後建立並登記 Session

登入成功時由 `AppStartUp` 呼叫 `SessionManager.Add` 把目前連線登記到全域字典。底層會把 `SessionId` 寫入通道資料，便於協定層回呼時依 ID 反查。

```csharp
using GameFrameX.Apps.Common.Session;

// netWorkChannel 來自於協定層的 INetWorkChannel
var session = new Session(sessionId, netWorkChannel);
SessionManager.Add(session);
```

Source: [SessionManager.cs#L186-L191](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L186-L191)

### 2. 登入成功後繫結角色 ID 與簽名

透過 `UpdateSession` 把 `roleId` 與 `sign` 寫入目前連線；如果該 `roleId` 已在另一台裝置登入，框架會向舊工作階段傳送「帳號已在其他裝置登入」提示並踢下線。

```csharp
SessionManager.UpdateSession(sessionId, roleId, sign);
```

底層行為(摘自原始碼)：

1. 用 `GetByRoleId(roleId)` 找出舊工作階段。
2. 建構 `RespPrompt { Type = 5, Content = "你的账号已在其他设备上登陆" }` 並透過 `oldSession.WriteAsync` 傳送。
3. 呼叫 `oldSession.WorkChannel.ClearData()` + `Close()`,並 `Remove(oldSession.SessionId)`。
4. 對目前工作階段呼叫 `SetPlayerId(roleId)` / `SetSign(sign)`。

Source: [SessionManager.cs#L200-L229](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L200-L229)

### 3. 透過 Session 向用戶端回覆訊息

`Session.WriteAsync` 會委派給底層網路通道傳送，可附帶錯誤碼。

```csharp
var session = SessionManager.Get(sessionId);
if (session != null)
{
    await session.WriteAsync(messageObject, errorCode: 0);
}
```

Source: [Session.cs#L99-L105](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs#L99-L105)

### 4. 監聽連線中斷(主動踢人 / 網路斷線)

連線中斷由 `AppStartUp` 鉤子統一處理，原始碼範例(節錄)：

```csharp
protected override async ValueTask OnDisconnected(IAppSession appSession, CloseEventArgs disconnectEventArgs)
{
    var session = SessionManager.Get(appSession.Id);
    if (session != null)
    {
        var roomAgent = await ActorManager.GetComponentAgent<RoomComponentAgent>();
        await roomAgent.MarkPlayerDisconnected(session.PlayerId);
    }
}
```

`RoomComponentAgent` 中預留了 120 秒斷線寬限(`DisconnectedPlayerAutoLeaveSeconds`),逾時才會真正踢出房間。

Source: [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76)、[RoomComponentAgent.cs#L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L45)

### 5. 回應 SessionRemove 事件以完成下線收尾

`SessionManager` 在三種情況下會發出 `EventId.SessionRemove`(值=1000):

- `Remove(sessionId)`
- `KickOffLineByUserId(roleId)`
- `RemoveAll()`
- `UpdateSession` 頂號時移除舊工作階段

框架以 `[Event(EventId.SessionRemove)]` 特性將監聽器繫結到玩家 Agent,預設實作會呼叫 `agent.OnLogout()`。你可以依業務擴充：

```csharp
[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

Source: [SessionRemoveEventListener.cs#L39-L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L39-L45)、[EventId.cs#L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Event/EventId.cs#L41)

## 常見變體

### 依角色 ID 主動踢人

```csharp
SessionManager.KickOffLineByUserId(roleId);
```

會在內部發出 `SessionRemove`,觸發 `OnLogout`。來源:[SessionManager.cs#L79-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L79-L89)。

### 關閉時清空所有工作階段

```csharp
await SessionManager.RemoveAll();
```

會在逐一發出 `SessionRemove` 後對字典執行 `Clear()`。來源:[SessionManager.cs#L158-L170](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L158-L170)。

### 分頁查詢線上玩家

`GetPageList(pageSize, pageIndex)` 會過濾掉 `ActorManager` 中已不存在的 Actor,只回傳真正線上的玩家。來源:[SessionManager.cs#L65-L73](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L65-L73)。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `GetByRoleId(roleId)` 一律回傳 null | 玩家 Actor 未註冊，或 `SessionMap` 已被非同步清理 | 確保登入流程中 `ActorManager` 已註冊玩家，且呼叫端在 Session 生命週期內存取 |
| 頂號提示送出後舊連線未立即關閉 | 僅 `WriteAsync` 未呼叫 `WorkChannel.Close()` | 使用框架內建的 `SessionManager.UpdateSession` 流程，不要自行手動管理舊工作階段 |
| 斷線玩家未自動離房 | 未在 `OnDisconnected` 呼叫 `MarkPlayerDisconnected` | 參考 [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76) 範本，將斷線轉送到房間 Agent |

## 背景(選用)

`SessionManager` 使用 `ConcurrentDictionary<string, Session>` 作為全域儲存，每個連線一個 `SessionId`;`Session` 內部持有 `INetWorkChannel` 用於收發資料。`UpdateSession` 的「先移除再等 Disconnected」註解([L217](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L217))說明頂號時若只靠斷線回呼清理會產生延遲，因此同步 `Remove` 舊項目以確保狀態一致。
