# 씬 리소스 이름이 유효하지 않을 때 어떻게 해야 하나요

`LoadScene(string sceneAssetName, ...)`를 호출할 때 전달한 리소스 이름(경로)이 YooAsset 리소스 매니페스트에서 조회되지 않으면 씬 로드가 즉시 실패하며, 흔한 증상으로는 `LoadSceneFailure` 이벤트가 트리거되거나, `await`가 반환한 `Task`가 예외를 던지거나, 에디터 로그에 "리소스가 존재하지 않음 / asset not found" 오류가 출력되는 것이 있습니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `LoadSceneFailure` 이벤트가 트리거되고, `SceneAssetName`이 전달한 문자열임 | YooAsset 리소스 매니페스트에 이 `sceneAssetName`이 없음 | 올바른 "에셋 이름/에셋 경로"로 다시 시도하고, 패키징 출력에 등록되어 있는지 확인 |
| `sceneAssetName`이 비어 있거나 null이라고 보고됨 | 호출 전에 경로가 제대로 구성되지 않았거나, 설정 테이블에서 빈 문자열을 읽어옴 | 호출 전에 널 검사를 수행하고, 설정 테이블의 완전한 `Assets/...` 경로를 사용 |
| 비동기 `Task`가 `OperationCanceledException`을 던지거나 계속 반환되지 않음 | 동일한 리소스 이름이 이미 `m_LoadingSceneAssetNames`에 있어 중복 로드가 무시됨 | 먼저 `UnloadScene`을 호출하거나 이전 로드가 완료되기를 기다려, 동시 중복 로드를 피함 |
| 에디터에서는 정상이지만 패키징 후 씬을 찾을 수 없음 | 해당 씬이 YooAsset 리소스 패키지에 포함되지 않았거나, 패키지 이름과 로드 경로가 일치하지 않음 | YooAsset 수집기에 씬 파일을 추가하고 리소스 패키지를 다시 빌드 |

## 수정 단계

### 1. 리소스 이름이 비어 있지 않고 매니페스트와 일치하는지 검증

`LoadScene` 내부에서는 `sceneAssetName`을 YooAsset 씬 조회의 key로 사용하므로, 문자열이 YooAsset 수집기가 생성한 에셋 경로와 완전히 일치해야 합니다(일반적으로 `Assets/Scenes/xxx.unity`).

```csharp
// 권장: 호출하기 전에 먼저 검증
if (string.IsNullOrWhiteSpace(sceneAssetName))
{
    GameFrameworkLog.Error("[Scene] sceneAssetName은 비어 있을 수 없습니다");
    return;
}
var handle = await GameEntry.Scene.LoadScene(sceneAssetName,
    UnityEngine.SceneManagement.LoadSceneMode.Single);
```

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L337-L348)는 네 개의 `LoadScene` 오버로드를 노출하며, 시그니처는 각각 `(string)`, `(string, LoadSceneMode)`, `(string, object)`, `(string, LoadSceneMode, object)`입니다. 어떤 오버로드든 유효한 `sceneAssetName`을 전달해야 합니다.

### 2. 실패 이벤트를 수신하여 실제 리소스 이름 확인

`LoadSceneFailure` 이벤트를 구독하면 이벤트 인자에서 런타임에 실제로 로드를 시도한 `SceneAssetName`을 가져올 수 있습니다:

```csharp
GameEntry.Scene.LoadSceneFailure += (sender, e) =>
{
    Debug.LogError($"씬 로드 실패: {e.SceneAssetName}, 오류 메시지: {e.ErrorMessage}");
};
```

이벤트 소스는 [LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs)에 있습니다. 로그에 출력된 `SceneAssetName`을 YooAsset 리소스 매니페스트(`AssetBundle` / `AssetPackage` 목록)와 대조하면, 대개 철자나 대소문자 오류를 바로 찾아낼 수 있습니다.

### 3. YooAsset이 해당 씬을 수집하고 빌드했는지 확인

씬이 로드되려면 두 가지 조건을 충족해야 합니다:

1. YooAsset 수집기 규칙에 이 `.unity` 파일을 포함시킬 것;
2. YooAsset 빌드 프로세스(패키징/로컬 빌드)를 다시 실행하고, 실행 모드(Run Mode)에서 최신으로 산출된 리소스 패키지를 사용할 것.

Unity 에디터에서만 로드되고 패키징 후에는 실패한다면, 거의 대부분 이 단계를 수행하지 않은 경우입니다.

### 4. 동일한 리소스 이름의 동시 로드 방지

`GameSceneManager`는 내부적으로 `m_LoadingSceneAssetNames`로 로드 중인 리소스를 추적하며, 동일한 `sceneAssetName`으로 `LoadScene`을 반복 호출하면 새 `Task`를 받을 수 없어 "무효"로 보이는 현상이 나타납니다. 해결 방법은 매 로드 로직이 해당 리소스 이름을 독점하도록 하거나, 이전 `LoadScene`이 반환한 `Task`가 완료된 후 다음 호출을 시작하는 것입니다.

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L371)의 완전한 구현은 네 매개변수 오버로드에 있으며, 성공 또는 실패 콜백이 호출되기 전까지 `SceneHandle`과 `UserData`를 `m_LoadingSceneAssetNames`에 저장한다는 것을 확인할 수 있습니다.

## 검증

정상적으로 로드되는 씬과 대조하여 다음을 실행해 보세요:

1. 확실히 존재하는 씬(예: `Assets/Scenes/Init.unity`)으로 `LoadScene`을 호출하여 `LoadSceneSuccess` 이벤트가 트리거되는지 확인;
2. `sceneAssetName`을 일부러 존재하지 않는 문자열로 바꾸어, `LoadSceneFailure`가 트리거되고 로그에 실제 시도한 리소스 이름이 출력되는지 확인;
3. 존재하지 않는 문자열을 올바른 경로로 되돌린 후 다시 `LoadScene`을 호출하여 성공하는지 확인.

1단계와 3단계가 모두 성공하고 중간 단계의 실패 이벤트가 예상대로 트리거되면, "씬 리소스 이름이 유효하지 않음" 문제는 문자열/경로 문제로 특정된 것이며, 프레임워크 측 API 호출 방식의 오류가 아님을 알 수 있습니다.
