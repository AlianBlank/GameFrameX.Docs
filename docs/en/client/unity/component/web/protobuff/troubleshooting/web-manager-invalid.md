# What to Do When the "Web manager is invalid." Fatal Log Appears at Startup

This Fatal log originates from `WebProtoBuffComponent.Awake()`: it is printed when `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` returns `null`, indicating that the Web ProtoBuff manager module was not successfully retrieved (not registered or the implementation type was stripped). The component then `return`s, causing all subsequent Web request calls to fail.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Web manager is invalid.` is printed immediately at startup, and subsequent calls to `Post` and other APIs throw `NullReferenceException` | `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` returns `null`; the manager implementation is not registered with the framework entry | See fix step 1 below |
| The log only appears in builds (on device/after stripping); works fine in the editor | Managed code stripping removed the `WebProtoBuffManager` implementation class | See fix step 2 below |
| The `GameFrameXWebProtoBuffCroppingHelper` was manually removed from a GameObject | This Helper references the manager type via `typeof` to prevent linker stripping | See fix step 3 below |
| Calling `Post<T>` reports that the method does not exist | The `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` macro is not enabled (this macro only affects `Post<T>` and is unrelated to the Fatal log itself) | See fix step 4 below |

## Fix Steps

The log's check logic is shown below for reference during troubleshooting:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IWebProtoBuffManager);
    base.Awake();
    m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
    if (m_WebProtoBuffManager == null)
    {
        Log.Fatal("Web manager is invalid.");
        return;
    }

    m_WebProtoBuffManager.Timeout = m_Timeout;
}
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L77-L90)

1. **Verify that the manager implementation class is reachable**. `WebProtoBuffManager` (located at `Runtime/Web/WebProtoBuffManager.cs`, namespace `GameFrameX.Web.ProtoBuff.Runtime`) is the implementation of `IWebProtoBuffManager`; `GetModule` relies on the GameFrameX runtime base package (where `GameFrameworkEntry` resides) to complete registration. Confirm that the GameFrameX base runtime package is correctly installed in the project and that this package's assembly compiles without errors (no red compilation errors in the Console).
2. **Reduce/disable managed stripping**. Lower the stripping level in Unity's `Player Settings → Managed Stripping Level`, or configure preservation rules for this package's assembly to ensure `WebProtoBuffManager` is not stripped.
3. **Keep the anti-stripping Helper**. `WebProtoBuffComponent` enforces a dependency on this Helper via `[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]`; it holds references to all key types in this package:

```csharp
[Preserve]
public class GameFrameXWebProtoBuffCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(WebProtoBuffComponent);
        _ = typeof(IWebProtoBuffManager);
        _ = typeof(WebProtoBuffManager);
    }
}
```

Source: [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs#L6-L16)

   Do not manually remove the `GameFrameXWebProtoBuffCroppingHelper` component from GameObjects in the scene.
4. **Enable the network macro as needed**. To use Protocol Buffer requests, add `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` to `Scripting Define Symbols`; otherwise `Post<T>` will not be compiled into the component (see the `#if` condition at line 92 of `WebProtoBuffComponent.cs`).

## Verification

- Re-enter Play mode (or rebuild); the `Web manager is invalid.` Fatal log no longer appears in the Console.
- Modifying `Timeout` (default `5f` seconds) in the component's Inspector takes effect normally—it directly reads and writes `m_WebProtoBuffManager.Timeout`.
- After enabling the macro, `WebProtoBuffComponent.Post<T>(url, message)` can be called normally.
