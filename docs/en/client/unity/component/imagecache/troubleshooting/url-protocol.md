# What to Do When URL Protocol Validation Fails

When you call `LoadImageAsync`, if the URL passed in does not start with `http://` or `https://`, the component will directly reject the load and output a warning in the console. This call returns `null` and will not trigger the download or cache process.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Console shows `ImageCache: url must start with http:// or https://. url: ...`, and `LoadImageAsync` returns `null` | URL is missing the protocol prefix or the protocol is not http/https (e.g., `ftp://`, `file://`, `data:`, relative paths, `www.example.com/x.png`, etc.) | Prepend `http://` or `https://` to the URL string |
| URL appears correct but still fails validation | URL has extra whitespace, newlines, or invisible characters at the beginning or end | Call `Trim()` to remove leading/trailing whitespace before calling |
| URL passes validation but loading still fails | URL protocol is valid but the resource is unavailable, network is unreachable, or the server returns an error | See the section "Loading Still Fails After Passing Validation" below |

## Fix Steps

### 1. URL Is Missing the Protocol Prefix

The validation logic only accepts the `http://` and `https://` prefixes; other protocols or bare domains will be rejected.

```csharp
// Invalid — bare domains will be rejected
string bad1 = "www.example.com/img.png";
string bad2 = "example.com/img.png";

// Valid
string good1 = "http://www.example.com/img.png";
string good2 = "https://www.example.com/img.png";
```

Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L78-L82)

### 2. URL Has Extra Whitespace at the Beginning or End

`StartsWith` validation is case-sensitive and does not perform trimming; any leading whitespace will cause the prefix comparison to fail. It is recommended to explicitly `Trim` before calling.

```csharp
string rawUrl = "  https://example.com/img.png  ";
string url = rawUrl.Trim();

var tex = await ImageCacheComponent.Instance.LoadImageAsync(url);
```

### 3. Loading Still Fails After URL Passes Validation

Validation only checks the protocol prefix; it does not verify whether the resource is actually downloadable. If the "url must start with ..." message does not appear in the log, troubleshoot in order:

- Console shows `ImageCache: url is null or empty.` — The passed-in string is `null` or empty; provide a valid URL.
- Console shows a download failure event (`DownloadFailure`) — Server returns 404/403, network timeout, or CORS restriction; check the server status and HTTPS certificate.
- WebGL platform: After validation passes, `LoadImageWebGLAsync` is called, and the browser handles caching; if the browser reports a CORS error, the server needs to return the correct cross-origin headers.

Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## Verification

1. Before calling, print or breakpoint to confirm the URL starts with `http://` or `https://`, and has no leading/trailing whitespace.
2. After issuing `LoadImageAsync`, if a non-null `Texture2D` is returned and there is no "url must start with" warning in the console, the validation has passed and the load succeeded.
3. If it still returns `null`, refer to the diagnosis table above and check the log keywords to locate the specific failure stage.
