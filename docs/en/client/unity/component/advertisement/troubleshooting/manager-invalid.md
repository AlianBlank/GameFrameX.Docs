# What to do when "Advertisement manager is invalid"

When `Log.Fatal("Advertisement manager is invalid.")` appears in the runtime console, it means `AdvertisementComponent.Awake()` cannot obtain an instance of the advertisement manager through `GameFrameworkEntry.GetModule<IAdvertisementManager>()`. The component will return directly, and subsequent `Start`, `Initialize` and other processes will not execute.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Log error `Advertisement manager is invalid.` | No `IAdvertisementManager` implementation registered in `GameFrameworkEntry` | Add an `AdvertisementComponent` to the scene, and fill in the full class name of the manager class that inherits from `BaseAdvertisementManager` in the Inspector |
| Same error as above, component is mounted but still reports error | The `componentType` field is filled in incorrectly (class name typo, missing namespace, does not inherit from `BaseAdvertisementManager`) | Fill in the complete "namespace.classname", make sure the class inherits from `BaseAdvertisementManager` and implements `IAdvertisementManager` |
| Same error as above, the runtime manager for a certain platform is `null` | The platform's advertisement SDK package is not imported, and the implementation class cannot be found in the assembly | Install the corresponding platform SDK (see "Fix Steps" below) or temporarily switch `componentType` to an installed platform |
| Same error as above, only Debug build reports error | IL2CPP / managed code stripping in Player Settings excluded the manager class | Retain the manager's assembly in `link.xml` or Player Settings' `Managed Stripping Level` |

Original error text and trigger location:

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L85-L97
private IAdvertisementManager _advertisementManager;

protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IAdvertisementManager);
    base.Awake();
    _advertisementManager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
    if (_advertisementManager == null)
    {
        Log.Fatal("Advertisement manager is invalid.");
        return;
    }
    // ...
}
```

## Fix Steps

### 1. Confirm AdvertisementComponent exists in the scene

`AdvertisementComponent` is the entry component of the advertisement system. Without it, the framework will not be driven to register the advertisement manager module. How to mount:

1. Create an empty GameObject in the first startup scene (commonly named `GameFrameX`).
2. `Add Component → GameFrameX/Advertisement`, mount `AdvertisementComponent`.

### 2. Fill in componentType correctly in the Inspector

`AdvertisementComponent` loads the advertisement manager through reflection. The **full name (namespace + class name)** of the specific implementation class that inherits from `BaseAdvertisementManager` **must** be filled in, otherwise `Utility.Assembly.GetType(componentType)` returns `null` and the module will not be registered.

Common implementation classes (based on the official repository):

| Platform | Typical Implementation Class |
|------|-----------|
| Android | `YourNamespace.AndroidAdvertisementManager` |
| iOS | `YourNamespace.IOSAdvertisementManager` |
| WebGL General | `YourNamespace.WebGLAdvertisementManager` |
| WebGL WeChat Mini Game | `YourNamespace.WebGLWeChatAdvertisementManager` |
| WebGL Douyin Mini Game | `YourNamespace.WebGLDouYinAdvertisementManager` |
| WebGL Kuaishou Mini Game | `YourNamespace.WebGLKuaiShouAdvertisementManager` |

Key points for filling in:

- Must be the **complete type name**, including the namespace.
- The class must be `public`, and inherit from `BaseAdvertisementManager` (indirectly implements `IAdvertisementManager`).
- `BaseAdvertisementManager` itself inherits from `GameFrameworkModule`, which is the prerequisite for `GameFrameworkEntry.GetModule<T>()` to recognize the module.

### 3. Confirm target platform SDK is installed

The implementation class pointed to by `componentType` depends on the advertisement SDK of the corresponding platform (such as Pangle, AdMob, WeChat Mini Game advertisement SDK, etc.). If only the WebGL platform's manager is mounted in an Android project, the Android build will still fail to find the implementation, triggering the same error. Handling:

- Install the SDK package corresponding to the target platform (`Packages/manifest.json` or `.unitypackage`).
- Or temporarily switch `componentType` in the Inspector to the implementation of an installed platform.

### 4. Check code stripping and assembly inclusion

iOS / IL2CPP builds perform managed code stripping, which may incorrectly remove the manager. Two handling methods:

- Project Settings → Player → Other Settings → Set `Managed Stripping Level` to `Low` or lower.
- Or explicitly retain the manager's assembly in `Assets/link.xml`:

```xml
<linker>
  <assembly fullname="YourAdvertisementImpl" preserve="all"/>
</linker>
```

### 5. Check `m_config` and ad unit IDs

The error itself is unrelated to configuration, but `Start()` will call `_advertisementManager.Initialize(m_config)`. If the manager is `null` at this time (`_advertisementManager == null`), it will immediately throw `NullReferenceException`. Therefore, after the manager is restored, please also confirm:

- The `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` corresponding to the current platform are filled in.
- `m_config` (`AdvertisementConfig` instance) is not `null`, otherwise the initialization in `Start` will be skipped:

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L120-L126
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)

## Verification

After fixing according to the above steps, do the following checks to confirm the problem is resolved:

1. Run the game, `Advertisement manager is invalid.` no longer appears in the Console.
2. Set a breakpoint after `Awake`, confirm `_advertisementManager != null`.
3. Check that `_advertisementManager.Initialize(m_config)` in `Start` can enter normally and complete the advertisement SDK initialization callback.
4. Call an ad playback interface (such as rewarded video), it can return the display result normally.

## Common Errors

- **Only filling in the class name without the namespace**: `Utility.Assembly.GetType(componentType)` returns `null`, the module will not be registered.
- **Manager class does not inherit from `BaseAdvertisementManager`**: Even if `IAdvertisementManager` is implemented, it will not be registered as a `GameFrameworkModule`.
- **`componentType` not updated when switching platforms**: When switching from Android to iOS for packaging, `componentType` still points to the Android implementation class, resulting in a missing manager.
- **Mounting multiple `AdvertisementComponent`s**: `[DisallowMultipleComponent]` prevents duplicate mounting, but if multiple GameObjects each have one mounted in the scene, only the one that `Awake`s first will take effect.
