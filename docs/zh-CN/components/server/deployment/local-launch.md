# 使用 quick_start-game.bat 本地启动

`quick_start-game.bat` 是 `GameFrameX.Launcher` 目录下的游戏服务器一键启动脚本,执行后会在本地拉起一个 `ServerType=Game` 的网关进程,自动连接内嵌的发现中心并连接 MongoDB 数据库,适合开发阶段快速验证服务是否能起得来。

## 前置条件

- Windows 系统,已安装 .NET 10.0 SDK 或运行时(`TargetFramework=net10.0`)
- 已克隆或下载本仓库,并完成 `GameFrameX.Launcher` 的 Release 构建,产物位于 `bin\app\GameFrameX.Launcher.dll`
- 本机 `127.0.0.1` 上的 `21001` 端口可被 `DiscoveryCenter`(发现中心)监听,`29090/29100/29010/29110` 未被占用
- 网络可访问脚本中指定的 MongoDB Atlas 地址(需确保账号 `gameframex` / 密码可用)

## 操作步骤

1. 打开命令行,进入 `GameFrameX.Launcher` 目录:

   ```bat
   cd GameFrameX.Launcher
   ```

2. 直接双击或在命令行中执行 `quick_start-game.bat`:

   ```bat
   quick_start-game.bat
   ```

   脚本实际调用的是:

   ```bat
   start dotnet GameFrameX.Launcher.dll --ServerType=Game --ServerId=9000 --APMPort=29090 --InnerIp=127.0.0.1 --InnerPort=29100 --OuterIp=127.0.0.1 --OuterPort=29010 --MinModuleId=1 --MaxModuleId=9999 --WsPort=29110 --DiscoveryCenterIp=127.0.0.1 --DiscoveryCenterPort=21001 --HttpCode=inner_httpcode --DataBaseUrl="mongodb+srv://gameframex:f9v42aU9DVeFNfAF@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority" --DataBaseName=gameframex
   ```

   Source: [quick_start-game.bat](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/quick_start-game.bat#L1-L1)

3. 脚本通过 `start` 启动一个新的控制台窗口加载 `GameFrameX.Launcher.dll`,程序入口会调用 `GameApp.Entry` 完成初始化。

   ```csharp
   internal static class Program
   {
       private static async Task Main(string[] args)
       {
   #if DEBUG
           LogOptions.Default.IsConsole = true;
   #endif
           await GameApp.Entry(args, () =>
           {
               CacheStateTypeManager.Init();
               MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
           }, LogAction);
       }
   ```

   Source: [Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L5-L17)

4. 在新弹出的控制台窗口中观察日志:看到 APM、Inner、Outer、Ws 四个端口依次开始监听,且没有报错堆栈,即表示游戏服务器已经在本地成功启动。

## 启动参数说明

| 参数 | 值 | 含义 |
|------|-----|------|
| `--ServerType` | `Game` | 进程类型为游戏服(网关) |
| `--ServerId` | `9000` | 当前服务器唯一编号 |
| `--APMPort` | `29090` | 应用性能管理/管理端口 |
| `--InnerIp` / `--InnerPort` | `127.0.0.1` / `29100` | 内网通信地址 |
| `--OuterIp` / `--OuterPort` | `127.0.0.1` / `29010` | 外网客户端接入地址 |
| `--MinModuleId` / `--MaxModuleId` | `1` / `9999` | 消息模块 ID 分配区间 |
| `--WsPort` | `29110` | WebSocket 端口 |
| `--DiscoveryCenterIp` / `--DiscoveryCenterPort` | `127.0.0.1` / `21001` | 注册中心地址 |
| `--HttpCode` | `inner_httpcode` | HTTP 路由编码 |
| `--DataBaseUrl` | Atlas 连接串 | MongoDB 连接地址 |
| `--DataBaseName` | `gameframex` | 数据库名 |

## 常见错误

- **找不到 `GameFrameX.Launcher.dll`**:说明尚未编译或输出目录不是脚本预期的 `bin\app`。`csproj` 中 Release 配置输出到 `..\bin\app\`,请先在该解决方案根目录执行 `dotnet build -c Release`,或在 `GameFrameX.Launcher` 目录下构建。

  Source: [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L20-L23)

- **`dotnet` 不是内部或外部命令**:未安装 .NET 10 SDK,或安装后未将 `dotnet.exe` 加入 PATH。

- **连接 `127.0.0.1:21001` 失败**:发现中心没有启动。`quick_start-game.bat` 只会拉起 Game 服,需要先单独启动 `DiscoveryCenter` 服务再执行本脚本。

- **MongoDB 连接报错**:脚本中写死了账号 `gameframex` 与密码,若该账号被回收或网络受限,需把脚本中的 `--DataBaseUrl` 改成可用的连接串。

## 背景

`GameFrameX.Launcher` 既承担 Game 服入口,也承担构建产物的位置(`bin\app\GameFrameX.Launcher.dll`),通过传递不同的启动参数即可复用同一进程模型拉起不同类型的服务器。`quick_start-game.bat` 把常用的 Game 服参数固化为一条 `start dotnet ...` 命令,免去每次手动拼参数的麻烦。
