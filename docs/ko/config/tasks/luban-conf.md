# luban.conf 이해 및 수정 방법

`luban.conf`는 GameFrameX.Config의 마스터 설정 파일입니다: Luban 도구 체인에 어디에서 Excel을 읽을지, 어떤 데이터/코드 대상을 사용할지, 생성된 산출물을 어느 디렉터리에 저장할지 알려줍니다. 이 파일을 수정한 후 `gen-*.bat` / `gen-*.sh`를 실행하면 새 규칙에 따라 클라이언트와 서버 코드를 생성할 수 있습니다.

## 사전 조건

- [GameFrameX/GameFrameX.Config](https://github.com/GameFrameX/GameFrameX.Config) 저장소를 클론한 상태이며, 루트 디렉터리에 `luban.conf`가 존재해야 합니다.
- .NET 런타임이 설치되어 있어야 합니다(`Tools/Luban.exe` 실행용).
- `groups`(클라이언트/서버 데이터 그룹), `targets`(생성 대상), `commands`(실행할 명령) 세 가지 최상위 개념을 이해하고 있어야 합니다.

## 최상위 필드 요약

| 필드 | 역할 | 일반적인 값 |
|------|------|--------|
| `groups` | 테이블을 "클라이언트/서버"로 그룹화하며, 생성 시 그룹별로 필터링 | `c`(클라이언트), `s`(서버) |
| `schemaFiles` | Luban이 로드하는 schema 진입점(`Defines`, `__tables__` 등) | 아래 코드 블록 참조 |
| `dataDir` | Excel 데이터 루트 디렉터리 | `Excels` |
| `targets` | 생성 대상 집합, 각 대상은 하나의 코드/데이터 산출물 세트에 대응 | `server`, `client`, `all` |
| `toolPath` | Luban.dll의 상대 경로 | `/../Config/Tools/Luban.dll` |
| `UNITY_ASSETS_PATH` | Unity 프로젝트 Assets 디렉터리의 절대 경로(런타임 템플릿) | 비워 둠, 스크립트 실행 시 교체됨 |
| `SERVER_PATH` | 서버 프로젝트 루트 디렉터리의 절대 경로(런타임 템플릿) | 비워 둠, 스크립트 실행 시 교체됨 |
| `commands` | 각 생성 명령이 하나의 target에 대응하며, 명령줄 인자와 스위치 포함 | 아래 코드 블록 참조 |

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L95)

## 주요 필드별 상세 설명

### 1. groups: 데이터 분배 방식

`groups`는 각 테이블이 "클라이언트", "서버" 또는 "양단 공유" 중 어디에 속하는지 결정합니다. `default: true`는 해당 그룹의 모든 테이블이 기본적으로 생성 명령에 의해 사용됨을 의미합니다.

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

> 테이블이 어느 그룹에 속할지는 Excel에서 `__xxx__` 마커 열을 통해 표시하며, 여기서는 "어떤 그룹 이름이 존재하는지"만 정의합니다.

### 2. schemaFiles: 로드할 정의

`schemaFiles`는 Luban이 schema를 읽는 진입점이며, 순서는 상관없지만 네 줄은 필수입니다: `Defines`(내장 타입 목록), `__tables__.xlsx`(테이블 목록), `__beans__.xlsx`(복잡한 구조), `__enums__.xlsx`(열거형).

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

### 3. targets: 생성 대상 정의

각 target은 "데이터 한 세트 + 생성 산출물 한 세트"의 이름이 지정된 패키지입니다. `topModule`은 생성되는 네임스페이스이고, `manager`는 진입 클래스 이름입니다(런타임에서 `TablesComponent` 또는 `Tables` 싱글턴으로 로드).

```json
"targets": [
    { "name": "server", "manager": "TablesComponent", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "manager": "TablesComponent", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "manager": "Tables",         "groups": ["c","s"], "topModule": "cfg" }
]
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L35-L61)

### 4. commands: 실행할 생성 명령

`commands`는 실제로 `Luban.exe`에 전달되는 명령줄 배열입니다. 각 레코드는 하나의 `target`에 바인딩되며, `active: true/false`로 활성화 여부를 전환합니다. `%UNITY_ASSETS_PATH%`와 `%SERVER_PATH%`는 플레이스홀더이며, 생성 스크립트가 호출 전에 절대 경로로 교체합니다.

```json
"commands": [
    {
        "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
        "target": "server", "active": true
    },
    {
        "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate",
        "target": "client", "active": true
    }
]
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

자주 사용하는 스위치:

- `--dataTarget json | bin` —— 데이터 파일 저장 형식으로, `json`은 가독성이 좋고 `bin`은 크기가 작습니다.
- `--codeTarget cs-simple-json | cs-dotnet-json | cs-bin` —— 생성되는 C# 로드 코드 스타일로, 클라이언트는 `cs-simple-json`, 서버는 `cs-dotnet-json`, 바이너리 활성화 시 `cs-bin`을 사용합니다.
- `--validationFailAsError true` —— 검증 실패 시 단순 경고만 하지 않고 바로 오류로 처리합니다.
- `--xargs outputDataDir=...` / `--xargs outputCodeDir=...` —— 데이터와 코드 산출물의 출력 디렉터리이며, `%SERVER_PATH%`, `%UNITY_ASSETS_PATH%` 플레이스홀더를 지원합니다.

## 일반적인 변형

### 그룹 추가(예: 다국어 서브 클라이언트)

`groups` 배열에 항목을 하나 추가하고, 테이블 헤더의 `__xxx__` 열에서 해당 테이블에 새 그룹 이름을 지정하는 것도 잊지 마세요.

```json
{ "names": ["c"], "default": true },
{ "names": ["s"], "default": true },
{ "names": ["c_cn"], "default": true }
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

### JSON과 바이너리 산출물 전환

해당 command의 `--dataTarget json --codeTarget cs-simple-json`(또는 `cs-dotnet-json`)을 `--dataTarget bin --codeTarget cs-bin`으로 교체하고, `active`를 `true`로 설정합니다.

### 출력 디렉터리 변경

`commands[].command`의 `outputDataDir` / `outputCodeDir`를 직접 수정하면 됩니다. 스크립트의 통일된 경로를 재사용하려면 `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` 플레이스홀더를 그대로 유지하면 됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `gen-*.bat` 실행 시 `ToolPath not found` 오류 발생 | `toolPath` 상대 경로가 잘못되었거나, `Tools/Luban.dll`이 저장소에 없음 | 기본값 `/../Config/Tools/Luban.dll`을 유지하세요; `Tools/` 디렉터리를 이동하지 마세요 |
| 생성된 코드에서 네임스페이스를 찾을 수 없음 | `targets[].topModule` 철자 오류, 클라이언트/서버의 `topModule`은 서로 달라야 함 | 클라이언트는 `Hotfix.Config`, 서버는 `GameFrameX.Config`이며, 자신의 네임스페이스로 변경하세요 |
| 클라이언트 프로젝트에서 코드가 생성되지 않음 | 클라이언트 target의 `groups`에 해당 테이블이 속한 그룹이 포함되지 않음 | `targets[client].groups`에 해당 그룹 이름을 추가하거나, 테이블의 `__xxx__` 열을 조정하세요 |
| `commands`의 `active`가 모두 `false`임 | 모든 명령이 비활성화됨 | 실행해야 하는 항목을 `true`로 변경하세요 |
| 플레이스홀더 `%UNITY_ASSETS_PATH%`가 교체되지 않음 | `gen-*.bat` / `gen-*.sh`를 통하지 않고 `Luban.exe`를 직접 더블클릭함 | 저장소에 포함된 생성 스크립트를 통해 실행하세요. 스크립트가 플레이스홀더 교체를 담당합니다 |

## 배경(선택)

`luban.conf`의 schema는 Luban 도구 체인이 규정하며, 필드 의미는 Luban 공식과 일치합니다. 이 저장소는 `toolPath`, `UNITY_ASSETS_PATH`, `SERVER_PATH`, `commands[].active` 네 가지 필드를 추가로 확장하여, GameFrameX 워크플로에서 `gen-*.bat` / `gen-*.sh`를 통해 생성 명령 실행과 플레이스홀더 교체를 일괄 처리할 수 있도록 합니다.
