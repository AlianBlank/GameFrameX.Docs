# IL2CPP 發佈後類型遺失或出現錯誤時的處理方式

IL2CPP 在建置過程中會執行 Managed Code Stripping(受控程式碼裁剪)。LitJson 依賴反射來產生讀取器/寫入器，一旦被裁剪，在 IL2CPP 執行階段可能會遇到 `MissingMethodException`、`InvalidCastException`,或反序列化時得到空物件。本頁提供快速診斷與修復步驟。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| `MissingMethodException: ... LitJson ...` | IL2CPP 連結器裁剪掉了 LitJson 內部方法 | 加入 `link.xml` 並掛載 `LitJsonCroppingHelper` |
| 反序列化結果的欄位全為 `null`/預設值 | `JsonData`/`JsonMapper` 的匯出器被裁剪 | 加入 `link.xml` |
| `JsonMapper.ToObject<T>` 回傳物件但屬性遺失 | 自訂 T 的欄位/屬性被裁剪 | 在 `link.xml` 中依組件保留 T 的類型 |
| `Type.GetType("...")` 回傳 `null` | IL2CPP 不支援以字串名稱查找未保留的類型 | 使用泛型 `ToObject<T>()` 或在 `link.xml` 中保留對應類型 |
| 註冊自訂 Importer/Exporter 時出現 `InvalidCastException` | 委派的目標方法被裁剪 | 在 `link.xml` 中保留你的組件 |

## 修復步驟

### 1. 加入 link.xml 進行宣告式保留

在 Unity 專案的 `Assets` 任一子目錄下建立 `link.xml`(通常放在 `Assets/link.xml`),內容如下，以明確保留 LitJson 組件：

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
</linker>
```

建置時，LitJson 相關類型將依據此檔案被跳過裁剪。這是第一道防線。

來源:[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md#L40-L50)

### 2. 掛載 LitJsonCroppingHelper 進行執行階段防裁剪

此套件隨附 `LitJsonCroppingHelper`,會在 `Start()` 中透過 `typeof(...)` 明確引用所有 LitJson 公開類型，作為第二層保障：

```csharp
[Preserve]
public class LitJsonCroppingHelper : UnityEngine.MonoBehaviour
{
    [Preserve]
    public void Start()
    {
        _ = typeof(ArrayMetadata);
        _ = typeof(Condition);
        _ = typeof(ExporterFunc);
        _ = typeof(ExporterFunc<>);
        _ = typeof(JsonIgnoreAttribute);
        _ = typeof(JsonPropertyAttribute);
        _ = typeof(FsmContext);
        _ = typeof(IJsonWrapper);
        _ = typeof(ImporterFunc);
        _ = typeof(ImporterFunc<,>);
        _ = typeof(JsonData);
        _ = typeof(JsonException);
        _ = typeof(JsonMapper);
        _ = typeof(JsonMockWrapper);
        _ = typeof(JsonReader);
        _ = typeof(JsonToken);
        _ = typeof(JsonType);
        _ = typeof(JsonWriter);
        _ = typeof(Lexer);
        _ = typeof(ObjectMetadata);
        _ = typeof(OrderedDictionaryEnumerator);
        _ = typeof(ParserToken);
        _ = typeof(PropertyMetadata);
        _ = typeof(UnityTypeBindings);
        _ = typeof(WrapperFactory);
        _ = typeof(WriterContext);
    }
}
```

將此元件掛載到場景中**最早**啟動的 GameObject(例如 `Bootstrap`),以確保 `Start()` 在任何 `JsonMapper` 呼叫之前執行。

來源:[LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L12-L52)

### 3. 保留自訂資料類型

如果你使用 `JsonMapper.ToObject<MyData>("...")` 反序列化自訂類別，且 `MyData` 位於另一個組件中，則需要在 `link.xml` 中加入保留項目：

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
  <assembly fullname="MyGame.Models" preserve="all"/>
</linker>
```

或者只保留特定類型，以縮小套件體積：

```xml
<linker>
  <assembly fullname="MyGame.Models">
    <type fullname="MyGame.Models.PlayerData" preserve="all"/>
    <type fullname="MyGame.Models.InventoryItem" preserve="all"/>
  </assembly>
</linker>
```

### 4. 避免依賴以字串名稱載入類型

若類型未透過 `link.xml` 保留，`Type.GetType("MyGame.Models.PlayerData, MyGame.Models")` 在 IL2CPP 下會回傳 `null`。建議：

- 使用泛型 `JsonMapper.ToObject<PlayerData>(json)`;
- 或在 `link.xml` 中明確保留該類型；
- 或在透過 `JsonMapper.RegisterImporter<string, Type>(s => Type.GetType(s))` 註冊自訂 importer 時，確保目標類型已被保留。

來源:[UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L47)

### 5. 檢查 Unity 建置設定

1. `Player Settings > Managed Stripping Level`:在 IL2CPP 下，保持為 `Low` 或更低；若使用 `High`/自訂規則，務必搭配 `link.xml`。
2. `Player Settings > Strip Engine Code`:取消勾選，或在 `link.xml` 中將其納入例外。
3. 清除 Library/ScriptAssemblies 並重新打包，避免快取掩蓋設定變更。

## 驗證

1. 以 IL2CPP 打包後，啟動遊戲並觸發 `JsonMapper.ToJson` 與 `JsonMapper.ToObject` 的完整往返流程，確認沒有 `MissingMethodException`。
2. 在 Xcode/Android 日誌中搜尋關鍵字 `LitJson` 與 `MissingMethod`,確認沒有錯誤。
3. 反序列化結果物件的欄位值與原始 JSON 一致(沒有 null/預設值)。
4. 暫時將 `Managed Stripping Level` 設為 `High` 並重新測試，驗證 `link.xml` 與 `LitJsonCroppingHelper` 在最激進的裁剪下仍能正常運作。
