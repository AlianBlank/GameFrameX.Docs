# 旧版の Show/Load から Play(option) への移行方法

旧版の `Show(success, fail, onShowResult, customData)` および `Load(success, fail, customData)` の3引数呼び出しと、`Action<bool> onShowResult` のみを渡す `Play` を、`AdvertisementPlayOption` を用いた `Play(AdvertisementPlayOption option)` エントリポイントに統一して置き換えます。旧メソッドには `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]` が付与されており、コンパイル時に `CS0618` 警告が発生します。今後のバージョンで削除されるため、使用は避けてください。

## 前提条件

- `GameFrameX.Advertisement.Runtime` 名前空間を参照し、`IAdvertisementManager` またはコンポーネント `AdvertisementComponent` を取得できること。
- 現在使用している広告チャネルの `BaseAdvertisementManager` サブクラスを把握していること(新 API は抽象メソッドのため、対応するチャネル実装でオーバーライドが必要)。

## 操作手順

1. **`AdvertisementPlayOption` インスタンスを新規作成**し、元々引数に散らばっていた成功/失敗/表示結果コールバックと `customData` をすべてそのフィールドに格納します。

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   var option = new AdvertisementPlayOption
   {
       OnSuccess     = msg => Debug.Log($"成功:{msg}"),
       OnFail        = err => Debug.LogError($"失敗:{err}"),
       OnShowResult  = watched => Debug.Log($"完全視聴したか:{watched}"),
       customData    = "level=1",
   };
   ```

   Source: [AdvertisementPlayOption.cs#L36-L85](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L36-L85)

2. **旧エントリポイントを `Play(option)` に置き換えます**。`AdvertisementComponent` または `BaseAdvertisementManager` 上で呼び出し、完全に統一されたシグネチャになります:

   ```csharp
   GameFrameX.Advertisement.Runtime.AdvertisementComponent.Instance.Play(option);
   ```

   Source: [AdvertisementComponent.cs#L215-L219](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L215-L219)

   ```csharp
   public abstract void Play(AdvertisementPlayOption option);
   ```

   Source: [BaseAdvertisementManager.cs#L210-L211](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L210-L211)

3. **マッピング表に従って旧フィールドを `option` に移植**し、旧コードにコールバックの取りこぼしがないか確認します:

   | 旧 API 引数 / フィールド | 新 `AdvertisementPlayOption` フィールド |
   |--------------------|-----------------------------------|
   | `Show(success, fail, onShowResult, customData)` の `success` | `OnSuccess`(`Action<string>`) |
   | `Show(...)` の `fail` | `OnFail`(`Action<string>`) |
   | `Show(...)` / `Play(playResult, customData)` の `onShowResult` / `playResult` | `OnShowResult`(`Action<bool>`) |
   | `Show(...)` / `Load(...)` / `Play(...)` の `customData` | `customData`(`string`) |
   | サーバー側報酬検証に必要な拡張データ | `extraData`(`Load` 段階でのみ渡され、読み込み後の設定は無効) |

4. **旧呼び出し箇所を削除**します。プロジェクト内にまだ `Show(success, fail, onShowResult)` や `Load(success, fail)` の使い方が残っている場合は、一つずつ `Play(option)` に置き換えてください。コンパイラが `CS0618` 警告で通知してくれます。

## よくあるバリエーション

- **「完全視聴したか」のみが知りたい場合**:`OnShowResult` のみを設定し、他のコールバックは `null` のままにします。

  ```csharp
  var option = new AdvertisementPlayOption
  {
      OnShowResult = watched => GiveReward(watched),
  };
  ```

- **サーバー側報酬検証に拡張データを渡したい場合**:`extraData` を使用します。`Load` 段階でのみ有効である点に注意してください。

  ```csharp
  option.extraData = "user_id=42";
  ```

- **カスタムチャネルで `customData` が必要な場合**:`option.customData` に直接代入します。これは旧版の同名引数と同等です。

## よくある間違い

- **`extraData` を `customData` として使う**:`extraData` は `Load` 段階でサーバー側報酬検証にのみ渡され、広告再生時には有効になりません。ビジネス向けのコールバックには `customData` を使用してください。
- **旧 `Show`/`Load` を引き続き使用する**:これらはすでに `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]` が付与されており、使用すると警告が出るだけですが、今後のバージョンで削除されます。また、旧 `Show` の内部では `#pragma warning disable CS0618` で転送しているため、移行後にまとめて削除できます。
- **`option` のフィールドを未代入のまま `Play` を呼び出す**:特定のコールバック(例:`OnFail`)を空のままにすると、失敗時に上位層へ通知されず、トラブルシューティング時に「広告がトリガーされていない」と誤判定しやすくなります。
- **`Load` の後に `extraData` を変更する**:ドキュメントには「読み込み後の設定は無効」と明記されています。サーバー側で拡張情報を検証する必要がある場合は、必ず `Play(option)` の呼び出し前に設定してください。

## 背景(オプション)

移行後、すべてのチャネルマネージャーは抽象エントリポイント `Play(AdvertisementPlayOption option)` を1つだけオーバーライドすればよく、コールバックと拡張データを一箇所で集中管理できます。旧 `Show`/`Load`/`Play(Action<bool>, string)` はすべて旧メソッドとしてマークされ、コンポーネント層から新メソッドへ転送されます。これにより、API サーフェスを収束させながら呼び出し側への影響をゼロに保ちます。
