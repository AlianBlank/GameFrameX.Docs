# 표현식 트리/경로 결합 확장 사용 방법

`ExpressionExtension`은 `Expression<Func<T, bool>>` 대상의 체이닝 결합 메서드 그룹을 제공하여, 여러 개의 독립적으로 작성된 술어 표현식을 새로운 표현식으로 안전하게 조합할 수 있게 해줍니다. `Expression.AndAlso` / `ParameterExpression` 등의 보일러플레이트 코드를 직접 작성할 필요 없이, 쿼리 조건의 동적 결합, 필터 파이프라인 등의 시나리오에서 자주 사용됩니다.

## 사전 조건

- 프로젝트에서 `GameFrameX.Foundation.Extensions`를 참조합니다.
- 파일 상단에 `using System.Linq.Expressions;` 및 `using GameFrameX.Foundation.Extensions;`를 추가합니다.
- 대상 프레임워크가 `Expression<Func<T, bool>>`을 지원합니다(표준 .NET이면 충분).

## 작업 단계

### 1. `And`로 두 조건 결합

좌우 양쪽 표현식이 모두 충족되어야 할 때 `And`를 사용합니다(내부적으로 `Expression.AndAlso`를 사용하며 단락 평가(short-circuit evaluation)를 지원합니다).

```csharp
using System.Linq.Expressions;
using GameFrameX.Foundation.Extensions;

Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.And(expr2);

bool ok1 = combined.Compile()("testing"); // true
bool ok2 = combined.Compile()("test");    // false
```

Source: [ExpressionExtension.cs#L57-L67](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L57-L67)

### 2. `Or`로 두 조건 결합

어느 한쪽 표현식이라도 충족되면 될 때 `Or`를 사용합니다(내부적으로 `Expression.OrElse`를 사용하며 단락 평가를 지원합니다).

```csharp
Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.Or(expr2);
bool ok = combined.Compile()("test"); // true: StartsWith("test")에 해당
```

Source: [ExpressionExtension.cs#L114-L125](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L114-L125)

### 3. `AndIf` / `OrIf`로 스위치에 따라 결합

불리언 스위치에 따라 실제 결합 여부를 결정해야 할 때는 조건부 버전을 사용합니다. 조건이 `false`이면 좌측 표현식을 그대로 반환하며, 접근자나 재작성 로직을 거치지 않습니다.

```csharp
Expression<Func<string, bool>> left  = s => s.Length > 5;
Expression<Func<string, bool>> right = s => s.StartsWith("test");

bool enableFilter = true;
var withFilter = left.AndIf(() => enableFilter, right);

enableFilter = false;
var withoutFilter = left.AndIf(() => enableFilter, right); // left와 동일
```

Source: [ExpressionExtension.cs#L83-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L83-L100)

### 4. `Not`으로 부정

```csharp
Expression<Func<int, bool>> expr = x => x > 5;
var neg = expr.Not(); // x => !(x > 5), 즉 x <= 5와 동일
```

Source: [ExpressionExtension.cs#L171-L178](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L171-L178)

### 5. 다중 조건 체이닝 결합

반환값이 여전히 `Expression<Func<T, bool>>`이므로 연속해서 호출할 수 있습니다.

```csharp
Expression<Func<string, bool>> baseExpr = s => s != null;
var query = baseExpr
    .And(s => s.Length > 0)
    .And(s => s.Contains("foo"))
    .OrIf(() => AllowShort, s => s.Length <= 2);
```

## 일반적인 변형

- **술어 문자열 + LINQ 제공자**: 결합이 완료된 후 `Compile()`을 호출하여 `Func<T, bool>`을 얻어 직접 필터링할 수 있습니다. EF Core 등 ORM과 함께 사용하는 경우 `combined`를 `Where(...)`에 직접 전달하면 SQL로 변환됩니다.
- **빈 컬렉션 단락**: 외곽에서 `IEnumerable.Any()` 등으로 먼저 비어 있는지 확인한 후 `And` / `Or`을 호출할 수 있습니다.
- **다중 매개변수 람다**: `CustomExpressionVisitor`는 다중 매개변수 람다에 대해 첫 번째 매개변수만 교체하고 나머지는 그대로 유지합니다.

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| `ArgumentNullException`(매개변수명 `leftExpression` / `rightExpression` / `condition` / `expr`) | 표현식 또는 조건 대리자 중 하나가 `null`임 | 호출 전에 표현식에 대해 null 검사를 수행하거나, 외곽에서 항상 `true`를 반환하는 조건 대리자를 제공 |
| 결합 후 컴파일 실패, "매개변수 불일치" 오류 발생 | 전달된 좌우 표현식의 타입이 일치하지 않음(예: `Func<string,bool>`과 `Func<int,bool>`) | 두 표현식이 동일한 제네릭 매개변수 `T`를 사용하도록 보장 |
| 결합 결과에 단락(short-circuit) 동작이 없음 | 본 확장이 `And`/`Or`를 사용한다고 잘못 인식 | 본 확장의 `And`/`Or`는 내부적으로 `AndAlso`/`OrElse`를 사용하므로 자연스럽게 단락되며 추가 처리가 필요 없음 |
| 다중 매개변수 람다 결합 후 동작이 비정상 | 첫 번째 매개변수만 교체되고 나머지는 유지됨 | 술어를 하나의 매개변수만 받는 람다로 작성하거나, 직접 표현식을 재작성 |

## 배경(선택 사항)

`And` / `Or` / `AndIf` / `OrIf`는 모두 내부적으로 `CustomExpressionVisitor` 클래스(`ExpressionVisitor`에서 상속)를 통해 좌우 두 표현식의 각 `ParameterExpression`를 새로 생성된 통일된 매개변수로 교체한 다음, `Expression.Lambda`로 다시 조립합니다. 이렇게 하면 좌우 서브트리의 원래 구조를 유지하면서도 새 표현식이 단 하나의 매개변수만 갖도록 보장하여, 체이닝 결합과 ORM 간 번역 변환이 용이해집니다.
