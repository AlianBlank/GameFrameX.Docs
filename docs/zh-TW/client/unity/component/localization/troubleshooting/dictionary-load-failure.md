# 字典載入失敗（LoadDictionaryFailureEventArgs）怎麼辦

當當地語系化字典資源載入失敗時，框架會引發 `LoadDictionaryFailureEventArgs` 事件。該事件攜帶三個欄位——`DictionaryAssetName`（失敗的字典資源名稱）、`ErrorMessage`（錯誤訊息）、`UserData`（發起載入時傳入的自訂資料）——疑難排解時先讀取這三個欄位，即可定位是「資源名稱設定錯誤」還是「資源缺失/載入異常」。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `ErrorMessage` 指示資源不存在/找不到 | 字典資源未產生或未打包進資源包 | 請見下方【修復步驟 1】核對資源是否可載入 |
| `DictionaryAssetName` 為空或不符預期 | 呼叫載入時傳入了錯誤的資源名稱 | 請見下方【修復步驟 2】回查呼叫處傳入的資源名稱 |
| `UserData` 為空，無法區分是哪一次載入失敗 | 發起載入時未攜帶自訂資料 | 請見下方【修復步驟 3】在載入呼叫處傳入標記物件 |
| 事件從未觸發、也沒有成功事件 | 事件未訂閱，或載入流程未啟動 | 請見下方【修復步驟 4】確認訂閱與載入呼叫 |

欄位說明（取自事件類別的真實定義）：

| 屬性 | 型別 | 建構時預設值 | 說明 |
|------|------|--------------|------|
| `DictionaryAssetName` | `string` | `null` | 載入失敗的字典資源名稱 |
| `ErrorMessage` | `string` | `null` | 錯誤訊息（具體文字由底層載入流程傳回） |
| `UserData` | `object` | `null` | 使用者自訂資料 |

## 修復步驟

### 1. 用 ErrorMessage 確認資源是否可載入

在事件回呼中輸出三個欄位，先看 `ErrorMessage` 的具體內容；若提示資源不存在，表示 `DictionaryAssetName` 對應的字典資源未產生或未隨包建置，請去檢查該資源的產生/打包設定，而不是改程式碼。

```csharp
private void OnLoadDictionaryFailure(object sender, GameEventArgs e)
{
    var args = (LoadDictionaryFailureEventArgs)e;
    UnityEngine.Debug.LogError(
        $"字典載入失敗： {args.DictionaryAssetName}, 錯誤： {args.ErrorMessage}");
}
```

Source: [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L36-L58)

說明：訂閱/取消訂閱介面由 GameFrameX 事件元件提供，訂閱時以 `LoadDictionaryFailureEventArgs.EventId` 作為事件識別；回呼參數型別為 `GameEventArgs`，強制轉型為本事件型別後讀取欄位（事件基底類別與 `using GameFrameX.Event.Runtime;` 均來自該事件類別檔案中的真實參考）。

### 2. 回查 DictionaryAssetName 的來源

`DictionaryAssetName` 的值等於發起載入時傳入的 `dataAssetName`（見下方 `Create` Factory 方法），因此出現「名稱不對」時，應回到呼叫載入的那一行程式碼，核對傳入的資源名稱字串（注意大小寫、路徑前綴與後綴）。

```csharp
public static LoadDictionaryFailureEventArgs Create(string dataAssetName, string errorMessage, object userData)
{
    LoadDictionaryFailureEventArgs loadDictionaryFailureEventArgs = ReferencePool.Acquire<LoadDictionaryFailureEventArgs>();
    loadDictionaryFailureEventArgs.DictionaryAssetName = dataAssetName;
    loadDictionaryFailureEventArgs.ErrorMessage = errorMessage;
    loadDictionaryFailureEventArgs.UserData = userData;
    return loadDictionaryFailureEventArgs;
}
```

Source: [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L87-L102)

### 3. 用 UserData 區分多次載入

如果同一幀有多個字典正在載入，僅靠 `DictionaryAssetName` 可能不足以定位呼叫點。在每次發起載入時傳入一個可識別的 `userData`（如呼叫端物件或列舉標記），失敗事件中原樣帶回，即可確定是哪一次呼叫失敗。

### 4. 確認事件確實被訂閱、載入確實被發起

若既沒有失敗事件也沒有成功事件（`LoadDictionarySuccessEventArgs`），先確認：

1. 事件監聽已訂閱（以 `LoadDictionaryFailureEventArgs.EventId` 為識別）；
2. 字典載入呼叫確實執行到（可在呼叫前後加上日誌）；
3. 使用的組件未被裁剪——本元件透過 `GameFrameXLocalizationCroppingHelper` 明確保留型別，若你自訂了裁剪設定，需確保 `LoadDictionaryFailureEventArgs` 不被剔除：

```csharp
_ = typeof(ILocalizationManager);
_ = typeof(LoadDictionaryFailureEventArgs);
_ = typeof(LoadDictionarySuccessEventArgs);
```

## 驗證

- 重新觸發字典載入後，失敗回呼不再進入，或主控台不再輸出你列印的失敗日誌；
- 對應的字典資源出現 `LoadDictionarySuccessEventArgs`（成功事件，欄位為 `DictionaryAssetName`、`Duration`、`UserData`），表示載入流程已復原；
- 再次讀取 `LocalizationComponent` 上的當地語系化文案，能取得字典中的項目。

關於載入成功/進度事件與當地語系化元件的整體用法，請見儲存庫中文說明 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.zh-CN.md#L311-L313)。

## 背景

該事件繼承自 `GameEventArgs`，執行個體從 `ReferencePool` 參考池取得（`ReferencePool.Acquire<LoadDictionaryFailureEventArgs>()`），並在 `Clear()` 中把三個欄位重設為 `null` 後歸還池中。因此回呼中不要快取事件物件本身，只應讀取或複製欄位值，事件分派後物件會被重複使用。
