# HttpClientRequestException のスローとレスポンス例外の対処法

`GameFrameX.Foundation.Http.Extension` を通じて開始された HTTP リクエストが、成功以外のステータスコード、ネットワーク層の例外、または JSON の逆シリアル化に失敗した場合、フレームワークは `HttpClientRequestException` をスローします。このページでは、その識別方法、原因の特定方法、適切な修正方法の選び方について説明します。

## クイック診断

| 症状(例外メッセージ) | 原因 | 修正 |
|---|---|---|
| `HTTP request failed with status code {code} ({StatusCode}) for {uri}.` | サーバーが 4xx / 5xx レスポンスを返し、呼び出し側が `EnsureSuccessStatusCode()` を呼び出したか、内部のステータスコードチェックがトリガーされた | [修正手順 - ステータスコード失敗](#修正手順-ステータスコード失敗) を参照 |
| `HTTP request failed for {method} {uri}.` | 下層から `HttpRequestException`(DNS、接続、タイムアウト、TLS などのネットワーク層エラー)がスローされ、リトライ範囲外であるか、一般的な `Exception` が `HttpRequestException / JsonException` 分岐に該当する | [修正手順 - ネットワーク層 / 一般例外](#修正手順-ネットワーク層--一般例外) を参照 |
| `HTTP JSON response could not be deserialized for {uri}.` | レスポンスボディが有効な JSON ではないか、対象の型と一致しない | [修正手順 - JSON 逆シリアル化失敗](#修正手順-json-逆シリアル化失敗) を参照 |

例外型自体は `HttpRequestException` を継承しており、以下の診断フィールドが追加で提供されます:

| フィールド | 型 | 説明 |
|---|---|---|
| `StatusCode` | `HttpStatusCode?` | サーバーから返された HTTP ステータスコード(レスポンスがある場合) |
| `RequestUri` | `Uri?` | エラーが発生したリクエスト URI |
| `ResponseSummary` | `string?` | レスポンスボディの要約(失敗時に設定される) |
| `RawException` | `Exception?` | この例外をトリガーした元の例外(ある場合) |

```csharp
public sealed class HttpClientRequestException : HttpRequestException
{
    public HttpClientRequestException(
        string message,
        HttpStatusCode? statusCode,
        Uri? requestUri,
        string? responseSummary,
        Exception? rawException = null)
        : base(message, rawException, statusCode)
    {
        StatusCode = statusCode;
        RequestUri = requestUri;
        ResponseSummary = responseSummary;
        RawException = rawException;
    }

}
```

## 修正手順

### 修正手順:ステータスコード失敗

1. 呼び出し側で `try / catch` を使用して `HttpClientRequestException` をキャッチし、`StatusCode` で具体的な失敗タイプ(401、404、500 など)を判定します。

```csharp
try
{
    var response = await httpClient.SendJsonAsync<MyDto>(request, options);
    response.EnsureSuccessStatusCode();
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    // リソースが存在しないため、ビジネスフォールバック分岐に進む
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.Unauthorized)
{
    // トークンを更新するか、再ログインを促す
}
```

2. リクエストが本来フォールトトレラントであるべき場合(例: GET リストで 404 の場合に空を返すことを許可する)は、`EnsureSuccessStatusCode()` を呼び出さず、直接 `IsSuccessStatusCode` と `Body` を読んで自分で処理してください。

```csharp
public HttpClientResponse EnsureSuccessStatusCode()
{
    if (IsSuccessStatusCode)
    {
        return this;
    }

    throw new HttpClientRequestException(
        $"HTTP request failed with status code {(int)StatusCode} ({StatusCode}) for {RequestUri}.",
        StatusCode,
        RequestUri,
        Body);
}
```

Source: [HttpClientResponse.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientResponse.cs#L80-L92)

3. リトライ設定を確認してください。フレームワークはデフォルトで `HttpRequestException` に対して有限回数のリトライを行います。`attempt <= options.Retry.MaxRetries` の間は `HttpClientRequestException` をスローせず、バックオフによるリトライがトリガーされます。

```csharp
catch (HttpRequestException exception) when (allowRetry && attempt <= options.Retry.MaxRetries)
{
    await DelayBeforeRetryAsync(method, request.RequestUri, attempt, null, exception, options, effectiveToken);
    return (null, true);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L358-L362)

ステータスコードの失敗が発生したがリトライ回数が使い切られている場合、`CreateStatusException` でステータス付きの例外がスローされます:

```csharp
private static HttpClientRequestException CreateStatusException(
    HttpStatusCode statusCode,
    Uri? requestUri,
    string responseText)
{
    return new HttpClientRequestException(
        $"HTTP request failed with status code {(int)statusCode} ({statusCode}) for {requestUri}.",
        statusCode,
        requestUri,
        Summarize(responseText));
}
```

### 修正手順:ネットワーク層 / 一般例外

1. ネットワーク層(DNS、TCP、TLS、タイムアウト)は通常、下層の `HttpRequestException` として現れます。リトライ回数が使い切られた場合や、`HttpRequestException / JsonException` 以外の `Exception` が発生した場合は、以下のようにラップされます:

```csharp
catch (Exception exception) when (exception is HttpRequestException or JsonException)
{
    throw new HttpClientRequestException(
        $"HTTP request failed for {method} {request.RequestUri}.",
        null,
        request.RequestUri,
        null,
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L363-L371)

2. 調査の観点:
   - まず `ex.RawException?.Message` を確認してください。通常、そこに下層の真の原因が記載されています(例: `The requested name is valid, but no data of the requested type was found`)。
   - タイムアウトの場合は、`HttpClientRequestOptions` のタイムアウト閾値を上げるか、`Retry.MaxRetries / Retry.Delay` を調整してリトライをより十分に行ってください。
   - TLS / 証明書エラーの場合は、対象アドレスの証明書チェーンとサーバーの SNI 設定を確認してください。
   - カスタムの `HttpMessageHandler` チェーン下で他の例外がスローされた場合、フレームワークは `is HttpRequestException or JsonException` の場合のみラップします。それ以外の例外はそのまま伝播するため、別途キャッチする必要があります。

### 修正手順:JSON 逆シリアル化失敗

1. レスポンスボディが有効な JSON ではない場合や、フィールドの型が対象の型と一致しない場合は、以下がスローされます:

```csharp
catch (JsonException exception)
{
    throw new HttpClientRequestException(
        $"HTTP JSON response could not be deserialized for {requestUri}.",
        null,
        requestUri,
        Summarize(responseText),
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L430-L438)

2. 調査の観点:
   - `ex.RawException` から元の `JsonException` を取得し、具体的なフィールドパスと行番号を特定してください。
   - `ex.ResponseSummary` を確認し、レスポンスボディの要約から、サーバーが返したフォーマット(`application/json` vs `text/html`)を確認してください。
   - 必要に応じて `HttpClientRequestOptions.JsonSerializerOptions` で `PropertyNameCaseInsensitive`、`NumberHandling`、`AllowTrailingCommas` などを設定し、逆シリアル化をより寛容にしてください。

## 検証

1. 失敗するリクエスト(存在しないアドレスを指す、または 500 を返すエンドポイント)を意図的に作成し、`HttpClientRequestException` がキャッチされ、`StatusCode` / `RequestUri` / `ResponseSummary` の 3 つのフィールド値が期待どおりであることを確認します。
2. 逆シリアル化失敗のシナリオでは、`RawException` を `JsonException` に変換し、その `Path` が失敗の原因となったフィールドを指していることを確認します。
3. `Retry.MaxRetries > 0` の設定を有効にした状態で、対象インターフェースに一時的に 5xx を返させ、ログにバックオフによるリトライ記録が出現し、最終的にビジネス要件どおりに `HttpClientRequestException` がスローされることを確認します。
