# 依赖子包未安装导致编译失败怎么办

当 `com.gameframex.unity.entry` 引用了某个子包（例如 Network、UI、FairyGUI、Asset、Procedure 等）但该子包未安装或版本不一致时,Unity 控制台会报 `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Xxx.Runtime' which is not in the project` 或 `The type or namespace name 'X' could not be found`,编译因此中断。本页给出根据报错定位缺失子包并恢复编译的步骤。

## 快速诊断

| 症状(控制台原文) | 原因 | 修复 |
|---|---|---|
| `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Network.Runtime' which is not in the project.` | 项目中未安装 `com.gameframex.unity.network` 子包 | 通过 Package Manager 安装对应依赖 |
| `The type or namespace name 'GameApp' could not be found` | `com.gameframex.unity.entry` 未安装或被移除 | 重新安装入口包 |
| 编译错误信息中提到 `GameFrameX.UI.Runtime`、`GameFrameX.Asset.Runtime`、`GameFrameX.FSM.Runtime` 等,但项目里没有这些程序集 | 缺少对应的可选子包(可选依赖未安装) | 评估是否需要该子系统,不需要则卸载对它的引用,需要则安装 |
| 安装了子包但仍报 `assembly references ... which is not in the project` | 子包版本与 `package.json` 中声明的版本范围不匹配 | 升级/降级子包到依赖表中要求的版本 |
| 仅启用某个子系统(例如广告、登录)时报找不到类型 | 未启用对应的 `versionDefines` 宏,代码已被 `#if` 排除但脚本仍被加载 | 确认子包安装后宏会自动注入;若仍未生效,重启 Unity 并刷新 Assets |

### 2. 安装缺失的子包

打开 Unity → `Window` → `Package Manager`,点击左上角 `+` → `Add package by name...`,按上表中的 `name` 与 `version` 填入并安装。例如补齐 Network:

1. 打开 Package Manager。
2. 选择 `Add package by name`。
3. 名称:`com.gameframex.unity.network`,版本:`2.6.10`。
4. 点击 `Add`,等待 Unity 解析并下载。

安装完成后 Package Manager 会自动写入 `Packages/manifest.json`,并注入对应的 `versionDefines` 宏。

### 3. 版本不匹配时的处理

`package.json` 中写死的依赖版本是经测试兼容的组合。如果你手动锁定了更低/更高版本,`asmdef` 引用的程序集可能找不到。

- 查看 `Packages/manifest.json` 或 `Packages/packages-lock.json` 中对应包的版本。
- 与 `package.json` 中的 `dependencies` 字段对比,统一为目标版本。
- 如果是 Git URL 引用(例如 `com.gameframex.unity.network`),在 URL 后追加 `#2.6.10` 锁定标签。

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/package.json#L22-L42)

### 4. 不需要该子系统时的精简做法

如果你不需要某个可选子系统,可以避免安装它,同时让 `GameFrameX.Entry.Runtime` 不去引用对应程序集。具体做法是在你自己的 asmdef 中不再通过 `GameFrameX.Entry` 触发该路径,或者删除对该子系统的代码引用。`GameFrameX.Entry.Runtime.asmdef` 会随对应子包是否存在自动通过 `versionDefines` 启用/禁用代码分支。

```text
示例:你只用 Procedure + UI + Network,只需安装
  com.gameframex.unity.procedure@1.4.0
  com.gameframex.unity.ui@2.11.0
  com.gameframex.unity.network@2.6.10
其他可选子包(广告、登录、统计、XLua 等)不必安装,代码会通过宏自动剔除。
```

### 5. 安装后仍报错的清理步骤

1. 关闭 Unity。
2. 删除项目根目录下的 `Library/ScriptAssemblies/` 与 `Library/PlayerScriptAssemblies/`。
3. 删除 `Library/PackageCache/` 下与缺失子包相关的残留缓存。
4. 重新打开 Unity,等待首次导入完成。

完成后控制台不应再有缺失程序集的提示。

## 验证

- Unity Console 中 `Assembly ... references ... which is not in the project` 类报错清零。
- `Window` → `Package Manager` 中可以看到所有 `dependencies` 中声明的子包均处于 `Installed` 状态。
- 在任意脚本中能成功 `using GameFrameX.Entry.Runtime;` 并访问 `GameApp.Procedure`、`GameApp.Network` 等静态访问器。

## 背景(可选)

入口包 `com.gameframex.unity.entry` 通过 `GameFrameX.Entry.Runtime.asmdef` 集中声明所有子系统程序集的引用,并在 `versionDefines` 中按子包存在与否注入 `ENABLE_GAME_FRAME_X_*` 宏,使未安装子包的代码段被 `#if` 排除,从而实现按需编译。`package.json` 的 `dependencies` 字段是版本对齐的唯一真值来源——编译报"找不到程序集"时,优先核对这里的版本而非手动修改 asmdef。
