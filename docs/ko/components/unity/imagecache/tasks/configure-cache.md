# 캐시 경로 및 용량 구성 방법

`ImageCacheConfig`를 통해 디스크 캐시 경로, 최대 용량 및 만료 일수를 설정할 수 있으며, 컴포넌트 `Awake` 시 Inspector의 구성이 `IImageCacheManager.Config`로 동기화됩니다. 경로가 지정되지 않은 경우 기본적으로 `Application.persistentDataPath` 아래의 `cache/images/`가 사용됩니다.

## 사전 조건

- `ImageCacheComponent`가 씬 진입 GameObject에 부착되어 있어야 합니다.
- `GameFrameworkEntry`에 `ImageCacheManager`가 등록되어 있어야 합니다 (컴포넌트 `Awake` 내부에서 `componentType` 리플렉션을 통해 생성됨).

## 작업 단계

1. 씬에서 `ImageCacheComponent`가 부착된 GameObject를 선택하면 Inspector에 **Image Cache Config** 섹션이 표시되며, 여기에는 `Cache Path`, `Max Disk Size (Bytes)`, `Expire Days` 세 개의 필드가 있습니다.

2. 캐시 디렉토리 경로 `Cache Path`를 설정합니다. 비워둘 경우 `PathHelper.AppHotfixResPath + "/cache/images/"`가 기본 디렉토리로 사용됩니다. 사용자 정의 경로를 사용하는 경우 프로세스에 해당 디렉토리에 대한 읽기/쓰기 권한이 있어야 하며, 디렉토리가 존재하지 않으면 관리자가 필요에 따라 자동으로 생성합니다.

```csharp
[SerializeField]
private string m_CachePath;
public string CachePath { get; set; }
```

Source: [ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L12-L44)

3. 디스크 최대 용량 `MaxDiskSize`(바이트)를 설정합니다. `0`은 제한 없음을 의미합니다.

```csharp

public long MaxDiskSize { get; set; }
```

Source: [ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L18-L53)

4. 만료 일수 `ExpireDays`를 설정합니다. `0`은 만료되지 않음을 의미합니다.

```csharp

public int ExpireDays { get; set; }
```

Source: [ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L24-L62)

5. 런타임 구성 동기화: 컴포넌트 `Awake`는 직렬화된 필드를 관리자로 동기화하므로 수동으로 호출할 필요가 없습니다.

```csharp
_imageCacheManager.Config.CachePath = string.IsNullOrEmpty(m_Config.CachePath)
    ? PathHelper.AppHotfixResPath + "/cache/images/"
    : m_Config.CachePath;
_imageCacheManager.Config.MaxDiskSize = m_Config.MaxDiskSize;
_imageCacheManager.Config.ExpireDays = m_Config.ExpireDays;
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L49-L53)

## 일반적인 변형

- **런타임 구성 수정**: `ImageCacheComponent.Config`를 통해 구성 객체에 접근하여 `CachePath`, `MaxDiskSize`, `ExpireDays`에 직접 값을 할당할 수 있으며, 이후의 `LoadImageAsync` 호출은 새로운 값을 사용합니다.
- **WebGL 플랫폼**: 캐시는 브라우저에 의해 관리되므로 `CachePath`/`MaxDiskSize`/`ExpireDays`는 적용되지 않습니다. `IsCached`는 항상 `false`를 반환하며, `RemoveCache` 및 `ClearCache`를 호출하면 `ImageCache: ... is not supported on WebGL.` 경고가 출력됩니다.
- **비 WebGL 플랫폼**: 캐시 파일은 URL의 MD5를 파일명으로 사용하고 확장자는 `.png`입니다. 경로 형식은 `CachePath/<md5>.png`입니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 시작 로그 `ImageCache manager is invalid.` | `IImageCacheManager` 구현이 등록되지 않았거나 `componentType`이 잘못 설정됨 | Inspector에서 `Component Type`을 확인하여 `ImageCacheManager`로 해석될 수 있도록 함 |
| 시작 로그 `Download manager is invalid.(비 WebGL)` | `IDownloadManager`가 등록되지 않음 | `GameFrameworkEntry`에 다운로드 모듈이 로드되어 있는지 확인 |
| `RemoveCache` / `ClearCache` 호출 시 `not supported on WebGL.` 경고 출력 | WebGL은 디스크 캐시를 사용하지 않음 | 브라우저 캐시를 사용하거나 `UnityWebRequest`를 직접 호출하여 처리 |
| 사용자 정의 `CachePath` 설정 후 권한 오류 발생 | 경로에 쓸 수 없음 | `Application.persistentDataPath` 하위 디렉토리를 사용하거나 디렉토리에 쓸 수 있는지 확인 |

## 배경 정보 (선택 사항)

`ImageCacheConfig`는 `[Serializable]` 클래스이며 `ImageCacheComponent.m_Config`에 의해 직렬화됩니다. `ComponentTypeComponentInspector`를 통해 Inspector에 노출됩니다. `MaxDiskSize` 및 `ExpireDays`는 구성 항목으로만 보존되며, 현재 `ImageCacheManager`는 로드 과정에서 이 두 항목에 따라 정리를 수행하지 않습니다. 정리는 비즈니스 측에서 직접 `ClearCache`를 호출하여 수행해야 합니다.
