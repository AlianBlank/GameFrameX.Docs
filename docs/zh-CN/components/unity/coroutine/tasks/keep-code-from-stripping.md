# 如何在打包裁剪中保住协程组件

把 `GameFrameXCoroutineCroppingHelper` 挂到一个 Unity 场景里的 GameObject 上,即可让 `CoroutineComponent` 在 IL2CPP / Managed Stripping 开启的打包环境下不被裁剪掉,协程 API 仍可正常调用。

## 前置条件

- 已安装本协程包(`com.gameframex.unity.coroutine`)
- 目标平台启用托管代码裁剪(Managed Stripping 或 IL2CPP),或使用了 link.xml / Preserve 机制的项目
- 已有一个常驻场景(GameObject 在打包后不会销毁)

## 操作步骤

1. 在任意一个常驻场景(例如启动场景)里新建一个 GameObject,例如命名为 `GameFrameXCoroutineCroppingHelper`。
2. 为该 GameObject 添加 `GameFrameXCoroutineCroppingHelper` 组件。

   ```csharp
   using GameFrameX.Coroutine.Runtime;
   ```
   Source: [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

3. 不用挂载到 `DontDestroyOnLoad` —— 该组件的 `Start` 在任意场景里执行一次,都足以让裁剪器保留 `CoroutineComponent` 的类型引用。
4. 重新打包,运行游戏后即可照常使用 `GameEntry.GetComponent<CoroutineComponent>().StartCoroutine(...)`。

## 常见变体

- **不使用 CroppingHelper**:可以在项目中加一个 `link.xml`,把 `GameFrameX.Coroutine.Runtime` 命名空间整体保留。
- **避免任何额外 GameObject**:在任意已有组件的脚本里写 `private void Start() { _ = typeof(GameFrameX.Coroutine.Runtime.CoroutineComponent); }`,并给该类加上 `[Preserve]`,效果等同。
- **AOT 平台(IL2CPP + iOS/Android)**:强烈建议挂上 CroppingHelper,否则 `StartCoroutine` / `StopCoroutine` 的 `new` 重写在某些裁剪级别下会找不到对应方法。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 打包后调用 `StartCoroutine` 报 `MissingMethodException` | `CoroutineComponent` 的 `new` 重载方法被裁剪器移除 | 挂上 `GameFrameXCoroutineCroppingHelper`,或补 `link.xml` 保留命名空间 |
| 运行时找不到 `GameFrameXCoroutineCroppingHelper` 类型 | 该脚本在 AOT 下被一起裁掉了 | 不要在 link.xml 中误把 `GameFrameX.Coroutine.Runtime.*` 排除;CroppingHelper 自身已带 `[Preserve]` |
| 添加组件后场景里多了一个空物体 | 仅用于触发 `Start` 引用,没有视觉/逻辑副作用 | 可隐藏 `MeshRenderer`,或把它合并到已有的常驻单例对象上 |

## 背景(可选)

`GameFrameXCoroutineCroppingHelper` 内部仅有一段 `Start`,引用了 `typeof(CoroutineComponent)`。由于类与方法都标记了 `[Preserve]`(来自 `UnityEngine.Scripting`),Unity 的 Stripping 阶段会保留这条引用链,从而保住 `CoroutineComponent` 及其 `new` 隐藏的方法。
