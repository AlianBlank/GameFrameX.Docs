# 플레이어 펫(Pet) 모듈 구현

플레이어 펫(Pet) 모듈은 컴포넌트 형태로 플레이어 Actor에 마운트되어, 펫의 런타임 상태를 저장하고 펫 관련 이벤트에 응답하는 역할을 합니다. 본 절에서는 빈 모듈에서 시작하여 등록 가능하고 확장 가능한 펫 컴포넌트 스켈레톤을 완성해 나갑니다.

## 사전 조건

- 플레이어 Actor(`ActorType = GlobalConst.ActorTypePlayer`)가 이미 생성되어 있습니다.
- `GameFrameX.Core.Abstractions.Attribute`, `GameFrameX.Utility.Setting`, `GameFrameX.Core.Components`가 참조되어 있습니다.
- 프레임워크의 `StateComponent<TState>`와 `StateComponentAgent<TComponent, TState>`의 이중 계층 구조를 이해하고 있습니다(Apps 계층에서 정의와 상태를 담당하고, Hotfix 계층에서 로직을 작성합니다).

using GameFrameX.Apps.Player.Pet.Entity;

public class PetComponentAgent : StateComponentAgent<PetComponent, PetState>
{
    // 여기에 펫 관련 비즈니스를 작성합니다(예: GotNewPet 이벤트 응답)
}

출처: [PetComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Pet/PetComponentAgent.cs#L1-L7)

4. 서버를 시작하면 프레임워크가 `ActorType`에 따라 각 플레이어 Actor에 `PetComponent`와 `PetComponentAgent`를 자동으로 등록하며, 펫 상태는 `PetState.Cache` 라이프사이클에 진입합니다.

## 일반적인 변형

- **펫 획득 이벤트 응답**: `PetComponentAgent`에 `EventId.GotNewPet`을 처리하는 private 비동기 메서드를 추가하고, 중첩 `EventListener<T>` 클래스를 통해 이벤트를 구독합니다([PetComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Pet/PetComponentAgent.cs#L8-L28)의 주석 예시 참조).
- **컴포넌트 간 호출**: `PetComponentAgent` 내에서 `ActorManager.GetComponentAgent<ServerComponentAgent>()`를 통해 다른 컴포넌트 에이전트를 가져옵니다. 예를 들어 월드 레벨을 읽어 펫 속성을 결정합니다.
- **펫 데이터 필드**: `PetState`에 직렬화 가능한 속성(예: 펫 ID, 레벨, 경험치)을 직접 추가하면 프레임워크가 자동으로 저장 및 캐싱에 참여합니다.

## 자주 발생하는 오류

- **Agent 네임스페이스 불일치**: `PetComponentAgent`가 현재 위치한 네임스페이스는 `GameFrameX.Hotfix.Logic.Role.Pet`이고, Apps 계층은 `GameFrameX.Apps.Player.Pet.*`입니다. 예시를 복사하여 붙여넣을 때는 반드시 각자의 네임스페이스를 유지하여 프레임워크 리플렉션 실패를 방지해야 합니다.
- **`[ComponentType]` 누락**: `PetComponent`에 `ActorTypePlayer`가 지정되어 있지 않으면 플레이어 Actor에 마운트되지 않으며, 런타임에는 펫 기능이 완전히 동작하지 않는 것으로 나타납니다.
- **Apps 계층에 비즈니스 로직 작성**: Apps 계층은 패키징 시 메인 어셈블리에 포함되어 핫업데이트가 불가능합니다. 모든 가변 로직은 반드시 Hotfix 계층의 `PetComponentAgent`에 위치해야 합니다.

## 배경(선택 사항)

`PetComponent`는 프레임워크의 "컴포넌트 + 상태 + 에이전트" 3종 세트를 따릅니다. `StateComponent<TState>`는 상태 소속과 라이프사이클만 선언하고, 실제 비즈니스는 `StateComponentAgent<TComponent, TState>`에서 실행되며, 둘은 제네릭 파라미터로 짝을 이룹니다. `[ComponentType]`은 해당 컴포넌트가 프레임워크에 의해 어떤 종류의 Actor에 등록될지를 결정합니다.
