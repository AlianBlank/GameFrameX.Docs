# Invalid token 파싱 예외가 발생하면怎么办

LitJSON이 JSON 문자열을 파싱할 때 인식할 수 없는 어휘 단위(`ParserToken`)를 만나면 메시지가 `"Invalid token '{0}' in input string"` 인 `JsonException` 을 발생시킵니다. 이 페이지는 이러한 예외의 근본 원인을 빠르게 찾아 수정하는 데 도움을 줍니다.

## 빠른 진단

| 증상(예외 메시지) | 원인 | 해결 방법 |
|----------------|------|------|
| `Invalid token 'X' in input string`(token이 단일 문자) | JSON에 예상치 못한 문자가 포함됨 (이스케이프되지 않은 따옴표, 주석, 후행 쉼표 등) | 잘못된 문자를 삭제하거나 이스케이프 처리하여 JSON 사양을 준수 |
| `Invalid token 'X' in input string`(token이 숫자) | 숫자 리터럴이 잘못 작성됨 (예: `1.`, `0x1A`, 불필요한 기호) | 숫자 형식을 수정하고, 10진수만 사용하며, 선택적으로 소수점과 지수를 포함 |
| `Invalid token 'True' / 'False' / 'Null'` | bool 또는 null이 PascalCase로 작성됨 (예: `True`) | JSON에서 요구하는 전체 소문자 `true` / `false` / `null` 로 변경 |
| `Invalid token 'CharSeq'` | 문자열에 잘못된 문자가 포함됨 (짝이 맞지 않는 이스케이프 문자, 제어 문자 등) | 문자열 이스케이프 확인, 일반적인合法 이스케이프는 `\" \\ \/ \b \f \n \r \t \uXXXX` |
| `Invalid token 'End'` 또는 파싱 조기 종료 | JSON이 중간에 잘림 — 괄호/따옴표가 닫히지 않음 | 편집기에서 누락된 `{` `}` `[` `]` `"` 를補完 |

예외 메시지 템플릿은 다음과 같이 정의되며, 중괄호 안은 Lexer 단계의 `ParserToken` 열거형 값입니다:

```csharp
// Runtime/JsonException.cs
internal JsonException(ParserToken token) :
    base(string.Format(
             "Invalid token '{0}' in input string", token))
{
}
```

Source: [JsonException.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonException.cs#L51-L55)

## 수정 단계

### 1. 오류 발생 문자 위치 찾기

예외의 token(단일 문자 경우)을 원본 JSON 문자열과 대조하면 첫 번째 잘못된 문자를 찾을 수 있습니다. LitJSON의 `JsonReader`는 왼쪽에서 오른쪽으로 스캔하여 인식할 수 없는 첫 번째 문자를 만나면 오류를 발생시킵니다.

```csharp
// Runtime/JsonReader.cs
TableAddCol(parse_table, ParserToken.ArrayPrime, '[',
            (int)ParserToken.Value,
            (int)ParserToken.ValueRest,
            ']');
```

Source: [JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs#L266-L274)

### 2. 일반적인 잘못된 문자 수정

다음 작성 방법은 표준 JSON에서 모두非法이며, LitJSON은 즉시 `Invalid token` 을 발생시킵니다:

- 작은따옴표 문자열 `'foo'` —— 큰따옴표 `"foo"` 로 변경해야 함
- 주석 `// xxx` 또는 `/* xxx */` —— JSON은 주석을 지원하지 않으므로 제거 필요
- 후행 쉼표 `{ "a": 1, }` —— 쉼표 뒤에 요소가 있어야 함
- PascalCase bool/null `True` / `False` / `Null` —— 반드시 `true` / `false` / `null` 이어야 함
- 이스케이프되지 않은 제어 문자 또는裸 줄바꿈 —— 문자열 내부의 줄바꿈은 `\n` 으로 이스케이프 필요

### 3. 일반적인 잘못된 숫자 수정

`ParserToken.Number` 에 의해 트리거되는 `Invalid token` 은 보통 숫자 형식 문제입니다. 합법적인 숫자는 반드시 10진수이며, 선택적으로 소수점과 지수를 포함할 수 있습니다:

- 合법: `0`, `-1`, `3.14`, `-2.5e10`, `1.0E+3`
- 非法: `1.`(소수점 뒤 숫자 없음), `01`(선행 0), `0x1A`(16진수), `NaN`, `Infinity`, `+1`(불필요한 기호), `1,000`(천 단위 쉼표)

### 4. 최소 재현 케이스로 검증

수정 후, 최소 실행 가능한 스니펫으로 JSON이 올바르게 파싱되는지 검증하세요:

```csharp
using GameFrameX.LitJSON.Runtime;

string json = "{\"name\":\"litjson\",\"v\":1}";
JsonData data = JsonMapper.ToObject(json);
Debug.Log(data["name"]); // 출력: litjson
Debug.Log(data["v"]);    // 출력: 1
```

여전히 `Invalid token` 이 발생하면, 예외 메시지의 token 값과 원본 문자열 일부(오류 발생 위치 전후若干 문자 포함)를上游 데이터 소스 제공자에게 피드백하세요.

## 검증

1. Unity Editor의 Console에서 수정된 JSON 파싱 코드를 실행하여 `JsonException` 이 더 이상 발생하지 않는지 확인합니다.
2. 온라인 JSON 검증 도구(예: jsonlint.com)로 입력 문자열을 검증하여 "Valid JSON" 결과를 얻습니다.
3. JSON이 네트워크 또는 외부 파일에서 오는 경우, try/catch를 추가하고 `e.Message`를 출력하여 구체적인 오류 위치를 파악합니다:

```csharp
try
{
    var data = JsonMapper.ToObject(rawJson);
}
catch (JsonException e)
{
    Debug.LogError($"파싱 실패:{e.Message}");
}
```
