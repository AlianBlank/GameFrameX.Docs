# 实现玩家属性(Attribute)模块

玩家属性(Attribute)模块提供基于「最终值槽 + 派生槽」的统一计算公式,通过修改基础值、加法、第一层百分比、最终加法、最终百分比五个槽位来得到最终属性。本页说明如何在业务中初始化、修改并读取玩家属性。

## 前置条件

- 已熟悉 `GameFrameX` 的组件 / Agent 模式,了解 `PlayerAttributeComponent` 与 `PlayerAttributeComponentAgent` 的关系。
- 已了解事件总线,知道如何注册 `AttributeChangedEventArgs` 的监听器。

## 属性槽位与计算公式

每个最终属性(`AttributeType.Life` 等)对应五个数值槽,偏移由 `AttributeSlotKind` 定义,百分比基数 `PercentBase = 10000` 表示 100%。

| 槽位 | 偏移 | 用途 |
|------|------|------|
| Final | 0 | 最终值槽,编号等于主编号 |
| Base | 10000 | 基础值槽,来自配置、等级或初始化 |
| Add | 20000 | 加法修正 |
| Pct | 30000 | 第一层百分比修正(基数为 10000) |
| FinalAdd | 40000 | 最终加法修正 |
| FinalPct | 50000 | 最终百分比修正(基数为 10000) |

重算公式由 `AttributeCore.CalculateFinal` 提供:

```csharp
public static long CalculateFinal(long baseValue, long addValue, long pctValue, long finalAddValue, long finalPctValue)
{
    checked
    {
        var firstLayer = (baseValue + addValue) * (PercentBase + pctValue) / PercentBase;
        return (firstLayer + finalAddValue) * (PercentBase + finalPctValue) / PercentBase;
    }
}
```

## 操作步骤

### 1. 在玩家实体上挂载属性组件

`PlayerAttributeComponent` 已使用 `[ComponentType(GlobalConst.ActorTypePlayer)]` 标注,玩家实体创建时自动挂载,无需手动注册。

```csharp
[ComponentType(GlobalConst.ActorTypePlayer)]
public sealed class PlayerAttributeComponent : StateComponent<PlayerAttributeState>
{
}
```

Source: [PlayerAttributeComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/Component/PlayerAttributeComponent.cs#L38-L40)

### 2. 写入并重算最终属性

通过 `PlayerAttributeComponentAgent` 的变更入口修改派生槽后,使用 `AttributeCore.RecalculateFinal` 重新计算最终值,并写入对应 Final 槽。`TryGetFinalAttribute` 会从派生槽反推所属的最终属性。

```csharp
var state = await agent.GetState();
var attributes = state.Attributes;

// 修改 Life 的 Base 槽
var baseKey = AttributeCore.GetSlotAttribute(AttributeType.Life, AttributeSlotKind.Base);
attributes[baseKey] = 100;

// 重新计算 Life 最终值
attributes[AttributeType.Life] = AttributeCore.RecalculateFinal(attributes, AttributeType.Life);
```

Source: [AttributeCore.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/AttributeCore.cs#L46-L109)

### 3. 监听属性变更事件

订阅 `AttributeChangedEventArgs` 以响应属性变化(由 `PlayerAttributeChangedEventListener` 等具体监听器处理)。事件携带变更的属性编号与新值。

```csharp
public class AttributeChangedEventArgs : EventArgs
{
    public AttributeType AttributeType { get; }
    public long OldValue { get; }
    public long NewValue { get; }
}
```

Source: [AttributeChangedEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/EventData/AttributeChangedEventArgs.cs)

### 4. 使用初始默认值

玩家首次登录时,通过 `PlayerInitialAttributeDefaults` 提供的初始化数据填充 Base 槽,再触发首次重算,得到初始最终属性。

## 常见变体

- **百分比加成**:装备 / Buff 只改 `Pct` 或 `FinalPct` 槽,不需要直接计算最终值;玩家下线时移除对应修正即可。
- **跨实体属性聚合**:若需要把多个来源(玩家 + 宠物 + 装备)合并计算,可分别在各自维护一份属性字典,在最终读取处统一调用 `AttributeCore.RecalculateFinal`。
- **批量重算**:多个最终属性同时变化时,遍历已知最终属性(`AttributeCore.IsFinalAttribute` 返回 true 的 9 个枚举值)逐个调用 `RecalculateFinal` 即可。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `ArgumentOutOfRangeException: 必须传入已知最终属性。` | 把非最终属性或派生槽直接传给 `RecalculateFinal` | 只对 `IsFinalAttribute` 返回 true 的属性调用重算 |
| `ArgumentOutOfRangeException: 必须传入已知属性数值槽。` | `AttributeSlotKind` 传入了未定义的自定义值 | 限定使用 6 个内置枚举值 |
| 最终属性始终为 0 | 派生槽缺失但未触发重算 | 修改任一派生槽后,必须调用 `RecalculateFinal` 并回写 `Final` 槽 |
| 百分比加成结果偏差 100 倍 | 把 `0.5` 直接写入 Pct 槽 | Pct / FinalPct 槽使用基数为 `10000`,50% 写入 `5000` |

## 背景(可选)

属性编号设计上以 10000 / 20000 / 30000 等固定偏移区分槽位,使得任意派生槽都能通过 `value % PercentBase` 反推所属最终属性,便于统一处理变更事件。`PercentBase = 10000` 既避免浮点精度问题,也方便策划按「万分比」配置数值。
