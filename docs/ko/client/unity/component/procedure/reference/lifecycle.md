# 수명 주기 콜백

`ProcedureBase`는 `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`를 상속하며, 각 프로시저(Procedure)는 유한 상태 머신(FSM) 규약에 따라 생성, 진입, 폴링, 이탈, 소멸 단계에서 각각 하나의 가상 메서드를 트리거합니다. 이것이 바로 프로시저의 **수명 주기 콜백**입니다. 서브클래스에서 재정의하여 비즈니스 로직을 연결할 수 있습니다.

## 콜백 빠른 참조

| 콜백 | 시그니처 | 트리거 시점 |
|------|------|----------|
| `OnInit` | `protected override void OnInit(IFsm<IProcedureManager> procedureOwner)` | 상태 머신 초기화 시 (각 프로시저 인스턴스당 한 번) |
| `OnEnter` | `protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)` | 본 프로시저로 전환 시 |
| `OnUpdate` | `protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 매 프레임 폴링 (논리 경과 / 실제 경과) |
| `OnFixedUpdate` | `protected override void OnFixedUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 고정 스텝 폴링 |
| `OnLeave` | `protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)` | 본 프로시저를 떠날 때; `isShutdown=true`은 상태 머신 종료로 인한 이탈을 나타냅니다 |
| `OnDestroy` | `protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)` | 상태 머신 소멸 시 (각 프로시저 인스턴스당 한 번) |

모든 메서드의 기본 구현은 단순히 `base.Xxx(...)`만 호출하므로, 재정의할 수 있지만 **기본 동작 유지를 위해 `base` 호출을 유지해야 합니다**.

## 매개변수 설명

| 매개변수 | 의미 |
|------|------|
| `procedureOwner` | 본 프로시저를 보유한 상태 머신 객체, 타입은 `IFsm<IProcedureManager>`. 이를 통해 프로시저 관리자(`procedureOwner.Owner`)에 접근하거나 프로시저 전환 등을 수행할 수 있습니다. |
| `elapseSeconds` | 시간 스케일의 영향을 받는 논리 경과 시간(초). |
| `realElapseSeconds` | 시간 스케일의 영향을 받지 않는 실제 경과 시간(초). |
| `isShutdown` | `OnLeave`에서 `true`인 경우, 이번 이탈은 정상적인 전환이 아닌 상태 머신 종료로 인한 것임을 나타냅니다. |

## 트리거 시점 (관리자 API 대응)

| 관리자 작업 | 트리거되는 콜백 (해당 프로시저 인스턴스에서) |
|------------|----------------------------|
| `Initialize(fsmManager, procedures...)` | 전달된 각 프로시저가 차례로 `OnInit` 호출됨 |
| `StartProcedure<T>()` / `StartProcedure(Type)` | 대상 프로시저의 `OnEnter`; 이미 현재 프로시저가 있으면 먼저 기존 프로시저에 `OnLeave(isShutdown=false)` 호출 |
| 상태 머신 하트비트 (매 프레임) | 현재 프로시저의 `OnUpdate` 및 `OnFixedUpdate` |
| `DestroyProcedures()` | 현재 프로시저의 `OnLeave(isShutdown=true)`, 이후 등록된 모든 프로시저가 차례로 `OnDestroy` 호출됨 |
| `ReinitializeProcedures(procedures...)` | 먼저 `DestroyProcedures()`를 호출한 다음 새 프로시저 배열로 다시 `Initialize`를 호출하는 것과 동일 |

## 최소 사용법

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

public class MyProcedure : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // 본 프로시저에 필요한 리소스, 캐시 등을 초기화합니다
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 본 프로시저 진입 시 UI 시작, 이벤트 등록 등
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner,
        float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        // 매 프레임 비즈니스 로직 (조건 충족 시 procedureOwner를 통해 프로시저 전환)
    }

    protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)
    {
        base.OnLeave(procedureOwner, isShutdown);
        // UI 정리, 이벤트 등록 해제
        // isShutdown == true인 경우 상태 머신이 전체 종료되었음을 나타냅니다
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // 본 프로시저가 보유한 리소스를 해제합니다
    }
}
```

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 재정의 후 `base.OnXxx(...)` 호출을 잊어버려 상태 머신 내부 상태가 비정상적으로 됨 | 기본 클래스에서 상태 통계, 타이머 등의 암묵적 동작을 유지할 수 있음 | 재정의 끝에 항상 `base.OnXxx(...)` 호출 |
| `OnInit`에서 `StartProcedure`를 호출하여 프로시저 전환 | `Initialize` 단계에서는 아직 프로시저가 `OnEnter`되지 않았으므로, 미리 전환하면 상태 머신이 일관성 없는 상태가 됨 | `OnEnter` 또는 이후 `OnUpdate`에서 전환 |
| `OnDestroy`에서 `procedureOwner`의 다른 프로시저에 접근 | 소멸 단계에서는 상태 머신 내부 상태가 회수 중임 | 프로시저 간 참조는 `OnEnter`에서 캐시하고 `OnLeave`에서 정리하도록 변경 |
| `OnUpdate`에서 일회성 초기화 수행 | `OnUpdate`는 매 프레임 호출되므로 반복 트리거됨 | 일회성 로직은 `OnInit` 또는 `OnEnter`에 배치 |
| `OnEnter`가 매 `Initialize` 시 호출되길 기대함 | `OnInit`이 초기화 시 유일하게 호출되는 메서드이고, `OnEnter`는 상태 전환 시에만 호출됨 | 시작 로직은 `OnEnter`에, 데이터 준비는 `OnInit`에 배치 |
