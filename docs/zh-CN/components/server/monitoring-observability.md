# 如何启用监控指标与健康检查

完成本页配置后,服务将自动暴露 `/health`(完整健康状态)和 `/alive`(进程存活性)两个 HTTP 端点,内置 MongoDB 健康检查与 ASP.NET Core 默认健康检查,并通过 `AddServiceDefaults` 一键接入整个服务。

## 前置条件

- .NET 8+ ASP.NET Core 工程(本框架默认使用 .NET 9)
- 已在 `Program.cs` 中调用 `WebApplication.CreateBuilder()` 与 `builder.Build()`
- 服务内引用了 `GameFrameX.AppHost.ServiceDefaults` 包(框架默认引用)

## 操作步骤

### 1. 在 Program.cs 中注册服务默认值

`AddServiceDefaults` 会同时配置 OpenTelemetry、日志、指标、HTTP 韧性等基础设施,健康检查也在这一步一并开启。

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.AddServiceDefaults();
```

Source: [GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346)

### 2. 暴露健康检查端点

`MapDefaultEndpoints` 会注册 `/health` 与 `/alive` 两个端点。`/health` 要求所有检查通过,`/alive` 只要求存活标签为 `live` 的检查通过。

```csharp
var app = builder.Build();
app.MapDefaultEndpoints();
app.Run();
```

Source: [GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435)

### 3. 验证默认端点

启动服务后访问:

| 端点 | 用途 | 成功响应 |
|------|------|---------|
| `/health` | 完整健康检查(含依赖) | `Healthy` |
| `/alive` | 进程存活性 | `Healthy` |

如果只希望进程存活性探针,可使用 `/alive`,它不依赖 MongoDB 等下游组件。

## 启用 MongoDB 健康检查

框架内置了 `MongoDbHealthCheck`,只要在 DI 容器中注册 `IMongoClient`,再调用 `AddMongoDbHealthCheck` 即可自动接入到 `/health` 端点。

### 1. 注册 MongoDB 客户端

```csharp
builder.Services.AddSingleton<IMongoClient>(sp =>
    new MongoClient(builder.Configuration.GetConnectionString("MongoDb")));
```

### 2. 注册健康检查

```csharp
builder.Services.AddHealthChecks()
    .AddMongoDbHealthCheck();
```

Source: [GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99)

### 3. 检查行为说明

`MongoDbHealthCheck` 内部通过 `ListDatabaseNamesAsync` 探测连接,并使用连续失败计数避免抖动:

| 连续失败次数 | 返回状态 | 含义 |
|--------------|---------|------|
| 0(有数据库列表) | `Healthy` | 连接正常,失败计数清零 |
| 1 ~ 4 | `Degraded` | 暂时不可用,可继续重试 |
| ≥ 5 | `Unhealthy` | 连续失败超阈值,标记为不健康 |

## 常见变体

- **只暴露存活探针**:某些 Kubernetes 部署只需要 `/alive`,可省略对 MongoDB 等下游检查的注册,直接使用 `AddServiceDefaults` 默认的存活检查。
- **添加自定义检查**:实现 `IHealthCheck`,再调用 `.AddCheck("my-check", new MyHealthCheck())` 挂载到现有 `IHealthChecksBuilder`。
- **外部健康探测**:将 `/health` 作为负载均衡器或 APM 的探测 URL。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 访问 `/health` 返回 404 | 未调用 `app.MapDefaultEndpoints()` | 在 `app.Run()` 前加入 `app.MapDefaultEndpoints();` |
| `/health` 一直返回 `Unhealthy` | MongoDB 连接串错误或服务未启动 | 检查 `ConnectionStrings:MongoDb` 配置并确认 MongoDB 可达 |
| MongoDB 偶尔抖动导致状态频繁切换 | 默认阈值(连续 5 次失败)过严 | 在 `appsettings.json` 调整 `MongoDbHealthCheckOptions` 或改用 `Degraded` 容忍 |
| 只想看存活不看依赖 | 未区分 `/alive` 与 `/health` | 使用 `/alive` 端点,或在自定义检查上加 `tags: new[] { "live" }` |

## 背景

健康检查基于 `Microsoft.Extensions.Diagnostics.HealthChecks`,框架通过 `AddServiceDefaults` 默认注册了一个 `self` 检查(标记为 `live`),并暴露两条端点路径,用于在容器编排系统中区分"进程还活着"与"可以接流量"。

关于遥测与 OpenTelemetry 的整体接入,见《服务默认值与遥测》。
