# Quick Start: Load and Display Your First UI

This page walks you through loading a FairyGUI-published resource package into Unity and displaying your first UI in the scene. Only three real APIs are needed at the core: `UIPackage.AddPackage` handles loading the resource package, the `UIPanel` in the scene calls `CreateUI()` at runtime to complete instantiation and display, and `UIPackage.RemovePackage` handles unloading.

## Prerequisites

- The Unity project has this package installed (the repository's `Runtime/` directory is the FairyGUI runtime source code).
- A UI package has been published in the FairyGUI editor, containing at least one component (this guide uses the package name `Main` and the description file path `UI/Main` as an example).
- The published output has been imported into the Unity project.

## Steps

1. Load the resource package in your startup code. The argument passed in is the package description file path:

   ```csharp
   // "UI/Main" is the package description file path
   UIPackage.AddPackage("UI/Main");
   ```

   This call corresponds to `UIPackage AddPackage(string descFilePath)`; see the full definition at [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L298).

2. Create a new GameObject in the scene and attach the `UIPanel` component to it, then set its package name and component name (matching what was used at publish time).

3. Click Play to enter run mode. `UIPanel` will call `CreateUI()` at this point to complete creation and display; see the method definition at [UIPanel.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPanel.cs#L231). When loading a component, the runtime first checks whether the target package is already loaded to avoid duplicate loading:

   ```csharp
   if (!string.IsNullOrEmpty(packagePath) && UIPackage.GetByName(packageName) == null)
       UIPackage.AddPackage(packagePath);
   ```

   Source: [UIPainter.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPainter.cs#L64-L65) (`UIPainter` and `UIPanel` expose the same `CreateUI()`, see [UIPainter.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPainter.cs#L159))

4. Unload the resource package when the UI is no longer needed:

   ```csharp
   // The argument can be either the package id or the package name
   UIPackage.RemovePackage("Main");
   ```

   This corresponds to `void RemovePackage(string packageIdOrName)`, see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L458).

## Verification

After entering Play mode, the Game view should display the component content you created in the FairyGUI editor. If it does not appear, first check that the package name/component name filled in during step 2 exactly match what was used at publish time, then check that the description file path from step 1 is correct.

## Common Variants

**Asynchronously loading the resource package**: If you don't want loading to cause frame drops, use the async API instead, and continue creating the UI in the callback once loading completes:

```csharp
// Obtain the UIPackage in the callback once loading completes
UIPackage.AddPackageAsync("UI/Main", pkg => { /* Package loaded; you can proceed to create the UI */ });
```

This corresponds to `void AddPackageAsync(string assetPath, Action<UIPackage> callback)`, see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L381). Asynchronous object creation is assisted by [AsyncCreationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/AsyncCreationHelper.cs#L9-L11).

**Loading from an AssetBundle**: When the output is packed into an AssetBundle, use the `AddPackage(AssetBundle bundle)` overload, which internally forwards to `AddPackage(bundle, bundle, null)`, see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L220); if description assets and image assets are split into separate bundles, use `AddPackage(AssetBundle desc, AssetBundle res)` instead, see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L229-L231).

## Common Mistakes

- **Calling `AddPackage` repeatedly**: `UIPanel`/`UIPainter` check `UIPackage.GetByName(packageName) == null` before creating the UI to determine whether the package is already loaded; when writing your own startup code, you should perform the same check to avoid loading the same package twice.
- **Package name or component name mismatch with publish settings**: This causes the package or component to not be found and the UI to not display; go back to the FairyGUI editor and verify your publish settings.
- **Calling `CreateUI()` outside run mode**: `UIPanel`/`UIPainter` only create automatically when `Application.isPlaying` is true (see [UIPainter.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPainter.cs#L90-L91)); editor preview relies on their built-in editor extensions, so do not trigger it manually in Awake or editor scripts.
