# 如何加载子资源、全部资源与原生文件

本页介绍 `AssetComponent` 提供的三类特殊资源加载方式:同一资源文件下的多个子资源(如 SpriteAtlas 中的子 Sprite)、资源包内的全部资源,以及不经 Unity 解析的原生文件(如 .txt、.json、.lua)。所有 API 都通过 `GameFrameX.Asset.AssetComponent` 暴露,内部转发到 `_assetManager`。

## 前置条件

- 已完成 [AssetComponent 初始化](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Initialization.cs) 并能拿到 `AssetComponent` 实例。
- 待加载的资源已在 YooAsset / GameFrameX 资产管线中打包并发布,否则会得到失败句柄。

## 操作步骤

### 1. 加载子资源(`LoadSubAssetsAsync` / `LoadSubAssetSync`)

子资源指一个资源文件内嵌的多个 Unity 对象,典型场景是图集中的 Sprite 或 FBX 中多 Mesh。`SubAssetsHandle` 一次返回整组子资源,通过 `AssetObject` / `GetSubAssetObject` 取出具体成员。

```csharp
using System;
using System.Threading.Tasks;
using GameFrameX.Asset;
using UnityEngine;

public class SubAssetLoader
{
    // 按 AssetInfo 加载
    public async Task<SubAssetsHandle> LoadByInfoAsync(AssetInfo assetInfo)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadSubAssetsAsync(assetInfo);
    }

    // 按 path + Type 加载
    public async Task<SubAssetsHandle> LoadByPathAndTypeAsync(string path, Type type)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadSubAssetsAsync(path, type);
    }

    // 泛型版本:加载 SpriteAtlas 中的全部 Sprite
    public async Task<SubAssetsHandle> LoadSpritesAsync(string path)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadSubAssetsAsync<Sprite>(path);
    }

    // 同步版本
    public SubAssetsHandle LoadSync(string path)
    {
        return GameFrameX.Asset.AssetComponent.Instance.LoadSubAssetSync<Sprite>(path);
    }
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L122-L216)

### 2. 加载全部资源(`LoadAllAssetsAsync` / `LoadAllAssetsSync`)

加载资源包(或目录)内的所有同类型资源,返回 `AllAssetsHandle`。适用于一次性把所有关卡配置、Prefab 列表读入的场景。

```csharp
using System;
using System.Threading.Tasks;
using GameFrameX.Asset;
using UnityEngine;

public class AllAssetLoader
{
    // 泛型版本:加载全部 Prefab
    public async Task<AllAssetsHandle> LoadPrefabsAsync(string path)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadAllAssetsAsync<GameObject>(path);
    }

    // 非泛型版本
    public async Task<AllAssetsHandle> LoadByTypeAsync(string path, Type type)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadAllAssetsAsync(path, type);
    }

    // 加载资源包内所有资源对象
    public async Task<AllAssetsHandle> LoadAllAsync(string path)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadAllAssetsAsync(path);
    }
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L329-L371)

### 3. 加载原生文件(`LoadRawFileAsync` / `LoadRawFileSync`)

读取不经 Unity 序列化的原始字节,适用于文本(`.txt`、`.json`、`.lua`、`.csv`)、自定义二进制格式等。返回 `RawFileHandle`,通过 `RawFile` 属性拿到字节或文本。

```csharp
using System.Threading.Tasks;
using GameFrameX.Asset;

public class RawFileLoader
{
    public async Task<RawFileHandle> LoadAsync(string path)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadRawFileAsync(path);
    }

    public async Task<RawFileHandle> LoadByInfoAsync(AssetInfo assetInfo)
    {
        return await GameFrameX.Asset.AssetComponent.Instance.LoadRawFileAsync(assetInfo);
    }

    public RawFileHandle LoadSync(string path)
    {
        return GameFrameX.Asset.AssetComponent.Instance.LoadRawFileSync(path);
    }
}
```

## 常见变体

| 场景 | 推荐 API |
|------|---------|
| SpriteAtlas 中的多个 Sprite | `LoadSubAssetsAsync<Sprite>(path)` |
| 同一路径下不同类型筛选 | `LoadSubAssetsAsync(path, type)` |
| 关卡目录里全部 Prefab | `LoadAllAssetsAsync<GameObject>(path)` |
| 读 `config.json`、`level.txt` 这类文本 | `LoadRawFileAsync(path)` |
| 需要立刻拿到结果(初始化阶段) | 对应 `Sync` 版本 |

## 常见错误

- **拿到 `null` 句柄**:路径在 YooAsset 资源清单中不存在,先确认打包与发布生效再加载。
- **同步加载卡住主线程**:在移动端或大量资源场景不要用 `Sync` 版本,改用 `Async` 并 `await`。
- **子资源 `AssetObject` 为 `null`**:确认泛型 `T` 与图中真实类型一致(如 `Sprite` vs `Texture2D`),否则迭代时会出现空元素。
- **把原生文件当成 Unity 资源读**:`LoadAssetAsync` 会让 Unity 尝试反序列化,失败后请改用 `LoadRawFileAsync`。
- **忘记释放句柄**:子资源、全部资源、原生文件句柄同样需在不再使用时调用对应 `Release` 方法,否则会一直占用引用计数。
