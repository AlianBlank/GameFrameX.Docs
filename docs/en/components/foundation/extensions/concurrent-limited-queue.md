# How to Use the Concurrent Limited Queue

`ConcurrentLimitedQueue<T>` is a thread-safe fixed-length queue. When the number of elements reaches the capacity limit, it automatically discards elements according to the specified strategy, and can notify the caller via a callback when elements are discarded.

## Prerequisites

- Import the `GameFrameX.Foundation.Extensions` namespace.
- Available in .NET environments (depends on `System.Collections.Concurrent`).

## Steps

### 1. Create a Queue with a Specified Capacity

Pass in the maximum length; the default strategy is `DropOldest` (when full, removes the oldest element and adds the new element).

```csharp
using GameFrameX.Foundation.Extensions;

var queue = new ConcurrentLimitedQueue<int>(limit: 3);
queue.Enqueue(1);
queue.Enqueue(2);
queue.Enqueue(3);
queue.Enqueue(4); // At this point, 1 is automatically removed, leaving [2, 3, 4] in the queue
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L91-L110)

### 2. Choose an Overflow Strategy

Use `LimitedQueueOverflowStrategy` to choose how a full queue is handled:

| Strategy | Behavior |
|------|------|
| `DropOldest` | Removes the oldest element and adds the new element (default) |
| `DropNewest` | Discards the new element; the queue remains unchanged |
| `RejectNewItem` | Rejects the new element without triggering a discard notification |
| `Throw` | Throws an `InvalidOperationException` |

```csharp
var queue = new ConcurrentLimitedQueue<string>(limit: 2, LimitedQueueOverflowStrategy.DropNewest);
queue.Enqueue("a");
queue.Enqueue("b");
queue.Enqueue("c"); // "c" is discarded; the queue remains ["a", "b"]
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L245-L266)

### 3. Subscribe to the Discard Event

Use the `ItemDiscarded` callback to listen for discarded elements, which can be used for metrics tracking, logging, or compensating handling.

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 2, LimitedQueueOverflowStrategy.DropOldest)
{
    ItemDiscarded = item =>
    {
        Console.WriteLine($"丢弃元素 {item.Item}, 原因 {item.Reason}");
    }
};
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L138-L140)

### 4. Adjust the Capacity Limit

Dynamically adjust the capacity by assigning to `Limit` or calling the `SetLimit` method; when shrinking the capacity, removed elements are notified via the callback with the `LimitReduced` reason.

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 5);
for (var i = 0; i < 5; i++) queue.Enqueue(i);

queue.SetLimit(2); // Removes excess elements; Reason in the callback is LimitReduced
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L276-L296)

### 5. Dequeue and Peek

Uses standard concurrent queue semantics: `TryDequeue` / `TryPeek` / `ToArray` / `Clear` are all available.

```csharp
if (queue.TryPeek(out var head))
{
    Console.WriteLine($"队头: {head}");
}

if (queue.TryDequeue(out var first))
{
    Console.WriteLine($"出队: {first}");
}
```

## Common Variants

- **Initialize from an existing collection**: `new ConcurrentLimitedQueue<int>(new List<int> { 1, 2, 3 })` or implicit conversion `ConcurrentLimitedQueue<int> q = new List<int> { 1, 2, 3 };`; the capacity is automatically set to the collection size.
- **Use as `IProducerConsumerCollection<T>`**: You can directly call `TryAdd` / `TryTake`, which internally go through `TryEnqueue` / `TryDequeue`.
- **Avoid operating on the same queue inside the callback**: `ItemDiscarded` is triggered outside the internal lock, so enqueue/dequeue operations within the callback are safe, but avoid blocking for long periods.

## Common Errors

| Error | Description |
|------|------|
| Constructing with `limit <= 0` throws `ArgumentOutOfRangeException` | The capacity must be greater than 0 |
| Constructing with an empty collection throws `ArgumentOutOfRangeException` | The collection must contain more than 0 elements |
| `OverflowStrategy.Throw` throws `InvalidOperationException("The limited queue has reached its capacity.")` when enqueuing into a full queue | The caller needs to catch the exception or use a different strategy |
| Expecting `DropOldest` to trigger `ItemDiscarded` but using `RejectNewItem` | `RejectNewItem` does not trigger discard notifications |

## Background (Optional)

`ConcurrentLimitedQueue<T>` internally wraps a `ConcurrentQueue<T>` and uses a separate `_syncRoot` to protect the capacity count and enqueue overflow logic, so that capacity adjustment and enqueue strategy evaluation are completed atomically within the same critical section. The underlying `ConcurrentQueue` itself guarantees thread-safe element access.
