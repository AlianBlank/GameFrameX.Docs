# Android プラットフォームで StreamingAsset が読み込めない場合の対処法(ファイル名/圧縮/文字)

Android デバイスでは、本ライブラリは APK 内の `assets/` を通常のフォルダとして読み取るのではなく、APK の ZIP End-of-Central-Directory と Central Directory を読み取り、`offset/size` で直接 `FileStream` のスライスアクセスを行います。そのため「読み込めない」原因はほぼ以下の通りです:**パスが一致しない**、**APK 内のエントリが圧縮されている**、**ファイル名に特殊文字が含まれている**、または **split APK / patch パッケージ化されているが `base.apk` にヒットしない**。本記事では迅速な診断表と対応する修正手順を示します。

## 迅速診断

| 症状 | 直接的原因 | 修正入口 |
|------|----------|----------|
| `TryGetInfo` が `false` を返す / `OpenRead` が `FileNotFoundException` をスローする | 渡された相対パスと APK 内 `assets/` 下のエントリが一致しない(大小区別、スペース、`/` または `\` の書き方) | [パス大小区別と区切り文字を修正](#パスの大小区別と区切り文字を修正する) |
| `Debug.Assert` 発火:`CompressedSize != UncompressedSize` | APK ビルド時に Compression を有効にした、またはプラグイン/Gradle が `assets` を再圧縮した | [APK 内の assets の無圧縮を強制する](#apk-内の-assets-の無圧縮を強制する) |
| 実行時に `paths duplicate! <file>` 例外 | メイン APK と split/patch の両方を出力し、両方に同じ名前の `assets` エントリが含まれている | [split APK / OBB patch の処理](#split-apk--obb-patch-を処理する) |
| 中国語/日本語のファイル名が開けない、または大小区別の妙なリソースが見つからない | ZIP 規格はファイル名が ASCII か UTF-8 フラグ付きであることを要求するが、APK にはデフォルトで UTF-8 フラグが付かない | [ファイル名の命名規則を統一する](#ファイル名の命名規則を統一する) |
| 64 ビットプラグインをインストール後、Mono アップグレード後に `stream.CanSeek == false` または APK パスが無効でクラッシュ | `dataPath` が `base.apk` に正しく解決されていない(split サブパッケージの場合など) | [APK メインパッケージパスを確認する](#apk-メインパッケージパスを確認する) |

## 修正手順

### パスの大小区別と区切り文字を修正する

`BlankReadAssets.ApkImpl.TryGetInfo` は内部で `PathUtil.NormalizeRelativePath` を呼び出し、`StringComparer.OrdinalIgnoreCase` で `s_paths` の二分探索を行います。そのためパスは APK にパッケージングされた実際のファイル名と一対一で対応し、必ずスラッシュ `/` を使用する必要があります。

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L58-L84
public static bool TryGetInfo(string path, out ReadInfo info)
{
    path = PathUtil.NormalizeRelativePath(path);
    info = new ReadInfo();

    var index = Array.BinarySearch(s_paths, path, StringComparer.OrdinalIgnoreCase);
    if ( index < 0 )
    {
        return false;
    }
    ...
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L58-L84)

操作:

1. 実際にパッケージングされた APK を取得し(`Library/` または `Build/` ディレクトリにあります)、`unzip -l your.apk | head` で `assets/` 下のエントリの正確な大小区別を確認します。
2. コード内では統一して `/` を使用し、`\` を混在させず、`StreamingAssets` や `jar:file://...` といったプレフィックスも付けません。
3. リソース名は可能な限り `A–Z`、`a–z`、`0–9`、`_`、`-`、`.`、単層 `/` のみを使用します。

### APK 内の assets の無圧縮を強制する

本ライブラリはエントリを特定する際に以下のアサーションを行います(開発時に警告が出ます):

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L325-L340 (抜粋)
while ( ZipCentralDirectoryFileHeader.TryReadBlock(reader, out header) )
{
    if ( header.CompressedSize != header.UncompressedSize )
    {
#if UNITY_ASSERTIONS
        // 無圧縮 -> スライス読み取りが正しくなる
#endif
        continue;
    }
    ...
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L325-L340)

結果:圧縮されたエントリはスキップされ、「読み込めない」ように見えます。修正方法:

1. Unity:Player Settings → Publishing Settings → **Build APK(s) without compression** のチェックを外しますが、Gradle/AAPT が再圧縮しないことを確認します。
2. カスタム Gradle(メインテンプレート `unityLibrary` の `build.gradle`)の `android` ノードに以下を追加し、`assets/**/*.bundle`、`StreamingAssets/**` などのホットディレクトリの無圧縮を強制します:

```groovy
android {
    aaptOptions {
        noCompress 'bundle','unitydefaultresources','StreamingAssets','bin','config.json'
    }
}
```

3. 再パッケージング後、`unzip -lv your.apk | grep -E "Method|---"` でホットファイルの `Method` 列が `Stored`(`Defl:N` ではなく)であることを確認します。

### split APK / OBB patch を処理する

Initialize は `dataPath` の末尾を判定し、patch ディレクトリに進むか `base.apk` にフォールバックするかを決定します:

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L27-L56
public static void Initialize(string dataPath, string streamingAssetsPath)
{
    s_root = dataPath;
    if (dataPath.EndsWith("pram-shadow-files"))
    {
        Debug.Assert(streamingAssetsPath.EndsWith("pram-shadow-files/assets"));
        GetStreamingAssetsFromPatch(dataPath, paths, parts);
    }
    else
    {
        GetStreamingAssetsInfoFromJar(s_root, paths, parts);
        if (paths.Count == 0 && !Application.isEditor && Path.GetFileName(dataPath) != "base.apk")
        {
            var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
            if (File.Exists(newDataPath))
            {
                s_root = newDataPath;
                GetStreamingAssetsInfoFromJar(newDataPath, paths, parts);
            }
        }
    }
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

複数の split をホストするアプリケーションの場合は、以下が必要です:

1. 本物の `assets` を `base.apk` に集中して格納し、split パッケージ内に `assets/` サブディレクトリが残らないようにします。
2. Play Asset Delivery / カスタム patch ディレクトリを使用している場合は、呼び出し側から渡される `dataPath` が `.../pram-shadow-files` であることを確認します(論理分岐が `GetStreamingAssetsFromPatch` に進みます)。

### ファイル名の命名規則を統一する

ZIP Central Directory ではファイル名の長さが `[ushort]` の制限を受け、Unicode エンコーディングの処理は General Purpose Bit Flag ビット 11(UTF-8)に依存します。一部の Android ツールチェーンはこのフラグビットを書き込まないため、マルチバイト文字のファイル名が解析に失敗します。操作:

1. リソース名は一律 ASCII にします:`game_config`、`map_01.bin`、`lang_zh.json`。
2. `+`、`%`、`スペース`、絵文字の使用を禁止します。
3. 多言語リソースを必ずサポートする必要がある場合は、ファイル名に埋め込むのではなく、ディレクトリで区別します(`assets/i18n/zh/...`)。

### APK メインパッケージパスを確認する

split シナリオでは、Unity が提供する `Application.streamingAssetsPath` は `base.apk` を指さないため、Initialize は自動的にフォールバックします:

```csharp
var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
if (File.Exists(newDataPath)) { s_root = newDataPath; }
```

(Source は同上) ただし、プロジェクトで App Bundle のマージやカスタム aapt を行い、`assets` を `base.apk` 以外のファイルにリダイレクトしている場合、フォールバックは機能しません。修正方法:

1. デバイス側で `adb shell pm path <your.package>` を実行し、現在の Package の `base.apk` の実際のパスを見つけます。
2. `Application.streamingAssetsPath` と比較し、一致しない場合は Gradle/AGP で `--split-by-abi` / `--split-resources` が有効になっていないか確認し、`assets` を分割しないようにします。

## 検証

1. **オフライン照合チェックリスト**:生成された APK を `unzip -l` で `assets/` の先頭 50 件をリストアップし、コードから渡された相対パスと一つずつ照合します(大小区別、区切り文字、`.bin` 拡張子)。
2. **Editor と Device の同一ソース**:`BlankReadAssets.LooseFilesImpl`(非 Android)と `BlankReadAssets.ApkImpl`(Android)は同一の `PathUtil` に従うため、まず Editor で `OpenRead` を動作させてから、デバイスで検証します。
3. **読み込みオープンのスモークテスト**:

```csharp
using (var s = BlankReadAssets.OpenRead("config/game_config.json"))
{
    Debug.Assert(s.Length > 0, "size == 0 は APK 内で圧縮されているかパスが間違っていることを示す");
}
```

4. **実機ログ**:上記の `Debug.Assert` を `Debug.LogError` に置き換えて完全なスタックトレースを確認します。`Method != Stored` が表示された場合は、直接 [APK 内の assets の無圧縮を強制する](#apk-内の-assets-の無圧縮を強制する)に戻ってください。

## 背景(オプション)

Android では Unity は `Assets/StreamingAssets/` を APK の `assets/` セクションにまとめて格納します。ZIP コンテナの末尾からインデックスが見つかるため、iOS/Jar のように `UnityWebRequest` で `jar:file://...` を取得する必要はありません。本ライブラリは `File.OpenRead(apkPath)` + `SubReadOnlyStream` を直接使用し、ゼロコピー・スライスパスを通るため、「圧縮されているかどうか」と「パスが正しいかどうか」が、読み込めないか間違って読み込むかを直接決定します。
