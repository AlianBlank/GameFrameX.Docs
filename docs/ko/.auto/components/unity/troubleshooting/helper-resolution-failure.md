# Helper 타입을 찾을 수 없거나 생성에 실패할 때怎么办

코드에서 `Helper.Create`를 호출했는데 `null`이 반환되거나, 리플렉션 로딩 시 `cannot find Helper type` / `missing type` 오류가 발생할 때는 보통 해당 Helper 클래스가 빌드 시 제거(stripping)되었거나 네임스페이스/어셈블리 참조가 제대로 설정되지 않은 경우입니다. 이 페이지에서는 증상에 따라 원인을 파악하고 해결하는 방법을 제공합니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Helper.Create<XXHelper>()`에서 `GameFrameworkException: ...` 발생 | 해당 Helper의 `Create` 팩토리가 등록되지 않았거나 팩토리에서 생성자를 찾을 수 없음 | 리플렉션으로 해당 클래스에 매개변수 없는 생성자가 있는지 확인, [수정 1](#수정-1-매개변수-없는-생성자를-찾을-수-없음) 참조 |
| iOS/Android IL2CPP 빌드 후 일부 API에서 `MissingMethodException` 또는 `TypeLoadException` 발생 | 코드 스트리핑(Code Stripping)으로 Helper 타입이 제거됨 | 씬에 `GameFrameXCroppingHelper` 컴포넌트를 추가하거나 `link.xml`로 보존, [수정 2](#수정-2-빌드-후-제거됨) 참조 |
| `typeof(GameFrameX.Runtime.DoTweenHelper)` 컴파일 오류 | 해당 플러그인이 설치되지 않았거나 매크로가 활성화되지 않음 | 매크로를 활성화하거나 참조 제거, [수정 3](#수정-3-선택적-모듈의-헬퍼-클래스) 참조 |
| 에디터 확장에서 `HotFixAssemblyDefinitionHelper` 등 타입을 찾을 수 없음 | 네임스페이스 오류 또는 Editor 어셈블리가 컴파일되지 않음 | `Editor/` 디렉터리와 asmdef 확인, [수정 4](#수정-4-editor-헬퍼-클래스) 참조 |
| 사용자 정의 Helper 서브클래스에서 `not registered` 발생 | `Helper.Create` 또는 `Register`를 호출하지 않음 | 프레임워크 규약에 맞는 팩토리 패턴으로 등록, [수정 5](#수정-5-사용자-정의-helper) 참조 |

## 수정 1: 매개변수 없는 생성자를 찾을 수 없음

`Helper` 클래스의 모든 구체적인 구현(예: `DefaultLogHelper`, `DefaultCompressionHelper`, `DefaultTextHelper`, `DefaultVersionHelper`)은 **매개변수 없는 생성자**를 제공해야 합니다. `Helper.Create<T>()`이 리플렉션 `Activator.CreateInstance`을 사용하기 때문입니다.

1. Helper 서브클래스 확인:

```csharp
// 잘못된 예시 — Helper.Create<MyHelper>()가 실패합니다
public class MyHelper : ILogHelper
{
    public MyHelper(string name) { /* ... */ }
}

// 올바른 예시
public class MyHelper : ILogHelper
{
    public MyHelper() { }
    // ...
}
```

2. Unity Console에서 발생한 예외 메시지가 `GameFrameworkException`인지, 예외 내용에 보통 타입의 전체 이름이 포함되어 있는지 확인합니다.

3. 수정 후 `Helper.Create<MyHelper>()` 호출을 다시 트리거하여 검증합니다.

소스 코드에서 구체적인 Helper 타입 목록은 [GameFrameXCroppingHelper.cs#L21-L60](Runtime/GameFrameXCroppingHelper.cs#L21-L60)을 참조하세요.

## 수정 2: 빌드 후 제거됨

`Runtime/GameFrameXCroppingHelper.cs`의 존재 이유가 바로 IL2CPP/AOT 빌드 시 프레임워크 내부 타입이 제거되는 것을 방지하기 위함이며, 모든 참조는 `typeof()`로 표현됩니다. 런타임(에디터 제외)에서는 이 스크립트가 씬에서 반드시 인스턴스화되어야 합니다:

1. 첫 번째 시작 씬에서 빈 `GameObject`를 새로 만들고, `GameFrameXCroppingHelper` 컴포넌트를 부착한 뒤 `DontDestroyOnLoad`로 설정합니다.

```csharp
// 시작 스크립트에서
var go = new GameObject("GameFrameXCroppingHelper");
go.AddComponent<GameFrameXCroppingHelper>();
DontDestroyOnLoad(go);
```

2. HybridCLR / ILRuntime 등 핫 업데이트 방식을 사용하는 경우, 해당 타입들을 메인 패키지 AOT 어셈블리의 `link.xml`에 추가해야 합니다:

```xml
<linker>
  <assembly fullname="GameFrameX.Runtime" preserve="all"/>
</linker>
```

3. Build Settings에서 해당 스크립트가 Stripping 시 제거되지 않는지 확인합니다(임시로 Managed Stripping을 비활성화하여 검증 가능).

소스 참고: [GameFrameXCroppingHelper.cs#L1-L12](Runtime/GameFrameXCroppingHelper.cs#L1-L12).

## 수정 3: 선택적 모듈의 헬퍼 클래스

`DoTweenHelper`는 `#if ENABLE_GAME_FRAME_X_DO_TWEEN`으로 감싸여 있습니다([GameFrameXCroppingHelper.cs#L9-L11](Runtime/GameFrameXCroppingHelper.cs#L9-L11)). DOTween 플러그인을 도입하지 않았는데 해당 매크로를 활성화했거나, 반대의 경우:

| 상황 | 처리 방법 |
|------|------|
| DOTween을 사용하지 않는데 `ENABLE_GAME_FRAME_X_DO_TWEEN`을 활성화한 경우 | 매크로를 비활성화하거나 `DoTweenHelper`에 대한 참조를 제거 |
| DOTween을 사용하지만 매크로를 활성화하지 않은 경우 | `Project Settings → Player → Scripting Define Symbols`에서 `ENABLE_GAME_FRAME_X_DO_TWEEN` 추가 |
| 기타 선택적 플러그인(예: YooAsset, HybridCLR) 사용 시 | 해당 플러그인 문서를 참조하여 매크로가 비활성화되어 있을 때 `typeof()`로 이 Helper들을 참조하지 말 것 |

## 수정 4: Editor 헬퍼 클래스

저장소의 `Editor/` 디렉터리에는 여러 `*Helper.cs` 파일들(예: `BuildHotfixHelper.cs`, `BuildPostProcessHelper.cs`, `MiniGameDefineSymbolHelper.*.cs`)이 있으며, 이들은 Editor 어셈블리에서만 사용 가능합니다:

1. 스크립트가 `Editor/` 폴더 아래에 있는지, 또는 해당 `.asmdef`에 `includePlatforms: ["Editor"]`가 표시되어 있는지 확인합니다.
2. **런타임 코드에서는** 이 타입들을 `using`하거나 `typeof()`로 참조하면 **안 됩니다** — 배포 패키지에서 찾을 수 없어 오류가 발생합니다.
3. 플랫폼용 미니게임(`InternationalMiniGames` / `DomesticMiniGames` / `GamePlatforms`)을 새로 추가한 경우, 해당 플랫폼의 `MiniGameDefineSymbolHelper.<Platform>.cs`를 새로 추가하거나 보완해야 합니다.

소스 참고: [Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs](Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs), [Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs](Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs).

## 수정 5: 사용자 정의 Helper

프레임워크의 `Helper`는 정적 파사드 클래스이며([Runtime/Helper/Helper.cs#L44](Runtime/Helper/Helper.cs#L44)), `Helper.Create<T>()`는 규약에 따라 `T.Create()` 또는 동일한 이름의 팩토리 메서드를 찾습니다. 사용자 정의 Helper를 찾을 수 없는 경우:

1. 규약에 맞는 팩토리 메서드를 구현했는지 확인:

```csharp
public class MyJsonHelper : IJsonHelper
{
    public static IJsonHelper Create()
    {
        return new MyJsonHelper();
    }

    private MyJsonHelper() { } // private 생성자, Create를 통해서만 인스턴스를 얻을 수 있음
}
```

2. `GameEntry` 시작 후 반환된 인스턴스를 프레임워크에 등록:

```csharp
Utility.Json.IJsonHelper json = MyJsonHelper.Create();
GameEntry.RegisterHelper(json);
```

3. 에디터에서 중단점을 설정하고 `Helper.Create<T>`에서 사용자 정의 분기로 진입했는지 확인합니다.

## 검증

위 수정 작업을 완료한 후, 다음 단계로 문제가 해결되었는지 확인합니다:

1. **에디터**: Play 모드로 진입하여 모든 `Helper.Create` 호출에서 더 이상 예외가 발생하지 않아야 합니다.
2. **IL2CPP 실기기**: Player를 빌드하여 대상 기기에서 실행하고, Console에 `MissingMethodException` / `TypeLoadException`이 더 이상 나타나지 않는지 확인합니다.
3. **리플렉션 스캔**: 리플렉션으로 `GameFrameX.Runtime` 어셈블리의 모든 `*Helper` 타입을 나열하여, 그 수가 [GameFrameXCroppingHelper.cs#L21-L165](Runtime/GameFrameXCroppingHelper.cs#L21-L165)의 목록과 일치하는지 확인합니다.
4. **스트리핑 보고서**: IL2CPP의 `Strip Engine Code` 출력을 활성화하고, `Library/Il2cppBuildCache`에서 대상 타입이 제거 목록에 없는지 확인합니다.
