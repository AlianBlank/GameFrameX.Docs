# 傳送與接收網路訊息（定義訊息與註冊處理器）

在 GameFrameX Network 中，傳送與接收訊息只需三個步驟：定義繼承自 `MessageObject` 的訊息類別、撰寫實作對應 `IPacket*Handler` 介面的處理器類別，並透過 `INetworkChannel.Send(...)` 傳送。處理器**不需要手動註冊**——`DefaultNetworkChannelHelper.Initialize` 會以反射掃描組件，並自動呼叫 `RegisterHandler` 完成註冊。

## 前置條件

- 已建立並連線網路通道（`NetworkManager` 已就緒）。
- 訊息基礎類別 `MessageObject` 來自框架基礎庫；本套件的序列化約束為 `where T : MessageObject`。
- 處理器類別必須是**非抽象類別**、實作標記介面 `IPacketHandler`，並提供公開的無參數建構函式（反射會透過 `Activator.CreateInstance` 將其實例化）。

## 步驟

1. **定義訊息類別**：讓訊息繼承自 `MessageObject`。通道內部維護的傳送佇列為 `GameFrameworkLinkedList<MessageObject>`，序列化入口的泛型約束同樣是 `MessageObject`：

   ```csharp
   public bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject
   ```

   > 本儲存庫僅包含網路元件本身，不包含具體的遊戲端訊息定義（例如 protobuf 訊息類別）；您需要在遊戲專案中自行定義。

2. **實作處理器**：依傳送／接收階段選擇要實作的介面。所有處理器都必須實作標記介面 `IPacketHandler`（定義於 [IPacketHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketHandler.cs#L4)，註解為「標記介面，用於識別網路封包處理器」）：

   | 介面 | 註冊 API（透過反射自動呼叫） | 職責 |
   |------|---------------------------|------|
   | `IPacketReceiveHeaderHandler` | `RegisterHandler(IPacketReceiveHeaderHandler)` | 解析接收到的封包表頭 |
   | `IPacketReceiveBodyHandler` | `RegisterHandler(IPacketReceiveBodyHandler)` | 將封包本體反序列化為 `MessageObject` |
   | `IPacketSendHeaderHandler` | `RegisterHandler(IPacketSendHeaderHandler)` | 序列化封包表頭 |
   | `IPacketSendBodyHandler` | `RegisterHandler(IPacketSendBodyHandler)` | 序列化封包本體 |
   | `IPacketHeartBeatHandler` | `RegisterHeartBeatHandler(IPacketHeartBeatHandler)` | 產生／驗證心跳封包 |
   | `IMessageCompressHandler` / `IMessageDecompressHandler` | `RegisterMessageCompressHandler` / `RegisterMessageDecompressHandler` | 封包本體壓縮／解壓縮 |

   套件中提供了預設實作，您可以直接繼承或替換：[DefaultPacketReceiveHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveHeaderHandler.cs#L9)、[DefaultPacketReceiveBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveBodyHandler.cs#L7)、[DefaultPacketSendHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendHeaderHandler.cs#L10)、[DefaultPacketSendBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendBodyHandler.cs#L9)、[BasePacketHeartBeatHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/BasePacketHeartBeatHandler.cs#L7)。

3. **確認自動註冊**：在通道初始化期間，`DefaultNetworkChannelHelper.Initialize` 會掃描所有組件型別；每個實作 `IPacketHandler` 的非抽象類別都會被實例化並註冊到通道：

   ```csharp
   var types = Utility.Assembly.GetTypes();
   foreach (var type in types)
   {
       if (!type.IsClass || type.IsAbstract)
       {
           continue;
       }

       if (!type.IsImplWithInterface(packetHandlerBaseType))
       {
           continue;
       }

       if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
       {
           var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       else if (type.IsImplWithInterface(packetReceiveBodyHandlerBaseType))
       {
           var handler = (IPacketReceiveBodyHandler)Activator.CreateInstance(type);
           InjectChannelSerializer(handler, type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       // ...之後依序匹配 SendHeader / SendBody / HeartBeat / Compress / Decompress
   }
   ```

   來源：[DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L73-L107)

4. **傳送訊息**：呼叫通道的 `Send` 方法。套件內部傳送心跳的方式即為標準用法：

   ```csharp
   public bool SendHeartBeat()
   {
       if (m_NetworkChannel == null)
       {
           return false;
       }

       var message = m_NetworkChannel.PacketHeartBeatHandler.Handler();
       m_NetworkChannel.Send(message);
       return true;
   }
   ```

   來源：[DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L146-L156)

5. **接收訊息**：收到封包後，接收處理器鏈會完成解析；接收封包本體的反序列化會依據 `messageId` 還原出具體的 `MessageObject`：

   ```csharp
   public bool DeserializePacketHeader(byte[] source)
   public bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)
   ```

   來源：[DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L179-L189)

6. **（選用）監聽網路事件**：連線、關閉、心跳遺失與錯誤事件已由 Helper 統一訂閱（`NetworkConnectedEventArgs`、`NetworkClosedEventArgs`、`NetworkMissHeartBeatEventArgs`、`NetworkErrorEventArgs`）；遊戲端只需透過事件元件訂閱即可。詳見 [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128)。

## 常見變體

## 常見變體

- **自訂心跳**：繼承 `BasePacketHeartBeatHandler`（它同時實作了 `IPacketHeartBeatHandler` 與 `IPacketHandler`），並實作 `Handler()` 以回傳心跳訊息物件；傳送心跳時會呼叫 `m_NetworkChannel.Send(message)`，與一般訊息相同。
- **自訂壓縮**：分別實作 `IMessageCompressHandler` / `IMessageDecompressHandler` 並加上 `IPacketHandler` 標記；註冊後即會由 `SerializePacketHeader` / `DeserializePacketBody` 流程自動呼叫。預設實作詳見 [DefaultMessageCompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageCompressHandler.cs#L10) 與 [DefaultMessageDecompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageDecompressHandler.cs#L10)。
- **手動註冊處理器**：`INetworkChannel` 也提供了多種 `RegisterHandler` 多載（包含已標記為 `[Obsolete("Use RegisterHeartBeatHandler instead")]` 的心跳多載）。詳見 [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L150-L181)。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 處理器從未被呼叫 | 類別是抽象的，或未實作 `IPacketHandler` 標記介面；反射掃描會直接透過 `continue` 跳過它 | 將類別宣告為非抽象，並加上 `IPacketHandler` |
| 執行階段實例化處理器時拋出例外 | 反射使用 `Activator.CreateInstance(type)`，但缺少公開的無參數建構函式 | 為處理器加上公開的無參數建構函式 |
| 類別匹配到錯誤的註冊分支 | 註冊依照 `if / else if` 鏈中的 `ReceiveHeader → ReceiveBody → SendHeader → SendBody → HeartBeat → Compress → Decompress` 順序進行，並採用**第一個匹配** | 每個類別只實作一個處理器介面；拆分為多個類別 |
| 傳送／接收的封包表頭／本體解析行為不符預期 | 缺少序列化器注入（只有 `ReceiveBody` 與 `SendHeader` 分支會呼叫 `InjectChannelSerializer(handler, type)`） | 為對應的處理器設定通道序列化器，或直接使用套件的預設處理器 |
| 序列化呼叫拋出引數為 null 的例外 | `SerializePacketHeader` / `SerializePacketBody` 內部會以 `GameFrameworkGuard.NotNull` 驗證 `m_NetworkChannel`、`PacketSendHeaderHandler`、`PacketSendBodyHandler`、`messageObject` 與 `destination` | 傳送前先完成處理器註冊，並確保訊息與目標串流不為 null |

## 驗證

- 傳送端：觀察通道統計屬性 `SendPacketCount` / `SentPacketCount`（傳送佇列數量／已傳送數量），其會在 Unity Inspector 面板中顯示為 "Send Packet"。詳見 [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L108)。
- 接收端：在您的 `IPacketReceiveBodyHandler` 實作中設定中斷點，確認 `DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` 有被回呼且 `messageObject` 成功還原。

## 背景

在設計上，傳送／接收的封包處理拆分為「表頭／本體」兩段，傳送與接收方向各自擁有獨立的介面。傳送時，`SerializePacketHeader` 寫入表頭並產生本體緩衝區，接著 `SerializePacketBody` 寫入本體；接收則執行反向流程：`DeserializePacketHeader` → `DeserializePacketBody`。標記介面 `IPacketHandler` 結合組件反射，讓新的訊息與處理器無需修改框架程式碼即可自動接入（詳見 [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L60-L71)）。通道層的傳送佇列與處理器註冊實作位於 [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L525-L572)。
