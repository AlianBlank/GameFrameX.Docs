# Get Your First Config Table Running in 5 Minutes

Follow this page to create an Excel item table from scratch, run the generation script, obtain C# code and data files, and then read the first record in your program via `tables.TbXxx.Get(id)`. The whole process takes about 5 minutes.

## Prerequisites

- The repository `GameFrameX.Config` has been cloned locally (you can see `Excels/`, `Tools/`, `luban.conf`, and the generation scripts in the directory).
- [.NET SDK](https://dotnet.microsoft.com/download) is installed (used to run `Tools/Luban.dll`).
- Excel or another tool that can edit `.xlsx` files is installed (WPS / Numbers both work).
- Windows users need no extra steps; macOS / Linux users need to know how to run `sh` scripts in a terminal.

## Steps

### 1. Create a New Excel File

Create a new file under `Excels/Tables/`, following the "letter - English name - Chinese name" naming formula:

```
D-MyItem-我的道具表.xlsx
```

- `D`: sorting letter, any single letter.
- `MyItem`: English name, **it becomes the class name in code** `TbMyItem`; it must be in English, not Chinese.
- `我的道具表`: Chinese name, for humans to read, write whatever you like.

### 2. Fill in the First 4 Header Rows

The first 4 rows of the Excel file are a fixed "instruction manual" used to declare fields. Open the file and fill it in as follows:

| Row | Column 1 (Marker) | Column 2 | Column 3 | Column 4 |
|----|---------------|--------|--------|--------|
| 1  | `##var`       | `id`   | `name` | `price` |
| 2  | `##type`      | `int`  | `text` | `int`   |
| 3  | `##group`     |        |        |         |
| 4  | `##`          | Item ID | Item Name | Price    |

> The four markers `##var`, `##type`, `##group`, and `##` are fixed notation; the first column must be written exactly as shown.

Field type descriptions:

| Type | Purpose | Example |
|------|------|------|
| `int` | Integer | `10001` |
| `string` | Plain text that is not translated | `icon_diamond` |
| `text` | Multilingual key (the actual text is translated in `Excels/Local/`) | `diamond` |
| `bool` | True/false | `true` / `false` |
| `float` | Decimal number | `1.5` |

### 3. Fill in Data (Starting from Row 5)

Continue appending data rows below the header, one record per row:

| Column 1 | Column 2 | Column 3 | Column 4 |
|--------|--------|--------|--------|
|        | 10001  | diamond | 10     |
|        | 10002  | coin    | 1      |

Since `name` is of type `text`, `diamond` / `coin` are **multilingual keys**, and the actual translations still need to be written in the localization table. If you just want to get the pipeline running the first time, you can temporarily change the type to `string` and write Chinese directly to skip translation.

### 4. Run the Generation Script

Go back to the repository root and run the script for your platform:

- **Windows** (JSON output): double-click [gen-server-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-json.bat)
- **Windows** (binary output, faster loading): double-click [gen-server-bin.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.bat)
- **macOS / Linux**: run `sh gen-server-json.sh` or `sh gen-server-bin.sh` in a terminal

The script essentially invokes [Tools/Luban.dll](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-json.sh#L1) and reads the configuration from [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L94):

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json \
  --xargs outputDataDir=../Server/GameFrameX.Config/Json \
  --xargs tableImporter.name=gameframex \
  --xargs outputCodeDir=../Server/GameFrameX.Config/Config \
  --conf ./Luban.conf
```

If you see no red errors when it finishes, it succeeded.

### 5. Get the Generated Output

The tool outputs two things into the directories specified by the config options `outputCodeDir` and `outputDataDir`:

- **C# code** (e.g., `TbMyItem.cs`, `TablesComponent.cs`): each table corresponds to one `TbXxx` class.
- **Data files** (`.json` or `.bin`): the data filled in the table.

According to the `targets.server` configuration in `luban.conf`, the default `topModule` is `GameFrameX.Config`, and the namespace falls under `GameFrameX.Config`.

### 6. Use It in Code

```csharp
// After all tables have been loaded
var item = tables.TbMyItem.Get(10001);

Console.WriteLine(item.Id);    // 10001
Console.WriteLine(item.Name);  // "钻石"/"Diamond" in the current language
Console.WriteLine(item.Price); // 10
```

`tables` is an instance of `TablesComponent` (from the `manager` field in `luban.conf`), and `TbMyItem.Get(id)` returns exactly that row from your Excel file.

## Common Variants

**Only for one side (client c / server s)**: insert a group marker between the English name and the Chinese name. For example, `D-ItemConfig-c-道具表.xlsx` is generated only for the client; `D-ItemConfig-s-道具表.xlsx` is generated only for the server; without a group marker, it is generated for both sides.

**Table too large and want to split into files**: as long as the "English name" stays the same, you can use any number of Chinese names, and the tool will merge them automatically. For example, `D-ItemConfig-道具表-道具-1001.xlsx` and `D-ItemConfig-道具表-道具-1002.xlsx` will be merged into the same `TbItemConfig` table (the repository's [D-ItemConfig-道具表-道具-1001.xlsx](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Excels/Tables/D-ItemConfig-道具表-道具-1001.xlsx) uses exactly this pattern).

**Switch to binary output (faster and smaller)**: replace `--dataTarget json --codeTarget cs-dotnet-json` in the generation script with `--dataTarget bin --codeTarget cs-dotnet-bin`, corresponding to [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1) / [gen-server-bin.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.bat#L1).

**Three types of "advanced definition tables" already exist**: `Excels/__tables__.xlsx`, `Excels/__beans__.xlsx`, and `Excels/__enums__.xlsx` are used to declare complex field types such as enums and structs. Beginners can ignore them for now; `int`/`string`/`text` are enough to fill in tables.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Error "Chinese table names are not supported" | Chinese was written in the English-name segment (e.g., `D-我的道具-...`) | Change the English name to pure English, e.g., `MyItem` |
| No `TbMyItem` in the generated code | The Excel file is not under `Excels/Tables/`, or the number of filename segments is wrong | Check the file path and the three-segment `letter-EnglishName-ChineseName.xlsx` format |
| The `name` field shows the key instead of the translation in-game | Localization entries in `Excels/Local/` are missing | Add translations in each language for the key in `L-Localization-*.xlsx` |
| Running the script reports `dotnet` not found | .NET SDK is not installed | Download and install it from [dotnet.microsoft.com](https://dotnet.microsoft.com/download) |
| Data is not read | Forgot to load the config first (`TablesComponent.Load`) | Call `TablesComponent.Load(...)` at startup, then access `tables.TbMyItem` |

## Background (Optional)

The whole tool is built on top of [Luban](https://github.com/GameFrameX/luban): it reads the `.xlsx` files under `Excels/` and generates C# classes and JSON / binary data according to the schema declared in `luban.conf` (`__tables__`, `__beans__`, `__enums__`, `Defines/`). The `targets` array in `luban.conf` determines the generation target (server / client / all), and the `commands` array determines the specific commands (those with `active: true` will be triggered by the script). The `c` / `s` in `groups` works together with the group marker in the middle of the filename to decide which side a table is visible to.
