# 用 Tag 标签分组管理下载任务

通过给 `AddDownload` 传入 `tag` 字符串,可以把同一类下载任务归到一个分组,然后用 `GetDownloadInfos(tag)` 一次性查出该分组下所有任务的状态。本页说明如何给任务打 Tag、如何按 Tag 查询,以及常见错误。

## 前置条件

- 已安装 `com.gameframex.unity.download` 包,并在场景里挂好 `DownloadComponent`。
- 已获取 `DownloadComponent` 引用,例如 `GameEntry.GetComponent<DownloadComponent>()`。
- 已了解 `AddDownload` 的基本调用方式(见组件中的 `AddDownload(string, string)` 重载)。

## 操作步骤

### 1. 给下载任务打 Tag

调用带 `tag` 参数的 `AddDownload` 重载。Tag 是一个普通的字符串,你自己定义语义,例如 `"asset-bundle"`、`"lua-3.2.0"`、`"res-avatar"`。

```csharp
// 只指定 tag,使用默认优先级与 null userData
int id1 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/a.png",
    downloadUri:  "https://example.com/a.png",
    tag:          "asset-bundle");

// 指定 tag + 优先级
int id2 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/b.png",
    downloadUri:  "https://example.com/b.png",
    tag:          "asset-bundle",
    priority:     10);

// 指定 tag + 优先级 + userData(完整版本)
int id3 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/c.png",
    downloadUri:  "https://example.com/c.png",
    tag:          "asset-bundle",
    priority:     10,
    userData:     myCallback);
```

### 2. 按 Tag 一次性查询分组下所有任务

用 `GetDownloadInfos(string tag)` 得到该分组下的 `TaskInfo[]`,或用 `GetDownloadInfos(string tag, List<TaskInfo> results)` 复用已有列表避免 GC。

```csharp
// 返回 TaskInfo[]
TaskInfo[] infos = downloadComponent.GetDownloadInfos("asset-bundle");
foreach (var info in infos)
{
    Debug.Log($"tag={info.Tag} status={info.Status} progress={info.Progress}");
}

// 复用 List,避免每帧分配新数组
var buffer = new List<TaskInfo>();
downloadComponent.GetDownloadInfos("asset-bundle", buffer);
```

Source: [DownloadComponent.cs#L230-L245](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L230-L245)、[DownloadManager.cs#L225-L243](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L225-L243)

### 3. 按 Tag 统计进度

把 Tag 当成"批次"维度,在 UI 上做整批进度展示:

```csharp
void Update()
{
    var infos = downloadComponent.GetDownloadInfos("asset-bundle");
    if (infos.Length == 0) return;

    long downloaded = 0, total = 0;
    foreach (var info in infos)
    {
        downloaded += info.DownloadedLength;
        total      += info.TotalLength;
    }
    progressBar.value = total > 0 ? (float)downloaded / total : 0f;
}
```

> `TaskInfo` 的字段(`Status`、`Progress`、`DownloadedLength`、`TotalLength`、`Tag`、`SerialId` 等)由 `DownloadManager` 在任务生命周期内更新。

### 4. Editor Inspector 里查看 Tag

打开 `DownloadComponent` 的 Inspector,可以在 "Download Infos" 列表里直接看到 `Tag` 列,用来核对任务是否被打到预期分组。

## 常见变体

| 场景 | 用法 |
|------|------|
| 同一批资源,优先级不同 | 用相同 `tag`,不同 `priority`,可以一起查、分开调度 |
| 资源版本号作 Tag | 例如 `tag = "v1.2.3"`,方便按版本整批升级 |
| 取消整批任务 | 取出 `TaskInfo[]` 的 `SerialId`,逐个 `RemoveDownload(serialId)` |
| 携带回调上下文 | 用 `userData` 参数把回调塞进任务,Tag 仍按业务分类 |

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `GetDownloadInfos(tag)` 始终返回空 | 添加任务时没传 Tag,或 Tag 字符串不一致(大小写、空格) | 确认 `AddDownload` 用了带 `tag` 的重载,并把 Tag 存为常量 |
| 同一文件被加了多个 Tag 重复下载 | 不同 Tag 是独立任务,框架不会自动去重 | 用一个全局字典按 `downloadUri` 查重,或固定使用同一个 Tag |
| 调用 `AddDownload` 抛 `Download path is invalid.` / `Download uri is invalid.` | `downloadPath` 或 `downloadUri` 为空字符串或 null | 调用前判空,Tag 不影响这两个参数的校验 |

错误消息原文: [DownloadManager.cs#L360-L368](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L360-L368)

## 背景(可选)

`DownloadTask` 内部把 Tag 存为 `TaskBase.Tag`(字符串字段),`m_TaskPool` 按 Tag 维护任务集合,`GetDownloadInfos(tag)` 实际委托给 `m_TaskPool.GetTaskInfos(tag)`。Tag 只用于"分组 + 查询",不会影响下载优先级、并发数或失败重试策略——这些行为由 `priority` 和 `DownloadComponent` 的全局参数决定。Source: [DownloadTask.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs)
