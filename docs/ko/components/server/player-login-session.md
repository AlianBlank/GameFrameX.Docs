# 플레이어 로그인 및 세션(Session) 처리 방법

이 페이지는 두 가지 작업을 안내합니다: 플레이어가 클라이언트 메시지를 통해 로그인을 완료하도록 하는 것, 그리고 중복 로그인/연결 끊김 시 플레이어의 네트워크 세션을 올바르게 관리하는 것입니다. 완료하면 플레이어는 게임 로직에 진입할 수 있고, 서버도 오프라인 플레이어를 올바르게 정리할 수 있습니다.

## 사전 조건

- 클라이언트는 프레임워크 네트워크 레이어(KCP/HTTP)를 통해 요청을 보내며, 로그인 메시지는 Protobuf 프로토콜 번호 `ReqPlayerLogin` / `RespPlayerLogin`을 사용합니다.
- 서버에서 `GameApp`이 시작되었고, `SessionManager`가 등록되어 있습니다(프레임워크 시작 시 자동으로 로드됨).
- 계정 서비스 `LoginComponent`가 이미 존재하며([LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs) 참조), 계정 Token을 통해 `roleId`를 가져올 수 있습니다.

## 작업 단계

### 1. 로그인 요청 핸들러 구현

새로 `ReqPlayerLoginHandler`를 생성하고 `GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>`를 상속합니다. 프레임워크는 `[MessageMapping]`에 따라 메시지를 자동으로 라우팅합니다.

```csharp
using GameFrameX.Hotfix.Logic.Player.Login;
using GameFrameX.Apps.Player.Login.Component;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[MessageMapping(typeof(ReqPlayerLogin))]
internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
{
    protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
    {
        await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
    }
}
```

출처: [ReqPlayerLoginHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L30-L38)

### 2. LoginComponentAgent에서 바인딩 완료

`OnPlayerLogin` 내부에서는 순서대로 네 가지 작업을 수행합니다: 계정/서명 검증 → `roleId` 획득 → `roleId`와 `sign`을 현재 `Session`에 기록 → `SessionManager.UpdateSession` 호출로 바인딩 완료 및 중복 로그인 로직 트리거.

```csharp
// 의사 코드이며 호출 순서를 보여줍니다. 실제 시그니처는 LoginComponentAgent를 참조하세요.
var loginResult = await LoginComponent.LoginByToken(request.AccountToken); // roleId / sign 반환
NetWorkChannel.Session.SetPlayerId(loginResult.RoleId);
NetWorkChannel.Session.SetSign(loginResult.Sign);
await SessionManager.UpdateSession(NetWorkChannel.Session.SessionId, loginResult.RoleId, loginResult.Sign);
```

실제 시그니처는 `LoginComponentAgent.OnPlayerLogin(NetWorkChannel, request, response)`에서 제공됩니다. [LoginComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs)를 참조하세요.

### 3. Session 제거 이벤트 리스닝으로 로그아웃 마무리

`SessionRemoveEventListener`를 구현합니다. 프레임워크는 세션이 제거될 때(명시적 `Remove` 또는 중복 로그인 시 기존 세션 정리) `EventId.SessionRemove` 이벤트를 발생시켜 플레이어 로그아웃 로직을 트리거합니다.

```csharp
using GameFrameX.Apps.Common.Event;
using GameFrameX.Core.Abstractions.Events;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

출처: [SessionRemoveEventListener.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L30-L42)

### 4. 중복 로그인 및 세션 교체(프레임워크에서 이미 구현됨)

`SessionManager.UpdateSession` 내부에서는 먼저 `GetByRoleId(roleId)`를 호출하여 기존 세션을 찾고, `WriteAsync`를 통해 기존 연결에 `Type=5` 알림 메시지(`Apps.SessionManager.AccountAlreadyLoggedIn` 현지화 문구)를 전송한 다음, `ClearData()` + `Close()`를 실행하고, 마지막으로 `Remove(oldSession.SessionId)`를 호출합니다. 비즈니스 측에서 중복 로그인을 다시 구현할 필요는 없으며, `UpdateSession`을 호출했는지만 확인하면 됩니다.

```csharp
// SessionManager.UpdateSession에서 발췌
var oldSession = GetByRoleId(roleId);
if (oldSession != null)
{
    var msg = new RespPrompt { Type = 5,
        Content = LocalizationService.GetString(Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn) };
    await oldSession.WriteAsync(msg);
    oldSession.WorkChannel.ClearData();
    oldSession.WorkChannel.Close();
    Remove(oldSession.SessionId);
}
```

출처: [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L216-L240)

## 일반적인 변형

| 시나리오 | 방법 |
|------|------|
| 동일 플레이어가 동일 기기에서 반복 로그인 | `Session.Sign`이 동일하므로 `UpdateSession`으로 바인딩만 교체하며, 기존 연결을 강제 종료하지 않음 |
| 동일 플레이어가 다른 기기에서 로그인 | `Sign`이 다르므로 기존 세션이 종료되고 `Type=5` 알림 메시지를 받음 |
| HTTP를 통한 로그인 | [ReqLoginHttpHandler](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs)가 계정 Token을 처리하고, 비즈니스 측에서 `roleId`를 받은 후 클라이언트 `ReqPlayerLogin`을 통해 바인딩 완료 |
| GM 강제 퇴장 | `SessionManager.KickOffLineByUserId(roleId)`를 호출하면 `SessionRemove` 이벤트가 자동으로 발생함 |

## 자주 발생하는 오류

- **`UpdateSession` 호출 누락**: 로그인 검증은 통과했지만 `roleId`가 바인딩되지 않아, 이후 `PlayerId`로 세션을 조회할 수 없고 모든 플레이어 로직이 작동하지 않습니다.
- **`SessionRemove` 리스닝 누락**: 플레이어 연결 끊김 후 메모리 객체가 정리되지 않아 리소스 누수가 발생하고, 재접속 시 오래된 데이터를 받게 됩니다.
- **중복 로그인 안내 문구 미현지화**: 하드코딩된 문자열을 사용하여 `LocalizationService.GetString`을 우회하면, 다국어 환경에서 알림이 올바르게 표시되지 않습니다.
- **세션을 수동으로 `Remove`한 후 다시 수동으로 `Close`**: 프레임워크는 `UpdateSession` 내부에서 이미 기존 연결의 종료를 처리하므로, 비즈니스 측에서 한 번 더 호출하면 `SessionRemove`가 중복 트리거됩니다.

## 배경(선택 사항)

- `Session`은 연결 수준의 객체로, 내부에 `INetWorkChannel`을 보유하며, `SetData(GlobalConst.SessionIdKey, ...)`를 통해 네트워크 채널과 서로 바인딩됩니다.
- `SessionManager`는 `ConcurrentDictionary<string, Session>`을 사용하여 세션을 저장하고, 크로스 서버 라우팅을 위해 `PlayerRouteMap`을 유지 관리합니다. 중복 로그인 시 먼저 `Remove`한 후 `Disconnected` 콜백을 기다리는 방식으로 정리 지연을 방지합니다.
- 중복 로그인 알림 메시지 `Type=5`는 `RespPrompt` 프로토콜로 전달되며, 문구는 `Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn`에서 가져옵니다.
