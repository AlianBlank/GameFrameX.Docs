# 快速開始：第一個狀態機

依照本頁的步驟，您可以在 5 分鐘內執行 GameFrameX FSM 的最小閉環：定義狀態 → 建立 FSM → 啟動狀態 → 在狀態內轉換及讀寫資料。

## 前置條件

- Unity 2019.4 或以上版本
- 已透過 `Packages/manifest.json` 安裝 `com.gameframex.unity.fsm` 1.1.1(或使用 Git URL 直接連結至儲存庫)

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.fsm": "1.1.1"
  }
}
```

安裝後，`FsmComponent` 會以 `[GameFrameXAutoComponent(-6000)]` 自動附加至 `GameFramework` 啟動物件。

## 操作步驟

### 1. 定義狀態類別

繼承 `FsmState<T>`(`T` 為 FSM 擁有者型別)。依需要覆寫 6 個生命週期鉤子。在狀態內透過 `ChangeState<TNext>(fsm)` 觸發轉換。

```csharp
using GameFrameX.Fsm;
using UnityEngine;

public class Player { /* 玩家業務欄位 */ }

public class IdleState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        Debug.Log("Idle 進入");
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        if (Input.GetKeyDown(KeyCode.W))
        {
            ChangeState<MoveState>(fsm);
        }
    }

    protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
}

public class MoveState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        fsm.SetData("Speed", 5.0f);
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds) { }
}
```

來源:[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L97-L122)

### 2. 建立並啟動 FSM

透過 `FsmComponent` 建立，建立時一次傳入所有初始狀態的執行個體，最後使用 `Start<TState>()` 選擇進入狀態。

```csharp
using GameFrameX;
using GameFrameX.Fsm;
using GameFrameX.Fsm.Runtime;

var fsmComponent = GameEntry.GetComponent<FsmComponent>();
IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
fsm.Start<IdleState>();
```

`CreateFsm` 會由 [FsmManager](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs) 透過物件池分配 `Fsm<T>` 執行個體並填入 states 字典。`Start<T>` 會設定目前狀態並觸發 `OnEnter`。

### 3. 狀態間的轉換與資料讀寫

狀態中的 `IFsm<T> fsm` 參數不僅能觸發轉換，還提供狀態之間的鍵值資料存放區(`Variable` 內部會統一裝箱)。

```csharp
// 在所有狀態的 OnEnter / OnUpdate / OnLeave 內
fsm.SetData("Health", 100);
int hp = fsm.GetData<int>("Health");

if (fsm.HasData("Health"))
{
    fsm.RemoveData("Health");
}
```

進行狀態轉換時呼叫 `ChangeState<TNext>(fsm)`,框架會自動先呼叫前一個狀態的 `OnLeave(..., isShutdown: false)`,再呼叫新狀態的 `OnEnter`。

### 4. 銷毀 FSM

不再需要時呼叫 `DestroyFsm`,框架會觸發 `OnDestroy`,並將其回收至 `FsmManager` 的物件池。

```csharp
fsmComponent.DestroyFsm(fsm);
```

## 常見變化

| 情境 | 撰寫方式 |
|------|------|
| 同一擁有者型別需要多組 FSM 並存 | 使用 `CreateFsm(owner, name, new IdleState(), ...)` 多載傳入名稱 |
| 在執行階段新增狀態 | `fsm.AddState(new JumpState())` |
| 在執行階段移除非目前狀態 | `fsm.RemoveState<IdleState>()` |
| 保留狀態集合、清空資料並回到初始狀態 | `fsm.Reset()`,然後以 `Start<T>()` 重新啟動 |
| 以物理影格驅動 | 覆寫 `OnFixedUpdate` 後，`FsmComponent.FixedUpdate` 會自動分派 |
| 快速存取進入點(需要 com.gameframex.unity.entry) | 以 `GameApp.Fsm.CreateFsm(...)` 取代 `GameEntry.GetComponent<FsmComponent>()` |

## 常見錯誤

- **找不到 `FsmComponent`**:Unity 場景中未附加 `GameFramework` 啟動預製物件，因此元件不會自動實例化。
- **`Start<T>` 發生例外**：傳入的狀態型別未在建立時註冊。必須先加入 `CreateFsm` 的參數清單或 `AddState`。
- **資料未儲存**:`SetData` 內部會以 `Variable` 裝箱，因此讀取實值型別時必須使用相同泛型參數的 `GetData<int>("Health")`。
- **狀態轉換未生效**:`ChangeState<TNext>(fsm)` 必須在狀態鉤子內呼叫，且 `TNext` 必須已註冊。
- **同一 owner 的狀態機銷毀後再次 `Start`**:應先確認 `IsDestroyed == false`,否則必須重新呼叫 `CreateFsm`。

## 背景(選用)

`Fsm<T>` 內部使用 `Dictionary<Type, FsmState<T>>` 儲存狀態，`m_CurrentStateTime` 會在 `Update` 中累加。您可以在偵錯工具或自訂 Inspector 中讀取 `CurrentStateName` / `CurrentStateTime`。所有 FSM 皆由 `FsmManager` 集中管理，並透過 `FsmComponent` 向上層公開。
