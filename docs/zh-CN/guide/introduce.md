# 什么是 GameFrameX？

**一句话：一套帮你把游戏「从点子 → 做出来 → 上线运营」全包圆的开源工具箱。**

它不是一个引擎，也不是一个编辑器——你在 Unity / Godot 里做游戏，GameFrameX 负责把你做游戏时**真正费劲的脏活累活**全部包掉。

## 为什么选 GameFrameX？六大硬核优势

### ✅ 优势一：服务器开箱即用，不用从零造轮子

从零写联机服务器，一个人至少要折腾几个月：网络协议、消息分发、多线程、存档落库……GameFrameX 直接给你一套**生产验证过的 .NET 高性能服务器**（Actor 模型，能扛多人同时在线），10 分钟就能跑起来。

### ✅ 优势二：一套框架，四种引擎随便换

客户端同时支持 **Unity、Godot、Cocos Creator、LayaAir（LayaBox）**。框架层完全一致：你学会在 Unity 里用，切到 Godot 业务代码思路照搬。**不用被单一引擎绑死。**

### ✅ 优势三：Excel 改完就是代码，策划友好

道具、关卡、数值全在 Excel 里改，跑一下 LuBan 脚本，客户端和服务器两端的代码 + 数据**一键同步生成**。再也不用手动搬数据、再也不用「策划改个数值程序加三天班」。

### ✅ 优势四：协议改一处，两端自动同步

客户端 ↔ 服务器「对暗号」的协议，用 ProtoBuf 统一定义。`.proto` 文件改一处，工具一键导出两端 C# 代码——**协议不同步导致的联调事故从根上消灭。**

### ✅ 优势五：热更新原生支持，不发版也能改游戏

内置 HybridCLR（Unity）/ C# 热更（服务器 Hotfix 层）+ YooAsset 资源热更。上线后改逻辑、改资源，**不用等应用商店审核**，玩家下次启动就是新版。

### ✅ 优势六：从开发到运营，全链路都有

MongoDB 自动存档、Docker 一键部署、自带管理后台网页（看数据 / 管玩家 / 发配置）。**别人只给你框架，GameFrameX 连上线之后的事都想好了。**

> 说白了：**一个人也能像一个小团队那样，把一款联网游戏做出来、并且运营下去。**

## 对比一下：用和不用，差多少？

| 环节 | 自己从零搞 | 用 GameFrameX |
|------|-----------|--------------|
| 联机服务器 | 数月开发 + 踩坑 | 下载即用，10 分钟跑通 |
| 配置表 | 手写解析、两端各一套 | Excel 改完一键生成 |
| 客户端协议 | 手写序列化、易出错 | 工具自动导出两端代码 |
| 玩家存档 | 自己设计存储方案 | 继承一个类，自动落 MongoDB |
| 热更新 | 自己搭热更框架 | 原生内置，开箱即用 |
| 上线运营 | 另购后台 / 自己写 | 自带管理后台 |

## 适合谁用？

- 想做**联网 / 网游**、但被「服务器怎么搞」卡住的独立开发者
- 想快速搭个**游戏原型**验证点子的小团队
- 想完整学一遍「客户端 + 服务器 + 后台」全流程的学习者

## 里面都有什么技术？

你不需要现在就搞懂下表每一项，混个眼熟即可，后面用到时再回头查：

| 技术 | 在项目里干什么 | 什么时候会接触到 |
|------|--------------|----------------|
| .NET 10 | 编写和运行游戏服务器 | 环境准备就要装 |
| MongoDB | 存玩家数据（账号、角色、背包……） | 第一步跑数据库就用到 |
| Docker | 一条命令把 MongoDB 跑起来（可选，也可用官方免费云库） | 第一步跑数据库就用到 |
| LuBan | Excel 配置表 → 代码 + 数据 | 改数值、加道具时用到 |
| ProtoBuf | 客户端 ↔ 服务器的通讯协议 | 加新消息时用到 |
| FairyGUI | 做 UI 界面 | 改界面时用到 |
| HybridCLR | C# 代码热更新（不发版也能改逻辑） | 进阶内容 |
| YooAsset | 资源管理和热更下载 | 进阶内容 |

## 完全开源吗？

服务器、客户端框架、配置和协议工具全部开源（Apache 协议）。管理后台 GameFrameX.Admin 部分源码不开源，但有[在线演示](https://game.admin.web.vue.alianblank.com)可以先看效果。
