# Inspector 잠금 단축키 사용

이 기능은 Unity Editor 메뉴 명령을 통해 Inspector 창 잠금 상태를 전환합니다. 기본 단축키는 `%l`입니다. macOS에서는 일반적으로 `Command + L`, Windows/Linux에서는 일반적으로 `Ctrl + L`을 의미합니다.

## 사전 조건

- 프로젝트가 Unity Editor 내에 있습니다.
- `Editor/InspectorLockShortcut/InspectorLockShortcut.cs`가 Editor 어셈블리로 컴파일되었습니다. 일반적으로 파일이 `Editor` 디렉터리에 있는 것만으로 충분합니다.

## 작업 단계

1. 임의의 Unity Editor 창을 열고 Inspector 창이 생성되었는지 확인합니다.
2. `Ctrl + L`을 누릅니다(macOS에서는 `Command + L`). 또는 **Window > Toggle Inspector Lock**을 엽니다.
3. 잠금을 해제하려면 동일한 단축키를 다시 실행합니다. 메뉴 항목과 단축키는 모두 `Window/Toggle Inspector Lock %l`로 등록됩니다.

핵심 구현은 다음과 같습니다.

```csharp
using UnityEditor;

namespace GameFrameX.Editor
{
    public sealed class InspectorLockShortcut : EditorWindow
    {
        [MenuItem("Window/Toggle Inspector Lock %l")]
        private static void ToggleInspectorLock()
        {
            // 获取Inspector窗口
            var inspectorType = typeof(UnityEditor.Editor).Assembly.GetType("UnityEditor.InspectorWindow");
            var inspectorWindow = EditorWindow.GetWindow(inspectorType);
            // 使用反射调用isLocked属性
            var isLockedProperty = inspectorType.GetProperty("isLocked");
            var isLocked = (bool)isLockedProperty.GetValue(inspectorWindow);
            isLockedProperty.SetValue(inspectorWindow, !isLocked);
            // PrefabUtility.CreatePrefab( "Assets/Editor/ToggleInspectorLock.prefab", inspectorWindow);
        }
    }
}
```

## 일반적인 변형

- 메뉴 작업: **Window > Toggle Inspector Lock**를 선택하면 단축키를 기억할 필요가 없습니다.
- Inspector를 장기간 고정해야 할 때 단축키를 연속해서 눌러도 한 번만 전환됩니다. 잠금 후 현재 선택이 Inspector 내용에 영향을 미치는지 확인해야 합니다.

## 일반적인 오류

- **단축키가 응답하지 않음**: 포커스가 Unity Editor에 있는지, 다른 앱에 있지 않은지 확인합니다. 또한 시스템이 `Ctrl/Command + L`을 가로채지 않는지 확인합니다.
- **Inspector에 잠금 동작이 표시되지 않음**: 먼저 Inspector 창을 열거나 가져옵니다. 구현에서는 `EditorWindow.GetWindow(inspectorType)`을 통해 이 창을 가져옵니다.
- **단축키 충돌 수정**: `%l`은 `MenuItem`修饰符 구문이며, 일반적인 런타임 코드가 아닙니다. 수정하기 전에 Unity의 단축키 설정에서 충돌을 확인해야 합니다.

## 배경

이 구현은 리플렉션을 사용하여 UnityEditor 어셈블리의 `InspectorWindow.isLocked` 속성에 접근한 다음 현재 값을 반전시켜 다시 씁니다. 소스 코드에는 추가 영구 구성이나 이벤트 처리가 없습니다.
