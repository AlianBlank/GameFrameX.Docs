# UI 打开失败或白屏怎么办

当你调用 `GameApp.UI.OpenAsync<T>()` 之后界面没有出现、显示为白屏、或者整屏没反应,通常是因为 FairyGUI 资源包没有先加载、UI 路径写错、或者 UI 组件没有挂到场景根节点。本页按症状给出对应排查方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameApp.UI.OpenAsync<UILogin>()` 之后没报错但什么都没出现 | 目标 UI 所在的 FairyGUI 包没有 `AddPackageAsync` | 在打开 UI 前调用 `GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.XXX))` |
| 报"找不到包"或资源加载失败 | `FUIPackage` 枚举项写错 / 包名与打包资产不匹配 | 核对 `FUIPackage` 枚举值与 FairyGUI 编辑器里实际打包名 |
| UI 打开了但是整块白屏 | 走的是非全屏接口、而目标 UI 是 `OpenFullScreen` 类型,层级被遮盖 | 改用 `OpenFullScreenAsync<T>(path, group)` 并传入对应的 `UIGroupConstants` |
| 报"找不到 UI 路径" | `GetUIPath(nameof(X))` 的 `nameof(X)` 类名和真实类不一致 | 类名要与 FairyGUI 资源里 `Package_XXX` 生成的 `X.cs` 一致 |
| Hotfix 里调用 `GameApp.UI` 提示为空 | 还没等 `LoadUI()` 执行完就访问 | `await` 上面的加载,或把后续逻辑放进 `OpenAsync` 的续延里 |
| UI 能弹但立刻又消失 | 没有 await `CloseUIForm`,或者上层立刻又 `OpenUIForm` 把它覆盖 | 检查调用顺序,确保 `CloseUIForm<T>` 在 `await OpenAsync` 之后调用 |

## 修复步骤

### 1. UI 完全没出现 — 补加载 FairyGUI 包

框架要求在打开任何一个 UI 之前,先把对应的 FairyGUI 资源包加载进来。`HotfixLauncher.LoadUI` 已经演示了标准做法:

```csharp
#if ENABLE_UI_FAIRYGUI
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommon));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommonAvatar));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UIRoom));
#endif
await GameApp.UI.OpenAsync<UILogin>();
```

`FUIPackage.XXX` 枚举值必须和 FairyGUI 编辑器里导出的包名一致(例如 `UIRoom`、`UICommon`)。漏掉一个包,该包里所有 UI 都打不开。

Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L46)

### 2. 白屏或被遮盖 — 用对打开接口

打开"全屏类 UI"(登录、角色列表、主界面)必须使用 `OpenFullScreenAsync`,并传入 UI 组:

```csharp
await GameApp.UI.OpenFullScreenAsync<UIPlayerList>(
    Utility.Asset.Path.GetUIPath(nameof(UILogin)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

普通 `OpenAsync<T>()` 适合弹窗、提示框之类非全屏组件。如果目标 UI 实际上是全屏布局却用 `OpenAsync`,会出现"看似打开、实际被遮住或没绘制"的白屏现象。

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 3. 关闭后再开要 await

`CloseUIForm` 必须发生在 `await OpenAsync/OpenFullScreenAsync` 之后,否则上层 UI 会先把当前界面盖掉:

```csharp
await GameApp.UI.OpenFullScreenAsync<UIMain>(
    Utility.Asset.Path.GetUIPath(nameof(UIMain)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 4. 类名与 FairyGUI 生成代码保持一致

`GetUIPath(nameof(X))` 中传入的 `X` 必须和 FairyGUI 导出工具生成的 `Package_X.cs` 类名一致。如果改了类名忘了同步,会出现路径找不到、白屏、或者打开的是上一个旧界面。

### 5. 弹窗型 UI 关闭示例

通用确认/取消弹窗关闭时直接调用:

```csharp
GameApp.UI.CloseUIForm<UIDialogMessageBox>();
data.OnEnter?.Invoke();
```

Source: [UIDialogMessageBox.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UICommon/UIDialogMessageBox.cs#L22-L29)

### 6. Launcher 阶段的 UI 关闭

`LauncherUIHandler` 在初始化完成时会关掉启动界面:

```csharp
GameApp.UI.CloseUIForm<UILauncher>();
_ui = null;
```

Source: [LauncherUIHandler.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/LauncherUIHandler.cs#L66-L67)

## 验证

- 在 `LoadUI()` 里把所有 UI 用到的 `FUIPackage` 枚举项都注册一遍,启动日志里能看到对应包的加载行。
- `await OpenAsync<T>()` 返回后,Hierarchy 里能看到 `T` 实例挂到 FairyGUI 的 Stage 下,而不是停留在 Root 之外。
- 全屏 UI 切换时,在过渡期间旧界面会被新界面盖住而不是白屏一闪而过。
- 关闭后再调用 `OpenAsync<T>()`,新界面能正常显示(说明资源没被一次性回收,或者你已在销毁逻辑里正确释放)。

## 背景(可选)

`HotfixLauncher.LoadUI` 会先把 `UICommon`、`UICommonAvatar`、`UIRoom` 这些基础包预加载,然后再 `await OpenAsync<UILogin>`。后续 `UIPlayerList → UIMain` 的链式跳转都遵循"await 打开 → CloseUIForm 自己"的模式,这也是避免白屏/层级混乱的关键约定。
