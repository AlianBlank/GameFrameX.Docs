# Listener Not Firing or Callback Timing Incorrect

When you register callbacks via `MonoComponent.AddUpdateListener / AddFixedUpdateListener / AddLateUpdateListener / AddDestroyListener / AddOnApplicationFocusListener / AddOnApplicationPauseListener`, but the function doesn't execute at runtime, or the execution order doesn't match expectations, follow the steps in this page to troubleshoot.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Console outputs `Mono manager is invalid.` | No `MonoComponent` attached in the scene; framework module `IMonoManager` is not registered | See "Scene Missing MonoComponent" below |
| Console outputs `Event manager is invalid.` | No `EventComponent` attached in the scene; `OnApplicationFocus/Pause` events cannot be dispatched | See "EventComponent Missing" below |
| Listener never fires, no error reported | When `AddXxxListener` is called in `Awake`, `_monoManager` is still `null` | See "Registration Timing Earlier Than Awake" below |
| Listener fires only once, then silently afterwards | `null` was passed when calling `AddXxxListener` inside the callback, `MonoComponent` silently `return`s | See "Callback Function is null" below |
| `AddOnApplicationFocusListener` doesn't fire, but Update works normally | `EventComponent` is not attached; the event branch in `MonoComponent.OnApplicationFocus` is skipped directly | See "EventComponent Missing" below |
| Exception thrown inside callback is swallowed; subsequent listeners still execute | `QueueInvoking` wraps every `action.Invoke()` with `try/catch`, only writing `Log.Error` | See "Exceptions Inside Callbacks Silently Swallowed" below |
| LateUpdate listener executes before Update | Registration position is after `Update`; the manager dispatches in `LinkedList` order | See "Listener Registration Order vs Execution Order" below |
| Registered in `OnApplicationFocus(true)`, but only called once when losing and regaining focus simultaneously | Unity may merge events when the editor loses/gains focus | See "Editor Focus Loss Behavior" below |

## Fix Steps

### Scene Missing MonoComponent

`MonoComponent.Awake()` retrieves the module via `GameFrameworkEntry.GetModule<IMonoManager>()`; if it can't be retrieved, it calls `Log.Fatal("Mono manager is invalid.")` and directly `return`s. Afterwards, all Unity callbacks (`FixedUpdate / LateUpdate / OnDestroy / OnApplicationFocus / OnApplicationPause`) are skipped because `_monoManager == null`:

```csharp
// Runtime/Mono/MonoComponent.cs
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IMonoManager);
    base.Awake();
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs#L52-L63](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L63)

Fix:

1. On the `GameFramework` object in the game startup scene, click `Add Component → GameFrameX/Mono` to add `MonoComponent`.
2. Confirm that the object also has `BaseComponent` attached (framework entry); otherwise the module chain won't start.
3. Re-run the scene and confirm `Mono manager is invalid.` no longer appears in the console.

### EventComponent Missing

In addition to calling the callback on `_monoManager`, `OnApplicationFocus` and `OnApplicationPause` also broadcast the event to subscribers via `EventComponent.Fire`. If `m_EventComponent == null`, the event branch is skipped directly:

```csharp
// Runtime/Mono/MonoComponent.cs
private void OnApplicationFocus(bool focusStatus)
{
    if (_monoManager == null) { return; }
    _monoManager.OnApplicationFocus(focusStatus);
    if (m_EventComponent != null)
    {
        m_EventComponent.Fire(this, OnApplicationFocusChangedEventArgs.Create(focusStatus));
    }
}
```

Source: [MonoComponent.cs#L111-L123](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L111-L123)

Fix:

1. Add `EventComponent` on the same `GameFramework` object (`Add Component → GameFrameX/Event`).
2. Use `EventComponent.Subscribe` on the subscriber side to subscribe to `OnApplicationFocusChangedEventArgs.EventId`, rather than only calling `AddOnApplicationFocusListener`.
3. After running, you should see events dispatched in the logs.

### Registration Timing Earlier Than Awake

`_monoManager` is only assigned in `MonoComponent.Awake()`. If you call `GameEntry.GetComponent<MonoComponent>().AddUpdateListener(...)` in your own script's `Awake`, due to the undefined `Awake` order of scripts, you may get a `MonoComponent` instance where `_monoManager` hasn't been initialized yet. Even if it's assigned later, newly registered callbacks will work, but note: if `MonoComponent` hasn't called `Awake` yet, its internal `_monoManager` is `null`, and all `AddXxxListener` calls will fail to enqueue because `_monoManager` isn't initialized (the actual manifestation is a `NullReferenceException` or `Log.Fatal` output inside `MonoComponent` saying `fun is invalid.`).

Fix:

- Put registration logic in `Start`, or add `if (comp == null) return;` after getting `MonoComponent`.
- You can also get the manager directly via `GameFrameworkEntry.GetModule<IMonoManager>()`, bypassing `MonoComponent`.

### Callback Function is null

`MonoComponent.AddXxxListener` only writes `Log.Fatal` and `return`s for a `null` argument; it does not throw an exception nor enqueue:

```csharp
// Runtime/Mono/MonoComponent.cs
public void AddUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddUpdateListener(fun);
}
```

Source: [MonoComponent.cs#L207-L216](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L207-L216)

Whereas `MonoManager.AddXxxListener` throws `ArgumentNullException` directly on `null`. The semantics differ between the two layers—don't confuse them when writing code.

Fix:

- When registering, make sure `fun` is a non-null method group or lambda; don't pass `default(Action<float, float>)`.
- If `fun is invalid.` appears in the console, that's where `null` was passed.

### Exceptions Inside Callbacks Silently Swallowed

`MonoManager.QueueInvoking` wraps a `try/catch` around each listener during dispatch; exceptions are only written out via `Log.Error` and don't interrupt subsequent listeners:

```csharp
// Runtime/Mono/MonoManager.cs
foreach (var action in snapshot)
{
    try
    {
        UnityEngine.Profiling.Profiler.BeginSample($"QueueInvoking-{action.Method.Name}-{action.Target}");
        action.Invoke();
        UnityEngine.Profiling.Profiler.EndSample();
    }
    catch (Exception e)
    {
        Log.Error(e);
    }
}
```

Source: [MonoManager.cs#L319-L330](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L319-L330)

Fix:

- Search the console for `Log.Error` with the `QueueInvoking-` prefix to locate which listener threw the error.
- Use `try/catch` inside the callback to protect critical logic yourself, to avoid the situation where one listener's exception is ignored and it looks like "nothing happened".

### Listener Registration Order vs Execution Order

`MonoManager` stores listeners using `LinkedList<Action<...>>`, and traverses in enqueue order during dispatch. `LateUpdate` is dispatched after all `Update`s, but `MonoComponent` itself has no `Update` method (the source only contains `FixedUpdate`, `LateUpdate`, `OnDestroy`, `OnApplicationFocus`, `OnApplicationPause`):

```csharp
// Runtime/Mono/MonoComponent.cs
private void FixedUpdate() { _monoManager.FixedUpdate(); }
private void LateUpdate()  { _monoManager.LateUpdate(); }
```

Source: [MonoComponent.cs#L81-L92](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L81-L92)

In other words: **the framework has no Update hook**. If you think there is an `AddUpdateListener`, there actually is (`MonoManager._updateQueue` + `AddUpdateListener`), but the `MonoBehaviour.Update` that drives it is not explicitly declared in `MonoComponent`—this usually means the project needs to trigger `_monoManager.Update` via some other means (e.g., manually calling it inside a custom `MonoBehaviour.Update`, or confirming whether there's an inherited version).

Fix:

- Confirm that the project actually has `MonoBehaviour.Update` calling `_monoManager.Update()`; if there's only `MonoComponent`, Update listeners won't fire and you need to add it yourself.
- Relative order between listeners: callbacks registered first via `AddXxxListener` execute first, later registrations execute later. Register in order when strict sequencing is required.
- When focus is gained/lost multiple times in the same frame, Unity triggers events in the actual order they occur; the framework does not merge them.

### Editor Focus Loss Behavior

`OnApplicationFocus` triggers in the editor when: the window loses focus, clicking Play, Stop. Frequent triggering during development is normal. If it "appears not to fire" only in the editor, it's recommended to build to a real device or check `Edit → Project Settings → Player → Run In Background` before observing again.

## Verification

- `Mono manager is invalid.`, `Event manager is invalid.`, `fun is invalid.` no longer appear in the console.
- Register a simplest `Debug.Log` listener (e.g., `AddUpdateListener((a, b) => Debug.Log("update " + a))`), and you should see per-frame logs after running.
- When `OnApplicationFocus/Pause` switches window focus, the logs or event subscribers receive the corresponding event.
- When a callback throws an error, you should see an exception matching `QueueInvoking-YourMethod-YourTarget` in the logs, rather than complete silence.
