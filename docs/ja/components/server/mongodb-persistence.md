# MongoDB を使用してプレイヤーデータを永続化する方法

この章では、`GameFrameX.DataBase.Mongo` をゲームサーバーに統合し、プレイヤーデータの追加・検索・更新・削除とトランザクション書き込みを完了する方法を説明します。このページを読み終えると、サーバーで MongoDB ベースのプレイヤーデータ保存を直接実行できるようになります。

## 前提条件

- MongoDB がインストール済みであること（ローカルまたはクラスターのいずれでも可）。`mongodb://user:password@host:27017` の形式の接続文字列と対象データベース名が用意されていること。
- サーバープロジェクトに `GameFrameX.DataBase.Mongo` パッケージが追加されていること（名前空間 `GameFrameX.DataBase.Mongo`）。`GameFrameX.DataBase.Abstractions` の `IDatabaseService`、`DbOptions` にアクセス可能であること。
- プレイヤーデータの型は `BaseCacheState` を継承している必要があります。MongoDB は `typeof(T).Name` をコレクション名として使用します。

## 操作手順

### 1. サービスを作成して開く

`MongoDbService` はコアエントリポイントであり、`IDatabaseService` を実装します。`Open(DbOptions)` で接続を確立し、内部で `ping` 検証を実行し、`300 / 700 / 1500 ms` のバックオフで 3 回リトライします。失敗した場合は自動的に異常状態になり、リカバリータスクが起動します。

```csharp
using GameFrameX.DataBase.Mongo;
using GameFrameX.DataBase.Abstractions;

var mongo = new MongoDbService();
var options = new DbOptions
{
    ConnectionString = "mongodb://localhost:27017",
    Name = "GameFrameX",
};
bool ok = await mongo.Open(options);
if (!ok) throw new InvalidOperationException("MongoDB 初始化失敗");
```

設定項目 `Options.ConnectionString` と `Options.Name` は両方とも必須です。`Open` を繰り返し呼び出した場合に対象が同じであれば既存の接続を再利用し `ping` を再実行し、そうでなければ接続をリセットします。

### 2. プレイヤーデータ型を定義する

プレイヤーデータは `BaseCacheState` を継承する必要があります。フレームワークは書き込み時に `CreatedTime` と `UpdateTime` を自動的に管理し、コレクション名はデフォルトで型名になります。

```csharp
using GameFrameX.DataBase.Abstractions;

public sealed class PlayerState : BaseCacheState
{
    public string Name { get; set; }
    public int Level { get; set; }
    public long Gold { get; set; }
}
```

コレクションは `MongoDbContext.GetCollection<T>()` から取得され、返される `IMongoCollection<T>` は `typeof(T).Name` で命名されます。

### 3. プレイヤーデータを追加する

追加インターフェースは `MongoDbService.Add.cs` にあり、タイムスタンプを自動的に入力し、リトライ付きの書き込みチャネルを経由します：

```csharp
var player = new PlayerState { Id = "p_1001", Name = "Alice", Level = 1, Gold = 0 };
await mongo.AddAsync(player);
await mongo.AddListAsync(new[] { player, anotherPlayer }); // 一括、IsOrdered=false
```

`BulkWriteOptions` のデフォルトは `{ IsOrdered = false }` で、一括挿入は並列実行可能です。

### 4. 検索と更新

サービスは `MongodbService.Query.cs`、`MongoDbService.Update.cs` でそれぞれ読み取りパスと書き込みパスを担当します。読み取り操作のデフォルトの遅延バックオフは `{120, 300, 700} ms`、冪等な書き込みは `{150, 400, 900} ms`、トランザクションは `{200, 500, 1000} ms` です。一般的な使用方法：

```csharp
// 単一更新
await mongo.UpdateAsync(player);

// Id で存在を判定し、存在しなければ挿入；存在する場合はフィールド集合を更新（冪等）
await mongo.AddOrUpdateAsync(player);
await mongo.AddOrUpdateListAsync(manyPlayers);
```

### 5. ソフトデリートとトランザクション

削除インターフェースはソフトデリートとハードデリートをサポートしています。複数ステップの書き込みはトランザクションに入れることができます：

```csharp
await mongo.DeleteAsync(player);                 // ソフトデリート
await mongo.HardDeleteAsync(player);             // 物理削除
await mongo.RestoreAsync(player);                // ソフトデリートから復元
await mongo.ExecuteInTransactionAsync(token =>
{
    // ここで collection に対して複数の書き込み操作を行う
    return Task.CompletedTask;
});
```

### 6. ヘルスチェックと正常なシャットダウン

モジュールには `MongoDbHealthCheck` が組み込まれています：

```csharp
services.AddHealthChecks()
    .AddCheck<MongoDbHealthCheck>("mongodb");
```

サービスを閉じる際は `await mongo.Close()` を呼び出して接続を解放します。実行中は `mongo.AvailabilityState` で `Healthy / Degraded / Unhealthy` の状態を読み取ることができます。

## 一般的なバリエーション

- **データベースを切り替える**：`Open(...)` を再度呼び出し、別の `ConnectionString` / `Name` を渡します。内部で自動的に `MongoClient` と `MongoDbContext` がリセットされます。
- **ランタイムパラメータの調整**：`DbOptions.RuntimeOptions` を `ApplyRuntimeOptions` と組み合わせて使用し、タイムアウトなどの実行時パラメータを調整できます（`MongoDbService.Connection.cs` の 69-84 行目を参照）。
- **カスタムコレクション名**：`MongoDbContext.GetCollection<T>()` は固定で型名を使用します。カスタムが必要な場合は派生して `IMongoDatabase` を再利用してください。
- **指標の計装**：モジュールは `System.Diagnostics.Metrics` を使用して `db_open_retry_total`、`db_operation_latency_ms`、`db_health_status` などの指標を公開します。OpenTelemetry に接続できます。

## よくあるエラー

- **`await mongo.Open(options)` を書き忘れた状態で追加・削除・変更を呼び出す**：`EnsureInitialized()` が例外をスローするため、まず `Open` を成功させる必要があります。
- **`ConnectionString` または `Name` が空**：`Open` が `ArgumentNullException` をスローし、起動時にクラッシュします。
- **プレイヤーの型が `BaseCacheState` を継承していない**：ジェネリック制約 `where TState : BaseCacheState` がコンパイル時にエラーを検出します。
- **トランザクション内で非トランザクション操作を実行する**：`ExecuteInTransactionAsync` は MongoDB デプロイメントがレプリカセット/シャーディングクラスターであることを要求します。スタンドアロンの `mongod` では失敗します。
- **失敗状態を無視する**：`Open` が失敗すると、サービスは `Unhealthy` 状態になり、バックグラウンドのリカバリタスクが起動します。`AvailabilityState` とログ `MongoDbService.Open Exception` の両方を確認してください。

## 背景（オプション）

`MongoDbService` は `sealed partial class` であり、責務ごとに `Add / Update / Delete / Query / Collection / Connection / Index / Retry / Recovery / UpsertTransaction / Availability` などのファイルに分割して実装されています。可用性はプライベートカウンターとホワイトリスト（`NonCriticalReadOperationWhiteList`、`CoreWriteOperationWhiteList`）によって読み書きの降格戦略を決定し、`System.Threading.Volatile` で観測可能な指標を公開します。
