# IL2CPP/AOT ビルド:型がトリミングされるのを防ぐ

本パッケージは、IL2CPP/AOT ビルドにおけるマネージドコードストリッピング(Managed Stripping)に対して二重の防護を内蔵しています。コア型(`TimerComponent`、`TimerManager`、`ITimerManager`)にはすべて `[UnityEngine.Scripting.Preserve]` が付与されており、さらに `GameFrameXTimerCroppingHelper` というトリミング補助クラスを提供して、これらの型を明示的に参照します。本パッケージを正常に導入した後は、追加の設定は一切不要で、型がストリップされることはありません。

## 前提条件

- プロジェクトに本パッケージ(`com.gameframex.unity.timer`)がインストールされていること。
- ターゲットプラットフォームが Player Settings で IL2CPP スクリプティングバックエンドを使用していること(本機構は Mono バックエンドに副作用がなく、そのまま保持できます)。

### 2. トリミング補助クラスがパッケージとともにビルドされることを確認

パッケージ内の `Runtime/GameFrameXTimerCroppingHelper.cs` は、ストリップ防止の第二の防衛線です。クラスとメソッドにはいずれも `[Preserve]` が付与されており、`Start()` 内で `typeof` を使ってすべてのコア型を明示的に参照し、ストリッパーに静的参照ルートを残します:

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Timer.Runtime
{
    [Preserve]
    public class GameFrameXTimerCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(TimerComponent);
            _ = typeof(ITimerManager);
            _ = typeof(TimerManager);
        }
    }
}
```

出典:[GameFrameXTimerCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/GameFrameXTimerCroppingHelper.cs#L1-L17)

このファイルはパッケージの `Runtime` ディレクトリにあり、パッケージとともに自動的にビルドに組み込まれるため、シーンに手動でアタッチする必要はありません。

### 3. ビルドして検証

1. IL2CPP バックエンドに切り替え、実際のプラットフォームでのビルドを1回実行します(Play モードに入るだけではストリッピングの問題は検証できません)。
2. ビルド成果物で型が保持されていることを確認します。以下のいずれかの方法を選んでください:
   - ビルドレポート/ストリッピングログで `GameFrameX.Timer` を検索し、"stripped" に関連する削除記録がないことを確認する。
   - ビルドしたパッケージを実行し、タイマーコンポーネントが正常に初期化され、`AddTimer` といった呼び出しが実行できることを確認する。

## よくあるバリエーション

- **プロジェクト内のリフレクションに依存する他の型がストリップされる場合**:上記の補助クラスのパターンを自分のプロジェクトコードに複製できます。`[Preserve]` 付きの `MonoBehaviour` を新規作成し、`Start()` 内で `typeof` を使って保持したい型を参照します。これは Unity で汎用的に使われるトリミング防止手法であり、本パッケージの `GameFrameXTimerCroppingHelper` はまさにそのパターンの実例です。
- **ストリッピングレベルを引き上げた後にビルドが失敗する場合**:プロジェクトで High/Medium のストリッピングレベルを設定していても、`[Preserve]` と `typeof` による参照ルートは引き続き有効であり、タイマー型のために個別の調整を行う必要はありません。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| IL2CPP ビルドパッケージでタイマーの初期化に失敗する、インターフェース/コンポーネントが解決できない | ストリッパーが静的に参照されていない型を削除した(例:`[Preserve]` 属性やトリミング補助クラスを手動で削除した) | 上記の手順1、2に従ってマークと補助クラスを復元し、再ビルドする |
| エディターでは正常、実機パッケージで異常 | エディターはマネージドストリッピングを実行しないため、問題は AOT ビルドでのみ顕在化する | 実機/シミュレーターのビルドを基準とし、手順3で検証する |
| Play モードのみで検証し、検証済みと誤解する | Play モードは IL2CPP コンパイルとストリッピングを経由しない | 実際のプラットフォームビルドを実行して検証しなければならない |

## 背景

IL2CPP のマネージドコードストリッピングは、静的解析において「誰からも参照されていない」型を削除します。本パッケージの型はフレームワークのリフレクションや自動コンポーネント機構を通じてロードされることが多く、静的参照チェーンが不完全なため、削除可能と誤判定されやすくなっています。`[Preserve]` 属性はストリッパーに対して保持対象を直接伝え、トリミング補助クラスがさらに `typeof` によってコンパイル時に可視の参照ルートを提供します。この2つが重なることで、いかなるストリッピングレベルでも型が保持されることが保証されます。README ではこれを「IL2CPP の安全性——トリミング補助クラスによる AOT ビルドでの型ストリッピングの防止」として掲載しています([README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L35) を参照)。
