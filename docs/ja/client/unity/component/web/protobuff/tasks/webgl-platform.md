# WebGL とクロスプラットフォーム利用ガイド

本ページでは、WebGL とその他のプラットフォーム(エディター、Windows、モバイルなど)で Web ProtoBuff コンポーネントを使用して ProtoBuf HTTP リクエストを送信する方法について説明します。呼び出し側は同一の `Post<T>` API を使用し、コンポーネント内部では `#if UNITY_WEBGL` によって `UnityWebRequest` と `HttpWebRequest` を自動的に切り替えるため、プラットフォームごとにコードを2つ用意する必要はありません。

## 前提条件

- `com.gameframex.unity.web.protobuff` パッケージと、その依存関係(GameFrameX、`GameFrameX.Network`、ProtoBuf ランタイム)がインストール済みであること。
- リクエストとレスポンスのメッセージクラスは `MessageObject` を継承し、レスポンスクラスはさらに `IResponseMessage` を実装していること。
- WebGL ビルドでは IL2CPP を使用します。パッケージには [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs) が同梱されており、ビルド時のトリミング処理に参加します。

## 操作手順

1. **ターゲットプラットフォームのマクロが有効になっていることを確認します**。コンポーネントは `UNITY_WEBGL` マクロが定義されている場合のみ UnityWebRequest のパスを実行します。WebGL プラットフォームに切り替える(File → Build Settings → Switch Platform)と、マクロは自動的に有効になります。

   ```csharp
   using System;
   using System.Collections.Generic;
   using System.Text;
   using GameFrameX.Runtime;
   #if UNITY_WEBGL
   using UnityEngine.Networking;
   #endif
   ```

   ソース: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L1-L7)

2. **プラットフォームの必要に応じてタイムアウトと同時接続数の上限を調整します**。コンストラクターではデフォルトで `Timeout = 5`(秒)、`MaxConnectionPerServer = 8` が設定され、`Timeout` を変更すると `RequestTimeout` も同期的に更新されます。

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public WebProtoBuffManager()
   {
       MaxConnectionPerServer = 8;
       Timeout = 5f;
   }

   public float Timeout
   {
       get { return m_Timeout; }
       set
       {
           m_Timeout = value;
           RequestTimeout = TimeSpan.FromSeconds(value);
       }
   }

   public int MaxConnectionPerServer { get; set; }

   public TimeSpan RequestTimeout { get; set; }
   ```

   ソース: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L27-L54)

3. **直接 `Post<T>` を呼び出してリクエストを送信します**。これはクロスプラットフォームの統一エントリーポイントであり、レスポンスボディはメッセージ Id による型検証の後、`T` として逆シリアル化されます。

   ```csharp
   public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
   {
       DebugSendLog(message);
       var webBufferResult = await PostInner(url, message);
       if (webBufferResult.IsNotNull())
       {
           var messageObjectHttp = SerializerHelper.Deserialize<MessageHttpObject>(webBufferResult.Result);
           if (messageObjectHttp.IsNotNull() && messageObjectHttp.Id != default)
           {
               var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
               if (messageType != typeof(T))
               {
                   Log.Error($"Response message type is invalid. Expected '{typeof(T).FullName}', actual '{messageType.FullName}'.");
                   return default;
               }

               var messageObject = SerializerHelper.Deserialize<T>(messageObjectHttp.Body);
               DebugReceiveLog(messageObject);
               return messageObject;
           }
       }

       return default;
   }
   ```

   ソース: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L182-L205)

   カスタム例(識別子はソースコードと同一にします):

   ```csharp
   // message はリクエストのメッセージオブジェクト。LoginResponse : MessageObject, IResponseMessage
   var response = await webProtoBuffManager.Post<LoginResponse>(url, message);
   ```

4. **WebGL の差異に関する追加の処理は不要です**。リクエストがキューに入ると、`UpdateProtoBuf` は毎フレーム、同時接続数の上限内でデキューして `MakeProtoBufBytesRequest` を呼び出します。このメソッドの内部はプラットフォームごとにコンパイルされます:

   ```csharp
   void UpdateProtoBuf(float elapseSeconds, float realElapseSeconds)
   {
       lock (m_StringBuilder)
       {
           if (m_SendingProtoBufList.Count < MaxConnectionPerServer)
           {
               if (m_WaitingProtoBufQueue.Count > 0)
               {
                   var webProtoBufData = m_WaitingProtoBufQueue.Dequeue();

                   MakeProtoBufBytesRequest(webProtoBufData);

                   m_SendingProtoBufList.Add(webProtoBufData);
               }
           }
       }
   }
   ```

   ソース: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L39-L55)

## 一般的なバリエーション

- **WebGL プラットフォーム**:`UnityEngine.Networking.UnityWebRequest` を使用してリクエストを送信します。`Content-Type` は `application/x-protobuf`、タイムアウトは `RequestTimeout.TotalSeconds`(秒)から取得し、`completed` コールバックによって結果を処理します。`timeout` プロパティは `int` であるため、切り捨てを避けるために `Timeout` は整数秒に設定することを推奨します。

  ```csharp
  #if UNITY_WEBGL
              UnityEngine.Networking.UnityWebRequest unityWebRequest;
              if (webData.IsGet)
              {
                  unityWebRequest = UnityEngine.Networking.UnityWebRequest.Get(webData.URL);
              }
              else
              {
                  unityWebRequest = UnityEngine.Networking.UnityWebRequest.Post(webData.URL, string.Empty);
              }

              unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;
              unityWebRequest.SetRequestHeader("Content-Type", ProtoBufContentType);
              byte[] postData = webData.SendData;
              unityWebRequest.uploadHandler = new UnityEngine.Networking.UploadHandlerRaw(postData);

              var asyncOperation = unityWebRequest.SendWebRequest();
              asyncOperation.completed += (asyncOperation2) =>
              {
                  try
                  {
                      m_SendingProtoBufList.Remove(webData);
                      if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)
                      {
                          webData.Task.TrySetException(new Exception(unityWebRequest.error));
                          return;
                      }

                      webData.Task.SetResult(new WebBufferResult(webData.UserData, unityWebRequest.downloadHandler.data));
                  }
                  finally
                  {
                      unityWebRequest.Dispose();
                      ReferencePool.Release(webData);
                  }
              };
  #else
  ```

  ソース: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L83-L119)

- **WebGL 以外のプラットフォーム**(エディター、デスクトップ、モバイル):`HttpWebRequest` の非同期ストリーム実装を使用します。タイムアウトの単位はミリ秒(`RequestTimeout.TotalMilliseconds`)で、`WebExceptionStatus.Timeout` を `TimeoutException` に変換して上位層にスローします:

  ```csharp
                  HttpWebRequest request = WebRequest.CreateHttp(webData.URL);
                  request.Method = webData.IsGet ? WebRequestMethods.Http.Get : WebRequestMethods.Http.Post;
                  request.Timeout = (int)RequestTimeout.TotalMilliseconds; // リクエストのタイムアウト時間を設定
                  request.ContentType = ProtoBufContentType;
  ```

  ```csharp
              catch (WebException e)
              {
                  // タイムアウト例外をキャッチ
                  if (e.Status == WebExceptionStatus.Timeout)
                  {
                      webData.Task.SetException(new TimeoutException(e.Message));
                      return;
                  }

                  webData.Task.SetException(e);
              }
  ```

  ソース: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L120-L155)

- **リクエストボディのカプセル化**:外部には `MessageObject` のみを渡します。`PostInner` は自動的に `MessageHttpObject`(Id、UniqueId、Body)の層でラップし、バイナリにシリアル化してからキューに投入します:

  ```csharp
           var id = ProtoMessageIdHandler.GetReqMessageIdByType(message.GetType());
           MessageHttpObject messageHttpObject = new MessageHttpObject
           {
               Id = id,
               UniqueId = message.UniqueId,
               Body = SerializerHelper.Serialize(message),
           };
           var sendData = SerializerHelper.Serialize(messageHttpObject);
           var webData = WebProtoBufData.Create(url, sendData, uniTaskCompletionSource, userData);
           m_WaitingProtoBufQueue.Enqueue(webData);
  ```

  ソース: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L214-L229)

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `Response message type is invalid. Expected '...', actual '...'` のログが出力され、`default` が返る | サーバーが返したメッセージ Id に対応するレスポンスタイプが、呼び出し側が渡した `T` と一致しない | `ProtoMessageIdHandler` に登録されたリクエスト/レスポンスのマッピングと `Post<T>` のジェネリック引数を確認する |
| WebGL でリクエストが無応答 | 設定した `Timeout` に小数が含まれ、`(int)RequestTimeout.TotalSeconds` によって小さすぎる値に切り捨てられる(例:`0.5` → `0`) | `Timeout` を整数秒に設定する |
| リクエストがずっとハングしたまま | 同時接続数が `MaxConnectionPerServer`(デフォルト 8)に達し、以降のリクエストが `m_WaitingProtoBufQueue` に滞留している | `MaxConnectionPerServer` を引き上げるか、コンポーネントの `Update` が継続的に駆動されるようにする |
| WebGL のコンソールに `Unknown error` / CORS 系のネットワークエラーが出る | `unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null` の分岐がトリガーされ、例外テキストは `unityWebRequest.error` そのもの | サーバー側の CORS 設定と URL の到達可能性を確認する |
| WebGL 以外のプラットフォームで `TimeoutException` がスローされる | サーバーが `RequestTimeout`(ミリ秒精度)以内に応答しない | `Timeout` を大きくするか、サーバー側の処理時間を調査する |

## 検証

- WebGL とエディターの両方のプラットフォームでそれぞれ同じ `Post<T>` リクエストを送信し、どちらも逆シリアル化された `T` インスタンスが返り、`UniqueId` が一致することを確認します。
- `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` マクロを有効にすると、`接收消息 ID:[...] 消息内容:...` というデバッグログが確認できます(ソース: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L231-L237))。
- 意図的に `T` を誤った型に変更し、`Response message type is invalid...` エラーが発生することを確認して、型検証が機能していることを証明します。

## 背景

コンポーネントはプラットフォームごとの条件付きコンパイルにより2つの実装を持ちます。WebGL はランタイムの制限により `HttpWebRequest` を使用できないため、統一的に `UnityWebRequest` の `completed` コールバックを使用します。その他のプラットフォームでは `Task` ベースのストリーミング `HttpWebRequest` 実装が維持されます。両者の結果はどちらも同じ `TaskCompletionSource<WebBufferResult>` に書き戻されるため、上位層の `Post<T>` は差異を意識しません。URL のクエリパラメータ、再利用される `StringBuilder`、同時接続数の上限は [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs) で定義されています。
