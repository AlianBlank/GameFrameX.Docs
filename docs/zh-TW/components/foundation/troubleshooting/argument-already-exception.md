# 發生 ArgumentAlreadyException 時的處理方法

使用 GameFrameX.Foundation 時若發生 `ArgumentAlreadyException`（參數重複例外），表示某個參數值已經存在或發生重複。本頁面將說明如何快速找出原因並修正。

## 快速診斷

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 擲回 `ArgumentAlreadyException: <訊息>` | 業務程式碼主動擲回此例外（例如在註冊時偵測到重複的 ID / 重複的鍵值 / 重複的名稱） | 改為先檢查再賦值的邏輯，或在呼叫靜態輔助方法前先排除重複 |
| 擲回 `ArgumentNullException: message`、`ParamName = "message"` | 呼叫 `new ArgumentAlreadyException(null)` 或 `Throw(null)` 時 message 為 null | 傳入非 null 的說明字串 |
| 擲回 `ArgumentException: message`、`ParamName = "message"` | 傳入了空字串 `""` 或僅含空白字元（例如：`"   "`） | 傳入包含實際內容的說明字串 |
| 因擲回 `ArgumentNullException` 而誤以為是框架的 bug | 框架會對 message 參數執行 `ThrowIfNullOrWhiteSpace` 驗證，null / 空 / 空白皆會在前置階段被攔截 | 這是預期的行為，只要修正引數即可 |

## 修正步驟

### 1. 區分例外類型

`ArgumentAlreadyException` 本身只有在您或框架的程式碼明確呼叫時才會被擲回。`ArgumentNullException` / `ArgumentException` 則是其建構函式對 `message` 參數執行的前置驗證。

```csharp
using GameFrameX.Foundation.Extensions;

// 明確擲回
public void Register(string id)
{
    if (_dict.ContainsKey(id))
    {
        ArgumentAlreadyException.Throw($"id '{id}' 已存在");
    }
    _dict[id] = ...;
}
```

### 2. 處理「參數已存在」的業務情境

最常見的修正方式，是在新增元素前先進行存在檢查以避免重複。

```csharp
using GameFrameX.Foundation.Extensions;

public void AddUnique(string key, string value)
{
    if (_map.ContainsKey(key))
    {
        // 選項 A：直接跳過
        return;

        // 選項 B：擲回例外以交由上層判斷
        // ArgumentAlreadyException.Throw($"key '{key}' 已存在");
    }
    _map[key] = value;
}
```

### 3. message 為 null / 空 / 空白時的處理方式

若捕捉到 `ArgumentNullException` 或 `ArgumentException`，且 `ParamName` 為 `message`，表示呼叫端傳入了無效的字串，只需修正引數即可。

```csharp
using GameFrameX.Foundation.Extensions;

var msg = string.IsNullOrWhiteSpace(input)
    ? "預設值/鍵值已存在"
    : $"{input} 已存在";

try
{
    ArgumentAlreadyException.Throw(msg);
}
catch (ArgumentAlreadyException ex)
{
    // 業務處理
}
```

### 4. 單元測試中的預期行為

儲存庫中的測試已明確定義這 4 種行為，可直接對照參考。

| 輸入 | 預期的例外 |
|------|----------|
| `"Parameter already exists"` | `ArgumentAlreadyException` |
| `null` | `ArgumentNullException`、`ParamName = "message"` |
| `""` | `ArgumentException`、`ParamName = "message"` |
| `"   "` | `ArgumentException`、`ParamName = "message"` |

## 驗證

1. 確認 `message` 引數不是 null，也不是空字串或僅含空白字元。
2. 確認在業務端進行新增/註冊之前，已對目標集合執行存在檢查，或依賴框架的自動驗證。
3. 在單元測試中使用 `Assert.Throws<ArgumentAlreadyException>` 進行明確的斷言，以避免引數驗證修正遺漏。
