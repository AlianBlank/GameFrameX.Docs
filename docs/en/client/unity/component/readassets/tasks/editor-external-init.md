# Initialize with External APK / Custom Directory in Editor (Test Android Build)

Initialize `BlankReadAssets` in Unity Editor via an external APK file or custom directory, simulating Android StreamingAssets read behavior without packaging a real device. Useful for local debugging of AssetBundle, hot-update resources, or Android-specific path logic.

## Prerequisites

- The project has the `GameFrameX.ReadAssets` package integrated, and `Runtime/BlankReadAssets.cs` exists.
- Only takes effect under `UNITY_EDITOR`: these two APIs are wrapped in `#if UNITY_EDITOR` and will not be included in device builds.
- The APK to be tested must be a standard Android package with StreamingAssets located at `assets/` (Unity's default export form).

## Operation Steps

`BlankReadAssets` exposes two Editor-only entries. Choose one based on your debugging target.

### Method A: Initialize with External APK

```csharp
using GameFrameX.ReadAssets.Runtime;

// Format: Application.dataPath + "/../test.apk"
BlankReadAssets.InitializeWithExternalApk(apkPath);
```

Source entry and signature:

```csharp
[Preserve]
public static void InitializeWithExternalApk(string apkPath)
{
    BlankReadAssetsImpl.ApkMode = true;
    BlankReadAssetsImpl.Initialize(apkPath, "jar:file://" + apkPath + "!/assets/");
    s_initialized = true;
}
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

This call sets `EditorImpl.ApkMode` to `true`, so that subsequent `FileExists` / `OpenRead` / `ReadAllBytes` / `GetFiles` all go through `ApkImpl` (i.e., reading the `jar:file://...!/assets/` path inside the APK).

### Method B: Initialize with Custom Directory

```csharp
using GameFrameX.ReadAssets.Runtime;

// dataPath: the parent directory root of StreamingAssets in the file system
// streamingAssetsPath: the actual path of StreamingAssets itself (any directory can be used)
BlankReadAssets.InitializeWithExternalDirectories(dataPath, streamingAssetsPath);
```

Source entry and signature:

```csharp

public static void InitializeWithExternalDirectories(string dataPath, string streamingAssetsPath)
{
    BlankReadAssetsImpl.ApkMode = false;
    BlankReadAssetsImpl.Initialize(dataPath, streamingAssetsPath);

```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

Suitable for copying the built StreamingAssets to any directory, then simulating reads directly as a "file directory" in Editor.

### Step 3: Call Read APIs to Verify

```csharp
if (BlankReadAssets.FileExists("config/game.json"))
{
    byte[] bytes = BlankReadAssets.ReadAllBytes("config/game.json");
    // Or load an AssetBundle
    var bundle = BlankReadAssets.LoadAssetBundle("bundles/ui.bundle");
}
```

The initialization flag `s_initialized` will be set to `true` after one call, and all subsequent APIs will not reinitialize.

## Common Variants

| Scenario | Recommended Method | Description |
|------|----------|------|
| Verify StreamingAssets reads from a real Android build | Method A (APK) | Path prefix is fixed as `jar:file://<apk>!/assets/`, consistent with the real device |
| Debug with local StreamingAssets directory | Method B (Custom Directory) | `streamingAssetsPath` points to a custom directory outside the project's `Assets/StreamingAssets` |
| Pre-warm before `Awake` | Either one, manually call | Sets `s_initialized = true`, subsequent `EnsureInitialized` will not reset the mode |

When switching modes (APK ↔ Custom Directory), the corresponding initialization method must be called again, because `ApkMode` is a static flag.

## Common Errors

- Calling these two methods in Player build: they will be stripped by `#if UNITY_EDITOR`, causing compilation failure or missing symbols at runtime.
- Forgot to reinitialize after switching modes: `ApkMode` from the previous call is still `true`, all reads will continue through the APK branch.
- Passing a non-existent APK path to `InitializeWithExternalApk`: `ApkImpl.Initialize` will not actively throw an error, but subsequent `FileExists` / `OpenRead` will not find the file. Use `File.Exists(apkPath)` to self-check first.
- Confusing `Application.streamingAssetsPath` with the APK internal path: in APK mode, `streamingAssetsPath` is internally replaced with `jar:file://...!/assets/`. Do not manually pass `Application.streamingAssetsPath`.

## Background (Optional)

In Editor, `BlankReadAssetsImpl` selects the implementation through conditional compilation: `UNITY_EDITOR` uses `EditorImpl`, Android uses `ApkImpl`, and other platforms use `LooseFilesImpl`. Inside `EditorImpl`, it determines whether to forward requests to `ApkImpl` or `LooseFilesImpl` based on the `ApkMode` flag, thereby simulating read behaviors of different platforms within the editor process.
