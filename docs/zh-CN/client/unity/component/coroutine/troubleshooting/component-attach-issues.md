# 组件添加不上或重复挂载怎么办

遇到 `CoroutineComponent` 添加失败、添加后立刻被移除、或在 Inspector 中报"Can't add component"等情况时,通常与 Unity 重复挂载限制、`[DisallowMultipleComponent]` 特性或 GameFrameX 框架自动挂载流程有关。本页给出常见症状的快速定位与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `AddComponent<CoroutineComponent>()` 后报 `Can't add component ... because a MonoBehaviour is already attached` | 同一 GameObject 已经存在该组件,`CoroutineComponent` 标有 `[DisallowMultipleComponent]` | 见下方"先移除再添加"小节 |
| 手动 AddComponent 后,场景重新加载或切场景后组件消失 | 没有走 GameFrameX 框架流程,组件不是由框架的 `GameFrameXAutoComponent` 扫描器挂载的 | 见下方"由框架自动挂载"小节 |
| iOS / IL2CPP 打包后运行时找不到 `CoroutineComponent` 类型 | 被 Unity 链接器裁剪掉了 | 见下方"打包后丢失"小节 |
| `CoroutineComponent` 出现在场景中多个 GameObject 上,看起来"重复挂载" | 每个 GameObject 上各挂一份是允许的;实际重复只在"同一 GO"上才会被拒绝 | 见下方"区分'多 GO'与'同 GO 重复'"小节 |

## 修复步骤

### 先移除再添加(同 GO 重复挂载)

`CoroutineComponent` 在源码中标注了 `[DisallowMultipleComponent]`,这是 MonoBehaviour 内建特性,禁止同一 GameObject 上挂多份。

```csharp
// 报错: Can't add component 'CoroutineComponent' because a MonoBehaviour is already attached.
// 修复: 先移除已有的,再添加,或者直接复用已有的引用
if (gameObject.TryGetComponent<CoroutineComponent>(out var exist))
{
    // 已有就直接使用,不要重复 AddComponent
}
else
{
    exist = gameObject.AddComponent<CoroutineComponent>();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L15)

### 由框架自动挂载

正常情况下,**不要**在业务代码里手动 `AddComponent<CoroutineComponent>()`,而是由 GameFrameX 框架通过 `[GameFrameXAutoComponent(-6500)]` 特性在框架启动时自动挂载到框架入口 GameObject 上。组件 `Awake()` 内部把 `IsAutoRegister = false`,表示不参与运行时的二次注册流程。

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Coroutine")]
[GameFrameXAutoComponent(-6500)]
public class CoroutineComponent : GameFrameworkComponent
{
    protected override void Awake()
    {
        IsAutoRegister = false;
        base.Awake();
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L110)

如果一定要手动挂载,请确保:
1. GameObject 处于激活状态。
2. 当前没有其他同名组件实例(见上一节)。
3. 在能拿到 `GameFrameworkComponent` 基类所在宿主 GameObject 上挂载,避免与框架实例重复。

### 打包后丢失

IL2CPP / iOS 链接器可能裁剪掉未被显式引用的 MonoBehaviour 类型。源码里用一个空 `MonoBehaviour` 配合 `[Preserve]` 来防止类型被删:

```csharp
[Preserve]
public class GameFrameXCoroutineCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(CoroutineComponent); // 强制保留 CoroutineComponent
    }
}
```

Source: [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

修复:
1. 确认场景中存在挂着 `GameFrameXCoroutineCroppingHelper` 的 GameObject(或代码里显式引用过 `CoroutineComponent`)。
2. Unity Player Settings → Managed Stripping Level 在 iOS 上不要设为 `Low` / `Medium` 之外更激进的级别,否则需要额外配 `link.xml` 把命名空间 `GameFrameX.Coroutine.Runtime` 排除在外。

### 区分"多 GO"与"同 GO 重复"

- **多 GO 上各挂一份**(例如每个 UI 面板各挂一份):这是合法的,各自管各自的协程。
- **同一 GO 上挂两份**:报 `Can't add component`,见上方处理方式。

如果你以为框架"重复挂载"了多个实例,可以在 Hierarchy 里搜 `Coroutine`,确认它们确实在不同 GameObject 上;若全部在同一个 GO 上,只保留一份就够了。

## 验证

修复后用以下方式确认:

1. 在 Unity Console 中再无 `Can't add component` 报错。
2. 进入 Play Mode 后能在 Hierarchy 里看到框架入口 GameObject 上的 `CoroutineComponent`(标有 `GameFrameX/Coroutine` 菜单名)。
3. 调用 `StartCoroutine` 后协程能正常运行,`StopCoroutine(IEnumerator)` 用同一引用能成功停止——这表明组件已正确挂载并被框架接管。
