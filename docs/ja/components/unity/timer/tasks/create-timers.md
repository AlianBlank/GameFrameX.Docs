# タイマーの作成：繰り返し・単発・フレームごと

`TimerComponent` の 3 つのエントリポイントですべてのタイマーを作成できます:`Add`(繰り返し/無限繰り返し可能)、`AddOnce`(1 回のみ実行)、`AddUpdate`(毎フレーム実行)。3 つともタイマー ID を返すため、以降の一時停止・再開・照会・削除に使用できます。

## 前提条件

- シーンに GameFrameX フレームワークのオブジェクトが存在し、`TimerComponent` がアタッチされていること(メニューパスは `GameFrameX/Timer`、`[AddComponentMenu("GameFrameX/Timer")]`、[TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L12-L16) を参照)。
- 業務コードで名前空間 `GameFrameX.Timer.Runtime` を参照していること。

## 操作手順

1. `TimerComponent` の参照を取得します(例：GameFrameX のコンポーネント取得方法を使用)。

2. 要件に応じて作成メソッドを 1 つ選択します:

| 要件 | メソッド | 実際のシグネチャ |
|------|------|----------|
| N 秒ごとに実行、M 回または無限で繰り返し | `Add` | `int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)` |
| N 秒遅延後に 1 回だけ実行 | `AddOnce` | `int AddOnce(float interval, Action<object> callback, object callbackParam = null)` |
| 毎フレーム実行 | `AddUpdate` | `int AddUpdate(Action<object> callback)` / `int AddUpdate(Action<object> callback, object callbackParam)` |

シグネチャとデフォルト値の出典:[TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L80)。

3. コールバックを渡します(型は `Action<object>` 固定、パラメータは `null` 可能)。返された ID を保存します。

```csharp
// 1) 無限繰り返し:1 秒ごとに 1 回発火。repeat に 0 を渡すと無限繰り返しを意味する
int heartbeatId = timerComponent.Add(
    1f, 0,
    param => Debug.Log("heartbeat " + param),
    "tick",
    TimerTimeScale.Unscaled);

// 2) 単発:3 秒後に 1 回実行され、その後自動的に削除される
int delayId = timerComponent.AddOnce(3f, param => Debug.Log("done"));

// 3) フレームごと:毎フレーム Update で 1 回呼び出される
int frameId = timerComponent.AddUpdate(param => { /* 毎フレームのロジック */ });
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L80)

4. ID を使って以降の管理を行います:

```csharp
timerComponent.Pause(id);        // 一時停止(停止中は時間が蓄積されない)
timerComponent.Resume(id);       // 再開、一時停止した時点から蓄積を継続
timerComponent.Exists(id);       // まだ存在してアクティブかどうか
timerComponent.GetRemaining(id); // 残り秒数;存在しない場合は -1 を返す
timerComponent.GetElapsed(id);   // 蓄積済みの秒数;存在しない場合は -1 を返す
timerComponent.Remove(id);       // 削除
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L105-L118), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L124-L146), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L190-L200)

## よくあるバリエーション

### 繰り返し回数を制限して完了を監視する

`repeat > 0` は指定回数の発火後に自動削除されることを意味します;`onComplete` はタイマーの完了/削除時に発火します。

```csharp
// 0.5 秒ごとに 5 回繰り返し;5 回目の発火後に自動削除され onComplete がコールバックされる
int id = timerComponent.Add(
    0.5f, 5,
    param => Debug.Log("tick"),
    onComplete: () => Debug.Log("all ticks finished"));
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)(`Repeat` が 0 までデクリメントされると `Deleted` に設定され削除キューに入る), [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L134-L147)(削除時に `OnComplete` を実行)

### timeScale の影響を受けるタイマー

`timeScale` のデフォルトは `TimerTimeScale.Unscaled`(`Time.timeScale` の影響を受けない);ゲームの一時停止時にカウントダウンも一緒に止めたい場合は、`TimerTimeScale.Scaled` を渡します:

```csharp
// timeScale が変化すると(ゲームの一時停止など)、Scaled タイマーの進行もそれに応じて遅くなる/停止する
int id = timerComponent.Add(2f, 0, OnTick, timeScale: TimerTimeScale.Scaled);
```

Source: [TimerTimeScale.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerTimeScale.cs#L6-L13), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

### tag によるグループ管理

作成時に `tag` を渡しておくと、後からグループ単位で一時停止/再開/削除ができます:

```csharp
timerComponent.Add(1f, 0, OnTick, tag: "battle");
timerComponent.PauseByTag("battle");   // このグループをすべて一時停止
timerComponent.ResumeByTag("battle");  // このグループをすべて再開
timerComponent.RemoveByTag("battle");  // このグループをすべて削除
timerComponent.HasTag("battle");       // このグループにアクティブなタイマーが残っているかどうか
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L148-L183)

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| ログに `timer callback is null, {interval},{repeat}` が出力され、返却される ID が 0 になる | コールバックに `null` を渡した | 呼び出し前に null チェックを行ってから呼ぶ;マネージャーは警告を出力して作成を拒否する |
| 「1 回だけ実行」のはずが繰り返し発火する | `Add` の `repeat` に 0 を渡した(0 は無限繰り返しを意味する) | 単発タスクには `AddOnce` を使う、または `Add` に `repeat: 1` を渡す |
| `interval` に負数や 0 を渡したら「毎フレーム発火」する | `interval <= 0` はフレームごとのタイマーとして扱われる | フレームごとの動作を意図するなら `AddUpdate` を使う;不正な interval を `Add` に渡さない |
| 同じコールバックを再度 Add したらカウントが「リセット」された | コールバックがキーとなっており、重複した `Add` はその場でパラメータを更新して `Elapsed` をゼロにする | 複数の並行インスタンスが必要な場合は異なるコールバック(クロージャなど)を使用する |
| 一時停止後に `GetRemaining` が変化しない | 停止中は時間が蓄積されず、残り時間も当然凍結される | 予期された動作;`Resume` を呼び出すと継続する |
| コールバック内で例外がスローされる | デフォルトでは `CatchCallbackExceptions = false` のため、例外は上位へスローされる | 例外を握りつぶしたい場合は `TimerManager.CatchCallbackExceptions = true` を設定する。例外は `Timer callback error > ...` という Warning として記録される |

## 検証

- 作成後に `timerComponent.Exists(id)` を呼び出し、`true` が返されれば登録済みです([TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L110-L118))。
- `GetRemaining(id)` / `GetElapsed(id)` でカウントダウンを観察し、間隔や一時停止の効果を検証します;タイマーが存在しない場合は両方とも `-1` を返します([TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L185-L200))。
- 単発タイマーは発火後に `Exists(id)` が `false` になるはずです(発火が完了すると即座に削除されます。詳しくは [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L121) を参照)。

## 背景

`TimerComponent` は薄いラッパーにすぎず、実際のロジックは `TimerManager`(`ITimerManager` インターフェースを実装)にあります。マネージャーはコールバック関数をキーとして `TimerItem`(`Interval`、`Repeat`、`Elapsed`、`IsPaused`、`Tag`、`OnComplete` などのフィールドを含む)を管理し、毎フレーム `Update` 内で `TimeScaleMode` に基づいて時間ソースを選択して `Elapsed` を加算します。`Interval` に達するとコールバックを実行待ちリストに入れてロック外で実行し、他のスレッドのブロックを回避します;1 回の超過による余剰はクランプされ(0.03s を超えた場合はゼロにクリア)、低フレームレート時に連続してまとめて発火するのを防ぎます。非同期待機スタイルのタイマーの使用方法については、`TimerAsyncExtensions` を参照してください。
