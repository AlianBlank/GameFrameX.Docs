# How to Execute a Callback After the Current Frame Rendering Finishes

Call `CoroutineComponent.WaitForEndOfFrameFinish(callback)` to trigger the specified callback method after the current frame rendering completes and the engine emits the `WaitForEndOfFrame` signal. This is commonly used for scenarios such as taking screenshots, refreshing post-processing, and sampling after UI rendering.

## Prerequisites

- The `com.gameframex.unity.coroutine` package is installed and enabled.
- A `CoroutineComponent` component exists in the scene (automatically registered by `GameFrameXAutoComponent`), accessible via `GameEntry.GetComponent<CoroutineComponent>()`.
- The project references the `GameFrameX.Coroutine.Runtime` namespace.

## Steps

1. Get the coroutine component instance:

```csharp
using GameFrameX.Coroutine.Runtime;
using GameFrameX.Runtime;

CoroutineComponent coroutineComponent = GameEntry.GetComponent<CoroutineComponent>();
```

2. Prepare the callback method to be executed at the end of the frame (it can be a lambda or a named method):

```csharp
System.Action onFrameEnd = () =>
{
    // The code here will execute after the WaitForEndOfFrame signal of the current frame
    Debug.Log("Frame rendering finished.");
};
```

3. Call `WaitForEndOfFrameFinish` to start the end-of-frame callback:

```csharp
coroutineComponent.WaitForEndOfFrameFinish(onFrameEnd);
```

The internal implementation wraps `yield return new WaitForEndOfFrame()` together with the callback into an iterator coroutine, started via `StartCoroutine`, and invokes `callback?.Invoke()` when the signal is received.

Source: [CoroutineComponent.cs#L84-L104](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

## Complete Runnable Example

```csharp
using GameFrameX.Coroutine.Runtime;
using GameFrameX.Runtime;
using UnityEngine;

public class FrameEndCallbackExample : MonoBehaviour
{
    private void Start()
    {
        var coroutineComponent = GameEntry.GetComponent<CoroutineComponent>();
        coroutineComponent.WaitForEndOfFrameFinish(() =>
        {
            Debug.Log("End of frame reached.");
        });
    }
}
```

## Common Variations

- **Callbacks with data**: Since the signature is `System.Action`, use closures to capture local variables when you need to pass parameters:

  ```csharp
  Texture2D snapshot;
  coroutineComponent.WaitForEndOfFrameFinish(() =>
  {
      var rect = new Rect(0, 0, Screen.width, Screen.height);
      snapshot.ReadPixels(rect, 0, 0);
      snapshot.Apply();
  });
  ```

- **Queuing multiple times within the same frame**: Each call to `WaitForEndOfFrameFinish` starts a new coroutine, and they will all trigger their callbacks in the order they were started after the frame rendering finishes.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The callback method is not invoked | `StopAllCoroutines()` or `StopCoroutine` was called to terminate the coroutine started by `WaitForEndOfFrameFinish` before it could execute | Do not batch-stop coroutines while they are running; if cancellation is needed, use other cancellation mechanisms instead of relying on end-of-frame triggers |
| Error `CoroutineComponent is null` | The component was not obtained through the `GameFrameX` entry, or the component has not been registered | Use `GameEntry.GetComponent<CoroutineComponent>()` and ensure `GameFramework` has started |
| Wanting to obtain the `IEnumerator` from `WaitForEndOfFrameFinish` to manage it manually | The method returns `void`, and the internal coroutine is not exposed externally | This is expected behavior; if manual control over the iterator is needed, use `StartCoroutine` and wrap `yield return new WaitForEndOfFrame()` yourself |

## Background

`WaitForEndOfFrameFinish` reuses a shared `WaitForEndOfFrame` instance (a singleton `_waitForEndOfFrame` outside of `m_CoroutineMap`). Through `yield return`, Unity drives the coroutine to continue executing after the frame rendering finishes, then calls `callback?.Invoke()`. This avoids the GC pressure caused by `new WaitForEndOfFrame()` on every call.
