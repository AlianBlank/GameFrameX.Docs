# 撰寫可熱更新的業務程式碼（Hotfix 層規範）

本頁面說明如何在 `GameFrameX.Hotfix` 組件中撰寫可被熱替換的業務程式碼，並遵循框架的橋接與分層約束。

## 前置條件

- 已建立 `GameFrameX.Hotfix` 組件專案（參見儲存庫中的 [GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj)）。
- 參考 `GameFrameX.StartUp`、`GameFrameX.SuperSocket.*`、`GameFrameX.Apps.Common.Session` 等相依性。
- 編譯時啟用了 `GameFrameX.Architecture.Analyzers` 規則集（`GFX0004` 等）。

## Hotfix 層的核心約定

1. **橋接類別必須實作 `IHotfixBridge`**：所有需要在狀態層（Apps）與邏輯層（Hotfix）之間橋接的進入點類別必須實作該介面，且類別必須定義在 `GameFrameX.Hotfix` 組件內。`HotfixBridgeAssemblyAnalyzer` 會以 `GFX0004` 錯誤強制此規則。
2. **進入點類別使用 `partial`**：因為啟動生命週期分散在多個檔案（`AppStartUpHotfixGameByEntry.cs`、`AppStartUpHotfixGameByMain.cs` 等），類別必須保持 `partial`，否則啟動階段會編譯失敗。
3. **保留 `HotfixHandler` 標記類型**：`HotfixHandler` 是一個空的靜態類別，僅用於被反射定位。刪除會導致熱更時找不到進入點。

## 操作步驟

### 步驟 1：在 Hotfix 組件中宣告啟動橋接類別

新增或修改 `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`，宣告 `partial` 類別並實作 `IHotfixBridge`：

```csharp
using GameFrameX.StartUp;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge
{
    public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
    {
        if (reload)
        {
            ActorManager.ClearAgent();
            return true;
        }

        Init(setting.ServerType, setting);
        await RunServer();
        // 啟動計時器
        await QuartzTimer.Start();
        GlobalTimer.Start();
        await ComponentRegister.ActiveGlobalComponents();
        return true;
    }

    public async Task Stop(string message = "")
    {
        await StopAsync(message);
    }
}
```

來源：[AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L37-L60)

### 步驟 2：在另一個檔案中擴充訊息分發與生命週期

由於類別被宣告為 `partial`，可以在另一個檔案中覆寫 `StartAsync`、`PackageHandler`、`OnConnected`、`OnDisconnected`、`StopAsync` 等網路與生命週期掛鉤：

```csharp
using GameFrameX.Apps.Common.Session;
using GameFrameX.SuperSocket.Connection;
using GameFrameX.SuperSocket.Server.Abstractions.Session;
using GameFrameX.SuperSocket.WebSocket.Server;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame
{
    public override async Task StartAsync()
    {
        await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
            new DefaultMessageCompressHandler(),
            new DefaultMessageDecompressHandler(),
            HotfixManager.GetListHttpHandler(),
            HotfixManager.GetHttpHandler);
    }

    protected override async ValueTask PackageHandler(IAppSession appSession, IMessage message)
    {
        if (message is NetworkMessagePackage messagePackage)
        {
            var netWorkChannel = SessionManager.GetChannel(appSession.SessionID);
            if (netWorkChannel.IsNull()) return;

            var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
            if (handler == null)
            {
                LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
                return;
            }

            try
            {
                await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
            }
            catch (Exception exception)
            {
                LogHelper.Fatal(exception);
            }
        }
    }

    public override async Task StopAsync(string message = "")
    {
        await base.StopAsync(message);
        await SessionManager.RemoveAll();
        await QuartzTimer.Stop();
        await ActorManager.AllFinish();
        await GlobalTimer.Stop();
        await ActorManager.RemoveAll();
    }
}
```

來源：[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L43-L163)

### 步驟 3：不要刪除 `HotfixHandler` 標記類型

熱更框架依賴反射定位 `HotfixHandler` 類別作為進入點標記，保留即可，無需新增任何成員：

```csharp
namespace GameFrameX.Hotfix;

/// <summary>
/// 該類別文件用於處理熱更新標記。不能刪除。用於反射呼叫
/// </summary>
public static class HotfixHandler
{
}
```

來源：[HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8)

### 步驟 4：確保 IHotfixBridge 實作位於 Hotfix 組件

如果你新增了一個橋接實作（例如 `MyHotfixBridge : IHotfixBridge`），必須把檔案放在 `GameFrameX.Hotfix` 專案下；否則 `HotfixBridgeAssemblyAnalyzer` 會報 `GFX0004`：

```text
Type 'MyHotfixBridge' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not '<YourAssembly>'
```

來源：[HotfixBridgeAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs#L22-L44)

## 常見變體

- **按閘道啟動**：在 `AppStartUpHotfixGameByGateWay.cs` 中提供閘道端覆寫。
- **按心跳啟動**：在 `AppStartUpHotfixGameByHeart.cs` 中提供心跳端覆寫。
- **重載場景（`reload == true`）**：在 `OnLoadSuccess` 中只呼叫 `ActorManager.ClearAgent()` 並傳回，不要重新初始化網路與全域元件。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 編譯報 `Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix'` | `IHotfixBridge` 實作類別放錯了組件 | 把該類別檔案移到 `GameFrameX.Hotfix` 專案 |
| 啟動報「找不到熱更進入點」 | 誤刪了 `HotfixHandler` 靜態類別 | 重新宣告 `public static class HotfixHandler {}` |
| `partial` 報錯，找不到 `AppStartUpHotfixGame` 定義 | 在新檔案中忘記寫 `partial` 修飾詞 | 為所有部分類別加上 `internal partial class AppStartUpHotfixGame` |
| 熱更後狀態未清理 | `OnLoadSuccess(reload=true)` 分支中沒有呼叫 `ActorManager.ClearAgent()` | 按範本在 reload 分支先清空 Agent |

## 背景（可選）

`IHotfixBridge` 是狀態層呼叫邏輯層的橋接契約，約束其實作位於 `GameFrameX.Hotfix` 組件內，從而確保熱更新時整段橋接邏輯可以被整體替換；架構分析器 `HotfixBridgeAssemblyAnalyzer` 以 `GFX0004` 在編譯期強制此規則。
