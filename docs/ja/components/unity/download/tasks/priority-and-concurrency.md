# ダウンロード優先度と同時実行エージェント数の設定

このタスクページでは、ダウンロードタスクに**優先度**を設定する方法、およびコンポーネントの**ダウンロードエージェント(同時実行コルーチン)数**を調整して、同時ダウンロードタスクの上限を制御する方法について説明します。

## 前提条件

- `GameFrameX.Download.Runtime` を導入済みで、シーンに `DownloadComponent` をアタッチ済みであること(メニュー:GameFrameX / Download)。
- 対象ダウンロードタスクのローカル保存パス(`downloadPath`)とリモートアドレス(`downloadUri`)を把握していること。

## 操作手順

### 1. 個別タスクの優先度を設定する

`DownloadComponent.AddDownload` は複数のオーバーロードを提供しており、`priority` パラメータ(`int`、値が大きいほど優先度が高い、デフォルトは `0`)を受け取ります。最もよく使われる2つ:

```csharp
using GameFrameX.Download.Runtime;

// 優先度のみ指定
int serialId = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, priority: 100);

// tag と優先度を同時に指定
int serialId2 = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, tag: "asset-bundle", priority: 100);
```

ソースコード:

```csharp
// Runtime/Download/DownloadComponent.cs
private const int DefaultPriority = 0;
...
public int AddDownload(string downloadPath, string downloadUri, int priority)
{
    return AddDownload(downloadPath, downloadUri, null, priority, null);
}

public int AddDownload(string downloadPath, string downloadUri, string tag, int priority)
{
    return AddDownload(downloadPath, downloadUri, tag, priority, null);
}
```

### 2. 同時実行エージェント数を設定する

同時ダウンロード能力は `DownloadComponent.m_DownloadAgentHelperCount` によって決まり、デフォルトは `3` で、同時に最大3つのダウンロードコルーチンが動作することを意味します。Inspector で調整するか、コードで実行時に拡張する必要があります:

- **Inspector**:コンポーネントをアタッチした後、Inspector 内の `Download Agent Helper Count` フィールド(`m_DownloadAgentHelperCount` に対応)を直接変更します。コンポーネントの `Start()` 時に、この値に従ってエージェントが一括で作成されます。
- **実行時の追加**：動的に増やす必要がある場合は、コンポーネントの内部エントリを引き続き呼び出すか、`DownloadAgentHelperBase` をベースにしたカスタム拡張を行います([DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs) を参照)。

ソースコード(エージェントの作成):

```csharp
// Runtime/Download/DownloadComponent.cs
[SerializeField] private int m_DownloadAgentHelperCount = 3;
...
private void Start()
{
    ...
    for (int i = 0; i < m_DownloadAgentHelperCount; i++)
    {
        AddDownloadAgentHelper(i);
    }
}
```

### 3. 実行時にエージェントの使用状況を確認する

コンポーネントは以下の読み取り専用プロパティを提供しており、デバッグ HUD でリアルタイムに表示できます:

| プロパティ | 説明 |
|------|------|
| `TotalAgentCount` | 作成済みのダウンロードエージェント総数 |
| `FreeAgentCount` | 現在アイドル状態のダウンロードエージェント数 |
| `WorkingAgentCount` | 現在動作中のダウンロードエージェント数 |
| `WaitingTaskCount` | エージェントの空きを待機しているタスク数 |

ソースコード:

```csharp
// Runtime/Download/DownloadComponent.cs
public int TotalAgentCount   { get { return m_DownloadManager.TotalAgentCount; } }
public int FreeAgentCount    { get { return m_DownloadManager.FreeAgentCount; } }
public int WorkingAgentCount { get { return m_DownloadManager.WorkingAgentCount; } }
public int WaitingTaskCount  { get { return m_DownloadManager.WaitingTaskCount; } }
```

## よくあるバリエーション

- **重要リソースを優先**：初回画面のリソースには高い `priority`(例:`100`)を、バックグラウンドでの事前ダウンロードには `0` または負の値を使用します。
- **一時停止と再開**:`DownloadComponent.Paused = true/false` で新しいタスクの割り当てを一時的に停止できます。実行中のエージェントは中断されません。
- **`m_DownloadAgentHelperCount` の変更が即時反映される場合**：値が大きくなった場合のみ、コンポーネントの起動時にすべてのエージェントが事前作成されます。実行中に値を小さくしても既存のエージェントは破棄されないため、カスタムロジックと組み合わせて回収する必要があります。

## よくある間違い

- **「同時実行コルーチン」と「同時実行スレッド」の混同**：ダウンロードエージェントは `UnityWebRequest` コルーチンであり、この値は同時に実行される HTTP リクエスト数のみを制御し、スレッドとは無関係です。WebGL などの制約のあるプラットフォームでは大きすぎる値を設定しないでください。
- **タスクが開始されずに滞留する**:`WaitingTaskCount` が増加し続け、`FreeAgentCount` が常に 0 の場合、同時実行数が少なすぎるか、タスクのネットワークが遅いことを示しています——`m_DownloadAgentHelperCount` を適度に引き上げることができます。
- **優先度を指定しなければ高優先度になると思い込む**:`DefaultPriority = 0` なので、他のタスクに負の値が指定された場合、あなたの「デフォルト」タスクは逆に後回しにされます。

## 背景(オプション)

ダウンロードマネージャーは内部で `TaskPool<DownloadTask>` を使用してタスクをスケジューリングします(`[DownloadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs)`)。優先度の高いタスクが優先的に空きエージェントを獲得することで、ネットワーク出口の占有順序を制御します。
