# イベントの発火方法：Fire、FireNow と引数なしイベント

GameFrameX.Event でイベントを発火するには、`EventComponent` の `Fire`（スレッドセーフ、翌フレームにメインスレッドでコールバック）、`FireNow`（即時に同期ディスパッチ）、または `Fire(sender, eventId)`（カスタムイベント引数が不要なショートカット）のいずれかを呼び出すだけです。本ドキュメントでは、この 3 つの使い方の完全な手順、適用シーン、よくある落とし穴を紹介します。

## 前提条件

- シーンに GameFrameX エントリが既に存在し、`EventComponent` がフレームワークによって自動的にアタッチされていること（コンポーネントメニューは `GameFrameX/Event`、[EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43) を参照）。
- 対応するイベント ID が既に誰かによって購読されていること。そうでない場合、発火しても誰も受信しません（デフォルトハンドラーでフォールバック可能、下記の「よくあるバリエーション」を参照）。

## 操作手順

1. イベントコンポーネントの参照を取得します（独自の MonoBehaviour にアタッチするか、フレームワークのエントリから取得します）：

   ```csharp
   using GameFrameX.Event.Runtime;

   private EventComponent eventComponent;
   // Awake/Start 内で：
   // eventComponent = GameEntry.GetComponent<EventComponent>();
   ```

2. イベント引数クラスを準備します（`GameEventArgs` を継続し、`Create` ファクトリと `Clear`/リサイクルの規約を提供します）：

   ```csharp
   public class LevelUpEventArgs : GameEventArgs
   {
       public int Level { get; private set; }
       public static LevelUpEventArgs Create(int level) { /* ... */ }
   }
   ```

3. 遅延モードで発火（デフォルト推奨、スレッドセーフ）――イベントは送出後の翌フレームにメインスレッドでコールバックされます：

   ```csharp
   eventComponent.Fire(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L124-L128)

   対応するコンポーネントの API シグネチャ：

   ```csharp
   // イベントを送出します。この操作はスレッドセーフであり、メインスレッド以外で送出した場合でも、
   // イベントハンドラー関数がメインスレッドでコールバックされることが保証されますが、イベントは送出後の翌フレームにディスパッチされます。
   public void Fire(object sender, GameEventArgs e)
   {
       m_EventManager.Fire(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L150)

4. 即時モードで発火（メインスレッドのみで使用）――イベントは即座に同期ディスパッチされ、呼び出しが戻る前にハンドラーの実行が完了しています：

   ```csharp
   eventComponent.FireNow(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L130-L134)

   ```csharp
   // イベントの即時送出モードです。この操作はスレッドセーフではなく、イベントは即座にディスパッチされます。
   public void FireNow(object sender, GameEventArgs e)
   {
       m_EventManager.FireNow(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

5. 発火完了後、ディスパッチ結果を観察できます。3 つの方式の比較：

   | API | ディスパッチタイミング | スレッドセーフ | 典型的な用途 |
   |-----|---------|---------|---------|
   | `Fire(object, GameEventArgs)` | 翌フレーム、メインスレッド | はい | デフォルトの選択肢。子スレッド/非同期タスクからのイベント送出 |
   | `FireNow(object, GameEventArgs)` | 即時、同期 | いいえ | UI クリックなどメインスレッドでの即時応答、「イベント処理済み」の状態を後続で読み取る必要がある場合 |
   | `Fire(object, string)` | 翌フレーム、メインスレッド | はい | 引数なしの通知（内部で `EmptyEventArgs` にラップ） |

## よくあるバリエーション

**引数なしイベント（ショートカット）**：一回きりの通知のために引数クラスを定義したくない場合は、文字列 ID を直接渡します。コンポーネント内部では `EmptyEventArgs.Create(eventId)` にラップしてから `Fire` に渡され、その前に `eventId` の非空チェックが行われます：

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

```csharp
eventComponent.Fire(this, "level_up");
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L136-L140)

**子スレッドからの発火**：スレッドプール、Task、ネットワークコールバック内でイベントを送出する場合は必ず `Fire` を使用してください。コールバックがメインスレッド（翌フレーム）で発生することが保証されるため、コールバック内で Unity API に直接アクセスできます。

**未購読時のフォールバック**：購読者のいない ID を発火してもエラーにはなりませんが、「イベントを送ったのに誰も受け取らない」問題の切り分けのために、デフォルトハンドラーを設定できます：

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L142-L151)（API は [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L133-L140) にあります）

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| `Fire` 後、同じフレームでは処理結果を読み取れない | `Fire` は遅延ディスパッチであり、翌フレームにコールバックされる | 同じフレームで結果が必要な場合は `FireNow` を使用する |
| 子スレッドで `FireNow` を呼び出した後、コールバックの動作が異常になる | `FireNow` はスレッドセーフではない | 子スレッドでは必ず `Fire` を使用する |
| 発火後、ハンドラー内で取得したデータが正しくない/空である | 引数オブジェクトがリサイクル・再利用された、または正しく `Create` されていない | 発火のたびに引数クラスの `Create(...)` を呼び出し、古いインスタンスをキャッシュしない |
| イベントを送っても何の反応もない | 対象 ID に購読者がいない | `eventComponent.Check(id, handler)` や `Count(id)` で調査し、必要に応じてデフォルトハンドラーを設定して観察する |
| `Fire(sender, eventId)` が引数チェック例外をスローする | `eventId` が null または空文字列 | 空でない文字列 ID を渡すこと（`GameFrameworkGuard.NotNullOrEmpty` チェック） |

## 検証

- ハンドラー内でログを出力してイベントの受信を確認します：`Debug.Log($"升级到 {args.Level} 级")`（例は [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L102-L106) を参照）。
- 統計プロパティでクロスチェックします：`eventComponent.EventHandlerCount` / `eventComponent.EventCount` / `eventComponent.Count("level_up")`（[EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) と [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L153-L159) を参照）。

## 背景

`EventComponent` は薄いラッパーにすぎず、実際のロジックは `IEventManager`（`EventManager`）の中にあります。`Fire` はイベントプールのキューを利用して翌フレームにメインスレッドで一括ディスパッチするため、スレッドセーフです。`FireNow` はキューをスキップしてハンドラーを直接同期的に呼び出します。イベントの購読と購読解除については、『イベントの購読と購読解除の方法』を参照してください。
