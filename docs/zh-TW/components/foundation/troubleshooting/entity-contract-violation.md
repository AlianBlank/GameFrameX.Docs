# 實體合約驗證失敗時的處理方法

當 `EntityContractValidator.Validate<T>()` 回傳非空清單，或在執行階段 ORM 回報介面屬性不一致時，表示實體類別未滿足其所實作介面（例如：`IEntity`、`IVersionedEntity`、`IAuditableEntity`）的合約。本頁將說明如何依據錯誤訊息找出問題並修正。

## 快速診斷

| 症狀（`Reason` 文字的一部分） | 根本原因 | 修正方法 |
|------|------|------|
| `Property 'XXX' not found on type 'YYY'` | 實體類別缺少介面所需的屬性 | 在實體類別中加入同名稱、同型別的屬性 |
| `Property 'XXX' type mismatch: expected 'A', actual 'B'` | 屬性型別與介面宣告不一致 | 將屬性型別改為介面要求的型別（或可為 Null 的相容型別） |
| `Property 'XXX' is missing a getter` | 屬性僅以 `set` 宣告，缺少 `get`（或 `private get`） | 加入 public 的 getter |
| `Property 'XXX' is missing a setter` | 屬性只有 `get`，缺少 `set`（或 `private set`） | 加入 public 的 setter |
| `Property 'XXX' has multiple declarations on type 'YYY' (possible 'new' keyword shadowing)` | 以 `new` 關鍵字隱藏了繼承的介面屬性 | 刪除 `new`，或統合為單一屬性 |
| 呼叫 `Validate(null)` 時擲出 `ArgumentNullException` | 傳遞了 null 給 `Type` | 傳遞非 null 的實體型別 |

## 修正步驟

### 1. 屬性缺失

這是介面要求特定欄位（例如：`IVersionedEntity.Version`），但實體類別未宣告該欄位的情況。請在實體類別中加入對應的屬性：

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class Player : IVersionedEntity
{
    public long Version { get; set; } // 補上介面要求的屬性
}
```

來源： [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118)

### 2. 型別不一致

這是介面宣告為 `DateTime`，但實體卻使用 `DateTimeOffset` 或 `string` 的情況。請將型別改回介面要求的型別。當介面為實值型別時，實體可使用對應的 `Nullable<T>`，驗證工具會以 `Nullable.GetUnderlyingType` 判斷相容性。

```csharp
public interface IAuditableEntity
{
    DateTime CreatedAt { get; set; }
}

public class Order : IAuditableEntity
{
    public DateTime CreatedAt { get; set; } // 型別必須一致，也可使用 DateTime?
}
```

來源： [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

### 3. getter / setter 缺失

ORM 通常需要同時讀取與寫入。請補上存取子：

```csharp
public DateTime UpdatedAt { get; set; } // get 與 set 兩者都必須是 public
```

來源： [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144)

### 4. `new` 關鍵字造成的隱藏

這是從基底類別繼承的屬性被 `new` 重新宣告，導致 `GetProperty` 命中多個符合項而擲出 `AmbiguousMatchException` 的情況。請刪除 `new` 並統合為單一屬性：

```csharp
// 錯誤：以 new 關鍵字隱藏
public new long Version { get; set; }

// 正確：直接使用基底類別的宣告
// （刪除整個 new 宣告，或使用 override / 明確介面實作）
```

來源： [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108)

### 5. 呼叫自動驗證

在應用程式啟動時或單元測試中呼叫驗證工具，將違規項目一次輸出：

```csharp
using GameFrameX.Foundation.Orm.Entity;

var violations = EntityContractValidator.Validate<Player>();
foreach (var v in violations)
{
    Console.WriteLine($"{v.InterfaceType.Name}.{v.PropertyName}: {v.Reason}");
}
```

回傳的 `EntityContractViolation` 包含 3 個欄位：`InterfaceType`、`PropertyName`、`Reason`。

來源： [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L57-L87), [EntityContractViolation.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractViolation.cs#L38-L78)

## 驗證

修正後，再次呼叫 `Validate<T>()`：

- 若回傳的 `IList<EntityContractViolation>` 長度為 0，表示所有合約皆已滿足。
- 若仍回傳非空項目，請對照上述診斷表中的 `Reason`，持續修正直到清單為空。

## 驗證工具不會檢查的項目

`EntityContractValidator` 僅驗證介面中明確宣告的屬性：

- 介面從其他介面繼承的屬性，會透過 `Type.GetInterfaces()` 納入驗證範圍。
- 欄位（`public int Foo;`）、靜態成員、私用成員不在檢查範圍內。
- 僅當介面本身以屬性語法宣告該成員時才會進行驗證。以方法表達的合約不在範圍內。
