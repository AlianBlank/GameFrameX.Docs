# 기본 구현을 Helper로 교체하여 사용자 정의하는 방법

`EntityHelperBase` 및 `EntityGroupHelperBase` 파생 클래스를 사용자 정의하여 엔티티의 인스턴스화, 생성 및 해제 로직을 직접 처리할 수 있습니다. `EntityComponent`는 리플렉션 타입명(`m_EntityHelperTypeName` / `m_EntityGroupHelperTypeName`)과 Inspector에서 직접 드래그(`m_CustomEntityHelper` / `m_CustomEntityGroupHelper`)라는 두 가지 교체 방식을 제공합니다.

## 사전 조건

- GameFrameX Entity 컴포넌트 패키지가 설치되어 있고 씬에서 `EntityComponent`를 찾을 수 있어야 합니다.
- C# 상속과 Unity `MonoBehaviour`의 기본 사용법을 알고 있어야 합니다.
- 사용자 정의 Helper 클래스는 리플렉션으로 로드될 수 있는 어셈블리에 위치해야 합니다 (코드 트리밍 도구에 의해 제거되지 않도록).

## 작업 단계

1. **새로운 사용자 정의 엔티티 Helper 클래스 생성**, `EntityHelperBase`를 상속하고 세 개의 추상 메서드를 구현합니다.

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;
using UnityEngine;
using YooAsset;

namespace MyGame.Entity
{
    public class MyEntityHelper : EntityHelperBase
    {
        public override object InstantiateEntity(object entityAsset)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return null;
            }
            return handle.InstantiateSync();
        }

        public override IEntity CreateEntity(object entityInstance, IEntityGroup entityGroup, object userData)
        {
            var go = entityInstance as GameObject;
            if (go == null)
            {
                Log.Error("Entity instance is invalid.");
                return null;
            }
            go.transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform);
            return go.GetOrAddComponent<Entity>();
        }

        public override void ReleaseEntity(object entityAsset, object entityInstance)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return;
            }
            handle.Release();
            Destroy((Object)entityInstance);
        }
    }
}
```

출처: [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L41-L101)

2. **(선택 사항) 새로운 사용자 정의 엔티티 그룹 Helper 클래스 생성**, `EntityGroupHelperBase`를 상속합니다. 이 기본 클래스 자체에는 추상 멤버가 없으므로 필요에 따라 자식 오브젝트 관리 로직을 추가하면 됩니다.

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

namespace MyGame.Entity
{
    public class MyEntityGroupHelper : EntityGroupHelperBase
    {
        // 여기에서 엔티티 그룹 노드 관리 로직을 확장하세요
    }
}
```

출처: [EntityGroupHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityGroupHelperBase.cs#L39-L41)

3. **씬에서 `EntityComponent`를 열고 교체 방식을 선택합니다 (둘 중 하나 선택)**:

   - **방법 A (리플렉션 타입명)**: `Entity Helper Type Name` 또는 `Entity Group Helper Type Name` 필드를 네임스페이스를 포함한 전체 클래스명으로 수정합니다 (예: `MyGame.Entity.MyEntityHelper`).
   - **방법 B (Inspector에서 직접 드래그)**: 위의 Helper를 구현한 `MonoBehaviour` 프리팹을 `Custom Entity Helper` 또는 `Custom Entity Group Helper` 필드에 연결합니다.

```csharp
// EntityComponent의 관련 필드 선언
[SerializeField] private string m_EntityHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityHelper";
[SerializeField] private EntityHelperBase m_CustomEntityHelper = null;

[SerializeField] private string m_EntityGroupHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityGroupHelper";
[SerializeField] private EntityGroupHelperBase m_CustomEntityGroupHelper = null;
```

출처: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L62-L68)

4. **씬을 실행하여 검증합니다**. `EntityComponent.Start()`는 다음 우선순위에 따라 Helper를 생성합니다. 먼저 Inspector의 `m_CustomEntityHelper`가 할당되어 있는지 확인하고, 할당되지 않은 경우 `m_EntityHelperTypeName`을 통해 `Helper.CreateHelper`로 리플렉션 생성을 시도하며, 여전히 null이면 `Can not create entity helper.` 오류를 출력합니다.

```csharp
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
}
```

출처: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L171-L175)

## 일반적인 변형

| 시나리오 | 방법 |
|------|------|
| 엔티티 그룹 노드 마운트 전략만 교체 | `EntityGroupHelperBase`를 상속하고, `EntityHelperBase`는 기본 구현 유지 |
| Helper 내에서 Unity 라이프사이클에 접근하고 싶음 | 기본 클래스에서 상속받은 `MonoBehaviour` 메서드(`Awake/OnEnable/...`)를 직접 사용 |
| 어셈블리가 트리밍되어 리플렉션 실패 | `link.xml` 또는 `[Preserve]` 태그에 사용자 정의 Helper 클래스 보존 표시 ([GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L6-L24)의 보존 방식 참고) |

## 일반적인 오류

| 오류 현상 | 원인 | 해결 방법 |
|----------|------|------|
| 시작 로그 `Can not create entity helper.` 출력 | 리플렉션 타입명이 비어있거나 오타가 있으며, `CustomEntityHelper`도 드래그되지 않음 | 타입명에 네임스페이스가 포함되어 있는지 확인 (예: `MyGame.Entity.MyEntityHelper`) |
| 사용자 정의 Helper 내 `Awake`가 트리거되지 않음 | Inspector 드래그 방식이 아닌 리플렉션 생성 경로를 사용 중 | 방법 B로 Helper를 `m_CustomEntityHelper` 필드에 연결하거나, `CreateEntity`에서 직접 `Instantiate` 호출하여 연결 |
| `ReleaseEntity` 호출 후 오브젝트가 실제로 파괴되지 않음 | 재정의 시 `Object.Destroy` 호출이 누락됨 | `ReleaseEntity` 마지막에 `Destroy((Object)entityInstance)` 호출 추가 |
| 릴리스 버전에서 `MissingReferenceException` 발생 | 사용자 정의 클래스가 코드 트리밍됨 | `[Preserve]` 어트리뷰트 또는 `link.xml`에 보존 설정 추가 |

## 배경 (선택 사항)

`EntityComponent`의 내장 필드는 기본적으로 `DefaultEntityHelper` / `DefaultEntityGroupHelper`를 가리키며, 이는 내부적으로 YooAsset의 `AssetHandle`에 의존하여 인스턴스화 및 해제를 수행합니다 ([DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L48-L100) 참고). 사용자 정의 Helper의 존재 의미는 프레임워크를 수정하지 않고도 Addressables, 자체 개발 리소스 파이프라인 또는 오브젝트 풀을 사용하는 인스턴스화 방식으로 교체할 수 있도록 하는 데 있습니다.
