# How to Hide and Recycle Entities

Calling the hide interface of `EntityManager` puts an entity into the "hidden" state. The framework automatically recycles the instance object, releases the entity group slot it occupies, and triggers the `HideEntityCompleteEventArgs` event once hiding is complete. Hiding does not destroy configuration data, and the entity can be shown again at any time via `ShowEntity`.

## Prerequisites

- The entity manager has been initialized via `EntityComponent` and entity group registration is complete.
- You have the entity ID (`int entityId`) or an `IEntity` reference of the entity to hide.

## Steps

1. Get the `IEntityManager` via the entity component:

```csharp
IEntityManager entityManager = GameEntry.GetComponent<EntityComponent>().EntityManager;
```

2. Hide by entity ID (most common):

```csharp
// Without passing userData
entityManager.HideEntity(entityId);

// With business context
entityManager.HideEntity(entityId, userData);
```

The implementation first checks whether the entity is still in the loading queue; if it is still loading (`IsLoadingEntity` is true), the entity is added to `m_EntitiesToReleaseOnLoad` and recycled in the load callback; otherwise, the `EntityInfo` is retrieved from `m_EntityInfos` and `InternalHideEntity` is called to complete hiding.

Source: [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L46-L72)

3. You can also pass an `IEntity` reference directly:

```csharp
entityManager.HideEntity(entity);
entityManager.HideEntity(entity, userData);
```

A `GameFrameworkException("Entity is invalid.")` is thrown when the reference is `null`.

Source: [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L78-L96)

4. Batch hiding (commonly used when switching scenes or exiting levels):

```csharp
// Hide all loaded entities
entityManager.HideAllLoadedEntities(userData);

// Hide all loading entities (cancels unfinished loads)
entityManager.HideAllLoadingEntities();
```

`HideAllLoadedEntities` copies the keys of the current `m_EntityInfos` and then calls `InternalHideEntity` one by one, avoiding modifying the collection during iteration; `HideAllLoadingEntities` adds all entity IDs still loading to the pending-release set and clears the loading queue.

Source: [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L101-L135)

5. Listen for the hide-complete event and recycle custom resources in the callback (optional):

```csharp
EventComponent.Subscribe(HideEntityCompleteEventArgs.EventId, (sender, args) =>
{
    var e = (HideEntityCompleteEventArgs)args;
    // e.EntityId / e.EntityAssetName are available
    // Release resources exclusively held by this entity here, such as textures and AudioClips
});
```

`HideEntityCompleteEventArgs` is a runtime type referenced in `GameFrameXEntityCroppingHelper`; the framework publishes it at the end of `InternalHideEntity`.

Source: [GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L1-L20)

## Common Variants

- **Hide and detach parent-child relationships**: First call `DetachEntity(childEntityId, userData)` or `DetachChildEntities(parentEntityId, userData)`, then `HideEntity`. `DetachEntity` calls `OnDetached` on the parent entity and `OnDetachFrom` on the child entity before proceeding with the hide flow.
- **With user data**: All `HideEntity` / `HideAllLoadedEntities` / `DetachEntity` methods have an `object userData` overload for passing business context through to `IEntity.OnHide` and the event arguments.
- **Show again after hiding**: `HideEntity` only sets the entity to hidden and recycles the instance; the `EntityInfo` is retained. Simply call `ShowEntity(entityId, ...)` again to reuse it.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Log.Error("Can not find entity '{0}'.")` | `entityId` is not registered or has already been hidden | Confirm the entity is in the `WillShow` / `Show` state before calling |
| `GameFrameworkException: Entity is invalid.` | A `null` `IEntity` was passed | Use `HideEntity(entityId, ...)` instead, or perform a null reference check first |
| Entity still in the scene after hiding | Only `HideEntity` was called without listening for `HideEntityCompleteEventArgs`, so the custom logic was not triggered | Perform the release of your own held resources in the event callback, or confirm that `EntityGroupHelper.ReleaseEntity` has automatically recycled it |

## Background (Optional)

The recycling in `HideEntity` consists of two parts: the framework layer switches `EntityInfo.Status` to the hidden state in `InternalHideEntity`, calls `EntityGroupHelper.ReleaseEntity` to return the object to the pool, and publishes `HideEntityCompleteEventArgs`; the business layer releases exclusively-held resources in the event callback. Together, they recycle entity instances without destroying the configuration.
