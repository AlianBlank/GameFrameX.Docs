# 참조 풀을 사용하여 GC 할당 줄이기

참조 풀(`ReferencePool`)은 `IReference` 인터페이스를 구현한 객체 인스턴스를 캐시하는 데 사용되며, `Acquire`로 가져오고 `Release`로 반환하여 재사용함으로써 반복적인 `new`로 인한 GC 압력을 피합니다. 이 페이지에서는 GameFrameX에서 참조 풀을接入하고 커스텀 타입에 사용하는 완전한 단계를 제공합니다.

## 전제 조건

- 프로젝트에 `GameFrameX.Runtime.Base.ReferencePool`과 `GameFrameX.Runtime.ReferencePoolComponent`가 도입되어 있어야 합니다(프레임워크에 기본 포함됨).
- 씬에 `ReferencePoolComponent`가 부착되어 있거나(메뉴 `Add Component → GameFrameX → ReferencePool`), 코드에서 정적 클래스 `ReferencePool`을 통해 직접 접근해야 합니다.

## 작업 단계

1. **커스텀 타입이 `IReference`를 구현하도록 합니다**. 타입은 매개변수 없는 생성자를 가져야 하며, `Clear()`에서 필드를 초기화하여 다음에 꺼낼 때 깨끗한 상태를 보장해야 합니다.

   ```csharp
   using GameFrameX.Runtime;

   public sealed class DamageInfo : IReference
   {
       public int AttackerId { get; private set; }
       public int TargetId   { get; private set; }
       public float Amount  { get; private set; }

       public void Clear()
       {
           AttackerId = 0;
           TargetId   = 0;
           Amount     = 0f;
       }

       internal void Fill(int attackerId, int targetId, float amount)
       {
           AttackerId = attackerId;
           TargetId   = targetId;
           Amount     = amount;
       }
   }
   ```

   Source: [Tests/ReferencePoolTests.cs#L11-L29](/src/Tests/ReferencePoolTests.cs#L11-L29)

2. **Acquire로 인스턴스 가져오기**. 제네릭 버전을 사용하면 수동 형변환이 필요 없습니다; 풀이 비어 있으면 프레임워크가 매개변수 없는 생성자를 호출해 생성합니다.

   ```csharp
   DamageInfo info = ReferencePool.Acquire<DamageInfo>();
   ```

   시그니처:`public static T Acquire<T>() where T : class, IReference, new()`, [Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132) 참조.

3. **Release로 인스턴스 반환**. 반환 시 자동으로 `Clear()`가 호출되지만, 필드 단위 초기화는 여전히 사용자의 `Clear()`가 담당합니다.

   ```csharp
   ReferencePool.Release(info);
   ```

   시그니처:`public static void Release(IReference reference)`, [Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167) 참조. `null`을 전달하면 `GameFrameworkException("Reference is invalid.")`이 발생합니다, [Tests/ReferencePoolTests.cs#L79](/src/Tests/ReferencePoolTests.cs#L79) 참조.

4. **(선택 사항) 시작 전에 풀 용량 프리워밍**. 전투/레벨 시작 시 `Add<T>(count)`를 호출하여 런타임 중 즉각적인 확장을 피합니다.

   ```csharp
   ReferencePool.Add<DamageInfo>(64);
   ```

   시그니처:`public static void Add<T>(int count) where T : class, IReference, new()`, [Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181) 참조.

5. **(선택 사항) 풀 상태 확인**. 디버그 패널이나 Profiler 훅에서 각 타입의 캐시 정보를 읽습니다.

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| `GameFrameworkException: Reference is invalid.` | `null`을 `Release`에 전달함 | Release 전에 null 체크를 하거나, `using`/`try-finally` 블록 내에서 반환 |
| 꺼낸 객체에 이전 데이터가 남아 있음 | `Clear()`에서 필드를 초기화하지 않음 | `Clear()`에서 모든 필드를 명시적으로 기본값으로 재설정 |
| 타입을 `Acquire`할 수 없음 | 타입이 `IReference`를 구현하지 않았거나 `public` 매개변수 없는 생성자가 없음 | 인터페이스 구현, 매개변수 없는 생성자 추가 |
| Profiler에 풀이 폭증으로 표시됨 | 계속 Acquire만 하고 Release하지 않음 | 사용 종료 경로(예외 분기도 포함)에서 Release 보장; `try { ... } finally { Release(info); }` 사용 가능 |
| 엄격한 검사를 활성화한 후 성능 저하 | `ReferencePool.EnableStrictCheck = true`이 리플렉션 검증을 활성화함 | 디버그 기간에만 켜고, 릴리스 버전에서는 끔 |

## 배경(선택 사항)

각 CLR 타입은 풀 내부에 독립적인 `ReferenceCollection`을 가지며, 내부적으로 `Stack<IReference>`를 유지합니다. `Acquire`는 먼저 스택에서 팝하고, 스택이 비어 있을 때만 `new`합니다;`Release`는 `Clear()`를 호출한 후 스택에 푸시합니다. `EnableStrictCheck`를 활성화하면 리플렉션으로 타입을 검증하므로 성능에 영향을 미치며, 디버그 용도로만 사용됩니다.
