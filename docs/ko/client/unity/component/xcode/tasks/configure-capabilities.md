# App 기능(Capabilities) 구성

빌드 후처리용 JSON 구성 파일에 `capabilities` 필드를 작성하면, Unity가 Xcode 프로젝트를 내보낼 때 `gameframex.entitlements`를 자동으로 생성하고 In-App Purchase, Game Center, 푸시, iCloud, App Groups 등 13가지 기능을 `Unity-iPhone` 프로젝트에 기록합니다. Xcode를 수동으로 열어 체크할 필요가 없습니다.

## 사전 조건

- Unity 프로젝트에 이 패키지(`com.gameframex.unity.xcode`)가 설치되어 있고, `Editor/GameFrameX.Xcode.Editor.asmdef`가 존재해야 합니다.
- 빌드 후처리가 읽을 JSON 구성 파일이 이미 존재해야 합니다(최상위에 `capabilities` 객체 포함, [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L279-L303) 참조).
- 대상 플랫폼이 iOS여야 합니다(기능 설정 코드는 `#if UNITY_IOS` 블록 내에 위치).

## 작업 단계

1. 빌드 후처리에 사용되는 JSON 구성 파일을 열고 최상위의 `capabilities` 필드를 찾습니다(없는 경우 빈 객체 `"capabilities": {}`를 추가합니다).
2. 필요에 따라 기능을 활성화합니다. 다음은 전체 13개 항목을 모두 포함한 전체 예시입니다:

```json
{
  "capabilities": {
    "inAppPurchase": true,
    "gameCenter": false,
    "pushNotifications": false,
    "signInWithApple": false,
    "backgroundModes": ["audio", "remote-notification"],
    "iCloud": {
      "keyValueStorage": false,
      "iCloudDocument": false,
      "customContainers": []
    },
    "appGroups": [],
    "associatedDomains": [],
    "keychainSharing": false,
    "healthKit": false,
    "siri": false,
    "personalVPN": false,
    "dataProtection": false
  }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L281-L303)

3. iOS 빌드를 다시 실행합니다. 빌드 후처리는 `SetCapabilities`를 호출하여 `ProjectCapabilityManager`를 생성한 뒤, 각 기능을 항목별로 기록하고 저장합니다:

```csharp
var projectCapabilityManager = new ProjectCapabilityManager(path + "/Unity-iPhone.xcodeproj/project.pbxproj", "gameframex.entitlements", null, targetGuid);

// In-App Purchase
if (hashtable.ContainsKey("inAppPurchase") && hashtable["inAppPurchase"] is bool inAppPurchase && inAppPurchase)
{
    projectCapabilityManager.AddInAppPurchase();
    Debug.Log("已添加 In-App Purchase Capability");
}

// ... 나머지 기능은 구성에 따라 항목별로 기록됩니다 ...

projectCapabilityManager.WriteToFile();
```

출처: [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L29-L35)

4. 빌드 완료 후 Unity Console에서 로그를 확인합니다. 기능 하나가 성공적으로 추가될 때마다 `已添加 XXX Capability` 로그가 한 줄씩 출력되며(예: `已添加 Push Notifications Capability`), 마지막으로 `projectCapabilityManager.WriteToFile()`로 디스크에 기록합니다([PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L231-L231) 참조).

| 필드 | 타입 | 설명 |
| :--- | :--- | :--- |
| `inAppPurchase` | bool | 인앱 구매 |
| `gameCenter` | bool | Game Center |
| `pushNotifications` | bool | 푸시 알림 |
| `signInWithApple` | bool | Sign In with Apple |
| `backgroundModes` | string[] | 백그라운드 모드, 선택 가능한 값: `audio`, `location`, `voip`, `newsstand`, `external`, `bluetooth`, `bluetooth-peripheral`, `fetch`, `remote-notification` |

| `iCloud.iCloudDocument` | bool | iCloud 문서 저장소 |
| `iCloud.customContainers` | string[] | iCloud 사용자 지정 컨테이너 |
| `appGroups` | string[] | App Groups 식별자 |
| `associatedDomains` | string[] | 연관 도메인(Universal Links) |
| `keychainSharing` | bool 또는 object | `false` 비활성화; `true` 기본 그룹 사용; 또는 `{"accessGroups": ["group1"]}`로 사용자 지정 그룹 지정 |

## 일반적인 변형

### 인앱 구매 + 원격 푸시만 활성화

```json
{
  "capabilities": {
    "inAppPurchase": true,
    "pushNotifications": true
  }
}
```

푸시 알림은 `AddPushNotifications(false)`로 기록되며, 두 번째 매개변수는 `false`입니다(Push Notifications 환경 capability의 development 변형을 활성화하지 않음). [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L45-L50) 참조.

### 백그라운드 오디오 및 원격 알림 활성화

```json
{
  "capabilities": {
    "backgroundModes": ["audio", "remote-notification"]
  }
}
```

`backgroundModes` 배열의 문자열은 소문자로 변환되어 Unity의 `BackgroundModesOptions` 플래그 비트에 매핑된 후 한 번에 기록됩니다([PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L60-L108) 참조). 매핑 관계: `audio`→`AudioAirplayPiP`, `location`→`LocationUpdates`, `voip`→`VoiceOverIP`, `newsstand`→`NewsstandDownloads`, `external`→`ExternalAccessoryCommunication`, `bluetooth`→`UsesBluetoothLEAccessory`, `bluetooth-peripheral`→`ActsAsABluetoothLEAccessory`, `fetch`→`BackgroundFetch`, `remote-notification`→`RemoteNotifications`.

### iCloud 컨테이너 구성

```json
{
  "capabilities": {
    "iCloud": {
      "keyValueStorage": true,
      "iCloudDocument": true,
      "customContainers": ["iCloud.com.example.mygame"]
    }
  }
}
```

세 개의 하위 항목은 각각 `AddiCloud(enableKeyValueStorage, enableiCloudDocument, containers)`의 세 매개변수에 해당합니다([PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L111-L134) 참조).

### Keychain Sharing의 세 가지 작성 방법

```json
{
  "capabilities": {
    "keychainSharing": true,
    "keychainSharing_custom": { "accessGroups": ["group.com.example.shared"] }
  }
}
```

- `false`: Keychain Sharing을 기록하지 않습니다.
- `true`: 그룹 `$(AppIdentifierPrefix)` + 번들 ID(`bundleId`)를 자동으로 생성합니다([PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L159-L165) 참조).
- `{"accessGroups": [...]}`: 그룹을 명시적으로 지정합니다([PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L166-L183) 참조). 실제 구성에서는 둘 중 하나만 사용하며, 위의 예시는 두 가지 형식을 보여주기 위한 것입니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Console에 `已添加 XXX Capability` 로그가 전혀 없음 | `capabilities` 구성이 `null`이어서 `SetCapabilities`가 바로 `return`함 | JSON 최상위에 `"capabilities"` 객체가 존재하고 키 이름 철자가 정확한지 확인(대소문자 구분) |
| 특정 기능이 계속 적용되지 않음 | 불리언 항목을 문자열(예: `"true"`)로 작성하여 `is bool` 검사를 통과하지 못함 | 모든 불리언 항목은 JSON의 `true` / `false` 리터럴을 사용 |
| `backgroundModes` 전체가 무효화됨 | 배열 내 요소가 비어 있거나 대소문자가 일치하지 않음 | 코드가 `ToLower()` 후 매칭하므로 소문자로 작성하면 됨; 빈 요소는 건너뜀 |
| Keychain Sharing이 기록되지 않음 | `keychainSharing: true`인데 `bundleId`가 비어 있어 그룹 배열이 null임 | 구성에 `bundleId`를 함께 작성했는지 확인하거나, `accessGroups`로 명시적으로 지정 |
| `appGroups` / `associatedDomains`가 빈 배열일 때 기록되지 않음 | 코드에서 배열이 비어 있지 않은 경우에만 해당 Add 메서드를 호출함 | 최소한 하나의 그룹 또는 도메인을 입력 |

## 검증

1. iOS 프로젝트를 다시 빌드하면 Console에 `开始设置Capabilities`와 각 기능에 해당하는 `已添加 XXX Capability` 로그가 나타나야 합니다.
2. 내보낸 Xcode 프로젝트를 열고 `Unity-iPhone` 타깃을 선택한 뒤 **Signing & Capabilities**에서 대상 기능이 나타나고 프로젝트 내에 `gameframex.entitlements` 파일이 생성되었는지 확인합니다.
3. 실기기에서 관련 기능(예: 인앱 구매, 푸시)을 실행하여 Apple 개발자 포털의 App ID에 해당 기능이 체크되어 있는지 확인합니다. 이 패키지는 프로젝트 파일 작성만 담당하며, Apple Developer 포털의 App ID 구성은 여전히 수동으로 활성화해야 합니다.

## 배경

기능은 `PostProcessBuildHelper`의 partial 클래스인 `SetCapabilities` 메서드에서 일괄 처리됩니다. 이 메서드는 구성의 `Hashtable`을 읽고, 각 키에 대해 `UnityEditor.iOS.Xcode.ProjectCapabilityManager`의 해당 메서드(`AddInAppPurchase`, `AddGameCenter`, `AddPushNotifications`, `AddSignInWithApple`, `AddBackgroundModes`, `AddiCloud`, `AddAppGroups`, `AddKeychainSharing`, `AddAssociatedDomains`, `AddHealthKit`, `AddSiri`, `AddPersonalVPN`, `AddDataProtection`)를 호출한 후 마지막에 `WriteToFile()`로 한 번에 기록합니다. 전체 메서드는 `try/catch`로 감싸져 있어, 모든 예외는 `Debug.LogError`로 출력되며 빌드가 중단되지 않습니다. 패키지의 전체 구조와 구성 진입점에 대해서는 《개요》를 참조하십시오.
