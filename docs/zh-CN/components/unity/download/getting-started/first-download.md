# 5 分钟跑通第一个下载任务

跟着本页步骤,5 分钟内就能让一个文件从 URL 完整下载到本地磁盘,并通过事件拿到成功/失败回调。

## 前置条件

- Unity 2019.4 或更高版本
- 已安装本包(三种方式任选其一,见 README):
  - 在 `Packages/manifest.json` 的 `scopedRegistries` 中添加 GameFrameX 注册表,`dependencies` 加上 `com.gameframex.unity.download`
  - 或在 Package Manager 里通过 Git URL 添加 `https://github.com/gameframex/com.gameframex.unity.download.git`
  - 或把仓库直接放到 `Packages/` 目录
- 场景中存在 `GameFramework` 启动入口,且已挂载 `DownloadComponent`(组件默认会自动注册到 `GameEntry`)

## 操作步骤

1. **确认组件已挂载**。`DownloadComponent` 通过 `[GameFrameXAutoComponent(-4000)]` 自动注册,启动后可在 `GameEntry` 上获取:

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L44-L46)

2. **添加第一个下载任务**。最小可用调用只需两个参数:本地保存路径 `downloadPath` 与远端地址 `downloadUri`,返回任务序列 ID:

   ```csharp
   int serialId = downloadComponent.AddDownload(
       "/本地保存路径/file.zip",      // downloadPath
       "https://example.com/file.zip"  // downloadUri
   );
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L280)

3. **订阅成功/失败事件**(推荐)。通过 `EventComponent` 监听 `DownloadSuccess` 与 `DownloadFailure`:

   ```csharp
   var eventComponent = GameEntry.GetComponent<EventComponent>();
   eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);

   void OnDownloadSuccess(object sender, GameEventArgs e)
   {
       var args = (DownloadSuccessEventArgs)e;
       if (args.SerialId == serialId) { /* 下载完成 */ }
   }

   void OnDownloadFailure(object sender, GameEventArgs e)
   {
       var args = (DownloadFailureEventArgs)e;
       Debug.LogError($"下载失败:{args.ErrorMessage}");
   }
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/README.zh-CN.md#L98-L127)

4. **或者走异步**。如果不想订阅事件,可以直接 `await` `Download(...)` 的返回:

   ```csharp
   bool success = await downloadComponent.Download(
       "/本地保存路径/file.zip",
       "https://example.com/file.zip"
   );

   if (success) { /* 下载完成 */ }
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L312)

5. **验证**。运行场景后查看目标路径,文件存在且 `OnDownloadSuccess` 触发即为成功;若一直未触发,见下方「常见错误」。

## 常见变体

- **带优先级与标签** —— 数值越高越优先,可按标签分组查询或批量移除:

  ```csharp
  int id = downloadComponent.AddDownload(
      downloadPath, downloadUri,
      tag: "assets",
      priority: 10
  );
  TaskInfo[] infos = downloadComponent.GetDownloadInfos("assets");
  downloadComponent.RemoveDownloads("assets");
  ```

  Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L339-L348)

- **全局暂停 / 恢复** —— 切换 `Paused` 属性会作用于全部代理:

  ```csharp
  downloadComponent.Paused = true;   // 暂停
  downloadComponent.Paused = false;  // 恢复
  ```

  Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L69-L73)

- **只关心单次结果**(轻量写法) —— 用 `Download(path, uri)` 返回的 `Task<bool>` 直接 await,不需要订阅事件。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GetComponent<DownloadComponent>()` 返回 null | 场景未挂载 `GameFramework` 启动组件,或包未正确导入 | 确认 `Packages/manifest.json` 中依赖已生效,并检查启动入口 |
| 下载回调一直没触发 | 只调用了 `AddDownload` 却没订阅 `DownloadSuccessEventArgs` / `DownloadFailureEventArgs`,或回调里没匹配 `SerialId` | 订阅两个事件,并在回调里用 `args.SerialId == serialId` 过滤 |
| 文件写到了意外位置 | `downloadPath` 用了相对路径,Unity 在不同平台基准路径不同 | 使用绝对路径(如 `Application.persistentDataPath + "/file.zip"`) |
| 下载被卡住不结束 | `Paused` 被设为 `true` 全局暂停 | 把 `downloadComponent.Paused = false` |

## 背景(可选)

`DownloadComponent` 内部使用 `IDownloadManager` 管理一个可配置数量的下载代理池,默认 3 个代理并发执行,任务按优先级派发;底层通过 `UnityWebRequestDownloadAgentHelper` 与 Unity 的 `UnityWebRequest` 通信,可通过 Inspector 替换为自定义 `IDownloadAgentHelper` 实现。`FlushSize`(默认 1 MB)控制刷盘阈值,用于断点续传。
