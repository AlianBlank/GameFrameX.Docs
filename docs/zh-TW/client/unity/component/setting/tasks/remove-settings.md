# 設定的刪除與清除

使用 `ISettingManager` 介面，可以在執行時刪除單一項目，或一次清除所有設定。常用於重設玩家設定、清除快取以及切換帳戶等場景。

## 前置條件

- 已完成[快速開始](../../overview/quick-start)的初始化流程，且 `SettingManager` 已由 `SettingComponent` 建立並持有。
- 已透過 `SetSettingHelper` 設定設定輔助器 `ISettingHelper`。若未設定，刪除/清除介面將會擲出 `GameFrameworkException("Setting helper is invalid.")`。
- 已取得 `ISettingManager` 實例。請參閱下方「取得管理器」一節。

## 操作步驟

1. 取得設定管理器的實例。

   ```csharp
   var settingManager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>();
   if (settingManager == null)
   {
       // 通常是 SettingComponent 尚未附加,或是初始化失敗
       return;
   }
   ```

   來源:[SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

2. 指定名稱以刪除單一項目。刪除前可使用 `HasSetting` 確認是否存在。

   ```csharp
   const string key = "Player.MusicVolume";
   if (settingManager.HasSetting(key))
   {
       bool removed = settingManager.RemoveSetting(key);
       if (removed)
       {
           settingManager.Save();
       }
   }
   ```

   來源:[SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L210-L234)

3. 一次清除所有項目(請謹慎使用，所有索引鍵都會被刪除)。

   ```csharp
   settingManager.RemoveAllSettings();
   settingManager.Save(); // 是否需要手動呼叫 Save 取決於具體實作
   ```

   來源:[SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L244-L249)

4. 驗證結果。再次列舉設定項目，確認數量符合預期。

   ```csharp
   int remaining = settingManager.Count; // 應為 0(全部清除),或比刪除前少 1
   string[] names = settingManager.GetAllSettingNames();
   ```

   來源:[SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L84-L92)

## 介面速查表

| 方法 | 簽章 | 行為 |
|------|------|------|
| `HasSetting` | `bool HasSetting(string settingName)` | 若設定名稱為空，將擲出 `GameFrameworkException("Setting name is invalid.")`。否則查詢其是否存在。 |
| `RemoveSetting` | `bool RemoveSetting(string settingName)` | 回傳 `bool` 表示刪除是否成功。若設定名稱為空則擲出例外。 |
| `RemoveAllSettings` | `void RemoveAllSettings()` | 清除所有項目。沒有回傳值，且除參數驗證外不會發生其他錯誤。 |

來源:[ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L104-L133)

## 常見變化

- 僅刪除而不儲存：某些後端(例如 `PlayerPrefs`)若未明確呼叫 `Save`,變更將不會寫入磁碟，若刪除後程序崩潰，變更可能會遺失。請依據具體的 `ISettingHelper` 實作進行判斷。
- 刪除唯讀/預設設定：若設定是從序列化檔案載入的，`RemoveSetting` 通常只會影響執行時記憶體快取中的項目，不會寫回來源檔案。

## 常見錯誤

- **"Setting helper is invalid."**:未設定 `ISettingHelper`。請確認 `SettingComponent` 已正確初始化，且已指派輔助器。
- **"Setting name is invalid."**:`settingName` 為 `null` 或空字串。刪除前必須傳入有效的名稱。
- **刪除後仍讀取到舊值**：由於後端不會自動持久化，請記得呼叫 `Save()`。另外，下次執行 `Load()` 時，可能會從持久層再次載入同名項目。
- **未達到預期的清理效果**:`RemoveAllSettings` 不會重設後端的底層(例如 `PlayerPrefs` 中其他無關的索引鍵)，僅會清除目前管理器所持有的項目。

## 背景(選填)

`SettingManager` 是一個輕量的包裝器，所有刪除/清除操作都會直接轉發至 `ISettingHelper` 實作(抽象方法定義於 [`SettingHelperBase`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs))。`DefaultSettingHelper`、`PlayerPrefsSettingHelper` 等具體實作會各自決定是僅修改記憶體，還是同步至底層儲存。模組關閉時會自動呼叫 `Save()`。詳情請參閱 [`Shutdown`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L112-L115)。
