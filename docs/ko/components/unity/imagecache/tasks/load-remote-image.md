# 원격 이미지를 비동기로 로드하는 방법

`IImageCacheManager.LoadImageAsync`를 통해 원격 이미지를 비동기로 로드할 수 있습니다. WebGL이 아닌 플랫폼에서는 디스크 캐시를 우선 사용하고, 캐시 미스 시 로컬로 다운로드한 후 로드합니다. WebGL 플랫폼에서는 `UnityWebRequestTexture`를 통해 직접 로드하며, 캐시는 브라우저가 관리합니다.

## 사전 조건

- `com.gameframex.unity.imagecache` 패키지가 설치되어 있고, 씬에 `ImageCacheComponent`가 마운트되어 있어야 합니다.
- `com.gameframex.unity.download` 패키지가 설치되어 있어야 합니다(WebGL이 아닌 플랫폼에서 필수, 파일 다운로드용).
- 원격 이미지 주소는 반드시 `http://` 또는 `https://`로 시작해야 합니다.
- `ImageCacheConfig.CachePath`에 쓰기 가능한 로컬 디렉터리가 지정되어 있어야 합니다(WebGL이 아닌 플랫폼에서 필수).

## 작업 단계

1. 이미지 캐시 매니저 인스턴스를 가져옵니다. `ImageCacheComponent`는 이미 생명주기를 캡슐화하므로, 컴포넌트 필드 또는 `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IImageCacheManager>()`를 통해 직접 가져올 수 있습니다.

    ```csharp
    using GameFrameX.ImageCache.Runtime;
    using UnityEngine;

    public class MyImageLoader : MonoBehaviour
    {
        [SerializeField] private ImageCacheComponent imageCacheComponent;

        private IImageCacheManager _manager;

        private void Start()
        {
            _manager = imageCacheComponent; // 컴포넌트 자체가 IImageCacheManager를 구현함
        }
    }
    ```

    Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs)

2. `LoadImageAsync`를 호출하고 반환된 `Task<Texture2D>`를 `await` 합니다. 이 메서드는 디스크 캐시 적중, 파일 다운로드, `Texture2D` 디코딩의 전체 흐름을 자동으로 처리합니다. 로드 성공 시 `Texture2D`를 반환하고, 실패 시 `null`을 반환합니다.

    ```csharp
    using System.Threading;
    using System.Threading.Tasks;
    using UnityEngine;

    public async Task<Sprite> LoadHeadIconAsync(string url, CancellationToken ct)
    {
        var texture = await _manager.LoadImageAsync(url, ct);
        if (texture == null)
        {
            Debug.LogWarning($"로드 실패:{url}");
            return null;
        }

        var sprite = Sprite.Create(
            texture,
            new Rect(0, 0, texture.width, texture.height),
            new Vector2(0.5f, 0.5f));
        sprite.name = url;
        return sprite;
    }
    ```

    Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L18-L26)

3. 호출 전에 먼저 URL을 검증합니다. `LoadImageAsync` 내부에서 빈 문자열이거나 `http(s)://`로 시작하지 않는 주소는 경고를 출력하고 `null`을 반환합니다. 비즈니스 측에서도 사전에 방어적 검증을 수행하여 불필요한 `await`를 피할 수 있습니다.

    ```csharp
    if (string.IsNullOrEmpty(url) ||
        (!url.StartsWith("http://") && !url.StartsWith("https://")))
    {
        Debug.LogWarning("잘못된 URL");
        return null;
    }

    var tex = await _manager.LoadImageAsync(url);
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

4. (선택 사항)`CancellationToken`을 사용하여 진행 중인 로드를 취소합니다. WebGL이 아닌 플랫폼에서만生效하며, 페이지 파괴, 사용자의 씬 전환 등 미완료 로드를 해제하는 시나리오에 적합합니다.

    ```csharp
    private CancellationTokenSource _cts;

    public async void Reload(string url)
    {
        _cts?.Cancel();
        _cts = new CancellationTokenSource();

        var tex = await _manager.LoadImageAsync(url, _cts.Token);
        // 컴포넌트가 파괴된 경우 tex는 null일 수 있음
    }
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L122-L150)

5. 로드 완료 후 `Texture2D`를 UI에 적용합니다. `RawImage.texture`에 직접 할당하거나, 단계 2처럼 `Sprite`로 래핑하여 `Image`에 사용할 수 있습니다.

    ```csharp
    [SerializeField] private UnityEngine.UI.RawImage target;

    public async Task ApplyAsync(string url)
    {
        var tex = await _manager.LoadImageAsync(url);
        if (tex != null) target.texture = tex;
    }
    ```

## 일반적인 변형

- **미리 다운로드 및 캐시**: 동일한 URL에 대해 여러 번 `await LoadImageAsync`를 호출하면, 첫 번째 다운로드 후 파일이 URL의 MD5 해시 이름으로 `CachePath`에 캐시되어 후속 호출은 디스크에서 직접 읽으므로 반복 다운로드가 필요 없습니다. 씬 진입 시 자주 사용하는 이미지를 사전에 워밍업할 수 있습니다.

    ```csharp
    // WebGL이 아닌 플랫폼: IsCached는 이미 다운로드되었는지 판단하는 데 사용할 수 있음
    if (_manager.IsCached(url))
    {
        Debug.Log("로컬 캐시 적중");
    }
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L180-L194)

- **WebGL 플랫폼 로드**: `LoadImageAsync`는 `UNITY_WEBGL`에서 `UnityWebRequestTexture` 분기를 사용하며 더 이상 디스크에 쓰지 않습니다. `IsCached`는 항상 `false`를 반환하고, `RemoveCache`/`ClearCache`는 경고를 출력합니다. 비즈니스 측은 플랫폼을 구분할 필요가 없으며, API 동작은 일관됩니다.

    ```csharp
    // WebGL에서도 동일하게 호출, 내부에서 자동으로 UnityWebRequestTexture 분기를 사용함
    var tex = await _manager.LoadImageAsync(url);
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L91-L115)

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `LoadImageAsync`가 `null`을 반환하고, 로그에 `url is null or empty` 표시 | URL이 비어 있음 | 호출 전에 `string.IsNullOrEmpty`로 검증 |
| `null`을 반환하고, 로그에 `url must start with http:// or https://` 표시 | URL이 http(s)로 시작하지 않음 | 완전한 URL 사용, 로컬 경로 또는 `file://`를 전달하지 말 것 |
| WebGL이 아닌 플랫폼에서 다운로드 실패, 로그에 `download failed` 표시 | `DownloadManager`가 등록되지 않았거나 네트워크에 도달할 수 없음 | `GameFrameX`의 다운로드 매니저가 초기화되고 이벤트 콜백이 올바르게 등록되었는지 확인 |
| `CancellationToken` 취소 후 `Task`가 즉시 종료되지 않음 | 취소 로직은 WebGL이 아닌 플랫폼에서만, 그리고 캐시 읽기/파일 존재 여부 판단 이후 구간에서만 적용됨 | 취소 후에는 자체적으로 `tex == null`을 판단하고, `Task`가 예외를 던진다고 가정하지 말 것 |

## 배경(선택 사항)

- WebGL이 아닌 플랫폼: `ImageCacheManager`는 `Utility.Hash.MD5.Hash(url)`을 캐시 파일 이름으로 사용하며 확장자는 `.png`로 고정됩니다. 첫 캐시 미스 시 `IDownloadManager.AddDownload`를 통해 다운로드를 시작하고, `TaskCompletionSource`로 `DownloadSuccess` / `DownloadFailure` 이벤트를 기다립니다.
- WebGL 플랫폼: `UNITY_WEBGL` 매크로가 활성화되면 `LoadImageAsync`는 `UnityWebRequestTexture.GetTexture` + `SendWebRequest()`로 변경되며, 캐시는 전적으로 브라우저 HTTP Cache에 위임되므로 `IsCached`, `RemoveCache`, `ClearCache`는 모두 비활성화됩니다.

컴포넌트 초기화와 생명주기에 대해서는 《ImageCacheComponent 개요》를 참조하고, 캐시 구성 필드 의미에 대해서는 `ImageCacheConfig`를 참조하십시오.
