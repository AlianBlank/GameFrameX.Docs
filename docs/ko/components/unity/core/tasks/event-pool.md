# 이벤트 구독 및 발송

이벤트 풀 `EventPool<T>`를 통해 임의의 모듈이 "문자열 ID + 이벤트 매개변수" 형식으로 이벤트를 구독하고 발송할 수 있습니다. 메인 스레드에서 큐에 넣어 트리거하는 방식(`Fire`)과 즉시 동기 방식으로 트리거하는 방식(`FireNow`)을 모두 지원합니다.

## 사전 조건

- 커스텀 이벤트 매개변수는 반드시 `BaseEventArgs`를 상속하고, 이벤트를 구분하기 위한 고유한 문자열 `Id`를 구현해야 합니다.
- `EventPool` 모듈을 통해 `EventPool<T>` 인스턴스를 가져오거나 생성합니다. 이 튜토리얼에서는 이미 `EventPool<MyEventArgs>`를 가지고 있다고 가정합니다.
- 호출자는 게임 루프에서 `EventPool<T>.Update(elapseSeconds, realElapseSeconds)`를 트리거해야 합니다. 그렇지 않으면 `Fire` 큐의 이벤트가 발송되지 않습니다.

## 작업 단계

1. 이벤트 매개변수 클래스를 정의하고, `BaseEventArgs`를 상속하여 고유한 `Id`를 제공합니다.

   ```csharp
   public class PlayerHpChangedEventArgs : BaseEventArgs
   {
       public string PlayerId { get; set; }
       public int NewHp { get; set; }

       public override string Id => "PlayerHpChanged";
   }
   ```

   Source: [BaseEventArgs.cs](/Runtime/Base/EventPool/BaseEventArgs.cs#L43-L54)

2. 이벤트를 구독합니다. 모듈 초기화 시 `Subscribe`를 호출하여 문자열 이벤트 ID와 `EventHandler<T>` 콜백을 이벤트 풀에 등록합니다.

   ```csharp
   eventPool.Subscribe("PlayerHpChanged", OnPlayerHpChanged);

   void OnPlayerHpChanged(object sender, PlayerHpChangedEventArgs e)
   {
       Debug.Log($"{e.PlayerId} HP -> {e.NewHp}");
   }
   ```

   `EventHandler<T>`의 시그니처는 `EventPool<T>`의 타입 매개변수에서 비롯됩니다.

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

3. 이벤트를 발송합니다. 메인 스레드에서 `Fire`를 호출하면 이벤트가 큐에 추가되고, 다음 `Update`에서 모든 구독자에게 콜백됩니다. 스레드 간 `Fire` 호출도 안전합니다.

   ```csharp
   var args = ReferencePool.Acquire<PlayerHpChangedEventArgs>();
   args.PlayerId = "p_001";
   args.NewHp = 80;
   eventPool.Fire(this, args);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L304-L314)

4. 이벤트 풀을 구동합니다. 매 프레임 `Update`를 호출해야만 `Fire` 큐의 노드가 소비됩니다. 노드 처리가 완료되면 `ReferencePool.Release`를 통해 반환됩니다.

   ```csharp
   void Update()
   {
       eventPool.Update(0f, Time.deltaTime);
   }
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L113-L121)

5. 적절한 시점에 구독을 취소하여, 객체가 이미 파괴된 후에도 이벤트 풀이 콜백을 보유하고 있지 않도록 합니다.

   ```csharp
   eventPool.Unsubscribe("PlayerHpChanged", OnPlayerHpChanged);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L245-L281)

## 일반적인 변형

- **즉시 동기 발송**: 메인 스레드에서 큐잉이 필요 없는 경우, `FireNow`를 호출하여 현재 호출 스택에서 즉시 모든 구독자에게 이벤트를 발송할 수 있습니다. 단, 스레드 안전은 보장되지 않습니다.

  ```csharp
  eventPool.FireNow(this, args);
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L325-L336)

- **기본 핸들러 설정**: `SetDefaultHandler`를 통해 폴백 콜백을 등록할 수 있습니다. 특정 이벤트 ID에 구독자가 없을 때 호출됩니다.

  ```csharp
  eventPool.SetDefaultHandler((sender, e) => Debug.Log($"처리되지 않은 이벤트:{e.Id}"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L290-L293)

- **이벤트 풀 모드로 구독 규칙 제어**: `EventPool<T>` 생성 시 `EventPoolMode`를 전달하여 다중 또는重复 구독자 허용 여부를 결정합니다.

  | 모드 | 동작 |
  |------|------|
  | `EventPoolMode.Default` (0) | 반드시 존재해야 하며, 구독자는 하나만 허용 |
  | `EventPoolMode.AllowNoHandler` (1) | 구독자가 없는 이벤트 허용 |
  | `EventPoolMode.AllowMultiHandler` (2) | 동일한 이벤트 ID에 여러 구독자 등록 허용 |
  | `EventPoolMode.AllowDuplicateHandler` (4) | 동일한 콜백의重复 등록 허용(`AllowMultiHandler`와 함께 사용) |

  여러 플래그를 비트 단위로 조합할 수 있습니다. 예를 들어 `EventPoolMode.AllowMultiHandler | EventPoolMode.AllowDuplicateHandler`.

  Source: [EventPoolMode.cs](/Runtime/Base/EventPool/EventPoolMode.cs#L43-L77), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

- **구독 수 조회**: `EventHandlerCount` 또는 `Count(id)`를 통해 구독자 수를 읽어 디버깅 또는 UI 표시에 활용할 수 있습니다.

  ```csharp
  Debug.Log(eventPool.EventHandlerCount);
  Debug.Log(eventPool.Count("PlayerHpChanged"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L82-L91), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L164-L175)

## 일반적인 오류

| 오류 | 증상 | 처리 |
|------|------|------|
| `handler`가 `null`인 상태에서 `Subscribe`/`Unsubscribe`/`Check` 호출 | `GameFrameworkException("Event handler is invalid.")` 던짐 | 등록 전에 콜백이 인스턴스 메서드 또는 정적 delegate인지 확인, `null` 전달 금지 |
| `Fire` 이벤트에 구독자가 없고 모드에서 `AllowNoHandler`를 활성화하지 않은 경우 | "not allow multi handler." 또는 기본 핸들러 폴백 발생 | 생성자에서 필요에 따라 `EventPoolMode.AllowNoHandler` 추가 |
| `Update`를 호출하지 않아 큐를 소비하지 않는 경우 | 이벤트가 "사라진" 것처럼 보임 | 게임 루프에서 매 프레임 `eventPool.Update(...)`를 구동하도록 보장 |
| 객체 파괴 후 `Unsubscribe`를 호출하지 않은 경우 | 이벤트 트리거 시 이미 파괴된 객체에 콜백되어 null 참조 발생 | `OnDestroy`/`OnDisable`에서 `Unsubscribe` 호출 |

## 배경 (선택)

`EventPool<T>`는 내부적으로 `ConcurrentQueue<EventNode>`를 사용하여 `Fire`로 들어온 이벤트를 임시 저장하고, `Update`에서 이를 꺼내 `GameFrameworkMultiDictionary<string, EventHandler<T>>`를 통해 발송합니다. `_cachedNodes`는 "이벤트 처리 과정 중 안전하게 구독 취소"를 지원하기 위해 사용됩니다. `Fire`는 스레드 안전하며(다음 프레임의 메인 스레드에서 발송), `FireNow`는 즉시 동기 발송하므로 지연에 민감하지만 호출 스레드 안전을 보장할 수 있는 시나리오에 적합합니다.
