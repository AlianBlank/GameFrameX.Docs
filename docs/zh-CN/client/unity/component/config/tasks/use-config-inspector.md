# 如何在 Unity Inspector 中查看与管理 ConfigComponent

在挂载了 `ConfigComponent` 的 GameObject 上,Unity Inspector 会自动用自定义 Inspector 展示该组件的接口与实现类型映射,你可以在不写代码的情况下查看当前配置组件对应的 `IConfigManager` 接口以及实现类全名,并在需要时手动指定自定义实现。

## 前置条件

- 已安装 `com.gameframex.unity.config` 包,项目中存在 `ConfigComponent` 类。
- 场景中存在一个 GameObject,挂载了 `ConfigComponent`(组件菜单位于 `GameFrameX/Config`)。

## 操作步骤

1. 在场景中选中挂载 `ConfigComponent` 的 GameObject,Inspector 会自动切换为自定义 Inspector。自定义 Inspector 通过 `CustomEditor(typeof(ConfigComponent))` 特性绑定。

    ```csharp
    [CustomEditor(typeof(ConfigComponent))]
    internal sealed class ConfigComponentInspector : ComponentTypeComponentInspector
    {
        protected override void RefreshTypeNames()
        {
            RefreshComponentTypeNames(typeof(IConfigManager));
        }
    }
    ```

    Source: [Editor/Inspector/ConfigComponentInspector.cs#L38-L45](/src/Editor/Inspector/ConfigComponentInspector.cs#L38-L45)

2. Inspector 顶部会展示组件类型相关的只读字段,包括 `InterfaceComponentType`(固定为 `IConfigManager`)与 `ImplementationComponentType`(由 `Awake()` 时按 `componentType` 字符串解析得到)。这是判断运行时配置管理器实现是否正确的最快方式。

    ```csharp
    protected override void Awake()
    {
        m_ConfigNameTypeMap.Clear();
        ImplementationComponentType = Utility.Assembly.GetType(componentType);
        InterfaceComponentType = typeof(IConfigManager);
        base.Awake();
        m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
        if (m_ConfigManager == null)
        {
            Log.Fatal("Config manager is invalid.");
            return;
        }
    }
    ```

    Source: [Runtime/Config/ConfigComponent.cs#L73-L85](/src/Runtime/Config/ConfigComponent.cs#L73-L85)

3. 若运行时出现 `Config manager is invalid.` 致命日志,说明 `IConfigManager` 模块未注册,先回到 Game Framework 的模块注册流程修复。

4. 在运行时(Play Mode)读取 `Count` 属性可校验当前已加载的配置项数量:

    ```csharp
    var configComponent = GameEntry.GetComponent<ConfigComponent>();
    int count = configComponent.Count;
    ```

    Source: [Runtime/Config/ConfigComponent.cs#L62-L65](/src/Runtime/Config/ConfigComponent.cs#L62-L65)

5. 在脚本中按类型获取、检测、移除、清空配置项(这些 API 也间接用于运行时调试):

    ```csharp
    // 获取配置项(类型必须实现 IDataTable)
    var cfg = configComponent.GetConfig<MyConfig>();

    // 检测是否存在
    bool exists = configComponent.HasConfig<MyConfig>();

    // 移除单项 / 清空全部
    configComponent.RemoveConfig<MyConfig>();
    configComponent.RemoveAllConfigs();

    // 直接以名称添加
    configComponent.Add("MyConfig", dataTableInstance);
    ```

    Source: [Runtime/Config/ConfigComponent.cs#L117-L185](/src/Runtime/Config/ConfigComponent.cs#L117-L185)

## 常见变体

- 想自定义实现类时,在 `componentType` 字段填入完整的 `IConfigManager` 实现类全名(包括命名空间),`Awake()` 会通过 `Utility.Assembly.GetType` 解析;解析结果会显示在 Inspector 的 `ImplementationComponentType` 中,便于核对。
- 想排查裁剪问题,可在构建脚本中确认 `GameFrameXConfigCroppingHelper` 触发了对 `ConfigComponent` 与 `BaseDataTable<>` 的引用保留(由 `[Preserve]` 特性与裁剪助手共同保证)。

    ```csharp
    _ = typeof(BaseDataTable<>);
    _ = typeof(ConfigComponent);
    ```

    Source: [Runtime/GameFrameXConfigCroppingHelper.cs#L20-L22](/src/Runtime/GameFrameXConfigCroppingHelper.cs#L20-L22)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| Console 打印 `Config manager is invalid.` | `IConfigManager` 模块未注册或被裁剪 | 确认实现类存在并被框架自动注册;必要时显式引用 `GameFrameX.Runtime` 以防被裁剪 |
| Inspector `ImplementationComponentType` 显示空 | `componentType` 字符串拼写错误或程序集未加载 | 检查 `componentType` 是否与实现类全限定名完全一致 |
| `GetConfig<T>` 返回 `default` | 对应名称的配置项未通过 `Add` 注册 | 先调用 `configComponent.LoadConfig("...")` 或 `Add(...)` 再读取 |

## 背景(可选)

`ConfigComponent` 是继承自 `GameFrameworkComponent` 的 MonoBehaviour,框架通过 `[GameFrameXAutoComponent(-5000)]` 自动注册,优先级为 -5000。Inspector 派生自 `ComponentTypeComponentInspector`,核心职责是在编辑器中把接口与实现类的全限定名可视化,方便不运行游戏也能确认模块装配情况。
