# 로그에 "fun is invalid." 가 표시되거나 ArgumentNullException 이 발생하면 어떻게 해야 하나요

`MonoComponent` 의 `AddXxxListener` / `RemoveXxxListener` 시리즈 메서드를 호출할 때 로그에서 `fun is invalid.` 문구를 확인했거나, 테스트 코드에서 `ArgumentNullException` 을 포착했다면, 이는 모두 **`null` 콜백이 전달되었음**을 의미합니다. 이 페이지에서는 빠르게 원인을 파악하고 수정하는 방법을 안내합니다.

## 빠른 진단

| 증상 | 원인 | 수정 방법 |
|------|------|------|
| 실행 로그에 `fun is invalid.` 가 나타남 | `AddXxxListener` / `RemoveXxxListener` 에 전달된 `Action` 이 `null` 이라 내부에서 `Log.Fatal` 후 바로 `return` 하며 리스너가 동작하지 않음 | 콜백 변수에 실제 메서드나 `lambda` 를 할당하고, `?.` 로 null 체크 후 전달 |
| 단위 테스트에서 `ArgumentNullException` 이 발생함 | 동일한 인터페이스의 내부 `_monoManager` 가 `null` 에 대해 예외를 던지며 "null 전달 시 반드시 실패함" 을 검증함 | 위와 동일한 원인으로, `null` 이 아닌 콜백을 전달하도록 수정 |
| 시작 시 `Mono manager is invalid.` 가 보고됨 | `MonoComponent.Awake` 에서 `_monoManager == null` 이며, 프레임워크 모듈이 등록되지 않음 | 아래 "수정 단계 2" 참조 |
| 시작 시 `Event manager is invalid.` 가 보고됨 | `MonoComponent.Start` 에서 `m_EventComponent == null` 이며, 이벤트 컴포넌트가 부착되지 않음 | 아래 "수정 단계 2" 참조 |

## 수정 단계

### 1. 콜백이 `null` 일 때는 먼저 null 체크 후 전달

`MonoComponent` 는 모든 `Add*Listener` / `Remove*Listener` 에 대해 `if (fun == null)` 검증을 수행하며, 트리거 시 `Fatal` 로그만 기록하고 구독/구독 해제 동작은 전혀 수행하지 않으며 자동으로 예외를 던지지 않습니다 — 하지만 동작은 발생하지 않습니다.

Source: [MonoComponent.cs#L147-L171](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L147-L171)

```csharp
public void AddLateUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddLateUpdateListener(fun);
}
```

수정 방법: 전달하기 전에 먼저 null 체크를 하거나, null 병합 연산자를 사용해 기본 빈 구현을 제공하세요. 예:

```csharp
Action<float, float> onLate = null;
if (onLate != null)
{
    GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener(onLate);
}

// 또는 lambda 자리 표시자 사용
GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener((dt, fdt) => { /* 로직 */ });
```

### 2. 시작 단계에서 "Mono manager is invalid." 또는 "Event manager is invalid." 가 보고됨

이 두 로그 메시지는 `MonoComponent` 자체의 초기화 단계에서 발생하며, 콜백이 `null` 이어서 생기는 것이 아니라 프레임워크 모듈/컴포넌트가 준비되지 않아서 발생합니다.

```csharp
protected override void Awake()
{
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}

private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs#L52-L76](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76)

수정 방법:

1. 씬에 `IMonoManager` 를 구현한 모듈 엔트리 컴포넌트가 부착되어 있는지, 또는 해당 어셈블리가 Player Settings 의 `Scripting Define Symbols` / 어셈블리 정의에 포함되어 있는지 확인하세요.
2. GameFramework 의 `GameEntry` 프리팹에 `EventComponent` 를 부착하고, 그 실행 순서가 `MonoComponent` 보다 빠른지 확인하세요.

### 3. 관련된 모든 리스너 메서드

다음 메서드들은 `MonoComponent.cs` 에서 모두 "`null` 전달 → `fun is invalid.` 로그 → return" 의 동일한 패턴을 따르므로, 문제를排查할 때 함께 확인하세요:

## 검증

수정 후 아래 방법으로 문제가 해결되었는지 확인하세요:

1. **런타임**: 게임을 다시 실행한 뒤 로그에 `fun is invalid.`, `Mono manager is invalid.`, `Event manager is invalid.` 가 더 이상 나타나지 않는지 관찰하세요.
2. **콜백 트리거**: 콜백 본문 안에 `Debug.Log` 를 한 줄 추가하고, 해당 생명주기(예: `Update`, `LateUpdate`)에 진입했을 때 로그가 보이면 구독이 성공한 것입니다.
3. **단위 테스트**: 저장소의 `Tests/UnitTests.cs` 에 있는 `Assert.Throws<ArgumentNullException>(() => _manager.AddUpdateListener(null))` 등의 테스트는 **null 전달 시 반드시 실패한다**는 계약을 검증하기 위한 것입니다. 비즈니스 코드에서는 실제 델리게이트를 전달해야 합니다.
