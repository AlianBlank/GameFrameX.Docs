# HttpClientRequestException이 발생하고 응답 예외가 발생하면 어떻게 해야 하나요

`GameFrameX.Foundation.Http.Extension`을 통해 시작된 HTTP 요청이 성공하지 않는 상태 코드, 네트워크 계층 예외 또는 JSON 역직렬화 실패를 수신하면, 프레임워크는 `HttpClientRequestException`을 발생시킵니다. 이 페이지에서는 이를 식별하고, 원인을 파악하고, 올바른 수정 방법을 선택하는 방법을 설명합니다.

## 빠른 진단

예외 유형 자체는 `HttpRequestException`에서 상속되며 다음과 같은 추가 진단 필드를 제공합니다:

| 필드 | 유형 | 설명 |
|---|---|---|
| `StatusCode` | `HttpStatusCode?` | 서버에서 반환한 HTTP 상태 코드(응답이 있는 경우) |
| `RequestUri` | `Uri?` | 오류가 발생한 요청 URI |
| `ResponseSummary` | `string?` | 응답 본문의 제한된 요약(실패 시 채워짐) |
| `RawException` | `Exception?` | 이 예외를 트리거한 원본 예외(있는 경우) |

```csharp
public sealed class HttpClientRequestException : HttpRequestException
{
    public HttpClientRequestException(
        string message,
        HttpStatusCode? statusCode,
        Uri? requestUri,
        string? responseSummary,
        Exception? rawException = null)
        : base(message, rawException, statusCode)
    {
        StatusCode = statusCode;
        RequestUri = requestUri;
        ResponseSummary = responseSummary;
        RawException = rawException;
    }

    public new HttpStatusCode? StatusCode { get; }
    public Uri? RequestUri { get; }
    public string? ResponseSummary { get; }
    public Exception? RawException { get; }
}
```

## 수정 단계

### 수정 단계: 상태 코드 실패

1. 호출자에서 `try / catch`를 사용하여 `HttpClientRequestException`을 포착하고, `StatusCode`를 통해 구체적인 실패 유형(401, 404, 500 등)을 판단합니다.

```csharp
try
{
    var response = await httpClient.SendJsonAsync<MyDto>(request, options);
    response.EnsureSuccessStatusCode();
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    // 리소스가 존재하지 않으므로 비즈니스 폴백 분기로 이동
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.Unauthorized)
{
    // 토큰 새로 고침 또는 다시 로그인하라는 메시지 표시
}
```

2. 요청이 본래 내결함성이 있어야 하는 경우(예: GET 목록이 404를 반환하여 빈 결과를 허용하는 경우) `EnsureSuccessStatusCode()`를 호출하지 말고, 직접 `IsSuccessStatusCode`와 `Body`를 읽어 직접 처리합니다.

```csharp
public HttpClientResponse EnsureSuccessStatusCode()
{
    if (IsSuccessStatusCode)
    {
        return this;
    }

    throw new HttpClientRequestException(
        $"HTTP request failed with status code {(int)StatusCode} ({StatusCode}) for {RequestUri}.",
        StatusCode,
        RequestUri,
        Body);
}
```

Source: [HttpClientResponse.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientResponse.cs#L80-L92)

3. 재시도 설정을 확인합니다. 프레임워크는 기본적으로 `HttpRequestException`에 대해 제한된 횟수만큼 재시도하며, `attempt <= options.Retry.MaxRetries`인 경우 `HttpClientRequestException`을 발생시키지 않고 백오프 재시도를 트리거합니다.

```csharp
catch (HttpRequestException exception) when (allowRetry && attempt <= options.Retry.MaxRetries)
{
    await DelayBeforeRetryAsync(method, request.RequestUri, attempt, null, exception, options, effectiveToken);
    return (null, true);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L358-L362)

상태 코드 실패가 발생했지만 재시도 횟수가 소진된 경우, `CreateStatusException`에서 상태 정보가 포함된 예외가 발생합니다:

### 수정 단계: 네트워크 계층 / 일반 예외

1. 네트워크 계층(DNS, TCP, TLS, 시간 초과)은 일반적으로 하위 계층 `HttpRequestException`으로 나타�니다. 재시도 횟수가 소진되거나 `HttpRequestException / JsonException`이 아닌 `Exception`이 나타나면 다음과 같이 래핑됩니다:

```csharp
catch (Exception exception) when (exception is HttpRequestException or JsonException)
{
    throw new HttpClientRequestException(
        $"HTTP request failed for {method} {request.RequestUri}.",
        null,
        request.RequestUri,
        null,
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L363-L371)

2. 문제 해결 아이디어:
   - 먼저 `ex.RawException?.Message`를 읽으십시오. 여기에는 일반적으로 실제 근본 원인이 포함됩니다(예: `The requested name is valid, but no data of the requested type was found`).
   - 시간 초과인 경우, `HttpClientRequestOptions`의 시간 초과 임계값을 늘리거나 `Retry.MaxRetries / Retry.Delay`를 조정하여 재시도를 더 충분히 수행합니다.
   - TLS / 인증서 오류인 경우, 대상 주소의 인증서 체인과 서버 측 SNI 구성을 확인합니다.
   - 사용자 지정 `HttpMessageHandler` 체인에서 다른 예외가 발생한 경우, 프레임워크는 `is HttpRequestException or JsonException`일 때만 래핑합니다. 나머지 예외는 원래대로 전파되므로 별도로 포착해야 합니다.

### 수정 단계: JSON 역직렬화 실패

1. 응답 본문이 유효한 JSON이 아니거나 필드 유형이 대상 유형과 일치하지 않는 경우 다음 예외가 발생합니다:

```csharp
catch (JsonException exception)
{
    throw new HttpClientRequestException(
        $"HTTP JSON response could not be deserialized for {requestUri}.",
        null,
        requestUri,
        Summarize(responseText),
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L430-L438)

2. 문제 해결 아이디어:
   - `ex.RawException`을 통해 원본 `JsonException`을 가져와 실패한 필드의 구체적인 경로와 줄 번호를 찾습니다.
   - `ex.ResponseSummary`를 확인하여 응답 본문 요약을 검토하고 서버에서 반환한 형식(`application/json` vs `text/html`)을 확인합니다.
   - 필요한 경우 `HttpClientRequestOptions.JsonSerializerOptions`에서 `PropertyNameCaseInsensitive`, `NumberHandling`, `AllowTrailingCommas` 등을 구성하여 역직렬화를 더 관대하게 만듭니다.

## 검증

1. 실패할 요청을 의도적으로 구성하여(존재하지 않는 주소를 가리키거나 500을 반환하는 엔드포인트) `HttpClientRequestException`이 포착되고 `StatusCode` / `RequestUri` / `ResponseSummary` 세 필드의 값이 예상과 일치하는지 확인합니다.
2. 역직렬화 실패 시나리오에서 `RawException`을 `JsonException`으로 변환하여 해당 `Path`가 실패한 필드를 가리키는지 확인합니다.
3. `Retry.MaxRetries > 0`이 활성화된 구성에서 대상 인터페이스가 일시적으로 5xx를 반환하도록 하여 로그에 백오프 재시도 기록이 나타나고 최종적으로 비즈니스 예상대로 `HttpClientRequestException`이 발생하는지 확인합니다.
