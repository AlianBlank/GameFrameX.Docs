# 添加与移除系统框架和库

在构建后处理配置文件(XcodePostProcessConfig.json)中配置 `frameworks` 与 `libs` 节点,即可在 Xcode 工程生成时自动添加或移除系统框架(`.framework`)与系统库(`.tbd`),无需手动打开 Xcode 修改。

## 前置条件

- Unity 项目已安装 com.gameframex.unity.xcode 包。
- 平台切换到 iOS(`#if UNITY_IOS` 下代码才会执行)。
- 已在 Unity 工程中放置构建后处理配置文件(与 `capabilities`、`unityFramework`、`unityMain` 等节点同级)。

## 操作步骤

1. 打开构建后处理配置文件,定位到 `unityFramework` 或 `unityMain` 节点(两者结构相同,分别对应 Xcode 工程中的 UnityFramework 与 Unity-iPhone target)。
2. 在其中填入 `libs` 与 `frameworks` 配置,`"+"` 数组为要添加的项,`"-"` 数组为要移除的项:

```json
{
  "unityFramework": {
    "libs": { "+": ["libz.tbd"], "-": [] },
    "frameworks": {
      "+": ["WebKit.framework", "UserNotifications.framework"],
      "-": []
    }
  }
}
```

3. 执行 Unity 的 iOS 构建。构建结束后处理逻辑会读取上述配置并写入生成的 Xcode 工程。
4. 打开生成的 `.xcodeproj`,在 target 的 **General → Frameworks and Libraries**(或 Build Phases → Link Binary With Libraries)中确认结果。

## 常见变体

| 需求 | 配置方式 |
|------|----------|
| 只给 UnityFramework target 链接 `libz.tbd` | 在 `unityFramework.libs."+"` 中加入 `libz.tbd` |
| 给主 App target 添加系统框架 | 在 `unityMain.frameworks."+"` 中加入如 `WebKit.framework` |
| 移除 Unity 默认链接的框架 | 在对应节点 `"-"` 数组中写框架名,例如 `["UnityFramework.framework"]` |

## 实现入口

框架与库的写入由 `PostProcessBuildHelper` 的两个分部文件完成:

`frameworks` 节点走 `SetFrameworks`,内部直接调用 Unity `PBXProject` API:

```csharp
private static void SetFrameworks(PBXProject proj, string targetGuid, Hashtable hashtable)
{
    if (hashtable != null)
    {
        if (hashtable["+"] is ArrayList addList)
        {
            foreach (string framework in addList)
            {
                proj.AddFrameworkToProject(targetGuid, framework, false);
            }
        }

        if (hashtable["-"] is ArrayList removeList)
        {
            foreach (string framework in removeList)
            {
                proj.RemoveFrameworkFromProject(targetGuid, framework);
            }
        }
    }
}
```

Source: [PostProcessBuildHelper.Frameworks.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Frameworks.cs#L15-L35)

`libs` 节点走 `SetLibs`,以 SDK 相对路径 `usr/lib/` 挂载到 `Frameworks/` 分组再链接:

```csharp
private static void AddLibToProject(PBXProject proj, string targetGuid, string lib)
{
    string fileGuid = proj.AddFile("usr/lib/" + lib, "Frameworks/" + lib, PBXSourceTree.Sdk);
    proj.AddFileToBuild(targetGuid, fileGuid);
}

private static void RemoveLibFromProject(PBXProject proj, string targetGuid, string lib)
{
    string fileGuid = proj.AddFile("usr/lib/" + lib, "Frameworks/" + lib, PBXSourceTree.Sdk);
    proj.RemoveFileFromBuild(targetGuid, fileGuid);
}
```

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 配置后 Xcode 工程中没有变化 | 配置写错了层级,`libs`/`frameworks` 必须位于 `unityFramework` 或 `unityMain` 内 | 将节点移动到对应 target 配置下 |
| `.tbd` 库未链接,报 `Undefined symbols` | 库名写法不完整 | 系统库需带 `.tbd` 后缀,如 `libz.tbd` |
| 框架重复链接警告 | 同一框架同时在 `"+"` 中出现多次,或已被其他插件添加 | 从 `"+"` 数组去重,必要时把重复项写入 `"-"` |
| 添加后仍未生效 | 修改的是其他平台下的配置或未重新执行构建 | 确认 iOS 平台并重新 Build |

## 验证

- 打开生成的 Xcode 工程,选中对应 target,在 **Build Phases → Link Binary With Libraries** 中能看到 `"+"` 列出的框架与库。
- `libz.tbd` 等系统库出现在工程的 `Frameworks` 分组下,路径为 `usr/lib/`。
- 编译工程无 `Undefined symbols` 链接错误。
