# 커스텀 결제 채널 구현

`BasePaymentManager`를 상속하고 모든 추상 멤버를 구현한 뒤, 구현 클래스의 전체 타입 이름을 `PaymentComponent`의 해당 플랫폼 직렬화 필드에 입력하면, 게임 시작 시 컴포넌트가 자동으로 리플렉션을 통해 로드하여 해당 채널 구현으로 전환하므로 비즈니스 레이어의 호출 코드는 변경할 필요가 없습니다.

## 사전 조건

- `com.gameframex.unity.payment` 패키지가 설치되어 있고, 씬에 `GameFrameX/Payment` 컴포넌트(`PaymentComponent`, 이 컴포넌트는 `RequireComponent`를 통해 `GameFrameXPaymentCroppingHelper`를 강제로 포함함)가 추가되어 있어야 합니다.
- 구현 클래스가 속한 어셈블리가 Unity 컴파일에 포함되어야 합니다(즉, `Utility.Assembly.GetType`로 해석 가능해야 합니다).

## 작업 단계

### 1. 채널 매니저 클래스 생성

새 클래스를 생성하여 `GameFrameX.Payment.Runtime.BasePaymentManager`를 상속합니다(이 클래스는 `GameFrameworkModule`과 `IPaymentManager`의 이벤트 정의를 이미 구현했으며, 이벤트 발생용 메서드를 미리 마련해 두었습니다):

```csharp
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;
    // ...
}
```

출처: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L14-L34)

하위 클래스는 `public class MyPaymentManager : BasePaymentManager`와 같은 형태입니다(클래스 이름과 네임스페이스는 자유롭게 정하며, 이후 단계에서 전체 타입 이름이 사용됩니다).

`override`가 필요한 추상 멤버(모두 실제 소스 코드 시그니처 기준):

| 멤버 | 실제 시그니처 | 설명 |
|------|----------|------|
| `Init` | `void Init(bool isDebug = false, bool isClientVerify = false)` | 채널 SDK 초기화; `isDebug`는 샌드박스 모드, `isClientVerify`는 클라이언트 측 구매 검증 여부 |
| `IsReady` | `bool IsReady()` | 채널 준비 여부 |
| `SetPredefinedProductIds` | `void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds)` | 사전 정의된 상품 ID 사전 로드, 반드시 `Init` 이전에 호출해야 함 |
| `QueryPurchases` | `void QueryPurchases(PaymentProductType productType)` | 구매 기록 조회, 결과는 `OnQueryPurchasesResult` 콜백으로 전달 |
| `ConsumePurchase` | `void ConsumePurchase(string purchaseToken)` | 구매 소진, 결과는 `OnConsumePurchaseResult` 콜백으로 전달 |
| `BuyInApp` | `void BuyInApp(string productId, string orderId, string offerToken = "", string customData = "")` | 구버전 인터페이스, `[Obsolete]`로 표시됨, 여전히 override 필요 |
| `BuySubs` | `void BuySubs(string productId, string orderId, string offerToken = "", string customData = "")` | 구버전 인터페이스, `[Obsolete]`로 표시됨, 여전히 override 필요 |
| `Buy` | `void Buy(string productId, PaymentProductType productType, string orderId, string offerToken = "", string customData = "")` | 구버전 인터페이스, `[Obsolete]`로 표시됨, 여전히 override 필요 |
| `Buy` | `void Buy(PurchaseParams purchaseParams)` | 권장 진입점, 구매 매개변수로 채널 하위 클래스를 전달 가능 |

출처: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L42-L112)

### 2. 구현에서 이벤트 발생

채널 SDK 콜백 이후, 기본 클래스가 제공하는 protected 메서드를 호출하여 비즈니스 레이어에 알리세요. 이벤트 필드에 직접 접근하지 마세요:

```csharp
protected void RaisePurchaseSuccess(PaymentEventArgs e)
{
    OnPurchaseSuccess?.Invoke(this, e);
}

protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}

protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
{
    OnQueryPurchasesResult?.Invoke(this, e);
}

protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
{
    OnConsumePurchaseResult?.Invoke(this, e);
}
```

출처: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L41-L59)

### 3. (선택 사항) 채널 전용 구매 매개변수 확장

`Buy(PurchaseParams)`의 매개변수는 추상 기본 클래스이며, 공식 주석에 "각 채널은 상속하여 자체 필드를 확장할 수 있다"고 명시되어 있습니다:

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

출처: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

채널용 하위 클래스를 파생하여 채널 고유 매개변수(예: 채널 측 token, 채널 사용자 ID)를 속성으로 추가하고, `MyPaymentManager.Buy(PurchaseParams)`에서 다운캐스팅하여 읽어옵니다.

### 4. 구현 클래스를 PaymentComponent에 연결

`PaymentComponent`는 플랫폼별 직렬화 필드로 어떤 구현 클래스를 로드할지 결정하며, Inspector에서 해당 플랫폼 필드를 자신만의 전체 타입 이름으로 교체하면 됩니다. 프레임워크 기본값은 다음과 같습니다:

```csharp
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L24-L28)

플랫폼 매핑 규칙(`PaymentComponent.Awake`의 조건부 컴파일 기준):

| 컴파일 매크로 | 사용되는 필드 | 기본 구현 |
|--------|-----------|----------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `WebGLPaymentManager` |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `m_componentPCType` | `PCPaymentManager` |
| `UNITY_STANDALONE_OSX` | `m_componentMacType` | `ApplePaymentManager` |
| 기타 플랫폼 | — | `DefaultPaymentManager` |

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

로드 흐름: 컴포넌트는 `Awake`에서 `Utility.Assembly.GetType(componentType)`를 호출하여 타입을 해석한 뒤, `GameFrameworkEntry.GetModule<IPaymentManager>()`로 인스턴스를 가져옵니다. 해석에 실패하거나 모듈이 유효하지 않으면 `Log.Fatal("Pay Manager is invalid.")`가 실행됩니다.

### 5. 연결 검증

비즈니스 레이어에서 평소처럼 호출하면 되며, 구체적인 채널을 인식할 필요가 없습니다:

```csharp
// 이벤트 구독(PaymentComponent가 이미 이벤트를 내부 매니저로 전달함)
paymentComponent.OnPurchaseSuccess += (sender, e) => { /* 아이템 지급 */ };
paymentComponent.Init(isDebug: true, isClientVerify: false);
paymentComponent.Buy(myChannelPurchaseParams);
```

`PaymentComponent.Init`의 시그니처는 `public void Init(bool isDebug = false, bool isClientVerify = true)`이며, 내부적으로 `IPaymentManager.Init`로 바로 전달됩니다.

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

## 일반적인 변형

- **특정 플랫폼만 교체**: 해당 플랫폼 필드만 수정하고 나머지 플랫폼은 공식 채널 패키지를 유지하여 플랫폼 간 혼용을 구현합니다.
- **테스트 스텁 채널**: 모든 플랫폼 필드에 동일한 빈/모의 `BasePaymentManager` 하위 클래스를 입력하면 Editor 또는 지원되지 않는 플랫폼에서 사용할 수 있습니다(그렇지 않으면 목록에 없는 플랫폼은 `DefaultPaymentManager`로 폴백됩니다).
- **채널에 추가 구매 매개변수가 필요한 경우**: 채널용 `PurchaseParams` 하위 클래스를 구현하고, 비즈니스 레이어는 해당 하위 클래스의 생성 매개변수에만 의존합니다.

## 일반적인 오류

| 증상/현상 | 원인 | 해결 |
|-----------|------|------|
| 시작 시 곧바로 `Log.Fatal("Pay Manager is invalid.")` 발생 | 타입 이름 오기, 네임스페이스 불일치 또는 클래스가 어셈블리에 컴파일되지 않아 `Utility.Assembly.GetType` 해석 실패 | Inspector에 입력한 값이 "네임스페이스.클래스이름" 전체 형식인지, 그리고 스크립트에 컴파일 오류가 없는지 확인 |
| `Buy`가 아무 반응이 없고 오류도 없음 | `PaymentComponent`가 빈 매개변수에 대해 사전 검증을 수행함(예: `"Product ID is null or empty."`, `"Order ID is null or empty."`, `"Purchase token is null or empty."`) | `ProductId`/`OrderId`/`purchaseToken`이 비어 있지 않은지 확인; [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L230)의 검증 로직과 대조 |
| `SetPredefinedProductIds`가 적용되지 않음 | 인터페이스 주석에 "이 메서드는 반드시 Initialize() 이전에 호출해야 한다"고 명시되어 있음 | `Init` 호출 전에 사전 정의된 상품 ID를 먼저 설정 |
| 컴파일 시 `Obsolete` 경고 발생 | `BuyInApp`/`BuySubs`/구버전 `Buy` 오버로드 사용, 모두 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`로 표시되어 있음 | 대신 `PurchaseParams` 하위 클래스를 생성하여 `Buy(PurchaseParams)`를 호출하도록 변경 |
| 이벤트가 전혀 트리거되지 않음 | 채널 구현에서 이벤트에 직접 값을 할당했거나 기본 클래스의 `Raise*` 메서드를 호출하지 않음 | `RaisePurchaseSuccess` 등의 protected 메서드를 통해 일관되게 이벤트를 발생시킴 |

## 배경

프레임워크는 "컴포넌트 + 리플렉션" 방식으로 채널을 분리합니다: `PaymentComponent`는 `IPaymentManager` 인터페이스에만 의존하며, 런타임에 플랫폼 매크로에 따라 구현 클래스 이름 문자열을 선택하고 `Utility.Assembly.GetType`로 리플렉션하여 인스턴스화합니다. 비즈니스 코드는 구체적인 채널과 완전히 분리되어 있습니다(공식 `GameFrameX.Payment.Google` 등 채널 패키지도 마찬가지입니다). 결제 모듈의 전체 구조에 대해서는 《결제 모듈 소개》를 참고하세요.
