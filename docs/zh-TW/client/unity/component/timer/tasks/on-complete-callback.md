# 在計時器完成或移除時執行回呼

在 `Add(...)` 呼叫時傳入最後一個選擇性參數 `onComplete`（`System.Action`），計時器就會在**完成（重複次數耗盡）或被移除**時自動呼叫它。簽章如下：

```csharp
int Add(float interval, int repeat, Action<object> callback, object callbackParam = null,
        string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled,
        Action onComplete = null);
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L14-L22)

## 前置條件

- 場景中已建立並初始化 `TimerComponent`（它內部持有 `ITimerManager` 並轉發 `Add`）。
Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

## 操作步驟

1. 準備一個普通的計時回呼（`Action<object>`），它負責每次觸發時的工作。
2. 在 `Add` 呼叫中使用具名參數 `onComplete:` 傳入完成回呼（建議使用具名參數，因為它位於一串選擇性參數之後）。
3. 等待重複次數耗盡或手動移除，`onComplete` 會被自動呼叫一次。

```csharp
bool completed = false;

// 每 1 秒觸發一次，共 3 次；第 3 次結束後 completed 變為 true
int id = timerComponent.Add(1f, 3, _ => { Debug.Log("tick"); },
                            onComplete: () => completed = true);
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L660-L664)

手動移除同樣會觸發回呼——例如透過回呼函式移除：

```csharp
var callback = new Action<object>(_ => { });
_timerManager.Add(1f, 0, callback, onComplete: () => completed = true);
_timerManager.Remove(callback);   // 移除後 completed == true
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L677-L684)

## 常見變體

- **與標籤分組結合**：`onComplete` 是 `Add` 的參數之一，可與 `tag`、`timeScale` 一起使用，不影響按標籤的 `PauseByTag` / `ResumeByTag` / `RemoveByTag` 操作。
  Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L93-L118)
- **重複使用同一回呼重新新增**：對已存在的 `callback` 再次 `Add` 時會原位更新（`t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete)` 並重設計時），新傳入的 `onComplete` 會覆蓋舊的。
  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L243)

## 常見錯誤

- **期望無限重複的計時器觸發回呼**：`repeat = 0` 表示無限重複，計時器永遠不會「完成」，`onComplete` 不會觸發；需要結束時機就明確設定有限次數或呼叫 `Remove`。
  Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L688-L699)
- **回呼為 null 導致計時器未建立**：`callback == null` 時僅輸出警告 `Timer callback error` 前的日誌 `"timer callback is null, " + interval + "," + repeat` 並回傳 0，`onComplete` 自然也不會有觸發機會；主回呼 `callback` 必須非空（`onComplete` 本身可以為 null）。
  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L221-L225)
- **參數順序寫錯**：`onComplete` 是第 7 個參數，位置傳參容易錯位；建議始終使用具名參數 `onComplete: () => ...`。
  Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L22)

## 背景

`onComplete` 儲存在內部 `TimerItem` 的 `OnComplete` 欄位上（`public Action OnComplete;`），排程執行緒在把計時器標記為刪除並真正移出字典時呼叫 `i.OnComplete?.Invoke()`；標籤批次移除路徑同樣在移出標籤索引後呼叫 `t.OnComplete?.Invoke()`，因此自然完成與被移除都會走這一個出口。

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L134-L148)（自然完成路徑）
