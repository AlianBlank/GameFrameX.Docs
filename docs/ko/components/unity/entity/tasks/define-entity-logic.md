# 엔티티 비즈니스 로직(EntityLogic) 정의 방법

`EntityLogic` 기본 클래스를 상속하고 라이프사이클 메서드를 재정의함으로써 Unity `MonoBehaviour`를 GameFrameX의 엔티티 관리 시스템에 연결하여 표시/숨김/업데이트/부모-자식 연결 등의 콜백을 자동으로 받을 수 있습니다.

## 사전 조건

- `com.gameframex.unity.entity` 패키지가 설치되어 있어야 합니다(《빠른 시작》 참조).
- 프리팹(Prefab)에 `Entity` 컴포넌트가 있어야 하며, `EntityLogic` 서브클래스 스크립트는 동일한 GameObject에 부착되어야 합니다.

## 작업 단계

1. **스크립트를 생성하고 `EntityLogic`을 상속합니다**. 파일 이름은 클래스 이름과 동일해야 하며, `Assets/Scripts/` 하단의任意 위치에 배치합니다.

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
   }
   ```

   출처: [Runtime/Entity/EntityLogic.cs#L35-L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L35-L40)

2. **라이프사이클 메서드를 재정의합니다**. `EntityLogic`은 7개의 `protected internal virtual` 콜백을 제공하며, 필요에 따라 재정의하면 됩니다. 기본 클래스 동작을 유지하기 위해 `base` 메서드를 호출하는 것을 잊지 마세요.

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
       protected internal override void OnInit(object userData)
       {
           base.OnInit(userData);
           // 컴포넌트 참조 등을 초기화합니다
       }

       protected internal override void OnShow(object userData)
       {
           base.OnShow(userData);
           // 엔티티가 표시될 때 호출됩니다
       }

       protected internal override void OnHide(bool isShutdown, object userData)
       {
           base.OnHide(isShutdown, userData);
           // 엔티티가 숨겨질 때 호출됩니다
       }

       protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
       {
           base.OnUpdate(elapseSeconds, realElapseSeconds);
           // 매 프레임 업데이트 로직
       }
   }
   ```

   출처: [Runtime/Entity/EntityLogic.cs#L110-L198](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L110-L198)

3. **프리팹에 스크립트를 부착합니다**. Unity 에디터에서 프리�을 열고 `PlayerEntity` 컴포넌트를 `Entity` 컴포넌트와 동일한 GameObject에 드래그합니다(혹은 임의의 자식 오브젝트에 부착하면 `GetComponentInChildren`을 통해 `Entity`가 찾을 수도 있습니다).

4. **`EntityComponent`를 통해 엔티티를 표시합니다**. `EntityLogic`은 프레임워크가 엔티티를 표시할 때 자동으로 인스턴스화하므로, 비즈니스 측은 `ShowEntityAsync<T>`를 호출하기만 하면 됩니다.

   ```csharp
   var entityComponent = GameEntry.GetComponent<EntityComponent>();

   IEntity entity = await entityComponent.ShowEntityAsync<PlayerEntity>(
       entityId: 1,
       entityAssetName: "Assets/Prefabs/Player.prefab",
       entityGroupName: "PlayerGroup"
   );
   ```

   출처: [README.zh-CN.md#L99-L145](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/README.zh-CN.md#L99-L145)

## 재정의 가능한 라이프사이클 메서드

| 메서드 | 트리거 시점 | 비고 |
|------|----------|------|
| `OnInit(object userData)` | 엔티티 최초 초기화 | `Transform` 캐시, 원본 `Layer` 저장, `Entity` 참조 획득 |
| `OnShow(object userData)` | 엔티티가 표시 상태로 진입 | 프레임워크가 자동으로 `Available`을 `true`로 설정하고 `Visible = true`로 설정 |
| `OnHide(bool isShutdown, object userData)` | 엔티티가 숨겨짐 | `isShutdown=true`은 관리자 종료에 의해 트리거됨을 나타냄; 프레임워크가 원본 `Layer` 복원 |
| `OnUpdate(float, float)` | 표시 상태에서 매 프레임 | 매개변수는 논리 경과 초와 실제 경과 초 |
| `OnRecycle()` | 엔티티가 객체 풀로 반환 | 외부 리소스 참조 해제에 사용 |
| `OnAttached` / `OnAttachTo` | 자식 엔티티가 본 엔티티에 부착됨 | 기본적으로 `CachedTransform.SetParent(parentTransform)` 설정 |
| `OnDetached` / `OnDetachFrom` | 자식 엔티티 연결 해제 | 기본적으로 `Transform`을 원래 부모 노드로 복원 |
| `InternalSetVisible(bool)` | 가시성 변경 시 | 기본적으로 `gameObject.SetActive(visible)` 호출, 사용자 정의 전환 로직 재정의 가능 |

## 일반적인 속성

| 속성 | 타입 | 설명 |
|------|------|------|
| `Entity` | `Entity` | 연결된 엔티티 컴포넌트 참조 |
| `Name` | `string` | `gameObject.name` 읽기/쓰기 |
| `Available` | `bool` | 엔티티 사용 가능 여부, `OnShow`/`OnHide`에 의해 제어됨 |
| `Visible` | `bool` | 엔티티 가시성; 사용 불가능 상태에서 값을 할당하면 `Log.Warning("Entity '{0}' is not available.", Name)` 출력 |
| `CachedTransform` | `Transform` | 캐시된 `Transform`, 최초 `OnInit` 시 할당됨 |

## 일반적인 오류

- **`base`를 호출하지 않음**. 기본 클래스의 `OnInit`은 `Transform`을 캐시하고 원본 `Layer`를 저장하며, `OnShow`는 `Available=true`를 설정하고, `OnHide`는 `Layer`를 복원합니다; `base`를 건너뛰면 가시성, 계층, 자식 노드 상태에 이상이 발생합니다.
- **라이프사이클 외부에서 `Available` 접근**. 엔티티가 표시되지 않았을 때 `Available`은 `false`이며, 이때 `Visible`에 쓰기를 하면 기본 클래스에서 차단되고 경고가 출력되며 로직이 실행되지 않습니다.
- **`EntityLogic` 서브클래스에서 직접 `new` 사용**. 반드시 프리팹에 부착되어 `EntityComponent`가 객체 풀을 통해 생성해야 하며, 수동으로 `new`하면 프레임워크의 이벤트 디스패치와 객체 풀 회수를 우회합니다.

## 배경(선택 사항)

`EntityLogic`은 `partial`인 `EntityManager`를 통해 표시/숨김/회수 시 해당 `protected internal` 가상 메서드를 트리거하여, 비즈니스 클래스가 객체 풀, 리소스 로딩 및 계층 관리에 대해 알 필요가 없도록 합니다. 모든 메서드의 접근 제한자는 `protected internal`이며, 이는 동일한 어셈블리 내부이거나 `EntityManager`에 의해 명시적으로 호출될 때만 트리거됨을 의미하며, 비즈니스 코드에서 수동으로 호출해서는 안 됩니다.
