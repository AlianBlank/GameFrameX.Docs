# 파일 읽기 오류:ArgumentNullException / ArgumentException(path)

`BlankReadAssets`의 `OpenRead`, `ReadAllBytes`, `GetFiles` 등의 메서드를 호출할 때, 전달된 `path` 매개변수가 `null`이거나 빈 문자열이면 즉시 인자 예외가 발생합니다. `PathUtil.CombineSlash` / `NormalizeRelativePath`를 호출할 때 경로 구성 요소가 누락되어도 동일한 예외가 발생합니다. 이 페이지는 어떤 상황인지 빠르게 파악하고 수정할 수 있도록 도와줍니다.

## 수정 단계

### 1. `OpenRead` / `ReadAllBytes`에 `null` 전달

소스 진입점: [BlankReadAssets.OpenRead](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L132-L146) 및 [BlankReadAssets.ReadAllBytes](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L197-L211). 두 메서드 모두 먼저 `path == null` 검사를 수행합니다.

```csharp
using GameFrameX.Asset;

string path = ResolveConfigPath(); // null을 반환할 수 있음

if (string.IsNullOrEmpty(path))
{
    Debug.LogError("配置文件路径未配置,跳过读取");
    return;
}

byte[] data = BlankReadAssets.ReadAllBytes(path);
```

### 2. `OpenRead` / `ReadAllBytes`에 빈 문자열 전달

소스: [BlankReadAssets.cs#L139-L142](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L139-L142). `path.Length == 0`일 때 `ArgumentException("Empty path", "path")`가 발생합니다.

```csharp
// 错误示例
string dir = "config/";
string file = ""; // 来自配置读取失败
string full = dir + file; // -> "config/" 的子路径可能仍有效,但 file 自身为空就会报错
byte[] data = BlankReadAssets.ReadAllBytes(full); // 取决于 full,不能依赖

// 修正:用 PathUtil.CombineSlash 拼接并校验
string full = PathUtil.CombineSlash(dir, file);
if (string.IsNullOrEmpty(full) || full.EndsWith("/"))
{
    throw new InvalidOperationException("目标文件路径无效: " + full);
}
```

### 3. `PathUtil.CombineSlash`에서 `ArgumentNullException` 발생

소스: [PathUtil.CombineSlash](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75). `a` 또는 `b` 중 하나라도 `null`이면 예외가 발생합니다.

```csharp
string dir = settings.TryGetValue("assetDir", out var d) ? d : null;
string name = settings.TryGetValue("assetName", out var n) ? n : null;

if (dir == null || name == null)
{
    Debug.LogWarning("资源路径不完整,使用默认配置");
    dir = "fallback";
    name = "default.bin";
}

string full = PathUtil.CombineSlash(dir, name);
```

### 4. `PathUtil.NormalizeRelativePath`에서 `ArgumentException("Empty or null", "relative")` 발생

소스: [PathUtil.NormalizeRelativePath](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L83). 빈 문자열을 포함하여 모든 빈 값은 바로 예외를 발생시킵니다.

```csharp
public static byte[] SafeRead(string relative)
{
    if (string.IsNullOrWhiteSpace(relative))
    {
        Debug.LogError("relative 为空,放弃读取");
        return Array.Empty<byte>();
    }
    return BlankReadAssets.ReadAllBytes(relative);
}
```

### 5. APK 모드에서 `GetFiles`의 `path`가 `null`

소스: [BlankReadAssets.ApkImpl.GetFiles](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L93-L116). `path == null`일 때 먼저 `ArgumentNullException`이 발생하며, 그 후에 디렉터리 인덱스 검사를 수행합니다.

```csharp
string dir = request.GetQueryParam("dir");
if (string.IsNullOrEmpty(dir))
{
    dir = "/"; // 根目录兜底
}
string[] files = BlankReadAssets.GetFiles(dir, "*", SearchOption.TopDirectoryOnly);
```

### 6. APK 내부 `ArgumentException()` (메시지 없음)

소스: [BlankReadAssets.ApkImpl.cs#L299-L306](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L299-L306). 이는 APK 구현의 `GetFiles`/`GetDirectories`에서 디렉터리 기본 경로에 대한 이차 검증이 실패한 것으로, 일반적으로 `BlankReadAssetsImpl`이 올바르게 초기화되지 않았음을 의미합니다.

```csharp
// 编辑器侧:在调用 GetFiles 前确保完成初始化
BlankReadAssets.InitializeWithExternalApk(apkPath);

// 运行时:确保 streamingAssets 已挂载(BlankReadAssets 会通过 EnsureInitialized 自行检查)
if (!BlankReadAssets.FileExists("manifest/index.txt"))
{
    throw new IOException("APK 资源未挂载,无法枚举目录");
}
```

## 검증

위의 수정 사항을 적용한 후, 아래의 최소 검증 스크립트를 사용하여 원래 오류 시나리오를 재현하고 더 이상 예외가 발생하지 않는지 확인합니다.

```csharp
using GameFrameX.Asset;
using System;

void AssertNoThrow(string label, Action act)
{
    try { act(); Console.WriteLine($"[OK] {label}"); }
    catch (ArgumentNullException) { Console.WriteLine($"[FAIL] {label}: ArgumentNullException"); }
    catch (ArgumentException)   { Console.WriteLine($"[FAIL] {label}: ArgumentException"); }
}

AssertNoThrow("null path", () => BlankReadAssets.OpenRead(null));
AssertNoThrow("empty path", () => BlankReadAssets.OpenRead(""));
AssertNoThrow("valid path", () =>
{
    using var s = BlankReadAssets.OpenRead("config/test.txt");
});
```

예상 출력에서 처음 두 항목은 사용자의 `catch` 분기로 들어가 적절히 처리되어야 하며, 세 번째 항목 `[OK] valid path`는 반드시 정상적으로 통과해야 합니다.

## 일반적인 오류

- **`path + ""` 결합에 의존**: 빈 파일명은 `ReadAllBytes`가 `path.Length == 0` 분기로 들어가 `ArgumentException`을 발생시킵니다. 대신 `PathUtil.CombineSlash`를 사용하고 결과를 검증하세요.
- **`null`과 `""`을 같은 경우로 취급**: 소스 코드에서 `OpenRead`는 `null`에 대해 `ArgumentNullException`을, `""`에 대해 `ArgumentException`을 발생시키므로 예외 유형이 다르며, 로그 검색 시 이를 구분해야 합니다.
- **APK 모드에서 초기화를 잊는 경우**: 초기화되지 않은 상태에서는 `EnsureInitialized`가 인자 예외가 아닌 `InvalidOperationException`을 발생시키므로 잘못 판단하기 쉽습니다. 먼저 초기화 여부를 확인한 다음 인자 검사를 살펴보세요.
- **`PathUtil.NormalizeRelativePath`에 루트 경로 또는 따옴표로 묶인 문자열을 전달**: 이 메서드는 `"`로 묶인 문자열에 대해 특수 처리를 수행하며([PathUtil.cs#L93](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L93)), 경로에 쌍이 맞지 않는 큰따옴표가 포함되면 파싱 예외가 발생할 수 있습니다.
