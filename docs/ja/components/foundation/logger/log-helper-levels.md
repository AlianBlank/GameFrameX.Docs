# LogHelper を使ったレベル別ログの出力方法

`LogHelper` は `GameFrameX.Foundation.Logger` 名前空間にある静的クラスで、Serilog  기반으로 Debug / Verbose / Info / Warning / Error / Fatal の 6 レベルのログ出力方法を提供します。構造化テンプレート、コンソール出力、例外記録をサポートしています。このページを読めば、自分のコードでレベルに応じた規約に沿ったログを出力できるようになります。

## 前提条件

- .NET プロジェクトが `GameFrameX.Foundation.Logger` アセンブリを参照していること(Serilog は推移的依存関係として自動的に取り込まれます)。
- アプリケーション起動の早い段階で `LogHelper.SetLogger(...)` を通じて、設定済みの `Serilog.ILogger` を注入してください。さもないと `LogHelper` は内蔵の `InternalTempLogger` を使ってログを一時保存し、正規のロガーが利用可能になった時点でフラッシュします。

## 操作手順

### 1. ロガーの初期化

```csharp
using GameFrameX.Foundation.Logger;
using Serilog;

var logger = new LoggerConfiguration()
    .MinimumLevel.Verbose()      // 出力可能な最低レベルを Verbose に設定
    .WriteTo.Console()
    .CreateLogger();

LogHelper.SetLogger(logger);
```

Source: [LogHelper.cs#L101-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L101-L112)

### 2. レベルに対応するメソッドを呼び出す

6 つのレベルのエントリーメソッドはレベル名と直接対応しており、命名とシグネチャが一貫しています:`(string messageTemplate, ...)` または `(object message)` で、内部的には基盤となる `ILogger` の同名メソッドに処理を委譲します。

```csharp
using GameFrameX.Foundation.Logger;

// デバッグ / 詳細情報
LogHelper.Verbose("起動フェーズ:設定 {ConfigName} を読み込み中", configName);
LogHelper.Debug("ユーザー {Id} がキャッシュにヒット", userId);

// 一般情報
LogHelper.Info("ログイン成功 user={Id} ip={Ip}", userId, ip);
LogHelper.Info(loginResult);

// 警告
LogHelper.Warning("API {Api} の応答時間 {Ms}ms が閾値を超えました", apiName, elapsed);

// エラー
LogHelper.Error("注文失敗 orderId={Id}", orderId);

// 致命的
LogHelper.Fatal("データベース接続が切断されました {Conn}", connectionString);
```

### 3. 例外を含むエラー / 致命的ログの記録

`Error` / `Fatal` のオーバーロードは `Exception` パラメータをサポートしており、例外オブジェクトをログイベントに書き込みます:

```csharp
try
{
    DoWork();
}
catch (Exception ex)
{
    LogHelper.Error(ex, "実行失敗 task={Name}", taskName);
    // または Fatal レベル
    LogHelper.Fatal(ex, "致命的エラー task={Name}", taskName);
}
```

### 4. コンソールにのみ出力する

ファイル書き込みが不要で、Serilog を通す必要もないシナリオでは、`LogHelper.Console` を使用してください。これはミリ秒レベルのタイムスタンプ付きで `System.Console` に直接書き込みます:

```csharp
LogHelper.Console("サーバー起動中...");
LogHelper.Console("リソース {Count} 個を読み込み、所要時間 {Ms}ms", count, ms);
```

Source: [LogHelper.Console.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Console.cs)、[LogHelper.cs#L145-L156](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L145-L156)

### 5. アプリケーション終了前にバッファをフラッシュする

プログラム終了前に `FlushAndSave()` または `CloseAndFlushAsync()` を呼び出して、バッファ内のログをファイルに書き出してください:

```csharp
LogHelper.FlushAndSave();
// または
await LogHelper.CloseAndFlushAsync();
```

## よくあるバリエーション

- **構造化プロパティテンプレート**:各レベルには 1〜8 個のジェネリックオーバーロードがあり、オブジェクトを(文字列として連結するのではなく)プロパティとして直接バインドするため、下流の Sink でフィールド検索が容易になります:
  ```csharp
  LogHelper.Info<Player>("現在のプレイヤー {Current}", player);
  LogHelper.Info<Player, int>("プレイヤー {Current} が {Kills} 体撃破", player, kills);
  ```
  Source: [LogHelper.Info.cs#L87-L216](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L87-L216)

- **オブジェクト引数**:`object` を渡すと、`Info` は `ToString()` を呼び出し、`null` の場合は文字列 `"null object"` を記録します:
  ```csharp
  LogHelper.Info(someObject); // someObject が null の場合 "null object" を出力
  ```
  Source: [LogHelper.Info.cs#L48-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L48-L51)

- **ゼロ引数テンプレート**:メッセージテンプレートのみを与え、フォーマット値を伴わない場合は、文字列を直接出力するのと同等です。

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| `LogHelper.Info(...)` が何も出力しない | `LogHelper.SetLogger(...)` が呼び出されておらず、かつ `MinimumLevel` で該当レベルの通過が許可されていない | 起動時に Logger を注入し、デバッグ用に `MinimumLevel.Verbose()` を設定する |
| プロセス終了時にログが失われる | `FlushAndSave()` / `CloseAndFlushAsync()` が呼び出されていない | `OnExit` / `Main` の末尾で上記のいずれかのメソッドを呼び出す |
| テンプレートの `{Name}` が値に置換されない | 文字列内で余計なプレースホルダが使用されている、または引数の数が一致していない | Serilog 標準のテンプレート構文 `{Property}` を使用し、引数の数をプレースホルダと一致させる |
| 書き込み先ファイルの場所を知りたい | 現在のメソッドはパスを直接公開していないため、Serilog Sink を自身で設定する必要がある | `LoggerConfiguration().WriteTo.File(...)` で自行指定する |
| `null` オブジェクトを記録するとクラッシュする | `Info(object)` のみ `ToString()` のフォールバックを行っている;他のレベルの `null` 処理は Serilog に依存する | 文字列テンプレート版を使用するか、自前で null チェックを行う |

## 背景(オプション)

`LogHelper` は `public static partial class` であり、各レベルのメソッドは独立したファイル(`LogHelper.Debug.cs` など)に配置され、すべて `GetLogger()` を通じて現在の `Serilog.ILogger` を取得します。`SetLogger` がまだ呼び出されていない場合は、内部の `InternalTempLogger` を使用してログを一時保存し、正規のロガーが注入された時点で `FlushTo` で転送するため、**初期化順序が最初のログ呼び出しより前でなくても問題ありません**。レベルは下に行くほど詳細になり、本番環境では通常 `MinimumLevel` を `Information` に設定し、デバッグ時に `Debug` または `Verbose` に下げます。Serilog の全体的な統合については、《LogHandler 初期化によるログシステム設定方法》を参照してください。
