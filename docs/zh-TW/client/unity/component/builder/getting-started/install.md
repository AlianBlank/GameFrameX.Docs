# 安裝與整合

將 `com.gameframex.unity.builder` 整合到 Unity 專案後，即可從命令列呼叫 `GameFrameX.Builder.Editor.Builder.BuildApk` 等方法，自動執行 APK/IPA 與 AssetBundle 的建置、上傳與通知。本頁說明從零開始的整合步驟，以及最簡單的驗證方法。

## 前置條件

- Unity 2019.4 以上
- 現有的 Unity 專案(包含 `Assets/`、`ProjectSettings/`、`Packages/`)

## 操作步驟

### 方法一：Scoped Registry(建議)

1. 開啟專案根目錄下的 `Packages/manifest.json`。
2. 在檔案最頂層新增 `scopedRegistries` 區段，並將 `com.gameframex` 命名空間指向 GameFrameX 的 UPM 來源：

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ]
   }
   ```

   `scopes` 控制會透過此 registry 解析哪些套件。僅有以 `com.gameframex` 開頭的套件會從此來源取得。

3. 在 `dependencies` 中宣告 builder 套件：

   ```json
   {
     "dependencies": {
       "com.gameframex.unity.builder": "2.2.0"
     }
   }
   ```

4. 返回 Unity 編輯器後，Package Manager 會自動解析並匯入套件。

### 方法二：Git URL(直接連線 GitHub)

直接在 `Packages/manifest.json` 的 `dependencies` 中輸入 Git 網址:

```json
{
  "dependencies": {
    "com.gameframex.unity.builder": "https://github.com/GameFrameX/com.gameframex.unity.builder.git"
  }
}
```

或者，在 Unity 中開啟 **Window → Package Manager → Add package from git URL**,貼上上述網址並點擊 **Add**。

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.md#L66)

### 方法三：複製到 Packages 目錄

```bash
git clone https://github.com/GameFrameX/com.gameframex.unity.builder.git
mv com.gameframex.unity.builder YourProject/Packages/
```

將儲存庫目錄放置於專案的 `Packages/` 下，Unity 啟動時會自動將其載入並識別為本機套件。

## 驗證整合

從命令列啟動建置入口方法，確認套件已正確載入：

```bash
Unity -batchmode -nographics -projectPath /path/to/YourProject \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
      -BUILD_NUMBER 1 \
      -logFile -
```

參數說明：

| 參數 | 必要 | 說明 |
|------|------|------|
| `-executeMethod` | 是 | 要執行的入口方法。例如: `GameFrameX.Builder.Editor.Builder.BuildApk` |
| `-BUILD_NUMBER` | 是 | 建置編號 |
| `-logFile` | 否 | 日誌檔案路徑。傳入 `-` 時輸出至 stdout |
| `-BundleId` | 否 | 應用程式套件名稱。預設從 Player Settings 取得 |
| `-AppVersion` | 否 | 應用程式版本號。預設從 Player Settings 取得 |
| `-ChannelName` | 否 | 渠道名稱。預設為 `default` |

若 Unity 啟動後未出現 `MissingMethodException` 或找不到套件的錯誤，即表示整合成功。完整參數說明請參閱《命令列參數》。

## 常見變化

- **僅使用資產建置管線**： 將 `-executeMethod` 替換為 `GameFrameX.Builder.Editor.Builder.BuildAsset`,並視需要新增 `-PackageName`、`-BuildPipeline`、`-IsIncrementalBuildPackage` 等參數。
- **整合物件儲存自動上傳**： 在命令中加入 `-ObjectStorageKey` / `-ObjectStorageSecret` / `-ObjectStorageBucketName` / `-ObjectStorageEndPoint`。
- **僅需變更版本號**： 直接編輯 `Packages/manifest.json` 中 `com.gameframex.unity.builder` 的版本號，Unity 會自動重新解析。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| Package Manager 回報 `Could not find scoped registry` | `manifest.json` 中 `scopedRegistries` 的拼字或位置錯誤 | 確認 `scopedRegistries` 位於 JSON 最頂層，且 `url` 可存取 |
| `Unable to resolve package com.gameframex.unity.builder` | `com.gameframex` 未加入 `scopes`,或未設定 registry | 將 `com.gameframex` 加入 `scopedRegistries[0].scopes` |
| 命令列執行時回報 `MissingMethodException: Builder.BuildApk` | 套件未正確匯入，或方法被裁剪 | 刪除 `Packages/com.gameframex.unity.builder/` 與 `Library/PackageCache/` 內的快取後重新匯入 |
| Unity 啟動後主控台顯示 `License/CHANGELOG not found` 警告 | 舊版本缺少套件規範檔案 | 升級至 ≥ 2.2.1。此版本已補齊 `LICENSE`/`CHANGELOG`/`url`/`unity` 欄位 |

## 背景(選用)

此套件以 UPM 標準套件形式發布，目前最新版本為 2.2.1(補齊套件規範檔案)，建議版本為 2.2.0。儲存庫本身不依賴第三方 UPM 套件，整合成本僅需一行 JSON 設定。
