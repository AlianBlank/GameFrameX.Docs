# 첫 빌드 실행하기

이 페이지의 단계에 따라 Unity에서 명령줄을 통해 GameFrameX Builder의 자동화 빌드를 트리거하고 첫 번째 APK / 리소스 패키지를 생성할 수 있습니다.

## 사전 조건

- Unity 2019.4 이상 버전
- `Packages/manifest.json`을 통해 `com.gameframex.unity.builder` 설치 완료 (2.0.3 이상 권장)
- Player Settings(패키지명, 버전 번호, 아이콘 등)이 구성된 Unity 프로젝트

`manifest.json`에 scoped registry와 의존성을 추가하는 최소 사용 가능 구성:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.builder": "2.0.3"
  }
}
```

## 작업 단계

1. **Unity 프로젝트를 열고 패키지 가져오기가 완료될 때까지 기다립니다**. `Packages` 아래에서 `com.gameframex.unity.builder`를 볼 수 있으면 됩니다.

2. **`-executeMethod` 대상 메서드를 사용할 수 있는지 확인합니다**. 빌드 진입점은 `GameFrameX.Builder.Editor.Builder`에 있으며, 가장 일반적으로 사용되는 두 가지 메서드는 다음과 같습니다:

   | 메서드 | 기능 |
   |------|------|
   | `GameFrameX.Builder.Editor.Builder.BuildApk` | APK를 패키징하고 `-IsUploadApk` 활성화 시 객체 스토리지에 업로드 |
   | `GameFrameX.Builder.Editor.Builder.BuildAsset` | YooAsset 리소스 패키지 빌드 |

   Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L51-L78)

3. **명령줄에서 빌드를 트리거합니다**. 가장 간단한 명령줄 형식(BuildApk 예시):

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath /path/to/your/project \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
         -BUILD_NUMBER 1 \
         -logFile /path/to/build.log
   ```

   `-BUILD_NUMBER`는 필수 항목이며, `-logFile`이 생략되면 Builder가 자동으로 로그 경로를 생성합니다.

4. **빌드 결과를 확인합니다**. `-BUILD_NUMBER`, `-AppVersion`, `-BundleId` 등의 매개변수는 `Builder.BuildParamsParse`에 의해 `BuilderOptions`으로 파싱되어 전체 빌드 파이프라인을 구동합니다. 로그 파일 경로는 `-logFile`로 지정되며, APK 출력 위치는 Unity의 BuildPlayerAndroid에 의해 결정됩니다.

   Source: [Builder.BuildParamsParse.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs)

## 일반적인 변형

### 리소스 패키지만 빌드(APK 미배포)

`-executeMethod`를 `GameFrameX.Builder.Editor.Builder.BuildAsset`로 바꾸고 리소스 빌드 매개변수를 지정합니다:

```bash
Unity -batchmode -nographics -quit \
      -projectPath /path/to/your/project \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
      -BUILD_NUMBER 1 \
      -PackageName DefaultPackage \
      -BuildPipeline BuiltinBuildPipeline \
      -IsIncrementalBuildPackage false
```

리소스 빌드 매개변수(발췌):

| 매개변수 | 기본값 | 설명 |
|------|--------|------|
| `-PackageName` | `DefaultPackage` | 리소스 패키지 이름 |
| `-PackageVersion` | 타임스탬프 | 비워둘 경우 자동으로 타임스탬프 사용 |
| `-BuildPipeline` | `BuiltinBuildPipeline` | `BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` 중 선택 가능 |
| `-BuildinFileCopyOption` | `ClearAndCopyAll` | 내장 파일 복사 옵션 |
| `-IsIncrementalBuildPackage` | `false` | 증분 빌드 여부 |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L97-L106)

### CI에서 로그 및 업로드 추가

빌드 시 다음 플래그를 추가하면 패키징 완료 후 로그/APK/리소스 패키지를 객체 스토리지에 업로드할 수 있습니다:

```bash
-IsUploadLogFile \
-IsUploadApk \
-IsUploadAsset \
-ObjectStorageKey <key> \
-ObjectStorageSecret <secret> \
-ObjectStorageBucketName <bucket> \
-ObjectStorageEndPoint <endpoint>
```

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `executeMethod`에서 대상 메서드를 찾을 수 없음 | 패키지가 제대로 가져오기되지 않았거나 네임스페이스 철자가 잘못됨 | `Packages` 아래에 `com.gameframex.unity.builder`가 있는지 확인하고, 메서드 전체 이름은 `GameFrameX.Builder.Editor.Builder.BuildApk`여야 함 |
| `-BUILD_NUMBER` 누락 오류 | 필수 매개변수가 전달되지 않음 | 명령줄에 `-BUILD_NUMBER <n>` 추가 |
| 객체 스토리지 업로드 실패 | 객체 스토리지 매크로가 활성화되지 않음 | 프로젝트에 해당 객체 스토리지 하위 패키지가 설치되어 있고 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 시리즈 매크로가 활성화되어 있는지 확인 |

## 배경(선택 사항)

Builder는 정적 생성 단계에서 `BuildParamsParse`를 호출하여 명령줄 매개변수를 `BuilderOptions`으로 파싱한 다음, `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_*` 매크로에 따라 객체 스토리지 구현을 선택합니다. `BuildApk`은 Unity 패키징을 트리거하고 필요에 따라 업로드하는 역할만 합니다. 리소스 빌드는 독립적인 `BuildAsset` 경로를 따릅니다. Builder의 전체 매개변수 표시는 《명령줄 매개변수 참고》를 참조하세요.
