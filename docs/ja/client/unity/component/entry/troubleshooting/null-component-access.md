# GameApp.{Name} へのアクセスが null になる、または null 参照エラーが発生する場合の対処方法

`GameApp.XXX`（例：`GameApp.Asset`、`GameApp.Base`）へのアクセスが `null` を返したり、`NullReferenceException` をスローしたりする場合、通常は対応するコンポーネントが起動時に `GameEntry` に登録されていない、またはフレームワークの初期化前にプロパティが呼び出されたことが原因です。`GameApp` は `GameEntry.GetComponent<T>()` のキャッシュラッパーにすぎず、実際のコンポーネントインスタンスは `GameEntry` が管理しています。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GameApp.XXX` が `null` を返す | 対応するコンポーネントが `GameEntry` に登録されていない、または対応するマクロ/条件付きコンパイルが有効になっていない | コンポーネントクラスが `GameEntry` の起動プレハブ/登録フローにアタッチされていること、および対応するマクロ（例：`ENABLE_GAME_FRAME_X_ASSET`）が有効になっていることを確認する |
| `Awake`/`Start` の早期に `GameApp.XXX` にアクセスすると null エラーが出る | フレームワークの初期化が完了していない | フレームワークの初期化完了コールバック（例：`GameEntry.OnGameFrameInitialized`）の後に呼び出すよう変更する、またはビジネススクリプトの `OnEnable` 以降に呼び出す |
| `NullReferenceException: Object reference not set to an instance of an object` が発生する | 呼び出し前の null チェックがなく、かつコンポーネントが未登録 | null チェックを追加し、上記 2 項の方法で登録/呼び出しのタイミングを修正する |
| `KeyNotFoundException` が発生する / コンポーネント型が見つからない | コンポーネントの DLL/アセンブリがプロジェクトに含まれていない、または名前空間が不一致 | コンポーネントが含まれるアセンブリが参照されていることを確認し、`using GameFrameX.Runtime;` を追加する |
| マクロの有効化/無効化後に突然 null になる | コンポーネントが `#if` 条件付きコンパイルで丸ごと除外され、`GameApp.XXX` フィールドが存在しない | `#if` ブロックの外では該当プロパティにアクセスしない。代わりに `GameEntry.GetComponent<T>()` をフォールバックとして使用する |

## 修正手順

### 1. コンポーネントが GameEntry に登録されていることを確認する

`GameApp` の実装は、本質的には `GameEntry` から遅延的にコンポーネントを取得するものです:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }

    private static BaseComponent _base;
}
```

ソース: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L52)

`GameEntry.GetComponent<BaseComponent>()` でコンポーネントが見つからない場合、`_base` は `null` のままになります。起動フローの中で `BaseComponent` などのコンポーネントが `GameEntry` の初期化リストにアタッチされているかどうかを確認してください。

### 2. 条件付きコンパイルマクロを確認する

多くの `GameApp.XXX` はマクロで囲まれています。例えば、`GameApp.Asset` は `ENABLE_GAME_FRAME_X_ASSET` を要求します:

```csharp
#if ENABLE_GAME_FRAME_X_ASSET
public static partial class GameApp
{
    public static AssetComponent Asset
    {
        get
        {
            if (_asset == null)
            {
                _asset = GameEntry.GetComponent<AssetComponent>();
            }
            return _asset;
        }
    }

    private static AssetComponent _asset;
}
#endif
```

ソース: [Runtime/GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs#L32-L55)

対応するマクロが定義されていない場合、その `GameApp.Asset` プロパティはコンパイル時に存在せず、直接アクセスするとコンパイルエラーになります。逆に、**マクロを有効にしてコード内で対応する `GameApp.XXX` を使用する場合は、対応するコンポーネントも `GameEntry` に登録されていることを確認する必要があります**。

### 3. フレームワークの初期化完了後にアクセスする

`GameApp` のフィールドは遅延読み込みされる静的キャッシュです。フレームワークの `Awake` より前のライフサイクル（例：他のシングルトンの `Awake`）でアクセスすると、コンポーネントの登録がまだ完了していない可能性があります。フレームワークの初期化完了イベントがトリガーされた後にアクセスするか、ビジネススクリプトの `OnEnable` / `Start` 内でアクセスしてください。

### 4. null チェックによる保護を追加する

登録済みであっても、呼び出し前に null チェックを行うことを推奨します。エディターでゲームを停止する際やリソース解放フェーズでのアクセスを避けるためです:

```csharp
if (GameApp.Asset != null)
{
    GameApp.Asset.LoadAsset(...);
}
```

頻繁に null チェックが必要になる場合は、そもそもそのコンポーネントをここで使用すべきではないことを示しています。手順 1 に戻って登録を確認してください。

## 検証

以下の 3 ステップを実行して、問題が解決したことを確認します:

1. `Awake` 内で `GameApp.Base` などの重要なプロパティを出力し、`null` でないことを確認します。
2. `GameEntry.GetComponent<T>()` を使ってコンポーネントの存在を再確認します。
3. シーン内で実際の呼び出し（例：リソースのロード、イベントの発行）を 1 回トリガーし、null 参照がまだ発生するかどうかを観察します。

`GameEntry.GetComponent<T>()` が常に `null` を返す場合は、問題が `GameApp` というこの層ではなく、コンポーネントの登録フロー自体にあることを示しています。`GameEntry` の初期化コードに戻り、コンポーネントのアタッチとライフサイクルの順序を調査してください。
