# リソース、設定、ローカライズ、グローバル設定の使用方法

GameFrameX は「リソース読み込み、ホットアップデート、ローカライズ文字列、業務設定テーブル」という 4 種類のデータ要件を 4 つの独立したサブシステムに集約し、`GameApp.{サブシステム}` 静的プロパティを通じて統一的にアクセスします。このページでは、業務コードでこれら 4 つのコンポーネントを取得し、最も一般的なテーブル読み込み / 設定読み込み / 多言語テキスト取得 / リソース読み込み操作を完了する方法を説明します。

## 前提条件

- `com.gameframex.unity.entry` パッケージがインストール済みであり、必要に応じて対応するランタイムサブパッケージ(`GameFrameX.Asset.Runtime`、`GameFrameX.Config.Runtime`、`GameFrameX.GlobalConfig.Runtime`、`GameFrameX.Localization.Runtime`)がインストールされていること。
- Unity の **Project Settings → Player → Scripting Define Symbols** で対応するマクロが有効化されていること(各コンポーネントは独立して制御されます、下表を参照)。

| サブシステム | 有効化マクロ | 名前空間 |
|--------|--------|----------|
| リソース | `ENABLE_GAME_FRAME_X_ASSET` | `GameFrameX.Asset.Runtime` |
| 設定 | `ENABLE_GAME_FRAME_X_CONFIG` | `GameFrameX.Config.Runtime` |
| グローバル設定 | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` | `GameFrameX.GlobalConfig.Runtime` |
| ローカライズ | `ENABLE_GAME_FRAME_X_LOCALIZATION` | `GameFrameX.Localization.Runtime` |

マクロが有効化されていない場合、対応する `GameApp.{Name}` プロパティの定義全体がコンパイルに含まれず、業務コードで「`Asset` が見つかりません」などのエラーが直接発生します。

## 操作手順

### 1. サブシステムへのアクセサーを取得する

4 つのサブシステムのエントリ構造は完全に同一です。任意の業務クラスで静的プロパティ `GameApp.{サブシステム}` に直接アクセスすると、初回アクセス時に `GameEntry` から対応するコンポーネントが遅延ロードされます。

```csharp
// リソース
var asset = GameApp.Asset;
// 設定
var config = GameApp.Config;
// グローバル設定
var globalConfig = GameApp.GlobalConfig;
// ローカライズ
var localization = GameApp.Localization;
```

### 2. Asset コンポーネントでリソースを読み込む

`AssetComponent` は `GameFrameX.Asset.Runtime` パッケージによって提供され、`GameApp.Asset` を通じて取得します。呼び出し前に、このコンポーネントが `GameEntry` の起動フローで登録済みであることを確認してください。

```csharp
using GameFrameX.Asset.Runtime;

var asset = GameApp.Asset;
// 実際に利用可能な API はインストールした Asset サブパッケージのバージョンによって異なります。
// ここではエントリの呼び出し方法のみを示しており、具体的なシグネチャはサブパッケージのドキュメントを参照してください。
asset.LoadAssetAsync<GameObject>("Assets/Prefabs/Player.prefab", (prefab) =>
{
    Instantiate(prefab);
});
```

## よくあるバリエーション

- **非同期でのリソース読み込み**：読み込み完了を待つ必要があるコールバック内で `GameApp.Asset.LoadAssetAsync<T>` シリーズのメソッドを呼び出し、メインスレッドで同期ブロッキングしないでください。
- **多言語切り替え**：言語を切り替えた後は通常 UI テキストの更新が必要です。具体的な更新方法は Localization サブパッケージによって決まりますが、エントリは常に `GameApp.Localization` を経由します。
- **設定テーブルのホットリロード**:Config サブパッケージを使用する場合、通常はサブパッケージが提供する `Reload` インターフェースを使用し、基盤のファイルを直接操作しないでください。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| コンパイルエラー:`GameApp` に `Asset` / `Config` などの定義が含まれていない | Player Settings で対応するマクロが有効化されておらず、対応する partial クラスがコンパイルに含まれていない | 「前提条件」の表に従って `ENABLE_GAME_FRAME_X_*` マクロを追加する |
| 実行時に `GameApp.Asset` が `null` になる | `GameEntry` に `AssetComponent` が登録されていない | 起動フローの `RegisterComponent` 段階で対応するコンポーネントを追加する |
| 業務コードで多言語 / 設定フィールドが読み取れない | サブシステムのエントリを誤って使用している | 区別に注意:`GameApp.Config` は業務設定テーブルを読み込み、`GameApp.GlobalConfig` はグローバルパラメータを読み込み、`GameApp.Localization` は多言語テキストを読み込む |

## 背景(任意)

4 つのエントリプロパティはすべて `static partial class GameApp` の遅延ロードプロパティです。初回アクセス時に `GameEntry.GetComponent<T>()` を通じて登録済みのコンポーネントインスタンスを取得し、以降のアクセスではキャッシュされたフィールドを直接返します。各ファイルは対応する `ENABLE_GAME_FRAME_X_*` マクロで定義全体を囲んでいるため、業務プロジェクトは必要に応じてサブシステムを切り捨てることができ、フレームワーク全体をパッケージにコンパイルする必要はありません。
