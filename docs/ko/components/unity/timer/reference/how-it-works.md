# 작동 원리: 스레드 안전 업데이트 루프와 객체 풀

`TimerManager`는 매 프레임 `Update`에서 전역 락(`Locker`) 하나로 "활성 타이머 스캔 → 만료 항목 회수 → 신규 항목 병합"의 3단계 업데이트를 순차적으로 수행합니다. 모든 만료 콜백은 먼저 `_pendingCallbacks`에 수집된 뒤 락 외부에서 일괄 실행되어, 콜백 내부에서 다시 Add/Remove를 호출할 때 발생하는 교착 상태를 방지합니다. 제거된 `TimerItem`은 파괴되지 않고 참조를 비운 후 `Stack<TimerItem>` 객체 풀에 되돌려 재사용됩니다.

## 핵심 데이터 구조 빠른 참조

| 멤버 | 실제 타입/기본값 | 역할 |
|------|-----------------|------|
| `_items` | `Dictionary<Action<object>, TimerItem>` | 활성 타이머 테이블, **콜백 델리게이트를 key로 사용**(동일한 콜백에는 타이머가 하나만 존재 가능) |
| `_toAdd` | `Dictionary<Action<object>, TimerItem>` | 병합 대기 중인 신규 타이머, `Add()`는 여기에 먼저 기록하고 프레임 끝에 `_items`에 병합 |
| `_toRemove` | `List<TimerItem>` | 회수 대기 항목, Update에서 일괄 정리 |
| `_pool` | `Stack<TimerItem>`, 초기 용량 100 | `TimerItem` 객체 풀, 회수 후 재사용 |
| `_pendingCallbacks` | `List<(Action<object> Callback, object Param)>` | 해당 프레임의 만료 콜백 캐시, 락 외부에서 실행 |
| `_ids` | `Dictionary<int, Action<object>>` | 타이머 ID → 콜백 인덱스 |
| `_tags` | `Dictionary<string, List<int>>` | 태그 → ID 리스트 그룹 인덱스 |
| `_nextId` | `int`, 1부터 자동 증가 | ID 할당기 |
| `Locker` | `static readonly object` | 전역 락 객체, 모든 읽기/쓰기 경로에서 공유 |
| `CatchCallbackExceptions` | `static bool`, 기본값 `false` | `true`이면 콜백 예외를 삼키고 경고만 출력 |

## 매 프레임 업데이트 루프

`Update(float elapseSeconds, float realElapseSeconds)`는 `GameFrameworkModule`에서 상속되며, 프레임마다 프레임워크에 의해 한 번 구동됩니다. 전체 상태 스캔은 `lock (Locker)` 내부에서 이루어집니다:

1. **삭제 및 일시정지 항목 건너뛰기**: `Deleted`인 항목은 `_toRemove`에 들어가고, `IsPaused`인 항목은 누적을 건너뛰되 `_items`에 그대로 남습니다.
2. **시간 스케일 모드에 따른 시간 소스 선택**: `TimerTimeScale.Scaled`는 `elapseSeconds`를, 그 외에는 `realElapseSeconds`를 사용합니다.
3. **매 프레임 타이머**(interval <= 0)는 시간을 누적하지 않고 해당 프레임에서 즉시 트리거됩니다.
4. **일반 타이머**는 `Elapsed`를 누적하며, `Elapsed >= Interval`이면 `Interval`을 차감하고 `_pendingCallbacks`에 추가합니다.
5. **반복 횟수 차감**: `Repeat > 0`일 때 트리거마다 `Repeat--`되며, 0이 되면 `Deleted`로 표시되고 `_toRemove`에 들어갑니다.
6. **회수**: `_toRemove`를 순회하며 `OnComplete`를 트리거하고, `_items`/`_ids`/`_tags`에서 제거한 뒤 객체 풀에 반환합니다.
7. **병합**: `_toAdd`를 `_items`에 병합한 뒤 비웁니다.

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    lock (Locker)
    {
        if (_items.Count > 0)
        {
            var enumerator = _items.GetEnumerator();
            while (enumerator.MoveNext())
            {
                var timerItem = enumerator.Current.Value;
                if (timerItem.Deleted)
                {
                    _toRemove.Add(timerItem);
                    continue;
                }

                // Paused timer: skip elapsed accumulation but remain in _items
                if (timerItem.IsPaused)
                {
                    continue;
                }

                // Select time source based on TimeScaleMode
                float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L58-L81)

시간 누적과 트리거 판정(`Elapsed`의 남은 값이 0.03초를 초과하면 0으로 클램프되어, 렉 이후 연속 발동을 방지):

```csharp
timerItem.Elapsed += delta;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}

timerItem.Elapsed -= timerItem.Interval;
if (timerItem.Elapsed < 0 || timerItem.Elapsed > 0.03f)
    timerItem.Elapsed = 0;

if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}

if (timerItem.Callback != null)
{
    _pendingCallbacks.Add((timerItem.Callback, timerItem.Param));
}
```

## 콜백은 락 외부에서 실행(스레드 안전의 핵심)

`_pendingCallbacks`의 실행은 `lock` 블록 **외부**에서 이루어집니다. 이는 의도된 설계입니다. 콜백 내부에서 다시 `Add`/`Remove`/`Exists`를 호출할 때(이들은 각자 `lock (Locker)`을 수행) 락 내부에서 실행하면 즉시 교착 상태에 빠집니다. C#의 `lock`/Monitor는 동일한 스레드에 대해 재진입이 가능하지만, 진짜 위험은 락을 장시간 점유하여 다른 스레드(예: 비동기/백그라운드 스레드의 continuation)를 차단하는 것입니다. 콜백을 락 외부로 옮기면 콜백 안에서 안전하게 타이머를 추가/제거할 수 있습니다.

```csharp
// Execute callbacks outside lock to avoid blocking other threads
if (_pendingCallbacks.Count > 0)
{
    for (int i = 0; i < _pendingCallbacks.Count; i++)
    {
        var (callback, param) = _pendingCallbacks[i];
        if (CatchCallbackExceptions)
        {
            try
            {
                callback(param);
            }
            catch (Exception e)
            {
                Debug.LogWarning("Timer callback error > " + e.Message);
            }
        }
        else
        {
            callback(param);
        }
    }

    _pendingCallbacks.Clear();
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L166-L190)

주의: 콜백 실행 중 예외가 발생하고 `CatchCallbackExceptions == false`(기본값)이면 예외가 상위로 전파되어 `_pendingCallbacks`가 비워지지 않습니다. 이후 프레임에서 해당 리스트가 계속 누적되어 동일한 콜백 묶음이 중복 실행될 수 있습니다. 게임 초기화 시 `TimerManager.CatchCallbackExceptions = true`를 켜는 것을 권장합니다.

## 객체 풀: GetFromPool / ReturnToPool

`TimerItem`은 private 중첩 클래스로, 가져올 때는 `_pool`에서 우선적으로 팝하여 모든 실행 상태 필드를 리셋하고, 풀이 비어 있을 때만 `new`합니다. 반환할 때는 모든 델리게이트와 파라미터 참조를 비운 뒤 풀에 되돌려 넣어 객체 유지(Object Retention)로 인한 누수를 방지합니다.

```csharp
private TimerItem GetFromPool()
{
    TimerItem t;
    if (_pool.Count > 0)
    {
        t = _pool.Pop();
        t.Deleted = false;
        t.Elapsed = 0;
        t.IsPaused = false;
        t.PausedElapsed = 0;
        t.TimeScaleMode = TimerTimeScale.Unscaled;
        t.Tag = null;
        t.OnComplete = null;
    }
    else
    {
        t = new TimerItem();
    }

    return t;
}

private void ReturnToPool(TimerItem t)
{
    t.Callback = null;
    t.Param = null;
    t.Tag = null;
    t.OnComplete = null;
    _pool.Push(t);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L623-L652)

반환 진입점은 두 곳이며, 모두 락 내부에서 호출됩니다:

| 반환 시점 | 위치 | `OnComplete` 트리거 여부 |
|----------|------|---------------------|
| Update에서 만료/삭제 항목 회수(`Repeat` 소진 또는 `Deleted` 표시) | `Update` 내 `_toRemove` 정리 루프 | 예, `i.OnComplete?.Invoke()`가 반환 전에 호출됨 |
| `Remove(callback)`가 아직 `_toAdd`에 있고 병합되지 않은 항목에 적중 | `Remove(Action<object>)` | 예, 먼저 `t.OnComplete?.Invoke()` 후 반환 |

## Add의 세 가지 경로

`Add(...)`는 `lock` 내부에서 아래 순서대로 처리되며, 동일한 호출이라도 서로 다른 분기에 적중할 수 있습니다:

| 순서 | 조건 | 동작 |
|------|------|------|
| 1 | `callback == null` | 경고 `timer callback is null, {interval},{repeat}` 출력 후 `0` 반환 |
| 2 | 콜백이 이미 `_items`에 존재 | **제자리 업데이트**: `Set(...)`로 파라미터 재설정, `Elapsed = 0`, `Deleted/IsPaused` 해제 후 기존 `Id` 반환 |
| 3 | 콜백이 이미 `_toAdd`에 존재 | 동일하게 제자리 업데이트 후 기존 `Id` 반환 |
| 4 | 완전히 새로운 콜백 | `_nextId++`로 ID 할당, `GetFromPool()`로 객체 획득, `_toAdd`/`_ids`/`_tags`에 기록 후 새 `Id` 반환 |

```csharp
int id = _nextId++;
t = GetFromPool();
t.Id = id;
t.Interval = interval;
t.Repeat = repeat;
t.Callback = callback;
t.Param = callbackParam;
t.Tag = tag;
t.TimeScaleMode = timeScale;
t.OnComplete = onComplete;
_toAdd[callback] = t;
_ids[id] = callback;
AddToTagIndex(t);
return id;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L260)

key가 콜백 델리게이트 자체이기 때문에, **동일한 lambda/메서드에 대해 `Add`를 반복해도 두 번째 타이머가 생성되지 않으며**, 기존 타이머가 재설정됩니다 — 여기에는 `Elapsed`를 0으로 초기화하고 일시정지를 해제하는 것도 포함됩니다.

## Remove의 2단계 방식

`Remove(callback)`는 `_toAdd`에 적중하면 즉시 삭제하고 객체 풀에 반환합니다(해당 타이머는 스캔 루프에 진입한 적이 없음). `_items`에 적중하면 `t.Deleted = true`라는 지연 표시만 수행하며, 실제 회수는 다음 프레임 `Update`의 `_toRemove` 정리 루프에서 일어납니다. `Remove(int id)`도 마찬가지로, 먼저 `_ids`에서 콜백을 찾은 뒤 동일한 로직을 따릅니다.

```csharp
public void Remove(Action<object> callback)
{
    lock (Locker)
    {
        if (_toAdd.TryGetValue(callback, out var t))
        {
            _toAdd.Remove(callback);
            _ids.Remove(t.Id);
            RemoveFromTagIndex(t);
            t.OnComplete?.Invoke();
            ReturnToPool(t);
            return;
        }

        if (_items.TryGetValue(callback, out t))
        {
            t.Deleted = true;
        }
    }
}
```

## Shutdown 동작

`Shutdown`은 락 내부에서 `_toRemove`, `_toAdd`, `_items`, `_ids`, `_tags`, `_pendingCallbacks`를 비웁니다 — 단, **객체를 `_pool`에 반환하지 않고 어떤 `OnComplete`도 트리거하지 않는다**는 점에 유의하세요. 컴포넌트 파괴 후 풀의 객체들은 관리자와 함께 해제됩니다.

## 외부 컴포넌트와 구동 방식

`TimerComponent`는 Unity 측의 `GameFrameworkComponent`로, `Awake`에서 `GameFrameworkEntry.GetModule<ITimerManager>()`를 통해 `TimerManager` 인스턴스를 가져오며 자체의 모든 API는 단 한 줄의 포워딩만 수행합니다. 실제 매 프레임 구동은 프레임워크 기반 클래스 `GameFrameworkModule`의 `Update` 호출에서 비롯되며, `TimerComponent`에는 `[GameFrameXAutoComponent(-5000)]` 어트리뷰트가 부여되어 자동 등록 순서가 결정됩니다.

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");
        return;
    }
}
```
