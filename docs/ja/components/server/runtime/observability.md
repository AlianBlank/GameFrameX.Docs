# OpenTelemetry / Prometheus メトリクスとヘルスチェックの設定

このセクションでは、GameFrameX.Server 内蔵の OpenTelemetry テレメトリを有効化し、Prometheus メトリクス(`/metrics`)とヘルスチェック(`/health`)をモニタリングシステムに公開する方法を説明します。

## 前提条件

- GameFrameX.Server がデプロイ済みで、正常に起動できること。
- モニタリングシステムが `MetricsPort` で指定されたポート(デフォルト `29090`)のサーバーにアクセスできること。

## 操作手順

1. 起動パラメータまたは環境変数で OpenTelemetry のマスタースイッチを有効化します。

   ```bash
   --IsOpenTelemetry=true
   ```

   起動コマンドの例(`docker-compose.yml` 内の `MetricsPort` と `APMPort` の行を参考にしてください):

   ```bash
   --InnerPort=29100 \
   --MetricsPort=29090 \
   --IsEnableHttp=true
   ```

   出典: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L115-L121)

2. Prometheus メトリクス出力を有効化します(デフォルト `false`、`IsOpenTelemetry=true` が必要です)。

   ```bash
   --IsOpenTelemetryMetrics=true
   ```

   出典: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

3. (オプション)分散トレーシングを有効化します。

   ```bash
   --IsOpenTelemetryTracing=true
   ```

   出典: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

4. メトリクス収集ポートを設定します。未設定の場合はデフォルト値 `0`(つまり外部ポートを閉じる)を使用します。

   ```bash
   --MetricsPort=29090
   ```

   デフォルト値とサンプル値は下表の通りです。出典: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

5. サービスを再起動し、2 つのエンドポイントが利用可能か確認します:

   | エンドポイント | URL | 説明 |
   |------|-----|------|
   | ヘルスチェック | `http://<host>:29090/health` | サービスの稼働状態と準備状態 |
   | Prometheus メトリクス | `http://<host>:29090/metrics` | Prometheus が取得するメトリクステキスト |

   出典: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L175-L177)

## よくあるバリエーション

- **Docker Compose デプロイ**: `docker-compose.yml` の環境変数領域に以下の行を追加するだけで、イメージの変更は不要です。
  参考: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)
- **ヘルスチェックのみを有効化し、メトリクスはエクスポートしない**: `IsOpenTelemetryMetrics=false` のまま、`/health` エンドポイントのみをロードバランサーや K8s readiness プローブに接続します。
- **リモート OTLP コレクターへのエクスポート**: `IsOpenTelemetry=true` を基盤として `IsOpenTelemetryTracing` を有効化すれば、トレースデータを出力できます(具体的なコレクターアドレスはデプロイ要件に応じて別途設定してください)。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `/metrics` へのアクセスが接続拒否される | `IsOpenTelemetry` が有効化されていない | `--IsOpenTelemetry=true` を追加して再起動 |
| `IsOpenTelemetryMetrics` を有効化したのにメトリクスが出ない | マスタースイッチが欠落している | このパラメータは `IsOpenTelemetry=true` に依存しています |
| ポート競合 | `MetricsPort` と `APMPort` が同じポートを使用している | `MetricsPort=29090` を明示的に設定し、ホスト側のポートが空いていることを確認 |
| Prometheus がデータを取得できない | ファイアウォールでポートが許可されていない | セキュリティグループ / ファイアウォールで `MetricsPort` を許可 |

## 設定項目クイックリファレンス

| 名称 | 型 / デフォルト値 | 説明 |
|------|-------------|------|
| `IsOpenTelemetry` | `bool`、デフォルト `false` | OpenTelemetry テレメトリのマスタースイッチ |
| `IsOpenTelemetryMetrics` | `bool`、デフォルト `false` | Prometheus メトリクスエクスポートを有効化、`IsOpenTelemetry=true` が必要 |
| `IsOpenTelemetryTracing` | `bool`、デフォルト `false` | 分散トレーシングを有効化、`IsOpenTelemetry=true` が必要 |
| `MetricsPort` | `int`、デフォルト `0` | メトリクス収集ポート、サンプル値 `29090` |

出典: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)、[README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

## 背景

OpenTelemetry は CNCF 卒業の可観測性標準であり、GameFrameX.Server はマスタースイッチ + サブスイッチの二層設計により、メトリクスとトレーシングを分離しています。これにより、フルテレメトリが必要ない場合にヘルスチェックのみを公開でき、ホスト側のポートとリソースの占有を削減できます。
