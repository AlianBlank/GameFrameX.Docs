# 如何使用核心子系統：事件、流程、狀態機、計時器等

`GameFrameX` 透過 `GameApp` 靜態外觀(Facade)對外提供四大執行階段子系統——Event(事件)、Procedure(流程)、Fsm(狀態機)與 Timer(計時器)——每個子系統皆由對應的 `*Component` 承載，透過功能巨集(`ENABLE_GAME_FRAME_X_*`)進行裁剪，並統一透過 `GameEntry.GetComponent<>()` 延遲載入。

## 前置條件

- 已透過 Package Manager 匯入 `com.gameframex.unity.entry`,並視需要在 `HybridCLR/GameFrameX Settings` 中啟用 **Event / Procedure / Fsm / Timer** 子模組(對應自動產生的巨集，例如 `ENABLE_GAME_FRAME_X_EVENT`)。
- `GameApp.*.cs` 中的各個子系統都包裝在 `#if ENABLE_GAME_FRAME_X_*` 之內。若未啟用巨集，`GameApp.Event / Procedure / Fsm / Timer` 屬性將不會被編譯。引用前請務必先確認。

## 統一存取方式

所有子系統皆透過 `GameApp` 靜態類別取得，由內部的 `_xxx` 快取欄位在首次存取時延遲建立：

```csharp
using GameFrameX.Runtime;

var evt    = GameApp.Event;     // EventComponent
var proc   = GameApp.Procedure; // ProcedureComponent
var fsm    = GameApp.Fsm;       // FsmComponent
var timer  = GameApp.Timer;     // TimerComponent
```

> 若功能巨集已停用，存取對應屬性將觸發「找不到元件」錯誤或編譯錯誤。請先在專案設定中啟用對應功能。

## 步驟

### 1. 使用事件子系統

事件元件負責全域事件的訂閱與廣播；其類型位於 `GameFrameX.Event.Runtime.EventComponent`。

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;

// 訂閱
GameApp.Event.Subscribe<TestEvent>(OnTestEvent);

void OnTestEvent(object sender, TestEvent e)
{
    // 處理事件
}

// 觸發
GameApp.Event.Fire(sender, new TestEvent { /* 欄位 */ });

// 取消訂閱
GameApp.Event.Unsubscribe<TestEvent>(OnTestEvent);
```

### 2. 使用流程子系統

流程元件負責驅動 `ProcedureBase` 衍生類別之間的切換；其類型位於 `GameFrameX.Procedure.Runtime.ProcedureComponent`。

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

// 進入第一個流程(通常在遊戲啟動完成後)
GameApp.Procedure.StartProcedure<LaunchProcedure>();

// 執行時切換
GameApp.Procedure.StartProcedure<LoginProcedure>();

// 檢查目前流程
if (GameApp.Procedure.CurrentProcedure is LoginProcedure) { /* ... */ }
```

每個流程類別必須繼承自 `ProcedureBase`,並實作 `OnEnter` / `OnUpdate` / `OnLeave` 生命週期。

### 3. 使用狀態機子系統

狀態機元件承載多個 `Fsm<T>` 實例；其類型位於 `GameFrameX.Fsm.Runtime.FsmComponent`。

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Runtime;

// 建立並啟動狀態機
var fsm = GameApp.Fsm.Create("PlayerFsm", owner, new IdleState(), new RunState(), new AttackState());
GameApp.Fsm.StartFsm("PlayerFsm");

// 切換狀態
fsm.ChangeState<RunState>();
```

狀態類別必須繼承自 `FsmState<T>` 並覆寫 `OnEnter` / `OnUpdate` / `OnLeave`。

### 4. 使用計時器子系統

計時器元件支援單次、重複、基於幀等多種任務類型；其類型位於 `GameFrameX.Timer.Runtime.TimerComponent`。

```csharp
using GameFrameX.Timer.Runtime;
using GameFrameX.Runtime;

// 啟動單次計時器
int id = GameApp.Timer.AddOnce(5f, () => { /* 5 秒後執行 */ });

// 啟動重複計時器
int loopId = GameApp.Timer.AddRepeating(1f, () => { /* 每秒執行一次 */ });

// 取消
GameApp.Timer.Remove(loopId);
```

## 常見變化

- **跨流程共享資料**：將資料附加至 `ProcedureBase` 的衍生欄位，並在流程切換時伴隨 `GameApp.Procedure.CurrentProcedure` 一併存取。
- **事件 + 狀態機**：在狀態的 `OnEnter` 中呼叫 `GameApp.Event.Subscribe`,並在 `OnLeave` 中呼叫 `Unsubscribe`,以避免離開後仍持續回應。
- **計時器粒度**：除了秒級計時器外，`TimerComponent` 還提供幀數版本(由幀驅動)，適用於不依賴時間縮放的邏輯。

## 常見錯誤

- **未啟用功能巨集即存取**：不會產生編譯錯誤，但會在執行階段發生「元件未註冊」錯誤。解決方案：在專案設定中勾選對應的子系統巨集。
- **事件未取消訂閱導致記憶體洩漏**：銷毀物件前必須呼叫 `Unsubscribe`,尤其是當 `MonoBehaviour` 持有回呼時。
- **流程/狀態機缺少基底類別方法**：繼承 `ProcedureBase` / `FsmState<T>` 後若忘記實作 `OnEnter`,切換時將不會執行任何動作。
