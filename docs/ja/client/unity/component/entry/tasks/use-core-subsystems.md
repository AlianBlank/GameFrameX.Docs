# イベント、プロシージャ、ステートマシン、タイマーなどコアサブシステムの使用方法

`GameFrameX` は `GameApp` スタティックファサードを通じて、4 つの主要なランタイムサブシステム――イベント（Event）、プロシージャ（Procedure）、ステートマシン（Fsm）、タイマー（Timer）――を公開しています。各サブシステムはそれぞれ 1 つの `*Component` によって担われ、機能マクロ（`ENABLE_GAME_FRAME_X_*`）に従ってトリムされ、`GameEntry.GetComponent<>()` を通じて統一的に遅延ロードされます。

## 前提条件

- Package Manager を通じて `com.gameframex.unity.entry` を導入済みであり、必要に応じて `HybridCLR/GameFrameX Settings` で **Event / Procedure / Fsm / Timer** サブモジュールの有効化にチェックを入れていること（対応する `ENABLE_GAME_FRAME_X_EVENT` などのマクロが自動生成されます）。
- `GameApp.*.cs` 内の各サブシステムは `#if ENABLE_GAME_FRAME_X_*` 内にラップされており、マクロが有効でない場合は `GameApp.Event / Procedure / Fsm / Timer` プロパティがコンパイルされません。参照前に必ず確認してください。

## 統一されたアクセス方法

すべてのサブシステムは `GameApp` 静的クラスを通じてコンポーネントを取得し、初回アクセス時に内部の `_xxx` キャッシュフィールドによって遅延生成されます：

```csharp
using GameFrameX.Runtime;

var evt    = GameApp.Event;     // EventComponent
var proc   = GameApp.Procedure; // ProcedureComponent
var fsm    = GameApp.Fsm;       // FsmComponent
var timer  = GameApp.Timer;     // TimerComponent
```

> 有効化マクロがオフの場合、対応するプロパティへのアクセスは「コンポーネントが見つかりません」やコンパイルエラーを引き起こします。先にプロジェクト設定で該当機能を有効にしてください。

## 操作手順

### 1. イベントサブシステムを使用する

イベントコンポーネントはグローバルイベントの購読とブロードキャストを担当します。型は `GameFrameX.Event.Runtime.EventComponent` にあります。

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;

// 購読
GameApp.Event.Subscribe<TestEvent>(OnTestEvent);

void OnTestEvent(object sender, TestEvent e)
{
    // イベントを処理
}

// 発火
GameApp.Event.Fire(sender, new TestEvent { /* フィールド */ });

// 購読解除
GameApp.Event.Unsubscribe<TestEvent>(OnTestEvent);
```

### 2. プロシージャサブシステムを使用する

プロシージャコンポーネントは `ProcedureBase` 派生クラス間の切り替えを駆動します。型は `GameFrameX.Procedure.Runtime.ProcedureComponent` にあります。

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

// 最初のプロシージャに入る（通常はゲーム起動完了後）
GameApp.Procedure.StartProcedure<LaunchProcedure>();

// 実行時の切り替え
GameApp.Procedure.StartProcedure<LoginProcedure>();

// 現在のプロシージャを判定
if (GameApp.Procedure.CurrentProcedure is LoginProcedure) { /* ... */ }
```

各プロシージャクラスは `ProcedureBase` を継承し、`OnEnter` / `OnUpdate` / `OnLeave` ライフサイクルを実装する必要があります。

### 3. ステートマシンサブシステムを使用する

ステートマシンコンポーネントは複数の `Fsm<T>` を管理します。型は `GameFrameX.Fsm.Runtime.FsmComponent` にあります。

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Runtime;

// ステートマシンを作成して起動
var fsm = GameApp.Fsm.Create("PlayerFsm", owner, new IdleState(), new RunState(), new AttackState());
GameApp.Fsm.StartFsm("PlayerFsm");

// 状態を切り替え
fsm.ChangeState<RunState>();
```

状態クラスは `FsmState<T>` を継承し、`OnEnter` / `OnUpdate` / `OnLeave` をオーバーライドする必要があります。

### 4. タイマーサブシステムを使用する

タイマーコンポーネントは、一回限り、繰り返し、フレーム計時など多様なタスクをサポートします。型は `GameFrameX.Timer.Runtime.TimerComponent` にあります。

```csharp
using GameFrameX.Timer.Runtime;
using GameFrameX.Runtime;

// 一回限りのタイマーを開始
int id = GameApp.Timer.AddOnce(5f, () => { /* 5 秒後に実行 */ });

// 繰り返しタイマーを開始
int loopId = GameApp.Timer.AddRepeating(1f, () => { /* 毎秒実行 */ });

// キャンセル
GameApp.Timer.Remove(loopId);
```

## よくあるバリエーション

- **プロシージャ間でのデータ共有**：データを `ProcedureBase` の派生フィールドに持たせ、`GameApp.Procedure.CurrentProcedure` とともに切り替えてアクセスします。
- **イベント + ステートマシン**：状態の `OnEnter` で `GameApp.Event.Subscribe`、`OnLeave` で `Unsubscribe` を行い、離脱後も応答し続けるのを防ぎます。
- **タイマーの粒度**：秒単位のほか、`TimerComponent` はフレームカウント版（フレーム駆動）も提供しており、タイムスケールに依存しないロジックに適しています。

## よくあるエラー

- **機能マクロを有効化せずにアクセス**：コンパイル時にはエラーになりませんが、実行時に「コンポーネントが未登録」というエラーが発生します。解決策：プロジェクト設定で対応するサブシステムのマクロにチェックを入れてください。
- **イベントの購読解除漏れによるメモリリーク**：オブジェクトの破棄前に必ず `Unsubscribe` を行ってください。特に `MonoBehaviour` がコールバックを保持している場合です。
- **プロシージャ/ステートマシンで基底クラスのメソッド未実装**：`ProcedureBase` / `FsmState<T>` を継承した後に `OnEnter` を実装し忘れると、切り替え時に何も起こらない状態になります。
