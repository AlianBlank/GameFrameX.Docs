# 如何設定本地化多語言(text 欄位)

在 Excel 的設定表格中，若將欄位類型宣告為 `text`,即可將該欄連接至 `TbLocalization` 多語言表格。執行時會依據 key 取得目前語言的實際文字，因此可在同一份設定下實現多語言切換。

## 前置條件

- 已安裝 .NET SDK(Luban 工具的執行依賴)。
- 儲存庫根目錄下存在 `Excels/Local/` 目錄。用於放置帶有 `L-` 前綴的多語言檔案。
- 能夠執行生成腳本(`gen-client-json.sh` / `gen-server-json.sh` 等)。生成後，`TbLocalization` 類別會輸出至 `Hotfix/Config/Generate` 或 `Server.Config/Config`。

## 操作步驟

1. **將欄位類型宣告為 `text`**。在任何業務表格(成就表格、道具表格等)的 `##type` 行中，將欄位類型記述為 `text` 而非 `string`。`text` 代表在該欄填入 key,執行時會於多語言表格中查詢實際文字。`string` 則會直接作為原文使用，不會被翻譯。

   例如：成就表格的 `name` 與 `achievement_content` 欄位皆使用 `text` 類型，僅填入 key:

   | ##var | id | image | name | achievement_content |
   |-------|----|-------|------|---------------------|
   | ##type | int | int | text | text |
   | ##group | | | | |
   | ## | ID | 圖示 id | 成就 Key | 成就內容 Key |
   | | 900001 | 101 | achievement_001 | achievement_001_desc |

   出處:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L227-L232)

2. **理解 `text` 與 `string` 的差異**。`text` 是需要本地化的多語言文字(填入 key),`string` 則是不會被翻譯的純文字(直接填寫內容)。若誤將需要翻譯的欄位記述為 `string`,執行時取得的會是原始字串，翻譯不會生效。

   出處:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L223)

3. **準備多語言 Excel 檔案**。儲存庫在 `Excels/Local/` 下提供了 3 個範例，它們全部會合併至同一個 `TbLocalization` 表格：

   | 多語言分類 | 檔案 | 內容 |
   |------------|------|------|
   | 多語言-成就 | `Excels/Local/L-Localization-成就.xlsx` | 成就文字 |
   | 多語言-文字 | `Excels/Local/L-Localization-文本.xlsx` | 通用文字 |
   | 多語言-UI | `Excels/Local/L-Localization-UI.xlsx` | UI 文字 |

   多個 `L-Localization-*.xlsx` 只要英文部分(`Localization`)一致，即會自動合併：

   ```
   L-Localization-成就.xlsx    ┐
   L-Localization-文本.xlsx    ├→ 合併為 1 個 TbLocalization
   L-Localization-UI.xlsx      ┘
   ```

   出處:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L199), [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L250-L254)

4. **依模組分割多語言表格(選用)**。當文字量增多時，可依成就、UI、文字等模組分割為多個 `L-Localization-XXX.xlsx`。只要將英文檔名前綴保持為 `L-Localization` 即可，中文部分可自由命名(工具不會解析)。

   出處:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L256)

5. **確認生成命令中已啟用 `localizationFileName`**。在 `luban.conf` 中，用戶端的 `client` target 命令包含 `"localizationFileName": "Localization.xlsx"`,若缺少此項目，將不會生成 `TbLocalization`。

   ```json
   {
     "localizationFileName": "Localization.xlsx",
     "command": "--target client --dataTarget json --codeTarget cs-simple-json ...",
     "target": "client",
     "active": true
   }
   ```

   出處:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

6. **執行生成腳本**。在 Windows 上雙擊 `gen-client-json.bat`,在 Mac/Linux 上執行 `sh gen-client-json.sh`。生成完成後，業務表格的 `text` 欄位會映射至 `TbLocalization`,執行時即可透過 key 取得目前語言的文字。

## 常見變化

- **依用戶端/伺服器分組**：在多語言檔案的英文檔名後加上 `c-` 或 `s-`(例如:`L-Localization-c-UI.xlsx`),即可僅供對應端取得。
- **新增自訂多語言檔案**：放置於 `Excels/Local/` 之下，只要英文檔名前綴為 `L-Localization`,即會自動整合至 `TbLocalization`。
- **依數量分割大型表格**：與一般表格相同，使用相同英文名稱 + 不同中文名稱(例如:`L-Localization-UI-1.xlsx`、`L-Localization-UI-2.xlsx`),工具便會自動合併。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| 執行時取得的文字是 key 的字面值 | `##type` 被記述為 `string` 而非 `text` | 將欄位類型改為 `text` |
| 找不到生成的 `TbLocalization` | `luban.conf` 的 `client` target 命令中缺少 `localizationFileName` | 依照上述步驟 5 加入至命令 JSON |
| 表格的英文檔名包含中文 | 工具不允許英文名稱包含中文，若包含會直接報錯 | 將 `L-本地化-成就.xlsx` 改為 `L-Localization-成就.xlsx` 之類的形式 |
| 文字未生效，僅顯示 key | `L-Localization-*.xlsx` 未放置於 `Excels/Local/` 目錄 | 將檔案移動至 `Excels/Local/` 並重新執行生成腳本 |

## 背景(選用)

`text` 欄位本質上是參照 `TbLocalization` 的 key,所有 `L-Localization-*.xlsx` 會合併至同一個多語言表格。`string` 會跳過翻譯，直接以原始字串使用。`localizationFileName` 是 `luban.conf` 中啟用用戶端多語言生成的開關。
