# 使用時間尺度：讓計時器受/不受 Time.timeScale 影響

每個計時器都可以獨立選擇時間尺度：`TimerTimeScale.Unscaled`（真實時間，預設）或 `TimerTimeScale.Scaled`（受 `UnityEngine.Time.timeScale` 影響）。只需在呼叫 `Add` 時透過 `timeScale` 參數指定即可。

## 前置條件

- 專案中已引入 GameFrameX Timer 套件，並已取得 `ITimerManager` / `TimerManager` 執行個體（如透過 `TimerComponent` 取得）。

## 時間尺度列舉速查

`TimerTimeScale` 是一個 `byte` 列舉，定義如下：

| 名稱 | 值 | 行為 |
|------|----|------|
| `Unscaled` | 0 | 不受 `Time.timeScale` 影響（預設值，與既有行為相容） |
| `Scaled` | 1 | 受 `Time.timeScale` 影響 |

```csharp
public enum TimerTimeScale : byte
{
    /// <summary>不受 <see cref="UnityEngine.Time.timeScale"/> 影響（預設，與現有行為相容）。</summary>
    Unscaled = 0,

    /// <summary>受 <see cref="UnityEngine.Time.timeScale"/> 影響。</summary>
    Scaled = 1,
}
```

Source: [TimerTimeScale.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerTimeScale.cs#L6-L13)

## 操作步驟

1. 確認 `Add` 的完整簽章，`timeScale` 是第 6 個參數且預設為 `Unscaled`：

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217)（介面宣告見 [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L22)）

2. 新增一個**不受** `Time.timeScale` 影響的計時器（例如 UI 倒數計時、斷線重連倒數計時）——不傳 `timeScale`，或明確傳入 `Unscaled`：

```csharp
// 預設即為 Unscaled：遊戲暫停（timeScale = 0）時該計時器仍會繼續計時
timer.Add(1000f, 0, callback);
```

3. 新增一個**受** `Time.timeScale` 影響的計時器（例如慢動作、暫停選單等場景下的遊戲邏輯計時）——明確傳入 `timeScale: TimerTimeScale.Scaled`：

```csharp
// 受 Time.timeScale 影響（適用於慢動作、暫停選單等場景）
timer.Add(1000f, 0, callback, timeScale: TimerTimeScale.Scaled);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L165-L167)

4. 組合其他參數使用（回呼參數、標籤、完成回呼均可與 `timeScale` 同時指定）：

```csharp
// 單元測試中的真實呼叫範例：1 秒間隔、重複 1 次、Scaled 模式
_timerManager.Add(1f, 1, _ => callCount++, timeScale: TimerTimeScale.Scaled);
```

## 常見變體

- **暫停選單**：把 `Time.timeScale` 設為 0，遊戲邏輯用 `Scaled` 計時器（隨之凍結），彈出視窗動畫/倒數計時用 `Unscaled` 計時器（繼續計時）。
- **慢動作**：把 `Time.timeScale` 設為 0.5，`Scaled` 計時器的實際計時速度也變為原來的一半；`Unscaled` 計時器不受影響。
- **同一管理器混用**：兩種模式可在同一個 `TimerManager` 中混用，更新迴圈會按每個計時器各自的模式選擇時間源：

```csharp
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L81)

## 常見錯誤

- **以為預設就受 timeScale 影響**：`Add` 的 `timeScale` 參數預設值是 `Unscaled`，不改 `Time.timeScale` 時兩種模式行為相同（`timeScale = 1`），但一旦暫停/慢放，未明確傳入 `Scaled` 的計時器不會變慢。需要跟隨遊戲時間時必須明確寫 `timeScale: TimerTimeScale.Scaled`。
- **`timeScale = 0` 後 Scaled 計時器「遺失」**：計時器並未被移除，只是每幀增量 delta 為 0；恢復 `Time.timeScale` 後它會繼續計時。
- **位置參數搞錯**：`timeScale` 排在 `callbackParam`、`tag` 之後、`onComplete` 之前；建議始終用具名參數 `timeScale: TimerTimeScale.Scaled` 避免錯置。

## 背景

`TimerManager` 的更新方法同時接收縮放時間與真實時間兩路增量，更新每個計時器時按其 `TimeScaleMode` 選擇：`Scaled` 用 `elapseSeconds`，`Unscaled` 用 `realElapseSeconds`，因此兩種模式互不干擾；計時器物件回收重複使用時 `TimeScaleMode` 會被重設為 `Unscaled`（見 [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L633)）。
