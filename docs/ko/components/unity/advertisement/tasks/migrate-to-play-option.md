# 레거시 Show/Load에서 Play(option)로 마이그레이션하는 방법

기존의 `Show(success, fail, onShowResult, customData)`와 `Load(success, fail, customData)`의 3개 인자 호출, 그리고 `Action<bool> onShowResult`만 전달하는 `Play` 호출을 `AdvertisementPlayOption`을 사용하는 `Play(AdvertisementPlayOption option)` 진입점으로 통합하여 교체하세요. 기존 메서드는 `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`로 표시되어 있으며, 컴파일 시 `CS0618` 경고가 발생하고 계속 사용할 경우 향후 버전에서 제거됩니다.

## 사전 조건

- `GameFrameX.Advertisement.Runtime` 네임스페이스를 가져왔고, `IAdvertisementManager` 또는 컴포넌트 `AdvertisementComponent`를 사용할 수 있어야 합니다.
- 현재 사용 중인 광고 채널의 `BaseAdvertisementManager` 서브클래스를 파악하세요. 새 API는 추상 메서드이므로 해당 채널 구현에서 재정의해야 합니다.

## 작업 단계

1. **새 `AdvertisementPlayOption` 인스턴스를 생성**하고, 매개변수에 흩어져 있던 성공/실패/표시 결과 콜백과 `customData`를 모두 해당 필드에 담습니다.

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   var option = new AdvertisementPlayOption
   {
       OnSuccess     = msg => Debug.Log($"성공:{msg}"),
       OnFail        = err => Debug.LogError($"실패:{err}"),
       OnShowResult  = watched => Debug.Log($"완전 시청 여부:{watched}"),
       customData    = "level=1",
   };
   ```

   출처: [AdvertisementPlayOption.cs#L36-L85](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L36-L85)

2. **`Play(option)`으로 기존 진입점을 교체**합니다. `AdvertisementComponent` 또는 `BaseAdvertisementManager`에서 호출하며, 시그니처는 완전히 일관됩니다:

   ```csharp
   GameFrameX.Advertisement.Runtime.AdvertisementComponent.Instance.Play(option);
   ```

   출처: [AdvertisementComponent.cs#L215-L219](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L215-L219)

   ```csharp
   public abstract void Play(AdvertisementPlayOption option);
   ```

   출처: [BaseAdvertisementManager.cs#L210-L211](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L210-L211)

3. **매핑 표에 따라 기존 필드를 `option`으로 옮기고**, 기존 코드에서 누락된 콜백이 없는지 확인하세요:

   | 기존 API 매개변수 / 필드 | 새 `AdvertisementPlayOption` 필드 |
   |--------------------|-----------------------------------|
   | `Show(success, fail, onShowResult, customData)`의 `success` | `OnSuccess`(`Action<string>`) |
   | `Show(...)`의 `fail` | `OnFail`(`Action<string>`) |
   | `Show(...)` / `Play(playResult, customData)`의 `onShowResult` / `playResult` | `OnShowResult`(`Action<bool>`) |
   | `Show(...)` / `Load(...)` / `Play(...)`의 `customData` | `customData`(`string`) |
   | 서버 측 보상 검증에 필요한 확장 데이터 | `extraData`(`Load` 단계에서만 투과적으로 전달되며, 로드 후 설정은 무효) |

4. **기존 호출 지점을 제거**합니다. 프로젝트에 여전히 `Show(success, fail, onShowResult)` 또는 `Load(success, fail)` 사용처가 있다면, 각각 `Play(option)`으로 교체하면 됩니다. 컴파일러가 `CS0618` 경고로 알려줍니다.

## 일반적인 변형

- **"완전 시청 여부"만 알고 싶은 경우**: `OnShowResult`만 채우고 다른 콜백은 `null`로 유지합니다.

  ```csharp
  var option = new AdvertisementPlayOption
  {
      OnShowResult = watched => GiveReward(watched),
  };
  ```

- **서버 측 보상 검증을 위해 확장 데이터를 전달해야 하는 경우**: `extraData`를 사용하며, 로드 단계에서만 유효하다는 점에 유의하세요.

  ```csharp
  option.extraData = "user_id=42";
  ```

- **커스텀 채널에서 `customData`가 필요한 경우**: `option.customData`에 직접 값을 할당하면 되며, 이는 기존同名 매개변수와 동일합니다.

## 일반적인 오류

- **`extraData`를 `customData`처럼 사용하는 경우**: `extraData`는 `Load` 단계에서만 서버 측 보상 검증으로 투과적으로 전달되며, 광고 재생 시에는 적용되지 않습니다. 비즈니스 콜백에는 `customData`를 사용하세요.
- **기존 `Show`/`Load`를 계속 사용하는 경우**: 이미 `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`가 붙어 있어 계속 사용하면 경고만 발생하지만, 향후 버전에서는 제거됩니다. 또한 기존 `Show` 내부에서 `#pragma warning disable CS0618`으로 전달하므로, 마이그레이션 후 함께 삭제할 수 있습니다.
- **`option` 필드를 할당하지 않고 `Play`를 호출하는 경우**: 특정 콜백(예: `OnFail`)이 비어 있으면 실패 시 상위 레이어에 알림이 가지 않아, 문제 진단 시 "광고가 트리거되지 않았다"고 잘못 판단하기 쉽습니다.
- **`Load` 이후에 `extraData`를 수정하는 경우**: 문서에 "로드 후 설정은 무효"라고 명시되어 있습니다. 서버 측에서 확장 정보를 검증해야 할 때는 반드시 `Play(option)` 호출 전에 설정해야 합니다.

## 배경(선택 사항)

마이그레이션 후, 모든 채널 관리자는 단일 추상 진입점 `Play(AdvertisementPlayOption option)`만 재정의하면 됩니다. 콜백과 확장 데이터가 한 곳에서 집중 관리되며, 기존 `Show`/`Load`/`Play(Action<bool>, string)`은 모두 사용되지 않는 메서드로 표시되어 컴포넌트 레이어에서 새 메서드로 전달됩니다. 이를 통해 API 표면은 수렴되고 호출자는 코드 변경 없이 마이그레이션할 수 있습니다.
