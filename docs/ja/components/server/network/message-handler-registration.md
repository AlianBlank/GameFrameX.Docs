# クライアントメッセージの登録と処理(MessageId / Handler)

本文では、GameFrameX.Server で `MessageId` を通じてクライアントから送信されたメッセージを登録し処理する方法を紹介します。`BaseMessageHandler` を継承したクラスを作成し、`[MessageMapping]` でリクエストメッセージの型を标注するだけで、フレームワーク起動時に自動的にスキャンされ、ディスパッチが完了します。

## 前提条件

- メッセージ処理クラスは必ず `GameFrameX.Hotfix` プロジェクト内で定義する必要があります（アーキテクチャアナライザが強制チェックを行い、違反した場合にはコンパイルエラー `GFX0006` が発生します）。
- クラスには `sealed` を付ける必要があります（違反した場合には `GFX0010` が報告されます）。また、型名は必ず `Handler` で終わる必要があります（違反した場合には `GFX0012` が報告されます）。
- `.proto` ファイルからリクエスト/レスポンスのメッセージ型（例：`ReqLogin`、`RespLogin`）が生成済みであり、対象のプロジェクトから参照可能であること。

## 操作手順

1. `GameFrameX.Hotfix` 配下にハンドラクラスを作成し、`BaseMessageHandler<Req, Resp>` を継承します。クラスには `[MessageMapping(typeof(Req))]` を付与し、処理対象のリクエスト型を指定します。

```csharp
// GameFrameX.Hotfix/Logic/Login/LoginHandler.cs
using GameFrameX.Net;
using GameFrameX.Hotfix;

[MessageMapping(typeof(ReqLogin))]
[MessageResponse(typeof(RespLogin))]
internal sealed class LoginHandler : BaseMessageHandler<ReqLogin, RespLogin>
{
    public override async Task<RespLogin> Handle(ReqLogin request, NetWorkChannel channel)
    {
        var resp = new RespLogin { Code = 0, Message = "ok" };
        return await Task.FromResult(resp);
    }
}
```

参考: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L130-L140)

2. フレームワーク起動後、`AppStartUpHotfixGameByMain` はメッセージパケットを受信した際に `HotfixManager` から対応する `Handler` を取得し、`MessageId` から解析されたリクエストオブジェクトをハンドラに渡します。

```csharp
// フレームワーク側のディスパッチ中核ロジック
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
if (handler == null)
{
    LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
    return;
}
await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
```

参考: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L130-L141)

3. ゲートウェイサービス（`AppStartUpHotfixGameByGateWay`）のディスパッチも同様に `HotfixManager.GetTcpHandler(message.MessageId)` を使用するため、クライアントからバックエンドへのメッセージ処理パスが一貫しています。

```csharp
var handler = HotfixManager.GetTcpHandler(message.MessageId);
if (handler == null)
{
    LogHelper.Error($"找不到[{message.MessageId}][{messageObject.GetType()}]对应的handler");
    return;
}
```

参考: [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L123-L128)

## よくあるバリエーション

- **プレイヤー単位のメッセージ**（特定のプレイヤー Actor に紐付け）：`[MessageMapping]` と `BaseMessageHandler` の継承を利用し、フレームワークが対応するプレイヤーの Mailbox へメッセージをルーティングします。
- **グローバル単位のメッセージ**（サーバー Actor に紐付け）：同じく `[MessageMapping]` を使用しますが、ハンドラ内ではハートビートなど、ステートレスな処理のみを行うことが一般的です。

```csharp
// プレイヤー単位（README.ja.md からのサンプル）
// Player-level message (bound to a specific player Actor)
[MessageMapping(typeof(ReqAddItem))]
internal sealed class AddItemHandler

// グローバル単位（README.ja.md からのサンプル）
// Global-level message (bound to the server Actor)
[MessageMapping(typeof(ReqHeartBeat))]
internal sealed class HeartBeatHandler
```

参考: [README.ja.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.ja.md#L362-L376)

- **RPC 双方向呼び出し**：リクエスト側とレスポンス側の双方に `[MessageRpcMapping]` を标注し、`MessageRpcMappingAssemblyAnalyzer` がコンパイル時に検証します。ハンドラは必ず `GameFrameX.Hotfix` 内に定義する必要があり、違反した場合には `GFX0007` が報告されます。

## よくあるエラー

| 症状 / エラーコード | 原因 | 修正方法 |
|---|---|---|
| 実行時ログ：`找不到[xxx][yyy]对应的handler` | `[MessageMapping]` がハンドラをスキャンできていない | クラスが `GameFrameX.Hotfix` にあり、`Handler` で終わっていることを確認し、再コンパイルする |
| コンパイルエラー `GFX0006` | ハンドラが `GameFrameX.Hotfix` 内にない | クラスファイルを `GameFrameX.Hotfix` プロジェクトに移動する |
| コンパイルエラー `GFX0007` | RPC ハンドラが `GameFrameX.Hotfix` 内にない | `[MessageRpcMapping]` ハンドラを `GameFrameX.Hotfix` に移動する |
| コンパイルエラー `GFX0010` | ハンドラに `sealed` が付与されていない | クラスに `sealed` を付ける |
| コンパイルエラー `GFX0012` | クラス名が `Handler` で終わっていない | クラス名を `XxxHandler` に変更する |

## 背景（任意）

`GameFrameX.Architecture.Analyzers` はコンパイル時に `MessageMappingAssemblyAnalyzer`、`MessageMappingNameAnalyzer`、`MessageMappingSealedAnalyzer`、`MessageRpcMappingAssemblyAnalyzer` の4つのアナライザを通じて、ハンドラの配置場所、命名規則、封印性（sealed）を強制チェックします。これにより、実行時に `HotfixManager.GetTcpHandler(MessageId)` が必ず対象を見つけられることを保証しています。
