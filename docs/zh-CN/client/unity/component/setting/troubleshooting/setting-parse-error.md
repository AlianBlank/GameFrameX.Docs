# 配置项解析异常怎么办

当 `GameFrameX.Setting` 在加载或读取配置时抛出异常、返回默认值或 `Load()` 返回 `false`，通常表示底层存储文件损坏、辅助器未设置或键名非法。本页按异常现象给出快速诊断与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | 未给 `SettingManager` 设置 `ISettingHelper`,或传入 `null` | 先实例化具体 Helper(默认 `DefaultSettingHelper` 或 `PlayerPrefsSettingHelper`),再调用 `SetSettingHelper` |
| `GameFrameworkException: Setting name is invalid.` | `settingName` 为 `null` 或空字符串 | 调用 `HasSetting / GetBool / GetInt / GetFloat / GetString` 等方法前确保 `settingName` 非空 |
| 启动日志出现 `Load settings failure with exception '{0}'.` | 配置文件 `GameFrameworkSetting.dat` 缺失、损坏或权限不足 | 删除损坏文件或恢复权限后重新初始化,见下方「修复步骤」 |
| 启动日志出现 `Save settings failure with exception '{0}'.` | 配置目录只读、磁盘满或路径无效 | 检查 `FilePath` 指向的可写性,重新指向 `Application.persistentDataPath` |
| 读取到的值始终是类型默认值(`false / 0 / 0f / null`) | 键名拼写错误或新版本未写入该键 | 用 `GetAllSettingNames()` 列出全部键核对,或先调用带 `defaultValue` 的重载 |

## 修复步骤

### 1. 辅助器未设置导致 `Setting helper is invalid`

`SettingManager` 在每次读写前都会调用 `EnsureSettingHelper()`,若 `m_SettingHelper` 为 `null` 即抛出该异常。

Source: [SettingManager.cs#L47-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L47-L61)

```csharp
private void EnsureSettingHelper()
{
    if (m_SettingHelper == null)
    {
        throw new GameFrameworkException("Setting helper is invalid.");
    }
}
```

修复方法:

1. 创建继承自 `SettingHelperBase` 的 Helper 实例(框架内置 `DefaultSettingHelper`、`PlayerPrefsSettingHelper`)。
2. 通过 `GameFrameworkEntry.GetModule<ISettingManager>().SetSettingHelper(helper)` 注入。
3. `SetSettingHelper(null)` 本身也会抛同一异常,确保传入非空。

Source: [SettingManager.cs#L126-L134](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L126-L134)

### 2. 配置文件解析失败(`Load settings failure`)

`DefaultSettingHelper.Load()` 用 try/catch 包裹反序列化流程,任何异常都被转为日志并返回 `false`,不会抛出,但配置项将回到空集。

Source: [DefaultSettingHelper.cs#L126-L146](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L126-L146)

```csharp
public override bool Load()
{
    try
    {
        if (!File.Exists(m_FilePath))
        {
            return true;
        }

        using (FileStream fileStream = new FileStream(m_FilePath, FileMode.Open, FileAccess.Read))
        {
            m_Serializer.Deserialize(fileStream);
            return true;
        }
    }
    catch (Exception exception)
    {
        Log.Warning("Load settings failure with exception '{0}'.", exception);
        return false;
    }
}
```

修复方法:

1. **文件不存在**:首启正常,无需处理;若业务上需要预置默认值,在 `Load()` 返回 `false` 后调用 `SetBool/SetInt/...` 回填。
2. **文件头不匹配**:`DefaultSettingSerializer` 的 `Header` 为 `{'G','F','S'}`,若文件被其它程序改动将解析失败,删除该 `GameFrameworkSetting.dat` 后重新启动。

Source: [DefaultSettingSerializer.cs#L41-L67](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingSerializer.cs#L41-L67)
3. **磁盘/权限问题**:确认 `FilePath`(由 `Application.persistentDataPath` 等派生)所在目录可读写;在 Windows / macOS 上检查是否被杀毒软件隔离。

### 3. 键名为空导致 `Setting name is invalid`

`HasSetting / RemoveSetting` 会在 `EnsureSettingName` 中校验。

Source: [SettingManager.cs#L55-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L55-L61)

```csharp
private void EnsureSettingName(string settingName)
{
    if (string.IsNullOrEmpty(settingName))
    {
        throw new GameFrameworkException("Setting name is invalid.");
    }
}
```

修复方法:从配置中心取键名时做 `string.IsNullOrEmpty` 校验,或使用 `GetString(name, defaultValue)` / `GetInt(name, defaultValue)` 等带默认值的重载避开空键异常。

### 4. 保存失败(`Save settings failure`)

`Save()` 同样以 try/catch 包裹,异常时返回 `false` 并打印 `Save settings failure with exception '{0}'.`。

Source: [DefaultSettingHelper.cs#L156-L170](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L156-L170)

修复方法:

1. 确认 `FilePath` 已初始化(Helper 通过 `SetFilePath` 或初始化时赋值)。
2. 检查目标目录写入权限;`FileMode.Create` 需要可写。
3. 捕获 `Log.Warning` 输出中的 `IOException`、`UnauthorizedAccessException` 等具体异常,据此处理。

## 验证

按以下顺序确认问题已解决:

1. `GameFrameworkEntry.GetModule<ISettingManager>().Load()` 返回 `true`,且启动日志不再有 `Load settings failure` / `Save settings failure`。
2. `GetAllSettingNames()` 返回的数组包含你期望的全部键;用 `HasSetting("your.key")` 检查具体键存在。
3. 写入一次配置(`SetInt("score", 100)` → `Save()`),退出重启后 `GetInt("score")` 仍能读到 100。
4. 用 `SetSettingHelper(null)`、传入空键名等用例确认异常路径按预期抛出 `GameFrameworkException`,不会被吞掉。
