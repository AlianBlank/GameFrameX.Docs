# How to Clear Cache and Manage Resource Package Lifecycle

This page explains how to clear cache files, unload resources, and manage the YooAssets resource package lifecycle (destroy, switch default package) in `GameFrameX.Asset`.

## Prerequisites

- YooAssets has been initialized through `AssetComponent`, with at least one `ResourcePackage` existing.
- The business side has obtained the `GameFramework.GetComponent<AssetComponent>()` instance.
- Understand the [default package name constants](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L170-L183) and package name parameter rules.

## Steps

### 1. Unload a single resource (decrement reference count)

Using the default package:

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAsset("Assets/Prefabs/Hero.prefab");
```

Specify the package name:

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAsset("pkg_battle", "Assets/Prefabs/Hero.prefab");
```

The underlying call is `package.TryUnloadUnusedAsset(assetPath)`. Source: [AssetManager.cs#L100-L124](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L100-L124)

### 2. Asynchronously unload unused resources (GC-friendly)

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadUnusedAssetsAsync();                // Default package
GameFramework.GetComponent<AssetComponent>()
    .UnloadUnusedAssetsAsync("pkg_battle");    // Specified package
```

Only resources with a reference count of 0 are reclaimed, suitable for calling when switching scenes. Source: [AssetManager.cs#L150-L163](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L150-L163)

### 3. Asynchronously force reclamation of all resources in the package

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAllAssetsAsync();
```

Ignores reference counts and forcibly releases all resources loaded by the package. Source: [AssetManager.cs#L127-L144](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L127-L144)

### 4. Clear unused Bundle cache files

```csharp
GameFramework.GetComponent<AssetComponent>()
    .ClearUnusedBundleFilesAsync();
```

Only deletes Bundle files not referenced by any resource; does not unload loaded resources. Source: [AssetManager.cs#L189-L201](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L189-L201)

### 5. Clear all Bundle cache in the package

```csharp
GameFramework.GetComponent<AssetComponent>()
    .ClearAllBundleFilesAsync();
```

First `UnloadAllAssetsAsync` then `ClearUnusedBundleFilesAsync`, completely releasing. Source: [AssetManager.cs#L165-L183](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L165-L183)

### 6. Switch the default resource package

```csharp
var pkg = YooAssets.GetPackage("pkg_main");
GameFramework.GetComponent<AssetComponent>()
    .SetDefaultAssetsPackage(pkg);
```

Subsequent load/unload operations without specifying `packageName` will apply to the new default package. Source: [IAssetManager.cs#L443-L444](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L443-L444)

## Common Variants

| Scenario | Recommended API | Description |
|----------|-----------------|-------------|
| Switch scenes, release previous scene resources | `UnloadUnusedAssetsAsync` | Only reclaims unreferenced resources, avoiding accidental release |
| Exit instance, release entire package | `UnloadAllAssetsAsync` + `ClearUnusedBundleFilesAsync` | Releases both memory and cache |
| Thoroughly clean up before reinstalling a package | `ClearAllBundleFilesAsync` | One line completes resource + cache cleanup |
| Release a single resource on demand | `UnloadAsset(path)` | Decrements reference count by 1 |

## Common Mistakes

- **`packageName` is null but package was not created**: Before calling unload/clear, you must `CreatePackage` and `Initialize` first, otherwise `YooAssets.GetPackage` returns `null`. The method has internal `null` checks so it won't throw, but the operation will silently fail.
- **`UnloadAsset` reference count not reaching zero**: Repeatedly loading the same resource will increment the count; a corresponding number of `UnloadAsset` calls is needed to actually release it.
- **Confusing "unload resource" with "clear cache"**: `UnloadUnusedAssetsAsync` only clears memory; disk Bundle files require `ClearUnusedBundleFilesAsync` or `ClearAllBundleFilesAsync`.
- **Accessing resource immediately after force reclamation**: `UnloadAllAssetsAsync` is an asynchronous operation. You need to `yield return` or wait until the callback completes before operating on the corresponding asset, otherwise you will get a destroyed object.

## Background (Optional)

All cleanup APIs in `AssetManager` are forwarded to the YooAssets `ResourcePackage` object: `UnloadAsset` goes through `TryUnloadUnusedAsset` (reference count), `UnloadUnusedAssetsAsync` and `UnloadAllAssetsAsync` release memory, `ClearUnusedBundleFilesAsync` deletes from disk. `ClearAllBundleFilesAsync` is a composite action—it clears both memory and cache.
