# 네트워크, 다운로드, Web 및 Protobuf 통신 사용 방법

GameFrameX는 `GameApp.Network` / `GameApp.Download` 정적 접근자를 통해 네트워크 및 다운로드 컴포넌트를 노출하며, Web 요청과 Protobuf 통신은 해당하는 동반 패키지에서 제공합니다. 아래에 네 개의 하위 시스템을 연동하는 최소 단계를 제시합니다.

## 사전 조건

| 하위 시스템 | 필수 매크로 / 패키지 | 역할 |
|--------|-------------|------|
| 네트워크 (Network) | `ENABLE_GAME_FRAME_X_NETWORK` + `GameFrameX.Network.Runtime` | TCP / UDP 장기 연결, Protobuf 프로토콜 기반 |
| 다운로드 (Download) | `ENABLE_GAME_FRAME_X_DOWNLOAD` + `GameFrameX.Download.Runtime` | HTTP/HTTPS 파일 다운로드, 진행률 콜백 |
| Web | `GameFrameX.Web.Runtime` | 일회성 HTTP 요청(REST / JSON) |
| Protobuf | `GameFrameX.ProtoBuf.Runtime` | 메시지 인코딩/디코딩, Network 내부에서 사용됨 |

> 이 네 개의 컴포넌트는 모두 GameEntry 시작 시 등록되며, `GameApp.Network`, `GameApp.Download` 등의 정적 속성을 통해 싱글톤을 가져올 수 있습니다.

## 작업 단계

### 1. 네트워크 컴포넌트 활성화

`GameApp.Network`를 직접 호출하면 싱글톤을 가져올 수 있으며, 프레임워크 내부에서는 `GameEntry.GetComponent<NetworkComponent>()`를 사용합니다.

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Runtime;

var network = GameApp.Network;
network.Connect("127.0.0.1", 7000);
#endif
```

소스: [Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L55)

### 2. 다운로드 컴포넌트 활성화

다운로드 컴포넌트도 마찬가지로 `GameApp.Download` 싱글톤을 통해 접근합니다:

```csharp
#if ENABLE_GAME_FRAME_X_DOWNLOAD
using GameFrameX.Runtime;

var downloader = GameApp.Download;
downloader.DownloadAsync(url, savePath, (success, error) =>
{
    if (success) UnityEngine.Debug.Log("下载完成");
    else UnityEngine.Debug.LogError(error);
});
#endif
```

소스: [Runtime/GameApp.Download.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Download.cs#L32-L55)

### 3. Web 요청 보내기

Web 모듈은 일회성 HTTP 호출(JSON, 폼 등)에 사용되며, 장기 연결 Network와 서로 충돌하지 않습니다:

```csharp
using GameFrameX.Web.Runtime;

WebComponent web = GameEntry.GetComponent<WebComponent>();
web.Post("https://api.example.com/login", "{\"user\":\"x\"}",
    (statusCode, body) => UnityEngine.Debug.Log($"{statusCode} -> {body}"));
```

### 4. Protobuf로 메시지 직렬화

Network 내부에서 이미 Protobuf를 사용하고 있습니다. 사용자 정의 메시지를 만들 때 동일한 ProtoBuf 컴포넌트를 재사용합니다:

```csharp
using GameFrameX.ProtoBuf.Runtime;

byte[] bytes = ProtoBufComponent.Serialize(myMessage);
var restored = ProtoBufComponent.Deserialize<MyMessage>(bytes);
```

### 5. 종료 및 재연결

```csharp
GameApp.Network.Close();
GameApp.Network.Connect("127.0.0.1", 7000); // 연결을 다시 설정
```

## 일반적인 변형

- **다중 채널 장기 연결**: `NetworkComponent`는 여러 `NetworkChannel`을 지원하며, 각 channel마다 독립적인 하트비트 / 독립적인 인코딩·디코딩을 사용합니다.
- **이어받기**: `DownloadAsync` 콜백에서 이미 다운로드한 바이트를 저장하고, 시작 시 `Range` 헤더를 통해 이어서 다운로드합니다.
- **Protobuf 외의 프로토콜**: 새 `NetworkChannel`을 만들 때 사용자 정의 `INetworkChannelHelper`를 전달하면 JSON / MessagePack으로 교체할 수 있습니다.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GameApp.Network`가 `null` 반환 | `ENABLE_GAME_FRAME_X_NETWORK` 매크로가 정의되지 않음 | `Project Settings → Scripting Define Symbols`에 추가하고 `GameFrameX.Network` 패키지 설치 |
| 다운로드 콜백에서 `success=false`인데 `error` 텍스트가 없음 | URL이 잘못되었거나 디스크에 쓰기 권한이 없음 | `url`과 `savePath`를 확인하고 Application.persistentDataPath가 쓰기 가능한지 확인 |
| Web 요청이 0 상태 코드를 반환 | 대상 도메인이 Unity에서 허용되지 않음 | Player Settings → Other Settings → Allow downloads over HTTP 확인 |
| Protobuf 직렬화 시 예외 발생 | 메시지 클래스에 `[ProtoContract]` / `[ProtoMember]` 특성이 없음 | 메시지 필드에 특성을 추가하거나 protobuf-net의 `ImplicitFields = ImplicitFields.AllPublic` 사용 |

## 배경(선택 사항)

`GameApp`는 `partial class`이며, 각 하위 시스템이 별도의 파일로 구성되어 있고, 모두 `GameEntry.GetComponent<T>()`를 통해 지연 로딩되어 private 정적 필드에 캐시됩니다. 이를 통해 곳곳에 `GetComponent` 호출을 작성하지 않아도 되고, 매크로 단위로 불필요한 하위 시스템을 제거하기 쉬워져 배포 패키지 크기를 줄일 수 있습니다.
