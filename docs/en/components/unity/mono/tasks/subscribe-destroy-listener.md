# How to Listen for OnDestroy

Register a callback via `MonoComponent.AddDestroyListener(Action)`, and you will be notified when the `GameObject` to which `MonoComponent` is attached is destroyed, without needing to inherit `MonoBehaviour` and override `OnDestroy()` yourself.

## Prerequisites

- A `GameObject` with `MonoComponent` attached must exist in the scene (component menu: `GameFrameX/Mono`).
- The framework has initialized `IMonoManager` and `EventComponent` (both are automatically obtained by `MonoComponent.Awake()` / `Start()`).

## Steps

1. Hold a reference to `MonoComponent` in the script that needs to listen for destruction (via `GetComponent` or `FindObjectOfType`).
2. Call `AddDestroyListener`, passing in a parameterless `Action` delegate.
3. When the `GameObject` carrying the component is destroyed, `MonoComponent.OnDestroy()` will call `_monoManager.OnDestroy()`, which in turn triggers your registered callback.

```csharp
using System;
using GameFrameX.Mono.Runtime;
using UnityEngine;

public class DestroyWatcher : MonoBehaviour
{
    private MonoComponent _monoComponent;

    private void Awake()
    {
        _monoComponent = GetComponent<MonoComponent>();
    }

    private void OnEnable()
    {
        if (_monoComponent != null)
        {
            _monoComponent.AddDestroyListener(OnMonoDestroyed);
        }
    }

    private void OnDisable()
    {
        if (_monoComponent != null)
        {
            _monoComponent.RemoveDestroyListener(OnMonoDestroyed);
        }
    }

    private void OnMonoDestroyed()
    {
        Debug.Log("MonoComponent was destroyed");
    }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L97-L105)

The corresponding method for removing the listener:

```csharp
public void RemoveDestroyListener(Action fun)
```

Pass in the **same delegate instance** used during registration to unbind; passing in `null` will log a `fun is invalid.` fatal log and return directly.

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L111-L121)

## Common Variations

- **Manual `Destroy(gameObject)`**: As long as the `GameObject` carrying `MonoComponent` is destroyed, the callback will be triggered — it doesn't matter whether it's a `Destroy` call or a scene unload.
- **Scene switch unload**: When a scene switch causes `MonoComponent` to be destroyed, the same callback will be triggered, which can be used to clean up cross-scene caches.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `fun is invalid.` is printed on registration | The passed-in `Action` is `null` | Pass in a method group or lambda to ensure it is not null |
| Callback not triggered on destruction | `_monoManager` is `null` (component `Awake` runs before the manager is ready) | Confirm that `MonoComponent` is initialized through the normal process and has not had its `Awake` disabled |
| The same callback is triggered multiple times | `AddDestroyListener` was called multiple times to register the same delegate | Use `OnEnable`/`OnDisable` pairing to manage lifecycle, or remove before re-registering |

## Background (Optional)

`MonoComponent.OnDestroy()` is a Unity native lifecycle hook. The framework delegates the destroy event to `IMonoManager` here, so the business side can subscribe to destruction like subscribing to a regular event, rather than each class inheriting `MonoBehaviour` individually.
