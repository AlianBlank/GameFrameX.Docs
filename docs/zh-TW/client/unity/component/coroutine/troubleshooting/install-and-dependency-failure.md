# 安裝與相依性解析失敗怎麼辦

當你在 Unity 中透過 Package Manager 或 `manifest.json` 引入 `com.gameframex.unity.coroutine` 時，遇到相依性錯誤、版本衝突、找不到套件等情況，可按本頁診斷表對照修復。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `Package 'com.gameframex.unity.coroutine' could not be found` 或找不到對應版本 | `manifest.json` 沒設定 `scopedRegistries`,Unity 預設只會在 npm registry 查找 `com.gameframex.*` 開頭的套件 | 在 `manifest.json` 頂部新增 `scopedRegistries` 並指定 GameFrameX 來源，見下文修復步驟 1 |
| 報錯 `Unable to resolve dependency 'com.gameframex.unity: 2.5.1'` | 缺少執行階段相依性 `com.gameframex.unity`,或版本與已安裝的其他 GameFrameX 套件不一致 | 先單獨升級或降級到套件要求的 `com.gameframex.unity` 版本(見 `package.json` 中的相依性) |
| Unity 報 `Requires Unity 2019.4 or higher` | 目前專案的 Unity 版本低於套件要求的最低版本 | 升級 Unity 到 2019.4 或更高，或使用與之相符的舊版本套件 |
| 套件已下載但編譯報 `The type or namespace 'GameFrameX' could not be found` | Unity 快取未重新整理、相依性未真正寫入 `Library/PackageCache` | 刪除 `Library/PackageCache` 與 `Packages/packages-lock.json` 後重新啟動 Unity |
| 用 Git URL 安裝時報 `Could not read Username for 'https://github.com'` | 網路無法存取 GitHub,或私有儲存庫身分驗證失敗 | 改用 UPM scoped registry 方式，或為本儲存庫設定 SSH/HTTPS 憑證 |
| 套件匯入成功但 `CoroutineComponent` 報 `[DisallowMultipleComponent]` 衝突 | 同一 GameObject 已經掛載過 `CoroutineComponent` | 刪除多餘的同類型元件，只保留一個 |

## 修復步驟

### 1. 設定 scopedRegistries(GameFrameX 官方來源)

開啟專案根目錄下的 `Packages/manifest.json`,確認存在 `scopedRegistries` 區段。下面的範例來自儲存庫 README 的安裝說明：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.coroutine": "1.0.3"
  }
}
```

Source: [README.zh-CN.md#快速开始](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L40-L77)

要點：
- `scopes` 必須寫 `com.gameframex`,否則 `com.gameframex.*` 套件不會被該來源解析，Unity 會退回 npm 預設來源，直接報「找不到套件」。
- `url` 是 UPM 註冊表位址，不是一般網頁；如果你的網路無法存取，請繼續看下文「用 Git URL 替代方案」。

### 2. 檢查執行階段相依性 `com.gameframex.unity`

`com.gameframex.unity.coroutine` 本身相依於 `com.gameframex.unity`,儲存庫 [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L22-L24) 中宣告：

```json
"dependencies": {
  "com.gameframex.unity": "2.5.1"
}
```

如果專案中已明確宣告了更低版本的 `com.gameframex.unity`,Unity 會拒絕解析。處理方式：
- 升級 `com.gameframex.unity` 到 `2.5.1` 或與之相容的更高版本；或
- 刪除明確宣告，讓 `com.gameframex.unity.coroutine` 自動帶上正確版本。

### 3. Unity 版本必須 ≥ 2019.4

`package.json` 中 `unity` 欄位為 `2019.4`:

```json
"version": "1.2.0",
"unity": "2019.4",
```

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L6-L7)

低於 2019.4 的專案在 Package Manager 中會直接顯示「Requires Unity 2019.4 or higher」,必須先升級 Unity 編輯器。

### 4. 必要時清除快取並重新啟動

當套件明明已宣告卻編譯報錯、命名空間缺失時，先做這一步：
1. 關閉 Unity。
2. 刪除專案目錄下的 `Library/PackageCache` 資料夾。
3. 刪除 `Packages/packages-lock.json`。
4. 重新開啟 Unity,讓它按 `manifest.json` 重新拉取。

### 5. 替代安裝方式(用於 GitHub 無法連線時)

- 在 `manifest.json` 的 `dependencies` 下直接寫 Git URL:

```json
{
  "dependencies": {
    "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L70-L75)

- 或在 Unity 的 `Package Manager` → `Add package from git URL…` 中貼上 `https://github.com/gameframex/com.gameframex.unity.coroutine.git`。
- 或將儲存庫下載後直接放到專案 `Packages/` 目錄下。

## 驗證

修復後用下面任一方式確認：

1. 查看 Unity Console:不再出現「could not be found / Unable to resolve dependency」這類錯誤。
2. 在 Inspector 中 `Add Component` 能搜尋到 `Coroutine Component`,並能成功新增到 GameObject。
3. 用最小程式碼片段驗證命名空間可用：

```csharp
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(yourEnumerator);
```
