# 开启网络日志与使用 Inspector 面板

通过 Unity 菜单 `GameFrameX/Scripting Define Symbols` 开启发送/接收日志宏,即可让网络组件在控制台打印每条收发消息的 ID、类型与 JSON 内容;同时在 Play 模式下选中挂载 `NetworkComponent` 的物体,可在 Inspector 面板实时查看每个网络通道的连接状态、收发包数、心跳进度,并支持一键断开连接。

## 前置条件

- 项目已安装 GameFrameX Network 包,场景中已挂载 `NetworkComponent`。
- 日志通过 `Log.Debug` 输出,需确保 GameFrameX 日志组件的 Debug 级别日志处于开启状态,否则控制台看不到内容。

## 操作步骤

### 一、开启/关闭网络日志

1. 在 Unity 顶部菜单栏找到 `GameFrameX/Scripting Define Symbols` 分组。
2. 按需点击以下菜单项(点击后对应宏会写入 Player Settings 的 Scripting Define Symbols,Unity 会自动重新编译):

| 菜单项 | 作用 | 对应宏 |
|------|------|--------|
| `Enable Network Send Logs(开启网络发送日志打印)` | 打印发送的消息 | `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Disable Network Send Logs(关闭网络发送日志打印)` | 关闭发送日志 | 移除 `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Enable Network Receive Logs(开启网络接收日志打印)` | 打印接收的消息 | `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |
| `Disable Network Receive Logs(关闭网络接收日志打印)` | 关闭接收日志 | 移除 `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |

菜单实现来自 [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L67-L98),宏常量定义如下:

```csharp
public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG";
public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG";
public const string ForceEnableNetworkSendLogScriptingDefineSymbol = "FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET";
```

Source: [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L40-L44)

3. 开启后运行游戏,控制台将输出形如 `发送消息 ID:[10001,0,xxxReq] 消息内容:{...}` 与 `收到消息 ID:[...] 消息内容:{...}` 的日志。实际打印逻辑为:

```csharp
protected void DebugSendLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG
    var messageId = ProtoMessageIdHandler.GetReqMessageIdByType(messageObject.GetType());
    if (!IgnoreSendIds.Contains(messageId))
    {
        Log.Debug($"发送消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}

protected void DebugReceiveLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG
    var messageId = ProtoMessageIdHandler.GetRespMessageIdByType(messageObject.GetType());
    if (!IgnoreReceiveIds.Contains(messageId))
    {
        Log.Debug($"收到消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}
```

Source: [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L949-L969)

### 二、配置忽略打印的消息 ID

高频消息(如心跳)会刷屏,可在 Inspector 中把它们排除在日志之外:

1. 在场景中选中挂载 `NetworkComponent` 的物体。
2. 在 Inspector 面板找到以下两个字段(**仅非 Play 模式可编辑**):
   - `Ignore Log Printing For Sent Message IDs`:发送侧忽略的消息 ID 列表。
   - `Ignore Log Printing Of Received Message IDs`:接收侧忽略的消息 ID 列表。
3. 填入不想打印的消息 ID,进入 Play 模式即生效;命中列表的消息不会执行上面的 `Log.Debug`。

若需在代码中动态设置,通道基类提供了公开方法:

```csharp
public void SetIgnoreLogNetworkIds(List<int> sendIds, List<int> receiveIds)
{
    IgnoreSendIds = sendIds;
    IgnoreReceiveIds = receiveIds;
}
```

Source: [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L977-L982)

### 三、使用 Inspector 面板查看运行时状态

1. 进入 Play 模式,并在 Hierarchy 中选中场景里的 `NetworkComponent` 物体。
2. Inspector 顶部会显示 `Network Channel Count`,随后每个网络通道一个分组,包含:

| 面板字段 | 含义 |
|------|------|
| 通道名 + `Connected`/`Disconnected` | 通道名称与连接状态 |
| `Address Family` | 地址族(IPv4/IPv6 等) |
| `Local Address` / `Remote Address` | 本地/远端套接字地址,未连接时显示 `Unavailable` |
| `Send Packet` | `已发送包数 / 待发送包数` |
| `Miss Heart Beat Count` | 丢失心跳次数 |
| `Heart Beat` | `已流逝时间 / 心跳间隔`(秒,两位小数) |
| `Disconnect` 按钮 | 断开该通道 |

面板绘制核心代码如下,`Disconnect` 按钮内部调用 `Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError)`:

```csharp
EditorGUILayout.LabelField(networkChannel.Name, networkChannel.Connected ? "Connected" : "Disconnected");
EditorGUILayout.LabelField("Address Family", networkChannel.AddressFamily.ToString());
EditorGUILayout.LabelField("Send Packet", Utility.Text.Format("{0} / {1}", networkChannel.SendPacketCount, networkChannel.SentPacketCount));
EditorGUILayout.LabelField("Miss Heart Beat Count", networkChannel.MissHeartBeatCount.ToString());
EditorGUILayout.LabelField("Heart Beat", Utility.Text.Format("{0:F2} / {1:F2}", networkChannel.HeartBeatElapseSeconds, networkChannel.HeartBeatInterval));
EditorGUI.BeginDisabledGroup(!networkChannel.Connected);
{
    if (GUILayout.Button("Disconnect"))
    {
        networkChannel.Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError);
    }
}
```

Source: [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L95-L123)

此外,非 Play 模式下 Inspector 还可编辑两项运行配置:`RPC Timeout Time In Milliseconds`(滑条范围 3000–50000 毫秒)与 `Focus Send Heartbeat`。非 Play 模式下面板只显示配置区,并提示 `Available during runtime only.`,运行时状态区不渲染。

## 常见变体

- **强制 WebSocket 通道**:同一菜单分组下还有 `Enable Force WebSocket(开启强制使用WebSocket网络)` / `Disable Force WebSocket(关闭强制使用WebSocket网络)`,控制宏 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET`,用于强制网络走 WebSocket。
- **只想排查单向流量**:只开 `Enable Network Receive Logs`、关闭 Send,配合接收忽略列表过滤心跳,可以只看服务器下行消息。

## 常见错误

- **开启宏后没有任何日志**:日志级别是 `Log.Debug`,若 GameFrameX 日志组件屏蔽了 Debug 级别,或消息 ID 命中了忽略列表(`IgnoreSendIds`/`IgnoreReceiveIds`),都不会输出。
- **Inspector 里改不了字段**:`RPC Timeout`、`Focus Heartbeat`、两个忽略列表在 Play 模式下被禁用(`EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode)`),需退出 Play 模式后再改。
- **面板看不到通道状态**:运行时状态只在 Play 模式且物体位于场景 Hierarchy 中时绘制;非 Play 模式或选中的是 Prefab 资产时只显示提示信息。
- **宏未生效/编译报错**:宏写入后 Unity 会触发重编译,若日志仍未打印,检查 `Project Settings > Player > Scripting Define Symbols` 中宏是否确实存在(菜单只是对它做增删)。

## 背景

日志开关使用条件编译(`#if`)而非运行时布尔开关,是为了在关闭日志时零开销——整段 `Log.Debug` 与 JSON 序列化都不会进入构建产物。Inspector 由 `[CustomEditor(typeof(NetworkComponent))]` 的 `NetworkComponentInspector` 提供,并每帧调用 `Repaint()` 刷新运行时数据,因此在 Play 模式下数据是持续更新的。
