# ログ「Mono manager is invalid.」が表示された場合の対処法

`MonoComponent.Awake()` が `GameFrameworkEntry.GetModule<IMonoManager>()` で登録済みの `IMonoManager` 実装を取得できない場合、即座に `Log.Fatal("Mono manager is invalid.")` を呼び出してその後の初期化を中断するため、すべての Update/FixedUpdate/LateUpdate は実行されなくなります。

## 迅速な診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| コンソールログ:`Mono manager is invalid.` | `MonoManager` モジュールが `GameFrameworkEntry` にまだ登録されていない | `GameEntry` / 起動フローで `MonoComponent` より先に `GameFrameworkEntry.RegisterModule(new MonoManager())` を呼び出す |
| 同上。シーンに `MonoComponent` しかアタッチされておらず、`GameFrameworkEntry` のブートストラップがない | 起動順序の誤り：`MonoComponent` が `GameFrameworkEntry` の初期化より先に `Awake` されている | スクリプトの実行順序を調整し、`GameFrameworkEntry` の登録が先に完了するようにする |
| 同上。その後「Event manager is invalid.」も続けて表示される | `EventComponent` もアタッチされていない | `GameEntry` に `EventComponent` を追加する。[`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76) を参照 |

## 修正手順

### 1. 起動時に `MonoManager` モジュールを登録する

`MonoComponent` は「すでに存在するマネージャーを呼び出す」役割のみを担い、モジュールを実際に作成して登録する責任は起動フローにあります。フレームワークのエントリポイントで明示的に呼び出す必要があります。

```csharp
using GameFrameX.Mono.Runtime;
using GameFrameX.Runtime;

// GameFrameworkEntry の初期化段階（任意の MonoComponent.Awake より前）
GameFrameworkEntry.RegisterModule(new MonoManager());
```

登録ロジックは `IMonoManager` 実装のみを受け付け、`MonoManager` はフレームワークに付属のデフォルト実装です（[`MonoManager.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L42-L43)）。

### 2. `MonoComponent` の Awake が `GameFrameworkEntry` より遅くなるようにする

`MonoComponent` は `Awake` 内で `GameFrameworkEntry.GetModule<IMonoManager>()` からモジュールを取得します（[`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L57-L62)）。`MonoComponent` が `GameFrameworkEntry` のブートストラップスクリプトより早く `Awake` される GameObject にアタッチされていると、`GetModule` は `null` を返します。

修正方法：
1. `MonoComponent` を独立した GameObject にアタッチし、`GameFrameworkEntry` のエントリコンポーネントが先に `Awake` されるようにする。
2. Unity の `Project Settings → Script Execution Order` で `MonoComponent` を起動コンポーネントより後に配置する。

### 3. `MonoComponent` を無効化したり名前を変更したりしない

- クラスには `[DisallowMultipleComponent]` と `[AddComponentMenu("GameFrameX/Mono")]` が付与されています（[`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L42-L43)）。重複してアタッチしたり継承チェーンの名前を変更したりすると、基底クラスの `Awake` 動作に異常が発生し、モジュールの取得に失敗します。

## 検証

1. ゲームを起動し、コンソールに `Mono manager is invalid.` が表示されず、通常の Mono イベントフローが動作していることを確認する。
2. `IMonoManager.AddUpdate(...)` で登録したコールバックが毎フレーム呼び出されることを確認する：

```csharp
var mono = GameFrameworkEntry.GetModule<IMonoManager>();
mono.AddUpdate((dt, udt) => { /* 毎フレーム実行 */ });
```

3. それでも `MonoComponent.Start()` で `Event manager is invalid.` が出る場合は、`EventComponent` がアタッチされていないことを意味します。`MonoComponent.Start` のチェックパスに従って補完してください（[`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76)）。
