# "Localization manager is invalid / Base component is invalid" への対処法

この 2 つの Fatal ログは、それぞれ `LocalizationComponent` の `Awake()` と `Start()` から出力されます。`Awake()` 内で `GameFrameworkEntry.GetModule<ILocalizationManager>()` によってローカライズマネージャーモジュールを取得できない場合、または `Start()` 内で `GameEntry.GetComponent<BaseComponent>()` で Base コンポーネントが見つからない場合に出力され、その直後にコンポーネントはそのまま `return` するため、ローカライズ機能は動作しなくなります。大多数のケースは「ローカライズ実装アセンブリがパッケージと共にコンパイルされていない/クロップで除外されている」か「シーン内に GameFrameX の基本コンポーネントが不足している」ことが原因のため、下記の診断表に従って順番に切り分けていけば復旧できます。

## 修正手順

### 手順 1:実装アセンブリの存在確認

`LocalizationComponent.Awake()` では、インターフェース型を指定してモジュールを取得しています:

```csharp
m_LocalizationManager = GameFrameworkEntry.GetModule<ILocalizationManager>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L216)

`GetModule` が null を返す場合、`ILocalizationManager` の具象実装クラス(`LocalizationManager`)が `GameFrameworkEntry` に登録されていないことを意味します。多くの場合、その実装アセンブリがコンパイルに含まれていないことが原因です。以下を順番に確認してください:

1. Unity Console を開き、まずすべての**コンパイルエラー(Compiler Error)**を解消してください。コンパイルエラーが存在すると、Unity は一部のアセンブリのコンパイルをスキップし、それに伴ってモジュール登録も失われます。これが最もよく見られる原因です。
2. 本パッケージの `Runtime` ディレクトリ配下のランタイム asmdef(`GameFrameX.Localization`)がインポート済みで、かつ削除されていないことを確認してください。本パッケージのコンポーネントは `[RequireComponent(typeof(GameFrameXLocalizationCroppingHelper))]` として宣言されており、Inspector に Missing Script が表示される場合は、ランタイムアセンブリが欠落しているか、コンパイルに失敗していることを示します。
3. プロジェクトで GameFrameX のコンポーネントクロップ/モジュール削除の仕組みを有効にしている場合は、ローカライズモジュールが除外されていないことを確認してください。

### 手順 2:BaseComponent の補完

`Base component is invalid.` の判定は、`Start()` 内の次の検索に基づきます:

```csharp
BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227)

1. シーン内で `LocalizationComponent` をアタッチしているのと同じ GameFrameX ルートオブジェクト上に、`BaseComponent`(`EventComponent`、`SettingComponent` も `Start()` が同様に依存しています)が存在することを確認してください。
2. Inspector に "Missing (Mono Script)" と表示される場合は、対応するスクリプトがコンパイルされていないか、アセンブリが欠落していることを意味します。手順 1 に戻ってコンパイルエラーを解消してください。
3. これらのコンポーネントを複数のオブジェクトに分散して手動でアタッチしないでください。`GameEntry.GetComponent<T>()` は、それらがフレームワークのエントリ上に存在することを前提としています。

### 手順 3:ローカライズ Helper の確認

`Start()` ではその後、シリアライズされたフィールドに基づいて Helper を作成し、失敗した場合に `Can not create localization helper.` を出力します:

```csharp
LocalizationHelperBase localizationHelper = Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper);
if (localizationHelper == null)
{
    Log.Fatal("Can not create localization helper.");
    return;
}
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L254)

`LocalizationComponent` の Inspector で `m_LocalizationHelperTypeName` を確認してください。デフォルト値は完全な型名です:

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73)

カスタム Helper を使用する場合は、`m_CustomLocalizationHelper` フィールドに参照をドラッグして設定するか、`m_LocalizationHelperTypeName` を「名前空間.クラス名, アセンブリ名」という形式の完全に解決可能な型名にしてください。

## 検証

1. Play モードに再入し、Console に `Localization manager is invalid.`、`Base component is invalid.` などの上記の Fatal ログが表示されなくなることを確認します。
2. `Start()` が最後まで正常に実行されると、言語が初期化されます。エディター以外のモードでは、`Language == UnknownLocalization` の場合に自動的に `SystemLanguage` が採用され、最終的に `DefaultLanguage` が設定されます(参照:[LocalizationComponent.cs 261-272 行目](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L272))。`LocalizationComponent.Language`、`DefaultLanguage`、`DictionaryCount` を使って、コンポーネントが利用可能になったことを確認できます。
3. 文字列取得系の API(`GetLocalizedString`/`GetRawString` など)を一度呼び出し、空ではなく文字列が返ってくれば、一連の処理全体が正常に初期化されたことが確認できます。
