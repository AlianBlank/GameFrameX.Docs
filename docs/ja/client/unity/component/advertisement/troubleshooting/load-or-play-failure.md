# 広告の読み込みまたは再生に失敗した場合の対処法

`Play(...)` または `Load(...)` が失敗コールバックをトリガーした場合、通常は設定の欠落、広告枠 ID の未入力、SDK が初期化されていない、またはコールバックがバインドされていないことが原因です。以下では、症状ごとに原因を照らし合わせ、特定後に手順に従って修正してください。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `Play` が直接 `OnFail` に入り、ログに広告イベントがない | `Initialize` が呼び出されていない、または `m_config` が null | `Start` の前に `AdvertisementComponent` に `AdvertisementConfig` を注入するか、Inspector で設定アセットをチェックする |
| `Log.Fatal("Advertisement manager is invalid.")` | フレームワークに広告マネージャーの実装が登録されていない | `BaseAdvertisementManager` のサブクラスで `AdvertisementConfigAttribute` を使って登録し、シーン起動チェーンに配置する |
| 読み込み/再生時にコールバックが発生しない | `AdvertisementPlayOption.OnSuccess/OnFail/OnShowResult` が未代入 | `Play` の呼び出し前に `AdvertisementPlayOption` の 3 つの Action すべてに値を代入する |
| iOS/Android/ミニゲームで空の設定が読み込まれる | 現在のプラットフォームに対応する広告枠 ID フィールドが空 | `m_adUnitIdAndroid`、`m_adUnitIdiOS`、ミニゲーム三択(`WeChat` / `DouYin` / `KuaiShou`)の対応するフィールドを入力する |
| `Play` でエラーが出るが `OnShowResult` が false を返す | 表示フローは成功したが、SDK が完全再生とマークしなかった | 広告枠の審査状態と素材が拒否されていないか確認する(「広告枠審査が拒否されました」セクションを参照) |
| `Load` の非推奨警告 | 旧 API を使用している | `Play(AdvertisementPlayOption)` を使用し、`Load(success, fail)` は使用しない |

## 修正手順

### 1. 広告マネージャーが登録されていることを確認する

`AdvertisementComponent.Awake()` はリフレクションによって `IAdvertisementManager` の実装を取得しますが、取得できない場合は直接 `Log.Fatal` を出力します。以下を確認してください:

- カスタムマネージャークラスに `[AdvertisementConfigAttribute]` が付いており、`BaseAdvertisementManager` を継承している
- そのクラスがプロジェクト内で実際にランタイムアセンブリにコンパイルされている
- シーンに `AdvertisementComponent` が存在し、`componentType` フィールドがカスタムマネージャーを指している

参考実装場所:[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L87-L118)

### 2. AdvertisementConfig を注入する

`Start()` は `m_config != null` の場合にのみ `_advertisementManager.Initialize(m_config)` を呼び出します。Inspector で広告設定アセットを `m_config` フィールドにドラッグするか、コードで明示的に初期化してください:

```csharp
var component = GameEntry.GetComponent<AdvertisementComponent>();
component.Initialize(myAdvertisementConfig);
```

出典: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L140)

### 3. 現在のプラットフォームの広告枠 ID を入力する

`AdUnitId` はプラットフォームのコンパイルディレクティブによって値を取得し、いずれかの分岐が空の場合、SDK が有効な ID を取得できません。よくある漏れ:

- Android チャンネルに iOS の ID のみ入力した
- WebGL で汎用 ID を選択したが、`ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` マクロを有効にしており、ミニゲーム専用枠が未入力

Inspector で `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` の少なくとも 1 つに値があることをご確認ください。

出典: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57)

### 4. 再生コールバックを補完する

`AdvertisementPlayOption` の 3 つの Action のいずれかでも未代入の場合、対応するコールバックはトリガーされません:

```csharp
var option = new AdvertisementPlayOption
{
    OnSuccess = json => Debug.Log($"報酬付与成功: {json}"),
    OnFail    = err  => Debug.LogError($"再生失敗: {err}"),
    OnShowResult = shown => Debug.Log($"完全表示: {shown}"),
    customData = "level=1",
};
component.Play(option);
```

`extraData` は Load 段階でのみサーバーにシリアライズされて渡されるため、読み込み完了後に変更しても反映されません。

出典: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L84)

### 5. 非推奨の Load は使用しない

`BaseAdvertisementManager.Load(Action<string>, Action<string>, string)` は `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]` とマークされており、使用し続けると警告が発生するだけで新しいフローに自動的に橋渡しされません。`Play(AdvertisementPlayOption)` を統一して使用してください。

出典: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L236-L238)

### 6. デバッグモードでトラブルシューティングする

`m_debug = true` を有効にする(または `Initialize` の 2 番目の引数に `true` を渡す)と、SDK がより詳細なリクエストログを出力し、ネットワーク、署名、広告枠のいずれのエラーコードかを特定できます。

出典: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L59)

## 検証

修正後、項目ごとに確認してください:

1. 起動ログに `Advertisement manager is invalid.` の致命的ログが表示されなくなる。
2. `Play` を呼び出した際、`OnSuccess` または `OnFail` の少なくとも一方がトリガーされ、「完全な無音状態」にならない。
3. Android / iOS / WeChat ミニゲーム / Douyin / Kuaishou ミニゲームなどのコンパイルターゲットを切り替えても、`AdUnitId` が空にならない。
4. 広告プラットフォームの管理画面で広告枠のステータスが「承認済み」であり、頻度制限ポリシーがトリガーされていないことを確認する。
