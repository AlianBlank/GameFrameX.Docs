# 工作原理：建置後處理與設定合併流程

iOS 建置完成後，`PostProcessBuildHelper.OnPostProcessBuild`（回呼優先順序 `888`）會自動收集專案內**所有**名為 `XCodeConfig.json` 的檔案，深度合併為一份最終設定（含通路專屬覆蓋），再分兩個階段把設定寫入產生的 Xcode 專案。整個過程無需手動干預，只要把設定檔放進專案任意目錄即可。

## 觸發時機

進入點是 Unity 的建置後處理回呼，且僅在 iOS 平台生效：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }
    ...
}
```

來源：[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L20)

整個方法主體被 `try/catch` 包覆，例外透過 `Debug.LogException(e)` 輸出但**不會中斷打包**（[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L158-L161)）。類別整體位於 `#if UNITY_IOS` 條件編譯內。

## 設定探索與合併

流程按以下順序執行：

1. `SettingLoader.LoadSettingsData("XCodeConfig.json")` 掃描專案內全部 TextAsset，按檔名（不區分大小寫）精確匹配 `XCodeConfig.json`，結果按路徑排序保證合併順序確定。
2. 逐一讀取並以 `HashtableFromJson()` 解析，再透過 `finalConfig.Merge(table)` 深度遞迴合併到同一個 `Hashtable`。
3. 若存在通路識別碼，載入 `XCodeConfig.{channel}.json` 並**最後合併**，因此通路設定優先順序最高。
4. 合併結果為空則直接略過後續設定。

關鍵程式碼（通用設定合併部分）：

```csharp
var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

if (jsonPaths.Count == 0)
{
    LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
    return;
}

Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    if (table == null)
    {
        LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
        continue;
    }
    finalConfig.Merge(table);
}
```

來源：[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L49)

## 通路設定

通路名稱透過 `SettingLoader.GetChannel()` 取得：優先取命令列參數 `-channel`，沒有則回退至 EditorPrefs 鍵 `XCodeBuild_Channel`：

```csharp
var args = Environment.GetCommandLineArgs();
for (int i = 0; i < args.Length - 1; i++)
{
    if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
    {
        return args[i + 1];
    }
}
string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
if (!string.IsNullOrEmpty(editorChannel))
{
    return editorChannel;
}
return null;
```

來源：[Editor/SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)

通路設定檔名稱由基礎名稱拼接通路名稱產生，即 `XCodeConfig.{channel}.json`（[Editor/SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111)）。命中後以同樣方式合併到 `finalConfig`，因為排在最後，相同鍵會覆蓋通用設定；未命中時僅輸出日誌，不報錯（[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L52-L77)）。

## 兩階段套用流程

合併完成後，設定分兩個階段寫入 Xcode 專案（[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)）：

**第一階段：寫入 PBXProject（project.pbxproj）**

1. 讀取 `Unity-iPhone.xcodeproj/project.pbxproj` 為 `PBXProject`。
2. 對 **Unity-iPhone 主 target** 套用 `finalConfig["unityMain"]`（`Run(...)`，見下節）。
3. 對 **UnityFramework target** 套用 `finalConfig["unityFramework"]`。
4. `SetSigning` 設定簽署（僅主 target），讀取 `signing` 節點。
5. `SetupSwiftBridging` 設定 Swift 橋接，鍵 `swiftBridging` **預設即視為開啟**。
6. 寫回 project.pbxproj。

**第二階段：套用其他設定**

1. `RunPlist` 寫入 Info.Plist（`plist` 節點）。
2. `RunEnvironmentVariables` 設定啟動環境變數（`environmentVariables`）。
3. `RunArgument` 設定啟動參數（`launcherArgs`）。
4. `SetCapabilities` 設定 Capabilities（僅主 target），bundleId 取自 `signing.bundleId`。
5. 由於 Capabilities 透過 `ProjectCapabilityManager` 獨立寫檔，程式碼會**重新讀取** project.pbxproj 以保留其修改。
6. `RunLocalization` 套用在地化（`localizations`）。
7. PodFile：若 `podfile` 鍵指定了完整 Podfile 則複製並重寫 source；否則走舊路徑，把 `unityMain.pods` / `unityFramework.pods` 逐行注入到 `Unity-iPhone` 與 `UnityFramework` 兩個 target 區塊。
8. 最後執行 `pod install`，鍵 `podInstall` **預設即視為執行**，設定 `false` 可略過。

## Run()：target 層級設定的八項子任務

`Run` 是第一階段的核心，對單一 target 依序套用以下內容（對應 `unityMain` / `unityFramework` 下的各欄位）：

| 順序 | 方法 | 設定鍵 | 作用 |
|------|------|--------|------|
| 1 | `SetBuildProperties` | `properties` | 建置屬性 |
| 2 | `SetFrameworks` | `frameworks` | 框架 |
| 3 | `SetLibs` | `libs` | 系統函式庫 |
| 4 | `RunCopyFiles` | `files` | 複製檔案 |
| 5 | `CopyFolders` | `folders` | 複製資料夾 |
| 6 | `SetFilesCompileFlag` | `filesCompileFlag` | 檔案編譯標記 |
| 7 | `AddOtherLinkFlag` | `otherLinkerFlag` | Linker Flag |
| 8 | `AddRunPathSearchPaths` | `runPathSearchPaths` | Run Path Search Paths |

```csharp
static void Run(PBXProject pbxProject, string targetGuid, string mainTargetGuid, Hashtable hashtable, string path)
{
    SetBuildProperties(pbxProject, targetGuid, hashtable.Get<Hashtable>("properties"));
    SetFrameworks(pbxProject, targetGuid, hashtable.Get<Hashtable>("frameworks"));
    SetLibs(pbxProject, targetGuid, hashtable.Get<Hashtable>("libs"));
    RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
    CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
    SetFilesCompileFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("filesCompileFlag"));
    AddOtherLinkFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("otherLinkerFlag"));
    AddRunPathSearchPaths(pbxProject, targetGuid, hashtable.Get<Hashtable>("runPathSearchPaths"));
}
```

來源：[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L165-L183)

各子任務分別實作在同目錄下的部分類別檔案中，例如 `PostProcessBuildHelper.BuildProperties.cs`、`PostProcessBuildHelper.Frameworks.cs`、`PostProcessBuildHelper.Plist.cs`、`PostProcessBuildHelper.PodFile.cs`、`PostProcessBuildHelper.Capabilities.cs`、`PostProcessBuildHelper.Signing.cs` 等。

## 頂層設定鍵一覽

最終合併設定的頂層節點及其使用方式（均來自 [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L152)）：

| 鍵 | 類型 | 套用位置 | 說明 |
|----|------|----------|------|
| `unityMain` | object | Unity-iPhone target | 主 target 的 `Run()` 八項子任務 |
| `unityFramework` | object | UnityFramework target | 同上，作用於 Framework target |
| `signing` | object | 僅主 target | `SetSigning`，含 `bundleId` |
| `swiftBridging` | bool | 主 target + Framework | 預設視為 `true` |
| `plist` | object | Info.Plist | `RunPlist` |
| `environmentVariables` | object | scheme | `RunEnvironmentVariables` |
| `launcherArgs` | array | scheme | `RunArgument` |
| `capabilities` | object | 僅主 target | `SetCapabilities`，獨立寫檔 |
| `localizations` | array | 專案 | `RunLocalization` |
| `podSource` | array | Podfile | `RunPodfile` / `EnsurePodfileExists` |
| `podfile` | string | Podfile | 指定完整 Podfile 路徑，命中後走新路徑 |
| `podInstall` | bool | — | 預設視為 `true`；`false` 略過 `pod install` |

## 合併順序與覆蓋規則

優先順序從低到高，後合併的覆蓋先合併的（深合併，相同鍵以新值為準）：

1. 專案內所有 `XCodeConfig.json`（按排序後的路徑順序逐一合併）；
2. `XCodeConfig.{channel}.json` 通路專屬設定（最後合併，優先順序最高）。

因此想讓某通路覆蓋某個欄位，把該欄位寫進通路檔案即可，無需修改通用設定。
