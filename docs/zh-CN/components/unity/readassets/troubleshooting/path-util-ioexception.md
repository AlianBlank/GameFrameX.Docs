# PathUtil 抛 IOException:Invalid path: double dot error / Invalid characters

调用 `PathUtil.NormalizeRelativePath` 时,如果传入的相对路径包含越界的 `..` 段或非法字符,会抛出 `System.IO.IOException`,常见消息有两条:`Invalid path: double dot error (before N)` 和 `Invalid characters`。

## 快速诊断

| 症状(异常消息原文) | 根因 | 修复 |
|---|---|---|
| `Invalid path: double dot error (before <N>)` | 在已经到达"虚拟根 `/`"之后,还在用 `..` 想再向上一层 | 去掉多余的 `../`,确保路径不会越过入口根目录 |
| `Invalid characters` | 路径里含 `IsValidCharacter` 拒绝的字符(`\"`、`<`、`>`、`|`、控制字符 `<32`、`:`、`*`、`?`) | 移除或替换非法字符 |

两条异常都来自 `Runtime/PathUtil.cs` 的 `NormalizeRelativePath`。

## 修复步骤

### 1. 处理 `Invalid path: double dot error`

触发条件:解析过程中,`..` 试图越过已经被规范化的"根 `output`"。源码片段:

```csharp
// Runtime/PathUtil.cs#L107-L112
else if ( state == NormalizeState.PrevDoubleDot )
{
    if ( output.Length == 1 )
    {
        throw new System.IO.IOException("Invalid path: double dot error (before " + i + ")");
    }
    ...
}
```

也就是说,当一个 `..` 出现,而当前累计的输出只有开头的根斜杠时,就会直接抛异常。

修复方法:

1. 把传入的相对路径打印出来,定位"倒数"出问题的 `..`。
2. 计算实际可以向上走的层数(等于路径前缀里的非 `..` 段数),删掉多余的 `../`。
3. 如果调用方拼接时使用了 `Path.Combine` 把绝对路径和带 `../` 的相对路径拼在一起,改用 `PathUtil.CombineSlash` 或先 `NormalizeRelativePath` 再拼接。

```csharp
// 用 NormalizeRelativePath 之前,先把 ../ 收敛到合理范围
var safe = relative.Replace("..\\", "").Replace("../", "");
var normalized = PathUtil.NormalizeRelativePath(safe);
```

`NormalizeRelativePath` 还支持首尾双引号包裹:源码中如果检测到开头和结尾都是 `"`,会自动去掉它们再解析(`Runtime/PathUtil.cs#L93-L97`)。不要把它当作"逃生口"绕过非法字符——下面那种异常仍会抛。

### 2. 处理 `Invalid characters`

触发条件:路径里出现了 `IsValidCharacter` 不允许的字符:

```csharp
// Runtime/PathUtil.cs#L173-L180
public static bool IsValidCharacter(char c)
{
    if (c == '\"' || c == '<' || c == '>' || c == '|' || c < 32 || c == ':' || c == '*' || c == '?')
    {
        return false;
    }
    return true;
}
```

源码中抛异常的位置:

```csharp
// Runtime/PathUtil.cs#L159-L162
if (!IsValidCharacter(relative[i]))
{
    throw new System.IO.IOException("Invalid characters");
}
```

修复方法:

1. 在调用 `NormalizeRelativePath` 之前,过滤或替换掉上面 8 类字符。可以直接复用现成的判断:

```csharp
// 调用方先自检,避免直接踩到 IOException
foreach (var ch in relative)
{
    if (!PathUtil.IsValidCharacter(ch))
    {
        // 报错或替换
        throw new ArgumentException($"非法字符: {ch}");
    }
}
```

2. Windows 风格的盘符(`C:`、冒号)会被视作非法字符。如果路径来自用户输入或外部资源名,建议先做白名单校验。
3. 如果是文件通配符场景,请改用 `PathUtil.WildcardToRegex`(见 `Runtime/PathUtil.cs#L183-L186`),它只接受 `*` 与 `?` 作为元字符;其余非法字符会被 `Regex.Escape` 转义,不会再触发这里的 IOException。

## 验证

让 `NormalizeRelativePath` 在修复后能正常返回即可:

```csharp
// 合法路径:返回规范化结果,不应抛异常
var ok = PathUtil.NormalizeRelativePath("a/b/../c");   // -> "/a/c"
var ok2 = PathUtil.NormalizeRelativePath("\"a/b\"");   // 自动剥引号 -> "/a/b"

// 仍然非法的反例,用来确认异常路径仍能被捕获
try
{
    PathUtil.NormalizeRelativePath("../a");
    PathUtil.NormalizeRelativePath("a:b");
}
catch (System.IO.IOException ex)
{
    Debug.LogWarning(ex.Message); // 应当看到 double dot / Invalid characters
}
```

如果两条异常都不再抛出,说明问题已解决。

## 背景(可选)

`NormalizeRelativePath` 在内部把路径视作以 `/` 开头的相对虚拟根,逐字符扫描并维护 `PrevSlash / PrevDot / PrevDoubleDot / NothingSpecial` 四个状态(`Runtime/PathUtil.cs#L11-L17`);`..` 通过回退已写入的段实现,一旦回退到只剩根斜杠就视为越界。非法字符则放在字符落盘前(`Append`)做白名单校验——这就是两条异常的产生时机。
