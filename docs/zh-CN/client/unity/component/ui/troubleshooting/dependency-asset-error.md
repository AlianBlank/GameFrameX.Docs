# 界面加载依赖资源异常怎么办

当你在打开界面（`OpenUIFormAsync`）时遇到依赖资源加载失败,包括依赖资产不存在、加载回调未触发、依赖计数长时间不变,或打开流程被中断,可以通过本页的诊断表定位根因并修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `OpenUIFormFailure` 事件触发,`ErrorMessage` 提示资源不存在 | 传入的 `uiFormAssetPath` 与实际资产路径不一致,或资产未被 AssetBundle / Addressables 收录 | 核对路径字符串与 `UIFormAssetName`,重新构建依赖清单 |
| `LoadedCount` 始终为 0,`TotalCount` 大于 0 | 依赖资源加载回调未正确注册,或被并发打开请求抢占 | 串行化打开同一资源,确认 `OpenUIFormDependencyAssetEventArgs` 监听链路 |
| `DependencyAssetName` 为 `null` | 界面本身没有声明依赖资产,或依赖元数据未生成 | 重新生成 UI 配置,确认依赖资产列表非空 |
| `Task` 长时间未返回 `IUIForm` | 依赖加载链未完成,异步流程被 `await` 卡住 | 检查是否在 `OpenUIFormAsync` 调用方遗漏 `await`,确认资源管理器已初始化 |
| `UIFormAssetPath` / `UIFormAssetName` 为 `null` | 上层调用没有传入有效路径 | 在调用 `OpenUIFormAsync` 前校验参数,使用 `GameFrameworkGuard.NotNull` |

事件对象的核心字段定义如下,可结合日志核对:

## 修复步骤

### 1. 资源路径或名称不匹配

`OpenUIFormAsync` 接受两个关键参数:资源路径 `uiFormAssetPath` 与资源名称 `uiFormAssetName`(在加载对象内)。如果任意一个不对应工程内真实存在的资产,加载会立即失败并通过 `OpenUIFormFailure` 抛出。

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class UIFormLoadingObject : IReference
{
    public string UIFormAssetPath { get; private set; }
    public string UIFormAssetName { get; private set; }
    public Type UIFormType { get; private set; }
    public Task<IUIForm> Task { get; private set; }

    public static UIFormLoadingObject Create(string uiFormAssetPath, string uiFormAssetName, Type uiFormType, Task<IUIForm> task)
    {
        var uiFormLoadingObject = ReferencePool.Acquire<UIFormLoadingObject>();
        uiFormLoadingObject.UIFormAssetPath = uiFormAssetPath;
        uiFormLoadingObject.UIFormAssetName = uiFormAssetName;
        uiFormLoadingObject.UIFormType = uiFormType;
        uiFormLoadingObject.Task = task;
        return uiFormLoadingObject;
    }
}
```

Source: [BaseUIManager.UIFormLoadingObject.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.UIFormLoadingObject.cs#L43-L86)

操作步骤:

1. 在 Unity 中定位该 UI 预制体,复制其 `Addressables` 地址或 AssetBundle 路径。
2. 调用 `OpenUIFormAsync` 时使用完全相同的字符串(大小写敏感)。
3. 在 `OpenUIFormFailure` 回调内打印 `UIFormAssetName` 与 `ErrorMessage`,逐字符比对。

### 2. 异步流程未等待

`OpenUIFormAsync` 返回 `Task<IUIForm>`,内部实现 `InnerOpenUIFormAsync` 是抽象方法,由子类完成依赖加载。

```csharp
[UnityEngine.Scripting.Preserve]
public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}

[UnityEngine.Scripting.Preserve]
protected abstract Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false);
```

Source: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L114-L130)

如果调用方遗漏 `await`,`Task` 会进入未完成状态被静默丢弃,后续操作读取 `uiForm` 时得到 `null`。修复方式:

1. 调用处统一使用 `await uiManager.OpenUIFormAsync<MyForm>(path, true, userData);`。
2. 在协程或回调风格代码中使用 `.ContinueWith(...)` 或 `await` 同步上下文。
3. 配合 `OpenUIFormSuccess` / `OpenUIFormFailure` 事件确认流程已结束。

### 3. 依赖计数不变 / 回调未触发

`OpenUIFormDependencyAssetEventArgs` 当前在 `BaseUIManager` 中以注释形式保留(`m_OpenUIFormDependencyAssetEventHandler` 已注释),如果你的项目曾订阅该事件,需要重新启用并由子类在依赖加载过程中调用 `EventId` 分发。当 `LoadedCount` / `TotalCount` 长时间不变,通常是依赖加载回调没有被驱动,或 `TotalCount` 在初始化前已被读取为 0。

建议在自定义 `BaseUIManager` 子类内:

1. 在 `InnerOpenUIFormAsync` 中拉取依赖资产清单,得到 `totalCount`。
2. 每完成一个依赖加载,调用 `OpenUIFormDependencyAssetEventArgs.Create(...)` 并通过事件总线广播。
3. 监听端读取 `LoadedCount` / `TotalCount` 驱动进度条。

### 4. 失败事件未注册

`OpenUIFormFailure` 事件用于捕获异常,签名如下:

```csharp
[UnityEngine.Scripting.Preserve]
public event EventHandler<OpenUIFormFailureEventArgs> OpenUIFormFailure
{
    add { m_OpenUIFormFailureEventHandler += value; }
    remove { m_OpenUIFormFailureEventHandler -= value; }
}
```

Source: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L63-L68)

如果应用没有订阅该事件,异常只能通过 `Task` 抛出,可能在上层被静默吞掉。修复方式:在 UI 框架启动后第一时间注册 `OpenUIFormFailure` 与 `OpenUIFormSuccess`,将错误日志统一落盘或上报。

## 验证

1. 触发一次正常打开流程,确认 `OpenUIFormSuccess` 被触发且 `SerialId` 与请求一致。
2. 触发一次故意写错路径的打开请求,确认 `OpenUIFormFailure.ErrorMessage` 含可读信息。
3. 触发一次带依赖资产的界面,确认 `LoadedCount` 最终等于 `TotalCount`。
4. 在调试器内观察 `UIFormLoadingObject.Task.Status`,确保其由 `WaitingForActivation` 进入 `RanToCompletion` 或 `Faulted`。
