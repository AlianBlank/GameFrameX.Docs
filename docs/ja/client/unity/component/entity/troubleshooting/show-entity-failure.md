# エンティティの表示に失敗した場合の対処方法

`ShowEntity` / `ShowEntityAsync` を呼び出した後にエンティティがシーンに表示されない場合、またはログで `ShowEntityFailure` イベントの発生が確認できる場合は、通常、エンティティグループ、リソース、またはヘルパーコンポーネントの設定が正しくないことが原因です。本ページでは、よくある原因ごとに迅速な診断と修正手順を示します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `ShowEntityFailure` イベントが即時に発生し、ログに `Entity group name is invalid.` が含まれる | 渡された `entityGroupName` が `null` / 空文字列、または該当エンティティグループが未登録 | `EntityComponent` の `m_EntityGroups` に同名のエンティティグループを事前に追加する |
| `Entity group is invalid.` と表示される | エンティティグループは存在するが、その内部の `EntityGroup` インスタンスが未初期化または破棄されている | `HasEntityGroup` でグループの存在を確認してから `ShowEntity` を呼び出す |
| `Can not create entity helper.` と表示される | `EntityComponent.Awake`/`Start` 内で `m_EntityHelperTypeName` から `EntityHelperBase` をリフレクションによって生成できない | `m_EntityHelperTypeName` が `GameFrameX.Entity.Runtime.DefaultEntityHelper` またはカスタムヘルパークラスの完全型名であるかを確認する;カスタムヘルパーは `m_CustomEntityHelper` フィールドに設定する必要がある |
| `ShowEntityFailure` イベントが継続的に発生し、リソースのロードに失敗する | `m_AssetManager` が未設定、またはリソースアドレス(`entityAssetName`)が YooAsset のリソースマニフェストに存在しない | `EntityComponent.Start` で `SetResourceManager` が呼び出されていることを確認する;YooAsset でエンティティ Prefab のタグとアドレスを正しく設定する |
| エンティティの作成には成功したが GameObject が表示されない | `m_InstanceRoot` が可視のシーンルート配下に配置されていない、または Prefab 自体の Layer/可視性がオフになっている | シーン内で `EntityComponent` に可視の `m_InstanceRoot` を指定する;Prefab の `MeshRenderer` の状態を確認する |
| 非同期インターフェース `ShowEntityAsync` がいつまでも返らない | リソースのロードが停滞している、または `m_EntitiesBeingLoaded` で同一エンティティへの重複リクエストが発生している | 同一フレームで同一 `EntityId` に対して複数回の Show を発行しない;リソースマネージャーが外部からブロックされていないことを確認する |

## 修正手順

### 1. エンティティグループが登録済みであることを確認

`EntityManager` はエンティティグループ名が空の場合、`GameFrameworkException("Entity group name is invalid.")` を直接スローします。すべての `ShowEntity` 呼び出しの前に、必ず `EntityComponent.AddEntityGroup` でグループを追加しておく必要があります。

```csharp
// Source: Runtime/Entity/Entity/EntityManager.Get.cs#L53-L61
public bool HasEntityGroup(string entityGroupName)
{
    if (string.IsNullOrEmpty(entityGroupName))
    {
        throw new GameFrameworkException("Entity group name is invalid.");
    }
    return m_EntityGroups.ContainsKey(entityGroupName);
}
```

手順：

1. `EntityComponent` がアタッチされたシーンオブジェクトの Inspector を開く。
2. `Entity Groups` リストに使用するグループを追加する(`Name`、`InstanceAutoReleaseInterval`、`InstanceCapacity`、`InstanceExpireTime`、`InstancePriority` を入力)。
3. コードでグループ名を使用する前に、`HasEntityGroup` を呼び出して検証する。

### 2. エンティティヘルパーが利用可能であることを確認

`EntityComponent.Start` 内では `Helper.CreateHelper` が呼び出されてエンティティヘルパーが作成されます;`null` が返された場合、`Log.Error("Can not create entity helper.")` を出力して初期化を中止します。

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L171-L183
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
    return;
}
entityHelper.name = "Entity Helper";
Transform transform = entityHelper.transform;
transform.SetParent(this.transform);
transform.localScale = Vector3.one;
m_EntityManager.SetEntityHelper(entityHelper);
```

手順：

1. `Entity Helper Type Name` フィールドが指すクラスが存在することを確認する(デフォルトは `GameFrameX.Entity.Runtime.DefaultEntityHelper`)。
2. カスタムヘルパーは `EntityHelperBase` を継承し、エンティティのインスタンス化ロジックを実装している必要があります;インスタンスを `Entity Component` の `Custom Entity Helper` フィールドにドラッグします。
3. ヘルパークラスが独立したアセンブリに存在する場合、そのアセンブリがビルドに含まれており、リフレクションで解決できることを確認する。

### 3. リソースマネージャーが注入済みであることを確認

`EntityManager` はエンティティ Prefab のロード時に `IAssetManager` に依存します(`SetResourceManager` によって注入);未注入の場合、`ShowEntityFailure` がロード段階で失敗します。

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L167-L169
m_EntityManager.SetResourceManager(GameFrameworkEntry.GetModule<IAssetManager>());
m_EntityManager.SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>());
```

手順：

1. シーン内の `Asset Component`、`Object Pool Component` がアタッチされており、Awake の順序が `EntityComponent` よりも早いことを確認する。
2. YooAsset が正しく初期化されており、リソースマニフェストに渡された `entityAssetName`(パスまたはタグ)が存在することを確認する。
3. 必要に応じて `Enable Show Entity Dependency Asset Event` を有効にし、イベントを通じて依存リソースのダウンロードが完了したかを確認する。

### 4. 失敗イベントを監視して根本原因を特定する

`EntityComponent` は Awake 内でデフォルトで `ShowEntityFailure` を購読しています。デバッグ段階では、独自のスクリプトで追加購読し、`EntityId`、`EntityAssetName`、`EntityGroupName`、`ErrorMessage` などの情報を取得できます。

```csharp
// Source: Runtime/Entity/Entity/EntityManager.cs#L118-L122
public event EventHandler<ShowEntityFailureEventArgs> ShowEntityFailure
{
    add { m_ShowEntityFailureEventHandler += value; }
    remove { m_ShowEntityFailureEventHandler -= value; }
}
```

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L130-L131
m_EntityManager.ShowEntitySuccess += OnShowEntitySuccess;
m_EntityManager.ShowEntityFailure += OnShowEntityFailure;
```

手順：失敗コールバック内で `EventArgs.ErrorMessage` と `EventArgs.EntityId` をログに出力し、メッセージに基づいて上記の 1~3 の項目を確認する。

### 5. 実行時インスタンスのルートノードを確認する

エンティティヘルパーは `GameObject("Entity Instances")` を作成して `m_InstanceRoot` とします。このルートノードが無効化されている場合やシーン内に存在しない場合、エンティティは作成に成功しても視覚的には表示されません。

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L185-L190
if (m_InstanceRoot == null)
{
    m_InstanceRoot = new GameObject("Entity Instances").transform;
    m_InstanceRoot.SetParent(gameObject.transform);
    m_InstanceRoot.localScale = Vector3.one;
}
```

手順：

1. Hierarchy 内で `Entity Instances` ノードを特定し、アクティブ状態であることを確認する。
2. `m_InstanceRoot` をカスタマイズした場合は、親ノードと自身の両方がアクティブであり、カメラによってカリングされていないこと(`Layer` 設定、`Culling Mask` など)を確認する。

## 検証

1. テストシーンで `ShowEntity<MyEntityLogic>(entityId, "Default", "MyPrefab", userData)` を呼び出す。
2. Console を確認する:`ShowEntitySuccess` イベントが発生し、`OnShowEntitySuccess` が一度呼び出されるはずです。
3. Hierarchy 内で、エンティティの `EntityId` で命名された GameObject が `Entity Instances` 配下に現れ、位置/スケール/可視性が期待どおりであることを確認する。
4. `HideEntity(entityId)` を呼び出した後、オブジェクトがオブジェクトプールに回収され、`HideEntityComplete` イベントが正常に発生することを確認する。

## 背景(オプション)

`EntityManager` 内部では `m_EntityInfos`、`m_EntityGroups`、`m_EntitiesBeingLoaded` などの辞書とキューが管理されており、リソースのロードは `IAssetManager` を通じて非同期で実行され、完了後に `IEntityHelper` を呼び出してエンティティをインスタンス化し `ShowEntitySuccess` を発行します;いずれかのステップでエラーがスローされると `ShowEntityFailure` パスが実行され、`ShowEntityInfo` 参照オブジェクトが再利用されます([ShowEntityInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.ShowEntityInfo.cs#L38-L106))。
