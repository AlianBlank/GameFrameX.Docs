# 첫 번째 사용 가능한 프로시저

이 페이지의 단계에 따라 Unity 프로젝트에 `ProcedureComponent`를 부착하고, 두 개의 `ProcedureBase` 서브클래스를 작성한 뒤 진입 프로시저를 시작하면, 게임이 시작되자마자 바로 동작하도록 만들 수 있습니다.

## 사전 조건

- `com.gameframex.unity.procedure` 패키지와 그 의존성인 `com.gameframex.unity.fsm`, `com.gameframex.unity.runtime`가 설치되어 있어야 합니다.
- 프로젝트 진입 씬의 `GameFramework` 오브젝트에 `ProcedureComponent` 컴포넌트(`[AddComponentMenu("GameFrameX/Procedure")]`)가 부착되어 있어야 합니다.
- C# 클래스 상속과 Unity Inspector의 기본 사용법을 알고 있어야 합니다.

## 작업 단계

1. **프로시저 클래스 신규 생성**. `LaunchProcedure`(시작 프로시저, 일반적으로 기본 시스템 초기화를 담당)를 생성하여 `ProcedureBase`를 상속합니다:

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

public sealed class LaunchProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 여기서 기본 모듈 초기화를 수행합니다(예: 설정, 로그, 리소스 등)
    }
}
```

`ProcedureBase`는 `FsmState<IProcedureManager>`를 상속하며, 내부에 `OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy` 6개의 생명주기 훅이 내장되어 있으므로 필요에 따라 재정의하면 됩니다.

Source: [ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

2. **두 번째 프로시저 신규 생성**(예: `MainProcedure`). 이후 메인 화면이나 메인 로직으로 전환하는 데 사용됩니다:

```csharp
using GameFrameX.Procedure.Runtime;

public sealed class MainProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 씬 시작, UI 로딩, 메인 루프 시작
        ChangeState<MainProcedure>(procedureOwner); // 사용자 정의 전환 예시
    }
}
```

3. **Inspector에서 프로시저 목록 설정**. `ProcedureComponent`가 부착된 오브젝트를 선택하고 다음 필드를 입력합니다:

| 필드 | 역할 | 예시 |
|------|------|------|
| `Available Procedure Type Names` | 프레임워크가 생성하여 상태 머신에 추가할 모든 프로시저 타입의 전체 이름(네임스페이스 + 클래스명) | `MyGame.LaunchProcedure`, `MyGame.MainProcedure` |
| `Entrance Procedure Type Name` | 시작 진입 프로시저 타입의 전체 이름. 반드시 앞 단계의 목록에 나타나야 함 | `MyGame.LaunchProcedure` |

타입명은 리플렉션으로查找되므로, 해당 클래스를 `Utility.Assembly.GetType`으로 찾을 수 있어야 하며 매개변수 없는 생성자를 가져야 합니다. 컴포넌트는 `Start`에서 자동으로 `Activator.CreateInstance`로 인스턴스를 생성하고 초기화합니다.

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L129-L168)

4. **Play Mode 진입**. 프레임워크는 `Start`에서 다음 작업을 수행합니다:

   - 리플렉션으로 모든 프로시저 인스턴스를 생성합니다.
   - `m_ProcedureManager.Initialize(IFsmManager, procedures)`를 호출하여 FSM에 등록합니다.
   - 프레임 말에 `m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType())`를 호출하여 진입 프로시저를 시작합니다.

   진입 프로시저의 `OnEnter`가 트리거되면, 첫 번째 사용 가능한 프로시저가 이미 실행 중인 상태가 됩니다.

## 일반적인 변형

- **수동 시작 관리(StartupRunner 모드)**: `ProcedureComponent`에서 `Use Startup Runner = true`를 체크하면, 컴포넌트의 `Awake`는 `IProcedureManager`만 등록하며 자동으로 `Initialize/StartProcedure`를 호출하지 않습니다. `ApplicationStartupEntry`가 `StartupRunner.Run`을 통해 사용자가 지정한 위치에서 초기화와 시작을 대신 처리하므로, 중복 `Initialize`로 인한 "Already exist FSM" 오류를 방지할 수 있습니다.

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L127)

- **컴포넌트를 부착하지 않고 순수 코드로 초기화**: `IFsmManager`와 `IProcedureManager`를 가져온 후, 직접 프로시저 배열을 구성하여 `Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures)`를 호출하고, 이어서 `StartProcedure<T>()`를 호출합니다.

  Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L156)

- **런타임에 프로시저 전환**: 특정 프로시저의 `OnEnter` / `OnUpdate`에서 `procedureOwner.Start<TargetProcedure>()`를 호출하면 다른 프로시저로 전환할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 로그 `Entrance procedure is invalid.` | `Entrance Procedure Type Name`이 `Available Procedure Type Names` 목록에 없음 | 진입 타입명을 목록의 항목과 완전히 일치시킵니다 |
| 로그 `Can not find procedure type 'X'.` | 타입 전체 이름의 철자가 틀렸거나, 해당 타입이 런타임에서 로드 가능한 어셈블리에 없음 | 네임스페이스 + 클래스명을 사용하고, 어셈블리가 빌드되었는지 확인합니다 |
| 로그 `Can not create procedure instance 'X'.` | 프로시저 클래스에 접근 가능한 매개변수 없는 생성자가 없음 | `Procedure` 서브클래스에 명시적으로 매개변수 없는 생성자를 추가합니다(명시적으로 작성하지 않으면 자동으로 생성되지만, 매개변수가 있는 생성자를 정의하면 덮어쓰여집니다) |
| 예외 `You must initialize procedure first.` | `Initialize`를 호출하기 전에 `CurrentProcedure`, `StartProcedure` 등에 접근함 | 먼저 `Initialize`를 호출한 뒤 `StartProcedure`를 호출하거나, `ProcedureComponent`의 `Start`가 실행되었는지 확인합니다 |
| 예외 `Procedures is invalid.` | `Initialize`에 전달한 프로시저 배열의 길이가 0임 | 최소 하나 이상의 프로시저 인스턴스를 전달합니다 |
| 중복 `Initialize`로 `Already exist FSM` 발생 | 컴포넌트의 자동 초기화와 StartupRunner를 동시에 사용했거나, 수동으로 여러 번 `Initialize`를 호출함 | 둘 중 하나만 선택합니다: `Use Startup Runner`를 끄거나, 컴포넌트가 인터페이스만 등록하도록 하고 외부에서 통합하여 초기화합니다 |

## 배경(선택 사항)

`ProcedureManager`는 본질적으로 `GameFrameworkModule`이며, 내부적으로 `IFsmManager.CreateFsm(this, procedures)`를 통해 모든 프로시저를 유한 상태 머신의 상태로 등록합니다. `ProcedureBase`는 `FsmState<IProcedureManager>`에서 파생되므로, 프로시저 간의 전환 및 파괴는 FSM의 기능을 그대로 재사용합니다. `ProcedureComponent`는 단지 Unity 생명주기 안에서 타입명을 리플렉션으로 인스턴스화하여 `ProcedureManager`에 전달하는 역할만 담당합니다.
