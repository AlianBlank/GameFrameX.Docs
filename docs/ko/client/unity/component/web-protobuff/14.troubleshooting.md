# 자주 묻는 질문

이 문서는 GameFrameX Web ProtoBuff 컴포넌트 사용 과정에서 발생할 수 있는 일반적인 문제와 그 해결 방법을 수집합니다.

## 개요

Web ProtoBuff 컴포넌트는 GameFrameX 프레임워크의 네트워크 모듈로, Protocol Buffer 형식의 HTTP 요청을 처리합니다. 사용 과정에서 개발자는 컴파일 오류, 런타임 예외, 메시지 직렬화 문제 등에 부딪힐 수 있습니다. 이 문서는 개발자가 이러한 문제를 빠르게 파악하고 해결할 수 있도록 돕는 것을 목표로 합니다.

---

## 컴파일 관련 문제

### 1. Post 메서드가 보이지 않음

**문제 설명:**
코드에서 `WebProtoBuffComponent.Post<T>()` 메서드를 호출할 수 없고 IDE에서 메서드가 존재하지 않다고提示합니다.

**원인 분석:**
`Post<T>` 메서드는 컴파일 매크로 `#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`로 싸여 있습니다. 이 매크로가 정의되지 않으면 메서드를 사용할 수 없습니다.

**솔루션:**
Unity 편집기에서 **Edit > Project Settings > Player**를 열고, **Scripting Define Symbols**에 다음 매크로 정의를 추가합니다:

```
ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
```

> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

---

### 2. 컴포넌트 초기화 실패

**문제 설명:**
게임을 실행할 때 콘솔에 "Web manager is invalid." 오류 로그가 나타납니다.

**원인 분석:**
`WebProtoBuffComponent.Awake()` 메서드에서 `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()`를 통해 관리자 인스턴스를 가져오며, null이 반환되면 치명적 오류가 기록됩니다. 이는 일반적으로 다음 원인 때문입니다:

1. GameFrameX 핵심 프레임워크가 올바르게 초기화되지 않았습니다
2. `WebProtoBuffManager` 모듈이 등록되지 않았습니다
3. 어셈블리 축소로 인해 필요한 유형이 제거되었습니다

**솔루션:**
1. GameFrameX 핵심 프레임워크가 올바르게 설치되고 초기화되었는지 확인합니다
2. `GameFrameXWebProtoBuffCroppingHelper` 컴포넌트가 GameObject에 추가되었는지 확인합니다
3. IL2CPP 또는 어셈블리 축소를 사용하는 경우 필요한 Preserve 속성을 추가했는지 확인합니다

```csharp
// 컴포넌트에 이미 Preserve 속성이 자동으로 추가되었습니다
[UnityEngine.Scripting.Preserve]
[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]
public sealed class WebProtoBuffComponent : GameFrameworkComponent
```

> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L46-L90)

## 런타임 오류

### 3. 요청 타임아웃

**문제 설명:**
네트워크 요청이 오랫동안 응답하지 않으며 결국 타임아웃 예외가 발생합니다.

**원인 분석:**
컴포넌트의 기본 타임아웃 시간은 5초입니다. 서버 응답 시간이 이 값을 초과하면 타임아웃 오류가 발생합니다.

WebGL 플랫폼은 `UnityWebRequest.timeout`을 사용합니다:
```csharp
unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;
```

기타 플랫폼은 `HttpWebRequest.Timeout`을 사용합니다:
```csharp
request.Timeout = (int)RequestTimeout.TotalMilliseconds;
```

**솔루션:**
1. Inspector를 통해 타임아웃 시간을 조정합니다 (범위 0-120초)
2. 코드에서 동적으로 타임아웃을 설정합니다:

```csharp
// 컴포넌트 참조를 가져와서 타임아웃 시간 설정
var webComponent = GetComponent<WebProtoBuffComponent>();
webComponent.Timeout = 30f; // 30초로 설정
```

> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L60-L71)

### 4. 네트워크 오류

**문제 설명:**
요청이 실패하고 콘솔에 네트워크 오류 정보가 나타납니다.

**원인 분석:**
WebGL 플랫폼은 `UnityWebRequest.isNetworkError`와 `UnityWebRequest.isHttpError`를 통해 오류를 감지합니다:

```csharp
if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)
{
    webData.Task.TrySetException(new Exception(unityWebRequest.error));
    return;
}
```

기타 플랫폼은 `WebException`을捕获합니다:

```csharp
catch (WebException e)
{
    if (e.Status == WebExceptionStatus.Timeout)
    {
        webData.Task.SetException(new TimeoutException(e.Message));
        return;
    }
    webData.Task.SetException(e);
}
```

**솔루션:**
1. 네트워크 연결이 정상인지 확인합니다
2. 서버 주소 URL이 올바르게 되었는지 확인합니다
3. 방화벽 또는 프록시 설정을 확인합니다
4. 오류 메시지를 보고 구체적인 원인을 파악합니다

---

### 5. 응답 메시지 유형 불일치

**문제 설명:**
요청이 성공했지만 null을 반환하거나 "Response message type is invalid" 로그가 표시됩니다.

**원인 분석:**
컴포넌트가 응답 메시지 유형이 예상과 일치하는지 검증합니다:

```csharp
var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
if (messageType != typeof(T))
{
    Log.Error($"응답 메시지 유형이 유효하지 않습니다. 예상: '{typeof(T).FullName}', 실제: '{messageType.FullName}'.");
    return default;
}
```

이는 일반적으로 다음 원인 때문입니다:
1. 서버가 반환한 메시지 ID가 예상과 다릅니다
2. `ProtoMessageIdHandler`가 메시지 유형 매핑을 올바르게 등록하지 않았습니다

**솔루션:**
1. 서버가 반환한 메시지 ID가 요청/응답 유형 매핑과 일치하는지 확인합니다
2. `ProtoMessageIdHandler`가 메시지 유형을 올바르게 초기화했는지 확인합니다

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L185-L197)

## 메시지 정의 문제

### 6. 메시지 직렬화 실패

**문제 설명:**
요청을 보낼 때 직렬화 예외가 발생하거나 서버가 요청 데이터를解析할 수 없습니다.

**원인 분석:**
컴포넌트는 `SerializerHelper.Serialize()`를 사용하여 메시지를 직렬화하며, 요청 본문이 `MessageHttpObject`로 포장됩니다:

```csharp
MessageHttpObject messageHttpObject = new MessageHttpObject
{
    Id = id,
    UniqueId = message.UniqueId,
    Body = SerializerHelper.Serialize(message),
};
var sendData = SerializerHelper.Serialize(messageHttpObject);
```

메시지 유형은 다음 조건을 충족해야 합니다:
1. `[ProtoContract]` 속성으로 표시되어야 합니다
2. `MessageObject` 베이스 클래스를 상속해야 합니다
3. 모든 속성이 `[ProtoMember]`로 표시되어야 합니다

**솔루션:**
메시지 유형을 올바르게 선언합니다:

```csharp
using ProtoBuf;
using GameFrameX.Network.Runtime;

[ProtoContract]
public class LoginRequest : MessageObject
{
    [ProtoMember(1)]
    public string Username { get; set; }

    [ProtoMember(2)]
    public string Password { get; set; }
}

[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)]
    public bool Success { get; set; }

    [ProtoMember(2)]
    public string Token { get; set; }
}
```

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L210-L225)

---

### 7. 응답 메시지 인터페이스 미구현

**문제 설명:**
컴파일 오류 또는 런타임 예외가 발생하며 응답 유형이 특정 인터페이스를 구현해야 한다고提示합니다.

**원인 분석:**
`Post<T>` 메서드의 제네릭 제약 조건은 유형이 `MessageObject`를 상속하고 `IResponseMessage` 인터페이스를 구현해야 합니다:

```csharp
public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message)
    where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
```

**솔루션:**
응답 클래스가 두 가지 유형을 모두 상속하는지 확인합니다:

```csharp
[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)]
    public bool Success { get; set; }
}
```

> Source: [IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L22-L24)

## 플랫폼 관련 문제

### 8. WebGL 플랫폼 요청 실패

**문제 설명:**
WebGL 플랫폼 빌드 후 네트워크 요청이 정상적으로 작동하지 않습니다.

**원인 분석:**
WebGL 플랫폼은 `UnityWebRequest`를 사용하고 `HttpWebRequest`는 사용하지 않으며, 두 가지의 API와 동작에 차이가 있습니다:

```csharp
#if UNITY_WEBGL
        UnityEngine.Networking.UnityWebRequest unityWebRequest;
        if (webData.IsGet)
        {
            unityWebRequest = UnityEngine.Networking.UnityWebRequest.Get(webData.URL);
        }
        else
        {
            unityWebRequest = UnityEngine.Networking.UnityWebRequest.Post(webData.URL, string.Empty);
        }

        unityWebRequest.SetRequestHeader("Content-Type", ProtoBufContentType);
        byte[] postData = webData.SendData;
        unityWebRequest.uploadHandler = new UnityEngine.Networking.UploadHandlerRaw(postData);
#else
        // HttpWebRequest 사용
#endif
```

**솔루션:**
1. Unity 버전이 WebGL 요청을 지원하는지 확인합니다
2. 브라우저 콘솔에跨域 오류가 있는지 확인합니다
3. 서버가 올바른 CORS 헤더를 구성했는지 확인합니다
4. Content-Type이 `application/x-protobuf`로 설정되었는지 확인합니다

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L85-L117)

### 9. 어셈블리 축소 문제

**문제 설명:**
IL2CPP打包后组件无法正常工作.

**원인 분석:**
Unity의 어셈블리 축소 기능이 "사용되지 않은" 것으로 간주되는 유형을 제거하여 런타임에 필요한 클래스를 찾을 수 없습니다.

**솔루션:**
컴포넌트에 이미 필요한 유형이 잘리지 않도록 `UnityEngine.Scripting.Preserve` 속성이 추가되었습니다:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Web ProtoBuff")]
[UnityEngine.Scripting.Preserve]
[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]
public sealed class WebProtoBuffComponent : GameFrameworkComponent
```

여전히 문제가 발생하면 수동으로 링커 구성 파일을 추가하거나 다음 코드를 사용하여 유형을 강제 유지할 수 있습니다:

```csharp
// 시작 시 호출하여 유형이 잘리는 것을 방지
void PreserveTypes()
{
    _ = typeof(WebProtoBuffComponent);
    _ = typeof(IWebProtoBuffManager);
    _ = typeof(WebProtoBuffManager);
}
```

> Source: [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs#L6-L17)

## 디버깅 및 로그

### 10. 디버깅 로그 활성화

**문제 설명:**
요청과 응답의 상세 정보를 확인해야 하지만 방법을 모릅니다.

**원인 분석:**
컴포넌트는 디버깅 로그 기능을 제공하지만 기본적으로 비활성화되어 있습니다. 다음 매크로를 통해 활성화할 수 있습니다:

- `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` - 전송 로그
- `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` - 수신 로그

**솔루션:**
Player Settings에 이상의 매크로 정의 중 하나 또는 모두를 추가합니다:

```
ENABLE_GAMEFRAMEX_WEB_SEND_LOG;ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
```

로그 출력 형식 예시:

```csharp
// 전송 로그
Log.Debug($"메시지 전송 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 메시지 내용:{...}");

// 수신 로그
Log.Debug($"메시지 수신 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 메시지 내용:{...}");
```

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L227-L241)
