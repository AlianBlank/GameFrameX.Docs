# 如何使用 EntityContractValidator 校验契约

`EntityContractValidator` 用于校验实体类型与其实现接口之间的属性一致性:接口里声明的每个属性,实体类必须存在同名属性、类型兼容(支持 `Nullable<T>` 与可赋值协变),并提供接口所要求的 `getter` / `setter`。

## 前置条件

- 项目引用 `GameFrameX.Foundation.Orm.Entity` 程序集。
- 目标框架支持 `System.Reflection`(所有 .NET 版本均可)。
- 待校验的类型为 `class`,并且至少实现了一个带有属性的接口。

## 操作步骤

1. **选择校验入口**。提供两种重载,结果完全一致:

   ```csharp
   using GameFrameX.Foundation.Orm.Entity;

   // 泛型重载(编译期已知类型)
   var violations = EntityContractValidator.Validate<MyEntity>();

   // 非泛型重载(运行期反射得到 Type)
   var violations = EntityContractValidator.Validate(typeof(MyEntity));
   ```

   Source: [EntityContractValidator.cs#L57-L87](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L57-L87)

2. **遍历违反项并定位原因**。返回类型为 `IList<EntityContractViolation>`,每条记录包含三个字段:

   | 字段 | 类型 | 含义 |
   |------|------|------|
   | `InterfaceType` | `Type` | 被违反的接口类型 |
   | `PropertyName` | `string` | 缺失或不匹配的属性名 |
   | `Reason` | `string` | 中英双语描述的具体原因 |

   Source: [EntityContractViolation.cs#L38-L79](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractViolation.cs#L38-L79)

3. **典型最小调用**:

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       foreach (var v in violations)
       {
           Console.WriteLine($"[{v.InterfaceType.Name}.{v.PropertyName}] {v.Reason}");
       }
   }
   ```

4. **在 CI / 启动期挂载断言**(推荐做法):

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       throw new InvalidOperationException(
           $"实体 MyEntity 违反契约:{string.Join("; ", violations.Select(v => v.Reason))}");
   }
   ```

## 校验的四类违反

`ValidateInterface` 对接口上的每个属性按顺序检查,命中即 `continue`,每类违反只会触发一次:

| 顺序 | 触发条件 | `Reason` 关键词 | 源码行 |
|------|----------|------------------|--------|
| 1 | `GetProperty` 抛出 `AmbiguousMatchException`(多继承或 `new` 遮蔽) | "存在多个声明(可能使用了 new 关键字遮蔽)" | [L100-L108](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108) |
| 2 | 实体类不存在同名公开属性 | "不存在" | [L110-L118](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118) |
| 3 | 属性类型不兼容(`IsTypeCompatible` 返回 false) | "类型不匹配:期望 … 实际 …" | [L120-L128](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L120-L128) |
| 4 | 接口要求 `get` / `set`,但实现缺少对应访问器 | "缺少 getter" / "缺少 setter" | [L130-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144) |

`IsTypeCompatible` 的判定规则(支持 `Nullable<T>` 与协变):

- 完全相同 → 兼容;
- 去掉 `Nullable` 包装后相同 → 兼容;
- 其余情况走 `expected.IsAssignableFrom(actual)`。

Source: [EntityContractValidator.cs#L148-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

## 常见变体

- **校验泛型实体基类**:`Validate<EntityBase<Guid>>()`、`Validate<EntityTenantBase<Guid>>()` 等均返回空列表,框架内置基类全部自洽。Source: [EntityContractValidatorComprehensiveTests.cs#L78-L94](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/EntityContractValidatorComprehensiveTests.cs#L78-L94)
- **校验非实体类型**:可正常调用,但若类型实现的接口属性为显式接口实现(如 `int.IConvertible.TypeCode`),会触发"属性不存在"违反。Source: [L42-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/EntityContractValidatorComprehensiveTests.cs#L42-L51)
- **多级继承 + `new` 遮蔽**:即使在多层继承链中产生 `AmbiguousMatchException`,同一属性名只产生一条违反(命中后 `continue`)。Source: [OrmEntityBoundaryTests.cs#L60-L67](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/OrmEntityBoundaryTests.cs#L60-L67)

## 常见错误

| 错误用法 | 现象 | 修正 |
|----------|------|------|
| 传入 `null` 给 `Validate(Type)` | 抛出 `ArgumentNullException`,`ParamName = "entityType"` | 传入非空 `Type` 或改用泛型重载 | 
| 用 `explicit interface implementation` 实现接口属性 | 校验报告"属性不存在"——`GetProperty(Public|Instance)` 找不到显式实现 | 将属性改为公开属性,或在接口上只声明接口自身需要的成员 |
| 用 `new` 关键字遮蔽接口同名属性 | 触发 `AmbiguousMatchException`,报告"存在多个声明(可能使用了 new 关键字遮蔽)" | 删除 `new`,或重命名使其在实体类中保持唯一 |
| 把 `string?` 实现成 `string` 或反之 | 报告"类型不匹配" | `Nullable<T>` 与非可空 T 视为兼容,其他差异请保持一致 |

## 背景(可选)

`ValidateInterface` 通过 `entityType.GetInterfaces()` 枚举所有接口,逐接口、逐属性地用 `BindingFlags.Public | BindingFlags.Instance` 在实体类上查找同名属性;命中即记录一条 `EntityContractViolation` 并 `continue`,因此一个接口属性最多产生一条违反。多继承或 `new` 遮蔽导致 `GetProperty` 抛 `AmbiguousMatchException` 时,捕获异常并以专门文案报告,而非向外抛出。`IsTypeCompatible` 先按精确类型匹配,再去掉 `Nullable` 包装后匹配,最后用 `IsAssignableFrom` 处理协变场景。
