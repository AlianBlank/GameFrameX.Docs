# 런타임에 절차 조회 및 전환 방법

게임 런타임에 `IProcedureManager` 인터페이스를 통해 현재 절차를 조회하고, 절차 존재 여부를 판단하며, 지정된 절차 인스턴스를 가져오거나 서로 다른 절차 간 전환을 수행합니다.

## 사전 조건

- `GameFrameworkEntry.GetModule<IProcedureManager>()` 를 통해 절차 관리자 인스턴스를 획득해야 합니다.
- 절차 관리자가 `Initialize(IFsmManager, params ProcedureBase[])` 호출을 완료했으며, 최소 하나의 절차가 등록되어 있어야 합니다.

## 작업 단계

### 1. 절차 관리자 가져오기

```csharp
IProcedureManager procedureManager = GameFrameworkEntry.GetModule<IProcedureManager>();
```

소스 코드:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L34-L119)

### 2. 현재 절차 조회

`CurrentProcedure` 속성을 읽으면 현재 실행 중인 절차 인스턴스를 가져올 수 있으며, `CurrentProcedureTime` 은 현재 절차의 누적 실행 시간(초)입니다.

```csharp
ProcedureBase current = procedureManager.CurrentProcedure;
float elapsed = procedureManager.CurrentProcedureTime;
Debug.Log($"현재 절차:{current.GetType().Name},실행 시간 {elapsed:F2}s");
```

초기화되지 않은 경우 `GameFrameworkException("You must initialize procedure first.")` 이 발생합니다.

소스 코드:[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L67-L96)

### 3. 절차 존재 여부 판단 / 절차 인스턴스 가져오기

`HasProcedure` 와 `GetProcedure` 를 통해 관리자에 등록된 특정 절차를 조회할 수 있습니다.

```csharp
if (procedureManager.HasProcedure<MyBattleProcedure>())
{
    MyBattleProcedure proc = (MyBattleProcedure)procedureManager.GetProcedure<MyBattleProcedure>();
    // proc 사용
}
```

`HasProcedure`, `GetProcedure` 는 제네릭 오버로드와 `Type` 오버로드 두 가지 형식을 제공합니다.

소스 코드:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L78-L105)、[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L178-L235)

### 4. 지정된 절차로 전환

`StartProcedure` 를 호출하여 대상 절차로 진입하면, 프레임워크가 자동으로 이전 절차의 `OnLeave` 와 대상 절차의 `OnEnter` 를 트리거합니다.

```csharp
procedureManager.StartProcedure<MyBattleProcedure>();
```

Type 객체를 통해 전환해야 하는 경우 `StartProcedure(Type)` 오버로드를 사용합니다.

소스 코드:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L62-L73)、[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L147-L171)

### 5. 절차 집합 재등록(선택 사항)

전체 절차를 교체해야 할 경우 먼저 `DestroyProcedures()` 로 비우고, `ReinitializeProcedures(...)` 로 새로운 절차 배열을 사용해 다시 구축합니다.

```csharp
procedureManager.DestroyProcedures();
procedureManager.ReinitializeProcedures(new MyBootProcedure(),
                                        new MyLoginProcedure(),
                                        new MyBattleProcedure());
```

소스 코드:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L107-L118)

## 자주 사용하는 API 빠른 참조

| 작업 | 메서드 / 속성 | 비고 |
|------|------------|------|
| 현재 절차 | `CurrentProcedure` | 초기화되지 않은 경우 `GameFrameworkException` 발생 |
| 현재 절차 시간 | `CurrentProcedureTime` | 단위:초 |
| 존재 여부 | `HasProcedure<T>()` / `HasProcedure(Type)` | 초기화되지 않은 경우 예외 발생 |
| 인스턴스 가져오기 | `GetProcedure<T>()` / `GetProcedure(Type)` | `ProcedureBase` 반환 |
| 절차 전환 | `StartProcedure<T>()` / `StartProcedure(Type)` | OnLeave/OnEnter 트리거 |
| 파괴 | `DestroyProcedures()` | 등록된 모든 절차 비우기 |
| 재구축 | `ReinitializeProcedures(params ProcedureBase[])` | 새로운 집합으로 재초기화 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `You must initialize procedure first.` | 절차 관리자가 `Initialize` 를 호출하지 않은 상태에서 속성이나 메서드에 접근 | 먼저 `Initialize(fsmManager, procedures)` 를 호출하여 초기화 |
| `Procedures is invalid.` | `Initialize` 에 빈 배열 전달 | 최소 하나의 `ProcedureBase` 인스턴스 전달 |
| 전환 후 콜백 없음 | 대상 절차가 `Initialize` 를 통해 관리자에 등록되지 않음 | `HasProcedure` 로 점검하고 `ReinitializeProcedures` 를 통해 등록 |

## 배경(선택 사항)

`ProcedureManager` 는 내부적으로 `IFsmManager` 를 통해 `IFsm<IProcedureManager>` 상태 머신을 생성하며, 각 절차는 해당 상태 머신의 한 상태입니다. `StartProcedure` 는 사실상 기본 상태 머신의 `Start<T>()` 를 호출하므로, 절차 전환 콜백(`OnEnter` / `OnLeave` / `OnUpdate`)은 FSM 에 의해 트리거됩니다.
