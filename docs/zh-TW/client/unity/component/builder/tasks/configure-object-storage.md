# 物件儲存的設定方法(Tencent Cloud / Qiniu / Alibaba Cloud)

透過命令列參數與腳本巨集開關，將物件儲存的驗證資訊與儲存桶資訊整合至 GameFrameX 建置管線，在建置完成後自動將建置產出物(APK、日誌、資源包等)上傳至 Tencent Cloud COS、Qiniu Cloud KODO 或 Alibaba Cloud OSS。

## 前置條件

1. 已安裝 `com.gameframex.unity.builder` 套件。
2. 專案中已引入至少一個物件儲存子套件與對應的 Editor 上傳實作：
   - Tencent Cloud:`GameFrameX.ObjectStorage.Tencent.Editor`
   - Qiniu Cloud:`GameFrameX.ObjectStorage.QiNiu.Editor`
   - Alibaba Cloud:`GameFrameX.ObjectStorage.ALiYun.Runtime`
3. 在 `Assets/GameFrameX/GameFrameX.Runtime.Editor/Scripts/EditorSettings/GameFrameXSettings.asset` 中開啟對應平台的啟用開關(由 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_*` 巨集控制)。
4. 準備好物件儲存的存取驗證資訊與儲存桶資訊:`Key`(SecretId/AK)、`Secret`(SecretKey/SK)、`BucketName`、`EndPoint`(區域端點)。

## 操作步驟

1. 從命令列將 4 個物件儲存參數傳遞給建置器：

| 參數 | 說明 |
|------|------|
| `-ObjectStorageKey` | 物件儲存存取金鑰 |
| `-ObjectStorageSecret` | 物件儲存存取密鑰 |
| `-ObjectStorageBucketName` | 物件儲存儲存桶名稱 |
| `-ObjectStorageEndPoint` | 物件儲存區域端點 |

參數定義請參閱 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40):

```csharp
/// <summary>
/// 物件儲存的 Key
/// </summary>
public string ObjectStorageKey { get; set; } = string.Empty;

/// <summary>
/// 物件儲存的密鑰
/// </summary>
public string ObjectStorageSecret { get; set; } = string.Empty;

/// <summary>
/// 物件儲存的儲存桶名稱
/// </summary>
public string ObjectStorageBucketName { get; set; } = string.Empty;

/// <summary>
/// 物件儲存的儲存桶區域名稱
/// </summary>
public string ObjectStorageEndPoint { get; set; } = string.Empty;
```

2. 在 Unity 中啟用對應目標雲端供應商的腳本巨集。Builder.cs 會依據 `#if` 分支選擇上傳管理器：

```csharp
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_QI_NIU
            ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<QiNiuYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT
            ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<TencentCloudObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_A_LI_YUN
            ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<ALiYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif
ObjectStorageUploadManager.SetSavePath($"builder/{PlayerSettings.productName}/{EditorUserBuildSettings.activeBuildTarget.ToString()}/{_builderOptions.JobName}/{Application.version}/{_builderOptions.BuildNumber}");
```

3. 啟用上傳開關，並選擇要上傳的內容。例如，僅上傳資源包與日誌時：

```
-IsUploadLogFile -IsUploadAsset
```

上傳邏輯的觸發位置請參閱 [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L62-L78)。

## 常見變化情境

### Tencent Cloud COS

- 在主控台建立 COS 儲存桶，並記下儲存桶名稱(`BucketName`)與**所屬區域的存取端點**(`EndPoint`,格式如 `cos.ap-shanghai.myqcloud.com`)。
- 在主控台 → 存取管理(CAM) → API 金鑰管理中，新增 `SecretId` 與 `SecretKey`,並分別設定至 `-ObjectStorageKey`、`-ObjectStorageSecret`。
- 啟用巨集:`ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT`。

### Qiniu Cloud KODO

- 建立物件儲存空間，取得**儲存空間名稱**與**存取端點**(如華東 `upload.qiniup.com`、華南 `upload-z2.qiniup.com` 等)，並設定至 `-ObjectStorageEndPoint`。
- 在個人中心 → 金鑰管理中取得 `AK` / `SK`,分別作為 Key / Secret 使用。
- 啟用巨集:`ENABLE_GAME_FRAME_X_OBJECT_STORAGE_QI_NIU`。

### Alibaba Cloud OSS

- 建立 OSS Bucket,並記下 `BucketName` 與**外網存取 EndPoint**(例如:`oss-cn-hangzhou.aliyuncs.com`)。
- 在 RAM 存取控制 → 使用者 → 建立 AccessKey 中，取得 `AccessKeyId` 與 `AccessKeySecret`,並分別設定為 Key / Secret。
- 啟用巨集:`ENABLE_GAME_FRAME_X_OBJECT_STORAGE_A_LI_YUN`。

## 常見錯誤

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 建置後未輸出上傳日誌，並顯示 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 未啟用 | 總開關巨集未啟用 | 在 `GameFrameXSettings.asset` 中勾選「啟用物件儲存」 |
| 出現 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT` 等巨集未定義的錯誤 | 未安裝子套件，或未啟用巨集 | 確認對應的 Editor 子套件存在於 `Packages/manifest.json` 中，並啟用對應的巨集 |
| 上傳回傳 403 / SignatureDoesNotMatch | Key/Secret 順序顛倒，或儲存桶與驗證資訊不一致 | 在 Key 設定存取金鑰 ID(AK/SecretId),在 Secret 設定金鑰(SK/SecretKey),並確認與儲存桶所在帳號一致 |
| 上傳回傳 `NoSuchBucket` | 儲存桶名稱或 EndPoint 區域不一致 | 儲存桶名稱需嚴格區分大小寫；EndPoint 必須使用儲存桶所在區域的存取端點 |
| 找不到上傳路徑 / 覆蓋到先前的套件 | 未設定 `JobName` 與 `BuildNumber` | `SetSavePath` 以 `{JobName}/{Application.version}/{BuildNumber}` 三段組合路徑，只要缺少其中一項，就會回退至預設值 |

## 背景(選用)

建置器會在靜態建構函式中讀取 4 個命令列參數，依據已啟用巨集的分支建立對應供應商的上傳管理器實例，並透過 `IObjectStorageUploadManager` 統一公開 `UploadFile` 介面。因此，若要切換雲端供應商，只需替換啟用巨集與命令列參數即可。儲存路徑範本由 `PlayerSettings.productName` / `activeBuildTarget` / `JobName` / `Application.version` / `BuildNumber` 組合而成，因此便於按版本區隔過往的建置產出物。完整的進入點請參閱 [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L32-L48)。
