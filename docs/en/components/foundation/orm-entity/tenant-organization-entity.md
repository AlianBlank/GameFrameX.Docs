# How to Use the Tenant/Organization Isolation Entity Base Class

Inheriting from `EntityTenantOrganizationBase` (or its generic version) gives an entity both multi-tenant isolation and organization isolation capabilities — it automatically carries the `TenantId` and `CreateOrganizationId` fields and implements the `ITenantIdFilter` and `IOrganizationIdFilter` interfaces, so the ORM filters can automatically filter data by tenant/organization.

## Prerequisites

- The NuGet package is installed: `GameFrameX.Foundation.Orm.Entity`
- The ORM framework is configured with the tenant context (current `TenantId`) and organization context (current `CreateOrganizationId`) so that the filters can be automatically injected
- The database table already has `TenantId` and `CreateOrganizationId` columns (nullable `long?`)

## Steps

1. **Make the entity class inherit from `EntityTenantOrganizationBase<TKey>`**. Specify the primary key type (commonly `long` or `Guid`), and the entity automatically gets two nullable `long?` properties: `TenantId` and `CreateOrganizationId`.

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L44-L55)

2. **(Optional) Annotate the entity with the `[TenantTable]` attribute**. The ORM uses this to enable tenant isolation: automatically injecting tenant filtering, forcing tenant identity on writes, and blocking cross-tenant access.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
}
```

Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L63-L72)

3. **Use the non-generic version (when the primary key is determined by the base class)**. When `EntityBase` already provides a default primary key type, you can inherit from `EntityTenantOrganizationBase` directly without specifying `TKey`.

```csharp
public class GameArea : EntityTenantOrganizationBase
{
    public string AreaName { get; set; }
    public bool IsActive { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L64-L76)

4. **Write tenant and organization fields as needed**. The ORM interceptor automatically overwrites `TenantId` and `CreateOrganizationId` with the current context on insert/query; if you need manual control, you can assign them in your business code.

```csharp
var order = new GameOrder
{
    OrderNo      = "O-20260101-0001",
    Amount       = 99.5m,
    CreatedTime  = DateTime.UtcNow,
    // TenantId and CreateOrganizationId are automatically populated from the context
};
```

## Common Variants

| Scenario | Base Class | Description |
|----------|----------|------|
| Only tenant isolation needed, no organization distinction | `EntityTenantBase<TKey>` | Inherits `ITenantIdFilter`, no `CreateOrganizationId` field |
| Only organization isolation needed | Custom entity implementing `IOrganizationIdFilter` | Exposes only `CreateOrganizationId` |
| Both tenant + organization isolation needed | `EntityTenantOrganizationBase<TKey>` | Described on this page |
| Primary key type determined by framework default | `EntityTenantOrganizationBase` (non-generic) | No explicit `TKey` |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Query results include data from other tenants/organizations | Filter not enabled or context did not inject `TenantId`/`CreateOrganizationId` | Check ORM global filter registration; confirm the tenant/organization context is set on every request |
| `TenantId` is always `null` on writes | Entity class is also marked as a global table, or interceptor ordering issue | Do not annotate a tenant entity with `[SystemTable]` at the same time; use only `[TenantTable]` |
| `CreateOrganizationId` field not found after inheritance | Incorrectly inherited from `EntityTenantBase` (tenant only) | Switch to `EntityTenantOrganizationBase` or its generic version |
| Column name mismatch | Table schema is missing the `TenantId` or `CreateOrganizationId` column | Add the corresponding nullable `bigint` column in a database migration |

## Background (Optional)

`EntityTenantOrganizationBase` inherits from `EntityTenantBase` (bringing `TenantId` + `ITenantIdFilter`) while also implementing `IOrganizationIdFilter` (bringing `CreateOrganizationId`). Both filter interfaces are recognized by the ORM layer: queries automatically get a `WHERE TenantId = ? AND CreateOrganizationId = ?` condition appended, and inserts automatically fill in both fields. `[TenantTable]` is a table-level switch that tells the ORM tenant isolation is enabled for this table, and it is mutually exclusive with `[SystemTable]` (globally shared).

For the overall multi-tenant isolation design, see "How to Use the Tenant Isolation Entity Base Class".
