# 민감 로그 필드를 마스킹하는 방법

`SensitiveLogEventEnricher` + `SensitiveLogPropertyPolicy`를 통해 로그 이벤트가 Sink로 들어가기 전에 `token`, `password`, `authorization` 등 민감 필드를 일괄적으로 플레이스홀더로 대체하여 자격 증명이 로그 파일에 직접 기록되지 않도록 합니다.

## 사전 조건

- `GameFrameX.Foundation.Logger`를 이미 참조해야 합니다(기본적으로 로그 모듈과 함께 로드되며, 프레임워크 자체의 `LogHandler`에 기본 정책이 자동으로 등록되어 있습니다).
- Serilog의 구조화 로그 속성(`LogContext.PushProperty` 또는 템플릿 플레이스홀더)을 사용하여 값을 전달합니다. 본 메커니즘은 속성명을 기준으로 매칭하며, 전체 메시지 문자열을 파싱하지 않습니다.

## 작업 단계

### 1. 프레임워크 기본 정책 사용(설정 불필요)

`LogHandler`는 Serilog pipeline을 구성할 때 이미 `SensitiveLogEventEnricher()`를 자동으로 추가하므로, 기본적으로 내장된 10개의 필드명으로 마스킹이 수행됩니다.

```csharp
// 프레임워크에 이미 기본 등록되어 있으므로 수동 등록이 필요하지 않습니다.
.Enrich.With(new SensitiveLogEventEnricher())
```

Source: [GameFrameX.Foundation.Logger/LogHandler.cs#L119](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHandler.cs#L119)

기본적으로 커버되는 필드명(대소문자 무시):

| 필드명 |
|--------|
| `token`、`access_token`、`refresh_token` |
| `password`、`passwd` |
| `authorization`、`cookie` |
| `apiKey`、`secret`、`clientSecret` |

Source: [GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53)

대체 텍스트는 기본값이 `[REDACTED]`입니다(`replacement`에 빈 문자열을 전달한 경우에도 `[REDACTED]`로 폴백됩니다).

### 2. 민감 필드명 사용자 정의

추가 필드 컬렉션을 전달하면 기본 정책을 덮어씁니다(컬렉션은 "전달하면 전체 집합"이므로, 기본값에 추가하려면 먼저 `SensitiveLogPropertyPolicy.Default`의 필드명을 연결하세요):

```csharp
using GameFrameX.Foundation.Logger;

var policy = new SensitiveLogPropertyPolicy(
    new[] { "IdCard", "Phone", "BankAccount" },
    replacement: "***");

var enricher = new SensitiveLogEventEnricher(policy);

// 사용자 정의 LoggerConfiguration에 연결
Log.Logger = new LoggerConfiguration()
    .Enrich.With(enricher)
    .WriteTo.Console()
    .CreateLogger();
```

Source: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53)

필드명 매칭은 `StringComparer.OrdinalIgnoreCase`를 사용하므로, `Password`와 `password` 모두 매칭됩니다.

### 3. 마스킹 적용 확인

`Password` 속성을 포함한 로그를 작성하고, 출력이 `[REDACTED]`로 변경되었는지 확인합니다:

```csharp
using Serilog.Context;

using (LogContext.PushProperty("Password", "my-secret-password"))
{
    Log.Information("Login attempt for {UserId}", 42);
}
```

기대 출력에서 `Password` 필드 값은 실제 비밀번호가 아닌 `[REDACTED]`이어야 합니다. Enricher는 `StructureValue`, `SequenceValue`, `DictionaryValue`를 재귀적으로 처리하므로, 구조화된 객체 내부에 중첩된 민감 필드도 대체됩니다.

Source: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103)

## 일반적인 변형

- **모델 필드 레벨 마스킹**: ORM 엔티티에 표시를 추가하여(리스트/내보내기/직렬화 시 일괄 처리) `GameFrameX.Foundation.Orm.Attribute`의 `[SensitiveField(MaskingStrategy.Phone)]`를 사용합니다. 정책은 Phone, IdCard, Email, BankCard, Name, Address, Custom을 커버합니다. 이는 로그 Enricher와는 독립적인 두 가지 경로이므로, 직렬화 레이어에서 별도로 연결해야 합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }
}
```

Source: [GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

- **사용자 정의 플레이스홀더로 대체**: `SensitiveLogPropertyPolicy`를 구성할 때 두 번째 매개변수를 전달합니다. 예: `"***"`, `"已脱敏"`. 빈 문자열은 `[REDACTED]`로 폴백됩니다.
- **중첩 객체 마스킹**: Enricher는 기본적으로 `StructureValue` / `SequenceValue` / `DictionaryValue`를 재귀 처리하므로 추가 설정이 필요하지 않습니다. 속성명이 정책에 매칭될 때만 전체가 대체됩니다.

## 일반적인 오류

| 현상 | 원인 | 처리 |
|------|------|------|
| 로그에 여전히 평문 token이 나타남 | 자격 증명이 메시지 템플릿에 작성됨(예: `Log.Info("token={0}", token)`). 구조화 속성이 아님 | 구조화 속성을 사용하도록 `Log.Information("token={Token}", token)`로 변경 |
| 사용자 정의 필드명이 적용되지 않음 | 필드명에 공백이 포함되어 있거나 정책과 철자가 일치하지 않음 | `_propertyNames`은 `OrdinalIgnoreCase`로 정확히 매칭되므로, 이름을 다시 확인 |
| 정책에 `null` 컬렉션 전달 | 생성자가 `ArgumentNullException`을 던짐 | 최소한 `Array.Empty<string>()`를 전달하거나, 사용자 정의 컬렉션에 대해 null 검사 수행 |
| 모델 필드가 마스킹되지 않음 | `[SensitiveField]`는 ORM 직렬화 레이어에서만 작동하며 Serilog에 자동으로 연결되지 않음 | 로그 측에서 `SensitiveLogEventEnricher`도 함께 사용 |

## 배경(선택)

`SensitiveLogEventEnricher`는 Serilog의 `ILogEventEnricher`를 구현하며, `Enrich` 단계에서 `LogEvent.Properties`를 즉시 교체합니다. 정책 객체는 "민감 필드명 컬렉션 + 대체 텍스트"를 유지하는 역할을 담당합니다. 전체 체인은 이벤트가 Sink에 도달하기 전에 완료되므로, 파일, 콘솔, 원격上报 등 모든 다운스트림에서 원본 값을 더 이상 볼 수 없습니다.
