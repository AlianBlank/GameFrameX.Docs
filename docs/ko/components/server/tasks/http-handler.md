# HTTP 인터페이스 추가(Bag / Mail / Player 등)

이 문서에서는 `GameFrameX.Hotfix` 어셈블리에 HTTP 인터페이스를 새로 추가하여 Bag, Mail, Player 등의 비즈니스 기능을 외부에 제공하는 방법을 안내합니다. 완료하면 프레임워크가 이 인터페이스를 내장 HTTP 서비스에 자동으로 등록하므로, URL로 직접 호출하면 됩니다.

## 사전 조건

- 솔루션 내 `GameFrameX.Hotfix` 프로젝트 구조에 익숙하며, 비즈니스 코드가 `GameFrameX.Hotfix/Logic/Http/<모듈>/`에 위치한다는 것을 알고 있어야 합니다.
- 프로토콜 프로젝트(`GameFrameX.Proto`)에서 `HttpMessageRequestBase` / `HttpMessageResponseBase`의 요청 / 응답 타입과 `ErrorCode` 열거형을 이미 정의했어야 합니다.
- 프레임워크의 HTTP 시작 진입점 이해: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L40-L52)는 `HotfixManager.GetListHttpHandler()`를 통해 `BaseHttpHandler`를 상속하는 모든 클래스를 자동으로 스캔합니다.

## 작업 단계

1. **Handler 클래스 생성**: `GameFrameX.Hotfix/Logic/Http/<모듈>/` 아래에 `BaseHttpHandler`를 상속하는 `sealed class`를 새로 추가합니다. 클래스는 반드시 `GameFrameX.Hotfix` 어셈블리에 위치해야 하며, 그렇지 않으면 아키텍처 분석기 `GFX0003`에 의해 컴파일이 거부됩니다([HttpHandlerAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HttpHandlerAssemblyAnalyzer.cs#L10-L20)).

2. **세 가지 특성 부여**: 클래스에 `HttpMessageMapping`(라우팅), `HttpMessageRequest`(요청 타입), `HttpMessageResponse`(응답 타입, 생략 가능하지만 명시할 것을 강력히 권장)을 모두 표시해야 합니다. Mail 계열은 추가로 강타입 `HttpMessageRequestBase` 오버로드 사용이 요구됩니다:

```csharp
namespace GameFrameX.Hotfix.Logic.Http.Mail;

[HttpMessageMapping(typeof(QueryMailCampaignHttpHandler))]
[HttpMessageRequest(typeof(QueryMailCampaignRequest))]
[HttpMessageResponse(typeof(QueryMailCampaignResponse))]
[Description("Admin 查询运营邮件 Campaign 发布状态")]
public sealed class QueryMailCampaignHttpHandler : BaseHttpHandler
{
    public override async Task<string> Action(string ip, string url, HttpMessageRequestBase requestBase)
    {
        var request = (QueryMailCampaignRequest)requestBase;
        var response = new QueryMailCampaignResponse { Code = MailCampaignErrorCode.Ok };
        // ...비즈니스 로직...
        return HttpJsonResult.SuccessString(response);
    }
}
```

출처: [QueryMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/QueryMailCampaignHttpHandler.cs#L44-L70)

3. **`Action` 메서드 재정의**: 요청 본문 역직렬화 필요 여부에 따라 두 가지 시그니처 중 하나를 선택합니다:
   - 간단한 인터페이스(`ReloadHttpHandler`, `TestHttpHandler`): `Dictionary<string, object> parameters`를 받아 쿼리 파라미터를 직접 파싱합니다.
   - 강타입 인터페이스(Mail, Bag): `HttpMessageRequestBase requestBase`를 받으며, 프레임워크가 역직렬화를 대신 처리해 줍니다.

   반환값은 반드시 `string`이어야 하며, `HttpJsonResult` 유틸리티 메서드(`SuccessString` / `ParamErrorString` 등)를 통해 통일되게 직렬화합니다:

```csharp
public override Task<string> Action(string ip, string url, Dictionary<string, object> parameters)
{
    if (parameters.TryGetValue("version", out var version))
    {
        await HotfixManager.LoadHotfixModule(null, version.ToString());
        return Task.FromResult(HttpJsonResult.SuccessString(null));
    }
    return Task.FromResult(HttpJsonResult.ParamErrorString());
}
```

출처: [ReloadHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/ReloadHttpHandler.cs#L40-L60)

4. **빌드 및 시작**: 저장소 루트 디렉터리에서 빌드를 실행하면 프레임워크가 모든 `BaseHttpHandler` 하위 클래스를 자동으로 스캔하여 `HttpServer.Start(Setting.HttpPort, Setting.HttpsPort, HotfixManager.GetListHttpHandler(), HotfixManager.GetHttpHandler, null, Setting.HttpUrl)`에 등록합니다([AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L49-L51)). 시작 후에는 주석에 표시된 URL로 디버깅할 수 있습니다.

## 일반적인 변형

- **요청 / 응답 본문 없음**(`TestHttpHandler`): `HttpMessageMapping`만 표시하며, 데이터를 반환해야 할 때는 `HttpMessageResponseBase`를 상속하는 클래스를 직접 작성하면 됩니다.
- **이벤트 디스패치 필요**(Bag 아이템 지급): Handler 내에서 `EventDispatcher.Dispatch(...)`를 호출하고 `BagComponentAgent`가 완료될 때까지 비동기로 기다린 뒤, 마지막에 `HttpJsonResult.SuccessString`으로 종합 결과를 반환합니다([ReqPlayerSendItemHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Bag/ReqPlayerSendItemHttpHandler.cs#L45-L80)).
- **GM 계열 읽기 전용 인터페이스**(Player 온라인 목록): 마찬가지로 `Dictionary<string, object> parameters`를 사용하며, Handler 내부에서 SessionManager를 조회합니다. 템플릿은 `GetOnlinePlayerListHttpHandler`를 직접 참고하면 됩니다.
- **운영 메일 4종 세트**: `PreviewMailCampaignHttpHandler` / `PublishMailCampaignHttpHandler` / `QueryMailCampaignHttpHandler` / `RevokeMailCampaignHttpHandler`가 동일한 모듈에서 여러 인터페이스를 구현하는 표준 작성 방식을 보여줍니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 컴파일 시 `GFX0003` 오류 발생 | `BaseHttpHandler` 하위 클래스가 `GameFrameX.Hotfix` 어셈블리에 위치하지 않음 | Handler 클래스를 `GameFrameX.Hotfix/Logic/Http/...` 아래로 이동 |
| 시작 후 접속 시 404 발생 | `[HttpMessageMapping]`을 표시하지 않았거나, 타입 자체가 특성의 제네릭 인자로 전달되지 않음 | 특성 파라미터가 `typeof(YourHandler)` 자체인지 확인 |
| 요청 파라미터를 가져올 수 없음 | `Dictionary<string, object>` 시그니처를 사용했지만 프론트엔드에서 JSON Body를 전송함 | `HttpMessageRequestBase` 오버로드로 변경하고 `[HttpMessageRequest]` 추가 |
| `null` 반환 시 직렬화 실패 | 문자열 대신 객체를 직접 반환함 | `HttpJsonResult.SuccessString(response)`으로 한 번 감싸기 |
| 라우트가 GM 백오피스에서 인식되지 않음 | `[Description]`이 비어 있어 도구가 분류할 수 없음 | 의미 있는 중국어로 `Description("...")` 추가 |

## 배경(선택 사항)

`BaseHttpHandler`는 `GameFrameX.NetWork.HTTP`가 제공하는 이벤트 방식의 기본 클래스이며, 시작 시 `HotfixManager.GetListHttpHandler()`가 모든 비추상 하위 클래스를 리플렉션으로 찾아 `HttpServer`에 넘겨 라우팅 등록을 완료합니다. Mail / Bag / Player 모듈은 디렉터리별로 하위 네임스페이스를 분리하여 GM 백오피스와 자동화 스캔이 모듈별로 분류하기 쉽도록 합니다.
