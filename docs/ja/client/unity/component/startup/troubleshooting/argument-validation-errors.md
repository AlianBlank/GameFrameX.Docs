# 起動時の同期パラメータ検証例外が発生した場合の対処方法

`StartupRunner.Run(...)` を呼び出す際、渡されたパラメータが要件を満たしていない場合(例:`options` が null、`GlobalInfoUrls` が空配列など)、非同期ステートマシンに入る前に**同期的に** `ArgumentNullException` または `ArgumentException` をスローし、失敗結果として返されることはありません。この種の例外は「開発期の設定エラー」に分類されるため、検証段階で直ちに検出し、後続のコルーチンフローを汚染しないようにする必要があります。

## クイック診断

| 例外タイプ | 典型的なメッセージ原文 | 発生箇所 | 修正方針 |
|----------|--------------|----------|----------|
| `ArgumentNullException` | (メッセージなし、`ParamName`=`options`) | `StartupRunner.Run` 入口 | 有効な `StartupOptions` インスタンスを渡す |
| `ArgumentNullException` | (メッセージなし、`ParamName`=`uiHandler`) | `StartupRunner.Run` 入口 | `IStartupUIHandler` を実装して渡す |
| `ArgumentNullException` | (メッセージなし、`ParamName`=`hotfixLauncher`) | `StartupRunner.Run` 入口 | `IHotfixLauncher` を実装して渡す |
| `ArgumentException` | メッセージに `"GlobalInfoUrls"` を含む | `StartupRunner.Run` 入口 | `StartupOptions` に少なくとも1つのグローバル情報 API URL を入力する |
| `ArgumentNullException` | (メッセージなし、`ParamName`=`urls`) | `UrlFailoverRunner` コンストラクタ | URL 配列オブジェクト自体が null でないことを確認する |
| `ArgumentException` | `"URL list must contain at least one URL."` | `UrlFailoverRunner` コンストラクタ | URL 配列に少なくとも1つの要素を含める |
| `ArgumentException` | `"Max attempts per URL must be greater than zero."` | `UrlFailoverRunner` コンストラクタ | `maxAttemptsPerUrl` を `>= 1` に変更する |
| `ArgumentException` | `"Retry delay must be zero or greater."` | `UrlFailoverRunner` コンストラクタ | `retryDelayMs` を `>= 0` に変更する |
| `ArgumentNullException` | (メッセージなし、`ParamName`=`options`) | `StartupHttpParams.FromOptions` | null でない `StartupOptions` を渡す |

例外メッセージ原文とパラメータ名はいずれもソースコードから直接引用されたものであり、[Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L34-L60) と [Runtime/Failover/UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L40) を参照してください。

## 修正手順

### 1. `ArgumentNullException` の修正(options/uiHandler/hotfixLauncher)

`StartupRunner.Run` はコルーチンに入る前に、3つの引数が null かどうかを同期的にチェックします:

```csharp
public static UniTask<StartupResult> Run(
    StartupOptions options,
    IStartupUIHandler uiHandler,
    IHotfixLauncher hotfixLauncher)
```

対応する実装([Runtime/Startup/StartupRunner.cs#L45-L60](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L45-L60)):

```csharp
if (options == null)        throw new ArgumentNullException(nameof(options));
if (uiHandler == null)      throw new ArgumentNullException(nameof(uiHandler));
if (hotfixLauncher == null) throw new ArgumentNullException(nameof(hotfixLauncher));
```

修正方法：呼び出し前の入口で各項目をチェックするか、Inspector / DI コンテナ経由で null でないインスタンスが注入されていることを確認してください。例:

```csharp
if (StartupOptions.Instance == null)
{
    Debug.LogError("StartupOptions 未配置");
    return;
}
if (uiHandler == null || hotfixLauncher == null)
{
    Debug.LogError("UI/Hotfix 启动器未注册");
    return;
}
await StartupRunner.Run(StartupOptions.Instance, uiHandler, hotfixLauncher);
```

### 2. `ArgumentException` の修正(`GlobalInfoUrls` が空の場合)

3つの null チェックを通過した後、`Run` はさらに `options.GlobalInfoUrls` を検証します(対応する実装は [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L37-L60) を参照)。このフィールドが null または長さ 0 の場合、メッセージに `"GlobalInfoUrls"` を含む `ArgumentException` が同期的にスローされます。

修正方法:Unity で `Create > GameFrameX > Startup Options` からアセットを作成した後、Inspector の `GlobalInfoUrls` フィールドにアクセス可能なグローバル情報 API アドレスを少なくとも1つ入力してください(プライマリ/バックアップ URL は配列要素で区別します)。

### 3. `UrlFailoverRunner` がスローする検証例外の修正

`UrlFailoverRunner` は構築時に URL リストとリトライパラメータの完全な検証を行います([Runtime/Failover/UrlFailoverRunner.cs#L19-L34](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L34)):

```csharp
if (urls == null)
    throw new ArgumentNullException(nameof(urls));
if (urls.Length == 0)
    throw new ArgumentException("URL list must contain at least one URL.", nameof(urls));
if (maxAttemptsPerUrl <= 0)
    throw new ArgumentException("Max attempts per URL must be greater than zero.", nameof(maxAttemptsPerUrl));
if (retryDelayMs < 0)
    throw new ArgumentException("Retry delay must be zero or greater.", nameof(retryDelayMs));
```

修正方法：

- `UrlFailoverRunner` のコンストラクタに渡す配列参照が null ではなく、少なくとも1つの URL を含むことを確認してください。
- `maxAttemptsPerUrl` は ≥ 1 である必要があります。
- `retryDelayMs` は ≥ 0 である必要があります(0 は遅延なしのリトライを表し、有効です)。

### 4. `StartupHttpParams.FromOptions` がスローする null 例外の修正

`FromOptions` は `options` が null の場合に `ArgumentNullException` をスローします([Runtime/Http/StartupHttpParams.cs#L94-L99](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L94-L99))。`IStartupHttpParamsProvider` をオーバーライドしている場合は、`FromOptions` を呼び出す前に自分で null チェックを行ってください。

## 検証

- `StartupRunner.Run` の外側で `try/catch (ArgumentException)` / `try/catch (ArgumentNullException)` によりキャッチし、例外タイプと `ParamName`/`Message` が上の表と一致することを確認してください。
- `StartupOptions` アセットを修正した後、Editor で再度 PlayMode に入ると、起動フローは `ProcedureGetAppVersionInfoState` などの後続ノードへ正常に進み、最初のフレームで同期的にスローされることがなくなります。
- `UrlFailoverRunner` を直接構築して使用する場合は、単体テストで空配列や負数のリトライパラメータなどの境界値を渡し、上の表の例外メッセージを再現できることを確認してから修正してください。

## 背景(任意)

`StartupRunner.Run` は同期検証と非同期フローを分離しています。「明らかに間違っている」引数はすべて検証段階で同期的にスローされ、無効な状態が `UniTask` ステートマシンに入ることはありません。ネットワーク、パッチ、リモートサービスで実際に発生した問題のみが `StartupResult` / `StartupFailedEventArgs` を通じて非同期に報告されます。この取り決めは [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/CHANGELOG.md#L103) にも明確に記録されています:"Synchronous validation throws `ArgumentException` for empty `GlobalInfoUrls` before entering async state machine."
