# MongoDB 연결 실패 또는 엔티티 직렬화 오류가 발생하면 어떻게 하나요

서비스 시작 시 `MongoDB connection failed`, `数据库服务启动失败`, `No serializer found for ...`, `An error occurred while deserializing ...` 등의 오류가 발생하면, 이 페이지의 진단 표로 원인을 파악한 뒤 해당 섹션에 따라 수정하세요.

## 빠른 진단

| 증상 (콘솔/로그 원문) | 근본 원인 | 수정 방법 |
|---|---|---|
| `数据库服务启动失败` / `MongoDB connection failed` / `TimeoutException` | `DataBaseUrl`에 도달할 수 없음, 계정/비밀번호 오류, authSource 불일치, 단독 직접 연결 시 `directConnection` 미설정 | 「연결 설정 오류」 참조 |
| `MongoCommandException: Authentication failed` | 사용자 이름/비밀번호 오류 또는 대상 데이터베이스에 계정이 생성되지 않음 | 「인증 실패」 참조 |
| `No serializer found for type X` / `An error occurred while deserializing the X bson element ...` | 엔티티 클래스에 BsonClassMap이 등록되지 않았거나, 기반 클래스의 `BaseCacheState` 관련 필드가 무시되지 않음 | 「엔티티 직렬화 실패」 참조 |
| 시작 시 멈추거나 첫 `Insert`/`Find`에서 `MongoConnectionException` 발생 | Docker 컨테이너가 시작되지 않음, 포트가 점유됨, 또는 서비스가 mongo보다 먼저 시작됨 | 「서비스 의존성과 포트」 참조 |
| 쓰기 후 필드가 전부 `_t` discriminator인데 읽어오면 `null` | 여러 어셈블리에서 동일한 전체 클래스명을 사용하고 `Discriminator`를 설정하지 않았거나, 하위 클래스가 등록되지 않음 | 「엔티티 직렬화 실패 → Discriminator 충돌」 참조 |

## 수정 단계

### 연결 설정 오류

1. 구성 키 `DataBaseUrl`의 작성 방식을 확인하세요. 기본적으로 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L61-L65)의 `Setting.DataBaseUrl`을 통해 `GameDb.Init<MongoDbService>`에 전달되며, 연결 문자열 형식은 MongoDB Driver 요구 사항을 준수해야 합니다.

2. 로컬 Docker 시작 시 [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L2-L13)에 포함된 컨테이너 구성을 사용합니다:

   ```yaml
   mongodb:
     image: mongo
     container_name: mongodb
     ports:
       - "27017:27017"
     volumes:
       - ./running/database:/data/db
     environment:
       - MONGO_INITDB_ROOT_USERNAME=admin
       - MONGO_INITDB_ROOT_PASSWORD=admin
   ```

   이에 해당하는 연결 문자열 예시 (compose의 환경 변수와 일치):

   ```bash
   DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L60-L72)

3. [MongoDB Atlas](https://www.mongodb.com/atlas) 등의 클라우드 서비스를 사용할 때는 `mongodb+srv://` 형식을 유지하고 `retryWrites=true&w=majority`를 함께 지정합니다:

   ```csharp
   DataBaseUrl = "mongodb+srv://gameframex:***@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority",
   DataBaseName = "gameframex",
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L112-L113)

4. 로컬에서 `127.0.0.1`로 직접 연결할 때 `No routing to host`가 발생하면 `directConnection=true`를 추가합니다:

   ```text
   mongodb://admin:admin@127.0.0.1:27017/?authSource=admin&directConnection=true
   ```

### 인증 실패

1. `MONGO_INITDB_ROOT_USERNAME`/`MONGO_INITDB_ROOT_PASSWORD`가 연결 문자열의 계정과 일치하는지 확인합니다.
2. 계정이 `admin`에 생성되어 있고 대상 데이터베이스가 `gameframex`인 경우, 연결 문자열에 반드시 `?authSource=admin`을 포함해야 합니다. 그렇지 않으면 driver가 기본 데이터베이스로 인증을 시도하여 `Authentication failed`가 발생합니다.
3. 직접 생성한 계정에 단일 데이터베이스에만 권한을 부여한 경우: `authSource`는 해당 데이터베이스 이름과 반드시 일치해야 합니다.

### 서비스 의존성과 포트

1. `docker compose up mongodb -d` 실행 후 컨테이너가 정상인지 먼저 확인합니다:

   ```bash
   docker ps --filter name=mongodb
   docker logs mongodb --tail 50
   ```

2. 컨테이너와 게임 프로세스는 반드시 동일한 `gameframex` 네트워크에 있어야 합니다. 게임 프로세스를 단독으로 실행할 때는 `DataBaseUrl`의 호스트명을 `localhost` 또는 해당 IP로 변경하세요.
3. 호스트 포트 `27017`이 점유 중인 경우 compose 매핑을 수정하고(예: `"27018:27017"`), 연결 문자열도 함께 `27018`으로 변경합니다.

### 엔티티 직렬화 실패

1. 시작 시 어셈블리 내에서 `BaseCacheState`/`CacheState`를 상속하는 모든 엔티티를 스캔하여 BsonClassMap에 등록합니다. 등록 진입점은 [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)에 있습니다:

   ```csharp
   var assembly = typeof(AppsHandler).Assembly;
   BsonClassMapHelper.SetConvention();
   foreach (var type in assembly.GetTypes())
   {
       if (!typeof(BaseCacheState).IsAssignableFrom(type)) continue;
       HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
       BsonClassMapHelper.RegisterClass(type);
   }
   ```

   Source: [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)

2. `BsonClassMapHelper`는 자동 매핑을 수행하고 불필요한 필드를 무시합니다. 구현은 [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)를 참고하세요:

   ```csharp
   var bsonClassMap = new BsonClassMap(t);
   bsonClassMap.AutoMap();
   bsonClassMap.SetIgnoreExtraElements(true);
   bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
   BsonClassMap.RegisterClassMap(bsonClassMap);
   ```

   Source: [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

3. `No serializer found for type X`가 발생하는 경우의 일반적인 원인과 처리 방법:
   - 엔티티 클래스가 `BaseCacheState`를 상속하지 않아 등록 절차에서 건너뛰어진 경우 — 엔티티가 `BaseCacheState`를 상속하도록 하거나, 호출 전에 수동으로 `BsonClassMap.RegisterClassMap<T>()`를 실행하세요.
   - 엔티티가 다른 어셈블리(예: `GameFrameX.Hotfix`)에 정의되어 있는데 `CacheStateTypeManager`가 `AppsHandler` 어셈블리만 스캔한 경우 — 핫픽스 진입점에서 등록을 한 번 동기 호출하거나, 스캐너를 확장하여 Hotfix 어셈블리를 포함하세요.
   - 엔티티가 구체화되지 않은 제네릭 매개변수를 사용하는 경우 — 등록 전에 제네릭 인수를 모두 지정하세요.

4. **Discriminator 충돌**: 서로 다른 하위 타입이 동일한 이름을 사용하거나, 어셈블리 간에 동일한 전체 클래스명이 존재하면 역직렬화 시 `null`을 얻게 됩니다. 엔티티 클래스에 명시적으로 지정하세요:

   ```csharp
   [BsonDiscriminator("player_attr_v1")]
   public sealed class PlayerAttributeState : BaseCacheState { /* ... */ }
   ```

5. **기반 클래스 필드 오염**: `BaseCacheState`가 기본으로 가진 딕셔너리/버전 번호 필드를 MongoDB에 쓰고 싶지 않다면 해당 필드에 `[BsonIgnore]`를 추가하세요. `SetIgnoreExtraElements(true)`는 읽기 방향만 무시하므로, 쓰기는 여전히 명시적으로 무시해야 합니다.

6. 시작 순서는 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67)에 의해 보장됩니다: `GameDb.Init` → `ComponentRegister.Init` → `HotfixManager.LoadHotfixModule`. 핫픽스에서 직접 Mongo를 읽는 코드는 반드시 마지막 단계 이후에 배치해야 합니다. 그렇지 않으면 직렬화기가 아직 등록되지 않은 상태에서 `No serializer found`가 발생합니다.

## 검증

1. 서비스를 재시작하고 시작 로그에 다음이 순서대로 나타나는지 확인합니다: `开始启动数据库服务...` → `启动数据库服务 结束...` → `注册组件开始/结束` → `加载热更新模块结束`.
2. Mongo Shell 또는 Compass에서 `db.runCommand({ ping: 1 })`를 실행하면 `{ ok: 1 }`이 반환되어야 합니다.
3. 임의의 엔티티 클래스로 `Insert`/`Find`를 통해 읽기/쓰기 흐름을 한 번 수행하고, 읽어온 필드가 쓴 내용과 일치하는지 확인합니다.
4. 일부러 `DataBaseUrl`을 잘못된 주소로 변경한 뒤 다시 시작하면 즉시 `数据库服务启动失败`가 발생하고 근본 원인 스택이 출력되어야 합니다 — 예외 전파 경로가 정상 동작하는지 확인하는 데 사용합니다.
