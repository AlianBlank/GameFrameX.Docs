# 플랫폼 채널 연동

`PaymentComponent`에 각 플랫폼의 구현 타입 문자열을 구성하면, 프레임워크가 시작 시 플랫폼에 따라 해당 채널 `PaymentManager`(Google / Apple / WebGL / PC)를 자동으로 인스턴스화하며, 비즈니스 코드는 `IPaymentManager`만 대상으로 프로그래밍하면 됩니다. 자체 채널을 연동하려면 `BasePaymentManager`를 상속하고 타입 이름을 Inspector에 입력하기만 하면 됩니다.

## 사전 조건

- 핵심 결제 패키지(`GameFrameX.Payment.Runtime`)가 설치되어 있어야 합니다.
- 씬에 `PaymentComponent`가 부착되어 있어야 하며, 이는 `RequireComponent`를 통해 `GameFrameXPaymentCroppingHelper`를 자동으로 포함합니다.
- 대상 플랫폼의 채널 구현 패키지가 설치되어 있어야 합니다(아래 "채널 타입 대조표" 참조. 각 채널 구현은 해당 네임스페이스의 독립 패키지로 분포되어 있습니다).

## 작업 단계

1. 씬 오브젝트에 컴포넌트를 추가합니다. 메뉴 경로는 `GameFrameX/Payment`입니다(`AddComponentMenu`에서 지정됨):

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
{
    private IPaymentManager _paymentManager;
    [SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
    [SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
    [SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
    [SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
    [SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L28)

2. 대상 플랫폼에 해당하는 채널 구현 패키지를 설치합니다(패키지 이름은 아래 표의 네임스페이스와 일치하며, 예를 들어 Google 채널은 `GameFrameX.Payment.Google.Runtime`에 위치합니다).

3. 채널 타입 이름이 실제 설치된 구현과 일치하는지 확인합니다. 자체 구현으로 교체해야 하는 경우 Inspector에서 해당 플랫폼의 타입 문자열을 직접 수정하면 됩니다.

4. 시작 후 프레임워크가 플랫폼 매크로에 따라 구현을 자동으로 선택합니다:

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

| 플랫폼 매크로 | Inspector 필드 | 기본 구현 타입 |
|--------|----------------|--------------|

## 자체 채널 연동

1. `BasePaymentManager`를 상속합니다(이미 `GameFrameworkModule, IPaymentManager`를 구현하고 있으며, 네 가지 이벤트의 `Raise*` 트리거 메서드가 내장되어 있음). 추상 멤버를 모두 구현합니다:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    /// <summary>
    /// 구매 성공 이벤트
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;

    /// <summary>
    /// 구매 실패 이벤트
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;

    /// <summary>
    /// 구매 기록 조회 결과 이벤트
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

    /// <summary>
    /// 구매 소비 결과 이벤트
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    protected void RaisePurchaseFailed(PaymentEventArgs e)
    {
        OnPurchaseFailed?.Invoke(this, e);
    }

    protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
    {
        OnQueryPurchasesResult?.Invoke(this, e);
    }

    protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
    {
        OnConsumePurchaseResult?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);
}
```

출처: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L67)

나머지 추상 멤버인 `IsReady()`, `SetPredefinedProductIds(List<string>, List<string>)`, `QueryPurchases(PaymentProductType)`, `ConsumePurchase(string)`, `BuyInApp`/`BuySubs`/`Buy`(이미 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`로 표시됨)와 권장되는 `Buy(PurchaseParams)`는 모두 하위 클래스에서 구현해야 하며, 전체 시그니처는 [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L69-L137)를 참고하세요.

2. 채널에 추가 구매 매개변수가 필요한 경우 `PurchaseParams`를 상속하여 필드를 확장합니다(소스 코드 주석: "각 채널은 상속하여 자체 필드를 확장할 수 있음"):

```csharp
/// <summary>
/// 구매 매개변수 기본 클래스, 각 채널은 상속하여 자체 필드를 확장할 수 있음
/// </summary>
public abstract class PurchaseParams
{
    /// <summary>제품 ID 또는 SKU</summary>
    public string ProductId { get; set; }

    /// <summary>주문 ID</summary>
    public string OrderId { get; set; }

    /// <summary>제품 타입</summary>
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

출처: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

3. 구현 클래스의 전체 이름(네임스페이스 포함)을 `PaymentComponent`의 해당 플랫폼 Inspector 필드에 입력하고, 실행 후 `IsReady()`로 채널 초기화가 성공했는지 검증합니다.

## 일반적인 변형

- **Android 채널을 자체 SDK로 교체**: `m_componentAndroidType` 필드는 그대로 유지하고 값을 구현 클래스의 전체 이름(네임스페이스 포함)으로 변경한 후 다시 빌드하면 되며, `PaymentComponent` 코드를 수정할 필요가 없습니다.
- **Mac과 iOS가 Apple 채널 공유**: 기본 구성이 이미 그렇습니다 — `m_componentIOSType`과 `m_componentMacType` 모두 `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`를 가리킵니다.
- **에디터/미지원 플랫폼**: `#else` 분기에 해당하면 본 패키지에 내장된 `DefaultPaymentManager`가 폴백으로 사용되어, 에디터에서 비즈니스 흐름을 검증하기 용이합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()`가 null을 반환함. 일반적으로 채널 구현 클래스 이름을 잘못 쓰거나 해당 어셈블리가 컴파일되지 않은 경우 | Inspector의 플랫폼 타입 문자열이 실제 클래스 전체 이름, 네임스페이스와 일치하는지 확인하고 채널 구현 패키지가 설치되어 있는지 확인 |
| `Utility.Assembly.GetType(componentType)`로 타입을 가져올 수 없음 | 타입 이름이 어셈블리의 전체 이름과 일치하지 않음(철자/네임스페이스 오류) | 채널 구현 패키지에서 `namespace`와 클래스 이름을 확인한 후 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`와 같은 전체 이름을 입력 |
| 에디터에서 구매 호출 시 응답 없음 | `#else` 분기에 해당하여 `DefaultPaymentManager` 폴백 구현을 사용함 | 실기기/대상 플랫폼 빌드로 전환하여 검증하거나, 커스텀 채널 구현을 연동 |
| `Log.Warning("Product ID is null or empty.")` / `"Order ID is null or empty."` | 이전 버전 `BuyInApp`/`BuySubs`/`Buy(productId, ...)`에 빈 `productId` 또는 `orderId`가 전달됨 | 유효한 값을 전달하거나, 권장되는 `Buy(PurchaseParams)` 오버로드로 전환 |

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93)(Fatal 로그 위치); 나머지 경고 메시지는 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L163-L204) 참조

> 참고: `BuyInApp`, `BuySubs`, `Buy(productId, productType, orderId, ...)`는 모두 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`로 표시되어 있으므로, 신규 연동 시 `Buy(PurchaseParams)`를 직접 사용하시기 바랍니다([IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112)).

## 배경

`PaymentComponent`는 `Awake`에서 컴파일 매크로에 따라 `componentType`을 결정하고, `Utility.Assembly.GetType` 리플렉션을 통해 `ImplementationComponentType`을 얻은 다음, `IPaymentManager`를 인터페이스 타입으로 `GameFrameworkEntry`에 등록하고, 이후 `GameFrameworkEntry.GetModule<IPaymentManager>()`를 통해 인스턴스를 가져옵니다. 이를 통해 비즈니스 계층은 인터페이스에만 의존하고, 채널 구현은 Inspector 문자열을 통해 런타임에 주입되어 "하나의 비즈니스 코드, 다중 플랫폼 채널" 전환 방식을 구현합니다. 결제 컴포넌트의 전체 아키텍처와 전체 API에 대해서는 프레임워크 개요 페이지와 API 참조 페이지를 참고하세요.
