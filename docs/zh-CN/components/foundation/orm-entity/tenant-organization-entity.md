# 如何使用租户/组织隔离实体基类

继承 `EntityTenantOrganizationBase`（或其泛型版本）即可让实体同时具备多租户隔离和组织隔离能力——自动携带 `TenantId` 与 `CreateOrganizationId` 字段，并实现 `ITenantIdFilter` 与 `IOrganizationIdFilter` 接口，配合 ORM 过滤器即可按租户/组织自动过滤数据。

## 前置条件

- 已安装 NuGet 包：`GameFrameX.Foundation.Orm.Entity`
- ORM 框架已配置好租户上下文（当前 `TenantId`）与组织上下文（当前 `CreateOrganizationId`），以便过滤器能自动注入
- 数据库表已存在 `TenantId`、`CreateOrganizationId` 列（可空 `long?`）

## 操作步骤

1. **让实体类继承 `EntityTenantOrganizationBase<TKey>`**。指定主键类型（常用 `long` 或 `Guid`），实体自动获得 `TenantId`、`CreateOrganizationId` 两个可空 `long?` 属性。

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L44-L55)

2. **（可选）在实体上标注 `[TenantTable]` 特性**。ORM 会据此启用租户隔离特性：自动注入租户过滤、强制写入租户标识、阻止跨租户访问。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
}
```

Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L63-L72)

3. **使用非泛型版本（主键由基类决定时）**。当 `EntityBase` 已经为你提供了默认主键类型，可以直接继承 `EntityTenantOrganizationBase`，无需指定 `TKey`。

```csharp
public class GameArea : EntityTenantOrganizationBase
{
    public string AreaName { get; set; }
    public bool IsActive { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L64-L76)

4. **按需写入租户与组织字段**。ORM 拦截器会在新增/查询时自动用当前上下文覆盖 `TenantId` 与 `CreateOrganizationId`；如需手动控制，可在业务代码里赋值。

```csharp
var order = new GameOrder
{
    OrderNo      = "O-20260101-0001",
    Amount       = 99.5m,
    CreatedTime  = DateTime.UtcNow,
    // TenantId 与 CreateOrganizationId 由上下文自动填充
};
```

## 常见变体

| 场景 | 选择基类 | 说明 |
|------|----------|------|
| 仅需租户隔离，不区分组织 | `EntityTenantBase<TKey>` | 继承 `ITenantIdFilter`，无 `CreateOrganizationId` 字段 |
| 仅需组织隔离 | 自定义实体实现 `IOrganizationIdFilter` | 仅暴露 `CreateOrganizationId` |
| 同时需要租户 + 组织隔离 | `EntityTenantOrganizationBase<TKey>` | 本页介绍 |
| 主键类型由框架默认决定 | `EntityTenantOrganizationBase`（非泛型） | 不显式传 `TKey` |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 查询结果包含其他租户/组织数据 | 未启用过滤器或上下文未注入 `TenantId`/`CreateOrganizationId` | 检查 ORM 全局过滤器注册；确认每次请求已设置租户/组织上下文 |
| 写入时 `TenantId` 始终为 `null` | 实体类同时被标为全局表，或拦截器顺序问题 | 不要在租户实体上同时标注 `[SystemTable]`；只标 `[TenantTable]` |
| 继承后找不到 `CreateOrganizationId` 字段 | 误继承了 `EntityTenantBase`（仅租户） | 改用 `EntityTenantOrganizationBase` 或其泛型版本 |
| 列名不匹配 | 表结构缺少 `TenantId` 或 `CreateOrganizationId` 列 | 在数据库迁移中新增对应可空 `bigint` 列 |

## 背景(可选)

`EntityTenantOrganizationBase` 同时继承 `EntityTenantBase`（带来 `TenantId` + `ITenantIdFilter`）并实现 `IOrganizationIdFilter`（带来 `CreateOrganizationId`）。两个过滤器接口由 ORM 层识别，对查询自动追加 `WHERE TenantId = ? AND CreateOrganizationId = ?` 条件，对新增自动补齐两个字段。`[TenantTable]` 是表级开关，告诉 ORM 这张表启用租户隔离，与 `[SystemTable]`（全局共享）互斥。

关于多租户隔离的整体设计,见《如何使用租户隔离实体基类》。
