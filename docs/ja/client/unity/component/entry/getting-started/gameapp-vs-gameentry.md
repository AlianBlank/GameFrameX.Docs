# GameApp と GameEntry の2つのアクセス方法の選び方

GameFrameX はフレームワークコンポーネントを取得する2つの方法を提供しています:`GameEntry` はコンポーネントコンテナの低層エントリ(`GameFrameX.Runtime` パッケージで提供)であり、`GameApp` は本リポジトリが `GameEntry` をベースにカプセル化した「静的ファサード(facade)」で、よく使うコンポーネントをプロパティとして公開します。簡単に言うと:ビジネスコードは `GameApp.XXX` を呼び出し、`GameApp` 内部では一律に `GameEntry.GetComponent<XXXComponent>()` を呼び出します。

## 前提条件

- `com.gameframex.unity.entry`(本リポジトリ)がインストール済みであること
- `com.gameframex.unity.runtime` がインストール済みであること。`GameEntry` 型は `GameFrameX.Runtime` 名前空間で定義されているためです

```csharp
using GameFrameX.Runtime; // GameEntry を提供
// GameApp はグローバル名前空間にあるため、using は不要
```

ソース: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L32-L34)

## 2つのアクセス方法の形態比較

| 項目 | `GameEntry` | `GameApp` |
|------|-------------|-----------|
| 所属名前空間 | `GameFrameX.Runtime`(外部パッケージ) | グローバル名前空間(本リポジトリ) |
| 型 | 静的クラス、コンポーネントコンテナを提供 | `static partial class`、コンポーネントごとに1ファイル |
| 呼び出し形式 | `GameEntry.GetComponent<T>()` | `GameApp.<プロパティ名>` |
| 典型的な用途 | カスタムコンポーネントの登録、必要に応じた任意コンポーネントの取得 | 高頻度・常用コンポーネントへのショートカットアクセス |

`GameApp` のプロパティ getter の実装は、単純に `GameEntry.GetComponent<T>()` を1層ラップしたもので、結果を private な静的フィールドにキャッシュしています:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }
    private static BaseComponent _base;
}
```

## 選択の推奨事項

1. **日常的なビジネス開発では、`GameApp` を優先して使う**
   - コードが短く、可読性が高い:`GameApp.Base`、`GameApp.Mono`。
   - コンポーネントの具体的な型名を覚える必要がなく、IDE の自動補完で現在のパッケージにカプセル化済みのコンポーネントが一覧表示されます。
   - キャッシュにヒットした後はフィールド読み取りとなり、ほぼゼロオーバーヘッドです。

2. **本リポジトリでカプセル化されていないコンポーネントにアクセスする場合は、直接 `GameEntry` を使う**
   - 例えば、自分でカスタマイズした `MyComponent` をフレームワークに登録した場合、`GameEntry.GetComponent<MyComponent>()` でしかアクセスできません。
   - パッケージ/モジュール間の境界をまたぐコードを書く場合は、`GameEntry` を優先し、`GameApp` へのハード依存を避けてください。

3. **新しいコンポーネントを登録する際は、両方とも1箇所ずつ修正が必要**
   - `GameEntry.RegisterComponent<T>()` で登録を完了した後、ビジネス側から `GameApp.My` のようなプロパティアクセスを可能にしたい場合は、本リポジトリに `GameApp.My.cs` という partial ファイルを新規追加し、上記のテンプレートに従って getter とキャッシュフィールドを1層ラップするだけで済みます。

## 操作手順:`GameApp` プロパティを新規追加する

1. `Runtime/` 配下に `GameApp.My.cs` を新規追加します(必ず `partial` を使用し、`GameApp` と同じ名前空間にします)。

```csharp
public static partial class GameApp
{
    public static MyComponent My
    {
        get
        {
            if (_my == null)
            {
                _my = GameEntry.GetComponent<MyComponent>();
            }
            return _my;
        }
    }

    private static MyComponent _my;
}
```

2. フレームワークの起動フロー内で `GameEntry.RegisterComponent<MyComponent>()` を使って登録を完了します。
3. ビジネス側はそのまま `GameApp.My.DoSomething()` を呼び出すだけで使えます。

ソース: テンプレートの参考 [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

## よくあるエラー

| 症状 | 原因 | 対処 |
|------|------|------|
| `GameApp.Base` で `null` が取得される / 例外がスローされる | フレームワークの起動がまだ完了していない、または対応するコンポーネントが `RegisterComponent` されていない | 起動フローで `RegisterComponent<BaseComponent>` が呼ばれているか確認;ホットアップデート/再起動のシーンではタイミングに注意 |
| コンパイルエラーで `GameEntry` が存在しない | `using GameFrameX.Runtime;` がない | ファイルの先頭に `using GameFrameX.Runtime;` を追加 |
| `GameApp.Mono` などのプロパティが見つからない | 現在使用しているのが `com.gameframex.unity.entry` パッケージではない、またはパッケージのバージョンが古く対応する partial ファイルが含まれていない | 本パッケージを最新バージョンにアップグレード |
| 自分で書いた `GameApp.My` が `missing partial` エラーになる | 新しいファイルで `public static partial class GameApp` が宣言されていない | `partial` キーワードを補い、既存の `GameApp` と同じ名前にする |

## 背景(任意)

`GameEntry` はコンポーネントの辞書(`RegisterComponent` / `GetComponent<T>()`)を管理しており、フレームワークコンポーネントの「コンテナのルート」です。`GameApp` は実際の作業は行わず、高頻度のコンポーネントを取得して静的フィールドにキャッシュするだけで、呼び出し側がジェネリックを1回、クラス名を1回書く手間を省きます。2つの方法でアクセスするのは同一のコンポーネントインスタンスです。
