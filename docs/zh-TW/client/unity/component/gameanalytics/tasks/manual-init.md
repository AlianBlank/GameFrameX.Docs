# 如何手動初始化（ManualInit 使用情境）

在 GameAnalytics 元件自動初始化完成之後，呼叫 `GameAnalyticsComponent.ManualInit(extraArgs)` 可把登入後的玩家 ID、渠道號等**執行期才能取得的參數**補充傳給支援手動初始化的資料分析管理器。典型情境：SDK 需要等玩家登入拿到帳號後才能真正上報，這時在登入成功回呼裡呼叫一次 `ManualInit` 即可。

## 前置條件

- 場景中已有 `GameAnalyticsComponent`（選單 `Game Framework/GameAnalytics`），並在 Inspector 的「遊戲資料分析元件列表，按序上報」中配置了至少一個 `ComponentType` 與其 `Setting` 鍵值對。
- 目標管理器實作了 `IsManualInit()` 並在需要手動初始化時回傳 `true`——只有這類管理器才會接收 `ManualInit` 傳入的參數。

## 操作步驟

1. **保持元件自動初始化可用。** 元件在 `OnEnable()` 裡自動執行一次 `Init()`，按 Inspector 配置反射建立各管理器並呼叫其 `Init(args)`（參數來自 `Setting` 鍵值對），隨後把內部標記 `m_IsInit` 設為 `true`：

    ```csharp
    private void OnEnable()
    {
        Init();
    }
    ```

    來源：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L27-L30)

2. **確認自動初始化已生效。** 檢查 Console 沒有出現 `Can not find component type '...'` 報錯；該報錯表示 Inspector 裡的 `ComponentType` 填錯，對應管理器不會被建立，後續 `ManualInit` 也輪不到它。

3. **在合適時機呼叫 `ManualInit`，傳入執行期參數。** 例如玩家登入成功、取得帳號 ID/渠道資訊之後，透過場景中的 `GameAnalyticsComponent` 實例呼叫一次：

    ```csharp
    Dictionary<string, string> extraArgs = new Dictionary<string, string>();
    // 填入執行期才能確定的資料，例如帳號、渠道等
    gameAnalyticsComponent.ManualInit(extraArgs);
    ```

    元件層的真實實作如下——注意它先檢查 `m_IsInit`，再只對 `IsManualInit()` 為 `true` 的管理器轉發參數：

    ```csharp
    public void ManualInit(Dictionary<string, string> extraArgs)
    {
        if (!m_IsInit)
        {
            return;
        }

        foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
        {
            if (gameAnalyticsManager.IsManualInit())
            {
                gameAnalyticsManager.ManualInit(extraArgs);
            }
        }
    }
    ```

    來源：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L82-L100)

4. **（可選）在手動初始化後再補玩家 ID 等通用資訊。** `ManualInit` 只是透傳參數，不負責後續屬性；登入後可繼續呼叫 `SetPlayerId(playerId)` / `SetPublicProperties(key, value)`，這些方法同樣要求 `m_IsInit == true`。

## 常見變體

- **無額外參數、僅觸發各 SDK 的「就緒」回呼**：傳入空字典呼叫 `gameAnalyticsComponent.ManualInit(new Dictionary<string, string>());` 即可，管理器側自行決定如何處理。
- **自訂管理器接入手動初始化**：繼承 `BaseGameAnalyticsManager` 並實作兩個抽象方法，把 `IsManualInit()` 回傳 `true` 即可讓元件把 `extraArgs` 轉發給你：

    ```csharp
    public abstract void Init(Dictionary<string, string> args);
    public abstract void ManualInit(Dictionary<string, string> args);
    ...
    public abstract bool IsManualInit();
    ```

    來源：[BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L28-L50)

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| 呼叫了 `ManualInit` 沒有任何反應 | 元件的 `Init()` 尚未執行，`m_IsInit` 為 `false`，方法第一行直接 `return` | 等元件 `OnEnable()` 完成自動初始化後再呼叫（登入回呼等時機通常已滿足） |
| 某個管理器收不到 `extraArgs` | 該管理器的 `IsManualInit()` 回傳 `false` | 在管理器實作中讓 `IsManualInit()` 回傳 `true` |
| Console 輸出 `Can not find component type '...'` | Inspector 中 `ComponentType` 型別名填寫錯誤或組件未編譯 | 修正 `ComponentType`，確保型別實作 `IGameAnalyticsManager` |
| SDK 參數仍是 Inspector 裡 `Setting` 的舊值 | `ManualInit` 傳入的是補充參數，不會替換 `Init` 時由 `Setting` 提供的基礎參數 | 基礎配置仍放在 Inspector 的 `Setting`；執行期資料走 `ManualInit` |

## 背景

GameAnalytics 採用「兩層初始化」：`Init(args)` 在元件 `OnEnable()` 時用 Inspector `Setting` 的靜態配置自動執行，負責建立管理器；`ManualInit(extraArgs)` 面向需要執行期資料（如登入後的帳號）的 SDK，由業務在明確時機顯式觸發，且只作用於宣告了 `IsManualInit() == true` 的管理器。完整介面定義見 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L28)。
