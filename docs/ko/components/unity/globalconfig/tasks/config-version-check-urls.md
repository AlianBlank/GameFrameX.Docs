# 응용 프로그램 및 리소스 버전 검사 URL 구성 방법

GlobalConfig는 서버에서 전달된 전역 구성 객체를 통해 응용 프로그램 버전 검사 주소와 리소스 버전 검사 주소를 반환하며, 프런트엔드는 `CheckAppVersionUrl` 및 `CheckResourceVersionUrl` 두 필드만 소비하여 해당 버전 검사 요청을 시작하면 됩니다.

## 사전 조건

- `com.gameframex.unity.globalconfig` 패키지가 설치되어 있으며 진입점 컴포넌트 등록이 완료되었습니다.
- 비즈니스 측에 전역 정보를 반환하는 인터페이스가 배포되어 있으며, 인터페이스 JSON에 `CheckAppVersionUrl` 및 `CheckResourceVersionUrl` 필드가 포함되어 있습니다.
- 클라이언트가 해당 인터페이스가 있는 호스트 서버 주소에 액세스할 수 있습니다(`ResponseGlobalInfo.HostServerUrl` 필드 참조).

## 작업 단계

1. 서버 전역 정보 인터페이스의 응답 JSON에서 두 URL 필드가 모두 반환되는지 확인하고, 필드 이름은 클라이언트 모델과 엄격히 일치해야 합니다:

   ```json
   {
     "CheckAppVersionUrl": "https://your-cdn.example.com/api/app/version",
     "CheckResourceVersionUrl": "https://your-cdn.example.com/api/resource/version"
   }
   ```

2. 클라이언트에서 해당 JSON을 구문 분석한 후 `ResponseGlobalInfo`의 두 문자열 속성을 직접 읽습니다. 두 속성 모두 `string`이며 기본값은 `null`입니다.

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;

   var info = new ResponseGlobalInfo
   {
       CheckAppVersionUrl      = "https://your-cdn.example.com/api/app/version",
       CheckResourceVersionUrl = "https://your-cdn.example.com/api/resource/version",
       HostServerUrl           = "https://your-cdn.example.com",
       AOTCodeList             = "[]",
       Content                 = "{}"
   };
   ```

   Source: [Runtime/GlobalConfig/ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L1-L28)

3. 얻은 URL을 각각 응용 프로그램 버전 검사 및 리소스 버전 검사 모듈에 전달하여 해당 요청 객체를 시작합니다:

   ```csharp
   // 응용 프로그램 버전 검사 요청
   var appVersionReq = new RequestGameAppVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAppVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAppVersion.cs)

4. 리소스 버전 검사는 독립적인 요청 객체를 사용하며, 필드도 플랫폼, 채널, 언어 등 기본 정보입니다:

   ```csharp
   var assetReq = new RequestGameAssetPackageVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs)

5. 서버는 응용 프로그램 버전 검사 요청을 처리할 때 `ResponseGameAppVersion`를 반환하며, 여기에는 `IsForce`, `IsUpgrade`, `AppDownloadUrl`, `UpdateAnnouncement`, `UpdateTitle` 등 업그레이드 정보가 포함됩니다:

   ```csharp
   public class ResponseGameAppVersion
   {
       public bool   IsForce           { get; set; }
       public string AppDownloadUrl    { get; set; }
       public bool   IsUpgrade         { get; set; }
       public string UpdateAnnouncement{ get; set; }
       public string UpdateTitle       { get; set; }
   }
   ```

## 일반적인 변형

- **동일 주소 재사용**: 응용 프로그램과 리소스 버전 검사가 동일한 게이트웨이를 공유하는 경우 두 URL이 동일한 주소를 반환하도록 하고 게이트웨이 내에서 path 라우팅으로 구분할 수 있습니다.
- **점진적 분할 서버**: 서로 다른 채널(`Channel`)이 서로 다른 URL을 사용하는 경우 서버 측에서 요청 본문의 `Channel` 필드에 따라 해당 주소를 반환하면 되며, 클라이언트 코드는 변경되지 않습니다.

## 일반적인 오류

- **필드 이름 오타**: 인터페이스 필드 이름은 `CheckAppVersionUrl`, `CheckResourceVersionUrl`이어야 하며 첫 글자는 대문자, 카멜 표기법을 사용해야 합니다. 그렇지 않으면 `ResponseGlobalInfo` 역직렬화 후 두 속성이 모두 `null`이 됩니다.
- **HTTPS 미준비**: URL은 HTTPS를 사용해야 하며, 그렇지 않으면 Android 9+에서 기본 네트워크 정책에 의해 차단됩니다.
- **호스트 주소 구성 잊음**: `CheckAppVersionUrl`은 실제로 상대 경로 또는 하위 도메인만 전달하며, 실제 액세스 지점에는 `ResponseGlobalInfo.HostServerUrl`도 필요합니다. 그렇지 않으면 요청에서 호스트를 찾을 수 없습니다.

## 배경 (선택 사항)

`ResponseGlobalInfo`는 GlobalConfig 패키지에서 정의된 가장 간단한 DTO로, "주소를 클라이언트에 알리는" 역할만 담당합니다. 패키지 내에는 내장 HTTP 클라이언트가 없으며, 실제 요청과 캐싱은 상위 비즈니스 모듈에서 `RequestGameAppVersion` / `RequestGameAssetPackageVersion`을 기반으로 시작되며, 전역 구성과 분리되어 있어 다양한 네트워크 스택 통합이 용이합니다.
