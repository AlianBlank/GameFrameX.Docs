# Pause and Resume All Downloads

With a single `DownloadComponent.Paused` toggle, you can pause / resume **all** waiting or downloading tasks at once, without having to operate on each task serial number individually.

## Prerequisites

- A `DownloadComponent` has been attached in the scene and fully initialized (after `OnInit`)
- Tasks have already been added to the download queue via `AddDownload` or `AddDownloadAsync`

## Steps

1. **Get a reference to the download component**

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   ```

2. **Pause all downloads**

   Set `Paused` to `true`; the manager will stop dispatching tasks from the waiting queue to idle agents. Tasks already downloading will complete normally, but no new tasks will be started.

   ```csharp
   downloadComponent.Paused = true;
   ```

   Source: [DownloadComponent.cs#L69-L73](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L69-L73)

3. **Check whether it is currently paused**

   ```csharp
   if (downloadComponent.Paused)
   {
       // Currently paused; show a UI prompt
   }
   ```

   Source: [IDownloadManager.cs#L44-L48](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/IDownloadManager.cs#L44-L48)

4. **Resume all downloads**

   Set `Paused` to `false`; tasks in the waiting queue will immediately continue to be dispatched by priority.

   ```csharp
   downloadComponent.Paused = false;
   ```

   Source: [DownloadManager.cs#L80-L83](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L80-L83)

5. **Typical usage: with UI buttons**

   ```csharp
   public void OnPauseButtonClick()
   {
       GameEntry.GetComponent<DownloadComponent>().Paused = true;
   }

   public void OnResumeButtonClick()
   {
       GameEntry.GetComponent<DownloadComponent>().Paused = false;
   }
   ```

## Common Variants

- **Automatically pause when the app goes to the background**: Set `Paused = true` in `OnApplicationPause(true)`, and set it to `false` in `OnApplicationPause(false)` when returning to the foreground.
- **Pause only specific tasks**: This switch is global; if you only want to pause a specific task, you can remove it from the waiting queue or implement separate pause logic (this framework does not provide a per-task `Pause`).
- **Check the number of tasks affected by the pause**: You can see the number of waiting tasks via `WaitingTaskCount`, but you cannot directly distinguish between "waiting due to pause" and "normally queued".

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Some tasks are still downloading after setting `Paused = true` | Tasks already dispatched to agents are not forcibly interrupted; only new task starts are blocked | This is expected behavior; wait for current tasks to finish naturally, or call `RemoveDownload` first |
| Downloads do not resume after `Paused = false` | Tasks have already reached the `Done` / `Error` terminal states, or all agents are occupied | Check `WorkingAgentCount` and the task `Status` |
| Exceptions such as `KeyNotFoundException` are thrown | Called before `DownloadComponent` is initialized | Make sure `GameEntry` has completed initialization |

## Background (Optional)

`Paused` is actually just a boolean pass-through of `DownloadTaskPool.Paused`. The manager checks this flag every frame when scheduling tasks to decide whether to dispatch new tasks from the waiting queue, so the switching overhead is extremely low, making it suitable for frequent toggling.
