# 如何處理支付結果事件

在 `PaymentComponent` 上訂閱 4 個支付事件（購買成功、購買失敗、查詢購買紀錄結果、消耗購買結果），在回呼中根據 `PaymentEventArgs.ResultCode` 分發處理，並使用 `PurchaseToken` 完成消耗。全部 API 定義於 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64) 與 [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)。

## 前置條件

- 場景中已存在 GameFrameX 根物件，並掛有 `PaymentComponent`（選單 `GameFrameX/Payment`，元件要求同時存在 `GameFrameXPaymentCroppingHelper`）。
- 已呼叫 `Init()` 初始化支付管理器，且 `IsReady()` 回傳 `true` 後再發起購買：

```csharp
// 簽名：public void Init(bool isDebug = false, bool isClientVerify = true)
// 簽名：public bool IsReady()
paymentComponent.Init(isDebug: false, isClientVerify: true);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115)

## 操作步驟

1. 取得 `PaymentComponent` 引用（例如透過 GameFrameX 模組入口）。
2. 在遊戲啟動階段訂閱事件，在銷毀階段對稱退訂（`PaymentComponent` 直接透傳到內部 `IPaymentManager`）：

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseSuccess += OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed += OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult += OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult += OnConsumePurchaseResult;

// 退出/銷毀時
paymentComponent.OnPurchaseSuccess -= OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed -= OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult -= OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult -= OnConsumePurchaseResult;
```

事件在元件上的真實宣告如下（`add`/`remove` 直接轉發給管理器）：

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}

public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L64)

3. 在回呼中按 `ResultCode` 分支處理，並透過 `PaymentEventArgs` 的欄位取得資料：

```csharp
private void OnPurchaseSuccess(object sender, PaymentEventArgs e)
{
    // e.ProductId / e.OrderId / e.PurchaseToken / e.PurchaseData / e.CustomData
}

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    switch (e.ResultCode)
    {
        case PaymentResultCode.Cancelled:
            // 使用者主動取消，一般靜默處理
            break;
        case PaymentResultCode.NetworkError:
        case PaymentResultCode.ServiceUnavailable:
            // 提示稍後重試
            break;
        case PaymentResultCode.ItemAlreadyOwned:
        case PaymentResultCode.VerifyFailed:
        default:
            // 使用 e.ErrorMessage 展示或回報
            break;
    }
}
```

4. 一次性商品發放成功後，使用回呼中的 `PurchaseToken` 呼叫 `ConsumePurchase` 消耗購買，其結果同樣透過 `OnConsumePurchaseResult` 事件回傳：

```csharp
// 簽名：public void ConsumePurchase(string purchaseToken)
paymentComponent.ConsumePurchase(e.PurchaseToken);
```

## 常見變體

- **補單/恢復購買**：呼叫 `QueryPurchases(PaymentProductType)` 後監聽 `OnQueryPurchasesResult`，對 `ResultCode == PaymentResultCode.Success` 的歷史訂單逐個發放並 `ConsumePurchase(e.PurchaseToken)`。
- **只關心結果碼**：`OnPurchaseSuccess` 與 `OnPurchaseFailed` 均攜帶同一 `PaymentEventArgs` 結構，失敗情境額外依賴 `ErrorMessage`。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 日誌出現 `You are using DefaultPaymentManager which is a stub...` | Editor/非行動平台落到佔位實作，事件不會觸發 | 串接通路實作（如 Google/Apple），或在實機驗證 |
| 日誌出現 `Pay Manager is invalid.` | 管理器模組未正確載入 | 檢查 `PaymentComponent` 與裁剪輔助元件是否齊全 |
| 日誌出現 `Purchase token is null or empty.` | 呼叫 `ConsumePurchase` 時傳了空權杖 | 使用回呼回傳的 `e.PurchaseToken` |

上述警告/錯誤原文來自 [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L48) 與 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L152)。

## 驗證

- 訂閱後發起一次 `Buy(new PurchaseParams(...))`，確認 `OnPurchaseSuccess` 或 `OnPurchaseFailed` 至少觸發一次，且 `e.ProductId`、`e.OrderId` 與發起參數一致。
- `ConsumePurchase` 呼叫後確認 `OnConsumePurchaseResult` 回傳且 `ResultCode == PaymentResultCode.Success`。

## 背景

`PaymentComponent` 是薄封裝：4 個事件透過 `add`/`remove` 存取子直接轉發給平台實作（Android 為 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`，iOS/macOS 為 `Apple.Runtime.ApplePaymentManager`，WebGL/PC 各有對應實作，其餘平台回退到 `DefaultPaymentManager` 佔位）。因此事件處理邏輯與平台無關，統一在元件層訂閱即可。
