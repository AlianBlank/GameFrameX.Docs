# 하트비트 메커니즘 구성(앱 포커스 상실/획득 전략 포함)

하트비트는 "채널 레벨 구성 + 하트비트 핸들러" 두 부분으로 구성됩니다: 네트워크 채널에 `HeartBeatInterval`(기본 30초)을 설정하고 `IPacketHeartBeatHandler` 핸들러를 등록하면 연결이 해당 간격으로 하트비트 패킷을 전송합니다. 추가로 `NetworkComponent`에서 Focus Heartbeat를 체크하면 앱의 포커스 상실/획득에 따라 하트비트가 자동으로 시작/중지되며, 하트비트 유실 시 `NetworkMissHeartBeatEventArgs` 이벤트를 통해 비즈니스 계층에 알립니다.

## 사전 조건

- com.gameframex.unity.network 패키지가 설치되어 있고, 씬에 GameFrameX Entry 및 `NetworkComponent` 컴포넌트가 존재해야 합니다(메뉴 `GameFrameX/Network`).
- 하트비트 메시지 구조를 커스터마이징해야 하는 경우 `IPacketHeartBeatHandler`를 구현합니다. 해당 인터페이스는 하트비트 간격 속성을 제공하도록 요구합니다:

```csharp
public interface IPacketHeartBeatHandler
{
    float HeartBeatInterval { get; }
}
```

출처: [IPacketHeartBeatHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketHeartBeatHandler.cs#L11)

## 작업 단계

1. `NetworkComponent`의 Inspector 패널에서 **Focus Heartbeat** 필드(해당 `m_FocusHeartbeat`, 기본값 `false`)를 체크하여 포커스 상실/획득 전략을 활성화합니다:

```csharp
/// <summary>
/// 애플리케이션이 포커스를 획득했을 때 하트비트 패킷을 전송할지 여부입니다. 기본값은 false입니다.
/// </summary>
[SerializeField] private bool m_FocusHeartbeat = false;
```

출처: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L65-L68)

2. 체크하면 Unity의 포커스 콜백이 포커스 상태를 네트워크 매니저에 동기화합니다 — 포커스를 잃으면 `hasFocus`가 `false`, 다시 획득하면 `true`가 되며, 추가 코드가 필요 없습니다:

```csharp
/// <summary>
/// 애플리케이션이 포커스를 획득하거나 상실할 때 호출됩니다.
/// </summary>
/// <param name="hasFocus">애플리케이션이 포커스를 획득했는지 여부입니다.</param>
private void OnApplicationFocus(bool hasFocus)
{
    if (!m_FocusHeartbeat)
    {
        return;
    }

    m_NetworkManager.SetFocusHeartbeat(hasFocus);
    Log.Info($"SetFocusHeartbeat: {hasFocus}");
}
```

출처: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L79-L92)

3. `NetworkComponent.CreateNetworkChannel`를 통해 채널을 생성합니다(내부에서 이벤트 및 RPC 타임아웃이 자동으로 연결됨):

```csharp
public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
{
    GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
    var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
    networkChannel.SetIgnoreLogNetworkIds(m_IgnoredSendNetworkIds, m_IgnoredReceiveNetworkIds);
    return networkChannel;
}
```

출처: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L182)

4. 획득한 `INetworkChannel`에 하트비트 핸들러를 등록하고 필요에 따라 하트비트 매개변수를 조정합니다:

```csharp
INetworkChannel channel = networkComponent.CreateNetworkChannel("Main", new MyChannelHelper());
channel.RegisterHeartBeatHandler(new MyHeartBeatHandler());
channel.HeartBeatInterval = 15f;                      // 단위: 초, 기본값 30f
channel.ResetHeartBeatElapseSecondsWhenReceivePacket = true; // 아무 패킷이나 수신하면 타이머 리셋
```

출처: [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L174)

5. 하트비트 유실 이벤트를 구독합니다. `NetworkComponent`는 `Awake`에서 매니저 이벤트를 GameFrameX 이벤트 시스템으로 포워딩하므로, 비즈니스 계층은 `NetworkMissHeartBeatEventArgs`만 리스닝하면 됩니다:

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
m_NetworkManager.NetworkMissHeartBeat += OnNetworkMissHeartBeat;
m_NetworkManager.NetworkError += OnNetworkError;
```

출처: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L109-L113)

이벤트 인자는 `NetworkMissHeartBeatEventArgs.Create(INetworkChannel, int missCount)`로 생성되며, 유실 횟수 `MissCount`를 포함합니다:

```csharp
public static NetworkMissHeartBeatEventArgs Create(INetworkChannel networkChannel, int missCount)
{
    NetworkMissHeartBeatEventArgs networkMissHeartBeatEventArgs = ReferencePool.Acquire<NetworkMissHeartBeatEventArgs>();
    networkMissHeartBeatEventArgs.NetworkChannel = networkChannel;
```

출처: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L81-L84)

## 채널 하트비트 관련 멤버 빠른 참조

`INetworkChannel`에서 하트비트와 관련된 멤버(모두 인터페이스에서 선언됨):

| 멤버 | 시그니처/타입 | 설명 |
|------|-----------|------|
| `HeartBeatInterval` | `float { get; set; }` | 하트비트 간격(초), 런타임 중 수정 가능; 음수 값은 검증에서 거부됨 |
| `HeartBeatElapseSeconds` | `float { get; }` | 현재 하트비트 경과 시간, 읽기 전용 |
| `MissHeartBeatCount` | `int { get; }` | 현재 누적 하트비트 유실 횟수, 읽기 전용 |
| `ResetHeartBeatElapseSecondsWhenReceivePacket` | `bool { get; set; }` | 아무 패킷이나 수신 시 하트비트 타이머를 리셋할지 여부 |
| `PacketHeartBeatHandler` | `IPacketHeartBeatHandler { get; }` | 현재 등록된 하트비트 핸들러 |
| `RegisterHeartBeatHandler` | `void RegisterHeartBeatHandler(IPacketHeartBeatHandler handler)` | 하트비트 핸들러 등록 |
| `RegisterHandler` | `[Obsolete("Use RegisterHeartBeatHandler instead")]` | 이전 등록 인터페이스, 더 이상 사용되지 않음 |

출처: [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L82) · [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L174) · [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L180-L181)

채널 구현의 기본 간격은 30초입니다(`private const float DefaultHeartBeatInterval = 30f;`), 출처: [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L52)

## 검증

`NetworkComponent`가 부착된 오브젝트를 선택하면 Inspector에서 각 채널의 하트비트 상태를 실시간으로 표시합니다:

```csharp
EditorGUILayout.LabelField("Miss Heart Beat Count", networkChannel.MissHeartBeatCount.ToString());
EditorGUILayout.LabelField("Heart Beat", Utility.Text.Format("{0:F2} / {1:F2}", networkChannel.HeartBeatElapseSeconds, networkChannel.HeartBeatInterval));
```

출처: [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L109-L110)

런타임에 앱을 백그라운드로 전환했다가 다시 돌아오면, Focus Heartbeat를 체크한 경우 Console에 `SetFocusHeartbeat: False/True` 로그가 출력되어 포커스 전략이 적용되었음을 확인할 수 있습니다.

## 일반적인 변형

- **비즈니스 패킷에만 관심을 두고 독립적인 하트비트 패킷을 전송하지 않으려는 경우**: `ResetHeartBeatElapseSecondsWhenReceivePacket`을 `true`로 설정하면 어떤 패킷이든 수신 시 타이머가 리셋되어, 실제로 오랫동안 데이터가 없을 때만 하트비트 유실로 판정합니다.
- **런타임 중 하트비트 빈도 동적 조정**: 채널에 직접 `channel.HeartBeatInterval = 새 값;`을 할당하면 설정자가 즉시 적용되며, 음수 값은 검증에서 거부됩니다(CHANGELOG의 "HeartBeatInterval 음수 값 검증 추가" 항목 참조, 출처: [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md#L77)).
- **다중 채널 차별화 하트비트**: 각 채널이 각자 `RegisterHeartBeatHandler`를 호출하고 자신만의 `HeartBeatInterval`을 설정하며, `NetworkComponent`의 Focus Heartbeat 스위치는 모든 채널에 일괄 적용됩니다.

## 일반적인 오류

| 현상 | 원인 | 해결 |
|------|------|------|
| 백그라운드 전환/포그라운드 복귀 후 하트비트 동작이 변하지 않음 | `m_FocusHeartbeat`가 여전히 기본값 `false`이며 `OnApplicationFocus`가 바로 return함 | Inspector에서 Focus Heartbeat 체크 |
| 하트비트 유실 알림을 받지 못함 | 매니저 이벤트만 구독하고 이벤트 시스템을 통해 리스닝하지 않았거나, `NetworkComponent.Start`에서 `EventComponent`를 가져오지 못함(로그 `Event component is invalid.`) | 씬에 Event 컴포넌트가 존재하는지 확인하고 `NetworkMissHeartBeatEventArgs`를 리스닝 |
| 하트비트 간격 설정 시 오류/무효 | 음수 값을 전달함, `HeartBeatInterval`에 음수 값 검증이 추가됨 | 양수를 전달(단위: 초) |
| `RegisterHandler` 호출 시 컴파일 경고/오류 발생 | 해당 메서드에 `[Obsolete("Use RegisterHeartBeatHandler instead")]`가 표시되어 있음 | `RegisterHeartBeatHandler`로 변경 |
| 하트비트 간격이 적용되지 않음 | 핸들러 자체의 `IPacketHeartBeatHandler.HeartBeatInterval`이 채널 설정과 충돌하거나 핸들러가 등록되지 않음 | 먼저 `RegisterHeartBeatHandler`를 호출한 후 채널 `HeartBeatInterval` 설정 |

## 배경

하트비트 타이밍은 채널 내부(`NetworkManager.NetworkChannelBase`)에서 이루어집니다: 기본 간격은 30초이며, 누적 유실 횟수는 `MissHeartBeatCount`로 기록됩니다. `ProcessHeartBeat`에서 연결 끊김을 트리거할 때 `Close` 호출을 먼저 락 외부로 이동시켜 중첩 락으로 인한 데드락을 방지합니다([CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md#L98) 참조). 포커스 전략은 `NetworkComponent`가 Unity의 `OnApplicationFocus` 콜백을 수신한 후 `INetworkManager.SetFocusHeartbeat(bool)`를 호출하는 방식으로 구현되므로, 이 전략은 매니저 하위의 모든 채널에 적용됩니다. 네트워크 패킷 처리 파이프라인의 전체 구조에 대해서는 《네트워크 컴포넌트 개요》를 참조하십시오.
