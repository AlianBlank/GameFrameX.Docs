# 出現 DefaultPaymentManager 佔位警告怎麼辦

當你在 Unity Console 中看到 `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).` 警告時，表示目前 `PaymentComponent` 沒有解析到任何渠道（Google / Apple / WebGL / PC）的支付管理器，而是退回到了佔位實作 `DefaultPaymentManager`。這不是錯誤，佔位實作只會印出警告並回傳「未實作」，但所有支付呼叫都不會真正運作；解決辦法是讓執行平台命中對應的渠道實作型別。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| Console 印出 `You are using DefaultPaymentManager which is a stub. ...` | `PaymentComponent.Awake()` 中平台巨集未命中任何分支，`componentType` 落到 `typeof(DefaultPaymentManager).FullName` | 檢查目前執行平台巨集與 `m_component*Type` 欄位設定，見下文[修復步驟](#修復步驟) |
| `Init(...)`、`Buy(...)`、`QueryPurchases(...)`、`ConsumePurchase(...)` 等任意呼叫都印出同一條警告 | `DefaultPaymentManager` 的所有方法均為空實作，只 `Log.Warning(NotImplWarning)` | 整合渠道套件後重新呼叫，見[修復步驟](#修復步驟) |
| `IsReady()` 始終回傳 `false`，永遠無法發起購買 | `DefaultPaymentManager.IsReady()` 硬編碼回傳 `false` | 屬佔位實作的預期行為，整合渠道實作後自然恢復 |
| 在 Editor 中執行出現該警告 | Editor / 非行動平台走 `#else` 分支，固定使用 `DefaultPaymentManager` | 預期行為；如需在 Editor 中測試，見[常見變體](#常見變體) |
| 實機上（Android / iOS）仍出現該警告 | 渠道實作組件未安裝，`Utility.Assembly.GetType(componentType)` 回傳 null 或型別缺失 | 安裝對應渠道套件（Google / Apple / WebGL / PC），或手動修正 Inspector 中的型別名稱 |

## 修復步驟

### 1. 確認目前命中的平台分支

`PaymentComponent.Awake()` 依編譯巨集選擇實作型別，只有所有巨集都不命中時才會落到 `DefaultPaymentManager`：

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
            if (_paymentManager == null)
            {
                Log.Fatal("Pay Manager is invalid.");
                return;
            }
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L94)

對照上表：實機 Android 應命中 `UNITY_ANDROID`，iOS 應命中 `UNITY_IOS`；如果命中了渠道分支仍出現警告，表示渠道型別本身缺失（見第 3 步）。

### 2. 檢查渠道型別名稱設定

`PaymentComponent` 上的渠道型別名稱是序列化欄位，預設值如下：

```csharp
private IPaymentManager _paymentManager;
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L23-L28)

在 Inspector 中選取掛載了 `PaymentComponent` 的物件（元件選單路徑 `GameFrameX/Payment`），檢查對應平台欄位是否被改成無效值；若曾手動修改且不確定，請還原為上表的預設完整名稱。

### 3. 安裝對應的渠道支付套件

預設型別名稱指向的是獨立渠道套件中的類別，本套件只提供介面與佔位實作：

| 平台巨集 | 期望的實作型別 | 所需渠道套件 |
|--------|----------------|------------|
| `UNITY_ANDROID` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` | Google 支付套件 |
| `UNITY_IOS` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple 支付套件 |
| `UNITY_WEBGL` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` | WebGL 支付套件 |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` | PC 支付套件 |
| `UNITY_STANDALONE_OSX` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple 支付套件 |
| 其餘（含 Editor） | `GameFrameX.Payment.Runtime.DefaultPaymentManager` | 本套件自帶 |

若渠道套件未安裝，`Utility.Assembly.GetType(componentType)` 拿不到型別，執行時只會得到佔位實作並觸發本警告。安裝渠道套件後重新進入 Play / 重新打包即可。

### 4. 透過日誌行為確認佔位實作

佔位實作的全部方法行為如下（用於反向確認問題確實出在佔位實作上）：

```csharp
public sealed class DefaultPaymentManager : BasePaymentManager
{
    private const string NotImplWarning = "You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).";

    public override void Init(bool isDebug = false, bool isClientVerify = false)
    {
        Log.Warning(NotImplWarning);
    }

    public override bool IsReady()
    {
        return false;
    }
```

Source: [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L17-L36)

其餘方法（`QueryPurchases`、`ConsumePurchase`、`BuyInApp`、`BuySubs`、`Buy`、`SetPredefinedProductIds`）與 `Init` 一樣只印出 `Log.Warning(NotImplWarning)`，見 [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L38-L81)。

## 常見變體

- **只想在 Editor 裡不洗版**：Editor 平台巨集走 `#else` 分支，必然使用 `DefaultPaymentManager`，警告無法透過設定消除；可以在日誌過濾中遮蔽該警告文字，或在呼叫支付介面前先用 `IsReady()` 做防護（佔位實作恆回傳 `false`）。
- **串接自有伺服器/渠道**：繼承 `BasePaymentManager` 並實作 `IPaymentManager` 的抽象成員（`Init`、`IsReady`、`SetPredefinedProductIds`、`QueryPurchases`、`ConsumePurchase`、`Buy` 系列，抽象簽名見 [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L61-L96)），然後把 Inspector 中對應平台的 `m_component*Type` 欄位改成你的實作類別完整名稱，即可替換佔位實作。

## 驗證

1. 重新進入 Play 模式或重新建置執行，Console 不再出現 `You are using DefaultPaymentManager which is a stub. ...` 警告。
2. 呼叫 `PaymentComponent.Init(...)` 後再呼叫 `IsReady()`（元件會直接轉發到管理器，見 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115)）：佔位實作恆為 `false`，渠道實作初始化完成後應能在就緒時回傳 `true`。
3. 發起一次測試購買，`OnPurchaseSuccess` / `OnPurchaseFailed` 事件應有回呼；佔位實作下這些事件永遠不會被觸發（沒有任何 `Raise*` 呼叫）。

## 背景

`DefaultPaymentManager` 是框架為 Editor 與未識別平台提供的後備實作，保證在未接入任何渠道套件時遊戲仍可編譯、啟動，且每次誤用支付介面都會以警告形式提示開發者去整合渠道實作（CHANGELOG 中也明確記錄了「所有方法加入未實作警告日誌」、「`IsReady()` 回傳 `false`」這兩項行為）。實作型別的選擇完全由編譯巨集加序列化型別名稱決定，與執行時環境無關，因此只需修改設定或安裝套件即可解決，無需修改框架程式碼。
