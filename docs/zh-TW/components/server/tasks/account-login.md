# 實作帳號登入(Account / Login 流程)

本頁帶你接好用戶端發起的帳號登入訊息，完成從 `ReqPlayerLogin` 進入到角色資料落地的最小閉環。完成後，用戶端會拿到 `RespPlayerLogin` 並進入遊戲業務。

## 前置條件

- 已部署 `GameFrameX.Server` 閘道與中心服，Actor 類型 `ActorTypeServer` 可用。
- 資料庫中已存在 `PlayerState` 資料表，主鍵欄位為 `Id`(登入訊息按 `Id` 查找)。
- 用戶端能發送 `ReqPlayerLogin` 訊息，並能收到 `RespPlayerLogin`。
- 已引用以下命名空間:`GameFrameX.Apps.Account.Login.Component`、`GameFrameX.Apps.Account.Login.Entity`、`GameFrameX.Apps.Player.Player.Entity`、`GameFrameX.Monitor.Player`。

1. **在中心服註冊登入元件**。`LoginComponent` 透過 `[ComponentType(GlobalConst.ActorTypeServer)]` 綁定到 `ActorTypeServer`,作為帳號/角色登入的承載元件。

       protected override bool IsCreateDefaultState { get; set; } = false;

2. **實作按角色 ID 查詢玩家**。在 `LoginComponent` 中暴露 `OnPlayerLogin(ReqPlayerLogin)`,內部使用 `GameDb.FindAsync<PlayerState>` 按主鍵查詢；每次呼叫前先打點登入計數器。

   ```csharp
   public async Task<PlayerState> OnPlayerLogin(ReqPlayerLogin reqLogin)
   {
       MetricsPlayerHelper.LoginCounterOptions.Inc();
       return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
   }
   ```

   Source: [GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47)

3. **編寫 Agent 完成綁定與轉發**。`LoginComponentAgent.OnPlayerLogin` 負責：呼叫元件查詢玩家、把玩家 `Id` 寫入 `NetWorkChannel`(鍵名 `GlobalConst.ActorIdKey`),再透過 `ActorManager` 拿到玩家 Actor 上的 `PlayerComponentAgent`,把登入交給真正的玩家元件。

   ```csharp
   public async Task OnPlayerLogin(INetWorkChannel workChannel, ReqPlayerLogin reqLogin, RespPlayerLogin response)
   {
       var playerState = await OwnerComponent.OnPlayerLogin(reqLogin);
       if (playerState == null)
       {
           //角色找不到?
           return;
       }

       // 綁定玩家ID
       workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id);
       var playerComponentAgent = await ActorManager.GetComponentAgent<PlayerComponentAgent>(playerState.Id);
       await playerComponentAgent.OnPlayerLogin(workChannel, playerState, response);
   }
   ```

   Source: [GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58)

4. **註冊訊息處理器**。`ReqPlayerLoginHandler` 透過 `[MessageMapping(typeof(ReqPlayerLogin))]` 標註，繼承 `GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>`,在 `ActionAsync` 中直接把請求轉發給 Agent。

   ```csharp
   [MessageMapping(typeof(ReqPlayerLogin))]
   internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
   {
       protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
       {
           await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
       }
   }
   ```

   Source: [GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L34-L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L34-L41)

5. **在用戶端發送登入**。用戶端按 `ReqPlayerLogin` 協定(包含 `Id`)發起請求，等待 `RespPlayerLogin` 回傳，後續業務訊息即可在玩家 Actor 上處理。

## 常見變體

- **HTTP 登入入口**：儲存庫另有 `GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs`,用於把 HTTP 請求轉換成同一條登入鏈路；前端需要走 HTTP 而非 TCP 時可直接使用。
- **關閉範例程式碼**:`GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs` 目前整段被 `/* … */` 註解掉，作為舊版 `ReqLogin` 實作的參考，實際接入請使用 `ReqPlayerLogin` 鏈路。

## 常見錯誤

- **`playerState == null` 直接回傳**：此時 `response` 沒有被賦值，用戶端會一直等待或逾時。務必在 Agent 中根據業務協定給 `response` 寫入錯誤碼，或拋出明確例外。
- **忘記 `workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id)`**:後續訊息無法路由到玩家 Actor,玩家收不到業務推送。
- **`IsCreateDefaultState = false` 與 `PlayerState` 缺失**：當玩家首次登入且資料庫裡無紀錄時，需要先在 `OnPlayerLogin` 裡建立 `PlayerState`,否則永遠回傳 `null`。

## 背景(可選)

- `LoginComponent` 標記 `ActorTypeServer`,表明登入邏輯跑在中心服 Actor 上，不與具體玩家 Actor 耦合。
- `LoginComponentAgent` 是狀態元件代理，負責把跨 Actor 的訊息收斂到 `LoginComponent`,再按玩家 ID 派發到對應的 `PlayerComponentAgent`。
