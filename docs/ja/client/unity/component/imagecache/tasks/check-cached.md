# 画像がキャッシュ済みかどうかを判定する方法

`IsCached(string url)` を使用することで、指定された URL の画像がローカルキャッシュにダウンロード済みかどうかを判定できます。キャッシュヒット時は重複したネットワークリクエストを回避できます。WebGL プラットフォームでは常に `false` を返し、その他のプラットフォームでは URL の MD5 値をファイル名としてキャッシュファイルの存在をチェックします。

## 前提条件

- `ImageCacheComponent` をゲームフレームワークのコンポーネントマネージャーにアタッチ済みであること(または `IImageCacheManager` インスタンスを保持していること)。
- 現在のビルドプラットフォームが**WebGL ではない**こと(WebGL ではキャッシュは無意味であり、インターフェースは常に `false` を返します)。

## 操作手順

1. キャッシュコンポーネントのインスタンスを取得します:

```csharp
var cache = GameEntry.GetComponent<ImageCacheComponent>();
```

2. `IsCached` を呼び出し、リモート画像のアドレスを渡します:

```csharp
string url = "https://example.com/avatar.png";
bool cached = cache.IsCached(url);
if (cached)
{
    // キャッシュヒット済み、ローカルでの読み込み処理に直接進むか、ダウンロードプロンプトをスキップできます
}
else
{
    // ダウンロードフローに進みます(例: cache.LoadImageAsync(url))
}
```

3. `IImageCacheManager` でも同じメソッドが公開されているため、インターフェース経由で直接呼び出すことができます:

```csharp
IImageCacheManager manager = cache;
bool cached = manager.IsCached(url);
```

インターフェースシグネチャについては `IImageCacheManager.cs` の 34 行目、実装については `ImageCacheManager.cs` の 180 行目、コンポーネントのラッパーについては `ImageCacheComponent.cs` の 83 行目を参照してください。

## よくあるバリエーション

- **空の URL を渡す**:`IsCached(string url)` は `url` が `null` または空文字列の場合に `false` を直接返し、例外をスローしません。
- **WebGL プラットフォーム**:`#if UNITY_WEBGL` のコンパイル分岐によって制御されており、ダウンロード済みかどうかにかかわらず `false` を返すため、これによって「未キャッシュ」と判断しないでください。
- **非同期読み込みとの組み合わせ**:`LoadImageAsync` の前に `IsCached` を呼び出すことで、UI のプレースホルダー/進捗プロンプトに利用でき、空白のちらつきを防げます。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| WebGL で `IsCached` が常に `false` を返す | WebGL はローカルファイルキャッシュをサポートしていないため、ソースコードでは固定で `false` を返す | WebGL ではこのチェックをスキップするか「未キャッシュ」フローとして扱う |
| 同じ URL でもサイズ/クロップパラメータが異なると判定結果が変わる | キャッシュキーは**元の URL の MD5** であり、query string 付きの URL は別のリソースとして扱われる | URL 文字列をダウンロード時と一致させておく |
| `CachePath` 設定を変更後に古いファイルが無効になる | パスの変更により、古いキャッシュファイルが新しいパス下に存在しない | 古いディレクトリをクリーンアップするか、移行後に判定する |

## 背景(任意)

実装は `ImageCacheManager.cs` にあり、コア処理は `Utility.Hash.MD5.Hash(url)` に `Utility.Const.FileNameSuffix.PNG` を連結してキャッシュパスを生成し、`FileHelper.IsExists` でファイルの存在を判定しています。判定処理は同期的で純粋なローカル IO であり、オーバーヘッドは非常に低いため、UI ロジックの前段で呼び出すのに適しています。
