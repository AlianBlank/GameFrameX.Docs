# iOS / tvOS / visionOS 채널 구성

iOS, tvOS, visionOS 플랫폼에서 채널 정보는 Xcode 프로젝트의 `Info.plist`에 저장됩니다. 본 패키지는 빌드 시 `Info.plist`를 자동으로 검사하여 `channel` 키가 없으면 기본값 `default`를 자동으로 기록합니다. Xcode에서 이 값을 실제 채널명으로 변경하면, 런타임에 `BlankGetChannel.GetChannelName()`으로 읽을 수 있습니다.

## 사전 조건

- Unity 프로젝트에 본 패키지 `com.gameframex.unity.getchannel`이 설치되어 있어야 합니다(Unity 2019.4+).
- iOS 빌드 타겟으로 전환되어 있어야 합니다(`File > Build Settings > iOS > Switch Platform`). 참고: 빌드 후처리 스크립트는 `#if UNITY_IOS`로 컴파일되며, `BuildTarget.iOS`일 때만 적용됩니다.

## 작업 단계

1. Unity에서 iOS 빌드를 실행하여(`Build` 또는 `Build And Run`) Xcode 프로젝트를 생성합니다. 빌드가 완료되면 스크립트가 생성된 `Info.plist`를 자동으로 처리합니다:

   ```csharp
   private static void Run(string path)
   {
       const string channelKey = "channel";
       const string channelValue = "default";

       string plistPath = path + "/Info.plist";
       PlistDocument plist = new PlistDocument();
       plist.ReadFromString(File.ReadAllText(plistPath));
       if (!plist.root.values.TryGetValue(channelKey, out var value))
       {
           plist.root.SetString(channelKey, channelValue);
           plist.WriteToFile(plistPath);
           Debug.Log("配置渠道成功=>" + channelValue);
       }
       else
       {
           Debug.Log("已有渠道,跳过设置=>" + value);
       }
   }
   ```

   출처: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

   이 콜백은 `[PostProcessBuild(99)]`에 연결되어 있으며, `BuildTarget.iOS`에만 적용됩니다. 처리 중 발생한 예외는 캡처되어 `Debug.LogException`으로 출력되며, 빌드가 중단되지 않습니다.

2. 생성된 Xcode 프로젝트를 열고, `Info.plist`에서 `channel`의 값을 실제 채널명으로 변경합니다. 필요에 따라 다른 키(예: `sub_channel`)를 추가할 수 있습니다:

   ```xml
   <key>channel</key>
   <string>ios_cn_taptap</string>

   <key>sub_channel</key>
   <string>beta</string>
   ```

   출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L133-L141)

3. C# 코드에서 채널을 읽습니다:

   ```csharp
   using UnityEngine;

   public class MyGameScript : MonoBehaviour
   {
       void Start()
       {
           // Get default channel (key name is "channel")
           string channel = BlankGetChannel.GetChannelName();
           Debug.Log("Current channel: " + channel);

           // Get channel with a specific key
           string customChannel = BlankGetChannel.GetChannelName("channelName");
           Debug.Log("Custom channel: " + customChannel);

           // Get channel with a default fallback value
           string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
           Debug.Log("Sub channel: " + subChannel);
       }
   }
   ```

   출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L103-L123)

4. 실기기/시뮬레이터에서 실행하여 Console에 출력된 채널 값이 `Info.plist`의 값과 일치하는지 확인합니다.

## 일반적인 변형

- **커스텀 키 이름**: 기본 키 `channel`을 사용하지 않아도 되며, `Info.plist`에 임의의 키(예: `channelName`)를 정의한 후 `BlankGetChannel.GetChannelName("channelName")`을 호출하면 됩니다. 해당 키는 반드시 `Info.plist`에 실제로 존재해야 합니다.
- **다단계 채널**: `channel`과 `sub_channel` 두 개의 키를 동시에 유지하며, 메인 채널과 서브 채널을 각각 읽습니다.
- **폴백 값을 사용한 읽기**: API의 전체 시그니처는 다음과 같습니다

  ```csharp
  public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
  ```

  출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98)

  두 번째 매개변수는 C# 레이어에서 읽기 실패 시 반환되는 기본값을 지정합니다. 전달하지 않으면 `default`입니다.

## 일반적인 오류

- **Console에 `unknown` 출력**: 네이티브 레이어에서 `Info.plist`를 읽을 때 해당 키를 찾지 못하면 문자열 `unknown`을 반환합니다. Xcode 프로젝트의 `Info.plist`에 해당 키가 실제로 존재하는지, 철자가 C# 호출의 `channelKey`와 완전히 일치하는지 확인하십시오. 관련 구현은 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)을 참고하십시오.
- **채널명을 변경했는데 재빌드 후 다시 `default`로 덮어써짐**: 스크립트는 키가 존재하지 않을 때만 기록합니다. Xcode 프로젝트에서 `channel`을 변경한 후 Unity에서 다시 Build하여 전체 Xcode 프로젝트 디렉터리를 덮어쓴 경우 다시 수정해야 합니다. 증분 빌드이고 키가 이미 존재하는 경우, 스크립트는 건너뛰고 `已有渠道,跳过设置=>...`를 출력합니다.
- **tvOS / visionOS 빌드 후 `Info.plist`가 기록되지 않음**: 후처리 스크립트는 `BuildTarget.iOS` 기준으로 판단하므로, 해당 플랫폼을 iOS 빌드 파이프라인으로 전환하여 프로젝트를 생성한 후에 적용되는지 확인하십시오. 키가 기록되지 않았다면 Xcode에서 직접 `channel` 키를 수동으로 추가할 수 있습니다.

## 검증

- Unity Console에 `配置渠道成功=>default`(최초) 또는 `已有渠道,跳过设置=>xxx`(이미 존재)가 나타나면 후처리 스크립트가 실행된 것입니다. [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L43-L48)를 참고하십시오.
- Xcode에서 `Info.plist`를 열어 `channel` 키와 현재 값을 확인할 수 있습니다.
- App을 실행하면 `BlankGetChannel.GetChannelName()`이 반환하는 값이 `Info.plist`의 값과 일치합니다. 키가 존재하지 않으면 `unknown`을 반환합니다.

## 배경

iOS 네이티브 플러그인은 `[[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"]`에서 메인 번들의 `Info.plist` 딕셔너리를 읽고, 전달된 키 이름으로 값을 가져와 C 문자열로 변환하여 C# 레이어에 반환합니다. 값을 가져올 수 없으면 `unknown`을 반환합니다. 이것이 채널 값이 반드시 `Info.plist`에 구성되어야 하고, 키 이름이 호출 매개변수와 일치해야 하는 이유입니다. 구현은 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)을 참고하십시오.

Android 채널 구성에 대해서는 《Android 채널 구성》을 참고하십시오. Editor/PC/WebGL 등의 플랫폼은 `Resources/application_config.txt`를 사용하며, 자세한 내용은 README를 참고하십시오.
