# 啟動流程卡在 ProcedureLauncherState 時怎麼辦 → 該如何處理

如果 `StartupRunner.RunAsync` 已將啟動鏈推進至 `ProcedureLauncherState`,但畫面未出現且流程未轉換至 `ProcedureGetGlobalInfoState`(整個啟動 Promise 永遠處於 `Pending` 狀態)，問題絕大多數出在 FSM 黑板資料、UI 資源或 `WebComponent` 初始化上。本頁提供快速診斷與對應的修正步驟。

## 快速診斷

| 症狀 | 原因 | 修正 |
|------|------|------|
| 啟動後出現黑畫面，日誌中只看到進入 `ProcedureLauncherState`,而 `ChangeState<ProcedureGetGlobalInfoState>` 未執行 | `BlackBoardKeys.StartupOptions` 或 `BlackBoardKeys.StartupUIHandler` 為空，導致 `OnEnter` 提前 `return` | 參閱下方「修正 1:FSM 黑板資料缺失」 |
| 啟動畫面短暫出現後消失，或完全未出現並卡在啟動頁面 | `IStartupUIHandler.StartAsync` 擲出例外或中斷 | 參閱下方「修正 2:UI Handler 啟動失敗」 |
| 啟動至 Launcher 階段時，主控台出現 `WebComponent` 相關的 Null 參考錯誤 | `GameEntry.GetComponent<WebComponent>()` 回傳 `null`,Web 模組未註冊 | 參閱下方「修正 3:WebComponent 未註冊」 |
| 流程卡住且從未進入 `OnEnter` | 在 `procedureManager.StartProcedure<ProcedureLauncherState>()` 之前未正確將資料注入 FSM,或 `StartupOptions.LauncherUIResName` 路徑錯誤 | 參閱下方「修正 4:LauncherUIResName 資源路徑錯誤」 |
| 啟動鏈僅執行到 Launcher,`UniTaskCompletionSource` 未被 SetResult | 後續 Procedure 負責在 Launcher 之後執行 `SetResult`,Launcher 本身只轉換狀態 | 參閱下方「修正 5:等待後續 Procedure 完成」 |

## 修正步驟

### 修正 1:FSM 黑板資料缺失

`ProcedureLauncherState.OnEnter` 會從 FSM 黑板讀取 `StartupOptions` 與 `IStartupUIHandler`,只要其中之一為 `null`,方法便會立即 `return`,既不轉換狀態也不會產生任何錯誤：

```csharp
// 來源:Runtime/Procedures/Startup/ProcedureLauncherState.cs
var options = optionsBox.Value as StartupOptions;
var uiHandler = uiHandlerBox.Value as IStartupUIHandler;

if (options == null || uiHandler == null)
{
    return; // 直接結束導致流程卡住,但不會拋出例外
}
```

請確認 `StartupRunner.RunAsync` 在呼叫 `StartProcedure<ProcedureLauncherState>` 之前，確實傳入了非 null 的 `options` 與 `uiHandler`:

```csharp
// 來源:Runtime/Startup/StartupRunner.cs
procedureFsm.SetData(BlackBoardKeys.StartupOptions, optionsBox);
procedureFsm.SetData(BlackBoardKeys.StartupUIHandler, uiHandlerBox);
```

若您自行組建啟動鏈(未使用 `StartupRunner`),必須在呼叫 `StartProcedure<ProcedureLauncherState>()` 之前以相同的 key 注入資料。請參閱 [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs)。

### 修正 2:UI Handler 啟動失敗

`OnEnter` 實際上會在 `await uiHandler.StartAsync(options.LauncherUIResName)` 處等待 UI 載入完成。若 `IStartupUIHandler` 實作中發生例外，該例外會被 `async void` 吞掉而導致流程卡住；若發生中斷(例如 Addressables 資源尚未就緒)，同樣不會轉換至下一個狀態。

檢查順序：

1. 在自訂的 `IStartupUIHandler.StartAsync` 進入點加上 `try/catch`,至少將例外輸出至日誌，確認是否確實發生例外。
2. 在 Editor 中暫時將 `LauncherUIResName` 指定為已確認存在的 Prefab/Asset,以排除資源路徑錯誤。
3. 若使用了 `UniTaskCompletionSource`,請確認 `StartAsync` 內部有呼叫 `TrySetResult`,且未遺漏任何 `await`。

### 修正 3:WebComponent 未註冊

`ProcedureLauncherState` 在轉換狀態前必須對 `WebComponent` 讀取與寫入 Header。若模組未註冊，`GameEntry.GetComponent<WebComponent>()` 會回傳 `null`,下一行的 `webComponent.RemoveBaseHeader(...)` 便會立即拋出 NRE:

```csharp
// 來源:Runtime/Procedures/Startup/ProcedureLauncherState.cs
var webComponent = GameEntry.GetComponent<WebComponent>();
webComponent.RemoveBaseHeader(StartupProcedureUtility.GameFrameXApiKeyHeader);
// ...
```

請確認 `GameEntry` 的模組註冊流程中，`WebComponent` 已加入元件表，且執行階段的呼叫順序早於 `StartupRunner.RunAsync` 的執行。

### 修正 4:LauncherUIResName 資源路徑錯誤

`options.LauncherUIResName` 必須指向有效的 UI Prefab 或資源位址。若資源不存在，大多數 `IStartupUIHandler` 實作不會主動失敗，而是陷入「等待資源載入」的無限迴圈。驗證方式：

1. 在建立 `StartupOptions` 時輸出 `LauncherUIResName`,與 Addressables Groups / Resources 目錄中的實際 key 比對。
2. 先以 `EPlayMode.EditorSimulateMode` 搭配已確認存在的資源執行一次啟動流程，以排除建置/分組問題。

### 修正 5:等待後續 Procedure 完成

`ProcedureLauncherState` 本身的職責僅是「載入啟動 UI → 轉換至下一個狀態」，並不會呼叫 `UniTaskCompletionSource.SetResult`。若您觀察到的「卡住」實際上是 `StartupRunner.RunAsync` 回傳的 `UniTask<StartupResult>` 持續處於 `Pending` 狀態，請確認 `ProcedureGetGlobalInfoState` 及後續 Procedure 是否會在最終成功/失敗時執行 `StartupProcedureUtility.GetCompletionSource(fsm).TrySetResult(...)`。

請參閱 [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs) 中 `GetCompletionSource` 的實作，確認取得的正是 `StartupRunner` 注入至 `BlackBoardKeys.StartupCompletionSource` 的那個 `UniTaskCompletionSource`。

## 驗證

修正完成後，請依下列順序確認整條鏈是否順暢：

1. 確認啟動後日誌中可看到進入 `ProcedureLauncherState.OnEnter`,且隨後也進入 `ProcedureGetGlobalInfoState.OnEnter`。不應只看到前者。
2. 確認 `StartupRunner.RunAsync` 回傳的 `UniTask<StartupResult>` 會在合理時間內(通常數秒)完成，而非持續停留在 `Pending` 狀態。
3. 確認主控台不再出現 `WebComponent` Null 參考或 UI 資源載入失敗的錯誤。
4. 若使用了自訂的 `IStartupUIHandler`,請以中斷點確認 `StartAsync` 會在 `LauncherUIResName` 對應的資源就緒後返回，且返回後呼叫堆疊會回到 `ProcedureLauncherState` 的 `ChangeState<ProcedureGetGlobalInfoState>`。
