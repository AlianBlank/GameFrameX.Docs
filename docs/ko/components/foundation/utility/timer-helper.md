# TimerHelper를 사용하여 시간대/타임스탬프 처리하는 방법

`TimerHelper`는 정적 시간 유틸리티 클래스로, UTC 또는 현재 설정된 시간대를 기반으로 한 시간 가져오기, Unix 타임스탬프 변환 및 차이 계산 기능을 제공합니다. 기본 시간대는 UTC이며, `SetTimeZone`을 통해 임의의 시스템 시간대로 전환할 수 있습니다.

## 사전 조건

- `GameFrameX.Foundation.Utility` 네임스페이스를 참조해야 합니다.
- Linux/macOS에서 IANA 시간대 ID를 지정할 때는 현재 런타임에 해당 ID가 등록되어 있는지 확인하세요(Windows에서는 "China Standard Time" 등의 이름을 사용).

```csharp
using GameFrameX.Foundation.Utility;
```

## 작업 단계

### 1. 시간대 선택 및 설정

`TimerHelper`의 기본 시간대는 `TimeZoneInfo.Utc`이며, 명명 규칙은 다음과 같습니다.

| 접미사 | 의미 |
|------|------|
| 접미사 없음 | 기본 메서드, 일반적으로 UTC 시간 반환 |
| `WithUtc` | UTC 시간 기반 계산 |
| `WithTimeZone` | `CurrentTimeZone` 기반 계산 |
| `WithTimeZoneOffset` | UTC 타임스탬프 + 시간대 오프셋 |

`SetTimeZone`으로 시간대를 전환하며, `null` 또는 유효하지 않은 ID를 전달하면 UTC로 폴백됩니다.

```csharp
// TimeZoneInfo 객체 사용
TimerHelper.SetTimeZone(TimeZoneInfo.FindSystemTimeZoneById("Asia/Shanghai"));

// 시간대 ID 문자열 사용 (실패 시 자동으로 UTC로 폴백)
bool ok = TimerHelper.SetTimeZone("China Standard Time");
if (!ok) { /* UTC로 폴백 */ }
```

### 3. Unix 타임스탬프 가져오기 및 생성

| 메서드 | 반환 | 설명 |
|------|------|------|
| `UnixTimeSeconds()` | `long` | UTC 초 단위 타임스탬프 |
| `UnixTimeMilliseconds()` | `long` | UTC 밀리초 단위 타임스탬프 |
| `UnixTimeSecondsWithTimeZoneOffset()` | `long` | 표준 UTC 타임스탬프 + 현재 시간대 오프셋 + `TimeOffsetSeconds` |
| `UnixTimeMillisecondsWithTimeZoneOffset()` | `long` | 표준 UTC 타임스탬프 + 현재 시간대 오프셋 + `TimeOffsetMilliseconds` |
| `DateTimeToSecondsWithTimeZone(DateTime)` | `long` | 임의의 `DateTime`을 현재 시간대 시간으로 간주하고 초 단위 타임스탬프 생성 |
| `DateTimeToMillisecondsWithTimeZone(DateTime)` | `long` | 위와 동일, 밀리초 단위 |

```csharp
long sec  = TimerHelper.UnixTimeSeconds();
long msec = TimerHelper.UnixTimeMilliseconds();

// 오프셋 포함: UTC+8에서는 표준 UTC 타임스탬프보다 28800초 큼
long secOffset  = TimerHelper.UnixTimeSecondsWithTimeZoneOffset();
long msecOffset = TimerHelper.UnixTimeMillisecondsWithTimeZoneOffset();

// DateTime -> 타임스탬프 (Unspecified는 기본적으로 CurrentTimeZone으로 해석)
DateTime t = new DateTime(2024, 1, 1, 0, 0, 0, DateTimeKind.Unspecified);
long tsZ = TimerHelper.DateTimeToSecondsWithTimeZone(t);
```

## 일반적인 변형

- **크로스 플랫폼 시간대 ID**: Windows에서는 "China Standard Time", Linux/macOS에서는 "Asia/Shanghai"를 사용. `SetTimeZone(string)`은 ID가 유효하지 않을 때 예외를 잡고 `false`를 반환합니다.
- **Epoch 상수**: `EpochUtc = 1970-01-01T00:00:00Z (Utc)`, `EpochLocal = 1970-01-01T00:00:00 (Local)`. `EpochLocal`은 항상 시스템 로컬 시간대를 따르며, `CurrentTimeZone`의 영향을 받지 않습니다.

Source: [TimerHelper.cs#L117-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/Time/TimerHelper.cs#L117-L145)

## 일반적인 오류

| 오류 | 원인 | 회피 방법 |
|------|------|----------|
| `SetTimeZone("Asia/Shanghai")`이 Windows에서 `false` 반환 | Linux/macOS는 IANA ID를 사용, Windows는 Microsoft 시간대 이름 사용 | OS 레이어에서 `TimeZoneInfo.FindSystemTimeZoneById`로 판단하거나, `SetTimeZone(TimeZoneInfo)`를 호출해 명시적으로 전달 |
| `Kind=Unspecified`인 `DateTime`을 전달했을 때 "시간대" 시간이 올바르지 않음 | `ConvertToUtc`이 `Unspecified`를 `CurrentTimeZone` 시간으로 처리 | `DateTimeKind.Utc` 또는 `DateTimeKind.Local`을 명시적으로 설정한 후 전달 |
| 멀티스레드 환경에서 `CurrentTimeZone`의 값이 일관되지 않게 읽힘 | 정적 필드는 `volatile`로 작성되며, 복합 연산의 원자성을 보장하지 않음 | 읽기 전용 구성 시나리오로는 충분함; 런타임에频繁하게 전환할 경우 자체적으로 락 추가 필요 |
