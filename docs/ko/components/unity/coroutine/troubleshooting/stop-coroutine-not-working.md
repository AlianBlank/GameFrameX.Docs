# `StopCoroutine`을 호출했지만 코루틴이 멈추지 않는 경우怎么办

`CoroutineComponent.StopCoroutine(...)`을 호출했지만 코루틴이 계속 실행되며, 씬이 닫히거나 `StopAllCoroutines`가 호출되어야만 정리됩니다. 이는 보통 전달한 `IEnumerator` 인스턴스가 시작할 때 사용된 것과 같은 참조가 아니어서, 컴포넌트 내부의 추적 테이블이 이를 찾지 못하기 때문입니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `StopCoroutine(ienumerator)` 호출 후에도 코루틴이 계속 실행됨 | 전달한 `IEnumerator` 인스턴스가 시작할 때의 것과 동일하지 않아 딕셔너리에서 찾지 못하고, 결국 `base.StopCoroutine`으로 폴백되지만 `base` 경로는 해당 코루틴을 실제로 추적하고 있지 않음 | `StartCoroutine`에 전달한 원본 `IEnumerator` 참조를 저장해 두고, 정지할 때 동일한 변수를 전달 |
| `StartCoroutine`이 반환한 `UnityEngine.Coroutine`으로 정지하는 것이 무효 | 추적 테이블에서 해당 코루틴을 제거하지 않고 기본 클래스 `MonoBehaviour.StopCoroutine` 경로를 호출함 | `CoroutineComponent` 인스턴스에서 `StopCoroutine(UnityEngine.Coroutine)` 오버로드를 호출하도록 변경 |
| `WaitForEndOfFrameFinish`의 콜백이 정지 후에도 계속 트리거됨 | `yield return WaitForEndOfFrame`이 아직 다음 프레임에 도달하기 전에 정지했지만, 해당 프레임이 종료된 후에도 콜백이 계속 실행됨 | 코루틴을 정지하기 전에 먼저 `callback`을 null로 설정하거나, 조건 판단을 사용하도록 변경 |

## 수정 단계

### 시나리오 1: `StopCoroutine(IEnumerator)`이 적용되지 않음

`CoroutineComponent`는 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>`을 사용하여 시작된 모든 코루틴을 추적하며, key는 `IEnumerator` 참조입니다. 딕셔너리에서 찾지 못하면 소스 코드는 `base.StopCoroutine(enumerator)` 분기로 진행합니다:

```csharp
public new void StopCoroutine(IEnumerator enumerator)
{
    if (m_CoroutineMap.TryGetValue(enumerator, out var coroutine))
    {
        base.StopCoroutine(coroutine);
        m_CoroutineMap.TryRemove(enumerator, out _);
    }
    else
    {
        base.StopCoroutine(enumerator);
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

해결 방법: 시작할 때 전달한 `IEnumerator`를 필드에 저장하고, 정지할 때 동일한 참조를 전달합니다.

```csharp
private IEnumerator _runningRoutine;

void Start()
{
    _runningRoutine = MyRoutine();
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StartCoroutine(_runningRoutine);
}

void StopMyRoutine()
{
    // 동일한 인스턴스를 전달, _runningRoutine은 딕셔너리의 key임
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StopCoroutine(_runningRoutine);
}

IEnumerator MyRoutine()
{
    while (true) { yield return null; }
}
```

### 시나리오 2: `UnityEngine.Coroutine` 오버로드로 정지하는 것이 무효

만약 받은 것이 `StartCoroutine`이 반환한 `UnityEngine.Coroutine`이라면, 반드시 두 번째 오버로드를 사용해야 합니다. 소스 코드는 딕셔너리를 순회하여 해당 항목을 찾아 제거합니다:

```csharp
public new void StopCoroutine(UnityEngine.Coroutine coroutine)
{
    base.StopCoroutine(coroutine);
    foreach (var item in m_CoroutineMap)
    {
        if (item.Value == coroutine)
        {
            m_CoroutineMap.TryRemove(item.Key, out _);
            break;
        }
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L56-L67)

흔한 실수: `Coroutine` 참조를 첫 번째 오버로드인 `StopCoroutine(IEnumerator)`에 전달하면, 딕셔너리에서 찾지 못하고 `else` 분기로 빠집니다.

### 시나리오 3: 모든 코루틴을 한 번에 정리

단순히 모두 정지하고 싶다면, `StopAllCoroutines` 오버로드를 직접 사용하세요. 이는 개별적으로 정지하고 딕셔너리를 비웁니다:

```csharp
GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
    .StopAllCoroutines();
```

소스 코드는 먼저 딕셔너리를 순회하여 개별적으로 정지한 다음, 추적되지 않은 코루틴을 처리하기 위해 `base.StopAllCoroutines()`를 호출합니다:

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

## 검증

1. 코루틴 내부에 주기적으로 출력하는 `Debug.Log`를 추가하고, `StopCoroutine` 호출 후 1초 이내에 새로운 로그가 출력되지 않는지 확인합니다.
2. Unity Profiler의 Memory 패널에서 `Coroutine`을 확인하여 백그라운드 작업이 계속 증가하는지 확인합니다.
3. 코루틴 내에 `yield return new WaitForSeconds(...)`이 포함된 경우, 정지 후 해당 `WaitForSeconds`의 콜백이 더 이상 완료되지 않아야 합니다.
