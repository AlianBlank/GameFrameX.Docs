# アプリとリソースのバージョン確認 URL を設定する方法

GlobalConfig は、サーバーから配信されるグローバル設定オブジェクトを通じてアプリバージョン確認アドレスとリソースバージョン確認アドレスを返し、フロントエンドは `CheckAppVersionUrl` と `CheckResourceVersionUrl` の 2 つのフィールドを消費するだけで、対応するバージョン確認リクエストを開始できます。

## 前提条件

- `com.gameframex.unity.globalconfig` パッケージがインストールされ、エントリコンポーネントの登録が完了していること。
- 業務側でグローバル情報を返すインターフェースがデプロイ済みであり、インターフェース JSON には `CheckAppVersionUrl` と `CheckResourceVersionUrl` フィールドが含まれていること。
- クライアントがそのインターフェースが配置されているホストサーバーアドレスにアクセスできること( `ResponseGlobalInfo.HostServerUrl` フィールドを参照)。

## 操作手順

1. サーバーのグローバル情報インターフェースのレスポンス JSON において、2 つの URL フィールドの両方が返されることを確認し、フィールド名はクライアントモデルと厳密に一致させてください:

   ```json
   {
     "CheckAppVersionUrl": "https://your-cdn.example.com/api/app/version",
     "CheckResourceVersionUrl": "https://your-cdn.example.com/api/resource/version"
   }
   ```

2. クライアントがこの JSON を解析した後、`ResponseGlobalInfo` の 2 つの文字列プロパティを直接読み取ります。2 つのプロパティはいずれも `string` で、デフォルト値は `null` です。

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;

   var info = new ResponseGlobalInfo
   {
       CheckAppVersionUrl      = "https://your-cdn.example.com/api/app/version",
       CheckResourceVersionUrl = "https://your-cdn.example.com/api/resource/version",
       HostServerUrl           = "https://your-cdn.example.com",
       AOTCodeList             = "[]",
       Content                 = "{}"
   };
   ```

   Source: [Runtime/GlobalConfig/ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L1-L28)

3. 得られた URL をそれぞれアプリバージョン確認とリソースバージョン確認モジュールに渡し、対応するリクエストオブジェクトを開始します:

   ```csharp
   // アプリバージョン確認リクエスト
   var appVersionReq = new RequestGameAppVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAppVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAppVersion.cs)

4. リソースバージョン確認は独立したリクエストオブジェクトを使用し、フィールドも同様にプラットフォーム、チャンネル、言語などの基本情報となります:

   ```csharp
   var assetReq = new RequestGameAssetPackageVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs)

5. サーバーはアプリバージョン確認リクエストを処理する際に `ResponseGameAppVersion` を返し、その中には `IsForce`、`IsUpgrade`、`AppDownloadUrl`、`UpdateAnnouncement`、`UpdateTitle` などのアップグレード情報が含まれます:

   ```csharp
   public class ResponseGameAppVersion
   {
       public bool   IsForce           { get; set; }
       public string AppDownloadUrl    { get; set; }
       public bool   IsUpgrade         { get; set; }
       public string UpdateAnnouncement{ get; set; }
       public string UpdateTitle       { get; set; }
   }
   ```

   Source: [Runtime/GlobalConfig/ResponseGameAppVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGameAppVersion.cs#L1-L33)

## よくあるバリエーション

- **同一アドレスの共有**:アプリとリソースのバージョン確認が同じゲートウェイを共有する場合、2 つの URL に同じアドレスを返させ、ゲートウェイ内で path ルーティングにより区別することができます。
- **グレー release・分割サーバー**:異なるチャンネル(`Channel`)が異なる URL を使用する場合、サーバー側でリクエストボディの `Channel` フィールドに基づいて対応するアドレスを返せばよく、クライアントコードは変更不要です。

## よくあるエラー

- **フィールド名のスペルミス**:インターフェースフィールド名は必ず `CheckAppVersionUrl`、`CheckResourceVersionUrl` とし、先頭大文字のキャメルケースでなければなりません。そうでないと `ResponseGlobalInfo` のデシリアライズ後、2 つのプロパティがどちらも `null` になります。
- **HTTPS が未準備**:URL は HTTPS を使用しなければなりません。使用しないと Android 9+ ではデフォルトのネットワークポリシーによってブロックされます。
- **ホストアドレスの設定忘れ**:`CheckAppVersionUrl` には実際には相対パスやサブドメインのみが含まれるため、実際のエンドポイントには `ResponseGlobalInfo.HostServerUrl` も必要です。そうでないとリクエストがホストを見つけられません。

## 背景(オプション)

`ResponseGlobalInfo` は GlobalConfig パッケージで定義された最もシンプルな DTO であり、「アドレスをクライアントに伝える」という役割のみを担います。パッケージには HTTP クライアントが内蔵されておらず、実際のリクエストとキャッシュは上位の業務モジュールが `RequestGameAppVersion` / `RequestGameAssetPackageVersion` に基づいて実行するため、グローバル設定から疎結合となり、さまざまなネットワークスタックの統合が容易になります。
