# What to Do About the Initialization Error "Can not find component type"

This error is thrown by `GameAnalyticsComponent.Init()`: the `ComponentType` string of an analytics component configured in the Inspector cannot be resolved to a real type at runtime by `Utility.Assembly.GetType()`. That Provider is skipped directly (`continue`), and the corresponding analytics channel will not report any data at all. The core fix is to make `ComponentType` match the full type name (including namespace) of a class that actually exists and implements `IGameAnalyticsManager`.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Can not find component type 'XXX'` and no reports at all from that channel | The `ComponentType` string does not match the real class name/namespace (text was hand-edited, class was renamed) | Re-select the correct type in the Inspector dropdown, see Step 1 below |
| Works fine in the editor, but errors after building for a device | The assembly/code containing the implementation class was stripped or not included in the build | Confirm that the implementation class's assembly participates in the build and is not removed by code stripping |
| The class in the configuration does exist, but the error still occurs | The type name does not include the full namespace, so `Utility.Assembly.GetType` cannot find it | Use the full type name, e.g. `GameFrameX.GameAnalytics.Runtime.XXXManager` |
| The desired type simply does not appear in the dropdown list | The class does not implement the `IGameAnalyticsManager` interface, so it will not be listed by the Inspector | Make the class implement `IGameAnalyticsManager` (usually by inheriting `BaseGameAnalyticsManager`) |

The logic that produces the error (note: even if the type can be found but does not implement `IGameAnalyticsManager`, it will simply silently have no effect without raising an error):

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }
```

## Fix Steps

### 1. Re-select the type using the Inspector dropdown instead of typing the string manually

Select the GameAnalytics component in the scene (`AddComponentMenu("Game Framework/GameAnalytics")`), and re-select the ComponentType for the failing entry in the "Game analytics component list, reported in order" list in the Inspector.

The candidate list in the dropdown is generated by `GameAnalyticsComponentInspector.RefreshTypeNames()`: it scans all runtime types that implement `IGameAnalyticsManager`, plus a `NoneOptionName` empty option.

```csharp
protected override void RefreshTypeNames()
{
    List<string> managerTypeNameList = new List<string>
    {
        NoneOptionName
    };
    managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
    m_ManagerTypeNames = managerTypeNameList.ToArray();
}
```

Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

If you can see the target type in the dropdown, simply select it — the Inspector writes a type name that is consistent with runtime resolution, which completely eliminates hand-typed spelling/namespace errors.

### 2. If the target type is not in the dropdown, check the class definition

The implementation class must be an implementation of `IGameAnalyticsManager`. The simplest approach is to inherit the abstract base class `BaseGameAnalyticsManager` provided by the framework and implement its abstract members:

```csharp
public abstract class BaseGameAnalyticsManager : GameFrameworkModule, IGameAnalyticsManager
{
    public abstract void Init(Dictionary<string, string> args);
    public abstract void ManualInit(Dictionary<string, string> args);
    public abstract bool IsManualInit();
    ...
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L10-L36)

### 3. Confirm the configuration data itself is valid

`ComponentType` is stored in the serialized class `GameAnalyticsComponentProvider` (defined around line 362 of `Runtime/GameAnalytics/GameAnalyticsComponent.cs`) and is serialized together with the scene/prefab. The following situations produce "leftover invalid type names":

- After the implementation class is deleted or renamed, the serialized string in old scenes/prefabs is not updated accordingly;
- Copying someone else's scene or prefab without importing the analytics SDK packages it depends on into the current project.

How to handle it: open the corresponding scene/prefab, and either change the failing Provider entry to a valid type or simply delete that entry.

## Verification

1. Re-enter Play mode (or re-enable the component to trigger `OnEnable` → `Init()`); the Console no longer shows `Can not find component type '...'`.
2. Call a public API once (e.g. `GameAnalyticsComponent.SetPlayerId("test")`) to confirm there are no exceptions and that data reaches the corresponding channel; `Init()` iterates over all successfully created `IGameAnalyticsManager` instances and calls their `Init(args)`.

```csharp
var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
{
    Dictionary<string, string> args = new Dictionary<string, string>();
    foreach (var param in gameAnalyticsComponentProvider.Setting)
    {
        args[param.Key] = param.Value;
    }

    gameAnalyticsManager.Init(args);
    m_GameAnalyticsManager.Add(gameAnalyticsManager);
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L65-L75)

Note that `Init()` has an `m_IsInit` re-entry guard, so repeated calls will not re-resolve types; when verifying, you must observe during a fresh initialization (re-entering Play mode or re-enabling the component).

## Background

`GameAnalyticsComponent` builds the Provider list in `Awake`, calls `Init()` in `OnEnable`, uses reflection — `Utility.Assembly.GetType` + `Activator.CreateInstance` — to instantiate each analytics channel manager from a string, and passes the entry's `Setting` dictionary from the Inspector straight through to `Init(Dictionary<string, string> args)`. This "string + reflection" design allows component configuration to be independent of compile-time dependencies; the trade-off is that an invalid type name can only be discovered at runtime, which manifests as the error covered on this page.
