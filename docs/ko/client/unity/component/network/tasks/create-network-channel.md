# 서버 연결: 채널 생성 및 채널 헬퍼 구현(TCP/WebSocket)

네트워크 채널을 생성하려면 `NetworkComponent.CreateNetworkChannel(channelName, networkChannelHelper)`를 호출하고 `INetworkChannelHelper`를 구현한 채널 헬퍼를 전달하기만 하면 됩니다. 프레임워크는 컴파일 매크로에 따라 기반 구현을 자동으로 선택하며, WebGL/WebSocket 매크로가 활성화되어 있으면 `WebSocketNetworkChannel`을, 그렇지 않으면 `SystemTcpNetworkChannel`을 사용합니다.

## 사전 조건

- 씬에 `NetworkComponent`가 부착되어 있어야 합니다(네임스페이스 `GameFrameX.Network.Runtime`).
- 전송 방식이 결정되어 있어야 합니다. 기본값은 시스템 TCP이며, WebSocket이 필요한 경우 매크로 `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` 또는 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET`을 활성화해야 합니다.
- 채널 헬퍼 클래스를 준비합니다(프레임워크에 내장된 `DefaultNetworkChannelHelper`를 그대로 사용하거나, 해당 인터페이스에 맞춰 직접 구현할 수 있습니다).

## 작업 단계

1. 채널 헬퍼를 준비합니다. 프레임워크에 내장된 [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L13)는 `INetworkChannelHelper`의 모든 멤버를 구현하므로, 그대로 재사용하거나 사용자 지정 헬퍼의 템플릿으로 사용할 수 있습니다:

   | 멤버 | 시그니처(DefaultNetworkChannelHelper 기준) | 설명 |
   |------|------|------|
   | `SetChannelSerializer` | `void SetChannelSerializer(IMessageSerializer serializer)` | 채널 수준 메시지 직렬화기를 설정하며, 반드시 `Initialize` 이전에 호출해야 합니다 |
   | `Initialize` | `void Initialize(INetworkChannel netChannel)` | 채널 참조를 저장하고 리플렉션으로 각 핸들러를 등록하며 네트워크 이벤트를 구독합니다 |
   | `PrepareForConnecting` | `void PrepareForConnecting()` | 연결 전에 Socket 수신/송신 버퍼를 `1024 * 64 - 1`로 설정합니다 |
   | `SendHeartBeat` | `bool SendHeartBeat()` | `PacketHeartBeatHandler`를 사용해 하트비트 패킷을 구성하고 전송합니다 |
   | `SerializePacketHeader<T>` | `bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject` | 채널의 `PacketSendHeaderHandler`에 위임합니다 |
   | `SerializePacketBody` | `bool SerializePacketBody(byte[] messageBodyBuffer, MemoryStream destination)` | 채널의 `PacketSendBodyHandler`에 위임합니다 |
   | `DeserializePacketHeader` | `bool DeserializePacketHeader(byte[] source)` | 채널의 `PacketReceiveHeaderHandler`에 위임합니다 |
   | `DeserializePacketBody` | `bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` | 채널의 `PacketReceiveBodyHandler`에 위임합니다 |
   | `Clear` | `void Clear()` | 채널을 닫고(`NetworkCloseReason.Dispose` / `NetworkErrorCode.DisposeError`) 참조를 정리합니다 |

2. (선택 사항) 헬퍼에 채널 수준 직렬화기를 설정합니다. 반드시 채널 초기화(`Initialize`) 이전에 호출해야 하며, 그렇지 않으면 예외가 발생합니다:

   ```csharp
   public void SetChannelSerializer(IMessageSerializer serializer)
   {
       if (m_NetworkChannel != null)
       {
           throw new InvalidOperationException(
               "SetChannelSerializer must be called before Initialize().");
       }
       m_ChannelSerializer = serializer;
   }
   ```

   출처: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L32-L40)

3. `NetworkComponent.CreateNetworkChannel`를 호출하여 채널을 생성합니다. `channelName`은 비어 있으면 안 되고, 타임아웃 시간은 컴포넌트의 `m_rpcTimeout` 값을 사용하며, 로그를 무시할 메시지 Id 목록이 자동으로 적용됩니다:

   ```csharp
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
       networkChannel.SetIgnoreLogNetworkIds(m_IgnoredSendNetworkIds, m_IgnoredReceiveNetworkIds);
       return networkChannel;
   }
   ```

   출처: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L176-L182)

4. TCP / WebSocket은 컴파일 매크로에 의해 자동으로 선택되며, 런타임에는 전환할 수 없습니다. 선택 로직은 `NetworkManager.CreateNetworkChannel`에 있습니다:

   ```csharp
   #if (ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL) || FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET
       NetworkChannelBase networkChannel = new WebSocketNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #else
       NetworkChannelBase networkChannel = new SystemTcpNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #endif
   ```

   출처: [NetworkManager.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.cs#L220-L224)

   두 기반 구현은 모두 `NetworkChannelBase : INetworkChannel, IDisposable`의 sealed 하위 클래스이며, 각각 [NetworkManager.SystemTcpNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/SystemSocket/NetworkManager.SystemTcpNetworkChannel.cs#L45)와 [NetworkManager.WebSocketNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/WebSocket/NetworkManager.WebSocketNetworkChannel.cs#L48)에 위치합니다.

5. 채널 초기화 시 헬퍼는 리플렉션으로 어셈블리를 스캔하여 해당 인터페이스를 구현한 핸들러를 채널에 자동으로 등록합니다(패킷 헤더 수신, 패킷 본문 수신, 패킷 헤더 송신, 패킷 본문 송신, 하트비트, 압축, 압축 해제). 따라서 사용자 지정 핸들러는 해당 인터페이스만 구현하면 됩니다:

   ```csharp
   if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
   {
       var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
       m_NetworkChannel.RegisterHandler(handler);
   }
   ```

   출처: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L86-L90)

6. 반환된 `INetworkChannel`을 통해 대상 서버에 연결하고, 이벤트 컴포넌트에서 연결/종료/하트비트 손실/오류 네 가지 이벤트를 구독합니다. 헬퍼는 `Initialize`에서 이미 구독하고 있으며, `NetworkComponent`가 이를 전역 이벤트로 전달합니다:

   ```csharp
   Event.CheckSubscribe(NetworkConnectedEventArgs.EventId, OnNetworkConnectedEventArgs);
   Event.CheckSubscribe(NetworkClosedEventArgs.EventId, OnNetworkClosedEventArgs);
   Event.CheckSubscribe(NetworkMissHeartBeatEventArgs.EventId, OnNetworkMissHeartBeatEventArgs);
   Event.CheckSubscribe(NetworkErrorEventArgs.EventId, OnNetworkErrorEventArgs);
   ```

   출처: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128)

7. 더 이상 필요하지 않을 때 채널을 제거합니다:

   ```csharp
   public bool DestroyNetworkChannel(string channelName)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       return m_NetworkManager.DestroyNetworkChannel(channelName);
   }
   ```

   출처: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L190-L194)

## 일반적인 변형

- **기본 헬퍼 직접 재사용**: 대다수 프로젝트는 `CreateNetworkChannel("main", new DefaultNetworkChannelHelper())`를 직접 호출하고, `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler` / `IPacketSendHeaderHandler` / `IPacketSendBodyHandler` / `IPacketHeartBeatHandler` / `IMessageCompressHandler` / `IMessageDecompressHandler`를 구현하는 핸들러 클래스를 함께 사용하기만 하면 되며, 등록은 리플렉션으로 자동 수행됩니다.
- **WebSocket으로 전환**: Player Settings에서 매크로 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET`을 추가하거나(WebGL이 아닌 플랫폼에서 WebSocket 강제 사용), `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL`(WebGL 플랫폼)을 사용합니다.
- **다중 채널 동시 사용**: 서로 다른 서버/게이트웨이에 대해 여러 채널을 생성하고, 각각 독립적으로 명명된 `channelName`과 헬퍼 인스턴스를 전달합니다. `NetworkComponent.GetAllNetworkChannels()`로 모든 채널을 가져올 수 있습니다([NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L154-L157) 참조).

## 일반적인 오류

| 증상/오류 메시지 | 원인 | 회피 방법 |
|------|------|------|
| `SetChannelSerializer must be called before Initialize().` | 채널 초기화(`Initialize`가 이미 채널을 헬퍼에 할당함) 이후에 `SetChannelSerializer`가 호출됨 | 먼저 `SetChannelSerializer`를 호출한 뒤 생성/초기화를 수행합니다 |
| 채널 생성 시 매개변수 검증 예외 발생 | `channelName`이 비어 있거나 null임 | 비어 있지 않은 채널 이름을 전달합니다(`GameFrameworkGuard.NotNullOrEmpty`) |
| WebSocket을 사용하려 했는데 TCP로 동작함 | 현재 매크로가 WebSocket 분기에 해당하지 않음 | 매크로 `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` 또는 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET`이 적용되었는지 확인합니다 |
| 직렬화 시 `GameFrameworkGuard.NotNull` 예외 발생 | 채널에 아직 `PacketSendHeaderHandler` / `PacketSendBodyHandler`가 등록되지 않음 | 리플렉션 등록이 이루어지도록 해당 핸들러 클래스가 존재하고 해당 인터페이스를 구현하는지 확인합니다 |

## 검증

- `CreateNetworkChannel`이 null이 아닌 `INetworkChannel` 인스턴스를 반환하면 채널 생성에 성공한 것입니다.
- `Initialize` 중단점 또는 로그에서 `IPacketReceiveHeaderHandler`, `IPacketSendBodyHandler` 등이 `RegisterHandler`로 등록되었는지 확인합니다.
- `NetworkConnectedEventArgs` 이벤트를 수신하면 연결에 성공한 것입니다. `NetworkErrorEventArgs`, `NetworkClosedEventArgs`는 실패 원인을 확인하는 데 사용할 수 있습니다.

## 배경

채널 헬퍼(`INetworkChannelHelper`)는 채널과 구체적인 패킷 형식 간의 어댑터 계층입니다. 송신 시 메시지를 `IPacketSendHeaderHandler` / `IPacketSendBodyHandler`에 전달하여 패킷을 조립하고, 수신 시 `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler`를 거쳐 패킷을 `MessageObject`로 분해합니다. 하트비트, 압축, 압축 해제도 등록된 핸들러를 통해 수행됩니다. 전송 계층(TCP 또는 WebSocket)은 `NetworkManager.CreateNetworkChannel` 내에서 컴파일 매크로에 의해 결정되며, 비즈니스 코드는 이를 인식하지 않습니다.
