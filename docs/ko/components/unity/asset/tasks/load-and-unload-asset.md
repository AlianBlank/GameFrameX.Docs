# 일반 리소스 로드 및 해제 방법(동기 / 비동기)

이 페이지에서는 `AssetComponent`(또는 하위 레이어의 `AssetManager`)를 사용하여 경로별로 일반 리소스(Prefab, Texture2D, TextAsset 등)를 로드하고, 반환된 `AssetHandle`에서 객체를 가져온 뒤, 사용 완료 후 올바르게 해제하여 리소스가 메모리에 상주하지 않도록 하는 방법을 설명합니다.

## 사전 조건

- 리소스 패키지가 초기화되어 있어야 합니다. 패키지 초기화는 `InitPackageAsync`를 통해 수행되며, 시그니처는 다음과 같습니다.

```csharp
public Task<bool> InitPackageAsync(string packageName, string hostServerURL, string fallbackHostServerURL, bool isDefaultPackage = false)
```

> Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L65-L98)

- 패키지 이름을 지정하지 않은 경우, 언로드 인터페이스는 기본 패키지인 `DefaultPackageName` / `ConstDefaultPackageName`을 사용합니다.
- 씬에 `AssetComponent`가 부착되어 있어야 합니다(이 컴포넌트는 모든 로드 인터페이스를 내부의 `_assetManager`로 전달합니다).

## 작업 단계

### 1. 비동기 로드(권장)

리소스 경로를 전달하고 `await`하여 `AssetHandle`을 얻은 다음 `AssetObject`로 객체를 가져옵니다. 비동기 인터페이스에는 4개의 오버로드가 있습니다.

```csharp
public Task<AssetHandle> LoadAssetAsync(string path)
public Task<AssetHandle> LoadAssetAsync<T>(string path) where T : UnityEngine.Object
public Task<AssetHandle> LoadAssetAsync(string path, Type type)
public Task<AssetHandle> LoadAssetAsync(AssetInfo assetInfo)
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L283-L399)

호출 예제(제네릭 오버로드가 가장 일반적으로 사용되며, 리소스 타입을 직접 제약할 수 있습니다).

```csharp
// Prefab을 비동기로 로드하고 인스턴스화
var handle = await assetComponent.LoadAssetAsync<GameObject>("Assets/Res/Prefabs/Player.prefab");
var go = UnityEngine.Object.Instantiate((GameObject)handle.AssetObject);
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L324-L327)

### 2. 동기 로드

초기화流程이나 시작 단계의 작은 리소스는 동기 인터페이스를 사용할 수 있으며, 반환값은 `Task`가 아닌 직접적인 `AssetHandle`입니다.

```csharp
public AssetHandle LoadAssetSync(string path)
public AssetHandle LoadAssetSync<T>(string path) where T : UnityEngine.Object
public AssetHandle LoadAssetSync(string path, Type type)
```

```csharp
var handle = assetComponent.LoadAssetSync<TextAsset>("Assets/Res/Config/level.txt");
```

### 3. 사용 완료 후 해제

해제는 세 가지 세분화 수준을 제공하며, 보유한 것에 따라 선택합니다.

```csharp
// A. 리소스 경로만 알고 있는 경우(기본 패키지)
assetComponent.UnloadAsset("Assets/Res/Prefabs/Player.prefab");

// B. 멀티 패키지 시나리오, 패키지 이름 지정
assetComponent.UnloadAsset("MyPackage", "Assets/Res/Prefabs/Player.prefab");

// C. 핸들을 보유한 경우
assetComponent.UnloadAssetHandle(handle);
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L766-L795)

경로별 언로드는 내부적으로 `TryUnloadUnusedAsset`을 거치며, 이는 "참조되지 않는 리소스를 언로드 시도"하는 것이므로 여전히 참조 중인 경우 실제로 언로드되지 않습니다.

```csharp
public void UnloadAsset(string assetPath)
{
    GameFrameworkGuard.NotNull(assetPath, nameof(assetPath));
    var package = YooAssets.GetPackage(DefaultPackageName);
    package.TryUnloadUnusedAsset(assetPath);
}
```

> Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L100-L124)

### 4. 일괄 회수(씬 전환 시)

```csharp
// 현재 참조되지 않는 리소스를 언로드(기본 패키지, packageName에 null을 전달하면 기본 패키지 사용)
```

## 일반적인 변형

| 요구 사항 | 사용할 인터페이스 | 반환 타입 |
|------|-----------|---------|
| 리소스 하나만 필요, 비동기 | `LoadAssetAsync<T>(string path)` | `Task<AssetHandle>` |
| 리소스 하나만 필요, 동기 | `LoadAssetSync<T>(string path)` | `AssetHandle` |
| 타입이 런타임에 결정됨 | `LoadAssetAsync(string path, Type type)` / `LoadAssetSync(string path, Type type)` | `Task<AssetHandle>` / `AssetHandle` |
| 이미 `AssetInfo`가 있음 | `LoadAssetAsync(AssetInfo)` / `LoadAssetSync(AssetInfo)` | `Task<AssetHandle>` / `AssetHandle` |
| 리소스 패키지의 모든 객체 로드 | `LoadAllAssetsAsync<T>(string path)` / `LoadAllAssetsSync<T>(string path)` | `Task<AllAssetsHandle>` / `AllAssetsHandle` |
| 서브 리소스 객체 로드(예: 아틀라스의 Sprite) | `LoadSubAssetsAsync(string path)` / `LoadSubAssetsSync(string path)` | `SubAssetsHandle` |
| 원본 파일 로드(바이너리/텍스트 원문) | `LoadRawFileAsync(string path)` / `LoadRawFileSync(string path)` | `Task<RawFileHandle>` / `RawFileHandle` |
| 씬 로드 | `LoadSceneAsync(string path, LoadSceneMode sceneMode, bool activateOnLoad = true)` | `Task<SceneHandle>` |

### 특정 타입의 편의 인터페이스

저장소에서는 일반적인 Unity 타입을 위해 별도의 분할 클래스 파일(`AssetComponent.Prefab.cs`, `AssetComponent.Sprite.cs`, `AssetComponent.Texture2D.cs`, `AssetComponent.TextAsset.cs`, `AssetComponent.AudioClip.cs`, `AssetComponent.Material.cs`, `AssetComponent.Shader.cs` 등)을 제공합니다. 핸들이 아닌 강력한 타입의 객체를 직접 받아야 할 경우 우선적으로 이 파일들의 인터페이스를 확인하십시오.

## 일반적인 오류

| 잘못된做法 | 결과 | 올바른 做法 |
|---------|------|---------|
| `path`에 `null` 전달 | 하위 레이어의 `GameFrameworkGuard.NotNull(assetPath, nameof(assetPath))`가 예외 발생 | 호출 전에 경로가 비어 있지 않은지 확인 |
| 패키지 초기화 전에 로드/언로드 | `YooAssets.GetPackage(...)`이 패키지를 가져올 수 없음 | 먼저 `await InitPackageAsync(...)` 성공 후 로드 |
| 멀티 패키지 리소스 언로드 시 패키지 이름 전달 누락 | `DefaultPackageName`이 사용되어 대상 리소스가 실제로 언로드되지 않음 | `UnloadAsset(packageName, assetPath)` 오버로드 사용 |
| `UnloadAsset`이 반드시 즉시 메모리를 해제할 것이라고 기대 | 하위 레이어는 `TryUnloadUnusedAsset`이며, 여전히 참조 중이면 언로드되지 않음 | 먼저 인스턴스화된 객체를 파괴하거나 참조를 끊은 다음 언로드하고, 필요 시 `UnloadUnusedAssetsAsync()` 호출 |
| 메인 스레드 게임에서 동기 로드를 대량 사용 | 프레임 드롭 | 런타임에는 항상 `LoadAssetAsync`를 사용하고, 동기 로드는 시작/초기화에만 사용 |
| `handle`을 직접 리소스 객체로 사용 | 타입 불일치 | `handle.AssetObject`을 사용하고 대상 타입으로 강제 캐스팅 |
| 아직 사용 중인 패키지에 `UnloadAllAssetsAsync` 호출 | 참조 중인 객체 손실, 텍스처가 보라색으로 변함 | 씬 전환 시, 참조가 없음을 확신한 경우에만 호출 |

## 배경(선택)

비동기 인터페이스는 내부적으로 `TaskCompletionSource`를 사용하여 YooAssets의 `Completed` 콜백을 `Task`로 브릿지하므로 직접 `await`할 수 있습니다. 이것이 로드 인터페이스가 모두 핸들(`AssetHandle` 등)을 반환하고裸 객체(naked object)를 반환하지 않는 이유이기도 합니다. 핸들은 참조 카운트를承载하고 언로드는 이에 의존합니다.
