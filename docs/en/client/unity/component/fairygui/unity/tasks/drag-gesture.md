# Drag and Gesture Interaction

When adding gesture interaction to UI components in FairyGUI, use the gesture classes in the `Runtime/Gesture/` directory: `SwipeGesture` (swipe), `LongPressGesture` (long press), `PinchGesture` (pinch zoom), and `RotationGesture` (rotation). They all inherit from `EventDispatcher` and dispatch gesture data to business code via event callbacks. Note: **No** standalone drag gesture class (such as `DragGesture` or `DragDropManager`) was **found** in this repository. For drag requirements, refer to the drag interfaces of components (GObject) themselves; that part is outside the scope of the source code verified on this page.

## Prerequisites

- The package has been imported into the Unity project, and the `Runtime/Gesture/` directory is compiled with the package (`FairyGUI` related assemblies).
- The gesture target is a FairyGUI display object (e.g., a component inside a `GComponent`).

2. Construct the corresponding gesture instance in your business script, with the target component as the host (constructor parameters should follow the constructor in the corresponding source file).

3. Listen for gesture begin/move/end via event callbacks, and read the gesture data in the callbacks to update UI or logic. For each gesture class's event constant names and callback parameter structures, please open the source files in the table above directly — the source code verification on this page is limited, signatures were not excerpted item by item, and to avoid misuse they are not repeated here.

4. Release the instance when the gesture is no longer needed, to avoid callbacks still firing after the component has been destroyed.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Cannot find the `DragGesture` / `DragDropManager` type | The repository's `Runtime/Gesture/` contains only the 4 gesture classes above; the search found no matching drag class | Use `SwipeGesture` for swiping; for true "pick-up and drop" interaction, verify GObject's drag-related interfaces before using them |
| Gesture does not respond | The gesture is not bound to the correct host component, or the component does not have touch interaction enabled | Verify the target component passed in during construction, and confirm that it can receive touch events |
| Callback parameter fields used incorrectly | The data structure carried by events is defined by each gesture's source file | Open the corresponding gesture source file to verify the fields before coding |

## Background

The gesture classes are located under `Runtime/Gesture/` and are part of the FairyGUI runtime; they parse multi-touch/pointer input into semantic events (swipe direction, pinch ratio, rotation angle, long-press duration), so the business layer only needs to subscribe to events without computing anything itself. No directly presentable usage examples were found in the source code; this page uses "select class → construct → listen → release" as the integration workflow, with signature details based solely on the source files.
