# 言語変更イベントをリッスンしてUIテキストを更新する方法

`LocalizationComponent.Language` に新しい言語を代入すると、コンポーネントは3つの言語変更イベントを順番にブロードキャストします。UIスクリプトでそのうちの1つ(`LocalizationLanguageChangeAfterEventArgs` を推奨)を購読すると、コールバック内で新旧の言語を取得してUIテキストを更新できます。

## 前提条件

- プロジェクトで GameFrameX の Localization および Event コンポーネントが有効になっていること。
- シーンに `LocalizationComponent` が存在すること:言語を切り替えると、それが依存する `SettingComponent` を通じて言語設定が永続化され、`EventComponent` を通じてイベントがディスパッチされます。

## 操作手順

3つのイベントはいずれも同じデータ(`Language` 新言語、`OldLanguage` 旧言語)を保持するため、必要に応じていずれか1つを購読するだけでよい:

| イベント引数クラス | ディスパッチ順序 | 適用シナリオ |
|------|------|------|
| `LocalizationLanguageChangeBeforeEventArgs` | 1 | 切り替えフローの中で最初に通知を受け取る。切り替え前の記録/準備に適している |
| `LocalizationLanguageChangeEventArgs` | 2 | 汎用的な言語変更イベント |
| `LocalizationLanguageChangeAfterEventArgs` | 3 | 切り替え完了の通知。ここでUIテキストを更新することを推奨 |

3つのイベントは `Language` セッター内で同期的かつ連続的にディスパッチされます:

```csharp
set
{
    if (m_LocalizationManager.Language != value)
    {
        var oldLanguage = m_LocalizationManager.Language;
        m_LocalizationManager.Language = value;
        m_SettingComponent.SetString(nameof(LocalizationComponent) + "." + nameof(Language), value);
        m_SettingComponent.Save();
        var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
        var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
        var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
    }
}
```

出典: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L155-L171)

### 1. イベントハンドラーメソッドを作成する

コールバックの引数には対応するイベント引数クラスをそのまま使用し、そこから新言語と旧言語を読み取ります:

```csharp
private void OnLanguageChanged(object sender, LocalizationLanguageChangeAfterEventArgs e)
{
    Debug.Log($"语言由 {e.OldLanguage} 切换为 {e.Language}");
    // ここで e.Language に基づいてテキストを再取得し、このUIのすべてのテキストコントロールを更新する
}
```

イベント引数クラスの `Language` / `OldLanguage` の定義と `EventId` は以下の通りです。`EventId` は型の完全名です:

```csharp
[Preserve] public static readonly string EventId = typeof(LocalizationLanguageChangeAfterEventArgs).FullName;

[Preserve]
public string Language { get; private set; }   // 現在の(新しい)言語

[Preserve]
public string OldLanguage { get; private set; } // 旧言語
```

出典： [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41-L67)

### 2. リスナーの登録と解除

イベントは GameFrameX の Event コンポーネントを通じてディスパッチされます(`m_EventComponent.Fire(...)`)。`EventId` 定数でリスナーを登録し、UIの破棄/無効化時に購読を解除する、典型的な記述例は以下の通りです:

```csharp
private void OnEnable()
{
    GameEntry.Event.AddListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}

private void OnDisable()
{
    GameEntry.Event.RemoveListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}
```

> 注:`AddListener` / `RemoveListener` の正確なシグネチャは com.gameframex.unity.event パッケージを参照してください。本リポジトリのローカライズコンポーネントは、`EventId`(型の完全名、すなわち `GameFrameX.Localization.Runtime.LocalizationLanguageChangeAfterEventArgs`)によるイベントのディスパッチのみを担当します。

### 3. 言語を切り替えてイベントを発生させる

`Language` に現在とは異なる言語値を代入するだけで、3つのイベントすべてが発生します:

```csharp
GameEntry.GetComponent<LocalizationComponent>().Language = "ChineseSimplified";
```

代入と同時に、言語が自動的に設定へ書き込まれ(キー名 `LocalizationComponent.Language`)保存されるため、次回起動時に読み戻すことができます。

### 4. コールバック内でテキストを更新する

手順1のコールバック内で、`e.Language`(またはコンポーネントの現在の `Language`)に基づいて対応する言語のテキストを再読み込みし、各テキストコントロールを更新します。言語関連のコントロールのみを更新することもでき、UIを再構築する必要はありません。

## 検証

- 言語を切り替えた後、手順1のコールバック内のログに旧言語と新言語が出力されていること。
- 現在と同じ値に言語を設定しても、コールバックは**トリガーされません**(セッターに `!=` の判定があります。上記の出典の157行目を参照)。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 言語切り替え後にコールバックが実行されない | リスナー登録時に使用した ID がイベントの実際の ID と一致していない | イベントクラス自体の定数 `LocalizationLanguageChangeAfterEventArgs.EventId` を統一して使用し、文字列を手書きしないこと |
| コールバックで読み取った言語が `UnknownLocalization` になる | イベント引数の参照プール再利用が正しく扱われていない | コールバック内で取得した `e.Language` / `e.OldLanguage` をすぐに使用し、イベント引数オブジェクト自体をキャッシュしないこと |
| 言語を繰り返し切り替えると重複したイベントを受信する | 購読解除のタイミングが適切でない、または重複して登録されている | `OnEnable` で登録、`OnDisable` で解除し、必ずペアになるようにする |
| 同じ言語を設定した後にテキストを更新したいが反応がない | セッターは同じ値の場合ショートし、イベントをディスパッチしない | 強制的に更新する必要がある場合は、呼び出し側で更新ロジックを自前で実行するか、一度目的の言語以外の値に設定してから再度目的の言語に切り替える |

## 背景

3つのイベント引数クラスはいずれも `GameEventArgs` を継承しており、インスタンスは `ReferencePool.Acquire<T>()` で取得されます(参照プールによる再利用)。そのため、イベント引数オブジェクトを長期間保持しないでください。言語の変更は `LocalizationComponent.Language` のセッターによって一元的に駆動されます。まずマネージャーの言語を更新して設定を永続化し、その後「Before → Change → After」の順序で3つのイベントが同期的にディスパッチされるため、リスナー側でタイミングの違いを区別する必要はなく、どれか1つを選択すれば十分です。
