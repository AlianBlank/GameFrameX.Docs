# 如何订阅与取消订阅事件

通过场景中的 `EventComponent`(菜单 `GameFrameX/Event`)订阅事件:调用 `CheckSubscribe(id, handler)` 完成订阅,调用 `Unsubscribe(id, handler)` 或 `CheckUnsubscribe(id, handler)` 取消订阅。处理器签名为 `EventHandler<GameEventArgs>`,事件编号 `id` 为 `string`。

## 前置条件

- 场景中已存在 GameFrameX 入口并挂载了 `EventComponent` 组件(`[AddComponentMenu("GameFrameX/Event")]`)。
- 如需自定义事件参数,准备一个继承 `GameEventArgs` 的参数类;无参数事件可直接用 `string` 事件编号。

## 订阅与取消订阅相关 API

| 方法 | 真实签名 | 行为 |
|------|----------|------|
| `EventComponent.CheckSubscribe` | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 未订阅时才订阅,可安全重复调用 |
| `EventComponent.Unsubscribe` | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 取消订阅(直接转发给管理器) |
| `EventComponent.CheckUnsubscribe` | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | handler 不存在时不执行任何操作 |
| `EventComponent.Check` | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 检查是否存在该处理函数 |
| `EventComponent.Count` | `int Count(string id)` | 该事件编号下的处理函数数量 |
| `IEventManager.Subscribe` | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | 管理器层原生订阅,不做去重 |

组件上的方法都是对 `IEventManager` 的转发,`CheckSubscribe` 的真实实现是"先 `Check` 再 `Subscribe`":

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

## 操作步骤

1. 在脚本中保存对 `EventComponent` 的引用(通过 Inspector 序列化引用或查找场景中的组件)。组件在 `Awake` 中自动获取 `IEventManager` 模块:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

2. 编写事件处理函数,签名必须是 `void (object sender, GameEventArgs e)`,即 `EventHandler<GameEventArgs>`。自定义参数类直接继承 `GameEventArgs`(本身为空的抽象基类,继承自 `BaseEventArgs`):

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class GameEventArgs : BaseEventArgs
{
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

3. 在初始化时机(如 `OnEnable`)订阅事件,推荐使用 `CheckSubscribe` 避免重复订阅:`m_EventComponent.CheckSubscribe("Player.HealthChanged", OnHealthChanged);`。
4. 在销毁/禁用时机(如 `OnDisable`/`OnDestroy`)取消订阅:`m_EventComponent.CheckUnsubscribe("Player.HealthChanged", OnHealthChanged);`。对应实现:

```csharp
public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.Unsubscribe(id, handler);
}

public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L118-L131)

5. 处理函数内部按需把 `e` 转换为自定义参数类型后读取数据。取消订阅后,可通过 `m_EventComponent.Check(id, handler)` 返回 `false`、`Count(id)` 返回 `0` 验证已解除订阅。

## 常见变体

- **重复初始化场景**:多次进入同一逻辑时直接用 `CheckSubscribe` / `CheckUnsubscribe`,两者内部都先检查再执行,重复调用不会报错。`CheckUnsubscribe` 的实现在管理器层判断 `handler` 不存在时不执行任何操作:

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (m_EventPool.Check(id, handler))
    {
        m_EventPool.Unsubscribe(id, handler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L140-L146)

- **无参数事件**:只需要一个事件编号、不需要携带数据时,可用 `Fire(object sender, string eventId)` 直接以字符串触发。组件内部会自动创建 `EmptyEventArgs`:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`EmptyEventArgs.Create` 从引用池获取对象并设置事件编号:

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

- **兜底处理**:调用 `SetDefaultHandler(EventHandler<GameEventArgs> handler)` 设置默认事件处理函数,用于接收没有订阅者的事件。

## 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| 组件初始化失败,日志输出 `Event manager is invalid.` | 场景缺少可用的 `IEventManager` 模块/GameFrameX 入口未初始化 | 确认场景中存在 GameFrameX 入口并挂载 `EventComponent` |
| 同一处理器被多次触发 | 使用了 `IEventManager.Subscribe`(不去重)且重复调用 | 改用 `EventComponent.CheckSubscribe` |
| 取消订阅时报错 | 传入了未订阅的 `handler` 或 `id` 不匹配 | 改用 `EventComponent.CheckUnsubscribe` |
| 处理函数签名不匹配 | 未使用 `EventHandler<GameEventArgs>`(`void (object, GameEventArgs)`) | 按该签名编写处理函数 |
| 事件触发时机与预期不符 | `Fire` 是线程安全的但事件在下一帧分发,`FireNow` 立即分发但非线程安全 | 按需选择 `Fire` / `FireNow` |

## 背景

`EventComponent` 是 Unity 场景上的门面组件,所有订阅 API 转发到 `IEventManager`(`EventManager`),后者再委托内部的 `m_EventPool` 完成实际的事件池维护。因此调用方只需面对 `EventComponent` 的 `Subscribe`/`Unsubscribe`/`Check` 语义,不必关心底层事件池。
