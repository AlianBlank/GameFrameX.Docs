# 初始化支付系統

在 Unity 場景中掛載 `PaymentComponent` 並呼叫 `Init`，即可完成支付系統的初始化：元件會在 `Awake` 中依目前平台自動選擇對應的支付管理器實作（Google / Apple / WebGL / PC），你只需設定商品 ID、傳入沙箱與驗證開關即可開始使用購買介面。

## 前置條件

- Unity 專案已安裝本套件。任選一種方式（詳見 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/README.zh-CN.md#L40-L67)）：
  - 在 `Packages/manifest.json` 的 `dependencies` 中加入 `"com.gameframex.unity.payment": "https://github.com/gameframex/com.gameframex.unity.payment.git"`；
  - 或透過 Unity `Package Manager` 的 `Git URL` 方式加入；
  - 或直接將存放庫放到 `Packages` 目錄下自動識別。
- 已安裝相依套件 `com.gameframex.unity`（版本 1.1.1 及以上）。
- 目標平台為 Android（Google Play）或 iOS（App Store）；Editor 及其他平台會回落到佔位實作（見下文「常見錯誤」）。

## 操作步驟

1. 在啟動場景中建立 GameObject，透過選單 `GameFrameX/Payment` 加入 `PaymentComponent`。元件宣告了相依與入口選單：

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

加入元件時，`GameFrameXPaymentCroppingHelper` 會由 `RequireComponent` 自動帶上，無需手動加入；同一物件上不允許重複掛載。

2. （可選）確認平台實作類型。元件會在 `Awake` 中根據編譯巨集自動選擇實作類別的全名：

```csharp
#if UNITY_ANDROID
    componentType = m_componentAndroidType;
#elif UNITY_IOS
    componentType = m_componentIOSType;
#elif UNITY_WEBGL
    componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
    componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
    componentType = m_componentMacType;
#else
    componentType = typeof(DefaultPaymentManager).FullName;
#endif
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L83)

各平台的預設類型名稱（可在 Inspector 的序列化欄位中修改）：

| 欄位 | 預設值 | 生效平台 |
|------|--------|----------|
| `m_componentAndroidType` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` | Android |
| `m_componentIOSType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | iOS |
| `m_componentWebGLType` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` | WebGL |
| `m_componentPCType` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` | Windows / Linux |
| `m_componentMacType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | macOS |

3. 在呼叫 `Init` 之前，如需預先載入商品快取，先呼叫 `SetPredefinedProductIds`（該方法必須在初始化之前呼叫）：

```csharp
/// <summary>
/// 設定預先載入的預定義商品ID,用於預先載入快取,注意：此方法必須在Initialize()之前呼叫
/// </summary>
/// <param name="inAppProductIds">內購商品ID清單</param>
/// <param name="subsProductIds">訂閱商品ID清單</param>
[UnityEngine.Scripting.Preserve]
public void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds)
{
    _paymentManager.SetPredefinedProductIds(inAppProductIds, subsProductIds);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L117-L126)

4. 呼叫 `Init` 完成初始化。元件上的簽章與預設值如下：

```csharp
/// <summary>
/// 初始化
/// </summary>
/// <param name="isDebug">是否為沙箱購買</param>
/// <param name="isClientVerify">是否執行用戶端購買驗證</param>
[UnityEngine.Scripting.Preserve]
public void Init(bool isDebug = false, bool isClientVerify = true)
{
    _paymentManager.Init(isDebug, isClientVerify);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L96-L105)

參數說明：

| 參數 | 類型 | 預設值 | 說明 |
|------|------|--------|------|
| `isDebug` | `bool` | `false` | 是否使用沙箱購買模式 |
| `isClientVerify` | `bool` | `true`（元件層）/ `false`（介面層） | 是否執行用戶端購買驗證；強連網、由伺服器驗證時應傳入 `false` |

介面層的定義與註解（以伺服器驗證為準時傳入 `false`）：

```csharp
/// <param name="isClientVerify">是否執行用戶端驗證購買成功，如果是強連網驗證。不需要開啟，設定為false，進行伺服器驗證</param>
[UnityEngine.Scripting.Preserve]
void Init(bool isDebug = false,bool isClientVerify = false);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L37-L43)

5. 用 `IsReady()` 輪詢/檢查支付系統是否就緒，就緒後再發起購買：

```csharp
/// <summary>
/// 支付系統是否準備好
/// </summary>
/// <returns>準備好回傳true，否則回傳false</returns>
[UnityEngine.Scripting.Preserve]
public bool IsReady()
{
    return _paymentManager.IsReady();
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L107-L115)

6. （可選）訂閱購買結果事件，事件在元件上直接透傳自 `IPaymentManager`：`OnPurchaseSuccess`、`OnPurchaseFailed`、`OnQueryPurchasesResult`、`OnConsumePurchaseResult`，參數類型均為 `EventHandler<PaymentEventArgs>`。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64)

## 常見變體

- **切換到自研/其他渠道實作**：不修改程式碼，直接在 Inspector 中把對應平台的序列化欄位（如 `m_componentAndroidType`）改為你的實作類別全名，要求該類別實作 `IPaymentManager`（通常繼承 `BasePaymentManager`）。元件透過 `Utility.Assembly.GetType(componentType)` 反射載入類型。
Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L84-L85)
- **沙箱/測試環境**：呼叫 `Init(true)` 將 `isDebug` 設為 `true`，走渠道沙箱購買流程。
- **伺服器端驗證**：呼叫 `Init(isDebug: false, isClientVerify: false)`，購買成功後由伺服器驗證回執，用戶端不做本機校驗。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 日誌輸出 `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).`，且 `IsReady()` 恆為 `false` | 目前平台（如 Editor）回落到了佔位實作 `DefaultPaymentManager` | 確認目標平台為 Android/iOS 並已安裝對應渠道套件；或接入自訂實作類別 |
| 日誌輸出 `Pay Manager is invalid.` 並中斷 | `GameFrameworkEntry.GetModule<IPaymentManager>()` 回傳 null，模組未註冊 | 檢查 GameFrameX 基礎套件（`com.gameframex.unity`）是否安裝、版本是否相符 |
| 預定義商品未生效 | `SetPredefinedProductIds` 在 `Init` 之後才呼叫 | 將該呼叫移到 `Init` 之前 |
| 平台實作類型不對 | Inspector 中序列化欄位被改錯，或切換平台後巨集未生效 | 按上文平台對照表核對欄位值；切換平台後重新編譯 |

佔位實作的相關原始碼（供比對日誌）：

```csharp
private const string NotImplWarning = "You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).";

public override void Init(bool isDebug = false, bool isClientVerify = false)
{
    Log.Warning(NotImplWarning);
}

public override bool IsReady()
{
    return false;
}
```

Source: [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L36)

## 驗證

- 初始化後呼叫 `PaymentComponent.IsReady()`：回傳 `true` 表示渠道實作已就緒；Editor/未接入渠道的平台上回傳 `false` 屬預期行為。
- Console 中不再出現 `DefaultPaymentManager which is a stub` 警告，表示目前平台已載入到真實渠道實作。

## 背景

`PaymentComponent` 是 GameFrameworkComponent，`Awake` 中根據編譯巨集確定實作類別全名，經 `Utility.Assembly.GetType` 解析為 `ImplementationComponentType`，介面類型固定為 `IPaymentManager`，隨後透過 `GameFrameworkEntry.GetModule<IPaymentManager>()` 取得模組實例；元件上的 `Init`、`IsReady`、`Buy` 等方法均是對該實例的轉發。渠道實作（Google、Apple 等）在本存放庫中不包含原始碼，需要單獨安裝對應渠道套件。
