# 呼叫了 StopCoroutine 但協程沒停怎麼辦

你呼叫了 `CoroutineComponent.StopCoroutine(...)`,但協程依然在跑,直到場景關閉或 `StopAllCoroutines` 才被清掉。這通常是因為傳入的 `IEnumerator` 實例與啟動時使用的不是同一個參考,導致元件內部追蹤表無法命中。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `StopCoroutine(ienumerator)` 呼叫後協程仍在跑 | 傳入的不是啟動時的同一個 `IEnumerator` 實例，字典查不到，只能回退到 `base.StopCoroutine`,但 `base` 路徑並沒有真正追蹤到這個協程 | 儲存 `StartCoroutine` 時傳入的原始 `IEnumerator` 參考，停止時傳同一個變數 |
| 用 `StartCoroutine` 回傳的 `UnityEngine.Coroutine` 停止無效 | 呼叫的是基底類別 `MonoBehaviour.StopCoroutine` 路徑，而沒有從追蹤表中移除該協程 | 改為呼叫 `CoroutineComponent` 實例上的 `StopCoroutine(UnityEngine.Coroutine)` 多載 |
| `WaitForEndOfFrameFinish` 的回呼在停止後仍觸發了 | 在 `yield return WaitForEndOfFrame` 還未到下一幀時停止，該幀結束後回呼依然會跑 | 在停止協程前先把 `callback` 置空，或改用條件判斷 |

## 修復步驟

### 場景 1:`StopCoroutine(IEnumerator)` 沒生效

`CoroutineComponent` 用 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 追蹤所有啟動過的協程，key 是 `IEnumerator` 參考。字典未命中時，原始碼會走 `base.StopCoroutine(enumerator)` 分支：

```csharp
public new void StopCoroutine(IEnumerator enumerator)
{
    if (m_CoroutineMap.TryGetValue(enumerator, out var coroutine))
    {
        base.StopCoroutine(coroutine);
        m_CoroutineMap.TryRemove(enumerator, out _);
    }
    else
    {
        base.StopCoroutine(enumerator);
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

解決方法：把啟動時傳入的 `IEnumerator` 儲存到欄位裡，停止時傳同一個參考。

```csharp
private IEnumerator _runningRoutine;

void Start()
{
    _runningRoutine = MyRoutine();
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StartCoroutine(_runningRoutine);
}

void StopMyRoutine()
{
    // 傳入同一個實例,_runningRoutine 是字典的 key
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StopCoroutine(_runningRoutine);
}

IEnumerator MyRoutine()
{
    while (true) { yield return null; }
}
```

### 場景 2:用 `UnityEngine.Coroutine` 多載停止無效

如果拿到的是 `StartCoroutine` 回傳的 `UnityEngine.Coroutine`,必須用第二個多載，原始碼會遍歷字典找到對應項目並移除：

```csharp
public new void StopCoroutine(UnityEngine.Coroutine coroutine)
{
    base.StopCoroutine(coroutine);
    foreach (var item in m_CoroutineMap)
    {
        if (item.Value == coroutine)
        {
            m_CoroutineMap.TryRemove(item.Key, out _);
            break;
        }
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L56-L67)

常見錯誤：把 `Coroutine` 參考丟給第一個多載 `StopCoroutine(IEnumerator)`,字典查不到，落入 `else` 分支。

### 場景 3:一次性清掉所有協程

如果只想乾脆全部停下，直接用 `StopAllCoroutines` 多載，它會逐個停止並清空字典：

```csharp
GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
    .StopAllCoroutines();
```

原始碼先遍歷字典逐一停止、再呼叫 `base.StopAllCoroutines()` 處理未追蹤的協程：

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

## 驗證

1. 在協程內部加 `Debug.Log` 週期性輸出，呼叫 `StopCoroutine` 後 1 秒內不再有新日誌。
2. 在 Unity Profiler 的 Memory 面板查看 `Coroutine`,看背景任務是否還在增長。
3. 若協程內嵌 `yield return new WaitForSeconds(...)`,停止後該 `WaitForSeconds` 不應再完成回呼。
