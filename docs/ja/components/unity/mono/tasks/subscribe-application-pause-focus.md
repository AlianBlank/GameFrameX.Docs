# アプリケーションの一時停止とフォーカスの変化を監視する方法

このパッケージを使用すると、MonoBehaviour 以外のシステムでも Unity の `OnApplicationPause` および `OnApplicationFocus` コールバックを監視できるため、アプリがバックグラウンドに入ったり、フォアグラウンドに戻ったりする際に、音楽の一時停止、進捗の保存、フォーカス UI の更新などの操作を実行できます。

## 前提条件

- `com.gameframex.unity.mono` パッケージがインストールされていること(バージョン ≥ 1.1.4)。
- プロジェクトに `GameFrameX.Event.Runtime` イベントシステムが導入されていること(このパッケージの依存関係です)。

## 操作手順

### 1. イベントシステムによる購読(推奨)

イベントシステム方式は最も疎結合であり、ビジネスロジックが複数のマネージャーに分散しているシナリオに適しています。

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Mono.Runtime;

private void OnFocusChanged(object sender, GameEventArgs e)
{
    var args = (OnApplicationFocusChangedEventArgs)e;
    if (args.IsFocus)
    {
        // アプリがフォアグラウンドに戻った
    }
    else
    {
        // アプリがバックグラウンドに入った
    }
}

private void OnPauseChanged(object sender, GameEventArgs e)
{
    var args = (OnApplicationPauseChangedEventArgs)e;
    if (args.IsPause)
    {
        // アプリがシステムによって一時停止された
    }
    else
    {
        // アプリが一時停止から回復した
    }
}

// 購読
GameFrameXEntry.GetModule<EventComponent>().Subscribe(OnApplicationFocusChangedEventArgs.EventId, OnFocusChanged);
GameFrameXEntry.GetModule<EventComponent>().Subscribe(OnApplicationPauseChangedEventArgs.EventId, OnPauseChanged);
```

イベント ID は `OnApplicationFocusChangedEventArgs.EventId` / `OnApplicationPauseChangedEventArgs.EventId` によって識別されます。

### 2. Mono コンポーネントによる直接監視

ロジックが MonoBehaviour 派生クラス内に書かれている場合、または Unity の生のコールバックを受信したい場合は、このパッケージの Mono ブリッジコンポーネントをアタッチし、監視メソッドを追加します。

```csharp
private void OnApplicationFocus(bool isFocus)
{
    // isFocus: true でフォアグラウンドに入る、false でバックグラウンドに入る
}

private void OnApplicationPause(bool isPause)
{
    // isPause: true でシステムにより一時停止、false で一時停止から回復
}

// 登録
monoComponent.AddOnApplicationFocusListener(OnApplicationFocus);
monoComponent.AddOnApplicationPauseListener(OnApplicationPause);

// 不要になったら削除
monoComponent.RemoveOnApplicationFocusListener(OnApplicationFocus);
monoComponent.RemoveOnApplicationPauseListener(OnApplicationPause);
```

## イベントパラメータの対照

| イベントクラス | フィールド | 意味 |
|--------|------|------|
| [OnApplicationFocusChangedEventArgs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationFocusChangedEventArgs.cs#L40-L87) | `bool IsFocus` | true はアプリがフォーカスを取得した(フォアグラウンドに戻った)、false はフォーカスを失った(バックグラウンドに入った)ことを示す |
| [OnApplicationPauseChangedEventArgs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationPauseChangedEventArgs.cs#L40-L88) | `bool IsPause` | true はシステムにより一時停止された、false は回復したことを示す |

両方のイベントクラスは `GameEventArgs` を継承しており、`ReferencePool.Acquire<T>()` を通じて参照プールから取得されます。使用後はフレームワークによって一括回収されます。

## よくあるバリエーション

- **バックグラウンド/フォアグラウンドの切り替えのみを気にする場合**:`OnApplicationFocusChangedEventArgs` のみを購読し、`IsFocus=false` はバックグラウンドへの切り替えと同等です。
- **一時停止とフォーカス喪失を区別する場合**:モバイルデバイスでは、ロック画面は通常 `OnApplicationPause=true` をトリガーします。システムレベルのダイアログポップアップは通常 `OnApplicationFocus=false` のみをトリガーします。個別に処理する必要がある場合は、両方のイベントを購読してください。
- **イベントオブジェクトの構築**:フレームワーク内部では `OnApplicationPauseChangedEventArgs.Create(bool)` / `OnApplicationFocusChangedEventArgs.Create(bool)` を使用します。ビジネス側では通常、手動で構築する必要はありません。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| 監視メソッドが一度も呼び出されない | `Subscribe` / `AddOnApplicationFocusListener` を呼び出していない | モジュール初期化時に明示的に一度登録する |
| イベントを受信したが `IsFocus` が常に `false` である | 購読時に 2 つのイベントの `EventId` を逆に記述した | `Focus` イベントは `IsFocus` を返し、`Pause` イベントは `IsPause` を返すことに注意する |
| 複数回重複してトリガーされる | Mono コンポーネント監視とイベントシステム購読の両方をアタッチしており、同じ信号が 2 つの経路を通過している | どちらかを選択し、ディスパッチ箇所でビジネスロジックの重複排除を行う |
| 監視の削除が機能しない | 削除時に異なるメソッド参照を渡した | `Add` / `Remove` には同じ `Action` / メソッド参照を渡す必要がある |

## 背景(オプション)

`OnApplicationPause` と `OnApplicationFocus` は、Unity エンジンが MonoBehaviour 上で提供するコールバックです。このパッケージはこれらを GameFrameX イベントバスのメッセージに転送し、純粋な C# システム(`MonoBehaviour` 派生なし)でもアプリケーションのライフサイクル変化に応答できるようにします。イベントインスタンスは参照プールで再利用され、GC を削減します。
