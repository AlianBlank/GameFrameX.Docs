# 註冊並處理用戶端訊息(MessageId / Handler)

本文展示如何在 GameFrameX.Server 中透過 `MessageId` 註冊並處理用戶端發來的訊息——只需要建立一個繼承自 `BaseMessageHandler` 的類別,並用 `[MessageMapping]` 標註請求訊息型別即可，框架啟動時會自動掃描並完成分派。

## 前置條件

- 訊息處理類別必須定義在 `GameFrameX.Hotfix` 專案中(架構分析器會強制驗證，違反時編譯報錯 `GFX0006`)。
- 類別必須標記為 `sealed`(違反時報告 `GFX0010`),且型別名稱必須以 `Handler` 結尾(違反時報告 `GFX0012`)。
- 已透過 `.proto` 檔案產生請求/回應的訊息型別(例如 `ReqLogin`、`RespLogin`),且在目標專案裡能被引用。

## 操作步驟

1. 在 `GameFrameX.Hotfix` 下建立處理器類別，繼承 `BaseMessageHandler<Req, Resp>`,並在類別上用 `[MessageMapping(typeof(Req))]` 指明要處理的請求型別。

```csharp
// GameFrameX.Hotfix/Logic/Login/LoginHandler.cs
using GameFrameX.Net;
using GameFrameX.Hotfix;

[MessageMapping(typeof(ReqLogin))]
[MessageResponse(typeof(RespLogin))]
internal sealed class LoginHandler : BaseMessageHandler<ReqLogin, RespLogin>
{
    public override async Task<RespLogin> Handle(ReqLogin request, NetWorkChannel channel)
    {
        var resp = new RespLogin { Code = 0, Message = "ok" };
        return await Task.FromResult(resp);
    }
}
```

Source: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L130-L140)

2. 框架啟動後，`AppStartUpHotfixGameByMain` 會在收到訊息封包時從 `HotfixManager` 取出對應的 `Handler`,並把 `MessageId` 解析出來的請求物件傳給你：

```csharp
// 框架側的分派核心邏輯
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
if (handler == null)
{
    LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
    return;
}
await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
```

Source: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L130-L141)

3. 閘道服務(`AppStartUpHotfixGameByGateWay`)的分派同樣使用 `HotfixManager.GetTcpHandler(message.MessageId)`,保證用戶端到後端的訊息處理路徑一致：

```csharp
var handler = HotfixManager.GetTcpHandler(message.MessageId);
if (handler == null)
{
    LogHelper.Error($"找不到[{message.MessageId}][{messageObject.GetType()}]对应的handler");
    return;
}
```

Source: [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L123-L128)

## 常見變體

- **玩家級訊息**(綁定到具體玩家 Actor):用 `[MessageMapping]` + 繼承 `BaseMessageHandler`,由框架把訊息路由到對應玩家的 Mailbox。
- **全域級訊息**(綁定到伺服器 Actor):同樣用 `[MessageMapping]`,但處理器裡通常只做無狀態處理，例如心跳。

```csharp
// 玩家級(範例來自 README.ja.md)
// Player-level message (bound to a specific player Actor)
[MessageMapping(typeof(ReqAddItem))]
internal sealed class AddItemHandler

// 全域級(範例來自 README.ja.md)
// Global-level message (bound to the server Actor)
[MessageMapping(typeof(ReqHeartBeat))]
internal sealed class HeartBeatHandler
```

Source: [README.ja.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.ja.md#L362-L376)

- **RPC 雙向呼叫**：在請求/回應雙方都標註 `[MessageRpcMapping]`,由 `MessageRpcMappingAssemblyAnalyzer` 在編譯期驗證。處理器必須定義在 `GameFrameX.Hotfix`,違反時報告 `GFX0007`。

## 常見錯誤

| 症狀 / 錯誤碼 | 原因 | 修復 |
|---|---|---|
| 執行時日誌:`找不到[xxx][yyy]对应的handler` | `[MessageMapping]` 未掃描到處理器 | 確認類別在 `GameFrameX.Hotfix` 且以 `Handler` 結尾，重新編譯 |
| 編譯報錯 `GFX0006` | 處理器不在 `GameFrameX.Hotfix` | 將類別檔案移到 `GameFrameX.Hotfix` 專案 |
| 編譯報錯 `GFX0007` | RPC 處理器不在 `GameFrameX.Hotfix` | 將 `[MessageRpcMapping]` 處理器移到 `GameFrameX.Hotfix` |
| 編譯報錯 `GFX0010` | 處理器未標記 `sealed` | 給類別加上 `sealed` |
| 編譯報錯 `GFX0012` | 類別名稱不以 `Handler` 結尾 | 把類別名稱改為 `XxxHandler` |

## 背景(可選)

`GameFrameX.Architecture.Analyzers` 在編譯期透過 `MessageMappingAssemblyAnalyzer`、`MessageMappingNameAnalyzer`、`MessageMappingSealedAnalyzer`、`MessageRpcMappingAssemblyAnalyzer` 四個分析器強制驗證處理器放置位置、命名規範和密封性，確保執行時 `HotfixManager.GetTcpHandler(MessageId)` 一定能找到目標。
