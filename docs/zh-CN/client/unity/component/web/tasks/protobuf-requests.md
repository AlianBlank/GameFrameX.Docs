# 如何使用 Protocol Buffers 请求

通过 `WebManager` 提供的 `GetProtoBuf` / `PostProtoBuf` 泛型方法，即可用 protobuf-net 消息对象发起 HTTP 请求并直接得到反序列化后的响应对象；消息类型需实现 `IExtensible` 并用 `ProtoContract`/`ProtoMember` 标注。

## 前置条件

- 已安装 `com.gameframex.unity.web` 包，场景中存在 `WebComponent` 并持有 `IWebManager`（`WebManager`）实例。
- 消息类型按 protobuf-net 规则标注（`ProtoContract` + `ProtoMember`），满足 `class, IExtensible` 泛型约束。

## API 速查

| 方法 | 签名 | 说明 |
|------|------|------|
| `GetProtoBuf` | `Task<T> GetProtoBuf<T>(string url) where T : class, IExtensible;` | GET 一个 protobuf 消息并反序列化为 `T` |
| `PostProtoBuf` | `Task<T> PostProtoBuf<T>(string url, IExtensible requestData) where T : class, IExtensible;` | 将请求体序列化为 protobuf 后 POST，响应反序列化为 `T` |

## 操作步骤

1. 定义 protobuf 请求/响应消息类，字段用 `[ProtoMember(n)]` 指定编号：

```csharp
[ProtoContract]
public class UserResponse
{
    [ProtoMember(1)]
    public string UserName { get; set; }

    [ProtoMember(2)]
    public string Email { get; set; }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L116-L124)

2. 在业务代码中调用 `PostProtoBuf`（或 `GetProtoBuf`），`await` 返回的 Task 即得到响应对象：

```csharp
public async Task<UserResponse> GetUserProtoBufAsync(string userId)
{
    var request = new UserRequest { UserId = userId };
    return await webManager.PostProtoBuf<UserResponse>(
        "https://api.example.com/user/protobuf",
        request
    );
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L126-L133)

3. 按需包裹错误处理，例如捕获超时与网络 IO 异常：

```csharp
try
{
    return await webManager.GetToString(url);
}
catch (WebException ex) when (ex.Status == WebExceptionStatus.Timeout)
{
    Debug.LogError("请求超时: " + ex.Message);
    return null;
}
catch (IOException ex)
{
    Debug.LogError("网络IO错误: " + ex.Message);
    return null;
}
```

## 常见变体

- **自定义请求头**：protobuf 请求走 `WebBinaryData` 的 `Header` 字典，发送时会逐项写入请求头（原生平台写入 `request.Headers`，WebGL 平台调用 `SetRequestHeader`）。见 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L104-L110) 与 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L140-L146)。
- **WebGL 平台**：同一套 API 在 `UNITY_WEBGL` 下改用 `UnityWebRequest` + `UploadHandlerRaw` 上传字节，其余平台使用 `HttpWebRequest` 写入请求流。见 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L83-L101)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 请求发出后一直没有响应 | protobuf 请求先进入等待队列，由 `UpdateBinary` 每帧驱动出队；若 `WebManager` 未被更新（组件未激活）或已发送数达到 `MaxConnectionPerServer`，请求会一直排队 | 确认 `WebComponent` 正常运行、`WebManager` 处于更新状态，并合理设置并发上限 |
| 反序列化结果字段为空 | 消息类型缺少 `[ProtoContract]` / `[ProtoMember(n)]` 标注，或类型不满足 `class, IExtensible` 约束 | 为请求/响应类型补全 protobuf-net 特性标注 |
| 服务端解析失败 | 请求 `Content-Type` 固定为 `application/octet-stream`，服务端需按 protobuf 二进制解析 | 服务端按二进制 protobuf 处理，而不是文本格式 |

## 验证

- 在 `PostProtoBuf` 调用后打印响应对象字段（如 `response.UserName`），能取到服务端返回值即说明请求与反序列化成功。
- 发生网络错误时会抛出异常（原生平台为 `HttpWebRequest` 相关异常，WebGL 平台为 `unityWebRequest.error` 包装的 `Exception`），可据此确认失败原因。

## 背景

protobuf 请求在框架内部按"Binary 请求"处理：调用 `GetProtoBuf`/`PostProtoBuf` 后，请求被包装为 `WebBinaryData` 进入 `m_WaitingBinaryQueue`；每帧 `UpdateBinary` 在并发数未达上限时出队并调用 `MakeBinaryBytesRequest` 发送，响应字节封装为 `WebBufferResult` 完成回调。相关实现见 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L17-L55)。
