# 常见问题解答

本文档汇总了使用 GameFrameX Event 事件系统插件时可能遇到的常见问题及其解决方案。

## 概述

GameFrameX Event 是一个基于 Game Framework 的事件系统插件，提供类型安全的事件订阅、派发和管理功能。在使用过程中，开发者可能会遇到一些常见问题，本文档提供详细的排查指南和解决方案。

## 常见问题与解决方案

### 1. 事件无法接收

#### 症状
发布事件后，订阅者没有收到事件通知。

#### 原因分析
- 事件 ID 不匹配
- 订阅时机过早（事件管理器尚未初始化）
- 订阅者已被销毁但未取消订阅
- 使用了错误的事件派发方式

#### 解决方案

**检查事件 ID 一致性：**

```csharp
// 确保发布和订阅使用相同的事件 ID
public class GameStartEventArgs : GameEventArgs
{
    public override string Id => "game_start";  // 定义统一的事件 ID
}

// 订阅时
eventComponent.CheckSubscribe("game_start", OnGameStart);

// 发布时
eventComponent.Fire(this, GameStartEventArgs.Create("game_start"));
```

> Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L98-L101)

**确保订阅时机正确：**

```csharp
public class MyComponent : MonoBehaviour
{
    private void Start()
    {
        // 在 Awake 或 Start 中订阅事件，此时事件系统已初始化
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        eventComponent.CheckSubscribe("game_start", OnGameStart);
    }

    private void OnDestroy()
    {
        // 组件销毁时取消订阅，防止内存泄漏
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        if (eventComponent != null)
        {
            eventComponent.Unsubscribe("game_start", OnGameStart);
        }
    }

    private void OnGameStart(object sender, GameEventArgs e)
    {
        // 处理事件
    }
}
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L82-L88)

### 2. 内存泄漏

#### 症状
游戏运行时间变长后，内存占用持续增长，或者在场景切换后出现异常。

#### 原因分析
- 订阅事件后未取消订阅
- 事件处理函数持有大量对象引用
- 事件参数对象未正确释放回对象池

#### 解决方案

**始终在适当位置取消订阅：**

```csharp
public class PlayerController : MonoBehaviour
{
    private EventHandler<GameEventArgs> _onGameStartHandler;

    private void Awake()
    {
        // 保存委托引用，以便后续取消订阅
        _onGameStartHandler = OnGameStart;
    }

    private void Start()
    {
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        eventComponent.CheckSubscribe("game_start", _onGameStartHandler);
    }

    private void OnDestroy()
    {
        // 重要：销毁时取消订阅！
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        if (eventComponent != null)
        {
            eventComponent.Unsubscribe("game_start", _onGameStartHandler);
        }
    }

    private void OnGameStart(object sender, GameEventArgs e)
    {
        // 处理事件
    }
}
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L106-L114)

**正确使用对象池：**

```csharp
// 创建自定义事件参数时使用对象池
public class ScoreEventArgs : GameEventArgs
{
    public int Score { get; private set; }

    public static ScoreEventArgs Create(int score)
    {
        var args = ReferencePool.Acquire<ScoreEventArgs>();
        args.Score = score;
        return args;
    }

    public override void Clear()
    {
        Score = 0;
    }

    public override string Id => "score_changed";
}

// 发布事件
eventComponent.Fire(this, ScoreEventArgs.Create(100));

// 注意：Fire 方法会在下一帧自动释放参数回对象池
// 如果使用 FireNow，需要手动释放
```

> Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L32-L37)

### 3. 事件系统初始化失败

#### 症状
运行时出现 "Event manager is invalid" 错误，或事件功能完全不可用。

#### 原因分析
- 缺少必需的依赖包 `GameFrameX.Runtime`
- EventComponent 未正确添加到场景
- GameFrameworkEntry 未正确初始化

#### 解决方案

**安装依赖包：**

确保已安装 `GameFrameX.Runtime` 依赖包。可通过以下方式安装：

```json
// 在 manifest.json 的 dependencies 中添加
{
  "com.gameframex.unity.runtime": "https://github.com/GameFrameX/com.gameframex.unity.runtime.git"
}
```

> Source: [GameFrameX.Event.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameX.Event.Runtime.asmdef#L2-L5)

**正确配置 EventComponent：**

```csharp
// 在场景中创建一个空物体，添加 EventComponent
public class GameEntry : MonoBehaviour
{
    public static EventComponent EventComponent { get; private set; }

    private void Awake()
    {
        // 确保场景中有 EventComponent
        EventComponent = gameObject.GetOrAddComponent<EventComponent>();
    }
}
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L43-L54)

### 4. 事件派发时机问题

#### 症状
- 事件在预期之前或之后触发
- 异步操作中事件处理顺序不正确

#### 原因分析
- 混淆了 `Fire()` 和 `FireNow()` 的区别
- 对线程安全机制理解不足

#### 解决方案

**理解两种派发模式的区别：**

| 方法 | 线程安全 | 派发时机 | 适用场景 |
|------|---------|---------|---------|
| `Fire()` | 是 | 下一帧 | 大多数情况，特别是跨线程调用 |
| `FireNow()` | 否 | 立即 | 紧急事件、同步回调 |

```csharp
public class NetworkManager
{
    // 网络回调可能在子线程调用，使用 Fire 确保线程安全
    public void OnReceiveData(byte[] data)
    {
        // 在子线程中接收数据
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        
        // 使用 Fire 在主线程下一帧处理
        eventComponent.Fire(this, new NetworkDataEventArgs(data));
    }

    // 本地同步事件可以使用 FireNow
    public void TriggerImmediateEvent()
    {
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        
        // 立即派发，用于需要即时反馈的场景
        eventComponent.FireNow(this, new ImmediateEventArgs());
    }
}
```

> Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L127-L140)

### 5. 重复订阅问题

#### 症状
同一个事件处理函数被多次调用，导致逻辑重复执行。

#### 原因分析
- 在 `Start()` 中重复调用订阅方法
- 未检查是否已订阅就再次订阅

#### 解决方案

**使用 CheckSubscribe 自动检查：**

```csharp
private void Start()
{
    var eventComponent = GameEntry.GetComponent<EventComponent>();
    
    // CheckSubscribe 会检查是否已订阅，避免重复订阅
    eventComponent.CheckSubscribe("score_changed", OnScoreChanged);
}

// 不要使用旧的 Subscribe 方法（已标记为 obsolete）
// eventComponent.Subscribe("score_changed", OnScoreChanged);  // 不推荐
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L82-L88)

### 6. 自定义事件参数问题

#### 症状
自定义事件参数无法被正确派发或接收。

#### 原因分析
- 未正确继承 `GameEventArgs`
- 未实现必需的 `Id` 属性和 `Clear()` 方法
- 未使用对象池正确管理生命周期

#### 解决方案

**正确创建自定义事件参数：**

```csharp
// 1. 继承 GameEventArgs
public class PlayerDieEventArgs : GameEventArgs
{
    // 2. 实现 Id 属性
    public override string Id => "player_die";
    
    // 3. 添加事件数据
    public int PlayerId { get; private set; }
    public string Reason { get; private set; }

    // 4. 使用静态 Create 方法封装对象池获取
    public static PlayerDieEventArgs Create(int playerId, string reason)
    {
        var args = ReferencePool.Acquire<PlayerDieEventArgs>();
        args.PlayerId = playerId;
        args.Reason = reason;
        return args;
    }

    // 5. 实现 Clear 方法释放数据
    public override void Clear()
    {
        PlayerId = 0;
        Reason = null;
    }
}
```

> Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L16-L18)

> Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L18-L25)
