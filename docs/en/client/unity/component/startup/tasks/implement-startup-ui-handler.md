# How to Implement a Custom Startup UI Handler

By implementing the `IStartupUIHandler` interface and injecting it at startup, any UI backend (FairyGUI / UGUI / custom) can be integrated into the GameFrameX startup process to handle displaying progress text, the download progress bar, and the version upgrade dialog.

## Prerequisites

- The project references `GameFrameX.Startup.Runtime`.
- An `IStartupUIHandler` implementation class is ready (placed in the application layer or your own UI package).
- The UI resource referenced by `StartupOptions.LauncherUIResName` exists (default `"UI/UILauncher"`).

## Steps

1. **Implement the interface**: Create a new class that implements `IStartupUIHandler`, where `StartAsync` loads and displays the full-screen UI, `SetTipText` / `SetProgress` / `SetProgressUpdateFinish` are used to update tips and progress, `ShowUpgradeAsync` is used for the version upgrade dialog, and `Dispose` is used to close the UI and release subscriptions.

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   public sealed class MyStartupUIHandler : IStartupUIHandler
   {
       public async UniTask StartAsync(string uiResName)
       {
           // Load and open the full-screen startup UI according to uiResName
           // For example, load it via FairyGUI / UGUI / Addressables, etc.
           await UniTask.CompletedTask;
       }

       public void SetTipText(string text)
       {
           // Update the tip text (text)
       }

       public void SetProgress(float progress, string sizeInfo)
       {
           // progress: 0-1, sizeInfo: e.g. "5.2MB / 100MB"
       }

       public void SetProgressUpdateFinish()
       {
           // Visual feedback when the download completes (hide the progress bar, etc.)
       }

       public UniTask<bool> ShowUpgradeAsync(StartupUpgradeInfo upgradeInfo)
       {
           // When IsForce = true, the upgrade is forced; return true to continue the flow, return false to stay on the dialog
           // AppDownloadUrl / UpdateTitle / UpdateAnnouncement are rendered directly to the UI
           return UniTask.FromResult(true);
       }

       public void Dispose()
       {
           // Close the UI, release subscriptions, and reclaim resources
       }
   }
   ```

2. **Inject into the launcher**: `StartupRunner.Run` accepts an `IStartupUIHandler` parameter, and internally writes it to the flow's BlackBoard (key `BlackBoardKeys.StartupUIHandler`) so that all Procedures can read it.

   ```csharp
   using GameFrameX.Startup.Runtime;
   using UnityEngine;

   public sealed class StartupEntry : MonoBehaviour
   {
       private async void Start()
       {
           var options = new StartupOptions
           {
               LauncherUIResName = "UI/UILauncher",
           };
           var uiHandler = new MyStartupUIHandler();
           var hotfixLauncher = /* your IHotfixLauncher */ null;
           var procedures = /* your procedure list */ null;

           var result = await StartupRunner.Run(options, uiHandler, hotfixLauncher, procedures);
           Debug.Log($"Startup completed: {result.Success}");
       }
   }
   ```

3. **Read it in a Procedure**: Business-side Procedures can get the injected instance via `StartupProcedureUtility.GetUIHandler(procedureOwner)` and call `SetTipText` / `SetProgress`, etc. to update the UI.

   ```csharp
   var ui = StartupProcedureUtility.GetUIHandler(procedureOwner);
   ui?.SetTipText("正在检查版本...");
   ui?.SetProgress(0.5f, "52MB / 100MB");
   ```

   Source: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L46-L48)

4. **Cleanup after startup finishes**: After `StartupRunner` completes, call `uiHandler.Dispose()` to close the full-screen UI and release subscriptions.

## Common Variants

- **Force upgrade dialog**: When `ShowUpgradeAsync` receives `StartupUpgradeInfo.IsForce == true`, only render the dialog and return `false`, waiting for the user to navigate to `AppDownloadUrl`.
- **Progress units**: `sizeInfo` is formatted by the caller; a typical format is `"5.2MB / 100MB"`. If you need custom units, parse it yourself inside `SetProgress`.
- **Replace the default UI resource**: Simply change `LauncherUIResName` to your own agreed UI resource path; `StartAsync` will receive that value.

## Common Errors

| Error | Cause | Fix |
|------|------|------|
| `NullReferenceException` occurs in a Procedure | `uiHandler` was not passed into `StartupRunner.Run`, so it is `null` in the BlackBoard | Check that the argument order at the call site matches `StartupRunner.Run(options, uiHandler, hotfixLauncher, procedures)` |
| `SetProgress` does not display | The `progress` value is not within 0-1, or the `sizeInfo` string is empty | Ensure the caller normalizes the value, or clamp the boundaries on the UI side |
| `ShowUpgradeAsync` never returns | Forgot `UniTask.FromResult` or did not `await` the close callback | Wrap the button click into a `UniTaskCompletionSource<bool>` to complete the Task |
| The flow gets stuck after the upgrade dialog returns `false` | The flow expects the user to choose `true` in order to advance; force-upgrade scenarios should return `false` and be handled externally | Non-force upgrade dialogs should return `true` |

## Background (Optional)

`IStartupUIHandler` decouples the UI layer from the startup flow: the package depends only on the interface and the `BlackBoardKeys.StartupUIHandler` key name, while the concrete FairyGUI / UGUI implementation is left to the application layer. `StartupRunner.Run` writes the handler into the flow FSM via `VarObject`, and each Procedure then retrieves it with `StartupProcedureUtility.GetUIHandler`.
