# What to Do When Entity Display Fails

After calling `ShowEntity` / `ShowEntityAsync`, if the entity does not appear in the scene, or the log indicates that the `ShowEntityFailure` event has been triggered, it is usually caused by incorrect configuration of entity groups, resources, or helper components. This page provides quick diagnosis and fix steps based on common causes.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| The `ShowEntityFailure` event is triggered immediately, and the log contains `Entity group name is invalid.` | The passed-in `entityGroupName` is `null` / an empty string, or the entity group is not registered | Add an entity group with the same name to `m_EntityGroups` of `EntityComponent` in advance |
| The message `Entity group is invalid.` appears | The entity group exists, but its internal `EntityGroup` instance is not initialized or has been destroyed | Use `HasEntityGroup` to confirm the group exists first, then call `ShowEntity` |
| The message `Can not create entity helper.` appears | `EntityComponent.Awake`/`Start` failed to reflect an `EntityHelperBase` instance based on `m_EntityHelperTypeName` | Check whether `m_EntityHelperTypeName` is `GameFrameX.Entity.Runtime.DefaultEntityHelper` or the fully qualified type name of a custom helper class; custom helpers must be attached to the `m_CustomEntityHelper` field |
| The `ShowEntityFailure` event keeps triggering and resource loading fails | `m_AssetManager` is not set, or the asset address (`entityAssetName`) is not in the YooAsset asset manifest | Confirm that `EntityComponent.Start` has called `SetResourceManager`; correctly configure the tags and addresses of the entity Prefab in YooAsset |
| The entity is created successfully but the GameObject is not displayed | `m_InstanceRoot` is not attached to a visible scene root, or the Prefab's own Layer/visibility is disabled | Specify a visible `m_InstanceRoot` for `EntityComponent` in the scene; check the Prefab's `MeshRenderer` state |
| The async API `ShowEntityAsync` never returns | Resource loading is stuck, or `m_EntitiesBeingLoaded` receives duplicate requests for the same entity | Avoid issuing multiple Show calls for the same `EntityId` in the same frame; confirm the resource manager is not blocked externally |

## Fix Steps

### 1. Confirm the Entity Group Is Registered

`EntityManager` throws `GameFrameworkException("Entity group name is invalid.")` directly when the entity group name is empty. Before any `ShowEntity` call, the group must be added first via `EntityComponent.AddEntityGroup`.

```csharp
// Source: Runtime/Entity/Entity/EntityManager.Get.cs#L53-L61
public bool HasEntityGroup(string entityGroupName)
{
    if (string.IsNullOrEmpty(entityGroupName))
    {
        throw new GameFrameworkException("Entity group name is invalid.");
    }
    return m_EntityGroups.ContainsKey(entityGroupName);
}
```

Steps:

1. Open the Inspector of the scene object with `EntityComponent` attached.
2. In the `Entity Groups` list, add the groups to be used (fill in `Name`, `InstanceAutoReleaseInterval`, `InstanceCapacity`, `InstanceExpireTime`, `InstancePriority`).
3. Before using a group name in code, call `HasEntityGroup` to validate it.

### 2. Confirm the Entity Helper Is Available

`EntityComponent.Start` calls `Helper.CreateHelper` to create the entity helper; if it returns `null`, it outputs `Log.Error("Can not create entity helper.")` and aborts initialization.

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L171-L183
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
    return;
}
entityHelper.name = "Entity Helper";
Transform transform = entityHelper.transform;
transform.SetParent(this.transform);
transform.localScale = Vector3.one;
m_EntityManager.SetEntityHelper(entityHelper);
```

Steps:

1. Confirm the class pointed to by the `Entity Helper Type Name` field exists (default is `GameFrameX.Entity.Runtime.DefaultEntityHelper`).
2. Custom helpers must inherit from `EntityHelperBase` and implement the entity instantiation logic; drag the instance onto the `Custom Entity Helper` field of the `Entity Component`.
3. If the helper class is in a separate assembly, confirm that the assembly is included in the build and can be resolved via reflection.

### 3. Confirm the Resource Manager Is Injected

`EntityManager` depends on `IAssetManager` (injected via `SetResourceManager`) when loading entity Prefabs; if not injected, `ShowEntityFailure` will fail at the loading stage.

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L167-L169
m_EntityManager.SetResourceManager(GameFrameworkEntry.GetModule<IAssetManager>());
m_EntityManager.SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>());
```

Steps:

1. Confirm that `Asset Component` and `Object Pool Component` are attached in the scene and their Awake order is earlier than `EntityComponent`.
2. Confirm that YooAsset is correctly initialized and the passed-in `entityAssetName` (path or tag) exists in the asset manifest.
3. If necessary, enable `Enable Show Entity Dependency Asset Event` and observe via events whether dependent resources have finished downloading.

### 4. Listen to Failure Events to Locate the Root Cause

`EntityComponent` already subscribes to `ShowEntityFailure` by default in Awake. During debugging, you can additionally subscribe in your own scripts to obtain information such as `EntityId`, `EntityAssetName`, `EntityGroupName`, and `ErrorMessage`.

```csharp
// Source: Runtime/Entity/Entity/EntityManager.cs#L118-L122
public event EventHandler<ShowEntityFailureEventArgs> ShowEntityFailure
{
    add { m_ShowEntityFailureEventHandler += value; }
    remove { m_ShowEntityFailureEventHandler -= value; }
}
```

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L130-L131
m_EntityManager.ShowEntitySuccess += OnShowEntitySuccess;
m_EntityManager.ShowEntityFailure += OnShowEntityFailure;
```

Steps: In the failure callback, print `EventArgs.ErrorMessage` and `EventArgs.EntityId`, and trace back to items 1–3 above based on the message.

### 5. Check the Runtime Instance Root Node

The entity helper creates a `GameObject("Entity Instances")` as `m_InstanceRoot`; if this root node is disabled or not in the scene, the entity is created successfully but is visually invisible.

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L185-L190
if (m_InstanceRoot == null)
{
    m_InstanceRoot = new GameObject("Entity Instances").transform;
    m_InstanceRoot.SetParent(gameObject.transform);
    m_InstanceRoot.localScale = Vector3.one;
}
```

Steps:

1. Locate the `Entity Instances` node in the Hierarchy and confirm it is active.
2. If `m_InstanceRoot` is customized, confirm that both its parent node and itself are active and not culled by the camera (e.g., `Layer` settings, `Culling Mask`, etc.).

## Verification

1. Call `ShowEntity<MyEntityLogic>(entityId, "Default", "MyPrefab", userData)` in a test scene.
2. Watch the Console: the `ShowEntitySuccess` event should appear, and `OnShowEntitySuccess` should be called once.
3. In the Hierarchy, confirm a GameObject named after the entity's `EntityId` appears under `Entity Instances`, with the expected position/scale/visibility.
4. After calling `HideEntity(entityId)`, confirm the object is recycled back to the object pool and the `HideEntityComplete` event triggers normally.

## Background (Optional)

`EntityManager` internally maintains dictionaries and queues such as `m_EntityInfos`, `m_EntityGroups`, and `m_EntitiesBeingLoaded`; resource loading is done asynchronously via `IAssetManager`, and upon completion `IEntityHelper` is called to instantiate the entity and emit `ShowEntitySuccess`; any error thrown at any step goes through the `ShowEntityFailure` path and reuses the `ShowEntityInfo` reference object ([ShowEntityInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.ShowEntityInfo.cs#L38-L106)).
