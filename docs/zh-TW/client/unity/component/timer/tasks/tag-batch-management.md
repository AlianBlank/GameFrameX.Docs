# 依標籤批次管理計時器

用 `Add()` 建立計時器時傳入 `tag` 字串，之後即可用 `PauseByTag` / `ResumeByTag` / `RemoveByTag` / `HasTag` 四個方法一次操作同標籤下的全部計時器，而不必逐個持有計時器 ID。

## 前置條件

- 場景中已存在 `TimerComponent` 元件（選單路徑 `GameFrameX/Timer`），它在 `Awake` 中透過 `GameFrameworkEntry.GetModule<ITimerManager>()` 取得管理器。

## 操作步驟

1. 用 `Add()` 建立計時器，並把分組名傳給第 5 個參數 `tag`。`tag` 預設為 `null`，只有顯式傳入的計時器才會進入該標籤分組：

```csharp
using System;
using GameFrameX.Timer.Runtime;
using UnityEngine;

public class BattleScene : MonoBehaviour
{
    TimerComponent _timer;

    void Start()
    {
        // Add(interval, repeat, callback, callbackParam, tag, ...)
        _timer.Add(1f, 0, OnEnemyTick, null, "Battle");    // 每秒刷新，無限重複
        _timer.Add(5f, 10, OnBuffRefresh, null, "Battle"); // 每 5 秒一次，共 10 次
        _timer.Add(30f, 1, OnBossRoar, null, "Battle");    // 30 秒後觸發一次
    }

    void OnEnemyTick(object param) { /* ... */ }
    void OnBuffRefresh(object param) { /* ... */ }
    void OnBossRoar(object param) { /* ... */ }
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

2. 需要整組暫停時呼叫 `PauseByTag`，暫停期間不累積時間：

```csharp
_timer.PauseByTag("Battle"); // 例如：開啟暫停選單時
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L152-L155)

3. 恢復時呼叫 `ResumeByTag`，從暫停處繼續累積：

```csharp
_timer.ResumeByTag("Battle"); // 例如：關閉暫停選單時
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L161-L164)

4. 分組結束時呼叫 `RemoveByTag` 一次性移除全部成員：

```csharp
_timer.RemoveByTag("Battle"); // 例如：戰鬥結束時統一清理
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L170-L173)

5. 用 `HasTag` 判斷該標籤下是否還有活躍計時器，再做後續邏輯：

```csharp
if (_timer.HasTag("Battle"))
{
    Debug.Log("戰鬥計時器仍在執行");
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L180-L183)

標籤相關方法一覽：

| 方法 | 簽章 | 說明 |
|------|------|------|
| `PauseByTag` | `void PauseByTag(string tag)` | 暫停該標籤下所有未刪除的計時器 |
| `ResumeByTag` | `void ResumeByTag(string tag)` | 恢復該標籤下所有計時器 |
| `RemoveByTag` | `void RemoveByTag(string tag)` | 移除該標籤下所有計時器 |
| `HasTag` | `bool HasTag(string tag)` | 該標籤下存在至少一個計時器時回傳 `true` |

以上方法同時定義在 `ITimerManager` 介面與 `TimerComponent` 上，二者行為一致。

## 常見變體

- **只執行一次的任務也要歸組**：`AddOnce` 與 `AddUpdate` 沒有提供 `tag` 參數；若需要依標籤管理，改用 `Add(interval, 1, callback, param, tag)` 等價實作單次觸發。
- **依 ID 精確操作單一成員**：`Add()` 的回傳值是計時器 ID，可搭配 `Pause(int id)` / `Resume(int id)` / `Remove(int id)` / `IsPaused(int id)` 單獨控制組內某一項，參見 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L105-L146)。

## 常見錯誤

- **標籤傳成了 `null` 或空字串**：`Add` 的 `tag` 參數預設 `null`，漏傳時計時器不會進入任何分組，後續 `PauseByTag` 等呼叫對其無效，但不會出錯——呼叫一個沒有成員的標籤是安全的空操作。
- **以為 `RemoveByTag` 會觸發 `onComplete`**：標籤操作走的是與 `Remove(id)` 相同的移除路徑（[TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)），只做移除，不要依賴其中的完成回呼做場景切換等關鍵邏輯。
- **在回呼內直接 `RemoveByTag` 目前標籤**：實作中先把 ID 集合複製到暫存清單再逐個移除以避免遍歷中修改集合，因此可以安全在回呼內呼叫；但仍建議把移除延後到回呼返回後，保持邏輯清晰。

## 背景

`TimerManager` 內部用 `_tags`（`tag -> ID 集合`）記錄分組，`TimerItem` 上儲存 `Tag` 字串；所有標籤操作都在 `lock (Locker)` 內完成，確保多執行緒下的安全。`PauseByTag` 只對未刪除的項生效並置 `IsPaused = true`，`ResumeByTag` 則無條件清除暫停標記，`HasTag` 只要 `ids.Count > 0` 即回傳 `true`。關於計時器模組的整體結構，見《計時器元件概述》。
