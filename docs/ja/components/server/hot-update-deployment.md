# ホットアップデートパッケージの公開と有効性の検証方法

ホットアップデートを公開するには、3つのステップだけです。`GameFrameX.Hotfix.dll` をコンパイルし、DLL をサーバーの固定ディレクトリに配置し、Reload HTTP インターフェースを呼び出して読み込みをトリガーします。有効性の検証は、返されるバージョン番号とサーバーログの確認で行います。

## 前提条件

- GameFrameX サービスがすでにサーバーで稼働しており、HTTP ポート(デフォルト `28080`)にアクセス可能であること
- ビジネスコードの修正が完了し、ローカルでのコンパイルが通ること
- 対象マシンでホットアップデート DLL の配置ディレクトリが確定していること(以下では `/opt/gameframex/hotfix/` を例とする)

## 操作手順

1. **新バージョンの Hotfix アセンブリをコンパイルする**

   ソリューションのルートディレクトリで実行します:

   ```bash
   dotnet build GameFrameX.Hotfix/GameFrameX.Hotfix.csproj -c Release
   ```

   ビルド成果物のパス:`GameFrameX.Hotfix/bin/Release/net10.0/GameFrameX.Hotfix.dll`。

2. **DLL をサーバーの指定ディレクトリに配置する**

   ビルド成果物とその依存関係(新しく導入された NuGet パッケージがある場合)をサーバーのホットアップデート用ディレクトリにコピーします:

   ```bash
   scp GameFrameX.Hotfix/bin/Release/net10.0/GameFrameX.Hotfix.dll \
       user@server:/opt/gameframex/hotfix/
   ```

3. **ホットアップデート HTTP インターフェースをトリガーする**

   ```bash
   curl -X POST "http://<server-ip>:28080/game/api/Reload?version=1.7.2"
   ```

   サーバーから返される `version` が現在有効なバージョン番号です。

4. **有効性を検証する**

   - 同じインターフェースを再度 GET するかログを確認し、バージョン番号が `1.7.2` に更新されたことを確認する
   - サーバーログで `HotfixManager` が新しいアセンブリを読み込み、`HotfixModule` が Agent / Handler / EventListener をスキャンした記録を確認する
   - 新ロジックがヒットする業務リクエストを 1 回実行し、動作が想定通りであることを検証する

## よくあるバリエーション

- **Docker 環境への配置**:DLL をコンテナにマウントされたボリュームディレクトリにコピーする(例: `docker cp GameFrameX.Hotfix.dll game:/app/hotfix/`)、その後ホストにマッピングされたポート `38080` を呼び出す。
- **マルチインスタンスクラスタ**:各 `game-1` ~ `game-N` ノードに対してステップ 2 とステップ 3 を繰り返すか、設定管理ツールを利用して一括配信する。
- **一部の Agent のみを更新する**:DLL 全体を再公開する必要はなく、`GameFrameX.Hotfix` プロジェクトで対応する `*Agent.cs` のみを修正し、再ビルドして配置するだけでよい。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|:-----|:-----|:-----|
| Reload インターフェースが 500 またはタイムアウトを返す | 新しい DLL に依存アセンブリが足りない | 新しく追加された NuGet 依存関係もホットアップデート用ディレクトリに一緒にコピーする |
| Reload は成功したがバージョン番号が変化しない | HTTP アドレスが game サービスを指していない、またはポートが間違っている | 呼び出しているのが `game` サービスの HTTP ポートであることを確認する(デフォルト `28080`、ホストマッピング `38080`) |
| Reload 後も業務動作が変化しない | 修正したコードが `Hotfix` レイヤではなく `Apps`(ホットアップデート不可)レイヤに存在する | `GameFrameX.Hotfix` 配下の `*Agent.cs`、Handler、EventHandler のみがホットアップデート可能で、永続化状態は `Apps` レイヤにある |
| 古いリクエストが処理途中で中断された | 猶予期間の終了を待たずにサービスを再起動した | 古いアセンブリはデフォルトで 10 分間の猶予期間が保持されるため、ログにアンロード完了が表示されるのを待ってから操作する |

## 背景(任意)

ホットアップデートはリサイクル可能な `AssemblyLoadContext` を介して新しい DLL を読み込み、読み込み完了後に `HotfixModule` が Agent、Handler、EventListener をスキャンし、`ActorManager.ClearAgent()` を呼び出してキャッシュされた Agent インスタンスをクリアします。Apps レイヤ(`StateComponent`、永続化状態)はホットアップデート不可であり、これはホットアップデートの境界におけるハードな制約です。
