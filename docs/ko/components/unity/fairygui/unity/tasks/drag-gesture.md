# 드래그 및 제스처 인터랙션

FairyGUI에서 UI 컴포넌트에 제스처 인터랙션을 추가할 때는 `Runtime/Gesture/` 디렉터리의 제스처 클래스를 사용합니다: `SwipeGesture`(스와이프), `LongPressGesture`(길게 누르기), `PinchGesture`(핀치 줌), `RotationGesture`(회전)이며, 이들은 모두 `EventDispatcher`를 상속하고 이벤트 콜백을 통해 비즈니스 코드에 제스처 데이터를 전달합니다. 참고: 본 저장소에서는 독립적인 드래그 제스처 클래스(예: `DragGesture` 또는 `DragDropManager`)가 **검색되지 않았으므로**, 드래그 기능이 필요하면 컴포넌트(GObject) 자체의 드래그 인터페이스를 참조하십시오. 해당 부분은 이 페이지에서 확인한 소스 코드 범위에 포함되지 않습니다.

## 사전 조건

- 본 패키지가 Unity 프로젝트에 임포트되어 있고, `Runtime/Gesture/` 디렉터리가 패키지와 함께 컴파일됩니다(`FairyGUI` 관련 어셈블리).
- 제스처의 대상은 FairyGUI 디스플레이 객체입니다(예: `GComponent` 내의 컴포넌트).

2. 비즈니스 스크립트에서 해당 제스처 인스턴스를 생성하고, 대상 컴포넌트를 호스트로 지정합니다(생성자 매개변수는 해당 소스 파일의 생성자 정의를 따릅니다).

3. 이벤트 콜백으로 제스처의 트리거/이동/종료를 감지하고, 콜백에서 제스처 데이터를 읽어 UI 또는 로직을 갱신합니다. 각 제스처 클래스의 이벤트 상수 이름과 콜백 매개변수 구조는 위 표의 소스 파일을 직접 열어 확인하십시오. 이 페이지의 소스 코드 확인 범위가 제한적이어 시그니처를 항목별로 발췌하지 않았으며, 오용을 방지하기 위해 여기에 다시 서술하지 않습니다.

4. 제스처가 더 이상 필요 없을 때 인스턴스를 해제하여, 컴포넌트가 파괴된 후에도 콜백이 계속 트리거되는 것을 방지합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `DragGesture` / `DragDropManager` 타입을 찾을 수 없음 | 본 저장소의 `Runtime/Gesture/`에는 위 4개의 제스처 클래스만 있으며, 검색 결과 드래그 클래스와 일치하는 항목이 없음 | 스와이프에는 `SwipeGesture` 사용; 실제 "집어서 놓기(드래그 앤 드롭)" 인터랙션은 GObject의 드래그 관련 인터페이스를 확인한 후 사용하십시오 |
| 제스처가 반응하지 않음 | 제스처가 올바른 호스트 컴포넌트에 바인딩되지 않았거나, 컴포넌트의 터치 인터랙션이 활성화되지 않음 | 생성 시 전달한 대상 컴포넌트를 확인하고, 해당 컴포넌트가 터치 이벤트를 수신할 수 있는지 확인 |
| 콜백 매개변수 필드를 잘못 사용함 | 이벤트가 담고 있는 데이터 구조는 각 제스처 소스 파일의 정의를 기준으로 함 | 해당 제스처 소스 파일을 열어 필드를 확인한 후 코딩 |

## 배경

제스처 클래스는 `Runtime/Gesture/` 아래에 위치하며, FairyGUI 런타임의 일부입니다. 이들은 멀티 터치/포인터 입력을 시맨틱 이벤트(스와이프 방향, 핀치 비율, 회전 각도, 길게 누르기 시간)로 해석하며, 비즈니스 계층은 이벤트를 구독하기만 하면 되고 직접 계산할 필요가 없습니다. 소스 코드에서 직접 보여줄 수 있는 호출 예제를 찾지 못했으므로, 이 페이지는 "클래스 선택 → 생성 → 구독 → 해제"를 연동 흐름의 주축으로 삼으며, 시그니처 세부 사항은 소스 파일을 유일한 근거로 합니다.
