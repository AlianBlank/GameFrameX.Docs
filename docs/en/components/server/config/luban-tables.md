# Loading Luban Config Tables with TablesComponent

`TablesComponent` is a config table container automatically generated by the Luban tool in GameFrameX.Config. It is responsible for loading all `.json` config tables into `ConfigComponent` at runtime and resolving cross-table reference relationships. After reading this page, you will be able to load all Luban tables in one pass during server or client startup and access specific entries on demand.

## Prerequisites

- The `GameFrameX.Config` project has been generated via the Luban tool, and the output includes `TablesComponent.cs` along with `Tables/*.cs` and `Local/*.cs`.
- The project references `GameFrameX.Core.Abstractions` (which provides `ConfigComponent` and `BeanBase`).
- Prepare the JSON files exported by Luban (following naming conventions such as `tables_tbxxx` and `local_tblocalization`), and deploy them to a location readable by the `loader` callback (local files, AssetBundle, or remote download all work).

## Steps

1. **Instantiate the config manager**. `ConfigComponent` already creates `TablesComponent` internally, so use it directly:

   ```csharp
   var configComponent = new ConfigComponent();
   var tables = configComponent.Tables; // Private property; must be injected via Init below
   ```

   Source: [ConfigComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/ConfigComponent.cs#L14-L19)

2. **Call `Init` to inject `ConfigComponent`**. This step hands the table registration entry point over to `ConfigComponent`, so subsequent `Add` calls write tables into the unified container:

   ```csharp
   tables.Init(configComponent);
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

3. **Provide a `loader` callback and load asynchronously**. The `loader` receives a table name and returns the `JsonElement` for that table's JSON. All tables are loaded in parallel, and `Refresh` runs automatically afterwards to resolve references:

   ```csharp
   await tables.LoadAsync(async tableName =>
   {
       var json = await File.ReadAllTextAsync($"Configs/{tableName}.json");
       return JsonDocument.Parse(json).RootElement.Clone();
   });
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L56)

4. **Read specific tables and entries**. Once loading completes, obtain the concrete table objects through `TablesComponent`'s strongly typed properties. For example:

   ```csharp
   var itemConfig = tables.TbItemConfig;
   var oneItem = itemConfig.Get(1001); // Index/query method generated by Luban
   ```

   The table properties currently exposed by `TablesComponent`: `TbLocalization`, `TbAchievementConfig`, `TbItemConfig`, `TbSoundsConfig`.

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L18-L21)

5. **(Optional) Reload in hot-update scenarios**. There is no need to call `Init` again before calling `LoadAsync` again; the `loader` re-reads the latest JSON for each table, and `Refresh()` re-runs `PostInit` and `ResolveRef`, overwriting the previous reference relationships.

## Common Variants

- **Remote download + local cache**: Implement the `loader` as "check the local cache first, fall back to HTTP on a cache miss, save to disk after downloading, and parse the JSON", enabling CDN hot updates for Luban tables.
- **Read from AssetBundle**: On the client, replace the `loader` with `Resources.LoadAsync<TextAsset>(tableName).Result.text`; simply keep the function signature consistent — no changes to `TablesComponent` are needed.
- **Lazy loading for selected tables**: Comment out the tables that do not need to be loaded at startup from `LoadAsync` (the commented-out code is preserved in the generated files), and load them on demand from the business side via `new TbXxx(...)` instead.

## Common Errors

- **Table JSON not found**: An exception thrown by `loader` causes `Task.WhenAll` to fail, and the entire `LoadAsync` throws; make sure file naming strictly follows the `tables_xxx` / `local_xxx` prefixes.
- **Reference resolution failure**: `Refresh()` internally calls `ResolveRef(this)` on each table; if `PostInit` or `ResolveRef` accesses a table that has not been loaded yet, a null reference occurs, so make sure every related table goes through `LoadAsync`.
- **Repeated `Init`**: Calling `Init` again re-executes `RemoveAllConfigs()`, which clears the loaded table references; this is normally only used in reset scenarios.
- **Modifying generated files**: `TablesComponent.cs` and `Tables/*.cs` are both marked with `// <auto-generated>` at the top; any hand-written changes will be overwritten the next time Luban regenerates.

## Background (Optional)

`TablesComponent` is the product of the Luban `gen_cs_server_json` / `gen_cs_client_json` templates: each table corresponds to a `BeanBase` subclass (e.g., [`ItemConfig`](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Tables/ItemConfig.cs#L15-L76)); the constructor deserializes fields from a `JsonElement`, and `ResolveRef` is used to link `xxx_ref` fields back to concrete row objects across tables.
