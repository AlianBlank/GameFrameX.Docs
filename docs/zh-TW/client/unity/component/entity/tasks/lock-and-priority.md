# 如何鎖定實體並控制回收優先順序

實體框架透過物件池重複使用實體實例。您可以鎖定某個實體實例以防止其被自動回收，並在建立實體群組時設定物件池優先順序以影響回收順序。本頁說明如何呼叫這兩項功能以及它們如何生效。

## 前置條件

- 場景中已附加 `EntityComponent`，並已透過 Inspector 或程式碼新增實體群組。
- 只有在實體群組存在之後，才能對群組內的實體執行鎖定/解鎖操作。

## 步驟

### 1. 鎖定或解鎖實體實例

透過 `EntityComponent.SetEntityInstanceLocked(Entity entity, bool locked)` 設定。一旦鎖定，底層物件池在自動釋放時將不會回收該實例；一旦解鎖，它將恢復為可回收狀態。

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

public class MyBehaviour : MonoBehaviour
{
    [SerializeField] private EntityComponent entityComponent;

    // 鎖定實體以防止自動回收（例如在播放重要過場動畫時）
    public void LockEntity(Entity entity)
    {
        entityComponent.SetEntityInstanceLocked(entity, true);
    }

    // 過場動畫結束後解鎖，讓物件池能正常回收
    public void UnlockEntity(Entity entity)
    {
        entityComponent.SetEntityInstanceLocked(entity, false);
    }
}
```

來源：[EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L1140-L1170)

### 2. 新增實體群組時設定物件池優先順序

`AddEntityGroup` 的完整多載接受一個 `instancePriority` 參數。數值越大，當底層物件池執行自動釋放時，該實例越晚被回收。`0` 為預設值，對應常數 `DefaultPriority`。

```csharp
using GameFrameX.Entity.Runtime;

public class MyBootstrap
{
    public void Setup(EntityComponent entityComponent)
    {
        // 容量 32，到期時間 60 秒，優先順序 10（高於預設值 0，較晚被回收）
        entityComponent.AddEntityGroup(
            entityGroupName: "Boss",
            instanceAutoReleaseInterval: 60f,
            instanceCapacity: 32,
            instanceExpireTime: 60f,
            instancePriority: 10);

        // 使用預設優先順序（0）的簡化多載
        entityComponent.AddEntityGroup("Bullet", 30f);
    }
}
```

來源：[EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L246-L290)

### 3. 在 Inspector 中設定優先順序

`EntityComponent` 的 `EntityGroup` 序列化類別公開了 `InstancePriority` 欄位，可直接在 Inspector 中調整。在執行階段，該優先順序會連同 `AddEntityGroup` 一起註冊到底層物件池。

```csharp
[SerializeField] private int m_InstancePriority = 0; // 預設為 0

public int InstancePriority
{
    get { return m_InstancePriority; }
}
```

來源：[EntityComponent.EntityGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.EntityGroup.cs#L41-L77)

## 關鍵 API 快速參考

| API | 位置 | 說明 |
|------|------|------|
| `EntityComponent.SetEntityInstanceLocked(Entity, bool)` | `EntityComponent.cs` | 鎖定/解鎖指定的實體實例 |
| `EntityComponent.AddEntityGroup(string, float, int, float, int)` | `EntityComponent.cs` | 建立帶有優先順序的實體群組 |
| `IEntityGroup.SetEntityInstanceLocked(object, bool)` | `IEntityGroup.cs` | 實體群組層級的鎖定介面 |
| `EntityGroup.InstancePriority` | `EntityComponent.EntityGroup.cs` | Inspector 中公開的優先順序欄位 |
| `DefaultPriority` 常數 | `EntityComponent.cs` | 預設優先順序，值為 `0` |

## 常見變體

- 簡化版 `AddEntityGroup(string, float)`：僅指定群組名稱與自動釋放間隔；容量、到期時間與優先順序皆使用預設值。
- 序列化設定：在 `EntityComponent` 的 Inspector 中新增實體群組後，`m_InstancePriority` 會作為參數傳入 `AddEntityGroup`，無需任何程式碼介入。
- 透過 `IEntityGroup` 直接呼叫：在自訂實體群組輔助器或管理器擴充中，您也可以先取得 `IEntityGroup` 再呼叫 `SetEntityInstanceLocked`。

## 常見錯誤

- 鎖定 `null` 實體：`SetEntityInstanceLocked` 會存取 `entity.gameObject`，因此傳入 `null` 會拋出 Null 參考例外；請先透過 `GetEntity(entityId)` 取得有效的實體。
- 認為鎖定的實體不會被 `HideEntity` 回收：鎖定只影響物件池的自動回收；`HideEntity` 仍會立即將實體歸還至物件池，請依據業務邏輯搭配使用。
- 認為優先順序數值越大「越好」：這裡的「高優先順序」＝較晚被回收，而非更高的品質；設定前請先確認它符合「關鍵資源最後回收」的預期。
- 忘記解鎖：鎖定的實體實例會無限期常駐於物件池中；大量鎖定卻從未解鎖將耗盡物件池容量，並影響後續的 `ShowEntity` 呼叫。

## 背景說明（選讀）

鎖定最終會被轉發到底層的 `IObjectPool<EntityInstanceObject>.SetLocked`，當 `AutoReleaseInterval` 觸發時，物件池會跳過被鎖定的物件；優先順序會在建構 `EntityGroup` 時傳入 `CreateSingleSpawnObjectPool`，作為物件池本身在多個群組之間選擇回收目標的依據。
