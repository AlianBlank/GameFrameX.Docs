# 建置巨集與條件編譯符號說明

本頁面彙整 GameFrameX 框架在原始碼、Assembly Definition 與 Unity Player Settings 中實際使用到的**建置巨集 / 條件編譯符號**，並說明每個符號的生效平台、定義位置以及如何在專案中啟用或偵測它們。

> 凡是帶有 `UNITY_` 前綴的符號由 Unity 引擎自動注入；框架自訂符號(如 `ENABLE_GAME_FRAME_X_HYBRID_CLR`)透過 `asmdef` 的 `versionDefines` 自動注入。

## 符號速查表

| 符號 | 作用域 | 定義來源 | 用途 |
|------|--------|----------|------|
| `UNITY_EDITOR` | Editor 組件 | Unity 自動注入 | 僅在編輯器生效的程式碼區塊 |
| `UNITY_ANDROID` | Android 平台 | Unity 自動注入 | Android 平台特化邏輯 |
| `UNITY_IOS` | iOS 平台 | Unity 自動注入 | iOS 平台特化邏輯 |
| `UNITY_STANDALONE` | 獨立平台(Win/Mac/Linux) | Unity 自動注入 | 桌面端特化邏輯 |
| `UNITY_2018_1_OR_NEWER` | 版本偵測 | Unity 自動注入 | 版本相容分支 |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` | 啟用 HybridCLR 熱更的組件 | `versionDefines`(偵測 `com.code-philosophy.hybridclr` 套件) | 控制與 HybridCLR 整合相關的程式碼路徑 |

> 完整 Unity 平台/版本巨集清單請參閱 Unity 官方文件(執行階段符號不會出現在原始碼中，但會被編譯器自動識別)。

## 框架自訂符號：ENABLE_GAME_FRAME_X_HYBRID_CLR

該符號是框架層面目前**唯一**透過 `asmdef` 的 `versionDefines` 注入的自訂巨集。當專案中安裝 `com.code-philosophy.hybridclr` 套件時，Unity 會自動向 `GameFrameX.Startup.Application` 組件注入該巨集，進而啟用與 HybridCLR 熱更相關的程式碼路徑。

```json
{
    "name": "GameFrameX.Startup.Application",
    "references": [
        "GameFrameX.Runtime",
        "HybridCLR.Runtime",
        "HybridCLRData"
    ],
    "versionDefines": [
        {
            "name": "com.code-philosophy.hybridclr",
            "expression": "",
            "define": "ENABLE_GAME_FRAME_X_HYBRID_CLR"
        }
    ]
}
```

Source: [Unity.Startup.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Unity.Startup.asmdef#L33-L39)

### 使用範例

```csharp
using UnityEngine;

namespace GameFrameX
{
    public static class HotUpdateGate
    {
        public static bool IsHotUpdateSupported
        {
            get
            {
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
                return true;
#else
                return false;
#endif
            }
        }
    }
}
```

### 驗證巨集是否生效

在 Unity 中執行選單 **Window → General → Test Runner**,或在任何指令碼中透過反映讀取：

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
    Debug.Log("HybridCLR 已啟用,熱更程式碼會進入熱更組件。");
#else
    Debug.LogWarning("未啟用 HybridCLR,Startup 會以 AOT 方式執行。");
#endif
```

若輸出 *HybridCLR 已啟用* 字樣，表示 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 已成功注入。

## 平台巨集的實際用法

### Android 平台特化設定

`ProjectSettingEditor.cs` 在 Android 平台上關閉安全區域限制，並寫入團隊 ID 佔位符；非 Android 平台時該分支會被編譯器剔除。

```csharp
public override void OnInspectorGUI()
{
    base.OnInspectorGUI();
    PlayerSettings.assemblyVersionValidation = false;
#if UNITY_ANDROID
    PlayerSettings.Android.renderOutsideSafeArea = true;
#endif
#if UNITY_IOS
    PlayerSettings.iOS.appleDeveloperTeamID = "XXXXXX";
#endif
}
```

Source: [ProjectSettingEditor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/ProjectSettingEditor/ProjectSettingEditor.cs#L28-L52)

### 版本相容分支

`AutoCopySymbolsPostprocessor.cs` 使用 `UNITY_2018_1_OR_NEWER` 遮蔽 32 位元 x86 架構處理邏輯(Unity 2018.1 起不再支援 Android x86 建置)。

```csharp
#if UNITY_2018_1_OR_NEWER

#else
    if ((PlayerSettings.Android.targetArchitectures & AndroidArchitecture.X86) > 0)
    {
        var dir = CopySymbols(symbolsDir, abi_x86);
        GenerateAllSymbols(dir);
    }
#endif
```

Source: [AutoCopySymbolsPostprocessor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/AutoCopySymbolsPostprocessor.cs#L46-L54)

## 平台層級組件隔離

`includePlatforms` / `excludePlatforms` 控制組件是否參與對應平台建置，**不需要**額外巨集。

| 組件 | includePlatforms | 效果 |
|--------|------------------|------|
| `Unity.Editor` | `["Editor"]` | 僅編輯器建置，玩家包不會包含 |
| `Unity.Startup` / `Unity.HotFix` / `HybridCLRData` | `[]`(全部) | 所有平台建置都會參與 |

Source: [Unity.Editor.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/Unity.Editor.asmdef#L11-L13)

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| 在 Android 裝置上看到 x86 lib 檔案殘留 | 啟用了 `UNITY_2018_1_OR_NEWER` 之前過時的路徑 | 升級 Unity 至 2018.1+,讓巨集正確剔除 x86 處理 |
| HotFix 組件未參與建置 | `UNITY_HOTFIX` 等老舊巨集被誤用 | 使用現代 HybridCLR 注入的 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 或 `includePlatforms` 設定 |
| 玩家包仍包含 Editor 工具程式碼 | `Unity.Editor` 組件的 `includePlatforms` 未設定為 `Editor` | 在 `.asmdef` 中明確宣告 `"includePlatforms": ["Editor"]` |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` 始終未定義 | HybridCLR 套件未安裝或套件名稱拼錯 | 在 Package Manager 確認 `com.code-philosophy.hybridclr` 已安裝，並核對 `asmdef` 中 `versionDefines.name` 拼字一致 |

## 新增自訂建置巨集

1. 開啟對應的 `.asmdef`,在根層級加入 `defineConstraints` 或 `versionDefines`(用於受套件管理控制)。
2. 若需全域生效(不受套件管理控制)，使用 **Edit → Project Settings → Player → Other Settings → Scripting Define Symbols**。
3. 在 C# 程式碼中使用標準 `#if SYMBOL_NAME ... #endif` 語法參考；Unity 在建置時會自動依目前目標平台剔除不相符的分支。
