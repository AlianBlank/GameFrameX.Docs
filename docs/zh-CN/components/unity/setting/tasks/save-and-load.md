# 保存与加载配置

使用 GameFrameX 设置组件把游戏配置（玩家偏好、关卡参数等）写入持久化后端，并在需要时读取回来。本页给出在 Unity 工程内完成保存与加载的最小路径。

## 前置条件

- 已将 `com.gameframex.unity.setting` 包导入 Unity 工程。
- 场景里已挂载 `GameFrameX/Setting` 组件（`SettingComponent`），它会在 `Start` 时自动调用 `Load()`，并通过 `m_SettingHelperTypeName` 选择默认的 `PlayerPrefsSettingHelper`。

## 操作步骤

1. **确认默认 Helper 类型**。`SettingComponent` 默认使用 `PlayerPrefsSettingHelper`，无需改动即可在 PlayerPrefs 中读写。如果切换到小游戏平台，可在 Inspector 中把 `Setting Helper Type Name` 改为对应的 `AlipayMiniGameSettingStorage` / `DouYinMiniGameSettingStorage` / `KuaiShouMiniGameSettingStorage` / `WeChatMiniGameSettingStorage`。

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L100)

2. **写入配置**。通过 `SettingComponent` 的 `SetXxx` 系列方法把值写入内存：

   ```csharp
   using GameFrameX.Setting.Runtime;

   var setting = GameFrameXEntry.GetComponent<SettingComponent>();
   setting.SetBool("MusicOn", true);
   setting.SetInt("Level", 3);
   setting.SetString("PlayerName", "Alice");
   setting.SetFloat("Volume", 0.8f);
   ```

   写入方法仅修改内存，不会立刻落盘。

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L225-L228)

3. **调用 Save() 落盘**。在合适的时机（例如退出游戏、切场景前）执行：

   ```csharp
   setting.Save();
   ```

   `PlayerPrefsSettingHelper.Save()` 会委托给当前平台的 `ISettingStorageBackend.Save()` 实际写入。返回值表示保存是否成功，可在调试时打日志确认。

   Source: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L99-L102)

4. **读取配置**。`SettingComponent.Start()` 已经调用了 `Load()`，下一次进入场景即可用 `GetXxx` 读取：

   ```csharp
   bool musicOn = setting.GetBool("MusicOn", true);     // 带默认值
   int level   = setting.GetInt("Level", 1);
   string name = setting.GetString("PlayerName", "");
   float vol   = setting.GetFloat("Volume", 1.0f);
   ```

   每个 `GetXxx` 都提供带默认值的重载，键不存在时返回默认值。

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L102-L108)

5. **管理键**。查询、删除单个或全部配置项：

   ```csharp
   if (setting.HasSetting("Level")) { /* ... */ }
   setting.RemoveSetting("Level");
   setting.RemoveAllSettings();
   ```

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L157-L185)

## 常见变体

- **跨平台写入**。把 `m_SettingHelperTypeName` 改为小游戏平台对应的 `*MiniGameSettingStorage`，读写逻辑无需修改。
- **自定义后端**。实现 `ISettingStorageBackend`，通过 `PlayerPrefsSettingHelper.SetStorageBackendForTests` 注入（也可在自定义 `SettingHelperBase` 子类中使用 `SettingStorageBackendFactory.Create()`）。
- **批量更新**。在一次业务事件末尾集中调用一次 `Save()`，避免每改一项就写一次磁盘。

## 常见错误

- **忘了调 Save()**：`SetXxx` 只改内存，不调 `Save()` 数据不会持久化，重启后丢失。
- **启动期就读取**：不要在 `Awake` 里读取，`SettingComponent` 在 `Start` 才执行 `Load()`。读取逻辑应放在 `Start` 或之后。
- **依赖枚举所有键**：PlayerPrefs 不支持 `GetAllSettingNames()`，调用会得到 `null` 并打印 `GetAllSettingNames is not supported.` 警告。改用业务层自己维护已知键列表。

## 背景（可选）

`SettingComponent` 是 MonoBehaviour 入口，`SettingManager` 是无依赖的模块核心，`SettingHelperBase` 把读写分发到具体后端。`PlayerPrefsSettingHelper` 默认通过 `SettingStorageBackendFactory` 选用对应平台的后端实现，从而在同一套 API 下兼容 PlayerPrefs 和小游戏平台存储。
