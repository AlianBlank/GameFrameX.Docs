# IL2CPP 建置後 UI 功能異常時的解決方法

以 IL2CPP 建置後，Unity 的受管理程式碼剝離(Managed Code Stripping)可能會將 FairyGUI 中僅以反射/字串方式參考的型別裁切掉，導致 UI 無法顯示、元件遺失或按鈕沒有反應，也可能在 logcat/Xcode 主控台中出現 `NullReferenceException`、`TypeLoadException` 等例外。本頁面將引導您進行診斷與解決：確認 `link.xml` 是否已套用、將 `FairyGUICroppingHelper` 掛載至起始場景、調整剝離等級。

## 快速診斷

| 症狀 | 原因 | 解決 |
|------|------|------|
| 建置後 UI 未顯示 / 部分元件為空 | 受管理程式碼剝離移除了未以靜態方式參考的型別 | 確認 `Runtime/link.xml` 已包含於套件中，參閱[解決步驟 1](#步驟-1確認-linkxml-已包含在套件中) |
| 主控台中出現與 `FairyGUI.*` 型別相關的 `NullReferenceException` / `TypeLoadException` | 以反射方式產生的型別(例如 UI 套件元件)被裁切 | 掛載防止剝離的指令碼 `FairyGUICroppingHelper`,參閱[解決步驟 2](#步驟-2將-fairyguicroppinghelper-掛載到起始場景) |
| Editor 中正常，實機上異常；資源套件非同步載入時沒有回呼 | `AsyncCreationHelper` 等回呼型別被裁切 | 同上，`FairyGUICroppingHelper.Start()` 會明確參考 `AsyncCreationHelper` |
| 剝離等級較高時(Medium/High)重現問題 | IL2CPP 預設會移除僅以反射方式使用的組件 | 調低 Managed Stripping Level 或依賴 `link.xml`,參閱[解決步驟 3](#步驟-3調整-managed-stripping-level) |

## 解決步驟

### 步驟 1:確認 link.xml 已包含在套件中

本套件已包含 `Runtime/link.xml`,並將整個 `FairyGUI.Runtime` 組件設定為 `preserve="all"`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="FairyGUI.Runtime" preserve="all"/>
</linker>
```

來源:[Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/link.xml#L1-L4)

確認事項：

1. 確認 `Runtime/link.xml` 是否存在於專案中(透過 Package Manager 安裝時會隨套件一併包含)。
2. 若是直接將 FairyGUI 原始碼複製到專案中，則須確認 `link.xml` 的 `fullname` 與實際組件名稱一致(請參考組件的 `.asmdef` 名稱)。名稱不一致時，此檔案將不會生效。
3. 在建置日誌中搜尋 `link.xml`,確認建置時已套用此 linker 描述。

### 步驟 2:將 FairyGUICroppingHelper 掛載到起始場景

套件提供了防止剝離的指令碼 `FairyGUICroppingHelper`,會在 `Start()` 中明確參考所有 FairyGUI 型別，讓剝離器無法將其移除：

```csharp
/// <summary>
/// 防止程式碼執行時發生剝離錯誤。請將此指令碼加入起始場景。不會對邏輯造成任何影響
/// </summary>
[Preserve]
public class FairyGUICroppingHelper : MonoBehaviour
{
    [Preserve]
    void Start()
    {
        _ = typeof(FairyGUI.AlignType);
        _ = typeof(FairyGUI.Anymous_T);
        _ = typeof(FairyGUI.AsyncCreationHelper);
        // ...以下依序參考其餘所有 FairyGUI 型別
```

來源:[Runtime/FairyGUICroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/FairyGUICroppingHelper.cs#L6-L17)

操作方式：在起始(第一個)場景中新增一個空的 GameObject,並透過 `Add Component` 加入 `FairyGUICroppingHelper` 即可。此指令碼不會對執行邏輯造成任何影響，僅用於保留型別。

### 步驟 3:調整 Managed Stripping Level

在 **Project Settings → Player → Other Settings → Optimization** 中：

| 建置目標 | 設定項目 | 建議值 |
|------------|--------|--------|
| Android | Managed Stripping Level | Low 或 Disabled(問題難以排解時，先設為 Disabled 以釐清原因) |
| iOS | Managed Stripping Level | Low 或 Disabled |

調低等級後重新建置。若 `Disabled` 時正常，而提高等級後就異常，表示仍有部分型別需要依靠 `link.xml` / `[Preserve]` 來保留。與其長期關閉剝離，請優先完成步驟 1 與 2。

## 驗證

1. 以 IL2CPP 重新建置並安裝至實機。
2. 執行先前異常的畫面：確認 UI 能正常顯示，且按鈕/非同步載入有收到回呼。
3. 確認 logcat(Android)或 Xcode 主控台(iOS)中不再出現與 `FairyGUI.*` 相關的 `NullReferenceException` / `TypeLoadException`。
4. 您可以在建置輸出的 `IL2CPP` 產生目錄(例如 `Temp/StagingArea/Data/Il2CppOutputDirectory`)中搜尋先前遺失的型別名稱，確認其未被裁切。
