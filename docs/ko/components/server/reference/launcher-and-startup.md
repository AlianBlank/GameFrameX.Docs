# 런처 및 시작 항목 참조(Program.cs / AppStartUpGame)

이 페이지는 게임 서버의 시작 진입점과 기본 시작 항목 설정을 조회하기 위한 문서입니다. `Program.cs`는 프로세스 진입점과 로그 정책을 정의하며, `AppStartUpGame`은 게임 서버 시작 항목으로, Actor 제한, 데이터베이스, 컴포넌트, 핫업데이트 모듈을 순서대로 초기화한 후 메인 루프에 진입합니다.

## 시작 진입점(Program.cs)

시작 진입점은 `GameFrameX.Launcher` 어셈블리에 위치하며, `Main` 내부에서는 세 가지 작업만 수행합니다: 컴파일 모드에 따라 로그 옵션 설정, 프레임워크 진입점 `GameApp.Entry` 호출, 콜백을 전달하여 캐시 및 프로토콜 초기화 완료.

```csharp
internal static class Program
{
    private static async Task Main(string[] args)
    {
#if DEBUG
        LogOptions.Default.IsConsole = true;
#endif
        await GameApp.Entry(args, () =>
        {
            CacheStateTypeManager.Init();
            MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
        }, LogAction);
    }

    private static void LogAction(LogOptions options)
    {
#if DEBUG
        options.IsConsole = true;
#else
        options.IsConsole = false;
#endif
    }
}
```

| 항목 | 값 / 동작 | 설명 |
|------|-------------|------|

| 로그 콜백 | `LogAction(LogOptions)` | 컴파일 모드에 따라 `IsConsole`을 다시 덮어씀 |

## 시작 항목(AppStartUpGame)

`AppStartUpGame`은 특성 `[StartUpTag(GameServerConst.Game.Name)]`으로 `Game` 타입 서버로 표시되며, `AppStartUpBase`를 상속합니다. `StartAsync`는 시작의 메인 흐름이고, `Init`은 필요에 따라 기본 `AppSetting`을 구성합니다.

```csharp
[StartUpTag(GameServerConst.Game.Name)]
internal sealed class AppStartUpGame : AppStartUpBase
{
    public override async Task StartAsync() { /* 아래 표의 단계 순서 참조 */ }

    protected override void Init()
    {
        if (Setting == null)
        {
            Setting = new AppSetting { /* 기본값은 아래 표 참조 */ };
        }
        base.Init();
    }
}
```

출처: [GameFrameX.Launcher/StartUp/AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L41-L118)

### StartAsync 시작 순서

| 단계 | 동작 | 핵심 호출 |
|------|------|----------|
| 1 | `hotfix` 디렉터리 준비 | `Directory.Exists` / `Directory.CreateDirectory` |
| 2 | Actor 제한 초기화 | `ActorLimit.Init(ActorLimit.RuleType.None)` |
| 3 | 데이터베이스 서비스 시작 | `GameDb.Init<MongoDbService>(...)`, 실패 시 `InvalidOperationException("数据库服务启动失败")` 예외 발생 |
| 4 | 컴포넌트 등록 | `ComponentRegister.Init(typeof(AppsHandler).Assembly)` |
| 5 | 핫업데이트 모듈 로드 | `HotfixManager.LoadHotfixModule(Setting)` |
| 6 | 런타임 시작 완료 표시 | `GameAppRuntime.MarkStarted(...)` |
| 7 | 종료 신호 대기 | `await AppExitToken` |
| 8 | 핫업데이트 중지 | `await HotfixManager.Stop(exitMessage)` |

예외 경로: 어느 단계에서든 예외가 발생하면 `catch (Exception e)`에서 캡처되며, 로그를 기록한 후 8단계로 진입하여 핫업데이트를 중지한 다음 프로세스가 종료됩니다.

### 기본 AppSetting 필드

`Init()`은 `Setting == null`일 때 기본 `AppSetting`을 구성하며, 필드의 의미와 기본값은 다음과 같습니다:

| 필드 | 타입/값 | 기본값 | 의미 |
|------|-----------|--------|------|
| `ServerId` | `int` | `GameServerConst.Game.Id` | 서버 고유 ID |
| `ServerType` | `string` | `GameServerConst.Game.Name` | 서버 타입 이름(`[StartUpTag]`에 대응) |
| `IsEnableTcp` | `bool` | `true` | TCP 활성화 |
| `InnerPort` | `int` | `29100` | 내부 TCP 포트 |
| `MetricsPort` | `int` | `29090` | 모니터링 포트 |
| `IsEnableHttp` | `bool` | `true` | HTTP 활성화 |
| `HttpPort` | `int` | `28080` | HTTP 포트 |
| `IsEnableWebSocket` | `bool` | `true` | WebSocket 활성화 |
| `WsPort` | `int` | `29110` | WebSocket 포트 |
| `HttpIsDevelopment` | `bool` | `true` | HTTP 개발 모드 |
| `MinModuleId` | `int` | `10` | 모듈 메시지 ID 하한 |
| `MaxModuleId` | `int` | `9999` | 모듈 메시지 ID 상한 |
| `TagName` | `string` | `"GameFrameX"` | 로그/트레이싱 태그 |
| `DataBaseUrl` | `string` | 리포지토리 내장 MongoDB 연결 문자열 | Mongo 연결 URL |
| `DataBaseName` | `string` | `"gameframex"` | Mongo 데이터베이스 이름 |

## 일반적인 오류

| 현상 | 발생 조건 | 확인 방향 |
|------|----------|----------|
| 시작 시 `InvalidOperationException: 数据库服务启动失败` 발생 | `GameDb.Init<MongoDbService>`가 `false` 반환 | `DataBaseUrl` / `DataBaseName`의 연결 가능 여부 및 Mongo 네트워크 도달 가능성 확인 |
| Release 패키지 콘솔에서 로그가 보이지 않음 | `DEBUG`가 아닌 컴파일 | `Program.LogAction`이 `IsConsole`을 강제로 `false`로 설정함, 이는 의도된 동작 |
| 핫업데이트 디렉터리 누락 | `hotfix`가 존재하지 않음 | 시작 흐름에서 자동으로 `CreateDirectory`를 수행하므로 수동으로 만들 필요 없음; 권한이 부족하면 예외 발생 |
| `AppSetting`이 외부에서 덮어씌워짐 | 호출자가 `Init()` 전에 이미 값을 할당함 | `Init()`은 `Setting == null`일 때만 기본값을 채우므로, 먼저 주입하고 시작하면 전달한 값이 우선 적용됨 |
