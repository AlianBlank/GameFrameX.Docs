# 如何配置 URL 主备 failover 策略

使用 `UrlFailoverRunner.ExecuteAsync` 即可让一组 URL 按顺序进行主备切换,并对每个 URL 做最多 N 次重试。本页给出可直接复制运行的最小用法、参数含义以及常见踩坑点。

## 前置条件

- 项目已安装 `com.gameframex.unity.startup` 包,并引用了 `GameFrameX.Startup.Runtime` 命名空间。
- 业务侧实现一个 `Func<string, UniTask<UrlAttemptResult>>` 委托,负责对单个 URL 发起实际请求(GET/POST 等),并根据响应返回 `UrlAttemptResult.Succeed()` 或 `UrlAttemptResult.Fail(errorMessage)`。
- 已引入 `Cysharp.Threading.Tasks` 与 `UniTask` 异步机制(`using Cysharp.Threading.Tasks;`)。

## 操作步骤

1. **准备 URL 列表**。把候选 URL 按"主—备—备…"的顺序放进 `IReadOnlyList<string>`,运行时按数组下标依次尝试。

2. **实现单 URL 尝试委托**。对每个 URL 发起一次请求,根据 HTTP 状态码或业务码返回成功或失败结果。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;
   using UnityEngine.Networking;

   UniTask<UrlAttemptResult> TryFetchAsync(string url)
   {
       return UniTask.RunOnThreadPool(async () =>
       {
           using var req = UnityWebRequest.Get(url);
           await req.SendWebRequest();
           if (req.result == UnityWebRequest.Result.Success)
           {
               return UrlAttemptResult.Succeed();
           }
           return UrlAttemptResult.Fail(req.error ?? "unknown error");
       });
   }
   ```

   Source: [UrlAttemptResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlAttemptResult.cs#L6-L27)

3. **调用 `UrlFailoverRunner.ExecuteAsync`**。传入 URL 列表、每个 URL 的最大尝试次数、重试间隔毫秒数与上一步的委托。

   ```csharp
   using System.Collections.Generic;
   using System.Threading;
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   public async UniTask<UrlFailoverResult> RunAsync(CancellationToken ct = default)
   {
       var urls = new[] { "https://api-primary.example.com", "https://api-backup.example.com" };

       return await UrlFailoverRunner.ExecuteAsync(
           urls,
           maxAttemptsPerUrl: 3,
           retryDelayMs: 500,
           attempt: TryFetchAsync,
           onProgress: (url, attempt, total) =>
               UnityEngine.Debug.Log($"try {attempt}/{total} -> {url}"),
           cancellationToken: ct);
   }
   ```

   Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L14-L43)

4. **处理返回的 `UrlFailoverResult`**。成功后使用业务数据;失败时根据 `FailedUrl` 与 `ErrorMessage` 决定是否走降级逻辑或上报埋点。

   ```csharp
   var result = await RunAsync(this.GetCancellationTokenOnDestroy());
   if (!result.Success)
   {
       UnityEngine.Debug.LogError($"all URLs failed. last={result.FailedUrl}, err={result.ErrorMessage}");
       return;
   }
   ```

   Source: [UrlFailoverResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverResult.cs#L6-L30)

## 常见变体

- **同步写法(单测中常见)**。直接把委托写成立即返回 `UniTask.FromResult(...)`,无需等待。

  ```csharp
  var result = await UrlFailoverRunner.ExecuteAsync(
      new[] { "http://a", "http://b" },
      maxAttemptsPerUrl: 2,
      retryDelayMs: 0,
      attempt: url => UniTask.FromResult(
          url == "http://b" ? UrlAttemptResult.Succeed() : UrlAttemptResult.Fail("down")));
  ```

  Source: [UrlFailoverRunnerTests.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Tests/Runtime/UrlFailoverRunnerTests.cs#L63-L85)

- **不重试,只切主备**。把 `maxAttemptsPerUrl` 设为 `1`、`retryDelayMs` 设为 `0`,即"一次失败立刻切下一个 URL",无延迟。

  ```csharp
  await UrlFailoverRunner.ExecuteAsync(urls, maxAttemptsPerUrl: 1, retryDelayMs: 0, attempt: TryFetchAsync);
  ```

  Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L68-L71)

- **带进度回调**。`onProgress(url, attempt, total)` 在每次尝试前触发,`attempt` 从 `1` 开始计数,便于驱动 UI 进度条。

  Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L57-L57)

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 同步抛 `ArgumentNullException`,参数名 `urls` | URL 列表传了 `null` | 至少传 `new string[0]` 以外的列表;空数组会抛 `ArgumentException` |
| 同步抛 `ArgumentException`,提示 "URL list must contain at least one URL." | 传入空数组 `new string[0]` | 至少包含 1 个 URL |
| 同步抛 `ArgumentException`,提示 "Max attempts per URL must be greater than zero." | `maxAttemptsPerUrl < 1` | 把每 URL 尝试次数设置为 ≥ 1 |
| 同步抛 `ArgumentException`,提示 "Retry delay must be zero or greater." | `retryDelayMs < 0` | 设置为 `0` 或正整数 |
| 同步抛 `ArgumentNullException`,参数名 `attempt` | 尝试委托传了 `null` | 给 `attempt` 传入一个有效的 `Func<string, UniTask<UrlAttemptResult>>` |
| 所有 URL 都失败时业务方收到 `result.Success == false`,但 `FailedUrl` 为空字符串 | 未在任何 URL 上调用过失败路径(几乎不会发生),或所有失败都被吞掉 | 检查委托内是否始终返回了 `UrlAttemptResult.Fail(...)` |

校验这些参数约束的实现位于 `UrlFailoverRunner.ExecuteAsync` 的入口处。

## 背景(可选)

`UrlFailoverRunner` 是一个静态工具类,它按"URL 顺序 × 每 URL 尝试次数"两层循环执行:外层遍历 `urls`,内层对单个 URL 重复调用传入的 `attempt` 委托,直到成功或耗尽 `maxAttemptsPerUrl`。一旦某个 URL 成功,立即返回 `UrlFailoverResult.Succeed()`,不再尝试后续 URL;只有当所有 URL 的所有重试都失败时,才返回包含最后一次失败 URL 与错误信息的 `UrlFailoverResult.Fail(...)`。`retryDelayMs > 0` 时,会在同一 URL 的两次尝试之间用 `UniTask.Delay` 等待;`maxAttemptsPerUrl == 1` 则不等待也不重试。
