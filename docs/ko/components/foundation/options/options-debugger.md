# 애플리케이션 시작 시 디버그 정보를 출력하는 방법

`OptionsBuilder.CreateWithDebug<T>`를 사용하거나 직접 `OptionsDebugger.PrintParsedOptions`를 호출하면, 애플리케이션 시작 시 이미 파싱된 커맨드 라인 매개변수, 값, 타입, 기본값, 필수 여부 등의 정보를 테이블 형식으로 콘솔에 출력하여 시작 단계의 구성 문제를 쉽게 디버깅할 수 있습니다.

## 사전 조건

- NuGet을 통해 `GameFrameX.Foundation.Options`를 참조해야 합니다.
- `class` 구성 타입이 정의되어 있어야 하며, 속성에 `OptionAttribute`를 표시해야 합니다(`OptionAttribute` 사용법 참고).

## 작업 단계

1. 구성 타입 `AppOptions`를 정의하고, 각 속성에 `OptionAttribute`를 추가합니다:

```csharp
using GameFrameX.Foundation.Options.Attributes;

public sealed class AppOptions
{
    [Option(LongName = "host", Description = "服务监听地址", Required = true)]
    public string Host { get; set; } = "127.0.0.1";

    [Option(LongName = "port", Description = "服务端口", DefaultValue = 8080)]
    public int Port { get; set; }

    [Option(LongName = "token", Sensitive = true, Description = "访问令牌")]
    public string Token { get; set; }
}
```

Source: [AppOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/OptionsDebuggerSensitiveOutputTests.cs#L1-L40)

2. `Main`/`Program`에서 `CreateWithDebug`를 사용하여 한 줄로 구성 및 출력합니다:

```csharp
using GameFrameX.Foundation.Options;

var options = OptionsBuilder.CreateWithDebug<AppOptions>(
    args: args,
    skipValidation: false);

Console.WriteLine($"使用 Host = {options.Host}");
```

`CreateWithDebug` 내부에서 이미 `OptionsDebugger.PrintParsedOptions(result)`를 호출하여 파싱 결과를 테이블로 출력합니다.

Source: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L175-L184)

3. `OptionsBuilder<T>.Build()` 또는 `OptionsProvider.Get<T>()`을 사용하는 경우, 이미 성공 경로에서 자동으로 `PrintParsedOptions`를 호출하므로 추가로 출력할 필요가 없습니다.

Source: [OptionsProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsProvider.cs#L185-L218)

4. 출력 시기를 직접 제어하려면 직접 호출합니다:

```csharp
OptionsDebugger.PrintParsedOptions(options);
```

출력 내용에는 헤더 `Command-line parameter and parsed configuration object information`와 6개 열의 테이블이 포함됩니다: 옵션, 값, 필수 여부, 타입, 설명, 기본값. 민감 필드(`Sensitive = true`)의 값은 마스킹됩니다.

Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L70-L91)
Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L161-L172)

## 일반적인 변형

- **수동으로 예외를 잡고 출력**: `TryCreate`가 실패하면 `result`가 기본값 객체로 폴백되므로, catch 후 `PrintParsedOptions`를 다시 호출하여 오류 컨텍스트를 출력할 수 있습니다.
- **이미 생성된 객체만 출력**: 시작 단계가 아닌 디버깅 시, 임의의 위치에서 `TOptions` 인스턴스를 가져온 후 직접 `OptionsDebugger.PrintParsedOptions(options)`를 호출하면 됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|----------|
| 콘솔 열이 어긋나거나 와이드 문자가 깨짐 | 콘솔 너비가 `DefaultConsoleWidth`(120)보다 작고, 열 너비가 압축됨 | 시작 시 콘솔 너비를 크게 조정하거나, 와이드 문자를 지원하는 터미널에서 실행 |
| 테이블의 특정 열이 잘림 | 설명 텍스트가 너무 길어 `MaxDisplayElements` 제한이 트리거됨 | `Description` 텍스트를 줄이거나 여러 속성으로 분할 |
| 민감 필드가 평문으로 표시됨 | `OptionAttribute.Sensitive`가 활성화되지 않음 | 키를 포함하는 속성에 명시적으로 `Sensitive = true` 추가 |
| 테이블 없이 출력됨 | 타입이 `class`가 아니거나 공개 인스턴스 속성이 없음 | `where T : class, new()` 구성 타입 사용 |

## 배경 지식 (선택)

`OptionsDebugger`는 리플렉션을 사용하여 `T`의 공개 속성을 열거하고, 테이블에서 문자 표시 너비(중국어는 더블 너비)로 콘솔 너비에 적응하며, 민감 필드를 마스킹합니다. 시작 단계 출력은 `CreateWithDebug`와 `OptionsProvider` 내부에서 통합 호출되어, 각 곳에서 반복적인 보일러플레이트 코드를 피합니다.
