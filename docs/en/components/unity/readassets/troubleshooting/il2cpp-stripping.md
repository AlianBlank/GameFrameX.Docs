# What to Do When APIs Are Stripped After IL2CPP Build

The IL2CPP backend strips types and members that are "not directly referenced by code" through the managed bytecode linker (Unity Linker / IL2CPP stripping). If `MissingMethodException`, `NullReferenceException`, or "it works in the Editor but not after build" occurs when calling this library's API after an IL2CPP build, it is caused by stripping. This page provides quick diagnosis and fix methods.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Editor / Mono build works fine, but after IL2CPP build it reports `MissingMethodException: void BlankReadAssets::xxx` | The linker stripped the entry point that was invoked via reflection / dynamic calls | Confirm that the dependency package's `Runtime/link.xml` has been included; or add `[Preserve]` to your custom invocation point |
| Calling APIs like `BlankReadAssets.OpenRead` returns `null` or throws a null reference, but the linker doesn't report an error | The namespace / internal class was stripped, causing the implementation branch to be reduced to an empty shell | Re-confirm that `link.xml` covers the `GameFrameX.ReadAssets.Runtime` and `GameFrameX.ReadAssets.Runtime.ZipArchive` namespaces |
| Everything works on all platforms after build, but Android IL2CPP StreamingAssets reads return empty | `ApkImpl` / `LooseFilesImpl` implementation classes were stripped, and the platform branch falls back to a no-implementation path | Check whether Managed Stripping is enabled; if necessary, disable Strip Engine Code in Player Settings or add a link.xml |

## Fix Steps

### 1. Confirm that the `link.xml` in the dependency package exists and is shipped with the build

This repository explicitly declares the assemblies and namespaces to preserve in `Runtime/link.xml`, and Unity Linker picks it up automatically at packaging time:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="BlankReadAssets.Runtime" preserve="all">
        <namespace fullname="GameFrameX.ReadAssets.Runtime" preserve="all"/>
        <namespace fullname="GameFrameX.ReadAssets.Runtime.ZipArchive" preserve="all"/>
    </assembly>
</linker>
```

Source: [Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/link.xml#L1-L7)

How to confirm: unzip the `.apk` / `.ipa` / build output, and check that a `link.xml` can be found alongside `*_Data/Managed` or under `Assets/`, and that its content contains `BlankReadAssets.Runtime`. UPM packages include this file through the `samples` field in `package.json` or via direct file inclusion.

### 2. Check the Strip level in Player Settings

`Project Settings → Player → Other Settings → Managed Stripping`:

| Level | Risk | Recommendation |
|------|------|------|
| Disabled | Won't be stripped, but the package size will be larger | Use for temporary verification |
| Low | Only strips obviously unused code | Usually sufficient |
| Medium / High | Reflection and dynamically loaded code may be stripped | Must be paired with `link.xml` |

If your project sets Managed Stripping to High, proceed to step 3 and add `[Preserve]` to reflection call sites.

### 3. Public APIs come with `[Preserve]`, and newly integrated code can be annotated the same way

All public APIs in this library are already annotated with `[Preserve]`. Examples:

```csharp
[Preserve]
public static string Root
{
    get
    {
        EnsureInitialized();
        return BlankReadAssetsImpl.s_root;
    }
}

[Preserve]
public static void Initialize()
{
    BlankReadAssetsImpl.Initialize(Application.dataPath, Application.streamingAssetsPath);
    s_initialized = true;
}
```

Source: [Runtime/BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L37-L68)

When your business layer calls this library via reflection (e.g. `Type.GetMethod("OpenRead")`), Unity Linker cannot see the call relationship; add `[Preserve]` to the entry point or wrapper method to preserve it:

```csharp
using UnityEngine.Scripting;

[Preserve]
public static Stream OpenAsset(string file)
{
    return BlankReadAssets.OpenRead(file);
}
```

### 4. Fallback via a custom link.xml (not recommended as the only approach)

Append a section to `Assets/link.xml` in your project to preserve namespaces you use indirectly:

```xml
<linker>
    <assembly fullname="YourGame" preserve="all"/>
</linker>
```

This is equivalent to "preserve the entire assembly"; use only as a last-resort fallback to avoid long-term reliance.

## Verification

After completing the fix, verify in the following order:

1. **Repackage locally with IL2CPP**: `File → Build Settings → Player Settings → Other Settings → Configuration → Scripting Backend = IL2CPP`, then Build And Run (or `Build`) again.
2. **Reproduce with a Release build**: The Editor's IL2CPP backend only runs the linker after packaging, so stripping issues cannot be reproduced in the Editor.
3. **Check remaining symbols in the build output**: Use `il2cppdumper` / `ilspycmd` to decompile `il2cpp.so` or the metadata in `*_Data/Managed`, and confirm that the `BlankReadAssets` type and entry points still exist.
4. **Add a logging fence**: Write a `Debug.Log` line before and after the call, and check logcat / Player.log after running to see whether the entry point was reached. If the entry point is reached but the error still occurs, the issue is not stripping, but runtime logic.

## Background (Optional)

Unity Linker strips by default based on "direct code references"; cross-assembly reflection, `Activator.CreateInstance`, and type lookup by string name will all lose their call graphs. This library's `Runtime/link.xml` explicitly preserves the `BlankReadAssets.Runtime` assembly and the `ZipArchive` namespace during packaging, forming a double safety net together with the `[Preserve]` attribute on public APIs; as long as both of these take effect, APIs will not be stripped after an IL2CPP build.
