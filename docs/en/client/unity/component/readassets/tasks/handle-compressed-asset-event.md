# Handling Android Compressed StreamingAsset Events

When files under the `StreamingAssets` directory are stored in compressed form in the APK build (especially in App Bundle), Unity cannot read them directly via file offset. This framework scans the APK's Central Directory during initialization, and triggers the `CompressedStreamingAssetFound` event when such files are discovered, allowing you to intercept and handle them at runtime.

## Prerequisites

- The event signature only genuinely exists under the `UNITY_ANDROID` or `UNITY_EDITOR` (when using `InitializeWithExternalApk`) platforms; `add`/`remove` are no-ops on other platforms.
- The project must have been initialized via `BlankReadAssets.Initialize()` or `BlankReadAssets.Root` (automatically triggered on the first access to any API).

## Steps

1. **Subscribe to the event**. The event signature is `Func<string, bool>`, which receives the full file name in the APK (e.g. `"assets/config/data.json"`) and returns `true` to indicate that you have handled it, so the framework will not emit any warning:

```csharp
using GameFrameX.ReadAssets.Runtime;

BlankReadAssets.CompressedStreamingAssetFound += fileName =>
{
    // fileName looks like "assets/xxx.bin"
    if (fileName.EndsWith(".json"))
    {
        // Your fallback logic: download from remote / copy from persistentDataPath / use built-in defaults, etc.
        Debug.Log($"Handled compressed StreamingAsset: {fileName}");
        return true;
    }
    return false;
};
```

2. **Subscribe before initialization**. The event is triggered when `ApkImpl.Initialize` → `GetStreamingAssetsInfoFromJar` scans the APK, so the subscription must occur earlier than the first read. It is recommended to place it in `RuntimeInitializeOnLoadMethod`:

```csharp
using UnityEngine;
using GameFrameX.ReadAssets.Runtime;

public static class Bootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSplashScreen)]
    private static void Init()
    {
        BlankReadAssets.CompressedStreamingAssetFound += OnCompressed;
    }

    private static bool OnCompressed(string fileName)
    {
        // Returning true means "handled", and the framework will stay silent
        return false;
    }
}
```

3. **(Optional) Validate in the Editor**. Load a real APK via `InitializeWithExternalApk` to trigger the same event in the editor, which is convenient for joint debugging:

```csharp
BlankReadAssets.InitializeWithExternalApk(@"C:\builds\game.apk");
```

The event shares the same `ApkImpl` scanning logic with `InitializeWithExternalApk` ([BlankReadAssets.ApkImpl.cs#L294-L354](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L294-L354)).

## Common Variants

- **Don't want to subscribe, just want it to be silent**. Implement the partial method `AndroidIsCompressedFileStreamingAsset`, returning `false` to let the framework directly ignore that file—skipping event dispatch and without logging:

```csharp
using GameFrameX.ReadAssets.Runtime;
using UnityEngine;

public partial class BlankReadAssets
{
    static partial void AndroidIsCompressedFileStreamingAsset(string fileName, ref bool isStreamingAsset)
    {
        // For example, suppress a certain type of resource
        if (fileName.StartsWith("assets/internal/")) isStreamingAsset = false;
    }
}
```

See the declaration of the partial method at [BlankReadAssets.ApkImpl.cs#L334](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L334).

- **App Bundle scenario**. If the project itself is an App Bundle (`*.aab`) that is uploaded to Google Play and later expanded into multiple `.apk` splits, the framework will automatically fall back to scanning `base.apk` in the same directory when `dataPath` is not `base.apk` ([BlankReadAssets.ApkImpl.cs#L43-L51](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L43-L51)); this branch still triggers the same event, and no changes to the subscription code are required.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Debug.LogAssertionFormat` keeps reporting `BlankReadAssets: file ... is where Streaming Assets are put, but is compressed.` | Nobody subscribed to the event, and no partial method filter is implemented | Subscribe to `CompressedStreamingAssetFound` or implement `AndroidIsCompressedFileStreamingAsset` |
| Writing `BlankReadAssets.CompressedStreamingAssetFound += ...` under iOS / Standalone directly causes a compilation error | The event only has a real signature under `UNITY_EDITOR || UNITY_ANDROID` | Wrap the subscription code with `#if UNITY_ANDROID || UNITY_EDITOR`; or ignore it (no-op on other platforms) |
| Subscription timing is too late, and it triggers once immediately after startup | The event fires synchronously inside `Initialize` | Subscribe in `[RuntimeInitializeOnLoadMethod(BeforeSplashScreen)]` or an even earlier bootstrap |
| Mistakenly thinking that returning `false` will throw an exception | Returning `false` only means "not handled"; the framework proceeds along the unsubscribed path (which may assert) | Return `true` once you have actually handled it |

## Background (Optional)

When packaging for Android, Unity by default compresses `assets/` files in the APK that exceed a threshold; however, `BlankReadAssets` locates the offset and uncompressed size of files inside `StreamingAssets` directly through the ZIP Central Directory. This "read raw bytes by offset" strategy fails only when the file inside the APK is compressed (`CompressedSize != UncompressedSize`). The event mechanism is designed for this: it lets the business side decide how to fall back on compressed assets ([BlankReadAssets.cs#L70-L78](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L70-L78)).
