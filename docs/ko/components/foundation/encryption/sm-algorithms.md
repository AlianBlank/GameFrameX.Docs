# 国密 SM2/SM3/SM4 사용 방법

`GameFrameX.Foundation.Encryption`은(는) 国密三大 알고리즘의 원스톱 진입점을 제공합니다: `Sm2Helper` (비대칭 암호화/복호화 / 키 쌍 생성), `Sm4Helper` (대칭 암호화/복호화, CBC / ECB 지원) 그리고 BouncyCastle 기반의 `SM3Util.Hash` (SM3 해시). 이 페이지에서는 세 가지 알고리즘의 최소 사용 가능한 코드 예제와 일반적인 함정을 제시합니다.

## 사전 조건

- 네임스페이스 추가: `GameFrameX.Foundation.Encryption`, `GameFrameX.Foundation.Encryption.Sm`.
- 프로젝트에 BouncyCastle(`Org.BouncyCastle.*`)이 참조되어 있어야 하며, 프레임워크에 기본 포함되어 있습니다.
- SM2 공개키/개인키는 16진수 문자열입니다; SM4 키는 hex가 아닌 모드에서 길이가 16바이트이고, hex 모드에서는 32개의 16진수 문자입니다.

## 작업 단계

### 1. SM3 해시

SM3은 해시 알고리즘이며 암호화 알고리즘이 아닙니다. `SM3Util.Hash`는 문자열을 받아 고정 길이(256비트)의 16진수 다이제스트를 반환하며, 내부적으로 UTF-8 인코딩을 사용하여 플랫폼 간 일관성을 보장합니다.

```csharp
using GameFrameX.Foundation.Encryption.Sm;

string hash = SM3Util.Hash("hello world");
// 동일한 입력에 대해 여러 번 호출해도 결과가 동일하므로 무결성 검증에 사용할 수 있습니다
```

Source: [SM3Util.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm/SM3Util.cs#L47-L69)

### 2. SM2 비대칭 암호화

`Sm2Helper`은(는) 문자열과 바이트 배열 두 가지 오버로드를 제공하며, 키 쌍 생성을 지원합니다;底层은 BouncyCastle을 기반으로 합니다.

```csharp
using GameFrameX.Foundation.Encryption;

// 키 쌍 생성
Sm2Helper.GenerateKeyPair(out string publicKey, out string privateKey);

// 공개키 암호화
string cipher = Sm2Helper.Encrypt(publicKey, "secret message");

// 개인키 복호화
string plain = Sm2Helper.Decrypt(privateKey, cipher);
```

바이트 배열 오버로드 (바이너리 데이터 / 네트워크 프로토콜에 적합):

```csharp
byte[] pubKeyBytes = Convert.FromHexString(publicKey);
byte[] data = System.Text.Encoding.UTF8.GetBytes("payload");
string cipherHex = Sm2Helper.Encrypt(pubKeyBytes, data);
byte[] plainBytes = Sm2Helper.Decrypt(Convert.FromHexString(privateKey), Convert.FromHexString(cipherHex));
```

Source: [Sm2Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm2Helper.cs#L62-L174)

### 3. SM4 대칭 암호화

`Sm4Helper`은(는) 기본적으로 CBC 모드를 사용합니다; 키 길이 규칙: hex가 아닌 모드에서 16바이트, hex 모드에서 32문자; `iv`를 전달하지 않으면 hex 모드에서 기본값으로 모두 0(`00000000000000000000000000000000`)이 채워집니다.

CBC 암호화 / 복호화:

```csharp
using GameFrameX.Foundation.Encryption;

string key = "0123456789abcdef";        // 16 바이트
string cipher = Sm4Helper.EncryptCbc(key, "明文文本");
string plain  = Sm4Helper.DecryptCbc(key, cipher);
```

ECB 모드 (IV 불필요):

```csharp
string cipher = Sm4Helper.EncryptEcb(key, "明文文本");
string plain  = Sm4Helper.DecryptEcb(key, cipher);
```

JavaScript 호환 모드 (프론트엔드 sm-crypto 등 라이브러리와 호환되는 padding 동작):

```csharp
string cipher = Sm4Helper.EncryptCbc(key, "明文", forJavascript: true);
string plain  = Sm4Helper.DecryptCbc(key, cipher, forJavascript: true);
```

hex 키 모드:

```csharp
string hexKey = "0123456789ABCDEF0123456789ABCDEF"; // 32개의 16진수 문자
string cipher = Sm4Helper.EncryptCbc(hexKey, "明文", hexString: true);
```

## 일반적인 변형

| 시나리오 | 권장 사항 |
|------|----------|
| 프론트엔드 / Node와의 상호 운용 | SM4에 `forJavascript: true` 사용, 프론트엔드는 sm-crypto의 동일 모드 사용 |
| 긴 메시지 서명 검증 | 먼저 `SM3Util.Hash`로 다이제스트를 얻은 다음, 비즈니스 필드와 함께 전송하여 비교 |
| 빈번한 바이너리 스트림 암호화/복호화 | SM2 / SM4의 바이트 배열 오버로드를 사용하여 문자열 인코딩/디코딩 오버헤드 회피 |
| SM2 키 영구 저장 | `GenerateKeyPair`에서 출력된 16진수 문자열을 직접 저장; 자체 Base64 처리 금지 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `ArgumentException: KeyMustBe16Characters` | SM4 키가 hex가 아닌 모드에서 16바이트가 아님 | 문자열 길이를 조정하거나, `hexString: true`을(를) 사용하여 32자 hex 전달 |
| `ArgumentException: KeyMustBe32Characters` | hex 모드 키 길이가 32가 아님 | hex 문자열이 잘렸거나 불필요한 문자가 추가되지 않았는지 확인 |
| SM2 복호화 시 `CryptographicException(Sm2InvalidDataFormat)` 발생 | 공개키와 개인키가 일치하지 않거나, 암호문이 잘못 재인코딩됨 | 암호화/복호화 양쪽의 16진수 대소문자가 일치하고 불필요한 Base64 처리가 없음을 확인 |
| SM3 해시가 플랫폼마다 다른 결과 반환 | 입력이 `Encoding.Default`로 재인코딩됨 | 반드시 UTF-8 인코딩으로 전달; `SM3Util.Hash`은(는) 내부적으로 이미 UTF-8을 사용 |
| `ArgumentException(PublicKeyStringCannotBeEmpty)` | SM2 공개키 문자열이 비어 있음 | `GenerateKeyPair` 출력이 잘리지 않았는지 확인 |

## 배경 (선택 사항)

`Sm2Helper` / `Sm4Helper`은(는) 비즈니스 지향의 얇은 래퍼이며, 모든 원본 로직(타원 곡선 점 연산, SM4 라운드 키 확장 등)은 BouncyCastle에서 처리합니다; `SM3Util`은 BouncyCastle의 `Sm3Digest`을(를) 직접 재사용합니다. 세 가지 유형의 예외는 `Sm*Helper` 계층에서 캡처된 후 `CryptographicException`으로(로) 통합 래핑되어, 상위 계층에서 하나의 유형으로 캡처할 수 있도록 합니다.

관련 항목: 대칭 암호화 빠른 참조는 《문자열 암호화/복호화 방법》을 참조; 서명 / 검증 워크플로우는 《RSA 사용 방법》을 참조.
