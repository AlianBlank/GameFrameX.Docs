# Android 플랫폼에서 StreamingAsset을 읽을 수 없을 때怎么办(파일명/압축/문자)

Android 기기에서 본 라이브러리는 APK 내의 `assets/`를 일반 폴더로 읽지 않고, APK의 ZIP End-of-Central-Directory와 Central Directory를 읽어 `offset/size`로 직접 `FileStream` 슬라이스에 접근합니다. 그래서 "읽을 수 없다"의 거의 모든 원인은 **경로 불일치**, **APK 내 항목이 압축됨**, **파일명에 특수 문자 포함**, 또는 **split APK / patch 패키지로 나뉘어 `base.apk`에 해당되지 않음**입니다. 본 문서는 빠른 진단 표와 대응 수정 단계를 제공합니다.

## 수정 단계

### 경로 대소문자와 구분자 수정

`BlankReadAssets.ApkImpl.TryGetInfo` 내부에서 `PathUtil.NormalizeRelativePath`를 호출하고, `StringComparer.OrdinalIgnoreCase`로 `s_paths`에 대해 이분 탐색을 수행하므로 경로는 APK에 패키징된 실제 파일명과 일치해야 하며 반드시 슬래시 `/`를 사용해야 합니다.

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L58-L84
public static bool TryGetInfo(string path, out ReadInfo info)
{
    path = PathUtil.NormalizeRelativePath(path);
    info = new ReadInfo();

    var index = Array.BinarySearch(s_paths, path, StringComparer.OrdinalIgnoreCase);
    if ( index < 0 )
    {
        return false;
    }
    ...
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L58-L84)

작업:

1. 실제 패키징된 APK를 확보(`Library/` 또는 `Build/` 디렉터리)한 후, `unzip -l your.apk | head`로 `assets/` 하위 항목의 정확한 대소문자를 확인합니다.
2. 코드에서는 통일하여 `/`만 사용하고, `\`를 혼용하거나 `StreamingAssets` 접두사 또는 `jar:file://...`를 포함하지 않습니다.
3. 리소스명은 가급적 `A–Z`, `a–z`, `0–9`, `_`, `-`, `.`, 단일 계층 `/`만 사용합니다.

### APK 내 assets 비압축 강제

본 라이브러리는 항목을 찾을 때 다음과 같은 어설션을 수행합니다(개발 기간 동안 경고):

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L325-L340 (발췌)
while ( ZipCentralDirectoryFileHeader.TryReadBlock(reader, out header) )
{
    if ( header.CompressedSize != header.UncompressedSize )
    {
#if UNITY_ASSERTIONS
        // 비압축 -> 슬라이스 읽기가 올바름
#endif
        continue;
    }
    ...
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L325-L340)

결과: 압축된 항목은 건너뛰어 "읽을 수 없는" 것처럼 보입니다. 수정:

1. Unity:Player Settings → Publishing Settings → **Build APK(s) without compression**을 체크하지 않되, Gradle/AAPT가 재압축하지 않는지 확인합니다.
2. 커스텀 Gradle(메인 템플릿 `unityLibrary`의 `build.gradle`)에서 `android` 노드에 다음을 추가하여 `assets/**/*.bundle`, `StreamingAssets/**` 등의 핫스팟 디렉터리를 비압축으로 설정합니다:

```groovy
android {
    aaptOptions {
        noCompress 'bundle','unitydefaultresources','StreamingAssets','bin','config.json'
    }
}
```

3. 재패키징 후, `unzip -lv your.apk | grep -E "Method|---"`로 핫스팟 파일의 `Method` 열이 `Stored`인지(`Defl:N`이 아닌지) 확인합니다.

### split APK / OBB patch 처리

Initialize는 `dataPath`의 끝을 판별하여 patch 디렉터리로 갈지 `base.apk`로 돌아갈지 결정합니다:

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L27-L56
public static void Initialize(string dataPath, string streamingAssetsPath)
{
    s_root = dataPath;
    if (dataPath.EndsWith("pram-shadow-files"))
    {
        Debug.Assert(streamingAssetsPath.EndsWith("pram-shadow-files/assets"));
        GetStreamingAssetsFromPatch(dataPath, paths, parts);
    }
    else
    {
        GetStreamingAssetsInfoFromJar(s_root, paths, parts);
        if (paths.Count == 0 && !Application.isEditor && Path.GetFileName(dataPath) != "base.apk")
        {
            var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
            if (File.Exists(newDataPath))
            {
                s_root = newDataPath;
                GetStreamingAssetsInfoFromJar(newDataPath, paths, parts);
            }
        }
    }
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

여러 split를 호스팅하는 앱이라면 다음이 필요합니다:

1. 실제 `assets`를 `base.apk`에 집중시켜 패키징하고, split 패키지에 `assets/` 하위 디렉터리가 남지 않도록 합니다.
2. Play Asset Delivery / 커스텀 patch 디렉터리를 사용하는 경우, 호출자가 전달한 `dataPath`가 `.../pram-shadow-files`인지 확인합니다(논리 분기가 `GetStreamingAssetsFromPatch`로 진행됨).

### 파일명 명명 규칙 통일

ZIP Central Directory에서 파일명 길이는 `[ushort]` 제약을 받으며, Unicode 인코딩 처리는 General Purpose Bit Flag의 비트 11(UTF-8)에 의존합니다. 일부 Android 툴체인은 이 플래그 비트를 쓰지 않아 멀티바이트 문자 파일명 파싱이 실패합니다. 작업:

1. 리소스명은 모두 ASCII로 합니다: `game_config`, `map_01.bin`, `lang_zh.json`.
2. `+`, `%`, 공백, 이모지를 금지합니다.
3. 다국어 리소스를 반드시 지원해야 한다면, 디렉터리로 구분합니다(`assets/i18n/zh/...`). 파일명에 임베드하지 않습니다.

### APK 메인 패키지 경로 확인

split 시나리오에서 Unity가 제공하는 `Application.streamingAssetsPath`는 `base.apk`를 가리키지 않으며, Initialize가 자동으로 fallback합니다:

```csharp
var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
if (File.Exists(newDataPath)) { s_root = newDataPath; }
```

(Source 동일) 다만 프로젝트에서 App Bundle 병합 또는 커스텀 aapt를 수행하여 `assets`를 `base.apk`가 아닌 다른 파일로 리다이렉트한 경우 fallback이 실패합니다. 수정:

1. 디바이스에서 `adb shell pm path <your.package>`로 현재 Package의 `base.apk` 실제 경로를 찾습니다.
2. `Application.streamingAssetsPath`와 비교하여 일치하지 않으면, Gradle/AGP에서 `--split-by-abi` / `--split-resources`를 활성화했는지 확인하고 `assets`를 함께 분할하지 않도록 합니다.

## 검증

1. **오프라인 확인 체크리스트**: 생성된 APK를 `unzip -l`로 `assets/`의 상위 50개 항목을 나열하고, 코드에서 전달한 상대 경로와 하나씩 대조합니다(대소문자, 구분자, `.bin` 접미사).
2. **Editor vs Device 동일 출처**:`BlankReadAssets.LooseFilesImpl`(비 Android)과 `BlankReadAssets.ApkImpl`(Android)은 모두 동일한 `PathUtil`을 따르므로, 먼저 Editor에서 `OpenRead`를 통과시킨 다음 기기에서 검증합니다.
3. **읽기 스모크 테스트**:

```csharp
using (var s = BlankReadAssets.OpenRead("config/game_config.json"))
{
    Debug.Assert(s.Length > 0, "size == 0, APK 내부가 압축되었거나 경로가 잘못됨");
}
```

4. **실기기 로그**: 위의 `Debug.Assert`를 `Debug.LogError`로 교체하여 전체 스택을 확인합니다; `Method != Stored`가 표시되면 바로 [APK 내 assets 비압축 강제](#apk-내-assets-비압축-강제)로 돌아갑니다.

## 배경(선택)

Android에서 Unity는 `Assets/StreamingAssets/` 전체를 APK의 `assets/` 섹션에 넣으며, ZIP 컨테이너 끝에서 인덱스를 찾을 수 있으므로 iOS/Jar의 `UnityWebRequest`로 `jar:file://...`를 가져오는 방식이 필요 없습니다. 본 라이브러리는 `File.OpenRead(apkPath)` + `SubReadOnlyStream`로 직접 영(0) 복사 슬라이스 경로를 사용하므로, "압축 여부"와 "경로 정확성"이 읽지 못함과 잘못된 읽기의 여부를 직접 결정합니다.
