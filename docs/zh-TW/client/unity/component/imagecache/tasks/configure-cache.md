# 快取路徑與容量的設定方式

可透過 `ImageCacheConfig` 設定磁碟快取的路徑、最大容量與有效期限天數。元件的 `Awake` 時，Inspector 上的設定會同步至 `IImageCacheManager.Config`,若未指定路徑，預設將使用 `Application.persistentDataPath` 下的 `cache/images/`。

## 前置條件

- `ImageCacheComponent` 已附加至場景入口的 GameObject。
- `ImageCacheManager` 已註冊至 `GameFrameworkEntry`(會在元件的 `Awake` 內透過 `componentType` 以反射方式生成)。

## 操作步驟

1. 在場景中選取附加了 `ImageCacheComponent` 的 GameObject 後，Inspector 會顯示 **Image Cache Config** 區段，其中包含 `Cache Path`、`Max Disk Size (Bytes)`、`Expire Days` 三個欄位。

2. 設定快取目錄的路徑 `Cache Path`。若留空，將使用 `PathHelper.AppHotfixResPath + "/cache/images/"` 作為預設目錄。若使用自訂路徑，請確認處理程序對該目錄具有讀寫權限。若目錄不存在，管理器會視需要自動建立。

```csharp
[SerializeField]
private string m_CachePath;
public string CachePath { get; set; }
```

來源:[ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L12-L44)

3. 設定磁碟最大容量 `MaxDiskSize`(位元組)。`0` 表示無限制。

```csharp
[SerializeField]
private long m_MaxDiskSize;
public long MaxDiskSize { get; set; }
```

來源:[ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L18-L53)

4. 設定有效期限天數 `ExpireDays`。`0` 表示永久有效。

```csharp
[SerializeField]
private int m_ExpireDays;
public int ExpireDays { get; set; }
```

來源:[ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L24-L62)

5. 執行階段設定同步：元件的 `Awake` 會將序列化欄位同步至管理器，因此無需手動呼叫。

```csharp
_imageCacheManager.Config.CachePath = string.IsNullOrEmpty(m_Config.CachePath)
    ? PathHelper.AppHotfixResPath + "/cache/images/"
    : m_Config.CachePath;
_imageCacheManager.Config.MaxDiskSize = m_Config.MaxDiskSize;
_imageCacheManager.Config.ExpireDays = m_Config.ExpireDays;
```

來源:[ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L49-L53)

## 常見變化

- **在執行階段變更設定**：從 `ImageCacheComponent.Config` 取得設定物件，並直接指派至 `CachePath`、`MaxDiskSize`、`ExpireDays`。後續的 `LoadImageAsync` 將使用新的值。
- **WebGL 平台**：快取由瀏覽器管理，因此 `CachePath`/`MaxDiskSize`/`ExpireDays` 無效。`IsCached` 一律回傳 `false`,呼叫 `RemoveCache` 與 `ClearCache` 時會輸出 `ImageCache: ... is not supported on WebGL.` 警告。
- **非 WebGL 平台**：快取檔案的名稱為 URL 的 MD5 雜湊值，副檔名為 `.png`,路徑格式為 `CachePath/<md5>.png`。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 啟動日誌 `ImageCache manager is invalid.` | 未註冊 `IImageCacheManager` 的實作，或 `componentType` 設定錯誤 | 在 Inspector 中確認 `Component Type`,確保能解析為 `ImageCacheManager` |
| 啟動日誌 `Download manager is invalid.(非 WebGL)` | 未註冊 `IDownloadManager` | 確認 `GameFrameworkEntry` 已載入下載模組 |
| 呼叫 `RemoveCache` / `ClearCache` 時輸出警告 `not supported on WebGL.` | WebGL 不使用磁碟快取 | 使用瀏覽器快取，或自行以 `UnityWebRequest` 呼叫處理 |
| 設定自訂 `CachePath` 後發生權限錯誤 | 路徑無法寫入 | 使用 `Application.persistentDataPath` 的子目錄，或確認目錄的寫入權限 |

## 背景(選填)

`ImageCacheConfig` 是 `[Serializable]` 類別，由 `ImageCacheComponent.m_Config` 序列化，並透過 `ComponentTypeComponentInspector` 公開至 Inspector。`MaxDiskSize` 與 `ExpireDays` 僅作為設定項目保留，目前的 `ImageCacheManager` 在載入處理中不會依據這兩項執行清理。清理需要由業務端自行呼叫 `ClearCache`。
