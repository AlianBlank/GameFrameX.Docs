# Actor / ComponentAgent를 사용하여 동시 작업 스케줄링

Actor는 "플레이어/씬/글로벌" 등의 비즈니스 엔티티를 단일 스레드 직렬 실행 스케줄링 단위로 래핑합니다. ComponentAgent는 Actor 위의 재사용 가능한 비즈니스 컴포넌트로, 모든 엔티티 간 호출은 `ActorManager`를 통해 가져오므로 락을 피하고 데이터 일관성을 보장합니다. 이 페이지에서는 ComponentAgent를 가져오고 호출하여 동시 작업을 스케줄링하는 방법을 보여줍니다.

## 사전 조건

- GameFrameX Actor 프레임워크가 연동되어 있고, `ActorManager`가 런타임 환경에서 접근 가능해야 합니다.
- `ComponentAgent<TComponent>` 또는 `StateComponentAgent<TComponent, TState>`를 상속하는 컴포넌트 Agent가 이미 존재해야 합니다.
- 비즈니스 엔티티에 `ActorId`(`long` 타입)가 이미 있어야 하며, `ActorId`가 없는 글로벌 Agent 호출은 `GetComponentAgent<T>()`를 사용합니다.

## 작업 단계

1. Actor에 접근 가능한 임의의 위치에서 `ActorManager`를 통해 대상 컴포넌트 Agent를 가져옵니다.

```csharp
// 글로벌 공유 컴포넌트(ActorId 차원 없음)
var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
await serverComp.RemoveOnlineRole(ActorId);
```

출처: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L46-L53)

2. 특정 플레이어의 컴포넌트를 조작해야 할 때, 플레이어 `ActorId`를 두 번째 매개변수로 전달하면 프레임워크가 해당 Actor의 직렬 큐로 라우팅합니다.

```csharp
var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
await attributeComponentAgent.InitializeDefaultsSilent();
```

출처: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L77-L78)

3. 동일한 Actor의 여러 Agent를 직렬로 스케줄링할 때는 비즈니스 순서대로 `await` 호출하면 되며, 프레임워크가 동일한 Actor 내 호출이 직렬로 실행됨을 보장합니다.

```csharp
// 모두 동일한 플레이어 ActorId에서 순서대로 직렬 실행됩니다
var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
await mailAgent.SyncAsync();

var bagAgent = await ActorManager.GetComponentAgent<BagComponentAgent>(playerState.Id);
await bagAgent.SomeBusiness();
```

출처: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L91-L92)

4. Agent의 작업이 완료되면 Actor 참조를 보유한 곳에서 자동 회수를 설정하여 상시 상주를 피합니다.

```csharp
// 로그아웃 후 자동으로 회수됩니다
SetAutoRecycle(true);
QuartzTimer.Remove(ScheduleIdSet);
```

출처: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L50-L52)

## 일반적인 변형

| 시나리오 | 작성 방법 | 설명 |
|------|------|------|
| 글로벌 싱글턴 컴포넌트 | `await ActorManager.GetComponentAgent<T>()` | `ActorId`를 전달하지 않고 프로세스 수준 공유 Agent를 가져옵니다 |
| 플레이어 전용 컴포넌트 | `await ActorManager.GetComponentAgent<T>(actorId)` | 프레임워크가 `actorId`를 기준으로 해당 플레이어 Actor로 라우팅합니다 |
| 룸/씬 컴포넌트 | `await ActorManager.GetComponentAgent<RoomComponentAgent>()` | 일반적으로 글로벌 Agent이며, 내부에서 룸 Key로 다시 인덱싱합니다 |

## 일반적인 오류

- `new T()`로 직접 Agent 생성: Agent는 반드시 `ActorManager`가 생성하고 관리해야 하며, 수동 인스턴스화는 직렬 큐와 회수 메커니즘을 우회하게 됩니다.
- `ActorId`를 보유하지 않은 곳에서 플레이어 전용 Agent 호출: Actor를 찾을 수 없어 오류가 발생합니다. 글로벌 컴포넌트는 매개변수 없는 `GetComponentAgent<T>()`를 사용하세요.
- 플레이어 로그아웃 시 `SetAutoRecycle(true)` 호출을 잊은 경우: Agent가 계속 상주하며 큐와 타이머 리소스를 점유합니다([PlayerComponentAgent.OnLogout](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L45-L53) 참조).

## 배경(선택 사항)

Actor 모델은 "동일한 플레이어/씬에 대한 동시 접근"을 직렬 메시지 큐로 변환하며, ComponentAgent는 Actor에 매달린 비즈니스 단위입니다. `ActorManager`는 컴포넌트 라이프사이클과 Actor 간 라우팅을 동시에 담당하며, 이것이 로그인 흐름의 모든 초기화 작업이 락 없이 단일 `await` 체인에서 완료될 수 있는 이유입니다.
