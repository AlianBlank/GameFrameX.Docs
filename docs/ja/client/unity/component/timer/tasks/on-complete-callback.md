# タイマーの完了または削除時にコールバックを実行する

`Add(...)` の呼び出し時に最後のオプション引数 `onComplete`（`System.Action`）を渡すと、タイマーは**完了（繰り返し回数の消費）または削除された時**に自動的にそれを呼び出します。シグネチャは以下の通りです：

```csharp
int Add(float interval, int repeat, Action<object> callback, object callbackParam = null,
        string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled,
        Action onComplete = null);
```

出典：[ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L14-L22)

## 前提条件

- シーンに `TimerComponent` が作成・初期化済みであること（内部に `ITimerManager` を保持し、`Add` を転送します）。
出典：[TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

## 操作手順

1. 毎回のトリガー時の処理を担当する、通常の定期コールバック（`Action<object>`）を用意します。
2. `Add` の呼び出しで名前付き引数 `onComplete:` を使って完了コールバックを渡します（一連のオプション引数の後ろに位置するため、名前付き引数の使用を推奨します）。
3. 繰り返し回数の消費または手動削除を待つと、`onComplete` が自動的に一度だけ呼び出されます。

```csharp
bool completed = false;

// 1秒ごとに1回、合計3回トリガー；3回目の終了後に completed が true になる
int id = timerComponent.Add(1f, 3, _ => { Debug.Log("tick"); },
                            onComplete: () => completed = true);
```

出典：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L660-L664)

手動での削除でも同様にコールバックがトリガーされます――例えばコールバック関数を介した削除：

```csharp
var callback = new Action<object>(_ => { });
_timerManager.Add(1f, 0, callback, onComplete: () => completed = true);
_timerManager.Remove(callback);   // 削除後 completed == true
```

出典：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L677-L684)

## よくあるバリエーション

- **タググループとの併用**：`onComplete` は `Add` の引数の一つであり、`tag`、`timeScale` と一緒に使用できます。タグによる `PauseByTag` / `ResumeByTag` / `RemoveByTag` 操作には影響しません。
  出典：[ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L93-L118)
- **同一コールバックの再利用による再追加**：既に存在する `callback` に対して再度 `Add` すると、その場で更新されます（`t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete)` が呼ばれ、計時がリセットされます）。新しく渡された `onComplete` は古いものを上書きします。
  出典：[TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L243)

## よくある間違い

- **無限繰り返しのタイマーでコールバックのトリガーを期待する**：`repeat = 0` は無限繰り返しを意味し、タイマーは永遠に「完了」しないため、`onComplete` はトリガーされません。終了のタイミングが必要な場合は、有限回数を明示的に設定するか `Remove` を呼び出してください。
  出典：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L688-L699)
- **コールバックが null のためタイマーが作成されない**：`callback == null` の場合、警告 `Timer callback error` の前のログ `"timer callback is null, " + interval + "," + repeat` のみを出力して 0 を返すため、`onComplete` も当然トリガーされる機会がありません。メインのコールバック `callback` は null 以外である必要があります（`onComplete` 自体は null でも構いません）。
  出典：[TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L221-L225)
- **引数の順序の書き間違い**：`onComplete` は第 7 引数であり、位置による引数指定では順序がずれやすいため、常に名前付き引数 `onComplete: () => ...` を使用することをお勧めします。
  出典：[ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L22)

## 背景

`onComplete` は内部の `TimerItem` の `OnComplete` フィールドに格納され（`public Action OnComplete;`）、スケジューリングスレッドがタイマーを削除対象としてマークし、実際にディクショナリから取り除く際に `i.OnComplete?.Invoke()` を呼び出します。タグ一括削除のパスも同様に、タグインデックスから取り除いた後に `t.OnComplete?.Invoke()` を呼び出すため、自然完了でも削除でもこの一つの出口を通ります。
