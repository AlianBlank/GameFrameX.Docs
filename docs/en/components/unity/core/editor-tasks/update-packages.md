# Batch Update Project Dependencies

Use `UpdateAllPackageHelper` to batch update all Git dependencies ending with `.git` in `Packages/manifest.json` with one click, eliminating the tedious manual process of updating them one by one.

## Prerequisites

- `Packages/manifest.json` exists in the project root directory and contains at least one dependency URL in the `*.git` format.
- The project has been opened through Unity.
- The Git command is available in the system PATH (UPM's `Client.Add` will invoke local Git to pull from the remote).

## Steps

### Method 1: One-Click Batch Update via Menu

1. In the Unity editor top menu, select `GameFrameX → Update All Packages(更新所有git包)`.
2. When the confirmation dialog `是否更新所有包?` pops up, click **Yes**.
3. The tool will read `Packages/manifest.json`, add all dependencies ending with `.git` to the update queue, and display a cancelable progress bar.
4. After the update is complete, **restart Unity** to let UPM apply the changes.

The menu entry implementation is at [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L20-L32):

```csharp
[MenuItem("GameFrameX/Update All Packages(更新所有git包)", false, 2000)]
public static void UpdatePackages()
{
    var result = EditorUtility.DisplayDialog("更新包提示", "是否更新所有包?\n 更新完成之后需要[重启、重启、重启]Unity", "是", "否");
    if (result)
    {
        var manifestPath = Path.Combine(Application.dataPath, "..", "Packages", "manifest.json");
        UpdatePackagesFromManifest(manifestPath);
    }
}
```

### Method 2: Update to a Specific Version in the Package Manager Window

1. Open the editor window `GameFrameX → Package Manager`.
2. Select the package to update in the list, and click **Update To Version** in the toolbar.
3. The tool will rewrite that package's URL by appending the `#<version>` suffix, and immediately trigger the update flow through `UpdateAllPackageHelper.UpdatePackages(name, url)`.

Implementation is at [PackageManagerWindow.cs](/src/Editor/PackageManager/PackageManagerWindow.cs#L233-L274):

The toolbar entry is at [PackageManagerWindow.ToolBar.cs](/src/Editor/PackageManager/PackageManagerWindow.ToolBar.cs#L60-L70), where clicking the button directly invokes `UpdateAllPackageHelper.UpdatePackages()`.

### Method 3: Invoke from Code

If you want to reuse the same logic in custom editor scripts, simply call the two static methods:

```csharp
using GameFrameX.Editor;

// Enqueue a single Git dependency
UpdateAllPackageHelper.UpdatePackages("com.gameframex.runtime", "https://example.com/repo.git");

// Actually start pulling (sequentially call Client.Add from the queue)
UpdateAllPackageHelper.StartUpdate();
```

The signature definition is at [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L34-L42):

```csharp
/// <summary>
/// 更新指定包
/// </summary>
/// <param name="packageName">包名</param>
/// <param name="packageUrl">包地址</param>
public static void UpdatePackages(string packageName, string packageUrl)
{
    PackagesToUpdate.Enqueue((packageName, packageUrl));
}
```

## Manifest Scanning and Queue Population Logic

`UpdatePackages()` will call the private method `UpdatePackagesFromManifest` to parse `manifest.json`. Only dependencies ending with `.git` are enqueued; other forms such as version numbers or local paths are ignored. See [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L44-L64):

```csharp
foreach (var package in dependencies)
{
    string packageName = package.Key;
    string packageUrl = package.Value.ToString();
    if (packageUrl.EndsWith(".git"))
    {
        UpdatePackages(packageName, packageUrl);
    }
}
StartUpdate();
```

## Common Variants

| Scenario | Approach |
|------|------|
| Only want to update a single package to a fixed version | Open the Package Manager window and use the Update To Version feature (automatically appends `#<tag>`) |
| Only want batch updates while preserving version numbers | Make sure the URLs in manifest.json are in the form `https://.../repo.git#v1.2.0`; UPM will pull that tag |
| Want to extend updates to more sources from code | Enqueue more `(name, url)` yourself, then call `StartUpdate()` |

## Common Errors

- **Console error after update**: If the progress bar is canceled, the queue will be cleared by `PackagesToUpdate.Clear()`, see [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L92-L99); if you need to continue, retrigger the menu.
- **Changes to manifest.json did not take effect**: The menu prompt explicitly requires **restart, restart, restart Unity**, otherwise the UPM cache will not be refreshed.
- **Dependencies not in `.git` URL form are ignored**: For example, `file:./...` or OpenUPM links will be skipped; use the Update To Version feature in the Package Manager window instead.
- **`Client.Add` called too frequently**: The queue implementation `Queue<(name, url)>` processes serially to avoid concurrent request exceptions.

## Background (Optional)

Inside `UpdateAllPackageHelper`, the `AddRequest` + `EditorApplication.update` event is used to drive progress, calling `UnityEditor.PackageManager.Client.Add` for each package one by one, and providing cancelable progress feedback through `EditorUtility.DisplayCancelableProgressBar`. All state (`_addRequest`, `PackagesToUpdate`, `_allPackagesCount`, `_updatingPackagesIndex`) are `static` fields, preserved across calls, suitable for enqueueing multiple times and then starting once.
