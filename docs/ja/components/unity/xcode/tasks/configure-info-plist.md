# Info.plist の権限と URL Schemes の設定

Xcode ビルド設定(JSON)の最上位にある `plist` フィールドにキーと値のペアを追加すると、ビルド後に `PostProcessBuildHelper` が自動的にそれらを生成された `Info.plist` に書き込みます。権限の説明文、URL Schemes、スキームのホワイトリストなどはすべてこの一箇所の設定で完結し、Xcode プロジェクトを手作業で変更する必要はありません。

## 前提条件

- Unity プロジェクトに `com.gameframex.unity.xcode` パッケージがインストールされていること。
- iOS プラットフォームでビルドすること(Xcode 関連のコードは `#if UNITY_IOS` の下でコンパイルされます)。
- 最上位に `plist` オブジェクトを含む Xcode ビルド設定ファイルが既に存在すること(空でも可):

```json
"plist": {},
```

出典： [README.ja.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.ja.md#L84-L86)

## 手順

1. Xcode ビルド設定ファイルを開き、最上位の `plist` フィールドを探します(なければ空のオブジェクトを新規作成します)。
2. 権限の説明などの文字列のキーと値を追加します。例えばカメラやフォトライブラリの使用説明などです。
3. サードパーティログイン/アプリ呼び出しのコールバックが必要な場合は、`CFBundleURLTypes` を追加して URL Schemes を登録します。
4. 他の App がインストールされているかどうかの検出が必要な場合(iOS 9 以降で必須)、`LSApplicationQueriesSchemes` のホワイトリストを追加します。
5. iOS ビルドを実行します。コンソールに `设置项目[Info.plist]开始` と `设置项目[Info.plist]结束` のログが出力されれば、書き込み成功です:

```csharp
LogHelper.Log("设置项目[Info.plist]开始");
//plist
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
SetPlist(project, plist.root, hashtable);
//書き込み
plist.WriteToFile(plistPath);
LogHelper.Log("设置项目[Info.plist]结束");
```

出典： [Editor/PostProcessBuildHelper.Plist.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Plist.cs#L11-L22)

6. 生成された Xcode プロジェクトを開き、Target → Info タブで該当するキーが表示されていることを確認します。

以下はそのままコピーして使える `plist` 設定の例です(キー名は iOS 標準の Info.plist キーで、値の型はフレームワークがサポートする型によって決まります。下記の「背景」のマッピング表を参照してください):

```json
"plist": {
    "NSCameraUsageDescription": "扫描二维码需要使用相机",
    "NSPhotoLibraryUsageDescription": "保存截图需要访问相册",
    "LSApplicationQueriesSchemes": [
        "weixin",
        "weixinULAPI"
    ],
    "CFBundleURLTypes": [
        {
            "CFBundleURLName": "com.yourcompany.yourgame",
            "CFBundleURLSchemes": ["yourgame"]
        }
    ]
}
```

設定内の `plist` の値は、ビルド時に `finalConfig.Get<Hashtable>("plist")` で読み込まれ、処理フローに渡されます:

```csharp
// Info.Plistの設定
RunPlist(project, path, finalConfig.Get<Hashtable>("plist"));
```

## よくあるバリエーション

- **複数の URL Schemes**:`CFBundleURLTypes` 配列に複数の辞書オブジェクトを追加するだけでよく、各オブジェクトには `CFBundleURLName` と `CFBundleURLSchemes` を含めます。
- **バックグラウンドモード**:同じく `plist` の下に記述します。例:`"UIBackgroundModes": ["audio"]`(文字列配列)。
- **権限説明文のローカライズ**:フレームワークのローカライズ設定を使用すると、`.lproj/InfoPlist.strings` が自動生成され、`LSHasLocalizedDisplayName` が `true` に設定されます。多言語の文言を `plist` のキーと値にハードコードしないでください:

```csharp
plistPath = Path.Combine(path, "Info.plist");
if (File.Exists(plistPath))
{
    ...
    plist.WriteToFile(plistPath);
    LogHelper.Log("Updated Info.plist: Set LSHasLocalizedDisplayName to true");
}
```

## よくある間違い

- **数値は整数としてのみ書き込まれる**:書き込みロジックでは数値型に対して一律 `SetInteger(key, Convert.ToInt32(...))` が実行されるため、小数は切り捨てられます。浮動小数点値の書き込みには使用しないでください。
- **ブール値が文字列として書き込まれる**:実際の JSON ブール値(`true`/`false`)のみが `SetBoolean` を呼び出します。`"YES"` / `"true"` と記述すると文字列として書き込まれ、Info.plist 内で型エラーになります。
- **キー名のスペルミスは警告されない**:処理は「あるものをそのまま書き込む」項目ごとの上書きであるため、スペルミスのあるキー(`NSCameraUsageDesciption` など)でもエラーにはならず、Xcode の Info タブで手動で確認するしかありません。
- **ネスト構造の階層が誤っている**:`CFBundleURLTypes` は「配列 → 辞書 → 配列」のネストでなければならず、階層が一つ欠けると Xcode で URL Types ではなく通常の文字列として表示されます。

## 背景

`SetPlist` は設定値のランタイム型に従って再帰的に書き込みを行います。マッピングは以下の通りです(配列の要素にも同じ規則が適用されます):

| 設定値の型 | Info.plist の書き込み型 | 呼び出し |
|------|------|------|
| 文字列 | string | `SetString` |
| ブール値 | boolean | `SetBoolean` |
| 数値(double) | integer | `SetInteger`(`Convert.ToInt32`) |
| 配列(ArrayList) | array | `CreateArray` / `AddArray` |
| オブジェクト(Hashtable) | dict | `CreateDict` / `AddDict` |

```csharp
if (vType == typeof(string))
{
    node.SetString(key, (string)val);
}
else if (vType == typeof(bool))
{
    node.SetBoolean(key, (bool)val);
}
else if (vType == typeof(double))
{
    node.SetInteger(key, Convert.ToInt32((double)val));
}
else if (vType == typeof(ArrayList))
{
    var t = node.CreateArray(key);
    var array = val as ArrayList;
    SetPlist(proj, t, array);
}
else if (vType == typeof(Hashtable))
{
    var t = node.CreateDict(key);
    var table = val as Hashtable;
    SetPlist(proj, t, table);
}
```
