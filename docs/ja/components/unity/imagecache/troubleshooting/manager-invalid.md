# ImageCache manager is invalid エラーが発生した場合の対処法

ゲームの起動ログに `ImageCache manager is invalid.` が表示された場合、`ImageCacheComponent.Awake()` が `GameFrameworkEntry.GetModule<IImageCacheManager>()` でマネージャーインスタンスを取得しようとして `null` を返したことを意味します。フレームワーク内にこのインターフェースを実装したクラスが存在しません。その後コンポーネントは直接 `return` し、すべての画像読み込み(`LoadImageAsync`、`IsCached`、`RemoveCache`、`ClearCache`)は機能しません。

エラー発生箇所(`Awake` エントリ):

```csharp
_imageCacheManager = GameFrameworkEntry.GetModule<IImageCacheManager>();
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L42-L47)

## 迅速な診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動ログに `ImageCache manager is invalid.` が出力され、その後のすべての画像インターフェースが `null` / 無効を返す | `GameFrameworkEntry` に `IImageCacheManager` の実装が登録されていない | フレームワーク起動後に `GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager())` を呼び出す |
| 起動ログに `Download manager is invalid.`(WebGL プラットフォーム以外)も同時に表示される | `IDownloadManager` モジュールが不足しており、`Awake` が早期に return することでマネージャーが注入されない | まず `IDownloadManager`(例:`DownloadManager`)を登録し、その後 `ImageCacheManager` を登録する |
| エラーが特定のシーンでのみ発生する | 現在のシーンに `ImageCacheComponent` がアタッチされていない、または非アクティブの GameObject にアタッチされている | 常駐 GameObject に `ImageCacheComponent` をアタッチし、シーン読み込み時に `Awake` が完了していることを確認する |
| カスタム実装クラスが `IImageCacheManager` を継承しているにもかかわらずエラーが発生する | `componentType`(Inspector フィールド)の入力が誤っており、`Awake` 内の `Utility.Assembly.GetType(componentType)` が `null` を返す | Inspector で `Component Type` を名前空間を含む完全なクラス名に変更する |

## 修正手順

### 1. フレームワークエントリで `ImageCacheManager` を登録する

`ImageCacheComponent` はマネージャーインスタンスを自動的に作成しないため、ビジネスエントリ側で明示的に登録する必要があります。一般的な方法は、フレームワークの起動フローで以下を呼び出すことです:

```csharp
using GameFrameX.Runtime;
using GameFrameX.ImageCache.Runtime;

GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager());
```

Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L11-L48)

### 2. WebGL 以外のプラットフォームで Download モジュールを補完する

`ImageCacheComponent.Awake()` は `IDownloadManager` も検証するため、これが不足しているとマネージャー初期化が失敗します:

```csharp
#if !UNITY_WEBGL
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
((ImageCacheManager)_imageCacheManager).SetDownloadManager(downloadManager);
#endif
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55-L64)

したがって、登録順序は次のとおりである必要があります:まず `IDownloadManager` を登録し、次に `IImageCacheManager` を登録し、最後にシーン内の `ImageCacheComponent` がアタッチされたオブジェクトの `Awake` を実行します。

### 3. シーン内のコンポーネントのアタッチ状況を確認する

`ImageCacheComponent` が**常駐** GameObject(例:ブートストラップシーンの `GameFrameX` ルートノード)にアタッチされていることを確認してください。特定のビジネスシーンだけにアタッチされているのではありません。`Awake` はシーンが最初にアクティブ化されたときに一度だけトリガーされるため、これが存在しないとすべての画像呼び出しが無効になり、マネージャー作成の再試行は行われません。

### 4. カスタム実装クラスの場合は `Component Type` を確認する

`Awake` は `Utility.Assembly.GetType(componentType)` を使用して実装タイプを解析します:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IImageCacheManager);
base.Awake();
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L39-L41)

`componentType` には実装クラスの**完全修飾クラス名(名前空間を含む)** を入力する必要があり、そのクラスはランタイムアセンブリにコンパイルされている必要があります。そうでない場合、`Awake` の内部でまず例外が発生し、その後の `GetModule<IImageCacheManager>()` も `null` を返し、本エラーの引き金となります。

## 検証

上記の修正を完了した後、以下の方法で問題が解消されたことを確認してください:

1. ゲームを起動し、ログ内で `ImageCache manager is invalid.` を検索します。一致する項目がないはずです。
2. `GameFrameXEntry.GetModule<IImageCacheManager>()` を呼び出し、戻り値が `null` ではないことを確認します。
3. WebGL 以外のプラットフォームで `LoadImageAsync("https://example.com/test.png")` を一度実行し、`Config.CachePath` が指すディレクトリに正常にダウンロードおよびキャッシュできることを確認します。
