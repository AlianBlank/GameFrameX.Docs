# 다국어 앱 이름 설정

빌드 설정 JSON의 `localizations` 배열에서 각 언어에 대해 `languageCode`와 `validMap`(`CFBundleDisplayName` 키 포함)을 선언하면, 빌드 후 처리가 Xcode 프로젝트 디렉터리 아래에 `{languageCode}.lproj/InfoPlist.strings`를 자동으로 생성하고, 파일을 메인 target의 Resources에 추가하며, `Info.plist`에 `LSHasLocalizedDisplayName = true`를 기록하여 iOS 홈 화면 아이콘 아래에 해당 언어의 이름이 표시되도록 합니다.

## 사전 조건

- Unity가 iOS 플랫폼으로 전환되어 있고, 본 패키지(`com.gameframex.unity.xcode`)가 설치되어 있어야 합니다.
- 프로젝트에 `PostProcessBuildHelper`의 빌드 후 처리 흐름이 연동되어 있어야 합니다. 로컬화 로직은 이 흐름에서 일괄 트리거됩니다([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126) 참조, 병합된 설정에서 `localizations` 필드를 읽음).

## 작업 단계

1. iOS 빌드 설정 JSON에 `localizations` 배열을 추가합니다(`podInstall`, `capabilities` 등 필드와 동일한 레벨):

   ```json
   "localizations": [
     {
       "languageCode": "en",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "My Game" }
       ]
     },
     {
       "languageCode": "zh-Hans",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "我的游戏" }
       ]
     }
   ]
   ```

   필드 의미:

   | 필드 | 타입 | 설명 |
   |------|------|------|
   | `localizations` | array | 로컬화 설정 목록으로, 각 항목은 하나의 언어에 대응합니다 |
   | `languageCode` | string | 언어 코드이며 `{languageCode}.lproj` 디렉터리 이름으로 사용됩니다(예: `en.lproj`, `zh-Hans.lproj`); 비어 있거나 누락된 경우 해당 항목은 건너뜁니다 |
   | `validMap` | array | 키-값 쌍 목록으로, 각 항목은 `key`와 `value`를 포함합니다; 비어 있거나 누락된 경우 해당 항목은 건너뜁니다 |
   | `key` | string | Info.plist 키 이름; 앱 이름 로컬화에는 고정적으로 `CFBundleDisplayName`을 사용합니다 |
   | `value` | string | 해당 언어에서 표시되는 텍스트 |

   설정 예제의 구조는 [README.zh-TW.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-TW.md#L323-L346)의 `localizations` 섹션 작성 방식과 일치합니다. `languageCode` / `validMap`의 필드 이름은 [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L52)의 실제 읽기 로직을 기준으로 합니다.

2. iOS 빌드를 실행합니다. 후 처리가 다음 동작을 자동으로 수행합니다(수동 개입 불필요):

   ```csharp
   foreach (Hashtable loc in localizations)
   {
       ...
       // Create .lproj directory
       string lprojName = langCode + ".lproj";
       string lprojPath = Path.Combine(path, lprojName);
       if (!Directory.Exists(lprojPath))
       {
           Directory.CreateDirectory(lprojPath);
       }

       // Prepare InfoPlist.strings content
       StringBuilder sb = new StringBuilder();
       foreach (Hashtable map in validMap)
       {
           if (map.ContainsKey("key") && map.ContainsKey("value"))
           {
               string key = map["key"].ToString();
               string value = map["value"].ToString();
               sb.Append($"\"{key}\" = \"{value}\";\n");

               // CFBundleDisplayName 포함 여부 확인
               if (key == "CFBundleDisplayName")
               {
                   hasLocalizedDisplayName = true;
               }
           }
       }
       ...
   }
   ```

   출처: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L91)

3. 생성 결과를 확인합니다. 생성된 `en.lproj/InfoPlist.strings`의 내용은 다음과 같은 형태입니다:

   ```text
   "CFBundleDisplayName" = "My Game";
   ```

   생성 형식은 `sb.Append($"\"{key}\" = \"{value}\";\n")`에 의해 결정됩니다. [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L62-L90) 참조.

## 일반적인 변형

- **다른 Info.plist 키 동시에 로컬화**: `validMap`에 권한 설명 등의 키-값 쌍을 계속 추가할 수 있으며, 이들은 동일한 `InfoPlist.strings`에 함께 기록됩니다:

  ```json
  "validMap": [
    { "key": "CFBundleDisplayName", "value": "我的游戏" },
    { "key": "NSCameraUsageDescription", "value": "需要访问相机用于扫描二维码" }
  ]
  ```

- **더 많은 언어**: `localizations` 배열에 항목을 추가하기만 하면 되며, 각 언어마다 하나의 `.lproj` 디렉터리와 하나의 `InfoPlist.strings`가 생성됩니다.

- **로컬화 비활성화**: `localizations`를 빈 배열 `[]`로 설정하거나 해당 필드를 설정하지 않으면, 후 처리가 즉시 반환되어 아무런 변경도 하지 않습니다([PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L20-L23) 참조).

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 빌드 후 `.lproj` 디렉터리가 생성되지 않음 | `localizations`가 비어 있음/미설정이거나, 항목에 `languageCode`, `validMap`이 누락됨 | 설정이 병합된 최종 설정에 포함되었는지, 각 항목에 비어 있지 않은 `languageCode`와 비어 있지 않은 `validMap`이 모두 있는지 확인하세요(누락된 항목은 `continue`로 건너뜁니다) |
| 권한 설명만 로컬화되고 홈 화면 이름이 여전히 영문 | `validMap`에 `CFBundleDisplayName`이 없음 | 앱 이름 로컬화에는 반드시 키 이름 `CFBundleDisplayName`을 사용해야 하며, 이는 동시에 `LSHasLocalizedDisplayName`을 트리거하는 유일한 조건입니다 |
| `InfoPlist.strings`가 Xcode 프로젝트에 포함되지 않음(표시 언어가 기본값으로 fallback됨) | 파일이 Resources 빌드 단계에 추가되지 않음 | 후 처리가 `project.AddFile(...)` + `project.AddFileToBuild(mainTargetGuid, fileGuid)`로 주입합니다(아래 참조); 프로젝트 파일을 수동으로 삭제한 적이 있다면 다시 한번 빌드하세요 |
| 빌드 로그에 `InfoPlist.strings not found at: ...`가 나타남 | `.lproj` 디렉터리의 파일이 외부 스크립트에 의해 삭제되었거나 생성되지 않음 | 로컬화 이전에 디렉터리를 정리하는 다른 후 처리 스크립트가 있는지 확인하고 다시 빌드하세요 |

## 배경

트리거 흐름: `PostProcessBuildHelper`는 설정을 병합한 후 `RunLocalization(project, project.ProjectGuid(), path, finalConfig.Get("localizations") as ArrayList)`를 호출합니다([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126) 참조). `RunLocalization`은 파일을 생성한 후 `CFBundleDisplayName`이 감지되면 `Info.plist`의 `LSHasLocalizedDisplayName`을 `true`로 설정하고([PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L97-L108)), 이어서 `AddLocalizationToProject`가 각 `InfoPlist.strings`를 메인 target의 Resources에 추가하고 `project.pbxproj`에 다시 기록합니다:

```csharp
// PBXProject API를 사용하여 프로젝트에 파일 추가
string fileGuid = project.AddFile(infoPlistStringsPath, infoPlistStringsPath, PBXSourceTree.Source);

// 파일을 메인 target의 Resources 빌드 단계에 추가
project.AddFileToBuild(mainTargetGuid, fileGuid);

LogHelper.Log($"Added localization file to project: {infoPlistStringsPath}");
```

출처: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L194-L205)

iOS 빌드 후 처리의 전체 흐름과 기타 설정 항목에 대해서는 《iOS 빌드 후 처리 설정 참조》를 참고하세요.
