# 概要

GameFrameX Builder 是 GameFrameX ゲームフレームワーク的 Unity 自动化构建模块，提供完整的 CI/CD 构建フローサポート。该模块を通じて命令行参数驱动的构建方法，能够与 Jenkins、GitLab CI、GitHub Actions 等持续集成平台无缝集成，実装ゲームプロジェクト的自动化打包、资产生成和版本发布。

## Overview

GameFrameX Builder 是 GameFrameX ゲームフレームワーク的コアコンポーネント之一，专注于解决 Unity ゲームプロジェクト的自动化构建问题。在ゲーム开发过程中，频繁的版本发布和多渠道打包是一项耗时且容易出错的工作。Builder 模块を通じて标准化的命令行インターフェース和模块化的构建フロー设计，将这些重复性工作自动化，从而显著開発効率の向上和发布质量。

该模块的コア设计理念是将构建过程拆分为多个独立的阶段，每个阶段专注于特定的任务。这种设计不仅提高了代码的可维护性，还使得构建フロー可能に基づいてプロジェクト需求进行灵活配置。从技术実装角度来看，Builder 模块深度整合了 HybridCLR ホットアップデート解決策、YooAsset リソース管理系统以及多种云存储服务，形成了一套完整的ゲーム发布解決策。

## アーキテクチャ設計

GameFrameX Builder 采用模块化的アーキテクチャ設計，将构建过程中的不同機能分离到独立的クラス中実装。这种设计模式使得每个模块的职责清晰明确，メンテナンスと拡張が容易。以下是 Builder 模块的整体架构图：

## コア機能

### 命令行构建サポート

GameFrameX Builder 完全基づく命令行运行，所有的构建参数都を通じて命令行传递。这种设计使得构建过程可能完全自动化，无需人工干预。在 Builder.cs 中，を通じて `BuildParamsParse()` メソッド解析命令行参数，将各种构建选项存储到 BuilderOptions 对象中。

```csharp
private static void BuildParamsParse()
{
    var commandLineArgs = Environment.GetCommandLineArgs();
    _builderOptions = new BuilderOptions();
    for (var index = 0; index < commandLineArgs.Length; index++)
    {
        var commandLineArg = commandLineArgs[index];
        if (commandLineArg == "-logFile")
        {
            _builderOptions.LogFilePath = commandLineArgs[index + 1].Replace("/Unity/", "/");
        }
        else if (commandLineArg == "-executeMethod")
        {
            _builderOptions.ExecuteMethod = commandLineArgs[index + 1].Trim();
        }
        // ... 更多参数解析
    }
}
```
> Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L60-L74)

这种参数解析机制サポート丰富的构建选项，包括构建编号、任务名称、包名、版本号、渠道名称等。を通じて合理配置这些参数，开发团队可能実装完全自定义的构建フロー。

### 资产生成与打包

Builder 模块集成了 YooAsset リソース管理系统，提供强大的资产生成和打包機能。在 `BuildAsset()` メソッド中，実装了完整的リソース打包フロー，包括ホットアップデート代码复制、AOT 代码处理、リソース包构建等手順。

```csharp
public static void BuildAsset()
{
    // 复制ホットアップデート程序集
    Debug.Log("BuildReady Start Copy Hotfix Code");
    BuildHotfixHelper.CopyHotfixCode();
    AssetDatabase.Refresh();
    
    // 复制AOT代码
    Debug.Log("BuildReady Start Copy AOT Code");
    BuildHotfixHelper.CopyAOTCode();
    AssetDatabase.Refresh();
    
    // 构建リソース包
    var buildInFileCopyParams = AssetBundleBuilderSetting.GetPackageBuildinFileCopyParams(_builderOptions.PackageName, EBuildPipeline.BuiltinBuildPipeline);
    BuiltinBuildPipeline pipeline = new BuiltinBuildPipeline();
    BuildParameters buildParameters = new BuildParameters();
    buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage ? EBuildMode.IncrementalBuild : EBuildMode.ForceRebuild;
    // ... 更多配置
    pipeline.Run(buildParameters, true);
}
```
> Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L255-L296)

リソース打包サポート增量构建和全量构建两种模式，開発者可能に基づいて实际需求选择合适的构建方法。增量构建模式可能显著减少构建时间，特别适合开发阶段的频繁打包需求。

### ホットアップデートサポート

Builder 模块原生サポート HybridCLR ホットアップデート解決策。在构建准备阶段（`BuildReady()` メソッド），系统会自动检查 HybridCLR 的安装ステータス，并在必要时进行自动安装和配置。这一機能对于必要サポートホットアップデート的ゲームプロジェクト至关重要。

```csharp
public static void BuildReady()
{
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
    Debug.Log("BuildReady Start HybridCLR");
    var installerController = new InstallerController();
    var isInstalled = installerController.HasInstalledHybridCLR();
    if (!isInstalled || installerController.InstalledLibil2cppVersion != installerController.PackageVersion)
    {
        installerController.InstallDefaultHybridCLR();
    }
    // 生成ホットアップデート代理
    PrebuildCommand.GenerateAll();
#endif
    AssetDatabase.Refresh();
}
```
> Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L215-L244)

を通じて条件编译指令 `ENABLE_GAME_FRAME_X_HYBRID_CLR`，開発者可能灵活控制是否启用ホットアップデート機能。这种设计使得模块可能同时满足必要ホットアップデート和不必要ホットアップデート的不同プロジェクト需求。

### 云存储集成

GameFrameX Builder サポート多种云存储服务的集成，包括七牛云、腾讯云和阿里云。を通じて统一的インターフェース设计，可能方便地在不同云服务商之间切换。在构建过程中，生成的リソース包和 APK ファイル可能自动上传到指定的云存储空间。

```csharp
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_QI_NIU
    ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<QiNiuYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT
    ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<TencentCloudObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_A_LI_YUN
    ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<ALiYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif
#endif
```
> Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L32-L54)

云存储上传機能を通じて `IObjectStorageUploadManager` インターフェース进行抽象，使用工厂模式作成不同云服务商的具体実装。这种设计遵循了开闭原则，便于未来添加新的云存储サポート。

### 版本管理与通知

Builder 模块提供します完整的版本管理機能。构建完成后，可能自动更新リソース包版本号，并を通じて企业微信发送构建通知。这些機能大大提升了团队协作效率，使得関連人员能够及时了解构建ステータス和版本信息。

```csharp
if (_builderOptions.IsUpdateAssetPackageVersion)
{
    var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
    if (result)
    {
        WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
    }
}
```
> Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L335-L342)

版本更新を通じて HTTP POST お願いします求将构建信息发送到指定的服务器，而微信通知则使用企业微信的 Webhook インターフェース发送 Markdown 格式的构建报告。

## 构建フロー

GameFrameX Builder 的构建フロー分为多个阶段，每个阶段都有明确的目标和职责。以下是完整的构建フロー图：

```mermaid
flowchart TD
    Start([开始构建]) --> ParseArgs[解析命令行参数]
    ParseArgs --> Validate{验证必要参数}
    Validate -->|失败| Error1[抛出異常]
    Validate -->|成功| ExecuteMethod{执行メソッド判断}
    
    ExecuteMethod -->|BuildReady| Phase1[构建准备阶段]
    ExecuteMethod -->|BuildAsset| Phase2[资产生成阶段]
    ExecuteMethod -->|BuildApk| Phase3[APK打包阶段]
    
    Phase1 --> HybridCLR{HybridCLR<br/>サポート?}
    HybridCLR -->|是| InstallHC[安装/更新HybridCLR]
    HybridCLR -->|否| Refresh1[刷新AssetDatabase]
    InstallHC --> Refresh1
    Refresh1 --> Generate[生成热更代码]
    Generate --> UploadLog1{上传日志?}
    UploadLog1 -->|是| UploadLogFile1[上传日志ファイル]
    UploadLog1 -->|否| Phase1End[准备阶段完成]
    UploadLogFile1 --> Phase1End
    
    Phase2 --> CopyHotfix[复制热更代码]
    CopyHotfix --> CopyAOT[复制AOT代码]
    CopyAOT --> BuildBundle[构建リソース包]
    BuildBundle --> UploadLog2{上传日志?}
    UploadLog2 -->|是| UploadLogFile2[上传日志ファイル]
    UploadLog2 -->|否| CheckAsset{上传リソース?}
    UploadLogFile2 --> CheckAsset
    CheckAsset -->|是| UploadBundle[上传リソース包]
    CheckAsset -->|否| CheckVersion{更新版本?}
    UploadBundle --> CheckVersion
    CheckVersion -->|是| UpdateVersion[更新版本号]
    CheckVersion -->|否| Phase2End[构建阶段完成]
    UpdateVersion --> Notify{发送微信通知?}
    Notify -->|是| SendNotify[发送微信通知]
    Notify -->|否| Phase2End
    SendNotify --> Phase2End
    
    Phase3 --> BuildAndroid[构建Android APK]
    BuildAndroid --> UploadApk{上传APK?}
    UploadApk -->|是| UploadAPKFile[上传APKファイル]
    UploadApk -->|否| CheckLog3{上传日志?}
    UploadAPKFile --> CheckLog3
    CheckLog3 -->|是| UploadLogFile3[上传日志ファイル]
    CheckLog3 -->|否| Phase3End[打包阶段完成]
    UploadLogFile3 --> Phase3End
    
    Phase1End --> End([构建结束])
    Phase2End --> End
    Phase3End --> End
    Error1 --> End
```

从フロー图中可能看出，Builder 模块サポート三种主要的构建メソッド：构建准备（BuildReady）、资产生成（BuildAsset）和 APK 打包（BuildApk）。每种メソッド都可能独立运行，也可能按顺序组合使用以完成完整的构建フロー。

## 設定选项

BuilderOptions クラス定义了所有可用的构建参数，这些参数を通じて命令行传递给构建系统。以下是主要的配置选项：

| 选项 | クラス型 | 默认值 | 説明 |
|------|------|--------|------|
| ExecuteMethod | string | - | **必須**。指定要执行的构建メソッド（BuildReady、BuildAsset、BuildApk） |
| BuildNumber | string | - | **必須**。构建编号，に使用版本追踪 |
| JobName | string | - | 任务名称，に使用区分不同的构建任务 |
| PackageName | string | "DefaultPackage" | リソース包名称 |
| ChannelName | string | "default" | 渠道名称，に使用多渠道打包 |
| BundleId | string | - | 包名，为空时使用プロジェクト默认包名 |
| AppVersion | string | - | 程序版本号，为空时使用プロジェクト默认版本 |
| IsIncrementalBuildPackage | bool | false | 是否使用增量构建 |
| IsUploadAsset | bool | false | 是否上传リソース包到云存储 |
| IsUploadApk | bool | false | 是否上传 APK 到云存储 |
| IsUploadLogFile | bool | false | 是否上传日志ファイル到云存储 |
| IsUpdateAssetPackageVersion | bool | false | 是否更新リソース包版本 |
| UpdateAssetPackageVersionUrl | string | - | 版本更新服务器的 URL |
| UpdateAssetPackageVersionAuthorization | string | - | 版本更新お願いします求的授权信息 |
| WeChatBotKey | string | - | 企业微信机器人的 Key |
| Language | string | "default" | 多语言配置 |

## 使用シーン

GameFrameX Builder 适に使用多种ゲーム开发和发布シーン：

**持续集成环境**：在 Jenkins、GitLab CI 或 GitHub Actions 中配置自动化构建任务，当代码提交或合并到主分支时自动触发构建フロー。Builder 的命令行インターフェース可能方便地与这些 CI 系统集成，実装全自动化的构建和发布。

**多渠道打包**：を通じて配置不同的 ChannelName 和 PackageName 参数，可能快速生成针对不同渠道的ゲーム包。这种能力对于必要在多个平台或渠道发布ゲーム的プロジェクト尤为重要。

**ホットアップデート发布**：结合 HybridCLR ホットアップデート機能，可能在不重新发布ゲーム的情况下更新ゲーム内容。Builder 自动处理ホットアップデート代码的复制和打包，简化了ホットアップデート的发布フロー。

**版本管理**：を通じて版本更新和微信通知機能，团队成员可能及时了解每次构建的结果和变更内容，提高协作效率。
