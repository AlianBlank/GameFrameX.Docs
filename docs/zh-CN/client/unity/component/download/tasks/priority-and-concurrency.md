# 设置下载优先级与并发代理数

本任务页面讲解如何为下载任务设置**优先级**,以及如何调整组件的**下载代理(并发协程)数量**,从而控制同时下载的任务上限。

## 前置条件

- 已引入 `GameFrameX.Download.Runtime` 并在场景挂载 `DownloadComponent`(菜单:GameFrameX / Download)。
- 知道目标下载任务的本地保存路径(`downloadPath`)与远端地址(`downloadUri`)。

## 操作步骤

### 1. 设置单个任务的优先级

`DownloadComponent.AddDownload` 提供多个重载,接受 `priority` 参数(`int`,数值越大优先级越高,默认 `0`)。最常用的两个:

```csharp
using GameFrameX.Download.Runtime;

// 仅指定优先级
int serialId = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, priority: 100);

// 同时指定 tag 与优先级
int serialId2 = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, tag: "asset-bundle", priority: 100);
```

源码:

```csharp
// Runtime/Download/DownloadComponent.cs

    return AddDownload(downloadPath, downloadUri, null, priority, null);
```

### 2. 配置并发代理数

并发下载能力由 `DownloadComponent.m_DownloadAgentHelperCount` 决定,默认 `3`,表示同时最多有 3 个下载协程在工作。需要在 Inspector 中调整,或者通过代码在运行时扩展:

- **Inspector**:挂载组件后,Inspector 中直接修改 `Download Agent Helper Count` 字段(对应 `m_DownloadAgentHelperCount`)。组件 `Start()` 时会按该数值一次性创建代理。
- **运行时追加**:如需动态增加,可继续调用组件的内部入口或自定义基于 `DownloadAgentHelperBase` 的扩展(参考 [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs))。

源码(创建代理):

```csharp
// Runtime/Download/DownloadComponent.cs
[SerializeField] private int m_DownloadAgentHelperCount = 3;
...
private void Start()
{
    ...
    for (int i = 0; i < m_DownloadAgentHelperCount; i++)
    {
        AddDownloadAgentHelper(i);
    }
}
```

## 常见变体

- **关键资源优先**:首屏资源用较高 `priority`(如 `100`),后台预下载用 `0` 或负数。
- **暂停与恢复**:通过 `DownloadComponent.Paused = true/false` 临时停掉新任务下发,代理不会被打断。
- **修改 `m_DownloadAgentHelperCount` 立即生效**:仅当数值变大时,组件启动时就会预创建全部代理;运行中减小不会销毁已存在代理,需结合自定义逻辑回收。

## 常见错误

- **混淆"并发协程"与"并发线程"**:下载代理是 `UnityWebRequest` 协程,数值只控制同时进行的 HTTP 请求数,与线程无关;在 WebGL 等受限平台上不要设置过大。
- **任务被卡住不开始**:`WaitingTaskCount` 持续增长而 `FreeAgentCount` 恒为 0 时,说明并发数过小或任务网络较慢——可适当调高 `m_DownloadAgentHelperCount`。
- **未指定优先级即认为高优**:`DefaultPriority = 0`,若其他任务给了负值,你的"默认"任务反而会被排在后面。

## 背景(可选)

下载管理器内部使用 `TaskPool<DownloadTask>` 调度任务(`[DownloadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs)`)。优先级高的任务会优先获得空闲代理,从而控制网络出口的占用顺序。
