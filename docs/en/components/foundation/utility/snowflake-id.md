# How to Use Snowflake to Generate Distributed Unique IDs

With just one line, `SnowFlakeIdHelper.Instance.NextId()` generates a globally unique, monotonically increasing 64-bit integer ID, and the ID can be decoded back into its timestamp, WorkerId, DataCenterId, and sequence number when needed.

## Prerequisites

- Reference the namespace: `GameFrameX.Foundation.Utility.DistributedSystem.Snowflake`
- The project already references the `GameFrameX.Foundation.Utility` assembly
- For multi-instance deployments, each node must be configured with a distinct `WorkId` (0~31) and `DataCenterId` (0~31); otherwise, duplicate IDs will be generated

## Steps

1. **Simplest usage: generate an ID directly from the singleton**

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   long id = SnowFlakeIdHelper.Instance.NextId();
   ```

   `Instance` is internally a double-checked locking singleton; on first access, it initializes `IdWorker` with the current `WorkId=1`, `DataCenterId=1`, and `BaseTime=2025-01-01 UTC`.
   Source: [SnowFlakeIdHelper.cs#L181-L204](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L181-L204)

2. **Manually specify node IDs (single instance or testing)**

   Must be set **before** the first access to `Instance`; otherwise it will not take effect.

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   SnowFlakeIdHelper.WorkId = 2;
   SnowFlakeIdHelper.DataCenterId = 3;
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L133-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L133-L145)

3. **Use a WorkerIdProvider to automatically assign node IDs**

   The framework provides built-in strategies based on hostname, IP, process ID, and so on; simply inject one before the first access to `Instance`.

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   // Example: derive WorkId (0~31) automatically from an IP hash
   SnowFlakeIdHelper.SetWorkerIdProvider(new IpAddressWorkerIdProvider());
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L97-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L97-L100)

4. **(Optional) Modify the base time or bit widths**

   When the default `2025-01-01 UTC` starting point needs adjustment, or you want to customize the WorkerId/sequence bit widths, modify them before the first access:

   ```csharp
   SnowFlakeIdHelper.BaseTime = new DateTime(2020, 1, 1, 0, 0, 0, DateTimeKind.Utc).Ticks / 10000;
   SnowFlakeIdHelper.WorkerIdBits = 5;        // Default: 5
   SnowFlakeIdHelper.DatacenterIdBits = 5;    // Default: 5; can be set to 0 to disable the datacenter dimension
   SnowFlakeIdHelper.SequenceBits = 12;       // Default: 12; at most 4096 IDs per millisecond
   ```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Different machines/processes generate duplicate IDs | Both sides use the same `WorkId` or `DataCenterId` | Use `SetWorkerIdProvider` for automatic assignment, or configure a unique number for each machine |
| Adjustments to `WorkId` / `BaseTime` / bit widths have no effect | `Instance` has already been accessed somewhere and the singleton has been created | Complete configuration early at program startup, before any calls, or use separate `IdWorker` instances across tests |
| Abnormal timestamp when parsing old IDs | The wrong `BaseTime` or bit widths were used | Explicitly pass the same `baseTimeMs` and `workerIdBits`/`datacenterIdBits`/`sequenceBits` used at generation time |
| `Parse` throws `ArgumentOutOfRangeException` | The ID is negative | Snowflake IDs must be non-negative; check whether other ID types are being mixed in |
| Generation blocks or throws errors due to system clock rollback | The Snowflake algorithm is sensitive to clock rollback | Ensure NTP synchronization; on rollback, use a custom `IdWorker` to catch `InvalidSystemClock` instead of throwing errors directly |

## Background (Optional)

The default bit layout is `1 符号位 | 41 时间戳位 | 5 数据中心位 | 5 工作节点位 | 12 序列号位`, allowing a single node to generate up to 4096 IDs per millisecond. The base time is set to `2025-01-01 UTC`, which provides about 69 years of usage with a 41-bit timestamp. `SnowFlakeIdParser` uses exactly the same bitwise formulas, so as long as `BaseTime` and the bit widths match, an ID can be decoded losslessly. For a comparison with other distributed ID solutions, see "Distributed ID Selection".
