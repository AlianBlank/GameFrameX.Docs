# GameApp.{Name} 접근 시 null이 반환되거나 null 참조 오류가 발생하면 어떻게 하나요

`GameApp.XXX`(예: `GameApp.Asset`, `GameApp.Base`)에 접근할 때 `null`이 반환되거나 `NullReferenceException`이 발생하는 것은, 대개 해당 컴포넌트가 시작 시점에 `GameEntry`에 등록되지 않았거나, 프레임워크 초기화 전에 속성을 호출했기 때문입니다. `GameApp`은 단지 `GameEntry.GetComponent<T>()`에 대한 캐싱 래퍼일 뿐이며, 실제 컴포넌트 인스턴스는 `GameEntry`가 관리합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `GameApp.XXX`가 `null` 반환 | 해당 컴포넌트가 `GameEntry`에 등록되지 않았거나, 해당 매크로/조건부 컴파일이 활성화되지 않음 | 컴포넌트 클래스가 `GameEntry` 시작 프리팹/등록 프로세스에 추가되어 있는지 확인하고, 해당 매크로(예: `ENABLE_GAME_FRAME_X_ASSET`)를 활성화하세요 |
| `Awake`/`Start` 초반에 `GameApp.XXX`에 접근하면 null 오류 발생 | 프레임워크 초기화가 완료되지 않음 | 프레임워크 초기화 완료 콜백(예: `GameEntry.OnGameFrameInitialized`) 이후에 호출하도록 변경하거나, 비즈니스 스크립트의 `OnEnable` 이후에 호출하세요 |

| `KeyNotFoundException` 발생 / 컴포넌트 타입을 찾을 수 없음 | 컴포넌트 DLL/어셈블리가 프로젝트에 포함되지 않았거나, 네임스페이스가 일치하지 않음 | 컴포넌트가 속한 어셈블리가 참조되어 있는지 확인하고, `using GameFrameX.Runtime;`을 추가하세요 |
| 매크로를 활성화/비활성화한 후 갑자기 null이 됨 | 컴포넌트가 `#if` 조건부 컴파일에 의해 전체 제외되어 `GameApp.XXX` 필드가 존재하지 않음 | `#if` 블록 밖에서는 해당 속성에 접근하지 말고, 대신 `GameEntry.GetComponent<T>()`를 폴백으로 사용하세요 |

## 수정 단계

### 1. 컴포넌트가 GameEntry에 등록되었는지 확인

`GameApp`의 구현은 본질적으로 `GameEntry`에서 지연 방식으로 컴포넌트를 가져오는 것입니다:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }

    private static BaseComponent _base;
}
```

출처: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L52)

`GameEntry.GetComponent<BaseComponent>()`가 컴포넌트를 찾지 못하면 `_base`는 `null` 상태로 유지됩니다. 시작 프로세스에서 `BaseComponent` 등의 컴포넌트가 `GameEntry`의 초기화 목록에 추가되어 있는지 확인하세요.

### 2. 조건부 컴파일 매크로 확인

많은 `GameApp.XXX`는 매크로로 감싸져 있습니다. 예를 들어 `GameApp.Asset`는 `ENABLE_GAME_FRAME_X_ASSET` 매크로가 필요합니다:

```csharp
#if ENABLE_GAME_FRAME_X_ASSET
public static partial class GameApp
{
    public static AssetComponent Asset
    {
        get
        {
            if (_asset == null)
            {
                _asset = GameEntry.GetComponent<AssetComponent>();
            }
            return _asset;
        }
    }

    private static AssetComponent _asset;
}
#endif
```

출처: [Runtime/GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs#L32-L55)

해당 매크로가 정의되어 있지 않으면 이 `GameApp.Asset` 속성은 컴파일 시점에 존재하지 않아 직접 접근 시 컴파일 오류가 발생합니다. 반대로, **매크로를 활성화했고 코드에서 해당 `GameApp.XXX`를 사용한다면, 해당 컴포넌트도 `GameEntry`에 등록되어 있어야 합니다**.

### 3. 프레임워크 초기화 완료 후에 접근

`GameApp`의 필드는 지연 로딩되는 정적 캐시입니다. 프레임워크 `Awake` 이전의 라이프사이클(예: 다른 싱글턴의 `Awake`)에서 접근하면 컴포넌트가 아직 등록되지 않았을 수 있습니다. 프레임워크 초기화 완료 이벤트가 발생한 후에 접근하거나, 비즈니스 스크립트의 `OnEnable` / `Start`에서 접근하세요.

### 4. null 체크 보호 추가

등록되어 있더라도 호출 전에 null 체크를 하는 것이 좋습니다. 에디터에서 게임이 중지되거나 리소스가 해제되는 단계에서의 접근을 방지할 수 있습니다:

```csharp
if (GameApp.Asset != null)
{
    GameApp.Asset.LoadAsset(...);
}
```

null 체크가 자주 필요하다면, 해당 컴포넌트를 원래 이곳에서 사용하지 말아야 한다는 뜻입니다 — 단계 1로 돌아가 등록을 확인하세요.

## 검증

아래 3단계를 실행하여 문제가 해결되었는지 확인하세요:

1. `Awake`에서 `GameApp.Base` 등 주요 속성을 출력하여 `null`이 아닌지 확인합니다.
2. `GameEntry.GetComponent<T>()`를 통해 컴포넌트가 존재하는지 재확인합니다.
3. 씬에서 실제 호출을 한 번 수행하여(예: 리소스 하나 로드, 이벤트 한 번 발생) null 참조가 여전히 발생하는지 관찰합니다.

`GameEntry.GetComponent<T>()`가 계속 `null`을 반환한다면, 문제는 `GameApp` 계층이 아니라 컴포넌트 등록 프로세스 자체에 있다는 뜻입니다 — `GameEntry`의 초기화 코드로 돌아가 컴포넌트 마운트와 라이프사이클 순서를 점검하세요.
