# luban.conf の理解と変更方法

`luban.conf` は GameFrameX.Config のマスター設定ファイルです。Luban ツールチェーンに対して、どこで Excel を読み込み、どのデータ/コードターゲットを使用し、生成物をどのディレクトリに出力するかを指示します。このファイルを修正した後、`gen-*.bat` / `gen-*.sh` を実行するだけで、新しいルールに従ってクライアントとサーバーのコードを生成できます。

## 前提条件

- [GameFrameX/GameFrameX.Config](https://github.com/GameFrameX/GameFrameX.Config) リポジトリをクローン済みであり、ルートディレクトリに `luban.conf` が存在すること。
- .NET ランタイムがインストール済みであること(`Tools/Luban.exe` の実行に使用)。
- `groups`(クライアント/サーバーのデータグループ)、`targets`(生成ターゲット)、`commands`(実行するコマンド)という 3 つのトップレベル概念を理解していること。

## トップレベルフィールドの概要

| フィールド | 役割 | 典型的な値 |
|------|------|--------|
| `groups` | テーブルを「クライアント/サーバー」ごとにグループ化し、生成時にグループ単位でフィルタリングする | `c`(クライアント)、`s`(サーバー) |
| `schemaFiles` | Luban がロードする schema のエントリ(`Defines`、`__tables__` など) | 下記のコードブロックを参照 |
| `dataDir` | Excel データのルートディレクトリ | `Excels` |
| `targets` | 生成ターゲットの集合。各ターゲットは一式のコード/データ生成物に対応する | `server`、`client`、`all` |
| `toolPath` | Luban.dll の相対パス | `/../Config/Tools/Luban.dll` |
| `UNITY_ASSETS_PATH` | Unity プロジェクトの Assets ディレクトリの絶対パス(実行時テンプレート) | 空欄のまま。スクリプト実行時に置換される |
| `SERVER_PATH` | サーバープロジェクトのルートディレクトリの絶対パス(実行時テンプレート) | 空欄のまま。スクリプト実行時に置換される |
| `commands` | 各生成コマンドが 1 つの target に対応し、コマンドライン引数とスイッチを含む | 下記のコードブロックを参照 |

出典: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L95)

## 主要フィールドのセクション別解説

### 1. groups:データの振り分け方法

`groups` は、各テーブルが「クライアント」「サーバー」「両端で共有」のいずれに属するかを決定します。`default: true` は、そのグループのすべてのテーブルがデフォルトで生成コマンドの対象になることを意味します。

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

出典: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

> 各テーブルがどのグループに属するかは、Excel 内で `__xxx__` マーク列によって示されます。ここでは「どのグループ名が存在するか」のみを定義します。

### 2. schemaFiles:ロードする定義

`schemaFiles` は Luban が schema を読み込むためのエントリです。順序は問いませんが、次の 4 行は必須です:`Defines`(組み込み型ディレクトリ)、`__tables__.xlsx`(テーブル一覧)、`__beans__.xlsx`(複合構造)、`__enums__.xlsx`(列挙型)。

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

出典: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

### 3. targets:生成ターゲットの定義

各 target は「データ一式 + 生成物一式」の名前付きパッケージです。`topModule` は生成される名前空間、`manager` はエントリクラス名です(実行時に `TablesComponent` または `Tables` シングルトンでロードします)。

```json
"targets": [
    { "name": "server", "manager": "TablesComponent", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "manager": "TablesComponent", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "manager": "Tables",         "groups": ["c","s"], "topModule": "cfg" }
]
```

出典: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L35-L61)

### 4. commands:実行する生成コマンド

`commands` は実際に `Luban.exe` に渡されるコマンドラインの配列です。各レコードは 1 つの `target` に紐付けられ、`active: true/false` で有効/無効を切り替えます。`%UNITY_ASSETS_PATH%` と `%SERVER_PATH%` はプレースホルダーであり、生成スクリプトが呼び出し前に絶対パスへ置き換えます。

```json
"commands": [
    {
        "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
        "target": "server", "active": true
    },
    {
        "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate",
        "target": "client", "active": true
    }
]
```

出典: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

よく使うスイッチ:

- `--dataTarget json | bin` ―― データの保存形式。`json` は可読性が高く、`bin` はサイズが小さい。
- `--codeTarget cs-simple-json | cs-dotnet-json | cs-bin` ―― 生成される C# ロードコードのスタイル。クライアントには `cs-simple-json`、サーバーには `cs-dotnet-json`、バイナリを有効にする場合は `cs-bin` を使用。
- `--validationFailAsError true` ―― 検証失敗時に警告のみでなく、即座にエラーとして扱う。
- `--xargs outputDataDir=...` / `--xargs outputCodeDir=...` ―― データとコード生成物の出力ディレクトリ。`%SERVER_PATH%`、`%UNITY_ASSETS_PATH%` のプレースホルダーをサポート。

## よくあるバリエーション

### グループを追加する(例：多言語サブクライアント)

`groups` 配列に項目を 1 つ追加します。その際、テーブルヘッダーの `__xxx__` 列で該当テーブルに新しいグループ名を付けることを忘れないでください。

```json
{ "names": ["c"], "default": true },
{ "names": ["s"], "default": true },
{ "names": ["c_cn"], "default": true }
```

出典: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

### JSON とバイナリ生成物の切り替え

該当する command 内の `--dataTarget json --codeTarget cs-simple-json`(または `cs-dotnet-json`)を `--dataTarget bin --codeTarget cs-bin` に置き換え、`active` を `true` に設定します。

### 出力ディレクトリの変更

`commands[].command` 内の `outputDataDir` / `outputCodeDir` を直接修正します。スクリプト内の統一されたパスを再利用したい場合は、`%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` のプレースホルダーをそのまま残してください。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `gen-*.bat` 実行時に `ToolPath not found` と表示される | `toolPath` の相対パスの記述が誤っている、または `Tools/Luban.dll` がリポジトリ内に存在しない | デフォルトの `/../Config/Tools/Luban.dll` を維持し、`Tools/` ディレクトリを移動しない |
| 生成されたコードで名前空間が見つからない | `targets[].topModule` のスペルミス。クライアントとサーバーの `topModule` は異なっている必要がある | クライアントは `Hotfix.Config`、サーバーは `GameFrameX.Config`。自身の名前空間に合わせて修正する |
| クライアントプロジェクトにコードが生成されない | クライアント target の `groups` に、このテーブルが属するグループが含まれていない | `targets[client].groups` に該当するグループ名を追加するか、テーブルの `__xxx__` 列を調整する |
| `commands` 内の `active` がすべて `false` | すべてのコマンドが無効化されている | 実行したいコマンドを `true` に変更する |
| プレースホルダー `%UNITY_ASSETS_PATH%` が置き換えられない | `gen-*.bat` / `gen-*.sh` を経由せず、`Luban.exe` を直接ダブルクリックして実行した | リポジトリ付属の生成スクリプトから実行する。スクリプトがプレースホルダーの置換を行う |

## 背景(任意)

`luban.conf` の schema は Luban ツールチェーンによって規定されており、フィールドの意味は Luban 公式と同一です。本リポジトリでは、`toolPath`、`UNITY_ASSETS_PATH`、`SERVER_PATH`、`commands[].active` の 4 つのフィールドを追加拡張しており、GameFrameX のワークフロー内で `gen-*.bat` / `gen-*.sh` を通じて生成コマンドとプレースホルダー置換を一元的に制御するために使用されます。
