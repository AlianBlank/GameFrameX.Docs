# "Localization manager is invalid / Base component is invalid" 怎么办

这两条 Fatal 日志分别来自 `LocalizationComponent` 的 `Awake()` 与 `Start()`:`Awake()` 里通过 `GameFrameworkEntry.GetModule<ILocalizationManager>()` 取不到本地化管理器模块,或 `Start()` 里通过 `GameEntry.GetComponent<BaseComponent>()` 找不到 Base 组件时打印,随后组件直接 `return`,本地化功能不工作。绝大多数情况是"本地化实现程序集未随包编译/被裁剪"或"场景里缺少 GameFrameX 基础组件",按下方诊断表逐条排查即可恢复。

## 快速诊断

| 症状(控制台原文) | 出现位置 | 原因 | 修复 |
|------|------|------|------|
| `Localization manager is invalid.` | `Awake()`,取模块失败 | 本地化模块实现(如 `LocalizationManager`)所在的程序集没有编译进项目,或被 GameFrameX 裁剪配置剔除 | 见下方 [修复步骤 1:确认实现程序集存在](#步骤-1确认实现程序集存在) |
| `Base component is invalid.` | `Start()`,取 Base 组件失败 | 场景中的 GameFrameX 根对象上缺少 `BaseComponent`,或脚本编译错误导致组件丢失(Missing Script) | 见下方 [修复步骤 2:补齐 BaseComponent](#步骤-2补齐-basecomponent) |
| `Event component is invalid.` | `Start()` | 同根对象缺少 `EventComponent` | 与步骤 2 相同方式补齐 |
| `Setting component is invalid.` | `Start()` | 同根对象缺少 `SettingComponent` | 与步骤 2 相同方式补齐 |
| `Can not create localization helper.` | `Start()` | `m_LocalizationHelperTypeName` 指向的默认助手类型 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` 不存在,或自定义 Helper 类型名写错 | 见下方 [修复步骤 3:核对本地化 Helper](#步骤-3核对本地化-helper) |

## 修复步骤

### 步骤 1:确认实现程序集存在

`LocalizationComponent.Awake()` 中用接口类型取模块:

```csharp
m_LocalizationManager = GameFrameworkEntry.GetModule<ILocalizationManager>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L216)

`GetModule` 返回 null 意味着 `ILocalizationManager` 的具体实现类(`LocalizationManager`)没有被注册到 `GameFrameworkEntry`,通常是它所在的实现程序集没有参与编译。依次检查:

1. 打开 Unity Console,先清除所有 **编译错误(Compiler Error)**——存在编译错误时 Unity 会跳过部分程序集编译,模块注册随之丢失,这是最常见的诱因。
2. 确认本包 `Runtime` 目录下的运行时 asmdef(`GameFrameX.Localization`)已导入且未被移除;本包组件声明为 `[RequireComponent(typeof(GameFrameXLocalizationCroppingHelper))]`,若 Inspector 里出现 Missing Script,说明运行时程序集缺失或未编译成功。
3. 若项目启用了 GameFrameX 的组件裁剪/模块移除机制,确认本地化模块没有被剔除。

### 步骤 2:补齐 BaseComponent

`Base component is invalid.` 的判定依据是 `Start()` 中的查找:

```csharp
BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227)

1. 在场景中挂载 `LocalizationComponent` 的同一 GameFrameX 根对象上,确认存在 `BaseComponent`(以及 `EventComponent`、`SettingComponent`,`Start()` 同样依赖它们)。
2. 若 Inspector 中显示 "Missing (Mono Script)",说明对应脚本未编译或程序集缺失——回到步骤 1 清除编译错误。
3. 不要手工在多个对象上分散挂载这些组件;`GameEntry.GetComponent<T>()` 期望它们在框架入口上。

### 步骤 3:核对本地化 Helper

`Start()` 里随后会按序列化字段创建 Helper,失败时打印 `Can not create localization helper.`:

```csharp
LocalizationHelperBase localizationHelper = Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper);
if (localizationHelper == null)
{
    Log.Fatal("Can not create localization helper.");
    return;
}
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L254)

在 `LocalizationComponent` 的 Inspector 中核对 `m_LocalizationHelperTypeName`,默认值为完整类型名:

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73)

如果改用了自定义 Helper,要么在 `m_CustomLocalizationHelper` 字段拖入引用,要么保证 `m_LocalizationHelperTypeName` 是"命名空间.类名, 程序集名"形式的完整可解析类型名。

## 验证

1. 重新进入 Play 模式,Console 中不再出现 `Localization manager is invalid.`、`Base component is invalid.` 等上述 Fatal 日志。
2. `Start()` 正常走完会初始化语言:非编辑器模式下当 `Language == UnknownLocalization` 时自动采用 `SystemLanguage`,并最终设置 `DefaultLanguage`(来源见 [LocalizationComponent.cs 第 261-272 行](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L272))。可用 `LocalizationComponent.Language`、`DefaultLanguage`、`DictionaryCount` 断言组件已可用。
3. 调用一次取词接口(如 `GetLocalizedString`/`GetRawString` 家族)能返回字符串而非空,即确认整条链路初始化成功。
