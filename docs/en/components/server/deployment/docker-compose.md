# Deploying the Server with Docker / docker-compose

By following the steps on this page, you can get the GameFrameX server and MongoDB database up and running with `docker-compose` in a few minutes, and achieve persistence of configuration, hot updates, and logs through container volume mounts.

## Prerequisites

- Docker Engine 20.10+ and Docker Compose v2 installed (verify by running `docker compose version` on the command line)
- The following ports are open on the host machine: `27017` (MongoDB), `28080` (HTTP), `29090` (APM), `29100` (TCP), `29110` (WebSocket)
- `Dockerfile` and `docker-compose.yml` exist in the repository root directory (see below)

## Configuration File Structure

The repository root provides two ready-to-use files:

| File | Purpose |
|------|------|
| [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48) | Multi-stage build: compiles the project based on `mcr.microsoft.com/dotnet/sdk:10.0`, runs on `aspnet:10.0`, with the final image entry point being `/app/entrypoint.sh dotnet GameFrameX.Launcher.dll` |
| [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L1-L148) | Defines two services, `mongodb` and `gameframex`, sharing the `gameframex` bridge network, and mounts the host's `./running/*` into the container for persistence |

## Steps

### 1. Prepare Persistence Directories on the Host

`docker-compose.yml` mounts the following host directories into the container (if a directory does not exist, `docker compose` will create it automatically):

| Host Directory | Container Mount Point | Purpose |
|------------|------------|------|
| `./running/database` | `/data/db` | MongoDB data files |
| `./running/hotfix` | `/app/hotfix` | Hot update DLLs |
| `./running/json` | `/app/json` | JSON configuration |
| `./running/logs` | `/app/data/logs` | Application logs |
| `./running/GameAnalytics` | `/GameAnalytics` | Game analytics data |

```bash
mkdir -p running/{database,hotfix,json,logs,GameAnalytics}
```

### 2. Start the Services

Run in the repository root:

```bash
docker compose up -d --build
```

On the first run, the MongoDB image will be pulled and the GameFrameX image built according to the [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L5-L23) (publishing both the `GameFrameX.Launcher` and `GameFrameX.Hotfix` projects). The image startup entry point is written by [entrypoint.sh](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L33-L42):

```sh
#!/bin/sh
if [ -z "$(ls -A /app/hotfix 2>/dev/null)" ]; then
    echo "hotfix directory is empty, copying defaults..."
    cp -r /app/hotfix-default/* /app/hotfix/
fi
if [ -z "$(ls -A /app/json 2>/dev/null)" ]; then
    echo "json directory is empty, copying defaults..."
    cp -r /app/json-default/* /app/json/
fi
exec "$@"
```

> This script ensures that when the host's `./running/hotfix` or `./running/json` is empty, a copy will be made from the defaults built into the image, eliminating manual configuration during initial deployment.

### 3. Verify Service Status

```bash
docker compose ps
docker compose logs -f gameframex
```

The database connection string is configured by default in the compose file:

```yaml
DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
DataBaseName=gameframex
```

After a successful startup, clients can connect via `29100` (TCP), `29110` (WebSocket), and `28080` (HTTP).

## Key Configuration Quick Reference

Common environment variables exposed in [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L14-L139):

| Environment Variable | Default Value | Description |
|----------|--------|------|
| `ServerType` | `Game` | Server type; for multiple processes, separate with commas, e.g., `Game,Social,Chat` |
| `ServerId` | `1000` | Server ID; must be kept consistent when merging servers |
| `InnerPort` / `OuterPort` | `29100` | Internal communication port / external client connection port |
| `HttpPort` | `28080` | HTTP service port |
| `WsPort` | `29110` | WebSocket port (requires `IsEnableWebSocket=true`) |
| `APMPort` | `29090` | APM performance monitoring port |
| `DataBaseUrl` | `mongodb://admin:admin@mongodb:27017/?authSource=admin` | MongoDB connection string |
| `DataBaseName` | `gameframex` | Database name |
| `DiscoveryCenterIp` / `DiscoveryCenterPort` | `127.0.0.1` / `10001` | Service discovery center address |

The remaining commented-out environment variables (such as `IsEnableTcp`, `IsOpenTelemetry`, `LogIsGrafanaLoki`, etc.) retain their default values and can be uncommented as needed.

## Common Variants

- **Single-process mode**: Uncomment line 33 in [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L33-L34), set `IsSingleMode` to `true`, and adjust `ServerType` to a single value.
- **External MongoDB**: Change `DataBaseUrl` to an external address (e.g., `mongodb://user:pass@your-mongo-host:27017/?authSource=admin`) and remove the `mongodb` service block from the compose file.
- **HTTPS / WSS**: Enable the three environment variables `HttpsPort`, `WssPort`, and `WssCertFilePath`, and mount the certificate into the container.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `gameframex` reports `Unable to connect to MongoDB` at startup | The account in `DataBaseUrl` or the `mongodb` service name does not match | Confirm that the account `admin/admin` and the service name `mongodb` match the definitions in the compose file |
| `http://localhost:28080` is inaccessible | The host firewall has not opened the port | Open port 28080, or modify the `ports` mapping in the compose file |
| Hot update files not taking effect | `./running/hotfix` is not mounted or is empty | entrypoint.sh will automatically copy once from the image's default directory; make sure the host directory is writable |
| `dotnet restore` fails during the build stage | Sub-project csproj paths have changed | When modifying the project structure, update the `COPY` lines in the [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L9-L13) accordingly |

## Background (Optional)

The [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48) uses a four-stage build: `base` prepares the runtime image, `build` restores dependencies and compiles, `publish` produces the Launcher and Hotfix artifacts, and `final` copies only the files needed at runtime, keeping the final image lean while providing default value fallbacks for the hot update directories.
