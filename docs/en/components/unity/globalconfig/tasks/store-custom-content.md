# How to Store Custom Additional Content

Through the `GlobalConfigComponent.Content` field, you can persist a custom additional content string in the Inspector or at runtime, and read or modify it at any time.

## Prerequisites

- `GlobalConfigComponent` has been attached to the scene (can be added via the menu `GameFrameX/Global Config`).

## Steps

1. Directly enter a string in the `附加内容` (Additional Content) text box in the Inspector (supports multiple lines, default height 120). This field will be serialized into the scene and read at runtime via the `Content` property.

```csharp
// Runtime/GlobalConfig/GlobalConfigComponent.cs
[SerializeField] private string m_content = string.Empty;

public string Content
{
    get => m_content;
    set => m_content = value;
}
```

Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L81-L93)

2. Set or read via code at runtime:

```csharp
var component = UnityEngine.Object.FindObjectOfType<GameFrameX.GlobalConfig.Runtime.GlobalConfigComponent>();

// Set additional content
component.Content = "{\"key\":\"value\"}";

// Read additional content
string data = component.Content;
```

3. If you need to visualize this field in the Inspector, confirm that the custom inspector has drawn `m_content`:

```csharp
// Editor/Inspector/GlobalConfigComponentInspector.cs
m_Content = serializedObject.FindProperty("m_content");
...
EditorGUILayout.PropertyField(m_Content, m_ContentGUIContent, GUILayout.Height(120));
```

Source: [GlobalConfigComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Editor/Inspector/GlobalConfigComponentInspector.cs#L19-L38)

4. If the additional content comes from a server response, it can be carried via the `ResponseGlobalInfo.Content` field, then written to the component:

```csharp
// Runtime/GlobalConfig/ResponseGlobalInfo.cs
public class ResponseGlobalInfo
{
    public string Content { get; set; }
}
```

Source: [ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L24-L26)

## Common Variants

- **Storing a JSON string**: Treat `Content` as a JSON container, and deserialize it yourself using `JsonUtility.FromJson<T>`.
- **Storing AOT assembly list**: Similar to additional content, use the `AOTCodeList` (string) or `AOTCodeLists` (`List<string>`) field, the latter is automatically parsed by the setter.
- **Writing from the server**: Write the original string via `SetOriginalData(string)`; passing in `null` will throw an `ArgumentNullException`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Null reference reported after setting `Content = null` | The field type is `string` with no null check | Ensure non-null before writing, or handle null values yourself |
| `AOTCodeList` parsing failed | JSON format error | Check the `Log.Error(e)` output in the catch block to fix the JSON |
| Modifying `Content` at runtime has no effect | In play mode and the field is disabled | The field is read-only when playing in the editor; you need to exit play mode to modify it |

## Background (Optional)

`Content` and `OriginalData` are two independent channels: `Content` is used for business-defined custom additional content (editable in the Inspector), while `OriginalData` is the server's original data (writable only via code). Both are strings, and the serialization format is defined by the caller.
