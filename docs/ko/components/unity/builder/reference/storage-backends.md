# 지원되는 객체 스토리지 백엔드 빠른 참조

이 페이지에는 `com.gameframex.unity.builder`에서 현재 내장으로 지원하는 세 가지 객체 스토리지 백엔드(Qiniu Cloud, Tencent Cloud COS, Alibaba Cloud OSS), 각각에 대응되는 Unity 패키지명, 매크로 정의, 업로드 관리자 타입, 그리고 공통으로 사용되는 네 가지 커맨드라인 인수를 정리합니다.

## 백엔드 빠른 참조 표

| 백엔드 | 의존하는 Unity 패키지명 | 자동 정의되는 매크로 | 업로드 관리자 타입 | 네임스페이스 |
|------|------------------|--------------|----------------|----------|
| Qiniu Cloud | `com.gameframex.unity.objectstorage.qiniu` | `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_QI_NIU` | `QiNiuYunObjectStorageUploadManager` | `GameFrameX.ObjectStorage.QiNiu.Editor` |
| Tencent Cloud COS | `com.gameframex.unity.objectstorage.tencent` | `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT` | `TencentCloudObjectStorageUploadManager` | `GameFrameX.ObjectStorage.Tencent.Editor` |
| Alibaba Cloud OSS | `com.gameframex.unity.objectstorage.aliyun` | `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_A_LI_YUN` | `ALiYunObjectStorageUploadManager` | `GameFrameX.ObjectStorage.ALiYun.Runtime` |
| 공통 기반 패키지(필수) | `com.gameframex.unity.objectstorage` | `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` | 인터페이스 `IObjectStorageUploadManager` | `GameFrameX.ObjectStorage.Editor` |

매크로는 어셈블리 정의 파일의 `versionDefines`에 의해 자동으로 주입됩니다. `Packages/manifest.json`에 해당 패키지가 설치되어 있으면 매크로가 활성화되며, Player Settings에서 수동으로 추가할 필요가 없습니다:

## 백엔드 선택 로직 빠른 참조

세 백엔드는 `Builder` 정적 생성자에서 순차적으로 `#if`로 판단하여 생성되며, **상호 배타적인 `else if`가 아니므로** 뒤쪽의 할당이 앞쪽을 덮어씁니다. 적용 우선순위는 낮은 순서부터: Qiniu Cloud → Tencent Cloud → Alibaba Cloud.

```csharp
static Builder()
{
    BuildParamsParse();
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_QI_NIU
    ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<QiNiuYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT
    ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<TencentCloudObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_A_LI_YUN
    ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<ALiYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif
    ObjectStorageUploadManager.SetSavePath($"builder/{PlayerSettings.productName}/{EditorUserBuildSettings.activeBuildTarget.ToString()}/{_builderOptions.JobName}/{Application.version}/{_builderOptions.BuildNumber}");
#endif
}
```

> Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L32-L49)

**결론**: 동일한 프로젝트에서는 하나의 백엔드 패키지만 설치하세요. 그렇지 않으면 실제 업로드 대상이 생각한 것과 다를 수 있습니다.

## 인증 정보 인수 빠른 참조

네 가지 인증 정보 인수는 모든 백엔드에 공통이며, 모두 `BuilderOptions`를 통해 전달되고 기본값은 `string.Empty`입니다.

| 속성 | 타입 | 기본값 | 의미 |
|------|------|--------|------|
| `ObjectStorageKey` | `string` | `string.Empty` | 객체 스토리지의 Key(AccessKey / SecretId) |
| `ObjectStorageSecret` | `string` | `string.Empty` | 객체 스토리지의 비밀 키(SecretKey) |
| `ObjectStorageBucketName` | `string` | `string.Empty` | 객체 스토리지 버킷의 이름 |
| `ObjectStorageEndPoint` | `string` | `string.Empty` | 객체 스토리지 버킷의 리전 이름 / 액세스 포인트 |

```csharp
/// <summary>
/// 객체 스토리지의 Key
/// </summary>
public string ObjectStorageKey { get; set; } = string.Empty;

/// <summary>
/// 객체 스토리지의 비밀 키
/// </summary>
public string ObjectStorageSecret { get; set; } = string.Empty;

/// <summary>
/// 객체 스토리지 버킷의 이름
/// </summary>
public string ObjectStorageBucketName { get; set; } = string.Empty;

/// <summary>
/// 객체 스토리지 버킷의 리전 이름
/// </summary>
public string ObjectStorageEndPoint { get; set; } = string.Empty;
```

> Source: [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40)

해당하는 커맨드라인 인수명은 속성과 동일합니다. 예를 들어:

```text

```

## 업로드 경로 및 업로드 시점 빠른 참조

| 항목 | 값 / 트리거 조건 |
|------|---------------|
| 원격 저장 경로 템플릿 | `builder/{PlayerSettings.productName}/{activeBuildTarget}/{JobName}/{Application.version}/{BuildNumber}` |
| 경로 설정 호출 | `ObjectStorageUploadManager.SetSavePath(...)`, `Builder` 정적 생성자 끝에서 한 번 실행 |
| APK 업로드 | `_builderOptions.IsUploadApk`가 `true`일 때, `BuildApk()` 내부에서 `UploadFile(apkPath)` 호출 |
| 로그 업로드 | `_builderOptions.IsUploadLogFile`(기본값 `false`)이 `true`일 때, `UploadFile(_builderOptions.LogFilePath)` 호출 |

```csharp
public static void BuildApk()
{
    var apkPath = BuildProductHelper.BuildPlayerAndroid();
    if (_builderOptions.IsUploadApk)
    {
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
        ObjectStorageUploadManager.UploadFile(apkPath);
#endif
    }

    if (_builderOptions.IsUploadLogFile)
    {
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
        ObjectStorageUploadManager.UploadFile(_builderOptions.LogFilePath);
#endif
    }
}
```

## 객체 스토리지가 활성화되지 않았을 때 동작

`com.gameframex.unity.objectstorage`가 설치되어 있지 않으면 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`가 정의되지 않으며, `IObjectStorageUploadManager` 관련 모든 필드와 업로드 호출은 조건부 컴파일에 의해 제거됩니다. 빌드流程은 정상적으로 실행되지만 업로드 동작은 발생하지 않습니다.

어셈블리 참조 측에서는 세 백엔드의 Editor 어셈블리를 동시에 선언하고 있으며, 패키지가 없을 때는 Unity의 선택적 참조 메커니즘에 의해 무시됩니다:

```json
"references": [
  "GameFrameX.Runtime",
  "GameFrameX.Editor",
  "HybridCLR.Editor",
  "YooAsset.Editor",
  "YooAsset.Runtime",
  "YooAsset",
  "GameFrameX.ObjectStorage.Editor",
  "GameFrameX.ObjectStorage.QiNiu.Editor",
  "GameFrameX.ObjectStorage.Tencent.Editor",
  "GameFrameX.ObjectStorage.ALiYun.Editor"
]
```

> Source: [GameFrameX.Builder.Editor.asmdef](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/GameFrameX.Builder.Editor.asmdef#L3-L14)

> 주의: 업로드 관리자의 구체적인 구현(`ObjectStorageUploadFactory`, 각 백엔드 Manager의 재시도 및 분할 전략)은 별도의 `com.gameframex.unity.objectstorage.*` 패키지에 있으며, 본 저장소의 소스 코드에는 구현 세부 사항이 포함되어 있지 않습니다.
