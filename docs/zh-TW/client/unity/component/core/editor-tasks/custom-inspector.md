# 使用自訂 Inspector 監控池

在 Unity 編輯器執行模式下，透過 `ObjectPoolComponentInspector` 與 `ReferencePoolComponentInspector` 兩個自訂 Inspector 面板，即時查看物件池與引用池的容量、佔用、命中率等指標，並能把資料匯出為 CSV 檔案。

## 前置條件

1. 場景中已掛載 `ObjectPoolComponent` 或 `ReferencePoolComponent`（一般在 `GameFramework` 預製體上）。
2. Unity 必須處於 **Play Mode**，否則 Inspector 僅顯示空資訊提示 `Available during runtime only.`。
3. 元件必須掛在階層（Hierarchy）中的實例上，預製體資產上不會顯示池資料。

## 操作步驟

### 1. 開啟物件池（ObjectPool）監控面板

在 Hierarchy 中選中帶有 `ObjectPoolComponent` 的 GameObject，Inspector 會展開以下內容：

- `Object Pool Count`：當前已註冊的物件池數量。
- 每個物件池以摺疊項（`Foldout`）展示，標題是 `objectPool.FullName`。

展開後可以看到該池的即時屬性：

| 欄位 | 意義 |
|------|------|
| `Name` | 池名稱 |
| `Type` | 池內物件類型全名 |
| `Auto Release Interval` | 自動釋放間隔 |
| `Capacity` | 容量上限 |
| `Used Count` | 已使用物件數 |
| `Can Release Count` | 可立即釋放的物件數 |
| `Expire Time` | 過期時間 |
| `Priority` | 優先級 |

隨後是物件實例列表（`GetAllObjectInfos()`），每行顯示 `Name / Locked / Count 或 InUse / CustomCanReleaseFlag / Priority / LastUseTime`。當 `AllowMultiSpawn` 為 true 時，`In Use` 欄位被替換為 `Count`。

底部提供三個動作按鈕：

- `Release`：呼叫 `objectPool.Release()`，立刻釋放所有可釋放物件。
- `Release All Unused`：呼叫 `objectPool.ReleaseAllUnused()`。
- `Export CSV Data`：把當前池物件寫入 CSV，檔案預設名 `Object Pool Data - {Name}.csv`。

```csharp
ObjectPoolComponent t = (ObjectPoolComponent)target;
ObjectPoolBase[] objectPools = t.GetAllObjectPools(true);
foreach (ObjectPoolBase objectPool in objectPools)
{
    DrawObjectPool(objectPool);
}
```

### 2. 開啟引用池（ReferencePool）監控面板

選中帶有 `ReferencePoolComponent` 的 GameObject，執行時會展示：

- `Enable Strict Check` 開關：可即時切換嚴格檢查模式。
- `Reference Pool Count`：由 `ReferencePool.Count` 提供。
- `Show Full Class Name` 開關：切換列表按 `FullName` 還是 `Name` 排序。

池條目按組件（`Assembly.GetName().Name`）分組，每組一個摺疊項；展開後表格欄位依序為 `Unused / Using / Acquire / Release / Add / Remove`。

```csharp
ReferencePoolInfo[] referencePoolInfos = ReferencePool.GetAllReferencePoolInfos();
foreach (ReferencePoolInfo info in referencePoolInfos)
{
    string assemblyName = info.Type.Assembly.GetName().Name;
    // 按組件分組後展示
}
```

### 3. 匯出 CSV 並驗證

1. 在 Inspector 中點擊 `Export CSV Data`。
2. 彈出 `EditorUtility.SaveFilePanel`，選擇儲存路徑。
3. 寫入成功後 Console 輸出 `Export object pool CSV data to '{0}' success.`；失敗時輸出 `Export ... failure, exception is '{1}'.`，並以 `Debug.LogError` 形式記錄。

```csharp
File.WriteAllLines(exportFileName, data, Encoding.UTF8);
Debug.Log(Utility.Text.Format("Export object pool CSV data to '{0}' success.", exportFileName));
```

## 常見變體

- **多實例物件池（`AllowMultiSpawn = true`）**：行表頭切換為 `Locked\tCount\tFlag\tPriority\tLast Use Time`；CSV 中 `IsInUse` 欄位被 `SpawnCount` 取代。
- **空池狀態**：當 `GetAllObjectInfos().Length == 0`，Inspector 顯示 `Object Pool is Empty ...`，不會出現 `Release / Export` 按鈕。
- **非執行態**：物件池 Inspector 直接傳回 `Available during runtime only.`；引用池 Inspector 僅顯示 `Enable Strict Check` 序列化欄位。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| Inspector 只顯示 `Available during runtime only.` | 未進入 Play Mode | 點擊 Unity 的 `Play` 按鈕進入執行模式 |
| 選擇預製體資產看不到池資料 | `IsPrefabInHierarchy` 檢查失敗 | 把元件放到 Hierarchy 中的實例上 |
| 點擊 `Export CSV Data` 報 `failure, exception is ...` | 路徑無寫入權限或被佔用 | 換一個有寫入權限的目錄後重試 |
| 引用池面板只顯示 `m_EnableStrictCheck` 欄位 | 不在執行態 | 進入 Play Mode 後會自動展開 |

## 背景（選用）

兩個 Inspector 都繼承自 `GameFrameworkInspector` / `ComponentTypeComponentInspector`，透過 `[CustomEditor(typeof(...))]` 綁定到對應的 `BaseComponent`。`OnInspectorGUI` 末尾統一呼叫 `Repaint()`，保證池資料在執行時持續刷新。
