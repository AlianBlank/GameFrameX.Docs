# 設定の保存と読み込み

GameFrameX の設定コンポーネントを使用して、ゲーム設定（プレイヤー環境設定、レベルパラメータなど）を永続化バックエンドに書き込み、必要に応じて読み戻します。このページでは、Unity プロジェクト内で保存と読み込みを完了するための最小手順を示します。

## 前提条件

- `com.gameframex.unity.setting` パッケージが Unity プロジェクトにインポートされていること。
- シーンに `GameFrameX/Setting` コンポーネント（`SettingComponent`）がアタッチされていること。これは `Start` 時に自動的に `Load()` を呼び出し、`m_SettingHelperTypeName` を通じてデフォルトの `PlayerPrefsSettingHelper` を選択します。

## 操作手順

1. **デフォルトの Helper タイプを確認する**。`SettingComponent` はデフォルトで `PlayerPrefsSettingHelper` を使用するため、変更なしで PlayerPrefs への読み書きが可能です。ミニゲームプラットフォームに切り替える場合は、Inspector で `Setting Helper Type Name` に対応する `AlipayMiniGameSettingStorage` / `DouYinMiniGameSettingStorage` / `KuaiShouMiniGameSettingStorage` / `WeChatMiniGameSettingStorage` を指定します。

   ソース: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L100)

2. **設定を書き込みます**。`SettingComponent` の `SetXxx` シリーズメソッドを使用して値をメモリに書き込みます：

   ```csharp
   using GameFrameX.Setting.Runtime;

   var setting = GameFrameXEntry.GetComponent<SettingComponent>();
   setting.SetBool("MusicOn", true);
   setting.SetInt("Level", 3);
   setting.SetString("PlayerName", "Alice");
   setting.SetFloat("Volume", 0.8f);
   ```

   書き込みメソッドはメモリのみを変更し、すぐにはディスクに書き込まれません。

   ソース: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L225-L228)

3. **Save() を呼び出してディスクに書き込みます**。適切なタイミング（ゲームの終了時、シーン切り替え前など）に以下を実行します：

   ```csharp
   setting.Save();
   ```

   `PlayerPrefsSettingHelper.Save()` は現在のプラットフォームの `ISettingStorageBackend.Save()` に委譲して実際の書き込みを行います。戻り値は保存が成功したかどうかを示すため、デバッグ時にログを出力して確認できます。

   ソース: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L99-L102)

4. **設定を読み込みます**。`SettingComponent.Start()` はすでに `Load()` を呼び出しているため、次のシーン進入時に `GetXxx` を使用して読み取ることができます：

   ```csharp
   bool musicOn = setting.GetBool("MusicOn", true);     // デフォルト値付き
   int level   = setting.GetInt("Level", 1);
   string name = setting.GetString("PlayerName", "");
   float vol   = setting.GetFloat("Volume", 1.0f);
   ```

   各 `GetXxx` にはデフォルト値付きのオーバーロードが用意されており、キーが存在しない場合はデフォルト値が返されます。

   ソース: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L102-L108)

5. **キーを管理します**。個別またはすべての設定項目の照会、削除を行います：

   ```csharp
   if (setting.HasSetting("Level")) { /* ... */ }
   setting.RemoveSetting("Level");
   setting.RemoveAllSettings();
   ```

   ソース: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L157-L185)

## よくあるバリエーション

- **クロスプラットフォーム書き込み**。`m_SettingHelperTypeName` をミニゲームプラットフォームに対応する `*MiniGameSettingStorage` に変更すると、読み書きロジックを変更する必要はありません。
- **カスタムバックエンド**。`ISettingStorageBackend` を実装し、`PlayerPrefsSettingHelper.SetStorageBackendForTests` を通じて注入します（カスタム `SettingHelperBase` サブクラスで `SettingStorageBackendFactory.Create()` を使用することもできます）。
- **バッチ更新**。1 つのビジネスイベントの末尾で `Save()` を一度だけ集中して呼び出し、変更ごとにディスクに書き込むことを避けます。

## よくあるエラー

- **Save() の呼び出し忘れ**：`SetXxx` はメモリのみを変更するため、`Save()` を呼び出さないとデータは永続化されず、再起動後に失われます。
- **起動時に読み取る**：`Awake` 内で読み取らないでください。`SettingComponent` は `Start` で `Load()` を実行します。読み取りロジックは `Start` 以降に配置してください。
- **すべてのキーの列挙に依存する**：PlayerPrefs は `GetAllSettingNames()` をサポートしていないため、呼び出すと `null` が返され、`GetAllSettingNames is not supported.` という警告が出力されます。代わりに、ビジネス層で既知のキーリストを保持するようにしてください。

## 背景（オプション）

`SettingComponent` は MonoBehaviour のエントリポイントで、`SettingManager` は依存関係のないモジュールコアであり、`SettingHelperBase` が読み書きを特定のバックエンドにディスパッチします。`PlayerPrefsSettingHelper` はデフォルトで `SettingStorageBackendFactory` を通じて対応するプラットフォームのバックエンド実装を選択するため、同じ API で PlayerPrefs とミニゲームプラットフォームのストレージを互換的に扱います。
