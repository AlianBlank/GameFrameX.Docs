# Helper 类型找不到或创建失败怎么办

当代码里调用 `Helper.Create` 拿到 `null`、或反射加载时报 `cannot find Helper type` / `missing type` 时,通常意味着对应 Helper 类在构建时被裁剪,或命名空间/程序集引用没配齐。本页提供按症状定位与修复的方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `Helper.Create<XXHelper>()` 抛 `GameFrameworkException: ...` | 该 Helper 的 `Create` 工厂未注册或工厂未找到构造函数 | 用反射检查该类是否有无参构造函数,见 [修复 1](#修复-1-找不到无参构造函数) |
| iOS/Android IL2CPP 构建后某些 API 报 `MissingMethodException` 或 `TypeLoadException` | 代码裁剪(Code Stripping)把 Helper 类型剔除了 | 在场景里挂 `GameFrameXCroppingHelper` 或用 `link.xml` 保留,见 [修复 2](#修复-2-构建后被裁剪) |
| `typeof(GameFrameX.Runtime.DoTweenHelper)` 编译报错 | 没有安装对应插件,宏未启用 | 启用宏或移除引用,见 [修复 3](#修复-3-可选模块的辅助类) |
| 编辑器扩展找不到 `HotFixAssemblyDefinitionHelper` 等类型 | 命名空间错误或 Editor 程序集未编译 | 检查 `Editor/` 目录和 asmdef,见 [修复 4](#修复-4-editor-辅助类) |
| 自定义 Helper 子类抛 `not registered` | 未调用 `Helper.Create` 或 `Register` | 按框架约定的工厂模式注册,见 [修复 5](#修复-5-自定义-helper) |

## 修复 1:找不到无参构造函数

`Helper` 类的所有具体实现(例如 `DefaultLogHelper`、`DefaultCompressionHelper`、`DefaultTextHelper`、`DefaultVersionHelper`)都要求提供**无参构造函数**,因为 `Helper.Create<T>()` 走的是反射 `Activator.CreateInstance`。

1. 检查你的 Helper 子类:

```csharp
// 错误示例 — Helper.Create<MyHelper>() 会失败
public class MyHelper : ILogHelper
{
    public MyHelper(string name) { /* ... */ }
}

// 正确示例
public class MyHelper : ILogHelper
{
    public MyHelper() { }
    // ...
}
```

2. 在 Unity Console 中确认抛出的异常原文是否为 `GameFrameworkException`,异常内通常包含类型全名。

3. 修复后重新触发 `Helper.Create<MyHelper>()` 调用验证。

源码中具体 Helper 类型清单见 [GameFrameXCroppingHelper.cs#L21-L60](Runtime/GameFrameXCroppingHelper.cs#L21-L60)。

## 修复 2:构建后被裁剪

`Runtime/GameFrameXCroppingHelper.cs` 的存在就是为了防止 IL2CPP/AOT 构建时把框架内部类型剪掉,所有引用都通过 `typeof()` 表达。运行时(非编辑器)必须保证这个脚本在场景里被实例化:

1. 在首个启动场景里,新建一个空 `GameObject`,挂上 `GameFrameXCroppingHelper` 组件,设为 `DontDestroyOnLoad`。

```csharp
// 启动脚本中
var go = new GameObject("GameFrameXCroppingHelper");
go.AddComponent<GameFrameXCroppingHelper>();
DontDestroyOnLoad(go);
```

2. 如果使用 HybridCLR / ILRuntime 等热更方案,需要把这些类型加入主包 AOT 程序集的 `link.xml`:

```xml
<linker>
  <assembly fullname="GameFrameX.Runtime" preserve="all"/>
</linker>
```

3. 在 Build Settings 里确认该脚本不会在 Stripping 时被剔除(可临时关闭 Managed Stripping 验证)。

源参考: [GameFrameXCroppingHelper.cs#L1-L12](Runtime/GameFrameXCroppingHelper.cs#L1-L12)。

## 修复 3:可选模块的辅助类

`DoTweenHelper` 被 `#if ENABLE_GAME_FRAME_X_DO_TWEEN` 包裹([GameFrameXCroppingHelper.cs#L9-L11](Runtime/GameFrameXCroppingHelper.cs#L9-L11))。如果你没引入 DOTween 插件却启用了该宏,或者反过来:

| 情况 | 处理 |
|------|------|
| 没用 DOTween 却启用了 `ENABLE_GAME_FRAME_X_DO_TWEEN` | 关闭宏,或删除对 `DoTweenHelper` 的引用 |
| 用了 DOTween 但没启用宏 | 在 `Project Settings → Player → Scripting Define Symbols` 添加 `ENABLE_GAME_FRAME_X_DO_TWEEN` |
| 用其他可选插件(如 YooAsset、HybridCLR) | 查阅对应插件文档,在宏未启用时不要 `typeof()` 这些 Helper |

## 修复 4:Editor 辅助类

仓库里 `Editor/` 目录下有一批 `*Helper.cs`(如 `BuildHotfixHelper.cs`、`BuildPostProcessHelper.cs`、`MiniGameDefineSymbolHelper.*.cs`),它们只在 Editor 程序集可用:

1. 确认脚本在 `Editor/` 文件夹下,或对应的 `.asmdef` 标记了 `includePlatforms: ["Editor"]`。
2. **不要**在运行时代码里 `using` 或 `typeof()` 这些类型——发布包找不到就会报错。
3. 如果你新增了一个平台的小游戏(`InternationalMiniGames` / `DomesticMiniGames` / `GamePlatforms`),需要新增或补全对应平台的 `MiniGameDefineSymbolHelper.<Platform>.cs`。

源参考: [Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs](Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs)、[Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs](Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs)。

## 修复 5:自定义 Helper

框架里的 `Helper` 是一个静态门面类([Runtime/Helper/Helper.cs#L44](Runtime/Helper/Helper.cs#L44)),`Helper.Create<T>()` 会按约定查找 `T.Create()` 或同名工厂方法。如果你的自定义 Helper 找不到:

1. 确认实现了约定的工厂方法:

```csharp
public class MyJsonHelper : IJsonHelper
{
    public static IJsonHelper Create()
    {
        return new MyJsonHelper();
    }

    private MyJsonHelper() { } // 私有构造,只能通过 Create 拿到实例
}
```

2. 在 `GameEntry` 启动后,把返回的实例注册到框架:

```csharp
Utility.Json.IJsonHelper json = MyJsonHelper.Create();
GameEntry.RegisterHelper(json);
```

3. 编辑器下加断点,在 `Helper.Create<T>` 里确认是否走到了你自定义的分支。

## 验证

完成以上修复后,按以下步骤确认问题已解决:

1. **编辑器**:进入 Play 模式,所有 `Helper.Create` 调用应不再抛异常。
2. **IL2CPP 真机**:打包 Player,在目标设备上启动,Console 不再出现 `MissingMethodException` / `TypeLoadException`。
3. **反射扫描**:用反射列出 `GameFrameX.Runtime` 程序集中的所有 `*Helper` 类型,确认数量与 [GameFrameXCroppingHelper.cs#L21-L165](Runtime/GameFrameXCroppingHelper.cs#L21-L165) 列表一致。
4. **裁剪报告**:开启 IL2CPP 的 `Strip Engine Code` 输出,在 `Library/Il2cppBuildCache` 中确认目标类型不在裁剪列表。
