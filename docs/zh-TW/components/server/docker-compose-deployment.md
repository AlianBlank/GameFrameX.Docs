# 如何使用 Docker Compose 啟動多程序環境

按照本頁的步驟操作後，您將透過單一 `docker compose` 指令在本機啟動 1 個 MongoDB、2 個 Social 程序與 10 個 Game 程序。它們會透過容器網路互連，並準備對外暴露連接埠。

## 前置條件

- 已安裝 Docker Engine 與 Docker Compose v2（在終端機執行 `docker compose version` 應會輸出版本號）。
- 目前終端機位於儲存庫根目錄（即包含 `docker-compose.multi.yml` 的目錄）。
- 主機連接埠 `47017`、`48080–48089`、`49100–49109` 與 `49400–49401` 未被其他程序佔用。

## 步驟

1. **確認多程序編排檔案存在**。儲存庫根目錄中已備妥 `docker-compose.multi.yml`，總共宣告 13 個服務：`mongo`、`social-1`、`social-2`，以及 `game-1` … `game-10`。

   ```yaml
   name: gfx-multi
   ```
   來源：[docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L1-L3)

2. **了解服務探索如何注入**。多程序服務之間透過環境變數傳遞位址。`x-launcher-discovery-env` 使用 YAML 錨點，一次將所有節點的 `tcp://host:port` 注入每個容器：

   ```yaml
   x-launcher-discovery-env: &launcher-discovery-env
     services__Social_2001__tcp__0: "tcp://social-1:29400"
     services__Social_2002__tcp__0: "tcp://social-2:29401"
     services__Game_1001__tcp__0: "tcp://game-1:29100"
     ...
     services__Game_1010__tcp__0: "tcp://game-10:29109"
   ```
   每個服務透過 `environment: <<: *launcher-discovery-env` 重複使用同一組對應，因此無需在每個服務中重複撰寫。
   來源：[docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L3-L17)

3. **建置共用映像檔**。`docker-compose.multi.yml` 引用映像檔 `gameframex/server.launcher:local`，首次啟動前需要先建置：`social-1` 節點使用本地 `build` 建置內容，其他節點則重複使用此映像檔：

   ```yaml
   social-1:
     build:
       context: .
     image: gameframex/server.launcher:local
   ```
   來源：[docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L35-L38)

4. **啟動所有程序**。在儲存庫根目錄執行以下指令：

   ```bash
   docker compose -f docker-compose.multi.yml up -d
   ```

5. **檢查啟動順序與相依性**。所有 `game-*` 服務會透過 `depends_on` 等待 `mongo` 健康（`service_healthy`）、且 `social-1` / `social-2` 已啟動（`service_started`）後才會啟動，因此日誌會依照 `mongo → social → game` 的順序出現。

   ```yaml
   game-1:
     depends_on:
       mongo:
         condition: service_healthy
       social-1:
         condition: service_started
       social-2:
         condition: service_started
   ```
   來源：[docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L93-L101)

6. **驗證服務已上線**。Mongo 的健康檢查使用 `db.runCommand({ ping: 1 }).ok`，可直接以 docker 指令驗證：

   ```bash
   docker compose -f docker-compose.multi.yml ps
   docker compose -f docker-compose.multi.yml logs -f game-1
   ```

7. **存取節點**。`social-1` 對外暴露主機連接埠 `49400`（TCP）與 `48081`（HTTP），`game-1` 暴露 `49100` 與 `48080`，`game-10` 暴露 `49109` 與 `48089`。您可以直接連線到 `http://localhost:48080` 等位址進行除錯。

## 常見變體

- **僅執行最小的 2 程序拓撲**。儲存庫另提供 `docker-compose.yml`（Mongo + 1 個 Social + 1 個 Game，容器名稱使用 `gfx-game` / `gfx-social`，主機連接埠為 `37017/38080/38081/39100/39400`）。指令改為 `docker compose up -d`。
- **修改節點數量**。複製 `game-1` 區段，遞增 `ServerId` / `ServerInstanceId` / 連接埠，並在 `x-launcher-discovery-env` 中新增對應的一行 `services__Game_<id>__tcp__0`。
- **掛載自訂設定**。多程序編排已在每個容器中將 `./GameFrameX.Config/json` 以唯讀方式掛載至 `/app/Configs`。修改本機 JSON 後，重新啟動對應的容器即可生效。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `bind: address already in use` | 主機連接埠被佔用 | 修改 `docker-compose.multi.yml` 中 `ports` 的左側連接埠，或釋放主機上被佔用的連接埠 |
| `game-*` 不斷重新啟動，日誌顯示無法連線到 social | `up` 之前忘記等待 Mongo 健康 | 確認相依設定中的 `mongo: condition: service_healthy`，不要將其改為 `service_started` |
| `services__Game_xxxx` 的修改未生效 | 未同步至所有節點 | 透過 `environment: <<: *launcher-discovery-env` 重複使用錨點，不要在單一節點覆寫為其他名稱 |
| 寫入日誌時出現 `permission denied` | `running-multi/...` 目錄擁有者為 `root` | 刪除對應的掛載目錄並重新建立；容器以 `APP_UID` 身分寫入 `/app/data/logs` |

## 驗證

```bash
docker compose -f docker-compose.multi.yml ps        # 所有 State 皆為 running/healthy
docker compose -f docker-compose.multi.yml logs mongo # 可看到 waiting for connections
curl -s http://localhost:48080/                       # game-1 的 HTTP 連接埠有回應
```

若服務的容器結束代碼非零，可使用 `docker compose -f docker-compose.multi.yml logs --tail=200 <service>` 來找出根本原因。

## 背景（選讀）

`docker-compose.multi.yml` 使用映像檔 `gameframex/server.launcher:local`，該映像檔由根目錄的 `Dockerfile` 建置，會編譯 `GameFrameX.Launcher` 與 `GameFrameX.Hotfix` 專案。它也會將 Hotfix DLL 同時放到 `/app/hotfix/` 與 `/app/` 根目錄，以相容於預設從 `/app` 根目錄載入參考組件的熱更新邏輯。
