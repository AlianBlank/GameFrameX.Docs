# 運作原理：外觀層、條件編譯與延遲載入

`GameApp` 是一個靜態外觀類別，它透過 C# 的 `partial` 關鍵字將每個元件的存取入口拆分為獨立的原始碼檔案，透過 `#if` 條件編譯按需啟用它們，最後再以欄位快取實作延遲載入。

## 三大機制總覽

| 機制 | 用途 | 實作位置 |
|------|------|----------|
| `partial class GameApp` | 將所有元件的存取入口合併到同一個 `GameApp` 類別中 | [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53) |
| `#if ENABLE_GAME_FRAME_X_*` | 當模組未啟用時，其欄位、屬性與 using 指示詞都會被排除在編譯之外 | [Runtime/GameApp.Advertisement.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Advertisement.cs#L32-L56) |
| 欄位快取 + `GetComponent<T>()` | 首次存取時從 `GameEntry` 擷取元件，之後直接傳回快取欄位 | [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L39-L52) |

## 以三個步驟理解外觀層

1. **統一入口**。所有模組都透過靜態屬性 `GameApp.<ModuleName>` 存取，因此業務程式碼不需要持有 `GameEntry` 參考，也不需要關心元件的生命週期。
2. **編譯時期修剪**。每個模組（廣告、登入、熱更新、網路等）都對應一個獨立的 `GameApp.<ModuleName>.cs` 檔案，並在檔案開頭與結尾以 `#if ENABLE_GAME_FRAME_X_<MODULE>` / `#endif` 包裹。當巨集未定義時，整個檔案會被排除在編譯之外——不會增加任何體積，也不會引入對模組套件的相依性。
3. **執行階段延遲載入**。靜態屬性內的 `if (_xxx == null)` 檢查可確保 `GameEntry.GetComponent<T>()` 只會在首次存取時執行；之後直接傳回快取欄位，避免重複查詢。

## 典型程式碼片段

`GameApp.Base` 是外觀層的最小運作範例，僅公開一個屬性和一個私有的快取欄位：

```csharp
public static partial class GameApp
{
    /// <summary>
    /// 取得遊戲基礎元件。
    /// </summary>
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }

            return _base;
        }
    }

    private static BaseComponent _base;
}
```

來源：[Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

需要條件編譯的模組（例如廣告）會在外層加上 `#if` 保護：

```csharp
#if ENABLE_GAME_FRAME_X_ADVERTISEMENT
using GameFrameX.Runtime;
using GameFrameX.Advertisement.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// 取得廣告元件。
    /// </summary>
    public static AdvertisementComponent Advertisement
    {
        get
        {
            if (_advertisement == null)
            {
                _advertisement = GameEntry.GetComponent<AdvertisementComponent>();
            }

            return _advertisement;
        }
    }

    private static AdvertisementComponent _advertisement;
}
#endif
```

來源：[Runtime/GameApp.Advertisement.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Advertisement.cs#L32-L56)

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 存取 `GameApp.Advertisement` 時擲回「找不到類型」錯誤 | `ENABLE_GAME_FRAME_X_ADVERTISEMENT` 未在 Player Settings / asmdef 中定義 | 啟用對應的模組套件並定義該巨集，或將其加入 `scriptingDefineSymbols` |
| 啟用巨集後仍出現缺少 `using` 的錯誤 | 未安裝模組套件 | 透過 NuGet/UPM 安裝對應模組（例如 `GameFrameX.Advertisement`） |
| `GetComponent<T>()` 傳回 `null` | 目標元件未掛載到 `GameEntry` | 將對應的 `Component` 子類別掛載到 `GameEntry` 預製物上；詳見「如何掛載並初始化元件」 |

## 背景說明（選讀）

將每個模組的存取入口放進獨立的 `partial` 檔案，等同於「依模組拆分原始碼、以巨集控制要編譯的內容，並按需延遲載入實例」。這種做法能讓框架核心保持精簡：業務程式碼只需為其參考的模組啟用巨集；未被參考的模組既不會被編譯，也不會被打包，唯一的執行階段開銷只是一個靜態屬性 getter。
