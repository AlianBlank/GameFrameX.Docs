# GetData/SetData Data Reading Exception Quick Reference

This page addresses common exceptions and abnormal return scenarios encountered during `GetData` / `SetData` calls on `IFsm<T>`, providing symptom comparison and troubleshooting steps. For state machine usage, refer to the "Fsm Quick Start" guide.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Throws `GameFrameworkException("Data name is invalid.")` | `name` is `null` or an empty string | Use non-empty key names; constant strings are recommended |
| `GetData` always returns `null` | `SetData` was never called to write the key; or the state machine has been cleared by `Reset` / `Shutdown` | Explicitly call `SetData` before the first read, or use the `HasData` entry to check |
| After `SetData`, the field value is still the default when read immediately | On duplicate `SetData` calls, the old value is recycled to `ReferencePool`, and the new value is not actually replaced | Call `RemoveData` before `SetData`, or only call `SetData` once |
| Type conversion throws `InvalidCastException` | The generic parameter of `GetData<TData>` does not match the actual `Variable` subtype used when writing | Use the same `Variable` subtype on both read and write sides (e.g., `VarInt`, `VarString`) |
| Calling `GetData` after the state machine is destroyed throws an exception | When `m_IsDestroyed == true`, internal processes like `Reset` will deny access | Stop all access after destruction, or rebuild a new FSM |

## Fix Steps

### 1. Invalid Name (`Data name is invalid`)

Both `GetData(string)` and `SetData(string, Variable)` validate the name as the first step:

```csharp
if (string.IsNullOrEmpty(name))
{
    throw new GameFrameworkException("Data name is invalid.");
}
```

Source: [Fsm.cs#L469-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L527)

**Fix**: Use stable string constants for key names, such as `"Hp"`, `"Owner"`, and avoid passing in concatenated empty strings.

### 2. Read Returns `null`

`GetData` directly returns `null` when the internal dictionary is empty or the key does not exist, without throwing an exception:

```csharp
if (m_Datas == null)
{
    return null;
}

Variable data = null;
if (m_Datas.TryGetValue(name, out data))
{
    return data;
}

return null;
```

Source: [Fsm.cs#L469-L488](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488)

**Fix**:
1. Call `SetData` once during the state's `OnEnter` or immediately after the state machine is created to complete initialization.
2. Use `HasData(name)` to check existence before reading; if `false`, perform default initialization.
3. Note that `Reset()` clears all data (`m_Datas.Clear()`), and after `Shutdown` the dictionary returns to `null`, requiring reinitialization.

### 3. Old Value Recycled After Duplicate `SetData`

Internally, `SetData` first retrieves the old value, and if non-null, returns it to the reference pool:

```csharp
Variable oldData = GetData(name);
if (oldData != null)
{
    ReferencePool.Release(oldData);
}

m_Datas[name] = data;
```

Source: [Fsm.cs#L508-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L508-L527)

**Fix**:
- Instances of `Variable` subtypes are obtained from `ReferencePool` and managed by the framework internally; do not externally `new` them and then hand them to the state machine.
- If you want to replace the key name, use `RemoveData(name)` to explicitly return the old value, and then `SetData` the new key.

### 4. Generic Type Mismatch

`GetData<TData>` performs a direct cast, requiring `TData : Variable` and matching the subtype used when writing:

```csharp
public TData GetData<TData>(string name) where TData : Variable
{
    return (TData)GetData(name);
}
```

Source: [Fsm.cs#L458-L461](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

**Fix**: Explicitly use built-in subtypes such as `VarInt`, `VarFloat`, `VarString`, `VarBool`, `VarObject`, etc., on the caller side. Avoid using `object` or the `Variable` base class as `TData`, otherwise the cast will fail.

### 5. Access After Destruction

After `Fsm.Shutdown`, `m_IsDestroyed = true`, and subsequent access will be denied by internal processes like `Reset()`:

```csharp
if (m_IsDestroyed)
{
    throw new GameFrameworkException("FSM is destroyed, can not reset.");
}
```

Source: [Fsm.cs#L560-L565](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L560-L565)

**Fix**: Clear all external references before destroying the FSM; do not continue calling `GetData`/`SetData` after `OnDestroy`.

## Verification

Execute the following steps to confirm the issue has been resolved:

1. In the state's `OnEnter`, print `HasData("Hp")` and `GetData<VarInt>("Hp").Value` to confirm the read result matches expectations.
2. After `SetData("Hp", hpVar)`, call `GetData` again to verify the values are consistent.
3. After calling `Reset()`, read `GetData` again — it should return `null` without throwing an exception (as long as `name` is non-empty).
