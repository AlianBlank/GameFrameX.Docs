# 啟用請求日誌與 Inspector 使用方式

在 Unity 選單列的 `GameFrameX/Scripting Define Symbols` 中勾選「Web 傳送/接收日誌輸出啟用」，等待腳本重新編譯完成後，`WebManager` 發出的所有 HTTP 請求與接收到的回應都會以 `Log.Debug` 輸出到 Console。選取掛載 `WebComponent` 的 GameObject 後，Inspector 會額外提供一個 0–120 秒範圍、可調整請求逾時時間的 `Timeout` 滑桿。

## 前置條件

- 專案中已安裝 `com.gameframex.unity.web` 套件，且 Web 元件初始化已完成。
- Console 面板的日誌等級必須設定為顯示 Debug 日誌，否則即使啟用巨集也看不到輸出。

## 操作步驟：啟用請求日誌

1. 開啟 Unity 頂部選單 `GameFrameX/Scripting Define Symbols`。
2. 依需求點擊下方選單項目（點擊後立即生效，巨集會寫入目前 Build Target 的 Scripting Define Symbols）：

| 選單項目 | 功能 | 寫入的巨集 |
|------|------|---------|
| `Enable Web Send Logs(开启Web发送日志打印)` | 輸出每個請求的 URL、Header、Form | `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` |
| `Disable Web Send Logs(关闭Web发送日志打印)` | 移除傳送日誌巨集 | — |
| `Enable Web Receive Logs(开启Web接收日志打印)` | 輸出每個回應的 URL、Header、Form、Content | `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` |
| `Disable Web Receive Logs(关闭Web接收日志打印)` | 移除接收日誌巨集 | — |

3. 等待 Unity 重新編譯腳本（直到右下角的旋轉圖示消失為止）。
4. 執行任意 Web 請求（例如 `WebManager` 的 Get/Post 介面），即可在 Console 中看到 `Web Request: ...` 與 `Web Response: ...` 格式的 Debug 日誌。

選單項目的內部實作是新增/移除巨集定義：

```csharp
public static class WebLogScriptingDefineSymbols
{
    public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG";
    public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_SEND_LOG";

    [MenuItem("GameFrameX/Scripting Define Symbols/Enable Web Send Logs(开启Web发送日志打印)", false, 451)]
    public static void EnableNetworkSendLogs()
    {
        ScriptingDefineSymbols.AddScriptingDefineSymbol(EnableNetworkSendLogScriptingDefineSymbol);
    }
}
```

## 操作步驟：使用 WebComponent Inspector

1. 在 Hierarchy 中選取掛載 `WebComponent` 元件的 GameObject。
2. Inspector 面板底部會出現 `Timeout` 滑桿，數值範圍為 0–120。
3. 拖曳滑桿：
   - **執行模式（Play Mode）**：直接寫入執行階段物件 `t.Timeout`，會立即套用至後續請求。
   - **非執行模式**：寫入序列化屬性 `m_Timeout`，會與場景/prefab 一同儲存。

```csharp
[CustomEditor(typeof(WebComponent))]
internal sealed class WebComponentInspector : ComponentTypeComponentInspector
{
    public override void OnInspectorGUI()
    {
        base.OnInspectorGUI();
        serializedObject.Update();

        WebComponent t = (WebComponent)target;
        float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
        if (timeout != m_Timeout.floatValue)
        {
            if (EditorApplication.isPlaying)
            {
                t.Timeout = timeout;
            }
            else
            {
                m_Timeout.floatValue = timeout;
            }
        }

        serializedObject.ApplyModifiedProperties();
    }
}
```

出處：[Editor/Inspector/WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/Inspector/WebComponentInspector.cs#L7-L37)

> 由於 `WebComponentInspector` 繼承自 `ComponentTypeComponentInspector`，Inspector 中也會保留用於選擇元件 `IWebManager` 實作類型的下拉選單（`RefreshComponentTypeNames(typeof(IWebManager))`）。

## 常見變化

- **只查看請求、不查看回應**：僅點擊 `Enable Web Send Logs`。兩個巨集彼此獨立，可自由組合。
- **手動管理巨集**：直接在 `Project Settings → Player → Scripting Define Symbols` 輸入 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG;ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`，效果與選單操作相同。
- **逾時行為**：`Timeout` 滑桿記錄的值會在 `WebManager` 中以秒（WebGL）或毫秒（非 WebGL）為單位套用到請求。請參考 `Runtime/Web/WebManager.cs` 中的 `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;` 與 `request.Timeout = (int)RequestTimeout.TotalMilliseconds;`。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 點擊選單後 Console 中仍沒有 `Web Request/Web Response` 日誌 | Console 面板中 Debug 等級日誌被篩選掉 | 在 Console 右上角篩選器中勾選 Debug/Info |
| 日誌只出現在某些平台上 | 巨集是依 Build Target 分別套用，切換平台後需重新勾選 | 切換平台後重新執行選單項目 |
| 變更滑桿後請求仍以先前的逾時時間送出 | 非 Play 模式時的變更僅寫入 `m_Timeout`，需重新進入 Play 或儲存場景 | 在 Play 模式中調整，或儲存場景後重新進入 Play |
| 日誌內容未包含 `Form`/`Header` | 該請求本身沒有表單或請求標頭 | 確認呼叫端傳入的 header/form 參數 |

## 驗證

1. 執行 `GameFrameX/Scripting Define Symbols → Enable Web Send Logs` 後觸發任意 GET 請求。
2. 若 Console 出現 `Web Request: {URL} \n Header: ... \n Form: ...`，表示傳送日誌已生效；收到回應後出現 `Web Response: ... \n Content: ...`，表示接收日誌已生效。
3. 在 Play 模式中拖曳 Inspector 的 `Timeout` 滑桿並觸發請求，確認日誌中的請求耗時或逾時例外是否隨之變化。

## 背景

請求日誌是以條件編譯巨集 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 包裹 `Log.Debug` 呼叫的方式實作。巨集停用時，對應程式碼完全不會包含在編譯結果中，因此正式建置不會留下效能負擔。這也是操作選單開關時需要觸發一次腳本重新編譯的原因。Inspector 端的 `Timeout` 滑桿透過 `EditorGUILayout.Slider` 區分 Play 與非 Play 兩種寫入路徑，確保執行階段熱調整與場景序列化互不干擾。
