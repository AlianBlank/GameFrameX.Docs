# HTTP 公共參數配置方法

若要在啟動流程的所有 HTTP 請求中注入統一的公共參數(渠道、語言、裝置識別碼等)，只需實作 `IStartupHttpParamsProvider` 並將其註冊到流程上下文中即可。

## 前置條件

- 專案中已新增 `GameFrameX.Startup` 套件，且啟動流程可以存取 `IFsm<IProcedureManager>`。
- 已了解啟動選項 `StartupOptions` 的欄位含義(套件名稱、渠道、子渠道等)。

## 操作步驟

1. **實作參數容器(可選)**

   若只需重複使用基本欄位，可直接使用 `StartupHttpParams`。若需要新增欄位，則衍生新類別並實作 `IStartupHttpParams.ToJson()` 與 `ToDictionary()`。

   ```csharp
   using GameFrameX.Startup.Runtime;
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MyStartupHttpParams : StartupHttpParams
   {
       public string ServerId = string.Empty;

       public override string ToJson()
       {
           ServerId = ServerId ?? string.Empty;
           return Utility.Json.ToJson(this);
       }

       public override Dictionary<string, object> ToDictionary()
       {
           var dict = base.ToDictionary();
           dict["ServerId"] = ServerId ?? string.Empty;
           return dict;
       }
   }
   ```

   來源:[Runtime/Http/StartupHttpParams.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L19-L151)

2. **實作 `IStartupHttpParamsProvider`**

   在 `Create` 方法中，將 `StartupOptions`(以及所需的執行時上下文)對應到參數物件。

   ```csharp
   using GameFrameX.Startup.Runtime;

   public class MyStartupHttpParamsProvider : DefaultStartupHttpParamsProvider
   {
       public override IStartupHttpParams Create(StartupOptions options)
       {
           var p = (MyStartupHttpParams)base.Create(options);
           p.ServerId = "cn-east-1";
           p.AppVersion = Application.version;
           p.Platform = Application.platform.ToString();
           p.DeviceUniqueIdentifier = SystemInfo.deviceUniqueIdentifier;
           return p;
       }
   }
   ```

   來源:[Runtime/Http/DefaultStartupHttpParamsProvider.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/DefaultStartupHttpParamsProvider.cs#L9-L23)

3. **註冊到啟動流程**

   建立 `GameFrameX.Startup` 流程管理器後，將 Provider 實例寫入黑板鍵 `StartupHttpParamsProvider`(類型為 `VarObject`)。流程內部會透過 `StartupProcedureUtility.GetHttpParamsProvider` 讀取它，若未註冊，則會自動回退到 `DefaultStartupHttpParamsProvider`。

   ```csharp
   var provider = new MyStartupHttpParamsProvider();
   var providerBox = VarObject.Create(provider);
   procedureOwner.SetData(BlackBoardKeys.StartupHttpParamsProvider, providerBox);
   ```

   來源:[Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L71-L76)

4. **在 HTTP 請求中讀取公共參數**

   透過 `GetHttpParams(procedureOwner)` 取得目前作用中的參數實例，然後呼叫 `ToJson()` 或 `ToDictionary()`,將其注入 HTTP 客戶端/Body。

   ```csharp
   var httpParams = StartupProcedureUtility.GetHttpParams(procedureOwner);
   var dict = httpParams.ToDictionary();
   // 將 dict 合併到 POST 表單或 JSON body 中
   ```

   來源:[Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L78-L99)

## 公共參數欄位快速參考

| 欄位 | 類型 | 來源 | 說明 |
|------|------|------|------|
| `PackageName` | string | `StartupOptions.PackageName` | 應用程式套件名稱 |
| `Channel` | string | `StartupOptions.Channel` | 主渠道 |
| `SubChannel` | string | `StartupOptions.SubChannel` | 子渠道 |

## 常見變體

- **完全自訂欄位集**：不繼承 `StartupHttpParams`,而是直接實作 `IStartupHttpParams` 介面，在 `ToJson()` / `ToDictionary()` 中回傳自己的欄位。
- **依執行時平台分支**：在 `Provider.Create` 中根據 `Application.platform` 回傳不同的參數物件(例如：僅在主機平台額外新增 `ConsoleId`)。
- **參數動態更新**：若特定欄位(例如：伺服器地區)需要中途變更，只需重新建立參數物件並以 `SetData(BlackBoardKeys.StartupHttpParamsProvider, ...)` 覆寫即可。

## 常見錯誤

- **黑板註冊遺漏**:`GetHttpParamsProvider` 在未註冊時會回傳預設 Provider,因此業務邏輯不會出錯，但所有自訂欄位都會遺失。請確認 `SetData` 的執行時間早於首次使用參數的流程。
- **`options` 為 null 的情況**:`StartupHttpParams.FromOptions` 會對 `null` 擲出 `ArgumentNullException`。在自訂 Provider 中，請先進行 null 檢查，或確保在呼叫 `FromOptions` 之前已指派 `StartupOptions`。
- **衍生類別遺漏 `ToDictionary`**:若只覆寫 `ToJson` 而未覆寫 `ToDictionary`,新增的欄位將不會出現在字典形式的請求主體中，伺服器可能因此收不到該欄位。兩個方法必須同時實作。
- **欄位名與後端規範不一致**:`ToDictionary` 的 key(例如:`"Channel"`)是傳送至後端的欄位名稱，因此變更名稱後必須與後端契約同步。

## 背景(可選)

啟動框架不會直接發出 HTTP 請求，而是將「如何產生公共參數」抽象化為 `IStartupHttpParamsProvider`,並將「如何使用參數」交給上層 HTTP 模組處理。框架僅保證可以在流程中取得 `IStartupHttpParams` 實例，至於要放入 Header、Query、Body、Form 中的哪一個，則由呼叫端決定。這樣的設計使得 HTTP 實作可以自由替換(GameFrameX.Network、BestHTTP、UnityWebRequest 等)，同時公共參數始終保持一致。
