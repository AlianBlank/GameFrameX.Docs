# 熱更新後玩家資料或 Actor 狀態異常怎麼辦

熱更新透過 `IHotfixBridge` 橋接介面把狀態層(Apps)的呼叫轉送到邏輯層(Hotfix)。如果橋接實作沒有放在正確的組件，或熱更新後舊版本 DLL 沒有被卸載，就會出現玩家資料不一致、Actor 狀態錯亂的問題。本頁提供從錯誤訊息直接定位到修復點的路徑。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 編譯報 `GFX0004: Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not 'Y'` | `IHotfixBridge` 實作類別被放在非 `GameFrameX.Hotfix` 的組件裡 | 把橋接類別遷移到 `GameFrameX.Hotfix` 專案(見下文「修復步驟 1」) |
| 熱更後玩家資料遺失、屬性回退到預設值 | 熱更組件未被替換，狀態層仍在呼叫舊版橋接 | 清理 `bin/` 下的舊 DLL,重新觸發熱更(見下文「修復步驟 2」) |
| Actor 收到呼叫但方法版本不一致(部分呼叫走新邏輯、部分走舊邏輯) | AppDomain 中殘留多份 `IHotfixBridge` 實作 | 確保全專案只有一個 `IHotfixBridge` 實作，且位於 `GameFrameX.Hotfix`(見下文「修復步驟 3」) |
| 執行階段報 `HotfixHandler` 反射找不到 | 標記類別被刪除或命名空間被修改 | 保留 `GameFrameX.Hotfix.HotfixHandler` 靜態類別，不要重新命名 |

## 修復步驟

### 1. 橋接類別必須放在 `GameFrameX.Hotfix` 組件

架構分析器會在編譯期驗證 `IHotfixBridge` 的實作位置，違反規則會直接報錯 `GFX0004`:

```csharp
// GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs
private static readonly DiagnosticDescriptor SDescriptor = new DiagnosticDescriptor(
    "GFX0004",
    "IHotfixBridge must be defined in GameFrameX.Hotfix",
    "Type '{0}' implements IHotfixBridge and must be defined in assembly '{1}', not '{2}'",
    ArchitectureAnalyzerConstants.Category,
    DiagnosticSeverity.Error,
    true);
```

Source: [HotfixBridgeAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs#L22-L28)

修復方法：

1. 在方案中開啟出錯的實作類別所在的 `.cs` 檔案。
2. 把它移到 `GameFrameX.Hotfix/StartUp/` 目錄，並將 `.cs` 檔頭的命名空間改為 `GameFrameX.Hotfix.StartUp`。
3. 確認檔案開頭包含 `internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge`(參考既有入口)。
4. 重建方案，確認 `GFX0004` 錯誤消失。

### 2. 讓熱更 DLL 真正被替換

狀態層(Apps)呼叫邏輯層(Hotfix)完全依賴 `IHotfixBridge`,如果舊版 DLL 沒有卸載，玩家資料序列化/反序列化用的就是舊 schema,看起來就像「熱更後狀態異常」。修復步驟：

1. 停止所有執行中的 GameFrameX.Server 處理程序。
2. 刪除服務輸出目錄下的 `GameFrameX.Hotfix.dll`(以及對應的 `.pdb`)和 `hotfix/` 資源目錄。
3. 把新編譯的 `GameFrameX.Hotfix.dll` 複製到熱更新目錄，版本號需大於目前線上版本。
4. 啟動服務，觸發一次熱更流程，觀察日誌確認載入的 DLL 版本號。
5. 讓一個測試帳號登入並觸發涉及橋接呼叫的操作，確認資料正確寫入資料庫。

### 3. 全專案只保留一個 `IHotfixBridge` 實作

如果有多個類別實作 `IHotfixBridge`(例如新舊版本並存)，Actor 會隨機繫結到其中一個，導致狀態層看到的方法版本與邏輯層不一致。修復步驟：

1. 在全專案搜尋 `: IHotfixBridge`,確認只有一處實作：

   ```bash
   grep -rn "IHotfixBridge" --include="*.cs"
   ```

2. 如果找到多處，保留 `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGame*.cs` 裡的那一份，刪除或合併其餘實作。
3. 重新編譯，確認 `GFX0004` 沒有報「重複定義」。

### 4. 不要刪除 `HotfixHandler` 標記類別

`HotfixHandler` 是一個空類別，但它承擔反射入口的職責，刪掉會讓熱更引擎找不到標記：

```csharp
// GameFrameX.Hotfix/HotfixHandler.cs
namespace GameFrameX.Hotfix;

/// <summary>
/// 該類文件用於處理熱更新標記。不能刪除。用於反射呼叫
/// </summary>
public static class HotfixHandler
{
}
```

Source: [HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8)

如果日誌中出現「找不到 `HotfixHandler`」或「反射標記缺失」，按上面的程式碼把空類別加回 `GameFrameX.Hotfix` 專案即可。

## 驗證

修復完成後按下列順序驗證：

1. 編譯方案，確認沒有 `GFX0004` 錯誤，也沒有其他 `GFX####` 錯誤。
2. 啟動服務，查看啟動日誌中熱更新模組載入的 DLL 版本號，與本機建置版本一致。
3. 用測試帳號登入並觸發一個會呼叫 `IHotfixBridge` 方法的業務(例如登入、領取郵件、修改屬性)，觀察資料庫記錄是否符合預期。
4. 模擬一次熱更(替換 DLL),重複第 3 步，確認熱更前後行為一致、資料沒有回退。

## 背景

`IHotfixBridge` 是狀態層(Apps)與邏輯層(Hotfix)之間唯一的呼叫通道。架構分析器(`HotfixBridgeAssemblyAnalyzer`)強制將實作限定在 `GameFrameX.Hotfix` 組件內，以保證熱更時可以整體替換；狀態層只持有介面參考，因此替換過程對玩家而言是無感知的。一旦橋接被破壞或殘留舊 DLL,Actor 與玩家資料就會出現「新邏輯寫、新讀取」或「新舊混用」的不一致現象，本流程就是圍繞這兩類根本原因展開的。
