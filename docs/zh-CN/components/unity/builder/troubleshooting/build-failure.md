# 构建失败与命令行参数错误怎么办

当通过命令行调用构建流程时，构建失败几乎总是由"参数缺失 / 拼错 / 值非法"或"前置步骤未完成"导致。本页按报错原文给出对应的根因与修复方法。

## 快速诊断

| 症状(报错原文/关键字) | 根因 | 修复 |
|---|---|---|
| `executeMethod is null` | 未通过 `-ExecuteMethod` 传入入口方法名 | 在命令行加上 `-ExecuteMethod <命名空间.类.方法>` |
| `build number is null` | 未通过 `-BuildNumber` 传入构建号 | 在命令行加上 `-BuildNumber <版本号>` |
| `无效的构建管线类型: <xxx>，可选值: BuiltinBuildPipeline, ScriptableBuildPipeline, RawFileBuildPipeline` | `-BuildPipeline` 取值不是合法的枚举名 | 取值改为 `BuiltinBuildPipeline`、`ScriptableBuildPipeline` 或 `RawFileBuildPipeline` 之一 |
| `无效的内置文件拷贝选项: <xxx>，可选值: None, ClearAndCopyAll, ClearAndCopyByTags, OnlyCopyNew` | `-BuildinFileCopyOption` 取值非法 | 取值改为 `None`、`ClearAndCopyAll`、`ClearAndCopyByTags` 或 `OnlyCopyNew` 之一;不传则默认 `ClearAndCopyAll` |
| 日志里完全没有任何本工具输出,但 Unity 退出了 | `LogFilePath` 指向的位置不可写,或构建号为空导致路径推导失败 | 检查 `-LogFilePath` 目录权限,或显式提供 `-BuildNumber` |
| `-BuildPipeline`/`-PackageVersion` 等带值参数不生效 | 把值紧贴参数写成 `-BuildPipelineBuiltinBuildPipeline` | 参数与值之间**必须有空格**,写成 `-BuildPipeline BuiltinBuildPipeline` |
| BuildAsset 正常但 BuildPlayer(出包)阶段红字 | 前置的 `BuildAsset` 没跑过,或热更/AOT 代码目录为空 | 先跑 `BuildAsset`,确认 `Assets/.../Hotfix/`、`AOT/` 目录有内容再出包 |

## 修复步骤

### 1. 补齐必填的三个参数

解析器强制要求 `-ExecuteMethod`、`-BuildNumber`、`-LogFilePath`(后者未传时会自动按前两者推导,但仍建议显式提供)。命令样例:

```bash
Unity \
  -batchmode -nographics -quit \
  -projectPath /path/to/project \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
  -BuildNumber 1.0.0.1 \
  -LogFilePath ../Logs/BuildAsset_1.0.0.1.log \
  -ChannelName default \
  -PackageName DefaultPackage
```

任一缺失都会抛 `Exception`,进程直接退出。来源:[Editor/Builder.BuildParamsParse.cs#L175-L189](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L175-L189)。

### 2. 修正 `-BuildPipeline` 与 `-BuildinFileCopyOption` 的取值

这两个参数都通过 `Enum.TryParse` 校验,大小写不敏感但**必须是枚举名**,不能是数字也不能是拼写错误:

- `-BuildPipeline`:可选 `BuiltinBuildPipeline`(默认)、`ScriptableBuildPipeline`、`RawFileBuildPipeline`
- `-BuildinFileCopyOption`:可选 `None`、`ClearAndCopyAll`(默认)、`ClearAndCopyByTags`、`OnlyCopyNew`

```bash
  -BuildPipeline BuiltinBuildPipeline \
  -BuildinFileCopyOption ClearAndCopyAll \
```

校验逻辑:[Editor/Builder.BuildAsset.cs#L40-L84](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L84)。

### 3. 保证 `-xxx <值>` 之间是空格分隔

解析器按 `commandLineArgs` 逐项扫描,每个 switch 用 `index + 1` 取下一个元素,所以参数与值之间必须是空格(不是 `=`、不是连写)。来源:[Editor/Builder.BuildParamsParse.cs#L152-L172](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L152-L172)。

正确:`-PackageVersion 20240101120000`
错误:`-PackageVersion=20240101120000`、`-PackageVersion20240101120000`

### 4. 先 `BuildAsset` 再 `BuildPlayer`

`BuildAsset` 内部会拷贝热更与 AOT 程序集、刷新 AssetDatabase,然后再调用 YooAsset 打包。如果直接跑出包命令却发现热更代码缺失、构建报"找不到程序集"或资源打包为空,通常是跳过了资源打包步骤。修复:流水线拆成两步,先跑 `BuildAsset`,再跑 `BuildPlayerAndroid`/`BuildPlayerIOS`。来源:[Editor/Builder.BuildAsset.cs#L15-L27](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L15-L27)、[Editor/Builder.cs#L60-L66](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L60-L66)。

### 5. 让 `-BundleId` / `-AppVersion` 真正生效

这两个参数只有在传入非空字符串时才会覆盖 `PlayerSettings`。如果命令行传了但 `PlayerSettings` 没变化,检查两端都没有多余空格或换行(代码会做 `Trim`)。来源:[Editor/Builder.BuildParamsParse.cs#L194-L202](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L194-L202)。

## 验证

1. 命令行首行不再出现 `executeMethod is null` / `build number is null`,说明必填参数已补齐。
2. Edit/Console 中能找到一行 `-----------构建参数开始-----------` 紧接着 `_builderOptions` 的 JSON 输出,确认所有参数被正确解析。来源:[Editor/Builder.BuildParamsParse.cs#L191-L193](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L191-L193)。
3. `BuildAsset` 完成后日志包含 `BuildAsset End`,再启动 `BuildPlayer*` 才不会因资源缺失失败。来源:[Editor/Builder.BuildAsset.cs#L99-L100](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L99-L100)。

## 背景(可选)

工具由 `Builder.BuildParamsParse` 解析命令行 → 写入 `BuilderOptions` → 分发到 `BuildAsset` / `BuildPlayer*`。校验集中在解析阶段(`Exception` 抛出)和 `BuildAsset` 起点的枚举 `TryParse`,所以"构建失败"几乎都在这两层被截获,真正需要回到 YooAsset / Unity 出包自身排查的反而是少数情况。
