# 증분 빌드 활성화 방법

`BuildAsset`를 호출하여 리소스 패키지를 빌드할 때 `IsIncrementalBuildPackage`를 `true`로 설정하면, 빌더는 YooAsset의 빌드 모드를 `EBuildMode.IncrementalBuild`로 전환하여 변경된 리소스만 다시 패키징하고 변경되지 않은 부분은 건너뛰어 빌드 시간을 크게 단축합니다.

## 사전 조건

- 《빠른 시작》에 따라 `GameFrameX.Builder.Editor` 어셈블리를 이미 연동했습니다.
- 현재 빌드 파이프라인이 `BuiltinBuildPipeline` 또는 `RawFileBuildPipeline`입니다(두 파이프라인의 `BuildParameters` 모두 `BuildMode` 필드를 지원합니다).
- 이번 빌드가 기존 패키징 이력이 있는 리소스 패키지 디렉터리를 대상으로 합니다. 첫 빌드는 재사용 가능한 캐시가 없어 전체 재구축과 효과가 동일합니다.

## 작업 단계

1. **코드에서 활성화**

   `BuilderOptions.IsIncrementalBuildPackage`에 직접 `true`를 할당한 후 빌드를 호출합니다:

   ```csharp
   var options = new GameFrameX.Builder.Editor.BuilderOptions
   {
       PackageName = "DefaultPackage",
       IsIncrementalBuildPackage = true,
   };
   GameFrameX.Builder.Editor.Builder.BuildAsset(options);
   ```

   Source: [Editor/BuilderOptions.cs#L72-L75](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L72-L75)

2. **명령줄 매개변수로 활성화**

   CI / 배치 스크립트에 `-IsIncrementalBuildPackage` 플래그를 추가하면, `Builder.BuildParamsParse`가 이를 `true`로 파싱합니다(명령줄 방식은 값을 전달할 필요 없이 해당 플래그가 나타나면 활성화로 간주함):

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
         -PackageName DefaultPackage \
         -IsIncrementalBuildPackage
   ```

   Source: [Editor/Builder.BuildParamsParse.cs#L90-L93](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L90-L93)

3. **적용 확인**

   빌드를 시작하면 `Builder.BuildAsset`는 다음 할당을 실행하여 YooAsset의 빌드 모드를 증분으로 전환합니다:

   ```csharp
   buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage
       ? EBuildMode.IncrementalBuild
       : EBuildMode.ForceRebuild;
   ```

   Source: [Editor/Builder.BuildAsset.cs#L65](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L65)

   `IsIncrementalBuildPackage`가 `false`(기본값)이거나 `-IsIncrementalBuildPackage`를 전달하지 않으면, 빌드 모드는 `EBuildMode.ForceRebuild`가 됩니다.

## 일반적인 변형

- **리소스 업로드와 증분 빌드를 동시에 수행**: `-IsUploadAsset`와 `-IsIncrementalBuildPackage`를 함께 전달하면 됩니다. 두 플래그는 독립적으로 파싱되며 서로 영향을 주지 않습니다.
- **전체 빌드로 폴백**: 공식 메이저 버전 배포 전에는 이 매개변수를 제거하거나 명시적으로 `false`를 전달할 것을 권장합니다(어떤 플래그도 전달하지 않으면 기본값 `false`). 이를 통해 `EBuildMode.ForceRebuild` 재구축을 강제합니다.

## 일반적인 오류

- **첫 빌드도 증분으로 실행되어 적용 실패로 오인**: 증분 빌드는 이전 출력 캐시에 의존하며, 첫 패키징에는 재사용 가능한 캐시가 없어 결과물이 전체 빌드와 동일한 것은 정상입니다.
- **명령줄에서 하이픈 접두사를 빠뜨림**: `-IsIncrementalBuildPackage`에는 반드시 `-`가 붙어야 합니다. `IsIncrementalBuildPackage`로 작성하면 파싱되지 않아 기본값 `false`로 처리됩니다.
- **`PackageName` 철자 오류 혼용**: 증분 빌드의 캐시는 패키지 이름 디렉터리별로 격리됩니다. `PackageName`을 새로운 이름으로 변경하면 캐시가 일치하지 않아 "전체 빌드처럼 느린" 증상이 나타납니다. 기존 캐시를 재사용할 때는 반드시 `PackageName`을 동일하게 유지하세요.

## 배경(선택 사항)

`IsIncrementalBuildPackage`는 `BuilderOptions`에서 일반적인 불리언 필드일 뿐이며, 실제로 적용되는 위치는 `Builder.BuildAsset`가 그 값을 YooAsset의 `EBuildMode`(증분 vs 강제 재구축)로 매핑하는 곳입니다. 명령줄과 코드라는 두 진입점은 최종적으로 동일한 필드로 모이므로 두 방식의 동작은 일치합니다.
