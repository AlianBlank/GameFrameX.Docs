# 如何將建置產出物上傳至物件儲存體

透過向 Unity 命令列傳入物件儲存相關參數，建置管線可在套件輸出後，自動將日誌、資源、APK 上傳至 S3 協定相容的物件儲存體(OSS/S3/cos 等)。本頁面將解說本儲存庫公開的設定開關與觸發位置，並說明如何將建置產出物推送至遠端儲存桶。

## 前置條件

- 已依照 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md) 將 `com.gameframex.unity.builder` 導入 Unity 專案。
- 已導入實作 `ObjectStorageUploadManager.UploadFile(string)` 的物件儲存 SDK 套件(本儲存庫透過編譯巨集 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 進行連接，若未導入該 SDK,上傳程式碼將不會被編譯)。
- 已備妥物件儲存桶的 `Key`、`Secret`、`BucketName`、`EndPoint`(地區/Endpoint)。

## 操作步驟

1. 在建置機器上準備物件儲存參數。以下 4 個欄位會在 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40) 中被解析：

   | 欄位 | 意義 |
   |------|------|
   | `ObjectStorageKey` | 存取 Key(帳號 AccessKey) |
   | `ObjectStorageSecret` | 存取 Secret |
   | `ObjectStorageBucketName` | 儲存桶(Bucket)名稱 |
   | `ObjectStorageEndPoint` | 儲存桶所在地區的 Endpoint |

2. 在 Unity 命令列中使用 `-ObjectStorageKey`、`-ObjectStorageSecret`、`-ObjectStorageBucketName`、`-ObjectStorageEndPoint` 傳入上述 4 個值。建置指令碼會透過 `Builder.BuildParamsParse` 以反射方式將值設定到 `_builderOptions`。

3. 開啟對應的上傳開關。儲存庫提供 3 個互不衝突的布林值開關。詳細內容請參閱 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L62-L125):

   | 開關 | 預設值 | 作用 |
   |------|--------|------|
   | `IsUploadLogFile` | `false` | 建置準備階段上傳日誌 |
   | `IsUploadAsset` | `false` | 建置資源後上傳資產包 |
   | `IsUploadApk` | `false` | APK 輸出後上傳安裝包 |

4. 以 `BuildReady` 為例，日誌上傳的實際觸發程式碼位於 [Builder.BuildReady.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49):

   ```csharp
   AssetDatabase.Refresh();
   if (_builderOptions.IsUploadLogFile)
   {
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.UploadFile(_builderOptions.LogFilePath);
   #endif
   }
   ```

   Source: [Editor/Builder.BuildReady.cs#L43-L49](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49)

   僅在已定義 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 編譯符號的情況下，`UploadFile` 的呼叫才會被納入建置。否則整個區塊會被前置處理器排除，工作也不會報錯。

5. 觸發建置。選擇以下任一進入點命令，並確認開關已開啟：

   ```bash
   Unity -batchmode -quit -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildReady \
         -ObjectStorageKey <your-key> \
         -ObjectStorageSecret <your-secret> \
         -ObjectStorageBucketName <your-bucket> \
         -ObjectStorageEndPoint <your-endpoint> \
         -IsUploadLogFile true \
         -IsUploadAsset true \
         -IsUploadApk true \
         -logFile -
   ```

   參數會由 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L127-L130) 以反射方式寫入模型，並可在日誌中輸出 `ToString()` 進行驗證。

## 常見變化

- **僅想推送日誌**：只指定 `-IsUploadLogFile true`,其餘兩個上傳開關保持預設的 `false`。
- **僅想推送資源包**：在呼叫 `BuildAsset` 管線時指定 `-IsUploadAsset true`。
- **僅想推送 APK**:在呼叫 `BuildApk` 管線時指定 `-IsUploadApk true`。
- **想依環境隔離**：將 4 個儲存參數放入 CI 的環境變數，並在建置指令碼中再次設定至命令列。

## 常見錯誤

- **執行時回報「找不到 ObjectStorageUploadManager」**:本儲存庫僅保留上傳開關，實際的上傳類別由外部物件儲存 SDK 提供。需要將對應的實作套件安裝至 `Packages/manifest.json`,並在 Player Settings 的 `Scripting Define Symbols` 中加入 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`。否則 `#if` 分支將被排除。
- **在儲存桶中找不到檔案**：請確認 `ObjectStorageEndPoint` 是儲存桶所在地區的 Endpoint(而非控制台的網域名稱)，並確認儲存桶的 ACL 允許該 Key 進行寫入。
- **多個建置同時上傳發生衝突**：建置編號 `BuildNumber` 會用於遠端路徑(在外部 SDK 內組合而成)。在並行執行場景下，必須確保 `BuildNumber` 是唯一的。

## 背景(選讀)

儲存庫採用「開關 + 編譯巨集」的最小耦合設計。`BuilderOptions` 僅負責將命令列參數儲存至模型，實際呼叫 `ObjectStorageUploadManager` 的只有 `BuildReady`、`BuildAsset`、`BuildApk` 三條管線內的上傳分支。若未定義 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`,上傳程式碼將不會納入編譯，即使專案沒有物件儲存的相依性，也能直接使用本工具。
