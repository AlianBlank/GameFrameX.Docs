# 分區表 / 版本控制 / 匯入匯出的宣告方式

只要在實體類別上加入 `PartitionTableAttribute`、`VersionControlAttribute`、`ImportExportAttribute` 這三個特性，即可一次宣告資料庫資料表是否支援分區、是否啟用版本控制，以及是否參與匯入匯出流程。本頁將介紹可直接複製使用的最小範例，以及幾種最常見的變化用法。

## 前置條件

- 需參照 `GameFrameX.Foundation.Orm.Attribute` 命名空間；
- 實體類別必須包含與特性中宣告之欄位同名的屬性(如分區鍵、版本欄位等)；
- 實際的 DDL 由上層 ORM / 移轉工具依據特性產生，因此本文件僅說明宣告方式。

## 操作步驟

### 1. 宣告分區表

在實體類別上加入 `PartitionTableAttribute`,並在建構函式中傳入分區鍵欄位與分區類型。雜湊分區可指定 `PartitionCount`,範圍分區可指定 `Interval`。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[PartitionTable("CreateDate", PartitionType.Range, PartitionInterval.Monthly)]
public class OrderHistory
{
    public int Id { get; set; }
    public int UserId { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreateDate { get; set; }  // 分區鍵
}
```

來源:[PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L63-L91)

選擇性屬性:`AutoCreatePartition`(預設 `true`)、`RetentionDays`(預設 `0`,代表永久保留)、`PartitionValues`(清單分區時指定)、`PartitionCount`(預設 `4`,用於雜湊分區)。

```csharp
[PartitionTable("UserId", PartitionType.Hash, PartitionCount = 16)]
public class UserActivity
{
    public long Id { get; set; }
    public int UserId { get; set; }
    public string Activity { get; set; }
    public DateTime Timestamp { get; set; }
}
```

來源:[PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L82-L89)

### 2. 宣告版本控制

在實體類別上加入 `VersionControlAttribute`,在建構函式中傳入版本欄位名稱，並視需要指定版本策略。實體必須包含同名的版本欄位屬性。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[VersionControl("Version", VersionStrategy.Optimistic)]
public class Document
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }
    public int Version { get; set; }  // 版本號欄位
    public DateTime LastModified { get; set; }
    public string LastModifiedBy { get; set; }
}
```

來源:[VersionControlAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/VersionControlAttribute.cs#L63-L74)

選擇性屬性:`EnableHistory`(預設 `false`)、`HistoryTableName`、`MaxHistoryVersions`(預設 `0`,代表無上限)、`ConflictHandling`(預設 `ThrowException`)、`AutoUpdateVersion`(預設 `true`)、`ComparisonMode`(預設 `Increment`)。

若需要保留歷史版本，可將 `EnableHistory` 設為 `true`,並可指定歷史資料表名稱：

```csharp
[VersionControl("RowVersion", VersionStrategy.Timestamp, EnableHistory = true)]
public class UserProfile
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
    public byte[] RowVersion { get; set; }
}
```

來源:[VersionControlAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/VersionControlAttribute.cs#L76-L83)

### 3. 宣告匯入匯出

在實體類別上加入 `ImportExportAttribute`,並在建構函式中傳入對應的格式與匯入匯出方向。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[ImportExport(ImportExportFormat.Excel, ImportExportDirection.Bidirectional)]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

(程式碼範例基於 `ImportExportAttribute` 的公開建構函式 `ImportExport(ImportExportFormat, ImportExportDirection)`。)

來源:[ImportExportAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/ImportExportAttribute.cs)

## 常見變化

| 情境 | 撰寫方式 | 說明 |
|------|------|------|
| 清單分區 | 在 `PartitionTable("Region", PartitionType.List)` 加上 `PartitionValues = "North,South,East,West"` | 以預先定義的值清單進行分區 |
| 僅匯出 | `ImportExport(ImportExportFormat.Csv, ImportExportDirection.ExportOnly)` | 關閉匯入入口 |
| 僅匯入且啟用驗證 | `ImportExport(ImportExportFormat.Excel, ImportExportDirection.ImportOnly, ValidateOnImport = true)` | 匯入時執行欄位驗證 |
| 三種特性疊加 | 在實體上同時撰寫 `PartitionTable` + `VersionControl` + `ImportExport` | 大型資料表 + 並行處理 + 資料交換的情境 |

`PartitionTableAttribute` 與 `VersionControlAttribute` 皆為 `AllowMultiple = false`,在同一個類別上各僅能宣告一次。`ImportExportAttribute` 同樣僅允許宣告一次。

## 常見錯誤

- **分區鍵或版本欄位不存在**：若實體類別中沒有與 `PartitionKey` / `VersionField` 同名的屬性，移轉或執行階段的驗證就會失敗。請先新增欄位，再加入特性。
- **雜湊分區的 `PartitionCount <= 0`**:建構函式會擲回 `ArgumentOutOfRangeException`,並顯示 `Partition count must be positive.`。必須傳入正整數。
- **`partitionKey` / `versionField` 傳入 `null` 或空白字串**：會觸發 `ArgumentNullException` 或 `ArgumentException.ThrowIfNullOrWhiteSpace`,因此應直接傳入常數字串。
- **清單分區忘記指定 `PartitionValues`**:清單分區必須明確宣告值集合，否則無法確定分區邊界。
- **版本欄位類型與策略不一致**：例如 `VersionStrategy.Timestamp` 對應的欄位應為 `byte[]` 或 `DateTime`,`Optimistic` 則對應 `int/long`。若混用，版本比較將會失敗。
