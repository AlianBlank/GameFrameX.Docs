# "Event manager is invalid." 치명적 오류 해결 방법

이 `Log.Fatal("Event manager is invalid.")` 메시지는 `EventComponent.Awake()`에서 출력됩니다. `GameFrameworkEntry.GetModule<IEventManager>()`가 `null`을 반환하면 이 로그가 출력되고, 이어서 컴포넌트가 곧바로 `return`하면서 `m_EventManager`는 빈 상태로 남아, 이후 모든 이벤트 구독/디스패치 호출에서 NullReferenceException이 발생합니다. 핵심 원인은 **`IEventManager`의 구현 타입이 프레임워크에서 발견되어 등록되지 않은 것**입니다(구현 타입 이름 설정 오류, 이름 변경/네임스페이스 이동, 또는 코드 스트리핑으로 인한 제거).

오류가 발생하는 위치(실제 소스 코드):

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

## 해결 단계

### 1. EventComponent의 구현 타입 설정 확인

`EventComponent`는 `Awake()`에서 리플렉션 `Utility.Assembly.GetType(componentType)`으로 구현 타입을 해석한 뒤, `GameFrameworkEntry.GetModule<IEventManager>()`가 모듈을 가져옵니다. `componentType`는 Inspector에서 직렬화되어 저장되는 문자열이며, 에디터 측에서 `EventComponentInspector`가 후보 목록을 채웁니다:

```csharp
[CustomEditor(typeof(EventComponent))]
internal sealed class EventComponentInspector : ComponentTypeComponentInspector
{
    // ...
    RefreshComponentTypeNames(typeof(IEventManager));
}
```

소스: [EventComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Editor/Inspector/EventComponentInspector.cs#L36-L63)

작업 절차:

1. `EventComponent`가 부착된 GameObject를 선택합니다(기본값은 GameFrameX 루트 오브젝트이며, 컴포넌트 메뉴는 `GameFrameX/Event`입니다).
2. Inspector에서 컴포넌트 타입 드롭다운을 확인하여 선택된 값이 `GameFrameX.Event.Runtime.EventManager`(이 패키지 내 유일한 구현)인지 확인합니다.
3. 비어 있거나 빨간색/누락(Missing)으로 표시되면 `EventManager`를 다시 선택하고 씬과 관련 프리팹을 저장합니다.
4. 다시 Play 모드로 진입하여 확인합니다.

### 2. EventManager 구현 타입이 스트리핑되지 않았는지 확인

이 패키지의 구현 클래스에는 `[UnityEngine.Scripting.Preserve]` 보호가 함께 적용되어 있습니다:

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class EventManager : GameFrameworkModule, IEventManager
{
    private readonly EventPool<GameEventArgs> m_EventPool;

    public EventManager()
    {
        m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
    }
}
```

소스: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L38-L49)

작업 절차:

1. Player Settings에서 `Managed Stripping Level`을 활성화했거나 IL2CPP를 사용하는 경우, 패키지 내 `Preserve` 어트리뷰트가 제거되지 않았는지 확인하세요(어셈블리의 스트리핑 면제 설정은 변경하지 마세요). 이 패키지는 스트리핑 환경에서의 보조 처리를 위해 [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs)도 함께 제공합니다.
2. `Runtime` 어셈블리(`GameFrameX.Event.Runtime` 네임스페이스)가 실제로 빌드에 포함되는지 확인합니다(asmdef의 플랫폼 선택 여부, Build에서 수동으로 제외되지 않았는지).

### 3. GameFrameX/Event 컴포넌트 재구성

컴포넌트가 복사해 온 프리팹에서 가져온 것이고 직렬화 데이터가 이미 유효하지 않은 경우:

1. GameObject에서 현재 `EventComponent`를 제거합니다(컴포넌트에 `[DisallowMultipleComponent]`가 지정되어 있어 동일한 오브젝트에 중복 부착할 수 없습니다).
2. `Add Component → GameFrameX → Event`를 통해 다시 추가합니다. 컴포넌트 정의는 다음과 같습니다:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Event")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-7000)]
public sealed class EventComponent : GameFrameworkComponent
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)

3. `GameFrameworkEntry`가 속한 GameFrameX 기본 런타임 패키지가 설치되어 있고 참조되고 있는지 확인합니다(`GetModule<T>`는 이를 통해 모듈 등록 스캔을 수행함).
4. 씬을 저장한 후 다시 Play 모드로 진입합니다.

## 검증

- 시작 시 Console에 더 이상 `Fatal: Event manager is invalid.`가 출력되지 않습니다.
- 임의의 스크립트에서 이벤트 컴포넌트의 읽기 전용 속성에 접근해도 더 이상 null 참조가 발생하지 않습니다. 예: `EventCount` / `EventHandlerCount`(내부적으로 `m_EventManager`로 직접 전달됨, [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L50-L61) 참조).
- `Check(id, handler)` 또는 `Subscribe(id, handler)`를 한 번 호출하면 정상적으로 반환/등록되며, `Count(id)` 카운트도 예상과 일치합니다.
