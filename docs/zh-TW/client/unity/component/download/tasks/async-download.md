# 使用 await 非同步等待下載完成

`DownloadComponent` 提供了一個回傳 `Task<bool>` 的 `Download` 方法，可直接在協程或非同步方法裡用 `await` 等待檔案下載完成，無需訂閱事件回呼。

## 前置條件

- 場景中已掛載 `DownloadComponent` 元件(透過 `[GameFrameXAutoComponent(-4000)]` 自動註冊)。
- 業務程式碼能拿到 `DownloadComponent` 實例，通常透過 `GameEntry.GetComponent<DownloadComponent>()` 取得。

## 操作步驟

1. 呼叫 `DownloadComponent.Download(downloadPath, downloadUri)`,取得一個 `Task<bool>`。
2. 在 `async` 方法裡 `await` 這個任務，值為 `true` 表示下載成功，`false` 表示失敗或下載未開始。
3. 依回傳值決定後續邏輯(載入資源、提示錯誤等)。

最小可用範例：

```csharp
using System.Threading.Tasks;
using GameFrameX.Download.Runtime;

public async Task LoadRemoteConfigAsync()
{
    var download = GameEntry.GetComponent<DownloadComponent>();
    bool ok = await download.Download(
        downloadPath: Application.persistentDataPath + "/config.json",
        downloadUri:  "https://example.com/config.json");

    if (ok)
    {
        // 讀取本機檔案繼續後續邏輯
    }
    else
    {
        // 下載失敗時的回退處理
    }
}
```

## 常見變體

- 帶標籤或優先順序的版本依然走原 `AddDownload` 流程,`Download` 方法目前僅暴露最常用的 `(path, uri)` 多載。如需自訂標籤或優先順序，可繼續使用 `AddDownload` + 事件方式。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| `await` 永遠不回傳,值一直是 `false` | 下載任務尚未進入下載管理器,`m_Downloads.TryGetValue` 失敗,直接回傳了一個已 `TrySetResult(false)` 的任務 | 確認路徑與 URI 合法,並確保 `DownloadComponent` 已 `Start`(相依於 `EventComponent` 與 `m_DownloadManager`) |
| 呼叫處出現 `NullReferenceException` | 業務側 `DownloadComponent` 未在場景中或尚未 Awake | 透過 `GameEntry.GetComponent<DownloadComponent>()` 取得,並先判斷是否為 null |
| 多任務並行時，回傳的 `Task` 互相覆蓋 | `Download` 方法根據 `serialId` 在內部字典中尋找對應的 `TaskCompletionSource<bool>` | 不同下載使用獨立的 `await` 變數接收，避免混用回傳值 |

## 背景(選用)

內部使用 `ConcurrentDictionary<int, DownloadData>` 維護 `serialId` 到 `TaskCompletionSource<bool>` 的映射;`Awake` 中訂閱 `DownloadSuccess` / `DownloadFailure` 事件，在回呼裡呼叫 `TrySetResult(true/false)`,從而把事件式 API 轉成 `Task` API。
