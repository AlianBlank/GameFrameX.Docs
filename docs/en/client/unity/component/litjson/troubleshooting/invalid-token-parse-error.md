# What to Do When an Invalid Token Parsing Exception Occurs

When LitJSON encounters an unrecognizable lexical token (`ParserToken`) while parsing a JSON string, it throws a `JsonException` with the message `"Invalid token '{0}' in input string"`. This page helps you quickly identify the root cause of this exception and fix it.

## Quick Diagnosis

| Symptom (Exception Message) | Cause | Fix |
|----------------|------|------|
| `Invalid token 'X' in input string` (token is a single character) | Unexpected characters appear in the JSON (such as unescaped quotes, comments, trailing commas) | Remove or escape illegal characters, ensuring compliance with the JSON specification |
| `Invalid token 'X' in input string` (token is a number) | Incorrect numeric literal (such as `1.`, `0x1A`, extra symbols) | Correct the number format, only use decimals, with optional decimal point and exponent |
| `Invalid token 'True' / 'False' / 'Null'` | Boolean or null written in PascalCase, e.g. `True` | Use the all-lowercase `true` / `false` / `null` required by JSON |
| `Invalid token 'CharSeq'` | Illegal characters appear inside the string (such as unmatched escape characters, control characters) | Check string escaping; common legal escapes are `\" \\ \/ \b \f \n \r \t \uXXXX` |
| `Invalid token 'End'` or parsing ends prematurely | JSON truncated early — brackets/quotes not closed | Add the missing `{` `}` `[` `]` `"` in the editor |

The exception message template is defined as follows, where the content inside the braces is the `ParserToken` enum value from the Lexer stage:

```csharp
// Runtime/JsonException.cs
internal JsonException(ParserToken token) :
    base(string.Format(
             "Invalid token '{0}' in input string", token))
{
}
```

## Fix Steps

### 1. Locate the Position of the Erroneous Character

Compare the token in the exception (in the single-character case) with the original JSON string to locate the first illegal character. LitJSON's `JsonReader` scans from left to right and throws an error when it encounters the first unrecognizable character.

```csharp
// Runtime/JsonReader.cs
TableAddCol(parse_table, ParserToken.ArrayPrime, '[',
            (int)ParserToken.Value,
            (int)ParserToken.ValueRest,
            ']');
```

Source: [JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs#L266-L274)

### 2. Fix Common Illegal Characters

The following notations are invalid in standard JSON, and LitJSON will directly throw `Invalid token`:

- Single-quoted strings `'foo'` — must be changed to double quotes `"foo"`
- Comments `// xxx` or `/* xxx */` — JSON does not support comments, they need to be removed
- Trailing commas `{ "a": 1, }` — there must be another element after the comma
- PascalCase boolean/null `True` / `False` / `Null` — must be `true` / `false` / `null`
- Unescaped control characters or bare newlines — newlines inside strings need to be escaped with `\n`

### 3. Fix Common Illegal Numbers

An `Invalid token` triggered by `ParserToken.Number` is usually a number format issue. Legal numbers must be decimal, with optional decimal point and exponent:

- Legal: `0`, `-1`, `3.14`, `-2.5e10`, `1.0E+3`
- Illegal: `1.` (no digits after the decimal point), `01` (leading zero), `0x1A` (hexadecimal), `NaN`, `Infinity`, `+1` (extra sign), `1,000` (thousands separator comma)

### 4. Validate with a Minimal Reproducible Example

After fixing, use a minimal executable snippet to verify that your JSON can be parsed correctly:

```csharp
using GameFrameX.LitJSON.Runtime;

string json = "{\"name\":\"litjson\",\"v\":1}";
JsonData data = JsonMapper.ToObject(json);
Debug.Log(data["name"]); // Output: litjson
Debug.Log(data["v"]);    // Output: 1
```

If `Invalid token` is still reported, please provide the token value from the exception message and a snippet of the original string (including a few characters before and after the error position) to the upstream data source provider.

## Validation

1. Run the fixed JSON parsing code in the Unity Editor's Console to confirm that no `JsonException` is thrown.
2. Use an online JSON validation tool (such as jsonlint.com) to validate the input string and get a "Valid JSON" result.
3. If the JSON comes from the network or an external file, add try/catch and print `e.Message` to help locate the specific error position:

```csharp
try
{
    var data = JsonMapper.ToObject(rawJson);
}
catch (JsonException e)
{
    Debug.LogError($"Parsing failed: {e.Message}");
}
```
