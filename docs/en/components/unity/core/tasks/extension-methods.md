# Simplify Unity APIs with Extension Methods

GameFrameX provides a large number of extension methods for Unity built-in types (`GameObject`, `Transform`, `Vector2/3/4`, `Component`, etc.), mounting new behavior directly onto the original types so you can complete common operations with less boilerplate code. This page lists the most commonly used extension methods by type and provides ready-to-copy examples.

## Steps

### 1. Import the Namespace

All extension methods are located in the `GameFrameX.Runtime` namespace. Add it at the top of the file to use all extensions.

```csharp
using GameFrameX.Runtime;
```

### 2. Operate on `GameObject` / `Component`

`GetOrAddComponent` and `DestroyComponent` are the two most common component-level extensions.

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class Player : MonoBehaviour
{
    private Rigidbody _rigidbody;

    void Awake()
    {
        // Add automatically if it does not exist, return directly if it does
        _rigidbody = gameObject.GetOrAddComponent<Rigidbody>();
    }

    void OnDisable()
    {
        // Destroy a component of the specified type
        gameObject.DestroyComponent<Rigidbody>();

        // Or call from the Component itself to destroy a component of the same type on the same GameObject
        _rigidbody.DestroyComponent();
    }
}
```

### 3. Find and Set Single Axis on `Transform`

`FindChildName` supports depth-first search for child nodes at any level; `SetPositionX/Y/Z` is used to modify only one axis of the world position, avoiding reading out the whole group and writing it back.

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class Enemy : MonoBehaviour
{
    public Transform weaponSlot;

    void Start()
    {
        // Depth search for a child node named "WeaponSocket"
        var socket = transform.FindChildName("WeaponSocket");
        if (socket != null)
        {
            weaponSlot = socket;
        }

        // Modify only the X axis of the world position
        transform.SetPositionX(10f);
    }
}
```

### 4. Convert Between `Vector2 / Vector3 / Vector4`

Different UI and physics calls have different preferences for vector types. Use `ToVector2 / ToVector3 / ToVector4` to switch dimensions in one line.

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class CameraShake : MonoBehaviour
{
    public Vector3Int gridPos;

    void Update()
    {
        // Vector3Int → Vector3
        Vector3 worldPos = gridPos.ToVector3();

        // Vector3 (x, y, z) → Vector2 (x, z), ignoring Y
        Vector2 topDown = worldPos.ToVector2();

        // Vector3 → Vector4, w defaults to 0
        Vector4 homogeneous = worldPos.ToVector4();
    }
}
```

### 5. Quick String Comparison and Null Check

`EqualsFast` compares character by character from the tail to the head, avoiding the extra overhead of `string.Equals` on some platforms; `IsNotNull` / `IsNull` are object null-check extensions provided by `ObjectExtension`.

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class NameTag : MonoBehaviour
{
    public string targetName = "Player";

    void Update()
    {
        // Quickly compare whether two strings are equal
        if (transform.name.EqualsFast(targetName))
        {
            Debug.Log("Match");
        }

        // Null check, equivalent to != null, but does not call Unity's overloaded ==
        if (this.IsNotNull())
        {
            // ...
        }
    }
}
```

## Common Mistakes

- **Forgot `using GameFrameX.Runtime;`** — Extension methods must be visible to be called; if the IDE shows red, check the namespace first.
- **`gameObject.DestroyComponent()` without generic** — This method only returns and destroys a component of the same type when called on the `Component` itself; for `GameObject` you must pass the generic `DestroyComponent<T>()`.
- **Confusing `FindChildName` with `Transform.Find`** — `Transform.Find` can only find direct child nodes; use `FindChildName` when cross-level lookup is needed.
- **`EqualsFast` returns true on two nulls** — Same behavior as `string.Equals`, but note that it does not do culture (locale)-sensitive comparison; for localization scenarios, still use `string.Equals`.

## Background (Optional)

Extension methods in C# are attached to existing types via the `this T self` modifier, and at the IL level they are compiled into ordinary static methods. GameFrameX encapsulates common Unity boilerplate (such as `GetComponent` + `AddComponent`, `Find` depth search, vector dimension conversion) into extensions, retaining the zero-allocation benefit of static calls while gaining chainable syntax and IDE IntelliSense. All extension classes are marked with `[UnityEngine.Scripting.Preserve]` to ensure they remain available after IL2CPP / code stripping.
