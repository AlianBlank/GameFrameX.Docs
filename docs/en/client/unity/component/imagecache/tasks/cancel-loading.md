# How to Cancel an In-Progress Image Load

By passing a `CancellationToken` to cancel the load task, `LoadImageAsync` will abort subsequent processing at an appropriate point and return `null`; the cancellation mechanism only takes effect on non-WebGL platforms and will not immediately interrupt the network request during download.

## Prerequisites

- The image cache component has been obtained via `GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>()`.
- The target build platform is not WebGL (on WebGL the `cancellationToken` will be ignored, see "Common Errors" below).

## Steps

1. **Create a cancellable token source**. Use `CancellationTokenSource` to generate a token and pass it to the loading API through the `Token` property.

   ```csharp
   using System.Threading;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   var component = GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>();
   var cts = new CancellationTokenSource();
   ```

2. **Initiate the load and pass in the token**. Call `LoadImageAsync(url, cts.Token)` to get a `Task<Texture2D>`.

   ```csharp
   var task = component.LoadImageAsync("https://example.com/foo.png", cts.Token);
   ```

3. **Call `Cancel()` at an appropriate time**. Trigger cancellation when a page is closed, a list item is recycled, etc.:

   ```csharp
   cts.Cancel();
   ```

4. **Handle the return result**. A cancelled task returns `null` (without throwing an exception); just follow the failure branch:

   ```csharp
   var tex = await task; // returns null when cancelled
   if (tex == null) return;
   ```

   Source: [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## Common Variations

- **Bind to `MonoBehaviour` lifecycle for automatic cancellation**: Tie the `CancellationTokenSource` to the GameObject lifecycle (e.g., a custom `MonoBehaviour` calls `cts.Cancel()` in `OnDestroy`), so no manual management is needed when switching scenes.
- **Timeout cancellation**: `cts.CancelAfter(TimeSpan.FromSeconds(5))` sets an automatic timeout cancellation.
- **Cancel multiple tasks by condition**: Share a single `CancellationTokenSource` across a group of `LoadImageAsync` calls with the same token, and abort all of them with a single `Cancel()`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| On WebGL platform, the task still completes after calling `Cancel()` | `LoadImageAsync` does not accept `cancellationToken` under the `#if UNITY_WEBGL` branch, see [ImageCacheManager.cs#L84-L85](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L85) | On WebGL, you need to discard the returned Texture2D yourself via business-layer flags |
| After cancellation the download still runs in the background and a cache file appears on disk | The current implementation only checks the token **after a successful download**, and will not interrupt the in-progress download, see [ImageCacheManager.cs#L139-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L139-L149) | If you need to fully stop the request, actively remove the task via `_downloadManager` before cancellation, or ignore the download result at the business layer |
| Awaiting the task after `Cancel()` throws `OperationCanceledException` | This API does not use `ThrowIfCancellationRequested`; a cancelled call uniformly returns `null`, see [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149) | Use `if (tex == null)` to check for cancellation; do not catch `OperationCanceledException` |

## Verification

After successful cancellation, the following two conditions indicate normal behavior:

- `await LoadImageAsync(...)` returns `null`.
- No `OperationCanceledException` is thrown, and there are no subsequent image decoding logs (because it directly `return null` after detecting cancellation).

## Background (Optional)

The non-WebGL branch of `LoadImageAsync` only checks `IsCancellationRequested` once between "download complete → about to read the local file", so the actual semantics of cancellation is "abandon this result after the download finishes", rather than interrupting the network request. On the WebGL platform, since it is implemented through `UnityWebRequestTexture` + browser cache, the method signature does not expose a token, and the caller can only decide whether to use the result after receiving it.
