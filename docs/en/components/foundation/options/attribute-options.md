# How to Use Attributes on a Class to Map Arguments and Environment Variables

By adding attributes such as `Option`, `EnvironmentVariable`, and `FlagOption` to class properties, you can let `OptionsBuilder` automatically bind command-line arguments and environment variables to strongly-typed properties, without writing parsing code manually.

## Prerequisites

- Reference the `GameFrameX.Foundation.Options` assembly.
- `using GameFrameX.Foundation.Options.Attributes;` (optional, only for using short names).
- Your options class must have a parameterless constructor (constraint `where TOptions : class, new()`).

## Steps

### 1. Define an Options Class with Attributes

The `EnvironmentVariable` property of `Option` directly declares the environment variable name corresponding to the option; the `EnvironmentVariable` attribute is used for scenarios where the property is "read only from environment variables, not exposed as a command-line argument".

```csharp
using GameFrameX.Foundation.Options.Attributes;

public class MyOptions
{
    // Command-line option + environment variable: --port or TEST_PORT
    [Option("port", DefaultValue = 8080, EnvironmentVariable = "TEST_PORT")]
    public int Port { get; set; }

    // Long name + environment variable + default value
    [Option(LongName = "host", EnvironmentVariable = "TEST_HOST", DefaultValue = "localhost")]
    public string Host { get; set; }

    // Boolean switch, no value needed
    [FlagOption(LongName = "verbose")]
    public bool Verbose { get; set; }

    // Required
    [Option(LongName = "api-key", Required = true)]
    public string ApiKey { get; set; }
}
```

### 2. Build in One Line with `OptionsBuilder`

`OptionsBuilder` provides multiple static entry points to construct objects from command-line arguments, environment variables, a combination of both, or default values only.

```csharp
using GameFrameX.Foundation.Options;

// Command-line arguments only
var opts1 = OptionsBuilder.Create<MyOptions>(args);

// Mixed command-line + environment variables (default behavior)
var opts2 = OptionsBuilder.Create<MyOptions>(
    args,
    boolFormat: BoolArgumentFormat.TrueFalse,
    ensurePrefixedKeys: true,
    useEnvironmentVariables: true);

// Environment variables only
var opts3 = OptionsBuilder.CreateFromEnvironmentOnly<MyOptions>();

// Command-line only, ignoring environment variables
var opts4 = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);

// Default values only (suitable for testing)
var opts5 = OptionsBuilder.CreateDefault<MyOptions>();
```

Source: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L122)

### 3. Bind Environment-Only Properties with the `EnvironmentVariable` Attribute

When a property should only be read from environment variables and should not appear in the command-line help, using the `EnvironmentVariable` attribute is more direct.

```csharp
public class MyOptions
{
    [EnvironmentVariable("DATABASE_URL")]
    public string DatabaseUrl { get; set; }

    [EnvironmentVariable("API_KEY")]
    public string ApiKey { get; set; }
}

var options = OptionsBuilder.CreateFromEnvironmentOnly<MyOptions>();
Console.WriteLine(options.DatabaseUrl);
```

Source: [EnvironmentVariableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/EnvironmentVariableAttribute.cs#L43-L54)

### 4. Validate Required Properties

`Build(skipValidation: false)` validates that all properties marked with `Required = true` have been assigned a value (via command line or environment variables).

```csharp
// No --api-key provided, this throws an exception
var options = OptionsBuilder.Create<MyOptions>(new[] { "--port", "9090" });

// Skip the required-property check, suitable for default-value scenarios
var defaults = OptionsBuilder.CreateDefault<MyOptions>();
```

## Common Variants

- **Boolean switch**: `[FlagOption]` makes a boolean property appear only as `--verbose`, without passing `true`/`false`. Source: [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L20)
- **Sensitive information masking**: Add `Sensitive = true` to `Option`, and `OptionsDebugger` will automatically mask the value in output. Source: [OptionAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/OptionAttribute.cs#L104-L112)
- **Combining multiple attributes**: When the same property is decorated with both `Option` and other attributes, the builder treats `Option` as the primary attribute. Source: [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L28-L32)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Build()` throws "missing required option" | A property with `Required = true` did not receive a value from the command line or environment variables | Provide the argument, or call `Build(skipValidation: true)` in test scenarios |
| Environment variables not taking effect | `useEnvironmentVariables: false` was explicitly passed when constructing `OptionsBuilder`, or `CreateFromArgsOnly` was used | Switch to `Create<TOptions>(args)` (defaults to `true`) or `CreateFromEnvironmentOnly<TOptions>()` |
| Properties without attributes are ignored | The framework only parses attributed properties; plain properties keep their type default values | Add `Option`, `FlagOption`, or `EnvironmentVariable` to the properties you want to bind |

## Background (Optional)

`OptionsBuilder<T>` uses reflection to iterate over the public properties of `T` and, based on attribute metadata, decides whether to take values from command-line arguments, environment variables, or defaults; `EnvironmentVariableAttribute` and `OptionAttribute.EnvironmentVariable` are two entry points to the same mechanism — the former suits "environment-variable-only" properties, while the latter suits "command-line + environment variable" overridable properties.
