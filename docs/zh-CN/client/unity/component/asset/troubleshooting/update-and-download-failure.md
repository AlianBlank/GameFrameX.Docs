# 热更新卡住、下载失败或版本不一致怎么办

当你在热更新流程(基于 YooAsset 的 HostPlayMode)中出现"流程卡在某个状态不动"、"补丁下载报错"、或"客户端版本与远端清单对不上"时,按本页表格与步骤定位修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 流程卡在 `UpdateStaticVersion`(获取远端 `PackageVersion` 失败) | `hostServerURL` 不可访问,或远端没有发布 `PackageVersion` 文件 | 见 [修复步骤 §1](#修复步骤) |
| 流程卡在 `UpdateManifest`(清单拉取失败) | `fallbackHostServerURL` 没配、清单路径错误、或 `AppVersion` 与远端不一致 | 见 [修复步骤 §2](#修复步骤) |
| `CreateDownloader` 为空 / 没有需要下载的文件 | 本地缓存已覆盖当前 `PackageVersion`,或 `AppVersion` 不匹配导致清单里无可下载项 | 见 [修复步骤 §3](#修复步骤) |
| `DownloadWebFiles` 中途失败、个别文件报错 | 单文件下载失败;受 `FailedTryAgain` 与 `VerifyLevel` 影响 | 见 [修复步骤 §4](#修复步骤) |
| 启动报 "远端版本与本地不兼容" | 客户端 `AppVersion` < 远端最低支持版本 | 见 [修复步骤 §5](#修复步骤) |

`EPatchStates` 枚举值定义如下,用于日志对照:

Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L32)

```csharp
public enum EPatchStates
{
    UpdateStaticVersion,
    UpdateManifest,
    CreateDownloader,
    DownloadWebFiles,
    PatchDone,
}
```

## 修复步骤

### §1 卡在 UpdateStaticVersion

1. 检查传入的 `hostServerURL`,确认能直接在浏览器打开并返回文本 `PackageVersion`(YooAsset 默认布局)。
2. 确认打包机已发布该资源包;远端目录至少要包含 `PackageVersion.txt` / `GameVersion.txt`。
3. 若启用 CDN,确认 CDN 回源地址指向真实的资源服务器。

### §2 卡在 UpdateManifest

1. 必须同时提供 `fallbackHostServerURL`(备用地址)。`HostPlayMode` 初始化时使用了 `RemoteServices` 把两者都传给 YooAsset。

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L148-L164)

```csharp
private InitializationOperation InitializeYooAssetHostPlayMode(
    ResourcePackage resourcePackage,
    string hostServerURL,
    string fallbackHostServerURL)
{
    var remoteServices = new RemoteServices(hostServerURL, fallbackHostServerURL);
    var createParameters = new HostPlayModeParameters
    {
        BuildinFileSystemParameters = FileSystemParameters.CreateDefaultBuildinFileSystemParameters(),
        CacheFileSystemParameters   = FileSystemParameters.CreateDefaultCacheFileSystemParameters(remoteServices),
    };
    return resourcePackage.InitializeAsync(createParameters);
}
```

2. 确认客户端 `AppVersion` 不高于远端 `GameVersion.txt`(YooAsset 会按 AppVersion 过滤清单)。
3. 看日志中 YooAsset 返回的清单 URL,手动在浏览器打开应能下载 `PackageManifest_{AppVersion}_{PackageVersion}.hash` 与 `.bytes`。

### §3 CreateDownloader 为空

1. 如果刚清过缓存或首次安装,这是预期行为,跳过下载直接进入游戏即可。
2. 如果不应该为空(确实有新资源),通常是 `AppVersion` 选错导致清单内容错误,回到 §2 检查版本号。

### §4 DownloadWebFiles 失败

可通过 `IAssetManager` 上的两个参数调节下载行为:

Source: [IAssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L13-L41)

```csharp
/// 同时下载的最大数目。
int DownloadingMaxNum { get; set; }

/// 失败重试最大数目。
int FailedTryAgain { get; set; }

/// 获取或设置下载文件校验等级。
EFileVerifyLevel VerifyLevel { get; }
```

1. 适当提高 `DownloadingMaxNum`(默认较小值,高带宽可调到 10~20)。
2. 适当提高 `FailedTryAgain`,避免网络抖动直接判失败。
3. 若大量 CDN 文件 404,先去构建产物目录核对文件名;YooAsset 远端布局需与构建时一致。
4. 若怀疑文件被劫持或损坏,把 `VerifyLevel` 提到更高级别(由 `EFileVerifyLevel` 枚举决定),YooAsset 会校验文件哈希。

### §5 远端版本与本地不兼容

YooAsset 在 `UpdateManifest` 阶段会校验 `AppVersion`,低于远端要求的版本会被拒绝。处理方式:

1. 把客户端 `Player Settings.bundleVersion` 或调用 `InitPackageAsync` 时传入的版本号升到 `>=` 远端 `GameVersion.txt`。
2. 重新出包再发版;不要试图在老客户端上绕过。

## 验证

1. 观察进度回调能完整经过 `UpdateStaticVersion → UpdateManifest → CreateDownloader → DownloadWebFiles → PatchDone`,没有跳过或卡死。
2. YooAsset 缓存目录(如 `Application.persistentDataPath/yooasset/{packageName}/` )里能看到本次版本对应的 `.bytes` / `.hash` 缓存文件。
3. 进入游戏后,所有热更资源能正常加载,不再回退到内置包。
