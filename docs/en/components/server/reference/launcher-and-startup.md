# Launcher and Startup Item Reference (Program.cs / AppStartUpGame)

This page is a reference for the game server startup entry point and its default startup configuration. `Program.cs` defines the process entry point and logging strategy; `AppStartUpGame` is the game server startup item, responsible for initializing Actor limits, the database, components, and hot-update modules in order, then entering the main loop.

## Startup Entry Point (Program.cs)

The startup entry point is located in the `GameFrameX.Launcher` assembly. `Main` does only three things: set logging options based on the compilation mode, call the framework entry point `GameApp.Entry`, and pass in callbacks to complete cache and protocol initialization.

```csharp
internal static class Program
{
    private static async Task Main(string[] args)
    {
#if DEBUG
        LogOptions.Default.IsConsole = true;
#endif
        await GameApp.Entry(args, () =>
        {
            CacheStateTypeManager.Init();
            MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
        }, LogAction);
    }

    private static void LogAction(LogOptions options)
    {
#if DEBUG
        options.IsConsole = true;
#else
        options.IsConsole = false;
#endif
    }
}
```

### Key Behavior Quick Reference

| Item | Value / Behavior | Description |
|------|-------------|------|
| Entry method | `static async Task Main(string[] args)` | Standard async Main, accepts command-line arguments |
| DEBUG build | `LogOptions.IsConsole = true` | Console logs visible during development |
| Release build | `LogOptions.IsConsole = false` | No console output after release |
| Framework entry | `GameApp.Entry(args, initAction, logAction)` | Starts the GameApp runtime |
| Initialization callback | `CacheStateTypeManager.Init()` | Registers cache state types |
| Initialization callback | `MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly)` | Scans the assembly containing message protocol handlers |
| Logging callback | `LogAction(LogOptions)` | Overrides `IsConsole` again based on compilation mode |

## Startup Item (AppStartUpGame)

`AppStartUpGame` is tagged as a `Game` type server via the attribute `[StartUpTag(GameServerConst.Game.Name)]` and inherits from `AppStartUpBase`. `StartAsync` is the main startup flow, and `Init` constructs the default `AppSetting` as needed.

```csharp
[StartUpTag(GameServerConst.Game.Name)]
internal sealed class AppStartUpGame : AppStartUpBase
{
    public override async Task StartAsync() { /* See the table below for step order */ }

    protected override void Init()
    {
        if (Setting == null)
        {
            Setting = new AppSetting { /* Default values are listed in the table below */ };
        }
        base.Init();
    }
}
```

### StartAsync Startup Order

| Step | Action | Key Calls |
|------|------|----------|
| 1 | Prepare the `hotfix` directory | `Directory.Exists` / `Directory.CreateDirectory` |
| 2 | Initialize Actor limits | `ActorLimit.Init(ActorLimit.RuleType.None)` |
| 3 | Start the database service | `GameDb.Init<MongoDbService>(...)`, throws `InvalidOperationException("数据库服务启动失败")` on failure |
| 4 | Register components | `ComponentRegister.Init(typeof(AppsHandler).Assembly)` |
| 5 | Load hot-update modules | `HotfixManager.LoadHotfixModule(Setting)` |
| 6 | Mark the runtime as started | `GameAppRuntime.MarkStarted(...)` |
| 7 | Wait for the exit signal | `await AppExitToken` |
| 8 | Stop hot updates | `await HotfixManager.Stop(exitMessage)` |

Exception path: any exception thrown at any step is caught by `catch (Exception e)`; after logging, it proceeds to step 8 to stop hot updates and then exits the process.

### Default AppSetting Fields

`Init()` constructs the default `AppSetting` when `Setting == null`. The field meanings and default values are as follows:

| Field | Type/Value | Default Value | Description |
|------|-----------|--------|------|
| `ServerId` | `int` | `GameServerConst.Game.Id` | Unique server ID |
| `ServerType` | `string` | `GameServerConst.Game.Name` | Server type name (corresponds to `[StartUpTag]`) |
| `IsEnableTcp` | `bool` | `true` | Enable TCP |
| `InnerPort` | `int` | `29100` | Internal TCP port |
| `MetricsPort` | `int` | `29090` | Metrics port |
| `IsEnableHttp` | `bool` | `true` | Enable HTTP |
| `HttpPort` | `int` | `28080` | HTTP port |
| `IsEnableWebSocket` | `bool` | `true` | Enable WebSocket |
| `WsPort` | `int` | `29110` | WebSocket port |
| `HttpIsDevelopment` | `bool` | `true` | HTTP development mode |
| `MinModuleId` | `int` | `10` | Lower bound of module message IDs |
| `MaxModuleId` | `int` | `9999` | Upper bound of module message IDs |
| `TagName` | `string` | `"GameFrameX"` | Log/trace tag |
| `DataBaseUrl` | `string` | Built-in MongoDB connection string in the repository | Mongo connection URL |
| `DataBaseName` | `string` | `"gameframex"` | Mongo database name |

## Common Errors

| Symptom | Trigger Condition | Troubleshooting Direction |
|------|----------|----------|
| Startup throws `InvalidOperationException: 数据库服务启动失败` | `GameDb.Init<MongoDbService>` returns `false` | Check whether `DataBaseUrl` / `DataBaseName` are reachable, and verify Mongo network accessibility |
| No console logs visible in the Release package | Not compiled with `DEBUG` | `Program.LogAction` forcibly sets `IsConsole` to `false`; this is expected behavior |
| Hot-update directory missing | `hotfix` does not exist | The startup process automatically calls `CreateDirectory`, so no manual creation is needed; insufficient permissions will throw an exception |
| `AppSetting` overridden externally | The caller assigned a value before `Init()` | `Init()` only fills in defaults when `Setting == null`; if you inject before startup, the value you pass in takes precedence |
