# 如何设置玩家 ID 与公共属性

通过 `IGameAnalyticsManager` 接口的 `SetPlayerId(string playerId)` 与 `SetPublicProperties(string key, object value)` 两个调用,即可在游戏运行期为所有后续上报事件附加玩家标识与公共属性。框架在初始化时已自动写入一组设备公共属性,你只需追加业务字段。

## 前置条件

- 项目已安装 `com.gameframex.unity.gameanalytics` 包并挂载 `GameAnalyticsComponent` 组件。
- 已调用 `Init` / `ManualInit` 完成初始化(可用 `IsInit()` 确认)。

## 操作步骤

1. 获取管理器实例(通过 `GameAnalyticsComponent` 暴露的管理器接口)。
2. 在玩家登录成功后设置玩家 ID:

```csharp
// 玩家登录成功后,绑定玩家 ID(后续所有事件都会携带该 ID)
GameAnalyticsComponent.Instance.SetPlayerId("123456789");
```

`SetPlayerId` 的接口签名为 `void SetPlayerId(string playerId)`,定义在 `IGameAnalyticsManager` 中,基类 `BaseGameAnalyticsManager` 中声明为抽象方法,由具体平台子类实现:

```csharp
/// <summary>
/// 设置玩家ID
/// </summary>
/// <param name="playerId">玩家ID</param>
void SetPlayerId(string playerId);
```

Source: [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L100-L104)

3. 追加业务公共属性,每次设置一个键值对:

```csharp
// 每次调用写入一个 Key,重复设置同一 Key 会覆盖旧值
GameAnalyticsComponent.Instance.SetPublicProperties("server_id", "s1001");
GameAnalyticsComponent.Instance.SetPublicProperties("vip_level", 5);
```

基类实现会忽略空 Key 并写入内部字典 `m_PublicProperties`:

```csharp
public virtual void SetPublicProperties(string key, object value)
{
    if (string.IsNullOrEmpty(key))
    {
        return;
    }

    m_PublicProperties[key] = value;
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L53-L65)

4. (可选)读取或清空公共属性:

```csharp
// 读取:返回内部字典的副本,修改副本不影响真实公共属性
Dictionary<string, object> props = GameAnalyticsComponent.Instance.GetPublicProperties();

// 清空业务属性;随后会自动重新写入设备信息公共属性
GameAnalyticsComponent.Instance.ClearPublicProperties();
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L67-L83)

## 内置的设备公共属性

初始化阶段框架会通过 `AddDeviceInfoToPublicProperties()` 自动写入以下公共属性,你无需手动设置,且 `ClearPublicProperties()` 后会自动恢复:

| 分类 | 属性 Key |
|------|----------|
| 设备 | `device_id`、`device_model`、`device_type` |
| 操作系统 | `os` |
| 应用 | `app_version`、`unity_version`、`platform` |
| 硬件 | `processor_type`、`processor_count`、`processor_frequency`、`system_memory_size` |
| 图形 | `graphics_device_name`、`graphics_device_type`、`graphics_memory_size`、`graphics_device_version`、`graphics_shader_level` |
| 屏幕 | `screen_width`、`screen_height`、`screen_dpi`、`screen_refresh_rate` |
| 本地化 | `system_language`、`current_culture` |
| 网络 | `network_type`(取值 `No Network` / `Mobile Data` / `WiFi` / `Unknown`) |

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L86-L144)

## 常见变体

- **切换账号**:先 `ClearPublicProperties()` 清掉旧账号业务字段,再重新 `SetPlayerId` 与 `SetPublicProperties`。清空后会自动恢复设备信息属性。
- **覆盖内置属性**:自定义 Key 与上表相同时会直接覆盖内置值(同一字典写入);一般建议避免这样做,以免丢失设备维度信息。

## 常见错误

- **空 Key 会被静默忽略**:`SetPublicProperties` 对 `string.IsNullOrEmpty(key)` 直接 `return`,不会抛异常也不会写入,设置无效时先检查 Key 是否为空。
- **`ClearPublicProperties` 不会清空玩家 ID**:该方法只清空公共属性字典并重建设备属性,玩家 ID 需要单独重新 `SetPlayerId`。
- **`GetPublicProperties` 返回的是副本**:`return new Dictionary<string, object>(m_PublicProperties);`,直接改返回值不会影响真实上报的公共属性。

## 背景

公共属性存储在基类的 `m_PublicProperties` 字典中,事件上报时随所有事件一起携带,适合放置相对稳定的维度字段(渠道、服务器、会员等级等);频繁变化的数值更适合用事件的自定义字段 `Event(string eventName, Dictionary<string, object> customF)` 上报。
