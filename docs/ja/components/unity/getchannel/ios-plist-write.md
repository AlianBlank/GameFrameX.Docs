# iOS ビルド後 Info.plist にチャネルが書き込まれない、またはスキップされる

エクスポートされた Xcode プロジェクトの `Info.plist` に `channel` キーがない、または実行時に `BlankGetChannel.GetChannelName()` が常に `default` を返す場合、よくある原因は以下の通りです:`PostProcessBuildHandler` が `#if UNITY_IOS` 条件コンパイルにより除外されている、ビルドターゲットが `BuildTarget.iOS` ではない、または plist に既に `channel` キーが存在するためハンドラーが設計通りスキップしている。本書では症状ごとに原因を特定し、修正方法を示します。

## クイック診断

| 症状(エディターのコンソール / エクスポートされたプロジェクト) | 原因 | 修正 |
|------|------|------|
| `配置渠道成功` や `已有渠道` のログが一切出力されず、plist に `channel` キーがない | エディターの現在のアクティブプラットフォームが iOS ではなく、`PostProcessBuildHandler` 全体が `#if UNITY_IOS` で除外され、コンパイルに参加していない | iOS プラットフォームに切り替えて再ビルド(手順 1 を参照) |
| ログが `已有渠道,跳过设置=>xxx` である | `Info.plist` に既に `channel` キーが存在する(より早く実行される他の `PostProcessBuild` コールバックまたはテンプレートが書き込んだ)ため、ハンドラーが検出しても上書きしない | 手順 2 を参照 |
| ビルドターゲットが tvOS / visionOS | `OnPostProcessBuild` 内で `target != BuildTarget.iOS` の場合に即座に `return` し、tvOS/visionOS ビルドは意図的にスキップされる | 手順 3 を参照 |
| Editor ログに例外のスタックトレースが出るが、ビルドは成功し、plist は未書き込み | `Run()` がスローした例外は `Debug.LogException(e)` で記録されるだけで、ビルドは中断されない | 手順 4 を参照 |
| `channel` キーは書き込まれるが、値が常に `default` | 書き込まれる値は定数 `const string channelValue = "default";` であり、動的なチャネル名ではない | 手順 5 を参照 |

## 修正手順

### 1. エディターのビルドターゲットが iOS であることを確認

ハンドラーファイル全体が `#if UNITY_IOS` で囲まれており、さらにコールバック内でもターゲットプラットフォームのフィルタリングを行っています:

```csharp
#if UNITY_IOS
        [PostProcessBuild(99)]
        public static void OnPostProcessBuild(BuildTarget target, string path)
        {
            if (target != BuildTarget.iOS)
            {
                return;
            }

            try
            {
                Run(path);
            }
            catch (Exception e)
            {
                Debug.LogException(e);
            }
        }
#endif
```

ソース: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L1-L29)

操作：**File → Build Settings** でアクティブプラットフォームを iOS に切り替えてから、ビルドを実行してください。切り替え後にスクリプトが再コンパイルされ、コールバックが登録されて初めて有効になります。

### 2. `channel` キーが既に存在するためスキップされる

```csharp
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

ソース: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L36-L48)

このロジックはキーが**存在しない**場合にのみ書き込み、既存の値はすべて保持されます。対処方法は 2 つあります:

1. 既存の値が誤っている場合：他の `PostProcessBuild` コールバックが先に `channel` を書き込んでいないか確認してください。本コールバックの順序は `99` で、順序値が小さいコールバックが先に実行されます。自身のコールバック順序を調整するか、相手側の書き込みロジックを削除してください。
2. 既存の値が正しい場合：対処は不要です。これは外部のチャネルパッケージングツールが書き込んだ値を上書きしないための、期待される冪等動作です。

### 3. tvOS / visionOS ビルドがスキップされる

ランタイム層は tvOS/visionOS をサポートしています(ネイティブ呼び出しで plist を読み取り)が、ビルド後処理は `BuildTarget.iOS` のみを処理します。tvOS/visionOS の場合は:

- エクスポートされた Xcode プロジェクトの `Info.plist` に手動で `channel` キーを追加する。または
- 独自のビルドスクリプトで `BuildTarget.tvOS` などのターゲットに対して同様の plist 書き込みロジックを実行する。

### 4. ビルド時に例外が発生するが plist が書き込まれない

`OnPostProcessBuild` はすべての例外をキャッチし、`Debug.LogException(e)` で出力するだけなので、ビルドは失敗せず、plist も書き込まれません。典型的な発生箇所は `Run()` 内です:

- `File.ReadAllText(plistPath)` が `FileNotFoundException` をスロー:`path` パラメーターはビルド出力ディレクトリであり、Xcode プロジェクトが生成されていないか、パスが正しくない。
- `plist.ReadFromString` が解析例外をスロー:plist が他のツールによって破損している。

操作：Unity Console で `PostProcessBuildHandler` に関連するスタックトレースを検索し、`path` が指すビルド出力ディレクトリを修正してから再ビルドしてください。

### 5. 書き込まれる値が `default` に固定されている

```csharp
const string channelKey = "channel";
const string channelValue = "default";
```

ソース: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L33-L34)

書き込まれる値はコンパイル時定数の `"default"` であり、現在のチャネルを読み取るわけではありません。したがって、このハンドラーの位置づけは**フォールバック書き込み**であり、`Info.plist` に少なくとも `channel` キーが存在することを保証します。実際のチャネル名は、独自のチャネルパッケージングフローで `channel` キーに書き込むか上書きしてください。フォールバックロジックは、キーが既に存在する場合は自ら処理を譲ります(手順 2 を参照)。

## 検証

以下の順序で修正が有効になったことを確認します:

1. Unity ビルド完了後、Console に `配置渠道成功=>default`(または `已有渠道,跳过设置=>xxx`)が表示される。
2. エクスポートされた Xcode プロジェクトを開き、`Info.plist` に以下が存在する:

```xml
<key>channel</key>
<string>default</string>
```

このキーと値のペアの形式が、ランタイムのネイティブインターフェースが読み取る形式です。[Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26) のコメント説明を参照してください。

3. 実機で実行し、`BlankGetChannel.GetChannelName()` を呼び出して戻り値を検証します。iOS では `DllImport("__Internal")` を通じてネイティブの `getChannelName` を呼び出し、キャッシュも行われます:

```csharp
#elif UNITY_IOS || UNITY_TVOS || UNITY_VISIONOS
        channelName = getChannelName(channelKey);
#endif
        ChannelCache[channelKey] = channelName;
        return channelName;
```

ソース: [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L136-L141)

注意:`GetChannelName(string channelKey = "channel", string defaultValue = "default")` のデフォルト値も `"default"` であり、チャネルキーの読み取りに失敗するとそのまま `default` を返します。これは「plist に未書き込み」の現象と同じです。まず手順 2 で plist 内にキーが確実に存在することを確認してから、ランタイムの読み取りを調査してください。
