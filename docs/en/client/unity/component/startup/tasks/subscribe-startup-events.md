# How to Subscribe to Startup Completed and Failed Events

With `StartupCompletedEventArgs` and `StartupFailedEventArgs`, you can receive notifications when the startup flow completes or fails, useful for scene transitions, releasing the loading UI, reporting analytics events, or prompting the player to retry.

## Prerequisites

- The project has integrated `GameFrameX.Startup.Runtime`, and you have obtained the event component `EventComponent` via `GameEntry`.
- Familiarity with the GameFrameX event subscription pattern (`EventComponent.Subscribe`).

## Event IDs and Fields

| Event | EventId | Readable Fields | Trigger Timing |
|------|---------|----------|----------|
| Startup success | `typeof(StartupCompletedEventArgs).FullName` | None | After `ProcedureGameLauncherState` finishes the hot update and disposes the UI |
| Startup failure | `typeof(StartupFailedEventArgs).FullName` | `FailedProcedureName`, `FailedUrl`, `ErrorMessage` | When any Procedure stops the flow due to a network or business failure |

`StartupFailedEventArgs.Create(procedureName, url, errorMessage)` is called by `StartupProcedureUtility`; `procedureName` is the name of the Procedure state where the failure occurred, and `url` is an empty string for non-network failures.

## Steps

### 1. Subscribe to the Startup Completed Event

Call `Subscribe` after `GameEntry` initialization is complete and before the startup flow begins, registering the handler to `EventComponent`:

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;
using GameFrameX.Startup.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupCompletedEventArgs.EventId,
    OnStartupCompleted);

static void OnStartupCompleted(object sender, GameEventArgs e)
{
    var args = e as StartupCompletedEventArgs;
    // Navigate to the main scene, play the login animation, etc.
}
```

`StartupCompletedEventArgs` has no extra fields; simply call `Clear()` to return it to the reference pool.

Source: [StartupCompletedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupCompletedEventArgs.cs#L1-L38)

### 2. Subscribe to the Startup Failed Event

The failure event carries the Procedure name, the last failed URL, and the error description, making it suitable for UI prompts and reporting:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);

static void OnStartupFailed(object sender, GameEventArgs e)
{
    var args = (StartupFailedEventArgs)e;
    Debug.LogError($"启动失败 [{args.FailedProcedureName}] {args.FailedUrl} {args.ErrorMessage}");
    // Show a retry button, report analytics events
}
```

Source: [StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L1-L62)

### 3. Unsubscribe

Call `Unsubscribe` when it is no longer needed, passing the same delegate reference; otherwise, `EventComponent` will keep holding the callback.

```csharp
GameEntry.GetComponent<EventComponent>().Unsubscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);
```

## Common Variants

- **Only listening for failures**: Subscribe only to `StartupFailedEventArgs.EventId` and not to the success event.
- **Handling success/failure with the same callback**: Branch on `GameEventArgs e` using `is StartupCompletedEventArgs` / `is StartupFailedEventArgs`.
- **Detecting business failures via the hot-update layer**: When `IHotfixLauncher.StartAsync` returns `Result.Success == false`, `ProcedureGameLauncherState` calls `CompleteFailure` to trigger the failure event, with `FailedProcedureName` fixed to `"ProcedureGameLauncherState"` and `FailedUrl` as an empty string.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Callback not triggered after startup completes | Subscription happens too late; the event has already been fired | Call `Subscribe` before `GameEntry` starts or in the entry script's `Awake` |
| Cannot read the URL in the failure callback | `StartupFailedEventArgs.FailedUrl` only has a value for network-type failures | Use `FailedProcedureName` + `ErrorMessage` as a fallback prompt |
| Duplicate triggering caused by subscribing again after receiving the callback | No deduplication, or the handler was registered for both startups | `Subscribe` again only after `Unsubscribe`, or clean up uniformly when `GameEntry` restarts |
| Directly calling `new StartupCompletedEventArgs()` and sending it | Events are fired uniformly by the framework internally and should not be triggered externally | Do not fire manually; only consume on the `EventComponent.Subscribe` side |

## Background

Both events are fired within `StartupProcedureUtility.CompleteSuccess` / `CompleteFailure`:

- `CompleteFailure` calls `EventComponent.Fire(procedureOwner, StartupFailedEventArgs.Create(...))`;
- `CompleteSuccess` calls `EventComponent.Fire(procedureOwner, StartupCompletedEventArgs.Create())`.

Event IDs follow the `typeof(X).FullName` pattern, consistent with the entire GameFrameX suite; event objects are acquired from the reference pool via `ReferencePool.Acquire`, and the framework internally handles `Clear` and recycling.
