# 如何使用 RSA 加解密与签名

`RsaHelper` 把 RSA 非对称加密封装成静态方法，支持 Base64 密钥的加解密、签名验签，以及 XML 密钥的密钥对生成与实例加解密。本页带你走完从生成密钥到加解密、签名验签的完整流程。

## 前置条件

- 项目引用 `GameFrameX.Foundation.Encryption` 程序集，并 `using GameFrameX.Foundation.Encryption;`。
- .NET 运行时支持 `System.Security.Cryptography.RSA`（.NET 6+ 即可）。
- 准备一对 Base64 格式的 RSA 密钥（PKCS#8/PKCS#1）或 XML 格式密钥；没有可用 `RsaHelper.Make()` 现生成。

## 操作步骤

### 1. 生成一对 RSA 密钥（XML 格式）

```csharp
using GameFrameX.Foundation.Encryption;

var keyPair = RsaHelper.Make(); // 返回字典，包含 "privateKey" 与 "publicKey"
string privateKeyXml = keyPair["privateKey"];
string publicKeyXml  = keyPair["publicKey"];
```

字典里两个键分别是 XML 格式的私钥（含 `Modulus`、`Exponent`、私有参数等）和公钥，可直接保存或转 Base64。

### 2. 用公钥加密、私钥解密（XML 密钥）

`Encrypt(string, string)` 与 `Decrypt(string, string)` 接收 XML 格式密钥，返回 Base64 字符串。

```csharp
using GameFrameX.Foundation.Encryption;
using System.Text;

string plain = "Hello, RSA!";

// 加密：公钥 XML + 明文 → Base64 密文
string cipher = RsaHelper.Encrypt(publicKeyXml, plain);

// 解密：私钥 XML + Base64 密文 → 明文
string back = RsaHelper.Decrypt(privateKeyXml, cipher);
```

如果想直接拿到字节数组，加密侧用 `RsaHelper.Encrypt(string publicKey, byte[] content)`，解密侧用 `RsaHelper.Decrypt(string privateKey, byte[] content)`。

### 3. 用公钥加密、私钥解密（Base64 密钥）

`EncryptBase64` 与 `DecryptBase64` 接收 Base64 编码的密钥，内部自动识别 PKCS#8 / PKCS#1：

```csharp
string cipher64 = RsaHelper.EncryptBase64(publicKeyBase64, plain);
string plain64 = RsaHelper.DecryptBase64(privateKeyBase64, cipher64);
```

加密采用 **OAEP-SHA256** 填充；当明文超过单块上限时会自动分块加密，适合任意长度数据。

### 4. 私钥签名、公钥验签

签名与验签固定使用 SHA256 + PKCS#1 填充，密钥同样支持 PKCS#8 与 PKCS#1：

```csharp
string signature = RsaHelper.Sign(privateKeyBase64, plain);
bool ok = RsaHelper.Verify(publicKeyBase64, plain, signature);
```

`Verify` 返回 `true` 表示签名有效；公钥/数据/签名任一被篡改都会返回 `false`。

### 5. 用实例复用同一对密钥

适合需要反复加解密的场景（构造时持有 `RSA` 资源，记得 `Dispose`）：

```csharp
using (var helper = new RsaHelper(privateKeyXml))
{
    string cipher = helper.Encrypt(plain);             // 实例公钥加密（XML 私钥同时包含公钥参数）
    string back   = helper.Decrypt(cipher);            // 实例私钥解密
}
```

或者直接传入 `System.Security.Cryptography.RSA` 实例：`new RsaHelper(rsaInstance)`。

## 常见变体

| 场景 | 推荐 API | 密钥格式 |
|------|---------|----------|
| 与 Java/Go 等互通，密钥是 PEM 内的 Base64 段 | `EncryptBase64` / `DecryptBase64` / `Sign` / `Verify` | PKCS#8 或 PKCS#1 Base64 |
| 内部 .NET 体系，长期保存密钥到配置文件 | `Make()` + `Encrypt` / `Decrypt` | XML |
| 大文件分块加密 | `EncryptBase64` / `DecryptBase64` | Base64（自动分块） |
| 同一密钥多次调用，避免重复导入 | `new RsaHelper(key)` 实例化 | XML 或 `RSA` 对象 |

## 常见错误

| 现象 | 原因 | 处置 |
|------|------|------|
| `CryptographicException` "Bad Data" | Base64 字符串不是合法的 PKCS#8/PKCS#1 密钥 | 确认 PEM 去掉 `-----BEGIN/END-----` 与换行后再 Base64 |
| `Encrypt` 报 "Key not valid for use in specified state" | XML 字符串是私钥而非公钥 | `Make()` 返回的 `publicKey` 才能用于加密 |
| `Verify` 始终返回 `false` | 签名数据被改、密钥对不匹配、或签名用了不同哈希 | 确认参与签名的原文 UTF-8 与验签一致；双方都使用 SHA256 |
| 加解密结果乱码 | 两侧填充方式不一致 | `EncryptBase64`/`DecryptBase64` 必须成对使用，都是 OAEP-SHA256 |

## 背景（可选）

- 加密填充：自 C-05 修复后，加解密统一使用 `RSAEncryptionPadding.OaepSHA256`，避免 PKCS#1 v1.5 的 Bleichenbacher 攻击风险。
- 签名填充：签名/验签固定为 `RSASignaturePadding.Pkcs1` + `HashAlgorithmName.SHA256`，与多数外部系统默认一致。
- 资源管理：实例方法持有非托管 RSA 资源，使用 `new RsaHelper(...)` 后必须调用 `Dispose()` 或用 `using`。
