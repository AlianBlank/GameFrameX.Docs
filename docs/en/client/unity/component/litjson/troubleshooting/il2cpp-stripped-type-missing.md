# What to Do When Types Are Missing or Errors Occur After IL2CPP Release

IL2CPP performs Managed Code Stripping during the build process. LitJson relies on reflection to generate readers/writers, and once stripped, you may encounter `MissingMethodException`, `InvalidCastException`, or empty objects upon deserialization at IL2CPP runtime. This page provides quick diagnosis and fix steps.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `MissingMethodException: ... LitJson ...` | IL2CPP linker stripped internal LitJson methods | Add `link.xml` and attach `LitJsonCroppingHelper` |
| Deserialization result fields are all `null`/default values | `JsonData`/`JsonMapper` exporters were stripped | Add `link.xml` |
| `JsonMapper.ToObject<T>` returns object but properties are lost | Fields/properties of custom T were stripped | Preserve the T's types by assembly in `link.xml` |
| `Type.GetType("...")` returns `null` | IL2CPP does not support looking up non-preserved types by string name | Use generic `ToObject<T>()` or preserve the corresponding type in `link.xml` |
| `InvalidCastException` when registering custom Importer/Exporter | The delegate's target method was stripped | Preserve your assembly in `link.xml` |

## Fix Steps

### 1. Add link.xml for Declarative Preservation

Create `link.xml` under any `Assets` subdirectory of your Unity project (typically placed at `Assets/link.xml`) with the following content, which explicitly preserves the LitJson assembly:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
</linker>
```

During the build, LitJson-related types will be skipped from stripping based on this file. This is the first line of defense.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md#L40-L50)

### 2. Attach LitJsonCroppingHelper for Runtime Anti-Stripping

The repository comes with `LitJsonCroppingHelper`, which explicitly references all public LitJson types via `typeof(...)` in `Start()`, serving as a second layer of insurance:

```csharp
[Preserve]
public class LitJsonCroppingHelper : UnityEngine.MonoBehaviour
{
    [Preserve]
    public void Start()
    {
        _ = typeof(ArrayMetadata);
        _ = typeof(Condition);
        _ = typeof(ExporterFunc);
        _ = typeof(ExporterFunc<>);
        _ = typeof(JsonIgnoreAttribute);
        _ = typeof(JsonPropertyAttribute);
        _ = typeof(FsmContext);
        _ = typeof(IJsonWrapper);
        _ = typeof(ImporterFunc);
        _ = typeof(ImporterFunc<,>);
        _ = typeof(JsonData);
        _ = typeof(JsonException);
        _ = typeof(JsonMapper);
        _ = typeof(JsonMockWrapper);
        _ = typeof(JsonReader);
        _ = typeof(JsonToken);
        _ = typeof(JsonType);
        _ = typeof(JsonWriter);
        _ = typeof(Lexer);
        _ = typeof(ObjectMetadata);
        _ = typeof(OrderedDictionaryEnumerator);
        _ = typeof(ParserToken);
        _ = typeof(PropertyMetadata);
        _ = typeof(UnityTypeBindings);
        _ = typeof(WrapperFactory);
        _ = typeof(WriterContext);
    }
}
```

Attach this component to the GameObject that starts **earliest** in a scene (e.g., `Bootstrap`) to ensure `Start()` runs before any `JsonMapper` call.

Source: [LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L12-L52)

### 3. Preserve Custom Data Types

If you use `JsonMapper.ToObject<MyData>("...")` to deserialize a custom class, and `MyData` is located in another assembly, you need to add preservation entries to `link.xml`:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
  <assembly fullname="MyGame.Models" preserve="all"/>
</linker>
```

Or preserve only specific types to reduce package size:

```xml
<linker>
  <assembly fullname="MyGame.Models">
    <type fullname="MyGame.Models.PlayerData" preserve="all"/>
    <type fullname="MyGame.Models.InventoryItem" preserve="all"/>
  </assembly>
</linker>
```

### 4. Avoid Relying on Loading Types by String Name

`Type.GetType("MyGame.Models.PlayerData, MyGame.Models")` will return `null` under IL2CPP if the type has not been preserved via `link.xml`. Suggestions:

- Use the generic `JsonMapper.ToObject<PlayerData>(json)`;
- Or explicitly preserve the type in `link.xml`;
- Or when registering a custom importer via `JsonMapper.RegisterImporter<string, Type>(s => Type.GetType(s))`, ensure the target type has been preserved.

Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L47)

### 5. Check Unity Build Settings

1. `Player Settings > Managed Stripping Level`: Under IL2CPP, keep it at `Low` or lower; if using `High`/custom rules, be sure to coordinate with `link.xml`.
2. `Player Settings > Strip Engine Code`: Uncheck or include as a `link.xml` exception.
3. Clean Library/ScriptAssemblies and re-package to avoid cache masking configuration changes.

## Verification

1. After packaging with IL2CPP, launch the game and trigger a complete round-trip flow of `JsonMapper.ToJson` and `JsonMapper.ToObject`, confirming there is no `MissingMethodException`.
2. Search for keywords `LitJson` and `MissingMethod` in Xcode/Android logs to confirm no errors.
3. The field values of the deserialized result object match the original JSON (no null/default values).
4. Temporarily set `Managed Stripping Level` to `High` and re-test to verify that `link.xml` and `LitJsonCroppingHelper` still work under the most aggressive stripping.
