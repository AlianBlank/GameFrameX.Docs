# What to Do If Opening a UI Form Fails

When calling `OpenUIForm` / `OpenUIFormAsync` does not bring up the UI form, or when you receive the `OpenUIFormFailureEventArgs` event, you can use the diagnostic table on this page to locate the cause and fix it. Common failure causes mostly fall into a few categories: **asset not registered, UI group does not exist, missing scripting define symbols, script not attached**.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| The instance returned by `OpenUIForm` is `null`, or `OpenUIFormFailureEventArgs.ErrorMessage` reports the asset cannot be found | `uiFormAssetName` is not registered in the UI component (missing configuration or typo) | Fill in the asset name in the UIForm configuration and confirm that `UIFormAssetName` exactly matches what the caller passes in |
| The error reports the UI group / UIGroup cannot be found | The passed-in `uiGroupName` does not exist | Call `AddUIGroup` to add the group first, or pass in an already-registered group name |
| The entire `UIComponent` throws errors or `OpenUIForm` cannot be called | The project has not enabled the `GameFrameX.UI` scripting define | In the editor, add the scripting define via `UISystemScriptingDefineCheckHandler`, or add `GameFrameX.UI` in Player Settings |
| The asset exists but the logic does not trigger after the UI form opens | The UIForm prefab does not have the corresponding logic script attached | Attach the correct logic class component to the `UIForm` prefab |
| `OpenUIFormFailureEventArgs` never fires, but the UI form is not displayed either | The events are not subscribed, so failures are silently swallowed | Subscribe to `OpenUIFormSuccessEventArgs` / `OpenUIFormFailureEventArgs` before calling |
| `uiFormAssetPath` and `uiFormAssetName` are confused, causing asynchronous loading to fail | "Path" and "asset name" are swapped when calling | Distinguish them: the configuration takes `UIFormAssetName` (the logical name), while `uiFormAssetPath` is the asset address |

## Fix Steps

### 1. Asset not registered / name misspelled

Open the UI configuration and confirm that the `UIFormAssetName` field of the corresponding UIForm is filled in and that the name matches the `OpenUIForm` call.

```csharp
// Caller: the name must match m_UIFormAssetName in UIFormInspector
UIComponent.OpenUIForm("ShopUI", "Normal");
```

See [UIFormInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UIFormInspector.cs#L92-L110) for the available fields of the `UIForm` prefab.

### 2. UI group does not exist

`uiGroupName` must be a group name that has already been registered via `AddUIGroup`. Common scenario: copying someone else's code but forgetting to register custom groups such as `Window` or `Popup`.

### 3. Scripting define not enabled

All interfaces of `UIComponent` depend on the `GameFrameX.UI` scripting define. If it has never been enabled, calls will throw errors directly. At runtime, [UISystemScriptingDefineCheckHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UISystemScriptingDefineCheckHandler.cs) automatically checks for it and adds it in the editor.

### 4. Subscribe to the failure event to locate the real error

Do not rely only on the return value. Subscribing to `OpenUIFormFailureEventArgs` gives you the full error stack, which is faster than blind guessing.

```csharp
// From the README.md example
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnUIFormOpenFailure);
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnUIFormOpenSuccess);

private void OnUIFormOpenFailure(object sender, GameEventArgs e)
{
    var args = (OpenUIFormFailureEventArgs)e;
    Debug.LogError($"Failed to open {args.UIFormAssetName}: {args.ErrorMessage}");
}
```

See [OpenUIFormFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormFailureEventArgs.cs#L88-L131) for the field definitions of `ErrorMessage`, `UIFormAssetName`, `SerialId`, and `UserData`.

### 5. The UIForm prefab is missing the logic script

If the UI form "opens" but its logic (`OnInit`, `OnOpen`, `OnUpdate`) does not execute, the prefab is usually missing the `IUIForm` logic component. Open the corresponding prefab and attach the script that inherits from `UIForm` to the root node.

## Verification

Confirm each item in the following order:

1. Seeing `OpenUIFormSuccessEventArgs` fire in the Console means the UI form opened successfully.
2. Use `Debug.LogError` in `OnUIFormOpenFailure` to print the `ErrorMessage`, then use keywords from the message (e.g., "not found", "has not been") to go back to the diagnosis table above.
3. Close and reopen the UI form to confirm that scene switching does not cause UI state loss.
4. In the Editor, check that the Inspector of the `UIForm` component (`UIFormAssetName`, `FullName`, `SerialId`) displays correctly.
