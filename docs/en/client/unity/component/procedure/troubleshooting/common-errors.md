# Common Errors Quick Reference

When using the `GameFrameX.Procedure` module, almost all runtime exceptions stem from the same root cause — **calling any procedure operation before `ProcedureManager.Initialize`**. Below is a list of high-frequency errors; once you see the symptom, you can locate the fix.

## Quick Diagnosis

| Symptom (exception/log text) | Cause | Fix |
|------|------|------|
| `GameFrameworkException: You must initialize procedure first.` (when accessing `CurrentProcedure`, `CurrentProcedureTime`, `StartProcedure`, `HasProcedure`, `GetProcedure`) | Business code calls procedure APIs before `ProcedureManager.Initialize`, leaving the internal `m_ProcedureFsm` as `null` | Configure `Available Procedure Type Names` and `Entrance Procedure Type Name` on the GameObject that has `ProcedureComponent` attached, then call after the component finishes `Initialize` |
| `GameFrameworkException: Procedures is invalid.` (thrown in `Initialize`) | The `procedures` array passed to `Initialize` is `null` or has a length of 0 | Pass at least one `ProcedureBase` subclass instance |
| `Log.Fatal("Procedure manager is invalid.")` (during component `Awake`) | The framework did not register the `IProcedureManager` implementation; `GameFrameworkEntry.GetModule<IProcedureManager>()` returns `null` | Make sure the assembly containing the procedure module is properly packaged into the project and not stripped; it is normally auto-registered by `GameFrameXAutoComponent` — if stripped, check the asmdef |
| `Log.Warning("Available procedure type names is empty. Procedure auto start skipped.")` | The `ProcedureComponent.m_AvailableProcedureTypeNames` field is empty or not filled in | Add at least one procedure type full name in the Inspector (e.g. `MyGame.Procedure.LaunchProcedure, MyGame`) |
| `Log.Error("Can not find procedure type '{0}'.")` | The type full name in `m_AvailableProcedureTypeNames` is mistyped, has a wrong namespace, or the target assembly is not loaded | Use a fully qualified name that `Utility.Assembly.GetType` can resolve, and confirm the type actually exists in a loaded assembly |
| `Log.Error("Can not create procedure instance '{0}'.")` | The type can be found but is not a subclass of `ProcedureBase` or lacks a parameterless constructor | Make your custom procedure inherit from `ProcedureBase` and keep a `public` parameterless constructor |
| `Log.Error("Entrance procedure is invalid.")` | `m_EntranceProcedureTypeName` does not match any entry in `m_AvailableProcedureTypeNames` | The entrance procedure type name must exactly match one entry in `Available Procedure Type Names` |
| Runtime `Already exist FSM.` (when used together with `StartupRunner`) | Both the legacy auto-initialization and the new `StartupRunner` are enabled, causing `Initialize` to be called twice | Set `ProcedureComponent.m_UseStartupRunner` to `true`, letting `ApplicationStartupEntry + StartupRunner.Run` take over initialization |

## Fix Steps

### 1. Calling Procedure APIs Before Initialization

All throw points are in `ProcedureManager` within the null-check branch for `m_ProcedureFsm`, for example `StartProcedure<T>()`:

```csharp
[Preserve]
public void StartProcedure<T>() where T : ProcedureBase
{
    if (m_ProcedureFsm == null)
    {
        throw new GameFrameworkException("You must initialize procedure first.");
    }

    m_ProcedureFsm.Start<T>();
}
```

Source: [ProcedureManager.cs#L148-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L148-L156)

`CurrentProcedure`, `CurrentProcedureTime`, `HasProcedure`, and `GetProcedure` go through the same null-check logic:

```csharp
if (m_ProcedureFsm == null)
{
    throw new GameFrameworkException("You must initialize procedure first.");
}
```

Source: [ProcedureManager.cs#L72-L78](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L72-L78)

Fix: After attaching `ProcedureComponent`, let it complete `Initialize` and `StartProcedure` inside the `Start` coroutine:

```csharp
m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);

yield return new WaitForEndOfFrame();

m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
```

Source: [ProcedureComponent.cs#L164-L168](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

On the business side, initiate procedure switching only after the scene finishes loading and `CurrentProcedure` returns a non-`null` value.

### 2. `Initialize` Receives an Empty Procedure Array

```csharp
public void Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)
{
    GameFrameworkGuard.NotNull(fsmManager, nameof(fsmManager));
    GameFrameworkGuard.NotNull(procedures, nameof(procedures));
    if (procedures.Length <= 0)
    {
        throw new GameFrameworkException("Procedures is invalid.");
    }

    m_FsmManager = fsmManager;
    m_ProcedureFsm = m_FsmManager.CreateFsm(this, procedures);
}
```

Source: [ProcedureManager.cs#L130-L141](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)

Fix: Pass at least 1 item for `procedures`, and they must inherit from `ProcedureBase`:

```csharp
public abstract class ProcedureBase : FsmState<IProcedureManager>
{
    // Subclasses override OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy
}
```

Source: [ProcedureBase.cs#L38-L98](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

### 3. Incorrect Procedure Type Name in the Inspector

`ProcedureComponent.Start` creates instances via reflection by type name; any failure will interrupt startup:

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

Source: [ProcedureComponent.cs#L135-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L156)

Fix: Fill in the Inspector using the format `Namespace.ClassName, AssemblyName`, and make sure the entrance name appears in the available list; otherwise it falls through to the `Entrance procedure is invalid.` error:

```csharp
if (m_EntranceProcedure == null)
{
    Log.Error("Entrance procedure is invalid.");
    yield break;
}
```

Source: [ProcedureComponent.cs#L158-L162](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L158-L162)

### 4. Duplicate Initialization with `StartupRunner`

Under the new startup pipeline, the component needs to yield initialization rights:

```csharp
[SerializeField] private bool m_UseStartupRunner = false;
...
if (m_UseStartupRunner)
{
    // ApplicationStartupEntry + StartupRunner.Run takes over Initialize and StartProcedure;
    // this component only handles registering IProcedureManager in Awake, avoiding duplicate Initialize with the new entrypoint that triggers Already exist FSM.
    yield break;
}
```

Source: [ProcedureComponent.cs#L65-L127](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L65-L127)

Fix: When enabling `StartupRunner`, check `Use Startup Runner`, letting `ApplicationStartupEntry` handle scheduling uniformly.

## Verification

Confirm each item in the following order; if any fails, refer back to the corresponding row in the table above:

1. After startup, the Console has no `GameFrameworkException: You must initialize procedure first.`, and `ProcedureComponent.CurrentProcedure` is not `null`.
2. After switching scenes or re-logging in, there is no repeated `Already exist FSM.` in the logs.
3. Add a `Debug.Log` inside the `OnEnter` of your custom `ProcedureBase` subclass to confirm it is actually being called and not swallowed by an exception.
4. `m_AvailableProcedureTypeNames` has at least 1 entry, and `m_EntranceProcedureTypeName` exactly matches one of them.
