# IL2CPP 构建后 UI 代码被裁剪怎么办

Unity 在 IL2CPP 打包时会执行 Managed Code Stripping（托管代码裁剪），把"看起来没有被静态引用"的类型和方法裁掉。本包的 FairyGUI 辅助器（如 `FairyGUIFormHelper`、`FairyGUILoadAsyncResourceHelper`）主要由 GameFrameX UI 框架在运行时间接调用，正是容易被误裁的目标——编辑器一切正常，真机上 UI 打不开或实例化辅助器时抛异常。本包已通过 `[UnityEngine.Scripting.Preserve]` 特性做了全量防裁剪，若仍出现问题，通常是裁剪等级设置过高或工程自有 UI 代码缺少防护。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 编辑器正常，IL2CPP 真机构建后打开 UI 失败、界面辅助器或异步资源辅助器实例化报错 | `Managed Stripping Level` 设置过高，框架间接调用的辅助器类型被裁剪 | 见下文[步骤 1](#1-确认本包版本与-preserve-标注) 与[步骤 2](#2-降低-managed-stripping-level) |
| 包内类型/成员被裁剪，但使用的是旧版本包 | 旧版本可能未覆盖全部成员的 `[UnityEngine.Scripting.Preserve]` 标注 | 升级本包（当前版本见 [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/package.json#L6)），见步骤 1 |
| 工程自定义的 FairyGUI 扩展组件（继承 `GComponent`/`GObject` 的自有类）在真机丢失 | 工程自有代码未做防裁剪处理，与本包无关 | 为自有类补 `[UnityEngine.Scripting.Preserve]` 或工程级 `link.xml`，见步骤 3 |

## 修复步骤

### 1. 确认本包版本与 Preserve 标注

本包在类、字段、属性、方法级别全部标注了 `[UnityEngine.Scripting.Preserve]`，官方说明为"**IL2CPP 安全** — Preserve 特性防止 IL2CPP 构建时代码裁剪"（见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L38)）。

类级与成员级标注的真实写法如下，可对照你本地包内文件确认：

```csharp
[UnityEngine.Scripting.Preserve]
internal sealed class FairyGUILoadAsyncResourceHelper : IAsyncResource
{
    [UnityEngine.Scripting.Preserve]
    private readonly Dictionary<string, UIPackageData> m_UIPackages = new Dictionary<string, UIPackageData>(32);
```

Source: [FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L47-L51)

若发现包内文件缺少这些标注，先通过 Package Manager 升级本包再重新构建。

### 2. 降低 Managed Stripping Level

`[Preserve]` 只能保护"被标注的成员"；当工程整体裁剪等级过高时仍可能出现边缘场景被裁。按以下顺序调整：

1. 打开 `Edit → Project Settings → Player → Other Settings`。
2. 将 `Managed Stripping Level`（IL2CPP 下）从 `High`/`Medium` 降为 `Low` 或 `Minimal`。
3. 重新用 IL2CPP 构建真机包验证。

若因包体原因必须保持高裁剪等级，执行步骤 3 用 `link.xml` 整程序集保留。

### 3. 为工程自有代码补防裁剪（或整程序集 link.xml）

本仓库中**未包含** `link.xml`（防裁剪完全依赖 `[UnityEngine.Scripting.Preserve]`），因此工程自有代码需要自行防护。两种方式任选：

- **特性方式（推荐，与本包做法一致）**：对自定义的 FairyGUI 扩展组件、反射调用的窗体逻辑类逐个标注：

```csharp
[UnityEngine.Scripting.Preserve]
public class MyCustomPanel : GComponent
{
}
```

- **link.xml 方式**：在 `Assets` 下任意位置（如 `Assets/link.xml`）保留整个程序集。注意这是你需要自行创建的工程文件，本包内没有现成的：

```xml
<linker>
  <assembly fullname="Your.GameAssembly" preserve="all"/>
</linker>
```

### 4. 排查 FairyGUI 扩展器反射注册链

本包通过反射获取程序集内的 UI 辅助器实现，这条链路在裁剪后最容易断。确认以下类在构建产物中存在（构建日志或 `{项目}_BackUpThisFolder_ButDontShipItWithYourGame` 内的符号文件）：

- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIUIGroupHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUILoadAsyncResourceHelper`（internal 类，经接口 `IAsyncResource` 间接调用，最易被裁）

## 验证

1. 用 IL2CPP 构建真机包（Android/iOS 均可），不要用 Mono 模式复测。
2. 真机上依次打开依赖不同 UI 分组的界面，确认：界面正常创建（`UIPackage.CreateObject` 路径）、异步加载的 UI 包（YooAsset 路径）能正常回调 `LoadResource`、无 `TypeLoadException`/`NullReferenceException` 之类的辅助器实例化异常。
3. 可选：在构建日志中搜索 `Stripping` 相关警告，确认 `GameFrameX.UI.FairyGUI.Runtime` 程序集未被裁剪报告。

## 背景

本包的辅助器并非由业务代码直接 new 出来，而是由 GameFrameX UI 框架在运行时按接口与反射方式实例化，静态分析看不到引用，IL2CPP 就可能判定其"未使用"而裁剪。`[UnityEngine.Scripting.Preserve]` 会向裁剪器声明"保留此成员及其被引用项"，本包从类、字段到方法做了全覆盖（可见 [FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L47) 与 [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L53)），因此正常情况下你不需要为本包再写任何防裁剪配置。
