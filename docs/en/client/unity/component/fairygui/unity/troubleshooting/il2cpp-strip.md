# What to Do When UI Functions Are Abnormal After IL2CPP Build

After building with IL2CPP, Unity's Managed Code Stripping may strip out FairyGUI types that are only referenced via reflection/strings, causing UI not to display, missing components, unresponsive buttons, or exceptions such as `NullReferenceException` and `TypeLoadException` appearing in the logcat/Xcode console. This page provides troubleshooting and fix steps: confirm that `link.xml` is taking effect, attach `FairyGUICroppingHelper` to the startup scene, and adjust the stripping level.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| UI not displaying after build / some components empty | Managed code stripping removed types not statically referenced | Confirm that `Runtime/link.xml` is included in the package, see [Fix Step 1](#step-1-confirm-that-linkxml-is-included-in-the-package) |
| Console reports `NullReferenceException` / `TypeLoadException` involving `FairyGUI.*` types | Types created via reflection (e.g., UI package components) were stripped | Attach the `FairyGUICroppingHelper` anti-stripping script, see [Fix Step 2](#step-2-attach-fairyguicroppinghelper-to-the-startup-scene) |
| Works fine in the Editor but abnormal on device; async package loading receives no callbacks | Callback types such as `AsyncCreationHelper` were stripped | Same as above; `FairyGUICroppingHelper.Start()` explicitly references `AsyncCreationHelper` |
| Problem reproduces when the stripping level is too high (Medium/High) | IL2CPP strips assemblies that are only used via reflection by default | Lower the Managed Stripping Level or rely on `link.xml`, see [Fix Step 3](#step-3-adjust-the-managed-stripping-level) |

## Fix Steps

### Step 1: Confirm that link.xml is included in the package

This package ships with `Runtime/link.xml`, which sets the entire `FairyGUI.Runtime` assembly to `preserve="all"`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="FairyGUI.Runtime" preserve="all"/>
</linker>
```

Source: [Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/link.xml#L1-L4)

Key checks:

1. Confirm that `Runtime/link.xml` exists in the project (it is included with the package when installed via the Package Manager).
2. If you copied the FairyGUI source code into your own project, make sure the `fullname` in `link.xml` matches the actual assembly name (see the assembly's `.asmdef` name); if the names do not match, this file will not take effect.
3. Search for `link.xml` in the build logs to confirm that this linker descriptor was applied during the build.

### Step 2: Attach FairyGUICroppingHelper to the startup scene

The package provides the anti-stripping script `FairyGUICroppingHelper`, which explicitly references all FairyGUI types in `Start()` to prevent the stripper from removing them:

```csharp
/// <summary>
/// Prevents stripping errors at runtime. Add this script to the startup scene. It has no effect on logic.
/// </summary>
[Preserve]
public class FairyGUICroppingHelper : MonoBehaviour
{
    [Preserve]
    void Start()
    {
        _ = typeof(FairyGUI.AlignType);
        _ = typeof(FairyGUI.Anymous_T);
        _ = typeof(FairyGUI.AsyncCreationHelper);
        // ...all FairyGUI types are referenced one by one below
```

Source: [Runtime/FairyGUICroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/FairyGUICroppingHelper.cs#L6-L17)

How to: In the startup (first) scene, create an empty GameObject and add `FairyGUICroppingHelper` via `Add Component`. This script has no effect on runtime logic; it is only used to preserve types.

### Step 3: Adjust the Managed Stripping Level

In **Project Settings → Player → Other Settings → Optimization**:

| Build Target | Setting | Recommended Value |
|------------|--------|--------|
| Android | Managed Stripping Level | Low or Disabled (use Disabled first to troubleshoot difficult cases) |
| iOS | Managed Stripping Level | Low or Disabled |

Rebuild after lowering the level. If everything works fine with `Disabled` but breaks after raising it, some types still rely on `link.xml` / `[Preserve]` to be preserved—prioritize Fix Steps 1 and 2 rather than keeping stripping disabled long-term.

## Verification

1. Rebuild the IL2CPP package and install it on a device.
2. Trigger the screens that previously had issues: confirm that the UI displays correctly and that buttons/async loading receive callbacks.
3. In logcat (Android) or the Xcode console (iOS), confirm that `NullReferenceException` / `TypeLoadException` related to `FairyGUI.*` no longer occur.
4. Optionally, search for the previously missing type names in the `IL2CPP` generated directory of the build output (e.g., `Temp/StagingArea/Data/Il2CppOutputDirectory`) to confirm they were not stripped.
