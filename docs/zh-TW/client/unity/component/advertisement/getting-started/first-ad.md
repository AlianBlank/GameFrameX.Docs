# 第一支廣告：從掛載元件到播放完成

按照本頁操作，你將在場景中獲得一個可用的 `AdvertisementComponent`，透過 `Play(AdvertisementPlayOption)` 播放一次廣告，並在回呼中收到三種結果：「播放成功 / 失敗 / 完整觀看」。

## 前置條件

| 項目 | 說明 |
|---|---|
| GameFrameX Runtime | 元件繼承自 `GameFrameworkComponent`，並透過 `GameFrameworkEntry.GetModule<IAdvertisementManager>()` 取得模組，因此場景中必須已存在 GameFrameX 框架入口 |
| 特定廣告實作 | 本套件僅提供抽象層（`IAdvertisementManager` / `AdvertisementConfig`）；實際的渠道 SDK 實作需另行整合 |
| 各平台廣告單元 ID | 依目標平台（Android / iOS / WebGL / 微信 / 抖音 / 快手）準備 |

## 步驟

### 1. 掛載廣告元件

在場景中選取 GameFrameX 框架所在的 GameObject，並透過選單 **GameFrameX → Advertisement** 新增該元件。此元件帶有 `[DisallowMultipleComponent]`，因此單一物件上只能掛載一個。

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Advertisement")]
public class AdvertisementComponent : GameFrameworkComponent
{
    [SerializeField] private string m_adUnitIdAndroid = string.Empty;
    [SerializeField] private string m_adUnitIdiOS = string.Empty;
    [SerializeField] private string m_adUnitIdWebGL = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLWeChat = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLDouYin = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLKuaiShou = string.Empty;
    [SerializeField] private bool m_debug = false;
    [SerializeReference, SerializeField] private AdvertisementConfig m_config = null;
}
```

> 來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L43-L61)

### 2. 在 Inspector 中填入各平台的廣告單元 ID

Inspector 中的六個 ID 欄位各自對應一個平台。在 `Awake` 中，元件會根據目前的編譯平台與小遊戲巨集自動選擇其中之一，並指派給唯讀屬性 `AdUnitId`：

```csharp
AdUnitId =
#if UNITY_WEBGL
#if ENABLE_WECHAT_MINI_GAME
        m_adUnitIdWebGLWeChat
#elif ENABLE_DOUYIN_MINI_GAME
        m_adUnitIdWebGLDouYin
#elif ENABLE_KUAISHOU_MINI_GAME
        m_adUnitIdWebGLKuaiShou
#else
        m_adUnitIdWebGL
#endif
#elif UNITY_ANDROID
        m_adUnitIdAndroid
#elif UNITY_IOS
        m_adUnitIdiOS
#else
        string.Empty
#endif
        ;
```

> 來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)

換句話說，在編輯器中（當目標不是 Android / iOS / WebGL 時），`AdUnitId` 會是空字串。這是預期行為，並非配置錯誤。

### 3. 提供配置並完成初始化

`AdvertisementConfig` 是一個抽象基底類別，只有一個通用欄位 `isDebug`；渠道特定的參數由你的實作類別進行擴充：

```csharp
[Preserve]
[Serializable]
public abstract class AdvertisementConfig
{
    /// <summary>
    /// 是否啟用除錯模式。
    /// </summary>
    [Preserve]
    public bool isDebug;
}
```

> 來源：[AdvertisementConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L41-L53)

初始化有兩種方式，任選其一即可：

- **方式 A（推薦，零程式碼）**：欄位 `m_config` 標記了 `[SerializeReference]`，因此你可以直接在 Inspector 中選擇你的配置子類別並填入參數。當 `m_config != null` 時，元件的 `Start()` 會自動呼叫 `Initialize`：

```csharp
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

> 來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)

- **方式 B（程式碼）**：自行建立配置物件並傳入，這同時會覆寫元件的 `Config`：

```csharp
[Preserve]
public void Initialize(AdvertisementConfig config)
{
    m_config = config;
    _advertisementManager.Initialize(config);
}
```

> 來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L135-L140)

### 4. 播放廣告並處理結果

播放一律透過 `Play(AdvertisementPlayOption option)` 進行，並將各回呼放入 option 物件中：

```csharp
using GameFrameX.Advertisement.Runtime;
using GameFrameX.Runtime;
using UnityEngine;

public class RewardButton : MonoBehaviour
{
    public void OnClickWatchAd()
    {
        var component = GameEntry.GetComponent<AdvertisementComponent>();

        component.Play(new AdvertisementPlayOption
        {
            extraData  = "level_10_double_reward", // 僅在 Load 階段透傳給伺服器端獎勵驗證
            customData = "from_main_ui",
            OnSuccess = data => Log.Info($"Ad played successfully, extra data: {data}"),
            OnFail    = error => Log.Error($"Ad playback failed: {error}"),
            OnShowResult = isShown => Log.Info($"Whether the ad was successfully shown: {isShown}"),
        });
    }
}
```

> 來源：[AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L42-L85)、[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L215-L219)

三個回呼的語義（摘自原始碼註解）：

| 回呼 | 簽章 | 觸發時機 |
|---|---|---|
| `OnSuccess` | `Action<string>` | 廣告播放成功（例如獎勵驗證通過），參數為額外資料 |
| `OnFail` | `Action<string>` | 廣告播放失敗，參數為錯誤訊息 |
| `OnShowResult` | `Action<bool>` | 廣告顯示結果，參數表示是否成功顯示 |

> 來源：[AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L46-L68)

### 5. 需要時新增額外資料

播放前，你可以透過 `SetExtraData(key, value)` 附加鍵值對，它會被直接轉發給管理器：

```csharp
[Preserve]
public void SetExtraData(string key, string value)
{
    Debug.Log($"[AdComponent] SetExtraData: key={key}, value={value ?? "(null)"}, managerType={_advertisementManager?.GetType().FullName ?? "(null)"}");
    _advertisementManager.SetExtraData(key, value);
}
```

> 來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L168-L173)

## 常見變體

### 直接使用管理器介面，繞過元件

元件只是 `IAdvertisementManager` 的一層薄封裝。當你需要在非 MonoBehaviour 程式碼中播放廣告時，可以直接取得該模組：

```csharp
var manager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
manager.Play(new AdvertisementPlayOption
{
    OnSuccess    = data => { /* 發放獎勵 */ },
    OnFail       = error => { /* 通知 */ },
    OnShowResult = isShown => { /* 統計分析 */ },
});
```

> 來源：[IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L96-L97)

### 舊版 API（仍可編譯，但已標記為過時）

以下成員皆標記了 `[Obsolete]`，僅建議在遷移舊專案時短期使用：

| 過時成員 | 過時訊息 | 替代方案 |
|---|---|---|
| `Initialize(string adUnitId, bool isDebug = false)` | `Use Initialize(AdvertisementConfig) instead.` | `Initialize(AdvertisementConfig)` |
| `Show(Action<string>, Action<string>, Action<bool>)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |
| `Play(Action<bool> onShowResult, string customData = null)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |
| `Load(Action<string> success, Action<string> fail)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |

> 來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L150-L236)

## 常見錯誤

| 症狀 | 原因 | 解決方案 |
|---|---|---|
| 主控台輸出 `Advertisement manager is invalid.`（`Log.Fatal`） | `GameFrameworkEntry.GetModule<IAdvertisementManager>()` 回傳 null——未註冊可用的廣告管理器實作 | 確認已整合特定渠道實作，且元件的 `componentType` 能被 `Utility.Assembly.GetType` 解析 |
| `AdUnitId` 為空字串 | 目前平台不在 `UNITY_WEBGL` / `UNITY_ANDROID` / `UNITY_IOS` 分支內，原始碼會回退為 `string.Empty` | 切換至目標平台（或實機）測試；在編輯器中為空屬正常現象 |
| 小遊戲平台取到的是一般 WebGL 的 ID | 未定義 `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 巨集 | 在 Player Settings 的 Scripting Define Symbols 中新增對應巨集 |
| 播放時拋出 `NullReferenceException` | 未初始化就呼叫 `Play`：當 `m_config` 為 null 時，`Start()` 不會自動呼叫 `Initialize` | 在 Inspector 中指定 `Config`，或在播放前手動呼叫 `Initialize(AdvertisementConfig)` |
| 已設定 `extraData` 但伺服器端驗證未收到 | 此欄位「僅在廣告載入（Load）階段透傳給伺服器端獎勵驗證回呼；載入後設定無效」 | 在觸發載入 / 播放前一次性填好 `extraData`，播放期間不要變更 |
| 新增第二個廣告元件失敗 | 該類別帶有 `[DisallowMultipleComponent]` | 單一 GameObject 上僅保留一個 `AdvertisementComponent` |

## 背景（選讀）

在 `Awake` 中，元件會將 `InterfaceComponentType` 設為 `typeof(IAdvertisementManager)`，並透過反射從 `componentType` 解析實作類型。因此，切換渠道 SDK 時業務程式碼無需變更——只需替換實作與配置子類別。
