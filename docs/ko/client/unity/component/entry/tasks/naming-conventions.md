# 명명 규칙과 약어 매핑 이해하기(Component / FUI / GUI)

`GameApp`은 Game Frame X의 정적 퍼사드(Facade) 클래스로, `GameApp.{Name}`을 `GameEntry.GetComponent<{Name}Component>()`에 매핑합니다. 명명 규칙을 이해하면 문서를 찾아보지 않고도 `GameApp.XXX`를 통해 임의의 내장 컴포넌트를 직접 가져올 수 있습니다.

## 명명 매핑 규칙

대다수의 컴포넌트는 "`Component` 접미사 제거"라는 직역 규칙을 따르며, `FUI`와 `GUI`만이 약어 예외입니다.

| GameApp 속성 | 동등한 호출 | 유형 |
|---|---|---|
| `GameApp.Event` | `GameEntry.GetComponent<EventComponent>()` | 일반 매핑 |
| `GameApp.UI` | `GameEntry.GetComponent<UIComponent>()` | 일반 매핑 |
| `GameApp.Asset` | `GameEntry.GetComponent<AssetComponent>()` | 일반 매핑 |
| `GameApp.FUI` | `GameEntry.GetComponent<FairyGUIComponent>()` | 약어 예외(FUI=FairyGUI) |
| `GameApp.GUI` | `GameEntry.GetComponent<UGUIComponent>()` | 약어 예외(GUI=uGUI) |

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L30-L38)

## 약어 예외 설명

`FUI`와 `GUI`는 두 UI 하위 시스템의 역사적인 약어로, 첫 글자를 대문자로 하는 간결한 표기를 유지하고 있으며, "`Component` 접미사 제거" 규칙과 일치하지 않으므로 사용 시 특별히 주의해야 합니다:

- **FUI** → `FairyGUIComponent`(FairyGUI 기반 UI 컴포넌트, [CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6)에 따라 fairygui 의존성이 제거됨)
- **GUI** → `UGUIComponent`(Unity 기본 UGUI 기반 UI 컴포넌트, `GameApp.GUI.cs`에 정의되어 있으며 컴파일 매크로 `ENABLE_GAME_FRAME_X_L_UGUI`로 제어됨)

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
public static partial class GameApp
{
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }
            return _gui;
        }
    }
}
#endif
```

출처: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

## 작업 단계

자신의 스크립트에서 다음 단계에 따라 매핑을 사용합니다:

1. **이름 확인**: 먼저 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L32-L38)의 대조표에서 `GameApp.{Name}`을 조회하여 해당 `*Component` 타입을 찾습니다.
2. **일반 컴포넌트**: `GameApp.Event`, `GameApp.UI`, `GameApp.Asset` 등을 직접 작성합니다.
3. **UI 컴포넌트**: UI 하위 시스템은 두 가지로 구분되며, 엔진 방식에 따라 `GameApp.FUI`(FairyGUI) 또는 `GameApp.GUI`(UGUI)를 선택합니다.
4. **필요 시 매크로 활성화**: `GameApp.GUI`는 `ENABLE_GAME_FRAME_X_L_UGUI` 컴파일 매크로를 켜야만 존재합니다. `GameApp.FUI`는 FairyGUI 패키지에 의존하므로, 해당 의존성을 제거하면 이 속성도 함께 무효화됩니다.

```csharp
// 일반 매핑 예시
var evt = GameApp.Event;
var asset = GameApp.Asset;

// UI 하위 시스템: 엔진 방식에 따라 하나를 선택
var fairygui = GameApp.FUI;   // FairyGUIComponent(FairyGUI 패키지 필요)
var ugui = GameApp.GUI;       // UGUIComponent(ENABLE_GAME_FRAME_X_L_UGUI 매크로 필요)
```

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| `GameApp.FUI` 컴파일 시 "정의되지 않음" 오류 발생 또는 null 반환 | fairygui 의존성이 제거됨([CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6)) | `GameApp.GUI`로 변경하거나 FairyGUI 패키지 설치 |
| `GameApp.GUI`에 접근할 수 없음 | 컴파일 매크로 `ENABLE_GAME_FRAME_X_L_UGUI` 누락 | Player Settings의 Scripting Define Symbols에 해당 매크로 추가 |
| `GameApp.FUI`를 `UIComponent`로 잘못 인식 | `FUI`는 `FairyGUIComponent`이며, `UI`가 `UIComponent`임 | 두 UI 하위 시스템을 구분하여, 범용 UI는 `GameApp.UI`, 엔진 UI는 `GameApp.FUI`/`GameApp.GUI`를 사용 |
| `GameApp.GameApp`과 같은 중복 이름 오용 | 속성 이름은 `Component`를 제거한 이름이지, 컴포넌트의 원래 이름이 아님 | "XxxComponent → Xxx" 규칙에 따라 작성 (예: `AssetComponent → Asset`) |

## 배경

`GameApp`은 C# `partial class`로 파일 단위로 구성되어 있으며, 각 컴포넌트는 하나의 `GameApp.{Name}.cs` 파일에 대응합니다. 내부적으로 지연 로딩(lazy loading) 정적 필드로 첫 번째 호출 결과를 캐시하며, 이후 접근 시 캐시를 직접 반환하여 중복 조회를 방지합니다. `FUI`와 `GUI`의 약어는 기존 코드와의 호환성 유지 및 UI 호출 경로 단축을 위해 남겨진 것이며, 새 코드에서 엔진 방식을 구분할 필요가 없다면 범용 `GameApp.UI`(`UIComponent`)를 우선 사용하는 것이 좋습니다.
