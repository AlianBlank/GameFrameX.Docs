# 이벤트 시스템을 사용하여 모듈 디커플링하는 방법

이벤트 시스템을 통해 모듈 간에 직접 상호 참조할 필요 없이, 이벤트를 정의하고 게시하고, 독립적인 리스너가 이벤트를 처리하도록 하기만 하면 느슨한 결합을 구현할 수 있습니다. 이 페이지에서는 이벤트를 정의하고, 리스너를 작성하고, 이벤트를 디스패치하는 방법을 소개합니다.

## 사전 조건

- C# 제네릭과 비동기 프로그래밍(`async`/`await`)에 대한 이해.
- 프로젝트에서 `GameFrameX.Core.Abstractions.Events`와 `GameFrameX.Core.Events`를 참조함.
- Actor와 컴포넌트 에이전트의 기본 개념을 이해함(Actor 모듈 문서 참조).

## 핵심 개념 빠른 참조

| 이름 | 소속 타입 | 역할 |
|------|----------|------|
| `GameEventArgs` | `GameFrameX.Core.Abstractions.Events.GameEventArgs` | 이벤트 인자 기본 클래스, 모든 커스텀 이벤트 인자는 이를 상속해야 함 |
| `IEventListener` | `GameFrameX.Core.Abstractions.Events.IEventListener` | 리스너 인터페이스, `HandleEvent` 메서드 정의 |
| `EventListener<T>` | `GameFrameX.Core.Events.EventListener<T>` | 리스너 추상 기본 클래스, 특정 컴포넌트 에이전트(`T : IComponentAgent`)에 대한 이벤트 처리 가능 |
| `EventDispatcher.Dispatch` | `GameFrameX.Core.Events.EventDispatcher` | 정적 진입점, 지정된 Actor 또는 전역 리스너에게 이벤트를 게시하는 데 사용 |

## 작업 단계

### 1. 이벤트 인자 정의

`GameEventArgs`를 상속하는 클래스를 만들어 이벤트 데이터를 전달합니다. `GameEventArgs` 자체는 `System.EventArgs`만 상속하며 어떤 필드도 포함하지 않습니다.

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class PlayerLoginEventArgs : GameEventArgs
{
    public long PlayerId { get; }
    public DateTime LoginTime { get; }

    public PlayerLoginEventArgs(long playerId)
    {
        PlayerId = playerId;
        LoginTime = DateTime.UtcNow;
    }
}
```

### 2. 리스너 구현

두 가지 작성 방법이 있습니다: `IEventListener`를 직접 구현하거나, 제네릭 기본 클래스 `EventListener<T>(T : IComponentAgent)`를 상속하는 것입니다.

**작성 방법 A: `EventListener<T>` 상속(권장, 컴포넌트 에이전트 접근이 필요한 경우)**

```csharp
using GameFrameX.Core.Events;

public sealed class PlayerLoginListener : EventListener<PlayerComponentAgent>
{
    protected override async Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        if (gameEventArgs is not PlayerLoginEventArgs args) return;
        // 컴포넌트 에이전트를 통해 컴포넌트 상태에 접근
        var player = agent.GetPlayer();
        await player.OnLogin(args.LoginTime);
    }
}
```

`EventListener<T>`는 전달된 `IComponentAgent`를 제네릭 `T`로 자동 변환하고, 내부적으로 사용자가 구현한 `HandleEvent(T agent, GameEventArgs)`를 호출합니다.

**작성 방법 B: `IEventListener` 직접 구현(컴포넌트 에이전트 접근이 필요 없는 경우)**

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class GlobalStartupListener : IEventListener
{
    public Type AgentType => null;
    public Task HandleEvent(IComponentAgent agent, GameEventArgs gameEventArgs)
        => HandleEvent(gameEventArgs);

    public Task HandleEvent(GameEventArgs gameEventArgs)
    {
        // 전역 이벤트 처리 로직
        return Task.CompletedTask;
    }
}
```

리스너는 프레임워크에 의해 **싱글톤** 방식으로 관리되므로, 구현 시 스레드 안전성을 보장해야 합니다.

### 3. 리스너 등록

리스너는 프레임워크가 `GameFrameX.Hotfix` 어셈블리를 스캔하여 자동으로 등록하며, 일반적으로 `GameFrameX.Hotfix` 프로젝트 아래에 배치하기만 하면 자동으로 발견됩니다. 네이밍은 프로젝트 아키텍처 규칙을 따라야 합니다(`EventListener`를 접미사로 사용하며, 구체적인 제약 사항은 `GameFrameX.Architecture.Analyzers`가 강제로 검사합니다).

### 4. 이벤트 디스패치

정적 클래스 `EventDispatcher.Dispatch`를 호출하여 대상 ActorId, 이벤트 ID, 이벤트 인자를 전달합니다. actorId에 해당하는 Actor가 존재하지 않으면 이벤트는 자동으로 **전역 리스너**에게 디스패치됩니다.

```csharp
using GameFrameX.Core.Events;

// actorId에 해당하는 Actor 컨텍스트에서 이벤트 디스패치
EventDispatcher.Dispatch(playerActorId, EventId.PlayerLogin, new PlayerLoginEventArgs(playerId));
```

이벤트 ID는 `int` 타입의 상수를 사용하며, 일반적으로 `GameFrameX.Apps/Common/Event/EventId.cs`에 집중적으로 정의되어 있습니다.

## 일반적인 변형

| 시나리오 | 작성 방법 |
|------|------|
| 플레이어 수준 이벤트(플레이어 컴포넌트 접근 필요) | `EventListener<PlayerComponentAgent>`를 상속하고 `HandleEvent(T, GameEventArgs)`를 재정의 |
| 전역/서버 수준 이벤트 | `IEventListener`를 구현하고 에이전트 없는 버전의 `HandleEvent(GameEventArgs)` 사용 |
| 인자 없는 이벤트 수신 | 이벤트 인자가 `GameEventArgs`를 상속하지만 어떤 필드도 포함하지 않음 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `NoListenersFound` 경고 표시 | 해당 이벤트 ID에 등록된 리스너가 없음 | 리스너 클래스가 `GameFrameX.Hotfix` 어셈블리에 위치하고 네이밍이 분석기 규칙을 준수하는지 확인 |
| `HandleEvent`가 수신한 이벤트 인자가 다른 타입임 | 이벤트가 다른 이벤트 ID로 잘못 디스패치됨 | 집중 정의된 `EventId` 상수를 사용하고 하드코딩된 매직 넘버 지양 |
| 리스너의 여러 인스턴스가 상태를 공유하여 동시성 문제 발생 | 리스너는 싱글톤이지만 내부 상태가 스레드 안전하게 보호되지 않음 | 가변 상태를 지역 변수로 변경하거나 락을 추가하고, 리스너에 요청 수준의 데이터를 저장하지 않도록 함 |

## 배경(선택 사항)

이벤트 디스패치는 Actor 컨텍스트 내에서 **직렬로** 실행되며(`foreach` + `await`), 동일한 Actor에서 이벤트가 동시에 실행되지 않도록 보장합니다. Actor가 존재하지 않으면 새 스레드에서 전역 리스너를 디스패치합니다. 각 리스너의 예외는 `LogHelper.Error`에 의해 캡처 및 기록되며, 다른 리스너의 처리를 중단시키지 않습니다. 자세한 내용은 [EventDispatcher.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Events/EventDispatcher.cs#L50-L135)를 참조하세요.
