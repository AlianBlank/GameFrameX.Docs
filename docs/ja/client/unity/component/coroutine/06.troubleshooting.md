# 常见问题

本文档收集了使用 CoroutineComponent コルーチンコンポーネント时常见的问题及解決策。

## 概要

CoroutineComponent 是 GameFrameX フレームワーク的コルーチン管理コンポーネント，を拡張 Unity 内置的コルーチン機能，提供更好的コルーチン生命周期管理和内存安全控制。该コンポーネント使用 `ConcurrentDictionary` 线程安全字典来跟踪所有运行的コルーチン，确保可能随时管理和停止コルーチン。

> 详细使用説明お願いします参考 [使用指南](./3-getting-started.index) 和 [API 参考](./4-api-reference.coroutine-component)。

## よくある質問列表

### Q1: 为什么在同一 GameObject 上无法添加多个 CoroutineComponent？

**问题説明：**
在同一个 GameObject 上尝试添加第二个 CoroutineComponent 时，Unity 编辑器报错或无法添加。

**原因：**
CoroutineComponent 使用了 `[DisallowMultipleComponent]` プロパティ，该プロパティ禁止在同一 GameObject 上添加多个相同クラス型的コンポーネント。

**解決策：**
- 确保每个 GameObject 只有一个 CoroutineComponent インスタンス
- 如果必要管理多个コルーチン，お願いします在同一个 CoroutineComponent インスタンス上启动多个コルーチン
- 使用 `StopAllCoroutines()` メソッド停止所有コルーチン

```csharp
// 正确用法：在同一个コンポーネント上管理多个コルーチン
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(CoroutineA());
coroutineComponent.StartCoroutine(CoroutineB());
coroutineComponent.StopAllCoroutines(); // 停止所有コルーチン
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L10-L11)

### Q2: StartCoroutine 传入 null 枚举器会怎样？

**问题説明：**
向 `StartCoroutine` メソッド传入 `null` 值的 IEnumerator 时会发生什么？

**原因：**
如果向 `StartCoroutine` 传入 null 枚举器，Unity 底层会抛出空引用異常。

**解決策：**
- 在启动コルーチン前始终检查枚举器是否为 null
- 添加空值保护逻辑

```csharp
IEnumerator myCoroutine = GetSomeCoroutine(); // 可能是 null

if (myCoroutine != null)
{
    coroutineComponent.StartCoroutine(myCoroutine);
}
```

### Q3: 如何正确停止一个正在运行的コルーチン？

**问题説明：**
呼び出し `StopCoroutine` 后コルーチン似乎仍在运行，或者无法停止コルーチン。

**原因：**
- 传入的 IEnumerator 与启动时的枚举器不是同一个引用
- コルーチン已经执行完毕
- コルーチン在 StopCoroutine 呼び出し前已经结束

**解決策：**
- 保存启动コルーチン时返回的 IEnumerator 引用
- 使用 `StopAllCoroutines()` 停止所有コルーチン
- 确保在コルーチン执行过程中及时停止

```csharp
// 保存コルーチン引用
IEnumerator myCoroutine = coroutineComponent.StartCoroutine(MyLongRunningTask());

// 在适当的时机停止
coroutineComponent.StopCoroutine(myCoroutine);

// 或者停止所有コルーチン
coroutineComponent.StopAllCoroutines();
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L32-L45)

### Q4: コンポーネント挂载的 GameObject 被销毁后会发生什么？

**问题説明：**
当包含 CoroutineComponent 的 GameObject 被销毁时，正在运行的コルーチン会怎样？

**原因：**
当 GameObject 被销毁时，Unity 会自动停止该 GameObject 上的所有コルーチン。CoroutineComponent を継承 MonoBehaviour，因此也会遵循这一行为。

**建议：**
- 在シーン切换或对象销毁前，手动呼び出し `StopAllCoroutines()` 确保コルーチン干净停止
- 使用 OnDestroy 生命周期钩子进行清理

```csharp
private void OnDestroy()
{
    // 确保在对象销毁前停止所有コルーチン
    if (coroutineComponent != null)
    {
        coroutineComponent.StopAllCoroutines();
    }
}
```

### Q5: WaitForEndOfFrameFinish 的回调传入 null 会崩溃吗？

**问题説明：**
向 `WaitForEndOfFrameFinish` メソッド传入 null 回调会发生什么？

**原因：**
CoroutineComponent 使用了空值合并运算符 `callback?.Invoke()`，因此传入 null 回调不会导致崩溃，呼び出し会被安全地忽略。

**源码验证：**
```csharp
public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(_WaitForEndOfFrameFinish(callback));
}

private IEnumerator _WaitForEndOfFrameFinish(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke(); // 使用 ?. 操作符安全呼び出し
}
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L97)

### Q6: 如何在帧渲染结束后执行逻辑？

**问题説明：**
必要在 Unity 每帧渲染结束后执行某些操作，べき如何使用？

**解決策：**
使用 `WaitForEndOfFrameFinish` メソッド，该メソッド会在当前帧的渲染完成后执行回调。

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    // 这个回调会在帧渲染结束后执行
    Debug.Log("帧渲染结束，执行逻辑");
});
```

**适用シーン：**
- 在 UI 渲染后取得屏幕截图
- 在物理计算完成后执行某些操作
- 必要在帧末尾进行ステータス同步

### Q7: CoroutineComponent 是线程安全的吗？

**问题説明：**
CoroutineComponent 可能在多线程环境中使用吗？

**原因：**
是的，CoroutineComponent 使用了 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 来存储コルーチン映射，该数据结构是线程安全的。

**注意事项：**
- 虽然内部存储是线程安全的，但コルーチン本身在 Unity 主线程上执行
- 多线程访问时，主要必要考虑的是 IEnumerator 引用的正确传递

### Q8: コルーチン未正确停止导致内存泄漏如何处理？

**问题説明：**
コルーチン未正确停止可能导致内存泄漏，如何预防？

**原因：**
如果不正确停止コルーチン，特别是包含无限循环或长时间等待的コルーチン，可能会导致内存泄漏。CoroutineComponent を通じて维护コルーチン映射表来帮助管理这个问题。

**解決策：**
- 使用 `StopAllCoroutines()` 清理所有コルーチン
- 在コンポーネント销毁时确保呼び出し `StopAllCoroutines()`
- 使用具有明确结束条件的コルーチン

```csharp
private void OnDestroy()
{
    // 重要：确保停止所有コルーチン防止内存泄漏
    StopAllCoroutines();
}
```

### Q10: CoroutineComponent 必要手动添加到 GameObject 吗？

**问题説明：**
为什么コンポーネント没有自动添加到シーン中？

**原因：**
CoroutineComponent 在 `Awake` メソッド中設定了 `IsAutoRegister = false`，这意味着コンポーネント不会自动注册到フレームワーク的自动注册系统中。

**解決策：**
必要手动将 CoroutineComponent 添加到 GameObject 上：

```csharp
// 手动添加コンポーネント
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();

// 或者在 Unity 编辑器中手动添加
// 1. 选择 GameObject
// 2. 点击 Add Component
// 3. 搜索 "Game Framework/Coroutine"
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L99-L103)

### Q11: 如何在 Unity 编辑器中找到 CoroutineComponent？

**问题説明：**
在 Unity 编辑器中如何添加 CoroutineComponent？

**解決策：**
由于コンポーネント使用了 `[AddComponentMenu("Game Framework/Coroutine")]` プロパティ，您可能を通じて以下方法添加：

1. 在 Unity 编辑器中选择 GameObject
2. 右键点击 Inspector 面板 → Add Component
3. 在搜索框中输入 "Coroutine" 或 "Game Framework/Coroutine"
4. 选择 CoroutineComponent

## 诊断手順

如果遇到无法解决的问题，お願いします按以下手順进行诊断：

1. **检查 GameObject ステータス**：确认 GameObject 和コンポーネント是否已激活
2. **检查コルーチン引用**：确认に使用停止コルーチン的 IEnumerator 引用是否正确
3. **查看 Unity 控制台**：检查是否有错误或警告信息
4. **使用 StopAllCoroutines**：作为调试手段，先停止所有コルーチン排查问题
5. **检查シーン切换**：确认シーン切换时コルーチン是否被正确清理
