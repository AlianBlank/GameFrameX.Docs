# 頻道總是回傳 default 時該怎麼辦

當 `BlankGetChannel.GetChannelName()` 無法從目標平台讀取頻道設定時，會回傳參數 `defaultValue` 的預設值 `"default"`。這種現象絕大多數源自下列原因：目前平台的設定來源中沒有 `channel` 金鑰、金鑰名稱不一致，或是首次查詢的結果已儲存在靜態快取中。API 簽章如下：

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L97-L98)

## 快速診斷

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 在 Editor / PC / WebGL / 遊戲主機上回傳 `default` | `Assets/Resources/application_config.txt` 不存在，或缺少 `channel=` 行 | 在 `Assets/Resources/` 底下建立 `application_config.txt` 並寫入 `channel=xxx` |
| 新增或修改了 `application_config.txt` 仍回傳 `default` | 靜態快取 `ChannelCache` 已快取 `default`,因此本工作階段內不會再讀取 | 結束 Play 模式以觸發 Domain Reload,或重新啟動 Unity 後再次測試 |
| Android 實機上回傳 `default` | `<meta-data android:name="channel" .../>` 未寫在主要執行 Activity 內，或金鑰名稱不是 `channel` | 將 `meta-data` 移至 AndroidManifest.xml 中主要執行 `<activity>` 標籤內部 |
| iOS 實機上回傳 `default` | 建置後處理腳本在 Info.plist 沒有 `channel` 金鑰時會自動寫入 `"default"` | 在建置前，或由優先順序更高的後處理預先寫入 `channel` 金鑰 |
| iOS 回傳的不是 `default` 而是 `unknown` | Info.plist 中沒有該金鑰，iOS 原生實作回傳 `"unknown"` | 在 Info.plist 加入 `channel` 金鑰 |
| 查詢 `sub_channel` 等自訂金鑰時回傳 `default` | 傳入的 `channelKey` 與設定檔的金鑰名稱不一致 | 確認金鑰名稱後，以正確的金鑰寫入設定 |

## 解決步驟

### 1. Editor / PC / WebGL: 確認 application_config.txt

這些平台以 `Resources.Load<TextAsset>("application_config")` 讀取，檔案必須位於 `Assets/Resources/application_config.txt`,格式為一行一個 `金鑰=值`:

```text
channel=editor_cn_test
sub_channel=test
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L106-L121)

請注意剖析規則(以原始碼 `L110-L119` 為準):

- 以 `\n` / `\r` / `\r\n` 分隔各行，空行會被忽略；
- 每行以 `=` 分割，且**必須有超過 1 個區段**。像 `channel`(不含 `=`)這種形式的整行都會被捨棄；
- 金鑰與值兩端的空白會以 `Trim()` 移除，因此寫成 `channel = abc` 也能讀到 `abc`。

### 2. 排除靜態快取干擾

結果會寫入靜態字典 `ChannelCache`,同一工作階段內的第二次呼叫會直接使用快取。特別注意：當 `textAsset == null`(檔案不存在)時，`default` 會被寫入快取，之後即使新增檔案也不會重新讀取：

```csharp
if (ChannelCache.TryGetValue(channelKey, out var value))
{
    return value;
}
// ...
var textAsset = Resources.Load<TextAsset>("application_config");
if (textAsset != null)
{
    // 剖析並填入 ChannelCache
}
else
{
    ChannelCache[channelKey] = defaultValue;  // 找不到檔案時會快取 default
}
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L100-L125)

在 Editor 中確認設定是否生效前，請先結束 Play 模式(觸發 Domain Reload),或重新啟動 Unity 後再進入 Play 模式測試。Android / iOS 亦同：修改 Manifest 或 plist 後必須重新建置，程序內不會自動更新。

### 3. Android: 將 meta-data 放入主要執行 Activity 內

Android 透過 JNI 呼叫 `com.alianhome.getchannel.MainActivity` 的靜態方法 `GetChannel` 來讀取，金鑰名稱預設為 `channel`:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

請將其加在 `AndroidManifest.xml` 的**主要執行 Activity 標籤內部**(而非 `<application>` 底下)：

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

確認事項：

- 金鑰名稱必須是 `android:name="channel"`,並與 C# 端傳入的 `channelKey` 一致。若要取得其他金鑰，請在呼叫時傳入 `GetChannelName("想要的金鑰名稱")`。
- 使用自訂 Manifest 的方式(自訂 `Assets/Plugins/Android/AndroidManifest.xml`)時，必須與 Unity 目前使用的範本一致，並確認打包進 APK 後仍然位於主要 Activity 內。

### 4. iOS / tvOS / visionOS: 確認 Info.plist

iOS 端透過 `DllImport("__Internal")` 呼叫原生 `getChannelName`,從 Info.plist 讀取 `channel` 金鑰：

```csharp
[DllImport("__Internal")]
private static extern string getChannelName(string channelKey);
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L47-L48)

原生實作在找不到金鑰時會回傳 `"unknown"`(不是 C# 端的 `default`):

```objc
NSString * channel_value =  [dict objectForKey:channel_name_String];
if (channel_value != nil) {
    return StringToCharArray(channel_value);
}
channel_value = @"unknown";
return StringToCharArray(channel_value);
```

來源： [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

套件中的 `channel` 金鑰會在 `PostProcessBuild(99)` 建置後處理中自動寫入。**只有當該金鑰不存在時**才會寫入，且寫入的值固定為 `"default"`,因此以本套件預設流程建置出的 iOS 建置產物會取得 `default`。這是刻意為之的設計：

```csharp
const string channelKey = "channel";
const string channelValue = "default";

string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

來源： [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

若要取得實際頻道，請選擇以下其中一種做法：

1. 撰寫 `callbackOrder` 小於 `99` 的 `PostProcessBuild` 處理器，先將實際頻道寫入 Info.plist。這樣本套件就會偵測到金鑰已存在而跳過(日誌輸出 `已有渠道,跳过设置=>`);
2. 或直接修改建置產物中的 Info.plist,再重新簽署。

在 Info.plist 中類型必須為 String:

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)

## 驗證

1. 依照上述步驟完成所有設定後，重新啟動應用程式(或重新啟動 Unity 並進入 Play 模式)；
2. 在啟動初期(查詢頻道之前)呼叫並輸出：

```csharp
string channel = BlankGetChannel.GetChannelName();
Debug.Log("channel = " + channel);
```

來源： [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

3. 在 Android 上使用 `adb logcat | grep channel` 確認輸出；在 iOS 上則於 Xcode 主控台確認。iOS 建置時若後處理已生效，建置日誌中會出現 `配置渠道成功=>` 或 `已有渠道,跳过设置=>` 字樣；
4. 若輸出值與寫入設定的一致，表示修改已完成；若仍是 `default`,請回到「快速診斷」表格，逐一重新確認各平台的設定來源與快取。
