# 實作玩家屬性(Attribute)模組

玩家屬性(Attribute)模組提供基於「最終值槽 + 派生槽」的統一計算公式，透過修改基礎值、加法、第一層百分比、最終加法、最終百分比五個槽位來得到最終屬性。本頁說明如何在業務中初始化、修改並讀取玩家屬性。

## 前置條件

- 已熟悉 `GameFrameX` 的元件 / Agent 模式，了解 `PlayerAttributeComponent` 與 `PlayerAttributeComponentAgent` 的關係。
- 已了解事件匯流排，知道如何註冊 `AttributeChangedEventArgs` 的監聽器。

## 屬性槽位與計算公式

每個最終屬性(`AttributeType.Life` 等)對應五個數值槽，偏移由 `AttributeSlotKind` 定義，百分比基數 `PercentBase = 10000` 表示 100%。

| 槽位 | 偏移 | 用途 |
|------|------|------|
| Final | 0 | 最終值槽，編號等於主編號 |
| Base | 10000 | 基礎值槽，來自配置、等級或初始化 |
| Add | 20000 | 加法修正 |
| Pct | 30000 | 第一層百分比修正(基數為 10000) |
| FinalAdd | 40000 | 最終加法修正 |
| FinalPct | 50000 | 最終百分比修正(基數為 10000) |

重算公式由 `AttributeCore.CalculateFinal` 提供：

```csharp
public static long CalculateFinal(long baseValue, long addValue, long pctValue, long finalAddValue, long finalPctValue)
{
    checked
    {
        var firstLayer = (baseValue + addValue) * (PercentBase + pctValue) / PercentBase;
        return (firstLayer + finalAddValue) * (PercentBase + finalPctValue) / PercentBase;
    }
}
```

## 操作步驟

### 1. 在玩家實體上掛載屬性元件

`PlayerAttributeComponent` 已使用 `[ComponentType(GlobalConst.ActorTypePlayer)]` 標註，玩家實體建立時自動掛載，無需手動註冊。

```csharp
[ComponentType(GlobalConst.ActorTypePlayer)]
public sealed class PlayerAttributeComponent : StateComponent<PlayerAttributeState>
{
}
```

Source: [PlayerAttributeComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/Component/PlayerAttributeComponent.cs#L38-L40)

### 2. 寫入並重算最終屬性

透過 `PlayerAttributeComponentAgent` 的變更入口修改派生槽後，使用 `AttributeCore.RecalculateFinal` 重新計算最終值，並寫入對應 Final 槽。`TryGetFinalAttribute` 會從派生槽反推所屬的最終屬性。

```csharp
var state = await agent.GetState();
var attributes = state.Attributes;

// 修改 Life 的 Base 槽
var baseKey = AttributeCore.GetSlotAttribute(AttributeType.Life, AttributeSlotKind.Base);
attributes[baseKey] = 100;

// 重新計算 Life 最終值
attributes[AttributeType.Life] = AttributeCore.RecalculateFinal(attributes, AttributeType.Life);
```

Source: [AttributeCore.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/AttributeCore.cs#L46-L109)

### 3. 監聽屬性變更事件

訂閱 `AttributeChangedEventArgs` 以回應屬性變化(由 `PlayerAttributeChangedEventListener` 等具體監聽器處理)。事件攜帶變更的屬性編號與新值。

```csharp
public class AttributeChangedEventArgs : EventArgs
{
    public AttributeType AttributeType { get; }
    public long OldValue { get; }
    public long NewValue { get; }
}
```

Source: [AttributeChangedEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/EventData/AttributeChangedEventArgs.cs)

### 4. 使用初始預設值

玩家首次登入時，透過 `PlayerInitialAttributeDefaults` 提供的初始化資料填充 Base 槽，再觸發首次重算，得到初始最終屬性。

## 常見變體

- **百分比加成**：裝備 / Buff 只改 `Pct` 或 `FinalPct` 槽，不需要直接計算最終值；玩家下線時移除對應修正即可。
- **跨實體屬性聚合**：若需要把多個來源(玩家 + 寵物 + 裝備)合併計算，可分別在各自維護一份屬性字典，在最終讀取處統一呼叫 `AttributeCore.RecalculateFinal`。
- **批次重算**：多個最終屬性同時變化時，遍歷已知最終屬性(`AttributeCore.IsFinalAttribute` 回傳 true 的 9 個列舉值)逐個呼叫 `RecalculateFinal` 即可。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `ArgumentOutOfRangeException: 必须传入已知最终属性。` | 把非最終屬性或派生槽直接傳給 `RecalculateFinal` | 只對 `IsFinalAttribute` 回傳 true 的屬性呼叫重算 |
| `ArgumentOutOfRangeException: 必须传入已知属性数值槽。` | `AttributeSlotKind` 傳入了未定義的自訂值 | 限定使用 6 個內建列舉值 |
| 最終屬性始終為 0 | 派生槽缺失但未觸發重算 | 修改任一派生槽後，必須呼叫 `RecalculateFinal` 並回寫 `Final` 槽 |
| 百分比加成結果偏差 100 倍 | 把 `0.5` 直接寫入 Pct 槽 | Pct / FinalPct 槽使用基數為 `10000`,50% 寫入 `5000` |

## 背景(選用)

屬性編號設計上以 10000 / 20000 / 30000 等固定偏移區分槽位，使得任意派生槽都能透過 `value % PercentBase` 反推所屬最終屬性，便於統一處理變更事件。`PercentBase = 10000` 既避免浮點精度問題，也方便企劃按「萬分比」配置數值。
