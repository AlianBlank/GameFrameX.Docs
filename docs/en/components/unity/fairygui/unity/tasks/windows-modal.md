# Windows, Popups, and Modal Waiting

FairyGUI's `GWindow` handles window display, hiding, modality, and dragging; `GWindow.ShowModalWait`/`CloseModalWait` provides modal waiting within a window, while `GRoot.ShowModalWait` provides full-screen modal waiting. This page provides the complete steps from creating a window, setting modality, to using modal waiting.

## Prerequisites

- This package has been imported into the project, with the FairyGUI runtime located in the `Runtime/` directory.
- The UI package has been exported with the FairyGUI editor and loaded via `UIPackage.AddPackage` (the package name used in the examples below is `ModalWaiting`).

## Steps

### 1. Define a window subclass and set contentPane in OnInit

The content displayed by a window is set via `contentPane`; it is recommended to do this in `OnInit`. Below is the modal waiting example included in the repository:

```csharp
using FairyGUI;

public class Window4 : Window
{
    public Window4()
    {
    }

    protected override void OnInit()
    {
        this.contentPane = UIPackage.CreateObject("ModalWaiting", "TestWin").asCom;
        this.contentPane.GetChild("n1").onClick.Add(OnClick);
    }

    void OnClick()
    {
        this.ShowModalWait();
        Timers.inst.Add(3, 1, (object param) => { this.CloseModalWait(); });
    }
}
```

### 2. Show the window and set modality

`GWindow` provides two display entry points, `Show`/`ShowOn`, both of which are handled uniformly by `GRoot.ShowWindow` internally:

```csharp
public void Show()
{
    GRoot.inst.ShowWindow(this);
}

public void ShowOn(GRoot r)
{
    r.ShowWindow(this);
}
```
Source: [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L186-L201)

When modality is needed (blocking full-screen clicks behind the popup), set `modal` to `true` before calling `Show()`:

```csharp
public bool modal
{
    get { return _modal; }
    set { _modal = value; }
}
```
Source: [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L262-L269)

`GRoot` internally holds the modal blocking layer field `_modalLayer`; window display and layering are handled uniformly by `GRoot.ShowWindow(GWindow win)` (see [GRoot.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GRoot.cs#L35-L36) and [GRoot.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GRoot.cs#L126-L130)).

Call `CenterOn` when the window needs to be centered:

```csharp
public void CenterOn(GRoot r, bool restraint)
{
    this.SetXY((int)((r.width - this.width) / 2), (int)((r.height - this.height) / 2));
    if (restraint)
    {
        this.AddRelation(r, RelationType.Center_Center);
        this.AddRelation(r, RelationType.Middle_Middle);
    }
}
```

### 3. Show/close the in-window modal waiting

`GWindow.ShowModalWait` displays a waiting indicator at the front of the window; the resource is specified via `UIConfig.windowModalWaiting`:

```csharp
public void ShowModalWait()
{
    ShowModalWait(0);
}

public void ShowModalWait(int requestingCmd)
{
    if (requestingCmd != 0)
        _requestingCmd = requestingCmd;

    if (UIConfig.windowModalWaiting != null)
    {
        if (_modalWaitPane == null)
        {
            _modalWaitPane = UIPackage.CreateObjectFromURL(UIConfig.windowModalWaiting);
            _modalWaitPane.SetHome(this);
        }

        LayoutModalWaitPane();

        AddChild(_modalWaitPane);
    }
}
```
Source: [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L279-L310)

To close it, use `CloseModalWait(int requestingCmd)`: if the `requestingCmd` passed in differs from the one used with `ShowModalWait`, the function returns immediately with no effect; it only actually closes when they match. The original source comment reads:

> Closes the modal wait. If requestingCmd is different from the one passed in to ShowModalWait, this function performs no action and returns immediately.

Source: [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L334-L349)

Layout logic of the waiting pane: when `contentArea` is set, it only covers the content area; otherwise it fills the entire window:

```csharp
virtual protected void LayoutModalWaitPane()
{
    if (_contentArea != null)
    {
        Vector2 pt = _frame.LocalToGlobal(Vector2.zero);
        pt = this.GlobalToLocal(pt);
        _modalWaitPane.SetXY((int)pt.x + _contentArea.x, (int)pt.y + _contentArea.y);
        _modalWaitPane.SetSize(_contentArea.width, _contentArea.height);
    }
    else
        _modalWaitPane.SetSize(this.width, this.height);
}
```
Source: [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L312-L323)

### 4. Use full-screen modal waiting (locking the entire screen)

`GRoot.ShowModalWait()` locks the entire screen using the resource specified by `UIConfig.globalModalWaiting`, suitable for scenarios such as network waiting. See its definition in [GRoot.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GRoot.cs#L203-L204); `GRoot` is the topmost component of the UI display list, created automatically by the framework, and can be accessed directly via `GRoot.inst`:

```csharp
public static GRoot inst
{
    get
    {
        if (_inst == null)

```

## Common Window Lifecycle

Recommended practices given in the source class comments (summary of the original text):

- Put initialization operations such as setting `contentPane` in `Window.OnInit`;
- Creating windows dynamically: call `Window.addUISource` in the constructor, passing in your own implementation of `IUISource`; resources are loaded before `OnInit` is executed when the window is shown for the first time;
- Show animation: override `doShowAnimation`, and call `onShown` when the animation ends; write business logic in `onShown`;
- Hide animation: override `doHideAnimation`, and call `HideImmediately` when the animation ends (note: do not call `onHide` directly); write business logic in `onHide`.

## Common Mistakes

- **Calling `CloseModalWait(cmd)` has no effect**: the `requestingCmd` passed in does not match the one used with `ShowModalWait`, so the function returns directly. Both calls must use the same command word, or both use the parameterless version.
- **`ShowModalWait` does not display anything**: when `UIConfig.windowModalWaiting` is `null`, no waiting pane is created; likewise, full-screen waiting requires `UIConfig.globalModalWaiting` to be set. These two configuration items are defined in [UIConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIConfig.cs#L22-L29).
- **The window is not actually hidden after the hide animation**: after overriding `doHideAnimation`, you must call `HideImmediately` when the animation ends instead of calling `onHide` directly.
- **The modal waiting pane covers the entire window**: when `contentArea` is set, the pane only covers the content area; otherwise it fills the window; specify it in `OnInit` as needed.
