# 如何打包 Asset Bundle 资源

按照本页操作后,你可以让 GameFrameX 的构建器基于 [YooAsset](https://github.com/tuyoogame/YooAsset) 把项目资源打成 Asset Bundle,并按配置决定是否启用增量构建、上传对象存储、推送版本与企微通知。

## 前置条件

- Unity 编辑器已打开目标工程,并安装本仓库的 `com.gameframex.unity.builder` 包。
- 已安装 `YooAsset` 与 `GameFrameX.Editor`(本包依赖),以便 `Builder.BuildAsset()` 能调用到 `EBuildPipeline`、`AssetBundleCollectorSettingData`、`AssetBundleBuilderSetting` 等类型。
- YooAsset 资源收集器(`AssetBundleCollectorSettingData`)中已配置好要收集的资源包(否则循环不到任何 `Packages`)。
- 通过 [Builder.BuildParamsParse](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs) 传入 `_builderOptions`,或自行在调用 `Builder.BuildAsset()` 前对其赋值。

## 操作步骤

1. 在 Editor 菜单或 CI 脚本中调用 `Builder.BuildAsset()`,框架会先复制热更 DLL 与 AOT 代码,并强制把所有收集包的 `LocationToLower` 设为 `true`,保证文件大小写不敏感:

   ```csharp
   Debug.Log("BuildAsset Start Copy Hotfix Code");
   BuildHotfixHelper.CopyHotfixCode();
   AssetDatabase.Refresh();
   BuildHotfixHelper.CopyAOTCode();
   AssetDatabase.Refresh();

   foreach (var assetBundleCollectorPackage in AssetBundleCollectorSettingData.Setting.Packages)
   {
       assetBundleCollectorPackage.LocationToLower = true;
   }
   AssetBundleCollectorSettingData.SaveFile();
   ```

   Source: [Builder.BuildAsset.cs#L17-L37](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L17-L37)

2. 选择构建管线。可选值为 `ScriptableBuildPipeline`、`RawFileBuildPipeline`(未匹配则回退 `BuiltinBuildPipeline`),通过 `_builderOptions.BuildPipeline` 传入:

   ```csharp
   if (!Enum.TryParse(typeof(EBuildPipeline), _builderOptions.BuildPipeline, true, out var buildPipelineObj))
   {
       Debug.LogError($"无效的构建管线类型: {_builderOptions.BuildPipeline}，可选值: {string.Join(", ", Enum.GetNames(typeof(EBuildPipeline)))}");
       return;
   }
   ```

   Source: [Builder.BuildAsset.cs#L40-L64](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L64)

3. 准备 `BuildParameters`。在此步骤里把构建模式(BuildMode / ForceRebuild)、目标平台、版本号、文件名风格、输出根目录、内置拷贝目录、是否启用共享包规则等一次性配置完毕:

   ```csharp
   buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage ? EBuildMode.IncrementalBuild : EBuildMode.ForceRebuild;
   buildParameters.BuildTarget = EditorUserBuildSettings.activeBuildTarget;
   buildParameters.PackageVersion = string.IsNullOrWhiteSpace(_builderOptions.PackageVersion)
       ? DateTime.Now.ToString("yyyyMMddHHmmss")
       : _builderOptions.PackageVersion;
   buildParameters.VerifyBuildingResult = true;
   buildParameters.FileNameStyle = EFileNameStyle.HashName;
   buildParameters.BuildOutputRoot = AssetBundleBuilderHelper.GetDefaultBuildOutputRoot();
   buildParameters.BuildinFileRoot = AssetBundleBuilderHelper.GetStreamingAssetsRoot();
   buildParameters.PackageName = _builderOptions.PackageName;
   buildParameters.EnableSharePackRule = true;
   buildParameters.EncryptionServices = new EncryptionNone();
   ```

   Source: [Builder.BuildAsset.cs#L65-L94](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L65-L94)

4. 执行构建并捕获异常,失败时 `Environment.Exit(1)` 让 CI 进程立刻失败:

   ```csharp
   bool isSuccess = false;
   try
   {
       pipeline.Run(buildParameters, true);
       isSuccess = true;
   }
   catch (Exception e)
   {
       Debug.LogException(e);
       Environment.Exit(1);
   }
   ```

   Source: [Builder.BuildAsset.cs#L95-L107](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L95-L107)

5. 构建成功后,根据 `_builderOptions` 的开关决定是否上传资源包、更新版本号、发企微通知。完整 `finally` 分支如下:

   ```csharp
   if (isSuccess && _builderOptions.IsUploadAsset)
   {
       string savePath = $"Bundles/{PlayerSettings.applicationIdentifier}/{EditorUserBuildSettings.activeBuildTarget}/{Application.version}/{_builderOptions.ChannelName}/{_builderOptions.PackageName}/{buildParameters.PackageVersion}";
       string uploadPath = $"{buildParameters.BuildOutputRoot}/{buildParameters.BuildTarget}/{Application.version}/{buildParameters.PackageName}/{buildParameters.PackageVersion}";
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.SetSavePath(savePath);
       ObjectStorageUploadManager.UploadDirectory(uploadPath);
   #endif
   }
   if (_builderOptions.IsUpdateAssetPackageVersion)
   {
       BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
   }
   ```

   Source: [Builder.BuildAsset.cs#L108-L143](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L108-L143)

## 常见变体

- **切换构建管线**: 修改 `_builderOptions.BuildPipeline`,可选 `ScriptableBuildPipeline` / `RawFileBuildPipeline`,其他值走 `BuiltinBuildPipeline`。
- **强制全量构建**: 把 `IsIncrementalBuildPackage` 设为 `false`,构建模式变为 `EBuildMode.ForceRebuild`。
- **控制内置包拷贝策略**: `_builderOptions.BuildinFileCopyOption` 留空则按 `ClearAndCopyAll` 处理,否则按 `EBuildinFileCopyOption` 枚举解析,无效值会直接 `return`。
- **上传日志/资源到对象存储**: 提前在编译符号中开启 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 及对应子模块(七牛/腾讯/阿里云),见 [Builder.cs#L27-L48](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L27-L48)。
- **改用自定义包名/版本**: 直接设置 `_builderOptions.PackageName` 和 `_builderOptions.PackageVersion`,版本号留空时会自动以 `yyyyMMddHHmmss` 填充。

## 常见错误

| 症状(源码报错原文) | 原因 | 修复 |
|---|---|---|
| `无效的构建管线类型: {xxx}` | `_builderOptions.BuildPipeline` 字符串无法解析为 `EBuildPipeline` | 按枚举名传值:`BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` |
| `无效的内置文件拷贝选项: {xxx}` | `_builderOptions.BuildinFileCopyOption` 不是 `EBuildinFileCopyOption` 枚举值 | 使用合法枚举名,或留空走默认 `ClearAndCopyAll` |
| 构建后进程直接退出码 `1`,控制台抛出异常 | `pipeline.Run` 抛异常,被 catch 后 `Environment.Exit(1)` | 查看 `Debug.LogException(e)` 堆栈修复 YooAsset 配置或收集器后再重跑 |
| `Builder.BuildAsset()` 一进来 `Packages` 列表为空 | YooAsset 资源收集器(`AssetBundleCollectorSettingData`)未配置 | 先在 YooAsset 工具栏里添加收集包再触发构建 |

## 背景(可选)

`Builder.BuildAsset()` 会在 YooAsset 之上做三件事:① 拷贝热更 DLL 与 AOT 代码;② 强制把收集包路径转为小写,避免 Linux/Android 上大小写差异导致打包失败;③ 调用对应 `IBuildPipeline`(`BuiltinBuildPipeline` 等)生成清单,并依据 `_builderOptions` 决定是否上传与版本通知。`EnableSharePackRule = true` 让资源可以打共享包,减少首包体积;加密接口默认 `EncryptionNone`,可在调用前自行替换 `buildParameters.EncryptionServices`。
