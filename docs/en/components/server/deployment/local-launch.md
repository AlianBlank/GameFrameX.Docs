# Starting Locally with quick_start-game.bat

`quick_start-game.bat` is a one-click startup script for the game server located in the `GameFrameX.Launcher` directory. When executed, it launches a gateway process with `ServerType=Game` locally, automatically connects to the embedded Discovery Center and the MongoDB database. It is ideal for quickly verifying during the development stage whether the service can start up.

## Prerequisites

- Windows system with .NET 10.0 SDK or runtime installed (`TargetFramework=net10.0`)
- This repository has been cloned or downloaded, and a Release build of `GameFrameX.Launcher` has been completed, with the output located at `bin\app\GameFrameX.Launcher.dll`
- Port `21001` on the local machine `127.0.0.1` can be listened on by `DiscoveryCenter` (Discovery Center), and ports `29090/29100/29010/29110` are not occupied
- The network can access the MongoDB Atlas address specified in the script (ensure the account `gameframex` / password is valid)

## Steps

1. Open a command line and navigate to the `GameFrameX.Launcher` directory:

   ```bat
   cd GameFrameX.Launcher
   ```

2. Double-click `quick_start-game.bat` directly or execute it from the command line:

   ```bat
   quick_start-game.bat
   ```

   The script actually invokes:

   ```bat
   start dotnet GameFrameX.Launcher.dll --ServerType=Game --ServerId=9000 --APMPort=29090 --InnerIp=127.0.0.1 --InnerPort=29100 --OuterIp=127.0.0.1 --OuterPort=29010 --MinModuleId=1 --MaxModuleId=9999 --WsPort=29110 --DiscoveryCenterIp=127.0.0.1 --DiscoveryCenterPort=21001 --HttpCode=inner_httpcode --DataBaseUrl="mongodb+srv://gameframex:f9v42aU9DVeFNfAF@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority" --DataBaseName=gameframex
   ```

   Source: [quick_start-game.bat](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/quick_start-game.bat#L1-L1)

3. The script uses `start` to launch a new console window that loads `GameFrameX.Launcher.dll`, and the program entry point calls `GameApp.Entry` to complete initialization.

   ```csharp
   internal static class Program
   {
       private static async Task Main(string[] args)
       {
   #if DEBUG
           LogOptions.Default.IsConsole = true;
   #endif
           await GameApp.Entry(args, () =>
           {
               CacheStateTypeManager.Init();
               MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
           }, LogAction);
       }
   ```

   Source: [Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L5-L17)

4. Observe the logs in the newly opened console window: when you see the four ports — APM, Inner, Outer, and Ws — begin listening in sequence, with no error stack traces, it means the game server has been successfully started locally.

## Startup Parameters

| Parameter | Value | Description |
|------|-----|------|
| `--ServerType` | `Game` | The process type is game server (gateway) |
| `--ServerId` | `9000` | Unique ID of the current server |
| `--APMPort` | `29090` | Application performance management / management port |
| `--InnerIp` / `--InnerPort` | `127.0.0.1` / `29100` | Internal network communication address |
| `--OuterIp` / `--OuterPort` | `127.0.0.1` / `29010` | External client access address |
| `--MinModuleId` / `--MaxModuleId` | `1` / `9999` | Message module ID allocation range |
| `--WsPort` | `29110` | WebSocket port |
| `--DiscoveryCenterIp` / `--DiscoveryCenterPort` | `127.0.0.1` / `21001` | Registry center address |
| `--HttpCode` | `inner_httpcode` | HTTP routing code |
| `--DataBaseUrl` | Atlas connection string | MongoDB connection address |
| `--DataBaseName` | `gameframex` | Database name |

## Common Errors

- **`GameFrameX.Launcher.dll` not found**: This means the project has not been compiled yet, or the output directory is not the `bin\app` expected by the script. In the `csproj`, the Release configuration outputs to `..\bin\app\`. Please first run `dotnet build -c Release` in the solution root directory, or build in the `GameFrameX.Launcher` directory.

  Source: [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L20-L23)

- **`dotnet` is not recognized as an internal or external command**: The .NET 10 SDK is not installed, or `dotnet.exe` was not added to PATH after installation.

- **Failed to connect to `127.0.0.1:21001`**: The Discovery Center is not running. `quick_start-game.bat` only launches the Game server; you need to start the `DiscoveryCenter` service separately first, then run this script.

- **MongoDB connection error**: The script hardcodes the account `gameframex` and its password. If this account has been reclaimed or the network is restricted, you need to change the `--DataBaseUrl` in the script to a working connection string.

## Background

`GameFrameX.Launcher` serves both as the Game server entry point and as the location of the build output (`bin\app\GameFrameX.Launcher.dll`). By passing different startup parameters, the same process model can be reused to launch different types of servers. `quick_start-game.bat` consolidates the commonly used Game server parameters into a single `start dotnet ...` command, eliminating the hassle of manually assembling parameters each time.
