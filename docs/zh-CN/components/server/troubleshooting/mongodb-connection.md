# MongoDB 连接失败或实体序列化报错怎么办

启动服务时遇到 `MongoDB connection failed`、`数据库服务启动失败`、`No serializer found for ...`、`An error occurred while deserializing ...` 等报错时，按本页诊断表定位原因，再按对应小节修复。

## 快速诊断

| 症状（控制台/日志原文） | 根因 | 修复 |
|---|---|---|
| `数据库服务启动失败` / `MongoDB connection failed` / `TimeoutException` | `DataBaseUrl` 不可达、账号密码错误、authSource 不匹配、单机直连没开 `directConnection` | 见「连接配置错误」 |
| `MongoCommandException: Authentication failed` | 用户名/密码错误或目标库没创建账号 | 见「认证失败」 |
| `No serializer found for type X` / `An error occurred while deserializing the X bson element ...` | 实体类没有注册 BsonClassMap，或基类带 `BaseCacheState` 的字段没忽略 | 见「实体序列化失败」 |
| 启动时卡住或首次 `Insert`/`Find` 抛 `MongoConnectionException` | Docker 容器未启动、端口被占用、或服务先于 mongo 启动 | 见「服务依赖与端口」 |
| 写入后字段全是 `_t` discriminator，但读出来是 `null` | 多程序集用了同一全类名且未设置 `Discriminator`，或子类未注册 | 见「实体序列化失败 → Discriminator 冲突」 |

## 修复步骤

### 连接配置错误

1. 确认配置键 `DataBaseUrl` 的写法。默认通过 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L61-L65) 中的 `Setting.DataBaseUrl` 传给 `GameDb.Init<MongoDbService>`，连接串格式必须符合 MongoDB Driver 要求。

2. 本机 Docker 启动时使用 [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L2-L13) 自带的容器配置：

   ```yaml
   mongodb:
     image: mongo
     container_name: mongodb
     ports:
       - "27017:27017"
     volumes:
       - ./running/database:/data/db
     environment:
       - MONGO_INITDB_ROOT_USERNAME=admin
       - MONGO_INITDB_ROOT_PASSWORD=admin
   ```

   对应的连接串示例（与 compose 中环境变量一致）：

   ```bash
   DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L60-L72)

3. 使用 [MongoDB Atlas](https://www.mongodb.com/atlas) 等云服务时，保持 `mongodb+srv://` 形式，并附带 `retryWrites=true&w=majority`：

   ```csharp
   DataBaseUrl = "mongodb+srv://gameframex:***@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority",
   DataBaseName = "gameframex",
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L112-L113)

4. 本地直连 `127.0.0.1` 时若遇到 `No routing to host`，加上 `directConnection=true`：

   ```text
   mongodb://admin:admin@127.0.0.1:27017/?authSource=admin&directConnection=true
   ```

### 认证失败

1. 检查 `MONGO_INITDB_ROOT_USERNAME`/`MONGO_INITDB_ROOT_PASSWORD` 与连接串里的账号是否一致。
2. 当账号建在 `admin` 而目标库是 `gameframex` 时，连接串必须带 `?authSource=admin`，否则 driver 会用默认库校验而抛 `Authentication failed`。
3. 自建账号后只对单一库授权：`authSource` 必须等于该库名。

### 服务依赖与端口

1. `docker compose up mongodb -d` 先确认容器健康：

   ```bash
   docker ps --filter name=mongodb
   docker logs mongodb --tail 50
   ```

2. 容器和游戏进程必须在同一个 `gameframex` 网络下；单独运行游戏进程时把 `DataBaseUrl` 的主机名换成 `localhost` 或对应 IP。
3. 主机端口 `27017` 被占用时修改 compose 映射（如 `"27018:27017"`），连接串同步改成 `27018`。

### 实体序列化失败

1. 启动时会扫描程序集内所有继承 `BaseCacheState`/`CacheState` 的实体并注册 BsonClassMap。注册入口见 [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)：

   ```csharp
   var assembly = typeof(AppsHandler).Assembly;
   BsonClassMapHelper.SetConvention();
   foreach (var type in assembly.GetTypes())
   {
       if (!typeof(BaseCacheState).IsAssignableFrom(type)) continue;
       HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
       BsonClassMapHelper.RegisterClass(type);
   }
   ```

   Source: [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)

2. `BsonClassMapHelper` 会自动映射并忽略多余字段，参考实现 [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)：

   ```csharp
   var bsonClassMap = new BsonClassMap(t);
   bsonClassMap.AutoMap();
   bsonClassMap.SetIgnoreExtraElements(true);
   bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
   BsonClassMap.RegisterClassMap(bsonClassMap);
   ```

   Source: [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

3. 出现 `No serializer found for type X` 时的常见原因与处理：
   - 实体类未继承 `BaseCacheState`，被注册流程跳过 — 让实体继承 `BaseCacheState` 或在调用前手动 `BsonClassMap.RegisterClassMap<T>()`。
   - 实体在另一个程序集（如 `GameFrameX.Hotfix`）中定义，但 `CacheStateTypeManager` 只扫描了 `AppsHandler` 程序集 — 在热更入口同步调用一次注册，或扩展扫描器覆盖 Hotfix 程序集。
   - 实体使用了泛型参数未具体化 — 在注册前补齐泛型实参。

4. **Discriminator 冲突**：不同子类型同名、跨程序集同全类名都会让反序列化拿到 `null`。在实体类上显式指定：

   ```csharp
   [BsonDiscriminator("player_attr_v1")]
   public sealed class PlayerAttributeState : BaseCacheState { /* ... */ }
   ```

5. **基类字段污染**：`BaseCacheState` 自带的字典/版本号字段若不想写入 MongoDB，给字段加 `[BsonIgnore]`；已经 `SetIgnoreExtraElements(true)` 只忽略读取方向，写入仍需显式忽略。

6. 启动顺序由 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67) 保证：`GameDb.Init` → `ComponentRegister.Init` → `HotfixManager.LoadHotfixModule`。热更里直接读 Mongo 的代码必须放在最后一步之后，否则序列化器还没注册就会抛 `No serializer found`。

## 验证

1. 重启服务，观察启动日志依次出现：`开始启动数据库服务...` → `启动数据库服务 结束...` → `注册组件开始/结束` → `加载热更新模块结束`。
2. 在 Mongo Shell 或 Compass 中执行 `db.runCommand({ ping: 1 })`，应返回 `{ ok: 1 }`。
3. 用任意实体类的 `Insert`/`Find` 走一遍读写流程，断言读出字段与写入一致。
4. 故意把 `DataBaseUrl` 改成错误地址再次启动，应立即抛 `数据库服务启动失败` 并打印根因栈 — 用来确认异常透传链路是通的。
