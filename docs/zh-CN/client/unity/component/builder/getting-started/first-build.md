# 运行第一个构建

按照本页步骤，你可以在 Unity 中通过命令行触发 GameFrameX Builder 的自动化构建，并产出第一个 APK / 资源包。

## 前置条件

- Unity 2019.4 或更高版本
- 已通过 `Packages/manifest.json` 安装 `com.gameframex.unity.builder`（推荐 2.0.3 及以上）
- 一个已配置好 Player Settings（包名、版本号、图标等）的 Unity 工程

在 `manifest.json` 中添加 scoped registry 与依赖的最小可用配置：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.builder": "2.0.3"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L36-L72)

## 操作步骤

1. **打开 Unity 工程，等待包导入完成**。在 `Packages` 下能看到 `com.gameframex.unity.builder` 即可。

2. **确认 `-executeMethod` 目标方法可用**。构建入口位于 `GameFrameX.Builder.Editor.Builder`，最常用的两个方法是：

   | 方法 | 作用 |
   |------|------|
   | `GameFrameX.Builder.Editor.Builder.BuildApk` | 打包 APK，并在开启 `-IsUploadApk` 时上传到对象存储 |
   | `GameFrameX.Builder.Editor.Builder.BuildAsset` | 构建 YooAsset 资源包 |

   Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L51-L78)

3. **在命令行触发构建**。最简单的命令行形式（以 BuildApk 为例）：

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath /path/to/your/project \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
         -BUILD_NUMBER 1 \
         -logFile /path/to/build.log
   ```

   `-BUILD_NUMBER` 是必填项；`-logFile` 缺省时 Builder 会自动生成日志路径。

4. **查看构建结果**。`-BUILD_NUMBER`、`-AppVersion`、`-BundleId` 等参数会被 `Builder.BuildParamsParse` 解析到 `BuilderOptions`，驱动整条构建管线。日志文件路径由 `-logFile` 指定，APK 输出位置由 Unity 的 BuildPlayerAndroid 决定。

   Source: [Builder.BuildParamsParse.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs)

## 常见变体

### 仅打资源包（不发 APK）

把 `-executeMethod` 换成 `GameFrameX.Builder.Editor.Builder.BuildAsset`，再指定资源构建参数：

```bash
Unity -batchmode -nographics -quit \
      -projectPath /path/to/your/project \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
      -BUILD_NUMBER 1 \
      -PackageName DefaultPackage \
      -BuildPipeline BuiltinBuildPipeline \
      -IsIncrementalBuildPackage false
```

资源构建参数（节选）：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-PackageName` | `DefaultPackage` | 资源包名称 |
| `-PackageVersion` | 时间戳 | 留空时自动使用时间戳 |
| `-BuildPipeline` | `BuiltinBuildPipeline` | 可选 `BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` |
| `-BuildinFileCopyOption` | `ClearAndCopyAll` | 内置文件拷贝选项 |
| `-IsIncrementalBuildPackage` | `false` | 是否增量构建 |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L97-L106)

### 在 CI 中加日志与上传

构建时加上以下标记，可在打包结束后上传日志/APK/资源包到对象存储：

```bash
-IsUploadLogFile \
-IsUploadApk \
-IsUploadAsset \
-ObjectStorageKey <key> \
-ObjectStorageSecret <secret> \
-ObjectStorageBucketName <bucket> \
-ObjectStorageEndPoint <endpoint>
```

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `executeMethod` 找不到目标方法 | 包未正确导入，或命名空间拼写错误 | 确认 `Packages` 下存在 `com.gameframex.unity.builder`，方法全名应为 `GameFrameX.Builder.Editor.Builder.BuildApk` |
| 报缺少 `-BUILD_NUMBER` | 必填参数未传入 | 在命令行补上 `-BUILD_NUMBER <n>` |
| 对象存储上传失败 | 未启用对象存储宏 | 确认工程安装了对应对象存储子包并启用了 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 系列宏 |

## 背景（可选）

Builder 在静态构造阶段会调用 `BuildParamsParse` 把命令行参数解析到 `BuilderOptions`，再按 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_*` 宏选择对象存储实现。`BuildApk` 仅负责调起 Unity 出包并按需上传；资源构建则走独立的 `BuildAsset` 路径。关于 Builder 的整体参数表，见《命令行参数参考》。
