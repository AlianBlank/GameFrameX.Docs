# How to Use Core Subsystems: Events, Procedures, State Machines, Timers, etc.

`GameFrameX` exposes four major runtime subsystems through the `GameApp` static facade—Event, Procedure, Fsm, and Timer—each carried by a corresponding `*Component`, trimmed via feature macros (`ENABLE_GAME_FRAME_X_*`), and uniformly lazily loaded through `GameEntry.GetComponent<>()`.

## Prerequisites

- `com.gameframex.unity.entry` has been imported via the Package Manager, and the **Event / Procedure / Fsm / Timer** submodules have been enabled as needed in `HybridCLR/GameFrameX Settings` (corresponding to auto-generated macros such as `ENABLE_GAME_FRAME_X_EVENT`).
- Each subsystem in `GameApp.*.cs` is wrapped inside `#if ENABLE_GAME_FRAME_X_*`. If the macro is not enabled, the `GameApp.Event / Procedure / Fsm / Timer` properties will not be compiled. Make sure to confirm before referencing them.

## Unified Access Method

All subsystems are obtained through the `GameApp` static class, lazily created by the internal `_xxx` cache fields upon first access:

```csharp
using GameFrameX.Runtime;

var evt    = GameApp.Event;     // EventComponent
var proc   = GameApp.Procedure; // ProcedureComponent
var fsm    = GameApp.Fsm;       // FsmComponent
var timer  = GameApp.Timer;     // TimerComponent
```

> If the feature macro is disabled, accessing the corresponding property will trigger a "component not found" error or a compilation error. Enable the corresponding feature in the project settings first.

## Steps

### 1. Using the Event Subsystem

The event component handles global event subscription and broadcasting; its type is located at `GameFrameX.Event.Runtime.EventComponent`.

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;

// Subscribe
GameApp.Event.Subscribe<TestEvent>(OnTestEvent);

void OnTestEvent(object sender, TestEvent e)
{
    // Handle event
}

// Fire
GameApp.Event.Fire(sender, new TestEvent { /* fields */ });

// Unsubscribe
GameApp.Event.Unsubscribe<TestEvent>(OnTestEvent);
```

### 2. Using the Procedure Subsystem

The procedure component drives switching between `ProcedureBase` derived classes; its type is located at `GameFrameX.Procedure.Runtime.ProcedureComponent`.

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

// Enter the first procedure (usually after game startup completes)
GameApp.Procedure.StartProcedure<LaunchProcedure>();

// Switch at runtime
GameApp.Procedure.StartProcedure<LoginProcedure>();

// Check current procedure
if (GameApp.Procedure.CurrentProcedure is LoginProcedure) { /* ... */ }
```

Each procedure class must inherit from `ProcedureBase` and implement the `OnEnter` / `OnUpdate` / `OnLeave` lifecycle.

### 3. Using the State Machine Subsystem

The state machine component hosts multiple `Fsm<T>` instances; its type is located at `GameFrameX.Fsm.Runtime.FsmComponent`.

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Runtime;

// Create and start a state machine
var fsm = GameApp.Fsm.Create("PlayerFsm", owner, new IdleState(), new RunState(), new AttackState());
GameApp.Fsm.StartFsm("PlayerFsm");

// Change state
fsm.ChangeState<RunState>();
```

State classes must inherit from `FsmState<T>` and override `OnEnter` / `OnUpdate` / `OnLeave`.

### 4. Using the Timer Subsystem

The timer component supports one-shot, repeating, frame-based, and various other task types; its type is located at `GameFrameX.Timer.Runtime.TimerComponent`.

```csharp
using GameFrameX.Timer.Runtime;
using GameFrameX.Runtime;

// Start a one-shot timer
int id = GameApp.Timer.AddOnce(5f, () => { /* Executes after 5 seconds */ });

// Start a repeating timer
int loopId = GameApp.Timer.AddRepeating(1f, () => { /* Executes every second */ });

// Cancel
GameApp.Timer.Remove(loopId);
```

## Common Variants

- **Sharing data across procedures**: Attach data to derived fields of `ProcedureBase`, and access it alongside `GameApp.Procedure.CurrentProcedure` as it switches.
- **Events + state machines**: Call `GameApp.Event.Subscribe` in the state's `OnEnter` and `Unsubscribe` in `OnLeave` to avoid responding after leaving.
- **Timer granularity**: In addition to second-level timers, `TimerComponent` also provides a frame-count version (frame-driven), suitable for logic that does not depend on time scaling.

## Common Errors

- **Accessing without enabling the feature macro**: No compilation error, but a "component not registered" runtime error occurs. Solution: check the corresponding subsystem macro in project settings.
- **Memory leak from unsubscribed events**: You must call `Unsubscribe` before destroying objects, especially when a `MonoBehaviour` holds the callback.
- **Procedure/state machine missing base class methods**: Forgetting `OnEnter` after inheriting from `ProcedureBase` / `FsmState<T>` will cause silent inaction during switching.
