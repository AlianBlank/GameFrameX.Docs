# GameApp.{Name} 访问为 null 或报空引用怎么办

访问 `GameApp.XXX`（如 `GameApp.Asset`、`GameApp.Base`）返回 `null` 或抛出 `NullReferenceException`，通常是因为对应组件未在启动时被注册到 `GameEntry`,或者在框架初始化前就调用了属性。`GameApp` 只是对 `GameEntry.GetComponent<T>()` 的缓存封装,真正的组件实例由 `GameEntry` 管理。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameApp.XXX` 返回 `null` | 对应组件未注册到 `GameEntry`,或对应的宏/条件编译未启用 | 确认组件类已挂到 `GameEntry` 启动预制体/注册流程,并启用对应宏(如 `ENABLE_GAME_FRAME_X_ASSET`) |
| 在 `Awake`/`Start` 早期访问 `GameApp.XXX` 报空 | 框架初始化未完成 | 改在框架初始化完成回调(如 `GameEntry.OnGameFrameInitialized`)之后再调用,或在业务脚本的 `OnEnable` 之后 |
| 报 `NullReferenceException: Object reference not set to an instance of an object` | 调用前未做空判断,且组件未注册 | 加上空判断,并按上两条修复注册/调用时机 |
| 报 `KeyNotFoundException` / 找不到组件类型 | 组件 DLL/程序集未打进项目,或命名空间不一致 | 确认组件所在程序集已引用,并 `using GameFrameX.Runtime;` |
| 启用/禁用宏后突然变 null | 组件被 `#if` 条件编译整体排除,`GameApp.XXX` 字段不存在 | 在 `#if` 块外不要访问该属性;改用 `GameEntry.GetComponent<T>()` 兜底 |

## 修复步骤

### 1. 确认组件已注册到 GameEntry

`GameApp` 的实现本质是延迟从 `GameEntry` 取组件:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }

    private static BaseComponent _base;
}
```

Source: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L52)

如果 `GameEntry.GetComponent<BaseComponent>()` 找不到组件,`_base` 会保持 `null`。请检查启动流程里是否把 `BaseComponent` 等组件挂到了 `GameEntry` 的初始化列表中。

### 2. 检查条件编译宏

很多 `GameApp.XXX` 是被宏包裹的,例如 `GameApp.Asset` 要求 `ENABLE_GAME_FRAME_X_ASSET`:

```csharp
#if ENABLE_GAME_FRAME_X_ASSET
public static partial class GameApp
{
    public static AssetComponent Asset
    {
        get
        {
            if (_asset == null)
            {
                _asset = GameEntry.GetComponent<AssetComponent>();
            }
            return _asset;
        }
    }

    private static AssetComponent _asset;
}
#endif
```

Source: [Runtime/GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs#L32-L55)

如果没定义对应宏,该 `GameApp.Asset` 属性在编译期就不存在,直接访问会编译报错;反过来,**如果你启用了宏但代码里使用了对应 `GameApp.XXX`,就必须确保对应组件也被注册到 `GameEntry`**。

### 3. 在框架初始化完成后再访问

`GameApp` 的字段是懒加载的静态缓存。如果你在框架 `Awake` 之前的生命周期(如其他单例的 `Awake`)里访问它,组件可能还没注册完毕。请在框架初始化完成事件触发后再访问,或在你的业务脚本 `OnEnable` / `Start` 中访问。

### 4. 加上空判断保护

即便是注册了,也建议在调用前判空,避免在编辑器停止游戏或资源释放阶段访问:

```csharp
if (GameApp.Asset != null)
{
    GameApp.Asset.LoadAsset(...);
}
```

如果频繁需要判空,说明组件本身就不该在此处使用——回到步骤 1 检查注册。

## 验证

执行下面 3 步确认问题解决:

1. 在 `Awake` 中打印 `GameApp.Base` 等关键属性,确认非 `null`。
2. 通过 `GameEntry.GetComponent<T>()` 二次确认组件存在。
3. 在场景里触发一次实际调用(如加载一个资源、发起一次事件),观察是否还有空引用。

如果 `GameEntry.GetComponent<T>()` 始终返回 `null`,说明问题在组件注册流程本身,而不在 `GameApp` 这层——回到 `GameEntry` 的初始化代码排查组件挂载与生命周期顺序。
