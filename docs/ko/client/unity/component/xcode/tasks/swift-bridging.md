# Objective-C/Swift 혼합 브리징 활성화

`XCodeConfig.json`에서 `swiftBridging`을 `true`로 설정합니다(또는 기본값 그대로 두어도 됩니다. 이 설정은 **기본 활성화**되어 있습니다). iOS 프로젝트를 빌드하면 GameFrameX가 Swift 브리징 파일과 브리징 헤더 파일을 자동으로 생성하고, `SWIFT_VERSION=5.0`과 `SWIFT_OBJC_BRIDGING_HEADER`를 설정합니다. 전체 과정에서 Xcode 팝업이 없으므로 CI에서 바로 사용할 수 있습니다.

## 사전 조건

- 프로젝트에 GameFrameX Xcode Config 패키지를 도입했고, 《XCodeConfig.json 설정 개요》에 따라 기본 설정을 완료했어야 합니다(이 패키지는 iOS 빌드 시 후처리를 자동으로 실행하므로 어떤 API도 수동으로 호출할 필요가 없습니다).
- 빌드 대상이 iOS 플랫폼이어야 합니다(관련 코드는 `#if UNITY_IOS` 블록 내에 있습니다).

## 작업 단계

1. 프로젝트 루트 디렉터리(또는 모듈 디렉터리)의 `XCodeConfig.json`을 열어 `swiftBridging`을 `true`로 설정합니다:

   ```json
   {
     "swiftBridging": true
   }
   ```

   > 이 키는 생략할 수 있으며, 생략 시 `true`로 간주됩니다(기본 활성화). 판정 로직은 아래 소스 코드를 참고하세요:

   ```csharp
   // Swift 브리징 설정 (기본 활성화)
   bool swiftBridging = !finalConfig.ContainsKey("swiftBridging") || finalConfig.Get<bool>("swiftBridging");
   SetupSwiftBridging(project, project.GetUnityMainTargetGuid(), project.GetUnityFrameworkTargetGuid(), path, swiftBridging);
   ```

   Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101)

2. Unity에서 iOS 빌드를 실행하면(File → Build Settings → Build) 후처리 단계에서 다음 작업이 자동으로 수행됩니다:

   - 생성된 Xcode 프로젝트 루트 디렉터리에 `gameframex_swift_bridging.swift`를 생성합니다(파일이 존재하지 않을 때만 작성되며, 내용은 `import Foundation`, 파일 헤더에 `DO NOT EDIT`가 표시됩니다);
   - `Unity-iPhone-Bridging-Header.h` 브리징 헤더 파일을 생성합니다;
   - `.swift` 파일을 UnityFramework target 컴파일에 추가하고, 브리징 헤더 파일을 프로젝트에 추가합니다;
   - 메인 target과 UnityFramework target에 `SWIFT_VERSION = 5.0`을 설정하고, 메인 target에 `SWIFT_OBJC_BRIDGING_HEADER = Unity-iPhone-Bridging-Header.h`를 설정합니다.

   핵심 구현:

   ```csharp
   proj.AddFileToBuild(frameworkTargetGuid, proj.AddFile(swiftFile, SwiftBridgingFileName, PBXSourceTree.Source));
   proj.AddFile(bridgingHeaderFile, SwiftBridgingHeaderName, PBXSourceTree.Source);

   proj.SetBuildProperty(mainTargetGuid, "SWIFT_VERSION", "5.0");
   proj.SetBuildProperty(mainTargetGuid, "SWIFT_OBJC_BRIDGING_HEADER", SwiftBridgingHeaderName);

   proj.SetBuildProperty(frameworkTargetGuid, "SWIFT_VERSION", "5.0");

   LogHelper.Log("[SwiftBridging] Swift bridging header configured");
   ```

   Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L37-L45)

3. 결과 검증: 생성된 `.xcodeproj`를 열고 **Unity-iPhone** target 선택 → Build Settings에서 확인합니다:
   - `SWIFT_VERSION`이 `5.0`으로 표시됩니다;
   - `SWIFT_OBJC_BRIDGING_HEADER`가 `Unity-iPhone-Bridging-Header.h`로 표시됩니다;
   - Unity Console에 `[SwiftBridging] Swift bridging header configured`가 출력됩니다.

## 일반적인 변형

- **혼합 브리징 비활성화**: `"swiftBridging": false`를 명시적으로 작성합니다. `SetupSwiftBridging` 시작 부분에 `if (!enabled) return;`가 있어, 비활성화하면 어떤 파일도 생성되지 않고 어떤 Swift 빌드 속성도 설정되지 않습니다.
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L12-L14)
- **브리징 헤더에서 Objective-C 헤더 노출**: 브리징 헤더 파일은 존재하지 않을 때만 생성되고 이후 덮어쓰이지 않습니다(`File.Exists` 판단). 생성된 `Unity-iPhone-Bridging-Header.h`에 직접 `#import`를 추가해도 되며, 반복 빌드 시에도 수정 사항이 유실되지 않습니다.
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L27-L35)
- **다중 모듈 협업**: 여러 `XCodeConfig.json`은 깊은 재귀 방식으로 병합되며, 최종적으로 병합된 `swiftBridging` 값이 적용됩니다. 어느 설정에도 명시하지 않으면 기본값은 `true`입니다.
  Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L100)

## 일반적인 오류

- **Xcode에서 Swift 파일이 보이지 않음 / `SWIFT_OBJC_BRIDGING_HEADER`가 비어 있음**: 대부분 설정 병합 후 `swiftBridging`이 특정 `XCodeConfig.json`에서 명시적으로 `false`로 설정된 경우입니다. 병합에 참여하는 모든 설정 파일을 확인하세요.
- **브리징 헤더 파일 내용을 수정했는데 다시 "사라진" 경우**: Xcode 프로젝트 디렉터리가 다시 생성되었는지 확인하세요(Unity 덮어쓰기 내보내기는 디렉터리를 재생성합니다). 브리징 헤더는 파일이 존재하지 않을 때만 작성되므로, 커스텀 `#import`는 덮어쓰이지 않는 안정적인 위치에 두거나 직접 작성한 스크립트로 주입하는 것을 권장합니다.
- **Swift 구문 오류 / 버전 불일치**: 이 패키지는 `SWIFT_VERSION = 5.0`을 고정하여 기록합니다. 프로젝트에서 수동으로 이전 버전 값으로 되돌리지 마세요. 반복 빌드 시 다시 5.0으로 덮어써집니다.
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L40-L43)

## 배경

이 기능은 **Unity-iPhone(메인) target과 UnityFramework target**에만 작용합니다: Swift 파일은 UnityFramework target 컴파일에 추가되며, `SWIFT_OBJC_BRIDGING_HEADER`는 메인 target에만 설정됩니다. Xcode에서 Swift 파일을 수동으로 새로 만들 때 표시되는 "브리징 헤더를 생성하시겠습니까?" 대화상자와 달리, 이 흐름은 전적으로 후처리 스크립트로 완료되므로 CI 환경에서 무인 빌드도 팝업에 의해 차단되지 않습니다.
