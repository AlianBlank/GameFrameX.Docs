# 変数とバインダブルプロパティを使ったデータ駆動

GameFrameX では、`Variable<T>` は参照カウント付きの強型データコンテナ(サブシステム間で弱型の値を渡すために使用)、`BindableProperty<T>` は値変更コールバック付きのリアクティブプロパティ(UI とロジックのデータバインディングに使用)です。このページでは、データ駆動シナリオにおける両者の典型的な使い方を示します。

## 前提条件

- `GameFrameX.Runtime` 名前空間が導入済みであること。
- GameFrameX の参照プール / `IReference` の概念を理解していること(`Variable<T>` のみ必要)。

## 操作手順

### 1. `Variable<T>` を使ってモジュール間データを保持する

`Variable<T>` を継承して具体的な型を実装すれば、イベントやパラメータテーブルで弱型の `object` として渡し、インスタンスを取得した時点で強型として値を取り出せます。

```csharp
using GameFrameX.Runtime;

public class IntVariable : Variable<int>
{
    public IntVariable() { }
    public IntVariable(int value) { SetValue(value); }
}
```

使用方法:

```csharp
var v = ReferencePool.Acquire<IntVariable>();
v.SetValue(42);
int actual = v.Value;                // 強型で値を取得
object boxed = v.GetValue();         // 弱型にボックス化(イベント引数用)
ReferencePool.Release(v);            // 参照プールに返却、Clear() が呼ばれる
```

設定する型が一致しない場合、`SetValue(object)` は `GameFrameworkException` をスローし、メッセージの原文は次のとおりです:

```
Cannot set value of type '{0}' to variable of type '{1}'.
```

> 参照プールと `IReference` の全体的なワークフローについては、《IReference と参照プール》を参照してください。

### 2. `BindableProperty<T>` を使って値変更通知を行う

`BindableProperty<T>` は代入時に新旧の値が等しくない場合、登録済みのコールバックを自動的に呼び出します。UI の更新駆動によく使われます。

```csharp
using System;
using GameFrameX.Runtime;

public sealed class PlayerStats
{
    public readonly BindableProperty<int> Hp = new BindableProperty<int>(100);
    public readonly BindableProperty<string> Name = new BindableProperty<string>("Hero");
}
```

購読と購読解除:

```csharp
var stats = new PlayerStats();

Action<int> onHp = newHp => Debug.Log($"HP -> {newHp}");
stats.Hp.Add(onHp);                       // コールバックを登録
stats.Hp.Value = 80;                       // コールバックを発火、ログに "HP -> 80" を出力
stats.Hp.Value = 80;                       // 等しい値は発火しない
stats.Hp.Remove(onHp);                     // コールバックを削除
stats.Hp.Clear();                          // すべてのコールバックをクリア
```

### 3. 直近の値をすぐに取得したい場合は `RegisterWithInitValue` を使う

購読時にコールバックを即座に 1 回呼び出したい場合(現在の値を渡す)、`RegisterWithInitValue` を使用します:

```csharp
stats.Hp.RegisterWithInitValue(newHp => UpdateHpBar(newHp));
```

## よくあるバリエーション

| シナリオ | 選択 | キー API |
|------|------|----------|
| イベント / タスクの弱型パラメータ | `Variable<T>` のサブクラス | `SetValue(object)` / `GetValue()` |
| UI バインディング / 複数オブザーバーの同期 | `BindableProperty<T>` | `Add` / `Remove` / `RegisterWithInitValue` |
| 重複発火を防ぎたい | `BindableProperty<T>` | 内部で `Equals` 比較済み、同値は発火しない |
| 変数をプール化して再利用したい | `Variable<T>` | `ReferencePool.Acquire / Release` |

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `Cannot set value of type 'X' to variable of type 'Y'.` | `Variable<T>` の `SetValue(object)` に `T` 以外の型を渡した | 呼び出し側で型変換を行うか、一致するサブクラスに変更する |
| 代入後にコールバックが実行されない | 新旧の値が等しいため、`BindableProperty` 内部の `Equals` 比較でスキップされる | これは想定動作です。強制通知が必要な場合は、`Equals` が false を返す新しいインスタンスを使用してください |
| `Add(null)` が例外をスローする | `BindableProperty.Add` が `GameFrameworkGuard.NotNull` で検証している | 具体的な `Action<T>` メソッドまたはラムダを渡す |
| 参照プール返却後もコールバックが発火する | `Variable<T>` はプール回収済みだが外部が依然として参照を保持している | 保持側の `Clear()` または解放時に参照を同時にクリアする |## 背景(任意)

- `Variable` は `IReference` を実装しており、`ReferencePool` による取得 / 解放をサポートします。`Clear()` は値を `default(T)` にリセットし、イベントやタスク引数のような「使い捨て」シナリオでの GC 削減に適しています。
- `BindableProperty<T>` は内部で `Equals` を使って新旧値を比較し、実際に変化した場合のみコールバックします。`Add` はチェーンして自身を返すことが可能で、`Remove` は正しく解除するために同じデリゲート参照を渡す必要があります。
