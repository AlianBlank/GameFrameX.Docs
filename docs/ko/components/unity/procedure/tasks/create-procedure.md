# 如何编写一个流程

本章讲解如何编写一个自定义的 Procedure(流程),并接入 `ProcedureComponent` 让框架在启动后自动进入该流程。每个 Procedure 继承自 `ProcedureBase`,并通过有限状态机(FSM)由 `ProcedureManager` 调度运行。

## 前置条件

- 已安装 `com.gameframex.unity.procedure` 包,场景中存在 `ProcedureComponent`(挂载在 `GameFramework` 启动对象上,带 `[GameFrameXAutoComponent(-1000)]` 自动注册)。
- 已引入 `GameFrameX.Procedure.Runtime` 与 `GameFrameX.Fsm.Runtime` 命名空间。
- 至少有一个继承 `ProcedureBase` 的具体类型;框架通过 `Activator.CreateInstance` 反射创建实例,因此流程类必须有无参(或可省略)构造函数。

## 操作步骤

### 1. 创建流程类并继承 ProcedureBase

`ProcedureBase` 本身继承自 `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`,暴露 `OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy` 六个生命周期回调,默认实现均为空,可按需重写。

Source: [ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L30-L98)

最小可用示例(参考单元测试中的真实用法):

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

internal class ProcedurePreload : ProcedureBase { }

internal class ProcedureLogin : ProcedureBase { }

internal class ProcedureMain : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // 初始化资源、配置、热更新等
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 进入主场景逻辑
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // 释放资源
    }
}
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L13-L40)

### 2. 在 Inspector 中注册流程

选中场景中挂载 `ProcedureComponent` 的对象,在 Inspector 中:

- `Available Procedure Type Names`:填入所有可用的流程类型全名(包括命名空间),例如 `GameFrameX.Procedure.ProcedurePreload`、`GameFrameX.Procedure.ProcedureLogin`、`GameFrameX.Procedure.ProcedureMain`。
- `Entrance Procedure Type Name`:填入启动入口流程的类型全名,必须与上面数组中的某一项完全一致,否则 `Start()` 协程会因 `m_EntranceProcedure == null` 直接返回并打印 `Entrance procedure is invalid.`。

`ProcedureComponent.Start()` 会按上述配置反射创建流程实例,并调用 `ProcedureManager.Initialize(...)` 与 `StartProcedure(...)`。

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L51-L169)

### 3. 在流程内切换到下一个流程

每个流程内可通过 `procedureOwner` 拿到所属的 `IProcedureManager`,然后调用 `procedureOwner.StartProcedure<T>()`(或 `StartProcedure(typeof(T))`)切到下一个状态。例如,在 `ProcedureLogin` 登录完成后跳到 `ProcedureMain`:

```csharp
protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
{
    base.OnEnter(procedureOwner);
    // ...登录成功逻辑...
    procedureOwner.StartProcedure<ProcedureMain>();
}
```

也可以通过组件访问:

```csharp
GameEntry.GetComponent<ProcedureComponent>().StartProcedure(typeof(ProcedureMain));
```

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L202-L240)

### 4. 通过 StartupRunner 接管启动流程(可选)

如果项目使用了 `ApplicationStartupEntry` + `StartupRunner.Run` 的新启动方式,需要把 `ProcedureComponent` 上的 `Use Startup Runner` 勾选为 `true`,此时 `ProcedureComponent` 仅在 `Awake` 中注册 `IProcedureManager`,不再调用 `Initialize` 与 `StartProcedure`,由 StartupRunner 负责装配流程并启动入口流程,避免重复 `Initialize` 报 `Already exist FSM`。

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L55-L127)

## 常见变体

| 场景 | 做法 |
|------|------|
| 不使用组件,只通过 `ProcedureManager` API | `new ProcedureManager().Initialize(fsmManager, procs)` 后调用 `StartProcedure<T>()` |
| 需要轮询(`OnUpdate`) | 在对应流程类中重写 `OnUpdate(IFsm<IProcedureManager>, float, float)`,框架每帧轮询 |
| 需要固定间隔轮询 | 重写 `OnFixedUpdate(IFsm<IProcedureManager>, float, float)` |
| 退出流程前清理 | 重写 `OnLeave(IFsm<IProcedureManager>, bool isShutdown)`,根据 `isShutdown` 区分正常切换与关闭状态机 |
| 检查/获取已注册的流程实例 | 使用 `HasProcedure<T>()` / `GetProcedure<T>()` |

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L41-L273)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `You must initialize procedure first.` | 在调用 `Initialize` 前就访问了 `CurrentProcedure` / `StartProcedure` / `HasProcedure` / `GetProcedure` | 先调用 `ProcedureManager.Initialize(fsmManager, procedures)`,再访问上述 API |
| `ArgumentNullException`(参数为 `fsmManager`) | `Initialize` 传入 `null` | 传入有效的 `IFsmManager`(例如 `GameFrameworkEntry.GetModule<IFsmManager>()`) |
| `Procedures is invalid.` | `procedures` 数组为空 | 至少传入一个流程实例 |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` 与 `Available Procedure Type Names` 中的任何一项都不匹配 | 确保入口类型全名严格等于数组中的某一项 |
| `Can not find procedure type '{0}'.` | 类型全名拼写错误,或对应程序集未加载 | 检查命名空间与程序集引用 |
| `Already exist FSM` | 同时启用了 `ProcedureComponent` 与 `StartupRunner` 两条启动流程 | 把 `ProcedureComponent` 的 `Use Startup Runner` 设为 `true`,或不要让 StartupRunner 再 `Initialize` |

## 背景(可选)

`ProcedureBase` 是 `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>` 的薄封装,`ProcedureManager` 内部以 `IFsm<IProcedureManager>` 形式持有这些状态。`ProcedureComponent` 默认在 `Start()` 协程中反射创建流程实例、调用 `Initialize`,然后跳到入口流程;当 `Use Startup Runner` 为 `true` 时改为只注册 `IProcedureManager`,由 `ApplicationStartupEntry` 接管初始化与启动,适用于热更新与资源分包场景。
