# 整合 CocoaPods 相依性

在 Unity 匯出 iOS 專案後，本套件會依據 JSON 設定自動產生（或複製）Podfile、注入 `pod` 相依性，並在建置輸出目錄直接執行 `pod install`，全程無需手動開啟終端機。宣告相依性有兩種方式：在 `unityMain` / `unityFramework` 內撰寫 `pods` 欄位（建議，逐條注入），或以 `podfile` 指定一份完整 Podfile 檔案（設定後忽略 `pods`）。

## 前置條件

- 建置機器為 macOS 且已安裝 CocoaPods：`sudo gem install cocoapods`。未安裝時會在日誌中看到 `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)`。
- 專案已引入本套件，並準備好 Xcode 設定 JSON（範本與範例隨套件提供：`Editor/XCodeConfigTemplate.json`、`Editor/XCodeConfigDemo.json`）。

## 操作步驟

1. 在設定 JSON 的 `unityMain`（主專案 target）或 `unityFramework`（UnityFramework target）區塊內新增 `pods` 欄位。`key` 為 pod 名稱，`value` 為版本限制，空字串表示不限制：

   ```json
   "podSource": [
       "https://mirrors.tuna.tsinghua.edu.cn/git/CocoaPods/Specs.git"
   ],
   "podfile": "",
   "podInstall": true,
   ```

   頂層欄位如上（Demo 中的實際取值）；`pods` 則寫在目標區塊內部，Demo 範例值如下：

   ```json
   "pods": {
       "Ads-CN-Beta": ", :subspecs => ['CSJMediation']"
   }
   ```

2. （可選）設定 `podSource` 使用國內鏡像源加速 `pod install`；未設定時自動產生的 Podfile 會寫入預設來源 `https://github.com/CocoaPods/Specs.git`。

3. 觸發 iOS 建置。建置後處理會按以下順序套用 CocoaPods 設定：

   - `CopyPodfile`：若已設定 `podfile` 路徑，直接將該檔案複製到建置輸出目錄，之後僅重寫其中的 `source` 行；
   - 否則採注入路徑：`EnsurePodfileExists` 先確保 Podfile 存在（不存在則依目前 `PlayerSettings.iOS.targetOSVersionString` 產生骨架，為空時回退 `12.0`），再由 `AddPodsForTarget` 分別向 `Unity-iPhone` 和 `UnityFramework` 兩個 target 注入 `pod` 行（自動略過已存在的同名 pod）；
   - 最後 `RunPodInstall` 在建置輸出目錄執行 `pod install`（可用 `"podInstall": false` 略過）。

   ```csharp
   // PodFile
   var podSourceList = finalConfig.Get("podSource") as ArrayList;
   string podfileConfigPath = finalConfig.Get("podfile") as string;
   bool podfileCopied = CopyPodfile(path, podfileConfigPath);

   if (podfileCopied)
   {
       // 新路徑：已複製完整 Podfile，僅需重寫 source URL
       RunPodfile(path, podSourceList);
   }
   else
   {
       // 舊路徑（向下相容）：從 JSON 設定的 pods 欄位逐行注入
       var mainPods = finalConfig.Get<Hashtable>("unityMain")?.Get<Hashtable>("pods");
       var frameworkPods = finalConfig.Get<Hashtable>("unityFramework")?.Get<Hashtable>("pods");
       if ((mainPods != null && mainPods.Count > 0) || (frameworkPods != null && frameworkPods.Count > 0))
       {
           EnsurePodfileExists(path, podSourceList);
           AddPodsForTarget(path, "Unity-iPhone", mainPods);
           AddPodsForTarget(path, "UnityFramework", frameworkPods);
       }
   }
   ```

4. 驗證結果：查看 Unity Console 中的 `[Pods]` 與 `[PodInstall]` 前綴日誌（如 `[Pods] 已为 Unity-iPhone 添加 N 个 pod 依赖`、`[PodInstall] pod install 完成`），並確認建置輸出目錄下產生了 `Podfile` 與 `Pods` 目錄、`.xcworkspace` 可正常開啟。

## 設定項目速查

| 設定項目 | 型別 / 預設值 | 說明 |
|------|------|------|
| `podSource` | `string[]` / 未設定時使用 `https://github.com/CocoaPods/Specs.git` | 寫入 Podfile 頂部的 `source` 來源列表，可填國內鏡像 |
| `podfile` | `string` / `""` | 完整 Podfile 檔案路徑，支援相對路徑（基於 Unity 專案根目錄，即 Assets 的上一層）與絕對路徑；設定後忽略 `pods` |
| `podInstall` | `bool` / `true` | 是否在建置後自動執行 `pod install`，設為 `false` 可略過 |
| `unityMain.pods` / `unityFramework.pods` | `object` / `{}` | key 為 pod 名稱，value 為版本限制；空字串表示無限制 |

## 版本限制寫法

`pods` 的 value 按以下規則組合成 Podfile 中的 `pod` 行：

```csharp
// 產生 pod 行
foreach (DictionaryEntry kv in pods)
{
    var podName = kv.Key.ToString().Trim();
    if (existingPods.Contains(podName)) continue;

    var version = kv.Value?.ToString()?.Trim();
    if (string.IsNullOrEmpty(version))
    {
        podLines.Add($"  pod '{podName}'");
    }
    else if (version.Contains("=>") || version.StartsWith(":"))
    {
        podLines.Add($"  pod '{podName}', {version}");
    }
    else
    {
        podLines.Add($"  pod '{podName}', '{version}'");
    }
}
```

對應關係：`""` → `pod 'Name'`；含 `=>` 或以 `:` 開頭（如 `:subspecs => [...]`、`:git => '...'`）→ 原樣接在逗號後不加引號；其餘（如 `~> 1.0`）→ 自動補上單引號變為 `pod 'Name', '~> 1.0'`。

## 常見變體

- **使用完整 Podfile**：相依性複雜時，把維護好的 Podfile 放到專案內，設定 `"podfile": "MyPodfile"`（相對 Unity 專案根目錄）或絕對路徑。複製成功後僅會重寫其中的 `source` 行，其餘內容原樣保留；檔案不存在時日誌會給出 `[Pods] 配置指定的 Podfile 不存在: {src}` 並回退到 `pods` 注入路徑。
- **略過自動 pod install**：CI 需要自行控制安裝時機時設定 `"podInstall": false`，建置後處理只產生/注入 Podfile，由管線後續步驟執行 `pod install`。
- **私有來源 / 多來源**：`podSource` 是陣列，可同時寫入多個 `source` 行，例如同時保留官方 Specs 與私有儲存庫。

## 常見錯誤

| 現象（日誌原文） | 原因 | 修復 |
|------|------|------|
| `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)` | 建置機器未安裝 CocoaPods，或 pod 不在常見路徑（`.gem/ruby/bin`、Homebrew、`/usr/local/bin`、`/usr/bin`）且 `which pod` 解析失敗 | 安裝 CocoaPods；或將 pod 軟連結到 `/usr/local/bin/pod` 等可被偵測的路徑 |
| `[Pods] 配置指定的 Podfile 不存在: {src}` | `podfile` 路徑寫錯或檔案被移動 | 改為正確路徑；相對路徑基於 Unity 專案根目錄（Assets 上一層） |
| `[Pods] 未找到 target '{targetName}' do, 跳过设置` | 自訂 Podfile 中 target 行格式不符（必須形如 `target 'Unity-iPhone' do`） | 修正 target 行寫法，或直接使用 `pods` 注入方式 |
| `[PodInstall] pod install 失败 (退出码: {code}): {error}` | pod 版本限制衝突、來源無法連線、Gem/Ruby 環境問題等 | 依 error 輸出排查；可先使用鏡像源，必要時設定 `"podInstall": false` 手動執行 `pod install` 重現問題 |
| `当前不是Pod 项目结构,跳过设置` | 建置輸出目錄缺少 `Podfile` | 使用 `pods` 注入方式讓其自動建立，或提供 `podfile` 設定 |

## 驗證

- Unity Console 中依次出現 `修改PodFile 文件的源, 开始/结束`、`[Pods] ...`、`[PodInstall] 开始执行 pod install...` 與 `[PodInstall] pod install 完成`。
- 建置輸出目錄存在 `Podfile`（內容含設定的 `source` 行與各 target 的 `pod` 行）、`Pods/` 目錄及 `Podfile.lock`。
- 開啟產生的 `.xcworkspace`（而非 `.xcodeproj`），相依函式庫出現在 Pods 專案中且能順利編譯。

## 背景

CocoaPods 相關邏輯集中在建置後處理的第二階段，實作於 `PostProcessBuildHelper` 的部分類別檔案中：[PostProcessBuildHelper.PodFile.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.PodFile.cs#L19) 提供 `RunPodfile`（重寫 source 行）、`EnsurePodfileExists`（產生骨架）、`CopyPodfile`（複製自訂 Podfile）、`AddPodsForTarget`（依 target 注入並去重）、`RunPodInstall` 與 `GetPodFullPath`；主流程在 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156) 中串接。執行 `pod install` 時會明確設定 `LANG` / `LC_ALL` 為 `en_US.UTF-8`（CocoaPods 對編碼有要求），並解析 pod 的絕對路徑（Unity 子程序不繼承 shell PATH），這是常見「終端機可用但建置時找不到 pod」問題的根本原因。關於 iOS 建置後處理的整體流程，請參閱《iOS 建置後處理》。
