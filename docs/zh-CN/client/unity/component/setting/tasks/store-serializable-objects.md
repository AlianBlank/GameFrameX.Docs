# 存取可序列化对象配置

使用 `SettingComponent` 的 `GetObject<T>` 与 `SetObject<T>` 接口,将任意 `[Serializable]` 标记的对象以单一字符串键读写到游戏配置存储中。

## 前置条件

- 项目中已挂载 `GameFrameXSettingCroppingHelper` 与 `SettingComponent`(后者通过 `[RequireComponent]` 自动要求前者)。
- 待存储的类型必须标记 `[System.Serializable]`,字段会被 `UnityEngine.JsonUtility` 序列化。
- 通过 `GameFrameworkEntry.GetModule<ISettingManager>()` 获取管理器实例,或在 `SettingComponent.Awake()` 完成后再调用存储 API。

## 操作步骤

1. **定义可序列化的配置类**。类型必须用 `[Serializable]` 标注,字段需为 `public` 或带 `[SerializeField]`:

   ```csharp
   using System;
   using UnityEngine;

   [Serializable]
   public class PlayerProfile
   {
       public string playerId;
       public int level;
       public bool vip;
       public Vector3 lastPosition;
   }
   ```

2. **获取配置管理器**。组件初始化完成后,直接通过组件实例访问:

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingComponent = UnityEngine.Object.FindObjectOfType<SettingComponent>();
   ISettingManager settingManager = settingComponent.GetComponent<SettingComponent>() != null
       ? GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>()
       : null;
   ```

   也可以缓存组件的引用,在需要时直接读取 `settingComponent` 上的 `ISettingManager` 模块。

3. **写入对象**。调用 `SetObject<T>(string settingName, T value)`,框架内部用 `JsonUtility.ToJson` 转为字符串后写入底层存储:

   ```csharp
   var profile = new PlayerProfile
   {
       playerId = "p-1001",
       level = 12,
       vip = true,
       lastPosition = new Vector3(1.5f, 0f, -3.2f),
   };

   settingManager.SetObject("profile.current", profile);
   settingManager.Save();
   ```

   Source: [SettingManager.cs#L300-L320](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L300-L320)

4. **读取对象**。通过 `GetObject<T>(string settingName)` 取回,若键不存在则返回 `null`(带默认值的重载 `GetObject<T>(string settingName, T defaultValue)` 在缺失时返回默认值):

   ```csharp
   if (settingManager.HasSetting("profile.current"))
   {
       PlayerProfile loaded = settingManager.GetObject<PlayerProfile>("profile.current");
       Debug.Log($"欢迎回来,{loaded.playerId},等级 {loaded.level}");
   }
   ```

5. **删除与清空**。对象与基础类型共用同一存储:

   ```csharp
   settingManager.RemoveSetting("profile.current");  // 移除单个键
   settingManager.RemoveAllSettings();                // 清空全部
   ```

## 常见变体

| 场景 | 用法 | 说明 |
|------|------|------|
| 缺省值兜底 | `GetObject<PlayerProfile>("profile.current", defaultProfile)` | 键不存在时返回传入的默认值对象 |
| 列举所有键 | `string[] keys = settingManager.GetAllSettingNames();` | 调试时快速定位已存储的对象名 |
| 跨小游戏平台 | 使用 `WeChatMiniGameSettingStorage` 等平台实现 | 通过 `SettingStorageBackendFactory` 切换底层,API 保持一致 |
| 复杂嵌套 | `[Serializable] class Wrapper { public PlayerProfile profile; public Settings settings; }` | `JsonUtility` 支持嵌套 `[Serializable]` 类型,但不支持字典/接口 |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | 在 `SettingComponent.Awake()` 之前调用了 `GetObject`/`SetObject` | 等待组件初始化完成,或把读写逻辑放到业务模块的 `Start`/`Awake` 阶段 |
| `GameFrameworkException: Setting name is invalid.` | 传入的 `settingName` 为 `null` 或空串 | 在调用前做 `string.IsNullOrEmpty` 校验 |
| 读出的字段全部为默认值 | 字段声明为 `private` 且未加 `[SerializeField]` | 给字段加 `[SerializeField]`,或改为 `public` |
| 字典/接口成员被吞掉 | `JsonUtility` 不支持 `Dictionary`、接口、属性 | 改用 `List<T>` 或自定义可序列化包装类 |
| 修改未落盘 | 写入后忘记调用 `Save()` | 在写入完成后调用 `settingManager.Save()`;框架在 `Shutdown` 时会自动 `Save` |

## 背景(可选)

`SettingManager` 把对象与基础类型统一映射到底层 `ISettingHelper`,后者把字符串通过 `JsonUtility.ToJson` 序列化、再委托给 `ISettingStorageBackend`(默认 `UnityPlayerPrefsSettingStorage`)持久化。读取时反向用 `JsonUtility.FromJson<T>` 还原,因此只有能被 `JsonUtility` 处理的对象才能被存取。关于底层存储后端的切换,见《自定义设置存储后端》。
