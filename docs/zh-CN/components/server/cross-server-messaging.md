# 如何实现跨服 RPC 调用与统一消息发送

通过框架提供的 `IUnifiedMessageSender` 接口,可以在业务层一行代码完成"本服直发/跨服转发/离线处理"的玩家消息投递,以及"服务发现+一致性选路+超时重试"的跨服 RPC 调用,无需感知底层协议。

## 前置条件

- 已引入 `GameFrameX.NetWork.RemoteMessaging` 程序集,并在启动阶段调用 `UnifiedMessageSenderHolder.Initialize(...)` 初始化发送器。
- 目标玩家已通过 SessionManager/路由解析器建立路由(`IPlayerRouteResolver`)。
- 消息对象继承自 `MessageObject`(请求-响应 RPC 的响应还需实现 `IResponseMessage`)。

## 操作步骤

### 1. 在启动期初始化统一发送器

业务层通过全局访问点 `UnifiedMessageSenderHolder.Sender` 拿到 `IUnifiedMessageSender` 实例。框架在 `AppStartUpHotfixGameByEntry` 中已经给出了默认装配示例。

```csharp
// 框架默认装配:仅依赖 SessionManager 的内存态路由
var remoteClient = RemoteMessagingBuilder.BuildFromEnvironment();
UnifiedMessageSenderHolder.InitializeWithDefaults(
    new DefaultPlayerRouteResolver(),
    remoteClient);
```

如果你使用自定义组件(例如替换路由解析器或服务实例选择器),也可以手动构造并通过 `Initialize(IUnifiedMessageSender)` 注入。

### 2. 发送消息给目标玩家

`SendToPlayerAsync` 会自动按"本服在线 → 本服投递 → 路由解析 → 跨服转发 → 离线处理"的顺序处理,业务层只关心返回结果。

```csharp
var sender = UnifiedMessageSenderHolder.Sender;

var msg = new NotifyFriendOnline
{
    FriendId = 10001,
    OnlineServerId = 3,
};

var result = await sender.SendToPlayerAsync(
    playerId: 10001,
    message: msg,
    options: new PlayerSendOptions
    {
        OfflineStrategy = PlayerOfflineStrategy.StoreOffline,
        TimeoutMs = 3000,
        AllowRetry = true,
        MaxRetryCount = 2,
    });

if (result.Status == PlayerDeliverStatus.RemoteDelivered)
{
    // 已通过跨服转发投递到目标服
}
```

`PlayerSendResult` 的 `Status` 字段覆盖所有可能的投递状态(`LocalDelivered` / `RemoteDelivered` / `OfflineStored` / `Offline` / `RouteMissing` / `Cancelled` / `Failed`),用枚举判断即可。

### 3. 发起跨服 RPC(请求-响应)

调用 `SendToServerAsync<TResp>` 时,内部会自动做服务发现、实例选择与一致性路由,并把结果以 `ServerSendResult<TResp>` 返回。

```csharp
var req = new ReqQueryGuildMembers
{
    GuildId = 42,
    PageIndex = 1,
};

ServerSendResult<RespQueryGuildMembers> rpc =
    await sender.SendToServerAsync<RespQueryGuildMembers>(
        serviceName: GameServerConst.Guild.Name,
        message: req,
        options: new ServerSendOptions
        {
            TimeoutMs = 5000,
            AllowRetry = true,
            MaxRetryCount = 1,
        });

if (rpc.IsSuccess)
{
    // rpc.Response 即 RespQueryGuildMembers
    foreach (var member in rpc.Response.Members) { /* ... */ }
}
else
{
    // rpc.StatusCode: EndpointNotFound / Timeout / Failed ...
}
```

底层使用的"跨服玩家转发"内部协议定义在 `ReqSendToPlayerInner` / `RespSendToPlayerInner`,转发时会附带 `TargetPlayerId` 与原始 `InnerMessage`。

### 4. 单向跨服通知(不等待响应)

不需要回包时,使用 `SendToServerOneWayAsync`:

```csharp
await sender.SendToServerOneWayAsync(
    serviceName: GameServerConst.Chat.Name,
    message: new NotifyServerKickPlayer { PlayerId = 10001 });
```

返回的 `ServerSendResult.IsSuccess` 表示"是否成功将消息送入发送通道",并不保证对端已处理。

## 常见变体

- **同一玩家可能落在不同服**:直接调用 `SendToPlayerAsync` 即可,不需要业务层手动查询路由。
- **要求"先到先得"的全局广播**:用 `SendToServerOneWayAsync` 发送到目标服务名,由服务侧多实例各自处理。
- **跨服转发失败但已知玩家离线**:在 `PlayerSendOptions.OfflineStrategy` 上选 `StoreOffline`(暂存离线消息)或 `Discard`(丢弃);默认按 `Offline` 返回失败。
- **需要对结果埋点/打点**:发送器持有 `MessageSendMetrics`,可从 `UnifiedMessageSenderHolder.Metrics` 取到聚合指标。

## 常见错误

| 现象 | 原因 | 规避 |
|------|------|------|
| `UnifiedMessageSenderHolder has not been initialized. Call Initialize() first during startup.` | 启动期未调用 `Initialize` | 在 `AppStartUp` 或服务入口处先 `InitializeWithDefaults(...)` |
| `Service name is empty` | `SendToServerAsync` 的 `serviceName` 传空串 | 使用 `GameServerConst.*.Name` 常量,不要手写字符串 |
| 状态为 `RouteMissing` | `IPlayerRouteResolver` 未找到该玩家的路由 | 检查 SessionManager/登录流程是否完成注册 |
| 状态为 `RemoteDelivered` 但对端未处理 | 对端未注册对应消息的 Handler | 确认消息类型已通过源码生成器注册,详见后台诊断页 |
| `Cross-server forwarding failed: ...` | 跨服转发抛异常(网络/超时) | 设置 `TimeoutMs` 与 `MaxRetryCount`,或在调用方 `try/catch` 兜底 |

## 背景(可选)

`UnifiedMessageSender` 把"本服 Session 投递"、"玩家路由解析"、"跨服 RPC 客户端"、"服务实例选择器"四件事聚合在一个接口背后;业务层只需要选择目标(`playerId` 或 `serviceName`)与策略(`OfflineStrategy` / `TimeoutMs` / `Retry`),路由与转发的细节由框架承担。
