# How to Set a Default Handler for Unhandled Events

After calling `EventComponent.SetDefaultHandler` to register an `EventHandler<GameEventArgs>` callback, any event fired via `Fire` / `FireNow` that has no subscribers will fall into this callback instead of being silently discarded — commonly used for logging, alerting, or tallying missed events.

## Prerequisites

- A GameObject with the `EventComponent` component attached already exists in the scene (the event feature is enabled).
- You are familiar with the basic event subscription/firing usage.

## Steps

1. Write a callback method with the signature `EventHandler<GameEventArgs>`; reading `e.Id` inside it gives you the event ID:

```csharp
void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L145-L150)

2. During initialization (e.g., in `Start` or the module entry point), call `SetDefaultHandler` to register:

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L144-L145)

3. Fire an event that no one subscribes to, in order to verify:

```csharp
// Shortcut: no custom event arguments required; it internally wraps with EmptyEventArgs.Create(eventId)
eventComponent.Fire(this, "level_up");
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`Fire` is a thread-safe deferred dispatch — even when fired from a worker thread, the callback executes on the main thread in the next frame; if you want the default handler to be invoked immediately, use `FireNow` instead (immediate dispatch, main thread only).

## Common Variants

| Requirement | Approach |
|------|------|
| Replace the default handler | Call `SetDefaultHandler(newHandler)` again to override the old callback |
| Remove the default handler | Call `SetDefaultHandler(null)`; afterwards, events with no subscribers go back to being silently discarded |
| Route events with custom arguments to the fallback | `eventComponent.Fire(this, LevelUpEventArgs.Create(5))`; in the callback, downcast `e` to the specific argument type |
| Track down who fired an event | Log `sender` (the event sender) in the callback and report it together with `e.Id` |

## Common Mistakes

- **Mismatched callback signature**: `SetDefaultHandler` only accepts `EventHandler<GameEventArgs>`; writing it as `Action<string>` or as a handler for a specific argument type will fail to compile. Handle subscribed events in specific handlers first; the default handler uniformly receives `GameEventArgs`.
- **Forgetting that the default handler only catches events with "no subscribers"**: if that `Id` already has any subscribers, the event is dispatched normally to the subscribers and never enters the default handler. Do not use the default handler as a global event listener.
- **Misusing `FireNow` on a worker thread**: `FireNow` dispatches immediately and is not thread-safe; calling it from a background thread leads to undefined behavior. Use `Fire` on background threads.
- **Throwing exceptions inside the default handler**: the callback runs within the main event dispatch flow, and an exception will interrupt dispatch; make sure to catch exceptions properly inside the callback.

## Background

`EventComponent.SetDefaultHandler` is just a thin forwarding layer; internally it calls `m_EventManager.SetDefaultHandler(handler)`, which in turn hands the callback to the underlying event pool (`m_EventPool.SetDefaultHandler`). During dispatch, if an event ID has no matching handler, the event pool calls the default handler instead, thereby providing an "unhandled event fallback".
