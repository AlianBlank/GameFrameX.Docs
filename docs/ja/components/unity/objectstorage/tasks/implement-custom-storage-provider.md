# カスタムオブジェクトストレージプロバイダーの実装方法

`IObjectStorageManager` と `IObjectStorageUploadManager` の 2 つのインターフェースを実装し、`ObjectStorageUploadFactory` に組み込むことで、GameFrameX オブジェクトストレージフレームワークに任意の新バックエンド(自作 MinIO、Huawei OBS、七牛、Upyun、内部ファイルサーバーなど)を追加でき、アップロードフローを内蔵プロバイダーと同様にファクトリで一元的にスケジューリングできます。

## 前提条件

- Unity プロジェクトに `com.gameframex.unity.objectstorage` パッケージがインストール済みであること。
- 連携するバックエンドが、accessKey / secretKey / bucketName / endpoint の 4 つの基本パラメータを持ち、標準的なオブジェクトストレージプロトコル(分片/アップロード/進捗コールバック)に応答できること。
- カスタムプロバイダーの実装を配置するための Editor アセンブリを用意する(任意の `Editor/` ディレクトリ配下の `.asmdef` 内に配置し)、ランタイムを汚染しないようにすること。

## 操作手順

1. **プロバイダー実装クラスを作成し**、`IObjectStorageManager` と `IObjectStorageUploadManager` の 2 つのインターフェースを実装します。`IObjectStorageManager.Init` は資格情報とバケット情報を受け取るために使用し、`IObjectStorageUploadManager` は実際のアップロード、分片、進捗コールバックを担当します。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;

   namespace GameFrameX.ObjectStorage.Editor
   {
       public sealed class MyCustomObjectStorageManager
           : IObjectStorageManager, IObjectStorageUploadManager
       {
           public void Init(string accessKey, string secretKey,
                            string bucketName, string endpoint = null)
           {
               // 内部フィールドに保存し、アップロードメソッドで使用する
           }

           // IObjectStorageUploadManager のアップロードメソッドを実装します...
       }
   }
   ```

   `IObjectStorageManager` インターフェースの定義については [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13) を参照してください。`Init` メソッドのシグネチャは以下のとおりです:

   ```csharp
   void Init(string accessKey, string secretKey, string bucketName, string endpoint = null);
   ```
   Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L12)

2. **アップロードと進捗コールバックのロジックを実装します**。`BaseObjectStorageUploadManager` の責務分割を参考にしてください。基底クラスは共通の分片、リトライ、進捗集計を担当します。サブクラスでは「認証ヘッダーの構築」と「分片 PUT/POST」を独自のバックエンドプロトコルに置き換えるだけで済みます。基底クラスのエントリポイントは [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs) にあります。

3. **ファクトリに登録します**。[ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs) を開き、ファクトリの作成/選択分岐にプロバイダータイプを追加し、設定に応じてファクトリが実装インスタンスを返せるようにします。

4. **呼び出し側でファクトリから取得します**。アップロード側は変更不要で、`ObjectStorageUploadFactory` から `IObjectStorageUploadManager` を取得するだけです:

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create(providerName);
   ((IObjectStorageManager)uploader).Init(accessKey, secretKey, bucketName, endpoint);
   uploader.Upload(localPath, remoteKey, onProgress, onComplete);
   ```

## よくあるバリエーション

- **同じプロトコルで異なるベンダー**:例えば AWS S3、Alibaba OSS、Tencent COS はいずれも S3 プロトコルに互換性があるため、1 つの実装クラスで複数の `endpoint` をサポートでき、`Init` 時に署名リージョンを区別できます。
- **endpoint のない内網ストレージ**:`endpoint` を空のままにし、実装内部で `bucketName` から内網アドレスを組み立てます。
- **複数資格情報のローテーション**:`Init` で資格情報リストの受け渡しを許可し、アップロード時に分片前にトークンを自動更新します。

## よくあるエラー

| エラー | 原因 | 修正方法 |
|------|------|------|
| ファクトリが内蔵プロバイダーを返す | 自分のタイプを `ObjectStorageUploadFactory` に登録していない | ファクトリの選択分岐に新しい provider 名を追加する |
| `Init` 後にアップロードが 401/403 を返す | accessKey/secretKey と endpoint リージョンが一致していない | `Init` 内でリージョンを検証し、実際のリクエストアドレスを出力する |
| 進捗が常に 0 のまま止まる | 実装クラスが分片コールバックを `IObjectStorageUploadManager` の進捗イベントに変換していない | `BaseObjectStorageUploadManager` の進捗集計ポイントを参照する |
| Unity ランタイムで型が見つからない | 実装クラスをランタイムアセンブリではなく Editor アセンブリに配置した | コードを任意の `Editor/` ディレクトリに配置し、`.asmdef` に `Editor` プラットフォームが含まれていることを確認する |

## 背景(オプション)

フレームワークは「資格情報管理」と「アップロード実行」を 2 つのインターフェースに分離しています。`IObjectStorageManager` は資格情報の初期化のみを担当し、`IObjectStorageUploadManager` は実際のネットワーク分片と進捗を担当します。両者は通常同じクラスで実装され、ファクトリは provider 名に応じてインスタンスを選択します。これにより呼び出しエントリが統一されるだけでなく、バックエンドの差し替えも簡単になります。
