# バージョンアップグレードと依存関係の互換性に関する問題

`com.gameframex.unity.download` をアップグレードしたり、上流の依存関係(Unity メインフレームワーク、イベントモジュール)を更新したりする際に、コンパイルエラー、名前空間の欠落、または `Package Manager` の解決失敗などの問題が発生した場合は、このページでトラブルシューティングできます。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `Package Manager` が `An error occurred while resolving packages: Project depends on 'com.gameframex.unity'` を報告する | メインフレームワークの依存関係が欠落している、またはバージョンが `com.gameframex.unity.download` の要件を満たしていない | `manifest.json` 内で [com.gameframex.unity](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L25-L28) を指定のバージョンまで追加またはアップグレードする |
| コンパイル時に `The type or namespace name 'GameFrameX' could not be found` が発生する | `com.gameframex.unity.event` が欠落しているかバージョンが低すぎる | イベントパッケージの依存関係 [com.gameframex.unity.event 1.3.0](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L25-L28) を補完する |
| アップグレード後に `WWWDownloadAgentHelper` 関連のシンボルが見つからない | 1.1.2 より前のバージョンには名前空間/スペルの誤りがあり、旧 API は変更済み | [1.1.2 以降](https://github.com/gameframex/com.gameframex.unity.download/blob/main/CHANGELOG.md#L15-L21) にアップグレードし、修正後の名前空間で参照する |
| `Library/PackageCache` に旧バージョンの残留が発生し、動作が新バージョンと一致しない | Unity が旧バージョンをキャッシュしたままで、クリーンアップされていない | `Library/PackageCache/com.gameframex.unity.download*` を削除し、パッケージを再解決する |
| Unity 2019.4 以下でプロジェクトを開くとパッケージ非互換のエラーが発生する | パッケージが最低 Unity バージョンを 2019.4 と宣言している | Unity Editor を [2019.4 以上](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L7) にアップグレードする |

## 修正手順

### 1. パッケージの依存関係宣言を確認する

`com.gameframex.unity.download` 自身が宣言している依存関係は以下の通りです(バージョンは随時更新されるため、リポジトリの内容を優先してください):

```json
"dependencies": {
  "com.gameframex.unity.event": "1.3.0",
  "com.gameframex.unity": "2.5.1"
}
```

出典: [package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L25-L28)

プロジェクトの `Packages/manifest.json` でこれら 2 つの依存関係が欠落している、バージョンが低すぎる、または別のバージョンが明示的に固定されている場合は、上記のバージョンに合わせた後、Unity に再解決させる必要があります。

### 2. Unity プロジェクトでパッケージをアップグレードする

以下の順序で操作することで、ほとんどのキャッシュ問題を回避できます:

1. Unity Editor を閉じます。
2. `Packages/manifest.json` を編集し、`com.gameframex.unity.download` を目的のバージョン(例:`1.2.1`)に変更します。
3. `Library/PackageCache/com.gameframex.unity.download*`、`Library/PackageCache/com.gameframex.unity*`、`Library/PackageCache/com.gameframex.unity.event*` の 3 つのディレクトリの旧キャッシュを削除します。
4. Unity を再度開き、`Package Manager` に依存関係を再解決させます。

### 3. 1.2.0 のフレームワーク自動登録の変更への対応

1.2.0 以降、モジュールは GameFrameX フレームワークの自動登録メカニズムに対応しました([CHANGELOG 1.2.0](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L8-L13))。1.2.0 以上のバージョンにアップグレードする場合は、メインフレームワーク `com.gameframex.unity` も同時に 2.5.1 以降にアップグレードしてください。そうしない場合、自動登録に必要なエントリタイプが見つからない可能性があります。

### 4. 1.1.2 の名前空間修正への対応

1.1.2 では `WWWDownloadAgentHelper` の名前空間およびスペルの誤りが修正されました([CHANGELOG 1.1.2](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L15-L21))。1.1.1 以前のバージョンからアップグレードする場合、プロジェクト内にこのヘルパークラスの旧名前を参照する `using` やコードがある場合は、新しい名前空間に合わせて調整する必要があります。そうしないとコンパイルに失敗します。

### 5. 1.1.1 の依存関係補完への対応

1.1.1 より前のバージョンでは、`package.json` に重要な依存関係が欠落している可能性があります([CHANGELOG 1.1.1](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L23-L29))。より古いバージョンからアップグレードする場合は、途中で依存関係を手動修正せず、[1.2.1](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L1-L6) に直接アップグレードすることをお勧めします。

### 6. Assembly Definition の変更への対応

本パッケージは 3 つのディレクトリで独立した `.asmdef` メタデータを維持しています:

- [Runtime/GameFrameX.Download.Runtime.asmdef.meta](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/GameFrameX.Download.Runtime.asmdef.meta)
- [Editor/GameFrameX.Download.Editor.asmdef.meta](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Editor/GameFrameX.Download.Editor.asmdef.meta)
- [Tests/GameFrameX.Download.Tests.asmdef.meta](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Tests/GameFrameX.Download.Tests.asmdef.meta)

プロジェクトでカスタム `.asmdef` を使用している場合、アップグレード後に「型が見つからない/アクセスできない」というエラーが発生したら、カスタムアセンブリがこの 3 つのアセンブリを正しく参照しているかを確認するか、カスタム asmdef の `overrideReferences` で依存パッケージのアセンブリを許可してください。

## 検証

1. Unity Editor を開き、`Window > Package Manager` で `com.gameframex.unity.download` が目的のバージョンとして表示され、`Dependencies` 領域に `com.gameframex.unity` と `com.gameframex.unity.event` が解決済みであることを確認します。
2. Console に赤いコンパイルエラー、特に `GameFrameX` 名前空間や `WWWDownloadAgentHelper` に関連するエラーがないことを確認します。
3. プロジェクト起動後にダウンロードのエントリポイント(例:`DownloadManager` の登録フロー)を一度呼び出し、実行時に `MissingMethodException` や `TypeLoadException` が発生しないことを確認します。
4. 手順 3 が失敗した場合は、`Library/PackageCache` に戻り、実際にキャッシュされているバージョン番号が `package.json` と一致しているかを確認してください。
