# プラットフォームチャネルの接続

`PaymentComponent` 上で各プラットフォームの実装タイプ文字列を設定すると、フレームワークは起動時にプラットフォームに応じて対応するチャネルの `PaymentManager`(Google / Apple / WebGL / PC)を自動的にインスタンス化します。ビジネスコードは `IPaymentManager` のみを対象にプログラミングすればよく、独自チャネルを接続するには `BasePaymentManager` を継承し、そのタイプ名を Inspector に入力するだけです。

## 前提条件

- 本決済コアパッケージ(`GameFrameX.Payment.Runtime`)がインストール済みであること。
- シーンに `PaymentComponent` がアタッチ済みであること。`RequireComponent` により `GameFrameXPaymentCroppingHelper` が自動的に付加されます。
- ターゲットプラットフォームのチャネル実装パッケージがインストール済みであること(下記の「チャネルタイプ対応表」を参照。各チャネルの実装は対応する名前空間の独立したパッケージに配置されています)。

## 操作手順

1. シーンのオブジェクトにコンポーネントを追加します。メニューパスは `GameFrameX/Payment` です(`AddComponentMenu` による指定):

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
{
    private IPaymentManager _paymentManager;
    [SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
    [SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
    [SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
    [SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
    [SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

出典:[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L28)

2. ターゲットプラットフォームに対応するチャネル実装パッケージをインストールします(パッケージ名は下表の名前空間と一致します。例えば Google チャネルは `GameFrameX.Payment.Google.Runtime` にあります)。

3. チャネルタイプ名が実際にインストールした実装と一致していることを確認します。独自実装に差し替える場合は、Inspector で対応プラットフォームのタイプ文字列を直接変更します。

4. 起動後、フレームワークはプラットフォームマクロに基づいて実装を自動選択します:

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
```

出典:[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

## 独自チャネルの接続

1. `BasePaymentManager` を継承します(このクラスは `GameFrameworkModule, IPaymentManager` を実装済みで、4つのイベントに対する `Raise*` トリガーメソッドを内蔵しています)。抽象メンバーを実装してください:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    /// <summary>
    /// 購入成功イベント
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;

    /// <summary>
    /// 購入失敗イベント
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;

    /// <summary>
    /// 購入履歴照会結果イベント
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

    /// <summary>
    /// 購入消費結果イベント
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    protected void RaisePurchaseFailed(PaymentEventArgs e)
    {
        OnPurchaseFailed?.Invoke(this, e);
    }

    protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
    {
        OnQueryPurchasesResult?.Invoke(this, e);
    }

    protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
    {
        OnConsumePurchaseResult?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);
}
```

出典:[BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L67)

そのほかの抽象メンバーである `IsReady()`、`SetPredefinedProductIds(List<string>, List<string>)`、`QueryPurchases(PaymentProductType)`、`ConsumePurchase(string)`、`BuyInApp`/`BuySubs`/`Buy`(`[Obsolete("请使用 Buy(PurchaseParams) 替代")]` のマーク付き)および推奨されている `Buy(PurchaseParams)` は、すべてサブクラスで実装する必要があります。完全なシグネチャは [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L69-L137) を参照してください。

2. チャネルが追加の購入パラメータを必要とする場合は、`PurchaseParams` を継承してフィールドを拡張します(ソースコメント:「各チャネルは継承して独自フィールドを拡張可能」):

```csharp
/// <summary>
/// 購入パラメータの基底クラス。各チャネルは継承して独自フィールドを拡張可能
/// </summary>
public abstract class PurchaseParams
{
    /// <summary>製品IDまたはSKU</summary>
    public string ProductId { get; set; }

    /// <summary>注文ID</summary>
    public string OrderId { get; set; }

    /// <summary>製品タイプ</summary>
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

出典:[PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

3. 実装クラスの完全修飾名(名前空間を含む)を `PaymentComponent` の対応プラットフォームの Inspector フィールドに入力し、実行後に `IsReady()` でチャネルが正常に初期化されたかどうかを検証します。

## よくあるバリエーション

- **Android チャネルを独自 SDK に置き換える**:`m_componentAndroidType` フィールドはそのままに、値を実装クラスの完全修飾名(名前空間を含む)に変更して再ビルドするだけでよく、`PaymentComponent` のコードを変更する必要はありません。
- **Mac と iOS で Apple チャネルを共用**:デフォルト設定はすでにそうなっています――`m_componentIOSType` と `m_componentMacType` はどちらも `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` を指しています。
- **エディター/未対応プラットフォーム**:`#else` ブランチに該当した場合、本パッケージ内蔵の `DefaultPaymentManager` がフォールバックとして使用されるため、エディターでビジネスフローを一通り動かすのに便利です。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` が null を返す。多くの場合、チャネル実装クラス名の誤り、または対応するアセンブリが未コンパイル | Inspector のプラットフォームタイプ文字列が実際のクラスの完全名・名前空間と一致しているかを確認し、チャネル実装パッケージがインストール済みであることを確認する |
| `Utility.Assembly.GetType(componentType)` で型が取得できない | 型名がアセンブリ内の完全名と一致しない(スペル/名前空間の誤り) | チャネル実装パッケージ内で `namespace` とクラス名を確認したうえで、`GameFrameX.Payment.Google.Runtime.GooglePaymentManager` のような完全な名前を入力する |
| エディターで購入を呼び出しても反応がない | `#else` ブランチに該当し、`DefaultPaymentManager` のフォールバック実装が使用されている | 実機/ターゲットプラットフォームのビルドに切り替えて検証するか、カスタムチャネル実装を接続する |
| `Log.Warning("Product ID is null or empty.")` / `"Order ID is null or empty."` | 旧バージョンの `BuyInApp`/`BuySubs`/`Buy(productId, ...)` に空の `productId` または `orderId` が渡された | 有効な値を渡すか、推奨されている `Buy(PurchaseParams)` オーバーロードに変更する |

出典:[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93)(Fatal ログの位置);その他の警告メッセージは [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L163-L204) を参照

> 説明:`BuyInApp`、`BuySubs`、`Buy(productId, productType, orderId, ...)` にはいずれも `[Obsolete("请使用 Buy(PurchaseParams) 替代")]` がマークされています。新規に接続する場合は `Buy(PurchaseParams)` を直接使用してください([IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112))。

## 背景

`PaymentComponent` は `Awake` 内でコンパイルマクロに基づいて `componentType` を決定し、`Utility.Assembly.GetType` によるリフレクションで `ImplementationComponentType` を取得して、`IPaymentManager` をインターフェース型として `GameFrameworkEntry` に登録します。その後、`GameFrameworkEntry.GetModule<IPaymentManager>()` によってインスタンスを取得します。これによりビジネス層はインターフェースのみに依存し、チャネル実装は Inspector の文字列を通じて実行時に注入されるため、「一つのビジネスコードで複数プラットフォームのチャネルを切り替える」方式が実現されています。決済コンポーネントの全体アーキテクチャと完全な API については、フレームワーク概要ページと API リファレンスページを参照してください。
