# 如何實作自訂統計 Provider（繼承 BaseGameAnalyticsManager）

繼承 `BaseGameAnalyticsManager` 並實作全部抽象成員，就能得到一個可被 `GameAnalyticsComponent` 自動發現、初始化並轉發所有事件上報的自訂統計 Provider。整個框架沒有內建任何具體 Provider，接入 ThinkingData、友盟或自建埋點服務都需要按本頁方式自行實作。

## 前置條件

- 專案中已安裝 GameFrameX 執行階段（`GameFrameworkModule`、`GameFrameworkComponent` 來自 `GameFrameX.Runtime`）。
- 場景中已有 GameAnalytics 元件（選單 `Game Framework/GameAnalytics`，元件為 `[DisallowMultipleComponent]`）。

## 操作步驟

### 1. 新增類別並繼承 BaseGameAnalyticsManager

`BaseGameAnalyticsManager` 是抽象類別，繼承 `GameFrameworkModule` 並實作 `IGameAnalyticsManager`，已內建共用屬性字典 `m_PublicProperties` 和初始化標記 `m_IsInit`：

```csharp
public abstract class BaseGameAnalyticsManager : GameFrameworkModule, IGameAnalyticsManager
{
    protected bool m_IsInit = false;
    protected readonly Dictionary<string, object> m_PublicProperties = new Dictionary<string, object>();
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L10-L17)

### 2. 實作全部抽象成員

下面這些成員沒有預設實作，子類別必須全部實作（簽章直接來自基底類別）：

| 成員 | 簽章 | 說明 |
|------|------|------|
| `Init` | `public abstract void Init(Dictionary<string, string> args)` | 自動初始化，args 來自 Inspector 中的 Setting 鍵值對 |
| `ManualInit` | `public abstract void ManualInit(Dictionary<string, string> args)` | 手動初始化，僅當 `IsManualInit()` 回傳 `true` 時元件才會呼叫 |
| `IsManualInit` | `public abstract bool IsManualInit()` | 是否採用手動初始化模式 |
| `StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer` | `public abstract void Xxx(string eventName)` | 一組事件計時方法（共四個） |
| `Event` | `public abstract void Event(string eventName)` | 上報事件 |
| `Event` | `public abstract void Event(string eventName, float eventValue)` | 上報帶數值事件 |
| `Event` | `public abstract void Event(string eventName, Dictionary<string, object> customF)` | 上報帶自訂欄位事件 |
| `Event` | `public abstract void Event(string eventName, float eventValue, Dictionary<string, object> customF)` | 上報帶數值與自訂欄位事件 |
| `SetPlayerId` | `public abstract void SetPlayerId(string playerId)` | 設定玩家 ID |

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L31-L202)、[IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L105)

以下骨架僅按基底類別的真實簽章搭建，方法主體由你接入具體 SDK 後填充：

```csharp
using System.Collections.Generic;
using GameFrameX.GameAnalytics.Runtime;

namespace YourGame.Analytics
{
    public class MyAnalyticsProvider : BaseGameAnalyticsManager
    {
        public override void Init(Dictionary<string, string> args)
        {
            // args 中的鍵值來自 GameAnalyticsComponent Inspector 裡的 Setting
            m_IsInit = true;
        }

        public override void ManualInit(Dictionary<string, string> args) { }
        public override bool IsManualInit() { return false; }

        public override void StartTimer(string eventName) { /* 計時開始 */ }
        public override void PauseTimer(string eventName) { }
        public override void ResumeTimer(string eventName) { }
        public override void StopTimer(string eventName) { /* 上報耗時事件 */ }

        public override void Event(string eventName) { /* 轉發到目標 SDK */ }
        public override void Event(string eventName, float eventValue) { }
        public override void Event(string eventName, Dictionary<string, object> customF) { }
        public override void Event(string eventName, float eventValue, Dictionary<string, object> customF) { }

        public override void SetPlayerId(string playerId) { /* 綁定帳號 */ }
    }
}
```

### 3. 在 GameAnalyticsComponent 中註冊 Provider

元件透過反射依型別全名字串建立實例，因此你的類別**必須有無參數建構函式**，並將完整型別名稱（含命名空間）填入 Provider 條目的 `ComponentType`：

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L77)

具體操作：在 Inspector 中展開 `GameAnalyticsComponent` 的 Provider 清單，新增條目：

| 欄位 | 填寫內容 |
|------|----------|
| `ComponentType` | `YourGame.Analytics.MyAnalyticsProvider`（含命名空間的型別全名） |
| `Setting` | 需要傳給 `Init(args)` 的鍵值對，如 `app_id`、`server_url` 等 |

### 4. 透過元件統一呼叫

初始化會在 `OnEnable()` 時自動觸發一次 `Init()`；之後所有上報都走元件層，元件會把呼叫轉發給清單裡的每一個 Provider：

```csharp
// 上報事件（元件層帶參數驗證與未初始化保護）
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

業務程式碼中的典型用法：`GameEntry.GameAnalytics.Event("level_complete")`、`StartTimer("battle")` / `StopTimer("battle")`、`SetPlayerId(userId)`。

## 常見變體

- **手動初始化**：讓 `IsManualInit()` 回傳 `true`，元件的 `ManualInit(Dictionary<string, string> extraArgs)` 就會在合適的時機（例如玩家登入後）把額外參數傳給你的 `ManualInit` 實作；回傳 `false` 時元件會跳過該 Provider 的手動初始化呼叫。
- **多個 Provider 並存**：Provider 清單可設定多項（例如同時接入 ThinkingData + 自建日誌），元件層所有 `Event` / 計時 / `SetPlayerId` 呼叫會循環轉發給每一個已初始化的 Provider。
- **自訂裝置共用屬性**：預設裝置資訊（`device_id`、`os`、`app_version`、`network_type` 等）由 `AddDeviceInfoToPublicProperties()` 寫入；可 `override` 該 `protected virtual` 方法增刪欄位。`SetPublicProperties(key, value)` 可隨時追加自訂共用屬性。

```csharp
protected override void AddDeviceInfoToPublicProperties()
{
    base.AddDeviceInfoToPublicProperties();
    m_PublicProperties["channel"] = "your_channel";
}
```

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| 主控台輸出 `Can not find component type 'xxx'.` | `ComponentType` 填寫的型別全名拼錯或組件未被反射掃描到 | 核對命名空間與型別名稱；確認類別是 `public` 且具有無參數建構函式 |
| 主控台反覆輸出 `GameAnalyticsManager is not init.` | 子類別 `Init(args)` 中忘記把 `m_IsInit` 設為 `true` | 在 `Init` 成功後設定 `m_IsInit = true` |
| 呼叫 `Event` 時擲回參數例外 | 事件名稱為空 | `GameFrameworkGuard.NotNullOrEmpty` 要求事件名稱非空，請傳入有效字串 |
| `ManualInit` 的參數拿不到 | 該 Provider 的 `IsManualInit()` 回傳了 `false` | 回傳 `true` 才會收到元件轉發 |
| `SetPublicProperties(key, value)` 無效 | `key` 為空字串時基底類別直接 `return` | 使用非空 key |

## 背景

`GameAnalyticsComponent` 在 `Awake` 中設定 `IsAutoRegister = false` 並在 `OnEnable` 裡完成一次 `Init()`：它按 `ComponentType` 字串反射建立 `IGameAnalyticsManager` 實例，把 Inspector 中 `Setting` 的鍵值對打包成 `Dictionary<string, string>` 傳給 `Init(args)`，之後以「廣播」方式把所有上報呼叫轉發給全部 Provider。基底類別 `BaseGameAnalyticsManager` 則統一維護 `m_IsInit` 與 `m_PublicProperties`（裝置/系統/網路共用屬性），子類別只需關注各自 SDK 的上報細節。
