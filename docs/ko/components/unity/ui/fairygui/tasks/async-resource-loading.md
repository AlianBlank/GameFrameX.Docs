# 비동기 리소스 로드 방식 전환(YooAsset / Resources)

본 프레임워크에서 FairyGUI UI가 YooAsset 비동기 로드를 사용할지 Resources 동기 로드를 사용할지는 **UI를 열 때 전달되는 리소스 경로에 Bundles 디렉터리 이름이 포함되어 있는지 여부로 자동 결정됩니다**(판단 기준은 `Utility.Asset.Path.BundlesDirectoryName`). 로더 코드를 수정할 필요가 없으며, UI 패키지를 올바른 디렉터리에 배치하고 올바른 `uiFormAssetPath`를 전달하기만 하면 전환이 완료됩니다.

## 사전 조건

- YooAsset 모드: 프로젝트에 GameFrameX의 Asset 컴포넌트가 구성되어 있고(코드에서 `GameEntry.GetComponent<AssetComponent>()`로 획득), UI 패키지 산출물이 Bundles 디렉터리 아래에 위치합니다.
- Resources 모드: UI 패키지를 `Resources` 디렉터리에 직접 배치합니다.
- FairyGUI 런타임 라이브러리가 이미 임포트되어 있습니다(`using FairyGUI;`).

## 작업 단계

1. **UI 패키지 저장 위치 확인**:
   - YooAsset 비동기 로드 사용: 패키지를 Bundles 디렉터리에 배치(경로에 `Utility.Asset.Path.BundlesDirectoryName` 포함).
   - Resources 동기 로드 사용: 패키지를 `Resources` 디렉터리에 배치하며, 경로에 Bundles 디렉터리 이름이 포함되지 않습니다.

2. **UI 열기 API를 호출하고 해당 경로를 전달합니다**. 프레임워크는 `UIManager.InnerLoadUIFormAsync`에서 경로에 따라 자동으로 분기하며, 판단 로직은 다음과 같습니다:

```csharp
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);

var lastIndexOfStart = uiFormAssetPath.LastIndexOf("/", StringComparison.OrdinalIgnoreCase);
// 경로에 /가 없으면 전체 경로가 패키지 이름이 됩니다(Resources 디렉터리의 간단한 경로에 해당)
var packageName = lastIndexOfStart >= 0 ? uiFormAssetPath.Substring(lastIndexOfStart + 1) : uiFormAssetPath;
// UI 패키지가 이미 로드되었는지 확인
var hasUIPackage = FairyGuiPackage.Has(packageName);
...
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Resources에서 로드
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

출처: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L130-L149)

3. **YooAsset 분기는 먼저 UI 패키지를 비동기로 로드한 후 UI 리소스를 로드합니다**. 패키지가 이미 로드되어 있으면 바로 UI를 생성하고, 그렇지 않으면 `AddPackageAsync`로 패키지를 로드한 뒤 `路径 + "_fui"`에서 UI 설명 리소스를 비동기로 로드합니다:

```csharp
if (hasUIPackage)
{
    // UI 패키지가 존재하면 UI를 생성
    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 1, openUIFormInfo);
}

if (packageName == uiFormAssetName)
{
    // UI 리소스 이름과 패키지 이름이 일치하면 바로 로드
    await FairyGuiPackage.AddPackageAsync(assetPath);
}
else
{
    // 일치하지 않으면 경로를 다시 조합
    string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
    await FairyGuiPackage.AddPackageAsync(newPackagePath);
}

string newAssetPackagePath = assetPath;
if (packageName != uiFormAssetName)
{
    newAssetPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
}

newAssetPackagePath += "_fui";
// 패키지에서 로드
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);

if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    // 로드 성공
    openUIFormInfo.SetAssetHandle(assetHandle);
    return LoadAssetSuccessCallback(assetPath, uiFormAssetName, openUIFormInfoData, assetHandle.Progress, openUIFormInfo);
}

// UI 패키지가 존재하지 않음
return LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo);
```

출처: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L151-L189)

4. **패키지 내 하위 리소스(아틀라스, 사운드, 폰트 등)의 비동기 로드는 `FairyGUILoadAsyncResourceHelper`가 담당합니다**. 이 클래스는 `IAsyncResource` 인터페이스를 구현하며, `AssetComponent`의 비동기 인터페이스를 통해 통일되게 처리합니다:

```csharp
internal sealed class FairyGUILoadAsyncResourceHelper : IAsyncResource
{
    public async void LoadResource(string assetName, string uiPackageName, string extension, PackageItemType type, Action<bool, string, object> action)
    {
        ...
        assetHandle = await AssetComponent.LoadAssetAsync<UnityEngine.Object>(assetName);
        ...
        var allAssetsHandle = await AssetComponent.LoadAllAssetsAsync<UnityEngine.Object>(assetName);
        if (!(allAssetsHandle.IsDone && allAssetsHandle.Status == EOperationStatus.Succeed))
        {
            action.Invoke(false, assetName, null);
            return;
        }
        ...
    }
}
```

출처: [FairyGUIPackageComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPackageComponent.cs#L148)

6. **리소스 해제 시 패키지 이름을 기준으로 언로드합니다**. `ReleasePackage` / `ReleaseAllPackage`는 설명 파일과 리소스를 언로드하기 위해 `AssetComponent.UnloadAsset`를 함께 호출합니다:

```csharp
public void ReleasePackage(string uiPackageName)
{
    if (m_UIPackages.TryGetValue(uiPackageName, out var uiPackageData))
    {
        AssetComponent.UnloadAsset(uiPackageData.DescAssetPath);
        if (uiPackageData.ResourceAssetPath != null)
        {
            AssetComponent.UnloadAsset(uiPackageData.ResourceAssetPath);
        }

        uiPackageData.Dispose();
        m_UIPackages.Remove(uiPackageName);
    }
}
```

출처: [FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L61-L74)

## 일반적인 변형

| 변형 | 방법 |
|------|------|
| 패키지 이름과 UI 이름이 다름 | 경로 전달 시 디렉터리를 패키지 이름으로 사용: 코드는 `uiFormAssetPath`의 마지막 세그먼트를 `packageName`으로 취하며, UI 이름과 일치하지 않으면 `PathHelper.Combine(uiFormAssetPath, packageName)`으로 다시 조합하여 로드 |
| Resources 간단 경로(`/` 포함 안 함) | 전체 경로가 그대로 패키지 이름이 되며, `FairyGuiPackage.AddPackageSync` 동기 로드 분기로 진행 |
| 패키지가 이미 로드됨 | `FairyGuiPackage.Has(packageName)`가 true이면 로드를 건너뛰고 바로 UI 생성 흐름으로 진입 |
| 프리로드 후 완료 대기 | `FairyGuiPackage.AddPackageAsync(descFilePath)`가 반환하는 `Task<UIPackage>`를 사용하며, 내부적으로 `m_UIPackageLoading` 딕셔너리 + `TaskCompletionSource`로 중복 로드를 방지 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| UI를 열 때 바로 동기로 반환되고 비동기를 거치지 않음 | `assetPath`에 Bundles 디렉터리 이름이 포함되지 않아 Resources 동기 분기로 분기됨 | YooAsset 모드에서 경로에 `Utility.Asset.Path.BundlesDirectoryName`가 포함되어 있는지 확인 |
| `LoadAssetFailureCallback`가 호출됨 | `assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed`가 false이며 YooAsset 핸들이 실패함 | 반환된 `assetHandle.LastError`를 확인하고 `路径 + "_fui"` 리소스가 Bundles에 패키징되어 있는지 확인 |
| `加载资源失败 Unknown file type: ...` 로그 | `PackageItemType`가 `FairyGUILoadAsyncResourceHelper`의 default 분기에 해당함(또는 `FAIRYGUI_DRAGONBONES` 매크로가 활성화되지 않음) | 리소스 유형이 지원되는지 확인; DragonBones에는 `FAIRYGUI_DRAGONBONES` 매크로 정의 필요 |
| 콘솔에 `!a`로 끝나는 Asset을 찾을 수 없다는 오류 발생 | FairyGUI 내보내기 시 "투명 채널 분리"를 체크하지 않아 `!a` 리소스를 로드할 수 없음 | 소스 코드 주석에 해당 오류가 **실행에 영향을 주지 않는다**고 명시되어 있음; 제거하려면 내보내기 시 투명 채널 분리를 활성화 |
| 언로드 후에도 UI 리소스가 메모리를 점유함 | `ReleasePackage`를 호출하지 않아 설명 파일과 리소스 핸들이 Unload되지 않음 | `FairyGUILoadAsyncResourceHelper.ReleasePackage(uiPackageName)` 또는 `ReleaseAllPackage()` 호출 |

이 중 default 분기와 DragonBones 분기의 원본 로그는 다음과 같습니다:

```csharp
default:
{
    Log.Error("加载资源失败 Unknown file type: " + assetName + " extension: " + extension);
    action.Invoke(false, assetName, null);
    break;
}
```

## 검증

- YooAsset 모드: UI를 열기 전후에 AssetComponent의 로드 로그를 관찰하여, `xxx_fui` 설명 리소스와 아틀라스/텍스처에 대한 비동기 로드가 나타나고 로드 성공 콜백이 `LoadAssetSuccessCallback`로 진행되는지 확인합니다.
- Resources 모드: 중단점 또는 로그로 `FairyGuiPackage.AddPackageSync(assetPath)` 분기에 진입했으며 UI가 정상적으로 표시되는지 확인합니다.
- 해제 검증: `ReleasePackage` 호출 후 동일한 UI를 다시 열면 다시 로드가 성공해야 하며, 핸들 누수 오류가 없어야 합니다.

## 배경

두 가지 로드 방식은 동일한 열기 흐름을 공유하며, `InnerLoadUIFormAsync`에서만 경로에 따라 분기합니다. 패키지 내 하위 리소스는 `IAsyncResource`를 구현한 `FairyGUILoadAsyncResourceHelper`로 통일되게 처리되어 `AssetComponent.LoadAssetAsync` / `LoadAllAssetsAsync`를 통해 완료되므로, 로드 방식을 전환할 때 어떤 헬퍼 코드도 교체할 필요가 없습니다.
