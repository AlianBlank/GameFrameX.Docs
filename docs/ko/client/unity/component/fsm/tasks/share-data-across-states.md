# 상태 간 데이터 공유 방법 (Variable)

`Fsm<T>`에 내장된 `SetData` / `GetData` 메서드를 사용하여 문자열을 Key로 `Variable` 实例를 저장하고 가져옴으로써, 임의의 두 `FsmState<T>` 사이에서 런타임 데이터를 안전하게 전달할 수 있습니다.

## 사전 조건

- `FsmComponent.CreateFsm<T>`를 통해 유한 상태 머신을 생성하고 최소 두 개의 상태를 등록한 상태여야 합니다.
- 상태 클래스가 `FsmState<T>`를 상속하여 `OnEnter` / `OnUpdate` / `OnExit`에서 `fsm` 매개변수를 통해 FSM에 접근할 수 있어야 합니다.
- 공유하는 데이터 타입은 반드시 `Variable`(내장 또는 사용자 정의 모두 가능)을 상속해야 합니다.

## 작업 단계

1. **공유 데이터 타입 확인**: 프레임워크는 데이터가 `Variable`에서 파생되도록 요구합니다. 이는 FSM이 객체 풀(`ReferencePool`)을 통해 `Variable` 인스턴스를 재사용하여 GC를 피하기 때문입니다.

   ```csharp
   // 정수 진행률 공유 (0~100)
   public sealed class ProgressVar : Variable
   {
       private int m_Value;
       public int Value
       {
           get => m_Value;
           set => m_Value = value;
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L46)

2. **상태 A에서 데이터 쓰기**: `SetData<TData>(name, data)`를 호출합니다. 동일한 이름의 데이터를 다시 쓸 때, 이전 인스턴스는 자동으로 `ReferencePool`으로 회수됩니다.

   ```csharp
   public class LoadingState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = new ProgressVar { Value = 0 };
           fsm.SetData("Progress", progress);
       }

       protected override void OnUpdate(IFsm<MyOwner> fsm, float elapseSeconds, float realElapseSeconds)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress != null)
           {
               progress.Value += 1; // 직접 Value를 수정하며, 다시 Set할 필요 없음
           }
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L497-L500)

3. **상태 B에서 데이터 읽기**: 강 타입 `GetData<TData>(name)`을 사용하여 직접 파생 클래스의 인스턴스를 가져옵니다. 키가 존재하지 않거나 타입이 일치하지 않으면 `null`을 반환합니다.

   ```csharp
   public class PlayState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress == null)
           {
               // 상태 머신에 해당 데이터가 없으므로 필요에 따라 폴백 처리
               return;
           }
           fsm.Owner.Ui.ShowProgress(progress.Value);
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

4. **더 이상 필요하지 않을 때 데이터 정리**: `RemoveData(name)`을 호출하면 데이터 객체가 객체 풀로 회수됩니다.

   ```csharp
   fsm.RemoveData("Progress");
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L535)

## 일반적인 변형

| 시나리오 | 사용법 | 비고 |
|------|------|------|
| 정확한 타입을 모르며 존재 여부만 확인 | `fsm.GetData("Progress")`가 `Variable` 기본 클래스를 반환 | 참조: [Fsm.cs#L469](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488) |
| 여러 상태가 동일한 키를 반복적으로 덮어쓰기 | 직접 다시 `SetData` 호출 | 이전 인스턴스가 자동으로 `ReferencePool.Release`됨 ([Fsm.cs#L521-L524](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L521-L524)) |
| 공유 데이터에 GC 재사용이 필요하지 않음 | 임의의 `Variable` 서브클래스 전달 가능 | 프레임워크는 기본 클래스만 `Variable`로 강제하며, 필드는 자유롭게 사용 가능 |

## 일반적인 오류

| 오류 현상 | 원인 | 해결 방법 |
|----------|------|------|
| `name`으로 빈 문자열을 전달하여 `GameFrameworkException("Data name is invalid.")` 발생 | API에서 `name`이 비어 있지 않아야 함 | 상수나 열거형을 key로 사용 |
| `GetData<TData>`가 `null`을 반환하여 NRE 발생 | 해당 Key가 한 번도 쓰여지지 않았거나 타입이 일치하지 않음 | 쓰기 측에서 `SetData` 후 읽거나, 먼저 `GetData(name)`으로 존재 여부 확인 |
| 동일한 이름의 데이터를 반복적으로 `new`하여 메모리 증가 | `Variable` 객체를 재사용하지 않음 | 동일한 인스턴스를 재사용하고 내부 필드만 수정; 필요한 경우에만 `SetData`로 덮어쓰기 |
| FSM이 파괴된 후에도 `GetData`에 접근 | FSM이 이미 파괴됨 | `OnExit` 내에서 참조 정리, `IFsm<T>` 핸들을 캐시하지 말 것 |

## 배경 (선택 사항)

`m_Datas`는 `Dictionary<string, Variable>`이며, `Fsm<T>`가 처음 `SetData`를 호출할 때 필요에 따라 생성합니다 ([Fsm.cs#L515-L518](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L515-L518)). 동일한 이름의 키를 덮어쓸 때 `ReferencePool.Release`를 호출하여 풀로 회수하므로, `Variable`은 반드시 참조 풀 프로토콜을 구현해야 합니다 (`Variable`을 상속하면 이미 포함됨).
