# What to Do When a Download Fails: Troubleshooting Error Codes and Callbacks

When `DownloadComponent` raises `DownloadFailureEventArgs` or `DownloadAgentHelperErrorEventArgs`, the task is in a failed state. This page helps you quickly locate the root cause based on the fields in the error callback and fix it.

## Quick Diagnosis

| Symptom (callback field values) | Root Cause | One-Sentence Fix |
|---|---|---|
| `ErrorMessage` contains `"... 416 ..."`, and `DeleteDownloading == true` (UnityWebRequest) or starts with `"416"` (WWW) | HTTP 416 Range Not Satisfiable — the remote server does not support the requested byte range | See the "416 Range Error" fix steps below |
| `ErrorMessage` is non-empty but does not contain 416 | Network layer exception (timeout, DNS failure, disconnection, protocol error, etc.) | See the "Network Layer Errors" fix steps below |
| `DeleteDownloading == true` and `ErrorMessage` is non-empty | The file written by the task needs to be deleted to avoid leftovers | See the "Clean Up Failed Leftovers" fix steps below |
| No callback for a long time, `WorkingAgentCount == TotalAgentCount` | All Agents are occupied; new tasks are waiting in the queue | See the "Stuck Tasks" fix steps below |

> For field definitions, see [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L38-L88) and [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L38-L116).

## Fix Steps

### 1. Subscribe to the Failure Callback to Get the Raw Information First

The event subscription location after `DownloadComponent.Awake` has already registered `DownloadFailure`; you only need to implement the handler and obtain `DownloadFailureEventArgs` via the event bus or `IDownloadManager.DownloadFailure`:

```csharp
using GameFrameX.Download.Runtime;
using GameFrameX.Event.Runtime;

// Subscribe via the event bus (recommended, decoupled from the component)
GameEntry.GetComponent<EventComponent>().Subscribe(
    DownloadFailureEventArgs.EventId,
    OnDownloadFailure
);

private void OnDownloadFailure(object sender, GameEventArgs e)
{
    var args = (DownloadFailureEventArgs)e;
    Debug.LogError($"[Download] FAIL serial={args.SerialId} path={args.DownloadPath} uri={args.DownloadUri} err={args.ErrorMessage} userData={args.UserData}");
}
```

Source: [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L80-L97)

### 2. 416 Range Not Satisfiable

This is the framework's signal that "the remote server rejected the resume byte range." The framework detects it as follows:

- UnityWebRequest implementation: `DeleteDownloading = true` when `responseCode == 416`.
- WWW implementation: `DeleteDownloading = true` when the `error` string starts with `"416"`.

Source: [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs#L44-L44) ; [UnityWebRequestDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/UnityWebRequestDownloadAgentHelper.cs#L240-L240) ; [WWWDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/WWWDownloadAgentHelper.cs#L248-L248)

Fix steps:

1. After receiving a failure callback with `DeleteDownloading == true`, delete the leftover partial local file.
2. Call `DownloadComponent.AddDownload(url, tag, priority, userData)` again; the framework will restart the download from 0.
3. If the CDN/OSS does not support `Range` requests, disable resumable downloads or exclude this file type at the address layer.

### 3. Network Layer Errors (Timeout / DNS / Connection Reset)

`DownloadAgentHelperErrorEventArgs.ErrorMessage` passes through Unity's native error strings directly, such as `"Cannot resolve destination host"`, `"Request timeout"`, `"Connection failure"`.

Fix steps:

1. Increase `DownloadComponent.Timeout` (default 30 seconds) as needed; for example, change it to 60 seconds for public internet files: see [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60-L62).
2. Check whether the address requires HTTPS or is being intercepted by a proxy.
3. Implement retries: in the `DownloadFailure` callback, re-enqueue a download task for the same URL (note: replace `UserData` to distinguish retry attempts).

### 4. Clean Up Failed Leftovers

When `DownloadAgentHelperErrorEventArgs.DeleteDownloading == true`, the framework recommends that you clean up the local partial file:

```csharp
private void OnAgentError(object sender, GameEventArgs e)
{
    var args = (DownloadAgentHelperErrorEventArgs)e;
    if (args.DeleteDownloading && !string.IsNullOrEmpty(localPath) && File.Exists(localPath))
    {
        File.Delete(localPath);
    }
}
```

Source: [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L67-L73)

### 5. Stuck Tasks (Queue Backlog)

Not receiving `DownloadSuccess` for a long time without triggering `DownloadFailure` usually means all Agents are occupied. Monitor the following properties to diagnose:

| Property | Meaning |
|---|---|
| `DownloadComponent.TotalAgentCount` | Total number of Agents, default 3 |
| `DownloadComponent.WorkingAgentCount` | Agents currently downloading |
| `DownloadComponent.WaitingTaskCount` | Tasks waiting in the queue |
| `DownloadComponent.Paused` | Whether globally paused |

Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L78-L105)

Fix:

1. Increase `Download Agent Helper Count` in the Inspector.
2. Confirm that no one set `DownloadComponent.Paused = true` and forgot to restore it.
3. Use `DownloadComponent.GetDownloadInfo(serialId)` / `GetDownloadInfos(tag)` to get the current task status.

## Verification

Verify that the issue is resolved in the following order:

1. Trigger a download that is known to fail (e.g., by entering a wrong address or deliberately disconnecting the network), and confirm that you receive the `DownloadFailure` callback and that `ErrorMessage` matches expectations.
2. For the 416 scenario, confirm that there are no leftover local files after the callback, and that calling `AddDownload` again successfully downloads the complete file.
3. For the network timeout scenario, reduce `Timeout` to reproduce the issue once, then reproduce it through to success with the new timeout value.
4. Run a batch download and confirm that `WaitingTaskCount` returns to zero within a reasonable time and `FreeAgentCount` recovers to `TotalAgentCount`.
