# 플레이어 ID 및 공통 속성 설정 방법

`IGameAnalyticsManager` 인터페이스의 `SetPlayerId(string playerId)`와 `SetPublicProperties(string key, object value)` 두 가지 호출만으로 게임 런타임 중 이후 전송되는 모든 이벤트에 플레이어 식별자와 공통 속성을 추가할 수 있습니다. 프레임워크는 초기화 시 디바이스 공통 속성을 자동으로 기록하므로, 비즈니스 필드만 추가하면 됩니다.

## 사전 조건

- 프로젝트에 `com.gameframex.unity.gameanalytics` 패키지가 설치되어 있고 `GameAnalyticsComponent` 컴포넌트가 부착되어 있어야 합니다.
- `Init` / `ManualInit`을 호출하여 초기화가 완료되어 있어야 합니다(`IsInit()`로 확인 가능).

## 작업 단계

1. 매니저 인스턴스를 가져옵니다(`GameAnalyticsComponent`가 노출하는 매니저 인터페이스를 통해).
2. 플레이어 로그인에 성공한 후 플레이어 ID를 설정합니다:

```csharp
// 플레이어 로그인 성공 후 플레이어 ID를 바인딩합니다(이후 모든 이벤트에 이 ID가 포함됨)
GameAnalyticsComponent.Instance.SetPlayerId("123456789");
```

`SetPlayerId`의 인터페이스 시그니처는 `void SetPlayerId(string playerId)`이며, `IGameAnalyticsManager`에 정의되어 있고 기본 클래스 `BaseGameAnalyticsManager`에서 추상 메서드로 선언되어 구체적인 플랫폼 하위 클래스에서 구현합니다:

```csharp
/// <summary>
/// 플레이어 ID 설정
/// </summary>
/// <param name="playerId">플레이어 ID</param>
void SetPlayerId(string playerId);
```

출처: [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L100-L104)

3. 비즈니스 공통 속성을 추가합니다. 한 번의 호출로 하나의 키-값 쌍을 설정합니다:

```csharp
// 호출 시 하나의 Key를 기록하며, 동일한 Key를 다시 설정하면 기존 값을 덮어씁니다
GameAnalyticsComponent.Instance.SetPublicProperties("server_id", "s1001");
GameAnalyticsComponent.Instance.SetPublicProperties("vip_level", 5);
```

기본 클래스 구현은 빈 Key를 무시하고 내부 딕셔너리 `m_PublicProperties`에 기록합니다:

```csharp
public virtual void SetPublicProperties(string key, object value)
{
    if (string.IsNullOrEmpty(key))
    {
        return;
    }

    m_PublicProperties[key] = value;
}
```

출처: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L53-L65)

4. (선택 사항) 공통 속성을 읽거나 비웁니다:

```csharp
// 읽기: 내부 딕셔너리의 복사본을 반환하며, 복사본을 수정해도 실제 공통 속성에는 영향을 주지 않습니다
Dictionary<string, object> props = GameAnalyticsComponent.Instance.GetPublicProperties();

// 비즈니스 속성을 비웁니다. 이후 디바이스 정보 공통 속성이 자동으로 다시 기록됩니다
GameAnalyticsComponent.Instance.ClearPublicProperties();
```

출처: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L67-L83)

## 내장 디바이스 공통 속성

초기화 단계에서 프레임워크는 `AddDeviceInfoToPublicProperties()`를 통해 다음 공통 속성을 자동으로 기록합니다. 수동으로 설정할 필요가 없으며, `ClearPublicProperties()` 이후에도 자동으로 복원됩니다:

| 분류 | 속성 Key |
|------|----------|
| 디바이스 | `device_id`, `device_model`, `device_type` |
| 운영 체제 | `os` |
| 애플리케이션 | `app_version`, `unity_version`, `platform` |
| 하드웨어 | `processor_type`, `processor_count`, `processor_frequency`, `system_memory_size` |
| 그래픽 | `graphics_device_name`, `graphics_device_type`, `graphics_memory_size`, `graphics_device_version`, `graphics_shader_level` |
| 화면 | `screen_width`, `screen_height`, `screen_dpi`, `screen_refresh_rate` |
| 로컬라이제이션 | `system_language`, `current_culture` |
| 네트워크 | `network_type`(값: `No Network` / `Mobile Data` / `WiFi` / `Unknown`) |

출처: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L86-L144)

## 일반적인 변형

- **계정 전환**: 먼저 `ClearPublicProperties()`로 이전 계정의 비즈니스 필드를 지운 다음, 다시 `SetPlayerId`와 `SetPublicProperties`를 설정합니다. 비운 후에는 디바이스 정보 속성이 자동으로 복원됩니다.
- **내장 속성 덮어쓰기**: 사용자 지정 Key가 위 표와 동일하면 내장 값이 직접 덮어써집니다(동일한 딕셔너리에 기록). 디바이스 차원의 정보를 잃지 않도록 일반적으로 이런 방식은 피하는 것이 좋습니다.

## 일반적인 오류

- **빈 Key는 조용히 무시됩니다**: `SetPublicProperties`는 `string.IsNullOrEmpty(key)`인 경우 바로 `return`하며, 예외를 발생시키지도 않고 기록하지도 않습니다. 설정이 적용되지 않을 때는 먼저 Key가 비어 있는지 확인하세요.
- **`ClearPublicProperties`는 플레이어 ID를 비우지 않습니다**: 이 메서드는 공통 속성 딕셔너리만 비우고 디바이스 속성을 재구성할 뿐이며, 플레이어 ID는 별도로 다시 `SetPlayerId`해야 합니다.
- **`GetPublicProperties`는 복사본을 반환합니다**: `return new Dictionary<string, object>(m_PublicProperties);` — 반환값을 직접 수정해도 실제로 전송되는 공통 속성에는 영향을 주지 않습니다.

## 배경

공통 속성은 기본 클래스의 `m_PublicProperties` 딕셔너리에 저장되며, 이벤트 전송 시 모든 이벤트와 함께 전달됩니다. 상대적으로 안정적인 차원 필드(채널, 서버, 멤버십 등급 등)를 넣기에 적합하며, 자주 변하는 수치는 이벤트의 사용자 지정 필드 `Event(string eventName, Dictionary<string, object> customF)`로 전송하는 것이 더 적합합니다.
