# 打包後事件型別被刪減失效怎麼辦

在 Editor 裡執行正常，但使用 IL2CPP 打包（尤其是開啟 Managed Stripping Level Medium/High）後，事件觸發後沒有回呼、或透過型別名稱反射取不到事件型別——這幾乎都是受管理程式碼刪減把「只被字串/反射參考」的事件型別刪掉了。本模組核心型別已由 `GameFrameXEventCroppingHelper` 與 `[Preserve]` 保護，你自己的自訂 `EventArgs` 型別需要依下文補齊保護。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `Fire` 後訂閱的回呼不執行，Editor 下正常 | 自訂事件 `EventArgs` 型別被刪減，`Type.FullName` 無法解析 | 步驟 1：為自訂事件類別加上 `[Preserve]` |
| `Utility.Assembly.GetType(componentType)` 取不到實作型別，元件初始化失敗 | 實作型別只被字串參考，被 linker 刪掉 | 步驟 2：確認刪減保護 Helper 存在於場景/組件 |
| 首包/熱更組件裡所有事件型別整體失效 | 整個組件被刪減 | 步驟 3：用 `link.xml` 完整保留組件 |
| 不想逐一檢查 | 只想快速恢復可用 | 步驟 4：調低 Managed Stripping Level |

## 修復步驟

### 1. 為自訂事件類別加上 `[Preserve]`（建議）

模組的事件基底類別本身就是這麼保護的，比照它為每個自訂事件類別加上特性：

```csharp
namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// 遊戲邏輯事件基底類別。
    /// </summary>
    [UnityEngine.Scripting.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

來源：[GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

事件 ID 依賴型別全名字串（例如 `EmptyEventArgs` 內部使用 `typeof(EmptyEventArgs).FullName` 作為 `_eventId`），型別一旦被刪減，訂閱與觸發的 ID 就對不上了，所以必須確保型別不被刪除。請參閱 [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L15-L21)。

### 2. 確認模組內建的刪減保護 Helper 生效

模組內建了一個參考保護元件，打包時只要該組件有參與編譯，核心型別就不會被刪減：

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Event.Runtime
{
    [Preserve]
    public class GameFrameXEventCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(EventManager);
            _ = typeof(EventComponent);
            _ = typeof(GameEventArgs);
            _ = typeof(IEventManager);
        }
    }
}
```

來源：[GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs#L1-L18)

檢查時確認兩點：

1. `GameFrameX.Event.Runtime` 組件沒有被整體刪掉（見步驟 3 的備援方案）。
2. 你自己新增的型別不在上面的參考清單裡，仍需依步驟 1 單獨加上 `[Preserve]`。

另外 `EventComponent` 在初始化時用 `Utility.Assembly.GetType(componentType)` 依字串解析實作型別，這一步對刪減最敏感，請參閱 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L67-L69)。

### 3. 用 `link.xml` 完整保留組件（備援）

在 `Assets` 下任意位置（例如 `Assets/StreamingAssets` 之外的一般目錄）新增 `link.xml`，把執行階段組件整體保留，並把你的自訂事件所在組件也加進來：

```xml
<linker>
  <assembly fullname="GameFrameX.Event.Runtime" preserve="all"/>
  <!-- 你的自訂事件型別所在組件，依 asmdef 名稱填寫 -->
  <assembly fullname="YourGame.Logic" preserve="all"/>
</linker>
```

組件名稱以儲存庫中的 asmdef 為準：執行階段組件檔案為 `Runtime/GameFrameX.Event.Runtime.asmdef`，編輯器組件為 `Editor/GameFrameX.Event.Editor.asmdef`。

### 4. 調低 Managed Stripping Level

`Project Settings → Player → Other Settings → Optimization → Managed Stripping Level` 調到 `Minimal` 或 `Low`，刪減強度下降後多數「字串參考被刪」的問題會消失。代價是安裝包變大，建議僅用於快速驗證根本原因是否為刪減。

## 驗證

1. 重新建置實機包（Editor 不會觸發刪減，必須用實際建置驗證）。
2. 在場景裡訂閱一個事件並 `Fire`，確認回呼有執行。
3. 也可用事件計數介面做程式化驗證：`EventManager` 提供 `EventHandlerCount`、`EventCount` 屬性與 `Count(string id)` 方法，訂閱成功後對應 ID 的處理常式數量應大於 0。請參閱 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L54-L65) 與 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L98-L102)。

## 背景

本模組的事件以「型別全名字串」為 ID，訂閱、觸發、元件實作解析都經過字串/反射路徑；IL2CPP 的受管理 linker 只追蹤靜態可見參考，看不到這些動態參考，於是判定相關型別「未使用」並刪除。`[Preserve]` 特性與 `link.xml` 都是向 linker 宣告「此型別必須保留」的標準手段，`GameFrameXEventCroppingHelper.Start` 裡的顯式 `typeof(...)` 參考同理。
