# 如何建立具名 FSM（同一類型的多個實例）

當同一持有者類型需要存在多個彼此獨立的狀態機時（例如：場景中有多個 NPC 各自執行自己的 AI、多個投射物各自執行自己的狀態流程），請使用 `CreateFsm` 的**具名多載**，以不同的 `name` 區分各實例，並使用 `GetFsm<T>(name)` / `DestroyFsm<T>(name)` 依名稱存取。

## 前置條件

- 已安裝 `com.gameframex.unity.fsm` 套件，且 `FsmManager` 已透過 `FsmComponent` 啟動（詳情請參閱《Fsm 簡介》）。
- 已為持有者類型定義多個 `FsmState<T>` 子類別。

## 操作步驟

1. **使用 `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` 建立具名 FSM**。若重複建立同名 FSM，將會拋出 `GameFrameworkException("Already exist FSM '{0}'.")`，因此每個實例的 `name` 必須唯一。

```csharp
using GameFrameX.Fsm.Runtime;

// owner 可以是不同的物件，或同一類型的不同實例
var npcAi1 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_001", new MyNpc(), idleState, patrolState, attackState);

var npcAi2 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_002", new MyNpc(), idleState, patrolState, attackState);
```

來源：[FsmManager.cs#L319-L330](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L319-L330)

2. **依名稱取得 FSM 並啟動**。無名稱的多載 `GetFsm<T>()` 只會回傳同一持有者類型的單一「預設」FSM，具名 FSM 必須使用 `GetFsm<T>(string name)`。

```csharp
var fsm = GameEntry.GetModule<IFsmManager>().GetFsm<MyNpc>("NPC_001");
fsm.Start<PatrolState>();
```

來源：[FsmManager.cs#L239-L242](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L239-L242)

3. **依名稱檢查或移除**。`HasFsm<T>(name)` / `DestroyFsm<T>(name)` 與建立一一對應；請在物件銷毀前呼叫 `DestroyFsm`，否則 `FsmManager` 內部的字典會持有無效的參考。

```csharp
var mgr = GameEntry.GetModule<IFsmManager>();
if (mgr.HasFsm<MyNpc>("NPC_001"))
{
    mgr.DestroyFsm<MyNpc>("NPC_001");
}
```

來源：[FsmManager.cs#L182-L186](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L182-L186) · [FsmManager.cs#L397-L401](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L397-L401)

4. **透過 `FullName` 進行除錯定位**。`FsmBase.FullName` 會回傳 `TypeNamePair` 的字串，可用於區分多個實例的日誌。

```csharp
Debug.Log(npcAi1.FullName); // 例如："MyNpc(NPC_001)"
```

來源：[FsmBase.cs#L67-L70](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs#L67-L70)

## 常見變化

**List 形式的狀態集合**：同樣的命名規則也適用於 `CreateFsm<T>(string name, T owner, List<FsmState<T>> states)` 多載。

```csharp
var states = new List<FsmState<MyNpc>> { idleState, patrolState, attackState };
GameEntry.GetModule<IFsmManager>().CreateFsm<MyNpc>("NPC_003", new MyNpc(), states);
```

來源：[FsmManager.cs#L354-L365](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L354-L365)

**以 `Type` 存取（不使用泛型）**：在只有 `Type` 資訊的情境下，可使用 `GetFsm(Type ownerType, string name)` / `HasFsm(Type ownerType, string name)` / `DestroyFsm(Type ownerType, string name)` 進行操作。

來源：[IFsmManager.cs#L71-L73](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsmManager.cs#L71-L73) · [IFsmManager.cs#L99-L103](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsmManager.cs#L99-L103) · [IFsmManager.cs#L177-L183](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsmManager.cs#L177-L183)

## 常見錯誤

| 現象 | 原因 | 避免方法 |
|------|------|------|
| `Already exist FSM 'MyNpc(NPC_001)'` | 已存在同名 FSM；無名稱多載的預設值為 `name = string.Empty`，因此無名稱的呼叫會彼此衝突 | 為每個實例使用唯一的 `name`；先移除現有的再重新建立 |
| `GetFsm<MyNpc>()` 回傳 `null` | 未傳入 `name` 時只會匹配名稱為空的 FSM | 改為使用 `GetFsm<MyNpc>("NPC_001")` |
| `Owner type is invalid` | 使用 `Type` 多載時傳入了 `null` | 呼叫前確認不為 `null` |
