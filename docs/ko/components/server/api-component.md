## 컴포넌트 에이전트 공개 멤버

`IComponentAgent`의 주요 멤버는 다음 표와 같으며, 구현 또는 호출 시 직접 참조하여 사용할 수 있습니다:

| 멤버 | 시그니처 | 설명 |
|------|------|------|
| `ActorId` | `long ActorId { get; }` | 현재 Agent에 바인딩된 Actor의 고유 식별자입니다. |
| `Owner` | `IComponent Owner { get; }` | Agent가 속한 상위 컴포넌트 인스턴스입니다. |
| `OwnerType` | `ushort OwnerType { get; }` | 소유자 컴포넌트의 타입 식별자(ushort)입니다. |
| `SetOwner(IComponent)` | `void SetOwner(IComponent owner)` | 컴포넌트 소유자를 설정/변경합니다. |

## 컴포넌트 타입 및 라이프사이클 규약

컴포넌트의 활성화 흐름은 다음 순서대로 연결되며, 비즈니스 측에서는 훅(hook) 메서드를 재정의할 때 필요에 따라 로직을 채워 넣으면 됩니다:

1. `BeforeActivation` —— 사전 처리, `false`를 반환하면 활성화를 중단할 수 있습니다.
2. `Active` —— 실제 초기화를 수행합니다.
3. `AfterActivation` —— 초기화 마무리 작업입니다.

비활성화는 반대 방향으로 진행됩니다:

1. `BeforeInActivation` —— 상태 저장/리소스 해제입니다.
2. `Inactive` —— 비활성화를 수행합니다.
3. `AfterInActivation` —— 정리 확인입니다.

## 어노테이션 검사기(등록 제약)

`GameFrameX.Architecture.Analyzers`는 컴파일 시점 검사기를 제공하여 컴포넌트와 Agent의 네이밍/상속이 등록 규칙을 준수하도록 합니다:

| 검사기 | 역할 |
|--------|------|
| `ComponentAgentAssemblyAnalyzer` | 컴포넌트 Agent가 속한 어셈블리를 검증합니다. |
| `ComponentAgentNameAnalyzer` | Agent 네이밍 규칙을 검증합니다. |
| `StateComponentAgentSealedAnalyzer` | `StateComponentAgent`가 반드시 `sealed`여야 함을 검증합니다. |
| `StateComponentAssemblyAnalyzer` | `StateComponent`가 속한 어셈블리를 검증합니다. |
