# JSON 設定熱更新（localization / achievement / item / sounds）

GameFrameX 透過監聽 `GameFrameX.Config/json/` 下的 JSON 檔案變更,將 localization、achievement、item、sounds 等本機設定於執行階段熱載入，無需重新啟動處理程序即可讓最新文案/數值在遊戲中生效。

## 前置條件

- 設定檔位於儲存庫根目錄下的 `GameFrameX.Config/json/` 目錄(如 `local_tblocalization.json`、`tables_tbachievementconfig.json`)。
- 設定類別由 Luban + 原始碼產生器自動產生到 `GameFrameX.Config/Config/Local/` 與 `GameFrameX.Config/Config/Tables/`,修改 JSON 後必須重新產生程式碼，否則新增欄位不會被讀取。

## 操作步驟

1. **定位 JSON 設定目錄**：所有可熱更新的本機表 JSON 檔案都放在 `GameFrameX.Config/json/`,檔名前綴 `local_` 表示本機表，`tables_` 表示 Luban 主表。

2. **修改設定內容**：直接編輯對應的 JSON。例如修改一段多語系文案：

   ```json
   [
     {
       "key": "ui_welcome",
       "ChineseSimplified": "欢迎回来",
       "ChineseTraditional": "歡迎回來",
       "English": "Welcome back",
       "Japanese": "おかえりなさい",
       "Korean": "환영합니다",
       "Thai": "ขอต้อนรับกลับมา",
       "Indonesian": "Selamat datang kembali",
       "French": "Bienvenue",
       "German": "Willkommen zurück",
       "Russian": "Добро пожаловать",
       "Italian": "Ben tornato",
       "PortuguesePortugal": "Bem-vindo de volta",
       "Spanish": "Bienvenido de vuelta",
       "Vietnamese": "Chào mừng trở lại"
     }
   ]
   ```

   欄位定義請參閱自動產生的實體類別:
   [Localization.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Local/Localization.cs#L39-L56)

3. **觸發熱載入**：執行階段的處理程序會監聽該目錄的寫入事件；儲存 JSON 檔案後伺服器端會在不重新啟動的情況下重新讀取並覆寫記憶體中的表。

4. **讓程式碼使用最新值**：業務端透過自動產生的表存取子(如 `TbLocalization`、`TbAchievementConfig`)取得資料，無需修改呼叫程式碼——只需確保產生器已基於最新 JSON 重新產生。

## 常見變體

- **新增語言欄位**：在 JSON 中附加欄位並對應修改 Luban 表結構，重新產生程式碼後熱更新才能識別新欄位。
- **新增條目**：直接在 JSON 陣列中附加物件，鍵值必須符合 `BeanBase` 子類別的欄位命名(`Key`、`English` 等)。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 儲存 JSON 後遊戲內文案沒變 | 沒有重新產生實體類別程式碼，新增欄位未被識別 | 重新執行 Luban + 原始碼產生器產生 `Localization.cs` 等 |
| 啟動時擲回 `JsonElement` 反序列化例外 | JSON 欄位名稱或大小寫與產生的類別不相符 | 依 `Localization.cs` 中 `GetProperty("...")` 的欄位名稱修正 |
| 熱更新後舊條目消失 | 直接覆寫整個陣列檔案而非附加/修改 | 僅修改目標條目，保留陣列結構 |

## 背景(可選)

JSON 表由 Luban 在編譯期產生 C# 實體類別(標記 `<auto-generated>`),執行階段透過 `JsonElement` 解析為 `BeanBase` 子類別實例。熱更新透過檔案系統監聽實作，所以 **JSON 必須寫在 `GameFrameX.Config/json/` 下並確保與產生的程式碼同源**，否則反序列化會失敗。
