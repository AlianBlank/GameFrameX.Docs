# 如何使用 LogHelper 输出分级日志

`LogHelper` 是 `GameFrameX.Foundation.Logger` 命名空间下的静态类,基于 Serilog 提供 Debug / Verbose / Info / Warning / Error / Fatal 共 6 个级别的日志输出方法,支持结构化模板、控制台输出和异常记录。读完本页你就能在自己的代码里按级别写出符合约定的日志。

## 前置条件

- .NET 项目已引用 `GameFrameX.Foundation.Logger` 程序集(Serilog 已作为传递依赖被引入)。
- 在应用启动早期通过 `LogHelper.SetLogger(...)` 注入一个配置好的 `Serilog.ILogger`,否则 `LogHelper` 会使用内置的 `InternalTempLogger` 暂存日志,等正式日志器就位后再刷入。

## 操作步骤

### 1. 初始化日志器

```csharp
using GameFrameX.Foundation.Logger;
using Serilog;

var logger = new LoggerConfiguration()
    .MinimumLevel.Verbose()      // 允许输出最低级别为 Verbose
    .WriteTo.Console()
    .CreateLogger();

LogHelper.SetLogger(logger);
```

Source: [LogHelper.cs#L101-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L101-L112)

### 2. 按级别调用对应方法

六个级别的入口方法命名直接对应级别名,签名一致:`(string messageTemplate, ...)` 或 `(object message)`,内部委托给底层 `ILogger` 的同名方法。

```csharp
using GameFrameX.Foundation.Logger;

// 调试 / 详细信息
LogHelper.Verbose("启动阶段:加载配置 {ConfigName}", configName);
LogHelper.Debug("用户 {Id} 命中缓存", userId);

// 一般信息
LogHelper.Info("登录成功 user={Id} ip={Ip}", userId, ip);
LogHelper.Info(loginResult);

// 警告
LogHelper.Warning("接口 {Api} 响应耗时 {Ms}ms 超过阈值", apiName, elapsed);

// 错误
LogHelper.Error("下单失败 orderId={Id}", orderId);

// 致命
LogHelper.Fatal("数据库连接中断 {Conn}", connectionString);
```

### 3. 记录带异常的错误/致命日志

`Error` / `Fatal` 重载支持 `Exception` 参数,会把异常对象写入日志事件:

```csharp
try
{
    DoWork();
}
catch (Exception ex)
{
    LogHelper.Error(ex, "执行失败 task={Name}", taskName);
    // 或 Fatal 级别
    LogHelper.Fatal(ex, "致命错误 task={Name}", taskName);
}
```

Source: [LogHelper.Error.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Error.cs)、[LogHelper.Fatal.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Fatal.cs)

### 4. 仅打印到控制台

不需要写文件、也不走 Serilog 的场景,用 `LogHelper.Console`,它会带毫秒级时间戳直接写到 `System.Console`:

```csharp
LogHelper.Console("服务器启动中...");
LogHelper.Console("加载资源 {Count} 个,耗时 {Ms}ms", count, ms);
```

Source: [LogHelper.Console.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Console.cs)、[LogHelper.cs#L145-L156](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L145-L156)

### 5. 应用退出前刷新缓冲

程序关闭前调用 `FlushAndSave()` 或 `CloseAndFlushAsync()` 把缓冲区里的日志写入文件:

```csharp
LogHelper.FlushAndSave();
// 或
await LogHelper.CloseAndFlushAsync();
```

## 六个级别速查表

| 级别 | 方法 | 典型用途 | Serilog 对应方法 |
|------|------|----------|------------------|
| Verbose | `LogHelper.Verbose(...)` | 最细粒度的追踪信息、循环内细节 | `ILogger.Verbose` |
| Debug | `LogHelper.Debug(...)` | 调试期诊断信息,发布版本通常关闭 | `ILogger.Debug` |
| Info | `LogHelper.Info(...)` | 业务流程关键节点(登录、下单、退出) | `ILogger.Information` |
| Warning | `LogHelper.Warning(...)` | 可恢复异常、阈值告警、降级 | `ILogger.Warning` |
| Error | `LogHelper.Error(...)` / `Error(Exception, ...)` | 业务失败、捕获到的异常 | `ILogger.Error` |
| Fatal | `LogHelper.Fatal(...)` / `Fatal(Exception, ...)` | 进程级致命错误、不可恢复 | `ILogger.Fatal` |

## 常见变体

- **结构化属性模板**:每个级别都有 1~8 个泛型重载,直接把对象作为属性绑定(不是拼字符串),便于下游 Sink 按字段检索:
  ```csharp
  LogHelper.Info<Player>("当前玩家 {Current}", player);
  LogHelper.Info<Player, int>("玩家 {Current} 击杀 {Kills}", player, kills);
  ```
  Source: [LogHelper.Info.cs#L87-L216](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L87-L216)

- **对象入参**:传 `object` 时,`Info` 会调用 `ToString()`,为 `null` 时记录字符串 `"null object"`:
  ```csharp
  LogHelper.Info(someObject); // someObject 为 null 时输出 "null object"
  ```
  Source: [LogHelper.Info.cs#L48-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L48-L51)

- **零参数模板**:仅给消息模板、不带任何格式化值,等价于直接打印字符串。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| `LogHelper.Info(...)` 没输出任何内容 | 没有调用 `LogHelper.SetLogger(...)`,且未配置 `MinimumLevel` 放行该级别 | 在启动时注入 Logger,并设置 `MinimumLevel.Verbose()` 以便调试 |
| 进程退出时日志丢失 | 没有调用 `FlushAndSave()` / `CloseAndFlushAsync()` | 在 `OnExit` / `Main` 末尾调用上述任一方法 |
| 模板里 `{Name}` 没有被替换为值 | 字符串里用了多余的占位符、参数数量不匹配 | 用 Serilog 标准模板语法 `{Property}`,参数个数与占位符一致 |
| 想知道写入文件的位置 | 当前方法不直接暴露路径,需要自行配置 Serilog Sink | 通过 `LoggerConfiguration().WriteTo.File(...)` 自行指定 |
| 记录 `null` 对象时崩溃 | 仅 `Info(object)` 做了 `ToString()` 兜底;其他级别对 `null` 的处理取决于 Serilog | 改用字符串模板版本,或自行判空 |

## 背景(可选)

`LogHelper` 是一个 `public static partial class`,每个级别的方法分布在独立文件里(`LogHelper.Debug.cs` 等),全部通过 `GetLogger()` 获取当前 `Serilog.ILogger`。如果 `SetLogger` 还未被调用,会使用内部 `InternalTempLogger` 暂存日志,等正式日志器注入时再 `FlushTo` 过去,因此**初始化顺序不必严格先于首次日志调用**。Level 越往下越详细,生产环境通常把 `MinimumLevel` 设为 `Information`,调试时再下调为 `Debug` 或 `Verbose`。关于 Serilog 的整体接入,见《如何配置 LogHandler 初始化日志系统》。
