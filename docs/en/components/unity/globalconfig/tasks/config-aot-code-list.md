# How to Configure the AOT Code List

After configuring the `AOTCodeList` field on `GlobalConfigComponent`, the framework parses it into an assembly list for hot-update solutions such as hybridclr to load supplementary metadata at runtime. Once configured, the actual assembly array can be obtained via the `AOTCodeLists` property.

## Prerequisites

- The `com.gameframex.unity.globalconfig` package has been installed in the project.
- A GameObject with `GlobalConfigComponent` attached exists in the scene (automatically created by the `GameFrameX` framework entry point).

## Steps

1. Select the GameObject with `GlobalConfigComponent` attached in the Hierarchy, and locate the **Supplementary Assembly List** field (AOTCodeList) in the Inspector.
2. Fill in a JSON string in this field, where each item in the array is the name of an AOT assembly to be loaded (typically used together with `HybridCLR`'s `AOTMetadataLoader`).
3. After compilation, the read-only **Supplementary Metadata List** below the Inspector will display the resolved assembly array (populated by the setter during deserialization).
4. Runtime code can directly read this array and pass it to `RuntimeApi.LoadMetadataForAOTAssembly`.

## Field Reference

| Inspector Name | Field Name | Type | Read/Write | Purpose |
|----------------|------------|------|------------|---------|
| Supplementary Assembly List | `m_aotCodeList` | `string` | Read/Write | JSON string, the entry point for source code persistence |
| Supplementary Metadata List | `m_aotCodeLists` | `List<string>` | Read-only | Parsed assembly name list |
| Raw Data | `m_originalData` | `string` | Read-only | Raw response returned from remote |

Field definitions in `GlobalConfigComponent`:

```csharp
[SerializeField] private string m_aotCodeList = string.Empty;

[SerializeField] private List<string> m_aotCodeLists = new List<string>();

public List<string> AOTCodeLists
{
    get { return m_aotCodeLists; }
}

public string AOTCodeList
{
    get { return m_aotCodeList; }
    set
    {
        m_aotCodeList = value;
        try
        {
            m_aotCodeLists = Utility.Json.ToObject<List<string>>(value);
        }
        catch (Exception e)
        {
            Log.Error(e);
        }
    }
}
```

## Runtime Access

The `GlobalConfigComponent` singleton can be obtained via `GameEntry`:

```csharp
var aotList = GameEntry.GlobalConfig.AOTCodeLists;
foreach (var asm in aotList)
{
    // Hand over to hybridclr: RuntimeApi.LoadMetadataForAOTAssembly(...)
}
```

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| `AOTCodeLists` remains empty after setting `AOTCodeList` | Invalid JSON format, `Utility.Json.ToObject` throws an exception that is swallowed by `Log.Error` | Check `Log.Error` output in the console and fix the JSON (pay attention to double quotes, commas, and square brackets) |
| Cannot edit in play mode | Inspector is entirely disabled during playback | Exit play mode before modifying |
| List does not refresh after modification | The setter only parses on assignment; directly modifying `m_aotCodeList` will not re-parse | Re-assign the `AOTCodeList` property, or restart the Inspector |

## Background

The design where `AOTCodeList` is a string while `AOTCodeLists` is a `List<string>` is intended to keep the serialized field as a primitive type (for easy Inspector editing and network transmission), while deserializing the JSON into a usable list at runtime. The `m_aotCodeLists` field is read-only to prevent external code from bypassing the setter and the JSON validation.
