# 一键切换国内小游戏平台

通过 Unity 编辑器菜单 `GameFrameX/Scripting Define Symbols/Domestic Mini Games(国内小游戏)` 下的命令,可以一键开启或关闭某个国内小游戏平台的适配宏定义,并自动屏蔽其他国内小游戏平台的互斥宏。

## 前置条件

- 编辑器 Build Target 已切换到 `WebGL`(`MiniGameDefineSymbolHelper` 的菜单项与实现均包在 `#if UNITY_WEBGL` 下,否则菜单不会出现)。
- 工程已引入 GameFrameX 编辑器扩展程序集(本目录 `Editor/MiniGame/` 下的脚本)。
- 了解每个平台对应的宏定义会被写入 `Project Settings → Player → Scripting Define Symbols`(WebGL 平台)。

## 操作步骤

1. 在 Unity 顶部菜单点击 **GameFrameX → Scripting Define Symbols → Domestic Mini Games(国内小游戏)**,展开子菜单。
2. 选择目标平台下的 **Enable xxx Mini Game(开启[xxx 小游戏]适配)** 项。
3. 切换完成后 Console 会逐条打印 `xxx 小游戏宏定义 [ENABLE_XXX_MINI_GAME] 已经打开`。
4. 切换到另一平台时,再次选择对应 Enable 项即可,旧平台的宏会自动被清理。

例如开启微信小游戏:

```csharp
// Editor/MiniGame/DomesticMiniGames/MiniGameDefineSymbolHelper.WeChat.cs
public static readonly string[] EnableWeChatMiniGameScriptingDefineSymbol =
    new[] { "ENABLE_WECHAT_MINI_GAME", "WEIXINMINIGAME" };

#if UNITY_WEBGL
[MenuItem("GameFrameX/Scripting Define Symbols/Domestic Mini Games(国内小游戏)/Enable WeChat Mini Game(开启[微信小游戏]适配)", false, 2000)]
#endif
public static void EnableWeChatMiniGame()
{
#if UNITY_WEBGL
    DisableOtherMiniGameScriptingDefineSymbols(EnableWeChatMiniGameScriptingDefineSymbol);
    foreach (var define in EnableWeChatMiniGameScriptingDefineSymbol)
    {
        if (!ScriptingDefineSymbols.HasScriptingDefineSymbol(BuildTargetGroup.WebGL, define))
        {
            ScriptingDefineSymbols.AddScriptingDefineSymbol(define);
        }
        Debug.Log($"微信小游戏宏定义 [{define}] 已经打开");
    }
    EnableUnifiedMiniGameScriptingDefineSymbol();
#endif
}
```

## 常见变体

- **关闭某平台宏**: 选择 `Disable xxx Mini Game(关闭[xxx 小游戏]适配)`,会从 `Scripting Define Symbols` 中移除该平台对应的宏并打印 `xxx 小游戏宏定义 [xxx] 已经关闭`。
- **只移除本平台宏、不影响其他国内小游戏平台宏**: 关闭时不会调用 `DisableOtherMiniGameScriptingDefineSymbols`,只刷新统一小游戏宏。
- **同时启用多个平台**: 默认互斥。每次 Enable 一个平台时,`DisableOtherMiniGameScriptingDefineSymbols` 会先清掉其他国内小游戏宏。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 菜单里看不到 `Domestic Mini Games(国内小游戏)` 子菜单 | 当前 Build Target 不是 WebGL | 切到 WebGL 后再打开菜单 |
| Enable 后编译报错 `The type or namespace xxx could not be found` | 第三方小游戏 SDK 的 SDK 项目未导入 | 先安装对应平台的 Unity 适配包,再 Enable 宏 |
| 切到新平台后旧平台的代码仍参与编译 | 手动合并过 `Scripting Define Symbols` 导致清理失败 | 在 Player Settings 中清空 WebGL 的宏,再使用 Enable 菜单重置 |

## 背景

Enable 流程固定三步:先调用 `DisableOtherMiniGameScriptingDefineSymbols` 清理其他国内小游戏宏 → 遍历本平台宏集合,按需 `AddScriptingDefineSymbol` → 调用 `EnableUnifiedMiniGameScriptingDefineSymbol()` 刷新统一小游戏宏;Disable 流程则是移除本平台宏并调用 `RefreshUnifiedMiniGameScriptingDefineSymbol()`。这种"先清再加"的写法避免了多个国内小游戏平台宏同时存在时,同一份代码引用了不同平台 SDK 导致的类型冲突。
