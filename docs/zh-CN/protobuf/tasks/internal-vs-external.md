# 如何区分外部协议与内部协议

通过 `.proto` 文件的文件名前缀、`package` 命名与 `option module` 数值,就能快速判断一个协议属于客户端与服务端交互的"外部协议",还是服务器集群内部通信用的"内部协议"。

## 前置条件

- 已克隆 [GameFrameX.Protobuf](https://github.com/GameFrameX/GameFrameX.Protobuf) 仓库。
- 了解 `.proto` 文件的基本结构(`syntax`、`package`、`option`、`message`)。

## 判定速查表

| 维度 | 外部协议(客户端 ↔ 服务端) | 内部协议(服务器 ↔ 服务器) |
|------|---------------------------|----------------------------|
| 文件名前缀 | 数字下划线开头,例如 `_0010_`、`_0120_` | 以 `_-` 开头(如 `_-0120_Inner_Social.proto`)或带 `Inner` 标识(如 `_0002_InnerBasic.proto`) |
| `package` 命名 | 业务域名称,如 `Basic`、`Social`、`User`、`Bag` | 业务域前加 `Inner`,如 `InnerBasic`、`InnerSocial` |
| `option module` 数值 | **正数**(通常 10、20、100、120 等按业务递增) | **负数**或**小正数**(如 `-120`、`2`) |
| 通信对象 | 游戏客户端与网关/业务服 | 服务器之间、跨服、后台调度 |

下面用仓库里的真实文件对比说明。

## 操作步骤

1. **看文件名**——`_-` 开头或文件名中含 `Inner` 关键字的,优先判定为内部协议。

   ```text
   _0010_Basic.proto            ← 外部
   _0120_Social.proto           ← 外部
   _0002_InnerBasic.proto       ← 内部(文件名带 Inner)
   _-0120_Inner_Social.proto    ← 内部(文件名前缀 "_-" 且带 Inner)
   ```

   Source: [_0010_Basic.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0010_Basic.proto#L1-L3)

2. **看 `package` 声明**——内部协议的包名固定以 `Inner` 开头,外部协议则为直接的英文业务名。

   ```protobuf
   syntax = "proto3";
   package Basic;          // 外部:Basic
   option module = 10;
   ```

   Source: [_0010_Basic.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0010_Basic.proto#L1-L3)

   ```protobuf
   syntax = "proto3";
   package InnerBasic;     // 内部:InnerBasic
   option module = 2;
   ```

   Source: [_0002_InnerBasic.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0002_InnerBasic.proto#L1-L3)

3. **看 `option module` 数值**——这是最可靠的机器可读判定依据:正数为外部,负数为内部,小正数(如 2)通常用于"基础内部协议"。

   ```protobuf
   option module = 10;     // 外部(Basic)
   option module = 120;    // 外部(Social)
   option module = 2;      // 内部(InnerBasic)
   option module = -120;   // 内部(InnerSocial,负数镜像外部编号)
   ```

   Sources: [_0010_Basic.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0010_Basic.proto#L3), [_0120_Social.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0120_Social.proto#L3), [_0002_InnerBasic.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0002_InnerBasic.proto#L3), [_-0120_Inner_Social.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_-0120_Inner_Social.proto#L3)

4. **看消息名约定**——内部协议的 `Req`/`Resp`/`Info` 通常带 `Inner` 前缀,与外部同业务消息区分开。

   ```protobuf
   // 内部协议
   message ReqInnerFriendByAdd { int64 PlayerId = 1; }
   message RespInnerFriendByAdd { bool Success = 1; }
   message InnerFriendInfo { int64 PlayerId = 1; string PlayerName = 2; }
   ```

   Source: [_-0120_Inner_Social.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_-0120_Inner_Social.proto#L6-L22)

   ```protobuf
   // 外部协议(同业务对比)
   message ReqDeleteFriend { int64 PlayerId = 1; }
   message RespDeleteFriend {}
   message FriendInfo { int64 PlayerId = 1; string PlayerName = 2; }
   ```

   Source: [_0120_Social.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0120_Social.proto#L5-L30)

## 常见变体

- **同业务的内外配对**:当某个业务(如 `Social`)既需要客户端能力,又需要服务器内部能力时,会出现一对文件——外部 `_0120_Social.proto` + 内部 `_-0120_Inner_Social.proto`,`module` 编号互为相反数(120 ↔ -120)。

- **纯基础内部协议**:不与任何外部业务配对,例如 `_0002_InnerBasic.proto`,`module = 2` 用最小号段表示"全局基础内部消息"。

- **新增内部协议**:若要新增一个内部协议,沿用 `Inner{业务}` 命名、给一个负的 `module` 值,并确保与对应外部 `module` 互为相反数,即可被框架自动识别。

## 常见错误

| 错误做法 | 后果 | 正确做法 |
|----------|------|----------|
| 内部协议误用正 `module` 或缺 `Inner` 命名 | 框架路由层把它当外部协议下发给客户端 | 内部协议必须 `package` 以 `Inner` 开头,并使用**负数** `module` |
| 在外部协议文件里写 `ReqInnerXxx` 消息名 | 与内部协议命名冲突,排查困难 | 外部消息名保持纯业务前缀,内部消息统一加 `Inner` |
| 漏掉 `option module` 声明 | 生成代码或运行时路由失败 | 每个 `.proto` 都必须显式声明 `option module`,且与命名约定一致 |

## 背景(可选)

仓库按"四位数字编号"组织协议:前两位为业务大类,后两位为该业务内编号。内部协议在此基础上加 `Inner` 前缀,并通过负的 `module` 值让运行时在分发层一眼识别——内部协议只走服务器内网/集群通道,绝不暴露给客户端。

关于协议文件命名规范的完整说明,见仓库根目录的协议说明文档。
