# 依存サブパッケージが未インストール导致的コンパイル失敗への対処法

`com.gameframex.unity.entry` が何らかのサブパッケージ(例：Network、UI、FairyGUI、Asset、Procedure など)を参照しているにもかかわらず、そのサブパッケージが未インストールまたはバージョン不一致の場合、Unity コンソールには `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Xxx.Runtime' which is not in the project` や `The type or namespace name 'X' could not be found` というエラーが表示され、コンパイルが中断されます。本ページでは、エラーに基づいて不足しているサブパッケージを特定し、コンパイルを復旧させる手順を説明します。

## クイック診断

| 症状(コンソール原文) | 原因 | 修正 |
|---|---|---|
| `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Network.Runtime' which is not in the project.` | プロジェクトに `com.gameframex.unity.network` サブパッケージが未インストール | Package Manager で対応する依存パッケージをインストール |
| `The type or namespace name 'GameApp' could not be found` | `com.gameframex.unity.entry` が未インストールまたは削除されている | エントリーパッケージを再インストール |
| コンパイルエラーメッセージに `GameFrameX.UI.Runtime`、`GameFrameX.Asset.Runtime`、`GameFrameX.FSM.Runtime` などが言及されているが、プロジェクトにこれらのアセンブリが存在しない | 対応するオプションサブパッケージが不足(オプション依存が未インストール) | 該当サブシステムが必要か評価し、不要なら参照を削除、必要ならインストール |
| サブパッケージをインストール済みなのに `assembly references ... which is not in the project` と表示される | サブパッケージのバージョンが `package.json` で宣言されたバージョン範囲と一致しない | 依存テーブルが要求するバージョンへサブパッケージをアップグレード/ダウングレード |
| 特定のサブシステム(例：広告、ログイン)を有効にしたときのみ型が見つからないというエラーが出る | 対応する `versionDefines` マクロが有効化されておらず、コードは `#if` で除外されているのにスクリプトがロードされ続けている | サブパッケージのインストール後にマクロが自動注入されることを確認。仍未生效の場合は Unity を再起動し Assets を更新 |

### 2. 不足しているサブパッケージをインストールする

Unity を開き `Window` → `Package Manager` へ進み、左上の `+` → `Add package by name...` をクリックし、上表の `name` と `version` に従って入力してインストールします。例として Network を補完する場合：

1. Package Manager を開く。
2. `Add package by name` を選択。
3. 名前:`com.gameframex.unity.network`、バージョン:`2.6.10`。
4. `Add` をクリックし、Unity が解決・ダウンロードするのを待つ。

インストール完了後、Package Manager は自動的に `Packages/manifest.json` へ書き込み、対応する `versionDefines` マクロを注入します。

### 3. バージョン不一致時の対処

`package.json` に固定された依存バージョンは、互換性がテスト済みの組み合わせです。手動でそれより低い/高いバージョンに固定した場合、`asmdef` が参照するアセンブリが見つからなくなることがあります。

- `Packages/manifest.json` または `Packages/packages-lock.json` 内の該当パッケージのバージョンを確認。
- `package.json` の `dependencies` フィールドと照合し、目標バージョンに統一。
- Git URL 参照の場合(例： `com.gameframex.unity.network`)、URL の後に `#2.6.10` を付加してタグを固定。

### 4. 該当サブシステムが不要な場合の簡素化方法

特定のオプションサブシステムが不要な場合は、それをインストールせずに済ませると同時に、`GameFrameX.Entry.Runtime` が対応アセンブリを参照しないようにできます。具体的には、自分の asmdef 内で `GameFrameX.Entry` 経由でそのパスをトリガーしない、または該当サブシステムへのコード参照を削除します。`GameFrameX.Entry.Runtime.asmdef` は、対応サブパッケージの有無に応じて `versionDefines` によりコード分岐を自動的に有効/無効化します。

```text
例:Procedure + UI + Network だけを使う場合、インストールが必要なのは
  com.gameframex.unity.procedure@1.4.0
  com.gameframex.unity.ui@2.11.0
  com.gameframex.unity.network@2.6.10
その他のオプションサブパッケージ(広告、ログイン、統計、XLua など)のインストールは不要で、コードはマクロによって自動的に除外されます。
```

### 5. インストール後もエラーが出る場合のクリーンアップ手順

1. Unity を終了。
2. プロジェクトルート直下の `Library/ScriptAssemblies/` と `Library/PlayerScriptAssemblies/` を削除。
3. `Library/PackageCache/` 配下にある、不足サブパッケージに関連する残存キャッシュを削除。
4. Unity を再起動し、初回インポートの完了を待つ。

完了後、コンソールにアセンブリ不足の警告は表示されなくなるはずです。

## 検証

- Unity Console で `Assembly ... references ... which is not in the project` 系のエラーがゼロになる。
- `Window` → `Package Manager` で、`dependencies` に宣言されたすべてのサブパッケージが `Installed` 状態になっている。
- 任意のスクリプトで `using GameFrameX.Entry.Runtime;` が成功し、`GameApp.Procedure`、`GameApp.Network` などの静的アクセサにアクセスできる。

## 背景(オプション)

エントリーパッケージ `com.gameframex.unity.entry` は、`GameFrameX.Entry.Runtime.asmdef` を通じてすべてのサブシステムアセンブリへの参照を一括宣言し、`versionDefines` においてサブパッケージの有無に応じて `ENABLE_GAME_FRAME_X_*` マクロを注入することで、未インストールのサブパッケージのコード区間を `#if` で除外し、必要に応じたコンパイルを実現しています。`package.json` の `dependencies` フィールドはバージョン整合の唯一の真実の情報源(Single Source of Truth)です——コンパイルで「アセンブリが見つからない」と報告された場合は、asmdef を手動で修正するのではなく、まずここのバージョンを確認してください。
