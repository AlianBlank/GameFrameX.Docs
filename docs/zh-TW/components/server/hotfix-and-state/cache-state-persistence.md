# 使用 CacheState + BsonClassMap 持久化實體

透過 `CacheStateTypeManager.Init()` 一次性掃描所有實作 `ICacheState` 的實體類別,框架會同時把它們註冊到 `BsonClassMap`,後續 MongoDB 序列化即可直接讀寫,無須在每個實體上手寫對應。

## 前置條件

- 已參考 `GameFrameX.Apps` 組件(包含 `BsonClassMapHelper`、`CacheStateTypeManager`)。
- 實體類別需要實作 `ICacheState` 介面(標記為可快取/可持久化的實體)。
- 行程啟動階段呼叫過一次 `Init()`,通常放在 `Program.Main` 中其他元件初始化之前。

## 操作步驟

1. **讓實體實作 `ICacheState` 介面**

   任何需要被持久化(典型為寫入 MongoDB)的實體都必須實作 `ICacheState`。框架只掃描實作該介面的型別。

2. **在啟動入口呼叫一次 `CacheStateTypeManager.Init()`**

   `Init()` 會掃描 `AppsHandler` 所在組件,篩選出所有實作 `ICacheState` 的型別,用 `XxHash32(类型全名)` 作為 id 寫入內部 `ConcurrentDictionary<long, Type>`,並對每個型別呼叫 `BsonClassMapHelper.RegisterClass` 註冊到 MongoDB 驅動程式。

   ```csharp
   // GameFrameX.Launcher/Program.cs
   static void Main(string[] args)
   {
       CacheStateTypeManager.Init();
       MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
       // ... 其他启动逻辑
   }
   ```

   來源:[GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L10-L20)

3. **`Init()` 內部會同時註冊兩個 BSON Convention**

   - `DictionaryRepresentationConvention`:把 `IDictionary` 的 BSON 表示固定為 `ArrayOfDocuments`,避免在不同驅動程式版本下預設行為不一致。
   - `EmptyContainerSerializeMethodConvention`:對 `List<T>`、`Dictionary<,>`、`ConcurrentDictionary<,>` 等容器,在元素個數為 0 時跳過序列化,減少空欄位寫入。

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   ConventionRegistry.Register(nameof(DictionaryRepresentationConvention),
                               new ConventionPack { new DictionaryRepresentationConvention(), }, _ => true);

   ConventionRegistry.Register(nameof(EmptyContainerSerializeMethodConvention),
                               new ConventionPack { new EmptyContainerSerializeMethodConvention(), }, _ => true);
   ```

   來源:[GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L102-L111)

4. **對每個實體執行 `BsonClassMap.AutoMap` 並忽略多餘欄位**

   框架以型別全名的 `XxHash32` 作為字典主鍵,保證 `GetType(id)` 在不同行程/重新啟動後能穩定找回原型別;`AutoMap` + `SetIgnoreExtraElements(true)` 讓新增欄位不會使舊資料反序列化失敗。

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   public static void RegisterClass(Type t)
   {
       var bsonClassMap = new BsonClassMap(t);
       bsonClassMap.AutoMap();
       bsonClassMap.SetIgnoreExtraElements(true);
       bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
       BsonClassMap.RegisterClassMap(bsonClassMap);
   }
   ```

   來源:[GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

5. **執行階段透過 `GetType(id)` 反查型別,完成多型反序列化**

   當 BSON 文件裡只存了型別 id 時,呼叫 `CacheStateTypeManager.GetType(id)` 即可取回具體的 `Type`,再交給 MongoDB 驅動程式建構物件。

   ```csharp
   // GameFrameX.Apps/CacheStateTypeManager.cs
   public static Type GetType(long id)
   {
       HashMap.TryGetValue(id, out var value);
       return value;
   }
   ```

   來源:[GameFrameX.Apps/CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L41-L45)

## 常見變體

- **新增了實作 `ICacheState` 的實體類別**：重新啟動行程即可，無須手動呼叫任何註冊 API,`Init()` 會自動掃描。
- **實體不在 `AppsHandler` 所在組件**：呼叫 `BsonClassMapHelper.RegisterAllClass(assembly)` 手動把目標組件餵給註冊流程，完成額外掃描。
- **臨時停用空容器跳過序列化**：不要註冊 `EmptyContainerSerializeMethodConvention`,或在自己的實體上單獨設定 `SetShouldSerializeMethod`。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 啟動時出現 `BsonClassMap already registered` | 同一型別被重複註冊 | `RegisterClass` 內已有 `IsClassMapRegistered` 防護,檢查是否在 `Init()` 之外手動呼叫過 `RegisterClassMap` |
| 反序列化遺失欄位或擲出 `Element ... does not match any field` | 沒有呼叫 `SetIgnoreExtraElements` | 確認走的是 `BsonClassMapHelper.RegisterClass` 路徑 |
| `CacheStateTypeManager.GetType(id)` 回傳 `null` | 實體類別未實作 `ICacheState`,`Init` 時未被收錄 | 為實體加上 `ICacheState` 介面,重新啟動行程 |
| `Dictionary` 在 BSON 裡表現為 `Document` | 未註冊 `DictionaryRepresentationConvention` | 確認 `Init()` 已執行,且在所有 MongoDB 操作之前 |

## 背景

框架選用 `XxHash32(type.ToString())` 作為型別 id,是為了讓 id 穩定且與 .NET 型別全名一一對應,同時佔用空間小;把 `SetIgnoreExtraElementsIsInherited` 開啟,是為了讓子類別繼承的欄位在新增時也不會破壞舊文件。Convention 全域註冊使用 `_ => true`,意味著對所有未明確對應的類別都生效,降低業務端心智負擔。
