# 결제 시스템 초기화

Unity 씬에 `PaymentComponent`를 부착하고 `Init`을 호출하면 결제 시스템 초기화가 완료됩니다: 컴포넌트는 `Awake`에서 현재 플랫폼에 따라 해당하는 결제 관리자 구현(Google / Apple / WebGL / PC)을 자동으로 선택하며, 상품 ID만 설정하고 샌드박스 및 검증 스위치를 전달하면 바로 구매 인터페이스를 사용할 수 있습니다.

## 사전 조건

- Unity 프로젝트에 이 패키지가 설치되어 있어야 합니다. 아래 방법 중 하나를 선택하세요 (자세한 내용은 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/README.zh-CN.md#L40-L67) 참조):
  - `Packages/manifest.json`의 `dependencies`에 `"com.gameframex.unity.payment": "https://github.com/gameframex/com.gameframex.unity.payment.git"`를 추가;
  - 또는 Unity `Package Manager`의 `Git URL` 방식으로 추가;
  - 또는 저장소를 `Packages` 디렉터리 아래에 직접 배치하여 자동 인식.
- 의존성 패키지 `com.gameframex.unity`(버전 1.1.1 이상)가 설치되어 있어야 합니다.
- 대상 플랫폼은 Android(Google Play) 또는 iOS(App Store)입니다. Editor 및 기타 플랫폼은 플레이스홀더 구현으로 폴백됩니다 (아래 "일반적인 오류" 참조).

## 작업 단계

1. 시작 씬에 GameObject를 생성하고, 메뉴 `GameFrameX/Payment`를 통해 `PaymentComponent`를 추가합니다. 컴포넌트는 의존성과 진입 메뉴를 다음과 같이 선언합니다:

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

컴포넌트를 추가하면 `GameFrameXPaymentCroppingHelper`는 `RequireComponent`에 의해 자동으로 함께 추가되므로 수동으로 추가할 필요가 없으며, 동일한 오브젝트에 중복 부착은 허용되지 않습니다.

2. (선택) 플랫폼 구현 타입을 확인합니다. 컴포넌트는 `Awake`에서 컴파일 매크로에 따라 구현 클래스의 전체 이름을 자동으로 선택합니다:

```csharp
#if UNITY_ANDROID
    componentType = m_componentAndroidType;
#elif UNITY_IOS
    componentType = m_componentIOSType;
#elif UNITY_WEBGL
    componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
    componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
    componentType = m_componentMacType;
#else
    componentType = typeof(DefaultPaymentManager).FullName;
#endif
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L83)

각 플랫폼의 기본 타입 이름 (Inspector의 직렬화 필드에서 수정 가능):

| 필드 | 기본값 | 적용 플랫폼 |
|------|--------|----------|
| `m_componentAndroidType` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` | Android |
| `m_componentIOSType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | iOS |
| `m_componentWebGLType` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` | WebGL |
| `m_componentPCType` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` | Windows / Linux |
| `m_componentMacType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | macOS |

3. `Init`을 호출하기 전에 상품 캐시를 미리 로드해야 하는 경우, 먼저 `SetPredefinedProductIds`를 호출합니다 (이 메서드는 반드시 초기화 이전에 호출해야 합니다):

```csharp
/// <summary>
/// 사전 로드할 사전 정의된 상품 ID를 설정합니다. 캐시 미리 로드에 사용됩니다. 주의: 이 메서드는 반드시 Initialize() 이전에 호출해야 합니다
/// </summary>
/// <param name="inAppProductIds">인앱 상품 ID 목록</param>
/// <param name="subsProductIds">구독 상품 ID 목록</param>
[UnityEngine.Scripting.Preserve]
public void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds)
{
    _paymentManager.SetPredefinedProductIds(inAppProductIds, subsProductIds);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L117-L126)

4. `Init`을 호출하여 초기화를 완료합니다. 컴포넌트의 시그니처와 기본값은 다음과 같습니다:

```csharp
/// <summary>
/// 초기화
/// </summary>
/// <param name="isDebug">샌드박스 구매 여부</param>
/// <param name="isClientVerify">클라이언트 구매 검증 수행 여부</param>
[UnityEngine.Scripting.Preserve]
public void Init(bool isDebug = false, bool isClientVerify = true)
{
    _paymentManager.Init(isDebug, isClientVerify);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L96-L105)

매개변수 설명:

| 매개변수 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `isDebug` | `bool` | `false` | 샌드박스 구매 모드 사용 여부 |
| `isClientVerify` | `bool` | `true`(컴포넌트 계층) / `false`(인터페이스 계층) | 클라이언트 구매 검증 수행 여부; 상시 온라인 환경에서 서버가 검증하는 경우 `false`를 전달해야 합니다 |

인터페이스 계층의 정의와 주석 (서버 검증을 기준으로 할 때는 `false` 전달):

```csharp
/// <param name="isClientVerify">클라이언트에서 구매 성공 검증 수행 여부. 상시 온라인 검증인 경우 활성화할 필요 없이 false로 설정하여 서버 검증을 진행합니다</param>
[UnityEngine.Scripting.Preserve]
void Init(bool isDebug = false,bool isClientVerify = false);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L37-L43)

5. `IsReady()`로 결제 시스템이 준비되었는지 폴링/확인하고, 준비된 후 구매를 시작합니다:

```csharp
/// <summary>
/// 결제 시스템이 준비되었는지 여부
/// </summary>
/// <returns>준비되었으면 true, 그렇지 않으면 false를 반환</returns>
[UnityEngine.Scripting.Preserve]
public bool IsReady()
{
    return _paymentManager.IsReady();
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L107-L115)

6. (선택) 구매 결과 이벤트를 구독합니다. 이벤트는 컴포넌트에서 `IPaymentManager`로부터 직접 전달됩니다: `OnPurchaseSuccess`, `OnPurchaseFailed`, `OnQueryPurchasesResult`, `OnConsumePurchaseResult`, 매개변수 타입은 모두 `EventHandler<PaymentEventArgs>`입니다.

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64)

## 일반적인 변형

- **자체 개발/기타 채널 구현으로 전환**: 코드를 수정하지 않고 Inspector에서 해당 플랫폼의 직렬화 필드(예: `m_componentAndroidType`)를 사용 중인 구현 클래스의 전체 이름으로 변경합니다. 해당 클래스는 `IPaymentManager`를 구현해야 합니다 (일반적으로 `BasePaymentManager`를 상속). 컴포넌트는 `Utility.Assembly.GetType(componentType)`를 통해 리플렉션으로 타입을 로드합니다.
Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L84-L85)
- **샌드박스/테스트 환경**: `Init(true)`를 호출하여 `isDebug`를 `true`로 설정하면 채널 샌드박스 구매 흐름을 따라갑니다.
- **서버 측 검증**: `Init(isDebug: false, isClientVerify: false)`를 호출하면 구매 성공 후 서버가 영수증을 검증하며, 클라이언트는 로컬 검증을 수행하지 않습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 로그에 `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).`가 출력되고 `IsReady()`가 항상 `false`임 | 현재 플랫폼(예: Editor)이 플레이스홀더 구현 `DefaultPaymentManager`로 폴백됨 | 대상 플랫폼이 Android/iOS이고 해당 채널 패키지가 설치되어 있는지 확인; 또는 커스텀 구현 클래스 연결 |
| 로그에 `Pay Manager is invalid.`가 출력되고 중단됨 | `GameFrameworkEntry.GetModule<IPaymentManager>()`가 null을 반환함, 모듈이 등록되지 않음 | GameFrameX 기반 패키지(`com.gameframex.unity`)가 설치되어 있는지, 버전이 일치하는지 확인 |
| 사전 정의된 상품이 적용되지 않음 | `SetPredefinedProductIds`가 `Init` 이후에 호출됨 | 해당 호출을 `Init` 이전으로 이동 |
| 플랫폼 구현 타입이 올바르지 않음 | Inspector의 직렬화 필드가 잘못 수정되었거나, 플랫폼 전환 후 매크로가 적용되지 않음 | 위의 플랫폼 매핑 표에 따라 필드 값 확인; 플랫폼 전환 후 재컴파일 |

플레이스홀더 구현의 관련 소스 코드 (로그 비교용):

```csharp
private const string NotImplWarning = "You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).";

public override void Init(bool isDebug = false, bool isClientVerify = false)
{
    Log.Warning(NotImplWarning);
}

public override bool IsReady()
{
    return false;
}
```

Source: [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L36)

## 검증

- 초기화 후 `PaymentComponent.IsReady()`를 호출합니다: `true`가 반환되면 채널 구현이 준비된 것입니다. Editor 또는 채널이 연결되지 않은 플랫폼에서 `false`가 반환되는 것은 예상된 동작입니다.
- Console에 `DefaultPaymentManager which is a stub` 경고가 더 이상 나타나지 않으면 현재 플랫폼에 실제 채널 구현이 로드되었음을 의미합니다.

## 배경

`PaymentComponent`는 GameFrameworkComponent이며, `Awake`에서 컴파일 매크로에 따라 구현 클래스의 전체 이름을 결정하고, `Utility.Assembly.GetType`으로 `ImplementationComponentType`을 해석하며, 인터페이스 타입은 `IPaymentManager`로 고정되고, 이후 `GameFrameworkEntry.GetModule<IPaymentManager>()`를 통해 모듈 인스턴스를 가져옵니다. 컴포넌트의 `Init`, `IsReady`, `Buy` 등의 메서드는 모두 해당 인스턴스로의 전달입니다. 채널 구현(Google, Apple 등)의 소스 코드는 이 저장소에 포함되어 있지 않으므로 해당 채널 패키지를 별도로 설치해야 합니다.
