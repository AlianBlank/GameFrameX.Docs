# 設定載入失敗時的處理方式

當 `SettingComponent.Start()` 中的 `m_SettingManager.Load()` 回傳 `false` 時，主控台會輸出 `Load settings failure.`。這表示設定載入流程失敗。本頁面將說明如何快速找出失敗原因並加以修正。

## 快速診斷

| 症狀（原始日誌） | 原因 | 修正 |
|------|------|------|
| `Setting manager is invalid.` | `ISettingManager` 模組未註冊，或 GameFramework 尚未啟動 | 請參閱 [模組未註冊](#模組未註冊-setting-manager-is-invalid) |
| `Can not create setting helper.` | `SettingHelper` 型別名稱設定錯誤、組件未包含在執行階段中，或找不到自訂 Helper 類別 | 請參閱 [Helper 建立失敗](#helper-建立失敗-can-not-create-setting-helper) |
| `Load settings failure.` | `ISettingHelper.Load()` 的實作回傳了 `false`（載入 / 反序列化失敗） | 請參閱 [Load 實作回傳 false](#load-實作回傳-false-load-settings-failure) |
| `Setting helper is invalid.` 例外 | 在呼叫 `Load()` / `Save()` 之前未呼叫 `SetSettingHelper()` | 請參閱 [Helper 未設定導致例外](#helper-未設定導致例外-setting-helper-is-invalid) |
| 平台的小遊戲儲存空間中沒有資料 | PlayerPrefs / 小遊戲的儲存後端為空，沒有可載入的內容 | 請參閱 [儲存後端為空](#儲存後端為空) |

## 模組未註冊（Setting manager is invalid）

`SettingComponent.Awake()` 會透過 `GameFrameworkEntry.GetModule<ISettingManager>()` 取得管理器。若回傳 `null`，則會輸出 `Setting manager is invalid.` 並立即 return，之後的 `Start()` 中將不會執行 Load。

修正步驟：

1. 請確認場景中存在 `GameFrameX.Runtime.GameFrameworkEntry`（或同等的啟動元件）。框架的進入點必須在 `SettingComponent` 之前啟動。
2. 請確認 `SettingManager` 模組已包含在框架的組件清單中（位於 `Runtime/Setting/Setting/SettingManager.cs`，命名空間為 `GameFrameX.Setting.Runtime`），且未被排除在套件之外。
3. 若使用自訂的 GameFramework 啟動流程，則需要將 `SettingManager` 加入啟動模組清單。

## Helper 建立失敗（Can not create setting helper）

`SettingComponent.Awake()` 會呼叫 `Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper)`。若回傳 `null`，則會輸出 `Can not create setting helper.`。

```csharp
// 出處：Runtime/Setting/SettingComponent.cs#L87-L92
SettingHelperBase settingHelper = Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper);
if (settingHelper == null)
{
    Log.Error("Can not create setting helper.");
    return;
}
```

修正步驟：

1. 請在 Inspector 中確認 `SettingComponent` 的 `Setting Helper Type Name`。預設值為 `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`。
2. 若使用自訂 Helper，請確認自訂類別繼承自 `SettingHelperBase`（`Runtime/Setting/SettingHelperBase.cs#L43`），且完全限定型別名稱（包含命名空間）的拼字正確無誤。
3. 請確認自訂 Helper 所在的組件已包含在 Player / 小遊戲的執行階段建置中，且未被刪除。
4. 若要注入 `m_CustomSettingHelper` 欄位，請將其拖曳至 Inspector，並確認場景中只有一個 `SettingComponent`。

## Load 實作回傳 false（Load settings failure）

若 Helper 建立成功，但 `Load()` 內部處理失敗，`SettingComponent.Start()` 便會輸出 `Load settings failure.`：

```csharp
// 出處：Runtime/Setting/SettingComponent.cs#L102-L108
private void Start()
{
    if (!m_SettingManager.Load())
    {
        Log.Error("Load settings failure.");
    }
}
```

`SettingManager.Load()` 內部只是將處理委派給目前的 Helper：

```csharp
// 出處：Runtime/Setting/Setting/SettingManager.cs#L145-L150
public bool Load()
{
    EnsureSettingHelper();
    return m_SettingHelper.Load();
}
```

請依 Helper 的種類分別處理：

- **PlayerPrefsSettingHelper**：`Load()` 一律回傳 `true`（[出處](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L86-L89)）。如果顯示此錯誤，請先確認實際生效的 Helper 類別並非自訂實作。
- **自訂 Helper**：請在 `Load()` 中逐一確認檔案是否存在、讀取權限以及反序列化例外。建議新增詳細的日誌以定位失敗位置。
- **小遊戲平台 Helper**（WeChat / DouYin / KuaiShou / Alipay）：請以 `SettingStorageBackendFactory.Create()` 取得 `ISettingStorageBackend`，並確認已定義對應的平台巨集，且 SDK 已正確整合。

## Helper 未設定導致例外（Setting helper is invalid）

若未在 `SettingManager` 上呼叫 `SetSettingHelper()` 就呼叫 `Load()` / `Save()` / `GetAllSettingNames()`，將會擲回 `GameFrameworkException("Setting helper is invalid.")`：

```csharp
// 出處：Runtime/Setting/Setting/SettingManager.cs#L130
throw new GameFrameworkException("Setting helper is invalid.");
```

這只可能發生在不透過 `SettingComponent` 而直接 new 出 `SettingManager` 的情況。修正方法：請先呼叫 `SetSettingHelper(yourHelper)` 再呼叫 `Load()`。或者直接使用 `SettingComponent`，它會在 `Awake()` 中自動注入。

## 儲存後端為空

`PlayerPrefsSettingHelper` 會透過 `SettingStorageBackendFactory.Create()` 延遲載入 `ISettingStorageBackend`。若工廠回傳 `null`，或平台 SDK 尚未初始化，`GetString` / `SetString` 等呼叫將會發生例外，並以 `false` 的形式從 `Load()` / `Save()` 回傳。

修正步驟：

1. 請確認對應的平台巨集已啟用（`UNITY_WEBGL`、小遊戲平台的巨集等）。
2. 請確認平台 SDK 已在 `Awake()` / `Start()` 之前完成初始化。
3. 請在 `PlayerPrefsSettingHelper` 之前注入測試用的 `ISettingStorageBackend`。請參考 `SetStorageBackendForTests(...)` 的用法。

## 驗證

修正完成後，請依照以下順序確認：

1. 啟動遊戲，確認主控台沒有顯示 `Load settings failure.` 或上述提到的錯誤日誌。
2. `SettingComponent.GetAllSettingNames()` 能正常回傳（PlayerPrefs 的實作一律回傳空陣列，這是預期行為）。
3. 呼叫 `SettingComponent.Save()` 後重新啟動遊戲，確認能以 `HasSetting(name)` / `GetString(name)` 讀回先前寫入的值。
4. 若仍發生例外，請保留完整的堆疊資訊，並確認問題不在繼承自 `SettingHelperBase` 的具體類別上。
