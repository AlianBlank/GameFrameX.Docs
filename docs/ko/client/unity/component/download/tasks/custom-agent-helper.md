# 사용자 지정 다운로드 에이전트 도우미

`IDownloadAgentHelper` 인터페이스를 구현하여 기본 다운로드 백엔드(프록시 획득, 파일 저장, 스트리밍 읽기 등의 동작)를 교체하거나 확장할 수 있습니다.

## 사전 조건

- `Microsoft.Kiota.Authentication.Azure` 또는 관련 Kiota 인증 패키지가 프로젝트에 추가되어 있어야 합니다.
- 대상 프로젝트는 C# / .NET을 사용하며, 의존성 주입과 `IHttpClient` 수명 주기를 이해하고 있어야 합니다.
- 다운스트림 호출 소스로 사용할 수 있는 `IAuthenticationProvider` 인스턴스가 이미 있어야 합니다.

## 작업 단계

1. 새 클래스를 만들어 `IDownloadAgentHelper` 인터페이스의 세 멤버를 구현합니다(구체적인 시그니처는 소스 코드 기준).
2. 생성자에서 필요한 의존성을 주입합니다(예: `IHttpClient`, `IAuthenticationProvider`, `ILogger` 등).
3. 구현된 인스턴스를 싱글톤 또는 스코프 방식으로 `IServiceCollection`에 등록합니다.
4. 요청 실행 전에 이 도우미를 필요로 하는 호출자에게 전달합니다(예: `KiotaClientFactory`의 관련 오버로드).
5. 최소화된 다운로드 요청을 한 번 실행하여 사용자 지정 로직(로그, 중단점, 파일 경로)이 적용되는지 확인합니다.

## 일반적인 변형

- **로그 래핑**: 기존 구현 외부에 한 겹을 씌워 로그/원격 측정만 추가하고 나머지는 전달합니다.
- **경로 재작성**: 테넌트 또는 사용자 컨텍스트에 따라 임시 파일을 격리된 디렉터리에 저장합니다.
- **스트리밍 청킹**: 청크 크기와 동시성을 사용자 지정하여 기본 `BufferSize` 동작을 재정의합니다.

## 일반적인 오류

| 현상 | 가능한 원인 | 처리 |
|------|---------|------|
| 등록 후 적용되지 않음 | 기본 등록이 교체되지 않았거나 스코프가 일치하지 않음 | `services.AddSingleton<>` / `AddScoped<>` 선택 확인 |
| 다운로드 실패 시 오류 정보 없음 | `HttpRequestException`이 캐처되어 전달되지 않음 | `DownloadAsync`에서 `try/catch`로 래핑하고 기록 |
| 파일이 사용 중임 | 스트림이 해제되지 않음 | `await using` 또는 명시적 `Dispose()` |
| 인증 헤더 누락 | `GetAuthenticationProvider`에서 다운스트림 provider를 호출하지 않음 | 교체가 아닌 전달 |

## 배경(선택 사항)

`IDownloadAgentHelper`는 Kiota가 추상화한 다운로드 기능 확장 지점입니다. 기본 구현은 `HttpClient`를 사용하며, 사용자 지정 구현은 인증, 재시도, 저장 정책 등 횡단 관심사를 연결할 수 있습니다. 이 페이지에서는 연결 방법만 설명하며, 인증 제공자의 전체 설계는 여기서 다루지 않습니다.
