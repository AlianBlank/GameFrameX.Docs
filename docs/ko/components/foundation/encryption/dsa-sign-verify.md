# DSA 서명 및 검증 사용 방법

`DsaHelper`는 DSA 디지털 서명 알고리즘의 서명 및 검증 기능을 제공하며, SHA256을 해시 알고리즘으로 사용하고 키는 XML 문자열 형식으로 저장합니다. 이 페이지에서는 키 쌍 생성, 단일 문자열 서명 및 검증부터 `DsaHelper` 인스턴스 재사용까지의 전체 단계를 시연합니다.

## 사전 조건

- 프로젝트에서 `GameFrameX.Foundation.Encryption` 패키지를 참조합니다.
- 대상 프레임워크는 .NET입니다(`System.Security.Cryptography.DSA` 지원). `DsaHelper`는 내부적으로 `DSA.Create()`를 사용하며, Windows / Linux / macOS 모두에서 실행 가능합니다.
- 네임스페이스 `using GameFrameX.Foundation.Encryption;`을 사용합니다.

## 작업 단계

### 1. DSA 키 쌍 생성

`DsaHelper.Make()`를 호출하여 개인 키와 공개 키의 XML 문자열을 한 번에 얻고, 각각 키 이름 `privatekey`, `publickey`로 가져옵니다:

```csharp
using GameFrameX.Foundation.Encryption;

var keys = DsaHelper.Make();
string privateKey = keys["privatekey"]; // XML 개인 키
string publicKey  = keys["publickey"];  // XML 공개 키
```

출처: [DsaHelper.cs#L127-L140](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L127-L140)

### 2. 문자열 데이터 서명(정적 메서드)

서명할 문자열과 개인 키를 `SignData(string, string)`에 전달하면 Base64로 인코딩된 서명 값을 반환합니다. 개인 키 형식이 잘못되면 `CryptographicException`이 발생하며 메시지는 `"Invalid DSA private key."`입니다.

```csharp
using GameFrameX.Foundation.Encryption;

string data = "hello world";
string signature = DsaHelper.SignData(data, privateKey); // Base64 문자열 반환
```

실제 서명 흐름: `Encoding.UTF8.GetBytes` → `DSA.SignData(..., HashAlgorithmName.SHA256)` → `Convert.ToBase64String`.

출처: [DsaHelper.cs#L189-L200](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L189-L200)

### 3. 문자열 서명 검증(정적 메서드)

원문, Base64 서명, 공개 키를 `VerifyData(string, string, string)`에 전달하면 `true`는 서명이 유효함을 나타냅니다. 공개 키 형식이 잘못되었거나 서명이 유효하지 않으면 `false`를 반환합니다(예외를 던지지 않음):

```csharp
using GameFrameX.Foundation.Encryption;

bool ok = DsaHelper.VerifyData(data, signature, publicKey);
```

내부적으로 `DSA.VerifyData(..., HashAlgorithmName.SHA256)`를 호출하며, `CryptographicException`과 `XmlException`을 잡아 `false`를 반환합니다.

출처: [DsaHelper.cs#L282-L287](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L282-L287)

### 4. 바이트 배열 직접 서명 및 검증(선택 사항)

문자열/Base64 인코딩 및 디코딩을 피하려면 `byte[]` 오버로드를 사용할 수도 있습니다. 서명 시 `CryptographicException` 또는 `XmlException`은 내부에서 흡수되어 `null`을 반환하므로 직접 처리해야 합니다:

```csharp
using GameFrameX.Foundation.Encryption;

byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello world");
byte[] signedBytes = DsaHelper.SignData(payload, privateKey);     // 실패 시 null 반환
bool valid = DsaHelper.VerifyData(payload, signedBytes, publicKey); // 실패 시 false 반환
```

출처: [DsaHelper.cs#L153-L176](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L153-L176), [DsaHelper.cs#L246-L270](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L246-L270)

### 5. `DsaHelper` 인스턴스 재사용(선택 사항)

동일한 프로세스 내에서 반복적으로 서명/검증을 수행해야 하는 경우, `using`을 사용하여 공개 키 또는 개인 키를 보유한 `DsaHelper` 인스턴스를 생성하고 매번 `FromXmlString`의 오버헤드를 피하는 것이 좋습니다. 인스턴스 메서드는 `_dsa.SignData` / `_dsa.VerifyData`를 사용하며 예외는 직접 상위로 전파됩니다:

```csharp
using GameFrameX.Foundation.Encryption;

using (var signer = new DsaHelper(privateKey))
{
    string signature = signer.SignData("hello world"); // Base64
}

using (var verifier = new DsaHelper(publicKey))
{
    bool ok = verifier.VerifyData("hello world", signature);
}
```

생성 시 두 가지 오버로드를 지원합니다: `DSA` 인스턴스 또는 XML 키 문자열을 전달합니다. null / 빈 문자열을 전달하면 각각 `ArgumentNullException` / `ArgumentException`이 발생하며, XML이 잘못된 경우 `CryptographicException`이 발생합니다.

출처: [DsaHelper.cs#L70-L102](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L70-L102), [DsaHelper.cs#L212-L232](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L212-L232), [DsaHelper.cs#L299-L320](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L299-L320)

## 일반적인 변형

- **인스턴스를 사용한 서명과 정적 검증 함께 사용(프로세스 간 전송 시나리오)**: 발신자는 `new DsaHelper(privateKey).SignData(원문)`을 사용하여 Base64 서명을 메시지와 함께 보내고, 수신자는 `DsaHelper.VerifyData(원문, 서명, 공개 키)`로 검증합니다.
- **원시 바이트 스트림 서명**: 데이터가 이미 바이트인 경우(예: 직렬화된 protobuf), `byte[]` 오버로드를 직접 호출하여 UTF-8 / Base64 인코딩 및 디코딩을 건너뜁니다.
- **키가 구성 파일에서 오는 경우**: `Make()`에서 출력한 XML 문자열을 구성 센터에 저장하고 시작 시 읽어 생성자 또는 정적 메서드에 직접 전달합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `SignData(string, string)`이 `CryptographicException: Invalid DSA private key.` 발생 | 개인 키 문자열이 유효한 DSA XML이 아니거나 공개 키가 개인 키로 잘못 전달됨 | `Make()["privatekey"]`가 전달되었는지 확인; XML이 손상된 경우 재생성 |
| `SignData(byte[], string)`이 `null` 반환 | 개인 키 형식异常(`CryptographicException` 또는 `XmlException`이 내부적으로 흡수됨) | 키 XML 확인; 문자열 오버로드를 사용하면 명확한 예외 정보를 얻을 수 있음 |
| `VerifyData`가 항상 `false` 반환 | 공개 키/원문/서명 중 하나라도 일치하지 않음(인코딩, 잘림, 다른 키 쌍 사용) | 원문이 UTF-8로 일관되게 인코딩되었는지, 서명이 이중 Base64되지 않았는지, 서명 및 검증 당사자가配套 키 쌍을 사용하는지 확인 |
| `new DsaHelper(null)`이 `ArgumentNullException` 발생 | null인 `DSA` 인스턴스 또는 키 문자열을 전달함 | 생성하기 전에 입력 검증; XML 키는 `ArgumentException.ThrowIfNullOrEmpty` 이후에 전달해야 함 |
| macOS에서 2048비트 키 지정 실패 | 플랫폼 DSA 구현이 기본이 아닌 키 크기에 대해 제한적으로 지원 | `DsaHelper.Make()`로 생성된 기본 크기 키 쌍을 직접 사용 |

## 배경(선택 사항)

`DsaHelper`는 내부적으로 더 이상 사용되지 않는 `DSACryptoServiceProvider`를 대체하여 `DSA.Create()`를 통합 사용하며, 서명 해시를 명시적으로 `HashAlgorithmName.SHA256`으로 지정하여 DSA 기본 SHA-1의 약점을 회피합니다. 클래스는 `IDisposable`을 구현하므로 인스턴스를 장기간 보유할 때는 반드시 `using`을 사용하여 기본 비관리 리소스를 해제해야 합니다. DSA는 서명 및 검증에만 사용되며 암호화/복호화에는 사용할 수 없습니다.
