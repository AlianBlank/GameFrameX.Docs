# 生成腳本的執行方式(用戶端/伺服器)

只需執行儲存庫根目錄下的 `gen-*.bat` 或 `gen-*.sh` 腳本，即可將 `Excels/` 下的 Excel 表格自動轉換為可在用戶端(Unity)或伺服器(.NET)直接使用的程式碼與資料檔案。本頁將介紹 4 種腳本的差異、最基本的執行步驟，以及常見錯誤的修正方式。

## 4 個生成腳本一覽

儲存庫提供了 4 個生成入口，由**目標端**(`client` / `server`)與**輸出格式**(`bin` / `json`)的組合構成：

| 腳本 | 目標端 | 資料格式 | 程式碼格式 | 輸出位置(資料 / 程式碼) |
|------|--------|----------|----------|------------------------|
| `gen-client-bin.sh` / `.bat` | 用戶端 | 二進位(`bin`) | C# 二進位序列化(`cs-bin`) | `../Unity/Assets//Bundles/Config` / `../Unity/Assets//Hotfix/Config/Generate` |
| `gen-client-json.sh` / `.bat` | 用戶端 | JSON | C# | `Unity/Assets/Bundles/Config` / `Unity/Assets/Hotfix/Config/Generate` |
| `gen-server-bin.sh` / `.bat` | 伺服器 | 二進位(`bin`) | C# .NET 二進位序列化(`cs-dotnet-bin`) | `../Server/GameFrameX.Config/Json` / `../Server/GameFrameX.Config/Config` |
| `gen-server-json.sh` / `.bat` | 伺服器 | JSON | C# | `Server/GameFrameX.Config/Json` / `Server/GameFrameX.Config/Config` |

> `c` = 用戶端(client)、`s` = 伺服器(server)、`bin` = 二進位、`json` = 文字。同一目標端下，`bin` 檔案較小、載入速度較快;`json` 可讀性高，便於查看資料。

## 前置條件

- 已安裝 **.NET SDK**(腳本會透過 `dotnet` 來啟動 `./Tools/Luban.dll`)。
- 儲存庫內的 `Tools/Luban.dll`、`luban.conf`、`Defines/builtin.xml`、`Excels/__tables__.xlsx`(包含 `__beans__`、`__enums__`)請務必放在原始位置，不要移動。
- 表格已按照規則填寫完畢(`Excels/Tables/` 內的表格名稱格式為 `字母-英文名-中文名.xlsx`,英文名中不得包含中文)。

## 操作步驟

1. 開啟終端機 / 命令列，並 **`cd` 到儲存庫的根目錄**(看得到 `gen-*.sh`、`gen-*.bat` 的那一層)。腳本內的相對路徑全部以該目錄為基準，因此請勿在子目錄中執行。

2. 選擇目標端與輸出格式，並執行對應的腳本：

   - **用戶端 JSON 生成(最常用的入門指令)：**

     ```bash
     sh gen-client-json.sh
     ```

     在 Windows 上對應的操作是雙擊 `gen-client-json.bat`。

   - **用戶端二進位生成：**

     ```bash
     sh gen-client-bin.sh
     ```

     [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1) 的核心呼叫如下：

     ```bash
     dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin \
       --xargs outputDataDir=../Unity/Assets//Bundles/Config \
       --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
       --xargs tableImporter.name=gameframex \
       -x l10n.provider=gameframex \
       -x l10n.textFile.keyFieldName=key \
       -x l10n.textFile.path=./Excels/Local/ \
       --conf ./Luban.conf
     ```

     來源:[gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1)

   - **伺服器二進位生成：**

     ```bash
     sh gen-server-bin.sh
     ```

     實際的呼叫內容請參考 [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1):

     ```bash
     dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin \
       --xargs outputDataDir=../Server/GameFrameX.Config/Json \
       --xargs tableImporter.name=gameframex \
       --xargs outputCodeDir=../Server/GameFrameX.Config/Config \
       --conf ./Luban.conf
     ```

     來源:[gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1)

   - **伺服器 JSON 生成：** 執行 `sh gen-server-json.sh`(對應的 `.bat`)。

3. 等待腳本執行完成。只要最後停在 `pause`(Windows `.bat`),或是沒有出現紅色的錯誤訊息，就算成功。

4. 確認產出結果：
   - 用戶端:`Unity/Assets/Hotfix/Config/Generate/` 下應該會有自動生成的 C# 類別(例如:`TbAchievementConfig.cs`),`Unity/Assets/Bundles/Config/` 下則是資料檔案。
   - 伺服器:`Server/GameFrameX.Config/Config/` 下是 C# 類別，`Server/GameFrameX.Config/Json/` 下是資料檔案。

## 常見變化

- **只想針對特定目標端生成時：** 只要在表格名稱加上群組標記即可，不需要切換腳本。例如，`D-ItemConfig-道具表.xlsx` 會同時生成到用戶端與伺服器，`D-ItemConfig-c-道具表.xlsx` 只會生成到用戶端，`D-ItemConfig-s-道具表.xlsx` 只會生成到伺服器。詳情請參考 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md)。
- **變更多語系文字(Excels/Local/)時：** 只要照原樣重新執行同一個腳本即可，不需要重新啟動任何東西。
- **變更表格標頭(欄位名稱/型別)時：** 重新執行腳本 → 重新生成程式碼 → 在呼叫端配合新的欄位名稱進行編譯。
- **bin 與 json 的切換：** 在同一個目標端下，只要把 `gen-client-bin.sh` 換成 `gen-client-json.sh` 重新執行即可。若是在用戶端執行時切換了格式，也請記得更新載入程式碼。

## 常見錯誤

- **`'dotnet' is not recognized` / `dotnet: command not found`**:原因是尚未安裝 .NET SDK,或是終端機無法在 PATH 中找到它。請先安裝 .NET 6+ SDK,再重新開啟終端機。
- **`Could not find ./Tools/Luban.dll`**:目前所在目錄不正確。請先 `cd` 到包含 `Tools/` 的儲存庫根目錄，再重新執行。
- **`不支持中文表名` / 類別名稱出現亂碼**：檔名中的英文部分寫入了中文。請改為 `字母-英文名-中文名.xlsx` 的格式，英文名只能使用英數字元與底線。
- **輸出目錄殘留舊檔案，並引用了已刪除的欄位**：請把 `outputCodeDir` 指向的目錄(例如:`Unity/Assets/Hotfix/Config/Generate/`)整個刪除後，再重新執行腳本。
- **`failed: conf file` / 設定錯誤**：因為修改了 `luban.conf` 而導致解析失敗。請從 Git 還原該檔案後再重試。請勿任意變更頂層欄位。
- **從 `text` 欄位讀取多語 key,但讀到的仍是 key 本身**：請確認你執行的是 `gen-client-bin.sh`,或是帶有 `-x l10n.provider=gameframex -x l10n.textFile.path=./Excels/Local/` 等一系列參數的命令，而不是只使用 `--conf ./Luban.conf` 的命令。

## 背景(選讀)

4 個腳本本質上都是在呼叫 `dotnet ./Tools/Luban.dll`,差異只在 3 個開關:`--target`(決定要使用 client 還是 server 的程式碼範本與資料型別對應)、`--dataTarget`(決定資料的儲存格式為 `bin` 或 `json`)、`--codeTarget`(決定生成的 C# 序列化方式(例如:`cs-bin`、`cs-dotnet-bin`))。`outputDataDir` 與 `outputCodeDir` 控制產出檔案的儲存位置，`--conf ./Luban.conf` 則指向專案層級的設定。`gen-client-bin.sh` 中比 `gen-server-bin.sh` 多了幾個 `-x l10n.*` 參數，是因為 Unity 端需要把 `text` 欄位的多語 key 直接解析成目前語言的字串，所以在腳本中明確注入了在地化提供者。
