# Xcode 프로젝트에 파일 및 폴더 복사

이 페이지에서는 Xcode 빌드 후처리(post-process) 설정에서 로컬 파일 또는 전체 폴더를 생성된 Xcode 프로젝트에 복사하고, 자동으로 Build 목록과 검색 경로에 추가하는 방법을 설명합니다. Xcode 설정 파일(JSON)의 `files`와 `folders` 필드에 "소스 경로 → 대상 경로" 매핑을 작성하기만 하면, 빌드 시 자동으로 복사가 실행됩니다.

## 사전 조건

- Unity 프로젝트가 iOS 플랫폼으로 전환되어 있어야 합니다(구현은 모두 `#if UNITY_IOS` 아래에 있습니다).
- Xcode 빌드 후처리 기본 연동이 완료되어 있어야 합니다: `PostProcessBuildHelper`가 빌드 콜백에서 병합된 설정을 읽고 `Run`을 호출합니다.

## 작업 단계

1. Xcode 빌드 후처리 설정 파일을 열고, 대상 target의 설정 노드(예: `unityMain` / `unityFramework`에 해당하는 해시 테이블)를 찾습니다.
2. 해당 노드 아래에 `files` 필드를 추가합니다. Key는 소스 파일 경로(Unity 프로젝트 루트 디렉터리, 즉 `Environment.CurrentDirectory` 기준 상대 경로)이고, Value는 대상 경로(생성된 Xcode 프로젝트 디렉터리 기준 상대 경로)입니다:

```json
{
  "files": {
    "Assets/Plugins/iOS/NativeCode.mm": "Libraries/NativeCode.mm",
    "Assets/Plugins/iOS/MySDK.framework": "Frameworks/MySDK.framework"
  }
}
```

3. 전체 폴더를 복사해야 할 때는 `folders` 필드를 추가하며, 마찬가지로 "소스 경로 → 대상 경로" 매핑을 사용합니다:

```json
{
  "folders": {
    "Assets/Plugins/iOS/NativeFolder": "Libraries/NativeFolder"
  }
}
```

4. iOS 빌드를 한 번 실행합니다. 빌드가 끝나면 `Run`이 순서대로 복사를 실행합니다: 먼저 `RunCopyFiles`가 `files`를 처리하고, 이어서 `CopyFolders`가 `folders`를 처리합니다:

```csharp
// 파일 복사
RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
// 폴더 복사
CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L173-L176)

5. Xcode 프로젝트에서 확인합니다: 파일이 해당 대상 경로에 나타나고, `AddFileToBuild`에 의해 대상 target의 Build 목록에 추가되어 있습니다. 콘솔에는 `copy file {src} -> {des}` 로그가 출력됩니다.

## 복사 동작 세부 사항

복사는 단순한 파일 복사가 아니며, 다음 동작들은 소스 코드 구현에서 비롯된 것으로 설정 시 알아두어야 합니다:

| 동작 | 설명 |
|------|------|
| 대상 디렉터리 자동 생성 | `CopyFolder`는 먼저 이미 존재하는 동일 이름의 디렉터리/파일을 삭제한 후, `Directory.CreateDirectory`로 다시 생성하여 재귀적으로 복사합니다 |
| 기존 파일 덮어쓰기 | 단일 파일 복사에는 `File.Copy(src, des, true)`가 사용되며, 동일 이름의 파일은 덮어써집니다 |
| 숨김 파일 및 불필요한 파일 무시 | 파일명이 `.`로 시작하거나 `.gitkeep`, `.DS_Store`인 파일은 건너뛰며, 복사하지도 Build에 추가하지도 않습니다 |
| 자동으로 Build에 추가 | 파일은 `proj.AddFile` + `proj.AddFileToBuild`를 통해 프로젝트에 추가됩니다 |
| 검색 경로 자동 추가 | `.framework` / `.xcframework` 복사 시 자동으로 `FRAMEWORK_SEARCH_PATHS` 추가; `.h`는 자동으로 `HEADER_SEARCH_PATHS` 추가; `.a`는 자동으로 `LIBRARY_SEARCH_PATHS` 추가되며, 접두사는 `$PROJECT_DIR`입니다 |
| bundle은 메인 target에도 동시 추가 | `folders`에서 `.bundle`로 끝나는 항목은 대상 target 외에도 `AddFileToBuild(mainTargetGuid, fileGuid)`를 통해 Unity 메인 target에도 추가됩니다 |
| 폴더 전체를 framework로 취급 | `folders`의 대상 경로가 `.framework` / `.xcframework` / `.bundle` / `.a`로 끝나면, 전체 디렉터리가 단일 라이브러리 파일로 취급되어 빌드에 추가되며, 더 이상 재귀적으로 확장되지 않습니다 |

파일 복사의 핵심 구현:

```csharp
private static void CopyFile(PBXProject proj, string targetGuid, string xcodePath, string src, string des)
{
    bool needCopy = IsNeedCopy(src);
    if (needCopy)
    {
        File.Copy(src, des, true);
        proj.AddFileToBuild(targetGuid, proj.AddFile(des, des.Replace(xcodePath + "/", ""), PBXSourceTree.Absolute));
        AutoAddSearchPath(proj, xcodePath, targetGuid, des);
        Debug.Log("copy file " + src + " -> " + des);
    }
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L42-L52)

폴더 재귀 복사의 핵심 구현(먼저 대상을 비우고 다시 생성):

```csharp
private static void CopyFolder(string srcPath, string dstPath)
{
    if (Directory.Exists(dstPath))
    {
        Directory.Delete(dstPath, true);
    }

    if (File.Exists(dstPath))
    {
        File.Delete(dstPath);
    }

    Directory.CreateDirectory(dstPath);

    foreach (var file in Directory.GetFiles(srcPath))
    {
        if (IsNeedCopy(Path.GetFileName(file)))
        {
            File.Copy(file, Path.Combine(dstPath, Path.GetFileName(file)));
        }
    }

    foreach (var dir in Directory.GetDirectories(srcPath))
    {
        CopyFolder(dir, Path.Combine(dstPath, Path.GetFileName(dir)));
    }
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L172-L198)

## 일반적인 변형

- **SDK / 정적 라이브러리 복사**: `.framework`, `.xcframework`, `.a`를 `folders`에 넣고, 대상 경로를 `Frameworks/xxx.framework`로 직접 작성합니다. 프레임워크는 Link Binary With Libraries에 추가되고 검색 경로가 자동으로 보완됩니다(`AddFrameworkToProject(targetGuid, root, false)`). `.a` 정적 라이브러리는 링크 단계에만 추가됩니다.
- **리소스 bundle 복사**: `folders`에서 `.bundle`로 끝나는 디렉터리는 Unity 메인 target과 UnityFramework target에 동시에 추가되며, 패키지와 함께 배포해야 하는 리소스에 적합합니다.
- **파일을 프로젝트에 넣기만 하고 컴파일에 참여시키지 않는 세부 조정**: 복사 완료 후, 같은 레벨의 `filesCompileFlag` 설정을 통해 컴파일 플래그를 설정할 수 있으며, 이 단계는 복사 이후에 실행됩니다(`SetFilesCompileFlag`).

## 일반적인 오류

| 문제 | 원인 | 해결 방법 |
|------|------|------|
| 복사 후 Xcode에서 파일을 찾을 수 없음 | 소스 경로를 절대 경로로 썼거나 상대 경로 계층이 잘못됨 | `files`/`folders`의 Key는 Unity 프로젝트 루트 디렉터리 기준 상대 경로이며, 실행 시 `Path.Combine(Environment.CurrentDirectory, key)`가 사용됩니다 |
| 일부 파일이 계속 복사되지 않음 | `IsNeedCopy`의 제외 규칙에 해당됨 | 파일명이 `.`로 시작하거나 `.gitkeep`, `.DS_Store`인 파일은 바로 건너뛰므로 이름을 바꾸거나 이동하세요 |
| 빌드할 때마다 대상 디렉터리 내용이 "사라짐" | `CopyFolder`가 먼저 `Directory.Delete(dstPath, true)`로 대상 디렉터리를 비움 | 다른 내용을 `folders` 설정의 대상 디렉터리에 수동으로 넣지 마세요 |
| 단일 파일 복사 시 대상이 이미 존재한다는 예외가 발생하며 적용되지 않음 | 실제로는 그렇지 않으며, 단일 파일 복사에는 `overwrite: true`가 포함됨 | 그래도 실패한다면 대상 디렉터리에 동일 이름의 폴더가 있는지 확인하세요(디렉터리로 처리됨) |
| framework 링크 시 찾을 수 없다는 오류 발생 | 자동 검색 경로 로직이 실행되지 않음 | `.framework` / `.xcframework` / `.a`로 끝나는지 확인하세요. `AutoAddSearchPath`는 이 세 가지 확장자에만 적용됩니다 |

## 배경

복사는 Xcode 프로젝트 생성 이후에 발생합니다: `PostProcessBuildHelper`가 PBXProject와 병합된 설정을 읽고, `Run`이 properties, frameworks, libs, files, folders 등을 순서대로 처리합니다. `CopyFolders`가 추가로 `mainTargetGuid`를 받는 것은 `.bundle`이 Unity 메인 target에도 동시에 연결되도록 하기 위함입니다. 파일 경로는 모두 `PBXSourceTree`를 기반으로 하며, framework/정적 라이브러리는 `Source`, 단일 파일은 `Absolute`를 사용합니다.
