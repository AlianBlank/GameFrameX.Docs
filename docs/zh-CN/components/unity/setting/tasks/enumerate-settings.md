# 枚举全部配置项

通过 `SettingManager` 提供的方法,把当前已加载的所有配置项名称一次性取出来,用于配置调试、导出、批量校验或批量删除前的预览。

## 前置条件

- 已通过 `SettingComponent.SetSettingHelper` 注入实现(如 `DefaultSettingHelper` 或 `PlayerPrefsSettingHelper`),并成功调用 `Load()` 加载过配置。
- 已经能拿到 `SettingManager` 实例,常规做法是从 `GameEntry` / `SettingComponent.SettingManager` 属性读取。

## 操作步骤

1. 拿到 `SettingManager` 实例。常见入口是 `GameEntry.GetComponent<SettingComponent>().SettingManager`,或直接由 `SettingComponent` 暴露的 `GetSettingManager` 派生方法。

2. 调用 `GetAllSettingNames()` 直接拿到配置项名数组。

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingManager = GameEntry.GetComponent<SettingComponent>().SettingManager;
   string[] names = settingManager.GetAllSettingNames();

   foreach (var name in names)
   {
       UnityEngine.Debug.Log(name);
   }
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L140-L260),[ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L85-L95)

3. 若要复用已有列表(避免 GC),使用带 `List<string>` 参数的重载:

   ```csharp
   var results = new System.Collections.Generic.List<string>(settingManager.Count);
   settingManager.GetAllSettingNames(results);
   ```

   Source: [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L81-L92)

4. 结合 `HasSetting` 与 `RemoveSetting`,可以批量校验或清理:

   ```csharp
   foreach (var name in settingManager.GetAllSettingNames())
   {
       if (name.StartsWith("tmp_") && settingManager.HasSetting(name))
       {
           settingManager.RemoveSetting(name);
       }
   }
   settingManager.Save();
   ```

   Source: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs)

## 常见变体

- **使用 `List<string>` 重载**:当你在循环里反复调用枚举,或要拼接其他字符串集合时,带列表的重载可避免重复分配。
- **按前缀过滤**:配合 LINQ 或 `StartsWith` 做白名单/黑名单过滤,例如只导出 `ui_*` 开头的键。
- **配套运行时枚举器**:`DefaultSetting` 与 `PlayerPrefsSettingHelper` 自身也提供 `GetAllSettingNames()` 实现;如果绕过管理器直接读默认设置实例,接口签名一致。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 调用时抛 `Setting helper is invalid.` | 未调用 `SetSettingHelper` 或管理器尚未初始化 | 在启动时注入 `DefaultSettingHelper`/`PlayerPrefsSettingHelper` |
| 调用时抛 `Setting name is invalid.` | 传入了空字符串或 `null` | 仅对枚举返回的项进行二次访问,避免手写空名 |
| 拿到的数组为空 | 没有调用过 `Load()`,或加载失败 | 先 `Load()` 并检查返回值,再枚举 |
| 修改后没生效 | 未调用 `Save()` | 在移除/写入后调用 `settingManager.Save()` |

## 背景(可选)

`GetAllSettingNames` 在接口层定义为 `string[]` 与 `List<string>` 两个重载,具体存储由 `ISettingHelper` 实现决定(`DefaultSettingHelper` 走 `DefaultSetting` 内存字典;`PlayerPrefsSettingHelper` 走 PlayerPrefs)。管理器只是把调用转发给注入的 helper,因此枚举的范围与 `Load()` 时加载到的数据完全一致。
