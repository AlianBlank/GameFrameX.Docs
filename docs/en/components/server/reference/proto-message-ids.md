# Protocol Messages and MessageId Quick Reference

This page summarizes the `MessageId` and related constants used in the protocol layer of GameFrameX.Server, helping you quickly locate protocol numbers, module number ranges, and processing entry points when you encounter issues such as "handler not found" or "MessageId out of range".

## MessageId Routing Quick Reference

| Dimension | Value / Meaning | Source |
|------|------------|------|
| `MinModuleMessageID` | The minimum module message number delivered to the `Agent` at startup | [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L104) |
| `MaxModuleMessageID` | The maximum module message number delivered to the `Agent` at startup | [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L105) |
| `Setting.MinModuleId` | The minimum module number allowed in the server configuration (used for gateway delivery) | [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L104) |
| `Setting.MaxModuleId` | The maximum module number allowed in the server configuration | [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L105) |

> The value of `MessageId` must fall between `MinModuleMessageID` and `MaxModuleMessageID`; otherwise, `HotfixManager.GetTcpHandler` will return `null`.

## Protocol Entry and Handler Lookup

After the server receives a TCP message, it looks up the corresponding Handler in `HotfixManager` by `MessageId`:

```csharp
var handler = HotfixManager.GetTcpHandler(message.MessageId);
if (handler == null)
{
    LogHelper.Error($"找不到[{message.MessageId}][{messageObject.GetType()}]对应的handler");
    return;
}
```

Source: [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L123-L127)

In the main entry mode, the lookup is likewise performed via `messagePackage.Header.MessageId`:

```csharp
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);

}
```

## Distinction from EventId

`MessageId` (protocol layer) and `EventId` (intra-module event layer) are two different identification systems; do not mix them:

| Name | Scope | Definition Location |
|------|---------|---------|
| `MessageId` | The protocol number transmitted between the gateway / Agent | Protocol generation code ([MessageProtoHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/MessageProtoHandler.cs)) |
| `EventId` | In-process event bus / inter-module events | [EventId.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Event/EventId.cs#L34) |

## Protocol Boundaries Delivered at Gateway Startup

When `AppStartUpHotfixGameByGateWay` establishes a connection with an `Agent`, it broadcasts its module number range to the other side; the `Agent` will only forward requests whose `MessageId` falls within this range:

```csharp
ServerID = Setting.ServerId,
MinModuleMessageID = Setting.MinModuleId,
MaxModuleMessageID = Setting.MaxModuleId,
```

## Common Errors and Troubleshooting Entry Points

| Symptom / Original Log Text | Cause | Fix Direction |
|----------------|------|---------|
| `找不到[{MessageId}][{Type}]对应的handler` | The `MessageId` is not registered, or falls outside the module number range | Confirm that `Setting.MinModuleId` / `MaxModuleId` covers this protocol |
| `Agent` reports message number out of range | The `Min/MaxModuleMessageID` delivered by the gateway does not match the Agent configuration | Check both `Setting.MinModuleId` / `MaxModuleId` |
| Client cannot connect / receives illegal messages | `MessageId` is mistakenly used as `EventId` | Refer to the previous section "Distinction from EventId" |
