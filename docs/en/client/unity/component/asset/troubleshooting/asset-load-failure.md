# What to Do When Resources Fail to Load, Load Empty, or Have Incorrect Paths

When `AssetComponent.LoadAssetAsync`, `LoadAssetSync`, the various extension methods (such as `LoadPrefabAsync`/`LoadAudioAsync`), or the `AssetHandle` returned by interfaces in `AssetManager` cannot obtain a valid object, follow the steps on this page to diagnose the issue.

## Quick Diagnosis

| Symptom | Possible Cause | Fix |
|------|----------|------|
| `AssetHandle.AssetObject` is `null`, or `GetAssetObject<T>()` returns `null` | Incorrect resource path / resource not packaged / asset package not initialized | See the fix steps in "Asset Package Not Initialized" and "Incorrect Path" |
| Fatal log `Asset manager is invalid.` | `_assetManager` not obtained (missing module or type not registered) | See "Asset Manager Not Ready" |
| Loading fails on WebGL | `EPlayMode` not switched to `WebPlayMode` | See "Play Mode Mismatch" |
| Loads successfully in editor but fails after publishing | Play mode mismatch (e.g., still `EditorSimulateMode`) | See "Play Mode Mismatch" |
| In the async load completion callback, `handle.Status` does not equal `Succeed` | Resource does not exist / type mismatch / network download failed | See "Incorrect Path" and "Type Mismatch" |
| Object returned but has empty material / missing texture | Resource dependencies not packaged, or sub-resources not loaded with `LoadSubAssetsAsync` | See "Dependencies and Sub-Resources" |

## Fix Steps

### Asset Package Not Initialized

`AssetComponent.Awake` only sets the play mode; the actual initialization is performed by `Start` calling `_assetManager.Initialize()`; and each specific asset package needs to be explicitly initialized via `InitPackageAsync` before it becomes available. Loading resources from an uninitialized package will yield an empty handle.

```csharp
// When the asset component first starts, run initialization once for each asset package to be used
bool ok = await GameEntry.GetComponent<AssetComponent>()
    .InitPackageAsync("DefaultPackage", hostServer, fallbackHostServer, isDefaultPackage: true);
if (!ok)
{
    // Initialization failed; check whether host/fallbackHostServer configuration is correct
}
```

### Incorrect Path

The path must use the location address recorded by the YooAssets collection phase (typically `assets/...` all lowercase), and must include the file extension. Extension methods like `LoadPrefabAsync` internally call `LoadAssetAsync<GameObject>(path)`; an incorrect path will fail to retrieve the GameObject.

```csharp
// Correct: use the resource location address collected during packaging
var handle = await assetComponent.LoadPrefabAsync("assets/game/prefabs/player.prefab");
var go = handle.GetAssetObject<GameObject>();

// Wrong: written as a Unity asset path / missing extension / inconsistent case
var bad = await assetComponent.LoadPrefabAsync("Assets/Prefabs/Player"); // ❌
```

Source: [AssetComponent.Prefab.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Prefab.cs#L26-L29)

### Play Mode Mismatch

In `AssetComponent.Awake`, `GamePlayMode` is forcibly overridden in non-editor environments and on WebGL — `EditorSimulateMode` is changed to `HostPlayMode`, and `WebPlayMode` is always used for WebGL. If resources are visible in the editor but unavailable after publishing, 99% of the time it's because the mode wasn't switched correctly.

```csharp
// Explicitly specify play mode in the Inspector or in code
assetComponent.GamePlayMode = EPlayMode.HostPlayMode;
// No need to set manually for WebGL; Awake will force it to WebPlayMode
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L62-L85)

### Type Mismatch

The generic version `LoadAssetAsync<T>` filters resources by type `T`; if the actual resource is a `Texture2D` but you call `LoadAssetAsync<Sprite>(path)`, you'll get a null object. You can use the non-generic overload to get the raw object and then use `GetAssetObject<T>()` to retrieve the correct type.

```csharp
// Load via the non-generic interface after obtaining AssetInfo, to avoid guessing the type wrong
var assetInfo = YooAssets.GetAssetInfo("assets/ui/icon.png");
var handle = assetComponent.LoadAssetAsync(assetInfo);
var sprite = handle.GetAssetObject<Sprite>();
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L357-L361)

### Asset Manager Not Ready

In `AssetComponent.Awake`, if `GameFrameworkEntry.GetModule<IAssetManager>()` returns `null`, a fatal log `Asset manager is invalid.` is written and the method returns immediately. In this case, all subsequent `LoadAssetAsync` calls will get invalid handles — usually because `AssetComponent`'s `componentType` did not resolve to the corresponding implementation class.

```csharp
// Check inside Awake
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L83)

### Dependencies and Sub-Resources

Sprites inside SpriteAtlas, sub-sprites in atlases, and textures referenced by Materials are all dependencies or sub-resources. You cannot fetch dependency objects after the main resource is loaded. You need to:

- Load the main resource and its dependencies together: use `LoadSubAssetsAsync<T>(path)`, or pack the dependencies into the same package so YooAssets collects them automatically.
- Get sub-sprites from an atlas: use `LoadSubAssetsAsync<Sprite>(atlasPath)`, then retrieve them by name from the `SubAssetsHandle`.

```csharp
var subHandle = await assetComponent.LoadSubAssetsAsync<Sprite>("assets/ui/atlas/mainAtlas.png");
foreach (var sprite in subHandle.AllAssetObjects)
{
    // Each sub asset is a Sprite
}
```

## Verification

Verify whether the issue is resolved in the following order:

1. Print the type and name of the object on `AssetHandle.AssetObject` returned by `LoadAssetAsync` to confirm it is the expected object.
2. Check whether `handle.Status` is `Succeed`; if not, `handle.LastError` will provide the original error message from YooAssets.
3. Confirm the value of `AssetComponent.GamePlayMode` on the target platform (simulation mode in editor; should be `WebPlayMode` on WebGL).
4. Search for this path in the YooAssets AssetBundle Collector to confirm it belongs to an initialized asset package and has been built into the current version.
