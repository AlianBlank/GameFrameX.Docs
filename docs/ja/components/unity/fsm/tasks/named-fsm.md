# 名前付き FSM の作成方法(同タイプの複数インスタンス)

同一の所有者タイプに対して互いに独立した複数のステートマシンが必要な場合(たとえば、シーン内に複数の NPC がそれぞれ AI を実行する、複数の弾道がそれぞれ独自の状態フローで動作する場合)、`CreateFsm` の**名前付きオーバーロード**を使用し、異なる `name` でインスタンスを区別し、`GetFsm<T>(name)` / `DestroyFsm<T>(name)` で名前によってアクセスします。

## 前提条件

- `com.gameframex.unity.fsm` パッケージがインストール済みで、`FsmComponent` により `FsmManager` が起動されていること(詳細は《Fsm 概要》を参照)。
- 所有者タイプに対して複数の `FsmState<T>` サブクラスが定義済みであること。

## 操作手順

1. **`CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` を使用して名前付き FSM を作成する**。同名の FSM を重複して作成すると `GameFrameworkException("Already exist FSM '{0}'.")` がスローされるため、各インスタンスの `name` は一意でなければなりません。

```csharp
using GameFrameX.Fsm.Runtime;

// owner には異なるオブジェクト、または同一タイプの異なるインスタンスを使用可能
var npcAi1 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_001", new MyNpc(), idleState, patrolState, attackState);

var npcAi2 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_002", new MyNpc(), idleState, patrolState, attackState);
```

Source: [FsmManager.cs#L319-L330](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L319-L330)

2. **名前を指定して FSM を取得し、起動する**。名前なしのオーバーロード `GetFsm<T>()` は同一所有者タイプの「デフォルト」の FSM のみを返すため、名前付き FSM は必ず `GetFsm<T>(string name)` を使用する必要があります。

```csharp
var fsm = GameEntry.GetModule<IFsmManager>().GetFsm<MyNpc>("NPC_001");
fsm.Start<PatrolState>();
```

Source: [FsmManager.cs#L239-L242](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L239-L242)

3. **名前を指定して確認または破棄する**。`HasFsm<T>(name)` / `DestroyFsm<T>(name)` は作成と一対一で対応します。オブジェクト破棄前に `DestroyFsm` を呼び出してください。さもないと `FsmManager` 内のディクショナリが無効な参照を保持してしまいます。

```csharp
var mgr = GameEntry.GetModule<IFsmManager>();
if (mgr.HasFsm<MyNpc>("NPC_001"))
{
    mgr.DestroyFsm<MyNpc>("NPC_001");
}
```

Source: [FsmManager.cs#L182-L186](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L182-L186) · [FsmManager.cs#L397-L401](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L397-L401)

4. **`FullName` でデバッグ時の特定を行う**。`FsmBase.FullName` は `TypeNamePair` の文字列を返すため、ログで複数のインスタンスを区別するのに使用できます。

```csharp
Debug.Log(npcAi1.FullName); // 例: "MyNpc(NPC_001)"
```

Source: [FsmBase.cs#L67-L70](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs#L67-L70)

## よくあるバリエーション

**List 形式の状態集合**:同じ命名規則が `CreateFsm<T>(string name, T owner, List<FsmState<T>> states)` オーバーロードにも適用されます。

```csharp
var states = new List<FsmState<MyNpc>> { idleState, patrolState, attackState };
GameEntry.GetModule<IFsmManager>().CreateFsm<MyNpc>("NPC_003", new MyNpc(), states);
```

Source: [FsmManager.cs#L354-L365](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L354-L365)

**`Type` でアクセスする(ジェネリック不使用)**:`GetFsm(Type ownerType, string name)` / `HasFsm(Type ownerType, string name)` / `DestroyFsm(Type ownerType, string name)` を使用して、`Type` 情報しか持たないシーンでも操作可能です。

## よくあるエラー

| 現象 | 原因 | 回避策 |
|------|------|------|
| `Already exist FSM 'MyNpc(NPC_001)'` | 同名の FSM が既に存在する。名前なしオーバーロードはデフォルトで `name = string.Empty` となるため、名前なし呼び出し同士が互いに排他になる | 各インスタンスに一意の `name` を使用する。古いものを破棄してから作成する |
| `GetFsm<MyNpc>()` で `null` が返される | `name` を渡さない場合、空の名前の FSM のみがマッチする | `GetFsm<MyNpc>("NPC_001")` を使用する |
| `Owner type is invalid` | `Type` オーバーロード使用時に `null` を渡した | 呼び出し前に `null` でないことを確認する |
