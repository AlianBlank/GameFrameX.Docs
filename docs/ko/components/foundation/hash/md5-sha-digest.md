# MD5/SHA1/SHA256/SHA512을 사용하여 다이제스트를 계산하는 방법

`GameFrameX.Foundation.Hash` 네임스페이스의 `HashHelper` 통합 진입점을 통해 한 줄의 코드로 문자열, 바이트 배열, 스트림 또는 파일의 MD5 / SHA1 / SHA256 / SHA512 다이제스트를 계산하고 소문자 16진수 문자열을 반환할 수 있습니다.

## 사전 조건

- `GameFrameX.Foundation.Hash` 어셈블리를 참조해야 합니다.
- 대상 프레임워크가 .NET의 `System.Security.Cryptography`를 지원해야 합니다 (SHA1/SHA256/SHA512는 시스템 구현 사용).
- 기본적으로 UTF-8로 문자열을 바이트로 변환하며, 다른 인코딩이 필요한 경우 명시적으로 `Encoding`을 전달하세요.

## 작업 단계

### 1. 통합 진입점 선택 (권장)

`HashHelper.Compute`는 `HashAlgorithmKind` 열거형에 따라 요청을 해당 알고리즘 구현으로分发합니다. 시그니처는 아래 표와 같습니다.

| 시그니처 | 적용 입력 | 설명 |
|------|---------|------|
| `Compute(HashAlgorithmKind algorithm, string input, Encoding encoding = null)` | 문자열 | 기본값 UTF-8 |
| `Compute(HashAlgorithmKind algorithm, byte[] input)` | 바이트 배열 | 16진수 문자열 반환 |
| `Compute(HashAlgorithmKind algorithm, Stream input)` | 데이터 스트림 | 동기 계산 |
| `ComputeAsync(HashAlgorithmKind algorithm, Stream input, CancellationToken ct = default)` | 데이터 스트림 | 비동기 계산 |

지원되는 알고리즘 열거형 값: `Md5`, `Sha1`, `Sha256`, `Sha512`.

```csharp
using System.Text;
using GameFrameX.Foundation.Hash;

string s = "hello";

// 문자열 → 다이제스트
string md5    = HashHelper.Compute(HashAlgorithmKind.Md5,    s);
string sha1   = HashHelper.Compute(HashAlgorithmKind.Sha1,   s);
string sha256 = HashHelper.Compute(HashAlgorithmKind.Sha256, s);
string sha512 = HashHelper.Compute(HashAlgorithmKind.Sha512, s);

// 바이트 배열 → 다이제스트
byte[] data = Encoding.UTF8.GetBytes("payload");
string hex  = HashHelper.Compute(HashAlgorithmKind.Sha256, data);

// 스트림 → 다이제스트
using FileStream fs = File.OpenRead("big.bin");
string fileSha256 = HashHelper.Compute(HashAlgorithmKind.Sha256, fs);

// 비동기 스트림
string asyncHash = await HashHelper.ComputeAsync(HashAlgorithmKind.Sha512, fs);
```

### 2. 해당 알고리즘 헬퍼 클래스 직접 호출

특정 알고리즘만 신경 쓰는 경우 열거형 분배를 건너뛰고 전용 정적 클래스를 직접 사용할 수 있습니다.

| 클래스 | 문자열 오버로드 | 바이트 배열 오버로드 | 스트림 오버로드 | 비동기 스트림 오버로드 |
|----|-----------|-------------|--------|-----------|
| `Md5Helper` | `Hash(string, Encoding = null)` | `Hash(byte[])` | `Hash(Stream)` | `HashAsync(Stream, CancellationToken)` |
| `Sha1Helper` | `ComputeHash(string, Encoding = null)` | `ComputeHash(byte[])` | `ComputeHash(Stream)` | `ComputeHashAsync(Stream, CancellationToken)` |
| `Sha256Helper` | `ComputeHash(string, Encoding = null)` | `ComputeHash(byte[])` | `ComputeHash(Stream)` | `ComputeHashAsync(Stream, CancellationToken)` |
| `Sha512Helper` | `ComputeHash(string, Encoding = null)` | `ComputeHash(byte[])` | `ComputeHash(Stream)` | `ComputeHashAsync(Stream, CancellationToken)` |

```csharp
using GameFrameX.Foundation.Hash;

string md5Hex    = Md5Helper.Hash("hello");
string sha1Hex   = Sha1Helper.ComputeHash("hello");
string sha256Hex = Sha256Helper.ComputeHash("hello");
string sha512Hex = Sha512Helper.ComputeHash("hello");
```

### 3. 알고리즘이 보안 시나리오에 적합한지 판단

`HashHelper.IsCryptographicallySecure(HashAlgorithmKind)`는 현재 알고리즘이 보안에 민감한 시나리오에 사용할 수 있는지 알려줍니다.

| 알고리즘 | 암호학적 보안 여부 |
|------|--------------|
| `Md5` | 아니요 |
| `Sha1` | 아니요 |
| `Sha256` | 예 |
| `Sha512` | 예 |

```csharp
if (!HashHelper.IsCryptographicallySecure(HashAlgorithmKind.Md5))
{
    // 비보안 검증에만 사용 (캐시 키, 중복 제거 핑거프린트 등)
}
```

### 4. 다이제스트 비교 (타이밍 공격 방지)

두 다이제스트를 비교할 때 `HashHelper`에서 제공하는 고정 시간 비교를 사용하여 타이밍 분석 공격을 방지하는 것이 좋습니다.

| 메서드 | 입력 매개변수 | 용도 |
|------|------|------|
| `FixedTimeEquals(byte[] expected, byte[] actual)` | 원본 바이트 | 해시 바이트 배열 비교 |
| `FixedTimeEqualsHex(string expectedHex, string actualHex)` | 16진수 문자열 | HEX 문자열 비교, 잘못된 형식은 `false` 반환 |
| `FixedTimeEqualsBase64(string expectedBase64, string actualBase64)` | Base64 문자열 | Base64 문자열 비교, 잘못된 형식은 `false` 반환 |

```csharp
bool ok = HashHelper.FixedTimeEqualsHex(expectedHex, actualHex);
```

## 일반적인 변형

- **파일의 SHA-256 계산**: 먼저 `File.OpenRead`로 `FileStream`을 가져온 다음 `HashHelper.Compute(HashAlgorithmKind.Sha256, stream)`을 호출합니다. `Stream`이 Seek할 수 없는 경우 후속 읽기에 영향을 주지 않도록 `ComputeAsync`를 대신 사용할 수 있습니다.
- **대용량 파일 청크 단위 읽기**: 데이터를 청크 단위로 `MemoryStream` 또는 `CryptoStream`에 쓴 다음 해당 `ComputeHash(Stream)` 오버로드에 전달합니다.
- **UTF-8이 아닌 인코딩**: 문자열 오버로드에서 명시적으로 `Encoding` 인스턴스를 전달합니다. 예: `Encoding.GetEncoding("GB18030")`.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `ArgumentNullException: input` 던져짐 | 전달된 문자열/바이트 배열/스트림이 `null`임 | 호출 전에 null 검사 수행 |
| `ArgumentOutOfRangeException: algorithm` 던져짐 | 구현되지 않은 `HashAlgorithmKind` 값을 전달함 | 열거형에서 지원하는 네 가지 값만 사용 |
| 해시 비교 시 `false`를 반환하지만 로그에 일치한다고 표시됨 | `==` 문자열 비교를 사용함. 타이밍 공격에 취약하며 대소문자 구분 | `FixedTimeEqualsHex`를 사용하고 대소문자를 통일 |
| MD5 다이제스트 길이가 32가 아님 | 잘못된 알고리즘을 사용했거나 직접 인코딩을 수행함 | `Md5Helper.Hash`는 자체적으로 32자리 소문자 16진수를 출력함 |
| `FixedTimeEqualsHex`가 항상 `false`임 | 입력이 유효한 16진수 문자열이 아님 | 먼저 `Convert.ToHexString`을 호출하여 표준 소문자 문자열 생성 |

## 배경 (선택 사항)

`HashHelper.Compute`는 내부적으로 `switch` 표현식을 통해 요청을 `Md5Helper`, `Sha1Helper`, `Sha256Helper`, `Sha512Helper`로分发하며, 각 헬퍼 클래스는 `System.Security.Cryptography`의 해당 구현을 호출하고 `Convert.ToHexString`(소문자)으로 결과를 반환합니다. MD5 및 SHA-1은 "호환성 및 비보안 검증 시나리오에만 사용"으로 표시되어 있으며, 보안과 관련된 경우 SHA-256 또는 SHA-512를 사용하세요.
