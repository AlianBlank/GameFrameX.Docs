# 如何在活躍場景變更時重新整理主相機

當活躍場景切換時，Unity 的 `Camera.main` 可能仍指向舊場景中的相機，或回傳 `null`。框架的 `SceneComponent` 會在內部自動呼叫 `RefreshMainCamera()`，將 `m_MainCamera` 重新指向當前活躍場景中標記為 `MainCamera` 的相機。您也可以在自訂時機手動觸發重新整理。

## 前置條件

- `SceneComponent` 已掛載於場景中（隨框架的 `GameEntry` 自動初始化）。
- 已透過 `GameEntry.GetComponent<SceneComponent>()` 取得元件實例。
- 目標場景中存在帶有 `MainCamera` 標籤的 `Camera`（此為 Unity 內建 `Camera.main` 的判斷標準）。

## 步驟

1. **自動重新整理：監聽場景變更結果，框架會在內部呼叫。** 當 `SetActiveScene` 成功切換活躍場景後，將自動呼叫 `RefreshMainCamera()`，並觸發 `ActiveSceneChangedEventArgs` 事件：

   ```csharp
   // 訂閱活躍場景變更事件
   EventComponent eventComponent = GameEntry.GetComponent<EventComponent>();
   eventComponent.Subscribe(ActiveSceneChangedEventArgs.EventId, OnActiveSceneChanged);

   private void OnActiveSceneChanged(object sender, GameEventArgs e)
   {
       var args = (ActiveSceneChangedEventArgs)e;
       // 此時 SceneComponent.MainCamera 已自動更新
       Camera mainCamera = GameEntry.GetComponent<SceneComponent>().MainCamera;
       // ...
   }
   ```

   來源：[Runtime/Scene/SceneComponent.cs#L383-L390](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L383-L390)

2. **手動重新整理：在自訂時機呼叫公開方法。** 直接呼叫 `RefreshMainCamera()`，其內部會將 `m_MainCamera` 重新賦值為 `Camera.main`：

   ```csharp
   SceneComponent sceneComponent = GameEntry.GetComponent<SceneComponent>();
   sceneComponent.RefreshMainCamera();

   Camera current = sceneComponent.MainCamera;
   Debug.Log($"Main camera after refresh: {(current != null ? current.name : \"null\")}");
   ```

   來源：[Runtime/Scene/SceneComponent.cs#L386-L390](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L386-L390)

3. **讀取主相機：透過唯讀屬性存取。** 快取的相機實例透過 `MainCamera` 屬性對外公開：

   ```csharp
   public Camera MainCamera
   {
       get { return m_MainCamera; }
   }
   ```

   來源：[Runtime/Scene/SceneComponent.cs#L70-L74](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L70-L74)

## 常見變化情況

- **Single 模式非同步載入視窗期間的重新整理**：由於 YooAsset 的 await 完成時機可能早於 Unity 場景的 `isLoaded=true`，`SetActiveScene` 內部的 `try/catch` 會吞掉 `ArgumentException` 並直接執行 `RefreshMainCamera()`。此時 `Camera.main` 可能仍為 `null`；這是預期行為。待 Unity 真正完成載入並自動啟用場景後，下一次 `RefreshMainCamera()` 即可取得正確結果。
  來源：[Runtime/Scene/SceneComponent.cs#L447-L478](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L447-L478)
- **自訂相機標籤**：如果您使用的相機標籤不是 `MainCamera`，請勿依賴 `RefreshMainCamera()`。請改用 `GameObject.FindWithTag`，或自行快取並寫入 `m_MainCamera`（存取需要自訂方式）。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `MainCamera` 始終為 `null` | 活躍場景中不存在帶有 `MainCamera` 標籤的 `Camera`，或相機物件尚未實例化 | 確保目標場景中存在帶有 `MainCamera` 標籤的 `Camera`；在 `LoadSceneSuccess` 之後再次呼叫 `RefreshMainCamera()` |
| 切換場景後，視圖仍使用舊相機渲染 | 僅呼叫了 `SceneManager.LoadScene`，未使用框架的 `LoadScene` 流程，因此框架不會觸發重新整理 | 使用 `SceneComponent` 的 `LoadScene` 系列方法，或手動呼叫 `RefreshMainCamera()` |
| 重複呼叫 `SetActiveScene` 擲出 `ArgumentException` | 連續切換期間，舊協程與新協程同時競爭 `SetActiveScene` | 框架內部已透過 `StopCoroutine` 處理；若您自行實作，請務必先停止舊協程，詳見 `RefreshSceneOrder` 內部的處理方式 |

## 背景

`RefreshMainCamera` 的實作僅一行：`m_MainCamera = Camera.main;`。它依賴 Unity 內建的 `Camera.main`（本質上就是 `GameObject.FindWithTag("MainCamera")`），因此重新整理是否成功完全取決於活躍場景中是否存在帶有正確標籤的 `Camera`。框架會在兩個時機自動呼叫它：成功設定活躍場景之後，以及活躍場景控柄失效時的後備處理（以避免異常污染日誌）。
