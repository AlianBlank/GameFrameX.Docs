# よくあるエラー早見表

`GameFrameX.Procedure` フローモジュールを使用する際、ほぼすべての実行時例外は同じ根本原因に起因します——**`ProcedureManager.Initialize` 呼び出し前に何らかのフロー操作を行った**ことです。以下に高频エラーを一括で列挙しますので、症状を見れば修正箇所を特定できます。

## クイック診断

| 症状（例外/ログ原文） | 原因 | 修正方法 |
|------|------|------|
| `GameFrameworkException: You must initialize procedure first.`（`CurrentProcedure`、`CurrentProcedureTime`、`StartProcedure`、`HasProcedure`、`GetProcedure` アクセス時） | 業務コードが `ProcedureManager.Initialize` 呼び出し前にフロー API を呼び出したため、内部の `m_ProcedureFsm` が `null` のまま | `ProcedureComponent` をアタッチした GameObject に `Available Procedure Type Names` と `Entrance Procedure Type Name` を設定し、コンポーネントの `Initialize` 完了後に呼び出すようにする |
| `GameFrameworkException: Procedures is invalid.`（`Initialize` 時にスロー） | `Initialize` に渡した `procedures` 配列が `null` または長さが 0 | 少なくとも 1 つの `ProcedureBase` サブクラスのインスタンスを渡す |
| `Log.Fatal("Procedure manager is invalid.")`（コンポーネントの `Awake` 段階） | フレームワークに `IProcedureManager` 実装が登録されておらず、`GameFrameworkEntry.GetModule<IProcedureManager>()` が `null` を返す | フローモジュールを含むアセンブリがプロジェクトに正しくパッケージングされ、削除されていないか確認。通常は `GameFrameXAutoComponent` により自動登録されるため、削除された場合は asmdef を確認する |
| `Log.Warning("Available procedure type names is empty. Procedure auto start skipped.")` | `ProcedureComponent.m_AvailableProcedureTypeNames` フィールドが空配列または未設定 | Inspector で少なくとも 1 つのフロー型完全名（例：`MyGame.Procedure.LaunchProcedure, MyGame`）を追加する |
| `Log.Error("Can not find procedure type '{0}'.")` | `m_AvailableProcedureTypeNames` の型完全名のスペルミス、名前空間誤り、または対象アセンブリが読み込まれていない | `Utility.Assembly.GetType` で解決可能な完全修飾名を使用し、型が実際に読み込まれたアセンブリに存在することを確認する |
| `Log.Error("Can not create procedure instance '{0}'.")` | 型は見つかったが、`ProcedureBase` のサブクラスではないか、引数なしコンストラクタが存在しない | カスタムフローは `ProcedureBase` を継承し、`public` の引数なしコンストラクタを保持する |
| `Log.Error("Entrance procedure is invalid.")` | `m_EntranceProcedureTypeName` が `m_AvailableProcedureTypeNames` のいずれとも一致しない | 入口フロー型名は `Available Procedure Type Names` のいずれかと完全一致させる必要がある |
| 実行時に `Already exist FSM.` が発生（`StartupRunner` と併用時） | 旧版の自動初期化と新版の `StartupRunner` を同時に有効にしたため、`Initialize` が 2 回呼び出される | `ProcedureComponent.m_UseStartupRunner` を `true` に設定し、`ApplicationStartupEntry + StartupRunner.Run` に初期化を任せる |

## 修正手順

### 1. 初期化前にフロー API を呼び出した場合

スロー箇所はすべて `ProcedureManager` 内の `m_ProcedureFsm` の null チェック分岐にあり、たとえば `StartProcedure<T>()` では以下の通りです：

```csharp
[Preserve]
public void StartProcedure<T>() where T : ProcedureBase
{
    if (m_ProcedureFsm == null)
    {
        throw new GameFrameworkException("You must initialize procedure first.");
    }

    m_ProcedureFsm.Start<T>();
}
```

Source: [ProcedureManager.cs#L148-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L148-L156)

`CurrentProcedure`、`CurrentProcedureTime`、`HasProcedure`、`GetProcedure` も同じ null チェックロジックを通ります：

```csharp
if (m_ProcedureFsm == null)
{
    throw new GameFrameworkException("You must initialize procedure first.");
}
```

Source: [ProcedureManager.cs#L72-L78](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L72-L78)

修正方法：`ProcedureComponent` をアタッチした後、その `Start` コルーチン内で `Initialize` と `StartProcedure` を完了させます：

```csharp
m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);

yield return new WaitForEndOfFrame();

m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
```

Source: [ProcedureComponent.cs#L164-L168](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

業務側はシーンのロード完了と `CurrentProcedure` が非 `null` を返した後、フロー切り替えを開始するようにしてください。

### 2. `Initialize` に空のフロー配列が渡された場合

```csharp
public void Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)
{
    GameFrameworkGuard.NotNull(fsmManager, nameof(fsmManager));
    GameFrameworkGuard.NotNull(procedures, nameof(procedures));
    if (procedures.Length <= 0)
    {
        throw new GameFrameworkException("Procedures is invalid.");
    }

    m_FsmManager = fsmManager;
    m_ProcedureFsm = m_FsmManager.CreateFsm(this, procedures);
}
```

Source: [ProcedureManager.cs#L130-L141](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)

修正方法：`procedures` は少なくとも 1 つ以上渡し、`ProcedureBase` を継承している必要があります：

```csharp
public abstract class ProcedureBase : FsmState<IProcedureManager>
{
    // サブクラスで OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy をオーバーライド
}
```

Source: [ProcedureBase.cs#L38-L98](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

### 3. Inspector のフロー型名の設定誤り

`ProcedureComponent.Start` は型名に基づいてリフレクションでインスタンスを作成するため、いずれかの手順が失敗すると起動が中断されます：

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

Source: [ProcedureComponent.cs#L135-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L156)

修正方法：Inspector で `名前空間.クラス名, アセンブリ名` の形式で記入し、入口名が利用可能リストに含まれていることを確認してください。含まれていない場合、以下の `Entrance procedure is invalid.` エラーが発生します：

```csharp
if (m_EntranceProcedure == null)
{
    Log.Error("Entrance procedure is invalid.");
    yield break;
}
```

Source: [ProcedureComponent.cs#L158-L162](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L158-L162)

### 4. `StartupRunner` との重複初期化

新しい起動チェーンでは、コンポーネントは初期化権を渡す必要があります：

```csharp
[SerializeField] private bool m_UseStartupRunner = false;
...
if (m_UseStartupRunner)
{
    // ApplicationStartupEntry + StartupRunner.Run が Initialize と StartProcedure を担当し、
    // このコンポーネントは Awake で IProcedureManager を登録する役割のみを持つ。新エントリとの Initialize 重複による Already exist FSM を回避する。
    yield break;
}
```

Source: [ProcedureComponent.cs#L65-L127](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L65-L127)

修正方法：`StartupRunner` を有効化する際は `Use Startup Runner` にチェックを入れ、`ApplicationStartupEntry` に統一的にスケジューリングさせましょう。

## 検証

以下の順序で各項目を確認してください。いずれかが失敗した場合は、上記表の対応する行を再確認してください：

1. 起動後、Console に `GameFrameworkException: You must initialize procedure first.` が出力されず、`ProcedureComponent.CurrentProcedure` が `null` でないこと。
2. シーン切り替えまたは再ログイン後、ログに重複した `Already exist FSM.` が出力されないこと。
3. カスタム `ProcedureBase` サブクラスの `OnEnter` で `Debug.Log` を出力し、例外で飲み込まれるのではなく実際に呼び出されることを確認する。
4. `m_AvailableProcedureTypeNames` に少なくとも 1 項目があり、`m_EntranceProcedureTypeName` がそのいずれかと完全一致していること。
