# 在編輯器中以外部 APK / 自訂目錄初始化（測試 Android 建置）

在 Unity 編輯器中透過外部 APK 檔案或自訂目錄初始化 `BlankReadAssets`，無需打包至實機即可模擬 Android StreamingAssets 的讀取行為。適用於本地除錯 AssetBundle、熱更新資源或 Android 特有的路徑邏輯。

## 前置條件

- 專案已整合 `GameFrameX.ReadAssets` 套件，且 `Runtime/BlankReadAssets.cs` 檔案存在。
- 僅在 `UNITY_EDITOR` 下生效：這兩個 API 被 `#if UNITY_EDITOR` 包裹，不會包含在裝置建置中。
- 待測試的 APK 必須是標準的 Android 套件，StreamingAssets 位於 `assets/`（Unity 預設匯出形式）。

## 操作步驟

`BlankReadAssets` 提供兩個僅限編輯器使用的進入點。請根據您的除錯目標選擇其中之一。

### 方法 A：以外部 APK 初始化

```csharp
using GameFrameX.ReadAssets.Runtime;

// 格式：Application.dataPath + "/../test.apk"
BlankReadAssets.InitializeWithExternalApk(apkPath);
```

原始碼進入點與簽名：

```csharp
[Preserve]
public static void InitializeWithExternalApk(string apkPath)
{
    BlankReadAssetsImpl.ApkMode = true;
    BlankReadAssetsImpl.Initialize(apkPath, "jar:file://" + apkPath + "!/assets/");
    s_initialized = true;
}
```

原始碼：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

此呼叫會將 `EditorImpl.ApkMode` 設為 `true`，使後續的 `FileExists` / `OpenRead` / `ReadAllBytes` / `GetFiles` 全部走 `ApkImpl`（即讀取 APK 內部的 `jar:file://...!/assets/` 路徑）。

### 方法 B：以自訂目錄初始化

```csharp
using GameFrameX.ReadAssets.Runtime;

// dataPath：檔案系統中 StreamingAssets 的上層目錄根目錄
// streamingAssetsPath：StreamingAssets 本身的實際路徑（可使用任意目錄）
BlankReadAssets.InitializeWithExternalDirectories(dataPath, streamingAssetsPath);
```

原始碼進入點與簽名：

```csharp
[Preserve]
public static void InitializeWithExternalDirectories(string dataPath, string streamingAssetsPath)
{
    BlankReadAssetsImpl.ApkMode = false;
    BlankReadAssetsImpl.Initialize(dataPath, streamingAssetsPath);
    s_initialized = true;
}
```

原始碼：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

適用於將建置好的 StreamingAssets 複製到任意目錄，然後在編輯器中直接以「檔案目錄」形式模擬讀取。

### 步驟 3：呼叫讀取 API 進行驗證

```csharp
if (BlankReadAssets.FileExists("config/game.json"))
{
    byte[] bytes = BlankReadAssets.ReadAllBytes("config/game.json");
    // 或載入 AssetBundle
    var bundle = BlankReadAssets.LoadAssetBundle("bundles/ui.bundle");
}
```

初始化旗標 `s_initialized` 在一次呼叫後會被設為 `true`，後續所有 API 將不會重新初始化。

## 常見變體

| 情境 | 建議方法 | 說明 |
|------|----------|------|
| 驗證真實 Android 建置的 StreamingAssets 讀取 | 方法 A（APK） | 路徑前綴固定為 `jar:file://<apk>!/assets/`，與實機一致 |
| 使用本地 StreamingAssets 目錄除錯 | 方法 B（自訂目錄） | `streamingAssetsPath` 指向專案 `Assets/StreamingAssets` 之外的自訂目錄 |
| 在 `Awake` 之前預熱 | 任一方法，手動呼叫 | 設定 `s_initialized = true`，後續的 `EnsureInitialized` 將不會重設模式 |

切換模式（APK ↔ 自訂目錄）時，必須再次呼叫對應的初始化方法，因為 `ApkMode` 是靜態旗標。

## 常見錯誤

- 在 Player 建置中呼叫這兩個方法：它們會被 `#if UNITY_EDITOR` 剝離，導致編譯失敗或執行階段缺少符號。
- 切換模式後忘記重新初始化：前一次呼叫的 `ApkMode` 仍為 `true`，所有讀取會繼續走 APK 分支。
- 傳入不存在的 APK 路徑給 `InitializeWithExternalApk`：`ApkImpl.Initialize` 不會主動拋出錯誤，但後續的 `FileExists` / `OpenRead` 會找不到檔案。請先使用 `File.Exists(apkPath)` 自行檢查。
- 將 `Application.streamingAssetsPath` 與 APK 內部路徑混淆：在 APK 模式下，`streamingAssetsPath` 內部會被替換為 `jar:file://...!/assets/`。請勿手動傳入 `Application.streamingAssetsPath`。

## 背景說明（選讀）

在編輯器中，`BlankReadAssetsImpl` 透過條件編譯選擇實作：`UNITY_EDITOR` 使用 `EditorImpl`，Android 使用 `ApkImpl`，其他平台使用 `LooseFilesImpl`。在 `EditorImpl` 內部，會根據 `ApkMode` 旗標決定將請求轉發至 `ApkImpl` 或 `LooseFilesImpl`，從而在編輯器行程中模擬不同平台的讀取行為。
