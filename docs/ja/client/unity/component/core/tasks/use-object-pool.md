# オブジェクトプールを使用してゲームオブジェクトを再利用する

オブジェクトプール(Object Pool)は `ObjectBase` 型のゲームオブジェクトを再利用するために使用され、`Spawn` で取り出し、`Unspawn` で回収することで、`Instantiate`/`Destroy` の繰り返しによる GC とインスタンス化コストを回避します。フレームワークは `GameFrameX.ObjectPool` 名前空間の下に `IObjectPool<T>`、`IObjectPoolManager`、`ObjectPoolComponent` などのエントリを提供します。

## 前提条件

- `ObjectPoolComponent` がアタッチされていること(メニュー `GameFrameX/Object Pool`)、フレームワーク起動時に `IObjectPoolManager` モジュールが自動的に初期化されます。
- ビジネスオブジェクトは `ObjectBase` を継承し、その抽象メソッドを実装する必要があります。
- 名前空間:`GameFrameX.ObjectPool`、`GameFrameX.Runtime`。

## 操作手順

### 1. プール化するオブジェクト型を定義する

ビジネスクラスに `ObjectBase` を継承させ、`Spawn`/`Unspawn`/`Release` の3つのライフサイクルフックをオーバーライドします:

```csharp
using GameFrameX.ObjectPool;
using UnityEngine;

public class Bullet : ObjectBase
{
    public float Speed { get; set; }

    // オブジェクトがプールから取り出されるときに呼ばれる
    protected override void OnSpawn()
    {
        gameObject.SetActive(true);
    }

    // オブジェクトがプールに戻されるときに呼ばれる
    protected override void OnUnspawn()
    {
        gameObject.SetActive(false);
    }

    // オブジェクトが実際に破棄されるときに呼ばれる
    protected override void OnRelease()
    {
        Object.Destroy(gameObject);
    }
}
```

### 2. オブジェクトプールを作成する

`ObjectPoolComponent` を通じてプールを作成します。`SingleSpawn` は同一オブジェクトが並行して複数回取り出されることを許可しないことを示し、`MultiSpawn` は許可します。`name` は省略可能で、`capacity` はプールの容量を制御し、`expireTime` はオブジェクトの有効期限を秒単位で設定します。

```csharp
using GameFrameX.Runtime;
using GameFrameX.ObjectPool;
using UnityEngine;

public class BulletSpawner : MonoBehaviour
{
    [SerializeField] private ObjectPoolComponent poolComponent;
    [SerializeField] private Bullet bulletPrefab;

    private IObjectPool<Bullet> _bulletPool;

    private void Start()
    {
        // 単一取得を許可するプールを作成、容量は 32
        _bulletPool = poolComponent.CreateSingleSpawnObjectPool<Bullet>(
            name: "BulletPool",
            capacity: 32,
            expireTime: 60f);
    }

    public Bullet SpawnBullet(Vector3 pos)
    {
        var bullet = _bulletPool.Spawn();
        if (bullet == null)
        {
            bullet = Object.Instantiate(bulletPrefab, pos, Quaternion.identity);
            bullet.Speed = 10f;
            // オブジェクトをプールに登録する、spawned=true は即座に取り出し済み状態であることを示す
            _bulletPool.Register(bullet, spawned: true);
        }
        bullet.transform.position = pos;
        return bullet;
    }

    public void DespawnBullet(Bullet bullet)
    {
        _bulletPool.Unspawn(bullet);
    }
}
```

### 3. 回収と解放

`Unspawn` はオブジェクトをプールに戻し、`ReleaseObject` は単一のオブジェクトを完全に破棄し、`Release()` はすべての解放可能なオブジェクトを解放します(期限切れオブジェクトの定期的なクリーンアップによく使用されます)。`SetLocked(obj, true)` は自動解放をスキップします。

```csharp
// 返却
bulletPool.Unspawn(bullet);

// 単一のオブジェクトを完全に破棄
bulletPool.ReleaseObject(bullet);

// すべての解放可能なオブジェクトを即座にクリーンアップ
bulletPool.Release();

// バッチで選別して解放
bulletPool.Release(10, (target, bullet) => bullet.Speed <= 0);
```

### 4. マネージャーを通じてプールを照会する

`IObjectPoolManager` は型別、名前別、条件別の照会インターフェースを公開しており、デバッグパネルやモジュール間共有に適しています:

```csharp
IObjectPoolManager mgr = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IObjectPoolManager>();
if (mgr.HasObjectPool<Bullet>("BulletPool"))
{
    var pool = mgr.GetObjectPool<Bullet>("BulletPool");
    Debug.Log($"プールオブジェクト数:{pool.Count}, 解放可能:{pool.CanReleaseCount}");
}
```

## よくあるバリエーション

| シーン | 推奨 API | 説明 |
|------|----------|------|
| 同一オブジェクトは1つの使用者のみ許可 | `CreateSingleSpawnObjectPool` | デフォルトモード、エフェクトや一時的な UI に適している |
| 同一オブジェクトを複数箇所で共有可能 | `CreateMultiSpawnObjectPool` | マテリアル、テクスチャ、ハンドル系オブジェクトに適している |
| 型と名前の二重検索 | `GetObjectPool<T>(name)` | 同じ型の複数プール(例:異なるレベル) |
| デバッグ時にすべてのプールを列挙 | `GetAllObjectPools(sort: true)` | `Priority` でソートして返す |

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `Spawn()` が常に `null` を返す | プールが空で、`Register` を呼び出して初期オブジェクトを注入していない | `Spawn()` が `null` を返した場合にオブジェクトをインスタンス化し、`pool.Register(obj, spawned: true)` を呼び出す |
| オブジェクトが繰り返しリークする | ビジネス側で `Unspawn` していない、または `Unspawn` 時に型が一致しない | 使用終了時に明示的に `Unspawn` を呼び出し、オブジェクトの型を確認する |
| 容量上限に達した後 Spawn を継続できない | プールが `Capacity` 上限に達し、複数取得が許可されていない | `Capacity` を調整するか、`CreateMultiSpawnObjectPool` に変更する |
| 自動解放が使用中のオブジェクトを消去してしまう | `SetLocked(obj, true)` が設定されていない | 使用前に `SetLocked` を呼び出してオブジェクトをロックする |

## 背景(オプション)

フレームワークはオブジェクトを `ObjectBase`(`[IReference]`)として抽象化し、`Register/Spawn/Unspawn/Release` の4つのアクションでライフサイクルを駆動します。各オブジェクトプールは独立して `Capacity`(容量上限)、`ExpireTime`(有効期限秒数)、`AutoReleaseInterval`(自動解放間隔)、`Priority`(ソート重み)を維持します。`ObjectPoolComponent` は Unity 側のエントリポイントであり、内部的に `ObjectPoolManager` に委譲して具体的なプールの作成、照会、解放戦略を実装します。コンポーネント全体の登録フローについては、《オブジェクトプールコンポーネントの初期化》を参照してください。
