# 並行限制佇列的使用方法

`ConcurrentLimitedQueue<T>` 是執行緒安全的固定長度佇列。當元素數量達到容量上限時，會依指定的策略自動捨棄元素，並可在捨棄時透過回呼通知呼叫端。

## 前置條件

- 引入 `GameFrameX.Foundation.Extensions` 命名空間。
- 可在 .NET 環境中使用（相依於 `System.Collections.Concurrent`）。

## 操作步驟

### 1. 建立指定容量的佇列

傳入最大長度，預設為 `DropOldest` 策略（佇列已滿時刪除最舊的元素並加入新元素）。

```csharp
using GameFrameX.Foundation.Extensions;

var queue = new ConcurrentLimitedQueue<int>(limit: 3);
queue.Enqueue(1);
queue.Enqueue(2);
queue.Enqueue(3);
queue.Enqueue(4); // 此時 1 會被自動刪除，佇列中剩餘 [2, 3, 4]
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L91-L110)

### 2. 選擇溢位策略

透過 `LimitedQueueOverflowStrategy` 選擇佇列已滿時的行為：

| 策略 | 行為 |
|------|------|
| `DropOldest` | 刪除最舊的元素並加入新元素（預設） |
| `DropNewest` | 捨棄新元素，佇列保持不變 |
| `RejectNewItem` | 拒絕新元素，不產生捨棄通知 |
| `Throw` | 擲出 `InvalidOperationException` |

```csharp
var queue = new ConcurrentLimitedQueue<string>(limit: 2, LimitedQueueOverflowStrategy.DropNewest);
queue.Enqueue("a");
queue.Enqueue("b");
queue.Enqueue("c"); // "c" 會被捨棄，佇列保持為 ["a", "b"]
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L245-L266)

### 3. 訂閱捨棄事件

透過 `ItemDiscarded` 回呼監看被捨棄的元素，可用於指標記錄、日誌記錄或補償處理。

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 2, LimitedQueueOverflowStrategy.DropOldest)
{
    ItemDiscarded = item =>
    {
        Console.WriteLine($"已捨棄元素 {item.Item}，原因 {item.Reason}");
    }
};
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L138-L140)

### 4. 調整容量上限

可透過設定 `Limit` 屬性或呼叫 `SetLimit` 方法動態調整容量。縮小時被刪除的元素會以 `LimitReduced` 為原因透過回呼收到通知。

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 5);
for (var i = 0; i < 5; i++) queue.Enqueue(i);

queue.SetLimit(2); // 刪除多餘的元素，回呼中的 Reason 會是 LimitReduced
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L276-L296)

### 5. 出佇列與查看

使用標準的並行佇列語意：`TryDequeue` / `TryPeek` / `ToArray` / `Clear` 皆可使用。

```csharp
if (queue.TryPeek(out var head))
{
    Console.WriteLine($"前端: {head}");
}

if (queue.TryDequeue(out var first))
{
    Console.WriteLine($"出佇列: {first}");
}
```

## 常見變化用法

- **從現有集合初始化**：使用 `new ConcurrentLimitedQueue<int>(new List<int> { 1, 2, 3 })` 或隱含轉換 `ConcurrentLimitedQueue<int> q = new List<int> { 1, 2, 3 };`，容量會自動設定為集合的大小。
- **作為 `IProducerConsumerCollection<T>` 使用**：可直接呼叫 `TryAdd` / `TryTake`，內部會使用 `TryEnqueue` / `TryDequeue`。
- **避免在回呼中操作同一個佇列**：由於 `ItemDiscarded` 是在內部鎖定之外引發，因此在回呼中進行入佇列/出佇列是安全的，但請避免長時間封鎖。

## 常見錯誤

| 錯誤 | 說明 |
|------|------|
| 以 `limit <= 0` 建構時擲出 `ArgumentOutOfRangeException` | 容量必須大於 0 |
| 傳入空集合進行建構時擲出 `ArgumentOutOfRangeException` | 集合的元素數量必須大於 0 |
| 使用 `OverflowStrategy.Throw` 時向已滿的佇列入列會擲出 `InvalidOperationException("The limited queue has reached its capacity.")` | 呼叫端必須攔截例外狀況，或使用其他策略 |
| 預期 `DropOldest` 會觸發 `ItemDiscarded`，但實際使用的是 `RejectNewItem` | `RejectNewItem` 不會產生捨棄通知 |

## 背景（選擇性）

`ConcurrentLimitedQueue<T>` 內部封裝了 `ConcurrentQueue<T>`，並使用獨立的 `_syncRoot` 保護容量計數與入佇列的溢位處理。這使得容量調整與入佇列策略的判斷能在同一個關鍵區段內以原子方式完成。底層的 `ConcurrentQueue` 本身即保證執行緒安全的元素存取。
