# UI 管理器(IUIManager)工作原理

`IUIManager` 是 GameFrameX UI 模块的总入口，负责统一管理界面组(`IUIGroup`)、界面实例池、加载/关闭流程与对外事件。本页解释它内部如何运转——从打开一个界面到回收它，调用链上发生了什么，以及各配置项的意义。

## 接口一览

`IUIManager` 定义在 [Runtime/UI/IUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIManager.cs) 中，其核心成员按职责分组如下。

| 分类 | 成员 | 作用 |
|------|------|------|
| 实例池配置 | `InstanceAutoReleaseInterval`、`InstanceCapacity`、`InstanceExpireTime`、`RecycleInterval` | 控制 UI 实例对象池的容量、过期时间、自动释放与回收节奏 |
| 动画开关 | `IsEnableUIShowAnimation`、`IsEnableUIHideAnimation` | 是否启用界面显示/隐藏动画 |
| 组管理 | `AddUIGroup`、`HasUIGroup`、`GetUIGroup`、`GetAllUIGroups` | 增/查 UI 组 |
| 界面查询 | `HasUIForm`、`GetUIForm(s)`、`GetAllLoadedUIForms`、`IsLoadingUIForm`、`IsValidUIForm` | 按序列号或资源名查界面 |
| 打开/关闭 | `OpenUIFormAsync`、`CloseUIForm`、`CloseAllLoadedUIForms`、`CloseAllLoadingUIForms` | 异步打开、关闭、批量关闭 |
| 事件 | `OpenUIFormSuccess`、`OpenUIFormFailure`、`CloseUIFormComplete` | 异步操作完成时的回调 |
| 依赖注入 | `SetObjectPoolManager`、`SetResourceManager`、`SetUIFormHelper` | 注入底层对象池、资产、辅助器 |

抽象基类 `BaseUIManager : GameFrameworkModule, IUIManager`（[Runtime/BaseUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L36-L39)）负责保存这些状态并实现通用逻辑。

## 关键内部字段

`BaseUIManager` 用以下字段追踪状态（[BaseUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L48-L114)）：

| 字段 | 用途 |
|------|------|
| `m_UIFormsBeingLoaded` | 加载中的界面（序列号 → 资源路径） |
| `m_UIFormsToReleaseOnLoad` | 加载完毕后需要立刻释放的界面 |
| `m_RecycleQueue` | 待回收的界面队列 |
| `m_RecycleInterval`、`m_RecycleTime` | 回收节奏控制（默认 60 秒） |
| `m_Serial` | 自增序列号生成器 |
| `m_AssetManager`、`m_ObjectPoolManager`、`m_UIFormHelper` | 通过 setter 注入的依赖 |

## 打开一个界面的流程

`OpenUIFormAsync` 入口在 [Runtime/BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118)。两个重载最终都委托给内部 `InnerOpenUIFormAsync`：

```csharp
public Task<IUIForm> OpenUIFormAsync<T>(string uiFormAssetPath, bool pauseCoveredUIForm, object userData, bool isFullScreen = false) where T : class, IUIForm
{
    return InnerOpenUIFormAsync(uiFormAssetPath, typeof(T), pauseCoveredUIForm, userData, isFullScreen);
}

public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}
```

Source: [Runtime/BaseUIManager.Open.cs#L100-L118](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118)

打开过程中，管理器按以下顺序工作：

1. 申请自增 `serialId`，把 `{serialId, assetPath}` 写入 `m_UIFormsBeingLoaded`。
2. 通过 `m_AssetManager` 异步加载 Prefab，加载完成事件里实例化 `IUIForm`。
3. 将实例放入所属 `IUIGroup`，根据 `pauseCoveredUIForm` 决定是否触发目标组内被覆盖界面的 `OnCover`/`OnReveal`。
4. 触发 `OpenUIFormSuccess` 事件，把 `IUIForm` 通过 `Task` 返回给调用方。
5. 任何阶段异常都会触发 `OpenUIFormFailure` 并从 `m_UIFormsBeingLoaded` 移除条目。

## 关闭一个界面的流程

`CloseUIForm` 提供按序列号、按实例、按泛型、按 `userData` 的重载，统一在 [Runtime/BaseUIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs) 中实现。流程要点：

1. 校验 `IsValidUIForm`，通过则从 `IUIGroup` 摘除。
2. 根据 `IsEnableUIHideAnimation` 决定是否播放隐藏动画。
3. 默认进入回收队列延迟回收；传 `isNowRecycle: true` 时立刻回收到对象池。
4. 回收完成后触发 `CloseUIFormComplete`。

回收队列由 `RecycleInterval`（默认 60 秒）控制节奏，到点批量回收到 `m_ObjectPoolManager` 中的 `m_InstancePool`。

## 实例对象池

`m_InstancePool` 是 `IObjectPoolManager` 下的一个对象池，对应 UI 实例的可复用缓存。`InstanceCapacity`、`InstanceExpireTime`、`InstanceAutoReleaseInterval` 三个属性直接转发到该池的对应字段（[BaseUIManager.cs#L122-L182](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L122-L182)）。

| 属性 | 转发目标 |
|------|---------|
| `InstanceAutoReleaseInterval` | `m_InstancePool.AutoReleaseInterval` |
| `InstanceCapacity` | `m_InstancePool.Capacity` |
| `InstanceExpireTime` | `m_InstancePool.ExpireTime` |

含义：池满了会按过期时间淘汰最久未使用的实例，避免频繁实例化 Prefab。

## 事件回调

三个事件在 [BaseUIManager.Open.cs#L42-L68](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L42-L68) 通过显式 `add`/`remove` 维护，便于在 IL2CPP 下保留：

- `OpenUIFormSuccess(OpenUIFormSuccessEventArgs)` — 加载并初始化成功后触发。
- `OpenUIFormFailure(OpenUIFormFailureEventArgs)` — 资源加载失败、类型不匹配、辅助器未注入等情况触发。
- `CloseUIFormComplete(CloseUIFormCompleteEventArgs)` — 关闭流程（动画、回收）全部走完时触发。

## 依赖注入顺序

`BaseUIManager` 不会自己创建 `IAssetManager`、`IObjectPoolManager`、`IUIFormHelper`，必须由调用方在调用 `Open/Close` 前通过对应 setter 注入。这三者在 `OpenUIFormAsync` 路径上必须就绪，否则 `OpenUIFormFailure` 会被立即触发。
