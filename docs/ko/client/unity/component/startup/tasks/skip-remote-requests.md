# WebGL 스탠드얼론 또는 백엔드 없는 시나리오에서 원격 요청을 건너뛰는 방법

WebGL 스탠드얼론 버전 또는 비즈니스 백엔드가 없는 시나리오에서는 `StartupOptions.SkipRemoteStartupRequests` 또는 `EPlayMode.OfflinePlayMode`를 통해 전역 정보, App 버전, 리소스 패키지 버전 등의 원격 요청을 건너뛰고 로컬 리소스 초기화로 직접 진입하여, 시작 시 네트워크 대기에 걸리거나 실패 오류가 발생하는 것을 방지할 수 있습니다.

## 사전 조건

- `StartupOptions` 에셋(`Assets > Create > GameFrameX > Startup Options`)을 이미 생성했습니다.
- 리소스 실행 모드(`GamePlayMode`)가 `EditorSimulateMode`가 아니어야 합니다. 그렇지 않으면 에디터에서는 기본적으로 전역 정보를 건너뜁니다.
- `StartupOptions` 에셋이 시작 프로세스에 주입되어 있습니다(`Startup Runner` / 부트스트랩 컴포넌트의 `SetOptions` 또는 기본 로드를 통해).

## 작업 단계

### 방안 A: 건너뛰기 스위치만 활성화(WebGL 스탠드얼론 권장)

Inspector에서 `StartupOptions` 에셋을 선택하고, **Network** 카테고리를 펼친 뒤 **Skip Remote Startup Requests**를 체크합니다.

```csharp
// Runtime/Startup/StartupOptions.cs
[Tooltip("원격 시작 요청(전역 정보, App 버전, 리소스 패키지 버전)을 건너뛸지 여부입니다. WebGL 스탠드얼론 등 백엔드가 없는 시나리오에서 활성화하면 로컬 리소스 초기화로 직접 진입합니다.")]
public bool SkipRemoteStartupRequests = false;
```

출처: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31)

코드 측에서도 런타임에 전환할 수 있습니다:

```csharp
using GameFrameX.Startup.Runtime;

var options = Resources.Load<StartupOptions>("StartupOptions");
options.SkipRemoteStartupRequests = true;
```

시작 프로세스는 `ProcedureGetGlobalInfoState.OnEnter`에서 이 스위치를 읽으며, 값이 `true`이면 원격 요청을 건너뛰고 `ProcedurePatchInit`으로 직접 진입합니다:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var options = StartupProcedureUtility.GetOptions(procedureOwner);
if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

출처: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L42-L48)

### 방안 B: 실행 모드를 Offline으로 전환

`StartupOptions.GamePlayMode`를 `EPlayMode.OfflinePlayMode`(YooAsset의 오프라인 모드, 로컬로 패키징된 리소스 사용)로 설정합니다. `ProcedureGetGlobalInfoState`는 건너뛰기 스위치보다 먼저 OfflinePlayMode를 매칭합니다:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

출처: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L35-L40)

Offline 모드에서는 이후 Patch 프로세스도 마찬가지로 숏서킷됩니다: `ProcedurePatchInit`, `ProcedureUpdateManifest`, `ProcedureUpdateStaticVersion` 모두 `OfflinePlayMode`에 대해 즉시 건너뛰기 처리를 하므로, 더 이상 원격 매니페스트를 요청하지 않습니다.

출처: [ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L36) · [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L42) · [ProcedureUpdateStaticVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateStaticVersion.cs#L49)

## 일반적인 변형

| 시나리오 | 권장 방법 | 핵심 스위치 |
|------|----------|----------|
| WebGL 스탠드얼론(YooAsset 리소스는 있으나 버전 서비스 없음) | `SkipRemoteStartupRequests = true`, `GamePlayMode`는 스탠드얼론 모드 유지 | SkipRemoteStartupRequests |
| WebGL 완전 오프라인(로컬 빌드 산출물) | `GamePlayMode = OfflinePlayMode` | GamePlayMode |
| 에디터 내 백엔드 없는 디버깅 | `GamePlayMode = EditorSimulateMode` | GamePlayMode |

세 가지 모드의 `ProcedureGetGlobalInfoState.OnEnter`에서의 매칭 순서는 다음과 같습니다: EditorSimulateMode → OfflinePlayMode → `SkipRemoteStartupRequests` → 실제 원격 요청.

## 일반적인 오류

- **Skip만 체크했는데 GamePlayMode가 여전히 온라인 모드인 경우**: 건너뛰기 스위치는 "시작 단계"의 원격 요청만 건너뜁니다. Patch 프로세스가 원격 CDN을 가리키고 있고 로컬 매니페스트가 없다면 `ProcedureUpdateManifest` / `ProcedureUpdateStaticVersion` 단계에서 계속 네트워크 응답을 기다리게 됩니다.
- **Offline 모드에서 로컬 리소스를 준비하지 않은 경우**: OfflinePlayMode는 YooAsset이 이미 `StreamingAssets`에 전체 패키지 리소스를 준비해 두었다고 가정합니다. 그렇지 않으면 이후 로드 시 "패키지를 찾을 수 없음" 또는 "매니페스트가 비어 있음" 오류가 발생합니다.
- **SO 수정 후 적용되지 않는 경우**: `StartupOptions`에 대한 런타임 수정은 시작 프로세스가 시작되기 전(컴포넌트 초기화 전)에 완료되어야 합니다. FSM이 시작된 후에 값을 할당했다면, 씬을 다시 시작하거나 `StartupRunner.Restart()`를 호출해야 합니다.
- **WebGL 교차 출처 정책이 설정되지 않은 경우**: 스탠드얼론 버전이라 하더라도 WebGL은 여전히 CORS에 올바르게 응답해야 합니다. "선택 사항인" 원격 URL을 하나 유지해야 한다면, 반드시 웹 서버에서 `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy`를 설정하거나 서버 측 프록시를 사용하십시오.

## 검증

게임을 시작하면 Console에 다음 로그 중 하나가 표시되어야 하며(선택한 방안에 따라 다름), "Loading... (x/y)"와 같은 네트워크 대기 메시지가 나타나지 않아야 합니다:

- `Skip remote startup requests option enabled, skip remote startup requests.`
- `Offline play mode, skip remote startup requests.`
- `Editor simulate mode, skip global info request.`

이후 프로세스는 로컬 리소스 초기화(UI 리소스 열기, 로컬 매니페스트 로드 등)로 직접 진입하며, 최종적으로 비즈니스 씬에 진입해야 합니다.

## 배경(선택 사항)

시작 프로세스는 기본적으로 `ProcedureGetGlobalInfoState → ProcedureGetAppVersionInfoState → ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState → ProcedurePatchInit` 순서로 실행되며, 처음 세 노드는 모두 원격으로 HTTP 요청을 보냅니다. WebGL 스탠드얼론 또는 데모 시나리오에는 사용 가능한 백엔드가 없는 경우가 많으므로, 가장 이른 노드(`ProcedureGetGlobalInfoState`)에서 일괄적으로 차단하면 무의미한 실패 재시도의 연쇄를 피하고 첫 화면 표시 시간을 단축할 수 있습니다.

시작 프로세스의 전체 아키텍처에 대해서는 《Runtime/Procedures/Startup》 디렉터리의 프로세스 소스 코드를 참조하십시오.
