# AOT 代码列表 JSON 解析失败怎么办

运行时为 `GlobalConfigComponent.AOTCodeList` 赋值时,如果字符串不是合法的 JSON 数组格式,`GlobalConfigComponent` 会通过 `Utility.Json.ToObject<List<string>>(value)` 反序列化失败并调用 `Log.Error(e)` 记录异常,导致 `AOTCodeLists` 保持为空,AOT 元数据补充失效。本页说明常见原因与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台输出 `Log.Error`,内容为 JSON 解析异常,但 `AOTCodeList` 字符串已写入 | 字符串不是合法 JSON 数组 | 用 `[ "A", "B" ]` 格式重写,见下方"修正 JSON 格式" |
| `AOTCodeLists` 始终为空列表,但无报错 | 空字符串或未触发 setter | 给字段赋一个非空 JSON 数组字符串 |
| IL2CPP/iOS 下出现 `MissingMethodException` 或 `TypeLoadException` | `AOTCodeLists` 没解析出类型/程序集名,补充元数据未生成 | 在 Inspector 的「补充程序集列表」填写完整 JSON,并确认 HybridCLR/IL2CPP 生效 |
| 含中文逗号 `,` 或单引号 `'…'` | JSON 要求双引号 + 半角逗号 | 把字符串改为标准 JSON |
| 多行、注释、尾随逗号 | JSON 不支持注释与尾逗号 | 改为单行、严格合法的字符串数组 |

## 修复步骤

### 1. 确认目标格式

源码中 setter 直接反序列化为 `List<string>`,因此字段必须是**字符串数组**的 JSON 表示。合法示例:

```json
["GameFrameX.Runtime","GameFrameX.GlobalConfig.Runtime"]
```

源码位置:

```csharp
public string AOTCodeList
{
    get { return m_aotCodeList; }
    set
    {
        m_aotCodeList = value;
        try
        {
            m_aotCodeLists = Utility.Json.ToObject<List<string>>(value);
        }
        catch (Exception e)
        {
            Log.Error(e);
        }
    }
}
```

Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L64-L79)

### 2. 修正 JSON 格式

在 Inspector 上选中挂有 `GlobalConfigComponent` 的 GameObject,找到 **「补充程序集列表」** 字段(`m_aotCodeList`),把内容改为严格的 JSON 数组:

- 必须是 `[` 开始、`]` 结束
- 元素必须用**双引号**包裹,不能使用单引号
- 元素之间用**半角逗号**加一个空格
- 不要写注释、不要留尾随逗号、不要在末尾加 `;`

Inspector 中字段名与序列化属性对应关系如下:

| Inspector 显示名 | 序列化字段 | 类型 |
|------------------|-----------|------|
| 补充程序集列表 | `m_aotCodeList` | `string`(JSON 原文) |
| 补充元数据列表 | `m_aotCodeLists` | `List<string>`(解析后,运行时只读) |

Source: [GlobalConfigComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Editor/Inspector/GlobalConfigComponentInspector.cs#L13-L14)

### 3. 通过代码设置时保证格式

如果从远端下发的配置赋值给 `AOTCodeList`,请在写入前用 `Utility.Json.ToObject<List<string>>` 先做一次验证,避免把后端脏数据塞进 setter:

```csharp
var raw = "[\"GameFrameX.Runtime\",\"GameFrameX.GlobalConfig.Runtime\"]";
globalConfig.AOTCodeList = raw; // 内部 try/catch,失败会 Log.Error
```

源码中 setter 已经对解析异常做了 `try/catch` 并 `Log.Error`,因此**不会向上抛**——但异常会被记入日志,`AOTCodeLists` 保持原值不变,这是排查「解析失败」的关键观察点。

Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L70-L78)

### 4. 确认 AOT 补充元数据链路

`AOTCodeLists` 列表里的字符串需要与项目里 HybridCLR(或同类 AOT 工具)要求补充的程序集名一一对应。如果列表能解析成功但运行时仍报 `MissingMethodException`,说明问题出在 AOT 工具链本身,而非 JSON 解析环节。

## 验证

1. 在 Inspector 修改 **「补充程序集列表」** 后,确认 **「补充元数据列表」** 立即出现与 JSON 等长的条目数。
2. 在 Editor 控制台搜索 `Log.Error` 或 `Json` 关键字,确认无解析异常输出。
3. 打包 IL2CPP/AOT 目标平台(iOS、WebGL 等)后启动,检查原先的 `MissingMethodException` 是否消失。

## 背景(可选)

`AOTCodeList` 与 `AOTCodeLists` 是「源 JSON 字符串 + 解析后缓存列表」的双字段设计,setter 把解析异常吞掉只记日志,是为了避免脏配置打断业务初始化——代价是失败容易被忽略,需通过日志与「补充元数据列表」是否填充来反向确认。
