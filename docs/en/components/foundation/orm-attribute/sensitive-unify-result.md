# How to Annotate Sensitive Fields and Custom Unified Results

Adding the `[SensitiveField]` attribute to an entity property allows the field to be automatically masked during serialization, export, and log output according to built-in strategies or custom rules; adding `[CustomUnifyResult]` to a class or method lets the framework apply the normalization (unified result) handler with the specified name to that target. This page provides the minimal working usage of both attributes along with common variants.

## Prerequisites

- Install the NuGet package `GameFrameX.Foundation.Orm.Attribute` (namespace `GameFrameX.Foundation.Orm.Attribute`).
- The .NET project uses a C# language version that supports `System.Attribute` attribute syntax.

## Steps

### 1. Annotate Sensitive Fields

Apply `[SensitiveField]` to the entity properties that need masking, and specify the masking strategy via `MaskingStrategy`:

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }

    [SensitiveField(MaskingStrategy.Email)]
    public string Email { get; set; }

    [SensitiveField(MaskingStrategy.BankCard)]
    public string BankCard { get; set; }
}
```

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

### 2. Choose a Built-in Masking Strategy

The `MaskingStrategy` enum provides 7 built-in strategies (not counting `None`), covering common sensitive data types:

| Strategy | Behavior |
|------|------|
| `None` | No masking (default value) |
| `Phone` | Keeps the first 3 and last 4 digits |
| `IdCard` | Keeps the first 6 and last 4 digits |
| `Email` | Keeps the first character and the domain |
| `BankCard` | Keeps the last 4 digits |
| `Name` | Keeps the surname |
| `Address` | Keeps province/city/district; masks the detailed address |
| `Custom` | Custom rules (combined with `KeepPrefix`/`KeepSuffix`/`CustomPattern`) |

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L132-L196)

### 3. Annotate a Custom Unified Result

Add `[CustomUnifyResult("处理器名称")]` to a class or method, and the framework will apply the corresponding normalization strategy by name (such as data format conversion, result wrapping, or exception handling):

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[CustomUnifyResult("ApiResponse")]
public class UserController
{
    public User GetUser(int id) => userService.GetById(id);
}

[CustomUnifyResult("DatabaseResult")]
public class UserRepository
{
    public List<User> GetUsers() => database.Query<User>();
}
```

## Common Variants

### Custom Prefix/Suffix Masking

When the strategy is `MaskingStrategy.Custom`, use it together with `KeepPrefix` (the number of prefix characters to keep) and `KeepSuffix` (the number of suffix characters to keep):

```csharp
[SensitiveField(MaskingStrategy.Custom, KeepPrefix = 1, KeepSuffix = 1)]
public string Nickname { get; set; }
```

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L59-L60)

### Custom Regex Masking

When more complex masking rules are needed, set `CustomPattern` to pass in a custom regular expression (effective only with the `Custom` strategy):

```csharp
[SensitiveField(MaskingStrategy.Custom, CustomPattern = "\\d{4}")]
public string CustomField { get; set; }
```

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L95-L101)

### Annotating Unified Results on Multiple Targets

`[CustomUnifyResult]` supports `AttributeTargets.All` and allows multiple annotations on the same target (`AllowMultiple = true`):

```csharp
[CustomUnifyResult("ApiResponse")]
[CustomUnifyResult("Audit")]
public class OrderController
{
    public Order GetOrder(int id) => orderService.GetById(id);
}
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentNullException`: `name` cannot be null | A `null` name is passed when constructing `[CustomUnifyResult]` | Use a non-empty string as the handler name |
| Field is not masked | `MaskingStrategy` is not specified when annotating, so it defaults to `None` | Explicitly specify the strategy, e.g., `[SensitiveField(MaskingStrategy.Phone)]` |
| Custom rules have no effect | `KeepPrefix`/`KeepSuffix`/`CustomPattern` are ignored under strategies other than `Custom` | Set `Strategy` to `MaskingStrategy.Custom` |
| Field annotation has no effect | `[SensitiveField]` is placed on a class or field rather than a property | The attribute only allows `AttributeTargets.Property` and can only be used on properties |

## Background (Optional)

`SensitiveFieldAttribute` can only be applied to properties and does not allow multiple annotations. Its purpose is "plaintext inside the database, masked outside the database" — data is stored with its original value intact and is masked according to the strategy when output externally (serialization, export, logging). `CustomUnifyResultAttribute` is a marker attribute that the framework looks up by name to apply the corresponding normalization handler. Both are declarative metadata whose behavior is interpreted by the runtime framework.
