# PathUtil API 快速參考

`PathUtil` 是 GameFrameX.ReadAssets 所提供的靜態路徑工具類別。類別內部的所有方法皆標記了 `[Preserve]`，以防止 Unity 程式碼剝離（code stripping）。它主要用於正規化相對路徑、判斷分隔符號、拼接路徑，以及將萬用字元轉換為正規表示式。

## 方法快速參考

| 名稱 | 簽章 | 說明 |
|------|-----------|-------------|
| `IsDirectorySeparator` | `bool IsDirectorySeparator(char c)` | 判斷字元是否為 `/` 或 `\` 目錄分隔符號 |
| `FixTrailingDirectorySeparators` | `string FixTrailingDirectorySeparators(string path)` | 修正路徑結尾處重複的分隔符號（保留一個分隔符號） |
| `CombineSlash` | `string CombineSlash(string a, string b)` | 以 `/` 拼接兩個路徑片段；若任一參數為 `null` 則拋出 `ArgumentNullException` |
| `NormalizeRelativePath` | `string NormalizeRelativePath(string relative, bool forceTrailingSlash = false)` | 將相對路徑正規化為以 `/` 開頭，並處理 `.` / `..` 片段 |
| `IsValidCharacter` | `bool IsValidCharacter(char c)` | 判斷字元是否為有效的檔案名稱/路徑字元 |
| `WildcardToRegex` | `Regex WildcardToRegex(string pattern)` | 將 `*` / `?` 萬用字元模式編譯為不區分大小寫的正規表示式 |

來源：[PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L9-L187)

## 例外狀況與預設行為

| 方法 | 觸發條件 | 拋出 / 回傳 |
|--------|-------------------|------------------|
| `CombineSlash` | 任一參數為 `null` | `ArgumentNullException("a")` 或 `ArgumentNullException("b")` |
| `NormalizeRelativePath` | 輸入為 `null` 或空字串 | `ArgumentException("Empty or null", "relative")` |
| `NormalizeRelativePath` | `..` 嘗試超出根目錄（沒有上層目錄） | `System.IO.IOException("Invalid path: double dot error (before " + i + ")")` |
| `NormalizeRelativePath` | 路徑包含非法字元，如 `\`、`<`、`>`、`|`、`<32`、`:`、`*`、`?` | `System.IO.IOException("Invalid characters")` |
| `IsValidCharacter` | 字元為 `\`、`<`、`>`、`|`、`<32`、`:`、`*`、`?` | 回傳 `false`，否則回傳 `true` |
| `WildcardToRegex` | 預設不區分大小寫 | 回傳前後帶有 `^...$` 錨點的 `Regex` |

來源：[PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L41-L186)

## 使用範例

### 拼接路徑

```csharp
using GameFrameX.ReadAssets.Runtime;

// 拼接後得到 "a/b"
var p1 = PathUtil.CombineSlash("a", "b");
// 拼接後得到 "a/b"
var p2 = PathUtil.CombineSlash("a/", "b");
// 當 b 以 '/' 開頭時，直接回傳 b
var p3 = PathUtil.CombineSlash("a", "/b");
```

來源：[PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75)

### 正規化相對路徑

```csharp
using GameFrameX.ReadAssets.Runtime;

// "./a/./b/../c"  → "/a/c"
var normalized = PathUtil.NormalizeRelativePath("./a/./b/../c");
// 強制結尾斜線："a/b/"  → "/a/b/"
var dirPath = PathUtil.NormalizeRelativePath("a/b", forceTrailingSlash: true);
// 以雙引號包裹的路徑也會被去除："\"a/b\""  → "/a/b"
var stripped = PathUtil.NormalizeRelativePath("\"a/b\"");
```

來源：[PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L77-L170)

### 萬用字元轉換為正規表示式

```csharp
using GameFrameX.ReadAssets.Runtime;

// "*.json" 會被編譯為 ^.*\.json$（不區分大小寫）
var regex = PathUtil.WildcardToRegex("*.json");
// 比對 ".cs" 副檔名
var csRegex = PathUtil.WildcardToRegex("*.cs");
```

來源：[PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L182-L186)

## 內部呼叫方

`PathUtil` 在 `BlankReadAssets` 的各平台實作中被用作路徑前置處理器：

| 呼叫位置 | 方法 | 用途 |
|-----------|--------|---------|
| `BlankReadAssets.ApkImpl.Read` | `NormalizeRelativePath(path)` | 正規化讀取請求路徑 |
| `BlankReadAssets.ApkImpl.ReadDirectory` | `NormalizeRelativePath(path, forceTrailingSlash:true)` | 正規化目錄路徑，並保留結尾斜線 |
| `BlankReadAssets.ApkImpl.Exists` | `NormalizeRelativePath(path, forceTrailingSlash:true)` | 正規化路徑以判斷目錄是否存在 |
| `BlankReadAssets.ApkImpl` 目錄搜尋 | `WildcardToRegex(searchPattern)` | 將 `*.xxx` 萬用字元模式轉換為篩選用的正規表示式 |
| `BlankReadAssets.LooseFilesImpl.Read` | `NormalizeRelativePath(path, forceTrailingSlash:true)` | 鬆散檔案（loose files）實作的路徑正規化 |
| `BlankReadAssets.LooseFilesImpl.ReadFileInfo` | `NormalizeRelativePath(path)` | 檔案資訊查詢的路徑正規化 |
| `BlankReadAssets.LooseFilesImpl.Exists` | `NormalizeRelativePath(path)` | 存在性檢查的路徑正規化 |

## 注意事項

- 所有公開方法皆標記了 `[Preserve]`，因此即使在啟用受控程式碼剝離（managed code stripping）的 IL2CPP 建置中，它們仍會被保留。
- `NormalizeRelativePath` 會主動在結果前面加上前導 `/`；呼叫方不應自行在前方加上根目錄符號。
- `WildcardToRegex` 會先使用 `Regex.Escape` 進行跳脫，再替換 `*`/`?`。傳入的 `.` 和 `(` 等字元會自動被跳脫為常值字元。
