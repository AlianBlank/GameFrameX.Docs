# 연결 실패 또는 연결 중단 시 대처 방법

연결 실패 또는 연결 중단 시, GameFrameX Network는 `NetworkErrorEventArgs`(`ErrorCode`, `SocketErrorCode`, `ErrorMessage` 포함)와 `NetworkConnectedEventArgs` / `NetworkClosedEventArgs` 연결 상태 이벤트를 통해 오류 코드와 `NetworkCloseReason` 종료 원인을 상위 계층에 전달합니다. 먼저 이러한 이벤트를 구독하여 오류 코드를 확인한 후, 아래 표의 오류 코드/종료 원인과 대조하여 문제를 파악하고 복구하세요.

## 빠른 진단

| 증상 (오류 코드 / 종료 원인) | 근본 원인 | 복구 방법 |
|------|------|------|
| 종료 원인이 `ConnectAddressError` | 서버 주소 또는 포트 형식 오류 (예: URL에 scheme 누락, 포트 범위 초과) | 연결 주소를 확인하세요. 아래 「주소와 포트 확인」 참고 |
| 종료 원인이 `ConnectAddressExceptionError` | 주소 파싱 중 예외 발생 (예: 잘못된 IP 문자열, DNS 실패) | 유효한 주소로 변경하고 파싱을 검증하세요. 아래 「주소와 포트 확인」 참고 |
| 오류 코드 `AddressFamilyError` | 설정된 `AddressFamily`가 주소의 실제 패밀리와 불일치 (IPv4/IPv6 불일치) | 채널의 AddressFamily를 서버 주소와 일치시키세요. 아래 「AddressFamily 확인」 참고 |
| 오류 코드 `ConnectError`, `SocketErrorCode`가 `ConnectionRefused` / `TimedOut` | 서버가 리스닝 중이 아님, 방화벽 차단 또는 네트워크 접근 불가 | 서버가 시작되었고 포트가 허용되었는지 확인 |
| 오류 코드 `SocketError` / `SendError` / `ReceiveError` | 하위 Socket에서 송수신 단계 중 오류 발생 | `SocketErrorCode`로 원인을 파악하세요. 일반적으로 상대방이 연결을 종료한 후 계속 송수신하는 경우가 많습니다 |
| 종료 원인이 `MissHeartBeat`, 오류 코드 `MissHeartBeatError` | 하트비트 시간 초과로 연결 끊김 판정 | 하트비트 간격을 조정하고 「포커스 제어 하트비트」 설정을 확인하세요. 아래 「하트비트 연결 끊김 진단」 참고 |
| 종료 원인이 `Timeout` (WebSocket) | WebSocket 연결 설정 시간 초과로 보호 종료 트리거 | ws/wss 주소와 서버 핸드셰이크 소요 시간을 확인하고, 필요시 연결 시간 초과 보호가 포함된 버전으로 업그레이드하세요 (CHANGELOG 참고) |

위의 오류 코드와 종료 원인은 모두 소스 코드에 실제로 정의된 것입니다. 전체 값은 [NetworkErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkErrorCode.cs#L38-L136)를 참고하세요:

```csharp
public static class NetworkCloseReason
{
    public const string Normal = "Normal";
    public const string Timeout = "Timeout";
    public const string Dispose = "Dispose";
    public const string ConnectClose = "ConnectClose";
    public const string ConnectAddressError = "ConnectAddressError";
    public const string ConnectAddressExceptionError = "ConnectAddressExceptionError";
    public const string MissHeartBeat = "MissHeartBeat";
}

public enum NetworkErrorCode : byte
{
    Unknown = 0,
    AddressFamilyError,
    SocketError,
    ConnectError,
    SendError,
    ReceiveError,
    SerializeError,
    DeserializePacketHeaderError,
    DeserializePacketError,
    MissHeartBeatError,
    DisposeError,
}
```

출처: [NetworkErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkErrorCode.cs#L38-L136)

## 복구 단계

### 1단계: 오류 및 종료 이벤트를 구독하여 실제 오류 코드 확인

`NetworkComponent` 초기화 시 채널 이벤트를 `m_NetworkManager`의 `NetworkConnected` / `NetworkClosed` 등의 이벤트에 브리지합니다:

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
```

출처: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L108-L110)

오류 이벤트는 세 개의 진단 필드를 포함하며, `SocketErrorCode`는 `System.Net.Sockets.SocketError`의 원시 값입니다:

```csharp
public INetworkChannel NetworkChannel { get; private set; }
public NetworkErrorCode ErrorCode { get; private set; }
public SocketError SocketErrorCode { get; private set; }
public string ErrorMessage { get; private set; }

public static NetworkErrorEventArgs Create(INetworkChannel networkChannel, NetworkErrorCode errorCode, SocketError socketErrorCode, string errorMessage)
```

출처: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L71-L104)

오류 콜백에서 `ErrorCode`, `SocketErrorCode`, `ErrorMessage` 세 값을 출력한 후, 위의 진단 표와 대조하세요.

### 주소와 포트 확인

1. 종료 원인에 `ConnectAddressError` 또는 `ConnectAddressExceptionError`가 나타나면, 먼저 주소 문자열 자체가 유효한지 확인하세요: TCP는 `IP:端口` 형식, WebSocket은 `ws://host:port` 또는 `wss://host:port` 형식을 사용합니다.
2. Unity와 같은 네트워크에 있는 머신에서 `telnet host port`(TCP) 또는 브라우저 직접 접속(WebSocket)으로 서버에 도달 가능한지 검증하세요. 연결되지 않으면 먼저 서버 리스닝 또는 방화벽 문제를 해결하세요.
3. 동일한 주소를 사용하는 여러 채널 인스턴스를 동시에 생성하여 서버가 능동적으로 거부하는 상황이 아닌지 확인하세요.

### AddressFamily 확인

`AddressFamilyError`는 설정된 주소 패밀리가 실제 주소와 일치하지 않음을 나타냅니다. 일반적으로 서버 주소가 IPv6(또는 도메인이 IPv6로 확인됨)인데 채널이 IPv4(`InterNetwork`)로 연결을 시도하는 경우에 발생합니다. 채널 초기화 시 사용하는 `NetworkAddressFamily`를 서버 주소의 실제 패밀리와 일치시키면 이 오류가 해결됩니다. 선택 가능한 패밀리 정의는 [NetworkAddressFamily.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkAddressFamily.cs)를 참고하세요.

### 하트비트 연결 끊김 진단

1. `MissHeartBeat` / `MissHeartBeatError`가 발생하면, 채널이 예상 시간 내에 하트비트 응답을 받지 못해 컴포넌트가 "하트비트 누락"으로 연결을 종료했음을 의미합니다.
2. 이 패키지는 "포커스 제어 하트비트"(앱이 백그라운드로 전환되면 하트비트 일시 중지, 포그라운드 복귀 시 재개)를 지원합니다. 백그라운드 전환/포그라운드 복귀 로직이 서버의 시간 초과 임계값과 일치하는지 확인하세요: 백그라운드에 너무 오래 있으면 서버가 시간 초과로 판정합니다.
3. 하트비트 간격 상한 또는 서버 측 시간 초과 시간을 적절히 늘린 후 다시 테스트하세요.

## 검증

- 다시 연결한 후 `NetworkConnected` 이벤트가 정상적으로 트리거되고, 일정 시간 동안 더 이상 `NetworkErrorEventArgs` 또는 `NetworkClosedEventArgs`(원인이 `Normal`이 아닌 경우)를 받지 않습니다.
- WebSocket 채널의 경우, 장시간 일시 중지(백그라운드 전환 후 포그라운드 복귀) 시 더 이상 `Timeout` 종료가 발생하지 않습니다.
- 하트비트 시나리오에서 더 이상 `NetworkMissHeartBeatEventArgs` 이벤트가 트리거되지 않습니다([NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs) 참고).

## 배경

오류와 종료는 두 개의 이벤트 체인으로 분리되어 있습니다: 순간적인 오류는 `NetworkErrorEventArgs`(세분화된 오류 코드 + 원시 `SocketError`)로 처리되고, 연결 라이프사이클은 `NetworkConnectedEventArgs` / `NetworkClosedEventArgs`(`NetworkCloseReason` 포함)로 처리됩니다. CHANGELOG에는 WebSocket 연결 시간 초과 보호, 연결 이벤트 순서, `SystemTcpNetworkChannel` 수신 실패 처리 등의 문제가 이미 수정되어 있으므로, 예상치 못한 연결 끊김이 발생하면 먼저 패키지 버전이 최신인지 확인하세요. 자세한 내용은 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md)를 참고하세요.
