# What to Do When a Timer Does Not Fire or Queries Return -1

A timer not invoking its callback, or `GetRemaining` / `GetElapsed` / `GetRepeatLeft` returning `-1`, usually falls into one of the following categories: the callback is null so `Add` fails immediately and returns 0; the timer was just registered via `Add` and has not yet been flushed into `_items` by `Update`; the repeat count is exhausted or the timer was removed via `Remove`; it was paused by `Pause` without a `Resume`; or `Time.timeScale` is 0 in `Scaled` mode. This page provides a symptom-based diagnostic table and the corresponding fix steps (the examples below assume you already hold a `TimerManager` / `ITimerManager` instance; on the Unity side, same-named methods are forwarded through `TimerComponent`).

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Add` returns 0 and the console outputs `timer callback is null, {interval},{repeat}` | The `callback` parameter is null; registration is rejected | Make sure the callback is non-null before registering; see [Fix 1](#1-add-returns-0-callback-is-null) |
| Querying `GetRemaining`/`GetElapsed`/`GetRepeatLeft` immediately after `Add` returns -1 | The timer is still in the `_toAdd` queue and is only flushed into `_items` at the end of the next `Update` | Wait one frame before querying, or check with `Exists(id)` first; see [Fix 2](#2-query-returns--1-right-after-add-timer-has-not-yet-been-flushed-by-update) |
| Querying after `AddOnce` fires once returns -1 | After `repeat` decrements to 0 the timer is deleted and removed from `_ids`; this is normal behavior | Call `Add` again if you need it to fire again; see [Fix 3](#3-repeat-count-exhausted-or-already-removed-by-remove) |
| `Exists(id)` is true but the timer never fires | `Pause(id)` was called without `Resume`; or `Scaled` mode with `Time.timeScale = 0` | Call `Resume(id)`; or switch to the default `Unscaled`; see [Fix 4](#4-paused-via-pause-and-never-resumed), [Fix 5](#5-scaled-mode-with-timetimescale-equal-to-0) |
| After registering a second timer with the same callback, the first timer's counting "restarts from zero" | The callback delegate is the dictionary key; a repeated `Add` resets it in place (`Elapsed = 0`) | Use a separate callback/lambda for each timer; see [Fix 6](#6-repeated-registration-of-the-same-callback-resets-the-timer) |
| After one callback throws an exception, subsequent callbacks never run | `TimerManager.CatchCallbackExceptions` defaults to `false`; the exception propagates directly and interrupts this round of dispatch | Set it to `true` to locate the offending callback; see [Fix 7](#7-callback-throwing-an-exception-swallows-subsequent-callbacks) |

## Fix Steps

### 1. `Add` Returns 0: Callback Is null

The full signature and failure branch of `Add` are shown below; when `callback == null` it only logs a warning and returns 0, and that ID will never fire:

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
{
    lock (Locker)
    {
        if (callback == null)
        {
            Debug.LogWarning("timer callback is null, " + interval + "," + repeat);
            return 0;
        }
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L225)

Validate the return value right after registering:

```csharp
int id = timerManager.Add(1f, 0, OnTick);
if (id == 0)
{
    // The callback is null and registration failed; you should not keep using this id here
}
```

### 2. Query Returns -1 Right After `Add`: Timer Has Not Yet Been Flushed by `Update`

A new timer first goes into `_toAdd` and is only flushed into `_items` at the end of `Update`; the query methods return a valid value only if they find a non-deleted entry in `_items`, otherwise they return -1:

```csharp
public float GetRemaining(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return -1f;
        }

        if (_items.TryGetValue(callback, out var t) && !t.Deleted)
        {
            // ...return the remaining time
        }

        // Timer is in _toAdd (not yet flushed)
        return -1f;
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L552-L575)

The flush happens as the last step of `Update`, so "register this frame, query this frame" will always yield -1:

```csharp
if (_toAdd.Count > 0)
{
    var enumerator = _toAdd.GetEnumerator();
    while (enumerator.MoveNext())
    {
        _items.Add(enumerator.Current.Key, enumerator.Current.Value);
    }

    enumerator.Dispose();
    _toAdd.Clear();
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L153-L163)

**Fix**: Move the query to the next frame (a coroutine's `yield return null`, or another per-frame callback), or check `Exists(id)` first — it checks both `_toAdd` and `_items` and returns true for timers that have "not yet been flushed".

### 3. Repeat Count Exhausted or Already Removed by `Remove`

A timer with `repeat > 0` decrements on each firing and is marked deleted once it reaches 0; on deletion the ID is removed from `_ids`, after which every ID-based query returns -1. `AddOnce` is internally just `repeat = 1` — destroyed after firing once; `repeat = 0` means infinite looping.

```csharp
if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)

**Fix**: This is by design, not a bug. Pass `repeat = 0` if you need periodic firing; a -1 after a one-shot task finishes is normal. Do not reuse the old ID — just call `Add` again to get a new one.

### 4. Paused via `Pause` and Never Resumed

`Pause(id)` sets `IsPaused = true`; from then on `Update` simply `continue`s — no time accumulates and no callbacks fire, but the timer stays in `_items` (`Exists(id)` is still true). `Resume(id)` sets `IsPaused` back to false and resumes counting:

```csharp
if (timerItem.IsPaused)
{
    continue;
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L75-L78)

**Fix**: Call `Resume(id)`; make sure no code path calls `Pause` without a matching `Resume`. You can use the Inspector or logs to check whether any timers are currently paused.

### 5. `Scaled` Mode with `Time.timeScale` Equal to 0

The time source is chosen by `TimeScaleMode`, defaulting to `Unscaled` (unaffected by `timeScale`); if you passed `TimerTimeScale.Scaled` at registration, pausing the game (`Time.timeScale = 0`) makes the delta 0, and the timer will never reach its trigger condition:

```csharp
// Select time source based on TimeScaleMode
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L80-L81)

**Fix**: For logic that must keep running while the game is paused — UI, reconnect handling, etc. — keep the default `Unscaled` and do not pass the `timeScale` parameter; pass `TimerTimeScale.Scaled` only for timers that should pause with the game.

### 6. Repeated Registration of the Same Callback Resets the Timer

Internally the callback delegate serves as the dictionary key. Calling `Add` again for a callback that already exists does not create a new timer; instead it resets it in place (`Elapsed = 0`) and reuses the old ID — which typically shows up as "the first timer inexplicably counting from scratch":

```csharp
// Re-add existing callback: update in-place
if (_items.TryGetValue(callback, out var t))
{
    UpdateTagIndex(t, tag);
    t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete);
    t.Elapsed = 0;
    t.Deleted = false;
    t.IsPaused = false;
    return t.Id;
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L236)

**Fix**: Give each timer on the same object its own method or lambda (each lambda is a distinct delegate instance); when you need to update parameters, you can deliberately leverage this "re-register to reset" behavior.

### 7. Callback Throwing an Exception Swallows Subsequent Callbacks

Callbacks are dispatched together outside the lock. `TimerManager.CatchCallbackExceptions` defaults to `false`; an exception thrown by one callback interrupts this round of the for loop, so every callback later in the same frame is skipped. Setting it to `true` catches the exception and only logs `Timer callback error > {message}`:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L172-L186)

**Fix**: While troubleshooting, set `TimerManager.CatchCallbackExceptions = true` and watch the warnings to locate the callback that throws; after fixing the root cause, restore the default to avoid swallowing exceptions.

## Verification

After applying the fixes above, confirm each item:

1. `Add` returns a non-zero ID and `Exists(id)` is true (registration succeeded, including the "not yet flushed" phase).
2. After waiting one frame, `GetRemaining(id)` / `GetElapsed(id)` no longer return -1 and their values advance over time.
3. The callback is invoked once `interval` is reached; `GetRepeatLeft(id)` returning 0 means infinite looping, and any other positive value is the remaining count.
4. After `Pause(id)`, `GetElapsed(id)` stops growing; after `Resume(id)` it grows again.
5. With `TimerManager.CatchCallbackExceptions = true` set, there are no `Timer callback error >` warnings, meaning no callback is throwing exceptions.
