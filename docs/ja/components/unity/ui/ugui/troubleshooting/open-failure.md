# UI 画面の表示に失敗した場合の対処方法

`UIManager.OpenUIForm` / `OpenUIFormAsync` を呼び出した後、画面が表示されない、例外がスローされる、失敗コールバックのみがトリガーされるなどの問題が発生した場合は、このページの方法で根本原因を迅速に特定して修正してください。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `OpenUIFormFailureEventArgs` コールバック内のエラーメッセージが `Resources.Load failed for path: <path>` | リソースパスが `BundlesDirectoryName` 配下にないため Resources 読み込みが実行されるが、パスが存在しない | 「Resources パスのリソース読み込み失敗」を参照 |
| `OpenUIFormFailureEventArgs` に `assetHandle.LastError` が含まれている | パッケージ内読み込みが実行されるが、`LoadAssetAsync` が `Failed` 状態を返す | 「パッケージ内リソース読み込み失敗」を参照 |
| 例外 `GameFrameworkException: Can not create UI form in UI form helper.` | `UGUIFormHelper.CreateUIForm` が `null` を返す | 「ロジックスクリプトの型不一致 / スクリプト未アタッチ」を参照 |
| 例外 `GameFrameworkException: Open UI form info is invalid.` | `LoadAssetSuccess/FailureCallback` 内の `openUIFormInfo` が空 | 「ハンドルとコールバックのライフサイクル異常」を参照 |
| 例外 `ArgumentNullException`(`GameFrameworkGuard.NotNull` からスロー) | 渡された `m_AssetManager` / `m_UIFormHelper` / `uiFormType` が null | 「主要パラメータが null」を参照 |
| コンソールに `UI form instance type Xxx is invalid.` と表示されるが例外はない | プレハブに `IUIForm` を継承するロジックスクリプトがアタッチされていない | 「ロジックスクリプトの型不一致 / スクリプト未アタッチ」を参照 |
| リソースプール再利用の分岐で複数の表示要求が出ても、表示されるのは 1 つだけ | シングルトン表示モード(`UseSingletonOpenMode`)がヒットし、後続の要求がマージされる | 「シングルトン表示がマージされる」を参照 |

## 修正手順

### Resources パスのリソース読み込み失敗

`InnerLoadUIFormAsync` はパスに `BundlesDirectoryName` が含まれていない場合 `Resources.Load` を使用しますが、見つからない場合は失敗メッセージを構築して返します:

```csharp
if (uiFormAssetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    var original = (GameObject)Resources.Load(assetPath);
    if (original == null)
    {
        return LoadAssetFailureCallback(assetPath, $"Resources.Load failed for path: {assetPath}", openUIFormInfo);
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L144-L155](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L144-L155)

修正方法:

1. `uiFormAssetPath + uiFormType.Name` が任意の `Resources/` ディレクトリ配下に実際に存在することを確認してください(大文字と小文字を区別)。
2. リソースが AssetBundle にある場合は、パスを `BundlesDirectoryName`(デフォルトは `Assets/AssetBundle/` またはゲームでカスタマイズされたサブディレクトリ名)を含むように変更し、パッケージ内読み込みの分岐を通るようにしてください。
3. 失敗コールバックを登録して具体的なパスを取得してください:

```csharp
m_UIManager.OpenUIFormFailureEvent += (sender, args) =>
{
    Debug.LogError($"OpenFail [{args.UIFormAssetName}] {args.ErrorMessage}");
};
```

### パッケージ内リソース読み込み失敗

パッケージ内の分岐は `AssetManager.LoadAssetAsync` を使用し、ステータスが `Succeed` 以外の場合は失敗と見なされます:

```csharp
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(assetPath);
if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    ...
    return LoadAssetSuccessCallback(assetPath, gameObject, assetHandle.Progress, openUIFormInfo);
}
return LoadAssetFailureCallback(assetPath, assetHandle.LastError, openUIFormInfo);
```

Source: [Runtime/UIManager.Open.cs#L158-L169](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L158-L169)

修正方法:

1. `assetHandle.LastError` を確認してください。一般的な原因:AssetBundle マニフェストにこの画面が含まれていない、パッケージ化パスと読み込みパスが一致しない、依存パッケージの読み込みが完了する前に Open を呼び出している。
2. `m_AssetManager` が初期化されていることを確認してください(「主要パラメータが null」を参照)。
3. 起動フローで AssetBundle マニフェストの解析が完了するまで待ってから、表示要求を発行してください。

### ロジックスクリプトの型不一致 / スクリプト未アタッチ

`UGUIFormHelper.CreateUIForm` は、インスタンスが `GameObject` ではない、または `IUIForm` スクリプトがアタッチされていない場合に `null` を返し、その後の `InternalOpenUIForm` で `Can not create UI form in UI form helper.` がスローされます:

```csharp
var componentType = uiGameObject.GetOrAddComponent(uiFormType);
if (!(componentType is IUIForm uiForm))
{
    Log.Error($"UI form instance type {uiFormType} is invalid.");
    return null;
}
```

Source: [Runtime/UGUIFormHelper.cs#L91-L105](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L91-L105)

修正方法:

1. 失敗時の Preload の動作:Preload は引き続き画面を作成し OnAwake を実行するため、ロジックスクリプトが初期化されていないデータに依存しないことを確認してください。
2. Preload のリソースパスと表示パスが完全に一致していることを確認してください。異なる場合は、2 つのプールが異なるプレハブを指してしまいます。

### ハンドルとコールバックのライフサイクル異常

`LoadAssetSuccessCallback` / `LoadAssetFailureCallback` が受け取る `openUIFormInfo` が空の場合、`Open UI form info is invalid.` がスローされます。この情報は `UIFormLoadingObject.Create` によって `InnerOpenUIFormAsync` 内で作成されます:

```csharp
UIFormLoadingObject uiFormLoadingObject = UIFormLoadingObject.Create(uiFormAssetPath, uiFormAssetName, uiFormType, uiForm);
m_LoadingUIForms.Add(uiFormLoadingObject);
```

Source: [Runtime/UIManager.Open.cs#L108-L110](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L108-L110)

この種の例外は通常、カスタム `UIFormHelper` が規約に従って `OpenUIFormInfo` を構築していない場合に発生します。必要でない限り、リソース読み込みコールバックを上書きしないでください。

### 主要パラメータが null

`InnerOpenUIFormAsync` のエントリで主要フィールドに対して `GameFrameworkGuard.NotNull` チェックが行われ、いずれかが空の場合、すぐに `ArgumentNullException` がスローされます:

```csharp
GameFrameworkGuard.NotNull(m_AssetManager, nameof(m_AssetManager));
GameFrameworkGuard.NotNull(m_UIFormHelper, nameof(m_UIFormHelper));
GameFrameworkGuard.NotNull(uiFormType, nameof(uiFormType));
```

Source: [Runtime/UIManager.Open.cs#L72-L74](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L72-L74)

修正方法:

1. `OpenUIForm` を呼び出す前に、`UIManager` の初期化が完了していることを確認してください(フレームワークの `GameFramework` 起動フロー)。
2. 呼び出し側が渡す `Type` は null でなく、`IUIForm` を実装している必要があります。
3. `UIFormHelper` を置き換えた場合は、それが `UIManager` に登録されていることを確認してください。

## 検証

修正後、最小限のテストケースで検証してください:

```csharp
var form = await m_UIManager.OpenUIFormAsync<MyUIFomLogic>("Assets/AssetBundle/UI/");
if (form == null)
{
    Debug.LogError("Open failed, see OpenUIFormFailureEvent for details.");
}
```

確認事項:

- `OpenUIFormSuccessEvent` がトリガーされ、コールバック内で `duration > 0` であること。
- 失敗イベントが再発せず、対象の画面が UI カメラに表示されること。
- `IsLoadingUIForm(assetName)` が `false` を返し、`GetUIForm(assetName)` が非 null のインスタンスを返すこと。## シングルトン表示がマージされる

画面クラスが `[OptionUIGroup]` を使用するか、フレームワークによってシングルトン表示モード(`UseSingletonOpenMode`)と判定された場合、同じリソース名での表示要求を繰り返すと既存のインスタンスが返され、`RefocusUIForm` がトリガーされ、新实例は作成されません:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L77-L97](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L77-L97)

修正方法:

1. 毎回新实例を作成することを期待する場合は、このモードのシングルトンマーカーをオフにするか、ビジネス層でインスタンスのライフサイクルを自行管理してください。
2. 並行した表示要求は同じ読み込み Task にマージされ、同じ読み込み結果を待ちます:

```csharp
foreach (var loadingUIForm in m_LoadingUIForms)
{
    if (loadingUIForm.UIFormAssetPath == uiFormAssetPath &&
        loadingUIForm.UIFormAssetName == uiFormAssetName &&
        loadingUIForm.UIFormType == uiFormType)
    {
        return await loadingUIForm.Task;
    }
}
```

Source: [Runtime/UIManager.Open.cs#L88-L96](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L88-L96)

並行した 2 回目の表示要求は新しい失敗コールバックをトリガーせず、最初の要求の失敗/成功イベントのみがトリガーされます。
