# 界面层级/深度异常怎么办

界面层级/深度异常通常表现为:打开新界面时被旧界面遮挡、同一界面组内多个界面互相穿插显示、模态弹窗被底层穿透、3D 场景物件穿透到 UI 之上。本页按症状给出对应的诊断与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 新打开的界面被之前的界面盖住，看不到 | 新界面被加入 UI 组时,组深度 `Depth` 没有变化,Camera 在 `ScreenSpaceCamera` 模式下被旧组遮挡 | 见下文「深度值未生效」 |
| 同组内多个界面互相穿插,层级关系错乱 | UGUI 用 `localPosition.z = depth * 1000` 作为伪深度,人为修改了预制体的 `localPosition.z` 把界面错位 | 见下文「界面 Z 被误改」 |
| 3D 场景物件穿透显示到 UI 之上 | UI 相机的 `clearFlags` 与 `cullingMask` 配置错误,3D 物件被渲染进 UI 层 | 见下文「3D 物件穿透 UI」 |
| 弹出框点击事件穿透到下层界面 | 根 `Canvas` 的 `overrideSorting`/`sortingOrder` 与 `GraphicRaycaster` 被破坏 | 见下文「射线穿透到下层」 |
| 打开第一个界面后,`UGUI runtime root is invalid.` 报错 | `UI` Layer 不存在,`LayerMask.NameToLayer("UI")` 返回 `-1` | 见下文「UI Layer 缺失」 |
| 同一界面关闭后再打开,层级顺序变了 | UI 组内界面顺序由 Hierarchy 中的兄弟索引决定,被其他系统改动过 | 见下文「兄弟索引被改」 |

## 修复步骤

### 深度值未生效

`UGUIUIGroupHelper.SetDepth` 是层级生效的唯一入口,签名如下:

```csharp
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

Source: [UGUIUIGroupHelper.cs#L66-L70](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

排查要点:

1. 确认 UI 是在 `UIComponent.AddUIGroup` 后由框架调用 `SetDepth`,而不是由业务层手动设置 `localPosition.z`。如果业务层把 `localPosition.z` 又改回 `0`,层级就被打回原形。
2. 确认根 `Canvas` 处于 `ScreenSpaceCamera` 模式,根相机的 `depth` 不小于场景中其他相机的 `depth`(框架默认 `uiCamera.depth = 10f`)。

### 界面 Z 被误改

界面挂载到 UI 组节点后,该节点的 `localPosition.z` 已经被框架强制写入 `depth * 1000`。任何在预制体中设置的 `localPosition.z` 都会在运行时被覆盖;反过来,如果业务层在 `OnOpen`/`OnShow` 里又把这个值写回 `0`,会出现"一会儿对、一会儿错"的闪烁。

正确做法:不要在界面脚本里碰 `transform.localPosition.z`,需要"层级内再分级"时使用子节点或新增 UI 组,而不是改 Z 值。

### 3D 物件穿透 UI

UI 相机在框架初始化时按下面的方式构造:

```csharp
uiCamera.clearFlags = CameraClearFlags.Depth;
uiCamera.cullingMask = uiLayer >= 0 ? 1 << uiLayer : uiCamera.cullingMask;
```

Source: [UGUIUIGroupHelper.cs#L159-L165](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L159-L165)

如果场景中的 3D 物件出现在了 UI 之上,通常是:

- 3D 物件所在 Layer 与 UI Layer 重名/冲突,被错误纳入 `cullingMask`。
- 3D 相机的 `depth` 大于 UI 相机的 `depth`(默认 `10f`),3D 物件后绘制但因 `clearFlags.Depth` 不清深度而"叠加"。

处理方式:把 3D 物件放到独立 Layer(例如 `Default`),不要复用 `UI` Layer。

### 射线穿透到下层

`EnsureCanvas` 中显式启用了:

```csharp
canvas.overrideSorting = true;
canvas.sortingOrder = 0;
canvasObject.GetOrAddComponent<GraphicRaycaster>();
```

Source: [UGUIUIGroupHelper.cs#L199-L212](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L199-L212)

如果在 Inspector 中手动删除了 `GraphicRaycaster`、或把 `overrideSorting` 关闭,会出现"看得见但点不到"或"点到了下层"。建议把根 Canvas 视为只读,层级问题通过新建 UI 组或子 Canvas 解决。

### UI Layer 缺失

`UGUIUIGroupHelper` 全程依赖 `LayerMask.NameToLayer("UI")`,若工程中没有名为 `UI` 的 Tag/Layer,所有相关 `Log.Error` 会触发且层级与遮罩关系全部失效。

修复:在 `Edit ▸ Project Settings ▸ Tags and Layers` 中添加 `UI` Layer(建议第 5 层),保留名称为 `UI`。

### 兄弟索引被改

UI 组内的多个界面在 Hierarchy 中以兄弟节点的形式存在,后打开的会显示在上层。如果调用方使用了 `transform.SetSiblingIndex`、`SetAsLastSibling` 等方法把某个弹窗"压回去",会出现层级闪烁。

建议:界面层级只用 `Depth`(UI 组)控制,不要在界面脚本里改兄弟索引。

## 验证

执行完修复后,按下面顺序验证:

1. 连续打开 3 个不同 UI 组下的界面,后开的应盖在先开之上。
2. 同组内打开 2 个界面,后开的应在上层且互不穿透。
3. 打开一个全屏模态弹窗,点击弹窗外的空白处不应触发底层按钮。
4. 用 Hierarchy 选中根 `UGUICanvas`,确认子节点 `localPosition.z` 依次为 `0`、`1000`、`2000`。
5. 在 Scene 视图切换到 UI 相机,确认 `cullingMask` 只勾选了 `UI` Layer。

相关入口与扩展点见 [UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs) 和 [UGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs)。
