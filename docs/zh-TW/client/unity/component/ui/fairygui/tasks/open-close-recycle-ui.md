# 開啟、關閉與回收介面

本頁講解 FairyGUI 版 `UIManager` 的介面生命週期用法:如何觸發開啟(含單例去重與實例池重用)、關閉後如何回收,以及回收不等於銷毀時該注意什麼。對外開啟/關閉入口繼承自 GameFrameX.UI 套件的 `BaseUIManager`,本儲存庫(外掛)透過覆寫 `InnerOpenUIFormAsync` 與 `RecycleUIForm` 完成 FairyGUI 的具體實作。

## 前置條件

- 場景中已存在 `FairyGUIPackageComponent` 元件。`UIManager.SetResourceManager` 在設定資源管理器時會執行 `GameEntry.GetComponent<FairyGUIPackageComponent>()`,並以 `GameFrameworkGuard.NotNull` 驗證,缺失會直接拋出錯誤:

```csharp
public override void SetResourceManager(IAssetManager assetManager)
{
    base.SetResourceManager(assetManager);
    FairyGuiPackage = GameEntry.GetComponent<FairyGUIPackageComponent>();
    GameFrameworkGuard.NotNull(FairyGuiPackage, nameof(FairyGuiPackage));
}
```

Source: [UIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs#L87-L92)

- 回收間隔有下限:建構函式中 `m_RecycleInterval` 小於 10 時強制設為 10(秒),即介面實例在池中最少保留 10 秒後才可能被真正釋放。
- 介面邏輯類別繼承自 `FUI`(它繼承自 `UIForm`),透過 `GObject` 屬性存取 FairyGUI 物件。

## 操作步驟：開啟介面

1. 以非同步方式請求開啟介面，`InnerOpenUIFormAsync` 是所有開啟請求的匯聚點，簽章為：

```csharp
protected override async Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L64-L64)

2. 若該介面類型啟用了單例開啟模式(`UseSingletonOpenMode(uiFormType)`),已開啟則直接重用並重新聚焦，正在載入中則等待同一個任務，不會重複實例化：

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }

    foreach (var value in m_LoadingUIForms)
    {
        if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
        {
            return await value.Task;
        }
    }
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L85)

3. 未命中單例分支時，先嘗試從實例池取回(`m_InstancePool.Spawn(uiFormAssetName)`),命中則直接以新序號 `InternalOpenUIForm` 完成開啟，完全不經過資源載入：

```csharp
var uiFormInstanceObject = m_InstancePool.Spawn(uiFormAssetName);

if (uiFormInstanceObject != null)
{
    // 池重用也會分配新的請求序號，確保每次開啟請求可觀測。
    int serialId = ++m_Serial;
    return InternalOpenUIForm(serialId, uiFormAssetPath, uiFormAssetName, uiFormType, uiFormInstanceObject.Target, pauseCoveredUIForm, false, 0f, userData, isFullScreen);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L87-L94)

4. 池中也沒有時進入 `InnerLoadUIFormAsync`:從資源路徑擷取套件名稱，若 FairyGUI 套件尚未載入則按來源載入——`Resources` 目錄用 `FairyGuiPackage.AddPackageSync(assetPath)` 同步載入；Bundle 路徑用 `FairyGuiPackage.AddPackageAsync` 非同步載入，再載入帶 `_fui` 後綴的介面資源：

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // 從 Resources 中載入
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

5. 載入成功後回呼 `LoadAssetSuccessCallback` 建立介面實例；載入失敗則走 `LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo)`,錯誤訊息來自 `assetHandle.LastError`。

## 操作步驟：關閉與回收

關閉介面最終會呼叫本儲存庫覆寫的 `RecycleUIForm`,其完整邏輯是：觸發 `uiForm.OnRecycle()`,再從 `Handle` 對應的 GameObject 上取 `DisplayObjectInfo`,拿到 `GComponent` 後歸還實例池；僅當 `isDispose == true` 時才額外 `ReleaseObject` 真正銷毀：

```csharp
protected override void RecycleUIForm(IUIForm uiForm, bool isDispose = false)
{
    uiForm.OnRecycle();
    var formHandle = uiForm.Handle as GameObject;
    if (!formHandle)
    {
        return;
    }

    var displayObjectInfo = formHandle.GetComponent<DisplayObjectInfo>();
    if (!displayObjectInfo)
    {
        return;
    }

    var component = displayObjectInfo.displayObject.gOwner as GComponent;
    if (component == null)
    {
        return;
    }

    m_InstancePool.Unspawn(component);
    if (isDispose)
    {
        m_InstancePool.ReleaseObject(component);
    }
}
```

Source: [UIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Close.cs#L53-L79)

要點：

| 參數 | 行為 |
|------|------|
| `isDispose = false`(預設) | `Unspawn` 歸還實例池，物件保留，下次開啟直接重用 |
| `isDispose = true` | 歸還後再 `ReleaseObject` 銷毀釋放 |
| `Handle` 不是 GameObject / 缺 `DisplayObjectInfo` / `gOwner` 不是 `GComponent` | 僅呼叫 `OnRecycle()` 後提前傳回，不入池 |

## 常見變體：顯示與隱藏動畫

介面類別 `FUI` 覆寫了 `Show` / `Hide`,將 FairyGUI 物件交給處理器播放動畫；是否播放動畫由 `EnableShowAnimation` / `EnableHideAnimation` 與動畫名稱 `ShowAnimationName` / `HideAnimationName` 控制，處理器為 null 時直接回呼完成：

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}

public override void Hide(IUIFormHideHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableHideAnimation, HideAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

Source: [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L74-L105)

另一個常見變體是套件名稱與介面資源名不一致：此時會重新拼接套件路徑 `PathHelper.Combine(uiFormAssetPath, packageName)` 後再 `AddPackageAsync`,並在其後拼接 `_fui` 載入介面資源，詳見 [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L158-L178)。

## 常見錯誤

- **開啟介面時拋出 `FairyGuiPackage` 為 null 的守衛例外**:`FairyGUIPackageComponent` 未掛載或未初始化，先在場景/進入點補齊該元件再呼叫 `SetResourceManager`。
- **開啟失敗但沒看到細節**：Bundle 模式下失敗原因取自 `assetHandle.LastError`,並以 `LoadAssetFailureCallback` 收尾；排查時確認路徑中包含 `BundlesDirectoryName` 指示的 Bundle 目錄名，且套件名稱能從資源路徑正確擷取。
- **關閉後記憶體未下降**：預設 `isDispose = false` 只歸還實例池，實例在池中最少保留 `m_RecycleInterval`(下限 10 秒),這是預期行為；確實需要銷毀時以 `isDispose: true` 回收。
- **頻繁開關同一介面出現重複實例**：確認該介面類型啟用了 `UseSingletonOpenMode`;未啟用時每次開啟都會走池/載入流程，允許同時存在多份。
## 驗證

- 開啟後透過傳回的 `IUIForm` 檢查 `GObject` 是否已掛到 `FUI.GObject`,單例介面二次開啟應傳回同一實例並觸發 `RefocusUIForm`。
- 關閉後確認介面實例可從池中再次 `Spawn` 重用(預設路徑),或以 `isDispose: true` 後不可再重用(銷毀路徑)。
- 動畫路徑驗證:`Show`/`Hide` 完成回呼 `complete` 必須被呼叫，否則上層流程不會繼續。

## 背景

開啟流程分三級短路：單例去重 → 實例池重用 → 非同步載入。`m_LoadingUIForms` 清單記錄進行中的載入任務以合併並發請求，每次開啟(包括池重用)都會分配新的 `m_Serial` 序號用於觀測。回收路徑上，`FUI.InternalSetVisible` 只改可見性不發事件，真正的實例歸還/銷毀都集中在 `RecycleUIForm` 中基於 `GComponent` 與 `m_InstancePool` 完成。
