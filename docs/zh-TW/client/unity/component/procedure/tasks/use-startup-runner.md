# 如何使用 StartupRunner 接管啟動

`ProcedureComponent` 預設會在 `Start()` 中自動初始化並啟動流程；勾選 `Use Startup Runner` 後，它只會在 `Awake` 中註冊 `IProcedureManager`，實際的流程初始化與啟動則交由 `ApplicationStartupEntry` + `StartupRunner.Run` 處理，以避免「Already exist FSM」衝突。

## 前置條件

- 已安裝 GameFrameX 流程套件（`com.gameframex.unity.procedure`）。
- GameFrameX 啟動管線（`ApplicationStartupEntry` 與 `StartupRunner.Run`）已整合至專案，否則不會觸發接管流程。
- 場景中有一個掛載 `ProcedureComponent` 的 GameObject，可透過選單 `GameFrameX > Procedure` 新增。

## 步驟

1. 在場景中選取掛載 `ProcedureComponent` 的 GameObject，並在 Inspector 中勾選 `Use Startup Runner` 核取方塊（對應欄位 `m_UseStartupRunner`）。

2. 勾選後，`ProcedureComponent.Start()` 會立即 `yield break`，不會執行 `Initialize` 或呼叫 `StartProcedure`，僅保留 `Awake` 中的 `IProcedureManager` 註冊：

   ```csharp
   private IEnumerator Start()
   {
       if (m_ProcedureManager == null)
       {
           yield break;
       }

       if (m_UseStartupRunner)
       {
           // Initialize 與 StartProcedure 由 ApplicationStartupEntry + StartupRunner.Run 接管。
           // 此元件只負責在 Awake 中註冊 IProcedureManager，避免與新的入口點重複呼叫 Initialize 而回報「Already exist FSM」。
           yield break;
       }
       // ...
   }
   ```

   來源：[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L168)

3. 在 `ApplicationStartupEntry` 中透過 `StartupRunner.Run` 啟動流程：建構流程陣列並指定入口流程，最後呼叫 `IProcedureManager.Initialize` 與 `StartProcedure`。典型的呼叫形式如下（與傳統 `Start()` 模式中的內嵌程式碼一致）：

   ```csharp
   ProcedureBase[] procedures = new ProcedureBase[m_AvailableProcedureTypeNames.Length];
   for (int i = 0; i < m_AvailableProcedureTypeNames.Length; i++)
   {
       Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
       procedures[i] = (ProcedureBase)Activator.CreateInstance(procedureType);
       if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
       {
           m_EntranceProcedure = procedures[i];
       }
   }

   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   來源：[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L168)

4. 執行場景，確認啟動入口成功啟動第一個流程（例如 `ProcedurePreload`），且主控台中沒有出現任何與重複初始化相關的錯誤。

## 傳統模式與 StartupRunner 模式比較

| 模式 | 觸發位置 | 入口設定 | 適用情境 |
|------|---------|---------|---------|
| 傳統模式（未勾選核取方塊） | `ProcedureComponent.Start()` 自動觸發 | Inspector 中的 `Available Procedures` 與 `Entrance Procedure` | 單獨使用流程元件，未與統一啟動入口整合 |
| StartupRunner 模式（已勾選核取方塊） | `ApplicationStartupEntry` + `StartupRunner.Run` | 由啟動入口的執行階段程式碼決定 | 使用 GameFrameX 統一啟動入口的統一管線 |

## 常見錯誤

- **Already exist FSM**：兩種模式同時啟用，導致 `Initialize` 被呼叫兩次。解決方式：確保初始化只在其中一種模式中觸發，或保持勾選 `Use Startup Runner` 核取方塊並移除 `Start()` 中的內嵌啟動程式碼。
- **入口流程為 null**：當 `m_EntranceProcedureTypeName` 未指定有效的型別名稱時，傳統模式會印出 `Entrance procedure is invalid.` 並結束；在 StartupRunner 模式中，則需要在自己的入口程式碼中指定入口流程。
- **找不到流程型別**：當 `Utility.Assembly.GetType(...)` 回傳 null 時，會印出 `Can not find procedure type '{0}'.`。請檢查型別的完整名稱是否包含命名空間，以及組件是否已載入。

## 背景

啟用 `UseStartupRunner` 時，`Awake` 仍會透過 `GameFrameworkEntry.GetModule<IProcedureManager>()` 註冊並持有流程管理器的參考，但會將「建構流程陣列 → `Initialize` → `StartProcedure`」這三個步驟延後至 `ApplicationStartupEntry` 中的 `StartupRunner.Run` 執行，藉此讓流程啟動由統一啟動入口編排控制，得以在統一管線中與其他子系統進行序列／平行啟動。
