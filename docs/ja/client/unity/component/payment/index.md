# 動作原理:プラットフォームルーティングとコンポーネント組み立て

`PaymentComponent` は `Awake()` 内で、現在のコンパイルプラットフォームの Unity マクロに基づいて決済マネージャー実装クラスの完全修飾名文字列を 1 つ選択し、リフレクションによってそれを `IPaymentManager` モジュールとして組み立てます。各プラットフォームの具体的な実装(Google、Apple、WebGL、PC)は独立したパッケージによって提供され、本リポジトリにはルーティングフレームワーク、インターフェース、およびデフォルト実装のみが含まれます。

## プラットフォームルーティング決定表

`PaymentComponent` の 5 つの `[SerializeField]` フィールドには各プラットフォームの実装クラスの完全修飾名が保存されており、Inspector で上書きできます:

```csharp
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

出典:[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L24-L28)

実行時はコンパイルマクロに基づいて、いずれか 1 つにルーティングされます:

| コンパイルマクロ | 使用フィールド | デフォルト実装クラスの完全修飾名 |
|------|------|------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `m_componentPCType` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` |
| `UNITY_STANDALONE_OSX` | `m_componentMacType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` |
| その他のプラットフォーム | なし | `typeof(DefaultPaymentManager).FullName` |

```csharp
protected override void Awake()
{
#if UNITY_ANDROID
    componentType = m_componentAndroidType;
#elif UNITY_IOS
    componentType = m_componentIOSType;
#elif UNITY_WEBGL
    componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
    componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
    componentType = m_componentMacType;
#else
    componentType = typeof(DefaultPaymentManager).FullName;
#endif
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IPaymentManager);
    base.Awake();

    _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
    if (_paymentManager == null)
    {
        Log.Fatal("Pay Manager is invalid.");
        return;
    }
}
```

## コンポーネント組み立ての流れ

起動時の組み立ては以下の順序で行われ、各ステップは上記のソースコード内で確認できます:

1. `PaymentComponent` はシーン上のオブジェクトにアタッチされる Unity コンポーネントで、`[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]` を持ち、`GameFrameworkComponent` を継承しています。
2. `Awake()` はコンパイルマクロに基づいて実装クラスの完全修飾名を 1 つ選択し、基底クラスのフィールド `componentType` に書き込みます。
3. `Utility.Assembly.GetType(componentType)` はリフレクションによって実装クラスの `Type` を解決し、`ImplementationComponentType` に代入します。`InterfaceComponentType` は `typeof(IPaymentManager)` に固定されています。
4. `base.Awake()`(GameFrameworkComponent のロジック)が、この 2 つの `Type` に基づいてモジュールインスタンスを作成/登録します。
5. `GameFrameworkEntry.GetModule<IPaymentManager>()` は組み立て済みのモジュールを取得して `_paymentManager` に保存します。取得できない場合は `Log.Fatal("Pay Manager is invalid.")` が呼び出されます。
6. その後、`PaymentComponent` のすべての公開メソッド(`Init`、`IsReady`、`Buy`、`QueryPurchases`、`ConsumePurchase` など)は、パラメータ検証を行った後、単に `_paymentManager` へ転送するだけです。

例として `Buy` の転送と検証:

```csharp
[UnityEngine.Scripting.Preserve]
public void Buy(PurchaseParams purchaseParams)
{
    if (purchaseParams == null)
    {
        Log.Warning("Purchase params is null.");
        return;
    }

    if (string.IsNullOrEmpty(purchaseParams.ProductId))
    {
        Log.Warning("Product ID is null or empty.");
        return;
    }

    if (string.IsNullOrEmpty(purchaseParams.OrderId))
    {
        Log.Warning("Order ID is null or empty.");
        return;
    }

    _paymentManager.Buy(purchaseParams);
}
```

## 実装側の契約：BasePaymentManager

各プラットフォームパッケージ(Google、Apple など)のマネージャーは `BasePaymentManager : GameFrameworkModule, IPaymentManager` を継承します。このクラスは 4 つのイベント(`OnPurchaseSuccess`、`OnPurchaseFailed`、`OnQueryPurchasesResult`、`OnConsumePurchaseResult`)を一括して宣言し、サブクラスがイベントを発生させるための `RaiseXxx(e)` protected メソッドを提供するとともに、`Init`、`IsReady` などを抽象メンバーとして宣言しています:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    [UnityEngine.Scripting.Preserve]
    protected BasePaymentManager()
    {
    }

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);

    [UnityEngine.Scripting.Preserve]
    public abstract bool IsReady();
```

出典:[BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L74)

`PaymentComponent` 上の対応する同名イベントは、`_paymentManager` のイベント(add/remove アクセサー)に直接転送されるため、上位層の購読と実装側の発生は同一のイベントソースになります:

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}
```

## ストリッピング防止：GameFrameXPaymentCroppingHelper

`PaymentComponent` は `GameFrameXPaymentCroppingHelper` と同じゲームオブジェクト上に共存する必要があります(`[RequireComponent]`)。この Helper の `Start()` は `_ = typeof(...)` によってインターフェース、デフォルト実装、パラメータ/イベントの型を強く参照し、コードストリッピングや IL2CPP ビルド時にこれらの型が削除されないことを保証します:

```csharp
[Preserve]
public class GameFrameXPaymentCroppingHelper : MonoBehaviour
{
    [Preserve]
    void Start()
    {
        _ = typeof(PaymentComponent);
        _ = typeof(BasePaymentManager);
        _ = typeof(IPaymentManager);
        _ = typeof(DefaultPaymentManager);
        _ = typeof(PurchaseParams);
        _ = typeof(PaymentEventArgs);
        _ = typeof(PaymentProductType);
        _ = typeof(PaymentResultCode);
    }
}
```

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| ログに `Pay Manager is invalid.`(Fatal)が出る | `GameFrameworkEntry.GetModule<IPaymentManager>()` が null を返す。通常はルーティング文字列に対応する実装パッケージが未インストールか、クラス名が変更されている | 対応プラットフォームの決済実装パッケージをインストールするか、Inspector でそのプラットフォームの `Type` フィールドを正しいクラスの完全修飾名に戻す |
| デフォルト実装が実行され、実際の決済が行われない | 現在のプラットフォームが 5 つのマクロ分岐のいずれにも該当しない(エディターやその他のプラットフォームなど)ため、`DefaultPaymentManager` にフォールバックしている | 期待される動作です。実機を対応プラットフォーム向けにビルドした場合のみ、具体的な実装にルーティングされます |
| ストリッピング/IL2CPP ビルド後に型が失われる | リフレクションで読み込まれる型がストリッピングされた | `GameFrameXPaymentCroppingHelper` による強参照で既に回避済み。このコンポーネントを削除しないでください |
| `Buy` を呼んでも何も反応せず、Warning ログのみが出る | `purchaseParams` が null、または `ProductId`/`OrderId` が空のため、パラメータ検証で直接 return される | `PurchaseParams` の必須フィールドを確認してから呼び出してください |

## 背景

「完全修飾名の文字列 + リフレクション」を使用して直接 `typeof(...)` としない理由は次の通りです:各プラットフォームの実装は独立したパッケージ(`com.gameframex.unity.payment.google` など)に存在し、本リポジトリのコンパイル時にはそれらを参照していません。型をハードコードするとコンパイル依存が生じますが、文字列はターゲットプラットフォームのビルド時に初めて解決されます。これにより、本パッケージを単独でリリースでき、プラットフォームパッケージは必要に応じて導入でき、また Inspector のシリアライズフィールドにより、プロジェクトはコードを変更せずに実装を差し替えることができます。
