# 機能特性

GameFrameX Web ProtoBuff コンポーネント提供基づく Protocol Buffer 的 HTTP 网络お願いします求機能，サポート异步发送和接收 ProtoBuf 消息，是 Unity ゲーム与后端服务器通信的轻量级解決策。

## 概要

Web ProtoBuff コンポーネント是 GameFrameX ゲームフレームワーク的网络模块扩展，专门に使用处理基づく **Protocol Buffer** 格式的网络通信。与传统的 JSON/XML 相比，Protocol Buffer 具有更高的序列化效率和更小的数据体积，非常适合移动ゲームシーン下的网络通信。

该コンポーネント提供します完整的お願いします求管理機能，包括お願いします求队列、超时控制、异步响应处理等特性，同时サポート Unity WebGL 平台和原生平台（PC/Android/iOS）的网络お願いします求呼び出し。

## コア機能

### 1. Protocol Buffer 消息サポート

コンポーネント原生サポート Protocol Buffer 消息格式的序列化与反序列化。お願いします求消息和响应消息都采用 ProtoBuf 格式传输，相比 JSON 可节省 30%-70% 的带宽。

消息结构采用 `MessageObject` 基クラス，配合 `[ProtoContract]` 和 `[ProtoMember]` プロパティ标记実装自动序列化：

```csharp
[ProtoContract]
public class LoginRequest : MessageObject
{
    [ProtoMember(1)]
    public string Username { get; set; }
    
    [ProtoMember(2)]
    public string Password { get; set; }
}

[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)]
    public bool Success { get; set; }
    
    [ProtoMember(2)]
    public string Token { get; set; }
}
```
> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L178-L201)

コンポーネント使用专用的 `application/x-protobuf` Content-Type 进行お願いします求，确保服务端能够正确识别 ProtoBuf 格式数据：

```csharp
private const string ProtoBufContentType = "application/x-protobuf";
```
> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L32)

### 2. 异步お願いします求处理

コンポーネント采用基づく `Task<T>` 的异步编程模式，サポート `async/await` 语法糖，使网络お願いします求代码简洁易读：

```csharp
public async void Login()
{
    var request = new LoginRequest 
    { 
        Username = "user", 
        Password = "password" 
    };
    
    string url = "http://api.example.com/login";
    
    try
    {
        LoginResponse response = await WebComponent.Post<LoginResponse>(url, request);
        
        if (response != null)
        {
            Debug.Log($"Login Result: {response.Success}, Token: {response.Token}");
        }
    }
    catch (System.Exception e)
    {
        Debug.LogError($"Request Failed: {e.Message}");
    }
}
```
> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108)

### 3. お願いします求队列管理

コンポーネント内部维护お願いします求队列，サポート并发控制和お願いします求优先级管理，确保网络お願いします求有序进行：

```mermaid
flowchart TD
    subgraph RequestFlow["お願いします求フロー"]
        Start[开始お願いします求] --> Enqueue[加入等待队列]
        Enqueue --> Check{等待队列\n有お願いします求?}
        Check -->|是| CheckLimit{当前并发数\n< 最大连接数?}
        CheckLimit -->|是| Dequeue[取出お願いします求]
        CheckLimit -->|否| Wait[等待]
        Dequeue --> Send[发送HTTPお願いします求]
        Send --> Response[接收响应]
        Response --> Complete[完成回调]
        Check -->|否| Wait2[等待]
        Wait --> Check
        Wait2 --> Check
    end
```

コア队列管理逻辑：


## 使用限制

コンポーネント的 ProtoBuf 機能必要を通じて编译宏来启用。在 Unity Player Settings 中必要添加以下宏定义：

```
ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
```

未定义此宏时，`Post<T>` メソッド将被禁用，确保不会在生产环境中意外呼び出し未配置的機能。

```csharp
#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
{
    return m_WebProtoBuffManager.Post<T>(url, message);
}
#endif
```
> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

## リソース清理

コンポーネント在关闭时会自动清理所有お願いします求リソース，防止内存泄漏：

```csharp
protected override void Shutdown()
{
    ShutdownProtoBuf();
    m_MemoryStream.Dispose();
}

private void ShutdownProtoBuf()
{
    while (m_WaitingProtoBufQueue.Count > 0)
    {
        var webData = m_WaitingProtoBufQueue.Dequeue();
        webData.Dispose();
    }
    // ... 清理发送中的お願いします求
}
```
