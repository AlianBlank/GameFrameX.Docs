# 如何實作自訂物件儲存提供者

透過實作 `IObjectStorageManager` 與 `IObjectStorageUploadManager` 兩個介面並串接 `ObjectStorageUploadFactory`,你可以在 GameFrameX 物件儲存框架裡加入任意一種新的後端(例如自建 MinIO、華為 OBS、七牛、又拍、內部檔案伺服器等)，讓上傳流程像內建提供者一樣被工廠統一調度。

## 前置條件

- 已在 Unity 專案中安裝 `com.gameframex.unity.objectstorage` 套件。
- 你要對接的後端具備：accessKey / secretKey / bucketName / endpoint 四項基本參數，並能回應標準物件儲存協定(分片/上傳/進度回呼)。
- 準備一個放置自訂提供者實作的 Editor 組件(放在任意 `Editor/` 目錄下的 `.asmdef` 中)，避免污染執行階段。

## 操作步驟

1. **建立提供者實作類別**，同時實作 `IObjectStorageManager` 和 `IObjectStorageUploadManager` 兩個介面。`IObjectStorageManager.Init` 用於接收憑證和儲存桶資訊，`IObjectStorageUploadManager` 負責實際的上傳、分片與進度回呼。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;

   namespace GameFrameX.ObjectStorage.Editor
   {
       public sealed class MyCustomObjectStorageManager
           : IObjectStorageManager, IObjectStorageUploadManager
       {
           public void Init(string accessKey, string secretKey,
                            string bucketName, string endpoint = null)
           {
               // 儲存到內部欄位,供上傳方法使用
           }

           // 實作 IObjectStorageUploadManager 的上傳方法 ...
       }
   }
   ```

   `IObjectStorageManager` 介面定義見 [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13),`Init` 方法簽章如下：

   ```csharp
   void Init(string accessKey, string secretKey, string bucketName, string endpoint = null);
   ```
   Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L12)

2. **實作上傳與進度回呼邏輯**。參考 `BaseObjectStorageUploadManager` 的職責劃分：基底類別負責通用的分片、重試、進度聚合；你的子類別只需要把「鑑權標頭建構」和「分片 PUT/POST」換成自家後端協定即可。基底類別入口在 [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)。

3. **註冊到工廠**。開啟 [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs),在工廠的建立/選擇分支裡加入你的提供者類型，使工廠可以根據組態回傳你的實作實例。

4. **在呼叫端按工廠取得**。上傳端不需要改動，透過 `ObjectStorageUploadFactory` 取得 `IObjectStorageUploadManager` 即可：

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create(providerName);
   ((IObjectStorageManager)uploader).Init(accessKey, secretKey, bucketName, endpoint);
   uploader.Upload(localPath, remoteKey, onProgress, onComplete);
   ```

## 常見變體

- **同一協定、不同廠商**：例如 AWS S3、阿里 OSS、騰訊 COS 都相容 S3 協定，可以讓一個實作類別支援多個 `endpoint`,在 `Init` 時區分簽章區域。
- **無 endpoint 的內網儲存**：把 `endpoint` 留空，實作內部根據 `bucketName` 拼湊出內網位址。
- **多憑證輪詢**：在 `Init` 裡允許傳入憑證清單，上傳時分片前自動續約 token。

## 常見錯誤

| 錯誤 | 原因 | 修正 |
|------|------|------|
| 工廠回傳的是內建提供者 | 沒有把自己的類型註冊到 `ObjectStorageUploadFactory` | 在工廠選擇分支裡加入新 provider 名 |
| `Init` 後上傳回報 401/403 | accessKey/secretKey 與 endpoint 區域不相符 | 在 `Init` 裡驗證區域並列印實際請求位址 |
| 進度永遠停在 0 | 實作類別沒把分片回呼轉換為 `IObjectStorageUploadManager` 的進度事件 | 參考 `BaseObjectStorageUploadManager` 的進度聚合點 |
| Unity 執行階段找不到類型 | 實作類別放進了執行階段組件而不是 Editor 組件 | 把程式碼放到任意 `Editor/` 目錄，並確認 `.asmdef` 包含 `Editor` 平台 |

## 背景(可選)

框架把「管理憑證」和「執行上傳」分成兩個介面:`IObjectStorageManager` 只關心憑證初始化，`IObjectStorageUploadManager` 關心實際的網路分片與進度；兩者通常由同一個類別實作，工廠根據 provider 名選出一個實例，既統一了呼叫入口，也便於替換後端。
