# コードストリッピングによるインターフェース消失の回避方法

Unity はパッケージビルド時にマネージドコードストリッピング（Managed Code Stripping）を実行し、IL2CPP コンパイル後に未参照の型、メソッド、プロパティを削除します。業務コードがリフレクション、文字列、または動的ロードによって GameFrameX のリソースインターフェースにアクセスする場合、ストリッピングされた拡張メソッド（例：`LoadTexture2DAsync`、`LoadPrefabSync`）は直接消滅し、実行時に `MissingMethodException` が発生します。本ページでは、本リポジトリで既に使用されている防护（保護）方案と、新規カスタム拡張時に必ず従うべき記述方法を説明します。

## 前提条件

- プロジェクトが Unity IL2CPP バックエンド（Android / iOS / WebGL でデフォルト有効）を使用している。
- Player Settings → Managed Stripping Level が Low より高い、または Engine Code Stripping が有効になっている。
- `GameFrameX.Asset` パッケージがプロジェクトにインポート済み。

## 操作手順

### 1. リポジトリで既に标注（マーク）されている拡張メソッドを再利用する

リポジトリでは、すべての公開拡張クラスとメンバーに `[UnityEngine.Scripting.Preserve]` が付与されており、直接呼び出すだけでストリッパーがそれらを保持します。例として以下の `LoadTexture2DAsync` 拡張を示します：

```csharp
[UnityEngine.Scripting.Preserve]
public static class AssetComponentTexture2DExtensions
{
    [UnityEngine.Scripting.Preserve]
    public static Task<AssetHandle> LoadTexture2DAsync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetAsync<Texture2D>(path);
    }

    [UnityEngine.Scripting.Preserve]
    public static AssetHandle LoadTexture2DSync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetSync<Texture2D>(path);
    }
}
```

ソース: [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs#L13-L44)

`AssetComponent` 自身と `GamePlayMode` プロパティにも `[Preserve]` が付与されています：

```csharp
[RequireComponent(typeof(GameFrameXAssetCroppingHelper))]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-4000)]
public sealed class AssetComponent : GameFrameworkComponent
{
    [UnityEngine.Scripting.Preserve]
    public EPlayMode GamePlayMode { get; set; }
}
```

ソース: [Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L18-L45)

### 2. 新規カスタム拡張にも Preserve 属性を付与する

自身のプロジェクトで `AssetComponent` の拡張メソッドを追加する場合、静的クラスと各パブリックメンバーすべてに `[Preserve]` を必ず付与してください。さもないとストリッパーは「未参照」と見なして削除します。

```csharp
using UnityEngine;
using UnityEngine.Scripting;
using GameFrameX.Asset.Runtime;

[Preserve]
public static class MyAssetComponentExtensions
{
    [Preserve]
    public static AssetHandle LoadMyAssetSync(this AssetComponent self, string path)
    {
        return self.LoadAssetSync<Object>(path);
    }
}
```

配置場所の推奨：`AssetComponent` と同じディレクトリまたは同じアセンブリに配置すると、ビルド時にストリッパーがまとめてスキャンできます。

### 3. プロジェクトにヘルパーコンポーネントが存在することを確認する

`AssetComponent` は `[RequireComponent]` によって `GameFrameXAssetCroppingHelper` を强制的にアタッチし、シーン内で関連型を保持します：

```csharp
[Preserve]
public class GameFrameXAssetCroppingHelper : MonoBehaviour
{
}
```

ソース: [Runtime/GameFrameXAssetCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/GameFrameXAssetCroppingHelper.cs)

`AssetComponent` のインスタンスが実行シーンに存在し続ける限り（`GameFrameXAutoComponent` がフレームワーク起動時に自動生成）、ストリッパーはこの参照チェーン上のすべてのマーク済みメンバーを保持します。

### 4. 必要に応じて link.xml をフォールバックとして提供する

業務側でリフレクション（例：文字列名による `LoadPrefabAsync` の呼び出し）を介してリソースインターフェースにアクセスする場合、コンパイル時の参照を解析できないため、追加で `Assets/` 下に `link.xml` を配置してアセンブリ全体を强制的に保持してください：

```xml
<linker>
  <assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>
</linker>
```

`link.xml` は `Resources` ディレクトリ以外の任意の `Assets` サブディレクトリ下に配置する必要があり、そうすることで Unity が処理します。

## よくあるバリエーション

| シーン | 方法 |
|------|------|
| 汎用ジェネリック入口 `LoadAssetAsync<T>` | 直接呼び出し。T は呼び出し元から提供され、参照チェーンは静的解析で識別されるため、追加の `[Preserve]` は不要。 |
| カスタム非同期ラッパー層 | ラッパーメソッドの外層に `[Preserve]` を付与し、ラッパーメソッドが少なくとも一箇所から静的に呼び出されるようにする。 |
| WebGL プラットフォーム | `EPlayMode.WebPlayMode` を強制的に使用。`AssetComponent.Awake` にこの分岐が組み込まれている。 |
| Addressables / YooAsset を介した間接リフレクション呼び出し | `link.xml` によるフォールバックも同時に提供する。 |

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| パッケージビルド後に `LoadXxxAsync` を呼び出すと `MissingMethodException` が発生 | その拡張メソッドがどのコードからも静的に参照されておらず、IL2CPP によりストリッピングされた。 | 拡張クラスとメソッドに `[UnityEngine.Scripting.Preserve]` を追加する。 |
| `GameFrameX.Asset.Runtime` アセンブリ内の型へのリフレクション呼び出しが失敗する | アセンブリ全体がストリッピングされた。 | `Assets/link.xml` に `<assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>` を追加する。 |
| WebGL パッケージビルド後のリソースロードで `Asset manager is invalid.` エラーが発生 | 実行モードが `EditorSimulateMode` に还原された。 | `AssetComponent.Awake` ですでに処理済み。`m_GamePlayMode` がビルド成果物内でシリアライズされていることを確認する。 |
| シーンから `AssetComponent` を削除するとすべてのリソースインターフェースが消える | `RequireComponent(GameFrameXAssetCroppingHelper)` も一緒に削除された。 | `AssetComponent` を単独で削除しない。置き換える場合は `CroppingHelper` も保持するか、再アタッチする。 |

## 検証

1. Unity Editor → Build Settings で IL2CPP パッケージ（Android または iOS）をビルドする。
2. 実機／シミュレーターで `await assetComponent.LoadTexture2DAsync("Assets/Textures/xxx.png");` を実行し、`MissingMethodException` が発生しないことを確認する。
3. `il2cppdumper` または `Unity Symbol` ツールでパッケージ内の dll を逆引きし、`GameFrameX.Asset.Runtime` アセンブリ内の拡張型がまだ存在することを確認する。
4. それでも失敗する場合は、カスタムの `link.xml` / `[Preserve]` 标记を段階的に除去し、ストリッピングされたメンバーを特定する。

## 背景（任意）

`[UnityEngine.Scripting.Preserve]` は Unity 公式がマネージドコードストリッパーに提供する「ホワイトリスト」标记であり、link.xml でメンバーごとに保持することと等価です。リポジトリがすべての公開拡張 API にこの标记を付与しているのは、これらのメソッドがリフレクションやジェネリックの間接呼び出しで多用され、コンパイル時の参照グラフではカバーできないためです。本セクションに関連するソース：[Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs) および [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs)。
