# 사용하지 않는 Unity 패키지를 제거하는 방법

이 도구를 사용하면 `Packages/manifest.json`에서 지정된 종속성을 한 번에 제거하고, `Packages/` 하위의 해당 로컬 패키지 디렉터리도 함께 삭제할 수 있으며, 정리 완료 후 자동으로 `AssetDatabase.Refresh()`를 호출합니다. 전체 프로세스는 Unity Editor에서 명령줄 매개변수를 통해 트리거됩니다.

## 사전 조건

- Unity 프로젝트 루트 디렉터리에 `Packages/manifest.json`이 존재해야 합니다(표준 UPM 프로젝트).
- 명령줄 호출자가 프로세스 매개변수에 `-RemovePackages` 매개변수를 전달할 수 있어야 합니다(배치 처리, CI, 메뉴 호출 모두 가능).
- `Newtonsoft.Json`이 필요합니다(`manifest.json`의 파싱이 이 라이브러리에 의존하며, Editor 어셈블리에 이미 포함되어 있음).

## 작업 단계

1. 제거할 패키지 목록을 준비합니다. 패키지 이름은 `manifest.json`의 `dependencies` 하위 key와 완전히 일치해야 합니다(예: `com.unity.xr.management`).
2. Unity Editor 명령줄에 `-RemovePackages` 매개변수를 전달하고, 그 뒤에 반각 쉼표로 구분된 패키지 이름 목록을 붙입니다.
3. `PackageRemovalHelper.Run()`을 트리거하면, 도구가 다음 순서대로 실행됩니다:
   - 명령줄 매개변수를 파싱하여 제거할 패키지 목록을 얻습니다; `-RemovePackages`가 전달되지 않은 경우 즉시 예외를 던집니다.
   - `manifest.json`의 `dependencies`에서 해당 항목을 삭제하고, 임시 파일 방식으로 원자적으로 다시 씁니다.
   - `Packages/<패키지 이름>` 로컬 디렉터리(임베디드 패키지 / file:// 참조 패키지)를 삭제합니다.
   - `AssetDatabase.Refresh()`를 호출합니다.

## 일반적인 변형

- **`manifest.json`만 정리하고 로컬 디렉터리는 삭제하지 않음**: 도구는 `dependencies[packageName]`의 존재 여부를 하나씩 판단합니다; manifest에 없는 항목은 `Debug.Log`만 출력하고 건너뛰며, 오류를 보고하지 않습니다.
- **로컬 임베디드 패키지 디렉터리만 삭제**: `manifest.json`에는 없지만 `Packages/` 하위에 있는 로컬 폴더의 경우, 도구가 해당 디렉터리를 삭제합니다; 반대의 경우도 마찬가지입니다——두 작업은 서로 독립적입니다.
- **경로 안전 보호**: 패키지 이름에 `/`, `\`, `:` 또는 `..`가 포함된 경우 비정상적인 것으로 식별되어 건너뛰며, `Packages/` 밖으로 벗어가지 않습니다.

```csharp
if (string.IsNullOrWhiteSpace(packageName) ||
    packageName.IndexOfAny(new[] { '/', '\\', ':' }) >= 0 ||
    packageName.Contains(".."))
{
    Debug.LogWarning($"[PackageRemoval] 패키지 이름이 올바르지 않음, 건너뜀: {packageName}");
    continue;
}
```

## 배경 지식 (선택 사항)

이 도구는 "먼저 manifest를 수정하고, 그다음 로컬 디렉터리를 삭제하고, 마지막에 `AssetDatabase.Refresh`를 수행"하는 순서를 채택하여, Unity가 다음 리소스 새로 고침 시 이미 삭제된 임베디드 패키지를 더 이상 파싱하지 않도록 보장합니다. `manifest.json`은 `*.tmp`를 거쳐 다시 덮어쓰는 방식으로 기록되어, 반쪽짜리 쓰기로 인한 JSON 손상을 방지합니다.
