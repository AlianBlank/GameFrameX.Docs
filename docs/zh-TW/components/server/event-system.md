# 如何使用事件系統進行模組解耦

透過事件系統，模組之間不需要直接互相參考。只需定義事件、發佈事件，並由獨立的監聽器處理，即可實現鬆散耦合。本頁說明如何定義事件、撰寫監聽器以及分發事件。

## 前置條件

- 熟悉 C# 泛型與非同步程式設計（`async`/`await`）。
- 專案已參考 `GameFrameX.Core.Abstractions.Events` 與 `GameFrameX.Core.Events`。
- 了解 Actor 與元件代理的基本概念（請參閱 Actor 模組文件）。

## 核心概念快速參考

| 名稱 | 類型 | 用途 |
|------|----------|------|
| `GameEventArgs` | `GameFrameX.Core.Abstractions.Events.GameEventArgs` | 事件參數的基底類別；所有自訂事件參數都必須繼承自它 |
| `IEventListener` | `GameFrameX.Core.Abstractions.Events.IEventListener` | 監聽器介面，定義了 `HandleEvent` 方法 |
| `EventListener<T>` | `GameFrameX.Core.Events.EventListener<T>` | 抽象監聽器基底類別，可處理特定元件代理（`T : IComponentAgent`）的事件 |
| `EventDispatcher.Dispatch` | `GameFrameX.Core.Events.EventDispatcher` | 用於將事件發佈至指定 Actor 或全域監聽器的靜態進入點 |

## 操作步驟

### 1. 定義事件參數

建立一個繼承自 `GameEventArgs` 的類別以承載事件資料。`GameEventArgs` 本身僅繼承 `System.EventArgs`，不包含任何欄位。

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class PlayerLoginEventArgs : GameEventArgs
{
    public long PlayerId { get; }
    public DateTime LoginTime { get; }

    public PlayerLoginEventArgs(long playerId)
    {
        PlayerId = playerId;
        LoginTime = DateTime.UtcNow;
    }
}
```

### 2. 實作監聽器

有兩種方式：直接實作 `IEventListener`，或繼承泛型基底類別 `EventListener<T>`（`T : IComponentAgent`）。

**方式 A：繼承 `EventListener<T>`（建議，在需要存取元件代理時使用）**

```csharp
using GameFrameX.Core.Events;

public sealed class PlayerLoginListener : EventListener<PlayerComponentAgent>
{
    protected override async Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        if (gameEventArgs is not PlayerLoginEventArgs args) return;
        // 透過元件代理存取元件狀態
        var player = agent.GetPlayer();
        await player.OnLogin(args.LoginTime);
    }
}
```

`EventListener<T>` 會自動將傳入的 `IComponentAgent` 轉換為泛型 `T`，並在內部呼叫您實作的 `HandleEvent(T agent, GameEventArgs)`。

**方式 B：直接實作 `IEventListener`（在不需要存取元件代理時使用）**

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class GlobalStartupListener : IEventListener
{
    public Type AgentType => null;
    public Task HandleEvent(IComponentAgent agent, GameEventArgs gameEventArgs)
        => HandleEvent(gameEventArgs);

    public Task HandleEvent(GameEventArgs gameEventArgs)
    {
        // 全域事件處理邏輯
        return Task.CompletedTask;
    }
}
```

監聽器由框架以**單例**方式管理，因此實作必須是執行緒安全的。

### 3. 註冊監聽器

監聽器由框架透過掃描 `GameFrameX.Hotfix` 組件自動註冊。通常會將它們放置在 `GameFrameX.Hotfix` 專案下以便自動發現。命名必須遵循專案架構規則（以 `EventListener` 作為後綴；具體限制由 `GameFrameX.Architecture.Analyzers` 強制執行）。

### 4. 分發事件

呼叫靜態類別 `EventDispatcher.Dispatch`，傳入目標 ActorId、事件 ID 與事件參數。如果 actorId 對應的 Actor 不存在，事件會自動分發給**全域監聽器**。

```csharp
using GameFrameX.Core.Events;

// 在 actorId 對應的 Actor 上下文中分發事件
EventDispatcher.Dispatch(playerActorId, EventId.PlayerLogin, new PlayerLoginEventArgs(playerId));
```

事件 ID 使用 `int` 常數，通常集中定義於 `GameFrameX.Apps/Common/Event/EventId.cs`。

## 常見變體

| 情境 | 做法 |
|------|------|
| 玩家層級事件（需要存取玩家元件） | 繼承 `EventListener<PlayerComponentAgent>`，覆寫 `HandleEvent(T, GameEventArgs)` |
| 全域／伺服器層級事件 | 實作 `IEventListener`，使用無代理版本的 `HandleEvent(GameEventArgs)` |
| 監聽無參數事件 | 事件參數繼承 `GameEventArgs`，但不承載任何欄位 |

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 顯示 `NoListenersFound` 警告 | 此事件 ID 未註冊任何監聽器 | 確認監聽器類別位於 `GameFrameX.Hotfix` 組件中，且命名符合分析器規則 |
| `HandleEvent` 收到其他類型的事件參數 | 事件被錯誤地分發到另一個事件 ID | 使用集中定義的 `EventId` 常數；避免硬編碼的魔術數字 |
| 多個監聽器實例之間共享狀態造成並行問題 | 監聽器是單例，但其內部狀態不是執行緒安全的 | 將可變狀態改為區域變數或加入鎖定；避免在監聽器中儲存請求層級的資料 |

## 背景說明（選讀）

在 Actor 上下文中的事件分發以**序列**方式執行（`foreach` + `await`），確保同一個 Actor 下的事件不會並行執行；當 Actor 不存在時，全域監聽器會在新執行緒上分發。每個監聽器的例外都會被攔截並由 `LogHelper.Error` 記錄，且不會中斷其他監聽器的處理。詳情請參閱 [EventDispatcher.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Events/EventDispatcher.cs#L50-L135)。
