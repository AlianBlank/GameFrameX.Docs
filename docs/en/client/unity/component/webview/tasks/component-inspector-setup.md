# How to Add and Configure the WebView Component in a Scene

After attaching the `WebViewComponent` component to a Unity scene and selecting a platform implementation, you can pop up a WebView page at runtime with a single line of code, `Show(url)`, with support for fullscreen, hiding, and executing JavaScript. This page provides the complete steps from adding the component to verifying it works.

## Prerequisites

- The GameFrameX WebView package (`com.gameframex.unity.webview`) is installed in the project, and `Runtime/WebViewComponent.cs` is included in compilation.
- A GameFrameX framework entry already exists in the scene (`WebViewComponent` inherits from `GameFrameworkComponent`, so the framework component system must be available).
- A runtime implementation class implementing `IWebViewManager` has been imported (this repository only contains the abstract layer `BaseWebViewManager`; concrete platform implementations must be provided by the user).

## Steps

1. Open the target scene and select the GameObject that hosts the framework components (usually the root object with other GameFrameX components attached).

2. Add the component via the menu: **Add Component → Game Framework → WebView**. The component is registered to this menu via the following attributes:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("Game Framework/WebView")]
[UnityEngine.Scripting.Preserve]
public partial class WebViewComponent : GameFrameworkComponent
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L10-L13)

> Only one `WebViewComponent` can be attached to the same GameObject (`DisallowMultipleComponent`).

3. Select the implementation type in the Inspector. The Inspector is provided by an editor script and lists all types implementing `IWebViewManager`:

```csharp
[CustomEditor(typeof(WebViewComponent))]
internal sealed class WebViewComponentInspector : ComponentTypeComponentInspector
{
    protected override void RefreshTypeNames()
    {
        RefreshComponentTypeNames(typeof(IWebViewManager));
    }
}
```

Source: [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L13-L20)

4. Run the scene. The component resolves the implementation based on the type saved in the Inspector during `Awake`, and completes initialization in `Start`:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IWebViewManager);
base.Awake();
if (!IsRuntimeComponentReady)
{
    return;
}

_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L38)

5. Get the component in your business code and call the API. The complete list of available interfaces is as follows (component methods correspond one-to-one with `IWebViewManager`):

| Method | Signature | Description |
|------|------|------|
| Show WebView | `void Show(string url)` | Loads and displays the page at the specified url |
| Fullscreen | `void MakeFullScreen()` | Switches the WebView to fullscreen |
| Execute JavaScript | `void ExecuteJavaScript(string javaScript)` | Executes JS code on the current page |
| Hide | `void Hide()` | Hides the WebView |

Source: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L12-L40)

Usage example:

```csharp
var webView = GameEntry.GetComponent<WebViewComponent>();
webView.Show("https://example.com");
webView.ExecuteJavaScript("console.log('hello');");
webView.MakeFullScreen();
webView.Hide();
```

> The usage example above is a standard combination of the public APIs `WebViewComponent.Show/ExecuteJavaScript/MakeFullScreen/Hide`; the method signatures are all taken from the source code. The specific way to obtain the component depends on your GameFrameX entry wrapper.

## Common Variants

- **Custom platform implementation**: Create a class inheriting from `BaseWebViewManager` and implement the five abstract methods `Initialize`, `Show`, `MakeFullScreen`, `ExecuteJavaScript`, and `Hide`; it will then appear in the Inspector's implementation type dropdown list:

```csharp
public abstract partial class BaseWebViewManager : GameFrameworkModule, IWebViewManager
{
    public abstract void Initialize();
    public abstract void Show(string url);
    public abstract void MakeFullScreen();
    public abstract void ExecuteJavaScript(string javaScript);
    public abstract void Hide();
}
```

Source: [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39)

- **Creating the component via code**: If you need to attach it dynamically, you can call `AddComponent<WebViewComponent>()` directly on a GameObject. Since the implementation type is resolved immediately in `Awake`, make sure the implementation type serialized in the Inspector is configured; otherwise, at runtime it will take the early-return branch where `IsRuntimeComponentReady == false`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The implementation type dropdown list in the Inspector is empty | No concrete class implementing `IWebViewManager` exists (this repository only provides the abstract layer) | Write an implementation class inheriting from `BaseWebViewManager`, then refresh |
| Runtime log `Web View manager is invalid.` (`Log.Fatal`) | `GameFrameworkEntry.GetModule<IWebViewManager>()` returns null; the module is not registered | Confirm the implementation class is available and the type selected in the Inspector is correct |
| The component silently does nothing; `Show` has no response | `Awake` returns early because `IsRuntimeComponentReady` is false, leaving `_webViewManager` null | Check whether the implementation type string saved in the Inspector can be resolved by `Utility.Assembly.GetType` |
| A second WebView component cannot be attached to the same object | The class is annotated with `[DisallowMultipleComponent]` | Just attach only one WebView component per scene |

## Verification

- No `Log.Fatal("Web View manager is invalid.")` output after entering run mode means the module was resolved successfully.
- Calling `Show("https://example.com")` pops up the page; calling `MakeFullScreen()` and `Hide()` in sequence behaves as expected.

## Background

`WebViewComponent` is a facade component in the GameFrameworkComponent system: the Inspector is only responsible for selecting the implementation type of `IWebViewManager` and serializing it as a string; at runtime, the component resolves it back to a type via reflection in `Awake`, then obtains the module instance through `GameFrameworkEntry.GetModule<T>()`, and calls `Initialize()` in `Start` to complete initialization. As a result, the business layer depends only on the component's four public methods, decoupled from the concrete platform implementation.
