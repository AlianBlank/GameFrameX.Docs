# 使用引用池減少 GC 配置

引用池(`ReferencePool`)用於快取實作了 `IReference` 介面的物件實例,透過 `Acquire` 取得、`Release` 歸還複用,避免反覆 `new` 造成的 GC 壓力。本頁給出在 GameFrameX 中接入引用池並用於自訂類型的完整步驟。

## 前置條件

- 專案已引入 `GameFrameX.Runtime.Base.ReferencePool` 與 `GameFrameX.Runtime.ReferencePoolComponent`(隨框架預設打包)。
- 場景裡掛有 `ReferencePoolComponent`(選單 `Add Component → GameFrameX → ReferencePool`),或在程式碼裡直接透過靜態類別 `ReferencePool` 存取。

## 操作步驟

1. **讓自訂類型實作 `IReference`**。類型必須有無參建構函式,並在 `Clear()` 中把欄位復位,保證下一次取出時是乾淨狀態。

   ```csharp
   using GameFrameX.Runtime;

   public sealed class DamageInfo : IReference
   {
       public int AttackerId { get; private set; }
       public int TargetId   { get; private set; }
       public float Amount  { get; private set; }

       public void Clear()
       {
           AttackerId = 0;
           TargetId   = 0;
           Amount     = 0f;
       }

       internal void Fill(int attackerId, int targetId, float amount)
       {
           AttackerId = attackerId;
           TargetId   = targetId;
           Amount     = amount;
       }
   }
   ```

   Source: [Tests/ReferencePoolTests.cs#L11-L29](/src/Tests/ReferencePoolTests.cs#L11-L29)

2. **Acquire 取得實例**。使用泛型版本無需手動轉型;池空時框架會呼叫無參建構函式新建。

   ```csharp
   DamageInfo info = ReferencePool.Acquire<DamageInfo>();
   ```

   簽名:`public static T Acquire<T>() where T : class, IReference, new()`,見 [Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132)。

3. **Release 歸還實例**。歸還時會自動呼叫 `Clear()`,但欄位級重置仍由你的 `Clear()` 負責。

   ```csharp
   ReferencePool.Release(info);
   ```

   簽名:`public static void Release(IReference reference)`,見 [Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167)。傳入 `null` 會擲出 `GameFrameworkException("Reference is invalid.")`,見 [Tests/ReferencePoolTests.cs#L79](/src/Tests/ReferencePoolTests.cs#L79)。

4. **(可選)啟動前預熱池容量**。在戰鬥/關卡開始時呼叫 `Add<T>(count)`,避免執行時即時擴容。

   ```csharp
   ReferencePool.Add<DamageInfo>(64);
   ```

   簽名:`public static void Add<T>(int count) where T : class, IReference, new()`,見 [Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181)。

5. **(可選)查看池狀態**。在偵錯面板或 Profiler 鉤子裡讀取各類型快取資訊。

   ```csharp
   ReferencePoolInfo[] infos = ReferencePool.GetAllReferencePoolInfos();
   foreach (var info in infos)
   {
       UnityEngine.Debug.Log($"{info.Type.Name}: using={info.UsingReferenceCount} unused={info.UnusedReferenceCount}");
   }
   ```

   簽名見 [Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98)。

## 常見變體

- **執行時按 `Type` 取得**(無法使用泛型時):

  ```csharp

  ```

  見 [Runtime/Base/ReferencePool/ReferencePool.cs#L142-L147](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L142-L147)。
- **按 `Type` 預熱**:


- **整體清空**(場景切換、退出戰鬥時):

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `GameFrameworkException: Reference is invalid.` | 把 `null` 傳給了 `Release` | Release 前做非空判斷,或在 `using`/`try-finally` 區塊內歸還 |
| 取出物件殘留上次資料 | `Clear()` 沒把欄位復位 | 在 `Clear()` 中明確把所有欄位重設為預設值 |
| 類型無法 `Acquire` | 類型未實作 `IReference` 或沒有 `public` 無參建構函式 | 實作介面、補齊無參建構函式 |
| Profiler 顯示池暴漲 | 一直 Acquire 不 Release | 在使用結束路徑(例外分支也算)確保 Release;可用 `try { ... } finally { Release(info); }` |
| 開啟嚴格檢查後效能下降 | `ReferencePool.EnableStrictCheck = true` 啟用了反射驗證 | 僅在偵錯期開啟,發行版關閉 |

## 背景(可選)

每個 CLR 類型在池內有一個獨立的 `ReferenceCollection`,內部維護 `Stack<IReference>`。`Acquire` 優先出堆疊,堆疊空才 `new`;`Release` 呼叫 `Clear()` 後壓堆疊。開啟 `EnableStrictCheck` 會透過反射驗證類型,影響效能,僅用於偵錯。
