# PathUtil API 速查

`PathUtil`는 GameFrameX.ReadAssets에서 제공하는 정적 경로 유틸리티 클래스로, 내부의 모든 메서드에는 `[Preserve]` 표시가 되어 있어 Unity 코드 스트리핑을 방지하며, 주로 상대 경로 정규화, 구분자 판정, 경로 결합, 와일드카드를 정규식으로 변환하는 데 사용됩니다.

## 메서드 빠른 참조

| 이름 | 시그니처 | 설명 |
|------|------|------|
| `IsDirectorySeparator` | `bool IsDirectorySeparator(char c)` | 문자가 `/` 또는 `\` 디렉터리 구분자인지 판정 |
| `FixTrailingDirectorySeparators` | `string FixTrailingDirectorySeparators(string path)` | 경로 끝의 중복된 구분자 수정 (하나의 구분자 유지) |
| `CombineSlash` | `string CombineSlash(string a, string b)` | `/`로 두 경로 세그먼트를 결합하며, 어느 하나라도 `null`이면 `ArgumentNullException` 발생 |
| `NormalizeRelativePath` | `string NormalizeRelativePath(string relative, bool forceTrailingSlash = false)` | 상대 경로를 `/`로 시작하는 형식으로 정규화하고, `.` / `..` 세그먼트 처리 |
| `IsValidCharacter` | `bool IsValidCharacter(char c)` | 문자가合法的 파일명/경로 문자인지 판정 |
| `WildcardToRegex` | `Regex WildcardToRegex(string pattern)` | `*` / `?` 와일드카드 패턴을 대소문자 구분 없는 정규식으로 컴파일 |

## 예외 및 기본 동작

| 메서드 | 트리거 조건 | 발생/반환 |
|------|----------|-----------|
| `CombineSlash` | 어느 매개변수라도 `null` | `ArgumentNullException("a")` 또는 `ArgumentNullException("b")` |
| `NormalizeRelativePath` | 인자가 `null` 또는 빈 문자열 | `ArgumentException("Empty or null", "relative")` |
| `NormalizeRelativePath` | `..`이(가) 루트를 넘어가려 시도 (상위 디렉터리가 더 이상 없음) | `System.IO.IOException("Invalid path: double dot error (before " + i + ")")` |
| `NormalizeRelativePath` | 경로에 `\"`/`<`/`>`/`|`/`<32`/`:`/`*`/`?` 등의 illegal 문자가 포함됨 | `System.IO.IOException("Invalid characters")` |
| `IsValidCharacter` | 문자가 `\"`, `<`, `>`, `|`, `<32`, `:`, `*`, `?` | `false` 반환, 그 외에는 `true` 반환 |
| `WildcardToRegex` | 기본적으로 대소문자 무시 | `Regex` 반환, 패턴 양쪽에 `^...$` 추가 |

## 사용 예제

### 경로 결합

```csharp
using GameFrameX.ReadAssets.Runtime;

// 결합하여 "a/b" 얻기
var p1 = PathUtil.CombineSlash("a", "b");
// 결합하여 "a/b" 얻기
var p2 = PathUtil.CombineSlash("a/", "b");
// b가 '/'로 시작하면 b를 직접 반환
var p3 = PathUtil.CombineSlash("a", "/b");
```

Source: [PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75)

### 상대 경로 정규화

```csharp
using GameFrameX.ReadAssets.Runtime;

// "./a/./b/../c"  → "/a/c"
var normalized = PathUtil.NormalizeRelativePath("./a/./b/../c");
// 끝에 슬래시 강제 유지: "a/b/"  → "/a/b/"
var dirPath = PathUtil.NormalizeRelativePath("a/b", forceTrailingSlash: true);
// 큰따옴표로 감싸진 경로도 제거됨: "\"a/b\""  → "/a/b"
var stripped = PathUtil.NormalizeRelativePath("\"a/b\"");
```

## 내부 호출자

`PathUtil`은(는) `BlankReadAssets`의 다양한 플랫폼 구현에서 경로 전처리기(path preprocessor)로 호출됩니다:

| 호출 지점 | 메서드 | 용도 |
|--------|------|------|
| `BlankReadAssets.ApkImpl.Read` | `NormalizeRelativePath(path)` | 읽기 요청 경로 정규화 |
| `BlankReadAssets.ApkImpl.ReadDirectory` | `NormalizeRelativePath(path, forceTrailingSlash:true)` | 디렉터리 경로 정규화, 끝 슬래시 유지 |
| `BlankReadAssets.ApkImpl.Exists` | `NormalizeRelativePath(path, forceTrailingSlash:true)` | 정규화하여 디렉터리 존재 여부 판정 |
| `BlankReadAssets.ApkImpl` 디렉터리 검색 | `WildcardToRegex(searchPattern)` | `*.xxx` 와일드카드 패턴을 필터링 정규식으로 변환 |
| `BlankReadAssets.LooseFilesImpl.Read` | `NormalizeRelativePath(path, forceTrailingSlash:true)` | 루즈 파일(loose files) 구현의 경로 정규화 |
| `BlankReadAssets.LooseFilesImpl.ReadFileInfo` | `NormalizeRelativePath(path)` | 파일 정보 조회 경로 정규화 |
| `BlankReadAssets.LooseFilesImpl.Exists` | `NormalizeRelativePath(path)` | 존재 여부 판정의 경로 정규화 |

## 주의 사항

- 모든 공개 메서드에는 `[Preserve]`가 표시되어 있어, 관리 코드 스트리핑이 활성화된 IL2CPP 빌드에서도 보존됩니다.
- `NormalizeRelativePath`는 결과에 선행 `/`를 능동적으로 추가하므로, 호출자는 루트를 추가로 결합하면 안 됩니다.
- `WildcardToRegex`는 `Regex.Escape`를 먼저 사용하여 이스케이프한 다음 `*`/`?`를 치환하므로, 전달된 `.`, `(` 등의 문자는 자동으로 리터럴로 이스케이프됩니다.
