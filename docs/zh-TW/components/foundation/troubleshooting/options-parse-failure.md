# 命令列引數解析失敗時的處理方法

使用 `OptionsBuilder` 或 `CommandLineArgumentConverter` 解析命令列引數時，若發生 `ArgumentException`、`ArgumentAlreadyException`、必要選項驗證失敗、屬性值型別不一致等情況，請依照本頁的診斷表找出根本原因並進行修正。

## 快速診斷

| 症狀（錯誤訊息/現象） | 原因 | 修正方式 |
|----------------------|------|------|
| `Argument cannot contain null` 形式的 `ArgumentException`，參數名稱為 `args` | `args` 陣列中包含 `null` 元素（在 `Main` 的引數中通常不會發生，但手動建構時可能會混入） | 請參閱 [從 args 中移除 null 元素](#修正-1從-args-中移除-null-元素) |
| 被 `ArgumentException` 包裹的「處理參數時發生錯誤： ...」 | 解析處理中的其他分支發生例外，並被 `ConvertToStandardFormat` 的外層 `catch` 包裹 | 檢查 `ex.InnerException.Message`，對應到具體的子問題；請參閱 [修正 2](#修正-2調查處理參數時的內部例外) |
| 必要選項未指派時處理程序當機，或欄位成為預設值 | 缺少必要參數，且未傳入 `skipValidation: true` | 使用 `skipValidation` 略過驗證，或補上必要參數；請參閱 [修正 3](#修正-3補上必要參數或略過驗證) |
| 相同的索引鍵被指派兩次，後面的值未生效，或擲回 `ArgumentAlreadyException` | 傳入了重複的相同選項，或環境變數與命令列中同名索引鍵發生衝突 | 請參閱 [修正 4](#修正-4解決引數重複或環境變數與命令列衝突的問題) |
| 布林型別欄位被填入 `"true"/"false"` 以外的字串 | 在 `BoolArgumentFormat.Flag` 模式下，下一個看起來像值的權杖被當作布林值消耗/無法被識別 | 明確傳入 `--flag=true`，或切換 `BoolArgumentFormat`；請參閱 [修正 5](#修正-5布林引數的解析異常) |
| 負數（例如：`--offset=-3`）被識別為「選項索引鍵」，而將下一個引數誤當作值 | 當 `IsNegativeNumber` 將其識別為負數時，`IsOptionToken` 會回傳 `false`，但含空格的負數表示方式可能被誤判 | 以 `--offset=-3` 的格式撰寫值，避免在負數後面繼續附加值；請參閱 [修正 6](#修正-6負數與含空格值的解析異常) |
| 索引鍵/值組 `--key=` 後面的值遺失，欄位成為預設值 | 空字串的值被視為「沒有值」，而略過下一個項目 | 若想保留空值，請使用 `--key=""`，或維持 `EnsurePrefixedKeys=true` 讓 `--key=` 能被正常處理 |

## 修正步驟

### 修正 1：從 args 中移除 null 元素

`ConvertToStandardFormat` 一偵測到 `arg == null` 就會立即擲回 `ArgumentException`：

```csharp
// CommandLineArgumentConverter.ConvertToStandardFormat
if (arg == null)
{
    throw new ArgumentException(LocalizationService.GetString(LocalizationKeys.Exceptions.ArgsCannotContainNull), nameof(args));
}
```

修正方式：在呼叫前先進行過濾：

```csharp
using GameFrameX.Foundation.Options;

var cleanArgs = (args ?? Array.Empty<string>())
    .Where(a => a != null)
    .ToArray();

var options = OptionsBuilder.Create<MyOptions>(cleanArgs);
```

> 出處：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L188-L194)

### 修正 2：調查處理參數時的內部例外

`ConvertToStandardFormat` 的外層 `catch` 會將 `ArgumentException` 以外的例外包裹後重新擲回：

```csharp
catch (Exception ex)
{
    throw new ArgumentException(
        LocalizationService.GetString(LocalizationKeys.Exceptions.ProcessingError, ex.Message),
        ex);
}
```

調查步驟：

1. 攔截外層的 `ArgumentException`，讀取 `ex.InnerException` 以取得實際的堆疊追蹤。
2. 若 `InnerException` 為 `ArgumentAlreadyException`，請前往 [修正 4](#修正-4解決引數重複或環境變數與命令列衝突的問題)。
3. 若 `InnerException` 與反映/型別轉換相關（例如：`InvalidCastException`、`FormatException`），通常是因為命令列值的字串無法轉換為目標屬性型別。請檢查 `MyOptions` 中對應欄位的型別與所傳入的值。

> 出處：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L219-L227)

### 修正 3：補上必要參數或略過驗證

`OptionsBuilder.Create<TOptions>(args, skipValidation)` 的第二個參數控制是否略過必要選項的驗證。在開發/偵錯階段，或不想讓處理程序終止的情境下，可以如下使用：

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.Create<MyOptions>(args, skipValidation: true);
```

若商務邏輯上不允許略過，則必須確認所有標記為「必要」的選項皆已傳入：

- 使用 `OptionsDebugger.PrintParsedOptions(opts)` 輸出解析結果，確認每個屬性是否為預期的值。
- 請注意，環境變數會作為「隱含來源」補上欄位值，因此即使「看似沒有傳入命令列」，實際上可能是環境變數已經生效。

> 出處：[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L67)

### 修正 4：解決引數重複或環境變數與命令列衝突的問題

同名索引鍵重複會觸發 `ArgumentAlreadyException`：

```csharp
// ArgumentAlreadyException.Throw
public static void Throw(string message)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(message, nameof(message));
    throw new ArgumentAlreadyException(message);
}
```

修正方式：

- 命令列層級：合併重複的選項，讓相同的邏輯索引鍵只出現一次。
- 命令列與環境變數：使用 `OptionsBuilder.CreateFromArgsOnly<TOptions>(args)` 明確停用環境變數，避免同名索引鍵被覆寫時造成邏輯混亂：

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);
```

> 出處：[ArgumentAlreadyException.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ArgumentAlreadyException.cs#L69-L73)、[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L103-L107)

### 修正 5：布林引數的解析異常

在 `BoolArgumentFormat.Flag`（預設）模式下，`AttachValueIfPresent` 會略過被識別為布林常值的下一個權杖，以避免在 `--verbose true` 這種寫法中，`true` 被誤當成 `--verbose` 的值：

```csharp
if (BoolFormat == BoolArgumentFormat.Flag && BooleanParser.IsBooleanValue(nextArg))
{
    return currentIndex + 1;
}
```

若要將布林值指派給字串/集合型別的欄位，請使用索引鍵/值組格式：

```bash
# 請勿這樣寫（布林值會被略過）
myapp --mode true

# 請這樣寫
myapp --mode=true
```

> 出處：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L336-L344)

### 修正 6：負數與含空格值的解析異常

`IsOptionToken` 已對負數做了例外處理：

```csharp
private static bool IsOptionToken(string value)
{
    if (string.IsNullOrEmpty(value)) return false;
    if (!value.StartsWith("-")) return false;
    return !IsNegativeNumber(value);
}
```

不過，在 `EnsurePrefixedKeys=true` 的情況下，被誤判為「非選項」的負數權杖會被 `NormalizeKey` 加上 `--` 前置詞：

```csharp
return EnsurePrefixedKeys ? "--" + arg : arg;
```

因此，建議在傳入負數時明確加上前置詞，或使用索引鍵/值組格式：

```bash
# 建議：索引鍵/值組不會被改寫
myapp --offset=-3

# 不建議：可能會被補成 `-- -3`，或被誤判為選項
myapp offset -3
```

包含空格的字串值會由 `AppendTokenWithQuotingIfNeeded` 自動加上雙引號。從 `string[]` 進入解析時已先以空格分割完畢，因此不需要額外處理。從單一字串重新建構命令列時（`ToCommandLineString`），會自動加上引號。

> 出處：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L347-L365)

## 驗證

請依照下列順序確認問題已解決：

1. 使用 `OptionsBuilder.CreateWithDebug<TOptions>(args)` 輸出解析結果，確認每個屬性的最終值。
2. 使用 `OptionsBuilder.TryCreate<TOptions>(args, out var result, out var error)` 包裹失敗路徑：失敗時會回傳預設執行個體，可透過 `error` 取得錯誤訊息，且處理程序不會當機。
3. 在偵錯工具中觀察 `ex.InnerException`，確認根本原因已被找出（特別是 `ArgumentAlreadyException`、`FormatException` 等子例外）。

> 出處：[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L149-L184)
