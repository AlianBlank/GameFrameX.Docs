# 第一个可用的流程

按照本页步骤,你可以在 Unity 工程中挂上 `ProcedureComponent`、编写两个 `ProcedureBase` 子类并启动入口流程,让游戏在启动后立刻运行起来。

## 前置条件

- 已安装 `com.gameframex.unity.procedure` 包,以及其依赖的 `com.gameframex.unity.fsm`、`com.gameframex.unity.runtime`。
- 工程入口场景的 `GameFramework` 物体上挂有 `ProcedureComponent` 组件(`[AddComponentMenu("GameFrameX/Procedure")]`)。
- 了解 C# 类继承与 Unity Inspector 基本用法。

## 操作步骤

1. **新建流程类**。创建 `LaunchProcedure`(启动流程,通常负责初始化基础系统),继承自 `ProcedureBase`:

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

public sealed class LaunchProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 此处进行基础模块初始化,如配置、日志、资源等
    }
}
```

`ProcedureBase` 继承自 `FsmState<IProcedureManager>`,内置 `OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy` 六个生命周期钩子,按需重写即可。

Source: [ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

2. **新建第二个流程**(例如 `MainProcedure`),用于后续切到主界面或主逻辑:

```csharp
using GameFrameX.Procedure.Runtime;

public sealed class MainProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 启动场景、加载 UI、开始主循环
        ChangeState<MainProcedure>(procedureOwner); // 自定义流转示例
    }
}
```

3. **在 Inspector 配置流程列表**。选中挂有 `ProcedureComponent` 的物体,填写以下字段:

| 字段 | 作用 | 示例 |
|------|------|------|
| `Available Procedure Type Names` | 框架要创建并加入状态机的全部流程类型全名(命名空间 + 类名) | `MyGame.LaunchProcedure`、`MyGame.MainProcedure` |
| `Entrance Procedure Type Name` | 启动入口流程的类型全名,必须出现在上一步的列表里 | `MyGame.LaunchProcedure` |

类型名通过反射查找,因此类必须能被 `Utility.Assembly.GetType` 找到,且拥有无参构造函数。组件会在 `Start` 中自动 `Activator.CreateInstance` 并初始化。

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L129-L168)

4. **进入 Play Mode**。框架会在 `Start` 中完成以下动作:

   - 反射创建所有流程实例。
   - 调用 `m_ProcedureManager.Initialize(IFsmManager, procedures)` 注册到 FSM。
   - 等到帧末后调用 `m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType())` 启动入口流程。

   入口流程的 `OnEnter` 被触发后,即代表你的第一个可用的流程已经运行起来。

## 常见变体

- **手动接管启动(StartupRunner 模式)**:在 `ProcedureComponent` 上勾选 `Use Startup Runner = true`,组件 `Awake` 只注册 `IProcedureManager`,不自动 `Initialize/StartProcedure`;由 `ApplicationStartupEntry` 通过 `StartupRunner.Run` 在你指定的位置接管初始化与启动,可避免重复 `Initialize` 报 "Already exist FSM"。

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L127)

- **不挂组件,纯代码初始化**:在拿到 `IFsmManager` 与 `IProcedureManager` 后,自行构造流程数组并调用 `Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures)`,再 `StartProcedure<T>()`。

  Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L156)

- **运行时切换流程**:在某个流程的 `OnEnter` / `OnUpdate` 中调用 `procedureOwner.Start<TargetProcedure>()` 即可切到另一个流程。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志 `Entrance procedure is invalid.` | `Entrance Procedure Type Name` 没有出现在 `Available Procedure Type Names` 列表里 | 让入口类型名与列表中某一项完全一致 |
| 日志 `Can not find procedure type 'X'.` | 类型全名拼写错误,或该类型不在运行时能加载到的程序集里 | 使用命名空间 + 类名,确认程序集已被构建 |
| 日志 `Can not create procedure instance 'X'.` | 流程类没有可访问的无参构造函数 | 为 `Process` 子类显式添加无参构造函数(不显式写也会自动生成,但若定义了带参构造会被覆盖) |
| 抛 `You must initialize procedure first.` | 在调用 `Initialize` 之前就访问了 `CurrentProcedure`、`StartProcedure` 等 | 先 `Initialize`,再 `StartProcedure`;或确认 `ProcedureComponent` 的 `Start` 已执行 |
| 抛 `Procedures is invalid.` | 传给 `Initialize` 的流程数组长度为 0 | 至少传入一个流程实例 |
| 重复 `Initialize` 报 `Already exist FSM` | 同时使用了组件自动初始化与 StartupRunner,或多次手动 `Initialize` | 二选一:要么关闭 `Use Startup Runner`,要么让组件只注册接口、由外部统一初始化 |

## 背景(可选)

`ProcedureManager` 本质是一个 `GameFrameworkModule`,内部通过 `IFsmManager.CreateFsm(this, procedures)` 把所有流程注册成有限状态机的状态,`ProcedureBase` 派生自 `FsmState<IProcedureManager>`,因此流程之间的切换、销毁都直接复用 FSM 能力。`ProcedureComponent` 只是负责在 Unity 生命周期里把类型名反射成实例并喂给 `ProcedureManager`。

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)
