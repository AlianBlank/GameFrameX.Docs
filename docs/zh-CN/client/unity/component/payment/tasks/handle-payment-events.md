# 如何处理支付结果事件

在 `PaymentComponent` 上订阅 4 个支付事件（购买成功、购买失败、查询购买记录结果、消耗购买结果），在回调里根据 `PaymentEventArgs.ResultCode` 分发处理，并用 `PurchaseToken` 完成消耗。全部 API 定义于 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64) 与 [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)。

## 前置条件

- 场景中已存在 GameFrameX 根对象，并挂有 `PaymentComponent`（菜单 `GameFrameX/Payment`，组件要求同时存在 `GameFrameXPaymentCroppingHelper`）。
- 已调用 `Init()` 初始化支付管理器，且 `IsReady()` 返回 `true` 后再发起购买：

```csharp
// 签名：public void Init(bool isDebug = false, bool isClientVerify = true)
// 签名：public bool IsReady()
paymentComponent.Init(isDebug: false, isClientVerify: true);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115)

## 操作步骤

1. 获取 `PaymentComponent` 引用（例如通过 GameFrameX 模块入口）。
2. 在游戏启动阶段订阅事件，在销毁阶段对称退订（`PaymentComponent` 直接透传到内部 `IPaymentManager`）：

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseSuccess += OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed += OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult += OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult += OnConsumePurchaseResult;

// 退出/销毁时
paymentComponent.OnPurchaseSuccess -= OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed -= OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult -= OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult -= OnConsumePurchaseResult;
```

事件在组件上的真实声明如下（`add`/`remove` 直接转发给管理器）：

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}

public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L64)

3. 在回调中按 `ResultCode` 分支处理，并通过 `PaymentEventArgs` 的字段取数据：

```csharp
private void OnPurchaseSuccess(object sender, PaymentEventArgs e)
{
    // e.ProductId / e.OrderId / e.PurchaseToken / e.PurchaseData / e.CustomData
}

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    switch (e.ResultCode)
    {
        case PaymentResultCode.Cancelled:
            // 用户主动取消，一般静默处理
            break;
        case PaymentResultCode.NetworkError:
        case PaymentResultCode.ServiceUnavailable:
            // 提示稍后重试
            break;
        case PaymentResultCode.ItemAlreadyOwned:
        case PaymentResultCode.VerifyFailed:
        default:
            // 用 e.ErrorMessage 展示或上报
            break;
    }
}
```

4. 一次性商品发货成功后，用回调里的 `PurchaseToken` 调用 `ConsumePurchase` 消耗购买，其结果同样通过 `OnConsumePurchaseResult` 事件返回：

```csharp
// 签名：public void ConsumePurchase(string purchaseToken)
paymentComponent.ConsumePurchase(e.PurchaseToken);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L133-L152)

## 常见变体

- **补单/恢复购买**：调用 `QueryPurchases(PaymentProductType)` 后监听 `OnQueryPurchasesResult`，对 `ResultCode == PaymentResultCode.Success` 的历史订单逐个发货并 `ConsumePurchase(e.PurchaseToken)`。
- **只关心结果码**：`OnPurchaseSuccess` 与 `OnPurchaseFailed` 均携带同一 `PaymentEventArgs` 结构，失败场景额外依赖 `ErrorMessage`。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志出现 `You are using DefaultPaymentManager which is a stub...` | Editor/非移动平台落到占位实现，事件不会触发 | 接入渠道实现（如 Google/Apple），或在真机验证 |
| 日志出现 `Pay Manager is invalid.` | 管理器模块未正确加载 | 检查 `PaymentComponent` 与裁剪辅助组件是否齐全 |
| 日志出现 `Purchase token is null or empty.` | 调 `ConsumePurchase` 传了空令牌 | 使用回调返回的 `e.PurchaseToken` |

上述警告/错误原文来自 [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L48) 与 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L152)。

## 验证

- 订阅后发起一次 `Buy(new PurchaseParams(...))`，确认 `OnPurchaseSuccess` 或 `OnPurchaseFailed` 至少触发一次，且 `e.ProductId`、`e.OrderId` 与发起参数一致。
- `ConsumePurchase` 调用后确认 `OnConsumePurchaseResult` 返回且 `ResultCode == PaymentResultCode.Success`。

## 背景

`PaymentComponent` 是薄封装：4 个事件通过 `add`/`remove` 访问器直接转发给平台实现（Android 为 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`，iOS/macOS 为 `Apple.Runtime.ApplePaymentManager`，WebGL/PC 各有对应实现，其余平台回退到 `DefaultPaymentManager` 占位）。因此事件处理逻辑与平台无关，统一在组件层订阅即可。
