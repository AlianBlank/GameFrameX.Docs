# 언어 변경 이벤트를 수신하고 UI 텍스트를 새로고침하는 방법

`LocalizationComponent.Language`에 새 언어를 할당하면 컴포넌트가 세 개의 언어 변경 이벤트를 순서대로 브로드캐스트합니다. UI 스크립트에서 그중 하나를 구독하면(`LocalizationLanguageChangeAfterEventArgs` 권장) 콜백에서 이전 언어와 새 언어를 얻어 UI 텍스트를 새로고침할 수 있습니다.

## 사전 조건

- 프로젝트에서 GameFrameX의 Localization 및 Event 컴포넌트가 활성화되어 있어야 합니다.
- 씬에 `LocalizationComponent`가 존재해야 합니다: 언어 전환 시 이 컴포넌트가 의존하는 `SettingComponent`를 통해 언어 설정을 영속화하고, `EventComponent`를 통해 이벤트를 발생시킵니다.

## 작업 단계

세 이벤트는 모두 동일한 데이터(`Language` 새 언어, `OldLanguage` 이전 언어)를 전달하므로 필요에 따라 하나를 선택해 구독하면 됩니다:

| 이벤트 인자 클래스 | 발생 순서 | 적용 시나리오 |
|------|------|------|
| `LocalizationLanguageChangeBeforeEventArgs` | 1 | 전환 프로세스에서 가장 먼저 통지를 받으며, 전환 전 기록/준비 작업에 적합 |
| `LocalizationLanguageChangeEventArgs` | 2 | 일반 언어 변경 이벤트 |
| `LocalizationLanguageChangeAfterEventArgs` | 3 | 전환 완료 통지, 여기서 UI 텍스트를 새로고침하는 것을 권장 |

세 이벤트는 `Language` setter 안에서 동기적이고 연속적으로 발생합니다:

```csharp
set
{
    if (m_LocalizationManager.Language != value)
    {
        var oldLanguage = m_LocalizationManager.Language;
        m_LocalizationManager.Language = value;
        m_SettingComponent.SetString(nameof(LocalizationComponent) + "." + nameof(Language), value);
        m_SettingComponent.Save();
        var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
        var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
        var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
    }
}
```

소스: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L155-L171)

### 1. 이벤트 처리 메서드 작성

콜백 매개변수로 해당 이벤트 인자 클래스를 직접 사용하고, 여기서 새 언어와 이전 언어를 읽어옵니다:

```csharp
private void OnLanguageChanged(object sender, LocalizationLanguageChangeAfterEventArgs e)
{
    Debug.Log($"语言由 {e.OldLanguage} 切换为 {e.Language}");
    // 여기서 e.Language에 따라 텍스트를 다시 가져와 이 UI의 모든 텍스트 컨트롤을 새로고침합니다
}
```

이벤트 인자 클래스의 `Language` / `OldLanguage` 정의와 `EventId`는 다음과 같으며, `EventId`는 타입의 전체 이름입니다:

```csharp
[Preserve] public static readonly string EventId = typeof(LocalizationLanguageChangeAfterEventArgs).FullName;

[Preserve]
public string Language { get; private set; }   // 현재(새) 언어

[Preserve]
public string OldLanguage { get; private set; } // 이전 언어
```

소스: [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41-L67)

### 2. 리스너 등록 및 해제

이벤트는 GameFrameX의 Event 컴포넌트를 통해 발생합니다(`m_EventComponent.Fire(...)`). `EventId` 상수로 리스너를 등록하고, UI가 파괴/비활성화될 때 구독을 해제하는 일반적인 작성 예시입니다:

```csharp
private void OnEnable()
{
    GameEntry.Event.AddListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}

private void OnDisable()
{
    GameEntry.Event.RemoveListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}
```

> 참고: `AddListener` / `RemoveListener`의 정확한 시그니처는 com.gameframex.unity.event 패키지를 기준으로 합니다. 이 저장소의 로컬라이제이션 컴포넌트는 `EventId`(타입 전체 이름, 즉 `GameFrameX.Localization.Runtime.LocalizationLanguageChangeAfterEventArgs`)로 이벤트를 발생시키는 역할만 담당합니다.

### 3. 언어 전환으로 이벤트 트리거

`Language`에 현재와 다른 언어 값을 할당하면 세 이벤트가 모두 트리거됩니다:

```csharp
GameEntry.GetComponent<LocalizationComponent>().Language = "ChineseSimplified";
```

할당과 동시에 언어가 설정에 자동으로 기록되어(키 이름 `LocalizationComponent.Language`) 저장되며, 다음 실행 시 다시 읽어올 수 있습니다.

### 4. 콜백에서 텍스트 새로고침

1단계의 콜백에서 `e.Language`(또는 컴포넌트의 현재 `Language`)에 따라 해당 언어의 텍스트를 다시 로드하고 각 텍스트 컨트롤을 업데이트합니다. UI를 다시 빌드할 필요 없이 언어 관련 컨트롤만 새로고침해도 됩니다.

## 검증

- 언어 전환 후 1단계 콜백의 로그에 이전 언어와 새 언어가 출력되어야 합니다;
- 언어를 현재와 동일한 값으로 설정하면 콜백은 트리거되지 **않습니다**(setter에 `!=` 판단이 있음, 위 소스 157행 참조).

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 언어 전환 후 콜백이 실행되지 않음 | 리스너 등록 시 사용한 ID가 이벤트의 실제 ID와 일치하지 않음 | 이벤트 클래스에 내장된 상수 `LocalizationLanguageChangeAfterEventArgs.EventId`를 통일해 사용하고, 문자열을 직접 작성하지 마세요 |
| 콜백에서 읽은 언어가 `UnknownLocalization`임 | 이벤트 인자의 참조 풀 재사용을 올바르게 처리하지 않음 | 콜백 내에서 `e.Language` / `e.OldLanguage`를 즉시 사용하고, 이벤트 인자 객체 자체를 캐시하지 마세요 |
| 언어를 반복 전환한 후 중복 이벤트가 수신됨 | 구독 해제 시점이 잘못되었거나 중복 등록됨 | `OnEnable`에서 등록, `OnDisable`에서 해제하여 항상 쌍을 이루도록 합니다 |
| 동일한 언어 설정 후 텍스트를 새로고침하려 해도 반응이 없음 | setter가 동일한 값이면 단락되어 이벤트를 발생시키지 않음 | 강제 새로고침이 필요할 때는 호출부에서 직접 새로고침 로직을 트리거하거나, 대상 언어 외의 값을 먼저 설정한 뒤 다시 전환하세요 |

## 배경

세 이벤트 인자 클래스는 모두 `GameEventArgs`를 상속하며, 인스턴스는 `ReferencePool.Acquire<T>()`로 획득합니다(참조 풀 재사용). 따라서 이벤트 인자 객체를 장기간 보유하지 마세요. 언어 변경은 `LocalizationComponent.Language`의 setter에서 일괄적으로 구동됩니다. 먼저 관리자의 언어를 업데이트하고 설정을 영속화한 다음, "Before → Change → After" 순서로 세 이벤트를 동기적으로 발생시키므로, 리스너는 순서 차이를 구분할 필요 없이 아무거나 하나를 선택하면 됩니다.

이벤트 발생과 언어 기록 로직은 setter 내에 집중되어 있으며, 관련 소스 코드는 다음과 같습니다:

- [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L155-L171) — 언어 할당, 설정 영속화 및 세 이벤트 발생
- [LocalizationLanguageChangeBeforeEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeBeforeEventArgs.cs#L1-L80) — 전환 전 이벤트 인자
- [LocalizationLanguageChangeEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeEventArgs.cs#L11-L33) — 일반 변경 이벤트 인자
- [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41-L116) — 전환 후 이벤트 인자와 `EventId`

로컬라이제이션 컴포넌트의 전체 아키텍처와 사용법에 대해서는 개요 페이지를 참조하세요.
