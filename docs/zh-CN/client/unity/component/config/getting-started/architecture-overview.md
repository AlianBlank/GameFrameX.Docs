# 工作原理:Config 组件架构速览

Config 组件以 `ConfigComponent` 为入口,通过 `IConfigManager` 接口把配置项交给 `ConfigManager` 模块统一管理;运行时按 `IDataTable` 接口异步加载、缓存并向业务层提供键值访问。本页用一张图说清"组件—模块—数据表"三层关系,以及一段从加载到读取的最小代码路径。

## 快速开始

1. 在场景里给 `GameFramework` GameObject 添加 `ConfigComponent`(组件菜单:`GameFrameX/Config`)。
2. 业务侧通过 `GameEntry.GetComponent<ConfigComponent>()` 拿到组件。
3. 组件在 `Awake()` 中调用 `GameFrameworkEntry.GetModule<IConfigManager>()` 解析出 `ConfigManager` 实例([ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85))。
4. 任意 `IDataTable` 子类调用自身的 `LoadAsync()`,加载完成后通过 `ConfigManager.AddConfig(configName, table)` 注册,后续可用 `HasConfig` / `GetConfig` 查询。

```csharp
var configComp = GameEntry.GetComponent<ConfigComponent>();
var module = GameFrameworkEntry.GetModule<IConfigManager>();
module.AddConfig("MyTable", myDataTable);   // IDataTable 由 BaseDataTable<T> 派生
```

## 工作原理速览

整体分为三层:**Unity 组件层**(`ConfigComponent`)、**框架模块层**(`IConfigManager` / `ConfigManager`)、**数据表层**(`IDataTable` / `BaseDataTable<T>`)。组件层负责在 Unity 生命周期里把模块解析出来,模块层负责以 `ConcurrentDictionary<string, IDataTable>` 维护配置集合,数据表层负责具体的加载、解析、键值查询。

各层职责一览:

| 层 | 关键类型 | 文件 | 主要职责 |
|----|----------|------|----------|
| 组件层 | `ConfigComponent` | [ConfigComponent.cs](/Runtime/Config/ConfigComponent.cs) | 在 `Awake()` 中解析 `IConfigManager` 模块;通过 `[GameFrameXAutoComponent(-5000)]` 自动注入到 GameFramework |
| 模块层 | `IConfigManager`、`ConfigManager` | [IConfigManager.cs](/Runtime/Config/Config/IConfigManager.cs)、[ConfigManager.cs](/Runtime/Config/Config/ConfigManager.cs) | 以 `ConcurrentDictionary<string, IDataTable>` 维护配置项,暴露 `Add` / `Remove` / `Has` / `Get` 接口 |
| 数据表层 | `IDataTable`、`BaseDataTable<T>` | [IDataTable.cs](/Runtime/Config/Config/IDataTable.cs)、[BaseDataTable.cs](/Runtime/Config/Config/BaseDataTable.cs) | 负责单张表的异步加载、键索引与查询 |
| 事件层 | `LoadConfigSuccessEventArgs` 等 | [LoadConfigSuccessEventArgs.cs](/Runtime/EventArgs/LoadConfigSuccessEventArgs.cs) | 加载成功 / 失败 / 进度事件,业务侧订阅即可感知 |

## 关键 API 与默认值

`IConfigManager` 是模块层的对外契约,签名直接来源于源码:

| 成员 | 签名 | 默认值 / 说明 |
|------|------|---------------|
| `Count` | `int Count { get; }` | 当前已注册的配置项数量,取自内部字典 `m_ConfigDatas.Count` |
| `HasConfig` | `bool HasConfig(string configName)` | 名称匹配使用 `StringComparer.Ordinal` |
| `AddConfig` | `void AddConfig(string configName, IDataTable configValue)` | 写入 `m_ConfigDatas` |
| `RemoveConfig` | `bool RemoveConfig(string configName)` | 从字典中移除指定配置项 |
| `GetConfig` | `IDataTable GetConfig(string configName)` | 按名称取回 `IDataTable` |
| `RemoveAllConfigs` | `void RemoveAllConfigs()` | 清空全部配置项 |
| `Shutdown` | `void Shutdown()` | 释放所有 `IDataTable` 并清空字典 |

`ConfigComponent` 的相关关键代码:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Config")]
[GameFrameXAutoComponent(-5000)]
public sealed class ConfigComponent : GameFrameworkComponent
{
    protected override void Awake()
    {
        ImplementationComponentType = Utility.Assembly.GetType(componentType);
        InterfaceComponentType = typeof(IConfigManager);
        base.Awake();
        m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
        if (m_ConfigManager == null)
        {
            Log.Fatal("Config manager is invalid.");
            return;
        }
    }
}
```

`ConfigManager` 用 `ConcurrentDictionary<string, IDataTable>` 存放所有表,并发安全;每个 key 的字符串比较采用 `StringComparer.Ordinal`,大小写敏感:

```csharp
public sealed partial class ConfigManager : GameFrameworkModule, IConfigManager
{
    private readonly ConcurrentDictionary<string, IDataTable> m_ConfigDatas;

    public ConfigManager()
    {
        m_ConfigDatas = new ConcurrentDictionary<string, IDataTable>(StringComparer.Ordinal);
    }
}
```

`IDataTable` 是非泛型数据表接口,核心方法 `LoadAsync()` 返回 `Task`,用于异步加载:

```csharp
[Preserve]
public interface IDataTable
{
    [Preserve]
    Task LoadAsync();
    int Count { get; }
    // ... 取行 / 索引 等成员
}
```
