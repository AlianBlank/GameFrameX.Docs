# First Available Procedure

Follow the steps on this page to attach a `ProcedureComponent` to your Unity project, write two `ProcedureBase` subclasses, and launch the entry procedure so the game starts running immediately after launch.

## Prerequisites

- The `com.gameframex.unity.procedure` package is installed, along with its dependencies `com.gameframex.unity.fsm` and `com.gameframex.unity.runtime`.
- The `GameFramework` GameObject in the project's entry scene has a `ProcedureComponent` component attached (`[AddComponentMenu("GameFrameX/Procedure")]`).
- You are familiar with C# class inheritance and basic Unity Inspector usage.

## Steps

1. **Create a procedure class**. Create `LaunchProcedure` (the launch procedure, typically responsible for initializing base systems), inheriting from `ProcedureBase`:

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

public sealed class LaunchProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // Perform base module initialization here, such as configuration, logging, resources, etc.
    }
}
```

`ProcedureBase` inherits from `FsmState<IProcedureManager>`, and provides six built-in lifecycle hooks: `OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy`. Override them as needed.

Source: [ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

2. **Create a second procedure** (for example `MainProcedure`), used for subsequently switching to the main UI or main logic:

```csharp
using GameFrameX.Procedure.Runtime;

public sealed class MainProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // Launch scene, load UI, start main loop
        ChangeState<MainProcedure>(procedureOwner); // Custom transition example
    }
}
```

3. **Configure the procedure list in the Inspector**. Select the GameObject with `ProcedureComponent` attached, and fill in the following fields:

| Field | Purpose | Example |
|------|------|------|
| `Available Procedure Type Names` | The full names (namespace + class name) of all procedure types the framework should create and add to the state machine | `MyGame.LaunchProcedure`, `MyGame.MainProcedure` |
| `Entrance Procedure Type Name` | The full type name of the entry procedure at launch; must appear in the list from the previous step | `MyGame.LaunchProcedure` |

Type names are looked up via reflection, so the class must be findable by `Utility.Assembly.GetType` and must have a parameterless constructor. The component will automatically call `Activator.CreateInstance` and initialize in `Start`.

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L129-L168)

4. **Enter Play Mode**. The framework will perform the following actions in `Start`:

   - Reflectively create all procedure instances.
   - Call `m_ProcedureManager.Initialize(IFsmManager, procedures)` to register them with the FSM.
   - Wait until the end of the frame and then call `m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType())` to start the entry procedure.

   Once `OnEnter` of the entry procedure is triggered, your first available procedure is up and running.

## Common Variations

- **Manual startup takeover (StartupRunner mode)**: Check `Use Startup Runner = true` on `ProcedureComponent`. The component's `Awake` only registers `IProcedureManager` and does not automatically call `Initialize/StartProcedure`; `ApplicationStartupEntry` takes over initialization and startup via `StartupRunner.Run` at the location you specify, which avoids duplicate `Initialize` throwing "Already exist FSM".

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L127)

- **No component attached, pure code initialization**: After obtaining `IFsmManager` and `IProcedureManager`, manually construct the procedure array and call `Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures)`, then `StartProcedure<T>()`.

  Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L156)

- **Switching procedures at runtime**: Call `procedureOwner.Start<TargetProcedure>()` in a procedure's `OnEnter` / `OnUpdate` to switch to another procedure.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Log `Entrance procedure is invalid.` | `Entrance Procedure Type Name` does not appear in the `Available Procedure Type Names` list | Make the entry type name exactly match an item in the list |
| Log `Can not find procedure type 'X'.` | The full type name is misspelled, or the type is not in an assembly loadable at runtime | Use namespace + class name, and confirm the assembly has been built |
| Log `Can not create procedure instance 'X'.` | The procedure class has no accessible parameterless constructor | Explicitly add a parameterless constructor to the `Process` subclass (one is auto-generated if not written explicitly, but is overridden if a parameterized constructor is defined) |
| Throws `You must initialize procedure first.` | Accessed `CurrentProcedure`, `StartProcedure`, etc. before calling `Initialize` | Call `Initialize` first, then `StartProcedure`; or confirm `ProcedureComponent`'s `Start` has executed |
| Throws `Procedures is invalid.` | The procedure array passed to `Initialize` has length 0 | Pass at least one procedure instance |
| Duplicate `Initialize` throws `Already exist FSM` | Both component auto-initialization and StartupRunner are used, or `Initialize` is called manually multiple times | Choose one: either disable `Use Startup Runner`, or let the component only register the interface while external code performs unified initialization |

## Background (Optional)

`ProcedureManager` is essentially a `GameFrameworkModule`. Internally, it registers all procedures as states of a finite state machine via `IFsmManager.CreateFsm(this, procedures)`. `ProcedureBase` derives from `FsmState<IProcedureManager>`, so switching and destroying between procedures directly reuses FSM capabilities. `ProcedureComponent` is only responsible for reflecting type names into instances within the Unity lifecycle and feeding them to `ProcedureManager`.

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)
