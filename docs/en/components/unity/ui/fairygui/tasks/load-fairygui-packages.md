# Loading and Unloading FairyGUI Packages

Use `AddPackageSync` / `AddPackageAsync` provided by `FairyGUIPackageComponent` to load FairyGUI packages, and use `RemovePackage` to unload them by package name. When a UI form is opened, `UIManager` automatically checks and loads the corresponding package, so manual intervention is usually unnecessary.

## Prerequisites

- The project has `com.gameframex.unity.ui.fairygui` installed, and the package description file has been published in the FairyGUI editor (in Asset mode this is the `{packageName}_fui` asset; in Resources mode it is the description file path).
- A UI form has been opened through GameFrameX's `UIManager` (the automatic loading flow depends on it).

## Steps

First, familiarize yourself with the three entry methods:

| Method | Signature | Description |
|------|------|------|
| Sync loading | `void AddPackageSync(string descFilePath, bool isLoadAsset = true)` | Internally calls `UIPackage.AddPackage`, suitable for packages under the Resources directory |
| Async loading | `Task<UIPackage> AddPackageAsync(string descFilePath, bool isLoadAsset = true)` | Returns an awaitable task, suitable for Bundle loading |
| Unload | `void RemovePackage(string packageName)` | Looks up and removes from the loaded dictionary by package name (Name) |

1. **When synchronous loading is needed** (e.g., the package is located in the Resources directory and not in a Bundle): call `AddPackageSync` and pass in the description file path. `isLoadAsset` defaults to `true`, which calls `LoadAllAssets()` after registering the package to preload all assets.

```csharp
public void AddPackageSync(string descFilePath, bool isLoadAsset = true)
{
    if (!m_UILoadedPackages.TryGetValue(descFilePath, out var packageData))
    {
        var package = UIPackage.AddPackage(descFilePath);
        packageData = new UIPackageData(descFilePath, package.name, isLoadAsset);
        packageData.SetPackage(package);
        m_UILoadedPackages[descFilePath] = packageData;
        if (isLoadAsset)
        {
            packageData.Package.LoadAllAssets();
        }
    }
}
```

2. **When asynchronous loading is needed** (the package is in an AssetBundle): `await AddPackageAsync(descFilePath)`. Duplicate requests for the same `descFilePath` reuse the same `TaskCompletionSource` and will not load a second time.

```csharp
var tcs = new TaskCompletionSource<UIPackage>();

void Complete(UIPackage uiPackage)
{
    m_UIPackageLoading.Remove(descFilePath);
    packageData = new UIPackageData(descFilePath, uiPackage.name, isLoadAsset);
    packageData.SetPackage(uiPackage);
    if (isLoadAsset)
    {
        packageData.Package.LoadAllAssets();
    }

    m_UILoadedPackages[descFilePath] = packageData;
    tcs.TrySetResult(packageData.Package);
}

m_UIPackageLoading[descFilePath] = tcs;
UIPackage.AddPackageAsync(descFilePath, Complete);
return tcs.Task;
```

3. **In most cases manual loading is not required**: when opening a UI form, `UIManager` first checks whether the package is already loaded (`FairyGuiPackage.Has(packageName)`); if the path does not contain the Bundle directory name, it goes through synchronous loading, otherwise it loads asynchronously and then loads the `{packageName}_fui` asset.

In the Bundle branch, the package name is taken from the last segment of `uiFormAssetPath` (if there is no `/`, the whole string is used as the package name); when the asset name differs from the package name, the path is reassembled using the package name and the `_fui` suffix is appended:

```csharp
if (packageName == uiFormAssetName)
{
    // If the UI asset name matches the package name, load directly
    await FairyGuiPackage.AddPackageAsync(assetPath);
}
else
{
    // Otherwise, reassemble the path
    string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
    await FairyGuiPackage.AddPackageAsync(newPackagePath);
}

string newAssetPackagePath = assetPath;
if (packageName != uiFormAssetName)
{
    newAssetPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
}

newAssetPackagePath += "_fui";
// Load from the package
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

## Common Variants

- **Register the package only, without immediately loading all assets**: pass `isLoadAsset: false` to `AddPackageSync` / `AddPackageAsync` to skip `LoadAllAssets()`; assets are then loaded on demand when components are instantiated. Suitable for scenarios where a single package contains large assets but only some of its UI forms are used at a time.
- **Loading the same package repeatedly**: `AddPackageAsync` deduplicates internally via `m_UIPackageLoading` — while the same `descFilePath` is still loading, the existing `tcs.Task` is returned directly; once loading has completed, `Task.FromResult(packageData.Package)` is returned via `m_UILoadedPackages`. Therefore calling the same package multiple times is safe and will not create duplicate instances.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| UI form fails to open, the callback goes to `LoadAssetFailureCallback` | In the Bundle branch, the `{packageName}_fui` asset fails to load (the asset was not built into the Bundle, or the path does not match) | Confirm the FairyGUI published output has been imported, and that the last segment of `uiFormAssetPath` matches the package name, or that `{packageName}/{packageName}_fui` exists in the directory when they differ |
| The package still takes effect after `RemovePackage` | A description file path was passed instead of the package name | Call `RemovePackage` with `UIPackage.name` (i.e., the `Name` recorded at load time) |
| A package under the Resources directory can never be loaded asynchronously | When `assetPath` does not contain the Bundle directory name (`Utility.Asset.Path.BundlesDirectoryName`), the synchronous branch is forced | Use `AddPackageSync` in Resources mode; if async is required, move the package into a Bundle directory |
| The same package gets loaded into multiple instances | `UIPackage.AddPackage` was called directly, bypassing `FairyGUIPackageComponent` | Always go through `AddPackageSync` / `AddPackageAsync` and let the dictionaries inside the component deduplicate |

## Background (Optional)

`FairyGUIPackageComponent` maintains package state with two dictionaries: `m_UIPackageLoading` (loading, `descFilePath → TaskCompletionSource`) and `m_UILoadedPackages` (loaded, `descFilePath → UIPackageData`). After loading completes, the entry is written to the latter and removed from the former; when unloading, the `descFilePath` is looked up by `Name` and then removed from FairyGUI's `UIPackage` registry. For the overall GameFrameX UI architecture and the division of responsibilities among components, see the Overview page.
