# What to Do When Accessing GameApp.{Name} Returns null or Throws a Null Reference

Accessing `GameApp.XXX` (e.g., `GameApp.Asset`, `GameApp.Base`) returning `null` or throwing a `NullReferenceException` is usually caused by the corresponding component not being registered to `GameEntry` at startup, or by accessing the property before the framework has been initialized. `GameApp` is merely a cached wrapper around `GameEntry.GetComponent<T>()`; the actual component instances are managed by `GameEntry`.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `GameApp.XXX` returns `null` | The corresponding component is not registered to `GameEntry`, or the corresponding macro/conditional compilation is not enabled | Confirm the component class is attached to the `GameEntry` startup prefab/registration flow, and enable the corresponding macro (e.g., `ENABLE_GAME_FRAME_X_ASSET`) |
| Accessing `GameApp.XXX` early in `Awake`/`Start` reports null | Framework initialization has not completed | Call it after the framework initialization callback (e.g., `GameEntry.OnGameFrameInitialized`), or after `OnEnable` in your business scripts |
| Throws `NullReferenceException: Object reference not set to an instance of an object` | No null check before calling, and the component is not registered | Add a null check, and fix the registration/call timing as described in the two rows above |
| Throws `KeyNotFoundException` / component type not found | The component DLL/assembly is not included in the project, or the namespace is inconsistent | Confirm the assembly containing the component is referenced, and add `using GameFrameX.Runtime;` |
| Suddenly becomes null after enabling/disabling a macro | The component is entirely excluded by `#if` conditional compilation, and the `GameApp.XXX` field does not exist | Do not access the property outside the `#if` block; use `GameEntry.GetComponent<T>()` as a fallback |

## Fix Steps

### 1. Confirm the Component Is Registered to GameEntry

`GameApp` is essentially implemented as a lazy retrieval of components from `GameEntry`:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }

    private static BaseComponent _base;
}
```

Source: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L52)

If `GameEntry.GetComponent<BaseComponent>()` cannot find the component, `_base` will remain `null`. Check whether components such as `BaseComponent` are attached to `GameEntry`'s initialization list in the startup flow.

### 2. Check Conditional Compilation Macros

Many `GameApp.XXX` properties are wrapped in macros. For example, `GameApp.Asset` requires `ENABLE_GAME_FRAME_X_ASSET`:

```csharp
#if ENABLE_GAME_FRAME_X_ASSET
public static partial class GameApp
{
    public static AssetComponent Asset
    {
        get
        {
            if (_asset == null)
            {
                _asset = GameEntry.GetComponent<AssetComponent>();
            }
            return _asset;
        }
    }

    private static AssetComponent _asset;
}
#endif
```

Source: [Runtime/GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs#L32-L55)

If the corresponding macro is not defined, the `GameApp.Asset` property does not exist at compile time, and accessing it directly will cause a compilation error. Conversely, **if you enable the macro and use the corresponding `GameApp.XXX` in your code, you must also ensure the corresponding component is registered to `GameEntry`**.

### 3. Access After Framework Initialization Completes

`GameApp`'s fields are lazily loaded static caches. If you access them in a lifecycle phase before the framework's `Awake` (e.g., in another singleton's `Awake`), the components may not have finished registering yet. Access them after the framework initialization event fires, or in your business script's `OnEnable` / `Start`.

### 4. Add Null Check Protection

Even if the component is registered, it is recommended to perform a null check before calling, to avoid accessing it when the game is stopped in the editor or during the resource release phase:

```csharp
if (GameApp.Asset != null)
{
    GameApp.Asset.LoadAsset(...);
}
```

If you frequently need null checks, it means the component should not be used there in the first place—go back to step 1 to check the registration.

## Verification

Perform the following 3 steps to confirm the issue is resolved:

1. Print key properties such as `GameApp.Base` in `Awake` to confirm they are not `null`.
2. Use `GameEntry.GetComponent<T>()` to double-check that the component exists.
3. Trigger an actual call in the scene (e.g., load an asset, fire an event) and observe whether null references still occur.

If `GameEntry.GetComponent<T>()` always returns `null`, the problem lies in the component registration flow itself, not in the `GameApp` layer—go back to `GameEntry`'s initialization code to troubleshoot component attachment and lifecycle ordering.
