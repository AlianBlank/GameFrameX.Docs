# 熱修復啟動器(Hotfix Launcher)整合方式(IHotfixLauncher)

實作 `IHotfixLauncher` 介面後，啟動流程會在資源修補完成後呼叫使用者的熱修復方案(HybridCLR、ILRuntime、自行開發的方案等)，至於如何載入組件並進入熱修復進入點，則由應用程式層決定。

## 前置條件

- 啟動流程必須已正確初始化(請參閱啟動流程整合文件)。
- 必須已準備好 `StartupOptions` 設定資產，並填入 `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`。
- 必須已匯入 `GameFrameX.Startup.Runtime` 命名空間與 `Cysharp.Threading.Tasks`。

## 介面合約

`IHotfixLauncher` 僅公開一個非同步方法，無論成功或失敗都必須回傳 `HotfixLaunchResult`,且不得直接拋出例外。

```csharp
using Cysharp.Threading.Tasks;

namespace GameFrameX.Startup.Runtime
{
    /// <summary>
    /// 熱修復啟動介面，由應用程式層實作。套件不綁定於特定熱修復方案(HybridCLR / 其他)。
    /// </summary>
    public interface IHotfixLauncher
    {
        UniTask<HotfixLaunchResult> StartAsync(StartupOptions options);
    }
}
```

Source: [IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L1-L17)

## 作業步驟

1. 在應用程式專案底下建立新類別(例如:`MyHotfixLauncher`)並實作 `IHotfixLauncher`。
2. 在 `StartAsync` 中依據 `options` 讀取熱修復 DLL/組件，並透過反射呼叫進入方法(建立並回傳 `HotfixLaunchResult.Succeed()` 或 `HotfixLaunchResult.Fail(message)`)。
3. 請勿在 `StartAsync` 中拋出例外 — 失敗時請建立並回傳 `HotfixLaunchResult.Fail("錯誤訊息")`,啟動框架會據此進入失敗分支並發佈 `StartupFailedEventArgs`。
4. 將 `MyHotfixLauncher` 實例注入至啟動管理器(通常透過 `StartupManager` 的注入介面或 `GameObject` 拖曳設定)，以覆蓋框架的預設 Launcher。
5. 執行啟動流程。當 Patch 階段全部完成後，框架會自動呼叫 `StartAsync`。

## 常見變體

- **HybridCLR 方案**：在 `StartAsync` 中透過 `HybridCLR.RuntimeApi.LoadDllFromMemory` 載入 DLL 後，以 `System.Reflection.Assembly` 反射呼叫進入方法。
- **純資源熱修復(無 DLL)**:以 `Resources.Load<GameObject>` 直接載入預製物件後 `Instantiate`,進入邏輯中可跳過反射步驟。
- **需要初始化階段的方案**：若熱修復框架需要非同步初始化(例如：下載、驗證),請在 `StartAsync` 內 `await` 完成後再回傳 `Succeed`。

## 常見錯誤

| 現象 | 原因 | 解決方式 |
|------|------|------|
| 啟動時當機或黑畫面 | `StartAsync` 中發生未處理的例外 | 改為在捕捉例外後回傳 `HotfixLaunchResult.Fail(message)` |
| 回傳 `Success=true` 但遊戲未進入主場景 | 進入方法名稱/類型名稱拼寫錯誤 | 確認 `StartupOptions` 的 `HotfixEntryTypeName` / `HotfixEntryMethodName` 與 DLL 完全一致 |
| 持續停留在 Patch 階段 | 未注入自訂 `IHotfixLauncher`,導致框架使用預設的空實作 | 在啟動管理器中替換為自行實作的類別 |

## 背景(選用)

`IHotfixLauncher` 是套件刻意公開的擴充點。套件內部僅規範「Patch 完成 → 呼叫 Launcher → 取得結果」此一協定，不綁定於特定熱修復方案，以避免與 HybridCLR 等第三方套件產生強耦合。
