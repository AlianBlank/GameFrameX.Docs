# 啟動失敗或資料庫連線錯誤時的處理方式

當服務在啟動過程中崩潰，或日誌中出現 Mongo 連線錯誤時，問題通常是 `--DataBaseUrl` / `--DataBaseName` 配置錯誤、Mongo 容器尚未就緒，或網路/驗證失敗。本頁面將協助您快速定位並修復問題。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| 啟動日誌中包含 `connection refused` / `No connection could be made` | Mongo 連接埠無法連線或位址錯誤 | 檢查 `--DataBaseUrl` 中的主機與連接埠 |
| 啟動日誌中包含 `Authentication failed` / `authSource` 錯誤 | 驗證來源或使用者名稱/密碼不符 | 修正連線字串 `?authSource=...` 與帳號密碼 |
| 啟動日誌中包含 `Database name cannot be empty` 或缺少資料庫的提示 | 未傳遞 `--DataBaseName` 或資料庫名稱拼寫錯誤 | 加入 `--DataBaseName=xxx` |
| 容器啟動順序異常：Game 在 Mongo 之前啟動 | `depends_on` 不會等待健康檢查通過 | 使用 `condition: service_healthy` 等待 Mongo 就緒 |
| 從本機連線到 Docker 內的 Mongo 失敗 | 連接埠未開放給主機或開放的連接埠錯誤 | 檢查 `docker-compose.yml` 中的 `ports` 映射 |

## 修復步驟

### 1. 驗證 `--DataBaseUrl` 與 `--DataBaseName`

啟動參數必須明確傳遞資料庫連線字串與資料庫名稱。`docker-compose.yml` 中的預設值如下：

```yaml
command:
  - "--DataBaseUrl=mongodb://mongo:27017/?authSource=admin"
  - "--DataBaseName=gameframex"
```

來源：[docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L36-L37)

若要從本機直接連線到 Docker 內的 Mongo,請使用 `mongodb://localhost:37017/?authSource=admin`(對應 compose 檔案中的 `37017:27017` 連接埠映射)。多伺服器版本則使用 `localhost:47017` 與 `gameframex_multi`。

```yaml
ports:
  - "37017:27017"
```

來源：[docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L7-L7)

```yaml
ports:
  - "47017:27017"
```

來源：[docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L23-L23)

### 2. 等待 Mongo 健康檢查通過

Game 與 Social 服務必須等待 Mongo 的 `healthcheck` 通過後才能啟動。compose 檔案已透過 `condition: service_healthy` 強制執行此規則；請勿將其更改為 `service_started`。

```yaml
depends_on:
  mongo:
    condition: service_healthy
```

來源：[docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L21-L23)

健康檢查命令使用 `ping` 驗證可連線性：

```yaml
healthcheck:
  test: [ "CMD", "mongosh", "--quiet", "--eval", "db.runCommand({ ping: 1 }).ok" ]
  interval: 5s
  timeout: 3s
  retries: 20
```

來源：[docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L9-L12)

手動驗證 Mongo 狀態：

```bash
docker exec -it gfx-mongo mongosh --quiet --eval "db.runCommand({ ping: 1 }).ok"
# 預期輸出:1
```

### 3. 檢查資料磁碟區與持久化

多伺服器版本將 Mongo 資料掛載到 `./running-multi/mongo:/data/db`。若主機目錄權限不足或磁碟已滿，Mongo 將反覆重啟，導致 Game 連線不穩定。

```yaml
volumes:
  - "./running-multi/mongo:/data/db"
```

來源：[docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L30-L31)

請確保目錄可寫入且有足夠空間：

```bash
ls -ld ./running-multi/mongo
df -h ./running-multi/mongo
```

### 4. 修正驗證來源

預設情況下未啟用使用者名稱/密碼，`?authSource=admin` 僅作為管理員資料庫的識別。若您的 Mongo 啟用了 `mongod --auth`,則需要在 URL 中附加帳號密碼，並將 `authSource` 更改為實際的驗證資料庫(通常為 `admin`)。

```bash
# 啟用驗證時的連線字串範例
--DataBaseUrl=mongodb://user:password@mongo:27017/?authSource=admin
```

## 驗證

完成修復後，請依以下順序確認：

1. 檢查 Mongo 健康狀態:`docker ps`,並確保 `STATUS` 欄位包含 `(healthy)`。
2. 重啟 Game 服務:`docker compose up -d --force-recreate game`,並觀察日誌中不再出現 Mongo 錯誤。
3. 進入 Mongo 容器驗證資料庫已建立:`docker exec -it gfx-mongo mongosh --quiet --eval "show dbs"`。您應該能看到 `gameframex` 或 `gameframex_multi`。
4. 若仍然失敗，請收集啟動日誌(`docker logs gfx-game | tail -200`)並對照診斷表格繼續排查。

## 常見錯誤

- **使用容器內部主機名稱存取本機資料庫**。直接在主機上執行用戶端時，`--DataBaseUrl` 中的 `mongo` 主機名稱無法解析；您需要將其更改為 `localhost` 或主機的 IP。
- **修改了連接埠映射但忘記更新 URL**。修改 `ports` 後，`--DataBaseUrl` 中的連接埠也必須一併更新，否則 Game 仍會使用舊連接埠連線。
- **`depends_on` 僅指定了 `service_started`**。這只會等待容器行程啟動，而非等待 Mongo 完成初始化，導致反覆出現暫時性連線失敗。
- **Mongo 重啟後 Game 不會自動重連**。在預設的 `restart: unless-stopped` 設定下，Game 需要手動執行 `docker compose restart game` 才能重新連線。
