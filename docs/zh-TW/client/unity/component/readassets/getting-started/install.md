# 安裝與套件匯入（UPM/manifest.json/PM）

將 `com.gameframex.unity.readassets` 安裝到 Unity 專案後，即可使用 `BlankReadAssets` 來存取 StreamingAssets。此套件相容於 Unity 2019.4 及以上版本，目前發行版本為 `1.2.1`。

## 前置條件

| 項目 | 要求 |
|---|---|
| Unity 版本 | 2019.4 或更高（參見 [package.json](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/package.json#L5)） |
| 執行環境 | 編輯器 / 桌面 / 行動裝置 / Android（存取 APK 內的 StreamingAssets）皆支援 |
| 是否需要初始化 | 無需手動初始化——首次呼叫 API 時會自動完成 |

## 安裝方式

從以下四種方式中任選其一。建議使用 UPM Registry（方式一）。

### 方式一：UPM Scoped Registry（建議）

編輯專案根目錄下的 `Packages/manifest.json`，新增 `scopedRegistries` 節點，並在 `dependencies` 中加入套件名稱：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.readassets": "1.2.0"
  }
}
```

`scopes` 控制哪些套件名稱前綴會透過此 registry 解析。只有以 `com.gameframex` 開頭的套件才會從 GameFrameX registry 取得。來源：[package.json](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/package.json#L2-L41)

### 方式二：Git URL 直接引用

直接在 `Packages/manifest.json` 的 `dependencies` 中寫入 Git 位址，Unity 會拉取 `main` 分支：

```json
{
  "dependencies": {
    "com.gameframex.unity.readassets": "https://github.com/gameframex/com.gameframex.unity.readassets.git"
  }
}
```

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/README.zh-CN.md#L64-L69)

### 方式三：Unity Package Manager 介面

1. 開啟 Unity 並從選單列選取 `Window → Package Manager`。
2. 點選左上角的 `+` 按鈕，然後選取 `Add package from git URL...`。
3. 輸入位址：`https://github.com/gameframex/com.gameframex.unity.readassets.git`。
4. 點選 `Add`，等待 Unity 拉取並顯示在清單中。

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/README.zh-CN.md#L70)

### 方式四：本機複製

將儲存庫根目錄直接複製到 Unity 專案的 `Packages/` 資料夾（例如 `Packages/com.gameframex.unity.readassets/`），Unity 會自動辨識並載入。來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/README.zh-CN.md#L71)

## 安裝後驗證

在任何 C# 腳本中撰寫一次呼叫。若能成功編譯，即表示匯入成功：

```csharp
using GameFrameX.ReadAssets;

// 取得 StreamingAssets 根目錄路徑
string root = BlankReadAssets.Root;
```

若想提前初始化（可選），可在主執行緒上手動呼叫：

```csharp
BlankReadAssets.Initialize();
```

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/README.zh-CN.md#L76-L84)

## 常見變化

### 固定到特定版本（方式一 + 方式二）

- Registry 方式：將 `"1.2.0"` 取代為想要固定的 SemVer 版本，例如 `"1.2.1"`。
- Git URL 方式：在位址後面加上 `#v1.2.1`，例如 `https://github.com/gameframex/com.gameframex.unity.readassets.git#v1.2.1`。

### 匯入範例

此套件在 `Samples~` 目錄中包含一個名為 `Better Streaming Assets Samples` 的範例場景。安裝完成後，可在 Package Manager 套件詳情頁面的 `Samples` 分頁中匯入。來源：[package.json](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/package.json#L7-L12)

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|---|---|---|
| Package Manager 回報 `Could not resolve package`，指出找不到 `com.gameframex.unity.readassets` | 未設定 `scopedRegistries` 或 `scopes` 撰寫錯誤 | 依照「方式一」在 `manifest.json` 中新增 GameFrameX registry，`scopes` 必須為 `["com.gameframex"]` |
| 方式二 / 方式三拉取速度極慢甚至失敗 | 網路無法存取 `github.com` | 改用方式一（使用 GameFrameX UPM registry）或方式四（本機複製） |
| 匯入後，Unity 主控台回報找不到 `BlankReadAssets` 命名空間 | 套件實際上並未解析進專案，通常是因為 dependencies 中存在同名的舊套件 | 開啟 `Packages/manifest.json`，確認 `com.gameframex.unity.readassets` 是唯一相符的項目，刪除 lock 檔案後重試 |
| 在 Android 上讀取 StreamingAssets 時回報 `IOException` | 使用了 `System.IO.File` 直接讀取 APK 內部路徑 | 這正是此套件要解決的問題——請改用 `BlankReadAssets.ReadAllBytes(...)` 等 API |

## 背景說明（選讀）

此套件建構於 [BetterStreamingAssets](https://github.com/gwiazdorrr/BetterStreamingAssets) 之上，提供 `System.IO` 風格的統一 API。所有公開 API 皆以 `[Preserve]` 標註，可安全用於 IL2CPP 建置。套件資訊（名稱、版本、Unity 版本需求、registry 位址等）集中維護於 [package.json](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/package.json)。
