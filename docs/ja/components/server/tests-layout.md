## テスト実行

### 前提条件

- .NET SDK がインストール済みであること(バージョンは各被テストプロジェクトの `TargetFramework` と一致)。
- リポジトリルートで復元可能な NuGet ソースが利用可能であること。

### 操作手順

1. 依存関係を復元してテストディレクトリに移動:

```bash
dotnet restore Tests/GameFrameX.Tests/GameFrameX.Tests.csproj
cd Tests/GameFrameX.Tests
```

2. 全テストを実行:

```bash
dotnet test --nologo
```

3. 名前でフィルタリングして単一のテストクラスを実行(例:`LNumberFixTest` のみ):

```bash
dotnet test --filter "FullyQualifiedName~LNumberFixTest"
```

4. カバレッジ収集を有効化:

```bash
dotnet test --collect:"XPlat Code Coverage"
```

レポートはデフォルトで `TestResults/<guid>/coverage.cobertura.xml` に出力されます。

### よくあるバリエーション

| シナリオ | コマンドスニペット |
|------|------|
| 詳細ログ | `dotnet test --logger "console;verbosity=detailed"` |
| 指定した名前空間のみ実行 | `dotnet test --filter "FullyQualifiedName~GameFrameX.Tests.NetWork.Kcp"` |
| デバッグモードで実行 | `dotnet test -c Debug` |
| 統合テストを除外 | `dotnet test --filter "FullyQualifiedName!~Integration"` |

## テスト作成例

テストクラスは通常の class を継承し、`[Fact]` でケースをマークし、`Assert.*` でアサーションを行います。以下は `Tests/GameFrameX.Tests/LNumberFixTest.cs` からの実際のスニペットです:

```csharp
using GameFrameX.Utility;
using Xunit;

namespace GameFrameX.Tests
{
    public class LNumberFixTest
    {
        [Fact]
        public void TestCreateNegativeNumbers()
        {
            var negativeNumber = LNumber.Create(-123, -4567);

            Assert.True(negativeNumber.Raw < 0, "Raw value should be negative");
            Assert.True((double)negativeNumber < 0, "Double value should be negative");
            Assert.Equal(-124, negativeNumber.Floor);
            Assert.Equal(-123, negativeNumber.Ceiling);
            Assert.Equal(-123, (long)negativeNumber);
        }
    }
}
```

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `error NU1605: Detected package downgrade` | ソリューションルートが統一バージョンに復元されていない | テストディレクトリだけでなくリポジトリルートで `dotnet restore` を実行 |
| `Could not load file or assembly 'GameFrameX.Core'` | 被テストプロジェクトがビルドされていない | まずソリューション全体を `dotnet build` してから `dotnet test` を実行 |
| テスト発見数が 0 | `xunit.runner.visualstudio` または `Microsoft.NET.Test.Sdk` が不足 | csproj 内の PackageReference がコメントアウトまたは削除されていないか確認 |
| `coverlet` が出力されない | `--collect` パラメータが指定されていない | `--collect:"XPlat Code Coverage"` を追加 |
| `MongoDb` テスト接続失敗 | ローカルで MongoDB インスタンスが起動していない | MongoDB を起動するか、テスト前に `docker run -p 27017:27017 mongo` を実行 |

## 検証

- `dotnet test` の終了コードが 0 で、出力に `Passed: <N>, Failed: 0, Skipped: 0` が含まれる。
- `TestResults/` 配下に `coverage.cobertura.xml` が生成され、サイズが 0 ではない。
- IDE(Rider / Visual Studio)の Test Explorer で、ディレクトリと一対一に対応するテストスイートが確認できる。
