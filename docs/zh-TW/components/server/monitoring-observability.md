# 如何啟用監控計量與健康檢查

完成本頁的設定後，服務會自動公開兩個 HTTP 端點：`/health`（完整健康狀態）與 `/alive`（處理程序存活狀態）。其中包含內建的 MongoDB 健康檢查與 ASP.NET Core 預設健康檢查，只要呼叫一次 `AddServiceDefaults` 即可整合到整個服務中。

## 必要條件

- .NET 8+ 的 ASP.NET Core 專案（本框架預設使用 .NET 9）
- 已在 `Program.cs` 中呼叫 `WebApplication.CreateBuilder()` 與 `builder.Build()`
- 服務已參考 `GameFrameX.AppHost.ServiceDefaults` 套件（框架預設已參考）

## 步驟

### 1. 在 Program.cs 中註冊服務預設值

`AddServiceDefaults` 會同時設定 OpenTelemetry、記錄、計量、HTTP 復原力等基礎結構。此步驟也會啟用健康檢查。

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.AddServiceDefaults();
```

來源：[GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346)

### 2. 公開健康檢查端點

`MapDefaultEndpoints` 會註冊 `/health` 與 `/alive` 端點。`/health` 需要所有檢查都通過，而 `/alive` 只需要標記為 `live` 的檢查通過。

```csharp
var app = builder.Build();
app.MapDefaultEndpoints();
app.Run();
```

來源：[GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435)

### 3. 驗證預設端點

啟動服務後，請造訪：

| 端點 | 用途 | 成功回應 |
|------|------|---------|
| `/health` | 完整健康檢查（包含相依性） | `Healthy` |
| `/alive` | 處理程序存活狀態 | `Healthy` |

如果只需要處理程序存活探測，可以使用 `/alive`，它不依賴 MongoDB 等下游元件。

## 啟用 MongoDB 健康檢查

框架內建 `MongoDbHealthCheck`。只要在 DI 容器中註冊 `IMongoClient` 並呼叫 `AddMongoDbHealthCheck`，它就會自動接入 `/health` 端點。

### 1. 註冊 MongoDB 用戶端

```csharp
builder.Services.AddSingleton<IMongoClient>(sp =>
    new MongoClient(builder.Configuration.GetConnectionString("MongoDb")));
```

### 2. 註冊健康檢查

```csharp
builder.Services.AddHealthChecks()
    .AddMongoDbHealthCheck();
```

來源：[GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99)

### 3. 檢查行為說明

`MongoDbHealthCheck` 內部會呼叫 `ListDatabaseNamesAsync` 來探測連線，並使用連續失敗計數器來避免狀態抖動：

| 連續失敗次數 | 傳回狀態 | 意義 |
|--------------|---------|------|
| 0（傳回資料庫清單） | `Healthy` | 連線正常，失敗計數器重設 |
| 1 ~ 4 | `Degraded` | 暫時無法使用，重試可能成功 |
| ≥ 5 | `Unhealthy` | 連續失敗超過臨界值，標記為不健康 |

來源：[GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L69-L99](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L69-L99)

## 常見變化情境

- **僅公開存活探測**：某些 Kubernetes 部署只需要 `/alive`。您可以略過 MongoDB 等下游檢查的註冊，直接使用 `AddServiceDefaults` 提供的預設存活檢查。
- **新增自訂檢查**：實作 `IHealthCheck`，然後呼叫 `.AddCheck("my-check", new MyHealthCheck())` 將它附加到現有的 `IHealthChecksBuilder`。
- **外部健康探測**：將 `/health` 作為負載平衡器或 APM 的探測 URL。

## 常見錯誤

| 徵狀 | 原因 | 修正方式 |
|------|------|------|
| 存取 `/health` 傳回 404 | 未呼叫 `app.MapDefaultEndpoints()` | 在 `app.Run()` 之前加上 `app.MapDefaultEndpoints();` |
| `/health` 一律傳回 `Unhealthy` | MongoDB 連線字串不正確或服務未執行 | 檢查 `ConnectionStrings:MongoDb` 設定，並確認 MongoDB 可連線 |
| MongoDB 偶發抖動導致狀態頻繁變更 | 預設臨界值（連續失敗 5 次）過於嚴格 | 調整 `appsettings.json` 中的 `MongoDbHealthCheckOptions`，或將 `Degraded` 視為可容忍狀態 |
| 只想檢視存活狀態而不包含相依性 | 未區分 `/alive` 與 `/health` | 使用 `/alive` 端點，或在自訂檢查加上 `tags: new[] { "live" }` |

## 背景

健康檢查以 `Microsoft.Extensions.Diagnostics.HealthChecks` 為基礎。框架透過 `AddServiceDefaults` 預設註冊 `self` 檢查（標記為 `live`），並公開兩個端點路徑，以在容器協調流程系統中區分「處理程序仍在執行」與「準備接收流量」。

如需整體的遙測與 OpenTelemetry 整合，請參閱「服務預設值與遙測」。
