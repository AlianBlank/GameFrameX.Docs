# 프로세스 간 전환 방법

프로세스 전환은 `IProcedureManager.StartProcedure`를 통해 완료됩니다. 게임의 모든 위치(프로세스 클래스 내부, 외부 시스템, UI 버튼 콜백)에서 `ProcedureComponent.Procedure`를 가져올 수 있는 곳이라면 어디서나 호출할 수 있습니다. 이 페이지에서는 매니저 획득부터 전환 완료까지의 최소 실행 가능한 단계를 제공합니다.

## 사전 조건

- `ProcedureBase`를 상속받은 여러 프로세스 클래스(예: `ProcedureLogin`, `ProcedureMain`)를 이미 생성했습니다.
- `ProcedureComponent`가 씬에 부착되어 있으며, Inspector의 `Available Procedure Type Names`에 해당 프로세스 유형 이름이 입력되어 있습니다.
- 전체 아키텍처를 이미 이해했으며, 《개요》를 참조하세요.

## 작업 단계

### 1. 프로세스 매니저 가져오기

`ProcedureComponent`의 `Procedure` 속성을 통해 `IProcedureManager`를 가져옵니다:

```csharp
using GameFrameX.Procedure.Runtime;
using UnityEngine;

ProcedureComponent procedureComponent = GameFrameX.Runtime.GameFrameworkEntry.GetComponent<ProcedureComponent>();
IProcedureManager procedureManager = procedureComponent.Procedure;
```

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L70-L74)

### 2. 현재 프로세스의 `OnUpdate`에서 전환 시작

가장 일반적인 전환 방식: 특정 프로세스의 폴링에서 조건이 충족되었음을 감지하면 `StartProcedure`를 호출하며, 매니저는 현재 프로세스의 `OnLeave`와 대상 프로세스의 `OnEnter`를 트리거합니다.

```csharp
using GameFrameX.Procedure.Runtime;

public class ProcedureLogin : ProcedureBase
{
    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);

        if (로그인 완료 조건이 충족됨)
        {
            procedureOwner.Owner.StartProcedure<ProcedureMain>();
        }
    }
}
```

`IProcedureManager.StartProcedure`의 두 가지 오버로드 정의는 [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L64-L73)에서 확인할 수 있으며, 내부적으로 상태 머신의 상태 전환을 호출합니다.

### 3. 외부 코드에서 전환

반드시 프로세스 내부에서 전환할 필요는 없습니다. 게임 내에서 `IProcedureManager` 참조를 보유한 모든 곳에서 호출할 수 있습니다:

```csharp
using GameFrameX.Procedure.Runtime;

procedureManager.StartProcedure(typeof(ProcedureMain));
// 또는 제네릭 버전
procedureManager.StartProcedure<ProcedureMain>();
```

제네릭 버전 소스 서명:

```csharp
public interface IProcedureManager
{
    void StartProcedure<T>() where T : ProcedureBase;
    void StartProcedure(Type procedureType);
}
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L60-L73)

### 4. 전환 성공 확인

전환 후 `CurrentProcedure`와 `CurrentProcedureTime`을 읽어 새 프로세스가 적용되었고 타이머가 0으로 재설정되었는지 확인합니다. 단위 테스트의 작성 방식을 참고할 수 있습니다:

```csharp
m_ProcedureManager.Initialize(m_FsmManager, new ProcedurePreload(), new ProcedureMain());
m_ProcedureManager.StartProcedure<ProcedurePreload>();

Assert.IsNotNull(m_ProcedureManager.CurrentProcedure);
Assert.IsInstanceOf<ProcedurePreload>(m_ProcedureManager.CurrentProcedure);
Assert.AreEqual(0f, m_ProcedureManager.CurrentProcedureTime);
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L153-L173)

## 일반적인 변형

### 전환하지 않고 조회만

전환 전에 `HasProcedure`로 대상이 등록되어 있는지 확인하여 상태 머신 내부에서 예외가 발생하는 것을 방지할 수 있습니다:

```csharp
if (procedureManager.HasProcedure<ProcedureMain>())
{
    procedureManager.StartProcedure<ProcedureMain>();
}
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L78-L89)

### 전환하지 않고 등록된 인스턴스 가져오기

때로는 조건 판단을 위해 현재 프로세스 인스턴스를 읽기만 할 뿐 전환할 필요는 없습니다:

```csharp
ProcedureBase main = procedureManager.GetProcedure<ProcedureMain>();
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L94-L105)

## 일반적인 오류

- **호출 시기가 너무 이름**: 프로세스 매니저의 `Initialize` 이전에 메서드를 호출하면 예외가 발생합니다. 단위 테스트의 `CurrentProcedure_BeforeInitialize_Throws`, `HasProcedure_BeforeInitialize_Throws`가 이를 검증하며, [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L96-L128)에서 확인할 수 있습니다. 먼저 `Initialize`를 완료한 다음 `StartProcedure`를 호출하도록 하세요.
- **대상 프로세스가 등록되지 않음**: `StartProcedure`는 프로세스가 `Initialize(..., params ProcedureBase[] procedures)` 또는 `ReinitializeProcedures`를 통해 등록되어 있어야 합니다. `HasProcedure<T>()`로 사전 판단할 수 있습니다.
- **`OnEnter` / `OnInit` 내에서 전환**: 상태 머신 초기화 단계에서 `StartProcedure`를 호출하면 자체 수명 주기와 충돌할 수 있으므로, `OnUpdate` 또는 외부 드라이버에 두는 것이 좋습니다.

## 배경(선택 사항)

`ProcedureComponent`는 `m_ProcedureManager`를 보유하고 있으며, 시작 시 Inspector에 구성된 `m_AvailableProcedureTypeNames`을 통해 리플렉션으로 프로세스 인스턴스를 생성하고 순차적으로 `StartProcedure`를 호출합니다. 이후 `m_EntranceProcedure`가 초기 프로세스가 됩니다. 전환 시 기본 상태 머신이 `OnLeave`/`OnEnter` 흐름을 실행합니다. `m_UseStartupRunner = true`인 경우, 컴포넌트 자체는 더 이상 `Initialize`를 호출하지 않으며, `ApplicationStartupEntry` + `StartupRunner.Run`이 인계받아 중복 `Initialize`를 방지합니다.
