# WebGL プラットフォームでの使用方法

WebGL プラットフォームで `ImageCacheComponent` を使用してリモート画像を読み込む際、コンポーネントは自動的にブラウザ管理の `UnityWebRequestTexture` チャンネルに切り替え、ローカルディスクキャッシュ関連の API が no-op になるため、WebGL 用の追加分岐コードを書く必要はありません。

## 前提条件

- `GameFrameXImageCacheCroppingHelper` と `ImageCacheComponent` をシーンまたはランタイムエントリに追加済みであること。
- WebGL ビルドでリモート画像のクロスドメイン読み込みが許可されていること（サーバーが CORS ヘッダーを返すか、Player Settings で `Allow downloads over HTTP` / `Use default CORS` を設定する）。
- リモート画像 URL は必ず `http://` または `https://` で始まり、コンポーネントはプレフィックスを検証する。

## 操作手順

1. シーンに `ImageCacheComponent` をアタッチした後、通常通り `LoadImageAsync` を呼び出します。WebGL ではコンポーネントが `LoadImageWebGLAsync` を呼び出して `UnityWebRequestTexture` を使用し、ブラウザ自身の HTTP キャッシュに管理されます。

   ```csharp
   using System.Threading;
   using System.Threading.Tasks;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   public class WebGLSample : MonoBehaviour
   {
       public ImageCacheComponent imageCache;

       public async Task<Sprite> LoadRemoteIcon(string url, CancellationToken ct = default)
       {
           Texture2D tex = await imageCache.LoadImageAsync(url, ct);
           if (tex == null)
           {
               Debug.LogWarning($"読み込み失敗：{url}");
               return null;
           }
           return Sprite.Create(tex, new Rect(0, 0, tex.width, tex.height), Vector2.one * 0.5f);
       }
   }
   ```

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L115)

2. WebGL では `IsCached`、`RemoveCache`、`ClearCache` は常に使用できません。前者は WebGL で常に `false` を返し、後者 2 つはディスクキャッシュを直接サポートしません。呼び出し前にプラットフォームを判定し、ビジネスロジックで誤解を招くログが出力されないようにしてください。

   ```csharp
   if (Application.platform != RuntimePlatform.WebGLPlayer)
   {
       bool hit = imageCache.IsCached(url);
       // …WebGL 以外の場合のみディスクキャッシュ判定を行う
   }
   ```

   Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L28-L47)

3. クロスドメインと Mixed Content の処理：ブラウザはデフォルトでクロスドメインテクスチャを禁止しています。リモートサーバーは `Access-Control-Allow-Origin` を返すか、同じドメインで画像をホストする必要があります。HTTPS サイトでは HTTPS 画像 URL を使用してください。さもないとブラウザがリクエストをブロックします。

4. テクスチャの解放：`UnityWebRequestTexture.GetContent` が返す `Texture2D` はフレームワークによって自動的に破棄されません。コンポーネントのアンロードやシーン切り替え時には `Object.Destroy(texture)` を呼び出し、VRAM リークを避けてください。

5. キャンセルトークンは非 WebGL プラットフォームでのみ有効です。WebGL では渡された `CancellationToken` は無視されるため、UI レイヤー（例：パネルを閉じる）で戻り値の `Task` を直接破棄してください。

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L66-L89)

## 一般的なバリエーション

- **エディタでの WebGL シミュレーション**：Editor での実行時は引き続きディスクキャッシュロジックが使用されます。WebGL の挙動を検証したい場合は、`File → Build Settings → WebGL → Build And Run` からビルドしてデバッグしてください。
- **UnityWebRequest を直接使用**：進捗処理やカスタムヘッダーが必要な場合は、WebGL 分岐で `UnityWebRequestTexture.GetTexture` を直接呼び出すことができ、`ImageCacheComponent` を経由する必要はありません。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `url must start with http:// or https://.` 警告 | URL にプロトコルヘッダーがない、または相対パスを使用している | `https://` プレフィックスを補完する |
| ブラウザが CORS / Mixed Content エラーを報告する | リモートサーバーが CORS ヘッダーを返していない、またはプロトコルが一致しない | サーバーに `Access-Control-Allow-Origin` を追加するか、同ドメイン / 同プロトコルでリソースをホストする |
| `RemoveCache` / `ClearCache` を呼び出しても効果がない | WebGL にはディスクキャッシュがない | ビジネスレイヤーでこれら 2 つのエントリを非表示にし、ブラウザ自身のキャッシュクリアポリシーに切り替える |
| `IsCached` が常に `false` を返す | WebGL ではブラウザキャッシュを認識しない | `LoadImageAsync` を直接呼び出し、ヒットの判断はブラウザに任せる |
| シーン切り替えを繰り返すと VRAM が増加する | WebGL が返した `Texture2D` が解放されていない | シーンアンロード / 画像置き換えの前に `Object.Destroy(texture)` を呼び出す |

## 背景（オプション）

非 WebGL プラットフォームでは、`ImageCacheComponent.Awake` は `IDownloadManager` 経由でファイルを取得し、URL の MD5 をファイル名としてディスクに保存します。WebGL では `#if !UNITY_WEBGL` のコードブロック全体が削除されるため、`IDownloadManager` は WebGL で参照も注入もされません。WebGL プラットフォームは `UnityEngine.Networking.UnityWebRequestTexture` のみに依存し、ブラウザがすべてのキャッシュロジックを管理します。そのため、コンポーネントは WebGL ではディスクに介入する必要もできず、また介入できません。

関連コンポーネントの全体フローについては [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L1-L100) を参照してください。
