# APK 安裝包的建置方法

透過呼叫 `GameFrameX.Builder.Editor.Builder.BuildApk()`，可以一鍵將 Unity 專案打包為 Android APK，並可根據需要上傳至物件儲存。本頁面將說明命令列呼叫方式、參數說明以及常見的錯誤處理方法。

## 前置條件

1. Unity 編輯器已安裝本套件（`com.gameframex.unity.builder`），且 Unity 編輯器的平台已切換至 **Android**。
2. 已設定完成 Android 簽署、SDK、NDK、JDK 等環境（請參考 Unity 官方的 Android Player Settings）。
3. 若要將 APK 上傳至物件儲存，請在 `BuildPipeline → PlayerSettings → Scripting Define Symbols` 中新增 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`，並視需要啟用 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT` / `_QI_NIU` / `_A_LI_YUN` 其中之一。

## 操作步驟

### 1. 在 Unity 編輯器中直接呼叫

開啟 `Window → General → Search`，執行選單項目 `Builder/BuildApk`，或在任何編輯器腳本中呼叫以下內容：

```csharp
using GameFrameX.Builder.Editor;

public static class MyBuildEntry
{
    public static void BuildApk()
    {
        GameFrameX.Builder.Editor.Builder.BuildApk();
    }
}
```

來源：[Editor/Builder.cs#L59-L78](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L59-L78)

### 2. 從 CI 以命令列呼叫

使用 `Unity.exe -batchmode -executeMethod` 啟動打包的進入點，並透過命令列參數控制建置行為。常見的參數請參閱下表。

| 命令列參數 | 意義 | 預設值 |
|------------|------|--------|
| `-executeMethod` | 要執行的方法完整名稱。此處指定為 `GameFrameX.Builder.Editor.Builder.BuildApk` | 無 |
| `-logFile` | Unity 日誌的輸出路徑。日誌末尾的 `/Unity/` 會被替換為 `/` | 無 |
| `-BUILD_NUMBER` | 建置編號 | 無 |
| `-JOB_NAME` | Jenkins 等 CI 的任務名稱 | 無 |
| `-PackageName` | YooAsset 資源包名稱 | 無 |
| `-ChannelName` | 渠道名稱 | 無 |
| `-BundleId` | Android 包名（BundleId） | 無 |
| `-AppVersion` | 應用程式版本 | 無 |
| `-PackageVersion` | 資源包版本 | 無 |
| `-BuildPipeline` | 打包管線類型 | 無 |
| `-Language` | 語言 | 無 |
| `-IsUploadApk` | 開關：建置完成後將 APK 上傳至物件儲存 | `false` |
| `-IsUploadLogFile` | 開關：上傳日誌檔案 | `false` |
| `-IsUploadAsset` | 開關：上傳資源 | `false` |
| `-IsUpdateAssetPackageVersion` | 開關：更新遠端資源包的版本號 | `false` |
| `-UpdateAssetPackageVersionUrl` | 版本號更新介面位址 | 無 |
| `-UpdateAssetPackageVersionAuthorization` | 版本號更新介面認證標頭 | 無 |
| `-WeChatBotKey` | 企業微信機器人 Webhook Key（打包結果通知） | 無 |
| `-ObjectStorageKey / -ObjectStorageSecret / -ObjectStorageBucketName / -ObjectStorageEndPoint` | 物件儲存存取認證資訊 | 無 |

參數解析邏輯位於 `Builder.BuildParamsParse`。在每個 `-xxx` 後面直接指定值，即可賦值給 `BuilderOptions` 中對應的欄位。

```text
Unity.exe -batchmode -nographics -quit \
  -projectPath <ProjectPath> \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
  -logFile <LogPath>/builder.log \
  -BUILD_NUMBER 100 \
  -JOB_NAME nightly \
  -BundleId com.example.game \
  -AppVersion 1.0.0 \
  -PackageVersion 100 \
  -ChannelName official \
  -IsUploadApk \
  -WeChatBotKey <WeChatKey>
```

來源：[Editor/Builder.BuildParamsParse.cs#L13-L160](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L13-L160)

### 3. 產出物與上傳路徑

在 `BuildApk` 內部，`BuildProductHelper.BuildPlayerAndroid()` 會執行實際的打包作業並產生 APK 檔案路徑：

- APK 預設會輸出至 `Library/PlayerDataCache/...` 以外的專案建置目錄。具體路徑以 `BuildProductHelper` 的輸出為準。
- 若傳入 `-IsUploadApk`，儲存至物件儲存的路徑如下：
  `builder/{productName}/{activeBuildTarget}/{JobName}/{Application.version}/{BuildNumber}`。

來源：[Editor/Builder.cs#L47](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L47),[Editor/Builder.cs#L62-L78](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L62-L78)

## 常見變化

- **僅本機建置、不上傳**：不加上 `-IsUploadApk` 即可。
- **同時上傳日誌**：新增 `-IsUploadLogFile` 後，`-logFile` 指定的日誌也會上傳至相同的物件儲存路徑。
- **啟用物件儲存支援**：在打包用的 Editor 專案中啟用 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 巨集，並根據雲端廠商新增 `_TENCENT` / `_QI_NIU` / `_A_LI_YUN` 其中之一。`Builder` 的靜態建構子會根據巨集選擇對應的 `IObjectStorageUploadManager` 實作。
- **企業微信通知**：透過 `-WeChatBotKey` 傳入機器人 Webhook Key，即可在打包結束後推播通知結果。

## 常見錯誤

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 發生 `Exception: InvalidOperationException`，且日誌顯示未啟用物件儲存 | 已傳入 `-IsUploadApk`，但專案中沒有 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 巨集 | 在 PlayerSettings 的 Scripting Define Symbols 中新增對應的巨集，或移除 `-IsUploadApk` |
| 切換至 `Android` 平台後仍出現 "Build target not supported" | 呼叫 `BuildApk` 時當前的 `BuildTarget` 不是 Android | 確認 `EditorUserBuildSettings.activeBuildTarget == Android` |
| 參數未生效（例如：`BundleId` 未被替換） | 命令列參數拼寫錯誤或缺少值 | 按照上表以 `-BundleId <value>` 格式使用，值需緊接在參數名稱後面 |
| 找不到 `GameFrameX.Builder.Editor.Builder.BuildApk` | 未匯入套件，或類別名稱拼寫錯誤 | 確認 Package Manager 中已安裝該套件，並確認完整類別名稱為 `GameFrameX.Builder.Editor.Builder` |

## 背景（可選）

`Builder` 是一個 `partial class`，參數解析委派給 `Builder.BuildParamsParse`，實際的 APK 產生則委派給框架內部的 `BuildProductHelper.BuildPlayerAndroid()`。上傳部分以 `IObjectStorageUploadManager` 進行抽象化，目前內建 Tencent Cloud、Alibaba Cloud、Qiniu Cloud 三種實作，但只有在啟用對應的編譯巨集時才會參與編譯。
