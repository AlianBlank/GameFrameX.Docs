# 코루틴 시작 및 중지 방법

`CoroutineComponent`를 통해 단일 코루틴을 시작 및 중지하고, 모든 코루틴을 일괄 중지하는 방법입니다.

## 사전 조건

- `com.gameframex.unity.coroutine` 패키지가 설치되어 있고, �에 `CoroutineComponent` 컴포넌트가 부착되어 있어야 합니다 (프레임워크가 자동으로 해당 컴포넌트를 등록합니다).
- 호출자가 `CoroutineComponent` 인스턴스를 가져올 수 있어야 합니다 (일반적으로 `GameEntry.GetComponent<CoroutineComponent>()` 또는 사용자 정의 컴포넌트에서 참조를 보유하는 방식).

## 작업 단계

### 1. 코루틴 컴포넌트 가져오기

```csharp
var coroutineComponent = GameEntry.GetComponent<CoroutineComponent>();
```

### 2. 코루틴 시작

반복자 메서드를 `StartCoroutine`에 전달하면, 컴포넌트가 내부에서 `ConcurrentDictionary`로 해당 코루틴을 추적하며, 이후 동일한 반복자 인스턴스를 통해 중지할 수 있습니다.

```csharp
IEnumerator MyTask()
{
    yield return new WaitForSeconds(1f);
    Debug.Log("1초 후 실행");
}

IEnumerator enumerator = MyTask();
coroutineComponent.StartCoroutine(enumerator);
```

> 주의: `IEnumerator`가 딕셔너리의 key로 사용될 때 참조 동등성을 사용하므로, `StopCoroutine`은 `StartCoroutine` 시 사용한 **동일한** `IEnumerator` 인스턴스를 전달해야 합니다.

소스 코드:[CoroutineComponent.cs#L28-L33](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

### 3. 단일 코루틴 중지

반복자 또는 `UnityEngine.Coroutine` 객체 두 가지 방식으로 중지할 수 있으며, 컴포넌트는 Unity 엔진과 내부 추적 딕셔너리에서 동시에 제거합니다.

```csharp
// 방법 A: 반복자를 통해 중지 (시작 시 사용한 동일한 인스턴스를 전달해야 함)
coroutineComponent.StopCoroutine(enumerator);

// 방법 B: UnityEngine.Coroutine 객체를 통해 중지
coroutineComponent.StopCoroutine(handle);
```

소스 코드:[CoroutineComponent.cs#L39-L67](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L67)

### 4. 모든 코루틴 중지

추적 중인 코루틴을 비운 후 베이스 클래스 메서드를 호출하면, 실행 중인 모든 코루틴을 완전히 정리할 수 있으며, 씬 전환이나 종료 로직에 적합합니다.

```csharp
coroutineComponent.StopAllCoroutines();
```

## 일반적인 변형

### 프레임 종료 콜백

현재 프레임 렌더링이 완료된 후 로직을 실행해야 할 때, `WaitForEndOfFrameFinish`에서 제공하는 편리한 인터페이스를 사용할 수 있으며, 직접 반복자를 작성할 필요가 없습니다.

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    Debug.Log("현재 프레임 렌더링 완료");
});
```

소스 코드:[CoroutineComponent.cs#L101-L104](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L101-L104)

> 콜백이 트리거되기 전에 `StopCoroutine` 또는 `StopAllCoroutines`로 해당 코루틴을 중지하면, 콜백은 실행되지 않습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|----------|
| `StopCoroutine`이 동작하지 않음 | 전달한 `IEnumerator`가 시작 시의 동일한 인스턴스가 아님 (예: 반복자 메서드를 다시 호출한 경우) | 시작 시 반환되거나 전달된 `IEnumerator` 참조를 저장하고, 중지 시 재사용 |
| 코루틴 객체 보유로 인한 메모리 누수 | 객체 파괴 전에 코루틴을 중지하지 않음 | `OnDestroy`에서 `StopAllCoroutines`를 호출하거나, 명시적으로 `StopCoroutine` 호출 |
| 하위 클래스 참조로 `StartCoroutine`을 호출하면 추적 딕셔너리에 들어가지 않음 | `new`로 기본 클래스 메서드를 숨겨서, `CoroutineComponent` 타입 참조에서만 기록됨 | 항상 `CoroutineComponent` 타입의 참조로 `StartCoroutine`을 호출 |

## 배경 정보 (선택 사항)

`CoroutineComponent`는 `GameFrameworkComponent`를 상속하며, `new` 키워드를 통해 `MonoBehaviour`의 동일한 이름 메서드를 재정의합니다. 내부적으로 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>`을 사용하여 시작 매개변수와 Unity가 반환한 코루틴 핸들을 함께 저장하므로, 반복자 또는 핸들로 양방향 중지가 가능하며, 스레드 안전한 접근을 보장합니다.
