# 설정 삭제 및 비우기

`ISettingManager` 인터페이스를 통해 런타임에 개별 설정 항목을 삭제하거나 모든 설정을 한 번에 비울 수 있으며, 이는 플레이어 설정 초기화, 캐시 삭제 또는 계정 전환 시에 자주 사용됩니다.

## 전제 조건

- [빠른 시작](../../overview/quick-start)의 초기화流程를 완료했으며, `SettingManager`가 `SettingComponent`에 의해 생성 및 보유되고 있어야 합니다.
- 설정 헬퍼 `ISettingHelper`가 `SetSettingHelper`를 통해 설정되어 있어야 합니다. 그렇지 않으면 삭제/비우기 인터페이스가 `GameFrameworkException("Setting helper is invalid.")`을 발생시킵니다.
- `ISettingManager` 인스턴스를 가져와야 합니다. 아래 "매니저 가져오기" 섹션을 참조하세요.

## 작업 단계

1. 설정 매니저 인스턴스를 가져옵니다.

   ```csharp
   var settingManager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>();
   if (settingManager == null)
   {
       // 일반적으로 SettingComponent가 마운트되지 않았거나 초기화에 실패한 경우
       return;
   }
   ```

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

2. 이름으로 개별 설정 항목을 삭제합니다. 삭제 전에 `HasSetting`으로 존재 여부를 먼저 확인할 수 있습니다.

   ```csharp
   const string key = "Player.MusicVolume";
   if (settingManager.HasSetting(key))
   {
       bool removed = settingManager.RemoveSetting(key);
       if (removed)
       {
           settingManager.Save();
       }
   }
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L210-L234)

3. 모든 설정 항목을 한 번에 비웁니다(주의해서 사용하세요. 모든 키가 제거됩니다).

   ```csharp
   settingManager.RemoveAllSettings();
   settingManager.Save(); // 실제 구현에 따라 수동 Save가 필요한지 결정
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L244-L249)

4. 결과를 확인합니다. 설정 항목을 다시 열거하여 예상 개수와 일치하는지 확인합니다.

   ```csharp
   int remaining = settingManager.Count; // 0(전체 비우기)이거나 삭제 전보다 1 적어야 함
   string[] names = settingManager.GetAllSettingNames();
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L84-L92)

## 인터페이스 빠른 참조

| 메서드 | 시그니처 | 동작 |
|------|------|------|
| `HasSetting` | `bool HasSetting(string settingName)` | 설정 이름이 비어 있으면 `GameFrameworkException("Setting name is invalid.")`을 발생시킵니다. 그렇지 않으면 존재 여부를 조회합니다. |
| `RemoveSetting` | `bool RemoveSetting(string settingName)` | `bool`을 반환하며, 성공적으로 제거되었는지 여부를 나타냅니다. 설정 이름이 비어 있으면 예외를 발생시킵니다. |
| `RemoveAllSettings` | `void RemoveAllSettings()` | 모든 항목을 비웁니다. 반환 값이 없으며, 매개변수 검증 외의 오류가 없습니다. |

Source: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L104-L133)

## 일반적인 변형

- 삭제만 하고 저장하지 않음: 일부 백엔드(예: `PlayerPrefs`)는 명시적으로 `Save`를 호출해야 디스크에 기록되므로, 삭제 후 프로세스가 충돌하면 변경 사항이 손실될 수 있습니다. 이는 구체적인 `ISettingHelper` 구현에 따라 다릅니다.
- 읽기 전용/기본 설정 삭제: 설정이 직렬화 파일에서 온 경우, `RemoveSetting`은 일반적으로 런타임 메모리 캐시의 항목에만 영향을 미치며 원본 파일에 다시 쓰지 않습니다.

## 일반적인 오류

- **"Setting helper is invalid."**: `ISettingHelper`가 설정되지 않았습니다. `SettingComponent`가 올바르게 초기화되고 헬퍼가 할당되었는지 확인하세요.
- **"Setting name is invalid."**: `settingName`이 `null`이거나 빈 문자열입니다. 삭제 전에 유효한 이름을 전달해야 합니다.
- **삭제 후에도 이전 값을 읽을 수 있음**: 백엔드가 자동으로 영구 저장하지 않으므로 `Save()`를 호출해야 합니다. 그렇지 않으면 다음 `Load()`에서 동일 이름의 항목이 영구 저장소에서 다시 로드됩니다.
- **예상한 정리 효과가 없음**: `RemoveAllSettings`는 백엔드 기반(예: `PlayerPrefs`의 기타 무관 항목)을 재설정하지 않으며, 현재 매니저가 보유한 항목만 비웁니다.

## 배경(선택 사항)

`SettingManager`는 얇은 껍질이며, 모든 삭제/비우기 작업은 `ISettingHelper` 구현([`SettingHelperBase`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs)에 추상 메서드 정의됨)에 직접 전달됩니다. `DefaultSettingHelper`, `PlayerPrefsSettingHelper` 등 구체적인 구현은 각각 메모리를 변경할지 또는 기본 저장소와 동기화할지 결정합니다. 모듈 종료 시 자동으로 `Save()`가 호출되며, [`Shutdown`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L112-L115)을 참조하세요.
