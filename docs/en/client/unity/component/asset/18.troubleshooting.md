# Troubleshooting

This document summarizes common issues and their solutions when using the GameFrameX Asset component.

## Overview

The Asset component is built on YooAsset and provides unified resource loading and management interfaces. In actual use, various errors may occur due to platform differences, configuration errors, or resource path issues. This document aims to help developers quickly locate and resolve these problems.

## Initialization Issues

### Issue: Resource System Initialization Failed

**Symptoms:** "Asset manager is invalid" or initialization-related errors appear when the game starts.

**Possible Causes:**
1. AssetComponent not correctly added to the scene
2. IAssetManager module not registered

**Solution:**

Ensure AssetComponent is correctly configured in the Unity scene:

```csharp
// Add AssetComponent in Unity scene
// Path: GameObject -> GameFrameX -> Asset
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L18-L64)

Check if GameFrameworkEntry is correctly initialized:

```csharp
// Ensure AssetManager module is registered at startup
GameFrameworkEntry.RegisterModule<AssetManager>();
```

### Issue: Package Initialization Returns False

**Symptoms:** `InitPackageAsync` method returns false or throws an exception.

**Possible Causes:**
1. Runtime mode (EPlayMode) not correctly set
2. Host server URL not configured
3. YooAssets internal initialization failed

**Solution:**

Ensure the runtime mode is correctly set before initialization:

```csharp
var assetComponent = GameEntry.GetComponent<AssetComponent>();
assetComponent.GamePlayMode = EPlayMode.HostPlayMode;
```

> Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L18-L47)

## Resource Loading Issues

### Issue: Invalid Resource Path

**Symptoms:** Prompt indicates invalid path or resource not found when loading resources.

**Possible Causes:**
1. Resource path written incorrectly
2. Resource not added to build manifest
3. Resource tag configuration error

**Solution:**

Use `HasAssetPath` method to verify if the path is valid:

```csharp
var assetComponent = GameEntry.GetComponent<AssetComponent>();
if (assetComponent.HasAssetPath("Prefabs/Player"))
{
    var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
}
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L570-L573)

### Issue: Async Load Returns Null

**Symptoms:** After async loading, getting null or invalid Handle.

**Possible Causes:**
1. Resource path does not exist
2. Resource type mismatch
3. Exception occurred during loading

**Solution:**

Always check the Handle status:

```csharp
var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
if (handle.Status == YooAsset.EOperationStatus.Succeed)
{
    var player = handle.AssetObject as GameObject;
}
else
{
    Log.Error($"Resource loading failed: {handle.Error}");
}
```

### Issue: Synchronous Loading Freezes in Editor Mode

**Symptoms:** Using synchronous loading in Editor simulation mode causes the editor to freeze.

**Cause Analysis:** EditorSimulateMode uses editor resources, and synchronous loading blocks the main thread.

**Solution:**

Prefer using async loading:

```csharp
// Not recommended
var handle = assetComponent.LoadAssetSync<GameObject>("Prefabs/Player");

// Recommended
var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
```

## Memory Management Issues

### Issue: Memory Usage Continues to Grow

**Symptoms:** Memory usage keeps increasing after the game runs for a while.

**Possible Causes:**
1. Loaded resources not correctly released
2. Frequently creating resource handles but not calling Release
3. Not regularly cleaning up unused resources

**Solution:**

Correctly release resource handles:

```csharp
var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
// Release after use
handle.Release();
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L622-L628)

Regularly clean up unused resources:

```csharp
// Call at appropriate time
assetComponent.UnloadUnusedAssetsAsync();
assetComponent.ClearUnusedBundleFilesAsync();
```

### Issue: Resource Unloading Ineffective

**Symptoms:** Resources still exist after calling UnloadAsset.

**Possible Causes:**
1. References still holding the resources
2. Package is locked

**Solution:**

Force unload all resources:

```csharp
// Force reclaim all resources
assetComponent.UnloadAllAssetsAsync(packageName);
```

## Platform-Specific Issues

### Issue: WebGL Platform Resource Loading Fails

**Symptoms:** Resources cannot be loaded or downloaded on WebGL platform.

**Possible Causes:**
1. WebPlayMode must be used in WebGL mode
2. Server CORS configuration issue
3. Memory limitation

**Solution:**

In non-editor environment, AssetComponent automatically sets WebPlayMode:

```csharp
#if UNITY_WEBGL && !UNITY_EDITOR
GamePlayMode = EPlayMode.WebPlayMode;
#endif
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L44-L52)

### Issue: Mini-Game Platform Compilation Errors

**Symptoms:** Compilation errors occur on WeChat, ByteDance, or Kuaishou mini-game platforms.

**Historical Fixes:**
- Fixed Kuaishou mini-game platform compilation errors (v2.4.0)
- Removed WeChat mini-game platform conditional compilation errors (v2.3.0)
- Fixed WeChat mini-game environment initialization (v2.2.2)

**Solution:**

Ensure using the latest version and correctly configuring the mini-game platform:

```csharp
#if ENABLE_WECHAT_MINI_GAME
// WeChat mini-game specific configuration
GameEntry.GetComponent<AssetComponent>().gameObject
    .GetOrAddComponent<WeChatConfigHandler>();
#endif
```

> Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L105-L119)

### Issue: EditorSimulateMode Ineffective After Build

**Symptoms:** Works fine in Editor mode during development, but resources cannot be loaded after building.

**Cause:** EditorSimulateMode is only effective in editor environment.

**Solution:**

Ensure the correct runtime mode is set before building:

```csharp
#if UNITY_EDITOR
assetComponent.GamePlayMode = EPlayMode.EditorSimulateMode;
#else
assetComponent.GamePlayMode = EPlayMode.HostPlayMode; // or other appropriate mode
#endif
```

## Download and Update Issues

### Issue: Resource Download Failed

**Symptoms:** File download fails during patch update.

**Possible Causes:**
1. Network connection issue
2. Server URL configuration error
3. File verification failed

**Solution:**

Listen for download failure events:

```csharp
// Subscribe to download failure event
GameEntry.Event.Subscribe(AssetWebFileDownloadFailedEventArgs.EventId, OnDownloadFailed);

private void OnDownloadFailed(object sender, GameEventArgs e)
{
    var args = e as AssetWebFileDownloadFailedEventArgs;
    Log.Error($"Download failed: {args.FileName}, error: {args.Error}");
}
```

### Issue: Patch Manifest Update Failed

**Symptoms:** Error occurred when updating patch manifest.

**Possible Causes:**
1. Manifest file corrupted
2. Network issue
3. Version mismatch

**Solution:**

Listen for manifest update failure events:

```csharp
GameEntry.Event.Subscribe(AssetPatchManifestUpdateFailedEventArgs.EventId, OnManifestUpdateFailed);

private void OnManifestUpdateFailed(object sender, GameEventArgs e)
{
    var args = e as AssetPatchManifestUpdateFailedEventArgs;
    Log.Error($"Manifest update failed: {args.PackageName}, error: {args.Error}");
}
```

> Source: [AssetPatchManifestUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchManifestUpdateFailedEventArgs.cs#L36-L48)

## Debugging Tips

### Using Event System for Debugging

The Asset component provides a complete event system for debugging:

```csharp
// Subscribe to state change event
GameEntry.Event.Subscribe(AssetPatchStatesChangeEventArgs.EventId, OnPatchStatesChange);

// Subscribe to download progress event
GameEntry.Event.Subscribe(AssetDownloadProgressUpdateEventArgs.EventId, OnDownloadProgress);

// Subscribe to found update files event
GameEntry.Event.Subscribe(AssetFoundUpdateFilesEventArgs.EventId, OnFoundUpdateFiles);
```

> Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L33)

### Viewing Runtime Mode

View the current runtime mode in logs:

```csharp
// AssetManager.Initialize() outputs current mode
Log.Info($"Resource system runtime mode: {PlayMode}");
```

> Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L49)

### Checking Package Status

```csharp
var package = assetComponent.GetAssetsPackage("DefaultPackage");
if (package != null)
{
    var version = package.GetPackageVersion();
    Log.Info($"Current package version: {version}");
}
```
