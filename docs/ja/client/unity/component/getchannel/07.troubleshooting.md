# 常见问题

本文档列出使用 GameFrameX GetChannel 插件时可能遇到的常见问题及其解決策。

## 概要

GameFrameX GetChannel は Unity 插件，に使用在多平台（iOS、tvOS、visionOS、Android、Editor、PC、WebGL、UWP 和主机平台）中取得应用分发渠道信息。在实际使用过程中，由于平台配置差异、代码混淆、リソースファイル位置等问题，用户可能会遇到各种问题。本文档旨在帮助開発者快速定位和解决这些问题。

## 平台配置问题

### Android 平台

#### 问题：取得渠道返回 "default"

**症状**：在 Android 平台上呼び出し `BlankGetChannel.GetChannelName()` 始终返回 "default"，而不是配置的渠道值。

**原因**：Android 平台的実装依赖于 Java 原生代码。当前插件代码硬编码呼び出し `com.alianhome.getchannel.MainActivity` クラス中的静态メソッド `GetChannel`。

```csharp
// Runtime/BlankGetChannel.cs (第132-134行)
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```
> Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L132-L134)

**解決策**：

您必要在您的 Android プロジェクト中作成一个 Java クラス来実装取得渠道的逻辑。有以下两种方法：

**方法一：使用 Gradle 插件（推荐）**

参考 [平台配置 - Android](./4-platform-configuration) 文档，配置 Gradle 插件来自动注入渠道信息。

**方法二：手动実装 Java 代码**

在您的 Android 原生代码中作成以下クラス：

```java
// MainActivity.java (或任何启动 Activity)
package com.yourcompany.yourgame;

import android.app.Activity;
import android.os.Bundle;
import android.content.pm.ApplicationInfo;
import android.content.pm.PackageManager;

public class MainActivity extends Activity
{
    @Override
    protected void onCreate(Bundle savedInstanceState)
    {
        super.onCreate(savedInstanceState);
    }
    
    // 供 Unity C# 呼び出し取得渠道信息
    public static String GetChannel(String key)
    {
        try 
        {
            ApplicationInfo appInfo = getApplicationContext()
                .getPackageManager()
                .getApplicationInfo(getPackageName(), PackageManager.GET_META_DATA);
            Bundle bundle = appInfo.metaData;
            return bundle.getString(key, "default");
        } 
        catch (Exception e) 
        {
            return "default";
        }
    }
}
```

**重要ヒント**：如果您不実装此 Java クラス，Android 平台会因找不到クラス而抛出異常，但插件会捕获異常并返回默认值 "default"。

#### 问题：AndroidManifest.xml 配置不生效

**症状**：已在 AndroidManifest.xml 中配置了 `<meta-data>` 标签，但取得渠道时仍返回默认值。

**解決策**：

1. 确认 `<meta-data>` 标签位于 `<application>` 标签内部，而不是 `<activity>` 标签内：

```xml
<application>
    <activity 
        android:name=".MainActivity"
        android:label="@string/app_name">
        <!-- meta-data 不能放在这里 -->
    </activity>
    
    <!-- 正确位置：application 标签内 -->
    <meta-data
        android:name="channel"
        android:value="android_cn_taptap" />
</application```
> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L113-L128)

2. 确认 `android:name` プロパティ与 C# 代码中使用的 key 完全匹配（区分大小写）。

### iOS / tvOS / visionOS 平台

#### 问题：iOS 构建后 Info.plist 没有渠道信息

**症状**：使用 Unity 构建 iOS プロジェクト后，Info.plist 中没有自动添加渠道信息。

**原因**：插件的 `PostProcessBuildHandler` 会在构建时检查 Info.plist，如果已存在 `channel` 键，则不会添加默认值。

```csharp
// Editor/PostProcessBuildHandler.cs (第39-47行)
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过設定=>" + value);
}
```
> Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L39-L47)

**解決策**：

1. 如果必要設定自定义渠道值，お願いします在构建前手动在 Info.plist 中添加 `channel` 键值对
2. 如果希望使用默认值 "default"，必ず Info.plist 中没有 `channel` 键

---

#### 问题：iOS 渠道取得返回 null 或空字符串

**症状**：在 iOS 平台上取得渠道时返回空值或 null。

**可能原因**：

1. **Info.plist 配置错误**：键名与代码呼び出し不匹配
2. **P/Invoke 问题**：原生メソッド未正确链接

**解決策**：

1. 确认 Info.plist 中的配置格式正确：

```xml
<key>channel</key>
<string>ios_cn_taptap</string>
```
> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L96-L104)

2. 确认 C# 代码中使用的 key 与 Info.plist 中的键名完全一致：

```csharp
// 默认 key 为 "channel"
string channel = BlankGetChannel.GetChannelName();

// 如果 Info.plist 使用了其他键名
string customChannel = BlankGetChannel.GetChannelName("your_custom_key");
```

### Editor / PC / WebGL / UWP / 主机平台

#### 问题：Resources ファイル读取失败

**症状**：在 Editor、PC、WebGL 等平台取得渠道时始终返回 "default"。

**原因**：插件从 `Resources/application_config.txt` ファイル读取配置，如果ファイル不存在或格式不正确，将返回默认值。

**解決策**：

1. 确认 `application_config.txt` ファイル位于 `Assets/Resources/` ディレクトリ下（注意大小写）

2. 确认ファイル内容格式正确（每行 `key=value`）：

```
channel=editor_cn_test
sub_channel=beta
```
> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L136-L142)

3. 检查 Unity 控制台是否有リソース加载失败的警告信息

---

#### 问题：修改配置ファイル后渠道值未更新

**症状**：修改 `application_config.txt` 后，取得到的渠道值没有变化。

**原因**：插件使用缓存机制避免重复读取配置ファイル。

```csharp
// Runtime/BlankGetChannel.cs (第100-103行)
if (ChannelCache.TryGetValue(channelKey, out var value))
{
    return value;
}
```
> Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L100-L103)

**解決策**：

1. 在 Unity Editor 中重新启动ゲーム（Editor 模式下按 Play 时修改リソースファイル必要重启）
2. 如果必要强制刷新，可能在ゲーム启动时清除缓存：

```csharp
// 注意：这是内部成员，直接访问必要を通じて反射或其他方法
// 建议：重启ゲーム或重新加载シーン
```

## 代码混淆与剥离问题

### 问题：渠道取得機能在 release build 中失效

**症状**：在发布版本中，`BlankGetChannel.GetChannelName()` 始终返回默认值。

**原因**：Unity 的代码剥离（Code Stripping）機能可能将 `BlankGetChannel` クラス及関連平台代码从最终构建中移除。

**解決策**：

1. **使用 `link.xml` ファイル**（插件已包含）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="BlankGetChannel.Runtime" preserve="all"/>
</linker>
```
> Source: [link.xml](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/link.xml#L1-L3)

2. **在クラス上添加 Preserve 特性**（插件已添加）：

```csharp
// Runtime/BlankGetChannel.cs (第35行)
[UnityEngine.Scripting.Preserve]
public sealed class BlankGetChannel
```

3. **在 Unity Player Settings 中调整代码剥离级别**：
   - 打开 `Edit > Project Settings > Player`
   - 在 `Other Settings` 中找到 `Managed Stripping Level`
   - 如果问题持续，将级别从 `High` 降低到 `Medium` 或 `Low`

## 键名配置问题

### 问题：key 名不匹配导致取得失败

**症状**：使用特定 key 取得渠道时返回默认值，而不是配置的值。

**原因**：C# 代码中使用的 key 与平台配置ファイル内の key 不一致。

**解決策**：

| 平台 | 配置ファイル位置 | 键名示例 |
|------|-------------|---------|
| iOS/tvOS/visionOS | Info.plist | `channel` |
| Android | AndroidManifest.xml `<meta-data>` | `channel` |
| Editor/PC/WebGL | Resources/application_config.txt | `channel=editor_cn` |

确保在所有平台使用统一的 key 名称，或在代码中明确指定正确的 key：

```csharp
// 使用默认 key "channel"
string channel = BlankGetChannel.GetChannelName();

// 使用自定义 key
string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
```

## 多平台构建问题

### 问题：某些平台无法取得渠道信息

**症状**：在某些平台上渠道機能正常，但在其他平台上返回默认值。

**排查手順**：

1. **确认当前构建的平台**：
```csharp
Debug.Log("Current Platform: " + Application.platform);
Debug.Log("Is Android: " + Application.platform == RuntimePlatform.Android);
Debug.Log("Is iOS: " + Application.platform == RuntimePlatform.IPhonePlayer);
```

2. **检查各平台的配置**：
   - Android：检查 AndroidManifest.xml 中的 meta-data
   - iOS：检查 Info.plist 中的键值对
   - Editor/PC：检查 Resources/application_config.txt ファイル

3. **查看 Unity 控制台日志**：
   - iOS 构建时会输出 "配置渠道成功" 或 "已有渠道,跳过設定"

## API 使用问题

### 问题：返回 "default" 值无法区分是否配置

**症状**：无法判断返回的 "default" 是来自配置还是未配置的默认值。

**解決策**：

使用重载メソッド提供明确的默认值：

```csharp
// 返回 "default" 可能是因为配置了 channel=default，也可能是未配置
string channel = BlankGetChannel.GetChannelName();

// 使用明确的默认值来区分
string channel = BlankGetChannel.GetChannelName("channel", "unknown");
if (channel == "unknown")
{
    Debug.LogWarning("渠道未配置！");
}
```

## 快速诊断清单

当遇到渠道取得问题时，お願いします按以下顺序检查：

- [ ] **平台配置检查**：确认目标平台的配置ファイル已正确設定
- [ ] **键名一致性检查**：确认代码中的 key 与配置ファイル内の key 完全一致（区分大小写）
- [ ] **リソースファイル位置检查**：确认 application_config.txt 位于 Assets/Resources/ ディレクトリ
- [ ] **代码剥离检查**：确认 link.xml 存在且 Player Settings 未启用激进剥离
- [ ] **日志检查**：查看 Unity 控制台是否有関連警告或错误信息
- [ ] **平台特定检查**：
  - Android：确认 MainActivity 中実装了 GetChannel メソッド
  - iOS：确认 Info.plist 中存在 channel 键
