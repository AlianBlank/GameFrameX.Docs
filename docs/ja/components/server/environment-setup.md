# 環境の準備とローカルビルド

このセクションでは、GameFrameX サーバーをローカルで動作させるために必要な環境とツールを準備し、初めてビルドを行い、サーバーの起動ログがコンソールに表示されるまでを案内します。

## 前提条件

| ツール/コンポーネント | 要件 | 備考 |
|----------|------|------|
| .NET SDK | .NET 10.0 SDK のみサポート | .NET 8/9 とは互換性がありません |
| データベース | MongoDB 4.x 以上 | ローカルインストールまたは Docker で起動可能 |
| IDE | Visual Studio 2022 または JetBrains Rider | .NET 10 を認識できるエディタであれば可 |
| オプション | Docker | MongoDB コンテナをすばやく起動するために使用 |
| オプション | Git | リポジトリのクローン |

> 上記のバージョン要件は、プロジェクトの README の「環境要件」セクション([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L168-L172))に由来します。バッジにも `.NET-10.0` と明示されています([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L8))。

## 操作手順

1. **リポジトリをクローンしてサーバーディレクトリに移動する**

   ```bash
   git clone https://github.com/GameFrameX/GameFrameX.git
   cd GameFrameX/Server
   ```

2. **NuGet 依存関係を復元する**

   ```bash
   dotnet restore
   ```

   これにより、`GameFrameX.AppHost` などのプロジェクトにある `Aspire.Hosting.*` などの NuGet パッケージが取得されます([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L9-L12))。

3. **ソリューションをビルドする**

   ```bash
   dotnet build
   ```

   初回ビルドではすべてのモジュール(ホットフィックス層 `Hotfix` と永続化層 `Apps` を含む)がコンパイルされ、ビルド成果物は各プロジェクトの `bin/` ディレクトリに出力されます。

4. **MongoDB を起動する**

   以下のいずれかの方法を選択してください:

   ```bash
   # 方法一: ローカルの mongod
   mongod --dbpath /path/to/data

   # 方法二: Docker
   docker run -d -p 27017:27017 --name mongo mongo:8.2
   ```

   起動が成功すると、MongoDB はデフォルトで `127.0.0.1:27017` をリッスンします。

5. **Launcher を実行してサーバーを起動する**

   サービス種別とポートを指定するコマンドライン引数を使用します(詳細な引数については《起動パラメータ》リファレンスページを参照):

   ```bash
   dotnet run --project GameFrameX.Launcher -- \
       --ServerType=Game \
       --ServerId=1000 \
       --OuterPort=29100 \
       --HttpPort=28080 \
       --DataBaseUrl=mongodb://127.0.0.1:27017 \
       --DataBaseName=gameframex
   ```

   上記のコマンドは、README が提供する「最小起動」パスに対応しています([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L203-L210))。

6. **起動を検証する**

   - ブラウザまたは curl で `http://localhost:28080/game/api/health` にアクセスし、正常なステータスが返されることを確認します。
   - Launcher のコンソールでログを確認し、Actor とネットワークリスナーがともに準備完了になっていることを確認します。

## よくあるバリエーション

### Aspire AppHost を使用したワンクリックオーケストレーション

リポジトリのルートディレクトリには `GameFrameX.AppHost` プロジェクトが用意されており、.NET Aspire SDK を使用して MongoDB コンポーネントを参照しています([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19))。AppHost を直接 F5 で実行すると、Aspire Dashboard が MongoDB と Launcher を自動的に起動します:

```bash
dotnet run --project GameFrameX.AppHost
```

### IDE でのデバッグ

Rider/VS で `GameFrameX.Launcher` をスタートアッププロジェクトに設定し、上記のコマンドライン引数を「実行構成 → Program arguments」に貼り付けることで、起動フローをブレークポイントでデバッグできます。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `dotnet restore` で `NETSDK1045`(.NET 10 がインストールされていない)が報告される | .NET 8/9 がインストールされており、.NET 10 がインストールされていない | [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) をインストールし、デフォルト SDK として設定する |
| ビルドで `NU1605` / パッケージ競合が報告される | 子プロジェクトが互換性のない推移的依存関係を固定している | `bin/` と `obj/` を削除して `dotnet restore` を再実行する |
| 起動時に `MongoDB connection refused` が報告される | MongoDB が起動していないか、ポートが占有されている | `mongod` が実行中であることを確認するか、`--DataBaseUrl` を調整する |
| ヘルスチェックが 404 / ポートが応答しない | `--HttpPort` が占有されているか、`--OuterPort` が既存のプロセスと競合している | ポートを変更して再起動する |

## 背景(オプション)

本プロジェクトは .NET 10 SDK + .NET Aspire 13.4.6 に基づいてローカル依存関係をオーケストレーションしています([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19))。Launcher(`GameFrameX.Launcher`)は実際に Actor とネットワークリスナーをホストするプロセスのエントリーポイントであり、コマンドライン引数を `StartupOptions` にマッピングし、`GameFrameX.StartUp` にホストの起動を指示する役割を担います。

実行時設定項目の完全なリストについては、《起動パラメータリファレンス》を参照してください。
