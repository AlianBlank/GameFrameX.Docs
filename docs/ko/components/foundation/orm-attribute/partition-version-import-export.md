# 분할 테이블 / 버전 관리 / 가져오기·내보내기 선언 방법

엔티티 클래스에 `PartitionTableAttribute`, `VersionControlAttribute`, `ImportExportAttribute` 세 가지 특성을 추가하면 데이터베이스 테이블의 분할 지원 여부, 버전 관리 활성화 여부, 가져오기·내보내기 흐름 참여 여부를 한 번에 선언할 수 있습니다. 이 페이지에서는 바로 복사하여 사용할 수 있는 최소 예제와 가장 흔히 사용되는 몇 가지 변형을 제공합니다.

## 사전 조건

- `GameFrameX.Foundation.Orm.Attribute` 네임스페이스 참조;
- 엔티티 클래스는 특성에 선언된 필드와 동일한 이름의 속성을 포함해야 함(예: 분할 키, 버전 필드 등);
- 실제 DDL은 상위 ORM/마이그레이션 도구에서 특성에 따라 생성되며, 이 문서에서는 선언 방법만 설명합니다.

## 작업 단계

### 1. 분할 테이블 선언

엔티티 클래스에 `PartitionTableAttribute`를 추가하고, 생성자에서 분할 키 필드와 분할 유형을 전달합니다. 해시 분할의 경우 `PartitionCount`를 지정할 수 있으며, 범위 분할의 경우 `Interval`을 지정할 수 있습니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[PartitionTable("CreateDate", PartitionType.Range, PartitionInterval.Monthly)]
public class OrderHistory
{
    public int Id { get; set; }
    public int UserId { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreateDate { get; set; }  // 분할 키
}
```

Source: [PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L63-L91)

선택 속성: `AutoCreatePartition`(기본값 `true`), `RetentionDays`(기본값 `0`은 영구 보관을 의미), `PartitionValues`(리스트 분할 시 입력), `PartitionCount`(기본값 `4`, 해시 분할에 사용).

```csharp
[PartitionTable("UserId", PartitionType.Hash, PartitionCount = 16)]
public class UserActivity
{
    public long Id { get; set; }
    public int UserId { get; set; }
    public string Activity { get; set; }
    public DateTime Timestamp { get; set; }
}
```

Source: [PartitionTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/PartitionTableAttribute.cs#L82-L89)

### 2. 버전 관리 선언

엔티티 클래스에 `VersionControlAttribute`를 추가하고, 생성자에서 버전 필드명을 전달하며, 선택적으로 버전 전략을 지정합니다. 엔티티에는 동일한 이름의 버전 필드 속성이 포함되어야 합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[VersionControl("Version", VersionStrategy.Optimistic)]
public class Document
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }
    public int Version { get; set; }  // 버전 번호 필드
    public DateTime LastModified { get; set; }
    public string LastModifiedBy { get; set; }
}
```

Source: [VersionControlAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/VersionControlAttribute.cs#L63-L74)

선택 속성: `EnableHistory`(기본값 `false`), `HistoryTableName`, `MaxHistoryVersions`(기본값 `0`은 제한 없음을 의미), `ConflictHandling`(기본값 `ThrowException`), `AutoUpdateVersion`(기본값 `true`), `ComparisonMode`(기본값 `Increment`).

이력 버전을 보존해야 할 때는 `EnableHistory`를 `true`로 설정하고 선택적으로 이력 테이블 이름을 지정할 수 있습니다:

```csharp
[VersionControl("RowVersion", VersionStrategy.Timestamp, EnableHistory = true)]
public class UserProfile
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
    public byte[] RowVersion { get; set; }
}
```

Source: [VersionControlAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/VersionControlAttribute.cs#L76-L83)

### 3. 가져오기·내보내기 선언

엔티티 클래스에 `ImportExportAttribute`를 추가하고, 생성자에서 지원되는 형식과 가져오기·내보내기 방향을 전달합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[ImportExport(ImportExportFormat.Excel, ImportExportDirection.Bidirectional)]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

(코드 예제는 `ImportExportAttribute`의 공개 생성자 `ImportExport(ImportExportFormat, ImportExportDirection)`를 기반으로 합니다.)

## 일반적인 변형

| 시나리오 | 작성 방법 | 설명 |
|------|------|------|
| 리스트 분할 | `PartitionTable("Region", PartitionType.List)`에 `PartitionValues = "North,South,East,West"` 추가 | 사전 정의된 값 리스트로 분할 |
| 내보내기만 | `ImportExport(ImportExportFormat.Csv, ImportExportDirection.ExportOnly)` | 가져오기入口를 닫음 |
| 가져오기만, 검증 활성화 | `ImportExport(ImportExportFormat.Excel, ImportExportDirection.ImportOnly, ValidateOnImport = true)` | 가져오기 시 필드 검증 실행 |
| 세 가지 특성叠加 | 엔티티에 `PartitionTable` + `VersionControl` + `ImportExport` 동시 작성 | 대용량 테이블 + 동시성 + 데이터 교환 시나리오 |

`PartitionTableAttribute`와 `VersionControlAttribute`는 모두 `AllowMultiple = false`이므로, 동일한 클래스에서 각각 한 번만 선언할 수 있습니다. `ImportExportAttribute` 또한 한 번만 허용됩니다.

## 일반적인 오류

- **분할 키 또는 버전 필드가 존재하지 않음**: 엔티티 클래스에 `PartitionKey` / `VersionField`와 동일한 이름의 속성이 없으면 마이그레이션 또는 런타임 검증이 실패합니다. 먼저 필드를 추가한 후 특성을 추가하세요.
- **해시 분할 `PartitionCount <= 0`**: 생성자가 `ArgumentOutOfRangeException`을 던지며, `Partition count must be positive.`라는 메시지를 표시합니다. 양의 정수를 전달해야 합니다.
- **`partitionKey` / `versionField`에 `null` 또는 공백 전달**: `ArgumentNullException` 또는 `ArgumentException.ThrowIfNullOrWhiteSpace`가 트리거되므로, 상수 문자열을 직접 전달하세요.
- **리스트 분할에서 `PartitionValues` 입력을 잊음**: 리스트 분할은 반드시 값 집합을 명시적으로 선언해야 하며, 그렇지 않으면 분할 경계를 결정할 수 없습니다.
- **버전 필드 유형과 전략 불일치**: 예를 들어 `VersionStrategy.Timestamp`는 해당 필드가 `byte[]` 또는 `DateTime`이어야 하고, `Optimistic`은 `int/long`이어야 합니다. 혼용하면 버전 비교가 실패합니다.
