# 핫픽스 진입점(HotfixLauncher)接入 방법

본 페이지 설정을 완료하면 프레임워크가 시작될 때 AOT DLL과 Hotfix DLL을 자동으로 로드하고, 리플렉션을 통해 지정된 진입 메서드를 호출하여 핫픽스 어셈블리를 구동합니다.

## 사전 조건

- 핫픽스 어셈블리 `Unity.Hotfix`(기본 Assembly Definition)가 생성되어 있어야 합니다.
- 정적 진입 클래스와 매개변수가 없는 정적 메서드(예: `Hotfix.HotfixLauncher.Main`)가 이미 존재해야 합니다.
- `Assets/Resources/StartupOptions.asset`에서 다음 세 가지 설정을 확인해야 합니다(프레임워크 기본값으로 이미 작성되어 있음):
  - `HotfixAssemblyName: Unity.Hotfix`
  - `HotfixEntryTypeName: Hotfix.HotfixLauncher`
  - `HotfixEntryMethodName: Main`

## 작업 단계

1. **진입 클래스 생성**. `Assets/Hotfix/` 디렉터리에 `HotfixLauncher.cs`를 새로 만들고, 기본 네임스페이스 `Hotfix`를 사용하며, 정적 `Main()` 메서드를 핫픽스 진입점으로 제공합니다.

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX;
   using GameFrameX.UI.Runtime;
   using Hotfix.Config;
   using Hotfix.Config.Local;
   using Hotfix.Config.Tables;
   using Hotfix.UI;

   namespace Hotfix
   {
       public static class HotfixLauncher
       {
           public static void Main()
           {
               Log.Info("Hello World HybridCLR");
               LoadConfig();
               LoadUI();
           }
       }
   }
   ```

   Source: [HotfixLauncher.cs#L26-L34](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L26-L34)

2. **진입점에서 설정과 UI 로드**. 프레임워크는 진입 메서드만 호출하며, 이후의 리소스, 설정, UI 초기화는 모두 이 메서드에서 구동됩니다. 템플릿 프로젝트는 `TablesComponent`를 사용하여 JSON/바이너리 설정 테이블을 로드하고, `await` 방식으로 로그인 UI를 엽니다.

   ```csharp
   private static async void LoadUI()
   {
       await GameApp.UI.OpenAsync<UILogin>();
   }

   static async void LoadConfig()
   {
       _tablesComponent = new TablesComponent();
       _tablesComponent.Init(GameApp.Config);
       await _tablesComponent.LoadAsync(ConfigLoader);
       TranslateText();
   }

   static TablesComponent _tablesComponent;
   ```

   Source: [HotfixLauncher.cs#L36-L61](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L61)

3. **`StartupOptions.asset`의 세 가지 키 값이 진입점과 일치하는지 확인**. 프레임워크 구동기 `HotfixHelper.StartHotfixInternalAsync`는 이 세 가지 필드를 읽어 리플렉션으로 메서드를 호출하며, 기본값은 아래 표와 같습니다. 네임스페이스나 클래스명을 변경했다면 반드시 여기서도 함께 수정해야 합니다.

   | 키 | 기본값 | 역할 |
   |---|---|---|
   | `HotfixAssemblyName` | `Unity.Hotfix` | 로드할 DLL명(`.dll` 제외) |
   | `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` | 진입 클래스의 완전한 타입명(네임스페이스 + 클래스명) |
   | `HotfixEntryMethodName` | `Main` | 진입 메서드명, `public static` 매개변수 없는 메서드여야 함 |

   Source: [HotfixHelper.cs#L62-L70](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70)、[StartupOptions.asset#L24-L26](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Resources/StartupOptions.asset#L24-L26)

4. **시작 흐름에 `ApplicationHotfixLauncher`가 연결되어 있는지 확인**. 프레임워크 진입점 `ApplicationStartupEntry`는 이를 통해 시작 UI 핸들러와 핫픽스 구동기를 `StartupRunner.Run`에 연결합니다. 별도 수정 없이 참조만 존재하면 됩니다.

   ```csharp
   var result = await StartupRunner.Run(startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   Source: [ApplicationStartupEntry.cs#L43](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L43)、[ApplicationHotfixLauncher.cs#L12](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs#L12)

## 일반적인 변형

- **바이너리 설정 테이블**: `HotfixLauncher.LoadConfig`에서 `LoadAsync(ConfigLoader)`를 `LoadAsync(ConfigBufferLoader)`로 바꾸고, 컴파일 옵션에서 `ENABLE_BINARY_CONFIG`를 활성화합니다(템플릿은 이미 `#if ENABLE_BINARY_CONFIG` 조건부 컴파일을 사용 중).
- **HybridCLR 비활성화**(네이티브 IL2CPP 경로): `ENABLE_GAME_FRAME_X_HYBRID_CLR` 또는 `DISABLE_HYBRIDCLR`이 활성화되면, `HotfixHelper.StartHotfixInternalAsync`은 `RunNative` 분기를 따라가 `Utility.Assembly.GetType`으로 리플렉션 호출을 직접 수행하며, AOT DLL 로드 과정이 필요하지 않습니다.
- **사용자 지정 진입 클래스명**: 예를 들어 `HotfixLauncher`를 `MyGame.EntryBoot`로 변경한 경우, `StartupOptions.asset`의 `HotfixEntryTypeName`도 `MyGame.EntryBoot`로, `HotfixEntryMethodName`은 `Boot`으로 함께 수정합니다.

## 일반적인 오류

- **진입 클래스/메서드 시그니처 불일치**: 반드시 `public static`이고 매개변수가 없어야 합니다. 그렇지 않으면 `entryType.GetMethod(entryMethodName)`이 `null`을 반환하며, 로그에서 `EntryType=>method ` 뒤가 비어 있게 표시됩니다.
- **네임스페이스 또는 클래스명 오타**: `HotfixEntryTypeName`은 반드시 `네임스페이스.클래스명`의 완전한 형식을 사용해야 하며, DLL 내 실제 네임스페이스와 일치해야 합니다. 그렇지 않으면 `Run`에서 `entryType.FullName`이 `NullReferenceException`을 던집니다.
- **진입점은 수정했지만 `StartupOptions.asset`는 재시작하지 않음**: 변경 사항은 런타임에 적용되지 않으므로, Editor에서 해당 ScriptableObject를 다시 선택하거나 Player를 재시작해야 합니다.
- **`#if ENABLE_UI_FAIRYGUI` 분기 실수로 삭제**: 템플릿에서 FairyGUI 패키지 로드는 조건부 컴파일로 감싸져 있습니다. FairyGUI를 사용하는데 해당 매크로를 정의하지 않으면 `LoadUI`에서 UI 패키지 로드가 실패합니다.

## 배경 지식(선택 사항)

`HotfixHelper.StartHotfixInternalAsync`는 Editor 내부에서는 이미 로드된 어셈블리를 직접 순회하여 DLL을 찾고, 패키지 빌드 후에는 `AOTGenericReferences.PatchedAOTAssemblyList` 순서대로 AOT 메타데이터를 로드한 다음, `Assembly.Load`로 Hotfix DLL을 로드하고, 마지막으로 리플렉션으로 진입 메서드를 호출합니다. `ApplicationHotfixLauncher`는 단지 `HotfixHelper`를 `IHotfixLauncher` 인터페이스에 맞게适配한 것으로, `StartupRunner`에서 동일한 시작 흐름을 재사용할 수 있게 합니다.
