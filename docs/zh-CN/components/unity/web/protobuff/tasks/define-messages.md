# 如何定义请求与响应消息类型

在 GameFrameX Web ProtoBuff 中,请求消息只需继承 `GameFrameX.Network.Runtime.MessageObject` 并按 protobuf-net 规则标注 `[ProtoContract]`/`[ProtoMember]`;响应消息在此基础上还要实现 `GameFrameX.Network.Runtime.IResponseMessage` 接口,才能作为 `WebComponent.Post<T>` 的泛型参数被反序列化返回。类型约束全部由 API 签名在编译期强制,定义对了就能直接 `await` 拿到强类型响应。

## 前置条件

- 已安装 `com.gameframex.unity.web.protobuff` 包(参见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L43-L74))。
- 在 Unity 的 **Player Settings → Scripting Define Symbols** 中添加宏 `ENABLE_GAME_FRAME_X_WEB_PROTOBF_NETWORK`(README 中写作 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`)。没有该宏,组件中相关的 `Post<T>` 方法不会参与编译(整个实现包在 `#if ... #endif` 条件编译内)。
- 项目中已引入 protobuf-net(`using ProtoBuf;`),消息类用它生成或手写。

## 操作步骤

### 1. 确认编译期类型约束

先看清 API 对两边的消息类型各有什么要求,再动手定义:

| 角色 | 必须满足的条件 | 出处 |
|------|----------------|------|
| 请求消息(`message` 参数) | 继承 `MessageObject` | [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108) |
| 响应消息(泛型 `T`) | 继承 `MessageObject` **且** 实现 `IResponseMessage` | [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108) |

组件对外暴露的真实签名(`where` 子句即全部硬性要求):

```csharp
public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message)
    where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
{
    return m_WebProtoBuffManager.Post<T>(url, message);
}
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108)

底层管理器签名一致,只是用 `using` 简化了命名空间:

```csharp
public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
```

Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L182)

### 2. 定义请求消息

请求消息继承 `MessageObject`,并按 protobuf-net 规则标注契约与字段编号。以下为按上述约束编写的新类型模板(自行创建,非仓库自带文件):

```csharp
using GameFrameX.Network.Runtime;
using ProtoBuf;

[ProtoContract]
public class LoginRequest : MessageObject
{
    [ProtoMember(1)] public string UserName { get; set; }
    [ProtoMember(2)] public string Password { get; set; }
}
```

### 3. 定义响应消息

响应消息比请求多一步:实现 `IResponseMessage`。以下同为按约束编写的模板:

```csharp
using GameFrameX.Network.Runtime;
using ProtoBuf;

[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)] public int Code { get; set; }
    [ProtoMember(2)] public string Token { get; set; }
}
```

### 4. 发送并接收强类型响应

定义完成后,按 README 官方用法调用即可,`T` 填你定义的响应类型:

```csharp
using GameFrameX.Web.ProtoBuff.Runtime;

// 发送请求并等待结果
LoginResponse response = await WebComponent.Post<LoginResponse>(url, request);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L108-L113)

## 常见变体

- **WebGL 平台**:同一套消息定义无需改动。WebGL 下走 `UnityWebRequest` 路径,由组件自动设置 `Content-Type: application/x-protobuf` 并把 `MessageObject` 序列化后的字节作为原始 body 上传(见 [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L83-L97));非 WebGL 平台走另一条分支。
- **超时时间**:由管理器的 `RequestTimeout`(`TimeSpan`)控制,设置秒数时会自动换算(`RequestTimeout = TimeSpan.FromSeconds(value)`),见 [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L41-L54)。
- **用 `.proto` 文件生成**:同样适用,只要生成的 C# 类满足"继承 `MessageObject`(+ 响应实现 `IResponseMessage`)"并保留 `[ProtoContract]`/`[ProtoMember]` 标注即可。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `Post<T>` 不存在 / 找不到方法 | 未定义宏 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`,条件编译把方法裁掉了 | 在 Player Settings → Scripting Define Symbols 添加宏并重新编译 |
| 泛型参数编译报错"缺少 IResponseMessage" | 响应类型只继承了 `MessageObject`,没实现 `IResponseMessage` | 给响应类加上 `, IResponseMessage` |
| 请求参数编译报错 | 请求类没有继承 `MessageObject`(例如只标了 `[ProtoContract]`) | 让请求类继承 `MessageObject` |
| 响应字段全为默认值 | 字段没标 `[ProtoMember(n)]` 或编号与服务端不一致 | 补齐/对齐字段编号 |
| 服务端解析 body 失败 | Content-Type 或序列化方式不匹配 | 确认服务端按 `application/x-protobuf` 解析 protobuf 二进制 |

## 验证

- 编译通过:`WebComponent.Post<LoginResponse>(url, request)` 能解析到方法,说明宏、继承关系、接口实现全部满足。
- 运行时:`await` 返回的 `LoginResponse` 实例中字段为服务端下发的真实值(可在 Inspector 或日志中打印确认),即定义正确。

## 背景

请求侧只要求"可被 protobuf-net 序列化的 `MessageObject`",发送前会被统一序列化为二进制;响应侧因为要在收到字节后还原成具体类型,所以通过 `IResponseMessage` 接口在类型系统上区分"这是可反序列化的响应消息"。整个收发由 `WebProtoBuffManager` 的等待队列/发送列表调度,与消息定义无耦合,定义消息时无需关心。
