# 如何切換語言：系統語言偵測、預設語言回退與偏好持久化

本頁說明在 GameFrameX Unity Localization 套件中完成一次語言切換的完整流程：讀取系統語言、在不支援時回退到預設語言、把使用者選擇持久化，並在下次啟動時優先恢復使用者偏好。

## 前置條件

- Unity 專案已安裝 `com.gameframex.unity.localization` 套件。
- 已為至少一種目標語言準備好本地化資源（語言表/語言包），並確保其中包含預設語言。
- 已能進入執行階段並存取本套件對外公開的本地化管理入口（具體類型請查閱套件的入口腳本）。

## 操作步驟

1. **確認語言資源就緒**：啟動時先確認所有候選語言的本地化資料已載入，否則切換後取不到文字。
2. **讀取持久化的使用者偏好**：啟動時優先讀取上次儲存的語言偏好（通常是 `PlayerPrefs` 或套件內自己的持久化封裝）。
   - 若存在有效偏好且該語言可用，直接套用，跳過第 3、4 步。
   - 若無偏好，繼續第 3 步。
3. **偵測系統語言**：透過 Unity 引擎提供的系統語言資訊（引擎層面為 `Application.systemLanguage`，套件內通常有對應封裝）取得目前裝置語言。
4. **匹配與回退**：將系統語言對應到套件內支援的語言：
   - 命中支援清單 → 套用該語言；
   - 未命中（例如系統語言無對應語言包）→ 回退到預設語言，保證介面始終有文案可顯示。
5. **執行切換**：呼叫本套件的切換語言入口，觸發文字重新整理（UI 上的本地化元件應隨語言變化重新取值）。
6. **持久化偏好**：使用者主動選擇語言後，立即寫入偏好儲存，確保下次啟動按第 2 步恢復。
7. **驗證**：切換後檢查介面上已顯示的本地化文字是否更新為新語言；重新啟動應用程式後確認語言仍是使用者上次的選擇。

## 常見錯誤

| 現象 | 可能原因 | 規避方法 |
|------|----------|----------|
| 切換語言後介面文字未更新 | 本地化元件未訂閱語言變化事件，或切換時新語言資料尚未載入完成 | 確認先載入語言資料再切換；檢查元件是否監聽語言變更 |
| 每次啟動都回到系統語言 | 切換後未寫入偏好，或啟動時先偵測系統語言再讀偏好 | 保證「讀偏好優先於偵測系統語言」的順序，且使用者選擇後立即持久化 |
| 介面出現空白/Key 原文 | 系統語言不在支援清單且未正確回退，或目前語言缺少對應詞條 | 確認預設語言回退邏輯生效，並補齊缺失詞條 |
| 偏好儲存的語言在換包/清除資料後失效 | 偏好儲存隨應用程式資料被清除，未做容錯 | 讀取偏好時驗證語言是否仍受支援，不支援則走回退流程 |

## 背景

這一套「偏好優先 → 系統語言 → 預設語言」的三級順序是本地化套件的通用設計：預設語言作為最後保障，確保任何情況下介面都有文案；系統語言讓首次啟動自動貼合使用者環境；持久化偏好則尊重使用者的主動選擇，避免每次啟動被系統語言覆蓋。具體的偵測、匹配與持久化實作（包括是否使用 `PlayerPrefs`、支援語言清單在哪裡定義、預設語言如何設定）請直接查閱儲存庫原始碼。
