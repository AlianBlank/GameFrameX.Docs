# RSA による暗号化・復号化と署名の使用方法

`RsaHelper` は RSA 非対称暗号化を静的メソッドにカプセル化し、Base64 キーの暗号化・復号化、署名・検証、および XML キーのキーペア生成とインスタンス暗号化・復号化をサポートします。このページでは、キー生成から暗号化・復号化、署名・検証までの完全な流れを解説します。

## 前提条件

- プロジェクトが `GameFrameX.Foundation.Encryption` アセンブリを参照し、`using GameFrameX.Foundation.Encryption;` を記述していること。
- .NET ランタイムが `System.Security.Cryptography.RSA` をサポートしていること（.NET 6+ で対応）。
- Base64 形式の RSA キーペア（PKCS#8/PKCS#1）または XML 形式のキーを用意する。ない場合は `RsaHelper.Make()` でその場で生成可能。

## 操作手順

### 1. RSA キーペア（XML 形式）を生成する

```csharp
using GameFrameX.Foundation.Encryption;

var keyPair = RsaHelper.Make(); // 辞書を返し、"privateKey" と "publicKey" を含む
string privateKeyXml = keyPair["privateKey"];
string publicKeyXml  = keyPair["publicKey"];
```

辞書内の 2 つのキーはそれぞれ XML 形式の秘密鍵（`Modulus`、`Exponent`、秘密パラメータなどを含む）と公開鍵で、そのまま保存したり Base64 に変換したりできます。

### 2. 公開鍵で暗号化、秘密鍵で復号化（XML キー）

`Encrypt(string, string)` と `Decrypt(string, string)` は XML 形式のキーを受け取り、Base64 文字列を返します。

```csharp
using GameFrameX.Foundation.Encryption;
using System.Text;

string plain = "Hello, RSA!";

// 暗号化：公開鍵 XML + 平文 → Base64 暗号文
string cipher = RsaHelper.Encrypt(publicKeyXml, plain);

// 復号化：秘密鍵 XML + Base64 暗号文 → 平文
string back = RsaHelper.Decrypt(privateKeyXml, cipher);
```

バイト配列を直接取得したい場合は、暗号化側で `RsaHelper.Encrypt(string publicKey, byte[] content)` を、復号化側で `RsaHelper.Decrypt(string privateKey, byte[] content)` を使用してください。

### 3. 公開鍵で暗号化、秘密鍵で復号化（Base64 キー）

`EncryptBase64` と `DecryptBase64` は Base64 エンコードされたキーを受け取り、内部で自動的に PKCS#8 / PKCS#1 を識別します。

```csharp
string cipher64 = RsaHelper.EncryptBase64(publicKeyBase64, plain);
string plain64 = RsaHelper.DecryptBase64(privateKeyBase64, cipher64);
```

暗号化には **OAEP-SHA256** パディングを使用します。平文が 1 ブロックの上限を超える場合は自動的にブロック分割して暗号化するため、任意の長さのデータに適しています。

### 4. 秘密鍵で署名、公開鍵で検証

署名と検証は SHA256 + PKCS#1 パディングを固定で使用し、キーも PKCS#8 と PKCS#1 の両方をサポートします。

```csharp
string signature = RsaHelper.Sign(privateKeyBase64, plain);
bool ok = RsaHelper.Verify(publicKeyBase64, plain, signature);
```

`Verify` が `true` を返せば署名が有効です。公開鍵/データ/署名のいずれかが改ざんされると `false` を返します。

### 5. インスタンスで同じキーペアを再利用する

暗号化・復号化を繰り返す必要があるシナリオに適しています（コンストラクタで `RSA` リソースを保持するため、`Dispose` を忘れずに呼び出してください）。

```csharp
using (var helper = new RsaHelper(privateKeyXml))
{
    string cipher = helper.Encrypt(plain);             // インスタンスの公開鍵で暗号化（XML 秘密鍵には公開鍵パラメータも含まれる）
    string back   = helper.Decrypt(cipher);            // インスタンスの秘密鍵で復号化
}
```

または `System.Security.Cryptography.RSA` インスタンスを直接渡すこともできます：`new RsaHelper(rsaInstance)`。

## よくあるバリエーション

| シナリオ | 推奨 API | キー形式 |
|------|---------|----------|
| Java/Go などとの相互運用、キーが PEM 内の Base64 セグメント | `EncryptBase64` / `DecryptBase64` / `Sign` / `Verify` | PKCS#8 または PKCS#1 Base64 |
| 内部 .NET システム、長期間キーを設定ファイルに保存 | `Make()` + `Encrypt` / `Decrypt` | XML |
| 大容量ファイルのブロック暗号化 | `EncryptBase64` / `DecryptBase64` | Base64（自動ブロック分割） |
| 同じキーで複数回呼び出し、インポートを繰り返さない | `new RsaHelper(key)` でインスタンス化 | XML または `RSA` オブジェクト |

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| `CryptographicException` "Bad Data" | Base64 文字列が有効な PKCS#8/PKCS#1 キーではない | PEM から `-----BEGIN/END-----` と改行を除去してから Base64 化されているか確認 |
| `Encrypt` で "Key not valid for use in specified state" | XML 文字列が公開鍵ではなく秘密鍵 | `Make()` が返す `publicKey` のみが暗号化に使用可能 |
| `Verify` が常に `false` を返す | 署名データが改ざんされた、キーペアが一致しない、または異なるハッシュで署名された | 署名対象の原文 UTF-8 と検証時が一致しているか確認。双方が SHA256 を使用しているか確認 |
| 暗号化・復号化の結果が文字化けする | 両側のパディング方式が一致していない | `EncryptBase64`/`DecryptBase64` は必ず対で使用し、いずれも OAEP-SHA256 |

## 補足（任意）

- 暗号化パディング：C-05 の修正以降、暗号化・復号化は統一して `RSAEncryptionPadding.OaepSHA256` を使用し、PKCS#1 v1.5 の Bleichenbacher 攻撃リスクを回避しています。
- 署名パディング：署名/検証は固定で `RSASignaturePadding.Pkcs1` + `HashAlgorithmName.SHA256` を使用し、多くの外部システムのデフォルトと一致しています。
- リソース管理：インスタンスメソッドはアンマネージド RSA リソースを保持するため、`new RsaHelper(...)` を使用した後は必ず `Dispose()` を呼び出すか、`using` を使用してください。
