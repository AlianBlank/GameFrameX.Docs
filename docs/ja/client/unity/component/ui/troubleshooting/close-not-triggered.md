# UIクローズがトリガーされない場合の対処方法

`CloseUIForm` を呼び出した後にUIが閉じられない、`OnClose` がトリガーされない、または `CloseUIFormComplete` イベントが配信されない場合、通常は渡されたシリアル番号が無効である、UIがロード中である、パネル自体がクローズを禁止している、あるいはアニメーションリサイクルを無効化するスイッチによってクローズコールバックが遮断されていることが原因です。本ページでは、症状別に原因を特定するための診断表と修正手順を示します。

## クイック診断

| 症状(コンソール/動作) | 原因 | 修正 |
|---|---|---|
| ログに `Can not find UI form '{serialId}'.` と出力される | 渡された `serialId` が現在使用不可(既にクローズ済み、未オープン、またはスペルミス) | `GetAllLoadedUIForms()` で実際の `SerialId` を取得してから渡す |
| 画面が消えたように見えないが、コンソールにエラーはない | UIがまだロード中で、ロードキューの「クローズ待ちリサイクル」リストに統合されている | ロード完了後に自動リサイクルされるのを待つ。またはマネージャーの後続フレームで `ReleaseAllLoadedUIForms()` を呼び出す |
| `OnClose` が呼び出されないが、イベントは既にトリガーされている | UIに `IsDisableClosing` フラグが設定されている | スクリプト内で `SetDisableClosing(true)` が呼び出されていないか確認し、クローズ前に解除する |
| `CloseUIForm<T>` を呼び出した後に何の反応もない | ジェネリックオーバーロードは `FullName` でマッチングするため、複数インスタンスのシナリオではヒットに失敗する | `IUIForm` 参照を直接保持するか、`serialId` を使ってクローズする |
| クローズ後にUIが再び表示される | `IsDisableRecycling = true` のため、インスタンスがリサイクルされず直接オブジェクトプールに戻る | 設定/スクリプト内の `IsDisableRecycling` 設定を確認する |
| クローズアニメーション再生後にUIが消えない | `EnableHideAnimation = true` の場合、`Hide` コールバックがトリガーされない | カスタム `Hide` 実装が `Action onComplete` を正しくコールバックしているか確認する |

> 上記のエラーメッセージと判定分岐はすべて [BaseUIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L79-L223) によるものです。

## 修正手順

### 1. 渡された `serialId` またはUI参照が有効か確認する

`CloseUIForm(int serialId, ...)` はまず `GetUIForm(serialId)` を呼び出し、見つからない場合は `Can not find UI form '{serialId}'.` を出力して `return` します。**例外はスローされません**。具体的な参照を使ってクローズしてください:

```csharp
// OpenUIForm の戻り値から実際の SerialId を取得する
int serialId = GameEntry.UI.OpenUIForm("UIPrefabs/LoginForm");
// クローズが必要なとき:
GameEntry.UI.CloseUIForm(serialId);
```

または `IUIForm` 参照を直接保持してクローズメソッドを呼び出し、外部で管理されるIDへの依存を避けてください。

出典: [BaseUIManager.Close.cs#L94-L104](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L94-L104)

### 2. UIがまだロード中である

クローズメソッドを呼び出した時点で、対象のUIが「ロード中」のコレクションに含まれている(`IsLoadingUIForm(serialId)` が真)場合、マネージャーはそれを `m_UIFormsToReleaseOnLoad` に入れ、**そのまま return し、`OnClose` とイベントコールバックは実行されません**。この場合、後で `ReleaseAllLoadedUIForms()` を呼び出すことで、非同期ロード完了後に即座にリサイクルさせる必要があります:

```csharp
GameEntry.UI.CloseUIForm(serialId);          // この時点ではキューに入るだけで、実際にはクローズされない可能性がある
// Update 内で検知する
GameEntry.UI.ReleaseAllLoadedUIForms(false);  // ロード完了後に再度リサイクルをトリガーする
```

出典： [BaseUIManager.Close.cs#L161-L170](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L161-L170) および [BaseUIManager.Close.cs#L287-L299](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L287-L299)

### 3. パネルがクローズを無効化している(`IsDisableClosing`)

クローズロジックはイベント配信前に以下をチェックします:

```csharp
if (uiForm.IsDisableClosing)
{
    return;
}
```

スクリプト内で誤って `SetDisableClosing(true)` が残っている場合(例：ダイアログ確認フローで一時的に無効化した後に戻し忘れた場合など)、`CloseUIForm` は**サイレントに終了**します。クローズ前に明示的に元に戻してください:

```csharp
uiForm.SetDisableClosing(false);
GameEntry.UI.CloseUIForm(uiForm);
```

出典： [BaseUIManager.Close.cs#L172-L175](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L172-L175)

### 4. ジェネリックオーバーロード `CloseUIForm<T>` がヒットしない

`CloseUIForm<T>` は `typeof(T).FullName` でマッチングを行い、`HasUIFormFullName` もヒットした場合にのみ実際にクローズされます。複数インスタンスのシナリオでは、最初にマッチしたインスタンスに遮断された後、直接 `break` する可能性があります。ビジネス側で `IUIForm` 参照を自身で保持することをお勧めします。

```csharp
// 推奨:インターフェースのインスタンスを直接取得する
IUIForm form = ...;
GameEntry.UI.CloseUIForm(form, userData: null, isNowRecycle: true);
```

出典： [BaseUIManager.Close.cs#L130-L149](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L130-L149)

### 5. イベントサブスクリプションがトリガーされない

`CloseUIFormComplete` は通常の .NET イベントであり、クローズ時にコールバックを受け取るにはまず `+=` でサブスクライブする必要があります。イベント引数は参照プールから取得され、使用後は自動的にリサイクルされるため、ビジネスコードでは `CloseUIFormCompleteEventArgs` をキャッシュしないでください:

```csharp
GameEntry.UI.CloseUIFormComplete += (sender, e) =>
{
    Debug.Log($"UIをクローズ: {e.UIFormAssetName}, SerialId={e.SerialId}");
};
```

出典： [BaseUIManager.Close.cs#L43-L57](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L43-L57) および [CloseUIFormCompleteEventArgs.cs#L43-L157](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/CloseUIFormCompleteEventArgs.cs#L43-L157)

### 6. クローズアニメーションとリサイクルの連携

`EnableHideAnimation = true` の場合、クローズ時にまず `Hide(...)` が実行され、そのコールバック内で `OnClose` と `Refresh` が呼び出されます。カスタムの `Hide` 実装が渡された `onComplete` コールバックの呼び出しを忘れた場合、`OnClose` もイベントも実行されません。アニメーション付きクローズの完全なフローは以下の通りです:

```csharp
uiGroup.RemoveUIForm(uiForm, true);   // 非表示としてマーク
uiForm.Hide(m_UIFormHideHandler, () =>
{
    uiForm.OnClose(m_IsShutdown, userData);
    uiGroup.Refresh();
    if (isNowRecycle)
        RecycleUIForm(uiForm, true);
});
```

即座に破棄したいだけの場合(GameObject を含む)は `isNowRecycle` を `true` に設定すると、マネージャーは `RecycleUIForm` を同期的に呼び出し、リサイクルキューをスキップします。

出典: [BaseUIManager.Close.cs#L180-L202](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L180-L202)

## 検証

1. クローズインターフェース呼び出し後、ログに `Can not find UI form '{serialId}'.` が**出力されなくなる**ことを確認します。
2. `CloseUIFormComplete` のサブスクライブ関数が少なくとも1回トリガーされ、`OnClose` ライフサイクルがヒットしていること。
3. クローズ後、次の `GetAllLoadedUIForms()` にその `SerialId` が含まれなくなっていること(`IsDisableRecycling = true` の場合を除く)。
4. `m_UIFormsBeingLoaded` と `m_UIFormsToReleaseOnLoad` が空になっていることを確認(`CloseAllLoadingUIForms` / `ReleaseAllLoadedUIForms` の動作が期待通りであること)。
