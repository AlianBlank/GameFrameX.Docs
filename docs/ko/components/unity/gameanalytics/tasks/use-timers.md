# 타이머를 사용하여 시간을 집계하는 방법 (시작 / 일시정지 / 재개 / 종료)

`GameAnalyticsComponent`(또는 하위 `IGameAnalyticsManager`)의 네 가지 타이머 인터페이스를 호출하는 것만으로 완전한 시간 집계를 수행할 수 있습니다: `StartTimer` 시작, `PauseTimer` 일시정지, `ResumeTimer` 재개, `StopTimer` 종료 및 해당 이벤트의 시간 데이터 생성. 네 인터페이스 모두 하나의 매개변수 `eventName`(이벤트 이름)만 받으며, 컴포넌트는 이를 초기화된 모든 분석 백엔드로 전달합니다.

## 사전 조건

- 씬에 `GameAnalyticsComponent`가 부착되어 있고 초기화(`Init` / `ManualInit`)가 완료되어 있어야 합니다. 초기화되지 않은 상태에서 타이머 호출은 조용히 무시되며, `GameAnalyticsManager is not init.` 경고가 출력될 수 있습니다.
- 구체적인 초기화 절차는 해당 컴포넌트 문서를 참조하십시오.

## 작업 단계

1. 컴포넌트가 초기화되었는지 확인합니다(`IsInit()`가 `true` 반환).
2. 게임플레이 시작 지점에서 `StartTimer`를 호출하고 이번에 집계할 이벤트 이름을 전달합니다:

```csharp
public void StartTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StartTimer(eventName);
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/README.md#L80-L86)

3. (선택 사항) 백그라운드로 전환하거나 플레이어가 게임플레이를 떠날 때 `PauseTimer`를 호출하여 누적을 일시정지합니다:

```csharp
_gameAnalyticsComponent.PauseTimer("level_1_playtime");
```

4. (선택 사항) 플레이어가 돌아오면 `ResumeTimer`를 호출하여 누적을 계속합니다:

```csharp
_gameAnalyticsComponent.ResumeTimer("level_1_playtime");
```

5. 게임플레이 종료 시 `StopTimer`를 호출하여 타이머를 종료하면, 시간 데이터가 이벤트 이름과 함께 전송됩니다:

```csharp
public void StopTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StopTimer(eventName);
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/README.md#L90-L96)

### 복사하여 바로 사용할 수 있는 완전한 래퍼

```csharp
private const string LevelTimerName = "level_1_playtime";

public void OnLevelStart()
{
    GameAnalyticsComponent.Instance.StartTimer(LevelTimerName);
}

public void OnApplicationPause(bool pauseStatus)
{
    if (pauseStatus)
    {
        GameAnalyticsComponent.Instance.PauseTimer(LevelTimerName);
    }
    else
    {
        GameAnalyticsComponent.Instance.ResumeTimer(LevelTimerName);
    }
}

public void OnLevelFinish()
{
    GameAnalyticsComponent.Instance.StopTimer(LevelTimerName);
}
```

참고: `GameAnalyticsComponent.Instance`의 구체적인 획득 방식은 프로젝트의 컴포넌트 등록 방식에 따라 다릅니다. 위의 네 가지 메서드 이름과 시그니처는 모두 저장소의 실제 인터페이스에서 가져온 것입니다.

## 일반적인 변형

- **일시정지가 필요 없는 짧은 시간 집계**: `StartTimer`와 `StopTimer`만 호출하면 되며, `PauseTimer` / `ResumeTimer`는 생략할 수 있습니다(README에 제시된 공식 예시도 이 두 가지 호출만 포함).
- **여러 이벤트의 병렬 타이머**: 서로 다른 `eventName`으로 각각 `StartTimer`를 호출하면 각 타이머는 서로 영향을 주지 않습니다. 동일한 이벤트 이름을 반복해서 시작하는 동작은 하위 분석 백엔드에 따라 결정되므로, 동일한 이벤트 이름은 직렬로 사용할 것을 권장합니다.
- **하위 Manager 직접 연동**: 컴포넌트를 거치지 않고 `IGameAnalyticsManager` 구현체를 직접 보유하는 경우, 컴포넌트 순회를 우회하여 동일한 이름의 인터페이스를 직접 호출할 수 있습니다. `BaseGameAnalyticsManager`는 네 가지 타이머 메서드를 추상 메서드로 선언하며, 구체적인 백엔드에서 구현합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 타이머 호출 시 데이터가 전혀 전송되지 않음 | 컴포넌트가 초기화되지 않아 `m_IsInit == false`일 때 메서드가 바로 `return`함 | 먼저 `Init` / `ManualInit`를 호출한 후 타이머 시작 |
| 로그에 `GameAnalyticsManager is not init.`가 나타남 | `StartTimer` / `StopTimer`가 순회 중 일부 백엔드의 `IsInit()`가 `false`임을 발견 | 각 분석 백엔드가 모두 초기화 완료되었는지 확인 |
| 빈 이벤트 이름 전달 시 즉시 예외 발생 | `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))`가 빈 값/`null`을 차단함 | `eventName`이 비어 있지 않도록 보장 |
| 일시정지 후에도 시간이 계속 계산됨 | `PauseTimer` 외의 메서드만 호출했거나 이벤트 이름이 일치하지 않음 | 일시정지와 재개는 시작 시와 동일한 `eventName`을 사용해야 함 |

`StartTimer`를 예로 들면, 컴포넌트 내부의 매개변수 및 초기화 상태 검사는 다음과 같습니다(`StopTimer`도 동일한 로직):

```csharp
public void StartTimer(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.StartTimer(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179)

## 검증

- `StopTimer` 호출 후, 해당 분석 플랫폼(GameAnalytics 대시보드)에서 해당 `eventName`의 시간 데이터가 나타나는지, 수치가 합리적인지 확인합니다.
- 데이터가 없다면 Console에 `GameAnalyticsManager is not init.` 경고가 있는지 확인하고, `eventName`이 비어 있지 않은지, 시작과 종료에 동일한 이름을 사용했는지 확인합니다.

## 배경

`GameAnalyticsComponent`는 네 가지 타이머 인터페이스의 퍼사드입니다. 먼저 매개변수 가드와 초기화 검사를 수행한 후, 호출을 `m_GameAnalyticsManager` 목록에 있는 초기화된 모든 `IGameAnalyticsManager` 구현체에 브로드캐스트합니다(`PauseTimer` / `ResumeTimer`의 브로드캐스트는 두 번째 `IsInit()` 검사를 수행하지 않지만, 마찬가지로 컴포넌트 수준의 `m_IsInit`에 의해 차단됩니다). 실제 타이머 로직은 각 분석 백엔드가 `BaseGameAnalyticsManager`의 추상 메서드에서 구현합니다.
