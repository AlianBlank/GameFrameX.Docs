# 優先度と同時実行で再生リクエストを制御する方法

`PlaySoundParams.Priority` とサウンドグループの `AvoidBeingReplacedBySamePriority` スイッチを使用することで、同じサウンドグループ内における複数の同時再生リクエスト間の割り込み動作を制御できます。優先度の数値が大きいほど優先され、割り込みが発生した場合、再生中のサウンドは新しいリクエストに置き換えられます。

## 前提条件

- `GameFrameX.Sound.Runtime` でサウンドグループを登録し、そのサウンドグループに少なくとも1つのサウンドエージェント(`SoundAgent`)を割り当て済みであること。
- 呼び出し元が `ISoundManager` インスタンスを取得できること(通常は `GameEntry.Sound` 経由)。

## 操作手順

1. 再生前に参照プールからパラメータオブジェクトを作成し、優先度を設定してから `PlaySound` のオーバーロードに渡します:

```csharp
using GameFrameX.Sound.Runtime;

var p = PlaySoundParams.Create(isLoop: false);
p.Priority = 100; // 数値が大きいほど優先される
p.FadeInSeconds = 0.1f;

int serialId = GameEntry.Sound.PlaySound("sfx/click", "SoundEffect", p);
```

出典: [PlaySoundParams.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundParams.cs#L105-L239)

2. サウンドグループに対して、同じ優先度での相互割り込みを許可するかどうかを設定します。デフォルトでは、新しいリクエストの優先度が現在再生中のサウンドより**厳密に大きい**場合にのみ置き換えられます。同じ優先度でも新しいサウンドに置き換えられるようにしたい場合は、このスイッチをオンにします:

```csharp
ISoundGroup group = GameEntry.Sound.GetSoundGroup("SoundEffect");
group.AvoidBeingReplacedBySamePriority = false; // 同じ優先度でも割り込まれる
```

出典： [ISoundGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Interface/ISoundGroup.cs#L50-L53)

3. 再生失敗イベントを監視し、「優先度が低いために無視された」リクエストを捕捉して、計測やフォールバックのロジックに使用します:

```csharp
GameEntry.Sound.PlaySoundFailure += (sender, args) =>
{
    if (args.ErrorCode == PlaySoundErrorCode.IgnoredDueToLowPriority)
    {
        // 現在のグループ内のエージェントがすべて使用中で、優先度も割り込みに足りないため破棄された
    }
};
```

出典: [PlaySoundErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundErrorCode.cs#L60-L64)

## よくあるバリエーション

- **重要な音声を一切中断させない**:セリフやストーリー用の音声を再生する際、`Priority` を通常の効果音よりはるかに高い値(例： 1000)に設定し、対象グループの `AvoidBeingReplacedBySamePriority` を `true` のままにしておきます。これにより、同じ優先度のBGMに追い出されることはありません。
- **同じグループに複数エージェントで高同時実行**:`SoundEffect` グループに複数の `SoundAgent`(例： 8〜16個)を割り当て、多くの短い効果音を並行再生できるようにします。こうすると、新しいリクエストがエージェントすら確保できなかった場合にのみ、優先度による裁定が行われます。
- **同時再生数の上限だけを設定**：優先度を区別せず、同じグループでの同時再生数を制限したいだけの場合は、すべてのリクエストにデフォルトの優先度(`Constant.DefaultPriority`)を使用させ、`AvoidBeingReplacedBySamePriority = true` を維持します。最も早く追加されたサウンドが新しいリクエストによって追い出されます。

## よくある間違い

- **優先度を音量やピッチと混同する**:`Priority` は整数型であり、割り込みの裁定にのみ使用されます。`VolumeInSoundGroup` や `Pitch` とは無関係です。
- **同じ優先度でも置き換えられると期待しているのにスイッチを変更していない**:デフォルトでは `AvoidBeingReplacedBySamePriority = true` であり、新しいサウンドの優先度が再生中のサウンドより厳密に高くなければ割り込みできず、それ以外の場合は `IgnoredDueToLowPriority` が返されます。
- **パラメータオブジェクトの返却を忘れる**:`PlaySoundParams` は参照プールから取得されるため、使用後は速やかに `ReferencePool.Release(p)` を呼び出してください。長期間保持すると状態が汚染される原因になります。
- **グループ内に利用可能なエージェントがないまま再生を実行する**:グループにエージェントが割り当てられていない場合も同様に失敗します。事前に `SoundGroup.SoundAgentCount > 0` を確認してください。

## 背景(任意)

`ISoundAgent` と `ISoundAgentHelper` はどちらも毎フレーム `Priority` を基盤となる `AudioSource` に同期し、マネージャーは「エージェント + 優先度」モデルに基づいて割り込みを裁定します。優先度の数値は相対的な概念であり、実装側は重要な音源が通常の音源より高くなることを保証するだけで十分です。
