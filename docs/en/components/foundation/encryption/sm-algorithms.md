# How to Use SM2/SM3/SM4 (Chinese National Cryptographic Standards)

`GameFrameX.Foundation.Encryption` provides a one-stop entry point for the three Chinese national cryptographic algorithms: `Sm2Helper` (asymmetric encryption/decryption / key pair generation), `Sm4Helper` (symmetric encryption/decryption, supporting CBC / ECB), and BouncyCastle-based `SM3Util.Hash` (SM3 digest). This page provides minimal working code examples for all three algorithms along with common pitfalls.

## Prerequisites

- Import the namespaces: `GameFrameX.Foundation.Encryption`, `GameFrameX.Foundation.Encryption.Sm`.
- The project references BouncyCastle (`Org.BouncyCastle.*`), which is included by default with the framework.
- SM2 public/private keys are hexadecimal strings; SM4 keys are 16 bytes in non-hex mode, and 32 hexadecimal characters in hex mode.

## Steps

### 1. SM3 Hashing

SM3 is a hash algorithm, not an encryption algorithm. `SM3Util.Hash` accepts a string and returns a fixed-length (256-bit) hexadecimal digest, using UTF-8 encoding internally to ensure cross-platform consistency.

```csharp
using GameFrameX.Foundation.Encryption.Sm;

string hash = SM3Util.Hash("hello world");
// Multiple calls with the same input produce identical results, which can be used for integrity verification
```

Source: [SM3Util.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm/SM3Util.cs#L47-L69)

### 2. SM2 Asymmetric Encryption

`Sm2Helper` provides both string and byte array overloads and supports key pair generation; it is built on top of BouncyCastle.

```csharp
using GameFrameX.Foundation.Encryption;

// Generate a key pair
Sm2Helper.GenerateKeyPair(out string publicKey, out string privateKey);

// Encrypt with the public key
string cipher = Sm2Helper.Encrypt(publicKey, "secret message");

// Decrypt with the private key
string plain = Sm2Helper.Decrypt(privateKey, cipher);
```

Byte array overloads (suitable for binary data / network protocols):

```csharp
byte[] pubKeyBytes = Convert.FromHexString(publicKey);
byte[] data = System.Text.Encoding.UTF8.GetBytes("payload");
string cipherHex = Sm2Helper.Encrypt(pubKeyBytes, data);
byte[] plainBytes = Sm2Helper.Decrypt(Convert.FromHexString(privateKey), Convert.FromHexString(cipherHex));
```

Source: [Sm2Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm2Helper.cs#L62-L174)

### 3. SM4 Symmetric Encryption

`Sm4Helper` uses CBC mode by default; key length rules: 16 bytes in non-hex mode, 32 characters in hex mode; when `iv` is not provided, hex mode defaults to all zeros (`00000000000000000000000000000000`).

CBC encryption / decryption:

```csharp
using GameFrameX.Foundation.Encryption;

string key = "0123456789abcdef";        // 16 bytes
string cipher = Sm4Helper.EncryptCbc(key, "明文文本");
string plain  = Sm4Helper.DecryptCbc(key, cipher);
```

ECB mode (no IV required):

```csharp
string cipher = Sm4Helper.EncryptEcb(key, "明文文本");
string plain  = Sm4Helper.DecryptEcb(key, cipher);
```

JavaScript compatibility mode (padding behavior interoperable with frontend libraries such as sm-crypto):

```csharp
string cipher = Sm4Helper.EncryptCbc(key, "明文", forJavascript: true);
string plain  = Sm4Helper.DecryptCbc(key, cipher, forJavascript: true);
```

hex key mode:

```csharp
string hexKey = "0123456789ABCDEF0123456789ABCDEF"; // 32 hexadecimal characters
string cipher = Sm4Helper.EncryptCbc(hexKey, "明文", hexString: true);
```

## Common Variants

| Scenario | Recommended Practice |
|------|----------|
| Interoperability with frontend / Node | Use `forJavascript: true` for SM4, and the same mode with sm-crypto on the frontend |
| Signature verification for long messages | First compute the digest with `SM3Util.Hash`, then transmit it alongside business fields for comparison |
| High-frequency encryption/decryption of binary streams | Use the byte array overloads of SM2 / SM4 to avoid string encoding/decoding overhead |
| Persisting SM2 keys | Store the hexadecimal string output by `GenerateKeyPair` directly; do not Base64-encode it yourself |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentException: KeyMustBe16Characters` | SM4 key is not 16 bytes in non-hex mode | Adjust the string length, or use `hexString: true` with a 32-character hex key |
| `ArgumentException: KeyMustBe32Characters` | hex-mode key length is not 32 | Check whether the hex string was truncated or padded with extra characters |
| SM2 decryption throws `CryptographicException(Sm2InvalidDataFormat)` | Public/private key mismatch, or the ciphertext was incorrectly double-encoded | Confirm that both sides use consistent hex casing and no extra Base64 encoding was applied |
| SM3 hash differs across platforms | Input was re-encoded with `Encoding.Default` | Always pass UTF-8-encoded input; `SM3Util.Hash` already uses UTF-8 internally |
| `ArgumentException(PublicKeyStringCannotBeEmpty)` | SM2 public key string is empty | Check that the `GenerateKeyPair` output was not truncated |

## Background (Optional)

`Sm2Helper` / `Sm4Helper` are thin, business-oriented wrappers; all the underlying logic (elliptic curve point operations, SM4 round key expansion, etc.) is handled by BouncyCastle; `SM3Util` directly reuses BouncyCastle's `Sm3Digest`. Exceptions from the three algorithms are caught at the `Sm*Helper` layer and uniformly wrapped as `CryptographicException`, making it easy for upper layers to catch a single exception type.
