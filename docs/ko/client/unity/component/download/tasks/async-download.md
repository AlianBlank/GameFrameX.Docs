# await를 사용하여 다운로드 완료를 비동기로 대기하기

`DownloadComponent`는 `Task<bool>`를 반환하는 `Download` 메서드를 제공하며, 코루틴이나 비동기 메서드에서 `await`로 파일 다운로드 완료를 직접 기다릴 수 있어 이벤트 콜백을 구독할 필요가 없습니다.

## 사전 조건

- 씬에 `DownloadComponent` 컴포넌트가 이미 추가되어 있어야 합니다(`[GameFrameXAutoComponent(-4000)]`를 통해 자동 등록됨).
- 비즈니스 코드에서 `DownloadComponent` 인스턴스를 가져올 수 있어야 하며, 일반적으로 `GameEntry.GetComponent<DownloadComponent>()`로 획득합니다.

## 작업 단계

1. `DownloadComponent.Download(downloadPath, downloadUri)`를 호출하여 `Task<bool>`를 얻습니다.
2. `async` 메서드에서 이 작업을 `await`하며, 값이 `true`이면 다운로드 성공, `false`이면 실패 또는 다운로드가 시작되지 않았음을 의미합니다.
3. 반환값에 따라 후속 로직(리소스 로드, 오류 알림 등)을 결정합니다.

최소 사용 예제:

```csharp
using System.Threading.Tasks;
using GameFrameX.Download.Runtime;

public async Task LoadRemoteConfigAsync()
{
    var download = GameEntry.GetComponent<DownloadComponent>();
    bool ok = await download.Download(
        downloadPath: Application.persistentDataPath + "/config.json",
        downloadUri:  "https://example.com/config.json");

    if (ok)
    {
        // 로컬 파일을 읽어 후속 로직을 진행
    }
    else
    {
        // 다운로드 실패 시 폴백 처리
    }
}
```

## 일반적인 변형

- 태그 또는 우선순위가 있는 버전은 여전히 기존 `AddDownload` 흐름을 따르며, `Download` 메서드는 현재 가장 많이 사용되는 `(path, uri)` 오버로드만 노출합니다. 커스텀 태그나 우선순위가 필요한 경우 `AddDownload` + 이벤트 방식을 계속 사용할 수 있습니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `await`가 영원히 반환되지 않고 값이 계속 `false`임 | 다운로드 작업이 아직 다운로드 관리자에 진입하지 않아 `m_Downloads.TryGetValue`가 실패하고, 이미 `TrySetResult(false)`가 적용된 작업이 바로 반환됨 | 경로와 URI가 유효한지 확인하고, `DownloadComponent`가 `Start`되었는지 확인(`EventComponent` 및 `m_DownloadManager`에 의존) |
| 호출 지점에서 `NullReferenceException` 발생 | 비즈니스 측의 `DownloadComponent`가 씬에 없거나 아직 Awake되지 않음 | `GameEntry.GetComponent<DownloadComponent>()`로 획득하고, 먼저 null 여부 확인 |
| 여러 작업 동시 실행 시 반환된 `Task`가 서로 덮어써짐 | `Download` 메서드는 `serialId`를 기반으로 내부 딕셔너리에서 해당 `TaskCompletionSource<bool>`를 조회함 | 서로 다른 다운로드는 독립된 `await` 변수로 받아 반환값 혼용을 피함 |

## 배경(선택)

내부적으로 `ConcurrentDictionary<int, DownloadData>`를 사용하여 `serialId`에서 `TaskCompletionSource<bool>`로의 매핑을 유지합니다. `Awake`에서 `DownloadSuccess` / `DownloadFailure` 이벤트를 구독하고, 콜백에서 `TrySetResult(true/false)`를 호출하여 이벤트 기반 API를 `Task` API로 변환합니다.
