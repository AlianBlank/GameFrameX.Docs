# 자식 스레드에서 안전하게 이벤트를 디스패치하는 방법

자식 스레드(예: 네트워크 스레드, Task, 비동기 콜백)에서 `FireNow`가 아닌 `Fire`를 호출하기만 하면 이벤트를 안전하게 디스패치할 수 있습니다. 이 작업은 스레드 안전하며, 이벤트는 큐에 적재되어 메인 스레드의 다음 프레임에 이벤트 처리 함수가 콜백되는 것이 보장됩니다. 처리 함수 안에서는 안심하고 Unity API에 접근할 수 있습니다.

## 사전 조건

- 씬에 `EventComponent`가 부착된 오브젝트가 이미 존재함(또는 모듈 시스템을 통해 `EventManager`를 이미 획득함).
- 메인 스레드에서 먼저 이벤트 구독(`Subscribe` / `CheckSubscribe`)을 완료하고, 자식 스레드는 `Fire`만 담당합니다.

## 작업 단계

1. 메인 스레드(예: `Awake`/`Start`)에서 씬에 있는 `EventComponent`의 참조를 통해 이벤트를 구독합니다. `Fire`로 디스패치한 이벤트는 처리 함수가 없어도 오류가 발생하지 않습니다(이벤트 풀이 `AllowNoHandler | AllowMultiHandler` 모드로 생성됨):

```csharp
private void Start()
{
    // CheckSubscribe: 존재하지 않을 때만 구독하여 중복 등록을 방지
    eventComponent.CheckSubscribe(DownloadFinishedEventArgs.EventId, OnDownloadFinished);
}

private void OnDownloadFinished(object sender, GameEventArgs e)
{
    // Fire로 디스패치한 이벤트는 메인 스레드에서 콜백이 보장되므로 Unity 오브젝트를 직접 조작할 수 있음
    Debug.Log("下载完成");
}
```

`CheckSubscribe`의 실제 구현(존재하지 않을 때만 구독):

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

2. 자식 스레드에서 스레드 안전한 `Fire`를 호출하여 이벤트를 디스패치합니다(아래는 호출 방식 예시이며, `EventComponent`의 실제 인터페이스는 단계 끝의 소스 코드 발췌를 참고하세요). 이벤트는 던져진 후 **다음 프레임**에 메인 스레드에서 전달됩니다:

```csharp
// 자식 스레드 코드(예: Task.Run / 네트워크 라이브러리 콜백), eventComponent는 씬에 있는 EventComponent의 참조
Task.Run(() =>
{
    byte[] data = DownloadFromNetwork(); // 시간이 오래 걸리는 작업
    eventComponent.Fire(this, EmptyEventArgs.Create(DownloadFinishedEventArgs.EventId));
});
```

`EventComponent.Fire`는 두 개의 오버로드를 제공하며, 그중 이벤트 ID로 디스패치하는 오버로드는 내부적으로 `EmptyEventArgs.Create(eventId)`를 사용하고 ID에 대해 비어 있지 않음을 검증합니다:

```csharp
public void Fire(object sender, GameEventArgs e)
{
    m_EventManager.Fire(sender, e);
}

public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L147-L161)

3. 사용자 정의 데이터를 함께 전달해야 할 때는 `GameEventArgs`를 상속하는 파라미터 타입을 직접 정의하고, 자식 스레드에서 데이터를 채운 후 `Fire`와 함께 던집니다(아래는 호출 방식 예시이며, `EmptyEventArgs`는 리포지토리에 내장된 인자 없는 이벤트이고, 사용자 정의 파라미터 클래스도 같은 방식으로 구현합니다):

```csharp
public class DownloadFinishedEventArgs : GameEventArgs
{
    public const string EventId = "Download.Finished";
    public byte[] Data { get; set; }
}

// 자식 스레드에서 디스패치:
eventComponent.Fire(this, new DownloadFinishedEventArgs { Data = data });

// 메인 스레드 처리 함수에서 읽기:
private void OnDownloadFinished(object sender, GameEventArgs e)
{
    var args = (DownloadFinishedEventArgs)e;
    UseBytes(args.Data);
}
```

`GameEventArgs`는 상속이 개방된 추상 기본 클래스로, `GameFrameX.Event.Runtime` 네임스페이스에 위치합니다:

```csharp
public abstract class GameEventArgs : BaseEventArgs
{
}
```

출처: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

## 일반적인 변형

| 시나리오 | 방법 |
|------|------|
| 알림만 필요하고 데이터가 없는 경우 | `Fire(sender, eventId)` 문자열 오버로드, 내부에서 `EmptyEventArgs.Create(eventId)`로 빈 파라미터를 생성 |
| `IEventManager`를 직접 보유하는 경우 | `IEventManager.Fire(object sender, GameEventArgs e)`, 컴포넌트 래퍼와 동작이 동일 |
| 이벤트가 메인 스레드에서만 발생하며 같은 프레임에 적용되어야 하는 경우 | `FireNow`를 사용하되, **자식 스레드에서 호출해서는 절대 안 됨**(아래 참조) |

## 흔한 실수

| 실수 | 결과 및 회피 방법 |
|------|-----------|
| 자식 스레드에서 `FireNow` 호출 | `FireNow`는 **스레드 안전하지 않으며**, 호출한 스레드에서 즉시 디스패치되어 처리 함수가 자식 스레드에서 실행되고 Unity가 크래시될 수 있습니다. 자식 스레드에서는 반드시 `Fire`를 사용하세요. 소스 코드 주석에 명시되어 있습니다: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L167-L175) |
| `Fire`가 같은 프레임에 적용되기를 기대함 | `Fire`로 디스패치한 이벤트는 던져진 후 다음 프레임에야 전달되므로, 같은 프레임 타이밍에 의존하는 로직(예: 즉시 상태 읽기)은 처리 함수 콜백 이후에 실행되도록 변경해야 합니다 |
| 자식 스레드에서 `Subscribe`/`Unsubscribe` | 구독 테이블 작업에는 스레드 안전성 보장이 없으므로, 처리 함수의 추가/제거는 메인 스레드에서만 수행하세요 |
| 이벤트 ID로 빈 문자열 전달 | `Fire(sender, eventId)` 내부의 `GameFrameworkGuard.NotNullOrEmpty`가 검증 예외를 즉시 던집니다 |

## 배경

`EventManager`는 `GameFrameworkModule`(우선순위 7)입니다. `Fire`는 이벤트를 내부 `EventPool<GameEventArgs>` 큐에 넣습니다. 모듈은 매 프레임 메인 스레드의 `Update`에서 `m_EventPool.Update(elapseSeconds, realElapseSeconds)`를 호출하여 큐를 비우고 처리 함수를 콜백하며, 이것이 "자식 스레드에서 던지고, 메인 스레드에서 콜백하고, 다음 프레임에 전달한다"의 유래입니다. 관련 구현은 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L76-L92)와 [IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L93-L104)를 참고하세요.
