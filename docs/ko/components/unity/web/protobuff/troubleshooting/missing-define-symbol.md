# Post 메서드가 존재하지 않거나 컴파일 오류가 발생하는 경우(매크로 미정의)

`WebProtoBuffComponent.Post<T>()`를 호출했을 때 메서드가 존재하지 않는다는 메시지가 표시되거나, 컴파일러가 `GameFrameX.Network.Runtime.MessageObject` 타입을 찾을 수 없다고 오류를 보고하는 경우, 거의 모두 같은 원인입니다: 프로젝트에 `com.gameframex.unity.network` 패키지가 설치되어 있지 않아 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 매크로가 자동으로 정의되지 않았고, `Post` 관련 코드가 조건부 컴파일에 의해 통째로 잘려나갔기 때문입니다.

## 빠른 진단

|------|------|------|
| `'WebProtoBuffComponent' does not contain a definition for 'Post'`(CS1061) | `Post<T>` 메서드 전체가 `#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`로 감싸져 있어, 매크로가 정의되지 않으면 메서드가 존재하지 않음 | `com.gameframex.unity.network` 패키지를 설치하여 매크로가 자동으로 적용되도록 함, 아래 [해결 단계](#1-네트워크-패키지-설치-확인) 참조 |

매크로 잘라내기 로직은 소스 코드에서 직접 확인할 수 있습니다. `Post` 메서드 전체가 조건부 컴파일로 감싸져 있습니다:

```csharp
#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
        /// <summary>
        /// Post 요청을 전송하며, Protocol Buffer 메시지를 전송하고 수신하는 데 사용됩니다.
        /// 이 메서드는 ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK 매크로 정의가 활성화되어 있을 때만 사용할 수 있습니다.
        /// </summary>
        public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
        {
            return m_WebProtoBuffManager.Post<T>(url, message);
        }
#endif
```

출처: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

인터페이스 `IWebProtoBuffManager`의 `Post`도 동일한 방식으로 작성되어 있으며([IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L11-L24)), `Timeout` 속성은 항상 사용할 수 있고 매크로의 영향을 받지 않습니다.

## 해결 단계

### 1. 네트워크 패키지 설치 확인

매크로는 수동으로 구성하는 것이 아니라 런타임 어셈블리 정의 파일의 `versionDefines`에 의해 자동으로 제어됩니다: 프로젝트에 `com.gameframex.unity.network` 패키지가 존재하기만 하면 Unity가 자동으로 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`를 정의합니다.

```json
  "versionDefines": [
    {
      "name": "com.gameframex.unity.network",
      "expression": "",
      "define": "ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK"
    }
  ]
```

출처: [GameFrameX.Web.ProtoBuff.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L17-L23)

확인 및 설치 방법:

1. Unity 메뉴에서 `Window → Package Manager`를 열고 `Packages: In Project` 뷰로 전환합니다.
2. `com.gameframex.unity.network`를 찾습니다(표시 이름은 일반적으로 GameFrameX Network).
3. 없다면 `+ → Add package from git URL...`를 선택하여 네트워크 패키지의 저장소 주소를 입력해 추가합니다.
4. 의존하는 어셈블리에는 `GameFrameX.Runtime`, `GameFrameX.Web.Runtime`, `ProtoBuffer.Runtime`도 포함됩니다([asmdef 참조 목록](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L4-L9) 참조). 정상적인 경우 이들은 의존성으로 함께 설치됩니다.

### 2. Unity가 스크립트 정의를 새로 고치도록 하기

패키지 설치가 완료되면 Unity가 자동으로 `versionDefines`를 새로 고치고 재컴파일을 트리거합니다. 그렇지 않은 경우:

1. 메뉴에서 `Assets → Reimport All`을 실행하거나, 프로젝트 루트 디렉터리 아래의 `Library/ScriptAssemblies` 폴더를 삭제한 뒤 Unity를 다시 엽니다.
2. 컴파일이 완료될 때까지 기다린 후 Console에 오류가 없는지 확인합니다.

### 3. 수동으로 매크로 정의하기(폴백)

네트워크 패키지가 이미 설치되어 있는데도 매크로가 여전히 적용되지 않는다면(예: 구버전 Unity에서 `versionDefines` 지원에 이상이 있는 경우):

1. `Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`를 엽니다.
2. `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`를 추가합니다(여러 매크로는 세미콜론으로 구분).
3. Enter 키를 눌러 저장하고 재컴파일이 완료될 때까지 기다립니다.

주의: 매크로를 수동으로 정의하는 것은 어디까지나 폴백일 뿐입니다. 네트워크 패키지가 실제로 누락된 경우 `Post` 내부에서 참조하는 `MessageObject`, `IResponseMessage` 타입이 여전히 존재하지 않아 컴파일은 계속 실패합니다. 따라서 반드시 단계 1을 먼저 완료하세요.

## 검증

1. 아무 스크립트에서나 `webProtoBuffComponent.Post<`를 입력하면 IDE가 `Post<T>(string url, MessageObject message)` 오버로드를 자동 완성으로 표시해야 합니다.
2. `Project Settings → Player → Script Compilation`에서 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`가 적용된 것을 확인할 수 있습니다(또는 수동으로 확인 가능).
3. 씬에서 `WebProtoBuff Component`가 부착된 오브젝트의 Inspector가 정상적으로 표시되고, Console에 `Web manager is invalid.` 치명적 로그가 없어야 합니다(이 로그는 컴포넌트가 올바르게 초기화되지 않았음을 나타내며, 매크로 문제와는 다릅니다).

## 배경

`Post`는 네트워크 계층의 protobuf 메시지 타입에 의존하는데, 네트워크 패키지는 선택적 의존성이므로 이 컴포넌트는 asmdef의 `versionDefines`를 사용하여 "네트워크 패키지가 설치되어 있을 때만 Post 메서드를 노출"하는 필요에 따른 잘라내기를 구현합니다: `expression`이 비어 있으면 해당 패키지의 모든 버전이 조건을 충족한다는 의미입니다. 오류 발생 지점이 인터페이스가 아니라 컴포넌트 클래스에서 자주 나타나는 이유이기도 합니다. 두 곳의 `#if`는 동시에 존재하기 때문입니다.
