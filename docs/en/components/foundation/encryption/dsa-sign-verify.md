# How to Sign and Verify with DSA

`DsaHelper` provides signing and verification capabilities for the DSA digital signature algorithm, using SHA256 as the digest algorithm, with keys stored and retrieved as XML strings. This page demonstrates the complete steps from generating a key pair, signing and verifying a single string, to reusing a `DsaHelper` instance.

## Prerequisites

- The project references the `GameFrameX.Foundation.Encryption` package.
- The target framework is .NET (supporting `System.Security.Cryptography.DSA`); `DsaHelper` uses `DSA.Create()` internally, so it works across Windows / Linux / macOS.
- Use the namespace `using GameFrameX.Foundation.Encryption;`.

## Steps

### 1. Generate a DSA Key Pair

Call `DsaHelper.Make()` to obtain the private and public key XML strings in one go, retrieving them with the key names `privatekey` and `publickey` respectively:

```csharp
using GameFrameX.Foundation.Encryption;

var keys = DsaHelper.Make();
string privateKey = keys["privatekey"]; // XML private key
string publicKey  = keys["publickey"];  // XML public key
```

Source: [DsaHelper.cs#L127-L140](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L127-L140)

### 2. Sign String Data (Static Method)

Pass the string to sign and the private key into `SignData(string, string)`, which returns a Base64-encoded signature value. If the private key format is incorrect, a `CryptographicException` is thrown with the message `"Invalid DSA private key."`.

```csharp
using GameFrameX.Foundation.Encryption;

string data = "hello world";
string signature = DsaHelper.SignData(data, privateKey); // Returns a Base64 string
```

The actual signing process: `Encoding.UTF8.GetBytes` → `DSA.SignData(..., HashAlgorithmName.SHA256)` → `Convert.ToBase64String`.

Source: [DsaHelper.cs#L189-L200](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L189-L200)

### 3. Verify a String Signature (Static Method)

Pass the original text, Base64 signature, and public key into `VerifyData(string, string, string)`. A return value of `true` means the signature is valid; it returns `false` when the public key format is incorrect or the signature is invalid (no exception is thrown):

```csharp
using GameFrameX.Foundation.Encryption;

bool ok = DsaHelper.VerifyData(data, signature, publicKey);
```

Under the hood it calls `DSA.VerifyData(..., HashAlgorithmName.SHA256)` and returns `false` after catching `CryptographicException` and `XmlException`.

Source: [DsaHelper.cs#L282-L287](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L282-L287)

### 4. Sign and Verify Byte Arrays Directly (Optional)

To avoid string/Base64 encoding and decoding, you can also use the `byte[]` overload. During signing, `CryptographicException` or `XmlException` is swallowed and `null` is returned, so you need to handle this yourself:

```csharp
using GameFrameX.Foundation.Encryption;

byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello world");
byte[] signedBytes = DsaHelper.SignData(payload, privateKey);     // Returns null on failure
bool valid = DsaHelper.VerifyData(payload, signedBytes, publicKey); // Returns false on failure
```

Source: [DsaHelper.cs#L153-L176](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L153-L176), [DsaHelper.cs#L246-L270](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L246-L270)

### 5. Reuse a `DsaHelper` Instance (Optional)

If you need to sign/verify repeatedly within the same process, it is recommended to create a `DsaHelper` instance with `using` to hold the public or private key, avoiding the overhead of `FromXmlString` on each call. Instance methods go through `_dsa.SignData` / `_dsa.VerifyData`, and exceptions propagate directly:

```csharp
using GameFrameX.Foundation.Encryption;

using (var signer = new DsaHelper(privateKey))
{
    string signature = signer.SignData("hello world"); // Base64
}

using (var verifier = new DsaHelper(publicKey))
{
    bool ok = verifier.VerifyData("hello world", signature);
}
```

The constructor supports two overloads: passing in a `DSA` instance or an XML key string; passing null / an empty string throws `ArgumentNullException` / `ArgumentException` respectively, and invalid XML throws `CryptographicException`.

## Common Variants

- **Sign with an instance but verify with the static method (cross-process transmission scenario)**: The sender uses `new DsaHelper(privateKey).SignData(originalText)` to obtain a Base64 signature that is sent along with the message, and the receiver verifies it with `DsaHelper.VerifyData(originalText, signature, publicKey)`.
- **Signing raw byte streams**: When the data is already in byte form (e.g., an already-serialized protobuf), call the `byte[]` overload directly, skipping UTF-8 / Base64 encoding and decoding.
- **Keys from a configuration file**: Store the XML string output by `Make()` in your configuration center, read it at startup, and feed it directly to the constructor or the static methods.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `SignData(string, string)` throws `CryptographicException: Invalid DSA private key.` | The private key string is not valid DSA XML, or a public key was mistakenly passed in as the private key | Confirm you are passing in `Make()["privatekey"]`; regenerate if the XML is corrupted |
| `SignData(byte[], string)` returns `null` | The private key format is invalid (`CryptographicException` or `XmlException` is swallowed internally) | Check the key XML; switching to the string overload gives you a clear exception message |
| `VerifyData` always returns `false` | Any one of the public key/original text/signature does not match (encoding, truncation, different key pairs used) | Ensure the original text is consistently UTF-8 encoded, the signature has not been Base64-encoded twice, and both signing and verifying parties use a matching key pair |
| `new DsaHelper(null)` throws `ArgumentNullException` | A null `DSA` instance or key string was passed in | Validate inputs before constructing; XML keys should be checked with `ArgumentException.ThrowIfNullOrEmpty` before being passed in |
| Specifying a 2048-bit key fails on macOS | The platform's DSA implementation has limited support for non-default key sizes | Just use the default-size key pair generated by `DsaHelper.Make()` |

## Background (Optional)

`DsaHelper` internally uses `DSA.Create()` uniformly in place of the deprecated `DSACryptoServiceProvider`, and explicitly specifies `HashAlgorithmName.SHA256` as the signing digest, avoiding the weakness of DSA's default SHA-1; the class implements `IDisposable`, so when holding an instance long-term, be sure to use `using` to release the underlying unmanaged resources. DSA is only for signing and verification and cannot be used for encryption/decryption.
