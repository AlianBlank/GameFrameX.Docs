# Adding an HTTP Interface (Bag / Mail / Player, etc.)

This page shows you how to add a new HTTP interface in the `GameFrameX.Hotfix` assembly to expose business capabilities such as Bag, Mail, and Player externally. Once done, the framework automatically registers the interface with the built-in HTTP service, and you can invoke it directly via URL.

## Prerequisites

- You are familiar with the `GameFrameX.Hotfix` project structure in the solution and know that business code lives in `GameFrameX.Hotfix/Logic/Http/<Module>/`.
- You have already defined the request/response types deriving from `HttpMessageRequestBase` / `HttpMessageResponseBase` in the protocol project (`GameFrameX.Proto`), as well as the `ErrorCode` enum.
- You understand the framework's HTTP startup entry point: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L40-L52) automatically scans all classes inheriting from `BaseHttpHandler` via `HotfixManager.GetListHttpHandler()`.

## Steps

1. **Create the Handler class**: add a new `sealed class` under `GameFrameX.Hotfix/Logic/Http/<Module>/` that inherits from `BaseHttpHandler`. The class must live in the `GameFrameX.Hotfix` assembly; otherwise, the architecture analyzer `GFX0003` will reject the build ([HttpHandlerAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HttpHandlerAssemblyAnalyzer.cs#L10-L20)).

2. **Apply the three attributes**: the class must be annotated with `HttpMessageMapping` (routing), `HttpMessageRequest` (request type), and `HttpMessageResponse` (response type; can be omitted but strongly recommended). The Mail series additionally requires using the strongly-typed `HttpMessageRequestBase` overload:

```csharp
namespace GameFrameX.Hotfix.Logic.Http.Mail;

[HttpMessageMapping(typeof(QueryMailCampaignHttpHandler))]
[HttpMessageRequest(typeof(QueryMailCampaignRequest))]
[HttpMessageResponse(typeof(QueryMailCampaignResponse))]
[Description("Admin 查询运营邮件 Campaign 发布状态")]
public sealed class QueryMailCampaignHttpHandler : BaseHttpHandler
{
    public override async Task<string> Action(string ip, string url, HttpMessageRequestBase requestBase)
    {
        var request = (QueryMailCampaignRequest)requestBase;
        var response = new QueryMailCampaignResponse { Code = MailCampaignErrorCode.Ok };
        // ...business logic...
        return HttpJsonResult.SuccessString(response);
    }
}
```

Source: [QueryMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/QueryMailCampaignHttpHandler.cs#L44-L70)

3. **Override the `Action` method**: choose one of two signatures depending on whether the request body needs to be deserialized:
   - Simple interfaces (`ReloadHttpHandler`, `TestHttpHandler`): take `Dictionary<string, object> parameters` and parse the query parameters yourself.
   - Strongly-typed interfaces (Mail, Bag): take `HttpMessageRequestBase requestBase`; the framework deserializes it for you.

   The return value must be a `string`, serialized uniformly via the `HttpJsonResult` utility methods (`SuccessString` / `ParamErrorString`, etc.):

```csharp
public override Task<string> Action(string ip, string url, Dictionary<string, object> parameters)
{
    if (parameters.TryGetValue("version", out var version))
    {
        await HotfixManager.LoadHotfixModule(null, version.ToString());
        return Task.FromResult(HttpJsonResult.SuccessString(null));
    }
    return Task.FromResult(HttpJsonResult.ParamErrorString());
}
```

Source: [ReloadHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/ReloadHttpHandler.cs#L40-L60)

4. **Build and start**: run the build from the repository root; the framework automatically scans all `BaseHttpHandler` subclasses and registers them with `HttpServer.Start(Setting.HttpPort, Setting.HttpsPort, HotfixManager.GetListHttpHandler(), HotfixManager.GetHttpHandler, null, Setting.HttpUrl)` ([AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L49-L51)). Once started, you can debug it using the URL annotated in the comments.

## Common Variants

- **No request / no response body** (`TestHttpHandler`): annotate only `HttpMessageMapping`; when you need to return data, simply hand-write a class inheriting from `HttpMessageResponseBase`.
- **Event dispatch required** (Bag item granting): call `EventDispatcher.Dispatch(...)` inside the Handler, asynchronously wait for `BagComponentAgent` to finish, then return the aggregated result with `HttpJsonResult.SuccessString` ([ReqPlayerSendItemHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Bag/ReqPlayerSendItemHttpHandler.cs#L45-L80)).
- **GM-style read-only interfaces** (Player online list): also use `Dictionary<string, object> parameters`; the Handler queries SessionManager internally — for a template, refer directly to `GetOnlinePlayerListHttpHandler`.
- **The four operational-mail handlers**: `PreviewMailCampaignHttpHandler` / `PublishMailCampaignHttpHandler` / `QueryMailCampaignHttpHandler` / `RevokeMailCampaignHttpHandler` demonstrate the standard pattern for multiple interfaces within the same module.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Build fails with `GFX0003` | The `BaseHttpHandler` subclass is not placed in the `GameFrameX.Hotfix` assembly | Move the Handler class under `GameFrameX.Hotfix/Logic/Http/...` |
| 404 when accessing after startup | `[HttpMessageMapping]` is missing, or the type itself was not passed into the attribute as the generic argument | Make sure the attribute argument is `typeof(YourHandler)` itself |
| Request parameters are not available | Used the `Dictionary<string, object>` signature, but the client sends a JSON body | Switch to the `HttpMessageRequestBase` overload and add `[HttpMessageRequest]` |
| Returns `null`, serialization fails | Returned an object directly instead of a string | Wrap it with `HttpJsonResult.SuccessString(response)` |
| Route is not recognized by the GM backend | `[Description]` is empty, so tools cannot categorize it | Add a semantically meaningful Chinese `Description("...")` |

## Background (Optional)

`BaseHttpHandler` is the event-based base class provided by `GameFrameX.NetWork.HTTP`; at startup, `HotfixManager.GetListHttpHandler()` reflects over all non-abstract subclasses and hands them to `HttpServer` to complete route registration. The Mail / Bag / Player modules are split into sub-namespaces by directory, making it easy for the GM backend and automated scans to categorize them by module.
