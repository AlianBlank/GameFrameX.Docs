# 实现自定义支付渠道

继承 `BasePaymentManager` 并实现其全部抽象成员,再把你的实现类完整类型名填到 `PaymentComponent` 上对应平台的序列化字段中,游戏启动时组件会自动通过反射加载并切换到你的渠道实现,业务层调用代码无需改动。

## 前置条件

- 已安装 `com.gameframex.unity.payment` 包,场景中挂有 `GameFrameX/Payment` 组件(`PaymentComponent`,它通过 `RequireComponent` 强制附带 `GameFrameXPaymentCroppingHelper`)。
- 你的实现类所在程序集需参与 Unity 编译(即能被 `Utility.Assembly.GetType` 解析到)。

## 操作步骤

### 1. 创建渠道管理器类

新建类继承 `GameFrameX.Payment.Runtime.BasePaymentManager`(它已实现 `GameFrameworkModule` 与 `IPaymentManager` 的事件定义,并预留了事件抛出方法):

```csharp
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;
    // ...
}
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L14-L34)

子类形如 `public class MyPaymentManager : BasePaymentManager`(类名与命名空间自定,后续步骤要用到完整类型名)。

需要 `override` 的抽象成员(全部来自真实源码签名):

| 成员 | 真实签名 | 说明 |
|------|----------|------|
| `Init` | `void Init(bool isDebug = false, bool isClientVerify = false)` | 初始化渠道 SDK;`isDebug` 沙盒模式,`isClientVerify` 是否做客户端验单 |
| `IsReady` | `bool IsReady()` | 渠道是否就绪 |
| `SetPredefinedProductIds` | `void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds)` | 预定义商品 ID 预加载,必须在 `Init` 之前调用 |
| `QueryPurchases` | `void QueryPurchases(PaymentProductType productType)` | 查询购买记录,结果经 `OnQueryPurchasesResult` 回调 |
| `ConsumePurchase` | `void ConsumePurchase(string purchaseToken)` | 消耗购买,结果经 `OnConsumePurchaseResult` 回调 |
| `BuyInApp` | `void BuyInApp(string productId, string orderId, string offerToken = "", string customData = "")` | 旧接口,已标 `[Obsolete]`,仍需 override |
| `BuySubs` | `void BuySubs(string productId, string orderId, string offerToken = "", string customData = "")` | 旧接口,已标 `[Obsolete]`,仍需 override |
| `Buy` | `void Buy(string productId, PaymentProductType productType, string orderId, string offerToken = "", string customData = "")` | 旧接口,已标 `[Obsolete]`,仍需 override |
| `Buy` | `void Buy(PurchaseParams purchaseParams)` | 推荐入口,购买参数可传入渠道子类 |

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L42-L112)

### 2. 在实现中抛出事件

渠道 SDK 回调后,调用基类提供的受保护方法通知业务层,不要直接访问事件字段:

```csharp
protected void RaisePurchaseSuccess(PaymentEventArgs e)
{
    OnPurchaseSuccess?.Invoke(this, e);
}

protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}

protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
{
    OnQueryPurchasesResult?.Invoke(this, e);
}

protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
{
    OnConsumePurchaseResult?.Invoke(this, e);
}
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L41-L59)

### 3. (可选)扩展渠道专属购买参数

`Buy(PurchaseParams)` 的参数是抽象基类,官方注释明确"各渠道可继承并扩展自有字段":

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

为你的渠道派生一个子类,把渠道特有参数(如渠道侧 token、渠道用户 ID)作为属性加上去;在 `MyPaymentManager.Buy(PurchaseParams)` 中向下转型读取。

### 4. 将实现类接入 PaymentComponent

`PaymentComponent` 按平台用序列化字段决定加载哪个实现类,在 Inspector 中把对应平台字段替换为你自己的完整类型名即可。框架默认值如下:

```csharp
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L24-L28)

平台映射规则(来自 `PaymentComponent.Awake` 的条件编译):

| 编译宏 | 使用的字段 | 默认实现 |
|--------|-----------|----------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `WebGLPaymentManager` |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `m_componentPCType` | `PCPaymentManager` |
| `UNITY_STANDALONE_OSX` | `m_componentMacType` | `ApplePaymentManager` |
| 其他平台 | — | `DefaultPaymentManager` |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

加载流程:组件在 `Awake` 中调用 `Utility.Assembly.GetType(componentType)` 解析类型,再由 `GameFrameworkEntry.GetModule<IPaymentManager>()` 取得实例;解析失败或模块无效时会 `Log.Fatal("Pay Manager is invalid.")`。

### 5. 验证接入

在业务层照常调用,无需感知具体渠道:

```csharp
// 订阅事件(PaymentComponent 已把事件转发到底层管理器)
paymentComponent.OnPurchaseSuccess += (sender, e) => { /* 发货 */ };
paymentComponent.Init(isDebug: true, isClientVerify: false);
paymentComponent.Buy(myChannelPurchaseParams);
```

`PaymentComponent.Init` 的签名为 `public void Init(bool isDebug = false, bool isClientVerify = true)`,内部直接转发到 `IPaymentManager.Init`。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

## 常见变体

- **只替换某个平台**:仅修改对应平台字段,其余平台保留官方渠道包,实现各平台混用。
- **测试桩渠道**:为所有平台字段填入同一个空的/模拟的 `BasePaymentManager` 子类,即可在 Editor 或不支持的平台上使用(否则非列出的平台会落到 `DefaultPaymentManager`)。
- **渠道需要购买额外参数**:为渠道实现 `PurchaseParams` 子类,业务层只依赖该子类构造参数。

## 常见错误

| 症状/现象 | 原因 | 修复 |
|-----------|------|------|
| 启动即 `Log.Fatal("Pay Manager is invalid.")` | 类型名写错、命名空间不符或类未被编译进程序集,`Utility.Assembly.GetType` 解析失败 | 核对 Inspector 中填写的是"命名空间.类名"完整形式,且脚本无编译错误 |
| `Buy` 无任何反应且无报错 | `PaymentComponent` 对空参数做了前置校验,例如 `"Product ID is null or empty."`、`"Order ID is null or empty."`、`"Purchase token is null or empty."` | 检查 `ProductId`/`OrderId`/`purchaseToken` 非空;对照 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L230) 的校验逻辑 |
| `SetPredefinedProductIds` 不生效 | 接口注释明确要求"此方法必须在 Initialize() 之前调用" | 在调用 `Init` 之前先设置预定义商品 ID |
| 编译报 `Obsolete` 警告 | 使用了 `BuyInApp`/`BuySubs`/旧 `Buy` 重载,均已标 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]` | 改为构造 `PurchaseParams` 子类并调用 `Buy(PurchaseParams)` |
| 事件从未触发 | 在渠道实现里直接给事件赋值/未调用基类 `Raise*` 方法 | 统一通过 `RaisePurchaseSuccess` 等受保护方法抛出事件 |

## 背景

框架通过"组件 + 反射"解耦渠道:`PaymentComponent` 只依赖 `IPaymentManager` 接口,运行时按平台宏选择实现类名字符串并用 `Utility.Assembly.GetType` 反射实例化,业务代码与具体渠道(官方 `GameFrameX.Payment.Google` 等渠道包同理)完全隔离。关于支付模块的整体结构,见《支付模块简介》。
