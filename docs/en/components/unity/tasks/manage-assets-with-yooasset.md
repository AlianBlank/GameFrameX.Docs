# How to Use AssetBundle with YooAsset for Asset Loading

This page guides you through asset bundling, configuration, and loading with YooAsset in the GameFrameX.Unity project: place the assets to be bundled into the corresponding group directories under `Assets/Bundles`, use `YooAssetSettings` to control the manifest file name and the default output folder, then run a build to generate the `PackageManifest` manifest and the `yoo` asset bundles, and simply load by address at runtime.

## Prerequisites

- The Unity project has YooAsset installed via the Package Manager (referenced by `YooAssetSettings.asset` via script GUID `9753568a72b014c7092614d3be8b353f`).
- The project root contains the `Assets/AssetBundleSetting/` folder with two core configuration files:
  - [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset)
  - [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml)
- Assets are placed under `Assets/Bundles/{GroupName}` by group (AOTCode / Code / UI / Config / Image / Sprites).

## Steps

### 1. Prepare the Asset Directories

YooAsset's collectors are fixed to the six groups under `Assets/Bundles` (AOTCode, Code, UI, Config, Image, Sprites). Place the assets to be included in the AssetBundle into the corresponding folders by purpose, for example:

- `Assets/Bundles/UI` — UI prefabs, atlases, fonts
- `Assets/Bundles/Config` — config tables, binary assets
- `Assets/Bundles/Sprites` / `Assets/Bundles/Image` — art textures

See the collection rules in [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L5-L22):

```xml
<Group GroupActiveRule="EnableGroup" GroupName="UI" GroupDesc="" AssetTags="">
  <Collector CollectPath="Assets/Bundles/UI" CollectGUID="4010ac95965b3164e83fa268b290dbf4"
            CollectType="MainAssetCollector" AddressRule="AddressByFileName"
            PackRule="PackDirectory" FilterRule="CollectAll" UserData="" AssetTags="" />
</Group>
```

> Each `<Collector>` means "which directory to collect → which rule generates the address → how it is bundled". The current project uniformly uses `AddressByFileName` (the file name serves as the load address) + `PackDirectory` (each directory is bundled into one package).

### 2. Verify YooAsset Global Settings

Open [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L12-L16) and check two fields:

| Field | Current Value | Meaning |
|------|--------|------|
| `ManifestFileName` | `PackageManifest` | File name of the manifest loaded at runtime |
| `DefaultYooFolderName` | `yoo` | Default output directory name for build artifacts |

If your project uses a manifest or output directory with different names, modify them here and make sure the runtime and build sides stay consistent.

### 3. Trigger the YooAsset Build

YooAsset provides a build entry under the Unity menu `YooAsset → Build` (provided by the editor script referenced by `m_Script` in `YooAssetSettings.asset`). Build artifacts are output to the `yoo` folder configured by `DefaultYooFolderName`, mainly including:

- `PackageManifest` (the manifest file, which records all package names, versions, and asset addresses)
- AssetBundle files for each group (naming follows `UniqueBundleName="True"`, see [AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3))

### 4. Load Assets by Address at Runtime

After the build completes, deploy the manifest and AssetBundles from the `yoo` directory to `StreamingAssets` (or a remote CDN). At startup, the YooAsset initialization system reads `PackageManifest`, and the business code simply loads by the addresses generated with `AddressByFileName`:

```csharp
// Pseudocode: aligned with the YooAsset public API; the actual types depend on the YooAsset version you have installed
var package = YooAssets.GetPackage("DefaultPackage");
var op = package.LoadAssetAsync<GameObject>("Assets/Bundles/UI/LoginPanel.prefab");
yield return op;
var go = op.InstantiateObject;
```

## Common Variants

- **Adding a new asset group**: Append a `<Group>` inside `<Package>` of [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml) along with the corresponding `<Collector CollectPath="Assets/Bundles/你的分组">`; YooAsset will recognize it automatically after the editor restarts.
- **Changing the bundling granularity**: Change the `<Collector>`'s `PackRule` from `PackDirectory` to `PackSeparately` (each asset in its own bundle) or `PackTogether` (the whole group bundled into one package).
- **Switching the address rule**: Change `AddressRule` to `AddressByGroupAndFileName` or a custom rule, then load with the new addresses at runtime.

## Common Errors

- **Asset not found at runtime**: First confirm that `ManifestFileName` and `DefaultYooFolderName` are consistent between the build side and runtime ([YooAssetSettings.asset L15-L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L15-L16)); then confirm the asset is actually placed under `Assets/Bundles/<GroupName>` and the group has `GroupActiveRule="EnableGroup"`.
- **Duplicate bundling or package name conflicts**: Make sure the `<Common>` node has `UniqueBundleName="True"` (see [AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3)); otherwise, directories with the same name will overwrite each other.
- **Configuration changes not taking effect**: YooAsset's collection configuration is re-parsed only after the editor restarts or the YooAsset window is reopened; after editing the XML, switch back to the main Editor window before building.

## Background (Optional)

The project adopts YooAsset as its unified asset management solution: `AssetBundleCollectorConfig.xml` describes "which assets → which address → which package", while `YooAssetSettings.asset` describes "how the manifest is named → where artifacts are placed". With the two sides decoupled, you can adjust the bundling granularity without rewriting code, and switch the runtime mode (local / CDN) without changing the asset structure.
