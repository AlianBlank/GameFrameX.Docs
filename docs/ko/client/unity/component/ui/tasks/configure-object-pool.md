# 오브젝트 풀 용량 및 회수 전략 조정 방법

UI 프레임워크는 UI 인스턴스를 `IObjectPoolManager`에 위임해 관리하며, `UIComponent`의 몇 가지 필드만으로 용량, 자동 회수/해제 간격, 만료 시간을 조정할 수 있습니다. 이 페이지의 설정을 완료하면 UI 인스턴스 오브젝트 풀이 몇 개의 UI를 캐시할 수 있는지, 얼마의 주기로 회수를 스캔하는지 제어할 수 있습니다.

## 사전 조건

- 프로젝트에 `GameFrameX.ObjectPool`가 통합되어 있어야 합니다(`UIComponent.cs` 33행 `using GameFrameX.ObjectPool;`).
- 씬에 `UIComponent`가 부착된 GameObject가 존재하고, `m_UIManager.SetObjectPoolManager(...)` 주입이 완료되어 있어야 합니다(`UIComponent.cs` 504행 `SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>())`).
- UI 컴포넌트와 오브젝트 풀 관리자의 전체적인 구성에 대해서는 《UI 모듈 초기화 방법》을 참조하십시오.

## 작업 단계

1. **Inspector에서 용량 및 전략 필드 조정**. `UIComponent`가 부착된 GameObject를 선택하면 Inspector에서 다음 직렬화 필드를 직접 확인하고 기본값을 수정할 수 있습니다:

| 필드명 | 기본값 | 의미 |
|--------|--------|------|
| `m_InstanceCapacity` | `16` | UI 인스턴스 오브젝트 풀 용량 상한 |
| `m_InstanceExpireTime` | `60`초 | 풀 내 객체가 해당 초수를 초과해 유휴 상태이면 해제 가능한 것으로 간주 |
| `m_InstanceAutoReleaseInterval` | `60`초 | 자동 스캔/해제 간격 |
| `m_RecycleInterval` | `60`초 | 회수 가능한 객체를 자동 회수하는 간격 |
| `m_EnableAutoReleaseUIForm` | `false` | 자동 회수 활성화 여부 |

필드 정의 예시:

```csharp
[SerializeField] private float m_InstanceAutoReleaseInterval = 60f;
[SerializeField] private int   m_InstanceCapacity          = 16;
[SerializeField] private float m_InstanceExpireTime        = 60f;
[SerializeField] private int   m_RecycleInterval           = 60;
[SerializeField] private bool  m_EnableAutoReleaseUIForm   = false;
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L107-L141)

2. **런타임에 속성을 통해 동적으로 조정**. `UIComponent`는 위 필드를 공용 속성으로 노출하며, 런타임에 값을 변경하면 직렬화 필드에 다시 기록됨과 동시에 `m_UIManager`에 전달됩니다:

```csharp
// 용량, 만료 시간, 자동 해제/회수 간격 조정
uiComponent.InstanceCapacity           = 32;   // 용량
uiComponent.InstanceExpireTime         = 120f; // 만료 초수
uiComponent.InstanceAutoReleaseInterval = 30f; // 자동 해제 간격
uiComponent.RecycleInterval            = 30;  // 회수 간격
uiComponent.EnableAutoReleaseUIForm    = true; // 자동 회수 활성화
```

속성 구현:

```csharp
public int   InstanceCapacity            { get => m_UIManager.InstanceCapacity;             set => m_UIManager.InstanceCapacity            = m_InstanceCapacity            = value; }
public float InstanceExpireTime          { get => m_UIManager.InstanceExpireTime;           set => m_UIManager.InstanceExpireTime          = m_InstanceExpireTime          = value; }
public float InstanceAutoReleaseInterval { get => m_UIManager.InstanceAutoReleaseInterval;  set => m_UIManager.InstanceAutoReleaseInterval = m_InstanceAutoReleaseInterval = value; }
public int   RecycleInterval             { get => m_UIManager.RecycleInterval;              set => m_UIManager.RecycleInterval             = m_RecycleInterval             = value; }
public bool  EnableAutoReleaseUIForm     { get => m_EnableAutoReleaseUIForm;                set => m_EnableAutoReleaseUIForm = value; }
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L322-L359)

3. **자동 회수 스위치 끄기(선택 사항)**. 회수를 수동으로 제어하려면 `EnableAutoReleaseUIForm`을 `false`로 설정하십시오. 그러면 타이머가 더 이상 자동 스캔을 트리거하지 않으며, `CloseUIForm`을 명시적으로 호출할 때만 인스턴스가 풀로 반환됩니다.

4. **저장 및 검증**. 씬을 다시 시작하거나 Play Mode에 다시 진입한 뒤, Inspector에서 필드 값이 적용되었는지 확인합니다. Profiler에서 `UI Form Instance Pool`의 용량을 관찰하여 `InstanceCapacity`를 초과하지 않는지 확인합니다.

## 일반적인 변형

- **단계별 튜닝**: 출시 전 에디터에서 `m_InstanceCapacity`를 높게(예: 32) 설정하여 피크 부하 테스트를 용이하게 합니다. 정식 빌드에서는 `InstanceCapacity`를 동적으로 낮춰 상주 메모리를 절감합니다.
- **자주 열고 닫는 고빈도 UI**(예: Toast, Tips): `InstanceExpireTime`을 작게(예: 10초) 설정하여 유휴 객체가 최대한 빨리 해제되도록 하고, 풀 용량을 점유하지 않도록 합니다.
- **무거운 UI**(캐릭터 패널, 상점): `m_InstanceCapacity`를 1~2로 조정하고 `InstanceExpireTime`을 크게(예: 300초) 설정하여 재사용을 위해 캐시를 유지합니다.
- **자동 회수 완전히 끄기**: `m_EnableAutoReleaseUIForm = false`로 설정하여, 비즈니스 로직이 직접 회수 시점을 결정하도록 합니다(주로 컷신 진행 중에 사용).

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 필드를 변경해도 적용되지 않음 | 런타임에 속성만 변경하고 `m_UIManager`에 기록하지 않았거나, `EnableAutoReleaseUIForm`을 활성화하지 않은 경우 | `m_EnableAutoReleaseUIForm = true`인지 확인하고, 속성(필드가 아닌)을 통해 값을 할당합니다 |
| 풀 객체가 금방 비어지고 UI가 느리게 열림 | `InstanceExpireTime` 또는 `InstanceAutoReleaseInterval`이 너무 작음 | `InstanceExpireTime`을 60초 이상으로, `InstanceAutoReleaseInterval`을 30초 이상으로 조정 |
| 메모리가 지속적으로 증가함 | `InstanceCapacity`가 너무 크고 `InstanceExpireTime`이 너무 김 | `InstanceCapacity`를 줄이고 `InstanceExpireTime`을 단축 |
| 잦은 GC | `RecycleInterval`이 너무 작아 타이머가 반복적으로 트리거됨 | `RecycleInterval`을 30~60초로 조정 |

## 배경(선택 사항)

`UIComponent`는 내부적으로 설정을 `m_UIManager`와 직렬화 필드에 동시에 전달하며, 이는 런타임 변경 사항이 Editor에서도 직렬화되어 유지되도록 하기 위함입니다. `IObjectPoolManager`가 구체적인 오브젝트 풀 전략(만료 회수, 정기 해제)을 담당하며, UI 모듈은 매개변수 전달과 스위치만 담당합니다. `m_InstancePriority` 같은 비공개 필드를 변경해도 적용되지 않습니다.
