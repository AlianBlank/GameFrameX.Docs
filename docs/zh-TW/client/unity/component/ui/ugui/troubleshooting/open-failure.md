# 介面開啟失敗時的處理方法

呼叫 `UIManager.OpenUIForm` / `OpenUIFormAsync` 後，若介面未顯示、發生例外，或只觸發了失敗回呼，請依照本頁內容快速找出根本原因並修復。

## 快速診斷

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `OpenUIFormFailureEventArgs` 回呼的錯誤訊息為 `Resources.Load failed for path: <path>` | 資源路徑不在 `BundlesDirectoryName` 之下，因而嘗試以 Resources 載入，但該路徑不存在 | 請參閱「Resources 路徑資源載入失敗」 |
| `OpenUIFormFailureEventArgs` 包含 `assetHandle.LastError` | 嘗試從包內載入，但 `LoadAssetAsync` 回傳 `Failed` 狀態 | 請參閱「包內資源載入失敗」 |
| 例外 `GameFrameworkException: Can not create UI form in UI form helper.` | `UGUIFormHelper.CreateUIForm` 回傳 `null` | 請參閱「邏輯腳本型別不一致 / 未掛載腳本」 |
| 例外 `GameFrameworkException: Open UI form info is invalid.` | `LoadAssetSuccess/FailureCallback` 中的 `openUIFormInfo` 為空 | 請參閱「控制代碼與回呼生命週期例外」 |
| 例外 `ArgumentNullException`(由 `GameFrameworkGuard.NotNull` 擲出) | 傳入的 `m_AssetManager` / `m_UIFormHelper` / `uiFormType` 為 null | 請參閱「核心參數為 null」 |
| 主控台輸出 `UI form instance type Xxx is invalid.`，但沒有例外 | Prefab 未掛載繼承 `IUIForm` 的邏輯腳本 | 請參閱「邏輯腳本型別不一致 / 未掛載腳本」 |
| 資源池重用分支中發出多次開啟請求，卻只顯示 1 個 | 符合單例開啟模式(`UseSingletonOpenMode`)，後續請求被合併 | 請參閱「單例開啟被合併」 |

## 解決步驟

### Resources 路徑資源載入失敗

`InnerLoadUIFormAsync` 在路徑不包含 `BundlesDirectoryName` 時會使用 `Resources.Load`，找不到時會組合失敗訊息並回傳：

```csharp
if (uiFormAssetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    var original = (GameObject)Resources.Load(assetPath);
    if (original == null)
    {
        return LoadAssetFailureCallback(assetPath, $"Resources.Load failed for path: {assetPath}", openUIFormInfo);
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L149-L160](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L149-L160)

解決方法：

1. 確認 `uiFormAssetPath + uiFormType.Name` 確實存在於任一 `Resources/` 目錄之下(區分大小寫)。
2. 若資源位於 AssetBundle 中，請將路徑改為包含 `BundlesDirectoryName`(預設為 `Assets/AssetBundle/`，或遊戲自訂的子目錄名稱)，讓其改走包內載入分支。
3. 註冊失敗回呼以取得具體路徑：

```csharp
m_UIManager.OpenUIFormFailureEvent += (sender, args) =>
{
    Debug.LogError($"OpenFail [{args.UIFormAssetName}] {args.ErrorMessage}");
};
```

### 包內資源載入失敗

包內分支會經過 `AssetManager.LoadAssetAsync`，狀態不是 `Succeed` 時即視為失敗：

```csharp
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(assetPath);
if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    ...
    return LoadAssetSuccessCallback(assetPath, gameObject, assetHandle.Progress, openUIFormInfo);
}
return LoadAssetFailureCallback(assetPath, assetHandle.LastError, openUIFormInfo);
```

Source: [Runtime/UIManager.Open.cs#L163-L174](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L163-L174)

解決方法：

1. 檢查 `assetHandle.LastError`。常見原因：AssetBundle 清單未包含該介面、打包路徑與載入路徑不一致、在相依套件載入完成前就呼叫了 Open。
2. 確認 `m_AssetManager` 已完成初始化(請參閱「核心參數為 null」)。
3. 在啟動流程中，待 AssetBundle 清單解析完成後再開始開啟請求。

### 邏輯腳本型別不一致 / 未掛載腳本

`UGUIFormHelper.CreateUIForm` 在執行個體不是 `GameObject`、或未掛載 `IUIForm` 腳本時會回傳 `null`，之後 `InternalOpenUIForm` 會擲出 `Can not create UI form in UI form helper.`：

```csharp
var componentType = uiGameObject.GetOrAddComponent(uiFormType);
if (!(componentType is IUIForm uiForm))
{
    Log.Error($"UI form instance type {uiFormType} is invalid.");
    return null;
}
```

Source: [Runtime/UGUIFormHelper.cs#L91-L105](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L91-L105)

解決方法：

1. 開啟失敗時的 Preload 行為：Preload 仍會建立介面並呼叫 OnAwake，因此必須確保邏輯腳本不依賴尚未初始化的資料。
2. 確認 Preload 的資源路徑與開啟路徑完全相同。否則兩個池會指向不同的 Prefab。

### 控制代碼與回呼生命週期例外

若 `LoadAssetSuccessCallback` / `LoadAssetFailureCallback` 收到的 `openUIFormInfo` 為空，會擲出 `Open UI form info is invalid.`。這項資訊是在 `InnerOpenUIFormAsync` 中以 `UIFormLoadingObject.Create` 建立的：

```csharp
UIFormLoadingObject uiFormLoadingObject = UIFormLoadingObject.Create(uiFormAssetPath, uiFormAssetName, uiFormType, uiForm);
m_LoadingUIForms.Add(uiFormLoadingObject);
```

Source: [Runtime/UIManager.Open.cs#L113-L115](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L113-L115)

這類例外通常發生在自訂的 `UIFormHelper` 未依照規範建構 `OpenUIFormInfo` 時。若非必要，請勿覆寫資源載入回呼。

### 核心參數為 null

`InnerOpenUIFormAsync` 的進入點會對核心欄位執行 `GameFrameworkGuard.NotNull` 驗證，只要有任一項為空，便會立即擲出 `ArgumentNullException`：

```csharp
GameFrameworkGuard.NotNull(m_AssetManager, nameof(m_AssetManager));
GameFrameworkGuard.NotNull(m_UIFormHelper, nameof(m_UIFormHelper));
GameFrameworkGuard.NotNull(uiFormType, nameof(uiFormType));
```

Source: [Runtime/UIManager.Open.cs#L72-L74](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L72-L74)

解決方法：

1. 在呼叫 `OpenUIForm` 之前，確認 `UIManager` 已完成初始化(框架的 `GameFramework` 啟動流程)。
2. 呼叫端傳入的 `Type` 不可為 null，且必須實作 `IUIForm`。
3. 若更換了 `UIFormHelper`，請確認已將其註冊至 `UIManager`。

## 驗證

修復後，請以最小的使用案例進行驗證：

```csharp
var form = await m_UIManager.OpenUIFormAsync<MyUIFomLogic>("Assets/AssetBundle/UI/");
if (form == null)
{
    Debug.LogError("Open failed, see OpenUIFormFailureEvent for details.");
}
```

確認事項：

- `OpenUIFormSuccessEvent` 被觸發，且回呼中 `duration > 0`。
- 不再發生失敗事件，且目標介面已顯示於 UI 攝影機上。
- `IsLoadingUIForm(assetName)` 回傳 `false`，且 `GetUIForm(assetName)` 回傳非 null 的執行個體。## 單例開啟被合併

若介面類別帶有 `[OptionUIGroup]`，或框架判定為單例開啟模式(`UseSingletonOpenMode`)，則以相同資源名稱重複開啟時，會回傳既有的執行個體並觸發 `RefocusUIForm`，而不會建立新執行個體：

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L79-L111](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L79-L111)

執行個體池重用(`m_InstancePool.Spawn`)只會在此單例區塊內執行。自 2.6.2 起，多執行個體介面不再從池中取出執行個體重用，而是每次都透過下方的載入流程建立新執行個體(修正了原先因池為 MultiSpawn 池，多執行個體開啟時會取回使用中的同一 `GameObject`，導致多個介面共用同一個物件而互相覆寫的問題)：

```csharp
// 執行個體池重用僅用於單一執行個體模式。執行個體池是 MultiSpawn 池（允許同一物件被並行取出），
// 多執行個體介面開啟時會取回使用中的同一 GameObject，GetOrAddComponent 又取回同一邏輯元件，
// 造成多個介面共用一個物件互相覆蓋；多執行個體介面每次走下方載入流程新建執行個體，
// 關閉時照常 Unspawn/Release，不依賴池重用。
var uiFormInstanceObject = m_InstancePool.Spawn(assetPath);
if (uiFormInstanceObject != null)
{
    // 池重用時也會配置新的請求序列號，確保每次開啟請求皆可觀測。
    int serialId = ++m_Serial;
    return InternalOpenUIForm(serialId, uiFormAssetPath, uiFormAssetName, uiFormType, uiFormInstanceObject.Target, pauseCoveredUIForm, false, 0f, userData, isFullScreen);
}
```

Source: [Runtime/UIManager.Open.cs#L100-L110](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L100-L110)

解決方法：

1. 若期望每次都建立新執行個體，請停用該模式的單例標記(或由業務層自行管理執行個體的生命週期)。
2. 並發的開啟請求會合併為同一個載入 Task，等待相同的載入結果：

```csharp
foreach (var loadingUIForm in m_LoadingUIForms)
{
    if (loadingUIForm.UIFormAssetPath == uiFormAssetPath &&
        loadingUIForm.UIFormAssetName == uiFormAssetName &&
        loadingUIForm.UIFormType == uiFormType)
    {
        return await loadingUIForm.Task;
    }
}
```

Source: [Runtime/UIManager.Open.cs#L90-L98](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L90-L98)

並發的第二個開啟不會觸發新的失敗回呼，只會觸發第一個請求的失敗/成功事件。
