# 載入或卸載事件未觸發時的處理方式

當您呼叫 `SceneComponent.LoadScene` / `UnloadScene` 後，發現 `LoadSceneSuccess`、`LoadSceneFailure`、`UnloadSceneSuccess`、`UnloadSceneFailure` 或 `LoadSceneUpdate` 任何一個事件都沒有收到時，請逐一按照本頁的疑難排解步驟進行排查。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| 整個載入/卸載過程中皆未收到任何事件回呼 | `EventComponent` 未註冊到 `GameEntry`，或場景元件啟動時印出 `Event component is invalid.` | 確認 `EventComponent` 已掛載到 `GameEntry`，且在 `SceneComponent` 之前完成初始化 |
| 僅 `LoadSceneUpdate` 未收到 | `SceneComponent` 中的 `Enable Load Scene Update Event` 選項未勾選 | 在 Inspector 中勾選 `Enable Load Scene Update Event`，或在 Prefab 中將 `m_EnableLoadSceneUpdateEvent` 重新設定為 `true` |
| 收到 `LoadSceneFailure` 但 `UserData` 為 null | 載入失敗發生在取得 `YooAsset` 控制代碼之前 | 檢查 `sceneAssetName` 是否以 `Assets/` 開頭，並存在於建置清單中。詳見下文 |
| 有收到事件，但業務端的處理常式未執行 | `Subscribe` 中的 `EventId` 不正確，或訂閱發生在 `Awake` 之前 | 使用 `typeof(...).FullName` 作為 `EventId`，並確認訂閱時機在 `GameEntry` 啟動之後 |
| 重複載入同一場景時，第二次未收到 `LoadSceneSuccess` | 第一次成功後，場景已加入 `LoadedScenes`，因此再次呼叫 `LoadScene` 會走 YooAsset 的同步路徑 | 請參閱「常見變體」一節 |

## 修復步驟

### 1. 確認 SceneComponent 已掛載並啟動

`SceneComponent` 會在 `Awake` 中檢查場景管理器與事件元件。若缺少任一者，會記錄 `Fatal` 並直接返回，之後將不會派發任何事件：

```csharp
// Runtime/Scene/SceneComponent.cs
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IGameSceneManager);
    base.Awake();
    _gameSceneManager = GameFrameworkEntry.GetModule<IGameSceneManager>();
    if (_gameSceneManager == null)
    {
        Log.Fatal("Scene manager is invalid.");
        return;
    }
    // ... 訂閱事件
    m_GameFrameworkScene = UnityEngine.SceneManagement.SceneManager.GetSceneAt(GameEntry.GameFrameworkSceneId);
    if (!m_GameFrameworkScene.IsValid())
    {
        Log.Fatal("Game Framework scene is invalid.");
        return;
    }
}
```

來源：[SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L79-L113)

操作步驟：
1. 選取入口場景的 GameFramework 根節點，確認存在 `Scene Component`（選單路徑 `GameFrameX/Scene`）。
2. 執行後檢查 Console，確認是否出現如 `Scene manager is invalid.` 或 `Game Framework scene is invalid.` 之類的致命（Fatal）日誌。
3. 若出現任何一條，表示 `SceneComponent` 未能完成訂閱，必須先解決此問題。

### 2. 確認 EventComponent 已掛載

`Start` 階段會再次驗證 `EventComponent`。若缺少該元件，會記錄 `Fatal` 並直接返回。此時事件訂閱已掛鉤於 `_gameSceneManager`，但將不再被 `Fire` 到上層：

```csharp
// Runtime/Scene/SceneComponent.cs
private void Start()
{
    BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
    if (baseComponent == null)
    {
        Log.Fatal("Base component is invalid.");
        return;
    }

    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event component is invalid.");
        return;
    }
    // ...
}
```

來源：[SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L115-L139)

操作方式：在 GameFramework 根節點上新增 `Event Component`，並確保其優先順序早於 `SceneComponent`（`SceneComponent` 的 `GameFrameXAutoComponent` 優先順序為 `-4000`，詳見 [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L48)）。

### 3. 在業務端正確訂閱事件

事件透過 `EventComponent.Fire` 進行派發。訂閱者必須使用對應 `EventArgs` 型別的 `EventId`（即 `typeof(...).FullName`）：

```csharp
// Runtime/EventArgs/LoadSceneSuccessEventArgs.cs
public sealed class LoadSceneSuccessEventArgs : GameEventArgs { /* ... */ }

// Runtime/EventArgs/LoadSceneFailureEventArgs.cs
public static readonly string EventId = typeof(LoadSceneFailureEventArgs).FullName;
```

來源：[LoadSceneSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneSuccessEventArgs.cs#L40-L41)、[LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs#L46)

訂閱範例（使用 `GameFrameX.Event.Runtime.EventComponent` 的標準 API）：

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    LoadSceneSuccessEventArgs.EventId,
    OnLoadSceneSuccess);

private void OnLoadSceneSuccess(object sender, GameEventArgs e)
{
    var args = (LoadSceneSuccessEventArgs)e;
    // args.SceneAssetName / args.Duration / args.UserData
}
```

常見陷阱：

| 錯誤寫法 | 結果 |
|----------|------|
| 以字串字面值方式填寫 `LoadSceneSuccessEventArgs.EventId`，但有拼字錯誤或缺少空格 | 永遠收不到事件 |
| 使用 `Subscribe<LoadSceneSuccessEventArgs>(handler)` 多載，但該型別未公開 `EventId` | 編譯時期錯誤，或執行時期靜默失敗 |
| 訂閱寫在靜態建構函式或網域初始化中，發生在事件觸發之後 | 會錯過該回呼 |

### 4. 檢查 LoadSceneUpdate 是否被開關停用

`SceneComponent` 預設會訂閱 `LoadSceneUpdate`，但對應欄位可在 Inspector 中關閉：

```csharp
// Runtime/Scene/SceneComponent.cs
[SerializeField] private bool m_EnableLoadSceneUpdateEvent = true;
if (m_EnableLoadSceneUpdateEvent)
{
    _gameSceneManager.LoadSceneUpdate += OnLoadGameSceneUpdate;
}
```

來源：[SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L63-L97)

若僅缺少 `LoadSceneUpdate`，請選取場景中的 `Scene Component` 並勾選 `Enable Load Scene Update Event`。

### 5. 檢查 SceneAssetName 是否有效

`HasScene` 會拒絕不以 `Assets/` 開頭的名稱：

```csharp
// Runtime/Scene/SceneComponent.cs
public bool HasScene(string sceneAssetName)
{
    if (string.IsNullOrEmpty(sceneAssetName))
    {
        Log.Error("Scene asset name is invalid.");
        return false;
    }
    if (!sceneAssetName.StartsWith("Assets/", StringComparison.Ordinal) ||
        // ...
        )
    {
        Log.Error("Scene asset name '{0}' is invalid.", sceneAssetName);
        return false;
    }
    // ...
}
```

來源：[SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L271-L295)

傳入錯誤的名稱會觸發 `LoadSceneFailure`，錯誤訊息通常為 `Scene asset name 'xxx' is invalid.`。

### 6. 檢查底層 YooAsset 控制代碼的狀態

`GameSceneManager` 透過 `YooAsset.SceneHandle` 派發成功/失敗。若控制代碼建立失敗，場景將不會進入 `m_LoadingSceneAssetNames`，自然也不會觸發後續事件：

```csharp
// Runtime/Scene/Scene/GameSceneManager.cs
private readonly Dictionary<string, YooAsset.SceneHandle> m_LoadedSceneAssetNames;
private readonly Dictionary<string, SceneHandleData> m_LoadingSceneAssetNames;
private readonly Dictionary<string, YooAsset.SceneHandle> m_UnloadingSceneAssetNames;
```

來源：[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L59-L61)

在錯誤發生的情境下呼叫 `SceneComponent.GetLoadingSceneAssetNames()` 與 `GetUnloadingSceneAssetNames()`。若回傳為空，表示從未進入非同步佇列，事件不會被觸發——請回到步驟 5 檢查資源名稱。

## 驗證

完成上述步驟後，請依照下表進行確認：

| 驗證項目 | 預期結果 |
|--------|------|
| Console 中沒有如 `Scene manager is invalid.` 的 Fatal 日誌 | 是 |
| 業務端的 `LoadSceneSuccessEventArgs` 回呼被命中，且 `SceneAssetName` 與請求值一致 | 是 |
| `LoadSceneFailure` 僅在故意傳入錯誤名稱時觸發，並附帶 `ErrorMessage` | 是 |
| `LoadSceneUpdate` 進度從 0 持續觸發至 1，最終命中 `LoadSceneSuccess` | 是 |
| 主動呼叫 `UnloadScene` 後命中 `UnloadSceneSuccess` | 是 |

若僅缺少個別事件，請回到「快速診斷」表格定位具體的行。若所有事件皆未收到且沒有 Fatal 日誌，幾乎可以確認是 `EventComponent` 未掛載或訂閱時機過早。
