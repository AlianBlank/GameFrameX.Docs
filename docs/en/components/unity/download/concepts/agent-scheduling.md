# Multi-Agent Scheduling and Task Lifecycle

The download manager maintains multiple download agents (`DownloadAgent`) simultaneously via `TaskPool<DownloadTask>`. All submitted tasks are queued by priority, claimed by idle agents, and advanced in a unified polling loop. This page explains how agents are created and scheduled, and the various states and events a task goes through during its lifecycle.

## Quick Start

1. When starting the component, register several download agent helpers via `DownloadComponent` (each helper corresponds to an independent agent, enabling parallel downloads):

```csharp
// AddDownloadAgentHelper will new DownloadAgent(helper) and m_TaskPool.AddAgent(agent)
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
```

Source: [DownloadManager.cs#L204-L213](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L204-L213)

2. Call `AddDownload(...)` to submit a task. The task enters `TaskPool`'s waiting queue, waiting to be claimed by an idle agent:

```csharp
int serialId = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/pkg.zip",
    downloadUri:  "https://example.com/pkg.zip",
    tag:         "asset",
    priority:    0);
```

Source: [DownloadManager.cs#L269-L296](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L269-L296)

3. The framework module calls `DownloadManager.Update` every frame, which internally forwards the update to the task pool. After an agent claims a task, it calls `IDownloadAgentHelper.Download` to start the transfer, and fires the `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` events during the process.

```csharp

protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_TaskPool.Update(elapseSeconds, realElapseSeconds);
    m_DownloadCounter.Update(elapseSeconds, realElapseSeconds);
}
```

## Agent Scheduling

The download manager creates an independent `DownloadAgent` for each helper in `AddDownloadAgentHelper`, and registers it via `TaskPool<DownloadTask>.AddAgent`. `TaskPool` is responsible for maintaining the agent collection and the waiting queue, and only assigns tasks to agents in an idle state.

Key statistics of the agent collection and queue states are exposed through `DownloadManager` and can be read directly in a UI or debug panel:

| Name | Source Property | Meaning |
|------|----------|------|
| Total agents | `TotalAgentCount` | Total number of registered download agents |
| Free agents | `FreeAgentCount` | Number of agents currently not carrying a task |
| Working agents | `WorkingAgentCount` | Number of agents currently downloading |
| Waiting tasks | `WaitingTaskCount` | Number of tasks enqueued but not yet claimed |
| Current speed | `CurrentSpeed` | Instantaneous speed calculated by `DownloadCounter` (MB/s) |
| Paused flag | `Paused` | Pausing stops agents from claiming new tasks |

Source: [DownloadManager.cs#L86-L142](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L86-L142)

Overview of the scheduling flow:

1. Register agents: `AddDownloadAgentHelper` → `new DownloadAgent(helper)` → `m_TaskPool.AddAgent(agent)`.
2. Submit tasks: `AddDownload` → construct via `DownloadTask.Create` → written into the task pool's waiting queue.
3. Claim tasks: each frame, `TaskPool.Update` hands the highest-priority task in the waiting queue to an idle agent, which then calls `IDownloadAgentHelper.Download(downloadUri, userData)`.
4. Release agents: after an agent completes (successfully or not), it is marked as idle, and the task pool can continue dispatching other waiting tasks in the next round.

> For the internal priority comparison and waiting queue implementation of `TaskPool<T>`, see the GameFrameX runtime source code; this component only provides the `DownloadTask` and `DownloadAgent` implementations.

## Task Lifecycle

Every download task is a `DownloadManager.DownloadTask`, inherits from `TaskBase`, is created via `ReferencePool.Acquire<DownloadTask>()`, and is returned to the object pool in `Clear()`. Tasks have the following states:

| Status Enum Value | Value | Description |
|------------|------|------|
| `DownloadTaskStatus.Todo` | 0 | Enqueued, waiting to be claimed by an agent |
| `DownloadTaskStatus.Doing` | 1 | Claimed by an agent, currently transferring |
| `DownloadTaskStatus.Done` | 2 | Download complete, file written to disk |
| `DownloadTaskStatus.Error` | 3 | Download failed (timeout, network error, etc.) |

Source: [DownloadManager.DownloadTaskStatus.cs#L39-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTaskStatus.cs#L39-L60)

Key fields carried by `DownloadTask`:

| Field | Type | Meaning |
|------|------|------|
| `SerialId` | `int` | Auto-incremented via `s_Serial`; each `Create` performs `++s_Serial` |
| `DownloadPath` | `string` | Storage path of the file after the download completes |
| `DownloadUri` | `string` | Original download URL |
| `FlushSize` | `int` | Threshold size for flushing the buffer to disk (overridden by manager defaults) |
| `Timeout` | `float` | Download timeout in seconds (overridden by manager defaults) |
| `Priority` | `int` | Task priority; higher values are dispatched first |
| `Tag` | `string` | Task tag; enables batch querying of `TaskInfo` by tag |
| `UserData` | `object` | Custom data passed through to `IDownloadAgentHelper.Download` |

### Lifecycle Stages

1. **Enqueue**: After the `AddDownload` overloads funnel into the full-parameter version, the task is created by `DownloadTask.Create(downloadPath, downloadUri, tag, priority, flushSize, timeout, userData)` with an initial state of `Todo`, and immediately enters `TaskPool`'s waiting queue.
2. **Dispatch**: `TaskPool.Update` hands the task to an idle `DownloadAgent`. In the `OnDownloadAgentStart` callback, the agent switches the task state to `Doing` and opens a local `FileStream`.
3. **In Progress**: The agent continuously receives `DownloadAgentHelperUpdateBytesEventArgs` / `UpdateLength` from the `IDownloadAgentHelper`, accumulating `m_DownloadedLength` and `m_SavedLength`. When `m_WaitFlushSize` reaches `FlushSize`, data is flushed to disk, while `m_WaitTime` is updated periodically for timeout determination.
4. **Complete / Fail**: On success, `DownloadAgentSuccess` is fired; on failure (including timeout), `DownloadAgentFailure` is fired. The agent closes the stream and cleans up state, the task state is set to `Done` or `Error`, and the task awaits automatic return to the object pool by `TaskPool`.
5. **Resource Recycling**: `Clear()` resets task fields to `Todo`/empty values, then `ReferencePool.Release` puts it back into the pool, awaiting reuse by the next `Create`.

## Common Issues

| Symptom | Cause | Fix |
|------|------|------|
| All tasks remain at `WaitingTaskCount > 0`, `WorkingAgentCount = 0` | `AddDownloadAgentHelper` was never called; the task pool has no agents | Add at least one `IDownloadAgentHelper` (UnityWebRequest / WWW implementation) as needed during component startup |
| `Download agent helper is invalid.` is thrown immediately on component startup | `null` was passed in, or the object was released prematurely | Ensure a valid instance is passed in and that it is not `Dispose`d prematurely by external code |
| Tasks stay in `Doing` for a long time and are then marked as failed | `Timeout` is set too short, or `FlushSize` is too large on a weak network, causing buffered data to remain unflushed | Adjust via `DownloadManager.Timeout` / `DownloadManager.FlushSize`, or use the `AddDownload` overload to override per task |
| Multiple helpers registered but concurrency remains 1 | The same helper instance was registered multiple times, causing agents to share the underlying connection | Call `AddDownloadAgentHelper` only once per `UnityWebRequestDownloadAgentHelper`/`WWWDownloadAgentHelper` instance |

## Background (Optional)

The download manager is a `GameFrameworkModule` (`Priority = 5`). In `Update`, it fully delegates scheduling to `TaskPool<DownloadTask>`; this class is only responsible for:

- Maintaining a list of download agents (injected via `AddDownloadAgentHelper`).
- Converting each `AddDownload` into `DownloadTask.Create(...)` and handing it to the task pool.
- Listening to the agent's four events (`Start/Update/Success/Failure`) and exposing them externally as unified event callbacks.
- Using `DownloadCounter` to convert byte increments from all agents into a unified instantaneous download speed.

The task object (`DownloadTask`) itself is managed by `ReferencePool`, and the agent (`DownloadAgent`) implements `ITaskAgent<DownloadTask>` and `IDisposable`. These two abstractions are its contract for interfacing with `TaskPool`, and are also what keeps it consistent with the GameFrameX runtime task scheduling subsystem.
