# 如何创建并启动一个 FSM

通过 `FsmComponent` 创建持有指定 Owner 的有限状态机,传入状态实例并调用 `Start<TState>()` 让其开始轮询,即可在游戏中驱动实体行为。本页给出从定义状态到启动运行的完整最小路径。

## 前置条件

- 已安装 `com.gameframex.unity.fsm` 包。
- 场景中已存在挂载 `FsmComponent` 的 GameObject(组件带 `[GameFrameXAutoComponent(-6000)]`,框架启动时会自动注册)。
- 已定义至少一个继承 `FsmState<T>` 的状态类(关于状态定义,见《如何定义 FsmState》)。

## 操作步骤

1. 获取 `FsmComponent` 实例。

   ```csharp
   var fsmComponent = GameEntry.GetComponent<FsmComponent>();
   ```

2. 调用 `CreateFsm<T>` 创建状态机,传入 Owner 与全部初始状态实例。

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
   ```

   `FsmComponent.CreateFsm<T>(T owner, params FsmState<T>[] states)` 的源码定义在 [FsmComponent.cs#L197-L208](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L197-L208),内部转发到 `IFsmManager.CreateFsm`。
   同一 Owner 也可以用带 `name` 的重载创建多个并存实例:

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm<Player>("Combat", player, new IdleState(), new AttackState());
   ```

3. 调用 `Start<TState>()` 让 FSM 进入首个状态。

   ```csharp
   fsm.Start<IdleState>();
   ```

   `Start<TState>()` 会触发目标状态的 `OnEnter`,并从下一帧开始每帧调用 `OnUpdate`。
   `Start` 接口定义见 [IFsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsm.cs)。

4. 在任意状态内部通过 `ChangeState<TState>(fsm)` 切换状态。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

## 常见变体

| 场景 | 调用方式 |
|------|----------|
| 同一 Owner 上需要多个独立 FSM | 使用 `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` 并通过 `name` 区分 |
| 运行期追加新状态 | `fsm.AddState(new JumpState())` |
| 运行期移除状态(不能是当前状态) | `fsm.RemoveState<IdleState>()` |
| 退出当前状态、清空数据后重启 | `fsm.Reset(); fsm.Start<IdleState>();` |
| 通过 `GameApp` 快捷访问(需 `com.gameframex.unity.entry`) | `IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());` |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `Log.Fatal("FSM manager is invalid.")` | `Awake` 阶段未取到 `IFsmManager` 实现,通常是框架初始化顺序问题 | 确保 `FsmComponent` 挂载在框架根 GameObject 上,且 GameFrameX 框架组件先于业务脚本初始化 |
| `Start<TState>()` 报"状态不存在" | `CreateFsm` 时未传入该状态,或随后调用了 `RemoveState` | 在 `CreateFsm` 的 `params FsmState<T>[] states` 中补齐,或在 `Start` 前调用 `AddState` |
| FSM 没有被驱动 / `OnUpdate` 不触发 | `FsmComponent` 的 `FixedUpdate` 依赖 `m_FsmManager` 非空;若组件未挂载或被禁用,Update 不会执行 | 确认场景中存在激活的 `FsmComponent` |
| `CreateFsm` 对同一 Owner 返回已存在的实例 | 同 Owner + 同 name 时复用旧 FSM | 用不同的 `name` 区分,或先 `DestroyFsm` 再创建 |

## 验证

- 在 `IdleState.OnEnter` 中打日志,运行场景应立即看到一次输出。
- 在 `IdleState.OnUpdate` 中打日志,运行场景应每帧看到输出,说明 `FsmComponent.FixedUpdate` 在驱动轮询。
- 调用 `fsm.IsRunning` 应为 `true`;调用 `fsm.CurrentState` 应返回刚 `Start` 的状态类型。
