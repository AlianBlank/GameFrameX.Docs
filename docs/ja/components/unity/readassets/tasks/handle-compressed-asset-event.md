# Android 圧縮 StreamingAsset イベントの処理

APK ビルド(特に App Bundle)において `StreamingAssets` ディレクトリ内のファイルが APK 内で圧縮保存されている場合、Unity はファイルオフセットから直接読み取ることができません。本フレームワークは初期化時に APK の Central Directory をスキャンし、そのようなファイルを検出すると `CompressedStreamingAssetFound` イベントを発火し、ランタイムでこれを傍受して対応できるようにします。

## 前提条件

- イベントの実体が定義されるのは `UNITY_ANDROID` または `UNITY_EDITOR`(`InitializeWithExternalApk` を使用時)プラットフォームのみです。その他のプラットフォームでは `add`/`remove` は空の操作となります。
- プロジェクトが `BlankReadAssets.Initialize()` または `BlankReadAssets.Root` 経由で初期化済みであること(任意の API に初めてアクセスした際に自動的にトリガーされます)。

## 操作手順

1. **イベントを購読する**。イベントシグネチャは `Func<string, bool>` で、APK 内のファイルフルネーム(例:`"assets/config/data.json"`)を受け取り、`true` を返すと「処理済み」とみなされ、フレームワークは警告を出さなくなります:

```csharp
using GameFrameX.ReadAssets.Runtime;

BlankReadAssets.CompressedStreamingAssetFound += fileName =>
{
    // fileName は "assets/xxx.bin" のような形式
    if (fileName.EndsWith(".json"))
    {
        // フォールバック処理:リモートからダウンロード / persistentDataPath からコピー / 内蔵のデフォルト値 など
        Debug.Log($"圧縮された StreamingAsset を処理: {fileName}");
        return true;
    }
    return false;
};
```

2. **初期化より前に購読する**。イベントは `ApkImpl.Initialize` → `GetStreamingAssetsInfoFromJar` が APK をスキャンする際に発火するため、初回読み取りより前に購読を完了させる必要があります。`RuntimeInitializeOnLoadMethod` に配置することを推奨します:

```csharp
using UnityEngine;
using GameFrameX.ReadAssets.Runtime;

public static class Bootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSplashScreen)]
    private static void Init()
    {
        BlankReadAssets.CompressedStreamingAssetFound += OnCompressed;
    }

    private static bool OnCompressed(string fileName)
    {
        // true を返すと「処理済み」を意味し、フレームワークは静かにする
        return false;
    }
}
```

3. **(オプション)Editor で検証する**。`InitializeWithExternalApk` 経由で実際の APK をロードすると、エディタ上でも同じイベントを発火させることができるため、連携デバッグに便利です:

```csharp
BlankReadAssets.InitializeWithExternalApk(@"C:\builds\game.apk");
```

イベントは `InitializeWithExternalApk` と同一の `ApkImpl` スキャンロジックを共有しています([BlankReadAssets.ApkImpl.cs#L294-L354](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L294-L354))。

## よくあるバリエーション

- **イベントは購読せず、単に無視したい**。部分メソッド `AndroidIsCompressedFileStreamingAsset` を実装し、`false` を返すことでフレームワークがそのファイルを直接無視するようにし、イベントのディスパッチに入らず、ログも出力されません:

```csharp
using GameFrameX.ReadAssets.Runtime;
using UnityEngine;

public partial class BlankReadAssets
{
    static partial void AndroidIsCompressedFileStreamingAsset(string fileName, ref bool isStreamingAsset)
    {
        // 例えば特定のリソースを除外する
        if (fileName.StartsWith("assets/internal/")) isStreamingAsset = false;
    }
}
```

部分メソッドの宣言箇所は [BlankReadAssets.ApkImpl.cs#L334](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L334) を参照してください。

- **App Bundle シナリオ**。プロジェクト自体が App Bundle(`*.aab`)であり、Google Play にアップロード後に複数の `.apk` スプリットに展開される場合、`dataPath` が `base.apk` でないときにフレームワークは同じディレクトリにある `base.apk` に自動的にフォールバックして再スキャンします([BlankReadAssets.ApkImpl.cs#L43-L51](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L43-L51))。この分岐でも同じイベントが発火するため、購読側のコードに変更は必要ありません。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| `Debug.LogAssertionFormat` が `BlankReadAssets: file ... is where Streaming Assets are put, but is compressed.` を繰り返し出力する | 誰もイベントを購読しておらず、部分メソッドによるフィルタも実装されていない | `CompressedStreamingAssetFound` を購読するか、`AndroidIsCompressedFileStreamingAsset` を実装する |
| iOS / Standalone で `BlankReadAssets.CompressedStreamingAssetFound += ...` を記述するとコンパイルエラーになる | そのイベントは `UNITY_EDITOR || UNITY_ANDROID` でのみ実シグネチャが存在する | 購読コードを `#if UNITY_ANDROID || UNITY_EDITOR` で囲む。または無視する(他プラットフォームでは no-op) |
| 購読タイミングが遅すぎて、起動直後に一度だけ発火してしまう | イベントは `Initialize` の内部で同期的に発火される | `[RuntimeInitializeOnLoadMethod(BeforeSplashScreen)]` またはそれより早い bootstrap で購読する |
| `false` を返すと例外が投げられると誤解している | `false` の返却は「未処理」を意味するのみで、フレームワークは購読なしのパスに従って処理を継続する(アサートで中断する可能性あり) | 実際に処理した場合は `true` を返す |

## 背景(オプション)

Unity は Android パッケージング時、デフォルトで APK 内のしきい値を超える `assets/` ファイルを一括圧縮します。しかし `BlankReadAssets` は ZIP の Central Directory を直接たどって `StreamingAssets` 内ファイルのオフセットと非圧縮サイズを特定しているため、APK 内でそのファイルが圧縮されている場合(`CompressedSize != UncompressedSize`)に、「オフセット指定で生バイトを読み取る」という戦略は失敗します。そのためイベント機構が設計されました。これにより業務側で圧縮されたアセットのフォールバック方法を決定できます([BlankReadAssets.cs#L70-L78](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L70-L78))。
