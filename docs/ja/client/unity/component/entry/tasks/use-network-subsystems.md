# ネットワーク、ダウンロード、Web、Protobuf 通信の使用方法

GameFrameX は `GameApp.Network` / `GameApp.Download` 静的アクセサーを通じてネットワークおよびダウンロードコンポーネントを公開します。Web リクエストと Protobuf 通信は対応するコンパニオンパッケージによって提供されます。以下に、4 つのサブシステムを組み込むための最小手順を示します。

## 前提条件

| サブシステム | 必要なマクロ / パッケージ | 役割 |
|--------|-------------|------|
| ネットワーク (Network) | `ENABLE_GAME_FRAME_X_NETWORK` + `GameFrameX.Network.Runtime` | TCP / UDP 常時接続、Protobuf プロトコルに基づく |
| ダウンロード (Download) | `ENABLE_GAME_FRAME_X_DOWNLOAD` + `GameFrameX.Download.Runtime` | HTTP/HTTPS ファイルダウンロード、進捗コールバック |
| Web | `GameFrameX.Web.Runtime` | 単発 HTTP リクエスト(REST / JSON) |
| Protobuf | `GameFrameX.ProtoBuf.Runtime` | メッセージのエンコード/デコード、Network 内部で使用 |

> これら 4 つのコンポーネントはいずれも GameEntry 起動時に登録され、`GameApp.Network`、`GameApp.Download` などの静的プロパティを通じてシングルトンを取得します。

## 操作手順

### 1. ネットワークコンポーネントを有効にする

`GameApp.Network` を直接呼び出すだけでシングルトンを取得できます。フレームワーク内部では `GameEntry.GetComponent<NetworkComponent>()` が呼ばれます。

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Runtime;

var network = GameApp.Network;
network.Connect("127.0.0.1", 7000);
#endif
```

Source: [Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L55)

### 2. ダウンロードコンポーネントを有効にする

ダウンロードコンポーネントも同様に `GameApp.Download` シングルトンを通じてアクセスします:

```csharp
#if ENABLE_GAME_FRAME_X_DOWNLOAD
using GameFrameX.Runtime;

var downloader = GameApp.Download;
downloader.DownloadAsync(url, savePath, (success, error) =>
{
    if (success) UnityEngine.Debug.Log("下载完成");
    else UnityEngine.Debug.LogError(error);
});
#endif
```

Source: [Runtime/GameApp.Download.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Download.cs#L32-L55)

### 3. Web リクエストを送信する

Web モジュールは単発の HTTP 呼び出し(JSON、フォームなど)に使用され、常時接続の Network とは互いに干渉しません:

```csharp
using GameFrameX.Web.Runtime;

WebComponent web = GameEntry.GetComponent<WebComponent>();
web.Post("https://api.example.com/login", "{\"user\":\"x\"}",
    (statusCode, body) => UnityEngine.Debug.Log($"{statusCode} -> {body}"));
```

### 4. Protobuf でメッセージをシリアライズする

Network 内部では既に Protobuf が使用されています。カスタムメッセージでも同じ ProtoBuf コンポーネントを再利用します:

```csharp
using GameFrameX.ProtoBuf.Runtime;

byte[] bytes = ProtoBufComponent.Serialize(myMessage);
var restored = ProtoBufComponent.Deserialize<MyMessage>(bytes);
```

### 5. 切断と再接続

```csharp
GameApp.Network.Close();
GameApp.Network.Connect("127.0.0.1", 7000); // 接続を再確立する
```

## よくあるバリエーション

- **マルチチャネルの常時接続**:`NetworkComponent` は複数の `NetworkChannel` をサポートし、各 channel が独立したハートビート / 独立したエンコード・デコードを持ちます。
- **レジュームダウンロード**:`DownloadAsync` のコールバックでダウンロード済みバイト数を保存し、起動時に `Range` ヘッダーで再開します。
- **Protobuf 以外のプロトコル**:新規 `NetworkChannel` 作成時にカスタム `INetworkChannelHelper` を渡すことで、JSON / MessagePack に置き換えられます。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `GameApp.Network` が `null` を返す | `ENABLE_GAME_FRAME_X_NETWORK` マクロが定義されていない | `Project Settings → Scripting Define Symbols` に追加し、`GameFrameX.Network` パッケージをインストールする |
| ダウンロードコールバックで `success=false` になるが `error` テキストがない | URL が不正、またはディスクに書き込み権限がない | `url` と `savePath` を確認し、Application.persistentDataPath が書き込み可能であることを確認する |
| Web リクエストがステータスコード 0 を返す | 対象ドメインが Unity で許可されていない | Player Settings → Other Settings → Allow downloads over HTTP を確認する |
| Protobuf シリアライズで例外がスローされる | メッセージクラスに `[ProtoContract]` / `[ProtoMember]` が付与されていない | メッセージフィールドに属性を追加するか、protobuf-net の `ImplicitFields = ImplicitFields.AllPublic` を使用する |

## 背景(任意)

`GameApp` は `partial class` であり、各サブシステムがそれぞれ独自のファイルを持ち、`GameEntry.GetComponent<T>()` を通じて統一的に遅延ロードされ、プライベート静的フィールドにキャッシュされます。これにより、あちこちで `GetComponent` 呼び出しを書かずに済み、またマクロ単位で不要なサブシステムを除外しやすくなり、リリースパッケージのサイズを削減できます。
