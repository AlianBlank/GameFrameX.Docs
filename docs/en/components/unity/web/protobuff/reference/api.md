# WebProtoBuff API Quick Reference (Post / Timeout / Connection Count)

This page collects the public APIs of the WebProtoBuff module: the `Post<T>` request method, the default values and meanings of the three configuration items `Timeout` / `RequestTimeout` / `MaxConnectionPerServer`, and the exceptions that may be thrown during requests. All entries are taken from real signatures in the source code.

## Post Request Method

| Name | Signature | Description |
|------|------|------|
| `IWebProtoBuffManager.Post<T>` | `Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage` | Sends a POST request with a Protobuf message and parses the response as `T`; only available when the `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` macro is enabled |
| `WebProtoBuffComponent.Post<T>` | `Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage` | Same-named forwarding method at the Unity component layer, internally calls the manager's `Post<T>` |

The interface definition can be found at [IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L9-L29), and the component forwarding at [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108).

`Post<T>` internal flow: wraps the message into a `MessageHttpObject` (containing `Id`, `UniqueId`, `Body`), serializes it, and puts it into the waiting queue; after the response returns, it first looks up the response type by `Id` — if it does not match `T`, it logs an error and returns `default`:

```csharp
public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
{
    DebugSendLog(message);
    var webBufferResult = await PostInner(url, message);
    if (webBufferResult.IsNotNull())
    {
        var messageObjectHttp = SerializerHelper.Deserialize<MessageHttpObject>(webBufferResult.Result);
        if (messageObjectHttp.IsNotNull() && messageObjectHttp.Id != default)
        {
            var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
            if (messageType != typeof(T))
            {
                Log.Error($"Response message type is invalid. Expected '{typeof(T).FullName}', actual '{messageType.FullName}'.");
                return default;
            }

            var messageObject = SerializerHelper.Deserialize<T>(messageObjectHttp.Body);
            DebugReceiveLog(messageObject);
            return messageObject;
        }
    }

    return default;
}
```

## Configuration Properties (Timeout / Connection Count)

| Name | Type | Default Value | Defined In | Description |
|------|------|--------|--------|------|
| `Timeout` | `float` | `5f` (seconds) | `IWebProtoBuffManager` / `WebProtoBuffManager` / `WebProtoBuffComponent` | POST request timeout in seconds; setting it also updates `RequestTimeout` |
| `RequestTimeout` | `TimeSpan` | `TimeSpan.FromSeconds(5)` | `WebProtoBuffManager` | The request timeout duration converted from `Timeout`, used when actually sending requests |
| `MaxConnectionPerServer` | `int` | `8` | `WebProtoBuffManager` | Maximum number of concurrent connections per server; when the number of in-flight requests reaches this value, subsequent requests stay in the waiting queue |
| `m_Timeout` (serialized field) | `float` | `5f` | `WebProtoBuffComponent` | The "Timeout. Unit: seconds" field on the Inspector; written into the manager during `Awake` |

```csharp
public WebProtoBuffManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

public int MaxConnectionPerServer { get; set; }

public TimeSpan RequestTimeout { get; set; }
```

## Runtime Behavior Quick Reference

| Behavior | Basis |
|------|------|
| Request Content-Type is fixed to `application/x-protobuf` | `ProtoBufContentType` constant |
| Non-WebGL platforms use `HttpWebRequest`, with `request.Timeout` set to `RequestTimeout.TotalMilliseconds` | `MakeProtoBufBytesRequest` |
| WebGL platform uses `UnityWebRequest`, with `unityWebRequest.timeout` set to `(int)RequestTimeout.TotalSeconds` | `MakeProtoBufBytesRequest` |
| After a timeout is caught, the task ends with a `TimeoutException` | `WebExceptionStatus.Timeout` branch |
| The concurrency limit is controlled by `MaxConnectionPerServer`: a request is dequeued from the waiting queue only when `m_SendingProtoBufList.Count < MaxConnectionPerServer` | `UpdateProtoBuf` |
| On Shutdown, all `WebProtoBuffData` in the waiting queue and the sending list are returned to the reference pool | `ShutdownProtoBuf` |

## Component Initialization

`WebProtoBuffComponent` is a wrapper component attached to a Unity scene; in `Awake` it retrieves the module from `GameFrameworkEntry` and writes the Inspector-serialized timeout into the manager; if the module cannot be retrieved, it logs `Log.Fatal("Web manager is invalid.")`:

```csharp
m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
if (m_WebProtoBuffManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebProtoBuffManager.Timeout = m_Timeout;
```
