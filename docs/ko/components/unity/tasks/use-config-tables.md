# 설정 테이블(설정 센터)을 로드하고 사용하는 방법

이 페이지에서는 GameFrameX.Unity에서 LuBan 도구로 생성되어 `Hotfix.Config` 어셈블리에서 호스팅되는 설정 테이블 데이터를 로드하고 사용하는 방법을 설명합니다. 설정 테이블은 `TbXxxConfig` 형식으로 제공되며, `TablesComponent`를 통해 통합 초기화된 후 `Id` 또는 문자열 키로 항목을 조회할 수 있습니다.

## 사전 조건

- LuBan 편집기 확장을 통해 설정 테이블 코드가 생성되어 있어야 합니다(기본 출력 디렉터리: `Assets/Hotfix/Config/Generate/`).
- 프로젝트에 `GameFrameX.Config.Runtime` 및 `SimpleJSON` 런타임 의존성이 포함되어 있어야 합니다.
- 비즈니스 측에서 설정 테이블의 리소스 로드 방식(로컬 StreamingAssets / 원격 CDN)을 정하고, `Func<Task<JSONNode>>`를 `TbXxxConfig` 생성자에 제공해야 합니다.

## 작업 단계

1. 설정 테이블의 엔터티 클래스와 테이블 클래스가 생성되었는지 확인합니다. 각 테이블은 두 개의 파일에 대응됩니다: 엔터티 클래스 `XxxConfig`(필드 + 생성 + `Deserialize`)와 테이블 클래스 `TbXxxConfig`(`BaseDataTable<XxxConfig>` 상속).

   예시: `AchievementConfig` 엔터티 클래스는 [AchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L16-L50)에 정의되어 있고, 테이블 컨테이너는 [TbAchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L60)에 있습니다. `TbAchievementConfig`는 `BaseDataTable<Tables.AchievementConfig>`를 상속하며, 생성자를 통해 `_loadFunc`를 주입받습니다.

   ```csharp
   // Source: Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L38
   public partial class TbAchievementConfig : BaseDataTable<Tables.AchievementConfig>
   {
       private readonly System.Func<System.Threading.Tasks.Task<JSONNode>> _loadFunc;
       public TbAchievementConfig(System.Func<System.Threading.Tasks.Task<JSONNode>> loadFunc)
       {
           _loadFunc = loadFunc;
       }
       public override async System.Threading.Tasks.Task LoadAsync()
       {
           var jsonNode = await _loadFunc();
           StringDataMaps.Clear();
           DataList.Clear();
           foreach(var _ele in jsonNode.Children)
           {
               Tables.AchievementConfig _v;
               { if(!_ele.IsObject) { throw new SerializationException(); }
                 _v = Tables.AchievementConfig.DeserializeAchievementConfig(_ele); }
               DataList.Add(_v);
               LongDataMaps.Add(_v.Id, _v);
               StringDataMaps.Add(_v.Id.ToString(), _v);
           }
           PostInit();
       }
   }
   ```

2. 각 테이블에 대해 `loadFunc`를 제공합니다. 내부에서 로컬/원격 리소스에서 JSON을 읽어 `JSONNode`로 역직렬화합니다.

   ```csharp
   // loadFunc 예시: StreamingAssets에서 비동기로 읽어 JSON 파싱
   Func<Task<JSONNode>> loadAchievement = async () =>
   {
       var text = await File.ReadAllTextAsync(
           Path.Combine(Application.streamingAssetsPath, "AchievementConfig.json"));
       return JSON.Parse(text);
   };

   var tbAchievement = new TbAchievementConfig(loadAchievement);
   await tbAchievement.LoadAsync();
   ```

3. 모든 `TbXxxConfig`를 `TablesComponent`에 등록하여 로드, 테이블 간 참조 해석(`ResolveRef`), 다국어 키 번역(`TranslateText`)을 통합 관리하도록 합니다.

   ```csharp
   // 테이블 인스턴스를 TablesComponent에 추가하고 초기화 실행
   var tables = new TablesComponent();
   tables.Add(tbAchievement);   // 다른 TbXxxConfig도 동일한 방식
   await tables.InitAsync();    // 내부에서 의존 순서대로 각 테이블의 LoadAsync + ResolveRef 호출
   ```

4. 비즈니스 코드에서 `Id` 또는 키로 데이터를 조회합니다. `BaseDataTable<T>`는 `LongDataMaps`, `StringDataMaps`, `DataList` 세 가지 컬렉션을 제공하므로 키를 통해 직접 읽을 수 있습니다.

   ```csharp
   // 엔터티 클래스가 노출하는 필드 예시(읽기 전용 속성)
   // Source: Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L51-L80
   var row = tables.Achievement.Get(1001);   // LongDataMaps["1001"]
   var nameKey = row.Name;                   // 다국어 Key
   var conditions = row.AchievementUnlockCondition;  // List<int>
   ```

5. 테이블 간 참조 및 다국어 처리: 모든 테이블의 `LoadAsync`가 완료된 후 `ResolveRef(tables)`를 호출하여 항목이 다른 테이블의 참조를 해석하도록 합니다. 그런 다음 `TranslateText(translator)`를 호출하여 `xxx_Localization_Key`의 현지화를 완료합니다.

   ```csharp
   // Source: TbAchievementConfig.cs#L40-L54
   tbAchievement.ResolveRef(tables);
   tbAchievement.TranslateText((key, defaultText) => Localization.Get(key) ?? defaultText);
   ```

## 일반적인 변형

- **로컬 리소스 vs 원격 리소스**: `loadFunc` 내부에서 각각 `Application.streamingAssetsPath` 읽기 또는 `UnityWebRequest.Get` 다운로드를 구현할 수 있으며, 최종적으로 `JSONNode`를 반환하기만 하면 됩니다.
- **다국어 키**: `AchievementConfig`는 생성 시 다국어 필드를 `Name_Localization_Key`, `AchievementContent_Localization_Key`, `LockText_Localization_Key`로 복사하며, `TranslateText` 콜백을 통해 교체됩니다.
- **확장 타입 매핑**: 열거형과 외부 타입은 [ExternalTypeUtil.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Extension/ExternalTypeUtil.cs)에서 등록할 수 있으며, LuBan 역직렬화 시 참조됩니다.

## 일반적인 오류

- **JSON 필드 타입 불일치**: `Deserialize`는 타입이 일치하지 않을 때 `SerializationException`을 발생시킵니다(`AchievementConfig.cs` 31-36번째 줄의 단언문). Excel/JSON 내보내기 스크립트와 엔터티 클래스의 필드 타입이 일치하는지 확인하세요.
- **`ResolveRef` 호출 누락**: 테이블 간 참조 필드가 기본값/빈 값으로 유지되므로, 반드시 모든 테이블의 `LoadAsync`가 완료된 후 호출해야 합니다.
- **`LoadAsync` 중복 호출**: 먼저 `Clear()`를 호출하지 않으면 `LongDataMaps`/`StringDataMaps`에 키가 중복됩니다. 생성된 코드는 시작 부분에서 `Clear()`를 호출하지만, `loadFunc`를 수동으로 재사용할 때는 여전히 주의가 필요합니다.
- **생성된 파일 직접 수정**: `XxxConfig.cs`와 `TbXxxConfig.cs` 상단에는 모두 `<auto-generated>` 표시가 있으며, 변경 사항은 다음 생성 시 덮어쓰여집니다. 커스텀 로직은 `partial`의 다른 부분 파일에 작성해야 합니다.

## 배경(선택 사항)

LuBan은 GameFrameX와 함께 제공되는 Excel→JSON→C# 코드 생성 도구입니다: Excel로 테이블 구조를 정의하고, 도구는 JSON 데이터 파일과 위와 같은 `BeanBase` / `BaseDataTable<T>` 형태의 엔터티 + 컨테이너 코드를 생성합니다. `TablesComponent`는 설정 센터 역할을 하여 시작 단계에서 로드, 참조 해석을 통합 처리하고 필요에 따라 현지화를 트리거하여, 비즈니스 측이 강타입 객체를 대상으로만 프로그래밍하도록 합니다.
