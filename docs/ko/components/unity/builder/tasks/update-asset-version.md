# 원격 Asset 패키지 버전 업데이트 방법

빌드가 완료되면, 이 도구는 현재 Asset 패키지의 버전 번호, 플랫폼, 채널, 언어 등 메타데이터를 HTTP POST를 통해 사용자가 지정한 원격 인터페이스로 보고하여, 서버 측에서 최신 버전을 기록/배포하는 데 사용됩니다. 이 페이지에서는 해당 기능을 활성화하고 구성하는 방법을 설명합니다.

## 사전 조건

- `BuilderOptions`(빌드 매개변수)에서 Asset 패키지 빌드 관련 필드를 구성했어야 합니다: `PackageName`, `PackageVersion`, 빌드 파이프라인 등.
- 버전 보고를 수신할 HTTP 인터페이스(POST JSON)를 준비하고, 게이트웨이 측에서 `Authorization` 헤더를 미리 약속해야 합니다.
- 원격 서비스가 배포되어 빌드 머신에서 접근 가능해야 합니다.

## 작업 단계

1. `BuilderOptions`에서 `IsUpdateAssetPackageVersion`을 활성화하고, 인터페이스와 인증 정보를 입력합니다:

   ```csharp
   _builderOptions.IsUpdateAssetPackageVersion = true;
   _builderOptions.UpdateAssetPackageVersionUrl = "https://your-server/api/asset/version";
   _builderOptions.UpdateAssetPackageVersionAuthorization = "Bearer your-token";
   ```

   필드 정의는 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L82-L95)에 있습니다.

2. 빌드 산출물이 성공적으로 생성되었는지 확인합니다. 버전 보고는 빌드+업로드 직후에 실행되며, 트리거 로직은 [Builder.BuildAsset.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L134-L141)을 참조하세요:

   ```csharp
   if (_builderOptions.IsUpdateAssetPackageVersion)
   {
       var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
       if (result)
       {
           WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
       }
   }
   ```

3. 빌드를 시작합니다. `BuilderUpdateAssetPackageVersionHelper.Run`은 아래 필드들을 JSON POST 방식으로 `UpdateAssetPackageVersionUrl`에 보고합니다:

   | 필드 | 출처 |
   |------|------|
   | `AppVersion` | `Application.version` |
   | `PackageName` | `Application.identifier` |
   | `AssetPackageVersion` | `buildParameters.PackageVersion` |
   | `AssetPackageName` | `buildParameters.PackageName` |
   | `Platform` | `buildParameters.BuildTarget.ToString()` |
   | `Language` | `builderOptions.Language` |
   | `Channel` | `builderOptions.ChannelName` |

   구현은 [BuilderUpdateAssetPackageVersionHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderUpdateAssetPackageVersionHelper.cs#L51-L86)를 참조하세요.

4. 서버 측에서 성공을 반환하면, 도구는 추가로 `WeChatNotifyWorkHelper.Run`을 호출하여 기업 위챗(企微) 알림을 발송합니다(구성되어 있는 경우).

## 일반적인 변형

- **로컬 업로드만 수행, 버전 보고 안 함**: `IsUpdateAssetPackageVersion`을 `false`로 유지하여 HTTP 호출을 건너뜁니다.
- **타임스탬프를 버전 번호로 사용**: `PackageVersion`을 비워두면, 빌드 시 자동으로 타임스탬프로 채워집니다([BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L98-L100)).
- **다중 플랫폼 개별 보고**: 각 `BuildTarget`마다 한 번씩 빌드를 실행하면, 매번 해당 플랫폼 문자열이 `Platform` 필드로 보고됩니다.

## 일반적인 오류

- **HTTP 호출에서 예외 발생**: 요청의 기본 타임아웃은 30초입니다(`httpClient.Timeout = TimeSpan.FromSeconds(30)`). 예외는 `catch`되어 `Debug.LogException`으로 출력되며, 빌드流程은 중단되지 않지만 버전 보고는 성공하지 못합니다. 서버 측 로그 또는 Unity Console에서 스택 트레이스를 확인할 수 있습니다.
- **Authorization 미설정**: `UpdateAssetPackageVersionAuthorization`이 빈 문자열일 때, `httpClient.DefaultRequestHeaders.Add("Authorization", "")`는 빈 인증 헤더를 전송하며, 일반적으로 서버 측에서 거부됩니다. 게이트웨이 측에서 약속된 토큰을 입력하세요.
- **원격 URL이 비어 있음**: `UpdateAssetPackageVersionUrl`이 빈 문자열이면 유효하지 않은 주소로 POST가 전송되어 반드시 예외가 발생합니다.

## 배경 지식 (선택 사항)

버전 보고는 빌드 流程의 선택적 마무리 단계이며, 기본적으로 비활성화되어 있습니다(`IsUpdateAssetPackageVersion = false`). 이는 YooAsset 빌드 산출물 생성 후, 객체 스토리지 업로드 이후에 순차적으로 실행됩니다; 성공을 반환해야만 기업 위챗 알림이 트리거되므로, "빌드 체인의 최종 성공"의 간단한 신호로 활용할 수 있습니다.
