# 子スレッドから安全にイベントをディスパッチする方法

子スレッド（ネットワークスレッド、Task、非同期コールバックなど）で `Fire`（`FireNow` ではなく）を呼び出すだけで、安全にイベントをディスパッチできます：この操作はスレッドセーフであり、イベントはキューに入れられ、メインスレッドの次のフレームでイベント処理関数がコールバックされることが保証されています。処理関数の中では Unity API を安心して操作できます。

## 前提条件

- シーン内に `EventComponent` をアタッチしたオブジェクトが存在すること（またはモジュールシステムを通じて `EventManager` を取得済みであること）。
- メインスレッドで先にイベントの購読（`Subscribe` / `CheckSubscribe`）を完了しておき、子スレッドは `Fire` のみを担当します。

## 操作手順

1. メインスレッド（`Awake`/`Start` など）で、シーン内の `EventComponent` の参照を通じてイベントを購読します。`Fire` でディスパッチされたイベントに処理関数がなくてもエラーにはなりません（イベントプールは `AllowNoHandler | AllowMultiHandler` モードで作成されています）：

```csharp
private void Start()
{
    // CheckSubscribe：存在しない場合のみ購読し、重複登録を回避
    eventComponent.CheckSubscribe(DownloadFinishedEventArgs.EventId, OnDownloadFinished);
}

private void OnDownloadFinished(object sender, GameEventArgs e)
{
    // Fire でディスパッチされたイベントはメインスレッドでコールバックされることが保証されており、Unity オブジェクトを直接操作できます
    Debug.Log("下载完成");
}
```

`CheckSubscribe` の実際の実装（存在しない場合のみ購読）：

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

出典: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

2. 子スレッドでスレッドセーフな `Fire` を呼び出してイベントをディスパッチします（以下は呼び出し方の例です。`EventComponent` の実際のインターフェースは手順の最後にあるソースコード抜粋を参照してください）。イベントは送出後の**次のフレーム**にメインスレッドで配信されます：

```csharp
// 子スレッドのコード（例：Task.Run / ネットワークライブラリのコールバック）。eventComponent はシーン内の EventComponent への参照
Task.Run(() =>
{
    byte[] data = DownloadFromNetwork(); // 時間のかかる処理
    eventComponent.Fire(this, EmptyEventArgs.Create(DownloadFinishedEventArgs.EventId));
});
```

`EventComponent.Fire` は 2 つのオーバーロードを提供しており、イベント ID によるディスパッチのオーバーロードは内部で `EmptyEventArgs.Create(eventId)` を使用し、ID に対して非空検証を行います：

```csharp
public void Fire(object sender, GameEventArgs e)
{
    m_EventManager.Fire(sender, e);
}

public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

出典: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L147-L161)

3. カスタムデータを含める必要がある場合は、`GameEventArgs` を継承したパラメータ型を独自に定義し、子スレッドでデータを設定してから `Fire` で送出します（以下は呼び出し方の例です。`EmptyEventArgs` はリポジトリに組み込みの引数なしイベントで、カスタムパラメータクラスも同じ考え方で実装します）：

```csharp
public class DownloadFinishedEventArgs : GameEventArgs
{
    public const string EventId = "Download.Finished";
    public byte[] Data { get; set; }
}

// 子スレッドでディスパッチ：
eventComponent.Fire(this, new DownloadFinishedEventArgs { Data = data });

// メインスレッドの処理関数で読み取る：
private void OnDownloadFinished(object sender, GameEventArgs e)
{
    var args = (DownloadFinishedEventArgs)e;
    UseBytes(args.Data);
}
```

`GameEventArgs` は継承に開かれた抽象基底クラスで、`GameFrameX.Event.Runtime` 名前空間にあります：

```csharp
public abstract class GameEventArgs : BaseEventArgs
{
}
```

出典: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

## よくあるバリエーション

| シナリオ | 方法 |
|------|------|
| 通知のみ、データなし | `Fire(sender, eventId)` の文字列オーバーロード。内部で `EmptyEventArgs.Create(eventId)` を使って空のパラメータを構築 |
| `IEventManager` を直接保持している | `IEventManager.Fire(object sender, GameEventArgs e)`。コンポーネントのラップ動作と一致 |
| イベントがメインスレッドのみで、同フレームでの反映が必要 | `FireNow` を使いますが、**子スレッドで呼び出すことは絶対に禁止**です（下記参照） |

## よくある間違い

| 間違い | 結果と回避策 |
|------|-----------|
| 子スレッドで `FireNow` を呼び出す | `FireNow` は**スレッドセーフではありません**。呼び出したスレッド上で即座に配信されるため、処理関数が子スレッドで実行され、Unity がクラッシュする可能性があります。子スレッドでは必ず `Fire` を使用してください。ソースコードのコメントにも明記されています：[EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L167-L175) |
| `Fire` が同フレームで反映されることを期待する | `Fire` でディスパッチされたイベントは送出後の次のフレームで配信されるため、同フレームのタイミングに依存するロジック（状態の即時読み取りなど）は、処理関数のコールバック後に実行するよう変更する必要があります |
| 子スレッドで `Subscribe`/`Unsubscribe` を行う | 購読テーブルの操作にはスレッドセーフの保証がないため、処理関数の追加・削除はメインスレッドでのみ行ってください |
| イベント ID に空文字列を渡す | `Fire(sender, eventId)` 内部の `GameFrameworkGuard.NotNullOrEmpty` が検証例外を直接スローします |

## 背景

`EventManager` は `GameFrameworkModule` です（優先度 7）。`Fire` はイベントを内部の `EventPool<GameEventArgs>` キューに入れます。モジュールは毎フレーム、メインスレッドの `Update` 内で `m_EventPool.Update(elapseSeconds, realElapseSeconds)` を呼び出してキューを空にし、処理関数をコールバックします。これが「子スレッドで送出、メインスレッドでコールバック、次のフレームで配信」という動作の由来です。関連する実装は [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L76-L92) と [IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L93-L104) を参照してください。
