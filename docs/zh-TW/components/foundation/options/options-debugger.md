# 如何在應用程式啟動時輸出除錯資訊

使用 `OptionsBuilder.CreateWithDebug<T>` 或直接呼叫 `OptionsDebugger.PrintParsedOptions`,即可在應用程式啟動時，以表格形式將已解析的命令列引數、值、型別、預設值、是否必填等資訊輸出至主控台。如此一來，便能輕鬆對啟動時的設定問題進行疑難排解。

## 前置條件

- 已從 NuGet 參考 `GameFrameX.Foundation.Options`。
- 已定義 `class` 設定型別，且各屬性均已套用 `OptionAttribute`(請參閱 `OptionAttribute` 的使用方式)。

## 操作步驟

1. 定義設定型別 `AppOptions`,並在各屬性上套用 `OptionAttribute`:

```csharp
using GameFrameX.Foundation.Options.Attributes;

public sealed class AppOptions
{
    [Option(LongName = "host", Description = "服务监听地址", Required = true)]
    public string Host { get; set; } = "127.0.0.1";

    [Option(LongName = "port", Description = "服务端口", DefaultValue = 8080)]
    public int Port { get; set; }

    [Option(LongName = "token", Sensitive = true, Description = "访问令牌")]
    public string Token { get; set; }
}
```

Source: [AppOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/OptionsDebuggerSensitiveOutputTests.cs#L1-L40)

2. 在 `Main`/`Program` 中使用 `CreateWithDebug`,以一行程式碼同時完成建置與輸出：

```csharp
using GameFrameX.Foundation.Options;

var options = OptionsBuilder.CreateWithDebug<AppOptions>(
    args: args,
    skipValidation: false);

Console.WriteLine($"使用 Host = {options.Host}");
```

`CreateWithDebug` 內部已呼叫 `OptionsDebugger.PrintParsedOptions(result)`,會以表格形式輸出解析結果。

Source: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L175-L184)

3. 使用 `OptionsBuilder<T>.Build()` 或 `OptionsProvider.Get<T>()` 時，同樣會在成功路徑中自動呼叫 `PrintParsedOptions`,因此不需要額外輸出。

Source: [OptionsProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsProvider.cs#L185-L218)

4. 若想自行控制輸出時機，可直接呼叫：

```csharp
OptionsDebugger.PrintParsedOptions(options);
```

輸出內容包含標頭 `Command-line parameter and parsed configuration object information`,以及 6 欄的表格(選項、值、必填、型別、說明、預設值)。機密欄位(`Sensitive = true`)的值將被遮罩。

Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L70-L91)
Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L161-L172)

## 常見變化

- **手動攔截例外並輸出**：當 `TryCreate` 失敗時，`result` 會回退為預設值物件。可在 catch 之後呼叫 `PrintParsedOptions` 來輸出錯誤上下文。
- **僅輸出已建置的物件**：在啟動時以外的除錯情境中，只要在某處取得 `TOptions` 執行個體，直接呼叫 `OptionsDebugger.PrintParsedOptions(options)` 即可。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 主控台欄位錯亂、全形字元位置偏移 | 主控台寬度小於 `DefaultConsoleWidth`(120),導致欄寬被壓縮 | 啟動時加寬主控台寬度，或改用支援全形字元的終端機執行 |
| 表格中特定欄位被截斷 | 說明文字過長，達到 `MaxDisplayElements` 的上限 | 縮短 `Description` 的文字，或將其拆分為多個屬性 |
| 機密欄位以明文顯示 | 未啟用 `OptionAttribute.Sensitive` | 在包含金鑰的屬性上明確加上 `Sensitive = true` |
| 未以表格形式輸出 | 型別並非 `class`,或沒有公開的執行個體屬性 | 使用符合 `where T : class, new()` 的設定型別 |

## 背景(選用)

`OptionsDebugger` 會以反射列舉 `T` 的公開屬性，依字元的顯示寬度(中文為全形寬度)適應主控台寬度，並遮罩機密欄位。由於啟動時的輸出已在 `CreateWithDebug` 與 `OptionsProvider` 內部統一呼叫，因此可避免在各處重複撰寫樣板程式碼。
