# What to Do When Entity Contract Validation Fails

When `EntityContractValidator.Validate<T>()` returns a non-empty list, or the ORM reports an interface property inconsistency at runtime, it means the entity class does not satisfy the contract of the interface it implements (such as `IEntity`, `IVersionedEntity`, `IAuditableEntity`). This page provides troubleshooting and fix methods organized by error message.

## Quick Diagnosis

| Symptom (`Reason` text fragment) | Root Cause | Fix |
|------|------|------|
| `Property 'XXX' not found on type 'YYY'` | Entity class is missing a property required by the interface | Add a property with the same name and type to the entity class |
| `Property 'XXX' type mismatch: expected 'A', actual 'B'` | Property type does not match the interface declaration | Change the property type to the type required by the interface (or a nullable compatible type) |
| `Property 'XXX' is missing a getter` | Property is declared with `set` but no `get` (or `private get`) | Add a public getter |
| `Property 'XXX' is missing a setter` | Property only has `get` without `set` (or `private set`) | Add a public setter |
| `Property 'XXX' has multiple declarations on type 'YYY' (possible 'new' keyword shadowing)` | Inherited interface property is shadowed using the `new` keyword | Remove `new`, or merge into a single property |
| Calling `Validate(null)` throws `ArgumentNullException` | A null `Type` was passed in | Pass in a non-null entity type |

## Fix Steps

### 1. Missing Property

The interface requires a field (such as `IVersionedEntity.Version`) but the entity class does not declare it. Simply add the corresponding property in the entity class:

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class Player : IVersionedEntity
{
    public long Version { get; set; } // Add the property required by the interface
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118)

### 2. Type Mismatch

The interface declares `DateTime`, but the entity uses `DateTimeOffset` or `string` instead. Change the type back to what the interface requires; when the interface type is a value type, the entity can use the corresponding `Nullable<T>`, and the validator will perform compatibility checks via `Nullable.GetUnderlyingType`.

```csharp
public interface IAuditableEntity
{
    DateTime CreatedAt { get; set; }
}

public class Order : IAuditableEntity
{
    public DateTime CreatedAt { get; set; } // The type must match; DateTime? is also acceptable
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

### 3. Missing getter / setter

ORMs often need both read and write access. Complete the accessors:

```csharp
public DateTime UpdatedAt { get; set; } // Both get and set must be public
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144)

### 4. `new` Keyword Shadowing

A property inherited from a base class is redeclared with `new`, causing `GetProperty` to hit multiple matches and trigger an `AmbiguousMatchException`. Remove `new` and merge into a single property:

```csharp
// Wrong: new keyword shadowing
public new long Version { get; set; }

// Correct: use the base class declaration directly
// (Delete the entire new declaration, or use override/explicit interface implementation)
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108)

### 5. Automated Validation Invocation

Call the validator at application startup or in unit tests to print out all violations at once:

```csharp
using GameFrameX.Foundation.Orm.Entity;

var violations = EntityContractValidator.Validate<Player>();
foreach (var v in violations)
{
    Console.WriteLine($"{v.InterfaceType.Name}.{v.PropertyName}: {v.Reason}");
}
```

The returned `EntityContractViolation` contains three fields: `InterfaceType`, `PropertyName`, and `Reason`.

## Verification

Call `Validate<T>()` again after fixing:

- If the returned `IList<EntityContractViolation>` has length 0, all contracts are satisfied.
- If non-empty items are still returned, continue fixing by matching `Reason` against the diagnostic table above until the list is empty.

## What the Validator Does Not Check

`EntityContractValidator` only validates properties explicitly declared in the interface:

- Properties inherited by the interface from other interfaces are included in validation via `Type.GetInterfaces()`.
- Fields (`public int Foo;`), static members, and private members are not checked.
- Validation only occurs when the interface itself declares the member using property syntax; contracts expressed as methods are out of scope.
