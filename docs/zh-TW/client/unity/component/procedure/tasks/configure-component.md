# 如何設定 ProcedureComponent

`ProcedureComponent` 是 GameFrameX 流程系統的入口元件。它負責註冊 `IProcedureManager`、收集可用的流程類別，並在啟動時進入指定的入口流程。本頁說明如何在 Unity 中進行設定，讓遊戲如預期地從入口流程開始執行。

## 前置條件

- 專案已加入 `GameFrameX.Procedure` 組件。
- 已準備好繼承自 [ProcedureBase](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L80) 的流程類別(例如入口流程 `ProcedureLaunch`)。
- 場景中已存在 `GameFramework` 預製物(包含 `GameFrameXEntry` / `GameFrameworkEntry`),用來承載 `GameFrameworkComponent` 的衍生元件。

## 步驟

1. 將 `GameFramework` 預製物放置到場景中，並使用 **Add Component → GameFrameX → Procedure** 加入 `ProcedureComponent`。

   元件屬性會透過 `ProcedureComponentInspector` 在 Inspector 中視覺化呈現：

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Procedure")]
   [GameFrameXAutoComponent(-1000)]
   public sealed class ProcedureComponent : GameFrameworkComponent
   ```

   來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L43-L46)

2. 在 Inspector 的 **Available Procedures** 區域中，勾選所有需要啟用的流程類別(必須繼承自 `ProcedureBase`)。Inspector 會透過反射 `typeof(ProcedureBase)` 自動收集候選型別：

   ```csharp
   m_ProcedureTypeNames = TypeHelper.GetRuntimeTypeNames(typeof(ProcedureBase));
   ```

   來源:[ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L162-L165)

3. 在 **Entrance Procedure** 下拉選單中選取入口流程。此值會寫入序列化欄位 `m_EntranceProcedureTypeName`,並在啟動時透過型別比對找出入口實例：

   ```csharp
   if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
   {
       m_EntranceProcedure = procedures[i];
   }
   ```

   來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L152-L155)

4. 進入 Play 模式後，元件會在 `Start` 協程中呼叫 `Initialize` 與 `StartProcedure`:

   ```csharp
   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   yield return new WaitForEndOfFrame();
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

5. 執行後，您可以在 Inspector 頂部的 **Current Procedure** 欄位查看目前的流程：

   ```csharp
   EditorGUILayout.LabelField("Current Procedure", currentProcedureName);
   ```

   來源:[ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L83)

## 常見變化

- **使用 StartupRunner 接管啟動**：在 Inspector 中勾選 **Use Startup Runner**。在此模式下，`Awake` 中只會註冊 `IProcedureManager`;不再呼叫 `Initialize` 與 `StartProcedure`,改由 `ApplicationStartupEntry` 透過 `StartupRunner.Run` 接管：

  ```csharp
  if (m_UseStartupRunner)
  {
      // Initialize 與 StartProcedure 已由 ApplicationStartupEntry + StartupRunner.Run 接管。
      // 此元件僅負責在 Awake 中註冊 IProcedureManager,
      // 以避免與新入口重複 Initialize 而回報「Already exist FSM」。
      yield break;
  }
  ```

  來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L122-L127)

  勾選後，Inspector 會顯示提示訊息，並忽略下方的 **Available Procedures** 與 **Entrance Procedure** 設定：

  ```csharp
  EditorGUILayout.HelpBox("Procedure startup has been delegated to StartupRunner.Run. Available Procedures and Entrance Procedure configurations will be ignored.", MessageType.Info);
  ```

  來源:[ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L59)

- **在執行階段重新初始化流程**：呼叫 `ReinitializeProcedures` 可銷毀現有的狀態機，並以新的流程陣列重新初始化。常用於熱更新或自訂啟動順序：

  ```csharp
  [Preserve]
  public void ReinitializeProcedures(ProcedureBase[] procedures, ProcedureBase entranceProcedure)
  {
      m_ProcedureManager.ReinitializeProcedures(procedures);
      m_EntranceProcedure = entranceProcedure;
  }
  ```

  來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

## 常見錯誤

| 症狀 | 原始日誌 | 原因與修正方式 |
|------|----------|-----------|
| 流程未啟動 | `Available procedure type names is empty. Procedure auto start skipped.` | Inspector 中的 **Available Procedures** 為空。執行前請至少勾選一個流程類別。 |
| 無法建立實例 | `Can not find procedure type '{0}'.` | 型別名稱不存在於執行階段組件中。請確認流程類別已編譯且命名空間完整。 |
| 建立失敗 | `Can not create procedure instance '{0}'.` | 流程類別缺少無參數建構函式，或未繼承 `ProcedureBase`。 |
| 未設定入口 | `Entrance procedure is invalid.` | 未選取 **Entrance Procedure**,或所選項目不在 **Available Procedures** 清單中。 |
| 啟動時回報重複的 FSM | 啟用 StartupRunner 後仍由舊版 `Initialize` 路徑觸發 | 檢查是否同時存在兩個入口(`ApplicationStartupEntry` 與舊版 `ProcedureComponent.Start`),僅保留其中一個。 |

## 背景說明(選用)

`ProcedureComponent` 會在 `Awake` 中透過 `GameFrameworkEntry.GetModule<IProcedureManager>()` 取得流程管理器；只有在 `IsRuntimeComponentReady` 為 `true` 時才會繼續執行，以避免在編輯器模式下進行不正確的初始化。當 `m_UseStartupRunner` 為 `false`(預設值)時，`Start` 協程會根據反射取得的型別名稱陣列建構 `ProcedureBase` 實例，並從比對到的入口流程開始執行；當為 `true` 時，只註冊模組，並將初始化與啟動完全委派給 `StartupRunner.Run`,以避免因重複 `Initialize` 而導致 `Already exist FSM` 錯誤。
