# AES 加解密 사용 방법

`AesHelper`은(는) AES-GCM 기반의 인증된 加解密 기능을 제공합니다: 평문과 키를 전달하면 Base64 암호문을 얻을 수 있으며, 동일한 키로 복호화하면 원문을 복원할 수 있습니다. 매번 암호화마다 Salt와 Nonce가 무작위로 생성되므로 호출자가 관리할 필요가 없습니다.

## 전제 조건

- 프로젝트에서 NuGet 패키지 `GameFrameX.Foundation.Encryption`을(를) 참조합니다.
- 대상 프레임워크가 `System.Security.Cryptography.AesGcm`을(를) 지원해야 합니다(.NET 5+ / .NET Standard 2.1 플랫폼 구현).
- `using GameFrameX.Foundation.Encryption;` 및 `using System.Text;`.

##操作 단계

### 1. 문자열 加解密(Base64 출력)

```csharp
using GameFrameX.Foundation.Encryption;

string plain = "Hello, World! 这是一个测试字符串。";
string key = "MySecretKey123456";

string cipher = AesHelper.Encrypt(plain, key);
string back = AesHelper.Decrypt(cipher, key);
// back == plain
```

### 2. 바이트 배열 加解密(바이너리 데이터용)

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

byte[] data = Encoding.UTF8.GetBytes("任意二进制数据");
byte[] cipherBytes = AesHelper.Encrypt(data, "MySecretKey123456");
byte[] plainBytes = AesHelper.Decrypt(cipherBytes, "MySecretKey123456");
```

### 3. 加解密 후 디스크 저장 또는 전송

`cipher`(Base64 문자열) 또는 `cipherBytes`(바이너리)를 데이터베이스, 설정 파일에 저장하거나 네트워크로 전송하고, 수신 측은 동일한 키로 `Decrypt`을(를) 호출하여 복원합니다.

```csharp
// 伪代码：将密文保存到文件
File.WriteAllText("secret.bin", cipher);

// 伪代码：读取并解密
string read = File.ReadAllText("secret.bin");
string original = AesHelper.Decrypt(read, key);
```

## 일반적인 변형

- **다양한 길이의 키**: 소스 코드는 PBKDF2(SHA256, 600,000 회)를 사용하여 임의의 문자열 키를 32바이트 키로 파생시키므로, `"ShortKey"`부터 `"VeryLongKeyThatExceedsNormalLength123456789"`까지 모두 정상적으로 加解密됩니다.
- **Unicode/Emoji를 포함한 평문**: 평문은 UTF-8로 인코딩된 후 암호화에参与하며, `"🚀🌟💻🎮🔥"` 등 4바이트 문자도 정상적으로 왕복됩니다.
- **동일한 평문 + 동일한 키로 두 번 암호화**: Salt/Nonce가 무작위이므로 두 결과가 서로 다르지만, 두 결과 모두 원문으로 복호화됩니다 — 이것이 AES-GCM의 의미적 보안 특성입니다.

## 일반적인 오류

| 현상 | 원인 | 수정 |
|------|------|------|
| `ArgumentException: Plain text cannot be null or empty` | 평문이 `null` 또는 `""`임 | 암호화 전에 문자열이 비어 있지 않은지 확인 |
| `ArgumentException: Encryption key cannot be null or empty` | 키가 비어 있음 | 길이 ≥ 1의 비어 있지 않은 문자열 키 제공 |
| `ArgumentException: Cipher text byte array is too short to be valid.` | 암호문 길이가 45바이트 미만임(1+16+12+16 헤더) | `Encrypt`의 전체 출력이 전달되는지 확인 |
| `CryptographicException: Unsupported AES payload format version.` | 암호문 헤더 버전 바이트가 `2`가 아님 | 현재 버전의 라이브러리로 업그레이드하거나 이전 버전으로 복호화 |
| `CryptographicException`(복호화 시) | 암호화 시의 키와 일치하지 않거나 데이터가 변조됨 | 加解密에 동일한 키를 사용하는지 확인하고 전송 무결성을 검증 |

> 加解密 호출에서 어떤 매개변수라도 `null` / 빈 문자열이면 즉시 `ArgumentException`이(가) 발생하므로, 호출 전에 단언하거나 외부의 `try/catch`에서 처리할 수 있습니다.

## 배경(선택 사항)

구현은 AES-GCM 인증 암호화를采用합니다: 매번 16바이트 Salt와 12바이트 Nonce를 무작위로 생성하고, PBKDF2(SHA256, 600k 회)로 문자열 키를 32바이트 세션 키로 파생시킵니다. 출력 형식은 `Version(1) | Salt(16) | Nonce(12) | Tag(16) | 密文`이며, Tag는 무결성 검사에 사용됩니다. 변조되거나 키가 잘못되면 복호화 단계에서 `CryptographicException`이(가) 발생합니다.
