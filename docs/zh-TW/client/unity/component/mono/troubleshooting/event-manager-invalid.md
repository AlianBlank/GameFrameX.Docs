# 日誌出現 "Event manager is invalid." 怎麼辦

當 `MonoComponent` 在場景中啟動後無法從 `GameEntry` 取得 `EventComponent` 實例時，會在日誌中印出 `Event manager is invalid.` 並中止後續初始化流程，導致 Mono 模組的事件訂閱/發布全部失效。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 啟動時出現 `Event manager is invalid.` | 啟動場景裡沒有掛載 `EventComponent` | 在啟動場景的 `GameFramework` 節點上新增 `EventComponent`,見下文修復步驟 1 |
| 啟動時出現 `Event manager is invalid.` | 啟動場景掛載了 `EventComponent`,但 `MonoComponent` 的腳本執行順序早於 `EventComponent.Awake` | 在 Project Settings 中把 `MonoComponent` 的 Script Execution Order 調到 `Default` 之後，見修復步驟 2 |
| 啟動時出現 `Event manager is invalid.` | 同一元件上額外掛了重複的 `EventComponent`,導致 `GameEntry` 中儲存的實例被覆蓋/釋放 | 移除多餘的 `EventComponent`,確保框架入口節點上只有一份 |

## 修復步驟

### 1. 在啟動場景新增 EventComponent

`MonoComponent.Start()` 透過 `GameEntry.GetComponent<EventComponent>()` 取得事件元件；只有掛在 GameFramework 啟動物件上的元件才能被 `GameEntry` 索引到。

1. 開啟專案中的啟動場景(例如 `Assets/GameFrameX/Launch/Launch.unity`)。
2. 選取 `GameFramework` 根 GameObject。
3. Inspector → Add Component → 搜尋並新增 `GameFrameX.Event.EventComponent`。
4. 重新執行，日誌應不再出現 `Event manager is invalid.`。

參考錯誤發生位置：

```csharp
// 來源:Runtime/Mono/MonoComponent.cs
private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76)

### 2. 檢查腳本執行順序

`MonoComponent.Start()` 會在所有元件 `Awake` 之後才執行，但若專案自訂了 Script Execution Order 把 `MonoComponent` 提前，可能會拿到尚未註冊到 `GameEntry` 的 `EventComponent`。

1. Edit → Project Settings → Script Execution Order。
2. 把 `MonoComponent` 拖曳到 `Default Time` 之後，或明確指定一個晚於 `EventComponent` 的 Order 值。
3. 重新執行驗證。

### 3. 檢查重複掛載或場景殘留

如果同一個 GameObject 上被手動新增了多個 `EventComponent`,或者舊場景裡殘留了舊的 `EventComponent` 而新程式碼在另一個物件上實例化了它，`GameEntry.GetComponent` 會因為類型重複而回傳空引用。

1. 在 Hierarchy 中搜尋 `t:EventComponent`,確認只有一處實例。
2. 刪除多餘實例後再次執行。

## 驗證

1. 執行場景，開啟 Console,搜尋 `Event manager is invalid.`,應不再出現。
2. 在 `MonoComponent` 所在物件上掛一個測試腳本，在 `Start` 中呼叫 `GameEntry.GetComponent<EventComponent>()` 並斷言非空。
3. 完整執行一次事件訂閱/發布流程(`Subscribe` → `Fire` → `Unsubscribe`),確認事件能正常送達監聽者。

## 背景(可選)

`MonoComponent` 把 `EventComponent` 的引用快取在 `m_EventComponent` 欄位，後續 `OnApplicationFocus` 等生命週期回呼都會重複使用它。一旦 `Start` 階段拿不到引用，欄位會維持 null,後續事件相關的初始化會被靜默跳過——這也是為什麼錯誤只出現一次、但功能卻不正常運作的原因。

關於 Mono 模組的整體接入流程，見《如何接入 Mono 模組》。
