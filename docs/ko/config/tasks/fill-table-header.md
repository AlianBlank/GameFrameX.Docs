# 표 헤더와 필드 타입 작성 방법

각 데이터 테이블(`Excels/Tables/` 위치)의 처음 4행은 고정된 「헤더」로, 이 표에 어떤 필드가 있는지, 각 필드가 어떤 타입인지 도구에 알려주는 역할을 합니다. 아래에서 행별로 무엇을 작성하고, 어떤 필드 타입을 선택할 수 있는지 안내합니다.

## 사전 조건

- `Excels/Tables/` 아래에 데이터 테이블을 새로 만들어 두어야 합니다(네이밍 규칙은 《표 이름 짓는 방법》 참조).
- Excel / WPS / Numbers로 해당 `.xlsx` 파일을 엽니다.

## 작업 단계

1. **처음 4행의 위치 확인**: 각 테이블의 1~4행은 헤더이며, 5행부터 데이터를 작성합니다.
2. **1행 `##var` 작성**: 2열부터 각 칸에 영어 **필드명**을 하나씩 작성합니다(예: `id`, `name`, `price`). 이 이름들은 생성된 코드의 속성명이 됩니다.
3. **2행 `##type` 작성**: 필드명과 일대일로 대응하여 해당 필드의 **타입**을 작성합니다(사용 가능한 타입은 아래 표 참조).
4. **3행 `##group` 작성**: 필드 그룹으로, 일반적으로 비워 두면 됩니다.
5. **4행 `##` 작성**: 한국어 설명을 작성하며, 사람이 보기 위한 것일 뿐 생성 결과에는 영향을 주지 않습니다.
6. **5행부터 실제 데이터 작성**: 한 칸에 하나의 값을 `##type` 행의 타입에 맞게 작성합니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L97-L131)

작성하면 다음과 같이 됩니다(아이템 테이블 예시):

| ##var    | id    | name   | price |
|----------|-------|--------|-------|
| ##type   | int   | text   | int   |
| ##group  |       |        |       |
| ##       | 아이템ID | 아이템명 | 가격  |
| （데이터） | 10001 | diamond | 10   |

> 이 네 행의 첫 번째 칸(`##var`, `##type`, `##group`, `##`)은 고정 마커이므로 반드시 그대로 작성하고, 다른 단어로 바꾸지 마십시오.

## 자주 사용하는 필드 타입

| 타입      | 의미                                   | 데이터 예시                  |
|-----------|----------------------------------------|---------------------------|
| `int`     | 정수                                   | `10001`                   |
| `long`    | 큰 정수                                 | `9999999999`              |
| `float`   | 소수                                   | `1.5`                     |
| `double`  | 고정밀 소수                             | `3.14159`                 |
| `bool`    | 예/아니오                                  | `true` / `false`          |
| `string`  | 일반 텍스트(번역 안 함)                     | `icon_diamond`            |
| `text`    | 다국어 텍스트(key를 작성, 텍스트는 `Local/`에 있음)  | `diamond`                 |
| `vec2`    | 2차원 좌표, 쉼표로 두 개의 float 구분           | `1.0,2.0`                 |
| `vec3`    | 3차원 좌표, 쉼표로 세 개의 float 구분           | `1.0,2.0,3.0`             |
| `vec4`    | 4차원 좌표, 쉼표로 네 개의 float 구분           | `1.0,2.0,3.0,4.0`         |
| 열거형 이름    | `__enums__.xlsx`에서 정의된 타입     | `ItemType`                |
| bean 이름   | `__beans__.xlsx`에서 정의된 구조체   | `Reward`                  |

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L212-L223)、[Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml#L2-L36)

> `vec2/vec3/vec4`는 클라이언트에서 `UnityEngine.Vector2/3/4`로 매핑되고, 서버에서는 `System.Numerics.Vector2/3/4`로 매핑되어 양쪽 모두에서 바로 사용할 수 있습니다.

## 일반적인 변형

**1. 필드명을 한국어로 작성? 불가능**
필드명은 반드시 영어여야 합니다(`##var` 행). 그렇지 않으면 코드 생성 시 *「중국어 테이블명/필드명은 지원하지 않음」* 오류가 발생합니다.

**2. 다국어 텍스트를 사용하고 싶을 때**
`##type`을 `text`로 설정하고, 데이터 칸에 key(예: `diamond`)를 작성한 후, `Excels/Local/` 아래의 로컬라이제이션 테이블에 `diamond = 다이아몬드/ダイヤ…`와 같이 작성합니다. `text`와 `string`의 차이: `text`는 번역이 필요하고, `string`은 번역하지 않습니다.

**3. 열거형 / 구조체를 사용하고 싶을 때**
먼저 `Excels/__enums__.xlsx` 또는 `__beans__.xlsx`에서 타입을 정의한 후, `##type` 행에 정의된 이름(예: `ItemType`, `Reward`)을 바로 작성합니다.

**4. 특정 필드를 클라이언트 또는 서버 전용으로 만들고 싶을 때**
테이블 파일명에 그룹 마커를 추가합니다(`c` = 클라이언트, `s` = 서버). 필드 자체는 변화가 없으며, 테이블 전체가 해당 쪽으로만 내보내집니다.

## 자주 발생하는 오류

| 오류 현상                                              | 원인                                  | 해결 방법                                                |
|-------------------------------------------------------|---------------------------------------|-----------------------------------------------------|
| 생성 시 *「중국어 테이블명/필드명은 지원하지 않음」* 오류 발생                  | `##var` 행의 필드명에 중국어를 작성함              | 필드명을 영어로 바꾸고, 한국어 설명은 4행 `##`에 작성           |
| `text` 필드가 게임에서 원본 key(예: `diamond`)로 표시됨     | `Excels/Local/`에서 해당 언어의 번역문을 설정하지 않음 | 로컬라이제이션 테이블에서 key를 각 언어로 번역                      |
| `vec3` 필드 생성 시 오류 발생                                   | 불필요한 공백 또는 세미콜론을 작성함                    | 영어 쉼표로 엄격하게 구분: `1.0,2.0,3.0`                   |
| `##var` / `##type` 철자 오류(예: `##vars`)                | 헤더 마커는 반드시 그대로 작성해야 함                      | `##var`, `##type`, `##group`, `##`로 수정           |
| 데이터를 1행부터 작성함                                  | 헤더가 데이터로 덮어짐                        | 데이터를 5행부터 시작하도록 아래로 이동하고, 처음 4행은 반드시 헤더여야 함             |## 배경(선택 사항)

도구는 `.xlsx`를 읽을 때 처음 4행의 헤더만 확인하여 생성할 필드를 결정합니다. `##var`는 속성명을, `##type`은 C# 타입과 읽기/쓰기 방식을 결정하며, `##`은 주석일 뿐 생성에 참여하지 않습니다. `vec2/vec3/vec4` 등의 내장 타입의 크로스 플랫폼 매핑은 [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml)에서 제어하므로, Excel에는 간단한 숫자만 작성하면 서버/클라이언트 코드에서는 실제 `Vector3` 등의 구조체가 됩니다.
