# Subscribe to and Dispatch Events

Through the event pool `EventPool<T>`, any module can subscribe to and dispatch events in the form of "string ID + event arguments". It supports queuing and firing events on the main thread (`Fire`), as well as immediate synchronous firing (`FireNow`).

## Prerequisites

- Custom event arguments must inherit from `BaseEventArgs` and implement a unique string `Id` (used to distinguish event types).
- Obtain or create an `EventPool<T>` instance through the `EventPool` module. This tutorial assumes you can already get an `EventPool<MyEventArgs>`.
- The caller must ensure that `EventPool<T>.Update(elapseSeconds, realElapseSeconds)` is triggered in the game loop; otherwise, events in the `Fire` queue will not be dispatched.

## Steps

1. Define an event argument class that inherits from `BaseEventArgs` and provides a unique `Id`.

   ```csharp
   public class PlayerHpChangedEventArgs : BaseEventArgs
   {
       public string PlayerId { get; set; }
       public int NewHp { get; set; }

       public override string Id => "PlayerHpChanged";
   }
   ```

   Source: [BaseEventArgs.cs](/Runtime/Base/EventPool/BaseEventArgs.cs#L43-L54)

2. Subscribe to the event. During module initialization, call `Subscribe` to register the string event ID and the `EventHandler<T>` callback into the event pool.

   ```csharp
   eventPool.Subscribe("PlayerHpChanged", OnPlayerHpChanged);

   void OnPlayerHpChanged(object sender, PlayerHpChangedEventArgs e)
   {
       Debug.Log($"{e.PlayerId} HP -> {e.NewHp}");
   }
   ```

   The signature of `EventHandler<T>` comes from the type parameter of `EventPool<T>`.

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

3. Dispatch the event. Call `Fire` on the main thread to add the event to the queue. The event will be delivered to all subscribers on the next `Update`, and cross-thread `Fire` is also safe.

   ```csharp
   var args = ReferencePool.Acquire<PlayerHpChangedEventArgs>();
   args.PlayerId = "p_001";
   args.NewHp = 80;
   eventPool.Fire(this, args);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L304-L314)

4. Drive the event pool. The `Update` must be driven every frame to consume the nodes queued by `Fire`; after a node is processed, it is returned via `ReferencePool.Release`.

   ```csharp
   void Update()
   {
       eventPool.Update(0f, Time.deltaTime);
   }
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L113-L121)

5. Unsubscribe at an appropriate time to prevent the event pool from holding callbacks for objects that have already been destroyed.

   ```csharp
   eventPool.Unsubscribe("PlayerHpChanged", OnPlayerHpChanged);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L245-L281)

## Common Variations

- **Immediate synchronous dispatch**: When on the main thread and queuing is not required, you can call `FireNow`. The event will be delivered immediately to all subscribers within the current call stack, but it is not thread-safe.

  ```csharp
  eventPool.FireNow(this, args);
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L325-L336)

- **Set a default handler**: Register a fallback callback via `SetDefaultHandler`. It will be invoked when an event ID has no subscribers.

  ```csharp
  eventPool.SetDefaultHandler((sender, e) => Debug.Log($"Unhandled event:{e.Id}"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L290-L293)

- **Control subscription rules via event pool mode**: Pass an `EventPoolMode` into the constructor of `EventPool<T>` to decide whether multiple or duplicate subscribers are allowed.

  | Mode | Behavior |
  |------|------|
  | `EventPoolMode.Default` (0) | Must exist and can only have one subscriber |
  | `EventPoolMode.AllowNoHandler` (1) | Allows events with no subscribers |
  | `EventPoolMode.AllowMultiHandler` (2) | Allows multiple subscribers for the same event ID |
  | `EventPoolMode.AllowDuplicateHandler` (4) | Allows registering the same callback multiple times (must be combined with `AllowMultiHandler`) |

  Multiple flags can be combined using bitwise operations, e.g., `EventPoolMode.AllowMultiHandler | EventPoolMode.AllowDuplicateHandler`.

  Source: [EventPoolMode.cs](/Runtime/Base/EventPool/EventPoolMode.cs#L43-L77), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

- **Query subscriber count**: Read the subscriber count via `EventHandlerCount` or `Count(id)` for debugging or UI display purposes.

  ```csharp
  Debug.Log(eventPool.EventHandlerCount);
  Debug.Log(eventPool.Count("PlayerHpChanged"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L82-L91), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L164-L175)

## Common Errors

| Error | Symptom | Resolution |
|------|------|------|
| Calling `Subscribe`/`Unsubscribe`/`Check` with a `null` `handler` | Throws `GameFrameworkException("Event handler is invalid.")` | Ensure the callback is an instance method or a static delegate before registering; do not pass `null` |
| No subscribers for a `Fire` event and the mode does not enable `AllowNoHandler` | Throws "not allow multi handler." or falls back to the default handler | Add `EventPoolMode.AllowNoHandler` in the constructor as needed |
| Not calling `Update` to consume the queue | Events appear to "disappear" | Ensure the game loop drives `eventPool.Update(...)` every frame |
| Not calling `Unsubscribe` after object destruction | The event triggers a callback on a destroyed object, causing a null reference | Call `Unsubscribe` in `OnDestroy`/`OnDisable` |

## Background (Optional)

Internally, `EventPool<T>` uses a `ConcurrentQueue<EventNode>` to temporarily store events from `Fire`, then dequeues and dispatches them through a `GameFrameworkMultiDictionary<string, EventHandler<T>>` during `Update`; `_cachedNodes` supports "safe unsubscription during event handling". `Fire` is thread-safe (dispatched on the main thread on the next frame), while `FireNow` dispatches immediately and synchronously, suitable for latency-sensitive scenarios where call thread safety can be guaranteed.
