# Configuring Multilingual App Names

Declare `languageCode` and `validMap` (containing the `CFBundleDisplayName` key) for each language in the `localizations` array of the build configuration JSON. The post-build process will automatically generate `{languageCode}.lproj/InfoPlist.strings` in the Xcode project directory, add the files to the main target's Resources, and write `LSHasLocalizedDisplayName = true` into `Info.plist`, so that the iOS home screen shows the app name in the corresponding language under the icon.

## Prerequisites

- Unity has been switched to the iOS platform, and this package (`com.gameframex.unity.xcode`) is installed.
- The project has integrated the `PostProcessBuildHelper` post-build process — the localization logic is triggered uniformly by this process (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126), which reads the `localizations` field from the merged configuration).

## Steps

1. Add the `localizations` array to the iOS build configuration JSON (at the same level as fields such as `podInstall` and `capabilities`):

   ```json
   "localizations": [
     {
       "languageCode": "en",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "My Game" }
       ]
     },
     {
       "languageCode": "zh-Hans",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "我的游戏" }
       ]
     }
   ]
   ```

   Field descriptions:

   | Field | Type | Description |
   |------|------|------|
   | `localizations` | array | List of localization configurations, one entry per language |
   | `languageCode` | string | Language code, used as the `{languageCode}.lproj` directory name (e.g., `en.lproj`, `zh-Hans.lproj`); the entry is skipped if this is empty or missing |
   | `validMap` | array | List of key-value pairs, each containing `key` and `value`; the entry is skipped if this is empty or missing |
   | `key` | string | Info.plist key name; app name localization always uses `CFBundleDisplayName` |
   | `value` | string | Display text for that language |

   The structure of this example matches the `localizations` section in [README.zh-TW.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-TW.md#L323-L346); the field names of `languageCode` / `validMap` follow the actual reading logic in [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L52).

2. Run the iOS build. The post-build process automatically performs the following actions (no manual intervention required):

   ```csharp
   foreach (Hashtable loc in localizations)
   {
       ...
       // Create .lproj directory
       string lprojName = langCode + ".lproj";
       string lprojPath = Path.Combine(path, lprojName);
       if (!Directory.Exists(lprojPath))
       {
           Directory.CreateDirectory(lprojPath);
       }

       // Prepare InfoPlist.strings content
       StringBuilder sb = new StringBuilder();
       foreach (Hashtable map in validMap)
       {
           if (map.ContainsKey("key") && map.ContainsKey("value"))
           {
               string key = map["key"].ToString();
               string value = map["value"].ToString();
               sb.Append($"\"{key}\" = \"{value}\";\n");

               // Check whether CFBundleDisplayName is included
               if (key == "CFBundleDisplayName")
               {
                   hasLocalizedDisplayName = true;
               }
           }
       }
       ...
   }
   ```

   Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L91)

3. Check the generated results. The generated `en.lproj/InfoPlist.strings` content looks like this:

   ```text
   "CFBundleDisplayName" = "My Game";
   ```

   The output format is determined by `sb.Append($"\"{key}\" = \"{value}\";\n")`; see [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L62-L90).

## Common Variants

- **Localizing other Info.plist keys at the same time**: You can add more key-value pairs, such as permission descriptions, to `validMap`; they will be written into the same `InfoPlist.strings`:

  ```json
  "validMap": [
    { "key": "CFBundleDisplayName", "value": "我的游戏" },
    { "key": "NSCameraUsageDescription", "value": "需要访问相机用于扫描二维码" }
  ]
  ```

- **More languages**: Simply append entries to the `localizations` array; each language generates its own `.lproj` directory and `InfoPlist.strings` file.

- **Disabling localization**: Set `localizations` to an empty array `[]` or omit the field entirely; the post-build process returns directly without making any changes (see [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L20-L23)).

## Troubleshooting

| Symptom | Cause | Fix |
|------|------|------|
| No `.lproj` directory generated after the build | `localizations` is empty/not configured, or entries are missing `languageCode` / `validMap` | Verify the configuration made it into the final merged configuration and that every entry has a non-empty `languageCode` and a non-empty `validMap` (entries missing these are skipped by `continue`) |
| Only the permission description is localized; the home screen name is still in English | `CFBundleDisplayName` is not in `validMap` | App name localization must use the key `CFBundleDisplayName`, which is also the only condition that triggers `LSHasLocalizedDisplayName` |
| `InfoPlist.strings` is not in the Xcode project (display language falls back to the default) | The file was not added to the Resources build phase | The post-build process injects it with `project.AddFile(...)` + `project.AddFileToBuild(mainTargetGuid, fileGuid)`; see below. If you have manually deleted project files, run the build again |
| Build log shows `InfoPlist.strings not found at: ...` | Files in the `.lproj` directory were deleted by external scripts or not generated | Check whether other post-build scripts clean up the directory before localization runs, then rebuild |

## Background

Trigger chain: After merging configurations, `PostProcessBuildHelper` calls `RunLocalization(project, project.ProjectGuid(), path, finalConfig.Get("localizations") as ArrayList)` (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126)). After `RunLocalization` generates the files, once `CFBundleDisplayName` is detected it sets `LSHasLocalizedDisplayName` in `Info.plist` to `true` ([PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L97-L108)), after which `AddLocalizationToProject` adds each `InfoPlist.strings` to the main target's Resources and writes back `project.pbxproj`:

```csharp
// Add the file to the project using the PBXProject API
string fileGuid = project.AddFile(infoPlistStringsPath, infoPlistStringsPath, PBXSourceTree.Source);

// Add the file to the main target's Resources build phase
project.AddFileToBuild(mainTargetGuid, fileGuid);

LogHelper.Log($"Added localization file to project: {infoPlistStringsPath}");
```

Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L194-L205)
