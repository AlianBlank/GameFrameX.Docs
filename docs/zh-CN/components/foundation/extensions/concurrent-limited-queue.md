# 如何使用并发受限队列

`ConcurrentLimitedQueue<T>` 是一个线程安全的定长队列，当元素数量达到容量上限时按指定策略自动丢弃元素，并可在丢弃时通过回调通知调用方。

## 前置条件

- 引入 `GameFrameX.Foundation.Extensions` 命名空间。
- .NET 环境中可用（依赖 `System.Collections.Concurrent`）。

## 操作步骤

### 1. 创建指定容量的队列

传入最大长度，默认为 `DropOldest` 策略（满时移除最旧元素，加入新元素）。

```csharp
using GameFrameX.Foundation.Extensions;

var queue = new ConcurrentLimitedQueue<int>(limit: 3);
queue.Enqueue(1);
queue.Enqueue(2);
queue.Enqueue(3);
queue.Enqueue(4); // 此时 1 被自动移除，队列中剩 [2, 3, 4]
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L91-L110)

### 2. 选择溢出策略

通过 `LimitedQueueOverflowStrategy` 选择队列已满时的处理方式：

| 策略 | 行为 |
|------|------|
| `DropOldest` | 移除最旧元素，加入新元素（默认） |
| `DropNewest` | 丢弃新元素，队列保持不变 |
| `RejectNewItem` | 拒绝新元素，不触发丢弃通知 |
| `Throw` | 抛出 `InvalidOperationException` |

```csharp
var queue = new ConcurrentLimitedQueue<string>(limit: 2, LimitedQueueOverflowStrategy.DropNewest);
queue.Enqueue("a");
queue.Enqueue("b");
queue.Enqueue("c"); // "c" 被丢弃，队列中仍是 ["a", "b"]
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L245-L266)

### 3. 订阅丢弃事件

通过 `ItemDiscarded` 回调监听被丢弃的元素，可用于打点、记录日志或补偿处理。

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 2, LimitedQueueOverflowStrategy.DropOldest)
{
    ItemDiscarded = item =>
    {
        Console.WriteLine($"丢弃元素 {item.Item}, 原因 {item.Reason}");
    }
};
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L138-L140)

### 4. 调整容量上限

通过 `Limit` 赋值或 `SetLimit` 方法动态调整容量；缩容时被移除的元素会通过回调以 `LimitReduced` 原因通知。

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 5);
for (var i = 0; i < 5; i++) queue.Enqueue(i);

queue.SetLimit(2); // 移除多余元素，回调中 Reason 为 LimitReduced
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L276-L296)

### 5. 出队与查看

使用标准并发队列语义：`TryDequeue` / `TryPeek` / `ToArray` / `Clear` 均可使用。

```csharp
if (queue.TryPeek(out var head))
{
    Console.WriteLine($"队头: {head}");
}

if (queue.TryDequeue(out var first))
{
    Console.WriteLine($"出队: {first}");
}
```

## 常见变体

- **从已有集合初始化**：`new ConcurrentLimitedQueue<int>(new List<int> { 1, 2, 3 })` 或隐式转换 `ConcurrentLimitedQueue<int> q = new List<int> { 1, 2, 3 };`，容量自动设为集合大小。
- **作为 `IProducerConsumerCollection<T>` 使用**：可直接调用 `TryAdd` / `TryTake`，底层走 `TryEnqueue` / `TryDequeue`。
- **避免在回调中再操作同一队列**：`ItemDiscarded` 在内部锁外触发，回调内的入队/出队是安全的，但要避免长时间阻塞。

## 常见错误

| 错误 | 说明 |
|------|------|
| `limit <= 0` 时构造抛 `ArgumentOutOfRangeException` | 容量必须大于 0 |
| 传入空集合构造抛 `ArgumentOutOfRangeException` | 集合元素数必须大于 0 |
| `OverflowStrategy.Throw` 在满队入队时抛 `InvalidOperationException("The limited queue has reached its capacity.")` | 调用方需要捕获异常或改用其他策略 |
| 期望 `DropOldest` 在 `ItemDiscarded` 中触发但用了 `RejectNewItem` | `RejectNewItem` 不触发丢弃通知 |

## 背景（可选）

`ConcurrentLimitedQueue<T>` 内部封装了 `ConcurrentQueue<T>`，并使用独立的 `_syncRoot` 保护容量计数和入队溢出逻辑，使容量调整与入队策略判定在同一临界区内原子完成。底层 `ConcurrentQueue` 自身保证线程安全的元素存取。
