# What to Do When Hot Update Stalls, Download Fails, or Versions Are Inconsistent

When the hot update flow (based on YooAsset's HostPlayMode) gets stuck at a state, throws patch download errors, or the client version doesn't match the remote manifest, follow the table and steps on this page to locate and fix the issue.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Flow stuck at `UpdateStaticVersion` (failed to fetch remote `PackageVersion`) | `hostServerURL` is unreachable, or remote has not published `PackageVersion` file | See [Fix Steps §1](#fix-steps) |
| Flow stuck at `UpdateManifest` (manifest fetch failed) | `fallbackHostServerURL` not configured, manifest path incorrect, or `AppVersion` inconsistent with remote | See [Fix Steps §2](#fix-steps) |
| `CreateDownloader` is empty / no files to download | Local cache already covers current `PackageVersion`, or `AppVersion` mismatch causes no downloadable items in manifest | See [Fix Steps §3](#fix-steps) |
| `DownloadWebFiles` fails midway with individual file errors | Single file download failed; affected by `FailedTryAgain` and `VerifyLevel` | See [Fix Steps §4](#fix-steps) |
| Startup reports "Remote version incompatible with local" | Client `AppVersion` < remote minimum supported version | See [Fix Steps §5](#fix-steps) |

The `EPatchStates` enum values are defined as follows, used for log reference:

Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L32)

```csharp
public enum EPatchStates
{
    UpdateStaticVersion,
    UpdateManifest,
    CreateDownloader,
    DownloadWebFiles,
    PatchDone,
}
```

## Fix Steps

### §1 Stuck at UpdateStaticVersion

1. Check the passed-in `hostServerURL`, confirm it can be opened directly in a browser and returns the text `PackageVersion` (YooAsset default layout).
2. Confirm the build machine has published the asset bundle; the remote directory must at least contain `PackageVersion.txt` / `GameVersion.txt`.
3. If CDN is enabled, confirm the CDN origin address points to the actual asset server.

### §2 Stuck at UpdateManifest

1. `fallbackHostServerURL` (fallback address) must be provided. `HostPlayMode` initialization uses `RemoteServices` to pass both to YooAsset.

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L148-L164)

```csharp
private InitializationOperation InitializeYooAssetHostPlayMode(
    ResourcePackage resourcePackage,
    string hostServerURL,
    string fallbackHostServerURL)
{
    var remoteServices = new RemoteServices(hostServerURL, fallbackHostServerURL);
    var createParameters = new HostPlayModeParameters
    {
        BuildinFileSystemParameters = FileSystemParameters.CreateDefaultBuildinFileSystemParameters(),
        CacheFileSystemParameters   = FileSystemParameters.CreateDefaultCacheFileSystemParameters(remoteServices),
    };
    return resourcePackage.InitializeAsync(createParameters);
}
```

2. Confirm that client `AppVersion` is not higher than remote `GameVersion.txt` (YooAsset filters manifests by AppVersion).
3. Check the manifest URL returned by YooAsset in the logs; opening it manually in the browser should download `PackageManifest_{AppVersion}_{PackageVersion}.hash` and `.bytes`.

### §3 CreateDownloader Is Empty

1. If the cache was just cleared or this is the first install, this is expected behavior—skip the download and enter the game directly.
2. If it shouldn't be empty (there really are new assets), usually the wrong `AppVersion` causes incorrect manifest content; go back to §2 to check the version number.

### §4 DownloadWebFiles Failure

Download behavior can be adjusted through two parameters on `IAssetManager`:

Source: [IAssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L13-L41)

```csharp
/// Maximum number of simultaneous downloads.
int DownloadingMaxNum { get; set; }

/// Maximum number of retries on failure.
int FailedTryAgain { get; set; }

/// Gets or sets the file verification level.
EFileVerifyLevel VerifyLevel { get; }
```

1. Appropriately increase `DownloadingMaxNum` (the default is small; on high bandwidth it can be adjusted to 10~20).
2. Appropriately increase `FailedTryAgain` to avoid network jitter being judged as failure directly.
3. If a large number of CDN files return 404, first verify filenames against the build output directory; YooAsset's remote layout must match the build-time layout.
4. If files are suspected of being hijacked or corrupted, raise `VerifyLevel` to a higher level (determined by the `EFileVerifyLevel` enum); YooAsset will verify file hashes.

### §5 Remote Version Incompatible with Local

YooAsset validates `AppVersion` during the `UpdateManifest` phase; versions below the remote requirement will be rejected. Handling:

1. Raise the client `Player Settings.bundleVersion` or the version number passed in when calling `InitPackageAsync` to be `>=` the remote `GameVersion.txt`.
2. Rebuild and re-release; do not attempt to bypass on the old client.

## Verification

1. Observe that the progress callback completes through `UpdateStaticVersion → UpdateManifest → CreateDownloader → DownloadWebFiles → PatchDone` without skipping or freezing.
2. In the YooAsset cache directory (e.g., `Application.persistentDataPath/yooasset/{packageName}/`), you can see the `.bytes` / `.hash` cache files corresponding to this version.
3. After entering the game, all hot-updated assets load normally and no longer fall back to the built-in package.
