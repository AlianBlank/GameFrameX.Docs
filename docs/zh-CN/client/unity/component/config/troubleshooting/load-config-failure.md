# 配置加载失败怎么办

当通过 `ConfigComponent` 注册或读取全局配置时,如果出现 `LoadConfigFailureEventArgs`(事件编号为 `LoadConfigFailureEventArgs` 的完整类名),或调用 `GetConfig<T>()` 返回 `default`/`null`,通常意味着底层 `ConfigManager` 未拿到配置数据。本页帮助你快速定位原因并修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志打印 `Config manager is invalid.` | `ConfigComponent.Awake` 时未取到 `IConfigManager` 实现 | 见 [ConfigManager 未注入](#configmanager-未注入) |
| `GetConfig<T>()` 返回 `null` / `default(T)` | 资源加载成功但未通过 `Add` 注册到管理器,或资源名与类型名不匹配 | 见 [未注册到 ConfigComponent](#未注册到-configcomponent) |
| 收到 `LoadConfigFailureEventArgs`,`ErrorMessage` 含 `IOException` / 解析失败 | 配置二进制 / JSON 资源未生成或与代码不同步 | 见 [配置资源缺失或格式损坏](#配置资源缺失或格式损坏) |
| `HasConfig<T>()` 始终返回 `false` | 取名键使用了区分大小写比较(`StringComparer.Ordinal`) | 见 [配置名称大小写不匹配](#配置名称大小写不匹配) |

## 修复步骤

### ConfigManager 未注入

`ConfigComponent.Awake` 通过 `GameFrameworkEntry.GetModule<IConfigManager>()` 获取管理器实现。如果框架未注册 `ConfigManager`,会立即记录致命日志并直接返回,后续所有读写都无效。

[ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85) 中:

```csharp
protected override void Awake()
{
    m_ConfigNameTypeMap.Clear();
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IConfigManager);
    base.Awake();
    m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
    if (m_ConfigManager == null)
    {
        Log.Fatal("Config manager is invalid.");
        return;
    }
}
```

确认工程内已包含 `GameFrameX.Config.Runtime.ConfigManager` 程序集,并在引导阶段先于业务代码触发框架初始化(框架的 `[GameFrameXAutoComponent(-5000)]` 特性会保证它早于普通业务组件注册)。

### 未注册到 ConfigComponent

`ConfigComponent` 本身只负责"按名存取",**不**负责加载资源。读取配置前,必须把解析后的 `IDataTable` 显式塞进管理器:

```csharp
ConfigComponent.Instance.Add(typeof(MyConfig).Name, myDataTableInstance);
var cfg = ConfigComponent.Instance.GetConfig<MyConfig>();
```

[ConfigComponent.cs#L182-L185](/Runtime/Config/ConfigComponent.cs#L182-L185) 中:

```csharp
public void Add(string configName, IDataTable dataTable)
{
    m_ConfigManager.AddConfig(configName, dataTable);
}
```

如果跳过 `Add` 直接 `GetConfig<T>()`,`ConfigManager` 内部字典中无该键,返回 `default`,并触发 `LoadConfigFailureEventArgs`。

### 配置资源缺失或格式损坏

当你通过资源系统异步加载二进制/JSON 并反序列化为 `IDataTable` 时,如果文件不存在、版本不匹配或反序列化抛出异常,资源层会回调失败事件 `LoadConfigFailureEventArgs`,其字段含义如下:

[LoadConfigFailureEventArgs.cs#L43-L65](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L43-L65) 中:

```csharp
public sealed class LoadConfigFailureEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(LoadConfigFailureEventArgs).FullName;

    public LoadConfigFailureEventArgs()
    {
        ConfigAssetName = null;
        ErrorMessage = null;
        UserData = null;
    }

    public override string Id { get { return EventId; } }
    public string ConfigAssetName { get; private set; }
    public string ErrorMessage    { get; private set; }
    public object UserData        { get; private set; }
}
```

排查要点:

1. 在订阅事件时打印 `e.ConfigAssetName` 与 `e.ErrorMessage`,定位是哪个资源失败;
2. 重新导出/生成配置(确保 Excel/Lua/JSON 已重导,二进制已重新打包到 StreamingAssets 或 Addressables);
3. 如果配置结构体字段有变动,确认已重新生成代码与数据表,旧二进制将无法反序列化。

### 配置名称大小写不匹配

`ConfigManager` 在构造字典时使用了 `StringComparer.Ordinal`,即**严格区分大小写**且与文化无关:

[ConfigManager.cs#L58-L61](/Runtime/Config/ConfigManager.cs#L58-L61) 中:

```csharp
public ConfigManager()
{
    m_ConfigDatas = new ConcurrentDictionary<string, IDataTable>(StringComparer.Ordinal);
}
```

`ConfigComponent.GetTypeName<T>()` 用的是 `typeof(T).Name`,而你传入的 `configName` 若大小写不同则视为不同键。注册与查询时务必保持字符串完全一致。

## 验证

修复后,通过以下方式确认问题已解决:

1. `Log.Fatal("Config manager is invalid.")` 不再出现;
2. `HasConfig<T>()` 对目标类型返回 `true`;
3. `GetConfig<T>()` 返回非空实例,字段值与源数据一致;
4. 订阅 `LoadConfigFailureEventArgs.EventId`,不再收到任何失败事件。

```csharp
GameFrameworkEvent.Get().Subscribe(LoadConfigFailureEventArgs.EventId, (sender, e) =>
{
    var args = (LoadConfigFailureEventArgs)e;
    Log.Error($"配置加载失败: {args.ConfigAssetName} - {args.ErrorMessage}");
});
```
