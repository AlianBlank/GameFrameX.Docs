# Startup-Related Issues and Solutions

This page summarizes the most common errors and exceptions during the startup phase of `ProcedureComponent`. Fixes are provided based on the actual behavior of [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs) and [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs).

## Quick Diagnosis

| Symptom (original console output) | Cause | Fix |
|------|------|------|
| `Procedure manager is invalid.` | The framework failed to obtain `IProcedureManager` from `GameFrameworkEntry`, usually because `ProcedureComponent` is not attached or its `Awake` has not been executed. | See [Fix 1](#fix-1-procedure-manager-is-invalid) |
| `Available procedure type names is empty. Procedure auto start skipped.` | The `Available Procedure Type Names` array in the Inspector is empty. | See [Fix 2](#fix-2-available-procedure-type-names-is-empty) |
| `Can not find procedure type '{0}'.` | The type name string in `Available Procedure Type Names` does not match any `Type` in the current assembly. | See [Fix 3](#fix-3-can-not-find-procedure-type) |
| `Can not create procedure instance '{0}'.` | The type name was found, but the instance cannot be created via `Activator.CreateInstance` (abstract class / no public constructor). | See [Fix 4](#fix-4-can-not-create-procedure-instance) |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` does not appear in `Available Procedure Type Names`. | See [Fix 5](#fix-5-entrance-procedure-is-invalid) |
| `You must initialize procedure first.` | `StartProcedure` / `HasProcedure` / `GetProcedure` / `CurrentProcedure` / `CurrentProcedureTime` was called before `Initialize`. | See [Fix 6](#fix-6-you-must-initialize-procedure-first) |
| `Procedures is invalid.` | An empty array was passed when calling `m_ProcedureManager.Initialize(..., procedures)`. | See [Fix 7](#fix-7-procedures-is-invalid) |
| `Already exist FSM.` Re-enters the scene after startup | `Use Startup Runner` is enabled but the old logic of `ProcedureComponent` is still running, causing duplicate initialization by `ApplicationStartupEntry`. | See [Fix 8](#fix-8-already-exist-fsm) |

## Fix Steps

### Fix 1: Procedure manager is invalid

Executed in `ProcedureComponent.Awake`:

```csharp
m_ProcedureManager = GameFrameworkEntry.GetModule<IProcedureManager>();
if (m_ProcedureManager == null)
{
    Log.Fatal("Procedure manager is invalid.");
    return;
}
```

Troubleshooting:

1. Confirm that a GameObject with `ProcedureComponent` attached exists in the scene. The component menu path is `GameFrameX/Procedure`.
2. Confirm that `GameFrameworkEntry` has been initialized properly (other `GameFrameworkComponent` instances are also attached and have executed `Awake`).
3. Check whether any other component has registered an `IProcedureManager` implementation, causing the interface to be occupied — only one implementation is allowed per interface.
4. When handling IL2CPP / stripping, the `[Preserve]` attribute has been declared on the manager class. If it is still lost, check whether your own `link.xml` covers `GameFrameX.Procedure.Runtime`.

### Fix 2: Available procedure type names is empty

Check in `ProcedureComponent.Start`:

```csharp
if (m_AvailableProcedureTypeNames == null || m_AvailableProcedureTypeNames.Length <= 0)
{
    Log.Warning("Available procedure type names is empty. Procedure auto start skipped.");
    yield break;
}
```

Fix: Fill in the `Available Procedure Type Names` array in the Inspector with the full names of the procedure classes (namespace + class name), at least one entry.

### Fix 3: Can not find procedure type

Corresponding code:

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

Fix:

1. The string must exactly match `Type.FullName`, for example `GameFrameX.Procedure.Runtime.ProcedureLaunch`.
2. If the procedure class is in a custom assembly, confirm that the assembly has been loaded (Build Settings → Player Settings → even when "Disable Domain Reload" is unchecked, ensure the code has been compiled into the project).
3. This is most often triggered when you rename / move the namespace and forget to sync the Inspector. After changing a class name, always go back to the Inspector to update the string.

### Fix 4: Can not create procedure instance

Corresponding code:

```csharp
procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

Fix: Ensure that the procedure class is `public`, has a public parameterless constructor, and is neither abstract nor an interface. The standard pattern for `ProcedureBase`:

```csharp
public sealed class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
    }
}
```

### Fix 5: Entrance procedure is invalid

Matching the entrance procedure in `Start`:

```csharp
if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

If `m_EntranceProcedure` is still `null` after the loop ends, `Entrance procedure is invalid.` is output. Fix: Set the `Entrance Procedure Type Name` field to **exactly** one of the entries in `Available Procedure Type Names`.

### Fix 6: You must initialize procedure first

Several members of `ProcedureManager` throw this exception when `m_ProcedureFsm == null`, for example:

```csharp
public ProcedureBase CurrentProcedure
{
    get
    {
        if (m_ProcedureFsm == null)
        {
            throw new GameFrameworkException("You must initialize procedure first.");
        }
        return (ProcedureBase)m_ProcedureFsm.CurrentState;
    }
}
```

Trigger conditions: Any of `CurrentProcedure` / `CurrentProcedureTime` / `StartProcedure` / `HasProcedure` / `GetProcedure` is called before `Initialize`.

Fix:

1. By default, `ProcedureComponent.Start` will automatically call `Initialize` + `StartProcedure`, so you don't need to call them manually.
2. If you hold an `IProcedureManager` yourself and access it first, call `Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)` before accessing other members.
3. When `Use Startup Runner` is enabled, the component's `Start` will not auto-start the procedure — in this case, `ApplicationStartupEntry` / `StartupRunner.Run` is responsible for initialization. Make sure it actually runs.

### Fix 7: Procedures is invalid

Pre-check in `ProcedureManager.Initialize`:

```csharp
if (procedures.Length <= 0)
{
    throw new GameFrameworkException("Procedures is invalid.");
}
```

Fix: Do not pass an empty array to `Initialize`. Pass at least one `ProcedureBase` instance.

### Fix 8: Already exist FSM

When `Use Startup Runner = true`, `ProcedureComponent.Start` exits immediately:

```csharp
if (m_UseStartupRunner)
{
    yield break;
}
```

This branch exists precisely to avoid duplicate `Initialize` with `ApplicationStartupEntry` + `StartupRunner.Run`, which would trigger `Already exist FSM` (the same `IProcedureManager` holder has `CreateFsm` called on it repeatedly).

Fix: Choose one of the two — do not mix them:

- Old mode: `Use Startup Runner = false`, relying on the Inspector array to auto-start.
- New mode: `Use Startup Runner = true`, where `ApplicationStartupEntry` takes over the startup flow via `StartupRunner.Run`.

## Verification

After applying the fixes above, you can confirm the issue is resolved by:

1. Re-enter Play Mode. The corresponding error no longer appears in the console, and `ProcedureComponent.CurrentProcedure` is not `null`.
2. Add a log in the `OnEnter` of the first procedure (e.g., `ProcedureLaunch`). Confirm the log appears, indicating `StartProcedure` has actually taken effect.
3. Call `ChangeState<ProcedureXxx>()` in the second procedure and observe whether the state transition behaves as expected, verifying that the entire FSM has been initialized correctly.
4. If `Use Startup Runner` is enabled, confirm that `ApplicationStartupEntry` actually calls `StartupRunner.Run` and passes in your entrance procedure type, otherwise the procedure will never start (only `Awake` will register the manager).
