# 빌드 매크로 및 조건부 컴파일 심볼 설명

이 페이지는 GameFrameX 프레임워크가 소스 코드, Assembly Definition 및 Unity Player Settings에서 실제로 사용하는 **빌드 매크로 / 조건부 컴파일 심볼**을 요약하며, 각 심볼의 적용 플랫폼, 정의 위치, 그리고 프로젝트에서 활성화하거나 감지하는 방법을 설명합니다.

> `UNITY_` 접두사가 붙은 모든 심볼은 Unity 엔진에 의해 자동으로 주입됩니다. 프레임워크에서 직접 정의한 심볼(예: `ENABLE_GAME_FRAME_X_HYBRID_CLR`)은 `asmdef`의 `versionDefines`를 통해 자동으로 주입됩니다.

## 심볼 빠른 참조 표

| 심볼 | 범위 | 정의 출처 | 용도 |
|------|--------|----------|------|
| `UNITY_EDITOR` | Editor 어셈블리 | Unity 자동 주입 | 에디터에서만 적용되는 코드 블록 |
| `UNITY_ANDROID` | Android 플랫폼 | Unity 자동 주입 | Android 플랫폼 특화 로직 |
| `UNITY_IOS` | iOS 플랫폼 | Unity 자동 주입 | iOS 플랫폼 특화 로직 |
| `UNITY_STANDALONE` | 독립 플랫폼(Win/Mac/Linux) | Unity 자동 주입 | 데스크톱 특화 로직 |
| `UNITY_2018_1_OR_NEWER` | 버전 감지 | Unity 자동 주입 | 버전 호환 분기 |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` | HybridCLR 핫업데이트를 활성화하는 어셈블리 | `versionDefines`(`com.code-philosophy.hybridclr` 패키지 감지) | HybridCLR 통합과 관련된 코드 경로 제어 |

> 전체 Unity 플랫폼/버전 매크로 목록은 Unity 공식 문서를 참조하세요(런타임 심볼은 소스 코드에 나타나지 않지만 컴파일러가 자동으로 인식합니다).

## 프레임워크 커스텀 심볼: ENABLE_GAME_FRAME_X_HYBRID_CLR

이 심볼은 프레임워크 레벨에서 현재 `asmdef`의 `versionDefines`를 통해 주입되는 **유일한** 커스텀 매크로입니다. 프로젝트에 `com.code-philosophy.hybridclr` 패키지가 설치되면, Unity는 자동으로 `GameFrameX.Startup.Application` 어셈블리에 이 매크로를 주입하여 HybridCLR 핫업데이트와 관련된 코드 경로를 활성화합니다.

```json
{
    "name": "GameFrameX.Startup.Application",
    "references": [
        "GameFrameX.Runtime",
        "HybridCLR.Runtime",
        "HybridCLRData"
    ],
    "versionDefines": [
        {
            "name": "com.code-philosophy.hybridclr",
            "expression": "",
            "define": "ENABLE_GAME_FRAME_X_HYBRID_CLR"
        }
    ]
}
```

출처: [Unity.Startup.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Unity.Startup.asmdef#L33-L39)

### 사용 예제

```csharp
using UnityEngine;

namespace GameFrameX
{
    public static class HotUpdateGate
    {
        public static bool IsHotUpdateSupported
        {
            get
            {
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
                return true;
#else
                return false;
#endif
            }
        }
    }
}
```

### 매크로 적용 여부 검증

Unity에서 메뉴 **Window → General → Test Runner**를 실행하거나 임의의 스크립트에서 리플렉션으로 읽어 확인할 수 있습니다.

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
    Debug.Log("HybridCLR이 활성화되어 있어 핫업데이트 코드가 핫업데이트 어셈블리로 들어갑니다.");
#else
    Debug.LogWarning("HybridCLR이 활성화되지 않아 Startup은 AOT 방식으로 실행됩니다.");
#endif
```

*HybridCLR이 활성화되었습니다*라는 메시지가 출력되면, `ENABLE_GAME_FRAME_X_HYBRID_CLR`이 성공적으로 주입된 것입니다.

## 플랫폼 매크로의 실제 사용법

### Android 플랫폼 특화 설정

`ProjectSettingEditor.cs`는 Android 플랫폼에서 안전 영역 제한을 비활성화하고 팀 ID 플레이스홀더를 기록합니다. Android가 아닌 플랫폼에서는 해당 분기가 컴파일러에 의해 제거됩니다.

```csharp
public override void OnInspectorGUI()
{
    base.OnInspectorGUI();
    PlayerSettings.assemblyVersionValidation = false;
#if UNITY_ANDROID
    PlayerSettings.Android.renderOutsideSafeArea = true;
#endif
#if UNITY_IOS
    PlayerSettings.iOS.appleDeveloperTeamID = "XXXXXX";
#endif
}
```

출처: [ProjectSettingEditor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/ProjectSettingEditor/ProjectSettingEditor.cs#L28-L52)

### 버전 호환 분기

`AutoCopySymbolsPostprocessor.cs`는 `UNITY_2018_1_OR_NEWER`를 사용하여 32비트 x86 아키텍처 처리 로직을 차단합니다(Unity 2018.1부터 Android x86 빌드를 더 이상 지원하지 않음).

```csharp
#if UNITY_2018_1_OR_NEWER

#else
    if ((PlayerSettings.Android.targetArchitectures & AndroidArchitecture.X86) > 0)
    {
        var dir = CopySymbols(symbolsDir, abi_x86);
        GenerateAllSymbols(dir);
    }
#endif
```

출처: [AutoCopySymbolsPostprocessor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/AutoCopySymbolsPostprocessor.cs#L46-L54)

## 플랫폼 레벨 어셈블리 격리

`includePlatforms` / `excludePlatforms`는 해당 플랫폼 빌드에 어셈블리가 참여하는지 여부를 제어하며, **추가 매크로는 필요하지 않습니다**.

| 어셈블리 | includePlatforms | 효과 |
|--------|------------------|------|
| `Unity.Editor` | `["Editor"]` | 에디터 빌드에만 포함되며, 플레이어 패키지에는 포함되지 않음 |
| `Unity.Startup` / `Unity.HotFix` / `HybridCLRData` | `[]`(전체) | 모든 플랫폼 빌드에 참여 |

출처: [Unity.Editor.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/Unity.Editor.asmdef#L11-L13)

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Android 기기에서 x86 lib 파일이 남아 있음 | 더 이상 사용되지 않는 `UNITY_2018_1_OR_NEWER` 이전 경로가 활성화됨 | Unity를 2018.1 이상으로 업그레이드하여 매크로가 x86 처리를 올바르게 제거하도록 함 |
| HotFix 어셈블리가 빌드에 참여하지 않음 | `UNITY_HOTFIX` 등 오래된 매크로를 잘못 사용 | 현대적인 HybridCLR 주입 방식인 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 또는 `includePlatforms` 설정을 사용 |
| 플레이어 패키지에 Editor 도구 코드가 여전히 포함됨 | `Unity.Editor` 어셈블리의 `includePlatforms`가 Editor로 설정되지 않음 | `.asmdef`에서 `"includePlatforms": ["Editor"]`를 명시적으로 선언 |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR`이 항상 정의되지 않음 | HybridCLR 패키지가 설치되지 않았거나 패키지 이름의 철자가 잘못됨 | Package Manager에서 `com.code-philosophy.hybridclr`가 설치되었는지 확인하고, `asmdef`의 `versionDefines.name` 철자가 일치하는지 확인 |

## 커스텀 빌드 매크로 추가

1. 해당 `.asmdef`를 열고 루트 레벨에 `defineConstraints` 또는 `versionDefines`(패키지 관리 제어를 받는 경우)를 추가합니다.
2. 전역적으로 적용해야 하는 경우(패키지 관리 제어와 무관), **Edit → Project Settings → Player → Other Settings → Scripting Define Symbols**를 사용합니다.
3. C# 코드에서 표준 `#if SYMBOL_NAME ... #endif` 구문으로 참조합니다. Unity는 빌드 시 현재 대상 플랫폼에 맞지 않는 분기를 자동으로 제거합니다.
