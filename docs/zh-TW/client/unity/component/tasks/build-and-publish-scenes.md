# 如何建置與發佈 Launcher / LauncherAuto 場景

本頁面說明 GameFrameX.Unity 中 `Assets/Scenes/Launcher.unity` 和 `Assets/Scenes/LauncherAuto.unity` 兩個啟動場景的建置與發佈要點，包括它們在 Build Settings 中的索引位置、所承載的 UI 元件，以及發佈到獨立平台時的常見處理。

## 前置條件

- 已安裝 Unity Editor(與儲存庫 `ProjectSettings/` 中宣告的版本一致)。
- 專案已透過 Unity Hub 開啟，目錄中存在 `Assets/Scenes/Launcher.unity` 和 `Assets/Scenes/LauncherAuto.unity` 兩個場景檔案。
- 已安裝 GameFrameX 框架執行階段，場景中預製的 `UILauncher` 元件腳本可用。

## 操作步驟

### 1. 開啟 File → Build Settings

在 Unity 選單列選擇 `File` → `Build Settings`,在 `Scenes In Build` 清單中確認 `Launcher` 與 `LauncherAuto` 已被加入，且 `Launcher` 通常作為索引 0 的首個啟動場景。

### 2. 驗證場景檔案存在

確認以下兩個檔案在專案中存在，這是後續建置產物能包含啟動場景的前提：

- [Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity)
- [Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity)

### 3. 檢查 Launcher 場景中的 UILauncher 元件

`Launcher.unity` 中掛載了 `UILauncher` 腳本元件，負責啟動器 UI 與版本偵測邏輯。檔案中保留了元件參考：

```yaml
propertyPath: m_Name
value: UILauncher
```

參考來源:[Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity#L1158)

開啟場景後，在 Hierarchy 頂部 GameObject 上應能看到 `UILauncher` 元件，欄位包括版本號、熱更新位址、伺服器清單等。若欄位為空，需先在 Inspector 設定好再發佈。

### 4. 處理 LauncherAuto 場景的 Build Settings

`LauncherAuto.unity` 內部以 YAML 形式宣告了自身的 `m_BuildSettings` 段(序列化版本 3),Unity 依據此段記錄場景參與建置的開關以及光照/Lightmap 設定。直接開啟檔案可看到：

```yaml
m_BuildSettings:
  serializedVersion: 3
```

參考來源:[Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity#L105-L107)

若需要在 Build Settings 中停用該場景，可在 `m_BuildSettings` 下調整 `m_Scenes` 參考或直接在 Unity 編輯器中取消勾選。

### 5. 選擇目標平台並建置

在 Build Settings 中選擇目標平台(Windows、Android、iOS、macOS 等)，點擊 `Build` 或 `Build And Run`。Unity 會按 `Scenes In Build` 中的順序，把 `Launcher` 與 `LauncherAuto` 一併打包到 Player 二進位中。

### 6. 驗證產物

建置完成後，在輸出目錄檢查：

- 可執行檔能正常啟動並進入 `Launcher` 場景；
- `LauncherAuto` 在設定自動跳過 UI 時被載入；
- 啟動器介面上的版本號、熱更新位址顯示正確。

## 常見變體

- **LauncherAuto 自動跳場景**：若希望啟動後直接進入業務場景而不是顯示 UI 啟動器，可在 Player Settings → 其他設定中啟用 `LauncherAuto`,該場景通常用於無 UI 的自動化啟動流程。
- **按平台裁剪場景**：對 WebGL 等弱平台，可以從 Build Settings 中移除 `LauncherAuto`,只保留 `Launcher`;反之對獨立用戶端可同時勾選。
- **替換 UILauncher 欄位**：不同發佈渠道使用不同的熱更新位址，在建置前臨時切換 `UILauncher` 腳本上的設定即可。

## 常見錯誤

- **建置後啟動黑屏**：通常是因為 `UILauncher` 元件欄位未設定(版本號、熱更新位址為空)，導致啟動器初始化失敗。
- **Scenes In Build 缺失場景**：手動加入新場景時，把 `Launcher` 或 `LauncherAuto` 從清單中移除，執行時會跳過啟動器直接報錯。
- **場景 GUID 衝突**：直接複製 .unity 檔案時若保留原 `m_SceneGUID`,會導致 Build Settings 參考錯亂，務必讓 Unity 重新匯入並產生新 GUID。

## 背景(可選)

`Launcher` 與 `LauncherAuto` 是 GameFrameX 的雙啟動場景組合:`Launcher` 提供帶 UI 的啟動器，負責版本檢查、熱更新與伺服器選擇;`LauncherAuto` 為後台或自動化啟動場景，跳過 UI 直接載入業務邏輯。`m_BuildSettings` 是 Unity 場景檔案中描述參與建置狀態的中繼資料段，被 Editor 與 Player 共同讀取。
