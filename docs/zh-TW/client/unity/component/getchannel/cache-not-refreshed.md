# 修改渠道設定後仍讀取到舊值時的處理方法

已修改 `application_config.txt`、AndroidManifest 的 meta-data 或 iOS 的 Info.plist,但 `BlankGetChannel.GetChannelName()` 仍返回舊值時，原因絕大多數不外乎兩種：一是行程內的靜態快取 `ChannelCache` 命中後不再重新讀取；二是設定在建置時已打包進套件，對已建置的應用程式而言修改磁碟檔案無效。

## 快速診斷

| 症狀 | 原因 | 解決 |
|------|------|------|
| 在 Editor/PC/WebGL 中修改了 `application_config.txt`,但 `GetChannelName()` 仍返回舊值 | 靜態字典 `ChannelCache` 命中時會直接返回，不會重新讀取檔案 | 結束 Play Mode 後再次進入(觸發腳本網域重新載入)，參見下方「清空行程內快取」 |
| 在 Editor 中修改檔案並重新啟動 Play Mode 後仍是舊值 | Unity 尚未重新匯入該 TextAsset,`Resources.Load` 仍返回舊資源 | 切換至 Editor 視窗等待重新匯入完成，或在該檔案上按右鍵執行 `Reimport` 後再進入 Play Mode |
| 建置(Standalone/WebGL)後修改設定檔，但 App 內渠道未變化 | `Resources/application_config.txt` 已在建置時固定於套件中 | 修改 `Assets/Resources/application_config.txt` 後重新建置並覆蓋安裝 |
| 在 Android 上修改了 AndroidManifest 的 meta-data 但未生效 | meta-data 已編譯進 APK,且首次讀取結果已存入快取 | 修改 manifest 後重新建置並安裝；執行階段無法更新 |
| iOS 重新建置後渠道仍為 `default` 或舊值 | `PostProcessBuildHandler` 僅在 Info.plist 中**不存在** `channel` 金鑰時才寫入，若已有值則跳過 | 在 Xcode 中刪除或修改 Info.plist 的 `channel` 金鑰後重新建置，參見下方 |
| iOS 上未設定金鑰時返回的不是 C# 端的 `default`,而是 `unknown` | 原生 `getChannelName` 在找不到金鑰時固定返回 `unknown` | 在 Info.plist 中加入對應的金鑰 |
| 設定值包含 `=` 導致讀入的值被截斷 | 解析時以 `=` 分割後只取第二個區段 | 避免在值中使用 `=`,參見下方「值被截斷的情況」 |

## 解決步驟

### 清空行程內快取(最常見的根本原因)

`GetChannelName` 首先會查詢靜態快取，一旦命中便立即返回，完全跳過之後的讀取邏輯：

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
{
    if (ChannelCache.TryGetValue(channelKey, out var value))
    {
        return value;
    }

    string channelName = defaultValue;
    ...
    ChannelCache[channelKey] = channelName;
    return channelName;
}
```

來源:[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98-L141)

快取字典為 `private static readonly`,且該儲存庫完全未提供清空快取的公開 API,因此**執行階段無法更新**，只能讓靜態欄位隨網域/行程一併重建：

1. 在 Editor 中：結束 Play Mode → 等待編譯/網域重新載入完成 → 再次進入 Play Mode 後讀取。
2. 實機/獨立執行版：結束應用程式行程後重新啟動(僅解決快取問題；若設定本身已包含在套件內部，則須依下方章節重新建置)。

另外請注意一個副作用：在 Editor/PC 分支中，首次讀取時會將 `application_config.txt` 的**所有** `key=value` 一次性寫入快取(參見 [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L107-L121))。因此修改檔案後，即使以其他 channelKey 查詢，取得的仍是首次載入時的舊內容。

### Editor/PC/WebGL:讓 Resources 重新載入

這些平台會讀取 `Resources.Load<TextAsset>("application_config")`,即 `Assets/Resources/application_config.txt`:

1. 確認檔案路徑為 `Assets/Resources/application_config.txt`(即使沒有副檔名也能載入，內容為逐行 `key=value`)。
2. 修改並儲存後，點擊 Unity 視窗以觸發重新匯入(或在檔案上按右鍵 → `Reimport`)。
3. 依照「清空行程內快取」重新啟動 Play Mode。
4. 已建置的套件：修改磁碟上的檔案無效，必須修改 `Assets/Resources/application_config.txt` 後重新建置。

### Android:修改 meta-data 後重新建置

Android 渠道透過原生類別的靜態呼叫取得，首次結果同樣會進入快取：

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

來源:[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

修改 AndroidManifest.xml 中對應的 meta-data 後，必須重新建置 APK/AAB 並覆蓋安裝；行程內不會自動更新。

### iOS:PostProcessBuild 的「跳過設定」處理

iOS 建置後處理僅在 Info.plist 中沒有 `channel` 金鑰時才寫入 `default`,若已有值則直接跳過：

```csharp
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

來源:[PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

若要變更渠道值：請直接修改或刪除 Xcode 專案 Info.plist 中的 `channel` 金鑰(刪除後會由此處理邏輯重新寫入)，再重新建置至實機。另請注意，原生層的預設返回值為 `unknown`:

```objc
char * getChannelName(char * channel_name) {
    NSString* channel_name_String=  [NSString stringWithUTF8String:channel_name];
    NSString* File = [[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"];
    NSMutableDictionary* dict = [[NSMutableDictionary alloc] initWithContentsOfFile:File];
    NSString * channel_value =  [dict objectForKey:channel_name_String];
    if (channel_value != nil) {
        return StringToCharArray(channel_value);
    }
    channel_value = @"unknown";
    return StringToCharArray(channel_value);
}
```

來源:[BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

### 值被截斷的情況：確認設定行格式

解析邏輯會將每一行以 `=` 分割，只取第二個區段並套用 `Trim()`:

```csharp
var split = line.Split(new string[] { "=" }, StringSplitOptions.RemoveEmptyEntries);
if (split.Length > 1)
{
    var key = split[0].Trim();
    var channelValue = split[1].Trim();
    ChannelCache[key] = channelValue;
}
```

來源:[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120)

`channel=a=b` 會被解析為 `a`。請從值中移除 `=`(或改用其他分隔字元的編碼方式)，並依照「清空行程內快取」重新啟動後再次確認。

## 驗證

1. 修改設定並重新啟動 Play Mode / 重新建置後，呼叫以下程式碼：

```csharp
string channel = BlankGetChannel.GetChannelName();
string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
```

來源:[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

2. 確認返回值與設定檔的新值一致；在 iOS 上沒有金鑰時應觀察到 `unknown`(而非 C# 預設參數 `default`)。
3. 若仍是舊值，請先懷疑快取未被清空(重新啟動 Play Mode / 行程)，接著懷疑實際讀取的設定與預期不同(Editor 請確認 `Assets/Resources/application_config.txt`,Android 請確認 manifest meta-data,iOS 請確認 Info.plist)。
