# 启动流程卡在 ProcedureLauncherState 怎么办

当 `StartupRunner.RunAsync` 已经把启动链推进到 `ProcedureLauncherState`,但界面不出现、流程不切换到 `ProcedureGetGlobalInfoState`(整个启动 Promise 永远 `Pending`)时,问题几乎都出在 FSM 黑板数据、UI 资源、或 `WebComponent` 初始化上。本页给出快速诊断与对应的修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动后黑屏,日志中只看到进入 `ProcedureLauncherState`,`ChangeState<ProcedureGetGlobalInfoState>` 未执行 | `BlackBoardKeys.StartupOptions` 或 `BlackBoardKeys.StartupUIHandler` 为空,`OnEnter` 提前 `return` | 见下方"修复 1:FSM 黑板数据缺失" |
| 启动界面一闪而过或根本不出现,卡在启动页 | `IStartupUIHandler.StartAsync` 抛异常或挂起 | 见下方"修复 2:UI Handler 启动失败" |
| 启动到 Launcher 阶段时控制台报 `WebComponent` 相关空引用 | `GameEntry.GetComponent<WebComponent>()` 返回 `null`,Web 模块未注册 | 见下方"修复 3:WebComponent 未注册" |
| 流程卡住且从未进入 `OnEnter` | `procedureManager.StartProcedure<ProcedureLauncherState>()` 之前 FSM 没有正确注入数据,或 `StartupOptions.LauncherUIResName` 路径错误 | 见下方"修复 4:LauncherUIResName 资源路径错误" |
| 启动链路只跑到 Launcher,但 `UniTaskCompletionSource` 没有 SetResult | 后续 Procedure 在 Launcher 之后才负责 `SetResult`,Launcher 自身只切换状态 | 见下方"修复 5:等待后续 Procedure 完成" |

## 修复步骤

### 修复 1:FSM 黑板数据缺失

`ProcedureLauncherState.OnEnter` 会从 FSM 黑板读取 `StartupOptions` 和 `IStartupUIHandler`,二者任一为 `null` 都会导致方法直接 `return`,既不切换状态也不报错:

```csharp
// 来源: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var options = optionsBox.Value as StartupOptions;
var uiHandler = uiHandlerBox.Value as IStartupUIHandler;

if (options == null || uiHandler == null)
{
    return; // 直接退出,流程卡住,无异常
}
```

确认 `StartupRunner.RunAsync` 在调用 `StartProcedure<ProcedureLauncherState>` 之前确实传入了非空的 `options` 与 `uiHandler`:

```csharp
// 来源: Runtime/Startup/StartupRunner.cs
procedureFsm.SetData(BlackBoardKeys.StartupOptions, optionsBox);
procedureFsm.SetData(BlackBoardKeys.StartupUIHandler, uiHandlerBox);
```

如果你是自行组装启动链(未走 `StartupRunner`),需要在调用 `StartProcedure<ProcedureLauncherState>()` 前用同样的 key 注入数据,见 [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs)。

### 修复 2:UI Handler 启动失败

`OnEnter` 在 `await uiHandler.StartAsync(options.LauncherUIResName)` 处会真正等待 UI 加载完成。如果 `IStartupUIHandler` 实现里抛出异常,异常会被 `async void` 吞掉,流程卡死;如果挂起(例如 Addressables 资源未就绪),同样不会切到下一态。

排查顺序:

1. 在自定义 `IStartupUIHandler.StartAsync` 入口加 `try/catch`,至少把异常打到日志,确认是否真的抛了。
2. 在 Editor 下临时把 `LauncherUIResName` 指向一个已确认存在的 Prefab/Asset,排除资源路径错误。
3. 如果你用了 `UniTaskCompletionSource`,确认它在 `StartAsync` 内部被 `TrySetResult`,而不是遗忘 `await`。

### 修复 3:WebComponent 未注册

`ProcedureLauncherState` 在切换状态前需要从 `WebComponent` 读写 Header,如果模块没注册,`GameEntry.GetComponent<WebComponent>()` 返回 `null`,下一行 `webComponent.RemoveBaseHeader(...)` 立刻 NRE:

```csharp
// 来源: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var webComponent = GameEntry.GetComponent<WebComponent>();
webComponent.RemoveBaseHeader(StartupProcedureUtility.GameFrameXApiKeyHeader);
// ...
```

在 `GameEntry` 的模块注册流程里确认 `WebComponent` 已加入组件表,且运行时调用顺序早于 `StartupRunner.RunAsync` 发起。

### 修复 4:LauncherUIResName 资源路径错误

`options.LauncherUIResName` 必须指向一个有效的 UI 预制体或资源地址。资源不存在时,大多数 `IStartupUIHandler` 实现会进入"等资源加载"的死循环,而不会主动失败。验证方法:

1. 在 `StartupOptions` 构造时打印 `LauncherUIResName`,与 Addressables Groups / Resources 目录中的实际键对照。
2. 先用 `EPlayMode.EditorSimulateMode` + 已知存在的资源跑一遍启动流程,排除打包/分组问题。

### 修复 5:等待后续 Procedure 完成

`ProcedureLauncherState` 自身的职责只是"加载启动 UI → 切到下一态",并不会调用 `UniTaskCompletionSource.SetResult`。如果你观察到的"卡住"实际上是 `StartupRunner.RunAsync` 返回的 `UniTask<StartupResult>` 一直 `Pending`,请检查 `ProcedureGetGlobalInfoState` 及后续 Procedure 是否在最终成功/失败时执行了 `StartupProcedureUtility.GetCompletionSource(fsm).TrySetResult(...)`。

参见 [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs) 中 `GetCompletionSource` 的实现确认取到的就是 `StartupRunner` 注入到 `BlackBoardKeys.StartupCompletionSource` 的那个 `UniTaskCompletionSource`。

## 验证

修复后按下列顺序确认链路通畅:

1. 启动后日志能看到 `ProcedureLauncherState.OnEnter` 进入,紧接着 `ProcedureGetGlobalInfoState.OnEnter` 也进入,而不是只看到前者。
2. `StartupRunner.RunAsync` 返回的 `UniTask<StartupResult>` 在合理时间内(通常几秒)完成,而不是一直 `Pending`。
3. 控制台不再出现 `WebComponent` 空引用或 UI 资源加载失败的报错。
4. 如果使用了自定义 `IStartupUIHandler`,断点确认 `StartAsync` 在 `LauncherUIResName` 对应资源就绪后返回,且返回后调用栈能回到 `ProcedureLauncherState` 的 `ChangeState<ProcedureGetGlobalInfoState>`。
