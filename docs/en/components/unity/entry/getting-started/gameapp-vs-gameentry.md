# How to Choose Between the Two Access Methods: GameApp and GameEntry

GameFrameX provides two ways to access framework components: `GameEntry` is the low-level entry point of the component container (provided by the `GameFrameX.Runtime` package), while `GameApp` is a "static facade" built on top of `GameEntry` by this repository, exposing commonly used components as properties. Simply put: business code calls `GameApp.XXX`, and `GameApp` internally routes everything through `GameEntry.GetComponent<XXXComponent>()`.

## Prerequisites

- `com.gameframex.unity.entry` (this repository) is installed
- `com.gameframex.unity.runtime` is installed, because the `GameEntry` type is defined under the `GameFrameX.Runtime` namespace

```csharp
using GameFrameX.Runtime; // Provides GameEntry
// GameApp is in the global namespace, no using directive needed
```

Source: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L32-L34)

## Comparison of the Two Access Methods

| Dimension | `GameEntry` | `GameApp` |
|------|-------------|-----------|
| Namespace | `GameFrameX.Runtime` (external package) | Global namespace (this repository) |
| Type | Static class providing the component container | `static partial class`, one file per component |
| Invocation form | `GameEntry.GetComponent<T>()` | `GameApp.<PropertyName>` |
| Typical use | Registering custom components, retrieving any component on demand | Quick access to frequently used components |

The property getter implementation of `GameApp` simply wraps `GameEntry.GetComponent<T>()` and caches the result in a private static field:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }
    private static BaseComponent _base;
}
```

## Selection Recommendations

1. **For daily business development, prefer `GameApp`**
   - Shorter code with better readability: `GameApp.Base`, `GameApp.Mono`.
   - No need to memorize the specific type names of components; IDE auto-completion lists the components already wrapped in the current package.
   - Once the cache is hit, it's a field read with nearly zero overhead.

2. **To access components not wrapped in this repository, use `GameEntry` directly**
   - For example, if you have created a custom `MyComponent` and registered it into the framework, you can only use `GameEntry.GetComponent<MyComponent>()`.
   - When writing code at cross-package/cross-module boundaries, prefer `GameEntry` to avoid creating a hard dependency on `GameApp`.

3. **When registering a new component, both sides need one change each**
   - After registering via `GameEntry.RegisterComponent<T>()`, if you want the business side to access it as a property like `GameApp.My`, add a new `GameApp.My.cs` partial file in this repository and wrap a getter and a cache field following the template above.

## How-To: Add a New `GameApp` Property

1. Add `GameApp.My.cs` under `Runtime/` (it must use `partial` and be in the same namespace as `GameApp`).

```csharp
public static partial class GameApp
{
    public static MyComponent My
    {
        get
        {
            if (_my == null)
            {
                _my = GameEntry.GetComponent<MyComponent>();
            }
            return _my;
        }
    }

    private static MyComponent _my;
}
```

2. Register it with `GameEntry.RegisterComponent<MyComponent>()` in the framework startup flow.
3. The business side can then simply call `GameApp.My.DoSomething()`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GameApp.Base` returns `null` / throws an exception | The framework has not finished starting up, or the corresponding component was not registered with `RegisterComponent` | Check whether the startup flow calls `RegisterComponent<BaseComponent>`; pay attention to timing in hot-update/restart scenarios |
| Compile error: `GameEntry` does not exist | Missing `using GameFrameX.Runtime;` | Add `using GameFrameX.Runtime;` at the top of the file |
| Cannot find properties such as `GameApp.Mono` | You are not using the `com.gameframex.unity.entry` package, or the package version is too old and does not include the corresponding partial file | Upgrade this package to the latest version |
| Your own `GameApp.My` reports a `missing partial` error | The new file does not declare `public static partial class GameApp` | Add the `partial` keyword and use the same class name as the existing `GameApp` |

## Background (Optional)

`GameEntry` maintains a component dictionary (`RegisterComponent` / `GetComponent<T>()`) and serves as the "container root" of framework components. `GameApp` does no actual work; it simply retrieves frequently used components and caches them in static fields, saving the caller from writing a generic parameter and typing out the class name. Both access methods reference the same component instances.
