# ImageCache manager is invalid 报错怎么办

当你在游戏启动日志里看到 `ImageCache manager is invalid.` 时,说明 `ImageCacheComponent.Awake()` 在通过 `GameFrameworkEntry.GetModule<IImageCacheManager>()` 拉取管理器实例时拿到了 `null` —— 框架里没人实现这个接口。组件随后会直接 `return`,所有图片加载(`LoadImageAsync`、`IsCached`、`RemoveCache`、`ClearCache`)都不会生效。

报错来源(`Awake` 入口):

```csharp
_imageCacheManager = GameFrameworkEntry.GetModule<IImageCacheManager>();
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L42-L47)

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动日志报 `ImageCache manager is invalid.`,后续所有图片接口返回 `null` / 无效果 | 没有在 `GameFrameworkEntry` 注册 `IImageCacheManager` 的实现 | 启动框架后调用 `GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager())` |
| 启动日志同时出现 `Download manager is invalid.`(非 WebGL 平台) | 缺少 `IDownloadManager` 模块,`Awake` 提前返回导致管理器未注入 | 先注册 `IDownloadManager`(如 `DownloadManager`),再注册 `ImageCacheManager` |
| 报错只在某个场景出现 | 当前场景没有挂着 `ImageCacheComponent`,或挂在未激活的 GameObject 上 | 在常驻 GameObject 上挂 `ImageCacheComponent`,确保场景加载时它已 `Awake` |
| 自定义实现类继承 `IImageCacheManager`,仍报错 | `componentType`(Inspector 字段)填写错误,`Awake` 中 `Utility.Assembly.GetType(componentType)` 返回 `null` | 在 Inspector 把 `Component Type` 改为带命名空间的完整类名 |

## 修复步骤

### 1. 在框架入口注册 `ImageCacheManager`

`ImageCacheComponent` 不会自动创建管理器实例,必须由业务入口显式注册。常见做法是在框架启动流程中调用:

```csharp
using GameFrameX.Runtime;
using GameFrameX.ImageCache.Runtime;

GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager());
```

Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L11-L48)

### 2. 非 WebGL 平台补齐 Download 模块

`ImageCacheComponent.Awake()` 还会校验 `IDownloadManager`,缺它同样会让管理器初始化失败:

```csharp
#if !UNITY_WEBGL
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
((ImageCacheManager)_imageCacheManager).SetDownloadManager(downloadManager);
#endif
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55-L64)

因此顺序应是:先注册 `IDownloadManager`,再注册 `IImageCacheManager`,最后才让场景里挂着 `ImageCacheComponent` 的对象 `Awake`。

### 3. 检查场景里的组件挂载

确认 `ImageCacheComponent` 挂在**常驻** GameObject 上(例如引导场景的 `GameFrameX` 根节点),而不是只在某个业务场景里。`Awake` 只在场景首次激活时触发一次,缺失会让所有图片调用失效,且不会再次尝试创建管理器。

### 4. 自定义实现类时检查 `Component Type`

`Awake` 会用 `Utility.Assembly.GetType(componentType)` 解析实现类型:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IImageCacheManager);
base.Awake();
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L39-L41)

`componentType` 必须填实现类的**完整类名(含命名空间)**,且该类已编译进运行时程序集;否则 `Awake` 内部会先抛异常,后续 `GetModule<IImageCacheManager>()` 同样返回 `null`,触发本条报错。

## 验证

完成上述修复后,用以下方式确认问题消失:

1. 启动游戏,在日志中搜索 `ImageCache manager is invalid.`,应无匹配项。
2. 调用 `GameFrameXEntry.GetModule<IImageCacheManager>()`,返回值非 `null`。
3. 在非 WebGL 平台执行一次 `LoadImageAsync("https://example.com/test.png")`,能成功下载并缓存到 `Config.CachePath` 指向的目录。
