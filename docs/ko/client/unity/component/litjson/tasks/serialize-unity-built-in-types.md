# Unity 내장 타입(Vector3, Quaternion, Color 등) 직렬화 방법

`UnityTypeBindings`은(는) `Vector2 / Vector3 / Vector4 / Quaternion / Color / Color32 / Bounds / Rect / RectOffset / Type`에 대한 JSON exporter를 이미 등록해 두었으므로, 비즈니스 코드에서 직접 `JsonMapper.ToJson(obj)`를 호출하면 이러한 내장 타입을 JSON 객체로 출력할 수 있습니다. 역직렬화할 때 이러한 내장 타입은 `JsonData`로还原됩니다(레지스트리에 `Type`에 대한 importer만 등록되어 있기 때문이므로). `JsonData`를 받은 후 구조체를 직접 재구성해야 합니다.

## 사전 조건

- `GameFrameX.LitJSON.Runtime` 어셈블리를 이미 참조했음(Unity Package에 기본 포함되어 있음).
- 정적 생성자는 타입이 처음 액세스될 때 자동으로 `Register()`를 호출하므로 수동으로 트리거할 필요가 없음.

## 작업 단계

1. **`JsonMapper.ToJson`을 직접 호출하여 구조체 직렬화**

   `UnityTypeBindings.Register()`로 등록된 모든 타입은 객체의 필드이든 `ToJson`에 직접 전달되든, 아래 schema에 따라 출력됩니다:

   ```csharp
   using GameFrameX.LitJSON.Runtime;
   using UnityEngine;

   var player = new
   {
       position = new Vector3(1f, 2f, 3f),
       rotation = Quaternion.identity,
       tint     = new Color(0.1f, 0.2f, 0.3f, 1f),
       hp       = 100
   };

   string json = JsonMapper.ToJson(player);
   // {"position":{"x":1.0,"y":2.0,"z":3.0},
   //  "rotation":{"x":0.0,"y":0.0,"z":0.0,"w":1.0},
   //  "tint":{"r":0.1,"g":0.2,"b":0.3,"a":1.0},
   //  "hp":100}
   ```

   Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L50-L114)

2. **출력되는 필드명 확인**

   아래 표는 `UnityTypeBindings`에서 등록된 exporter가 결정하는, JSON에서 각 내장 타입에 대응되는 필드명입니다:

   | 타입 | 출력 필드 |
   |------|----------|
   | `Vector2` | `x`, `y` |
   | `Vector3` | `x`, `y`, `z` |
   | `Vector4` | `x`, `y`, `z`, `w` |
   | `Quaternion` | `x`, `y`, `z`, `w` |
   | `Color` / `Color32` | `r`, `g`, `b`, `a` |
   | `Bounds` | `center` (중첩 Vector3), `size` (중첩 Vector3) |
   | `Rect` | `x`, `y`, `width`, `height` |
   | `RectOffset` | `top`, `left`, `bottom`, `right` |
   | `Type` | 완전한 타입명 (`FullName`) |

   Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L44-L150)

3. **역직렬화 시 수동으로 복원**

   `UnityTypeBindings`은(는) `Type`에 대해서만 importer를 등록했습니다. 구조체 타입은 아직 importer가 없으므로 `JsonMapper.ToObject<Vector3>(json)`은(는) 예외를 던집니다. 안전한 방법은 먼저 `ToObject<JsonData>`를 사용하여 딕셔너리를 가져온 다음 필드별로 재구성하는 것입니다:

   ```csharp
   using GameFrameX.LitJSON.Runtime;
   using UnityEngine;

   string json = "{\"x\":1.0,\"y\":2.0,\"z\":3.0}";
   JsonData data = JsonMapper.ToObject<JsonData>(json);

   Vector3 v = new Vector3(
       (float)data["x"],
       (float)data["y"],
       (float)data["z"]
   );
   ```

   중첩 구조(예: `Bounds`)를 포함하는 경우, `JsonData`를 레이어별로 펼치면 됩니다:

   ```csharp
   string boundsJson = "{\"center\":{\"x\":0,\"y\":0,\"z\":0},\"size\":{\"x\":1,\"y\":1,\"z\":1}}";
   JsonData bd = JsonMapper.ToObject<JsonData>(boundsJson);

   Bounds bounds = new Bounds(
       new Vector3((float)bd["center"]["x"], (float)bd["center"]["y"], (float)bd["center"]["z"]),
       new Vector3((float)bd["size"]["x"],    (float)bd["size"]["y"],    (float)bd["size"]["z"])
   );
   ```

## 일반적인 변형

- **중첩 객체의 내장 타입**: `Vector3`을(를) 어떤 클래스의 필드/속성으로 사용할 때, 직렬화는 자동으로 `RegisterExporter<Vector3>` 경로를 따르므로 추가 구성이 필요하지 않습니다.
- **사용자 정의 ScriptableObject 또는 MonoBehaviour**: 내장 타입을 `SerializeField` 필드로 사용하면, `JsonMapper.ToJson`은(는) 마찬가지로 위 표에 따라 출력합니다.
- **특정 필드만 출력**: `JsonMapper.ToJson(new { pos = transform.position })`을(를) 직접 호출하면 됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `JsonException: Can't assign object ... to ...` `ToObject<Vector3>` 호출 시 | Unity 내장 타입에는 exporter만 등록되어 있고 importer는 등록되어 있지 않음 | 먼저 `ToObject<JsonData>`을(를) 호출한 다음 필드별로 수동으로 구성 |
| JSON에 필드 대신 `{}`이(가) 나타남 | 등록 전에 `ToJson`을(를) 호출했거나, 사용자 정의 클래스의 동일한 이름 필드가 무시됨 | `UnityTypeBindings` 어셈블리가 참조되는지 확인(정적 생성자가 폴백으로 등록) |
| 필드명이 Unity 기본값과 다름 | 이 바인딩은 소문자 필드명(`x`/`y`/`r`/`g`...)을 사용함 | 이 표의 필드명으로 읽기/쓰기를 수행하고 `X`/`R`을(를) 가정하지 말 것 |
| `Type` 필드 역직렬화 시 `null` 반환 | `Type.GetType`이(가) 해당 FullName을 찾을 수 없음(크로스 어셈블리/동적 어셈블리) | `Type.GetType(s + ", AssemblyName")`을(를) 사용하거나 직접 importer를 다시 등록 |

## 배경(선택 사항)

`UnityTypeBindings`은(는) 정적 생성자와 `_registered` 플래그를 통해 등록이 한 번만 발생하도록 보장합니다. 각 내장 타입을 배열이 아닌 JSON 객체에 매핑하여 사람이 읽고 버전 진화가 용이하도록 합니다(`x`/`y`/`z` 순서 조정은 역직렬화를 손상시키지 않음). `JsonMapper`의 전체 아키텍처는 《개요》 페이지를 참조하세요.
