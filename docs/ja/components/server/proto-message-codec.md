# Proto メッセージの定義とエンコード/デコードの組み込み方法

メッセージクラスに属性マークを追加し、`INetworkMessage` インターフェースを実装することで、カスタムメッセージをフレームワークの ProtoBuf シリアライズと ID ルーティングシステムに接続し、送受信両端でのメッセージエンコード/デコードを実現できます。

## 前提条件

- プロジェクトが `GameFrameX.ProtoBuf.Net` を参照していること(ProtoBuf の `Serializer.Serialize` / `Deserialize` / `Merge` をカプセル化)。
- プロジェクトが `GameFrameX.NetWork.Abstractions` を参照していること、メッセージ ID 登録とハートビート/リクエスト/レスポンス分類に使用。
- アセンブリの起動段階で `MessageProtoHelper.Init(assemblies)` を一度呼び出し、属性をスキャンして辞書に書き込むこと。

## 操作手順

### 1. メッセージタイプの定義

メッセージクラスは `INetworkMessage` インターフェースを実装し、`MessageTypeHandlerAttribute` を通じてグローバルに一意な `MessageId` と `OperationType` を登録する必要があります。業務セマンティクスに応じて、`IRequestMessage`、`IResponseMessage`、`INotifyMessage`、`IHeartBeatMessage` を選択的に実装できます。

```csharp
using GameFrameX.NetWork.Abstractions;
using GameFrameX.NetWork.Abstractions.Interface;

[MessageTypeHandler(1001, (byte)MessageOperationType.Request)]
public sealed class LoginRequest : INetworkMessage, IRequestMessage
{
    public string UserName { get; set; }
    public string Password { get; set; }
}

[MessageTypeHandler(1002, (byte)MessageOperationType.Response)]
public sealed class LoginResponse : INetworkMessage, IResponseMessage
{
    public int Code { get; set; }
    public string Token { get; set; }
}

[MessageTypeHandler(9999, (byte)MessageOperationType.Notify)]
public sealed class HeartBeat : INetworkMessage, IHeartBeatMessage
{
    public long Timestamp { get; set; }
}
```

`MessageTypeHandlerAttribute` は `MessageId` と `OperationType` を保持し、登録段階でこれらを使用して `MessageProtoHelper` 内部の辞書を埋めます。

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L218-L254)

### 2. 起動時にメッセージマッピングを初期化

アプリ起動時に、メッセージクラスを含むアセンブリを `MessageProtoHelper.Init` に渡します。これは `MessageTypeHandlerAttribute` でマークされたすべてのタイプをスキャンし、ID によって `AllMessageDictionary`、`RequestDictionary`、`ResponseDictionary`、`HeartBeatList`、`OperationType` に登録します。ID が重複している場合、`ArgumentAlreadyException` がスローされます。

```csharp
using System.Reflection;
using GameFrameX.NetWork.Abstractions;

MessageProtoHelper.Init(
    Assembly.GetExecutingAssembly(),
    typeof(LoginRequest).Assembly
);
```

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L187-L208)

### 3. ProtoBuf によるシリアライズとデシリアライズの使用

`GameFrameX.ProtoBuf.Net.ProtoBufSerializerHelper` は ProtoBuf の `Serializer.Serialize` / `Deserialize` / `Merge` をカプセル化しており、メッセージ本体のバイトストリームエンコード/デコードに直接使用できます。

```csharp
using GameFrameX.ProtoBuf.Net;

// シリアライズ(オブジェクト -> バイト配列)
byte[] payload = ProtoBufSerializerHelper.Serialize(loginRequest);

// デシリアライズ(バイト配列 -> オブジェクト)
var message = ProtoBufSerializerHelper.Deserialize<LoginRequest>(payload);

// マージモード:バイトストリームを既存インスタンスにマージし、新規オブジェクトの割り当てを回避
var merged = ProtoBufSerializerHelper.Deserialize(payload, existingInstance);
```

マージモードは増分更新シナリオに適しています。空のバイト配列は例外をスローせず元のインスタンスを直接返します。

Source: [ProtoBufSerializerHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.ProtoBuf.Net/ProtoBufSerializerHelper.cs#L17-L82)

### 4. 送受信フローでのメッセージタイプの照会

ネットワーク層がバイトストリームを受信した後、まず `MessageId` でタイプを照会し、次に `ProtoBufSerializerHelper` を使用してデシリアライズできます。

```csharp
int messageId = ReadMessageId(buffer);
Type messageType = MessageProtoHelper.GetMessageTypeById(messageId);
if (messageType != null)
{
    object message = ProtoBufSerializerHelper.Deserialize(buffer, messageType);
    // 処理ロジックにディスパッチ...
}
```

逆方向の送信時は、まず `MessageProtoHelper.SetMessageId(message)` を使用して `MessageId` をオブジェクトに書き戻し、その後シリアライズを行います。

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L60-L149)

## 一般的なバリエーション

| シナリオ | 記述方法 | 説明 |
|------|------|------|
| ハートビートメッセージ | `IHeartBeatMessage` を実装 | 自動的に `HeartBeatList` に追加され、`GetMessageOperationType` は直接 `HeartBeat` を返す |
| リクエスト/レスポンスペアリング | `IRequestMessage` と `IResponseMessage` をそれぞれ実装 | `RequestDictionary` / `ResponseDictionary` にそれぞれ登録され、RPC ペアリングを容易にする |
| 増分更新 | `Deserialize<T>(byte[] data, T instance)` | `Serializer.Merge` を使用し、インスタンスを再利用して GC を削減 |
| 列挙型フィールド | `ProtoEnumAttribute` を使用 | `GameFrameX.ProtoBuf.Net` で提供、ソースコードディレクトリを参照 |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動時に `ArgumentAlreadyException(... MessageIdDuplicate ...)` がスローされる | 2 つのクラスが同じ `MessageId` を共有している | `MessageTypeHandler` の最初のパラメータを変更し、グローバルに一意であることを保証する |
| `GetMessageTypeById` が `null` を返す | その ID に対して `Init` が呼び出されていないか、登録されていない | 起動段階で `MessageProtoHelper.Init(assembly)` を呼び出し、メッセージクラスがそのアセンブリにコンパイルされていることを確認する |
| `ProtoBufSerializerHelper.Serialize` が例外をスローする | フィールドに ProtoBuf `[ProtoMember]` / `[ProtoContract]` などの属性が付いていない | メッセージクラスが ProtoBuf シリアライズ属性(`GameFrameX.ProtoBuf.Net` では `ProtoContractAttribute`、`ProtoIncludeAttribute` など)を正しく宣言しているか確認する |
| ハートビートが通常メッセージとして処理される | `IHeartBeatMessage` が実装されていない | ハートビートクラスにこのインターフェースを実装させる。`Init` 段階で自動的にハートビートテーブルに追加される |

## 背景(オプション)

フレームワークは「メッセージ ID ↔ タイプ」マッピング(`MessageProtoHelper`)と「オブジェクト ↔ バイト」マッピング(`ProtoBufSerializerHelper`)を分離しています。前者は ID によって正しい .NET タイプを見つけ、リクエスト/レスポンス/通知/ハートビートを区別する役割を担い、後者は ProtoBuf 形式のバイナリ読み書きを担当します。`GameFrameX.Proto/MessageProtoHandler` は名前空間のプレースホルダーであり、実際のエンコード/デコードのエントリーポイントは `ProtoBufSerializerHelper` です。トランスポート層(TCP/KCP)がこれらのバイトをどのようにカプセル化するかについては、ネットワーク層の関連ドキュメントを参照してください。
