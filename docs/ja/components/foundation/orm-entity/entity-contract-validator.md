# EntityContractValidator を使用してコントラクトを検証する方法

`EntityContractValidator` は、エンティティ型とそれが実装するインターフェイスの間のプロパティ一貫性を検証するために使用されます。インターフェースで宣言されている各プロパティについて、エンティティクラスには同じ名前のプロパティが存在し、型が互換性があり（`Nullable<T>` と代入共変性をサポート）、インターフェースが要求する `getter` / `setter` を提供する必要があります。

## 前提条件

- プロジェクトが `GameFrameX.Foundation.Orm.Entity` アセンブリを参照していること。
- ターゲットフレームワークが `System.Reflection` をサポートしていること（すべての .NET バージョンで利用可能）。
- 検証対象の型が `class` であり、少なくとも 1 つのプロパティを持つインターフェースを実装していること。

## 操作手順

1. **検証エントリを選択する**。2 種類のオーバーロードが提供されており、結果は完全に同じです:

   ```csharp
   using GameFrameX.Foundation.Orm.Entity;

   // ジェネリック版オーバーロード(コンパイル時に型が判明)
   var violations = EntityContractValidator.Validate<MyEntity>();

   // 非ジェネリック版オーバーロード(実行時にリフレクションで Type を取得)
   var violations = EntityContractValidator.Validate(typeof(MyEntity));
   ```

   Source: [EntityContractValidator.cs#L57-L87](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L57-L87)

2. **違反項目を反復処理して原因を特定する**。戻り値の型は `IList<EntityContractViolation>` で、各レコードには 3 つのフィールドが含まれます:

   | フィールド | 型 | 意味 |
   |------|------|------|
   | `InterfaceType` | `Type` | 違反されたインターフェース型 |
   | `PropertyName` | `string` | 欠落または不一致のプロパティ名 |
   | `Reason` | `string` | 中英二言語で記述された具体的な原因 |

   Source: [EntityContractViolation.cs#L38-L79](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractViolation.cs#L38-L79)

3. **典型的な最小呼び出し**:

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       foreach (var v in violations)
       {
           Console.WriteLine($"[{v.InterfaceType.Name}.{v.PropertyName}] {v.Reason}");
       }
   }
   ```

4. **CI / 起動時にアサーションを組み込む**(推奨される方法):

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       throw new InvalidOperationException(
           $"エンティティ MyEntity がコントラクトに違反しています:{string.Join("; ", violations.Select(v => v.Reason))}");
   }
   ```

## 検証される 4 種類の違反

`ValidateInterface` はインターフェース上の各プロパティを順番にチェックし、ヒットすれば `continue` するため、各種類の違反は 1 回だけトリガーされます:

| 順序 | トリガー条件 | `Reason` キーワード | ソースコード行 |
|------|----------|------------------|--------|
| 1 | `GetProperty` が `AmbiguousMatchException` をスロー(複数継承または `new` による隠蔽) | "存在多个声明(可能使用了 new 关键字遮蔽)" | [L100-L108](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108) |
| 2 | エンティティクラスに同じ名前のパブリックプロパティが存在しない | "不存在" | [L110-L118](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118) |
| 3 | プロパティ型に互換性がない(`IsTypeCompatible` が false を返す) | "类型不匹配:期望 … 实际 …" | [L120-L128](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L120-L128) |
| 4 | インターフェースが `get` / `set` を要求しているが、実装に対応するアクセサがない | "缺少 getter" / "缺少 setter" | [L130-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144) |

`IsTypeCompatible` の判定ルール(`Nullable<T>` と共変性をサポート):

- 完全に同じ → 互換性あり;
- `Nullable` ラッピングを取り除いた後、同じ → 互換性あり;
- それ以外の場合は `expected.IsAssignableFrom(actual)` を使用。

Source: [EntityContractValidator.cs#L148-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

## 一般的なバリエーション

- **ジェネリックエンティティ基底クラスの検証**:`Validate<EntityBase<Guid>>()`、`Validate<EntityTenantBase<Guid>>()` などはすべて空のリストを返します。フレームワーク内蔵の基底クラスはすべて自己整合性を備えています。Source: [EntityContractValidatorComprehensiveTests.cs#L78-L94](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/EntityContractValidatorComprehensiveTests.cs#L78-L94)
- **非エンティティ型の検証**:正常に呼び出せますが、型が実装するインターフェースのプロパティが明示的なインターフェース実装(例: `int.IConvertible.TypeCode`)である場合、"属性不存在" 違反がトリガーされます。Source: [L42-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/EntityContractValidatorComprehensiveTests.cs#L42-L51)
- **複数レベルの継承 + `new` による隠蔽**:複数レベルの継承チェーンで `AmbiguousMatchException` が発生した場合でも、同じプロパティ名に対して 1 つの違反のみが生成されます(ヒット後に `continue`)。Source: [OrmEntityBoundaryTests.cs#L60-L67](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/OrmEntityBoundaryTests.cs#L60-L67)

## よくあるエラー

| エラーな使用方法 | 現象 | 修正方法 |
|----------|------|------|
| `null` を `Validate(Type)` に渡す | `ArgumentNullException` がスローされ、`ParamName = "entityType"` となる | 空でない `Type` を渡すか、ジェネリック版オーバーロードを使用する |
| `explicit interface implementation` を使用してインターフェースプロパティを実装する | 検証で "属性不存在" が報告される — `GetProperty(Public|Instance)` は明示的実装を見つけられない | プロパティをパブリックプロパティに変更するか、インターフェース自体に必要なメンバーのみをインターフェース上で宣言する |
| `new` キーワードを使用してインターフェースの同名プロパティを隠蔽する | `AmbiguousMatchException` がトリガーされ、"存在多个声明(可能使用了 new 关键字遮蔽)" が報告される | `new` を削除するか、エンティティクラス内で一意になるように名前を変更する |
| `string?` を `string` として、またはその逆を実装する | "类型不匹配" が報告される | `Nullable<T>` と非 nullable T は互換性ありとみなされるため、他の差異については一致させてください |

## 背景(オプション)

`ValidateInterface` は `entityType.GetInterfaces()` を使用してすべてのインターフェースを列挙し、各インターフェースのプロパティを `BindingFlags.Public | BindingFlags.Instance` を使用してエンティティクラス上で順番に検索します。ヒットすると `EntityContractViolation` の 1 レコードが記録されて `continue` されるため、1 つのインターフェースプロパティが生成する違反は最大 1 件です。複数継承または `new` による隠蔽によって `GetProperty` が `AmbiguousMatchException` をスローした場合、例外をキャッチして専用のテキストで報告され、外部にはスローされません。`IsTypeCompatible` はまず厳密な型一致を確認し、次に `Nullable` ラッピングを除去した一致を確認し、最後に `IsAssignableFrom` を使用して共変性シナリオを処理します。
