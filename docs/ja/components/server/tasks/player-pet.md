# プレイヤー Pet モジュールを実装する

プレイヤー Pet モジュールはコンポーネントの形式でプレイヤー Actor にマウントされ、ペットの実行時状態を保存しペット関連イベントに応答する役割を担います。本セクションでは空のモジュールから始め、登録可能で拡張可能なペットコンポーネントのスケルトンを組み上げます。

## 前提条件

- プレイヤー Actor(`ActorType = GlobalConst.ActorTypePlayer`)が作成済みであること。
- `GameFrameX.Core.Abstractions.Attribute`、`GameFrameX.Utility.Setting`、`GameFrameX.Core.Components` が導入済みであること。
- フレームワークの `StateComponent<TState>` と `StateComponentAgent<TComponent, TState>` の二層構造(Apps 層での定義と状態、Hotfix 層でのロジック記述)について理解していること。

}

## よくあるバリエーション

- **ペット取得イベントへの応答**: `PetComponentAgent` に `EventId.GotNewPet` を処理するプライベート非同期メソッドを追加し、ネストされた `EventListener<T>` クラスを介してイベントを購読します([PetComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Pet/PetComponentAgent.cs#L8-L28) のコメント例を参照してください)。
- **コンポーネントをまたいだ呼び出し**: `PetComponentAgent` 内で `ActorManager.GetComponentAgent<ServerComponentAgent>()` を使って他のコンポーネントエージェントを取得します。例えばワールドレベルを読み取ってペット属性を決定するといった用途に使用します。
- **ペットデータフィールド**: `PetState` に直接シリアル化可能な属性(ペット ID、レベル、経験値など)を追加します。フレームワークが自動的にアーカイブとキャッシュに参加します。

## よくあるエラー

- **Agent の名前空間が不一致**: 現在 `PetComponentAgent` が属している名前空間は `GameFrameX.Hotfix.Logic.Role.Pet` ですが、Apps 層は `GameFrameX.Apps.Player.Pet.*` です。サンプルをコピー＆ペーストする際は、それぞれの名前空間をそのまま保持し、フレームワークのリフレクション失敗を避けてください。
- **`[ComponentType]` の付け忘れ**: `PetComponent` に `ActorTypePlayer` が指定されていない場合、プレイヤー Actor にマウントされず、実行時の挙動としてペット機能が完全に無効になります。
- **Apps 層にビジネスロジックを書いてしまう**: Apps 層はパッケージング時にメインアセンブリに入り、ホットアップデートできません。可変ロジックは必ず Hotfix 層の `PetComponentAgent` に記述してください。

## 背景(オプション)

`PetComponent` はフレームワークの「コンポーネント + 状態 + エージェント」三点セットに沿って構成されています。`StateComponent<TState>` は状態の帰属とライフサイクルのみを宣言し、実際のビジネスは `StateComponentAgent<TComponent, TState>` で動作します。この二つはジェネリック引数で対応付けられ、`[ComponentType]` によってそのコンポーネントがどの種類の Actor に登録されるかが決定されます。
