# Find GObject by Path

Use `FairyGUIPathFinderHelper.GetUIFromPath(path)` to directly retrieve a `GObject` at runtime by its hierarchical path (e.g., `GRoot/Group/MyButton`), without having to call `GetChild` level by level; conversely, `gObject.GetUIPath()` returns the full path of any object.

## Prerequisites

- Reference the namespaces `FairyGUI` and `GameFrameX.UI.FairyGUI.Runtime` (this Helper is located in the `GameFrameX.UI.FairyGUI.Runtime` assembly).
- The search starts from `GRoot.inst`; the target object must already be attached to the current display list (under GRoot). Objects inside views that are not open or have been destroyed cannot be found.

## Steps

1. (Optional) Get the full path first. If you are unsure of the hierarchy names, call the extension method `GetUIPath()` on any `GObject` to print its path:

```csharp
using FairyGUI;
using GameFrameX.UI.FairyGUI.Runtime;

// Get the hierarchical path of a GObject, e.g. "GRoot/UISynthesisScene/ContentBox/ListSelect/1990197248/icon"
string path = gObject.GetUIPath();
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L43-L57)

2. Resolve the object from the path string and check the return value for null (when the object cannot be found, the method has already logged an error internally and returned `null`):

```csharp
// Resolve a GObject from a path
GObject obj = FairyGUIPathFinderHelper.GetUIFromPath("GRoot/Group/MyButton");
if (obj == null)
{
    // Invalid path: the Log will show "error uiPath : can not found ui by this path : ..."
    return;
}
```

Path format rules (determined by the parsing logic of `GetUIFromPath`):

| Notation | Rule |
|------|------|
| Separator | Names at each level are separated by `/` |
| `GRoot` segment | Automatically skipped; including or omitting the `GRoot` prefix has the same effect |
| Normal segment | Looks up by name via `GComponent.GetChild(name)`; must match the object name set in the editor |
| `$number` segment | First tries `GetChild` with the full name; if not found, treats the number after `$` as a child index and retrieves it with `GetChildAt(index)` |
| Empty queue | When an empty path is passed, the root object `GRoot.inst` is returned directly |

## Common Variants

- **Locate unnamed child objects by index**: Write the path segment as `$index`; for example, `"GRoot/MyList/$3"` means the 4th child of `MyList`. An out-of-range index or hitting a non-component node throws an exception and returns `null`:

```csharp
// First tries to look up by the name "$3"; on failure, looks up by index with GetChildAt(3)
GObject item = FairyGUIPathFinderHelper.GetUIFromPath("GRoot/MyList/$3");
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L166-L187)

- **Check whether an object is under a given path**: Use `SearchPathInclude`. A path of `all` (case-insensitive) matches no object (returns `false`):

```csharp
// Check whether gObject is under the path "GRoot/Group/Panel" (supports $index segments)
bool inside = FairyGUIPathFinderHelper.SearchPathInclude("GRoot/Group/Panel", gObject);
```

## Common Errors

| Symptom (Log.Error / exception text) | Root cause | How to avoid |
|------|------|------|
| `error uiPath : can not found ui by this path :{path}, error : ...` | Any path segment failed to resolve; the method caught the exception and returned `null` | First print the real path with `GetUIPath()` and copy it |
| `Invalid UI path: child not found` | A segment name does not match the actual child name (case sensitivity, renaming) | Verify the object name in the editor |
| `Invalid UI path: index out of range` | The `$index` is outside the `numChildren` range | Check the number of children |
| `Invalid UI path: not a GComponent` | An intermediate node in the path is a plain `GObject` (e.g., an image or text) with no children | Intermediate segments must be component nodes |
| Returns `null` but no path error | The target object is not displayed under GRoot | Make sure the view is open and has not been closed |

## Background

`GetUIPath` walks up from the target object via `SearchParent`, collecting each `name` level by level, then reverses them and joins them with `/`; therefore, the path it outputs can be fed directly back into `GetUIFromPath` to recover the same object. `GetUIFromPath` splits the path into a queue, skips `GRoot`, and then recursively calls `SearchChild` segment by segment starting from `GRoot.inst`; nothing is cached, so every call traverses the current display tree live.
