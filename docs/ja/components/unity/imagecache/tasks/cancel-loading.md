# 进行中の画像読み込みをキャンセルする方法

`CancellationToken` を通じて読み込みタスクをキャンセルすることで、`LoadImageAsync` は適切なタイミングで後続の処理を中断し `null` を返します。キャンセル機構は WebGL 以外のプラットフォームでのみ有効であり、ダウンロード処理の最中にネットワークリクエストを直ちに遮断することはありません。

## 前提条件

- `GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>()` を通じて画像キャッシュコンポーネントを取得済みであること。
- ターゲットのビルドプラットフォームが WebGL ではないこと（WebGL では `cancellationToken` は無視されます。詳細は後述の「よくあるエラー」を参照）。

## 操作手順

1. **キャンセル可能なトークンソースを作成**。`CancellationTokenSource` を使用してトークンを生成し、`Token` プロパティを通じて読み込みインターフェースに渡します。

   ```csharp
   using System.Threading;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   var component = GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>();
   var cts = new CancellationTokenSource();
   ```

2. **読み込みを開始しトークンを渡す**。`LoadImageAsync(url, cts.Token)` を呼び出し、`Task<Texture2D>` を取得します。

   ```csharp
   var task = component.LoadImageAsync("https://example.com/foo.png", cts.Token);
   ```

3. **適切なタイミングで `Cancel()` を呼び出す**。ページの閉じ、リストアイテムのリサイクルなどの状況が発生した場合にキャンセルをトリガーします。

   ```csharp
   cts.Cancel();
   ```

4. **返り値を処理する**。キャンセルされたタスクは `null` を返します（例外はスローされません）。失敗時の分岐として扱ってください。

   ```csharp
   var tex = await task; // キャンセル済みの場合 null を返す
   if (tex == null) return;
   ```

   ソース: [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## よくあるバリエーション

- **`MonoBehaviour` のライフサイクルに連動した自動キャンセル**：`CancellationTokenSource` を GameObject のライフサイクルにバインドする（例：独自の `MonoBehaviour` の `OnDestroy` 内で `cts.Cancel()` を呼び出す）。シーン切り替え時に手動で管理する必要がなくなります。
- **タイムアウトによるキャンセル**：`cts.CancelAfter(TimeSpan.FromSeconds(5))` でタイムアウトを設定し自動キャンセル。
- **条件に応じて複数タスクをキャンセル**：同じ `CancellationTokenSource` を複数の `LoadImageAsync` 呼び出しで共有し、`Cancel()` 一度で全部中止。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| WebGL プラットフォームで `Cancel()` を呼び出してもタスクが完了してしまう | `LoadImageAsync` は `#if UNITY_WEBGL` 分岐で `cancellationToken` を受け取らない。[ImageCacheManager.cs#L84-L85](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L85) を参照 | WebGL では業務層のフラグなどで返された Texture2D を自前で破棄する必要があります |
| キャンセル後もダウンロードがバックグラウンドで継続し、ディスクにキャッシュファイルが生成される | 現在の実装はダウンロード**成功完了後**にのみトークンを確認するため、進行中のダウンロードは中断されません。[ImageCacheManager.cs#L139-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L139-L149) を参照 | リクエストを完全に停止したい場合は、キャンセル前に `_downloadManager` から能動的にタスクを削除するか、業務層でダウンロード結果を無視してください |
| `Cancel()` 後、await したタスクが `OperationCanceledException` をスローする | 本インターフェースは `ThrowIfCancellationRequested` を使用しないため、キャンセル時は一律 `null` を返します。[ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149) を参照 | `if (tex == null)` でキャンセルを判定し、`OperationCanceledException` をキャッチしないでください |

## 検証

キャンセルが成功した場合、以下の2点を満たしていれば正常です。

- `await LoadImageAsync(...)` が `null` を返す。
- `OperationCanceledException` がスローされず、また後続の画像デコードログも出力されない（キャンセル検出後に直接 `return null` するため）。

## 背景（任意）

WebGL 以外の分岐の `LoadImageDiskCacheAsync` は「ダウンロード完了 → ローカルファイルの読み取り準備」の間で1回だけ `IsCancellationRequested` を確認します。そのためキャンセルの実際のも意味は「ダウンロード終了後に今回の結果を破棄する」ことであり、ネットワークリクエストを中断するものではありません。WebGL プラットフォームは `UnityWebRequestTexture` + ブラウザキャッシュで実装されているため、メソッドのシグネチャにトークンが公開されておらず、呼び出し側は結果を取得した後で自らが使用可否を判断するしかありません。

全体のアーキテクチャとダウンロードマネージャーの連携方法については、『概要』を参照してください。
