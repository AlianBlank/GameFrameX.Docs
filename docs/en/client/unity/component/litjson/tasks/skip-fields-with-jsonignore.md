# How to Skip Fields or Properties with JsonIgnore

Add `[JsonIgnore]` to fields or properties that should be excluded from the JSON output. `JsonMapper` will automatically skip them during serialization; the same applies to deserialization—the member will not be written to either. This page demonstrates the specific usage in a Unity project.

## Prerequisites

- The LitJSON package (`com.gameframex.unity.litjson`) is installed, with the namespace `GameFrameX.LitJSON.Runtime` referenced.
- The target type is a regular class or struct that can be accessed reflectively by `JsonMapper` (fields must be `public` or marked with `JsonProperty`; properties must have public getters/setters).

## Steps

1. Add the `[JsonIgnore]` attribute to the field or property that should not be serialized.

```csharp
using GameFrameX.LitJSON.Runtime;

public class PlayerState
{
    public string Name { get; set; }

    public int Hp { get; set; }

    // Runtime cache used for debugging; not written to JSON
    [JsonIgnore]
    public double LastDamageTime { get; set; }

    // Derived field calculated on the fly; not involved in serialization
    [JsonIgnore]
    public int AttackPower => Hp / 2;

    // Sensitive field that should not be persisted
    [JsonIgnore]
    public string AuthToken;
}
```

Source: [Runtime/JsonIgnoreAttribute.cs#L30-L43](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonIgnoreAttribute.cs#L30-L43)

2. Call `JsonMapper.ToJson` for serialization as usual; the marked members will not appear in the output.

```csharp
var state = new PlayerState { Name = "Hero", Hp = 80, LastDamageTime = 1.23, AuthToken = "secret" };
string json = JsonMapper.ToJson(state);
// Output: {"Name":"Hero","Hp":80}  —— LastDamageTime / AttackPower / AuthToken have been skipped
```

Source: [Runtime/JsonMapper.cs#L380-L424](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs#L380-L424)

3. During deserialization, `JsonMapper.ToObject<T>` also ignores these members; their values remain as the type's default values.

```csharp
var restored = JsonMapper.ToObject<PlayerState>(json);
// restored.LastDamageTime == 0.0; restored.AuthToken == null
```

## Common Variations

- **Skip fields instead of properties**: `[JsonIgnore]` supports both fields and properties (`AttributeTargets.Field | AttributeTargets.Property`), with identical usage.
- **Combine with `JsonProperty` for renaming**: Use `[JsonProperty("alias")]` on members that need to be exported, and use `[JsonIgnore]` on members that need to be skipped—the two do not interfere with each other.
- **Skip base class members**: If a field/property inherited from a base class is marked with `[JsonIgnore]`, derived classes will also skip it during serialization.

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| `[JsonIgnore]` is applied but the field still appears in JSON | Incorrect namespace reference; mistakenly using another `JsonIgnore` (such as `Newtonsoft.Json.JsonIgnoreAttribute`) | `using GameFrameX.LitJSON.Runtime;` and use the `JsonIgnoreAttribute` provided by this library |
| Throws `NullReferenceException` | Bug in older versions: `as ICollection<Attribute>` returns null, causing a null reference when reading attributes | Upgrade to a version that includes the fix from commit bfc8581 |
| Static fields are serialized | This attribute only applies to instance members | Static fields are not serialized by default in this library; no special handling is required |

## Background (Optional)

The `AttributeUsage` of `JsonIgnoreAttribute` only permits marking `Field` and `Property`, with `AllowMultiple = false` (`Runtime/JsonIgnoreAttribute.cs#L40`). When `JsonMapper` reflects over the type, it calls `continue` to skip members marked with `[JsonIgnore]`, so derived class fields or `readonly` fields are ignored as well.
