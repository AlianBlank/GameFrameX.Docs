# How to Refresh the Main Camera When the Active Scene Changes

When the active scene switches, Unity's `Camera.main` may still point to the camera from the old scene or return `null`. The framework's `SceneComponent` automatically calls `RefreshMainCamera()` internally to re-point `m_MainCamera` to the camera tagged as `MainCamera` in the current active scene. You can also manually trigger a refresh at custom timings.

## Prerequisites

- The `SceneComponent` has been mounted in the scene (automatically initialized with the framework's `GameEntry`).
- The component instance has been obtained via `GameEntry.GetComponent<SceneComponent>()`.
- A `Camera` with the `MainCamera` tag exists in the target scene (the criterion used by Unity's built-in `Camera.main`).

## Steps

1. **Automatic Refresh: Listen for scene change results, the framework calls it internally.** After `SetActiveScene` successfully switches the active scene, `RefreshMainCamera()` will be called automatically, and the `ActiveSceneChangedEventArgs` event will be triggered:

   ```csharp
   // Subscribe to active scene changes
   EventComponent eventComponent = GameEntry.GetComponent<EventComponent>();
   eventComponent.Subscribe(ActiveSceneChangedEventArgs.EventId, OnActiveSceneChanged);

   private void OnActiveSceneChanged(object sender, GameEventArgs e)
   {
       var args = (ActiveSceneChangedEventArgs)e;
       // At this point SceneComponent.MainCamera has been updated automatically
       Camera mainCamera = GameEntry.GetComponent<SceneComponent>().MainCamera;
       // ...
   }
   ```

   Source: [Runtime/Scene/SceneComponent.cs#L383-L390](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L383-L390)

2. **Manual Refresh: Call the public method at custom timings.** Directly call `RefreshMainCamera()`, which internally re-assigns `m_MainCamera` to `Camera.main`:

   ```csharp
   SceneComponent sceneComponent = GameEntry.GetComponent<SceneComponent>();
   sceneComponent.RefreshMainCamera();

   Camera current = sceneComponent.MainCamera;
   Debug.Log($"Main camera after refresh: {(current != null ? current.name : \"null\")}");
   ```

   Source: [Runtime/Scene/SceneComponent.cs#L386-L390](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L386-L390)

3. **Read the Main Camera: Access via the read-only property.** The cached camera instance is exposed through the `MainCamera` property:

   ```csharp
   public Camera MainCamera
   {
       get { return m_MainCamera; }
   }
   ```

## Common Variations

- **Refresh during Single mode async loading window**: Since YooAsset's await completion may occur before Unity's scene `isLoaded=true`, the `try/catch` inside `SetActiveScene` will swallow the `ArgumentException` and directly proceed to `RefreshMainCamera()`. At this point `Camera.main` may still be `null`; this is expected behavior. After Unity truly completes loading and automatically activates the scene, the next `RefreshMainCamera()` will yield the correct result.
  Source: [Runtime/Scene/SceneComponent.cs#L447-L478](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L447-L478)
- **Custom Camera Tag**: If you use a camera with a tag other than `MainCamera`, do not rely on `RefreshMainCamera()`. Instead, use `GameObject.FindWithTag` or cache and write to `m_MainCamera` yourself (access requires a custom approach).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `MainCamera` is always `null` | No `Camera` with the `MainCamera` tag exists in the active scene, or the camera object has not been instantiated | Ensure a `Camera` with the `MainCamera` tag exists in the target scene; call `RefreshMainCamera()` again after `LoadSceneSuccess` |
| After switching scenes, the view still renders with the old camera | Only `SceneManager.LoadScene` was called, not the framework's `LoadScene` flow, so the framework does not trigger a refresh | Use the `LoadScene` family of methods from `SceneComponent`, or manually call `RefreshMainCamera()` |
| Repeated `SetActiveScene` throws `ArgumentException` | During consecutive switches, the old coroutine and new coroutine contend for `SetActiveScene` | The framework handles this internally via `StopCoroutine`; if you implement it yourself, make sure to stop the old coroutine first, see the handling inside `RefreshSceneOrder` |

## Background

The implementation of `RefreshMainCamera` is just one line: `m_MainCamera = Camera.main;`. It relies on Unity's built-in `Camera.main` (which is essentially `GameObject.FindWithTag("MainCamera")`), so whether the refresh succeeds depends entirely on whether a `Camera` with the correct tag exists in the active scene. The framework automatically calls it at two timings: after successfully setting the active scene, and as a fallback when the active scene handle becomes invalid (to avoid polluting logs with exceptions).
