# サーバーからグローバル設定情報を取得して書き込む方法

このガイドでは、`GlobalConfigComponent` を通じてサーバーからグローバル設定（JSON）を取得し、`ResponseGlobalInfo` にデシリアライズしてコンポーネントに書き込む方法を説明します。これにより、ゲーム内の他のモジュールが `HostServerUrl`、`CheckAppVersionUrl`、`AOTCodeLists` などのフィールドを読み取れるようになります。

## 前提条件

- `com.gameframex.unity.globalconfig` パッケージがインストール済みで、シーンに `GameFrameX/Global Config` コンポーネントが存在すること。
- サーバーが JSON を返す HTTP インターフェースを提供しており、JSON 構造が `ResponseGlobalInfo` のフィールドに対応していること。
- プロジェクト内で利用可能な HTTP/WebRequest ツールが存在すること（本ガイドの例では `UnityWebRequest` を使用）。

## 操作手順

1. コンポーネントの参照を取得します。コンポーネントは `GameFrameworkComponent` を継承しているため、`GameEntry.GetComponent<GlobalConfigComponent>()` で取得できます。

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   var cfg = GameEntry.GetComponent<GlobalConfigComponent>();
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L13-L14)

2. リクエスト本体 `RequestGlobalInfo` を構築します。これは `RequestBase` を継承しており、言語、プラットフォーム、パッケージ名、チャンネルなどの共通フィールドが組み込まれています。必要に応じて拡張できます。

   ```csharp
   var req = new RequestGlobalInfo
   {
       Language    = "zh-CN",
       AppVersion  = Application.version,
       Platform    = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel     = "default",
       SubChannel  = string.Empty,
   };
   ```

   Source: [RequestGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGlobalInfo.cs#L6-L8), [RequestBase.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestBase.cs#L6-L37)

3. HTTP リクエストを送信し JSON テキストを読み取ります。コルーチンと `UnityWebRequest` の併用を推奨します。

   ```csharp
   string url = "https://your-server/global-info";
   string json = null;

   using (var www = UnityEngine.Networking.UnityWebRequest.Post(url, JsonUtility.ToJson(req)))
   {
       www.SetRequestHeader("Content-Type", "application/json");
       yield return www.SendWebRequest();

       if (www.result == UnityEngine.Networking.UnityWebRequest.Result.Success)
       {
           json = www.downloadHandler.text;
       }
       else
       {
           Debug.LogError(www.error);
       }
   }
   ```

4. JSON 文字列を生データとして保存します。コンポーネントは `SetOriginalData(string)` を提供しており、`null` を渡すと `ArgumentNullException` が発生するため、防御的に処理してください。

   ```csharp
   cfg.SetOriginalData(json);
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L126-L134)

5. JSON を `ResponseGlobalInfo` にデシリアライズし、`SetGlobalConfig(...)` を呼び出してコンポーネントに書き込みます。同様に、`null` を渡すと `ArgumentNullException` が発生します。

   ```csharp
   var info = JsonUtility.FromJson<ResponseGlobalInfo>(json);
   cfg.SetGlobalConfig(info);
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L160-L168)

6. グローバル情報を読み取って使用します。後続のモジュールは `cfg.GlobalInfo`、`cfg.HostServerUrl`、`cfg.CheckAppVersionUrl`、`cfg.AOTCodeLists` などのプロパティでアクセスできます。`AOTCodeLists` は `AOTCodeList` 文字列から自動的に `List<string>` にデシリアライズされます。

   ```csharp
   string host        = cfg.HostServerUrl;          // サーバーから下发されたオプションの上書き値
   string checkApp    = cfg.GlobalInfo.CheckAppVersionUrl;
   var   aotList      = cfg.AOTCodeLists;           // List<string>
   string rawSnapshot = cfg.OriginalData;           // 保持されている元の JSON
   ```

   Source: [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L56-L120), [ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L6-L27)

## よくあるバリエーション

- **ローカルオフラインキャッシュ**:まず `cfg.OriginalData` を読み取って前回保存された JSON を取得し、新しいリクエストが失敗した場合は古い値を再利用することで、起動ごとにネットワークでブロックされることを回避できます。
- **リトライ付きリクエスト**:ステップ 3 を `for (int i = 0; i < 3; i++)` のリトライループ内に配置し、すべて失敗した場合にローカルキャッシュにフォールバックします。
- **リクエストフィールドの拡張**:サーバーが追加のパラメータ（サーバー ID など）を必要とする場合は、`class MyRequest : RequestGlobalInfo { public string ServerId; }` のように新しいクラスを作成でき、フィールドは JSON と一緒に自動的にシリアライズされます。

## よくあるエラー

| 症状 | 原因 | 対処 |
|------|------|------|
| `SetOriginalData(null)` が `ArgumentNullException` をスロー | null 参照が渡された | 呼び出し前に `json != null` を判定し、失敗時は古い値を保持するか空文字列を書き込む |
| `SetGlobalConfig(null)` が `ArgumentNullException` をスロー | デシリアライズ結果が null（空文字列/不正な JSON） | 先に `string.IsNullOrEmpty` で判定し、失敗時はログを記録して書き込みを中断する |
| `cfg.AOTCodeLists` が空 | `AOTCodeList` フィールドが有効な JSON 配列文字列でない | 書き込み時は `["A","B"]` 形式を使用する。シリアライズ失敗時はコンポーネント内部で `Log.Error` によるフォールバックが実装済み |

## 背景（オプション）

`GlobalConfigComponent` は `GameFrameworkComponent` であり、`IsAutoRegister = false` で自動登録を無効化しているため、`GameEntry` が能動的に `GetComponent<T>()` で取得する必要があります。また、「元の JSON キャッシュ」と「デシリアライズ結果」という 2 つの状態を同時に保持しており、前者はローカルフォールバック用、後者は業務モジュールがフィールドごとに読み取るために使用されます。`AOTCodeList` は `set` 時に同期的に `List<string>` に解析されキャッシュされるため、アクセスごとにデシリアライズを繰り返すことを回避できます。
