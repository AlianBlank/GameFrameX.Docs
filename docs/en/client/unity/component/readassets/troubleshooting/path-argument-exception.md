# File Read Errors: ArgumentNullException / ArgumentException(path)

When calling `BlankReadAssets` methods like `OpenRead`, `ReadAllBytes`, `GetFiles`, etc., if the `path` parameter passed in is `null` or an empty string, an argument exception is thrown immediately. Similarly, calling `PathUtil.CombineSlash` / `NormalizeRelativePath` with missing path components also throws the same type of exception. This page helps you quickly identify which case you're hitting and fix it.

## Fix Steps

### 1. `OpenRead` / `ReadAllBytes` Receive `null`

Source entry: [BlankReadAssets.OpenRead](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L132-L146) and [BlankReadAssets.ReadAllBytes](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L197-L211). Both first perform a `path == null` null-check.

```csharp
using GameFrameX.Asset;

string path = ResolveConfigPath(); // May return null

if (string.IsNullOrEmpty(path))
{
    Debug.LogError("Config file path is not configured, skipping read");
    return;
}

byte[] data = BlankReadAssets.ReadAllBytes(path);
```

### 2. `OpenRead` / `ReadAllBytes` Receive Empty String

Source: [BlankReadAssets.cs#L139-L142](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L139-L142). When `path.Length == 0`, it throws `ArgumentException("Empty path", "path")`.

```csharp
// Wrong example
string dir = "config/";
string file = ""; // From a failed config read
string full = dir + file; // -> Sub-path of "config/" might still be valid, but if file itself is empty, it will throw an error
byte[] data = BlankReadAssets.ReadAllBytes(full); // Depends on full, cannot rely on it

// Fix: concatenate with PathUtil.CombineSlash and validate
string full = PathUtil.CombineSlash(dir, file);
if (string.IsNullOrEmpty(full) || full.EndsWith("/"))
{
    throw new InvalidOperationException("Invalid target file path: " + full);
}
```

### 3. `PathUtil.CombineSlash` Throws `ArgumentNullException`

Source: [PathUtil.CombineSlash](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75). Throws if either `a` or `b` is `null`.

### 4. `PathUtil.NormalizeRelativePath` Throws `ArgumentException("Empty or null", "relative")`

Source: [PathUtil.NormalizeRelativePath](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L83). Any empty value will be thrown directly, even an empty string.

```csharp
public static byte[] SafeRead(string relative)
{
    if (string.IsNullOrWhiteSpace(relative))
    {
        Debug.LogError("relative is empty, aborting read");
        return Array.Empty<byte>();
    }
    return BlankReadAssets.ReadAllBytes(relative);
}
```

### 5. `path` is `null` for `GetFiles` in APK Mode

Source: [BlankReadAssets.ApkImpl.GetFiles](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L93-L116). When `path == null`, it throws `ArgumentNullException` first, before performing any directory index checks.

```csharp

{
    dir = "/"; // Fallback to root directory
}
string[] files = BlankReadAssets.GetFiles(dir, "*", SearchOption.TopDirectoryOnly);
```

### 6. Internal `ArgumentException()` (No Message) in APK

Source: [BlankReadAssets.ApkImpl.cs#L299-L306](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L299-L306). ## Common Mistakes

- **Relying on `path + ""` concatenation**: An empty file name causes `ReadAllBytes` to hit the `path.Length == 0` branch and throw `ArgumentException`. Use `PathUtil.CombineSlash` instead and validate the result.
- **Treating `null` and `""` as the same case**: The source throws `ArgumentNullException` for `null` and `ArgumentException` for `""` in `OpenRead`; the exception types are different, so be careful when searching logs.
- **Forgetting to initialize first in APK mode**: When uninitialized, `EnsureInitialized` throws `InvalidOperationException` rather than an argument exception, which can be misleading; confirm initialization first, then check argument validation.
- **Passing root paths or quoted strings to `PathUtil.NormalizeRelativePath`**: This method has special handling for strings wrapped in `"` ([PathUtil.cs#L93](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L93)); unpaired double quotes embedded in the path may cause parsing exceptions.
