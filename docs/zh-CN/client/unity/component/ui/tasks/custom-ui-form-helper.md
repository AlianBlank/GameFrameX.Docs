# 如何自定义 UI Form Helper

通过继承 `UIFormHelperBase` 并实现 `IUIFormHelper` 的三个方法,你可以接管界面资源的实例化、`IUIForm` 业务对象的创建以及界面释放流程;再让 `UIComponent` 通过类名字符串或预制体引用使用你的实现即可生效。

## 前置条件

- 已熟悉 GameFrameX UI 子系统的基本流程(关于整体架构,见相关说明)。
- 项目已安装 `com.gameframex.unity.ui` 包,且场景中挂有 `UIComponent`。

## 操作步骤

1. **实现 `IUIFormHelper` 接口或继承 `UIFormHelperBase`。**

   `UIFormHelperBase` 已经帮你处理了 `MonoBehaviour` 生命周期与 `Scripting.Preserve]` 标记,你只需要继承它并实现三个抽象方法。

   接口定义位于 [IUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIFormHelper.cs#L40-L76),抽象基类位于 [UIFormHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)。

   ```csharp
   using System;
   using GameFrameX.UI.Runtime;
   using UnityEngine;

   public class MyUIFormHelper : UIFormHelperBase
   {
       public override object InstantiateUIForm(object uiFormAsset)
       {
           // 根据你使用的 UI 方案(FairyGUI / UGUI / 其他)实例化界面资源
           var prefab = uiFormAsset as GameObject;
           if (prefab == null) return null;
           return Instantiate(prefab);
       }

       public override IUIForm CreateUIForm(object uiFormInstance, Type uiFormType, object userData)
       {
           // 把 uiFormInstance 绑定到 uiFormType 对应的业务逻辑脚本,返回 IUIForm
           var go = uiFormInstance as GameObject;
           var form = go.GetComponent(uiFormType) as IUIForm;
           if (form != null)
           {
               (form as Component).gameObject.SetActive(true);
           }
           return form;
       }

       public override void ReleaseUIForm(object uiFormAsset, object uiFormInstance, object assetHandle,
                                          string uiFormAssetPath, string uiFormAssetName)
       {
           // 销毁实例并按需归还资源句柄
           var go = uiFormInstance as GameObject;
           if (go != null) Destroy(go);
       }
   }
   ```
   Source: [Runtime/UIFormHelperBase.cs#L42-L81](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)

2. **让 `UIComponent` 使用你的 Helper。**

   `UIComponent` 同时支持"类型名反射创建"和"直接拖入自定义 Helper 预制体"两种方式。选择其中一种:

   - **方式 A —— 通过类型名**:把 `UIComponent` Inspector 上的 `UI Form Helper Type Name` 改为你的类全名(含命名空间)。默认值为 `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`。
   - **方式 B —— 通过预制体**:将你的 `MyUIFormHelper` 挂到一个 GameObject 上做成预制体,拖到 `UIComponent` 的 `Custom UI Form Helper` 字段。运行时 `Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper)` 会优先使用该引用。

   ```csharp
   // Runtime/UIComponent.cs 中读取自定义 Helper 的逻辑
   UIFormHelperBase uiFormHelper = Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper);
   if (uiFormHelper == null)
   {
       Log.Error("Can not create UI form helper.");
       return;
   }
   uiFormHelper.name = "UIFormHelper";
   transform = uiFormHelper.transform;
   transform.SetParent(this.transform);
   transform.localScale = Vector3.one;
   m_UIManager.SetUIFormHelper(uiFormHelper);
   ```
   Source: [Runtime/UIComponent.cs#L526-L538](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L526-L538)

3. **保证类型名命名空间与 ComponentType 一致。**

   启动时 `UIComponent` 会校验:`m_UIFormHelperTypeName` 必须以当前 UI 系统对应的命名空间开头,否则会在控制台报错 `UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.` 并禁用该组件。

   ```csharp
   if (!m_UIFormHelperTypeName.StartsWithFast(namespaceName))
   {
       Debug.LogError("UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.");
       enabled = false;
       return;
   }
   ```
   Source: [Runtime/UIComponent.cs#L437-L442](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L437-L442)

4. **运行时手动替换 Helper(可选)。**

   如果你想在游戏运行中切换 Helper,直接调用 `BaseUIManager.SetUIFormHelper(IUIFormHelper)`:

   ```csharp
   m_UIManager.SetUIFormHelper(new MyUIFormHelper());
   ```
   Source: [Runtime/BaseUIManager.cs#L313-L320](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L313-L320)

## 常见变体

| 场景 | 做法 |
|------|------|
| 接入 FairyGUI | 让 Helper 内部解析 `uiFormAsset` 为 FairyGUI 组件并返回 `GComponent`,`CreateUIForm` 中返回包装该 `GComponent` 的 `IUIForm` 实现。 |
| 接入 UGUI | 直接以 `GameObject` 作为通用载体,在 `InstantiateUIForm` 内调用 `Object.Instantiate`,`CreateUIForm` 内通过 `GetComponent(uiFormType)` 绑定逻辑脚本。 |
| 在运行时热替换 | 通过 `BaseUIManager.SetUIFormHelper` 替换为新的 Helper 实例,但需自行管理旧实例的销毁。 |

## 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| 启动后控制台报错 `UI组件的 UI Form Helper 设置错误。` | `UI Form Helper Type Name` 的命名空间与当前 `ComponentType` 不匹配。 | 把命名空间改为与所选 UI 系统一致(如 FairyGUI 用 `GameFrameX.UI.FairyGUI.Runtime`、`UGUI` 用 `GameFrameX.UI.UGUI.Runtime`)或拖入正确预制体。 |
| 打开界面时报 `Can not create UI form helper.` | 类型名拼写错误或自定义预制体未挂脚本。 | 检查 `m_UIFormHelperTypeName` 完整类名,或确认 `m_CustomUIFormHelper` 预制体上挂的是 `UIFormHelperBase` 子类。 |
| `SetUIFormHelper(null)` 抛异常 | `BaseUIManager` 内部对入参做了非空校验。 | 始终传入非空实例,需清空时换成默认实现。 |

## 背景(可选)

`IUIFormHelper` 把"资源怎么变成 GameObject / GComponent"和"怎么把它与逻辑脚本绑定"这两件事从 UI 管理器里抽离出来,使同一套 `BaseUIManager` 能适配不同 UI 方案。`UIComponent` 在 `Start` 里按"类型名 → 自定义预制体"的优先级创建 Helper,再调用 `BaseUIManager.SetUIFormHelper` 写入框架。
