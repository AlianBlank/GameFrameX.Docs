# 如何刪除不必要的 Unity 套件

使用此工具可以一次從 `Packages/manifest.json` 中刪除指定的相依性，並刪除 `Packages/` 下對應的本機套件目錄。清理完成後，會自動呼叫 `AssetDatabase.Refresh()`。整體流程是透過 Unity Editor 的命令列參數觸發。

## 前置條件

- Unity 專案根目錄中存在 `Packages/manifest.json`（標準的 UPM 專案）。
- 命令列呼叫端能夠透過處理程序參數傳入 `-RemovePackages` 參數（批次、CI、選單呼叫皆可）。
- 需要 `Newtonsoft.Json`（`manifest.json` 的解析依賴此函式庫，Editor 組件中已包含其參考）。

## 操作步驟

1. 準備要刪除的套件名稱清單。套件名稱必須與 `manifest.json` 中 `dependencies` 下的 key 完全一致（例如：`com.unity.xr.management`）。
2. 在 Unity Editor 的命令列中傳入 `-RemovePackages` 參數，其後接上以半形逗號分隔的套件名稱清單。
3. 觸發 `PackageRemovalHelper.Run()` 後，工具會依照以下順序執行：
   - 解析命令列參數以取得要刪除的套件清單。若未傳入 `-RemovePackages`，則直接拋出例外。
   - 從 `manifest.json` 的 `dependencies` 中刪除對應的項目，並透過暫存檔案以原子方式寫回。
   - 刪除 `Packages/<套件名>` 的本機目錄（內嵌套件 / file:// 參照套件）。
   - 呼叫 `AssetDatabase.Refresh()`。

## 常見變化

- **僅清除 `manifest.json`，不刪除本機目錄**：工具會逐一判斷 `dependencies[packageName]` 是否存在。不在 manifest 中的項目僅以 `Debug.Log` 記錄並跳過，不會產生錯誤。
- **僅刪除本機內嵌套件目錄**：若某個本機資料夾未記載於 `manifest.json` 但置於 `Packages/` 下，工具會刪除對應的目錄。反之亦然 — 兩項操作彼此獨立。
- **路徑安全防護**：若套件名稱包含 `/`、`\`、`:`、`..` 中任一項，會被視為不合法並跳過，不會逸出到 `Packages/` 之外。

```csharp
if (string.IsNullOrWhiteSpace(packageName) ||
    packageName.IndexOfAny(new[] { '/', '\\', ':' }) >= 0 ||
    packageName.Contains(".."))
{
    Debug.LogWarning($"[PackageRemoval] 包名不合法，跳过: {packageName}");
    continue;
}
```

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 拋出例外 `未检测到 -RemovePackages 参数。用法: -RemovePackages 包名1,包名2,包名3` | 命令列未傳入 `-RemovePackages`，或忘記附加值 | 在呼叫參數中加入 `-RemovePackages 包名1,包名2` |
| 主控台輸出 `[PackageRemoval] manifest.json 中未找到依赖，跳过: xxx` | `manifest.json` 中沒有該項目（可能僅存在於 `Packages/` 子目錄中） | 確認套件名稱與 `manifest.json` 的 key 完全一致。允許僅刪除本機目錄 |
| `[PackageRemoval] manifest.json 不存在: ...` | 專案並非 UPM 專案，或路徑已被變更 | 確認 `Packages/manifest.json` 位於專案根目錄 |
| `[PackageRemoval] 包名不合法，跳过: xxx` | 名稱中包含 `/`、`\`、`:`、`..` 中任一項 | 僅使用純套件名稱（例：`com.example.foo`）。請勿附加版本號或路徑前綴 |
| `[PackageRemoval] 本地包目录不存在，跳过: xxx` | 僅在 `manifest.json` 中宣告的遠端相依性，本機沒有對應目錄 | 屬於正常情況，無需處理 |

## 背景（可選）

此工具採用「先修改 manifest，接著刪除本機目錄，最後執行 `AssetDatabase.Refresh`」的順序，以避免 Unity 在下次資源重新整理時再次解析已刪除的內嵌套件。`manifest.json` 採用先寫入 `*.tmp` 再覆寫的方式，避免因寫入中斷而造成 JSON 損毀。
