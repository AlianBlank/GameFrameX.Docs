# 实现自定义存储 Helper

继承 [SettingHelperBase](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44) 并实现 `ISettingHelper` 全部成员，把读写真正落到你自己的存储介质（数据库、加密文件、远程接口等）上即可。框架会在启动时通过 `SettingComponent` 调用你的 Helper 完成加载与保存。

## 前置条件

- 已安装 `com.gameframex.unity.setting` 包并能在 Inspector 看到 `SettingComponent`。
- 了解 C# 抽象类与 `MonoBehaviour` 生命周期，Helper 必须挂到场景里的 GameObject 上。
- 自有存储介质（如 SQLite、本地加密文件、远端 Key-Value 服务等）。

## 操作步骤

1. **创建 Helper 类，继承基类**。
   新建脚本 `Assets/Scripts/MySettingHelper.cs`，继承 `GameFrameX.Setting.Runtime.SettingHelperBase`。基类本身是抽象 `MonoBehaviour`，框架靠它拿到所有 `ISettingHelper` 成员。

   ```csharp
   using GameFrameX.Setting.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
   }
   ```

   Source: [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44)

2. **实现必须重写的抽象成员**。基类声明的抽象成员对照表如下，全部用 `override` 实现：

   | 成员 | 签名 | 行为建议 |
   |------|------|---------|
   | `Count` | `int Count { get; }` | 不支持时返回 `-1`（参考 `PlayerPrefsSettingHelper` 的做法） |
   | `Load()` | `bool Load()` | 不需要预加载可直接返回 `true` |
   | `Save()` | `bool Save()` | 真正落盘后再返回 |
   | `GetAllSettingNames()` | `string[] GetAllSettingNames()` | 不支持可 `Log.Warning` 后返回 `null` |
   | `GetAllSettingNames(List<string>)` | `void GetAllSettingNames(List<string> results)` | `results == null` 时抛 `GameFrameworkException("Results is invalid.")`，否则 `results.Clear()` |
   | `HasSetting` / `RemoveSetting` / `RemoveAllSettings` | 见接口 | 委托到自己的存储 |
   | `GetBool/Int/Float/String`、`SetBool/Int/Float/String` | 见接口 | 委托到自己的存储；不存在时返回约定默认值 |

   完整签名参见 [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L42-L42) 与 [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L43-L43)。

3. **把读写委托到具体存储**。最小示例：用内存字典模拟存储。

   ```csharp
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
       private readonly Dictionary<string, string> _store = new Dictionary<string, string>();

       public override int Count => _store.Count;

       public override bool Load() { return true; }

       public override bool Save() { /* 写回文件/数据库 */ return true; }

       public override bool HasSetting(string settingName) => _store.ContainsKey(settingName);

       public override bool RemoveSetting(string settingName) => _store.Remove(settingName);

       public override void RemoveAllSettings() => _store.Clear();

       public override void SetString(string settingName, string value) => _store[settingName] = value;

       public override string GetString(string settingName, string defaultValue)
           => _store.TryGetValue(settingName, out var v) ? v : defaultValue;

       // Bool/Int/Float 同理；布尔可借助 SetInt/GetInt 0/1 存储，参考 PlayerPrefsSettingHelper。
   }
   ```

   Source: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L42-L42)（基类的标准实现范例，演示了如何把 `GetBool`/`SetBool` 委托到底层 `StorageBackend.GetInt/SetInt`）

4. **把脚本挂到场景中的 GameObject**。`SettingHelperBase` 继承自 `MonoBehaviour`，必须挂到 GameObject 才能被 `SettingComponent` 发现并实例化。

5. **在 `SettingComponent` 的 Inspector 中选择 `Custom Setting Helper`**。将 `Setting Helper Type` 设置为你的 `MySettingHelper`，框架启动时会反射创建该 Helper。

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)（`SettingComponent` 负责创建并持有 `ISettingHelper` 实例）

## 常见变体

- **不修改 Helper，只切换底层存储后端**：若你想继续用 `PlayerPrefsSettingHelper`，但希望底层走 SQLite/微信小游戏 SDK，只需要实现一个 `ISettingStorageBackend`，并通过 `SettingStorageBackendFactory.RegisterMiniGameBackend` 在启动阶段注册。`PlayerPrefsSettingHelper` 内部即通过 `StorageBackend` 属性懒加载该后端。

  ```csharp
  // 平台启动时（仅在非 UNITY_EDITOR 下生效）
  SettingStorageBackendFactory.RegisterMiniGameBackend(() => new MySqliteBackend());
  ```

  Source: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

- **小游戏平台实现参考**：`WeChatMiniGameSettingStorage`、`AlipayMiniGameSettingStorage` 等已经按 `ISettingStorageBackend` 接口包装了平台原生 API，可作为最小可用实现范例。

  Source: [WeChatMiniGameSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/MiniGame/WeChat/WeChatMiniGameSettingStorage.cs)、[Storage/ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs)

## 常见错误

- **没继承 `SettingHelperBase`**：直接实现 `ISettingHelper` 也可以，但 `SettingComponent` 通常按 `SettingHelperBase` 派生类扫描；保持继承关系更稳妥。
- **Helper 未挂到场景对象**：`SettingHelperBase` 是 `MonoBehaviour`，未挂载时框架无法实例化，运行时会拿到默认实现或抛异常。
- **`GetAllSettingNames(List<string>)` 中漏掉 `results == null` 校验**：基类期望抛 `GameFrameworkException("Results is invalid.")`，框架其他模块依赖此约定。
- **在 Helper 构造里访问 `UnityEngine.PlayerPrefs` 等需运行时的 API**：不要在静态构造或字段初始化阶段访问 Unity API，应放到 `Load()` 或首次访问时执行。
- **保存逻辑吞掉异常**：写入失败应返回 `false`，让 `SettingComponent` 能感知失败并提示；不要静默 `try/catch` 后返回 `true`。

## 背景（可选）

`PlayerPrefsSettingHelper` 把所有读写转交给 `ISettingStorageBackend`，由 `SettingStorageBackendFactory` 在 `UNITY_EDITOR` 下使用 `UnityPlayerPrefsSettingStorage`、在真机小游戏平台下使用由各平台 adapter 注册的工厂；这是一条"不重写 Helper 也能切换底层存储"的快速通道。只有当业务真正需要一种全新的 Helper 行为（如远端拉取、加密、跨进程同步）时，才需要按本页步骤实现自定义 `SettingHelperBase` 派生类。
