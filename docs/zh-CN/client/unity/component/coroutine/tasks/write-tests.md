# 如何为协程逻辑编写测试

协程逻辑依赖 Unity 运行时（`MonoBehaviour`、`StartCoroutine`），无法在纯 NUnit 编辑器单元测试中直接驱动。本页说明 `GameFrameX.Coroutine.Tests` 的约定，以及在 Unity PlayMode 测试中验证协程行为的做法。

## 前置条件

- 已安装 Unity（与 `com.gameframex.unity.coroutine` 兼容的版本）。
- 已通过 Package Manager 安装本包，Tests 程序集 `GameFrameX.Coroutine.Tests` 会被一并导入。
- 用于 PlayMode 测试时，工程内还需要 `UnityEngine.TestRunner` 与 `UnityEditor.TestRunner` 程序集（默认随 Unity 附带）。

## Tests 程序集约定

`Tests/GameFrameX.Coroutine.Tests.asmdef` 仅在 Editor 平台生效，并通过 `references` 显式依赖 `GameFrameX.Coroutine.Runtime`，避免污染运行时构建。

```json
{
    "name": "GameFrameX.Coroutine.Tests",
    "references": [
        "GameFrameX.Coroutine.Runtime"
    ],
    "rootNamespace": "GameFrameX.Coroutine.Tests",
    "includePlatforms": [
        "Editor"
    ]
}
```

Source: [GameFrameX.Coroutine.Tests.asmdef](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/GameFrameX.Coroutine.Tests.asmdef#L1-L18)

## 操作步骤

### 1. 在 Editor 程序集下放占位单元测试

`Tests/UnitTests.cs` 明确说明：协程模块不能在纯 NUnit 环境运行，因此保留一个占位用例，避免误以为“没有测试覆盖 = 未测试”。

```csharp
using NUnit.Framework;

namespace GameFrameX.Coroutine.Tests
{
    internal class UnitTests
    {
        [Test]
        public void TestPlaceholder()
        {
            // Coroutine 模块依赖 Unity 运行时（MonoBehaviour、StartCoroutine），
            // 无法在纯 NUnit 环境中直接测试协程逻辑。
            // 协程相关的集成测试应在 Unity PlayMode 测试中编写。
            Assert.Pass("Coroutine module requires Unity runtime for testing.");
        }
    }
}
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/UnitTests.cs#L1-L16)

### 2. 编写 PlayMode 测试覆盖真实协程

新建一个 PlayMode 测试程序集（命名空间自定，例如 `GameFrameX.Coroutine.PlayModeTests`），在 `asmdef` 中 `includePlatforms` 留空、`references` 加入 `GameFrameX.Coroutine.Runtime` 与 `nunit.framework`。用例中通过 `GameFrameX.Entry.GetComponent<CoroutineComponent>()` 获取组件，再调用其带 `new` 关键字的 `StartCoroutine` / `StopCoroutine` 来验证行为。

```csharp
using System.Collections;
using GameFrameX.Coroutine.Runtime;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

namespace GameFrameX.Coroutine.PlayModeTests
{
    public class CoroutineComponentTests
    {
        [UnityTest]
        public IEnumerator StartAndStop_TracksEnumerator()
        {
            var component = GameFrameX.Entry.GetComponent<CoroutineComponent>();
            Assert.IsNotNull(component);

            var routine = component.StartCoroutine(Sample());
            yield return null;

            // 同一个 IEnumerator 实例应能被 StopCoroutine 正确终止并移出跟踪表。
            component.StopCoroutine(routine);
            yield return null;
        }

        private static IEnumerator Sample()
        {
            yield return null;
        }
    }
}
```

> 注意：`CoroutineComponent.StartCoroutine` / `StopCoroutine` 使用 `new` 隐藏基类方法，必须通过 `CoroutineComponent` 类型的引用调用，组件才会把协程加入跟踪表。详见 [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L50)。

### 3. 运行测试

- 在 Unity Editor 中打开 **Window → General → Test Runner**。
- 切到 **PlayMode** 标签页，选中刚编写的 PlayMode 程序集，点击 **Run All**。
- 占位 Editor 用例在 **EditMode** 标签页运行，预期结果为 `Passed`。

## 常见变体

- **仅做 EditMode 校验**：保留 `UnitTests.TestPlaceholder` 占位即可，保证 CI 上的 EditMode 套件不会因本模块缺失而报错。
- **结合自定义事件/计时逻辑**：把业务协程封装成返回 `IEnumerator` 的纯方法，在 PlayMode 用例里 `yield return` 多次再断言最终状态。
- **断言异常/日志**：使用 `LogAssert.Expect` 捕获组件在异常协程里输出的日志，避免测试误报失败。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| PlayMode 测试 `CoroutineComponent` 为 `null` | 还未走完 `GameFrameX` 启动流程就取值 | 在 `yield return null` 之后再获取，或在 `[SetUp]` 中等待 `Entry` 初始化完成 |
| `StopCoroutine` 找不到协程 | 通过 `MonoBehaviour` 基类引用调用，绕过了 `new` 隐藏方法 | 始终用 `CoroutineComponent` 类型引用调用 `StartCoroutine` / `StopCoroutine` |
| EditMode 用例运行时报 “Type or namespace not found” | 测试程序集未引用 `GameFrameX.Coroutine.Runtime` | 在 `asmdef` 的 `references` 中加上 `GameFrameX.Coroutine.Runtime` |
| PlayMode 用例被忽略 | PlayMode 程序集 `includePlatforms` 误填了 `Editor` | 将 `includePlatforms` 留空，让程序集在所有平台编译 |

## 背景(可选)

`CoroutineComponent` 用 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 跟踪协程，因此 `StopCoroutine` 必须传入与 `StartCoroutine` 相同的 `IEnumerator` 实例；该约束要求测试在同一次方法调用里持有枚举器引用。
