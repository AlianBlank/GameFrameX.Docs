# 服务启动报 GameApp.Entry / Init 初始化失败怎么办

服务在启动入口 `GameFrameX.Launcher/Program.cs` 调用 `GameApp.Entry` 时抛出异常,或 `Init` 回调中的初始化逻辑报错,导致进程直接退出。本页帮助你按报错信息快速定位是配置、组件注册还是协议扫描出了问题。

## 快速诊断

| 症状 / 报错关键字 | 原因 | 修复 |
|-------------------|------|------|
| `EntryPointNotFoundException` / 找不到 `GameApp.Entry` | 启动项目未引用 `GameFrameX.Launcher` 或基线包未还原 | 见下方"修复步骤 - 1. 入口找不到" |
| `CacheStateTypeManager.Init` 阶段抛异常 | 实体类未实现 `ICacheState` 接口,或程序集未正确加载 | 见下方"修复步骤 - 2. 实体类扫描失败" |
| `MessageProtoHelper.Init` 抛 `NullReferenceException` / 找不到协议 | 协议类库未生成,或传入的 `Assembly` 不包含 `MessageProtoHandler` | 见下方"修复步骤 - 3. 协议初始化失败" |
| `BsonClassMap` 注册冲突(重复注册同一类型) | 重复调用 `Init`,或多个程序集包含同名实体 | 确认仅在启动时调用一次 `Init`,移除重复实体类 |
| `appsettings.json` 解析失败 / 连接字符串为空 | 配置缺失或 `GameFrameX.Config` 配置表未生成 | 见下方"修复步骤 - 4. 配置文件相关" |
| 启动卡住不退出,也无报错 | `Init` 回调中阻塞调用,或后台线程未启动 | 见下方"修复步骤 - 5. 启动卡死" |

## 修复步骤

### 1. 入口找不到 `GameApp.Entry`

`GameApp.Entry` 位于基线引擎包中,启动器依赖它作为启动总入口。

```csharp
// GameFrameX.Launcher/Program.cs
internal static class Program
{
    private static async Task Main(string[] args)
    {
#if DEBUG
        LogOptions.Default.IsConsole = true;
#endif
        await GameApp.Entry(args, () =>
        {
            CacheStateTypeManager.Init();
            MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
        }, LogAction);
    }
}
```

Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L1-L28)

处理方式:

1. 在启动项目根目录执行 `dotnet restore`,确认 NuGet 源可访问。
2. 检查 `.csproj` 中是否引用了 `GameFrameX.Launcher`(或对应的基线包)。
3. 清理输出目录后重新生成:`dotnet clean && dotnet build`。

### 2. `CacheStateTypeManager.Init` 阶段抛异常

`CacheStateTypeManager.Init` 会扫描 `AppsHandler` 所在程序集中所有实现 `ICacheState` 的类型,并把它们的 Bson 映射注册到 MongoDB 驱动。

```csharp
// GameFrameX.Apps/CacheStateTypeManager.cs
public static void Init()
{
    var assembly = typeof(AppsHandler).Assembly;
    BsonClassMapHelper.SetConvention();

    var types = assembly.GetTypes();
    foreach (var type in types)
    {
        var isImplWithInterface = type.IsImplWithInterface(typeof(ICacheState));
        if (isImplWithInterface)
        {
            HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
            BsonClassMapHelper.RegisterClass(type);
        }
    }
}
```

Source: [GameFrameX.Apps/CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L12-L45)

常见原因及处理:

| 子症状 | 处理 |
|--------|------|
| `ReflectionTypeLoadException` | 程序集中存在依赖缺失的程序集,清理 NuGet 后重新生成 |
| `BsonClassMap already registered for type` | 重复调用 `Init`,确认启动入口只调用一次 |
| 某些实体序列化失败 | 在实体类上使用 `[BsonIgnoreExtraElements]` 或按文档补齐字段 |

### 3. `MessageProtoHelper.Init` 协议初始化失败

`Program.cs` 中通过 `MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly)` 把所有协议消息类注册到分发系统。

```csharp
MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
```

Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L12-L16)

处理方式:

1. 确认协议生成器已运行,项目中已生成 `MessageProtoHandler` 等类。
2. 如果你把协议类拆到独立项目,需要把协议项目引用到启动项目中,并把 `typeof(MessageProtoHandler)` 替换为协议项目中对应的入口类型。
3. 若 `Initialize` 抛 "重复请求 ID / 操作编号冲突",说明客户端/服务端协议版本不一致,需重新生成协议并保持版本同步。

### 4. 配置文件相关

启动流程依赖 `GameFrameX.Config` 生成的配置表(例如 `Property`、`PropItem`、`TablesComponent` 等)。这些类会在构造函数末尾调用 `partial void PostInit();`。若配置表文件缺失,会在 `TablesComponent.ResolveRef()` 之前就已经报"找不到表"。

处理方式:

1. 先运行配置生成工具(常见入口是 `GameFrameX.Config.Tools` 或仓库文档中说明的 `dotnet run --project ...` 之类的命令),把所有 `*.cs` 重新生成。
2. 确认 `appsettings.json` 存在,且包含 MongoDB、Redis、网络监听端口等节点。
3. 重新生成后再编译启动项目。

### 5. 启动卡死

如果 `GameApp.Entry` 一直没有返回:

- 检查 `Init` 回调中是否有阻塞调用或同步等待(例如 `Thread.Sleep`、同步 HttpClient)。
- 确认网络监听配置正确,Mongo/Redis 连接可达,网络组件不会因重试而卡死。
- 在调试模式下保留 `LogOptions.Default.IsConsole = true`,便于看到卡死前的日志。

## 验证

按下面顺序验证启动是否恢复正常:

1. 重新执行 `dotnet build`,确保没有重新出现的编译错误。
2. 启动程序,确认日志中出现 `Server started` 或类似的"监听中"提示。
3. 用 `mongosh` 等工具查 Mongo 中的实体集合,确认 `BsonClassMap` 注册成功(无启动期异常)。
4. 客户端发出第一条消息,能正确进入对应的 `MessageProtoHandler` 处理函数。

如果以上均通过,但仍无法启动,请搜集完整启动日志与堆栈,联系框架维护人员并附上报错上下文中 `Program.cs` 调用 `GameApp.Entry` 的源码版本。
