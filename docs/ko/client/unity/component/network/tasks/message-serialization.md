# 커스텀 메시지 직렬화 및 압축

`IMessageSerializer`를 구현하고 `MessageSerializerRegistry.RegisterGlobal()`을 호출해 등록하면, 네트워크 계층의 메시지 인코딩/디코딩을 직접 만든 방식(Protobuf, JSON, MemoryPack 등)으로 교체할 수 있습니다. 압축과 압축 해제는 `IMessageCompressHandler` / `IMessageDecompressHandler` 인터페이스를 구현하여 교체합니다. 직렬 변환기를 등록하지 않으면 프레임워크가 명확한 예외 메시지를 던집니다.

## 사전 조건

- `com.gameframex.unity.network` 패키지가 설치되어 있고 네트워크 컴포넌트 설정이 완료되어 있어야 합니다.
- 커스텀 메시지 타입은 `MessageObject`를 상속해야 합니다(직렬화 메서드의 제네릭 제약 조건 요구 사항).

## 핵심 인터페이스 요약

| 이름 | 실제 시그니처 | 설명 |
|------|----------|------|
| `IMessageSerializer.Serialize<T>` | `byte[] Serialize<T>(T message) where T : MessageObject` | 메시지 객체 직렬화 |
| `IMessageSerializer.Deserialize` | `object Deserialize(byte[] data, Type targetType)` | 대상 메시지 타입으로 역직렬화 |
| `IMessageCompressHandler.Handler` | `byte[] Handler(byte[] message)` | 메시지 데이터 압축 |
| `MessageSerializerRegistry.RegisterGlobal` | `void RegisterGlobal(IMessageSerializer serializer)` | 전역 직렬 변환기 등록 |
| `MessageSerializerRegistry.Global` | `IMessageSerializer Global { get; }` | 전역 직렬 변환기를 가져오며, 등록되지 않은 경우 폴백 구현 반환 |
| `MessageSerializerRegistry.Reset` | `void Reset()` | 기본 폴백 구현으로 재설정 |

압축 인터페이스의 전체 정의는 다음과 같으며, 압축 해제 인터페이스 `IMessageDecompressHandler`가 이와 한 쌍으로 존재합니다:

```csharp
namespace GameFrameX.Network.Runtime
{
    /// <summary>
    /// 메시지 압축기 인터페이스 정의, 메시지 데이터 압축에 사용
    /// </summary>
    public interface IMessageCompressHandler
    {
        /// <summary>
        /// 압축 처리
        /// </summary>
        /// <param name="message">압축되지 않은 메시지 내용</param>
        /// <returns></returns>
        byte[] Handler(byte[] message);
    }
}
```

## 작업 단계

1. **커스텀 직렬 변환기 구현**: 새 클래스를 만들어 `IMessageSerializer`를 구현하고, `Serialize<T>`와 `Deserialize` 두 메서드를 작성합니다. 메서드 시그니처는 기본 구현을 기준으로 합니다:

}

public object Deserialize(byte[] data, Type targetType)

Source: [DefaultMessageSerializer.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageSerializer.cs#L33-L55)

2. **전역 직렬 변환기로 등록**: 게임 초기화 단계(네트워크 채널 생성 이전)에 레지스트리를 호출하여 구현 인스턴스를 전달합니다:

```csharp
public static void RegisterGlobal(IMessageSerializer serializer)
{
    if (serializer == null)
    {
        throw new ArgumentNullException(nameof(serializer));
    }
    _global = serializer;
}
```

Source: [MessageSerializerRegistry.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/MessageSerializerRegistry.cs#L35-L42)

즉, 비즈니스 측에서 `MessageSerializerRegistry.RegisterGlobal(new MyProtobufSerializer());` 한 줄만 작성하면 연동이 완료됩니다.

3. **압축 및 압축 해제 핸들러 구현**: `IMessageCompressHandler`와 `IMessageDecompressHandler`를 각각 구현하고, `Handler(byte[] message)`에서 압축/압축 해제된 바이트 배열을 반환합니다. 프레임워크에는 기본 구현인 `DefaultMessageCompressHandler`와 `DefaultMessageDecompressHandler`(`Runtime/Network/Helper/`에 위치)가 포함되어 있어 커스텀 시 참고할 수 있습니다. 이번 검증 범위에서는 소스 코드에서 압축기의 독립적인 등록 진입점을 찾지 못했으므로, 교체 방법은 위 기본 구현의 호출부를 참조하여 확인하시기 바랍니다.

4. **검증**: 커스텀 메시지 하나를 전송하고 상대편에서 수신된 필드를 출력해 직렬화 및 압축 파이프라인이 정상 동작하는지 확인합니다.

## 자주 발생하는 오류

| 증상/오류 메시지 원문 | 원인 | 해결 방법 |
|------|------|------|
| `InvalidOperationException: No IMessageSerializer registered. Call MessageSerializerRegistry.RegisterGlobal() or provide a channel-level serializer.` | 아무 직렬 변환기도 등록하지 않아 전역이 폴백 구현 `DefaultMessageSerializer`로 설정되었고, 이 구현의 메서드는 항상 해당 예외를 던짐 | 초기화 단계에서 `MessageSerializerRegistry.RegisterGlobal(...)`을 호출하거나, 채널에 채널 수준 직렬 변환기를 제공 |
| `ArgumentNullException` (매개변수 이름 `serializer`) | `RegisterGlobal`에 `null`을 전달함 | `null`이 아닌 구현 인스턴스 전달 |
| 등록 후에도 기존 로직이 계속 사용됨 | 등록 시점이 첫 메시지 송수신보다 늦음 | 등록을 네트워크 채널 생성 이전으로 앞당기고, 필요 시 `MessageSerializerRegistry.Reset()` 호출 후 다시 등록 |

## 배경

`MessageSerializerRegistry`는 내부적으로 `volatile` 필드로 전역 인스턴스를 유지합니다. `Global` 속성은 등록되지 않은 경우 폴백으로 `DefaultMessageSerializer.Instance`를 반환하며, 이 폴백 구현의 메서드 본문은 예외를 던지는 코드 한 줄뿐이라 사용자가 실제 직렬 변환기를 등록하도록 알려주는 역할만 합니다. 따라서 "등록 누락"은 조용히 실패하는 대신 첫 메시지 송수신 시점에 명확한 오류로 드러납니다.
