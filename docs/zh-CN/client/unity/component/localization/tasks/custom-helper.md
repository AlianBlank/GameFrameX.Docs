# 如何自定义本地化 Helper（重写系统语言检测）

自定义本地化 Helper 只需要两步：写一个继承 `LocalizationHelperBase` 的类并重写 `SystemLanguage` 属性，然后在 `LocalizationComponent` 面板上把 Helper 换成你的类型。默认实现使用 `CultureInfo.CurrentCulture` 检测系统语言，重写该属性即可换成任意检测策略（读存档、读账号设置、固定语言等）。

## 前置条件

- 已安装 `com.gameframex.unity.localization` 包。
- 场景中已存在挂有 `LocalizationComponent` 的对象。

## 操作步骤

### 1. 编写自定义 Helper 类

先看基类定义——Helper 是一个 `MonoBehaviour`，唯一需要实现的是只读属性 `SystemLanguage`：

```csharp
namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// 本地化辅助器基类。
    /// </summary>
    [Preserve]
    public abstract class LocalizationHelperBase : MonoBehaviour, ILocalizationHelper
    {
        /// <summary>
        /// 获取系统语言。
        /// </summary>
        [Preserve]
        public abstract string SystemLanguage { get; }
    }
}
```

Source: [LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L37-L48)

默认实现 `DefaultLocalizationHelper` 的写法如下，它取当前区域名并把 `-` 换成 `_`（例如 `zh-CN` → `zh_CN`）：

```csharp
using System.Globalization;
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// 默认本地化辅助器。
    /// </summary>
    [Preserve]
    public class DefaultLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public DefaultLocalizationHelper()
        {
        }

        /// <summary>
        /// 获取系统语言。
        /// </summary>
        [Preserve]
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
    }
}
```

Source: [DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L32-L57)

照着默认实现的骨架，写一个自己的类。下面示例把系统语言固定为 `zh_CN`（结构对照 `DefaultLocalizationHelper` 改写，返回值可换成你自己的检测逻辑，注意保持 `xx_XX` 下划线格式）：

```csharp
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    [Preserve]
    public class MyLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public override string SystemLanguage
        {
            get { return "zh_CN"; } // 在这里实现自己的语言检测
        }
    }
}
```

### 2. 在 LocalizationComponent 上配置自定义 Helper

`LocalizationComponent` 暴露了两个序列化字段用于选择 Helper：

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";

[SerializeField] private LocalizationHelperBase m_CustomLocalizationHelper = null;
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

- 在 Inspector 的 **Localization Helper** 下拉框中选择你的自定义类型（面板内部通过 `HelperInfo<LocalizationHelperBase>` 列出可选 Helper，见 [LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L46)）。
- `m_LocalizationHelperTypeName` 需要是**完整类型名**（含命名空间），参考默认值 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` 的写法。

### 3. 运行时确认 Helper 生效

组件在初始化时通过 `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)` 创建 Helper 实例（见 [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L250)）。运行后查询 `LocalizationComponent` 的系统语言/语言相关属性，返回值应来自你的重写逻辑。

## 常见变体

- **按 Unity 系统语言映射**：在 `SystemLanguage` 的 getter 中根据 Unity 的 `Application.systemLanguage` 映射到项目使用的语言码（如 `zh_CN`、`en_US`）。
- **从存档或账号设置读取**：getter 中读取项目自身的存档/云端设置，返回用户上次选择的语言，实现"首次跟随系统、之后跟随用户设置"。
- **回退默认值**：`LocalizationComponent` 上的 `m_DefaultLanguage` 默认为 `zh_CN`，加载本地化失败时会使用默认语言兜底（见 [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L68)）。可将其与自定义 Helper 配合，保证未支持语言也能显示内容。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| Inspector 里找不到自己的 Helper 类型 | 类未继承 `LocalizationHelperBase`，或不在编译范围内 | 确认类声明为 `public class Xxx : LocalizationHelperBase`，且已保存编译通过 |
| 运行时 Helper 为 null | `m_LocalizationHelperTypeName` 填错（少命名空间、拼写错误） | 类型名必须为完整名（含命名空间），参考默认值 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` |
| 返回语言不生效/匹配不到字典 | 返回的语言码格式不对 | 保持 `xx_XX` 下划线格式（默认实现会把 `-` 替换为 `_`），不要返回 `zh-CN`、`Chinese` 等格式 |
| 自定义 Helper 类被裁剪（IL2CPP/链接器裁剪） | 未标注保留特性 | 类和属性加上 `[Preserve]`（参考默认实现中的用法） |
| 语言切换后界面未刷新 | 直接改 Helper 返回值不触发事件 | 通过 `LocalizationComponent.Language` 的 setter 设置语言，才会触发语言变更事件（Before/Change/After） |

## 背景

`LocalizationComponent` 在初始化时通过 `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)` 按"类型名 + 可选自定义实例"两种方式创建 Helper，因此自定义 Helper 既能通过 Inspector 面板选择（写入类型名字符串），也能直接拖引用。语言获取走 `SystemLanguage` 属性，语言设置与持久化则由组件的 `Language` / `DefaultLanguage` 属性负责（配合 `SettingComponent` 保存），并在切换时依次触发 `LocalizationLanguageChangeBeforeEventArgs`、`LocalizationLanguageChangeEventArgs`、`LocalizationLanguageChangeAfterEventArgs` 三个事件。

关于本地化组件的整体用法，见本包《LocalizationComponent》相关文档。
