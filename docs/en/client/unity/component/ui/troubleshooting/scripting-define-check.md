# What to Do When the Editor Scripting Define Symbol Check Fails

When a dialog saying "No UI system scripting define symbol detected" pops up on Unity editor startup or after scripts recompile, or the console reports that the `UISystemScriptingDefineCheckHandler` check did not pass, it means that neither the `ENABLE_UI_UGUI` nor the `ENABLE_UI_FAIRYGUI` symbol exists under the current `EditorUserBuildSettings.selectedBuildTargetGroup`. The UI system cannot determine which adaptation branch to take, and the missing symbol must be added immediately.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Dialog "No UI system scripting define symbol detected" pops up | Neither the UGUI nor the FairyGUI symbol is enabled | See "Enable the FairyGUI System Symbol" or "Switch to the UGUI System Symbol" below |
| `HasScriptingDefineSymbol` returns `false` even though the symbol was added manually | The check targets `selectedBuildTargetGroup`, while the symbol was only added to other platforms | Switch to the corresponding Build Target and add it again |
| Both symbols exist at the same time | The UI system was switched previously without mutual exclusion | See "What to Do When Both Symbols Exist" below |
| The symbol was added but is still reported as missing | Unity recompilation was not awaited, or the menu method did not trigger the write | Trigger the menu item to write the symbol, then wait for compilation to finish before closing the editor |

The check logic of `UISystemScriptingDefineCheckHandler`:

```csharp
// Editor/UISystemScriptingDefineCheckHandler.cs#L18-L27
var hasUGUIScriptingDefineSymbol = ScriptingDefineSymbols.HasScriptingDefineSymbol(
    EditorUserBuildSettings.selectedBuildTargetGroup,
    UISystemScriptingDefineSymbols.UGUIScriptingDefineSymbol);

var hasFairyGUIScriptingDefineSymbol = ScriptingDefineSymbols.HasScriptingDefineSymbol(
    EditorUserBuildSettings.selectedBuildTargetGroup,
    UISystemScriptingDefineSymbols.FairyGUIScriptingDefineSymbol);

if (!(hasFairyGUIScriptingDefineSymbol || hasUGUIScriptingDefineSymbol))
{
    EditorUtility.DisplayDialog("没有检测到 UI 系统的宏定义存在",
        "将自动启用 FairyGUI 的 UI 系统,可以在菜单 GameFrameX/Scripting Define Symbols 中切换", "我知道了");
    UISystemScriptingDefineSymbols.EnableFairyGUISystem();
}
```

## Fix Steps

### Enable the FairyGUI System Symbol

If neither symbol is enabled when the editor starts, FairyGUI is enabled automatically by default; if it was disabled manually, you can enable it again manually:

1. In the Unity menu bar, select `GameFrameX/Scripting Define Symbols/Enable FairyGUI(开启 FairyGUI 适配)`.
2. Wait for Unity to finish recompiling; the dialog should no longer pop up the next time the editor starts.

The corresponding source code removes the UGUI symbol and adds the FairyGUI symbol in a mutually exclusive manner:

```csharp
// Editor/UISystemScriptingDefineSymbols.cs#L58-L63
[MenuItem("GameFrameX/Scripting Define Symbols/Enable FairyGUI(开启FairyGUI适配)", false, 1001)]
public static void EnableFairyGUISystem()
{
    ScriptingDefineSymbols.RemoveScriptingDefineSymbol(UGUIScriptingDefineSymbol);
    ScriptingDefineSymbols.AddScriptingDefineSymbol(FairyGUIScriptingDefineSymbol);
}
```

### Switch to the UGUI System Symbol

When you have confirmed the project actually uses UGUI:

1. From the menu, select `GameFrameX/Scripting Define Symbols/Enable UGUI(开启 UGUI 适配)`.
2. Wait for compilation to finish, then verify that `ENABLE_UI_UGUI` has been added to `Project Settings/Player/Other Settings/Scripting Define Symbols`.

```csharp
// Editor/UISystemScriptingDefineSymbols.cs#L48-L53
[MenuItem("GameFrameX/Scripting Define Symbols/Enable UGUI(开启UGUI适配)", false, 1000)]
public static void EnableUGUISystem()
{
    ScriptingDefineSymbols.RemoveScriptingDefineSymbol(FairyGUIScriptingDefineSymbol);
    ScriptingDefineSymbols.AddScriptingDefineSymbol(UGUIScriptingDefineSymbol);
}
```

### What to Do When Both Symbols Exist

Manually editing Scripting Define Symbols can easily leave both symbols behind. Based on the UI system the project actually uses, click the corresponding menu item once more to clean them up in a mutually exclusive way (the two methods above internally `Remove` the other symbol first and then `Add` the current one).

### The Check Targets the Current Build Target

`UISystemScriptingDefineCheckHandler` checks `EditorUserBuildSettings.selectedBuildTargetGroup`. If you switched the target platform in `File/Build Settings` (for example, from Standalone to Android), the symbol may only exist on the old platform. To handle this:

1. Switch to the target platform in Build Settings.
2. Run the corresponding menu item again (`Enable UGUI` or `Enable FairyGUI`) to write the symbol into the current Build Target.

## Verification

- Re-trigger the check: right-click any asset in the Project view and choose `Reimport`, or restart the editor; the "No UI system scripting define symbol detected" dialog should no longer appear.
- Open the menu `Edit/Project Settings/Player`, expand `Other Settings/Scripting Define Symbols`, and confirm that `ENABLE_UI_UGUI` or `ENABLE_UI_FAIRYGUI` is listed there.
- Branches wrapped in `#if ENABLE_UI_UGUI` or `#if ENABLE_UI_FAIRYGUI` in code are entered correctly.
