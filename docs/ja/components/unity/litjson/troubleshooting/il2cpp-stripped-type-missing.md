# IL2CPP リリース後に型の欠落やエラーが発生した場合の対処方法

IL2CPP はビルド時にマネージドコードのストリッピング(Managed Code Stripping)を行います。LitJson はリフレクションに依存してリーダー/ライターを生成するため、ストリッピングされると IL2CPP ランタイムで `MissingMethodException` や `InvalidCastException` が発生したり、デシリアライズが空のオブジェクトを返したりします。このページでは、迅速な診断と修正手順を紹介します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `MissingMethodException: ... LitJson ...` | IL2CPP リンカーが LitJson の内部メソッドをストリッピングした | `link.xml` を追加し、`LitJsonCroppingHelper` をアタッチする |
| デシリアライズ結果のフィールドがすべて `null`/デフォルト値になる | `JsonData`/`JsonMapper` のエクスポーターがストリッピングされた | `link.xml` を追加する |
| `JsonMapper.ToObject<T>` がオブジェクトを返すがプロパティが失われる | カスタム T のフィールド/プロパティがストリッピングされた | `link.xml` でアセンブリ単位にその T の型を保持する |
| `Type.GetType("...")` が `null` を返す | IL2CPP では文字列名による、保持されていない型の検索がサポートされていない | ジェネリックの `ToObject<T>()` を使用するか、`link.xml` で該当する型を保持する |
| カスタム Importer/Exporter の登録時に `InvalidCastException` が発生する | デリゲートのターゲットメソッドがストリッピングされた | `link.xml` で自分のアセンブリを保持する |

## 修正手順

### 1. link.xml による宣言的な保持を追加

Unity プロジェクトの `Assets` 配下の任意のサブディレクトリに `link.xml` を作成します(通常は `Assets/link.xml` に配置)。内容は以下の通りで、LitJson アセンブリを明示的に保持する役割を持ちます:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
</linker>
```

ビルド時にはこのファイルに基づいて LitJson 関連の型のストリッピングがスキップされます。これが第一の防御線です。

出典:[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md#L40-L50)

### 2. LitJsonCroppingHelper をアタッチしてランタイムでのストリッピングを防止

リポジトリには `LitJsonCroppingHelper` が同梱されており、`Start()` 内で `typeof(...)` を通じてすべてのパブリックな LitJson 型を明示的に参照し、第二のセーフティネットとして機能します:

```csharp
[Preserve]
public class LitJsonCroppingHelper : UnityEngine.MonoBehaviour
{
    [Preserve]
    public void Start()
    {
        _ = typeof(ArrayMetadata);
        _ = typeof(Condition);
        _ = typeof(ExporterFunc);
        _ = typeof(ExporterFunc<>);
        _ = typeof(JsonIgnoreAttribute);
        _ = typeof(JsonPropertyAttribute);
        _ = typeof(FsmContext);
        _ = typeof(IJsonWrapper);
        _ = typeof(ImporterFunc);
        _ = typeof(ImporterFunc<,>);
        _ = typeof(JsonData);
        _ = typeof(JsonException);
        _ = typeof(JsonMapper);
        _ = typeof(JsonMockWrapper);
        _ = typeof(JsonReader);
        _ = typeof(JsonToken);
        _ = typeof(JsonType);
        _ = typeof(JsonWriter);
        _ = typeof(Lexer);
        _ = typeof(ObjectMetadata);
        _ = typeof(OrderedDictionaryEnumerator);
        _ = typeof(ParserToken);
        _ = typeof(PropertyMetadata);
        _ = typeof(UnityTypeBindings);
        _ = typeof(WrapperFactory);
        _ = typeof(WriterContext);
    }
}
```

このコンポーネントを、シーン内で**最も早く起動する** GameObject(例:`Bootstrap`)にアタッチし、`Start()` がどの `JsonMapper` 呼び出しよりも先に実行されるようにします。

出典:[LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L12-L52)

### 3. カスタムデータ型を保持する

`JsonMapper.ToObject<MyData>("...")` でカスタムクラスをデシリアライズする場合、`MyData` が他のアセンブリに配置されているときは、`link.xml` に保持エントリを追加する必要があります:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
  <assembly fullname="MyGame.Models" preserve="all"/>
</linker>
```

または、特定の型のみを保持してパッケージサイズを削減することもできます:

```xml
<linker>
  <assembly fullname="MyGame.Models">
    <type fullname="MyGame.Models.PlayerData" preserve="all"/>
    <type fullname="MyGame.Models.InventoryItem" preserve="all"/>
  </assembly>
</linker>
```

### 4. 文字列名による型の読み込みへの依存を避ける

`Type.GetType("MyGame.Models.PlayerData, MyGame.Models")` は IL2CPP 環境下では、その型が `link.xml` で保持されていない場合に `null` を返します。推奨事項:

- ジェネリックの `JsonMapper.ToObject<PlayerData>(json)` を使用する。
- または、`link.xml` でその型を明示的に保持する。
- または、`JsonMapper.RegisterImporter<string, Type>(s => Type.GetType(s))` を呼び出してカスタムインポーターを登録する際は、対象の型が保持されていることを確認する。

出典:[UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L47)

### 5. Unity のビルド設定を確認する

1. `Player Settings > Managed Stripping Level`:IL2CPP では `Low` 以下を維持します。`High`/カスタムルールを使用する場合は、必ず `link.xml` を併用してください。
2. `Player Settings > Strip Engine Code`:チェックを外すか、`link.xml` の例外に含めます。
3. Library/ScriptAssemblies をクリーンアップしてから再ビルドし、キャッシュによって設定変更が隠されるのを防ぎます。

## 検証

1. IL2CPP でビルドした後、ゲームを起動して `JsonMapper.ToJson` と `JsonMapper.ToObject` の双方向フローを一度完全に実行し、`MissingMethodException` が発生しないことを確認します。
2. Xcode/Android のログでキーワード `LitJson`、`MissingMethod` を検索し、エラーがないことを確認します。
3. デシリアライズ結果のオブジェクトのフィールド値が元の JSON と一致していること(null/デフォルト値がないこと)を確認します。
4. 一時的に `Managed Stripping Level` を `High` にして再テストし、最も厳しいストリッピング条件下でも `link.xml` と `LitJsonCroppingHelper` が引き続き有効であることを検証します。
