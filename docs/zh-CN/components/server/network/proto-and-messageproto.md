# 添加 Proto 协议并接入 MessageProtoHandler

在 `GameFrameX.Proto` 工程中新增一个 `.proto` 文件后,只要让 `MessageProtoHandler` 类被该程序集承载,启动器就会在初始化阶段自动扫描并注册全部协议消息类型,无需手写注册代码。

## 前置条件

- 解决方案中已存在 `GameFrameX.Proto` 工程,其引用了 `GameFrameX.NetWork 1.13.0` 包,用于协议消息的编解码与分发。
- 目标框架为 `net10.0`(`LangVersion=10`)。
- 业务模块(例如 `GameFrameX.Apps`)通过 `ProjectReference` 引用 `GameFrameX.Proto`,以便生成的协议类型对编译期可见。

## 操作步骤

1. 在 `GameFrameX.Proto/Proto/` 目录下创建 `.proto` 文件,定义消息与服务。例如新建 `GameFrameX.Proto/Proto/Helloworld.proto`:

   ```protobuf
   syntax = "proto3";

   option csharp_namespace = "GameFrameX.Proto";

   package helloworld;

   // 请求消息
   message HelloRequest
   {
       string name = 1;
   }

   // 响应消息
   message HelloReply
   {
       string message = 1;
   }

   service Greeter
   {
       rpc SayHello (HelloRequest) returns (HelloReply);
   }
   ```

   文件直接放在 `Proto` 文件夹下,该文件夹已由 csproj 声明为保留目录,IDE 与 MSBuild 都不会把它当代码编译。

   Source: [GameFrameX.Proto/GameFrameX.Proto.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/GameFrameX.Proto.csproj#L12-L14)

2. 确认 `MessageProtoHandler` 类位于 `GameFrameX.Proto` 程序集内。该类是空壳静态类,作用是充当“协议处理器锚点”,让后续初始化代码能通过它的 `Assembly` 反射到当前程序集里所有的协议消息类型:

   ```csharp
   namespace GameFrameX.Proto;

   /// <summary>
   /// 协议消息处理器
   /// </summary>
   public static class MessageProtoHandler
   {
   }
   ```

   Source: [GameFrameX.Proto/MessageProtoHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/MessageProtoHandler.cs#L1-L8)

3. 在启动入口(目前是 `GameFrameX.Launcher/Program.cs`)调用一次 `MessageProtoHelper.Init`,传入 `MessageProtoHandler` 所在程序集,完成所有 `proto` 消息类型的注册:

   ```csharp
   MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
   ```

   Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L14-L15)

4. 在需要消费协议类型的下游工程中添加项目引用,让生成代码对调用方可见:

   ```xml
   <ProjectReference Include="..\GameFrameX.Proto\GameFrameX.Proto.csproj" />
   ```

   Source: [GameFrameX.Apps/GameFrameX.Apps.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/GameFrameX.Apps.csproj#L10-L10)

5. 编译并启动 Launcher。`MessageProtoHandler` 所在程序集中新增的 `.proto` 消息类型会被自动注册到消息分发管线。

## 常见变体

- **多 `.proto` 文件**:在 `GameFrameX.Proto/Proto/` 下并列放置多个 `.proto` 文件即可,`MessageProtoHelper.Init` 会一次性扫描整个程序集。
- **切换 C# 命名空间**:在每个 `.proto` 文件顶部用 `option csharp_namespace = "Your.Namespace";` 控制生成代码的命名空间,与 `MessageProtoHandler` 所在的 `GameFrameX.Proto` 解耦。
- **不在 Launcher 启动**:只要调用方能够访问 `GameFrameX.NetWork.MessageProtoHelper.Init`,传入 `MessageProtoHandler` 所在程序集即可完成注册,与启动项目无关。

## 常见错误

- **把 `.proto` 放在工程根目录而非 `Proto` 文件夹**:虽然 csproj 没有显式排除,但 `Proto` 文件夹是保留目录,放在更浅的位置容易在后续接入代码生成器时被 `*.proto` 默认规则误处理。
- **忘记 `MessageProtoHelper.Init`**:不调用 `Init` 的话,新协议不会被注册,运行时会找不到消息类型处理器。
- **下游工程未引用 `GameFrameX.Proto`**:即使注册成功,调用方也无法拿到生成的消息类型,编译期会报“找不到类型”。
- **改名 `MessageProtoHandler` 类或类不在 Proto 程序集**:`typeof(MessageProtoHandler).Assembly` 将指向错误的程序集,新协议不会被发现。

## 背景

`GameFrameX.NetWork` 包的 `MessageProtoHelper.Init(Assembly)` 通过反射扫描传入程序集内由 `.proto` 生成的 C# 消息类型并完成注册。`MessageProtoHandler` 在 `GameFrameX.Proto` 中是占位用的静态类,它唯一的“作用”就是让启动器能拿到一个稳定的类型,从而定位到 `GameFrameX.Proto` 程序集——这避免了硬编码程序集名称。
