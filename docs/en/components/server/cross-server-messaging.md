# How to Implement Cross-Server RPC Calls and Unified Message Sending

Through the framework's `IUnifiedMessageSender` interface, player message delivery with "local direct send / cross-server forwarding / offline handling" and cross-server RPC calls with "service discovery + consistent routing + timeout retry" can be accomplished in a single line of code at the business layer, without needing to be aware of the underlying protocols.

## Prerequisites

- The `GameFrameX.NetWork.RemoteMessaging` assembly has been introduced, and `UnifiedMessageSenderHolder.Initialize(...)` is called during the startup phase to initialize the sender.
- The target player has established a route through SessionManager/route resolver (`IPlayerRouteResolver`).
- The message object inherits from `MessageObject` (the response of request-response RPC also needs to implement `IResponseMessage`).

## Steps

### 1. Initialize the Unified Sender During Startup

The business layer obtains an `IUnifiedMessageSender` instance through the global access point `UnifiedMessageSenderHolder.Sender`. The framework has provided a default assembly example in `AppStartUpHotfixGameByEntry`.

```csharp
// Default framework assembly: only depends on SessionManager's in-memory routing state
var remoteClient = RemoteMessagingBuilder.BuildFromEnvironment();
UnifiedMessageSenderHolder.InitializeWithDefaults(
    new DefaultPlayerRouteResolver(),
    remoteClient);
```

If you use custom components (for example, replacing the route resolver or service instance selector), you can also manually construct and inject them through `Initialize(IUnifiedMessageSender)`.

### 2. Send Messages to the Target Player

`SendToPlayerAsync` automatically processes in the order of "local online → local delivery → route resolution → cross-server forwarding → offline handling". The business layer only cares about the return result.

```csharp
var sender = UnifiedMessageSenderHolder.Sender;

var msg = new NotifyFriendOnline
{
    FriendId = 10001,
    OnlineServerId = 3,
};

var result = await sender.SendToPlayerAsync(
    playerId: 10001,
    message: msg,
    options: new PlayerSendOptions
    {
        OfflineStrategy = PlayerOfflineStrategy.StoreOffline,
        TimeoutMs = 3000,
        AllowRetry = true,
        MaxRetryCount = 2,
    });

if (result.Status == PlayerDeliverStatus.RemoteDelivered)
{
    // Delivered to the target server through cross-server forwarding
}
```

The `Status` field of `PlayerSendResult` covers all possible delivery states (`LocalDelivered` / `RemoteDelivered` / `OfflineStored` / `Offline` / `RouteMissing` / `Cancelled` / `Failed`), which can be determined using the enum.

### 3. Initiate Cross-Server RPC (Request-Response)

When calling `SendToServerAsync<TResp>`, the framework will automatically perform service discovery, instance selection, and consistent routing, and return the result as `ServerSendResult<TResp>`.

```csharp
var req = new ReqQueryGuildMembers
{
    GuildId = 42,
    PageIndex = 1,
};

ServerSendResult<RespQueryGuildMembers> rpc =
    await sender.SendToServerAsync<RespQueryGuildMembers>(
        serviceName: GameServerConst.Guild.Name,
        message: req,
        options: new ServerSendOptions
        {
            TimeoutMs = 5000,
            AllowRetry = true,
            MaxRetryCount = 1,
        });

if (rpc.IsSuccess)
{
    // rpc.Response is RespQueryGuildMembers
    foreach (var member in rpc.Response.Members) { /* ... */ }
}
else
{
    // rpc.StatusCode: EndpointNotFound / Timeout / Failed ...
}
```

The internal protocol for "cross-server player forwarding" used by the underlying layer is defined in `ReqSendToPlayerInner` / `RespSendToPlayerInner`, and `TargetPlayerId` and the original `InnerMessage` will be attached during forwarding.

### 4. One-Way Cross-Server Notification (No Response Required)

When no response is needed, use `SendToServerOneWayAsync`:

```csharp
await sender.SendToServerOneWayAsync(
    serviceName: GameServerConst.Chat.Name,
    message: new NotifyServerKickPlayer { PlayerId = 10001 });
```

The returned `ServerSendResult.IsSuccess` indicates whether "the message was successfully sent into the sending channel", and does not guarantee that the receiver has processed it.

## Common Variations

- **The same player may land on different servers**: Just call `SendToPlayerAsync` directly; the business layer doesn't need to manually query the route.
- **Global broadcast requiring "first come, first served"**: Use `SendToServerOneWayAsync` to send to the target service name, and let each instance on the service side handle it individually.
- **Cross-server forwarding fails but the player is known to be offline**: Select `StoreOffline` (temporarily store offline messages) or `Discard` (discard) on `PlayerSendOptions.OfflineStrategy`; by default, it returns failure as `Offline`.
- **Need to track the results**: The sender holds `MessageSendMetrics`, which can be obtained from `UnifiedMessageSenderHolder.Metrics` as aggregated metrics.

## Common Errors

| Symptom | Cause | Mitigation |
|------|------|------|
| `UnifiedMessageSenderHolder has not been initialized. Call Initialize() first during startup.` | `Initialize` was not called during the startup phase | Call `InitializeWithDefaults(...)` first in `AppStartUp` or the service entry point |
| `Service name is empty` | `serviceName` of `SendToServerAsync` is passed as an empty string | Use `GameServerConst.*.Name` constants instead of writing strings manually |
| Status is `RouteMissing` | `IPlayerRouteResolver` did not find the route for this player | Check whether SessionManager/login flow has completed registration |
| Status is `RemoteDelivered` but the receiver did not process it | The receiver has not registered a Handler for the corresponding message | Confirm that the message type has been registered through the source code generator, see the backend diagnostics page for details |
| `Cross-server forwarding failed: ...` | Cross-server forwarding threw an exception (network/timeout) | Set `TimeoutMs` and `MaxRetryCount`, or use `try/catch` as a fallback at the caller |

## Background (Optional)

`UnifiedMessageSender` aggregates four things behind one interface: "local Session delivery", "player route resolution", "cross-server RPC client", and "service instance selector"; the business layer only needs to select the target (`playerId` or `serviceName`) and the strategy (`OfflineStrategy` / `TimeoutMs` / `Retry`), and the details of routing and forwarding are handled by the framework.
