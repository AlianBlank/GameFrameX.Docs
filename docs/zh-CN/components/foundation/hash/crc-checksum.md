# 如何使用 CRC32/CRC64 校验数据

`GameFrameX.Foundation.Hash.CrcHelper` 提供了 CRC32 与 CRC64 两种循环冗余校验算法,支持对字节数组、`Stream` 流(同步与异步)直接计算校验值,并能将 CRC32 整数拆分为大端字节数组用于存储或传输。

## 前置条件

- 引用命名空间 `GameFrameX.Foundation.Hash`,类名为 `CrcHelper`(静态分部类)。
- 目标框架: .NET Standard 2.x 及以上,支持 `Stream`、`Task`、`CancellationToken`。

## 操作步骤

### 1. 计算字节数组的 CRC32

最简调用,传入完整字节数组即可得到 `int` 类型的 CRC32 校验值。

```csharp
using GameFrameX.Foundation.Hash;
using System.Text;

byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data);   // 返回 int
```

Source: [CrcHelper.cs#L121-L126](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L121-L126)

### 2. 计算字节数组指定范围的 CRC32

传入 `offset` 与 `length`,只对字节数组的一段切片计算 CRC32;越界或负数会抛 `ArgumentException`。

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data, offset: 2, length: 5);
```

Source: [CrcHelper.cs#L140-L152](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L140-L152)

### 3. 计算流的 CRC32(同步)

按 4 KB(`CachedBytesLength = 0x1000`)分块读取并计算,适合大文件校验。

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = CrcHelper.GetCrc32(stream);
```

Source: [CrcHelper.cs#L163-L183](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L163-L183)

### 4. 异步计算流的 CRC32

异步版本使用 `Stream.ReadAsync`,支持 `CancellationToken` 取消。

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = await CrcHelper.GetCrc32Async(stream, cancellationToken);
```

Source: [CrcHelper.cs#L188-L202](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L188-L202)

### 5. 计算字节数组 / 流的 CRC64

CRC64 三个公开重载:`GetCrc64(byte[])`、`GetCrc64(Stream)`、`GetCrc64Async(Stream, CancellationToken)`,返回 `ulong`。

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
ulong crc64 = CrcHelper.GetCrc64(data);                 // 字节数组

using var stream = File.OpenRead("big.bin");
ulong crc64FromStream = CrcHelper.GetCrc64(stream);    // 同步流

ulong crc64Async = await CrcHelper.GetCrc64Async(stream); // 异步流
```

Source: [CrcHelper.cs#L66-L110](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L66-L110)

### 6. CRC32 整数转大端字节数组

CRC32 结果常需落地存储,`GetCrc32Bytes` 提供两种用法:

```csharp
int crc32 = CrcHelper.GetCrc32(data);

// 方式一: 返回新的 4 字节数组(大端序)
byte[] bytes = CrcHelper.GetCrc32Bytes(crc32);

// 方式二: 写入已有数组的指定位置
byte[] buffer = new byte[64];
CrcHelper.GetCrc32Bytes(crc32, buffer, offset: 0);
```

Source: [CrcHelper.cs#L212-L257](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L212-L257)

## 常见变体

- **CRC32 搭配字节码循环异或**: `CrcHelper.GetCrc32(stream, code, length)` 是 internal 重载,先把 `code` 字节数组循环异或到数据流上,再算 CRC;适用于带密钥的轻量校验场景。
- **不同数据长度的一致性**: CRC 算法对相同输入始终返回相同结果,故可用于网络包校验、文件指纹、存档完整性校验。
- **大文件流式计算**: 通过 `Stream` 重载(同步/异步)按 4 KB 分块处理,内存占用稳定。

## 常见错误

| 错误现象 | 原因 | 修复 |
|----------|------|------|
| `ArgumentNullException`("bytes") | 传入的 `byte[]` 为 null | 调用前检查或用 `Array.Empty<byte>()` |
| `ArgumentException`(InvalidDataLength) | `GetCrc32(bytes, offset, length)` 的 `offset` 越界或 `length` 为负 | 确保 `offset >= 0`、`length >= 0` 且 `offset + length <= bytes.Length` |
| `ArgumentException`(InvalidDataLength) | `GetCrc32Bytes` 的 `offset` 越界或目标数组剩余空间不足 4 字节 | 保证 `offset >= 0` 且 `offset + 4 <= bytes.Length` |
| `ArgumentNullException`("stream") | 流为 null | 校验流是否成功打开,文件路径是否正确 |
| 计算结果不一致 | 字符串编码不一致(UTF-8 / GBK / UTF-16) | 双方使用同一 `Encoding`,例如都使用 `Encoding.UTF8.GetBytes` |

## 背景(可选)

CRC32 默认多项式 `0xedb88320`、种子 `0xffffffff`(IEEE 802.3 / zlib 同款),CRC64 内部委托给 `Crc64` 类的 `Append` + `GetCurrentHashAsUInt64`。校验值适合做非加密完整性检查,不可代替 HMAC 等带密钥的鉴别算法。
