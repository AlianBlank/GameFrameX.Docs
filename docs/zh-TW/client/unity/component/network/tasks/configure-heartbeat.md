# 設定心跳機制(含應用程式失焦/取得焦點策略)

心跳由兩部分組成：「通道層級設定 + 心跳處理器」。在網路通道上設定 `HeartBeatInterval`(預設 30 秒)並註冊 `IPacketHeartBeatHandler` 處理器，連線便會以該間隔傳送心跳封包；接著在 `NetworkComponent` 上勾選 Focus Heartbeat,心跳就會隨應用程式失去/取得焦點自動停止/啟動，遺漏的心跳則會透過 `NetworkMissHeartBeatEventArgs` 事件回報給業務層。

## 前置條件

- 已安裝 com.gameframex.unity.network 套件，且場景中包含 GameFrameX Entry 與 `NetworkComponent` 元件(選單 `GameFrameX/Network`)。
- 如需自訂心跳訊息結構，請實作 `IPacketHeartBeatHandler`;該介面要求提供心跳間隔屬性：

```csharp
public interface IPacketHeartBeatHandler
{
    float HeartBeatInterval { get; }
}
```

來源:[IPacketHeartBeatHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketHeartBeatHandler.cs#L11)

## 步驟

1. 在 `NetworkComponent` 的 Inspector 面板中勾選 **Focus Heartbeat** 欄位(對應 `m_FocusHeartbeat`,預設為 `false`),以啟用失焦/取得焦點策略：

```csharp
/// <summary>
/// 應用程式取得焦點時是否傳送心跳封包;預設為 false
/// </summary>
[SerializeField] private bool m_FocusHeartbeat = false;
```

來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L65-L68)

2. 勾選後，Unity 的焦點回呼會將焦點狀態同步至網路管理器——失去焦點時 `hasFocus` 為 `false`,重新取得焦點時為 `true`;無需撰寫額外的程式碼：

```csharp
/// <summary>
/// 應用程式取得或失去焦點時呼叫。
/// </summary>
/// <param name="hasFocus">應用程式是否擁有焦點。</param>
private void OnApplicationFocus(bool hasFocus)
{
    if (!m_FocusHeartbeat)
    {
        return;
    }

    m_NetworkManager.SetFocusHeartbeat(hasFocus);
    Log.Info($"SetFocusHeartbeat: {hasFocus}");
}
```

來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L79-L92)

3. 透過 `NetworkComponent.CreateNetworkChannel` 建立通道(內部會自動完成事件與 RPC 逾時的掛接):

```csharp
public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
{
    GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
    var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
    networkChannel.SetIgnoreLogNetworkIds(m_IgnoredSendNetworkIds, m_IgnoredReceiveNetworkIds);
    return networkChannel;
}
```

來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L182)

4. 在取得的 `INetworkChannel` 上註冊心跳處理器，並視需要調整心跳參數：

```csharp
INetworkChannel channel = networkComponent.CreateNetworkChannel("Main", new MyChannelHelper());
channel.RegisterHeartBeatHandler(new MyHeartBeatHandler());
channel.HeartBeatInterval = 15f;                      // 單位:秒,預設 30f
channel.ResetHeartBeatElapseSecondsWhenReceivePacket = true; // 收到任何封包即重設計時器
```

來源:[INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L174)

5. 訂閱心跳遺漏事件。`NetworkComponent` 已在 `Awake` 中將管理器的事件轉發至 GameFrameX 事件系統，因此業務層只需監聽 `NetworkMissHeartBeatEventArgs`:

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
m_NetworkManager.NetworkMissHeartBeat += OnNetworkMissHeartBeat;
m_NetworkManager.NetworkError += OnNetworkError;
```

來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L109-L113)

事件參數透過 `NetworkMissHeartBeatEventArgs.Create(INetworkChannel, int missCount)` 建構，其中包含遺漏次數 `MissCount`:

```csharp
public static NetworkMissHeartBeatEventArgs Create(INetworkChannel networkChannel, int missCount)
{
    NetworkMissHeartBeatEventArgs networkMissHeartBeatEventArgs = ReferencePool.Acquire<NetworkMissHeartBeatEventArgs>();
    networkMissHeartBeatEventArgs.NetworkChannel = networkChannel;
```

來源:[NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L81-L84)

## 通道心跳成員速查表

`INetworkChannel` 上與心跳相關的成員(皆宣告於介面中)：

| 成員 | 簽章/型別 | 說明 |
|------|-----------|------|
| `HeartBeatInterval` | `float { get; set; }` | 心跳間隔(秒)；可在執行時修改；負值會被驗證機制拒絕 |
| `HeartBeatElapseSeconds` | `float { get; }` | 目前心跳已經過的時間，唯讀 |
| `MissHeartBeatCount` | `int { get; }` | 目前累計的心跳遺漏次數，唯讀 |
| `ResetHeartBeatElapseSecondsWhenReceivePacket` | `bool { get; set; }` | 收到任何封包時是否重設心跳計時器 |
| `PacketHeartBeatHandler` | `IPacketHeartBeatHandler { get; }` | 目前已註冊的心跳處理器 |
| `RegisterHeartBeatHandler` | `void RegisterHeartBeatHandler(IPacketHeartBeatHandler handler)` | 註冊心跳處理器 |
| `RegisterHandler` | `[Obsolete("Use RegisterHeartBeatHandler instead")]` | 舊版註冊 API,已棄用 |

執行時，將應用程式切換到背景再切回；若已勾選 Focus Heartbeat,Console 會輸出 `SetFocusHeartbeat: False/True` 日誌，代表焦點策略已生效。

## 常見變體

- **只關心業務封包，不額外傳送獨立的心跳封包**：將 `ResetHeartBeatElapseSecondsWhenReceivePacket` 設為 `true`;任何收到的封包都會重設計時器，唯有長時間確實沒有資料時才會回報心跳遺漏。
- **在執行時動態調整心跳頻率**：直接以 `channel.HeartBeatInterval = newValue;` 對通道賦值；setter 會立即生效，負值則會被驗證機制拒絕(參見 CHANGELOG 中的「HeartBeatInterval 新增負值驗證」條目，來源:[CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md#L77))。
- **多通道差異化心跳**：各通道自行呼叫 `RegisterHeartBeatHandler` 並設定自己的 `HeartBeatInterval`;`NetworkComponent` 的 Focus Heartbeat 開關則統一套用至所有通道。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 切換至背景/返回前景後心跳行為未改變 | `m_FocusHeartbeat` 仍為預設的 `false`,因此 `OnApplicationFocus` 直接返回 | 在 Inspector 中勾選 Focus Heartbeat |
| 未收到心跳遺漏通知 | 只訂閱了管理器的事件，未透過事件系統監聽；或 `NetworkComponent.Start` 未能取得 `EventComponent`(日誌:`Event component is invalid.`) | 確認場景中存在 Event 元件，並監聽 `NetworkMissHeartBeatEventArgs` |
| 設定心跳間隔時報錯/無效果 | 傳入了負值;`HeartBeatInterval` 具有負值驗證 | 傳入正數(單位：秒) |
| 呼叫 `RegisterHandler` 產生編譯警告/錯誤 | 該方法被標記為 `[Obsolete("Use RegisterHeartBeatHandler instead")]` | 改用 `RegisterHeartBeatHandler` |
| 心跳間隔未生效 | 處理器自身的 `IPacketHeartBeatHandler.HeartBeatInterval` 與通道設定衝突，或未註冊任何處理器 | 先呼叫 `RegisterHeartBeatHandler`,再設定通道的 `HeartBeatInterval` |

## 背景

心跳計時發生在通道內部(`NetworkManager.NetworkChannelBase`):預設間隔為 30 秒，累計遺漏次數由 `MissHeartBeatCount` 追蹤；在 `ProcessHeartBeat` 中觸發斷線時，會先將 `Close` 呼叫移到鎖外，以避免巢狀鎖造成死結(參見 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md#L98))。焦點策略由 `NetworkComponent` 監聽 Unity 的 `OnApplicationFocus` 回呼並呼叫 `INetworkManager.SetFocusHeartbeat(bool)` 來實現，因此該策略會套用至管理器下的所有通道。如需網路封包處理流程的整體結構，請參閱「網路元件總覽」。
