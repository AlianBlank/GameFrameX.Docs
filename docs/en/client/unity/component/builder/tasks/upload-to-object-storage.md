# How to Upload Build Artifacts to Object Storage

By passing object storage-related parameters in the Unity command line, the build pipeline can automatically upload logs, assets, or APKs to an S3-compatible object storage (OSS/S3/COS, etc.) after packaging. This page explains the configuration switches and trigger points exposed by this repository, helping you push build artifacts to a remote bucket.

## Prerequisites

- `com.gameframex.unity.builder` has been installed into the Unity project as described in [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md).
- An object storage SDK package implementing `ObjectStorageUploadManager.UploadFile(string)` has been introduced (this repository integrates it via the compile macro `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`; the upload code will not compile when this SDK is not introduced).
- The `Key`, `Secret`, `BucketName`, `EndPoint` (Region/Endpoint) of the object storage bucket have been prepared.

## Steps

1. Prepare the object storage parameters on the build machine. The following four fields are parsed by [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40):

   | Field | Description |
   |------|------|
   | `ObjectStorageKey` | Access Key (Account AccessKey) |
   | `ObjectStorageSecret` | Access Secret |
   | `ObjectStorageBucketName` | Bucket Name |
   | `ObjectStorageEndPoint` | Endpoint of the region where the bucket resides |

2. Pass the above four values through `-ObjectStorageKey`, `-ObjectStorageSecret`, `-ObjectStorageBucketName`, `-ObjectStorageEndPoint` in the Unity command line. The build script will reflectively populate them back into `_builderOptions` via `Builder.BuildParamsParse`.

3. Turn on the corresponding upload switches. The repository provides three non-conflicting boolean switches, see [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L62-L125):

   | Switch | Default | Function |
   |------|--------|------|
   | `IsUploadLogFile` | `false` | Upload logs during build preparation |
   | `IsUploadAsset` | `false` | Upload asset bundles after building assets |
   | `IsUploadApk` | `false` | Upload installer after producing APK |

4. Taking `BuildReady` as an example, the actual trigger code for log upload is in [Builder.BuildReady.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49):

   ```csharp
   AssetDatabase.Refresh();
   if (_builderOptions.IsUploadLogFile)
   {
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.UploadFile(_builderOptions.LogFilePath);
   #endif
   }
   ```

   Source: [Editor/Builder.BuildReady.cs#L43-L49](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49)

   Only when the `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` compile symbol is defined will the `UploadFile` call enter the build; otherwise, the entire block is stripped by the preprocessor and the task will not report an error.

5. Trigger the build. Choose any entry command, and make sure the switches are enabled:

   ```bash
   Unity -batchmode -quit -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildReady \
         -ObjectStorageKey <your-key> \
         -ObjectStorageSecret <your-secret> \
         -ObjectStorageBucketName <your-bucket> \
         -ObjectStorageEndPoint <your-endpoint> \
         -IsUploadLogFile true \
         -IsUploadAsset true \
         -IsUploadApk true \
         -logFile -
   ```

   The parameters are written into the model via reflection by [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L127-L130); you can print `ToString()` in the log for verification.

## Common Variants

- **Only push logs**: only pass `-IsUploadLogFile true`, leaving the other two upload switches at their default `false`.
- **Only push asset bundles**: pass `-IsUploadAsset true` when invoking the `BuildAsset` pipeline.
- **Only push APK**: pass `-IsUploadApk true` when invoking the `BuildApk` pipeline.
- **Environment isolation**: put the four storage parameters into CI environment variables, and have the build script populate them back into the command line.

## Common Errors

- **Runtime error "ObjectStorageUploadManager not found"**: this repository only holds the upload switches; the actual upload class is provided by an external object storage SDK. You need to install the corresponding implementation package in `Packages/manifest.json`, and add `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` to `Scripting Define Symbols` in Player Settings; otherwise the `#if` branch will be stripped.
- **No files in the bucket**: confirm that `ObjectStorageEndPoint` is the Endpoint of the region where the bucket resides (not the console domain), and that the bucket's ACL allows the Key to write.
- **Conflicts when multiple builds upload simultaneously**: the build number `BuildNumber` participates in the remote path (assembled within the external SDK); ensure `BuildNumber` is unique in concurrent scenarios.

## Background (Optional)

The repository is designed as a minimal "switch + compile macro" coupling: `BuilderOptions` is only responsible for moving command-line parameters into the model, and the actual call to `ObjectStorageUploadManager` only appears in the upload branches of the three pipelines `BuildReady`, `BuildAsset`, and `BuildApk`; when `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` is not defined, the upload code is entirely excluded from compilation, ensuring that projects without object storage dependencies can use this tool directly.
