# 엔티티에서 라이프사이클 메서드가 호출되지 않을 때 해결 방법

`ShowEntity` / `HideEntity` 호출 후 엔티티의 `OnInit` / `OnShow` / `OnUpdate` / `OnHide` 중 어느 것도 호출되지 않는 경우, 일반적으로 `EntityLogicType`이 제대로 전달되지 않았거나, 프리팹에 같은 이름의 스크립트가 이미 존재하거나, `EntityComponent`가 초기화되지 않았기 때문입니다. 이 페이지는 "로그 오류 → 근본 원인 → 한 줄 수정" 순서로 빠르게 확인할 수 있도록 구성되어 있습니다.

## 빠른 진단

| 증상(로그/현상) | 근본 원인 | 수정 방법 |
|---|---|---|
| `Entity '{0}' OnInit userData is not ShowEntityInfo.` | `ShowEntity` 호출 시 `ShowEntityInfo`(내부 `EntityLogicType` 포함)를 `userData`로 전달하지 않음 | `ShowEntity<T>` 제네릭 오버로드를 사용하거나, 사용자 정의 `userData` 내부에서 `ShowEntityInfo`로 래핑 |
| `Entity logic type is invalid.` 또는 `Entity '{0}' can not add entity logic.` | `ShowEntityInfo.EntityLogicType`이 `null`이거나, 해당 타입이 `EntityLogic`의 서브클래스가 아니거나, `MonoBehaviour`가 아님 | `EntityLogicType`에 `EntityLogic`을 상속받는 구체적인 `MonoBehaviour` 서브클래스의 `Type`을 할당 |
| `Entity group is inconsistent for non-new-instance entity.` | 동일한 엔티티 객체가 서로 다른 `EntityGroup`에 재사용됨 | `ShowEntity` 호출 시 첫 번째와 동일한 `EntityGroup`을 전달하거나, 객체 풀을 비움 |
| `Entity '{0}' On{Init/Show/Hide} with exception ...` | 직접 구현한 `OnInit/OnShow/OnHide`에서 예외가 발생하여 프레임워크의 `try/catch`에 의해 삼켜짐 | 재정의한 메서드 내부에서 직접 `try/catch`로 디버깅하고, 먼저 `base.OnXxx(...)`가 예외를 발생시키지 않도록 보장 |
| 프리팹에 자신의 스크립트가 이미 부착되어 있어 프레임워크가 새 스크립트를 추가하지 않음 | 프리팹에 동일한 `EntityLogicType` 스크립트가 이미 있어 `Entity.OnInit`에서 재사용되며, 진입 로직이 다른 스크립트에 작성되어 있음 | 비즈니스 로직을 `EntityLogic`을 상속받아 구현하고, 별도의 `MonoBehaviour`를 부착하지 말 것 |
| `OnUpdate`가 호출되지 않음 | `EntityLogic`의 `enabled`가 `OnRecycle`에서 `false`로 설정되었으나, 다시 `ShowEntity` 후에 복원되지 않음; 혹은 `HideEntity` 후 객체가 회수됨 | 서브클래스에서 수동으로 `enabled = false`를 설정하지 말 것; `ShowEntity`가 `OnInit` 경로를 거치는지 확인하고, 객체 풀 점검 |

## 수정 단계

### 1. 제네릭 `ShowEntity`를 사용하여 프레임워크가 자동으로 `EntityLogicType`을 주입하도록 함

프레임워크는 `Entity.OnInit`에서 `userData as ShowEntityInfo`의 `EntityLogicType` 필드를 읽습니다([Entity.cs#L112-L124](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L112-L124)). 가장 실수하기 어려운 방법은 `EntityComponent.ShowEntity<T>`를 직접 사용하는 것입니다:

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

// MyEntityLogic : EntityLogic 이며, EntityId 에 해당하는 프리팹에 부착되어 있다고 가정
GameEntry.GetComponent<EntityComponent>()
    .ShowEntity<MyEntityLogic>(entityId, "Assets/Prefabs/MyEntity.prefab", "Default", userData);
```

출처:[Runtime/Entity/EntityComponent.cs#L48](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L48)

### 2. `EntityLogic` 서브클래스가 `MonoBehaviour`이며 타입이 추가 가능한지 확인

`Entity.OnInit`은 `gameObject.AddComponent(entityLogicType)`을 통해 주입합니다([Entity.cs#L141](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L141-L146)). 따라서:

```csharp
using UnityEngine;
using GameFrameX.Entity.Runtime;

public sealed class MyEntityLogic : EntityLogic   // MonoBehaviour 이어야 함
{
    protected internal override void OnInit(object userData)
    {
        base.OnInit(userData);
        // 초기화 로직
    }

    protected internal override void OnShow(object userData)
    {
        base.OnShow(userData);
        // 매 ShowEntity 호출 시 여기에 진입
    }

    protected internal override void OnHide(bool isShutdown, object userData)
    {
        base.OnHide(isShutdown, userData);
        // 숨김 로직
    }

    protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(elapseSeconds, realElapseSeconds);
        // 매 프레임 로직
    }
}
```

출처:[Runtime/Entity/EntityLogic.cs#L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L40)、[Runtime/Entity/EntityLogic.cs#L133](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L133)、[Runtime/Entity/EntityLogic.cs#L196](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L196)

주의: `EntityLogic`의 라이프사이클 메서드는 모두 `protected internal virtual`로 선언되어 있으므로, 반드시 `override`로 재정의해야 하며 `public` / `private`로 선언해서는 안 됩니다.

### 3. `OnUpdate`가 호출되지 않는 일반적인 원인排查

`Entity.OnRecycle`은 `m_EntityLogic.enabled = false`를 호출합니다([Entity.cs#L173-L174](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L173-L174)). 객체 풀에서 꺼낸 후 `ShowEntity`를 호출할 때, `Entity.OnInit`이 `m_EntityLogic != null`이고 타입이 일치함을 감지하면 `enabled`만 `true`로 재설정합니다([Entity.cs#L130](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L130-L131)). 서브클래스에서 직접 `enabled = false`를 작성하면 재사용 시 더 이상 `OnUpdate`가 호출되지 않으므로 해당 코드를 제거하면 됩니다.

### 4. 로그를 사용하여 호출 체인 검증

위 사항이 모두 정상이지만 여전히 메서드가 호출되지 않는 경우, 각 `override`의 첫 줄에 `Debug.Log`를 추가하여 `ShowEntity` 호출 후 1 프레임 내에 `OnInit` / `OnShow`에 도달하는지 확인합니다. 참고: 각 예외 상황에서 `Entity`는 `Log.Error`를 통해 구체적인 원인을 출력하므로([Entity.cs#L149-L156](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L149-L156)), 코드를 보는 것보다 Console을 확인하는 것이 더 빠릅니다.

## 검증

1. 씬을 실행한 후 첫 `ShowEntity` 호출 시 `OnInit` → `OnShow`의 `Debug.Log`가 표시되고, 이후 매 프레임 `OnUpdate`에 진입해야 합니다.
2. `HideEntity`를 호출하면 `OnHide`가 트리거되고, 객체는 여전히 객체 풀에 존재해야 합니다(씬에는 보이지 않지만 풀 카운트 +1).
3. 동일한 `EntityId`로 다시 `ShowEntity`를 호출하면 (재사용하지 않는 전제하에) `OnInit`이 아닌 `OnShow`만 트리거되어야 합니다(이때는 객체 풀 재사용 경로를 따름).
4. `OnInit/OnShow/OnHide`에서 한 번 `Exception`을 던져 테스트하여, `Log.Error` 메시지가 진단 표의 첫 번째 줄과 일치하는지 확인합니다.

## 배경(선택 사항)

`Entity`는 `MonoBehaviour`이며 `EntityLogic`의 호스트 역할을 합니다: `ShowEntity` → 리소스 로드 → 게임 객체에 `ShowEntityInfo.EntityLogicType`을 통해 `AddComponent<EntityLogic>`을 수행한 후, 순서대로 `OnInit` → `OnShow` → 매 프레임 `OnUpdate` → `HideEntity` 시 `OnHide` → 회수 시 `OnRecycle`이 호출됩니다. 일반적인 오류는 모두 `EntityLogicType`이라는 한 가지 매개변수에 집중되어 있으며, 제네릭 `ShowEntity<T>`이 이를 대신 처리해 줍니다.
