# 如何销毁一个 FSM

调用 `FsmManager` 上的 `DestroyFsm` 重载即可销毁一个有限状态机；销毁后该 FSM 会从管理器中移除，并标记为已销毁(`IsDestroyed == true`)，下一轮 Update 时将不再被驱动。

## 前置条件

- 已在项目中通过 `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IFsmManager>()` 获取到 `IFsmManager` 实例(或通过 `FsmComponent` 获取)。
- 已通过 `CreateFsm` 创建了目标 FSM,并记住其持有者类型 `T` 与名称(`null` 表示匿名)。

## 操作步骤

1. **按持有者类型销毁(匿名 FSM)**

   ```csharp
   IFsmManager fsmMgr = GameFrameX.Runtime.GameFrameworkEntry.GetModule<GameFrameX.Fsm.Runtime.IFsmManager>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>();
   ```

2. **按持有者类型 + 名称销毁**

   ```csharp
   bool ok = fsmMgr.DestroyFsm<MyOwner>("BattleFsm");
   ```

3. **直接传入 FSM 引用销毁**

   当你仍持有 `IFsm<T>` 或 `FsmBase` 句柄时,可直接传入,无需再写泛型与名称:

   ```csharp
   IFsm<MyOwner> fsm = fsmMgr.GetFsm<MyOwner>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>(fsm);   // 泛型重载
   bool ok2 = fsmMgr.DestroyFsm(fsm as FsmBase); // 非泛型重载
   ```

`DestroyFsm` 的返回值为 `bool`,表示是否成功销毁;不存在的 FSM 会返回 `false`。

## 常见变体

- **从 `FsmComponent` 销毁**:`FsmComponent` 内部封装了 `IFsmManager`,可直接使用 `GameEntry.GetComponent<FsmComponent>().DestroyFsm<MyOwner>(name)` 形式。
- **批量清理**:管理器 `Shutdown` 时会遍历并对所有 FSM 调用 `Shutdown()`,无需手动逐个销毁([FsmManager.cs#L138-L147](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L138-L147))。
- **存在性校验**:销毁前可先调用 `HasFsm<T>(name)` 避免重复销毁带来的 `false` 返回。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `DestroyFsm` 返回 `false` | 传入的持有者类型或名称与创建时不一致,或 FSM 已被销毁 | 用 `HasFsm` 校验后再销毁,或直接传 `FsmBase` 句柄 |
| 销毁后仍收到 Update 回调 | 销毁是延迟生效,本帧 Update 已经派发 | 在下一帧再观察;管理器 Update 内会跳过 `IsDestroyed == true` 的 FSM |
| `DestroyFsm(typeof(T))` 抛 `GameFrameworkException("Owner type is invalid.")` | 传入 `null` | 改用泛型重载,或自行判空 |

## 验证

销毁后可通过以下任一方式校验:

```csharp
Assert.IsFalse(fsmMgr.HasFsm<MyOwner>()); // 不存在即成功
Assert.AreEqual(0, fsmMgr.Count);          // 计数应为 0
```

参考单元测试:[UnitTests.cs#L33-L45](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L33-L45)。

## 背景(可选)

`FsmManager` 内部以 `Dictionary<TypeNamePair, FsmBase>` 保存 FSM,Update 循环会先复制一份临时列表再遍历,遍历时跳过 `IsDestroyed == true` 的条目,因此中途销毁不会影响本次迭代。销毁通过 `Shutdown()` 释放状态资源并从字典移除。
