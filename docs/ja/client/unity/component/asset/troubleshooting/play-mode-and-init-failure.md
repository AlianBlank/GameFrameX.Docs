# 実行モードがサポートされていない、または初期化に失敗した場合はどうすればよいか

`AssetManager` はリソースパッケージの初期化時に `EPlayMode` に基づいて4つの具体的な初期化メソッド(Editor シミュレート/オフライン/オンライン/WebGL)にディスパッチします。モード値が列挙型内にない場合は直接例外がスローされます。モードとプラットフォームの不一致、URL の欠落、または YooAsset の初期化未実施も初期化失敗の原因となります。以下に一般的な症状と対応する修正方法を示します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `ArgumentOutOfRangeException: Unsupported play mode: <値>` | `PlayMode` が `EPlayMode` の4つの有効な値内にない | 下記の「修正手順 1」を参照 |
| ビルド/実機で `EditorSimulateMode` を使用しており、リソース読み込みがエラーになる | エディタ以外の環境では自動的に `HostPlayMode` に強制変更されるが、URL が未設定 | 下記の「修正手順 2」を参照 |
| WebGL プラットフォームで `HostPlayMode` などの非 Web モードを選択し、初期化が失敗する | WebGL では `WebPlayMode` が強制的に使用され、非 Web モードはサポートされない | 下記の「修正手順 3」を参照 |
| `hostServerURL is null` またはリソースパッケージを作成できない | オンライン/Web モードで URL が渡されていない;YooAsset が先に初期化されていない | 下記の「修正手順 4」を参照 |
| `Asset manager is invalid.` | `_assetManager` モジュールが登録されていない | 下記の「修正手順 5」を参照 |

## 修正手順

### 1. `PlayMode` の値が不正

`AssetManager.CreateInitializationOperationHandler` は `switch` で4つの有効なモードを照合し、デフォルト分岐で直接例外をスローします:

```csharp
default:
{
    throw new ArgumentOutOfRangeException(nameof(PlayMode), PlayMode, $"Unsupported play mode: {PlayMode}");
}
```

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L42-L46)

`AssetComponent.GamePlayMode` フィールド(Inspector では `m_GamePlayMode` と表示)の値が `EditorSimulateMode / OfflinePlayMode / HostPlayMode / WebPlayMode` の4つの列挙値以内であり、外部スクリプトによって誤って `(EPlayMode)999` のような整数に代入されていないことを確認してください。

### 2. ランタイムで `EditorSimulateMode` を誤用

`AssetComponent.Awake` はエディタ以外の環境で `EditorSimulateMode` を強制的に `HostPlayMode` に変更しますが、オンラインモードではダウンロード URL の指定が必須です:

```csharp
#if !UNITY_EDITOR
    if (GamePlayMode == EPlayMode.EditorSimulateMode)
    {
        GamePlayMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    GamePlayMode = EPlayMode.WebPlayMode;
#endif
#endif
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L65-L73)

修正: ビルド前に `GamePlayMode` をターゲットプラットフォームに合った有効な値に変更してください(オフライン版は `OfflinePlayMode`、オンライン版は `HostPlayMode` を使用し `hostServerURL` を正しく設定)。

### 3. WebGL プラットフォームで非 Web モードを選択

WebGL では `WebPlayMode` への強制変更が発生します。それでも `HostPlayMode` で CDN/ミニゲーム方式を採用したい場合は、`InitPackageAsync` 呼び出し時に正しい `hostServerURL` と `fallbackHostServerURL` を渡し、対応するミニゲームプラットフォームマクロ(`ENABLE_DOUYIN_MINI_GAME`、`ENABLE_WECHAT_MINI_GAME`、`ENABLE_KUAISHOU_MINI_GAME` など)が有効になっていることを確認し、それぞれの `ByteGame/Wechat/Kuaishou` ファイルシステム分岐を経由するようにしてください(`InitializeYooAssetWebPlayMode` を参照)。

### 4. URL の欠落または YooAsset が未初期化

`AssetManager.Initialize` は `InitPackageAsync` より先に呼び出す必要があります。そうでないと YooAsset の内部状態が不完全になります:

```csharp
public void Initialize()
{
    Log.Info($"资源系统运行模式：{PlayMode}");
    YooAssets.Initialize();
    YooAssets.SetOperationSystemMaxTimeSlice(Milliseconds > 0 ? Milliseconds : 30);
    Log.Info("Asset Init Over");
}
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L45-L54)

`InitPackageAsync` は引数に対して `NotNull` 検証を行い、いずれかが空の場合 `ArgumentNullException` をスローします:

```csharp
GameFrameworkGuard.NotNull(packageName, nameof(packageName));
GameFrameworkGuard.NotNull(hostServerURL, nameof(hostServerURL));
GameFrameworkGuard.NotNull(fallbackHostServerURL, nameof(fallbackHostServerURL));
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L69-L71)

修正: `AssetComponent.Start` が既にトリガーされている(これは `_assetManager.Initialize()` を呼び出します)ことを確認し、`InitPackageAsync(packageName, host, fallbackHost, isDefaultPackage:true)` を呼び出す際に有効な URL を渡してください。

### 5. `Asset manager is invalid.`

`AssetComponent.Awake` が `IAssetManager` モジュールを取得できない場合、致命的なログを出力して直接 return します:

```csharp
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L82)

修正: GameFrameX フレームワークのエントリ(`GameEntry`)がシーンに存在し、`AssetComponent` の `ImplementationComponentType`/`InterfaceComponentType` の設定が正しいこと、フレームワークがリフレクションで `AssetManager` 実装クラスを構築できることを確認してください。

## 検証

1. Unity Console でログ `资源系统运行模式：<PlayMode>` と `Asset Init Over` の両方が表示されることを確認します。両方表示されていれば `Initialize()` が完了しています。
2. `InitPackageAsync` を呼び出した後、`InitializationOperation` の完了を待ちます。`true` を返し `Status == EOperationStatus.Succeed` であれば、リソースパッケージの初期化は成功です。
3. `LoadAssetAsync` を一度トリガーし、`AssetHandle` が取得でき、`LastError` が空であることを確認します。
4. ビルドプラットフォーム(WebGL/Android/iOS)で上記の手順を繰り返し、`Unsupported play mode` や `hostServerURL is null` が再度スローされないことを確認します。
