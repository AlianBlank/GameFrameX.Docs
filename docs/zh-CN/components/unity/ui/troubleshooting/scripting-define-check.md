# 编辑器脚本宏检查失败怎么办

当 Unity 编辑器启动或脚本重编后弹出 "没有检测到 UI 系统的宏定义存在" 对话框,或控制台报 `UISystemScriptingDefineCheckHandler` 检查未通过时,意味着当前 `EditorUserBuildSettings.selectedBuildTargetGroup` 下既没有 `ENABLE_UI_UGUI` 也没有 `ENABLE_UI_FAIRYGUI` 这两个宏,UI 系统无法判定走哪条适配分支,需要立即补上。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 弹窗 "没有检测到 UI 系统的宏定义存在" | UGUI 与 FairyGUI 两个宏都未启用 | 见下方"启用 FairyGUI 系统宏"或"切换到 UGUI 系统宏" |
| `HasScriptingDefineSymbol` 返回 `false`,但宏已手动添加 | 检查的是 `selectedBuildTargetGroup`,而宏只加到了其它平台 | 切到对应 Build Target 后重新添加 |
| 两个宏同时存在 | 之前切换 UI 系统时未互斥 | 见下方"两个宏同时存在怎么办" |
| 加了宏仍提示缺失 | 未等待 Unity 重编译,或菜单方法未触发写入 | 触发菜单项写入后,等待编译完成再关闭编辑器 |

`UISystemScriptingDefineCheckHandler` 的判定逻辑:

```csharp
// Editor/UISystemScriptingDefineCheckHandler.cs#L18-L27
var hasUGUIScriptingDefineSymbol = ScriptingDefineSymbols.HasScriptingDefineSymbol(
    EditorUserBuildSettings.selectedBuildTargetGroup,
    UISystemScriptingDefineSymbols.UGUIScriptingDefineSymbol);

var hasFairyGUIScriptingDefineSymbol = ScriptingDefineSymbols.HasScriptingDefineSymbol(
    EditorUserBuildSettings.selectedBuildTargetGroup,
    UISystemScriptingDefineSymbols.FairyGUIScriptingDefineSymbol);

if (!(hasFairyGUIScriptingDefineSymbol || hasUGUIScriptingDefineSymbol))
{
    EditorUtility.DisplayDialog("没有检测到 UI 系统的宏定义存在",
        "将自动启用 FairyGUI 的 UI 系统,可以在菜单 GameFrameX/Scripting Define Symbols 中切换", "我知道了");
    UISystemScriptingDefineSymbols.EnableFairyGUISystem();
}
```

宏常量定义:

```csharp
// Editor/UISystemScriptingDefineSymbols.cs#L42-L43
public const string UGUIScriptingDefineSymbol = "ENABLE_UI_UGUI";
public const string FairyGUIScriptingDefineSymbol = "ENABLE_UI_FAIRYGUI";
```

## 修复步骤

### 启用 FairyGUI 系统宏

编辑器启动时若检测到两个宏都没启用,默认会自动启用 FairyGUI;若手动关闭过,可手动再启用:

1. 在 Unity 菜单栏选择 `GameFrameX/Scripting Define Symbols/Enable FairyGUI(开启 FairyGUI 适配)`。
2. 等待 Unity 重新编译完成,再次启动编辑器时不应再弹窗。

对应源码会互斥地移除 UGUI 宏、添加 FairyGUI 宏:

```csharp
// Editor/UISystemScriptingDefineSymbols.cs#L58-L63
[MenuItem("GameFrameX/Scripting Define Symbols/Enable FairyGUI(开启FairyGUI适配)", false, 1001)]
public static void EnableFairyGUISystem()
{
    ScriptingDefineSymbols.RemoveScriptingDefineSymbol(UGUIScriptingDefineSymbol);
    ScriptingDefineSymbols.AddScriptingDefineSymbol(FairyGUIScriptingDefineSymbol);
}
```

### 切换到 UGUI 系统宏

确认项目确实使用 UGUI 时:

1. 菜单选择 `GameFrameX/Scripting Define Symbols/Enable UGUI(开启 UGUI 适配)`。
2. 等待编译完成,验证 `ENABLE_UI_UGUI` 已加入 `Project Settings/Player/Other Settings/Scripting Define Symbols`。

```csharp
// Editor/UISystemScriptingDefineSymbols.cs#L48-L53
[MenuItem("GameFrameX/Scripting Define Symbols/Enable UGUI(开启UGUI适配)", false, 1000)]
public static void EnableUGUISystem()
{
    ScriptingDefineSymbols.RemoveScriptingDefineSymbol(FairyGUIScriptingDefineSymbol);
    ScriptingDefineSymbols.AddScriptingDefineSymbol(UGUIScriptingDefineSymbol);
}
```

### 两个宏同时存在怎么办

手动编辑过 Scripting Define Symbols 容易残留两个宏。按项目所用的实际 UI 系统,再点一次对应菜单项即可互斥清理(上述两个方法内部会先 `Remove` 另一个宏再 `Add` 当前宏)。

### 检查的是当前 Build Target

`UISystemScriptingDefineCheckHandler` 检查的是 `EditorUserBuildSettings.selectedBuildTargetGroup`。如果在 `File/Build Settings` 中切换了目标平台(例如从 Standalone 切到 Android),宏可能只存在于旧平台。处理方式:

1. 切到目标 Build Settings 平台。
2. 重新走一次对应菜单项(`Enable UGUI` 或 `Enable FairyGUI`),把宏写入当前 Build Target。

## 验证

- 重新触发检查:在 Project 视图右键 `Reimport` 任一资源,或重启编辑器,不应再弹出 "没有检测到 UI 系统的宏定义存在"。
- 菜单 `Edit/Project Settings/Player`,展开 `Other Settings/Scripting Define Symbols`,确认其中有 `ENABLE_UI_UGUI` 或 `ENABLE_UI_FAIRYGUI`。
- 代码侧用 `#if ENABLE_UI_UGUI` 或 `#if ENABLE_UI_FAIRYGUI` 包裹的分支能正确进入。
