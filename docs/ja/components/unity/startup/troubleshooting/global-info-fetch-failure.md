# グローバル情報インターフェースの取得に失敗した場合の対処方法

起動フローが `ProcedureGetGlobalInfoState` に入った後、すべての `GlobalInfoUrls` が設定の返却に失敗し(かつ利用可能なローカルキャッシュが存在しない場合)、`StartupFailedEventArgs` がトリガーされ、`ProcedureGetGlobalInfoState` を失敗フロー名として起動が終了します。本文書では、よくある原因、切り分け方法、および対応する修正について説明します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 起動直後に `ArgumentException`: `StartupOptions.GlobalInfoUrls must contain at least one URL.` がスローされる | `StartupOptions.GlobalInfoUrls` が `null` または空の配列 | 「修正手順 1」を参照 |
| フローがグローバル情報リクエストをスキップし、直接 `ProcedurePatchInit` に遷移する | `SkipRemoteStartupRequests = true`、または `GamePlayMode` が `EditorSimulateMode` / `OfflinePlayMode` | 「修正手順 2」を参照 |
| 失敗イベント `StartupFailedEventArgs` 内の `procedureName = "ProcedureGetGlobalInfoState"`、UI の `Loading... (n/total)` 表示のまま固まる | URL フェイルオーバーがすべて失敗(ネットワーク/タイムアウト/HTTP エラー/サーバーが非成功コードを返却) | 「修正手順 3」を参照 |
| 一度失敗した後も起動が成功し、UI に `Using cached startup config...` が表示される | 前回成功した結果が `StartupNetworkCacheUtility` によってキャッシュに書き込まれており、今回はフォールバックロジックで動作している | 「修正手順 4」を参照 |
| WebGL/スタンドアロン環境でバックエンドにアクセスできず、起動がネットワーク段階で固まる | リモート起動リクエストを有効にすべきでない | 「修正手順 2」の `SkipRemoteStartupRequests` の使い方を参照 |

`procedureName`、`failedUrl`、`errorMessage` の 3 つのフィールドは [`StartupProcedureUtility.CompleteFailure`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L162-L167) によって `StartupFailedEventArgs` に書き込まれるため、正確な切り分けに利用できます。

## 修正手順

### 修正手順 1:空の `GlobalInfoUrls` が設定されている

`StartupRunner.Run` は async ステートマシンに入る前に同期的に検証を行います:

```csharp
// Runtime/Startup/StartupRunner.cs
if (options.GlobalInfoUrls == null || options.GlobalInfoUrls.Length == 0)
{
    throw new ArgumentException(
        "StartupOptions.GlobalInfoUrls must contain at least one URL.",
        nameof(StartupOptions.GlobalInfoUrls));
}
```

Source: [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L63-L68)

`StartupOptions` アセットに少なくとも 1 つの URL を入力します:

```csharp
// Runtime/Startup/StartupOptions.cs
[Header("Network")] [Tooltip("全局信息接口 URL 主备列表，按顺序尝试。空数组视为配置错误。")]
public string[] GlobalInfoUrls = new string[0];
```

Source: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### 修正手順 2:実行環境でリモートリクエストを発行すべきでないケース

`ProcedureGetGlobalInfoState.OnEnter` には 3 つの早期リターン分岐があり、いずれかが該当するとグローバル情報インターフェースがスキップされます:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode)
{
    Debug.Log("Editor simulate mode, skip global info request.");
    ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
    return;
}

if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}

if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L28-L48)

対応する処理:

| シナリオ | 設定すべき値 | 備考 |
|------|--------|------|
| エディター シミュレーションモード | `GamePlayMode = EPlayMode.EditorSimulateMode` | エディターでのみ有効。非エディター環境では `StartupRunner.NormalizeAssetPlayMode` が `HostPlayMode` に書き換えます |
| オフラインモード | `GamePlayMode = EPlayMode.OfflinePlayMode` | 直接 `ProcedurePatchInit` に遷移し、リモートへの試行は行われません |
| WebGL スタンドアロン / バックエンドなし | `SkipRemoteStartupRequests = true` | フィールドの説明は [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31) を参照 |

### 修正手順 3:URL フェイルオーバーがすべて失敗

`GetGlobalInfoAsync` は [`UrlFailoverRunner.ExecuteAsync`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L67-L92) を通じて `GlobalInfoUrls` を順番に試行し、各 URL 内部で最大 `MaxAttemptsPerUrl` 回、試行間の待ち時間は `RetryDelayMs` ミリ秒です。HTTP 例外または `responseGlobalInfo.IsSuccess == false` のいずれかが発生すると、その試行は失敗とみなされます:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var json = await GameEntry.GetComponent<WebComponent>().PostToString(url, jsonParams);
var responseGlobalInfo = json.Result.ToHttpJsonResultData<ResponseGlobalInfo>();
if (!responseGlobalInfo.IsSuccess)
{
    return UrlAttemptResult.Fail("Global info server returned code " + responseGlobalInfo.Code);
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L75-L84)

以下の順序で切り分けを行います:

1. `StartupOptions` に少なくとも 1 つのアクセス可能な URL が入力されており、「メイン→バックアップ」の順に並んでいることを確認します。
2. ブラウザー/Postman でその URL に直接 `POST` リクエストを送り、同じ `jsonParams`(`StartupProcedureUtility.CreateHttpParams` で生成)を使用して、サーバーが `IsSuccess == true` を返すことを確認します。
3. `MaxAttemptsPerUrl`(デフォルト 3)と `RetryDelayMs`(デフォルト 3000)が小さすぎて、不安定なネットワーク環境で試行回数が早々に尽きてしまっていないか確認します:

   ```csharp
   // Runtime/Startup/StartupOptions.cs
   public int MaxAttemptsPerUrl = 3;
   public int RetryDelayMs = 3000;
   ```
   Source: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L26-L28)

4. `IStartupHttpParamsProvider` で `PackageName` / `Channel` / `SubChannel` などの共通パラメーターがサーバー側で正しく認識されていることを確認します。欠落や誤りがあると、サーバーが非成功コードを返す原因になります。

### 修正手順 4:ローカルキャッシュによるフォールバックの有効化

すべての URL が失敗した場合、`GetGlobalInfoAsync` は前回成功時に書き込まれたキャッシュの読み取りを試みます。ヒットすれば起動を続行します:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (!result.Success)
{
    if (StartupNetworkCacheUtility.TryApplyCachedGlobalInfo())
    {
        uiHandler?.SetTipText("Using cached startup config...");
        ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
        return;
    }

    StartupProcedureUtility.CompleteFailure(
        procedureOwner,
        nameof(ProcedureGetGlobalInfoState),
        result.FailedUrl,
        result.ErrorMessage);
    return;
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L94-L109)

- キャッシュキーは `GameFrameX.Startup.NetworkCache.GlobalInfo` で、[`StartupNetworkCacheUtility`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupNetworkCacheUtility.cs#L23) によって管理されます。
- 不安定なネットワーク環境でも起動を続行させたい場合は、まず良好なネットワーク環境で完全なフローを 1 回実行してキャッシュを書き込み、その後フォールバックロジックを維持します。
- キャッシュを使用させず「ネットワーク失敗時に即座にエラーを出す」ようにしたい場合は、呼び出し側で `StartupResult` を取得した際に `ProcedureName == "ProcedureGetGlobalInfoState"` を明示的に判定し、ユーザーにネットワークの確認を促します。

## 検証

1. アプリケーションを再起動し、起動フローがグローバル情報インターフェースの失敗によって中断されなくなったことを確認します。
2. 起動失敗時に `StartupFailedEventArgs` を確認します:`procedureName` が `ProcedureGetGlobalInfoState` ではなくなっているか、起動が `Using cached startup config...` のパスで完了しているはずです。
3. `StartupOptions` Inspector([`StartupOptionsInspector`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Editor/StartupOptionsInspector.cs#L24-L66) がドラッグによる並べ替え UI を提供)で、`GlobalInfoUrls` の順序が正しく、空文字列が含まれていないことを確認します。
