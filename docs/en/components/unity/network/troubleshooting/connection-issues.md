# What to Do About Connection Failures or Connection Interruptions

When a connection fails or is interrupted, GameFrameX Network reports error codes and `NetworkCloseReason` close reasons to the upper layer via `NetworkErrorEventArgs` (which includes `ErrorCode`, `SocketErrorCode`, `ErrorMessage`) as well as the connection state events `NetworkConnectedEventArgs` / `NetworkClosedEventArgs`. First subscribe to these events to obtain the error code, then match it against the error codes/close reasons in the table below to locate and fix the issue.

## Quick Diagnosis

| Symptom (Error Code / Close Reason) | Root Cause | Fix |
|------|------|------|
| Close reason is `ConnectAddressError` | Server address or port has an invalid format (e.g., URL missing a scheme, port out of range) | Verify the connection address; see "Check the Address and Port" below |
| Close reason is `ConnectAddressExceptionError` | Address resolution threw an exception (e.g., invalid IP string, DNS failure) | Switch to a valid address and verify resolution; see "Check the Address and Port" below |
| Error code `AddressFamilyError` | The configured `AddressFamily` does not match the actual address family (IPv4/IPv6 mismatch) | Make the channel's AddressFamily consistent with the server address; see "Verify AddressFamily" below |
| Error code `ConnectError`, with `SocketErrorCode` of `ConnectionRefused` / `TimedOut` | Server not listening, firewall blocking, or network unreachable | Confirm the server is running and the port is allowed through |
| Error code `SocketError` / `SendError` / `ReceiveError` | The underlying Socket failed during send/receive | Locate the issue by `SocketErrorCode`; commonly caused by continuing to send/receive after the connection was closed by the peer |
| Close reason is `MissHeartBeat`, error code `MissHeartBeatError` | Judged as disconnected due to heartbeat timeout | Adjust the heartbeat interval and check the "focus-controlled heartbeat" configuration; see "Troubleshoot Heartbeat Disconnections" below |
| Close reason is `Timeout` (WebSocket) | WebSocket connection establishment timed out, triggering a protective close | Check the ws/wss address and the server handshake duration; if necessary, upgrade to a version that includes connection timeout protection (see CHANGELOG) |

The error codes and close reasons above are actual definitions from the source code. For the complete set of values, see [NetworkErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkErrorCode.cs#L38-L136):

## Fix Steps

### Step 1: Subscribe to the error and close events to get the real error code

During initialization, `NetworkComponent` already bridges channel events to `m_NetworkManager`'s `NetworkConnected` / `NetworkClosed` and other events:

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L108-L110)

The error event carries three diagnostic fields; `SocketErrorCode` is the raw `System.Net.Sockets.SocketError` value:

```csharp
public INetworkChannel NetworkChannel { get; private set; }
public NetworkErrorCode ErrorCode { get; private set; }
public SocketError SocketErrorCode { get; private set; }
public string ErrorMessage { get; private set; }

public static NetworkErrorEventArgs Create(INetworkChannel networkChannel, NetworkErrorCode errorCode, SocketError socketErrorCode, string errorMessage)
```

Source: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L71-L104)

In the error callback, print the three values `ErrorCode`, `SocketErrorCode`, and `ErrorMessage`, then match them against the diagnosis table above.

### Check the Address and Port

1. If the close reason is `ConnectAddressError` or `ConnectAddressExceptionError`, first confirm the address string itself is valid: use `IP:port` for TCP, and `ws://host:port` or `wss://host:port` for WebSocket.
2. From a machine on the same network as Unity, verify the server is reachable using `telnet host port` (TCP) or by accessing it directly in a browser (WebSocket); if unreachable, first resolve the server listening or firewall issue.
3. Confirm you are not opening multiple channel instances using the same address simultaneously, which could cause the server to actively refuse connections.

### Verify AddressFamily

`AddressFamilyError` indicates that the configured address family does not match the actual address. This commonly happens when the server address is IPv6 (or the domain resolves to IPv6) while the channel connects as IPv4 (`InterNetwork`). Making the `NetworkAddressFamily` used at channel initialization match the actual family of the server address will eliminate this error. For the available family definitions, see [NetworkAddressFamily.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkAddressFamily.cs).

### Troubleshoot Heartbeat Disconnections

1. When `MissHeartBeat` / `MissHeartBeatError` occurs, it means the channel did not receive a heartbeat reply within the expected time, and the component closed the connection due to a "missing heartbeat".
2. This package supports "focus-controlled heartbeat" (pausing heartbeats when the app goes to the background and resuming them when it returns to the foreground). Make sure your background/foreground transition logic matches the server's timeout threshold: staying in the background too long will cause the server to judge the connection as timed out.
3. Appropriately increase the heartbeat interval limit or the server-side timeout, then retest.

## Verification

- After reconnecting, the `NetworkConnected` event fires normally, and no more `NetworkErrorEventArgs` or `NetworkClosedEventArgs` (with a reason other than `Normal`) are received for a period of time.
- For WebSocket channels, a long suspension (going to the background and then returning to the foreground) no longer results in a `Timeout` close.
- In heartbeat scenarios, the `NetworkMissHeartBeatEventArgs` event is no longer triggered (see [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs)).

## Background

Errors and closes are split into two event chains: transient errors go through `NetworkErrorEventArgs` (fine-grained error codes + raw `SocketError`), while the connection lifecycle goes through `NetworkConnectedEventArgs` / `NetworkClosedEventArgs` (including `NetworkCloseReason`). Issues such as WebSocket connection timeout protection, connection event ordering, and `SystemTcpNetworkChannel` receive failure handling have already been fixed in the CHANGELOG. If you encounter strange disconnections, first confirm you are on the latest package version; see [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md) for details.
