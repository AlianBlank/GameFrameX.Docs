# ダウンロードイベントの購読（開始/進捗/成功/失敗）

`EventComponent` を使って `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` の 4 つのイベントを購読すると、ダウンロードタスクのライフサイクルの任意の段階でコールバックを受け取ることができ、UI プログレスバーや通知メッセージ、失敗時のリトライロジックを駆動できます。

## 前提条件

- `com.gameframex.unity.download` パッケージがインストール済みであり、`GameEntry` に `DownloadComponent` がアタッチされていること。
- プロジェクト内で GameFrameX の `EventComponent` が有効になっていること（`DownloadComponent` はこれを通じてすべてのダウンロードイベントを配信します）。
- 有効なローカル保存パスとリモートダウンロードアドレスが用意されていること。

## 操作手順

1. `DownloadComponent` と `EventComponent` のインスタンスを取得します：

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   var eventComponent    = GameEntry.GetComponent<EventComponent>();
   ```

2. `EventComponent.Subscribe` を使って 4 つのイベントを購読します。コールバックのシグネチャは `void Handler(object sender, GameEventArgs e)` に固定されています：

   ```csharp
   eventComponent.Subscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Subscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

3. ダウンロードタスクを追加し、返された `serialId` を記録します。コールバック内でどのダウンロードかを区別するために使用します：

   ```csharp
   int serialId = downloadComponent.AddDownload(
       "/本地保存路径/file.zip",      // downloadPath
       "https://example.com/file.zip" // downloadUri
   );
   ```

4. 4 つのコールバック内で `GameEventArgs` を対応する型にキャストし、フィールドを読み取ります：

   ```csharp
   void OnDownloadStart(object sender, GameEventArgs e)
   {
       var args = (DownloadStartEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadUpdate(object sender, GameEventArgs e)
   {
       var args = (DownloadUpdateEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadSuccess(object sender, GameEventArgs e)
   {
       var args = (DownloadSuccessEventArgs)e;
       if (args.SerialId == serialId)
       {
           // ダウンロード完了：args.DownloadPath / args.DownloadUri / args.CurrentLength / args.UserData
       }
   }

   void OnDownloadFailure(object sender, GameEventArgs e)
   {
       var args = (DownloadFailureEventArgs)e;
       Debug.LogError($"ダウンロード失敗：{args.ErrorMessage}");
   }
   ```

5. 使用後は必ず `Unsubscribe` を呼び出し、メモリリークや誤発火を防ぎます：

   ```csharp
   eventComponent.Unsubscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Unsubscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Unsubscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

## よくあるバリエーション

- **SerialId によるフィルタリング**：同じ `DownloadComponent` で複数のタスクが並行して実行される可能性があるため、コールバック内で `args.SerialId == serialId` を使ってどのダウンロードかを区別します。
- **UserData 付きのタスク**：`AddDownload` のオーバーロードを呼び出す際に `userData` を添付できます。4 つのイベント引数にはすべてそのまま引き渡されるため、ビジネスコンテキストをコールバックに一緒に持ち込むのに便利です。
- **完了結果だけを受け取りたい場合**：4 つのコールバックを書きたくない場合は、代わりに `await downloadComponent.Download(...)` を使用できます。詳細は README の「非同期用法」セクションを参照してください。

## よくある間違い

- **EventId の記述ミス**：必ず `XxxEventArgs.EventId` 定数を使用し、自分で文字列を組み立てないでください。ソースコードでは 4 つの `EventId` はいずれも `typeof(XxxEventArgs).FullName` であり、書き間違えるとイベントを購読できなくなります。
- **コールバックは受信したが SerialId が一致しない**：並行ダウンロード時にコールバック内で `args.SerialId` をフィルタリングしておらず、他のタスクの結果を自分のものと見なしてしまいます。
- **`Unsubscribe` を忘れた**：スクリプトの破棄やシーン切り替え後に購読を解除していないと、コールバックが古いインスタンスに保持され続け、メモリリークや重複発火を引き起こしやすくなります。
- **`WWWDownloadAgentHelper` 使用時に取得できるのは旧版のイベントチェーン**：4 つの `DownloadXxxEventArgs` は `DownloadComponent` 層の統一イベントであり、下層の `DownloadAgentHelper` のイベントとは異なります。UI の進捗には前者を購読し、Helper 層のイベントを直接購読しないでください。

## 背景（任意）

4 つの `DownloadXxxEventArgs` はいずれも `GameFrameX.Event.Runtime.GameEventArgs` を継承しており、`DownloadComponent` が内部ステートマシンの切り替え時に `EventComponent.Fire(this, ...)` を通じて配信します。`AddDownload` の後に Start、ダウンロード中に Update、最終的に Success または Failure が配信されます。イベント機構により、呼び出し側は `DownloadComponent` の返却オブジェクトを保持しなくても非同期通知を受け取ることができます。
