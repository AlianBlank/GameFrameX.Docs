# How to Handle Special Floating-Point Values and Unicode Escaping

When serializing with `JsonHelper.DefaultOptions`, the framework automatically writes/reads back literals not permitted by the JSON specification—such as `NaN`, `Infinity`, and `-Infinity`—as strings, and uses `UnicodeJsonEncoder` to prevent Chinese characters and Emoji from being converted to `\uXXXX`, all out of the box.

## Prerequisites

- Reference the namespace `GameFrameX.Foundation.Json`.
- Use the framework-provided `JsonHelper.ToJson(...)` / `JsonHelper.ToObject<T>(...)`, or directly reuse `JsonHelper.DefaultOptions` as the `JsonSerializerOptions`.

## Steps

### 1. Serialize Special Floating-Point Numbers with the Default Configuration

`DefaultOptions` already registers `SpecialFloatingPointConverter` and `SpecialFloatingPointConverterFloat`, which serialize `double.NaN` / `double.PositiveInfinity` / `double.NegativeInfinity` (as well as the `float` equivalents) as `"NaN"`, `"Infinity"`, and `"-Infinity"`, and restore them during deserialization.

```csharp
using GameFrameX.Foundation.Json;

var payload = new
{
    A = double.NaN,
    B = double.PositiveInfinity,
    C = double.NegativeInfinity,
    D = 3.14,
};

string json = JsonHelper.ToJson(payload);
// Result: {"A":"NaN","B":"Infinity","C":"-Infinity","D":3.14}
```

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L107-L117)

### 2. Recognize Special Floating-Point Strings During Deserialization

The same converter matches `NaN` / `Infinity` / `-Infinity` using `OrdinalIgnoreCase` in `Read`, and throws a `JsonException` when it encounters an unrecognized string.

```csharp
using GameFrameX.Foundation.Json;

var obj = JsonHelper.ToObject<Sample>("{\"V\":\"NaN\"}");
// obj.V == double.NaN

var obj2 = JsonHelper.ToObject<Sample>("{\"V\":\"-Infinity\"}");
// obj2.V == double.NegativeInfinity

public sealed class Sample { public double V { get; set; } }
```

Examples of the original exception messages:
- `Cannot convert JSON string 'xxx' to Double.`
- `Cannot convert JSON token 'xxx' to Double.`

Source: [SpecialFloatingPointConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/SpecialFloatingPointConverter.cs#L58-L95)

### 3. Prevent Chinese Characters/Emoji from Being Escaped to `\uXXXX`

`JsonHelper.DefaultOptions.Encoder` is explicitly set to `UnicodeJsonEncoder.Singleton`. This encoder follows RFC 8259 §7, escaping only `"`, `\`, `/`, and control characters (`\b` `\f` `\n` `\r` `\t` as well as `<= \u001f`), while all other characters are output as-is.

```csharp
using GameFrameX.Foundation.Json;

string json = JsonHelper.ToJson(new { Name = "张三", Emoji = "😀" });
// Result: {"Name":"张三","Emoji":"😀"}
```

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L96-L96) and [UnicodeJsonEncoder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/UnicodeJsonEncoder.cs#L186-L195)

## Common Variants

- `JsonHelper.FormatOptions`: Enables indented, pretty-printed output while maintaining the behavior described above.
- Only need a custom encoder: You can directly assign `UnicodeJsonEncoder.Singleton` to your own `JsonSerializerOptions.Encoder` without depending on `JsonHelper`.
- `float` version: The converter chain includes `SpecialFloatingPointConverterFloat`, so `float.NaN` / `float.PositiveInfinity` / `float.NegativeInfinity` follow the same set of rules.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L110-L116), [SpecialFloatingPointConverterFloat.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/SpecialFloatingPointConverterFloat.cs#L46-L46)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Chinese characters become `\u4E2D\u6587` when calling `System.Text.Json.JsonSerializer.Serialize` directly | No encoder specified; `JavaScriptEncoder.Default` is used | Reuse `JsonHelper.DefaultOptions`, or set `Encoder = UnicodeJsonEncoder.Singleton` yourself |
| `double.NaN` is serialized as the illegal JSON literal `NaN` (other libraries may refuse to parse it) | `SpecialFloatingPointConverter` is not registered | Use `JsonHelper.ToJson`, or add the converter to your custom `JsonSerializerOptions.Converters` |
| Deserializing `"NaN"` throws `JsonException: The JSON value could not be converted to System.Double` | Missing `JsonNumberHandling.AllowNamedFloatingPointLiterals` or a custom converter | Use `JsonHelper.DefaultOptions` (which has this flag enabled and the converter registered) |

## Background (Optional)

`UnicodeJsonEncoder` minimizes escaping according to the `char` rules of RFC 8259 §7 by overriding `FindFirstCharacterToEncode` and `TryEncodeUnicodeScalar`; the special floating-point converters round-trip `NaN`/`±Infinity` as strings, bypassing the JSON specification's own numeric literal restrictions, thereby remaining compatible with front-end implementations such as `JSON.parse`.
