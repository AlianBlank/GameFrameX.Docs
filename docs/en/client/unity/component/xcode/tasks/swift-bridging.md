# Enabling Objective-C/Swift Mixed-Language Bridging

Set `swiftBridging` to `true` in `XCodeConfig.json` (or leave it at the default — this option is **enabled by default**). After building the iOS project, GameFrameX will automatically generate the Swift bridging file and bridging header file, and set `SWIFT_VERSION=5.0` and `SWIFT_OBJC_BRIDGING_HEADER`, with no Xcode pop-ups at any point, making it directly usable in CI.

## Prerequisites

- The GameFrameX Xcode Config package has been imported into the project, and basic configuration has been completed according to the "XCodeConfig.json Configuration Overview" (this package automatically runs post-processing during iOS builds; no API calls are needed).
- The build target is the iOS platform (the relevant code is inside the `#if UNITY_IOS` block).

## Steps

1. Open the `XCodeConfig.json` in the project root (or module directory) and set `swiftBridging` to `true`:

   ```json
   {
     "swiftBridging": true
   }
   ```

   > This key can be omitted — when omitted, it is treated as `true` (enabled by default). See the source code below for the decision logic:

   ```csharp
   // Set up Swift bridging (enabled by default)
   bool swiftBridging = !finalConfig.ContainsKey("swiftBridging") || finalConfig.Get<bool>("swiftBridging");
   SetupSwiftBridging(project, project.GetUnityMainTargetGuid(), project.GetUnityFrameworkTargetGuid(), path, swiftBridging);
   ```

   Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101)

2. Run an iOS build in Unity (File → Build Settings → Build); the post-processing stage will automatically:

   - Create `gameframex_swift_bridging.swift` in the root of the generated Xcode project (written only if it does not exist; content is `import Foundation`, with the file header marked `DO NOT EDIT`);
   - Create the `Unity-iPhone-Bridging-Header.h` bridging header file;
   - Add the `.swift` file to the UnityFramework target for compilation, and add the bridging header file to the project;
   - Set `SWIFT_VERSION = 5.0` for both the main target and the UnityFramework target, and set `SWIFT_OBJC_BRIDGING_HEADER = Unity-iPhone-Bridging-Header.h` for the main target.

   Core implementation:

   ```csharp
   proj.AddFileToBuild(frameworkTargetGuid, proj.AddFile(swiftFile, SwiftBridgingFileName, PBXSourceTree.Source));
   proj.AddFile(bridgingHeaderFile, SwiftBridgingHeaderName, PBXSourceTree.Source);

   proj.SetBuildProperty(mainTargetGuid, "SWIFT_VERSION", "5.0");
   proj.SetBuildProperty(mainTargetGuid, "SWIFT_OBJC_BRIDGING_HEADER", SwiftBridgingHeaderName);

   proj.SetBuildProperty(frameworkTargetGuid, "SWIFT_VERSION", "5.0");

   LogHelper.Log("[SwiftBridging] Swift bridging header configured");
   ```

   Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L37-L45)

3. Verify the result: open the generated `.xcodeproj`, select the **Unity-iPhone** target → Build Settings:
   - `SWIFT_VERSION` shows `5.0`;
   - `SWIFT_OBJC_BRIDGING_HEADER` shows `Unity-iPhone-Bridging-Header.h`;
   - The Unity Console outputs `[SwiftBridging] Swift bridging header configured`.

## Common Variants

- **Disabling mixed-language bridging**: explicitly write `"swiftBridging": false`. `SetupSwiftBridging` starts with `if (!enabled) return;`; when disabled, no files are created and no Swift build properties are set.
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L12-L14)
- **Exposing Objective-C headers in the bridging header**: the bridging header file is only generated when it does not exist and is never overwritten afterward (checked via `File.Exists`). You can directly append `#import` statements to the generated `Unity-iPhone-Bridging-Header.h`, and repeated builds will not lose your changes.
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L27-L35)
- **Multi-module collaboration**: multiple `XCodeConfig.json` files are deeply and recursively merged, and the merged `swiftBridging` value takes effect; if not specified in any configuration, it defaults to `true`.
  Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L100)

## Common Errors

- **Swift file not visible in Xcode / `SWIFT_OBJC_BRIDGING_HEADER` is empty**: most likely `swiftBridging` was explicitly set to `false` in one of the `XCodeConfig.json` files during the merge. Check all configuration files involved in the merge.
- **Bridging header changes "disappeared"**: check whether the Xcode project directory was regenerated (Unity's overwrite export rebuilds the directory). The bridging header is only written when the file does not exist; it is recommended to place custom `#import` statements in a stable location that won't be overwritten, or inject them with your own script.
- **Swift syntax errors / version mismatch**: this package always writes `SWIFT_VERSION = 5.0`; do not manually change it back to an older value in the project, as repeated builds will overwrite it back to 5.0.
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L40-L43)

## Background

This feature only affects the **Unity-iPhone (main) target and the UnityFramework target**: the Swift file is added to the UnityFramework target for compilation, and `SWIFT_OBJC_BRIDGING_HEADER` is only set on the main target. Unlike the "Would you like to create a bridging header?" dialog that appears when manually creating a Swift file in Xcode, this process is completed entirely by the post-processing script, so unattended builds in CI environments will not be blocked by pop-ups.
