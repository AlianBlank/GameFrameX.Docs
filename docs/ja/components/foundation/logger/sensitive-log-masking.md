# 機密ログフィールドのマスキング方法

`SensitiveLogEventEnricher` + `SensitiveLogPropertyPolicy` を利用することで、ログイベントが Sink に到達する前に `token`、`password`、`authorization` などの機密フィールドを統一的にプレースホルダーに置換し、認証情報がログファイルに直接書き込まれることを防ぎます。

## 前提条件

- `GameFrameX.Foundation.Logger` を参照していること(デフォルトでログモジュールと一緒に読み込まれ、フレームワーク自身の `LogHandler` には自動的にデフォルトポリシーが適用されます)。
- Serilog の構造化ログ属性(`LogContext.PushProperty` またはテンプレートプレースホルダー)を使用して値を受け取ること。本メカニズムは属性名の一致によって判定するため、メッセージ文字列全体は解析しません。

## 操作手順

### 1. フレームワークのデフォルトポリシーを使用する(ゼロ設定)

`LogHandler` は Serilog pipeline の構築時に `SensitiveLogEventEnricher()` を自動的に追加しているため、デフォルトで内蔵の10個のフィールド名に対してマスキングが行われます。

```csharp
// フレームワークにはデフォルトで組み込まれているため、手動登録は不要
.Enrich.With(new SensitiveLogEventEnricher())
```

ソース: [GameFrameX.Foundation.Logger/LogHandler.cs#L119](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHandler.cs#L119)

デフォルトでカバーされるフィールド名(大文字小文字を区別しない):

| フィールド名 |
|--------|
| `token`、`access_token`、`refresh_token` |
| `password`、`passwd` |
| `authorization`、`cookie` |
| `apiKey`、`secret`、`clientSecret` |

ソース: [GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53)

置換テキストのデフォルトは `[REDACTED]` です(`replacement` に空文字列が渡された場合も `[REDACTED]` にフォールバックします)。

### 2. 機密フィールド名をカスタマイズする

追加のフィールドコレクションを渡すことでデフォルトポリシーを上書きできます(コレクションは「渡したものがそのまま全集合」となるため、デフォルトに加えて追加したい場合はまず `SensitiveLogPropertyPolicy.Default` のフィールド名を連結してください):

```csharp
using GameFrameX.Foundation.Logger;

var policy = new SensitiveLogPropertyPolicy(
    new[] { "IdCard", "Phone", "BankAccount" },
    replacement: "***");

var enricher = new SensitiveLogEventEnricher(policy);

// カスタム LoggerConfiguration に組み込む
Log.Logger = new LoggerConfiguration()
    .Enrich.With(enricher)
    .WriteTo.Console()
    .CreateLogger();
```

ソース: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53)

フィールド名の一致には `StringComparer.OrdinalIgnoreCase` が使用されるため、`Password` と `password` の両方がヒットします。

### 3. マスキングが有効であることを確認する

`Password` 属性を含むログを書き込み、出力が `[REDACTED]` に変わることを確認します:

```csharp
using Serilog.Context;

using (LogContext.PushProperty("Password", "my-secret-password"))
{
    Log.Information("Login attempt for {UserId}", 42);
}
```

期待される出力では `Password` フィールドの値が `[REDACTED]` となり、実際のパスワードにはなりません。Enricher は `StructureValue`、`SequenceValue`、`DictionaryValue` を再帰的に処理するため、構造化オブジェクト内のネストされた機密フィールドも置換されます。

ソース: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103)

## よくあるバリエーション

- **モデルフィールドレベルのマスキング**:ORM エンティティに注釈を付けて(リスト/エクスポート/シリアライズ時に統一処理)したい場合は、`GameFrameX.Foundation.Orm.Attribute` の `[SensitiveField(MaskingStrategy.Phone)]` を使用します。ポリシーは Phone、IdCard、Email、BankCard、Name、Address、Custom をカバーします。これはログ Enricher とは別の独立した仕組みであるため、シリアライズ層に別途組み込む必要があります。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }
}
```

ソース: [GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

- **カスタムプレースホルダーへの置換**:`SensitiveLogPropertyPolicy` を構築する際に第2引数(例: `"***"`、`"已脱敏"`)を渡します。空文字列を渡した場合は `[REDACTED]` にフォールバックします。
- **ネストされたオブジェクトのマスキング**:Enricher はデフォルトで `StructureValue` / `SequenceValue` / `DictionaryValue` を再帰処理するため、追加設定は不要です。属性名がポリシーにヒットした場合のみ、値がまとめて置換されます。

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| ログに依然として平文の token が現れる | 認証情報がメッセージテンプレート内に書かれている(例: `Log.Info("token={0}", token)`)ため、構造化属性になっていない | `Log.Information("token={Token}", token)` のように構造化属性を使用するように変更する |
| カスタムフィールド名が有効にならない | フィールド名にスペースが含まれているか、ポリシーと綴りが一致していない | `_propertyNames` は `OrdinalIgnoreCase` で完全一致するため、名称を確認する |
| ポリシーに `null` コレクションを渡した | コンストラクタが `ArgumentNullException` をスローする | 少なくとも `Array.Empty<string>()` を渡すか、カスタムコレクション側で null チェックを行う |
| モデルフィールドがマスキングされない | `[SensitiveField]` は ORM シリアライズ層にのみ作用し、Serilog には自動連携されない | ログ側でも `SensitiveLogEventEnricher` を併用する |

## 背景(任意)

`SensitiveLogEventEnricher` は Serilog の `ILogEventEnricher` を実装し、`Enrich` 段階で `LogEvent.Properties` をインプレースで置換します。ポリシーオブジェクトは「機密フィールド名の集合 + 置換テキスト」を管理します。一連の処理はイベントが Sink に到達する前に完了するため、ファイル、コンソール、リモート送信などすべての下流で元の値を見ることはありません。
