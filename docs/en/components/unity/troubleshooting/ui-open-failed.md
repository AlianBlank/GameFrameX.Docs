# What to Do When a UI Fails to Open or Shows a White Screen

When you call `GameApp.UI.OpenAsync<T>()` and the interface does not appear, displays as a white screen, or the entire screen is unresponsive, it is usually because the FairyGUI asset package was not loaded first, the UI path is written incorrectly, or the UI component is not attached to the scene root node. This page provides troubleshooting methods organized by symptom.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| No error after `GameApp.UI.OpenAsync<UILogin>()`, but nothing appears | The FairyGUI package containing the target UI was not loaded with `AddPackageAsync` | Call `GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.XXX))` before opening the UI |
| Reports "package not found" or asset loading fails | `FUIPackage` enum entry is wrong / package name does not match the packaged assets | Verify the `FUIPackage` enum values against the actual package names exported in the FairyGUI editor |
| UI opens but the entire screen is blank | A non-fullscreen API was used while the target UI is an `OpenFullScreen` type, so it is covered by other layers | Switch to `OpenFullScreenAsync<T>(path, group)` and pass in the corresponding `UIGroupConstants` |
| Reports "UI path not found" | The `nameof(X)` class name in `GetUIPath(nameof(X))` does not match the actual class | The class name must match the `X.cs` generated from `Package_XXX` in the FairyGUI assets |
| Calling `GameApp.UI` in the Hotfix reports it is null | It was accessed before `LoadUI()` finished executing | `await` the loading above, or put the subsequent logic into the continuation of `OpenAsync` |
| The UI pops up but immediately disappears | `CloseUIForm` was not awaited, or a higher layer immediately calls `OpenUIForm` to cover it | Check the call order and make sure `CloseUIForm<T>` is called after `await OpenAsync` |

## Fix Steps

### 1. UI Does Not Appear at All — Load the Missing FairyGUI Package

The framework requires that the corresponding FairyGUI asset package be loaded before opening any UI. `HotfixLauncher.LoadUI` already demonstrates the standard approach:

```csharp
#if ENABLE_UI_FAIRYGUI
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommon));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommonAvatar));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UIRoom));
#endif
await GameApp.UI.OpenAsync<UILogin>();
```

The `FUIPackage.XXX` enum values must match the package names exported from the FairyGUI editor (e.g., `UIRoom`, `UICommon`). If a package is missed, all UIs in that package will fail to open.

Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L46)

### 2. White Screen or Covered — Use the Correct Opening API

Opening "fullscreen-type UIs" (login, character list, main interface) must use `OpenFullScreenAsync` and pass in a UI group:

```csharp
await GameApp.UI.OpenFullScreenAsync<UIPlayerList>(
    Utility.Asset.Path.GetUIPath(nameof(UILogin)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

The regular `OpenAsync<T>()` is suitable for non-fullscreen components such as popups and alert boxes. If the target UI is actually a fullscreen layout but `OpenAsync` is used, you will see a white screen where the UI "seems to open but is actually covered or not drawn".

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 3. Reopening After Closing Requires await

`CloseUIForm` must happen after `await OpenAsync/OpenFullScreenAsync`; otherwise the higher-level UI will cover the current interface first:

```csharp
await GameApp.UI.OpenFullScreenAsync<UIMain>(
    Utility.Asset.Path.GetUIPath(nameof(UIMain)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 4. Keep Class Names Consistent with the FairyGUI Generated Code

The `X` passed into `GetUIPath(nameof(X))` must match the class name of the `Package_X.cs` generated by the FairyGUI export tool. If you rename a class and forget to sync it, you will get path-not-found errors, a white screen, or the previous old interface opening instead.

### 5. Example of Closing a Popup-Style UI

The generic confirm/cancel popup is closed by calling directly:

```csharp
GameApp.UI.CloseUIForm<UIDialogMessageBox>();
data.OnEnter?.Invoke();
```

Source: [UIDialogMessageBox.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UICommon/UIDialogMessageBox.cs#L22-L29)

### 6. UI Closing During the Launcher Stage

`LauncherUIHandler` closes the startup screen once initialization is complete:

```csharp
GameApp.UI.CloseUIForm<UILauncher>();
_ui = null;
```

Source: [LauncherUIHandler.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/LauncherUIHandler.cs#L66-L67)

## Verification

- In `LoadUI()`, register all the `FUIPackage` enum entries used by the UIs; the corresponding package loading lines should appear in the startup log.
- After `await OpenAsync<T>()` returns, you should see the `T` instance attached under FairyGUI's Stage in the Hierarchy, rather than remaining outside the Root.
- When switching fullscreen UIs, during the transition the old interface is covered by the new one instead of a white screen flashing by.
- After closing, calling `OpenAsync<T>()` again displays the new interface normally (indicating the assets were not reclaimed all at once, or you have correctly released them in the destruction logic).

## Background (Optional)

`HotfixLauncher.LoadUI` first preloads the base packages `UICommon`, `UICommonAvatar`, and `UIRoom`, and then awaits `OpenAsync<UILogin>`. The subsequent chained navigation of `UIPlayerList → UIMain` all follows the pattern of "await the open → CloseUIForm itself", which is also the key convention for avoiding white screens / layer confusion.
