# Advertisement manager is invalid怎么办

런타임 콘솔에 `Log.Fatal("Advertisement manager is invalid.")`이 표시되면, `AdvertisementComponent.Awake()`에서 `GameFrameworkEntry.GetModule<IAdvertisementManager>()`로 광고 매니저 인스턴스를 가져올 수 없다는 의미이며, 컴포넌트가 바로 return되고 이후의 `Start`, `Initialize` 등의 흐름이 실행되지 않습니다.

## 해결 단계

### 1. 씬에 AdvertisementComponent가 존재하는지 확인

`AdvertisementComponent`는 광고 시스템 진입 컴포넌트이며, 이것이 없으면 프레임워크가 광고 매니저 모듈을 등록하지 않습니다. 부착 방법:

1. 첫 번째 시작 씬에 빈 GameObject를 생성합니다 (일반적으로 `GameFrameX`).
2. `Add Component → GameFrameX/Advertisement`를 선택하여 `AdvertisementComponent`를 부착합니다.

### 2. Inspector에서 componentType을 올바르게 입력

`AdvertisementComponent`는 리플렉션을 통해 광고 매니저를 로드하므로, **반드시** `BaseAdvertisementManager`를 상속한 구체적인 구현 클래스의 전체 이름(네임스페이스 + 클래스명)을 입력해야 합니다. 그렇지 않으면 `Utility.Assembly.GetType(componentType)`이 `null`을 반환하여 모듈이 등록되지 않습니다.

일반적인 구현 클래스 (공식 저장소 기준):

| 플랫폼 | 일반적인 구현 클래스 |
|------|-----------|
| Android | `YourNamespace.AndroidAdvertisementManager` |
| iOS | `YourNamespace.IOSAdvertisementManager` |
| WebGL 범용 | `YourNamespace.WebGLAdvertisementManager` |
| WebGL 위챗 미니게임 | `YourNamespace.WebGLWeChatAdvertisementManager` |
| WebGL 두yin 미니게임 | `YourNamespace.WebGLDouYinAdvertisementManager` |
| WebGL 콰이서우 미니게임 | `YourNamespace.WebGLKuaiShouAdvertisementManager` |

입력 시 주의사항:

- **완전한 타입명**이어야 하며, 네임스페이스를 포함해야 합니다.
- 클래스는 반드시 `public`이고, `BaseAdvertisementManager`를 상속해야 합니다(간접적으로 `IAdvertisementManager` 구현).
- `BaseAdvertisementManager` 자체가 `GameFrameworkModule`을 상속하는데, 이는 `GameFrameworkEntry.GetModule<T>()`이 모듈을 식별하기 위한 전제 조건입니다.

참조 인터페이스 및 베이스 클래스 정의:


### 3. 대상 플랫폼 SDK가 설치되어 있는지 확인

`componentType`이 가리키는 구현 클래스는 해당 플랫폼의 광고 SDK(예:穿山甲, AdMob, 위챗 미니게임 광고 SDK 등)에 의존합니다. Android 프로젝트에서 WebGL 플랫폼의 매니저만 부착한 경우, Android 패키징 시 여전히 구현을 찾을 수 없어 동일한 오류가 발생합니다. 처리 방법:

- 대상 플랫폼에 해당하는 SDK 패키지 설치 (`Packages/manifest.json` 또는 `.unitypackage`).
- 또는 Inspector에서 임시로 `componentType`을 설치된 플랫폼의 구현으로 전환.

### 4. 코드 스트리핑 및 어셈블리 포함 확인

iOS / IL2CPP 빌드는 관리 코드 스트리핑을 수행하므로, 잘못 제거될 수 있습니다. 두 가지 처리 방법:

- Project Settings → Player → Other Settings → `Managed Stripping Level`을 `Low` 이하로 설정.
- 또는 `Assets/link.xml`에서 매니저가 포함된 어셈블리를 명시적으로 보존:

```xml
<linker>
  <assembly fullname="YourAdvertisementImpl" preserve="all"/>
</linker>
```

### 5. `m_config` 및 광고 슬롯 ID 확인

오류 자체는 설정과 관련이 없지만, `Start()`가 `_advertisementManager.Initialize(m_config)`를 호출할 때 매니저가 비어있으면 (`_advertisementManager == null`) 즉시 `NullReferenceException`이 발생합니다. 따라서 매니저 복구 후 다음 사항도 함께 확인:

- 현재 플랫폼에 해당하는 `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*`가 입력되어 있는지 확인.
- `m_config` (`AdvertisementConfig` 인스턴스)가 `null`이 아닌지 확인, 그렇지 않으면 `Start`의 초기화가 건너뜁니다:

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L120-L126
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

## 검증

위 단계를 따라 수정한 후, 다음 검사를 수행하여 문제가 해결되었는지 확인:

1. 게임을 실행하고 Console에 `Advertisement manager is invalid.`가 더 이상 나타나지 않는지 확인.
2. `Awake` 이후에 중단점을 설정하여 `_advertisementManager != null`인지 확인.
3. `Start`에서 `_advertisementManager.Initialize(m_config)`가 정상적으로 진입하여 광고 SDK 초기화 콜백을 완료하는지 확인.
4. 광고 재생 인터페이스(예: 보상형 동영상)를 한 번 호출하여 정상적으로 노출 결과를 반환하는지 확인.

## 일반적인 오류

- **클래스명만 입력하고 네임스페이스를 쓰지 않음**: `Utility.Assembly.GetType(componentType)`이 `null`을 반환하여 모듈이 등록되지 않음.
- **매니저 클래스가 `BaseAdvertisementManager`를 상속하지 않음**: `IAdvertisementManager`를 구현했더라도 `GameFrameworkModule`로 등록되지 않음.
- **다중 플랫폼 전환 시 `componentType`을 업데이트하지 않음**: Android에서 iOS로 패키징 전환할 때, `componentType`이 여전히 Android 구현 클래스를 가리키고 있어 매니저가 누락됨.
- **여러 개의 `AdvertisementComponent` 중복 부착**: `[DisallowMultipleComponent]`가 중복 부착을 방지하지만, 씬에 여러 GameObject가 각각 부착된 경우 먼저 `Awake`된 것만 적용됨.
