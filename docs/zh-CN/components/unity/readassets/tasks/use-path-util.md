# 使用 PathUtil 处理路径（规范化/拼接/通配符）

`PathUtil` 是一个静态工具类，专门用于处理读写资源时涉及的相对路径：把混合分隔符、`.`、`..` 的路径规范化，把两段路径安全地拼接成 `/` 分隔的字符串，以及把 `*`/`?` 通配符转换为可直接用于匹配的正则。

## 前置条件

- 项目已引入 `com.gameframex.unity.readassets` 包。
- 代码中 `using GameFrameX.ReadAssets.Runtime;`。

## 常用方法一览

| 方法 | 作用 |
|------|------|
| `IsDirectorySeparator(char c)` | 判断字符是否为 `/` 或 `\` |
| `FixTrailingDirectorySeparators(string path)` | 把结尾多余的连续分隔符合并成一个 |
| `CombineSlash(string a, string b)` | 用 `/` 拼接两段路径，避免重复或缺失分隔符 |
| `NormalizeRelativePath(string relative, bool forceTrailingSlash = false)` | 把相对路径规范化为 `/a/b/c` 形式，处理 `.`、`..` 和混合分隔符 |
| `IsValidCharacter(char c)` | 判断字符是否为路径允许的字符 |
| `WildcardToRegex(string pattern)` | 把 `*`/`?` 通配符转换为大小写不敏感的正则 |

## 操作步骤

### 1. 拼接两段路径

```csharp
using GameFrameX.ReadAssets.Runtime;

string full = PathUtil.CombineSlash("assets/config", "settings.json");
// 结果："assets/config/settings.json"

string root = PathUtil.CombineSlash("assets/config/", "sub/file.json");
// 结果："assets/config/sub/file.json"，不会重复斜杠

string abs = PathUtil.CombineSlash("assets/config", "/absolute/file.json");
// 当 b 以 '/' 开头时，直接返回 b："absolute/file.json"
```

### 2. 规范化相对路径

`NormalizeRelativePath` 会把 `\` 全部转换为 `/`，折叠 `.`、解析 `..`，并校验非法字符。默认不保留结尾斜杠，传 `forceTrailingSlash: true` 可强制保留。

```csharp
using GameFrameX.ReadAssets.Runtime;

// 混合分隔符 → 统一为 /
string p1 = PathUtil.NormalizeRelativePath("a\\b\\c");
// 结果："a/b/c"

// 解析 . 和 ..
string p2 = PathUtil.NormalizeRelativePath("a/./b/../c");
// 结果："a/c"

// 强制保留结尾斜杠
string p3 = PathUtil.NormalizeRelativePath("a/b/c", forceTrailingSlash: true);
// 结果："a/b/c/"

// 两侧带引号的字符串会被剥离
string p4 = PathUtil.NormalizeRelativePath("\"a/b\"");
// 结果："a/b"
```

Source: [Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L170)

### 3. 使用通配符匹配

`WildcardToRegex` 把通配符转成正则，`*` 对应任意字符序列，`?` 对应单个字符，匹配时大小写不敏感。

```csharp
using System.Text.RegularExpressions;
using GameFrameX.ReadAssets.Runtime;

Regex rx = PathUtil.WildcardToRegex("assets/configs/*.json");
bool match1 = rx.IsMatch("assets/configs/settings.json"); // true
bool match2 = rx.IsMatch("assets/configs/data.json");    // true
bool match3 = rx.IsMatch("assets/configs/sub/a.json");   // false（* 不跨 /）

Regex rx2 = PathUtil.WildcardToRegex("file_?.txt");
bool match4 = rx2.IsMatch("file_1.txt"); // true
bool match5 = rx2.IsMatch("file_12.txt"); // false
```

Source: [Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L183-L186)

## 常见变体

- **保留引号原样**：如果路径不是被双引号包围的整段字符串（仅首或尾有 `"`），`NormalizeRelativePath` 不会剥离引号；引号也属于非法字符，会抛 `Invalid characters`。
- **判断字符是否合法**：`IsValidCharacter` 拒绝 `"`、`<`、`>`、`|`、`*`、`?`、`:` 以及控制字符（ASCII < 32），可在自定义校验中复用。
- **拼接绝对路径**：`CombineSlash` 中若 `b` 以 `/` 开头，会直接返回 `b`（去掉前导 `/`），用于"以传入路径覆盖前缀"的场景。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| `ArgumentException: Empty or null` | `NormalizeRelativePath` 传入了 `null` 或空串 | 提前做空值判断 |
| `IOException: Invalid path: double dot error` | `..` 多到超出当前目录（已退到根） | 检查路径是否真的在根目录之上 |
| `IOException: Invalid characters` | 路径含 `"`、`<`、`>`、`|`、`*`、`?`、`:` 或控制字符 | 用 `IsValidCharacter` 过滤或修正输入 |
| `ArgumentNullException: a / b` | `CombineSlash` 任一参数为 `null` | 调用前做空值检查 |

## 背景（可选）

`PathUtil` 把读资源流程中最容易踩坑的三件事——分隔符、`./..`、通配符——集中到一个静态类里：`NormalizeRelativePath` 用状态机解析路径段，保证输出统一以 `/` 开头且不含冗余；`WildcardToRegex` 用 `Regex.Escape` 兜底后再替换 `*`/`?`，避免路径中的点号被当成正则元字符。
