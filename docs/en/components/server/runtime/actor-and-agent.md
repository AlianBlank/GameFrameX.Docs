# Scheduling Concurrent Tasks with Actor / ComponentAgent

Actor wraps business entities such as "player/scene/global" into scheduling units that execute serially on a single thread; ComponentAgent is a reusable business component attached to an Actor. All cross-entity calls are obtained through `ActorManager`, thereby avoiding locks and guaranteeing data consistency. This page demonstrates how to obtain and invoke ComponentAgent to schedule concurrent tasks.

## Prerequisites

- The GameFrameX Actor framework has been integrated, and `ActorManager` is accessible in the runtime environment.
- A component Agent inheriting from `ComponentAgent<TComponent>` or `StateComponentAgent<TComponent, TState>` already exists.
- The business entity already has an `ActorId` (of type `long`); global Agent calls without an `ActorId` use `GetComponentAgent<T>()`.

## Steps

1. At any location where the Actor is accessible, obtain the target component Agent through `ActorManager`.

```csharp
// Global shared component (no ActorId dimension)
var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
await serverComp.RemoveOnlineRole(ActorId);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L46-L53)

2. When you need to operate on a specific player's component, pass the player's `ActorId` as the second argument, and the framework will route the call to the corresponding Actor's serial queue.

```csharp
var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
await attributeComponentAgent.InitializeDefaultsSilent();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L77-L78)

3. When scheduling multiple Agents under the same Actor serially, simply `await` the calls in business order; the framework guarantees that calls within the same Actor execute serially.

```csharp
// All land on the same player ActorId, executing serially in order
var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
await mailAgent.SyncAsync();

var bagAgent = await ActorManager.GetComponentAgent<BagComponentAgent>(playerState.Id);
await bagAgent.SomeBusiness();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L91-L92)

4. When the Agent's work is complete, enable automatic recycling where the Actor reference is held, to avoid it staying resident.

```csharp
// Automatically recycled after logout
SetAutoRecycle(true);
QuartzTimer.Remove(ScheduleIdSet);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L50-L52)

## Common Variants

| Scenario | Usage | Description |
|------|------|------|
| Global singleton component | `await ActorManager.GetComponentAgent<T>()` | Do not pass `ActorId`; obtains a process-level shared Agent |
| Player-private component | `await ActorManager.GetComponentAgent<T>(actorId)` | The framework routes to the corresponding player Actor by `actorId` |
| Room/scene component | `await ActorManager.GetComponentAgent<RoomComponentAgent>()` | Usually a global Agent that internally indexes by room Key |

## Common Mistakes

- Creating an Agent directly with `new T()`: Agents must be created and managed by `ActorManager`; manual instantiation bypasses the serial queue and recycling mechanisms.
- Calling a player-private Agent where no `ActorId` is held: this throws an error because the Actor cannot be found; for global components, use the parameterless `GetComponentAgent<T>()`.
- Forgetting to call `SetAutoRecycle(true)` when the player logs out: the Agent will remain resident, consuming queue and timer resources (see [PlayerComponentAgent.OnLogout](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L45-L53)).

## Background (Optional)

The Actor model transforms "concurrent access to the same player/scene" into serial message queues, while ComponentAgent is the business unit attached to an Actor; `ActorManager` handles both component lifecycle and cross-Actor routing, which is why all initialization operations in the login flow can be completed in a single `await` chain without locks.
