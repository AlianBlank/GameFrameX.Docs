# Unity / .NET에서 생성된 구성을 읽는 방법

이 페이지의 단계를 따르면, Unity 클라이언트 또는 .NET 서버의 코드에서 `gen-client-*` / `gen-server-*` 스크립트가 생성한 구성 데이터를 직접 읽을 수 있으며, 전체 과정에서 파싱 코드를 직접 작성할 필요가 없습니다.

## 사전 조건

- 문서 요구 사항에 따라 `Excels/Tables/`에 Excel 표를 준비했습니다(명명 규칙은 아래 참조).
- 생성 스크립트를 이미 실행하여, Unity 프로젝트 아래에 C# 클래스(예: `TbItemConfig`, `TbAchievementConfig`)와 데이터 파일이 존재합니다.
- `Tables` 컨테이너 클래스의 네임스페이스를 가져옵니다(기본적으로 생성 경로의 루트 네임스페이스 아래에 있음).

## 작업 단계

1. `Excels/Tables/` 디렉터리에서 Excel 파일 이름이 `字母-英文名-中文名.xlsx` 규칙을 따르도록 생성/확인합니다. 예:

   ```
   D-ItemConfig-道具表-道具-1001.xlsx
   ```

   출처: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L94-L96)

2. 생성 스크립트를 실행합니다(Windows에서는 `.bat` 더블 클릭, Mac/Linux에서는 `sh` 사용). 실행이 완료되면 Unity 프로젝트 아래에 C# 클래스와 데이터 파일이 생성됩니다:

   ```bash
   # 클라이언트 (Unity)
   sh gen-client-json.sh
   # 또는 gen-client-bin.sh

   # 서버 (.NET)
   sh gen-server-bin.sh
   # 또는 gen-server-json.sh
   ```

   출처: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L136-L141)

3. 코드에서 `tables` 컨테이너를 통해 해당 표를 가져오고, 기본 키로 `Get(id)`를 사용해 단일 레코드를 조회합니다:

   ```csharp
   // id가 10001인 아이템을 가져옵니다
   var item = tables.TbItemConfig.Get(10001);

   // 아이템 이름은 자동으로 현재 언어로 표시됩니다(예: 중국어에서는 「钻石」로 표시)
   Debug.Log(item.Name);
   Debug.Log(item.Price); // 10
   ```

   출처: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L152-L159)

4. 도구가 생성한 코드에서 클래스 이름은 `Tb英文名` 규칙을 따르며, 아래 표는 이 저장소의 기존 Excel과 생성된 클래스 이름의 대응 관계입니다:

   | Excel 파일 이름 | 생성된 C# 클래스 이름 |
   |--------------|---------------|
   | `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
   | `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
   | `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |
   | `L-Localization-成就.xlsx` | `TbLocalization` |

   출처: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L194-L199)

## 일반적인 변형

- **대형 표 분할**: 한 표의 데이터가 특히 많은 경우(수천 건), **영어 이름이 동일**하기만 하면 되고 중국어 이름은 임의로 구분하면, 도구가 자동으로 동일한 표로 병합합니다. 예를 들어 `D-ItemConfig-道具表.xlsx`와 `D-ItemConfig-道具表-1001.xlsx`는 `TbItemConfig`로 병합됩니다.
- **한쪽에서만 사용**: 영어 이름과 중국어 이름 사이에 그룹 표시 `c`(클라이언트 전용) 또는 `s`(서버 전용)를 추가합니다. 추가하지 않으면 양쪽 모두 생성됩니다.
  - `D-ItemConfig-c-道具表.xlsx` → 클라이언트에서만 `TbItemConfig` 사용
  - `D-ItemConfig-s-道具表.xlsx` → 서버에서만 `TbItemConfig` 사용
- **데이터 유형 선택**: `text`는 다국어 번역이 적용되는 필드입니다(key를 입력하고, 실제 텍스트는 `Local/`에 있음). `string`은 번역 없이 그대로 사용되는 일반 문자열입니다.

## 자주 발생하는 오류

| 오류 | 원인 | 해결 방법 |
|------|------|------|
| `tables.TbXxx` 클래스를 찾을 수 없음 | 생성 스크립트를 실행하지 않았거나 Excel 파일 이름에 영어 부분을 입력하지 않음 | `gen-client-json.sh` / `gen-client-bin.sh`를 실행하고, 파일 이름에 유효한 영어 부분이 있는지 확인 |
| 도구에서 `不支持中文表名` 오류 발생 | 파일 이름의 영어 부분에 중국어를 입력함 | 해당 부분을 순수 영어로 변경(예: `道具表`가 아닌 `ItemConfig`) |
| `Get(id)`가 null 반환 | 해당 표 데이터에 id가 없음 | 먼저 `tables.TbXxx.GetAll()`을 사용하거나 전체 데이터를 직접 읽어 id가 존재하는지 확인 |
| 필드 값이 번역된 텍스트가 아닌 key임 | 필드 유형에 `text` 대신 `string`을 사용함 | 표 헤더 두 번째 행의 유형을 `string`에서 `text`로 변경한 뒤 다시 생성 |

## 배경(선택)

`tables`는 Luban이 생성한 전체 컨테이너이며, 각 `TbXxx` 표는 하나의 Excel에 대응합니다. `text` 유형 필드는 읽을 때 현재 언어의 로컬라이제이션 매핑을 거치므로, `Excels/Local/`에 각 언어별 key 번역을 모두 구비해야 합니다.
