# 如何使用实体、协程、声音、场景与 Mono 管理

`GameFrameX` 通过 `GameApp` 静态门面以懒加载方式暴露各运行时子系统组件,包括实体、协程、声音、场景、Mono 等。每个子系统都对应 `GameEntry.GetComponent<T>()` 获取的组件实例,使用时只需在代码中访问 `GameApp.{子系统名}` 即可。本页说明这些子系统的接入方式与典型用法。

## 前置条件

1. 已安装 `com.gameframex.unity.entry` 包,并在场景中挂载 `GameEntry` 启动器。
2. 已通过 Package Manager 安装各子系统对应的运行时包:
   - `com.gameframex.unity.entity`(实体)
   - `com.gameframex.unity.coroutine`(协程)
   - `com.gameframex.unity.sound`(声音)
   - `com.gameframex.unity.scene`(场景)
   - 内置 Mono 管理器随 entry 包提供
3. 项目已定义相应的启用宏:`ENABLE_GAME_FRAME_X_ENTITY`、`ENABLE_GAME_FRAME_X_COROUTINE` 等(各组件源码以 `#if` 守护,缺少宏时相关字段不会编译,见下文"常见错误")。

## 操作步骤

### 1. 通过 GameApp 访问子系统

所有子系统在 `GameApp` 类中以 `public static {组件类} {子系统名}` 形式暴露,首次访问时通过 `GameEntry.GetComponent<T>()` 创建并缓存。无需手动 `new` 或注册。

```csharp
using GameFrameX.Runtime;

public static partial class GameApp
{
    public static EntityComponent Entity
    {
        get
        {
            if (_entity == null)
            {
                _entity = GameEntry.GetComponent<EntityComponent>();
            }
            return _entity;
        }
    }

    private static EntityComponent _entity;
}
```

Source: [Runtime/GameApp.Entity.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Entity.cs#L36-L55)

协程组件采用完全一致的模式:

```csharp
using GameFrameX.Runtime;
using GameFrameX.Coroutine.Runtime;

public static partial class GameApp
{
    public static CoroutineComponent Coroutine
    {
        get
        {
            if (_coroutine == null)
            {
                _coroutine = GameEntry.GetComponent<CoroutineComponent>();
            }
            return _coroutine;
        }
    }

    private static CoroutineComponent _coroutine;
}
```

Source: [Runtime/GameApp.Coroutine.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Coroutine.cs#L36-L55)

调用示例:

```csharp
// 实体
var entityComponent = GameApp.Entity;

// 协程
var coroutineComponent = GameApp.Coroutine;
```

### 2. 实体(Entity)使用要点

通过 `GameApp.Entity` 取得 `EntityComponent` 后,可使用框架提供的实体创建、查询、销毁接口。实体由 `EntityComponent` 统一管理生命周期,常配合 `Entity` 基类与 `EntityLogic` 逻辑脚本使用。详细接口签名以 `EntityComponent` 源码为准,本仓库不直接持有其实现,需查阅 `com.gameframex.unity.entity` 包内文档。

### 3. 协程(Coroutine)使用要点

通过 `GameApp.Coroutine` 取得 `CoroutineComponent`,在任意非 MonoBehaviour 上下文中启动协程任务。协程组件底层包装了 Unity 的 `Coroutine` 机制,可在非 Mono 类中安全地启动延时、分帧操作。调用入口通常形如:

```csharp
GameApp.Coroutine.StartCoroutine(MyRoutine());

GameApp.Coroutine.StopCoroutine(handle);
```

具体重载以 `CoroutineComponent` 源文件为准。

### 4. 声音(Sound)使用要点

声音子系统沿用同样的静态门面入口。仓库中 `Runtime/GameApp.Sound.cs` 通过 `#if` 守护提供 `GameApp.Sound`,返回 `SoundComponent` 实例。常用操作包括播放 BGM、播放音效、暂停/恢复、设置音量等,具体 API 以 `SoundComponent` 实现为准。

```csharp
// 仅示意:实际签名见 SoundComponent
GameApp.Sound.PlayMusic(musicId);
GameApp.Sound.PlaySound(soundId);
```

### 5. 场景(Scene)使用要点

`Runtime/GameApp.Scene.cs` 同样以 `GameApp.Scene` 暴露 `SceneComponent`。可通过该组件加载、卸载场景,以及获取当前已加载的场景资源信息。典型流程:传入场景资源名 → 触发异步加载 → 加载完成后挂载并切换激活场景。

```csharp
// 仅示意
GameApp.Scene.LoadScene("MainCity", onComplete: () => { /* 进入场景完成 */ });
```

### 6. Mono 管理使用要点

`Mono` 管理器用于在非 MonoBehaviour 类中获得类似 `Mono` 的能力(轮询、协程、定时器等),与 `GameApp.Coroutine` 协同工作。通过 `GameApp` 上的 Mono 相关属性可直接获取,后续调用 `Update`/`OnDestroy` 等生命周期钩子无需继承 `MonoBehaviour`。

## 常见变体

- **跨平台裁剪**:每个 `GameApp.*.cs` 都使用 `#if ENABLE_GAME_FRAME_X_{NAME}` 条件编译,可在项目 `csc.rsp` 或 `Player Settings` 中按需启用/关闭子系统,关闭后对应的 `GameApp.{Name}` 字段会消失。
- **依赖注入扩展**:若不希望使用静态门面,可直接调用 `GameEntry.GetComponent<EntityComponent>()` 等获取原始组件引用,二者等价。
- **部分子系统命名差异**:如某些版本以 `Mono` 而非 `MonoManager` 命名,请以当前运行时包版本源码为准。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameApp.Entity` / `GameApp.Coroutine` 等属性不存在 | 未安装对应子系统包,或未定义 `ENABLE_GAME_FRAME_X_ENTITY` / `ENABLE_GAME_FRAME_X_COROUTINE` 等宏 | 在 Package Manager 中安装对应包,并在项目 `csc.rsp` 或 `Scripting Define Symbols` 中加入宏定义 |
| 调用时返回 `null` 或抛空引用 | 场景中未挂载 `GameEntry`,或子系统未在 `GameEntry` 上注册组件 | 在启动场景添加 `GameEntry` 预制体并检查 Inspector 中已勾选目标组件 |
| 协程未执行 | 调用 `StartCoroutine` 时传入的方法未返回 `IEnumerator`,或在 `Mono` 上下文被销毁后调用 | 确认方法签名,避免在已销毁对象上启动协程 |
| 声音/场景接口找不到 | 子系统包未升级到与当前 entry 包匹配的版本 | 升级对应运行时包,或参考目标版本 `SoundComponent` / `SceneComponent` 真实签名 |

## 背景(可选)

`GameApp` 是一个 `partial class`,每个子系统对应一份 `Runtime/GameApp.{Name}.cs` 文件,各自以 `#if` 守护、互不耦合,目的就是按需裁剪包体。所有组件都通过 `GameEntry.GetComponent<T>()` 的懒加载模式获取,首次访问时由 `GameEntry` 实例化并缓存到 `GameApp` 私有静态字段,后续调用直接返回缓存,既保证全局唯一,又避免模块加载顺序问题。
