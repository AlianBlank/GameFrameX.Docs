# HTTP 공통 파라미터 구성 방법

시작 프로세스의 모든 HTTP 요청에 통일된 공통 파라미터(채널, 언어, 기기 식별자 등)를 주입하려면, `IStartupHttpParamsProvider`를 구현하여 프로세스 컨텍스트에 등록하기만 하면 됩니다.

## 사전 조건

- 프로젝트에 `GameFrameX.Startup` 패키지가 이미 추가되어 있고, 시작 프로세스에서 `IFsm<IProcedureManager>`에 접근할 수 있어야 합니다.
- 시작 옵션 `StartupOptions`의 필드 의미(패키지명, 채널, 서브 채널 등)를 이해하고 있어야 합니다.

## 작업 단계

1. **파라미터 컨테이너 구현(선택 사항)**

   기본 필드만 재사용하면 되는 경우 `StartupHttpParams`를 그대로 사용하면 됩니다. 새 필드를 추가해야 하는 경우 새 클래스를 파생하여 `IStartupHttpParams.ToJson()`과 `ToDictionary()`를 구현합니다.

   ```csharp
   using GameFrameX.Startup.Runtime;
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MyStartupHttpParams : StartupHttpParams
   {
       public string ServerId = string.Empty;

       public override string ToJson()
       {
           ServerId = ServerId ?? string.Empty;
           return Utility.Json.ToJson(this);
       }

       public override Dictionary<string, object> ToDictionary()
       {
           var dict = base.ToDictionary();
           dict["ServerId"] = ServerId ?? string.Empty;
           return dict;
       }
   }
   ```

   출처: [Runtime/Http/StartupHttpParams.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L19-L151)

2. **`IStartupHttpParamsProvider` 구현**

   `Create` 메서드에서 `StartupOptions`(및 필요한 런타임 컨텍스트)를 파라미터 객체로 매핑합니다.

   ```csharp
   using GameFrameX.Startup.Runtime;

   public class MyStartupHttpParamsProvider : DefaultStartupHttpParamsProvider
   {
       public override IStartupHttpParams Create(StartupOptions options)
       {
           var p = (MyStartupHttpParams)base.Create(options);
           p.ServerId = "cn-east-1";
           p.AppVersion = Application.version;
           p.Platform = Application.platform.ToString();
           p.DeviceUniqueIdentifier = SystemInfo.deviceUniqueIdentifier;
           return p;
       }
   }
   ```

   출처: [Runtime/Http/DefaultStartupHttpParamsProvider.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/DefaultStartupHttpParamsProvider.cs#L9-L23)

3. **시작 프로세스에 등록**

   `GameFrameX.Startup` 프로세스 매니저를 생성한 후, 프로바이더 인스턴스를 블랙보드 키 `StartupHttpParamsProvider`(타입 `VarObject`)에 기록합니다. 프로세스 내부에서는 `StartupProcedureUtility.GetHttpParamsProvider`를 통해 이를 읽으며, 등록되지 않은 경우 자동으로 `DefaultStartupHttpParamsProvider`로 폴백됩니다.

   ```csharp
   var provider = new MyStartupHttpParamsProvider();
   var providerBox = VarObject.Create(provider);
   procedureOwner.SetData(BlackBoardKeys.StartupHttpParamsProvider, providerBox);
   ```

   출처: [Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L71-L76)

4. **HTTP 요청에서 공통 파라미터 읽기**

   `GetHttpParams(procedureOwner)`를 통해 현재 활성화된 파라미터 인스턴스를 가져온 다음, `ToJson()` 또는 `ToDictionary()`를 호출하여 HTTP 클라이언트/Body에 주입합니다.

   ```csharp
   var httpParams = StartupProcedureUtility.GetHttpParams(procedureOwner);
   var dict = httpParams.ToDictionary();
   // dict를 POST 폼 또는 JSON body에 병합
   ```

   출처: [Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L78-L99)

## 공통 파라미터 필드 빠른 참조

| 필드 | 타입 | 소스 | 설명 |
|------|------|------|------|
| `PackageName` | string | `StartupOptions.PackageName` | 애플리케이션 패키지명 |
| `Channel` | string | `StartupOptions.Channel` | 메인 채널 |
| `SubChannel` | string | `StartupOptions.SubChannel` | 서브 채널 |
| `AppVersion` | string | 일반적으로 `Application.version` 사용 | 애플리케이션 버전 |
| `Platform` | string | 일반적으로 `Application.platform` 사용 | 실행 플랫폼 |
| `DeviceUniqueIdentifier` | string | 일반적으로 `SystemInfo.deviceUniqueIdentifier` 사용 | 기기 고유 식별자 |
| `Language` | string | 직접 입력 | 시스템 언어 |
| `UserLanguage` | string | 직접 입력 | 사용자 언어 |

출처: [Runtime/Http/StartupHttpParams.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L21-L83)

## 일반적인 변형

- **완전한 커스텀 필드 집합**: `StartupHttpParams`를 상속하지 않고 `IStartupHttpParams` 인터페이스를 직접 구현하여, `ToJson()` / `ToDictionary()`에서 자신만의 필드를 반환합니다.
- **런타임 플랫폼별 분기**: `Provider.Create`에서 `Application.platform`에 따라 다른 파라미터 객체를 반환합니다(예: 콘솔 플랫폼에만 `ConsoleId` 추가).
- **파라미터 동적 갱신**: 특정 필드(예: 서버 지역)가 도중에 변경되어야 하는 경우, 파라미터 객체를 다시 생성하여 `SetData(BlackBoardKeys.StartupHttpParamsProvider, ...)`로 덮어쓰기만 하면 됩니다.

## 자주 발생하는 오류

- **블랙보드 등록 누락**: `GetHttpParamsProvider`는 등록되지 않은 경우 기본 프로바이더를 반환하므로 비즈니스 로직에서 오류가 발생하지는 않지만, 모든 커스텀 필드가 손실됩니다. 등록 전에 `SetData`가 파라미터를 처음 사용하는 프로세스보다 먼저 실행되는지 확인하세요.
- **`options`가 null인 경우**: `StartupHttpParams.FromOptions`는 `null`에 대해 `ArgumentNullException`을 발생시킵니다. 커스텀 Provider에서는 먼저 null 검사를 수행하거나, `FromOptions`를 호출하기 전에 `StartupOptions`가 할당되어 있음을 보장하세요.
- **파생 클래스에서 `ToDictionary` 누락**: `ToJson`만 오버라이드하고 `ToDictionary`를 오버라이드하지 않으면, 새로 추가한 필드가 딕셔너리 형식의 요청 본문에 나타나지 않아 서버가 받지 못할 수 있습니다. 두 메서드는 반드시 모두 구현해야 합니다.
- **필드명과 백엔드 규약 불일치**: `ToDictionary`의 key(예: `"Channel"`)는 백엔드로 전송되는 필드명이므로, 이름을 변경한 후에는 백엔드 계약과 동기화해야 합니다.

## 배경(선택 사항)

시작 프레임워크는 직접 HTTP 요청을 발생시키지 않으며, "공통 파라미터를 어떻게 생성할지"를 `IStartupHttpParamsProvider`로 추상화하고, "파라미터를 어떻게 소비할지"는 상위 HTTP 모듈에 맡깁니다. 프레임워크는 프로세스에서 `IStartupHttpParams` 인스턴스를 가져올 수 있다는 점만 보장하며, 이를 Header, Query, Body, Form 중 어디에 넣을지는 호출자가 결정합니다. 이러한 설계 덕분에 HTTP 구현을 자유롭게 교체할 수 있으면서(GameFrameX.Network, BestHTTP, UnityWebRequest 등) 공통 파라미터는 항상 일관성을 유지합니다.
