# POST リクエストの送信方法(フォームと JSON)

`WebComponent` / `WebManager` が提供する `PostToString`、`PostToBytes` シリーズのメソッドに `Dictionary<string, object>` のフォーム辞書を渡すことで、POST リクエストを送信し、非同期でレスポンスを取得できます。すべての POST リクエストは内部で `WebJsonData` として統一的にカプセル化されてリクエストキューに入り、その後 `UnityWebRequest.Post` によって送信されます。

## 前提条件

- プロジェクトに `com.gameframex.unity.web` パッケージがインストールされていること(このリポジトリがそのパッケージのソースコードです)。
- シーンに `WebComponent` をアタッチする(これは `WebManager` の Mono ラッパーであり、カスタム Inspector が付属しています)、またはお使いのフレームワークの通常の方法で `WebManager` のインスタンスを取得してください。

## 操作手順

1. フォームパラメータの辞書を構築します。キーは `string`、値は `object` です:

```csharp
public Task<WebStringResult> PostToString(string url, Dictionary<string, object> from, object userData = null)
```

出典:[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L492-L496)

2. `PostToString` を呼び出し、返された `Task<WebStringResult>` を `await` します。例:`await webComponent.PostToString(url, form);`。フォームを渡さない場合、`from` は `null` にできます(`WebComponent` のオーバーロードではデフォルト値が直接指定されています)。

```csharp
public Task<WebStringResult> PostToString(string url, Dictionary<string, object> from = null, object userData = null)
```

出典:[WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L175-L176)

3. フォームを同時に URL クエリ文字列にも配置する必要がある場合は、`queryString` 付きのオーバーロード(`Dictionary<string, string>`)を使用します:

```csharp
public Task<WebStringResult> PostToString(string url, Dictionary<string, object> from, Dictionary<string, string> queryString, object userData = null)
```

出典:[WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L188-L189)

4. リクエストヘッダーをカスタマイズする必要がある場合は、4 引数のオーバーロードを使用します(`header` も同様に `Dictionary<string, string>` です):

```csharp
public Task<WebStringResult> PostToString(string url, Dictionary<string, object> from, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)
{
    var uniTaskCompletionSource = new TaskCompletionSource<WebStringResult>();
    from = MergeForm(from);
    queryString = MergeQueryString(queryString);
    header = MergeHeader(header);
    url = UrlHandler(url, queryString);

    WebJsonData webJsonData = WebJsonData.Create(url, header, from, uniTaskCompletionSource, userData);
    m_WaitingNormalQueue.Enqueue(webJsonData);
    return uniTaskCompletionSource.Task;
}
```

出典:[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L548-L560)

5. レスポンスがバイナリ(ファイルのダウンロードなど)の場合は、対応する `PostToBytes` に切り替えます。返り値は `Task<WebBufferResult>` です:

```csharp
public Task<WebBufferResult> PostToBytes(string url, Dictionary<string, object> from, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)
```

出典:[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L571-L573)

## 一般的なバリエーション

### すべての POST に共通フォームフィールドを追加する

`WebManager` は「基本データ」の管理を提供します:共通フィールドをあらかじめ登録しておくと、以降の `MergeForm` のたびにそれがリクエストフォームにマージされます(上記の 4 引数オーバーロードの 552 行目の `from = MergeForm(from)` を参照)。

```csharp
/// <summary>
/// 基本フォームデータを追加する
/// </summary>
/// <param name="key">フォームキー</param>
/// <param name="value">フォーム値</param>
public void AddBaseForm(string key, object value)
{
    m_BaseForm[key] = value;
}
```

出典:[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L586-L594)

併せて `RemoveBaseForm(string key)` とクリア用メソッドも用意されています。詳細は [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L596-L609) を参照してください。同様に、`MergeQueryString` / `MergeHeader` は「基本クエリ文字列 / 基本リクエストヘッダー」をマージします。

### 純粋な JSON ボディ

ソースコードには、「シリアライズ済みの JSON 文字列をリクエストボディとして直接扱う」公開 POST メソッドは見つかりませんでした。`WebJsonData.Create(url, header, from, ...)` はフォーム辞書(`Dictionary<string, object>`)の経路を使用し、最終的に `UnityWebRequest.Post(webJsonData.URL, string.Empty)` によって送信されます([WebManager.cs L214](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L213-L215) を参照)。サーバー側が生の JSON ボディを要求する場合は、`header` 付きのオーバーロードを使用して `Content-Type` 関連のヘッダーを自分で設定できます。具体的な JSON ボディの実装の詳細は、ソースコード中に見つからなかったため、検証済みのサンプルを提示できません。

## よくあるエラー

| 問題 | 原因 | 回避策 |
|------|------|------|
| パラメータが付与されない | `from` に `null` を渡した、またはキー名のスペルがサーバー側の取り決めと一致していない | 辞書のキー名を一つずつ照合する。共通フィールドが `RemoveBaseForm` で削除されていないことを確認する |
| 共通フィールドが意図せず混入する | 以前に `AddBaseForm` を呼び出しており、`MergeForm` のたびにマージされる | 共通フィールドの使用が終わったらクリア用メソッドを呼び出す(上記参照) |
| 期待通りの文字列結果が得られない | `PostToBytes`(バイナリ結果)を呼び出している | テキストレスポンスには `PostToString`、バイナリレスポンスには `PostToBytes` を使用する |
| カスタムヘッダーが有効にならない | 間違ったオーバーロードに渡している(引数の順序は `from → queryString → header`) | 4 引数オーバーロードを使用する。順序は上記の早見表を参照 |

## 背景(任意)

POST リクエストは統一的に `WebJsonData` を経由します:`WebJsonData.Create(...)` がリクエストデータオブジェクトを生成して `m_WaitingNormalQueue` にエンキューし、`TaskCompletionSource` の `Task` を返します。送信側は `UnityWebRequest.Post(url, string.Empty)` を使用してリクエストを構築します([WebManager.cs L557-L559](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L556-L560)、[L214](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L213-L215))。`WebComponent` は薄いラッパーにすぎず、内部で `WebManager` の同名オーバーロードに転送しています([WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L175-L189))。
