# ライフサイクルコールバック

`ProcedureBase` は `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>` を継承しており、各 Procedure（流程）は有限状態機械（FSM）の規約に従い、生成・進入・ポーリング・退出・破棄の各段階でそれぞれ仮想メソッドをトリガーします。これらが Procedure の**ライフサイクルコールバック**です。サブクラスでオーバーライドすることでビジネスロジックを実装できます。

## コールバック一覧

| コールバック | シグネチャ | トリガータイミング |
|------|------|----------|
| `OnInit` | `protected override void OnInit(IFsm<IProcedureManager> procedureOwner)` | ステートマシン初期化時（各 Procedure インスタンスにつき 1 回） |
| `OnEnter` | `protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)` | この Procedure に切り替えたとき |
| `OnUpdate` | `protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 毎フレームのポーリング（論理経過時間 / 実経過時間） |
| `OnFixedUpdate` | `protected override void OnFixedUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 固定ステップでのポーリング |
| `OnLeave` | `protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)` | この Procedure から離れるとき。`isShutdown=true` はステートマシン終了による退出を示す |
| `OnDestroy` | `protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)` | ステートマシン破棄時（各 Procedure インスタンスにつき 1 回） |

すべてのメソッドの既定実装は `base.Xxx(...)` のみとなっており、オーバーライドは可能ですが、基底クラスの動作を維持するために **`base` 呼び出しを残してください**。

## パラメータの説明

| パラメータ | 意味 |
|------|------|
| `procedureOwner` | この Procedure を保持するステートマシンオブジェクト。型は `IFsm<IProcedureManager>`。これを通じて Procedure マネージャー（`procedureOwner.Owner`）へのアクセスや Procedure の切り替えなどを行う。 |
| `elapseSeconds` | 時間スケールの影響を受ける論理経過時間（秒）。 |
| `realElapseSeconds` | 時間スケールの影響を受けない実経過時間（秒）。 |
| `isShutdown` | `OnLeave` において `true` の場合、この退出は通常の切り替えではなくステートマシンが閉じられたことが原因であることを示す。 |

## トリガータイミング（マネージャー API との対応）

| マネージャー操作 | トリガーされるコールバック（該当 Procedure インスタンス上で） |
|------------|----------------------------|
| `Initialize(fsmManager, procedures...)` | 引数で渡された各 Procedure が順に `OnInit` をトリガーされる |
| `StartProcedure<T>()` / `StartProcedure(Type)` | 対象の Procedure が `OnEnter` をトリガーされる。現在の Procedure がある場合は、まず旧 Procedure に `OnLeave(isShutdown=false)` がトリガーされる |
| ステートマシンのハートビート（毎フレーム） | 現在の Procedure の `OnUpdate` と `OnFixedUpdate` |
| `DestroyProcedures()` | 現在の Procedure に `OnLeave(isShutdown=true)` がトリガーされ、その後すべての登録済み Procedure に `OnDestroy` が順にトリガーされる |
| `ReinitializeProcedures(procedures...)` | 先に `DestroyProcedures()` を実行し、その後新しい Procedure 配列で `Initialize` を再実行するのと同等 |

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L39-L119)

## 最小の使用例

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

public class MyProcedure : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // この Procedure で必要なリソースやキャッシュなどを初期化
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // この Procedure に進入したときに UI を起動したり、イベントを登録したりする
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner,
        float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        // 毎フレームのビジネスロジック（条件を満たしたら procedureOwner 経由で Procedure を切り替える）
    }

    protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)
    {
        base.OnLeave(procedureOwner, isShutdown);
        // UI のクリーンアップやイベントの解除
        // isShutdown == true の場合はステートマシン全体が閉じられたことを示す
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // この Procedure が保持しているリソースを解放
    }
}
```

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| オーバーライド後に `base.OnXxx(...)` を呼び忘れたため、ステートマシン内部の状態が異常になる | 基底クラスが状態統計やタイマーなどの暗黙的な動作を保持している可能性がある | 常にオーバーライドの末尾で `base.OnXxx(...)` を呼び出す |
| `OnInit` 内で `StartProcedure` を呼び出して Procedure を切り替える | `Initialize` 段階では Procedure はまだ `OnEnter` されていないため、早期に切り替えるとステートマシンが不整合な状態になる | 切り替えは `OnEnter` または以降の `OnUpdate` で行うようにする |
| `OnDestroy` 内で `procedureOwner` の他の Procedure にアクセスする | 破棄段階ではステートマシン内部の状態が回収中である | 他 Procedure への参照は `OnEnter` 時にキャッシュし、`OnLeave` 時にクリーンアップするように変更する |
| `OnUpdate` で一度きりの初期化を行う | `OnUpdate` は毎フレーム呼び出されるため、繰り返しトリガーされる | 一度きりのロジックは `OnInit` または `OnEnter` に配置する |
| `OnEnter` が毎回 `Initialize` 時に呼ばれることを期待する | 初期化時に一度だけ呼ばれるのは `OnInit` であり、`OnEnter` は状態切り替え時にのみ呼ばれる | 起動ロジックは `OnEnter` に、データ準備は `OnInit` に配置する |
