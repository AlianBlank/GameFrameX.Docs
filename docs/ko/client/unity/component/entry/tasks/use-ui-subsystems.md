# UI, GUI, FairyGUI 3대 인터페이스 진입점 사용 방법

GameFrameX의 진입점 패키지는 세 개의 정적 속성 `GameApp.UI`, `GameApp.GUI`, `GameApp.FUIPackage`를 통해 각각 UI, UGUI, FairyGUI 3대 인터페이스 컴포넌트를 노출합니다. 컴파일 매크로에 따라 해당 모듈을 활성화하기만 하면, 모든 비즈니스 코드에서 이 컴포넌트를 직접 사용하여 인터페이스를 열거나/관리할 수 있습니다.

## 사전 조건

- 프로젝트에 GameFrameX 진입점 패키지 [com.gameframex.unity.entry](https://github.com/GameFrameX/com.gameframex.unity.entry)가 이미 추가되어 있어야 합니다.
- 프로젝트의 `Assembly Definition` 또는 프로젝트 설정에서 다음의 해당 컴파일 매크로를 활성화합니다(하나 선택 또는 조합):
  - `ENABLE_GAME_FRAME_X_UI`: `GameApp.UI`(UI 하위 시스템)를 활성화합니다.
  - `ENABLE_GAME_FRAME_X_L_UGUI`: `GameApp.GUI`(UGUI 하위 시스템)를 활성화합니다.
  - `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`: `GameApp.FUIPackage`(FairyGUI 패키지 관리)를 활성화합니다.
- `GameEntry`를 통해 해당 런타임 컴포넌트(`UIComponent`, `UGUIComponent`, `FairyGUIPackageComponent`)가 등록되어 있어야 합니다.

## 3대 진입점 한눈에 보기

| 진입점 | 컴파일 매크로 | 반환 컴포넌트 | 대표적인 용도 |
|------|--------|----------|----------|
| `GameApp.UI` | `ENABLE_GAME_FRAME_X_UI` | `UIComponent` | GameFrameX 자체 UI 하위 시스템의 통합 진입점 |
| `GameApp.GUI` | `ENABLE_GAME_FRAME_X_L_UGUI` | `UGUIComponent` | UGUI 기반의 전통적인 인터페이스 컴포넌트 진입점 |
| `GameApp.FUIPackage` | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` | `FairyGUIPackageComponent` | FairyGUI 리소스 패키지/인터페이스 관리 진입점 |

## 작업 단계

### 1. UI 하위 시스템 활성화(`GameApp.UI`)

프로젝트 수준에서 매크로 `ENABLE_GAME_FRAME_X_UI`를 활성화하면, 어느 코드에서든 `GameApp.UI`를 통해 `UIComponent` 인스턴스를 가져올 수 있습니다:

```csharp
#if ENABLE_GAME_FRAME_X_UI
var ui = GameApp.UI;   // 첫 액세스 시 GameEntry.GetComponent<UIComponent>()를 통해 지연 로드
ui.SomeApi();
#endif
```

출처: [GameApp.UI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.UI.cs#L32-L55)

### 2. UGUI 하위 시스템 활성화(`GameApp.GUI`)

프로젝트 수준에서 매크로 `ENABLE_GAME_FRAME_X_L_UGUI`를 활성화한 후, `GameApp.GUI`를 통해 `UGUIComponent` 인스턴스를 가져옵니다:

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
var gui = GameApp.GUI; // GameEntry.GetComponent<UGUIComponent>() 지연 로드
gui.SomeApi();
#endif
```

출처: [GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

### 3. FairyGUI 패키지 관리 활성화(`GameApp.FUIPackage`)

프로젝트 수준에서 매크로 `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`를 활성화한 후, `GameApp.FUIPackage`를 통해 `FairyGUIPackageComponent`를 가져옵니다:

```csharp
#if ENABLE_GAME_FRAME_X_UI_FAIRYGUI
var fUIPackage = GameApp.FUIPackage; // GameEntry.GetComponent<FairyGUIPackageComponent>() 지연 로드
fUIPackage.SomeApi();
#endif
```

출처: [GameApp.FairyGUIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.FairyGUIPackage.cs#L32-L55)

### 4. 비즈니스 코드에서 안전하게 접근하기

세 진입점 모두 지연 로드(lazy loading) 방식을 사용합니다: 첫 액세스 시 `GameEntry.GetComponent<T>()`를 호출하여 컴포넌트를 가져오고 캐시하며, 이후에는 정적 필드를 직접 재사용합니다. 속성 내부에서 `if (_xxx == null)` 널 검사를 사용하므로, 비즈니스 시스템에서는 읽기만 하고 쓰지 않을 것을 권장하며, 멀티스레드 컨텍스트에서 정적 필드를 재설정하지 않도록 주의해야 합니다.

```csharp
var ui = GameApp.UI;
var gui = GameApp.GUI;
var pkg = GameApp.FUIPackage;
```

## 일반적인 변형

- 여러 UI 체계 동시 활성화: 동일한 프로젝트에서 `ENABLE_GAME_FRAME_X_UI`, `ENABLE_GAME_FRAME_X_L_UGUI`, `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`를 동시에 활성화할 수 있으며, `GameApp` 클래스는 `partial` 형태로 세 부분의 확장을 병합하여 서로 영향을 주지 않습니다.
- FairyGUI만 활성화: 프로젝트에서 FairyGUI만 사용하는 경우 `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`만 선택하면 되며, 코드 생성 시 나머지 두 속성은 제거됩니다.
- UGUI + FairyGUI 혼합: `ENABLE_GAME_FRAME_X_L_UGUI`와 `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`를 동시에 활성화하고, `GameApp.GUI`로 UGUI 흐름을 처리하며, `GameApp.FUIPackage`로 FairyGUI 리소스 패키지를 관리합니다.

## 자주 발생하는 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 컴파일 오류 `GameApp 不包含 UI 的定义` | `ENABLE_GAME_FRAME_X_UI` 컴파일 매크로가 활성화되지 않음 | 프로젝트 또는 asmdef의 Scripting Define Symbols에 `ENABLE_GAME_FRAME_X_UI` 추가 |
| 컴파일 오류 `GameApp 不包含 GUI 的定义` | `ENABLE_GAME_FRAME_X_L_UGUI`가 활성화되지 않음 | `ENABLE_GAME_FRAME_X_L_UGUI` 추가 |
| 컴파일 오류 `GameApp 不包含 FUIPackage 的定义` | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`가 활성화되지 않음 | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` 추가 |
| 런타임에 `GameApp.UI`가 반환하는 컴포넌트가 `null`임 | `GameEntry`에 `UIComponent`가 등록되지 않음 | 시작 흐름에서 `GameEntry.RegisterComponent`를 통해 `UIComponent` 인스턴스 등록 |

## 배경(선택 사항)

진입점 패키지는 `partial class GameApp` 방식으로 서로 다른 하위 시스템의 접근 진입점을 독립된 파일로 분리하고, 컴파일 매크로로 감싸 필요에 따른 컴파일을 구현함으로써 활성화되지 않은 UI 체계에 대한 하드 의존성을 방지합니다. 세 속성 내부는 모두 `if (_x == null) _x = GameEntry.GetComponent<T>()` 형태의 싱글톤 지연 로드 패턴을 사용하며, `GameEntry` 컴포넌트 등록 메커니즘과 일관성을 유지합니다.
