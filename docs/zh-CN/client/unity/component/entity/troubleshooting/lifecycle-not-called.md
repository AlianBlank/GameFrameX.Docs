# 实体未触发生命周期方法怎么办

如果你的 `ShowEntity` / `HideEntity` 调用之后,实体里的 `OnInit` / `OnShow` / `OnUpdate` / `OnHide` 一个都没进,通常是 `EntityLogicType` 没正确传入、预制体上已经有同名脚本,或者 `EntityComponent` 没初始化。这页按"日志报错 → 根因 → 一行修复"的方式速查。

## 快速诊断

| 症状(日志/现象) | 根因 | 修复 |
|---|---|---|
| `Entity '{0}' OnInit userData is not ShowEntityInfo.` | `ShowEntity` 时没把 `ShowEntityInfo`(含 `EntityLogicType`)作为 `userData` 传入 | 用 `ShowEntity<T>` 泛型重载,或在自定义 `userData` 中包装 `ShowEntityInfo` |
| `Entity logic type is invalid.` 或 `Entity '{0}' can not add entity logic.` | `ShowEntityInfo.EntityLogicType` 是 `null`,或该类型不是 `EntityLogic` 子类,不是 `MonoBehaviour` | 给 `EntityLogicType` 赋值为继承 `EntityLogic` 的具体 `MonoBehaviour` 子类的 `Type` |
| `Entity group is inconsistent for non-new-instance entity.` | 同一个实体对象被复用到不同 `EntityGroup` | 在 `ShowEntity` 时传入与第一次相同的 `EntityGroup`,或清空对象池 |
| `Entity '{0}' On{Init/Show/Hide} with exception ...` | 你的 `OnInit/OnShow/OnHide` 抛异常,被框架 `try/catch` 吞掉 | 在重写方法内自己 `try/catch` 调试,先保证 `base.OnXxx(...)` 不抛异常 |
| 预制体已挂了你自己的脚本,框架没添加新的 | 预制体上已有同 `EntityLogicType` 脚本,被 `Entity.OnInit` 复用,而你的入口逻辑写在别的脚本里 | 把业务逻辑继承 `EntityLogic` 后实现,不要另外挂 `MonoBehaviour` |
| `OnUpdate` 不进 | `EntityLogic` 上的 `enabled` 在 `OnRecycle` 中被设为 `false`,再次 `ShowEntity` 后未恢复;或者 `HideEntity` 后对象被回收了 | 不要在子类里手动 `enabled = false`;确认 `ShowEntity` 走的是 `OnInit` 路径,并检查对象池 |

## 修复步骤

### 1. 用泛型 `ShowEntity` 让框架自动注入 `EntityLogicType`

框架在 `Entity.OnInit` 中读取 `userData as ShowEntityInfo` 的 `EntityLogicType` 字段([Entity.cs#L112-L124](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L112-L124))。最不容易出错的方式是直接用 `EntityComponent.ShowEntity<T>`:

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

// 假设 MyEntityLogic : EntityLogic,且挂在 EntityId 对应的预制体上
GameEntry.GetComponent<EntityComponent>()
    .ShowEntity<MyEntityLogic>(entityId, "Assets/Prefabs/MyEntity.prefab", "Default", userData);
```

来源:[Runtime/Entity/EntityComponent.cs#L48](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L48)

### 2. 确认 `EntityLogic` 子类是 `MonoBehaviour` 且类型可被添加

`Entity.OnInit` 通过 `gameObject.AddComponent(entityLogicType)` 注入([Entity.cs#L141](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L141-L146))。所以:

```csharp
using UnityEngine;
using GameFrameX.Entity.Runtime;

public sealed class MyEntityLogic : EntityLogic   // 必须是 MonoBehaviour
{
    protected internal override void OnInit(object userData)
    {
        base.OnInit(userData);
        // 初始化逻辑
    }

    protected internal override void OnShow(object userData)
    {
        base.OnShow(userData);
        // 每次 ShowEntity 都会进这里
    }

    protected internal override void OnHide(bool isShutdown, object userData)
    {
        base.OnHide(isShutdown, userData);
        // 隐藏逻辑
    }

    protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(elapseSeconds, realElapseSeconds);
        // 每帧逻辑
    }
}
```

来源:[Runtime/Entity/EntityLogic.cs#L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L40)、[Runtime/Entity/EntityLogic.cs#L133](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L133)、[Runtime/Entity/EntityLogic.cs#L196](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L196)

注意:`EntityLogic` 的生命周期方法全部声明为 `protected internal virtual`,必须用 `override` 重写,而不是 `public` / `private`。

### 3. 排查 `OnUpdate` 不触发的常见原因

`Entity.OnRecycle` 会调用 `m_EntityLogic.enabled = false`([Entity.cs#L173-L174](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L173-L174))。当对象从对象池里取出再 `ShowEntity` 时,`Entity.OnInit` 检测到 `m_EntityLogic != null` 且类型一致,只会把 `enabled` 重置为 `true`([Entity.cs#L130](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L130-L131))。如果你在子类里手写 `enabled = false`,就会导致复用时不再 `OnUpdate`——把它去掉即可。

### 4. 用日志验证调用链

如果以上都正常但还是进不了方法,在每个 `override` 的第一行加 `Debug.Log`,确认 `ShowEntity` 之后的 1 帧内是否走到 `OnInit` / `OnShow`。注意:每种异常情况 `Entity` 都会用 `Log.Error` 输出具体原因([Entity.cs#L149-L156](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L149-L156)),查 Console 比看代码更快。

## 验证

1. 运行场景,第一次 `ShowEntity` 后应看到 `OnInit` → `OnShow` 的 `Debug.Log`,此后每帧进 `OnUpdate`。
2. 调用 `HideEntity`,应看到 `OnHide` 触发,且对象仍存在于对象池中(场景里看不到,但池子计数 +1)。
3. 再次 `ShowEntity` 同一 `EntityId`,应只触发 `OnShow`(不复用前提下),而不是 `OnInit`(此时走的是对象池复用分支)。
4. 在 `OnInit/OnShow/OnHide` 中抛一次 `Exception` 测试,确认 `Log.Error` 文案与诊断表第一行一致。

## 背景(可选)

`Entity` 是 `MonoBehaviour`,作为 `EntityLogic` 的宿主:`ShowEntity` → 资源加载 → 通过 `ShowEntityInfo.EntityLogicType` 在游戏对象上 `AddComponent<EntityLogic>`,然后依次回调 `OnInit` → `OnShow` → 每帧 `OnUpdate` → `HideEntity` 时 `OnHide` → 回收时 `OnRecycle`。常见出错点集中在 `EntityLogicType` 这一个参数上,泛型 `ShowEntity<T>` 已替你处理。
