# 拡張メソッドを使用して Unity API を簡素化する

GameFrameX は Unity の組み込み型（`GameObject`、`Transform`、`Vector2/3/4`、`Component` など）に対して多数の拡張メソッドを提供しており、元の型に新しい挙動を直接追加することで、ボイラープレートコードを減らして一般的な操作を実現できます。このページでは、型ごとに最もよく使われる拡張メソッドをまとめ、すぐにコピーして使えるサンプルを紹介します。

## 操作手順

すべての拡張メソッドは `GameFrameX.Runtime` 名前空間にあります。ファイルの先頭に追加すれば、すべての拡張が利用可能になります。


### 2. `GameObject` / `Component` を操作する

`GetOrAddComponent` と `DestroyComponent` は、最もよく使われる 2 つのコンポーネントレベルの拡張です。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class Player : MonoBehaviour
{
    private Rigidbody _rigidbody;

    void Awake()
    {
        // 存在しなければ自動追加、存在すればそのまま返す
        _rigidbody = gameObject.GetOrAddComponent<Rigidbody>();
    }

    void OnDisable()
    {
        // 指定した型のコンポーネントを破棄する
        gameObject.DestroyComponent<Rigidbody>();

        // または Component 自身から呼び出し、同じ GameObject 上の同型コンポーネントを破棄する
        _rigidbody.DestroyComponent();
    }
}
```

### 3. `Transform` での検索と単一軸の代入

`FindChildName` は深さ優先で任意の階層の子ノードを検索できます。`SetPositionX/Y/Z` はワールド座標の特定の軸のみを変更し、全体のベクトル読み書きを避けて使用します。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class Enemy : MonoBehaviour
{
    public Transform weaponSlot;

    void Start()
    {
        // "WeaponSocket" という名前の子ノードを深く検索する
        var socket = transform.FindChildName("WeaponSocket");
        if (socket != null)
        {
            weaponSlot = socket;
        }

        // ワールド座標の X 軸のみを変更する
        transform.SetPositionX(10f);
    }
}
```

### 4. `Vector2 / Vector3 / Vector4` 間の変換

UI や物理の API 呼び出しではベクトル型の好みが異なるため、`ToVector2 / ToVector3 / ToVector4` を使えば 1 行で次元の切り替えができます。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class CameraShake : MonoBehaviour
{
    public Vector3Int gridPos;

    void Update()
    {
        // Vector3Int → Vector3
        Vector3 worldPos = gridPos.ToVector3();

        // Vector3 (x, y, z) → Vector2 (x, z)、Y は無視
        Vector2 topDown = worldPos.ToVector2();

        // Vector3 → Vector4、w は既定で 0
        Vector4 homogeneous = worldPos.ToVector4();
    }
}
```

### 5. 文字列の高速比較と null 判定

`EqualsFast` は文字単位で末尾から前方へ比較し、一部のプラットフォームでの `string.Equals` のオーバーヘッドを回避します。`IsNotNull` / `IsNull` は `ObjectExtension` が提供するオブジェクトの null 判定拡張です。

```csharp
using GameFrameX.Runtime;
using UnityEngine;

public class NameTag : MonoBehaviour
{
    public string targetName = "Player";

    void Update()
    {
        // 2 つの文字列が等しいかを高速比較する
        if (transform.name.EqualsFast(targetName))
        {
            Debug.Log("一致しました");
        }

        // null 判定、!= null と等価だが Unity のオーバーロード == は呼び出さない
        if (this.IsNotNull())
        {
            // ...
        }
    }
}
```

## よくある間違い

- **`using GameFrameX.Runtime;` を忘れる** — 拡張メソッドは参照可能でないと呼び出せません。赤いエラーが出る場合はまず名前空間を確認してください。
- **`gameObject.DestroyComponent()` にジェネリックを指定しない** — このメソッドは `Component` 自身から呼び出した場合のみ同型のコンポーネントを返して破棄します。`GameObject` に対しては必ずジェネリックを指定した `DestroyComponent<T>()` を使用してください。
- **`FindChildName` と `Transform.Find` の混同** — `Transform.Find` は直接の子ノードしか探せません。階層をまたいで検索する場合は `FindChildName` を使用してください。
- **`EqualsFast` は 2 つの null に対して true を返す** — `string.Equals` と同じ挙動ですが、ロケール依存の比較は行わない点に注意してください。ローカライズが関わるシナリオでは引き続き `string.Equals` を使用してください。

## 背景（任意）

拡張メソッドは C# では `this T self` 修飾子によって既存型に追加され、IL レベルでは通常の静的メソッドとしてコンパイルされます。GameFrameX は Unity でよく使われるボイラープレート（`GetComponent` + `AddComponent`、`Find` の深さ探索、ベクトルの次元変換など）をすべて拡張としてカプセル化しており、静的呼び出しによるアロケーションゼロの利点と、メソッドチェーン記述・IDE の入力補完の両方を実現しています。すべての拡張クラスには `[UnityEngine.Scripting.Preserve]` が付与されており、IL2CPP やコードストリッピング後も利用可能です。
