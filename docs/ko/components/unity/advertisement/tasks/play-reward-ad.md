# 보상형 동영상 광고 재생 방법

이 페이지의 단계에 따라 GameFrameX 광고 컴포넌트를 호출하여 보상형 동영상 광고를 재생할 수 있으며, 사용자가 광고를 끝까지 시청한 후 `AdvertisementPlayOption.OnShowResult`를 통해 보상 지급 콜백을 받아 게임 내에서 코인, 부활 횟수 등의 아이템을 지급할 수 있습니다.

## 사전 조건

1. `com.gameframex.unity.advertisement` 패키지를 프로젝트에 통합하고, 기본 광고 SDK(예:穿山甲, 优量汇, 각 WebGL 미니게임 광고 애그리게이터)의 통합 및 초기화를 완료해야 합니다.
2. 씬에 [AdvertisementComponent](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L45-L46)가 부착된 GameObject가 존재하며, Inspector에서 해당 플랫폼의 광고 슬롯 ID(Android/iOS/WebGL/WeChat/DouYin/KuaiShou)를 입력해야 합니다.
3. 스크립트 방식으로 호출하는 경우, 먼저 컴포넌트 참조를 가져와야 합니다:

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;

public class RewardAdCaller : MonoBehaviour
{
    private AdvertisementComponent _adComponent;

    private void Awake()
    {
        _adComponent = GetComponent<AdvertisementComponent>();
    }
}
```

## 작업 단계

1. Inspector에서 각 플랫폼의 보상형 동영상 광고 슬롯 ID를 입력합니다. 컴포넌트는 현재 빌드 플랫폼에 따라 해당 ID를 자동으로 선택합니다 ([AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117) 참조).

2. (선택 사항) `Start` 이전에 보상형 광고에 서버 콜백에 필요한 투장 필드(예: 사용자 ID, 주문 번호 등)를 설정합니다:

```csharp
_adComponent.SetExtraData("userId", "10001");
_adComponent.SetExtraData("orderId", "20240101001");
```

`SetExtraData` 구현은 [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L173-L189)에서 확인할 수 있으며, `value`가 `null`이면 해당 키가 제거됩니다.

3. 플레이어가 "광고 보고 보상 받기" 버튼을 클릭했을 때, [AdvertisementPlayOption](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L85) 인스턴스를 생성하고 세 개의 콜백을 채웁니다:

```csharp
public void OnClickWatchAd()
{
    var option = new AdvertisementPlayOption
    {
        OnSuccess = msg => Debug.Log($"보상형 동영상 성공: {msg}"),
        OnFail    = err => Debug.LogWarning($"보상형 동영상 실패: {err}"),
        OnShowResult = watched =>
        {
            // watched == true는 사용자가 끝까지 시청했다는 의미이며, 보상을 지급할 수 있음
            if (watched)
            {
                GrantReward();
            }
        },
        extraData  = "{\"orderId\":\"20240101001\"}", // Load 단계에서만 서버로 투장됨
        customData = "reward_coins_100"               // 재생 시 콜백으로 투장됨
    };

    _adComponent.Play(option);
}
```

4. `Play(AdvertisementPlayOption)`를 호출하여 광고를 재생합니다. 이 메서드 정의는 [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L216-L219)에서 확인할 수 있습니다:

```csharp
_adComponent.Play(option);
```

5. `OnShowResult` 콜백에서 `watched` 값에 따라 보상 지급 여부를 결정합니다(예: +100 코인). 끝까지 시청한 콜백만 유효한 노출로 간주됩니다.

## 일반적인 변형

- **이전 API(`[Obsolete]`로 표시됨)**: 이전 버전의 `Show`/`Load` 메서드(세 개의 `Action`을 직접 전달하는 방식)도 여전히 사용할 수 있지만, 컴파일 시 `CS0618` 경고가 발생하므로 가능한 한 빨리 `Play(AdvertisementPlayOption)`로 마이그레이션하는 것을 권장합니다. 정의는 [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L85-L124)에서 확인할 수 있습니다.
- **매니저를 통한 직접 호출**: `AdvertisementComponent`를 거치고 싶지 않은 경우, `GameFrameworkEntry.GetModule<IAdvertisementManager>()`를 통해 직접 `Play(AdvertisementPlayOption)`를 호출할 수도 있습니다. 시그니처는 [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L97-L97)에서 확인할 수 있습니다.
- **WebGL 다중 플랫폼 분기**: 대상이 WebGL인 경우, 보상형 동영상 광고 슬롯 ID는 `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 컴파일 매크로에 따라 각각 결정되므로, 각 미니게임별로 별도로 신청하여 ID를 입력해야 합니다.

## 일반적인 오류

| 증상 | 원인 | 수정 방법 |
|------|------|----------|
| `Log.Fatal("Advertisement manager is invalid.")` | `IAdvertisementManager` 구현이 등록되지 않음 | 해당 플랫폼의 광고 SDK 패키지를 통합하거나, `Awake` 이전에 `GameFrameworkEntry`가 초기화되었는지 확인 |
| `ArgumentNullException: config` | `Initialize`에 전달된 `AdvertisementConfig`가 null임 | 먼저 설정 객체를 `new`로 생성하거나, Inspector에서 `m_config`에 값을 할당한 후 `Start`가 자동으로 초기화하도록 함 |
| 광고는 표시되지만 `OnShowResult`가 계속 `false`임 | 사용자가 중간에 종료했거나 기본 SDK에서 오류 발생 | `OnFail`에서 오류 정보를 출력하여 문제를 파악하고, `extraData`/`customData`로 인해 서버측 검증이 실패하지 않는지 확인 |
| WebGL 컴파일 시 광고 슬롯을 찾을 수 없다는 오류 발생 | 컴파일 매크로가 활성화되지 않았거나 해당 미니게임 ID가 입력되지 않음 | Player Settings의 Scripting Define Symbols를 확인하고, 해당 미니게임에 대해 `m_adUnitIdWebGLWeChat` 등의 필드를 입력 |

## 배경 지식 (선택 사항)

`AdvertisementPlayOption`은 성공/실패/표시 결과의 세 가지 콜백과 `extraData`/`customData`의 두 가지 투장 필드를 동시에 담습니다: `extraData`는 `Load` 단계에서만 JSON으로 직렬화되어 서버의 보상 검증으로 투장되며, 로드가 완료된 후에 설정해도 무효입니다; `customData`는 재생 시 기본 SDK 콜백으로 투장됩니다. `BaseAdvertisementManager`는 `_delegating` 상호 배제 락을 사용하여 새로운 `Initialize`와 이전 `Initialize`가 서로 재귀적으로 호출되는 것을 방지합니다. 자세한 내용은 [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L111-L163)에서 확인할 수 있습니다.
