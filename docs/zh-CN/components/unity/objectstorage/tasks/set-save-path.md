# 如何设置对象保存路径

调用 `SetSavePath(string)` 可设置对象在对象存储中的目标保存路径,后续 `UploadDirectory` 与 `UploadFile` 上传的文件都会落到该路径下。

## 前置条件

- 已通过 `ObjectStorageUploadFactory` 拿到一个 `IObjectStorageUploadManager` 实例(具体类型由工厂根据当前平台/配置创建,继承自 `BaseObjectStorageUploadManager`)。
- 已确认要写入的桶(`bucketName`)并完成 `Init(accessKey, secretKey, bucketName, endpoint)`。

## 操作步骤

1. 获取上传管理器实例。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs)

2. 调用 `SetSavePath` 指定对象在桶内的保存路径(支持带或不带结尾分隔符)。

   ```csharp
   // 写法 A:不写结尾分隔符
   manager.SetSavePath("game/assets/textures");
   
   // 写法 B:带结尾分隔符,实现内部会自动去掉最后一个分隔符
   manager.SetSavePath("game/assets/textures/");
   ```

   实现会先判断 `savePath` 是否以 `Path.DirectorySeparatorChar` 结尾,如果是则 `Substring(0, savePath.Length - 1)` 截掉,最后再赋给 `BucketSavePath`。两种写法等价。

   Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

3. 路径设置完成后,再调用上传接口,文件就会保存到 `BucketSavePath` 下。

   ```csharp
   // 上传整个目录
   manager.UploadDirectory("/本地/Assets/Textures");
   
   // 或上传单个文件
   bool ok = manager.UploadFile("/本地/Assets/Textures/icon.png");
   ```

   Source: [IObjectStorageUploadManager.cs#L9-L21](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9-L21)

## 常见变体

- **每次上传前重置路径**:同一次会话中可以反复调用 `SetSavePath`,以切换不同子目录上传。`BucketSavePath` 是受保护字段,每次调用都会被覆盖。
- **相对路径 vs 绝对键前缀**:`SetSavePath` 接收的是对象键(Key)的前缀,例如 `"game/v1"`,并非本地文件系统路径。本地路径由 `UploadDirectory` / `UploadFile` 单独传入。

## 常见错误

- **路径写成反斜杠结尾(Windows 习惯)**:`SetSavePath` 只检查 `Path.DirectorySeparatorChar`(平台原生分隔符),传入 Windows 的 `"a\\b\\"` 会保留反斜杠。建议统一传正斜杠或不含分隔符的形式。
- **忘记先 `Init` 就 `SetSavePath`**:虽然 `SetSavePath` 本身不校验 `Init` 状态,但后续上传需要合法的凭证,未 `Init` 时上传会失败。先 `Init` 再设置路径、再上传。
- **调用顺序错乱**:`SetSavePath` 必须在 `UploadDirectory` / `UploadFile` 之前调用;否则已发出的上传会沿用上一次设置的 `BucketSavePath`(默认 `string.Empty`)。

## 背景(可选)

`BucketSavePath` 是 `BaseObjectStorageUploadManager` 的受保护字段,具体实现类(如各云厂商适配)会把它当作对象 Key 的前缀拼接到上传请求中,因此本质上是"对象键前缀",而非"本地磁盘路径"。
