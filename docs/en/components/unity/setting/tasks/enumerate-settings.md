# Enumerate All Configuration Items

Use the methods provided by `SettingManager` to retrieve all currently loaded configuration item names at once, useful for configuration debugging, exporting, batch validation, or previewing before batch deletion.

## Prerequisites

- A helper implementation (such as `DefaultSettingHelper` or `PlayerPrefsSettingHelper`) has been injected via `SettingComponent.SetSettingHelper`, and `Load()` has been successfully called to load the configuration.
- A `SettingManager` instance is already accessible. The common approach is to read it from the `GameEntry` / `SettingComponent.SettingManager` property.

## Steps

1. Obtain the `SettingManager` instance. A common entry point is `GameEntry.GetComponent<SettingComponent>().SettingManager`, or the `GetSettingManager` derived method exposed directly by `SettingComponent`.

2. Call `GetAllSettingNames()` to directly obtain an array of configuration item names.

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingManager = GameEntry.GetComponent<SettingComponent>().SettingManager;
   string[] names = settingManager.GetAllSettingNames();

   foreach (var name in names)
   {
       UnityEngine.Debug.Log(name);
   }
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L140-L260), [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L85-L95)

3. To reuse an existing list (avoiding GC), use the overload with a `List<string>` parameter:

   ```csharp
   var results = new System.Collections.Generic.List<string>(settingManager.Count);
   settingManager.GetAllSettingNames(results);
   ```

   Source: [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L81-L92)

4. Combined with `HasSetting` and `RemoveSetting`, batch validation or cleanup can be performed:

   ```csharp
   foreach (var name in settingManager.GetAllSettingNames())
   {
       if (name.StartsWith("tmp_") && settingManager.HasSetting(name))
       {
           settingManager.RemoveSetting(name);
       }
   }
   settingManager.Save();
   ```

   Source: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs)

## Common Variations

- **Using the `List<string>` overload**: When you repeatedly call enumeration in a loop, or need to concatenate other string collections, the overload with a list avoids repeated allocations.
- **Filter by prefix**: Use LINQ or `StartsWith` to perform allowlist/blocklist filtering, for example, exporting only keys starting with `ui_*`.
- **Companion runtime enumerators**: `DefaultSetting` and `PlayerPrefsSettingHelper` themselves also provide `GetAllSettingNames()` implementations; if you bypass the manager and read the default setting instance directly, the interface signatures are consistent.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Throws `Setting helper is invalid.` on call | `SetSettingHelper` was not called or the manager is not yet initialized | Inject `DefaultSettingHelper`/`PlayerPrefsSettingHelper` at startup |
| Throws `Setting name is invalid.` on call | An empty string or `null` was passed in | Only perform secondary access on items returned by enumeration; avoid manually writing empty names |
| The retrieved array is empty | `Load()` was never called, or loading failed | Call `Load()` first and check the return value, then enumerate |
| Modifications don't take effect | `Save()` was not called | Call `settingManager.Save()` after removing/writing |

## Background (Optional)

`GetAllSettingNames` is defined at the interface layer with two overloads, `string[]` and `List<string>`. The specific storage is determined by the `ISettingHelper` implementation (`DefaultSettingHelper` uses the `DefaultSetting` in-memory dictionary; `PlayerPrefsSettingHelper` uses PlayerPrefs). The manager simply forwards the call to the injected helper, so the enumeration scope is exactly the same as the data loaded during `Load()`.
