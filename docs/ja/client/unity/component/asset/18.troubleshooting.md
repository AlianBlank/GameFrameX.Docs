# よくある質問

このドキュメントは GameFrameX Asset リソースコンポーネントの使用中に発生する可能性のある一般的な問題とその解決策を汇总します。

## 概要

Asset リソースコンポーネントは YooAsset に基づいて構築されており、统一されたリソースロード与管理インターフェースを提供します。實際の使用では、プラットフォームの差異、設定エラーまたはリソースパスの問題により、各种のエラーが発生する可能性があります。このドキュメントは開発者が問題を迅速に特定して解決するために作成されました。

## 初期化の問題

### 問題：リソースシステム初期化失敗

**症状：** ゲーム起動時に "Asset manager is invalid" または初期化関連エラーが発生する。

**可能性のある原因：**
1. AssetComponent がシーンに正しく追加されていない
2. IAssetManager モジュールが登録されていない

**解決策：**

Unity シーンで AssetComponent が正しく設定されていることを確認します：

```csharp
// Unity シーンに AssetComponent を追加
// パス：GameObject -> GameFrameX -> Asset
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L18-L64)

GameFrameworkEntry が正しく初期化されていることを確認します：

```csharp
// 起動時に AssetManager モジュールが登録されていることを確認
GameFrameworkEntry.RegisterModule<AssetManager>();
```

### 問題：リソースパッケージ初期化が false を返す

**症状：** `InitPackageAsync` メソッドが false を返すか例外をスローする。

**可能性のある原因：**
1. 実行モード（EPlayMode）が正しく設定されていない
2. Host サーバー URL が設定されていない
3. YooAssets の内部初期化失敗

**解決策：**

初期化前に実行モードが正しく設定されていることを確認します：

```csharp
var assetComponent = GameEntry.GetComponent<AssetComponent>();
assetComponent.GamePlayMode = EPlayMode.HostPlayMode;
```

> Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L18-L47)

## リソースロードの問題

### 問題：リソースパスが無効

**症状：** リソースをロードする際にパスが無効またはリソースが見つからないというヒントが表示される。

**可能性のある原因：**
1. リソースパスが間違っている
2. リソースがビルド清单に追加されていない
3. リソースタグの設定が間違っている

**解決策：**

`HasAssetPath` メソッドを使用してパスが有効か確認します：

```csharp
var assetComponent = GameEntry.GetComponent<AssetComponent>();
if (assetComponent.HasAssetPath("Prefabs/Player"))
{
    var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
}
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L570-L573)

### 問題：非同期ロードでリソースが null を返す

**症状：** 非同期でリソースをロードした後、null または無効な Handle を取得する。

**可能性のある原因：**
1. リソースパスが存在しない
2. リソースタイプが一致しない
3. ロードプロセス中に例外が発生した

**解決策：**

常に Handle のステータスを確認します：

```csharp
var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
if (handle.Status == YooAsset.EOperationStatus.Succeed)
{
    var player = handle.AssetObject as GameObject;
}
else
{
    Log.Error($"リソースロード失敗: {handle.Error}");
}
```

### 問題：同期ロードがエディタモードでフリーズする

**症状：** エディタシミュレートモードで同期ロードを使用するとエディタがフリーズする。

**原因分析：** EditorSimulateMode はエディタ内のリソースを使用し、同期ロードはメインスレッドをブロックする。

**解決策：**

非同期ロード方式を優先的に使用します：

```csharp
// 非推奨
var handle = assetComponent.LoadAssetSync<GameObject>("Prefabs/Player");

// 推奨
var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
```

## メモリ管理の問題

### 問題：メモリ使用量が増加し続ける

**症状：** ゲーム運行一段时间後、メモリ使用量が不断增加する。

**可能性のある原因：**
1. ロードしたリソースが正しく解放されていない
2. リソースハンドルを頻繁に作成した하지만 Release を呼び出していない
3. 未使用のリソースを定期的に清理していない

**解決策：**

リソースハンドルを正しく解放します：

```csharp
var handle = await assetComponent.LoadAssetAsync<GameObject>("Prefabs/Player");
// 使用完毕后解放
handle.Release();
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L622-L628)

未使用のリソースを定期的に清理します：

```csharp
// 適切なタイミングで呼び出し
assetComponent.UnloadUnusedAssetsAsync();
assetComponent.ClearUnusedBundleFilesAsync();
```

### 問題：リソースアンロードが無効

**症状：** UnloadAsset を呼び出した後もリソースが残っている。

**可能性のある原因：**
1. まだ該リソースを держаする参照がある
2. リソースパッケージがロックされている

**解決策：**

すべてのリソースを強制的にアンロードします：

```csharp
// すべてのリソースを強制回収
assetComponent.UnloadAllAssetsAsync(packageName);
```

## プラットフォーム固有の問題

### 問題：WebGL プラットフォームでリソースロード失敗

**症状：** WebGL プラットフォームでリソースをロードまたはダウンロードできない。

**可能性のある原因：**
1. WebGL モードでは WebPlayMode を使用する必要がある
2. サーバー CORS 設定の問題
3. メモリ制限

**解決策：**

非エディタ環境では、AssetComponent は自動的に WebPlayMode を設定します：

```csharp
#if UNITY_WEBGL && !UNITY_EDITOR
GamePlayMode = EPlayMode.WebPlayMode;
#endif
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L44-L52)

### 問題：小游戏プラットフォームでコンパイルエラー

**症状：** 微信、抖音、快手小游戏プラットフォームでコンパイルエラーが発生する。

**歴史的な修正記録：**
- 快手小游戏プラットフォームのコンパイルエラーを修正 (v2.4.0)
- 微信小游戏プラットフォームの条件付きコンパイルエラーを移除 (v2.3.0)
- 微信小游戏環境の初期化を修正 (v2.2.2)

**解決策：**

最新バージョンを使用していることを確認し、小游戏プラットフォームを正しく設定します：

```csharp
#if ENABLE_WECHAT_MINI_GAME
// 微信小游戏特定設定
GameEntry.GetComponent<AssetComponent>().gameObject
    .GetOrAddComponent<WeChatConfigHandler>();
#endif
```

> Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L105-L119)

### 問題：EditorSimulateMode がパッケージング後に無効

**症状：** 開発時は Editor モードが正常なのに、パッケージング後にリソースをロードできない。

**原因：** EditorSimulateMode はエディタ環境でのみ有効。

**解決策：**

パッケージング前に正しい実行モードを設定していることを確認します：

```csharp
#if UNITY_EDITOR
assetComponent.GamePlayMode = EPlayMode.EditorSimulateMode;
#else
assetComponent.GamePlayMode = EPlayMode.HostPlayMode; // またはその他の適切なモード
#endif
```

## ダウンロード更新の問題

### 問題：リソースダウンロード失敗

**症状：** パッチ更新時にファイルダウンロードに失敗する。

**可能性のある原因：**
1. ネットワーク接続の問題
2. サーバー URL 設定エラー
3. ファイル検証失敗

**解決策：**

ダウンロード失敗イベントを监听します：

```csharp
// ダウンロード失敗イベントを購読
GameEntry.Event.Subscribe(AssetWebFileDownloadFailedEventArgs.EventId, OnDownloadFailed);

private void OnDownloadFailed(object sender, GameEventArgs e)
{
    var args = e as AssetWebFileDownloadFailedEventArgs;
    Log.Error($"ダウンロード失敗: {args.FileName}, エラー: {args.Error}");
}
```

### 問題：パッチマニフェスト更新失敗

**症状：** パッチマニフェスト更新時にエラーが発生する。

**可能性のある原因：**
1. Manifest ファイルが破損している
2. ネットワーク問題
3. バージョンが一致しない

**解決策：**

マニフェスト更新失敗イベントを监听します：

```csharp
GameEntry.Event.Subscribe(AssetPatchManifestUpdateFailedEventArgs.EventId, OnManifestUpdateFailed);

private void OnManifestUpdateFailed(object sender, GameEventArgs e)
{
    var args = e as AssetPatchManifestUpdateFailedEventArgs;
    Log.Error($"マニフェスト更新失敗: {args.PackageName}, エラー: {args.Error}");
}
```

> Source: [AssetPatchManifestUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchManifestUpdateFailedEventArgs.cs#L36-L48)

## デバッグテクニック

### イベントシステムを使用したデバッグ

Asset コンポーネントはデバッグに使用するための完全なイベントシステムを提供します：

```csharp
// ステータス変更イベントを購読
GameEntry.Event.Subscribe(AssetPatchStatesChangeEventArgs.EventId, OnPatchStatesChange);

// ダウンロード進捗イベントを購読
GameEntry.Event.Subscribe(AssetDownloadProgressUpdateEventArgs.EventId, OnDownloadProgress);

// 更新ファイル発見イベントを購読
GameEntry.Event.Subscribe(AssetFoundUpdateFilesEventArgs.EventId, OnFoundUpdateFiles);
```

> Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L33)

### 実行モードの確認

ログで現在の実行モードを確認します：

```csharp
// AssetManager.Initialize() は現在のモードを出力
Log.Info($"リソースシステム実行モード：{PlayMode}");
```

> Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L49)

### リソースパッケージステータスの確認

```csharp
var package = assetComponent.GetAssetsPackage("DefaultPackage");

}
```
