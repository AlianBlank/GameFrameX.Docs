# 요청 로그 활성화 및 Inspector 사용 방법

Unity 메뉴 바의 `GameFrameX/Scripting Define Symbols`에서 「Web 송신/수신 로그 출력 활성화」를 체크하고 스크립트 재컴파일이 완료되기를 기다리면, `WebManager`가 보내는 모든 HTTP 요청과 수신된 응답이 `Log.Debug`로 Console에 출력됩니다. `WebComponent`가 부착된 GameObject를 선택하면 Inspector에 요청 타임아웃을 조정할 수 있는 0–120초 범위의 `Timeout` 슬라이더가 추가로 제공됩니다.

## 사전 조건

- 프로젝트에 `com.gameframex.unity.web` 패키지가 설치되어 있고 Web 컴포넌트 초기화가 완료되어 있어야 합니다.
- Console 패널의 로그 레벨이 Debug 로그를 표시하도록 설정되어 있어야 하며, 그렇지 않으면 매크로를 활성화해도 출력이 보이지 않습니다.

## 작업 단계: 요청 로그 활성화

1. Unity 상단 메뉴 `GameFrameX/Scripting Define Symbols`를 엽니다.
2. 필요에 따라 아래 메뉴 항목을 클릭합니다(클릭 즉시 적용되며, 매크로는 현재 Build Target의 Scripting Define Symbols에 기록됩니다):

| 메뉴 항목 | 기능 | 기록되는 매크로 |
|------|------|---------|
| `Enable Web Send Logs(开启Web发送日志打印)` | 각 요청의 URL, Header, Form 출력 | `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` |
| `Disable Web Send Logs(关闭Web发送日志打印)` | 송신 로그 매크로 제거 | — |
| `Enable Web Receive Logs(开启Web接收日志打印)` | 각 응답의 URL, Header, Form, Content 출력 | `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` |
| `Disable Web Receive Logs(关闭Web接收日志打印)` | 수신 로그 매크로 제거 | — |

3. Unity가 스크립트를 다시 컴파일할 때까지 기다립니다(오른쪽 하단의 회전 아이콘이 사라질 때까지).
4. 임의의 Web 요청을 실행하면(예: `WebManager`의 Get/Post 인터페이스), Console에서 `Web Request: ...` 및 `Web Response: ...` 형식의 Debug 로그를 확인할 수 있습니다.

메뉴 항목의 내부 구현은 매크로 정의의 추가/제거입니다:

```csharp
public static class WebLogScriptingDefineSymbols
{
    public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG";
    public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_SEND_LOG";

    [MenuItem("GameFrameX/Scripting Define Symbols/Enable Web Send Logs(开启Web发送日志打印)", false, 451)]
    public static void EnableNetworkSendLogs()
    {
        ScriptingDefineSymbols.AddScriptingDefineSymbol(EnableNetworkSendLogScriptingDefineSymbol);
    }
}
```

출처: [Editor/WebLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/WebLogScriptingDefineSymbols.cs#L40-L61)

매크로를 활성화하면 `WebManager`의 해당 코드 세그먼트가 패키지에 컴파일되어 포함되며, 로그 내용은 요청/응답의 URL, Header, Form 및 응답 Content입니다(오류 발생 시 Content는 오류 메시지):

```csharp
#if ENABLE_GAMEFRAMEX_WEB_SEND_LOG
    Log.Debug($"Web Request: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)}");
#endif
```

출처: [Runtime/Web/WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L202-L204)


## 작업 단계: WebComponent Inspector 사용

1. Hierarchy에서 `WebComponent` 컴포넌트가 부착된 GameObject를 선택합니다.
2. Inspector 패널 하단에 `Timeout` 슬라이더가 나타나며, 값 범위는 0–120입니다.
3. 슬라이더를 드래그합니다:
   - **실행 모드(Play Mode)**: 런타임 객체 `t.Timeout`에 직접 기록되며, 이후 요청에 즉시 적용됩니다.
   - **비실행 모드**: 직렬화 속성 `m_Timeout`에 기록되며, 씬/prefab과 함께 저장됩니다.

```csharp
[CustomEditor(typeof(WebComponent))]
internal sealed class WebComponentInspector : ComponentTypeComponentInspector
{
    public override void OnInspectorGUI()
    {
        base.OnInspectorGUI();
        serializedObject.Update();

        WebComponent t = (WebComponent)target;
        float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
        if (timeout != m_Timeout.floatValue)
        {
            if (EditorApplication.isPlaying)
            {
                t.Timeout = timeout;
            }
            else
            {
                m_Timeout.floatValue = timeout;
            }
        }

        serializedObject.ApplyModifiedProperties();
    }
}
```

출처: [Editor/Inspector/WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/Inspector/WebComponentInspector.cs#L7-L37)

> `WebComponentInspector`는 `ComponentTypeComponentInspector`를 상속하므로, Inspector에는 컴포넌트의 `IWebManager` 구현 타입을 선택하는 드롭다운(`RefreshComponentTypeNames(typeof(IWebManager))`)도 함께 유지됩니다.

## 일반적인 변형

- **요청만 보고 응답은 보지 않기**: `Enable Web Send Logs`만 클릭합니다. 두 매크로는 서로 독립적이므로 자유롭게 조합할 수 있습니다.
- **매크로 수동 관리**: `Project Settings → Player → Scripting Define Symbols`에 직접 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG;ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`를 입력해도 메뉴 조작과 동일한 효과가 있습니다.
- **타임아웃 동작**: `Timeout` 슬라이더로 기록된 값은 `WebManager`에서 초(WebGL) 또는 밀리초(비 WebGL) 단위로 요청에 적용됩니다. `Runtime/Web/WebManager.cs`의 `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;`와 `request.Timeout = (int)RequestTimeout.TotalMilliseconds;`를 참고하세요.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 메뉴 클릭 후에도 Console에 `Web Request/Web Response` 로그가 없음 | Console 패널에서 Debug 레벨 로그가 필터링됨 | Console 오른쪽 상단 필터에서 Debug/Info 체크 |
| 로그가 일부 플랫폼에서만 나타남 | 매크로는 Build Target별로 각각 적용되므로 플랫폼 전환 후 다시 체크해야 함 | 플랫폼 전환 후 메뉴 항목을 다시 실행 |
| 슬라이더 변경 후에도 이전 타임아웃으로 요청이 전송됨 | Play 모드가 아닐 때의 변경은 `m_Timeout`에만 기록되므로 Play 재진입 또는 씬 저장 필요 | Play 모드에서 조정하거나, 씬을 저장한 후 Play에 다시 진입 |
| 로그 내용에 `Form`/`Header`가 포함되지 않음 | 해당 요청 자체에 폼이나 요청 헤더가 없음 | 호출 측에서 전달한 header/form 매개변수 확인 |

## 검증

1. `GameFrameX/Scripting Define Symbols → Enable Web Send Logs` 실행 후 임의의 GET 요청을 발생시킵니다.
2. Console에 `Web Request: {URL} \n Header: ... \n Form: ...`가 나타나면 송신 로그가 적용된 것이며, 응답 수신 후 `Web Response: ... \n Content: ...`가 나타나면 수신 로그가 적용된 것입니다.
3. Play 모드에서 Inspector의 `Timeout` 슬라이더를 드래그하며 요청을 발생시키고, 로그의 요청 소요 시간이나 타임아웃 예외가 그에 따라 변하는지 확인합니다.

## 배경

요청 로그는 조건부 컴파일 매크로 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`로 `Log.Debug` 호출을 감싸는 방식으로 구현됩니다. 매크로가 비활성화되면 해당 코드는 컴파일 결과물에 전혀 포함되지 않으므로 정식 빌드에 성능 오버헤드가 남지 않습니다. 이것이 메뉴 스위치를 작동할 때 스크립트 재컴파일이 한 번 트리거되어야 하는 이유이기도 합니다. Inspector 측의 `Timeout` 슬라이더는 `EditorGUILayout.Slider`를 통해 Play와 비 Play 두 가지 기록 경로를 구분하여, 런타임 핫 조정과 씬 직렬화가 서로 간섭하지 않도록 보장합니다.
