# 如何使用 StartupRunner 接管启动

`ProcedureComponent` 默认会在 `Start()` 里自动初始化并启动流程；当勾选 `Use Startup Runner` 后，它只会在 `Awake` 中注册 `IProcedureManager`，真正的流程初始化与启动交给 `ApplicationStartupEntry` + `StartupRunner.Run` 接管，避免出现「Already exist FSM」冲突。

## 前置条件

- 已安装 GameFrameX 流程包（`com.gameframex.unity.procedure`）。
- 项目中已接入 GameFrameX 启动管线（`ApplicationStartupEntry` 与 `StartupRunner.Run`），否则接管流程不会有人触发。
- 场景中存在挂载了 `ProcedureComponent` 的游戏对象，可通过菜单 `GameFrameX > Procedure` 添加。

## 操作步骤

1. 在场景中选择挂载了 `ProcedureComponent` 的游戏对象，在 Inspector 中勾选 `Use Startup Runner` 复选框（对应字段 `m_UseStartupRunner`）。

2. 勾选后，`ProcedureComponent.Start()` 会立即 `yield break`，不会执行 `Initialize` 也不会调用 `StartProcedure`，仅保留 `Awake` 中的 `IProcedureManager` 注册：

   ```csharp
   private IEnumerator Start()
   {
       if (m_ProcedureManager == null)
       {
           yield break;
       }

       if (m_UseStartupRunner)
       {
           // 由 ApplicationStartupEntry + StartupRunner.Run 接管 Initialize 和 StartProcedure，
           // 本组件仅承担 Awake 注册 IProcedureManager 的职责，避免与新入口重复 Initialize 报 Already exist FSM。
           yield break;
       }
       // ...
   }
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L168)

3. 在 `ApplicationStartupEntry` 中通过 `StartupRunner.Run` 启动流程：构造流程数组并指定入口流程，最后调用 `IProcedureManager.Initialize` 与 `StartProcedure`。典型调用形态如下（与传统模式的 `Start()` 内联代码一致）：

   ```csharp
   ProcedureBase[] procedures = new ProcedureBase[m_AvailableProcedureTypeNames.Length];
   for (int i = 0; i < m_AvailableProcedureTypeNames.Length; i++)
   {
       Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
       procedures[i] = (ProcedureBase)Activator.CreateInstance(procedureType);
       if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
       {
           m_EntranceProcedure = procedures[i];
       }
   }

   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L168)

4. 运行场景，确认启动入口成功拉起首个流程（例如 `ProcedurePreload`），并在控制台看不到重复初始化相关的报错。

## 传统模式 vs StartupRunner 模式

| 模式 | 触发位置 | 入口配置 | 适用场景 |
|------|---------|---------|---------|
| 传统模式（勾选框未勾选） | `ProcedureComponent.Start()` 自动 | Inspector 中 `Available Procedures` 与 `Entrance Procedure` | 单独使用流程组件、不接入统一启动入口 |
| StartupRunner 模式（勾选框勾选） | `ApplicationStartupEntry` + `StartupRunner.Run` | 由启动入口的运行时代码决定 | 使用 GameFrameX 统一启动入口的统一管线 |

## 常见错误

- **Already exist FSM**：两种模式同时启用导致 `Initialize` 被调用两次。解决：确保只在一种模式下触发初始化，或保留 `Use Startup Runner` 勾选、移除 `Start()` 内联启动。
- **入口流程为 null**：未在 `m_EntranceProcedureTypeName` 指定有效类型名时，传统模式会打印 `Entrance procedure is invalid.` 后退出；StartupRunner 模式下需要在自己的入口代码里指定入口流程。
- **流程类型找不到**：`Utility.Assembly.GetType(...)` 返回 null 时会打印 `Can not find procedure type '{0}'.`，请检查类型全名是否含命名空间且程序集已加载。

## 背景

启用 `UseStartupRunner` 时，`Awake` 仍会通过 `GameFrameworkEntry.GetModule<IProcedureManager>()` 注册并持有流程管理器引用，但把「构造流程数组 → `Initialize` → `StartProcedure」三步推迟到 `ApplicationStartupEntry` 的 `StartupRunner.Run` 中执行，从而让流程启动受统一启动入口编排控制，与其他子系统在统一管线下串行/并行启动。
