# 10 分鐘跑通第一個遊戲腳本

跟著本頁,你能在 Unity 工程裡把 GameFrameX 跑起來,讓一個簡單的遊戲腳本(透過 `GameFrameworkLog` 輸出日誌)正常執行,作為後續使用框架其他模組的起點。

## 前置條件

- Unity 2019.4 或更高版本([README.md](/README.md#L57-L61))
- 專案啟用了 .NET Standard 2.0+ API 相容等級
- 透過 Unity Package Manager 或直接 clone 方式,把 `com.gameframex.unity` 加入工程

## 操作步驟

1. **在場景裡建立啟動腳本。** 新建一個 C# 腳本,例如 `MyGameEntry.cs`,掛到任意場景物體上:

   ```csharp
   using UnityEngine;
   using GameFrameX;

   public class MyGameEntry : MonoBehaviour
   {
       private void Start()
       {
           // 框架提供的統一日誌入口,詳見 GameFrameworkLog
           GameFrameworkLog.Info("Hello, GameFrameX!");
       }
   }
   ```

2. **確認命名空間。** 框架的執行階段基底類別位於 `GameFrameX` 命名空間下,例如 `GameFrameworkEntry`、`GameFrameworkLog` 等(目錄參考 [Runtime/Base](/Runtime/Base))。

3. **執行場景。** 在 Unity 中點擊 Play,Console 視窗應輸出 `Hello, GameFrameX!`,說明框架執行階段已被正確載入並可被你的腳本呼叫。

4. **接入框架事件(選用,驗證擴充能力)。** 如果你想繼續驗證事件/任務池,可以定義一個繼承自框架事件基底類別的參數,並使用事件訂閱 API 來監聽它(詳見《事件池》與《任務池》章節)。

## 常見變體

- **作為 UPM 套件安裝**:在 `Packages/manifest.json` 的 `dependencies` 中加入 `"com.gameframex.unity": "https://github.com/GameFrameX/com.gameframex.unity.git"`,然後回到本頁步驟 1。
- **作為子模組 / 直接嵌入**:把倉庫複製到工程 `Assets/` 下任意目錄,完成後同樣從步驟 1 開始。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| `GameFrameworkLog` 找不到 | 命名空間未引用或套件未正確匯入 | 在腳本頂部 `using GameFrameX;`,並確認套件已加入 `Packages/manifest.json` |
| Console 無任何輸出 | 腳本未掛載或 `Start` 未觸發 | 把腳本掛到場景物體上,確保場景被載入 |
| 編譯報 `.NET Standard` 相關錯誤 | 工程 API 相容等級過低 | Player Settings → Api Compatibility Level 改為 `.NET Standard 2.1` |

## 背景(選用)

GameFrameX 採用 Runtime / Plugins / Editor 三層模組化架構,Runtime 模組下的 `Base/` 提供框架核心基座,包括日誌、事件池、引用池、任務池、變數系統等子系統([README.md](/README.md#L65-L108))。完成本頁腳本執行後,可繼續閱讀各子系統頁面深入使用。
