# 切換儲存後端

將 Setting 模組的鍵值儲存從預設的 `UnityPlayerPrefsSettingStorage` 切換至小遊戲平台 SDK 所提供的儲存後端，把設定資料保存到小遊戲平台自身的儲存媒體中。

## 前提條件

- 已安裝 `com.gameframex.unity.setting` 套件以及其所依賴的 GameFrameX Runtime。
- 目標平台為小遊戲（WeChat／Douyin／Alipay／Kuaishou 等），且已匯入對應平台的 adapter 組件（包含 `RegisterMiniGameBackend` 的呼叫）。
- 在 Unity Editor 中執行時不會經過小遊戲的工廠分支，將繼續使用 `UnityPlayerPrefsSettingStorage`。若要驗證儲存邏輯，必須建置至目標平台並執行。

## 操作步驟

1. 實作自訂後端。小遊戲 SDK 通常以非同步方式提供 `setStorageSync`／`getStorageSync`，因此需要將其包裝為 `ISettingStorageBackend`。最小契約包含 `Save`、`HasKey`、`DeleteKey`、`DeleteAll`、`GetInt/SetInt`、`GetFloat/SetFloat`、`GetString/SetString`。

   來源：[ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs#L1-L30)

2. 產生工廠委派並註冊至 `SettingStorageBackendFactory`。在遊戲啟動階段（GameFrameX 框架初始化之後、首次 `SettingComponent.Save`／`Load` 之前）呼叫以下內容：

   ```csharp
   using GameFrameX.Setting.Runtime;

   SettingStorageBackendFactory.RegisterMiniGameBackend(() => new WeChatMiniGameSettingStorage());
   ```

   註冊方法在傳入 `null` 時會拋出 `GameFrameworkException("Storage backend factory is invalid.")`。

   來源：[SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

3. 工廠會在執行時選擇後端。`Create()` 的分支邏輯如下：

   | 建置條件 | 使用的後端 |
   |----------|----------|
   | `UNITY_EDITOR` | `UnityPlayerPrefsSettingStorage`（固定） |
   | 玩家建置且 `s_MiniGameBackendFactory` 已註冊 | 已註冊工廠的回傳值 |
   | 玩家建置但未註冊 | 回退至 `UnityPlayerPrefsSettingStorage`（不會拋出錯誤） |

   來源：[SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L32-L39)

4. 讓 `SettingHelperBase` 的具體實作使用此後端。套件內預設的 `PlayerPrefsSettingHelper` 會直接呼叫 `UnityEngine.PlayerPrefs`，因此在跨平台對應時，需要改寫為將處理委派給 `SettingStorageBackendFactory.Create()` 回傳的物件。如此可避免在不支援 `PlayerPrefs` 的平台（部分小遊戲執行環境）上發生找不到 API 的問題。

   來源：[UnityPlayerPrefsSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/UnityPlayerPrefsSettingStorage.cs#L9-L67)

## 常見變化

- **官方小程式 SDK adapter**：`Runtime/MiniGame/` 目錄下已提供 WeChat、Douyin、Alipay、Kuaishou 四種 adapter（如 `WeChatMiniGameSettingStorage.cs`），各自會在平台 SDK 啟動時呼叫 `SettingStorageBackendFactory.RegisterMiniGameBackend` 來註冊自身的實作。只需匯入對應的 adapter 組件即可，無需自行實作 `ISettingStorageBackend`。
- **加密儲存**：在自訂後端中於 `SetString` 時進行 AES 加密、於 `GetString` 時進行解密，然後註冊該後端。
- **記憶體／除錯後端**：在單元測試或除錯場景中，可註冊僅保存至記憶體內字典的實作。每次程序重新啟動時會自動清除。

## 常見錯誤

- **`UNITY_EDITOR` 下自訂後端無法生效**：`Create()` 在 Editor 下始終回傳 `UnityPlayerPrefsSettingStorage`，因此即使註冊邏輯有執行也不會生效。必須建置至目標平台的小程式並執行。
- **註冊時機過晚**：若在 `SettingComponent.Save()` 或首次 `Load()` 之後才呼叫 `RegisterMiniGameBackend`，已快取的 PlayerPrefs 後端將不會被替換。請務必在 `SettingManager` 首次持久化之前完成註冊。
- **註冊 `null` 工廠**：會直接拋出 `GameFrameworkException("Storage backend factory is invalid.")`，導致啟動流程中斷。請在傳入前進行 null 檢查。
- **未替換 `PlayerPrefsSettingHelper`**：若業務邏輯同時使用 `PlayerPrefsSettingHelper`，它會直接呼叫 `UnityEngine.PlayerPrefs`。在不支援 PlayerPrefs 的小遊戲執行環境中將導致編譯／執行失敗。請替換為自訂 Helper，或以統一的儲存存取方式加以包裝。

## 背景（可選）

儲存後端的設計目的，是將「使用什麼來保存」從 `SettingHelperBase` 的衍生類別中分離出來。平台 SDK 的匯入方透過 `RegisterMiniGameBackend` 注入工廠，再由 `SettingStorageBackendFactory.Create()` 在執行時依平台進行選擇。Editor 為了除錯會始終回退至 `UnityPlayerPrefsSettingStorage`，未註冊時同樣會安全地回退。
