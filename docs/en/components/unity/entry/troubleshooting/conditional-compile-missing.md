# What to Do When Conditional Compilation Makes a Subsystem Unavailable

When a subsystem property on `GameApp` (such as `Network`, `GUI`, `Entity`, `Download`) cannot be accessed, the compiler reports "`GameApp` does not contain a definition for XXX", or calling it directly throws a null reference, it is usually because the corresponding conditional compilation symbol is missing, causing the entire `GameApp.XXX.cs` file to be excluded as a whole by `#if … #endif` at compile time—not because the API genuinely does not exist.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Properties such as `GameApp.Network`, `GameApp.GUI`, `GameApp.Entity` cannot be found; IDE shows red errors | The corresponding `ENABLE_GAME_FRAME_X_XXX` symbol is not defined, so the entire `GameApp.XXX.cs` is excluded by `#if … #endif` | Add the missing symbol in *Project Settings → Player → Scripting Define Symbols*, or install the corresponding submodule package |
| The component returned by calling `GameApp.XXX` is `null`; calling its methods throws `NullReferenceException` | The symbol is defined and the property exists, but the underlying component is not registered with `GameEntry` | Check the `GameEntry.RegisterComponent` flow and confirm that the corresponding Runtime package is installed and started |
| A subsystem suddenly becomes unavailable after switching platforms (e.g., iOS/Android/Editor) | Some symbols are also wrapped in platform-specific compilation, or symbols are only defined for specific platforms | Check whether the symbol changes together with platform symbols such as `UNITY_IOS` and `UNITY_ANDROID` |

## Fix Steps

### 1. Confirm which subsystem you are using

Each subsystem corresponds to a `Runtime/GameApp.<Name>.cs` file, wrapped at the beginning and end by the same symbol. Below are the subsystems currently present in the repository and their corresponding symbols:

| Subsystem | File | Conditional Compilation Symbol |
|--------|------|------------|
| Network | `Runtime/GameApp.Network.cs` | `ENABLE_GAME_FRAME_X_NETWORK` |
| GUI (UGUI) | `Runtime/GameApp.GUI.cs` | `ENABLE_GAME_FRAME_X_L_UGUI` |
| Entity | `Runtime/GameApp.Entity.cs` | `ENABLE_GAME_FRAME_X_ENTITY` |
| Download | `Runtime/GameApp.Download.cs` | `ENABLE_GAME_FRAME_X_DOWNLOAD` |
| GlobalConfig | `Runtime/GameApp.GlobalConfig.cs` | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` |
| Advertisement | `Runtime/GameApp.Advertisement.cs` | `ENABLE_GAME_FRAME_X_ADVERTISEMENT` |
| Apple Login | `Runtime/GameApp.AppleLogin.cs` | `ENABLE_GAME_FRAME_X_APPLE_LOGIN` |
| Facebook Login | `Runtime/GameApp.FaceBookLogin.cs` | `ENABLE_GAME_FRAME_X_FACEBOOK_LOGIN` |
| Google Login | `Runtime/GameApp.GoogleLogin.cs` | `ENABLE_GAME_FRAME_X_GOOGLE_LOGIN` |
| QQ Login | `Runtime/GameApp.QQLogin.cs` | `ENABLE_GAME_FRAME_X_QQ_LOGIN` |
| WeChat Login | `Runtime/GameApp.WeChatLogin.cs` | `ENABLE_GAME_FRAME_X_WECHAT_LOGIN` |
| In-App Purchase Payment | `Runtime/GameApp.Payment.cs` | `ENABLE_GAME_FRAME_X_PAYMENT` |
| Mono Behaviour | `Runtime/GameApp.Mono.cs` | `ENABLE_GAME_FRAME_X_MONO` |
| Web ProtoBuf | `Runtime/GameApp.Web.ProtoBuff.cs` | `ENABLE_GAME_FRAME_X_WEB_PROTO_BUFF` |

> There is one naming exception: the GUI subsystem's symbol is `ENABLE_GAME_FRAME_X_L_UGUI` (with the `L_` prefix), not `ENABLE_GAME_FRAME_X_GUI`; simply add the symbol name exactly as shown in the table.

### 2. Add the missing symbol in Scripting Define Symbols

Open `Edit → Project Settings → Player`, and in *Other Settings → Configuration → Scripting Define Symbols*, add the symbol you found in the previous step. Separate multiple symbols with a semicolon `;`.

```text
ENABLE_GAME_FRAME_X_NETWORK;ENABLE_GAME_FRAME_X_L_UGUI;ENABLE_GAME_FRAME_X_ENTITY
```

After adding them, return to the IDE and trigger a script recompilation (`Assets → Reimport` or restart the Editor); the IDE red errors will disappear.

### 3. Confirm the corresponding Runtime package is installed

The symbol is just a switch; the actual types (such as `NetworkComponent` and `UGUIComponent`) come from the Runtime assemblies of each submodule. The snippet below is `GameApp.Network.cs`, which only participates in compilation once the symbol is enabled; as you can see, it depends on `GameFrameX.Network.Runtime`:

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Network.Runtime;
using GameFrameX.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// Gets the network component.
    /// </summary>
    public static NetworkComponent Network
    {
        get
        {
            if (_network == null)
            {
                _network = GameEntry.GetComponent<NetworkComponent>();
            }

            return _network;
        }
    }

    private static NetworkComponent _network;
}
#endif
```

Source: [Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L56)

The GUI subsystem works the same way:

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
using GameFrameX.Runtime;
using GameFrameX.LUGUI.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// Gets the UI component.
    /// </summary>
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }

            return _gui;
        }
    }

    private static UGUIComponent _gui;
}
#endif
```

Source: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

If you have added the symbol but types such as `NetworkComponent` / `UGUIComponent` still cannot be found, it means the corresponding submodule package has not been installed via UPM/Package Manager; open `Window → Package Manager` and install the corresponding package.

### 4. Confirm the component is registered with `GameEntry` at startup

Internally, `GameApp.XXX` all use `GameEntry.GetComponent<XXXComponent>()`, so the component must also have been registered in the startup flow. If `GetComponent` returns `null`, add the corresponding component in `GameEntry`'s `RegisterComponent` call chain.

## Verification

1. Properties such as `GameApp.Network` and `GameApp.GUI` no longer show red errors in the IDE.
2. At runtime, calling `GameApp.Network` no longer returns `null`, and method calls no longer throw `NullReferenceException`.
3. When switching compilation between different target platforms (Editor, iOS, Android), the subsystems in use are available on every platform.
