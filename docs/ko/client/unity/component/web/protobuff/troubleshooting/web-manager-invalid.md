# 시작 시 "Web manager is invalid." 치명적 로그가 발생하면 어떻게 해야 하나요

이 Fatal 로그는 `WebProtoBuffComponent.Awake()`에서 발생합니다: `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()`가 `null`을 반환할 때 출력되며, Web ProtoBuff 관리자 모듈을 성공적으로 가져오지 못했음을(등록되지 않았거나 구현 타입이 제거됨) 나타냅니다. 컴포넌트는 즉시 `return`하며, 이후 모든 Web 요청 호출이 실패하게 됩니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 시작 시 즉시 `Web manager is invalid.`가 출력되고, 이후 `Post` 등 인터페이스 호출 시 `NullReferenceException` 발생 | `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()`가 `null`을 반환함, 관리자 구현체가 프레임워크 엔트리에 등록되지 않음 | 아래 수정 단계 1 참조 |
| 빌드 패키지(실기기/스트리핑 후)에서만 이 로그가 발생하고, 에디터에서는 정상 동작 | 관리 코드 스트리핑이 `WebProtoBuffManager` 구현 클래스를 제거함 | 아래 수정 단계 2 참조 |
| 오브젝트에서 `GameFrameXWebProtoBuffCroppingHelper`를 수동으로 삭제한 경우 | 해당 Helper는 `typeof`로 관리자 타입을 참조하여 링커 스트리핑을 방지하는 데 사용됨 | 아래 수정 단계 3 참조 |

## 수정 단계

로그 판정 코드는 다음과 같으며, 대조하여 문제를排查하는 데 사용할 수 있습니다:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IWebProtoBuffManager);
    base.Awake();
    m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
    if (m_WebProtoBuffManager == null)
    {
        Log.Fatal("Web manager is invalid.");
        return;
    }

    m_WebProtoBuffManager.Timeout = m_Timeout;
}
```

출처: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L77-L90)

1. **관리자 구현 클래스 접근 가능 확인**. `WebProtoBuffManager`(`Runtime/Web/WebProtoBuffManager.cs` 위치, 네임스페이스 `GameFrameX.Web.ProtoBuff.Runtime`)는 `IWebProtoBuffManager`의 구현체이며, `GetModule`은 `GameFrameworkEntry`가 포함된 GameFrameX 런타임 기본 패키지에 의존하여 등록을 완료합니다. 프로젝트에 GameFrameX 기본 런타임 패키지가 올바르게 설치되어 있고, 이 패키지의 어셈블리 컴파일에 오류가 없는지(Console에 빨간색 컴파일 오류 없음) 확인하세요.
2. **관리 코드 스트리핑 낮추기/비활성화**. Unity의 `Player Settings → Managed Stripping Level`에서 스트리핑 수준을 낮추거나, 이 패키지 어셈블리에 대한 보존 규칙을 구성하여 `WebProtoBuffManager`가 제거되지 않도록 합니다.
3. **스트리핑 방지 Helper 유지**. `WebProtoBuffComponent`는 `[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]`를 통해 해당 Helper를 강제로 의존하며, 이 Helper는 이 패키지의 모든 핵심 타입에 대한 참조를 유지합니다:

```csharp
[Preserve]
public class GameFrameXWebProtoBuffCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(WebProtoBuffComponent);
        _ = typeof(IWebProtoBuffManager);
        _ = typeof(WebProtoBuffManager);
    }
}
```

출처: [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs#L6-L16)

   씬 내 오브젝트의 `GameFrameXWebProtoBuffCroppingHelper` 컴포넌트를 수동으로 삭제하지 마세요.
4. **필요에 따라 네트워크 매크로 활성화**. Protocol Buffer 요청을 사용해야 하는 경우 `Scripting Define Symbols`에 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`를 추가하세요. 그렇지 않으면 `Post<T>`가 컴포넌트에 컴파일되지 않습니다(`WebProtoBuffComponent.cs` 92행의 `#if` 조건 참조).

## 검증

- Play 모드에 다시 진입(또는 다시 빌드)하면 Console에 더 이상 `Web manager is invalid.` Fatal 로그가 나타나지 않습니다.
- 컴포넌트 Inspector에서 `Timeout`(기본값 `5f`초)을 수정하면 정상적으로 적용됩니다 — 이는 `m_WebProtoBuffManager.Timeout`을 직접 읽고 씁니다.
- 매크로 활성화 후 `WebProtoBuffComponent.Post<T>(url, message)`를 정상적으로 호출할 수 있습니다.
