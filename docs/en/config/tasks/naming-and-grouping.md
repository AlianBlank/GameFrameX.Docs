# How to Name Tables and Restrict the Generation Target (client/server)

Through the file naming convention, you can decide which side (client / server / both) each Excel data table is generated for, as well as what the final generated C# class name will be. Naming follows the `Letter - EnglishName [- Group] - ChineseName.xlsx` format.

## Naming Formula

```
Letter - EnglishName - ChineseName.xlsx
Letter - EnglishName - Group - ChineseName.xlsx      ← Use this when you want to restrict the table to one side only
```

Meaning of the three segments:

| Segment | Purpose | Rule | Example |
|----|------|------|------|
| **Letter** | A single letter used for sorting, making files easy to find | Any letter or number | `C`, `D`, `S`, `L` |
| **English name** | Becomes the code class name `TbEnglishName` | English only; **Chinese is not allowed** | `ItemConfig` → `TbItemConfig` |
| **Group** (optional) | Restricts generation to client / server | See the table below | `c`, `s` |
| **Chinese name** | A human-readable name | Anything you like; multiple `-` separators are allowed | `道具表`, `道具表-1001` |

> ⚠️ **Never write Chinese in the English name**, otherwise the tool will report an error: *"Chinese table names are not supported"*.

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L163-L200)

## Steps

1. **Decide on the English name** — it will be used as the C# class name. Once you've picked it, keep it in mind; the tool automatically adds the `Tb` prefix.
2. **Decide whether to restrict the generation target**:
   - No restriction (generated for both sides): don't add the group segment.
   - Client only: add `-c-` after the English name.
   - Server only: add `-s-` after the English name.
3. **Add the sorting letter and the Chinese name**, assembling the final file name according to `Letter - EnglishName [- Group] - ChineseName.xlsx`.
4. Place the file under `Excels/Tables/`, then run the corresponding `gen-client-*.bat/.sh` or `gen-server-*.bat/.sh` to regenerate the code.

## Generation Target Reference

| File Name | Effect |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | Used by **both** client and server (default) |
| `D-ItemConfig-c-道具表.xlsx` | **Client only** |
| `D-ItemConfig-s-道具表.xlsx` | **Server only** |

> `c` = client, `s` = server. Without a group, the table is generated for both sides.

The grouping rules come from the `c` / `s` groups defined in [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L15), as well as the `groups` list that each of the `targets` in [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L35-L60) is bound to.

## Common Variants

**Splitting one table into multiple files**: When a table has a particularly large amount of data (e.g., thousands of items), you can split it into several files by number. As long as the **English names are identical**, they are automatically merged into a single C# class:

```
D-ItemConfig-道具表-1-1000.xlsx      ← Items 1~1000
D-ItemConfig-道具表-1001-2000.xlsx   ← Items 1001~2000
D-ItemConfig-道具表-2001-3000.xlsx   ← Items 2001~3000
```

The three files are ultimately merged into a single `TbItemConfig`. Localization tables are split according to the same rule:

```
L-Localization-成就.xlsx    ┐
L-Localization-文本.xlsx    ├→ merged into a single TbLocalization
L-Localization-UI.xlsx      ┘
```

The numbers and categories inside the Chinese name are for humans only; the tool does not parse them.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The tool reports the error *"Chinese table names are not supported"* | Chinese characters were written in the English-name segment | Change the English-name segment to pure English and move the Chinese text to the third segment |
| The Excel file was modified but no new class appears in the code | The file is not under `Excels/Tables/`, or the group is written incorrectly | Confirm the file location and double-check the English name and group |
| You wanted only one of client / server to use the table, but it ended up on both sides | The `-c-` or `-s-` group segment is missing | Add `-c-` (client) or `-s-` (server) after the English name |
| Split into multiple files but multiple classes were generated | The English names of the files are inconsistent | Make the English-name segment exactly identical across all files for the same table |

## Background (Optional)

The grouping mechanism is defined by the `groups` and `targets` sections of `luban.conf`: `groups` lists the two groups `c` and `s`, and in `targets`, `client` is bound to `groups: ["c"]` while `server` is bound to `groups: ["s"]`. Whichever group appears in the file name, the tool generates the table only for the targets bound to that group. The configuration is controlled by [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L60) and generally requires no modification.

For details on filling in table headers (`##var` / `##type` / `##group` / `##`) and field types, see *How to Fill In Data Table Headers and Field Types*.
