# 増分ビルドを有効化する方法

`BuildAsset` を呼び出してリソースパッケージをビルドする際、`IsIncrementalBuildPackage` を `true` に設定することで、ビルダーは YooAsset のビルドモードを `EBuildMode.IncrementalBuild` に切り替え、変更があったリソースのみを再パッケージ化し、変更されていない部分はスキップするため、ビルド時間を大幅に短縮できます。

## 前提条件

- 『クイックスタート』に従って `GameFrameX.Builder.Editor` アセンブリを統合済みであること。
- 現在のビルドパイプラインが `BuiltinBuildPipeline` または `RawFileBuildPipeline` であること(どちらも `BuildParameters` が `BuildMode` フィールドをサポートしています)。
- 今回のビルド対象が、過去に出力履歴のあるリソースパッケージディレクトリであること。初回ビルドは再利用可能なキャッシュがないため、フル再構築と同じ効果になります。

## 操作手順

1. **コードで有効化する**

   `BuilderOptions.IsIncrementalBuildPackage` に直接 `true` を代入してからビルドを呼び出します:

   ```csharp
   var options = new GameFrameX.Builder.Editor.BuilderOptions
   {
       PackageName = "DefaultPackage",
       IsIncrementalBuildPackage = true,
   };
   GameFrameX.Builder.Editor.Builder.BuildAsset(options);
   ```

   ソース: [Editor/BuilderOptions.cs#L72-L75](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L72-L75)

2. **コマンドライン引数で有効化する**

   CI / バッチスクリプトに `-IsIncrementalBuildPackage` フラグを追加すると、`Builder.BuildParamsParse` がそれを `true` として解析します(コマンドライン方式では値を渡す必要はなく、このフラグが存在すれば有効とみなされる点に注意してください):

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
         -PackageName DefaultPackage \
         -IsIncrementalBuildPackage
   ```

   ソース: [Editor/Builder.BuildParamsParse.cs#L90-L93](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L90-L93)

3. **有効化されたことを確認する**

   ビルド開始後、`Builder.BuildAsset` は次の代入を実行し、YooAsset のビルドモードを増分ビルドに切り替えます:

   ```csharp
   buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage
       ? EBuildMode.IncrementalBuild
       : EBuildMode.ForceRebuild;
   ```

   ソース: [Editor/Builder.BuildAsset.cs#L65](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L65)

   `IsIncrementalBuildPackage` が `false`(デフォルト値)の場合、または `-IsIncrementalBuildPackage` が指定されていない場合、ビルドモードは `EBuildMode.ForceRebuild` となります。

## よくあるバリエーション

- **リソースアップロードと増分ビルドを同時に行う**: `-IsUploadAsset` と `-IsIncrementalBuildPackage` を一緒に指定するだけで、両フラグは独立して解析され互いに影響しません。
- **フルビルドにフォールバックする**: 正式版のメジャーバージョンをリリースする前に、このパラメータを削除するか、明示的に `false` を指定することをお勧めします(フラグを指定しない場合のデフォルトは `false`)、強制的に `EBuildMode.ForceRebuild` で再構築を行います。

## よくあるエラー

- **初回ビルドでも増分ビルドが実行され、有効化に失敗したと思い込む**: 増分ビルドは前回の出力キャッシュに依存します。初回出力には再利用可能なキャッシュがないため、出力結果がフルビルドと同じになるのは正常な動作です。
- **コマンドラインでハイフンプレフィックスの書き忘れ**: `-IsIncrementalBuildPackage` には `-` が必須です。`IsIncrementalBuildPackage` と書くと解析されず、デフォルト値の `false` として処理されます。
- **`PackageName` のスペルミスによる混在**: 増分ビルドのキャッシュはパッケージ名ディレクトリごとに分離されています。`PackageName` を新しい名前に変更するとキャッシュが一致せず、「フルビルドと同じくらい遅い」という現象になります。古いキャッシュを再利用する場合は、必ず `PackageName` を一致させてください。

## 背景(オプション)

`IsIncrementalBuildPackage` は `BuilderOptions` 内では単なる通常のブールフィールドであり、実際に有効化されるのは `Builder.BuildAsset` がその値を YooAsset の `EBuildMode`(増分 vs 強制再構築)にマップする部分です。コマンドラインとコードの2つのエントリポイントは最終的に同じフィールドに集約されるため、両方式の動作は一致しています。
