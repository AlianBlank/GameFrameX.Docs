# Multi-Resolution Adaptation

FairyGUI's multi-resolution adaptation is driven by the `UIContentScaler` component: you set a design resolution and a match mode, and at runtime a global `scaleFactor` is calculated based on the screen size to scale `GRoot`, so the UI maintains a consistent visual proportion across different resolutions. You can configure the component in the Inspector, or set it in code with `GRoot.inst.SetContentScaleFactor`.

## Prerequisites

- A FairyGUI `Stage` already exists in the scene (GRoot is attached to its GameObject). In Play Mode, the actual scaling parameters are always taken from the `UIContentScaler` on the `Stage` object.
- If you need to edit the scaling parameters in the Inspector, the custom `UIContentScaler` editor can be found at [UIContentScalerEditor.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/UIContentScalerEditor.cs#L13).

## Steps

### Method 1: Configure UIContentScaler in the Inspector

1. Select the GameObject containing `Stage` and add the component via the menu `FairyGUI/UI Content Scaler`:

    ```csharp
    [AddComponentMenu("FairyGUI/UI Content Scaler")]
    public class UIContentScaler : MonoBehaviour
    ```

    Source: [UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L8-L10)

2. In the Inspector, set the following in order:
   - **Design Resolution X / Y**: the design resolution (e.g., 1920 × 1080).
   - **Screen Match Mode**: the width/height match mode (see table below).
   - **Ignore Orientation**: whether to keep the proportion without recalculating when switching between landscape and portrait (default `false`, i.e., automatic adaptation).

3. Enter Play Mode. On `OnEnable`, the component passes the parameters to the `UIContentScaler` on `Stage`, taking effect immediately:

    ```csharp
    UIContentScaler scaler = Stage.inst.gameObject.GetComponent<UIContentScaler>();
    if (scaler != this)
    {
        scaler.scaleMode = scaleMode;
        if (scaleMode == ScaleMode.ScaleWithScreenSize)
        {
            scaler.designResolutionX = designResolutionX;
            scaler.designResolutionY = designResolutionY;
            scaler.screenMatchMode = screenMatchMode;
            scaler.ignoreOrientation = ignoreOrientation;
        }
        else if (scaleMode == ScaleMode.ConstantPhysicalSize)
        {
            scaler.fallbackScreenDPI = fallbackScreenDPI;
            scaler.defaultSpriteDPI = defaultSpriteDPI;
        }
        else
        {
            scaler.constantScaleFactor = constantScaleFactor;
        }
        scaler.ApplyChange();
        GRoot.inst.ApplyContentScaleFactor();
    }
    ```

    Source: [UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L81-L112)

### Method 2: Call GRoot.SetContentScaleFactor in Code

```csharp
// Set by design resolution + match mode (default MatchWidthOrHeight)
GRoot.inst.SetContentScaleFactor(1920, 1080);

// Specify the match mode
GRoot.inst.SetContentScaleFactor(1920, 1080, UIContentScaler.ScreenMatchMode.MatchHeight);

// Use a fixed pixel scale (ConstantPixelSize)
GRoot.inst.SetContentScaleFactor(1.5f);
```

Its internal implementation:

```csharp
public void SetContentScaleFactor(int designResolutionX, int designResolutionY, UIContentScaler.ScreenMatchMode screenMatchMode)
{
    UIContentScaler scaler = Stage.inst.gameObject.GetComponent<UIContentScaler>();
    scaler.designResolutionX = designResolutionX;
    scaler.designResolutionY = designResolutionY;
    scaler.scaleMode = UIContentScaler.ScaleMode.ScaleWithScreenSize;
    scaler.screenMatchMode = screenMatchMode;
    scaler.ApplyChange();
    ApplyContentScaleFactor();
}
```

Source: [GRoot.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GRoot.cs#L93-L102)

### Responding to Screen Size Changes

During initialization, `Stage` automatically calls `GRoot._inst.ApplyContentScaleFactor()` once (see [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L119)), which sets the GRoot size to "screen size ÷ scaleFactor" and scales it as a whole:

```csharp
public void ApplyContentScaleFactor()
{
    this.SetSize(Mathf.CeilToInt(Stage.inst.width / UIContentScaler.scaleFactor), Mathf.CeilToInt(Stage.inst.height / UIContentScaler.scaleFactor));
    this.SetScale(UIContentScaler.scaleFactor, UIContentScaler.scaleFactor);
}
```

Source: [GRoot.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GRoot.cs#L120-L124)

To manually recalculate when the window/resolution changes, call `scaler.ApplyChange()` first, then `GRoot.inst.ApplyContentScaleFactor()`.

## Configuration Quick Reference

| Field | Type / Default | Description |
|------|---------------|------|
| `scaleMode` | `ScaleMode` enum | `ConstantPixelSize` / `ScaleWithScreenSize` / `ConstantPhysicalSize` |
| `screenMatchMode` | `ScreenMatchMode` enum | `MatchWidthOrHeight` / `MatchWidth` / `MatchHeight` |
| `designResolutionX` / `designResolutionY` | `int` | Design resolution; when 0, `ApplyChange` returns directly without scaling |
| `fallbackScreenDPI` | `int`, default `96` | Fallback DPI used when the device DPI is 0 |
| `defaultSpriteDPI` | `int`, default `96` | Standard DPI for atlas sprites |
| `constantScaleFactor` | `float`, default `1` | Fixed scale factor in `ConstantPixelSize` mode |
| `ignoreOrientation` | `bool`, default `false` | When `false`, dx/dy are automatically swapped according to the orientation of the screen versus the design resolution, so the proportion doesn't jump when switching between landscape and portrait |
| `UIContentScaler.scaleFactor` | `static float`, initial value `1` | Current global scale factor, capped at 10 |
| `UIContentScaler.scaleLevel` | `static int` | Multiplier tier based on scaleFactor (0=x1, 1=x2, 2=x3, 3=x4) |

Original enum definitions:

```csharp
public enum ScaleMode
{

    ScaleWithScreenSize,
    ConstantPhysicalSize
}

public enum ScreenMatchMode
{
    MatchWidthOrHeight,
    MatchWidth,
    MatchHeight
}
```

## Common Variants

- **UI supporting both landscape and portrait**: keep `ignoreOrientation = false` (default). `ApplyChange` automatically swaps dx/dy when "screen is landscape, design is portrait" or "screen is portrait, design is landscape", ensuring `scaleFactor` doesn't jump when the screen rotates (see [UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L164-L172)).
- **Scale by physical size (DPI)**: set `scaleMode` to `ConstantPhysicalSize` and configure `defaultSpriteDPI` and `fallbackScreenDPI`. The calculation is `scaleFactor = dpi / defaultSpriteDPI` (use `fallbackScreenDPI` when the device has no DPI; if it is still 0, use 96), see [UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L185-L195).
- **Make UI components follow the screen size**: adaptation only handles global scaling; to stretch individual components along with GRoot, use Relations, e.g., `pane.AddRelation(GRoot.inst, RelationType.Size)`, which internally relies on the `onSizeChanged` event (see [RelationItem.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/RelationItem.cs#L575)).

scaleFactor calculation for each match mode (under `ScaleWithScreenSize`):

```csharp
if (screenMatchMode == ScreenMatchMode.MatchWidthOrHeight)
{
    float s1 = (float)screenWidth / dx;
    float s2 = (float)screenHeight / dy;
    scaleFactor = Mathf.Min(s1, s2);
}
else if (screenMatchMode == ScreenMatchMode.MatchWidth)
    scaleFactor = (float)screenWidth / dx;
else
    scaleFactor = (float)screenHeight / dy;
```

Source: [UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L174-L183)

## Common Mistakes

| Symptom | Cause | Fix |
|------|------|------|
| UI doesn't scale after setting the resolution | `designResolutionX` or `designResolutionY` is 0, so `ApplyChange` returns directly | Fill in a non-zero design resolution ([UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L159-L162)) |
| Modifying the Scaler in the scene has no effect in Play Mode | In Play Mode, the `UIContentScaler` on the `Stage` GameObject is what actually takes effect; other components merely "pass the parameters over" | Configure it on the `Stage` object, or use `GRoot.inst.SetContentScaleFactor` instead ([UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L85-L88)) |
| UI proportion jumps after switching between landscape and portrait | `ignoreOrientation` was set to `true`, so orientation changes no longer participate in the calculation | Change it back to `false` ([UIContentScaler.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIContentScaler.cs#L66-L70)) |
| The other dimension gets cropped or black bars appear with MatchWidth/Height | Single-side matching only aligns one side | Switch to `MatchWidthOrHeight`, which takes `min(s1, s2)` to ensure neither side gets cropped |
| UI too large/small on high-resolution screens | In `ConstantPixelSize` mode, `constantScaleFactor` is fixed and doesn't change with resolution | Switch to `ScaleWithScreenSize` + a design resolution |

## Verification

- Print the global scale factor to confirm it has taken effect: `Debug.Log(UIContentScaler.scaleFactor)`.
- Check that `GRoot.inst.width / height` is approximately "screen size ÷ design ratio" (`ApplyContentScaleFactor` rounds up with `Mathf.CeilToInt`, see [GRoot.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GRoot.cs#L120-L124)).
- Change the Game view resolution/aspect ratio and confirm the UI layout and sharpness meet expectations.

## Background

`UIContentScaler.ApplyChange` calculates `scaleFactor` based on `scaleMode` (capped at 10), then calls `UpdateScaleLevel` to bucket it into a multiplier tier of 0–3 and increments `StageCamera.screenSizeVer` to trigger a camera update; `GRoot.ApplyContentScaleFactor` then scales GRoot by `scaleFactor` and sets its logical size to the screen size divided by `scaleFactor`. For the overall structure of Stage and GRoot, see the overview page.
