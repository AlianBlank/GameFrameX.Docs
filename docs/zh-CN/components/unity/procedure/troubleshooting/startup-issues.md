# 启动相关问题怎么办

本页汇总 `ProcedureComponent` 启动阶段最常见的报错和异常情况,基于 [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs) 和 [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs) 的实际行为给出修复方法。

## 快速诊断

| 症状(控制台原文) | 原因 | 修复 |
|------|------|------|
| `Procedure manager is invalid.` | 框架未能从 `GameFrameworkEntry` 获取 `IProcedureManager`,通常是没有挂载 `ProcedureComponent` 或组件未执行 `Awake`。 | 见 [修复 1](#修复-1procedure-manager-is-invalid) |
| `Available procedure type names is empty. Procedure auto start skipped.` | Inspector 里 `Available Procedure Type Names` 数组为空。 | 见 [修复 2](#修复-2available-procedure-type-names-is-empty) |
| `Can not find procedure type '{0}'.` | `Available Procedure Type Names` 中的类型名字符串在当前程序集里查不到对应 `Type`。 | 见 [修复 3](#修复-3can-not-find-procedure-type) |
| `Can not create procedure instance '{0}'.` | 类型名能查到,但无法通过 `Activator.CreateInstance` 实例化(抽象类 / 无公共构造函数)。 | 见 [修复 4](#修复-4can-not-create-procedure-instance) |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` 没出现在 `Available Procedure Type Names` 里。 | 见 [修复 5](#修复-5entrance-procedure-is-invalid) |
| `You must initialize procedure first.` | 在 `Initialize` 之前就调用了 `StartProcedure` / `HasProcedure` / `GetProcedure` / `CurrentProcedure` / `CurrentProcedureTime`。 | 见 [修复 6](#修复-6you-must-initialize-procedure-first) |
| `Procedures is invalid.` | 自己调用 `m_ProcedureManager.Initialize(..., procedures)` 时传入了空数组。 | 见 [修复 7](#修复-7procedures-is-invalid) |
| `Already exist FSM.` 启动后再次进入场景 | 启用了 `Use Startup Runner` 但仍让 `ProcedureComponent` 跑旧逻辑,被 `ApplicationStartupEntry` 重复初始化。 | 见 [修复 8](#修复-8already-exist-fsm) |

## 修复步骤

### 修复 1:Procedure manager is invalid

`ProcedureComponent.Awake` 中执行:

```csharp
m_ProcedureManager = GameFrameworkEntry.GetModule<IProcedureManager>();
if (m_ProcedureManager == null)
{
    Log.Fatal("Procedure manager is invalid.");
    return;
}
```

排查方向:

1. 确认场景中存在挂载了 `ProcedureComponent` 的 GameObject,组件菜单路径是 `GameFrameX/Procedure`。
2. 确认 `GameFrameworkEntry` 已正常初始化(其他 `GameFrameworkComponent` 也已挂载并 `Awake`)。
3. 查看是否有其他组件注册过 `IProcedureManager` 实现,造成接口被占用 —— 同一接口只能有一个实现。
4. 处理 IL2CPP / 剥离裁剪时,`[Preserve]` 特性已在管理器类上声明,如果仍然丢失,检查自身的 `link.xml` 是否覆盖 `GameFrameX.Procedure.Runtime`。

### 修复 2:Available procedure type names is empty

`ProcedureComponent.Start` 中的检查:

```csharp
if (m_AvailableProcedureTypeNames == null || m_AvailableProcedureTypeNames.Length <= 0)
{
    Log.Warning("Available procedure type names is empty. Procedure auto start skipped.");
    yield break;
}
```

修复方法:在 Inspector 的 `Available Procedure Type Names` 数组中填入流程类全名(命名空间 + 类名),至少一项。

### 修复 3:Can not find procedure type

对应代码:

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

修复方法:

1. 字符串必须与 `Type.FullName` 完全一致,例如 `GameFrameX.Procedure.Runtime.ProcedureLaunch`。
2. 如果流程类放在自定义程序集,确认该程序集已被加载(构建设置 → Player Settings → 不勾选 "Disable Domain Reload" 时仍要保证代码已编译到工程)。
3. 改名 / 移动命名空间后忘了同步 Inspector 时最容易触发,改完类名一定要回 Inspector 同步字符串。

### 修复 4:Can not create procedure instance

对应代码:

```csharp
procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

修复方法:确保流程类是 `public`、有公共无参构造函数,且不是抽象类或接口。`ProcedureBase` 的标准写法:

```csharp
public sealed class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
    }
}
```

### 修复 5:Entrance procedure is invalid

`Start` 中匹配入口流程:

```csharp
if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

如果循环结束 `m_EntranceProcedure` 仍为 `null`,会输出 `Entrance procedure is invalid.`。修复方法:把 `Entrance Procedure Type Name` 字段填成 `Available Procedure Type Names` 中**完全相同**的某一项。

### 修复 6:You must initialize procedure first

`ProcedureManager` 多个成员在 `m_ProcedureFsm == null` 时抛此异常,例如:

```csharp
public ProcedureBase CurrentProcedure
{
    get
    {
        if (m_ProcedureFsm == null)
        {
            throw new GameFrameworkException("You must initialize procedure first.");
        }
        return (ProcedureBase)m_ProcedureFsm.CurrentState;
    }
}
```

触发条件:`CurrentProcedure` / `CurrentProcedureTime` / `StartProcedure` / `HasProcedure` / `GetProcedure` 中任一项在 `Initialize` 之前被调用。

修复方法:

1. 默认情况下,`ProcedureComponent.Start` 会自动 `Initialize` + `StartProcedure`,你无需手动调用。
2. 若自己持有 `IProcedureManager` 并先行访问,请先调用 `Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)` 再访问其他成员。
3. 启用 `Use Startup Runner` 时,组件 `Start` 不会自动启动流程 —— 这时由 `ApplicationStartupEntry` / `StartupRunner.Run` 负责初始化,确保它确实执行了。

### 修复 7:Procedures is invalid

`ProcedureManager.Initialize` 的前置检查:

```csharp
if (procedures.Length <= 0)
{
    throw new GameFrameworkException("Procedures is invalid.");
}
```

修复方法:不要向 `Initialize` 传空数组,至少传一个 `ProcedureBase` 实例。

### 修复 8:Already exist FSM

当 `Use Startup Runner = true` 时,`ProcedureComponent.Start` 直接退出:

```csharp
if (m_UseStartupRunner)
{
    yield break;
}
```

这条分支的存在就是为了避免与 `ApplicationStartupEntry` + `StartupRunner.Run` 重复 `Initialize` 触发 `Already exist FSM`(同一个 `IProcedureManager` 持有者被反复调用 `CreateFsm`)。

修复方法:二选一,不要混用:

- 旧模式:`Use Startup Runner = false`,依赖 Inspector 数组自动启动。
- 新模式:`Use Startup Runner = true`,由 `ApplicationStartupEntry` 通过 `StartupRunner.Run` 接管启动流程。

## 验证

按上述修复调整后,可通过以下方式确认问题已解决:

1. 重新进入 Play Mode,控制台不再输出对应错误,且 `ProcedureComponent.CurrentProcedure` 不为 `null`。
2. 在首个流程(如 `ProcedureLaunch`)的 `OnEnter` 里打日志,确认日志出现,说明 `StartProcedure` 已真正生效。
3. 在第二个流程里调用 `ChangeState<ProcedureXxx>()`,观察状态切换是否符合预期,验证整个 FSM 已正确初始化。
4. 如果启用了 `Use Startup Runner`,确认 `ApplicationStartupEntry` 中实际调用了 `StartupRunner.Run` 并传入了你的入口流程类型,否则流程永远不会启动(只有 `Awake` 注册了管理器)。
