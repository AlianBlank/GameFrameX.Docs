# 장면에 WebView 컴포넌트를 추가하고 구성하는 방법

Unity 장면에 `WebViewComponent` 컴포넌트를 부착하고 플랫폼 구현을 선택하면, 런타임에 단 한 줄의 코드 `Show(url)`로 WebView 페이지를 띄울 수 있으며, 전체 화면, 숨기기 및 JavaScript 실행을 지원합니다. 이 페이지에서는 컴포넌트 추가부터 실행 검증까지의 전체 단계를 안내합니다.

## 사전 조건

- 프로젝트에 GameFrameX WebView 패키지(`com.gameframex.unity.webview`)가 설치되어 있고, `Runtime/WebViewComponent.cs`가 컴파일에 포함되어 있어야 합니다.
- 장면에 GameFrameX 프레임워크 진입점이 이미 존재해야 합니다(`WebViewComponent`는 `GameFrameworkComponent`를 상속하므로 프레임워크 컴포넌트 체계가 사용 가능해야 함).
- `IWebViewManager`를 구현하는 런타임 구현 클래스가 도입되어 있어야 합니다(이 저장소에는 추상 계층인 `BaseWebViewManager`만 포함되어 있으며, 구체적인 플랫폼 구현은 사용자 측에서 제공해야 함).

## 작업 단계

1. 대상 장면을 열고, 프레임워크 컴포넌트를 담을 GameObject를 선택합니다(일반적으로 다른 GameFrameX 컴포넌트가 부착된 루트 오브젝트).

2. 메뉴를 통해 컴포넌트를 추가합니다: **Add Component → Game Framework → WebView**. 컴포넌트는 다음 어트리뷰트를 통해 해당 메뉴에 등록됩니다:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("Game Framework/WebView")]
[UnityEngine.Scripting.Preserve]
public partial class WebViewComponent : GameFrameworkComponent
```

출처: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L10-L13)

> 동일한 GameObject에는 하나의 `WebViewComponent`만 부착할 수 있습니다(`DisallowMultipleComponent`).

3. Inspector에서 구현 타입을 선택합니다. Inspector는 에디터 스크립트로 제공되며, `IWebViewManager`를 구현하는 모든 타입을 나열합니다:

```csharp
[CustomEditor(typeof(WebViewComponent))]
internal sealed class WebViewComponentInspector : ComponentTypeComponentInspector
{
    protected override void RefreshTypeNames()
    {
        RefreshComponentTypeNames(typeof(IWebViewManager));
    }
}
```

출처: [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L13-L20)

4. 장면을 실행합니다. 컴포넌트는 `Awake`에서 Inspector에 저장된 타입에 따라 구현을 해석하고, `Start`에서 초기화를 완료합니다:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IWebViewManager);
base.Awake();
if (!IsRuntimeComponentReady)
{
    return;
}

_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

출처: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L38)

5. 비즈니스 코드에서 컴포넌트를 가져와 API를 호출합니다. 사용 가능한 전체 인터페이스는 다음과 같습니다(컴포넌트 메서드는 `IWebViewManager`와 일대일로 대응됨):

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| WebView 표시 | `void Show(string url)` | 지정된 url의 페이지를 로드하고 표시 |
| 전체 화면 | `void MakeFullScreen()` | WebView를 전체 화면으로 전환 |
| JavaScript 실행 | `void ExecuteJavaScript(string javaScript)` | 현재 페이지에서 JS 코드 실행 |
| 숨기기 | `void Hide()` | WebView 숨기기 |

출처: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L12-L40)

호출 예시:

```csharp
var webView = GameEntry.GetComponent<WebViewComponent>();
webView.Show("https://example.com");
webView.ExecuteJavaScript("console.log('hello');");
webView.MakeFullScreen();
webView.Hide();
```

> 위 호출 예시는 `WebViewComponent.Show/ExecuteJavaScript/MakeFullScreen/Hide` 공개 API의 표준 사용법 조합이며, 메서드 시그니처는 모두 소스 코드에서 발췌한 것입니다. 컴포넌트를 가져오는 구체적인 방법은 사용자의 GameFrameX 진입점 캡슐화에 따라 다릅니다.

## 일반적인 변형

- **커스텀 플랫폼 구현**: `BaseWebViewManager`를 상속하는 클래스를 생성하고 `Initialize`, `Show`, `MakeFullScreen`, `ExecuteJavaScript`, `Hide` 다섯 개의 추상 메서드를 구현하면 Inspector의 구현 타입 드롭다운 목록에 나타납니다:

```csharp
public abstract partial class BaseWebViewManager : GameFrameworkModule, IWebViewManager
{
    public abstract void Initialize();
    public abstract void Show(string url);
    public abstract void MakeFullScreen();
    public abstract void ExecuteJavaScript(string javaScript);
    public abstract void Hide();
}
```

출처: [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39)

- **코드로 컴포넌트 생성**: 동적으로 부착해야 하는 경우 GameObject에 직접 `AddComponent<WebViewComponent>()`를 호출하면 됩니다. `Awake`에서 즉시 구현 타입을 해석하므로, Inspector에 직렬화된 구현 타입이 구성되어 있는지 확인하십시오. 그렇지 않으면 런타임에 `IsRuntimeComponentReady == false`인 조기 반환 분기로 진입하게 됩니다.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Inspector에서 구현 타입 드롭다운 목록이 비어 있음 | `IWebViewManager`를 구현하는 구체 클래스가 없음(이 저장소는 추상 계층만 제공) | `BaseWebViewManager`를 상속하는 구현 클래스를 작성한 후 새로 고침 |
| 런타임 로그 `Web View manager is invalid.`(`Log.Fatal`) | `GameFrameworkEntry.GetModule<IWebViewManager>()`가 null을 반환함, 모듈이 등록되지 않음 | 구현 클래스를 사용할 수 있고 Inspector에서 타입이 올바르게 선택되었는지 확인 |
| 컴포넌트가 조용히 작동하지 않고 `Show`가 반응하지 않음 | `Awake`에서 `IsRuntimeComponentReady`가 false여서 조기 반환, `_webViewManager`가 null | Inspector에 저장된 구현 타입 문자열이 `Utility.Assembly.GetType`으로 해석 가능한지 확인 |
| 동일한 오브젝트에 두 번째 WebView 컴포넌트를 부착할 수 없음 | 클래스에 `[DisallowMultipleComponent]`가 지정되어 있음 | 장면마다 WebView 컴포넌트를 하나만 부착하면 됨 |

## 검증

- 실행 모드에 진입한 후 `Log.Fatal("Web View manager is invalid.")` 출력이 없으면 모듈 해석에 성공한 것입니다.
- `Show("https://example.com")` 호출 시 페이지가 뜨는지 확인; `MakeFullScreen()`, `Hide()`를 순서대로 호출했을 때 동작이 예상대로인지 확인.

## 배경

`WebViewComponent`는 GameFrameworkComponent 체계에서 퍼사드 역할을 하는 컴포넌트입니다. Inspector는 `IWebViewManager`의 구현 타입을 선택하고 문자열로 직렬화하는 역할만 담당하며, 런타임에는 컴포넌트가 `Awake`에서 리플렉션으로 타입을 해석한 뒤 `GameFrameworkEntry.GetModule<T>()`를 통해 모듈 인스턴스를 가져오고, `Start`에서 `Initialize()`를 호출해 초기화를 완료합니다. 따라서 비즈니스 계층은 컴포넌트의 네 가지 공개 메서드에만 의존하며, 구체적인 플랫폼 구현과 디커플링됩니다.
