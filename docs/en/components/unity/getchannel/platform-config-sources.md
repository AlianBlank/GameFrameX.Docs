# Cross-Platform Channel Configuration Source Reference Table

This page provides a quick reference for where `BlankGetChannel.GetChannelName` reads channel values on each platform, the key name formats, the fallback values when not configured, and the corresponding native implementation entry points.

## Platform-Specific Configuration Examples

**Android** — Declare `meta-data` inside the main launch Activity (this Activity is the Java-side `com.alianhome.getchannel.MainActivity`):

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

**iOS/tvOS/visionOS** — Add a String type key-value pair in Info.plist:

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)

**Editor/PC/WebGL/UWP/Consoles** — Create `application_config.txt` in the `Resources` directory, with one `key=value` entry per line:

```text
channel=editor_cn_test
sub_channel=test
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L28-L33)

## Reading Behavior Highlights

- **Custom key names**: Call `GetChannelName("sub_channel", "unknown")` to read the sub-channel; the Android/iOS side likewise queries `meta-data` or Info.plist using the passed-in `channelKey`.
- **txt parsing rules**: Only lines where `split.Length > 1` are accepted, meaning they must contain `=`; the part before the first `=` is the key and the part after is the value; both are trimmed and written to cache. See [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120) for details.
- **When TextAsset is missing**: `defaultValue` is written to cache and returned directly.
- **iOS native fallback value**: Returns the hardcoded `unknown` when the key is not found in Info.plist, instead of the C#-side `defaultValue`. See [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L31-L35).
- **iOS build fallback**: [PostProcessBuildHandler](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49) checks Info.plist after iOS builds; if the `channel` key does not exist, it automatically writes `default` and logs `配置渠道成功=>default`; if it already exists, it logs `已有渠道,跳过设置=>{value}`.
- **Caching strategy**: On all platforms, the first read result is written to the `ChannelCache` dictionary (initial capacity 32); repeated calls within the same process will not read the native configuration again. See [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L57).
