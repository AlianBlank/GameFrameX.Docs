# 如何以優先順序與並行性控制播放請求

透過 `PlaySoundParams.Priority` 與聲音群組的 `AvoidBeingReplacedBySamePriority` 開關，可以控制同一聲音群組內多個同時播放請求之間的搶佔行為：優先順序數字越大越優先，一旦發生搶佔，就會以新請求取代。

## 前置條件

- 已透過 `GameFrameX.Sound.Runtime` 註冊聲音群組，並在該聲音群組中分配至少一個聲音代理程式(`SoundAgent`)。
- 呼叫方可取得 `ISoundManager` 執行個體(通常透過 `GameEntry.Sound`)。

## 操作步驟

1. 播放前先透過參考池建立參數物件，設定優先順序後，將其傳遞給 `PlaySound` 多載：

```csharp
using GameFrameX.Sound.Runtime;

var p = PlaySoundParams.Create(isLoop: false);
p.Priority = 100; // 數字越大越優先
p.FadeInSeconds = 0.1f;

int serialId = GameEntry.Sound.PlaySound("sfx/click", "SoundEffect", p);
```

來源： [PlaySoundParams.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundParams.cs#L105-L239)

2. 設定聲音群組是否允許相同優先順序之間互相搶佔。預設情況下，只有當新請求的優先順序**嚴格大於**目前正在播放的聲音時，才會被取代；若希望相同優先順序也能被新聲音取代，請開啟該開關：

```csharp
ISoundGroup group = GameEntry.Sound.GetSoundGroup("SoundEffect");
group.AvoidBeingReplacedBySamePriority = false; // 相同優先順序也會被搶佔
```

來源： [ISoundGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Interface/ISoundGroup.cs#L50-L53)

3. 監聽播放失敗事件，以擷取「因優先順序而被忽略」的請求，並用於追蹤或備援邏輯：

```csharp
GameEntry.Sound.PlaySoundFailure += (sender, args) =>
{
    if (args.ErrorCode == PlaySoundErrorCode.IgnoredDueToLowPriority)
    {
        // 目前群組內的代理程式已全部佔用，且優先順序不足以搶佔，因此被丟棄
    }
};
```

來源： [PlaySoundErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundErrorCode.cs#L60-L64)

## 常見變體

- **確保關鍵語音絕不被中斷**：播放台詞/劇情語音時，將 `Priority` 設定為遠高於一般音效的值(例如 1000),並將該群組的 `AvoidBeingReplacedBySamePriority` 保持為 `true`,如此一來，相同優先順序的 BGM 便無法將其擠掉。
- **以同一群組內的多個代理程式實現高並行性**：在 `SoundEffect` 群組中分配多個 `SoundAgent`(例如 8~16 個)，讓大多數短音效能夠平行播放，只有當新請求連代理程式都無法取得時，才會進行優先順序判定。
- **僅設定並行上限**：若不區分優先順序，只想限制同一群組內的同時播放數量，可讓所有請求使用預設優先順序(`Constant.DefaultPriority`),並保持 `AvoidBeingReplacedBySamePriority = true`,如此最早加入的聲音會被新請求擠掉。

## 常見錯誤

- **將優先順序誤認為音量或音高**:`Priority` 是整數型別，僅用於搶佔判定，與 `VolumeInSoundGroup`、`Pitch` 無關。
- **期待相同優先順序也會被取代，卻未變更開關**：預設值為 `AvoidBeingReplacedBySamePriority = true`,新聲音的優先順序必須嚴格高於播放中的聲音才能搶佔，否則會回傳 `IgnoredDueToLowPriority`。
- **忘記歸還參數物件**:`PlaySoundParams` 取自參考池，使用完畢後應立即呼叫 `ReferencePool.Release(p)`,以避免長期持有導致狀態污染。
- **在群組內沒有可用代理程式時觸發播放**：若群組未分配任何代理程式，同樣會播放失敗，因此請先確認 `SoundGroup.SoundAgentCount > 0`。

## 背景(選用)

`ISoundAgent` 與 `ISoundAgentHelper` 都會在每幀將 `Priority` 同步到底層的 `AudioSource`,管理器以「代理程式 + 優先順序」模型判定搶佔；優先順序數值屬於相對概念，業務端只需確保關鍵聲音來源的優先順序高於一般聲音來源即可。
