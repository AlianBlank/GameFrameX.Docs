# UI 레이어/깊이 이상이 발생하면

UI 레이어/깊이 이상은 일반적으로 다음과 같이 나타납니다: 새 UI를 열 때 이전 UI에 가려짐, 동일한 UI 그룹 내 여러 UI가 서로 교차하여 표시됨, 모달 팝업이 하위 레이어를 뚫고 통과함, 3D 씬 오브젝트가 UI 위로 뚫고 나옴. 본 문서는 증상에 따라 진단 및 수정 방법을 안내합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 새로 연 UI가 이전 UI에 가려져 보이지 않음 | 새 UI를 UI 그룹에 추가할 때 그룹 깊이 `Depth`가 변하지 않음, Camera가 `ScreenSpaceCamera` 모드에서 이전 그룹에 의해 가려짐 | 아래 「깊이 값이 적용되지 않음」 참고 |
| 같은 그룹 내 여러 UI가 서로 교차하여 레이어 관계가 뒤섞임 | UGUI는 `localPosition.z = depth * 1000`를 의사 깊이로 사용하는데, 프리팹의 `localPosition.z`를 임의로 수정하여 UI가 어긋남 | 아래 「UI Z 값이 잘못 변경됨」 참고 |
| 3D 씬 오브젝트가 UI 위로 뚫고 표시됨 | UI 카메라의 `clearFlags`와 `cullingMask` 설정 오류, 3D 오브젝트가 UI 레이어로 렌더링됨 | 아래 「3D 오브젝트가 UI를 뚫고 나오는 문제」 참고 |
| 팝업 클릭 이벤트가 하위 UI로 뚫고 통과함 | 루트 `Canvas`의 `overrideSorting`/`sortingOrder`와 `GraphicRaycaster`가 손상됨 | 아래 「레이가 하위 레이어를 뚫고 통과함」 참고 |
| 첫 UI를 연 후, `UGUI runtime root is invalid.` 오류 발생 | `UI` 레이어가 존재하지 않아 `LayerMask.NameToLayer("UI")`가 `-1`을 반환 | 아래 「UI 레이어 누락」 참고 |

## 수정 단계

### 깊이 값이 적용되지 않음

`UGUIUIGroupHelper.SetDepth`는 레이어 적용의 유일한 진입점이며, 시그니처는 다음과 같습니다:

```csharp
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

Source: [UGUIUIGroupHelper.cs#L66-L70](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

확인 포인트:

1. UI가 `UIComponent.AddUIGroup` 호출 후 프레임워크가 `SetDepth`를 호출하는지 확인하고, 비즈니스 레이어에서 수동으로 `localPosition.z`를 설정하지 않아야 합니다. 비즈니스 레이어가 `localPosition.z`를 다시 `0`으로 되돌리면 레이어가 원래대로 돌아갑니다.
2. 루트 `Canvas`가 `ScreenSpaceCamera` 모드인지 확인하고, 루트 카메라의 `depth`가 씬 내 다른 카메라의 `depth`보다 작지 않아야 합니다(프레임워크 기본값 `uiCamera.depth = 10f`).

### UI Z 값이 잘못 변경됨

UI를 UI 그룹 노드에 마운트한 후, 해당 노드의 `localPosition.z`는 프레임워크에 의해 `depth * 1000`으로 강제로 기록됩니다. 프리팹에서 설정한 모든 `localPosition.z`는 런타임에 덮어쓰여집니다. 반대로 비즈니스 레이어가 `OnOpen`/`OnShow`에서 이 값을 다시 `0`으로 쓰면 "가끔 맞고 가끔 틀리는" 깜빡임 현상이 발생합니다.

올바른 방법: UI 스크립트에서 `transform.localPosition.z`를 건드리지 마시고, "레이어 내 추가 분류"가 필요할 때는 자식 노드 또는 새 UI 그룹을 사용하고, Z 값을 변경하지 마십시오.

### 3D 오브젝트가 UI를 뚫고 나오는 문제

UI 카메라는 프레임워크 초기화 시 다음과 같이 구성됩니다:

```csharp
uiCamera.clearFlags = CameraClearFlags.Depth;
uiCamera.cullingMask = uiLayer >= 0 ? 1 << uiLayer : uiCamera.cullingMask;
```

Source: [UGUIUIGroupHelper.cs#L159-L165](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L159-L165)

씬 내 3D 오브젝트가 UI 위로 나타나는 경우, 일반적으로 다음 원인입니다:

- 3D 오브젝트가 있는 레이어가 UI 레이어와 이름이 같거나 충돌하여 잘못 `cullingMask`에 포함됨.
- 3D 카메라의 `depth`가 UI 카메라의 `depth`(기본값 `10f`)보다 커서, 3D 오브젝트가 나중에 그려지지만 `clearFlags.Depth`로 깊이가 지워지지 않아 "중첩"됨.

처리 방법: 3D 오브젝트를 독립된 레이어(예: `Default`)에 두고 `UI` 레이어를 재사용하지 마십시오.

### 레이가 하위 레이어를 뚫고 통과함

`EnsureCanvas`에서 다음이 명시적으로 활성화됩니다:

```csharp
canvas.overrideSorting = true;
canvas.sortingOrder = 0;
canvasObject.GetOrAddComponent<GraphicRaycaster>();
```

Source: [UGUIUIGroupHelper.cs#L199-L212](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L199-L212)

Inspector에서 `GraphicRaycaster`를 수동으로 삭제하거나 `overrideSorting`을 끄면 "보이는데 클릭되지 않음" 또는 "하위 레이어를 클릭함" 현상이 발생합니다. 루트 Canvas는 읽기 전용으로 취급하고, 레이어 문제는 새 UI 그룹 또는 자식 Canvas를 만들어 해결하는 것을 권장합니다.

### UI 레이어 누락

`UGUIUIGroupHelper`는 전 과정에서 `LayerMask.NameToLayer("UI")`에 의존하며, 프로젝트에 `UI`라는 Tag/Layer가 없으면 관련 `Log.Error`가 모두 트리거되고 레이어 및 마스크 관계가 모두 무효화됩니다.

수정: `Edit ▸ Project Settings ▸ Tags and Layers`에서 `UI` 레이어(5번째 레이어 권장)를 추가하고 이름을 `UI`로 유지하십시오.

### 형제 인덱스가 변경됨

UI 그룹 내 여러 UI는 Hierarchy에서 형제 노드 형태로 존재하며, 나중에 연 것이 위쪽에 표시됩니다. 호출 측이 `transform.SetSiblingIndex`, `SetAsLastSibling` 등의 메서드로 특정 팝업을 "뒤로 밀어 넣으면" 레이어 깜빡임이 발생합니다.

권장 사항: UI 레이어는 `Depth`(UI 그룹)로만 제어하고, UI 스크립트에서 형제 인덱스를 변경하지 마십시오.

## 검증

수정 후 다음 순서로 검증합니다:

1. 서로 다른 UI 그룹 3개에 속한 UI를 연속으로 열어, 나중에 연 것이 먼저 연 것 위에 표시되어야 합니다.
2. 같은 그룹 내 UI 2개를 열어, 나중에 연 것이 위쪽에 있고 서로 뚫고 나오지 않아야 합니다.
3. 전체 화면 모달 팝업을 열어, 팝업 외 빈 곳을 클릭해도 하위 버튼이 트리거되지 않아야 합니다.
4. Hierarchy에서 루트 `UGUICanvas`를 선택하여 자식 노드의 `localPosition.z`가 차례로 `0`, `1000`, `2000`인지 확인합니다.
5. Scene 뷰에서 UI 카메라로 전환하여 `cullingMask`에 `UI` 레이어만 체크되어 있는지 확인합니다.
