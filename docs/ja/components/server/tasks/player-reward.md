# プレイヤー報酬(Reward)モジュールの実装

このページでは、プレイヤー Actor 上で `RewardGrantComponentAgent.GrantAsync` を使用して報酬を一括支給する方法を説明します。呼び出しの前提条件、リクエスト/レスポンスの構造、ルーティングルール、冪等性台帳の動作について解説します。

## 前提条件

- 対象のプレイヤー Actor がオンラインであり、`RewardGrantComponent` がフレームワークによって `[ComponentType(GlobalConst.ActorTypePlayer)]` で自動的にアタッチされるため、手動登録は不要です。
- `TbItemConfig` アイテムテーブル設定(`GameFrameX.Config.Tables`)が存在すること。通常アイテムのルーティングでは `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)` を使用して `ItemId` の存在を検証します。
- 呼び出し元がプレイヤー Actor を解決できるサーバー側のコンテキスト(例: ホットアップデート層 `GameFrameX.Hotfix.Logic.Player.Reward` 名前空間下のコード)にあること。
- `BagComponentAgent` が準備完了していること。通常アイテムの支給は最終的に `BagComponentAgent.UpdateChanged(...)` を呼び出してバッグに書き込みます(オンライン時は push notify、オフライン時は永続化のみ)。

## 操作手順

1. **`RewardGrantRequest` を構築する。** `RoleId` は対象プレイヤーの `ActorId` である必要があります。`SourceType` / `SourceId` / `TraceId` の 3 つで一意に識別され、`RoleId:SourceType:SourceId:TraceId` という冪等キーを構成します。`Rewards` は支給するエントリのリストです。

   ```csharp
   using GameFrameX.Apps.Player.Reward.Entity;

   var request = new RewardGrantRequest
   {
       RoleId    = playerActorId,
       SourceType = RewardSourceType.Mail,            // ビジネスソース、None は禁止
       SourceId  = $"mail:{mailId}:attachment:{attachmentId}",
       TraceId   = Guid.NewGuid().ToString("N"),      // 一意な追跡番号
       Rewards   = new List<RewardItem>
       {
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1001, Count = 5 },
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1002, Count = 1 },
       },
   };
   ```
   Source: [RewardGrantRequest.cs#L41-L67](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L41-L67)

2. **コンポーネントエージェントを介して `GrantAsync` を呼び出す。** エントリーポイントは `RewardGrantComponentAgent.GrantAsync` で、`[Service]` が付与されているため、同じ Actor 内の他のエージェントコンポーネントや上位ビジネスから直接 await できます。

   ```csharp
   using GameFrameX.Hotfix.Logic.Player.Reward;

   var agent = await ActorManager.GetComponentAgent<RewardGrantComponentAgent>(playerActorId);
   var result = await agent.GrantAsync(request);
   ```
   Source: [RewardGrantComponentAgent.cs#L51-L91](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L51-L91)

3. **`RewardGrantResult` を読み取る。** `Items` は各項目の成功/失敗とエラーコードを示します。`AllSuccess` は全て成功したかどうかを示します。`ErrorCode` は全体集約コード(`Ok` / `PartialSuccess` / 最初の失敗項目のエラーコード)です。

   ```csharp
   if (result.AllSuccess)
   {
       // 全ての報酬がバッグに書き込まれたか、冪等ヒット
   }
   else
   {
       foreach (var item in result.Items)
       {
           if (!item.Success)
           {
               // item.ErrorCode の取りうる値は OperationStatusCode を参照
           }
       }
   }
   ```
   Source: [RewardGrantRequest.cs#L72-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L72-L89)

4. **必要に応じてルーティングを拡張する。** 第一期では `RewardType.NormalItem` のみが実際に実装され(`BagState` に書き込み)、その他のタイプ(HiddenItem / MonthCard / LifetimeCard / VipPoint / Equity など)は `DispatchAsync` 内で `OperationStatusCode.Unsupported` を返すため、通常バッグを汚染しません。新しいタイプを追加する場合は、`DispatchAsync` の `switch` 分岐に対応するサブルーティング実装を追加してください。
   Source: [RewardGrantComponentAgent.cs#L96-L172](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L96-L172)

## よくあるバリエーション

- **運営補填 / 引き換えコード / イベント報酬:** ビジネスソースが異なる場合は、`SourceType` と `SourceId` の連結方法を変更するだけで済みます。`GrantAsync` が唯一の資産支給エントリーポイントであるため、これを迂回してバッグに直接書き込まないでください。
- **オフラインプレイヤーへの報酬支給:** `BagComponentAgent.UpdateChanged(channel, ...)` は `channel` が空の場合、永続化のみを行い notify をプッシュしないため、ビジネス側で追加の分岐は不要です。
- **リクエストに拡張フィールドを含める:** `RewardItem.ExtraData` は予約フィールドであり、現在の支給フローでは解析されませんが、冪等台帳にそのまま永続化されるため、後続のルーティングで読み取ることができます。

## よくあるエラー

| 症状 | 原因 | 回避策 |
|------|------|--------|
| リクエスト全体の `ErrorCode = Unsupported` | `RewardType` が実装済みルーティングにない(`NormalItem` 以外は未対応) | 第一期は通常アイテムのみ支給。拡張前に `DispatchAsync` にルーティングを追加する |
| 単一項目の `ErrorCode = InvalidReward` | `RewardItem.Count <= 0` | 呼び出し前に `Count > 0` を検証する |
| 単一項目の `ErrorCode = NotFound` | `ItemId` が `TbItemConfig` に存在しない | 先に設定テーブルを作成し、その後にプランナーがテーブルを埋める |
| リクエスト全体の `ErrorCode = Unprocessable` | バッグコンポーネントの更新失敗(`bagState.IsNull()`) | `BagComponentAgent` とプレイヤー Actor の状態を確認する |
| 報酬の重複支給 | 冪等キー `RoleId:SourceType:SourceId:TraceId` が一意でない | 同一ビジネスでは 3 つのフィールドを安定させ、再試行が必要な場合は `TraceId` をそのまま再利用する |
