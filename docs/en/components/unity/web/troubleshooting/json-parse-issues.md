# What to Do When JSON Parsing Results Are Incorrect

When the JSON string returned by `WebManager` produces `IsSuccess == false`, `Data == null`, `Code` always being 0, or missing fields after being parsed by `ToHttpJsonResultData<T>()`, it is usually caused by the response structure not conforming to the `{"code":0,"message":"...","data":"..."}` convention, `data` being a nested object, or `T` lacking a parameterless constructor / having mismatched field names. Follow the diagnostic table below item by item to locate the issue.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `IsSuccess == false` and `Code` is a non-zero value | Server returned a business error code; `data` was not parsed (source code returns a failure result directly when `Code != 0`) | Check the logs for `message` and handle it as a business error; see "Non-zero Code" below |
| `IsSuccess == false`, `Code == 0`, `Data == null` | An exception was thrown during parsing and swallowed by `catch`, only outputting `Log.Error(e)` and returning the default failure result | Check the exception stack trace output by `Log.Error` in the Console; verify the JSON structure matches `T` |
| `Data` is a `new T()` instance with all default values | The server returned an empty string for `data`; the source code directly returns `new T()` when `data` is empty | Confirm whether the API actually returns empty `data`; if unexpected, check the raw response |
| All fields in `Data` are default values, but no error is reported | `data` is an object but failed to be processed as a `string`, or `T`'s property names don't match the JSON field names | Add `[JsonProperty("字段名")]` to `T`'s properties; see fix steps below |
| No raw response visible in the logs at all | The macro `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` is not defined | Add `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` in Player Settings / script macros and recompile |
| Deserialization directly throws a `JsonMapper` exception | Field type errors in `T` under the `class, new()` constraint scenario (e.g., date formats, nested dictionaries) | Simplify `T` to a minimal reproducible model and add fields back one by one to troubleshoot |

## Fix Steps

### 1. First enable response logging to get the raw JSON

`WebManager` logs the raw content when receiving a response, but a macro switch is required:

- Request logging: `ENABLE_GAMEFRAMEX_WEB_SEND_LOG`
- Response logging: `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`

The response logging implementation in the source code (`unityWebRequest.downloadHandler.text` is the raw response body):

```csharp
#if ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
                    Log.Debug($"Web Response: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)} \n Content: {unityWebRequest.downloadHandler.text}");
#endif
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L248-L250)

After obtaining the raw JSON, compare it with the unified response structure. This step resolves most "incorrect parsing" issues.

### 2. Confirm the response conforms to the unified structure `{"code", "message", "data"}`

The parser strongly depends on these three field names, bound via `JsonProperty`:

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class HttpJsonResult
{
    /// <summary>
    /// Response code; 0 indicates success
    /// </summary>
    [JsonProperty("code")]
    public int Code { get; set; }

    /// <summary>
    /// Response message
    /// </summary>
    [JsonProperty("message")]
    public string Message { get; set; }

    /// <summary>
    /// Response data.
    /// </summary>
    [JsonProperty("data")]
    public string Data { get; set; }
}
```

Source: [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L8-L27)

Verification points:

| Verification Item | Expected | Behavior When Non-conforming |
|--------|------|--------------|
| Field names | Must be `code` / `message` / `data` | Fields missing or always default values |
| `code` | 0 indicates success | When non-zero, `IsSuccess` is always `false` |
| `data` | Expected to be a string (string form of nested JSON) | If it's a direct object literal, `Data` may fail to parse |

If the server returns different top-level field names (e.g., `status`/`msg`/`result`), you need to either have the server return according to this convention first, or deserialize into a custom structure yourself; you cannot use `ToHttpJsonResultData<T>()` directly.

### 3. Make `T` satisfy the constraints and map fields correctly

The extension method signature and internal parsing logic of `ToHttpJsonResultData<T>`:

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // Deserialize the JSON string into an HttpJsonResult object
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // Check whether the response code indicates success
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // Return the default failure result
        }

        resultData.IsSuccess = true; // Set the success flag
        // Deserialize the data part; if the data is empty, return the default instance of type T
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // Catch and output exception information
        Log.Error(e);
    }

    return resultData; // Return the result data
}
```

Source: [HttpJsonResultHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultHelper.cs#L20-L48)

Checklist when troubleshooting `T`:

1. `T` must be a `class` with a parameterless constructor (`where T : class, new()`); structs and abstract classes won't work.
2. `T`'s property names must match the JSON field names inside `data`; when they don't match, add `[JsonProperty("字段名")]` (`GameFrameX.LitJSON.Runtime.JsonProperty` provided by LitJSON).
3. When `data` is an empty string, what you get is `new T()`; don't mistake "all default values" for a parsing failure—this is actually the intended behavior of the source code.
4. After a parsing exception is caught, only `Log.Error(e)` is called; `IsSuccess` stays `false` and `Code` stays 0. When you see this combination, check the Console's exception logs first.

### 4. Handle non-zero `Code` as a business error

The meanings of the fields `HttpJsonResultData<T>` returns to callers:

| Field | Type | Description |
|------|------|------|
| `IsSuccess` | `bool` | Whether successful, defaults to `false` |
| `Code` | `int` | Response code; 0 indicates success, non-zero indicates a server business error code |
| `Data` | `T` | The deserialized data when successful; default value or `null` when failed |

Source: [HttpJsonResultData.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultData.cs#L8-L28)

If `Code` is non-zero, it means the server returned a business error and `Data` will not be parsed; you need to show the corresponding prompt or retry based on `Code` and `message` (which can be viewed from the raw response logs).

## Verification

1. Define the `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` macro and re-initiate the request, confirming that the raw response in the logs conforms to the `{"code":0,"message":"...","data":"..."}` structure.
2. Call `.ToHttpJsonResultData<T>()` on the raw response and assert `IsSuccess == true`.
3. Check each field of `Data`'s property values against the `data` field contents (including nested objects).
4. When both request/response macros are enabled, `WebManager` will output the complete request headers and forms, which can further rule out the possibility of "incorrect request parameters causing the server to return an incorrect structure".
