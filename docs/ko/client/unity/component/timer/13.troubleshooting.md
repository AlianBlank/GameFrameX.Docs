# 자주 묻는 질문

이 문서는 Timer 타이머 컴포넌트 사용 시 발생할 수 있는 자주 묻는 질문과 해결 방법을 요약합니다.

## 개요

Timer 컴포넌트는 GameFrameX 프레임워크가 제공하는 타이머 기능 모듈로, Unity 프로젝트에 타이머 작업, 지연 실행 및 프레임 업데이트等功能을 제공합니다. 사용 과정에서 사용자가一些问题에 직면할 수 있으며, 이 문서는 상세한 진단 및 해결 방법을 제공합니다.

## 자주 묻는 질문 및 해결 방법

### 1. 타이머가 실행되지 않음

#### 증상
타이머 작업을 추가한 후 콜백 함수가 한 번도 실행되지 않음.

#### 가능 원인
- Timer 컴포넌트가 Scene의 GameObject에 올바르게 추가되지 않음
- GameFramework 프레임워크가 올바르게 초기화되지 않음
- TimerManager 모듈이 등록되지 않음

#### 해결 방법

**컴포넌트 추가 여부 확인:**

```csharp
// Scene에 TimerComponent가 있는지 확인
var timerComponent = FindObjectOfType<TimerComponent>();
if (timerComponent == null)
{
    Debug.LogError("TimerComponent를 찾을 수 없습니다. 먼저 컴포넌트를 추가하세요");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

**프레임워크 초기화 확인:**
GameFramework 프레임워크가 게임 시작 시 올바르게 초기화되었는지 확인합니다. TimerComponent는 Awake에서 GameFrameworkEntry에서 ITimerManager 인스턴스를 가져옵니다:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("타이머 관리자가 유효하지 않습니다.");  // 타이머 관리자가 유효하지 않음
        return;
    }
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

### 2. 콜백 함수 매개변수 전달 문제

#### 증상
콜백 함수에 전달된 매개변수가 null이거나 매개변수를 올바르게 가져올 수 없음.

#### 가능 원인
- callbackParam 매개변수를 올바르게 전달하지 않음
- AddOnce의 단일 매개변수 오버로드를 잘못 사용함

#### 해결 방법

Timer 컴포넌트의 콜백 함수 시그니처는 `Action<object>`이며, 매개변수는 callbackParam을 통해 전달됩니다:

```csharp
// 매개변수를 올바르게 전달하는 방식
timerComponent.Add(1.0f, 1, OnTimerComplete, "전달할 데이터");

// 콜백 함수에서 매개변수 수신
private void OnTimerComplete(object param)
{
    Debug.Log($"타이머 완료, 매개변수: {param}");  // 출력: 타이머 완료, 매개변수: 전달할 데이터
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

### 3. 간격 시간 단위 혼동

#### 증상
타이머 실행 간격이 예상과 다름. 예: 1000밀리초로 설정했는데 매초 여러 번 실행됨.

#### 가능 원인
**중요: Timer 컴포넌트의 interval 매개변수 단위는 초(seconds)이며, 밀리초가 아닙니다!**

README 문서에 잘못된 설명이 있을 수 있으며, 실제 코드에서 interval은 초 단위 부동소수점입니다:

```csharp
// interval 매개변수 단위는 초 (seconds)
public void Add(float interval, int repeat, Action<object> callback, object callbackParam = null)
{
    _timerManager.Add(interval, repeat, callback, callbackParam);
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

#### 해결 방법

```csharp
// ❌ 오류: 1000을 밀리초로 이해
timerComponent.Add(1000f, 1, callback);  // 실제로는 1000초 간격으로 실행됨

// ✅ 올바름: interval을 초로 이해
timerComponent.Add(1.0f, 1, callback);  // 1초 후 한 번 실행
timerComponent.Add(0.5f, 5, callback); // 0.5초마다 실행, 총 5회

// 밀리초를 올바르게 변환하는 작성법
float intervalInSeconds = 1000f / 1000f;  // 1000밀리초 = 1초
timerComponent.AddOnce(intervalInSeconds, callback);
```

### 4. 타이머 작업 중복 추가

#### 증상
동일 콜백 함수로 Add 메서드를 여러 번 호출한 후 타이머 동작이 비정상임.

#### 가능 원인
TimerManager는 콜백 함수를 딕셔너리 키로 사용합니다. 동일한 콜백의 타이머를 추가하면 새 타이머가 아닌 기존 타이머가 업데이트됩니다:

```csharp
// 코드 구현: 콜백이 이미 존재하면 기존 타이머 업데이트
if (_items.TryGetValue(callback, out var t))
{
    t.Set(interval, repeat, callback, callbackParam);
    t.Elapsed = 0;
    t.Deleted = false;
    return;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L173)

#### 해결 방법

새 타이머를 추가하기 전 이미 존재하는지 확인:

```csharp
// 타이머가 이미 존재하는지 확인
if (!timerComponent.Exists(MyCallback))
{
    timerComponent.Add(1.0f, 5, MyCallback);
}
else
{
    Debug.LogWarning("타이머가 이미 존재합니다. 먼저 제거 후 추가하세요");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 5. 콜백 함수 예외로 타이머 크래시 발생

#### 증상
타이머 콜백에서 예외가 발생하면 전체 타이머 시스템이 중지됨.

#### 가능 원인
기본적으로 콜백 함수의 예외가 타이머 실행을 중단시킵니다.

#### 해결 방법

TimerManager는 `CatchCallbackExceptions` 정적 속성을 통해 예외 처리 동작을 제어합니다:

```csharp
// 예외 포획 활성화, 콜백 예외로 인한 타이머 크래시 방지
TimerManager.CatchCallbackExceptions = true;

// 타이머 작업 추가
timerComponent.Add(1.0f, 0, OnTimerTick);

// 콜백 함수에서 예외가 발생해도 타이머가 종료되지 않음
private void OnTimerTick(object param)
{
    // 예외가 발생할 수 있는 코드
    throw new Exception("시뮬레이션 예외");
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L41-L43)

예외 포획을 활성화하면 예외가 포획되어 경고 로그에 기록되고 해당 타이머가 삭제 표시됩니다:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        timerItem.Callback(timerItem.Param);
    }
    catch (Exception e)
    {
        timerItem.Deleted = true;
        Debug.LogWarning("Timer: timer(internal=" + timerItem.Interval + ", repeat=" + timerItem.Repeat + ") callback error > " + e.Message);
    }
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L86-L97)

### 6. 타이머 메모리 누수

#### 증상
장시간 실행 후 메모리 점유율이 지속적으로 증가함.

#### 가능 원인
- 타이머 작업 완료 후 올바르게 제거되지 않음
- AddUpdate로 추가된 프레임 업데이트 작업이 수동으로 제거되지 않음

#### 해결 방법

**반복 횟수가 제한된 타이머의 경우:**
Repeat = 0은 무한 반복을 의미하고, Repeat > 0은 지정 횟수 실행 후 자동 제거됩니다:

```csharp
// ✅ Repeat = 0은 무한 반복, 수동으로 제거 필요
timerComponent.Add(1.0f, 0, repeatingCallback);

// 적절한 때에 수동 제거
timerComponent.Remove(repeatingCallback);

// ✅ Repeat > 0은 지정 횟수 실행 후 자동 제거
timerComponent.Add(1.0f, 5, limitedCallback);  // 5회 실행 후 자동 제거
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L73-L81)

**프레임 업데이트 작업(AddUpdate)의 경우:**
AddUpdate는 본질적으로 극단적으로 짧은 간격(0.001초)의 반복 타이머를 사용하며, 반드시 수동으로 제거해야 합니다:

```csharp
// 프레임 업데이트 작업 추가
timerComponent.AddUpdate(OnUpdate);

// 객체 파괴 또는 필요 없을 때 제거
timerComponent.Remove(OnUpdate);
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L206-L219)

### 7. 타이머 정밀도 문제

#### 증상
타이머 실행 시간이 정밀하지 않아 큰 오차가 존재함.

#### 가능 원인
- 너무 작은 간격 시간 사용
- 게임 프레임률이 불안정함
- 백그라운드로 전환할 때 Unity의 시간 시스템이 변경됨

#### 해결 방법

TimerManager는 `realElapseSeconds`(실제 경과 시간)를 사용하여 타이머를 계산합니다:

```csharp
// 내부적으로 realElapseSeconds를 사용하여 경과 시간 계산
timerItem.Elapsed += realElapseSeconds;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L63-L71)

**최적화 제안:**

```csharp
// ❌ 너무 작은 간격 사용 피하기
timerComponent.Add(0.0001f, 0, callback);  // 성능 문제 발생 가능

// ✅ 권장: 최소 간격 0.01초 (10밀리초) 이상
timerComponent.Add(0.01f, 0, callback);

// 더 높은 정밀도가 필요한 시나리오에서는 Unity의 Update 또는 Coroutine 사용 고려
```

### 8. 코루틴에서 타이머 사용

#### 증상
코루틴에서 생성한 타이머 동작이 비정상임.

#### 해결 방법

Timer 컴포넌트는 코루틴에서 사용할 수 있지만 생명 주기 관리에 주의해야 합니다:

```csharp
IEnumerator StartTimerInCoroutine()
{
    // 코루틴에서 타이머 사용
    timerComponent.AddOnce(2.0f, OnDelayComplete, "코루틴 데이터");
    
    yield return new WaitForSeconds(2.0f);
    // 코루틴 종료되지만 타이머 작업은 계속 실행 중일 수 있음
}

private void OnDelayComplete(object param)
{
    Debug.Log($"지연 완료: {param}");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L48-L51)

## 진단 도구

### 타이머 상태 확인

Exists 메서드를 사용하여 타이머가 존재하는지 확인합니다:

```csharp
// 특정 콜백의 타이머가 존재하는지 확인
bool isRunning = timerComponent.Exists(MyCallback);

if (isRunning)
{
    Debug.Log("타이머가 실행 중입니다");
}
else
{
    Debug.Log("타이머가 실행 중이 아니거나 완료됨");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 모든 활성 타이머 나열

TimerManager가 딕셔너리를 사용하여 타이머를 저장하므로 확장 기능을 통해 활성 타이머 목록을 가져올 수 있습니다:

```csharp
// 참고: TimerManager의 _items 필드는 비공개입니다
// 디버깅이 필요한 경우 로그 출력 활성화
Debug.Log($"현재 활성 타이머 수: {활성 수}");
```

## 성능 주의 사항

### 1. 콜백 함수 위임 생성

타이머를 추가할 때마다 익명 Lambda 식을 콜백으로 사용하지 마세요. 새 위임 인스턴스가 생성되어 타이머를 올바르게 제거할 수 없습니다:

```csharp
// ❌ 오류: 익명 메서드는 제거할 수 없음
timerComponent.Add(1.0f, 1, (param) => Debug.Log("test"));

// ✅ 올바름: 명명된 메서드 사용
timerComponent.Add(1.0f, 1, OnTimerTick);

// 나중에 올바르게 제거할 수 있음
timerComponent.Remove(OnTimerTick);

private void OnTimerTick(object param)
{
    Debug.Log("Timer tick");
}
```

### 2. 다수의 타이머

TimerManager는 딕셔너리와 잠금을 사용하여 구현되어 수천 개의 동시 타이머가 있으면 성능에 영향을 줄 수 있습니다. 여러 타이머 작업을 병합하거나 다른方式来管理을 고려하세요.
