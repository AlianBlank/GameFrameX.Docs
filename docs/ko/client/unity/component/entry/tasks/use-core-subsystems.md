# 이벤트, 프로시저, 상태 머신, 타이머 등 핵심 하위 시스템 사용 방법

`GameFrameX`는 `GameApp` 정적 파사드를 통해 4대 런타임 하위 시스템——이벤트(Event), 프로시저(Procedure), 상태 머신(Fsm), 타이머(Timer)——을 노출하며, 각각은 하나의 `*Component`로 구동되고, 기능 매크로(`ENABLE_GAME_FRAME_X_*`)에 따라 활성화 범위가 조정되며, `GameEntry.GetComponent<>()`를 통해 통일되게 지연 로딩됩니다.

## 사전 조건

- Package Manager를 통해 `com.gameframex.unity.entry`를 가져왔고, 필요에 따라 `HybridCLR/GameFrameX Settings`에서 **Event / Procedure / Fsm / Timer** 하위 모듈을 체크하여 활성화해야 합니다(해당하는 `ENABLE_GAME_FRAME_X_EVENT` 등의 매크로가 자동 생성됨).
- `GameApp.*.cs`에서 각 하위 시스템은 `#if ENABLE_GAME_FRAME_X_*` 내부에 감싸져 있으며, 매크로가 활성화되지 않으면 `GameApp.Event / Procedure / Fsm / Timer` 속성이 컴파일되지 않으므로 참조하기 전에 반드시 확인하십시오.

## 통일된 접근 방식

모든 하위 시스템은 `GameApp` 정적 클래스를 통해 컴포넌트를 가져오며, 처음 접근할 때 내부 `_xxx` 캐시 필드에 의해 지연 생성됩니다:

```csharp
using GameFrameX.Runtime;

var evt    = GameApp.Event;     // EventComponent
var proc   = GameApp.Procedure; // ProcedureComponent
var fsm    = GameApp.Fsm;       // FsmComponent
var timer  = GameApp.Timer;     // TimerComponent
```

> 활성화 매크로가 꺼져 있으면 해당 속성 접근 시 "컴포넌트를 찾을 수 없음" 또는 컴파일 오류가 발생하므로, 먼저 프로젝트 설정에서 해당 기능을 활성화하십시오.

## 작업 단계

### 1. 이벤트 하위 시스템 사용

이벤트 컴포넌트는 전역 이벤트의 구독과 브로드캐스트를 담당하며, 타입은 `GameFrameX.Event.Runtime.EventComponent`에 위치합니다.

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;

// 구독
GameApp.Event.Subscribe<TestEvent>(OnTestEvent);

void OnTestEvent(object sender, TestEvent e)
{
    // 이벤트 처리
}

// 트리거
GameApp.Event.Fire(sender, new TestEvent { /* 필드 */ });

// 구독 해제
GameApp.Event.Unsubscribe<TestEvent>(OnTestEvent);
```

### 2. 프로시저 하위 시스템 사용

프로시저 컴포넌트는 `ProcedureBase` 파생 클래스 간의 전환을 구동하며, 타입은 `GameFrameX.Procedure.Runtime.ProcedureComponent`에 위치합니다.

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

// 첫 번째 프로시저 진입(보통 게임 시작 완료 후)
GameApp.Procedure.StartProcedure<LaunchProcedure>();

// 런타임 전환
GameApp.Procedure.StartProcedure<LoginProcedure>();

// 현재 프로시저 판별
if (GameApp.Procedure.CurrentProcedure is LoginProcedure) { /* ... */ }
```

각 프로시저 클래스는 `ProcedureBase`를 상속하고, `OnEnter` / `OnUpdate` / `OnLeave` 라이프사이클을 구현해야 합니다.

### 3. 상태 머신 하위 시스템 사용

상태 머신 컴포넌트는 여러 개의 `Fsm<T>`를 관리하며, 타입은 `GameFrameX.Fsm.Runtime.FsmComponent`에 위치합니다.

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Runtime;

// 상태 머신 생성 및 시작
var fsm = GameApp.Fsm.Create("PlayerFsm", owner, new IdleState(), new RunState(), new AttackState());
GameApp.Fsm.StartFsm("PlayerFsm");

// 상태 전환
fsm.ChangeState<RunState>();
```

상태 클래스는 `FsmState<T>`를 상속하고, `OnEnter` / `OnUpdate` / `OnLeave`를 재정의해야 합니다.

### 4. 타이머 하위 시스템 사용

타이머 컴포넌트는 일회성, 반복, 프레임 카운트 등 다양한 작업을 지원하며, 타입은 `GameFrameX.Timer.Runtime.TimerComponent`에 위치합니다.

```csharp
using GameFrameX.Timer.Runtime;
using GameFrameX.Runtime;

// 일회성 타이머 시작
int id = GameApp.Timer.AddOnce(5f, () => { /* 5초 후 실행 */ });

// 반복 타이머 시작
int loopId = GameApp.Timer.AddRepeating(1f, () => { /* 매초 실행 */ });

// 취소
GameApp.Timer.Remove(loopId);
```

## 일반적인 변형

- **프로시저 간 데이터 공유**: 데이터를 `ProcedureBase`의 파생 필드에 붙여, `GameApp.Procedure.CurrentProcedure`와 함께 전환하며 접근합니다.
- **이벤트 + 상태 머신**: 상태의 `OnEnter`에서 `GameApp.Event.Subscribe`를 하고, `OnLeave`에서 `Unsubscribe`를 하여, 상태를 벗어난 후에도 응답하는 것을 방지합니다.
- **타이머 정밀도**: 초 단위 외에도 `TimerComponent`는 프레임 카운트 버전(프레임 기반 구동)을 제공하며, 시간 스케일에 의존하지 않는 로직에 적합합니다.

## 일반적인 오류

- **기능 매크로를 활성화하지 않고 접근**: 컴파일 시에는 오류가 없지만 런타임에 "컴포넌트가 등록되지 않음" 오류가 발생합니다. 해결 방법: 프로젝트 설정에서 해당 하위 시스템 매크로를 체크하십시오.
- **이벤트 구독 해제 누락으로 인한 메모리 누수**: 객체가 파괴되기 전에 반드시 `Unsubscribe`해야 하며, 특히 `MonoBehaviour`가 콜백을 보유할 때 주의해야 합니다.
- **프로시저/상태 머신이 기본 클래스 메서드를 구현하지 않음**: `ProcedureBase` / `FsmState<T>`를 상속한 후 `OnEnter`를 누락하면 전환 시 아무런 동작 없이 조용히 넘어가는 문제가 발생합니다.
