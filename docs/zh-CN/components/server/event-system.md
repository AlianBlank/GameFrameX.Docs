# 如何使用事件系统进行模块解耦

通过事件系统,模块之间不需要直接相互引用,只需定义事件、发布事件、由独立的监听器处理事件,即可实现松耦合。本页介绍如何定义事件、编写监听器以及分发事件。

## 前置条件

- 了解 C# 泛型与异步编程(`async`/`await`)。
- 项目已引用 `GameFrameX.Core.Abstractions.Events` 与 `GameFrameX.Core.Events`。
- 已了解 Actor 与组件代理的基本概念(见 Actor 模块文档)。

## 核心概念速查

| 名称 | 所在类型 | 作用 |
|------|----------|------|
| `GameEventArgs` | `GameFrameX.Core.Abstractions.Events.GameEventArgs` | 事件参数基类,所有自定义事件参数都需继承它 |
| `IEventListener` | `GameFrameX.Core.Abstractions.Events.IEventListener` | 监听器接口,定义 `HandleEvent` 方法 |
| `EventListener<T>` | `GameFrameX.Core.Events.EventListener<T>` | 监听器抽象基类,可针对某个组件代理(`T : IComponentAgent`)处理事件 |
| `EventDispatcher.Dispatch` | `GameFrameX.Core.Events.EventDispatcher` | 静态入口,用于发布事件到指定 Actor 或全局监听器 |

## 操作步骤

### 1. 定义事件参数

创建一个继承自 `GameEventArgs` 的类,用于携带事件数据。`GameEventArgs` 本身仅继承 `System.EventArgs`,不含任何字段。

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class PlayerLoginEventArgs : GameEventArgs
{
    public long PlayerId { get; }
    public DateTime LoginTime { get; }

    public PlayerLoginEventArgs(long playerId)
    {
        PlayerId = playerId;
        LoginTime = DateTime.UtcNow;
    }
}
```

### 2. 实现监听器

有两种写法:直接实现 `IEventListener`,或继承泛型基类 `EventListener<T>(T : IComponentAgent)`。

**写法 A:继承 `EventListener<T>`(推荐,需要访问组件代理时)**

```csharp
using GameFrameX.Core.Events;

public sealed class PlayerLoginListener : EventListener<PlayerComponentAgent>
{
    protected override async Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        if (gameEventArgs is not PlayerLoginEventArgs args) return;
        // 通过组件代理访问组件状态
        var player = agent.GetPlayer();
        await player.OnLogin(args.LoginTime);
    }
}
```

`EventListener<T>` 会把传入的 `IComponentAgent` 自动转换为泛型 `T`,并在内部调用你实现的 `HandleEvent(T agent, GameEventArgs)`。

**写法 B:直接实现 `IEventListener`(不需要访问组件代理时)**

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class GlobalStartupListener : IEventListener
{
    public Type AgentType => null;
    public Task HandleEvent(IComponentAgent agent, GameEventArgs gameEventArgs)
        => HandleEvent(gameEventArgs);

    public Task HandleEvent(GameEventArgs gameEventArgs)
    {
        // 全局事件处理逻辑
        return Task.CompletedTask;
    }
}
```

监听器由框架以**单例**方式管理,实现需保证线程安全。

### 3. 注册监听器

监听器通过框架扫描 `GameFrameX.Hotfix` 程序集自动注册,通常放置在 `GameFrameX.Hotfix` 项目下即可被自动发现。命名需遵守项目架构规则(以 `EventListener` 为后缀,具体约束由 `GameFrameX.Architecture.Analyzers` 强制检查)。

### 4. 分发事件

调用静态类 `EventDispatcher.Dispatch`,传入目标 ActorId、事件 ID 与事件参数。如果 actorId 对应的 Actor 不存在,事件会自动派发给**全局监听器**。

```csharp
using GameFrameX.Core.Events;

// 在 actorId 对应的 Actor 上下文中派发事件
EventDispatcher.Dispatch(playerActorId, EventId.PlayerLogin, new PlayerLoginEventArgs(playerId));
```

事件 ID 使用 `int` 类型的常量,通常集中定义在 `GameFrameX.Apps/Common/Event/EventId.cs` 中。

## 常见变体

| 场景 | 写法 |
|------|------|
| 玩家级别事件(需要访问玩家组件) | 继承 `EventListener<PlayerComponentAgent>`,重写 `HandleEvent(T, GameEventArgs)` |
| 全局/服务器级事件 | 实现 `IEventListener`,使用无代理版本 `HandleEvent(GameEventArgs)` |
| 监听无参数事件 | 事件参数继承 `GameEventArgs`,但不携带任何字段 |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 提示 `NoListenersFound` 警告 | 该事件 ID 没有注册任何监听器 | 确认监听器类位于 `GameFrameX.Hotfix` 程序集且命名符合分析器规则 |
| `HandleEvent` 收到的事件参数是另一种类型 | 事件被错误地分发到了另一个事件 ID | 使用集中定义的 `EventId` 常量,避免硬编码魔数 |
| 监听器多实例共享状态引发并发问题 | 监听器是单例但内部状态未做线程安全保护 | 将可变状态改为局部变量或加锁,避免在监听器中保存请求级数据 |

## 背景(可选)

事件分发在 Actor 上下文内是**串行**执行(`foreach` + `await`),保证同一 Actor 下事件不会并发执行;Actor 不存在时则在新线程中派发全局监听器。每个监听器异常都会被 `LogHelper.Error` 捕获并记录,不会中断其它监听器的处理,详见 [EventDispatcher.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Events/EventDispatcher.cs#L50-L135)。
