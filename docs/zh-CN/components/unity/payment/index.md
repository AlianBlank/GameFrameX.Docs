# 工作原理:平台路由与组件装配

`PaymentComponent` 在 `Awake()` 中根据当前编译平台的 Unity 宏,选定一个支付管理器实现类的全名字符串,再通过反射把它装配为 `IPaymentManager` 模块。各平台的具体实现(谷歌、苹果、WebGL、PC)由独立包提供,本仓只包含路由框架、接口与默认实现。

## 平台路由决策表

`PaymentComponent` 上的 5 个 `[SerializeField]` 字段保存各平台的实现类全名,可在 Inspector 中覆盖:

```csharp
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L24-L28)

运行时按编译宏二选一路由:

| 编译宏 | 使用字段 | 默认实现类全名 |
|------|------|------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `m_componentPCType` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` |
| `UNITY_STANDALONE_OSX` | `m_componentMacType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` |
| 其他平台 | 无 | `typeof(DefaultPaymentManager).FullName` |

```csharp
protected override void Awake()
{
#if UNITY_ANDROID
    componentType = m_componentAndroidType;
#elif UNITY_IOS
    componentType = m_componentIOSType;
#elif UNITY_WEBGL
    componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
    componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
    componentType = m_componentMacType;
#else
    componentType = typeof(DefaultPaymentManager).FullName;
#endif
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IPaymentManager);
    base.Awake();

    _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
    if (_paymentManager == null)
    {
        Log.Fatal("Pay Manager is invalid.");
        return;
    }
}
```

## 组件装配流程

启动时的装配按以下顺序发生,每一步都可在上面的源码中定位:

1. `PaymentComponent` 是一个挂在场景物体上的 Unity 组件,带 `[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]`,并继承自 `GameFrameworkComponent`。
2. `Awake()` 根据编译宏选出一个实现类全名,写入基类字段 `componentType`。
3. `Utility.Assembly.GetType(componentType)` 通过反射解析出实现类的 `Type`,赋给 `ImplementationComponentType`;`InterfaceComponentType` 固定为 `typeof(IPaymentManager)`。
4. `base.Awake()`(GameFrameworkComponent 的逻辑)负责按这两个 `Type` 创建/注册模块实例。
5. `GameFrameworkEntry.GetModule<IPaymentManager>()` 取回装配好的模块,保存到 `_paymentManager`;取不到则 `Log.Fatal("Pay Manager is invalid.")`。
6. 之后 `PaymentComponent` 上的所有公开方法(`Init`、`IsReady`、`Buy`、`QueryPurchases`、`ConsumePurchase` 等)都只是参数校验后转发给 `_paymentManager`。

例如 `Buy` 的转发与校验:

```csharp
[UnityEngine.Scripting.Preserve]
public void Buy(PurchaseParams purchaseParams)
{
    if (purchaseParams == null)
    {
        Log.Warning("Purchase params is null.");
        return;
    }

    if (string.IsNullOrEmpty(purchaseParams.ProductId))
    {
        Log.Warning("Product ID is null or empty.");
        return;
    }

    if (string.IsNullOrEmpty(purchaseParams.OrderId))
    {
        Log.Warning("Order ID is null or empty.");
        return;
    }

    _paymentManager.Buy(purchaseParams);
}
```

## 实现侧的契约:BasePaymentManager

各平台包(谷歌、苹果等)中的管理器继承 `BasePaymentManager : GameFrameworkModule, IPaymentManager`。它集中声明了四个事件(`OnPurchaseSuccess`、`OnPurchaseFailed`、`OnQueryPurchasesResult`、`OnConsumePurchaseResult`),并提供 `RaiseXxx(e)` 保护方法供子类触发事件,同时把 `Init`、`IsReady` 等声明为抽象成员:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    [UnityEngine.Scripting.Preserve]
    protected BasePaymentManager()
    {
    }

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);

    [UnityEngine.Scripting.Preserve]
    public abstract bool IsReady();
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L74)

`PaymentComponent` 上对应的同名事件直接转发到 `_paymentManager` 的事件(add/remove 访问器),因此上层订阅与实现侧触发是同一份事件源:

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}
```

## 防裁剪:GameFrameXPaymentCroppingHelper

`PaymentComponent` 必须与 `GameFrameXPaymentCroppingHelper` 同物体共存(`[RequireComponent]`)。该 Helper 的 `Start()` 用 `_ = typeof(...)` 强引用接口、默认实现和参数/事件类型,确保代码裁剪或 IL2CPP 打包时这些类型不被裁掉:

```csharp
[Preserve]
public class GameFrameXPaymentCroppingHelper : MonoBehaviour
{
    [Preserve]
    void Start()
    {
        _ = typeof(PaymentComponent);
        _ = typeof(BasePaymentManager);
        _ = typeof(IPaymentManager);
        _ = typeof(DefaultPaymentManager);
        _ = typeof(PurchaseParams);
        _ = typeof(PaymentEventArgs);
        _ = typeof(PaymentProductType);
        _ = typeof(PaymentResultCode);
    }
}
```

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志出现 `Pay Manager is invalid.`(Fatal) | `GameFrameworkEntry.GetModule<IPaymentManager>()` 返回 null,通常是路由字符串对应的实现包未安装或类名被改 | 安装对应平台的支付实现包,或在 Inspector 中把该平台的 `Type` 字段改回正确的类全名 |
| 运行到默认实现,没有真实支付 | 当前平台不在五个宏分支内(如编辑器或其余平台),落到 `DefaultPaymentManager` | 属预期行为;真机构建到对应平台才会路由到具体实现 |
| 裁剪/IL2CPP 打包后类型丢失 | 反射加载的类型被裁剪 | 已由 `GameFrameXPaymentCroppingHelper` 强引用规避;不要移除该组件 |
| 调用 `Buy` 无任何反应,仅 Warning 日志 | `purchaseParams` 为 null,或 `ProductId`/`OrderId` 为空,参数校验直接 return | 检查 `PurchaseParams` 的必填字段后再调用 |

## 背景

之所以用"字符串全名 + 反射"而不是直接 `typeof(...)`:各平台实现位于独立的包(如 `com.gameframex.unity.payment.google`)中,本仓编译时不引用它们,写死类型会带来编译依赖;而字符串只在目标平台打包时才被解析。这样本包可以单独发布,平台包按需引入,Inspector 中的序列化字段也允许项目在不动代码的情况下替换实现。
