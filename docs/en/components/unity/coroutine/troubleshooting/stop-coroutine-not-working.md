# StopCoroutine Was Called But the Coroutine Didn't Stop

You called `CoroutineComponent.StopCoroutine(...)`, but the coroutine kept running and was only cleaned up when the scene closed or `StopAllCoroutines` was invoked. This usually happens because the `IEnumerator` instance passed in is not the same reference used when starting, causing the component's internal tracking table to miss.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Coroutine still runs after `StopCoroutine(ienumerator)` is called | The instance passed in is not the same `IEnumerator` used at start time, so the dictionary lookup fails and it falls back to `base.StopCoroutine`, but the `base` path does not actually track this coroutine | Save the original `IEnumerator` reference passed to `StartCoroutine`, and pass the same variable when stopping |
| Using the `UnityEngine.Coroutine` returned by `StartCoroutine` to stop is ineffective | The base class `MonoBehaviour.StopCoroutine` path is called, but the coroutine is not removed from the tracking table | Switch to calling the `StopCoroutine(UnityEngine.Coroutine)` overload on the `CoroutineComponent` instance |
| `WaitForEndOfFrameFinish` callback still fires after stopping | When stopped while `yield return WaitForEndOfFrame` has not yet reached the next frame, the callback still runs after that frame ends | Set `callback` to null before stopping the coroutine, or use conditional checks instead |

## Fix Steps

### Scenario 1: `StopCoroutine(IEnumerator)` Did Not Take Effect

`CoroutineComponent` uses `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` to track all started coroutines, where the key is the `IEnumerator` reference. When the dictionary misses, the source falls into the `base.StopCoroutine(enumerator)` branch:

```csharp
public new void StopCoroutine(IEnumerator enumerator)
{
    if (m_CoroutineMap.TryGetValue(enumerator, out var coroutine))
    {
        base.StopCoroutine(coroutine);
        m_CoroutineMap.TryRemove(enumerator, out _);
    }
    else
    {
        base.StopCoroutine(enumerator);
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

Solution: save the `IEnumerator` passed at start to a field, and pass the same reference when stopping.

```csharp
private IEnumerator _runningRoutine;

void Start()
{
    _runningRoutine = MyRoutine();
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StartCoroutine(_runningRoutine);
}

void StopMyRoutine()
{
    // Pass back the same instance; _runningRoutine is the dictionary's key
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StopCoroutine(_runningRoutine);
}

IEnumerator MyRoutine()
{
    while (true) { yield return null; }
}
```

### Scenario 2: Stopping with the `UnityEngine.Coroutine` Overload Is Ineffective

If you have the `UnityEngine.Coroutine` returned by `StartCoroutine`, you must use the second overload. The source iterates through the dictionary to find and remove the corresponding entry:

```csharp
public new void StopCoroutine(UnityEngine.Coroutine coroutine)
{
    base.StopCoroutine(coroutine);
    foreach (var item in m_CoroutineMap)
    {
        if (item.Value == coroutine)
        {
            m_CoroutineMap.TryRemove(item.Key, out _);
            break;
        }
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L56-L67)

Common mistake: passing the `Coroutine` reference to the first overload `StopCoroutine(IEnumerator)`, which misses in the dictionary and falls into the `else` branch.

### Scenario 3: Clear All Coroutines at Once

If you just want to stop everything outright, use the `StopAllCoroutines` overload directly. It stops each one individually and clears the dictionary:

```csharp
GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
    .StopAllCoroutines();
```

The source first iterates through the dictionary to stop each one, then calls `base.StopAllCoroutines()` to handle untracked coroutines:

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

## Verification

1. Add a periodic `Debug.Log` inside the coroutine; after calling `StopCoroutine`, no new logs should appear within 1 second.
2. Check `Coroutine` in Unity Profiler's Memory panel to see if background tasks are still growing.
3. If the coroutine nests `yield return new WaitForSeconds(...)`, that `WaitForSeconds` should not complete its callback after stopping.
