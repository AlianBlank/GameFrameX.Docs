# WebGL プラットフォーム利用ガイドと HTTPS 証明書の取り扱い

本ページでは、WebGL プラットフォームで GameFrameX Web を使用して HTTP(S) リクエストを送信する方法、および自己署名/信頼されていない証明書に遭遇した場合の対処方法について説明します。このライブラリは C# Task 非同期モデルに基づいており、WebGL、PC、モバイルをクロスプラットフォームでサポートしています。WebGL でのリクエストは最終的にブラウザのネットワークスタックによって実行されます。

## 前提条件

- Unity 2019.4 以上。
- ビルドターゲットを **WebGL** に切り替えていること(File → Build Settings → WebGL → Switch Platform)。
- `com.gameframex.unity.web` パッケージがインストール済みであること(下記の手順 1 を参照)。

## 操作手順

1. パッケージをインストールします。`Packages/manifest.json` に scoped registry を追加します(または Git URL を直接使用します):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.web": "1.3.5"
  }
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L43-L59)

   Package Manager で Git URL `https://github.com/gameframex/com.gameframex.unity.web.git` を使用することもできます。または、リポジトリを `Packages` ディレクトリにクローンすると自動的に読み込まれます。

2. プラットフォームを WebGL に切り替えた後、`GameFrameworkEntry.GetModule<IWebManager>()` でネットワークモジュールを取得します。

3. `async/await` でリクエストを送信します。以下はバイナリアップロードの完全な例です(WebGL でも同様に使用できます):

```csharp
public async Task UploadBinaryDataAsync(byte[] fileData, string fileName)
{
    var webManager = GameFrameworkEntry.GetModule<IWebManager>();

    var queryParams = new Dictionary<string, string>
    {
        { "fileName", fileName }
    };

    var headers = new Dictionary<string, string>
    {
        { "Content-Type", "application/octet-stream" },
        { "Authorization", "Bearer your-token" }
    };

    WebBufferResult result = await webManager.PostToBytes(
        "https://api.example.com/upload",
        fileData,
        queryParams,
        headers
    );

    if (result.IsSuccess)
    {
        Debug.Log("Upload successful!");
        byte[] responseData = result.Data;
    }
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L75-L104)

## HTTPS 証明書の取り扱い

- リポジトリには証明書バイパスコンポーネント [DefaultBypassCertificate.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/DefaultBypassCertificate.cs) が組み込まれており、証明書検証の失敗を回避する必要がある場面で使用できます。独自の `IWebManager` 実装やカスタム検証ロジックを作成する際の参考にしてください。
- リポジトリのソースコード内で `UNITY_WEBGL` を検索してもヒットしません:このパッケージには WebGL 専用のコード分岐はなく、WebGL ビルドでの TLS ハンドシェイクと証明書検証はブラウザのネットワークスタックが引き継ぎます。エディター/ネイティブプラットフォームでのバイパスコールバックは WebGL ページには適用されません。
- そのため、WebGL デプロイの推奨される方法は、**サイトと API ドメインに信頼された有効な証明書を設定すること**(例:Let's Encrypt)です。自己署名証明書の場合はリバースプロキシ/ゲートウェイ側で TLS を終端し、クライアント側のバイパスに依存しないでください。
- ページと API のプロトコルは一致している必要があります:HTTPS ページから HTTP API へのリクエストはブラウザによって「混在コンテンツ(Mixed Content)」としてブロックされるため、WebGL ページでは `https://` の API アドレスを統一的に使用してください。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| ブラウザコンソールに混在コンテンツ/Mixed Content のブロックが表示される | HTTPS ページから HTTP API へリクエストしている | API の URL を `https://` に統一する |
| WebGL のリクエストが拒否され、証明書が信頼されていないと表示される | サイトまたは API が自己署名/期限切れの証明書を使用している | ドメインに信頼された証明書を発行するか、ゲートウェイ側で TLS を終端する |
| エディターでは証明書のバイパスが有効だが、WebGL ビルド後は無効 | WebGL の TLS 検証はブラウザが実行し、クライアントのコールバックは関与しない | クライアント側のバイパスに依存しない;サーバー証明書を修正する |
| リクエストタイムアウト | ネットワークに到達できない、またはサーバーが応答しない | README の例外処理パターンに従って `WebExceptionStatus.Timeout` をキャッチする |
| WebGL でリクエストログが表示されない | 送受信ログのマクロが有効になっていない | メニュー GameFrameX/Scripting Define Symbols で対応するマクロを有効にしてから再ビルドする |

タイムアウトなどの例外は以下のパターンでキャッチします(README 公式の例):

```csharp
public async Task<string> SafeWebRequestAsync(string url)
{
    try
    {
        return await webManager.GetToString(url);
    }
    catch (WebException ex) when (ex.Status == WebExceptionStatus.Timeout)
    {
        Debug.LogError("Request timeout: " + ex.Message);
        return null;
    }
    catch (IOException ex)
    {
        Debug.LogError("Network IO error: " + ex.Message);
        return null;
    }
}
```

## よく使う API クイックリファレンス

コアインターフェースは [IWebManager](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs) です。よく使われるシグネチャ(README API Reference より抜粋):

| メソッド | シグネチャ | 説明 |
|------|------|------|
| GetToString | `Task<string> GetToString(string url)` | GET リクエスト、文字列を返す |
| GetToBytes | `Task<byte[]> GetToBytes(string url, Dictionary<string, string> queryString, Dictionary<string, string> header)` | GET リクエスト、バイト配列を返す |
| PostToString | `Task<string> PostToString(string url, Dictionary<string, string> formData = null)` | POST フォーム、文字列を返す |
| PostToBytes | `Task<WebBufferResult> PostToBytes(string url, byte[] binaryData, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | POST バイナリアップロード |
| GetProtoBuf | `Task<T> GetProtoBuf<T>(string url) where T : class, IExtensible` | Protocol Buffers GET |
| PostProtoBuf | `Task<T> PostProtoBuf<T>(string url, IExtensible requestData) where T : class, IExtensible` | Protocol Buffers POST |

## 背景

GameFrameX Web はクロスプラットフォームの HTTP ネットワークライブラリで、文字列、JSON、バイナリ、Protocol Buffers をサポートし、接続プールの再利用と最大同時接続数の制御も備えています(README の Features リストを参照)。WebGL ビルド時、Unity は `HttpClient`/`HttpWebRequest` のリクエストをブラウザの Fetch/XHR に変換するため、TLS、CORS、混在コンテンツなどのポリシーはすべてブラウザが決定します——これが証明書の問題をサーバー側で解決しなければならない理由です。ネットワークライブラリ全体の機能については、公式ドキュメント https://gameframex.doc.alianblank.com を参照してください。
