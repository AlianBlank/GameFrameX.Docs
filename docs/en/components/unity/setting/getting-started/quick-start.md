# Quick Start

Get up and running with GameFrameX Setting in minutes to add typed key-value storage to your Unity project: complete the installation, attach `SettingComponent` to a scene, and call `SetXxx` / `GetXxx` to read and write `bool` / `int` / `float` / `string` and serializable objects.

## Prerequisites

- Unity 2019.4 or later.
- Dependency package `com.gameframex.unity` 1.1.1, will be resolved automatically with the package.
- A `GameFramework` entry must exist in the scene (the runtime obtains the manager via `GameFrameworkEntry.GetModule<ISettingManager>()`).

## Installation

Choose any of the following methods to install it into your Unity project:

1. Edit `Packages/manifest.json` and add the scopedRegistries:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.setting": "1.5.2"
     }
   }
   ```

2. Add the Git dependency directly in `dependencies` of `manifest.json`:

   ```json
   {
     "com.gameframex.unity.setting": "https://github.com/gameframex/com.gameframex.unity.setting.git"
   }
   ```

3. In Unity's `Package Manager`, use **Add package from git URL** and paste the Git URL above.
4. Place the repository directly into the `Packages` directory of your Unity project, and Unity will recognize it automatically.

## Steps

### 1. Add SettingComponent to the Scene

Create an empty GameObject and add the component **GameFrameX/Setting** (`SettingComponent`). The component will automatically create `SettingManager` in `Awake` and load persisted data.

The component comes with a `GameFrameXSettingCroppingHelper` by default, which is enforced via `[RequireComponent]`.

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L43-L99)

### 2. Choose the Storage Backend

Two fields on `SettingComponent` determine the storage backend:

| Inspector Field | Purpose | Default Value |
|------|------|--------|
| `Setting Helper Type Name` | The full type name used to create `ISettingHelper` via reflection | `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` |
| `Custom Setting Helper` | Drag a `SettingHelperBase` subclass directly into the scene | `null` |

Available built-in backends:

- `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` (default) — Unity PlayerPrefs, adapted for Douyin, WeChat, Kuaishou, and Alipay mini-game SDKs.
- `GameFrameX.Setting.Runtime.DefaultSettingHelper` — Binary file storage based on `Application.persistentDataPath`.

How to switch: modify the `Setting Helper Type Name` field in the Inspector, or specify your own implementation in `Custom Setting Helper`.

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L54)

### 3. Write and Read Settings

Use the typed APIs provided by `SettingComponent` to manipulate settings. When a key does not exist or the data is corrupted, `GetXxx` will return the default value you passed in and print a warning; it will not throw an exception.

```csharp
using GameFrameX.Setting.Runtime;

SettingComponent setting = /* GetComponent or obtained via the GameFramework entry */;

// Write settings
setting.SetBool("FullScreen", true);
setting.SetInt("ResolutionWidth", 1920);
setting.SetFloat("Volume", 0.8f);
setting.SetString("PlayerName", "PlayerOne");

// Read settings (with default value fallback)
float volume = setting.GetFloat("Volume", 0.5f);

// Check whether a key exists
if (setting.HasSetting("PlayerName"))
{
    string name = setting.GetString("PlayerName");
}
```

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs) · [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L43-L73)

### 4. Persistence and Deletion

Modifications only take effect in memory by default; you must call `Save()` to persist them to disk. Deletion operations also support single-key and clear-all.

```csharp
// Persist to storage
setting.Save();

// Remove a single key
setting.RemoveSetting("PlayerName");

// Clear all settings
setting.RemoveAllSettings();
```

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

## Common Variations

- **Store serializable objects** — `SetObject<T>(string, T)` / `GetObject<T>(string)` use JSON serialization internally, suitable for save data and configuration structs.
- **Manual loading** — Call `setting.Load()` after the application starts to reload all settings from storage.
- **Enumerate all key names** — `setting.GetAllSettingNames()` returns a string array of all setting keys currently in memory (Note: the PlayerPrefs backend does not support this capability).
- **Mini-game platforms** — In Douyin, WeChat, Kuaishou, and Alipay mini-game builds, the PlayerPrefs backend will automatically route to the platform SDK's storage; `DefaultSettingHelper` still uses `Application.persistentDataPath` file I/O, which is consistent across all platforms.

## Common Errors

| Symptom | Cause | Workaround |
|------|------|----------|
| Log error `Setting manager is invalid.` after startup | The scene is missing the `GameFramework` entry, or the entry is not initialized before `SettingComponent` | Enable the scene containing `SettingComponent` only after `GameFramework` initialization is complete |
| Settings not taking effect after `Log.Fatal` | Failed to obtain `ISettingManager` during `Awake` | Check whether the `GameFramework` component chain is complete |
| Data lost after restarting the game following modifications | Memory writes were not committed via `Save()` | Explicitly call `setting.Save()` before application exit or at critical moments |
| Custom Helper not taking effect | The `Setting Helper Type Name` does not match the actual full type name, or `Custom Setting Helper` is set simultaneously | Priority: `Custom Setting Helper` > `Setting Helper Type Name`; choose one |
| Floating-point values read out abnormally in different language locales | `SetFloat` writes using `CultureInfo.InvariantCulture`, but the read side is localized | Always use `GetFloat`; do not deserialize the underlying string yourself |

## Background (Optional)

`SettingComponent` is a subclass of `GameFrameworkComponent`. During the `Awake` phase, it obtains `SettingManager` via `GameFrameworkEntry.GetModule<ISettingManager>()`, then creates and injects `ISettingHelper` using reflection or a custom field. `SettingManager` performs key name validation on all `SetXxx` / `GetXxx` calls; an empty key throws `GameFrameworkException("Setting name is invalid.")`. When data is corrupted, `TryParse` is used to fall back to the default value and `Log.Warning` is called, ensuring runtime continuity.
