# Helper の作成に失敗した場合の対処法

`SettingComponent` が `Awake` 段階で `Helper.CreateHelper` の呼び出しに失敗すると、Unity コンソールにエラーログ `Can not create setting helper.` が表示されます。その後、Helper がアタッチされていないため、すべての設定の読み書きが無効になります。このページでは、一般的な原因と修正手順を説明します。

## クイック診断

| 症状 / ログ | 原因 | 修正方法 |
|---|---|---|
| `Can not create setting helper.` かつ `m_CustomSettingHelper == null` | `m_SettingHelperTypeName` のスペルミス、名前空間の不一致、または Helper 型が配置されたアセンブリが IL2CPP/Managed Stripping で除去される | 「カスタム型名のスペルミス」セクションに従って完全修飾名を確認してください。組み込みの `PlayerPrefsSettingHelper` の場合は、「コードストリッピングによる型の欠落」セクションを参照してください |
| `Can not create setting helper.` かつ `m_CustomSettingHelper != null` | カスタム Helper クラスが `SettingHelperBase` を継承していない、`MonoBehaviour` ではない、またはパラメーターなしのコンストラクターがない | 「カスタム Helper クラスが不正」セクションに従って継承と名前空間を修正してください |
| `m_CustomSettingHelper != null` なのにエラーが表示される | カスタム Helper フィールドに、無効化されたスクリプトまたは欠落したスクリプト（スクリプトがない、または GUID が無効）がドラッグされている | 有効なカスタム Helper アセットを再アタッチするか、Inspector の `Custom Setting Helper` を空にしてください |
| コンソールに `Can not create setting helper.` は表示されないが、その後の `Save/Load` の動作がおかしい | `Awake` の完了を待っていない、または `SettingComponent` がシーンに存在しない | シーン内に `SettingComponent` が存在し、同じフレームで破棄されていないことを確認してください |

## 修正手順

### 1. カスタム型名のスペルミス、または型が見つからない

`SettingComponent` はデフォルトで、完全修飾名の文字列 `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` を使用してリフレクションにより Helper を作成します。この文字列に誤りがあると、`Helper.CreateHelper` は `null` を返します。

シーン内で `SettingComponent` がアタッチされている GameObject を開き、Inspector の `Setting Helper Type Name` フィールドに正しい完全修飾名を入力します。デフォルト値については、以下を参照してください。

```csharp
[SerializeField] private string m_SettingHelperTypeName = "GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper";
```

Source: [SettingComponent.cs#L52](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52)

名前空間は `using GameFrameX.Setting.Runtime;` と一致している必要があります。独自の Helper サブクラスを作成した場合は、文字列を `あなたの名前空間.あなたのHelperクラス名` に変更してください。

### 2. カスタム Helper クラスが不正

`m_CustomSettingHelper` を介して Helper インスタンスを直接指定する場合、そのクラスは次の条件を満たす必要があります。

- `SettingHelperBase` を継承すること。抽象基底クラスの定義については、[SettingHelperBase.cs#L43](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L43) を参照してください。
- `Helper.CreateHelper` が `gameObject.AddComponent<T>()` を呼び出すため、`MonoBehaviour` の派生クラスであること。
- クラスに `[UnityEngine.Scripting.Preserve]` が付与されているか、実際に参照されていること。付与されていない場合、IL2CPP リリースビルドで除去される可能性があります。

最小限の有効な例を以下に示します。

```csharp
using GameFrameX.Setting.Runtime;
using UnityEngine;

namespace MyGame.Settings
{
    [UnityEngine.Scripting.Preserve]
    public sealed class MySettingHelper : SettingHelperBase
    {
        public override int Count => 0;
        public override bool Load() => true;
        public override bool Save() => true;
        public override string[] GetAllSettingNames() => System.Array.Empty<string>();
        public override void GetAllSettingNames(System.Collections.Generic.List<string> results) { }
        public override bool HasSetting(string settingName) => false;
        public override bool RemoveSetting(string settingName) => false;
        public override bool GetBool(string settingName, bool defaultValue) => defaultValue;
        // 省略其余 Get/Set 重载,请参考 PlayerPrefsSettingHelper
    }
}
```

カスタム Helper を作成したら、Inspector の `Custom Setting Helper` フィールドにプレハブをドラッグし、`SettingComponent` が優先的に使用するようにします。

```csharp
[SerializeField] private SettingHelperBase m_CustomSettingHelper = null;
```

Source: [SettingComponent.cs#L54](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L54)

### 3. コードストリッピングによる型の欠落

`m_SettingHelperTypeName` が完全に正しくても、ビルド時に `Managed Stripping Level > Low` または IL2CPP リンキングが有効になっている場合、フレームワークの Helper クラスが静的解析で参照されず、除去される可能性があります。

リポジトリには、リリースビルド内ですべての Helper 型への参照を「保持」するための空の `GameFrameXSettingCroppingHelper` が用意されています。

```csharp
[UnityEngine.Scripting.Preserve]
public class GameFrameXSettingCroppingHelper : MonoBehaviour
{
    [UnityEngine.Scripting.Preserve]
    private void Awake()
    {
        _ = typeof(DefaultSetting);
        _ = typeof(DefaultSettingHelper);
        _ = typeof(DefaultSettingSerializer);
        _ = typeof(PlayerPrefsSettingHelper);
        _ = typeof(SettingComponent);
        _ = typeof(SettingHelperBase);
        _ = typeof(ISettingHelper);
    }
}
```

Source: [GameFrameXSettingCroppingHelper.cs#L41-L58](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/GameFrameXSettingCroppingHelper.cs#L41-L58)

`SettingComponent` には標準で `[RequireComponent(typeof(GameFrameXSettingCroppingHelper))]` が付与されているため、`SettingComponent` を追加すると、この Helper ノードが自動的に作成されます。**この子オブジェクトを手動で削除しないでください。**削除すると、`Awake` 内の `typeof(...)` の参照チェーンが切断され、型が依然として除去される可能性があります。

新しいカスタム Helper サブクラスを追加した場合は、必ずこのストリッピング対象リストにも `_ = typeof(あなたのHelperクラス);` という行を追加するか、Project Settings → Player → Other Settings で `Managed Stripping Level` を `Low` に設定するか、オフにしてください。

### 4. Awake より前に Setting にアクセスする

Helper の作成と `m_SettingManager.SetSettingHelper(settingHelper)` の呼び出しは `SettingComponent.Awake` 内でのみ行われ、その後、`Start` 内で `m_SettingManager.Load()` が実行されます。他のスクリプトの `Awake` で先に `GameFramework.Setting.*` API を呼び出した場合、Helper がまだ設定されていないため、「Helper の作成に失敗しました」や読み書きの異常として現れます。

修正方法としては、すべての Setting へのアクセスを `Start` 以降に移動するか、自分のスクリプト内で `MonoBehaviour.Start` → `yield return null` → 設定を読み取るという順序を実行してください。

## 検証

上記の手順で修正したら、次の 3 項目を確認してください。

1. シーンを起動し、コンソールに `Can not create setting helper.` が表示されなくなったこと、および `Setting manager is invalid.` も表示されていないことを確認します。
2. Hierarchy で `SettingComponent` がアタッチされた GameObject を選択すると、`settingHelper.name = "SettingHelper";` によって作成された、`SettingHelper` という名前の子オブジェクトが表示されます（[SettingComponent.cs#L94](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L94) を参照）。
3. `PlayerPrefsSettingHelper_BoolUsesIntStorage` などの単体テストを実行し、`SetBool/GetBool/HasSetting` が永続化バックエンドにヒットすることを確認します。[UnitTests.cs#L11-L21](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Tests/UnitTests.cs#L11-L21) を参照してください。
