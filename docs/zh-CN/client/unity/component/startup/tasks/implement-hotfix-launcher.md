# 如何接入热更启动器（IHotfixLauncher）

实现 `IHotfixLauncher` 接口即可让启动流程在资源补丁完成后调用你的热更方案（HybridCLR、ILRuntime、自研方案等），由你在应用层决定如何加载程序集并跳转到热更入口。

## 前置条件

- 启动流程已正确初始化（参考启动流程接入文档）。
- 已准备好 `StartupOptions` 配置资产，并填写 `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`。
- 已引入 `GameFrameX.Startup.Runtime` 命名空间与 `Cysharp.Threading.Tasks`。

## 接口契约

`IHotfixLauncher` 只暴露一个异步方法，无论成功或失败都必须返回 `HotfixLaunchResult`，不要直接抛出异常。

```csharp
using Cysharp.Threading.Tasks;

namespace GameFrameX.Startup.Runtime
{
    /// <summary>
    /// 热更启动接口，由应用层实现。包内不绑定具体热更方案（HybridCLR / 其他）。
    /// </summary>
    public interface IHotfixLauncher
    {
        UniTask<HotfixLaunchResult> StartAsync(StartupOptions options);
    }
}
```

Source: [IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L1-L17)

## 操作步骤

1. 在应用工程下新建类（例如 `MyHotfixLauncher`），实现 `IHotfixLauncher`。
2. 在 `StartAsync` 内根据 `options` 读取热更 DLL/程序集，并通过反射调用入口方法（构造 `HotfixLaunchResult.Succeed()` 或 `HotfixLaunchResult.Fail(message)` 返回）。
3. 不要在 `StartAsync` 内抛异常——失败时构造 `HotfixLaunchResult.Fail("错误信息")` 返回，启动框架会据此走失败分支并发布 `StartupFailedEventArgs`。
4. 把 `MyHotfixLauncher` 实例注入到启动管理器（通常通过 `StartupManager` 的注入接口或 `GameObject` 拖拽配置），覆盖框架默认的 Launcher。
5. 运行启动流程；当 Patch 阶段全部完成后，框架会自动调用你的 `StartAsync`。

## 最小实现示例

下面是基于契约测试的最小可用实现，可作为模板直接改造：

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public sealed class MyHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        try
        {
            // 1) 加载热更程序集（示例：使用 HybridCLR / YooAsset / 自研 loader）
            //    var assembly = LoadAssembly(options.HotfixAssemblyName);

            // 2) 通过反射跳转到热更入口
            //    var entryType = assembly.GetType(options.HotfixEntryTypeName);
            //    var entryMethod = entryType.GetMethod(options.HotfixEntryMethodName);
            //    entryMethod.Invoke(null, null);

            await UniTask.Yield();
            return HotfixLaunchResult.Succeed();
        }
        catch (System.Exception ex)
        {
            return HotfixLaunchResult.Fail(ex.Message);
        }
    }
}
```

## 常见变体

- **HybridCLR 方案**：在 `StartAsync` 中通过 `HybridCLR.RuntimeApi.LoadDllFromMemory` 加载 DLL，再用 `System.Reflection.Assembly` 反射调用入口方法。
- **纯资源热更（无 DLL）**：直接 `Resources.Load<GameObject>` 加载预制体后 `Instantiate`，入口逻辑可跳过反射步骤。
- **带初始化阶段的方案**：若你的热更框架需要异步初始化（如下载、校验），在 `StartAsync` 内 `await` 完成后再返回 `Succeed`。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 启动崩溃或黑屏 | `StartAsync` 抛出了未捕获异常 | 改为捕获后调用 `HotfixLaunchResult.Fail(message)` 返回 |
| 返回 `Success=true` 但游戏未进入主场景 | 入口方法名/类型名写错 | 检查 `StartupOptions` 中 `HotfixEntryTypeName` / `HotfixEntryMethodName` 与 DLL 中完全一致 |
| 一直停留在 Patch 阶段 | 未注入自定义 `IHotfixLauncher`，框架使用默认空实现 | 在启动管理器中替换为你自己的实现类 |

## 验证

- 运行启动流程，观察是否在 Patch 完成后进入热更入口。
- 单元测试可参考 `IHotfixLauncherContractTests`，断言成功实现返回 `result.Success == true` 且 `ErrorMessage` 为空字符串；失败实现返回 `result.Success == false` 且 `ErrorMessage` 等于传入的异常消息。

## 背景（可选）

`IHotfixLauncher` 是包刻意暴露的扩展点：包内只规定「Patch 完成 → 调 Launcher → 拿到结果」的协议，不绑定具体热更方案，以避免与 HybridCLR 等第三方包产生强耦合。
