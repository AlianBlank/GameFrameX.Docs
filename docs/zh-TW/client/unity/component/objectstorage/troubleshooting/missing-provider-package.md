# 找不到具體儲存提供者套件怎麼辦

`com.gameframex.unity.objectstorage` 僅定義物件儲存的抽象介面與工廠，**不包含**任何雲端廠商的具體實作。當你想要串接阿里雲 OSS、AWS S3、騰訊雲 COS 等具體服務時，需要單獨安裝對應的「物件儲存提供者套件」，找不到時按本頁步驟排查。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 想上傳到 OSS/S3/COS，但本儲存庫沒有對應實作類別 | 本套件只提供抽象，需要單獨的提供者套件 | 安裝 `com.gameframex.unity.objectstorage.aliyunoss`（或對應廠商）套件 |
| `Activator.CreateInstance<T>()` 擲回 `MissingMethodException` 或找不到類型 | 未引入實作套件，泛型參數對應的類別不存在 | 引入對應提供者套件，確保實作 `IObjectStorageUploadManager` 的類別已編譯 |
| 在 Package Manager 裡搜尋不到提供者套件 | 未設定 scopedRegistries，Unity 不會從 GameFrameX 登錄解析 | 在 `manifest.json` 中補上 `scopedRegistries`，見下文 |
| 已按 Git URL 新增，但 Unity 回報「無法解析相依性」 | `scopes` 未涵蓋 `com.gameframex`，或相依性名稱拼錯 | 檢查 `scopes` 陣列包含 `com.gameframex`，相依性名稱完全相符 |

## 修復步驟

### 1. 確認本套件只提供抽象

README 已明確說明：本套件定義了 `IObjectStorageUploadManager` 介面與 `BaseObjectStorageUploadManager` 抽象基底類別，並提供 `ObjectStorageUploadFactory` 靜態工廠，**服務商特定的實作以獨立套件的形式提供**。

```csharp
// 僅依賴本套件時，工廠無法運作——沒有可實例化的具體類型
public static IObjectStorageUploadManager Create<T>(
    string accessKey, string secretKey, string bucketName, string endpoint = null)
    where T : IObjectStorageUploadManager
{
    var manager = Activator.CreateInstance<T>();  // T 必須由提供者套件提供
    manager.Init(accessKey, secretKey, bucketName, endpoint);
    return manager;
}
```

Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

### 2. 設定 scopedRegistries（套件管理器安裝方式）

開啟 Unity 專案的 `Packages/manifest.json`，新增 GameFrameX 登錄與相依性：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.objectstorage": "1.1.0"
  }
}
```

注意 `scopes` 必須包含 `com.gameframex`，否則 Unity 不會從該登錄解析相依性。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/README.zh-CN.md#L41-L60)

### 3. 安裝具體的提供者套件

在 [GameFrameX 文件站](https://gameframex.doc.alianblank.com) 或 GitHub 組織下尋找以 `com.gameframex.unity.objectstorage.` 開頭的提供者套件，例如：

| 廠商 | 套件名稱（範例） |
|------|-------------|
| 阿里雲 OSS | `com.gameframex.unity.objectstorage.aliyunoss` |
| 其他 | 在文件站「物件儲存」分類下尋找最新支援的廠商清單 |

將對應套件名稱附加到 `dependencies`：

```json
"dependencies": {
  "com.gameframex.unity.objectstorage": "1.1.0",
  "com.gameframex.unity.objectstorage.aliyunoss": "x.y.z"
}
```

### 4. 用工廠建立具體實例

安裝提供者套件後，呼叫 `ObjectStorageUploadFactory.Create<T>()` 時把泛型參數替換為該套件中實作 `IObjectStorageUploadManager` 的具體類別。

```csharp
using GameFrameX.ObjectStorage.Editor;

// 由提供者套件提供，例如 AliyunOssUploadManager
IObjectStorageUploadManager uploader =
    ObjectStorageUploadFactory.Create<AliyunOssUploadManager>(
        accessKey: "your-access-key",
        secretKey: "your-secret-key",
        bucketName: "your-bucket",
        endpoint: "oss-cn-hangzhou.aliyuncs.com");

uploader.SetSavePath("remote/folder/");
uploader.UploadFile("Assets/Builds/pc.zip");
```

Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L1-L22)

### 5. 找不到提供者套件時的替代方案：自行實作

如果目標廠商暫無官方提供者套件，可繼承 `BaseObjectStorageUploadManager` 自行實作 `Init` / `UploadDirectoryInternal` / `UploadFileInternal`，再用工廠建立：

```csharp
using GameFrameX.ObjectStorage.Editor;

public sealed class MyVendorUploadManager : BaseObjectStorageUploadManager
{
    public override void Init(string accessKey, string secretKey,
                              string bucketName, string endpoint = null)
    {
        // 初始化 SDK 用戶端
    }

    protected override void UploadDirectoryInternal(string localDirectory)
    {
        // 走訪目錄並上傳
    }

    protected override bool UploadFileInternal(string localFilePathAndName)
    {
        // 單一檔案上傳實作
        return true;
    }
}
```

Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L5-L35)

## 驗證

1. 在 `manifest.json` 中儲存提供者套件相依性後，回到 Unity，等待套件管理器解析完成，主控台沒有紅色錯誤。
2. 撰寫一行 `Activator.CreateInstance<YourUploadManager>()` 測試程式碼，能成功執行且不擲回 `MissingMethodException`。
3. 呼叫 `UploadFile` 傳回 `true`，並在雲端廠商主控台看到新物件出現。
