# 發生無效語彙基元解析例外時該怎麼辦

當 LitJSON 在解析 JSON 字串時遇到無法辨識的語彙基元（lexical token，`ParserToken`），便會擲出 `JsonException`，並附帶訊息 `"Invalid token '{0}' in input string"`。本頁可協助您快速找出此例外的根本原因並加以修正。

## 快速診斷

| 症狀（例外訊息） | 原因 | 修正方式 |
|----------------|------|------|
| `Invalid token 'X' in input string`（語彙基元為單一字元） | JSON 中出現非預期的字元（例如未逸出的引號、註解、尾端逗號） | 移除或逸出非法字元，確保符合 JSON 規範 |
| `Invalid token 'X' in input string`（語彙基元為數字） | 數字常值格式錯誤（例如 `1.`、`0x1A`、多餘符號） | 修正數字格式，僅使用十進位數字，並可選擇性地加上小數點與指數 |
| `Invalid token 'True' / 'False' / 'Null'` | 布林值或 null 以帕斯卡命名法（PascalCase）撰寫，例如 `True` | 使用 JSON 規定的全小寫 `true` / `false` / `null` |
| `Invalid token 'CharSeq'` | 字串內部出現非法字元（例如不匹配的逸出字元、控制字元） | 檢查字串的逸出方式；常見的合法逸出序列為 `\" \\ \/ \b \f \n \r \t \uXXXX` |
| `Invalid token 'End'` 或解析提前結束 | JSON 提前被截斷——括號／引號未閉合 | 在編輯器中補上缺少的 `{` `}` `[` `]` `"` |

例外訊息範本的定義如下，其中大括號內的內容是來自語彙分析器（Lexer）階段的 `ParserToken` 列舉值：

```csharp
// Runtime/JsonException.cs
internal JsonException(ParserToken token) :
    base(string.Format(
             "Invalid token '{0}' in input string", token))
{
}
```

來源：[JsonException.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonException.cs#L51-L55)

## 修正步驟

### 1. 找出錯誤字元的位置

將例外中的語彙基元（單一字元的情況）與原始 JSON 字串進行比對，以定位第一個非法字元。LitJSON 的 `JsonReader` 會由左至右掃描，遇到第一個無法辨識的字元時就會擲出錯誤。

```csharp
// Runtime/JsonReader.cs
TableAddCol(parse_table, ParserToken.ArrayPrime, '[',
            (int)ParserToken.Value,
            (int)ParserToken.ValueRest,
            ']');
```

來源：[JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs#L266-L274)

### 2. 修正常見的非法字元

以下寫法在標準 JSON 中無效，LitJSON 會直接擲出 `Invalid token`：

- 單引號字串 `'foo'` —— 必須改為雙引號 `"foo"`
- 註解 `// xxx` 或 `/* xxx */` —— JSON 不支援註解，需要移除
- 尾端逗號 `{ "a": 1, }` —— 逗號後面必須接著另一個元素
- 帕斯卡命名法（PascalCase）的布林值／null `True` / `False` / `Null` —— 必須是 `true` / `false` / `null`
- 未逸出的控制字元或裸露的換行字元 —— 字串內的換行需要以 `\n` 逸出

### 3. 修正常見的非法數字

由 `ParserToken.Number` 觸發的 `Invalid token` 通常是數字格式問題。合法的數字必須為十進位，並可選擇性地加上小數點與指數：

- 合法：`0`、`-1`、`3.14`、`-2.5e10`、`1.0E+3`
- 非法：`1.`（小數點後沒有數字）、`01`（前置零）、`0x1A`（十六進位）、`NaN`、`Infinity`、`+1`（多餘的正負號）、`1,000`（千分位分隔逗號）

### 4. 以最小可重現範例進行驗證

修正後，請使用最小的可執行程式碼片段，確認您的 JSON 可以被正確解析：

```csharp
using GameFrameX.LitJSON.Runtime;

string json = "{\"name\":\"litjson\",\"v\":1}";
JsonData data = JsonMapper.ToObject(json);
Debug.Log(data["name"]); // 輸出：litjson
Debug.Log(data["v"]);    // 輸出：1
```

如果仍出現 `Invalid token`，請將例外訊息中的語彙基元值，以及原始字串的片段（包含錯誤位置前後幾個字元）提供給上游資料來源提供者。

## 驗證

1. 在 Unity 編輯器的主控台中執行修正後的 JSON 解析程式碼，確認沒有擲出 `JsonException`。
2. 使用線上 JSON 驗證工具（例如 jsonlint.com）驗證輸入字串，並取得「Valid JSON」的結果。
3. 如果 JSON 來自網路或外部檔案，請加上 try/catch 並印出 `e.Message`，以協助定位確切的錯誤位置：

```csharp
try
{
    var data = JsonMapper.ToObject(rawJson);
}
catch (JsonException e)
{
    Debug.LogError($"Parsing failed: {e.Message}");
}
```
