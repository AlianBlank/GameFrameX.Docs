# 빠른 시작: 첫 번째 상태 머신

이 페이지의 단계를 따르면 5분 이내에 GameFrameX FSM의 최소 폐루프를 실행할 수 있습니다: 상태 정의 → FSM 생성 → 상태 시작 → 상태 내에서 전환 및 데이터 읽기/쓰기.

## 사전 조건

- Unity 2019.4 이상
- `Packages/manifest.json`을 통해 `com.gameframex.unity.fsm` 1.1.1 설치 완료 (또는 Git URL을 사용하여 저장소에 직접 연결)

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.fsm": "1.1.1"
  }
}
```

설치 후, `FsmComponent`는 `[GameFrameXAutoComponent(-6000)]`로 `GameFramework` 시작 객체에 자동으로 부착됩니다.

## 작업 단계

### 1. 상태 클래스 정의

`FsmState<T>`를 상속합니다(`T`은 FSM 소유자 타입). 필요에 따라 6개의 생명주기 훅을 재정의합니다. 상태 내에서 `ChangeState<TNext>(fsm)`을 통해 전환을 트리거합니다.

```csharp
using GameFrameX.Fsm;
using UnityEngine;

public class Player { /* 플레이어 비즈니스 필드 */ }

public class IdleState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        Debug.Log("Idle 진입");
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        if (Input.GetKeyDown(KeyCode.W))
        {
            ChangeState<MoveState>(fsm);
        }
    }

    protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
}

public class MoveState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        fsm.SetData("Speed", 5.0f);
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds) { }
}
```

### 2. FSM 생성 및 시작

`FsmComponent`를 통해 생성하며, 생성 시 모든 초기 상태 인스턴스를 한 번에 전달하고, 마지막에 `Start<TState>()`를 사용하여 진입 상태를 선택합니다.

```csharp
using GameFrameX;
using GameFrameX.Fsm;
using GameFrameX.Fsm.Runtime;

var fsmComponent = GameEntry.GetComponent<FsmComponent>();
IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
fsm.Start<IdleState>();
```

`CreateFsm`은 [FsmManager](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs)가 객체 풀을 통해 `Fsm<T>` 인스턴스를 할당하고 states 딕셔너리를 채웁니다. `Start<T>`는 현재 상태를 설정하고 `OnEnter`를 트리거합니다.

### 3. 상태 간 전환 및 데이터 읽기/쓰기

상태 내의 `IFsm<T> fsm` 매개변수는 전환을 트리거할 뿐만 아니라 상태 간 키-값 데이터 저장소도 제공합니다(`Variable` 내부에서 통합 박싱).

```csharp
// 모든 상태의 OnEnter / OnUpdate / OnLeave 내에서
fsm.SetData("Health", 100);
int hp = fsm.GetData<int>("Health");

if (fsm.HasData("Health"))
{
    fsm.RemoveData("Health");
}
```

상태 전환 시 `ChangeState<TNext>(fsm)`을 호출하면, 프레임워크는 자동으로 이전 상태의 `OnLeave(..., isShutdown: false)`를 먼저 호출한 다음 새 상태의 `OnEnter`를 호출합니다.

### 4. FSM 파괴

더 이상 필요하지 않을 때 `DestroyFsm`을 호출하면, 프레임워크는 `OnDestroy`를 트리거하고 `FsmManager`의 객체 풀로 회수합니다.

```csharp
fsmComponent.DestroyFsm(fsm);
```

## 일반적인 변형

| 시나리오 | 작성 방법 |
|------|------|
| 동일한 소유자 타입에 대해 여러 FSM 세트가 공존해야 함 | `CreateFsm(owner, name, new IdleState(), ...)` 오버로드를 사용하여 이름 전달 |
| 런타임에 상태 추가 | `fsm.AddState(new JumpState())` |
| 런타임에 현재가 아닌 상태 제거 | `fsm.RemoveState<IdleState>()` |
| 상태 집합을 유지하고 데이터를 비우고 초기 상태로 돌아가기 | `fsm.Reset()`, 그런 다음 `Start<T>()`로 다시 시작 |
| 물리 프레임 구동 | `OnFixedUpdate`를 재정의하면, `FsmComponent.FixedUpdate`가 자동으로 디스패치 |
| 빠른 액세스 진입점 (com.gameframex.unity.entry 필요) | `GameEntry.GetComponent<FsmComponent>()` 대신 `GameApp.Fsm.CreateFsm(...)` |

## 일반적인 오류

- **`FsmComponent`를 찾을 수 없음**: Unity 씬에 `GameFramework` 시작 프리팹이 부착되지 않아 컴포넌트가 자동으로 인스턴스화되지 않음.
- **`Start<T>`에서 예외 발생**: 전달된 상태 타입이 생성 시 등록되지 않음. `CreateFsm`의 매개변수 목록 또는 `AddState`에 먼저 추가해야 함.
- **데이터가 저장되지 않음**: `SetData`는 내부적으로 `Variable`로 박싱하므로, 값 타입을 읽을 때 동일한 제네릭 매개변수 `GetData<int>("Health")`를 사용해야 함.
- **상태 전환이 적용되지 않음**: `ChangeState<TNext>(fsm)`은 상태 훅 내에서 호출되어야 하며, `TNext`는 이미 등록되어 있어야 함.
- **동일한 owner의 상태 머신이 파괴된 후 다시 `Start`**: 먼저 `IsDestroyed == false`인지 확인하고, 그렇지 않으면 `CreateFsm`을 다시 호출해야 함.

## 배경 (선택 사항)

`Fsm<T>`는 내부적으로 `Dictionary<Type, FsmState<T>>`를 사용하여 상태를 저장하고, `m_CurrentStateTime`은 `Update`에서 누적됩니다. 디버거 또는 사용자 정의 Inspector에서 `CurrentStateName` / `CurrentStateTime`을 읽을 수 있습니다. 모든 FSM은 `FsmManager`에 의해 중앙 집중식으로 관리되며, `FsmComponent`를 통해 상위 레이어에 노출됩니다.
