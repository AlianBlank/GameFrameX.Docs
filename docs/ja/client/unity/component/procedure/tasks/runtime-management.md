# ランタイム時にフローを照会・切り替えする方法

ゲームのランタイム中に `IProcedureManager` インターフェースを通じて現在のフローを照会し、フローの存在を確認し、指定されたフローインスタンスを取得したり、異なるフロー間で切り替えたりします。

## 前提条件

- `GameFrameworkEntry.GetModule<IProcedureManager>()` を通じてフローマネージャーのインスタンスを取得済みであること。
- フローマネージャーが `Initialize(IFsmManager, params ProcedureBase[])` の呼び出しを完了しており、少なくとも1つのフローが登録されていること。

## 操作手順

### 1. フローマネージャーを取得する

```csharp
IProcedureManager procedureManager = GameFrameworkEntry.GetModule<IProcedureManager>();
```

ソースコード:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L34-L119)

### 2. 現在のフローを照会する

`CurrentProcedure` プロパティを読み取ることで、現在実行中のフローインスタンスを取得できます。`CurrentProcedureTime` は現在のフローの経過時間(秒)です。

```csharp
ProcedureBase current = procedureManager.CurrentProcedure;
float elapsed = procedureManager.CurrentProcedureTime;
Debug.Log($"現在のフロー:{current.GetType().Name}、経過時間 {elapsed:F2}s");
```

初期化されていない場合、`GameFrameworkException("You must initialize procedure first.")` がスローされます。

ソースコード:[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L67-L96)

### 3. フローの存在確認 / フローインスタンス取得

`HasProcedure` と `GetProcedure` を通じて、マネージャーに登録されている特定のフローを照会できます。

```csharp
if (procedureManager.HasProcedure<MyBattleProcedure>())
{
    MyBattleProcedure proc = (MyBattleProcedure)procedureManager.GetProcedure<MyBattleProcedure>();
    // proc を使用
}
```

`HasProcedure`、`GetProcedure` はジェネリック版と `Type` 版の2つのオーバーロードを提供します。

ソースコード:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L78-L105)、[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L178-L235)

### 4. 指定フローへの切り替え

`StartProcedure` を呼び出すことで対象フローに入り、フレームワークは自動的に前のフローの `OnLeave` と対象フローの `OnEnter` をトリガーします。

```csharp
procedureManager.StartProcedure<MyBattleProcedure>();
```

型オブジェクトを通じて切り替えたい場合は、`StartProcedure(Type)` オーバーロードを使用します。

ソースコード:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L62-L73)、[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L147-L171)

### 5. フローコレクションの再登録(オプション)

すべてのフローを置き換えたい場合は、まず `DestroyProcedures()` でクリアし、その後 `ReinitializeProcedures(...)` で新しいフロー配列を使用して再構築します。

```csharp
procedureManager.DestroyProcedures();
procedureManager.ReinitializeProcedures(new MyBootProcedure(),
                                        new MyLoginProcedure(),
                                        new MyBattleProcedure());
```

ソースコード:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L107-L118)

## よく使う API 早見表

| 操作 | メソッド / プロパティ | 備考 |
|------|------------|------|
| 現在のフロー | `CurrentProcedure` | 未初期化時は `GameFrameworkException` をスロー |
| 現在のフロー経過時間 | `CurrentProcedureTime` | 単位:秒 |
| 存在確認 | `HasProcedure<T>()` / `HasProcedure(Type)` | 未初期化時は例外をスロー |
| インスタンス取得 | `GetProcedure<T>()` / `GetProcedure(Type)` | `ProcedureBase` を返す |
| フロー切り替え | `StartProcedure<T>()` / `StartProcedure(Type)` | OnLeave/OnEnter をトリガー |
| 破棄 | `DestroyProcedures()` | 登録されているすべてのフローをクリア |
| 再構築 | `ReinitializeProcedures(params ProcedureBase[])` | 新しいコレクションで再初期化 |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `You must initialize procedure first.` | フローマネージャーが `Initialize` を呼び出さずにプロパティやメソッドにアクセスした | まず `Initialize(fsmManager, procedures)` を呼び出して初期化する |
| `Procedures is invalid.` | `Initialize` に空の配列を渡した | 少なくとも1つの `ProcedureBase` インスタンスを渡す |
| 切り替え後にコールバックがない | 対象フローが `Initialize` を通じてマネージャーに登録されていない | `HasProcedure` で確認し、`ReinitializeProcedures` で登録する |

## 背景(オプション)

`ProcedureManager` は内部で `IFsmManager` を通じて `IFsm<IProcedureManager>` ステートマシンを作成し、各フローはそのステートマシンの1つの状態となります。`StartProcedure` は実際には基盤となるステートマシンの `Start<T>()` を呼び出すため、フロー切り替えのコールバック(`OnEnter` / `OnLeave` / `OnUpdate`)は FSM によってトリガーされます。
