# 如何使用表达式树/路径拼接扩展

`ExpressionExtension` 提供一组面向 `Expression<Func<T, bool>>` 的链式拼接方法,让你能把多个独立写好的谓词表达式安全地组合成一个新的表达式,无需手写 `Expression.AndAlso` / `ParameterExpression` 等样板代码,常用于查询条件动态拼接、过滤管线等场景。

## 前置条件

- 项目引用 `GameFrameX.Foundation.Extensions`。
- 文件顶部 `using System.Linq.Expressions;` 与 `using GameFrameX.Foundation.Extensions;`。
- 目标框架支持 `Expression<Func<T, bool>>`(标准 .NET 即可)。

## 操作步骤

### 1. 用 `And` 拼接两个条件

当左右两侧表达式都需要成立时使用 `And`(内部使用 `Expression.AndAlso`,支持短路求值)。

```csharp
using System.Linq.Expressions;
using GameFrameX.Foundation.Extensions;

Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.And(expr2);

bool ok1 = combined.Compile()("testing"); // true
bool ok2 = combined.Compile()("test");    // false
```

Source: [ExpressionExtension.cs#L57-L67](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L57-L67)

### 2. 用 `Or` 拼接两个条件

当任一表达式成立即可时使用 `Or`(内部使用 `Expression.OrElse`,支持短路求值)。

```csharp
Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.Or(expr2);
bool ok = combined.Compile()("test"); // true: 命中 StartsWith("test")
```

Source: [ExpressionExtension.cs#L114-L125](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L114-L125)

### 3. 用 `AndIf` / `OrIf` 按开关拼接

需要一个布尔开关决定是否实际参与拼接时,使用条件版本;条件为 `false` 直接返回左侧表达式,不再走访问器与重写逻辑。

```csharp
Expression<Func<string, bool>> left  = s => s.Length > 5;
Expression<Func<string, bool>> right = s => s.StartsWith("test");

bool enableFilter = true;
var withFilter = left.AndIf(() => enableFilter, right);

enableFilter = false;
var withoutFilter = left.AndIf(() => enableFilter, right); // 等价于 left
```

Source: [ExpressionExtension.cs#L83-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L83-L100)

### 4. 用 `Not` 取反

```csharp
Expression<Func<int, bool>> expr = x => x > 5;
var neg = expr.Not(); // 等价于 x => !(x > 5),即 x <= 5
```

Source: [ExpressionExtension.cs#L171-L178](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L171-L178)

### 5. 多条件链式拼接

由于返回值仍是 `Expression<Func<T, bool>>`,可以连续调用:

```csharp
Expression<Func<string, bool>> baseExpr = s => s != null;
var query = baseExpr
    .And(s => s.Length > 0)
    .And(s => s.Contains("foo"))
    .OrIf(() => AllowShort, s => s.Length <= 2);
```

## 常见变体

- **谓词字符串 + LINQ 提供程序**:拼接完成后调用 `Compile()` 得到 `Func<T, bool>` 直接筛选;若与 EF Core 等 ORM 配合,直接传 `combined` 给 `Where(...)`,它会被翻译为 SQL。
- **空集合短路**:可在外层用 `IEnumerable.Any()` 等方式先判空,再调用 `And` / `Or`。
- **多参数 Lambda**:`CustomExpressionVisitor` 对多参数 Lambda 仅替换第一个参数,其余保持原样。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `ArgumentNullException`(参数名 `leftExpression` / `rightExpression` / `condition` / `expr`) | 任一表达式或条件委托为 `null` | 调用前对表达式判空,或在外层提供一个永远返回 `true` 的条件委托 |
| 拼接后编译失败,报"参数不匹配" | 传入的左右表达式类型不一致(如 `Func<string,bool>` 与 `Func<int,bool>`) | 确保两个表达式使用同一泛型参数 `T` |
| 拼接结果没有短路行为 | 误以为本扩展用的是 `And`/`Or` | 本扩展 `And`/`Or` 内部使用 `AndAlso`/`OrElse`,天然短路,无需额外处理 |
| 多参数 Lambda 拼接后行为异常 | 仅第一个参数被替换,其余保留 | 把谓词写成只接收一个参数的 Lambda,或自行重写表达式 |

## 背景(可选)

`And` / `Or` / `AndIf` / `OrIf` 内部都通过内部类 `CustomExpressionVisitor`(继承自 `ExpressionVisitor`)把左右两个表达式各自的 `ParameterExpression` 替换成新建的统一参数,再用 `Expression.Lambda` 重新组装,这样既能保留左右子树的原始结构,又能保证新表达式只有一个参数,便于链式拼接与跨 ORM 翻译。
