# 逾時與並行連線數設定方式

在 GameFrameX.Web 中，逾時 `Timeout` 可透過 Inspector 序列化欄位或程式碼設定(預設值 5 秒)，並行連線數 `MaxConnectionPerServer` 僅能透過程式碼在 `IWebManager` 上設定(預設值 8)。此值會分別限制一般(JSON)請求與二進位請求兩個排程通道中同時處理的數量。

## 前置條件

- 場景中必須已新增 `WebComponent` 元件(選單 `GameFrameX/Web`)。
- 如需在程式碼中存取管理器，請參考命名空間 `GameFrameX.Web.Runtime` 與 `GameFrameX.Runtime`。

## 設定項目快速參考

| 設定項目 | 類型 | 預設值 | 套用位置 | 說明 |
|--------|------|--------|----------|------|
| `WebComponent.m_Timeout` | `float`(秒) | `5f` | Inspector 序列化欄位 | 元件初始化時寫入管理器 |
| `WebComponent.Timeout` | `float`(秒) | 代理管理器 | 屬性 | 同時回寫至序列化欄位 |
| `WebManager.Timeout` | `float`(秒) | `5f` | 管理器屬性 | 設定時 `RequestTimeout` 也會同步更新 |
| `WebManager.RequestTimeout` | `TimeSpan` | 由 `Timeout` 衍生 | 管理器屬性 | 實際傳遞給請求物件的逾時 |
| `WebManager.MaxConnectionPerServer` | `int` | `8` | 管理器屬性 | 一般通道與二進位通道各自的並行處理上限 |

## 操作步驟

### 1. 在 Inspector 中設定逾時

選取已新增 `WebComponent` 的 GameObject 後，在 Inspector 中修改**逾時**欄位(單位：秒，預設值 5):

```csharp
[SerializeField] [Tooltip("逾時。單位:秒")]
private float m_Timeout = 5f;
```

來源：[WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L59-L60)

在元件的 `Awake()` 時，此值會寫入管理器：

```csharp
m_WebManager = GameFrameworkEntry.GetModule<IWebManager>();
if (m_WebManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebManager.Timeout = m_Timeout;
```

來源：[WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L88)

### 2. 在程式碼中於執行階段調整逾時

`WebComponent.Timeout` 會直接代理至管理器，並同時將值回寫至序列化欄位：

```csharp
public float Timeout
{
    get { return m_WebManager.Timeout; }
    set { m_WebManager.Timeout = m_Timeout = value; }
}
```

來源：[WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L66-L70)

使用範例：

```csharp
// 於元件 Awake 之後呼叫,例如 Start()
webComponent.Timeout = 15f; // 將全域逾時變更為 15 秒
```

### 3. 在程式碼中設定並行連線數

`MaxConnectionPerServer` 僅存在於 `WebManager` / `IWebManager`,並未暴露於 `WebComponent`,因此必須透過程式碼修改：

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// 取得或設定逾時(秒)
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>
/// 取得或設定每個伺服器的最大連線數
/// </summary>
public int MaxConnectionPerServer { get; set; }
```

來源：[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L42-L70)

使用範例(與在 `WebComponent.Awake` 中取得模組的方式相同)：

```csharp
GameFrameworkEntry.GetModule<IWebManager>().MaxConnectionPerServer = 4; // 每個通道同時最多 4 個請求
```

來源：[WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L81)

## 常見變化

**分別控制兩個通道的並行處理**：一般(JSON)請求與二進位請求共用相同的 `MaxConnectionPerServer` 值，但各自獨立計數 — 排程進入點分別為 `m_SendingNormalList`(一般)與 `m_SendingBinaryList`(二進位):

```csharp
// 一般請求通道:在 Update 中依上限從等待佇列取出工作
if (m_SendingNormalList.Count < MaxConnectionPerServer)
{
    if (m_WaitingNormalQueue.Count > 0)
    {
        var webJsonData = m_WaitingNormalQueue.Dequeue();
        // ...啟動請求並加入 m_SendingNormalList
    }
}
```

來源：[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L75-L101)

```csharp
// 二進位請求通道:相同的上限判斷
if (m_SendingBinaryList.Count < MaxConnectionPerServer)
```

來源：[WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L43-L43)

**在不同後端傳遞逾時的方式**:`RequestTimeout` 分別在兩條路徑中以秒和毫秒為單位設定至下層請求：

```csharp
unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;   // UnityWebRequest 路徑(秒)
```

來源：[WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L96-L97)

```csharp
request.Timeout = (int)RequestTimeout.TotalMilliseconds; // 設定請求逾時(HttpWebRequest 路徑,毫秒)
```

來源：[WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L130-L132)

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 在 Inspector 中變更逾時但未生效 | `Awake()` 之後程式碼以 `WebComponent.Timeout` 或 `m_WebManager.Timeout` 再次覆寫了值 | 統一於同一處設定；若要在執行階段變更值，請於 `Start()` 或之後進行 |
| 想在 Inspector 中變更並行連線數但找不到欄位 | `MaxConnectionPerServer` 未序列化在 `WebComponent` 上 | 透過 `GameFrameworkEntry.GetModule<IWebManager>()` 以程式碼設定 |
| 設定 `Timeout = 0.5f` 後請求遲遲不會逾時 | 傳遞至 UnityWebRequest 時被 `(int)RequestTimeout.TotalSeconds` 截斷，低於 1 秒時會變成 `0` | 逾時值請設定為至少 `1f` 以上或更大的整數秒 |
| 將 `MaxConnectionPerServer` 誤解為全域總並行處理數 | 一般/二進位兩個通道各自以該值獨立判斷 | 評估並行處理上限時應按通道分別計算 |

## 背景(選用)

`Timeout` 的 setter 會同時衍生出 `RequestTimeout = TimeSpan.FromSeconds(value)`,當請求實際建立時，此值會寫入下層的 `UnityWebRequest.timeout`(秒)或 `HttpWebRequest.Timeout`(毫秒)。因此，逾時的修改僅會影響之後新啟動的請求。在並行處理方面，請求會先進入等待佇列，`WebManager.Update` 會每幀檢查 `m_SendingNormalList.Count < MaxConnectionPerServer`,只有在條件滿足時才會從佇列取出並啟動請求，超出的部分則繼續等待。
