# クライアントセッション（Session / 接続切断）の管理

GameFrameX は `Session` と `SessionManager` を通じて各ネットワーク接続のセッション状態を維持し、ログイン後のロール紐付け、先ログインによるキック、接続切断時のクリーンアップなどの動作を扱います。このページを読み終えると、ログイン、キック、オフラインなどのシナリオで Session を正しく読み書きし、`EventId.SessionRemove` イベントを受け取ってログアウト処理を行えるようになります。

## 前提条件

- `GameFrameX.Apps.Common.Session` 名前空間が導入済みであること（コードは [Session.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs) および [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs) にあります）。
- フレームワークの `AppStartUp` でプロトコルが接続され、`IAppSession` から接続情報を取得できること。
- プレイヤー Actor が `ActorManager` 経由で登録済みであること（登録されていない場合 `GetByRoleId` は null を返します）。

## 操作手順

### 1. ハンドシェイク／ログイン成功時に Session を作成して登録する

ログイン成功時に `AppStartUp` が `SessionManager.Add` を呼び出し、現在の接続をグローバル辞書に登録します。内部では `SessionId` がチャネルデータに書き込まれ、プロトコル層のコールバック時に ID で逆引きできるようになります。

```csharp
using GameFrameX.Apps.Common.Session;

// netWorkChannel はプロトコル層の INetWorkChannel から取得
var session = new Session(sessionId, netWorkChannel);
SessionManager.Add(session);
```

Source: [SessionManager.cs#L186-L191](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L186-L191)

### 2. ログイン成功後にロール ID と署名を紐付ける

`UpdateSession` を使用して `roleId` と `sign` を現在の接続に書き込みます。その `roleId` がすでに別のデバイスでログイン済みの場合、フレームワークは古いセッションに「アカウントが他のデバイスでログインされました」という通知を送信し、キックします。

```csharp
SessionManager.UpdateSession(sessionId, roleId, sign);
```

内部動作（ソースコードより抜粋）：

1. `GetByRoleId(roleId)` で古いセッションを検索。
2. `RespPrompt { Type = 5, Content = "你的账号已在其他设备上登陆" }` を構築し、`oldSession.WriteAsync` で送信。
3. `oldSession.WorkChannel.ClearData()` と `Close()` を呼び出し、`Remove(oldSession.SessionId)` を実行。
4. 現在のセッションに対して `SetPlayerId(roleId)` / `SetSign(sign)` を呼び出し。

Source: [SessionManager.cs#L200-L229](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L200-L229)

### 3. Session を通じてクライアントにメッセージを返信する

`Session.WriteAsync` は内部でネットワークチャネルへの送信を委譲し、エラーコードを添付できます。

```csharp
var session = SessionManager.Get(sessionId);
if (session != null)
{
    await session.WriteAsync(messageObject, errorCode: 0);
}
```

Source: [Session.cs#L99-L105](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs#L99-L105)

### 4. 接続切断（手動キック／ネットワーク切断）を監視する

接続切断は `AppStartUp` のフックで一元的に処理されます。ソースコード例（抜粋）：

```csharp
protected override async ValueTask OnDisconnected(IAppSession appSession, CloseEventArgs disconnectEventArgs)
{
    var session = SessionManager.Get(appSession.Id);
    if (session != null)
    {
        var roomAgent = await ActorManager.GetComponentAgent<RoomComponentAgent>();
        await roomAgent.MarkPlayerDisconnected(session.PlayerId);
    }
}
```

`RoomComponentAgent` には 120 秒のオフライン猶予（`DisconnectedPlayerAutoLeaveSeconds`）が設定されており、タイムアウト後に実際に部屋からキックされます。

Source: [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76)、[RoomComponentAgent.cs#L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L45)

### 5. SessionRemove イベントに応答してログアウト処理を行う

`SessionManager` は次の 3 つのケースで `EventId.SessionRemove`（値 = 1000）を発行します：

- `Remove(sessionId)`
- `KickOffLineByUserId(roleId)`
- `RemoveAll()`
- `UpdateSession` で先ログイン時に古いセッションを除去する際

フレームワークは `[Event(EventId.SessionRemove)]` 属性を使ってリスナーをプレイヤー Agent にバインドし、デフォルト実装は `agent.OnLogout()` を呼び出します。ビジネスロジックに応じて拡張できます：

```csharp
[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

Source: [SessionRemoveEventListener.cs#L39-L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L39-L45)、[EventId.cs#L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Event/EventId.cs#L41)

## よくあるバリエーション

### ロール ID を指定して手動キックする

```csharp
SessionManager.KickOffLineByUserId(roleId);
```

内部で `SessionRemove` が発行され、`OnLogout` がトリガーされます。出典：[SessionManager.cs#L79-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L79-L89)。

### シャットダウン時にすべてのセッションをクリアする

```csharp
await SessionManager.RemoveAll();
```

一つずつ `SessionRemove` を発行した後、辞書を `Clear()` します。出典：[SessionManager.cs#L158-L170](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L158-L170)。

### オンラインプレイヤーをページネーションで照会する

`GetPageList(pageSize, pageIndex)` は `ActorManager` に存在しない Actor を除外し、実際にオンラインのプレイヤーのみを返します。出典：[SessionManager.cs#L65-L73](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L65-L73)。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `GetByRoleId(roleId)` が常に null を返す | プレイヤー Actor が未登録、または `SessionMap` が非同期でクリアされている | ログイン処理で `ActorManager` にプレイヤーが登録されていることを確認し、Session のライフサイクル内でアクセスするようにする |
| 先ログイン通知送信後、古い接続が即座に閉じない | `WriteAsync` のみで `WorkChannel.Close()` を呼び出していない | フレームワーク付属の `SessionManager.UpdateSession` フローを使用し、古いセッションを手動で管理しない |
| オフラインのプレイヤーが自動的に退室しない | `OnDisconnected` で `MarkPlayerDisconnected` を呼び出していない | [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76) のテンプレートを参考に、切断イベントをルーム Agent に転送する |

## 背景（オプション）

`SessionManager` は `ConcurrentDictionary<string, Session>` をグローバルストレージとして使用し、各接続に 1 つの `SessionId` を割り当てます。`Session` は内部に `INetWorkChannel` を保持し、データの送受信に使用します。`UpdateSession` の「先に削除してから Disconnected を待つ」というコメント（[L217](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L217)）は、先ログイン時に切断コールバックによるクリーンアップのみに頼ると遅延が発生するため、古いエントリを同期的に `Remove` して状態の一貫性を保証していることを示しています。
