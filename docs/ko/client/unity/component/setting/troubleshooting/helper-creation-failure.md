# Helper 생성 실패 시 대처법

`SettingComponent`가 `Awake` 단계에서 `Helper.CreateHelper` 호출에 실패하면, Unity 콘솔에 `Can not create setting helper.` 오류 로그가 출력되고, 이후 모든 설정 읽기/쓰기는 Helper가 부착되지 않아 동작하지 않습니다. 이 페이지에서는 일반적인 원인과 수정 단계를 안내합니다.

## 빠른 진단

| 증상 / 로그 | 원인 | 해결 방법 |
|---|---|---|
| `Can not create setting helper.` 이면서 `m_CustomSettingHelper == null` | `m_SettingHelperTypeName` 철자 오류, 네임스페이스 불일치, 또는 Helper 타입이 포함된 어셈블리가 IL2CPP/Managed Stripping으로 제거됨 | "커스텀 타입명 철자 오류" 섹션에서 정규화된 이름(FQDN)을 확인하고, 내장 `PlayerPrefsSettingHelper`인 경우 "코드 스트리핑으로 타입 손실" 섹션 참조 |
| `Can not create setting helper.` 이면서 `m_CustomSettingHelper != null` | 커스텀 Helper 클래스가 `SettingHelperBase`를 상속하지 않거나, `MonoBehaviour`가 아니거나, 매개변수 없는 생성자가 없음 | "커스텀 Helper 클래스가 잘못됨" 섹션에 따라 상속과 네임스페이스 수정 |
| `m_CustomSettingHelper != null` 인데도 해당 오류가 출력됨 | 커스텀 Helper 필드에 비활성화되었거나 손실된 스크립트(스크립트 누락 또는 GUID 무효화)가 드래그됨 | 유효한 커스텀 Helper 에셋을 다시 부착하거나, Inspector에서 `Custom Setting Helper`를 비워 둠 |
| 콘솔에 `Can not create setting helper.`는 없지만 이후 `Save/Load` 동작이 비정상 | `Awake` 완료까지 기다리지 않았거나, `SettingComponent`가 씬에 없음 | 씬에 `SettingComponent`가 존재하는지 확인하고, 같은 프레임에서 파괴되지 않았는지 확인 |

## 수정 단계

### 1. 커스텀 타입명 철자 오류 또는 타입을 찾을 수 없음

`SettingComponent`는 기본적으로 정규화된 이름 문자열 `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`로 Helper를 리플렉션 생성합니다. 문자열이 잘못되면 `Helper.CreateHelper`는 `null`을 반환합니다.

씬에서 `SettingComponent`가 부착된 GameObject를 열고, Inspector의 `Setting Helper Type Name` 필드에 올바른 정규화된 이름을 입력합니다. 기본값은 다음과 같습니다:

```csharp
[SerializeField] private string m_SettingHelperTypeName = "GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper";
```

Source: [SettingComponent.cs#L52](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52)

네임스페이스는 `using GameFrameX.Setting.Runtime;`과 일치해야 합니다. 자체적으로 Helper 서브클래스를 작성한 경우, 문자열을 `네_네임스페이스.네_Helper클래스명`으로 변경해야 합니다.

### 2. 커스텀 Helper 클래스가 잘못됨

`m_CustomSettingHelper`로 Helper 인스턴스를 직접 지정한 경우, 해당 클래스는 다음 조건을 만족해야 합니다:

- `SettingHelperBase`를 상속해야 함 (추상 베이스 클래스 정의는 [SettingHelperBase.cs#L43](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L43) 참조).
- `MonoBehaviour` 파생 클래스여야 함 (`Helper.CreateHelper`가 `gameObject.AddComponent<T>()`를 호출하기 때문).
- 클래스에 `[UnityEngine.Scripting.Preserve]`가 지정되어 있거나 실제로 참조되어야 함, 그렇지 않으면 IL2CPP 빌드에서 제거됨.

최소 유효 예시:

```csharp
using GameFrameX.Setting.Runtime;
using UnityEngine;

namespace MyGame.Settings
{
    [UnityEngine.Scripting.Preserve]
    public sealed class MySettingHelper : SettingHelperBase
    {
        public override int Count => 0;
        public override bool Load() => true;
        public override bool Save() => true;
        public override string[] GetAllSettingNames() => System.Array.Empty<string>();
        public override void GetAllSettingNames(System.Collections.Generic.List<string> results) { }
        public override bool HasSetting(string settingName) => false;
        public override bool RemoveSetting(string settingName) => false;
        public override bool GetBool(string settingName, bool defaultValue) => defaultValue;
        // 나머지 Get/Set 오버로드는 생략, PlayerPrefsSettingHelper를 참고하세요
    }
}
```

커스텀 Helper를 만든 후, Inspector에서 프리팹을 `Custom Setting Helper` 필드로 드래그하여 `SettingComponent`가 우선적으로 사용하도록 합니다:

```csharp
[SerializeField] private SettingHelperBase m_CustomSettingHelper = null;
```

Source: [SettingComponent.cs#L54](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L54)

### 3. 코드 스트리핑으로 인한 타입 손실

`m_SettingHelperTypeName`이 완전히 올바르게 작성되었더라도, 패키징 시 `Managed Stripping Level > Low` 또는 IL2CPP 링커가 활성화되어 있으면, 프레임워크의 Helper 클래스가 정적 분석에서 참조되지 않아 제거될 수 있습니다.

저장소에는 이미 빈 `GameFrameXSettingCroppingHelper`가 제공되어 있으며, 이는 릴리스 빌드에서 모든 Helper 타입 참조를 "점유"하기 위한 용도입니다:

```csharp
[UnityEngine.Scripting.Preserve]
public class GameFrameXSettingCroppingHelper : MonoBehaviour
{
    [UnityEngine.Scripting.Preserve]
    private void Awake()
    {
        _ = typeof(DefaultSetting);
        _ = typeof(DefaultSettingHelper);
        _ = typeof(DefaultSettingSerializer);
        _ = typeof(PlayerPrefsSettingHelper);
        _ = typeof(SettingComponent);
        _ = typeof(SettingHelperBase);
        _ = typeof(ISettingHelper);
    }
}
```

Source: [GameFrameXSettingCroppingHelper.cs#L41-L58](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/GameFrameXSettingCroppingHelper.cs#L41-L58)

`SettingComponent`는 자체적으로 `[RequireComponent(typeof(GameFrameXSettingCroppingHelper))]`를 가지고 있으므로, `SettingComponent`를 추가할 때 이 Helper 노드가 자동으로 생성됩니다. **이 자식 오브젝트를 수동으로 삭제하지 마십시오**, 그렇지 않으면 `Awake`의 `typeof(...)` 참조 체인이 끊어져 타입이 여전히 제거될 수 있습니다.

새로운 커스텀 Helper 서브클래스를 추가한 경우, 반드시 이 스트리핑 목록에도 `_ = typeof(내_Helper_클래스);`를 한 줄 추가하거나, Project Settings → Player → Other Settings에서 `Managed Stripping Level`을 `Low` 또는 끄기로 설정해야 합니다.

### 4. Awake 이전에 Setting에 접근

`SettingComponent.Awake`에서 Helper를 생성하고 `m_SettingManager.SetSettingHelper(settingHelper)`를 호출한 다음, `Start`에서 `m_SettingManager.Load()`를 실행합니다. 다른 스크립트의 `Awake`에서 먼저 `GameFramework.Setting.*` API를 호출하면, 이 시점에는 Helper가 아직 설정되지 않아 "Helper 생성 실패" 또는 읽기/쓰기 비정상으로 나타납니다.

해결 방법: Setting에 대한 모든 접근을 `Start` 이후로 옮기거나, 자체 스크립트에서 `MonoBehaviour.Start` → `yield return null` → 설정 읽기 순서로 진행합니다.

## 검증

위 단계에 따라 수정한 후, 다음 세 가지 항목을 확인합니다:

1. 씬을 시작하고 콘솔에 더 이상 `Can not create setting helper.` 및 `Setting manager is invalid.`가 출력되지 않는지 확인합니다.
2. Hierarchy에서 `SettingComponent`가 부착된 GameObject를 선택하면, `SettingHelper`라는 이름의 자식 오브젝트(`settingHelper.name = "SettingHelper";`로 생성됨, [SettingComponent.cs#L94](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L94) 참조)가 보여야 합니다.
3. `PlayerPrefsSettingHelper_BoolUsesIntStorage` 등 단위 테스트를 실행하여 `SetBool/GetBool/HasSetting`이 모두 영구 저장 백엔드에 도달하는지 검증합니다: [UnitTests.cs#L11-L21](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Tests/UnitTests.cs#L11-L21) 참조.
