# What to Do When WeChat Notifications Are Not Delivered

If you don't receive a WeChat Work (企业微信) bot notification after a build completes, it is usually because `WeChatBotKey` was not passed in, the bot is not enabled, or the build flow never reached the `IsUpdateAssetPackageVersion` success branch. Before fixing, check your actual situation against the diagnostic table below.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Console shows `System.Net.Http.HttpRequestException` or timeout exception | Network cannot access `qyapi.weixin.qq.com`, or proxy is blocking it | Check the build machine's network/proxy, confirm it can access `https://qyapi.weixin.qq.com/cgi-bin/webhook/send` |
| WeChat group receives no messages at all | `-WeChatBotKey` was not passed on the command line, `BuilderOptions.WeChatBotKey` is an empty string | Add `-WeChatBotKey <Bot Key>` to the build command (note the casing) |
| Receives `{"errcode":40001,...}` or `errcode":40014` | Bot Key is incorrect or has expired | Recopy the Webhook Key of the WeChat Work group bot |
| Receives `{"errcode":45009,...}` | Message frequency exceeds the WeChat Work bot limit (20 messages/minute) | Reduce build frequency or split across multiple bots |
| Notification is never invoked, and there is no `Debug.Log(response)` in the log | `IsUpdateAssetPackageVersion` is false, or updating the asset package version failed | Also pass `-IsUpdateAssetPackageVersion true` and ensure `BuilderUpdateAssetPackageVersionHelper.Run` returns `true` |
| Unity Console only prints `Debug.LogException(e)` with no response body | Exception was swallowed by `catch (Exception e)` | See "Fix Steps - View Swallowed Exceptions" below |

## Fix Steps

### 1. Confirm `-WeChatBotKey` Was Passed on the Command Line

`BuilderOptions.WeChatBotKey` defaults to an empty string; it is only assigned when `-WeChatBotKey` is provided on the command line.

```csharp
else if (commandLineArg == "-WeChatBotKey")
{
    if (index + 1 < commandLineArgs.Length)
    {
        _builderOptions.WeChatBotKey = commandLineArgs[index + 1];
    }
}
```

Example build command (Unity command line):

```bash
-gameframex.builder -WeChatBotKey xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx -IsUpdateAssetPackageVersion true
```

For parameter details, see [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L117).

### 2. Confirm the Build Reached the Notification Branch

The notification is only sent after a successful asset version update, so passing `WeChatBotKey` alone is not enough.

```csharp
if (_builderOptions.IsUpdateAssetPackageVersion)
{
    var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
    if (result)
    {
        WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
    }
}
```

Pass both switches together:

```bash
-IsUpdateAssetPackageVersion true -WeChatBotKey <key>
```

If `BuilderUpdateAssetPackageVersionHelper.Run` returns false, the notification will not be triggered—you must first investigate why the version update failed.

### 3. Verify the Webhook Key Is Valid

When the Key is invalid, WeChat Work returns `errcode:40001` (incorrect secret) or `40014` (illegal Key). You can test directly with `curl`:

```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<Your Key>' \
  -H 'Content-Type: application/json' \
  -d '{"msgtype":"text","text":{"content":"hello"}}'
```

If `errcode: 0` is returned, it is working normally; otherwise, re-add the bot in the WeChat Work group to obtain a new Key.

### 4. View Swallowed Exceptions

`WeChatNotifyWorkHelper.Run` catches all exceptions and logs them via `Debug.LogException`. If you only see an exception stack trace, the HTTP call itself failed (network/DNS/timeout).

```csharp
try
{
    var httpResponseMessage = httpClient.PostAsync(url, stringContent).GetAwaiter().GetResult();
    var response = httpResponseMessage.Content.ReadAsStringAsync().GetAwaiter().GetResult();
    Debug.Log(response);
}
catch (Exception e)
{
    Debug.LogException(e);
}
```

Handling guidance: `httpClient.Timeout` is 30 seconds, which can be increased as appropriate in intranet environments; HTTPS certificates are handled by the system trust chain. If the build machine uses a self-signed proxy, additional `HttpClientHandler` configuration is required.

### 5. Confirm the Newtonsoft.Json Reference Exists

The CHANGELOG specifically mentions the issue of `WeChatNotifyWorkHelper` missing a `Newtonsoft.Json` reference. If compilation reports `The type or namespace name 'Newtonsoft' could not be found`, add the `Newtonsoft.Json` reference in `Editor/GameFrameX.Builder.Editor.asmdef` (or the corresponding assembly definition).

```text
* **builder:** Add missing Newtonsoft.Json reference for WeChatNotifyWorkHelper
```

## Verification

1. Run the build again and confirm that the Unity Console prints both `Debug.Log(response)` and a normal JSON response body (containing `errcode: 0`).
2. In the WeChat Work group, you should see a `### Game Asset Version Update` markdown notification containing fields such as time, asset version, and game version.
