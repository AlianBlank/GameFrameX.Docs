# 執行首次建置

按照本頁的步驟，您可以從 Unity 的命令列觸發 GameFrameX Builder 的自動建置，並產生第一個 APK / 資源包。

## 前置條件

- Unity 2019.4 或以上版本
- 已從 `Packages/manifest.json` 安裝 `com.gameframex.unity.builder`（建議 2.0.3 或以上版本）
- 已設定 Player Settings（套件名稱、版本號、圖示等）的 Unity 專案

在 `manifest.json` 中新增 scoped registry 與相依套件的最小設定：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.builder": "2.0.3"
  }
}
```

來源: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L36-L72)

## 操作步驟

1. **開啟 Unity 專案，等待套件匯入完成**。只要 `Packages` 底下有 `com.gameframex.unity.builder` 即可。

2. **確認 `-executeMethod` 的目標方法是否可用**。建置的進入點位於 `GameFrameX.Builder.Editor.Builder`，最常用的兩個方法如下：

   | 方法 | 用途 |
   |------|------|
   | `GameFrameX.Builder.Editor.Builder.BuildApk` | 打包 APK，若 `-IsUploadApk` 已啟用，則上傳至物件儲存 |
   | `GameFrameX.Builder.Editor.Builder.BuildAsset` | 建置 YooAsset 的資源包 |

   來源: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L51-L78)

3. **從命令列觸發建置**。最簡單的命令列形式（以 BuildApk 為例）：

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath /path/to/your/project \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
         -BUILD_NUMBER 1 \
         -logFile /path/to/build.log
   ```

   `-BUILD_NUMBER` 為必填項目。若省略 `-logFile`，Builder 會自動產生日誌檔案的路徑。

4. **確認建置結果**。`-BUILD_NUMBER`、`-AppVersion`、`-BundleId` 等參數會由 `Builder.BuildParamsParse` 解析至 `BuilderOptions`，並驅動整個建置管線。日誌檔案的路徑由 `-logFile` 指定，APK 的輸出位置則由 Unity 的 `BuildPlayerAndroid` 決定。

   來源: [Builder.BuildParamsParse.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs)

## 常見變化

### 僅建置資源包（不產生 APK）

將 `-executeMethod` 替換為 `GameFrameX.Builder.Editor.Builder.BuildAsset`，並指定資源建置用參數：

```bash
Unity -batchmode -nographics -quit \
      -projectPath /path/to/your/project \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
      -BUILD_NUMBER 1 \
      -PackageName DefaultPackage \
      -BuildPipeline BuiltinBuildPipeline \
      -IsIncrementalBuildPackage false
```

資源建置用參數（節錄）：

| 參數 | 預設值 | 說明 |
|------|--------|------|
| `-PackageName` | `DefaultPackage` | 資源包名稱 |
| `-PackageVersion` | 時間戳記 | 若留空，將自動使用時間戳記 |
| `-BuildPipeline` | `BuiltinBuildPipeline` | 可從 `BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` 中選擇 |
| `-BuildinFileCopyOption` | `ClearAndCopyAll` | 內建檔案的複製選項 |
| `-IsIncrementalBuildPackage` | `false` | 是否進行增量建置 |

來源: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L97-L106)

### 在 CI 中新增日誌與上傳

在建置時加入以下旗標，即可在打包完成後將日誌 / APK / 資源包上傳至物件儲存：

```bash
-IsUploadLogFile \
-IsUploadApk \
-IsUploadAsset \
-ObjectStorageKey <key> \
-ObjectStorageSecret <secret> \
-ObjectStorageBucketName <bucket> \
-ObjectStorageEndPoint <endpoint>
```

來源: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L107-L127)

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `executeMethod` 找不到目標方法 | 套件未正確匯入，或命名空間錯誤 | 確認 `Packages` 底下存在 `com.gameframex.unity.builder`，並將方法的完整名稱設為 `GameFrameX.Builder.Editor.Builder.BuildApk` |
| 出現缺少 `-BUILD_NUMBER` 的錯誤 | 未傳入必填參數 | 在命令列中加入 `-BUILD_NUMBER <n>` |
| 上傳至物件儲存失敗 | 未啟用物件儲存的巨集 | 確認專案已安裝對應的物件儲存子套件，且已啟用 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 系列巨集 |

## 背景（可選）

Builder 會在靜態建構階段呼叫 `BuildParamsParse`，將命令列引數解析至 `BuilderOptions`，接著依據 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_*` 巨集選擇物件儲存的實作。`BuildApk` 僅負責啟動 Unity 的套件輸出，並視需要進行上傳。資源建置則透過獨立的 `BuildAsset` 路徑進行。關於 Builder 的完整參數清單，請參閱《命令列引數參考》。
