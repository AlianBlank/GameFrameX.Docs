# How to Customize the UI Form Helper

By inheriting from `UIFormHelperBase` and implementing the three methods of `IUIFormHelper`, you can take over the instantiation of UI assets, the creation of `IUIForm` business objects, and the UI release flow; then have `UIComponent` use your implementation via a class name string or a prefab reference for it to take effect.

## Prerequisites

- Familiar with the basic workflow of the GameFrameX UI subsystem (see the relevant documentation for the overall architecture).
- The project has the `com.gameframex.unity.ui` package installed, and a `UIComponent` is attached in the scene.

## Steps

1. **Implement the `IUIFormHelper` interface or inherit from `UIFormHelperBase`.**

   `UIFormHelperBase` already handles the `MonoBehaviour` lifecycle and the `Scripting.Preserve]` attribute for you; you only need to inherit from it and implement the three abstract methods.

   The interface definition is located at [IUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIFormHelper.cs#L40-L76), and the abstract base class is located at [UIFormHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81).

   ```csharp
   using System;
   using GameFrameX.UI.Runtime;
   using UnityEngine;

   public class MyUIFormHelper : UIFormHelperBase
   {
       public override object InstantiateUIForm(object uiFormAsset)
       {
           // Instantiate the UI asset based on the UI solution you use (FairyGUI / UGUI / other)
           var prefab = uiFormAsset as GameObject;
           if (prefab == null) return null;
           return Instantiate(prefab);
       }

       public override IUIForm CreateUIForm(object uiFormInstance, Type uiFormType, object userData)
       {
           // Bind uiFormInstance to the business logic script corresponding to uiFormType, and return the IUIForm
           var go = uiFormInstance as GameObject;
           var form = go.GetComponent(uiFormType) as IUIForm;
           if (form != null)
           {
               (form as Component).gameObject.SetActive(true);
           }
           return form;
       }

       public override void ReleaseUIForm(object uiFormAsset, object uiFormInstance, object assetHandle,
                                          string uiFormAssetPath, string uiFormAssetName)
       {
           // Destroy the instance and return the asset handle as needed
           var go = uiFormInstance as GameObject;
           if (go != null) Destroy(go);
       }
   }
   ```
   Source: [Runtime/UIFormHelperBase.cs#L42-L81](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)

2. **Make `UIComponent` use your Helper.**

   `UIComponent` supports both "creation via type name reflection" and "directly dragging in a custom Helper prefab". Choose one of the following:

   - **Option A —— Via type name**: Change the `UI Form Helper Type Name` on the `UIComponent` Inspector to your fully qualified class name (including the namespace). The default value is `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`.
   - **Option B —— Via prefab**: Attach your `MyUIFormHelper` to a GameObject, make it a prefab, and drag it into the `Custom UI Form Helper` field of `UIComponent`. At runtime, `Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper)` will prefer this reference.

   ```csharp
   // Logic in Runtime/UIComponent.cs that reads the custom Helper
   UIFormHelperBase uiFormHelper = Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper);
   if (uiFormHelper == null)
   {
       Log.Error("Can not create UI form helper.");
       return;
   }
   uiFormHelper.name = "UIFormHelper";
   transform = uiFormHelper.transform;
   transform.SetParent(this.transform);
   transform.localScale = Vector3.one;
   m_UIManager.SetUIFormHelper(uiFormHelper);
   ```
   Source: [Runtime/UIComponent.cs#L526-L538](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L526-L538)

3. **Ensure the type name namespace matches the ComponentType.**

   At startup, `UIComponent` performs a validation: `m_UIFormHelperTypeName` must start with the namespace corresponding to the current UI system; otherwise, the console will report the error `UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.` and the component will be disabled.

   ```csharp
   if (!m_UIFormHelperTypeName.StartsWithFast(namespaceName))
   {
       Debug.LogError("UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.");
       enabled = false;
       return;
   }
   ```
   Source: [Runtime/UIComponent.cs#L437-L442](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L437-L442)

4. **Manually replace the Helper at runtime (optional).**

   If you want to switch the Helper while the game is running, simply call `BaseUIManager.SetUIFormHelper(IUIFormHelper)`:

   ```csharp
   m_UIManager.SetUIFormHelper(new MyUIFormHelper());
   ```
   Source: [Runtime/BaseUIManager.cs#L313-L320](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L313-L320)

## Common Variants

| Scenario | Approach |
|------|------|
| Integrating FairyGUI | Have the Helper internally parse `uiFormAsset` as a FairyGUI component and return a `GComponent`; in `CreateUIForm`, return an `IUIForm` implementation that wraps the `GComponent`. |
| Integrating UGUI | Use `GameObject` directly as the generic carrier; call `Object.Instantiate` inside `InstantiateUIForm`, and bind the logic script via `GetComponent(uiFormType)` inside `CreateUIForm`. |
| Hot-swapping at runtime | Replace with a new Helper instance via `BaseUIManager.SetUIFormHelper`, but you must manage the destruction of the old instance yourself. |

## Common Errors

| Error | Cause | Fix |
|------|------|------|
| After startup, the console reports the error `UI组件的 UI Form Helper 设置错误。` | The namespace of `UI Form Helper Type Name` does not match the current `ComponentType`. | Change the namespace to match the selected UI system (e.g., FairyGUI uses `GameFrameX.UI.FairyGUI.Runtime`, `UGUI` uses `GameFrameX.UI.UGUI.Runtime`), or drag in the correct prefab. |
| `Can not create UI form helper.` is reported when opening a UI form. | The type name is misspelled, or the custom prefab has no script attached. | Check that `m_UIFormHelperTypeName` is the fully qualified class name, or confirm that the script attached to the `m_CustomUIFormHelper` prefab is a subclass of `UIFormHelperBase`. |
| `SetUIFormHelper(null)` throws an exception | `BaseUIManager` internally performs a null check on the parameter. | Always pass a non-null instance; switch to the default implementation when you need to clear it. |

## Background (Optional)

`IUIFormHelper` extracts two concerns out of the UI manager — "how an asset becomes a GameObject / GComponent" and "how to bind it to a logic script" — so that the same `BaseUIManager` can adapt to different UI solutions. In `Start`, `UIComponent` creates the Helper with the priority "type name → custom prefab", and then calls `BaseUIManager.SetUIFormHelper` to write it into the framework.
