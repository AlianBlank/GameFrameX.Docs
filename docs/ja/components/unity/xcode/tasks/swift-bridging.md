# Objective-C/Swift 混在ブリッジングの有効化

`XCodeConfig.json` で `swiftBridging` を `true` に設定します（またはデフォルトのままにしておくこともできます——この設定は**デフォルトで有効**です）。iOS プロジェクトをビルドすると、GameFrameX は Swift ブリッジファイルとブリッジングヘッダーファイルを自動生成し、`SWIFT_VERSION=5.0` と `SWIFT_OBJC_BRIDGING_HEADER` を設定します。プロセス全体を通じて Xcode のダイアログは一切表示されず、そのまま CI で利用できます。

## 前提条件

- プロジェクトに GameFrameX Xcode Config パッケージが導入済みであり、『XCodeConfig.json 設定概要』に従って基本設定が完了していること（本パッケージは iOS ビルド時に自動的にポストプロセスを実行するため、API を手動で呼び出す必要はありません）。
- ビルドターゲットが iOS プラットフォームであること（関連コードは `#if UNITY_IOS` ブロック内にあります）。

## 操作手順

1. プロジェクトルート（またはモジュールディレクトリ）配下の `XCodeConfig.json` を開き、`swiftBridging` を `true` に設定します：

   ```json
   {
     "swiftBridging": true
   }
   ```

   > このキーは省略可能です——省略した場合は `true` とみなされます（デフォルトで有効）。判定ロジックは下記のソースコードを参照してください：

   ```csharp
   // Swift ブリッジを設定（デフォルトで有効）
   bool swiftBridging = !finalConfig.ContainsKey("swiftBridging") || finalConfig.Get<bool>("swiftBridging");
   SetupSwiftBridging(project, project.GetUnityMainTargetGuid(), project.GetUnityFrameworkTargetGuid(), path, swiftBridging);
   ```

   Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101)

2. Unity で iOS ビルド（File → Build Settings → Build）を実行すると、ポストプロセスの段階で以下が自動的に完了します：

   - 生成された Xcode プロジェクトのルートディレクトリに `gameframex_swift_bridging.swift` を作成します（存在しない場合にのみ書き込まれ、内容は `import Foundation`、ファイルヘッダーには `DO NOT EDIT` と記載されます）。
   - ブリッジングヘッダーファイル `Unity-iPhone-Bridging-Header.h` を作成します。
   - `.swift` ファイルを UnityFramework ターゲットのコンパイルに追加し、ブリッジングヘッダーファイルをプロジェクトに追加します。
   - メインターゲットと UnityFramework ターゲットに `SWIFT_VERSION = 5.0` を設定し、メインターゲットには `SWIFT_OBJC_BRIDGING_HEADER = Unity-iPhone-Bridging-Header.h` を設定します。

   中核となる実装：

   ```csharp
   proj.AddFileToBuild(frameworkTargetGuid, proj.AddFile(swiftFile, SwiftBridgingFileName, PBXSourceTree.Source));
   proj.AddFile(bridgingHeaderFile, SwiftBridgingHeaderName, PBXSourceTree.Source);

   proj.SetBuildProperty(mainTargetGuid, "SWIFT_VERSION", "5.0");
   proj.SetBuildProperty(mainTargetGuid, "SWIFT_OBJC_BRIDGING_HEADER", SwiftBridgingHeaderName);

   proj.SetBuildProperty(frameworkTargetGuid, "SWIFT_VERSION", "5.0");

   LogHelper.Log("[SwiftBridging] Swift bridging header configured");
   ```

   Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L37-L45)

3. 結果の検証：生成された `.xcodeproj` を開き、**Unity-iPhone** ターゲットを選択 → Build Settings：
   - `SWIFT_VERSION` が `5.0` と表示されます。
   - `SWIFT_OBJC_BRIDGING_HEADER` が `Unity-iPhone-Bridging-Header.h` と表示されます。
   - Unity Console に `[SwiftBridging] Swift bridging header configured` が出力されます。

## よくあるバリエーション

- **混在ブリッジングを無効化する**：明示的に `"swiftBridging": false` と記述します。`SetupSwiftBridging` の冒頭には `if (!enabled) return;` があり、無効化するとファイルは一切作成されず、Swift のビルドプロパティも一切設定されません。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L12-L14)
- **ブリッジングヘッダーで Objective-C ヘッダーを公開する**：ブリッジングヘッダーファイルは存在しない場合にのみ生成され、その後上書きされることはありません（`File.Exists` による判定）。生成された `Unity-iPhone-Bridging-Header.h` に直接 `#import` を追記でき、ビルドを繰り返しても変更が失われることはありません。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L27-L35)
- **複数モジュールでの連携**：複数の `XCodeConfig.json` は再帰的なディープマージによって統合され、最終的にはマージ後の `swiftBridging` の値が有効になります。いずれの設定にも明記されていない場合、デフォルトは `true` です。
  Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L100)

## よくあるエラー

- **Xcode に Swift ファイルが見当たらない / `SWIFT_OBJC_BRIDGING_HEADER` が空**：多くの場合、設定をマージした結果、どこかの `XCodeConfig.json` で `swiftBridging` が明示的に `false` に設定されていることが原因です。マージに関わるすべての設定ファイルを確認してください。
- **ブリッジングヘッダーファイルの内容を変更したのに「消えた」**：Xcode プロジェクトのディレクトリが再生成されていないか確認してください（Unity の上書きエクスポートではディレクトリが再構築されます）。ブリッジングヘッダーはファイルが存在しない場合にのみ書き込まれるため、カスタムの `#import` は上書きされない安定した場所に置くか、独自のスクリプトで注入することをお勧めします。
- **Swift の構文エラー / バージョン不一致**：本パッケージは `SWIFT_VERSION = 5.0` を固定で書き込みます。プロジェクト内で手作業で古いバージョンの値に書き戻さないでください。ビルドを繰り返すと再び 5.0 に上書きされます。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L40-L43)

## 背景

この機能が作用するのは **Unity-iPhone（メイン）ターゲットと UnityFramework ターゲットのみ**です：Swift ファイルは UnityFramework ターゲットのコンパイルに追加され、`SWIFT_OBJC_BRIDGING_HEADER` はメインターゲットにのみ設定されます。Xcode で手動で Swift ファイルを新規作成した際に表示される「ブリッジングヘッダーを作成するかどうか」のダイアログとは異なり、このフローは完全にポストプロセススクリプトによって完了するため、CI 環境での無人ビルドがダイアログによってブロックされることはありません。
