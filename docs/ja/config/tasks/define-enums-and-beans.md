# 列挙型・構造体・複合フィールドの定義方法

ある列のフィールドに「決まったいくつかの値」しか取らせたい場合（例：アイテムタイプ）や、複数のフィールドを 1 つの複合フィールドにまとめたい場合（例：座標、価格帯）は、`__enums__.xlsx` と `__beans__.xlsx` という 2 枚の「高度定義テーブル」を使用します。本記事では、列挙型と構造体をゼロから定義し、データテーブルで参照する方法を解説します。

## 前提条件

- 「設定テーブルの新規作成方法」の手順に従って、`Excels/Tables/` 配下に少なくとも 1 枚の通常データテーブルを作成済みであること（先頭 4 行のヘッダーの意味を理解していること）。
- ローカルに Excel、WPS、または `.xlsx` ファイルを編集できるツールがインストールされていること。
- `Excels/` ディレクトリ配下の `__enums__.xlsx` と `__beans__.xlsx` を確認済みであること（中身が空でも一度開いたことがあること）。

> この 2 枚のテーブルを一度定義すれば、すべてのデータテーブルの `##type` 行に列挙型名や構造体名を直接書いてフィールド型として使用できます。

## 操作手順

### ステップ 1：「列挙型定義テーブル」を開く

`Excels/__enums__.xlsx` を開きます。このテーブルの用途はただ 1 つ、すべての「列挙型」をここに集めて定義することです。

このテーブルのヘッダーも同様に固定の 4 行です：

| 行 | マーカー | 記入内容 |
|----|------|--------|
| 1 | `##var` | 列挙型の各値の英語名 |
| 2 | `##type` | すべて `int` と記入 |
| 3 | `##group` | 空欄のまま |
| 4 | `##` | 中国語の説明 |

> ツールは**英語の列名（`##var` 行）**で列挙型を識別します。命名規則：`EnumName.Member`、例：`ItemType.Consumable`。

### ステップ 2：列挙型を定義する

例えば「アイテムタイプ」に対する列挙型 `ItemType` を作成し、消耗品・装備・素材の 3 種類を含めるとします。`__enums__.xlsx` に次のように記入します：

| ##var | ItemType.Consumable | ItemType.Equipment | ItemType.Material |
|-------|---------------------|--------------------|-------------------|
| ##type | int | int | int |
| ##group | | | |
| ## | 消耗品 | 装備 | 素材 |

**命名のポイント：**

| 書き方 | 意味 |
|------|------|
| `ItemType.Consumable` | 列挙型名 = `ItemType`、メンバー = `Consumable` |
| `Color.R` / `Color.G` / `Color.B` | 同じテーブル内に複数の列挙型を定義でき、列名で区別します |

定義が完了すれば、すべてのデータテーブルの `##type` 行に `ItemType` と書くだけでこの列挙型を参照できます。

### ステップ 3：データテーブルで列挙型を使用する

アイテムテーブルを新規作成（または開き）、「タイプ」列の型に列挙型名を記入するだけです：

| ##var | id | name | type |
|-------|----|------|------|
| ##type | int | text | ItemType |
| ##group | | | |
| ## | アイテムID | アイテム名 | タイプ |
| | 10001 | diamond | ItemType.Consumable |
| | 10002 | sword | ItemType.Equipment |

ツールによる検証：セルには `ItemType.` で始まるメンバー名を記入する必要があり、そうしないと生成時に「未定義の列挙値」エラーが発生します。

### ステップ 4：「構造体定義テーブル」を開く

`Excels/__beans__.xlsx` を開きます。このテーブルの用途：複数のフィールドを再利用可能な複合型（例：`vec3` 座標、`Reward` 報酬パック）としてまとめることです。

ヘッダーは同様に固定の 4 行マーカーで、意味は通常のテーブルと同じです：

| 行 | マーカー | 記入内容 |
|----|------|--------|
| 1 | `##var` | フィールド名（英語） |
| 2 | `##type` | フィールド型（`int`、`string`、列挙型名、さらには別の構造体名も指定可能） |
| 3 | `##group` | 空欄のまま |
| 4 | `##` | 中国語の説明 |

> 構造体は `##var` 行の**列名（`.` 付き）**で識別されます。例えば `Reward.ItemId`、`Reward.Count` は同じ構造体 `Reward` の 2 つのフィールドを表します。

### ステップ 5：構造体を定義する

例えば、アイテム ID と数量を含む報酬パック `Reward` を定義します：

| ##var | Reward.ItemId | Reward.Count |
|-------|---------------|--------------|
| ##type | int | int |
| ##group | | | |
| ## | アイテムID | 数量 |

これで `ItemId`（int）と `Count`（int）の 2 つのフィールドを持つ `Reward` という名前の構造体が宣言されました。

**複合フィールドにはさらに構造体や列挙型をネストできます：**

| ##var | Reward.ItemId | Reward.ItemType | Reward.Pos.x | Reward.Pos.y |
|-------|---------------|------------------|--------------|--------------|
| ##type | int | ItemType | float | float |
| ##group | | | | |
| ## | アイテムID | アイテムタイプ | X座標 | Y座標 |

上の例では 2 つの構造体を定義しています：`Reward`（`ItemId`、`ItemType`、`Pos` を含む）と `Pos`（`x`、`y` を含む）です。

### ステップ 6：データテーブルで構造体を使用する

構造体名を `##type` 行に直接記入し、セルにはフィールド順に値を記入します（区切り文字は `,` または `;`、ツールは宣言順に読み取ります）：

| ##var | id | first_reward |
|-------|----|--------------|
| ##type | int | Reward |
| ##group | | | |
| ## | 実績ID | 初回クリア報酬 |
| | 900001 | 10001,1 |
| | 900002 | 10002,5 |

> 行内の区切り文字はツールの実際の設定に従います（デフォルトはカンマ `,`）。フィールドの順序は `__beans__.xlsx` の `##var` の順序と一致している必要があります。

## よくあるバリエーション

| シーン | 書き方 |
|------|------|
| リスト型フィールド（同一構造体を複数） | 型に `list,Reward` と記入し、セルでは `;` で各 Reward を区切る |
| マップ型フィールド | 型に `map,int,Reward` と記入（キー型が前、値型が後） |
| 多言語フィールドを構造体に組み込む | フィールド型を `text` と記入するだけ |
| 組み込み座標型を再利用 | `##type` に直接 `vec2` / `vec3` / `vec4` と記入（[Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml) に標準搭載） |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 生成時に *未定義の列挙型* と表示される | `__enums__.xlsx` にその列挙型名が記入されていない | `__enums__.xlsx` に `EnumName.Member` 形式で追記する |
| 生成時に *サポートされていない中国語のテーブル名* と表示される | 列名/列挙型名に中国語を使用した | 列挙型名、メンバー名、フィールド名は必ず英語にする |
| 構造体のフィールドが一致しない | セルの記入順序が `__beans__.xlsx` のフィールド順序と一致していない | `##var` 行の順序どおりに厳密に記入する |
| データ列がまったく読み取れない | `__var` / `##type` / `##group` / `##` のマーカーを書き間違えている | この 4 つのマーカーは固定文字列なので、そのまま正確に記述する |
| 同じ列挙型の競合 | `__enums__.xlsx` の同じ列に異なるプレフィックスのメンバーを記入した | 各列挙型を 1 列に独立させ、混在させない |

## 背景（任意）

`__enums__.xlsx` と `__beans__.xlsx` は、本質的には「コード内で `enum` / `class` を書く」作業を Excel に移したものです。プランナーがヘッダーを記入すると、ツールが対応する C# の列挙型とクラスを生成し、クライアント（Unity）とサーバー（.NET）がそれぞれ型の一致したコードを受け取ります。組み込み型（座標など）は [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml) で提供され、各プラットフォームごとの座標実装に自動的に適合します。
