# 语言切换不生效或不保存：系统语言回退与 Setting 持久化检查

当 `Language` 仍为哨兵值 `"zxx"`（`UnknownLocalization`）时，框架会在运行时**自动回退到系统语言**；而每次通过 `LocalizationComponent` 设置语言时，框架会写入 Setting 并 `Save()` 持久化。语言"不生效/不保存"绝大多数是因为：直接改了 `LocalizationManager.Language`（绕过了 Setting 写入）、编辑器模式被 `m_IsEnableEditorMode` + `EditorLanguage` 覆盖、或传入 `"zxx"` 被拒绝。下面按症状逐条排查。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 设置了语言，重启后仍显示系统语言 | 直接改的是 `LocalizationManager.Language`，没经过 `SettingComponent` 持久化 | 只通过 `LocalizationComponent.Language` 赋值，见 [修复 1](#修复-1用-localizationcomponentlanguage-切换并持久化) |
| 编辑器里怎么切语言，Play 后都被覆盖为 `zh_CN` 等固定值 | 组件勾选了 `m_IsEnableEditorMode`，`Start()` 中用 `EditorLanguage` 覆盖 | 取消勾选或修改 Inspector 上的 Editor Language，见 [修复 2](#修复-2编辑器下语言被-editorlanguage-覆盖) |
| 抛出 `GameFrameworkException: Language is invalid.` | 给 `Language` 赋了 `UnknownLocalization`（`"zxx"`），setter 直接抛异常 | 不要传 `"zxx"`；空值请显式赋默认语言，见 [修复 3](#修复-3传入-zxx-导致-language-is-invalid) |
| 抛出 `GameFrameworkException: default Language is invalid.` | 给 `DefaultLanguage` 赋了 `"zxx"` | 赋合法语言码（如 `"zh_CN"`、`"en_US"`），见 [修复 3](#修复-3传入-zxx-导致-language-is-invalid) |
| 启动日志出现 `Can not create localization helper.` 后语言相关功能全挂 | `m_LocalizationHelperTypeName` 被改成错误类型名，Helper 创建失败 | 恢复为默认全名 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper`，见 [修复 4](#修复-4helper-创建失败导致-systemlanguage-不可用) |
| 日志 `Setting component is invalid.`，语言设置读写全失效 | 场景缺少 `SettingComponent`，`Start()` 直接 Fatal 返回 | 挂上 Setting 组件，见 [修复 4](#修复-4helper-创建失败导致-systemlanguage-不可用) |
| 切了语言但界面文本没变 | 语言事件发出去了，但字典未重新加载或 UI 未刷新 | 监听 `LocalizationLanguageChangeAfterEventArgs` 后重载字典/刷新 UI，见 [修复 5](#修复-5切语言后文本未刷新) |
| 界面出现 `<NoKey>xxx` | 当前语言字典里没有该 Key | 补齐对应语言字典条目，见 [验证](#验证) |

## 修复步骤

### 修复 1：用 `LocalizationComponent.Language` 切换并持久化

持久化只发生在 `LocalizationComponent` 这一层的 setter 中：写入 Setting 键 `LocalizationComponent.Language` 并立即 `Save()`，随后依次抛出 Before / Change / After 三个语言事件。直接改 `LocalizationManager.Language` 不会写 Setting，重启即丢失。

```csharp
// 正确：经组件层赋值 —— 写 Setting + Save + 触发三个语言事件
GameEntry.GetComponent<LocalizationComponent>().Language = "en_US";

// 错误：绕过组件层，重启后丢失（不写 Setting，不发事件）
// GameFrameXEntry.GetModule<ILocalizationManager>().Language = "en_US";
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L140-L171)

对应的 Setting 键与读取顺序（getter 先查 Setting，仍未知才回退）：

```csharp
get
{
    if (m_LocalizationManager.Language == UnknownLocalization)
    {
        var value = m_SettingComponent.GetString(nameof(LocalizationComponent) + "." + nameof(Language));
        if (value.IsNotNullOrWhiteSpace())
        {
            m_LocalizationManager.Language = value;
        }
    }

    return m_LocalizationManager.Language;
}
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L143-L153)

`DefaultLanguage` 的行为完全一致，仅键名换为 `LocalizationComponent.DefaultLanguage`：[LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L104-L128)

### 修复 2：编辑器下语言被 `EditorLanguage` 覆盖

`Start()` 中按编辑器模式分两条路径：勾选了 `m_IsEnableEditorMode` 时，编辑器内语言被强制设为 `EditorLanguage`；打包环境（或未勾选）时，仅当 `Language == UnknownLocalization` 才回退到系统语言。

```csharp
#if UNITY_EDITOR
            if (m_IsEnableEditorMode)
            {
                Language = EditorLanguage != UnknownLocalization ? EditorLanguage : m_LocalizationManager.SystemLanguage;
            }
#else
            if (Language == UnknownLocalization)
            {
                Language = m_LocalizationManager.SystemLanguage;
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L270)

操作方法：

1. 选中场景中的 Localization 组件，检查 **Is Enable Editor Mode** 是否勾选。
2. 已勾选时，Inspector 上的 **Editor Language**（默认 `zh_CN`）会在每次 Play 时覆盖之前保存的语言——要么取消勾选，要么把它改成你要验证的语言。
3. 默认序列化值参考（`m_EditorLanguage`/`m_DefaultLanguage` 均为 `"zh_CN"`，编辑器模式默认关闭）：

```csharp
        [SerializeField] private string m_EditorLanguage = "zh_CN";

        [SerializeField] private string m_DefaultLanguage = "zh_CN";

        [SerializeField] private bool m_EnableLoadDictionaryUpdateEvent = false;
        [SerializeField] private bool m_IsEnableEditorMode = false;
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L71)

### 修复 3：传入 `zxx` 导致 `Language is invalid.`

`"zxx"` 是"未知本地化"哨兵值，两个 setter 都会拒绝它：

```csharp
            set
            {
                if (value == UnknownLocalization)
                {
                    throw new GameFrameworkException("Language is invalid.");
                }

                _language = value;
            }
```

Source: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L100-L108)

| 属性 | 异常消息原文 | 触发值 |
|------|--------------|--------|
| `LocalizationManager.Language` | `Language is invalid.` | `"zxx"` |
| `LocalizationManager.DefaultLanguage` | `default Language is invalid.` | `"zxx"` |

`default Language is invalid.` 的出处见 [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L71-L83)。赋值时改用真实语言码即可。

### 修复 4：Helper 创建失败导致 `SystemLanguage` 不可用

`Start()` 依次依赖 `BaseComponent`、`EventComponent`、`SettingComponent`，任一缺失都会 `Log.Fatal` 后 `return`，语言读写全部瘫痪；随后按 `m_LocalizationHelperTypeName` 创建 Helper，失败则日志 `Can not create localization helper.`。而 `SystemLanguage` 内部有非空守卫，Helper 为空时直接抛出：

```csharp
        public string SystemLanguage
        {
            get
            {
                GameFrameworkGuard.NotNull(_localizationHelper, nameof(_localizationHelper));
                return _localizationHelper.SystemLanguage;
            }
        }
```

Source: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L115-L122)

操作方法：

1. 确认场景中存在 Setting/Event 组件（日志出现 `Setting component is invalid.` / `Event component is invalid.` 即为缺失），出处 [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227-L246)。
2. 检查 Inspector 上 **Localization Helper Type Name** 是否仍为默认全名：

```csharp
        [SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

3. 默认 Helper 的系统语言来自 `CultureInfo.CurrentCulture`，并把 `-` 换成 `_`（如 `zh-CN` → `zh_CN`）。若设备区域格式与你的字典命名不一致，就是"回退语言永远对不上"的根因：

```csharp
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
```

Source: [DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L52-L55)

可继承 `LocalizationHelperBase` 重写 `SystemLanguage`（抽象定义见 [LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L47)），再通过 **Custom Localization Helper** 槽位替换默认实现。

### 修复 5：切语言后文本未刷新

`LocalizationComponent.Language` 的 setter 在保存后依次触发三个事件：`LocalizationLanguageChangeBeforeEventArgs`、`LocalizationLanguageChangeEventargs`（Change）、`LocalizationLanguageChangeAfterEventArgs`，均携带 `oldLanguage` 与新语言。字典重载与 UI 刷新应订阅这些事件完成，典型时机是 After：

```csharp
var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventargs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L163-L168)

事件参数定义见 [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41)。

## 验证

1. **语言值**：Inspector 选中 Localization 组件后，面板会直接显示 `Language`、`System Language` 两个只读字段（[LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L70-L72)）。切换语言后确认 `Language` 为新值、`System Language` 为设备区域值。
2. **持久化**：设置语言 → 停止 Play → 再次 Play，`Language` 应保持新值（getter 会从 Setting 键 `LocalizationComponent.Language` 读回）。
3. **回退逻辑**：清掉本地 Setting 后再 Play，`Language` 应等于 `SystemLanguage`——因为 `LocalizationManager.Language` 在未设置时返回系统语言：

```csharp
            get
            {
                if (_language == UnknownLocalization)
                {
                    return SystemLanguage;
                }

                return _language;
            }
```

Source: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L91-L99)

4. **字典**：取值正常时不再输出 `<NoKey>{key}` 占位（[LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L168-L177)）；若仍出现，说明当前语言的字典未加载或缺 Key，请为对应语言补齐字典。

## 背景

`Language` 采用哨兵值 `"zxx"`（`LocalizationManager.UnknownLocalization` 常量，见 [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L53)）表示"未设置"，三处回退链为：组件层 getter → Setting 持久值；管理器 getter → `SystemLanguage`；`Start()` → 系统语言兜底赋值。语言码遵循 RFC 5646 风格（组件上的 `[HelpURL]` 即指向该规范），内部统一用 `_` 替代 `-`。
