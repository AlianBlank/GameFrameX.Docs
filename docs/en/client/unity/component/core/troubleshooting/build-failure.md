# What to Do When Build Failures and Hotfix Anomalies Occur

This page addresses common issues encountered when using the `BuildProduct` (Build Product) and `BuildHotfix` (Build Hotfix) menus in GameFrameX. Use the symptoms to troubleshoot and apply fixes that are consistent with the source code.

## Quick Diagnosis

| Symptom (Log Text) | Cause | Fix |
|------|------|------|
| `当前构建目标不是 Windows` | The menu requires the current `BuildTarget` to match the menu target, but you switched to another platform | Open `File → Build Settings`, switch the platform to the corresponding target before triggering the menu |
| `当前构建目标不是 Mac Os` | Same as above, for the macOS build entry | Switch to `StandaloneOSX` and retry |
| `当前构建目标不是 WebGL` | Same as above, for the WebGL build entry | Switch to `WebGL` and retry |
| `当前构建目标不是 Android` | Same as above, for the Android build entry | Switch to `Android` and retry |
| `输出路径异常,取消打包AAB` | The build output directory is empty or not writable | See fix step 4 below |
| `未找到HybridCLR数据目录:{path}` | The HybridCLR generation flow has not been run yet, `HybridCLRData/AssembliesPostIl2CppStrip/<Target>` does not exist | Run `HybridCLR → Generate` first, then copy AOT |
| `复制Hotfix DLL到Assets/Bundles/Code完成` followed by hotfix code still not found at runtime | `Unity.HotFix.dll` was not copied to `Library/ScriptAssemblies` | Trigger `GameFrameX → Build → Copy HotFix Code` |
| `Build Output Path:...` but the build fails with errors | Insufficient permissions or disk space for the output directory | Switch to a writable directory and clean up old artifacts |

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L101-L110), [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L80-L100)

## Fix Steps

### 1. Platform Mismatch ("当前构建目标不是 XXX")

`BuildProductHelper` validates `EditorUserBuildSettings.activeBuildTarget` at each platform entry. If it does not match, it directly calls `Debug.LogError` and `return`:

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    Debug.Log(EditorUserBuildSettings.activeBuildTarget);
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("当前构建目标不是 Windows");
        return;
    }
    ...
}
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L101-L110)

**Steps:**

1. Open the Unity menu `File → Build Settings…`
2. Switch to the `Target Platform` corresponding to the entry (Windows64 / macOS / WebGL / Android)
3. Click `Switch Platform` and wait for the platform switch to complete
4. Re-execute `GameFrameX → Build → <Corresponding Platform>`

### 2. AOT Metadata Copy Failure ("未找到HybridCLR数据目录")

`CopyAOTCode` copies `*.dll` from `<Project>/HybridCLRData/AssembliesPostIl2CppStrip/<activeBuildTarget>` to `Assets/Bundles/AOTCode/`. If the directory does not exist, it reports an error and returns:

```csharp
DirectoryInfo aotCodeDir = new DirectoryInfo(path);
if (!aotCodeDir.Exists)
{
    Debug.LogError($"未找到HybridCLR数据目录:{path}");
    return;
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L84-L92)

**Steps:**

1. In Unity, open `HybridCLR → Generate` (or the `HybridCLR/Generate` flow in your project) to generate the stripped AOT DLLs
2. Confirm that `*.dll` files appear under `HybridCLRData/AssembliesPostIl2CppStrip/<Target>`
3. Then execute `GameFrameX → Build → Copy AOT Code`

### 3. `Unity.HotFix.dll` Not Found

`BuildHotfixHelper.CopyHotfixCode()` by default copies from `Library/ScriptAssemblies/Unity.HotFix.dll` to `Assets/Bundles/Code/Unity.HotFix.dll.bytes`:

```csharp
private const string HotFixAssembliesDir = "Library/ScriptAssemblies";
private static readonly string[] HotfixDlls = new string[] { "Unity.HotFix.dll" };
private const string CodeDir = "Assets/Bundles/Code/";

foreach (var hotfix in HotfixDlls)
{
    var srcPath = Path.Combine(HotFixAssembliesDir, hotfix);
    if (!File.Exists(srcPath))
    {
        continue;
    }
    File.Copy(srcPath, Path.Combine(CodeDir, hotfix + Utility.Const.FileNameSuffix.Binary), true);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L21-L65)

If the DLL does not exist under `Library/ScriptAssemblies`, the code silently `continue`s, leaving `Assets/Bundles/Code/` empty. **Steps:**

1. Confirm that the `Unity.HotFix` `asmdef` (hotfix assembly) exists in the project, and the name must strictly be `Unity.HotFix.dll`
2. Switch to the corresponding build target and let Unity recompile. Verify that `Library/ScriptAssemblies/Unity.HotFix.dll` is generated
3. Then execute `GameFrameX → Build → Copy HotFix Code(复制热更新代码到Assets>Bundles>Code)`
4. Verify that `Unity.HotFix.dll.bytes` is generated under `Assets/Bundles/Code/`

### 4. AAB Output Path Anomaly

The Android AAB entry prints the following when validating the output directory:

```csharp
Debug.LogError("输出路径异常,取消打包AAB");
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L421)

**Steps:**

1. Before triggering the `GameFrameX/Build` menu, configure the build output directory, ensure the path exists and is writable by the current user
2. Clean up leftover artifacts from the previous build (old AAB files with the same name, read-only files)
3. Re-trigger the corresponding Android AAB entry

### 5. Temporarily Disable HybridCLR

The source code provides the macro switch `DISABLE_HYBRIDCLR`, which can be toggled with one click via the menu:

```csharp
public const string HybridCLRScriptingDefineSymbol = "DISABLE_HYBRIDCLR";

[MenuItem("GameFrameX/Scripting Define Symbols/Disable HybridCLR(关闭HybridCLR适配)", false, 5000)]
public static void DisableHybridCLR()
{
    ScriptingDefineSymbols.AddScriptingDefineSymbol(HybridCLRScriptingDefineSymbol);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L107-L116)

When the hotfix chain causes the overall build process to fail and you must produce a build first, you can temporarily go to `GameFrameX → Scripting Define Symbols → Disable HybridCLR` to skip the hotfix-related steps and isolate the issue. Then use `Enable HybridCLR` to restore it.

## Verification

After build/hotfix issues are fixed, perform a self-check in the following order:

1. The `BuildProductHelper` entry no longer prints LogError messages like `当前构建目标不是 XXX`, and the build reports `BuildResult.Succeeded`
2. `Assets/Bundles/Code/Unity.HotFix.dll.bytes` and the AOT DLLs for the current target exist under `Assets/Bundles/AOTCode/`
3. Run the build artifact, and the HybridCLR hotfix entry can normally load the hotfix assembly
