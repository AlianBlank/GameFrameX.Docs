# ログに「Event manager is invalid.」が出た場合の対処法

シーン内で `MonoComponent` の起動後、`GameEntry` から `EventComponent` インスタンスを取得できない場合、ログに `Event manager is invalid.` が出力され、その後の初期化処理が中断されます。その結果、Mono モジュールのイベント購読／発行がすべて無効になります。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動時に `Event manager is invalid.` が出る | 起動シーンに `EventComponent` がアタッチされていない | 起動シーンの `GameFramework` ノードに `EventComponent` を追加します。下記の修正手順 1 を参照してください |
| 起動時に `Event manager is invalid.` が出る | 起動シーンに `EventComponent` がアタッチされているが、`MonoComponent` のスクリプト実行順序が `EventComponent.Awake` より早い | Project Settings で `MonoComponent` の Script Execution Order を `Default` より後に設定します。修正手順 2 を参照してください |
| 起動時に `Event manager is invalid.` が出る | 同じコンポーネントに重複する `EventComponent` が追加されており、`GameEntry` に保存されたインスタンスが上書きまたは解放される | 余分な `EventComponent` を削除し、フレームワークのエントリーノードに 1 つだけ存在することを確認します |

## 修正手順

### 1. 起動シーンに EventComponent を追加する

`MonoComponent.Start()` は `GameEntry.GetComponent<EventComponent>()` を通じてイベントコンポーネントを取得します。`GameEntry` がインデックスを作成できるのは、GameFramework の起動オブジェクトにアタッチされたコンポーネントだけです。

1. プロジェクトの起動シーン（例：`Assets/GameFrameX/Launch/Launch.unity`）を開きます。
2. `GameFramework` ルート GameObject を選択します。
3. Inspector → Add Component → `GameFrameX.Event.EventComponent` を検索して追加します。
4. 再実行すると、ログに `Event manager is invalid.` が出力されなくなるはずです。

エラー発生箇所：

```csharp
// 来源:Runtime/Mono/MonoComponent.cs
private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

出典：[MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76)

### 2. スクリプトの実行順序を確認する

`MonoComponent.Start()` はすべてのコンポーネントの `Awake` 後に実行されますが、プロジェクトで Script Execution Order をカスタマイズして `MonoComponent` を前倒しした場合、`GameEntry` にまだ登録されていない `EventComponent` を取得する可能性があります。

1. Edit → Project Settings → Script Execution Order の順に選択します。
2. `MonoComponent` を `Default Time` より後にドラッグするか、`EventComponent` より遅い Order 値を明示的に指定します。
3. 再実行して確認します。

### 3. 重複するアタッチまたはシーン内の残存インスタンスを確認する

同じ GameObject に複数の `EventComponent` が手動で追加されている場合や、旧シーンに古い `EventComponent` が残存しており、新しいコードが別のオブジェクトにそれをインスタンス化した場合、`GameEntry.GetComponent` は型の重複により null 参照を返します。

1. Hierarchy で `t:EventComponent` を検索し、インスタンスが 1 つだけであることを確認します。
2. 余分なインスタンスを削除してから再実行します。

## 検証

1. シーンを実行して Console を開き、`Event manager is invalid.` を検索します。出現しないことを確認します。
2. `MonoComponent` が存在するオブジェクトにテストスクリプトをアタッチし、`Start` で `GameEntry.GetComponent<EventComponent>()` を呼び出して、null でないことをアサートします。
3. イベントの購読／発行フロー全体（`Subscribe` → `Fire` → `Unsubscribe`）を実行し、イベントがリスナーに正常に届くことを確認します。

## 背景（任意）

`MonoComponent` は `EventComponent` への参照を `m_EventComponent` フィールドにキャッシュし、後続の `OnApplicationFocus` などのライフサイクルコールバックでも再利用します。`Start` 段階で参照を取得できない場合、フィールドは null のままになり、後続のイベント関連初期化は暗黙的にスキップされます。これが、エラーが一度だけ表示されるにもかかわらず機能が動作しない理由です。

Mono モジュールの全体的な導入フローについては、『Mono モジュールの導入方法』を参照してください。
