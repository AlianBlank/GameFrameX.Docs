# 設定 OpenTelemetry / Prometheus 指標與健康檢查

本節示範如何啟用 GameFrameX.Server 內建的 OpenTelemetry 遙測,並將 Prometheus 指標(`/metrics`)與健康檢查(`/health`)公開給監控系統使用。

## 前置條件

- 已部署 GameFrameX.Server,並能正常啟動。
- 監控系統可存取伺服器上由 `MetricsPort` 指定的連接埠(預設 `29090`)。

## 操作步驟

1. 在啟動參數或環境變數中啟用 OpenTelemetry 總開關。

   ```bash
   --IsOpenTelemetry=true
   ```

   啟動命令範例(可參考 `docker-compose.yml` 中的 `MetricsPort` 與 `APMPort` 行):

   ```bash
   --InnerPort=29100 \
   --MetricsPort=29090 \
   --IsEnableHttp=true
   ```

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L115-L121)

2. 啟用 Prometheus 指標匯出(預設 `false`,需要 `IsOpenTelemetry=true`)。

   ```bash
   --IsOpenTelemetryMetrics=true
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

3. (可選)啟用分散式追蹤。

   ```bash
   --IsOpenTelemetryTracing=true
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

4. 設定指標收集連接埠。如未設定，使用預設值 `0`(即關閉對外連接埠)。

   ```bash
   --MetricsPort=29090
   ```

   預設值與範例值見下表，Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

5. 重新啟動服務，驗證兩個端點可用：

   | 端點 | URL | 說明 |
   |------|-----|------|
   | 健康檢查 | `http://<host>:29090/health` | 服務存活與就緒狀態 |
   | Prometheus 指標 | `http://<host>:29090/metrics` | Prometheus 擷取的指標文字 |

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L175-L177)

## 常見變體

- **Docker Compose 部署**：在 `docker-compose.yml` 的環境變數區加入以下行即可，無需修改映像檔。
  參考 [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)
- **僅啟用健康檢查、不匯出指標**：保持 `IsOpenTelemetryMetrics=false`,只需將 `/health` 端點接入負載平衡器或 K8s readiness 探針。
- **匯出至遠端 OTLP 收集器**：在 `IsOpenTelemetry=true` 基礎上啟用 `IsOpenTelemetryTracing` 即可輸出鏈路資料(具體收集器位址依部署需求另行設定)。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 存取 `/metrics` 回應連線被拒 | `IsOpenTelemetry` 未啟用 | 加上 `--IsOpenTelemetry=true` 後重新啟動 |
| 啟用 `IsOpenTelemetryMetrics` 後仍無指標 | 缺少總開關 | 該參數相依於 `IsOpenTelemetry=true` |
| 連接埠衝突 | `MetricsPort` 與 `APMPort` 佔用同一連接埠 | 明確設定 `MetricsPort=29090`,並確認宿主機連接埠閒置 |
| Prometheus 擷取不到資料 | 防火牆未開放連接埠 | 在安全性群組/防火牆中開放 `MetricsPort` |

## 設定項目速查

| 名稱 | 型別/預設值 | 說明 |
|------|-------------|------|
| `IsOpenTelemetry` | `bool`,預設 `false` | OpenTelemetry 遙測總開關 |
| `IsOpenTelemetryMetrics` | `bool`,預設 `false` | 啟用 Prometheus 指標匯出，需 `IsOpenTelemetry=true` |
| `IsOpenTelemetryTracing` | `bool`,預設 `false` | 啟用分散式追蹤，需 `IsOpenTelemetry=true` |
| `MetricsPort` | `int`,預設 `0` | 指標收集連接埠，範例值 `29090` |

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)、[README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

## 背景

OpenTelemetry 是 CNCF 已畢業的可觀測性標準，GameFrameX.Server 透過總開關 + 子開關的兩層設計，將指標與追蹤拆開，方便在不需要全量遙測時僅提供健康檢查，降低對宿主機連接埠與資源的佔用。
