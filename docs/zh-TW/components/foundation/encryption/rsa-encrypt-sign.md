# 使用 RSA 進行加密、解密與簽章的方法

`RsaHelper` 將 RSA 非對稱加密封裝為靜態方法，支援 Base64 金鑰的加密與解密、簽章與驗證，以及 XML 金鑰的金鑰組產生與實例加密、解密。本頁面將解說從金鑰產生到加密、解密、簽章與驗證的完整流程。

## 前置條件

- 專案已參考 `GameFrameX.Foundation.Encryption` 組件，並已撰寫 `using GameFrameX.Foundation.Encryption;`。
- .NET 執行階段支援 `System.Security.Cryptography.RSA`（.NET 6+ 起支援）。
- 準備 Base64 格式的 RSA 金鑰組（PKCS#8/PKCS#1）或 XML 格式的金鑰。若沒有，可使用 `RsaHelper.Make()` 當場產生。

## 操作步驟

### 1. 產生 RSA 金鑰組（XML 格式）

```csharp
using GameFrameX.Foundation.Encryption;

var keyPair = RsaHelper.Make(); // 回傳字典，包含 "privateKey" 與 "publicKey"
string privateKeyXml = keyPair["privateKey"];
string publicKeyXml  = keyPair["publicKey"];
```

字典中的兩個金鑰分別是 XML 格式的私鑰（包含 `Modulus`、`Exponent`、私有參數等）與公鑰，可直接儲存或轉換為 Base64。

### 2. 以公鑰加密、私鑰解密（XML 金鑰）

`Encrypt(string, string)` 與 `Decrypt(string, string)` 接收 XML 格式的金鑰，回傳 Base64 字串。

```csharp
using GameFrameX.Foundation.Encryption;
using System.Text;

string plain = "Hello, RSA!";

// 加密：公鑰 XML + 明文 → Base64 密文
string cipher = RsaHelper.Encrypt(publicKeyXml, plain);

// 解密：私鑰 XML + Base64 密文 → 明文
string back = RsaHelper.Decrypt(privateKeyXml, cipher);
```

若想直接取得位元組陣列，請在加密端使用 `RsaHelper.Encrypt(string publicKey, byte[] content)`，在解密端使用 `RsaHelper.Decrypt(string privateKey, byte[] content)`。

### 3. 以公鑰加密、私鑰解密（Base64 金鑰）

`EncryptBase64` 與 `DecryptBase64` 接收 Base64 編碼的金鑰，會在內部自動識別 PKCS#8 / PKCS#1。

```csharp
string cipher64 = RsaHelper.EncryptBase64(publicKeyBase64, plain);
string plain64 = RsaHelper.DecryptBase64(privateKeyBase64, cipher64);
```

加密使用 **OAEP-SHA256** 填充。當明文超過單一區塊的上限時，會自動進行區塊分割加密，因此適用於任意長度的資料。

### 4. 以私鑰簽章、公鑰驗證

簽章與驗證固定使用 SHA256 + PKCS#1 填充，金鑰也同時支援 PKCS#8 與 PKCS#1 兩種格式。

```csharp
string signature = RsaHelper.Sign(privateKeyBase64, plain);
bool ok = RsaHelper.Verify(publicKeyBase64, plain, signature);
```

若 `Verify` 回傳 `true`，表示簽章有效。若公鑰/資料/簽章任一項遭到竄改，則會回傳 `false`。

### 5. 以實例重複使用相同的金鑰組

適用於需要重複進行加密、解密的情境（建構函式會持有 `RSA` 資源，請務必記得呼叫 `Dispose`）。

```csharp
using (var helper = new RsaHelper(privateKeyXml))
{
    string cipher = helper.Encrypt(plain);             // 以實例的公鑰加密（XML 私鑰亦包含公鑰參數）
    string back   = helper.Decrypt(cipher);            // 以實例的私鑰解密
}
```

也可以直接傳入 `System.Security.Cryptography.RSA` 實例：`new RsaHelper(rsaInstance)`。

## 常見變化情境

| 情境 | 建議 API | 金鑰格式 |
|------|---------|----------|
| 與 Java/Go 等系統互通，金鑰為 PEM 內的 Base64 區段 | `EncryptBase64` / `DecryptBase64` / `Sign` / `Verify` | PKCS#8 或 PKCS#1 Base64 |
| 內部 .NET 系統，長期將金鑰保存在設定檔中 | `Make()` + `Encrypt` / `Decrypt` | XML |
| 大型檔案的區塊加密 | `EncryptBase64` / `DecryptBase64` | Base64（自動區塊分割） |
| 使用相同金鑰多次呼叫，避免重複匯入 | 以 `new RsaHelper(key)` 建立實例 | XML 或 `RSA` 物件 |

## 常見錯誤

| 現象 | 原因 | 處理方式 |
|------|------|------|
| `CryptographicException` "Bad Data" | Base64 字串不是有效的 PKCS#8/PKCS#1 金鑰 | 確認是否已從 PEM 中移除 `-----BEGIN/END-----` 與換行後再轉為 Base64 |
| `Encrypt` 出現 "Key not valid for use in specified state" | XML 字串是私鑰而非公鑰 | 僅 `Make()` 回傳的 `publicKey` 可用於加密 |
| `Verify` 一律回傳 `false` | 簽章資料遭到竄改、金鑰組不相符，或以不同的雜湊簽章 | 確認簽章對象的原文 UTF-8 與驗證時是否一致。確認雙方是否皆使用 SHA256 |
| 加密、解密結果出現亂碼 | 兩端的填充方式不一致 | `EncryptBase64`/`DecryptBase64` 必須成對使用，且皆為 OAEP-SHA256 |

## 補充（選用）

- 加密填充：自 C-05 的修正之後，加密與解密統一使用 `RSAEncryptionPadding.OaepSHA256`，以避免 PKCS#1 v1.5 的 Bleichenbacher 攻擊風險。
- 簽章填充：簽章/驗證固定使用 `RSASignaturePadding.Pkcs1` + `HashAlgorithmName.SHA256`，與許多外部系統的預設值一致。
- 資源管理：實例方法會持有非受控的 RSA 資源，因此使用 `new RsaHelper(...)` 後，請務必呼叫 `Dispose()` 或使用 `using`。
