# 사용자 정의 Helper를 연결하여 기본 구현 교체

GameFrameX에서 제공하는 `Helper.CreateHelper<T>` 진입점을 통해, 프레임워크 시작 시 사용자 정의 Helper로 기본 구현(예: 로그, 압축, 버전, JSON, 텍스트 Helper 등)을 교체할 수 있으며, 프로젝트 내부 도구 체인이나 서드파티 SDK 연동에 사용할 수 있습니다.

## 사전 조건

- 빠른 시작 문서에 따라 `GameFrameX` 프레임워크를 초기화하고, `Awake/Start`에서 `GameFrameXComponent`를 가져올 수 있어야 합니다.
- 사용자 정의 Helper 클래스가 대응하는 인터페이스(예: `GameFrameworkLog.ILogHelper`, `Utility.Compression.ICompressionHelper`, `Utility.Json.IJsonHelper`, `Utility.Text.ITextHelper`, `GameVersion.IVersionHelper`)를 구현했고, Unity 어셈블리에서 리플렉션으로 찾을 수 있어야 합니다.
- 사용자 정의 Helper는 `MonoBehaviour` 파생 클래스여야 합니다(프레임워크는 `GameObject.AddComponent`로 생성).

## 작업 단계

### 1. 사용자 정의 Helper 구현

새 클래스를 만들어 프레임워크 내장 인터페이스를 구현합니다. 아래는 기본 로그 Helper를 교체하는 예시입니다:

```csharp
using UnityEngine;
using GameFrameX;

namespace GameFrameX.Runtime
{
    [UnityEngine.Scripting.Preserve]
    public class MyLogHelper : GameFrameworkLog.ILogHelper
    {
        public void Log(GameFrameworkLogLevel level, object message)
        {
            // 프로젝트 자체 로그 SDK에 연동, 예: 서버로 업로드하거나 로컬 파일에 기록
            MyLogger.Write(level, message);
        }
    }
}
```

출처: [Runtime/Helper/DefaultLogHelper.cs](/Runtime/Helper/DefaultLogHelper.cs#L42-L83)

### 2. 문자열 타입 이름으로 등록

사용자 정의 Helper의 전체 클래스 이름(네임스페이스 포함)을 `Helper.CreateHelper<T>`에 전달합니다. 프레임워크는 리플렉션으로 해당 타입을 찾아 새 `GameObject`에 `AddComponent`합니다:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: "GameFrameX.Runtime.MyLogHelper",
    customHelper: null);
```

문자열 방식의 장점은 씬에 미리 컴포넌트를 배치할 필요가 없어 순수 코드 엔지니어링에 적합하다는 것입니다.

### 3. 프리제형 컴포넌트로 등록

사용자 정의 Helper를 `MonoBehaviour` 스크립트로 만들어 프리팹에 부착한 다음, `customHelper` 매개변수에 직접 전달합니다. 프레임워크는 컴포넌트가 이미 씬에 있는지 판단하여 직접 재사용할지 `Instantiate`로 복제할지 결정합니다:

```csharp
// myLogHelperPrefab은 프리팹의 MyLogHelper 컴포넌트 참조입니다
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: string.Empty,
    customHelper: myLogHelperPrefab);
```

`helperTypeName`을 비우고 `customHelper`가 비어 있지 않으면, `customHelper`를 우선 사용합니다; 반대로 `customHelper`가 비어 있으면 문자열로 타입을 조회합니다; 둘 다 비어 있으면 프레임워크는 경고를 출력하고 `null`을 반환합니다.

### 4. 프레임워크 진입점에 연결

`GameFrameXComponent.Awake` 또는 초기화 흐름에서 생성된 Helper를 해당 서브시스템에 주입합니다. `Log` 모듈을 예시로 들면:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    "GameFrameX.Runtime.MyLogHelper", null);
GameFrameworkLog.SetLogHelper(logHelper);
```

소스 코드 등록 진입점은 [Runtime/Helper/Helper.cs](/Runtime/Helper/Helper.cs#L57-L106)를 참조하세요.

```csharp
var helper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    target: myRoot,
    helperTypeName: "GameFrameX.Runtime.MyLogHelper",
    customHelper: null,
    index: 0);
```

## 일반적인 오류

| 현상 | 원인 | 수정 |
|------|------|------|
| 경고 `Can not find helper type 'XXX'.` | 문자열 클래스 이름 오타, 네임스페이스 누락, 또는 어셈블리에서 리플렉션이 활성화되지 않음 | `Type.FullName`으로 확인; 클래스가 있는 어셈블리가 IL2CPP에 의해 잘리지 않았는지 확인 |
| 경고 `Type 'A' is not assignable from 'B'.` | 사용자 정의 클래스가 대상 인터페이스를 구현하지 않음 | 사용자 정의 클래스가 해당 `IXxxHelper`를 `implements`하도록 함 |
| 경고 `You must set custom helper with '...' type first.` | `helperTypeName`이 비어 있고 `customHelper`도 `null`임 | 둘 중 하나를 채우거나, 먼저 `AddComponent`한 다음 전달 |
| 사용자 정의 로직이 적용되지 않음 | 해당 서브시스템의 `SetXxxHelper` 주입을 호출하지 않음 | 프레임워크 초기화 초기에 `CreateHelper` + `SetHelper` 주입 완료 |

## 배경(선택)

`Helper.CreateHelper<T>`는 내부적으로 `Utility.Assembly.GetType`을 통해 문자열로 타입을 조회하고, 찾은 후 `new GameObject().AddComponent`로 인스턴스화합니다; `customHelper`가 전달되면 컴포넌트가 이미 씬에 있는지 여부에 따라 재사용 또는 `Instantiate`합니다. 두 매개변수가 서로 백업 역할을 하여 설정 기반 엔지니어링과 설정 없는 엔지니어링 모두 연결할 수 있습니다.
