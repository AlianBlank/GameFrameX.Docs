# StartupRunner を使用して起動を接管する方法

`ProcedureComponent` はデフォルトでは `Start()` で自動的に初期化およびフロー起動を行います。`Use Startup Runner` をチェックすると、`Awake` 内で `IProcedureManager` を登録するのみとなり、実際のフロー初期化と起動は `ApplicationStartupEntry` + `StartupRunner.Run` に委ねられます。これにより「Already exist FSM」の競合を回避できます。

## 前提条件

- GameFrameX フローパッケージ（`com.gameframex.unity.procedure`）がインストールされていること。
- プロジェクトに GameFrameX 起動パイプライン（`ApplicationStartupEntry` と `StartupRunner.Run`）が組み込まれていること。そうでない場合、接管フローがトリガーされません。
- シーン内に `ProcedureComponent` がアタッチされたゲームオブジェクトが存在すること。メニュー `GameFrameX > Procedure` から追加できます。

## 操作手順

1. シーンで `ProcedureComponent` がアタッチされたゲームオブジェクトを選択し、Inspector で `Use Startup Runner` チェックボックス（対応するフィールドは `m_UseStartupRunner`）をチェックします。

2. チェックを入れると、`ProcedureComponent.Start()` は即座に `yield break` し、`Initialize` の実行や `StartProcedure` の呼び出しは行われず、`Awake` 内の `IProcedureManager` 登録のみが保持されます。

   ```csharp
   private IEnumerator Start()
   {
       if (m_ProcedureManager == null)
       {
           yield break;
       }

       if (m_UseStartupRunner)
       {
           // Initialize と StartProcedure は ApplicationStartupEntry + StartupRunner.Run に委ねる。
           // このコンポーネントは Awake で IProcedureManager を登録する役割のみを担い、
           // 新しい入口との二重 Initialize による Already exist FSM エラーを回避する。
           yield break;
       }
       // ...
   }
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L168)

3. `ApplicationStartupEntry` 内で `StartupRunner.Run` によりフローを起動します。フロー配列を構築し入口フローを指定した上で、最後に `IProcedureManager.Initialize` と `StartProcedure` を呼び出します。典型的な呼び出し形式は以下の通りです（従来のモードの `Start()` インラインコードと一致します）。

   ```csharp
   ProcedureBase[] procedures = new ProcedureBase[m_AvailableProcedureTypeNames.Length];
   for (int i = 0; i < m_AvailableProcedureTypeNames.Length; i++)
   {
       Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
       procedures[i] = (ProcedureBase)Activator.CreateInstance(procedureType);
       if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
       {
           m_EntranceProcedure = procedures[i];
       }
   }

   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L168)

4. シーンを実行し、起動入口から最初のフロー（例：`ProcedurePreload`）が正常に起動されること、およびコンソールに重複初期化に関するエラーが表示されないことを確認します。

## 従来モード vs StartupRunner モード

| モード | トリガー位置 | 入口設定 | 適用シーン |
|------|---------|---------|---------|
| 従来モード（チェックボックス未チェック） | `ProcedureComponent.Start()` で自動 | Inspector の `Available Procedures` と `Entrance Procedure` | フローコンポーネントを単体で使用し、統一起動入口を組み込まない場合 |
| StartupRunner モード（チェックボックスをチェック） | `ApplicationStartupEntry` + `StartupRunner.Run` | 起動入口のランタイムコードで決定 | GameFrameX 統一起動入口を使用する統一パイプラインの場合 |

## よくあるエラー

- **Already exist FSM**：両方のモードが同時に有効になり、`Initialize` が 2 回呼び出される。解決方法：必ず一方のモードのみで初期化をトリガーするか、`Use Startup Runner` をチェックしたまま `Start()` 内のインライン起動を削除してください。
- **入口フローが null**：`m_EntranceProcedureTypeName` に有効な型名が指定されていない場合、従来モードでは `Entrance procedure is invalid.` を出力して終了します。StartupRunner モードでは、自身の入口コード内で入口フローを指定する必要があります。
- **フロー型が見つからない**：`Utility.Assembly.GetType(...)` が null を返す場合、`Can not find procedure type '{0}'.` が出力されます。型の完全名に名前空間が含まれており、かつアセンブリが読み込まれているか確認してください。

## 背景

`UseStartupRunner` を有効にすると、`Awake` では引き続き `GameFrameworkEntry.GetModule<IProcedureManager>()` を通じてフローマネージャーを登録し参照を保持しますが、「フロー配列の構築 → `Initialize` → `StartProcedure`」の 3 ステップを `ApplicationStartupEntry` の `StartupRunner.Run` まで遅延させます。これにより、フロー起動が統一起動入口のオーケストレーション下で制御され、他のサブシステムと統一パイプライン下でシリアル/パラレルに起動されるようになります。
