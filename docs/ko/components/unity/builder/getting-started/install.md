# 설치 및 통합

`com.gameframex.unity.builder`를 Unity 프로젝트에 통합하면 명령줄을 통해 `GameFrameX.Builder.Editor.Builder.BuildApk` 등의 메서드를 호출하여 APK/IPA와 리소스 패키지 빌드, 업로드, 알림 전송을 자동으로 완료할 수 있습니다. 이 페이지에서는 처음부터 시작하는 통합 단계와 가장 간단한 검증 방법을 제공합니다.

## 사전 요구 사항

- Unity 2019.4 이상 버전
- 이미 존재하는 Unity 프로젝트(`Assets/`, `ProjectSettings/`, `Packages/` 포함)

## 작업 단계

### 방법 1:Scoped Registry(권장)

1. 프로젝트 루트 디렉터리의 `Packages/manifest.json`을 엽니다.
2. 파일 최상위에 `scopedRegistries` 섹션을 추가하고, `com.gameframex` 네임스페이스를 GameFrameX의 UPM 소스로 지정합니다:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ]
   }
   ```

   `scopes`는 이 레지스트리를 통해 어떤 패키지를 해석할지 제어합니다. `com.gameframex`로 시작하는 패키지만 해당 소스에서 가져옵니다.

3. `dependencies`에 builder 패키지를 선언합니다:

   ```json
   {
     "dependencies": {
       "com.gameframex.unity.builder": "2.2.0"
     }
   }
   ```

4. Unity 편집기로 돌아가면 Package Manager가 자동으로 패키지를 해석하고 가져옵니다.

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.md#L40-L66) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L36-L74)

### 방법 2:Git URL(GitHub 직접 연결)

`Packages/manifest.json`의 `dependencies`에 Git 주소를 직접 입력합니다:

```json
{
  "dependencies": {
    "com.gameframex.unity.builder": "https://github.com/GameFrameX/com.gameframex.unity.builder.git"
  }
}
```

또는 Unity에서 **Window → Package Manager → Add package from git URL**을 열고 위의 주소를 붙여넣은 후 **Add**를 클릭합니다.

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.md#L66)

### 방법 3:Packages 디렉터리에 클론

```bash
git clone https://github.com/GameFrameX/com.gameframex.unity.builder.git
mv com.gameframex.unity.builder YourProject/Packages/
```

저장소 디렉터리를 프로젝트의 `Packages/` 아래에 배치하면, Unity가 시작될 때 자동으로 로컬 패키지로 로드하여 인식합니다.

## 통합 검증

명령줄을 사용하여 빌드 진입 메서드를 한 번 트리거하여 패키지가 올바르게 로드되었는지 확인합니다:

```bash
Unity -batchmode -nographics -projectPath /path/to/YourProject \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
      -BUILD_NUMBER 1 \
      -logFile -
```

매개변수 설명:

| 매개변수 | 필수 여부 | 설명 |
|------|------|------|
| `-executeMethod` | 예 | 실행할 진입 메서드, 예: `GameFrameX.Builder.Editor.Builder.BuildApk` |
| `-BUILD_NUMBER` | 예 | 빌드 번호 |
| `-logFile` | 아니오 | 로그 파일 경로; `-` 전달 시 stdout으로 출력 |
| `-BundleId` | 아니오 | 앱 패키지명, 기본적으로 Player Settings에서 가져옴 |
| `-AppVersion` | 아니오 | 앱 버전 번호, 기본적으로 Player Settings에서 가져옴 |
| `-ChannelName` | 아니오 | 채널 이름, 기본값 `default` |

Unity가 시작한 후 `MissingMethodException` 또는 패키지를 찾을 수 없다는 오류가 보고되지 않으면 통합에 성공한 것입니다. 전체 매개변수 설명은 《명령줄 매개변수》를 참조하세요.

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.md#L68-L88) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L75-L95)

## 일반적인 변형

- **리소스 빌드 파이프라인만 사용**: `-executeMethod`를 `GameFrameX.Builder.Editor.Builder.BuildAsset`로 바꾸고 필요에 따라 `-PackageName`, `-BuildPipeline`, `-IsIncrementalBuildPackage` 등의 매개변수를 추가합니다.
- **오브젝트 스토리지 자동 업로드 통합**: 명령에 `-ObjectStorageKey` / `-ObjectStorageSecret` / `-ObjectStorageBucketName` / `-ObjectStorageEndPoint`를 추가합니다.
- **버전 번호 하나만 변경**: `Packages/manifest.json`에서 `com.gameframex.unity.builder`의 버전 번호를 직접 편집하면 Unity가 자동으로 다시 해석합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Package Manager에서 `Could not find scoped registry` 오류 보고 | `manifest.json`의 `scopedRegistries` 철자 또는 위치 오류 | JSON 최상위에 `scopedRegistries`가 있는지 확인하고 `url`에 접근 가능한지 확인 |
| `Unable to resolve package com.gameframex.unity.builder` | `com.gameframex`를 `scopes`에 추가하지 않았거나 registry가 설정되지 않음 | `scopedRegistries[0].scopes`에 `com.gameframex`를 추가 |
| 명령줄 실행 시 `MissingMethodException: Builder.BuildApk` 오류 보고 | 패키지가 올바르게 가져오지 않았거나 메서드가 잘림 | `Packages/com.gameframex.unity.builder/`와 `Library/PackageCache/`의 캐시를 삭제한 후 다시 가져오기 |
| Unity 시작 후 콘솔에 `License/CHANGELOG not found` 경고 표시 | 이전 버전 패키지 사양 누락 | 2.2.1 이상으로 업그레이드, 해당 버전에서 `LICENSE`/`CHANGELOG`/`url`/`unity` 필드를 보완 |

## 배경(선택 사항)

이 패키지는 UPM 표준 패키지로 배포되며, 현재 최신 버전은 2.2.1(패키지 사양 파일 보완)이고 권장 버전은 2.2.0입니다. 저장소 자체는 어떠한 타사 UPM 패키지에도 의존하지 않으며, 통합 비용은 단 한 줄의 JSON 설정뿐입니다.
