# Get Started with the Startup Flow in 5 Minutes

By following the steps on this page, it takes only about 5 minutes to go from installing the package to getting a `StartupRunner.Run(...)` call working: create a `StartupOptions` asset, implement two interfaces, and attach a bootstrap script to start.

## Prerequisites

- Unity 2019.4+
- GameFrameX framework and its dependencies installed: `com.gameframex.unity` / `com.gameframex.unity.procedure` / `com.gameframex.unity.fsm` / `com.gameframex.unity.event` / `com.gameframex.unity.cysharp.unitask`
- YooAsset (if the hotfix patching flow is enabled)

## Steps

### 1. Install the Package

Add the `com.gameframex.unity.startup` dependency in `Packages/manifest.json` and configure the GameFrameX scoped registry:

```json
{
  "dependencies": {
    "com.gameframex.unity.startup": "1.1.0"
  },
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ]
}
```

`scopes` ensures that only packages with the `com.gameframex` prefix are resolved from this registry.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L20-L39)

### 2. Create the Configuration Asset

Unity menu: `Create > GameFrameX > Startup Options`. This generates a `StartupOptions` ScriptableObject asset with commonly used items:
- `GlobalInfoUrls`: primary and fallback URL list for the global info API
- `GamePlayMode`: resource play mode, synced to the Asset component before startup
- `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`: hotfix entry
- `PackageName` / `Channel` / `SubChannel`: HTTP common parameters
- `LauncherUIResName`: launcher UI resource path (default `UI/UILauncher`)
- `SkipRemoteStartupRequests`: skip all remote startup requests (enable for WebGL standalone or when there is no backend)

### 3. Implement the UI Handler

Implement `IStartupUIHandler`; the framework calls back UI states through this interface:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class GameStartupUIHandler : IStartupUIHandler
{
    public UniTask StartAsync(string uiResName) { /* Load UI */ return UniTask.CompletedTask; }
    public void SetTipText(string text) { /* Update tip text */ }
    public void SetProgress(float progress, string sizeInfo) { /* Update progress bar */ }
    public void SetProgressUpdateFinish() { /* Mark as finished */ }
    public void Dispose() { /* Close UI, release subscriptions */ }
}
```

### 4. Implement the Hotfix Launcher (Optional)

If you need to enable hotfixing, implement `IHotfixLauncher`:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class HybridClrHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        // Load the hotfix assembly according to options.HotfixAssemblyName
        // Invoke options.HotfixEntryTypeName.options.HotfixEntryMethodName
        return HotfixLaunchResult.Succeed();
    }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L67-L79)

### 5. Start

Attach a bootstrap script to any GameObject and call `StartupRunner.Run` after the scene is loaded:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;
using UnityEngine;

public class GameBootstrap : MonoBehaviour
{
    [SerializeField] private StartupOptions _options;

    private async void Start()
    {
        var uiHandler = new GameStartupUIHandler();
        var hotfixLauncher = new HybridClrHotfixLauncher();

        var result = await StartupRunner.Run(_options, uiHandler, hotfixLauncher);

        if (result.Success)
        {
            // Startup completed, the game is ready
        }
        else
        {
            Debug.LogError($"Startup failed at {result.FailedProcedureName}: {result.ErrorMessage}");
        }
    }
}
```

`StartupResult` contains the `Success` / `FailedProcedureName` / `FailedUrl` / `ErrorMessage` fields.

## Common Variants

### Decouple Notifications with Event Subscriptions

Instead of directly `await`-ing, subscribe to the completion/failure events:

```csharp
GameApp.Event.Subscribe(StartupCompletedEventArgs.EventId, OnStartupCompleted);
GameApp.Event.Subscribe(StartupFailedEventArgs.EventId, OnStartupFailed);
```

`StartupCompletedEventArgs` and `StartupFailedEventArgs` are fired via `GameApp.Event.Fire`; both the await path and the event path will receive the notification.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L107-L112)

### WebGL / Standalone Deployment

Check `StartupOptions.SkipRemoteStartupRequests` to true to skip all remote startup requests (global info / app version / resource package version) and only run local YooAsset initialization.

### Primary/Fallback URL Failover

Configure multiple URLs in `StartupOptions.GlobalInfoUrls`; the framework tries them in order, and bounded retries per URL are controlled by `MaxAttemptsPerUrl`.

## Common Mistakes

- **No `async void` on `Start`**: `StartupRunner.Run` returns `UniTask<StartupResult>`; the bootstrap method must be `async void Start()`, otherwise the UniTask will not be driven.
- **Menu item `Create > GameFrameX > Startup Options` not found**: the package was not imported correctly; check `scopedRegistries` and `dependencies` in `Packages/manifest.json`.
- **Hotfix entry cannot be invoked**: if any of `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` is misspelled, the startup will report `FailedProcedureName` in the procedure FSM; check the log `result.ErrorMessage`.
- **Repeated startup**: repeated calls in the same scene will rebuild the procedure FSM; `StartupRunner.Run` is a one-shot entry point, do not call it in `OnEnable`.

## Background (Optional)

`StartupRunner.Run(options, uiHandler, hotfixLauncher)` internally builds a procedure FSM, writes the three instances `options` / `uiHandler` / `hotfixLauncher` into fixed BlackBoard keys (`__startup_options__` / `__startup_ui_handler__` / `__startup_hotfix_launcher__`), and all procedure states read them via `IFsm<IProcedureManager>.GetData<VarObject>(key)`; the completion result is exposed as a `UniTask<StartupResult>` through `__startup_completion_source__`. See `BlackBoardKeys.cs` for the full list of blackboard constants.
