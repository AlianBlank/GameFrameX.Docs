# 설정 로드 실패 시 대처 방법

`ConfigComponent`를 통해 전역 설정을 등록하거나 읽을 때, `LoadConfigFailureEventArgs`(이벤트 번호는 `LoadConfigFailureEventArgs`의 전체 클래스명)가 발생하거나, `GetConfig<T>()` 호출이 `default`/`null`을 반환하는 경우, 일반적으로 하위 `ConfigManager`가 설정 데이터를 가져오지 못했음을 의미합니다. 이 페이지는 원인을 빠르게 파악하고 수정하는 데 도움을 줍니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| 로그에 `Config manager is invalid.` 출력 | `ConfigComponent.Awake` 시 `IConfigManager` 구현체를 가져오지 못함 | [ConfigManager 미주입](#configmanager-미주입) 참조 |
| `GetConfig<T>()`가 `null` / `default(T)` 반환 | 리소스 로드는 성공했지만 `Add`를 통해 매니저에 등록되지 않았거나, 리소스명과 타입명이 일치하지 않음 | [ConfigComponent에 미등록](#configcomponent에-미등록) 참조 |
| `LoadConfigFailureEventArgs` 수신, `ErrorMessage`에 `IOException` / 파싱 실패 포함 | 설정 바이너리 / JSON 리소스가 생성되지 않았거나 코드와 동기화되지 않음 | [설정 리소스 누락 또는 형식 손상](#설정-리소스-누락-또는-형식-손상) 참조 |
| `HasConfig<T>()`가 항상 `false` 반환 | 이름 키 조회 시 대소문자 구분 비교(`StringComparer.Ordinal`) 사용 | [설정 이름 대소문자 불일치](#설정-이름-대소문자-불일치) 참조 |

## 해결 단계

### ConfigManager 미주입

`ConfigComponent.Awake`는 `GameFrameworkEntry.GetModule<IConfigManager>()`를 통해 매니저 구현체를 가져옵니다. 프레임워크에 `ConfigManager`가 등록되지 않은 경우 즉시 치명적 로그를 기록하고 바로 반환하며, 이후 모든 읽기/쓰기가 무효가 됩니다.

[ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85) 에서:

```csharp
protected override void Awake()
{
    m_ConfigNameTypeMap.Clear();
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IConfigManager);
    base.Awake();
    m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
    if (m_ConfigManager == null)
    {
        Log.Fatal("Config manager is invalid.");
        return;
    }
}
```

프로젝트 내에 `GameFrameX.Config.Runtime.ConfigManager` 어셈블리가 포함되어 있는지 확인하고, 부트스트랩 단계에서 비즈니스 코드보다 먼저 프레임워크 초기화가 트리거되도록 하십시오(프레임워크의 `[GameFrameXAutoComponent(-5000)]` 특성은 일반 비즈니스 컴포넌트보다 먼저 등록되도록 보장합니다).

### ConfigComponent에 미등록

`ConfigComponent` 자체는 "이름으로 저장 및 조회"만 담당하며, **리소스 로드를 책임지지 않습니다**. 설정을 읽기 전에 반드시 파싱된 `IDataTable`을 매니저에 명시적으로 추가해야 합니다:

```csharp
ConfigComponent.Instance.Add(typeof(MyConfig).Name, myDataTableInstance);
var cfg = ConfigComponent.Instance.GetConfig<MyConfig>();
```

[ConfigComponent.cs#L182-L185](/Runtime/Config/ConfigComponent.cs#L182-L185) 에서:

```csharp
public void Add(string configName, IDataTable dataTable)
{
    m_ConfigManager.AddConfig(configName, dataTable);
}
```

`Add`를 건너뛰고 직접 `GetConfig<T>()`를 호출하면, `ConfigManager` 내부 딕셔너리에 해당 키가 없어 `default`를 반환하고 `LoadConfigFailureEventArgs`가 트리거됩니다.

### 설정 리소스 누락 또는 형식 손상

리소스 시스템을 통해 비동기적으로 바이너리/JSON을 로드하여 `IDataTable`로 역직렬화할 때, 파일이 없거나 버전이 일치하지 않거나 역직렬화에서 예외가 발생하면 리소스 계층에서 실패 이벤트 `LoadConfigFailureEventArgs`를 콜백합니다. 해당 필드의 의미는 다음과 같습니다:

[LoadConfigFailureEventArgs.cs#L43-L65](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L43-L65) 에서:

```csharp
public sealed class LoadConfigFailureEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(LoadConfigFailureEventArgs).FullName;

    public LoadConfigFailureEventArgs()
    {
        ConfigAssetName = null;
        ErrorMessage = null;
        UserData = null;
    }

    public override string Id { get { return EventId; } }
    public string ConfigAssetName { get; private set; }
    public string ErrorMessage    { get; private set; }
    public object UserData        { get; private set; }
}
```

확인 포인트:

1. 이벤트를 구독할 때 `e.ConfigAssetName`과 `e.ErrorMessage`를 출력하여 어떤 리소스가 실패했는지 파악합니다;
2. 설정을 다시 내보내기/생성합니다(Excel/Lua/JSON이 다시 내보내기 되었는지, 바이너리가 StreamingAssets 또는 Addressables로 다시 패키징되었는지 확인);
3. 설정 구조체의 필드가 변경된 경우, 코드와 데이터 테이블을 재생성했는지 확인합니다. 이전 바이너리는 역직렬화할 수 없습니다.

### 설정 이름 대소문자 불일치

`ConfigManager`는 딕셔너리를 생성할 때 `StringComparer.Ordinal`을 사용하며, 이는 **엄격하게 대소문자를 구분**하고 문화권과 무관합니다:

[ConfigManager.cs#L58-L61](/Runtime/Config/ConfigManager.cs#L58-L61) 에서:

```csharp
public ConfigManager()
{
    m_ConfigDatas = new ConcurrentDictionary<string, IDataTable>(StringComparer.Ordinal);
}
```

`ConfigComponent.GetTypeName<T>()`은 `typeof(T).Name`을 사용하는 반면, 전달하는 `configName`의 대소문자가 다르면 서로 다른 키로 취급됩니다. 등록과 조회 시 문자열이 완전히 일치하도록 해야 합니다.

## 검증

수정 후, 다음 방법으로 문제가 해결되었는지 확인합니다:

1. `Log.Fatal("Config manager is invalid.")` 더 이상 나타나지 않음;
2. `HasConfig<T>()`이 대상 타입에 대해 `true` 반환;
3. `GetConfig<T>()`가 비어 있지 않은 인스턴스를 반환하고, 필드 값이 원본 데이터와 일치;
4. `LoadConfigFailureEventArgs.EventId`를 구독하여 더 이상 실패 이벤트를 받지 않음.

```csharp
GameFrameworkEvent.Get().Subscribe(LoadConfigFailureEventArgs.EventId, (sender, e) =>
{
    var args = (LoadConfigFailureEventArgs)e;
    Log.Error($"설정 로드 실패: {args.ConfigAssetName} - {args.ErrorMessage}");
});
```
