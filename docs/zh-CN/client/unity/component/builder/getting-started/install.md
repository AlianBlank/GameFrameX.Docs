# 安装与接入

把 `com.gameframex.unity.builder` 接入 Unity 工程后,你就可以通过命令行调用 `GameFrameX.Builder.Editor.Builder.BuildApk` 等方法,自动完成 APK/IPA 与资源包构建、上传和通知。本页给出从零开始的接入步骤与最简验证方式。

## 前置条件

- Unity 2019.4 或更高版本
- 一份已存在的 Unity 工程(包含 `Assets/`、`ProjectSettings/`、`Packages/`)

## 操作步骤

### 方式一:Scoped Registry(推荐)

1. 打开工程根目录下的 `Packages/manifest.json`。
2. 在文件顶层加入 `scopedRegistries` 段,把 `com.gameframex` 命名空间指向 GameFrameX 的 UPM 源:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ]
   }
   ```

   `scopes` 控制哪些包通过此注册表解析;只有以 `com.gameframex` 开头的包才会从该源获取。

3. 在 `dependencies` 中声明 builder 包:

   ```json
   {
     "dependencies": {
       "com.gameframex.unity.builder": "2.2.0"
     }
   }
   ```

4. 切回 Unity 编辑器,Package Manager 会自动解析并导入包。

### 方式二:Git URL(直连 GitHub)

在 `Packages/manifest.json` 的 `dependencies` 中直接填 Git 地址:

```json
{
  "dependencies": {
    "com.gameframex.unity.builder": "https://github.com/GameFrameX/com.gameframex.unity.builder.git"
  }
}
```

或者在 Unity 中打开 **Window → Package Manager → Add package from git URL**,粘贴上面的地址并点 **Add**。

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.md#L66)

### 方式三:克隆到 Packages 目录

```bash
git clone https://github.com/GameFrameX/com.gameframex.unity.builder.git
mv com.gameframex.unity.builder YourProject/Packages/
```

把仓库目录放到工程 `Packages/` 下后,Unity 启动时会自动作为本地包加载识别。

## 验证接入

用命令行触发一次构建入口方法,确认包已正确加载:

```bash
Unity -batchmode -nographics -projectPath /path/to/YourProject \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
      -BUILD_NUMBER 1 \
      -logFile -
```

参数说明:

| 参数 | 必填 | 说明 |
|------|------|------|
| `-executeMethod` | 是 | 要执行的入口方法,例如 `GameFrameX.Builder.Editor.Builder.BuildApk` |
| `-BUILD_NUMBER` | 是 | 构建号 |
| `-logFile` | 否 | 日志文件路径;传 `-` 输出到 stdout |
| `-BundleId` | 否 | 应用包名,默认取 Player Settings |
| `-AppVersion` | 否 | 应用版本号,默认取 Player Settings |
| `-ChannelName` | 否 | 渠道名称,默认 `default` |

只要 Unity 启动后没有报 `MissingMethodException` 或包找不到的错误,就说明接入成功。完整参数说明见《命令行参数》。

## 常见变体

- **只想用资源构建流水线**:把 `-executeMethod` 换成 `GameFrameX.Builder.Editor.Builder.BuildAsset`,并按需追加 `-PackageName`、`-BuildPipeline`、`-IsIncrementalBuildPackage` 等参数。
- **接入对象存储自动上传**:在命令里追加 `-ObjectStorageKey` / `-ObjectStorageSecret` / `-ObjectStorageBucketName` / `-ObjectStorageEndPoint`。
- **只改一个版本号**:直接编辑 `Packages/manifest.json` 里 `com.gameframex.unity.builder` 的版本号,Unity 会自动重新解析。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| Package Manager 报错 `Could not find scoped registry` | `manifest.json` 中 `scopedRegistries` 拼写或位置错误 | 确认 JSON 顶层有 `scopedRegistries`,且 `url` 可访问 |
| `Unable to resolve package com.gameframex.unity.builder` | 没有把 `com.gameframex` 加入 `scopes`,或未配置 registry | 在 `scopedRegistries[0].scopes` 中加入 `com.gameframex` |
| 命令行执行报 `MissingMethodException: Builder.BuildApk` | 包未正确导入,或方法被裁剪 | 删除 `Packages/com.gameframex.unity.builder/` 与 `Library/PackageCache/` 中的缓存后重新导入 |
| Unity 启动后控制台出现 `License/CHANGELOG not found` 警告 | 旧版本包规范缺失 | 升级到 ≥ 2.2.1,该版本补全了 `LICENSE`/`CHANGELOG`/`url`/`unity` 字段 |
