# Delete and Clear Settings

Through the `ISettingManager` interface, you can delete a single setting at runtime or clear all settings at once. This is commonly used for resetting player settings, clearing caches, or switching accounts.

## Prerequisites

- The initialization process in [Quick Start](../../overview/quick-start) has been completed, and `SettingManager` has been created and held by `SettingComponent`.
- The setting helper `ISettingHelper` has been set through `SetSettingHelper`, otherwise the delete/clear interfaces will throw `GameFrameworkException("Setting helper is invalid.")`.
- You need to obtain an `ISettingManager` instance. Refer to the "Get Manager" section below.

## Operation Steps

1. Get the setting manager instance.

   ```csharp
   var settingManager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>();
   if (settingManager == null)
   {
       // Usually SettingComponent is not mounted or initialization failed
       return;
   }
   ```

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

2. Delete a single setting by name. Before deleting, you can use `HasSetting` to check if it exists.

   ```csharp
   const string key = "Player.MusicVolume";
   if (settingManager.HasSetting(key))
   {
       bool removed = settingManager.RemoveSetting(key);
       if (removed)
       {
           settingManager.Save();
       }
   }
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L210-L234)

3. Clear all settings at once (use with caution, this will remove all keys).

   ```csharp
   settingManager.RemoveAllSettings();
   settingManager.Save(); // Whether to manually Save depends on the actual implementation
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L244-L249)

4. Verify the result. Enumerate the settings again to confirm the count matches expectations.

   ```csharp
   int remaining = settingManager.Count; // Should be 0 (all cleared) or 1 less than before deletion
   string[] names = settingManager.GetAllSettingNames();
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L84-L92)

## Interface Quick Reference

| Method | Signature | Behavior |
|------|------|------|
| `HasSetting` | `bool HasSetting(string settingName)` | Throws `GameFrameworkException("Setting name is invalid.")` when the setting name is empty; otherwise checks whether it exists. |
| `RemoveSetting` | `bool RemoveSetting(string settingName)` | Returns `bool` indicating whether the removal was successful. Throws an exception when the setting name is empty. |
| `RemoveAllSettings` | `void RemoveAllSettings()` | Clears all items; no return value, no errors other than parameter validation. |

Source: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L104-L133)

## Common Variations

- Delete without saving: Some backends (such as `PlayerPrefs`) require an explicit `Save` to persist data. If the process crashes after deletion, changes may be lost; this depends on the specific `ISettingHelper` implementation.
- Delete read-only/default settings: If the settings come from a serialized file, `RemoveSetting` typically only affects entries in the runtime in-memory cache and will not write back to the source file.

## Common Errors

- **"Setting helper is invalid."**: `ISettingHelper` is not set. Confirm that `SettingComponent` has been properly initialized and the helper has been assigned.
- **"Setting name is invalid."**: `settingName` is `null` or an empty string. A valid name must be provided before deletion.
- **Old values can still be read after deletion**: The backend does not auto-persist; remember to call `Save()`; or the next `Load()` will load the same-named entry back from the persistence layer.
- **Cleanup does not have the expected effect**: `RemoveAllSettings` does not reset the underlying backend (such as other unrelated keys in `PlayerPrefs`); it only clears the entries currently held by the manager.

## Background (Optional)

`SettingManager` is a thin shell. All delete/clear operations are forwarded directly to the `ISettingHelper` implementation (the abstract methods are defined in [`SettingHelperBase`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs)). Specific implementations such as `DefaultSettingHelper` and `PlayerPrefsSettingHelper` each decide whether to modify memory or sync to the underlying storage. `Save()` is called automatically when the module is shut down; see [`Shutdown`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L112-L115).
