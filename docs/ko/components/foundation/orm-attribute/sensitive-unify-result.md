# 민감 필드 표시 및 사용자 정의 정규화 결과

엔티티 속성에 `[SensitiveField]` 특성을 추가하면 해당 필드가 직렬화, 내보내기, 로그 출력 시 내장 전략 또는 사용자 정의 규칙에 따라 자동으로 마스킹됩니다. 클래스 또는 메서드에 `[CustomUnifyResult]`를 추가하면 프레임워크가 해당 대상에 지정된 이름의 정규화(통합 결과) 처리기를 적용합니다. 이 페이지에서는 두 특성의 최소 사용법과 일반적인 변형을 제시합니다.

## 사전 조건

- NuGet 패키지 `GameFrameX.Foundation.Orm.Attribute` 도입 (네임스페이스 `GameFrameX.Foundation.Orm.Attribute`).
- .NET 프로젝트에서 `System.Attribute` 특성 구문을 지원하는 C# 언어 버전 사용.

## 작업 단계

### 1. 민감 필드 표시

마스킹이 필요한 엔티티 속성에 `[SensitiveField]`를 사용하고, `MaskingStrategy`로 마스킹 전략을 지정합니다:

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }

    [SensitiveField(MaskingStrategy.Email)]
    public string Email { get; set; }

    [SensitiveField(MaskingStrategy.BankCard)]
    public string BankCard { get; set; }
}
```

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

### 2. 내장 마스킹 전략 선택

`MaskingStrategy` 열거형에는 7가지 내장 전략(`None` 제외)이 포함되어 있어 일반적인 민감 데이터 유형을 포괄합니다:

| 전략 | 동작 |
|------|------|
| `None` | 마스킹하지 않음 (기본값) |
| `Phone` | 앞 3자리와 뒤 4자리 유지 |
| `IdCard` | 앞 6자리와 뒤 4자리 유지 |
| `Email` | 첫 번째 문자와 도메인 유지 |
| `BankCard` | 뒤 4자리 유지 |
| `Name` | 성씨 유지 |
| `Address` |省市구(성/시/구) 유지, 상세 주소 마스킹 |
| `Custom` | 사용자 정의 규칙 (`KeepPrefix`/`KeepSuffix`/`CustomPattern`와 함께 사용) |

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L132-L196)

### 3. 사용자 정의 정규화 결과 표시

클래스 또는 메서드에 `[CustomUnifyResult("처리기 이름")]`을 추가하면, 프레임워크가 이름에 따라 해당 정규화 전략(예: 데이터 형식 변환, 결과 래핑, 예외 처리)을 적용합니다:

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[CustomUnifyResult("ApiResponse")]
public class UserController
{
    public User GetUser(int id) => userService.GetById(id);
}

[CustomUnifyResult("DatabaseResult")]
public class UserRepository
{
    public List<User> GetUsers() => database.Query<User>();
}
```

## 일반적인 변형

### 사용자 정의 접두사/접미사 마스킹

전략이 `MaskingStrategy.Custom`일 때, `KeepPrefix`(보존할 접두사 문자 수)와 `KeepSuffix`(보존할 접미사 문자 수)와 함께 사용합니다:

```csharp
[SensitiveField(MaskingStrategy.Custom, KeepPrefix = 1, KeepSuffix = 1)]
public string Nickname { get; set; }
```

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L59-L60)

### 사용자 정의 정규식 마스킹

더 복잡한 마스킹 규칙이 필요한 경우, `CustomPattern`을 설정하여 사용자 정의 정규 표현식을 전달합니다 (`Custom` 전략에서만 유효):

```csharp
[SensitiveField(MaskingStrategy.Custom, CustomPattern = "\\d{4}")]
public string CustomField { get; set; }
```

Source: [SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L95-L101)

### 여러 대상에 정규화 결과 표시

`[CustomUnifyResult]`는 `AttributeTargets.All`을 지원하며, 동일한 대상에 여러 번 표시할 수 있습니다 (`AllowMultiple = true`):

```csharp
[CustomUnifyResult("ApiResponse")]
[CustomUnifyResult("Audit")]
public class OrderController
{
    public Order GetOrder(int id) => orderService.GetById(id);
}
```

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| `ArgumentNullException`: `name`은 null일 수 없음 | `[CustomUnifyResult]` 생성 시 `null` 이름 전달 | 비어 있지 않은 문자열을 처리기 이름으로 사용 |
| 필드가 마스킹되지 않음 | 표시 시 `MaskingStrategy`를 전달하지 않아 기본값 `None`이 적용됨 | `[SensitiveField(MaskingStrategy.Phone)]`처럼 전략을 명시적으로 지정 |
| 사용자 정의 규칙이 적용되지 않음 | `KeepPrefix`/`KeepSuffix`/`CustomPattern`이 `Custom`이 아닌 전략에서 무시됨 | `Strategy`를 `MaskingStrategy.Custom`로 설정 |
| 필드 표시가无效 | `[SensitiveField]`를 클래스나 필드가 아닌 대상에 작성함 | 특성은 `AttributeTargets.Property`만 허용하며 속성에만 사용 가능 |

## 배경 (선택 사항)

`SensitiveFieldAttribute`는 속성에만 표시할 수 있으며 중복 표시가 허용되지 않습니다. 이는 "라이브러리 내에서는 평문, 외부 출력 시 마스킹" 원칙으로 작동합니다 — 데이터는 저장 시 원본 값을 유지하고, 외부 출력(직렬화, 내보내기, 로그) 시 전략에 따라 마스킹됩니다. `CustomUnifyResultAttribute`는 표시형 특성으로, 프레임워크 측에서 이름으로 조회하여 해당 정규화 처리기를 적용합니다. 두 가지 모두 선언적 메타데이터이며, 동작은 실행 프레임워크가 해석합니다.
