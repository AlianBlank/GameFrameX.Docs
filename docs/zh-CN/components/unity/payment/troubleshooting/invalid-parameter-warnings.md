# 调用没反应:参数为空警告速查

调用购买、消耗等接口后"没有任何反应"(不弹出支付、不触发事件),通常是因为传入参数为空或 null,`PaymentComponent` 在入口处就拦截并仅输出一条 Warning 日志后直接 `return`,请求根本没发出去。对照下表找到日志里对应的警告原文,即可定位是哪个参数没传。

## 快速诊断

| 症状(日志原文) | 触发位置/原因 | 修复 |
|------|------|------|
| `Product ID is null or empty.` | 调用 `Buy` / `BuyInApp` / `BuySubs` 时 `productId`(或 `PurchaseParams.ProductId`)为 null 或空字符串 | 传入商店后台配置的真实商品 ID/SKU,见下文「修复步骤 1」 |
| `Order ID is null or empty.` | 调用 `Buy` / `BuyInApp` / `BuySubs` 时 `orderId`(或 `PurchaseParams.OrderId`)为 null 或空字符串 | 先在自家服务器生成订单号再发起购买,见「修复步骤 2」 |
| `Purchase token is null or empty.` | 调用 `ConsumePurchase(purchaseToken)` 时购买令牌为空 | 从 `OnQueryPurchasesResult` / `OnPurchaseSuccess` 事件参数中取出真实 `PurchaseToken` 再消耗,见「修复步骤 3」 |
| `Purchase params is null.` | 调用 `Buy(PurchaseParams)` 时整个参数对象是 null | 用 `PurchaseParams` 子类构造并赋值后再传入,见「修复步骤 2」 |
| `Pay Manager is invalid.`(Fatal) | `Awake` 中 `GameFrameworkEntry.GetModule<IPaymentManager>()` 返回 null,平台实现类未正确加载 | 检查 `PaymentComponent` Inspector 上平台组件类型字段与对应渠道包是否已引入,见「修复步骤 4」 |

以上警告都只 `Log.Warning` 后立即 `return`,不会抛异常、也不会触发 `OnPurchaseFailed` —— 所以现象就是"调用没反应"。来源:[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L259)。

## 修复步骤

### 1. Product ID 为空

商品 ID 必须与商店后台配置的 SKU 完全一致(区分大小写、注意前后空格)。推荐用 `PurchaseParams` 子类构造:

```csharp
// ProductId 在构造后仍会被校验,为空同样会打 Warning 并直接 return
var param = new SomeChannelPurchaseParams(productId: "coin_pack_100", orderId: orderNo, productType: PaymentProductType.InApp);
paymentComponent.Buy(param);
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

排查要点:

- 若是从配置表/服务器读商品 ID,先打印实际值确认非空:`Debug.Log($"[{productId}]");`
- 确认没有把 `offerToken`、`customData` 这些"可空默认参数"的位置传串。
- `Buy(PurchaseParams)` 的校验顺序是:参数对象 null → `ProductId` 空 → `OrderId` 空,看日志先出哪条就能定位。

### 2. Order ID 为空或参数对象为 null

`OrderId` 是你自家服务器的订单号,购买校验会用到它,不允许为空。`PurchaseParams` 是抽象基类(`public abstract class PurchaseParams`),不能直接 `new`,必须使用各渠道子类;三个字段(`ProductId`、`OrderId`、`ProductType`)通过构造函数赋值:

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

常见踩坑:

- 订单号由异步接口生成,购买按钮在回调前就被点了 —— 在回调里再启用购买按钮。
- 旧接口 `BuyInApp` / `BuySubs` / `Buy(string, PaymentProductType, ...)` 已标 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`,但校验行为一致,迁移时同样要保证 `productId`、`orderId` 非空。

### 3. Purchase token 为空(消耗购买没反应)

`ConsumePurchase` 只接受非空 `purchaseToken`:

```csharp
public void ConsumePurchase(string purchaseToken)
{
    if (string.IsNullOrEmpty(purchaseToken))
    {
        Log.Warning("Purchase token is null or empty.");
        return;
    }

    _paymentManager.ConsumePurchase(purchaseToken);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L152)

正确做法是订阅 `OnPurchaseSuccess` 或 `OnQueryPurchasesResult` 事件,从 `PaymentEventArgs` 中拿到真实令牌后再调用消耗。

### 4. Pay Manager is invalid(Fatal)

`PaymentComponent.Awake` 按平台选择实现类类型(`m_componentAndroidType`、`m_componentIOSType`、`m_componentWebGLType`、`m_componentPCType`、`m_componentMacType`),其余平台回退到 `DefaultPaymentManager`。若 `GetModule<IPaymentManager>()` 返回 null 会打 `Log.Fatal("Pay Manager is invalid.")`。检查:

- Inspector 上平台类型字符串是否被改坏(默认如 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`);
- 对应渠道包是否已导入工程(类型不存在时 `Utility.Assembly.GetType` 解析失败);
- 当前运行平台是否落在某个 `UNITY_*` 分支内,否则走 `DefaultPaymentManager` 空实现,支付本身也不会有反应。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 验证

- 发起调用前在 Unity Console 过滤 Warning,确认不再出现上表任何一条日志。
- 参数合法时,调用会继续走到 `_paymentManager.Buy(...)` / `ConsumePurchase(...)`,随后可订阅 `OnPurchaseSuccess` / `OnPurchaseFailed` 事件确认支付链路被真正触发(事件在 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64) 上透传)。
- 用 `IsReady()` 确认支付系统已就绪再展示购买入口,可避免大量"没反应"类误报。
