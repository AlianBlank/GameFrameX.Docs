# 第一個可用流程

按照本頁的步驟，為您的 Unity 專案附加 `ProcedureComponent` 元件，撰寫兩個 `ProcedureBase` 子類別，並啟動進入流程，讓遊戲在啟動後立即開始執行。

## 前置條件

- 已安裝 `com.gameframex.unity.procedure` 套件及其相依套件 `com.gameframex.unity.fsm` 與 `com.gameframex.unity.runtime`。
- 專案入口場景中的 `GameFramework` GameObject 已掛載 `ProcedureComponent` 元件(`[AddComponentMenu("GameFrameX/Procedure")]`)。
- 您已熟悉 C# 類別繼承與 Unity Inspector 的基本用法。

## 步驟

1. **建立流程類別**。建立 `LaunchProcedure`(啟動流程，通常負責初始化基礎系統)，繼承自 `ProcedureBase`:

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

public sealed class LaunchProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 在此執行基礎模組初始化，例如設定、日誌、資源等。
    }
}
```

`ProcedureBase` 繼承自 `FsmState<IProcedureManager>`,並提供六個內建的生命週期掛鉤:`OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy`。可依需要覆寫它們。

來源:[ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

2. **建立第二個流程**(例如 `MainProcedure`),用於之後切換到主 UI 或主邏輯：

```csharp
using GameFrameX.Procedure.Runtime;

public sealed class MainProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 啟動場景、載入 UI、開始主迴圈
        ChangeState<MainProcedure>(procedureOwner); // 自訂轉換範例
    }
}
```

3. **在 Inspector 中設定流程清單**。選取掛載了 `ProcedureComponent` 的 GameObject,並填寫以下欄位：

| 欄位 | 用途 | 範例 |
|------|------|------|
| `Available Procedure Type Names` | 框架應建立並加入狀態機之所有流程類型的完整名稱(命名空間 + 類別名稱)| `MyGame.LaunchProcedure`、`MyGame.MainProcedure` |
| `Entrance Procedure Type Name` | 啟動時進入流程的完整類型名稱；必須出現在上一步驟的清單中 | `MyGame.LaunchProcedure` |

類型名稱是透過反映查詢的，因此類別必須能被 `Utility.Assembly.GetType` 找到，並且必須具有無參數建構函式。元件會自動呼叫 `Activator.CreateInstance`,並在 `Start` 中進行初始化。

來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L129-L168)

4. **進入 Play Mode**。框架將在 `Start` 中執行以下動作：

   - 以反映方式建立所有流程執行個體。
   - 呼叫 `m_ProcedureManager.Initialize(IFsmManager, procedures)` 將其註冊到 FSM。
   - 等待至影格結束，再呼叫 `m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType())` 以啟動進入流程。

   一旦進入流程的 `OnEnter` 被觸發，您的第一個可用流程便已啟動並執行中。

## 常見變化

- **手動接管啟動(StartupRunner 模式)**：在 `ProcedureComponent` 上勾選 `Use Startup Runner = true`。此時元件的 `Awake` 只會註冊 `IProcedureManager`,不會自動呼叫 `Initialize/StartProcedure`;改由 `ApplicationStartupEntry` 在您指定的位置透過 `StartupRunner.Run` 接管初始化與啟動，以避免重複的 `Initialize` 擲回「Already exist FSM」。

  來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L127)

- **未掛載元件、純程式碼初始化**：取得 `IFsmManager` 與 `IProcedureManager` 後，手動建構流程陣列並呼叫 `Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures)`,再呼叫 `StartProcedure<T>()`。

  來源:[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L156)

- **執行階段切換流程**：在某個流程的 `OnEnter` / `OnUpdate` 中呼叫 `procedureOwner.Start<TargetProcedure>()`,即可切換到另一個流程。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 日誌輸出 `Entrance procedure is invalid.` | `Entrance Procedure Type Name` 未出現在 `Available Procedure Type Names` 清單中 | 讓入口類型名稱與清單中的項目完全相符 |
| 日誌輸出 `Can not find procedure type 'X'.` | 完整類型名稱拼字錯誤，或該類型不在執行階段可載入的組件中 | 使用命名空間 + 類別名稱，並確認該組件已完成建置 |
| 日誌輸出 `Can not create procedure instance 'X'.` | 流程類別沒有可存取的無參數建構函式 | 在 `Process` 子類別中明確加入無參數建構函式(若未明確撰寫會自動產生一個，但若定義了帶參數建構函式則會被覆寫)|
| 擲回 `You must initialize procedure first.` | 在呼叫 `Initialize` 之前就存取了 `CurrentProcedure`、`StartProcedure` 等 | 先呼叫 `Initialize`,再呼叫 `StartProcedure`;或確認 `ProcedureComponent` 的 `Start` 已執行 |
| 擲回 `Procedures is invalid.` | 傳遞給 `Initialize` 的流程陣列長度為 0 | 至少傳入一個流程執行個體 |
| 重複 `Initialize` 擲回 `Already exist FSM` | 同時使用了元件自動初始化與 StartupRunner,或手動多次呼叫 `Initialize` | 二擇一：停用 `Use Startup Runner`,或讓元件僅註冊介面，改由外部程式碼統一進行初始化 |

## 背景說明(選用)

`ProcedureManager` 本質上是一個 `GameFrameworkModule`。它內部透過 `IFsmManager.CreateFsm(this, procedures)` 將所有流程註冊為有限狀態機的狀態。`ProcedureBase` 衍生自 `FsmState<IProcedureManager>`,因此流程之間的切換與銷毀直接重用了 FSM 的功能。`ProcedureComponent` 只負責在 Unity 生命週期內透過反映將類型名稱轉換為執行個體，並交給 `ProcedureManager`。

來源:[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)
