# How to Customize Helpers to Replace the Default Implementation

By creating custom derived classes of `EntityHelperBase` and `EntityGroupHelperBase`, you can take over the instantiation, creation, and release logic of entities; `EntityComponent` provides two replacement methods: reflection type names (`m_EntityHelperTypeName` / `m_EntityGroupHelperTypeName`) and direct Inspector drag-and-drop (`m_CustomEntityHelper` / `m_CustomEntityGroupHelper`).

## Prerequisites

- The GameFrameX Entity package is installed and `EntityComponent` can be found in the scene.
- Familiarity with C# inheritance and basic usage of Unity `MonoBehaviour`.
- Custom Helper classes must be placed in an assembly that can be loaded via reflection (to avoid being stripped by code trimming tools).

## Steps

1. **Create a custom entity Helper class**, inherit from `EntityHelperBase`, and implement the three abstract methods.

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;
using UnityEngine;
using YooAsset;

namespace MyGame.Entity
{
    public class MyEntityHelper : EntityHelperBase
    {
        public override object InstantiateEntity(object entityAsset)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return null;
            }
            return handle.InstantiateSync();
        }

        public override IEntity CreateEntity(object entityInstance, IEntityGroup entityGroup, object userData)
        {
            var go = entityInstance as GameObject;
            if (go == null)
            {
                Log.Error("Entity instance is invalid.");
                return null;
            }
            go.transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform);
            return go.GetOrAddComponent<Entity>();
        }

        public override void ReleaseEntity(object entityAsset, object entityInstance)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return;
            }
            handle.Release();
            Destroy((Object)entityInstance);
        }
    }
}
```

Source: [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L41-L101)

2. **(Optional) Create a custom entity group Helper class**, inheriting from `EntityGroupHelperBase`; this base class itself has no abstract members, so simply add child object management logic as needed.

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

namespace MyGame.Entity
{
    public class MyEntityGroupHelper : EntityGroupHelperBase
    {
        // Extend entity group node management here
    }
}
```

Source: [EntityGroupHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityGroupHelperBase.cs#L39-L41)

3. **Open `EntityComponent` in the scene and choose a replacement method (pick one of the two)**:

   - **Method A (reflection type name)**: Change the `Entity Helper Type Name` or `Entity Group Helper Type Name` field to the fully qualified class name (including namespace), for example `MyGame.Entity.MyEntityHelper`.
   - **Method B (direct Inspector drag-and-drop)**: Attach a `MonoBehaviour` prefab implementing the above Helper to the `Custom Entity Helper` or `Custom Entity Group Helper` field.

```csharp
// Relevant field declarations from EntityComponent
[SerializeField] private string m_EntityHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityHelper";
[SerializeField] private EntityHelperBase m_CustomEntityHelper = null;

[SerializeField] private string m_EntityGroupHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityGroupHelper";
[SerializeField] private EntityGroupHelperBase m_CustomEntityGroupHelper = null;
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L62-L68)

4. **Run the scene to verify**. `EntityComponent.Start()` creates the Helper with the following priority: it first checks whether `m_CustomEntityHelper` on the Inspector is assigned; if not, it uses `m_EntityHelperTypeName` to create the Helper via reflection through `Helper.CreateHelper`; if still null, it logs `Can not create entity helper.`.

```csharp
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
}
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L171-L175)

## Common Variants

| Scenario | Approach |
|----------|----------|
| Only replace the entity group node mounting strategy | Derive from `EntityGroupHelperBase`, keep `EntityHelperBase` using the default implementation |
| Want to access the Unity lifecycle inside the Helper | Directly use the `MonoBehaviour` methods inherited from the base class (`Awake/OnEnable/...`) |
| Assembly stripping causes reflection failure | Preserve custom Helper classes in `link.xml` or with `[Preserve]` attributes (refer to the preservation approach in [GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L6-L24)) |

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| Startup log shows `Can not create entity helper.` | Reflection type name is empty or misspelled, and `CustomEntityHelper` was not dragged in | Confirm the type name includes the namespace, e.g. `MyGame.Entity.MyEntityHelper` |
| `Awake` in the custom Helper does not trigger | The reflection creation path was used instead of Inspector drag-and-drop | Switch to Method B to attach the Helper to the `m_CustomEntityHelper` field, or manually call `Instantiate` to associate it in `CreateEntity` |
| Object is not actually destroyed after `ReleaseEntity` | The `Object.Destroy` call was omitted when overriding | Call `Destroy((Object)entityInstance)` at the end of `ReleaseEntity` |
| `MissingReferenceException` appears in release builds | Custom class was stripped by code trimming | Annotate with `[Preserve]` or add to `link.xml` |

## Background (Optional)

The built-in fields of `EntityComponent` point to `DefaultEntityHelper` / `DefaultEntityGroupHelper` by default, which internally rely on YooAsset's `AssetHandle` to complete instantiation and release (see [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L48-L100)). The purpose of custom Helpers is to allow you to replace them with Addressables, a self-developed asset pipeline, or an instantiation scheme with object pooling, without modifying the framework.
