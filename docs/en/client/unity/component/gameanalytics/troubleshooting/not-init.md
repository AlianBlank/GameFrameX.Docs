# Events Are Not Reported: What to Do About the "GameAnalyticsManager is not init." Warning

When you call interfaces such as `Event` / `StartTimer` / `StopTimer` on `GameAnalyticsComponent`, if the corresponding analytics SDK manager instance has not yet finished initializing internally, the component prints `GameAnalyticsManager is not init.` and skips that report. This warning comes from `GameAnalyticsComponent`'s uninitialized-state guard, meaning "the Provider has already created the `IGameAnalyticsManager` instance, but that instance's own `m_IsInit` is still false".

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Every `Event`/`StartTimer`/`StopTimer` call prints `GameAnalyticsManager is not init.` | The component's `Init()` has run and created the `IGameAnalyticsManager` instance, but `m_IsInit` inside the implementation class was never set to `true` (`Init(args)` does not complete the initialization, or the implementation is the "manual initialization" type and `ManualInit` has not been called yet) | See [Fix Step 1](#1-set-isinit-in-the-implementation-classs-init-or-manualinit) below |
| The console shows a `Log.Error`: `Can not find component type 'XXX'.` | The `ComponentType` type name configured in the Inspector cannot be resolved by `Utility.Assembly.GetType` (the type does not exist, or the namespace/assembly is wrong) | Verify the type name spelling and its assembly; this Provider will be skipped by `continue` |
| No warning at all, but events are not reported either | The `m_gameAnalyticsComponentProviders` list is empty, or an entry's `ComponentType` is a blank string (in that case the loop skips it directly and no instance is created); it may also be that the component-level `m_IsInit` is still false, so all calls silently `return` | Add a Provider to the "Game Analytics Component List, Report In Order" list in the component Inspector and select the implementation type; confirm the calls happen after the component's `OnEnable` |
| Reporting fails only in the very early stage right after game startup, with no warning | The component's `Init()` only runs in `OnEnable()`, so during the `Awake` phase `m_IsInit` is false and calls are silently discarded | Move the reporting logic to after the component is enabled |

The complete guard logic that triggers this warning (using `Event(string)` as an example; the other overloads and the timer interfaces have the same structure):

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

## Fix Steps

### 1. Set isinit in the implementation class's Init or ManualInit

The warning is decided by `IGameAnalyticsManager.IsInit()`, which is provided by the base class `BaseGameAnalyticsManager` and returns the protected field `m_IsInit`:

```csharp
protected bool m_IsInit = false;

/// <summary>
/// Whether it is initialized
/// </summary>
/// <returns></returns>
public bool IsInit()
{
    return m_IsInit;
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L12-L45)

`Init(Dictionary<string, string> args)` and `ManualInit(Dictionary<string, string> args)` are abstract methods, each implemented by the corresponding analytics SDK's implementation class. Check your implementation:

- If the SDK has no prerequisites such as user consent, write `m_IsInit = true;` after `Init(args)` completes the SDK initialization;
- If the SDK requires `ManualInit` (a privacy compliance flow), implementations whose `IsManualInit()` returns true must first call `GameAnalyticsComponent.ManualInit(extraArgs)` and set `m_IsInit` inside it. Note the component-side guard:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

`ManualInit` only forwards to implementations where `IsManualInit()` is true, and requires the component itself to have already run `Init()`.

### 2. Confirm the Provider is configured in the Inspector

The component calls `Init()` in `OnEnable()`, iterates over `m_gameAnalyticsComponentProviders`, creates instances of the implementation classes via reflection, and calls their `Init(args)`:

```csharp
private void OnEnable()
{
    Init();
}

public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }
            // ...create the instance, assemble args and call gameAnalyticsManager.Init(args)
        }
    }

    m_IsInit = true;
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L27-L80)

In the `GameAnalyticsComponent` Inspector in the scene (menu `Game Framework/GameAnalytics`), edit the list titled "Game Analytics Component List, Report In Order": add an element, select a type that implements `IGameAnalyticsManager` in the `ComponentType` dropdown (the dropdown options come from `Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager))`), and fill in the Key/Value parameters the implementation needs in `Setting` (e.g. AppId, SecretKey, etc., depending on the specific implementation).

### 3. Troubleshoot silent discards (no warning but nothing reported either)

The component-level guard is silent: when `!m_IsInit`, it returns directly without printing any log. If there is not even a warning, check in order:

1. Whether the call happens earlier than the component's `OnEnable` (during the `Awake` phase `m_IsInit` is still false);
2. Whether `m_gameAnalyticsComponentProviders` is an empty list or `ComponentType` is blank — in this case, no error is reported and no instance is created;
3. Whether the console shows the `Log.Error` `Can not find component type '...'` — that Provider will be skipped by `continue`.

## Verification

1. Start the game and confirm the console no longer shows the red `Can not find component type` error (this error directly causes the corresponding Provider to be skipped).
2. Call any `Event(...)` / `StartTimer(...)` and confirm the yellow `GameAnalyticsManager is not init.` warning is gone.
3. Check the corresponding analytics platform backend (e.g. ThinkingData, Shushu, etc., depending on the implementation class) to see whether events arrive; or add a temporary log inside the implementation class's `Init` to confirm `m_IsInit` has been set to true.

## Background

The warning involves two layers of guards: `GameAnalyticsComponent.m_IsInit` (component-level, set to true at `OnEnable`, silently discards when uninitialized) and each `IGameAnalyticsManager.IsInit()` (instance-level, prints this warning when uninitialized). `BaseGameAnalyticsManager` merely holds the `m_IsInit` field and exposes common capabilities such as `IsInit()` / `SetPublicProperties`; when the flag gets set is entirely decided by the concrete SDK implementation — therefore this warning almost always indicates that the implementation class's `Init`/`ManualInit` never set `m_IsInit` to true, or that the call happens before the manual initialization flow.
