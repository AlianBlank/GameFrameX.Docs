# 실행 모드가 지원되지 않거나 초기화에 실패할 때怎么办

`AssetManager`는 초기화 리소스 패키지에서 `EPlayMode`에 따라 네 가지 구체적인 초기화 메서드(에디터 시뮬레이션/싱글 플레이어/멀티 플레이어/WebGL)로 분배하며, 모드 값이 열거형 내에 없으면 직접 예외를 던집니다. 모드와 플랫폼이 일치하지 않거나 URL이 누락되거나 YooAsset이 먼저 초기화되지 않은 경우에도 초기화 실패가 발생할 수 있습니다. 다음은 일반적인 증상과 해당 해결 방법을 제시합니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `ArgumentOutOfRangeException: Unsupported play mode: <값>` | `PlayMode`가 `EPlayMode`의 네 가지 유효 값 내에 없음 | 아래 "해결 단계 1" 참조 |
| 패키징/실기에서 `EditorSimulateMode` 사용 시 리소스 로드 오류 | 비-에디터 환경에서 자동으로 `HostPlayMode`로 강제 변경되지만 URL이 설정되지 않음 | 아래 "해결 단계 2" 참조 |
| WebGL 플랫폼에서 `HostPlayMode` 등 비 Web 모드 선택 시 초기화 실패 | WebGL은 `WebPlayMode`를 강제로 사용하며, 비 Web 모드는 지원되지 않음 | 아래 "해결 단계 3" 참조 |
| `hostServerURL is null` 또는 리소스 패키지를 생성할 수 없음 | 멀티 플레이어/Web 모드에서 URL이 전달되지 않음, YooAsset이 먼저 초기화되지 않음 | 아래 "해결 단계 4" 참조 |
| `Asset manager is invalid.` | `_assetManager` 모듈이 등록되지 않음 | 아래 "해결 단계 5" 참조 |

## 해결 단계

### 1. `PlayMode` 값이 잘못됨

`AssetManager.CreateInitializationOperationHandler`는 `switch`로 네 가지 유효 모드를 매칭하며, 기본 분기에서 직접 예외를 던집니다:

```csharp
default:
{
    throw new ArgumentOutOfRangeException(nameof(PlayMode), PlayMode, $"Unsupported play mode: {PlayMode}");
}
```

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L42-L46)

`AssetComponent.GamePlayMode` 필드(Inspector에서 `m_GamePlayMode`라고 표시됨)의 값이 `EditorSimulateMode / OfflinePlayMode / HostPlayMode / WebPlayMode` 네 가지 열거형 값 중 하나이며, 외부 스크립트에서 잘못하여 `(EPlayMode)999`과 같은 정수로 설정되지 않았는지 확인하세요.

### 2. 런타임에서 `EditorSimulateMode`를 잘못 사용

`AssetComponent.Awake`는 비-에디터 환경에서 `EditorSimulateMode`를 `HostPlayMode`로 강제 변경하며, 멀티 플레이어 모드에서는 반드시 다운로드 URL을 제공해야 합니다:

```csharp
#if !UNITY_EDITOR
    if (GamePlayMode == EPlayMode.EditorSimulateMode)
    {
        GamePlayMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    GamePlayMode = EPlayMode.WebPlayMode;
#endif
#endif
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L65-L73)

해결 방법: 패키징 전에 `GamePlayMode`를 대상 플랫폼에 맞는 유효 값으로 변경하세요(싱글 플레이어는 `OfflinePlayMode`, 멀티 플레이어는 `HostPlayMode`를 사용하고 `hostServerURL`을 올바르게 입력).

### 3. WebGL 플랫폼에서 비 Web 모드 선택

WebGL은 `WebPlayMode`로 강제 변경됩니다. 여전히 `HostPlayMode`로 CDN/미니게임 방식을 진행하려면, `InitPackageAsync`를 호출할 때 올바른 `hostServerURL`과 `fallbackHostServerURL`을 전달하고, 해당 미니게임 플랫폼 매크로(`ENABLE_DOUYIN_MINI_GAME`, `ENABLE_WECHAT_MINI_GAME`, `ENABLE_KUAISHOU_MINI_GAME` 등)가 활성화되어 해당 `ByteGame/Wechat/Kuaishou` 파일 시스템 분기를 사용할 수 있도록 해야 합니다(`InitializeYooAssetWebPlayMode` 참조).

### 4. URL 누락 또는 YooAsset 미초기화

`AssetManager.Initialize`는 `InitPackageAsync`보다 먼저 호출되어야 하며, 그렇지 않으면 YooAsset 내부 상태가 완전하지 않습니다:

```csharp
public void Initialize()
{
    Log.Info($"资源系统运行模式：{PlayMode}");
    YooAssets.Initialize();
    YooAssets.SetOperationSystemMaxTimeSlice(Milliseconds > 0 ? Milliseconds : 30);
    Log.Info("Asset Init Over");
}
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L45-L54)

`InitPackageAsync`는 인자에 대해 `NotNull` 검증을 수행하며, 어느 하나라도 null이면 `ArgumentNullException`을 던집니다:

```csharp
GameFrameworkGuard.NotNull(packageName, nameof(packageName));
GameFrameworkGuard.NotNull(hostServerURL, nameof(hostServerURL));
GameFrameworkGuard.NotNull(fallbackHostServerURL, nameof(fallbackHostServerURL));
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L69-L71)

해결 방법: `AssetComponent.Start`가 트리거되었는지(이것이 `_assetManager.Initialize()`를 호출함) 확인하고, `InitPackageAsync(packageName, host, fallbackHost, isDefaultPackage:true)`를 호출할 때 유효한 URL을 전달하세요.

### 5. `Asset manager is invalid.`

`AssetComponent.Awake`가 `IAssetManager` 모듈을 가져올 수 없을 때 치명적 로그를 출력하고 직접 반환합니다:

```csharp
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L82)

해결 방법: GameFrameX 프레임워크 진입점(`GameEntry`)이 씬에 있는지 확인하고, `AssetComponent`의 `ImplementationComponentType`/`InterfaceComponentType` 설정이 올바른지 확인하여 프레임워크가 리플렉션으로 `AssetManager` 구현 클래스를 구성할 수 있도록 하세요.

## 검증

1. Unity Console에서 `资源系统运行模式：<PlayMode>` 및 `Asset Init Over` 로그를 확인할 수 있는지 확인하세요. 두 로그가 모두 나타나면 `Initialize()`가 완료된 것입니다.
2. `InitPackageAsync`를 호출한 후 `InitializationOperation`이 완료되기를 기다리세요. `true`를 반환하고 `Status == EOperationStatus.Succeed`이면 리소스 패키지가 성공적으로 초기화된 것입니다.
3. `LoadAssetAsync`를 한 번 트리거하여 `AssetHandle`을 받을 수 있고 `LastError`가 비어 있는지 확인하세요.
4. 패키징 플랫폼(WebGL/Android/iOS)에서 위 단계를 반복하여 `Unsupported play mode` 또는 `hostServerURL is null`이 더 이상 던져지지 않는지 확인하세요.
