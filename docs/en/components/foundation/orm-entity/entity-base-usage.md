# How to Write Entities by Inheriting from EntityBase / EntityBaseId

By inheriting from the framework's `EntityBase` / `EntityBaseId` entity base classes, your entity classes automatically acquire common fields such as primary key, audit fields, soft delete flag, optimistic lock version number, and enable switch, without needing to declare them repeatedly in every entity.

## Prerequisites

- The project already references the `GameFrameX.Foundation.Orm.Entity` assembly.
- Using an ORM that supports C# `Key`/`Required` data annotation attributes (such as SqlSugar / Entity Framework).

## Steps

### 1. Only the Primary Key Field Is Needed: Inherit from `EntityBaseId` / `EntityBaseId<TKey>`

If your entity only needs a primary key and doesn't care about audit fields such as creator, update time, or soft delete, simply inherit from `EntityBaseId`. The default primary key type is `long`, decorated with the `Key` and `Required` attributes.

```csharp
using System.ComponentModel.DataAnnotations;
using GameFrameX.Foundation.Orm.Entity;

public class Dictionary
{
    // Business fields
    public string Code { get; set; }
    public string Name { get; set; }
}
```

If the primary key is not `long`, use the generic version and specify the primary key type (`TKey` must be a non-nullable type):

```csharp
public class Dictionary<TKey>
    where TKey : notnull
{
    // The primary key Id is already declared by the base class
    public string Code { get; set; }
    public string Name { get; set; }
}
```

Source: [EntityBaseId.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L44-L82)

### 2. Full Audit Fields: Inherit from `EntityBase` / `EntityBase<TKey>`

Most business entities need audit, soft delete, optimistic lock, enable switch, and other fields, so directly inherit from `EntityBase`. The base class already implements interfaces such as `ISafeDeletedFilter`, `IVersionedEntity`, `ISafeEnabledFilter`, `ISafeCreatedFilter`, `ISafeUpdateFilter`, and the framework will automatically apply these filter conditions.

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class PlayerEntity : EntityBase
{
    // Provided by the base class: Id, CreatedId, CreatedTime, CreatedName,
    //            UpdateCount, UpdateTime, UpdatedId, UpdatedName,
    //            IsDeleted, DeleteTime, DeletedId, DeletedName,
    //            RowVersion, IsEnabled
    public string Name { get; set; }
    public int Level { get; set; }
}
```

Use the generic version for non-`long` primary keys:

```csharp
public class PlayerEntity<TKey> : EntityBase<TKey>
    where TKey : notnull
{
    public string Name { get; set; }
    public int Level { get; set; }
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L180)

### 3. Override Base Class Properties As Needed

All base class fields are decorated with `virtual`, so you can adjust default values or attach additional attributes in subclasses via `override`, for example, making `IsDeleted` null upon creation:

```csharp
public class OrderEntity : EntityBase
{
    public override bool? IsDeleted { get; set; }

    public string OrderNo { get; set; }
}
```

## Common Variants

| Scenario | Base Class | Key Capabilities |
|------|------|----------|
| Only the primary key is needed | `EntityBaseId` / `EntityBaseId<TKey>` | `Id` primary key field |
| Full audit + soft delete + optimistic lock + enable switch | `EntityBase` / `EntityBase<TKey>` | All base class capabilities above |
| Tenant isolation is also needed | `EntityTenantBase` / `EntityTenantBase<TKey>` | Adds `TenantId` filtering on top of `EntityBase` |
| Extended query filtering is also needed | `EntitySelectBase` / `EntitySelectBase<TKey>` | Adds `Select` filtering on top of `EntityBase` |

## Common Mistakes

- **Missing `where TKey : notnull`**: When using the generic base class, this constraint must be added; otherwise, compilation fails. The base class itself also enforces this constraint ([EntityBaseId.cs L67-L68](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L67-L68)).
- **Manually re-declaring the `Id` field**: `Id` is already provided by the base class. Do not declare it again in subclasses; otherwise, you will get compilation warnings about hiding base class members and it will break the ORM mapping.
- **Writing the entity class as non-`abstract`**: The base class is `abstract`. It is recommended to mark concrete entities as `abstract` or keep them instantiable, but business classes should avoid being inherited further.
- **Forgetting `[Key]` when customizing the primary key type**: `Id` already carries `[Key]` and `[Required]`. If your ORM relies on attributes to identify the primary key, no additional annotation is needed; only when overriding do you need to re-add `[Key]`.

## Background (Optional)

`EntityBase` aggregates 5 filter interfaces on top of `EntityBaseId` (`ISafeDeletedFilter`, `ISafeEnabledFilter`, `ISafeCreatedFilter`, `ISafeUpdateFilter`, `IVersionedEntity`). When generating SQL, the framework reads these interfaces and automatically appends conditions such as `IsDeleted = 0`, `IsEnabled = 1`, and optimistic lock checks, so the business side doesn't need to handle them manually. `EntityTenantBase` and `EntitySelectBase` are scenario-based base classes that further layer tenant isolation and extended query filtering on top of this foundation.
