# What to Do If Macro Switches Don't Take Effect or Conflict

The feature macros in this package (`FAIRYGUI_TMPRO`, `FAIRYGUI_SPINE`, `FAIRYGUI_INPUT_SYSTEM`, `WECHAT_MINI_GAME`, `DOUYIN_MINI_GAME`) **are NOT manually defined in Player Settings' Scripting Define Symbols**; instead, they are automatically toggled by `versionDefines` in `Fairygui.Runtime.asmdef` based on whether the corresponding packages are installed. In the vast majority of cases, a macro "not taking effect" means: the corresponding package isn't installed / the package name doesn't match, or you manually added the macro to the global symbols but the missing dependency causes conflict errors.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Using the Input System package but touch/click doesn't respond | `FAIRYGUI_INPUT_SYSTEM` not defined (package name doesn't match versionDefines or not installed), `Stage` takes the legacy input branch | Confirm `com.unity.inputsystem` is installed, see Step 1 below |
| TMP-related code (such as underline, faceDilate) not working | `FAIRYGUI_TMPRO` not defined, `com.unity.textmeshpro` not in the project | Install the TextMeshPro package to trigger recompilation |
| `GLoader3D` loading Spine assets has no effect / the `case PackageItemType.Spine` branch is compiled out | `FAIRYGUI_SPINE` not defined, neither spine package name matched | Install a spine package (either one matching is sufficient), see the package name list in Step 1 |
| Manually adding `FAIRYGUI_SPINE` in Player Settings causes CS0246 compilation errors (cannot find `Spine.Unity.SkeletonDataAsset` etc.) | The macro is forcibly enabled but the spine dependency is not in the project, so the Spine code in `UIPackage`/`GLoader3D` cannot compile | Remove the manually added global macro; instead, install the corresponding package so versionDefines enables it automatically |
| The entire `GTextInputWeChat` / `GTextInputDouYin` file for WeChat/Douyin mini games doesn't compile | The condition is `UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME` (same for Douyin); all three conditions are required | Switch to the WebGL platform + install the corresponding SDK package + enable the `ENABLE_*` macro on the Wx/StarkWebGL side |
| `#if` in the Editor assembly is always false | `Fairygui.Editor.asmdef`'s `versionDefines` is empty, so the editor assembly is unaware of these macros | Do not rely on these macros in Editor code; use them only in the Runtime assembly |

## Macro-to-Package Name Reference Table

The actual source of these macros is the `versionDefines` in [Fairygui.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Fairygui.Runtime.asmdef#L20-L51):

| Macro | Triggered by which package | What it controls in the source code |
|----|--------------|----------------|
| `FAIRYGUI_INPUT_SYSTEM` | `com.unity.inputsystem` | Input reading in `Stage` (switching between new/legacy input system) |
| `FAIRYGUI_TMPRO` | `com.unity.textmeshpro` | TMP rendering and property serialization for `GTextField` |
| `FAIRYGUI_SPINE` | `com.gameframex.unity.esotericsoftware.spine.spine-unity` or `com.esotericsoftware.spine.spine-csharp` (either one) | Spine loading/updating/releasing in `GLoader3D`, Spine asset binding in `UIPackage` |
| `WECHAT_MINI_GAME` | `com.qq.weixin.minigame` | Together with `UNITY_WEBGL` and `ENABLE_WECHAT_MINI_GAME`, enables the WeChat mini game input box |
| `DOUYIN_MINI_GAME` | `com.bytedance.starksdk` | Together with `UNITY_WEBGL` and `ENABLE_DOUYIN_MINI_GAME`, enables the Douyin mini game input box |

## Fix Steps

1. **First confirm the package is actually installed.** Open `Packages/manifest.json` or the Package Manager and verify that the package names below match **exactly** (versionDefines matches package names exactly and is case-sensitive):
   - `FAIRYGUI_SPINE` → `com.gameframex.unity.esotericsoftware.spine.spine-unity` **or** `com.esotericsoftware.spine.spine-csharp`
   - `FAIRYGUI_TMPRO` → `com.unity.textmeshpro`
   - `FAIRYGUI_INPUT_SYSTEM` → `com.unity.inputsystem`
   - `WECHAT_MINI_GAME` → `com.qq.weixin.minigame`
   - `DOUYIN_MINI_GAME` → `com.bytedance.starksdk`
   Note: The `references` in `Runtime/Fairygui.Runtime.asmdef` reference `spine-unity.Runtime`, `spine-unity`, `spine-csharp`, etc. simultaneously; as long as one of the spine packages is present, the macro will be enabled; if all are missing, it is recommended to keep `FAIRYGUI_SPINE` disabled as well (i.e., do not manually add the macro).
2. **Clear manually added global macros.** Open *Edit → Project Settings → Player → Scripting Define Symbols* and confirm there are **no** hand-written `FAIRYGUI_*`, `WECHAT_MINI_GAME`, `DOUYIN_MINI_GAME` entries. These macros are managed by asmdef version constraints; hard-coding them manually will keep force-compiling the related code after the packages are uninstalled, producing "type not found" errors such as CS0246.
3. **Trigger recompilation.** Unity refreshes automatically after installing/uninstalling packages; if it doesn't, right-click in the Project window and choose *Reimport All*, or restart Unity. versionDefines are re-evaluated on domain reload.
4. **Verify the three conditions for mini game platforms.** The WeChat/Douyin input box classes only compile when `UNITY_WEBGL && <platform macro> && ENABLE_*` all hold true:
   - Switch to the WebGL build target (only then is `UNITY_WEBGL` true);
   - The corresponding platform macro is automatically defined by the SDK package (see the table above);
   - `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` are provided by the Wx / StarkWebGL related packages; if your SDK version does not provide the macro, it is normal for the file to remain disabled—do not manually add it.
5. **Do not rely on these macros in Editor code.** In [Fairygui.Editor.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/Fairygui.Editor.asmdef#L15-L15), `versionDefines` is an empty array, so these macros are always invisible to the editor assembly; code that needs to branch on these macros must be placed in the `Runtime` assembly.

## Verification

- Temporarily add a compile-time self-check to any Runtime script (delete it after checking):

```csharp
#if FAIRYGUI_INPUT_SYSTEM
        Debug.Log("FAIRYGUI_INPUT_SYSTEM on");
#endif
#if FAIRYGUI_SPINE
        Debug.Log("FAIRYGUI_SPINE on");
#endif
```

- Open [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L11) or [GTextField.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextField.cs#L45-L46); if the code inside `#if` blocks is no longer grayed out in the IDE (it is grayed out when inactive), the macro has taken effect.
- CS0246 / CS0103 compilation errors previously caused by hand-written macros disappear after deleting the global macros, with no new errors in the console.
