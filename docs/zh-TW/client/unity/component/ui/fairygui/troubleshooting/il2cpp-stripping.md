# IL2CPP 建置後 UI 程式碼被裁剪怎麼辦

Unity 在 IL2CPP 打包時會執行 Managed Code Stripping（託管程式碼裁剪），把「看起來沒有被靜態引用」的類型和方法裁掉。本包的 FairyGUI 輔助器（如 `FairyGUIFormHelper`、`FairyGUILoadAsyncResourceHelper`）主要由 GameFrameX UI 框架在執行階段間接呼叫，正是容易被誤裁的目標——編輯器一切正常，實機上 UI 打不開或實例化輔助器時拋出例外。本包已透過 `[UnityEngine.Scripting.Preserve]` 特性做了全面防裁剪，若仍出現問題，通常是裁剪等級設定過高或專案自有 UI 程式碼缺少防護。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 編輯器正常，IL2CPP 實機建置後開啟 UI 失敗、介面輔助器或非同步資源輔助器實例化報錯 | `Managed Stripping Level` 設定過高，框架間接呼叫的輔助器類型被裁剪 | 見下文[步驟 1](#1-確認本包版本與-preserve-標註) 與[步驟 2](#2-降低-managed-stripping-level) |
| 包內類型/成員被裁剪，但使用的是舊版本包 | 舊版本可能未覆蓋全部成員的 `[UnityEngine.Scripting.Preserve]` 標註 | 升級本包（目前版本見 [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/package.json#L6)），見步驟 1 |
| 專案自訂的 FairyGUI 擴充元件（繼承 `GComponent`/`GObject` 的自有類別）在實機遺失 | 專案自有程式碼未做防裁剪處理，與本包無關 | 為自有類別補上 `[UnityEngine.Scripting.Preserve]` 或專案級 `link.xml`，見步驟 3 |

## 修復步驟

### 1. 確認本包版本與 Preserve 標註

本包在類別、欄位、屬性、方法級別全部標註了 `[UnityEngine.Scripting.Preserve]`，官方說明為「**IL2CPP 安全** — Preserve 特性防止 IL2CPP 建置時的程式碼裁剪」（見 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L38)）。

類別級與成員級標註的實際寫法如下，可對照你本地包內檔案確認：

```csharp
[UnityEngine.Scripting.Preserve]
internal sealed class FairyGUILoadAsyncResourceHelper : IAsyncResource
{
    [UnityEngine.Scripting.Preserve]
    private readonly Dictionary<string, UIPackageData> m_UIPackages = new Dictionary<string, UIPackageData>(32);
```

來源： [FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L47-L51)

公開輔助器類別的標註方式：

```csharp
[UnityEngine.Scripting.Preserve]
public class FairyGUIFormHelper : UIFormHelperBase
```

來源： [FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L46-L47)

方法級標註範例：

```csharp
[UnityEngine.Scripting.Preserve]

```

來源： [FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L60-L61)

若發現包內檔案缺少這些標註，先透過 Package Manager 升級本包再重新建置。

### 2. 降低 Managed Stripping Level

`[Preserve]` 只能保護「被標註的成員」；當專案整體裁剪等級過高時仍可能出現邊緣情境被裁。按以下順序調整：

1. 開啟 `Edit → Project Settings → Player → Other Settings`。
2. 將 `Managed Stripping Level`（IL2CPP 下）從 `High`/`Medium` 降為 `Low` 或 `Minimal`。
3. 重新用 IL2CPP 建置實機包驗證。

若因包體大小原因必須保持高裁剪等級，執行步驟 3 用 `link.xml` 保留整個組件。

### 3. 為專案自有程式碼補上防裁剪（或整個組件 link.xml）

本儲存庫中**未包含** `link.xml`（防裁剪完全依賴 `[UnityEngine.Scripting.Preserve]`），因此專案自有程式碼需要自行防護。兩種方式任選：

- **特性方式（推薦，與本包做法一致）**：對自訂的 FairyGUI 擴充元件、反射呼叫的表單邏輯類別逐一標註：

```csharp
[UnityEngine.Scripting.Preserve]
public class MyCustomPanel : GComponent
{
}
```

- **link.xml 方式**：在 `Assets` 下任意位置（如 `Assets/link.xml`）保留整個組件。注意這是你需要自行建立的專案檔案，本包內沒有現成的：

```xml
<linker>
  <assembly fullname="Your.GameAssembly" preserve="all"/>
</linker>
```

### 4. 檢查 FairyGUI 擴充器反射註冊鏈

本包透過反射取得組件內的 UI 輔助器實作，這條鏈路在裁剪後最容易中斷。確認以下類別在建置產物中存在（建置日誌或 `{项目}_BackUpThisFolder_ButDontShipItWithYourGame` 內的符號檔）：

- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIUIGroupHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUILoadAsyncResourceHelper`（internal 類別，經介面 `IAsyncResource` 間接呼叫，最易被裁）

## 驗證

1. 用 IL2CPP 建置實機包（Android/iOS 均可），不要用 Mono 模式重新測試。
2. 實機上依序開啟依賴不同 UI 群組的介面，確認：介面正常建立（`UIPackage.CreateObject` 路徑）、非同步載入的 UI 包（YooAsset 路徑）能正常回呼 `LoadResource`、無 `TypeLoadException`/`NullReferenceException` 之類的輔助器實例化例外。
3. 可選：在建置日誌中搜尋 `Stripping` 相關警告，確認 `GameFrameX.UI.FairyGUI.Runtime` 組件未被列入裁剪報告。

## 背景

本包的輔助器並非由業務程式碼直接 new 出來，而是由 GameFrameX UI 框架在執行階段按介面與反射方式實例化，靜態分析看不到引用，IL2CPP 就可能判定其「未使用」而裁剪。`[UnityEngine.Scripting.Preserve]` 會向裁剪器宣告「保留此成員及其被引用項」，本包從類別、欄位到方法做了全覆蓋（可見 [FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L47) 與 [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L53)），因此正常情況下你不需要為本包再編寫任何防裁剪設定。
