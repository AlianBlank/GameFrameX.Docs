# 설정 테이블을 로드하는 방법

`ConfigComponent`를 통해 하나 이상의 `IDataTable` 설정 테이블을 전역 설정 관리자에 로드하고, 게임의 어디서나 유형 또는 이름으로 읽습니다.

## 사전 조건

- 씬에 `GameFramework` 부트 컴포넌트가 이미 마운트되어 있어야 합니다(프레임워크 자체 포함). `ConfigComponent`는 `[GameFrameXAutoComponent(-5000)]`에 의해 자동으로 주입되므로 수동으로 추가할 필요가 없습니다.
- 사용자 정의 설정 클래스는 `IDataTable` 인터페이스를 구현해야 합니다([IDataTable.cs](/Runtime/Config/Config/IDataTable.cs) 참조).
- 이미 `IDataTable` 인스턴스가 있는 경우 `Add`로 주입할 수 있습니다. 자산 파일에서 로드해야 하는 경우 프레임워크의 `GameFrameX.Asset` 모듈과 함께 ScriptableObject / 바이너리를 읽은 후 `Add`를 호출하세요.

## 작업 단계

1. **컴포넌트 참조 가져오기**. `GameEntry.GetComponent<ConfigComponent>()`를 통해 컴포넌트를 가져온 다음 내부의 `IConfigManager`를 가져옵니다:

   ```csharp
   var configComponent = GameEntry.GetComponent<ConfigComponent>();
   var configManager   = GameFrameworkEntry.GetModule<IConfigManager>();
   ```

   Source: [ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85)

2. **로드 이벤트 등록**(선택 사항이지만 권장). 프레임워크는 로드 과정에서 다음 이벤트를 발생시키며, 이를 구독하여 성공 / 실패 콜백을 받을 수 있습니다:

   ```csharp
   GameFrameXEntry.GetSubscriber().Subscribe(LoadConfigSuccessEventArgs.EventId, OnLoadConfigSuccess);
   GameFrameXEntry.GetSubscriber().Subscribe(LoadConfigFailureEventArgs.EventId, OnLoadConfigFailure);
   GameFrameXEntry.GetSubscriber().Subscribe(LoadConfigUpdateEventArgs.EventId,   OnLoadConfigUpdate);
   ```

   Source: [LoadConfigSuccessEventArgs.cs#L52](/Runtime/EventArgs/LoadConfigSuccessEventArgs.cs#L52), [LoadConfigFailureEventArgs.cs#L52](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L52)

3. **설정 테이블 로드 및 주입**. 먼저 리소스 모듈을 사용하여 `IDataTable` 인스턴스를 메모리로 읽은 다음 `Add`를 호출하여 관리자에 씁니다. 예를 들어 바이너리 / 텍스트 설정 테이블을 로드합니다:

   ```csharp
   // 1) AssetComponent를 사용하여 자산을 메모리로 읽기(프로젝트마다 로드 방식이 다름)
   var dataTable = LoadMyConfigTable(); // IDataTable을 구현한 인스턴스를 반환

   // 2) 전역 설정 관리자에 주입, 이름과 유형 이름을 동일하게 유지하면 나중에 GetConfig<T>()에 용이
   configComponent.Add(nameof(MyConfigTable), dataTable);
   ```

   Source: [ConfigComponent.cs#L182-L185](/Runtime/Config/ConfigComponent.cs#L182-L185), [ConfigManager.cs#L124-L127](/Runtime/Config/Config/ConfigManager.cs#L124-L127)

4. **설정 테이블 읽기**. 제네릭 버전을 사용하는 것을 권장합니다. `typeof(T).Name`을 기반으로 설정 이름을 자동으로 매칭합니다:

   ```csharp
   if (configComponent.HasConfig<MyConfigTable>())
   {
       var cfg = configComponent.GetConfig<MyConfigTable>();
       // cfg 사용 ...
   }
   ```

   문자열 이름으로 가져올 수도 있습니다:

   ```csharp
   var cfg = (MyConfigTable)configManager.GetConfig("MyConfigTable");
   ```

   Source: [ConfigComponent.cs#L118-L143](/Runtime/Config/ConfigComponent.cs#L118-L143), [ConfigManager.cs#L152-L161](/Runtime/Config/Config/ConfigManager.cs#L152-L161)

5. **필요에 따라 제거 / 비우기**. 특정 테이블을 언로드하거나 씬을 종료할 때 정리합니다:

   ```csharp
   configComponent.RemoveConfig<MyConfigTable>(); // 단일 테이블 제거
   configComponent.RemoveAllConfigs();             // 모두 비우기
   ```

   Source: [ConfigComponent.cs#L154-L171](/Runtime/Config/ConfigComponent.cs#L154-L171)

## 일반적인 변형

- **일괄 사전 로드**: 메인 씬에 진입하기 전에 여러 테이블을 반복하여 `Add`하고, 성공 이벤트 콜백으로 프로세스를 통합하여 진행합니다.
- **핫 업데이트 교체**: 동일 이름 항목을 `Add`로 덮어쓰기만 하면 됩니다. `AddConfig`는 내부적으로 `TryAdd`를 거치므로 강제로 교체해야 하는 경우 먼저 `RemoveConfig`를 호출한 다음 `Add`를 호출하세요.
- **컴포넌트를 통하지 않음**: 직접 `GameFrameworkEntry.GetModule<IConfigManager>()`를 호출하여 `IConfigManager`를 가져온 다음 `AddConfig / GetConfig`를 호출해도 동일하게 사용할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GetConfig<T>()`가 `null` 반환 | 이름이 `typeof(T).Name`과 일치하지 않거나 `Add`가 호출되지 않음 | `Add` 시 전달된 이름과 유형 이름이 일치하는지 확인; 또는 이름으로 `GetConfig("Name")` 사용 |
| 중복 `Add` 후에도 이전 테이블이 여전히 유효함 | `AddConfig`는 `TryAdd`를 거치므로 동일 이름은 덮어쓰기되지 않음 | 먼저 `RemoveConfig`를 호출한 다음 `Add`를 호출 |
| 이벤트가 트리거되지 않음 | 이벤트 ID를 `Subscribe`하지 않음 | `LoadConfigSuccessEventArgs.EventId` 등을 구독 |
| `Config manager is invalid.` | 프레임워크 모듈이 등록되지 않았거나 파괴됨 | `GameFramework`가 시작되었으며 `Shutdown`되지 않았는지 확인 |

## 배경(선택 사항)

`ConfigComponent` 자체는 자산을 직접 구문 분석하지 않으며, `IDataTable` 컨테이너를 `IConfigManager`에 위임합니다. `ConfigManager`는 `ConcurrentDictionary<string, IDataTable>`을 사용하여 설정 항목을 저장하고, `ConfigComponent`는 유형 → 이름 매핑을 한 층 더 쌓아 `GetConfig<T>()`가 유형별로 빠르게 위치를 찾을 수 있도록 합니다. 자산 읽기 부분은 프로젝트의 `AssetComponent`가 담당하며 이 컴포넌트와 분리되어 있습니다.
