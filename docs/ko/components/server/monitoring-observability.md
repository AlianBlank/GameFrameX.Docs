# 모니터링 지표 및 헬스 체크 활성화 방법

이 페이지의 설정을 완료하면, 서비스는 `/health`(전체 헬스 상태)와 `/alive`(프로세스 생존 여부) 두 개의 HTTP 엔드포인트를 자동으로 노출하며, MongoDB 헬스 체크와 ASP.NET Core 기본 헬스 체크가 내장되어 있고, `AddServiceDefaults`를 통해 전체 서비스에 한 번에 연동됩니다.

## 사전 조건

- .NET 8+ ASP.NET Core 프로젝트(이 프레임워크는 기본적으로 .NET 9 사용)
- `Program.cs`에서 `WebApplication.CreateBuilder()`와 `builder.Build()`를 이미 호출함
- 서비스에서 `GameFrameX.AppHost.ServiceDefaults` 패키지를 참조함(프레임워크 기본 참조)

## 작업 단계

### 1. Program.cs에서 서비스 기본값 등록

`AddServiceDefaults`는 OpenTelemetry, 로그, 지표, HTTP 복원력 등의 인프라를 동시에 구성하며, 헬스 체크도 이 단계에서 함께 활성화됩니다.

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.AddServiceDefaults();
```

출처: [GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L344-L346)

### 2. 헬스 체크 엔드포인트 노출

`MapDefaultEndpoints`는 `/health`와 `/alive` 두 개의 엔드포인트를 등록합니다. `/health`는 모든 검사가 통과해야 하며, `/alive`는 `live` 태그가 붙은 검사만 통과하면 됩니다.

```csharp
var app = builder.Build();
app.MapDefaultEndpoints();
app.Run();
```

출처: [GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost.ServiceDefaults/Extensions.cs#L431-L435)

### 3. 기본 엔드포인트 확인

서비스를 시작한 후 접속합니다:

| 엔드포인트 | 용도 | 성공 응답 |
|------|------|---------|
| `/health` | 전체 헬스 체크(종속성 포함) | `Healthy` |
| `/alive` | 프로세스 생존 여부 | `Healthy` |

프로세스 생존 여부 프로브만 필요한 경우 `/alive`를 사용할 수 있으며, MongoDB 등 다운스트림 구성 요소에 의존하지 않습니다.

## MongoDB 헬스 체크 활성화

프레임워크에는 `MongoDbHealthCheck`가 내장되어 있어, DI 컨테이너에 `IMongoClient`를 등록한 후 `AddMongoDbHealthCheck`를 호출하기만 하면 `/health` 엔드포인트에 자동으로 연동됩니다.

### 1. MongoDB 클라이언트 등록

```csharp
builder.Services.AddSingleton<IMongoClient>(sp =>
    new MongoClient(builder.Configuration.GetConnectionString("MongoDb")));
```

### 2. 헬스 체크 등록

```csharp
builder.Services.AddHealthChecks()
    .AddMongoDbHealthCheck();
```

출처: [GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L42-L99)

### 3. 검사 동작 설명

`MongoDbHealthCheck`는 내부적으로 `ListDatabaseNamesAsync`를 통해 연결을 탐지하며, 연속 실패 횟수 카운트를 사용하여 플래핑을 방지합니다:

| 연속 실패 횟수 | 반환 상태 | 의미 |
|--------------|---------|------|
| 0(데이터베이스 목록 있음) | `Healthy` | 연결 정상, 실패 횟수 초기화 |
| 1 ~ 4 | `Degraded` | 일시적으로 사용 불가, 계속 재시도 가능 |
| ≥ 5 | `Unhealthy` | 연속 실패가 임계값을 초과하여 비정상으로 표시 |

출처: [GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L69-L99](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.DataBase.Mongo/HealthChecks/MongoDbHealthCheck.cs#L69-L99)

## 일반적인 변형

- **생존 프로브만 노출**: 일부 Kubernetes 배포에서는 `/alive`만 필요하므로, MongoDB 등 다운스트림 검사 등록을 생략하고 `AddServiceDefaults`의 기본 생존 검사를 직접 사용할 수 있습니다.
- **커스텀 검사 추가**: `IHealthCheck`를 구현한 후 `.AddCheck("my-check", new MyHealthCheck())`를 호출하여 기존 `IHealthChecksBuilder`에 연결합니다.
- **외부 헬스 탐지**: `/health`를 로드 밸런서 또는 APM의 탐지 URL로 사용합니다.

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| `/health` 접속 시 404 반환 | `app.MapDefaultEndpoints()`를 호출하지 않음 | `app.Run()` 이전에 `app.MapDefaultEndpoints();` 추가 |
| `/health`가 계속 `Unhealthy` 반환 | MongoDB 연결 문자열 오류 또는 서비스 미실행 | `ConnectionStrings:MongoDb` 설정을 확인하고 MongoDB에 접근 가능한지 확인 |
| MongoDB 간헐적 지터로 인한 상태 빈번한 전환 | 기본 임계값(연속 5회 실패)이 지나치게 엄격함 | `appsettings.json`에서 `MongoDbHealthCheckOptions`를 조정하거나 `Degraded` 허용 방식으로 변경 |
| 종속성 없이 생존 여부만 확인하고 싶음 | `/alive`와 `/health`를 구분하지 않음 | `/alive` 엔드포인트를 사용하거나 커스텀 검사에 `tags: new[] { "live" }` 추가 |

## 배경

헬스 체크는 `Microsoft.Extensions.Diagnostics.HealthChecks`를 기반으로 하며, 프레임워크는 `AddServiceDefaults`를 통해 `self` 검사(`live`로 태그됨)를 기본 등록하고, 두 개의 엔드포인트 경로를 노출하여 컨테이너 오케스트레이션 시스템에서 "프로세스가 살아 있는지"와 "트래픽을 받을 수 있는지"를 구분하는 데 사용합니다.

텔레메트리 및 OpenTelemetry의 전체적인 연동에 대해서는 《서비스 기본값과 텔레메트리》를 참고하십시오.
