# 列舉所有設定項目

使用 `SettingManager` 提供的方法，一次取得目前已載入的所有設定項目名稱。適用於設定的除錯、匯出、批次驗證，以及批次刪除前的預覽。

## 前置條件

- 已透過 `SettingComponent.SetSettingHelper` 注入實作（例如 `DefaultSettingHelper` 或 `PlayerPrefsSettingHelper`），並已呼叫 `Load()` 成功載入設定。
- 能夠取得 `SettingManager` 實例。常見作法是從 `GameEntry` / `SettingComponent.SettingManager` 屬性讀取。

## 操作步驟

1. 取得 `SettingManager` 實例。常見的進入點為 `GameEntry.GetComponent<SettingComponent>().SettingManager`，或 `SettingComponent` 所公開的 `GetSettingManager` 衍生方法。

2. 呼叫 `GetAllSettingNames()`，直接取得設定項目名稱的陣列。

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingManager = GameEntry.GetComponent<SettingComponent>().SettingManager;
   string[] names = settingManager.GetAllSettingNames();

   foreach (var name in names)
   {
       UnityEngine.Debug.Log(name);
   }
   ```

   來源: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L140-L260),[ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L85-L95)

3. 若想重複使用既有的清單（避免產生 GC），請使用帶有 `List<string>` 參數的多載：

   ```csharp
   var results = new System.Collections.Generic.List<string>(settingManager.Count);
   settingManager.GetAllSettingNames(results);
   ```

   來源: [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L81-L92)

4. 結合 `HasSetting` 與 `RemoveSetting`，即可進行批次驗證或批次刪除：

   ```csharp
   foreach (var name in settingManager.GetAllSettingNames())
   {
       if (name.StartsWith("tmp_") && settingManager.HasSetting(name))
       {
           settingManager.RemoveSetting(name);
       }
   }
   settingManager.Save();
   ```

   來源: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs)

## 常見變化

- **使用 `List<string>` 多載**：在迴圈中反覆呼叫列舉，或需要與其他字串集合合併時，帶清單的多載可避免重複的記憶體配置。
- **依前綴過濾**：結合 LINQ 或 `StartsWith`，以白名單／黑名單方式過濾。例如僅匯出以 `ui_*` 開頭的索引鍵。
- **搭配執行期列舉器**：`DefaultSetting` 與 `PlayerPrefsSettingHelper` 也各自提供 `GetAllSettingNames()` 的實作。若不透過管理器而是直接存取預設設定實例，介面簽章完全相同。

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| 呼叫時發生 `Setting helper is invalid.` | 未呼叫 `SetSettingHelper`，或管理器尚未初始化 | 在啟動時注入 `DefaultSettingHelper`／`PlayerPrefsSettingHelper` |
| 呼叫時發生 `Setting name is invalid.` | 傳入了空字串或 `null` | 僅對列舉回傳的項目進行二次存取，不要手動傳入空名稱 |
| 取得的陣列為空 | 未呼叫 `Load()`，或載入失敗 | 先呼叫 `Load()` 並確認回傳值，再進行列舉 |
| 變更未生效 | 未呼叫 `Save()` | 在刪除／寫入後呼叫 `settingManager.Save()` |

## 背景（選讀）

`GetAllSettingNames` 在介面層定義了 `string[]` 與 `List<string>` 兩種多載，實際的儲存方式取決於 `ISettingHelper` 的實作（`DefaultSettingHelper` 使用 `DefaultSetting` 的記憶體字典，`PlayerPrefsSettingHelper` 則使用 PlayerPrefs）。管理器只是將呼叫轉發給已注入的輔助器。因此，列舉的範圍會與 `Load()` 時載入的資料完全一致。
