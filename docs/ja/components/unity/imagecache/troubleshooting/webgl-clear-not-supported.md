# WebGL プラットフォームで RemoveCache / ClearCache が効かない場合の対処法

WebGL プラットフォームで `RemoveCache(url)` または `ClearCache()` を呼び出しても、実際にはキャッシュは一切削除されず、警告ログが出力されるだけです。これは WebGL ランタイムがローカルファイルシステムに直接アクセスできないためです。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `RemoveCache(url)` を呼び出しても画像がまだヒットする | WebGL では画像はブラウザの HTTP キャッシュによって管理され、フレームワーク側に削除可能なローカルコピーが存在しない | ブラウザ側のキャッシュ制御に切り替える（URL にバージョン番号を付与 / Cache-Control） |
| `ClearCache()` を呼び出してもディスク容量が変わらない | WebGL には「ディスクキャッシュ」という概念が存在せず、メソッドは即座に return する | ブラウザ側でクリーンアップを行う。`ClearCache` は WebGL 以外のプラットフォームでのみ呼び出す |
| `RemoveCache` / `ClearCache` を呼び出した際、Console に `ImageCache: RemoveCache is not supported on WebGL.` または `ImageCache: ClearCache is not supported on WebGL.` という警告が表示される | WebGL プラットフォームのコード分岐で明示的にその操作が無効化されている | 呼び出しを `#if !UNITY_WEBGL` で囲むか、ブラウザ側の方式に切り替える |

## 修正手順

### 1. プラットフォーム分岐が想定通りの動作であることを確認する

ソースコードでは `RemoveCache` と `ClearCache` はどちらも `#if UNITY_WEBGL` を通じて警告を返して即座に終了します：

```csharp
public void RemoveCache(string url)
{
    if (string.IsNullOrEmpty(url)) { return; }

#if UNITY_WEBGL
    Log.Warning("ImageCache: RemoveCache is not supported on WebGL.");
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    if (FileHelper.IsExists(cachePath))
    {
        FileHelper.Delete(cachePath);
    }
#endif
}

public void ClearCache()
{
#if UNITY_WEBGL
    Log.Warning("ImageCache: ClearCache is not supported on WebGL.");
#else
    if (!Directory.Exists(_config.CachePath)) { return; }
    FileHelper.CleanDirectory(_config.CachePath);
#endif
}
```

つまり、WebGL では `RemoveCache` / `ClearCache` は**「動かない」のではなく、ソースコードレベルで無効化されている**ということです。「ローカルキャッシュをクリアしよう」と試みても、何も起きません。

### 2. WebGL ではこの 2 つのメソッドを呼び出さないようにする

コードがクロスプラットフォームで動作する場合は、条件コンパイルを使って呼び出しをスキップしてください：

```csharp
public void OnUserClickClearCache()
{
#if !UNITY_WEBGL
    GameFrameX.ImageCache.Runtime.ImageCacheManager.Instance.ClearCache();
#endif
}
```

### 3. WebGL で「等価な」クリーンアップを行う

WebGL プラットフォームでは画像は `UnityWebRequestTexture` で読み込まれ、キャッシュはブラウザが管理します。「古い画像」がヒットしないようにするための一般的な方法は以下の通りです：

1. **URL にバージョン番号やハッシュを付与する**：リソースを更新するたびに URL のクエリパラメータを変更する（例：`?v=2`）。ブラウザはそれを新しいリソースリクエストとして扱います。
2. **サーバー側で適切な `Cache-Control` ヘッダーを返す**ことで、ブラウザ側の有効期限を制御する。
3. **ブラウザ側の `Caching.ClearCache()`（ブラウザ自身のストレージクリーンアップ API）を呼び出す** —— このコンポーネントはこのパスには対応していません。

### 4. `IsCached` の動作も合わせて確認する

WebGL では `IsCached(url)` も常に `false` を返します。フレームワーク内部にキャッシュコピーを保持しないため、WebGL でのヒット状態を判定するために使用してはいけません：

```csharp
public bool IsCached(string url)
{
    if (string.IsNullOrEmpty(url)) { return false; }

#if UNITY_WEBGL
    return false;
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    return FileHelper.IsExists(cachePath);
#endif
}
```

## 検証

- Editor または Standalone プラットフォームで `ClearCache()` を呼び出した後、キャッシュディレクトリ（`ImageCacheConfig.CachePath`）配下の PNG ファイルがクリアされているはずです。
- WebGL ビルドで `ClearCache()` を呼び出すと、Console に `ImageCache: ClearCache is not supported on WebGL.` という警告が表示され、IO エラーは一切発生しません。これは想定通りの分岐に入ったことを意味します。
- WebGL で修正手順 3 に従って URL のクエリパラメータを変更して再読み込みし、ブラウザが新しいリソースを取得したこと（古い画像がヒットしなくなったこと）を確認してください。

## 背景（任意）

WebGL サンドボックスには本物の「ローカルディスク」という概念がなく、`System.IO` はこのプラットフォームでは削除されています。そのため `ImageCacheManager` は WebGL 分岐では直接 `UnityWebRequestTexture` に進み、キャッシュをブラウザに任せています。これに伴い `IsCached` / `RemoveCache` / `ClearCache` も削除可能なローカルコピーを保持しないため、すべて「false を返す / 警告を出力する」早期リターンのパスを通ります。
