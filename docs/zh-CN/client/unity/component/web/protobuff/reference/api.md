# WebProtoBuff API 速查(Post / Timeout / 连接数)

本页收录 WebProtoBuff 模块的公开 API:`Post<T>` 请求方法、`Timeout` / `RequestTimeout` / `MaxConnectionPerServer` 三项配置的默认值与含义,以及请求过程中可能抛出的异常。所有条目均取自源码真实签名。

## Post 请求方法

| 名称 | 签名 | 说明 |
|------|------|------|
| `IWebProtoBuffManager.Post<T>` | `Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage` | 发送 Protobuf 消息的 POST 请求并把响应解析为 `T`;仅在启用 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 宏时可用 |
| `WebProtoBuffComponent.Post<T>` | `Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage` | Unity 组件层的同名转发方法,内部调用管理器的 `Post<T>` |

接口定义见 [IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L9-L29),组件转发见 [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108)。

`Post<T>` 内部流程:将消息包成 `MessageHttpObject`(含 `Id`、`UniqueId`、`Body`),序列化后入等待队列;响应返回后先按 `Id` 反查响应类型,若与 `T` 不一致会打错误日志并返回 `default`:

```csharp
public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
{
    DebugSendLog(message);
    var webBufferResult = await PostInner(url, message);
    if (webBufferResult.IsNotNull())
    {
        var messageObjectHttp = SerializerHelper.Deserialize<MessageHttpObject>(webBufferResult.Result);
        if (messageObjectHttp.IsNotNull() && messageObjectHttp.Id != default)
        {
            var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
            if (messageType != typeof(T))
            {
                Log.Error($"Response message type is invalid. Expected '{typeof(T).FullName}', actual '{messageType.FullName}'.");
                return default;
            }

            var messageObject = SerializerHelper.Deserialize<T>(messageObjectHttp.Body);
            DebugReceiveLog(messageObject);
            return messageObject;
        }
    }

    return default;
}
```

## 配置属性(Timeout / 连接数)

| 名称 | 类型 | 默认值 | 定义处 | 说明 |
|------|------|--------|--------|------|
| `Timeout` | `float` | `5f`(秒) | `IWebProtoBuffManager` / `WebProtoBuffManager` / `WebProtoBuffComponent` | POST 请求超时时间,单位秒;赋值时同步更新 `RequestTimeout` |
| `RequestTimeout` | `TimeSpan` | `TimeSpan.FromSeconds(5)` | `WebProtoBuffManager` | 由 `Timeout` 换算出的请求超时时长,实际发请求时使用 |
| `MaxConnectionPerServer` | `int` | `8` | `WebProtoBuffManager` | 每个服务器的最大并发连接数;同时发送中的请求数达到该值时,后续请求停留在等待队列 |
| `m_Timeout`(序列化字段) | `float` | `5f` | `WebProtoBuffComponent` | Inspector 上的"超时时间.单位:秒",`Awake` 时写入管理器 |

```csharp
public WebProtoBuffManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

public int MaxConnectionPerServer { get; set; }

public TimeSpan RequestTimeout { get; set; }
```

## 运行时行为速查

| 行为 | 依据 |
|------|------|
| 请求 Content-Type 固定为 `application/x-protobuf` | `ProtoBufContentType` 常量 |
| 非 WebGL 平台用 `HttpWebRequest`,`request.Timeout` 取 `RequestTimeout.TotalMilliseconds` | `MakeProtoBufBytesRequest` |
| WebGL 平台用 `UnityWebRequest`,`unityWebRequest.timeout` 取 `(int)RequestTimeout.TotalSeconds` | `MakeProtoBufBytesRequest` |
| 超时被捕获后以 `TimeoutException` 结束任务 | `WebExceptionStatus.Timeout` 分支 |
| 并发上限由 `MaxConnectionPerServer` 控制:仅当 `m_SendingProtoBufList.Count < MaxConnectionPerServer` 时才从等待队列出队一个请求 | `UpdateProtoBuf` |
| 关闭(Shutdown)时等待队列与发送列表中的 `WebProtoBufData` 全部归还引用池 | `ShutdownProtoBuf` |

对应源码:[WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L32-L55)(队列调度)、[WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L81-L169)(底层请求与超时异常)。

## 组件初始化

`WebProtoBuffComponent` 是挂到 Unity 场景上的封装组件,`Awake` 中从 `GameFrameworkEntry` 取模块并把 Inspector 序列化的超时写入管理器;取不到模块时会打 `Log.Fatal("Web manager is invalid.")`:

```csharp
m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
if (m_WebProtoBuffManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebProtoBuffManager.Timeout = m_Timeout;
```
