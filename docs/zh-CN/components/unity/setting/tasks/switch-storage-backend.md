# 切换存储后端

把 Setting 模块的键值存储从默认的 `UnityPlayerPrefsSettingStorage` 切换为小游戏平台 SDK 提供的存储后端，让配置数据落到小游戏平台自身的存储介质里。

## 前置条件

- 已安装 `com.gameframex.unity.setting` 包及其依赖的 GameFrameX Runtime。
- 目标平台是小游戏（微信/抖音/支付宝/快手等），并且已引入对应平台的 adapter 程序集（含 `RegisterMiniGameBackend` 调用）。
- 在 Unity Editor 中运行时不走小游戏工厂分支，仍使用 `UnityPlayerPrefsSettingStorage`，验证存储逻辑时需要打包到目标平台运行。

## 操作步骤

1. 实现自定义后端。小游戏 SDK 通常异步提供 `setStorageSync`/`getStorageSync` 接口，需要把它们包成 `ISettingStorageBackend`。最小契约包含 `Save`、`HasKey`、`DeleteKey`、`DeleteAll`、`GetInt/SetInt`、`GetFloat/SetFloat`、`GetString/SetString`。

   Source: [ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs#L1-L30)

2. 构造工厂委托并注册到 `SettingStorageBackendFactory`。在游戏启动阶段（晚于 GameFrameX 框架初始化、早于首次 `SettingComponent.Save`/`Load`）调用：

   ```csharp
   using GameFrameX.Setting.Runtime;

   SettingStorageBackendFactory.RegisterMiniGameBackend(() => new WeChatMiniGameSettingStorage());
   ```

   注册方法在传入 `null` 时会抛出 `GameFrameworkException("Storage backend factory is invalid.")`。

   Source: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

3. 工厂在运行期选择后端。`Create()` 的分支逻辑如下：

   | 构建条件 | 使用后端 |
   |----------|----------|
   | `UNITY_EDITOR` | `UnityPlayerPrefsSettingStorage`（恒定） |
   | 玩家构建且已注册 `s_MiniGameBackendFactory` | 已注册的工厂返回值 |
   | 玩家构建但未注册 | 退回 `UnityPlayerPrefsSettingStorage`（不会抛错） |

   Source: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L32-L39)

4. 让 `SettingHelperBase` 的具体实现使用该后端。包内默认 `PlayerPrefsSettingHelper` 已经直接调用 `UnityEngine.PlayerPrefs`，跨平台时要改写为委托给 `SettingStorageBackendFactory.Create()` 返回的对象，避免在不支持 `PlayerPrefs` 的平台（部分小游戏运行时）出现 API 缺失。

   Source: [UnityPlayerPrefsSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/UnityPlayerPrefsSettingStorage.cs#L9-L67)

## 常见变体

- **官方小程序 SDK adapter**：`Runtime/MiniGame/` 目录下已有微信、抖音、支付宝、快手四种 adapter（`WeChatMiniGameSettingStorage.cs` 等），分别在平台 SDK 启动时调用 `SettingStorageBackendFactory.RegisterMiniGameBackend` 注册自己的实现。直接引入对应 adapter 程序集即可，无需自行实现 `ISettingStorageBackend`。
- **加密存储**：在自定义后端里在 `SetString` 时用 AES 加密、`GetString` 时解密，再注册该后端。
- **内存/调试后端**：单元测试或调试场景可注册一个只在内存里存字典的实现，每次进程重启自动清空。

## 常见错误

- **在 `UNITY_EDITOR` 下看不到自定义后端生效**：`Create()` 在 Editor 下恒定返回 `UnityPlayerPrefsSettingStorage`，注册逻辑虽被执行但不会生效；必须打包到目标平台小程序运行。
- **注册时机过晚**：在 `SettingComponent.Save()` 或首次 `Load()` 之后才调用 `RegisterMiniGameBackend`，已缓存的 PlayerPrefs 后端不会被替换；要保证注册早于 `SettingManager` 第一次落盘。
- **注册 `null` 工厂**：直接抛出 `GameFrameworkException("Storage backend factory is invalid.")`，启动流程会被中断；传入前做空值检查。
- **未替换 `PlayerPrefsSettingHelper`**：若业务同时使用 `PlayerPrefsSettingHelper`，它直接调用 `UnityEngine.PlayerPrefs`，在不支持 PlayerPrefs 的小游戏运行时会出现编译/运行失败；要么替换为自定义 Helper，要么包一层统一的存储访问。

## 背景（可选）

存储后端的设计是把"用什么存"从 `SettingHelperBase` 派生类中剥离：平台 SDK 接入方通过 `RegisterMiniGameBackend` 注入工厂，`SettingStorageBackendFactory.Create()` 在运行时按平台挑选；Editor 永远回退到 `UnityPlayerPrefsSettingStorage` 以便调试，未注册时同样安全回退。
