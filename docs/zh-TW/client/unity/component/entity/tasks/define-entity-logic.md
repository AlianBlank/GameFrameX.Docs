# 如何定義實體業務邏輯(EntityLogic)

透過繼承 `EntityLogic` 基底類別並覆寫生命週期方法，Unity 的 `MonoBehaviour` 即可整合進 GameFrameX 的實體管理系統，自動接收顯示/隱藏/更新/父子附加等回呼。

## 前置條件

- 已安裝 `com.gameframex.unity.entity` 套件(詳見「快速開始」)。
- Prefab 必須掛載 `Entity` 元件;`EntityLogic` 子類別腳本應掛載在同一個 GameObject 上。

## 步驟

1. **建立腳本並繼承 `EntityLogic`**。檔案名稱必須與類別名稱一致，可放置於 `Assets/Scripts/` 下的任意位置。

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
   }
   ```

   來源:[Runtime/Entity/EntityLogic.cs#L35-L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L35-L40)

2. **覆寫生命週期方法**。`EntityLogic` 提供 7 個 `protected internal virtual` 回呼；依需求覆寫即可，並記得呼叫 `base` 方法以保留基底類別的行為。

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
       protected internal override void OnInit(object userData)
       {
           base.OnInit(userData);
           // 初始化元件參考等
       }

       protected internal override void OnShow(object userData)
       {
           base.OnShow(userData);
           // 實體顯示時呼叫
       }

       protected internal override void OnHide(bool isShutdown, object userData)
       {
           base.OnHide(isShutdown, userData);
           // 實體隱藏時呼叫
       }

       protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
       {
           base.OnUpdate(elapseSeconds, realElapseSeconds);
           // 每幀更新邏輯
       }
   }
   ```

   來源:[Runtime/Entity/EntityLogic.cs#L110-L198](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L110-L198)

3. **將腳本掛載到 Prefab 上**。在 Unity 編輯器中開啟 Prefab,並將 `PlayerEntity` 元件拖曳到與 `Entity` 元件相同的 GameObject 上(或掛載到任一子物件上;`Entity` 仍可透過 `GetComponentInChildren` 找到它)。

4. **透過 `EntityComponent` 顯示實體**。實體顯示時，框架會自動實例化 `EntityLogic`;業務端只需呼叫 `ShowEntityAsync<T>` 即可。

   ```csharp
   var entityComponent = GameEntry.GetComponent<EntityComponent>();

   IEntity entity = await entityComponent.ShowEntityAsync<PlayerEntity>(
       entityId: 1,
       entityAssetName: "Assets/Prefabs/Player.prefab",
       entityGroupName: "PlayerGroup"
   );
   ```

   來源:[README.zh-CN.md#L99-L145](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/README.zh-CN.md#L99-L145)

## 可覆寫的生命週期方法

| 方法 | 觸發時機 | 說明 |
|------|----------|------|
| `OnInit(object userData)` | 實體首次初始化 | 快取 `Transform`、保存原始 `Layer`,並取得 `Entity` 參考 |
| `OnShow(object userData)` | 實體進入顯示狀態 | 框架會自動將 `Available` 設為 `true`,並設定 `Visible = true` |
| `OnHide(bool isShutdown, object userData)` | 實體被隱藏 | `isShutdown=true` 表示由管理器關閉所觸發；框架會還原原始 `Layer` |
| `OnUpdate(float, float)` | 顯示期間的每一幀 | 參數為邏輯經過秒數與實際經過秒數 |
| `OnRecycle()` | 實體歸還至物件池 | 用於釋放外部資源參考 |
| `OnAttached` / `OnAttachTo` | 子實體附加至此實體 | 預設會執行 `CachedTransform.SetParent(parentTransform)` |
| `OnDetached` / `OnDetachFrom` | 子實體解除附加 | 預設會將 `Transform` 還原至原始父節點 |
| `InternalSetVisible(bool)` | 可見性變更時 | 預設會呼叫 `gameObject.SetActive(visible)`;可覆寫以自訂切換邏輯 |

來源:[Runtime/Entity/EntityLogic.cs#L110-L208](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L110-L208)

## 常用屬性

| 屬性 | 類型 | 說明 |
|------|------|------|
| `Entity` | `Entity` | 關聯實體元件的參考 |
| `Name` | `string` | 讀取/寫入 `gameObject.name` |
| `Available` | `bool` | 實體是否可用；由 `OnShow`/`OnHide` 控制 |
| `Visible` | `bool` | 實體是否可見；在不可用狀態下賦值會輸出 `Log.Warning("Entity '{0}' is not available.", Name)` |
| `CachedTransform` | `Transform` | 快取的 `Transform`,於首次 `OnInit` 時賦值 |

來源:[Runtime/Entity/EntityLogic.cs#L42-L104](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L42-L104)

## 常見錯誤

- **未呼叫 `base`**。基底類別的 `OnInit` 會快取 `Transform` 並保存原始 `Layer`,`OnShow` 會設定 `Available=true`,`OnHide` 會還原 `Layer`;略過 `base` 可能導致可見性、圖層及子節點狀態異常。
- **在生命週期之外存取 `Available`**。實體未顯示時，`Available` 為 `false`;此時寫入 `Visible` 會被基底類別攔截並發出警告，該邏輯不會執行。
- **直接對 `EntityLogic` 子類別使用 `new`**。它必須掛載到 Prefab 上，並由 `EntityComponent` 透過物件池建立；手動使用 `new` 會繞過框架的事件分發與物件池回收機制。

## 背景(選讀)

`EntityLogic` 的對應 `protected internal` 虛擬方法會由 `partial` 的 `EntityManager` 在顯示/隱藏/回收時觸發，讓業務類別無需感知物件池、資源載入與階層管理。所有方法皆具有 `protected internal` 存取修飾詞，代表它們只能在相同組件內觸發，或由 `EntityManager` 明確呼叫，不應在業務程式碼中手動呼叫。
