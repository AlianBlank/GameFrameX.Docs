# 常見問題

本文件列出使用 GameFrameX GetChannel 外掛時可能遇到的常見問題及其解決方案。

## 概述

GameFrameX GetChannel 是一個 Unity 外掛，用於在多平臺（iOS、tvOS、visionOS、Android、Editor、PC、WebGL、UWP 和主機平臺）中獲取應用分發渠道資訊。在實際使用過程中，由於平臺配置差異、程式碼混淆、資原始檔位置等問題，使用者可能會遇到各種問題。本文件旨在幫助開發者快速定位和解決這些問題。

## 平臺配置問題

### Android 平臺

#### 問題：獲取渠道返回 "default"

**症狀**：在 Android 平臺上呼叫 `BlankGetChannel.GetChannelName()` 始終返回 "default"，而不是配置的渠道值。

**原因**：Android 平臺的實現依賴於 Java 原生程式碼。當前外掛程式碼硬編碼呼叫 `com.alianhome.getchannel.MainActivity` 類中的靜態方法 `GetChannel`。

```csharp
// Runtime/BlankGetChannel.cs (第132-134行)
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```
> Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L132-L134)

**解決方案**：

您需要在您的 Android 專案中建立一個 Java 類來實現獲取渠道的邏輯。有以下兩種方式：

**方式一：使用 Gradle 外掛（推薦）**

參考 [平臺配置 - Android](./4-platform-configuration) 文件，配置 Gradle 外掛來自動注入渠道資訊。

**方式二：手動實現 Java 程式碼**

在您的 Android 原生程式碼中建立以下類：

```java
// MainActivity.java (或任何啟動 Activity)
package com.yourcompany.yourgame;

import android.app.Activity;
import android.os.Bundle;
import android.content.pm.ApplicationInfo;
import android.content.pm.PackageManager;

public class MainActivity extends Activity
{
    @Override
    protected void onCreate(Bundle savedInstanceState)
    {
        super.onCreate(savedInstanceState);
    }
    
    // 供 Unity C# 呼叫獲取渠道資訊
    public static String GetChannel(String key)
    {
        try 
        {
            ApplicationInfo appInfo = getApplicationContext()
                .getPackageManager()
                .getApplicationInfo(getPackageName(), PackageManager.GET_META_DATA);
            Bundle bundle = appInfo.metaData;
            return bundle.getString(key, "default");
        } 
        catch (Exception e) 
        {
            return "default";
        }
    }
}
```

**重要提示**：如果您不實現此 Java 類，Android 平臺會因找不到類而丟擲異常，但外掛會捕獲異常並返回預設值 "default"。

---

#### 問題：AndroidManifest.xml 配置不生效

**症狀**：已在 AndroidManifest.xml 中配置了 `<meta-data>` 標籤，但獲取渠道時仍返回預設值。

**解決方案**：

1. 確認 `<meta-data>` 標籤位於 `<application>` 標籤內部，而不是 `<activity>` 標籤內：

```xml
<application>
    <activity 
        android:name=".MainActivity"
        android:label="@string/app_name">
        <!-- meta-data 不能放在這裡 -->
    </activity>
    
    <!-- 正確位置：application 標籤內 -->
    <meta-data
        android:name="channel"
        android:value="android_cn_taptap" />
</application```
> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L113-L128)

2. 確認 `android:name` 屬性與 C# 程式碼中使用的 key 完全匹配（區分大小寫）。

### iOS / tvOS / visionOS 平臺

#### 問題：iOS 構建後 Info.plist 沒有渠道資訊

**症狀**：使用 Unity 構建 iOS 專案後，Info.plist 中沒有自動新增渠道資訊。

**原因**：外掛的 `PostProcessBuildHandler` 會在構建時檢查 Info.plist，如果已存在 `channel` 鍵，則不會新增預設值。

```csharp
// Editor/PostProcessBuildHandler.cs (第39-47行)
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳過設定=>" + value);
}
```
> Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L39-L47)

**解決方案**：

1. 如果需要設定自定義渠道值，請在構建前手動在 Info.plist 中新增 `channel` 鍵值對
2. 如果希望使用預設值 "default"，請確保 Info.plist 中沒有 `channel` 鍵

---

#### 問題：iOS 渠道獲取返回 null 或空字串

**症狀**：在 iOS 平臺上獲取渠道時返回空值或 null。

**可能原因**：

1. **Info.plist 配置錯誤**：鍵名與程式碼呼叫不匹配
2. **P/Invoke 問題**：原生方法未正確連結

**解決方案**：

1. 確認 Info.plist 中的配置格式正確：

```xml
<key>channel</key>
<string>ios_cn_taptap</string>
```
> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L96-L104)

2. 確認 C# 程式碼中使用的 key 與 Info.plist 中的鍵名完全一致：

```csharp
// 預設 key 為 "channel"
string channel = BlankGetChannel.GetChannelName();

// 如果 Info.plist 使用了其他鍵名
string customChannel = BlankGetChannel.GetChannelName("your_custom_key");
```

---

### Editor / PC / WebGL / UWP / 主機平臺

#### 問題：Resources 檔案讀取失敗

**症狀**：在 Editor、PC、WebGL 等平臺獲取渠道時始終返回 "default"。

**原因**：外掛從 `Resources/application_config.txt` 檔案讀取配置，如果檔案不存在或格式不正確，將返回預設值。

**解決方案**：

1. 確認 `application_config.txt` 檔案位於 `Assets/Resources/` 目錄下（注意大小寫）

2. 確認檔案內容格式正確（每行 `key=value`）：

```
channel=editor_cn_test
sub_channel=beta
```
> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L136-L142)

3. 檢查 Unity 控制檯是否有資源載入失敗的警告資訊

---

#### 問題：修改配置檔案後渠道值未更新

**症狀**：修改 `application_config.txt` 後，獲取到的渠道值沒有變化。

**原因**：外掛使用快取機制避免重複讀取配置檔案。

```csharp
// Runtime/BlankGetChannel.cs (第100-103行)
if (ChannelCache.TryGetValue(channelKey, out var value))
{
    return value;
}
```
> Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L100-L103)

**解決方案**：

1. 在 Unity Editor 中重新啟動遊戲（Editor 模式下按 Play 時修改資原始檔需要重啟）
2. 如果需要強制重新整理，可以在遊戲啟動時清除快取：

```csharp
// 注意：這是內部成員，直接訪問需要透過反射或其他方式
// 建議：重啟遊戲或重新載入場景
```

## 程式碼混淆與剝離問題

### 問題：渠道獲取功能在 release build 中失效

**症狀**：在釋出版本中，`BlankGetChannel.GetChannelName()` 始終返回預設值。

**原因**：Unity 的程式碼剝離（Code Stripping）功能可能將 `BlankGetChannel` 類及相關平臺程式碼從最終構建中移除。

**解決方案**：

1. **使用 `link.xml` 檔案**（外掛已包含）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="BlankGetChannel.Runtime" preserve="all"/>
</linker>
```
> Source: [link.xml](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/link.xml#L1-L3)

2. **在類上新增 Preserve 特性**（外掛已新增）：

```csharp
// Runtime/BlankGetChannel.cs (第35行)
[UnityEngine.Scripting.Preserve]
public sealed class BlankGetChannel
```

3. **在 Unity Player Settings 中調整程式碼剝離級別**：
   - 開啟 `Edit > Project Settings > Player`
   - 在 `Other Settings` 中找到 `Managed Stripping Level`
   - 如果問題持續，將級別從 `High` 降低到 `Medium` 或 `Low`

## 鍵名配置問題

### 問題：key 名不匹配導致獲取失敗

**症狀**：使用特定 key 獲取渠道時返回預設值，而不是配置的值。

**原因**：C# 程式碼中使用的 key 與平臺配置檔案中的 key 不一致。

**解決方案**：

| 平臺 | 配置檔案位置 | 鍵名示例 |
|------|-------------|---------|
| iOS/tvOS/visionOS | Info.plist | `channel` |
| Android | AndroidManifest.xml `<meta-data>` | `channel` |
| Editor/PC/WebGL | Resources/application_config.txt | `channel=editor_cn` |

確保在所有平臺使用統一的 key 名稱，或在程式碼中明確指定正確的 key：

```csharp
// 使用預設 key "channel"
string channel = BlankGetChannel.GetChannelName();

// 使用自定義 key
string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
```

## 多平臺構建問題

### 問題：某些平臺無法獲取渠道資訊

**症狀**：在某些平臺上渠道功能正常，但在其他平臺上返回預設值。

**排查步驟**：

1. **確認當前構建的平臺**：
```csharp
Debug.Log("Current Platform: " + Application.platform);
Debug.Log("Is Android: " + Application.platform == RuntimePlatform.Android);
Debug.Log("Is iOS: " + Application.platform == RuntimePlatform.IPhonePlayer);
```

2. **檢查各平臺的配置**：
   - Android：檢查 AndroidManifest.xml 中的 meta-data
   - iOS：檢查 Info.plist 中的鍵值對
   - Editor/PC：檢查 Resources/application_config.txt 檔案

3. **檢視 Unity 控制檯日誌**：
   - iOS 構建時會輸出 "配置渠道成功" 或 "已有渠道,跳過設定"

## API 使用問題

### 問題：返回 "default" 值無法區分是否配置

**症狀**：無法判斷返回的 "default" 是來自配置還是未配置的預設值。

**解決方案**：

使用過載方法提供明確的預設值：

```csharp
// 返回 "default" 可能是因為配置了 channel=default，也可能是未配置
string channel = BlankGetChannel.GetChannelName();

// 使用明確的預設值來區分
string channel = BlankGetChannel.GetChannelName("channel", "unknown");
if (channel == "unknown")
{
    Debug.LogWarning("渠道未配置！");
}
```

## 快速診斷清單

當遇到渠道獲取問題時，請按以下順序檢查：

- [ ] **平臺配置檢查**：確認目標平臺的配置檔案已正確設定
- [ ] **鍵名一致性檢查**：確認程式碼中的 key 與配置檔案中的 key 完全一致（區分大小寫）
- [ ] **資原始檔位置檢查**：確認 application_config.txt 位於 Assets/Resources/ 目錄
- [ ] **程式碼剝離檢查**：確認 link.xml 存在且 Player Settings 未啟用激進剝離
- [ ] **日誌檢查**：檢視 Unity 控制檯是否有相關警告或錯誤資訊
- [ ] **平臺特定檢查**：
  - Android：確認 MainActivity 中實現了 GetChannel 方法
  - iOS：確認 Info.plist 中存在 channel 鍵
