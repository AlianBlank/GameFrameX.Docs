# 常见问题

本文档汇总了使用 Timer タイマーコンポーネント时可能遇到的常见问题及其解決策。

## 概要

Timer コンポーネント是 GameFrameX フレームワーク提供的タイマー機能模块，为 Unity プロジェクト提供定时任务、延迟执行和帧更新等機能サポート。在使用过程中，用户可能会遇到一些问题，本文档将提供详细的诊断和解決策。

## よくある質問与解決策

### 1. 定时器不执行

#### 症状
添加定时任务后，回调函数从未被执行。

#### 可能原因
- Timer コンポーネント未正确添加到シーン中的 GameObject
- GameFramework フレームワーク未正确初期化
- TimerManager 模块未注册

#### 解決策

**检查コンポーネント是否添加：**

```csharp
// 确保シーン中有 TimerComponent
var timerComponent = FindObjectOfType<TimerComponent>();
if (timerComponent == null)
{
    Debug.LogError("TimerComponent 未找到，お願いします先添加コンポーネント");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

**检查フレームワーク初期化：**
确保在ゲーム启动时正确初期化了 GameFramework フレームワーク。TimerComponent 会在 Awake 时从 GameFrameworkEntry 取得 ITimerManager インスタンス：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");  // タイマー管理器无效
        return;
    }
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

### 2. 回调函数参数传递问题

#### 症状
传递给回调函数的参数为 null，或者无法正确取得参数。

#### 可能原因
- 未正确传递 callbackParam 参数
- 误用了 AddOnce 的单参数重载

#### 解決策

Timer コンポーネント的回调函数签名为 `Action<object>`，参数を通じて callbackParam 传递：

```csharp
// 正确传递参数的方法
timerComponent.Add(1.0f, 1, OnTimerComplete, "这是传递的数据");

// 回调函数接收参数
private void OnTimerComplete(object param)
{
    Debug.Log($"定时器完成，参数: {param}");  // 输出: 定时器完成，参数: 这是传递的数据
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

### 3. 间隔时间单位混淆

#### 症状
定时器执行间隔与预期不符，例如設定 1000 毫秒却每秒执行多次。

#### 可能原因
**重要：Timer コンポーネント的 interval 参数单位是秒（seconds），而不是毫秒！**

README 文档中存在错误説明，实际代码中 interval 是以秒为单位的浮点数：

```csharp
// interval 参数单位为秒 (seconds)
public void Add(float interval, int repeat, Action<object> callback, object callbackParam = null)
{
    _timerManager.Add(interval, repeat, callback, callbackParam);
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

#### 解決策

```csharp
// ❌ 错误：将 1000 理解为毫秒
timerComponent.Add(1000f, 1, callback);  // 实际上会以 1000 秒的间隔执行

// ✅ 正确：将 interval 视为秒
timerComponent.Add(1.0f, 1, callback);  // 1 秒后执行一次
timerComponent.Add(0.5f, 5, callback); // 每 0.5 秒执行一次，共 5 次

// 转换为毫秒的正确写法
float intervalInSeconds = 1000f / 1000f;  // 1000 毫秒 = 1 秒
timerComponent.AddOnce(intervalInSeconds, callback);
```

### 4. 定时任务重复添加

#### 症状
使用相同回调函数多次呼び出し Add メソッド后，定时器行为異常。

#### 可能原因
TimerManager 使用回调函数作为字典键，当添加相同回调的定时器时，会更新现有定时器而非作成新定时器：

```csharp
// 代码実装：如果回调已存在，会更新现有定时器
if (_items.TryGetValue(callback, out var t))
{
    t.Set(interval, repeat, callback, callbackParam);
    t.Elapsed = 0;
    t.Deleted = false;
    return;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L173)

#### 解決策

在添加新定时器前检查是否已存在：

```csharp
// 检查定时器是否已存在
if (!timerComponent.Exists(MyCallback))
{
    timerComponent.Add(1.0f, 5, MyCallback);
}
else
{
    Debug.LogWarning("定时器已存在，お願いします先移除后再添加");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 5. 回调函数異常导致定时器崩溃

#### 症状
定时器回调中发生異常后，整个定时器系统停止工作。

#### 可能原因
默认情况下，回调函数中的異常会中断定时器的执行。

#### 解決策

TimerManager 提供します `CatchCallbackExceptions` 静态プロパティ来控制異常处理行为：

```csharp
// 启用異常捕获，防止回调異常导致定时器崩溃
TimerManager.CatchCallbackExceptions = true;

// 添加定时任务
timerComponent.Add(1.0f, 0, OnTimerTick);

// 回调函数中即使发生異常也不会终止定时器
private void OnTimerTick(object param)
{
    // 可能抛出異常的代码
    throw new Exception("模拟異常");
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L41-L43)

启用異常捕获后，異常会被捕获并记录警告日志，同时标记该定时器为已删除：

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        timerItem.Callback(timerItem.Param);
    }
    catch (Exception e)
    {
        timerItem.Deleted = true;
        Debug.LogWarning("Timer: timer(internal=" + timerItem.Interval + ", repeat=" + timerItem.Repeat + ") callback error > " + e.Message);
    }
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L86-L97)

### 6. 定时器内存泄漏

#### 症状
长时间运行后，内存占用持续增长。

#### 可能原因
- 定时任务完成后未正确移除
- 使用 AddUpdate 添加的帧更新任务未手动移除

#### 解決策

**对于重复次数有限的定时器：**
Repeat = 0 表示无限重复，Repeat > 0 会在执行指定次数后自动移除：

```csharp
// ✅ Repeat = 0 会无限重复，必要手动移除
timerComponent.Add(1.0f, 0, repeatingCallback);

// 在适当时候手动移除
timerComponent.Remove(repeatingCallback);

// ✅ Repeat > 0 会在执行完指定次数后自动移除
timerComponent.Add(1.0f, 5, limitedCallback);  // 执行 5 次后自动移除
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L73-L81)

**对于帧更新任务（AddUpdate）：**
AddUpdate 本质上使用极小间隔（0.001秒）的重复定时器，必須手动移除：

```csharp
// 添加帧更新任务
timerComponent.AddUpdate(OnUpdate);

// 在对象销毁或不必要时移除
timerComponent.Remove(OnUpdate);
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L206-L219)

### 7. 定时器精度问题

#### 症状
定时器执行时间不精确，存在较大误差。

#### 可能原因
- 使用了过小的间隔时间
- ゲーム帧率不稳定
- 切换到后台时 Unity 的时间系统会发生变化

#### 解決策

TimerManager 使用 `realElapseSeconds`（实际经过的时间）来计算定时器：

```csharp
// 内部使用 realElapseSeconds 计算经过时间
timerItem.Elapsed += realElapseSeconds;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L63-L71)

**优化建议：**

```csharp
// ❌ 避免使用过小的间隔
timerComponent.Add(0.0001f, 0, callback);  // 可能导致性能问题

// ✅ 推荐：最小间隔不低于 0.01 秒（10 毫秒）
timerComponent.Add(0.01f, 0, callback);

// 对于必要更高精度的シーン，考虑使用 Unity 的 Update 或 Coroutine
```

### 8. 在コルーチン中使用定时器

#### 症状
在コルーチン中作成的定时器行为異常。

#### 解決策

Timer コンポーネント可能在コルーチン中使用，但必要注意生命周期管理：

```csharp
IEnumerator StartTimerInCoroutine()
{
    // 在コルーチン中使用定时器
    timerComponent.AddOnce(2.0f, OnDelayComplete, "コルーチン数据");
    
    yield return new WaitForSeconds(2.0f);
    // コルーチン结束，但定时器任务可能仍在运行
}

private void OnDelayComplete(object param)
{
    Debug.Log($"延迟完成: {param}");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L48-L51)

## 诊断工具

### 检查定时器ステータス

使用 Exists メソッド检查定时器是否存在：

```csharp
// 检查特定回调的定时器是否存在
bool isRunning = timerComponent.Exists(MyCallback);

if (isRunning)
{
    Debug.Log("定时器正在运行");
}
else
{
    Debug.Log("定时器未运行或已完成");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 列出所有活动定时器

由于 TimerManager 使用字典存储定时器，可能を通じて扩展来取得活动定时器列表：

```csharp
// 注意：TimerManager 的 _items 字段是私有的
// 如需调试，可能启用日志输出
Debug.Log($"当前活动定时器数量: {活动数量}");
```

## 性能注意事项

### 1. 回调函数委托作成

每次添加定时器时，不要使用匿名Lambda表达式作为回调，因为这会作成新的委托インスタンス，导致无法正确移除定时器：

```csharp
// ❌ 错误：匿名メソッド无法移除
timerComponent.Add(1.0f, 1, (param) => Debug.Log("test"));

// ✅ 正确：使用具名メソッド
timerComponent.Add(1.0f, 1, OnTimerTick);

// 之后可能正确移除
timerComponent.Remove(OnTimerTick);

private void OnTimerTick(object param)
{
    Debug.Log("Timer tick");
}
```

### 2. 大量定时器

TimerManager 使用字典和锁実装，对于数千个同时存在的定时器可能会有性能影响。考虑合并多个定时任务或使用其他方法管理。
