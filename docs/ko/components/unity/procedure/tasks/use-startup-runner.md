# StartupRunner를 사용하여 시작을 인계받는 방법

`ProcedureComponent`는 기본적으로 `Start()`에서 자동으로 흐름을 초기화하고 시작합니다. `Use Startup Runner`를 체크하면 `Awake`에서 `IProcedureManager`만 등록하고, 실제 흐름 초기화와 시작은 `ApplicationStartupEntry` + `StartupRunner.Run`에 인계하여 "Already exist FSM" 충돌이 발생하는 것을 방지합니다.

## 사전 조건

- GameFrameX 절차 패키지(`com.gameframex.unity.procedure`)가 설치되어 있어야 합니다.
- 프로젝트에 GameFrameX 시작 파이프라인(`ApplicationStartupEntry` 및 `StartupRunner.Run`)이 연결되어 있어야 합니다. 그렇지 않으면 인계 절차가 트리거되지 않습니다.
- `ProcedureComponent`가 부착된 게임 객체가 씬에 존재해야 하며, 메뉴 `GameFrameX > Procedure`를 통해 추가할 수 있습니다.

## 작업 단계

1. 씬에서 `ProcedureComponent`가 부착된 게임 객체를 선택하고 Inspector에서 `Use Startup Runner` 체크박스(필드 `m_UseStartupRunner`에 해당)를 체크합니다.

2. 체크 후, `ProcedureComponent.Start()`는 즉시 `yield break`되며 `Initialize`도 실행하지 않고 `StartProcedure`도 호출하지 않습니다. `Awake`의 `IProcedureManager` 등록만 유지됩니다:

   ```csharp
   private IEnumerator Start()
   {
       if (m_ProcedureManager == null)
       {
           yield break;
       }

       if (m_UseStartupRunner)
       {
           // ApplicationStartupEntry + StartupRunner.Run에서 Initialize와 StartProcedure를 인계받습니다.
           // 본 컴포넌트는 Awake에서 IProcedureManager를 등록하는 역할만 수행하며,
           // 새 진입점에서 중복 Initialize로 인한 Already exist FSM 보고를 방지합니다.
           yield break;
       }
       // ...
   }
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L168)

3. `ApplicationStartupEntry`에서 `StartupRunner.Run`을 통해 절차를 시작합니다. 절차 배열을 구성하고 진입 절차를 지정한 다음 `IProcedureManager.Initialize`와 `StartProcedure`를 호출합니다. 일반적인 호출 형태는 다음과 같습니다(기존 모드의 `Start()` 인라인 코드와 동일):

   ```csharp
   ProcedureBase[] procedures = new ProcedureBase[m_AvailableProcedureTypeNames.Length];
   for (int i = 0; i < m_AvailableProcedureTypeNames.Length; i++)
   {
       Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
       procedures[i] = (ProcedureBase)Activator.CreateInstance(procedureType);
       if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
       {
           m_EntranceProcedure = procedures[i];
       }
   }

   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L168)

4. 씬을 실행하여 시작 진입점이 첫 번째 절차(예: `ProcedurePreload`)를 성공적으로 시작했는지 확인하고, 콘솔에서 중복 초기화 관련 오류 보고가 없는지 확인합니다.

## 기존 모드 vs StartupRunner 모드

| 모드 | 트리거 위치 | 진입점 구성 | 적용 시나리오 |
|------|---------|---------|---------|
| 기존 모드(체크박스 미체크) | `ProcedureComponent.Start()` 자동 | Inspector의 `Available Procedures` 및 `Entrance Procedure` | 절차 컴포넌트 단독 사용, 통합 시작 진입점 미연결 |
| StartupRunner 모드(체크박스 체크) | `ApplicationStartupEntry` + `StartupRunner.Run` | 시작 진입점의 런타임 코드에 의해 결정 | GameFrameX 통합 시작 진입점을 사용하는 통합 파이프라인 |

## 일반적인 오류

- **Already exist FSM**: 두 모드가 동시에 활성화되어 `Initialize`가 두 번 호출됩니다. 해결: 한 가지 모드에서만 초기화를 트리거하거나 `Use Startup Runner` 체크를 유지하고 `Start()` 인라인 시작을 제거합니다.
- **진입 절차가 null**: `m_EntranceProcedureTypeName`에 유효한 타입명을 지정하지 않은 경우, 기존 모드는 `Entrance procedure is invalid.`를 출력한 후 종료합니다. StartupRunner 모드에서는 자체 진입 코드에서 진입 절차를 지정해야 합니다.
- **절차 타입을 찾을 수 없음**: `Utility.Assembly.GetType(...)`이 null을 반환하면 `Can not find procedure type '{0}'.`이 출력됩니다. 타입의 전체 이름에 네임스페이스가 포함되어 있는지, 어셈블리가 로드되어 있는지 확인하세요.

## 배경

`UseStartupRunner`이 활성화되면 `Awake`는 여전히 `GameFrameworkEntry.GetModule<IProcedureManager>()`를 통해 절차 관리자를 등록하고 참조를 보유하지만, "절차 배열 구성 → `Initialize` → `StartProcedure`"의 세 단계를 `ApplicationStartupEntry`의 `StartupRunner.Run`까지 연기합니다. 이를 통해 절차 시작이 통합 시작 진입점의 오케스트레이션 제어 하에 이루어지며, 다른 서브시스템이 통합 파이프라인에서 직렬/병렬로 시작되는 것과 일치합니다.
