# 熱更新卡住、下載失敗或版本不一致怎麼辦

當你在熱更新流程(基於 YooAsset 的 HostPlayMode)中出現「流程卡在某個狀態不動」、「補丁下載報錯」、或「客戶端版本與遠端清單對不上」時，按本頁表格與步驟定位修復。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 流程卡在 `UpdateStaticVersion`(取得遠端 `PackageVersion` 失敗) | `hostServerURL` 無法存取，或遠端沒有發布 `PackageVersion` 檔案 | 見 [修復步驟 §1](#修復步驟) |
| 流程卡在 `UpdateManifest`(清單拉取失敗) | `fallbackHostServerURL` 沒設定、清單路徑錯誤、或 `AppVersion` 與遠端不一致 | 見 [修復步驟 §2](#修復步驟) |
| `CreateDownloader` 為空 / 沒有需要下載的檔案 | 本地快取已覆蓋目前 `PackageVersion`,或 `AppVersion` 不相符導致清單裡無可下載項 | 見 [修復步驟 §3](#修復步驟) |
| `DownloadWebFiles` 中途失敗、個別檔案報錯 | 單一檔案下載失敗；受 `FailedTryAgain` 與 `VerifyLevel` 影響 | 見 [修復步驟 §4](#修復步驟) |
| 啟動時報「遠端版本與本地不相容」 | 客戶端 `AppVersion` < 遠端最低支援版本 | 見 [修復步驟 §5](#修復步驟) |

`EPatchStates` 列舉值定義如下，用於日誌對照：

Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L32)

```csharp
public enum EPatchStates
{
    UpdateStaticVersion,
    UpdateManifest,
    CreateDownloader,
    DownloadWebFiles,
    PatchDone,
}
```

## 修復步驟

### §1 卡在 UpdateStaticVersion

1. 檢查傳入的 `hostServerURL`,確認能直接在瀏覽器開啟並傳回文字 `PackageVersion`(YooAsset 預設佈局)。
2. 確認打包機已發布該資源包；遠端目錄至少要包含 `PackageVersion.txt` / `GameVersion.txt`。
3. 若啟用 CDN,確認 CDN 回源位址指向真實的資源伺服器。

### §2 卡在 UpdateManifest

1. 必須同時提供 `fallbackHostServerURL`(備用位址)。`HostPlayMode` 初始化時使用了 `RemoteServices` 將兩者都傳給 YooAsset。

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L148-L164)

```csharp
private InitializationOperation InitializeYooAssetHostPlayMode(
    ResourcePackage resourcePackage,
    string hostServerURL,
    string fallbackHostServerURL)
{
    var remoteServices = new RemoteServices(hostServerURL, fallbackHostServerURL);
    var createParameters = new HostPlayModeParameters
    {
        BuildinFileSystemParameters = FileSystemParameters.CreateDefaultBuildinFileSystemParameters(),
        CacheFileSystemParameters   = FileSystemParameters.CreateDefaultCacheFileSystemParameters(remoteServices),
    };
    return resourcePackage.InitializeAsync(createParameters);
}
```

2. 確認客戶端 `AppVersion` 不高於遠端 `GameVersion.txt`(YooAsset 會按 AppVersion 篩選清單)。
3. 查看日誌中 YooAsset 傳回的清單 URL,手動在瀏覽器開啟應能下載 `PackageManifest_{AppVersion}_{PackageVersion}.hash` 與 `.bytes`。

### §3 CreateDownloader 為空

1. 如果剛清過快取或首次安裝，這是預期行為，跳過下載直接進入遊戲即可。
2. 如果不應該為空(確實有新資源)，通常是 `AppVersion` 選錯導致清單內容錯誤，回到 §2 檢查版本號。

### §4 DownloadWebFiles 失敗

可透過 `IAssetManager` 上的兩個參數調整下載行為：

Source: [IAssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L13-L41)

```csharp
/// 同時下載的最大數目。
int DownloadingMaxNum { get; set; }

/// 失敗重試最大數目。
int FailedTryAgain { get; set; }

/// 取得或設定下載檔案驗證等級。
EFileVerifyLevel VerifyLevel { get; }
```

1. 適當提高 `DownloadingMaxNum`(預設較小值，高頻寬可調到 10~20)。
2. 適當提高 `FailedTryAgain`,避免網路抖動直接判定失敗。
3. 若大量 CDN 檔案 404,先去建置產物目錄核對檔案名稱；YooAsset 遠端佈局需與建置時一致。
4. 若懷疑檔案被劫持或損毀，將 `VerifyLevel` 提高到更高等級(由 `EFileVerifyLevel` 列舉決定)，YooAsset 會驗證檔案雜湊。

### §5 遠端版本與本地不相容

YooAsset 在 `UpdateManifest` 階段會驗證 `AppVersion`,低於遠端要求的版本會被拒絕。處理方式：

1. 將客戶端 `Player Settings.bundleVersion` 或呼叫 `InitPackageAsync` 時傳入的版本號升到 `>=` 遠端 `GameVersion.txt`。
2. 重新出包再發版；不要試圖在舊客戶端上繞過。

## 驗證

1. 觀察進度回呼能完整經過 `UpdateStaticVersion → UpdateManifest → CreateDownloader → DownloadWebFiles → PatchDone`,沒有跳過或卡死。
2. YooAsset 快取目錄(如 `Application.persistentDataPath/yooasset/{packageName}/`)裡能看到本次版本對應的 `.bytes` / `.hash` 快取檔案。
3. 進入遊戲後，所有熱更資源能正常載入，不再回退到內建包。
