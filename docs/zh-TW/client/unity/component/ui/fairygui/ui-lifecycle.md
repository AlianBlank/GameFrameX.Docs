# 工作原理：介面生命週期與載入佇列

本頁說明呼叫 `UIManager` 開啟一個 FairyGUI 介面後，框架內部依序發生什麼：單例去重 → 實例池重複使用 → 非同步載入佇列 → 生命週期回呼 → 群組重新整理，以及關閉時的回收邏輯。理解這條鏈路，可以解釋「為什麼重複開啟同一介面不會載入兩次」「為什麼關閉後介面不立即銷毀」等現象。

## 開啟介面時的生命週期時序

`InternalOpenUIForm` 是所有介面（無論新載入還是池重複使用）真正「誕生」的地方，回呼按以下順序執行，全部來自真實原始碼：

1. `m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData)` 建立 `IUIForm`；傳回 `null` 時擲出 `GameFrameworkException("Can not create UI form in UI form helper.")`。
2. `uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen)` 完成初始化；其中 `OnInitAction` 會在初始化回呼裡為 `FUI` 類型介面呼叫 `fui.SetGObject(uiFormInstance as GObject)` 繫結 GObject。
3. 介面加入 UI 群組：若 `uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm)` 為假，則 `uiGroup.AddUIForm(uiForm)`。
4. `uiForm.OnOpen(userData)` —— 業務端在開啟瞬間收到的回呼。
5. `uiForm.BindEvent()`、`uiForm.LoadData()`、`uiForm.UpdateLocalization()` 依序執行。
6. 若 `uiForm.EnableShowAnimation` 為真，`uiForm.Show(m_UIFormShowHandler, null)` 播放顯示動畫（見下文 FUI 的 `Show` 實作）。
7. `uiGroup.Refresh()` 重新整理群組深度與暫停狀態。
8. 觸發 `OpenUIFormSuccessEventArgs` 成功事件；任一步擲出例外則觸發 `OpenUIFormFailureEventArgs` 並重新擲出。

```csharp
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);

void OnInitAction(IUIForm obj)
{
    if (obj is FUI fui)
    {
        fui.SetGObject(uiFormInstance as GObject);
    }
}

if (!uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm))
{
    uiGroup.AddUIForm(uiForm);
}

uiForm.OnOpen(userData);
uiForm.BindEvent();
uiForm.LoadData();
uiForm.UpdateLocalization();
if (uiForm.EnableShowAnimation)
{
    uiForm.Show(m_UIFormShowHandler, null);
}

uiGroup.Refresh();
```

## 載入佇列與去重

`InnerOpenUIFormAsync` 在真正發起載入前會做三層去重，避免同一介面被並行載入：

1. **單例模式命中已開啟介面**：`UseSingletonOpenMode(uiFormType)` 為真時，先 `GetUIForm(uiFormAssetName)` 尋找已開啟實例，命中則 `RefocusUIForm(openedUIForm, userData)` 後直接傳回，不再載入。
2. **命中載入中佇列**：遍歷 `m_LoadingUIForms`（容量 64 的 `List<UIFormLoadingObject>`），若資源路徑、資源名稱、類型三者都相符，則 `await value.Task` 重複使用同一次載入結果。
3. **命中實例池**：`m_InstancePool.Spawn(uiFormAssetName)` 取回可重複使用的實例，成功則分配新的 `++m_Serial` 序號後直接走 `InternalOpenUIForm`（`isNewInstance: false`）。

只有三層都未命中，才呼叫 `InnerLoadUIFormAsync` 發起真正的資源載入，並將結果包裝成 `UIFormLoadingObject` 加入 `m_LoadingUIForms`；`await` 結束後在 `finally` 中移除並 `ReferencePool.Release`，確保佇列不會洩漏。

```csharp
foreach (var value in m_LoadingUIForms)
{
    if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
    {
        return await value.Task;
    }
}
```

## 資源載入路徑：Resources 與 Bundles

`InnerLoadUIFormAsync` 每次載入分配新序號，並登記到 `m_UIFormsBeingLoaded`，隨後依路徑特徵分流：

- **套件名稱推導**：取 `uiFormAssetPath` 最後一個 `/` 之後的部分作為 `packageName`；路徑中沒有 `/` 時整個路徑即為套件名稱。
- **已載入的套件**：`FairyGuiPackage.Has(packageName)` 為真則直接走 `LoadAssetSuccessCallback` 建立介面，不重複載入套件。
- **Resources 目錄**：`assetPath` 不包含 `Utility.Asset.Path.BundlesDirectoryName` 時，若套件未載入則 `FairyGuiPackage.AddPackageSync(assetPath)` 同步載入後建立介面。
- **Bundle 目錄**：套件名稱與資源名稱一致時 `await FairyGuiPackage.AddPackageAsync(assetPath)`；不一致則用 `PathHelper.Combine(uiFormAssetPath, packageName)` 重新拼接路徑非同步載入，然後載入 `路徑 + "_fui"` 資源（`m_AssetManager.LoadAssetAsync<UnityEngine.Object>`），成功才 `openUIFormInfo.SetAssetHandle(assetHandle)` 並建立介面。

```csharp
newAssetPackagePath += "_fui";
// 從套件中載入
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

### 載入成功 / 失敗回呼

| 回呼 | 行為 |
|------|------|
| `LoadAssetSuccessCallback` | 檢查 `m_UIFormsToReleaseOnLoad`（載入期間被取消的請求則直接釋放資源）；否則用 `m_UIFormHelper.InstantiateUIForm` 實例化並 `m_InstancePool.Register` 註冊到實例池，再走 `InternalOpenUIForm`（`isNewInstance: true`） |
| `LoadAssetFailureCallback` | 拼接錯誤訊息 `Utility.Text.Format("Load UI form failure, asset name '{0}', error message '{1}'.", ...)`，觸發 `OpenUIFormFailureEventArgs`；無失敗處理常式時直接 `throw new GameFrameworkException(appendErrorMessage)` |

兩處對無效 `OpenUIFormInfo` 均擲出 `GameFrameworkException("Open UI form info is invalid.")`。

## 顯示 / 隱藏動畫

`FUI`（FairyGUI 介面基底類別，繼承自 `UIForm`）將可見性操作轉發給關聯的 `GObject`：

- `Show(handler, complete)`：有 handler 時呼叫 `handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete)`，否則直接 `complete?.Invoke()`。
- `Hide(handler, complete)`：對稱地使用 `EnableHideAnimation` 與 `HideAnimationName`。
- `Visible`：讀取 `GObject.visible`；`GObject == null` 時恆為 `false`。`InternalSetVisible` 修改 `GObject.visible` 後依序觸發 `OnVisibleChanged` 回呼與 `UIFormVisibleChangedEventArgs` 事件。
- `MakeFullScreen()`：`GObject?.asCom?.MakeFullScreen()`。

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

## 關閉與實例回收

`RecycleUIForm(uiForm, isDispose)` 負責關閉後的回收，步驟為：

1. `uiForm.OnRecycle()` 先觸發業務回收回呼。
2. 取 `uiForm.Handle as GameObject`；為空直接傳回（無可回收的顯示物件）。
3. 從 GameObject 上取 `DisplayObjectInfo` 元件，再取 `displayObject.gOwner as GComponent`；任一為空直接傳回。
4. `m_InstancePool.Unspawn(component)` 將實例還回實例池等待重複使用；`isDispose == true` 時額外 `m_InstancePool.ReleaseObject(component)` 徹底銷毀。

也就是說，預設關閉只是「回池」，下次 `m_InstancePool.Spawn` 命中即可免載入重複使用；實例池回收間隔下限為 `10`（`m_RecycleInterval < 10` 時被強制改為 `10`）。

```csharp
m_InstancePool.Unspawn(component);
if (isDispose)
{
    m_InstancePool.ReleaseObject(component);
}
```

## 常見問題排解

| 現象 | 原因 | 處理 |
|------|------|------|
| 重複開啟同一介面，只有第一次走載入 | 單例模式下命中 `GetUIForm` 或 `m_LoadingUIForms` 去重 | 屬預期行為；需要新實例請關閉單例開啟模式 |
| 開啟介面時擲出 `Can not create UI form in UI form helper.` | `m_UIFormHelper.CreateUIForm` 傳回 `null` | 檢查 `uiFormType` 與已註冊的 `FairyGUIFormHelper` 是否能建立該類型 |
| 擲出 `Load UI form failure, asset name '...', error message '...'` | `_fui` 資源或 UI 套件載入失敗且未註冊失敗處理常式 | 核對套件名稱推導結果與 `uiFormAssetPath`，確認 `路徑_fui` 資源存在 |
| 擲出 `Open UI form info is invalid.` | 成功/失敗回呼收到的 `OpenUIFormInfo` 為 `null` | 屬框架內部資料異常，檢查是否有外部誤用回呼 |
| 關閉介面後記憶體未下降 | `RecycleUIForm` 預設僅 `Unspawn` 回池 | 需要徹底銷毀時使用帶 `isDispose` 的關閉路徑 |
