# Add and Initiate a Download

By calling `DownloadComponent.AddDownload(...)`, you can add a remote file to the download queue. The framework will automatically schedule download agents to complete the download, and return progress, success, and failure results to you via event callbacks.

## Prerequisites

- `DownloadComponent` is mounted in the scene (component menu `GameFrameX/Download`) and has started along with `GameFramework`.
- `EventComponent` is mounted in the scene; otherwise, download success / failure events cannot be dispatched.
- `Download Agent Helper Count` on `DownloadComponent` is greater than 0; the default value is 3.
- The directory of `downloadPath` has write permission.

## Steps

1. Get the `DownloadComponent` instance:

```csharp
var download = GameEntry.GetComponent<DownloadComponent>();
```

Source: [DownloadComponent.cs#L46-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L60)

2. Call `AddDownload` to add the download task to the queue, which returns the task's serial number `serialId`:

```csharp
int serialId = download.AddDownload(
    downloadPath: Application.persistentDataPath + "/files/bundle.zip",
    downloadUri:   "https://example.com/bundle.zip",
    tag:           "Bundle",
    priority:      0,
    userData:      null);
```

Source: [DownloadComponent.cs#L379-L385](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L379-L385)

3. Subscribe to the download events in `EventComponent` to receive callbacks; the event IDs are defined in `Constant.cs`:

```csharp
var eventComp = GameEntry.GetComponent<EventComponent>();
eventComp.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComp.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComp.Subscribe(DownloadUpdateEventArgs.EventId,   OnDownloadUpdate);
```

In the callbacks, `e.SerialId` corresponds to the `serialId` returned when the task was added.

4. Handle the download results. Both `DownloadSuccessEventArgs` / `DownloadFailureEventArgs` provide `SerialId`, which you can use to determine which task has finished.

## Common Variants

- **Only need a `Task<bool>`**: Use `download.Download(downloadPath, downloadUri)`, which internally wraps `AddDownload` + `TaskCompletionSource`; on completion the `Task` will `SetResult(true)`, and on failure / cancellation it will `SetResult(false)` / `TrySetCanceled()`.
  Source: [DownloadComponent.cs#L306-L317](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L317)

- **No tag / priority passed**: Simply use the two-parameter `AddDownload(string downloadPath, string downloadUri)`, with defaults `tag = null` and `priority = 0`.
  Source: [DownloadComponent.cs#L271-L274](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L274)

- **Batch management by tag**: Use `GetDownloadInfos(tag)` to query, and `RemoveDownloads(tag)` to cancel in batch.

## Common Errors

- **`Log.Fatal("Download manager is invalid.")`**: `DownloadComponent` is not mounted in the scene, or it did not Awake correctly. Check the GameFramework startup order.
- **`Log.Fatal("Event component is invalid.")`**: `EventComponent` is missing, so download events cannot be dispatched.
- **No write permission for the download directory**: Use a writable path provided by Unity such as `Application.persistentDataPath`; do not write to read-only locations like `StreamingAssets` or `jar:file://`.
- **New tasks keep waiting when all agents are busy**: Tasks will enter the waiting queue until an agent becomes free. You can monitor with `FreeAgentCount` / `WaitingTaskCount`.
  Source: [DownloadComponent.cs#L82-L105](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L82-L105)

## Background

During the `Start` phase, `DownloadComponent` creates a corresponding number of `UnityWebRequestDownloadAgentHelper` instances according to `Download Agent Helper Count` (which can be switched to a custom implementation in the Inspector), and all concurrent downloads rotate across these Helpers. `AddDownload` only enqueues the task; the actual HTTP request initiation and disk writing are scheduled by `DownloadManager` on the next frame.
