# UI 열기, 닫기 및 회수

이 문서에서는 FairyGUI 버전 `UIManager`의 UI 라이프사이클 사용법을 설명합니다: 열기를 트리거하는 방법(싱글톤 중복 제거 및 인스턴스 풀 재사용 포함), 닫은 후 회수 방법, 그리고 회수가 파괴와 같지 않을 때 주의할 점. 외부 열기/닫기 진입점은 GameFrameX.UI 패키지의 `BaseUIManager`를 상속하며, 본 저장소(플러그인)는 `InnerOpenUIFormAsync`와 `RecycleUIForm`을 재정의하여 FairyGUI의 구체적인 구현을 완성합니다.

## 사전 조건

- 씬에 `FairyGUIPackageComponent` 컴포넌트가 이미 존재해야 합니다. `UIManager.SetResourceManager`는 리소스 매니저를 설정할 때 `GameEntry.GetComponent<FairyGUIPackageComponent>()`를 실행하고 `GameFrameworkGuard.NotNull`으로 검증하며, 누락 시 즉시 오류가 발생합니다:

```csharp
public override void SetResourceManager(IAssetManager assetManager)
{
    base.SetResourceManager(assetManager);
    FairyGuiPackage = GameEntry.GetComponent<FairyGUIPackageComponent>();
    GameFrameworkGuard.NotNull(FairyGuiPackage, nameof(FairyGuiPackage));
}
```

출처: [UIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs#L87-L92)

- 회수 간격에는 하한이 있습니다: 생성자에서 `m_RecycleInterval`이 10보다 작으면 강제로 10(초)으로 설정되며, 즉 UI 인스턴스는 풀에서 최소 10초 동안 유지된 후에야 실제로 해제될 수 있습니다.
- UI 로직 클래스는 `FUI`(이는 `UIForm`을 상속함)를 상속하며, `GObject` 속성을 통해 FairyGUI 객체에 접근합니다.

## 작업 단계: UI 열기

1. 비동기 방식으로 UI 열기를 요청합니다. `InnerOpenUIFormAsync`는 모든 열기 요청이 수렴하는 지점이며, 시그니처는 다음과 같습니다:

```csharp
protected override async Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
```

출처: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L64-L64)

2. 해당 UI 타입이 싱글톤 열기 모드(`UseSingletonOpenMode(uiFormType)`)를 활성화한 경우, 이미 열려 있으면 기존 인스턴스를 재사용하고 다시 포커스하며, 로드 중이면 동일한 작업을 기다리므로 중복 인스턴스화가 일어나지 않습니다:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }

    foreach (var value in m_LoadingUIForms)
    {
        if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
        {
            return await value.Task;
        }
    }
}
```

출처: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L85)

3. 싱글톤 분기에 해당하지 않으면 먼저 인스턴스 풀에서 가져오기를 시도합니다(`m_InstancePool.Spawn(uiFormAssetName)`). 가져오기에 성공하면 새 시리얼 번호로 `InternalOpenUIForm`을 호출하여 열기를 완료하며, 리소스 로드를 전혀 거치지 않습니다:

```csharp
var uiFormInstanceObject = m_InstancePool.Spawn(uiFormAssetName);

if (uiFormInstanceObject != null)
{
    // 풀 재사용 시에도 새 요청 시리얼 번호를 할당하여 매 열기 요청을 관측 가능하게 합니다.
    int serialId = ++m_Serial;
    return InternalOpenUIForm(serialId, uiFormAssetPath, uiFormAssetName, uiFormType, uiFormInstanceObject.Target, pauseCoveredUIForm, false, 0f, userData, isFullScreen);
}
```

출처: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L87-L94)

4. 풀에도 없으면 `InnerLoadUIFormAsync`로 진입합니다: 리소스 경로에서 패키지 이름을 잘라내고, FairyGUI 패키지가 아직 로드되지 않았다면 출처에 따라 로드합니다 — `Resources` 디렉토리는 `FairyGuiPackage.AddPackageSync(assetPath)`로 동기 로드하고, Bundle 경로는 `FairyGuiPackage.AddPackageAsync`로 비동기 로드한 뒤, `_fui` 접미사가 붙은 UI 리소스를 로드합니다:

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Resources에서 로드
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

출처: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

5. 로드 성공 시 `LoadAssetSuccessCallback`이 콜백되어 UI 인스턴스를 생성합니다. 로드 실패 시에는 `LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo)`로 처리되며, 오류 메시지는 `assetHandle.LastError`에서 가져옵니다.

## 작업 단계: 닫기 및 회수

UI를 닫으면 최종적으로 본 저장소에서 재정의한 `RecycleUIForm`이 호출되며, 그 전체 로직은 다음과 같습니다: `uiForm.OnRecycle()`을 트리거하고, `Handle`에 해당하는 GameObject에서 `DisplayObjectInfo`를 가져온 뒤, `GComponent`를 얻어 인스턴스 풀에 반환합니다. `isDispose == true`인 경우에만 추가로 `ReleaseObject`를 호출하여 실제로 파괴합니다:

```csharp
protected override void RecycleUIForm(IUIForm uiForm, bool isDispose = false)
{
    uiForm.OnRecycle();
    var formHandle = uiForm.Handle as GameObject;
    if (!formHandle)
    {
        return;
    }

    var displayObjectInfo = formHandle.GetComponent<DisplayObjectInfo>();
    if (!displayObjectInfo)
    {
        return;
    }

    var component = displayObjectInfo.displayObject.gOwner as GComponent;
    if (component == null)
    {
        return;
    }

    m_InstancePool.Unspawn(component);
    if (isDispose)
    {
        m_InstancePool.ReleaseObject(component);
    }
}
```

출처: [UIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Close.cs#L53-L79)

요점:

| 파라미터 | 동작 |
|------|------|
| `isDispose = false`(기본값) | `Unspawn`으로 인스턴스 풀에 반환되어 객체가 유지되며, 다음 열기 시 즉시 재사용됩니다 |
| `isDispose = true` | 반환 후 다시 `ReleaseObject`로 파괴 및 해제합니다 |
| `Handle`이 GameObject가 아님 / `DisplayObjectInfo` 누락 / `gOwner`가 `GComponent`가 아님 | `OnRecycle()`만 호출한 후 조기 반환되며, 풀에 들어가지 않습니다 |

## 일반적인 변형: 표시 및 숨기기 애니메이션

UI 클래스 `FUI`는 `Show` / `Hide`를 재정의하여 FairyGUI 객체를 핸들러에 넘겨 애니메이션을 재생합니다. 애니메이션 재생 여부는 `EnableShowAnimation` / `EnableHideAnimation`과 애니메이션 이름 `ShowAnimationName` / `HideAnimationName`으로 제어되며, 핸들러가 null이면 완료 콜백을 직접 호출합니다:

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}

public override void Hide(IUIFormHideHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableHideAnimation, HideAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

출처: [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L74-L105)

또 다른 일반적인 변형은 패키지 이름과 UI 리소스 이름이 일치하지 않는 경우입니다: 이때는 패키지 경로를 `PathHelper.Combine(uiFormAssetPath, packageName)`으로 다시 조합한 후 `AddPackageAsync`를 호출하고, 그 뒤에 `_fui`를 이어 붙여 UI 리소스를 로드합니다. 자세한 내용은 [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L158-L178)를 참고하세요.

## 일반적인 오류

- **UI를 열 때 `FairyGuiPackage`가 null이라는 가드 예외 발생**: `FairyGUIPackageComponent`가 마운트되지 않았거나 초기화되지 않은 것입니다. 먼저 씬/진입점에 해당 컴포넌트를 추가한 뒤 `SetResourceManager`를 호출하세요.
- **열기에 실패했는데 세부 내용이 보이지 않음**: Bundle 모드에서 실패 원인은 `assetHandle.LastError`에서 가져오며, `LoadAssetFailureCallback`으로 마무리됩니다. 문제를 조사할 때는 경로에 `BundlesDirectoryName`이 나타내는 Bundle 디렉토리 이름이 포함되어 있는지, 패키지 이름이 리소스 경로에서 올바르게 잘려 나오는지 확인하세요.
- **닫은 후에도 메모리가 줄어들지 않음**: 기본값 `isDispose = false`는 인스턴스 풀에만 반환하며, 인스턴스는 풀에서 최소 `m_RecycleInterval`(하한 10초) 동안 유지됩니다. 이는 의도된 동작이며, 반드시 파괴해야 할 때는 `isDispose: true`로 회수하세요.
- **같은 UI를 반복해서 열고 닫을 때 중복 인스턴스 발생**: 해당 UI 타입이 `UseSingletonOpenMode`를 활성화했는지 확인하세요. 활성화되지 않은 경우 매번 열 때 풀/로드 흐름을 거치며, 여러 인스턴스가 동시에 존재하는 것이 허용됩니다.

## 검증

- 열기 후 반환된 `IUIForm`을 통해 `GObject`가 `FUI.GObject`에 마운트되었는지 확인합니다. 싱글톤 UI를 다시 열면 동일한 인스턴스가 반환되고 `RefocusUIForm`이 트리거되어야 합니다.
- 닫은 후 UI 인스턴스가 풀에서 다시 `Spawn`되어 재사용 가능한지(기본 경로), 또는 `isDispose: true` 처리 후 더 이상 재사용할 수 없는지(파괴 경로) 확인합니다.
- 애니메이션 경로 검증: `Show`/`Hide`의 완료 콜백 `complete`가 반드시 호출되어야 하며, 그렇지 않으면 상위 흐름이 계속 진행되지 않습니다.

## 배경

열기 흐름은 3단계 숏트서킷으로 이루어집니다: 싱글톤 중복 제거 → 인스턴스 풀 재사용 → 비동기 로드. `m_LoadingUIForms` 리스트는 진행 중인 로드 작업을 기록하여 동시 요청을 병합하며, 매 열기(풀 재사용 포함)마다 관측용으로 새로운 `m_Serial` 시리얼 번호가 할당됩니다. 회수 경로에서 `FUI.InternalSetVisible`은 가시성만 변경하고 이벤트를 발생시키지 않으며, 실제 인스턴스 반환/파괴는 모두 `RecycleUIForm`에서 `GComponent`와 `m_InstancePool`을 기반으로 이루어집니다.
