# Proto 프로토콜 추가 및 MessageProtoHandler 연동

`GameFrameX.Proto` 프로젝트에 새로운 `.proto` 파일을 추가한 후, `MessageProtoHandler` 클래스가 해당 어셈블리에 담겨 있기만 하면, 런처가 초기화 단계에서 모든 프로토콜 메시지 타입을 자동으로 스캔하여 등록하므로 등록 코드를 직접 작성할 필요가 없습니다.

## 사전 조건

- 솔루션에 `GameFrameX.Proto` 프로젝트가 이미 존재하며, 프로토콜 메시지의 인코딩/디코딩 및 디스패치를 위해 `GameFrameX.NetWork 1.13.0` 패키지를 참조합니다.
- 대상 프레임워크는 `net10.0`(`LangVersion=10`)입니다.
- 비즈니스 모듈(예: `GameFrameX.Apps`)은 생성된 프로토콜 타입이 컴파일 시점에 보이도록 `ProjectReference`를 통해 `GameFrameX.Proto`를 참조합니다.

## 작업 단계

1. `GameFrameX.Proto/Proto/` 디렉터리 아래에 `.proto` 파일을 생성하고 메시지와 서비스를 정의합니다. 예를 들어 `GameFrameX.Proto/Proto/Helloworld.proto`를 새로 만듭니다:

   ```protobuf
   syntax = "proto3";

   option csharp_namespace = "GameFrameX.Proto";

   package helloworld;

   // 요청 메시지
   message HelloRequest
   {
       string name = 1;
   }

   // 응답 메시지
   message HelloReply
   {
       string message = 1;
   }

   service Greeter
   {
       rpc SayHello (HelloRequest) returns (HelloReply);
   }
   ```

   파일은 `Proto` 폴더 바로 아래에 두면 됩니다. 이 폴더는 csproj에서 예약 디렉터리로 선언되어 있어 IDE와 MSBuild 모두 이를 코드로 컴파일하지 않습니다.

   Source: [GameFrameX.Proto/GameFrameX.Proto.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/GameFrameX.Proto.csproj#L12-L14)

2. `MessageProtoHandler` 클래스가 `GameFrameX.Proto` 어셈블리 안에 있는지 확인합니다. 이 클래스는 빈 껍데기 정적 클래스로, "프로토콜 핸들러 앵커" 역할을 하여 이후 초기화 코드가 해당 `Assembly`를 통해 현재 어셈블리의 모든 프로토콜 메시지 타입을 리플렉션으로 찾을 수 있게 합니다:

   ```csharp
   namespace GameFrameX.Proto;

   /// <summary>
   /// 프로토콜 메시지 핸들러
   /// </summary>
   public static class MessageProtoHandler
   {
   }
   ```

   Source: [GameFrameX.Proto/MessageProtoHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/MessageProtoHandler.cs#L1-L8)

3. 시작 진입점(현재는 `GameFrameX.Launcher/Program.cs`)에서 `MessageProtoHelper.Init`를 한 번 호출하여 `MessageProtoHandler`가 속한 어셈블리를 전달하면, 모든 `proto` 메시지 타입의 등록이 완료됩니다:

   ```csharp
   MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
   ```

   Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L14-L15)

4. 프로토콜 타입을 사용해야 하는 다운스트림 프로젝트에 프로젝트 참조를 추가하여, 생성된 코드가 호출자 측에서 보이도록 합니다:

   ```xml
   <ProjectReference Include="..\GameFrameX.Proto\GameFrameX.Proto.csproj" />
   ```

   Source: [GameFrameX.Apps/GameFrameX.Apps.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/GameFrameX.Apps.csproj#L10-L10)

5. 컴파일한 후 Launcher를 시작합니다. `MessageProtoHandler`가 속한 어셈블리에 새로 추가된 `.proto` 메시지 타입은 메시지 디스패치 파이프라인에 자동으로 등록됩니다.

## 일반적인 변형

- **여러 `.proto` 파일**: `GameFrameX.Proto/Proto/` 아래에 여러 `.proto` 파일을 나란히 배치하기만 하면 되며, `MessageProtoHelper.Init`가 전체 어셈블리를 한 번에 스캔합니다.
- **C# 네임스페이스 전환**: 각 `.proto` 파일 상단에서 `option csharp_namespace = "Your.Namespace";`를 사용해 생성 코드의 네임스페이스를 제어하여, `MessageProtoHandler`가 속한 `GameFrameX.Proto`와 분리할 수 있습니다.
- **Launcher에서 시작하지 않기**: 호출자가 `GameFrameX.NetWork.MessageProtoHelper.Init`에 접근할 수 있다면, `MessageProtoHandler`가 속한 어셈블리를 전달하는 것만으로 등록이 완료되며 시작 프로젝트와는 무관합니다.

## 자주 발생하는 오류

- **`.proto` 파일을 `Proto` 폴더가 아닌 프로젝트 루트에 배치**: csproj에서 명시적으로 제외하지는 않지만, `Proto` 폴더는 예약 디렉터리이므로 더 얕은 위치에 두면 이후 코드 제너레이터를 연동할 때 `*.proto` 기본 규칙에 의해 잘못 처리되기 쉽습니다.
- **`MessageProtoHelper.Init` 누락**: `Init`를 호출하지 않으면 새 프로토콜이 등록되지 않아 런타임에서 메시지 타입 핸들러를 찾을 수 없습니다.
- **다운스트림 프로젝트가 `GameFrameX.Proto`를 참조하지 않음**: 등록에 성공하더라도 호출자가 생성된 메시지 타입을 가져올 수 없어 컴파일 시점에 "타입을 찾을 수 없음" 오류가 발생합니다.
- **`MessageProtoHandler` 클래스 이름 변경 또는 클래스가 Proto 어셈블리에 없음**: `typeof(MessageProtoHandler).Assembly`가 잘못된 어셈블리를 가리키게 되어 새 프로토콜이 발견되지 않습니다.

## 배경

`GameFrameX.NetWork` 패키지의 `MessageProtoHelper.Init(Assembly)`는 리플렉션을 통해 전달된 어셈블리 내에서 `.proto`로 생성된 C# 메시지 타입을 스캔하여 등록을 완료합니다. `MessageProtoHandler`는 `GameFrameX.Proto`에서 자리 표시용으로 쓰이는 정적 클래스이며, 유일한 "역할"은 런처가 안정적인 타입을 얻어 `GameFrameX.Proto` 어셈블리를 찾을 수 있도록 하는 것입니다. 이를 통해 어셈블리 이름을 하드코딩하는 것을 피할 수 있습니다.
