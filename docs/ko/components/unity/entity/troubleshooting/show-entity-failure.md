# 엔티티 표시 실패 시 대처 방법

`ShowEntity` / `ShowEntityAsync` 호출 후 엔티티가 씬에 나타나지 않거나, 로그에서 `ShowEntityFailure` 이벤트가 발생하는 것은 보통 엔티티 그룹, 리소스 또는 헬퍼 컴포넌트 설정이 올바르지 않아서 발생합니다. 이 페이지에서는 일반적인 원인에 따라 빠른 진단 및 해결 단계를 안내합니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| `ShowEntityFailure` 이벤트가 즉시 발생하고 로그에 `Entity group name is invalid.` 포함 | 전달된 `entityGroupName`이 `null` / 빈 문자열이거나 해당 엔티티 그룹이 등록되지 않음 | `EntityComponent`의 `m_EntityGroups`에 동일한 이름의 엔티티 그룹을 미리 추가 |
| `Entity group is invalid.` 표시 | 엔티티 그룹은 존재하지만 내부 `EntityGroup` 인스턴스가 초기화되지 않았거나 파괴됨 | 먼저 `HasEntityGroup`으로 그룹 존재 여부를 확인한 후 `ShowEntity` 호출 |
| `Can not create entity helper.` 표시 | `EntityComponent.Awake`/`Start`에서 `m_EntityHelperTypeName`을 통해 `EntityHelperBase`를 리플렉션하지 못함 | `m_EntityHelperTypeName`이 `GameFrameX.Entity.Runtime.DefaultEntityHelper` 또는 사용자 정의 헬퍼 클래스의 전체 타입 이름인지 확인; 사용자 정의 헬퍼는 `m_CustomEntityHelper` 필드에 할당해야 함 |
| `ShowEntityFailure` 이벤트가 지속적으로 발생하고 리소스 로드 실패 | `m_AssetManager`가 설정되지 않았거나 리소스 주소(`entityAssetName`)가 YooAsset 리소스 매니페스트에 없음 | `EntityComponent.Start`에서 `SetResourceManager`를 호출했는지 확인; YooAsset에서 엔티티 Prefab의 태그와 주소를 올바르게 설정 |
| 엔티티는 성공적으로 생성되었지만 GameObject가 표시되지 않음 | `m_InstanceRoot`가 보이는 씬 루트에 연결되지 않았거나 Prefab 자체의 Layer/가시성이 비활성화됨 | 씬에서 `EntityComponent`에 보이는 `m_InstanceRoot`를 지정; Prefab의 `MeshRenderer` 상태 확인 |
| 비동기 인터페이스 `ShowEntityAsync`가 계속 반환되지 않음 | 리소스 로드가 중단되거나 `m_EntitiesBeingLoaded`에서 동일한 엔티티를 반복 요청 | 동일 프레임에서 동일한 `EntityId`에 대해 여러 번 Show를 호출하지 말 것; 리소스 매니저가 외부에서 차단되지 않았는지 확인 |

## 해결 단계

### 1. 엔티티 그룹 등록 여부 확인

`EntityManager`는 엔티티 그룹 이름이 비어 있을 때 `GameFrameworkException("Entity group name is invalid.")`을 즉시 발생시킵니다. 모든 `ShowEntity` 호출 전에 `EntityComponent.AddEntityGroup`을 통해 그룹을 먼저 추가해야 합니다.

```csharp
// Source: Runtime/Entity/Entity/EntityManager.Get.cs#L53-L61
public bool HasEntityGroup(string entityGroupName)
{
    if (string.IsNullOrEmpty(entityGroupName))
    {
        throw new GameFrameworkException("Entity group name is invalid.");
    }
    return m_EntityGroups.ContainsKey(entityGroupName);
}
```

작업:

1. `EntityComponent`가 부착된 씬 객체의 Inspector를 엽니다.
2. `Entity Groups` 목록에서 사용할 그룹을 추가합니다(`Name`, `InstanceAutoReleaseInterval`, `InstanceCapacity`, `InstanceExpireTime`, `InstancePriority` 입력).
3. 코드에서 그룹 이름을 사용하기 전에 먼저 `HasEntityGroup`으로 검증합니다.

### 2. 엔티티 헬퍼 사용 가능 여부 확인

`EntityComponent.Start`에서는 `Helper.CreateHelper`를 호출하여 엔티티 헬퍼를 생성합니다; `null`이 반환되면 `Log.Error("Can not create entity helper.")`를 출력하고 초기화를 중단합니다.

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L171-L183
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
    return;
}
entityHelper.name = "Entity Helper";
Transform transform = entityHelper.transform;
transform.SetParent(this.transform);
transform.localScale = Vector3.one;
m_EntityManager.SetEntityHelper(entityHelper);
```

작업:

1. `Entity Helper Type Name` 필드가 가리키는 클래스가 존재하는지 확인(기본값 `GameFrameX.Entity.Runtime.DefaultEntityHelper`).
2. 사용자 정의 헬퍼는 반드시 `EntityHelperBase`를 상속하고 엔티티 인스턴스화 로직을 구현해야 함; 인스턴스를 `Entity Component`의 `Custom Entity Helper` 필드에 드래그합니다.
3. 헬퍼 클래스가 별도의 어셈블리에 있는 경우 해당 어셈블리가 빌드에 포함되어 리플렉션으로 해석 가능한지 확인합니다.

### 3. 리소스 매니저 주입 여부 확인

`EntityManager`가 엔티티 Prefab을 로드할 때는 `IAssetManager`에 의존하며(`SetResourceManager`를 통해 주입), 주입되지 않으면 로드 단계에서 `ShowEntityFailure`가 발생합니다.

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L167-L169
m_EntityManager.SetResourceManager(GameFrameworkEntry.GetModule<IAssetManager>());
m_EntityManager.SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>());
```

작업:

1. 씬에 `Asset Component`, `Object Pool Component`가 마운트되어 있고 Awake 순서가 `EntityComponent`보다 빠른지 확인.
2. YooAsset이 올바르게 초기화되었으며 전달된 `entityAssetName`(경로 또는 태그)이 리소스 매니페스트에 존재하는지 확인.
3. 필요시 `Enable Show Entity Dependency Asset Event`를 활성화하여 이벤트를 통해 의존 리소스 다운로드 완료 여부를 관찰.

### 4. 실패 이벤트 청취를 통한 근본 원인 파악

`EntityComponent`는 Awake에서 기본적으로 `ShowEntityFailure`를 구독합니다. 디버그 단계에서는 자체 스크립트에서 추가로 구독하여 `EntityId`, `EntityAssetName`, `EntityGroupName`, `ErrorMessage` 등의 정보를 얻을 수 있습니다.

```csharp
// Source: Runtime/Entity/Entity/EntityManager.cs#L118-L122
public event EventHandler<ShowEntityFailureEventArgs> ShowEntityFailure
{
    add { m_ShowEntityFailureEventHandler += value; }
    remove { m_ShowEntityFailureEventHandler -= value; }
}
```

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L130-L131
m_EntityManager.ShowEntitySuccess += OnShowEntitySuccess;
m_EntityManager.ShowEntityFailure += OnShowEntityFailure;
```

작업: 실패 콜백에서 `EventArgs.ErrorMessage`와 `EventArgs.EntityId`를 출력하고, 해당 메시지를 기반으로 위의 1~3항을 다시 확인합니다.

### 5. 런타임 인스턴스 루트 노드 확인

엔티티 헬퍼는 `GameObject("Entity Instances")`를 `m_InstanceRoot`로 생성합니다. 이 루트 노드가 비활성화되어 있거나 씬에 없으면 엔티티는 성공적으로 생성되었지만 시각적으로 보이지 않습니다.

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L185-L190
if (m_InstanceRoot == null)
{
    m_InstanceRoot = new GameObject("Entity Instances").transform;
    m_InstanceRoot.SetParent(gameObject.transform);
    m_InstanceRoot.localScale = Vector3.one;
}
```

작업:

1. Hierarchy에서 `Entity Instances` 노드를 찾아 활성화 상태인지 확인.
2. `m_InstanceRoot`를 사용자 정의한 경우 부모 노드와 자체가 모두 활성화되어 있고 카메라 컬링(`Layer` 설정, `Culling Mask` 등)에 의해 제거되지 않았는지 확인.

## 검증

1. 테스트 씬에서 `ShowEntity<MyEntityLogic>(entityId, "Default", "MyPrefab", userData)`를 호출.
2. Console 관찰: `ShowEntitySuccess` 이벤트가 발생하고 `OnShowEntitySuccess`가 한 번 호출되어야 합니다.
3. Hierarchy에서 엔티티 `EntityId`로 명명된 GameObject가 `Entity Instances` 아래에 나타나는지 확인하고, 위치/스케일/가시성이 예상과 일치하는지 확인.
4. `HideEntity(entityId)`를 호출한 후 객체가 오브젝트 풀에 회수되고 `HideEntityComplete` 이벤트가 정상적으로 발생하는지 확인.

## 배경(선택 사항)

`EntityManager`는 내부적으로 `m_EntityInfos`, `m_EntityGroups`, `m_EntitiesBeingLoaded` 등의 딕셔너리와 큐를 유지 관리하며, 리소스 로드는 `IAssetManager`를 통해 비동기로 완료된 후 `IEntityHelper`를 호출하여 엔티티를 인스턴스화하고 `ShowEntitySuccess`를 발행합니다. 어느 단계에서든 오류가 발생하면 `ShowEntityFailure` 경로를 통해 `ShowEntityInfo` 참조 객체를 재사용합니다([ShowEntityInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.ShowEntityInfo.cs#L38-L106)).
