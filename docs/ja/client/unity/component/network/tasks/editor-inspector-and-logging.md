# ネットワークログの有効化と Inspector パネルの使用

Unity メニュー `GameFrameX/Scripting Define Symbols` から送信/受信ログのマクロを有効にすると、ネットワークコンポーネントがコンソールに各送受信メッセージの ID、型、JSON の内容を出力するようになります。また、Play モード中に `NetworkComponent` をアタッチしたオブジェクトを選択すると、Inspector パネルで各ネットワークチャネルの接続状態、送受信パケット数、ハートビートの進行状況をリアルタイムで確認でき、ワンクリックでの切断にも対応しています。

## 前提条件

- プロジェクトに GameFrameX Network パッケージがインストールされており、シーンに `NetworkComponent` がアタッチされていること。
- ログは `Log.Debug` で出力されるため、GameFrameX ログコンポーネントの Debug レベルのログが有効になっていることを確認してください。無効の場合、コンソールに内容が表示されません。

## 操作手順

### 一、ネットワークログの有効化/無効化

1. Unity の上部メニューバーで `GameFrameX/Scripting Define Symbols` グループを見つけます。
2. 必要に応じて以下のメニュー項目をクリックします(クリックすると、対応するマクロが Player Settings の Scripting Define Symbols に書き込まれ、Unity が自動的に再コンパイルを行います):

| メニュー項目 | 機能 | 対応マクロ |
|------|------|--------|
| `Enable Network Send Logs(开启网络发送日志打印)` | 送信メッセージを出力 | `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Disable Network Send Logs(关闭网络发送日志打印)` | 送信ログを無効化 | `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` を削除 |
| `Enable Network Receive Logs(开启网络接收日志打印)` | 受信メッセージを出力 | `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |
| `Disable Network Receive Logs(关闭网络接收日志打印)` | 受信ログを無効化 | `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` を削除 |

メニューの実装は [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L67-L98) にあり、マクロ定数は次のように定義されています:

```csharp
public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG";
public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG";
public const string ForceEnableNetworkSendLogScriptingDefineSymbol = "FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET";
```

Source: [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L40-L44)

3. 有効化後にゲームを実行すると、コンソールには `发送消息 ID:[10001,0,xxxReq] 消息内容:{...}` や `收到消息 ID:[...] 消息内容:{...}` といった形式のログが出力されます。実際の出力ロジックは以下の通りです:

```csharp
protected void DebugSendLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG
    var messageId = ProtoMessageIdHandler.GetReqMessageIdByType(messageObject.GetType());
    if (!IgnoreSendIds.Contains(messageId))
    {
        Log.Debug($"发送消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}

protected void DebugReceiveLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG
    var messageId = ProtoMessageIdHandler.GetRespMessageIdByType(messageObject.GetType());
    if (!IgnoreReceiveIds.Contains(messageId))
    {
        Log.Debug($"收到消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}
```

Source: [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L949-L969)

### 二、ログ出力を除外するメッセージ ID の設定

高頻度のメッセージ(ハートビートなど)はコンソールが流されてしまうため、Inspector でそれらをログの対象外に設定できます:

1. シーン内で `NetworkComponent` をアタッチしたオブジェクトを選択します。
2. Inspector パネルで以下の 2 つのフィールドを見つけます(**Play モード以外でのみ編集可能**):
   - `Ignore Log Printing For Sent Message IDs`:送信側で無視するメッセージ ID のリスト。
   - `Ignore Log Printing Of Received Message IDs`:受信側で無視するメッセージ ID のリスト。
3. 出力したくないメッセージ ID を入力すると、Play モードに入った時点で有効になります。リストに一致したメッセージに対しては上記の `Log.Debug` は実行されません。

コード内で動的に設定したい場合は、チャネルの基底クラスに公開メソッドが用意されています:

```csharp
public void SetIgnoreLogNetworkIds(List<int> sendIds, List<int> receiveIds)
{
    IgnoreSendIds = sendIds;
    IgnoreReceiveIds = receiveIds;
}
```

Source: [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L977-L982)

### 三、Inspector パネルでランタイム状態を確認

1. Play モードに入り、Hierarchy でシーン内の `NetworkComponent` オブジェクトを選択します。
2. Inspector の上部に `Network Channel Count` が表示され、その後、ネットワークチャネルごとに 1 つのグループとして、以下の内容が表示されます:

| パネルフィールド | 意味 |
|------|------|
| チャネル名 + `Connected`/`Disconnected` | チャネル名と接続状態 |
| `Address Family` | アドレスファミリー(IPv4/IPv6 など) |
| `Local Address` / `Remote Address` | ローカル/リモートのソケットアドレス。未接続の場合は `Unavailable` と表示 |
| `Send Packet` | `已发送包数 / 待发送包数` |
| `Miss Heart Beat Count` | ハートビート喪失回数 |
| `Heart Beat` | `已流逝时间 / 心跳间隔`(秒、小数点以下 2 桁) |
| `Disconnect` ボタン | このチャネルを切断 |

パネル描画の主要コードは以下の通りです。`Disconnect` ボタンは内部で `Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError)` を呼び出します:

```csharp
EditorGUILayout.LabelField(networkChannel.Name, networkChannel.Connected ? "Connected" : "Disconnected");
EditorGUILayout.LabelField("Address Family", networkChannel.AddressFamily.ToString());
EditorGUILayout.LabelField("Send Packet", Utility.Text.Format("{0} / {1}", networkChannel.SendPacketCount, networkChannel.SentPacketCount));
EditorGUILayout.LabelField("Miss Heart Beat Count", networkChannel.MissHeartBeatCount.ToString());
EditorGUILayout.LabelField("Heart Beat", Utility.Text.Format("{0:F2} / {1:F2}", networkChannel.HeartBeatElapseSeconds, networkChannel.HeartBeatInterval));
EditorGUI.BeginDisabledGroup(!networkChannel.Connected);
{
    if (GUILayout.Button("Disconnect"))
    {
        networkChannel.Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError);
    }
}
```

Source: [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L95-L123)

なお、Play モード以外では、Inspector で 2 つの実行時設定項目、すなわち `RPC Timeout Time In Milliseconds`(スライダー範囲 3000–50000 ミリ秒)と `Focus Send Heartbeat` を編集できます。Play モード以外ではパネルに設定エリアのみが表示され、`Available during runtime only.` と通知され、ランタイム状態エリアは描画されません。

## よくあるバリエーション

- **WebSocket チャネルの強制**：同じメニューグループには `Enable Force WebSocket(开启强制使用WebSocket网络)` / `Disable Force WebSocket(关闭强制使用WebSocket网络)` もあり、これらはマクロ `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` を制御し、ネットワークを強制的に WebSocket で通信させるために使用します。
- **一方向のトラフィックのみを調査したい場合**:`Enable Network Receive Logs` のみを有効にして Send をオフにし、受信側の除外リストと組み合わせてハートビートをフィルタリングすれば、サーバーからのダウンストリームメッセージのみを確認できます。

## よくあるエラー

- **マクロを有効にしてもログが一切出力されない**:ログレベルは `Log.Debug` です。GameFrameX ログコンポーネントが Debug レベルを遮断している場合、またはメッセージ ID が除外リスト(`IgnoreSendIds`/`IgnoreReceiveIds`)に一致する場合は、出力されません。
- **Inspector でフィールドを変更できない**:`RPC Timeout`、`Focus Heartbeat`、2 つの除外リストは Play モード中は無効化されています(`EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode)`)。Play モードを終了してから変更してください。
- **パネルにチャネルの状態が表示されない**:ランタイム状態は、Play モード中かつオブジェクトがシーンの Hierarchy 内にある場合にのみ描画されます。Play モード以外の場合、または選択しているのが Prefab アセットの場合は、メッセージのみが表示されます。
- **マクロが有効にならない/コンパイルエラーが発生する**:マクロの書き込み後、Unity は再コンパイルをトリガーします。それでもログが出力されない場合は、`Project Settings > Player > Scripting Define Symbols` にマクロが確実に存在するかを確認してください(メニューはそのマクロの追加と削除を行うだけです)。

## 背景

ログのオン/オフに実行時のブールスイッチではなく条件コンパイル(`#if`)を使用しているのは、ログを無効化した際のコストをゼロにするためです。`Log.Debug` のコード一式と JSON シリアライズはビルド成果物に含まれません。Inspector は `[CustomEditor(typeof(NetworkComponent))]` の `NetworkComponentInspector` によって提供され、毎フレーム `Repaint()` を呼び出してランタイムデータを更新するため、Play モード中はデータが継続的に更新されます。
