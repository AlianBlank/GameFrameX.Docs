# Implementing Player Basic Information (Player Entity and Login)

After completing the tasks on this page, you can have the client log in based on the character ID, while the server initializes player attributes upon login, adds the player to the online list, and returns the attribute snapshot and player information to the client.

## Prerequisites

- `LoginComponentAgent` and the login pipeline already exist (account verification passed, `playerState.Id` obtained).
- `PlayerComponent` has been registered on the player Actor via `[ComponentType(GlobalConst.ActorTypePlayer)]`.
- `PlayerAttributeComponent` has been mounted (it will be read and its snapshot pushed after login).

## Steps

1. Confirm the player entity definition (`PlayerState` inherits from `CacheState` and already includes account, name, level, gender, avatar, state, and login/offline times):

3. Call `PlayerComponentAgent.OnPlayerLogin` in the login handler to trigger the full login flow:

```csharp
public async Task OnPlayerLogin(INetWorkChannel workChannel, PlayerState playerState, RespPlayerLogin response)
{
    SessionManager.UpdateSession(workChannel.GameAppSession.SessionID, playerState.Id, playerState.Id.ToString());
    response.Code = playerState.State;
    response.CreateTime = playerState.CreatedTime;
    response.PlayerInfo = new PlayerInfo
    {
        Id = playerState.Id,
        Name = playerState.Name,
        Level = playerState.Level,
        State = playerState.State,
        Avatar = playerState.Avatar,
    };

    var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
    await attributeComponentAgent.InitializeDefaultsSilent();

    var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
    await serverComp.AddOnlineRole(ActorId);

    var roomComp = await ActorManager.GetComponentAgent<RoomComponentAgent>();
    await roomComp.MarkPlayerReconnected(ActorId);

    await workChannel.WriteAsync(attributeComponentAgent.BuildSyncSnapshot());

    var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
    await mailAgent.SyncAsync();
}
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L62-L93)

4. On player logout, clean up the online marker and recycle the Actor:

```csharp
public async Task OnLogout()
{
    var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
    await serverComp.RemoveOnlineRole(ActorId);
    SetAutoRecycle(true);
    QuartzTimer.Remove(ScheduleIdSet);
}
```

## Key Field Quick Reference

| Field | Type | Purpose |
|------|------|------|
| `AccountId` | `long` | Owning account, used to query the character list by account |
| `Name` / `Avatar` / `Gender` | `string` / `uint` / `int` | Passed in by the client at creation, returned as-is in the login response |
| `Level` | `uint` | Level; level-up logic is maintained by other modules |
| `State` | `int` | Player business state (e.g., normal/banned), written to `response.Code` in the login response |

## Common Variants

- Query only the character list without logging in: `ReqPlayerListHandler` in the repository is the entry point (see `GameFrameX.Hotfix/Logic/Account/Login/ReqPlayerListHandler.cs`), used to list characters before login.
- Create/list characters via HTTP: go through `GameFrameX.Hotfix/Logic/Http/Player/ReqPlayerCreateHttpHandler.cs` and `ReqPlayerListHttpHandler.cs`.
- Kick a player offline: use `GameFrameX.Hotfix/Logic/Http/Player/KickOffLineByUserIdPlayerHttpHandler.cs`.

## Common Errors

- `ReqPlayerCreateHandler` is currently fully commented out in the source code (see [ReqPlayerCreateHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Account/Login/ReqPlayerCreateHandler.cs)); do not implement the client protocol directly based on this class. Use the HTTP handlers instead, or extend it in `LoginComponentAgent`.
- If you forget to call `InitializeDefaultsSilent()` during login, the attribute snapshot may be uninitialized, causing the client to fail to read basic attributes.
- Omitting `SetAutoRecycle(true)` in logout handling will cause the player Actor to remain resident indefinitely, preventing memory from being reclaimed.

## Background (Optional)

`PlayerComponent` uses `StateComponent<PlayerState>` to hold player state. During login, `PlayerComponentAgent.OnPlayerLogin` chains together attribute initialization, adding to the online list, room reconnection marking, attribute snapshot pushing, and lazy mail synchronization, serving as the unified entry point for initializing all player subsystems after login.
