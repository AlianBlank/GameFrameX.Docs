# HTTP インターフェースの追加(Bag / Mail / Player など)

このページでは、`GameFrameX.Hotfix` アセンブリに新しい HTTP インターフェースを追加し、Bag、Mail、Player などのビジネス機能を外部に提供する方法を説明します。完了すると、フレームワークは自動的にこのインターフェースを内蔵 HTTP サービスに登録し、URL で直接呼び出すことができます。

## 前提条件

- ソリューション内の `GameFrameX.Hotfix` プロジェクト構造を理解しており、業務コードが `GameFrameX.Hotfix/Logic/Http/<モジュール>/` に配置されることを知っていること。
- プロトコルプロジェクト(`GameFrameX.Proto`)に `HttpMessageRequestBase` / `HttpMessageResponseBase` のリクエスト / レスポンス型、および `ErrorCode` 列挙型が定義済みであること。
- フレームワークの HTTP 起動エントリを理解していること:[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L40-L52) は `HotfixManager.GetListHttpHandler()` を介して `BaseHttpHandler` を継承するすべてのクラスを自動スキャンします。

## 操作手順

1. **Handler クラスの作成**:`GameFrameX.Hotfix/Logic/Http/<モジュール>/` の下に新しい `sealed class` を作成し、`BaseHttpHandler` を継承します。クラスは `GameFrameX.Hotfix` アセンブリに配置する必要があります。そうでない場合、アーキテクチャアナライザー `GFX0003` によってコンパイルが拒否されます([HttpHandlerAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HttpHandlerAssemblyAnalyzer.cs#L10-L20))。

2. **3 つの属性を付与**:クラスには `HttpMessageMapping`(ルート)、`HttpMessageRequest`(リクエスト型)、`HttpMessageResponse`(レスポンス型、省略可能だが強く推奨)を同時に指定する必要があります。Mail シリーズでは、強く型付けされた `HttpMessageRequestBase` オーバーロードの使用も要求されます:

```csharp
namespace GameFrameX.Hotfix.Logic.Http.Mail;

[HttpMessageMapping(typeof(QueryMailCampaignHttpHandler))]
[HttpMessageRequest(typeof(QueryMailCampaignRequest))]
[HttpMessageResponse(typeof(QueryMailCampaignResponse))]
[Description("Admin 查询运营邮件 Campaign 发布状态")]
public sealed class QueryMailCampaignHttpHandler : BaseHttpHandler
{
    public override async Task<string> Action(string ip, string url, HttpMessageRequestBase requestBase)
    {
        var request = (QueryMailCampaignRequest)requestBase;
        var response = new QueryMailCampaignResponse { Code = MailCampaignErrorCode.Ok };
        // ...业务逻辑...
        return HttpJsonResult.SuccessString(response);
    }
}
```

出典: [QueryMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/QueryMailCampaignHttpHandler.cs#L44-L70)

3. **`Action` メソッドのオーバーライド**:リクエストボディを逆シリアル化する必要があるかどうかによって、以下の 2 つのシグネチャのいずれかを選択します:
   - シンプルなインターフェース(`ReloadHttpHandler`、`TestHttpHandler`):`Dictionary<string, object> parameters` を受け取り、クエリパラメータを自前で解析します。
   - 強く型付けされたインターフェース(Mail、Bag):`HttpMessageRequestBase requestBase` を受け取り、フレームワークが既に逆シリアル化済みです。

   戻り値は `string` である必要があり、`HttpJsonResult` ユーティリティメソッド(`SuccessString` / `ParamErrorString` など)を使用してシリアル化します:

```csharp
public override Task<string> Action(string ip, string url, Dictionary<string, object> parameters)
{
    if (parameters.TryGetValue("version", out var version))
    {
        await HotfixManager.LoadHotfixModule(null, version.ToString());
        return Task.FromResult(HttpJsonResult.SuccessString(null));
    }
    return Task.FromResult(HttpJsonResult.ParamErrorString());
}
```

出典: [ReloadHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/ReloadHttpHandler.cs#L40-L60)

4. **ビルドと起動**:リポジトリのルートディレクトリでビルドを実行すると、フレームワークはすべての `BaseHttpHandler` サブクラスを自動スキャンし、`HttpServer.Start(Setting.HttpPort, Setting.HttpsPort, HotfixManager.GetListHttpHandler(), HotfixManager.GetHttpHandler, null, Setting.HttpUrl)` に登録します([AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L49-L51))。起動後、コメントに記載された URL でデバッグできます。

## よくあるバリエーション

- **リクエスト / レスポンスボディなし**(`TestHttpHandler`):`HttpMessageMapping` のみを指定し、データを返す必要がある場合は `HttpMessageResponseBase` を継承したクラスを手動で作成します。
- **イベントディスパッチが必要な場合**(Bag アイテム配布):Handler 内で `EventDispatcher.Dispatch(...)` を呼び出し、`BagComponentAgent` の完了を非同期で待ち、最後に `HttpJsonResult.SuccessString` で集計結果を返します([ReqPlayerSendItemHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Bag/ReqPlayerSendItemHttpHandler.cs#L45-L80))。
- **GM 系の読み取り専用インターフェース**(Player オンラインリスト):同じく `Dictionary<string, object> parameters` を使用し、Handler 内部で SessionManager を参照します。テンプレートは `GetOnlinePlayerListHttpHandler` を直接参考にしてください。
- **運営メールの 4 点セット**:`PreviewMailCampaignHttpHandler` / `PublishMailCampaignHttpHandler` / `QueryMailCampaignHttpHandler` / `RevokeMailCampaignHttpHandler` が、同じモジュール内に複数のインターフェースを作成する標準的な方法を示しています。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `GFX0003` でコンパイルエラー | `BaseHttpHandler` サブクラスが `GameFrameX.Hotfix` アセンブリに配置されていない | Handler クラスを `GameFrameX.Hotfix/Logic/Http/...` 下に移動する |
| 起動後アクセスすると 404 | `[HttpMessageMapping]` が指定されていない、または型自体が属性のジェネリック引数として渡されていない | 属性の引数が `typeof(YourHandler)` 自体であることを確認する |
| リクエストパラメータが取得できない | `Dictionary<string, object>` シグネチャを使用しているが、フロントエンドが JSON Body を送信している | `HttpMessageRequestBase` オーバーロードに変更し、`[HttpMessageRequest]` を追加する |
| `null` のシリアル化に失敗する | オブジェクトを直接返している(文字列ではなく) | `HttpJsonResult.SuccessString(response)` でラップする |
| ルートが GM 管理画面に認識されない | `[Description]` が空で、ツールが分類できない | 意味のある日本語の `Description("...")` を追加する |

## 背景(オプション)

`BaseHttpHandler` は `GameFrameX.NetWork.HTTP` が提供するイベントベースの基底クラスです。起動時に `HotfixManager.GetListHttpHandler()` がすべての非抽象サブクラスをリフレクションで取得し、`HttpServer` にルーティング登録を委ねます。Mail / Bag / Player モジュールはディレクトリごとにサブネームスペースで分割されており、GM 管理画面と自動スキャンがモジュールごとに分類しやすくなっています。
