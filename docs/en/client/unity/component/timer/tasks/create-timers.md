# Creating Timers: Repeating, One-shot, and Per-frame

All timers can be created through the three entry points of `TimerComponent`: `Add` (repeating/unlimited repeats), `AddOnce` (executes only once), and `AddUpdate` (executes every frame). All three return a timer ID that can be used for subsequent pausing, resuming, querying, and removal.

## Prerequisites

- A GameFrameX framework object already exists in the scene with `TimerComponent` attached (menu path `GameFrameX/Timer`, `[AddComponentMenu("GameFrameX/Timer")]`, see [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L12-L16)).
- Reference the `GameFrameX.Timer.Runtime` namespace in your business code.

## Steps

1. Get a `TimerComponent` reference (for example, via GameFrameX's component retrieval approach).

2. Choose a creation method based on your needs:

| Requirement | Method | Actual Signature |
|------|------|----------|
| Execute every N seconds, repeating M times or infinitely | `Add` | `int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)` |
| Execute only once after an N-second delay | `AddOnce` | `int AddOnce(float interval, Action<object> callback, object callbackParam = null)` |
| Execute every frame | `AddUpdate` | `int AddUpdate(Action<object> callback)` / `int AddUpdate(Action<object> callback, object callbackParam)` |

Source of signatures and default values: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L80).

3. Pass in a callback (type is fixed as `Action<object>`, parameter can be `null`), and save the returned ID.

```csharp
// 1) Unlimited repeat: triggers once per second; passing 0 for repeat means unlimited repetition
int heartbeatId = timerComponent.Add(
    1f, 0,
    param => Debug.Log("heartbeat " + param),
    "tick",
    TimerTimeScale.Unscaled);

// 2) One-shot: executes once after 3 seconds, then is automatically removed
int delayId = timerComponent.AddOnce(3f, param => Debug.Log("done"));

// 3) Per-frame: called once every frame in Update
int frameId = timerComponent.AddUpdate(param => { /* per-frame logic */ });
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L80)

4. Use the ID for subsequent management:

```csharp
timerComponent.Pause(id);        // Pause (time is not accumulated while paused)
timerComponent.Resume(id);       // Resume; accumulation continues from where it was paused
timerComponent.Exists(id);       // Whether it still exists and is active
timerComponent.GetRemaining(id); // Remaining seconds; returns -1 if it does not exist
timerComponent.GetElapsed(id);   // Seconds accumulated; returns -1 if it does not exist
timerComponent.Remove(id);       // Remove
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L105-L118), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L124-L146), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L190-L200)

## Common Variants

### Limiting Repeat Count and Listening for Completion

`repeat > 0` means the timer is automatically removed after triggering that number of times; `onComplete` fires when the timer completes/is removed.

```csharp
// Repeats 5 times, once every 0.5 seconds; after the 5th trigger it is automatically removed and onComplete is invoked
int id = timerComponent.Add(
    0.5f, 5,
    param => Debug.Log("tick"),
    onComplete: () => Debug.Log("all ticks finished"));
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)(when `Repeat` decrements to 0, it is set to `Deleted` and enters the removal queue), [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L134-L147)(executes `OnComplete` upon removal)

### Timers Affected by timeScale

`timeScale` defaults to `TimerTimeScale.Unscaled` (unaffected by `Time.timeScale`); if you want the countdown to pause together with the game when pausing, pass `TimerTimeScale.Scaled`:

```csharp
// When timeScale changes (e.g., pausing the game), Scaled timers slow down/stop accordingly
int id = timerComponent.Add(2f, 0, OnTick, timeScale: TimerTimeScale.Scaled);
```

Source: [TimerTimeScale.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerTimeScale.cs#L6-L13), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

### Group Management with tag

Pass a `tag` at creation time, then you can pause/resume/remove the whole group:

```csharp
timerComponent.Add(1f, 0, OnTick, tag: "battle");
timerComponent.PauseByTag("battle");   // Pause all timers in this group
timerComponent.ResumeByTag("battle");  // Resume all timers in this group
timerComponent.RemoveByTag("battle");  // Remove all timers in this group
timerComponent.HasTag("battle");       // Whether this group still has active timers
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L148-L183)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Log shows `timer callback is null, {interval},{repeat}` and the returned ID is 0 | Callback was passed as `null` | Check for null before calling; the manager directly warns and refuses to create the timer |
| Expected it to "run only once" but it triggers repeatedly | `Add` was passed 0 for `repeat` (0 means unlimited repeats) | Use `AddOnce` for one-shot tasks, or pass `repeat: 1` to `Add` |
| Passed a negative number or 0 for `interval` but it "triggers every frame" | `interval <= 0` is treated as a per-frame timer | Use `AddUpdate` if you want per-frame semantics; do not pass an invalid interval to `Add` |
| The count "resets" after Adding the same callback again | Callbacks are used as keys; a repeated `Add` updates parameters in place and resets `Elapsed` to zero | Use different callbacks (e.g., closures) when you need multiple parallel instances |
| `GetRemaining` does not change after pausing | Time is not accumulated while paused, so the remaining time naturally stays frozen | This is expected behavior; it continues after calling `Resume` |
| Exception thrown inside the callback | By default `CatchCallbackExceptions = false`, so exceptions propagate up | When you need to swallow exceptions, set `TimerManager.CatchCallbackExceptions = true`; exceptions will be logged as a Warning in the form `Timer callback error > ...` |

## Verification

- After creation, call `timerComponent.Exists(id)`; a return value of `true` means it is registered ([TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L110-L118)).
- Use `GetRemaining(id)` / `GetElapsed(id)` to observe the countdown and verify interval and pause behavior; both return `-1` when the timer does not exist ([TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L185-L200)).
- After a one-shot timer triggers, `Exists(id)` should become `false` (it is removed as soon as the trigger completes, see [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L121)).

## Background

`TimerComponent` is just a thin wrapper; the actual logic lives in `TimerManager` (which implements the `ITimerManager` interface). The manager maintains `TimerItem` instances keyed by callback function (containing fields such as `Interval`, `Repeat`, `Elapsed`, `IsPaused`, `Tag`, `OnComplete`), and every frame in `Update` it accumulates `Elapsed` using the time source selected according to `TimeScaleMode`. Once `Interval` is reached, the callback is placed into a pending-execution list and executed outside the lock to avoid blocking other threads; any overflow in a single tick is clamped (zeroed out when it exceeds 0.03s) to prevent consecutive catch-up triggers at low frame rates. For async/await style timer usage, see `TimerAsyncExtensions`.
