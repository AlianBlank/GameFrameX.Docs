# What to Do When Global Info API Fetch Fails

After the startup flow enters `ProcedureGetGlobalInfoState`, if all `GlobalInfoUrls` fail to return the configuration successfully (and no usable local cache is available), a `StartupFailedEventArgs` will be triggered and startup will end with `ProcedureGetGlobalInfoState` as the failed procedure name. This article explains common causes, troubleshooting methods, and corresponding fixes.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Startup immediately throws `ArgumentException`: `StartupOptions.GlobalInfoUrls must contain at least one URL.` | `StartupOptions.GlobalInfoUrls` is `null` or an empty array | See "Fix Step 1" |
| The flow skips the global info request and goes directly to `ProcedurePatchInit` | `SkipRemoteStartupRequests = true`, or `GamePlayMode` is `EditorSimulateMode` / `OfflinePlayMode` | See "Fix Step 2" |
| In the failure event `StartupFailedEventArgs`, `procedureName = "ProcedureGetGlobalInfoState"`, and the UI tip `Loading... (n/total)` is stuck | All URL failover attempts failed (network/timeout/HTTP error/server returned a non-success code) | See "Fix Step 3" |
| Startup still succeeds after the first failure, and the UI shows `Using cached startup config...` | The last successful result was written to the cache via `StartupNetworkCacheUtility`, so this run takes the fallback path | See "Fix Step 4" |
| WebGL/standalone environment cannot access the backend, and startup gets stuck at the network stage | Remote startup requests should not be enabled | See the usage of `SkipRemoteStartupRequests` in "Fix Step 2" |

The three fields `procedureName`, `failedUrl`, and `errorMessage` are written into `StartupFailedEventArgs` by [`StartupProcedureUtility.CompleteFailure`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L162-L167) and can be used for precise troubleshooting.

## Fix Steps

### Fix Step 1: An empty `GlobalInfoUrls` is configured

`StartupRunner.Run` validates synchronously before entering the async state machine:

```csharp
// Runtime/Startup/StartupRunner.cs
if (options.GlobalInfoUrls == null || options.GlobalInfoUrls.Length == 0)
{
    throw new ArgumentException(
        "StartupOptions.GlobalInfoUrls must contain at least one URL.",
        nameof(StartupOptions.GlobalInfoUrls));
}
```

Source: [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L63-L68)

Fill in at least one URL in the `StartupOptions` asset:

```csharp
// Runtime/Startup/StartupOptions.cs
[Header("Network")] [Tooltip("Primary and backup URL list for the global info API, tried in order. An empty array is treated as a configuration error.")]
public string[] GlobalInfoUrls = new string[0];
```

Source: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### Fix Step 2: The runtime environment should not make remote requests

`ProcedureGetGlobalInfoState.OnEnter` contains three early-exit branches; hitting any one of them will skip the global info API:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode)
{
    Debug.Log("Editor simulate mode, skip global info request.");
    ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
    return;
}

if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}

if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L28-L48)

Corresponding handling:

| Scenario | Setting | Notes |
|------|--------|------|
| Editor simulate mode | `GamePlayMode = EPlayMode.EditorSimulateMode` | Only effective in the editor; outside the editor, `StartupRunner.NormalizeAssetPlayMode` rewrites it to `HostPlayMode` |
| Offline mode | `GamePlayMode = EPlayMode.OfflinePlayMode` | Goes directly to `ProcedurePatchInit` without attempting remote access |
| WebGL standalone / no backend | `SkipRemoteStartupRequests = true` | See the field description in [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31) |

### Fix Step 3: All URL failover attempts failed

`GetGlobalInfoAsync` tries `GlobalInfoUrls` in order via [`UrlFailoverRunner.ExecuteAsync`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L67-L92), with at most `MaxAttemptsPerUrl` attempts per URL and an interval of `RetryDelayMs` milliseconds between attempts. Any HTTP exception or `responseGlobalInfo.IsSuccess == false` counts as a failed attempt:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var json = await GameEntry.GetComponent<WebComponent>().PostToString(url, jsonParams);
var responseGlobalInfo = json.Result.ToHttpJsonResultData<ResponseGlobalInfo>();
if (!responseGlobalInfo.IsSuccess)
{
    return UrlAttemptResult.Fail("Global info server returned code " + responseGlobalInfo.Code);
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L75-L84)

Troubleshoot in the following order:

1. In `StartupOptions`, confirm that at least one accessible URL is filled in and that they are ordered "primary → backup".
2. `POST` directly to the URL in a browser/Postman using the same `jsonParams` (generated via `StartupProcedureUtility.CreateHttpParams`), and confirm that the server returns `IsSuccess == true`.
3. Check whether `MaxAttemptsPerUrl` (default 3) and `RetryDelayMs` (default 3000) are too small, causing attempts to be exhausted too early on a weak network:

   ```csharp
   // Runtime/Startup/StartupOptions.cs
   public int MaxAttemptsPerUrl = 3;
   public int RetryDelayMs = 3000;
   ```
   Source: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L26-L28)

4. In `IStartupHttpParamsProvider`, confirm that common parameters such as `PackageName` / `Channel` / `SubChannel` are correctly recognized by the server; missing or incorrect values may also cause the server to return a non-success code.

### Fix Step 4: Enable the local cache fallback

When all URLs fail, `GetGlobalInfoAsync` tries to read the cache written by the last successful run; on a cache hit, startup continues:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (!result.Success)
{
    if (StartupNetworkCacheUtility.TryApplyCachedGlobalInfo())
    {
        uiHandler?.SetTipText("Using cached startup config...");
        ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
        return;
    }

    StartupProcedureUtility.CompleteFailure(
        procedureOwner,
        nameof(ProcedureGetGlobalInfoState),
        result.FailedUrl,
        result.ErrorMessage);
    return;
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L94-L109)

- The cache key is `GameFrameX.Startup.NetworkCache.GlobalInfo`, maintained by [`StartupNetworkCacheUtility`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupNetworkCacheUtility.cs#L23).
- If you want startup to continue even on a weak network, first run the full flow once in a good network environment to write the cache, then keep the fallback logic.
- If you want an immediate error on network failure instead of falling back to the cache, explicitly check `ProcedureName == "ProcedureGetGlobalInfoState"` when the caller receives the `StartupResult`, and prompt the user to check the network.
