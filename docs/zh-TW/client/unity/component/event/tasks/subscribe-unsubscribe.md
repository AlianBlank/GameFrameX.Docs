# 如何訂閱與取消訂閱事件

透過場景中的 `EventComponent`(選單 `GameFrameX/Event`)訂閱事件：呼叫 `CheckSubscribe(id, handler)` 完成訂閱，呼叫 `Unsubscribe(id, handler)` 或 `CheckUnsubscribe(id, handler)` 取消訂閱。處理器簽章為 `EventHandler<GameEventArgs>`,事件編號 `id` 為 `string`。

## 前置條件

- 場景中已存在 GameFrameX 入口並掛載了 `EventComponent` 元件(`[AddComponentMenu("GameFrameX/Event")]`)。
- 如需自訂事件參數，準備一個繼承 `GameEventArgs` 的參數類別；無參數事件可直接使用 `string` 事件編號。

## 訂閱與取消訂閱相關 API

| 方法 | 實際簽章 | 行為 |
|------|----------|------|
| `EventComponent.CheckSubscribe` | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 未訂閱時才訂閱，可安全重複呼叫 |
| `EventComponent.Unsubscribe` | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 取消訂閱(直接轉送給管理器) |
| `EventComponent.CheckUnsubscribe` | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | handler 不存在時不執行任何操作 |
| `EventComponent.Check` | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 檢查是否存在該處理函式 |
| `EventComponent.Count` | `int Count(string id)` | 該事件編號下的處理函式數量 |
| `IEventManager.Subscribe` | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | 管理器層原生訂閱，不做去重 |

元件上的方法都是對 `IEventManager` 的轉送，`CheckSubscribe` 的實際實作是「先 `Check` 再 `Subscribe`」:

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

## 操作步驟

1. 在腳本中保存對 `EventComponent` 的參考(透過 Inspector 序列化參考或尋找場景中的元件)。元件在 `Awake` 中自動取得 `IEventManager` 模組：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

2. 撰寫事件處理函式，簽章必須是 `void (object sender, GameEventArgs e)`,即 `EventHandler<GameEventArgs>`。自訂參數類別直接繼承 `GameEventArgs`(本身為空的抽象基底類別，繼承自 `BaseEventArgs`):

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class GameEventArgs : BaseEventArgs
{
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

3. 在初始化時機(如 `OnEnable`)訂閱事件，建議使用 `CheckSubscribe` 避免重複訂閱:`m_EventComponent.CheckSubscribe("Player.HealthChanged", OnHealthChanged);`。
4. 在銷毀/停用時機(如 `OnDisable`/`OnDestroy`)取消訂閱:`m_EventComponent.CheckUnsubscribe("Player.HealthChanged", OnHealthChanged);`。對應實作：

```csharp
public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.Unsubscribe(id, handler);
}

public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L118-L131)

5. 處理函式內部視需要將 `e` 轉換為自訂參數型別後讀取資料。取消訂閱後，可透過 `m_EventComponent.Check(id, handler)` 回傳 `false`、`Count(id)` 回傳 `0` 驗證已解除訂閱。

## 常見變體

- **重複初始化場景**：多次進入同一邏輯時直接使用 `CheckSubscribe` / `CheckUnsubscribe`,兩者內部都先檢查再執行，重複呼叫不會發生錯誤。`CheckUnsubscribe` 的實作在管理器層判斷 `handler` 不存在時不執行任何操作：

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (m_EventPool.Check(id, handler))
    {
        m_EventPool.Unsubscribe(id, handler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L140-L146)

- **無參數事件**：只需要一個事件編號、不需要攜帶資料時，可用 `Fire(object sender, string eventId)` 直接以字串觸發。元件內部會自動建立 `EmptyEventArgs`:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`EmptyEventArgs.Create` 從參考池取得物件並設定事件編號：

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

- **預設處理**：呼叫 `SetDefaultHandler(EventHandler<GameEventArgs> handler)` 設定預設事件處理函式，用於接收沒有訂閱者的事件。

## 常見錯誤

| 錯誤 | 原因 | 修正 |
|------|------|------|
| 元件初始化失敗，日誌輸出 `Event manager is invalid.` | 場景缺少可用的 `IEventManager` 模組/GameFrameX 入口未初始化 | 確認場景中存在 GameFrameX 入口並掛載 `EventComponent` |
| 同一處理器被多次觸發 | 使用了 `IEventManager.Subscribe`(不去重)且重複呼叫 | 改用 `EventComponent.CheckSubscribe` |
| 取消訂閱時發生錯誤 | 傳入了未訂閱的 `handler` 或 `id` 不相符 | 改用 `EventComponent.CheckUnsubscribe` |
| 處理函式簽章不相符 | 未使用 `EventHandler<GameEventArgs>`(`void (object, GameEventArgs)`) | 按該簽章撰寫處理函式 |
| 事件觸發時機與預期不符 | `Fire` 是執行緒安全的但事件在下一幀分發，`FireNow` 立即分發但非執行緒安全 | 視需要選擇 `Fire` / `FireNow` |

## 背景

`EventComponent` 是 Unity 場景上的門面元件，所有訂閱 API 轉送到 `IEventManager`(`EventManager`),後者再委派內部的 `m_EventPool` 完成實際的事件池維護。因此呼叫方只需面對 `EventComponent` 的 `Subscribe`/`Unsubscribe`/`Check` 語意，不必關心底層事件池。
