# 生成后找不到 TbXxx 类怎么办

跑完 `gen-client-json.bat` / `gen-client-json.sh` 后,在 Unity 或 .NET 工程里却找不到 `TbMyItem`、`TbAchievement` 之类的类——通常不是工具坏了,而是文件名、生成脚本或输出目录对不上。本页按错误现象给出诊断表和修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 完全找不到 `TbXxx` 类,输出目录里也没有对应 `.cs` 文件 | Excel 文件名不符合 `字母-英文名-中文名.xlsx` 规则,工具识别失败 | 见「修复步骤 1」 |
| 报错 `不支持中文表名` 或 `table name invalid` | 文件名的「英文名」段写了中文 | 见「修复步骤 2」 |
| `TbClient` 里有 `TbXxx`,`TbServer` 里没有(或反过来) | 文件名带分组标记 `c` / `s`,把表限制到了单端 | 见「修复步骤 3」 |
| 生成脚本跑完一闪而过,看不到任何 `Tb` 类 | 走错了脚本(跑了 server 端却去 client 工程找),或脚本未真正执行成功 | 见「修复步骤 4」 |
| 提示找不到 `luban.conf` / `Tools/` 目录 | 不在 `Config/` 根目录里运行脚本 | 见「修复步骤 5」 |
| 类名是 `TbXxx2`、`TbXxx_1`,不是预期的 `TbXxx` | 同一张表拆成了多份,英文名拼写不一致 | 见「修复步骤 6」 |

## 修复步骤

### 1. 检查 Excel 文件名是否符合命名规则

工具只识别严格符合 `字母-英文名-中文名.xlsx` 形式的文件,文件名错了就不会生成任何代码。

打开 `Config/Excels/Tables/` 文件夹,确认文件名形如:

```
D-ItemConfig-道具表.xlsx
```

三段含义:

| 段 | 作用 | 规则 |
|----|------|------|
| 字母 | 排序用的单字母 | 任意字母或数字 |
| 英文名 | **会变成代码类名 `Tb英文名`** | 必须纯英文,**不能写中文** |
| 中文名 | 给策划/同事看 | 任意,可含 `-` |

来源:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L164-L190)

示例对照表:

| 文件名 | 生成的类 |
|--------|----------|
| `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
| `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
| `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |

### 2. 英文名段不能含中文

如果报错 `不支持中文表名` 或 `table name invalid`,说明「英文名」段写了中文(如 `D-道具-我的道具表.xlsx`)。把中间那段改成纯英文即可:

```
错误:D-道具-我的道具表.xlsx
正确:D-Item-我的道具表.xlsx     → 生成 TbItem
```

### 3. 检查文件名里的分组标记

如果你只想给客户端或只给服务端用,需要在英文名和中文名中间加分组标记。**没意识到加了标记,就会以为类「丢了」**。

| 文件名 | 效果 |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | 客户端、服务端都用 |
| `D-ItemConfig-c-道具表.xlsx` | **只有客户端**有 `TbItemConfig` |
| `D-ItemConfig-s-道具表.xlsx` | **只有服务端**有 `TbItemConfig` |

确认要的目标工程是客户端还是服务端,然后选对应的文件名,或者把 `-c-` / `-s-` 去掉,让两边都生成。

来源:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

### 4. 确认跑的是正确的生成脚本

`Config/` 根目录下通常有多个生成脚本,**跑错脚本是找不到类的最常见原因**:

| 脚本 | 生成的类型 |
|------|----------|
| `gen-client-json.bat` / `gen-client-json.sh` | JSON 数据 + C# 类,用于客户端 |
| `gen-server-bin.bat` / `gen-server-bin.sh` | 二进制数据 + C# 类,用于服务端 |

- Windows:在 `Config/` 目录下双击对应 `.bat`
- Mac / Linux:终端里 `cd Config` 后运行 `sh gen-*.sh`

跑完后看输出目录里有没有新生成的 `.cs` 文件——有就说明成功了,只是可能在另一个工程里。

来源:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L134-L148)

### 5. 在 Config 根目录下执行脚本

`gen-*.bat` / `gen-*.sh` 依赖同目录下的 `luban.conf` 和 `Tools/` 目录。如果从别的目录执行,会出现找不到配置或工具目录的错误,生成会静默失败。

```bash
# 正确
cd Config
sh gen-client-json.sh

# 错误(从上级目录跑)
sh Config/gen-client-json.sh   # 可能找不到 luban.conf
```

### 6. 拆分多份表时英文名必须完全一致

一张表太大可以拆成多份,工具按「英文名」合并。**英文名拼写不一致就会拆成两张表,生成两个类**:

```
正确(都合并成 TbItemConfig):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemConfig-道具表-1001-2000.xlsx

错误(英文名不一致,生成 TbItemConfig 和 TbItemConfig2):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemCongfig-道具表-1001-2000.xlsx   ← 注意 ItemCongfig 拼错了
```

统一英文名后重新跑生成脚本。

来源:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L234-L248)

## 验证

按以上步骤修好后,用以下方法确认:

1. **重新跑生成脚本**,确保脚本**没有报错**就跑完(看到 `pause` 或 `Press any key` 而不是错误堆栈)。
2. **打开生成输出目录**,确认里面有 `TbXxx.cs` 和对应数据文件(JSON 或 bin)。
3. **在 Unity / .NET 工程里右键 → 重新生成/刷新项目**,让 IDE 识别新加的 `.cs` 文件。
4. **用最小调用验证**:

```csharp
// 假设表名是 ItemConfig,id 列填了 10001
var item = tables.TbItemConfig.Get(10001);
UnityEngine.Debug.Log(item.Name);
```

能正常打印说明类已正确加载;仍报 `TbItemConfig` 不存在,回到诊断表继续排查。
