# 가위바위보(RockPaperScissors) 게임 구현

이 페이지에서는 GameFrameX.Server에서 기존 가위바위보 게임 코드를 기반으로, 여러 플레이어가 손을 내고 동기화된 정산을 수행하는 방 내 게임을 연동하는 방법을 소개합니다. 완료하면 플레이어가 손을 제출하고, 서버가 규칙에 따라 승패를 판정하며, 게임 상태를 플레이어에게 실시간으로 전달하는 전체 흐름을 갖추게 됩니다.

## 사전 조건

- GameFrameX.Server 메인 프로젝트가 컴파일되어 실행 중이며, 프레임워크의 Actor/Component/MessageHandler 메커니즘을 사용할 수 있습니다.
- 네트워크 채널에서 현재 플레이어 ID를 추출할 수 있는 `RoomHandlerHelper.GetCurrentRoleId(netWorkChannel)`가 이미 있으며, 가위바위보 게임은 동일한 인증 경로를 재사용합니다.
- 클라이언트가 아래 표의 세 가지 메시지에 해당하는 요청/응답 처리를 이미 구현했습니다.

## 게임 메시지 목록

메시지 번호는 Proto에서 `(MainId << 16) + SubId`로 할당되며, 가위바위보 메인 모듈 ID는 `410`입니다.

| 메시지명 | 메시지 번호 | 방향 | 핵심 필드 |
|--------|--------|------|----------|
| `ReqRockPaperScissorsGameInfo` | `(410 << 16) + 10` | C→S | `RoomId` |
| `RespRockPaperScissorsGameInfo` | `(410 << 16) + 11` | S→C | `GameInfo`, `ErrorCode` |
| `ReqSubmitRockPaperScissorsGesture` | `(410 << 16) + 12` | C→S | `RoomId`, `Gesture` |
| `RespSubmitRockPaperScissorsGesture` | `(410 << 16) + 13` | S→C | `GameInfo`, `ErrorCode` |
| `ReqRestartRockPaperScissorsGame` | `(410 << 16) + 14` | C→S | `RoomId` |
| `RespRestartRockPaperScissorsGame` | `(410 << 16) + 15` | S→C | `GameInfo`, `ErrorCode` |

`RockPaperScissorsGesture` 열거형 값: `None = 0`, `Rock = 1`, `Scissors = 2`, `Paper = 3`. 클라이언트가 정산 전에 보는 모든 플레이어의 `Gesture`는 항상 `None`이며, 정산 후에야 실제 손을 읽을 수 있습니다.

## 서버 데이터 구조

서버는 `RockPaperScissorsGameListState`를 전역 캐시로 사용하며, `RoomId`를 키로 각 방의 한 판 가위바위보 데이터 `RockPaperScissorsGameState`를 저장하고, 그중 `GestureMap`이 각 플레이어의 이번 판 손을 기록합니다.

```csharp
public sealed class RockPaperScissorsGameListState : CacheState
{
    // Key: 방 ID, Value: 가위바위보 게임 데이터.
    public Dictionary<long, RockPaperScissorsGameState> Games { get; set; }
        = new Dictionary<long, RockPaperScissorsGameState>();
}

public sealed class RockPaperScissorsGameState
{
    public long RoomId { get; set; }
    public int Round { get; set; } = 1;
    // 플레이어 손 기록. Key: 플레이어 ID, Value: 손.
    public Dictionary<long, RockPaperScissorsGesture> GestureMap { get; set; }
        = new Dictionary<long, RockPaperScissorsGesture>();
    // 승리한 플레이어 ID. 무승부는 0.
    public long WinnerRoleId { get; set; }
}
```

출처: [RockPaperScissorsHandlerHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/RockPaperScissors/RockPaperScissorsHandlerHelper.cs#L36-L41)

3. **세 개의 메시지 핸들러 구현**. `GameFrameX.Hotfix/Logic/Game/RockPaperScissors/` 아래에 각각 배치합니다:
   - `ReqRockPaperScissorsGameInfoHandler`: 방의 현재 판 정보를 읽어 반환합니다.
   - `ReqSubmitRockPaperScissorsGestureHandler`: 플레이어의 손을 기록하고, 모두가 손을 낸 후 정산하여 `WinnerRoleId`를 기록하며, `GameInfo`를 반환합니다(`Gesture` 필드는 정산 전 외부에 `None`으로 유지됨).
   - `ReqRestartRockPaperScissorsGameHandler`: `GestureMap`을 재설정하고, `Round`를 증가시키며, 이전 판의 `WinnerRoleId`를 비워서 다음 판에서 다시 손을 낼 수 있도록 합니다.

4. **클라이언트 프로토콜 정렬**. 클라이언트는 위 표의 "메시지 번호"에 따라 각각 요청 구조체를 구성하고, 전송 전에 `Clear()`를 호출하며, 응답 수신 후 `ErrorCode`와 `GameInfo.Players`를 읽고, `HasGesture`를 통해 플레이어가 이미 손을 냈는지 판단합니다.

## 일반적인 변형

- **두 플레이어 시나리오**: `GestureMap`에 정확히 두 개의 레코드가 있을 때 정산할 수 있으며, 승자는 `WinnerRoleId`에 기록됩니다. 두 손이 같으면 `0`을 유지하여 무승부를 나타냅니다.
- **다중 플레이어 시나리오**: "임의의 두 명이 같은 손을 내면 나머지가 계속 진행한다"와 같은 규칙으로 확장할 수 있으며, 로직은 `ReqSubmitRockPaperScissorsGestureHandler` 내부에 작성하므로 Proto를 수정할 필요가 없습니다.
- **한 판 다시 플레이**: 클라이언트는 정산 결과를 받은 후 `ReqRestartRockPaperScissorsGame`(`(410 << 16) + 14`)을 호출하여 `Round`를 1 증가시키고 `GestureMap`을 비우면, 플레이어가 다시 손을 낼 수 있습니다.

## 일반적인 오류

- **상대방의 손 직접 읽기**: 서버는 정산 전에 `Gesture`를 `None`으로 설정하므로, 클라이언트가 정산을 기다리지 않고 읽으면 항상 `None`으로 보입니다.
- **`Clear()` 미호출**: Proto 메시지 객체를 재사용할 때 잔여 필드로 인해 이전 `RoomId` / `Gesture`가 새 요청으로 그대로 전달될 수 있으므로, 반드시 `Send` 전에 `req.Clear()`를 호출하십시오.
- **권한 초과 접근**: Handler에서 직접 `RoleId`를 해석하지 말고, `RockPaperScissorsHandlerHelper.GetCurrentRoleId(netWorkChannel)`로 통일하여 신분 위조를 방지하십시오.
- **방 간 데이터 유출**: 모든 읽기/쓰기는 `RoomId`를 사전 키로 사용하여 `RockPaperScissorsGameListState.Games`에 접근해야 하며, 절대 정적 필드로 방 상태를 저장하지 마십시오.
