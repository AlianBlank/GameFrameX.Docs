# How to Use UI Groups (UIGroup) to Control Canvas Hierarchy and Depth

With `UIGroup` (UI group), opened forms can be organized by business logic and attached to different `RectTransform` nodes. Each layer added within a group pushes the `Z` axis depth back in steps of 1000, which determines the drawing order and click hit order. This page covers the two most common usages: declaring a group on the form via an attribute, and manually assigning the group at runtime.

## Prerequisites

- The project has imported GameFrameX and `com.gameframex.unity.ui.ugui`, and the UI framework has been initialized in the scene via `UIComponent` (the scene contains nodes such as `UGUICanvas`, `UGUICamera`, and `EventSystem`, which are created on demand by `UGUIUIGroupHelper.EnsureRuntimeRoot` when the first form is opened).
- You already know that the form class you want to open implements `IUIForm` (or inherits from `UIForm` / a base class generated by the framework code generator).

## Steps

### Option 1: Bind a Form to a Group Using `OptionUIGroupAttribute`

Declare the `OptionUIGroup` attribute on the form type, and `UGUIFormHelper` will automatically retrieve the group with the same name from `UIComponent` and assign it to `uiForm.UIGroup`.

```csharp
using GameFrameX.UI.Runtime;

[OptionUIGroup("HUD")]
public sealed class HUDForm : UIForm
{
    // ...
}
```

`UGUIFormHelper` first reads `uiForm.UIGroup`. If it is null, it calls `m_UIComponent.GetUIGroup(...)` with the `GroupName` from the attribute:

```csharp
// Source: UGUIFormHelper.cs
var uiGroup = uiForm.UIGroup;
if (uiGroup == null)
{
    var attribute = uiFormType.GetCustomAttribute(typeof(OptionUIGroupAttribute));
    if (attribute is OptionUIGroupAttribute optionUIGroup)
    {
        uiGroup = m_UIComponent.GetUIGroup(optionUIGroup.GroupName);
    }

    uiForm.UIGroup = uiGroup;
}
```

Source: [UGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L112-L122)

### Option 2: Manually Assign a Group at Runtime

Before calling `UIComponent.OpenUIForm` (or indirectly through `UIManager.OpenUIForm`), retrieve the target `IUIGroup` from `UIComponent` yourself and assign it to `uiForm.UIGroup`.

```csharp
var group = GameEntry.UI.GetUIGroup("Popup"); // e.g., retrieve the group named "Popup"
// Assign the group after the form is opened
uiForm.UIGroup = group;
```

Once assigned, `UIManager.Open` passes the group as a parameter to `uiForm.Init(...)`, and subsequent open/close/focus operations are all managed under that group:

```csharp
// Source: UIManager.Open.cs
var uiGroup = uiForm.UIGroup;
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, null,
    pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L200-L201)

### How Depth Is Calculated

When each group is created via `UGUIUIGroupHelper`, it gets a `RectTransform`, and child nodes under the group are separated by `localPosition.z`:

```csharp
// Source: UGUIUIGroupHelper.cs
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

Source: [UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

Key points:

- `Depth` is the index of the group among all groups (usually assigned by `UIComponent` in creation order).
- Multiple forms within the same group are stacked backward in units of 1000 in the order they were opened, so the drawing order is deterministic under a `ScreenSpaceCamera` `Canvas` (`planeDistance = 100f`, `sortingOrder = 0`).
- To make some forms render on top of others, either put them in a group with a larger index, or let later-opened forms cover earlier ones within the same group.

### Runtime Structure of a Group

Calling `Handler(...)` performs the following:

1. Calls `SetDepth(depth)` to set the current node's `z` to `depth * 1000`;
2. Ensures `UGUICamera`, `UGUICanvas`, and `EventSystem` exist under the root via `EnsureRuntimeRoot`;
3. Creates a `GameObject` named `groupName` under `root`, attaches a `RectTransform` and stretches it full screen;
4. Sets the layer of the entire node and its children to `UI`;
5. Calls `Helper.CreateHelper` to attach a `UGUIUIGroupHelper` instance (or a custom helper you pass in) to the node:

```csharp
// Source: UGUIUIGroupHelper.cs
GameObject component = new GameObject(groupName);
component.transform.SetParent(root, false);
var uiLayer = LayerMask.NameToLayer("UI");
component.SetLayerRecursively(uiLayer);

RectTransform rectTransform = component.GetOrAddComponent<RectTransform>();
rectTransform.MakeFullScreen();
var uiGroupHelper = Helper.CreateHelper(component, uiGroupHelperTypeName,
    (UIGroupHelperBase)customUIGroupHelper, 0);
return uiGroupHelper;
```

Source: [UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L86-L113)

The final scene hierarchy looks roughly like this:

```
UIComponent
└── UGUICanvas (Canvas, CanvasScaler, GraphicRaycaster)
    ├── Default (Group 0)
    │   ├── FormA
    │   └── FormB
    ├── HUD (Group 1)
    │   └── HUDForm
    └── Popup (Group 2)
        └── PopupForm
```

## Common Variants

- **Multiple group layering**: Assign forms with different purposes such as `HUD`, `Popup`, `Dialog`, and `Loading` to different groups; groups are naturally layered by `depth * 1000`.
- **Replace the default helper**: Implement `IUIGroupHelper` (inherit `UIGroupHelperBase`), then pass it in via the `customUIGroupHelper` parameter when calling `UIComponent` to add a group, overriding the default `UGUIUIGroupHelper` behavior (e.g., a custom depth algorithm or extra components).
- **Editor customization**: View/adjust groups and depths in the Inspector via editor scripts such as `UGUIComponentInspector`.

## Common Mistakes

- **Neither declaring `OptionUIGroup` nor assigning manually**: When entering `UGUIFormHelper`, `uiGroup` is `null`, which eventually triggers the log `UI group is invalid.` and returns `null`, causing the form to fail to open.
- **Misspelled group name**: Using `OptionUIGroup("Popuo")` while the group in `UIComponent` is actually named `"Popup"` makes `GetUIGroup` return `null`, which likewise triggers `UI group is invalid.`. Agree on shared constants to avoid typos.
- **Expecting to change layering via `Canvas.sortingOrder`**: In this implementation, the group-level `Canvas.sortingOrder` is fixed at `0`; separation within/between groups relies on `localPosition.z = depth * 1000`. Changing `sortingOrder` directly in the Inspector will be overwritten by the next `Handler(...)` call.
- **Manually adding nodes under `UGUICanvas` but forgetting to set the `UI` layer**: Although nodes created by `UGUIUIGroupHelper` get `SetLayerRecursively(uiLayer)`, auxiliary UI child nodes you attach yourself must still be kept on the `UI` layer; otherwise they will be culled by `UGUICamera`'s `cullingMask`.

## Background (Optional)

The idea of `UIGroup` originates from the classic GameFrameX framework's form grouping: all forms share a single `UGUICanvas`, `Z` axis offsets prevent multiple Canvases from covering each other, and `GraphicRaycaster` handles click dispatching. `SetDepth` scales `depth` by 1000 directly to leave enough slots for repeatedly "bringing a form to front" within the same group — by adding small incremental offsets on top of the same `Depth` value, you can reliably push a specific form to the top of its group without affecting other groups.
