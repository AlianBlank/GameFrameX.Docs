# 如何撰寫可熱重載的業務邏輯（Hotfix 層）

將客戶端請求處理、登入、角色創建、HTTP 後台指令等業務邏輯放入 `GameFrameX.Hotfix` 組件中，即可在不重啟伺服器的情況下重新載入 dll 並立即生效。以下說明如何在 Hotfix 專案中新增一個框架可識別且可熱重載的訊息處理器。

## 前置條件

- 伺服器程序可正常啟動；框架會在啟動時呼叫 `HotfixManager.LoadHotfix` 來載入 `GameFrameX.Hotfix.dll`。
- `GameFrameX.Hotfix` 專案需參考 `GameFrameX.Core.Abstractions`（其中提供 `[MessageMapping]`、`GlobalRpcComponentHandler` 等基底類別與屬性）。
- 待處理的訊息請求/回應型別 `ReqXxx` / `RespXxx` 必須存在於共享協議專案中，並繼承框架的 `Message` 基底類別。

## 步驟

### 1. 建立訊息請求/回應型別

在協議專案中定義請求與回應，繼承框架的 `Message` 基底類別。框架會依據 `OpCode` 自動分派至對應的 Handler。

### 2. 在 Hotfix 專案中建立 Handler

Hotfix 層的所有業務訊息處理器皆放在 `GameFrameX.Hotfix/Logic/` 目錄下，並依業務模組組織成子資料夾（例如 `Account/Login`、`Http/Player`）。以下是一個標準的登入請求範例：

```csharp
namespace GameFrameX.Hotfix.Logic.Account.Login;

using PlayerLoginComponentAgent = GameFrameX.Hotfix.Logic.Player.Login.LoginComponentAgent;

[MessageMapping(typeof(ReqLogin))]
internal sealed class ReqLoginHandler : GlobalRpcComponentHandler<PlayerLoginComponentAgent, ReqLogin, RespLogin>
{
    protected override async Task ActionAsync(ReqLogin request, RespLogin response)
    {
        await ComponentAgent.OnLoginAsync(request, response);
    }
}
```

來源：[ReqLoginHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs#L30-L41)

關鍵要點：
- 必須使用 `[MessageMapping(typeof(ReqLogin))]` 屬性將 Handler 與請求型別綁定；框架在載入 Hotfix dll 時會透過反射掃描此屬性，以建立訊息 ID → Handler 的映射。
- 該類別繼承自 `GlobalRpcComponentHandler<TComponentAgent, TRequest, TResponse>`，框架會自動管理組件代理（`ComponentAgent`）的生命週期。
- 業務實作位於 `ComponentAgent` 上；Handler 僅負責「接收請求 → 呼叫代理」的薄層封裝。如此一來，所有狀態都集中在 Agent 中，熱重載後可輕鬆由新版本的同名 Agent 取代。
- 存取範圍請使用 `internal sealed`，以防止外部組件意外引用即將被卸載的 dll 中的型別。

### 3. 實作 ComponentAgent（實際的業務落地點）

Agent 繼承自 `BaseComponentAgent`（位於 Core 的 Hotfix.Agent 命名空間），可熱重載的業務邏輯即撰寫於其方法中。Agent 是 Handler 所呼叫的唯一「長存」物件，因此請將狀態、快取與協程放在這裡。

### 4. 建置並替換 dll

1. 建置 `GameFrameX.Hotfix` 專案以產出 `GameFrameX.Hotfix.dll`。
2. 將 dll 放置於伺服器執行目錄下預設的 `hotfix/` 子目錄（可透過 `HotfixManager.LoadHotfix` 的 `dllPath` 參數變更）。
3. 觸發框架的重新載入入口（透過運維 HTTP 指令或心跳呼叫 `HotfixManager.LoadHotfixModule`）；框架會先將舊模組加入 `OldModuleMap` 以處理過渡期間仍在執行中的請求，然後將新模組切換為當前模組 — 無需重啟程序。

```csharp
public static bool LoadHotfix(AppSetting setting, string dllVersion = "", string dllPath = "hotfix", string hotfixDllName = "GameFrameX.Hotfix.dll")
```

來源：[HotfixManager.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L95-L116)

### 5. 驗證

- 啟動日誌顯示 `HotfixManager.LoadHotfix` 回傳 `true`，且 `HotfixAssembly` 不為 null。
- 從客戶端發送帶有對應 `OpCode` 的請求；依 Hotfix 層日誌可見新的 Handler 已被呼叫。
- 替換 dll 後再次發送相同請求 — 行為會依新版本的邏輯改變，且舊 dll 正在處理中的請求不會被中斷（由 `OldModuleMap` 處理）。

## 常見變化

### HTTP 後台指令

HTTP 處理器的撰寫方式與 RPC 類似，但基底類別不同，並位於 `GameFrameX.Hotfix/Logic/Http/` 目錄下，例如 `GetOnlinePlayerHttpHandler`。HTTP URL → 處理器的映射由 `HotfixModule` 中的 `_httpHandlerMap` 維護，並在 dll 載入時自動註冊。

### Agent 包裝

`HotfixModule` 預設啟用 `_useAgentWrapper = true`，會將使用者撰寫的 Component 包裝為 `*Agent` 型別，以便在熱重載期間攔截呼叫並統一切換實作。大多數業務程式碼無需關心此開關 — 保持預設即可。

### 僅替換指定版本的 dll

若不想立即覆蓋當前生效的 dll，可先將新版本放置於帶版本號的子目錄中，再呼叫 `HotfixManager.LoadHotfix(..., dllVersion: "v1.2.3", ...)`。框架會優先載入 `{dllVersion}/GameFrameX.Hotfix.dll`，驗證通過後再切換至主版本目錄。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|---------|-------|-----|
| 啟動後日誌顯示「找不到處理器（handler not found）」 | 缺少 `[MessageMapping(typeof(ReqXxx))]` 或請求型別錯誤 | 在 Handler 類別上加上對應的屬性，並確認 `ReqXxx` 與請求主體型別完全相符 |
| 熱重載後，處理中的請求中途拋出 `MultiAgentImpException` | 舊、新 dll 中同時存在同名 Component；偵測到多個實作 | 檢查是否在其他地方 `new` 出 Component — 業務程式碼只能透過 `ComponentAgent` 存取 Component |
| 替換 dll 後行為未改變 | 替換到錯誤的目錄，或檔名不是 `GameFrameX.Hotfix.dll` | 確認目錄與檔名符合 `HotfixManager.LoadHotfix` 的 `dllPath` / `hotfixDllName` 參數 |
| 在 Handler 中 `new` 出跨 dll 的型別，熱重載後拋出 `FileNotFoundException` | 直接持有舊 dll 中某型別的執行個體 | 透過 `ComponentAgent` 間接存取業務物件；不要在 Handler 中快取跨 dll 的執行個體 |
| 變更了協議 OpCode 但未更新請求類別 | 框架依 OpCode 分派；舊請求被路由到錯誤的 Handler | 協議 OpCode 變更後應統一升級所有引用 — 不要在 Hotfix 層自行修改 OpCode |

## 背景說明（選讀）

`HotfixManager` 會在程序中維護當前的 `_module` 以及獨立的 `OldModuleMap`，確保舊 dll 中排隊的請求能執行完畢後才被回收。`HotfixModule.Init` 會掃描 dll 中所有標記了 `[MessageMapping]` 的 Handler，建立訊息 ID / HTTP URL / Component Agent 的映射，並透過 `_useAgentWrapper` 將使用者的 Component 包裝成可在熱重載時整體替換的 Agent — 這正是「只需重載 Hotfix dll 即可更新業務邏輯」的基礎。
