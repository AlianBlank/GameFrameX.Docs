# 如何訂閱啟動完成及失敗事件

透過 `StartupCompletedEventArgs` 與 `StartupFailedEventArgs`，可以在啟動流程完成或失敗時收到通知，並可用於場景切換、關閉載入 UI、指標回報或提示玩家重試等用途。

## 前置條件

- 專案中已整合 `GameFrameX.Startup.Runtime`，且可透過 `GameEntry` 取得事件元件 `EventComponent`。
- 需熟悉 GameFrameX 的事件訂閱模式（`EventComponent.Subscribe`）。

## 事件 ID 及欄位

| 事件 | EventId | 可讀取欄位 | 觸發時機 |
|------|---------|----------|----------|
| 啟動成功 | `typeof(StartupCompletedEventArgs).FullName` | 無 | `ProcedureGameLauncherState` 完成熱更新並 Dispose UI 之後 |
| 啟動失敗 | `typeof(StartupFailedEventArgs).FullName` | `FailedProcedureName`, `FailedUrl`, `ErrorMessage` | 在任何 Procedure 中因網路或業務失敗而中斷流程時 |

`StartupFailedEventArgs.Create(procedureName, url, errorMessage)` 由 `StartupProcedureUtility` 呼叫，其中 `procedureName` 是發生失敗的 Procedure 狀態名稱，而 `url` 在非網路失敗的情況下為空字串。

## 操作步驟

### 1. 訂閱啟動成功事件

在 `GameEntry` 初始化完成後、啟動流程開始前呼叫 `Subscribe`，將處理器註冊到 `EventComponent`：

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;
using GameFrameX.Startup.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupCompletedEventArgs.EventId,
    OnStartupCompleted);

static void OnStartupCompleted(object sender, GameEventArgs e)
{
    var args = e as StartupCompletedEventArgs;
    // 切換主場景、播放登入動畫等
}
```

`StartupCompletedEventArgs` 沒有額外欄位，因此直接呼叫 `Clear()` 即可將其歸還至參考池。

原始碼：[StartupCompletedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupCompletedEventArgs.cs#L1-L38)

### 2. 訂閱啟動失敗事件

失敗事件包含 Procedure 名稱、最後失敗的 URL 及錯誤說明，適合用於 UI 提示與回報：

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);

static void OnStartupFailed(object sender, GameEventArgs e)
{
    var args = (StartupFailedEventArgs)e;
    Debug.LogError($"启动失败 [{args.FailedProcedureName}] {args.FailedUrl} {args.ErrorMessage}");
    // 顯示重試按鈕、回報指標
}
```

原始碼：[StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L1-L62)

### 3. 取消訂閱

不再需要時呼叫 `Unsubscribe`，但必須傳入相同的委派參考，否則 `EventComponent` 會繼續持有該回呼。

```csharp
GameEntry.GetComponent<EventComponent>().Unsubscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);
```

## 常見變化

- **只想監控失敗的情況**：只訂閱 `StartupFailedEventArgs.EventId`，不訂閱成功事件。
- **以相同回呼處理成功/失敗**：對 `GameEventArgs e` 以 `is StartupCompletedEventArgs` / `is StartupFailedEventArgs` 分支判斷。
- **在熱更新層判斷業務失敗**：當 `IHotfixLauncher.StartAsync` 回傳 `Result.Success == false` 時，`ProcedureGameLauncherState` 會呼叫 `CompleteFailure` 觸發失敗事件，並將 `FailedProcedureName` 固定為 `"ProcedureGameLauncherState"`，`FailedUrl` 設為空字串。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 啟動完成後回呼未被觸發 | 訂閱時機過晚，事件已被 Fire | 在 `GameEntry` 啟動前或進入點腳本的 `Awake` 中呼叫 `Subscribe` |
| 失敗回呼中無法讀取 URL | `StartupFailedEventArgs.FailedUrl` 僅在網路相關失敗時才有值 | 以 `FailedProcedureName` + `ErrorMessage` 提供備援提示 |
| 收到回呼後再次訂閱導致重複觸發 | 未做去重，或在兩次啟動中都註冊了處理器 | 先 `Unsubscribe` 再 `Subscribe`，或在 `GameEntry` 重新啟動時統一清理 |
| 自行 `new StartupCompletedEventArgs()` 後發送 | 事件由框架內部統一 Fire，不應由外部觸發 | 不要手動 Fire，僅在 `EventComponent.Subscribe` 端消費 |

## 背景

這兩個事件都在 `StartupProcedureUtility.CompleteSuccess` / `CompleteFailure` 中觸發：

- `CompleteFailure` 會呼叫 `EventComponent.Fire(procedureOwner, StartupFailedEventArgs.Create(...))`。
- `CompleteSuccess` 會呼叫 `EventComponent.Fire(procedureOwner, StartupCompletedEventArgs.Create())`。

事件 ID 遵循 `typeof(X).FullName` 模式，與 GameFrameX 全系列產品保持一致。事件物件從參考池 `ReferencePool.Acquire` 取得，由框架內部負責 `Clear` 與回收。
