# FSM を作成して開始する方法

`FsmComponent` を使って指定された Owner を保持する有限状態マシンを作成し、状態のインスタンスを渡して `Start<TState>()` を呼び出してポーリングを開始することで、ゲーム内でエンティティの動作を駆動できます。このページでは、状態の定義から実行開始までの完全な最小パスを提供します。

## 前提条件

- `com.gameframex.unity.fsm` パッケージがインストールされていること。
- シーンに `FsmComponent` がアタッチされた GameObject が存在すること(コンポーネントには `[GameFrameXAutoComponent(-6000)]` が付いており、フレームワーク起動時に自動的に登録されます)。
- `FsmState<T>` を継承した状態クラスが少なくとも1つ定義されていること(状態の定義については「FsmState の定義方法」を参照)。

## 操作手順

1. `FsmComponent` のインスタンスを取得します。

   ```csharp
   var fsmComponent = GameEntry.GetComponent<FsmComponent>();
   ```

2. `CreateFsm<T>` を呼び出して状態マシンを作成し、Owner とすべての初期状態のインスタンスを渡します。

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
   ```

   `FsmComponent.CreateFsm<T>(T owner, params FsmState<T>[] states)` のソースコード定義は [FsmComponent.cs#L197-L208](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L197-L208) にあり、内部で `IFsmManager.CreateFsm` に転送されます。
   同じ Owner に対して `name` を指定したオーバーロードを使って複数の共存インスタンスを作成することもできます。

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm<Player>("Combat", player, new IdleState(), new AttackState());
   ```

3. `Start<TState>()` を呼び出して FSM を最初の状態に移行させます。

   ```csharp
   fsm.Start<IdleState>();
   ```

   `Start<TState>()` は対象の状態の `OnEnter` をトリガーし、次のフレームから毎フレーム `OnUpdate` を呼び出します。
   `Start` インターフェースの定義については [IFsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsm.cs) を参照してください。

4. 任意の状態の内部で `ChangeState<TState>(fsm)` を呼び出して状態を切り替えます。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

## よくあるバリエーション

| シナリオ | 呼び出し方法 |
|------|----------|
| 同じ Owner に対して複数の独立した FSM が必要な場合 | `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` を使用し、`name` で区別する |
| 実行時に新しい状態を追加する | `fsm.AddState(new JumpState())` |
| 実行時に状態を削除する(現在の状態以外) | `fsm.RemoveState<IdleState>()` |
| 現在の状態を終了し、データをクリアして再起動する | `fsm.Reset(); fsm.Start<IdleState>();` |
| `GameApp` 経由でショートカットアクセスする(`com.gameframex.unity.entry` が必要) | `IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());` |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `Log.Fatal("FSM manager is invalid.")` | `Awake` 段階で `IFsmManager` の実装が取得できていない。通常はフレームワークの初期化順序の問題 | `FsmComponent` がフレームワークのルート GameObject にアタッチされていること、GameFrameX フレームワークのコンポーネントがビジネススクリプトより先に初期化されることを確認する |
| `Start<TState>()` が「状態が存在しません」というエラーを報告する | `CreateFsm` 時にその状態が渡されていない、またはその後 `RemoveState` が呼ばれた | `CreateFsm` の `params FsmState<T>[] states` に追加する、または `Start` の前に `AddState` を呼び出す |
| FSM が駆動されない / `OnUpdate` がトリガーされない | `FsmComponent` の `FixedUpdate` は `m_FsmManager` が非 null に依存している。コンポーネントがアタッチされていないか無効化されている場合、Update は実行されない | シーンに有効な `FsmComponent` が存在することを確認する |
| `CreateFsm` が同じ Owner に対して既存のインスタンスを返す | 同じ Owner + 同じ name の場合、古い FSM が再利用される | 異なる `name` で区別するか、先に `DestroyFsm` を呼んでから作成する |

## 検証

- `IdleState.OnEnter` 内でログを出力すると、シーン実行時に即座に1回出力されます。
- `IdleState.OnUpdate` 内でログを出力すると、シーン実行時に毎フレーム出力され、`FsmComponent.FixedUpdate` がポーリングを駆動していることが確認できます。
- `fsm.IsRunning` を呼び出すと `true` になります。`fsm.CurrentState` を呼び出すと `Start` したばかりの状態タイプが返されます。
