# UI 開啟失敗或白屏怎麼辦

當你呼叫 `GameApp.UI.OpenAsync<T>()` 之後介面沒有出現、顯示為白屏、或者整個螢幕沒反應,通常是因為 FairyGUI 資源包沒有先載入、UI 路徑寫錯、或者 UI 元件沒有掛到場景根節點。本頁按症狀給出對應的排查方法。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `GameApp.UI.OpenAsync<UILogin>()` 之後沒報錯但什麼都沒出現 | 目標 UI 所在的 FairyGUI 包沒有 `AddPackageAsync` | 在開啟 UI 前呼叫 `GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.XXX))` |
| 報「找不到包」或資源載入失敗 | `FUIPackage` 列舉項寫錯 / 包名與打包資產不相符 | 核對 `FUIPackage` 列舉值與 FairyGUI 編輯器裡實際打包名 |
| UI 開啟了但是整塊白屏 | 呼叫的是非全螢幕介面、而目標 UI 是 `OpenFullScreen` 型別,層級被遮蓋 | 改用 `OpenFullScreenAsync<T>(path, group)` 並傳入對應的 `UIGroupConstants` |
| 報「找不到 UI 路徑」 | `GetUIPath(nameof(X))` 的 `nameof(X)` 類別名稱和真實類別不一致 | 類別名稱要與 FairyGUI 資源裡 `Package_XXX` 產生的 `X.cs` 一致 |
| Hotfix 裡呼叫 `GameApp.UI` 提示為空 | 還沒等 `LoadUI()` 執行完就存取 | `await` 上面的載入,或把後續邏輯放進 `OpenAsync` 的續延裡 |
| UI 能彈出但立刻又消失 | 沒有 await `CloseUIForm`,或者上層立刻又 `OpenUIForm` 把它覆蓋 | 檢查呼叫順序，確保 `CloseUIForm<T>` 在 `await OpenAsync` 之後呼叫 |

## 修復步驟

### 1. UI 完全沒出現 — 補載入 FairyGUI 包

框架要求在開啟任何一個 UI 之前，先把對應的 FairyGUI 資源包載入進來。`HotfixLauncher.LoadUI` 已經示範了標準做法：

```csharp
#if ENABLE_UI_FAIRYGUI
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommon));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommonAvatar));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UIRoom));
#endif
await GameApp.UI.OpenAsync<UILogin>();
```

`FUIPackage.XXX` 列舉值必須和 FairyGUI 編輯器裡匯出的包名一致(例如 `UIRoom`、`UICommon`)。漏掉一個包，該包裡所有 UI 都打不開。

Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L46)

### 2. 白屏或被遮蓋 — 用對開啟介面

開啟「全螢幕類 UI」(登入、角色清單、主介面)必須使用 `OpenFullScreenAsync`,並傳入 UI 群組:

```csharp
await GameApp.UI.OpenFullScreenAsync<UIPlayerList>(
    Utility.Asset.Path.GetUIPath(nameof(UILogin)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

普通 `OpenAsync<T>()` 適合彈窗、提示框之類非全螢幕元件。如果目標 UI 實際上是全螢幕佈局卻用 `OpenAsync`,會出現「看似開啟、實際被遮住或沒繪製」的白屏現象。

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 3. 關閉後再開要 await

`CloseUIForm` 必須發生在 `await OpenAsync/OpenFullScreenAsync` 之後，否則上層 UI 會先把目前介面蓋掉：

```csharp
await GameApp.UI.OpenFullScreenAsync<UIMain>(
    Utility.Asset.Path.GetUIPath(nameof(UIMain)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 4. 類別名稱與 FairyGUI 產生的程式碼保持一致

`GetUIPath(nameof(X))` 中傳入的 `X` 必須和 FairyGUI 匯出工具產生的 `Package_X.cs` 類別名稱一致。如果改了類別名稱忘了同步，會出現路徑找不到、白屏、或者開啟的是上一個舊介面。

### 5. 彈窗型 UI 關閉範例

通用確認/取消彈窗關閉時直接呼叫：

```csharp
GameApp.UI.CloseUIForm<UIDialogMessageBox>();
data.OnEnter?.Invoke();
```

Source: [UIDialogMessageBox.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UICommon/UIDialogMessageBox.cs#L22-L29)

### 6. Launcher 階段的 UI 關閉

`LauncherUIHandler` 在初始化完成時會關掉啟動介面：

```csharp
GameApp.UI.CloseUIForm<UILauncher>();
_ui = null;
```

Source: [LauncherUIHandler.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/LauncherUIHandler.cs#L66-L67)

## 驗證

- 在 `LoadUI()` 裡把所有 UI 用到的 `FUIPackage` 列舉項都註冊一遍，啟動日誌裡能看到對應包的載入記錄。
- `await OpenAsync<T>()` 回傳後，Hierarchy 裡能看到 `T` 實例掛到 FairyGUI 的 Stage 下，而不是停留在 Root 之外。
- 全螢幕 UI 切換時，在過渡期間舊介面會被新介面蓋住而不是白屏一閃而過。
- 關閉後再呼叫 `OpenAsync<T>()`,新介面能正常顯示(說明資源沒被一次性回收，或者你已在銷毀邏輯裡正確釋放)。

## 背景(可選)

`HotfixLauncher.LoadUI` 會先把 `UICommon`、`UICommonAvatar`、`UIRoom` 這些基礎包預先載入，然後再 `await OpenAsync<UILogin>`。後續 `UIPlayerList → UIMain` 的鏈式跳轉都遵循「await 開啟 → CloseUIForm 自己」的模式，這也是避免白屏/層級混亂的關鍵約定。
