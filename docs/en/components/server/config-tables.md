# How to Read and Write Design Configuration Tables (Tables)

After reading this page, you will master the unified entry point `TablesComponent` for all design configuration tables (`TbAchievementConfig`, `TbItemConfig`, `TbSoundsConfig`, `TbLocalization`) in GameFrameX, as well as the complete usage patterns for loading configuration tables, querying by primary key, iterating, conditional searching, and resolving references.

## Prerequisites

- The `GameFrameX.Config` assembly has been referenced in the project, and the corresponding design configuration table files have been generated.
- A `ConfigComponent` has been constructed to serve as the parameter for `TablesComponent.Init`.
- Prepare a loader of type `Func<string, Task<JsonElement>>` (a common implementation downloads JSON data from a local file or remote source and parses it into a `JsonElement`).

## Operation Steps

### 1. Initialize and Asynchronously Load All Configuration Tables

`TablesComponent` loads each table in parallel. Once loading is complete, it automatically calls `Refresh()`, which internally triggers `PostInit()` and `ResolveRef()` (used for cross-table reference resolution).

```csharp
using GameFrameX.Config;
using System.Text.Json;
using System.Threading.Tasks;

// Implemented by the caller, e.g., returns JSON content based on the resource name
async Task<JsonElement> Loader(string name)
{
    var bytes = await File.ReadAllBytesAsync($"Configs/{name}.json");
    return JsonDocument.Parse(bytes).RootElement.Clone();
}

var configComponent = new ConfigComponent();
var tables = new TablesComponent();
tables.Init(configComponent);
await tables.LoadAsync(Loader);
```

After loading is complete, each table can be accessed via `tables.TbAchievementConfig`, `tables.TbItemConfig`, `tables.TbSoundsConfig`, and `tables.TbLocalization`.

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L56)

### 2. Read a Single Record by Primary Key

All tables are based on `BaseDataTable<T>`, which supports both integer primary keys and string primary keys as indexing methods. The default return value when a read fails is `null`.

```csharp
// Read by integer primary key
var item = tables.TbItemConfig[1001];
if (item != null)
{
    Console.WriteLine(item.Name);
}

// Read by long integer primary key (used when the primary key is defined as long)
var ach = tables.TbAchievementConfig[100001L];

// Read by string primary key (commonly used for localization tables)
var loc = tables.TbLocalization["ui.btn.confirm"];
```

Internally, `this[id]` is essentially `TryGet(id, out var v) ? v : null`, and it does not throw an exception when the key is not found.

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L110-L180)

### 3. Use TryGet for Safe Retrieval and Distinguishing "Misses"

If you want to avoid getting `null` and being unable to distinguish between a missing configuration and business logic, you can use `TryGet` to get a `bool` return value:

```csharp
if (tables.TbSoundsConfig.TryGet(2005, out var sound))
{
    // sound is valid data
}
else
{
    // Configuration is missing, prompt the designer to fill in the table
}
```

There is also a `TryGet(string id, out T value)` overload for string keys. The signature can be found in the `IDataTable<T>` interface.

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L138-L141)

### 4. Iteration, Statistics, and Conditional Queries

`BaseDataTable<T>` provides LINQ-style common operations, implemented internally based on `DataList`:

| Operation | Method Signature | Purpose |
|------|---------|------|
| Get count | `int Count { get; }` | Caches the result; repeated calls do not recalculate |
| Get first | `T FirstOrDefault { get; }` | Returns the first entry after sorting |
| Get last | `T LastOrDefault { get; }` | Returns the last entry after sorting |
| All arrays | `T[] All { get; }` / `T[] ToArray()` / `List<T> ToList()` | Obtain a copy |
| Find one by condition | `T Find(Func<T, bool> func)` | Returns `null` if not found |
| Find multiple by condition | `T[] FindListArray(Func<T, bool> func)` / `List<T> FindList(...)` | Get an array or list |
| Iterate and execute | `void ForEach(Action<T> func)` | Process while iterating |
| Project max/min | `Tk Max<Tk>(Func<T, Tk>)` / `Tk Min<Tk>(...)` | Get the extreme value of a field |

Below is a typical example of "find items by type":

```csharp
// Find all items where Type == 2 (assuming this represents consumables)
var consumables = tables.TbItemConfig.FindListArray(x => x.Type == 2);
Console.WriteLine($"Consumable count: {consumables.Length}");

// Accumulate the maximum Id across all reward configurations
var maxRewardId = tables.TbAchievementConfig.Max(x => x.Id);
```

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L189-L329)

### 5. Refresh Tables (Hot Reload)

When the design tables need to be reloaded, simply call `LoadAsync` again:

```csharp
await tables.LoadAsync(Loader); // Reloads each table in parallel and triggers Refresh()
```

`Refresh()` will sequentially execute `PostInit()` and `ResolveRef()` to re-establish cross-table references.

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L73)

## Common Variants

### Reading Localized Multi-language Data

`TbLocalization` comes from the `GameFrameX.Config.Local` namespace and is indexed by string keys. Its usage is completely consistent with other tables:

```csharp
var key = "ui.title.home";
if (tables.TbLocalization.TryGet(key, out var loc))
{
    Console.WriteLine(loc.Content);
}
```

### Reinitializing the Loader

`Init` will first call `configComponent.RemoveAllConfigs()` to clear old registrations. So if you want to switch the entire data source, simply call `Init` again followed by `LoadAsync`:

```csharp
tables.Init(newConfigComponent);
await tables.LoadAsync(newLoader);
```

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

## Common Errors

- **Reading before `LoadAsync` completes**: Properties like `TbAchievementConfig` hold default references before `LoadAsync` finishes. Reading from default values will yield `null` or empty collections. Always `await tables.LoadAsync(Loader);`.
- **Confusing integer and long integer primary keys**: When the primary key is defined as `long`, passing an `int` overload will trigger implicit conversion but may overflow; when the primary key is defined as `int`, do not use the `long` overload either, as the semantics are inconsistent.
- **Cross-table references not refreshed**: `PostInit()` / `ResolveRef()` are triggered by `Refresh()`. In custom scenarios where `LoadAsync` is bypassed, reference fields may be `null`.
- **Misspelled string keys when using indexer access**: `this[string id]` silently returns `null` when the key is not found. It is safer to check with `TryGet` first.
- **Directly modifying `LongDataMaps` / `StringDataMaps` exposed by `BaseDataTable`**: They are `protected`, but modifying them via reflection will break the idempotency of subsequent hot reloads. Use the `LoadAsync` reloading path instead.

## Background (Optional)

`TablesComponent` is automatically produced by the configuration table generator (with an `<auto-generated>` header). It registers each `Tb*` table with `ConfigComponent` and completes reference resolution using `Refresh()` once loading is finished. `BaseDataTable<T>` abstracts common capabilities such as lookup, iteration, conditional queries, and aggregation into a base class. Each specific table is only responsible for its own JSON parsing and primary key mapping.

For the overall assembly of `ConfigComponent`, refer to the relevant source code under the `GameFrameX.Config` namespace. The field definitions for each `Tb*` table are automatically generated by the design configuration table generator based on Excel/JSON data.
