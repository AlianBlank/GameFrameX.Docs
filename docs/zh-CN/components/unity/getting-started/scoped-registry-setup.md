# 如何配置 Scoped Registry 并按需引入组件

通过在 `Packages/manifest.json` 中声明 `GameFrameX` 的 scoped registry(作用域注册源),你就可以让 Unity Package Manager 解析所有以 `com.gameframex` 开头的包,然后按项目需要挑选要引入的组件。

## 前置条件

- Unity 2019.4 或更高版本(已内置 Package Manager 对 scoped registry 的支持)。
- 项目根目录下存在 `Packages/manifest.json`(Unity 创建工程时自动生成)。

## 操作步骤

1. 打开项目根目录下的 `Packages/manifest.json`,在文件末尾的 `"scopedRegistries"` 数组中加入 GameFrameX 注册源(若数组已存在,直接追加一项即可):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L72)

2. 在同一文件的 `"dependencies"` 中,先加入核心运行时包 `com.gameframex.unity`(其余组件都依赖它):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

3. 按需追加其他组件的依赖项,例如资源管理、UI、网络、流程管理等。完整的 `dependencies` 写法如下(节选自本仓库 `Packages/manifest.json`):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0",
    "com.gameframex.unity.asset": "3.1.0",
    "com.gameframex.unity.config": "1.2.0",
    "com.gameframex.unity.coroutine": "1.1.0",
    "com.gameframex.unity.entity": "2.4.5",
    "com.gameframex.unity.entry": "1.3.0",
    "com.gameframex.unity.event": "1.3.0",
    "com.gameframex.unity.fsm": "1.2.0",
    "com.gameframex.unity.network": "2.6.10",
    "com.gameframex.unity.procedure": "1.4.0",
    "com.gameframex.unity.sound": "1.3.0",
    "com.gameframex.unity.ui": "2.11.0",
    "com.gameframex.unity.ui.fairygui": "3.4.2"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

4. 保存文件后回到 Unity 编辑器,Package Manager 会自动拉取新增的注册源与依赖;等待列表刷新完成,左侧即可看到 `GameFrameX - Scoped Registry` 分类下的所有可用包。

5. 版本号以 [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) 页面或 [GameFrameX UPM Registry](https://gameframex.upm.alianblank.uk) 为准;把 `"1.11.0"`、`"2.0.0"` 这类占位版本替换为实际目标版本即可。

## 常见变体

- **通过 Unity 编辑器添加**:在 `Edit ▸ Project Settings ▸ Package Manager ▸ Scoped Registries` 页面点击 `+`,填入 `Name=GameFrameX`、`URL=https://gameframex.upm.alianblank.uk`、`Scopes=com.gameframex`。保存后效果与直接编辑 `manifest.json` 一致。
- **同时使用多个注册源**:`scopedRegistries` 是数组,可在其中并列多个对象。本仓库就同时声明了 GameFrameX 和 `package.openupm.com`(用于 `io.sentry` 作用域):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    },
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["io.sentry"]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L80)

- **通过 Git URL 直接安装第三方组件**:对于未发布到 UPM 的包(例如 HybridCLR),可在 `dependencies` 中直接填写 Git 地址,绕过 scoped registry:

```json
{
  "dependencies": {
    "com.code-philosophy.hybridclr": "https://gitee.com/focus-creative-games/hybridclr_unity.git"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L3-L3)

- **只引入最小集合**:删掉不需要的依赖即可,GameFrameX 各组件按模块化拆分,无强制捆绑关系;只保留 `com.gameframex.unity` 与 `com.gameframex.unity.entry` 也能正常启动。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| Package Manager 报 `Unable to find package com.gameframex.unity` | `scopedRegistries` 没有声明,或 `scopes` 写成 `com.gameframex.unity` | 在 `scopedRegistries` 中加入 `scopes: ["com.gameframex"]` |
| 包能下载但 `assembly definition` 找不到命名空间 | 只引入了 `com.gameframex.unity` 没引 `com.gameframex.unity.entry`,或漏装子模块 | 补齐缺失的 `com.gameframex.unity.*` 依赖,确认 `com.gameframex.unity.entry` 已加入 |
| 编辑器一直卡在 "Resolving packages" | 多个注册源的 `scopes` 互相重叠,触发重复解析 | 让每个 scoped registry 的 `scopes` 互不重叠,例如 GameFrameX 用 `com.gameframex`、OpenUPM 用 `io.sentry` |
| 升级到新版本后 `dll` 缺失 | `dependencies` 里仍固定在旧版本,且新版本调整了包结构 | 在 [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) 查阅迁移说明后,统一更新版本号 |

## 背景(可选)

Scoped registry 是 Unity Package Manager 自 2019.3 起的官方机制:它通过 URL + 命名空间作用域(`scopes`)把私有/公共 npm 风格的 UPM 注册源接入工程,而不影响官方包和已有依赖。本仓库把 `com.gameframex.*` 全部托管在自建的 UPM registry `https://gameframex.upm.alianblank.uk`,因此只要作用域匹配,Package Manager 就能按版本解析到对应 tarball。
