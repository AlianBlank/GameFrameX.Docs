# 커스텀 객체 스토리지 제공자를 구현하는 방법

`IObjectStorageManager`와 `IObjectStorageUploadManager` 두 인터페이스를 구현하고 `ObjectStorageUploadFactory`에 연결하면, GameFrameX 객체 스토리지 프레임워크에 임의의 새로운 백엔드(예: 자체 구축 MinIO, Huawei OBS, Qiniu, Upyun, 내부 파일 서버 등)를 추가할 수 있어, 업로드 프로세스가 내장 제공자처럼 팩토리에 의해 통합 스케줄링됩니다.

## 사전 조건

- Unity 프로젝트에 `com.gameframex.unity.objectstorage` 패키지가 설치되어 있어야 합니다.
- 연동할 백엔드는 다음 네 가지 기본 파라미터(accessKey / secretKey / bucketName / endpoint)를 갖추고 있어야 하며, 표준 객체 스토리지 프로토콜(분할/업로드/진행률 콜백)에 응답할 수 있어야 합니다.
- 커스텀 제공자 구현을 배치할 Editor 어셈블리를 준비합니다(임의의 `Editor/` 디렉터리의 `.asmdef`에 위치), 런타임을 오염시키지 않도록 합니다.

## 작업 단계

1. **제공자 구현 클래스 생성**, 동시에 `IObjectStorageManager`와 `IObjectStorageUploadManager` 두 인터페이스를 구현합니다. `IObjectStorageManager.Init`은 인증 정보와 버킷 정보를 수신하는 데 사용되며, `IObjectStorageUploadManager`는 실제 업로드, 분할 및 진행률 콜백을 담당합니다.

   ```csharp
   using GameFrameX.ObjectStorage.Editor;

   namespace GameFrameX.ObjectStorage.Editor
   {
       public sealed class MyCustomObjectStorageManager
           : IObjectStorageManager, IObjectStorageUploadManager
       {
           public void Init(string accessKey, string secretKey,
                            string bucketName, string endpoint = null)
           {
               // 내부 필드에 저장하여 업로드 메서드에서 사용
           }

           // IObjectStorageUploadManager의 업로드 메서드 구현 ...
       }
   }
   ```

   `IObjectStorageManager` 인터페이스 정의는 [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13)를 참조하세요. `Init` 메서드 시그니처는 다음과 같습니다:

   ```csharp
   void Init(string accessKey, string secretKey, string bucketName, string endpoint = null);
   ```
   출처: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L12)

2. **업로드 및 진행률 콜백 로직 구현**. `BaseObjectStorageUploadManager`의 책임 분할을 참조하세요: 베이스 클래스는 일반적인 분할, 재시도, 진행률 집계를 담당하며, 서브클래스는 "인증 헤더 구성"과 "분할 PUT/POST"만 자체 백엔드 프로토콜로 교체하면 됩니다. 베이스 클래스 진입점은 [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)입니다.

3. **팩토리에 등록**. [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs)를 열고, 팩토리의 생성/선택 분기에 자신의 제공자 타입을 추가하여, 팩토리가 설정에 따라 구현 인스턴스를 반환할 수 있도록 합니다.

4. **호출자 측에서 팩토리를 통해 가져오기**. 업로드 측은 수정할 필요가 없으며, `ObjectStorageUploadFactory`를 통해 `IObjectStorageUploadManager`를 가져오면 됩니다:

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create(providerName);
   ((IObjectStorageManager)uploader).Init(accessKey, secretKey, bucketName, endpoint);
   uploader.Upload(localPath, remoteKey, onProgress, onComplete);
   ```

## 일반적인 변형

- **동일 프로토콜, 다른 벤더**: 예를 들어 AWS S3, Alibaba OSS, Tencent COS는 모두 S3 프로토콜과 호환되므로, 하나의 구현 클래스로 여러 `endpoint`를 지원할 수 있으며, `Init` 시 서명 영역을 구분합니다.
- **endpoint가 없는 내부 네트워크 스토리지**: `endpoint`를 비워두고, 구현 내부에서 `bucketName`을 기반으로 내부 네트워크 주소를 조합합니다.
- **다중 인증 정보轮询(Round-Robin)**: `Init`에서 인증 정보 목록을 전달할 수 있도록 허용하고, 업로드 시 분할 전에 자동으로 token을 갱신합니다.

## 일반적인 오류

| 오류 | 원인 | 수정 |
|------|------|------|
| 팩토리가 내장 제공자를 반환함 | 자신의 타입을 `ObjectStorageUploadFactory`에 등록하지 않음 | 팩토리 선택 분기에 새 provider 이름 추가 |
| `Init` 후 업로드 시 401/403 오류 발생 | accessKey/secretKey와 endpoint 영역이 일치하지 않음 | `Init`에서 영역을 검증하고 실제 요청 주소 출력 |
| 진행률이 항상 0에 멈춰 있음 | 구현 클래스가 분할 콜백을 `IObjectStorageUploadManager`의 진행률 이벤트로 변환하지 않음 | `BaseObjectStorageUploadManager`의 진행률 집계 지점 참조 |
| Unity 런타임에서 타입을 찾을 수 없음 | 구현 클래스가 Editor 어셈블리가 아닌 런타임 어셈블리에 배치됨 | 코드를 임의의 `Editor/` 디렉터리에 배치하고, `.asmdef`에 `Editor` 플랫폼이 포함되어 있는지 확인 |

## 배경(선택 사항)

프레임워크는 "인증 정보 관리"와 "업로드 실행"을 두 개의 인터페이스로 분리합니다: `IObjectStorageManager`는 인증 정보 초기화만 신경 쓰며, `IObjectStorageUploadManager`는 실제 네트워크 분할과 진행률을 담당합니다. 두 인터페이스는 일반적으로 동일한 클래스에서 구현되며, 팩토리는 provider 이름에 따라 인스턴스를 선택합니다. 이는 호출 진입점을 통일할 뿐만 아니라 백엔드 교체를 용이하게 합니다.
