# 儲存路徑設定與路徑分隔符號問題

當呼叫 `SetSavePath` 後，物件在儲存桶中的儲存路徑不符合預期(多出或缺少分隔符號、出現平台錯誤的斜線)時，通常源自於傳入路徑的格式與 `Path.DirectorySeparatorChar` 處理邏輯不一致。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 儲存路徑末尾被多切掉一個字元(如 `mybucket/folder` 變成 `mybucket/folde`) | 傳入路徑以反斜線 `\` 結尾，而目前平台分隔符號是正斜線 `/`(常見於 Windows 路徑寫入 Linux/Mac 目標) | 在呼叫前將 `\` 取代為平台分隔符號，或使用 `Path.Combine`/`Path.DirectorySeparatorChar` 組裝 |
| 儲存路徑末尾仍帶分隔符號(如 `mybucket/folder/`),後續串接產生 `mybucket/folder//file` | 呼叫端傳入的是不帶分隔符號結尾的字串，但實際上一次呼叫前已被手動截斷過；或傳入時無分隔符號但串接到了既有的帶分隔符號路徑上 | 改為每次呼叫前重新傳入完整路徑，避免疊加截斷 |
| 路徑中的 `/` 與 `\` 混用，遠端物件路徑出現 `mybucket/folder\file` | 直接串接了 Windows 風格路徑或字串中硬編碼的 `/` | 統一使用 `Path.DirectorySeparatorChar`,不要在遠端路徑中混用兩種斜線 |

## 修復步驟

### 1. 讓 `SetSavePath` 只處理一次

`SetSavePath` 的邏輯是：僅當傳入字串以 `Path.DirectorySeparatorChar` 結尾時，才會移除最後一個字元。

```csharp
public void SetSavePath(string savePath)
{
    if (savePath.EndsWith(Path.DirectorySeparatorChar.ToString()))
    {
        savePath = savePath.Substring(0, savePath.Length - 1);
    }

    BucketSavePath = savePath;
}
```

Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

因此，如果傳入路徑的結尾字元不是目前平台的 `Path.DirectorySeparatorChar`(例如在 Windows 下傳入以 `\` 結尾的路徑，而執行階段實際目標平台是 macOS/Linux),末尾分隔符號不會被移除，後續串接就會得到帶有多餘分隔符號的遠端路徑。

### 2. 使用平台相關的分隔符號

將硬編碼的 `/` 或 `\` 取代為 `Path.DirectorySeparatorChar`,或在 Windows 上傳入路徑時統一以 `\` 結尾。例如：

```csharp
string remote = $"mybucket{Path.DirectorySeparatorChar}folder";
manager.SetSavePath(remote);
```

### 3. 避免重複呼叫

每次呼叫 `SetSavePath` 都會根據傳入值整體重新寫入 `BucketSavePath`,所以不要先呼叫一次再手動串接；直接將最終路徑一次傳入。

```csharp
manager.SetSavePath("mybucket/folder");
```

## 驗證

1. 在上傳完成後，登入物件儲存主控台或呼叫 List 介面，確認物件 Key 與預期路徑一致，沒有多餘的 `/` 或 `\`。
2. 用一個已知檔案做單一檔案上傳(`UploadFile`),比較遠端 Key 是否等於 `BucketSavePath` + 本機相對路徑。
3. 在切換平台(Editor 平台切換到 macOS/Linux 再次執行)後重新設定路徑，確認分隔符號處理仍正確。
