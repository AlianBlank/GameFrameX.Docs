# JSON 요청 본문 전송 및 응답 파싱

`HttpClientJsonExtension`의 `PostJsonAsync / PutJsonAsync / PatchJsonAsync / SendJsonAsync` 등의 확장 메서드를 사용하면 한 단계로 JSON 요청 본문을 전송하고 응답을 대상 타입으로 역직렬화할 수 있습니다. 상태 코드를 직접 처리하거나 원시 응답 본문을 읽으려면 `*ResponseAsync` 계열 메서드를 사용한 다음 `HttpClientResponse.As<T>()`로 역직렬화하세요.

## 사전 요구 사항

- NuGet 패키지 `GameFrameX.Foundation.Http.Extension`을 참조합니다(`GameFrameX.Foundation.Http.Normalization`은 통합 JSON 응답 래퍼에 사용).
- `HttpClient` 인스턴스를 생성하거나 주입합니다(수명 주기 관리를 위해 `IHttpClientFactory` 사용 권장).
- .NET 6+(`HttpClientJsonExtension`은 `System.Net.Http.Json.JsonContent`에 의존).

## 작업 단계

### 1. 직접 강타입 응답 가져오기(가장 일반적)

`PostJsonAsync<TRequest, TResponse>`는 요청 객체를 JSON으로 직렬화하여 대상 주소에 POST하고, 성공 응답(2xx)을 `TResponse`로 역직렬화합니다. 성공하지 않은 상태에는 `HttpClientRequestException`이 발생하며, 내부에 상태 코드, 요청 URI 및 응답 본문이 포함됩니다.

```csharp
using System.Net.Http;
using System.Threading.Tasks;
using GameFrameX.Foundation.Http.Extension;

var httpClient = new HttpClient { BaseAddress = new System.Uri("https://api.example.com") };

var request = new CreateOrderRequest
{
    Sku = "SKU-001",
    Quantity = 2
};

CreateOrderResponse? response = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request);

System.Console.WriteLine(response?.OrderId);
```

```csharp
public sealed class CreateOrderRequest
{
    public string Sku { get; set; }
    public int Quantity { get; set; }
}

public sealed class CreateOrderResponse
{
    public string OrderId { get; set; }
    public string Status { get; set; }
}
```

### 2. JSON 직렬화, Header, 시간 초과 및 재시도 사용자 지정

`HttpClientRequestOptions`를 통해 `JsonSerializerOptions`, 요청 헤더, 시간 초과 및 재시도 정책을 주입합니다. 확장 메서드는 요청/응답/재시도 시 콜백을 자동으로 트리거하여 로깅이나 텔레메트리 수집에 활용할 수 있습니다.

```csharp
using System.Text.Json;
using GameFrameX.Foundation.Http.Extension;

var options = new HttpClientRequestOptions
{
    Timeout = System.TimeSpan.FromSeconds(10),
    JsonSerializerOptions = new JsonSerializerOptions
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase
    }
};
options.Headers["Authorization"] = "Bearer xxx";
options.Retry.MaxRetries = 3;
options.OnResponse = e =>
    System.Console.WriteLine($"[{e.Attempt}] {e.Method} {e.RequestUri} -> {(int)e.StatusCode}");

var result = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    options);
```

`HttpClientRetryOptions`는 기본적으로 `RequestTimeout / TooManyRequests / InternalServerError / BadGateway / ServiceUnavailable / GatewayTimeout`에서 재시도를 트리거하며, 기본 백오프는 100ms × `BackoffFactor=2`로 지수 증가합니다. POST/PATCH는 기본적으로 재시도하지 않으며, 필요하면 `AllowNonIdempotentRetry = true`로 설정합니다.

### 3. 원시 응답 가져오기(상태 코드 + Body + Header)

상태 코드에 따라 분기하거나 오류 본문을 읽은 후 역직렬화 방식을 결정해야 할 때는 `*ResponseAsync` 계열을 사용합니다. `HttpClientResponse.As<T>()`는 요청과 동일한 `JsonSerializerOptions`를 사용하여 Body를 파싱합니다.

```csharp
using GameFrameX.Foundation.Http.Extension;

var resp = await httpClient.PostResponseAsync<CreateOrderRequest>(
    HttpMethod.Post,
    "/orders",
    request);

System.Console.WriteLine($"status={resp.StatusCode} attempt={resp.Attempt}");

if (!resp.IsSuccessStatusCode)
{
    // 실패 시에도 Body를 가져와 통합 오류 처리에 활용
    System.Console.WriteLine($"error body: {resp.Body}");
    return;
}

CreateOrderResponse? ok = resp.As<CreateOrderResponse>();
System.Console.WriteLine(ok?.OrderId);

// 성공을 명시적으로 확인하고, 실패 시 HttpClientRequestException 발생
resp.EnsureSuccessStatusCode();
```

### 4. 임의 메서드 + JSON 요청 본문 전송

`SendJsonAsync<TRequest, TResponse>(HttpMethod method, …)`는 하위 수준 진입점이며, 다른 POST/PUT/PATCH 오버로드는 모두 이 메서드에 위임합니다. 사용자 지정 메서드나 타사 WebHook에 사용할 수 있습니다.

```csharp
var result = await httpClient.SendJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    HttpMethod.Post,
    "https://api.example.com/orders",
    request);
```

### 5. 요청 본문이 없는 JSON 호출

GET/DELETE/OPTIONS 등 Body가 없는 상황에서는 `GetJsonAsync<TResponse>`, `DeleteJsonAsync<TResponse>` 등의 단일 타입 매개변수 오버로드를 사용하면 됩니다.

```csharp
OrderList? list = await httpClient.GetJsonAsync<OrderList>("/orders?status=open");
```

## 일반적인 변형

### 통합 응답 래퍼 `IHttpJsonResult`

많은 백엔드는 `{ code, message, data }` 스타일의 반환 값을 사용합니다. `GameFrameX.Foundation.Http.Normalization`의 `IHttpJsonResult<T>` / `HttpJsonResultHelper`를 사용하면 확장이 `code` 필드를 자동으로 검증하고 `data`를 추출하도록 할 수 있습니다.

```csharp
using GameFrameX.Foundation.Http.Normalization;

var resp = await httpClient.PostJsonAsync<CreateOrderRequest, HttpJsonResult<CreateOrderResponse>>(
    "/orders",
    request);

HttpJsonResult<CreateOrderResponse> ok = HttpJsonResultHelper.EnsureSuccess(resp);
CreateOrderResponse data = ok.Data;
```

### 취소 토큰

모든 확장 메서드는 `CancellationToken`을 지원하므로 ASP.NET Core의 `HttpContext.RequestAborted`에 직접 연결할 수 있습니다.

```csharp
var resp = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    cancellationToken: HttpContext.RequestAborted);
```

## 일반적인 오류

- **`url`에 null 또는 빈 문자열 전달**:`SendJsonAsync` 내부의 `ArgumentException.ThrowIfNullOrWhiteSpace(url, nameof(url))`가 즉시 `ArgumentException`을 발생시킵니다.
- **역직렬화 실패**:`SendJsonAsync`는 2xx가 아닌 응답에서 `HttpClientRequestException`을 발생시킵니다. 응답이 200이지만 Body가 올바른 JSON이 아니면 `As<T>`가 `System.Text.Json.JsonException`을 발생시킵니다.
- **POST/PATCH는 자동으로 재시도하지 않음**:기본값은 `AllowNonIdempotentRetry=false`입니다. 쓰기 인터페이스를 재시도하려면 이 옵션을 명시적으로 활성화하거나 상대 서버가 멱등인지 확인해야 합니다.
- **`HttpClientRequestOptions` 재사용 시 `JsonSerializerOptions`가 덮어써짐**:이 속성은 `init`가 아니라 `set`이므로, 매 전송 전에 원하는 인스턴스를 전달했는지 확인해야 합니다.
- **응답 본문이 잘려 예외 메시지에 표시됨**:`HttpClientJsonExtension` 내부의 `ResponseSummaryLimit = 1024`로 인해 발생합니다. 전체 원문은 항상 `HttpClientRequestException.ResponseBody`에 있으며, `*ResponseAsync`로 `HttpClientResponse.Body`를 가져올 수 있습니다.

## 배경(선택 사항)

`HttpClientJsonExtension`은 내부적으로 `JsonContent.Create(request, options: options.JsonSerializerOptions)`를 사용하여 요청 본문을 구성합니다. 모든 메서드는 동일한 `ExecuteCoreAsync` 재시도/시간 초과 경로를 통과한 후 `Selector`에서 두 가지 결과로 분기합니다. 강타입 메서드는 상태 코드 예외를 발생시키고, `*ResponseAsync`는 `RawResponse`를 전달합니다. 따라서 하나의 동일한 코드 세트로 「객체를 직접 가져오기」와 「먼저 상태 코드 확인하기」 두 가지 사용 방식을 모두 지원합니다.
