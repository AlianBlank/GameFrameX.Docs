# 如何使用 HMAC-SHA256/HMAC-SHA512

调用 `HmacSha256Helper` 或 `HmacSha512Helper` 的静态方法即可在几行代码内得到带密钥的消息认证码（Base64 字符串），并使用 `Verify` 系列方法以固定时间比较安全地校验签名。两者提供字符串、字节数组与流（同步/异步）三组重载。

## 前置条件

- 项目目标框架需支持 `System.Security.Cryptography` 中的 `HMACSHA256` / `HMACSHA512`（.NET 6+ 推荐使用 `HMACSHA256.HashData`）。
- 引入命名空间 `GameFrameX.Foundation.Hash`。
- 准备一个 UTF-8 编码的密钥字符串（建议长度 ≥ 32 字节以匹配 SHA-256 块大小）。

## 操作步骤

### 1. 对字符串计算 HMAC-SHA256

```csharp
using GameFrameX.Foundation.Hash;

string message = "hello world";
string key = "my-secret-key";
string signature = HmacSha256Helper.Hash(message, key);
// signature 是 Base64 字符串，长度固定为 44 个字符（32 字节）
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L60-L66)

### 2. 对字节数组计算 HMAC-SHA512

```csharp
using System.Text;
using GameFrameX.Foundation.Hash;

byte[] message = Encoding.UTF8.GetBytes("payload");
byte[] key = Encoding.UTF8.GetBytes("another-secret-key");
string signature = HmacSha512Helper.Hash(message, key);
// signature 是 Base64 字符串，长度固定为 88 个字符（64 字节）
```

Source: [HmacSha512Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha512Helper.cs#L24-L29)

### 3. 对流进行异步 HMAC-SHA256

```csharp
using GameFrameX.Foundation.Hash;

using FileStream fs = File.OpenRead("data.bin");
byte[] key = Encoding.UTF8.GetBytes("my-secret-key");
string signature = await HmacSha256Helper.HashAsync(fs, key, cancellationToken);
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L94-L103)

### 4. 使用固定时间比较校验签名

为防止时序攻击，验证必须使用 `Verify`，而不是直接 `==` 比较字符串。

```csharp
using GameFrameX.Foundation.Hash;

bool ok = HmacSha256Helper.Verify("hello world", "my-secret-key", signature);
```

Source: [HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L119-L125)

## 常见变体

| 场景 | 推荐方法 |
|------|---------|
| 短消息（JSON、URL 参数） | `Hash(string, string)` |
| 已知字节缓冲（如协议包） | `Hash(byte[], byte[])` |
| 大文件或网络流 | `Hash(Stream, byte[])` 同步；`HashAsync` 在异步上下文 |
| 接口签名校验 | 对应 `Verify(...)` 系列，避免时序攻击 |
| 需要更高安全性 | 选用 `HmacSha512Helper`，输出 64 字节 |

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `ArgumentNullException: message` | 传入 `null` 字符串 | 提前判空或使用空串占位 |
| 客户端与服务端签名不一致 | 编码不一致（一方使用 GBK/ASCII） | 全链路统一使用 UTF-8 |
| `Verify` 永远返回 `false` | 用了 `==` 直接比较 Base64 字符串长度差异 | 使用 `Verify(...)` 走固定时间比较 |
| 性能瓶颈 | 大文件重复实例化 `HMACSHA256` | 复用密钥，仅创建一次实例 |

## 背景（可选）

- 输出始终是 Base64，便于在 HTTP Header、URL 或 JSON 中传输；若需十六进制，可自行 `Convert.FromBase64String` 后 `BitConverter`。
- `Verify` 内部使用 `HashHelper.FixedTimeEqualsBase64`，与直接字符串相等性比较不同，可降低侧信道风险。
- `HashData` 是 .NET 6+ 的单次静态 API；流版本仍使用 `HMACSHA256/512` 实例以支持 `ComputeHash(Stream)` 与 `ComputeHashAsync`。
