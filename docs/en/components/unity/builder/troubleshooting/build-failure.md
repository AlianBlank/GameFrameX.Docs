# What to Do When the Build Fails or Command-Line Arguments Are Wrong

When the build flow is invoked from the command line, build failures are almost always caused by "missing / mistyped / invalid arguments" or "prerequisite steps not completed". This page maps each error message to its root cause and fix.

## Quick Diagnosis

| Symptom (error text / keyword) | Root Cause | Fix |
|---|---|---|
| `executeMethod is null` | The entry method name was not passed via `-ExecuteMethod` | Add `-ExecuteMethod <namespace.class.method>` to the command line |
| `build number is null` | The build number was not passed via `-BuildNumber` | Add `-BuildNumber <version>` to the command line |
| `Invalid build pipeline type: <xxx>, valid values: BuiltinBuildPipeline, ScriptableBuildPipeline, RawFileBuildPipeline` | The value of `-BuildPipeline` is not a valid enum name | Change the value to one of `BuiltinBuildPipeline`, `ScriptableBuildPipeline`, or `RawFileBuildPipeline` |
| `Invalid built-in file copy option: <xxx>, valid values: None, ClearAndCopyAll, ClearAndCopyByTags, OnlyCopyNew` | The value of `-BuildinFileCopyOption` is invalid | Change the value to one of `None`, `ClearAndCopyAll`, `ClearAndCopyByTags`, or `OnlyCopyNew`; if not provided, the default is `ClearAndCopyAll` |
| The log contains no output from this tool at all, but Unity exits | The `LogFilePath` points to a non-writable location, or the build number is empty causing path derivation to fail | Check the directory permissions of `-LogFilePath`, or explicitly provide `-BuildNumber` |
| Value-bearing arguments such as `-BuildPipeline` / `-PackageVersion` have no effect | The value was written directly against the switch: `-BuildPipelineBuiltinBuildPipeline` | There **must be a space** between the switch and the value: `-BuildPipeline BuiltinBuildPipeline` |
| `BuildAsset` runs fine but `BuildPlayer` (packaging) phase shows red errors | The prerequisite `BuildAsset` was not run, or the hotfix/AOT code directories are empty | Run `BuildAsset` first, and confirm that the `Assets/.../Hotfix/` and `AOT/` directories contain files before packaging

Source of error log text: [Editor/Builder.BuildParamsParse.cs#L175-L183](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L175-L183), [Editor/Builder.BuildAsset.cs#L40-L44](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L44), [Editor/Builder.BuildAsset.cs#L76-L80](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L76-L80).

## Fix Steps

### 1. Fill in the Three Required Arguments

The parser strictly requires `-ExecuteMethod`, `-BuildNumber`, and `-LogFilePath` (the latter is auto-derived from the first two if omitted, but it is still recommended to provide it explicitly). Command example:

```bash
Unity \
  -batchmode -nographics -quit \
  -projectPath /path/to/project \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
  -BuildNumber 1.0.0.1 \
  -LogFilePath ../Logs/BuildAsset_1.0.0.1.log \
  -ChannelName default \
  -PackageName DefaultPackage
```

If any of them is missing, an `Exception` is thrown and the process exits immediately. Source: [Editor/Builder.BuildParamsParse.cs#L175-L189](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L175-L189).

### 2. Fix the Values of `-BuildPipeline` and `-BuildinFileCopyOption`

Both arguments are validated with `Enum.TryParse`. They are case-insensitive but **must be valid enum names**, neither numbers nor typos:

- `-BuildPipeline`: valid values are `BuiltinBuildPipeline` (default), `ScriptableBuildPipeline`, `RawFileBuildPipeline`
- `-BuildinFileCopyOption`: valid values are `None`, `ClearAndCopyAll` (default), `ClearAndCopyByTags`, `OnlyCopyNew`

```bash
  -BuildPipeline BuiltinBuildPipeline \
  -BuildinFileCopyOption ClearAndCopyAll \
```

Validation logic: [Editor/Builder.BuildAsset.cs#L40-L84](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L84).

### 3. Ensure `-xxx <value>` Are Separated by a Space

The parser scans `commandLineArgs` item by item, and for each switch it uses `index + 1` to read the next element, so the switch and its value **must** be separated by a space (not `=`, not concatenated). Source: [Editor/Builder.BuildParamsParse.cs#L152-L172](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L152-L172).

Correct: `-PackageVersion 20240101120000`
Incorrect: `-PackageVersion=20240101120000`, `-PackageVersion20240101120000`

### 4. Run `BuildAsset` Before `BuildPlayer`

`BuildAsset` internally copies the hotfix and AOT assemblies, refreshes the AssetDatabase, and then calls YooAsset for packaging. If you run the packaging command directly and find hotfix code is missing, the build reports "assembly not found", or the asset bundle output is empty, it usually means the asset packaging step was skipped. Fix: split the pipeline into two steps — run `BuildAsset` first, then `BuildPlayerAndroid` / `BuildPlayerIOS`. Source: [Editor/Builder.BuildAsset.cs#L15-L27](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L15-L27), [Editor/Builder.cs#L60-L66](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L60-L66).

### 5. Make `-BundleId` / `-AppVersion` Actually Take Effect

These two arguments only override `PlayerSettings` when a non-empty string is passed in. If they are passed via the command line but `PlayerSettings` does not change, check that there are no extra spaces or line breaks on either side (the code calls `Trim`). Source: [Editor/Builder.BuildParamsParse.cs#L194-L202](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L194-L202).

## Verification

1. The first line of the command-line output no longer contains `executeMethod is null` / `build number is null`, indicating that the required arguments have been provided.
2. In Edit/Console, you can find a line `-----------Build Parameters Begin-----------` immediately followed by the `_builderOptions` JSON output, confirming all arguments were parsed correctly. Source: [Editor/Builder.BuildParamsParse.cs#L191-L193](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L191-L193).
3. After `BuildAsset` completes, the log contains `BuildAsset End`; only then will launching `BuildPlayer*` not fail due to missing assets. Source: [Editor/Builder.BuildAsset.cs#L99-L100](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L99-L100).

## Background (Optional)

The tool parses the command line via `Builder.BuildParamsParse` → writes to `BuilderOptions` → dispatches to `BuildAsset` / `BuildPlayer*`. Validation is concentrated in the parsing stage (`Exception` throws) and the enum `TryParse` at the start of `BuildAsset`, so "build failures" are almost always caught at these two layers; cases that actually require digging into YooAsset / Unity packaging itself are the minority.
