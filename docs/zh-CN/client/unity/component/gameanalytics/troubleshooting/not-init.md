# 事件没有上报："GameAnalyticsManager is not init." 警告怎么办

当你调用 `GameAnalyticsComponent` 的 `Event` / `StartTimer` / `StopTimer` 等接口时，如果对应的分析 SDK 管理器实例内部尚未完成初始化，组件会打印 `GameAnalyticsManager is not init.` 并跳过这一次上报。这条警告来自 `GameAnalyticsComponent` 的空初始化守卫，表示"Provider 已创建出 `IGameAnalyticsManager` 实例，但该实例自己的 `m_IsInit` 仍是 false"。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 每次 `Event`/`StartTimer`/`StopTimer` 都打印 `GameAnalyticsManager is not init.` | 组件 `Init()` 已运行并创建了 `IGameAnalyticsManager` 实例，但实现类内部的 `m_IsInit` 没有被置为 `true`（`Init(args)` 没写完成初始化，或该实现是"手动初始化"型而还没调 `ManualInit`） | 见下方[修复步骤 1](#1-在实现类的-init-或-manualinit-中置起-isinit) |
| 控制台出现 `Log.Error`：`Can not find component type 'XXX'.` | Inspector 中配置的 `ComponentType` 类型名无法被 `Utility.Assembly.GetType` 解析（类型不存在、命名空间/程序集不对） | 核对类型名拼写与所在程序集，该条 Provider 会被 `continue` 跳过 |
| 没有任何警告，但事件也没有上报 | `m_gameAnalyticsComponentProviders` 列表为空，或某项的 `ComponentType` 为空白字符串（此时循环直接跳过，不会创建实例）；也可能组件级 `m_IsInit` 尚为 false，所有调用静默 `return` | 在组件 Inspector 的"游戏数据分析组件列表,按序上报"中添加 Provider 并选择实现类型；确认调用发生在组件 `OnEnable` 之后 |
| 只在游戏刚启动的极早阶段上报失败、无警告 | 组件的 `Init()` 在 `OnEnable()` 中才执行，`Awake` 阶段 `m_IsInit` 为 false，调用被静默丢弃 | 把上报逻辑挪到组件启用之后 |

触发这条警告的完整守卫逻辑（以 `Event(string)` 为例，其余重载与计时接口结构相同）：

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

## 修复步骤

### 1. 在实现类的 Init 或 ManualInit 中置起 isinit

警告的判定依据是 `IGameAnalyticsManager.IsInit()`，它由基类 `BaseGameAnalyticsManager` 提供并返回受保护字段 `m_IsInit`：

```csharp
protected bool m_IsInit = false;

/// <summary>
/// 是否初始化
/// </summary>
/// <returns></returns>
public bool IsInit()
{
    return m_IsInit;
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L12-L45)

`Init(Dictionary<string, string> args)` 和 `ManualInit(Dictionary<string, string> args)` 是抽象方法，由每个分析 SDK 的实现类自行实现。检查你的实现：

- 若 SDK 无需用户同意等前置条件，应在 `Init(args)` 完成 SDK 初始化后写 `m_IsInit = true;`；
- 若 SDK 需要 `ManualInit`（隐私合规流程），`IsManualInit()` 返回 true 的实现要先调 `GameAnalyticsComponent.ManualInit(extraArgs)`，并在其中置起 `m_IsInit`。注意组件侧守卫：

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

`ManualInit` 只会转发给 `IsManualInit()` 为 true 的实现，且要求组件自身已 `Init()`。

### 2. 确认 Provider 已在 Inspector 中配置

组件在 `OnEnable()` 调用 `Init()`，遍历 `m_gameAnalyticsComponentProviders`，通过反射创建实现类实例并调用其 `Init(args)`：

```csharp
private void OnEnable()
{
    Init();
}

public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }
            // ...创建实例、组装 args 并调用 gameAnalyticsManager.Init(args)
        }
    }

    m_IsInit = true;
}
```

### 3. 排查静默丢弃（无警告但也没上报）

组件级守卫是静默的：`!m_IsInit` 时直接 `return`，不打印任何日志。若连警告都没有，依次检查：

1. 调用时机是否早于组件 `OnEnable`（`Awake` 阶段 `m_IsInit` 仍为 false）；
2. `m_gameAnalyticsComponentProviders` 是否为空列表或 `ComponentType` 为空白——这种情况既不报错也不创建实例；
3. 控制台是否有 `Can not find component type '...'` 的 `Log.Error`——该 Provider 会被 `continue` 跳过。

## 验证

1. 启动游戏，确认控制台不再出现 `Can not find component type` 的红色错误（该错误会直接导致对应 Provider 被跳过）。
2. 调用任意 `Event(...)` / `StartTimer(...)`，确认 `GameAnalyticsManager is not init.` 黄色警告消失。
3. 在对应分析平台（如 ThinkingData、数数等，取决于实现类）后台查看事件是否到达；或在实现类的 `Init` 内加临时日志确认 `m_IsInit` 已置 true。

## 背景

警告分两层守卫：`GameAnalyticsComponent.m_IsInit`（组件级，`OnEnable` 时置 true，未初始化时静默丢弃）与各 `IGameAnalyticsManager.IsInit()`（实例级，未初始化时打印本条警告）。`BaseGameAnalyticsManager` 只是持有 `m_IsInit` 字段并透出 `IsInit()` / `SetPublicProperties` 等通用能力，置位时机完全由具体 SDK 实现决定——因此该警告几乎总是指向实现类的 `Init`/`ManualInit` 没有把 `m_IsInit` 置 true，或调用发生在手动初始化流程之前。

关于组件各上报接口的完整签名，见《GameAnalyticsComponent 参考》。
