# 订阅与分发事件

通过事件池 `EventPool<T>` 可以让任意模块以"字符串 ID + 事件参数"的形式订阅和分发事件,既能在主线程排队触发(`Fire`),也支持立即同步触发(`FireNow`)。

## 前置条件

- 自定义事件参数必须继承 `BaseEventArgs`,并实现唯一的字符串 `Id`(用于区分事件类型)。
- 通过 `EventPool` 模块获取或创建一个 `EventPool<T>` 实例,本教程假设你已经能拿到 `EventPool<MyEventArgs>`。
- 调用方需保证在游戏循环中触发 `EventPool<T>.Update(elapseSeconds, realElapseSeconds)`,否则 `Fire` 队列里的事件不会分发。

## 操作步骤

1. 定义事件参数类,继承 `BaseEventArgs` 并给出唯一的 `Id`。

   ```csharp
   public class PlayerHpChangedEventArgs : BaseEventArgs
   {
       public string PlayerId { get; set; }
       public int NewHp { get; set; }

       public override string Id => "PlayerHpChanged";
   }
   ```

   Source: [BaseEventArgs.cs](/Runtime/Base/EventPool/BaseEventArgs.cs#L43-L54)

2. 订阅事件。在模块初始化时调用 `Subscribe`,把字符串事件 ID 和 `EventHandler<T>` 回调注册到事件池中。

   ```csharp
   eventPool.Subscribe("PlayerHpChanged", OnPlayerHpChanged);

   void OnPlayerHpChanged(object sender, PlayerHpChangedEventArgs e)
   {
       Debug.Log($"{e.PlayerId} HP -> {e.NewHp}");
   }
   ```

   `EventHandler<T>` 的签名来自 `EventPool<T>` 的类型参数。

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

3. 分发事件。在主线程调用 `Fire` 即可把事件加入队列,事件会在下一次 `Update` 时回调到所有订阅者,跨线程 `Fire` 也安全。

   ```csharp
   var args = ReferencePool.Acquire<PlayerHpChangedEventArgs>();
   args.PlayerId = "p_001";
   args.NewHp = 80;
   eventPool.Fire(this, args);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L304-L314)

4. 驱动事件池。每帧驱动 `Update` 才会消费 `Fire` 排队的节点;节点处理完会通过 `ReferencePool.Release` 归还。

   ```csharp
   void Update()
   {
       eventPool.Update(0f, Time.deltaTime);
   }
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L113-L121)

5. 在合适的时机取消订阅,防止对象已销毁仍被事件池持有回调。

   ```csharp
   eventPool.Unsubscribe("PlayerHpChanged", OnPlayerHpChanged);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L245-L281)

## 常见变体

- **立即同步分发**:在主线程且不需要排队时,可调用 `FireNow`,事件会在当前调用栈立刻派发到所有订阅者,但不是线程安全的。

  ```csharp
  eventPool.FireNow(this, args);
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L325-L336)

- **设置默认处理器**:通过 `SetDefaultHandler` 注册兜底回调,当某事件 ID 没有订阅者时会被调用。

  ```csharp
  eventPool.SetDefaultHandler((sender, e) => Debug.Log($"未处理事件:{e.Id}"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L290-L293)

- **按事件池模式控制订阅规则**:`EventPool<T>` 构造时传入 `EventPoolMode`,决定是否允许多个或重复订阅者。

  | 模式 | 行为 |
  |------|------|
  | `EventPoolMode.Default` (0) | 必须存在且只能有一个订阅者 |
  | `EventPoolMode.AllowNoHandler` (1) | 允许事件没有订阅者 |
  | `EventPoolMode.AllowMultiHandler` (2) | 允许同一事件 ID 注册多个订阅者 |
  | `EventPoolMode.AllowDuplicateHandler` (4) | 允许注册重复的同一个回调(需配合 `AllowMultiHandler`) |

  多个标志可按位组合,例如 `EventPoolMode.AllowMultiHandler | EventPoolMode.AllowDuplicateHandler`。

  Source: [EventPoolMode.cs](/Runtime/Base/EventPool/EventPoolMode.cs#L43-L77), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

- **查询订阅数量**:通过 `EventHandlerCount` 或 `Count(id)` 读取订阅者数量,用于调试或 UI 展示。

  ```csharp
  Debug.Log(eventPool.EventHandlerCount);
  Debug.Log(eventPool.Count("PlayerHpChanged"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L82-L91), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L164-L175)

## 常见错误

| 错误 | 现象 | 处理 |
|------|------|------|
| `handler` 为 `null` 调用 `Subscribe`/`Unsubscribe`/`Check` | 抛出 `GameFrameworkException("Event handler is invalid.")` | 注册前确保回调是实例方法或静态委托,不要传 `null` |
| `Fire` 事件后没有任何订阅者且模式未开启 `AllowNoHandler` | 抛出 "not allow multi handler." 或默认处理器兜底 | 构造函数中按需加入 `EventPoolMode.AllowNoHandler` |
| 不调用 `Update` 消费队列 | 事件看起来"消失"了 | 确保游戏循环每帧驱动 `eventPool.Update(...)` |
| 对象销毁后未 `Unsubscribe` | 事件触发时回调到已销毁对象导致空引用 | 在 `OnDestroy`/`OnDisable` 中调用 `Unsubscribe` |

## 背景(可选)

`EventPool<T>` 内部用 `ConcurrentQueue<EventNode>` 暂存 `Fire` 来的事件,在 `Update` 中取出并通过 `GameFrameworkMultiDictionary<string, EventHandler<T>>` 派发;`_cachedNodes` 用于支持"事件处理过程中安全地取消订阅"。`Fire` 是线程安全的(会在下一帧主线程派发),`FireNow` 则是立即同步派发,适合对延迟敏感但能保证调用线程安全的场景。
