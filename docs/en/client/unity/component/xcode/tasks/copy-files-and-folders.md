# Copying Files and Folders into the Xcode Project

This page explains how to copy local files or entire folders into the generated Xcode project as part of the Xcode post-build process configuration, and automatically add them to the Build list and search paths. You only need to write "source path → destination path" mappings in the `files` and `folders` fields of the Xcode configuration file (JSON), and the copy will be performed automatically during the build.

## Prerequisites

- The Unity project has been switched to the iOS platform (the implementation is all under `#if UNITY_IOS`).
- The basic integration of Xcode post-build processing is complete: `PostProcessBuildHelper` reads the merged configuration in the build callback and calls `Run`.

## Steps

1. Open your Xcode post-build process configuration file and locate the configuration node for the target (e.g., the hashtable corresponding to `unityMain` / `unityFramework`).
2. Add a `files` field under that node, with the Key being the source file path (relative to the Unity project root, i.e., `Environment.CurrentDirectory`) and the Value being the destination path (relative to the generated Xcode project directory):

```json
{
  "files": {
    "Assets/Plugins/iOS/NativeCode.mm": "Libraries/NativeCode.mm",
    "Assets/Plugins/iOS/MySDK.framework": "Frameworks/MySDK.framework"
  }
}
```

3. To copy an entire folder, add a `folders` field, likewise using "source path → destination path" mappings:

```json
{
  "folders": {
    "Assets/Plugins/iOS/NativeFolder": "Libraries/NativeFolder"
  }
}
```

4. Trigger an iOS build. After the build finishes, `Run` performs the copies in order: first `RunCopyFiles` processes `files`, then `CopyFolders` processes `folders`:

```csharp
// Copy files
RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
// Copy folders
CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L173-L176)

5. Verify in the Xcode project: the file has appeared at the corresponding destination path and has been added to the target's Build list via `AddFileToBuild`; the console will output the `copy file {src} -> {des}` log.

## Copy Behavior Details

Copying is not a simple file copy; the following behaviors come from the source implementation and are worth knowing when configuring:

| Behavior | Description |
|------|------|
| Destination directory auto-created | `CopyFolder` first deletes an existing directory/file with the same name, then recreates it with `Directory.CreateDirectory` before copying recursively |
| Overwrites existing files | Single-file copy uses `File.Copy(src, des, true)`, so files with the same name are overwritten |
| Ignores hidden and junk files | Files whose names start with `.`, as well as `.gitkeep` and `.DS_Store`, are skipped — neither copied nor added to the Build |
| Automatically added to Build | Files are added to the project via `proj.AddFile` + `proj.AddFileToBuild` |
| Search paths added automatically | Copying `.framework` / `.xcframework` automatically adds `FRAMEWORK_SEARCH_PATHS`; `.h` automatically adds `HEADER_SEARCH_PATHS`; `.a` automatically adds `LIBRARY_SEARCH_PATHS`, prefixed with `$PROJECT_DIR` |
| Bundles also added to the main target | Items in `folders` ending with `.bundle` are added to the Unity main target via `AddFileToBuild(mainTargetGuid, fileGuid)` in addition to the target itself |
| Folder treated as a single framework | When the destination path in `folders` ends with `.framework` / `.xcframework` / `.bundle` / `.a`, the entire directory is added to the build as a single library file and is not recursively expanded |

Core implementation of file copying:

```csharp
private static void CopyFile(PBXProject proj, string targetGuid, string xcodePath, string src, string des)
{
    bool needCopy = IsNeedCopy(src);
    if (needCopy)
    {
        File.Copy(src, des, true);
        proj.AddFileToBuild(targetGuid, proj.AddFile(des, des.Replace(xcodePath + "/", ""), PBXSourceTree.Absolute));
        AutoAddSearchPath(proj, xcodePath, targetGuid, des);
        Debug.Log("copy file " + src + " -> " + des);
    }
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L42-L52)

Core implementation of recursive folder copying (clears the destination first, then recreates it):

```csharp
private static void CopyFolder(string srcPath, string dstPath)
{
    if (Directory.Exists(dstPath))
    {
        Directory.Delete(dstPath, true);
    }

    if (File.Exists(dstPath))
    {
        File.Delete(dstPath);
    }

    Directory.CreateDirectory(dstPath);

    foreach (var file in Directory.GetFiles(srcPath))
    {
        if (IsNeedCopy(Path.GetFileName(file)))
        {
            File.Copy(file, Path.Combine(dstPath, Path.GetFileName(file)));
        }
    }

    foreach (var dir in Directory.GetDirectories(srcPath))
    {
        CopyFolder(dir, Path.Combine(dstPath, Path.GetFileName(dir)));
    }
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L172-L198)

## Common Variants

- **Copying SDKs / static libraries**: Put `.framework`, `.xcframework`, and `.a` into `folders`, with the destination path written directly as `Frameworks/xxx.framework`. Frameworks are added to Link Binary With Libraries and search paths are automatically supplemented (`AddFrameworkToProject(targetGuid, root, false)`); `.a` static libraries are only added to the link phase.
- **Copying resource bundles**: Directories in `folders` ending with `.bundle` are added to both the Unity main target and the UnityFramework target, suitable for resources that need to be distributed with the package.
- **Fine-tuning when you only want to place files into the project without compiling them**: After copying completes, compile flags can be set via the sibling `filesCompileFlag` configuration; this step runs after the copy (`SetFilesCompileFlag`).

## Common Errors

| Issue | Cause | How to Avoid |
|------|------|------|
| File not found in Xcode after copying | The source path was written as an absolute path or the relative level is wrong | The Key of `files`/`folders` is a path relative to the Unity project root; at runtime it becomes `Path.Combine(Environment.CurrentDirectory, key)` |
| Some files are never copied | The exclusion rules of `IsNeedCopy` were triggered | Files whose names start with `.`, as well as `.gitkeep` and `.DS_Store`, are skipped outright; rename them or move them out |
| Destination directory contents "lost" after each build | `CopyFolder` first clears the destination directory with `Directory.Delete(dstPath, true)` | Do not manually place other content into the destination directory configured in `folders` |
| Single-file copy fails with a "destination already exists" error | This does not actually happen; single-file copies use `overwrite: true` | If it still fails, check whether a folder with the same name exists in the destination directory (it would be treated as a directory) |
| Framework link reports "not found" | The automatic search path logic was not applied | Make sure the path ends with `.framework` / `.xcframework` / `.a`; `AutoAddSearchPath` only takes effect for these three suffixes |

## Background

Copying happens after the Xcode project is generated: `PostProcessBuildHelper` reads the PBXProject and the merged configuration, and `Run` processes properties, frameworks, libs, files, folders, etc. in order; `CopyFolders` additionally receives `mainTargetGuid` so that `.bundle` can be attached to the Unity main target as well. File paths are all based on `PBXSourceTree`: frameworks/static libraries use `Source`, single files use `Absolute`.
