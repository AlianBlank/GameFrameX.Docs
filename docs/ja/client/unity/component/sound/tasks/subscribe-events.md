# 再生成功 / 失敗 / 更新イベントを購読する方法

GameFrameX イベントセンターで `PlaySoundSuccessEventArgs`、`PlaySoundFailureEventArgs`、`PlaySoundUpdateEventArgs` の 3 種類のイベントを購読すると、サウンドの読み込み完了、再生失敗、または再生進捗の更新時にコールバックを受信できます。通知のトリガー、UI 連動、計測ログの送信などに使用できます。

## 前提条件

- `com.gameframex.unity.sound` パッケージがインストール済みで、Sound コンポーネントが初期化され、正常に再生できること。
- 業務コードが `GameFrameX.Event.Runtime.GameEntry.Event`(`GameFrameX` イベントセンターのエントリ)にアクセスできること。

## 操作手順

### 1. 再生成功イベントを購読する

コールバックはサウンドの読み込みが完了して再生が開始された時点でトリガーされ、読み込みにかかった時間とサウンドエージェントを取得できます。

```csharp
using GameFrameX;
using GameFrameX.Sound.Runtime;

GameEntry.Event.Subscribe(PlaySoundSuccessEventArgs.EventId, OnPlaySoundSuccess);

private void OnPlaySoundSuccess(object sender, GameEventArgs e)
{
    var args = (PlaySoundSuccessEventArgs)e;
    // args.SerialId        - サウンドのシリアル番号
    // args.SoundAssetName  - サウンドアセット名
    // args.SoundAgent      - 再生に使用されるサウンドエージェント
    // args.Duration        - 読み込みにかかった時間(秒)
    // args.UserData        - 再生時に渡されるカスタムデータ
}
```

出典: [PlaySoundSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/EventArgs/PlaySoundSuccessEventArgs.cs#L41-L121)

### 2. 再生失敗イベントを購読する

コールバックはサウンドの読み込みまたは再生でエラーが発生した時点でトリガーされ、`PlaySoundErrorCode` のエラーコードとエラーメッセージを含みます。

```csharp
using GameFrameX;
using GameFrameX.Sound.Runtime;

GameEntry.Event.Subscribe(PlaySoundFailureEventArgs.EventId, OnPlaySoundFailure);

private void OnPlaySoundFailure(object sender, GameEventArgs e)
{
    var args = (PlaySoundFailureEventArgs)e;
    // args.SerialId         - サウンドのシリアル番号
    // args.SoundAssetName   - サウンドアセット名
    // args.SoundGroupName   - サウンドグループ名
    // args.PlaySoundParams  - 再生パラメータ
    // args.ErrorCode        - PlaySoundErrorCode のエラーコード
    // args.ErrorMessage     - エラーメッセージ
    // args.UserData         - カスタムデータ
}
```

出典: [PlaySoundFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/EventArgs/PlaySoundFailureEventArgs.cs#L41-L140)

### 3. 再生更新イベントを購読する

コールバックはサウンドの再生中に周期的にトリガーされ、現在の再生進捗を含みます。

```csharp
using GameFrameX;
using GameFrameX.Sound.Runtime;

GameEntry.Event.Subscribe(PlaySoundUpdateEventArgs.EventId, OnPlaySoundUpdate);

private void OnPlaySoundUpdate(object sender, GameEventArgs e)
{
    var args = (PlaySoundUpdateEventArgs)e;
    // args.SerialId        - サウンドのシリアル番号
    // args.SoundAssetName  - サウンドアセット名
    // args.SoundGroupName   - サウンドグループ名
    // args.PlaySoundParams - 再生パラメータ
    // args.Progress        - 読み込み/再生進捗(0~1)
    // args.UserData        - カスタムデータ
}
```

出典: [PlaySoundUpdateEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/EventArgs/PlaySoundUpdateEventArgs.cs#L41-L130)

### 4. 購読を解除する

受信が不要になったら、同じ `EventId` とコールバックインスタンスで購読を解除し、メモリリークを防ぎます。

```csharp
GameEntry.Event.Unsubscribe(PlaySoundSuccessEventArgs.EventId, OnPlaySoundSuccess);
GameEntry.Event.Unsubscribe(PlaySoundFailureEventArgs.EventId, OnPlaySoundFailure);
GameEntry.Event.Unsubscribe(PlaySoundUpdateEventArgs.EventId, OnPlaySoundUpdate);
```

## よくあるバリエーション

- **失敗原因だけを知りたい場合**:`PlaySoundFailureEventArgs` のみを購読し、`ErrorCode` に応じて異なる分岐(アセットの欠落、グループの欠落など)を処理します。
- **再生パラメータでコールバックをフィルタリング**:コールバック内で `PlaySoundParams` のカスタムフィールド(`UserData` など)を読み取り、条件に一致するイベントのみを処理します。
- **コールバック内で直接エージェントを取得**：成功イベントのコールバックでは `args.SoundAgent` から再生エージェントを取得でき、その後の `StopSound`、`PauseSound` などの操作に使用できます。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| 購読後に一度もトリガーされない | `PlaySoundXxxEventArgs.EventId` ではなく文字列を使用している | 各イベントクラスの静的フィールド `EventId`(`typeof(...).FullName`)を使用する |
| コールバック受信時にキャスト例外が発生 | `e` を別の `GameEventArgs` サブクラスにキャストしている | 購読したイベントに対応する `EventArgs` 型にキャストする |
| シーン終了後もコールバックがトリガーされる | `Unsubscribe` をしておらず、イベントセンターが破棄済みオブジェクトを保持している | `OnDestroy` で同じ `EventId` の購読を解除する |

## 背景(任意)

3 種類の `*EventArgs` はすべて `GameFrameX.Event.Runtime.GameEventArgs` を継承しており、Sound 内部で `ReferencePool` により再利用されます。コールバック内でフィールドを読み取ったらそれで完了です。`e` の参照を保持してフレームをまたいで使用しないでください。イベント ID は `typeof(...).FullName` から直接取得され、グローバルで一意です。
