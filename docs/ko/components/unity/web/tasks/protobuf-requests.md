# Protocol Buffers 요청 사용 방법

`WebManager`가 제공하는 `GetProtoBuf` / `PostProtoBuf` 제네릭 메서드를 사용하면 protobuf-net 메시지 객체로 HTTP 요청을 보내고 역직렬화된 응답 객체를 바로 얻을 수 있습니다. 메시지 타입은 `IExtensible`를 구현하고 `ProtoContract`/`ProtoMember`로 표시되어야 합니다.

## 사전 조건

- `com.gameframex.unity.web` 패키지가 설치되어 있고, 씬에 `WebComponent`가 존재하며 `IWebManager`(`WebManager`) 인스턴스를 보유하고 있어야 합니다.
- 메시지 타입이 protobuf-net 규칙에 따라 표시되어 있고(`ProtoContract` + `ProtoMember`), `class, IExtensible` 제네릭 제약을 충족해야 합니다.

## API 빠른 참조

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| `GetProtoBuf` | `Task<T> GetProtoBuf<T>(string url) where T : class, IExtensible;` | protobuf 메시지를 GET으로 가져와 `T`로 역직렬화 |
| `PostProtoBuf` | `Task<T> PostProtoBuf<T>(string url, IExtensible requestData) where T : class, IExtensible;` | 요청 본문을 protobuf로 직렬화하여 POST하고, 응답을 `T`로 역직렬화 |

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L196-L198)

## 작업 단계

1. protobuf 요청/응답 메시지 클래스를 정의하고, 필드는 `[ProtoMember(n)]`로 번호를 지정합니다:

```csharp
[ProtoContract]
public class UserResponse
{
    [ProtoMember(1)]
    public string UserName { get; set; }

    [ProtoMember(2)]
    public string Email { get; set; }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L116-L124)

2. 비즈니스 코드에서 `PostProtoBuf`(또는 `GetProtoBuf`)를 호출하고, 반환된 Task를 `await`하면 응답 객체를 얻을 수 있습니다:

```csharp
public async Task<UserResponse> GetUserProtoBufAsync(string userId)
{
    var request = new UserRequest { UserId = userId };
    return await webManager.PostProtoBuf<UserResponse>(
        "https://api.example.com/user/protobuf",
        request
    );
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L126-L133)

3. 필요에 따라 오류 처리를 추가합니다. 예를 들어 타임아웃과 네트워크 IO 예외를 캐치할 수 있습니다:

```csharp
try
{
    return await webManager.GetToString(url);
}
catch (WebException ex) when (ex.Status == WebExceptionStatus.Timeout)
{
    Debug.LogError("请求超时: " + ex.Message);
    return null;
}
catch (IOException ex)
{
    Debug.LogError("网络IO错误: " + ex.Message);
    return null;
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L138-L154)

## 일반적인 변형

- **사용자 지정 요청 헤더**: protobuf 요청은 `WebBinaryData`의 `Header` 딕셔너리를 사용하며, 전송 시 각 항목이 요청 헤더에 기록됩니다(네이티브 플랫폼에서는 `request.Headers`에 기록, WebGL 플랫폼에서는 `SetRequestHeader` 호출). [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L104-L110)와 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L140-L146)를 참조하세요.
- **WebGL 플랫폼**: 동일한 API가 `UNITY_WEBGL` 하에서는 `UnityWebRequest` + `UploadHandlerRaw`로 바이트를 업로드하고, 그 외 플랫폼에서는 `HttpWebRequest`로 요청 스트림을 작성합니다. [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L83-L101)를 참조하세요.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 요청을 보낸 후 응답이 계속 오지 않음 | protobuf 요청은 먼저 대기 큐에 진입하며 `UpdateBinary`가 매 프레임 큐에서 꺼내 처리합니다. `WebManager`가 업데이트되지 않거나(컴포넌트 비활성 상태) 전송된 요청 수가 `MaxConnectionPerServer`에 도달하면 요청이 계속 대기하게 됩니다 | `WebComponent`가 정상 작동하고 `WebManager`가 업데이트 상태인지 확인하고, 동시 실행 상한을 적절히 설정하세요 |
| 역직렬화 결과의 필드가 비어 있음 | 메시지 타입에 `[ProtoContract]` / `[ProtoMember(n)]` 표시가 없거나, 타입이 `class, IExtensible` 제약을 충족하지 않음 | 요청/응답 타입에 protobuf-net 특성(Attribute) 표시를 추가하세요 |
| 서버에서 파싱 실패 | 요청 `Content-Type`이 `application/octet-stream`으로 고정되어 있어, 서버는 protobuf 바이너리로 파싱해야 함 | 서버에서 텍스트 형식이 아닌 바이너리 protobuf로 처리하도록 하세요 |

## 검증

- `PostProtoBuf` 호출 후 응답 객체의 필드(예: `response.UserName`)를 출력했을 때 서버 반환 값을 가져올 수 있으면 요청과 역직렬화가 성공한 것입니다.
- 네트워크 오류가 발생하면 예외가 throw됩니다(네이티브 플랫폼에서는 `HttpWebRequest` 관련 예외, WebGL 플랫폼에서는 `unityWebRequest.error`로 래핑된 `Exception`). 이를 통해 실패 원인을 확인할 수 있습니다.

## 배경

protobuf 요청은 프레임워크 내부에서 "Binary 요청"으로 처리됩니다. `GetProtoBuf`/`PostProtoBuf`를 호출하면 요청이 `WebBinaryData`로 래핑되어 `m_WaitingBinaryQueue`에 들어가고, 매 프레임 `UpdateBinary`가 동시 실행 수가 상한에 도달하지 않았을 때 큐에서 꺼내 `MakeBinaryBytesRequest`를 호출하여 전송하며, 응답 바이트는 `WebBufferResult`로 래핑되어 콜백이 완료됩니다. 관련 구현은 [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L17-L55)를 참조하세요.
