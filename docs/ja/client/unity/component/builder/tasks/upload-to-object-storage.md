# ビルド成果物をオブジェクトストレージにアップロードする方法

Unity のコマンドラインにオブジェクトストレージ関連のパラメータを渡すことで、ビルドパイプラインがパッケージ出力後にログ、リソース、APK を自動的に S3 プロトコル互換のオブジェクトストレージ（OSS/S3/cos など）にアップロードできます。このページでは、本リポジトリが公開している設定スイッチとトリガー箇所を解説し、ビルド成果物をリモートバケットにプッシュする方法を説明します。

## 前提条件

- [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md) に従って `com.gameframex.unity.builder` を Unity プロジェクトに導入済みであること。
- `ObjectStorageUploadManager.UploadFile(string)` を実装したオブジェクトストレージ SDK パッケージを導入していること（本リポジトリはコンパイルマクロ `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` を通じて接続し、当該 SDK が導入されていない場合はアップロードコードがコンパイルされません）。
- オブジェクトストレージバケットの `Key`、`Secret`、`BucketName`、`EndPoint`（リージョン/Endpoint）を用意済みであること。

## 操作手順

1. ビルドマシン上でオブジェクトストレージパラメータを準備します。以下の4つのフィールドは [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40) で解析されます:

   | フィールド | 意味 |
   |------|------|
   | `ObjectStorageKey` | アクセス Key（アカウント AccessKey） |
   | `ObjectStorageSecret` | アクセス Secret |
   | `ObjectStorageBucketName` | バケット（Bucket）名 |
   | `ObjectStorageEndPoint` | バケットが存在するリージョンの Endpoint |

2. Unity のコマンドラインで `-ObjectStorageKey`、`-ObjectStorageSecret`、`-ObjectStorageBucketName`、`-ObjectStorageEndPoint` を使用して上記の4つの値を渡します。ビルドスクリプトが `Builder.BuildParamsParse` を通じてリフレクションで `_builderOptions` に値をセットします。

3. 対応するアップロードスイッチをオンにします。リポジトリでは互いに競合しない3つのブール値スイッチを提供しています。詳細は [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L62-L125) を参照してください:

   | スイッチ | デフォルト値 | 役割 |
   |------|--------|------|
   | `IsUploadLogFile` | `false` | ビルド準備段階でログをアップロード |
   | `IsUploadAsset` | `false` | ビルドリソース後にアセットパッケージをアップロード |
   | `IsUploadApk` | `false` | APK 出力後にインストールパッケージをアップロード |

4. `BuildReady` を例にすると、ログアップロードの実際のトリガーコードは [Builder.BuildReady.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49) にあります:

   ```csharp
   AssetDatabase.Refresh();
   if (_builderOptions.IsUploadLogFile)
   {
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.UploadFile(_builderOptions.LogFilePath);
   #endif
   }
   ```

   Source: [Editor/Builder.BuildReady.cs#L43-L49](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49)

   `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` コンパイルシンボルが定義されている場合のみ、`UploadFile` の呼び出しがビルドに組み込まれます。そうでない場合はブロック全体がプリプロセスで除外され、タスクはエラーを出しません。

5. ビルドをトリガーします。以下のいずれかのエントリコマンドを選択し、スイッチがオンになっていることを確認してください:

   ```bash
   Unity -batchmode -quit -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildReady \
         -ObjectStorageKey <your-key> \
         -ObjectStorageSecret <your-secret> \
         -ObjectStorageBucketName <your-bucket> \
         -ObjectStorageEndPoint <your-endpoint> \
         -IsUploadLogFile true \
         -IsUploadAsset true \
         -IsUploadApk true \
         -logFile -
   ```

   パラメータは [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L127-L130) によってリフレクションでモデルに書き込まれ、ログで `ToString()` を出力して検証できます。

## よくあるバリエーション

- **ログのみをプッシュしたい**:`-IsUploadLogFile true` のみを指定し、他の2つのアップロードスイッチはデフォルトの `false` のままにします。
- **リソースパッケージのみをプッシュしたい**:`BuildAsset` パイプライン呼び出し時に `-IsUploadAsset true` を指定します。
- **APK のみをプッシュしたい**:`BuildApk` パイプライン呼び出し時に `-IsUploadApk true` を指定します。
- **環境ごとに分離したい**:4つのストレージパラメータを CI の環境変数に入れ、ビルドスクリプト内で再度コマンドラインにセットします。

## よくあるエラー

- **実行時に「ObjectStorageUploadManager が見つかりません」と報告される**:本リポジトリはアップロードスイッチのみを保持しており、実際のアップロードクラスは外部のオブジェクトストレージ SDK が提供します。`Packages/manifest.json` に対応する実装パッケージをインストールし、Player Settings の `Scripting Define Symbols` に `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` を追加する必要があります。そうでない場合、`#if` 分岐が除外されます。
- **バケット内にファイルが見つからない**:`ObjectStorageEndPoint` がバケットが存在するリージョンの Endpoint であること（コンソールのドメイン名ではない）を確認し、バケットの ACL がその Key による書き込みを許可していることを確認してください。
- **複数のビルドが同時にアップロードして衝突する**:ビルド番号 `BuildNumber` がリモートパスに使用されます（外部 SDK 内で組み立てられます）。並列実行シナリオでは `BuildNumber` が一意であることを保証する必要があります。

## 背景（オプション）

リポジトリは「スイッチ + コンパイルマクロ」による最小結合の設計となっています。`BuilderOptions` はコマンドラインパラメータをモデルに格納する役割のみを担い、実際に `ObjectStorageUploadManager` を呼び出すのは `BuildReady`、`BuildAsset`、`BuildApk` の3つのパイプライン内のアップロード分岐のみです。`ENABLE_GAME_FRAME_X_OBJECT_STORAGE` が定義されていない場合、アップロードコードはコンパイルに含まれず、オブジェクトストレージの依存関係がないプロジェクトでも本ツールを直接使用できます。
