# 監聽網路事件（連線/斷線/錯誤/心跳遺失）

本頁面說明如何訂閱並處理網路模組所引發的四種事件：`NetworkConnectedEventArgs`（連線成功）、`NetworkClosedEventArgs`（連線關閉）、`NetworkErrorEventArgs`（網路錯誤）以及 `NetworkMissHeartBeatEventArgs`（心跳遺失）。這些事件全部繼承自 `GameFrameX.Event.Runtime.GameEventArgs`，並透過各型別的靜態欄位 `EventId`（其值等於該型別的完整名稱）註冊訂閱，在處理回呼中即可直接讀取事件所攜帶的欄位。

## 前置條件

- 已匯入 GameFrameX 網路元件（命名空間 `GameFrameX.Network.Runtime`）。
- 事件訂閱入口由 **GameFrameX.Event 元件**提供（`GameEventArgs` 基礎類別位於 `GameFrameX.Event.Runtime`；該元件不包含在本儲存庫中）。在訂閱本頁所列的事件 Id 之前，請先確認專案中已啟用事件元件。

## 步驟

1. 確認你要監聽的事件以及它們攜帶的欄位（全部位於 `GameFrameX.Network.Runtime` 命名空間）：

| 事件類別 | 觸發時機 | 攜帶欄位 | EventId 值 |
|--------|----------|----------|------------|
| `NetworkConnectedEventArgs` | 網路連線成功 | `NetworkChannel` (`INetworkChannel`)、`UserData`（`object`，連線時傳入的自訂資料） | `GameFrameX.Network.Runtime.NetworkConnectedEventArgs` |
| `NetworkClosedEventArgs` | 網路連線關閉 | `NetworkChannel`（完整欄位集合請參閱原始碼檔案） | `GameFrameX.Network.Runtime.NetworkClosedEventArgs` |
| `NetworkErrorEventArgs` | 網路錯誤 | `NetworkChannel`、`ErrorCode` (`NetworkErrorCode`)、`SocketErrorCode` (`System.Net.Sockets.SocketError`)、`ErrorMessage` (`string`) | `GameFrameX.Network.Runtime.NetworkErrorEventArgs` |
| `NetworkMissHeartBeatEventArgs` | 心跳封包遺失 | `NetworkChannel`、`MissCount`（`int`，目前為止的遺失次數） | `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs` |

2. 使用各事件類別的**靜態欄位** `EventId` 向事件元件註冊回呼；不要手寫字串——`EventId` 的定義就是該型別的完整名稱：

```csharp
/// <summary>
/// 網路連線成功事件的事件 Id。
/// </summary>
public static readonly string EventId = typeof(NetworkConnectedEventArgs).FullName;

/// <summary>
/// 取得網路連線成功事件的事件 Id。
/// </summary>
public override string Id
{
    get { return EventId; }
}
```

來源：[NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L44-L54)

3. 在回呼中依據事件型別讀取欄位。以錯誤事件為例，你可以同時取得框架層級的錯誤碼、Socket 層級的錯誤碼以及錯誤訊息：

```csharp
/// <summary>
/// 取得網路通道。
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// 取得錯誤碼。
/// </summary>
public NetworkErrorCode ErrorCode { get; private set; }

/// <summary>
/// 取得 Socket 錯誤碼。
/// </summary>
public SocketError SocketErrorCode { get; private set; }

/// <summary>
/// 取得錯誤訊息。
/// </summary>
public string ErrorMessage { get; private set; }
```

來源：[NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L68-L86)

4. 心跳遺失時，使用 `MissCount` 判斷嚴重程度（此計數會隨連續遺失而遞增），並結合 `NetworkChannel` 判斷是哪個通道：

```csharp
/// <summary>
/// 取得網路通道。
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// 取得目前為止遺失的心跳封包數量。
/// </summary>
public int MissCount { get; private set; }
```

來源：[NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L65-L73)

5. 回呼返回後**請勿快取事件物件**。事件實例來自參考池（透過 `ReferencePool.Acquire` 建立，欄位由 `Clear()` 重設），事件派發完成後欄位即被清空：

```csharp
public static NetworkConnectedEventArgs Create(INetworkChannel networkChannel, object userData)
{
    NetworkConnectedEventArgs networkConnectedEventArgs = ReferencePool.Acquire<NetworkConnectedEventArgs>();
    networkConnectedEventArgs.NetworkChannel = networkChannel;
    networkConnectedEventArgs.UserData = userData;
    return networkConnectedEventArgs;
}

/// <summary>
/// 清除網路連線成功事件。
/// </summary>
public override void Clear()
{
    NetworkChannel = null;
    UserData = null;
}
```

來源：[NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L77-L96)

## 常見變化

- **斷線後重連**：在 `NetworkMissHeartBeatEventArgs`（`MissCount` 超過門檻值）或 `NetworkClosedEventArgs` 的回呼中，記錄通道資訊（位址等，可從 `NetworkChannel` 取得），延遲一段時間後重新發起連線；連線結果再由 `NetworkConnectedEventArgs` 確認。
- **區分多個通道**：同時維護多條連線時，在所有回呼中應先比對 `NetworkChannel`（例如通道名稱）再進行處理，以免將通道 A 的錯誤誤認為通道 B 的。
- **分層的錯誤顯示**：以 `ErrorCode` 進行業務邏輯分支，並將 `SocketErrorCode`/`ErrorMessage` 用於日誌記錄與顯示給使用者的訊息文字。

## 常見錯誤

| 症狀 | 原因 | 如何避免 |
|------|------|----------|
| 手寫訂閱字串後收不到事件 | 字串與實際的 `EventId` 不一致（注意完整的命名空間前綴 `GameFrameX.Network.Runtime.`） | 一律使用靜態欄位（例如 `NetworkConnectedEventArgs.EventId`）訂閱 |
| 回呼中讀取到的欄位是 `null` / `0` | 事件物件來自參考池；派發後 `Clear()` 已重設欄位 | 在回呼內立即讀取並複製所需數值；不要快取事件實例 |
| 無法參考 `SocketErrorCode` / `ErrorMessage` | 未匯入 `System.Net.Sockets` 命名空間 | 在訂閱類別的檔案頂端加入 `using System.Net.Sockets;`（錯誤事件的原始碼檔案正是這樣匯入的） |
| 編譯時回報找不到 `GameEventArgs` | 事件基礎類別位於 GameFrameX.Event 元件中，不在本儲存庫內 | 請先安裝/啟用事件元件 |

## 背景

四個事件參數類別皆為 `sealed class ... : GameEventArgs`，並標記了 `[UnityEngine.Scripting.Preserve]` 以防止被程式碼裁剪（trimming）移除；實例透過靜態 `Create(...)` 從參考池取得，並在歸還前以 `Clear()` 重設欄位。這是框架統一的「參考池事件」模式，也是為什麼必須在回呼內立即使用資料的原因。事件類別的原始碼位於 `Runtime/EventArgs/` 目錄（[NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs)、[NetworkClosedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkClosedEventArgs.cs)、[NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs)、[NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs)）；錯誤碼列舉可見於 `Runtime/Network/Base/NetworkErrorCode.cs`，心跳處理相關的基礎類別可見於 `Runtime/Network/Helper/BasePacketHeartBeatHandler.cs` 與 `Runtime/Network/Base/IHeartBeatMessage.cs`。事件派發與訂閱 API 屬於 GameFrameX.Event 元件；關於事件元件的整體使用方式，請參閱其對應的文件。
