# 처리되지 않은 이벤트에 기본 핸들러를 설정하는 방법

`EventComponent.SetDefaultHandler`를 호출하여 `EventHandler<GameEventArgs>` 콜백을 등록하면, `Fire` / `FireNow`로 발생되었지만 구독자가 없는 모든 이벤트는 조용히 폐기되는 대신 이 콜백으로 전달됩니다 — 주로 로그 기록, 알림 또는 놓친 이벤트 통계에 사용됩니다.

## 사전 조건

- 씬에 `EventComponent` 컴포넌트가 부착된 오브젝트가 이미 존재함(이벤트 기능이 활성화됨).
- 기본적인 이벤트 구독/발생 사용법을 이미 이해하고 있어야 합니다.

## 작업 단계

1. 시그니처가 `EventHandler<GameEventArgs>`인 콜백 메서드를 작성합니다. 내부에서 `e.Id`를 읽으면 이벤트 번호를 얻을 수 있습니다:

```csharp
void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"처리되지 않은 이벤트: {e.Id}");
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L145-L150)

2. 초기화 단계(예: `Start` 또는 모듈 진입점)에서 `SetDefaultHandler`를 호출하여 등록합니다:

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L144-L145)

3. 구독자가 없는 이벤트를 발생시켜 검증합니다:

```csharp
// 바로 가기: 사용자 지정 이벤트 인자가 필요 없으며, 내부적으로 EmptyEventArgs.Create(eventId)로 래핑됩니다
eventComponent.Fire(this, "level_up");
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`Fire`는 스레드 안전한 지연 디스패치입니다 — 워커 스레드에서 발생시키더라도 콜백은 다음 프레임에 메인 스레드에서 실행됩니다. 기본 핸들러가 즉시 호출되기를 원한다면 `FireNow`(즉시 디스패치, 메인 스레드 전용)를 사용하세요.

## 일반적인 변형

| 요구 사항 | 방법 |
|------|------|
| 기본 핸들러 교체 | `SetDefaultHandler(newHandler)`를 다시 호출하여 기존 콜백을 덮어씀 |
| 기본 핸들러 해제 | `SetDefaultHandler(null)`을 호출하면, 이후 구독자가 없는 이벤트는 다시 조용히 폐기됨 |
| 사용자 지정 인자가 있는 이벤트 폴백 처리 | `eventComponent.Fire(this, LevelUpEventArgs.Create(5))`, 콜백에서 `e`를 구체적인 인자 타입으로 다운캐스팅 가능 |
| 이벤트를 발생시킨 주체 추적 | 콜백 내에서 `sender`(이벤트 발신자)를 `e.Id`와 함께 기록하여 보고 |

## 자주 발생하는 오류

- **콜백 시그니처 불일치**: `SetDefaultHandler`는 `EventHandler<GameEventArgs>`만 허용합니다. `Action<string>` 또는 구체적인 인자 타입 대상 핸들러로 작성하면 컴파일이 실패합니다. 구독된 이벤트는 구체적인 핸들러에서 먼저 처리하고, 기본 핸들러는 통일되게 `GameEventArgs`를 받아야 합니다.
- **기본 핸들러가 '구독자 없는' 이벤트에만 폴백으로 동작한다는 점을 잊음**: 해당 `Id`에 이미 구독자가 있다면 이벤트는 정상적으로 구독자에게 디스패치되며 기본 핸들러로 들어가지 않습니다. 기본 핸들러를 전역 이벤트 리스너처럼 사용하지 마세요.
- **워커 스레드에서 `FireNow` 오용**: `FireNow`는 즉시 디스패치되며 스레드 안전하지 않아, 자식 스레드에서 호출하면 정의되지 않은 동작이 발생할 수 있습니다. 자식 스레드에서는 `Fire`를 사용하세요.
- **기본 핸들러 내부에서 예외 발생**: 콜백은 이벤트 디스패치 주요 흐름에서 실행되므로 예외가 발생하면 디스패치가 중단됩니다. 콜백 내에서 예외 처리를 확실히 하세요.

## 배경

`EventComponent.SetDefaultHandler`는 단순한 전달 계층일 뿐이며, 내부적으로 `m_EventManager.SetDefaultHandler(handler)`를 호출하고, 이것이 다시 콜백을 하위 이벤트 풀(`m_EventPool.SetDefaultHandler`)에 넘깁니다. 디스패치 시 특정 이벤트 번호에 일치하는 핸들러가 없으면 이벤트 풀이 대신 기본 핸들러를 호출함으로써 "미처리 이벤트 폴백"을 구현합니다.
