# 使用 await 异步等待下载完成

`DownloadComponent` 提供了一个返回 `Task<bool>` 的 `Download` 方法,可直接在协程或异步方法里用 `await` 等待文件下载完成,无需订阅事件回调。

## 前置条件

- 场景中已挂载 `DownloadComponent` 组件(通过 `[GameFrameXAutoComponent(-4000)]` 自动注册)。
- 业务代码能拿到 `DownloadComponent` 实例,通常通过 `GameEntry.GetComponent<DownloadComponent>()` 获取。

## 操作步骤

1. 调用 `DownloadComponent.Download(downloadPath, downloadUri)`,获得一个 `Task<bool>`。
2. 在 `async` 方法里 `await` 这个任务,值为 `true` 表示下载成功,`false` 表示失败或下载未开始。
3. 按返回值决定后续逻辑(加载资源、提示错误等)。

最小可用示例:

```csharp
using System.Threading.Tasks;
using GameFrameX.Download.Runtime;

public async Task LoadRemoteConfigAsync()
{
    var download = GameEntry.GetComponent<DownloadComponent>();
    bool ok = await download.Download(
        downloadPath: Application.persistentDataPath + "/config.json",
        downloadUri:  "https://example.com/config.json");

    if (ok)
    {
        // 读取本地文件继续后续逻辑
    }
    else
    {
        // 下载失败时的回退处理
    }
}
```

## 常见变体

- 带标签或优先级的版本依然走原 `AddDownload` 流程,`Download` 方法当前仅暴露最常用的 `(path, uri)` 重载。如需自定义标签或优先级,可继续使用 `AddDownload` + 事件方式。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `await` 永远不返回,值一直是 `false` | 下载任务尚未进入下载管理器,`m_Downloads.TryGetValue` 失败,直接返回了一个已 `TrySetResult(false)` 的任务 | 确认路径与 URI 合法,并确保 `DownloadComponent` 已 `Start`(依赖 `EventComponent` 与 `m_DownloadManager`) |
| 调用处出现 `NullReferenceException` | 业务侧 `DownloadComponent` 未在场景中或尚未 Awake | 通过 `GameEntry.GetComponent<DownloadComponent>()` 获取,并先判空 |
| 多任务并发时,返回的 `Task` 互相覆盖 | `Download` 方法基于 `serialId` 在内部字典中查找对应的 `TaskCompletionSource<bool>` | 不同下载使用独立的 `await` 变量接收,避免混用返回值 |

## 背景(可选)

内部使用 `ConcurrentDictionary<int, DownloadData>` 维护 `serialId` 到 `TaskCompletionSource<bool>` 的映射;`Awake` 中订阅 `DownloadSuccess` / `DownloadFailure` 事件,在回调里调用 `TrySetResult(true/false)`,从而把事件式 API 转成 `Task` API。
