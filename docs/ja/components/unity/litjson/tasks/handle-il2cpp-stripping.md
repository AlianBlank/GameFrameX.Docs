# Unity IL2CPP マネージドコードストリッピングへの対処方法

IL2CPP + Managed Code Stripping を有効にした場合、`GameFrameX.LitJSON` は 3 層の相補的なメカニズムによって、自身の型がストリッピングされるのを防ぎます。本ページでは、これらのメカニズムがどのように連携して動作するか、またストリッピングが原因で `MissingMethodException` / `TypeLoadException` が発生した際に保護を補完する方法について説明します。

## 前提条件

- Unity 2019.4 以降([package.json](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/package.json#L5) を参照)
- Scoped Registry または Git URL で `com.gameframex.unity.litjson` をインストール済み(詳細は README を参照)
- プロジェクトが IL2CPP バックエンドを使用している(Android/iOS などのリリースプラットフォームではデフォルトで有効)

## 操作手順

### 1. ストリッピング保護がデフォルトで有効になっていることを確認する

パッケージには 3 層の保護が組み込まれており、**ほとんどのプロジェクトでは追加設定は不要**です:

| メカニズム | 役割 | ソース |
|------|------|------|
| `link.xml` | 名前空間内のすべての型を宣言的に保持 | パッケージレベルのフィルターファイル |
| `LitJsonCroppingHelper` | 起動時に `typeof()` で主要な型を参照 | `Runtime/LitJsonCroppingHelper.cs` |
| `[Preserve]` 属性 | リフレクションに依存するコンストラクター、プロパティ getter、エクスポーターをマーク | 各 Runtime クラス |

`LitJsonCroppingHelper` のインスタンスが 1 つでもシーン内でアクティブな状態にあれば、3 層目の保護が `Start()` 内で有効になります。

### 2. `LitJsonCroppingHelper` をシーンに配置する

任意の**最初のシーン**(Bootstrap / Loading シーン)を開き、空の GameObject を作成して `LitJson Cropping Helper` コンポーネントを追加します:

```csharp
// Runtime/LitJsonCroppingHelper.cs における Start() の実際の実装
[Preserve]
public void Start()
{
    _ = typeof(ArrayMetadata);
    _ = typeof(Condition);
    _ = typeof(ExporterFunc);
    _ = typeof(ExporterFunc<>);
    _ = typeof(JsonIgnoreAttribute);
    _ = typeof(JsonPropertyAttribute);
    _ = typeof(FsmContext);
    _ = typeof(IJsonWrapper);
    _ = typeof(ImporterFunc);
    _ = typeof(ImporterFunc<,>);
    _ = typeof(JsonData);
    _ = typeof(JsonException);
    _ = typeof(JsonMapper);
    _ = typeof(JsonMockWrapper);
    _ = typeof(JsonReader);
    _ = typeof(JsonToken);
    _ = typeof(JsonType);
    _ = typeof(JsonWriter);
    _ = typeof(Lexer);
    _ = typeof(ObjectMetadata);
    _ = typeof(OrderedDictionaryEnumerator);
    _ = typeof(ParserToken);
    _ = typeof(PropertyMetadata);
    _ = typeof(UnityTypeBindings);
    _ = typeof(WrapperFactory);
    _ = typeof(WriterContext);
}
```

ソース:[LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L23-L52)

各 `_ = typeof(...)` は C# 7.0 の discard 構文で、IL2CPP リンカーにこれらの型が「使用された」と認識させ、保持させるためのものです。

### 3. 独自のリフレクション対象クラスに `[Preserve]` を付ける(オプション)

LitJson がリフレクション経由でカスタム POCO を読み書きする場合、その型がコード内で明示的に new されていなければ、ストリッピングされる可能性が残ります。データクラスに `[Preserve]` を付けるだけで対応できます:

```csharp
using UnityEngine.Scripting;

[Preserve]
public class PlayerData
{
    public string Name;
    public int Level;
    public Vector3 Position;
}
```

### 4. IL2CPP ビルドを実行してバイナリを確認する

1. File → Build Settings → プラットフォームを iOS または Android に切り替える
2. Player Settings → Other Settings → Scripting Backend = `IL2CPP` に設定し、Managed Stripping Level はデフォルトの `High` のままにするか、明示的に `Low`/`Medium` に設定して再テストする
3. Build And Run
4. デバイス/シミュレーターで逆シリアル化を 1 回実行し(例:`JsonMapper.ToObject<PlayerData>(text)`)、例外が発生しないことを確認する

## よくあるバリエーション

- **コードのホットアップデートのシナリオ**:HybridCLR / ILRuntime を使用する場合、ホストプロジェクト内にホットアップデート DLL 用の link.xml も配置する必要があります。そうしないと、ホットアップデートコードが参照する LitJson の型がストリッピングされる可能性があります。
- **Addressables のリモートリソース**:実行時にリモートからロードされる `AssemblyDefinition` はメインプロジェクトの link.xml の対象外のため、リモートアセンブリ自身の asmdef の横にもう 1 つ配置する必要があります。
- **`LitJsonCroppingHelper` を使用しない**:手動で link.xml を記述して 3 層目の保護を代替できます(次のセクションを参照)。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 実行時に `MissingMethodException: void LitJson.JsonMapper::.cctor()` が発生 | `JsonMapper` の cctor がストリッピングされた | `LitJsonCroppingHelper` がシーンに配置され、アクティブになっていることを確認する |
| `TypeLoadException: Could not load type LitJson.Lexer` | `Lexer` 型がストリッピングされた | 同上、または独自のデータクラスに `[Preserve]` を付ける |
| `[Preserve]` を付けてもエラーが続く | source-only `link.xml` を使用しているが、マネージドストリッピングに無視されている | link.xml を `Assets/Plugins/` のサブ階層ではなく、`Assets/` のルートまたはパッケージのルートに配置する |
| iOS ビルドで `Start()` がトリガーされない | `LitJsonCroppingHelper` コンポーネントがロードされていないサブシーンに配置されている | 最初のシーンに直接配置するか、独自の `RuntimeInitializeOnLoadMethod` 内で手動で呼び出す |

## 背景(オプション)

LitJson はリフレクションを多用します(`JsonMapper.ToObject<T>` はリフレクションでフィールドを読み取り、setter に書き込みます)。IL2CPP の静的解析は直接呼び出されるコードしか識別できず、リフレクションの呼び出しチェーンは追跡できないため、`new` されていない型はストリッピングされます。パッケージでは**三重の防御**を採用しています:link.xml によるホワイトリスト、`LitJsonCroppingHelper` による実行時の `typeof` 参照、`[Preserve]` によるリフレクション入口へのマーキング——いずれか 1 層が機能しなくなっても、残りの 2 層がフォールバックとして機能します。

LitJson の全体的な使用方法については、[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md) を参照してください。
