# イベントが送信されない：「GameAnalyticsManager is not init.」警告の対処法

`GameAnalyticsComponent` の `Event` / `StartTimer` / `StopTimer` などのインターフェースを呼び出したとき、対応する分析 SDK マネージャーインスタンスの内部でまだ初期化が完了していない場合、コンポーネントは `GameAnalyticsManager is not init.` を出力し、今回の送信をスキップします。この警告は `GameAnalyticsComponent` の未初期化ガードによるもので、「Provider は `IGameAnalyticsManager` インスタンスを生成済みだが、そのインスタンス自身の `m_IsInit` はまだ false である」ことを意味します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `Event`/`StartTimer`/`StopTimer` を呼び出すたびに `GameAnalyticsManager is not init.` が出力される | コンポーネントの `Init()` は実行済みで `IGameAnalyticsManager` インスタンスも生成されているが、実装クラス内部の `m_IsInit` が `true` に設定されていない（`Init(args)` 内に初期化完了の処理が書かれていない、または該当実装が「手動初期化」型でまだ `ManualInit` が呼ばれていない） | 下記の[修正手順 1](#1-実装クラスの-init-または-manualinit-で-isinit-をセットする)を参照 |
| コンソールに `Log.Error`：`Can not find component type 'XXX'.` が表示される | Inspector で設定された `ComponentType` の型名が `Utility.Assembly.GetType` で解決できない（型が存在しない、名前空間/アセンブリが不正） | 型名のスペルと所属アセンブリを確認。該当 Provider は `continue` でスキップされる |
| 警告は一切出ないが、イベントも送信されない | `m_gameAnalyticsComponentProviders` リストが空、または項目の `ComponentType` が空白文字列（この場合ループがそのままスキップされ、インスタンスは生成されない）；コンポーネントレベルの `m_IsInit` がまだ false で、すべての呼び出しがサイレントに `return` している可能性もある | コンポーネント Inspector の「ゲームデータ分析コンポーネントリスト,順次送信」に Provider を追加して実装型を選択する；呼び出しがコンポーネントの `OnEnable` より後に行われていることを確認する |
| ゲーム起動直後のごく早い段階でのみ送信に失敗し、警告は出ない | コンポーネントの `Init()` は `OnEnable()` でようやく実行されるため、`Awake` 段階では `m_IsInit` が false であり、呼び出しがサイレントに破棄される | 送信ロジックをコンポーネントの有効化より後に移動する |

この警告を発生させる完全なガードロジック（`Event(string)` を例に挙げます。その他のオーバーロードとタイマー系インターフェースも構造は同じです）：

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

ソース：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

この警告が発生する 6 つの呼び出し箇所：`StartTimer`（L176）、`StopTimer`（L237）、`Event(string)`（L262）、`Event(string, float)`（L288）、`Event(string, Dictionary<string, object>)`（L321）、`Event(string, float, Dictionary<string, object>)`（L355）。

## 修正手順

### 1. 実装クラスの Init または ManualInit で isinit をセットする

警告の判定基準は `IGameAnalyticsManager.IsInit()` であり、これは基底クラス `BaseGameAnalyticsManager` が提供し、protected フィールド `m_IsInit` を返します：

```csharp
protected bool m_IsInit = false;

/// <summary>
/// 初期化済みかどうか
/// </summary>
/// <returns></returns>
public bool IsInit()
{
    return m_IsInit;
}
```

ソース：[BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L12-L45)

`Init(Dictionary<string, string> args)` と `ManualInit(Dictionary<string, string> args)` は抽象メソッドで、各分析 SDK の実装クラスがそれぞれ実装します。自分の実装を確認してください：

- SDK がユーザー同意などの前提条件を必要としない場合、`Init(args)` で SDK の初期化を完了した後に `m_IsInit = true;` を記述します。
- SDK が `ManualInit` を必要とする場合（プライバシーコンプライアンスフロー）、`IsManualInit()` が true を返す実装では、まず `GameAnalyticsComponent.ManualInit(extraArgs)` を呼び出し、その中で `m_IsInit` をセットする必要があります。コンポーネント側のガードに注意してください：

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

ソース：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

`ManualInit` は `IsManualInit()` が true の実装にのみ転送され、かつコンポーネント自身がすでに `Init()` 済みであることが必要です。

### 2. Provider が Inspector で設定済みであることを確認する

コンポーネントは `OnEnable()` で `Init()` を呼び出し、`m_gameAnalyticsComponentProviders` を走査し、リフレクションによって実装クラスのインスタンスを生成してその `Init(args)` を呼び出します：

```csharp
private void OnEnable()
{
    Init();
}

public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }
            // ...インスタンスを生成し、args を組み立てて gameAnalyticsManager.Init(args) を呼び出す
        }
    }

    m_IsInit = true;
}
```

ソース：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L27-L80)

シーン内の `GameAnalyticsComponent` の Inspector（メニュー `Game Framework/GameAnalytics`）で、タイトルが「ゲームデータ分析コンポーネントリスト,順次送信」のリストを編集します：要素を追加し、`ComponentType` ドロップダウンで `IGameAnalyticsManager` を実装した型を選択し（ドロップダウンの選択肢は `Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager))` から取得されます）、`Setting` に該当実装が必要とする Key/Value パラメータ（AppId、SecretKey など、具体的な実装によります）を設定します。

ソース：[GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

### 3. サイレント破棄の切り分け（警告がないが送信もされない場合）

コンポーネントレベルのガードはサイレントです：`!m_IsInit` の場合、ログを一切出力せずに直接 `return` します。警告すら出ない場合は、以下を順に確認してください：

1. 呼び出しタイミングがコンポーネントの `OnEnable` より早くないか（`Awake` 段階では `m_IsInit` はまだ false）。
2. `m_gameAnalyticsComponentProviders` が空リストでないか、または `ComponentType` が空白になっていないか――この場合、エラーも出力されずインスタンスも生成されません。
3. コンソールに `Can not find component type '...'` の `Log.Error` がないか――該当 Provider は `continue` でスキップされます。

## 検証

1. ゲームを起動し、コンソールに `Can not find component type` の赤いエラーがもう表示されないことを確認します（このエラーが発生すると該当 Provider はそのままスキップされます）。
2. 任意の `Event(...)` / `StartTimer(...)` を呼び出し、`GameAnalyticsManager is not init.` の黄色い警告が消えることを確認します。
3. 対応する分析プラットフォーム（ThinkingData、数数など、実装クラスによります）の管理画面でイベントが到達しているかを確認します。または、実装クラスの `Init` 内に一時的なログを追加して、`m_IsInit` が true にセットされたことを確認します。

## 背景

警告には 2 層のガードがあります：`GameAnalyticsComponent.m_IsInit`（コンポーネントレベル、`OnEnable` 時に true がセットされ、未初期化時はサイレントに破棄）と各 `IGameAnalyticsManager.IsInit()`（インスタンスレベル、未初期化時にこの警告を出力）。`BaseGameAnalyticsManager` は `m_IsInit` フィールドを保持し、`IsInit()` / `SetPublicProperties` などの汎用機能を公開するだけで、セットするタイミングは完全に個々の SDK 実装によって決まります――したがってこの警告は、ほとんどの場合、実装クラスの `Init`/`ManualInit` が `m_IsInit` を true にしていないこと、または呼び出しが手動初期化フローより前に行われていることを示しています。

コンポーネントの各送信インターフェースの完全なシグネチャについては、『GameAnalyticsComponent リファレンス』を参照してください。
