# 타이머가 트리거되지 않거나 조회가 -1을 반환할 때 어떻게 해야 하나요

타이머 콜백이 발생하지 않거나 `GetRemaining` / `GetElapsed` / `GetRepeatLeft`가 `-1`을 반환하는 경우, 대체로 다음 유형에 해당합니다: 콜백이 null이라 `Add`가 즉시 실패하고 0을 반환하는 경우, 타이머를 방금 `Add`했지만 아직 `Update`에 의해 `_items`로 반영되지 않은 경우, 반복 횟수가 소진되었거나 이미 `Remove`된 경우, `Pause` 후 `Resume`되지 않은 경우, `Scaled` 모드에서 `Time.timeScale`이 0인 경우. 이 페이지는 증상별 진단표와 해당 복구 단계를 제공합니다(아래 예제는 이미 `TimerManager` / `ITimerManager` 인스턴스를 보유하고 있으며, Unity 측에서는 `TimerComponent`를 통해 동일한 이름의 메서드가 전달된다고 가정합니다).

## 복구 단계

### 1. `Add`가 0을 반환함: 콜백이 null인 경우

`Add`의 전체 시그니처와 실패 분기는 다음과 같으며, `callback == null`이면 경고만 출력하고 0을 반환하며, 해당 ID는 절대 트리거되지 않습니다:

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
{
    lock (Locker)
    {
        if (callback == null)
        {
            Debug.LogWarning("timer callback is null, " + interval + "," + repeat);
            return 0;
        }
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L225)

등록 후 먼저 반환값을 검증하세요:

```csharp
int id = timerManager.Add(1f, 0, OnTick);
if (id == 0)
{
    // 콜백이 null이므로 등록에 실패한 것이며, 여기서 이 id를 계속 보유해서는 안 됨
}
```

### 2. 방금 `Add`한 직후 조회가 -1을 반환함: 타이머가 아직 `Update`로 반영되지 않음

새 타이머는 먼저 `_toAdd`에 들어가고, `Update` 마지막에야 `_items`로 반영됩니다; 조회 메서드는 `_items`에서 삭제되지 않은 항목을 찾았을 때만 유효한 값을 반환하며, 그렇지 않으면 -1을 반환합니다:

```csharp
public float GetRemaining(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return -1f;
        }

        if (_items.TryGetValue(callback, out var t) && !t.Deleted)
        {
            // ...남은 시간 반환
        }

        // Timer is in _toAdd (not yet flushed)
        return -1f;
    }
}
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L552-L575)

반영은 `Update`의 마지막 단계에서 일어나므로, “이번 프레임에 등록하고 이번 프레임에 조회”하면 반드시 -1을 얻게 됩니다:

```csharp
if (_toAdd.Count > 0)
{
    var enumerator = _toAdd.GetEnumerator();
    while (enumerator.MoveNext())
    {
        _items.Add(enumerator.Current.Key, enumerator.Current.Value);
    }

    enumerator.Dispose();
    _toAdd.Clear();
}
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L153-L163)

**복구 방법**: 조회를 다음 프레임으로 옮기거나(코루틴 `yield return null`, 또는 다른 매 프레임 콜백에 배치), 먼저 `Exists(id)`로 판단하세요——이 메서드는 `_toAdd`와 `_items`를 모두 확인하여 “아직 반영되지 않은” 타이머에 대해 true를 반환합니다.

### 3. 반복 횟수 소진 또는 이미 `Remove`됨

`repeat > 0`인 타이머는 트리거될 때마다 감소하며, 0이 되면 삭제로 표시됩니다; 삭제 시 ID가 `_ids`에서 제거되므로 이후 ID 기반 조회는 모두 -1을 반환합니다. `AddOnce`는 내부적으로 `repeat = 1`이며, 한 번 트리거되면 즉시 소멸됩니다; `repeat = 0`은 무한 반복을 의미합니다.

```csharp
if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)

**복구 방법**: 이는 설계된 동작이며 버그가 아닙니다. 주기적으로 트리거해야 한다면 `repeat = 0`을 전달하세요; 일회성 작업 종료 후의 -1은 정상이며, 이전 ID를 재사용하지 말고 다시 `Add`하여 새 ID를 얻으면 됩니다.

### 4. `Pause`된 후 복구되지 않음

`Pause(id)`는 `IsPaused = true`로 설정하며, 이후 `Update`는 곧바로 `continue`되어 시간이 누적되지 않고 콜백도 트리거되지 않지만, 타이머는 여전히 `_items`에 남아 있습니다(`Exists(id)`는 여전히 true). `Resume(id)`는 `IsPaused`를 다시 false로 설정하고 카운트를 이어갑니다:

```csharp
if (timerItem.IsPaused)
{
    continue;
}
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L75-L78)

**복구 방법**: `Resume(id)`를 호출하세요; `Pause`만 하고 `Resume`하지 않는 코드 경로가 없는지 확인하세요. Inspector나 로그로 현재 일시정지된 타이머가 있는지 확인할 수 있습니다.

### 5. `Scaled` 모드이고 `Time.timeScale`이 0인 경우

시간 소스는 `TimeScaleMode`에 따라 선택되며 기본값은 `Unscaled`입니다(`timeScale`의 영향을 받지 않음); 등록 시 `TimerTimeScale.Scaled`를 전달했다면, 게임 일시정지(`Time.timeScale = 0`) 시 delta가 0이 되어 타이머가 절대 트리거 조건에 도달하지 않습니다:

```csharp
// Select time source based on TimeScaleMode
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L80-L81)

**복구 방법**: UI, 접속 끊김 후 재연결 등 일시정지 중에도 실행되어야 하는 로직은 기본값인 `Unscaled`를 유지하며 `timeScale` 매개변수를 전달하지 마세요; 게임과 함께 일시정지되어야 하는 경우에만 `TimerTimeScale.Scaled`를 전달하도록 확인하세요.

### 6. 동일한 콜백 반복 등록으로 인한 카운트 초기화

내부적으로는 콜백 델리게이트가 딕셔너리 키로 사용됩니다. 이미 존재하는 콜백에 대해 다시 `Add`하면 새 타이머가 생성되지 않고 제자리에서 초기화(`Elapsed = 0`)되며 이전 ID를 재사용합니다——일반적으로 “첫 번째 타이머가 이유 없이 처음부터 다시 카운트하는” 현상으로 나타납니다:

```csharp
// Re-add existing callback: update in-place
if (_items.TryGetValue(callback, out var t))
{
    UpdateTagIndex(t, tag);
    t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete);
    t.Elapsed = 0;
    t.Deleted = false;
    t.IsPaused = false;
    return t.Id;
}
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L236)

**복구 방법**: 동일한 객체의 여러 타이머는 각각 독립적인 메서드나 람다를 사용하세요(각 람다는 서로 다른 델리게이트 인스턴스임); 매개변수를 업데이트해야 할 때는 이 “재등록 시 초기화” 동작을 의도적으로 활용할 수 있습니다.

### 7. 콜백이 예외를 던져 이후 콜백이 실행되지 않음

콜백은 락 외부에서 일괄 분배됩니다. `TimerManager.CatchCallbackExceptions`의 기본값은 `false`이며, 어떤 콜백이 던진 예외는 이번 for 루프를 중단시켜 같은 프레임에서 뒤에 오는 콜백이 모두 실행되지 않습니다. 이를 `true`로 설정하면 예외를 캐치하여 `Timer callback error > {message}`만 출력합니다:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L172-L186)

**복구 방법**: 문제 해결 기간에는 `TimerManager.CatchCallbackExceptions = true`로 설정하고 경고를 관찰하여 예외를 던지는 콜백을 찾으세요; 근본 원인을 복구한 후에는 예외를 집어삼키지 않도록 기본값으로 되돌리는 것을 권장합니다.

## 검증

위의 복구 작업을 수행한 후, 다음 항목을 하나씩 확인하세요:

1. `Add`가 0이 아닌 ID를 반환하며, `Exists(id)`가 true입니다(등록 성공, “아직 반영되지 않은” 단계 포함).
2. 한 프레임 기다린 후 `GetRemaining(id)` / `GetElapsed(id)`를 조회하면 더 이상 -1이 반환되지 않고 값이 시간이 지남에 따라 진행됩니다.
3. `interval`에 도달하면 콜백이 호출됩니다; `GetRepeatLeft(id)`가 0을 반환하면 무한 반복이며, 그 외 양수는 남은 횟수입니다.
4. `Pause(id)` 후에는 `GetElapsed(id)`가 더 이상 증가하지 않고, `Resume(id)` 후에 다시 증가합니다.
5. `TimerManager.CatchCallbackExceptions = true`로 설정한 후 `Timer callback error >` 경고가 없으면 예외를 던지는 콜백이 없다는 뜻입니다.
