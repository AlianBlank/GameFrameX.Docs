# Custom Message Serialization and Compression

By implementing `IMessageSerializer` and registering it via `MessageSerializerRegistry.RegisterGlobal()`, you can replace the network layer's message encoding/decoding with your own solution (Protobuf, JSON, MemoryPack, etc.); compression and decompression are replaced by implementing the `IMessageCompressHandler` / `IMessageDecompressHandler` interfaces. When no serializer is registered, the framework throws a clear exception.

## Prerequisites

- The `com.gameframex.unity.network` package has been installed and the network components have been configured.
- Custom message types must inherit from `MessageObject` (required by the generic constraint on the serialization method).

## Core Interface Overview

| Name | Actual Signature | Description |
|------|----------|------|
| `IMessageSerializer.Serialize<T>` | `byte[] Serialize<T>(T message) where T : MessageObject` | Serializes the message object |
| `IMessageSerializer.Deserialize` | `object Deserialize(byte[] data, Type targetType)` | Deserializes into the target message type |
| `IMessageCompressHandler.Handler` | `byte[] Handler(byte[] message)` | Compresses message data |
| `MessageSerializerRegistry.RegisterGlobal` | `void RegisterGlobal(IMessageSerializer serializer)` | Registers the global serializer |
| `MessageSerializerRegistry.Global` | `IMessageSerializer Global { get; }` | Gets the global serializer; returns the fallback implementation when nothing is registered |
| `MessageSerializerRegistry.Reset` | `void Reset()` | Resets to the default fallback implementation |

The complete definition of the compression interface is as follows; the decompression interface `IMessageDecompressHandler` exists as its counterpart:

1. **Implement a custom serializer**: Create a new class implementing `IMessageSerializer` and fill in both the `Serialize<T>` and `Deserialize` methods. Use the default implementation's signatures as the reference:

```csharp

{
    // TODO: Call your chosen serialization library here

}

public object Deserialize(byte[] data, Type targetType)

    // TODO: Call your chosen deserialization library here

}
```

Source: [DefaultMessageSerializer.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageSerializer.cs#L33-L55)

2. **Register as the global serializer**: During the game initialization phase (before creating network channels), call the registry and pass in your implementation instance:

```csharp
public static void RegisterGlobal(IMessageSerializer serializer)
{
    if (serializer == null)
    {
        throw new ArgumentNullException(nameof(serializer));
    }
    _global = serializer;
}
```

Source: [MessageSerializerRegistry.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/MessageSerializerRegistry.cs#L35-L42)

In other words, a single line on the business side — `MessageSerializerRegistry.RegisterGlobal(new MyProtobufSerializer());` — completes the integration.

3. **Implement the compression and decompression handlers**: Implement `IMessageCompressHandler` and `IMessageDecompressHandler` respectively, returning the compressed/decompressed byte array in `Handler(byte[] message)`. The framework ships with default implementations `DefaultMessageCompressHandler` and `DefaultMessageDecompressHandler` (located in `Runtime/Network/Helper/`), which can serve as references for customization. No separate registration entry point for the compressor was found within the scope of this source-code verification; refer to the callers of the default implementations mentioned above to confirm the replacement approach.

4. **Verify**: Send a custom message and print the received fields on the peer side to confirm that the serialization and compression pipeline is working.

## Common Errors

| Symptom/Error Message | Cause | Fix |
|------|------|------|
| `InvalidOperationException: No IMessageSerializer registered. Call MessageSerializerRegistry.RegisterGlobal() or provide a channel-level serializer.` | No serializer has been registered; the global falls back to `DefaultMessageSerializer`, whose methods always throw this exception | Call `MessageSerializerRegistry.RegisterGlobal(...)` during initialization, or provide a channel-level serializer for the channel |
| `ArgumentNullException` (parameter name `serializer`) | `null` was passed to `RegisterGlobal` | Pass a non-null implementation instance |
| Old logic still runs after registration | Registration happened after the first message send/receive | Move registration to before network channels are created; if necessary, call `MessageSerializerRegistry.Reset()` and then re-register |

## Background

`MessageSerializerRegistry` internally holds the global instance in a `volatile` field; the `Global` property returns `DefaultMessageSerializer.Instance` as a fallback when nothing is registered. This fallback implementation's method bodies contain nothing but a throw statement, specifically designed to prompt users to register a real serializer — therefore "forgetting to register" surfaces as a clear error on the first message send/receive rather than failing silently.
