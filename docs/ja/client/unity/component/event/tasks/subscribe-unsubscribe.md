# イベントの購読と購読解除の方法

シーン内の `EventComponent`(メニュー `GameFrameX/Event`)を通じてイベントを購読します。`CheckSubscribe(id, handler)` を呼び出して購読を完了し、`Unsubscribe(id, handler)` または `CheckUnsubscribe(id, handler)` を呼び出して購読を解除します。ハンドラーのシグネチャは `EventHandler<GameEventArgs>` で、イベント ID の `id` は `string` です。

## 前提条件

- シーンに GameFrameX エントリーが既に存在し、`EventComponent` コンポーネント(`[AddComponentMenu("GameFrameX/Event")]`)がアタッチされていること。
- カスタムイベント引数が必要な場合は、`GameEventArgs` を継承した引数クラスを用意します。引数なしのイベントは `string` のイベント ID をそのまま使用できます。

## 購読と購読解除に関する API

| メソッド | 実際のシグネチャ | 動作 |
|------|----------|------|
| `EventComponent.CheckSubscribe` | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 未購録の場合のみ購読し、安全に重複呼び出し可能 |
| `EventComponent.Unsubscribe` | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 購読解除(マネージャーへ直接転送) |
| `EventComponent.CheckUnsubscribe` | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | handler が存在しない場合は何もしない |
| `EventComponent.Check` | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 該当ハンドラー関数が存在するかを確認 |
| `EventComponent.Count` | `int Count(string id)` | 該当イベント ID 配下のハンドラー関数の数 |
| `IEventManager.Subscribe` | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | マネージャー層のネイティブな購読であり、重複排除は行わない |

コンポーネント上のメソッドはすべて `IEventManager` への転送であり、`CheckSubscribe` の実際の実装は「まず `Check` してから `Subscribe` する」です:

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

## 操作手順

1. スクリプト内に `EventComponent` への参照を保持します(Inspector によるシリアライズ参照、またはシーン内のコンポーネントの検索)。コンポーネントは `Awake` 内で自動的に `IEventManager` モジュールを取得します:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

2. イベントハンドラー関数を作成します。シグネチャは必ず `void (object sender, GameEventArgs e)`、すなわち `EventHandler<GameEventArgs>` である必要があります。カスタム引数クラスは `GameEventArgs`(それ自体は空の抽象基底クラスで、`BaseEventArgs` を継承)を直接継承します:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class GameEventArgs : BaseEventArgs
{
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

3. 初期化のタイミング(`OnEnable` など)でイベントを購読します。重複購読を避けるため、`CheckSubscribe` の使用を推奨します:`m_EventComponent.CheckSubscribe("Player.HealthChanged", OnHealthChanged);`。
4. 破棄/無効化のタイミング(`OnDisable`/`OnDestroy` など)で購読を解除します:`m_EventComponent.CheckUnsubscribe("Player.HealthChanged", OnHealthChanged);`。対応する実装:

```csharp
public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.Unsubscribe(id, handler);
}

public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L118-L131)

5. ハンドラー関数内部では、必要に応じて `e` をカスタム引数型にキャストしてからデータを読み取ります。購読解除後は、`m_EventComponent.Check(id, handler)` が `false` を返すこと、`Count(id)` が `0` を返すことで、購読が解除されたことを検証できます。

## よくあるバリエーション

- **重複初期化のケース**:同じロジックに複数回入る場合は `CheckSubscribe` / `CheckUnsubscribe` をそのまま使用します。両者とも内部でまずチェックしてから実行するため、重複呼び出ししてもエラーにはなりません。`CheckUnsubscribe` の実装は、マネージャー層で `handler` が存在しないと判断された場合に何もしないものです:

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (m_EventPool.Check(id, handler))
    {
        m_EventPool.Unsubscribe(id, handler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L140-L146)

- **引数なしイベント**:イベント ID だけが必要でデータを持たせる必要がない場合は、`Fire(object sender, string eventId)` で文字列を直接発火できます。コンポーネント内部で `EmptyEventArgs` が自動的に作成されます:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`EmptyEventArgs.Create` は参照プールからオブジェクトを取得し、イベント ID を設定します:

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

- **フォールバック処理**:`SetDefaultHandler(EventHandler<GameEventArgs> handler)` を呼び出してデフォルトのイベントハンドラー関数を設定し、購読者のいないイベントを受け取れるようにします。

## よくあるエラー

| エラー | 原因 | 修正 |
|------|------|------|
| コンポーネントの初期化に失敗し、ログに `Event manager is invalid.` が出力される | シーンに利用可能な `IEventManager` モジュールがない、または GameFrameX エントリーが初期化されていない | シーンに GameFrameX エントリーが存在し、`EventComponent` がアタッチされていることを確認する |
| 同じハンドラーが複数回発火される | `IEventManager.Subscribe`(重複排除なし)を使用して重複呼び出しした | `EventComponent.CheckSubscribe` に切り替える |
| 購読解除時にエラーが発生する | 未購読の `handler` を渡した、または `id` が一致しない | `EventComponent.CheckUnsubscribe` に切り替える |
| ハンドラー関数のシグネチャが一致しない | `EventHandler<GameEventArgs>`(`void (object, GameEventArgs)`)を使用していない | このシグネチャに従ってハンドラー関数を作成する |
| イベントの発火タイミングが想定と異なる | `Fire` はスレッドセーフだがイベントは次のフレームでディスパッチされ、`FireNow` は即時にディスパッチされるがスレッドセーフではない | 必要に応じて `Fire` / `FireNow` を選択する |

## 背景

`EventComponent` は Unity シーン上のファサードコンポーネントであり、すべての購読 API は `IEventManager`(`EventManager`)へ転送され、後者がさらに内部の `m_EventPool` に委譲して実際のイベントプールの管理を行います。そのため、呼び出し側は `EventComponent` の `Subscribe`/`Unsubscribe`/`Check` のセマンティクスだけを扱えばよく、低層のイベントプールを意識する必要はありません。
