# インストールして最初のイベントを動かす

このページでは、ゼロから完了までを案内します:`com.gameframex.unity.event` パッケージのインストール → `EventComponent` コンポーネントの追加 → イベント引数クラスの定義 → 購読 → イベントの発火 → Console でのコールバック出力確認。すべてそのまま写すれば動作します。

## 前提条件

- Unity 2019.4 以上(README のバッジ説明を参照)。
- プロジェクトに GameFrameX ランタイム基礎パッケージが導入済みであること(`EventComponent` は `GameFrameworkComponent` を継承し、`GameFrameX.Runtime` 名前空間を参照します)。
- 本パッケージ自体には他の依存関係はありません。

## 手順

### 1. パッケージをインストールする

どちらかの方法で Unity プロジェクトの `Packages/manifest.json` を編集します:

**方法 A:Scoped Registry(推奨)**

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.event": "1.1.1"
  }
}
```

`scopes` はどのパッケージをこのレジストリ経由で解決するかを制御します。`com.gameframex` で始まるパッケージのみがこのレジストリから取得されます。

**方法 B:Git URL 直接依存**

```json
{
   "com.gameframex.unity.event": "https://github.com/gameframex/com.gameframex.unity.event.git"
}
```

Unity の `Packages Manager` で `Git URL` 方式でアドレス `https://github.com/gameframex/com.gameframex.unity.event.git` を追加することもできますし、リポジトリを直接ダウンロードしてプロジェクトの `Packages` ディレクトリに置けば自動認識されます。

出典： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L40-L69)

### 2. EventComponent コンポーネントを追加する

`EventComponent` はイベントシステムの Unity エントリポイントで、コンポーネントメニュー **Component → GameFrameX → Event** から追加します(メニューパスは `[AddComponentMenu("GameFrameX/Event")]` で定義されています)。`[GameFrameXAutoComponent(-7000)]` 属性を持つため、GameFrameX の完全な起動フローでは自動生成されます。任意の常駐 GameObject に手動でアタッチしても同様に使用できます。コンポーネントは `Awake` 内で `GameFrameworkEntry.GetModule<IEventManager>()` によってマネージャーインスタンスを取得し、失敗した場合は `Log.Fatal("Event manager is invalid.")` を出力して動作を停止します。

出典： [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L77)

### 3. イベント引数クラスを定義する

各イベントは `GameEventArgs` を継承したクラスで扱い、文字列の `Id` でイベントの種類を識別します:

```csharp
public class LevelUpEventArgs : GameEventArgs
{
    public override string Id => "level_up";
    public int Level { get; private set; }

    public static LevelUpEventArgs Create(int level)
    {
        var args = ReferencePool.Acquire<LevelUpEventArgs>();
        args.Level = level;
        return args;
    }

    public override void Clear()
    {
        base.Clear();
        Level = 0;
    }
}
```

出典： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L75-L94)

`GameEventArgs` は `GameFrameX.Event.Runtime` 名前空間の抽象基底クラスです(`BaseEventArgs` を継承)。カスタムイベントは必ずここから派生させてください:
[GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L30-L40)

### 4. イベントを購読して発火する

新しいテストスクリプトを作成してシーンにアタッチします。コールバックのシグネチャは `void(object sender, GameEventArgs e)`、すなわち `EventHandler<GameEventArgs>` に固定されます:

```csharp
using GameFrameX.Event.Runtime;
using UnityEngine;

public class FirstEventDemo : MonoBehaviour
{
    private EventComponent m_EventComponent;

    private void Start()
    {
        m_EventComponent = GetComponent<EventComponent>();
        if (m_EventComponent == null)
        {
            m_EventComponent = FindObjectOfType<EventComponent>();
        }

        // 購読:存在しない場合は自動で購読され、重複呼び出しも安全
        m_EventComponent.CheckSubscribe("level_up", OnLevelUp);

        // イベント発火:遅延モード、次のフレームでメインスレッドからコールバック
        m_EventComponent.Fire(this, LevelUpEventArgs.Create(5));
    }

    private void OnLevelUp(object sender, GameEventArgs e)
    {
        var args = (LevelUpEventArgs)e;
        Debug.Log($"レベル {args.Level} にアップしました");
    }

    private void OnDestroy()
    {
        // 存在する場合は安全に購読解除、handler が存在しない場合は何もしない
        m_EventComponent.CheckUnsubscribe("level_up", OnLevelUp);
    }
}
```

出典： [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L95-L131) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L96-L128)

### 5. 検証

シーンを実行すると、Console に `レベル 5 にアップしました` と出力されるはずです。`Fire` は遅延配信である点に注意してください。イベントは発火後の**次のフレーム**でコールバックされるため、そのフレームでログが見えない場合は、1フレーム待ってから判断してください。

## よくあるバリエーション

**即時配信 `FireNow`**:イベントを即座に同期的に配信しますが、**スレッドセーフではありません**。メインスレッドからのみ呼び出してください。

```csharp
m_EventComponent.FireNow(this, LevelUpEventArgs.Create(5));
```

出典： [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

**カスタム引数なしの簡易発火**：データを携える必要がない場合は、文字列のイベント ID をそのまま使えます。内部では `EmptyEventArgs` が生成されます:

```csharp
m_EventComponent.Fire(this, "level_up");
```

出典： [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

**デフォルトハンドラーによるフォールバック**:未購読のイベントに対するフォールバックコールバックを設定します。「イベントを発火したのに誰も受け取らない」問題の切り分けによく使われます:

```csharp
m_EventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未処理のイベント: {e.Id}");
}
```

出典： [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L133-L140) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L142-L151)

**統計情報**:`Count(id)` で個別イベントのハンドラー数を、`EventHandlerCount` / `EventCount` でグローバルな数を取得できます。
出典： [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) · [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L87)

## よくあるミス

| 症状 | 原因 | 回避方法 |
|------|------|----------|
| Console に `Event manager is invalid.`(Fatal)が出る | コンポーネントが `GameFrameworkEntry.GetModule<IEventManager>()` でマネージャーを取得できなかった。多くは GameFrameX ランタイム基礎パッケージが準備できていない | まず GameFrameX ランタイムパッケージがインストールされ正常に初期化されていることを確認してから、`EventComponent` をアタッチする |
| `Fire` 後に同じフレームでコールバックが来ない | `Fire` は遅延配信であり、イベントは発火後の次のフレームでメインスレッドからコールバックされる | 期待される挙動です。即座に同期的なコールバックが必要な場合は `FireNow` を使う |
| 子スレッドからイベントを発火した後に動作が異常になる | 非メインスレッドから `FireNow` を呼び出した | 子スレッドでは `Fire` のみ使用可能(スレッドセーフ) |
| イベント引数に古いデータが入っている | カスタムイベント引数で `Clear()` のオーバーライドを忘れてフィールドをリセットしておらず、プーリングされたインスタンスを再利用する際に古い値が残った | 手順 3 のサンプルに倣い、`Clear()` 内でフィールドを1つずつリセットする |
| 同じコールバックが重複購読される | 複数箇所で `Subscribe` を呼び出し、存在チェックをしていない | `CheckSubscribe`(存在しない場合のみ購読)/ `CheckUnsubscribe`(存在する場合のみ解除)を使うか、先に `Check` してから操作する |
