# 통계 Provider 추가 및 구성 방법

`GameAnalyticsComponent` 컴포넌트의 Inspector에서 `IGameAnalyticsManager`를 구현한 타입을 「게임 데이터 분석 컴포넌트 목록, 순서대로 보고」에 추가하고, 각 항목에 `Setting` 키-값 쌍을 입력합니다. 런타임에 컴포넌트는 리플렉션을 통해 모든 Provider를 자동으로 인스턴스화하고 해당 `Init`을 호출하며, 이후 모든 보고 인터페이스는 목록 순서대로 각 Provider에 전달됩니다.

## 사전 조건

- 이 패키지 `com.gameframex.unity.gameanalytics`가 설치되어 있어야 합니다.
- 씬에 `GameAnalyticsComponent`가 이미 존재해야 합니다(`Add Component → Game Framework → GameAnalytics`를 통해 추가 가능).
- 씬에 `IGameAnalyticsManager` 인터페이스를 구현한 통계 구현 클래스가 최소 하나 이상 있어야 합니다(보통 각 서드파티 SDK 어댑터 패키지에서 제공). 그렇지 않으면 Inspector의 드롭다운 목록에 None만 표시됩니다.

## 작업 단계

1. `GameAnalyticsComponent`가 붙어 있는 GameObject를 선택하면, Inspector에서 `GameAnalyticsComponentInspector`가 「게임 데이터 분석 컴포넌트 목록, 순서대로 보고」라는 제목의 정렬 가능한 목록을 그립니다.

2. 목록 오른쪽 하단의 `+`를 클릭하여 새 항목을 추가합니다. 각 항목은 하나의 `GameAnalyticsComponentProvider`에 해당하며, 직렬화 필드는 다음과 같습니다:

| 필드 | 타입 | 설명 |
|------|------|------|
| `ComponentType` | `string` | `IGameAnalyticsManager`를 구현한 타입의 전체 이름, 드롭다운 박스에서 자동으로 기록됨 |
| `ComponentTypeNameIndex` | `int` | 에디터 드롭다운 박스의 현재 인덱스, 런타임에는 사용되지 않음 |
| `Setting` | `List<GameAnalyticsComponentParamKV>` | 해당 Provider에 전달되는 초기화 파라미터, 각 항목은 `Key`/`Value` 문자열 쌍 |

```csharp
[Serializable]
public class GameAnalyticsComponentProvider
{
    /// <summary>
    /// 구현 컴포넌트 타입
    /// </summary>
    public string ComponentType;

    /// <summary>
    /// 이것은 에디터용입니다
    /// </summary>
    public int ComponentTypeNameIndex = 0;

    /// <summary>
    /// 파라미터
    /// </summary>
    public List<GameAnalyticsComponentParamKV> Setting = new List<GameAnalyticsComponentParamKV>();
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L361-L378)

3. `ComponentType` 드롭다운 박스에서 대상 구현 클래스를 선택합니다. 드롭다운 항목은 Inspector가 리플렉션을 통해 모든 `IGameAnalyticsManager`의 런타임 타입을 수집하여 생성하며, 선택하면 타입 이름이 `ComponentType` 문자열에 기록됩니다:

```csharp
managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

4. `Setting`에 해당 Provider에 필요한 초기화 파라미터를 입력합니다(예: AppKey, Channel 등 구체적인 SDK 구현에서 정의한 키). 구현 어셈블리에 `BaseGameAnalyticsSetting`을 상속하는 클래스가 존재하면, Inspector가 해당 공용 필드를 기준으로 Setting 항목을 자동으로 채워주므로 Value만 입력하면 됩니다:

```csharp
var types = type.Assembly.GetTypes();
foreach (var typeImpl in types)
{
    if (typeImpl.BaseType != typeof(BaseGameAnalyticsSetting))
    {
        continue;
    }

    var fieldInfos = typeImpl.GetFields();
    ...
}
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L148-L158)

5. Play 모드에 진입합니다. 컴포넌트는 `OnEnable`에서 `Init()`을 호출하여 각 항목에 대해 리플렉션으로 인스턴스를 생성하고 `Setting`을 딕셔너리로 변환하여 전달합니다:

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L79)

6. 목록의 드래그 핸들을 이용하여 순서를 조정합니다. 순서는 전달 순서에만 영향을 미치며 기능에는 영향을 주지 않습니다. `Init`과 이후 모든 보고 호출은 목록 순서대로 실행됩니다.

## 일반적인 변형

- **로그인 후 추가 초기화가 필요한 SDK**: 일부 Provider는 `IsManualInit()`를 구현하여, 사용자 정보를 받은 후 컴포넌트의 `ManualInit(Dictionary<string, string> extraArgs)`를 호출하면 컴포넌트가 `extraArgs`를 수동 초기화가 필요한 모든 Provider에 전달합니다:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

- **플레이어 ID / 공용 속성 설정**: `SetPlayerId(string playerId)`, `SetPublicProperties(string key, object value)`, `ClearPublicProperties()`를 호출하면 목록의 모든 Provider에 동기적으로 전달되므로 하나씩 호출할 필요가 없습니다.
- **커스텀 Provider**: 새 클래스를 만들어 `IGameAnalyticsManager`를 구현합니다(인터페이스 정의는 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8) 참조). 매개변수 없는 생성자를 반드시 제공해야 합니다(컴포넌트가 `Activator.CreateInstance`로 인스턴스화함). Inspector가 Setting 키를 자동으로 생성하게 하려면, 같은 어셈블리에 `BaseGameAnalyticsSetting`을 상속하는 클래스를 정의하고 공용 필드로 각 설정 항목을 선언하면 됩니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 로그 `Can not find component type 'XXX'.`가 출력되고 해당 항목이 건너뛰어짐 | `ComponentType` 타입 이름을 `Utility.Assembly.GetType`으로 해석할 수 없음: 구현 클래스가 있는 어셈블리가 빌드에 포함되지 않았거나 직렬화 값을 수동으로 수정함 | 구현 패키지가 포함되어 있는지 확인하고 Inspector 드롭다운 박스에서 타입을 다시 선택 |
| 로그 `GameAnalyticsManager is not init.` | 컴포넌트가 `Init`되지 않은 상태에서 보고 인터페이스를 호출함(예: 컴포넌트가 비활성화되어 `OnEnable`이 실행되지 않음) | `GameAnalyticsComponent`가 활성화 상태인지 확인; 필요시 수동으로 `Init()` 호출 |
| 특정 항목이 오류 없이 조용히 무시됨 | `ComponentType`가 비어 있어 `Init` 내 `IsNotNullOrWhiteSpace` 검사를 통과하지 못하고 바로 건너뜀 | 해당 항목의 드롭다운 박스에서 구현 타입 선택 |
| `ManualInit` 호출이 효과가 없음 | `m_IsInit`이 false일 때 `ManualInit`이 바로 return됨; 또는 해당 Provider의 `IsManualInit()`가 false를 반환함 | Play 후 `Init`이 트리거되었는지 먼저 확인한 후, 구현의 `IsManualInit` 로직 확인 |
| Inspector 설정을 수정한 후에도 실행 시 여전히 이전 설정이 사용됨 | `Init`이 `m_IsInit`로 보호되어 첫 번째 호출에만 적용됨 | Play 모드를 재시작; 실행 중 `Init`을 반복 호출하는 것이 적용되기를 기대하지 마세요 |

## 검증

- Play 후 Console에 `Can not find component type` 오류가 없으면 모든 항목의 타입 해석이 성공한 것입니다.
- `SetPlayerId` 등 전달 인터페이스를 호출할 때 `GameAnalyticsManager is not init.` 경고가 없으면 Provider 목록 초기화가 완료된 것입니다.
- 각 Provider 구현의 `Init(Dictionary<string, string>)` 내에 중단점을 설정하거나 로그를 추가하여 `Setting`의 키-값이 설정대로 전달되었는지 확인합니다.

## 배경

컴포넌트는 어떠한 구체적인 SDK에도 직접 의존하지 않습니다. `Init` 시 리플렉션으로 `ComponentType`에 따라 인스턴스를 생성하고, `Setting` 목록을 `Dictionary<string, string>`으로 변환하여 `Init(args)`에 전달하며, 이후 모든 공용 인터페이스(set/보고 등)는 `m_GameAnalyticsManager`를 순회하며 하나씩 전달합니다. 이를 통해 여러 통계 SDK가 동시에 순서대로 보고되도록 구현됩니다.
