# 工作原理:线程安全更新循环与对象池

`TimerManager` 在每帧 `Update` 中用一个全局锁(`Locker`)串行完成"扫描活动定时器 → 回收到期项 → 合并新增项"三段式更新;所有到期回调先收集到 `_pendingCallbacks`,在锁外统一执行,避免回调里再调 Add/Remove 造成死锁;被移除的 `TimerItem` 不销毁,而是清空引用后压回 `Stack<TimerItem>` 对象池复用。

## 核心数据结构速查

| 成员 | 真实类型/默认值 | 作用 |
|------|-----------------|------|
| `_items` | `Dictionary<Action<object>, TimerItem>` | 活动定时器表,**以回调委托为 key**(同一回调只能有一个定时器) |
| `_toAdd` | `Dictionary<Action<object>, TimerItem>` | 待合并的新增定时器,`Add()` 先写这里,帧末并入 `_items` |
| `_toRemove` | `List<TimerItem>` | 待回收项,Update 中统一清理 |
| `_pool` | `Stack<TimerItem>`,初始容量 100 | `TimerItem` 对象池,回收复用 |
| `_pendingCallbacks` | `List<(Action<object> Callback, object Param)>` | 本帧到期回调缓存,锁外执行 |
| `_ids` | `Dictionary<int, Action<object>>` | 定时器 ID → 回调 的索引 |
| `_tags` | `Dictionary<string, List<int>>` | 标签 → ID 列表 的分组索引 |
| `_nextId` | `int`,从 1 自增 | ID 分配器 |
| `Locker` | `static readonly object` | 全局锁对象,所有读写路径共用 |
| `CatchCallbackExceptions` | `static bool`,默认 `false` | 为 `true` 时回调异常被吞掉并仅打印警告 |

## 每帧更新循环

`Update(float elapseSeconds, float realElapseSeconds)` 继承自 `GameFrameworkModule`,每帧被框架驱动一次,整个状态扫描在 `lock (Locker)` 内完成:

1. **跳过已删除与已暂停项**:`Deleted` 的项进 `_toRemove`;`IsPaused` 的项跳过累计但仍留在 `_items`。
2. **按时间缩放模式选时间源**:`TimerTimeScale.Scaled` 用 `elapseSeconds`,否则用 `realElapseSeconds`。
3. **逐帧定时器**(interval <= 0)不累计时间,当帧直接触发。
4. **普通定时器**累计 `Elapsed`,`Elapsed >= Interval` 时减去 `Interval` 并入 `_pendingCallbacks`。
5. **重复次数扣减**:`Repeat > 0` 时每次触发 `Repeat--`,减到 0 标记 `Deleted` 并进 `_toRemove`。
6. **回收**:遍历 `_toRemove`,触发 `OnComplete`,从 `_items`/`_ids`/`_tags` 摘除,归还对象池。
7. **合并**:把 `_toAdd` 并入 `_items` 并清空。

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    lock (Locker)
    {
        if (_items.Count > 0)
        {
            var enumerator = _items.GetEnumerator();
            while (enumerator.MoveNext())
            {
                var timerItem = enumerator.Current.Value;
                if (timerItem.Deleted)
                {
                    _toRemove.Add(timerItem);
                    continue;
                }

                // Paused timer: skip elapsed accumulation but remain in _items
                if (timerItem.IsPaused)
                {
                    continue;
                }

                // Select time source based on TimeScaleMode
                float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

时间累计与触发判定(`Elapsed` 余量超过 0.03 秒会被钳到 0,防止卡顿后连发):

```csharp
timerItem.Elapsed += delta;

{
    continue;
}

    timerItem.Elapsed = 0;

if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}

{
    _pendingCallbacks.Add((timerItem.Callback, timerItem.Param));
}
```

## 回调在锁外执行(线程安全的关键)

`_pendingCallbacks` 的执行在 `lock` 块**之外**。这是刻意设计:回调内部如果再调用 `Add`/`Remove`/`Exists`(它们各自会 `lock (Locker)`),在锁内执行将直接死锁——C# 的 `lock`/Monitor 对同一线程可重入,但真正的风险在于长时间持有锁阻塞其他线程(如异步/后台线程的续体)。把回调挪到锁外后,回调里可以安全地增删定时器。

```csharp
// Execute callbacks outside lock to avoid blocking other threads
if (_pendingCallbacks.Count > 0)
{
    for (int i = 0; i < _pendingCallbacks.Count; i++)
    {
        var (callback, param) = _pendingCallbacks[i];
        if (CatchCallbackExceptions)
        {
            try
            {
                callback(param);
            }
            catch (Exception e)
            {
                Debug.LogWarning("Timer callback error > " + e.Message);
            }
        }
        else
        {
            callback(param);
        }
    }

    _pendingCallbacks.Clear();
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L166-L190)

注意:回调执行时若抛异常且 `CatchCallbackExceptions == false`(默认),异常会向上传播,`_pendingCallbacks` 不会清空——后续帧该列表会继续被追加,可能重复执行同一批回调。建议在游戏初始化时把 `TimerManager.CatchCallbackExceptions = true` 打开。

## 对象池:GetFromPool / ReturnToPool

`TimerItem` 是私有嵌套类,取用时优先从 `_pool` 弹出并复位全部运行态字段,池空才 `new`;归还时清空所有委托与参数引用后压回,防止对象泄漏(Object Retention)。

```csharp
private TimerItem GetFromPool()
{
    TimerItem t;
    if (_pool.Count > 0)
    {
        t = _pool.Pop();
        t.Deleted = false;
        t.Elapsed = 0;
        t.IsPaused = false;
        t.PausedElapsed = 0;
        t.TimeScaleMode = TimerTimeScale.Unscaled;
        t.Tag = null;
        t.OnComplete = null;
    }
    else
    {
        t = new TimerItem();
    }

    return t;
}

private void ReturnToPool(TimerItem t)
{
    t.Callback = null;
    t.Param = null;
    t.Tag = null;
    t.OnComplete = null;
    _pool.Push(t);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L623-L652)

归还入口有两处,均在锁内调用:

| 归还时机 | 位置 | 触发 `OnComplete`? |
|----------|------|---------------------|
| Update 回收到期/删除项(`Repeat` 用尽或标记 `Deleted`) | `Update` 内 `_toRemove` 清理循环 | 是,`i.OnComplete?.Invoke()` 在归还前调用 |
| `Remove(callback)` 命中还在 `_toAdd`、尚未合并的项 | `Remove(Action<object>)` | 是,先 `t.OnComplete?.Invoke()` 再归还 |

## Add 的三条路径

`Add(...)` 在 `lock` 内按以下顺序处理,同一次调用可能命中不同分支:

| 顺序 | 条件 | 行为 |
|------|------|------|
| 1 | `callback == null` | 打印警告 `timer callback is null, {interval},{repeat}`,返回 `0` |
| 2 | 回调已在 `_items` | **原位更新**:`Set(...)` 重设参数、`Elapsed = 0`、清除 `Deleted/IsPaused`,返回原 `Id` |
| 3 | 回调已在 `_toAdd` | 同样原位更新,返回原 `Id` |
| 4 | 全新回调 | `_nextId++` 分配 ID,`GetFromPool()` 取对象,写入 `_toAdd`/`_ids`/`_tags`,返回新 `Id` |

```csharp
int id = _nextId++;
t = GetFromPool();
t.Id = id;
t.Interval = interval;
t.Repeat = repeat;
t.Callback = callback;
t.Param = callbackParam;
t.Tag = tag;
t.TimeScaleMode = timeScale;
t.OnComplete = onComplete;
_toAdd[callback] = t;
_ids[id] = callback;
AddToTagIndex(t);
return id;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L260)

由于 key 是回调委托本身,**对同一个 lambda/方法重复 `Add` 不会产生第二个定时器**,而是重置已存在的那个——包括把 `Elapsed` 归零和解除暂停。

## Remove 的两段式

`Remove(callback)` 命中 `_toAdd` 时直接删除并归还对象池(该定时器从未进入扫描循环);命中 `_items` 时只做 `t.Deleted = true` 延迟标记,实际回收发生在下一帧 `Update` 的 `_toRemove` 清理循环。`Remove(int id)` 同理:先经 `_ids` 查到回调,再走相同逻辑。

```csharp
public void Remove(Action<object> callback)
{
    lock (Locker)
    {
        if (_toAdd.TryGetValue(callback, out var t))
        {
            _toAdd.Remove(callback);
            _ids.Remove(t.Id);
            RemoveFromTagIndex(t);
            t.OnComplete?.Invoke();
            ReturnToPool(t);
            return;
        }

        if (_items.TryGetValue(callback, out t))
        {
            t.Deleted = true;
        }
    }
}
```

## Shutdown 行为

`Shutdown` 在锁内清空 `_toRemove`、`_toAdd`、`_items`、`_ids`、`_tags`、`_pendingCallbacks`——注意**不归还对象到 `_pool`、不触发任何 `OnComplete`**,组件销毁后池对象随管理器一起释放。

## 外层组件与驱动方式

`TimerComponent` 是 Unity 侧的 `GameFrameworkComponent`,`Awake` 中通过 `GameFrameworkEntry.GetModule<ITimerManager>()` 拿到 `TimerManager` 实例,自身全部 API 仅做一行转发。真正的每帧驱动来自框架基类 `GameFrameworkModule` 对 `Update` 的调用,`TimerComponent` 上挂有 `[GameFrameXAutoComponent(-5000)]` 决定其自动注册顺序。

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");
        return;
    }
}
```
