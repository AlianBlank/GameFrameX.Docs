# 快速上手:从零启动 GameFrameX 服务器

本页带你用最少步骤把 GameFrameX Server 跑起来:准备好 .NET 10 与 MongoDB,选一种启动方式(Docker / 命令行 / Rider / Visual Studio),看到健康检查与测试接口返回正常即视为启动成功。

## 前置条件

| 依赖 | 版本要求 |
| :--- | :--- |
| [.NET SDK](https://dotnet.microsoft.com/download) | 10.0+ |
| [MongoDB](https://www.mongodb.com/try/download/community) | 4.x+ |
| IDE(可选) | Visual Studio 2022 / JetBrains Rider / VS Code |
| Docker(可选) | 用于一键启动或本地拉起 MongoDB |

源码根目录见 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L1-L150)。

## 操作步骤

### 方式 1:Docker 一键启动

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
docker compose up -d --build
```

适合不想装本地 .NET 10 SDK 的用户;Compose 会同时拉起 MongoDB 与服务器容器。

### 方式 2:命令行本地启动

1. 单独启动 MongoDB:

```bash
docker compose up -d mongodb
```

2. 编译并从输出目录启动 Launcher:

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
dotnet restore
dotnet build Server.sln
cd bin/app_debug
dotnet GameFrameX.Launcher.dll
```

`GameFrameX.Launcher.dll` 是框架的入口程序集,对应工程文件见 [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L1-L41)。其中 `Debug` 配置的 `OutputPath` 为 `bin\app_debug`,`Release` 为 `bin\app`。

### 方式 3:JetBrains Rider 调试

1. 打开 `Server.slnx`;如果 Rider 版本不支持 `.slnx`,再打开 `Server.sln`。
2. 启动 MongoDB:`docker compose up -d mongodb`。
3. 为 `GameFrameX.Launcher` 创建或编辑 `.NET Project` 运行配置。
4. `Working directory` 设置为 `$SolutionDir$/bin/app_debug`。
5. `Program arguments` 留空(默认配置见 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs))。
6. 点击 Debug。如果 `bin/app_debug` 不存在,先执行一次 `dotnet build Server.sln`。

### 方式 4:Visual Studio 调试

1. 打开 `Server.slnx`;如果 Visual Studio 版本不支持 `.slnx`,再打开 `Server.sln`。
2. 将 `GameFrameX.Launcher` 设为启动项目。
3. 启动 MongoDB:`docker compose up -d mongodb`。
4. `Working directory` 设置为解决方案目录下的 `bin\app_debug`。
5. `Command line arguments` 留空。
6. 按 F5 启动调试。首次调试前若输出目录不存在,先 Build Solution。

## 常见变体

需要覆盖默认配置(端口、数据库连接等)时,在命令行追加启动参数:

```bash
dotnet GameFrameX.Launcher.dll \
    --ServerId=1000 \
    --ServerType=Game \
    --IsEnableTcp=true \
    --InnerPort=29100 \
    --MetricsPort=29090 \
    --IsEnableHttp=true \
    --HttpPort=28080 \
    --IsEnableWebSocket=true \
    --WsPort=29110 \
    --HttpIsDevelopment=true \
    --MinModuleId=10 \
    --MaxModuleId=9999 \
    --TagName=GameFrameX \
    --DataBaseUrl="mongodb://localhost:27017" \
    --DataBaseName=gameframex
```

| 参数 | 含义 |
| :--- | :--- |
| `--ServerId` `--ServerType` | 服务器唯一编号与类型(如 Game) |
| `--IsEnableTcp` `--InnerPort` | TCP 内网端口开关 |
| `--IsEnableHttp` `--HttpPort` `--HttpIsDevelopment` | HTTP 监听与是否开发模式 |
| `--IsEnableWebSocket` `--WsPort` | WebSocket 监听开关 |
| `--MetricsPort` | Prometheus 指标与健康检查端口 |
| `--MinModuleId` `--MaxModuleId` | 业务模块 ID 区间 |
| `--TagName` | 启动标签,用于路由到 `AppStartUpGame` 等启动器 |
| `--DataBaseUrl` `--DataBaseName` | MongoDB 连接串与库名 |

本地调试时**保持参数留空**即可,默认值在 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs` 中。

## 验证部署

启动成功后,通过下列端点确认服务正常:

| 端点 | 地址 | 说明 |
| :--- | :--- | :--- |
| 健康检查 | `http://localhost:29090/health` | 服务健康状态 |
| 指标监控 | `http://localhost:29090/metrics` | Prometheus 指标 |
| 测试接口 | `http://localhost:28080/game/api/test` | HTTP 连通性测试 |

三项任意一项返回正常即表示框架已正确拉起。

## 常见错误

| 症状 | 原因 | 修复 |
| :--- | :--- | :--- |
| 启动报 MongoDB 连接失败 | 未启动 MongoDB 或连接串与库名错 | 先 `docker compose up -d mongodb`,或调整 `--DataBaseUrl` `--DataBaseName` |
| Rider / VS 调试找不到 `bin/app_debug` | 首次构建未执行 | 先 `dotnet build Server.sln`,再启动调试 |
| `Server.slnx` 打不开 | IDE 版本过旧 | 改用 `Server.sln` |
| 端口被占用 | 默认 28080 / 29090 / 29100 / 29110 已被占用 | 参照"常见变体"小节传参覆盖 |
| HTTP 测试接口 404 | 框架未启用 HTTP 或端口配置冲突 | 确认 `--IsEnableHttp=true --HttpPort=28080` 与启动器一致 |

## 背景(可选)

GameFrameX Server 采用 Actor 模型与状态/逻辑分离:持久化数据在 `GameFrameX.Apps`,业务逻辑在 `GameFrameX.Hotfix`,可在不停服的情况下热替换。启动器 `AppStartUpGame` 通过 `[StartUpTag(GameServerConst.Game.Name)]` 与 `--TagName` 参数匹配,完成网络协议、组件代理与配置表的装配。源码组织详见 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L180-L260)。
