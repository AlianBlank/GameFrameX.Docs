# FSM을 파괴하는 방법

`FsmManager`의 `DestroyFsm` 오버로드를 호출하면 유한 상태 머신을 파괴할 수 있습니다. 파괴 후 해당 FSM은 관리자에서 제거되고 파괴된 것으로 표시되며(`IsDestroyed == true`), 다음 Update 라운드에서는 더 이상驱动되지 않습니다.

## 사전 조건

- 프로젝트에서 `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IFsmManager>()`를 통해 `IFsmManager` 인스턴스를 이미取得한 상태(또는 `FsmComponent`를 통해取得).
- `CreateFsm`을 통해 대상 FSM을 이미 생성하고, 소유자 타입 `T`와 이름(`null`은 익명)을 기억하고 있을 것.

## 操作 단계

1. **소유자 타입별로 파괴(익명 FSM)**

   ```csharp
   IFsmManager fsmMgr = GameFrameX.Runtime.GameFrameworkEntry.GetModule<GameFrameX.Fsm.Runtime.IFsmManager>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>();
   ```

2. **소유자 타입 + 이름으로 파괴**

   ```csharp
   bool ok = fsmMgr.DestroyFsm<MyOwner>("BattleFsm");
   ```

3. **FSM 참조를 직접 전달하여 파괴**

   여전히 `IFsm<T>` 또는 `FsmBase` 핸들을 보유하고 있는 경우, 직접 전달할 수 있으며 제네릭과 이름을 다시 작성할 필요가 없습니다:

   ```csharp
   IFsm<MyOwner> fsm = fsmMgr.GetFsm<MyOwner>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>(fsm);   // 제네릭 오버로드
   bool ok2 = fsmMgr.DestroyFsm(fsm as FsmBase); // 비제네릭 오버로드
   ```

`DestroyFsm`의 반환값은 `bool`이며, 파괴 성공 여부를 나타냅니다. 존재하지 않는 FSM은 `false`를 반환합니다.

## 일반적인 변형

- **`FsmComponent`에서 파괴하기**: `FsmComponent`는 내부적으로 `IFsmManager`를 캡슐화하므로 `GameEntry.GetComponent<FsmComponent>().DestroyFsm<MyOwner>(name)` 형식을 직접 사용할 수 있습니다.
- **일괄 정리**: 관리자의 `Shutdown` 시 모든 FSM을 순회하며 `Shutdown()`을 호출하므로 수동으로 하나씩 파괴할 필요가 없습니다([FsmManager.cs#L138-L147](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L138-L147)).
- **존재 여부 검증**: 파괴 전에 `HasFsm<T>(name)`을 호출하여 중복 파괴로 인한 `false` 반환을 방지할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `DestroyFsm`이 `false`를 반환함 | 전달된 소유자 타입 또는 이름이 생성 시와 일치하지 않거나, FSM이 이미 파괴됨 | `HasFsm`으로 검증 후 파괴하거나, `FsmBase` 핸들을 직접 전달 |
| 파괴 후에도 Update 콜백을 받음 | 파괴는 지연되어生效되며, 이번 프레임의 Update는 이미 디스패치됨 | 다음 프레임에 다시 관찰; 관리자의 Update에서 `IsDestroyed == true`인 FSM은 건너뜀 |
| `DestroyFsm(typeof(T))`이 `GameFrameworkException("Owner type is invalid.")`을 던짐 | `null`을 전달함 | 제네릭 오버로드를 사용하거나, 직접 null 체크 |

## 검증

파괴 후 다음 방법 중 하나로 검증할 수 있습니다:

## 배경(선택 사항)

`FsmManager`는 내부적으로 `Dictionary<TypeNamePair, FsmBase>`로 FSM을 저장하며, Update 루프는 먼저 임시 목록을 복사한 후 순회합니다. 순회 시 `IsDestroyed == true`인 항목은 건너뛰므로, 중간에 파괴해도 이번 반복에는 영향을 주지 않습니다. 파괴는 `Shutdown()`을 통해 상태 리소스를 해제하고 딕셔너리에서 제거합니다.
