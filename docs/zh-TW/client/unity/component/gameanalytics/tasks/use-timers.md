# 如何使用計時器統計時長（開始 / 暫停 / 恢復 / 結束）

呼叫 `GameAnalyticsComponent`（或底層 `IGameAnalyticsManager`）上的四個計時介面即可完成一次完整的時長統計：`StartTimer` 開始、`PauseTimer` 暫停、`ResumeTimer` 恢復、`StopTimer` 結束並產出該事件的時長資料。四個介面都只接收一個參數 `eventName`（事件名稱），元件會把它轉發給所有已初始化的分析後端。

## 前置條件

- 場景中已掛載 `GameAnalyticsComponent`，並完成初始化（`Init` / `ManualInit`）。未初始化時計時呼叫會被靜默忽略，並可能輸出 `GameAnalyticsManager is not init.` 警告。
- 如需了解具體的初始化流程，請參閱元件對應的文件。

## 操作步驟

1. 確認元件已初始化（`IsInit()` 回傳 `true`）。
2. 在玩法開始處呼叫 `StartTimer`，傳入本次要統計的事件名：

```csharp
public void StartTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StartTimer(eventName);
}
```

來源：[README.md](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/README.md#L80-L86)

3. （可選）切換到背景或玩家離開玩法時呼叫 `PauseTimer` 暫停累計：

```csharp
_gameAnalyticsComponent.PauseTimer("level_1_playtime");
```

4. （可選）玩家回來時呼叫 `ResumeTimer` 繼續累計：

```csharp
_gameAnalyticsComponent.ResumeTimer("level_1_playtime");
```

5. 玩法結束時呼叫 `StopTimer` 結束計時，時長資料會隨事件名上報：

```csharp
public void StopTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StopTimer(eventName);
}
```

來源：[README.md](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/README.md#L90-L96)

### 複製即用的完整封裝

```csharp
private const string LevelTimerName = "level_1_playtime";

public void OnLevelStart()
{
    GameAnalyticsComponent.Instance.StartTimer(LevelTimerName);
}

public void OnApplicationPause(bool pauseStatus)
{
    if (pauseStatus)
    {
        GameAnalyticsComponent.Instance.PauseTimer(LevelTimerName);
    }
    else
    {
        GameAnalyticsComponent.Instance.ResumeTimer(LevelTimerName);
    }
}

public void OnLevelFinish()
{
    GameAnalyticsComponent.Instance.StopTimer(LevelTimerName);
}
```

注意：`GameAnalyticsComponent.Instance` 的具體取得方式以你專案中的元件註冊方式為準；上面四個方法名與簽章均來自儲存庫的真實介面。

## 常見變體

- **不需要暫停的短時統計**：只呼叫 `StartTimer` 和 `StopTimer` 即可，`PauseTimer` / `ResumeTimer` 可省略（README 中給出的官方範例即只有這兩個呼叫）。
- **多個事件平行計時**：以不同 `eventName` 分別呼叫 `StartTimer`，各計時互不影響；同一事件名重複開始的行為由底層分析後端決定，建議同一事件名循序使用。
- **直接對接底層 Manager**：若不透過元件，而是直接持有 `IGameAnalyticsManager` 實作，可繞過元件迴圈直接呼叫同名介面；`BaseGameAnalyticsManager` 將四個計時方法宣告為抽象方法，由各具體後端實作。

來源：[BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L150-L168)

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 計時呼叫無任何資料上報 | 元件未初始化，`m_IsInit == false` 時方法直接 `return` | 先呼叫 `Init` / `ManualInit` 再開始計時 |
| 日誌出現 `GameAnalyticsManager is not init.` | `StartTimer` / `StopTimer` 遍歷時發現某個後端 `IsInit()` 為 `false` | 確認各分析後端均已初始化完成 |
| 傳入空事件名直接拋出例外 | `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))` 會攔截空/`null` | 確保 `eventName` 非空 |
| 暫停後時長仍被計入 | 只呼叫了 `PauseTimer` 之外的方法或事件名不一致 | 暫停與恢復必須使用與開始時相同的 `eventName` |

以 `StartTimer` 為例，元件內部對參數與初始化狀態的檢查如下（`StopTimer` 邏輯相同）：

```csharp
public void StartTimer(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.StartTimer(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

來源：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179)

## 驗證

- 呼叫 `StopTimer` 後，在對應的分析平台（GameAnalytics 後台）查看該 `eventName` 的時長資料是否出現且數值合理。
- 若無資料，檢查 Console 是否有 `GameAnalyticsManager is not init.` 警告，並確認 `eventName` 非空、開始與結束使用同一名稱。

## 背景

`GameAnalyticsComponent` 是四個計時介面的門面：它先做參數守衛與初始化檢查，再把呼叫廣播給 `m_GameAnalyticsManager` 清單中所有已初始化的 `IGameAnalyticsManager` 實作（`PauseTimer` / `ResumeTimer` 的廣播不做二次 `IsInit()` 判斷，但同樣受元件級 `m_IsInit` 攔截）。真正的計時邏輯由各分析後端在 `BaseGameAnalyticsManager` 的抽象方法中實作。
