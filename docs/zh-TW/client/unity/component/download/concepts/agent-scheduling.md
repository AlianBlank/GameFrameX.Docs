# 多代理排程與任務生命週期

下載管理器透過 `TaskPool<DownloadTask>` 同時維護多個下載代理(`DownloadAgent`),所有提交的任務會按優先順序排隊、被閒置代理領取、並在統一的輪詢迴圈裡推進。本頁說明代理如何被建立與排程，以及任務在生命週期中經歷的各個狀態與事件。

## 快速開始

1. 啟動元件時，透過 `DownloadComponent` 註冊若干下載代理輔助器(每個輔助器對應一個獨立代理，可平行下載)：

```csharp
// AddDownloadAgentHelper 會 new DownloadAgent(helper) 並 m_TaskPool.AddAgent(agent)
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
```

Source: [DownloadManager.cs#L204-L213](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L204-L213)

2. 呼叫 `AddDownload(...)` 提交任務，任務會進入 `TaskPool` 的等待佇列，等待閒置代理領取：

```csharp
int serialId = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/pkg.zip",
    downloadUri:  "https://example.com/pkg.zip",
    tag:         "asset",
    priority:    0);
```

Source: [DownloadManager.cs#L269-L296](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L269-L296)

3. 框架模組每幀呼叫 `DownloadManager.Update`,內部把更新轉送給任務池，代理領取任務後呼叫 `IDownloadAgentHelper.Download` 開始傳輸，並在過程中觸發 `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` 事件。

```csharp
// DownloadManager.Update -> m_TaskPool.Update(elapseSeconds, realElapseSeconds)
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_TaskPool.Update(elapseSeconds, realElapseSeconds);
    m_DownloadCounter.Update(elapseSeconds, realElapseSeconds);
}
```

Source: [DownloadManager.cs#L185-L189](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L185-L189)

## 代理排程

下載管理器在 `AddDownloadAgentHelper` 時為每一個輔助器建立獨立的 `DownloadAgent`,並透過 `TaskPool<DownloadTask>.AddAgent` 註冊。`TaskPool` 負責維護代理集合與等待佇列，只把任務分配給處於閒置狀態的代理。

代理集合中的關鍵統計量與佇列狀態都透過 `DownloadManager` 暴露，可在 UI 或除錯面板中直接讀取：

| 名稱 | 來源屬性 | 含義 |
|------|----------|------|
| 總代理數 | `TotalAgentCount` | 已被註冊的下載代理總數 |
| 閒置代理數 | `FreeAgentCount` | 目前未承載任務的代理數 |
| 工作代理數 | `WorkingAgentCount` | 正在下載中的代理數 |
| 等待任務數 | `WaitingTaskCount` | 已加入佇列但尚未被領取的任務數 |
| 目前速度 | `CurrentSpeed` | 由 `DownloadCounter` 計算的瞬時速度(MB/s) |
| 暫停旗標 | `Paused` | 暫停會讓代理停止領取新任務 |

Source: [DownloadManager.cs#L86-L142](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L86-L142)

排程方向一覽：

1. 註冊代理:`AddDownloadAgentHelper` → `new DownloadAgent(helper)` → `m_TaskPool.AddAgent(agent)`。
2. 提交任務:`AddDownload` → 建構 `DownloadTask.Create` → 寫入任務池等待佇列。
3. 領取任務：每幀 `TaskPool.Update` 把等待佇列裡優先順序最高的任務交給一個閒置代理，代理隨後呼叫 `IDownloadAgentHelper.Download(downloadUri, userData)`。
4. 釋放代理：代理完成(成功或失敗)後，自身被標記為閒置，任務池可在下一輪繼續分派其他等待任務。

> 關於 `TaskPool<T>` 內部的優先順序比較與等待佇列實作，見 GameFrameX 執行時原始碼；本元件只負責提供 `DownloadTask` 與 `DownloadAgent` 實作。

## 任務生命週期

每個下載任務都是 `DownloadManager.DownloadTask`,繼承自 `TaskBase`,透過 `ReferencePool.Acquire<DownloadTask>()` 建立，並在 `Clear()` 時歸還物件池。任務有以下狀態：

| 狀態列舉值 | 取值 | 說明 |
|------------|------|------|
| `DownloadTaskStatus.Todo` | 0 | 已加入佇列、等待代理領取 |
| `DownloadTaskStatus.Doing` | 1 | 已被代理領取，正在傳輸 |
| `DownloadTaskStatus.Done` | 2 | 下載完成、檔案寫入磁碟 |
| `DownloadTaskStatus.Error` | 3 | 下載失敗(逾時、網路錯誤等) |

Source: [DownloadManager.DownloadTaskStatus.cs#L39-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTaskStatus.cs#L39-L60)

`DownloadTask` 攜帶的關鍵欄位：

| 欄位 | 型別 | 含義 |
|------|------|------|
| `SerialId` | `int` | 透過 `s_Serial` 遞增分配，每次 `Create` 都 `++s_Serial` |
| `DownloadPath` | `string` | 下載完成後檔案的存放路徑 |
| `DownloadUri` | `string` | 原始下載位址 |
| `FlushSize` | `int` | 緩衝區寫入磁碟的臨界大小(由管理器預設值覆蓋) |
| `Timeout` | `float` | 下載逾時秒數(由管理器預設值覆蓋) |
| `Priority` | `int` | 任務優先順序，數值越大越靠前 |
| `Tag` | `string` | 任務標籤，可按標籤批次查詢 `TaskInfo` |
| `UserData` | `object` | 傳遞給 `IDownloadAgentHelper.Download` 的自訂資料 |

Source: [DownloadManager.DownloadTask.cs#L39-L130](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs#L39-L130)

### 生命週期階段

1. **加入佇列**：呼叫 `AddDownload` 多載進入完整參數版本後，由 `DownloadTask.Create(downloadPath, downloadUri, tag, priority, flushSize, timeout, userData)` 建立任務，初始狀態為 `Todo`,並立即進入 `TaskPool` 的等待佇列。
2. **分派**:`TaskPool.Update` 把任務交給一個閒置 `DownloadAgent`,代理在 `OnDownloadAgentStart` 回呼裡將任務狀態切換為 `Doing`,並開啟本機 `FileStream`。
3. **進行中**：代理持續接收 `IDownloadAgentHelper` 的 `DownloadAgentHelperUpdateBytesEventArgs` / `UpdateLength`,累計 `m_DownloadedLength` 與 `m_SavedLength`,當 `m_WaitFlushSize` 達到 `FlushSize` 時寫入磁碟，同時按週期更新 `m_WaitTime` 用於逾時判定。
4. **完成 / 失敗**：成功時觸發 `DownloadAgentSuccess`,失敗(包括逾時)時觸發 `DownloadAgentFailure`,代理關閉串流、清理狀態，任務狀態設為 `Done` 或 `Error`,等待 `TaskPool` 自動歸還物件池。
5. **資源回收**:`Clear()` 把任務欄位重設為 `Todo`/空值，再由 `ReferencePool.Release` 放回池中，等待下一次 `Create` 重複使用。

## 關鍵 API 速查

| 名稱 | 簽章 | 說明 |
|------|------|------|
| `DownloadManager.AddDownloadAgentHelper` | `void AddDownloadAgentHelper(IDownloadAgentHelper downloadAgentHelper)` | 註冊一個下載代理，輔助器不能為 `null`,否則建構時擲出 `GameFrameworkException("Download agent helper is invalid.")` |

## 常見錯誤

| 現象 | 原因 | 修正 |
|------|------|------|
| 所有任務一直停留在 `WaitingTaskCount > 0`、`WorkingAgentCount = 0` | 沒有呼叫 `AddDownloadAgentHelper`,任務池裡沒有任何代理 | 在元件啟動階段按需新增至少一個 `IDownloadAgentHelper`(UnityWebRequest / WWW 實作) |
| 啟動元件時立即擲出 `Download agent helper is invalid.` | 傳入 `null` 或物件被提前釋放 | 確保傳入的是有效實例，且不會被外部提前 `Dispose` |
| 任務長時間處於 `Doing` 後被標記失敗 | `Timeout` 設定過短，或在弱網路環境下 `FlushSize` 太大導致緩衝未寫入磁碟 | 透過 `DownloadManager.Timeout` / `DownloadManager.FlushSize` 調整，或使用 `AddDownload` 多載逐任務覆蓋 |
| 已註冊多個輔助器但並行數仍為 1 | 重複註冊了同一個輔助器實例導致代理共用底層連線 | 每個 `UnityWebRequestDownloadAgentHelper`/`WWWDownloadAgentHelper` 實例只呼叫一次 `AddDownloadAgentHelper` |

## 背景(選用)

下載管理器是 `GameFrameworkModule`(`Priority = 5`),在 `Update` 中把排程權完全交給 `TaskPool<DownloadTask>`,本類別只負責：

- 維護一份下載代理清單(透過 `AddDownloadAgentHelper` 注入)。
- 把每次 `AddDownload` 轉換為 `DownloadTask.Create(...)` 並交給任務池。
- 監聽代理的四個事件 (`Start/Update/Success/Failure`) 並對外暴露成統一的事件回呼。
- 藉助 `DownloadCounter` 把所有代理的位元組增量換算成統一的瞬時下載速度。

任務物件(`DownloadTask`)本身由 `ReferencePool` 託管，代理(`DownloadAgent`)實作 `ITaskAgent<DownloadTask>` 與 `IDisposable`,這兩個抽象是它與 `TaskPool` 對接的契約，也是與 GameFrameX 執行時任務排程子系統保持一致的地方。
