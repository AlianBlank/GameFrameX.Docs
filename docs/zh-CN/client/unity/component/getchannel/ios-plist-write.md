# iOS 构建后 Info.plist 渠道未写入或被跳过

导出的 Xcode 工程里 `Info.plist` 没有 `channel` 键,或运行时 `BlankGetChannel.GetChannelName()` 一直返回 `default`,常见原因是:`PostProcessBuildHandler` 被 `#if UNITY_IOS` 条件编译排除、构建目标不是 `BuildTarget.iOS`、或 plist 中已存在 `channel` 键导致处理程序按设计跳过。本文按症状定位并修复。

## 快速诊断

| 症状(编辑器控制台 / 导出工程) | 原因 | 修复 |
|------|------|------|
| 完全没有 `配置渠道成功` 或 `已有渠道` 日志,plist 无 `channel` 键 | 编辑器当前激活平台不是 iOS,整个 `PostProcessBuildHandler` 被 `#if UNITY_IOS` 排除,没有参与编译 | 切换到 iOS 平台后重新构建(见步骤 1) |
| 日志为 `已有渠道,跳过设置=>xxx` | `Info.plist` 已存在 `channel` 键(更早执行的其他 `PostProcessBuild` 回调或模板已写入),处理程序检测到后不覆盖 | 见步骤 2 |
| 构建目标是 tvOS / visionOS | `OnPostProcessBuild` 中 `target != BuildTarget.iOS` 直接 `return`,tvOS/visionOS 构建被主动跳过 | 见步骤 3 |
| Editor 日志出现异常堆栈,但构建仍成功、plist 未写入 | `Run()` 抛出的异常只被 `Debug.LogException(e)` 记录,不中断构建 | 见步骤 4 |
| `channel` 键写进去了,但值永远是 `default` | 写入值是常量 `const string channelValue = "default";`,并非动态渠道名 | 见步骤 5 |

## 修复步骤

### 1. 确认编辑器构建目标为 iOS

整个处理程序文件包在 `#if UNITY_IOS` 中,且回调里再次过滤目标平台:

```csharp
#if UNITY_IOS
        [PostProcessBuild(99)]
        public static void OnPostProcessBuild(BuildTarget target, string path)
        {
            if (target != BuildTarget.iOS)
            {
                return;
            }

            try
            {
                Run(path);
            }
            catch (Exception e)
            {
                Debug.LogException(e);
            }
        }
#endif
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L1-L29)

操作:在 **File → Build Settings** 中将激活平台切换为 iOS,再执行构建。切换后重新编译脚本,回调才会注册生效。

### 2. `channel` 键已存在导致跳过

```csharp
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L36-L48)

该逻辑只在键**不存在**时写入,已有值一律保留。两种处理方式:

1. 若已存在的值是错误的:检查是否有其他 `PostProcessBuild` 回调先写了 `channel`。本回调顺序为 `99`,顺序值更小的回调先执行;调整你的回调顺序,或删除对方写入逻辑。
2. 若已存在的值是正确的:无需处理,这是预期的幂等行为,避免覆盖外部渠道打包工具写入的值。

### 3. tvOS / visionOS 构建被跳过

运行时层支持 tvOS/visionOS(通过原生调用读取 plist),但构建后处理只处理 `BuildTarget.iOS`。对 tvOS/visionOS:

- 在导出的 Xcode 工程 `Info.plist` 中手动添加 `channel` 键;或
- 在你自己的构建脚本中为 `BuildTarget.tvOS` 等目标执行类似的 plist 写入逻辑。

### 4. 构建时出现异常但 plist 未写入

`OnPostProcessBuild` 捕获所有异常并仅通过 `Debug.LogException(e)` 打印,构建不会失败,plist 也就不会写入。典型触发点在 `Run()` 内:

- `File.ReadAllText(plistPath)` 抛 `FileNotFoundException`:`path` 参数是构建输出目录,Xcode 工程未生成或路径不对;
- `plist.ReadFromString` 抛解析异常:plist 被其他工具改坏。

操作:在 Unity Console 中搜索 `PostProcessBuildHandler` 相关堆栈,修正 `path` 指向的构建输出目录后重新构建。

### 5. 写入值固定为 `default`

```csharp
const string channelKey = "channel";
const string channelValue = "default";
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L33-L34)

写入值是编译期常量 `"default"`,并不读取当前渠道。因此该处理程序的定位是**兜底写入**,保证 `Info.plist` 至少存在 `channel` 键。真实的渠道名应在你自己的渠道打包流程中写入或覆盖 `channel` 键;兜底逻辑会在键已存在时主动让位(见步骤 2)。

## 验证

按以下顺序确认修复生效:

1. Unity 构建完成后,Console 出现 `配置渠道成功=>default`(或 `已有渠道,跳过设置=>xxx`)。
2. 打开导出的 Xcode 工程,`Info.plist` 中存在:

```xml
<key>channel</key>
<string>default</string>
```

该键值对格式即运行时原生接口读取的格式,见 [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26) 的注释说明。

3. 真机运行,调用 `BlankGetChannel.GetChannelName()` 验证返回值。iOS 上通过 `DllImport("__Internal")` 调用原生 `getChannelName`,并带缓存:

```csharp
#elif UNITY_IOS || UNITY_TVOS || UNITY_VISIONOS
        channelName = getChannelName(channelKey);
#endif
        ChannelCache[channelKey] = channelName;
        return channelName;
```

Source: [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L136-L141)

注意:`GetChannelName(string channelKey = "channel", string defaultValue = "default")` 的默认值也是 `"default"`,若渠道键读取失败会原样返回 `default`,与"未写入 plist"现象相同——先用第 2 步在 plist 里确认键确实存在,再排查运行时读取。
