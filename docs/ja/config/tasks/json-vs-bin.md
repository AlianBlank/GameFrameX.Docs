# JSON と BIN 出力形式の選び方

Luban は **JSON** と **BIN** の 2 種類のデータ出力形式をサポートしており、それぞれの形式に異なるコードテンプレートが対応しています。本ページでは、クライアント/サーバー、ランタイムパフォーマンス、可読性などの要件に基づいて、両者の中から素早く選択できるよう支援し、対応する生成スクリプトと設定項目への切り替え方法を案内します。

## 一言でいうと

- サーバー(C# / .NET):デフォルトは `JSON`、究極のロード速度を追求する場合は `BIN` に切り替える。
- クライアント(Unity):開発/デバッグには `JSON`、リリース版には `BIN` を強く推奨。
- 出力形式とコードテンプレートは一対一で対応しており、形式を変更する際は `--dataTarget` と `--codeTarget` を同時に変更する必要があります。

## 2 つの形式の比較表

| 項目 | JSON | BIN |
|------|------|-----|
| データファイルの可読性 | プレーンテキストで、エディタ/git で直接確認可能 | バイナリで、ツールまたはランタイムがないと読めない |
| ファイルサイズ | 大きめ(引用符、インデント、フィールド名を含む) | コンパクト(フィールドをコンパクトにシリアライズ、フィールド名なし) |
| ロード/パース速度 | 遅め(ランタイムで文字列をパース) | 速い(`MemoryStream` で直接読み取り) |
| Git diff/マージ | 扱いやすく、コンフリクトの解決も容易 | 扱いにくく、コンフリクトは基本的にファイル全体の置換しかできない |
| 対応するコードテンプレート | `cs-dotnet-json`(サーバー側)、`cs-simple-json`(クライアント側) | `cs-bin`(サーバーとクライアントで共用) |
| バリデーションの厳格さ | デフォルト | `--validationFailAsError true` で有効化 |
| 適したシーン | 開発期、サーバー、デバッグ、ホットアップデートの段階的リリース | クライアントの正式版、起動/メモリに敏感なシーン |

ソース設定は [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94) の `commands` セクションを参照してください。

## 操作手順:出力形式の選択と切り替え

### 1. 現在有効な形式を確認する

`luban.conf` を開き、`commands` 配列の中から生成したいターゲット(server または client)を見つけて、`active` フィールドを確認します:

- `active: true` → 現在有効なコマンド。
- `active: false` → 予備のコマンドで、手動で有効化する必要があります。

リポジトリでデフォルトで有効になっているのは JSON です:

```json
{
  "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

Source: [luban.conf#L66-L94](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

### 2. 生成スクリプトで素早く切り替える

リポジトリのルートディレクトリには 4 組の生成スクリプトが用意されており、`luban.conf` を変更せずにそのまま実行できます:

| ターゲット | JSON | BIN |
|------|------|-----|
| Server | `gen-server-json.bat` / `gen-server-json.sh` | `gen-server-bin.bat` / `gen-server-bin.sh` |
| Client | `gen-client-json.bat` / `gen-client-json.sh` | `gen-client-bin.bat` / `gen-client-bin.sh` |

例えば **サーバー BIN** に切り替える場合:

```bat
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

Source: [gen-server-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.bat#L1)

**クライアント BIN** に切り替える場合:

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

Source: [gen-client-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.bat#L1)

### 3. luban.conf を変更して対象コマンドを active にする

IDE/プラグインレベルでデフォルトで BIN を出力したい場合(例：正式リリースのパイプライン)、対応する `BIN` コマンドの `active` を `true` に変更し、`JSON` コマンドの `active` を `false` に変更します:

```json
{
  "command": "--target server --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

Source: [luban.conf#L78-L87](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L78-L87)

注意:`--validationFailAsError true` を指定すると、BIN 形式はバリデーション失敗時に警告ではなく直接エラーになります。正式環境では残しておくことを推奨します。

## よくあるバリエーション

### バリエーション A:サーバー JSON(デフォルト)

ローカル開発とサーバー側ホットアップデートに適しています。生成物は直接 `git diff` でき、テキスト検索も可能です。

```bat
dotnet.exe ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

Source: [gen-server-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-json.bat#L1)

### バリエーション B:クライアント JSON(デフォルト)

Unity クライアントのデバッグ段階に適しています。`*.json` を `Assets/Bundles/Config` にエクスポートし、コードテンプレートは `cs-simple-json` です。

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

Source: [gen-client-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1)

### バリエーション C:クライアント BIN(リリース推奨)

コードテンプレートは `cs-bin` に統一され、データはコンパクトなバイナリで、Unity 側でのロード時のメモリと IO をより節約できます。

```sh
dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate
```

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 実行時に `dataTarget/codeTarget 不匹配` とエラーが出る | `--dataTarget` だけ変更して、`--codeTarget` を変更していない | 両者はペアでなければならない(json↔cs-dotnet-json/cs-simple-json、bin↔cs-bin/cs-dotnet-bin/cs-dotnet-bin) |
| BIN ファイルを直接開いて内容を確認できない | bin を選んだのに json のように閲覧できると期待している | 対応する `cs-bin` テンプレートで読み込むべきであり、テキストパースを試みないこと |
| luban.conf を変更しても反映されない | 古いスクリプトを実行し続けている | 直接 `gen-*-bin.*` スクリプトを実行するか、`commands` 内の対象コマンドの `active` を `true` に変更する |
| クライアントのリリース後に起動が遅くなる | クライアントがまだ JSON を使用している | `gen-client-bin.*` に切り替え、BIN コマンドの `active` を `true` に設定する |
| サーバーが設定をホットアップデートした後のエラーが特定しにくい | サーバーが BIN を使用しているがバリデーションを有効にしていない | BIN コマンドに `--validationFailAsError true` を追加する |

## 背景(任意)

JSON と BIN の違いは、本質的に **可読性 / サイズ / パース速度** のトレードオフです。Luban はデータシリアライズ(`--dataTarget`)とコード生成テンプレート(`--codeTarget`)を分離しているため、同じデータを異なるランタイム表現で扱うことができます——開発期は JSON を維持し、正式期は BIN に切り替えるのが、GameFrameX が推奨する段階的なアプローチです。
