# 如何設定物件儲存路徑

呼叫 `SetSavePath(string)` 可設定物件在物件儲存中的目標儲存路徑,後續 `UploadDirectory` 與 `UploadFile` 上傳的檔案都會落到該路徑下。

## 前置條件

- 已透過 `ObjectStorageUploadFactory` 取得一個 `IObjectStorageUploadManager` 實例(具體類型由工廠根據當前平台/配置建立,繼承自 `BaseObjectStorageUploadManager`)。
- 已確認要寫入的儲存桶(`bucketName`)並完成 `Init(accessKey, secretKey, bucketName, endpoint)`。

## 操作步驟

1. 取得上傳管理器實例。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs)

2. 呼叫 `SetSavePath` 指定物件在儲存桶內的儲存路徑(支援帶或不帶結尾分隔符號)。

   ```csharp
   // 寫法 A:不寫結尾分隔符號
   manager.SetSavePath("game/assets/textures");
   
   // 寫法 B:帶結尾分隔符號,實作內部會自動去掉最後一個分隔符號
   manager.SetSavePath("game/assets/textures/");
   ```

   實作會先判斷 `savePath` 是否以 `Path.DirectorySeparatorChar` 結尾,如果是則 `Substring(0, savePath.Length - 1)` 截掉,最後再指派給 `BucketSavePath`。兩種寫法等價。

   Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

3. 路徑設定完成後，再呼叫上傳介面，檔案就會儲存到 `BucketSavePath` 下。

   ```csharp
   // 上傳整個目錄
   manager.UploadDirectory("/本地/Assets/Textures");
   
   // 或上傳單一檔案
   bool ok = manager.UploadFile("/本地/Assets/Textures/icon.png");
   ```

   Source: [IObjectStorageUploadManager.cs#L9-L21](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9-L21)

## 常見變體

- **每次上傳前重設路徑**：同一次工作階段中可以反覆呼叫 `SetSavePath`,以切換不同子目錄上傳。`BucketSavePath` 是受保護欄位,每次呼叫都會被覆寫。
- **相對路徑 vs 絕對鍵前綴**:`SetSavePath` 接收的是物件鍵(Key)的前綴,例如 `"game/v1"`,並非本機檔案系統路徑。本機路徑由 `UploadDirectory` / `UploadFile` 單獨傳入。

## 常見錯誤

- **路徑寫成反斜線結尾(Windows 習慣)**:`SetSavePath` 只檢查 `Path.DirectorySeparatorChar`(平台原生分隔符號),傳入 Windows 的 `"a\\b\\"` 會保留反斜線。建議統一傳正斜線或不含分隔符號的形式。
- **忘記先 `Init` 就 `SetSavePath`**:雖然 `SetSavePath` 本身不驗證 `Init` 狀態,但後續上傳需要合法的憑證,未 `Init` 時上傳會失敗。先 `Init` 再設定路徑、再上傳。
- **呼叫順序錯亂**:`SetSavePath` 必須在 `UploadDirectory` / `UploadFile` 之前呼叫;否則已發出的上傳會沿用上一次設定的 `BucketSavePath`(預設 `string.Empty`)。

## 背景(可選)

`BucketSavePath` 是 `BaseObjectStorageUploadManager` 的受保護欄位，具體實作類別(如各雲端供應商的配接實作)會把它當作物件 Key 的前綴拼接到上傳請求中，因此本質上是「物件鍵前綴」，而非「本機磁碟路徑」。
