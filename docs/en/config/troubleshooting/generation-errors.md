# What to Do When Generation Fails / Errors Occur

When Luban throws an exception or produces no output files after running `gen-*.bat` / `gen-*.sh`, work through the diagnostic table on this page item by item. Problems mostly fall into three categories: script paths, configuration placeholders, and Excel table structure.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Could not find a part of the path ... Tools/Luban.dll` | Tools directory missing or path mistyped | Create `Tools/` under the repository root and place `Luban.dll` in it, or fix the `toolPath` in `luban.conf` |
| `luban.conf not found` / `conf not loaded` | Current directory is wrong; the script didn't switch to the repository root | Run the script in the directory at the same level as `Tools/`, or have the script `cd` to the directory containing the config |
| Placeholders `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` not expanded | The two keys in `luban.conf` are empty strings | Replace `UNITY_ASSETS_PATH` and `SERVER_PATH` in `luban.conf` with absolute paths |
| Reports `Excel ... __tables__.xlsx` parse failure | Template headers corrupted, columns missing, or a multi-table merge went wrong | Restore `Excels/__tables__.xlsx`, `__beans__.xlsx`, `__enums__.xlsx`; do not delete columns manually |
| Reports `Localization.xlsx not found` | Localization file renamed/missing during client generation | The `localizationFileName` in the command defaults to `Localization.xlsx`; change it to the actual file name in the repository if needed |
| Command window flashes by; error not visible | Missing `pause` at the end (Windows) | Make sure the last line of `gen-*.bat` is `pause` (see existing scripts) |
| Only code generated, no data generated | `dataTarget` and `codeTarget` mismatch, or `outputDataDir` path is invalid | Set both `--dataTarget` and `--codeTarget`, and verify that `outputDataDir` is writable |
| Reports `validation failed` | `--validationFailAsError true` is configured and the data failed validation | Temporarily remove `--validationFailAsError true` to see the specific warnings, then re-enable it after fixing the data |

## Fix Steps

### 1. Luban.dll Not Found

Open `luban.conf` and check the `toolPath` field:

```json
"toolPath": "/../Config/Tools/Luban.dll",
```

The script actually invokes it like this:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf
```

Source: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L2)

These two places must stay consistent: if the script references `./Tools/Luban.dll`, then `Tools/Luban.dll` must exist in the repository. If your project puts the tools under `Config/Tools/`, update both `toolPath` and the script path accordingly.

### 2. Placeholders Not Expanded

The defaults in `luban.conf` are empty strings:

```json
"UNITY_ASSETS_PATH": "",
"SERVER_PATH": "",
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L62-L65)

The commands in `commands` reference these two variables, for example:

```json
"command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config"
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L78)

When you run the script directly, these `%XXX%` placeholders are not expanded, resulting in a "path does not exist" error at the file system level. Replace them with absolute paths on your machine before generating.

### 3. Excel Templates Corrupted

`luban.conf` declares four metadata tables via `schemaFiles`:

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

Whenever the error mentions these four files, restore them from the repository first, then check whether the column names of the business tables under `Excels/Tables/` and `Excels/Local/` correspond one-to-one with the fields in `__tables__.xlsx`.

### 4. Localization Table Not Found During Client Generation

The client command includes a separate `localizationFileName`, which by default expects a file named `Localization.xlsx`:

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L72-L77)

If your localization table has been renamed (e.g., the repository only contains `L-Localization-UI.xlsx`, `L-Localization-成就.xlsx`, `L-Localization-文本.xlsx`), change `localizationFileName` to the actual file name, or rename the table back to `Localization.xlsx`.

### 5. Script Window Flashes By Without Showing the Error

`gen-*.bat` scripts on Windows should all add `pause` at the end:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf

pause
```

Source: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L3)

If your script removed `pause`, the error is lost when the window closes, so you can't see the cause. Add `pause` and rerun it.

### 6. Server Binary Generation Fails

The server bin generation script provided by the repository looks like this:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
pause
```

Source: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L2)

Note that this is named `gen-server-bin.sh`, but its content is Windows-style `dotnet ... && pause`, and it depends on the relative path `../Server/GameFrameX.Config/`. When the error is path-related, confirm:
- The two directories `Server/GameFrameX.Config/Json` and `Server/GameFrameX.Config/Config` exist or are writable;
- The script was run from the repository root, not via `sh ./gen-server-bin.sh` from another directory.

## Verification

After applying the fixes above, run a minimal command to confirm the pipeline works:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json \
  --xargs outputDataDir=./out/Json \
  --xargs outputCodeDir=./out/Config \
  --conf ./Luban.conf
```

On success:
- `./out/Config/` should contain generated code such as `TablesComponent.cs`;
- `./out/Json/` should contain `Tb*.json` data files;
- There are no exception stack traces in the terminal.

Then run the corresponding platform scripts (`gen-server-json.bat` / `gen-client-json.sh`, etc.) once more to confirm everything works end to end.
