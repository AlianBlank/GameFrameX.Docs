# 使用 async/await 等待秒數與幀數

`TimerComponent` 公開了三個可直接 `await` 的等待方法:`WaitForSecondsAsync`(等待秒數)、`WaitForNextFrameAsync`(等待下一幀)、`WaitForFramesAsync`(等待指定幀數)。它們全部基於計時器管理器實作，等待與續體都在 Unity 主執行緒完成，可在協程之外用 `async` 方法寫出線性流程。

## 前置條件

- 場景/專案中已接入 `TimerComponent`(計時器管理器已隨元件初始化)。
- 呼叫方為 `async` 方法(`async void` 僅建議用於 Unity 事件函式，如 `Start`)。

## API 速查

| 方法 | 簽名 | 行為 |
|------|------|------|
| 等待秒數 | `Task WaitForSecondsAsync(float seconds, CancellationToken cancellationToken = default)` | `seconds` 秒後完成任務 |
| 等待下一幀 | `Task WaitForNextFrameAsync(CancellationToken cancellationToken = default)` | 下一幀更新後完成任務 |
| 等待幀數 | `Task WaitForFramesAsync(int frameCount, CancellationToken cancellationToken = default)` | 經過 `frameCount` 幀後完成;`frameCount <= 0` 時立即完成(傳回 `Task.CompletedTask`) |

`TimerComponent` 上的同名實例方法直接轉發給內部的 `ITimerManager`(見 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L245))。此外 `TimerAsyncExtensions` 以擴充方法形式向任意 `ITimerManager` 提供同樣三個能力：

```csharp
public static Task WaitForSecondsAsync(this ITimerManager timer, float seconds, CancellationToken cancellationToken = default)
public static Task WaitForNextFrameAsync(this ITimerManager timer, CancellationToken cancellationToken = default)
public static Task WaitForFramesAsync(this ITimerManager timer, int frameCount, CancellationToken cancellationToken = default)
```

Source: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L20-L72)

## 操作步驟

1. 在腳本中引用命名空間(按專案實際引用方式調整)：

```csharp
using System.Threading;
using System.Threading.Tasks;
```

2. 取得 `TimerComponent` 實例(下方範例以欄位 `timerComponent` 代表你專案中的元件參考)，用 `await` 等待秒數：

```csharp
public async void Start()
{
    // 等待 2 秒(基於 TimerComponent 轉發到內部 timerManager)
    await timerComponent.WaitForSecondsAsync(2f);
    UnityEngine.Debug.Log("2 秒後執行到這裡");
}
```

3. 等待幀數，或只等一幀：

```csharp
// 等待 60 幀後繼續
await timerComponent.WaitForFramesAsync(60);

// 只等下一幀
await timerComponent.WaitForNextFrameAsync();
```

4. 若持有 `ITimerManager` 參考，也可以直接呼叫擴充方法：

```csharp
await timerManager.WaitForSecondsAsync(1.5f);
```

## 常見變體

- **帶取消權杖的等待**(物件銷毀、玩法取消時提前結束)：

```csharp
var cts = new CancellationTokenSource();
await timerComponent.WaitForSecondsAsync(5f, cts.Token);
```

取消後再次 `await` 該任務會以取消狀態完成；呼叫前權杖已取消時，方法直接傳回 `Task.FromCanceled(cancellationToken)`,不會註冊任何計時器：

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return Task.FromCanceled(cancellationToken);
}
```

Source: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L22-L28)

- **順序串聯多個等待**:`await` 天然線性，直接依序撰寫即可，無需巢狀回呼。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `WaitForFramesAsync(0)` 或傳負數沒有等待 | `frameCount <= 0` 時直接傳回 `Task.CompletedTask`,這是文件化的行為 | 至少傳 `1`;要「立即讓出」請用 `WaitForNextFrameAsync()` |
| 權杖已取消卻仍進入等待流程 | 設計如此：已取消時立即傳回 `Task.FromCanceled`,不註冊計時器 | 檢查權杖生命週期，必要時換新權杖 |
| 續體裡存取 Unity 物件擲回主執行緒外的例外 | 所有等待與續體均在 Unity 主執行緒完成(類別註解明確宣告) | 不要在等待任務上呼叫 `ConfigureAwait(false)` 等改變上下文的寫法 |

## 背景

三個方法均以 `TaskCompletionSource<bool>` 包裝一次計時器回呼:`WaitForSecondsAsync` 用 `timer.AddOnce(seconds, ...)`,一次觸發後自動移除;`WaitForNextFrameAsync` 用 `AddOnce(0, ...)`,`interval=0` 即每幀、`repeat=1` 即執行一次;`WaitForFramesAsync` 用 `timer.Add(0, frameCount, ...)`,每幀執行、共 `frameCount` 次後移除。取消透過 `cancellationToken.Register` 將任務設為取消，回呼觸發時釋放註冊。實作見 [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L27-L94)。
