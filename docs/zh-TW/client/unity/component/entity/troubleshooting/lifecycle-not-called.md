# 若實體的生命週期方法未被觸發該怎麼辦

如果在呼叫 `ShowEntity` / `HideEntity` 之後，實體中的 `OnInit` / `OnShow` / `OnUpdate` / `OnHide` 皆未被呼叫，通常是因為 `EntityLogicType` 未正確傳入、prefab 上已存在同名腳本，或 `EntityComponent` 未初始化。本頁是以「日誌錯誤 → 根本原因 → 一行修復」方式整理的快速參考。

## 快速診斷

| 症狀（日誌/行為） | 根本原因 | 修復方式 |
|---|---|---|
| `Entity '{0}' OnInit userData is not ShowEntityInfo.` | 呼叫 `ShowEntity` 時，未將 `ShowEntityInfo`（其中包含 `EntityLogicType`）作為 `userData` 傳入 | 使用 `ShowEntity<T>` 泛型多載，或將 `ShowEntityInfo` 包入自訂的 `userData` 中 |
| `Entity logic type is invalid.` 或 `Entity '{0}' can not add entity logic.` | `ShowEntityInfo.EntityLogicType` 為 `null`，或該類型不是 `EntityLogic` 的子類別，或不是 `MonoBehaviour` | 將 `EntityLogicType` 指定為繼承 `EntityLogic` 的具體 `MonoBehaviour` 子類別的 `Type` |
| `Entity group is inconsistent for non-new-instance entity.` | 同一個實體物件在不同的 `EntityGroup` 中被重用 | 呼叫 `ShowEntity` 時傳入與第一次相同的 `EntityGroup`，或清空物件池 |
| `Entity '{0}' On{Init/Show/Hide} with exception ...` | 你的 `OnInit/OnShow/OnHide` 拋出了例外，被框架的 `try/catch` 吞掉 | 在覆寫的方法內加入自己的 `try/catch` 進行除錯；首先確保 `base.OnXxx(...)` 不會拋出例外 |
| prefab 上已掛載你自己的腳本，且框架未新增新的腳本 | prefab 上已有與 `EntityLogicType` 相符的腳本，該腳本被 `Entity.OnInit` 直接重用，而你的入口邏輯寫在另一個腳本中 | 透過繼承 `EntityLogic` 來實作業務邏輯；不要另外掛載獨立的 `MonoBehaviour` |
| `OnUpdate` 未被呼叫 | `EntityLogic` 的 `enabled` 在 `OnRecycle` 中被設為 `false`，且在下一次 `ShowEntity` 後未恢復；或物件在 `HideEntity` 後已被回收 | 不要在子類別中手動設定 `enabled = false`；確認 `ShowEntity` 有走 `OnInit` 路徑，並檢查物件池 |

## 修復步驟

### 1. 使用泛型 `ShowEntity`，讓框架自動注入 `EntityLogicType`

框架會在 `Entity.OnInit` 中讀取 `userData as ShowEntityInfo` 的 `EntityLogicType` 欄位（[Entity.cs#L112-L124](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L112-L124)）。最不容易出錯的方式是直接使用 `EntityComponent.ShowEntity<T>`：

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

// 假設 MyEntityLogic : EntityLogic，且它掛載在 EntityId 對應的 prefab 上
GameEntry.GetComponent<EntityComponent>()
    .ShowEntity<MyEntityLogic>(entityId, "Assets/Prefabs/MyEntity.prefab", "Default", userData);
```

來源：[Runtime/Entity/EntityComponent.cs#L48](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L48)

### 2. 確認 `EntityLogic` 子類別是 `MonoBehaviour`，且該類型可被新增

`Entity.OnInit` 透過 `gameObject.AddComponent(entityLogicType)` 注入邏輯（[Entity.cs#L141](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L141-L146)）。因此：

```csharp
using UnityEngine;
using GameFrameX.Entity.Runtime;

public sealed class MyEntityLogic : EntityLogic   // 必須是 MonoBehaviour
{
    protected internal override void OnInit(object userData)
    {
        base.OnInit(userData);
        // 初始化邏輯
    }

    protected internal override void OnShow(object userData)
    {
        base.OnShow(userData);
        // 每次 ShowEntity 呼叫都會進入這裡
    }

    protected internal override void OnHide(bool isShutdown, object userData)
    {
        base.OnHide(isShutdown, userData);
        // 隱藏邏輯
    }

    protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(elapseSeconds, realElapseSeconds);
        // 每幀邏輯
    }
}
```

來源：[Runtime/Entity/EntityLogic.cs#L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L40), [Runtime/Entity/EntityLogic.cs#L133](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L133), [Runtime/Entity/EntityLogic.cs#L196](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L196)

注意：`EntityLogic` 的生命週期方法皆宣告為 `protected internal virtual`，必須使用 `override` 進行覆寫，而非使用 `public` / `private`。

### 3. 排查 `OnUpdate` 未被觸發的常見原因

`Entity.OnRecycle` 會呼叫 `m_EntityLogic.enabled = false`（[Entity.cs#L173-L174](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L173-L174)）。當物件從物件池取出並再次呼叫 `ShowEntity` 時，`Entity.OnInit` 會偵測到 `m_EntityLogic != null` 且類型相符，於是只會將 `enabled` 重設回 `true`（[Entity.cs#L130](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L130-L131)）。如果你在子類別中手動設定 `enabled = false`，重用時 `OnUpdate` 將不再被呼叫——直接移除該設定即可。

### 4. 使用日誌驗證呼叫鏈

如果以上皆正常但方法仍未被呼叫，請在每個 `override` 的第一行加上 `Debug.Log`，以確認 `ShowEntity` 後 1 幀內是否有進入 `OnInit` / `OnShow`。注意：對於每種異常情況，`Entity` 都會透過 `Log.Error` 輸出具體原因（[Entity.cs#L149-L156](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L149-L156)）；查看 Console 會比閱讀程式碼更快。

## 驗證

1. 執行場景；第一次 `ShowEntity` 後，應該能看到 `OnInit` → `OnShow` 的 `Debug.Log`，之後 `OnUpdate` 每幀都會被呼叫。
2. 呼叫 `HideEntity`；應該能看到 `OnHide` 被觸發，且物件仍存在於物件池中（在場景中不可見，但物件池計數 +1）。
3. 使用相同的 `EntityId` 再次呼叫 `ShowEntity`；應該只觸發 `OnShow`（假設沒有重用），而不觸發 `OnInit`（這次走的是物件池重用分支）。
4. 在 `OnInit/OnShow/OnHide` 中拋出一次 `Exception` 作為測試，並確認 `Log.Error` 訊息與診斷表格第一列相符。

## 背景（選讀）

`Entity` 是一個 `MonoBehaviour`，作為 `EntityLogic` 的宿主：`ShowEntity` → 資源載入 → 透過 `ShowEntityInfo.EntityLogicType` 在遊戲物件上執行 `AddComponent<EntityLogic>`，接著回呼依序觸發：`OnInit` → `OnShow` → 每幀 `OnUpdate` → `HideEntity` 時觸發 `OnHide` → 回收時觸發 `OnRecycle`。常見的失敗點都集中在 `EntityLogicType` 這一個參數上，而泛型 `ShowEntity<T>` 已經替你處理好了。
