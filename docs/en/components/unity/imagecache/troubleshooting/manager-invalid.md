# What to do about the "ImageCache manager is invalid" error

When you see `ImageCache manager is invalid.` in the game startup logs, it means `ImageCacheComponent.Awake()` got `null` when fetching the manager instance via `GameFrameworkEntry.GetModule<IImageCacheManager>()` — nobody in the framework implements this interface. The component will then directly `return`, and all image loading operations (`LoadImageAsync`, `IsCached`, `RemoveCache`, `ClearCache`) will not work.

Error source (`Awake` entry):

```csharp
_imageCacheManager = GameFrameworkEntry.GetModule<IImageCacheManager>();
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L42-L47)

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Startup log reports `ImageCache manager is invalid.`, subsequent image interface calls return `null` / have no effect | No implementation of `IImageCacheManager` registered in `GameFrameworkEntry` | After starting the framework, call `GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager())` |
| Startup log also shows `Download manager is invalid.` (non-WebGL platform) | Missing `IDownloadManager` module, `Awake` returns early causing manager not injected | Register `IDownloadManager` first (e.g. `DownloadManager`), then register `ImageCacheManager` |
| Error only appears in a certain scene | The current scene doesn't have `ImageCacheComponent` attached, or it's attached to an inactive GameObject | Attach `ImageCacheComponent` to a persistent GameObject, ensure it has been `Awake`'d when the scene loads |
| Custom implementation class inherits `IImageCacheManager`, still reports error | `componentType` (Inspector field) is filled in incorrectly, `Utility.Assembly.GetType(componentType)` in `Awake` returns `null` | Change `Component Type` in Inspector to the full class name with namespace |

## Fix Steps

### 1. Register `ImageCacheManager` at the framework entry point

`ImageCacheComponent` does not automatically create the manager instance, it must be explicitly registered by the business entry. The common practice is to call it during the framework startup process:

```csharp
using GameFrameX.Runtime;
using GameFrameX.ImageCache.Runtime;

GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager());
```

Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L11-L48)

### 2. Add the Download module on non-WebGL platforms

`ImageCacheComponent.Awake()` also validates `IDownloadManager`; missing it will likewise cause the manager initialization to fail:

```csharp
#if !UNITY_WEBGL
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
((ImageCacheManager)_imageCacheManager).SetDownloadManager(downloadManager);
#endif
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55-L64)

So the order should be: first register `IDownloadManager`, then register `IImageCacheManager`, and finally let the object in the scene with `ImageCacheComponent` attached `Awake`.

### 3. Check component attachment in the scene

Make sure `ImageCacheComponent` is attached to a **persistent** GameObject (e.g. the `GameFrameX` root node in the bootstrap scene), not just in some business scene. `Awake` only triggers once when the scene is first activated; if it's missing, all image calls will fail, and it won't try to create the manager again.

### 4. Check `Component Type` when using a custom implementation class

`Awake` will use `Utility.Assembly.GetType(componentType)` to resolve the implementation type:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IImageCacheManager);
base.Awake();
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L39-L41)

`componentType` must be filled with the implementation class's **full class name (with namespace)**, and the class must be compiled into the runtime assembly; otherwise, `Awake` will throw an exception internally first, and the subsequent `GetModule<IImageCacheManager>()` will likewise return `null`, triggering this error.

## Verification

After completing the above fixes, confirm the issue is resolved using the following methods:

1. Start the game and search for `ImageCache manager is invalid.` in the logs — there should be no matches.
2. Call `GameFrameXEntry.GetModule<IImageCacheManager>()`, the return value should not be `null`.
3. On a non-WebGL platform, execute `LoadImageAsync("https://example.com/test.png")` once, it should successfully download and cache to the directory pointed to by `Config.CachePath`.
