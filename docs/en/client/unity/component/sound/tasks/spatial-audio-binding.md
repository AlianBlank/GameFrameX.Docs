# How to Bind a Sound to an Entity or World Coordinates

Binding a sound to an Entity or a world coordinate point makes the playback position follow the bound object — this is the basic usage of spatial audio. This page presents three binding approaches (entity / world coordinates / either-or option), all based on the actual overloads of `SoundComponent.PlaySound`.

## Prerequisites

- A `SoundComponent` is already attached in the scene (menu `GameFrameX/Sound`).
- The sound asset has been added to a sound group (for sound group configuration, see "How to Configure Sound Groups").
- When binding to an entity, the entity must inherit from `GameFrameX.Entity.Runtime.Entity`.
- To hear the spatial effect, the audio asset must have 3D Sound enabled in the importer.

## Steps

### Method 1: Bind to an Entity (Entity)

When the entity moves, the sound automatically follows its position during playback.

```csharp
using GameFrameX.Sound.Runtime;
using GameFrameX.Entity.Runtime;

public class PlayerFootstep : Entity
{
    private int m_SoundSerialId;

    public void PlayFootstep()
    {
        // Pass the Entity overload directly, binding to the current player entity
        m_SoundSerialId = await GameEntry.Sound
            .PlaySound("Footstep", "SFX", this);
    }
}
```

The equivalent string overload:

```csharp
int serialId = await GameEntry.Sound.PlaySound("Footstep", "SFX", playerEntity);
```

### Method 2: Bind to World Coordinates

When not binding to an entity, simply pass in a `Vector3` to play at a fixed position.

```csharp
Vector3 explosionPos = new Vector3(10f, 0f, 5f);
int serialId = await GameEntry.Sound.PlaySound("Explosion", "SFX", explosionPos);
```

Source: [SoundComponent.cs#L498-L500](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L498-L500)

### Method 3: Specify Both Binding and Position

If you need to pass in both an entity and coordinates (or extra custom data), use `PlaySoundParams` + `SoundPlayContext.Create(...)`:

```csharp
using GameFrameX.Sound.Runtime;
using UnityEngine;

SoundPlayParams param = new SoundPlayParams
{
    Loop = false,
    Volume = 1f,
    SpatialBlend = 1f // Full 3D spatial blend
};

SoundPlayContext ctx = SoundPlayContext.Create(
    bindingEntity: playerEntity,
    worldPosition: playerEntity.transform.position,
    userData: "footstep-tag"
);

int serialId = await GameEntry.Sound.PlaySound(
    "Footstep", "SFX", 0, param, ctx, -1);
```

`SoundPlayContext` actually carries three fields, all allocated from the object pool:

```csharp
public static SoundPlayContext Create(Entity.Runtime.Entity bindingEntity, Vector3 worldPosition, object userData)
{
    SoundPlayContext playSoundInfo = ReferencePool.Acquire<SoundPlayContext>();
    playSoundInfo.m_BindingEntity = bindingEntity;
    playSoundInfo.m_WorldPosition = worldPosition;
    playSoundInfo.m_UserData = userData;
    return playSoundInfo;
}
```

Source: [SoundPlayContext.cs#L99-L106](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundPlayContext.cs#L99-L106)

### Method 4: Use SoundPlayOptions to Choose Either One

If it is inconvenient to decide the binding at the call site, use `SoundPlayOptions` and let the framework pick for you: **entity binding takes priority**.

```csharp
using GameFrameX.Sound.Runtime;

SoundPlayOptions options = SoundPlayOptions.Create(
    soundAssetName: "Explosion",
    soundGroupName: "SFX");
options.BindingEntity = enemyEntity;   // Takes priority when not null
// options.WorldPosition = enemyEntity.transform.position; // Ignored

int serialId = await GameEntry.Sound.PlaySound(options);
```

The field conventions come from the source code:

> `BindingEntity`: Gets or sets the entity the sound is bound to. Mutually exclusive with `WorldPosition`; entity binding takes priority.
> `WorldPosition`: Gets or sets the world position of the sound. Ignored when `BindingEntity` is not `null`.

## Common Variants

### Reading Binding Info in the Callback

In the `PlaySoundSuccess` event callback, `eventArgs.UserData` passes back the `SoundPlayContext` you provided, from which you can retrieve the bound entity and coordinates:

```csharp
private void OnPlaySoundSuccess(object sender, GameFramework.Event.PlaySoundSuccessEventArgs e)
{
    SoundPlayContext ctx = (SoundPlayContext)e.UserData;
    if (ctx != null)
    {
        Debug.Log($"Playback succeeded: entity={ctx.BindingEntity?.Name} position={ctx.WorldPosition}");
    }
}
```

Source: [SoundComponent.cs#L762-L763](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L762-L763)

### Spatial Sound for Non-Player Entities

When the sound effect is attached to an NPC, simply pass the `Entity` instance as the third argument — no need to worry about Transform references.

```csharp
GameEntry.Sound.PlaySound("NPC_Talk", "Voice", npcEntity);
```

## Common Mistakes

| Symptom | Cause | Fix |
|------|------|------|
| The sound plays but does not follow the entity | What was passed in is not an `Entity` subclass, but a plain MonoBehaviour / Transform | Pass an object that inherits from `GameFrameX.Entity.Runtime.Entity`, or switch to the `Vector3 worldPosition` overload |
| Both an entity and coordinates were passed, but only the coordinates take effect | With `SoundPlayOptions`, `BindingEntity != null` causes `WorldPosition` to be ignored | Explicitly set only one of them; if you want to keep both, store the context yourself in `userData` |
| Casting `UserData` in the callback throws an error | The context overload using `SoundPlayContext.Create` was not used; only the old `userData` parameter was used | Make sure you are calling the five- or six-parameter `PlaySound` overload, or pass a `SoundPlayContext` instance as `userData` |
| The sound keeps playing after the entity is destroyed | The bound entity was recycled but never notified to stop | Call `GameEntry.Sound.StopSound(serialId, fadeOutSeconds)` in the entity's `OnDestroy` |

## Background (Optional)

All `PlaySound` overloads ultimately construct a `SoundPlayContext` and hand it to `ISoundManager.PlaySound`. The agent (`ISoundAgent`) holds this context during playback so that event callbacks and stop logic can retrieve the original bound object. When `BindingEntity` is `null`, the world coordinates are used as the AudioSource position. See [SoundPlayContext.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundPlayContext.cs#L41-L117) for details.
