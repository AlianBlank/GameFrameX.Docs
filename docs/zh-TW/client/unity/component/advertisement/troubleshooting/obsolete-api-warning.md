# 如何處理舊版 API 編譯警告

當您的程式碼呼叫標記為 `[Obsolete]` 的介面時，Unity 編譯器會在主控台輸出 `CS0618` 警告，並建議替代 API。本頁說明如何快速定位這些呼叫並切換至新的 API。

## 快速診斷

| 原始警告 | 觸發的舊版 API | 建議的替代方案 |
|---|---|---|
| `Use Initialize(AdvertisementConfig) instead.` | `AdvertisementComponent.Initialize(string adUnitId, bool isDebug)`、`IAdvertisementManager.Initialize(...)`、`BaseAdvertisementManager.Initialize(...)` | `Initialize(AdvertisementConfig config)` |
| `Use Play(AdvertisementPlayOption) instead.` | `AdvertisementComponent.Show(Action<string>, Action<string>, Action<bool>)`、`AdvertisementComponent.Play(Action<bool>, string)`,以及 `IAdvertisementManager` / `BaseAdvertisementManager` 中對應的 `Play` 多載 | `Play(AdvertisementPlayOption option)` |

`[Obsolete]` 標記的實際位置可在 [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L150-L191)、[IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L62-L122)、[BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L144-L236) 中找到。

## 修正步驟

### 1. 將 `Initialize(string, bool)` 取代為 `Initialize(AdvertisementConfig)`

舊版簽章僅接受廣告單元 ID 與偵錯旗標；新簽章接受由 `AdvertisementConfig` 衍生的組態物件，可承載更多參數(子類別由特定廣告 SDK 實作提供，例如 `PangleAdvertisementConfig` 等)。

```csharp
// 舊版寫法 —— 會觸發 CS0618
[Obsolete("Use Initialize(AdvertisementConfig) instead.")]
adComponent.Initialize("ad-unit-id-xxx", isDebug: true);

// 新版寫法
var config = new MyAdSdkConfig // 具體子類別由所使用的廣告 SDK 提供
{
    adUnitId = "ad-unit-id-xxx",
    isDebug = true,
};
adComponent.Initialize(config);
```

`AdvertisementConfig` 基底類別的定義請見 [AdvertisementConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L41-L53)。

### 2. 將 `Show` / 多參數 `Play` 取代為 `Play(AdvertisementPlayOption)`

舊版的 `Show(success, fail, onShowResult)` 與 `Play(onShowResult, customData)` 使用零散的參數；新介面將所有回呼與延伸資料集中到單一 `AdvertisementPlayOption` 物件中。

```csharp
// 舊版寫法 —— 會觸發 CS0618
[Obsolete("Use Play(AdvertisementPlayOption) instead.")]
adComponent.Show(
    success: info => Debug.Log($"成功:{info}"),
    fail: err => Debug.LogError($"失败:{err}"),
    onShowResult: shown => Debug.Log($"展示:{shown}"));

// 新版寫法
var option = new AdvertisementPlayOption
{
    OnSuccess = info => Debug.Log($"成功:{info}"),
    OnFail = err => Debug.LogError($"失败:{err}"),
    OnShowResult = shown => Debug.Log($"展示:{shown}"),
    customData = "reward-key-001",
};
adComponent.Play(option);
```

`AdvertisementPlayOption` 的欄位定義請見 [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L80)。

### 3. 必須暫時保留舊版呼叫時，於局部抑制 CS0618

框架在內部轉發舊版呼叫時已經這麼處理了：

```csharp
#pragma warning disable CS0618
_advertisementManager.Initialize(AdUnitId, isDebug);
#pragma warning restore CS0618
```

僅在移轉期間、針對極少數無法立即替換的外部相依點使用 `#pragma warning disable CS0618`,並在新版本中儘快移除。

## 驗證

1. 在 Unity 中清除(`Clear`)主控台，並觸發一次廣告初始化與播放。
2. 確認主控台不再顯示關於 `Use Initialize(AdvertisementConfig) instead.` 或 `Use Play(AdvertisementPlayOption) instead.` 的 `CS0618` 警告。
3. 執行完整的「初始化 → 播放 → 回呼」流程，並確認 `OnSuccess` / `OnFail` / `OnShowResult` 皆正常觸發。
