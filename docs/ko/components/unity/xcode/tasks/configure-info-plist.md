# Info.plist 권한 및 URL Schemes 구성

Xcode 빌드 구성(JSON) 최상위의 `plist` 필드에 키-값 쌍을 추가하면, 빌드 후 `PostProcessBuildHelper`가 자동으로 이를 생성된 `Info.plist`에 기록합니다. 권한 설명 문구, URL Schemes, scheme 화이트리스트 등이 모두 이 한 곳의 구성만으로 완료되므로, Xcode 프로젝트를 수동으로 수정할 필요가 없습니다.

## 사전 조건

- Unity 프로젝트에 `com.gameframex.unity.xcode` 패키지가 설치되어 있어야 합니다.
- iOS 플랫폼으로 빌드해야 합니다(Xcode 관련 코드는 `#if UNITY_IOS` 하에서 컴파일됨).
- 최상위 `plist` 객체를 포함하는 Xcode 빌드 구성 파일이 준비되어 있어야 합니다(빈 객체여도 괜찮습니다):

```json
"plist": {},
```

## 작업 단계

1. Xcode 빌드 구성 파일을 열고 최상위 `plist` 필드로 이동합니다(없으면 빈 객체를 새로 생성합니다).
2. 카메라, 사진 앨범 사용 안내 등 권한 설명 문자열 키-값을 추가합니다.
3. 서드파티 로그인/앱 호출 콜백이 필요한 경우 `CFBundleURLTypes`를 추가하여 URL Schemes를 등록합니다.
4. 다른 App 설치 여부를 감지해야 하는 경우(iOS 9+ 필수 사항), `LSApplicationQueriesSchemes` 화이트리스트를 추가합니다.
5. iOS 빌드를 실행합니다. 콘솔에 `设置项目[Info.plist]开始` 및 `设置项目[Info.plist]结束` 로그가 표시되면 성공적으로 기록된 것입니다:

```csharp
LogHelper.Log("设置项目[Info.plist]开始");
//plist
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
SetPlist(project, plist.root, hashtable);
//기록
plist.WriteToFile(plistPath);
LogHelper.Log("设置项目[Info.plist]结束");
```

출처: [Editor/PostProcessBuildHelper.Plist.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Plist.cs#L11-L22)

6. 생성된 Xcode 프로젝트를 열고 Target → Info 탭에서 해당 키가 나타났는지 확인합니다.

다음은 바로 복사하여 사용할 수 있는 `plist` 구성 예시입니다(키 이름은 iOS 표준 Info.plist 키이며, 값 타입은 프레임워크가 지원하는 타입에 따라 결정됩니다. 아래 "배경"의 매핑 표 참조):

```json
"plist": {
    "NSCameraUsageDescription": "扫描二维码需要使用相机",
    "NSPhotoLibraryUsageDescription": "保存截图需要访问相册",
    "LSApplicationQueriesSchemes": [
        "weixin",
        "weixinULAPI"
    ],
    "CFBundleURLTypes": [
        {
            "CFBundleURLName": "com.yourcompany.yourgame",
            "CFBundleURLSchemes": ["yourgame"]
        }
    ]
}
```

구성의 `plist` 값은 빌드 시 `finalConfig.Get<Hashtable>("plist")`를 통해 읽혀 처리 흐름에 전달됩니다:

```csharp
// Info.Plist 설정
RunPlist(project, path, finalConfig.Get<Hashtable>("plist"));
```

## 일반적인 변형

- **여러 세트의 URL Schemes**: `CFBundleURLTypes` 배열에 딕셔너리 객체를 여러 개 추가하면 되며, 각 객체에는 `CFBundleURLName`과 `CFBundleURLSchemes`가 포함됩니다.
- **백그라운드 모드**: 마찬가지로 `plist` 아래에 작성합니다(예: `"UIBackgroundModes": ["audio"]`, 문자열 배열).
- **권한 문구 현지화**: 프레임워크의 현지화 구성을 대신 사용하면 `.lproj/InfoPlist.strings`가 자동 생성되고 `LSHasLocalizedDisplayName`이 `true`로 설정됩니다. 다국어 문구를 `plist` 키-값에 하드코딩하지 마세요:

```csharp
plistPath = Path.Combine(path, "Info.plist");
if (File.Exists(plistPath))
{
    ...
    plist.WriteToFile(plistPath);
    LogHelper.Log("Updated Info.plist: Set LSHasLocalizedDisplayName to true");
}
```

출처: [Editor/PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L99-L106)

## 자주 발생하는 오류

- **숫자는 정수로만 기록됨**: 기록 로직은 숫자 타입에 대해 일괄적으로 `SetInteger(key, Convert.ToInt32(...))`를 실행하므로 소수점 이하는 잘려나갑니다. 부동소수점 값을 기록하는 용도로 사용하지 마세요.
- **불리언 값이 문자열로 기록됨**: 실제 JSON 불리언(`true`/`false`)인 경우에만 `SetBoolean`이 호출됩니다. `"YES"` / `"true"`로 작성하면 문자열로 기록되어 Info.plist에서 타입이 맞지 않게 됩니다.
- **키 이름 오타에 대한 알림 없음**: 처리 방식은 "있는 것을 있는 그대로 기록"하는 항목별 덮어쓰기이므로, 오타가 있는 키(예: `NSCameraUsageDesciption`)는 오류를 발생시키지 않으며 Xcode의 Info 탭에서 수동으로 확인해야 합니다.
- **중첩 구조 계층이 잘못됨**: `CFBundleURLTypes`는 반드시 "배열 → 딕셔너리 → 배열"의 중첩이어야 하며, 계층이 하나라도 부족하면 Xcode에서 URL Types가 아닌 일반 문자열로 표시됩니다.

## 배경

`SetPlist`는 구성 값의 런타임 타입에 따라 재귀적으로 기록하며, 매핑 관계는 다음과 같습니다(배열 요소에도 동일하게 적용):

| 구성 값 타입 | Info.plist 기록 타입 | 호출 |
|------|------|------|
| 문자열 | string | `SetString` |
| 불리언 | boolean | `SetBoolean` |
| 숫자(double) | integer | `SetInteger`(`Convert.ToInt32`) |
| 배열(ArrayList) | array | `CreateArray` / `AddArray` |
| 객체(Hashtable) | dict | `CreateDict` / `AddDict` |

```csharp
if (vType == typeof(string))
{
    node.SetString(key, (string)val);
}
else if (vType == typeof(bool))
{
    node.SetBoolean(key, (bool)val);
}
else if (vType == typeof(double))
{
    node.SetInteger(key, Convert.ToInt32((double)val));
}
else if (vType == typeof(ArrayList))
{
    var t = node.CreateArray(key);
    var array = val as ArrayList;
    SetPlist(proj, t, array);
}
else if (vType == typeof(Hashtable))
{
    var t = node.CreateDict(key);
    var table = val as Hashtable;
    SetPlist(proj, t, table);
}
```
