# Scheduling Asynchronous Tasks

`TaskPool<T>` manages asynchronous tasks through a "task agent + priority queue" approach: you register several `ITaskAgent<T>` instances with the pool, submit `TaskBase`-derived tasks, and the pool distributes tasks to idle agents by priority during each `Update` call. This page explains how to integrate and schedule asynchronous tasks.

## Prerequisites

- The `GameFrameX.Runtime` assembly has been imported (the task pool is located in [Runtime/Base/TaskPool](/Runtime/Base/TaskPool/TaskPool.cs#L44-L64), namespace `GameFrameX.Runtime`).
- Custom tasks inherit from `TaskBase`, and custom agents implement `ITaskAgent<T>`.
- Task objects should be obtained through `ReferencePool.Acquire<T>()`, and are automatically recycled after the pool releases them ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L11-L21)).

## Steps

1. **Define the task type**. Inherit from `TaskBase` and override at least the `Description` property. Use `Initialize(serializeId, tag, priority, userData)` to configure priority and custom data.

   ```csharp
   using GameFrameX.Runtime;

   public class LoadAssetTask : TaskBase
   {
       public string AssetName { get; private set; }

       public override string Description => $"LoadAsset:{AssetName}";

       public void Init(string assetName)
       {
           AssetName = assetName;
           Initialize(0, assetName, 0, null);
       }
   }
   ```

   Source: [Runtime/Base/TaskPool/TaskBase.cs](/Runtime/Base/TaskPool/TaskBase.cs)

2. **Implement the task agent**. Implement `Initialize / Update / Shutdown / Start / Reset` from `ITaskAgent<T>`. Return `StartTaskStatus.CanResume / CanNotResume` in `Start`, and mark completion via `Task.Done = true` ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L23-L62)).

   ```csharp
   public class LoadAssetAgent : ITaskAgent<LoadAssetTask>
   {
       public LoadAssetTask Task { get; private set; }
       public bool IsInitialized { get; private set; }
       public bool IsShutdown { get; private set; }

       public void Initialize() { IsInitialized = true; }
       public void Update(float e, float re) { /* After the real loading completes, set Task.Done = true */ }
       public void Shutdown() { IsShutdown = true; }

       public StartTaskStatus Start(LoadAssetTask task)
       {
           Task = task;
           return StartTaskStatus.CanResume; // For synchronous completion, return CanNotResume
       }

       public void Reset() { Task = null; }
   }
   ```

   Source: [Runtime/Base/TaskPool/ITaskAgent.cs](/Runtime/Base/TaskPool/ITaskAgent.cs)

3. **Create the task pool and register agents**. Instantiate `TaskPool<T>`, call `AddAgent` to register one or more agents; the number of agents is the maximum number of concurrent tasks.

   ```csharp
   var taskPool = new TaskPool<LoadAssetTask>();
   taskPool.AddAgent(new LoadAssetAgent());
   taskPool.AddAgent(new LoadAssetAgent()); // Concurrency: 2
   ```

   Source: [Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L58-L64)

4. **Submit tasks**. Obtain a task object through `ReferencePool.Acquire`, call `Initialize`, then call `AddTask`. Tasks are sorted by `priority` in descending order: the larger the value, the earlier they execute ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L127-L145)).

   ```csharp
   var task = ReferencePool.Acquire<LoadAssetTask>();
   task.Init("Config/battle.json");
   taskPool.AddTask(task);

   var urgent = ReferencePool.Acquire<LoadAssetTask>();
   urgent.Initialize(1, "Player/Avatar", 10, null); // priority=10 executes first
   taskPool.AddTask(urgent);
   ```

5. **Drive Update every frame**. Call `taskPool.Update(elapseSeconds, realElapseSeconds)` in the game's main loop. The pool automatically: ① advances all `WorkingAgent`s; ② distributes the highest-priority task from the waiting queue to an idle agent ([Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L136-L145)).

   ```csharp
   void Update()
   {
       taskPool.Update(Time.deltaTime, Time.unscaledDeltaTime);
   }
   ```

6. **Pause and cleanup**. To freeze scheduling, set `taskPool.Paused = true`; `Update` will return directly without triggering any task processing ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L185-L196)). When no longer in use, call `RemoveAllTasks()` + `Shutdown()`, and `ReferencePool.ClearAll()` to release task objects.

## Common Variants

| Scenario | Approach |
|------|------|
| Asynchronous time-consuming tasks (resource loading, network) | `Start` returns `CanResume`; poll progress in `Update`, and set `Task.Done = true` when complete |
| Tasks that can complete synchronously | `Start` returns `CanNotResume`; the pool will mark the agent as available for dispatch in the next frame |
| Control concurrency limit | Register only N `ITaskAgent<T>` instances; excess tasks remain in the `WaitingTasks` queue |
| Query task status | Use `GetAllTaskInfos()` to get `TaskInfo[]` (including `Priority`, `Status`, `Description`) |
| Cancel a specific task | `RemoveTask(serializeId, tag)` returns the object to the `ReferencePool` when matched |

## Common Errors

| Error | Description | Avoidance |
|------|------|------|
| `AddAgent(null)` | Throws `GameFrameworkException` ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L99-L101)) | Perform a null check before registering |
| Too few agents | The waiting queue accumulates; `WaitingTaskCount` stays greater than 0 | Register agents according to the expected concurrency |
| Forgetting to call `Update` | Tasks will never start executing | Hook `taskPool.Update` into the MonoBehaviour main loop or the framework's `GameFramework` dispatch |
| Agent's `Start` never returns `CanNotResume` nor sets `Task.Done` | The agent is permanently occupied; the number of idle agents doesn't grow | Explicitly set `Done = true` in the async callback or `Update` |
| Creating tasks directly via `new T()` | Tasks don't go through the reference pool and cannot be recycled for reuse | Use `ReferencePool.Acquire<T>()` |

## Background (Optional)

The task pool follows a "task = data / agent = executor" separation pattern: the pool itself is only responsible for dispatching and recycling, while the actual execution is delegated to `ITaskAgent<T>`. Priority is maintained by the `m_WaitingTasks` linked list in `priority` descending order, ensuring that the highest-priority task is always dequeued first. `Paused` is used for scenarios such as game pause or scene switching where background tasks need to be frozen.

For collaboration between the task pool and other subsystems, see "ReferencePool Reference".
