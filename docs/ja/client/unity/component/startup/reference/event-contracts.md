# イベントと通知の契約

起動フローは重要なノードで GameFrameX イベントバスを通じて結果をブロードキャストし、サブスクライバーは StartupManager の内部状態に手を加えることなく通知を受け取ります。本ページでは、公開されているすべてのイベント引数型、イベント ID、および使用契約を収録しています。

## イベント契約早見表

| イベント引数型 | イベント ID(EventId) | 発火タイミング | 主要フィールド |
|--------------|------------------|----------|----------|
| `StartupCompletedEventArgs` | `GameFrameX.Startup.Runtime.Events.StartupCompletedEventArgs` | `ProcedureGameLauncherState` がホットアップデートと UI Dispose を完了した後、フローが正常に終了したとき | なし |
| `StartupFailedEventArgs` | `GameFrameX.Startup.Runtime.Events.StartupFailedEventArgs` | いずれかの Procedure がネットワークまたはビジネス上の失敗によりフローを停止したとき | `FailedProcedureName`、`FailedUrl`、`ErrorMessage` |

イベント ID は `typeof(X).FullName` パターンを採用しており、GameFrameX ファミリー全体と一貫性を保っています。サブスクライブ時は静的フィールド `EventId` を使用し、文字列をハードコーディングしないでください。

## StartupCompletedEventArgs

起動の成功完了イベント。フローが `ProcedureGameLauncherState` に到達し、ホットアップデートのロードと UI Dispose を完了した後に一度だけ発火されます。

```csharp
public sealed class StartupCompletedEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(StartupCompletedEventArgs).FullName;
    public override string Id => EventId;

    public static StartupCompletedEventArgs Create()
    {
        return ReferencePool.Acquire<StartupCompletedEventArgs>();
    }

    public override void Clear()
    {
        // フィールドなし、空の実装
    }
}
```

サブスクライブ例:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupCompletedEventArgs.EventId,
    (sender, args) =>
    {
        // メインシーンへ遷移するか、次のモジュールをロードする
    });
```

## StartupFailedEventArgs

起動失敗イベント。いずれかの Procedure がネットワークまたはビジネス上の失敗によりフローを停止したときに発火されます。

```csharp
public sealed class StartupFailedEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(StartupFailedEventArgs).FullName;
    public override string Id => EventId;

    public string FailedProcedureName { get; private set; }
    public string FailedUrl { get; private set; }
    public string ErrorMessage { get; private set; }

    public static StartupFailedEventArgs Create(string procedureName, string url, string errorMessage)
    {
        var args = ReferencePool.Acquire<StartupFailedEventArgs>();
        args.FailedProcedureName = procedureName ?? string.Empty;
        args.FailedUrl = url ?? string.Empty;
        args.ErrorMessage = errorMessage ?? string.Empty;
        return args;
    }

    public override void Clear()
    {
        FailedProcedureName = string.Empty;
        FailedUrl = string.Empty;
        ErrorMessage = string.Empty;
    }
}
```

フィールド説明：

| フィールド | 型 | 説明 |
|------|------|------|
| `FailedProcedureName` | `string` | 失敗が発生した Procedure のステート名。`null` は空文字列に正規化されます |
| `FailedUrl` | `string` | 最後に試行して失敗した URL。ネットワーク以外の失敗の場合は空文字列 |
| `ErrorMessage` | `string` | エラーの説明 |

サブスクライブ例:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupFailedEventArgs.EventId,
    (sender, args) =>
    {
        var failed = (StartupFailedEventArgs)args;
        Debug.LogError($"启动失败:{failed.FailedProcedureName} {failed.ErrorMessage}");
    });
```

## 発火箇所

イベントは `StartupProcedureUtility` を通じて、フローの終了ノードで一元的に発火されます:

```csharp
// 失敗パス
GameEntry.GetComponent<EventComponent>().Fire(
    procedureOwner,
    StartupFailedEventArgs.Create(procedureName, failedUrl, errorMessage));

// 成功パス
GameEntry.GetComponent<EventComponent>().Fire(
    procedureOwner,
    StartupCompletedEventArgs.Create());
```

## 使用契約

1. **new でインスタンスを作成しない**:両方のイベント引数は `Create(...)` 静的メソッドを通じて `ReferencePool` から取得され、GC を回避します。
2. **Id を変更しない**:イベント ID は `typeof(T).FullName` であり、GameFrameX ファミリー全体のイベントプロトコルと一致しています。
3. **空文字列への統一**：失敗イベントの 3 つのフィールドは `Create` の時点で `null` を空文字列に正規化するため、サブスクライブ側で追加の null チェックは不要です。
4. **手動で Clear しない**：サブスクライバーはイベント引数の参照を保持すべきではありません。イベント発火後、フレームワークによって参照プールへ回収されます。
