# 實作玩家郵件(Mail)模組

透過本頁面，你能在 GameFrameX.Server 中啟用並擴充玩家郵身子系統：它由 `MailComponent` 承載玩家信箱(`MailBoxState`)、以 Campaign 形式批次傳送、並支援領取附件、撤回作廢、過期清理等完整生命週期。

## 前置條件

- 已基於 GameFrameX.Server 範本建立專案，玩家 Actor 能正常登入並落庫。
- 已熟悉 [Component / StateComponent 的基本用法](https://github.com/GameFrameX/GameFrameX.Server/blob/main/src/Example.cs),以及 Admin 後台 HTTP Handler 的註冊方式。
- 郵件獎勵道具需已在物品/獎勵模組中實作，`MailAttachmentInstance.ItemId` 參照對應物品表。

## 操作步驟

1. **掛載玩家郵件元件**。元件以玩家 Actor 為粒度，直接繼承 `StateComponent<MailBoxState>`,透過 `[ComponentType(GlobalConst.ActorTypePlayer)]` 自動綁定。

   ```csharp
   using GameFrameX.Apps.Player.Mail.Component;
   using GameFrameX.Apps.Player.Mail.Entity;

   namespace GameFrameX.Apps.Player.Mail.Component;

   /// <summary>
   /// 玩家郵件元件,掛載玩家粒度的信箱 <see cref="MailBoxState"/>。
   /// </summary>
   [ComponentType(GlobalConst.ActorTypePlayer)]
   public sealed class MailComponent : StateComponent<MailBoxState>
   {
   }
   ```

   Source: [MailComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/Component/MailComponent.cs#L34-L44)

2. **選擇郵件類型**。列舉編號發布後不可變，新增類型只能附加、不能重複使用舊值。

   ```csharp
   public enum MailType
   {
       System = 0,         // 系統郵件(如維護補償)
       Operation = 1,      // 營運郵件(Admin 發布,按過濾條件惰性建立)
       Compensation = 2,   // 補償郵件(定向補償,重複使用 Campaign 落庫)
   }
   ```

   Source: [MailType.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/MailType.cs#L37-L53)

3. **理解郵件狀態機**。`MailStatus` 決定一封玩家郵件實例的流轉:`Unread → Read → Claimed → Deleted`,或在撤回/過期時進入 `Revoked` / `Expired` 終態。

   ```csharp
   public enum MailStatus
   {
       Unread = 0,
       Read = 1,
       PartialClaimed = 2,
       Claimed = 3,
       Deleted = 4,    // 終態
       Revoked = 5,    // 終態
       Expired = 6,    // 終態
   }
   ```

   刪除僅在「無附件」或「附件全部已領」時被允許；撤回不會回滾已領附件。  
   Source: [MailEnums.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/MailEnums.cs#L43-L65)

4. **配套維度列舉**。`ReadStatus`(衍生自 `ReadTime`)、`AttachmentStatus`(列表展示用，來源資料為 `MailStatus` + 各附件 `ClaimStatus`)、`ClaimStatus`(單一附件： `Claimable` / `Claimed` / `Discarded`)。

   ```csharp
   public enum ClaimStatus
   {
       Claimable = 0,
       Claimed = 1,      // 終態,撤回不回滾
       Discarded = 2,    // 撤回/過期作廢未領附件
   }
   ```

   Source: [MailEnums.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/MailEnums.cs#L100-L109)

5. **使用 Admin HTTP Handler 發布/撤回 Campaign**。儲存庫已提供四類管理介面，可直接掛到 Admin 後台：

   - `PreviewMailCampaignHttpHandler`:預演命中玩家數與道具估算。
   - `PublishMailCampaignHttpHandler`:正式發布，落地 `MailCampaignState`。
   - `QueryMailCampaignHttpHandler`:查詢 Campaign 狀態(草稿/已發布/已撤回)。
   - `RevokeMailCampaignHttpHandler`:撤回 Campaign,已發郵件按 `MailStatus.Revoked` 處理。

   實際串接時按現有 Handler 註冊方式掛到 Admin 路由即可，典型位置：
   - [PreviewMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/PreviewMailCampaignHttpHandler.cs)
   - [PublishMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/PublishMailCampaignHttpHandler.cs)
   - [QueryMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/QueryMailCampaignHttpHandler.cs)
   - [RevokeMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/RevokeMailCampaignHttpHandler.cs)

6. **實作用戶端讀取與領取入口**。在玩家側 `MailAttachmentClaim` 之類的請求 Handler 中完成三件事：
   - 讀信:`Unread → Read`(`ReadStatus.Read`,冪等)。
   - 領取附件：逐個 `MailAttachmentInstance` 更新 `ClaimStatus` 至 `Claimed`,全部領取後整體進入 `MailStatus.Claimed`。
   - 刪除：僅當 `MailStatus == Claimed` 且無未領附件時允許置 `Deleted`。

   參考既有領取測試案例確認邊界： [MailAttachmentClaimTests.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix.Tests/MailAttachmentClaimTests.cs)、註冊相關： [MailCampaignRegistryTests.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix.Tests/MailCampaignRegistryTests.cs)。

## 常見變體

- **系統補償**：走 `MailType.System`,無需 Campaign,直接在遊戲程式碼裡向玩家 `MailComponent` 寫入 `MailState` 即可。
- **營運全服推送**：走 `MailType.Operation` + `PublishMailCampaignHttpHandler`,按 `MailCampaignFilter` 命中惰性建立到玩家信箱。
- **定向補償**：走 `MailType.Compensation`,重複使用 Campaign 落庫但繞過全服過濾，直接指定目標玩家 ID。

## 常見錯誤

- **列舉重複使用**：把 `System = 0` 改號或刪號，會導致線上玩家存檔中的 `MailType` 意義漂移。務必只附加、不重複使用。
- **撤回誤用**：對已領玩家附件做回滾。`Claimed` 附件在撤回時不可回退(`Discarded` 只針對未領附件)。
- **刪除未領附件**：未校驗 `ClaimStatus` 就將郵件置 `Deleted`,會導致玩家憑空損失道具。
- **Component 未掛載**：忘記給玩家 Actor 裝配 `MailComponent`,會出現 `MailComponentAgent` 呼叫 null 例外。

## 背景(可選)

`MailComponent` 僅作為狀態容器，真正的過濾命中、惰性建立、過期清理等邏輯集中在 `MailComponentAgent` 與 `MailCampaignState`;Campaign 是「一份定義 + N 份玩家實例」的二段式落庫，既便於營運審稿，也便於按 Campaign 維度做撤回。玩家側的「狀態機 + 維度衍生」(`MailStatus` / `ReadStatus` / `AttachmentStatus` / `ClaimStatus`)用於在不改來源資料的前提下提供列表展示與領取入口的穩定契約。
