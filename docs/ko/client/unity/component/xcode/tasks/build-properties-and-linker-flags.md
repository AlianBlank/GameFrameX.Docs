# Build Properties 및 링커 플래그 설정

`XCodeConfig.json`의 `unityMain` / `unityFramework` 섹션 아래에 `properties`(Build Settings)와 `otherLinkerFlag`(링커 플래그, 예: `OTHER_LDFLAGS`)를 작성하면, Unity가 iOS 프로젝트를 내보낸 후 빌드 후처리에 의해 생성된 Xcode 프로젝트에 자동으로 기록되므로, Xcode를 직접 열어 Build Settings를 수정할 필요가 없습니다.

## 사전 조건

- Unity가 iOS 플랫폼으로 전환되어 있어야 합니다.
- 프로젝트에 `XCodeConfig.json`이라는 이름의 설정 파일이 존재해야 합니다(파일명이 정확히 일치해야 하며, 후처리에서 해당 파일명 기준으로 스캔합니다). 저장소에 포함된 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) 또는 [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json)을 복사해 이름을 변경한 후 사용할 수 있습니다.

## 작업 단계

1. 프로젝트에 `XCodeConfig.json`을 생성합니다(내용은 저장소에 포함된 템플릿과 예시를 참고하세요).
2. 대상 target을 결정합니다: 메인 실행 프로그램 Unity-iPhone은 `unityMain` 섹션에, 동적 라이브러리는 `unityFramework` 섹션에 작성하며, 두 섹션의 구조는 완전히 동일합니다.
3. `properties` 필드로 Build Settings를 수정하며, 세 가지 연산자를 지원합니다:

| 연산자 | 실제 호출되는 PBXProject API | 기능 |
|--------|---------------------------|------|
| `=` | `SetBuildProperty(targetGuid, key, value)` | 특정 Build Setting 값을 직접 덮어씀 |
| `+` | `UpdateBuildProperty(targetGuid, key, list, null)` | 리스트형 Build Setting에 값 추가 |
| `-` | `UpdateBuildProperty(targetGuid, key, null, list)` | 리스트형 Build Setting에서 값 제거 |

   세 가지 연산자의 파싱 로직(`SetBuildProperties`에서 발췌):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}

Hashtable addTable = table.Get<Hashtable>("+");
// ... ArrayList를 List<string>으로 변환하는 부분 생략 ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), list, null);

Hashtable removeTable = table.Get<Hashtable>("-");
// ... ArrayList를 List<string>으로 변환하는 부분 생략 ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), null, list);
```

출처: [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L58)

4. 위 표의 구조에 따라 JSON을 작성합니다(키 `=`/`+`/`-` 아래의 키-값이 곧 Build Setting 이름과 값이며, `+`/`-`의 값은 반드시 배열이어야 합니다):

```json
{
  "unityFramework": {
    "properties": {
      "=": { "ENABLE_BITCODE": "NO" },
      "+": { "OTHER_LDFLAGS": ["-lxml2"] },
      "-": { "OTHER_LDFLAGS": ["-ObjC"] }
    }
  }
}
```

5. `otherLinkerFlag` 필드로 링커 플래그를 추가하며, `properties`와 같은 레벨에 위치합니다. 예시 파일의 실제 작성 예:

```json
"otherLinkerFlag": {
  "OTHER_LDFLAGS": ["-ObjC"]
}
```

출처: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L152-L154)

   플래그는 해당 Build Setting에 항목별로 하나씩 추가됩니다(각 항목마다 `AddBuildProperty`를 한 번씩 호출):

```csharp
foreach (DictionaryEntry kv in table)
{
    var keyStr = kv.Key.ToString().Trim();
    if (kv.Value is ArrayList list)
    {
        // 배열: 항목별로 AddBuildProperty
        foreach (var part in parts)
        {
            proj.AddBuildProperty(targetGuid, keyStr, part);
        }
    }
    else
    {
        // 문자열: 직접 AddBuildProperty
        proj.AddBuildProperty(targetGuid, keyStr, kv.Value.ToString().Trim());
    }
}
```

출처: [PostProcessBuildHelper.OtherLinkFlag.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.OtherLinkFlag.cs#L15-L47)

6. iOS 빌드를 트리거합니다. `[PostProcessBuild(888)]`의 `OnPostProcessBuild`가 모든 `XCodeConfig.json`을 읽어 하나의 설정으로 병합한 뒤, `GetUnityMainTargetGuid()`와 `GetUnityFrameworkTargetGuid()`에 차례로 설정을 적용하고, 마지막으로 `Unity-iPhone.xcodeproj/project.pbxproj`에 다시 기록합니다.

```csharp
Run(project, project.GetUnityMainTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityMain"), path);
Run(project, project.GetUnityFrameworkTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityFramework"), path);
```

출처: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L104)

## 일반적인 변형

- **배열 또는 단일 문자열 모두 가능**: `otherLinkerFlag`의 값을 배열(예: `["-ObjC", "-lxml2"]`)로 작성하면 항목별로 하나씩 추가되고, 단일 문자열로 작성하면 전체를 한 번만 추가합니다. 두 가지 작성 방식 모두 소스 코드에 처리 분기가 존재합니다.
- **여러 설정 파일 병합**: 스캔된 모든 `XCodeConfig.json`은 순서대로 병합되며, 나중에 병합된 내용이 먼저 병합된 내용을 덮어씁니다. 채널(`SettingLoader.GetChannel()`)이 활성화된 경우 `XCodeConfig.{channel}.json`이 마지막에 병합되어 우선순위가 가장 높습니다.
- **동일 섹션 내 기타 필드**: `unityMain` / `unityFramework` 섹션에는 `frameworks`, `libs`, `files`, `folders`, `filesCompileFlag`, `runPathSearchPaths` 등의 필드도 동시에 설정할 수 있으며, 동일한 `Run` 호출에서 순서대로 적용됩니다.

## 일반적인 오류

| 증상 / 로그 원문 | 원인 | 해결 방법 |
|-----------------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 파일명이 `XCodeConfig.json`이 아니거나 해당 위치가 스캔 범위 밖에 있음 | 올바른 파일명으로 변경하고 스캔 가능한 위치에 배치 |
| `{jsonPath} 解析失败, 跳过合并` | JSON 문법 오류 | JSON 검증 도구로 수정한 후 다시 빌드 |
| `合并后的配置为空，跳过设置` | 모든 파일의 파싱이 실패함 | 각 설정 파일의 문법 확인 |
| `properties` / `otherLinkerFlag`를 수정했지만 Xcode에 적용되지 않음 | 필드를 JSON 최상위 레벨에 작성함 | 이 두 필드는 반드시 `unityMain` 또는 `unityFramework` 섹션 내에 작성해야 하며, `Run`은 이 두 섹션에서만 읽음 |
| `+` / `-` 연산이 적용되지 않음 | 값을 문자열로 작성함 | 소스 코드에서 `i.Value as ArrayList`로 읽기 때문에 문자열은 빈 리스트가 되며, 반드시 배열로 작성해야 함 |

## 배경

`properties`는 최종적으로 `SetBuildProperty` / `UpdateBuildProperty`로, `otherLinkerFlag`는 `AddBuildProperty`로 연결되며, 모두 Unity에 내장된 `UnityEditor.iOS.Xcode.PBXProject`의 표준 인터페이스입니다. 차이점은 전자는 덮어쓰기 및 추가/제거를 지원하는 반면, 후자는 추가만 수행한다는 것입니다. 전체 프로세스는 `[PostProcessBuild(888)]` 콜백에 연결되어 있으며, `target == BuildTarget.iOS`일 때만 실행됩니다.
