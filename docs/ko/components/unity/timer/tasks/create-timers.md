# 타이머 생성: 반복, 1회 및 프레임별

`TimerComponent`의 세 가지 진입점만으로 모든 타이머를 생성할 수 있습니다: `Add`(반복/무한 반복 가능), `AddOnce`(한 번만 실행), `AddUpdate`(매 프레임 실행). 셋 모두 타이머 ID를 반환하며, 이후 일시 중지, 재개, 조회 및 제거에 사용할 수 있습니다.

## 사전 조건

- 씬에 GameFrameX 프레임워크 오브젝트가 이미 존재하고 `TimerComponent`가 부착되어 있어야 합니다(메뉴 경로 `GameFrameX/Timer`, `[AddComponentMenu("GameFrameX/Timer")]`, [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L12-L16) 참조).
- 비즈니스 코드에서 네임스페이스 `GameFrameX.Timer.Runtime`를 참조합니다.

## 작업 단계

1. `TimerComponent` 참조를 가져옵니다(예: GameFrameX의 컴포넌트 가져오기 방식 사용).

2. 필요에 따라 생성 메서드를 선택합니다:

| 요구 사항 | 메서드 | 실제 시그니처 |
|------|------|----------|
| N초마다 실행, M번 반복 또는 무한 | `Add` | `int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)` |
| N초 지연 후 한 번만 실행 | `AddOnce` | `int AddOnce(float interval, Action<object> callback, object callbackParam = null)` |
| 매 프레임 실행 | `AddUpdate` | `int AddUpdate(Action<object> callback)` / `int AddUpdate(Action<object> callback, object callbackParam)` |

시그니처 및 기본값 출처: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L80).

3. 콜백을 전달합니다(타입은 `Action<object>`로 고정, 매개변수는 `null` 가능). 반환된 ID를 저장합니다.

```csharp
// 1) 무한 반복: 1초마다 한 번 트리거되며, repeat에 0을 전달하면 무한 반복
int heartbeatId = timerComponent.Add(
    1f, 0,
    param => Debug.Log("heartbeat " + param),
    "tick",
    TimerTimeScale.Unscaled);

// 2) 단일 실행: 3초 후 한 번 실행된 뒤 자동으로 제거됨
int delayId = timerComponent.AddOnce(3f, param => Debug.Log("done"));

// 3) 프레임별: 매 프레임 Update마다 한 번 호출
int frameId = timerComponent.AddUpdate(param => { /* 매 프레임 로직 */ });
```

출처: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L80)

4. ID로 후속 관리를 수행합니다:

```csharp
timerComponent.Pause(id);        // 일시 중지(일시 중지 중 시간이 누적되지 않음)
timerComponent.Resume(id);       // 재개, 일시 중지 지점부터 누적 계속
timerComponent.Exists(id);       // 여전히 존재하며 활성 상태인지 확인
timerComponent.GetRemaining(id); // 남은 초; 존재하지 않으면 -1 반환
timerComponent.GetElapsed(id);   // 누적된 초; 존재하지 않으면 -1 반환
timerComponent.Remove(id);       // 제거
```

출처: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L105-L118), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L124-L146), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L190-L200)

## 일반적인 변형

### 반복 횟수 제한 및 완료 감지

`repeat > 0`은(는) 해당 횟수만큼 트리거된 후 자동으로 제거됨을 의미합니다; `onComplete`는 타이머가 완료/제거될 때 트리거됩니다.

```csharp
// 5회 반복, 0.5초마다 한 번; 5번째 트리거 후 자동 제거되고 onComplete 콜백이 호출됨
int id = timerComponent.Add(
    0.5f, 5,
    param => Debug.Log("tick"),
    onComplete: () => Debug.Log("all ticks finished"));
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)(`Repeat`가 0으로 감소하면 `Deleted`로 표시되고 제거 큐에 진입), [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L134-L147)(제거 시 `OnComplete` 실행)

### timeScale의 영향을 받는 타이머

`timeScale`의 기본값은 `TimerTimeScale.Unscaled`입니다(`Time.timeScale`의 영향을 받지 않음); 게임 일시 중지 시 카운트다운도 함께 멈추고 싶다면 `TimerTimeScale.Scaled`를 전달하세요:

```csharp
// timeScale 변경 시(예: 게임 일시 중지), Scaled 타이머의 진행도 함께 느려지거나 멈춤
int id = timerComponent.Add(2f, 0, OnTick, timeScale: TimerTimeScale.Scaled);
```

출처: [TimerTimeScale.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerTimeScale.cs#L6-L13), [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

### tag로 그룹 관리

생성 시 `tag`를 전달하면, 이후 그룹 전체를 일시 중지/재개/제거할 수 있습니다:

```csharp
timerComponent.Add(1f, 0, OnTick, tag: "battle");
timerComponent.PauseByTag("battle");   // 해당 그룹 전체 일시 중지
timerComponent.ResumeByTag("battle");  // 해당 그룹 전체 재개
timerComponent.RemoveByTag("battle");  // 해당 그룹 전체 제거
timerComponent.HasTag("battle");       // 해당 그룹에 아직 활성 타이머가 있는지 확인
```

출처: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L148-L183)

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 로그에 `timer callback is null, {interval},{repeat}`가 출력되고 반환된 ID가 0 | 콜백에 `null`을 전달함 | 호출하기 전에 null 검사를 먼저 수행; 매니저가 바로 경고를 출력하고 생성을 거부함 |
| "한 번만 실행"을 기대했는데 반복적으로 트리거됨 | `Add`의 `repeat`에 0을 전달함(0은 무한 반복을 의미) | 1회 작업에는 `AddOnce` 사용, 또는 `Add`에 `repeat: 1` 전달 |
| `interval`에 음수나 0을 전달했는데 "매 프레임 트리거"됨 | `interval <= 0`은 프레임별 타이머로 처리됨 | 프레임별 동작이 필요하면 `AddUpdate` 사용; 잘못된 interval을 `Add`에 전달하지 마세요 |
| 동일한 콜백을 다시 Add하면 카운트가 "초기화"됨 | 콜백을 키로 사용하여, 중복 `Add` 시 그 자리에서 매개변수를 업데이트하고 `Elapsed`를 0으로 초기화함 | 여러 병렬 인스턴스가 필요할 때는 서로 다른 콜백 사용(예: 클로저) |
| 일시 중지 후 `GetRemaining`이 변하지 않음 | 일시 중지 중 시간이 누적되지 않아 남은 시간이 그대로 고정됨 | 예상된 동작임; `Resume` 호출 후 계속 진행됨 |
| 콜백에서 예외 발생 | 기본값 `CatchCallbackExceptions = false`로, 예외가 상위로 전파됨 | 예외를 무시해야 할 때는 `TimerManager.CatchCallbackExceptions = true`로 설정, 예외는 `Timer callback error > ...` 형식의 Warning으로 기록됨 |

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L53-L56), [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L83-L84), [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L166-L187), [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L219-L243)

## 검증

- 생성 후 `timerComponent.Exists(id)`를 호출하여 `true`가 반환되면 등록된 것입니다([TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L110-L118)).
- `GetRemaining(id)` / `GetElapsed(id)`로 카운트다운을 관찰하여 간격과 일시 중지 효과를 검증합니다; 타이머가 존재하지 않으면 둘 다 `-1`을 반환합니다([TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L185-L200)).
- 1회용 타이머는 트리거 후 `Exists(id)`가 `false`로 바뀌어야 합니다(트리거 완료 즉시 제거됨, [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L121) 참조).

## 배경

`TimerComponent`는 단순한 얇은 래퍼일 뿐이며, 실제 로직은 `TimerManager`에 있습니다(`ITimerManager` 인터페이스 구현). 매니저는 콜백 함수를 키로 삼아 `TimerItem`을 유지 관리하며(`Interval`, `Repeat`, `Elapsed`, `IsPaused`, `Tag`, `OnComplete` 등의 필드 포함), 매 프레임 `Update`에서 `TimeScaleMode`에 따라 시간 소스를 선택해 `Elapsed`를 누적하고, `Interval`에 도달하면 콜백을 대기 실행 목록에 넣은 뒤 락 밖에서 실행하여 다른 스레드가 차단되지 않도록 합니다; 한 번 초과된 여분은 클램프 처리됩니다(0.03s 초과 시 0으로 초기화), 낮은 프레임 속도에서 연속 발동을 방지하기 위함입니다. 비동기 대기 스타일의 타이머 사용법에 대해서는 `TimerAsyncExtensions`를 참조하세요.
