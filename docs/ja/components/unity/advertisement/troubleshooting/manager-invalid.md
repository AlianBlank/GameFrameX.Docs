# Advertisement manager is invalid の対処法

ランタイムコンソールに `Log.Fatal("Advertisement manager is invalid.")` が出力された場合、`AdvertisementComponent.Awake()` が `GameFrameworkEntry.GetModule<IAdvertisementManager>()` で広告マネージャーのインスタンスを取得できず、コンポーネントは直接 return され、その後の `Start`、`Initialize` などのフローは実行されません。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| ログに `Advertisement manager is invalid.` エラーが出力される | `GameFrameworkEntry` に `IAdvertisementManager` の実装が登録されていない | シーンに `AdvertisementComponent` をアタッチし、Inspector で `BaseAdvertisementManager` を継承する具名管理器クラスの完全名を入力する |
| エラーは同じだが、コンポーネントはアタッチ済み | `componentType` フィールドの入力ミス（クラス名のスペルミス、名前空間の欠落、`BaseAdvertisementManager` を継承していない） | 「命名空间・クラス名」の完全名を入力し、クラスが `BaseAdvertisementManager` を継承し `IAdvertisementManager` を実装していることを確認する |
| エラーは同じだが、実行時のあるプラットフォームの管理器が `null` になる | そのプラットフォームの広告 SDK パッケージが導入されておらず、アセンブリ内に実装クラスが見つからない | 対応プラットフォームの SDK をインストールする（後述「修正手順」参照）または一時的にインストール済みプラットフォームの `componentType` に切り替える |
| エラーは同じだが、Debug ビルドのみで発生する | Player Settings の IL2CPP / マネージドコードストリッピングが管理器クラスを除外している | `link.xml` または Player Settings の `Managed Stripping Level` で管理器所在程序集 を保持する |

エラーの原文と発生箇所:

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L85-L97
private IAdvertisementManager _advertisementManager;

protected override void Awake()

    InterfaceComponentType = typeof(IAdvertisementManager);
    base.Awake();
    _advertisementManager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
    if (_advertisementManager == null)
    {
        Log.Fatal("Advertisement manager is invalid.");
        return;
    }
    // ...
}
```

## 修正手順

### 1. シーン内に AdvertisementComponent が存在することを確認する

`AdvertisementComponent` は広告システムのエントリポイントコンポーネントであり、これがないとフレームワークが広告マネージャーモジュールを登録しません。アタッチ手順:

1. 最初の起動シーンに空の GameObject を作成する（一般的な名前は `GameFrameX`）。
2. `Add Component → GameFrameX/Advertisement` を選択し、`AdvertisementComponent` をアタッチする。

### 2. Inspector で componentType を正しく入力する

`AdvertisementComponent` はリフレクションで広告管理器を読み込むため、**必ず** `BaseAdvertisementManager` を継承する具名実装クラスの完全名（命名空间 + クラス名）を入力する必要があります。さもないと `Utility.Assembly.GetType(componentType)` が `null` を返し、モジュールが登録されません。

一般的な実装クラス（公式リポジトリ为准）:

| プラットフォーム | 典型的な実装クラス |
|------|-----------|
| Android | `YourNamespace.AndroidAdvertisementManager` |
| iOS | `YourNamespace.IOSAdvertisementManager` |
| WebGL 汎用 | `YourNamespace.WebGLAdvertisementManager` |
| WebGL WeChat ミニゲーム | `YourNamespace.WebGLWeChatAdvertisementManager` |
| WebGL Douyin ミニゲーム | `YourNamespace.WebGLDouYinAdvertisementManager` |
| WebGL Kuaishou ミニゲーム | `YourNamespace.WebGLKuaiShouAdvertisementManager` |

入力時のポイント:

- 命名空间 を含む **完全型名** である必要があります。
- クラスは `public` であり、`BaseAdvertisementManager` を継承している必要があります（間接的に `IAdvertisementManager` を実装）。
- `BaseAdvertisementManager` 自体は `GameFrameworkModule` を継承しており、これが `GameFrameworkEntry.GetModule<T>()` がモジュールを識別する前提となります。

インターフェースと基底クラスの定義の参考:

```csharp

{
    [Preserve]
    void Initialize(AdvertisementConfig config);
    // ...
}

// Runtime/Advertisement/BaseAdvertisementManager.cs#L44-L45
[Preserve]

{
    // ...
}
```

### 3. ターゲットプラットフォームの SDK がインストール済みであることを確認する

`componentType` に指定された実装クラスは、対応するプラットフォームの広告 SDK（例: Pangle、AdMob、WeChat ミニゲーム広告 SDK など）に依存します。Android プロジェクトに WebGL プラットフォームの管理器のみをアタッチしている場合、Android のビルドでは実装が見つからず、同じエラーが発生します。対応方法:

- ターゲットプラットフォームに対応する SDK パッケージをインストールする（`Packages/manifest.json` または `.unitypackage`）。
- または一時的に Inspector の `componentType` をインストール済みプラットフォームの実装に切り替える。

### 4. コードストリッピングとアセンブリの含有を確認する

iOS / IL2CPP ビルドではマネージドコードのストリッピングが行われるため、誤って除去される可能性があります。2 つの対応方法:

- Project Settings → Player → Other Settings → `Managed Stripping Level` を `Low` 以下に設定する。
- または `Assets/link.xml` で管理器の所在程序集 を明示的に保持する:

```xml
<linker>
  <assembly fullname="YourAdvertisementImpl" preserve="all"/>
</linker>
```

### 5. `m_config` と広告枠 ID を確認する

エラー自体は設定とは無関係ですが、`Start()` は `_advertisementManager.Initialize(m_config)` を呼び出します。この時点で管理器が空（`_advertisementManager == null`）の場合、即座に `NullReferenceException` が発生します。したがって、管理器を復旧した後、以下も同時に確認してください:

- 現在のプラットフォームに対応する `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` が入力済みであること。
- `m_config`（`AdvertisementConfig` インスタンス）が `null` ではないこと。`null` の場合、`Start` の初期化はスキップされます:

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L120-L126
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)

## 検証

上記の手順で修正した後、以下のチェックを行い問題が解決されたことを確認してください:

1. ゲームを実行し、Console に `Advertisement manager is invalid.` が出現しなくなることを確認する。
2. `Awake` の後にブレークポイントを設定し、`_advertisementManager != null` であることを確認する。
3. `Start` 内の `_advertisementManager.Initialize(m_config)` が正常に呼び出され、広告 SDK の初期化コールバックが完了することを確認する。
4. 広告再生インターフェース（リワードビデオなど）を 1 回呼び出し、正常に展示結果が返ってくることを確認する。

## よくあるエラー

- **クラス名のみを入力し命名空间 を記述しない**:`Utility.Assembly.GetType(componentType)` が `null` を返し、モジュールが登録されません。
- **管理器クラスが `BaseAdvertisementManager` を継承していない**:`IAdvertisementManager` を実装していても、`GameFrameworkModule` として登録されません。
- **複数プラットフォームへの切り替え時に `componentType` を更新していない**:Android から iOS に切り替えてビルドする際、`componentType` が依然として Android 実装クラスを指しているため、管理器が見つかりません。
- **複数の `AdvertisementComponent` を重複アタッチする**:`[DisallowMultipleComponent]` により同一 GameObject への重複アタッチは防止されますが、シーン内に複数の GameObject がありそれぞれにアタッチされている場合、最初に `Awake` されたもののみが有効になります。
