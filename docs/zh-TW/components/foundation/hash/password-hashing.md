# 密碼雜湊的使用方式:PBKDF2/Bcrypt/Scrypt/Argon2id

透過 `PasswordHashHelper` 的一行呼叫，即可在 PBKDF2、Bcrypt、Scrypt、Argon2id 四種密碼雜湊演算法之間切換；登入驗證時會根據 PHC 前綴自動識別演算法，因此無需記錄使用了哪一種演算法。

## 前置條件

- 專案需參考 `GameFrameX.Foundation.Hash` 組件。
- `using GameFrameX.Foundation.Hash;`(Bcrypt/Scrypt/Argon2id 由 `BCrypt.Net-NNext.StrongName` 與 BouncyCastle 提供，無需額外安裝)。
- 目前的演算法種類可透過列舉型別 `PasswordHashAlgorithmKind` 選擇:`Pbkdf2` / `Bcrypt` / `Scrypt` / `Argon2id`。

## 操作步驟

### 1. 使用統一 Facade 為新密碼進行雜湊(以 Argon2id 為例)

```csharp
using GameFrameX.Foundation.Hash;

string phc = PasswordHashHelper.Hash(PasswordHashAlgorithmKind.Argon2id, "P@ssw0rd-テスト-🔑");
// phc 的格式為 $argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash>
// 直接將 phc 字串原樣儲存到資料庫即可
```

出處： [PasswordHashHelper.cs#L57-L74](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L57-L74)

### 2. 驗證密碼

無需記錄先前使用了哪一種演算法，Facade 會根據 PHC 前綴自動分派：

```csharp
bool ok = PasswordHashHelper.Verify(inputPassword, phcStoredInDb);
if (ok) { /* 登入成功 */ }
```

出處： [PasswordHashHelper.cs#L84-L102](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L84-L102)

### 3. 切換演算法種類

只需將步驟 1 中的 `PasswordHashAlgorithmKind.Argon2id` 替換為 `Pbkdf2` / `Bcrypt` / `Scrypt`,`Verify` 依然能識別資料庫中的舊 PHC 字串。

### 4. 判斷演算法是否為 OWASP 推薦

```csharp
bool isOwaspFirstChoice = PasswordHashHelper.IsRecommended(PasswordHashAlgorithmKind.Argon2id); // true
```

出處： [PasswordHashHelper.cs#L109-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L109-L112)

### 5. 主動識別 PHC 前綴

```csharp
PasswordHashAlgorithmKind? kind = PasswordHashHelper.DetectAlgorithm(storedHash);
// 識別表:$pbkdf2-sha256$、$2a$/$2b$/$2y$(bcrypt)、$scrypt$、$argon2id$
```

出處： [PasswordHashHelper.cs#L120-L147](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L120-L147)

## 常見變化

- **以較小參數對 PBKDF2 進行快速除錯**：直接呼叫 `Pbkdf2Helper.Hash(password, 100, 16)`(測試中即以這種方式對分派邏輯進行負載測試)，正式環境請使用 Facade 的預設參數。
- **以較小的工作因子使用 Bcrypt**:測試時以 `BcryptHelper.Hash(password, 4)` 產生；正式環境建議使用 Facade 的預設安全參數。
- **以較小參數對 Scrypt / Argon2id 進行冒煙測試**:`ScryptHelper.Hash(password, 1024, 1, 1)`、`Argon2idHelper.Hash(password, 16, 1, 1)` 是測試用的最小參數組合，用於單元測試的快速往返驗證。

## 常見錯誤

| 現象 | 原因 | 解決方案 |
|------|------|------|
| `Hash(未知の列挙値, pwd)` 擲出 `ArgumentOutOfRangeException` | 傳入的值不屬於 4 種已知演算法 | 僅使用 `Pbkdf2` / `Bcrypt` / `Scrypt` / `Argon2id` |
| `Hash(Bcrypt, 超長パスワード)` 擲出 `ArgumentOutOfRangeException` | bcrypt 的硬性上限為 72 位元組(UTF-8) | 超過 72 位元組的密碼請改用 Argon2id / Scrypt,或先取摘要再進行雜湊 |
| `Verify` 回傳 `false` 但密碼正確 | 儲存的字串不屬於 4 種 PHC 前綴之一，或格式已損毀 | 以 `DetectAlgorithm(storedHash)` 進行排查，並確認前綴完整無誤 |
| 想要「因 72 位元組限制而切換演算法」,卻使用了 `Argon2id` 以外的演算法 | OWASP 的首選是 Argon2id,其他演算法未必列為首選 | 以 `PasswordHashHelper.IsRecommended(kind)` 進行判斷 |

## 背景(可選)

`PasswordHashHelper` 是一層輕薄的 Facade,實際實作分別由 `Pbkdf2Helper`(BCL `Rfc2898DeriveBytes`)、`BcryptHelper`(`BCrypt.Net-Next.StrongName`,72 位元組硬性上限)、`ScryptHelper`、`Argon2idHelper`(BouncyCastle)承擔。`Verify` 依據 PHC 字串前綴($pbkdf2-sha256$ / $2a$|$2b$|$2y$ / $scrypt$ / $argon2id$)進行分派，因此即使日後將資料庫中的歷史 PBKDF2 升級為 Argon2id,舊的 PHC 字串仍可被識別。列舉型別 `PasswordHashAlgorithmKind` 與用於校驗和的 `HashAlgorithmKind` 語意不同，因此在密碼場景中請使用前者。
