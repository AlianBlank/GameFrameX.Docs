# 出现 Invalid character 异常怎么办

调用 `JsonMapper.ToObject` / `JsonReader` 解析输入时,如果抛出 `JsonException` 且消息形如 `Invalid character '{0}' in input string`,说明词法分析器在输入字符串中遇到了不在 JSON 词法表里的字符。本页帮助你快速定位原因并修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `Invalid character 'x' in input string`(x 是字母) | 输入不是合法 JSON,例如首字符直接是裸 `xyz`、裸 `true`、或非 JSON 文本(如 XML / YAML / 注释) | 用 JSON 在线校验工具确认格式;确保文本以 `{`、`[`、数字、字符串、`true`/`false`/`null` 之一开头 |
| 异常消息里是数字 / 控制字符(如 `Invalid character '\0'`) | 字符串末尾的 BOM(`\uFEFF`)、行尾 `\r`、残留的二进制字节 | 解析前 `Trim` / `Trim('\uFEFF')`;读取流时使用 `StreamReader` 默认 UTF-8 去 BOM |
| 异常消息里是反斜杠 `\` 后接非法字符 | 字符串里的转义序列不合法(如 `"\x"`、`"\u00"`、`"\u12"` 长度不足) | 转义序列只允许 `\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX`(4 位十六进制) |
| 异常消息里是 `'`(单引号)或 `,` 后的换行 | JSON 中混入了 JavaScript / Python 风格的语法(单引号字符串、注释、末尾逗号) | 删除单引号、改用双引号;删除 `//`、`/* */` 注释和对象/数组末尾的多余逗号 |
| 异常消息里是中文字符 | 直接把 `null` / `undefined` / C# 默认 `ToString()` 等传给了解析器 | 先判断响应体是否真的是 JSON(`Content-Type` / 首字符),否则不要调用 `JsonMapper.ToObject` |

异常消息的原始模板来自 `JsonException(int c)` 构造函数:

```csharp
internal JsonException(int c) :
    base(string.Format(
             "Invalid character '{0}' in input string", (char)c))
{
}
```

Source: [Runtime/JsonException.cs#L77-L83](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonException.cs#L77-L83)

## 修复步骤

### 1. 先打印出原始输入

不要在日志里只贴 `e.Message`,把真正传入解析器的字符串打出来,异常消息里的字符就是问题字符的位置。

```csharp
try
{
    var obj = GameFrameX.LitJSON.Runtime.JsonMapper.ToObject<Dictionary<string, object>>(rawText);
}
catch (GameFrameX.LitJSON.Runtime.JsonException ex)
{
    Debug.LogError($"LitJSON 解析失败: {ex.Message} | 原始输入长度={rawText?.Length} | 前 64 字符=[{rawText?.Substring(0, System.Math.Min(64, rawText?.Length ?? 0))}]");
}
```

### 2. 处理 BOM 与隐藏字符

服务端返回 UTF-8 with BOM、或文件被 Windows 记事本保存过,会在字符串首部留下 `\uFEFF`,词法器会把它当作“非法首字符”抛出。

```csharp
using GameFrameX.LitJSON.Runtime;

string rawText = File.ReadAllText(path);
// 去掉首部 BOM
if (!string.IsNullOrEmpty(rawText) && rawText[0] == '\uFEFF')
    rawText = rawText.Substring(1);

var data = JsonMapper.ToObject<MyData>(rawText);
```

来源参考:[Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs) 的状态机在遇到非表内码点时即抛出 `JsonException(c)`。

### 3. 修正转义序列

JSON 字符串只支持下列转义;其他如 `\'`、`\x`、`\v`、`\u{}`、未凑齐 4 位的 `\u` 都会触发 `Invalid character` 异常(出现位置在 `\` 之后的字符)。

| 合法转义 | 说明 |
|----------|------|
| `\"` | 双引号 |
| `\\` | 反斜杠 |
| `\/` | 正斜杠 |
| `\b` `\f` `\n` `\r` `\t` | 控制字符 |
| `\uXXXX` | 必须是 4 位十六进制(如 `\u4E2D`) |

### 4. 修正非法 JSON 语法

LitJSON 是严格 JSON 解析器,**不支持** JavaScript / JSON5 风格的扩展:

- 字符串只能用双引号,不能是单引号 `'…'`。
- 不允许 `//`、`/* */` 注释。
- 对象 / 数组最后一个元素后不能有 `,` 尾逗号。
- 数字不允许前导零或十六进制字面量(`0x1A`)。

```csharp
// 错误写法 —— 不是 JSON
var bad = "{ name: 'Tom', age: 18, }";

// 修正后
var good = "{\"name\":\"Tom\",\"age\":18}";
var obj = JsonMapper.ToObject<Dictionary<string, object>>(good);
```

### 5. 确认调用入口

`JsonMapper.ToObject` 入口签名见 [Runtime/JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs);`JsonReader` 流式入口见 [Runtime/JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs)。无论哪条入口,词法错误都会包装为同一类 `JsonException`。

## 验证

按以下顺序确认问题已解决:

1. 把引发异常的输入复制到任意在线 JSON 校验工具(如 jsonlint),确认格式合法后再回到代码。
2. 重新运行程序,确认 `JsonException` 不再抛出,且 `JsonMapper.ToObject<T>` 正常返回结果。
3. 如果数据来自网络响应,顺带校验响应头 `Content-Type: application/json` 与响应体首字符,避免把 HTML 错误页或空响应喂给解析器。

## 背景(可选)

LitJSON 的词法分析基于有限状态机 ([Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs));解析表 `parse_table` 不接受任何非 JSON 字符,一旦读到就通过 `JsonException(int c)` 抛出 `Invalid character '{0}' in input string`,异常消息里的字符就是问题字符本身,因此诊断时优先看这个字符而不是字符串内容。
