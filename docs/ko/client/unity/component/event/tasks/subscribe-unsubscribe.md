# 이벤트 구독 및 구독 해제 방법

씬의 `EventComponent`(메뉴 `GameFrameX/Event`)를 통해 이벤트를 구독합니다: `CheckSubscribe(id, handler)`를 호출하여 구독을 완료하고, `Unsubscribe(id, handler)` 또는 `CheckUnsubscribe(id, handler)`를 호출하여 구독을 해제합니다. 핸들러 시그니처는 `EventHandler<GameEventArgs>`이며, 이벤트 ID `id`는 `string`입니다.

## 사전 조건

- 씬에 GameFrameX 진입점이 이미 존재하며 `EventComponent` 컴포넌트(`[AddComponentMenu("GameFrameX/Event")]`)가 추가되어 있습니다.
- 사용자 지정 이벤트 인자가 필요한 경우 `GameEventArgs`를 상속하는 인자 클래스를 준비합니다. 인자가 없는 이벤트는 `string` 이벤트 ID를 직접 사용할 수 있습니다.

## 구독 및 구독 해제 관련 API

| 메서드 | 실제 시그니처 | 동작 |
|------|----------|------|
| `EventComponent.CheckSubscribe` | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 구독되지 않은 경우에만 구독하며, 안전하게 반복 호출 가능 |
| `EventComponent.Unsubscribe` | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 구독 해제(매니저에게 직접 전달) |
| `EventComponent.CheckUnsubscribe` | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | handler가 존재하지 않으면 아무 작업도 수행하지 않음 |
| `EventComponent.Check` | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 해당 처리 함수가 존재하는지 확인 |
| `EventComponent.Count` | `int Count(string id)` | 해당 이벤트 ID의 처리 함수 수 |
| `IEventManager.Subscribe` | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | 매니저 계층의 기본 구독, 중복 제거 없음 |

컴포넌트의 메서드는 모두 `IEventManager`로의 전달이며, `CheckSubscribe`의 실제 구현은 "먼저 `Check` 후 `Subscribe`"입니다:

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

## 작업 단계

1. 스크립트에 `EventComponent`에 대한 참조를 저장합니다(Inspector 직렬화 참조 또는 씬에서 컴포넌트 찾기). 컴포넌트는 `Awake`에서 자동으로 `IEventManager` 모듈을 가져옵니다:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

2. 이벤트 처리 함수를 작성합니다. 시그니처는 반드시 `void (object sender, GameEventArgs e)`, 즉 `EventHandler<GameEventArgs>`여야 합니다. 사용자 지정 인자 클래스는 `GameEventArgs`(자체적으로는 비어 있는 추상 기본 클래스이며 `BaseEventArgs`를 상속)를 직접 상속합니다:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class GameEventArgs : BaseEventArgs
{
}
```

출처: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

3. 초기화 시점(예: `OnEnable`)에 이벤트를 구독하며, 중복 구독을 방지하려면 `CheckSubscribe` 사용을 권장합니다: `m_EventComponent.CheckSubscribe("Player.HealthChanged", OnHealthChanged);`.
4. 파괴/비활성화 시점(예: `OnDisable`/`OnDestroy`)에 구독을 해제합니다: `m_EventComponent.CheckUnsubscribe("Player.HealthChanged", OnHealthChanged);`. 해당 구현:

```csharp
public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.Unsubscribe(id, handler);
}

public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L118-L131)

5. 처리 함수 내부에서 필요에 따라 `e`를 사용자 지정 인자 타입으로 변환한 후 데이터를 읽습니다. 구독 해제 후 `m_EventComponent.Check(id, handler)`가 `false`를 반환하고 `Count(id)`가 `0`을 반환하는지 확인하여 구독이 해제되었는지 검증할 수 있습니다.

## 일반적인 변형

- **반복 초기화 시나리오**: 동일한 로직에 여러 번 진입하는 경우 `CheckSubscribe` / `CheckUnsubscribe`를 직접 사용합니다. 두 메서드 모두 내부에서 먼저 확인한 후 실행하므로 반복 호출해도 오류가 발생하지 않습니다. `CheckUnsubscribe`의 구현은 매니저 계층에서 `handler`가 존재하지 않을 경우 아무 작업도 수행하지 않습니다:

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (m_EventPool.Check(id, handler))
    {
        m_EventPool.Unsubscribe(id, handler);
    }
}
```

출처: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L140-L146)

- **인자 없는 이벤트**: 이벤트 ID만 필요하고 데이터를 전달할 필요가 없는 경우, `Fire(object sender, string eventId)`를 사용하여 문자열로 직접 트리거할 수 있습니다. 컴포넌트 내부에서 자동으로 `EmptyEventArgs`를 생성합니다:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`EmptyEventArgs.Create`는 참조 풀에서 객체를 획득하여 이벤트 ID를 설정합니다:

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

출처: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

- **폴백 처리**: `SetDefaultHandler(EventHandler<GameEventArgs> handler)`를 호출하여 기본 이벤트 처리 함수를 설정합니다. 구독자가 없는 이벤트를 수신하는 데 사용됩니다.

## 일반적인 오류

| 오류 | 원인 | 해결 방법 |
|------|------|------|
| 컴포넌트 초기화 실패, 로그에 `Event manager is invalid.` 출력 | 씬에 사용 가능한 `IEventManager` 모듈이 없거나 GameFrameX 진입점이 초기화되지 않음 | 씬에 GameFrameX 진입점이 존재하고 `EventComponent`가 추가되어 있는지 확인 |
| 동일한 핸들러가 여러 번 트리거됨 | `IEventManager.Subscribe`(중복 제거 안 함)를 사용하여 반복 호출함 | `EventComponent.CheckSubscribe`로 변경 |
| 구독 해제 시 오류 발생 | 구독되지 않은 `handler`를 전달했거나 `id`가 일치하지 않음 | `EventComponent.CheckUnsubscribe`로 변경 |
| 처리 함수 시그니처 불일치 | `EventHandler<GameEventArgs>`(`void (object, GameEventArgs)`)를 사용하지 않음 | 해당 시그니처에 맞게 처리 함수 작성 |
| 이벤트 트리거 시점이 예상과 다름 | `Fire`는 스레드 안전하지만 이벤트가 다음 프레임에 분배되며, `FireNow`는 즉시 분배되지만 스레드 안전하지 않음 | 필요에 따라 `Fire` / `FireNow` 선택 |

## 배경

`EventComponent`는 Unity 씬의 퍼사드(facade) 컴포넌트로, 모든 구독 API는 `IEventManager`(`EventManager`)로 전달되며, 후자는 다시 내부의 `m_EventPool`에 위임하여 실제 이벤트 풀 유지 관리를 수행합니다. 따라서 호출자는 `EventComponent`의 `Subscribe`/`Unsubscribe`/`Check` 의미만 다루면 되며, 내부 이벤트 풀을 신경 쓸 필요가 없습니다.
