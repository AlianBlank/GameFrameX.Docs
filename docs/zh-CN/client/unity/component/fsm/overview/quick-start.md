# 快速上手:第一个状态机

按照本页步骤,你将在 5 分钟内跑通 GameFrameX FSM 的最小闭环:定义状态 → 创建 FSM → 启动状态 → 在状态内切换并读写数据。

## 前置条件

- Unity 2019.4 及以上
- 已通过 `Packages/manifest.json` 安装 `com.gameframex.unity.fsm` 1.1.1(或使用 Git URL 直连仓库)

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.fsm": "1.1.1"
  }
}
```

安装后,`FsmComponent` 会作为 `[GameFrameXAutoComponent(-6000)]` 自动挂到 `GameFramework` 启动对象上。

## 操作步骤

### 1. 定义状态类

继承 `FsmState<T>`(`T` 是 FSM 持有者类型),按需重写六个生命周期钩子。状态内通过 `ChangeState<TNext>(fsm)` 触发切换。

```csharp
using GameFrameX.Fsm;
using UnityEngine;

public class Player { /* 玩家业务字段 */ }

public class IdleState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        Debug.Log("进入 Idle");
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        if (Input.GetKeyDown(KeyCode.W))
        {
            ChangeState<MoveState>(fsm);
        }
    }

    protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
}

public class MoveState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        fsm.SetData("Speed", 5.0f);
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds) { }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L97-L122)

### 2. 创建并启动 FSM

通过 `FsmComponent` 创建,构造时一次性传入所有初始状态实例,最后用 `Start<TState>()` 选择入口状态。

```csharp
using GameFrameX;
using GameFrameX.Fsm;
using GameFrameX.Fsm.Runtime;

var fsmComponent = GameEntry.GetComponent<FsmComponent>();
IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
fsm.Start<IdleState>();
```

`CreateFsm` 由 [FsmManager](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs) 通过对象池分配 `Fsm<T>` 实例并填充 states 字典;`Start<T>` 设置当前状态并触发 `OnEnter`。

### 3. 在状态间切换并读写数据

状态内的 `IFsm<T> fsm` 参数既负责触发切换,也提供跨状态键值数据存储(`Variable` 内部统一装箱)。

```csharp
// 任何状态的 OnEnter / OnUpdate / OnLeave 中
fsm.SetData("Health", 100);
int hp = fsm.GetData<int>("Health");

if (fsm.HasData("Health"))
{
    fsm.RemoveData("Health");
}
```

切状态调用 `ChangeState<TNext>(fsm)`,框架会自动先调用旧状态的 `OnLeave(..., isShutdown: false)` 再调用新状态的 `OnEnter`。

### 4. 销毁 FSM

不在需要时调用 `DestroyFsm`,框架会触发 `OnDestroy` 并回收到 `FsmManager` 的对象池。

```csharp
fsmComponent.DestroyFsm(fsm);
```

## 常见变体

| 场景 | 写法 |
|------|------|
| 同一持有者类型需要并存多套 FSM | `CreateFsm(owner, name, new IdleState(), ...)` 重载传入名字 |
| 运行时追加状态 | `fsm.AddState(new JumpState())` |
| 运行时移除非当前状态 | `fsm.RemoveState<IdleState>()` |
| 保留状态集合、清空数据并回到初始 | `fsm.Reset()`,再用 `Start<T>()` 重启 |
| 物理帧驱动 | 重写 `OnFixedUpdate`,`FsmComponent.FixedUpdate` 会自动派发 |
| 快捷访问入口(需要 com.gameframex.unity.entry) | `GameApp.Fsm.CreateFsm(...)` 代替 `GameEntry.GetComponent<FsmComponent>()` |

## 常见错误

- **找不到 `FsmComponent`**:Unity 场景里没有挂载 `GameFramework` 启动预制体,组件未自动实例化。
- **`Start<T>` 抛异常**:传入的状态类型在创建时未注册,需先把它加入 `CreateFsm` 的参数列表或 `AddState`。
- **数据存不进去**:`SetData` 内部以 `Variable` 装箱,值类型读出时必须用同一泛型参数 `GetData<int>("Health")`。
- **切状态没生效**:`ChangeState<TNext>(fsm)` 必须在状态钩子内被调用,且 `TNext` 必须已被注册过。
- **同一个 owner 的状态机被销毁后又 `Start`**:先确认 `IsDestroyed == false`,否则需要重新 `CreateFsm`。

## 背景(可选)

`Fsm<T>` 内部用 `Dictionary<Type, FsmState<T>>` 存储状态,`m_CurrentStateTime` 在 `Update` 中累加,可在调试器或自定义 Inspector 中读取 `CurrentStateName` / `CurrentStateTime`。所有 FSM 由 `FsmManager` 集中管理,通过 `FsmComponent` 暴露给上层。
