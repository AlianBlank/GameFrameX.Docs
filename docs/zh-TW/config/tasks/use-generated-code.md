# 如何在 Unity / .NET 中讀取產生的設定

遵循本頁面的步驟，即可在 Unity 用戶端或 .NET 伺服器的程式碼中，直接讀取由 `gen-client-*` / `gen-server-*` 指令碼產生的設定資料。在整個作業過程中，無需手寫任何解析用的程式碼。

## 前置條件

- 已依照文件的需求，在 `Excels/Tables/` 中準備好 Excel 表格(命名規則後述)。
- 已執行過一次產生指令碼，Unity 專案下已存在 C# 類別(例如:`TbItemConfig`、`TbAchievementConfig`)以及資料檔案。
- 已匯入 `Tables` 容器類別的命名空間(預設位於產生路徑的根命名空間之下)。

## 操作步驟

1. 在 `Excels/Tables/` 目錄中，建立/確認 Excel 檔案名稱遵循 `字母-英文名-中文名.xlsx` 的規則。例如：

   ```
   D-ItemConfig-道具表-道具-1001.xlsx
   ```

   出處： [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L94-L96)

2. 執行產生指令碼(在 Windows 上雙擊 `.bat`,在 Mac/Linux 上使用 `sh`)。執行完成後，會在 Unity 專案下產生 C# 類別與資料檔案：

   ```bash
   # 用戶端 (Unity)
   sh gen-client-json.sh
   # 或 gen-client-bin.sh

   # 伺服器 (.NET)
   sh gen-server-bin.sh
   # 或 gen-server-json.sh
   ```

   出處： [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L136-L141)

3. 在程式碼中從 `tables` 容器取得對應的表格，並以主鍵透過 `Get(id)` 查詢一筆記錄：

   ```csharp
   // 取得 id 為 10001 的道具
   var item = tables.TbItemConfig.Get(10001);

   // 道具名稱會自動變為當前語言(例如在中文下會顯示為「钻石」)
   Debug.Log(item.Name);
   Debug.Log(item.Price); // 10
   ```

   出處： [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L152-L159)

4. 工具產生的程式碼中，類別名稱遵循 `Tb英文名` 的規則。下表為本儲存庫現有 Excel 與所產生類別名稱的對應關係：

   | Excel 檔案名稱 | 產生的 C# 類別名稱 |
   |--------------|---------------|
   | `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
   | `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
   | `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |
   | `L-Localization-成就.xlsx` | `TbLocalization` |

   出處： [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L194-L199)

## 常見變化

- **大型表格的分割**：當單一表格的資料量非常多(1000 筆以上)時，只要**英文名稱相同**，中文名稱可任意區分，工具會自動將其合併為同一個表格。例如 `D-ItemConfig-道具表.xlsx` 與 `D-ItemConfig-道具表-1001.xlsx` 會合併為 `TbItemConfig`。
- **僅單側使用**：在英文名稱與中文名稱之間加入群組標記 `c`(僅用戶端)或 `s`(僅伺服器)。若不加上，則兩側皆會產生。
  - `D-ItemConfig-c-道具表.xlsx` → 僅用戶端使用 `TbItemConfig`
  - `D-ItemConfig-s-道具表.xlsx` → 僅伺服器使用 `TbItemConfig`
- **資料型別的使用區分**:`text` 是會套用多語系翻譯的欄位(填入 key,實際字串放在 `Local/`)。`string` 則是不會翻譯、直接使用的普通字串。

## 常見錯誤

| 錯誤 | 原因 | 修正方式 |
|------|------|------|
| 找不到 `tables.TbXxx` 類別 | 尚未執行產生指令碼，或 Excel 檔案名稱的英文部分未填寫 | 執行 `gen-client-json.sh` / `gen-client-bin.sh`,並確認檔案名稱中包含有效的英文部分 |
| 工具顯示 `不支持中文表名` 錯誤 | 檔案名稱的英文部分填入了中文 | 將該部分改為純英文(例如：使用 `ItemConfig` 而非 `道具表`) |
| `Get(id)` 回傳 null | 該 id 不存在於表格的資料中 | 先使用 `tables.TbXxx.GetAll()`,或直接讀取全部資料以確認 id 是否存在 |
| 欄位的值為 key 而非翻譯後的字串 | 欄位型別使用了 `string` 而非 `text` | 將表頭第 2 行的型別從 `string` 改為 `text`,並重新產生 |

## 背景(選用)

`tables` 是 Luban 產生的根容器，每個 `TbXxx` 表格對應一個 Excel。`text` 型別的欄位在讀取時會經過依當前語言進行的在地化對應，因此必須在 `Excels/Local/` 中備齊各語言所有 key 的翻譯。
