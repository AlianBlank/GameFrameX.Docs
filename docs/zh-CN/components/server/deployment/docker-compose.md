# 使用 Docker / docker-compose 部署服务器

按本页步骤操作,你可以在几分钟内用 `docker-compose` 把 GameFrameX 服务器和 MongoDB 数据库拉起来,并通过容器卷挂载实现配置、热更和日志的持久化。

## 前置条件

- 已安装 Docker Engine 20.10+ 与 Docker Compose v2(命令行执行 `docker compose version` 验证)
- 宿主机已放通以下端口:`27017`(MongoDB)、`28080`(HTTP)、`29090`(APM)、`29100`(TCP)、`29110`(WebSocket)
- 项目仓库根目录存在 `Dockerfile` 与 `docker-compose.yml`(见下)

## 配置文件结构

仓库根目录提供两个开箱即用的文件:

| 文件 | 作用 |
|------|------|
| [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48) | 多阶段构建:基于 `mcr.microsoft.com/dotnet/sdk:10.0` 编译项目,基于 `aspnet:10.0` 运行,最终镜像入口为 `/app/entrypoint.sh dotnet GameFrameX.Launcher.dll` |
| [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L1-L148) | 定义 `mongodb` 与 `gameframex` 两个服务,共享 `gameframex` bridge 网络,并把宿主机的 `./running/*` 挂载进容器实现持久化 |

## 操作步骤

### 1. 准备宿主机的持久化目录

`docker-compose.yml` 把以下宿主机目录挂载到容器中(目录不存在时,`docker compose` 会自动创建):

| 宿主机目录 | 容器挂载点 | 用途 |
|------------|------------|------|
| `./running/database` | `/data/db` | MongoDB 数据文件 |
| `./running/hotfix` | `/app/hotfix` | 热更新 DLL |
| `./running/json` | `/app/json` | JSON 配置 |
| `./running/logs` | `/app/data/logs` | 应用日志 |
| `./running/GameAnalytics` | `/GameAnalytics` | 游戏分析数据 |

```bash
mkdir -p running/{database,hotfix,json,logs,GameAnalytics}
```

### 2. 启动服务

在仓库根目录执行:

```bash
docker compose up -d --build
```

首次运行会依次拉取 MongoDB 镜像并按 [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L5-L23) 构建 GameFrameX 镜像(`GameFrameX.Launcher` + `GameFrameX.Hotfix` 双工程 publish)。镜像启动入口由 [entrypoint.sh](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L33-L42) 写入:

```sh
#!/bin/sh
if [ -z "$(ls -A /app/hotfix 2>/dev/null)" ]; then
    echo "hotfix directory is empty, copying defaults..."
    cp -r /app/hotfix-default/* /app/hotfix/
fi
if [ -z "$(ls -A /app/json 2>/dev/null)" ]; then
    echo "json directory is empty, copying defaults..."
    cp -r /app/json-default/* /app/json/
fi
exec "$@"
```

> 该脚本保证了宿主机 `./running/hotfix`、`./running/json` 为空时,会从镜像内置的默认值复制一份,免去首次部署的人工配置。

### 3. 验证服务状态

```bash
docker compose ps
docker compose logs -f gameframex
```

数据库连接串已在 compose 中默认配置:

```yaml
DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
DataBaseName=gameframex
```

成功启动后,客户端可通过 `29100`(TCP)、`29110`(WebSocket)、`28080`(HTTP) 接入。

## 关键配置项速查

[docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L14-L139) 中暴露的常用环境变量:

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `ServerType` | `Game` | 服务器类型,多进程用逗号分隔,如 `Game,Social,Chat` |
| `ServerId` | `1000` | 服务器 ID,合服时需保持一致 |
| `InnerPort` / `OuterPort` | `29100` | 内部通信端口 / 外部客户端连接端口 |
| `HttpPort` | `28080` | HTTP 服务端口 |
| `WsPort` | `29110` | WebSocket 端口(需配合 `IsEnableWebSocket=true`) |
| `APMPort` | `29090` | APM 性能监控端口 |
| `DataBaseUrl` | `mongodb://admin:admin@mongodb:27017/?authSource=admin` | MongoDB 连接串 |
| `DataBaseName` | `gameframex` | 数据库名 |
| `DiscoveryCenterIp` / `DiscoveryCenterPort` | `127.0.0.1` / `10001` | 服务发现中心地址 |

其余被注释掉的环境变量(如 `IsEnableTcp`、`IsOpenTelemetry`、`LogIsGrafanaLoki` 等)均保留了默认值,可按需取消注释。

## 常见变体

- **单进程模式**:取消 [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L33-L34) 第 33 行的注释,把 `IsSingleMode` 设为 `true`,并把 `ServerType` 调整为单一值。
- **外部 MongoDB**:把 `DataBaseUrl` 改为外部地址(例如 `mongodb://user:pass@your-mongo-host:27017/?authSource=admin`),并删除 compose 中的 `mongodb` 服务块。
- **HTTPS / WSS**:启用 `HttpsPort`、`WssPort`、`WssCertFilePath` 三个环境变量,并将证书挂载进容器。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `gameframex` 启动报 `Unable to connect to MongoDB` | `DataBaseUrl` 中的账号或 `mongodb` 服务名不匹配 | 确认账号 `admin/admin` 与服务名 `mongodb` 与 compose 中定义一致 |
| `http://localhost:28080` 无法访问 | 宿主机防火墙未放通端口 | 放通 28080,或修改 compose 中 `ports` 映射 |
| 热更文件未生效 | `./running/hotfix` 未挂载或为空 | entrypoint.sh 会自动从镜像默认目录复制一次,确保宿主机目录可写 |
| 构建阶段 `dotnet restore` 失败 | 子工程 csproj 路径变化 | 仅修改项目结构时同步更新 [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L9-L13) 的 `COPY` 行 |

## 背景(可选)

[Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48) 采用四阶段构建:`base` 准备运行时镜像,`build` 还原依赖并编译,`publish` 产出 Launcher 与 Hotfix 两个产物,`final` 仅拷贝运行时必需的文件,从而让最终镜像保持精简并支持热更目录的默认值兜底。
