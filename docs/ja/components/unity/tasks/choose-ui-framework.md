# FairyGUI と UGUI の選択・切り替え方法

GameFrameX は2つの独立した UI アダプタパッケージを通じて FairyGUI と UGUI を同時にサポートしています。業務コードは生成段階でアダプタ層を選択するだけで、ランタイムではスクリプトマクロ（`ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI`）によって生成物を分離し、同一プロジェクト内での共存や切り替えが可能です。

## 前提条件

プロジェクトには Unity Package Manager を通じて以下のパッケージが導入されていること（[Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L36-L38) 参照）:

| パッケージ名 | バージョン | 役割 |
|------|------|------|
| `com.gameframex.unity.ui` | 2.11.0 | UI 基本フレームワーク（開く/閉じる/イベント） |
| `com.gameframex.unity.ui.fairygui` | 3.4.2 | FairyGUI アダプタ層 |
| `com.gameframex.unity.ui.ugui` | 2.6.0 | UGUI アダプタ層 |
| `com.gameframex.unity.fairygui.unity` | 5.3.4 | FairyGUI エディタランタイム |
| `com.unity.ugui` | 1.0.0 | Unity 内蔵 UGUI |

> FairyGUI の依存パッケージ `FairyGUI` は `com.gameframex.unity.fairygui.unity` が提供するため、追加で個別インストールする必要はありません。

## 選択のヒント

| シーン | 推奨方案 | 理由 |
|------|----------|------|
| アーティストが既に FairyGUI エディタで大量の `.fui` リソースを生成済み | FairyGUI | 既存のパッケージをそのまま利用可能。フィールド型は `GComponent` / `GTextField` など |
| チームが Unity ネイティブのワークフローに慣れており、Prefab + Canvas を使用 | UGUI | フィールド型が `UnityEngine.UI.Text` / `InputField` で、Unity の直感に合う |
| 2 セットの UI を共存させる必要がある（例: メイン画面は UGUI、キャンペーンポップアップは FairyGUI） | 両方有効化 | 異なるディレクトリに生成されたコードを分離するだけで実現可能 |
| ゼロから始めて、最短で習得したい | UGUI | FairyGUI エディタに依存せず、Prefab を直接配置できる |

## 操作手順:コンパイル生成物での方案選択

1. `Project Settings` → `Player` → `Scripting Define Symbols` に対応するマクロを追加（または削除）します:

   ```
   ENABLE_UI_FAIRYGUI   // FairyGUI アダプタを有効化
   ENABLE_UI_UGUI       // UGUI アダプタを有効化
   ```

2. FairyGUI 生成コード例 —— クラスは `FUI` を継承し、`UIPackage.CreateObject` で生成:

   ```csharp
   // 出典:Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs
   #if ENABLE_UI_FAIRYGUI
   public sealed partial class UIAnnouncement : FUI
   {
       public const string UIPackageName = "UILogin";
       public const string UIResName     = "UIAnnouncement";
       public const string URL           = "ui://f011l0h9aneks9g";

       public GComponent self { get; private set; }
       public GTextField  m_TextTitle { get; private set; }
   }
   #endif
   ```

   出典: [UIAnnouncement.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs#L3-L29)

3. UGUI 生成コード例 —— クラスは `UGUI` を継承し、`[SerializeField] [UGUIElementProperty]` でノードを公開:

   ```csharp
   // 出典:Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs
   #if ENABLE_UI_UGUI
   [OptionUIConfig(null, "Assets/Bundles/UI/UILogin")]
   public sealed partial class UILogin : UGUI
   {
       [SerializeField] [UGUIElementProperty("UserName")]
       private UnityEngine.UI.InputField UserName;
       public UnityEngine.UI.InputField m_UserName => UserName;
   }
   #endif
   ```

   出典: [UILogin.UI.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs#L3-L46)

4. UI Launcher を実行すると、フレームワークは現在アクティブなマクロに応じて対応する生成クラス（`FUI` または `UGUI`）を自動的に検出し、パネルを開きます。業務層でのハードコーディングは不要です。

## よくあるバリエーション

- **2 セットの UI を共存**: 両方のマクロを同時に定義し、FairyGUI 生成物は `Assets/Hotfix/UI/FairyGUI/` に、UGUI 生成物は `Assets/Hotfix/UI/UGUI/` に配置します。フレームワークはクラス名でマッチングします。
- **ランタイムで動的に切り替え**: 同一ビルドパッケージ内でマクロによる切り替えは推奨されません。A/B テストが必要な場合は、ビルドを 2 つ出し、それぞれで 1 つのマクロのみを有効化してください。
- **1 セットのみ残す**: もう一方のディレクトリにある生成コードを削除し、対応するマクロを削除すれば完了です。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| UI を開こうとすると `TypeInitializationException` が発生し、クラスが見つからない | `Scripting Define Symbols` に対応するマクロが追加されておらず、生成コードが `#if` で丸ごと除外されている | `ENABLE_UI_FAIRYGUI` または `ENABLE_UI_UGUI` を追加 |
| FairyGUI パッケージのロードに失敗し、リソースがピンク色で表示される | `com.gameframex.unity.fairygui.unity` がインストールされていない、または FairyGUI エディタからエクスポートされていない | パッケージを再インポートし、`.fui` パッケージアドレス `ui://...` が `UIPackageName` と一致していることを確認 |
| UGUI ノードがすべて `null` になる | Prefab のパスが `[OptionUIConfig]` の `Assets/Bundles/UI/...` と一致していない | UI コードを再生成するか、`OptionUIConfig` のパスを修正 |

## 検証

1. プロジェクトをコンパイルし、Console に `TypeLoadException` / `MissingMethodException` が出現しないことを確認。
2. 起動後、サンプルパネル（例: `UILogin`）を開くと、対応する方案のコントロールが表示されます。
3. マクロを切り替えて再コンパイルし、パネルの型が `FUI` サブクラスから `UGUI` サブクラスへ（またはその逆に）変わることを確認。

## 背景（任意）

2 つのアダプタパッケージは同じセマンティクスの `Open` / `Close` / `Show` フローを提供しますが、違いが出るのはノードバインディング方式のみです。FairyGUI は `GObject` 経由でパッケージ内のコンポーネントをリフレクションし、UGUI は `UGUIElementProperty` 属性経由で Prefab 上の `GameObject` をリフレクションします。業務コードは基底クラス `FUI` / `UGUI` のみに依存してプログラミングするため、フィールド型に直接依存することはありません。
