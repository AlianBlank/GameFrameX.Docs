# 連線至伺服器：建立通道與實作通道輔助器(TCP/WebSocket)

建立網路通道只需呼叫 `NetworkComponent.CreateNetworkChannel(channelName, networkChannelHelper)` 並傳入一個實作 `INetworkChannelHelper` 的通道輔助器；框架會依據編譯定義自動選擇底層實作——啟用 WebGL/WebSocket 定義時使用 `WebSocketNetworkChannel`,否則使用 `SystemTcpNetworkChannel`。

## 前置條件

- 場景中已掛載 `NetworkComponent`(命名空間為 `GameFrameX.Network.Runtime`)。
- 已確定傳輸方式：預設為系統 TCP;若需使用 WebSocket,則必須啟用 `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` 或 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` 定義。
- 已準備好通道輔助器類別(可直接使用框架內建的 `DefaultNetworkChannelHelper`,或依照其介面自行實作)。

## 步驟

1. 準備通道輔助器。框架內建的 [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L13) 實作了 `INetworkChannelHelper` 的所有成員，可直接重複使用，或作為自訂輔助器的範本：

   | 成員 | 簽章(來自 DefaultNetworkChannelHelper)| 說明 |
   |------|------|------|
   | `SetChannelSerializer` | `void SetChannelSerializer(IMessageSerializer serializer)` | 設定通道層級的訊息序列化器；必須在 `Initialize` 之前呼叫 |
   | `Initialize` | `void Initialize(INetworkChannel netChannel)` | 儲存通道參考、透過反射註冊處理器，並訂閱網路事件 |
   | `PrepareForConnecting` | `void PrepareForConnecting()` | 連線前將 Socket 傳送/接收緩衝區設定為 `1024 * 64 - 1` |
   | `SendHeartBeat` | `bool SendHeartBeat()` | 使用 `PacketHeartBeatHandler` 建構並傳送心跳封包 |
   | `SerializePacketHeader<T>` | `bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject` | 委派給通道的 `PacketSendHeaderHandler` |
   | `SerializePacketBody` | `bool SerializePacketBody(byte[] messageBodyBuffer, MemoryStream destination)` | 委派給通道的 `PacketSendBodyHandler` |
   | `DeserializePacketHeader` | `bool DeserializePacketHeader(byte[] source)` | 委派給通道的 `PacketReceiveHeaderHandler` |
   | `DeserializePacketBody` | `bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` | 委派給通道的 `PacketReceiveBodyHandler` |
   | `Clear` | `void Clear()` | 關閉通道(`NetworkCloseReason.Dispose` / `NetworkErrorCode.DisposeError`)並清理參考 |

2. (可選)為輔助器設定通道層級的序列化器。請注意，必須在通道初始化(`Initialize`)之前呼叫，否則會拋出例外：

   ```csharp
   public void SetChannelSerializer(IMessageSerializer serializer)
   {
       if (m_NetworkChannel != null)
       {
           throw new InvalidOperationException(
               "SetChannelSerializer must be called before Initialize().");
       }
       m_ChannelSerializer = serializer;
   }
   ```

   來源:[DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L32-L40)

3. 呼叫 `NetworkComponent.CreateNetworkChannel` 建立通道。`channelName` 不得為空，逾時時間取自元件的 `m_rpcTimeout`,且會自動套用忽略日誌用的訊息 ID 清單：

   ```csharp
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
       networkChannel.SetIgnoreLogNetworkIds(m_IgnoredSendNetworkIds, m_IgnoredReceiveNetworkIds);
       return networkChannel;
   }
   ```

   來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L176-L182)

4. TCP / WebSocket 會依編譯定義自動選擇，且無法在執行階段切換。選擇邏輯位於 `NetworkManager.CreateNetworkChannel`:

   ```csharp
   #if (ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL) || FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET
       NetworkChannelBase networkChannel = new WebSocketNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #else
       NetworkChannelBase networkChannel = new SystemTcpNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #endif
   ```

   來源:[NetworkManager.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.cs#L220-L224)

   兩種底層實作皆為 `NetworkChannelBase : INetworkChannel, IDisposable` 的密封子類別，分別位於 [NetworkManager.SystemTcpNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/SystemSocket/NetworkManager.SystemTcpNetworkChannel.cs#L45) 與 [NetworkManager.WebSocketNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/WebSocket/NetworkManager.WebSocketNetworkChannel.cs#L48)。

5. 通道初始化期間，輔助器會以反射方式掃描組件，並自動向通道註冊實作對應介面的處理器(接收標頭、接收主體、傳送標頭、傳送主體、心跳、壓縮、解壓縮)。因此，自訂處理器只需實作對應介面即可：

   ```csharp
   if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
   {
       var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
       m_NetworkChannel.RegisterHandler(handler);
   }
   ```

   來源:[DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L86-L90)

6. 使用回傳的 `INetworkChannel` 連線至目標伺服器，並在事件元件中訂閱連線/關閉/心跳遺失/錯誤這四種事件類型。輔助器已在 `Initialize` 中完成訂閱，`NetworkComponent` 會將其轉發為全域事件：

   ```csharp
   Event.CheckSubscribe(NetworkConnectedEventArgs.EventId, OnNetworkConnectedEventArgs);
   Event.CheckSubscribe(NetworkClosedEventArgs.EventId, OnNetworkClosedEventArgs);
   Event.CheckSubscribe(NetworkMissHeartBeatEventArgs.EventId, OnNetworkMissHeartBeatEventArgs);
   Event.CheckSubscribe(NetworkErrorEventArgs.EventId, OnNetworkErrorEventArgs);
   ```

   來源:[DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128)

7. 當不再需要通道時，將其銷毀：

   ```csharp
   public bool DestroyNetworkChannel(string channelName)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       return m_NetworkManager.DestroyNetworkChannel(channelName);
   }
   ```

   來源:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L190-L194)

## 常見變體

- **直接重複使用預設輔助器**：大多數專案只需呼叫 `CreateNetworkChannel("main", new DefaultNetworkChannelHelper())`,並搭配實作 `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler` / `IPacketSendHeaderHandler` / `IPacketSendBodyHandler` / `IPacketHeartBeatHandler` / `IMessageCompressHandler` / `IMessageDecompressHandler` 的處理器類別；註冊會透過反射自動完成。
- **切換至 WebSocket**:在 Player Settings 中加入 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` 定義(在非 WebGL 平台上強制使用 WebSocket),或使用 `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL`(適用於 WebGL 平台)。
- **多個通道並存**：為不同伺服器/閘道建立多個通道，每個通道各有唯一命名的 `channelName` 與輔助器實例；`NetworkComponent.GetAllNetworkChannels()` 可取得所有通道(參見 [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L154-L157))。

## 常見錯誤

| 症狀/錯誤 | 原因 | 如何避免 |
|------|------|------|
| `SetChannelSerializer must be called before Initialize().` | 在通道初始化之後才呼叫 `SetChannelSerializer`(`Initialize` 已將通道指派給輔助器)| 先呼叫 `SetChannelSerializer`,再執行建立/初始化 |
| 建立通道時拋出參數驗證例外 | `channelName` 為空或 null | 傳入非空的通道名稱(`GameFrameworkGuard.NotNullOrEmpty`)|
| 想要 WebSocket 卻使用了 TCP | 目前的編譯定義未進入 WebSocket 分支 | 確認 `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` 或 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` 定義已生效 |
| 序列化期間拋出 `GameFrameworkGuard.NotNull` | 通道尚未註冊 `PacketSendHeaderHandler` / `PacketSendBodyHandler` | 確認對應的處理器類別存在且實作相關介面，以便透過反射註冊 |

## 驗證

- 若 `CreateNetworkChannel` 回傳非 null 的 `INetworkChannel` 實例，表示通道建立成功。
- 在 `Initialize` 中使用中斷點或日誌，確認 `IPacketReceiveHeaderHandler`、`IPacketSendBodyHandler` 等已透過 `RegisterHandler` 註冊。
- 收到 `NetworkConnectedEventArgs` 事件表示連線成功；可使用 `NetworkErrorEventArgs` 與 `NetworkClosedEventArgs` 檢查失敗原因。

## 背景

通道輔助器(`INetworkChannelHelper`)是通道與具體封包格式之間的適配層：傳送時，訊息會交由 `IPacketSendHeaderHandler` / `IPacketSendBodyHandler` 建構封包；接收時，則透過 `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler` 解包為 `MessageObject`;心跳、壓縮與解壓縮也透過已註冊的處理器處理。傳輸層(TCP 或 WebSocket)由 `NetworkManager.CreateNetworkChannel` 內部的編譯定義決定，對業務程式碼而言是透明的。
