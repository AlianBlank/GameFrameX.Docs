# 當出現「Advertisement manager is invalid」時該怎麼辦

當執行時主控台出現 `Log.Fatal("Advertisement manager is invalid.")` 時，表示 `AdvertisementComponent.Awake()` 無法透過 `GameFrameworkEntry.GetModule<IAdvertisementManager>()` 取得廣告管理器的實例。元件會直接返回，後續的 `Start`、`Initialize` 等流程將不會執行。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| 出現日誌錯誤 `Advertisement manager is invalid.` | `GameFrameworkEntry` 中沒有註冊 `IAdvertisementManager` 實作 | 在場景中加入 `AdvertisementComponent`，並在 Inspector 中填入繼承自 `BaseAdvertisementManager` 的管理器類別完整類別名稱 |
| 同樣的錯誤，元件已掛載但仍報錯 | `componentType` 欄位填寫不正確（類別名稱拼寫錯誤、缺少命名空間、未繼承自 `BaseAdvertisementManager`） | 填寫完整的「命名空間.類別名稱」，確認類別繼承自 `BaseAdvertisementManager` 並實作 `IAdvertisementManager` |
| 同樣的錯誤，某平台的執行時管理器為 `null` | 未匯入該平台的廣告 SDK 套件，組件中找不到實作類別 | 安裝對應平台的 SDK（參見下方「修復步驟」），或暫時將 `componentType` 切換為已安裝的平台 |
| 同樣的錯誤，僅 Debug 建置時報錯 | Player Settings 中的 IL2CPP / 受管理程式碼剝離將管理器類別剔除 | 在 `link.xml` 或 Player Settings 的 `Managed Stripping Level` 中保留管理器所在的組件 |

原始錯誤文字與觸發位置：

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L85-L97
private IAdvertisementManager _advertisementManager;

protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IAdvertisementManager);
    base.Awake();
    _advertisementManager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
    if (_advertisementManager == null)
    {
        Log.Fatal("Advertisement manager is invalid.");
        return;
    }
    // ...
}
```

來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L85-L97)

## 修復步驟

### 1. 確認場景中存在 AdvertisementComponent

`AdvertisementComponent` 是廣告系統的入口元件。缺少它，框架就不會被驅動去註冊廣告管理器模組。掛載方式：

1. 在第一個啟動場景中建立一個空的 GameObject（通常命名為 `GameFrameX`）。
2. `Add Component → GameFrameX/Advertisement`，掛載 `AdvertisementComponent`。

### 2. 在 Inspector 中正確填寫 componentType

`AdvertisementComponent` 透過反射載入廣告管理器。**必須**填寫繼承自 `BaseAdvertisementManager` 的具體實作類別的**完整名稱（命名空間 + 類別名稱）**，否則 `Utility.Assembly.GetType(componentType)` 會返回 `null`，模組將不會被註冊。

常見的實作類別（基於官方儲存庫）：

| 平台 | 典型實作類別 |
|------|-----------|
| Android | `YourNamespace.AndroidAdvertisementManager` |
| iOS | `YourNamespace.IOSAdvertisementManager` |
| WebGL 通用 | `YourNamespace.WebGLAdvertisementManager` |
| WebGL 微信小遊戲 | `YourNamespace.WebGLWeChatAdvertisementManager` |
| WebGL 抖音小遊戲 | `YourNamespace.WebGLDouYinAdvertisementManager` |
| WebGL 快手小遊戲 | `YourNamespace.WebGLKuaiShouAdvertisementManager` |

填寫要點：

- 必須是**完整的型別名稱**，包含命名空間。
- 類別必須是 `public`，並繼承自 `BaseAdvertisementManager`（間接實作了 `IAdvertisementManager`）。
- `BaseAdvertisementManager` 本身繼承自 `GameFrameworkModule`，這是 `GameFrameworkEntry.GetModule<T>()` 能夠識別該模組的前提。

參考介面與基底類別定義：

```csharp

[Preserve]
public interface IAdvertisementManager
{
    [Preserve]
    void Initialize(AdvertisementConfig config);
    // ...
}

// Runtime/Advertisement/BaseAdvertisementManager.cs#L44-L45
[Preserve]
public abstract class BaseAdvertisementManager : GameFrameworkModule, IAdvertisementManager
{
    // ...
}
```

### 3. 確認已安裝目標平台 SDK

`componentType` 指向的實作類別相依於對應平台的廣告 SDK（例如 Pangle、AdMob、微信小遊戲廣告 SDK 等）。如果在 Android 專案中只掛載了 WebGL 平台的管理器，Android 建置時仍會找不到實作，觸發同樣的錯誤。處理方式：

- 安裝對應目標平台的 SDK 套件（`Packages/manifest.json` 或 `.unitypackage`）。
- 或暫時在 Inspector 中將 `componentType` 切換為已安裝平台的實作。

### 4. 檢查程式碼剝離與組件保留

iOS / IL2CPP 建置會執行受管理程式碼剝離，可能會誤將管理器移除。有兩種處理方式：

- Project Settings → Player → Other Settings → 將 `Managed Stripping Level` 設為 `Low` 或更低。
- 或在 `Assets/link.xml` 中明確保留管理器所在的組件：

```xml
<linker>
  <assembly fullname="YourAdvertisementImpl" preserve="all"/>
</linker>
```

### 5. 檢查 `m_config` 與廣告單元 ID

該錯誤本身與設定無關，但 `Start()` 會呼叫 `_advertisementManager.Initialize(m_config)`。如果此時管理器為 `null`（`_advertisementManager == null`），將立即拋出 `NullReferenceException`。因此，在管理器恢復正常後，還請確認：

- 已填寫與當前平台對應的 `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*`。
- `m_config`（`AdvertisementConfig` 實例）不為 `null`，否則 `Start` 中的初始化會被跳過：

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L120-L126
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

來源：[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)

## 驗證

按照上述步驟修復後，請進行以下檢查以確認問題已解決：

1. 執行遊戲，Console 中不再出現 `Advertisement manager is invalid.`。
2. 在 `Awake` 之後設定中斷點，確認 `_advertisementManager != null`。
3. 檢查 `Start` 中的 `_advertisementManager.Initialize(m_config)` 能正常進入，並完成廣告 SDK 的初始化回呼。
4. 呼叫廣告播放介面（例如激勵影片），能正常返回展示結果。

## 常見錯誤

- **只填寫類別名稱而未包含命名空間**：`Utility.Assembly.GetType(componentType)` 返回 `null`，模組將不會被註冊。
- **管理器類別未繼承自 `BaseAdvertisementManager`**：即使實作了 `IAdvertisementManager`，也不會被註冊為 `GameFrameworkModule`。
- **切換平台時未更新 `componentType`**：從 Android 切換到 iOS 打包時，`componentType` 仍指向 Android 的實作類別，導致管理器缺失。
- **掛載多個 `AdvertisementComponent`**：`[DisallowMultipleComponent]` 會防止重複掛載，但若場景中有多個 GameObject 各自掛載了一個，則只有最先執行 `Awake` 的那個會生效。
