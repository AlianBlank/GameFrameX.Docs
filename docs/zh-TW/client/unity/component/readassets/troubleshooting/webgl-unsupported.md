# 當 WebGL 平台無法使用時該怎麼辦

`com.gameframex.unity.readassets` 並未針對 WebGL 平台提供專屬的實作分支，而且 Unity WebGL 執行階段沙箱無法像本機磁碟或 APK 那樣，以同步方式直接開啟 StreamingAssets 中的檔案。因此，本框架在 WebGL 平台上**並未獲得官方支援**。一旦您將 Build Target 切換為 WebGL 並呼叫 `BlankReadAssets` 的任何 API，就會在編輯器中或執行階段遇到功能缺失或載入失敗的問題。

## 快速診斷

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 將 Build Target 切換為 WebGL 後，編譯器回報「WebGL is not supported」警告，或在 WebGL 建置中無法讀取 StreamingAssets 中的檔案 | 框架僅為 `UNITY_EDITOR` 與 `UNITY_ANDROID` 提供專屬實作分支。WebGL 與其他平台共用 `LooseFilesImpl`，而 WebGL 沙箱不支援同步的 `File` I/O | 參考下方修正步驟以切換解決方案 |
| 呼叫 `BlankReadAssets.ReadAllBytes / FileExists / LoadAssetBundle` 時回傳空值或擲出 `FileNotFoundException` | 在 WebGL 上，`LooseFilesImpl` 使用 `Application.streamingAssetsPath`，但 WebGL 上的 `AssetBundle.LoadFromFile` 必須改用 `UnityWebRequest` | 改用 Unity WebGL 原生介面（參見步驟 2） |
| 業務邏輯需要同時支援 WebGL 與 Android，並直接使用 `if (Application.platform == RuntimePlatform.WebGLPlayer)` 判斷 | 框架未為 WebGL 提供獨立的讀取路徑 | 在 WebGL 分支單獨呼叫 UnityWebRequest，其他平台則繼續使用 `BlankReadAssets`（參見步驟 3） |

## 修正步驟

### 1. 在 WebGL 建置中使用 UnityWebRequest

WebGL 平台上的檔案存取必須透過 `UnityWebRequest` 進行，這是 Unity WebGL 後端唯一正式支援的資源載入方式：

```csharp
using UnityEngine;
using UnityEngine.Networking;

public static class WebGLReadAssetsFallback
{
    public static UnityWebRequest ReadAllBytes(string relativePath)
    {
        // WebGL 上 StreamingAssets 的 URL 形如 http(s)://host/StreamingAssets/xxx
        var url = System.IO.Path.Combine(Application.streamingAssetsPath, relativePath);
        return UnityWebRequest.Get(url);
    }
}
```

### 2. 使用平台條件編譯保留舊有呼叫

在業務程式碼中使用巨集排除 WebGL，避免在 WebGL 上呼叫不支援的 API：

```csharp
#if !UNITY_WEBGL || UNITY_EDITOR
    using GameFrameX.ReadAssets.Runtime;
#endif

public byte[] LoadConfig(string path)
{
#if !UNITY_WEBGL || UNITY_EDITOR
    return BlankReadAssets.ReadAllBytes(path);
#else
    using (var req = WebGLReadAssetsFallback.ReadAllBytes(path))
    {
        req.SendWebRequest();
        while (!req.isDone) { }
        return req.downloadHandler.data;
    }
#endif
}
```

> 請參閱 `Runtime/BlankReadAssets.cs` 中依平台選擇實作的邏輯：

```csharp
#if UNITY_EDITOR
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.EditorImpl;
#elif UNITY_ANDROID
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.ApkImpl;
#else
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.LooseFilesImpl;
#endif
```

來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L11-L17)

### 3. 關於 AssetBundle 的額外說明

`BlankReadAssets.LoadAssetBundle` 內部呼叫 `AssetBundle.LoadFromFile`，而此 API 在 WebGL 上的行為是未定義的。如果您需要在 WebGL 上載入 AssetBundle，必須改用 `UnityWebRequestAssetBundle.GetAssetBundle`。框架目前並未提供對應的 WebGL 實作，因此您需要自行實作，或移除對此路徑的相依。

## 驗證

- 在編輯器中將 Build Target 切換為 WebGL，觸發場景初始化邏輯，確認除了「WebGL is not supported」之外，沒有印出其他執行階段例外。
- 在 WebGL Build 中開啟瀏覽器開發者工具，確認 `UnityWebRequest` 的請求路徑指向 `StreamingAssets` 底下正確的相對檔案，且回應為 200。
- 業務路徑調整為：非 WebGL 走 `BlankReadAssets`，WebGL 走 `UnityWebRequest`，並在兩條路徑上執行相同的資源載入煙霧測試。

## 背景說明（選讀）

此儲存庫的 README 在平台備註區段明確標示「WebGL is not supported」。本框架未提供 `UNITY_WEBGL` 實作分支。其他非 Android、非編輯器的平台全都對應至 `LooseFilesImpl`，後者是從實體磁碟讀取檔案，無法滿足 WebGL 沙箱的同步／非同步 I/O 需求。
