# 프로젝트 의존성 일괄 업데이트

`UpdateAllPackageHelper`를 통해 `Packages/manifest.json`에서 `.git`으로 끝나는 모든 Git 의존성을 원클릭으로 일괄 업데이트하여 수동으로 하나씩 작업하는 번거로운 과정을 없애줍니다.

## 사전 조건

- 프로젝트 루트 디렉토리에 `Packages/manifest.json`가 존재하며, 그 안에 최소 하나의 `*.git` 형식 의존성 주소가 포함되어 있어야 합니다.
- Unity로 본 프로젝트를 이미 열어둔 상태여야 합니다.
- 시스템 PATH에서 Git 명령을 사용할 수 있어야 합니다(UPM의 `Client.Add`가 로컬 Git을 호출하여 원격을 가져옵니다).

## 작업 단계

### 방법 1: 메뉴에서 원클릭 일괄 업데이트

1. Unity 에디터 상단 메뉴에서 `GameFrameX → Update All Packages(모든 git 패키지 업데이트)`를 선택합니다.
2. 확인 대화 상자 `모든 패키지를 업데이트하시겠습니까?`가 표시되면 **예**를 클릭합니다.
3. 도구가 `Packages/manifest.json`을 읽고 `.git`으로 끝나는 모든 의존성을 업데이트 큐에 추가한 다음 취소 가능한 진행률 표시줄을 표시합니다.
4. 업데이트가 완료되면 UPM이 변경 사항을 적용하도록 **Unity를 재시작**합니다.

진입점 구현은 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L20-L32)를 참조하세요:

```csharp
[MenuItem("GameFrameX/Update All Packages(更新所有git包)", false, 2000)]
public static void UpdatePackages()
{
    var result = EditorUtility.DisplayDialog("更新包提示", "是否更新所有包?\n 更新完成之后需要[重启、重启、重启]Unity", "是", "否");
    if (result)
    {
        var manifestPath = Path.Combine(Application.dataPath, "..", "Packages", "manifest.json");
        UpdatePackagesFromManifest(manifestPath);
    }
}
```

### 방법 2: Package Manager 창에서 지정 버전으로 업데이트

1. 에디터 창 `GameFrameX → Package Manager`를 엽니다.
2. 목록에서 업데이트할 패키지를 선택하고, 도구 모음에서 **Update To Version**을 클릭합니다.
3. 도구가 해당 패키지의 URL을 재작성하여 `#<version>` 접미사를 붙이고, `UpdateAllPackageHelper.UpdatePackages(name, url)`를 통해 즉시 업데이트 프로세스를 실행합니다.

구현은 [PackageManagerWindow.cs](/src/Editor/PackageManager/PackageManagerWindow.cs#L233-L274)을 참조하세요:

```csharp
saveManifest.Dependencies[dependency.Key] = url;
UpdateAllPackageHelper.UpdatePackages(packageName, url);
continue;
...
UpdateAllPackageHelper.StartUpdate();
AssetDatabase.Refresh();
```

도구 모음 진입점은 [PackageManagerWindow.ToolBar.cs](/src/Editor/PackageManager/PackageManagerWindow.ToolBar.cs#L60-L70)을 참조하세요. 버튼을 클릭하면 `UpdateAllPackageHelper.UpdatePackages()`를 직접 호출합니다.

### 방법 3: 코드 레이어에서 호출

사용자 정의 에디터 스크립트에서 동일한 로직을 재사용하려면 두 개의 정적 메서드를 직접 호출하면 됩니다:

```csharp
using GameFrameX.Editor;

// 단일 Git 의존성을 큐에 추가
UpdateAllPackageHelper.UpdatePackages("com.gameframex.runtime", "https://example.com/repo.git");

// 실제 가져오기 시작(큐에서 순서대로 Client.Add)
UpdateAllPackageHelper.StartUpdate();
```

시그니처 정의는 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L34-L42)를 참조하세요:

```csharp
/// <summary>
/// 更新指定包
/// </summary>
/// <param name="packageName">包名</param>
/// <param name="packageUrl">包地址</param>
public static void UpdatePackages(string packageName, string packageUrl)
{
    PackagesToUpdate.Enqueue((packageName, packageUrl));
}
```

## manifest 스캔 및 큐 채우기 로직

`UpdatePackages()`는 private 메서드 `UpdatePackagesFromManifest`를 호출하여 `manifest.json`을 파싱하고, `.git`으로 끝나는 의존성만 큐에 추가하며 그 외 형식의 버전 번호/로컬 경로는 무시됩니다. [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L44-L64)를 참조하세요:

```csharp
foreach (var package in dependencies)
{
    string packageName = package.Key;
    string packageUrl = package.Value.ToString();
    if (packageUrl.EndsWith(".git"))
    {
        UpdatePackages(packageName, packageUrl);
    }
}
StartUpdate();
```

## 일반적인 변형

| 시나리오 | 방법 |
|------|------|
| 특정 패키지만 고정 버전으로 업데이트하고 싶을 때 | Package Manager 창을 열고 Update To Version 기능을 사용하세요(자동으로 `#<tag>`를 붙임) |
| 버전 번호를 유지하면서 일괄 업데이트만 하고 싶을 때 | manifest.json의 URL이 `https://.../repo.git#v1.2.0` 형식인지 확인하세요. UPM이 해당 tag를 가져옵니다. |
| 코드에서 더 많은 소스 업데이트를 확장하고 싶을 때 | 더 많은 `(name, url)`을 직접 큐에 추가한 후 `StartUpdate()`를 호출하세요. |

## 일반적인 오류

- **업데이트 후 콘솔 오류**: 진행률 표시줄이 취소되면 큐가 `PackagesToUpdate.Clear()`로 비워집니다. [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L92-L99)를 참조하세요. 계속하려면 메뉴를 다시 실행하세요.
- **manifest.json 변경 사항이 적용되지 않음**: 메뉴 안내에서 명확히 **Unity 재시작, 재시작, 재시작**을 요구하며, 그렇지 않으면 UPM 캐시가 새로 고쳐지지 않습니다.
- **의존성이 `.git` 주소가 아니어서 무시됨**: 예를 들어 `file:./...` 또는 OpenUPM 링크는 건너뛰며, Package Manager 창의 Update To Version을 사용하여 처리해야 합니다.
- **`Client.Add` 호출 빈도가 너무 빠름**: 큐 구현 `Queue<(name, url)>`은 순차적으로 처리하여 동시 요청으로 인한 예외를 방지합니다.

## 배경(선택 사항)

`UpdateAllPackageHelper`는 내부적으로 `AddRequest` + `EditorApplication.update` 이벤트를 사용하여 진행률을 구동하고, 패키지마다 `UnityEditor.PackageManager.Client.Add`를 호출하며, `EditorUtility.DisplayCancelableProgressBar`를 통해 취소 가능한 진행률 피드백을 제공합니다. 모든 상태(`_addRequest`, `PackagesToUpdate`, `_allPackagesCount`, `_updatingPackagesIndex`)는 `static` 필드로 호출 간에 유지되므로, 여러 번 큐에 추가한 후 한 번에 시작하는 데 적합합니다.
