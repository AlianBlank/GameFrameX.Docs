# 安装与项目集成

按照本页步骤在 Unity 项目中集成 `com.gameframex.unity.objectstorage` 对象存储组件,完成后即可在代码中使用 `IObjectStorageManager`、`IObjectStorageUploadManager` 等接口,接入具体云服务商实现完成上传。

## 前置条件

- Unity 版本 ≥ 2019.4(本包 `unity` 字段声明的最低版本)
- 已在 Unity 中打开目标工程,或准备好一个待集成的工程根目录
- 可访问 GitHub 源仓库,或可访问 GameFrameX 的 UPM 注册表(`https://gameframex.upm.alianblank.uk`)

依赖关系来自 [package.json](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/package.json#L21-L23):

```json
"dependencies": {
  "com.gameframex.unity": "2.5.1"
}
```

安装本包时会自动拉取 `com.gameframex.unity` 2.5.1。

## 操作步骤

本包提供 4 种安装方式,任选其一即可。

### 方式一:通过 UPM 注册表(推荐)

1. 打开工程根目录下的 `Packages/manifest.json`。
2. 在 `scopedRegistries` 中加入 GameFrameX 注册表,并在 `dependencies` 中声明本包:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.objectstorage": "1.1.0"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/README.zh-CN.md#L41-L59)

3. `scopes` 控制哪些包从此注册表解析;只有 `com.gameframex` 命名前缀的包会走该注册表,其他包继续走默认源。
4. 保存文件后回到 Unity,等待 Package Manager 完成解析。

### 方式二:Git URL 直引

在 `Packages/manifest.json` 的 `dependencies` 节点下追加:

```json
{
  "dependencies": {
    "com.gameframex.unity.objectstorage": "https://github.com/gameframex/com.gameframex.unity.objectstorage.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/README.zh-CN.md#L61-L66)

此方式会直接拉取 `main` 分支最新提交,适合需要跟踪主分支的工程。

### 方式三:Unity Package Manager 添加 Git URL

1. 在 Unity 中打开 `Window → Package Manager`。
2. 点击左上角 `+`,选择 `Add package from git URL...`。
3. 输入:`https://github.com/gameframex/com.gameframex.unity.objectstorage.git`,点击 `Add`。

### 方式四:手动放置到 Packages 目录

1. 下载仓库 ZIP 或克隆到本地。
2. 将整个 `com.gameframex.unity.objectstorage` 文件夹移动到 Unity 工程的 `Packages/` 目录下。
3. Unity 会自动识别本地包并完成加载。

## 验证集成

安装完成后,在 Unity 中打开 `Window → Package Manager`,在 `In Project` 列表中应能看到 **Game Frame X Object Storage**。

包元数据来自 [package.json](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/package.json#L1-L8):

| 字段 | 值 |
|------|----|
| `name` | `com.gameframex.unity.objectstorage` |
| `displayName` | Game Frame X Object Storage |
| `category` | Game Framework X |
| `version` | `1.2.0` |
| `unity` | `2019.4` |

随后在你的启动逻辑里调用 `ObjectStorageUploadFactory` 创建一个上传管理器,即可使用 `IObjectStorageUploadManager` 暴露的文件/目录上传能力。具体工厂用法与服务商实现,见相关参考页。

## 常见变体

| 场景 | 选择 |
|------|------|
| 团队工程、希望版本可锁定 | 方式一(注册表 + 指定 `1.1.0` 这样的固定版本) |
| 内网环境无法访问 UPM | 方式四(手动放置,或在内网搭建 Git 源用方式二) |
| 需要在 Git URL 中固定分支或 Tag | 方式二,URL 写为 `https://github.com/gameframex/com.gameframex.unity.objectstorage.git#v1.1.0` |
| 想直接跟踪最新 main | 方式二或方式三,不带 ref |

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| Package Manager 报 `Could not resolve package` | 注册表 `url` 写错,或网络无法访问 `https://gameframex.upm.alianblank.uk` | 核对 `scopedRegistries.url`;切换方式二/方式四 |
| 误把 `com.gameframex` 包改从默认 npm 源解析 | 没配 `scopedRegistries.scopes`,或 `scopes` 漏掉 `com.gameframex` | 补齐 `scopes: ["com.gameframex"]` |
| `dependencies` 写的是最新包名但解析到旧版本 | 用了 Git URL 但缓存了旧 commit | 在 URL 末尾追加 `#v1.1.0` 锁定 tag |
| 报 `Unity 2019.4 required` | 工程 Unity 版本低于 2019.4 | 升级 Unity 或换用满足版本要求的工程 |

## 背景(可选)

本包仅提供对象存储的抽象接口与工厂,具体云服务商实现以同名独立包发布,例如阿里云 OSS、AWS S3 等。安装本包只是接入接口层,真正调用前还需安装并初始化对应服务商的实现包,然后通过 `ObjectStorageUploadFactory` 拿到 `IObjectStorageUploadManager` 实例即可调用 `UploadFile`、`UploadDirectory` 等方法。
