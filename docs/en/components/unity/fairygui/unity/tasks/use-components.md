# Using Components and Common Controls

`GComponent` is the base class of all components (containers) in FairyGUI, responsible for adding, removing, managing, and looking up child objects; common controls such as buttons, lists, and labels are all defined in the `Runtime/UI/` directory. This page provides the common steps for manipulating components in code, finding child controls, and choosing the appropriate control class.

## Prerequisites

- The package (FairyGUI for Unity) has been installed in the project, and the `Runtime` assembly compiles successfully.
- You already have the component instance to operate on (variables such as `component` and `icon` in the code below).

## Steps

1. First, learn the three key properties of a component: `rootContainer` is the root container; `container` is the content container, which is the same object as `rootContainer` when the component is not clipped; `scrollPane` only has a value when scrolling is enabled on the component, otherwise it is `null`.

```csharp
/// Root container.
public Container rootContainer { get; private set; }

/// Content container. If the component is not clipped, then container==rootContainer.
public Container container { get; protected set; }

/// The component's ScrollPane. If the component is not scrollable, the value is null.
public ScrollPane scrollPane { get; private set; }
```

Source: [GComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GComponent.cs#L19-L29)

2. Add, insert, and remove child objects. Common method signatures are as follows:

| Method | Signature | Description |
|------|------|------|
| AddChild | `GObject AddChild(GObject child)` | Adds a child object and places it on the top layer |
| AddChildAt | `virtual GObject AddChildAt(GObject child, int index)` | Inserts a child object at the specified index |
| RemoveChild | `GObject RemoveChild(GObject child, bool dispose)` | Removes a child object; destroys it immediately when `dispose` is true |
| RemoveChildAt | `virtual GObject RemoveChildAt(int index, bool dispose)` | Removes by index, with optional disposal |
| RemoveChildren | `void RemoveChildren(bool dispose = false)` | Removes all child objects |

Source: [GComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GComponent.cs#L216-L378)

```csharp
using FairyGUI;

// Add to the top layer
GObject added = component.AddChild(icon);

// Insert at the bottom layer (index 0)
component.AddChildAt(icon, 0);

// Remove but do not destroy; can be re-added with AddChild later
component.RemoveChild(added);

// Remove and destroy immediately
component.RemoveChild(added, true);
```

Source: [GComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GComponent.cs#L216-L303)

3. Find child controls. Look up by name, index, or path; after retrieval, you can cast to a concrete control type and operate on it:

```csharp
GObject title = component.GetChild("title");              // Returns null if not found
GObject first = component.GetChildAt(0);                  // Get by index
GObject deep  = component.GetChildByPath("panel.list");   // Look up layer by layer via path

// After retrieval, treat it as a component and continue operating on its subtree
GComponent panel = component.GetChild("panel") as GComponent;
```

Source: [GComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GComponent.cs#L392-L417)

4. To release a component, call `Dispose()` directly: it first destroys all `Transition`, `Controller`, and `ScrollPane` objects, then releases the display tree and disposes of each child object one by one, so do not manually destroy child objects again.

## Common Variants

- Deep lookup by path: `component.GetChildByPath("panel.list")` parses the path layer by layer, which is more concise than multiple `GetChild` calls.
- Lookup within a group: first find the `GGroup` by name, then use `GetChildInGroup(group, name)` to look up within that group.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GetChild` returns null | Misspelled name or the child object is not under this component | Verify the child object name in the editor; use `GetChildByPath` when the hierarchy is deep |
| Abnormal leaks after removing child objects | `RemoveChild(child)` does not destroy by default | If reuse is no longer needed, use `RemoveChild(child, true)` or `RemoveChildren(true)` instead |
| Double disposal | Manually calling `Dispose` on child objects and then disposing the component | Only dispose the top-level component; child objects are handled uniformly by `GComponent.Dispose` |
| `scrollPane` is null | Scrolling is not enabled on the component | Scrolling is only available after a ScrollPane is configured on the component |

## Background

`GComponent` inherits from `GObject`, internally maintains three lists — `_children`, `_controllers`, and `_transitions` — and creates a `Container` as its display object at construction; clipping (clip) and scrolling (ScrollPane) change the relationship between `container` and `rootContainer` when building the display list. For the component's place in the overall framework, see the Overview page.
