# ビルド失敗とホットアップデート異常時の対処法

このページでは、GameFrameX の `BuildProduct`（製品ビルド）と `BuildHotfix`（ホットアップデートビルド）メニューを使用する際によく発生する問題について、症状ごとの切り分け方法を示し、ソースコードと一致する修正方法を提供します。

## 迅速な診断

| 症状（ログ原文） | 原因 | 修正方法 |
|------|------|------|
| `当前构建目标不是 Windows` | メニューは現在の `BuildTarget` がメニューターゲットと一致することを要求しているが、他のプラットフォームに切り替え済み | `File → Build Settings` を開き、プラットフォームを対応するターゲットに切り替えてからメニューを実行する |
| `当前构建目标不是 Mac Os` | 同上、macOS パッケージングエントリ向け | `StandaloneOSX` に切り替えて再試行する |
| `当前构建目标不是 WebGL` | 同上、WebGL パッケージングエントリ向け | `WebGL` に切り替えて再試行する |
| `当前构建目标不是 Android` | 同上、Android パッケージングエントリ向け | `Android` に切り替えて再試行する |
| `输出路径异常,取消打包AAB` | ビルド出力ディレクトリが空または書き込み不可 | 後述の修正手順 4 を参照 |
| `未找到HybridCLR数据目录:{path}` | HybridCLR の生成フローをまだ実行していないため、`HybridCLRData/AssembliesPostIl2CppStrip/<Target>` が存在しない | まず `HybridCLR → Generate` を実行してから AOT をコピーする |
| `复制Hotfix DLL到Assets/Bundles/Code完成` の後でも実行時にホットアップデートコードが見つからない | `Unity.HotFix.dll` を `Library/ScriptAssemblies` にコピーしていない | `GameFrameX → Build → Copy HotFix Code` を実行する |
| `Build Output Path:...` と表示されているがビルドが失敗する | 出力ディレクトリの権限またはディスク容量不足 | 書き込み可能なディレクトリに変更し、古い生成物をクリーンアップする |

## 修正手順

### 1. プラットフォーム不一致（「当前构建目标不是 XXX」）

`BuildProductHelper` は各プラットフォームエントリで `EditorUserBuildSettings.activeBuildTarget` を最初に検証し、一致しない場合は `Debug.LogError` を出力して `return` します：

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    Debug.Log(EditorUserBuildSettings.activeBuildTarget);
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("当前构建目标不是 Windows");
        return;
    }
    ...
}
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L101-L110)

**操作手順：**

1. Unity メニュー `File → Build Settings…`
2. エントリに対応する `Target Platform`（Windows64 / macOS / WebGL / Android）に切り替える
3. `Switch Platform` をクリックしてプラットフォーム切替の完了を待つ
4. `GameFrameX → Build → <対応プラットフォーム>` を再実行する

### 2. AOT メタデータのコピー失敗（「未找到HybridCLR数据目录」）

`CopyAOTCode` は `<Project>/HybridCLRData/AssembliesPostIl2CppStrip/<activeBuildTarget>` から `*.dll` を `Assets/Bundles/AOTCode/` にコピーします。このディレクトリが存在しない場合はエラーを出力して return します：

```csharp
DirectoryInfo aotCodeDir = new DirectoryInfo(path);
if (!aotCodeDir.Exists)
{
    Debug.LogError($"未找到HybridCLR数据目录:{path}");
    return;
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L84-L92)

**操作手順：**

1. Unity で `HybridCLR → Generate`（または対応プロジェクトの `HybridCLR/Generate` フロー）を開いて、Strip 後の AOT DLL を生成する
2. `HybridCLRData/AssembliesPostIl2CppStrip/<Target>` 配下に `*.dll` が生成されたことを確認する
3. その後 `GameFrameX → Build → Copy AOT Code` を実行する

### 3. `Unity.HotFix.dll` が見つからない

`BuildHotfixHelper.CopyHotfixCode()` はデフォルトで `Library/ScriptAssemblies/Unity.HotFix.dll` から `Assets/Bundles/Code/Unity.HotFix.dll.bytes` にコピーします：

```csharp
private const string HotFixAssembliesDir = "Library/ScriptAssemblies";
private static readonly string[] HotfixDlls = new string[] { "Unity.HotFix.dll" };
private const string CodeDir = "Assets/Bundles/Code/";

foreach (var hotfix in HotfixDlls)
{
    var srcPath = Path.Combine(HotFixAssembliesDir, hotfix);
    if (!File.Exists(srcPath))
    {
        continue;
    }
    File.Copy(srcPath, Path.Combine(CodeDir, hotfix + Utility.Const.FileNameSuffix.Binary), true);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L21-L65)

`Library/ScriptAssemblies` 配下に該当 DLL がない場合、コードは静かに `continue` し、最終的に `Assets/Bundles/Code/` は空になります。**操作手順：**

1. プロジェクト内に `Unity.HotFix` の `asmdef`（ホットアップデートアセンブリ）が存在することを確認し、名前は厳密に `Unity.HotFix.dll` である必要がある
2. 対応するビルドターゲットに切り替え、Unity に再コンパイルさせて `Library/ScriptAssemblies/Unity.HotFix.dll` が生成されることを確認する
3. その後 `GameFrameX → Build → Copy HotFix Code(复制热更新代码到Assets>Bundles>Code)` を実行する
4. `Assets/Bundles/Code/` 配下に `Unity.HotFix.dll.bytes` が生成されたことを確認する

### 4. AAB 出力パスの異常

Android AAB エントリは出力ディレクトリを検証する際に以下を出力します：

```csharp
Debug.LogError("输出路径异常,取消打包AAB");
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L421)

**操作手順：**

1. `GameFrameX/Build` メニューを実行する前にビルド出力ディレクトリを設定し、パスが存在し現在のユーザーが書き込み可能であることを確認する
2. 前回のビルド残骸（同名古い AAB の占有、読み取り専用ファイル）をクリーンアップする
3. 対応する Android AAB エントリを再実行する

### 5. 一時的に HybridCLR を無効化したい

ソースコードにはマクロスイッチ `DISABLE_HYBRIDCLR` が用意されており、メニューからワンクリックで切り替えできます：

```csharp
public const string HybridCLRScriptingDefineSymbol = "DISABLE_HYBRIDCLR";

[MenuItem("GameFrameX/Scripting Define Symbols/Disable HybridCLR(关闭HybridCLR适配)", false, 5000)]
public static void DisableHybridCLR()
{
    ScriptingDefineSymbols.AddScriptingDefineSymbol(HybridCLRScriptingDefineSymbol);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L107-L116)

ホットアップデートリンクによってパッケージングフロー全体が失敗し、とりあえずビルド成果物を出す必要がある場合は、一時的に `GameFrameX → Scripting Define Symbols → Disable HybridCLR` を実行して、ホットアップデート関連のステップをスキップして問題を切り分け、その後 `Enable HybridCLR` で復元してください。

## 検証

ビルド/ホットアップデートの問題を修正した後、以下の順序で自己チェックを行ってください：

1. `BuildProductHelper` エントリが `当前构建目标不是 XXX` のような LogError を出力せず、ビルドレポートが `BuildResult.Succeeded` になる
2. `Assets/Bundles/Code/Unity.HotFix.dll.bytes` と `Assets/Bundles/AOTCode/` 配下に今回のターゲットの AOT DLL が存在する
3. ビルド成果物を実行し、HybridCLR ホットアップデートエントリが正常にホットアップデートアセンブリを読み込める
