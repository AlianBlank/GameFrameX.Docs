# Troubleshooting

This document collects common issues and solutions when using the CoroutineComponent.

## Overview

CoroutineComponent is the coroutine management component of the GameFrameX framework, extending Unity's built-in coroutine functionality and providing better coroutine lifecycle management and memory safety control. This component uses `ConcurrentDictionary` thread-safe dictionary to track all running coroutines, ensuring they can be managed and stopped at any time.

> For detailed usage instructions, refer to [Usage Guide](./3-getting-started.index) and [API Reference](./4-api-reference.coroutine-component).

## Common Issues

### Q1: Why can't I add multiple CoroutineComponent to the same GameObject?

**Problem Description:**
When trying to add a second CoroutineComponent to the same GameObject, the Unity Editor reports an error or cannot add it.

**Reason:**
CoroutineComponent uses the `[DisallowMultipleComponent]` attribute, which prevents adding multiple components of the same type to a GameObject.

**Solution:**
- Ensure only one CoroutineComponent instance per GameObject
- If you need to manage multiple coroutines, start multiple coroutines on the same CoroutineComponent instance
- Use `StopAllCoroutines()` method to stop all coroutines

```csharp
// Correct usage: manage multiple coroutines on the same component
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(CoroutineA());
coroutineComponent.StartCoroutine(CoroutineB());
coroutineComponent.StopAllCoroutines(); // Stop all coroutines
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L10-L11)

### Q2: What happens if I pass null to StartCoroutine?

**Problem Description:**
What happens when passing a null value IEnumerator to the `StartCoroutine` method?

**Reason:**
If you pass a null enumerator to `StartCoroutine`, Unity's underlying layer will throw a null reference exception.

**Solution:**
- Always check if the enumerator is null before starting a coroutine
- Add null protection logic

```csharp
IEnumerator myCoroutine = GetSomeCoroutine(); // May be null

if (myCoroutine != null)
{
    coroutineComponent.StartCoroutine(myCoroutine);
}
```

### Q3: How to correctly stop a running coroutine?

**Problem Description:**
After calling `StopCoroutine`, the coroutine seems to still be running, or the coroutine cannot be stopped.

**Reason:**
- The passed IEnumerator is not the same reference as when the coroutine was started
- The coroutine has already finished execution
- The coroutine ended before StopCoroutine was called

**Solution:**
- Save the IEnumerator reference returned when starting the coroutine
- Use `StopAllCoroutines()` to stop all coroutines
- Ensure timely stopping during coroutine execution

```csharp
// Save coroutine reference
IEnumerator myCoroutine = coroutineComponent.StartCoroutine(MyLongRunningTask());

// Stop at appropriate time
coroutineComponent.StopCoroutine(myCoroutine);

// Or stop all coroutines
coroutineComponent.StopAllCoroutines();
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L32-L45)

### Q4: What happens when the GameObject with the component is destroyed?

**Problem Description:**
What happens to running coroutines when the GameObject containing CoroutineComponent is destroyed?

**Reason:**
When a GameObject is destroyed, Unity automatically stops all coroutines on that GameObject. Since CoroutineComponent inherits from MonoBehaviour, it also follows this behavior.

**Suggestions:**
- Before scene transitions or object destruction, manually call `StopAllCoroutines()` to ensure coroutines stop cleanly
- Use OnDestroy lifecycle hook for cleanup

```csharp
private void OnDestroy()
{
    // Ensure all coroutines are stopped before object destruction
    if (coroutineComponent != null)
    {
        coroutineComponent.StopAllCoroutines();
    }
}
```

### Q5: Will passing null to WaitForEndOfFrameFinish crash?

**Problem Description:**
What happens when passing a null callback to the `WaitForEndOfFrameFinish` method?

**Reason:**
CoroutineComponent uses the null-coalescing operator `callback?.Invoke()`, so passing a null callback will not cause a crash; the call is safely ignored.

**Source Code Verification:**
```csharp
public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(_WaitForEndOfFrameFinish(callback));
}

private IEnumerator _WaitForEndOfFrameFinish(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke(); // Uses ?. operator for safe invocation
}
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L97)

### Q6: How to execute logic after frame rendering?

**Problem Description:**
Need to execute certain operations after Unity renders each frame. How to use it?

**Solution:**
Use the `WaitForEndOfFrameFinish` method, which executes the callback after the current frame rendering is complete.

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    // This callback executes after frame rendering
    Debug.Log("Frame rendering ended, executing logic");
});
```

**Applicable Scenarios:**
- Get screenshot after UI rendering
- Execute certain operations after physics calculations complete
- State synchronization needed at the end of frame

### Q7: Is CoroutineComponent thread-safe?

**Problem Description:**
Can CoroutineComponent be used in multi-threaded environments?

**Reason:**
Yes, CoroutineComponent uses `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` to store coroutine mappings, which is thread-safe.

**Notes:**
- Although internal storage is thread-safe, coroutines themselves execute on the Unity main thread
- When accessing from multiple threads, mainly consider correctly passing the IEnumerator reference

---

### Q8: How to handle memory leaks from uncorrectly stopped coroutines?

**Problem Description:**
Coroutines not correctly stopped may cause memory leaks. How to prevent?

**Reason:**
If coroutines are not correctly stopped, especially those containing infinite loops or long waits, memory leaks may occur. CoroutineComponent helps manage this issue by maintaining a coroutine mapping table.

**Solutions:**
- Use `StopAllCoroutines()` to clean up all coroutines
- Ensure `StopAllCoroutines()` is called when components are destroyed
- Use coroutines with clear end conditions

```csharp
private void OnDestroy()
{
    // Important: ensure all coroutines are stopped to prevent memory leaks
    StopAllCoroutines();
}
```

### Q10: Does CoroutineComponent need to be manually added to GameObject?

**Problem Description:**
Why isn't the component automatically added to the scene?

**Reason:**
CoroutineComponent sets `IsAutoRegister = false` in the `Awake` method, meaning the component does not automatically register with the framework's auto-registration system.

**Solution:**
Manually add CoroutineComponent to a GameObject:

```csharp
// Manual component addition
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();

// Or manually add in Unity Editor
// 1. Select GameObject
// 2. Click Add Component
// 3. Search "Game Framework/Coroutine"
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L99-L103)

### Q11: How to find CoroutineComponent in Unity Editor?

**Problem Description:**
How to add CoroutineComponent in Unity Editor?

**Solution:**

2. Right-click in Inspector panel -> Add Component
3. Search "Coroutine" or "Game Framework/Coroutine" in the search box

## Diagnostic Steps

If you encounter problems that cannot be resolved, follow these diagnostic steps:

1. **Check GameObject Status**: Confirm GameObject and component are active
2. **Check Coroutine References**: Confirm the IEnumerator reference used to stop the coroutine is correct
3. **View Unity Console**: Check for error or warning messages
4. **Use StopAllCoroutines**: As a debugging method, first stop all coroutines to isolate the problem
5. **Check Scene Transitions**: Confirm coroutines are correctly cleaned up during scene transitions
