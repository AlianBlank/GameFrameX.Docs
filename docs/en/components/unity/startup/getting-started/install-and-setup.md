# Installing and Configuring the GameFrameX Startup Package

This guide walks you through integrating the GameFrameX Startup package into a Unity project and completing the minimal configuration required for the first run: declaring the scoped registry, creating a `StartupOptions` asset, and implementing the UI and hotfix injection interfaces. Once done, you can call `await StartupRunner.Run(...)` to launch the full startup flow.

## Prerequisites

- Unity 2019.4 or higher (see the `unity` field in [package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L7))
- GameFrameX series dependencies such as UniTask are already enabled in the project (automatically resolved via the npm registry in the same repository; no manual declaration needed)
- Network access to the GameFrameX private npm registry `https://gameframex.upm.alianblank.uk`

## Steps

### 1. Add the Package and Scoped Registry to manifest.json

Open `Packages/manifest.json` in your project and add both the package dependency and the scoped registry (`scopes` must be limited to `com.gameframex` to use this registry):

```json
{
  "dependencies": {
    "com.gameframex.unity.startup": "1.1.0"
  },
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ]
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L22-L37)

After saving, Unity Package Manager will automatically fetch all dependencies listed in `package.json` ([package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L28-L40)).

### 2. Create the StartupOptions Configuration Asset

In the Unity Editor: `Assets > Create > GameFrameX > Startup Options` to generate a `StartupOptions` ScriptableObject asset.

Minimum required fields:

| Field | Description |
|------|------|
| `GlobalInfoUrls` | Primary and backup URL list for the global info endpoint (failover in order) |
| `GamePlayMode` | Asset runtime mode (the startup flow syncs it to the Asset component before loading assets) |
| `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` | Hotfix entry assembly / type / method |
| `PackageName` / `Channel` / `SubChannel` | Common HTTP parameters |
| `LauncherUIResName` | Startup UI resource path (default `UI/UILauncher`) |
| `SkipRemoteStartupRequests` | When true, skips all remote startup requests (global info / app version / bundle version); suitable for WebGL standalone or backend-less deployments |

See [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L1-L120) for field definitions and details.

### 3. Implement the UI Handler (IStartupUIHandler)

The UI backend is agnostic; you can use FairyGUI / UGUI / a custom implementation. The following members must be implemented:

```csharp
public class GameStartupUIHandler : IStartupUIHandler
{
    public UniTask StartAsync(string uiResName) { /* Load the UI */ }
    public void SetTipText(string text) { /* Update the tip text */ }
    public void SetProgress(float progress, string sizeInfo) { /* Update the progress bar */ }
    public void SetProgressUpdateFinish() { /* Mark as complete */ }
    public void Dispose() { /* Close the UI, release subscriptions */ }
}
```

### 4. Implement the Hotfix Launcher (IHotfixLauncher)

Hotfix solution agnostic; compatible with HybridCLR or other solutions. Load and invoke using the assembly / type / method names provided in `options`:

```csharp
public class HybridClrHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        // Load the hotfix assembly via options.HotfixAssemblyName
        // Invoke options.HotfixEntryTypeName.options.HotfixEntryMethodName
        return HotfixLaunchResult.Succeed();
    }
}
```

### 5. Trigger the Startup

Call `StartupRunner.Run(options, uiHandler, hotfixLauncher)` in your game entry script, then either await the returned `UniTask<StartupResult>` or subscribe to the `StartupCompleted` / `FailedEventArgs` events.

See [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L1-L80) for the entry point location.

## Common Variants

- **WebGL / standalone deployments**: Set `SkipRemoteStartupRequests` to `true` to skip the three remote requests (global info / app version / bundle version).
- **PlayMode switching**: Choose `EditorSimulateMode` / `OfflinePlayMode` / `HostPlayMode` / `WebPlayMode` in `StartupOptions.GamePlayMode` based on the target platform; the startup flow will adapt its branching accordingly.
- **Private npm registry**: The package's `publishConfig.registry` points to `https://npm.cnb.cool/GameFrameX/npm/-/packages/` (see [package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L41-L44)); only relevant if you need to build your own publishing pipeline.

## Common Errors

| Symptom | Possible Cause | Fix |
|------|----------|------|
| Package Manager cannot find `com.gameframex.unity.startup` | `scopedRegistries` not declared or `scopes` misconfigured | Confirm `scopes` includes `com.gameframex` and the URL is `https://gameframex.upm.alianblank.uk` |
| Startup stuck at "fetching global info" | All `GlobalInfoUrls` failed and `MaxAttemptsPerUrl` is exhausted | Check URL reachability; increase the retry count if necessary |
| Hotfix entry not triggered | `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` mismatch with the actual assembly | All three must exactly match the namespace.class.method in the hotfix DLL |
| Backend requests fail in WebGL deployments | `SkipRemoteStartupRequests` not enabled | Set it to `true` for standalone deployment scenarios |

## Background

The package name is `com.gameframex.unity.startup`, currently at version 1.4.3 ([package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L1-L6)). Design philosophy: variable items are centralized in the `StartupOptions` asset and two interfaces (`IStartupUIHandler` / `IHotfixLauncher`); business projects only need to implement the injections on both the UI and hotfix sides.
