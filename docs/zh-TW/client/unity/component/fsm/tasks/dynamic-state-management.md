# 如何動態新增與移除狀態

在有限狀態機執行期間，您可以隨時向已建立的 FSM 新增狀態，或移除不再需要的狀態。本頁說明如何在執行階段呼叫 `AddState` / `RemoveState`，以及需要注意的限制事項。

## 前置條件

- 必須已有 `IFsm<T>` 執行個體（透過 `FsmManager.CreateFsm` 建立，詳情請參閱建立流程）
- 需準備繼承 `FsmState<T>` 的狀態類別

## 操作步驟

1. **確認狀態不存在**（避免重複新增）。使用 `HasState<TState>()` 進行判斷，內部以 `Type` 作為字典索引鍵進行檢查。

   ```csharp
   if (!fsm.HasState<RunState>())
   {
       fsm.AddState(new RunState());
   }
   ```

   來源：[Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L328-L332)

2. **新增狀態**：呼叫 `AddState(FsmState<T>)`。若重複新增相同型別的狀態，將擲回 `GameFrameworkException`。

   ```csharp
   fsm.AddState(new RunState());
   Assert.AreEqual(2, fsm.FsmStateCount);
   ```

   來源：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L78-L91)

3. **啟動新增的狀態**（選用）：使用 `Start<TState>()` 立即切換至剛新增的狀態。

   ```csharp
   fsm.Start<RunState>();
   ```

   來源：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L89-L90)

4. **移除狀態**：呼叫 `RemoveState<TState>()`。回傳 `true` 表示移除成功，回傳 `false` 表示該狀態不存在。

   ```csharp
   if (fsm.RemoveState<RunState>())
   {
       // 已移除
   }
   ```

   來源：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L94-L107)

## 常見變化

### 在多個 FSM 間共用同一狀態執行個體

`AddState` 接收已建立的 `FsmState<T>` 執行個體。請勿將同一執行個體重複註冊至多個 FSM，否則狀態內的回呼會作用於多個 `Owner`，導致狀態污染。

### 透過 `Type` 呼叫（無法使用泛型時）

`IFsm<T>` 另提供非泛型多載 `HasState(Type)` 與 `GetState(Type)`，其簽章可在介面定義中確認：

```csharp
bool HasState(Type stateType);
FsmState<T> GetState(Type stateType);
```

來源：[IFsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsm.cs#L128-L144)

## 常見錯誤

| 錯誤症狀 | 原因 | 解決方法 |
|----------|------|------|
| 新增已存在型別的狀態時擲回 `GameFrameworkException` | 相同型別的狀態已註冊，FSM 內部以 `Type` 作為索引鍵防止重複 | 先以 `HasState<TState>()` 判斷，或僅新增一次 |
| `RemoveState` 移除目前執行中的狀態時擲回 `GameFrameworkException` | 框架為避免目前狀態的參考懸空，禁止移除目前狀態 | 先以 `Start<OtherState>()` 切換後再呼叫 `RemoveState` |
| `RemoveState` 回傳 `false` | 該型別的狀態尚未註冊 | 先確認 `HasState<TState>()` 是否為 `true` |
| 呼叫 `HasState(null)` / `HasState(非 FsmState 型別的值)` 時擲回例外 | 依介面規範，狀態型別必須繼承 `FsmState<T>` | 傳入有效的狀態型別 |

例外來源參考：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L109-L126)

## 背景（選用）

FSM 內部以 `Dictionary<Type, FsmState<T>>` 維護狀態集合，`AddState` / `RemoveState` 會直接操作此字典。為確保執行階段安全性，框架會在移除前驗證目標狀態並非 `CurrentState`。
