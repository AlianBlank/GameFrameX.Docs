# 啟動時出現 "Web manager is invalid." 嚴重日誌怎麼辦

這條 Fatal 日誌出自 `WebProtoBuffComponent.Awake()`：當 `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` 傳回 `null` 時印出，表示 Web ProtoBuff 管理器模組沒有被成功取得（未註冊或實作類型被裁剪）。元件隨即 `return`，後續所有 Web 請求呼叫都會失效。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 啟動即印出 `Web manager is invalid.`，之後呼叫 `Post` 等介面拋出 `NullReferenceException` | `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` 傳回 `null`，管理器實作未註冊到框架入口 | 見下方修復步驟 1 |
| 建置包（實機/裁剪後）才出現該日誌，編輯器正常 | 受控程式碼裁剪把 `WebProtoBuffManager` 實作類別裁掉了 | 見下方修復步驟 2 |
| 手動刪除了物件上的 `GameFrameXWebProtoBuffCroppingHelper` | 該 Helper 透過 `typeof` 參考管理器類型，用於防止連結器裁剪 | 見下方修復步驟 3 |
| 呼叫 `Post<T>` 時提示方法不存在 | 未啟用 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 巨集（該巨集只影響 `Post<T>`，與 Fatal 日誌本身無關） | 見下方修復步驟 4 |

## 修復步驟

日誌的判定程式碼如下，可用於對照排查：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IWebProtoBuffManager);
    base.Awake();
    m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
    if (m_WebProtoBuffManager == null)
    {
        Log.Fatal("Web manager is invalid.");
        return;
    }

    m_WebProtoBuffManager.Timeout = m_Timeout;
}
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L77-L90)

1. **確認管理器實作類別可達**。`WebProtoBuffManager`（位於 `Runtime/Web/WebProtoBuffManager.cs`，命名空間 `GameFrameX.Web.ProtoBuff.Runtime`）是 `IWebProtoBuffManager` 的實作，`GetModule` 相依於 `GameFrameworkEntry` 所在的 GameFrameX 執行階段基礎包完成註冊。確認專案中已正確安裝 GameFrameX 基礎執行階段包，且本包的組件編譯無錯誤（Console 無紅色編譯錯誤）。
2. **降低/關閉受控裁剪**。在 Unity 的 `Player Settings → Managed Stripping Level` 中調低裁剪等級，或為本包組件設定保留規則，確保 `WebProtoBuffManager` 不被裁掉。
3. **保留防裁剪 Helper**。`WebProtoBuffComponent` 透過 `[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]` 強制相依該 Helper，它持有對本包全部關鍵類型的參考：

```csharp
[Preserve]
public class GameFrameXWebProtoBuffCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(WebProtoBuffComponent);
        _ = typeof(IWebProtoBuffManager);
        _ = typeof(WebProtoBuffManager);
    }
}
```

Source: [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs#L6-L16)

   不要手動刪除場景中物件上的 `GameFrameXWebProtoBuffCroppingHelper` 元件。
4. **按需啟用網路巨集**。如需使用 Protocol Buffer 請求，在 `Scripting Define Symbols` 中加入 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`，否則 `Post<T>` 不會被編譯進元件（見 `WebProtoBuffComponent.cs` 第 92 行的 `#if` 條件）。

## 驗證

- 重新進入 Play 模式（或重新建置），Console 中不再出現 `Web manager is invalid.` Fatal 日誌。
- 元件 Inspector 中修改 `Timeout`（預設 `5f` 秒）能正常生效——它直接讀寫 `m_WebProtoBuffManager.Timeout`。
- 啟用巨集後，`WebProtoBuffComponent.Post<T>(url, message)` 可被正常呼叫。
