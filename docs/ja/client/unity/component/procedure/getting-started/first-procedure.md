# 最初に利用可能なフロー

このページの步骤に従って、Unityプロジェクトに`ProcedureComponent`をアタッチし、2つの`ProcedureBase`サブクラスを記述してエントリーフローを起動することで、ゲーム起動後に即座に動作させることができます。

## 前提条件

- `com.gameframex.unity.procedure`パッケージ、およびその依存パッケージである`com.gameframex.unity.fsm`、`com.gameframex.unity.runtime`がインストールされていること。
- プロジェクトのエントリシーンの`GameFramework`オブジェクトに`ProcedureComponent`コンポーネントがアタッチされていること(`[AddComponentMenu("GameFrameX/Procedure")]`)。
- C#クラスの継承とUnity Inspectorの基本的な使い方を理解していること。

## 操作步骤

1. **新しいフロークラスを作成**。`LaunchProcedure`(起動フロー、通常は基本システムの初期化を担当)を作成し、`ProcedureBase`から継承します:

```csharp
using GameFrameX.Procedure.Runtime;
using GameFrameX.Runtime;

public sealed class LaunchProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // ここで基本モジュールの初期化を行う。例：設定、ログ、リソースなど
    }
}
```

`ProcedureBase`は`FsmState<IProcedureManager>`を継承しており、`OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy`の6つのライフサイクルフックを内蔵しています。必要に応じてオーバーライドしてください。

Source: [ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

2. **2番目のフローを作成**(例:`MainProcedure`)。メインメニューやメインロジックへの遷移に使用します:

```csharp
using GameFrameX.Procedure.Runtime;

public sealed class MainProcedure : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // シーン起動、UI読み込み、メインループ開始
        ChangeState<MainProcedure>(procedureOwner); // カスタム遷移の例
    }
}
```

3. **Inspectorでフローリストを設定**。`ProcedureComponent`がアタッチされているオブジェクトを選択し、以下のフィールドを入力します:

| フィールド | 役割 | 例 |
|------|------|------|
| `Available Procedure Type Names` | フレームワークが作成して状態マシンに追加するすべてのフロー型の完全名(名前空間 + クラス名) | `MyGame.LaunchProcedure`、`MyGame.MainProcedure` |
| `Entrance Procedure Type Name` | 起動エントリーフローの型の完全名。前ステップのリストに含まれている必要があります | `MyGame.LaunchProcedure` |

型名はリフレクションで検索されるため、クラスは`Utility.Assembly.GetType`で見つかる必要があり、パラメータなしのコンストラクタを持つ必要があります。コンポーネントは`Start`内で自動的に`Automat.CreateInstance`して初期化を行います。

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L129-L168)

4. **Play Modeに入る**。フレームワークは`Start`内で以下の処理を完了します:

   - リフレクションですべてのフローインスタンスを作成。
   - `m_ProcedureManager.Initialize(IFsmManager, procedures)`を呼び出してFSMに登録。
   - フレーム末まで待機した後、`m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType())`を呼び出してエントリーフローを起動。

   エントリーフローの`OnEnter`がトリガーされると、最初の利用可能なフローが動作開始しています。

## よくあるバリエーション

- **手動で起動を引き継ぐ(StartupRunnerモード)**:`ProcedureComponent`の`Use Startup Runner = true`をチェックすると、コンポーネントの`Awake`では`IProcedureManager`の登録のみが行われ、自動的に`Initialize/StartProcedure`は実行されません。`ApplicationStartupEntry`が`StartupRunner.Run`を通じて指定された場所で初期化と起動を引き継ぎ、重複した`Initialize`による"Already exist FSM"エラーを回避できます。

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L127)

- **コンポーネントをアタッチせず、純粋なコードで初期化**:`IFsmManager`と`IProcedureManager`を取得した後、自分でフロー配列を構築し`Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures)`を呼び出し、その後`StartProcedure<T>()`を呼び出します。

  Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L156)

- **実行時のフロー切り替え**:あるフローの`OnEnter` / `OnUpdate`内で`procedureOwner.Start<TargetProcedure>()`を呼び出すことで、別のフローに切り替えることができます。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| ログ `Entrance procedure is invalid.` | `Entrance Procedure Type Name`が`Available Procedure Type Names`リストに存在しない | エントリ型名がリストのいずれかの項目と完全に一致するようにする |
| ログ `Can not find procedure type 'X'.` | 型の完全名のスペルが間違っている、またはその型がランタイムでロード可能なアセンブリにない | 名前空間 + クラス名を使用し、アセンブリがビルドされていることを確認する |
| ログ `Can not create procedure instance 'X'.` | フロークラスにアクセス可能なパラメータなしのコンストラクタがない | `Process`サブクラスに明示的にパラメータなしのコンストラクタを追加する(明示的に書かなくても自動生成されますが、パラメータ付きコンストラクタを定義すると上書きされます) |
| `You must initialize procedure first.`がスローされる | `Initialize`を呼び出す前に`CurrentProcedure`、`StartProcedure`などにアクセスした | 先に`Initialize`を呼んでから`StartProcedure`を呼ぶ。または`ProcedureComponent`の`Start`が実行されたことを確認する |
| `Procedures is invalid.`がスローされる | `Initialize`に渡したフロー配列の長さが0 | 少なくとも1つのフローインスタンスを传递する |
| `Initialize`の重複で`Already exist FSM`が報告される | コンポーネントによる自動初期化とStartupRunnerを同時に使用しているか、手動で`Initialize`を複数回呼び出している | 二者択一:`Use Startup Runner`をオフにするか、コンポーネントにはインターフェース登録のみを行わせ、外部で統一的に初期化する |

## 背景(オプション)

`ProcedureManager`は本質的に`GameFrameworkModule`であり、内部で`IFsmManager.CreateFsm(this, procedures)`を通じてすべてのフローを有限状態机的状態として登録します。`ProcedureBase`は`FsmState<IProcedureManager>`を派生しているため、フロー間の切り替えや破棄はすべてFSMの機能を直接再利用します。`ProcedureComponent`は単にUnityライフサイクル内で型名をリフレクションでインスタンス化し、`ProcedureManager`に渡す役割を担います。

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)
