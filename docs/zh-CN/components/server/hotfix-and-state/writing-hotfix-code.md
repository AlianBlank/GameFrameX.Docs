# 编写可热更新的业务代码（Hotfix 层规范）

本页面说明如何在 `GameFrameX.Hotfix` 程序集里编写可被热替换的业务代码，并遵循框架的桥接与分层约束。

## 前置条件

- 已创建 `GameFrameX.Hotfix` 程序集项目（参见仓库中 [GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj)）。
- 引用 `GameFrameX.StartUp`、`GameFrameX.SuperSocket.*`、`GameFrameX.Apps.Common.Session` 等依赖。
- 编译时启用了 `GameFrameX.Architecture.Analyzers` 规则集（`GFX0004` 等）。

## Hotfix 层的核心约定

1. **桥接类必须实现 `IHotfixBridge`**：所有需要在状态层（Apps）和逻辑层（Hotfix）之间桥接的入口类必须实现该接口，且类必须定义在 `GameFrameX.Hotfix` 程序集内。`HotfixBridgeAssemblyAnalyzer` 会以 `GFX0004` 错误强制此规则。
2. **入口类使用 `partial`**：因为启动生命周期分散在多个文件（`AppStartUpHotfixGameByEntry.cs`、`AppStartUpHotfixGameByMain.cs` 等），类必须保持 `partial`，否则启动阶段会编译失败。
3. **保留 `HotfixHandler` 标记类型**：`HotfixHandler` 是一个空的静态类，仅用于被反射定位。删除会导致热更时找不到入口。

## 操作步骤

### 步骤 1：在 Hotfix 程序集里声明启动桥接类

新建或修改 `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`，声明 `partial` 类并实现 `IHotfixBridge`：

```csharp
using GameFrameX.StartUp;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge
{
    public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
    {
        if (reload)
        {
            ActorManager.ClearAgent();
            return true;
        }

        Init(setting.ServerType, setting);
        await RunServer();
        // 启动定时器
        await QuartzTimer.Start();
        GlobalTimer.Start();
        await ComponentRegister.ActiveGlobalComponents();
        return true;
    }

    public async Task Stop(string message = "")
    {
        await StopAsync(message);
    }
}
```

### 步骤 2：在另一个文件中扩展消息分发与生命周期

由于类被声明为 `partial`，可以在另一个文件中覆写 `StartAsync`、`PackageHandler`、`OnConnected`、`OnDisconnected`、`StopAsync` 等网络与生命周期钩子：

```csharp
using GameFrameX.Apps.Common.Session;
using GameFrameX.SuperSocket.Connection;
using GameFrameX.SuperSocket.Server.Abstractions.Session;
using GameFrameX.SuperSocket.WebSocket.Server;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame
{
    public override async Task StartAsync()
    {
        await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
            new DefaultMessageCompressHandler(),
            new DefaultMessageDecompressHandler(),
            HotfixManager.GetListHttpHandler(),
            HotfixManager.GetHttpHandler);
    }

    protected override async ValueTask PackageHandler(IAppSession appSession, IMessage message)
    {
        if (message is NetworkMessagePackage messagePackage)
        {
            var netWorkChannel = SessionManager.GetChannel(appSession.SessionID);
            if (netWorkChannel.IsNull()) return;

            var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
            if (handler == null)
            {
                LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
                return;
            }

            try
            {
                await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
            }
            catch (Exception exception)
            {
                LogHelper.Fatal(exception);
            }
        }
    }

    public override async Task StopAsync(string message = "")
    {
        await base.StopAsync(message);
        await SessionManager.RemoveAll();
        await QuartzTimer.Stop();
        await ActorManager.AllFinish();
        await GlobalTimer.Stop();
        await ActorManager.RemoveAll();
    }
}
```

Source: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L43-L163)

### 步骤 3：不要删除 `HotfixHandler` 标记类型

热更框架依赖反射定位 `HotfixHandler` 类作为入口标记，保留即可，无需添加任何成员：

```csharp
namespace GameFrameX.Hotfix;

/// <summary>
/// 该类文档用于处理热更新标记。不能删除。用于反射调用
/// </summary>
public static class HotfixHandler
{
}
```

Source: [HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8)

### 步骤 4：保证 IHotfixBridge 实现位于 Hotfix 程序集

如果你新增了一个桥接实现（例如 `MyHotfixBridge : IHotfixBridge`），必须把文件放在 `GameFrameX.Hotfix` 项目下；否则 `HotfixBridgeAssemblyAnalyzer` 会报 `GFX0004`：

```text
Type 'MyHotfixBridge' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not '<YourAssembly>'
```

## 常见变体

- **按网关启动**：在 `AppStartUpHotfixGameByGateWay.cs` 里提供网关侧覆写。
- **按心跳启动**：在 `AppStartUpHotfixGameByHeart.cs` 里提供心跳侧覆写。
- **重载场景（`reload == true`）**：在 `OnLoadSuccess` 中只调用 `ActorManager.ClearAgent()` 并返回，不要重新初始化网络与全局组件。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 编译报 `Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix'` | `IHotfixBridge` 实现类放错了程序集 | 把该类文件移到 `GameFrameX.Hotfix` 项目 |
| 启动报“找不到热更入口” | 误删了 `HotfixHandler` 静态类 | 重新声明 `public static class HotfixHandler {}` |
| `partial` 报错，找不到 `AppStartUpHotfixGame` 定义 | 在新文件里忘写 `partial` 修饰符 | 给所有分片类加上 `internal partial class AppStartUpHotfixGame` |
| 热更后状态未清理 | `OnLoadSuccess(reload=true)` 分支里没调用 `ActorManager.ClearAgent()` | 按模板在 reload 分支先清空 Agent |

## 背景（可选）

`IHotfixBridge` 是状态层调用逻辑层的桥接契约，约束其实现在 `GameFrameX.Hotfix` 程序集内，从而保证热更新时整段桥接逻辑可以被整体替换；架构分析器 `HotfixBridgeAssemblyAnalyzer` 以 `GFX0004` 在编译期强制此规则。
