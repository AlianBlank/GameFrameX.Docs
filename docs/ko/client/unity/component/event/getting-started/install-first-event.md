# 첫 번째 이벤트 설치 및 실행

이 페이지는 처음부터 끝까지의 과정을 안내합니다: `com.gameframex.unity.event` 패키지 설치 → `EventComponent` 컴포넌트 추가 → 이벤트 인자 클래스 정의 → 구독 → 이벤트 발생 → Console에서 콜백 출력 확인. 그대로 따라 작성하기만 하면 정상 동작합니다.

## 사전 조건

- Unity 2019.4 이상(README 배지 설명 참조).
- 프로젝트에 GameFrameX 런타임 기반 패키지가 이미 포함되어 있어야 합니다(`EventComponent`는 `GameFrameworkComponent`를 상속하며 `GameFrameX.Runtime` 네임스페이스를 참조합니다).
- 이 패키지 자체에는 다른 의존성이 없습니다.

## 작업 단계

### 1. 패키지 설치

아래 방식 중 하나를 선택해 Unity 프로젝트의 `Packages/manifest.json`을 수정합니다:

**방식 A: Scoped Registry(권장)**

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.event": "1.1.1"
  }
}
```

`scopes`는 이 레지스트리를 통해 어떤 패키지가 해석되는지 제어하며, `com.gameframex`로 시작하는 패키지만 이 레지스트리에서 가져옵니다.

**방식 B: Git URL 직접 의존**

```json
{
   "com.gameframex.unity.event": "https://github.com/gameframex/com.gameframex.unity.event.git"
}
```

Unity의 `Packages Manager`에서 `Git URL` 방식으로 주소 `https://github.com/gameframex/com.gameframex.unity.event.git`를 추가하거나, 저장소를 직접 다운로드해 프로젝트의 `Packages` 디렉터리에 넣으면 자동으로 인식됩니다.

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L40-L69)

### 2. EventComponent 컴포넌트 추가

`EventComponent`는 이벤트 시스템의 Unity 진입점으로, 컴포넌트 메뉴 **Component → GameFrameX → Event**를 통해 추가합니다(메뉴 경로는 `[AddComponentMenu("GameFrameX/Event")]`로 정의됨). `[GameFrameXAutoComponent(-7000)]` 특성을 가지고 있어 완전한 GameFrameX 시작 흐름에서 자동으로 생성되며, 임의의 상주 GameObject에 수동으로 부착해도 동일하게 사용할 수 있습니다. 컴포넌트는 `Awake`에서 `GameFrameworkEntry.GetModule<IEventManager>()`를 통해 관리자 인스턴스를 가져오며, 실패 시 `Log.Fatal("Event manager is invalid.")`를 출력하고 동작을 멈춥니다.

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L77)

### 3. 이벤트 인자 클래스 정의

각 이벤트는 `GameEventArgs`를 상속하는 클래스 하나로 표현되며, 문자열 `Id`로 이벤트 타입을 식별합니다:

```csharp
public class LevelUpEventArgs : GameEventArgs
{
    public override string Id => "level_up";
    public int Level { get; private set; }

    public static LevelUpEventArgs Create(int level)
    {
        var args = ReferencePool.Acquire<LevelUpEventArgs>();
        args.Level = level;
        return args;
    }

    public override void Clear()
    {
        base.Clear();
        Level = 0;
    }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L75-L94)

`GameEventArgs`는 `GameFrameX.Event.Runtime` 네임스페이스의 추상 기본 클래스로(`BaseEventArgs` 상속), 커스텀 이벤트는 반드시 이 클래스에서 파생되어야 합니다:
[GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L30-L40)

### 4. 이벤트 구독 및 발생

새 테스트 스크립트를 만들어 씬에 부착합니다. 콜백 시그니처는 `void(object sender, GameEventArgs e)`로 고정되어 있으며, 곧 `EventHandler<GameEventArgs>`입니다:

```csharp
using GameFrameX.Event.Runtime;
using UnityEngine;

public class FirstEventDemo : MonoBehaviour
{
    private EventComponent m_EventComponent;

    private void Start()
    {
        m_EventComponent = GetComponent<EventComponent>();
        if (m_EventComponent == null)
        {
            m_EventComponent = FindObjectOfType<EventComponent>();
        }

        // 구독: 존재하지 않으면 자동으로 구독되며, 중복 호출도 안전합니다
        m_EventComponent.CheckSubscribe("level_up", OnLevelUp);

        // 이벤트 발생: 지연 모드, 다음 프레임에 메인 스레드에서 콜백됩니다
        m_EventComponent.Fire(this, LevelUpEventArgs.Create(5));
    }

    private void OnLevelUp(object sender, GameEventArgs e)
    {
        var args = (LevelUpEventArgs)e;
        Debug.Log($"升级到 {args.Level} 级");
    }

    private void OnDestroy()
    {
        // 존재할 때 안전하게 구독 해제, handler가 존재하지 않으면 아무 작업도 수행하지 않습니다
        m_EventComponent.CheckUnsubscribe("level_up", OnLevelUp);
    }
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L95-L131) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L96-L128)

### 5. 검증

씬을 실행하면 Console에 `升级到 5 级`가 출력되어야 합니다. `Fire`는 지연 분배 방식이라는 점에 유의하세요 — 이벤트는 발생 후 **다음 프레임**에 콜백되므로, 해당 프레임에서 로그가 보이지 않으면 한 프레임 기다린 뒤 판단하세요.

## 일반적인 변형

**즉시 분배 `FireNow`**: 이벤트가 즉시 동기적으로 분배되지만 **스레드 안전하지 않으므로** 메인 스레드에서만 호출해야 합니다.

```csharp
m_EventComponent.FireNow(this, LevelUpEventArgs.Create(5));
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

**커스텀 인자 없이 간편하게 발생시키기**: 데이터를 담을 필요가 없을 때는 문자열 이벤트 ID를 직접 사용하면, 내부적으로 `EmptyEventArgs`가 생성됩니다:

```csharp
m_EventComponent.Fire(this, "level_up");
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

**기본 핸들러 폴백**: 구독되지 않은 이벤트에 대한 폴백 콜백을 설정하며, "이벤트를 발생시켰는데 수신자가 없는" 문제를 추적할 때 자주 사용됩니다:

```csharp
m_EventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L133-L140) · [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L142-L151)

**통계 정보**: `Count(id)`로 개별 이벤트의 핸들러 수를 조회하고, `EventHandlerCount` / `EventCount`로 전체 수량을 조회합니다.
출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) · [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L87)

## 자주 발생하는 오류

| 현상 | 원인 | 회피 방법 |
|------|------|----------|
| Console에 `Event manager is invalid.`(Fatal) 출력 | 컴포넌트가 `GameFrameworkEntry.GetModule<IEventManager>()`를 통해 관리자를 가져오지 못함. 일반적으로 GameFrameX 런타임 기반 패키지가 준비되지 않은 경우 | 먼저 GameFrameX 런타임 패키지가 설치되고 정상적으로 초기화되었는지 확인한 뒤 `EventComponent`를 부착 |
| `Fire` 호출 후 해당 프레임에 콜백이 수신되지 않음 | `Fire`는 지연 분배이며, 이벤트는 발생 후 다음 프레임에 메인 스레드에서 콜백됨 | 예상된 동작임; 즉시 동기 콜백이 필요하면 `FireNow`를 사용 |
| 서브 스레드에서 이벤트 발생 후 동작이 비정상 | 메인 스레드가 아닌 곳에서 `FireNow`를 호출함 | 서브 스레드에서는 `Fire`(스레드 안전)만 사용 가능 |
| 이벤트 인자에서 오염된 데이터를 가져옴 | 커스텀 이벤트 인자에서 `Clear()`를 재정의해 필드를 초기화하는 것을 잊어, 풀링된 인스턴스를 재사용할 때 이전 값이 남음 | 3단계 예시를 참고하여 `Clear()`에서 필드를 하나씩 초기화 |
| 동일한 콜백이 중복 구독됨 | 여러 곳에서 `Subscribe`를 호출하면서 존재 여부 검사를 하지 않음 | `CheckSubscribe`(존재하지 않을 때만 구독)/ `CheckUnsubscribe`(존재할 때만 해제)를 사용하거나, 먼저 `Check`로 확인한 후 작업 |
