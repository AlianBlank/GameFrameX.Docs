# 이벤트 이름이 비어 있어 차단된 경우 어떻게 해야 하나요 (GameFrameworkGuard 검증)

`GameAnalyticsComponent`의 `Event`, `StartTimer` 등 인터페이스를 호출할 때 전달한 `eventName`이 `null` 또는 빈 문자열이기만 하면, 메서드 첫 줄의 `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))`가 검증 예외를 발생시킵니다. 이는 통계 SDK 오류가 아니라 입력 매개변수 보호입니다—— 비어 있지 않은 이벤트 이름을 전달하면 해결됩니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `Event` / `StartTimer` 등 메서드 호출 시 `GameFrameworkGuard.NotNullOrEmpty` 검증 예외가 발생하고 스택이 `GameAnalyticsComponent`를 가리킴 | `eventName`에 `null` 또는 빈 문자열이 전달됨 | 호출 체인으로 이동하여 비어 있지 않은 이벤트 이름을 전달하도록 수정, 아래 "수정 단계" 참조 |
| 이벤트 이름이 변수, 딕셔너리 또는 문자열 연결에서 가져와 간헐적으로 비어 있음 | 변수에 값이 할당되지 않음, 딕셔너리 key에서 값을 가져오지 못함, 연결 결과가 빈 문자열 | 리포트 전에 빈 값 검사 후 로그를 남겨 출처 파악 |
| 호출 시 예외는 발생하지 않지만 로그에 `GameAnalyticsManager is not init.`가 나타나고 데이터도 리포트되지 않음 | 이 페이지와 다른 문제: 컴포넌트 또는 특정 Manager가 초기화되지 않아 메서드 내부에서 해당 Manager를 건너뜀 | 먼저 초기화 인터페이스를 호출하여 `Init`을 완료한 뒤 이벤트를 리포트 |

## 수정 단계

### 1. 어떤 메서드에서 예외가 발생했는지 확인

`GameAnalyticsComponent`에서 `eventName`을 받는 모든 공개 메서드는 첫 줄에서 동일한 검증을 수행하므로, 먼저 예외 스택에서 진입점을 확인하세요:

| 메서드 | 시그니처 | 검증 위치 |
|------|------|-----------|
| 타이머 시작 | `StartTimer(string eventName)` | [L162](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L162) |
| 타이머 일시정지 | `PauseTimer(string eventName)` | [L187](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L187) |
| 타이머 재개 | `ResumeTimer(string eventName)` | [L205](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L205) |
| 타이머 종료 | `StopTimer(string eventName)` | [L223](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L223) |
| 이벤트 리포트 | `Event(string eventName)` | [L248](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L248) |
| 값을 포함한 이벤트 리포트 | `Event(string eventName, float eventValue)` | [L274](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L274) |
| 커스텀 필드를 포함한 이벤트 리포트 | `Event(string eventName, Dictionary<string, object> customF)` | [L300](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L300) |
| 값과 커스텀 필드를 포함한 이벤트 리포트 | `Event(string eventName, float eventValue, Dictionary<string, object> customF)` | [L334](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L334) |

검증은 어떤 초기화 검사보다도 먼저 실행됩니다—— 컴포넌트가 이미 `Init`되었더라도 빈 이벤트 이름은 마찬가지로 차단됩니다:

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

소스: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

### 2. 호출 지점에서 전달되는 이벤트 이름 확인

잘못 작성한 흔한 사례와 수정 예시:

```csharp
// 오류: 이벤트 이름이 딕셔너리/설정에서 오며, 값을 가져오지 못하면 null이 됨
string eventName = config.ContainsKey("level_complete") ? config["level_complete"] : null;
gameAnalyticsComponent.Event(eventName);

// 올바름: 비어 있지 않은 상수 또는 값이 할당된 변수를 전달하도록 보장
gameAnalyticsComponent.Event("level_complete");
```

이벤트 이름이 반드시 외부 데이터(설정 테이블, 서버 전달, 열거형 변환)에서 와야 하는 경우, 리포트 전에 빈 값 검사를 하고 로그를 남기면 데이터 원천의 문제를 발견하기 쉽습니다:

```csharp
if (string.IsNullOrEmpty(eventName))
{
    Debug.LogWarning($"[GameAnalytics] eventName 为空，来源：{source}");
    return;
}

gameAnalyticsComponent.Event(eventName);
```

### 3. 상수를 사용해 이벤트 이름 중앙 관리

모든 이벤트 이름을 상수 클래스로 통합하여, 직접 작성한 문자열의 오타나 빈 값 잘못 전달을 방지하세요:

```csharp
public static class AnalyticsEvents
{
    public const string LevelComplete = "level_complete";
    public const string AdWatched = "ad_watched";
}

gameAnalyticsComponent.Event(AnalyticsEvents.LevelComplete);
```

## 검증

- 예외가 발생했던 원래 호출 지점을 다시 트리거해도 Console에 더 이상 `GameFrameworkGuard.NotNullOrEmpty` 관련 예외가 나타나지 않는지 확인합니다.
- `GameAnalyticsManager is not init.` 경고가 함께 발생하지 않는지 확인합니다. 만약 나타난다면 이벤트 이름은 검증을 통과했지만 특정 Manager가 아직 초기화되지 않은 것이므로, 먼저 초기화를 완료한 후 리포트해야 합니다.
- 통계 플랫폼 백오피스에서 이벤트 데이터가 수신되었는지 확인합니다.

## 배경

`GameFrameworkGuard.NotNullOrEmpty`는 GameFrameX 기반 라이브러리의 가드 메서드입니다(구현은 이 리포지토리에 없으며, 이 리포지토리의 소스 코드에서 구체적인 예외 타입 세부 정보를 찾을 수 없음). 메서드 진입 지점에서 잘못된 매개변수를 신속하게 차단하는 데 사용됩니다. `GameAnalyticsComponent`는 이를 모든 공개 메서드의 첫 줄에 배치하여, 빈 이벤트 이름이 디스패치 루프에 진입하기 전에 차단되도록 하고 잘못된 데이터가 각 통계 채널로 유입되는 것을 방지합니다.
