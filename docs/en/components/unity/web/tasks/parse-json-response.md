# How to Parse JSON Responses

In GameFrameX.Web, the core of parsing a JSON response is calling the extension method `ToHttpJsonResultData<T>()` on the response string: it deserializes the server's unified structure (`code`/`message`/`data`) into `HttpJsonResultData<T>` and automatically sets `IsSuccess` based on `code`. The framework uses LitJSON (`GameFrameX.LitJSON.Runtime.JsonMapper`) under the hood to perform the deserialization.

## Prerequisites

- The project has imported the `GameFrameX.Web` and `GameFrameX.LitJSON` runtime modules.
- The server returns a unified JSON structure with the lowercase `code`, `message`, and `data` fields:

```json
{
  "code": 0,
  "message": "ok",
  "data": "{\"id\":1,\"name\":\"Player\"}"
}
```

Here `code == 0` indicates success, and `data` is a nested JSON string (which will be deserialized a second time into `T`).

## Steps

1. Define the business data model `T`: it must be a `class` with a parameterless constructor (the extension method signature constrains it as `where T : class, new()`). When field names don't match the JSON, annotate them with `[JsonProperty("...")]`.

```csharp
using GameFrameX.LitJSON.Runtime;

public sealed class PlayerInfo
{
    [JsonProperty("id")]
    public int Id { get; set; }

    [JsonProperty("name")]
    public string Name { get; set; }
}
```

2. Once you have the response string, call the extension method to get the result object:

```csharp
using GameFrameX.Web.Runtime;

HttpJsonResultData<PlayerInfo> result = responseText.ToHttpJsonResultData<PlayerInfo>();
```

3. Handle the result based on `IsSuccess` / `Code`:

```csharp
if (result.IsSuccess)
{
    PlayerInfo player = result.Data;
    Debug.Log($"玩家：{player.Id} {player.Name}");
}
else
{
    // When Code is non-zero it is a server-side error code; when Code is 0 and IsSuccess is false, it means deserialization threw an exception
    Log.Error($"请求失败，Code={result.Code}");
}
```

The complete logic of `ToHttpJsonResultData<T>` (parse the shell first, then parse `data` a second time) is as follows:

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // Deserialize the JSON string into an HttpJsonResult object
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // Check whether the response code indicates success
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // Return the default failure result
        }

        resultData.IsSuccess = true; // Set the success flag
        // Deserialize the data part; if the data is empty, return a default instance of type T
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // Catch and output the exception message
        Log.Error(e);
    }

    return resultData; // Return the result data
}
```

## Common Variants

- **Only care about the shell structure, no strongly-typed Data needed**: use `JsonMapper.ToObject<HttpJsonResult>(json)` directly to get the `Code` / `Message` / `Data` fields (`Data` is the raw string in this case).

```csharp
var shell = JsonMapper.ToObject<HttpJsonResult>(responseText);
Debug.Log($"code={shell.Code}, message={shell.Message}");
```

Source: [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L9-L33)

- **Getting the string response at the request stage**: `WebManager` internally attaches `TaskCompletionSource<WebStringResult>` / `TaskCompletionSource<WebBufferResult>` via `WebJsonData` (a private request description class), corresponding to string results and byte array results respectively; the string result can be fed directly into `ToHttpJsonResultData<T>`. For how to send a Web request, see *How to Make an HTTP Request*.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `IsSuccess == false` and `Code != 0` | The server returned a non-zero response code; `Data` remains `null` | Handle the business error based on `Code`; the meaning of `Code` values is defined by server-side convention |
| `IsSuccess == false` and `Code == 0` | Deserialization threw an exception, which was swallowed by `catch (Exception e)` and logged via `Log.Error(e)` | Check the console error log; verify the JSON format and field name mapping |
| Compilation error: missing `new()` constraint | `T` is a struct or has no parameterless constructor | Change the model to a `class` with a parameterless constructor |
| All fields in `Data` are default values | Field names don't match the JSON keys and are not annotated with `[JsonProperty]` | Map explicitly with `[JsonProperty("original key name")]` |
| `Data` is an all-default instance but `IsSuccess == true` | The server returned an empty string for `data`, in which case `new T()` is returned | Have the server ensure a valid `data` is included on success, or check for empty on the client side as needed |
| No fields are parsed at all | The shell field names are not lowercase `code`/`message`/`data` | Agree with the server on a unified shell structure; see [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L14-L27) |

## Verification

- Construct the string `{"code":0,"message":"ok","data":"{\"id\":1,\"name\":\"a\"}"}` and call `ToHttpJsonResultData<PlayerInfo>()`; you should get `IsSuccess == true` and `Data.Id == 1`.
- Change `code` to a non-zero value (e.g., `1001`); you should get `IsSuccess == false`, `Code == 1001`, and `Data == null`.
- Change the string to invalid JSON; you should get `IsSuccess == false`, `Code == 0`, and see exception output in the log.

## Background

`HttpJsonResultData<T>` is merely a thin wrapper over "unified shell + business data": `IsSuccess` (defaults to `false`), `Code` (int, 0 means success), and `Data` (`T`, `null` on failure). Inside the extension method, the response is first deserialized into `HttpJsonResult` to check `code`, then on success a second deserialization is performed on `data`. Exceptions are caught throughout and never rethrown, so callers only need to care about the two flags `IsSuccess` and `Code`.
