# JSON 응답 파싱 방법

GameFrameX.Web에서 JSON 응답 파싱의 핵심은 응답 문자열에 확장 메서드 `ToHttpJsonResultData<T>()`를 호출하는 것입니다: 이 메서드는 서버의 통일된 구조(`code`/`message`/`data`)를 `HttpJsonResultData<T>`로 역직렬화하고, `code`에 따라 `IsSuccess`를 자동으로 설정합니다. 프레임워크 내부에서는 LitJSON(`GameFrameX.LitJSON.Runtime.JsonMapper`)을 사용해 역직렬화를 수행합니다.

## 사전 조건

- 프로젝트에 `GameFrameX.Web`과 `GameFrameX.LitJSON` 런타임 모듈이 이미 포함되어 있어야 합니다.
- 서버가 통일된 JSON 구조를 반환하며, 필드는 소문자 `code`, `message`, `data`입니다:

```json
{
  "code": 0,
  "message": "ok",
  "data": "{\"id\":1,\"name\":\"Player\"}"
}
```

여기서 `code == 0`은 성공을 의미하며, `data`는 중첩된 JSON 문자열입니다(`T`로 다시 한번 역직렬화됨).

## 작업 단계

1. 비즈니스 데이터 모델 `T`를 정의합니다: 반드시 `class`여야 하며 매개변수 없는 생성자를 포함해야 합니다(확장 메서드 시그니처의 제약이 `where T : class, new()`이기 때문). 필드 이름이 JSON과 일치하지 않을 때는 `[JsonProperty("...")]`로 표시합니다.

```csharp
using GameFrameX.LitJSON.Runtime;

public sealed class PlayerInfo
{
    [JsonProperty("id")]
    public int Id { get; set; }

    [JsonProperty("name")]
    public string Name { get; set; }
}
```

2. 응답 문자열을 받은 후, 확장 메서드를 호출해 결과 객체를 얻습니다:

```csharp
using GameFrameX.Web.Runtime;

HttpJsonResultData<PlayerInfo> result = responseText.ToHttpJsonResultData<PlayerInfo>();
```

3. `IsSuccess` / `Code`에 따라 결과를 처리합니다:

```csharp
if (result.IsSuccess)
{
    PlayerInfo player = result.Data;
    Debug.Log($"玩家：{player.Id} {player.Name}");
}
else
{
    // Code가 0이 아니면 서버 오류 코드입니다. Code가 0이면서 IsSuccess가 false이면 역직렬화 과정에서 예외가 발생했음을 의미합니다
    Log.Error($"请求失败，Code={result.Code}");
}
```

`ToHttpJsonResultData<T>`의 전체 로직(먼저 셸을 파싱한 뒤 `data`를 다시 파싱)은 다음과 같습니다:

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // JSON 문자열을 HttpJsonResult 객체로 역직렬화
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // 응답 코드가 성공을 나타내는지 확인
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // 기본 실패 결과 반환
        }

        resultData.IsSuccess = true; // 성공 플래그 설정
        // 데이터 부분을 역직렬화하며, 데이터가 비어 있으면 타입 T의 기본 인스턴스를 반환
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // 예외 정보를 캡처하여 출력
        Log.Error(e);
    }

    return resultData; // 결과 데이터 반환
}
```

## 일반적인 변형

- **셸 구조만 필요하고 강타입 Data가 필요 없는 경우**: `JsonMapper.ToObject<HttpJsonResult>(json)`를 직접 사용해 `Code` / `Message` / `Data` 세 필드를 가져옵니다(이때 `Data`는 원본 문자열입니다).

```csharp
var shell = JsonMapper.ToObject<HttpJsonResult>(responseText);
Debug.Log($"code={shell.Code}, message={shell.Message}");
```

출처: [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L9-L33)

- **요청 단계에서 문자열 응답 얻기**: `WebManager`는 내부적으로 `WebJsonData`(비공개 요청 설명 클래스)를 통해 `TaskCompletionSource<WebStringResult>` / `TaskCompletionSource<WebBufferResult>`를 연결하며, 각각 문자열 결과와 바이트 배열 결과에 대응합니다. 문자열 결과는 그대로 `ToHttpJsonResultData<T>`에 전달하면 됩니다. Web 요청을 보내는 방법은 《HTTP 요청 보내는 방법》을 참고하세요.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `IsSuccess == false`이고 `Code != 0`임 | 서버가 0이 아닌 응답 코드를 반환해 `Data`가 `null`로 유지됨 | `Code`에 따라 비즈니스 오류 처리; `Code` 값의 의미는 서버 측 약속에 따름 |
| `IsSuccess == false`이고 `Code == 0`임 | 역직렬화 중 예외가 발생해 `catch (Exception e)`에서 처리되고 `Log.Error(e)`로 출력됨 | 콘솔 오류 로그 확인; JSON 형식과 필드 이름 매핑 점검 |
| 컴파일 오류 발생: `new()` 제약 누락 | `T`가 구조체이거나 매개변수 없는 생성자가 없음 | 모델을 매개변수 없는 생성자를 갖는 `class`로 변경 |
| `Data`의 필드가 모두 기본값임 | 필드 이름이 JSON 키와 일치하지 않고 `[JsonProperty]`가 표시되지 않음 | `[JsonProperty("원본 키 이름")]`으로 명시적 매핑 |
| `Data`가 전부 기본 인스턴스인데 `IsSuccess == true`임 | 서버가 반환한 `data`가 빈 문자열이라 이때 `new T()`가 반환됨 | 서버는 성공 시 유효한 `data`를 포함하도록 하거나, 클라이언트 측에서 필요에 따라 빈 값 확인 |
| 어떤 필드도 파싱되지 않음 | 셸 필드 이름이 소문자 `code`/`message`/`data`가 아님 | 서버와 통일된 셸 구조를 약정할 것, [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L14-L27) 참고 |

## 검증

- `{"code":0,"message":"ok","data":"{\"id\":1,\"name\":\"a\"}"}` 문자열을 만들어 `ToHttpJsonResultData<PlayerInfo>()`를 호출하면 `IsSuccess == true`이고 `Data.Id == 1`이어야 합니다.
- `code`를 0이 아닌 값(예: `1001`)으로 바꾸면 `IsSuccess == false`, `Code == 1001`, `Data == null`이어야 합니다.
- 문자열을 잘못된 JSON으로 바꾸면 `IsSuccess == false`, `Code == 0`이며 로그에서 예외 출력이 보여야 합니다.

## 배경

`HttpJsonResultData<T>`는 「통일된 셸 + 비즈니스 데이터」에 대한 얇은 래퍼일 뿐입니다: `IsSuccess`(기본값 `false`), `Code`(int, 0이 성공), `Data`(`T`, 실패 시 `null`). 확장 메서드 내부에서는 먼저 `HttpJsonResult`로 역직렬화해 `code`를 확인하고, 성공하면 `data`를 한 번 더 역직렬화합니다. 전 과정에서 예외가 캡처되어 밖으로 던져지지 않으므로 호출 측은 `IsSuccess`와 `Code` 두 플래그만 신경 쓰면 됩니다.
