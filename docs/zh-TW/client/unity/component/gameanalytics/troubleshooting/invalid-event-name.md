# 事件名稱為空被攔截（GameFrameworkGuard 驗證）怎麼辦

呼叫 `GameAnalyticsComponent` 的 `Event`、`StartTimer` 等介面時，只要傳入的 `eventName` 為 `null` 或空字串，方法第一行的 `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))` 就會拋出驗證例外。這不是統計 SDK 的錯誤，而是對傳入參數的保護——傳入非空的事件名即可解決。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 呼叫 `Event` / `StartTimer` 等方法時拋出 `GameFrameworkGuard.NotNullOrEmpty` 驗證例外，堆疊指向 `GameAnalyticsComponent` | `eventName` 傳入了 `null` 或空字串 | 進入呼叫鏈改為傳入非空事件名，見下方「修復步驟」 |
| 事件名來自變數、字典或字串串接，偶發為空 | 變數未賦值、字典 key 取不到值、串接結果為空字串 | 上報前先判斷是否為空並輸出日誌定位來源 |
| 呼叫沒有拋出例外，但日誌出現 `GameAnalyticsManager is not init.`，資料也未上報 | 與本頁不同：元件或某個 Manager 未初始化，方法內部直接跳過該 Manager | 先呼叫初始化介面完成 `Init`，再上報事件 |

## 修復步驟

### 1. 確認是哪個方法拋出例外

`GameAnalyticsComponent` 中所有接收 `eventName` 的公開方法都會在第一行執行同一項驗證，先從例外堆疊確認進入點：

驗證發生在任何初始化檢查之前——即使元件已經 `Init`，空事件名同樣會被攔截：

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

### 2. 檢查呼叫點傳入的事件名

常見錯誤寫法與修正：

```csharp
// 錯誤：事件名來自字典/設定，取不到值時為 null
string eventName = config.ContainsKey("level_complete") ? config["level_complete"] : null;
gameAnalyticsComponent.Event(eventName);

// 正確：保證傳入非空常數或已賦值的變數
gameAnalyticsComponent.Event("level_complete");
```

若事件名必須來自外部資料（設定表、伺服器下發、列舉轉換），在上報前先判斷是否為空並記錄日誌，便於發現資料源頭的問題：

```csharp
if (string.IsNullOrEmpty(eventName))
{
    Debug.LogWarning($"[GameAnalytics] eventName 為空，來源：{source}");
    return;
}

gameAnalyticsComponent.Event(eventName);
```

### 3. 用常數集中管理事件名

將所有事件名收斂為常數類別，避免手寫字串拼字錯誤或誤傳空值：

```csharp
public static class AnalyticsEvents
{
    public const string LevelComplete = "level_complete";
    public const string AdWatched = "ad_watched";
}

gameAnalyticsComponent.Event(AnalyticsEvents.LevelComplete);
```

## 驗證

- 重新觸發原來拋出例外的呼叫點，Console 不再出現 `GameFrameworkGuard.NotNullOrEmpty` 相關例外。
- 確認沒有伴隨 `GameAnalyticsManager is not init.` 警告；若出現，表示事件名已通過驗證，但某個 Manager 尚未初始化，需先完成初始化再上報。
- 在統計平台後台確認事件資料已收到。

## 背景

`GameFrameworkGuard.NotNullOrEmpty` 屬於 GameFrameX 基礎庫的守衛方法（實作不在本儲存庫內，本儲存庫原始碼中未找到其具體例外類型細節），用於在方法入口處快速攔截非法參數。`GameAnalyticsComponent` 將它放在每個公開方法的第一行，確保空事件名在進入分發迴圈前就被攔下，避免髒資料流入各統計渠道。
