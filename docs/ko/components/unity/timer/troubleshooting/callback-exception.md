# 콜백에서 예외가 발생하면 어떻게 하나요

타이머 콜백 내부에서 예외(예: null 참조, `InvalidOperationException`)가 발생하면 기본 동작은 예외가 그대로 위로 전파되어 `Update` 내 후속 콜백의 실행이 중단될 수 있습니다. `TimerManager.CatchCallbackExceptions`를 `true`로 설정하면 매니저가 예외를 캡처하여 경고 로그로 낮추며, 나머지 타이머의 계속 실행에는 영향을 주지 않습니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 콜백에서 예외 발생 후 콘솔에 바로 빨간색 오류가 표시되고 후속 타이머 콜백이 실행되지 않음 | `TimerManager.CatchCallbackExceptions`가 기본값 `false`로 유지되어 예외가 그대로 위로 전파됨 | 아래 단계에 따라 `true`로 설정한 후 콜백 자체의 로직을 점검 |
| 콘솔에 `Timer callback error > {예외 메시지}` 경고가 표시됨 | `CatchCallbackExceptions = true`일 때 캡처된 예외가 `Debug.LogWarning`으로 출력됨 | 경고 내용이 곧 콜백 내 실제 예외이므로 이를 바탕으로 콜백 코드 위치를 파악 |
| 테스트에서 예외가 `TargetInvocationException` 형태로 발생함 | 리플렉션으로 `Update`를 호출할 때 캡처되지 않은 예외가 `TargetInvocationException`으로 래핑됨 | 정상적인 전파 동작이며 타이머의 결함이 아님; 캡처를 켜거나 콜백을 수정하면 됨 |

## 수정 단계

### 1. 콜백 예외 캡처 활성화

게임 초기화 단계(콜백 설정 전)에 정적 스위치를 켭니다:

```csharp
TimerManager.CatchCallbackExceptions = true;
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L204-L206)

이 스위치의 기본값은 `false`입니다:

```csharp
/// <summary>
/// 콜백 예외 발생 여부
/// </summary>
public static bool CatchCallbackExceptions = false;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L53-L56)

### 2. 캡처 후 동작 이해

활성화하면 매니저는 콜백을 실행할 때 `try/catch`로 호출을 감싸며, 캡처된 예외는 경고만 출력하고 루프를 중단하지 않습니다:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L190)

참고: 모든 콜백은 락 외부에서 일괄 실행되므로, 단일 콜백의 예외가 삼켜지더라도 **같은 프레임 내 나머지 실행 대기 중인 콜백은 여전히 정상적으로 트리거됩니다**.

### 3. 테스트로 두 모드의 동작 재현

저장소의 유닛 테스트는 스위치의 두 가지 상태에서의 차이를 보여주므로 문제 해결 시 참고 자료로 직접 활용할 수 있습니다:

```csharp
[Test]
public void CatchCallbackExceptions_On_DoesNotThrow_OnException()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = true;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.DoesNotThrow(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Should catch exception silently");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}

[Test]
public void CatchCallbackExceptions_Off_ThrowsToCaller()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = false;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.Throws<TargetInvocationException>(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Exception should propagate through reflection as TargetInvocationException");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}
```

## 검증

- 스위치를 활성화한 후 예외를 발생시키는 콜백(예: `_ => throw new InvalidOperationException("test")`)을 만들고 타이머를 등록합니다;
- `Update`를 구동하여 시간을 진행시키고, 처리되지 않은 예외가 더 이상 발생하지 않으며 콘솔에 `Timer callback error > test` 형태의 노란색 경고만 표시되는지 확인합니다;
- 같은 프레임에 등록된 다른 타이머 콜백도 여전히 예상대로 실행되는지 확인합니다;
- 프로덕션 환경에서는 항상 예외 캡처를 끈 뒤 **콜백 자체를 수정**할 것을 권장하며, 스위치는 장애 격리 및 단일 콜백이 전체 프레임을 마비시키는 것을 방지하는 용도로만 사용합니다.

## 배경

콜백은 락 외부의 `_pendingCallbacks` 큐에서 일괄 실행되며, 이는 비즈니스 콜백이 오랫동안 락을 점유하여 다른 스레드를 차단하는 것을 방지하기 위함입니다. 모든 콜백이 순차적으로 실행되기 때문에 캡처되지 않은 예외 하나가 콜백 전체 배치를 종료시킬 수 있으므로, 프레임워크는 내결함성 대비책으로 이 전역 스위치를 제공합니다.
