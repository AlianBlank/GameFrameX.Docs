# AOT 보존 구성 및 검증 사용

Unity 메뉴 `GameFrameX/HybridCLR Generate AOT Preserve`를 통해 `link.xml`, 참조 요약 코드 및 유형별로 분할된 참조 코드 파일을 한 번에 생성하고, CI에서 검증 실행기를 통해 생성된 파일이 항상 최신 구성과 일치하도록 보장하여 HybridCLR 핫 업데이트 시 AOT 메타데이터가 누락되는 것을 방지합니다.

## 사전 조건

- 프로젝트에 HybridCLR이 설치되어 있어야 합니다(런타임에서 핫 업데이트 AOT 메타데이터에 의존).
- `IAotPreserveSettingsProvider`에 대한 사용자 정의 구현을 제공하거나, 기본 구현에서 구성 진입점을 배치해야 합니다(기본 구현 위치: [IAotPreserveSettingsProvider.cs](/Editor/AotPreserve/IAotPreserveSettingsProvider.cs)).
- Unity 편집기에서 프로젝트가 열려 있어야 하며, `Assets/Generated/` 디렉터리에 대한 쓰기 권한이 있어야 합니다.

## 작업 단계

1. **생성 트리거**. Unity 편집기 상단 메뉴에서 `GameFrameX > HybridCLR Generate AOT Preserve`를 선택하면 `AotPreserveGenerator.GenerateAndWrite()`가 호출되고 로그가 콘솔에 출력됩니다.

   메뉴 진입점 구현은 [AotPreserveMenu.cs#L20-L25](/Editor/AotPreserve/AotPreserveMenu.cs#L20-L25) 참조:

   ```csharp
   [MenuItem(AotPreserveConstants.MenuPath)]
   public static void Generate()
   {
       AotPreserveGenerator.GenerateAndWrite();
       Debug.Log("Hotfix AOT preserve files generated under " + AotPreserveConstants.GeneratedDirectory);
   }
   ```

2. **생성 경로 확인**. 생성 루트 디렉터리의 기본값은 `Assets/Generated/AotPreserve`이며, 핵심 산출물의 경로는 상수로 통합 관리됩니다. [AotPreserveConstants.cs#L17-L65](/Editor/AotPreserve/AotPreserveConstants.cs#L17-L65) 참조:

   | 산출물 | 경로 상수 | 실제 경로 |
   |------|----------|----------|
   | `link.xml`(관리 코드 stripping 보존) | `LinkXmlPath` | `Assets/Generated/AotPreserve/link.xml` |
   | 참조 요약 코드 | `ReferencesPath` | `Assets/Generated/AotPreserveReferences.cs` |
   | 유형별 분할 참조 파일 이름 접두사 | `ReferenceTypeFilePrefix` | `AotPreserveReference_<TypeName>.cs` |
   | 생성 코드가 속한 asmdef | `GeneratedAsmdefPath` | `Assets/Generated/AotPreserve.Generated.asmdef` |
   | 생성 보고 Markdown | `ReportPath` | `Assets/Generated/AotPreserve/aot_preserve_report.md` |

3. **CI에서 검증 호출**. CI 또는 유닛 테스트는 `AotPreserveValidationRunner.ValidateGeneratedFiles()`를 직접 호출할 수 있으며, 파일이 누락되었거나 만료된 경우 `InvalidOperationException`이 발생합니다. 예외 메시지는 모든 오류를 집계하며, [AotPreserveValidationRunner.cs#L20-L27](/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27) 참조:

   ```csharp
   public static void ValidateGeneratedFiles()
   {
       var errors = AotPreserveGenerator.ValidateGeneratedFiles();
       if (errors.Length > 0)
       {
           throw new InvalidOperationException(string.Join("\n", errors));
       }
   }
   ```

4. **오류 처리**. 생성 과정에서 오류가 발생하면(예: 잘못된 구성, 쓰기 실패), `GenerateAndWrite()`는 `InvalidOperationException`을 던지며, 메시지는 `"Hotfix AOT preserve generation failed:\n"`로 시작하고 오류를 한 줄씩 나열합니다. [AotPreserveGenerator.cs#L72-L78](/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L78) 참조; 디스크 쓰기 실패 시에는 `IOException` 또는 `UnauthorizedAccessException`도 발생할 수 있습니다.

## 일반적인 변형

- **프로그래밍 방식으로 트리거**: 메뉴 클릭이 필요하지 않은 경우, 편집기 스크립트에서 `AotPreserveGenerator.GenerateAndWrite()`를 직접 호출할 수 있습니다.
- **순수 빌드(디스크에 쓰지 않음)**: 사용자 정의 파이프라인에서 산출물만 미리 보고 싶은 경우, `AotPreserveGenerator.Build()`를 사용하여 `AotPreserveBuildResult`를 얻습니다(`LinkXml`, `ReferencesCode`, `GeneratedAsmdef`, `Report`, `ReferenceFiles`, `Errors` 포함). [AotPreserveGenerator.cs#L29-L61](/Editor/AotPreserve/AotPreserveGenerator.cs#L29-L61) 참조.
- **사용자 정의 구성 제공자**: `IAotPreserveSettingsProvider`를 구현하고 `AotPreserveSettingsProviderResolver`를 통해 주입하면 기본 구성의 출처를 재정의할 수 있습니다.

## 일반적인 오류

- **메뉴 클릭 후 콘솔에 `Hotfix AOT preserve generation failed: ...` 출력**: `Build()`에서 반환된 `AotPreserveBuildResult.Errors`가 비어 있지 않음을 의미하며, 일반적으로 `IAotPreserveSettingsProvider` 구성이 잘못되었거나 분석 단계가 실패한 경우입니다. 예외 메시지에 따라 하나씩 수정한 후 다시 생성하세요.
- **CI에서 검증 시 `InvalidOperationException`이 발생하며 여러 오류 나열**: `link.xml`, 참조 코드 또는 `asmdef`가 현재 분석 결과와 일치하지 않음을 나타냅니다. 메뉴에서 한 번 생성하여 새로 고치면 됩니다.
- **`UnauthorizedAccessException`**: `Assets/Generated/AotPreserve/` 디렉터리의 쓰기 권한과 `Assets/Generated/AotPreserve.Generated.asmdef`가 다른 프로세스에 의해 잠겨 있지 않은지 확인하세요.
- **생성된 파일 누락**: `Assets/Generated/AotPreserve`를 수동으로 삭제한 후 메뉴를 다시 트리거하지 않은 경우 - 메뉴에서 한 번 생성하면 전체 산출물을 재구성할 수 있습니다.

## 배경(선택 사항)

생성 진입점 `AotPreserveGenerator.GenerateAndWrite()`는 먼저 `AotPreserveAnalyzer.Analyze()`를 호출하여 보존해야 할 유형을 집계한 다음, `link.xml`(관리 stripping 시 어셈블리 수준 보존용), 집계 및 유형별로 분할된 참조 코드(런타임에서 AOT 메타데이터 로딩을 명시적으로 트리거하기 위함), 그리고 감사용 `aot_preserve_report.md` 보고서를 각각 생성합니다. `ValidateGeneratedFiles()`는 최신 분석 결과를 비교하여 파일이 만료되었는지 감지합니다.
