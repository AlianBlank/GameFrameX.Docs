# CocoaPods 依存関係の統合

Unity が iOS プロジェクトをエクスポートした後、本パッケージは JSON 設定に基づいて Podfile を自動生成(またはコピー)し、`pod` 依存関係を注入し、ビルド出力ディレクトリで直接 `pod install` を実行します。一連の処理全体でターミナルを手動で開く必要はありません。依存関係の宣言方法は 2 つあります:`unityMain` / `unityFramework` 内に `pods` フィールドを記述する方法(推奨、1 つずつ注入)、または `podfile` で完全な Podfile ファイルを指定する方法(設定すると `pods` は無視されます)。

## 前提条件

- ビルドマシンが macOS であり、CocoaPods がインストール済みであること:`sudo gem install cocoapods`。未インストールの場合、ログに `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)` が表示されます。
- プロジェクトに本パッケージが導入済みであり、Xcode 設定 JSON を準備していること(テンプレートとサンプルはパッケージに同梱:`Editor/XCodeConfigTemplate.json`、`Editor/XCodeConfigDemo.json`)。

## 操作手順

1. 設定 JSON の `unityMain`(メインプロジェクト target)または `unityFramework`(UnityFramework target)ブロック内に `pods` フィールドを追加します。`key` は pod 名、`value` はバージョン制約で、空文字列は制約なしを意味します:

   ```json
   "podSource": [
       "https://mirrors.tuna.tsinghua.edu.cn/git/CocoaPods/Specs.git"
   ],
   "podfile": "",
   "podInstall": true,
   ```

   最上位フィールドは上記の通りです(Demo での実際の値)。`pods` はターゲットブロック内部に記述します。Demo のサンプル値は以下の通りです:

   ```json
   "pods": {
       "Ads-CN-Beta": ", :subspecs => ['CSJMediation']"
   }
   ```

2. (任意)`podSource` を設定して国内ミラーソースを利用し、`pod install` を高速化します。未設定の場合、自動生成される Podfile にはデフォルトのソース `https://github.com/CocoaPods/Specs.git` が書き込まれます。

3. iOS ビルドを実行します。ビルド後処理は以下の順序で CocoaPods 設定を適用します:

   - `CopyPodfile`:`podfile` パスが設定されている場合、そのファイルをビルド出力ディレクトリに直接コピーし、その後その中の `source` 行のみを書き換えます;
   - そうでない場合は注入パスに進みます:`EnsurePodfileExists` がまず Podfile の存在を保証し(存在しない場合は現在の `PlayerSettings.iOS.targetOSVersionString` に基づいてスケルトンを生成、空の場合は `12.0` にフォールバック)、その後 `AddPodsForTarget` が `Unity-iPhone` と `UnityFramework` の 2 つの target にそれぞれ `pod` 行を注入します(既に存在する同名の pod は自動的にスキップ);
   - 最後に `RunPodInstall` がビルド出力ディレクトリで `pod install` を実行します(`"podInstall": false` でスキップ可能)。

   ```csharp
   // PodFile
   var podSourceList = finalConfig.Get("podSource") as ArrayList;
   string podfileConfigPath = finalConfig.Get("podfile") as string;
   bool podfileCopied = CopyPodfile(path, podfileConfigPath);

   if (podfileCopied)
   {
       // 新しいパス：完全な Podfile をコピー済みのため、source URL の書き換えのみ行う
       RunPodfile(path, podSourceList);
   }
   else
   {
       // 旧パス(後方互換):JSON 設定の pods フィールドから 1 行ずつ注入
       var mainPods = finalConfig.Get<Hashtable>("unityMain")?.Get<Hashtable>("pods");
       var frameworkPods = finalConfig.Get<Hashtable>("unityFramework")?.Get<Hashtable>("pods");
       if ((mainPods != null && mainPods.Count > 0) || (frameworkPods != null && frameworkPods.Count > 0))
       {
           EnsurePodfileExists(path, podSourceList);
           AddPodsForTarget(path, "Unity-iPhone", mainPods);
           AddPodsForTarget(path, "UnityFramework", frameworkPods);
       }
   }
   ```

4. 結果の検証：Unity Console の `[Pods]` と `[PodInstall]` プレフィックスのログを確認し(例:`[Pods] 已为 Unity-iPhone 添加 N 个 pod 依赖`、`[PodInstall] pod install 完成`)、ビルド出力ディレクトリに `Podfile` と `Pods` ディレクトリが生成されたこと、`.xcworkspace` が正常に開けることを確認します。

## 設定項目クイックリファレンス

| 設定項目 | 型 / デフォルト値 | 説明 |
|------|------|------|
| `podSource` | `string[]` / 未設定の場合は `https://github.com/CocoaPods/Specs.git` を使用 | Podfile 先頭に書き込む `source` ソースリスト。国内ミラーを指定可能 |
| `podfile` | `string` / `""` | 完全な Podfile ファイルのパス。相対パス(Unity プロジェクトのルートディレクトリ、つまり Assets の 1 つ上の階層基準)と絶対パスをサポート。設定すると `pods` は無視される |
| `podInstall` | `bool` / `true` | ビルド後に `pod install` を自動実行するかどうか。`false` に設定するとスキップ可能 |
| `unityMain.pods` / `unityFramework.pods` | `object` / `{}` | key は pod 名、value はバージョン制約。空文字列は制約なしを意味する |

## バージョン制約の書き方

`pods` の value は以下のルールに従って Podfile の `pod` 行に組み立てられます:

```csharp
// pod 行の構築
foreach (DictionaryEntry kv in pods)
{
    var podName = kv.Key.ToString().Trim();
    if (existingPods.Contains(podName)) continue;

    var version = kv.Value?.ToString()?.Trim();
    if (string.IsNullOrEmpty(version))
    {
        podLines.Add($"  pod '{podName}'");
    }
    else if (version.Contains("=>") || version.StartsWith(":"))
    {
        podLines.Add($"  pod '{podName}', {version}");
    }
    else
    {
        podLines.Add($"  pod '{podName}', '{version}'");
    }
}
```

対応関係:`""` → `pod 'Name'`;`=>` を含む、または `:` で始まる場合(例:`:subspecs => [...]`、`:git => '...'`)→ カンマの後に引用符なしでそのまま連結；それ以外(例:`~> 1.0`)→ 自動的にシングルクォートが補われ `pod 'Name', '~> 1.0'` になります。

## よくあるバリエーション

- **完全な Podfile を使用**:依存関係が複雑な場合、管理済みの Podfile をプロジェクト内に置き、`"podfile": "MyPodfile"`(Unity プロジェクトのルートディレクトリ基準の相対パス)または絶対パスを設定します。コピー成功後はその中の `source` 行のみが書き換えられ、それ以外の内容はそのまま保持されます;ファイルが存在しない場合、ログに `[Pods] 配置指定的 Podfile 不存在: {src}` が出力され、`pods` 注入パスにフォールバックします。
- **自動 pod install をスキップ**:CI でインストールのタイミングを自分で制御する必要がある場合は `"podInstall": false` を設定します。ビルド後処理は Podfile の生成/注入のみを行い、パイプラインの後続ステップで `pod install` を実行します。
- **プライベートソース / 複数ソース**:`podSource` は配列で、複数の `source` 行を同時に書き込めます。例えば公式 Specs とプライベートリポジトリを同時に保持できます。

## よくあるエラー

| 現象(ログ原文) | 原因 | 修正 |
|------|------|------|
| `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)` | ビルドマシンに CocoaPods が未インストール、または pod が一般的なパス(`.gem/ruby/bin`、Homebrew、`/usr/local/bin`、`/usr/bin`)に存在せず `which pod` の解決に失敗 | CocoaPods をインストールする;または pod を `/usr/local/bin/pod` など検出可能なパスにシンボリックリンクする |
| `[Pods] 配置指定的 Podfile 不存在: {src}` | `podfile` のパスが誤っている、またはファイルが移動された | 正しいパスに修正する;相対パスは Unity プロジェクトのルートディレクトリ(Assets の 1 つ上)基準 |
| `[Pods] 未找到 target '{targetName}' do, 跳过设置` | カスタム Podfile の target 行のフォーマットが不一致(`target 'Unity-iPhone' do` の形式である必要がある) | target 行の書き方を修正する、または `pods` 注入方式を直接使用する |
| `[PodInstall] pod install 失败 (退出码: {code}): {error}` | pod のバージョン制約の競合、ソースに到達できない、Gem/Ruby 環境の問題など | error の出力に従って調査する;まずミラーソースを試し、必要に応じて `"podInstall": false` を設定して手動で `pod install` を実行し問題を再現する |
| `当前不是Pod 项目结构,跳过设置` | ビルド出力ディレクトリに `Podfile` が存在しない | `pods` 注入方式で自動作成させる、または `podfile` 設定を提供する |

## 検証

- Unity Console に `修改PodFile 文件的源, 开始/结束`、`[Pods] ...`、`[PodInstall] 开始执行 pod install...`、`[PodInstall] pod install 完成` の順で表示される。
- ビルド出力ディレクトリに `Podfile`(内容に設定した `source` 行と各 target の `pod` 行を含む)、`Pods/` ディレクトリ、`Podfile.lock` が存在する。
- 生成された `.xcworkspace`(`.xcodeproj` ではなく)を開き、依存ライブラリが Pods プロジェクトに現れ、コンパイルが通ることを確認する。

## 背景

CocoaPods 関連のロジックはビルド後処理の第 2 段階に集約されており、`PostProcessBuildHelper` の部分クラスファイルに実装されています:[PostProcessBuildHelper.PodFile.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.PodFile.cs#L19) は `RunPodfile`(source 行の書き換え)、`EnsurePodfileExists`(スケルトン生成)、`CopyPodfile`(カスタム Podfile のコピー)、`AddPodsForTarget`(target ごとの注入と重複排除)、`RunPodInstall` と `GetPodFullPath` を提供します;メインフローは [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156) で連結されています。`pod install` 実行時には `LANG` / `LC_ALL` を明示的に `en_US.UTF-8` に設定し(CocoaPods にはエンコーディングの要件があるため)、pod の絶対パスを解決します(Unity のサブプロセスは shell PATH を継承しない)。これが「ターミナルでは使用できるのにビルド時に pod が見つからない」というよくある問題の根本原因です。iOS ビルド後処理全体のフローについては、『iOS ビルド後処理』を参照してください。
