# 如何使用计时器统计时长（开始 / 暂停 / 恢复 / 结束）

调用 `GameAnalyticsComponent`（或底层 `IGameAnalyticsManager`）上的四个计时接口即可完成一次完整的时长统计：`StartTimer` 开始、`PauseTimer` 暂停、`ResumeTimer` 恢复、`StopTimer` 结束并产出该事件的时长数据。四个接口都只接收一个参数 `eventName`（事件名称），组件会把它转发给所有已初始化的分析后端。

## 前置条件

- 场景中已挂载 `GameAnalyticsComponent`，并完成初始化（`Init` / `ManualInit`）。未初始化时计时调用会被静默忽略，并可能输出 `GameAnalyticsManager is not init.` 警告。
- 了解具体的初始化流程，请参阅组件对应文档。

## 操作步骤

1. 确认组件已初始化（`IsInit()` 返回 `true`）。
2. 在玩法开始处调用 `StartTimer`，传入本次要统计的事件名：

```csharp
public void StartTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StartTimer(eventName);
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/README.md#L80-L86)

3. （可选）切到后台或玩家离开玩法时调用 `PauseTimer` 暂停累计：

```csharp
_gameAnalyticsComponent.PauseTimer("level_1_playtime");
```

4. （可选）玩家回来时调用 `ResumeTimer` 继续累计：

```csharp
_gameAnalyticsComponent.ResumeTimer("level_1_playtime");
```

5. 玩法结束时调用 `StopTimer` 结束计时，时长数据随事件名上报：

```csharp
public void StopTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StopTimer(eventName);
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/README.md#L90-L96)

### 接口一览

| 名称 | 签名 | 说明 |
|------|------|------|
| 开始计时 | `void StartTimer(string eventName)` | 为指定事件名启动计时 |
| 暂停计时 | `void PauseTimer(string eventName)` | 暂停该事件名的时长累计 |
| 恢复计时 | `void ResumeTimer(string eventName)` | 从暂停处继续累计 |
| 结束计时 | `void StopTimer(string eventName)` | 结束计时并产出该事件的时长数据 |

四个签名均在 `IGameAnalyticsManager` 中定义（`StartTimer` L52、`PauseTimer` L58、`ResumeTimer` L64、`StopTimer` L70）。

### 复制即用的完整封装

```csharp
private const string LevelTimerName = "level_1_playtime";

public void OnLevelStart()
{
    GameAnalyticsComponent.Instance.StartTimer(LevelTimerName);
}

public void OnApplicationPause(bool pauseStatus)
{
    if (pauseStatus)
    {
        GameAnalyticsComponent.Instance.PauseTimer(LevelTimerName);
    }
    else
    {
        GameAnalyticsComponent.Instance.ResumeTimer(LevelTimerName);
    }
}

public void OnLevelFinish()
{
    GameAnalyticsComponent.Instance.StopTimer(LevelTimerName);
}
```

注意：`GameAnalyticsComponent.Instance` 的具体获取方式以你项目中的组件注册方式为准；上面四个方法名与签名均来自仓库真实接口。

## 常见变体

- **不需要暂停的短时统计**：只调用 `StartTimer` 和 `StopTimer` 即可，`PauseTimer` / `ResumeTimer` 可省略（README 中给出的官方示例即只有这两个调用）。
- **多个事件并行计时**：以不同 `eventName` 分别调用 `StartTimer`，各计时互不影响；同一事件名重复开始的行为由底层分析后端决定，建议同一事件名串行使用。
- **直接对接底层 Manager**：若不通过组件而是持有 `IGameAnalyticsManager` 实现，可绕过组件循环直接调用同名接口；`BaseGameAnalyticsManager` 将四个计时方法声明为抽象方法，由具体后端实现。

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L150-L168)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 计时调用无任何数据上报 | 组件未初始化，`m_IsInit == false` 时方法直接 `return` | 先调用 `Init` / `ManualInit` 再开始计时 |
| 日志出现 `GameAnalyticsManager is not init.` | `StartTimer` / `StopTimer` 遍历时发现某个后端 `IsInit()` 为 `false` | 确认各分析后端均已初始化完成 |
| 传入空事件名直接抛异常 | `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))` 会拦截空/`null` | 保证 `eventName` 非空 |
| 暂停后时长仍被计入 | 只调用了 `PauseTimer` 之外的方法或事件名不一致 | 暂停与恢复必须使用与开始时相同的 `eventName` |

以 `StartTimer` 为例，组件内部对参数与初始化状态的检查如下（`StopTimer` 逻辑相同）：

```csharp
public void StartTimer(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.StartTimer(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179)

## 验证

- 调用 `StopTimer` 后，在对应分析平台（GameAnalytics 后台）查看该 `eventName` 的时长数据是否出现且数值合理。
- 若无数据，检查 Console 是否有 `GameAnalyticsManager is not init.` 警告，并确认 `eventName` 非空、开始与结束使用同一名称。

## 背景

`GameAnalyticsComponent` 是四个计时接口的门面：它先做参数守卫与初始化检查，再把调用广播给 `m_GameAnalyticsManager` 列表中所有已初始化的 `IGameAnalyticsManager` 实现（`PauseTimer` / `ResumeTimer` 的广播不做二次 `IsInit()` 判断，但同样受组件级 `m_IsInit` 拦截）。真正的计时逻辑由各分析后端在 `BaseGameAnalyticsManager` 的抽象方法中实现。
