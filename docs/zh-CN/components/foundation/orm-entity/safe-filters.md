# 如何使用软删除/启用过滤接口

在实体上启用 `ISafeDeletedFilter` 与 `ISafeEnabledFilter` 后,框架会在基础实体 `EntityBase` 中自动提供软删除字段(`IsDeleted`、`DeleteTime`、`DeleteId`)和启用/禁用字段(`IsEnabled`),实现"逻辑删除"与"启用状态"统一管理。

## 前置条件

- 引入命名空间 `GameFrameX.Foundation.Orm.Entity`(提供 `EntityBase`、`EntityBase<TKey>`)。
- 引入命名空间 `GameFrameX.Foundation.Orm.Entity.Filter`(提供过滤器接口)。
- 实体类继承 `EntityBase` 或 `EntityBase<TKey>`。框架基类已经默认实现了 `ISafeDeletedFilter` 与 `ISafeEnabledFilter`,无需手动添加实现。

## 操作步骤

1. 让业务实体继承 `EntityBase`,即可同时拿到软删除和启用过滤字段。

```csharp
using GameFrameX.Foundation.Orm.Entity;
using GameFrameX.Foundation.Orm.Entity.Filter;

public class SysUser : EntityBase
{
    public string UserName { get; set; } = string.Empty;
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L46)

2. 实体类已自动包含以下软删除字段,可直接使用:

| 字段 | 类型 | 默认值 | 含义 |
|------|------|--------|------|
| `IsDeleted` | `bool?` | `false` | 软删除标记:`true` 已删除,`false` 未删除,`null` 未设置(按未删除处理) |
| `DeleteTime` | `long?` | `null` | 删除时间(时间戳) |
| `DeleteId` | `long?` | `null` | 删除人 Id |

```csharp
// 将用户标记为删除
sysUser.IsDeleted = true;
sysUser.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
sysUser.DeleteId = currentUserId;
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L120-L138)

3. 启用过滤(`ISafeEnabledFilter`)由基类 `EntityBase` 同时实现,用于记录实体启用状态。

4. 在仓储层查询时,通过过滤字段 `IsDeleted = false` 来排除已删除数据,实现软删除查询:

```csharp
// 示例:查询未删除的用户列表
var users = await dbContext.Set<SysUser>()
    .Where(u => u.IsDeleted == false || u.IsDeleted == null)
    .ToListAsync();
```

5. 删除操作时不要走物理删除,改为修改 `IsDeleted`:

```csharp
public void SoftDelete(SysUser user, long operatorId)
{
    user.IsDeleted = true;
    user.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
    user.DeleteId = operatorId;
}
```

## 常见变体

- 使用泛型主键基类 `EntityBase<TKey>`(如 `EntityBase<long>`),依旧自动包含软删除和启用字段。
- 想自定义主键类型时,继承 `EntityBase<TKey>` 并指定泛型参数即可:

```csharp
public class SysRole : EntityBase<long>
{
    public string RoleName { get; set; } = string.Empty;
}
```

- 如果只想用选择过滤而不需要审计字段,可继承 `EntitySelectBase`(它在 `EntityBase` 基础上额外实现 `ISelectFilter`),但仍然包含 `IsDeleted` 等软删除字段。

Source: [EntitySelectBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntitySelectBase.cs#L45-L45)

## 常见错误

- 误用物理删除:对继承 `EntityBase` 的实体调用 ORM 的 `Remove`/`Delete`,会绕过软删除标记,导致数据真正消失。请统一改为改写 `IsDeleted = true`。
- 查询遗漏 `IsDeleted` 过滤:如果不加 `Where(u => u.IsDeleted == false)`,会同时查出已删除记录。请在仓储层强制加上过滤条件。
- 误以为 `IsDeleted` 是 `bool` 而非 `bool?`:框架使用可空布尔,默认 `false`,新增实体若不显式赋值,会按"未删除"处理;手动设置 `null` 同样视为未删除。
