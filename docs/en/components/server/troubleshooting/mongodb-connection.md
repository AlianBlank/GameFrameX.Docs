# What to Do About MongoDB Connection Failures or Entity Serialization Errors

When starting the service, if you encounter errors such as `MongoDB connection failed`, `数据库服务启动失败`, `No serializer found for ...`, or `An error occurred while deserializing ...`, use the diagnostic table on this page to locate the cause, then follow the corresponding section to fix it.

## Quick Diagnosis

| Symptom (console/log text) | Root Cause | Fix |
|---|---|---|
| `数据库服务启动失败` / `MongoDB connection failed` / `TimeoutException` | `DataBaseUrl` unreachable, wrong username/password, authSource mismatch, or standalone direct connection without `directConnection` enabled | See "Connection Configuration Errors" |
| `MongoCommandException: Authentication failed` | Wrong username/password, or no account created for the target database | See "Authentication Failure" |
| `No serializer found for type X` / `An error occurred while deserializing the X bson element ...` | The entity class has no BsonClassMap registered, or fields inherited from the `BaseCacheState` base class are not ignored | See "Entity Serialization Failure" |
| Startup hangs, or the first `Insert`/`Find` throws `MongoConnectionException` | Docker container not started, port occupied, or the service starts before mongo | See "Service Dependencies and Ports" |
| After a write, the document contains only the `_t` discriminator, but reads return `null` | Multiple assemblies use the same fully qualified class name without setting `Discriminator`, or the subclass is not registered | See "Entity Serialization Failure → Discriminator Conflict" |

## Fix Steps

### Connection Configuration Errors

1. Verify the configuration key `DataBaseUrl`. By default, `Setting.DataBaseUrl` in [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L61-L65) is passed to `GameDb.Init<MongoDbService>`; the connection string format must comply with the MongoDB Driver requirements.

2. When starting with local Docker, use the container configuration provided by [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L2-L13):

   ```yaml
   mongodb:
     image: mongo
     container_name: mongodb
     ports:
       - "27017:27017"
     volumes:
       - ./running/database:/data/db
     environment:
       - MONGO_INITDB_ROOT_USERNAME=admin
       - MONGO_INITDB_ROOT_PASSWORD=admin
   ```

   Corresponding connection string example (consistent with the environment variables in compose):

   ```bash
   DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L60-L72)

3. When using cloud services such as [MongoDB Atlas](https://www.mongodb.com/atlas), keep the `mongodb+srv://` form and append `retryWrites=true&w=majority`:

   ```csharp
   DataBaseUrl = "mongodb+srv://gameframex:***@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority",
   DataBaseName = "gameframex",
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L112-L113)

4. When connecting directly to `127.0.0.1` locally, if you encounter `No routing to host`, add `directConnection=true`:

   ```text
   mongodb://admin:admin@127.0.0.1:27017/?authSource=admin&directConnection=true
   ```

### Authentication Failure

1. Check that `MONGO_INITDB_ROOT_USERNAME`/`MONGO_INITDB_ROOT_PASSWORD` match the credentials in the connection string.
2. When the account is created in `admin` but the target database is `gameframex`, the connection string must include `?authSource=admin`; otherwise the driver validates against the default database and throws `Authentication failed`.
3. If a self-created account is authorized for a single database only: `authSource` must equal that database's name.

### Service Dependencies and Ports

1. Run `docker compose up mongodb -d` and first confirm the container is healthy:

   ```bash
   docker ps --filter name=mongodb
   docker logs mongodb --tail 50
   ```

2. The container and the game process must be on the same `gameframex` network; when running the game process standalone, change the hostname in `DataBaseUrl` to `localhost` or the corresponding IP.
3. If host port `27017` is occupied, change the compose mapping (e.g., `"27018:27017"`) and update the connection string to `27018` accordingly.

### Entity Serialization Failure

1. At startup, all entities in the assembly inheriting `BaseCacheState`/`CacheState` are scanned and their BsonClassMaps registered. See the registration entry point in [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33):

   ```csharp
   var assembly = typeof(AppsHandler).Assembly;
   BsonClassMapHelper.SetConvention();
   foreach (var type in assembly.GetTypes())
   {
       if (!typeof(BaseCacheState).IsAssignableFrom(type)) continue;
       HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
       BsonClassMapHelper.RegisterClass(type);
   }
   ```

   Source: [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)

2. `BsonClassMapHelper` auto-maps and ignores extra elements; see the reference implementation in [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143):

   ```csharp
   var bsonClassMap = new BsonClassMap(t);
   bsonClassMap.AutoMap();
   bsonClassMap.SetIgnoreExtraElements(true);
   bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
   BsonClassMap.RegisterClassMap(bsonClassMap);
   ```

   Source: [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

3. Common causes and handling for `No serializer found for type X`:
   - The entity class does not inherit `BaseCacheState` and is skipped by the registration process — make the entity inherit `BaseCacheState` or manually call `BsonClassMap.RegisterClassMap<T>()` beforehand.
   - The entity is defined in another assembly (e.g., `GameFrameX.Hotfix`), but `CacheStateTypeManager` only scans the `AppsHandler` assembly — call the registration once in the hot-update entry point as well, or extend the scanner to cover the Hotfix assembly.
   - The entity uses generic parameters that are not concrete — fill in the generic type arguments before registration.

4. **Discriminator Conflict**: Different subtypes sharing the same name, or the same fully qualified class name across assemblies, can both cause deserialization to return `null`. Explicitly specify it on the entity class:

   ```csharp
   [BsonDiscriminator("player_attr_v1")]
   public sealed class PlayerAttributeState : BaseCacheState { /* ... */ }
   ```

5. **Base Class Field Pollution**: If you do not want the dictionary/version fields that come with `BaseCacheState` written to MongoDB, add `[BsonIgnore]` to those fields; `SetIgnoreExtraElements(true)` only ignores the read direction — writes still require explicit ignoring.

6. Startup order is guaranteed by [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67): `GameDb.Init` → `ComponentRegister.Init` → `HotfixManager.LoadHotfixModule`. Code in hot-update that reads Mongo directly must be placed after the last step; otherwise it will throw `No serializer found` because the serializers are not yet registered.

## Verification

1. Restart the service and observe the startup logs appearing in order: `开始启动数据库服务...` → `启动数据库服务 结束...` → `注册组件开始/结束` → `加载热更新模块结束`.
2. Run `db.runCommand({ ping: 1 })` in Mongo Shell or Compass; it should return `{ ok: 1 }`.
3. Run a read/write cycle with any entity class's `Insert`/`Find`, and assert that the fields read back match what was written.
4. Deliberately change `DataBaseUrl` to a wrong address and start again; it should immediately throw `数据库服务启动失败` and print the root-cause stack — this confirms the exception propagation chain is working.
