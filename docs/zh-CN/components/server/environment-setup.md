# 环境准备与本地构建

本节指导你在本地准备好运行 GameFrameX 服务端所需的环境与工具,并完成首次构建,直到能在控制台看到服务器启动日志。

## 前置条件

| 工具/组件 | 要求 | 备注 |
|----------|------|------|
| .NET SDK | 仅支持 .NET 10.0 SDK | 不兼容 .NET 8/9 |
| 数据库 | MongoDB 4.x 及以上 | 可本地安装或 Docker 启动 |
| IDE | Visual Studio 2022 或 JetBrains Rider | 任意可识别 .NET 10 的编辑器均可 |
| 可选 | Docker | 用于快速拉起 MongoDB 容器 |
| 可选 | Git | 克隆仓库 |

> 上述版本要求源自项目 README 的"环境要求"小节([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L168-L172))。徽章中同样明确标注了 `.NET-10.0`([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L8))。

## 操作步骤

1. **克隆仓库并进入服务端目录**

   ```bash
   git clone https://github.com/GameFrameX/GameFrameX.git
   cd GameFrameX/Server
   ```

2. **还原 NuGet 依赖**

   ```bash
   dotnet restore
   ```

   这会拉取 `GameFrameX.AppHost` 等项目里 `Aspire.Hosting.*` 等 NuGet 包([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L9-L12))。

3. **编译解决方案**

   ```bash
   dotnet build
   ```

   首次构建会编译所有模块(包括热更层 `Hotfix` 与持久化层 `Apps`),编译产物输出到各项目的 `bin/` 目录。

4. **启动 MongoDB**

   任选一种方式,任选其一即可:

   ```bash
   # 方式一:本地 mongod
   mongod --dbpath /path/to/data

   # 方式二:Docker
   docker run -d -p 27017:27017 --name mongo mongo:8.2
   ```

   启动成功后 MongoDB 默认监听 `127.0.0.1:27017`。

5. **运行 Launcher 启动服务器**

   使用命令行参数指定服务类型与端口(详细参数见《启动参数》参考页):

   ```bash
   dotnet run --project GameFrameX.Launcher -- \
       --ServerType=Game \
       --ServerId=1000 \
       --OuterPort=29100 \
       --HttpPort=28080 \
       --DataBaseUrl=mongodb://127.0.0.1:27017 \
       --DataBaseName=gameframex
   ```

   上述命令对应 README 提供的"最小启动"路径([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L203-L210))。

6. **验证启动**

   - 浏览器或 curl 访问 `http://localhost:28080/game/api/health`,期望返回健康状态。
   - 在 Launcher 控制台查看日志,确认 Actor 与网络监听均已就绪。

## 常见变体

### 使用 Aspire AppHost 一键编排

仓库根目录提供 `GameFrameX.AppHost` 项目,使用 `.NET Aspire` SDK,引用 MongoDB 组件([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19))。直接 F5 运行 AppHost 即可让 Aspire Dashboard 自动拉起 MongoDB 与 Launcher:

```bash
dotnet run --project GameFrameX.AppHost
```

### 在 IDE 中调试

在 Rider/VS 中将 `GameFrameX.Launcher` 设为启动项目,把上述命令行参数粘贴到"运行配置 → Program arguments"中,即可断点调试启动流程。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `dotnet restore` 报 `NETSDK1045` 提示未安装 .NET 10 | 安装了 .NET 8/9 而没有 .NET 10 | 安装 [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) 并设为默认 SDK |
| 构建报 `NU1605` / 包冲突 | 子项目锁定了不兼容的传递依赖 | 删除 `bin/`、`obj/` 后重新 `dotnet restore` |
| 启动报 `MongoDB connection refused` | MongoDB 未启动或端口被占用 | 确认 `mongod` 已运行,或调整 `--DataBaseUrl` |
| 健康检查 404 / 端口无响应 | `--HttpPort` 被占用或 `--OuterPort` 与现有进程冲突 | 更换端口后重新启动 |

## 背景(可选)

项目基于 .NET 10 SDK + .NET Aspire 13.4.6 编排本地依赖([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19))。Launcher(`GameFrameX.Launcher`)是真正承载 Actor 与网络监听的进程入口,负责把命令行参数映射到 `StartupOptions`,再驱动 `GameFrameX.StartUp` 启动宿主。

关于运行时配置项的完整列表,见《启动参数参考》。
