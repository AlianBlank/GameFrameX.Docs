# 用 async/await 等待秒数与帧数

`TimerComponent` 暴露了三个可直接 `await` 的等待方法:`WaitForSecondsAsync`(等秒数)、`WaitForNextFrameAsync`(等下一帧)、`WaitForFramesAsync`(等指定帧数)。它们全部基于定时器管理器实现,等待与续体都在 Unity 主线程完成,可在协程之外用 `async` 方法写出线性流程。

## 前置条件

- 场景/项目中已接入 `TimerComponent`(定时器管理器已随组件初始化)。
- 调用方为 `async` 方法(`async void` 仅建议用于 Unity 事件函数,如 `Start`)。

## API 速查

| 方法 | 签名 | 行为 |
|------|------|------|
| 等待秒数 | `Task WaitForSecondsAsync(float seconds, CancellationToken cancellationToken = default)` | `seconds` 秒后完成任务 |
| 等待下一帧 | `Task WaitForNextFrameAsync(CancellationToken cancellationToken = default)` | 下一帧更新后完成任务 |
| 等待帧数 | `Task WaitForFramesAsync(int frameCount, CancellationToken cancellationToken = default)` | 经过 `frameCount` 帧后完成;`frameCount <= 0` 时立即完成(返回 `Task.CompletedTask`) |

`TimerComponent` 上的同名实例方法直接转发给内部的 `ITimerManager`(见 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L245))。此外 `TimerAsyncExtensions` 以扩展方法形式向任意 `ITimerManager` 提供同样三个能力:

```csharp
public static Task WaitForSecondsAsync(this ITimerManager timer, float seconds, CancellationToken cancellationToken = default)
public static Task WaitForNextFrameAsync(this ITimerManager timer, CancellationToken cancellationToken = default)
public static Task WaitForFramesAsync(this ITimerManager timer, int frameCount, CancellationToken cancellationToken = default)
```

Source: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L20-L72)

## 操作步骤

1. 在脚本中引用命名空间(按项目实际引用方式调整):

```csharp
using System.Threading;
using System.Threading.Tasks;
```

2. 拿到 `TimerComponent` 实例(下方示例以字段 `timerComponent` 指代你项目中的组件引用),用 `await` 等待秒数:

```csharp
public async void Start()
{
    // 等待 2 秒(基于 TimerComponent 转发到内部 timerManager)
    await timerComponent.WaitForSecondsAsync(2f);
    UnityEngine.Debug.Log("2 秒后执行到这里");
}
```

3. 等待帧数,或只等一帧:

```csharp
// 等待 60 帧后继续
await timerComponent.WaitForFramesAsync(60);

// 只等下一帧
await timerComponent.WaitForNextFrameAsync();
```

4. 若持有 `ITimerManager` 引用,也可以直接调用扩展方法:

```csharp
await timerManager.WaitForSecondsAsync(1.5f);
```

## 常见变体

- **带取消令牌的等待**(对象销毁、玩法取消时提前结束):

```csharp
var cts = new CancellationTokenSource();
await timerComponent.WaitForSecondsAsync(5f, cts.Token);
```

取消后再次 `await` 该任务会以取消状态完成;调用前令牌已取消时,方法直接返回 `Task.FromCanceled(cancellationToken)`,不会注册任何定时器:

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return Task.FromCanceled(cancellationToken);
}
```

Source: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L22-L28)

- **顺序串联多个等待**:`await` 天然线性,直接依次书写即可,无需嵌套回调。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `WaitForFramesAsync(0)` 或传负数没有等待 | `frameCount <= 0` 时直接返回 `Task.CompletedTask`,这是文档化的行为 | 至少传 `1`;要"立即让出"请用 `WaitForNextFrameAsync()` |
| 令牌已取消却仍进入等待流程 | 设计如此:已取消时立即返回 `Task.FromCanceled`,不注册定时器 | 检查令牌生命周期,必要时换新令牌 |
| 续体里访问 Unity 对象报主线程外异常 | 所有等待与续体均在 Unity 主线程完成(类注释明确声明) | 不要在等待任务上调用 `ConfigureAwait(false)` 等改变上下文的写法 |

## 背景

三个方法均以 `TaskCompletionSource<bool>` 包装一次定时器回调:`WaitForSecondsAsync` 用 `timer.AddOnce(seconds, ...)`,一次触发后自动移除;`WaitForNextFrameAsync` 用 `AddOnce(0, ...)`,`interval=0` 即每帧、`repeat=1` 即执行一次;`WaitForFramesAsync` 用 `timer.Add(0, frameCount, ...)`,每帧执行、共 `frameCount` 次后移除。取消通过 `cancellationToken.Register` 将任务置为取消,回调触发时释放注册。实现见 [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L27-L94)。
