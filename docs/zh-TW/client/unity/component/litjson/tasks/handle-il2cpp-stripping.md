# 如何處理 Unity IL2CPP 託管程式碼剔除(Managed Code Stripping)

啟用 IL2CPP + Managed Code Stripping 之後，`GameFrameX.LitJSON` 會透過三層互補的機制保護自身型別免於被剔除。本頁說明這些機制如何協同運作，以及當遇到因剔除造成的 `MissingMethodException` / `TypeLoadException` 時，如何新增保護。

## 前置需求

- Unity 2019.4 或以上版本(詳見 [package.json](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/package.json#L5))
- 已透過 Scoped Registry 或 Git URL 安裝 `com.gameframex.unity.litjson`(詳細說明請參閱 README)
- 專案使用 IL2CPP 後端(Android/iOS 等發行平台上預設啟用)

## 步驟

### 1. 確認預設已啟用剔除保護

此套件內建三層保護。**大多數專案無需額外設定**:

| 機制 | 用途 | 來源 |
|------|------|------|
| `link.xml` | 以宣告方式保留命名空間內的所有型別 | 套件層級的篩選檔案 |
| `LitJsonCroppingHelper` | 啟動時透過 `typeof()` 觸及關鍵型別 | `Runtime/LitJsonCroppingHelper.cs` |
| `[Preserve]` 屬性 | 標記對反射敏感的建構函式、屬性 getter 與匯出器 | 各個 Runtime 類別 |

只要場景中有作用中的 `LitJsonCroppingHelper` 實例，第三層保護便會在 `Start()` 中生效。

### 2. 將 `LitJsonCroppingHelper` 掛載到場景

開啟任一**第一個場景**(Bootstrap / Loading 場景)，建立一個空的 GameObject,並加入元件 `LitJson Cropping Helper`:

```csharp
// Runtime/LitJsonCroppingHelper.cs 中 Start() 的實際實作
[Preserve]
public void Start()
{
    _ = typeof(ArrayMetadata);
    _ = typeof(Condition);
    _ = typeof(ExporterFunc);
    _ = typeof(ExporterFunc<>);
    _ = typeof(JsonIgnoreAttribute);
    _ = typeof(JsonPropertyAttribute);
    _ = typeof(FsmContext);
    _ = typeof(IJsonWrapper);
    _ = typeof(ImporterFunc);
    _ = typeof(ImporterFunc<,>);
    _ = typeof(JsonData);
    _ = typeof(JsonException);
    _ = typeof(JsonMapper);
    _ = typeof(JsonMockWrapper);
    _ = typeof(JsonReader);
    _ = typeof(JsonToken);
    _ = typeof(JsonType);
    _ = typeof(JsonWriter);
    _ = typeof(Lexer);
    _ = typeof(ObjectMetadata);
    _ = typeof(OrderedDictionaryEnumerator);
    _ = typeof(ParserToken);
    _ = typeof(PropertyMetadata);
    _ = typeof(UnityTypeBindings);
    _ = typeof(WrapperFactory);
    _ = typeof(WriterContext);
}
```

來源:[LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L23-L52)

每個 `_ = typeof(...)` 都使用了 C# 7.0 的捨棄(discard)語法，目的是讓 IL2CPP 連結器將這些型別視為「已使用」，進而保留它們。

### 3. 為自己的反射類別加上 `[Preserve]` 標記(選用)

當 LitJson 透過反射讀寫自訂的 POCO 時，若某個型別在程式碼中從未被明確 `new` 過，它仍可能被剔除。只需在您的資料類別上加上 `[Preserve]`:

```csharp
using UnityEngine.Scripting;

[Preserve]
public class PlayerData
{
    public string Name;
    public int Level;
    public Vector3 Position;
}
```

### 4. 觸發 IL2CPP 建置並驗證二進位檔案

1. File → Build Settings → 將平台切換至 iOS 或 Android
2. Player Settings → Other Settings → Scripting Backend = `IL2CPP`,將 Managed Stripping Level 保持為預設的 `High`,或明確設定為 `Low`/`Medium` 以便重新測試
3. Build And Run
4. 在裝置/模擬器上執行一次反序列化(例如 `JsonMapper.ToObject<PlayerData>(text)`),並確認沒有出現任何例外

## 常見變化情境

- **程式碼熱更新情境**：若使用 HybridCLR / ILRuntime,還需要在宿主專案中為熱更新 DLL 額外放置一份 link.xml,否則熱更新程式碼所引用的 LitJson 型別仍可能被剔除。
- **Addressables 遠端資源**：在執行階段從遠端載入的 `AssemblyDefinition` 不受主專案 link.xml 的約束；需要在該遠端組件自身的 asmdef 旁再放置一份。
- **不使用 `LitJsonCroppingHelper`**:可手動撰寫 link.xml 來取代第三層保護(詳見下一節)。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 執行階段出現 `MissingMethodException: void LitJson.JsonMapper::.cctor()` | `JsonMapper` 的 cctor 被剔除 | 確認 `LitJsonCroppingHelper` 已掛載到場景中且處於作用狀態 |
| `TypeLoadException: Could not load type LitJson.Lexer` | `Lexer` 型別被剔除 | 同上，或在您自己的資料類別上加上 `[Preserve]` |
| 加上 `[Preserve]` 後仍然出錯 | 僅放置了 link.xml,但被託管剔除忽略 | 將 link.xml 放在 `Assets/` 根目錄或套件根目錄，而非 `Assets/Plugins/` 之類的子層目錄 |
| iOS 建置不會觸發 `Start()` | `LitJsonCroppingHelper` 元件被掛載到未載入的子場景 | 直接掛載到第一個場景，或在自訂的 `RuntimeInitializeOnLoadMethod` 中手動呼叫 |

## 背景(選用)

LitJson 大量使用反射(`JsonMapper.ToObject<T>` 透過反射讀取欄位並寫入 setter)。IL2CPP 的靜態分析只能識別被直接呼叫的程式碼；反射呼叫鏈無法被追蹤，因此從未被 `new` 過的型別會被剔除。本套件採用**三重保護**：link.xml 作為白名單、透過 `LitJsonCroppingHelper` 在執行階段以 `typeof` 觸及型別，以及在反射進入點加上 `[Preserve]` 標註——任何一層失效時，另外兩層仍能提供安全網。
