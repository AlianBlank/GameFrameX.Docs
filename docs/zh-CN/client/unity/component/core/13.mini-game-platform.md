# 小游戏平台适配

小游戏平台适配模块提供了对 21 个主流小游戏平台的统一宏定义管理解决方案。通过该模块，开发者可以一键切换目标平台，系统会自动处理平台之间的互斥关系，并生成统一的 WebGL 小游戏宏定义。

## 概述

在开发 Unity WebGL 小游戏时，针对不同平台需要设置不同的脚本宏定义（Scripting Define Symbols）来启用平台特定的代码适配。传统方式需要手动在 PlayerSettings 中配置，既繁琐又容易出错。

小游戏平台适配模块通过以下设计解决这些问题：

- **一键切换**：通过 Unity 菜单栏快速启用/禁用目标平台
- **自动互斥**：启用新平台时自动关闭其他平台，避免宏定义冲突
- **统一标识**：自动管理 `ENABLE_WEBGL_MINI_GAME` 统一宏，便于编写跨平台通用代码
- **平台分类**：按国内小游戏、海外小游戏、设备厂商、游戏平台四类组织，便于管理

### 架构说明

核心层 `MiniGameDefineSymbolHelper` 是整个模块的主控制器，提供以下核心功能：

1. **获取所有平台符号** (`GetAllMiniGameScriptingDefineSymbols`)：收集所有已注册的小游戏平台宏定义
2. **关闭其他平台** (`DisableOtherMiniGameScriptingDefineSymbols`)：实现平台间的互斥逻辑
3. **启用统一符号** (`EnableUnifiedMiniGameScriptingDefineSymbol`)：管理 `ENABLE_WEBGL_MINI_GAME` 统一宏
4. **刷新统一符号** (`RefreshUnifiedMiniGameScriptingDefineSymbol`)：根据当前平台状态动态调整统一宏

平台层按功能分为四个文件夹，每个平台以 partial class 的形式扩展主类，通过 `[MenuItem]` 属性在 Unity 菜单栏生成对应的启用/禁用选项。

## 核心功能流程

```mermaid
sequenceDiagram
    participant Dev as 开发者
    participant Menu as Unity 菜单
    participant Main as MiniGameDefineSymbolHelper
    participant Other as 其他平台
    participant Util as ScriptingDefineSymbols
    participant PS as PlayerSettings

    Dev->>Menu: 选择"启用[XX小游戏]适配"
    Menu->>Main: 调用 EnableXXXMiniGame()
    
    Main->>Main: DisableOtherMiniGameScriptingDefineSymbols()
    loop 遍历所有平台
        Main->>Other: 检查是否需要关闭
        Other-->>Main: 返回平台符号数组
        Main->>Util: RemoveScriptingDefineSymbol()
        Util->>PS: 移除宏定义
    end
    
    Main->>Main: 遍历当前平台符号数组
    loop 启用当前平台
        Main->>Util: AddScriptingDefineSymbol()
        Util->>PS: 添加宏定义
    end
    
    Main->>Main: EnableUnifiedMiniGameScriptingDefineSymbol()
    Main->>Util: AddScriptingDefineSymbol("ENABLE_WEBGL_MINI_GAME")
    Util->>PS: 添加统一宏定义
    
    PS-->>Dev: 完成配置
    Dev->>Menu: 选择"关闭[XX小游戏]适配"
    Menu->>Main: 调用 DisableXXXMiniGame()
    
    Main->>Main: 遍历当前平台符号数组
    loop 禁用当前平台
        Main->>Util: RemoveScriptingDefineSymbol()
        Util->>PS: 移除宏定义
    end
    
    Main->>Main: RefreshUnifiedMiniGameScriptingDefineSymbol()
    Main->>Util: 动态调整统一宏定义
```

### 设计意图

该流程设计遵循以下原则：

1. **互斥性**：通过 `DisableOtherMiniGameScriptingDefineSymbols` 确保同时只有一个平台被激活，防止宏定义冲突导致的编译错误

2. **统一性**：每个平台启用时都会自动添加 `ENABLE_WEBGL_MINI_GAME` 统一宏，开发者可以使用该宏编写平台无关的核心逻辑

3. **动态刷新**：禁用平台时会检查是否还有其他平台处于激活状态，如果没有则自动关闭统一宏，避免无效宏定义的存在

## 使用示例

### 基础使用：启用平台

在 Unity 编辑器中，通过菜单栏选择对应的平台选项即可启用适配：

```
GameFrameX → Scripting Define Symbols → Domestic Mini Games → Enable WeChat Mini Game
```

启用后，系统会自动执行以下操作：
1. 关闭其他所有小游戏平台的宏定义
2. 启用微信小游戏的宏定义 (`ENABLE_WECHAT_MINI_GAME`, `WEIXINMINIGAME`)
3. 启用统一宏定义 (`ENABLE_WEBGL_MINI_GAME`)

### 代码中使用平台宏

```csharp
#if ENABLE_WECHAT_MINI_GAME
using WeChatMiniGame API;
// 微信小游戏特定代码
#elif ENABLE_DOUYIN_MINI_GAME
using DouYinMiniGameAPI;
// 抖音小游戏特定代码
#elif ENABLE_WEBGL_MINI_GAME
// 通用的 WebGL 小游戏逻辑
#endif
```

> Source: [MiniGameDefineSymbolHelper.WeChat.cs](https://github.com/GameFrameX/com.gameframex.unity/blob/main/Editor/MiniGame/DomesticMiniGames/MiniGameDefineSymbolHelper.WeChat.cs#L20-L40)

### 禁用平台

```
GameFrameX → Scripting Define Symbols → Domestic Mini Games → Disable WeChat Mini Game
```

禁用后，系统会移除该平台的宏定义，并检查是否需要调整统一宏定义。

### 核心实现逻辑

平台启用时的核心互斥逻辑：

```csharp
/// <summary>
/// 关闭除当前平台以外的其它小游戏平台宏定义。
/// Disables define symbols of other mini game platforms except the current one.
/// </summary>
/// <param name="currentMiniGameScriptingDefineSymbols">当前平台宏定义集合</param>
private static void DisableOtherMiniGameScriptingDefineSymbols(string[] currentMiniGameScriptingDefineSymbols)
{
#if UNITY_WEBGL
    var closedCount = 0;
    foreach (var defineSymbols in GetAllMiniGameScriptingDefineSymbols())
    {
        if (defineSymbols == null || object.ReferenceEquals(defineSymbols, currentMiniGameScriptingDefineSymbols))
        {
            continue;
        }

        foreach (var define in defineSymbols)
        {
            if (!ScriptingDefineSymbols.HasScriptingDefineSymbol(BuildTargetGroup.WebGL, define))
            {
                continue;
            }

            ScriptingDefineSymbols.RemoveScriptingDefineSymbol(define);
            closedCount++;
            UnityEngine.Debug.Log($"小游戏宏定义 [{define}] 已经关闭");
        }
    }

    UnityEngine.Debug.Log($"小游戏宏定义互斥清理完成，共关闭 {closedCount} 个宏定义");
#endif
}
```

> Source: [MiniGameDefineSymbolHelper.cs](https://github.com/GameFrameX/com.gameframex.unity/blob/main/Editor/MiniGame/MiniGameDefineSymbolHelper.cs#L52-L88)

## 配置说明

### 统一宏定义

所有启用了任意小游戏平台的项目都会自动获得 `ENABLE_WEBGL_MINI_GAME` 宏定义。该宏用于编写平台无关的核心逻辑：

```csharp
#if ENABLE_WEBGL_MINI_GAME
// 所有小游戏平台共用的代码
// 例如：统一的资源加载接口、通用的事件系统等
#endif
```

### 菜单项优先级

菜单项按照平台分类进行组织，优先级设置如下：

| 分类 | 优先级范围 | 说明 |
|------|-----------|------|
| 国内小游戏 | 2000-2099 | Domestic Mini Games |
| 游戏平台 | 2500-2599 | Game Platforms |
| 海外小游戏 | 3200-3499 | International Mini Games |
| 设备厂商 | 3700-3999 | Device OEMs |

### 注意事项

1. **仅支持 WebGL**：所有小游戏平台宏定义仅在 WebGL 构建目标下有效，代码中已添加 `#if UNITY_WEBGL` 保护
2. **互斥设计**：小游戏平台之间是互斥的，启用新平台会自动关闭旧平台
3. **宏定义格式**：平台宏定义通常包含两部分：
   - `ENABLE_XXX_MINI_GAME`：统一格式，便于识别
   - `XXXMINIGAME`：平台特定格式，与各平台 SDK 对应
