# APK インストールパッケージの構築方法

`GameFrameX.Builder.Editor.Builder.BuildApk()` を呼び出すことで、Unity プロジェクトをワンクリックで Android APK にパッケージ化し、必要に応じてオブジェクトストレージにアップロードできます。本ページではコマンドライン呼び出し、パラメータ説明、一般的なエラー処理方法について説明します。

## 前提条件

1. Unity エディタに本パッケージ（`com.gameframex.unity.builder`）がインストールされており、Unity エディタのプラットフォームが **Android** に切り替わっていること。
2. Android 署名、SDK、NDK、JDK などの環境が設定済みであること（Unity 公式 Android Player Settings を参照）。
3. APK をオブジェクトストレージにアップロードする場合は、`BuildPipeline → PlayerSettings → Scripting Define Symbols` に `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` を追加し、必要に応じて `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT` / `_QI_NIU` / `_A_LI_YUN` のいずれかを有効化してください。

## 操作手順

### 1. Unity エディタで直接呼び出す

`Window → General → Search` を開き、メニュー項目 `Builder/BuildApk` を実行するか、任意のエディタスクリプトで以下を呼び出します：

```csharp
using GameFrameX.Builder.Editor;

public static class MyBuildEntry
{
    public static void BuildApk()
    {
        GameFrameX.Builder.Editor.Builder.BuildApk();
    }
}
```

Source: [Editor/Builder.cs#L59-L78](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L59-L78)

### 2. CI からコマンドラインで呼び出す

`Unity.exe -batchmode -executeMethod` を使用してパッケージングのエントリポイントを起動し、コマンドライン引数でビルド動作を制御します。一般的なパラメータは以下の表をご覧ください。

| コマンドライン引数 | 意味 | デフォルト値 |
|------------|------|--------|
| `-executeMethod` | 実行するメソッドの完全名。ここでは `GameFrameX.Builder.Editor.Builder.BuildApk` を指定 | なし |
| `-logFile` | Unity ログの出力パス。ログ末尾の `/Unity/` が `/` に置換されます | なし |
| `-BUILD_NUMBER` | ビルド番号 | なし |
| `-JOB_NAME` | Jenkins などの CI のタスク名 | なし |
| `-PackageName` | YooAsset リソースパッケージ名 | なし |
| `-ChannelName` | チャネル名 | なし |
| `-BundleId` | Android パッケージ名（BundleId） | なし |
| `-AppVersion` | アプリバージョン | なし |
| `-PackageVersion` | リソースパッケージバージョン | なし |
| `-BuildPipeline` | パッケージングパイプラインの種類 | なし |
| `-Language` | 言語 | なし |
| `-IsUploadApk` | スイッチ：ビルド完了後に APK をオブジェクトストレージにアップロード | `false` |
| `-IsUploadLogFile` | スイッチ：ログファイルをアップロード | `false` |
| `-IsUploadAsset` | スイッチ：リソースをアップロード | `false` |
| `-IsUpdateAssetPackageVersion` | スイッチ：リモートリソースパッケージのバージョン番号を更新 | `false` |
| `-UpdateAssetPackageVersionUrl` | バージョン番号更新インターフェースアドレス | なし |
| `-UpdateAssetPackageVersionAuthorization` | バージョン番号更新インターフェース認証ヘッダ | なし |
| `-WeChatBotKey` | WeChat Work ボット Webhook Key（パッケージング結果通知） | なし |
| `-ObjectStorageKey / -ObjectStorageSecret / -ObjectStorageBucketName / -ObjectStorageEndPoint` | オブジェクトストレージアクセス認証情報 | なし |

パラメータ解析ロジックは `Builder.BuildParamsParse` にあります。各 `-xxx` の直後に値を指定すると、`BuilderOptions` の対応するフィールドに代入されます。

```text
Unity.exe -batchmode -nographics -quit \
  -projectPath <ProjectPath> \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
  -logFile <LogPath>/builder.log \
  -BUILD_NUMBER 100 \
  -JOB_NAME nightly \
  -BundleId com.example.game \
  -AppVersion 1.0.0 \
  -PackageVersion 100 \
  -ChannelName official \
  -IsUploadApk \
  -WeChatBotKey <WeChatKey>
```

Source: [Editor/Builder.BuildParamsParse.cs#L13-L160](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L13-L160)

### 3. 成果物とアップロードパス

`BuildApk` の内部では `BuildProductHelper.BuildPlayerAndroid()` が実際のパッケージングを実行し、APK ファイルパスを生成します：

- APK はデフォルトで `Library/PlayerDataCache/...` 以外のプロジェクトビルドディレクトリに出力されます。具体的なパスは `BuildProductHelper` の出力に従います。
- `-IsUploadApk` を渡した場合、オブジェクトストレージに保存されるパスは以下の通りです：
  `builder/{productName}/{activeBuildTarget}/{JobName}/{Application.version}/{BuildNumber}`。

Source: [Editor/Builder.cs#L47](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L47),[Editor/Builder.cs#L62-L78](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L62-L78)

## 一般的なバリエーション

- **ローカルビルドのみ、アップロードなし**: `-IsUploadApk` を付けなければよい。
- **ログも同時にアップロード**: `-IsUploadLogFile` を追加すると、`-logFile` で指定されたログも同じオブジェクトストレージパスにアップロードされます。
- **オブジェクトストレージサポートを有効化**: パッケージング用の Editor プロジェクトで `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` マクロを有効化し、クラウドベンダーに応じて `_TENCENT` / `_QI_NIU` / `_A_LI_YUN` のいずれかを追加します。`Builder` の静的コンストラクタでマクロに基づいて対応する `IObjectStorageUploadManager` 実装が選択されます。
- **WeChat Work 通知**: `-WeChatBotKey` でボット Webhook Key を渡すと、パッケージング終了後に結果をプッシュ通知できます。

## 一般的なエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `Exception: InvalidOperationException` が発生し、ログにオブジェクトストレージが有効化されていない旨が表示される | `-IsUploadApk` を渡したが、プロジェクトに `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` マクロがない | PlayerSettings の Scripting Define Symbols に対応するマクロを追加するか、`-IsUploadApk` を削除する |
| `Android` プラットフォームに切り替えた後も "Build target not supported" が発生する | `BuildApk` 呼び出し時に現在の `BuildTarget` が Android ではない | `EditorUserBuildSettings.activeBuildTarget == Android` であることを確認する |
| パラメータが有効にならない（例：`BundleId` が置換されない） | コマンドライン引数のスペルミスまたは値の欠落 | 上記の表に従って `-BundleId <value>` 形式で使用し、値は引数名の直後に記述する |
| `GameFrameX.Builder.Editor.Builder.BuildApk` が見つからない | パッケージがインポートされていないか、クラス名のスペルが間違っている | Package Manager に当該パッケージがインストールされていることを確認し、完全クラス名が `GameFrameX.Builder.Editor.Builder` であることを確認する |

## 背景（任意）

`Builder` は `partial class` で、パラメータ解析は `Builder.BuildParamsParse` に、実際の APK 生成はフレームワーク内部の `BuildProductHelper.BuildPlayerAndroid()` に委譲されています。アップロード部分は `IObjectStorageUploadManager` で抽象化されており、現在 Tencent Cloud、Alibaba Cloud、Qiniu Cloud の 3 種類の実装が組み込まれていますが、対応するコンパイルマクロが使用されている場合のみコンパイルに参加します。
