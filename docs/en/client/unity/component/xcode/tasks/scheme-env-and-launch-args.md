# Configuring Run Environment Variables and Launch Arguments

In `XCodeConfig.json`, you can configure the Run Scheme's environment variables and launch arguments for the generated Xcode project through the top-level fields `environmentVariables` (XcScheme environment variables, where both keys and values are strings) and `launcherArgs` (XcScheme launch argument list). After the build completes, `PostProcessBuildHelper` automatically writes them into `Unity-iPhone.xcscheme`, so there is no need to modify Xcode manually.

## Prerequisites

- The `com.gameframex.unity.xcode` package is installed in the project (Unity iOS platform).
- `Unity-iPhone.xcodeproj` exists in the build output directory (i.e., an iOS build has already been completed).
- The configuration file is named `XCodeConfig.json`; it can be placed anywhere in the project, and multiple files can coexist (automatically merged).

## Steps

1. Create or open `XCodeConfig.json` anywhere in the project.
2. Add the two top-level fields `environmentVariables` and `launcherArgs`:

```json
{
  "environmentVariables": {
    "IDEPreferLogStreaming": "YES",
    "OS_ACTIVITY_MODE": "disable"
  },
  "launcherArgs": ["-debug"]
}
```

3. Run the iOS build. After the build finishes, `PostProcessBuildHelper.OnPostprocessBuild` calls the following in order:

```csharp
// Launch environment variables
RunEnvironmentVariables(path, finalConfig.Get<Hashtable>("environmentVariables"));
// Run launch arguments
RunArgument(path, finalConfig.Get("launcherArgs") as ArrayList);
```

4. Open the generated Xcode project and go to `Product → Scheme → Edit Scheme → Run`; you will then see the written content under `Arguments Passed On Launch` and `Environment Variables`.

## Field Description

| Field | Type | Description |
| :--- | :--- | :--- |
| `environmentVariables` | object | XcScheme environment variables, where both keys and values are strings |
| `launcherArgs` | string[] | XcScheme launch argument list |

- Environment variables are written as `EnvironmentVariable` nodes, with `key`/`value` taken from the configuration, and `isEnabled="YES"` is always appended.
- Launch arguments are written one by one; whitespace-only strings are skipped.
- If either field is empty or missing, it is simply skipped without raising an error (the log outputs "参数为空或数据为空，跳过设置").

## Common Variants

- **Configure only launch arguments, without environment variables**: The two top-level fields are independent of each other, so you can provide just one of them:

```json
{
  "launcherArgs": ["-debug", "-stage"]
}
```

- **Merging multiple configuration files**: `XCodeConfig.json` files in different locations are merged automatically, so environment variables and launch arguments can be split across separate files for maintenance.
- **Common environment variable examples**: `IDEPreferLogStreaming=YES` (stream console log output) and `OS_ACTIVITY_MODE=disable` (disable system log output); the repository README uses these as examples.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The log outputs "[XcScheme-EnvironmentVariables] 参数为空或数据为空，跳过设置" | `environmentVariables` in the configuration is an empty object or missing | Verify that the top-level field is spelled `environmentVariables` and contains at least one key-value pair |
| The log outputs "[XcScheme-Argument] 参数为空或数据为空，跳过设置" | `launcherArgs` is an empty array or missing | Verify that the top-level field is spelled `launcherArgs` and is of array type |
| The exception "The xcscheme document does not contain build configuration setting" is thrown | The `LaunchAction` node does not exist in the scheme file | Verify that `Unity-iPhone.xcodeproj/xcshareddata/xcschemes/Unity-iPhone.xcscheme` in the build output directory is a valid scheme file exported by Unity |
| Environment variables/launch arguments are not visible in Xcode | The content is written to the Run Scheme's `LaunchAction` node | Check the Arguments tab under `Edit Scheme → Run`, not Build Configuration or another Scheme |

## Verification

- After building the Unity iOS package, check the Editor logs; you should see `设置项目[XcScheme-EnvironmentVariables]开始/结束` and `设置项目[XcScheme-Argument]开始/结束` appear in sequence.
- Open `Unity-iPhone.xcodeproj/xcshareddata/xcschemes/Unity-iPhone.xcscheme` in a text editor; under the `LaunchAction` node you should see nodes like the following:

```xml
<EnvironmentVariables>
  <EnvironmentVariable key="OS_ACTIVITY_MODE" value="disable" isEnabled="YES"/>
</EnvironmentVariables>
```

The corresponding source writing logic (excerpted from `AddEnvironmentVariablesPassedOnLaunch`):

```csharp
xElement?.Add(new XElement("EnvironmentVariable", new object[3]
{
    new XAttribute("key", key),
    new XAttribute("value", value),
    new XAttribute("isEnabled", "YES")
}));
```

## Background

`RunArgument` reads and writes the scheme file based on Unity's built-in `UnityEditor.iOS.Xcode.XcScheme` API; `RunEnvironmentVariables` parses the scheme XML directly with `XDocument`, finds or creates the `EnvironmentVariables` node under `LaunchAction`, and appends entries to it. The target file written by both is `Unity-iPhone.xcodeproj/xcshareddata/xcschemes/Unity-iPhone.xcscheme`.
