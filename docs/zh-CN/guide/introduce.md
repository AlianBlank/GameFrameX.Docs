# 什么是 GameFrameX？

**一句话：一套帮你把游戏「从点子 → 做出来 → 上线运营」全包圆的开源工具箱。**

它不是一个引擎，也不是一个编辑器——你在 Unity 里做游戏，GameFrameX 负责把你做游戏时**真正费劲的脏活累活**全部包掉。

## 它替你解决了什么麻烦？

做游戏（尤其是联网游戏），真正难的不是「画个角色、写个技能」，而是下面这些事：

| 你本来要自己折腾的事 | GameFrameX 直接给你准备好了 |
|---|---|
| 从零写一套联机服务器 | 现成的高性能服务器（.NET 写的，能扛多人同时在线） |
| 玩家存档存哪儿、怎么读出来 | 玩家数据存 MongoDB，读写快、自动落库 |
| Excel 配置手动搬进代码 | 用 LuBan 一键把 Excel 变成代码和数据 |
| 客户端和服务器「对暗号」 | 用 ProtoBuf 统一协议，改一处、两端同步 |
| 上线后两眼一抹黑 | 自带管理后台网页，看数据 / 管玩家 / 发配置 |
| 部署服务器头大 | 用 Docker 一键打包部署 |

> 说白了：**一个人也能像一个小团队那样，把一款联网游戏做出来、并且运营下去。**

## 支持哪些引擎？

客户端支持 **Unity、Cocos Creator、LayaAir（LayaBox）、Godot**——你用哪个，它都吃得下。本教程以最常用的 **Unity** 为主线。

## 里面都有什么技术？

你不需要现在就搞懂下表每一项，混个眼熟即可，后面用到时再回头查：

| 技术 | 在项目里干什么 | 什么时候会接触到 |
|------|--------------|----------------|
| .NET 10 | 编写和运行游戏服务器 | 环境准备就要装 |
| MongoDB | 存玩家数据（账号、角色、背包……） | 第一步跑数据库就用到 |
| Docker | 一条命令把 MongoDB 跑起来 | 第一步跑数据库就用到 |
| LuBan | Excel 配置表 → 代码 + 数据 | 改数值、加道具时用到 |
| ProtoBuf | 客户端 ↔ 服务器的通讯协议 | 加新消息时用到 |
| FairyGUI | 做 UI 界面 | 改界面时用到 |
| HybridCLR | C# 代码热更新（不发版也能改逻辑） | 进阶内容 |
| YooAsset | 资源管理和热更下载 | 进阶内容 |

## 适合谁用？

- 想做**联网 / 网游**、但被「服务器怎么搞」卡住的独立开发者
- 想快速搭个**游戏原型**验证点子的小团队
- 想完整学一遍「客户端 + 服务器 + 后台」全流程的学习者

## 完全开源吗？

服务器、客户端框架、配置和协议工具全部开源（Apache 协议）。管理后台 GameFrameX.Admin 部分源码不开源，但有[在线演示](https://game.admin.web.vue.alianblank.com)可以先看效果。
