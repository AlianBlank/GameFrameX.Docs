# 如何讀寫設計配置表（Tables）

閱讀本頁後，您將掌握 GameFrameX 中所有設計配置表（`TbAchievementConfig`、`TbItemConfig`、`TbSoundsConfig`、`TbLocalization`）的統一入口 `TablesComponent`，以及載入配置表、按主鍵查詢、迭代、條件搜尋與參照解析的完整使用模式。

## 前置條件

- 專案中已參考 `GameFrameX.Config` 組件，並已產生對應的設計配置表檔案。
- 已建構 `ConfigComponent`，作為 `TablesComponent.Init` 的參數。
- 準備一個 `Func<string, Task<JsonElement>>` 類型的載入器（常見實作是從本地檔案或遠端來源下載 JSON 資料並將其解析為 `JsonElement`）。

## 操作步驟

### 1. 初始化並非同步載入所有配置表

`TablesComponent` 會並行載入每張表。載入完成後會自動呼叫 `Refresh()`，其內部會觸發 `PostInit()` 與 `ResolveRef()`（用於跨表參照解析）。

```csharp
using GameFrameX.Config;
using System.Text.Json;
using System.Threading.Tasks;

// 由呼叫方實作，例如根據資源名稱回傳 JSON 內容
async Task<JsonElement> Loader(string name)
{
    var bytes = await File.ReadAllBytesAsync($"Configs/{name}.json");
    return JsonDocument.Parse(bytes).RootElement.Clone();
}

var configComponent = new ConfigComponent();
var tables = new TablesComponent();
tables.Init(configComponent);
await tables.LoadAsync(Loader);
```

載入完成後，即可透過 `tables.TbAchievementConfig`、`tables.TbItemConfig`、`tables.TbSoundsConfig` 與 `tables.TbLocalization` 存取每張表。

來源：[TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L56)

### 2. 按主鍵讀取單筆記錄

所有表皆基於 `BaseDataTable<T>`，支援整數主鍵與字串主鍵兩種索引方式。讀取失敗時的預設回傳值為 `null`。

```csharp
// 按整數主鍵讀取
var item = tables.TbItemConfig[1001];
if (item != null)
{
    Console.WriteLine(item.Name);
}

// 按長整數主鍵讀取（當主鍵定義為 long 時使用）
var ach = tables.TbAchievementConfig[100001L];

// 按字串主鍵讀取（常用於本地化表）
var loc = tables.TbLocalization["ui.btn.confirm"];
```

在內部，`this[id]` 本質上就是 `TryGet(id, out var v) ? v : null`，當找不到鍵時不會擲回例外。

來源：[BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L110-L180)

### 3. 使用 TryGet 安全讀取並區分「未命中」

如果您想避免取得 `null` 而無法區分是配置缺失還是業務邏輯問題，可以使用 `TryGet` 來取得 `bool` 回傳值：

```csharp
if (tables.TbSoundsConfig.TryGet(2005, out var sound))
{
    // sound 是有效資料
}
else
{
    // 配置缺失，提示策劃填表
}
```

針對字串鍵還有一個 `TryGet(string id, out T value)` 多載。其簽章可在 `IDataTable<T>` 介面中找到。

來源：[BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L138-L141)

### 4. 迭代、統計與條件查詢

`BaseDataTable<T>` 提供 LINQ 風格的常用操作，內部基於 `DataList` 實作：

| 操作 | 方法簽章 | 用途 |
|------|---------|------|
| 取得數量 | `int Count { get; }` | 快取結果；重複呼叫不會重新計算 |
| 取得第一筆 | `T FirstOrDefault { get; }` | 回傳排序後的第一筆資料 |
| 取得最後一筆 | `T LastOrDefault { get; }` | 回傳排序後的最後一筆資料 |
| 全部資料陣列 | `T[] All { get; }` / `T[] ToArray()` / `List<T> ToList()` | 取得副本 |
| 按條件查詢一筆 | `T Find(Func<T, bool> func)` | 找不到時回傳 `null` |
| 按條件查詢多筆 | `T[] FindListArray(Func<T, bool> func)` / `List<T> FindList(...)` | 取得陣列或列表 |
| 迭代執行 | `void ForEach(Action<T> func)` | 邊迭代邊處理 |
| 投影最大值/最小值 | `Tk Max<Tk>(Func<T, Tk>)` / `Tk Min<Tk>(...)` | 取得某欄位的極值 |

以下是一個典型的「按類型查詢物品」範例：

```csharp
// 查詢所有 Type == 2 的物品（假設代表消耗品）
var consumables = tables.TbItemConfig.FindListArray(x => x.Type == 2);
Console.WriteLine($"Consumable count: {consumables.Length}");

// 取得所有獎勵配置中的最大 Id
var maxRewardId = tables.TbAchievementConfig.Max(x => x.Id);
```

來源：[BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L189-L329)

### 5. 重新整理表格（熱重載）

當需要重新載入設計表時，只需再次呼叫 `LoadAsync`：

```csharp
await tables.LoadAsync(Loader); // 並行重新載入每張表並觸發 Refresh()
```

`Refresh()` 會依序執行 `PostInit()` 與 `ResolveRef()`，重新建立跨表參照。

來源：[TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L73)

## 常見變體

### 讀取本地化多語言資料

`TbLocalization` 來自 `GameFrameX.Config.Local` 命名空間，以字串鍵作為索引。其用法與其他表完全一致：

```csharp
var key = "ui.title.home";
if (tables.TbLocalization.TryGet(key, out var loc))
{
    Console.WriteLine(loc.Content);
}
```

### 重新初始化載入器

`Init` 會先呼叫 `configComponent.RemoveAllConfigs()` 清除舊的註冊。因此，如果您想切換整個資料來源，只需再次呼叫 `Init`，然後呼叫 `LoadAsync`：

```csharp
tables.Init(newConfigComponent);
await tables.LoadAsync(newLoader);
```

來源：[TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

## 常見錯誤

- **在 `LoadAsync` 完成前讀取**：在 `LoadAsync` 完成之前，`TbAchievementConfig` 等屬性持有的是預設參照。從預設值讀取會得到 `null` 或空集合。務必使用 `await tables.LoadAsync(Loader);`。
- **混淆整數與長整數主鍵**：當主鍵定義為 `long` 時，傳入 `int` 多載會觸發隱含轉換但可能發生溢位；當主鍵定義為 `int` 時，也不要使用 `long` 多載，因為語意不一致。
- **跨表參照未重新整理**：`PostInit()` / `ResolveRef()` 由 `Refresh()` 觸發。在繞過 `LoadAsync` 的自訂場景中，參照欄位可能為 `null`。
- **使用索引子存取時字串鍵拼寫錯誤**：當找不到鍵時，`this[string id]` 會靜默回傳 `null`。建議先用 `TryGet` 檢查會更安全。
- **直接修改 `BaseDataTable` 公開的 `LongDataMaps` / `StringDataMaps`**：它們是 `protected`，但透過反射修改會破壞後續熱重載的冪等性。請改用 `LoadAsync` 重新載入路徑。

## 背景說明（選讀）

`TablesComponent` 由配置表產生器自動產生（帶有 `<auto-generated>` 標頭）。它會將每張 `Tb*` 表註冊到 `ConfigComponent`，並在載入完成後透過 `Refresh()` 完成參照解析。`BaseDataTable<T>` 將查找、迭代、條件查詢與彙總等常用能力抽象到基底類別中。每張具體表只負責自身的 JSON 解析與主鍵映射。

關於 `ConfigComponent` 的整體組裝，請參考 `GameFrameX.Config` 命名空間下的相關原始碼。每張 `Tb*` 表的欄位定義由設計配置表產生器基於 Excel/JSON 資料自動產生。
