# サーバーへの接続:チャネルの作成とチャネルヘルパーの実装(TCP/WebSocket)

ネットワークチャネルを作成するには、`NetworkComponent.CreateNetworkChannel(channelName, networkChannelHelper)` を呼び出し、`INetworkChannelHelper` を実装したチャネルヘルパーを渡すだけです。フレームワークはコンパイルマクロに基づいて基盤となる実装を自動的に選択します。WebGL/WebSocket マクロが有効な場合は `WebSocketNetworkChannel` を、それ以外の場合は `SystemTcpNetworkChannel` を使用します。

## 前提条件

- シーンに `NetworkComponent` がアタッチされていること(名前空間 `GameFrameX.Network.Runtime`)。
- トランスポート方式が確定していること:デフォルトはシステム TCP です。WebSocket が必要な場合は、マクロ `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` または `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` を有効にする必要があります。
- チャネルヘルパークラスを準備していること(フレームワーク付属の `DefaultNetworkChannelHelper` をそのまま使用するか、そのインターフェースに従って独自に実装します)。

## 操作手順

1. チャネルヘルパーを準備します。フレームワーク付属の [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L13) は `INetworkChannelHelper` のすべてのメンバーを実装しており、そのまま再利用することも、カスタムヘルパーのテンプレートとして使用することもできます:

   | メンバー | シグネチャ(DefaultNetworkChannelHelper から) | 説明 |
   |------|------|------|
   | `SetChannelSerializer` | `void SetChannelSerializer(IMessageSerializer serializer)` | チャネルレベルのメッセージシリアライザーを設定します。`Initialize` の前に呼び出す必要があります |
   | `Initialize` | `void Initialize(INetworkChannel netChannel)` | チャネルへの参照を保存し、リフレクションで各ハンドラーを登録、ネットワークイベントを購読します |
   | `PrepareForConnecting` | `void PrepareForConnecting()` | 接続前に Socket の送受信バッファを `1024 * 64 - 1` に設定します |
   | `SendHeartBeat` | `bool SendHeartBeat()` | `PacketHeartBeatHandler` を使用してハートビートパケットを構築して送信します |
   | `SerializePacketHeader<T>` | `bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject` | チャネルの `PacketSendHeaderHandler` に委譲します |
   | `SerializePacketBody` | `bool SerializePacketBody(byte[] messageBodyBuffer, MemoryStream destination)` | チャネルの `PacketSendBodyHandler` に委譲します |
   | `DeserializePacketHeader` | `bool DeserializePacketHeader(byte[] source)` | チャネルの `PacketReceiveHeaderHandler` に委譲します |
   | `DeserializePacketBody` | `bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` | チャネルの `PacketReceiveBodyHandler` に委譲します |
   | `Clear` | `void Clear()` | チャネルを閉じ(`NetworkCloseReason.Dispose` / `NetworkErrorCode.DisposeError`)、参照をクリアします |

2. (オプション)ヘルパーにチャネルレベルのシリアライザーを設定します。チャネルの初期化(`Initialize`)より前に呼び出す必要があります。そうでない場合、例外がスローされる点に注意してください:

   ```csharp
   public void SetChannelSerializer(IMessageSerializer serializer)
   {
       if (m_NetworkChannel != null)
       {
           throw new InvalidOperationException(
               "SetChannelSerializer must be called before Initialize().");
       }
       m_ChannelSerializer = serializer;
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L32-L40)

3. `NetworkComponent.CreateNetworkChannel` を呼び出してチャネルを作成します。`channelName` は空にできません。タイムアウト時間にはコンポーネントの `m_rpcTimeout` が使用され、ログを無視するメッセージ Id のリストも自動的に適用されます:

   ```csharp
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
       networkChannel.SetIgnoreLogNetworkIds(m_IgnoredSendNetworkIds, m_IgnoredReceiveNetworkIds);
       return networkChannel;
   }
   ```

   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L176-L182)

4. TCP / WebSocket はコンパイルマクロによって自動的に選択され、実行時に切り替えることはできません。選択ロジックは `NetworkManager.CreateNetworkChannel` にあります:

   ```csharp
   #if (ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL) || FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET
       NetworkChannelBase networkChannel = new WebSocketNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #else
       NetworkChannelBase networkChannel = new SystemTcpNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #endif
   ```

   Source: [NetworkManager.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.cs#L220-L224)

   2つの基盤実装はいずれも `NetworkChannelBase : INetworkChannel, IDisposable` のシールドされた派生クラスで、それぞれ [NetworkManager.SystemTcpNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/SystemSocket/NetworkManager.SystemTcpNetworkChannel.cs#L45) と [NetworkManager.WebSocketNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/WebSocket/NetworkManager.WebSocketNetworkChannel.cs#L48) にあります。

5. チャネルの初期化時、ヘルパーはリフレクションでアセンブリをスキャンし、対応するインターフェースを実装したハンドラーをチャネルに自動登録します(受信ヘッダー、受信ボディ、送信ヘッダー、送信ボディ、ハートビート、圧縮、解凍)。そのため、カスタムハンドラーは対応するインターフェースを実装するだけで済みます:

   ```csharp
   if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
   {
       var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
       m_NetworkChannel.RegisterHandler(handler);
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L86-L90)

6. 返された `INetworkChannel` を通じて対象サーバーに接続し、イベントコンポーネントで接続/クローズ/ハートビートロスト/エラーの4種類のイベントを購読します。ヘルパーは `Initialize` 内ですでに購読しており、`NetworkComponent` がそれらをグローバルイベントとして転送します:

   ```csharp
   Event.CheckSubscribe(NetworkConnectedEventArgs.EventId, OnNetworkConnectedEventArgs);
   Event.CheckSubscribe(NetworkClosedEventArgs.EventId, OnNetworkClosedEventArgs);
   Event.CheckSubscribe(NetworkMissHeartBeatEventArgs.EventId, OnNetworkMissHeartBeatEventArgs);
   Event.CheckSubscribe(NetworkErrorEventArgs.EventId, OnNetworkErrorEventArgs);
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128)

7. 不要になった場合はチャネルを破棄します:

   ```csharp
   public bool DestroyNetworkChannel(string channelName)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       return m_NetworkManager.DestroyNetworkChannel(channelName);
   }
   ```

   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L190-L194)

## よくあるバリエーション

- **デフォルトヘルパーの直接再利用**：ほとんどのプロジェクトでは、`CreateNetworkChannel("main", new DefaultNetworkChannelHelper())` を直接呼び出し、あわせて `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler` / `IPacketSendHeaderHandler` / `IPacketSendBodyHandler` / `IPacketHeartBeatHandler` / `IMessageCompressHandler` / `IMessageDecompressHandler` を実装したハンドラークラスを用意するだけで済みます。登録はリフレクションによって自動的に行われます。
- **WebSocket への切り替え**:Player Settings でマクロ `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` を追加します(WebGL 以外のプラットフォームで WebSocket を強制使用)。または `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` を使用します(WebGL プラットフォーム)。
- **複数チャネルの併存**：異なるサーバー/ゲートウェイに対して複数のチャネルを作成し、それぞれに独立した名前の `channelName` とヘルパーインスタンスを渡します。`NetworkComponent.GetAllNetworkChannels()` ですべてのチャネルを取得できます([NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L154-L157) を参照)。

## よくあるエラー

| 症状/エラーメッセージ | 原因 | 回避方法 |
|------|------|------|
| `SetChannelSerializer must be called before Initialize().` | `SetChannelSerializer` が、チャネルの初期化(`Initialize` によってチャネルがヘルパーに割り当てられた後)より後に呼び出されている | 先に `SetChannelSerializer` を呼び出してから、作成/初期化を実行する |
| チャネル作成時に引数検証例外がスローされる | `channelName` が空または null である | 空でないチャネル名を渡す(`GameFrameworkGuard.NotNullOrEmpty`) |
| WebSocket を使いたいのに TCP が使用される | 現在のマクロが WebSocket 分岐に該当していない | マクロ `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` または `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` が有効になっていることを確認する |
| シリアライズ時に `GameFrameworkGuard.NotNull` がスローされる | チャネルに `PacketSendHeaderHandler` / `PacketSendBodyHandler` がまだ登録されていない | リフレクションによる登録が行えるよう、対応するハンドラークラスが存在し、該当するインターフェースを実装していることを確認する |

## 検証

- `CreateNetworkChannel` が null でない `INetworkChannel` インスタンスを返した場合、チャネルの作成に成功しています。
- `Initialize` のブレークポイントまたはログで、`IPacketReceiveHeaderHandler`、`IPacketSendBodyHandler` などが `RegisterHandler` によって登録されていることを確認します。
- `NetworkConnectedEventArgs` イベントを受信した場合は接続成功を示します。`NetworkErrorEventArgs`、`NetworkClosedEventArgs` は失敗原因の確認に使用できます。

## 背景

チャネルヘルパー(`INetworkChannelHelper`)は、チャネルと具体的なパケットフォーマット間のアダプター層です。送信時にはメッセージを `IPacketSendHeaderHandler` / `IPacketSendBodyHandler` に渡してパケットを組み立て、受信時には `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler` を介して `MessageObject` に分解します。ハートビート、圧縮、解凍も登録されたハンドラーを通じて行われます。トランスポート層(TCP または WebSocket)は `NetworkManager.CreateNetworkChannel` 内でコンパイルマクロによって決定され、ビジネスコードはそれを意識しません。
