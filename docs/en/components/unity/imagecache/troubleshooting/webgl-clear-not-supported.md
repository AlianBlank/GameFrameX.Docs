# What to Do When RemoveCache / ClearCache Doesn't Work on WebGL Platform

On the WebGL platform, calling `RemoveCache(url)` or `ClearCache()` will not actually clear any cache, but will only output a warning log, because the WebGL runtime cannot directly access the local file system.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| After calling `RemoveCache(url)`, the image is still being hit | On WebGL, images are cached by the browser's HTTP cache; there is no local copy inside the framework to delete | Use browser-side cache control instead (add version number to URL / Cache-Control header) |
| After calling `ClearCache()`, disk space doesn't change | On WebGL, there is no concept of "disk cache"; the method returns immediately | Clear it on the browser side; only call `ClearCache` on non-WebGL platforms |
| When calling `RemoveCache` / `ClearCache`, see warning `ImageCache: RemoveCache is not supported on WebGL.` or `ImageCache: ClearCache is not supported on WebGL.` in Console | The WebGL platform code branch explicitly disables this operation | Wrap with `#if !UNITY_WEBGL` before calling, or use browser-side solutions |

## Fix Steps

### 1. Confirm That the Platform Branch Is Expected Behavior

In the source code, both `RemoveCache` and `ClearCache` return a warning directly through `#if UNITY_WEBGL`:

```csharp
public void RemoveCache(string url)
{
    if (string.IsNullOrEmpty(url)) { return; }

#if UNITY_WEBGL
    Log.Warning("ImageCache: RemoveCache is not supported on WebGL.");
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    if (FileHelper.IsExists(cachePath))
    {
        FileHelper.Delete(cachePath);
    }
#endif
}

public void ClearCache()
{
#if UNITY_WEBGL
    Log.Warning("ImageCache: ClearCache is not supported on WebGL.");
#else
    if (!Directory.Exists(_config.CachePath)) { return; }
    FileHelper.CleanDirectory(_config.CachePath);
#endif
}
```

In other words: On WebGL, `RemoveCache` / `ClearCache` **are not broken**, but are disabled at the source code level. Any attempt to "clear local cache" will not work.

### 2. Avoid Calling These Two Methods on WebGL

If your code runs across platforms, use conditional compilation to skip the call:

```csharp
public void OnUserClickClearCache()
{
#if !UNITY_WEBGL
    GameFrameX.ImageCache.Runtime.ImageCacheManager.Instance.ClearCache();
#endif
}
```

### 3. Perform an "Equivalent" Clear on WebGL

On the WebGL platform, images are loaded by `UnityWebRequestTexture`, and the cache is managed by the browser. To prevent "old images" from being hit, common practices are:

1. **Add a version number or hash to the URL**: Change the URL query parameters after each resource update (e.g., `?v=2`), and the browser will treat it as a new resource request.
2. **Have the server return appropriate `Cache-Control` headers** to control expiration time on the browser side.
3. **Call the browser-side `Caching.ClearCache()` (browser's own storage cleanup API)** — this component does not handle that path.

### 4. Also Confirm `IsCached` Behavior

On WebGL, `IsCached(url)` also always returns `false` because the framework doesn't hold a cached copy internally; don't use it to determine the hit status on WebGL:

```csharp
public bool IsCached(string url)
{
    if (string.IsNullOrEmpty(url)) { return false; }

#if UNITY_WEBGL
    return false;
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    return FileHelper.IsExists(cachePath);
#endif
}
```

## Verification

- After calling `ClearCache()` on Editor or Standalone platforms, the PNG files in the cache directory (`ImageCacheConfig.CachePath`) should be cleared.
- When calling `ClearCache()` in a WebGL build, the Console should show the warning `ImageCache: ClearCache is not supported on WebGL.`, and no IO errors — indicating that the expected branch was taken.
- After changing URL query parameters on WebGL following fix step 3 and reloading, confirm that the browser fetched the new resource (the old image is no longer being hit).

## Background (Optional)

The WebGL sandbox doesn't have a real concept of "local disk", and `System.IO` is trimmed on this platform. Therefore, `ImageCacheManager` goes directly through `UnityWebRequestTexture` on the WebGL branch, leaving the cache to the browser; correspondingly, `IsCached` / `RemoveCache` / `ClearCache` don't hold any cleanable local copies either, so they all take the early-exit path of "returning false / outputting a warning".
