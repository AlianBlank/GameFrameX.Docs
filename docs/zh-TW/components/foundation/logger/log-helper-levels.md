# 使用 LogHelper 輸出各等級日誌的方法

`LogHelper` 是位於 `GameFrameX.Foundation.Logger` 命名空間中的靜態類別，基於 Serilog 提供 Debug / Verbose / Info / Warning / Error / Fatal 六個等級的日誌輸出方式。支援結構化模板、主控台輸出以及例外記錄。閱讀本頁後，您將能在自己的程式碼中依等級輸出符合規範的日誌。

## 前置條件

- .NET 專案需參照 `GameFrameX.Foundation.Logger` 組件(Serilog 會以遞移相依性的形式自動納入)。
- 請在應用程式啟動的早期階段，透過 `LogHelper.SetLogger(...)` 注入已設定好的 `Serilog.ILogger`。否則 `LogHelper` 會使用內建的 `InternalTempLogger` 暫存日誌，待正式記錄器可用時再沖刷輸出。

## 操作步驟

### 1. 初始化記錄器

```csharp
using GameFrameX.Foundation.Logger;
using Serilog;

var logger = new LoggerConfiguration()
    .MinimumLevel.Verbose()      // 將可輸出的最低等級設定為 Verbose
    .WriteTo.Console()
    .CreateLogger();

LogHelper.SetLogger(logger);
```

來源： [LogHelper.cs#L101-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L101-L112)

### 2. 呼叫對應等級的方法

六個等級的進入點方法與等級名稱直接對應，命名與簽章保持一致：`(string messageTemplate, ...)` 或 `(object message)`,內部會將處理委派給底層 `ILogger` 的同名方法。

```csharp
using GameFrameX.Foundation.Logger;

// 除錯 / 詳細資訊
LogHelper.Verbose("起動フェーズ:設定 {ConfigName} を読み込み中", configName);
LogHelper.Debug("ユーザー {Id} がキャッシュにヒット", userId);

// 一般資訊
LogHelper.Info("ログイン成功 user={Id} ip={Ip}", userId, ip);
LogHelper.Info(loginResult);

// 警告
LogHelper.Warning("API {Api} の応答時間 {Ms}ms が閾値を超えました", apiName, elapsed);

// 錯誤
LogHelper.Error("注文失敗 orderId={Id}", orderId);

// 致命
LogHelper.Fatal("データベース接続が切断されました {Conn}", connectionString);
```

來源： [LogHelper.Info.cs#L48-L76](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L48-L76)、[LogHelper.Debug.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Debug.cs)、[LogHelper.Verbose.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Verbose.cs)、[LogHelper.Warning.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Warning.cs)、[LogHelper.Error.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Error.cs)、[LogHelper.Fatal.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Fatal.cs)

### 3. 記錄包含例外的錯誤 / 致命日誌

`Error` / `Fatal` 的多載支援 `Exception` 參數，可將例外物件寫入日誌事件：

```csharp
try
{
    DoWork();
}
catch (Exception ex)
{
    LogHelper.Error(ex, "実行失敗 task={Name}", taskName);
    // 或使用 Fatal 等級
    LogHelper.Fatal(ex, "致命的エラー task={Name}", taskName);
}
```

來源： [LogHelper.Error.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Error.cs)、[LogHelper.Fatal.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Fatal.cs)

### 4. 僅輸出至主控台

在不需要寫入檔案、也不需要經過 Serilog 的情境下，請使用 `LogHelper.Console`。它會附帶毫秒級時間戳記，直接寫入 `System.Console`:

```csharp
LogHelper.Console("サーバー起動中...");
LogHelper.Console("リソース {Count} 個を読み込み、所要時間 {Ms}ms", count, ms);
```

來源： [LogHelper.Console.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Console.cs)、[LogHelper.cs#L145-L156](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L145-L156)

### 5. 在應用程式結束前沖刷緩衝區

程式結束前請呼叫 `FlushAndSave()` 或 `CloseAndFlushAsync()`,將緩衝區內的日誌寫出至檔案：

```csharp
LogHelper.FlushAndSave();
// 或
await LogHelper.CloseAndFlushAsync();
```

來源： [LogHelper.cs#L56-L70](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L56-L70)

## 六等級速查表

| 等級 | 方法 | 典型用途 | Serilog 對應方法 |
|------|------|----------|------------------|
| Verbose | `LogHelper.Verbose(...)` | 最細粒度的追蹤資訊、迴圈內的詳細輸出 | `ILogger.Verbose` |
| Debug | `LogHelper.Debug(...)` | 除錯階段的診斷資訊，發行版通常關閉 | `ILogger.Debug` |
| Info | `LogHelper.Info(...)` | 業務流程的重要節點(登入、下單、退出) | `ILogger.Information` |
| Warning | `LogHelper.Warning(...)` | 可復原的異常、閾值警示、優雅降級 | `ILogger.Warning` |
| Error | `LogHelper.Error(...)` / `Error(Exception, ...)` | 業務邏輯失敗、已捕捉的例外 | `ILogger.Error` |
| Fatal | `LogHelper.Fatal(...)` / `Fatal(Exception, ...)` | 程序層級的致命錯誤、無法復原 | `ILogger.Fatal` |

## 常見變化用法

- **結構化屬性模板**：各等級備有 1 至 8 個泛型多載，可將物件(而非以字串串接的方式)直接繫結為屬性，便於下游 Sink 進行欄位檢索：
  ```csharp
  LogHelper.Info<Player>("現在のプレイヤー {Current}", player);
  LogHelper.Info<Player, int>("プレイヤー {Current} が {Kills} 体撃破", player, kills);
  ```
  來源： [LogHelper.Info.cs#L87-L216](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L87-L216)

- **物件引數**：傳入 `object` 時，`Info` 會呼叫 `ToString()`;若為 `null`,則記錄字串 `"null object"`:
  ```csharp
  LogHelper.Info(someObject); // 當 someObject 為 null 時輸出 "null object"
  ```
  來源： [LogHelper.Info.cs#L48-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L48-L51)

- **零引數模板**：僅提供訊息模板、不帶格式化值時，等同於直接輸出字串。

## 常見錯誤

| 現象 | 原因 | 處理方式 |
|------|------|------|
| `LogHelper.Info(...)` 沒有任何輸出 | 未呼叫 `LogHelper.SetLogger(...)`,且 `MinimumLevel` 未允許該等級通過 | 於啟動時注入 Logger,並為除錯設定 `MinimumLevel.Verbose()` |
| 程序結束時日誌遺失 | 未呼叫 `FlushAndSave()` / `CloseAndFlushAsync()` | 在 `OnExit` / `Main` 結尾處呼叫上述任一方法 |
| 模板中的 `{Name}` 未被值取代 | 字串中使用多餘的佔位符，或引數數量不一致 | 使用 Serilog 標準模板語法 `{Property}`,並讓引數數量與佔位符一致 |
| 想知道日誌檔案的寫入位置 | 目前的方法未直接公開路徑，需自行設定 Serilog Sink | 以 `LoggerConfiguration().WriteTo.File(...)` 自行指定 |
| 記錄 `null` 物件時會當機 | 僅 `Info(object)` 提供 `ToString()` 後備處理；其他等級的 `null` 處理依賴 Serilog | 使用字串模板版本，或自行進行 null 檢查 |

## 背景(選讀)

`LogHelper` 是 `public static partial class`,各等級的方法配置於獨立的檔案(如 `LogHelper.Debug.cs`),全部透過 `GetLogger()` 取得目前的 `Serilog.ILogger`。若尚未呼叫 `SetLogger`,會使用內部的 `InternalTempLogger` 暫存日誌，並在正式記錄器注入時透過 `FlushTo` 轉送，因此**即使初始化順序不在第一次日誌呼叫之前也沒有問題**。等級越往下越詳細；正式環境通常將 `MinimumLevel` 設為 `Information`,除錯時再降至 `Debug` 或 `Verbose`。關於 Serilog 的整體整合，請參閱《透過 LogHandler 初始化設定日誌系統的方法》。
