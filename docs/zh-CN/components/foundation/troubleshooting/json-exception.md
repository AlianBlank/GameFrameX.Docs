# JSON 序列化异常与反序列化失败怎么办

当 `JsonHelper.Serialize`、`Deserialize` 或 `TryDeserialize` 抛出异常、返回 `false`、或返回结果不符合预期时,按本页诊断表对号入座,根据具体异常消息选择对应的修复步骤。`JsonHelper` 提供的 `Try*` API 与 `JsonHelperError` 可在不抛异常的情况下告诉你错误分类,优先使用它们定位问题。

## 快速诊断

| 症状(异常或结果) | 原因 | 修复 |
|------|------|------|
| `ArgumentNullException` 抛出,`obj` / `json` / `options` 之一为 null | 调用 `Serialize`、`Deserialize` 时传入了空参数 | 跳到 [入参为 null 或空](#修复-1入参为-null-或空字符串) |
| `ArgumentException`,提示 `null/empty/whitespace` | JSON 是空字符串或只有空白字符 | 跳到 [入参为 null 或空](#修复-1入参为-null-或空字符串) |
| `JsonException` 反序列化失败,包含 `The JSON value could not be converted` | JSON 有效但字段类型与目标 C# 类型不匹配 | 跳到 [类型不匹配](#修复-2json-有效但与目标类型不匹配) |
| 序列化结果中枚举显示为数字(0/1/2),对方反序列化报 `JsonException` | 没有使用 `DefaultOptions` / `FormatOptions`,枚举按数值写出 | 跳到 [枚举与属性名不匹配](#修复-3枚举值或属性名称不匹配) |
| 字段名 `UserName`/`username`/`user_name` 来回转换后丢失 | 调用方使用了自定义 `JsonSerializerOptions` 或 `PropertyNamingPolicy`,与 `DefaultOptions` 不一致 | 跳到 [枚举与属性名不匹配](#修复-3枚举值或属性名称不匹配) |

| UTF-8 流上 `SerializeAsync` 抛 `ArgumentNullException`,`stream` 为 null | 没传 `Stream` 或传了已释放的流 | 跳到 [流与字节数组](#修复-8流与字节数组操作) |

## 修复步骤

### 修复 1:入参为 null 或空字符串

`JsonHelper` 的 `Serialize` / `Deserialize` / `TryDeserialize` 都会先做参数校验。`Serialize` 在 `obj` 为 null 时直接抛 `ArgumentNullException`;`Deserialize` 在 `json` 为 null / 空 / 纯空白时抛 `ArgumentNullException` 或 `ArgumentException`。`TryDeserialize` 不会抛,而是返回 `false` 并附带 `JsonHelperError`。

```csharp
using GameFrameX.Foundation.Json;

// 反序列化时先校验字符串
if (string.IsNullOrWhiteSpace(json))
{
    return; // 或抛出业务异常
}

var user = JsonHelper.Deserialize<User>(json);
```

```csharp
using GameFrameX.Foundation.Json;

// 推荐:使用 TryDeserialize 避免异常开销
if (JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    // 成功
}
else if (error.Kind == JsonHelperErrorKind.InvalidInput)
{
    // 入参不合法
}
```

### 修复 2:JSON 有效但与目标类型不匹配

典型表现:`JsonException` 包含 `The JSON value could not be converted to <type>` 或 `is not a valid value for <type>`。常见原因有:

- 字段是 `int` 但 JSON 里是字符串 `"123"`(若未开启 `AllowReadingFromString` 会失败,`DefaultOptions` 已开启)。
- 字段是 `DateTime` 但 JSON 里是 `"2024-01-01T00:00:00Z"` 且时区不匹配。
- 字段是 `Guid`,但 JSON 里是空字符串或缺失引号。
- 多态类型:JSON 是子类,父类字段没有 `[JsonDerivedType]` 元数据。

修复建议:

1. 确认使用 `JsonHelper.DefaultOptions`(已开启 `PropertyNameCaseInsensitive`、`AllowReadingFromString`、`AllowNamedFloatingPointLiterals`、`AllowTrailingCommas`)。
2. 把可疑的 JSON 单独粘贴到 `JsonHelper.Deserialize<Dictionary<string, object>>(json)` 验证语法是否合法。
3. 对 `DateTime`/`Guid`/`decimal` 这类容易出问题的字段,在 DTO 上显式标注 `[JsonConverter]` 或确保字符串格式正确。
4. 多态类型加上 `[JsonDerivedType(typeof(SubType), "sub")]` 并在 JSON 中带 `"$type"` 字段。

```csharp
// 多态类型示例
[JsonPolymorphic(TypeDiscriminatorPropertyName = "$type")]
[JsonDerivedType(typeof(Dog), "dog")]
[JsonDerivedType(typeof(Cat), "cat")]
public abstract class Animal { public string Name { get; set; } }

public class Dog : Animal { public string Breed { get; set; } }
```

### 修复 3:枚举值或属性名称不匹配

`JsonHelper.DefaultOptions` 内置 `JsonStringEnumConverter`,把枚举序列化为字符串(例如 `"Active"` 而不是 `0`)。如果你自定义了 `JsonSerializerOptions` 而没有添加这个转换器,枚举会被写成数字。

同样,`DefaultOptions` 设置了 `PropertyNameCaseInsensitive = true` 与 `PropertyNamingPolicy = null`(保持原属性名)。如果你自己 new 一份 options,这两个开关默认是 false,就会按 `PascalCase` 严格匹配 JSON 里的字段名。

修复:

- 始终通过 `JsonHelper.DefaultOptions` 或 `JsonHelper.CreateDefaultOptions()` 生成配置;
- 不要在 `DefaultOptions` 上再设置 `PropertyNamingPolicy`,否则写入端会改变大小写。

```csharp
using GameFrameX.Foundation.Json;

// 推荐写法
var opts = JsonHelper.CreateDefaultOptions();
var json = JsonHelper.Serialize(obj, opts);

// 反序列化同样使用 DefaultOptions 或 CreateDefaultOptions()
var restored = JsonHelper.Deserialize<MyDto>(json, opts);
```

### 修复 4:循环引用

直接调用 `System.Text.Json.JsonSerializer.Serialize` 默认会抛 `InvalidOperationException`(`A possible object cycle was detected`)。`JsonHelper.DefaultOptions` 已设置 `ReferenceHandler = ReferenceHandler.IgnoreCycles`,遇到循环引用会直接跳过成 `$ref` 之类的占位。

修复:始终通过 `JsonHelper` 入口进行序列化,不要绕过去直接调 `JsonSerializer.Serialize(obj)`。

```csharp
using GameFrameX.Foundation.Json;

// 正确:循环引用会被自动处理
var json = JsonHelper.Serialize(order); // order -> user -> orders -> ...

// 错误:会抛 InvalidOperationException
var raw = System.Text.Json.JsonSerializer.Serialize(order);
```

### 修复 5:NaN / Infinity 等特殊浮点值

如果 JSON 来自 Python(`json.dumps(... allow_nan=True)`)或 JavaScript,可能含 `NaN` / `Infinity` / `-Infinity`。`System.Text.Json` 默认会抛 `JsonException`。`JsonHelper` 在 `Deserialize<T>` 中做了兜底:捕获异常后调用 `PreprocessSpecialFloatingPointValues` 预处理字符串,再重试。

如果你的代码直接调 `JsonSerializer.Deserialize` 而不经过 `JsonHelper`,或解析后还要再 `Deserialize` 一次其他片段,异常仍会复现。统一走 `JsonHelper.Deserialize<T>(json)` 即可。

```csharp
using GameFrameX.Foundation.Json;

// Python 输出: NaN / Infinity 会被 JsonHelper 自动处理
var json = "{\"x\": NaN, \"y\": Infinity}";
var obj = JsonHelper.Deserialize<MyDto>(json); // 不会抛异常
```

### 修复 6:字段被忽略或反序列化为默认值

可能原因:

- 属性是 `private set` / `init` 且没有 `[JsonInclude]`。
- 属性是 `required`,但 JSON 缺字段。
- 属性是 `record` 主构造函数参数,但缺少 `[JsonConstructor]`。
- 属性标记了 `[JsonIgnore]`。
- 字段是字典 / 集合但 JSON 是数组(或反之)。

修复:确认 DTO 属性可写、可被反射读取;对不可变类型添加 `[JsonConstructor]`;不要给业务字段加 `[JsonIgnore]`。

### 修复 7:使用 TryDeserialize 定位错误

`TryDeserialize` 永远不会抛异常,会通过 `JsonHelperError` 告诉你:

| `Kind` | 含义 | 建议处理 |
|--------|------|----------|
| `None` | 未发生错误 | 正常路径 |
| `InvalidInput` | JSON 本身语法错误、null、空字符串,或 options 为 null | 检查入参,用 `JsonSerializer.Deserialize<JsonElement>` 验证 JSON 语法 |
| `TypeMismatch` | JSON 合法,但字段类型对不上 | 跳到 [类型不匹配](#修复-2json-有效但与目标类型不匹配) |
| `Serialization` | 序列化阶段失败(对象→JSON) | 检查 DTO 是否有不可序列化的成员(指针、COM 对象等) |
| `Unknown` | 未分类错误,通常是运行时其他异常 | 读取 `ExceptionType` 与 `Message`,查看 `Path` / `LineNumber` 定位问题 |

`JsonHelperError` 还提供 `Path`、`LineNumber`、`BytePositionInLine`,可以直接定位到 JSON 的具体位置:

```csharp
using GameFrameX.Foundation.Json;

if (!JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    Console.WriteLine($"Kind={error.Kind}, Type={error.ExceptionType.Name}");
    Console.WriteLine($"Message={error.Message}");
    Console.WriteLine($"Path={error.Path}, Line={error.LineNumber}, Pos={error.BytePositionInLine}");
}
```

### 修复 8:流与字节数组操作

`SerializeAsync(Stream, ...)` 在 `stream` 为 null 时会抛 `ArgumentNullException`(`ArgumentNullException.ThrowIfNull(stream, nameof(stream))`)。如果写入的目标流已 `Dispose`,同样会失败。

```csharp
using System.IO;
using GameFrameX.Foundation.Json;

await using var ms = new MemoryStream();
await JsonHelper.SerializeAsync(ms, user); // OK
var bytes = ms.ToArray();

// 如果用 FileStream,先确认目录存在、文件可写
await using var fs = File.Create("user.json");
await JsonHelper.SerializeAsync(fs, user);
```

## 验证

按以下顺序验证问题已解决:

1. `TryDeserialize` 返回 `true`,且 `error.Kind == JsonHelperErrorKind.None`。
2. 反序列化后的对象字段值与 JSON 中字符串/数字一致(可打印出来核对)。
3. 序列化后再反序列化是同一个对象(`JsonHelper.Serialize(obj) → JsonHelper.Deserialize<T>(...) == obj` 的关键字段相等)。
4. 对可能失败的入参(空字符串、异常 JSON、含 NaN 的字符串)分别跑一遍,确认不会抛异常。

如果仍然失败,把 `JsonHelperError` 中的 `Path`、`LineNumber`、`Message` 一并贴到工单里,可以快速定位。
