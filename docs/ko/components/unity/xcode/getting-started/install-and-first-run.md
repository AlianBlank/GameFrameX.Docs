# 설치 및 첫 실행

GameFrameX Xcode 설정은 Unity Package입니다. 설치 후 어떤 C# 코드도 작성할 필요 없이 프로젝트에 `XCodeConfig.json` 하나만 배치하면, iOS 빌드가 끝날 때 Info.plist, 서명, Capabilities, CocoaPods 등 Xcode 프로젝트 수정이 자동으로 완료됩니다. 이 페이지에서는 패키지 설치부터 첫 번째 전체 프로세스 실행까지 안내합니다.

## 빠른 시작

### 1. 패키지 설치

아래 방식 중 하나를 선택하세요(버전을 통일 관리하기 쉬운 scopedRegistries 권장):

**방법 1: Scoped Registry(버전 지정 가능)** — `Packages/manifest.json`을 편집합니다:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.xcode": "1.11.1"
  }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L47-L63)

`scopes`는 어떤 패키지가 이 레지스트리를 통해 해석되는지 제어합니다: `com.gameframex`로 시작하는 패키지만 이 레지스트리에서 가져옵니다.

**방법 2: Git URL** — `manifest.json`의 `dependencies` 노드에 추가합니다:

```json
{
   "com.gameframex.unity.xcode": "https://github.com/gameframex/com.gameframex.unity.xcode.git"
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L67-L72)

**방법 3: Package Manager** — Unity의 `Package Manager`에서 `Git URL` 방식으로 추가하며, 주소는 위와 동일합니다.

**방법 4: 저장소 직접 다운로드** Unity 프로젝트의 `Packages` 디렉터리에 배치하면 자동으로 로드되어 인식됩니다.

환경 요구 사항: Unity 2019.4 이상.

### 2. 설정 파일 생성

설정 파일은 **반드시 `XCodeConfig.json`으로 명명해야 하며**, 프로젝트의 아무 위치에나 배치할 수 있습니다. 여러 파일의 동시 존재를 지원하며, 빌드 시 자동으로 깊은 병합이 수행됩니다(다중 모듈 협업에 적합). 채널별로 구분해야 하는 경우 `XCodeConfig.{채널명}.json`을 추가로 생성할 수 있으며, 채널 설정이 마지막에 병합되어 우선순위가 가장 높습니다.

최상위 구조는 다음과 같습니다:

```json
{
  "swiftBridging": true,
  "signing": {},
  "plist": {},
  "environmentVariables": {},
  "launcherArgs": [],
  "podSource": [],
  "podfile": "",
  "podInstall": true,
  "localizations": [],
  "capabilities": {},
  "unityFramework": {},
  "unityMain": {}
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L79-L96)

최소 동작 예시(Bitcode 비활성화 + plist 항목 하나 작성 + 시스템 프레임워크 하나 추가):

```json
{
  "plist": { "NSCameraUsageDescription": "用于拍摄头像" },
  "unityMain": {
    "properties": { "=": { "ENABLE_BITCODE": "NO" } },
    "frameworks": { "+": [ "WebKit.framework" ], "-": [] }
  }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L145-L173)

자주 사용하는 최상위 필드 요약:

| 필드 | 유형 | 설명 |
| :--- | :--- | :--- |
| `swiftBridging` | bool | Swift 브리징 헤더 파일 자동 생성(기본값 `true`) |
| `signing` | object | 코드 서명 설정(Team ID, Bundle Identifier 등) |
| `plist` | object | Info.plist 키-값 쌍, 값은 모든 타입 지원 |
| `capabilities` | object | iOS 앱 기능(인앱 결제, 푸시, iCloud 등) |
| `podfile` / `podInstall` | string / bool | 커스텀 Podfile 경로 / `pod install` 자동 실행 여부(기본값 `true`) |
| `unityMain` / `unityFramework` | object | 각각 Unity-iPhone과 UnityFramework target 설정에 해당 |

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L98-L111)

### 3. iOS 빌드 및 검증

1. Unity에서 플랫폼을 iOS로 전환한 후 빌드를 실행합니다(File → Build Settings → Build).
2. 빌드가 끝나면 도구가 자동으로 `[PostProcessBuild(888)]` 콜백에서 실행됩니다 — 대부분의 다른 후처리 스크립트보다 늦게 실행되며, `BuildTarget.iOS`에서만 작동합니다:

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        //설정 파일 읽기
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 일치하는 파일을 찾지 못한 경우 바로 반환
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }
```

출처: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L32)

3. Unity Console 로그를 확인합니다. 아래와 같은 출력이 보이면 설치가 성공하고 프로세스가 정상적으로 완료된 것입니다:
   - `[MergeConfig] 설정 병합 중: <XCodeConfig.json 경로>`
   - `[PBXProject] 최종 병합 설정 적용 중...`
   - `[OtherSettings] 최종 병합 설정 적용 중...`
4. 생성된 Xcode 프로젝트를 열어 결과를 확인합니다: Info.plist에 구성한 키가 나타나고, Build Settings에서 `ENABLE_BITCODE`가 `NO`로 변경되었는지 등.

출처: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L38-L107)

로그에 `未找到任何 XCodeConfig 相关配置文件, 跳过设置`가 나타나면 파일 이름이 `XCodeConfig.json`이 아니거나(대소문자 구분) 프로젝트 디렉터리 내에 없다는 뜻입니다. 이름을 변경하거나 이동한 후 다시 빌드하면 됩니다.

## 일반적인 변형

- **다중 모듈 다중 설정**: 각 모듈이 자체적으로 `XCodeConfig.json`을 배치하면 빌드 시 파일 순서대로 깊은 병합이 수행됩니다. 동일한 키는 '나중에 병합되는 쪽이 덮어씁니다'.
- **채널 차별화**: `SettingLoader.GetChannel()`으로 채널을 감지하고, `XCodeConfig.{channel}.json`을 읽어 마지막에 병합하여 덮어씁니다. 관련 로직은 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)를 참조하세요.
- **pod install 건너뛰기**: `"podInstall": false`로 설정하면 자동 `pod install` 실행을 건너뛸 수 있습니다. 커스텀 Podfile이 있는 경우 `"podfile": "<경로>"`로 지정합니다(`pods` 필드보다 우선순위가 높음). [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156)를 참조하세요.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| Console에 `未找到任何 XCodeConfig 相关配置文件, 跳过设置` 오류 발생 | 파일 이름이 `XCodeConfig.json`이 아니거나 프로젝트 디렉터리 내에 없음 | 대소문자를 구분하여 정확히 `XCodeConfig.json`으로 명명한 후 다시 빌드 |
| Console에 `<路径> 解析失败, 跳过合并` 오류 발생 | JSON 문법 오류 | JSON 검증 도구로 확인한 후 수정하고 다시 빌드 |
| Console에 `合并后的配置为空，跳过设置` 오류 발생 | 파일은 존재하지만 내용이 빈 객체 | 최소한 하나의 유효한 필드 작성 |
| 빌드 후 Xcode 프로젝트에 변화 없음 | 빌드 대상이 iOS가 아니거나 콜백에서 발생한 예외가 무시됨 | BuildTarget이 iOS인지 확인; Console에 `Debug.LogException`으로 출력된 예외 스택 트레이스가 있는지 확인 |

위 오류 메시지는 모두 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83)의 실제 로그 원문에서 가져온 것입니다.

## 검증

1. Console에 `[MergeConfig]` → `[PBXProject]` → `[OtherSettings]` 세 단계의 로그가 나타나며, 빨간색 Error가 없어야 합니다.
2. Xcode로 빌드 출력 디렉터리를 열고 다음을 확인합니다: Info.plist에 `plist` 설정 항목이 작성되었는지, Build Settings가 `properties` 설정과 일치하는지, `podfile`/`pods`를 구성한 경우 프로젝트 디렉터리에 Podfile이 생성되고 의존성이 설치되었는지.

## 배경

도구는 두 단계로 나뉘어 작성을 수행합니다: 첫 번째 단계에서는 빌드 속성, 프레임워크, 라이브러리, 파일 복사, 컴파일 플래그 등을 `Unity-iPhone`과 `UnityFramework` 두 target에 적용하고 `project.pbxproj`를 저장합니다. 두 번째 단계에서는 Plist, 환경 변수, 런처 인자, Capabilities, 현지화 및 CocoaPods를 처리하며, Capabilities를 별도로 디스크에 기록한 후 프로젝트 파일을 다시 읽어 해당 수정 사항을 보존합니다. Swift 브리징은 기본적으로 활성화되어 있으며, 메인 프로젝트에만 서명과 Capabilities를 설정합니다. 전체 구현은 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)를 참조하세요.

관련 페이지: 설정 파일의 전체 필드 설명은 저장소 내 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L75-L229)를 참조하세요.
