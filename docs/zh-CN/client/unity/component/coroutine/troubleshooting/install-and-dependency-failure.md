# 安装与依赖解析失败怎么办

当你在 Unity 中通过 Package Manager 或 `manifest.json` 引入 `com.gameframex.unity.coroutine` 时遇到依赖报错、版本冲突、找不到包等情况,可按本页诊断表对照修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `Package 'com.gameframex.unity.coroutine' could not be found` 或找不到对应版本 | `manifest.json` 没配置 `scopedRegistries`,Unity 默认只在 npm registry 查找 `com.gameframex.*` 开头的包 | 在 `manifest.json` 顶部添加 `scopedRegistries` 并指定 GameFrameX 源,见下文修复步骤 1 |
| 报错 `Unable to resolve dependency 'com.gameframex.unity: 2.5.1'` | 缺少运行时依赖 `com.gameframex.unity`,或版本与已安装的其他 GameFrameX 包不一致 | 先单独升级或回退到包要求的 `com.gameframex.unity` 版本(见 `package.json` 中的依赖) |
| Unity 报 `Requires Unity 2019.4 or higher` | 当前工程 Unity 版本低于包要求的最低版本 | 升级 Unity 到 2019.4 或更高,或使用与之匹配的旧版本包 |
| 包已下载但编译报 `The type or namespace 'GameFrameX' could not be found` | Unity 缓存未刷新、依赖未真正写入 `Library/PackageCache` | 删除 `Library/PackageCache` 与 `Packages/packages-lock.json` 后重启 Unity |
| 用 Git URL 安装报 `Could not read Username for 'https://github.com'` | 网络无法访问 GitHub 或私有仓库鉴权失败 | 改用 UPM scoped registry 方式,或为本仓库配置 SSH/HTTPS 凭据 |
| 包导入成功但 `CoroutineComponent` 报 `[DisallowMultipleComponent]` 冲突 | 同一 GameObject 已经挂过 `CoroutineComponent` | 删除多余的同类型组件,只保留一个 |

## 修复步骤

### 1. 配置 scopedRegistries(GameFrameX 官方源)

打开工程根目录下的 `Packages/manifest.json`,确认存在 `scopedRegistries` 节。下面的示例来自仓库 README 的安装说明:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.coroutine": "1.0.3"
  }
}
```

Source: [README.zh-CN.md#快速开始](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L40-L77)

要点:
- `scopes` 必须写 `com.gameframex`,否则 `com.gameframex.*` 包不会被该源解析,Unity 会回退到 npm 默认源,直接报“找不到包”。
- `url` 是 UPM 注册表地址,不是普通网页;如果你的网络无法访问,继续看下文“用 Git URL 备选方案”。

### 2. 检查运行时依赖 `com.gameframex.unity`

`com.gameframex.unity.coroutine` 自身依赖 `com.gameframex.unity`,仓库 [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L22-L24) 中声明:

```json
"dependencies": {
  "com.gameframex.unity": "2.5.1"
}
```

如果工程中已显式声明了更低版本的 `com.gameframex.unity`,Unity 会拒绝解析。处理:
- 升级 `com.gameframex.unity` 到 `2.5.1` 或与之兼容的更高版本;或
- 删除显式声明,让 `com.gameframex.unity.coroutine` 自动带上正确版本。

### 3. Unity 版本必须 ≥ 2019.4

`package.json` 中 `unity` 字段为 `2019.4`:

```json
"version": "1.2.0",
"unity": "2019.4",
```

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L6-L7)

低于 2019.4 的工程在 Package Manager 中会直接显示“Requires Unity 2019.4 or higher”,必须先升级 Unity 编辑器。

### 4. 必要时清缓存并重启

当包明明已声明但编译报错、命名空间缺失时,先做这一步:
1. 关闭 Unity。
2. 删除工程目录下 `Library/PackageCache` 文件夹。
3. 删除 `Packages/packages-lock.json`。
4. 重新打开 Unity,让它按 `manifest.json` 重新拉取。

### 5. 备选安装方式(用于 GitHub 不可达)

- 在 `manifest.json` 的 `dependencies` 下直接写 Git URL:

```json
{
  "dependencies": {
    "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L70-L75)

- 或在 Unity 的 `Package Manager` → `Add package from git URL…` 中粘贴 `https://github.com/gameframex/com.gameframex.unity.coroutine.git`。
- 或将仓库下载后直接放到工程 `Packages/` 目录下。

## 验证

修复后用下面任一方式确认:

1. 看 Unity Console:不再出现 “could not be found / Unable to resolve dependency” 这类报错。
2. 在 Inspector 中 `Add Component` 能搜索到 `Coroutine Component`,并能成功添加到 GameObject。
3. 用最小代码片段验证命名空间可用:

```csharp
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(yourEnumerator);
```
