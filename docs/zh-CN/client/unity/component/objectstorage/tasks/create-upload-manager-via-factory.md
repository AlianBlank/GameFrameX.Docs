# 如何使用工厂创建上传管理器

使用 `ObjectStorageUploadFactory.Create<T>` 静态方法，可以基于 `IObjectStorageUploadManager` 接口类型快速得到一个**已初始化**的上传管理器实例，无需手动 `new` 和调用 `Init`。

## 前置条件

- 引用 `GameFrameX.ObjectStorage.Editor` 命名空间
- 已有一个实现 `IObjectStorageUploadManager` 接口的具体类 `T`（可直接继承 [BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)）
- 准备好对象的 `accessKey`、`secretKey`、`bucketName`；若对象存储需要自定义地址，再准备 `endpoint`

## 操作步骤

1. 引入命名空间。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L1-L25)

2. 调用 `Create<T>` 静态工厂方法，传入凭据并拿到已初始化的管理器。

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create<MyObjectStorageUploadManager>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: null
   );
   ```

   工厂内部会执行两步操作：

   ```csharp
   var manager = Activator.CreateInstance<T>();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   return manager;
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. （可选）设置上传的目标路径。

   ```csharp
   uploader.SetSavePath("assets/uploads/");
   ```

   Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9)

4. 调用上传方法上传单个文件或整个目录。

   ```csharp
   bool ok = uploader.UploadFile("D:/build/asset.bundle");
   uploader.UploadDirectory("D:/build");
   ```

   Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L15-L21)

## 关键签名速查

| 成员 | 签名 | 说明 |
|------|------|------|
| `ObjectStorageUploadFactory.Create<T>` | `static IObjectStorageUploadManager Create<T>(string accessKey, string secretKey, string bucketName, string endpoint = null) where T : IObjectStorageUploadManager` | 通过 `Activator.CreateInstance<T>()` 创建实例并立即调用 `Init` |
| `IObjectStorageUploadManager.SetSavePath` | `void SetSavePath(string savePath)` | 设置上传到对象存储中的目标路径（自动去掉末尾分隔符） |
| `IObjectStorageUploadManager.UploadFile` | `bool UploadFile(string localFilePathAndName)` | 上传单个文件，成功返回 `true` |
| `IObjectStorageUploadManager.UploadDirectory` | `void UploadDirectory(string localDirectory)` | 上传整个目录 |

## 常见变体

- **不传入 endpoint**：对于不需要地址的对象存储，`endpoint` 留空即可。参数默认值为 `null`，无需显式传入。
- **自定义实现类**：若不直接继承 [BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)，只要类实现 `IObjectStorageUploadManager` 即可作为 `T` 传入；需自己实现 `Init`、`UploadDirectoryInternal`、`UploadFileInternal`。

## 常见错误

- **未实现接口就传入**：若 `T` 没有实现 `IObjectStorageUploadManager`，编译器会在 `where T : IObjectStorageUploadManager` 处直接报错。
- **重复初始化**：工厂已经调用过 `Init`，无需再手动调用一次，否则可能覆盖已设置的凭据。
- **`endpoint` 误传**：部分对象存储使用 `endpoint` 拼接请求地址，传错会导致上传失败；不需要时保持 `null`。

## 背景

工厂模式把"创建实例 + 初始化"封装成一步，调用方只关心传入凭据与最终接口，避免直接依赖具体实现类。关于整体架构，见《概述》。
