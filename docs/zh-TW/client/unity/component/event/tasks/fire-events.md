# 如何觸發事件：Fire、FireNow 與無參數事件

在 GameFrameX.Event 中觸發事件只需呼叫 `EventComponent` 上的 `Fire`（執行緒安全、下一幀主執行緒回呼）、`FireNow`（立即同步分發）或 `Fire(sender, eventId)`（無需自訂事件參數的捷徑）三者之一。本文提供三種用法的完整步驟、適用情境與常見陷阱。

## 前置條件

- 場景中已存在 GameFrameX 入口，`EventComponent` 隨框架自動掛載（元件選單為 `GameFrameX/Event`，見 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)）。
- 已經有人訂閱了對應的事件 ID，否則觸發後無人接收（可配合預設處理器兜底，見下文「常見變體」）。

## 操作步驟

1. 取得事件元件參考（掛在你的 MonoBehaviour 上或從框架入口取得）：

   ```csharp
   using GameFrameX.Event.Runtime;

   private EventComponent eventComponent;
   // 在 Awake/Start 中：
   // eventComponent = GameEntry.GetComponent<EventComponent>();
   ```

2. 準備事件參數類別（繼承 `GameEventArgs`，提供 `Create` 工廠與 `Clear`/回收約定）：

   ```csharp
   public class LevelUpEventArgs : GameEventArgs
   {
       public int Level { get; private set; }
       public static LevelUpEventArgs Create(int level) { /* ... */ }
   }
   ```

3. 延遲模式觸發（預設推薦，執行緒安全）——事件在拋出後的下一幀於主執行緒回呼：

   ```csharp
   eventComponent.Fire(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L124-L128)

   對應的元件 API 簽名：

   ```csharp
   // 拋出事件，這個操作是執行緒安全的，即使不在主執行緒中拋出，
   // 也可保證在主執行緒中回呼事件處理函式，但事件會在拋出後的下一幀分發。
   public void Fire(object sender, GameEventArgs e)
   {
       m_EventManager.Fire(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L150)

4. 立即模式觸發（僅在主執行緒使用）——事件立刻同步分發，呼叫回傳前處理器已執行完畢：

   ```csharp
   eventComponent.FireNow(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L130-L134)

   ```csharp
   // 拋出事件立即模式，這個操作不是執行緒安全的，事件會立刻分發。
   public void FireNow(object sender, GameEventArgs e)
   {
       m_EventManager.FireNow(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

5. 觸發完成後可觀察分發結果。三種方式對比：

   | API | 分發時機 | 執行緒安全 | 典型用途 |
   |-----|---------|---------|---------|
   | `Fire(object, GameEventArgs)` | 下一幀、主執行緒 | 是 | 預設選擇；子執行緒/非同步任務中拋事件 |
   | `FireNow(object, GameEventArgs)` | 立即、同步 | 否 | UI 點擊等主執行緒即時回應、需要讀到「事件已處理完」的後續狀態 |
   | `Fire(object, string)` | 下一幀、主執行緒 | 是 | 無參數通知（內部用 `EmptyEventArgs` 包裝） |

## 常見變體

**無參數事件（捷徑）**：不想為一次性通知定義參數類別時，直接傳字串 ID，元件內部會用 `EmptyEventArgs.Create(eventId)` 包裝後再走 `Fire`，並先對 `eventId` 做非空驗證：

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

```csharp
eventComponent.Fire(this, "level_up");
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L136-L140)

**子執行緒觸發**：在執行緒池、Task 或網路回呼中拋事件時必須用 `Fire`，它會保證回呼發生在主執行緒（下一幀），因此回呼裡可以直接存取 Unity API。

**無人訂閱時兜底**：觸發一個沒有訂閱者的 ID 不會報錯，但可設定預設處理器用於排查「事件發了沒人接」：

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L142-L151)（API 位於 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L133-L140)）

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| `Fire` 之後當幀讀不到處理結果 | `Fire` 是延遲分發，下一幀才回呼 | 當幀需要結果時改用 `FireNow` |
| 子執行緒裡呼叫 `FireNow` 後回呼行為異常 | `FireNow` 不是執行緒安全的 | 子執行緒一律用 `Fire` |
| 觸發後處理器內拿到的資料不對/為空 | 參數物件被回收複用或未正確 `Create` | 每次觸發都呼叫參數類別的 `Create(...)`，不要快取舊實例 |
| 事件發了沒有任何反應 | 目標 ID 無人訂閱 | 用 `eventComponent.Check(id, handler)` 或 `Count(id)` 排查，必要時設定預設處理器觀察 |
| `Fire(sender, eventId)` 拋出參數驗證例外 | `eventId` 為 null 或空字串 | 保證傳入非空的字串 ID（`GameFrameworkGuard.NotNullOrEmpty` 驗證） |

## 驗證

- 在處理器內輸出日誌確認收到事件：`Debug.Log($"升级到 {args.Level} 级")`（範例見 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L102-L106)）。
- 用統計屬性交叉檢查：`eventComponent.EventHandlerCount` / `eventComponent.EventCount` / `eventComponent.Count("level_up")`（見 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) 與 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L153-L159)）。

## 背景

`EventComponent` 只是薄封裝，實際邏輯在 `IEventManager`（`EventManager`）裡；`Fire` 藉助事件池的佇列在下一幀主執行緒統一分發，因此執行緒安全；`FireNow` 跳過佇列直接同步呼叫處理器。關於事件訂閱與取消訂閱，見《如何訂閱與取消訂閱事件》。
