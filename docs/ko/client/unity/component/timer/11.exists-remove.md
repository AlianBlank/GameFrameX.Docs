# 작업 확인 및 제거

Timer 타이머 컴포넌트에서 타이머 작업을 추가하는 것 외에도, 작업 존재 여부 확인 및 작업 제거 기능이 제공됩니다. 이러한 기능은 타이머 작업을 동적으로 관리하고, 중복 추가를 피하거나 특정 조건에서 작업을 취소하는 데 매우 유용합니다.

## 개요

TimerComponent는 작업 확인 및 제거를 위한 두 가지 핵심 메서드를 제공합니다:

- **Exists** - 지정 콜백 함수에 해당하는 작업이 존재하는지 확인
- **Remove** - 지정 콜백 함수에 해당하는 작업 제거 (취소)

이 두 메서드는 모두 콜백 함수의 참조(`Action<object>`)를 사용하여 작업을 식별 및 조작하므로, 전달된 위임 인스턴스가 동일해야 합니다.

## 핵심 기능

### 작업 존재 여부 확인

`Exists` 메서드는 지정 콜백 함수에 해당하는 타이머 작업이 유효한지 확인하는 데 사용됩니다.

```csharp
public bool Exists(Action<object> callback)
```

**구현 원리:**

> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L226-L243)

```csharp
public bool Exists(Action<object> callback)
{
    lock (Locker)
    {
        // 첫 번째 단계: 대기 추가 목록 확인
        if (_toAdd.ContainsKey(callback))
        {
            return true;
        }

        // 두 번째 단계: 활성 작업 목록 확인
        if (_items.TryGetValue(callback, out var at))
        {
            // 삭제 표시되지 않은 작업만 존재하는 것으로 간주
            return !at.Deleted;
        }

        return false;
    }
}
```

**확인 로직 설명:**

1. **대기 추가 목록 (`_toAdd`)**: 작업이刚刚 생성되었지만 아직 효력이 없는 대기 추가 대기열에 있는지 확인
2. **활성 작업 목록 (`_items`)**: 작업이 현재 활성 작업 목록에 있는지 확인
3. **삭제 표시 (`Deleted`)**: 삭제 표시된 작업은 딕셔너리에서 아직 제거되지 않았더라도 true 반환 안 함

### 지정 작업 제거

`Remove` 메서드는 지정 타이머 작업을 제거(취소)하는 데 사용됩니다. 이 메서드는 지연 삭제 메커니즘을 채택하며, 즉시 딕셔너리에서 제거하지 않고 다음 프레임 Update에서 정리합니다.

```csharp
public void Remove(Action<object> callback)
```

**구현 원리:**

> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L249-L264)

```csharp
public void Remove(Action<object> callback)
{
    lock (Locker)
    {
        // 작업이 아직 대기 추가 대기열에 있으면 즉시 취소 및 객체 풀에 반환
        if (_toAdd.TryGetValue(callback, out var t))
        {
            _toAdd.Remove(callback);
            ReturnToPool(t);
        }

        // 작업이 활성 목록에 있으면 Deleted로 표시
        if (_items.TryGetValue(callback, out t))
        {
            t.Deleted = true;
        }
    }
}
```

**제거 로직 설명:**

1. **대기 추가 대기열**: 작업이 아직 실행되지 않았으면 (아직 `_toAdd`에 있으면) 대기열에서 직접 제거 및 객체 풀에 반환
2. **활성 목록**: 작업이 활성 목록에서 실행 중이면 `Deleted = true`로 표시
3. **지연 정리**: 다음 프레임 `Update()` 루프에서 Deleted로 표시된 모든 작업이 자동으로 정리됨

## 사용 예시

### 기본 사용법

```csharp
using GameFrameX.Timer.Runtime;
using UnityEngine;

public class TimerExample : MonoBehaviour
{
    private TimerComponent _timer;

    private void Start()
    {
        _timer = GetComponent<TimerComponent>();

        // 콜백 메서드 정의
        void OnTick(object param)
        {
            Debug.Log($"Tick at {Time.time}");
        }

        // 타이머 작업 추가, 1초마다 실행
        _timer.Add(1.0f, 0, OnTick);

        // 작업 존재 여부 확인
        bool exists = _timer.Exists(OnTick);
        Debug.Log($"작업 존재 여부: {exists}"); // 출력: True

        // 작업 제거
        _timer.Remove(OnTick);

        // 다시 확인
        exists = _timer.Exists(OnTick);
        Debug.Log($"작업 존재 여부: {exists}"); // 출력: False
    }
}
```

> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L72-L89)

### 동적 작업 관리

실제 응용에서는 게임 상태에 따라 동적으로 작업을 추가 및 제거해야 할 수 있습니다:

```csharp
public class GameTimerManager : MonoBehaviour
{
    private TimerComponent _timer;
    private Action<object> _gameLoopTask;

    private void Start()
    {
        _timer = GetComponent<TimerComponent>();
        _gameLoopTask = OnGameLoop;
    }

    // 게임 일시 정지 시 루프 작업 중지
    public void PauseGame()
    {
        if (_timer.Exists(_gameLoopTask))
        {
            _timer.Remove(_gameLoopTask);
            Debug.Log("게임 루프 작업 일시 정지됨");
        }
    }

    // 게임 재개 시 루프 작업 다시 시작
    public void ResumeGame()
    {
        if (!_timer.Exists(_gameLoopTask))
        {
            _timer.AddUpdate(_gameLoopTask);
            Debug.Log("게임 루프 작업 재개됨");
        }
    }

    private void OnGameLoop(object param)
    {
        // 게임 루프 로직
    }
}
```

### 람다 식 주의 사항

람다 식을 사용할 때特别注意해야 합니다. 람다 식은 매번 새 위임 인스턴스를 생성하므로, 작업을 정확하게 일치시키고 제거할 수 없습니다:

```csharp
// ❌ 오류 예시: 람다 식이 매번 새 인스턴스 생성
_timer.Add(1.0f, 5, (param) => Debug.Log("Tick"));
_timer.Exists((param) => Debug.Log("Tick")); // false 반환, 다른 위임 인스턴스이기 때문
_timer.Remove((param) => Debug.Log("Tick"));  // 제거 불가, 다른 위임 인스턴스이기 때문

// ✅ 올바른 예시: 명명된 메서드 사용 또는 위임 참조 저장
Action<object> myTick = (param) => Debug.Log("Tick");
_timer.Add(1.0f, 5, myTick);
_timer.Exists(myTick);  // true 반환
_timer.Remove(myTick);   // 올바르게 제거
```

## 스레드 안전성

`Exists` 및 `Remove` 메서드는 모두 `lock (Locker)`를 사용하여 스레드 안전성을 보장합니다. TimerManager의 Update 메서드도 잠금 내에서 작업을 실행하므로, 이러한 메서드는 어떤 스레드에서도 안전하게 호출할 수 있습니다.

> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L38)

```csharp
private static readonly object Locker = new object();
```

## API 참고

### TimerComponent

#### `Exists(callback: Action<object>): bool`

지정 작업이 존재하는지 확인합니다.

**매개변수:**
- `callback` (`Action<object>`): 확인할 콜백 함수

**반환:** 
- `bool`: 작업이 존재하고 삭제 표시되지 않으면 true, 그렇지 않으면 false

#### `Remove(callback: Action<object>): void`

지정 작업을 제거합니다.

**매개변수:**
- `callback` (`Action<object>`): 제거할 콜백 함수

**설명:**
- 작업이 대기 추가 대기열에 있으면 즉시 제거됨
- 작업이 활성 목록에 있으면 삭제 표시되어 다음 프레임에서 정리됨

### ITimerManager

> Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L41-L52)

인터페이스 정의가 동일합니다:

```csharp
bool Exists(Action<object> callback);
void Remove(Action<object> callback);
```

## 자주 묻는 질문

### Remove 후 Exists가 여전히 true를 반환하는 이유는?

Remove 호출 후 Exists를 즉시 호출하면 여전히 true를 반환할 수 있습니다. 이유는:
1. 작업이 Deleted로 표시되었지만 아직 다음 프레임 Update에서 정리되지 않았음
2. 해결 방법: Remove 후 한 프레임 대기하거나 다른 메커니즘으로 확인

### 람다 식으로 작업을 일치시킬 수 없는怎么处理?

이전에 설명한 것처럼, 매번 람다 식이 새 위임 인스턴스를 생성합니다. 해결 방법은:
1. 명명된 메서드 대신 람다 사용
2. 위임 참조를 저장하고 재사용

### Remove를 여러 번 호출하면 문제가 발생합니까?

문제없습니다. Remove 메서드는 멱등 작업으로 설계되어 있어 여러 번 호출해도 오류가 발생하지 않습니다. 작업이 없으면 메서드가 자동으로 반환됩니다.
