# 如何做热更新:版本检查、清单更新与补丁下载

热更新由 `EPatchStates` 枚举定义的 5 个状态驱动:`UpdateStaticVersion`(更新静态资源版本)→ `UpdateManifest`(更新补丁清单)→ `CreateDownloader`(创建下载器)→ `DownloadWebFiles`(下载远端文件)→ `PatchDone`(补丁流程完毕)。本任务把"启动补丁 → 订阅状态变更 → 失败回滚 → 进入主流程"打通,让你在业务代码里跑通完整的热更链路。

## 前置条件

- 已通过 `GameFrameX.Runtime` 的 `GameEntry` 拿到 `AssetComponent` 实例(框架入口相关参见《快速开始》)。
- 远端服务器已经按 YooAsset 的目录结构部署好:根目录下的 `{platform}/{version}/{packageName}` 必须包含 `GameVersion.txt`、`{packageName}_PatchManifest_{version}.bytes`、`{packageName}_StaticVersion_{version}.bytes` 等文件。
- 项目里 `AssetPatchStatesChangeEventArgs` 等事件类型需要保留(代码里已带 `[UnityEngine.Scripting.Preserve]`,避免被裁剪)。

## 操作步骤

### 1. 订阅补丁状态变更事件

通过 `GameFrameX` 事件总线订阅 `AssetPatchStatesChangeEventArgs`,每进入下一个状态会收到回调,即可用来刷新进度条 UI。

```csharp
GameEntry.Event.Subscribe(AssetPatchStatesChangeEventArgs.EventId, OnPatchStatesChange);

private void OnPatchStatesChange(object sender, GameEventArgs e)
{
    var args = (AssetPatchStatesChangeEventArgs)e;
    // args.PackageName: 当前正在更新的资源包名
    // args.CurrentStates: EPatchStates 枚举(见下表)
    Debug.Log($"[{args.PackageName}] 进入阶段:{args.CurrentStates}");
}
```

Source: [AssetPatchStatesChangeEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchStatesChangeEventArgs.cs#L18-L46)

### 2. 订阅"发现待更新文件"与"下载进度"事件(可选但推荐)

这两个事件用来在 UI 上展示"共多少文件需要下载""当前下载到第几个/总共多大"。

| 事件 EventId | 事件参数 | 触发时机 | 关键字段 |
|---|---|---|---|
| `AssetFoundUpdateFilesEventArgs.EventId` | `AssetFoundUpdateFilesEventArgs` | CreateDownloader 之后、DownloadWebFiles 之前 | 待下载文件总数、总大小 |
| `AssetDownloadProgressUpdateEventArgs.EventId` | `AssetDownloadProgressUpdateEventArgs` | 每个文件下载过程中 | 当前进度、已下载/总大小、剩余大小 |

### 3. 订阅失败事件并处理回滚

热更过程中任何一步失败都会抛出对应的事件参数,需要在订阅处做重试或降级处理:

```csharp
GameEntry.Event.Subscribe(AssetStaticVersionUpdateFailedEventArgs.EventId, OnStaticVersionFailed);
GameEntry.Event.Subscribe(AssetPatchManifestUpdateFailedEventArgs.EventId, OnManifestFailed);
GameEntry.Event.Subscribe(AssetWebFileDownloadFailedEventArgs.EventId, OnFileDownloadFailed);
```

Source: [AssetStaticVersionUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetStaticVersionUpdateFailedEventArgs.cs) · [AssetPatchManifestUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchManifestUpdateFailedEventArgs.cs#L10-L25) · [AssetWebFileDownloadFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetWebFileDownloadFailedEventArgs.cs)

### 4. 启动热更新流程

调用 `AssetComponent` 提供的更新入口(实际签名请以当前仓库 `Runtime/Asset/AssetComponent.cs` 为准)。一次完整的补丁会话会按顺序进入下面五个状态:

```csharp
// 在 Boot 阶段(GameEntry 启动后)调用一次即可
var assetComponent = GameEntry.GetComponent<AssetComponent>();
assetComponent.UpdatePackages(); // 拉取版本号 → 比对清单 → 创建下载器 → 下载 → 回调 PatchDone
```

触发后,事件总线会按顺序广播:
1. `EPatchStates.UpdateStaticVersion` —— 对比远端 `GameVersion.txt` 与本地缓存版本。
2. `EPatchStates.UpdateManifest` —— 拉取 `{packageName}_PatchManifest_{version}.bytes` 与本地清单做差分。
3. `EPatchStates.CreateDownloader` —— 构造 `AssetDownloadProgressUpdateEventArgs` 等所需的下载器。
4. `EPatchStates.DownloadWebFiles` —— 真正下载差分文件;每个文件回调一次 `AssetDownloadProgressUpdateEventArgs`。
5. `EPatchStates.PatchDone` —— 流程结束,可以安全进入主场景。

Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L32)

## 常见变体

| 场景 | 做法 |
|---|---|
| 跳过检查直接用本地资源 | 调用 `AssetComponent` 的"仅本地"初始化重载,根本不进入 `UpdatePackages` |
| 只更新单个资源包 | 在 `UpdatePackages` 之前通过 `SetForceUpdateAllPackageVersions(true)` 之类开关控制范围 |
| 断点续传 | 事件 `AssetDownloadProgressUpdateEventArgs` 中保留已下载字节数,再次调用 `UpdatePackages` 时框架会自动续传未完成的文件 |

## 常见错误

| 症状 | 可能原因 | 规避 |
|---|---|---|
| `EPatchStates.PatchDone` 始终没触发 | 事件没订阅或订阅的 EventId 拼写错 | 用 `typeof(AssetPatchStatesChangeEventArgs).FullName` 作为 EventId,不要手写字符串 |
| 下载到一半无响应 | 没订阅 `AssetDownloadProgressUpdateEventArgs`,下载器可能被主线程等待 | 给下载器单独开异步上下文;UI 上显示进度 |
| 远端清单 404 | 服务器没部署 `{packageName}_PatchManifest_{version}.bytes` | 用框架自带上传工具(参见 YooAsset 官方 Builder)重新上传;事件 `AssetPatchManifestUpdateFailedEventArgs` 会带错误信息 |
| 静态版本文件下载失败 | 服务器缺 `{platform}/GameVersion.txt` 或缓存目录只读 | 检查 `Application.persistentDataPath` 写权限;监听 `AssetStaticVersionUpdateFailedEventArgs` |

## 背景(可选)

`EPatchStates` 把 YooAsset 的整套补丁生命周期抽象为 5 个枚举值,框架层只负责在状态切换时把 `AssetPatchStatesChangeEventArgs` 抛到 `GameFrameX` 事件总线,业务侧通过订阅 EventId 解耦。这样 UI、网络重试、降级策略都可以无侵入地替换,而补丁主流程保持稳定。
