# 启动器与启动项参考(Program.cs / AppStartUpGame)

这一页用于查阅游戏服务器启动入口及其默认启动项配置。`Program.cs` 定义进程入口与日志策略;`AppStartUpGame` 是游戏服启动项,负责按顺序初始化 Actor 限制、数据库、组件、热更新模块并进入主循环。

## 启动入口(Program.cs)

启动入口位于 `GameFrameX.Launcher` 程序集,`Main` 内部只做三件事:按编译模式设置日志选项、调用框架入口 `GameApp.Entry`、传入回调完成缓存与协议初始化。

```csharp
internal static class Program
{
    private static async Task Main(string[] args)
    {
#if DEBUG
        LogOptions.Default.IsConsole = true;
#endif
        await GameApp.Entry(args, () =>
        {
            CacheStateTypeManager.Init();
            MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
        }, LogAction);
    }

    private static void LogAction(LogOptions options)
    {
#if DEBUG
        options.IsConsole = true;
#else
        options.IsConsole = false;
#endif
    }
}
```

### 关键行为速查

| 项目 | 取值 / 行为 | 说明 |
|------|-------------|------|
| 入口方法 | `static async Task Main(string[] args)` | 标准 async Main,接收命令行参数 |
| DEBUG 编译 | `LogOptions.IsConsole = true` | 开发期控制台可见日志 |
| Release 编译 | `LogOptions.IsConsole = false` | 发布后控制台不输出 |
| 框架入口 | `GameApp.Entry(args, initAction, logAction)` | 启动 GameApp 运行时 |
| 初始化回调 | `CacheStateTypeManager.Init()` | 注册缓存状态类型 |
| 初始化回调 | `MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly)` | 扫描消息协议处理器所在程序集 |
| 日志回调 | `LogAction(LogOptions)` | 再次按编译模式覆盖 `IsConsole` |

## 启动项(AppStartUpGame)

`AppStartUpGame` 通过特性 `[StartUpTag(GameServerConst.Game.Name)]` 标注为 `Game` 类型服务器,并继承 `AppStartUpBase`。`StartAsync` 是启动主线,`Init` 用于按需构造默认 `AppSetting`。

```csharp
[StartUpTag(GameServerConst.Game.Name)]
internal sealed class AppStartUpGame : AppStartUpBase
{
    public override async Task StartAsync() { /* 见下表步骤顺序 */ }

    protected override void Init()
    {
        if (Setting == null)
        {
            Setting = new AppSetting { /* 默认值见下表 */ };
        }
        base.Init();
    }
}
```

Source: [GameFrameX.Launcher/StartUp/AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L41-L118)

### StartAsync 启动顺序

| 步骤 | 动作 | 关键调用 |
|------|------|----------|
| 1 | 准备 `hotfix` 目录 | `Directory.Exists` / `Directory.CreateDirectory` |
| 2 | 初始化 Actor 限制 | `ActorLimit.Init(ActorLimit.RuleType.None)` |
| 3 | 启动数据库服务 | `GameDb.Init<MongoDbService>(...)`,失败抛 `InvalidOperationException("数据库服务启动失败")` |
| 4 | 注册组件 | `ComponentRegister.Init(typeof(AppsHandler).Assembly)` |
| 5 | 加载热更新模块 | `HotfixManager.LoadHotfixModule(Setting)` |
| 6 | 标记运行时已启动 | `GameAppRuntime.MarkStarted(...)` |
| 7 | 等待退出信号 | `await AppExitToken` |
| 8 | 停止热更新 | `await HotfixManager.Stop(exitMessage)` |

异常路径:任意步骤抛出后会被 `catch (Exception e)` 捕获,记日志后进入第 8 步停止热更新再退出进程。

### 默认 AppSetting 字段

`Init()` 在 `Setting == null` 时构造默认 `AppSetting`,字段含义与默认值如下:

| 字段 | 类型/取值 | 默认值 | 含义 |
|------|-----------|--------|------|
| `ServerId` | `int` | `GameServerConst.Game.Id` | 服唯一 ID |
| `ServerType` | `string` | `GameServerConst.Game.Name` | 服类型名(对应 `[StartUpTag]`) |
| `IsEnableTcp` | `bool` | `true` | 启用 TCP |
| `InnerPort` | `int` | `29100` | 内部 TCP 端口 |
| `MetricsPort` | `int` | `29090` | 监控端口 |
| `IsEnableHttp` | `bool` | `true` | 启用 HTTP |
| `HttpPort` | `int` | `28080` | HTTP 端口 |
| `IsEnableWebSocket` | `bool` | `true` | 启用 WebSocket |
| `WsPort` | `int` | `29110` | WebSocket 端口 |
| `HttpIsDevelopment` | `bool` | `true` | HTTP 开发模式 |
| `MinModuleId` | `int` | `10` | 模块消息 ID 下限 |

## 常见错误

| 现象 | 触发条件 | 排查方向 |
|------|----------|----------|
| 启动抛 `InvalidOperationException: 数据库服务启动失败` | `GameDb.Init<MongoDbService>` 返回 `false` | 检查 `DataBaseUrl` / `DataBaseName` 是否可连通,以及 Mongo 网络可达性 |
| Release 包控制台看不到日志 | 非 `DEBUG` 编译 | `Program.LogAction` 会把 `IsConsole` 强制设为 `false`,这是预期行为 |
| 热更新目录缺失 | `hotfix` 不存在 | 启动流程会自动 `CreateDirectory`,无需手动建;若权限不足会抛异常 |
| `AppSetting` 被外部覆盖 | 调用方在 `Init()` 前已赋值 | `Init()` 仅在 `Setting == null` 时填充默认值,先注入再启动会以你传入值为准 |
