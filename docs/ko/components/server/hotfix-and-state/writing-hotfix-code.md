# 핫업데이트 가능한 비즈니스 코드 작성(Hotfix 레이어 규범)

이 페이지에서는 `GameFrameX.Hotfix` 어셈블리에서 핫 교체 가능한 비즈니스 코드를 작성하고, 프레임워크의 브리지 및 레이어 제약을 따르는 방법을 설명합니다.

## 사전 조건

- `GameFrameX.Hotfix` 어셈블리 프로젝트를 생성했음(저장소의 [GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj) 참조).
- `GameFrameX.StartUp`, `GameFrameX.SuperSocket.*`, `GameFrameX.Apps.Common.Session` 등의 의존성을 참조함.
- 컴파일 시 `GameFrameX.Architecture.Analyzers` 규칙 세트(`GFX0004` 등)가 활성화되어 있음.

## Hotfix 레이어의 핵심 규칙

1. **브리지 클래스는 반드시 `IHotfixBridge`를 구현해야 함**: 상태 레이어(Apps)와 로직 레이어(Hotfix) 사이를 브리지해야 하는 모든 진입 클래스는 이 인터페이스를 구현해야 하며, 해당 클래스는 반드시 `GameFrameX.Hotfix` 어셈블리 내에 정의되어야 합니다. `HotfixBridgeAssemblyAnalyzer`가 `GFX0004` 오류로 이 규칙을 강제합니다.
2. **진입 클래스는 `partial` 사용**: 시작 라이프사이클이 여러 파일(`AppStartUpHotfixGameByEntry.cs`, `AppStartUpHotfixGameByMain.cs` 등)에 분산되어 있기 때문에 클래스는 반드시 `partial`로 유지해야 하며, 그렇지 않으면 시작 단계에서 컴파일이 실패합니다.
3. **`HotfixHandler` 마커 타입 유지**: `HotfixHandler`는 빈 정적 클래스로, 리플렉션으로 위치를 찾기 위해서만 사용됩니다. 삭제하면 핫업데이트 시 진입점을 찾을 수 없게 됩니다.

## 작업 단계

### 1단계: Hotfix 어셈블리에서 시작 브리지 클래스 선언

`GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`를 새로 만들거나 수정하여 `partial` 클래스를 선언하고 `IHotfixBridge`를 구현합니다:

```csharp
using GameFrameX.StartUp;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge
{
    public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
    {
        if (reload)
        {
            ActorManager.ClearAgent();
            return true;
        }

        Init(setting.ServerType, setting);
        await RunServer();
        // 타이머 시작
        await QuartzTimer.Start();
        GlobalTimer.Start();
        await ComponentRegister.ActiveGlobalComponents();
        return true;
    }

    public async Task Stop(string message = "")
    {
        await StopAsync(message);
    }
}
```

출처: [AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L37-L60)

### 2단계: 다른 파일에서 메시지 디스패치 및 라이프사이클 확장

클래스가 `partial`로 선언되어 있으므로, 다른 파일에서 `StartAsync`, `PackageHandler`, `OnConnected`, `OnDisconnected`, `StopAsync` 등의 네트워크 및 라이프사이클 훅을 재정의할 수 있습니다:

```csharp
using GameFrameX.Apps.Common.Session;
using GameFrameX.SuperSocket.Connection;
using GameFrameX.SuperSocket.Server.Abstractions.Session;
using GameFrameX.SuperSocket.WebSocket.Server;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame
{
    public override async Task StartAsync()
    {
        await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
            new DefaultMessageCompressHandler(),
            new DefaultMessageDecompressHandler(),
            HotfixManager.GetListHttpHandler(),
            HotfixManager.GetHttpHandler);
    }

    protected override async ValueTask PackageHandler(IAppSession appSession, IMessage message)
    {
        if (message is NetworkMessagePackage messagePackage)
        {
            var netWorkChannel = SessionManager.GetChannel(appSession.SessionID);
            if (netWorkChannel.IsNull()) return;

            var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
            if (handler == null)
            {
                LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
                return;
            }

            try
            {
                await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
            }
            catch (Exception exception)
            {
                LogHelper.Fatal(exception);
            }
        }
    }

    public override async Task StopAsync(string message = "")
    {
        await base.StopAsync(message);
        await SessionManager.RemoveAll();
        await QuartzTimer.Stop();
        await ActorManager.AllFinish();
        await GlobalTimer.Stop();
        await ActorManager.RemoveAll();
    }
}
```

출처: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L43-L163)

### 3단계: `HotfixHandler` 마커 타입을 삭제하지 않기

핫업데이트 프레임워크는 리플렉션으로 `HotfixHandler` 클래스를 진입 마커로 위치시키므로, 그대로 유지하기만 하면 되며 멤버를 추가할 필요가 없습니다:

```csharp
namespace GameFrameX.Hotfix;

/// <summary>
/// 이 클래스 문서는 핫업데이트 마커 처리에 사용됩니다. 삭제하면 안 됩니다. 리플렉션 호출에 사용됩니다.
/// </summary>
public static class HotfixHandler
{
}
```

출처: [HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8)

### 4단계: IHotfixBridge 구현이 Hotfix 어셈블리에 위치하도록 보장

새로운 브리지 구현을 추가한 경우(예: `MyHotfixBridge : IHotfixBridge`), 파일을 반드시 `GameFrameX.Hotfix` 프로젝트 아래에 배치해야 합니다. 그렇지 않으면 `HotfixBridgeAssemblyAnalyzer`가 `GFX0004` 오류를 보고합니다:

```text
Type 'MyHotfixBridge' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not '<YourAssembly>'
```

출처: [HotfixBridgeAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs#L22-L44)

## 일반적인 변형

- **게이트웨이 기반 시작**: `AppStartUpHotfixGameByGateWay.cs`에서 게이트웨이 측 재정의를 제공합니다.
- **하트비트 기반 시작**: `AppStartUpHotfixGameByHeart.cs`에서 하트비트 측 재정의를 제공합니다.
- **재로드 시나리오(`reload == true`)**: `OnLoadSuccess`에서 `ActorManager.ClearAgent()`만 호출하고 반환하며, 네트워크와 전역 컴포넌트를 다시 초기화하지 않습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 컴파일 시 `Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix'` 오류 발생 | `IHotfixBridge` 구현 클래스가 잘못된 어셈블리에 배치됨 | 해당 클래스 파일을 `GameFrameX.Hotfix` 프로젝트로 이동 |
| 시작 시 "핫업데이트 진입점을 찾을 수 없음" 오류 발생 | `HotfixHandler` 정적 클래스를 실수로 삭제함 | `public static class HotfixHandler {}` 다시 선언 |
| `partial` 오류 발생, `AppStartUpHotfixGame` 정의를 찾을 수 없음 | 새 파일에 `partial` 한정자를 작성하지 않음 | 모든 부분 클래스에 `internal partial class AppStartUpHotfixGame` 추가 |
| 핫업데이트 후 상태가 정리되지 않음 | `OnLoadSuccess(reload=true)` 분기에서 `ActorManager.ClearAgent()`를 호출하지 않음 | 템플릿에 따라 reload 분기에서 먼저 Agent 비우기 |

## 배경(선택 사항)

`IHotfixBridge`는 상태 레이어가 로직 레이어를 호출하기 위한 브리지 계약으로, 그 구현이 `GameFrameX.Hotfix` 어셈블리 내에 있도록 제한함으로써 핫업데이트 시 전체 브리지 로직이 한꺼번에 교체될 수 있음을 보장합니다. 아키텍처 분석기 `HotfixBridgeAssemblyAnalyzer`가 컴파일 시점에 `GFX0004`로 이 규칙을 강제합니다.
