# 起動失敗/データベース接続異常が発生した場合の対処法

サービスが起動段階でクラッシュしたり、ログに Mongo 接続エラーが表示されたりする場合、通常は `--DataBaseUrl` / `--DataBaseName` の設定ミス、Mongo コンテナの未準備、ネットワーク/認証の不通が原因です。このページでは、迅速な特定と修復を支援します。

## 迅速な診断

| 症状 | 原因 | 修復方法 |
|------|------|------|
| 起動ログに `connection refused` / `No connection could be made` が含まれる | Mongo ポートに到達できない、またはアドレスが間違っている | `--DataBaseUrl` のホストとポートを確認 |
| 起動ログに `Authentication failed` / `authSource` エラーが含まれる | 認証ソースまたはアカウント/パスワードが一致しない | 接続文字列 `?authSource=...` と認証情報を修正 |
| 起動ログに `Database name cannot be empty` またはデータベース欠如のヒントが含まれる | `--DataBaseName` が渡されていない、またはデータベース名のスペルミス | `--DataBaseName=xxx` を補完 |
| コンテナの起動順序異常:Game が Mongo より先に起動する | `depends_on` が healthcheck の通過を待っていない | `condition: service_healthy` を使用して Mongo の完了を待機 |
| ローカルから docker 内の Mongo への接続が失敗する | ポートが外部に公開されていない、または公開ポートが間違っている | `docker-compose.yml` の `ports` マッピングと照合 |

## 修復手順

### 1. `--DataBaseUrl` と `--DataBaseName` の確認

起動パラメータには、データベース接続文字列とデータベース名を明示的に渡す必要があります。`docker-compose.yml` のデフォルト値は以下の通りです:

```yaml
command:
  - "--DataBaseUrl=mongodb://mongo:27017/?authSource=admin"
  - "--DataBaseName=gameframex"
```

ソース: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L36-L37)

ローカルから docker 内の Mongo に直接接続する場合は、`mongodb://localhost:37017/?authSource=admin` を使用します(compose ファイルの `37017:27017` のポートマッピングに対応)。多サーバー版では `localhost:47017` と `gameframex_multi` を使用します。

```yaml
ports:
  - "37017:27017"
```

ソース: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L7-L7)

```yaml
ports:
  - "47017:27017"
```

ソース: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L23-L23)

### 2. Mongo のヘルスチェック通過を待機

Game と Social サービスは、Mongo の `healthcheck` が通過するまで起動を待機する必要があります。compose では `condition: service_healthy` で制約されていますが、`service_started` に変更しないでください。

```yaml
depends_on:
  mongo:
    condition: service_healthy
```

ソース: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L21-L23)

ヘルスチェックコマンドは `ping` を使用して到達可能性を検証します:

```yaml
healthcheck:
  test: [ "CMD", "mongosh", "--quiet", "--eval", "db.runCommand({ ping: 1 }).ok" ]
  interval: 5s
  timeout: 3s
  retries: 20
```

ソース: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L9-L12)

Mongo の状態を手動で検証:

```bash
docker exec -it gfx-mongo mongosh --quiet --eval "db.runCommand({ ping: 1 }).ok"
# 期待される出力: 1
```

### 3. データボリュームと永続化の確認

多サーバー版では、Mongo のデータは `./running-multi/mongo:/data/db` にマウントされています。ホストのディレクトリ権限が不足していたり、ディスクが一杯の場合、Mongo は繰り返し再起動し、Game の接続が不安定になります。

```yaml
volumes:
  - "./running-multi/mongo:/data/db"
```

ソース: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L30-L31)

ディレクトリが書き込み可能で、十分な容量があることを確認:

```bash
ls -ld ./running-multi/mongo
df -h ./running-multi/mongo
```

### 4. 認証ソースの修正

デフォルトではアカウント/パスワードは有効化されておらず、`?authSource=admin` は管理データベースの識別としてのみ使用されます。Mongo で `mongod --auth` を有効にしている場合は、URL に認証情報を追加し、`authSource` を実際の認証データベース(一般的には `admin`)に変更する必要があります。

```bash
# 認証を有効にした接続文字列の例
--DataBaseUrl=mongodb://user:password@mongo:27017/?authSource=admin
```

## 検証

修復完了後、以下の順序で確認してください:

1. Mongo のヘルス状態を確認:`docker ps` を実行し、`STATUS` 列に `(healthy)` が含まれていることを確認。
2. Game サービスを再起動:`docker compose up -d --force-recreate game` を実行し、ログに Mongo 異常がもう表示されないことを確認。
3. Mongo コンテナに入り、データベースが作成されているか確認:`docker exec -it gfx-mongo mongosh --quiet --eval "show dbs"` で `gameframex` または `gameframex_multi` が見えるはずです。
4. それでも失敗する場合は、起動ログを採取し(`docker logs gfx-game | tail -200`)、診断表と照合して引き続き調査。

## よくあるエラー

- **コンテナ内部のホスト名を使用してローカルデータベースにアクセス**。ホスト側で直接クライアントを実行する場合、`--DataBaseUrl` 内の `mongo` ホストは解決できないため、`localhost` またはホストの IP に変更する必要があります。
- **ポートマッピングを変更しても URL の同期を忘れた**。`ports` を変更した後、`--DataBaseUrl` 内のポートも同期する必要があります。そうしないと、Game は引き続き古いポートで接続します。
- **`depends_on` に `service_started` しか書かれていない**。これはコンテナプロセスの起動を待つだけで、Mongo の初期化完了を待たないため、一時的な接続失敗が繰り返し発生します。
- **Mongo 再起動後、Game が自動再接続しない**。デフォルトの `restart: unless-stopped` では、Game は `docker compose restart game` を手動で実行しなければ再接続できません。
