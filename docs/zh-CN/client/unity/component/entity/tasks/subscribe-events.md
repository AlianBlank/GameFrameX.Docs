# 如何订阅生命周期事件

通过 `IEntityManager` 暴露的五个事件(`ShowEntitySuccess` / `ShowEntityFailure` / `ShowEntityUpdate` / `ShowEntityDependencyAsset` / `HideEntityComplete`),可以在实体显示、更新、隐藏的各个阶段得到回调,而不必修改实体内部代码。

## 前置条件

- 已在项目中获取到 `IEntityManager` 实例(通常通过 `GameEntry.GetComponent<EntityComponent>().EntityManager` 拿到)。
- 引用命名空间 `GameFrameX.Entity.Runtime`(事件参数)与 `System`(标准 `EventHandler<T>`)。

## 可订阅事件一览

| 事件 | 事件参数 | 触发时机 |
|------|---------|---------|
| `ShowEntitySuccess` | `ShowEntitySuccessEventArgs` | 实体加载并显示成功 |
| `ShowEntityFailure` | `ShowEntityFailureEventArgs` | 实体加载或显示失败 |
| `ShowEntityUpdate` | `ShowEntityUpdateEventArgs` | 实体显示过程中进度更新 |
| `ShowEntityDependencyAsset` | `ShowEntityDependencyAssetEventArgs` | 开始加载实体依赖资源 |
| `HideEntityComplete` | `HideEntityCompleteEventArgs` | 实体隐藏完成 |

Source: [IEntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/IEntityManager.cs#L55-L80)

## 操作步骤

1. 在需要监听的类中保存 `IEntityManager` 引用,并通过 `+=` 注册事件回调(每个事件签名形如 `EventHandler<TEventArgs>`,第二个参数 `e` 为对应事件参数)。

```csharp
using System;
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

public class MyListener
{
    private readonly IEntityManager m_EntityManager;

    public MyListener(IEntityManager entityManager)
    {
        m_EntityManager = entityManager;
        // 订阅生命周期事件
        m_EntityManager.ShowEntitySuccess    += OnShowEntitySuccess;
        m_EntityManager.ShowEntityFailure    += OnShowEntityFailure;
        m_EntityManager.ShowEntityUpdate     += OnShowEntityUpdate;
        m_EntityManager.ShowEntityDependencyAsset += OnShowEntityDependencyAsset;
        m_EntityManager.HideEntityComplete   += OnHideEntityComplete;
    }

    private void OnShowEntitySuccess(object sender, ShowEntitySuccessEventArgs e)
    {
        // e.Entity / e.Duration / e.UserData / e.EntityLogicType
        Log.Info($"实体 {e.Entity.Id} 显示成功,耗时 {e.Duration:F2}s");
    }

    private void OnShowEntityFailure(object sender, ShowEntityFailureEventArgs e)
    {
        Log.Warning($"实体显示失败: {e.EntityId}");
    }

    private void OnShowEntityUpdate(object sender, ShowEntityUpdateEventArgs e)
    {
        // e.Progress / e.EntityId
    }

    private void OnShowEntityDependencyAsset(object sender, ShowEntityDependencyAssetEventArgs e)
    {
        // e.EntityId / e.DependencyAssetName / e.LoadedCount / e.TotalCount
    }

    private void OnHideEntityComplete(object sender, HideEntityCompleteEventArgs e)
    {
        // e.EntityId / e.EntityAssetName / e.EntityGroup / e.UserData
    }
}
```

Source: [EntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.cs#L105-L150)

2. 当监听者生命周期结束(场景切换、`OnDestroy` 等)时,使用 `-=` 取消订阅,避免内存泄漏或对已销毁对象的多余回调。

```csharp
public void Dispose()
{
    m_EntityManager.ShowEntitySuccess    -= OnShowEntitySuccess;
    m_EntityManager.ShowEntityFailure    -= OnShowEntityFailure;
    m_EntityManager.ShowEntityUpdate     -= OnShowEntityUpdate;
    m_EntityManager.ShowEntityDependencyAsset -= OnShowEntityDependencyAsset;
    m_EntityManager.HideEntityComplete   -= OnHideEntityComplete;
}
```

3. 通过 `EntityComponent` 取得管理器并交给监听者使用。

```csharp
var entityManager = GameEntry.GetComponent<EntityComponent>().EntityManager;
var listener = new MyListener(entityManager);
```

## 常见变体

- **只想监听单个事件**:只 `+=` 关心的那个,例如只关心失败:`entityManager.ShowEntityFailure += OnFailed;`。
- **按实体 Id 过滤**:在回调内根据 `e.EntityId`(或 `e.Entity?.Id`)判断是否处理本次通知。
- **只想在加载阶段反馈进度**:仅订阅 `ShowEntityUpdate` 与 `ShowEntityDependencyAsset`,在 UI 上显示 `e.Progress` 或 `e.LoadedCount / e.TotalCount`。

## 常见错误

- **未取消订阅就销毁监听者**:`EntityManager` 是长生命周期模块,会持续持有回调委托,导致对象无法被 GC。请在 `OnDestroy` / `Dispose` 中成对 `-=`。
- **在回调里抛出未捕获异常**:事件是同步派发的,异常会沿着调用栈向上传播并中断后续处理;请在回调内 `try / catch`。
- **混淆 `EventId` 与 C# `event`**:`ShowEntitySuccessEventArgs.EventId` 用于全局事件总线(`GameFrameX.Event.Runtime`);这里介绍的是 `IEntityManager` 上的 `event EventHandler<T>` 订阅,二者不是同一套机制。

## 背景(可选)

`EntityManager` 内部以标准 .NET `event` 字段暴露上述五个回调,触发点在各 `Show`/`Hide` 流程的关键节点;`EventArgs` 通过 `ReferencePool` 获取与回收,因此请勿长期持有这些参数对象——它们在事件分发后会被归还池中。
