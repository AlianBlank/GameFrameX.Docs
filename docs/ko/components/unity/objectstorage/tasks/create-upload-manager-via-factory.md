# 팩토리를 사용하여 업로드 매니저를 생성하는 방법

`ObjectStorageUploadFactory.Create<T>` 정적 메서드를 사용하면 `IObjectStorageUploadManager` 인터페이스 타입을 기반으로 **초기화된** 업로드 매니저 인스턴스를 빠르게 얻을 수 있으며, 수동으로 `new`를 호출하거나 `Init`을 호출할 필요가 없습니다.

## 사전 조건

- `GameFrameX.ObjectStorage.Editor` 네임스페이스 참조
- `IObjectStorageUploadManager` 인터페이스를 구현하는 구체적인 클래스 `T`가 있어야 함([BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)를 직접 상속 가능)
- 객체의 `accessKey`, `secretKey`, `bucketName` 준비; 객체 스토리지에 사용자 지정 주소가 필요한 경우 `endpoint`도 준비

## 작업 단계

1. 네임스페이스를 가져옵니다.

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L1-L25)

2. `Create<T>` 정적 팩토리 메서드를 호출하여 자격 증명을 전달하고 초기화된 매니저를 받습니다.

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create<MyObjectStorageUploadManager>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: null
   );
   ```

   팩토리 내부에서는 다음 두 단계가 실행됩니다:

   ```csharp
   var manager = Activator.CreateInstance<T>();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   return manager;
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. (선택 사항) 업로드 대상 경로를 설정합니다.

   ```csharp
   uploader.SetSavePath("assets/uploads/");
   ```

   Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9)

4. 업로드 메서드를 호출하여 단일 파일 또는 전체 디렉토리를 업로드합니다.

   ```csharp
   bool ok = uploader.UploadFile("D:/build/asset.bundle");
   uploader.UploadDirectory("D:/build");
   ```

   Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L15-L21)

## 주요 시그니처 빠른 참조

| 멤버 | 시그니처 | 설명 |
|------|------|------|
| `ObjectStorageUploadFactory.Create<T>` | `static IObjectStorageUploadManager Create<T>(string accessKey, string secretKey, string bucketName, string endpoint = null) where T : IObjectStorageUploadManager` | `Activator.CreateInstance<T>()`로 인스턴스를 생성하고 즉시 `Init`을 호출 |
| `IObjectStorageUploadManager.SetSavePath` | `void SetSavePath(string savePath)` | 객체 스토리지에 업로드할 대상 경로 설정 (끝의 구분 기호 자동 제거) |
| `IObjectStorageUploadManager.UploadFile` | `bool UploadFile(string localFilePathAndName)` | 단일 파일 업로드, 성공 시 `true` 반환 |
| `IObjectStorageUploadManager.UploadDirectory` | `void UploadDirectory(string localDirectory)` | 전체 디렉토리 업로드 |

## 일반적인 변형

- **endpoint를 전달하지 않음**: 주소가 필요 없는 객체 스토리지의 경우 `endpoint`를 비워두면 됩니다. 매개변수 기본값은 `null`이므로 명시적으로 전달할 필요 없습니다.
- **사용자 지정 구현 클래스**: [BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)를 직접 상속하지 않더라도, 클래스가 `IObjectStorageUploadManager`를 구현하기만 하면 `T`로 전달할 수 있음; 단, `Init`, `UploadDirectoryInternal`, `UploadFileInternal`을 직접 구현해야 함.

## 일반적인 오류

- **인터페이스를 구현하지 않고 전달**: `T`가 `IObjectStorageUploadManager`를 구현하지 않은 경우, 컴파일러가 `where T : IObjectStorageUploadManager`에서 직접 오류를 발생시킵니다.
- **중복 초기화**: 팩토리가 이미 `Init`을 호출했으므로 수동으로 다시 호출할 필요 없으며, 다시 호출하면 설정된 자격 증명이 덮어쓰여질 수 있습니다.
- **`endpoint` 잘못 전달**: 일부 객체 스토리지는 `endpoint`로 요청 주소를 조합하므로, 잘못 전달하면 업로드가 실패할 수 있음; 필요하지 않은 경우 `null`로 유지합니다.

## 배경

팩토리 패턴은 "인스턴스 생성 + 초기화"를 한 단계로 캡슐화하여, 호출자는 자격 증명과 최종 인터페이스만 신경 쓰면 되며 구체적인 구현 클래스에 직접 의존하지 않아도 됩니다. 전체 아키텍처에 대해서는 《개요》를 참조하세요.
