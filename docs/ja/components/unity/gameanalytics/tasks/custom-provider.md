# カスタムアナリティクス Provider の実装方法（BaseGameAnalyticsManager を継承）

`BaseGameAnalyticsManager` を継承し、すべての抽象メンバーを実装することで、`GameAnalyticsComponent` に自動的に発見・初期化され、すべてのイベント送信が転送されるカスタムアナリティクス Provider が完成します。フレームワーク全体には具体的な Provider は一切内蔵されておらず、ThinkingData、友盟（Umeng）、または自作のトラッキングサービスを導入するには、いずれもこのページの方法に従って各自実装する必要があります。

## 前提条件

- プロジェクトに GameFrameX ランタイムがインストールされている（`GameFrameworkModule`、`GameFrameworkComponent` は `GameFrameX.Runtime` に含まれています）。
- シーンに GameAnalytics コンポーネントが存在する（メニュー `Game Framework/GameAnalytics`、コンポーネントは `[DisallowMultipleComponent]`）。

## 操作手順

### 1. 新しいクラスを作成して BaseGameAnalyticsManager を継承する

`BaseGameAnalyticsManager` は抽象クラスで、`GameFrameworkModule` を継承して `IGameAnalyticsManager` を実装しており、共通プロパティ辞書 `m_PublicProperties` と初期化フラグ `m_IsInit` が組み込まれています：

```csharp
public abstract class BaseGameAnalyticsManager : GameFrameworkModule, IGameAnalyticsManager
{
    protected bool m_IsInit = false;
    protected readonly Dictionary<string, object> m_PublicProperties = new Dictionary<string, object>();
```

### 2. すべての抽象メンバーを実装する

以下のメンバーにはデフォルト実装がなく、サブクラスで必ずすべて実装する必要があります（シグネチャは基底クラスから直接引用）：

| メンバー | シグネチャ | 説明 |
|------|------|------|
| `Init` | `public abstract void Init(Dictionary<string, string> args)` | 自動初期化。args は Inspector の Setting のキーと値のペアから渡される |
| `ManualInit` | `public abstract void ManualInit(Dictionary<string, string> args)` | 手動初期化。`IsManualInit()` が `true` を返す場合にのみコンポーネントから呼び出される |
| `IsManualInit` | `public abstract bool IsManualInit()` | 手動初期化モードを使用するかどうか |
| `StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer` | `public abstract void Xxx(string eventName)` | イベント計時用の4メソッド一式 |
| `Event` | `public abstract void Event(string eventName)` | イベントを送信 |
| `Event` | `public abstract void Event(string eventName, float eventValue)` | 数値付きイベントを送信 |
| `Event` | `public abstract void Event(string eventName, Dictionary<string, object> customF)` | カスタムフィールド付きイベントを送信 |
| `Event` | `public abstract void Event(string eventName, float eventValue, Dictionary<string, object> customF)` | 数値とカスタムフィールド付きイベントを送信 |
| `SetPlayerId` | `public abstract void SetPlayerId(string playerId)` | プレイヤー ID を設定 |

出典： [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L31-L202)、[IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L105)

以下のスケルトンは基底クラスの実際のシグネチャに基づいて組み立てたもので、メソッド本体は各自が実際の SDK を組み込んで実装してください：

```csharp
using System.Collections.Generic;
using GameFrameX.GameAnalytics.Runtime;

namespace YourGame.Analytics
{
    public class MyAnalyticsProvider : BaseGameAnalyticsManager
    {
        public override void Init(Dictionary<string, string> args)
        {
            // args のキーと値は GameAnalyticsComponent の Inspector の Setting から渡される
            m_IsInit = true;
        }

        public override void ManualInit(Dictionary<string, string> args) { }
        public override bool IsManualInit() { return false; }

        public override void StartTimer(string eventName) { /* 計測開始 */ }
        public override void PauseTimer(string eventName) { }
        public override void ResumeTimer(string eventName) { }
        public override void StopTimer(string eventName) { /* 経過時間イベントを送信 */ }

        public override void Event(string eventName) { /* 対象 SDK へ転送 */ }
        public override void Event(string eventName, float eventValue) { }
        public override void Event(string eventName, Dictionary<string, object> customF) { }
        public override void Event(string eventName, float eventValue, Dictionary<string, object> customF) { }

        public override void SetPlayerId(string playerId) { /* アカウントを紐付ける */ }
    }
}
```

出典： [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L31-L202)（スケルトンのメソッドシグネチャは基底クラスの抽象メンバーと一対一に対応しており、リポジトリ内に参考にできる具体的な Provider 実装はありません）

### 3. GameAnalyticsComponent に Provider を登録する

コンポーネントはリフレクションによって型の完全名文字列からインスタンスを生成するため、作成するクラスには**引数なしのコンストラクターが必須**であり、完全な型名（名前空間を含む）を Provider エントリーの `ComponentType` に入力する必要があります：

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```

出典： [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L77)

具体的な手順：Inspector で `GameAnalyticsComponent` の Provider リストを展開し、新しいエントリーを追加します：

| フィールド | 入力内容 |
|------|----------|
| `ComponentType` | `YourGame.Analytics.MyAnalyticsProvider`（名前空間を含む型の完全名） |
| `Setting` | `Init(args)` に渡すキーと値のペア。例：`app_id`、`server_url` など |

### 4. コンポーネント経由で統一的に呼び出す

初期化は `OnEnable()` のタイミングで `Init()` が一度だけ自動的に実行されます。以降のすべての送信はコンポーネント層を経由し、コンポーネントが呼び出しをリスト内の各 Provider に転送します：

```csharp
// イベントを送信（コンポーネント層にはパラメーター検証と未初期化時の保護が含まれる）
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

出典： [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

ビジネスコードでの典型的な使用例：`GameEntry.GameAnalytics.Event("level_complete")`、`StartTimer("battle")` / `StopTimer("battle")`、`SetPlayerId(userId)`。

## よくあるバリエーション

- **手動初期化**：`IsManualInit()` が `true` を返すようにすると、コンポーネントの `ManualInit(Dictionary<string, string> extraArgs)` が適切なタイミング（例：プレイヤーのログイン後）に追加パラメーターを実装した `ManualInit` に渡します。`false` を返す場合、コンポーネントはその Provider の手動初期化呼び出しをスキップします。
- **複数の Provider の併存**：Provider リストには複数の項目を設定できます（例：ThinkingData と自作ログを同時に接続）。コンポーネント層のすべての `Event` / 計時 / `SetPlayerId` 呼び出しは、初期化済みの各 Provider に対してループで転送されます。
- **カスタムのデバイス共通プロパティ**：デフォルトのデバイス情報（`device_id`、`os`、`app_version`、`network_type` など）は `AddDeviceInfoToPublicProperties()` によって書き込まれます。この `protected virtual` メソッドを `override` してフィールドを追加・削除できます。`SetPublicProperties(key, value)` では、カスタム共通プロパティをいつでも追加できます。

```csharp
protected override void AddDeviceInfoToPublicProperties()
{
    base.AddDeviceInfoToPublicProperties();
    m_PublicProperties["channel"] = "your_channel";
}
```

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| コンソールに `Can not find component type 'xxx'.` と出力される | `ComponentType` に入力した型の完全名が誤っている、またはアセンブリがリフレクションでスキャンされていない | 名前空間と型名を確認；クラスが `public` であり、引数なしのコンストラクターを持つことを確認 |
| コンソールに `GameAnalyticsManager is not init.` が繰り返し出力される | サブクラスの `Init(args)` 内で `m_IsInit` を `true` にするのを忘れている | `Init` 成功後に `m_IsInit = true` を設定する |
| `Event` の呼び出しでパラメーター例外がスローされる | イベント名が空 | `GameFrameworkGuard.NotNullOrEmpty` によりイベント名は空にできないため、有効な文字列を渡す |
| `ManualInit` のパラメーターが取得できない | その Provider の `IsManualInit()` が `false` を返している | `true` を返すようにするとコンポーネントからの転送を受け取れる |
| `SetPublicProperties(key, value)` が効かない | `key` が空文字列の場合、基底クラスはそのまま `return` する | 空でない key を使用する |

## 背景

`GameAnalyticsComponent` は `Awake` で `IsAutoRegister = false` を設定し、`OnEnable` で一度の `Init()` を完了します：`ComponentType` 文字列に基づいてリフレクションで `IGameAnalyticsManager` インスタンスを生成し、Inspector の `Setting` のキーと値のペアを `Dictionary<string, string>` にまとめて `Init(args)` に渡し、その後、すべての送信呼び出しを「ブロードキャスト」方式で全 Provider に転送します。基底クラス `BaseGameAnalyticsManager` は `m_IsInit` と `m_PublicProperties`（デバイス/システム/ネットワークの共通プロパティ）を一元管理し、サブクラスはそれぞれの SDK の送信詳細にのみ注力すればよい設計になっています。
