# 컴포넌트가 추가되지 않거나 중복으로 마운트되는 경우怎么办

`CoroutineComponent` 추가 실패, 추가 후 즉시 제거됨, 또는 Inspector에서 "Can't add component" 오류가 발생하는 경우, 이는 보통 Unity의 중복 마운트 제한, `[DisallowMultipleComponent]` 특성 또는 GameFrameX 프레임워크의 자동 마운트 프로세스와 관련이 있습니다. 이 페이지에서는 일반적인 증상에 대한 빠른 진단 및 수정 방법을 제공합니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `AddComponent<CoroutineComponent>()` 후 `Can't add component ... because a MonoBehaviour is already attached` 오류 발생 | 동일한 GameObject에 해당 컴포넌트가 이미 존재하며, `CoroutineComponent`에는 `[DisallowMultipleComponent]`가 지정되어 있음 | 아래 "먼저 제거 후 추가" 섹션 참조 |

## 수정 단계

### 먼저 제거 후 추가(동일 GO 중복 마운트)

`CoroutineComponent`는 소스 코드에 `[DisallowMultipleComponent]`가 지정되어 있으며, 이는 MonoBehaviour 내장 특성으로 동일한 GameObject에 여러 개를 마운트하는 것을 금지합니다.

```csharp
// 오류: Can't add component 'CoroutineComponent' because a MonoBehaviour is already attached.
// 해결: 먼저 기존 것을 제거한 후 추가하거나, 기존 참조를 직접 재사용
if (gameObject.TryGetComponent<CoroutineComponent>(out var exist))
{
    // 이미 있으면 직접 사용하고, AddComponent를 반복하지 마세요
}
else
{
    exist = gameObject.AddComponent<CoroutineComponent>();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L15)

### 프레임워크 자동 마운트

정상적인情况下, 비즈니스 코드에서 수동으로 `AddComponent<CoroutineComponent>()`를 호출하면 **안 되며**, GameFrameX 프레임워크가 `[GameFrameXAutoComponent(-6500)]` 특성을 통해 프레임워크 시작 시 프레임워크 진입점 GameObject에 자동으로 마운트합니다. 컴포넌트의 `Awake()` 내부에서는 `IsAutoRegister = false`로 설정하여 런타임의二次 등록 프로세스에 참여하지 않도록 합니다.

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Coroutine")]
[GameFrameXAutoComponent(-6500)]
public class CoroutineComponent : GameFrameworkComponent
{
    protected override void Awake()
    {
        IsAutoRegister = false;
        base.Awake();
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L110)

반드시 수동으로 마운트해야 하는 경우, 다음 사항을 확인하세요:
1. GameObject가 활성화 상태인지 확인하세요.
2. 동일한 이름의 다른 컴포넌트 인스턴스가 없는지 확인하세요( previous 섹션 참조).
3. `GameFrameworkComponent` 기본 클래스가 있는 호스트 GameObject에 마운트하여 프레임워크 인스턴스와 중복되지 않도록 하세요.

### 빌드 후 손실

IL2CPP / iOS 링커는 명시적으로 참조되지 않은 MonoBehaviour 타입을 제거할 수 있습니다. 소스 코드에서는 빈 `MonoBehaviour`와 `[Preserve]`를 함께 사용하여 타입이 삭제되지 않도록 합니다:

```csharp
[Preserve]
public class GameFrameXCoroutineCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(CoroutineComponent); // CoroutineComponent 강제 보존
    }
}
```

Source: [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

해결 방법:
1. 씬에 `GameFrameXCoroutineCroppingHelper`가 마운트된 GameObject가 존재하는지 확인하세요(또는 코드에서 `CoroutineComponent`를 명시적으로 참조했는지 확인).
2. Unity Player Settings → Managed Stripping Level은 iOS에서 `Low` / `Medium`보다 더 공격적인 레벨로 설정하지 마세요. 그렇지 않으면 `link.xml`을 추가로 구성하여 네임스페이스 `GameFrameX.Coroutine.Runtime`을 제외해야 합니다.

### "다중 GO"와 "동일 GO 중복" 구분

- **여러 GO에 각각 하나씩 마운트**(예: 각 UI 패널에 하나씩): 이는合法하며, 각자 자신의 코루틴을 관리합니다.
- **동일 GO에 두 개 마운트**: `Can't add component` 오류 발생, 위의 처리 방법 참조.

프레임워크가 여러 인스턴스를 "중복으로 마운트"했다고 생각된다면, Hierarchy에서 `Coroutine`을 검색하여 실제로 서로 다른 GameObject에 있는지 확인할 수 있습니다. 모두 동일한 GO에 있다면 하나만 유지하면 됩니다.

## 검증

수정 후 다음 방법으로 확인하세요:

1. Unity Console에 더 이상 `Can't add component` 오류가 없는지 확인합니다.
2. Play Mode 진입 후 Hierarchy에서 프레임워크 진입점 GameObject의 `CoroutineComponent`(`GameFrameX/Coroutine` 메뉴 이름이 표시됨)를 볼 수 있어야 합니다.
3. `StartCoroutine` 호출 후 코루틴이 정상적으로 실행되며, 동일한 참조로 `StopCoroutine(IEnumerator)`을 호출하여 성공적으로 중지할 수 있습니다. 이는 컴포넌트가 올바르게 마운트되고 프레임워크에 의해 관리되고 있음을 나타냅니다.
