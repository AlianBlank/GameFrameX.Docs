# 로그에 "Event manager is invalid." 가 출력될 때 해결 방법

`MonoComponent` 가 씬에서 시작될 때 `GameEntry` 로부터 `EventComponent` 인스턴스를 가져오지 못하면, 로그에 `Event manager is invalid.` 가 출력되고 후속 초기화 프로세스가 중단되어 Mono 모듈의 이벤트 구독/발행이 모두 실패하게 됩니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 시작 시 `Event manager is invalid.` 발생 | 시작 씬에 `EventComponent` 가 부착되어 있지 않음 | 시작 씬의 `GameFramework` 노드에 `EventComponent` 를 추가합니다. 아래 해결 단계 1 참조 |
| 시작 시 `Event manager is invalid.` 발생 | 시작 씬에 `EventComponent` 가 부착되어 있으나, `MonoComponent` 의 스크립트 실행 순서가 `EventComponent.Awake` 보다 빠름 | Project Settings 에서 `MonoComponent` 의 Script Execution Order 를 `Default` 이후로 조정합니다. 해결 단계 2 참조 |
| 시작 시 `Event manager is invalid.` 발생 | 동일한 컴포넌트에 중복된 `EventComponent` 가 추가로 부착되어, `GameEntry` 에 저장된 인스턴스가 덮어쓰기/해제됨 | 불필요한 `EventComponent` 를 제거하고, 프레임워크 엔트리 노드에 하나만 남아있도록 합니다 |

## 해결 단계

### 1. 시작 씬에 EventComponent 추가

`MonoComponent.Start()` 는 `GameEntry.GetComponent<EventComponent>()` 를 통해 이벤트 컴포넌트를 가져옵니다. `GameEntry` 가 인덱싱할 수 있는 컴포넌트는 GameFramework 시작 객체에 부착된 컴포넌트뿐입니다.

1. 프로젝트의 시작 씬(예: `Assets/GameFrameX/Launch/Launch.unity`)을 엽니다.
2. `GameFramework` 루트 GameObject 를 선택합니다.
3. Inspector → Add Component → `GameFrameX.Event.EventComponent` 를 검색하여 추가합니다.
4. 다시 실행하면 로그에 `Event manager is invalid.` 가 더 이상 나타나지 않아야 합니다.

오류 발생 위치 참고:

```csharp
// 출처:Runtime/Mono/MonoComponent.cs
private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76)

### 2. 스크립트 실행 순서 확인

`MonoComponent.Start()` 는 모든 컴포넌트의 `Awake` 이후에 실행되지만, 프로젝트에서 Script Execution Order 를 사용자 정의하여 `MonoComponent` 를 앞당긴 경우, 아직 `GameEntry` 에 등록되지 않은 `EventComponent` 를 가져올 수 있습니다.

1. Edit → Project Settings → Script Execution Order 로 이동합니다.
2. `MonoComponent` 를 `Default Time` 이후로 드래그하거나, `EventComponent` 보다 늦은 Order 값을 명시적으로 지정합니다.
3. 다시 실행하여 확인합니다.

### 3. 중복 부착 또는 씬 잔여물 확인

동일한 GameObject 에 여러 개의 `EventComponent` 가 수동으로 추가되었거나, 이전 씬에 오래된 `EventComponent` 가 남아 있고 새 코드가 다른 객체에서 이를 인스턴스화한 경우, `GameEntry.GetComponent` 가 타입 중복으로 인해 null 참조를 반환합니다.

1. Hierarchy 에서 `t:EventComponent` 를 검색하여 인스턴스가 하나만 있는지 확인합니다.
2. 불필요한 인스턴스를 삭제한 후 다시 실행합니다.

## 검증

1. 씬을 실행하고 Console 을 열어 `Event manager is invalid.` 를 검색했을 때 더 이상 나타나지 않아야 합니다.
2. `MonoComponent` 가 있는 객체에 테스트 스크립트를 부착하고, `Start` 에서 `GameEntry.GetComponent<EventComponent>()` 를 호출하여 null 이 아닌지 확인합니다.
3. 전체 이벤트 구독/발행 흐름(`Subscribe` → `Fire` → `Unsubscribe`) 을 한 번 진행하여 이벤트가 정상적으로 리스너에 도달하는지 확인합니다.

## 배경(선택 사항)

`MonoComponent` 는 `EventComponent` 의 참조를 `m_EventComponent` 필드에 캐시하며, 이후 `OnApplicationFocus` 같은 생명주기 콜백에서 이를 재사용합니다. `Start` 단계에서 참조를 가져오지 못하면 필드는 null 상태로 유지되고, 이후 이벤트 관련 초기화가 조용히 건너뛰어집니다 — 이것이 오류가 한 번만 나타나는데 기능은 작동하지 않는 이유입니다.

Mono 모듈의 전체 연동 절차에 대해서는 《Mono 모듈 연동 방법》 을 참조하세요.
