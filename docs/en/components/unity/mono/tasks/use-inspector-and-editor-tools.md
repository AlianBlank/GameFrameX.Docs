# How to Attach and Configure in the Unity Inspector

After adding `MonoComponent` to a GameObject in the scene, you can select the specific type that implements `IMonoManager` in the Inspector. The framework will create and manage this implementation via reflection at runtime.

## Prerequisites

- The `com.gameframex.unity.mono` package has been installed, along with its dependent GameFrameX runtime and Editor packages.
- A `GameFramework` entry GameObject exists in the scene (the root node required by the framework) to host `MonoComponent`.

## Steps

1. Select the target GameObject in the Hierarchy (usually the `GameFramework` entry) and click **Add Component** at the bottom of the Inspector.
2. Type `Mono` in the search box and select **GameFrameX/Mono** from the list. This menu path is injected by the attribute `[AddComponentMenu("GameFrameX/Mono")]`.
3. After adding, the Inspector will render the custom panel `MonoComponentInspector`. The **Component Type** dropdown lists all specific types in the current project that implement `IMonoManager`—just choose the implementation class you need.
4. At runtime, `MonoComponent.Awake()` will resolve the selected type via `Utility.Assembly.GetType(componentType)` and bind it to the `IMonoManager` interface.

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Mono")]
public class MonoComponent : GameFrameworkComponent
{
    protected override void Awake()
    {
        ImplementationComponentType = Utility.Assembly.GetType(componentType);
        InterfaceComponentType = typeof(IMonoManager);
        base.Awake();
        _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    }
}
```

## Common Variants

- **Custom editor context menu**: If you want the component to appear at a shallower level (for example, under the root menu `GameFrameX`), just modify the first parameter of `AddComponentMenu`, such as `[AddComponentMenu("GameFrameX/My Mono")]`. The new name will also affect the *Add Component* search results in the Inspector.
- **View available implementation classes**: Open `MonoComponentInspector.cs` to confirm that the panel only enumerates implementation types of `IMonoManager`. After adding a new `IMonoManager` implementation, refresh the Inspector to see it in the dropdown.

```csharp
[CustomEditor(typeof(MonoComponent))]
internal sealed class MonoComponentInspector : ComponentTypeComponentInspector
{
    protected override void RefreshTypeNames()
    {
        RefreshComponentTypeNames(typeof(IMonoManager));
    }
}
```

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| The *GameFrameX/Mono* menu is not visible when adding a component | The Editor assembly of the package was not imported, or the cache was not refreshed | Confirm that `Editor/Inspector/MonoComponentInspector.cs` has been compiled, then right-click *Reimport* in the Project view |
| Runtime log `Mono manager is invalid.` | `MonoComponent` is not retained in the scene, or `componentType` resolution failed | Make sure a valid implementation class is selected in the Inspector's **Component Type** |
| Adding the same component to the same GameObject is blocked | `MonoComponent` is annotated with `[DisallowMultipleComponent]` | Remove the existing one before re-adding, or attach it to another GameObject |
| Log `Event manager is invalid.` | `EventComponent` is missing from the scene | Add `EventComponent` to the `GameFramework` entry. See the GameFrameX framework documentation for details |

## Background (Optional)

`MonoComponent` uses `Utility.Assembly.GetType(componentType)` to reflectively load the selected implementation at runtime, thereby deferring the choice of the "concrete class" to the Inspector configuration phase. `MonoComponentInspector` inherits from `ComponentTypeComponentInspector` provided by `GameFrameX.Editor`, which automatically enumerates interface implementations and generates the dropdown.
