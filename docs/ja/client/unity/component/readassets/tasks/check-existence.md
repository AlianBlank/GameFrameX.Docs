# ファイルとディレクトリの存在確認

`BlankReadAssets` は `FileExists` と `DirectoryExists` という 2 つの静的メソッドを提供しており、ランタイム時に `StreamingAssets` 配下のファイルまたはディレクトリの存在を判定するために使用されます。これらは Android(APK を直接読み取り)、エディタ、その他のプラットフォーム(ルーズファイル)で正しく動作し、最初の呼び出し時に自動的に `Initialize` が呼ばれます。

## 前提条件

- `com.gameframex.unity.readassets` パッケージがインストールされていること。
- `StreamingAssets` ディレクトリがプロジェクト内に存在すること(ランタイム時に手動で初期化する必要はありません。API を最初に呼び出した際に自動的に完了します)。

## 操作手順

1. ファイルの存在を判定するには、`StreamingAssets` からの相対パスを渡します:

```csharp
using GameFrameX.ReadAssets.Runtime;

bool exists = BlankReadAssets.FileExists("configs/level1.json");
if (exists)
{
    // 安全に OpenRead / LoadAssetBundle などを続行する
}
```

2. ディレクトリの存在を判定する場合も、同様に相対パスを使用します(`/ `で開始または終了してもよく、内部で正規化されます):

```csharp
using GameFrameX.ReadAssets.Runtime;

bool dirExists = BlankReadAssets.DirectoryExists("configs/");
```

## API 早見表

| メソッド | シグネチャ | 説明 |
|------|------|------|
| `FileExists` | `static bool FileExists(string path)` | `StreamingAssets` からの相対パスでファイルの存在を確認 |
| `DirectoryExists` | `static bool DirectoryExists(string path)` | `StreamingAssets` からの相対パスでディレクトリの存在を確認 |

両メソッドとも `[Preserve]` が付与され、`EnsureInitialized()` によって自動的に初期化された後、プラットフォーム実装(`EditorImpl` / `ApkImpl` / `LooseFilesImpl`)に委譲されます。

## よくあるバリエーション

- エディタ内で外部 APK の `StreamingAssets` の存在を確認したい場合は、まず `InitializeWithExternalApk(apkPath)` を呼び出し、その後同じ `FileExists` / `DirectoryExists` を使用します。
- Android では、APK 内のパス判定は APK のディレクトリツリーをスキャンするため(`ApkImpl.DirectoryExists` は内部で `GetDirectoryIndex` を使用します)、大文字小文字や圧縮状態を気にする必要はありません。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| 常に `false` を返すが、ファイルは確かに存在する | 路径传成了绝对路径或包含 `Application.streamingAssetsPath` 前缀 | パスを絶対パスまたは `Application.streamingAssetsPath` プレフィックス付きではなく、`StreamingAssets` からの相対パスのみを渡す(例: `Application.streamingAssetsPath + "/config.json"` ではなく `"config.json"`) |
| パスにバックスラッシュや余分な `/` が含まれて誤判定される | プラットフォームのパス区切り文字の違い | `/` 区切りの相対パスをそのまま渡し、ツール内部で `PathUtil.NormalizeRelativePath` により正規化する |
| Android で `true` を返すが後続の `OpenRead` が例外をスローする | ファイルが APK 内で Unity によって圧縮指定されている | `BlankReadAssets.CompressedStreamingAssetFound` イベントを監視し、`UnityWebRequest` での読み取りに切り替える |

## 背景(任意)

プラットフォームの分岐は `BlankReadAssets.cs` の冒頭の条件コンパイルによって選択されます。`UNITY_EDITOR` は `EditorImpl`(APK モード/外部ディレクトリをサポート)、`UNITY_ANDROID` は `ApkImpl`(APK 内部のバイナリ検索で位置を特定)、その他のプラットフォームは `LooseFilesImpl`(ファイルシステムを直接使用)を使用します。APK 内の `DirectoryExists` は構築済みのパスインデックス `GetDirectoryIndex` で判定するため、実際の展開は発生しません。
