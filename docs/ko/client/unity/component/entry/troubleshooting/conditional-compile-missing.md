# 조건부 컴파일로 인해 특정 하위 시스템을 사용할 수 없을 때 어떻게 해야 하나요

`GameApp`에서 특정 하위 시스템(예: `Network`, `GUI`, `Entity`, `Download`)의 속성에 접근할 수 없거나, "`GameApp`에 XXX의 정의가 포함되어 있지 않습니다"라는 오류가 발생하거나, 호출 시 바로 null 참조 오류가 발생하는 경우, 대개 해당 조건부 컴파일 매크로가 누락되어 전체 `GameApp.XXX.cs` 파일이 컴파일 시 `#if … #endif`에 의해 통째로 제외된 것입니다. 실제로 이 API가 없는 것이 아닙니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| `GameApp.Network`, `GameApp.GUI`, `GameApp.Entity` 등의 속성을 찾을 수 없고 IDE에서 빨간색으로 표시됨 | 해당 `ENABLE_GAME_FRAME_X_XXX` 매크로가 정의되지 않아 전체 `GameApp.XXX.cs`가 `#if … #endif`에 의해 제외됨 | *Project Settings → Player → Scripting Define Symbols*에서 누락된 매크로를 추가하거나 해당 하위 모듈 패키지 설치 |
| `GameApp.XXX` 호출 시 반환된 컴포넌트가 `null`이고, 메서드 호출 시 `NullReferenceException` 발생 | 매크로가 정의되어 있고 속성도 존재하지만, 기반 컴포넌트가 `GameEntry`에 등록되지 않음 | `GameEntry.RegisterComponent` 흐름을 확인하여 해당 Runtime 패키지가 설치 및 시작되었는지 확인 |
| 플랫폼 전환(예: iOS/Android/Editor) 후 특정 하위 시스템이 갑자기 사용 불가 | 일부 매크로가 플랫폼 컴파일에 함께 포함되어 있거나, 매크로가 특정 플랫폼에만 정의됨 | 매크로가 `UNITY_IOS`, `UNITY_ANDROID` 등의 플랫폼 매크로와 함께 변경되는지 확인 |

## 수정 단계

### 1. 사용 중인 하위 시스템 확인

각 하위 시스템은 `Runtime/GameApp.<Name>.cs` 파일 하나에 해당하며, 파일의 처음과 끝이 동일한 매크로로 감싸져 있습니다. 다음은 저장소에 현재 존재하는 하위 시스템과 해당 매크로입니다:

| 하위 시스템 | 파일 | 조건부 컴파일 매크로 |
|--------|------|------------|
| 네트워크 Network | `Runtime/GameApp.Network.cs` | `ENABLE_GAME_FRAME_X_NETWORK` |
| GUI(UGUI) | `Runtime/GameApp.GUI.cs` | `ENABLE_GAME_FRAME_X_L_UGUI` |
| 엔티티 Entity | `Runtime/GameApp.Entity.cs` | `ENABLE_GAME_FRAME_X_ENTITY` |
| 다운로드 Download | `Runtime/GameApp.Download.cs` | `ENABLE_GAME_FRAME_X_DOWNLOAD` |
| 전역 설정 GlobalConfig | `Runtime/GameApp.GlobalConfig.cs` | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` |
| 광고 Advertisement | `Runtime/GameApp.Advertisement.cs` | `ENABLE_GAME_FRAME_X_ADVERTISEMENT` |
| Apple 로그인 AppleLogin | `Runtime/GameApp.AppleLogin.cs` | `ENABLE_GAME_FRAME_X_APPLE_LOGIN` |
| Facebook 로그인 | `Runtime/GameApp.FaceBookLogin.cs` | `ENABLE_GAME_FRAME_X_FACEBOOK_LOGIN` |
| Google 로그인 | `Runtime/GameApp.GoogleLogin.cs` | `ENABLE_GAME_FRAME_X_GOOGLE_LOGIN` |
| QQ 로그인 | `Runtime/GameApp.QQLogin.cs` | `ENABLE_GAME_FRAME_X_QQ_LOGIN` |
| WeChat 로그인 | `Runtime/GameApp.WeChatLogin.cs` | `ENABLE_GAME_FRAME_X_WECHAT_LOGIN` |
| 인앱 결제 | `Runtime/GameApp.Payment.cs` | `ENABLE_GAME_FRAME_X_PAYMENT` |
| Mono 동작 | `Runtime/GameApp.Mono.cs` | `ENABLE_GAME_FRAME_X_MONO` |
| Web ProtoBuf | `Runtime/GameApp.Web.ProtoBuff.cs` | `ENABLE_GAME_FRAME_X_WEB_PROTO_BUFF` |

> 네이밍에는 한 가지 특례가 있습니다: GUI 하위 시스템의 매크로는 `ENABLE_GAME_FRAME_X_GUI`가 아니라 `L_` 접두사가 붙은 `ENABLE_GAME_FRAME_X_L_UGUI`이므로, 표에 있는 매크로 이름을 그대로 추가하면 됩니다.

### 2. Scripting Define Symbols에 누락된 매크로 추가

`Edit → Project Settings → Player`를 열고, *Other Settings → Configuration → Scripting Define Symbols*에 이전 단계에서 찾은 매크로를 추가합니다. 여러 매크로는 세미콜론 `;`으로 구분합니다.

```text
ENABLE_GAME_FRAME_X_NETWORK;ENABLE_GAME_FRAME_X_L_UGUI;ENABLE_GAME_FRAME_X_ENTITY
```

추가한 후 IDE로 돌아가 스크립트를 한 번 다시 컴파일하도록 트리거하면(`Assets → Reimport` 또는 Editor 재시작) IDE의 빨간 표시가 사라집니다.

### 3. 해당 Runtime 패키지가 설치되어 있는지 확인

매크로는 단지 스위치일 뿐이며, 실제 타입(예: `NetworkComponent`, `UGUIComponent`)은 각 하위 모듈의 Runtime 어셈블리에서 제공됩니다. 아래는 매크로가 켜진 후에야 컴파일에 포함되는 `GameApp.Network.cs`로, `GameFrameX.Network.Runtime`에 의존함을 알 수 있습니다:

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Network.Runtime;
using GameFrameX.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// 네트워크 컴포넌트를 가져옵니다.
    /// </summary>
    public static NetworkComponent Network
    {
        get
        {
            if (_network == null)
            {
                _network = GameEntry.GetComponent<NetworkComponent>();
            }

            return _network;
        }
    }

    private static NetworkComponent _network;
}
#endif
```

출처: [Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L56)

GUI 하위 시스템도 마찬가지입니다:

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
using GameFrameX.Runtime;
using GameFrameX.LUGUI.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// UI 컴포넌트를 가져옵니다.
    /// </summary>
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }

            return _gui;
        }
    }

    private static UGUIComponent _gui;
}
#endif
```

출처: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

매크로를 추가했는데도 여전히 `NetworkComponent` / `UGUIComponent` 등의 타입을 찾을 수 없다는 메시지가 나오면, 해당 하위 모듈 패키지가 UPM/Package Manager를 통해 설치되지 않은 것입니다. `Window → Package Manager`를 열어 해당 패키지를 설치하면 됩니다.

### 4. 시작 시 컴포넌트가 `GameEntry`에 등록되었는지 확인

`GameApp.XXX` 내부는 모두 `GameEntry.GetComponent<XXXComponent>()`를 사용하므로, 시작 흐름에서 이 컴포넌트가 등록되어 있어야 합니다. `GetComponent`가 `null`을 반환하면 `GameEntry`의 `RegisterComponent` 호출 체인에 해당 컴포넌트를 추가하면 됩니다.

## 검증

1. IDE에서 `GameApp.Network`, `GameApp.GUI` 등의 속성에 더 이상 빨간 표시가 나타나지 않습니다.
2. 런타임에 `GameApp.Network`를 호출해도 더 이상 `null`이 반환되지 않고, 메서드 호출 시 더 이상 `NullReferenceException`이 발생하지 않습니다.
3. 다양한 대상 플랫폼(Editor, iOS, Android) 간에 컴파일을 전환해도 사용하는 하위 시스템이 모든 플랫폼에서 사용 가능합니다.
