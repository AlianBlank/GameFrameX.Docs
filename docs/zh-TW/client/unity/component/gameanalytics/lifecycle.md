# 工作原理：元件初始化與事件分發流程

`GameAnalyticsComponent` 是一個掛在場景中的 Unity 元件：它在 `Awake` 裡關閉自動註冊、在 `OnEnable` 裡讀取 Inspector 上設定的 Provider 清單，以反射實例化每個 `IGameAnalyticsManager` 並傳入設定字典完成初始化；之後所有上報呼叫（`Event` / 計時器 / 公共屬性）都會遍歷這些管理器逐一分發，並帶有初始化守衛與警告日誌。本頁說明這兩條鏈路的實際執行順序與程式碼位置。

## 初始化流程（從掛載到可用）

1. **元件掛載**：`GameAnalyticsComponent` 繼承自 `GameFrameworkComponent`，帶有 `[DisallowMultipleComponent]` 與 `[AddComponentMenu("Game Framework/GameAnalytics")]`，同一 GameObject 只能掛一個。
2. **`Awake` 階段**：建立管理器清單，並關閉元件的自動註冊（`IsAutoRegister = false`），再呼叫基底類別 `Awake()`：

```csharp
protected override void Awake()
{
    m_GameAnalyticsManager = new List<IGameAnalyticsManager>();
    IsAutoRegister = false;
    base.Awake();
}

private void OnEnable()
{
    Init();
}
```

來源：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L20-L30)

3. **`OnEnable` 觸發 `Init()`**：`Init()` 以 `m_IsInit` 做冪等保護，重複呼叫直接傳回。
4. **逐一處理 Provider**：遍歷序列化欄位 `m_gameAnalyticsComponentProviders`（在 Inspector 中設定），對每一項：
   - `ComponentType` 為空白字串時略過該條目；
   - 透過 `Utility.Assembly.GetType` 依類型名稱解析 `System.Type`，解析失敗時記錄錯誤日誌並 `continue`（錯誤原文：`Can not find component type '{類型名}'.`）；
   - 以 `Activator.CreateInstance` 反射建立實例，並要求它實作 `IGameAnalyticsManager`；
   - 將 Provider 的 `Setting` 鍵值對收集為 `Dictionary<string, string>` 作為 `args`，呼叫 `gameAnalyticsManager.Init(args)`，然後加入 `m_GameAnalyticsManager` 清單。
5. **設定 `m_IsInit = true`**，初始化完成，後續所有事件呼叫開始生效。

```csharp
public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }

            if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
            {
                Dictionary<string, string> args = new Dictionary<string, string>();
                foreach (var param in gameAnalyticsComponentProvider.Setting)
                {
                    args[param.Key] = param.Value;
                }

                gameAnalyticsManager.Init(args);
                m_GameAnalyticsManager.Add(gameAnalyticsManager);
            }
        }
    }

    m_IsInit = true;
}
```

來源：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L47-L80)

6. **（可選）手動初始化**：對於 `IsManualInit()` 傳回 `true` 的管理器（例如需要執行階段才能取得的參數，如登入後的票券），在元件已初始化後呼叫 `ManualInit(extraArgs)` 二次注入：

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

來源：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

## 事件分發流程

以 `Event(string eventName)` 為例，每次上報經過四層：

1. `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))`：事件名為空直接擲回守衛例外；
2. 元件級守衛：`m_IsInit == false` 時靜默傳回（元件未初始化，事件被捨棄）；
3. 遍歷 `m_GameAnalyticsManager`，對每個管理器檢查 `IsInit()`；
4. 管理器已初始化則呼叫其同名方法完成真正上報；否則輸出警告 `GameAnalyticsManager is not init.` 並略過該管理器（不影響其他管理器繼續分發）。

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

來源：[GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

`StartTimer` / `StopTimer` 走完全相同的守衛與警告邏輯（見 [GameAnalyticsComponent.cs#L160-L179](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179) 與 [#L221-L240](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L221-L240)）；`PauseTimer` / `ResumeTimer` / `SetPlayerId` 只做非空守衛與元件級 `m_IsInit` 檢查，不做單一管理器的 `IsInit()` 判斷。`Event` 有四個多載：`Event(string)`、`Event(string, float)`、`Event(string, Dictionary<string, object>)`、`Event(string, float, Dictionary<string, object>)`，分發方式一致。

## 守衛與日誌速查

| 觸發條件 | 行為 / 日誌原文 | 位置 |
|------|------|------|
| Provider 的 `ComponentType` 解析不到類型 | `Log.Error($"Can not find component type '{...}'.")`，略過該 Provider | `Init()` 內 |
| `eventName` 為空/null | `GameFrameworkGuard.NotNullOrEmpty` 擲回 | 各計時器/事件方法開頭 |
| 元件未初始化（`m_IsInit == false`） | 靜默傳回，不報錯 | 所有分發方法 |
| 某個管理器未初始化（`IsInit() == false`） | `Log.Warning("GameAnalyticsManager is not init.")`，略過該管理器 | `Event` / `StartTimer` / `StopTimer` |
| `SetPublicProperties` 的 key 為空 | 子類中直接 `return`，不寫入 | `BaseGameAnalyticsManager` |

## 公共屬性的注入與分發

管理器基底類別 `BaseGameAnalyticsManager` 繼承自 `GameFrameworkModule`（因此每個管理器本身也是框架模組，擁有 `Update` / `Shutdown` 生命週期鉤子，基底類別中為空實作），並維護一個 `m_PublicProperties` 字典：

- `SetPublicProperties(key, value)`：key 為空直接傳回，否則寫入字典；
- `ClearPublicProperties()`：清空字典後**立即重新注入裝置資訊**；
- `GetPublicProperties()`：傳回字典的淺層複本。

```csharp
public virtual void ClearPublicProperties()
{
    m_PublicProperties.Clear();
    AddDeviceInfoToPublicProperties();
}
```

來源：[BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L70-L74)

`AddDeviceInfoToPublicProperties()` 是 `protected virtual`，預設注入的公共屬性包括：裝置（`device_id` / `device_model` / `device_type`）、系統（`os` / `system_language` / `current_culture`）、應用程式（`app_version` / `unity_version` / `platform`）、CPU 與記憶體（`processor_type` / `processor_count` / `processor_frequency` / `system_memory_size`）、顯示卡（`graphics_device_name` 等 5 項）、螢幕（`screen_width` / `screen_height` / `screen_dpi` / `screen_refresh_rate`）以及依據 `Application.internetReachability` 推導的 `network_type`（取值 `No Network` / `Mobile Data` / `WiFi` / `Unknown`）。子類可覆寫它來增刪屬性。完整實作見 [BaseGameAnalyticsManager.cs#L88-L144](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L88-L144)。

元件層的 `GetPublicProperties()` 只傳回**第一個**管理器的屬性字典（遍歷中首個命中即 `return`），多個 Provider 並存時以清單最前面的為準。

## 自訂 Provider 的接入點

新增一個分析平台時需要實作 `IGameAnalyticsManager`（或直接繼承 `BaseGameAnalyticsManager` 複用公共屬性邏輯），介面要求實作：`Init(Dictionary<string, string>)`、`ManualInit(Dictionary<string, string>)`、`IsInit()`、`IsManualInit()`、公共屬性三件組、`StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer`、四個 `Event` 多載以及 `SetPlayerId`。完整介面定義見 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L46)。然後在 Inspector 裡把實作類別的類型名稱填進 Provider 清單並設定 `Setting` 鍵值對，即可被上述初始化流程自動實例化並納入事件分發。

## 常見錯誤

- **Provider 設定後沒有任何事件上報**：先檢查 Console 是否出現 `Can not find component type '...'`——類型名稱拼字錯誤或組件未參與打包都會導致該 Provider 被略過；再確認實作類別有無參數建構函式（`Activator.CreateInstance` 走預設建構）。
- **反覆收到 `GameAnalyticsManager is not init.` 警告**：說明元件層已初始化（`m_IsInit == true`），但某個管理器自身 `Init(args)` 後未把內部狀態設為已初始化，屬於實作類別的問題，與元件無關。
- **登入前呼叫 `Event` 被靜默捨棄**：元件未初始化時所有分發方法直接 `return`，不產生日誌；確認 `OnEnable` 是否已執行、`Init()` 是否曾被呼叫。
- **`ClearPublicProperties` 後公共屬性「清不乾淨」**：這是設計行為——清空後會自動重新寫入裝置資訊，裝置相關欄位始終存在。

## 背景

元件以 `IsAutoRegister = false` 阻止 GameFrameX 的元件自動註冊機制提前介入，確保初始化時機完全由 `OnEnable` 控制；以「反射 + 類型名字串」載入 Provider，使本套件無需引用任何具體平台 SDK 即可設定多平台並行上報，事件一次呼叫即廣播至全部已初始化管理器。
