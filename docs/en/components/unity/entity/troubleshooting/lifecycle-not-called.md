# What to Do If the Entity's Lifecycle Methods Are Not Triggered

If, after your `ShowEntity` / `HideEntity` calls, none of `OnInit` / `OnShow` / `OnUpdate` / `OnHide` in the entity gets called, it is usually because `EntityLogicType` was not passed in correctly, the prefab already has a script with the same name, or `EntityComponent` was not initialized. This page is a quick reference organized as "log error → root cause → one-line fix".

## Quick Diagnosis

| Symptom (log/behavior) | Root Cause | Fix |
|---|---|---|
| `Entity '{0}' OnInit userData is not ShowEntityInfo.` | When calling `ShowEntity`, `ShowEntityInfo` (which contains `EntityLogicType`) was not passed in as `userData` | Use the `ShowEntity<T>` generic overload, or wrap `ShowEntityInfo` in your custom `userData` |
| `Entity logic type is invalid.` or `Entity '{0}' can not add entity logic.` | `ShowEntityInfo.EntityLogicType` is `null`, or the type is not a subclass of `EntityLogic`, or not a `MonoBehaviour` | Assign `EntityLogicType` the `Type` of a concrete `MonoBehaviour` subclass that inherits `EntityLogic` |
| `Entity group is inconsistent for non-new-instance entity.` | The same entity object was reused in a different `EntityGroup` | Pass the same `EntityGroup` as the first time when calling `ShowEntity`, or clear the object pool |
| `Entity '{0}' On{Init/Show/Hide} with exception ...` | Your `OnInit/OnShow/OnHide` threw an exception, which was swallowed by the framework's `try/catch` | Add your own `try/catch` inside the overridden methods to debug; first make sure `base.OnXxx(...)` does not throw |
| The prefab already has your own script attached, and the framework did not add a new one | The prefab already has a script matching the `EntityLogicType`, which is reused by `Entity.OnInit`, while your entry logic is written in another script | Implement your business logic by inheriting `EntityLogic`; do not attach a separate `MonoBehaviour` |
| `OnUpdate` not called | `enabled` on `EntityLogic` was set to `false` in `OnRecycle` and not restored after the next `ShowEntity`; or the object was recycled after `HideEntity` | Do not manually set `enabled = false` in subclasses; confirm `ShowEntity` goes through the `OnInit` path, and check the object pool |

## Fix Steps

### 1. Use the generic `ShowEntity` to let the framework inject `EntityLogicType` automatically

The framework reads the `EntityLogicType` field of `userData as ShowEntityInfo` in `Entity.OnInit` ([Entity.cs#L112-L124](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L112-L124)). The least error-prone way is to use `EntityComponent.ShowEntity<T>` directly:

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

// Assume MyEntityLogic : EntityLogic, and it is attached to the prefab corresponding to EntityId
GameEntry.GetComponent<EntityComponent>()
    .ShowEntity<MyEntityLogic>(entityId, "Assets/Prefabs/MyEntity.prefab", "Default", userData);
```

Source: [Runtime/Entity/EntityComponent.cs#L48](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L48)

### 2. Confirm the `EntityLogic` subclass is a `MonoBehaviour` and the type can be added

`Entity.OnInit` injects the logic via `gameObject.AddComponent(entityLogicType)` ([Entity.cs#L141](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L141-L146)). Therefore:

```csharp
using UnityEngine;
using GameFrameX.Entity.Runtime;

public sealed class MyEntityLogic : EntityLogic   // Must be a MonoBehaviour
{
    protected internal override void OnInit(object userData)
    {
        base.OnInit(userData);
        // Initialization logic
    }

    protected internal override void OnShow(object userData)
    {
        base.OnShow(userData);
        // Every ShowEntity call enters here
    }

    protected internal override void OnHide(bool isShutdown, object userData)
    {
        base.OnHide(isShutdown, userData);
        // Hide logic
    }

    protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(elapseSeconds, realElapseSeconds);
        // Per-frame logic
    }
}
```

Source: [Runtime/Entity/EntityLogic.cs#L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L40), [Runtime/Entity/EntityLogic.cs#L133](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L133), [Runtime/Entity/EntityLogic.cs#L196](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L196)

Note: the lifecycle methods of `EntityLogic` are all declared as `protected internal virtual`, and must be overridden with `override`, not `public` / `private`.

### 3. Investigate common reasons `OnUpdate` is not triggered

`Entity.OnRecycle` calls `m_EntityLogic.enabled = false` ([Entity.cs#L173-L174](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L173-L174)). When the object is taken from the object pool and `ShowEntity` is called again, `Entity.OnInit` detects that `m_EntityLogic != null` and the type matches, and only resets `enabled` back to `true` ([Entity.cs#L130](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L130-L131)). If you manually set `enabled = false` in a subclass, `OnUpdate` will no longer be called on reuse — just remove it.

### 4. Use logging to verify the call chain

If everything above is fine but the methods are still not called, add a `Debug.Log` on the first line of each `override` to confirm whether `OnInit` / `OnShow` is reached within 1 frame after `ShowEntity`. Note: for every abnormal case, `Entity` outputs the specific reason via `Log.Error` ([Entity.cs#L149-L156](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L149-L156)); checking the Console is faster than reading code.

## Verification

1. Run the scene; after the first `ShowEntity`, you should see the `Debug.Log` of `OnInit` → `OnShow`, and then `OnUpdate` is called every frame.
2. Call `HideEntity`; you should see `OnHide` triggered, and the object still exists in the object pool (not visible in the scene, but the pool count +1).
3. Call `ShowEntity` again with the same `EntityId`; only `OnShow` should be triggered (assuming no reuse), not `OnInit` (this time it goes through the object-pool reuse branch).
4. Throw an `Exception` once in `OnInit/OnShow/OnHide` as a test, and confirm the `Log.Error` message matches the first row of the diagnostic table.

## Background (Optional)

`Entity` is a `MonoBehaviour` that acts as the host of `EntityLogic`: `ShowEntity` → asset loading → `AddComponent<EntityLogic>` on the game object via `ShowEntityInfo.EntityLogicType`, then the callbacks fire in order: `OnInit` → `OnShow` → `OnUpdate` every frame → `OnHide` on `HideEntity` → `OnRecycle` when recycled. Common failure points are concentrated on the single `EntityLogicType` parameter, which the generic `ShowEntity<T>` has already handled for you.
