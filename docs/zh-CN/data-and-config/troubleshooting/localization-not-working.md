# 本地化文案不生效怎么办

当你在 `Excels/Local/` 里新增或修改了多语言条目,运行时却看不到新文案时,通常是因为 **Luban 没有扫描到对应的本地化表**,或 **代码生成时没带上本地化参数**。本页给出常见症状与快速修复路径。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动后只看到 Key(如 `Text_001`)而不是译文 | 本地化文件未被 LuBan 加载 | 在生成命令中确认带上了 `-x l10n.textFile.path=./Excels/Local/` |
| 新加的 `L-Localization-*.xlsx` 没有生效 | 文件名未匹配 `L-Localization-` 前缀或未放入 `Excels/Local/` | 重命名为 `L-Localization-<分类>.xlsx` 并放到 `Excels/Local/` 目录 |
| 生成 `Localization.xlsx` 后仍报缺字段 | `luban.conf` 中 `localizationFileName` 未配置或拼写错误 | 在对应 target 的 command 中增加 `"localizationFileName": "Localization.xlsx"` |
| 切换语言后仍显示源语言文案 | 运行时代码没有重新加载本地化表 / 未触发再生成 | 删除旧生成产物,重新执行 `gen-client-json.sh`(或对应 .bat) |
| 客户端打包后远程文案是空字符串 | JSON 数据目录(例如 `Bundles/Config`)未刷新 | 重新执行 `gen-client-bin.sh`,让生成的 JSON 覆盖 `outputDataDir` |

## 修复步骤

### 1. 确认本地化文件位置与命名

本地化文件必须放在 `Excels/Local/` 目录,并以 `L-Localization-` 开头。仓库示例已包含 3 个本地化文件:

- `Excels/Local/L-Localization-UI.xlsx`
- `Excels/Local/L-Localization-成就.xlsx`
- `Excels/Local/L-Localization-文本.xlsx`

任何新加的本地化文件都要遵守同样的命名规则。

### 2. 在生成命令中开启本地化

仓库自带的 `gen-client-json.sh` 已经显式传入了本地化相关参数:

```bash
dotnet ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json \
  --xargs outputDataDir=../Unity/Assets//Bundles/Config \
  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
  --xargs tableImporter.name=gameframex \
  -x l10n.provider=gameframex \
  -x l10n.textFile.keyFieldName=key \
  -x l10n.textFile.path=./Excels/Local/ \
  --conf ./Luban.conf
```

Source: [gen-client-json.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.sh#L1-L1)

如果你的命令缺少 `-x l10n.textFile.path=./Excels/Local/` 或 `-x l10n.provider=gameframex`,加上后重新生成即可。

### 3. 在 `luban.conf` 中声明 `localizationFileName`

`luban.conf` 中需要在生成本地化数据的 target 里加上 `localizationFileName` 字段(默认名 `Localization.xlsx`):

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

### 4. 重新生成并覆盖产物

- 客户端 JSON:`gen-client-json.sh`(或 `gen-client-json.bat`),产物落到 `%UNITY_ASSETS_PATH%/Bundles/Config`。
- 客户端二进制:`gen-client-bin.sh`,产物同样是 `Bundles/Config`,但输出格式是 `cs-bin`。
- 服务端:服务端目前不需要本地化(`server` target 没有 `localizationFileName`),如确需为服务端开启多语言,参考 `client` 的写法补齐 `localizationFileName` 字段即可。

### 5. 检查表头与 `keyFieldName`

`-x l10n.textFile.keyFieldName=key` 表示本地化表必须有一列名为 `key`。如果你的表头列名不是 `key`(例如写成 `Key` 或 `ID`),会读取失败。处理方式:在 Excel 里把首列改名为 `key`,或在生成命令里把 `keyFieldName` 改成你表里的实际列名。

## 验证

1. 重新执行对应的生成脚本,确认命令行的 `active: true` 配置未关闭。
2. 检查生成目录(例如 `Bundles/Config` 或 `%SERVER_PATH%/Server.Config/Json`)是否产生并刷新了 `Localization.xlsx` 及其衍生数据。
3. 在运行时代码里按 `key` 读取本地化,切换语言后应当返回对应译文而不是空串或源语言。
4. 如果仍然只看到 `key` 本身,说明本地化数据没有被加载——回看第 2 步的命令是否带上了 `-x l10n.textFile.path`,以及 `Excels/Local/` 下是否真的有 `L-Localization-*.xlsx`。
