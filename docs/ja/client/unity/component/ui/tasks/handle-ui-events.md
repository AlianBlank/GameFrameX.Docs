# UI ライフサイクルイベントの処理方法

`UIForm` は、オープン、クローズ、被覆、一時停止などの重要なタイミングで一連の仮想メソッドを呼び出します。サブクラスでこれらのメソッドをオーバーライドするだけで、カスタムビジネスロジックを組み込めます。また、`UIEventSubscriber` を通じてフレームワークレベルで配信されるイベントをリッスンすることもできます。

## 前提条件

- プロジェクトに `GameFrameX.UI` モジュールが導入されており、`GameFrameX.UI.UIComponent` を通じて UI を開いたり閉じたりしている。
- 業務 UI スクリプトが `UIForm` を継承している(または `IUIForm` を実装している)。
- オープン/クローズイベントをリッスンする場合は、`GameFrameX.UI.UIComponent` のインスタンス(フレームワークのエントリ)を取得する必要があります。

## 操作手順

### 1. `UIForm` のライフサイクル仮想メソッドをオーバーライドする

`UIForm` はすべてのライフサイクルフックを `virtual` として公開しており、デフォルト実装は空です。サブクラスは必要に応じて override するだけでよく、呼び出し順序を気にする必要はありません。

```csharp
using GameFrameX.UI.Runtime;
using UnityEngine;

public class MyMainForm : UIForm
{
    public override void OnInit()
    {
        // 初回インスタンス化時に実行:子コントロールの検索、コンポーネントのバインド
        base.OnInit();
    }

    public override void OnOpen(object userData)
    {
        // 毎回のオープンでトリガー:外部から渡されたデータを受け取る
        base.OnOpen(userData);
    }

    public override void OnClose(bool isShutdown, object userData)
    {
        // クローズ時のクリーンアップ
        base.OnClose(isShutdown, userData);
    }

    public override void OnPause()
    {
        // 新しい UI に覆われて一時停止
        base.OnPause();
    }

    public override void OnResume()
    {
        // 被覆状態から復帰
        base.OnResume();
    }

    public override void OnCover()
    {
        // 覆われた(必ずしも一時停止ではない)
    }

    public override void OnReveal()
    {
        // 被覆から復帰
    }

    public override void OnRefocus(object userData)
    {
        // 再フォーカス(同一 UI の複数回表示)
    }

    public override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        // 毎フレームのポーリング
    }

    public override void OnDepthChanged(int uiGroupDepth, int depthInUIGroup)
    {
        // 深度の変更(グループ内の階層)
    }

    public override void OnRecycle()
    {
        // UI フォームがリサイクルされた
    }
}
```

出典: [UIForm.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIForm.cs#L600-L900)

### 2. オープン前に初期化デリゲートを注入する(オプション)

`UIForm.Init` は `Action<IUIForm>` デリゲートを受け取り、`OnInit` の前に呼び出されます。パラメータ注入や動的な初期化に適しています:

```csharp
var form = uiComponent.OpenUIForm("Assets/UI/MyMainForm.prefab", "MyMainForm",
    uiGroup: UIGroupNameConstants.Default,
    pauseCoveredUIForm: true,
    userData: myPayload,
    onInitAction: form =>
    {
        // OnInit の前に実行
        ((MyMainForm)form).Initialize(myPayload);
    });
```

出典： [UIForm.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIForm.cs#L548-L600)

### 3. フレームワークが配信するオープン/クローズイベントをリッスンする

`UIForm` を継承したくない場合は、`GameFrameX.Event` のイベント引数をサブスクライブすることもできます:

```csharp
using GameFrameX.UI.Runtime;
using GameFrameX.Event.Runtime;

// オープン成功イベントをサブスクライブ
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnOpenSuccess);
GameEntry.Event.Subscribe(CloseUIFormCompleteEventArgs.EventId, OnCloseComplete);
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnOpenFailure);

private void OnOpenSuccess(object sender, GameEventArgs e)
{
    var args = (OpenUIFormSuccessEventArgs)e;
    // args.UIForm / args.Duration
}

private void OnCloseComplete(object sender, GameEventArgs e)
{
    var args = (CloseUIFormCompleteEventArgs)e;
    // args.SerialId / args.UIFormAssetName
}
```

利用可能なイベント型は以下の表をご覧ください。

| イベント型 | トリガータイミング | 主なフィールド |
|---|---|---|
| `OpenUIFormSuccessEventArgs` | UI のオープン成功 | `UIForm`、`Duration` |
| `OpenUIFormFailureEventArgs` | UI のオープン失敗 | `ErrorMessage`、`UIFormAssetName` |
| `OpenUIFormDependencyAssetEventArgs` | 依存リソースのロード時 | `DependencyAssetName`、`LoadedCount`、`TotalCount` |
| `CloseUIFormCompleteEventArgs` | UI のクローズ完了 | `SerialId`、`UIFormAssetName` |

出典： [OpenUIFormSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormSuccessEventArgs.cs), [CloseUIFormCompleteEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/CloseUIFormCompleteEventArgs.cs)

## よくあるバリエーション

- **`UIEventSubscriber` による疎結合化**:[UIEventSubscriber.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIEventSubscriber.cs) を参照。`Awake`/`OnDestroy` 内で `Subscribe/Unsubscribe` を使ってサブスクリプションを一元管理でき、lambda が散在するのを防げます。
- **`Show` と `Hide` のオーバーライド**:この 2 つのメソッドは `abstract` であり、サブクラスはカスタムの表示/非表示アニメーション(`IUIFormShowHandler` / `IUIFormHideHandler`)を実装する必要があります。
- **共通イベントのバインド**:`BindEvent()` をオーバーライドしてボタンクリックなどを一括登録できます。`LoadData()` や `UpdateLocalization()` と組み合わせて段階的に処理します。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `OnInit` をオーバーライドしても反映されない | `base.OnInit()` を呼び出していないため、基底クラスの初期化がスキップされている | オーバーライド時の最初の行で `base.OnInit()` を呼び出す |
| クローズ後もロジックが動き続ける | `OnClose` をオーバーライドしておらず、Unity の破棄にのみ依存している | `OnClose` 内でコルーチン、タイマー、ネットワークリクエストを停止する |
| UI が覆われた後も入力に反応し続ける | `OnPause` / `OnCover` のオーバーライドを忘れて、インタラクティブコンポーネントを無効化していない | この 2 つのメソッドをオーバーライドし、ボタンを無効化するか `interactable = false` を設定する |
| 同一 UI を繰り返し開いたときにデータが更新されない | `OnInit` は初回のみ呼び出される | 実際の更新ロジックは `OnOpen` に置き、`userData` から最新データを取得する |

## 背景(オプション)

`UIForm` は `BaseUIManager` によって一元管理されており、ライフサイクルメソッドはマネージャーが状態遷移時に呼び出します:`Open` → `OnInit` → `OnOpen`;新しい UI が開いて古い UI を覆う際には `OnCover`/`OnPause` がトリガーされ、逆の遷移では `OnReveal`/`OnResume` がトリガーされます。フレームワークはどのメソッドのオーバーライドも強制せず、業務側は必要に応じてフックポイントを選択します。空の実装は基底クラスが提供します。
