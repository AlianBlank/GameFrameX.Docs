# 設定項目の解析異常が発生した場合の対処法

`GameFrameX.Setting` が設定の読み込みまたは取得時に例外をスローする、デフォルト値を返す、または `Load()` が `false` を返す場合、通常は基盤となるストレージファイルの破損、ヘルパーが未設定、またはキー名が無効であることを示しています。このページでは、異常現象ごとに迅速な診断と修復方法を示します。

## 迅速な診断

| 症状 | 原因 | 修復 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | `SettingManager` に `ISettingHelper` が設定されていない、または `null` が渡された | 具象 Helper(デフォルトの `DefaultSettingHelper` または `PlayerPrefsSettingHelper`)をインスタンス化してから `SetSettingHelper` を呼び出す |
| `GameFrameworkException: Setting name is invalid.` | `settingName` が `null` または空文字列 | `HasSetting / GetBool / GetInt / GetFloat / GetString` などのメソッドを呼び出す前に `settingName` が空でないことを確認する |
| 起動ログに `Load settings failure with exception '{0}'.` が表示される | 設定ファイル `GameFrameworkSetting.dat` が存在しない、破損している、または権限が不足している | 破損したファイルを削除するか権限を回復してから再初期化する。詳細は下記の「修復手順」を参照 |
| 起動ログに `Save settings failure with exception '{0}'.` が表示される | 設定ディレクトリが読み取り専用、ディスクフル、またはパスが無効 | `FilePath` が指す書き込み可能性を確認し、`Application.persistentDataPath` を再指定する |
| 取得した値が常に型のデフォルト値(`false / 0 / 0f / null`)になる | キー名のスペルミス、または新バージョンで該当キーが書き込まれていない | `GetAllSettingNames()` ですべてのキーを列挙して確認するか、`defaultValue` を指定したオーバーロードをまず呼び出す |

## 修復手順

### 1. ヘルパー未設定による `Setting helper is invalid`

`SettingManager` は読み書き前に毎回 `EnsureSettingHelper()` を呼び出し、`m_SettingHelper` が `null` の場合、この例外をスローします。

Source: [SettingManager.cs#L47-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L47-L61)

```csharp
private void EnsureSettingHelper()
{
    if (m_SettingHelper == null)
    {
        throw new GameFrameworkException("Setting helper is invalid.");
    }
}
```

修復方法:

1. `SettingHelperBase` を継承した Helper のインスタンスを作成する(フレームワークには `DefaultSettingHelper`、`PlayerPrefsSettingHelper` が組み込まれています)。
2. `GameFrameworkEntry.GetModule<ISettingManager>().SetSettingHelper(helper)` を通じて注入する。
3. `SetSettingHelper(null)` 自体も同一の例外をスローするため、必ず非 null を渡すようにする。

Source: [SettingManager.cs#L126-L134](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L126-L134)

### 2. 設定ファイルの解析失敗(`Load settings failure`)

`DefaultSettingHelper.Load()` は try/catch でデシリアライズ処理をラップしており、例外はすべてログに変換されて `false` を返します。例外はスローされませんが、設定項目は空集合に戻ります。

Source: [DefaultSettingHelper.cs#L126-L146](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L126-L146)

```csharp
public override bool Load()
{
    try
    {
        if (!File.Exists(m_FilePath))
        {
            return true;
        }

        using (FileStream fileStream = new FileStream(m_FilePath, FileMode.Open, FileAccess.Read))
        {
            m_Serializer.Deserialize(fileStream);
            return true;
        }
    }
    catch (Exception exception)
    {
        Log.Warning("Load settings failure with exception '{0}'.", exception);
        return false;
    }
}
```

修復方法:

1. **ファイルが存在しない**:初回起動では正常のため、対処不要。業務上デフォルト値が必要な場合は、`Load()` が `false` を返した後に `SetBool/SetInt/...` を呼び出して書き戻す。
2. **ファイルヘッダーが一致しない**:`DefaultSettingSerializer` の `Header` は `{'G','F','S'}` で、他のプログラムによってファイルが変更されると解析に失敗します。当該 `GameFrameworkSetting.dat` を削除してから再起動する。

Source: [DefaultSettingSerializer.cs#L41-L67](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingSerializer.cs#L41-L67)
3. **ディスク/権限の問題**:`FilePath`(`Application.persistentDataPath` 等から派生)が示すディレクトリが読み書き可能であることを確認する。Windows / macOS ではアンチウイルスソフトによって隔離されていないか確認する。

### 3. キー名が空であることによる `Setting name is invalid`

`HasSetting / RemoveSetting` は `EnsureSettingName` 内で検証を行います。

Source: [SettingManager.cs#L55-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L55-L61)

```csharp
private void EnsureSettingName(string settingName)
{
    if (string.IsNullOrEmpty(settingName))
    {
        throw new GameFrameworkException("Setting name is invalid.");
    }
}
```

修復方法:設定センターからキー名を取得する際に `string.IsNullOrEmpty` 検証を行うか、`GetString(name, defaultValue)` / `GetInt(name, defaultValue)` などデフォルト値を指定したオーバーロードを使用して空キーによる例外を回避する。

### 4. 保存失敗(`Save settings failure`)

`Save()` も同様に try/catch でラップされており、例外発生時には `false` を返し、`Save settings failure with exception '{0}'.` を出力します。

Source: [DefaultSettingHelper.cs#L156-L170](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L156-L170)

修復方法:

1. `FilePath` が初期化済みであることを確認する(Helper は `SetFilePath` または初期化時に設定)。
2. 対象ディレクトリの書き込み権限を確認する。`FileMode.Create` は書き込み権限が必要。
3. `Log.Warning` の出力に含まれる `IOException`、`UnauthorizedAccessException` などの具体的な例外を捕捉し、それに応じて処理する。

## 検証

以下の順序で問題が解決されたことを確認してください:

1. `GameFrameworkEntry.GetModule<ISettingManager>().Load()` が `true` を返し、起動ログに `Load settings failure` / `Save settings failure` がもはや表示されない。
2. `GetAllSettingNames()` が返す配列に、期待されるすべてのキーが含まれている。`HasSetting("your.key")` で特定のキーの存在を確認する。
3. 設定を一度書き込み(`SetInt("score", 100)` → `Save()`)、終了して再起動した後でも `GetInt("score")` が 100 を返す。
4. `SetSettingHelper(null)` や空のキー名を渡すなどのケースで、例外パスが予期どおり `GameFrameworkException` をスローし、握りつぶされないことを確認する。
