# 下載失敗怎麼辦:排查錯誤碼與回呼

當 `DownloadComponent` 拋出 `DownloadFailureEventArgs` 或 `DownloadAgentHelperErrorEventArgs` 時，任務處於失敗狀態。本頁幫助你根據錯誤回呼裡的欄位快速定位根因並修復。

## 快速診斷

| 症狀(回呼欄位取值) | 根因 | 一句話修復 |
|---|---|---|
| `ErrorMessage` 為 `"... 416 ..."`,且 `DeleteDownloading == true`(UnityWebRequest) 或以 `"416"` 開頭(WWW) | HTTP 416 Range Not Satisfiable — 遠端不支援請求的位元組區間 | 見下方「416 Range 錯誤」修復步驟 |
| `ErrorMessage` 非空，但未包含 416 | 網路層異常(逾時、DNS 失敗、斷線、協定錯誤等) | 見下方「網路層錯誤」修復步驟 |
| `DeleteDownloading == true` 且 `ErrorMessage` 非空 | 任務寫入的檔案需要被刪除，避免殘留 | 見下方「清理失敗殘留」修復步驟 |
| 長時間無回呼、`WorkingAgentCount == TotalAgentCount` | 全部 Agent 被佔用，新任務排隊等候 | 見下方「任務卡住」修復步驟 |

> 欄位定義見 [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L38-L88) 與 [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L38-L116)。

## 修復步驟

### 1. 訂閱失敗回呼，先取得原始資訊

在 `DownloadComponent.Awake` 之後的事件訂閱位置已經註冊好 `DownloadFailure`,你只需要實作處理函式，並透過事件匯流排或 `IDownloadManager.DownloadFailure` 取得 `DownloadFailureEventArgs`:

```csharp
using GameFrameX.Download.Runtime;
using GameFrameX.Event.Runtime;

// 透過事件匯流排訂閱(建議,與元件解耦)
GameEntry.GetComponent<EventComponent>().Subscribe(
    DownloadFailureEventArgs.EventId,
    OnDownloadFailure
);

private void OnDownloadFailure(object sender, GameEventArgs e)
{
    var args = (DownloadFailureEventArgs)e;
    Debug.LogError($"[Download] FAIL serial={args.SerialId} path={args.DownloadPath} uri={args.DownloadUri} err={args.ErrorMessage} userData={args.UserData}");
}
```

Source: [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L80-L97)

### 2. 416 Range Not Satisfiable

這是框架識別的「遠端拒絕斷點續傳區間」訊號。框架判斷方式如下：

- UnityWebRequest 實作:`responseCode == 416` 時 `DeleteDownloading = true`。
- WWW 實作:`error` 字串以 `"416"` 開頭時 `DeleteDownloading = true`。

Source: [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs#L44-L44) ; [UnityWebRequestDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/UnityWebRequestDownloadAgentHelper.cs#L240-L240) ; [WWWDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/WWWDownloadAgentHelper.cs#L248-L248)

修復操作：

1. 在收到 `DeleteDownloading == true` 的失敗回呼後，刪除本機殘留的分段檔案。
2. 重新呼叫 `DownloadComponent.AddDownload(url, tag, priority, userData)`,框架會從 0 重新下載。
3. 若 CDN/OSS 不支援 `Range` 請求，關閉斷點續傳或在位址層排除此檔案類型。

### 3. 網路層錯誤(逾時 / DNS / 連線重置)

`DownloadAgentHelperErrorEventArgs.ErrorMessage` 會直接傳遞 Unity 原生錯誤字串，例如 `"Cannot resolve destination host"`、`"Request timeout"`、`"Connection failure"`。

修復操作：

1. 把 `DownloadComponent.Timeout`(預設 30 秒)按需調大，例如網際網路上的檔案改為 60 秒：見 [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60-L62)。
2. 檢查位址是否需要 HTTPS、是否被代理伺服器攔截。
3. 實作重試：在 `DownloadFailure` 回呼裡重新排入同 URL 的下載任務(注意替換 `UserData` 以便區分重試次數)。

### 4. 清理失敗殘留

當 `DownloadAgentHelperErrorEventArgs.DeleteDownloading == true` 時，框架已建議你清理本機分片：

```csharp
private void OnAgentError(object sender, GameEventArgs e)
{
    var args = (DownloadAgentHelperErrorEventArgs)e;
    if (args.DeleteDownloading && !string.IsNullOrEmpty(localPath) && File.Exists(localPath))
    {
        File.Delete(localPath);
    }
}
```

Source: [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L67-L73)

### 5. 任務卡住(佇列堆積)

長時間取不到 `DownloadSuccess` 也不觸發 `DownloadFailure`,通常是 Agent 被佔滿。監控以下屬性判斷：

| 屬性 | 含義 |
|---|---|
| `DownloadComponent.TotalAgentCount` | 總 Agent 數，預設 3 |
| `DownloadComponent.WorkingAgentCount` | 正在下載的 Agent |
| `DownloadComponent.WaitingTaskCount` | 排隊中的任務 |
| `DownloadComponent.Paused` | 是否被全域暫停 |

Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L78-L105)

修復：

1. 在 Inspector 把 `Download Agent Helper Count` 調大。
2. 確認沒人把 `DownloadComponent.Paused = true` 之後忘了恢復。
3. 用 `DownloadComponent.GetDownloadInfo(serialId)` / `GetDownloadInfos(tag)` 取得目前任務狀態。

## 驗證

按以下順序驗證問題已解決：

1. 觸發一次已知會失敗的下載(例如填錯位址或故意中斷網路)，確認能收到 `DownloadFailure` 回呼且 `ErrorMessage` 與預期一致。
2. 對 416 情境，確認回呼後本機無殘留檔案，且重新呼叫 `AddDownload` 能成功下載到完整檔案。
3. 對網路逾時情境，把 `Timeout` 調小重現一次，然後用新的逾時值重新測試直到成功。
4. 執行一次批次下載，確認 `WaitingTaskCount` 在合理時間後歸零、`FreeAgentCount` 恢復到 `TotalAgentCount`。
