# 打包設定不生效怎麼辦

當你在 `XCodeConfig.json` 裡寫的建置設定、Plist、簽署或 Capabilities 沒有反映在匯出的 Xcode 專案中時，通常是：設定檔沒被找到、JSON 解析失敗、被其他同名設定或渠道設定覆寫，或寫錯了目標節點。本頁按日誌線索逐一定位修復。

所有設定的入口是 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L25) 的 `OnPostProcessBuild`,它在 `[PostProcessBuild(888)]` 優先順序、僅 `BuildTarget.iOS` 時執行，且整個檔案處於 `#if UNITY_IOS` 條件編譯下；內部所有例外都會被 `Debug.LogException` 吞掉，**打包不會失敗，只會靜默跳過**，所以第一件事是看 Unity Console。

## 快速診斷

| 症狀(Console 日誌 / Xcode 專案表現) | 原因 | 修復 |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 檔名不是精確的 `XCodeConfig.json`,或未被 Unity 匯入為 TextAsset,或目前不是 iOS 平台建置 | 見 [修復 1:確認設定檔能被找到](#修復-1確認設定檔能被找到) |
| `{jsonPath} 解析失败, 跳过合并` | JSON 格式非法(多餘逗號、單引號、註解等) | 見 [修復 2:驗證 JSON 語法](#修復-2驗證-json-語法) |
| `合并后的配置为空，跳过设置` | 所有找到的檔案解析後均為空或失敗 | 同上，並確認檔案內有內容 |
| 設定生效了但值不對 | 專案裡存在多個 `XCodeConfig.json`,按路徑排序後逐一 `Merge`,**後合併的覆寫先合併的** | 見 [修復 3:排查同名檔案覆寫](#修復-3排查同名檔案覆寫) |
| 某項設定只在部分渠道生效/不生效 | 渠道檔案 `XCodeConfig.{channel}.json` 最後合併、優先順序最高；渠道值來自 `-channel` 參數或 EditorPrefs 的 `XCodeBuild_Channel` | 見 [修復 4:檢查渠道設定與殘留渠道](#修復-4檢查渠道設定與殘留渠道) |
| `properties` 裡的項沒寫入 Build Settings | 設定放在了頂層而不是 `unityMain` / `unityFramework` 節點下，或沒按 `"="` / `"+"` / `"-"` 三種子表組織 | 見 [修復 5:確認鍵值的結構](#修復-5確認鍵值的結構) |
| Console 有紅色例外堆疊 | 設定型別不符(如把陣列當成物件)等執行階段例外，被攔截後整段後處理中止 | 見 [修復 6:讀取例外堆疊](#修復-6讀取例外堆疊) |
| Capabilities 生效但建置屬性遺失 | Capabilities 由 `ProjectCapabilityManager` 獨立寫入磁碟，若其他外掛在其之後覆寫 `project.pbxproj` 會遺失(本工具已透過重新讀取緩解) | 見 [修復 7:排除更高優先順序的外掛覆寫](#修復-7排除更高優先順序的外掛覆寫) |

## 修復步驟

### 修復 1:確認設定檔能被找到

載入邏輯在 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58-L77):它會走訪全部 `t:textasset` 資源，只匹配**檔名完全等於** `XCodeConfig.json`(忽略大小寫)的檔案，與所在目錄無關。

1. 確認檔名精確為 `XCodeConfig.json`(不是 `XCodeConfig.json.txt`、`xcodeconfig.json.bak`)。
2. 確認檔案已被 Unity 匯入：在 Project 視窗選取它，Inspector 中應顯示為 Text Asset;目錄下應存在同名 `.meta` 檔案。
3. 確認是 iOS 建置:`OnPostProcessBuild` 中 `target != BuildTarget.iOS` 時直接 return(見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L17-L20))。
4. 確認目前平台巨集滿足 `#if UNITY_IOS`——若專案從未切換到 iOS 平台，整個組件內容不會參與編譯。

### 修復 2:驗證 JSON 語法

每個檔案用 `json.HashtableFromJson()` 解析，失敗時輸出 `解析失败, 跳过合并` 並 continue(見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L39-L45))。解析器為輕量實作，不支援註解、尾端逗號、單引號字串。用任意 JSON 驗證器(如 VS Code 的 JSON 語言服務)檢查該檔案，重點看錯誤日誌裡印出的 `{jsonPath}` 是哪一個。

### 修復 3:排查同名檔案覆寫

工具會收集專案內**所有**名為 `XCodeConfig.json` 的檔案，排序後依次合併(見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L34-L49)):

```csharp
Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    ...
    finalConfig.Merge(table);
}
```

來源:[PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L35-L49)

1. 在 Console 搜尋 `[MergeConfig] 正在合并配置:`,日誌會列出每個參與合併的檔案路徑及順序。
2. 若第三方外掛自帶 `XCodeConfig.json`,其後合併的同名鍵值會覆寫你的值——刪除、改名(改名即不再參與合併)，或把自己的值改放到渠道檔案中(渠道檔案最後合併)。

### 修復 4:檢查渠道設定與殘留渠道

渠道識別的讀取順序是：命令列參數 `-channel` → EditorPrefs 鍵值 `XCodeBuild_Channel` → null(見 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)):

```csharp
public static string GetChannel()
{
    var args = Environment.GetCommandLineArgs();
    for (int i = 0; i < args.Length - 1; i++)
    {
        if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
        {
            return args[i + 1];
        }
    }

    string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
    if (!string.IsNullOrEmpty(editorChannel))
    {
        return editorChannel;
    }

    return null;
}
```

來源:[SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)

1. 渠道檔案命名必須為 `XCodeConfig.{channel}.json`(如 `XCodeConfig.ioschina.json`),見 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111)。
2. 渠道檔案最後合併、覆寫優先順序最高——若發現「預期的值被改掉了」，先確認是否命中了某個渠道檔案；Console 會印出 `[MergeConfig] 检测到渠道: {channel}` 與 `[MergeConfig] 正在合并渠道配置: {path}`。
3. **EditorPrefs 會跨專案、跨工作階段殘留**。之前 `SetChannel("xxx")` 設定過的渠道在下次打包時仍然生效，導致合併了不想要的渠道設定。清除方式：傳入空字串刪除該鍵值(見 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51))。

```csharp
GameFrameX.Xcode.Editor.SettingLoader.SetChannel(null); // 或傳空字串,清除殘留渠道
```

來源:[SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51)

### 修復 5:確認鍵值的結構

第一階段只讀取固定的頂層鍵值並分發給目標，見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L126):

| 頂層鍵值 | 寫入目標 | 說明 |
|------|---------|------|
| `unityMain` | UnityMain(主)target | properties / frameworks / libs / files / folders / filesCompileFlag / otherLinkerFlag / runPathSearchPaths / pods |
| `unityFramework` | UnityFramework target | 同上 |
| `signing` | 主 target | 簽署，同時取 `bundleId` 供 Capabilities 使用 |
| `plist` | Info.plist | 見 `RunPlist` |
| `environmentVariables` | scheme 環境變數 | 見 `RunEnvironmentVariables` |
| `launcherArgs` | scheme 啟動參數(陣列) | 見 `RunArgument` |
| `capabilities` | 主 target | Capabilities |
| `localizations` | 專案(陣列) | 在地化資源 |
| `podfile` / `podSource` | Podfile | 完整 Podfile 路徑 / 來源位址清單 |
| `swiftBridging` | bool,預設 true | Swift 橋接 |
| `podInstall` | bool,預設 true | 是否自動執行 `pod install` |

`properties` 內部再按 `"="`(直接 set)、`"+"`(向清單附加)、`"-"`(從清單移除)三張子表處理(見 [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L57)):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}
```

來源:[PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L20-L25)

常見寫錯:`properties` 放在頂層而不是 `unityMain.properties` 下；把應放入 `"+"` 的清單值寫進 `"="`;鍵值名稱拼寫大小寫不一致(Hashtable 鍵值區分大小寫)。

### 修復 6:讀取例外堆疊

整個流程包在 `try/catch` 中，例外只 `Debug.LogException`、不中斷打包(見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L158-L161))。若 Console 出現例外，例外點**之後**的所有設定都不會執行——例如 `plist` 前拋出例外，則 `capabilities`、`podfile`、`pod install` 全部被跳過。按堆疊定位到具體鍵值，通常是型別不符(物件寫成了陣列、字串寫成了數字)。

### 修復 7:排除更高優先順序的外掛覆寫

本工具以 `[PostProcessBuild(888)]` 執行，晚於大多數後處理(見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L15))。若你的其他外掛回呼優先順序大於 888,或直接編輯 `project.pbxproj` / Info.plist 而未基於本工具寫入磁碟後的內容，就會把設定覆寫掉。另注意：Capabilities 透過 `ProjectCapabilityManager` 獨立寫入磁碟，本工具在其之後重新讀取 `project.pbxproj` 再繼續寫 Localization(見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L121-L123));確認沒有第三方程式碼在這之後覆寫專案檔案。

## 驗證

1. 重新執行一次 iOS 建置，Console 中應依次出現：
   - 每個參與檔案的 `[MergeConfig] 正在合并配置: {path}`;
   - 若有渠道:`[MergeConfig] 检测到渠道: {channel}`;
   - `[PBXProject] 正在应用最终合并配置...` 與 `[OtherSettings] 正在应用最终合并配置...`;
   - 沒有任何紅色例外。
2. 開啟匯出目錄 `Unity-iPhone.xcodeproj/project.pbxproj`,搜尋你設定的建置屬性名稱，確認值已更新。
3. 檢查 `Info.plist` 中 `plist` 節點寫入的鍵值。
4. 在 Xcode 中選擇主 target,Signing & Capabilities 頁應顯示 `capabilities` 設定的項目;`project.entitlements` 應存在對應條目。
