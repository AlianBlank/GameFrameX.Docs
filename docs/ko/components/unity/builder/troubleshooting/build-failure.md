# 빌드 실패 및 명령줄 매개변수 오류 해결 방법

명령줄을 통해 빌드 프로세스를 호출할 때 빌드 실패는 거의 항상 "매개변수 누락 / 오타 / 잘못된 값" 또는 "선행 단계 미완료"로 인해 발생합니다. 이 페이지에서는 오류 메시지 원문에 따라 근본 원인과 수정 방법을 제공합니다.

## 빠른 진단

| 증상(오류 메시지 원문/키워드) | 근본 원인 | 해결 방법 |
|---|---|---|
| `executeMethod is null` | `-ExecuteMethod`로 진입 메서드 이름을 전달하지 않음 | 명령줄에 `-ExecuteMethod <네임스페이스.클래스.메서드>` 추가 |
| `build number is null` | `-BuildNumber`로 빌드 번호를 전달하지 않음 | 명령줄에 `-BuildNumber <버전 번호>` 추가 |
| `잘못된 빌드 파이프라인 유형: <xxx>, 선택 가능한 값: BuiltinBuildPipeline, ScriptableBuildPipeline, RawFileBuildPipeline` | `-BuildPipeline` 값이 올바른 열거형 이름이 아님 | 값을 `BuiltinBuildPipeline`, `ScriptableBuildPipeline`, `RawFileBuildPipeline` 중 하나로 변경 |
| `잘못된 내장 파일 복사 옵션: <xxx>, 선택 가능한 값: None, ClearAndCopyAll, ClearAndCopyByTags, OnlyCopyNew` | `-BuildinFileCopyOption` 값이 잘못됨 | 값을 `None`, `ClearAndCopyAll`, `ClearAndCopyByTags`, `OnlyCopyNew` 중 하나로 변경; 전달하지 않으면 기본값은 `ClearAndCopyAll` |
| 로그에 도구 출력이 전혀 없고 Unity가 종료됨 | `LogFilePath`가 가리키는 위치에 쓸 수 없거나, 빌드 번호가 비어 있어 경로 유도에 실패 | `-LogFilePath` 디렉터리 권한을 확인하거나, `-BuildNumber`를 명시적으로 제공 |
| `-BuildPipeline`/`-PackageVersion` 등 값이 있는 매개변수가 적용되지 않음 | 값을 매개변수에 붙여 `-BuildPipelineBuiltinBuildPipeline`처럼 작성함 | 매개변수와 값 사이에 **반드시 공백**이 있어야 함, `-BuildPipeline BuiltinBuildPipeline`처럼 작성 |
| BuildAsset은 정상이나 BuildPlayer(패키징) 단계에서 빨간색 오류 | 선행 `BuildAsset`이 실행되지 않았거나, 핫업데이트/AOT 코드 디렉터리가 비어 있음 | 먼저 `BuildAsset`을 실행하고, `Assets/.../Hotfix/`, `AOT/` 디렉터리에 내용이 있는지 확인한 후 패키징 |

## 수정 단계

### 1. 필수 매개변수 세 가지 채우기

파서는 `-ExecuteMethod`, `-BuildNumber`, `-LogFilePath`(후자는 전달되지 않을 때 앞의 두 항목으로 자동 유도시키지만 명시적 제공 권장)을 필수로 요구합니다. 명령 예시:

```bash
Unity \
  -batchmode -nographics -quit \
  -projectPath /path/to/project \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
  -BuildNumber 1.0.0.1 \
  -LogFilePath ../Logs/BuildAsset_1.0.0.1.log \
  -ChannelName default \
  -PackageName DefaultPackage
```

하나라도 누락되면 `Exception`이 발생하고 프로세스가 즉시 종료됩니다. 출처:[Editor/Builder.BuildParamsParse.cs#L175-L189](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L175-L189).

### 2. `-BuildPipeline`과 `-BuildinFileCopyOption` 값 수정

이 두 매개변수는 모두 `Enum.TryParse`로 검증되며, 대소문자는 구분하지 않지만 **반드시 열거형 이름**이어야 하고, 숫자나 오타가 있어서는 안 됩니다:

- `-BuildPipeline`:선택 가능한 값 `BuiltinBuildPipeline`(기본값), `ScriptableBuildPipeline`, `RawFileBuildPipeline`
- `-BuildinFileCopyOption`:선택 가능한 값 `None`, `ClearAndCopyAll`(기본값), `ClearAndCopyByTags`, `OnlyCopyNew`

```bash
  -BuildPipeline BuiltinBuildPipeline \
  -BuildinFileCopyOption ClearAndCopyAll \
```

검증 로직:[Editor/Builder.BuildAsset.cs#L40-L84](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L84).

### 3. `-xxx <값>` 사이에 공백으로 구분

파서는 `commandLineArgs`를 항목별로 스캔하고 각 switch에서 `index + 1`로 다음 요소를 가져오므로, 매개변수와 값 사이에는 반드시 공백이 있어야 합니다(`=` 사용 불가, 연속 작성 불가). 출처:[Editor/Builder.BuildParamsParse.cs#L152-L172](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L152-L172).

올바름:`-PackageVersion 20240101120000`
틀림:`-PackageVersion=20240101120000`, `-PackageVersion20240101120000`

### 4. 먼저 `BuildAsset` 실행 후 `BuildPlayer` 실행

`BuildAsset`은 내부적으로 핫업데이트 및 AOT 어셈블리를 복사하고 AssetDatabase를 새로 고친 다음 YooAsset 패키징을 호출합니다. 패키징 명령을 직접 실행했는데 핫업데이트 코드가 누락되거나, "어셈블리를 찾을 수 없음"이라는 빌드 오류가 발생하거나, 리소스 패키징이 비어 있는 경우, 일반적으로 리소스 패키징 단계를 건너뛴 것입니다. 수정:파이프라인을 두 단계로 분리하여 먼저 `BuildAsset`을 실행한 다음 `BuildPlayerAndroid`/`BuildPlayerIOS`를 실행합니다. 출처:[Editor/Builder.BuildAsset.cs#L15-L27](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L15-L27), [Editor/Builder.cs#L60-L66](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L60-L66).

### 5. `-BundleId` / `-AppVersion`이 실제로 적용되도록 하기

이 두 매개변수는 비어 있지 않은 문자열이 전달될 때만 `PlayerSettings`를 덮어씁니다. 명령줄에서 전달했지만 `PlayerSettings`가 변경되지 않은 경우, 양쪽 모두에 불필요한 공백이나 줄 바꿈이 없는지 확인하세요(코드에서 `Trim` 수행). 출처:[Editor/Builder.BuildParamsParse.cs#L194-L202](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L194-L202).

## 검증

1. 명령줄 첫 줄에 `executeMethod is null` / `build number is null`이 더 이상 나타나지 않으면 필수 매개변수가 채워진 것입니다.
2. Edit/Console에서 `-----------构建参数开始-----------` 다음 줄에 `_builderOptions`의 JSON 출력이 있는지 확인하여 모든 매개변수가 올바르게 구문 분석되었는지 확인합니다. 출처:[Editor/Builder.BuildParamsParse.cs#L191-L193](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L191-L193).
3. `BuildAsset` 완료 후 로그에 `BuildAsset End`가 포함되어 있어야 하며, 이후 `BuildPlayer*`를 시작해야 리소스 누락으로 인한 실패가 발생하지 않습니다. 출처:[Editor/Builder.BuildAsset.cs#L99-L100](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L99-L100).

## 배경(선택 사항)

도구는 `Builder.BuildParamsParse`가 명령줄을 구문 분석 → `BuilderOptions`에 기록 → `BuildAsset` / `BuildPlayer*`로分发합니다. 검증은 구문 분석 단계(`Exception` 발생)와 `BuildAsset` 시작점의 열거형 `TryParse`에 집중되어 있으므로, "빌드 실패"는 거의 이 두 계층에서 차단되며, 실제로 YooAsset / Unity 패키징 자체에 대한 문제 해결이 필요한 경우는 오히려 드뭅니다.
