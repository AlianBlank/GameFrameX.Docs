# EntityBase / EntityBaseId を継承してエンティティを作成する方法

フレームワークの `EntityBase` / `EntityBaseId` エンティティ基底クラスを継承することで、エンティティクラスは主キー、監査フィールド、論理削除フラグ、楽観ロックのバージョン番号、有効化フラグなどの共通フィールドを自動的に取得でき、各エンティティで重複して宣言する必要がなくなります。

## 前提条件

- プロジェクトが `GameFrameX.Foundation.Orm.Entity` アセンブリを参照していること。
- C# の `Key` / `Required` などのデータアノテーション属性をサポートする ORM（SqlSugar / Entity Framework など）を使用していること。

## 操作手順

### 1. 主キーフィールドのみ必要：`EntityBaseId` / `EntityBaseId<TKey>` を継承

エンティティが主キーのみを必要とし、作成者、更新時間、論理削除などの監査フィールドを気にしない場合は、`EntityBaseId` を継承してください。デフォルトの主キー型は `long` で、`Key` および `Required` 属性が付いています。

```csharp
using System.ComponentModel.DataAnnotations;
using GameFrameX.Foundation.Orm.Entity;

public class Dictionary
{
    // 業務フィールド
    public string Code { get; set; }
    public string Name { get; set; }
}
```

主キーが `long` 以外の場合は、汎用バージョンを使用して主キー型を指定してください（`TKey` は非null型である必要があります）：

```csharp
public class Dictionary<TKey>
    where TKey : notnull
{
    // 主キー Id は基底クラスで宣言済み
    public string Code { get; set; }
    public string Name { get; set; }
}
```

Source: [EntityBaseId.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L44-L82)

### 2. 完全な監査フィールド：`EntityBase` / `EntityBase<TKey>` を継承

ほとんどの業務エンティティは監査、論理削除、楽観ロック、有効化フラグなどのフィールドを必要とするため、直接 `EntityBase` を継承してください。基底クラスはすでに `ISafeDeletedFilter`、`IVersionedEntity`、`ISafeEnabledFilter`、`ISafeCreatedFilter`、`ISafeUpdateFilter` などのインターフェースを実装しており、フレームワークが自動的にこれらのフィルター条件を適用します。

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class PlayerEntity : EntityBase
{
    // 基底クラスで提供済み:Id、CreatedId、CreatedTime、CreatedName、
    //                    UpdateCount、UpdateTime、UpdatedId、UpdatedName、
    //                    IsDeleted、DeleteTime、DeletedId、DeletedName、
    //                    RowVersion、IsEnabled
    public string Name { get; set; }
    public int Level { get; set; }
}
```

`long` 以外の主キーを使用する場合は、汎用バージョンを使用してください：

```csharp
public class PlayerEntity<TKey> : EntityBase<TKey>
    where TKey : notnull
{
    public string Name { get; set; }
    public int Level { get; set; }
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L180)

### 3. 必要に応じて基底クラスのプロパティをオーバーライド

基底クラスのフィールドはすべて `virtual` 修飾子が付いているため、サブクラスで `override` を使用してデフォルト値や追加属性を調整できます。例えば、新規作成時に `IsDeleted` を `null` にすることができます：

```csharp
public class OrderEntity : EntityBase
{
    public override bool? IsDeleted { get; set; }

    public string OrderNo { get; set; }
}
```

## 一般的なバリエーション

| シーン | 基底クラス | 主な機能 |
|------|------|----------|
| 主キーのみ必要 | `EntityBaseId` / `EntityBaseId<TKey>` | `Id` 主キーフィールド |
| 完全な監査 + 論理削除 + 楽観ロック + 有効化フラグ | `EntityBase` / `EntityBase<TKey>` | 上記すべての基底クラスの機能 |
| テナント分離もさらに必要 | `EntityTenantBase` / `EntityTenantBase<TKey>` | `EntityBase` に `TenantId` フィルターを追加 |
| 拡張クエリフィルターもさらに必要 | `EntitySelectBase` / `EntitySelectBase<TKey>` | `EntityBase` に `Select` フィルターを追加 |

## よくあるエラー

- **`where TKey : notnull` を書き忘れる**：汎用基底クラスを使用する場合、この制約を追加する必要があります。追加しないとコンパイルに失敗します。基底クラス自体もこの制約を強制しています（[EntityBaseId.cs L67-L68](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L67-L68)）。
- **`Id` フィールドを手動で重複宣言する**：`Id` はすでに基底クラスで提供されているため、サブクラスで再度宣言しないでください。基底クラスのメンバーの非表示に関するコンパイル警告が発生し、ORM マッピングが壊れる原因となります。
- **エンティティクラスを `abstract` 以外にしている**：基底クラスは `abstract` であるため、具体的なエンティティも `abstract` にすることを推奨しますが、業務クラスはこれ以上継承されないようにすべきです。
- **カスタム主キー型で `[Key]` を忘れる**：`Id` にはすでに `[Key]`、`[Required]` が付いています。主キーを認識するために属性に依存する ORM を使用している場合、追加の注釈は不要です。再定義する場合にのみ `[Key]` を再度追加してください。

## 背景情報（オプション）

`EntityBase` は `EntityBaseId` の上に 5 つのフィルターインターフェース（`ISafeDeletedFilter`、`ISafeEnabledFilter`、`ISafeCreatedFilter`、`ISafeUpdateFilter`、`IVersionedEntity`）を集約しており、フレームワークは SQL を生成する際にこれらのインターフェースを読み取り、`IsDeleted = 0`、`IsEnabled = 1`、楽観ロックなどの条件を自動的に追加します。そのため、業務側での手動処理は不要です。`EntityTenantBase` と `EntitySelectBase` は、これを基盤としてテナント分離と拡張クエリフィルターを重ねたシナリオ別の基底クラスです。
