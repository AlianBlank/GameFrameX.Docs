# Accessing Serializable Object Configuration

Use the `GetObject<T>` and `SetObject<T>` interfaces of `SettingComponent` to read and write any object marked with `[Serializable]` to the game configuration storage using a single string key.

## Prerequisites

- `GameFrameXSettingCroppingHelper` and `SettingComponent` must be attached to the project (the latter automatically requires the former via `[RequireComponent]`).
- The type to be stored must be marked with `[System.Serializable]`, and its fields will be serialized by `UnityEngine.JsonUtility`.
- Obtain the manager instance via `GameFrameworkEntry.GetModule<ISettingManager>()`, or call the storage API after `SettingComponent.Awake()` has completed.

## Steps

1. **Define the serializable configuration class**. The type must be marked with `[Serializable]`, and the fields must be `public` or have `[SerializeField]`:

   ```csharp
   using System;
   using UnityEngine;

   [Serializable]
   public class PlayerProfile
   {
       public string playerId;
       public int level;
       public bool vip;
       public Vector3 lastPosition;
   }
   ```

2. **Obtain the configuration manager**. After the component is initialized, access it directly through the component instance:

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingComponent = UnityEngine.Object.FindObjectOfType<SettingComponent>();
   ISettingManager settingManager = settingComponent.GetComponent<SettingComponent>() != null
       ? GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>()
       : null;
   ```

   You can also cache a reference to the component and read the `ISettingManager` module from `settingComponent` directly when needed.

3. **Write the object**. Call `SetObject<T>(string settingName, T value)`. The framework internally uses `JsonUtility.ToJson` to convert it to a string before writing to the underlying storage:

   ```csharp
   var profile = new PlayerProfile
   {
       playerId = "p-1001",
       level = 12,
       vip = true,
       lastPosition = new Vector3(1.5f, 0f, -3.2f),
   };

   settingManager.SetObject("profile.current", profile);
   settingManager.Save();
   ```

   Source: [SettingManager.cs#L300-L320](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L300-L320)

4. **Read the object**. Retrieve it via `GetObject<T>(string settingName)`. If the key does not exist, it returns `null` (the overload `GetObject<T>(string settingName, T defaultValue)` returns the default value when missing):

   ```csharp
   if (settingManager.HasSetting("profile.current"))
   {
       PlayerProfile loaded = settingManager.GetObject<PlayerProfile>("profile.current");
       Debug.Log($"Welcome back, {loaded.playerId}, level {loaded.level}");
   }
   ```

5. **Delete and clear**. Objects and primitive types share the same storage:

   ```csharp
   settingManager.RemoveSetting("profile.current");  // Remove a single key
   settingManager.RemoveAllSettings();                // Clear all
   ```

## Common Variants

| Scenario | Usage | Description |
|------|------|------|
| Default value fallback | `GetObject<PlayerProfile>("profile.current", defaultProfile)` | Returns the provided default value object when the key does not exist |
| List all keys | `string[] keys = settingManager.GetAllSettingNames();` | Quickly locate stored object names during debugging |
| Cross mini-game platforms | Use platform implementations such as `WeChatMiniGameSettingStorage` | Switch the underlying backend via `SettingStorageBackendFactory`; the API remains consistent |
| Complex nesting | `[Serializable] class Wrapper { public PlayerProfile profile; public Settings settings; }` | `JsonUtility` supports nested `[Serializable]` types, but does not support dictionaries/interfaces |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | `GetObject`/`SetObject` was called before `SettingComponent.Awake()` | Wait for the component to finish initializing, or place read/write logic in the business module's `Start`/`Awake` phase |
| `GameFrameworkException: Setting name is invalid.` | The passed `settingName` is `null` or an empty string | Perform `string.IsNullOrEmpty` validation before calling |
| All read fields are default values | Fields are declared as `private` without `[SerializeField]` | Add `[SerializeField]` to the fields, or change them to `public` |
| Dictionary/interface members are dropped | `JsonUtility` does not support `Dictionary`, interfaces, or properties | Use `List<T>` instead, or define a custom serializable wrapper class |
| Changes are not persisted | `Save()` was not called after writing | Call `settingManager.Save()` after writing; the framework automatically calls `Save` during `Shutdown` |

## Background (Optional)

`SettingManager` uniformly maps objects and primitive types to the underlying `ISettingHelper`, which serializes the string via `JsonUtility.ToJson` and then delegates to `ISettingStorageBackend` (default: `UnityPlayerPrefsSettingStorage`) for persistence. When reading, it reverses the process with `JsonUtility.FromJson<T>`, so only objects that can be handled by `JsonUtility` can be accessed. For information on switching the underlying storage backend, see "Custom Setting Storage Backend".
