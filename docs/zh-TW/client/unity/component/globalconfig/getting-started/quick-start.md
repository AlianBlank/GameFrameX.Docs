# 快速開始

`GlobalConfig` 是 GameFrameX 的全域設定元件，用於集中管理應用程式版本檢查網址、資源版本檢查網址、主機伺服器位址以及可自訂的額外內容。本節將引導您完成安裝、掛載元件與讀取設定的完整流程。

## 前置條件

- Unity 2019.4 或以上版本。
- 需已安裝 `com.gameframex.unity` 與 `com.gameframex.unity.web` 兩個相依套件(最新穩定版本請參閱 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/README.zh-CN.md#L76-L80))。
- `GlobalConfigComponent` 繼承自 `GameFrameworkComponent`,因此必須已有 GameFrameX 框架的進入場景(包含 `GameFramework` 元件)。

## 安裝

請選擇以下任一方式完成安裝：

1. **修改 `Packages/manifest.json`(建議)**，新增 GameFrameX scoped registry:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.globalconfig": "1.3.2"
     }
   }
   ```

2. **直接透過 Git URL 新增**，寫在 `manifest.json` 的 `dependencies` 之下：

   ```json
   {
     "dependencies": {
       "com.gameframex.unity.globalconfig": "https://github.com/gameframex/com.gameframex.unity.globalconfig.git"
     }
   }
   ```

3. **Unity Package Manager → Add package from git URL**,輸入 `https://github.com/gameframex/com.gameframex.unity.globalconfig.git`。

4. **本機原始碼安裝**：將儲存庫目錄複製到專案的 `Packages/` 底下，Unity 會自動辨識。

## 操作步驟

1. **將元件掛載到框架進入點**。在進入 GameObject 上點擊 `Add Component → GameFrameX → Global Config` 來新增 `GlobalConfigComponent`。元件本身會在 `Awake` 中停用自動註冊(`IsAutoRegister = false`),需要在適當時機手動呼叫：

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   using UnityEngine;

   public class GlobalConfigBootstrap : MonoBehaviour
   {
       [SerializeField] private GlobalConfigComponent m_GlobalConfig;

       private void Start()
       {
           // 於啟動流程中呼叫,將元件註冊到 GameFrameX 框架
           GameFrameX.Runtime.GameFrameworkEntry.RegisterComponent(m_GlobalConfig);
       }
   }
   ```

   `Awake` 與元件特性的定義請參閱 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L11-L13)。

2. **填寫基本欄位**。在 Inspector 中至少輸入 `Check App Version Url` 或 `Check Resource Version Url` 其中之一，並視需要設定 `Host Server Url`、`Content`、`AOT Code List`。所有欄位都是元件中以 `[SerializeField]` 暴露的字串欄位，定義請參閱 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L18-L98)。

3. **從伺服器取得設定並注入**。使用任意 HTTP 用戶端請求全域資訊介面，將 JSON 反序列化為 `ResponseGlobalInfo` 後呼叫 `SetGlobalConfig`:

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   using GameFrameX.Runtime;

   var component = GameFrameworkEntry.GetComponent<GlobalConfigComponent>();
   var rawJson = "<伺服器回傳的 JSON>";
   var info = Utility.Json.ToObject<ResponseGlobalInfo>(rawJson);
   component.SetGlobalConfig(info);
   ```

   `ResponseGlobalInfo` 的欄位定義請參閱 [ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L6-L27)。`SetGlobalConfig` 會執行 null 值驗證並拋出 `ArgumentNullException`,簽章請參閱 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L160-L168)。

4. **在遊戲邏輯中讀取**。透過 `GameFrameworkEntry.GetComponent<GlobalConfigComponent>()` 取得實例，然後存取對應屬性：

   ```csharp
   var globalConfig = GameFrameworkEntry.GetComponent<GlobalConfigComponent>();
   string appVersionUrl = globalConfig.CheckAppVersionUrl;
   string resourceUrl   = globalConfig.CheckResourceVersionUrl;
   string hostUrl       = globalConfig.HostServerUrl;
   string extra         = globalConfig.Content;

   ResponseGlobalInfo info = globalConfig.GlobalInfo;
   string serverAotJson    = info?.AOTCodeList;
   ```

   `AOTCodeList` 是 JSON 字串，賦值時會自動解析為 `AOTCodeLists` 清單。解析失敗時會輸出錯誤日誌，但不會拋出例外([GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L46-L79))。

## 常見變體

- **只想儲存原始 JSON 字串的情況**：呼叫 `SetOriginalData(json)` 直接儲存，並由外部解析。簽章請參閱 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L126-L134)。
- **在 Inspector 中編輯 AOT 清單**：自 1.3.2 起，`AOTCodeLists` 已改為唯讀，清單會在透過 `AOTCodeList` JSON 欄位賦值後自動解析。詳情請參閱 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L51-L79) 及版本說明。
- **執行時切換伺服器位址**：直接對 `CheckAppVersionUrl`、`CheckResourceVersionUrl`、`HostServerUrl` 賦值即可，這些屬性都具有 setter。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `GetComponent<GlobalConfigComponent>()` 回傳 `null` | 元件未被手動註冊(`IsAutoRegister = false`) | 在啟動腳本中呼叫 `GameFrameworkEntry.RegisterComponent(m_GlobalConfig)` |
| `SetGlobalConfig(null)` 拋出 `ArgumentNullException` | 參數為 null | 呼叫前確認非 null,確保伺服器回傳有效物件 |
| `AOTCodeLists` 一直為空 | `AOTCodeList` 不是正確的 JSON 字串 | 確認伺服器下發的 JSON 是否為 `["a.dll","b.dll"]` 形式；失敗時主控台會輸出 `Log.Error` |
| 伺服器下發後 `GlobalInfo` 為 `null` | 尚未呼叫 `SetGlobalConfig` 或 `SetOriginalData` | 在請求成功回呼中呼叫 `SetGlobalConfig` |

## 背景(可選)

`GlobalConfigComponent` 是 `sealed` 的 `GameFrameworkComponent`,會在 `Awake` 中停用自動註冊，因此業務端需要自行控制其生命週期。它只持有設定，不會主動發起網路請求；`RequestBase` 與各 `Request*` / `Response*` 型別僅是配套的請求/回應資料載體，邏輯由呼叫方決定。
