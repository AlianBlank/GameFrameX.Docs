# 캐시 정리 및 리소스 패키지 수명 주기 관리 방법

이 페이지에서는 `GameFrameX.Asset`에서 캐시 파일 정리, 리소스 언로드, 그리고 YooAssets 리소스 패키지의 수명 주기 관리(소멸, 기본 패키지 전환)에 대해 설명합니다.

## 사전 조건

- `AssetComponent`를 통해 YooAssets를 초기화하고, 최소 하나의 `ResourcePackage`가 존재해야 합니다.
- 비즈니스 측에서 `GameFramework.GetComponent<AssetComponent>()` 인스턴스를 가져옵니다.
- [기본 패키지명 상수](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L170-L183)와 패키지명 매개변수 규칙을 이해합니다.

## 작업 단계

### 1. 단일 리소스 언로드(참조 카운트 1 감소)

기본 패키지 사용:

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAsset("Assets/Prefabs/Hero.prefab");
```

패키지명 지정:

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAsset("pkg_battle", "Assets/Prefabs/Hero.prefab");
```

내부적으로 `package.TryUnloadUnusedAsset(assetPath)`를 호출합니다. 출처: [AssetManager.cs#L100-L124](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L100-L124)

### 2. 미사용 리소스 비동기 언로드(GC 친화적)

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadUnusedAssetsAsync();                // 기본 패키지
GameFramework.GetComponent<AssetComponent>()
    .UnloadUnusedAssetsAsync("pkg_battle");    // 패키지 지정
```

참조 카운트가 0인 리소스만 회수하며, 씬 전환 시 호출하기에 적합합니다. 출처: [AssetManager.cs#L150-L163](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L150-L163)

### 3. 패키지 내 모든 리소스 비동기 강제 회수

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAllAssetsAsync();
```

참조 카운트에 관계없이 해당 패키지에서 로드한 모든 리소스를 강제로 해제합니다. 출처: [AssetManager.cs#L127-L144](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L127-L144)

### 4. 사용하지 않는 Bundle 캐시 파일 정리

```csharp
GameFramework.GetComponent<AssetComponent>()
    .ClearUnusedBundleFilesAsync();
```

어떤 리소스에서도 참조되지 않는 Bundle 파일만 삭제하며, 이미 로드된 리소스는 언로드하지 않습니다. 출처: [AssetManager.cs#L189-L201](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L189-L201)

### 5. 패키지 내 모든 Bundle 캐시 비우기

```csharp
GameFramework.GetComponent<AssetComponent>()
    .ClearAllBundleFilesAsync();
```

먼저 `UnloadAllAssetsAsync`를 호출한 다음 `ClearUnusedBundleFilesAsync`를 호출하여 완전히 해제합니다. 출처: [AssetManager.cs#L165-L183](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L165-L183)

### 6. 기본 리소스 패키지 전환

```csharp
var pkg = YooAssets.GetPackage("pkg_main");
GameFramework.GetComponent<AssetComponent>()
    .SetDefaultAssetsPackage(pkg);
```

이후 `packageName`을 지정하지 않는 로드/언로드 작업은 모두 새로운 기본 패키지에 대해 수행됩니다. 출처: [IAssetManager.cs#L443-L444](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L443-L444)

## 일반적인 변형

| 시나리오 | 권장 API | 설명 |
|------|----------|------|
| 씬 전환 시 이전 씬 리소스 해제 | `UnloadUnusedAssetsAsync` | 참조 없는 리소스만 회수하여 잘못된 해제 방지 |
| 인스턴스 종료 시 전체 패키지 해제 | `UnloadAllAssetsAsync` + `ClearUnusedBundleFilesAsync` | 메모리 해제와 캐시 정리 모두 수행 |
| 패키지 재설치 전 완전 정리 | `ClearAllBundleFilesAsync` | 리소스+캐시 정리를 한 줄로 완료 |
| 필요에 따라 단일 리소스 해제 | `UnloadAsset(path)` | 참조 카운트 1 감소 |

## 일반적인 오류

- **`packageName`이 null이지만 패키지가 생성되지 않음**: 언로드/정리를 호출하기 전에 반드시 먼저 `CreatePackage`를 호출하고 `Initialize`해야 합니다. 그렇지 않으면 `YooAssets.GetPackage`가 `null`을 반환하고, 메서드 내부에 `null` 판단이 있으므로 오류가 발생하지는 않지만 작업이 조용히 실패합니다.
- **`UnloadAsset` 참조 카운트가 0이 되지 않음**: 동일한 리소스를 반복적으로 로드하면 카운트가 증가하므로, 실제로 해제하려면 동일한 횟수의 `UnloadAsset`이 필요합니다.
- **"리소스 언로드"와 "캐시 정리" 혼동**: `UnloadUnusedAssetsAsync`는 메모리만 정리합니다. 디스크 Bundle 파일은 `ClearUnusedBundleFilesAsync` 또는 `ClearAllBundleFilesAsync`를 사용해야 합니다.
- **강제 회수 직후 리소스 접근**: `UnloadAllAssetsAsync`는 비동기 작업이므로, `yield return` 또는 콜백이 완료된 후에 해당 자산을 조작해야 합니다. 그렇지 않으면 이미 소멸된 객체를 가져오게 됩니다.

## 배경(선택 사항)

`AssetManager`의 모든 정리 API는 YooAssets의 `ResourcePackage` 객체로 전달됩니다. `UnloadAsset`은 `TryUnloadUnusedAsset`(참조 카운트)을 거치고, `UnloadUnusedAssetsAsync`와 `UnloadAllAssetsAsync`는 메모리를 해제하며, `ClearUnusedBundleFilesAsync`는 디스크를 삭제합니다. `ClearAllBundleFilesAsync`는 메모리와 캐시를 동시에 정리하는 조합 동작입니다.
