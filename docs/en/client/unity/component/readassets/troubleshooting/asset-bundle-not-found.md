# What to Do When Loading an AssetBundle Throws FileNotFoundException

When calling `BlankReadAssets.LoadAssetBundle` or `BlankReadAssets.LoadAssetBundleAsync`, if the relative path passed in does not match any resource in StreamingAssets, the framework will directly throw `System.IO.FileNotFoundException("File not found", path)`. This is the most common signal of a path resolution failure.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `FileNotFoundException: File not found` (message contains the passed `path`) | No file matches the path; commonly caused by wrong case, wrong slash, or the file not being placed under StreamingAssets | Pre-check with `FileExists`; use relative paths with `/` separator uniformly; confirm the resource is under `Assets/StreamingAssets/` |
| Works in Editor but fails on an Android device after build | The resource is compressed inside the APK, and the default `AssetBundle.LoadFromFile` cannot read it | Call `BlankReadAssets.SetCompressedAssetBundleFileNames(...)` to register the compressed file list |
| Resource actually exists but is reported as missing before the exception is thrown | The path prefix is written as `StreamingAssets/xxx`, but the framework has already implicitly stripped this prefix | Remove the `StreamingAssets/` prefix and pass only the relative subpath |

## Fix Steps

### 1. Pre-check the Path with FileExists

`BlankReadAssets.LoadAssetBundle` internally calls `GetInfoOrThrow` first, and if the file is not found it calls `ThrowFileNotFound` to throw an exception directly. Using `FileExists` to check first can quickly determine whether the path is wrong or the resource is missing:

```csharp
if (!BlankReadAssets.FileExists("ui/prefab/main.ab"))
{
    Debug.LogError("AssetBundle does not exist, please confirm it has been placed under StreamingAssets");
    return;
}
var bundle = BlankReadAssets.LoadAssetBundle("ui/prefab/main.ab");
```

The original exception and trigger location are as follows:

```csharp
private static void ThrowFileNotFound(string path)
{
    throw new FileNotFoundException("File not found", path);
}
```

### 2. The Path Must Be a Subpath Relative to StreamingAssets and Use `/`

The framework's `LooseFilesImpl.TryGetInfo` concatenates the passed path with `s_root` and then calls `File.Exists`:

```csharp
var fullPath = s_root + path;
if ( !File.Exists(fullPath) )
{
    return false;
}
info.readPath = fullPath;
```

Source: [BlankReadAssets.LooseFilesImpl.cs#L57-L71](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L57-L71)

- Correct: `"ui/prefab/main.ab"` (corresponds to `Assets/StreamingAssets/ui/prefab/main.ab`)
- Incorrect: `"StreamingAssets/ui/prefab/main.ab"`, `"ui\\prefab\\main.ab"`, absolute paths
- Case-sensitive: The Android device file system strictly distinguishes case

### 3. Identifying Compressed AssetBundles in APK

`AssetBundle.LoadFromFile` can only read uncompressed files inside an APK by default. If your build pipeline compresses `.ab` files into the APK, you need to register the list of compressed files before use; otherwise, the underlying `LoadFromFile` will throw `FileNotFoundException` or return a corrupted bundle. See `BlankReadAssets.SetCompressedAssetBundleFileNames` for how to register. This entry point uses the `AndroidIsCompressedFileStreamingAsset` partial method to let the host project inject the actual file name list:

```csharp
// Extend as needed in the host project
BlankReadAssets.SetCompressedAssetBundleFileNames(
    "ui/prefab/main.ab",
    "ui/prefab/login.ab"
);
```

Source: [BlankReadAssets.cs#L248](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L248)

### 4. Load Entry Points

The load interface signatures are as follows. The exception is only thrown during the path resolution phase; actual bundle read failures are thrown by Unity internally:

```csharp
public static AssetBundleCreateRequest LoadAssetBundleAsync(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFileAsync(info.readPath, crc, (ulong)info.offset);
}

public static AssetBundle LoadAssetBundle(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFile(info.readPath, crc, (ulong)info.offset);
}
```

Source: [BlankReadAssets.cs#L119-L130](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L119-L130)

If `GetInfoOrThrow` finds the file but `AssetBundle.LoadFromFile` still fails, the problem lies in the build artifact itself (CRC mismatch, wrong offset, compressed, etc.), and you need to go back to the build side to investigate.

## Verification

1. Before calling `LoadAssetBundle`, call `BlankReadAssets.FileExists(path)` first; the expected return is `true`.
2. For a path that loads correctly in Editor, copy it verbatim to the device: case, separators, and directory hierarchy must be exactly the same.
3. On an Android device, if `FileExists` returns `true` but loading still fails, check whether the `.ab` file is compressed inside the APK; if so, you need to register it with `SetCompressedAssetBundleFileNames` first.
