# 如何通过 FsmComponent 接入项目

`FsmComponent` 是 GameFrameX 框架下有限状态机（FSM）的统一入口组件,继承自 `GameFrameworkComponent`,挂载到场景后会通过 `GameFrameworkEntry.GetModule<IFsmManager>()` 获取底层状态机管理器,负责所有 FSM 的创建、查询、销毁以及 `FixedUpdate` 轮询。

## 前置条件

- 已安装 `com.gameframex.unity.fsm` 包(通过 `manifest.json` 引入)。
- 场景中已存在 GameFrameX 框架入口(由 `com.gameframex.unity.runtime` 提供),`FsmComponent` 依靠它解析 `IFsmManager`。
- 状态定义继承自 `FsmState<T>`,持有者类型 `T` 必须是引用类型(`class`)。

## 操作步骤

1. **在场景入口 GameObject 上添加 FSM 组件。** 在挂载 GameFrameX 框架入口组件(例如 `GameEntry`)的同一个 GameObject 上点击 `Add Component`,搜索 `GameFrameX/FSM` 并添加。组件类上标注了 `[AddComponentMenu("GameFrameX/FSM")]`,菜单项可直接定位。

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/FSM")]
   [GameFrameXAutoComponent(-6000)]
   public sealed class FsmComponent : GameFrameworkComponent
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L43-L47)

2. **获取组件实例。** 运行时通过 `GameEntry.GetComponent<FsmComponent>()` 取得引用;若同时引入了 `com.gameframex.unity.entry` 快捷包,可直接使用 `GameApp.Fsm`。

   ```csharp
   // 标准方式
   FsmComponent fsmComponent = GameEntry.GetComponent<FsmComponent>();

   // 快捷方式（依赖 com.gameframex.unity.entry）
   IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L47)

3. **定义状态类。** 继承 `FsmState<T>`,在虚方法里写入状态逻辑;通过 `ChangeState<TState>(fsm)` 触发转换。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnEnter(IFsm<Player> fsm) { }

       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }

       protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
   }
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L101-L123)

4. **创建并启动 FSM。** 调用 `CreateFsm<T>` 传入持有者与状态集合,再调用 `Start<TState>()` 启动。`Awake()` 内部会通过 `GameFrameworkEntry.GetModule<IFsmManager>()` 完成管理器绑定,获取失败时记录 `Log.Fatal("FSM manager is invalid.")`。

   ```csharp
   var player = new Player();
   IFsm<Player> fsm = fsmComponent.CreateFsm(
       player,
       new FsmState<Player>[] { new IdleState(), new MoveState() }
   );
   fsm.Start<IdleState>();
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L63-L74) · [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L204-L222)

5. **驱动循环无需手动调用。** `FsmComponent.FixedUpdate()` 会按 Unity 物理节奏调用 `m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime)`,因此挂上组件后 FSM 自动驱动;不要在业务脚本里重复 tick。

   ```csharp
   private void FixedUpdate()
   {
       if (m_FsmManager == null) return;
       m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
   }
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

6. **需要时销毁 FSM。** 通过 `DestroyFsm` 系列重载(按 owner 类型、按 `IFsm<T>` 引用、按 ownerType+name 等)清理。

   ```csharp
   fsmComponent.DestroyFsm(fsm);     // 销毁指定实例
   fsmComponent.DestroyFsm<Player>(); // 销毁该 owner 类型下未命名的 FSM
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L304-L318)

## 常见变体

- **命名 FSM(同 owner 类型共存多台机器)**:通过带 `name` 的 `CreateFsm` 重载区分,之后用 `HasFsm<T>(name)` / `GetFsm<T>(name)` 访问。例如角色身上同时有"战斗 FSM"和"AI 行为树 FSM"时,可以用不同 name 区分。

  ```csharp
  IFsm<Player> combat = fsmComponent.CreateFsm("Combat", player, new AttackState(), new HurtState());
  IFsm<Player> ai     = fsmComponent.CreateFsm("AI", player, new PatrolState(), new ChaseState());
  combat.Start<AttackState>();
  ai.Start<PatrolState>();
  ```

  Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L218-L222)

- **运行时增减状态**:通过 `IFsm<T>.AddState` / `RemoveState<TState>()` 动态调整。注意不能移除当前正在运行的状态。

  ```csharp
  fsm.AddState(new JumpState());
  fsm.RemoveState<IdleState>();
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L153-L158)

- **跨状态数据存取**:用 `SetData(name, value)` / `GetData<TData>(name)` / `HasData(name)` / `RemoveData(name)`,底层走对象池,运行期零 GC。

  ```csharp
  fsm.SetData("Health", 100);
  int hp = fsm.GetData<int>("Health");
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L141-L149)

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 控制台报 `FSM manager is invalid.` | `FsmComponent.Awake()` 时未在框架入口找到 `IFsmManager` 模块 | 确认场景里 GameFrameX 入口组件存在且先于 `FsmComponent` 完成初始化;确认已安装 FSM 包 |
| `CreateFsm` 后 `Start` 报 "状态不存在" | 状态未注册,或传入的 owner 类型与 `T` 不一致 | 检查 `CreateFsm<T>` 的 `T` 与 `FsmState<T>` 子类的 `T` 匹配,并把所有状态加进 `states` 数组 |
| 同一 owner 类型只能创建一个 FSM | 误用无 `name` 的重载,被隐式命名规则覆盖 | 改用带 `name` 的 `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` |
| FSM 不更新 | 业务脚本手动禁用了 `FixedUpdate` / 没挂 `FsmComponent` | 确认场景中有且仅有一个 `FsmComponent`,不要在状态里再调用 `m_FsmManager.FixedUpdate` |

## 背景(可选)

`FsmComponent` 仅是门面,它把请求转交给 `IFsmManager`(通过 `GameFrameworkEntry.GetModule<IFsmManager>()` 拿到)。`[GameFrameXAutoComponent(-6000)]` 标记控制组件自动注册顺序,`Count` 暴露当前 FSM 实例数量,便于编辑器与运行时监控;`[Preserve]` 标注保证 IL2CPP 裁剪时公共 API 不被误删。
