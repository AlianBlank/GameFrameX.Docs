# Scoped Registry 구성 및 필요에 따라 컴포넌트 도입 방법

`Packages/manifest.json`에 `GameFrameX`의 scoped registry(스코프 등록 소스)를 선언하면, Unity Package Manager가 `com.gameframex`로 시작하는 모든 패키지를 해석할 수 있게 되며, 프로젝트 요구 사항에 따라 도입할 컴포넌트를 선택할 수 있습니다.

## 사전 조건

- Unity 2019.4 이상 버전(Package Manager의 scoped registry 지원이 내장됨).
- 프로젝트 루트 디렉터리에 `Packages/manifest.json` 파일이 존재해야 함(Unity에서 프로젝트를 생성할 때 자동 생성됨).

## 작업 단계

1. 프로젝트 루트 디렉터리의 `Packages/manifest.json`을 열고, 파일 끝의 `"scopedRegistries"` 배열에 GameFrameX 등록 소스를 추가합니다(배열이 이미 존재한다면 항목을 하나 추가하면 됨):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ]
}
```

출처: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L72)

2. 같은 파일의 `"dependencies"`에 먼저 핵심 런타임 패키지인 `com.gameframex.unity`를 추가합니다(다른 모든 컴포넌트가 이 패키지에 의존함):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0"
  }
}
```

출처: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

3. 필요에 따라 다른 컴포넌트의 의존성을 추가합니다. 예를 들어 리소스 관리, UI, 네트워크, 프로시저 관리 등이 있습니다. 전체 `dependencies` 작성 예는 다음과 같습니다(이 저장소의 `Packages/manifest.json`에서 발췌):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0",
    "com.gameframex.unity.asset": "3.1.0",
    "com.gameframex.unity.config": "1.2.0",
    "com.gameframex.unity.coroutine": "1.1.0",
    "com.gameframex.unity.entity": "2.4.5",
    "com.gameframex.unity.entry": "1.3.0",
    "com.gameframex.unity.event": "1.3.0",
    "com.gameframex.unity.fsm": "1.2.0",
    "com.gameframex.unity.network": "2.6.10",
    "com.gameframex.unity.procedure": "1.4.0",
    "com.gameframex.unity.sound": "1.3.0",
    "com.gameframex.unity.ui": "2.11.0",
    "com.gameframex.unity.ui.fairygui": "3.4.2"
  }
}
```

출처: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

4. 파일을 저장한 후 Unity 편집기로 돌아가면, Package Manager가 자동으로 새로 추가된 등록 소스와 의존성을 가져옵니다. 목록 새로 고침이 완료될 때까지 기다리면 왼쪽에 `GameFrameX - Scoped Registry` 카테고리 아래의 사용 가능한 패키지를 모두 볼 수 있습니다.

5. 버전 번호는 [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) 페이지 또는 [GameFrameX UPM Registry](https://gameframex.upm.alianblank.uk)를 기준으로 합니다. `"1.11.0"`, `"2.0.0"` 같은 임시 버전 번호를 실제 대상 버전으로 교체하면 됩니다.

## 일반적인 변형

- **Unity 편집기를 통해 추가하기**: `Edit ▸ Project Settings ▸ Package Manager ▸ Scoped Registries` 페이지에서 `+`를 클릭하고, `Name=GameFrameX`, `URL=https://gameframex.upm.alianblank.uk`, `Scopes=com.gameframex`을 입력합니다. 저장한 후의 효과는 `manifest.json`을 직접 편집한 것과 동일합니다.
- **여러 등록 소스를 동시에 사용**: `scopedRegistries`는 배열이므로, 여러 객체를 병렬로 나열할 수 있습니다. 이 저장소 또한 GameFrameX와 `package.openupm.com`(`io.sentry` 스코프용)을 동시에 선언합니다:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    },
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["io.sentry"]
    }
  ]
}
```

출처: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L80)

- **Git URL을 통해 타사 컴포넌트를 직접 설치**: UPM에 게시되지 않은 패키지(예: HybridCLR)의 경우, `dependencies`에 Git 주소를 직접 입력하여 scoped registry를 우회할 수 있습니다:

```json
{
  "dependencies": {
    "com.code-philosophy.hybridclr": "https://gitee.com/focus-creative-games/hybridclr_unity.git"
  }
}
```

출처: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L3-L3)

- **최소한의 집합만 도입하기**: 필요하지 않은 의존성을 제거하면 됩니다. GameFrameX의 각 컴포넌트는 모듈별로 분리되어 있어 강제적인 번들 관계가 없습니다. `com.gameframex.unity`와 `com.gameframex.unity.entry`만 유지해도 정상적으로 시작할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Package Manager에서 `Unable to find package com.gameframex.unity` 오류 발생 | `scopedRegistries`가 선언되지 않았거나, `scopes`가 `com.gameframex.unity`로 잘못 작성됨 | `scopedRegistries`에 `scopes: ["com.gameframex"]` 추가 |
| 패키지는 다운로드되었지만 `assembly definition`에서 네임스페이스를 찾을 수 없음 | `com.gameframex.unity`만 도입하고 `com.gameframex.unity.entry`는 도입하지 않았거나, 하위 모듈이 누락됨 | 누락된 `com.gameframex.unity.*` 의존성을 보완하고, `com.gameframex.unity.entry`가 추가되었는지 확인 |
| 편집기가 계속 "Resolving packages"에서 멈춤 | 여러 등록 소스의 `scopes`가 서로 겹쳐 중복 해석이 발생함 | 각 scoped registry의 `scopes`가 겹치지 않도록 함. 예를 들어 GameFrameX는 `com.gameframex`를, OpenUPM은 `io.sentry`를 사용 |
| 새 버전으로 업그레이드한 후 `dll`이 누락됨 | `dependencies`에 여전히 이전 버전이 고정되어 있고, 새 버전에서 패키지 구조가 변경됨 | [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases)에서 마이그레이션 설명을 확인한 후 버전 번호를 일괄 업데이트 |

## 배경(선택 사항)

Scoped registry는 Unity Package Manager의 2019.3부터 공식 메커니즘입니다. URL + 네임스페이스 스코프(`scopes`)를 통해 프라이빗/퍼블릭 npm 스타일의 UPM 등록 소스를 프로젝트에 통합하며, 이는 공식 패키지와 기존 의존성에는 영향을 주지 않습니다. 이 저장소는 `com.gameframex.*`를 모두 자체 구축한 UPM registry인 `https://gameframex.upm.alianblank.uk`에서 호스팅합니다. 따라서 스코프만 일치하면 Package Manager가 버전에 따라 해당 tarball을 해석할 수 있습니다.
