# What to Do When ArgumentAlreadyException Is Thrown

When you encounter `ArgumentAlreadyException` (parameter already exists exception) while using GameFrameX.Foundation, it means a parameter value already exists or is duplicated. This page helps you quickly identify the cause and fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Throws `ArgumentAlreadyException: <your message>` | Business code actively threw this exception (e.g., a duplicate ID / duplicate key / duplicate name was detected during registration) | Switch to check-then-assign logic, or deduplicate before calling the static helper method |
| Throws `ArgumentNullException: message`, `ParamName = "message"` | The message passed when calling `new ArgumentAlreadyException(null)` or `Throw(null)` is null | Pass a non-null description string |
| Throws `ArgumentException: message`, `ParamName = "message"` | An empty string `""` or a string containing only whitespace (e.g., `"   "`) was passed | Pass a description string with actual content |
| Mistaking the thrown `ArgumentNullException` for a framework bug | The framework applies `ThrowIfNullOrWhiteSpace` validation to the message parameter; null/empty/whitespace are all intercepted upfront | This is expected behavior; simply fix the input parameter |

## Fix Steps

### 1. Distinguish Between Exception Types

`ArgumentAlreadyException` itself is only thrown when explicitly invoked by your code or framework code. `ArgumentNullException` / `ArgumentException` are upfront validations that its constructor performs on the `message` parameter.

```csharp
using GameFrameX.Foundation.Extensions;

// Explicit throw
public void Register(string id)
{
    if (_dict.ContainsKey(id))
    {
        ArgumentAlreadyException.Throw($"id '{id}' 已经存在");
    }
    _dict[id] = ...;
}
```

Source: [ArgumentAlreadyException.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ArgumentAlreadyException.cs#L43-L73)

### 2. Handle the "Parameter Already Exists" Business Scenario

The most common fix is to perform an existence check before adding an element, to avoid duplicates:

```csharp
using GameFrameX.Foundation.Extensions;

public void AddUnique(string key, string value)
{
    if (_map.ContainsKey(key))
    {
        // Option A: Skip
        return;

        // Option B: Throw and let the caller decide
        // ArgumentAlreadyException.Throw($"key '{key}' 已存在");
    }
    _map[key] = value;
}
```

### 3. Handle null / Empty / Whitespace message

If what you caught is `ArgumentNullException` or `ArgumentException` and `ParamName` is `message`, it means the caller passed in an invalid string. Simply fix the input parameter:

```csharp
using GameFrameX.Foundation.Extensions;

var msg = string.IsNullOrWhiteSpace(input)
    ? "默认值/键已经存在"
    : $"{input} 已经存在";

try
{
    ArgumentAlreadyException.Throw(msg);
}
catch (ArgumentAlreadyException ex)
{
    // Business handling
}
```

## Verification

1. Confirm that the `message` input is non-null and is not an empty or whitespace-only string.
2. Confirm that the business side performs an existence check on the target collection before adding/registering, or relies on the framework's automatic validation.
3. Use `Assert.Throws<ArgumentAlreadyException>` for explicit assertions in unit tests, to avoid missing input parameter validation changes.
