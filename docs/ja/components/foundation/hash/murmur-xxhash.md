# 高性能ハッシュ（MurmurHash3 / xxHash など）の使用方法

`GameFrameX.Foundation.Hash` は、MurmurHash3 と xxHash の 2 種類の非暗号化型高性能ハッシュアルゴリズムをすぐに使える API として提供しており、静的メソッドを直接呼び出すことで、文字列・バイト配列・`Type` の 32 / 64 / 128 ビットハッシュ値を計算できます。ハッシュテーブルのキー、ブルームフィルター、負荷分散のシャーディングなど、非セキュリティ用途で広く利用されます。

## 前提条件

- プロジェクトのターゲットフレームワークは .NET（コード内で `uint` / `ulong` / `ArgumentNullException.ThrowIfNull` などの BCL API を使用）。
- プロジェクトが `GameFrameX.Foundation.Hash` アセンブリを参照していること。xxHash の実装は NuGet パッケージ `Standart.Hash.xxHash` に依存しています。

## 操作手順

### 1. 文字列 / バイト配列の MurmurHash3 を計算する

`MurmurHash3Helper` には 2 つのオーバーロードが用意されており、デフォルトのシード値は `27` です。

```csharp
using GameFrameX.Foundation.Hash;

// 文字列版：UTF-8 でエンコードしてからハッシュを計算する。seed は省略可（デフォルト 27）
uint hash1 = MurmurHash3Helper.Hash("hello");
uint hash2 = MurmurHash3Helper.Hash("hello", seed: 1234u);

// バイト配列版：length と seed を明示的に指定する
byte[] data = System.Text.Encoding.UTF8.GetBytes("hello");
uint hash3 = MurmurHash3Helper.Hash(data, (uint)data.Length, seed: 27u);
```

Source: [MurmurHash3Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/MurmurHash3Helper.cs#L62-L68)

### 2. xxHash の 32 / 64 / 128 ビットハッシュを計算する

`XxHashHelper` は `byte[]` / `string` / `Type` およびジェネリック版を提供しており、戻り値の型はそれぞれ `uint` / `ulong` / `uint128` です。

```csharp
using GameFrameX.Foundation.Hash;
using Standart.Hash.xxHash;

// 32 ビット
uint h32 = XxHashHelper.Hash32("hello");
uint h32Type = XxHashHelper.Hash32<MyClass>();

// 64 ビット
ulong h64 = XxHashHelper.Hash64("hello");

// 128 ビット（戻り値は uint128 で、high64 / low64 を含む）
uint128 h128 = XxHashHelper.Hash128("hello");
bool zero = XxHashHelper.IsDefault(h128); // high64 と low64 の両方が 0 のときに true を返す
```

> ⚠️ 名前に注意：`Hash32(byte[])` は `ulong` を返し、`Hash32(string)` は `uint` を返します。これは SDK の実際のシグネチャであり、書き間違いではありません。

Source: [XxHashHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/XxHashHelper.cs#L62-L100)

### 3. シャーディングキー / ハッシュテーブルキーとして利用する

ユーザー ID、リクエスト ID、プレイヤー ID などをシャーディングキーやハッシュテーブルのキーとして使用する場合、文字列をそのまま渡せばよく、事前にバイト配列に変換する必要はありません。

```csharp
// ユーザー ID に基づいてシャードを選択する
int shardIndex = (int)(MurmurHash3Helper.Hash(userId) % shardCount);

// 64 ビットハッシュをハッシュバケットのキーにする
ulong bucketKey = XxHashHelper.Hash64($"player:{playerId}");
```

## よくあるバリエーション

| シナリオ | 推奨 API | 戻り値の型 |
|------|---------|----------|
| 少量データ、再現可能なシードが必要 | `MurmurHash3Helper.Hash(str, seed)` | `uint` |
| 高スループット、バイト配列、言語間互換性が必要 | `XxHashHelper.Hash32/64/128(buffer)` | `uint` / `ulong` / `uint128` |
| 型メタデータに対して安定したハッシュを取りたい（ディスパッチテーブル） | `XxHashHelper.Hash64<T>()` | `ulong` |
| 部分長のハッシュ（ストリーミング / シャーディングデータ） | `XxHashHelper.Hash128(buffer, length)` | `uint128` |

## よくあるエラー

- **MurmurHash3 を暗号化ハッシュとして使う**:MurmurHash3 は非暗号化ハッシュであり、衝突攻撃やプリイメージ攻撃には耐えられないため、パスワード・トークン・署名には使用しないでください。
- **シード値の一貫性を無視する**:同じデータでも `seed` が異なればまったく別のハッシュになります。上流と下流で一致させる必要がある場合は、必ず同じシード値（デフォルト `27`）を使用してください。
- **`Hash32(byte[])` と `Hash32(string)` の戻り値の型を混同する**:前者は `ulong`、後者は `uint` を返します。これは SDK の実際のシグネチャの違いです。
- **`null` を渡す**:すべてのオーバーロードで `ArgumentNullException` が発生します。`??` によるフォールバック処理を行うか、事前に検証してください。
- **MD5 / SHA-1 をセキュリティ用途に使用する**:`HashAlgorithmKind` 列挙型の `Md5` / `Sha1` は互換性と非セキュリティ検証のためのみであり、パスワード用途には `PasswordHashHelper` を使用してください。

## 背景（任意）

MurmurHash3 は本 SDK において純粋にマネージドコードで実装されており、コア部分は 4 バイトブロックのループ + 末尾のマージ + `Fmix32` のファイナライズミックスからなります。典型的な用途はハッシュテーブルキーやキャッシュシャーディングです。xxHash は NuGet パッケージ `Standart.Hash.xxHash` を介してネイティブ実装を呼び出しており、32 / 64 ビット版は多くのハードウェアで MD5 / SHA 系を大きく上回るスループットを示します。どちらも暗号化アルゴリズムではないため、「改ざん防止」を目的とする用途には SHA-2 / 3 や HMAC が必要です。
