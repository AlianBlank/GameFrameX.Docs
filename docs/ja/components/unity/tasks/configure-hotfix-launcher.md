# ホットアップデート入口(HotfixLauncher)の接入方法

本ページの設定を完了すると、フレームワーク起動時に自動的に AOT DLL と Hotfix DLL が読み込まれ、リフレクションによって指定された入口メソッドが呼び出され、ホットアップデートアセンブリが起動されます。

## 前提条件

- ホットアップデートアセンブリ `Unity.Hotfix`(デフォルトの Assembly Definition)が作成済みであること。
- 静的入口クラスと引数なしの静的メソッド(例:`Hotfix.HotfixLauncher.Main`)が存在すること。
- `Assets/Resources/StartupOptions.asset` に以下の3つの設定項目が表示されていること(フレームワークのデフォルトで既に書き込まれています):
  - `HotfixAssemblyName: Unity.Hotfix`
  - `HotfixEntryTypeName: Hotfix.HotfixLauncher`
  - `HotfixEntryMethodName: Main`

## 操作手順

1. **入口クラスを作成する**。`Assets/Hotfix/` ディレクトリに `HotfixLauncher.cs` を新規作成し、デフォルトの名前空間 `Hotfix` を使用して、ホットアップデートの入口として静的 `Main()` メソッドを提供します。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX;
   using GameFrameX.UI.Runtime;
   using Hotfix.Config;
   using Hotfix.Config.Local;
   using Hotfix.Config.Tables;
   using Hotfix.UI;

   namespace Hotfix
   {
       public static class HotfixLauncher
       {
           public static void Main()
           {
               Log.Info("Hello World HybridCLR");
               LoadConfig();
               LoadUI();
           }
       }
   }
   ```

   Source: [HotfixLauncher.cs#L26-L34](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L26-L34)

2. **入口で設定と UI を読み込む**。フレームワークは入口メソッドのみを呼び出し、その後のリソース、設定、UI の初期化はすべてこのメソッドが駆動します。テンプレートプロジェクトでは `TablesComponent` を使用して JSON/バイナリ設定テーブルを読み込み、`await` 方式でログイン UI を開きます。

   ```csharp
   private static async void LoadUI()
   {
       await GameApp.UI.OpenAsync<UILogin>();
   }

   static async void LoadConfig()
   {
       _tablesComponent = new TablesComponent();
       _tablesComponent.Init(GameApp.Config);
       await _tablesComponent.LoadAsync(ConfigLoader);
       TranslateText();
   }

   static TablesComponent _tablesComponent;
   ```

   Source: [HotfixLauncher.cs#L36-L61](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L61)

3. **`StartupOptions.asset` の3つのキー値が入口と一致しているか確認する**。フレームワーク起動クラス `HotfixHelper.StartHotfixInternalAsync` はこの3つのフィールドを読み取ってリフレクションでメソッドを呼び出します。デフォルト値は以下の表の通りです。名前空間やクラス名を変更した場合は、ここも同時に変更する必要があります。

   | キー | デフォルト値 | 役割 |
   |---|---|---|
   | `HotfixAssemblyName` | `Unity.Hotfix` | 読み込む DLL 名(`.dll` を含まない) |
   | `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` | 入口クラスの完全な型名(名前空間 + クラス名) |
   | `HotfixEntryMethodName` | `Main` | 入口メソッド名、`public static` の引数なしメソッドであること |

   Source: [HotfixHelper.cs#L62-L70](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70)、[StartupOptions.asset#L24-L26](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Resources/StartupOptions.asset#L24-L26)

4. **起動フローに `ApplicationHotfixLauncher` が組み込まれていることを確認する**。フレームワーク入口 `ApplicationStartupEntry` はこれを通じて起動 UI ハンドラとホットアップデート起動クラスを `StartupRunner.Run` に組み込みます。変更は不要で、参照が存在することを確認するだけで構いません。

   ```csharp
   var result = await StartupRunner.Run(startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

## よくあるバリエーション

- **バイナリ設定テーブル**:`HotfixLauncher.LoadConfig` 内の `LoadAsync(ConfigLoader)` を `LoadAsync(ConfigBufferLoader)` に置き換え、コンパイルオプションで `ENABLE_BINARY_CONFIG` を有効にします(テンプレートでは既に `#if ENABLE_BINARY_CONFIG` の条件コンパイルを使用しています)。
- **HybridCLR を無効にする**(ネイティブ IL2CPP パス):`ENABLE_GAME_FRAME_X_HYBRID_CLR` または `DISABLE_HYBRIDCLR` が有効な場合、`HotfixHelper.StartHotfixInternalAsync` は `RunNative` 分岐に進み、`Utility.Assembly.GetType` を使って直接リフレクションで入口を呼び出します。AOT DLL の読み込みフローは不要です。
- **入口クラス名を自定义**:例えば `HotfixLauncher` を `MyGame.EntryBoot` に変更した場合、`StartupOptions.asset` の `HotfixEntryTypeName` を `MyGame.EntryBoot` に、`HotfixEntryMethodName` を `Boot` に同時に変更します。

## よくあるエラー

- **入口クラス/メソッドのシグネチャが正しくない**:`public static` かつ引数なしである必要があります。そうでないと `entryType.GetMethod(entryMethodName)` が `null` を返し、ログに `EntryType=>method ` の後ろが空で表示されます。
- **名前空間またはクラス名のスペルミス**:`HotfixEntryTypeName` は `名前空間.クラス名` の完全な形式を使用し、DLL 内の実際の名前空間と一致している必要があります。一致していない場合、`Run` 内の `entryType.FullName` で `NullReferenceException` が発生します。
- **入口を変更したが `StartupOptions.asset` を再起動していない**:変更はランタイムには反映されません。Editor で該当 ScriptableObject を再選択するか、Player を再起動する必要があります。
- **`#if ENABLE_UI_FAIRYGUI` の分岐を誤って削除した**:テンプレートの FairyGUI パッケージの読み込みは条件コンパイルで囲まれています。FairyGUI を使用しているが該当マクロが定義されていない場合、`LoadUI` での UI パッケージの読み込みが失敗します。

## 背景(オプション)

`HotfixHelper.StartHotfixInternalAsync` は、エディタ内では読み込まれたアセンブリを直接走査して DLL を検索し、パッケージ後は `AOTGenericReferences.PatchedAOTAssemblyList` の順序に従って AOT メタデータを読み込み、その後 `Assembly.Load` で Hotfix DLL を読み込み、最後にリフレクションで入口メソッドを呼び出します。`ApplicationHotfixLauncher` は単に `HotfixHelper` を `IHotfixLauncher` インターフェースに適合させ、`StartupRunner` で同じ起動フローを再利用できるようにするためのものです。
