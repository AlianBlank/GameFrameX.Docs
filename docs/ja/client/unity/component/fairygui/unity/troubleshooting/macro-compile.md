# マクロスイッチが有効にならない・競合する場合の対処法

本パッケージの機能マクロ(`FAIRYGUI_TMPRO`、`FAIRYGUI_SPINE`、`FAIRYGUI_INPUT_SYSTEM`、`WECHAT_MINI_GAME`、`DOUYIN_MINI_GAME`)は、**Player Settings の Scripting Define Symbols で手動定義するものではなく**、`Fairygui.Runtime.asmdef` の `versionDefines` が、対応パッケージのインストール有無に応じて自動的にオン/オフします。マクロが「有効にならない」ケースのほとんどは、対応パッケージが未インストール/パッケージ名が一致しないこと、あるいはグローバルシンボルに手動でマクロを追記したものの依存関係が不足して競合エラーが発生していることが原因です。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| Input System パッケージを使用しているのにタッチ/クリックが反応しない | `FAIRYGUI_INPUT_SYSTEM` が未定義(パッケージ名が versionDefines と一致しない、または未インストール)。`Stage` が旧入力システムの分岐を実行している | `com.unity.inputsystem` がインストール済みであることを確認。下記の手順 1 を参照 |
| TMP 関連のコード(下線、faceDilate など)が有効にならない | `FAIRYGUI_TMPRO` が未定義で、`com.unity.textmeshpro` がプロジェクトに存在しない | TextMeshPro パッケージをインストールして再コンパイルを促す |
| `GLoader3D` による Spine リソースのロードが機能しない / `case PackageItemType.Spine` 分岐がコンパイル時に除外される | `FAIRYGUI_SPINE` が未定義で、2 つの spine パッケージ名のどちらにも一致していない | spine パッケージをインストールする(どちらか一方に一致すればよい)。手順 1 のパッケージ名一覧を参照 |
| Player Settings に手動で `FAIRYGUI_SPINE` を追加したら CS0246(`Spine.Unity.SkeletonDataAsset` 等が見つからない)のコンパイルエラーが発生 | マクロが強制的に有効化されたが spine の依存関係がプロジェクトに存在せず、`UIPackage`/`GLoader3D` 内の Spine コードがコンパイルできない | 手動で追加したグローバルマクロを削除し、代わりに対応パッケージをインストールして versionDefines による自動有効化に任せる |
| WeChat/DouYin ミニゲームの `GTextInputWeChat` / `GTextInputDouYin` ファイル全体がコンパイルされない | 条件は `UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME`(DouYin も同様)で、3 つの条件のいずれも欠かせない | WebGL プラットフォームへ切り替え + 対応 SDK パッケージをインストール + Wx/StarkWebGL 側で `ENABLE_*` マクロを有効化 |
| エディターアセンブリ内で `#if` が常に false になる | `Fairygui.Editor.asmdef` の `versionDefines` が空であり、エディターアセンブリはこれらのマクロを認識しない | Editor コードでこれらのマクロに依存しないこと。Runtime アセンブリでのみ使用する |

## マクロとパッケージ名の対応表

マクロの実際の定義元は [Fairygui.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Fairygui.Runtime.asmdef#L20-L51) の `versionDefines` です:

| マクロ | トリガーとなるパッケージ | ソースコードで制御する内容 |
|----|--------------|----------------|
| `FAIRYGUI_INPUT_SYSTEM` | `com.unity.inputsystem` | `Stage` の入力読み取り(新/旧入力システムの切り替え) |
| `FAIRYGUI_TMPRO` | `com.unity.textmeshpro` | `GTextField` の TMP レンダリングと属性のシリアライズ |
| `FAIRYGUI_SPINE` | `com.gameframex.unity.esotericsoftware.spine.spine-unity` または `com.esotericsoftware.spine.spine-csharp`(どちらか一方) | `GLoader3D` の Spine のロード/更新/解放、`UIPackage` の Spine リソースバインディング |
| `WECHAT_MINI_GAME` | `com.qq.weixin.minigame` | `UNITY_WEBGL`、`ENABLE_WECHAT_MINI_GAME` と併せて WeChat ミニゲームの入力ボックスを有効化 |
| `DOUYIN_MINI_GAME` | `com.bytedance.starksdk` | `UNITY_WEBGL`、`ENABLE_DOUYIN_MINI_GAME` と併せて DouYin ミニゲームの入力ボックスを有効化 |

主要なソースコード断片(マクロが実際に有効になる箇所):

```csharp
#if FAIRYGUI_INPUT_SYSTEM
using UnityEngine.InputSystem;
#endif
```

出典: [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L12)

```csharp
#if UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME
using UnityEngine;
```

出典： [GTextInputWeChat.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputWeChat.cs#L1-L2)

```csharp
#if UNITY_WEBGL && DOUYIN_MINI_GAME && ENABLE_DOUYIN_MINI_GAME
```

出典: [GTextInputDouYin.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputDouYin.cs#L1-L1)

## 修正手順

1. **まず、パッケージが本当にインストールされているかを確認します。** `Packages/manifest.json` または Package Manager を開き、以下のリストのパッケージ名と**完全に一致している**ことを確認してください(versionDefines はパッケージ名の完全一致で判定され、大文字小文字も区別されます):
   - `FAIRYGUI_SPINE` → `com.gameframex.unity.esotericsoftware.spine.spine-unity` **または** `com.esotericsoftware.spine.spine-csharp`
   - `FAIRYGUI_TMPRO` → `com.unity.textmeshpro`
   - `FAIRYGUI_INPUT_SYSTEM` → `com.unity.inputsystem`
   - `WECHAT_MINI_GAME` → `com.qq.weixin.minigame`
   - `DOUYIN_MINI_GAME` → `com.bytedance.starksdk`
   注意:`Runtime/Fairygui.Runtime.asmdef` の `references` には `spine-unity.Runtime`、`spine-unity`、`spine-csharp` などが同時に参照されており、いずれか 1 つの spine パッケージが存在すればマクロは有効になります。すべてが欠けている場合は、`FAIRYGUI_SPINE` も一緒に無効のままにしておくことをお勧めします(つまり、手動でマクロを補わないでください)。
2. **手動で追加したグローバルマクロを削除します。** *Edit → Project Settings → Player → Scripting Define Symbols* を開き、自分で手書きした `FAIRYGUI_*`、`WECHAT_MINI_GAME`、`DOUYIN_MINI_GAME` が**含まれていない**ことを確認します。これらのマクロは asmdef のバージョン制約によって管理されており、手動で固定してしまうと、パッケージをアンインストールした後も関連コードのコンパイルが強制され続け、CS0246 のような「型が見つからない」エラーが発生します。
3. **再コンパイルをトリガーします。** パッケージのインストール/アンインストール後、Unity は自動的にリフレッシュします。されない場合は、プロジェクトウィンドウで右クリックして *Reimport All* を実行するか、Unity を再起動してください。versionDefines はドメインリロード時に再評価されます。
4. **ミニゲームプラットフォームは 3 つの条件で確認します。** WeChat/DouYin の入力ボックスクラスは `UNITY_WEBGL && <プラットフォームマクロ> && ENABLE_*` がすべて同時に成立する場合にのみコンパイルされます:
   - WebGL ビルドプラットフォームに切り替えること(`UNITY_WEBGL` が真になるのはこの場合のみ);
   - 対応するプラットフォームマクロが SDK パッケージによって自動定義済みであること(上の表を参照);
   - `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` は Wx / StarkWebGL 関連パッケージから提供されます。お使いの SDK バージョンがこのマクロを提供しない場合、そのファイルが無効のままになるのは正常な動作なので、手動で書き足さないでください。
5. **Editor コードではこれらのマクロに依存しないこと。** [Fairygui.Editor.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/Fairygui.Editor.asmdef#L15-L15) の `versionDefines` は空配列であり、エディターアセンブリは上記のマクロを一切認識できません。マクロによる分岐が必要なコードは、必ず `Runtime` アセンブリに配置してください。

## 検証

- 任意の Runtime スクリプトに一時的にコンパイル時のセルフチェックを追加します(確認が終わったら削除):

```csharp
#if FAIRYGUI_INPUT_SYSTEM
        Debug.Log("FAIRYGUI_INPUT_SYSTEM on");
#endif
#if FAIRYGUI_SPINE
        Debug.Log("FAIRYGUI_SPINE on");
#endif
```

- [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L11) または [GTextField.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextField.cs#L45-L46) を開き、IDE 上で `#if` 内のコードがグレーアウトされなくなっていれば(無効の場合はグレー表示されます)、マクロが有効になっています。
- 手書きマクロが原因で発生していた CS0246 / CS0103 コンパイルエラーが、グローバルマクロを削除した後に消え、コンソールに新たなエラーが出ていないこと。
