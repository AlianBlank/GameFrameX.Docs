# よくある質問

このドキュメントでは、Timerタイマーコンポーネントの使用時に発生しやすい一般的な問題とその解決策を汇总します。

## 概要

TimerコンポーネントはGameFrameXフレームワークが提供するタイマー機能モジュールであり、Unityプロジェクトに定時任務、遅延実行、フレーム更新などの機能サポートを提供します。使用過程中で用户一些问题が発生する可能性があります。このドキュメント詳細な診断と解決策を提供します。

## よくある質問と解決策

### 1. タイマーが実行されない

#### 症状
定時任務を追加した後、コールバック関数が一度も実行されない。

#### 考えられる原因
- Timerコンポーネントがシーン内のGameObjectに正しく追加されていない
- GameFrameworkフレームワークが正しく初期化されていない
- TimerManagerモジュールが登録されていない

#### 解決策

**コンポーネントが追加されているかを確認：**

```csharp
// シーンにTimerComponentがあることを確認
var timerComponent = FindObjectOfType<TimerComponent>();
if (timerComponent == null)
{
    Debug.LogError("TimerComponentが見つかりません。まずコンポーネントを追加してください");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

**フレームワーク初期化を確認：**
ゲーム起動時にGameFrameworkフレームワークが正しく初期化されていることを確認します。TimerComponentはAwake時にGameFrameworkEntryからITimerManagerインスタンスを取得します：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");  // タイマーマネージャー無効
        return;
    }
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

### 2. コールバック関数パラメータ渡しの問題

#### 症状
コールバック関数に渡したパラメータがnull、または正しく取得できない。

#### 考えられる原因
- callbackParamパラメータが正しく渡されていない
- AddOnceの単一パラメータオーバーロードを誤って使用了

#### 解決策

Timerコンポーネントのコールバック関数シグネチャは`Action<object>`であり、パラメータはcallbackParamを通じて渡します：

```csharp
// パラメータを正しく渡す方法
timerComponent.Add(1.0f, 1, OnTimerComplete, "これは渡されるデータ");

// コールバック関数でパラメータを受け取る
private void OnTimerComplete(object param)
{
    Debug.Log($"タイマー完了、パラメータ: {param}");  // 出力: タイマー完了、パラメータ: これは渡されるデータ
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

### 3. 間隔時間单位の混同

#### 症状
タイマーの実行間隔が予想と合わない。例えば、1000ミリ秒を設定したのに毎秒複数回実行される。

#### 考えられる原因
**重要：Timerコンポーネントのintervalパラメータの単位は秒（seconds）であり、ミリ秒ではありません！**

READMEドキュメントには誤った説明があり、実際のコードではintervalは秒単位の浮動小数点数です：

```csharp
// intervalパラメータの単位は秒 (seconds)
public void Add(float interval, int repeat, Action<object> callback, object callbackParam = null)
{
    _timerManager.Add(interval, repeat, callback, callbackParam);
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

#### 解決策

```csharp
// ❌ 間違い：1000をミリ秒として理解
timerComponent.Add(1000f, 1, callback);  // 実際には1000秒間隔で実行される

// ✅ 正しい：intervalを秒として扱う
timerComponent.Add(1.0f, 1, callback);  // 1秒後に1回実行
timerComponent.Add(0.5f, 5, callback); // 毎0.5秒で5回実行

// ミリ秒に変換する正しい書き方
float intervalInSeconds = 1000f / 1000f;  // 1000ミリ秒 = 1秒
timerComponent.AddOnce(intervalInSeconds, callback);
```

### 4. 定時任務の重複追加

#### 症状
同じコールバック関数で複数回Addメソッドを呼び出した後、タイマーの動作が異常。

#### 考えられる原因
TimerManagerはコールバック関数を辞書キーとして使用しており、同じコールバックのタイマーを追加すると、既存のタイマーを更新して新しきマーバーを作成しません：

```csharp
// コード実装：コールバックが既に存在する場合、既存のタイマーを更新
if (_items.TryGetValue(callback, out var t))
{
    t.Set(interval, repeat, callback, callbackParam);
    t.Elapsed = 0;
    t.Deleted = false;
    return;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L173)

#### 解決策

新しいタイマーを追加する前に既に存在するかをチェック：

```csharp
// タイマーが既に存在するかをチェック
if (!timerComponent.Exists(MyCallback))
{
    timerComponent.Add(1.0f, 5, MyCallback);
}
else
{
    Debug.LogWarning("タイマーが既に存在します。まず削除してから追加してください");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 5. コールバック関数の例外によるタイマー崩壊

#### 症状
タイマーのコールバックで例外が発生した後、タイマーシステム全体が停止する。

#### 考えられる原因
デフォルトでは、コールバック関数の例外はタイマーの実行を中断させます。

#### 解決策

TimerManagerは`CatchCallbackExceptions`静的プロパティを提供して例外処理動作を制御します：

```csharp
// 例外捕獲を有効化、コールバック例外によるタイマー崩壊を防止
TimerManager.CatchCallbackExceptions = true;

// 定時任務を追加
timerComponent.Add(1.0f, 0, OnTimerTick);

// コールバック関数で例外が発生してもタイマーは終了しない
private void OnTimerTick(object param)
{
    // 例外をスローする可能性があるコード
    throw new Exception("例外をシミュレート");
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L41-L43)

例外捕獲を有効にすると、例外は捕獲されて警告ログに記録され、同時にそのタイマーは削除済みとしてマークされます：

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        timerItem.Callback(timerItem.Param);
    }
    catch (Exception e)
    {
        timerItem.Deleted = true;
        Debug.LogWarning("Timer: timer(internal=" + timerItem.Interval + ", repeat=" + timerItem.Repeat + ") callback error > " + e.Message);
    }
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L86-L97)

### 6. タイマーのメモリリーク

#### 症状
長時間実行後、メモリ使用量が持続的に増加。

#### 考えられる原因
- 定時任務完了後に正しく削除されていない
- AddUpdateで追加したフレーム更新任務が手動で削除されていない

#### 解決策

**繰り返し回数が 제한된定時タイマーについて：**
Repeat = 0は無限繰り返しを示し、Repeat > 0は指定回数実行後に自動削除されます：

```csharp
// ✅ Repeat = 0は無限繰り返し、手動で削除する必要がある
timerComponent.Add(1.0f, 0, repeatingCallback);

// 適切なタイミングで手動削除
timerComponent.Remove(repeatingCallback);

// ✅ Repeat > 0は指定回数実行後に自動削除
timerComponent.Add(1.0f, 5, limitedCallback);  // 5回実行後に自動削除
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L73-L81)

**フレーム更新任務（AddUpdate）について：**
AddUpdateは本质的には极小間隔（0.001秒）の繰り返しタイマーであり、手動で削除する必要があります：

```csharp
// フレーム更新任務を追加
timerComponent.AddUpdate(OnUpdate);

// オブジェクト破壞時または不要時に削除
timerComponent.Remove(OnUpdate);
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L206-L219)

### 7. タイマーの精度問題

#### 症状
タイマーの実行時間が不正確で、较大的誤差が存在する。

#### 考えられる原因
- 間隔時間が小さすぎる使用了
- ゲームのフレームレートが不安定
- 背景に切换时候Unityの時間システムが変化

#### 解決策

TimerManagerは`realElapseSeconds`（実際の経過時間）を使用してタイマーを計算します：

```csharp
// 内部でrealElapseSecondsを使用して経過時間を計算
timerItem.Elapsed += realElapseSeconds;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L63-L71)

**最適化提案：**

```csharp
// ❌ 間隔が小さすぎるのは避ける
timerComponent.Add(0.0001f, 0, callback);  // パフォーマンス問題を起こす可能性がある

// ✅ 推奨：最小間隔は0.01秒（10ミリ秒）以上
timerComponent.Add(0.01f, 0, callback);

// より高精度が必要なシーンでは、UnityのUpdateまたはCoroutineの使用を検討
```

### 8. コルーチンでタイマーを使用

#### 症状
コルーチンで作成したタイマーの動作が異常。

#### 解決策

Timerコンポーネントはコルーチンで使用できますが、ライフサイクル管理に注意が必要です：

```csharp
IEnumerator StartTimerInCoroutine()
{
    // コルーチンでタイマーを使用
    timerComponent.AddOnce(2.0f, OnDelayComplete, "コルーチンデータ");

    yield return new WaitForSeconds(2.0f);
    // コルーチン終了，但定时器任务可能仍在运行
}

private void OnDelayComplete(object param)
{
    Debug.Log($"遅延完了: {param}");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L48-L51)

## 診断ツール

### タイマーステータスをチェック

Existsメソッドを使用してタイマーが存在するかをチェック：

```csharp
// 特定コールバックのタイマーが存在するかをチェック
bool isRunning = timerComponent.Exists(MyCallback);

if (isRunning)
{
    Debug.Log("タイマーが実行中");
}
else
{
    Debug.Log("タイマーが実行されていないか完了済み");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### すべてのアクティブタイマーを列出

TimerManagerは辞書を使用してタイマーを存储しているため、拡張してアクティブタイマーリストを取得できます：

```csharp
// 注意：TimerManagerの_itemsフィールドはprivate
// デバッグが必要な場合はログ出力を有効化
Debug.Log($"現在のアクティブタイマー数: {アクティブ数}");
```

## パフォーマンス注意事項

### 1. コールバック関数 делегат作成

タイマーを追加するたびに、無名Lambda式をコールバックとして使用しないでください。なぜなら、新しい делегатインスタンスが作成され、タイマーを正しく削除できなくなります：

```csharp
// ❌ 間違い：無名メソッドは削除できない
timerComponent.Add(1.0f, 1, (param) => Debug.Log("test"));

// ✅ 正しい：具名メソッドを使用
timerComponent.Add(1.0f, 1, OnTimerTick);

// その後正しく削除可能
timerComponent.Remove(OnTimerTick);

private void OnTimerTick(object param)
{
    Debug.Log("Timer tick");
}
```

### 2. 大量のタイマー

TimerManagerは辞書とロックを実装しており、数千個の同時タイマーがある場合パフォーマンスに影響する可能性があります。複数のタイマー任務をマージまたは其他方法で管理することを検討してください。
