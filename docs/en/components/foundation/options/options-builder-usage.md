# How to Parse Command-Line Arguments with OptionsBuilder

`OptionsBuilder<T>` and `OptionsBuilder` (the static convenience class) can build strongly-typed configuration objects from `string[] args` and environment variables, supporting multiple types such as booleans, integers, floating-point numbers, and strings, and overriding properties by the priority of "command line > environment variables > default values".

## Prerequisites

- The project references the `GameFrameX.Foundation.Options` assembly.
- `using GameFrameX.Foundation.Options;`
- Prepare a configuration class with `public` setters (`T : class, new()` constraint).

## Steps

```csharp
public class AppConfig
{
    public string Host { get; set; } = "localhost";
    public int Port { get; set; } = 8080;
    public bool Debug { get; set; }
    public string LogLevel { get; set; } = "info";
    public double Timeout { get; set; } = 30.5;
}
```

### 2. Build in One Line with the Static Method (Recommended Entry Point)

`OptionsBuilder.Create<TOptions>(args)` is the most commonly used entry point; internally it instantiates an `OptionsBuilder<T>` and calls `Build()`.

```csharp
using GameFrameX.Foundation.Options;

static void Main(string[] args)
{
    var config = OptionsBuilder.Create<AppConfig>(args);
    Console.WriteLine($"{config.Host}:{config.Port}, debug={config.Debug}");
}
```

Source definition:

```csharp
public static TOptions Create<TOptions>(string[] args, bool skipValidation = false) where TOptions : class, new()
{
    var builder = new OptionsBuilder<TOptions>(args ?? Array.Empty<string>());
    return builder.Build(skipValidation);
}
```

### 3. Manually Instantiate the Builder (More Control)

When you need to control behaviors such as the boolean format, whether to enforce prefixes, and whether to read environment variables, construct the generic version directly:

```csharp
var builder = new OptionsBuilder<AppConfig>(
    args,
    boolFormat: BoolArgumentFormat.Flag,
    ensurePrefixedKeys: true,
    useEnvironmentVariables: true);
var config = builder.Build();
```

### 5. Launch and Pass Arguments

```bash
myapp.exe --host example.com --port 9090 --debug
```

The console will print the raw arguments, option mappings, the parsed object, and its JSON representation in property order (produced by `OptionsDebugger.PrintParsedOptions`).

## Common Variants

- **Command line only, without reading environment variables**:

  ```csharp
  var config = OptionsBuilder.CreateFromArgsOnly<AppConfig>(args);
  ```
- **Environment variables only, without reading args**:

  ```csharp
  var config = OptionsBuilder.CreateFromEnvironmentOnly<AppConfig>();
  ```
- **Fault-tolerant build that does not throw exceptions** (returns a default instance on failure, with the error in `error`):

  ```csharp
  if (!OptionsBuilder.TryCreate<AppConfig>(args, out var cfg, out var err))
  {
      Console.WriteLine($"解析失败,使用默认: {err}");
  }
  ```
- **When debug printing is needed**:

  ```csharp
  var config = OptionsBuilder.CreateWithDebug<AppConfig>(args);
  ```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Exception thrown when a required property is not assigned | Required-option validation is enabled | Call `Build(skipValidation: true)` or `Create<T>(args, skipValidation: true)` |
| `--verbose=true` is recognized as a string | The default boolean argument format is `Flag` (presence-only) | Use `BoolArgumentFormat.KeyValue` or `Separated` instead |
| Boolean flag has no effect | Used `Flag` but passed `--verbose true` (with a space in between) | Use `BoolArgumentFormat.Separated` instead, or write it as `--verbose=true` |
| Environment variables have no effect | Environment variable reading is disabled | Ensure `useEnvironmentVariables: true` (the default) |
| `args` is `null` | The caller did not pass it in | Internally handled by the `args ?? Array.Empty<string>()` fallback; you can also check for null yourself |

## Background (Optional)

`OptionsBuilder` uses reflection to read the `PropertyInfo` of `T` (results are cached in a `ConcurrentDictionary` to improve performance), mapping command-line arguments in forms such as `--key value`, `--key=value`, and `--flag`, as well as environment variables, to the corresponding properties by property name. The priority is: command line > environment variables > type field default values. Booleans support three parsing formats, controlled by the `BoolArgumentFormat` enum.
