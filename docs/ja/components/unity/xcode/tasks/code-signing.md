# コード署名の設定

`XCodeConfig.json` 設定ファイルの `signing` ノードに Team ID、バンドルID、署名アイデンティティなどのフィールドを記入しておくと、Unity が iOS プロジェクトをエクスポートした後、ビルド後処理がこれらの値を Xcode のメイン Target（Unity-iPhone）のビルド設定に自動的に書き込みます。Xcode で手動で署名を変更する必要はありません。

## 前提条件

- Unity iOS プラットフォームで正常にビルド・出力できること（PostProcessBuildPlayer フェーズで本コンポーネントが実行されます）。
- プロジェクトに `XCodeConfig.json` 設定ファイルが配置済みであること。未配置の場合は、リポジトリ内の [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) または [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json) を参考に作成してください。
- 手動署名（Manual）モードでは、事前に Apple Developer コンソールで Provisioning Profile を作成し、対応する証明書をローカルマシンにインストールしておく必要があります。

## 操作手順

1. プロジェクト内の `XCodeConfig.json` を開き（または新規作成し）、トップレベルに `signing` ノードを追加します。リポジトリ付属の Demo での記述例は以下の通りです：

```json
{
  "swiftBridging": true,
  "signing": {
    "teamId": "XXXXXXXXXX",
    "codeSignStyle": "Automatic",
    "provisioningProfileSpecifier": ""
  }
}
```

出典:[XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L2-L9)

2. 下表に従って `signing` 内のフィールドを記入します。すべてのフィールドはオプションで、空欄または未指定の場合、該当ビルド設定は Unity エクスポート時のデフォルト値のまま維持されます。`signing` ノードはメインプロジェクト（Unity-iPhone Target）にのみ適用されます。

| フィールド | 対応するビルド設定 | 説明 |
|------|--------------|------|
| `teamId` | `DEVELOPMENT_TEAM` | Apple Developer Team ID |
| `bundleId` | `PRODUCT_BUNDLE_IDENTIFIER` | アプリのバンドルID |
| `codeSignIdentity` | `CODE_SIGN_IDENTITY` | 署名証明書のアイデンティティ |
| `codeSignStyle` | `CODE_SIGN_STYLE` | 署名方式、`Automatic` または `Manual` |
| `provisioningProfileSpecifier` | `PROVISIONING_PROFILE_SPECIFIER` | プロビジョニングプロファイル名（Manual モードのみ必要） |

各フィールドの意味とマッピング関係は、テンプレートファイル内のコメントおよび `SetSigning` の実装に基づきます：

```csharp
private static void SetSigning(PBXProject proj, string targetGuid, Hashtable signing)
{
    if (signing == null) return;

    var teamId = signing.Get<string>("teamId");
    if (!string.IsNullOrEmpty(teamId))
    {
        proj.SetBuildProperty(targetGuid, "DEVELOPMENT_TEAM", teamId);
    }

    var bundleId = signing.Get<string>("bundleId");
    if (!string.IsNullOrEmpty(bundleId))
    {
        proj.SetBuildProperty(targetGuid, "PRODUCT_BUNDLE_IDENTIFIER", bundleId);
    }
    // codeSignIdentity / codeSignStyle / provisioningProfileSpecifier も同様に、空でない場合のみ書き込まれる
}
```

出典:[PostProcessBuildHelper.Signing.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Signing.cs#L15-L48)

3. 自動署名を使用する場合は、`teamId` + `codeSignStyle: "Automatic"` を指定するだけで、Xcode が証明書とプロビジョニングプロファイルを自動的に管理します。

4. 手動署名を使用する場合は、証明書とプロビジョニングプロファイルの情報を補完します：

```json
{
  "signing": {
    "teamId": "你的TeamID",
    "bundleId": "com.yourcompany.yourapp",
    "codeSignStyle": "Manual",
    "provisioningProfileSpecifier": "你的描述文件名称"
  }
}
```

プロビジョニングプロファイル名は、Apple Developer コンソールで作成した Profile 名と一致している必要があります。テンプレートのコメントには、このフィールドが「Manual モードのみ必要」と明記されています（[XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json#L14-L15) を参照）。

5. iOS プロジェクトをエクスポートします（またはビルドを実行します）。ビルド後処理はすべての `XCodeConfig.json` を読み込んでマージし、その後メイン Target に対して署名設定を呼び出します：

```csharp
// 署名設定（メインプロジェクトにのみ設定）
SetSigning(project, project.GetUnityMainTargetGuid(), finalConfig.Get<Hashtable>("signing"));
```

出典:[PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L96-L97)

6. 検証：生成された Xcode プロジェクトを開き、Unity-iPhone Target → Signing & Capabilities を選択して、Team、Bundle Identifier、Provisioning Profile が設定内容と一致していることを確認します。または、ターミナルで `xcodebuild -showBuildSettings | grep -E "DEVELOPMENT_TEAM|CODE_SIGN"` を直接実行して確認することもできます。

## よくあるバリエーション

**チャネルごとに署名設定を上書きする。** ビルド後処理はまずすべての共通 `XCodeConfig.json` をマージし、その後チャネル専用設定 `XCodeConfig.{channel}.json` をマージします。チャネル設定が最も優先度が高く、最後にマージされて上書きされます。そのため、異なるチャネル（例：異なるバンドルIDのクローンアプリ）ごとにチャネルファイルを配置し、`signing` 内の差分フィールドのみを記述できます：

```json
{
  "signing": {
    "bundleId": "com.yourcompany.app.channelA"
  }
}
```

チャネルファイルの命名形式とマージ順序については、[PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L76) および [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L80-L83) を参照してください。

**ScriptableObject による設定。** リポジトリには `XcodeConfig` ScriptableObject（メニュー `XcodeConfig/Create Settings`）も用意されており、Inspector で環境変数、Plist、Capabilities などの設定を管理できます。詳細は [XcodeConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XcodeConfig.cs#L10-L31) を参照してください。署名関連の JSON フィールドは引き続き `signing` ノードが基準となります。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| コンソールに `未找到任何 XCodeConfig 相关配置文件, 跳过设置` と出力される | プロジェクト内にスキャン可能な `XCodeConfig.json` が存在しない | テンプレートに従って設定ファイルを配置してから再度エクスポートする |
| コンソールに `合并后的配置为空，跳过设置` と出力される | 設定ファイルは存在するが、JSON の解析結果が空 | JSON の構文が正しいか確認する |
| `未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json`（Log のみ） | チャネルが設定されているが、対応するチャネルファイルが存在しない | 案内メッセージです。差分設定が必要な場合は `XCodeConfig.{channel}.json` を作成してください |
| エクスポート後も Xcode の Team が空のまま | `teamId` が空、またはフィールド名の誤り（空でないフィールドのみ書き込まれる） | フィールド名のスペルと大文字・小文字を確認:`teamId`、`bundleId`、`codeSignIdentity`、`codeSignStyle`、`provisioningProfileSpecifier` |
| 手動署名時にプロビジョニングプロファイルの不一致が発生 | `provisioningProfileSpecifier` が実際の Profile 名と一致していない、またはローカルマシンに対応する証明書が未インストール | Profile 名を確認し、証明書をインストールする |

上表のログ原文は、設定の読み込みとマージのフローに由来します。詳細は [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83) を参照してください。

## 背景

署名設定は Unity の PostProcessBuild フェーズで実行されます。コンポーネントはプロジェクト内のすべての `XCodeConfig.json` を読み込んで最終設定へマージし、生成された `Unity-iPhone.xcodeproj/project.pbxproj` を解析し、メイン Target（UnityMainTarget）に対してのみ署名関連のビルド設定を書き込み、その後プロジェクトをディスクへ書き戻します。すべての署名フィールドは「空でない場合のみ書き込む」という原則に従うため、必要なフィールドのみ設定できます。また、`signing.bundleId` は Capabilities 処理にも渡され、entitlements の設定と連携するために使用されます（[PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L116-L119) を参照）。
