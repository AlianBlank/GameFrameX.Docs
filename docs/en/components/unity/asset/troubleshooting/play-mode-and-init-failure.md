# What to Do When the Play Mode Is Unsupported or Initialization Fails

`AssetManager` dispatches to four specific initialization methods (Editor simulation / Offline / Host / WebGL) based on `EPlayMode` when initializing resource packages. If the mode value is not within the enum, an exception is thrown directly. Mode-platform mismatch, missing URLs, or YooAsset not being initialized first can also cause initialization to fail. Common symptoms and their corresponding fixes are provided below.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentOutOfRangeException: Unsupported play mode: <value>` | `PlayMode` is not within the four valid values of `EPlayMode` | See "Fix Step 1" below |
| Using `EditorSimulateMode` in packaged/build, resource loading fails | Non-editor environments automatically force-changed to `HostPlayMode`, but URL is not configured | See "Fix Step 2" below |
| Selecting a non-Web mode like `HostPlayMode` on WebGL platform, initialization fails | WebGL is forced to use `WebPlayMode`; non-Web modes are not supported | See "Fix Step 3" below |
| `hostServerURL is null` or resource package cannot be created | URL not provided in Host/Web mode; YooAsset not initialized first | See "Fix Step 4" below |
| `Asset manager is invalid.` | `_assetManager` module not registered | See "Fix Step 5" below |

## Fix Steps

### 1. Invalid `PlayMode` Value

`AssetManager.CreateInitializationOperationHandler` uses a `switch` to match the four valid modes, and the default branch throws an exception directly:

```csharp
default:
{
    throw new ArgumentOutOfRangeException(nameof(PlayMode), PlayMode, $"Unsupported play mode: {PlayMode}");
}
```

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L42-L46)

Confirm that the value of the `AssetComponent.GamePlayMode` field (named `m_GamePlayMode` in the Inspector) is within the four enum values `EditorSimulateMode / OfflinePlayMode / HostPlayMode / WebPlayMode`, and has not been incorrectly assigned by external scripts to an integer like `(EPlayMode)999`.

### 2. Misuse of `EditorSimulateMode` at Runtime

`AssetComponent.Awake` forces `EditorSimulateMode` to `HostPlayMode` in non-editor environments, and Host mode requires a download URL:

```csharp
#if !UNITY_EDITOR
    if (GamePlayMode == EPlayMode.EditorSimulateMode)
    {
        GamePlayMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    GamePlayMode = EPlayMode.WebPlayMode;
#endif
#endif
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L65-L73)

Fix: Before packaging, change `GamePlayMode` to a valid value matching the target platform (use `OfflinePlayMode` for offline build, use `HostPlayMode` for networked build and fill in `hostServerURL`).

### 3. Non-Web Mode Selected on WebGL Platform

WebGL will be force-overwritten to `WebPlayMode`; if you still want to use the `HostPlayMode` route for CDN/mini-game solutions, you need to pass the correct `hostServerURL` and `fallbackHostServerURL` when calling `InitPackageAsync`, and ensure that the corresponding mini-game platform macros (`ENABLE_DOUYIN_MINI_GAME`, `ENABLE_WECHAT_MINI_GAME`, `ENABLE_KUAISHOU_MINI_GAME`, etc.) are enabled to take the corresponding `ByteGame/Wechat/Kuaishou` file system branch (see `InitializeYooAssetWebPlayMode`).

### 4. URL Missing or YooAsset Not Initialized

`AssetManager.Initialize` must be called before `InitPackageAsync`, otherwise YooAsset's internal state will be incomplete:

```csharp
public void Initialize()
{
    Log.Info($"资源系统运行模式：{PlayMode}");
    YooAssets.Initialize();
    YooAssets.SetOperationSystemMaxTimeSlice(Milliseconds > 0 ? Milliseconds : 30);
    Log.Info("Asset Init Over");
}
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L45-L54)

`InitPackageAsync` performs `NotNull` validation on its parameters; if any is null, it throws `ArgumentNullException`:

```csharp
GameFrameworkGuard.NotNull(packageName, nameof(packageName));
GameFrameworkGuard.NotNull(hostServerURL, nameof(hostServerURL));
GameFrameworkGuard.NotNull(fallbackHostServerURL, nameof(fallbackHostServerURL));
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L69-L71)

Fix: Confirm that `AssetComponent.Start` has been triggered (it calls `_assetManager.Initialize()`), and pass a valid URL when calling `InitPackageAsync(packageName, host, fallbackHost, isDefaultPackage:true)`.

### 5. `Asset manager is invalid.`

`AssetComponent.Awake` prints a fatal log and returns directly when it cannot get the `IAssetManager` module:

```csharp
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L82)

Fix: Confirm that the GameFrameX framework entry (`GameEntry`) is in the scene, and that the `ImplementationComponentType`/`InterfaceComponentType` configuration of `AssetComponent` is correct, so the framework can reflectively construct the `AssetManager` implementation class.

## Verification

1. In the Unity Console, confirm that the logs `资源系统运行模式：<PlayMode>` and `Asset Init Over` appear. Both appearing indicates that `Initialize()` has completed.
2. After calling `InitPackageAsync`, wait for `InitializationOperation` to complete; if it returns `true` and `Status == EOperationStatus.Succeed`, the resource package initialization is successful.
3. Trigger a `LoadAssetAsync` to confirm that an `AssetHandle` can be obtained and `LastError` is empty.
4. Repeat the above steps on the packaging platform (WebGL/Android/iOS) to confirm that `Unsupported play mode` or `hostServerURL is null` is no longer thrown.
