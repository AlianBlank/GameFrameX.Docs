# FsmComponent を使ってプロジェクトに統合する方法

`FsmComponent` は GameFrameX フレームワークにおける有限状態機械（FSM）の統一エントリコンポーネントであり、`GameFrameworkComponent` を継承しています。シーンにアタッチされると `GameFrameworkEntry.GetModule<IFsmManager>()` を通じて基底の状態機械マネージャーを取得し、すべての FSM の作成・検索・破棄、および `FixedUpdate` ポーリングを担当します。

## 前提条件

- `com.gameframex.unity.fsm` パッケージがインストール済みであること（`manifest.json` から導入）。
- シーン内に GameFrameX フレームワークのエントリが存在すること（`com.gameframex.unity.runtime` が提供）。`FsmComponent` はこれに依存して `IFsmManager` を解決します。
- 状態の定義が `FsmState<T>` を継承しており、所有者タイプ `T` は参照型（`class`）である必要があります。

## 操作手順

1. **シーンエントリの GameObject に FSM コンポーネントを追加する。** GameFrameX フレームワークのエントリコンポーネント（例：`GameEntry`）がアタッチされている同じ GameObject 上で `Add Component` をクリックし、`GameFrameX/FSM` を検索して追加してください。コンポーネントクラスには `[AddComponentMenu("GameFrameX/FSM")]` が付与されているため、メニュー項目から直接見つけられます。

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/FSM")]
   [GameFrameXAutoComponent(-6000)]
   public sealed class FsmComponent : GameFrameworkComponent
   ```

   出典: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L43-L47)

2. **コンポーネントインスタンスを取得する。** 実行時には `GameEntry.GetComponent<FsmComponent>()` 経由で参照を取得します。`com.gameframex.unity.entry` ショートカットパッケージも導入済みであれば、`GameApp.Fsm` を直接使用できます。

   ```csharp
   // 標準的な方法
   FsmComponent fsmComponent = GameEntry.GetComponent<FsmComponent>();

   // ショートカット（com.gameframex.unity.entry に依存）
   IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());
   ```

   出典: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L47)

3. **状態クラスを定義する。** `FsmState<T>` を継承し、仮想メソッド内に状態ロジックを記述します。`ChangeState<TState>(fsm)` を呼び出して遷移をトリガーします。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnEnter(IFsm<Player> fsm) { }

       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }

       protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
   }
   ```

   出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L101-L123)

4. **FSM を作成して起動する。** `CreateFsm<T>` を呼び出し、所有者と状態の集合を渡します。次に `Start<TState>()` を呼び出して起動します。`Awake()` 内部では `GameFrameworkEntry.GetModule<IFsmManager>()` を通じてマネージャーへのバインディングが行われ、取得に失敗した場合は `Log.Fatal("FSM manager is invalid.")` が記録されます。

   ```csharp
   var player = new Player();
   IFsm<Player> fsm = fsmComponent.CreateFsm(
       player,
       new FsmState<Player>[] { new IdleState(), new MoveState() }
   );
   fsm.Start<IdleState>();
   ```

   出典: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L63-L74) · [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L204-L222)

5. **駆動ループを手動で呼ぶ必要はない。** `FsmComponent.FixedUpdate()` は Unity の物理サイクルに合わせて `m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime)` を呼び出すため、コンポーネントをアタッチすれば FSM は自動的に駆動されます。ビジネススクリプト内で重複して tick しないでください。

   ```csharp
   private void FixedUpdate()
   {
       if (m_FsmManager == null) return;
       m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
   }
   ```

   出典: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

6. **必要に応じて FSM を破棄する。** `DestroyFsm` シリーズのオーバーロード（owner タイプ指定、`IFsm<T>` 参照指定、ownerType+name 指定など）を使用してクリーンアップします。

   ```csharp
   fsmComponent.DestroyFsm(fsm);     // 指定インスタンスを破棄
   fsmComponent.DestroyFsm<Player>(); // その owner タイプの無名 FSM を破棄
   ```

   出典: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L304-L318)

## よくあるバリエーション

- **名前付き FSM（同じ owner タイプで複数台の機械を共存させる）**：`name` 付き `CreateFsm` オーバーロードで区別し、以降は `HasFsm<T>(name)` / `GetFsm<T>(name)` でアクセスします。例えばキャラクターに「戦闘 FSM」と「AI ビヘイビアツリー FSM」を同時に持たせる場合、異なる name で区別できます。

  ```csharp
  IFsm<Player> combat = fsmComponent.CreateFsm("Combat", player, new AttackState(), new HurtState());
  IFsm<Player> ai     = fsmComponent.CreateFsm("AI", player, new PatrolState(), new ChaseState());
  combat.Start<AttackState>();
  ai.Start<PatrolState>();
  ```

  出典: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L218-L222)

- **実行時の状態の増減**：`IFsm<T>.AddState` / `RemoveState<TState>()` を通じて動的に調整します。現在実行中の状態は削除できない点に注意してください。

  ```csharp
  fsm.AddState(new JumpState());
  fsm.RemoveState<IdleState>();
  ```

  出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L153-L158)

- **状態をまたいだデータの読み書き**：`SetData(name, value)` / `GetData<TData>(name)` / `HasData(name)` / `RemoveData(name)` を使用します。内部的にはオブジェクトプールを利用しており、実行時の GC はゼロです。

  ```csharp
  fsm.SetData("Health", 100);
  int hp = fsm.GetData<int>("Health");
  ```

  出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L141-L149)

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| コンソールに `FSM manager is invalid.` が出力される | `FsmComponent.Awake()` の時点でフレームワークエントリに `IFsmManager` モジュールが見つからない | シーン内に GameFrameX エントリ组件が存在し、`FsmComponent` よりも先に初期化が完了していることを確認。FSM パッケージがインストールされていることも確認 |
| `CreateFsm` 後の `Start` で「状態が存在しない」と報告される | 状態が登録されていない、または渡された owner タイプと `T` が一致していない | `CreateFsm<T>` の `T` と `FsmState<T>` サブクラスの `T` が一致しているか確認し、すべての状態を `states` 配列に追加する |
| 同じ owner タイプで FSM を1つしか作できない | `name` なしオーバーロードを誤用しており、暗黙の命名規則で上書きされている | `name` 付きの `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` を使用する |
| FSM が更新されない | ビジネススクリプトで `FixedUpdate` を手動で無効にしている / `FsmComponent` がアタッチされていない | シーン内に `FsmComponent` が1つだけ存在することを確認し、状態の内部で `m_FsmManager.FixedUpdate` を再度呼び出さない |

## 背景（任意）

`FsmComponent` は単なるファサードであり、リクエストを `IFsmManager`（`GameFrameworkEntry.GetModule<IFsmManager>()` を通じて取得）に転送します。`[GameFrameXAutoComponent(-6000)]` 属性はコンポーネントの自動登録順序を制御し、`Count` は現在の FSM インスタンス数を公開してエディタ・実行時の監視に利用できるようにします。`[Preserve]` 属性により、IL2CPP によるツリーシェイク時にパブリック API が誤って削除されないことが保証されます。
