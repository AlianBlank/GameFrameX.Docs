# 첫 번째 광고: 컴포넌트 부착부터 재생 완료까지

이 페이지를 따라 하면 씬에 사용 가능한 `AdvertisementComponent`를 얻고, `Play(AdvertisementPlayOption)`으로 광고를 한 번 재생하여 콜백에서 "재생 성공 / 실패 / 완전 시청 여부" 세 가지 결과를 받을 수 있습니다.

## 사전 조건

| 항목 | 설명 |
|---|---|
| GameFrameX 런타임 | 컴포넌트는 `GameFrameworkComponent`를 상속하며 `GameFrameworkEntry.GetModule<IAdvertisementManager>()`로 모듈을 가져오므로, 씬에 반드시 GameFrameX 프레임워크 엔트리가 있어야 합니다 |
| 구체적인 광고 구현 | 이 패키지는 추상 계층(`IAdvertisementManager` / `AdvertisementConfig`)만 제공하며, 실제 채널 SDK 구현은 별도로 연동해야 합니다 |
| 플랫폼 광고 단위 ID | 배포할 플랫폼에 맞춰 준비합니다 (Android / iOS / WebGL / WeChat / Douyin / Kuaishou) |

## 작업 단계

### 1. 광고 컴포넌트 부착

씬에서 GameFrameX 프레임워크가 있는 GameObject를 선택하고 메뉴 **GameFrameX → Advertisement**를 통해 컴포넌트를 추가합니다. 컴포넌트에는 `[DisallowMultipleComponent]`가 붙어 있어 한 객체에는 하나만 부착할 수 있습니다.

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Advertisement")]
public class AdvertisementComponent : GameFrameworkComponent
{
    [SerializeField] private string m_adUnitIdAndroid = string.Empty;
    [SerializeField] private string m_adUnitIdiOS = string.Empty;
    [SerializeField] private string m_adUnitIdWebGL = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLWeChat = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLDouYin = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLKuaiShou = string.Empty;
    [SerializeField] private bool m_debug = false;
    [SerializeReference, SerializeField] private AdvertisementConfig m_config = null;
}
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L43-L61)

### 2. Inspector에서 각 플랫폼 광고 단위 ID 입력

Inspector의 6개 ID 필드는 각각 하나의 플랫폼에 대응됩니다. 컴포넌트는 `Awake`에서 현재 컴파일 플랫폼과 미니게임 매크로에 따라 자동으로 하나를 선택하여 읽기 전용 속성 `AdUnitId`에 할당합니다.

```csharp
AdUnitId =
#if UNITY_WEBGL
#if ENABLE_WECHAT_MINI_GAME
        m_adUnitIdWebGLWeChat
#elif ENABLE_DOUYIN_MINI_GAME
        m_adUnitIdWebGLDouYin
#elif ENABLE_KUAISHOU_MINI_GAME
        m_adUnitIdWebGLKuaiShou
#else
        m_adUnitIdWebGL
#endif
#elif UNITY_ANDROID
        m_adUnitIdAndroid
#elif UNITY_IOS
        m_adUnitIdiOS
#else
        string.Empty
#endif
        ;
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)

즉, 에디터에서(Android / iOS / WebGL 대상 플랫폼이 아닐 때) `AdUnitId`는 빈 문자열이 되는데, 이는 예상된 동작이며 설정 오류가 아닙니다.

### 3. 설정 파일 제공 및 초기화 완료

`AdvertisementConfig`는 추상 기본 클래스이며, 공통 필드인 `isDebug`만 있습니다. 채널 관련 매개변수는 구현 클래스에서 확장합니다.

```csharp
[Preserve]
[Serializable]
public abstract class AdvertisementConfig
{
    /// <summary>
    /// 디버그 모드 활성화 여부.
    /// </summary>
    [Preserve]
    public bool isDebug;
}
```

> Source: [AdvertisementConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L41-L53)

초기화는 두 가지 방법 중 하나를 선택할 수 있습니다.

- **방법 A (권장, 코드 불필요)**: `m_config` 필드에 `[SerializeReference]`가 지정되어 있어 Inspector에서 직접 설정 하위 클래스를 선택하고 매개변수를 입력할 수 있습니다. 컴포넌트의 `Start()`는 `m_config != null`일 때 자동으로 `Initialize`를 호출합니다.

```csharp
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)

- **방법 B (코드)**: 설정 객체를 직접 생성하여 전달하면, 컴포넌트의 `Config`도 동시에 덮어씌워집니다.

```csharp
[Preserve]
public void Initialize(AdvertisementConfig config)
{
    m_config = config;
    _advertisementManager.Initialize(config);
}
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L135-L140)

### 4. 광고 재생 및 결과 처리

재생은 통일된 `Play(AdvertisementPlayOption option)`을 통해 이루어지며, 옵션 객체에 콜백을 넣습니다.

```csharp
using GameFrameX.Advertisement.Runtime;
using GameFrameX.Runtime;
using UnityEngine;

public class RewardButton : MonoBehaviour
{
    public void OnClickWatchAd()
    {
        var component = GameEntry.GetComponent<AdvertisementComponent>();

        component.Play(new AdvertisementPlayOption
        {
            extraData  = "level_10_double_reward", // Load 단계에서만 서버 보상 검증으로 전달됨
            customData = "from_main_ui",
            OnSuccess = data => Log.Info($"광고 재생 성공, 확장 데이터: {data}"),
            OnFail    = error => Log.Error($"광고 재생 실패: {error}"),
            OnShowResult = isShown => Log.Info($"광고가 성공적으로 표시되었는지 여부: {isShown}"),
        });
    }
}
```

> Sources: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L42-L85), [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L215-L219)

세 가지 콜백의 의미 (소스 코드 주석에서 발취).

| 콜백 | 시그니처 | 트리거 시점 |
|---|---|---|
| `OnSuccess` | `Action<string>` | 광고 재생 성공 (예: 보상 검증 통과), 매개변수는 확장 데이터 |
| `OnFail` | `Action<string>` | 광고 재생 실패, 매개변수는 오류 정보 |
| `OnShowResult` | `Action<bool>` | 광고 표시 결과, 매개변수는 성공적으로 표시되었는지 여부 |

> Source: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L46-L68)

### 5. 필요 시 추가 데이터 보완

재생 전에 `SetExtraData(key, value)`로 키-값 쌍을 추가할 수 있으며, 이는 관리자에게 직접 전달됩니다.

```csharp
[Preserve]
public void SetExtraData(string key, string value)
{
    Debug.Log($"[AdComponent] SetExtraData: key={key}, value={value ?? "(null)"}, managerType={_advertisementManager?.GetType().FullName ?? "(null)"}");
    _advertisementManager.SetExtraData(key, value);
}
```

## 일반적인 변형

### 컴포넌트를 거치지 않고 관리자 인터페이스 직접 사용

컴포넌트는 `IAdvertisementManager`의 얇은 래퍼일 뿐이므로, MonoBehaviour가 아닌 코드에서 재생해야 할 때는 모듈을 직접 가져올 수 있습니다.

```csharp
var manager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
manager.Play(new AdvertisementPlayOption
{
    OnSuccess    = data => { /* 보상 지급 */ },
    OnFail       = error => { /* 알림 */ },
    OnShowResult = isShown => { /* 이벤트 트래킹 */ },
});
```

> Source: [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L96-L97)

### 레거시 API (컴파일은 가능하지만 더 이상 사용되지 않음)

다음 멤버들은 모두 `[Obsolete]`가 붙어 있어, 레거시 프로젝트 마이그레이션 시 단기적으로만 사용하는 것을 권장합니다.

| 더 이상 사용되지 않는 멤버 | 더 이상 사용되지 않음 알림 원문 | 대체 |
|---|---|---|
| `Initialize(string adUnitId, bool isDebug = false)` | `Use Initialize(AdvertisementConfig) instead.` | `Initialize(AdvertisementConfig)` |
| `Show(Action<string>, Action<string>, Action<bool>)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |
| `Play(Action<bool> onShowResult, string customData = null)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |
| `Load(Action<string> success, Action<string> fail)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |

## 일반적인 오류

| 현상 | 원인 | 처리 |
|---|---|---|
| 콘솔에 `Advertisement manager is invalid.` 출력 (`Log.Fatal`) | `GameFrameworkEntry.GetModule<IAdvertisementManager>()`가 null 반환 - 사용 가능한 광고 관리자 구현이 등록되지 않음 | 구체적인 채널 구현이 연동되었는지 확인하고, 컴포넌트의 `componentType`이 `Utility.Assembly.GetType`으로 해석될 수 있는지 확인 |
| `AdUnitId`가 빈 문자열 | 현재 플랫폼이 `UNITY_WEBGL` / `UNITY_ANDROID` / `UNITY_IOS` 분기에 속하지 않아 소스 코드에서 `string.Empty`로 폴백됨 | 대상 플랫폼 (또는 실기기)으로 전환하여 다시 테스트; 에디터에서 빈 값은 정상 |
| 미니게임 플랫폼에서 일반 WebGL의 ID를 가져옴 | `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 매크로가 정의되지 않음 | Player Settings의 Scripting Define Symbols에서 해당 매크로를 추가 |
| 재생 시 `NullReferenceException` 발생 | 초기화하지 않고 `Play`를 호출함: `m_config`가 null이면 `Start()`에서 자동으로 `Initialize`를 호출하지 않음 | Inspector에서 `Config`를 지정하거나 재생 전에 수동으로 `Initialize(AdvertisementConfig)` 호출 |
| `extraData`를 설정했지만 서버 검증에서 가져올 수 없음 | 해당 필드는 "광고 로드 (Load) 단계에서만 서버 보상 검증 콜백으로 전달되며, 로드 후 설정은 무효" | 로드/재생을 트리거하기 전에 한 번에 `extraData`를 채우고, 재생 중간에 변경하지 말 것 |
| 두 번째 광고 컴포넌트 추가 실패 | 클래스에 `[DisallowMultipleComponent]`가 있음 | 한 GameObject에는 하나의 `AdvertisementComponent`만 유지 |

## 배경 (선택 사항)

컴포넌트는 `Awake`에서 `InterfaceComponentType`을 `typeof(IAdvertisementManager)`로 설정하고, 구현 타입은 `componentType` 리플렉션으로 해석되므로, 채널 SDK를 교체할 때 비즈니스 코드를 변경할 필요 없이 구현 및 설정 하위 클래스만 교체하면 됩니다.
