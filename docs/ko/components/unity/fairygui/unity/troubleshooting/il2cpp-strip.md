# IL2CPP 빌드 후 UI 기능이 비정상일 때 해결 방법

IL2CPP로 빌드한 후 Unity의 관리 코드 스트리핑(Managed Code Stripping)이 FairyGUI에서 리플렉션/문자열로만 참조되는 타입을 잘라내어, UI가 표시되지 않거나 컴포넌트가 유실되거나 버튼이 반응하지 않거나 logcat/Xcode 콘솔에서 `NullReferenceException`, `TypeLoadException` 등의 예외가 나타날 수 있습니다. 이 페이지에서는 진단 및 해결 단계를 안내합니다: `link.xml` 적용 확인, `FairyGUICroppingHelper`를 시작 씬에 부착, 스트리핑 수준 조정.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| 빌드 후 UI가 표시되지 않음 / 일부 컴포넌트가 비어 있음 | 관리 코드 스트리핑이 정적으로 참조되지 않은 타입을 제거함 | `Runtime/link.xml`이 패키지에 포함되었는지 확인, [해결 단계 1](#단계-1-linkxml이-패키지에-포함되어-있는지-확인) 참조 |
| 콘솔에서 `FairyGUI.*` 타입 관련 `NullReferenceException` / `TypeLoadException` 발생 | 리플렉션으로 생성되는 타입(예: UI 패키지 컴포넌트)이 잘려나감 | 스트리핑 방지 스크립트 `FairyGUICroppingHelper`를 부착, [해결 단계 2](#단계-2-fairyguicroppinghelper를-시작-씬에-부착) 참조 |

| 스트리핑 수준이 높을 때(Medium/High) 문제 재현 | IL2CPP가 기본적으로 리플렉션으로만 사용되는 어셈블리를 제거함 | Managed Stripping Level을 낮추거나 `link.xml`에 의존, [해결 단계 3](#단계-3-managed-stripping-level-조정) 참조 |

## 해결 단계

### 단계 1: link.xml이 패키지에 포함되어 있는지 확인

본 패키지에는 `Runtime/link.xml`이 포함되어 있으며, 전체 `FairyGUI.Runtime` 어셈블리를 `preserve="all"`로 설정합니다:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="FairyGUI.Runtime" preserve="all"/>
</linker>
```

출처: [Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/link.xml#L1-L4)

확인 사항:

1. `Runtime/link.xml`이 프로젝트에 존재하는지 확인합니다(Package Manager로 설치 시 패키지에 함께 포함됨).
2. FairyGUI 소스 코드를 직접 프로젝트에 복사한 경우, `link.xml`의 `fullname`이 실제 어셈블리 이름과 일치하는지 확인해야 합니다(어셈블리의 `.asmdef` 이름 참조). 이름이 일치하지 않으면 이 파일이 적용되지 않습니다.
3. 빌드 로그에서 `link.xml`을 검색하여 빌드 시 이 linker 설명이 적용되었는지 확인합니다.

### 단계 2: FairyGUICroppingHelper를 시작 씬에 부착

패키지에는 스트리핑 방지 스크립트인 `FairyGUICroppingHelper`가 제공되며, `Start()`에서 모든 FairyGUI 타입을 명시적으로 참조하여 스트리퍼가 이를 제거하지 못하도록 합니다:

```csharp
/// <summary>
/// 코드 실행 시 스트리핑 오류가 발생하는 것을 방지합니다. 이 스크립트를 시작 씬에 추가하세요. 로직에는 아무런 영향을 주지 않습니다
/// </summary>
[Preserve]
public class FairyGUICroppingHelper : MonoBehaviour
{
    [Preserve]
    void Start()
    {
        _ = typeof(FairyGUI.AlignType);
        _ = typeof(FairyGUI.Anymous_T);
        _ = typeof(FairyGUI.AsyncCreationHelper);
        // ...이하 모든 FairyGUI 타입을 순서대로 참조
```

출처: [Runtime/FairyGUICroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/FairyGUICroppingHelper.cs#L6-L17)

작업 방법: 시작(첫 번째) 씬에 빈 GameObject를 새로 만들고 `Add Component`로 `FairyGUICroppingHelper`를 추가하면 됩니다. 이 스크립트는 실행 로직에 아무런 영향을 주지 않으며, 오직 타입 보존 용도로만 사용됩니다.

### 단계 3: Managed Stripping Level 조정

**Project Settings → Player → Other Settings → Optimization**에서:

| 빌드 대상 | 설정 항목 | 권장 값 |
|------------|--------|--------|
| Android | Managed Stripping Level | Low 또는 Disabled(문제 해결이 어려울 때는 먼저 Disabled로 원인 파악) |
| iOS | Managed Stripping Level | Low 또는 Disabled |

수준을 낮춘 후 다시 빌드합니다. `Disabled`일 때는 정상이고 수준을 높이면 비정상이라면, 아직 일부 타입이 `link.xml` / `[Preserve]`에 의존하여 보존되어야 한다는 뜻입니다. 스트리핑을 장기적으로 끄는 대신 단계 1과 2를 우선 해결하세요.

## 검증

1. IL2CPP로 다시 빌드하여 실기기에 설치합니다.
2. 이전에 비정상이었던 화면을 실행합니다: UI가 정상적으로 표시되고 버튼/비동기 로드에 콜백이 오는지 확인합니다.
3. logcat(Android) 또는 Xcode 콘솔(iOS)에서 `FairyGUI.*` 관련 `NullReferenceException` / `TypeLoadException`이 더 이상 발생하지 않는지 확인합니다.
4. 빌드 출력의 `IL2CPP` 생성 디렉터리(예: `Temp/StagingArea/Data/Il2CppOutputDirectory`)에서 이전에 누락되었던 타입 이름을 검색하여 잘려나가지 않았는지 확인할 수 있습니다.
