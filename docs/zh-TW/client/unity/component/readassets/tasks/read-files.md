# 讀取 StreamingAssets 檔案（位元組/文字/資料流）

透過 `BlankReadAssets` 靜態類別提供的 `System.IO` 風格 API，可以以統一且執行緒安全的方式直接讀取 `StreamingAssets` 下的任何檔案。它支援四種讀取模式：位元組、文字、逐行與資料流，同時也支援讀取 Android APK 內部的檔案（無需解壓縮）。

## 前置條件

- 已透過 Package Manager 匯入 `com.gameframex.unity.readassets` 套件（詳情請參閱 `README.zh-CN.md` 的「安裝」章節）
- 目標檔案已放置於 Unity 專案的 `Assets/StreamingAssets/` 目錄下
- 不支援 WebGL 平台

## 操作步驟

### 1. 讀取全部位元組（適用場景：圖片、設定二進位檔、自訂資料檔案）

```csharp
using GameFrameX.ReadAssets.Runtime;

// 一次載入記憶體，適合較小的檔案
byte[] data = BlankReadAssets.ReadAllBytes("Config/settings.bin");
```

`path` 參數是相對於 `StreamingAssets` 根目錄的相對路徑（例如 `"Config/settings.bin"`）。傳入 `null` 會拋出 `ArgumentNullException`，傳入空字串則會拋出 `ArgumentException`。

來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L198-L211)

### 2. 以資料流方式讀取（適用場景：大型檔案、漸進式解析、相容 `Stream` 的程式庫）

```csharp
using (Stream stream = BlankReadAssets.OpenRead("Levels/level1.dat"))
{
    // 像使用一般 System.IO.Stream 一樣使用它
    byte[] buffer = new byte[4096];
    int read = stream.Read(buffer, 0, buffer.Length);
}
```

`OpenRead` 會回傳一個 `System.IO.Stream`。在 Android 上，底層會直接從 APK 內部讀取。呼叫端需負責對回傳的資料流進行 `Dispose`。

來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L133-L146)

### 3. 讀取全部文字（適用場景：JSON、TXT、XML、CSV 等純文字設定檔）

```csharp
string json = BlankReadAssets.ReadAllText("Config/app-config.json");
MyConfig config = JsonUtility.FromJson<MyConfig>(json);
```

`ReadAllText` 內部會呼叫 `OpenText`（包裝一個 UTF-8 的 `StreamReader`），該讀取器會在讀取完成後自動釋放（Dispose）。

來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L167-L173)

### 4. 逐行讀取（適用場景：日誌、表格、TXT 單字表）

```csharp
string[] lines = BlankReadAssets.ReadAllLines("Localization/zh-CN.txt");
foreach (var line in lines)
{
    Debug.Log(line);
}
```

回傳值為已移除換行符號的字串陣列；不含檔案結尾處的空白行。

來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L176-L190)

### 5. 僅取得 `StreamReader`（需要控制編碼或自訂讀取行為時）

如果預設行為不符合您的需求，可以使用 `OpenText` 取得 `StreamReader` 進行自訂處理：

```csharp
using (var sr = BlankReadAssets.OpenText("Data/big.csv"))
{
    string header = sr.ReadLine();
    while (!sr.EndOfStream)
    {
        string row = sr.ReadLine();
        // 處理每一行
    }
}
```

來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L149-L164)

## 常見變化

- **讀取前檢查檔案是否存在**：使用 `FileExists(path)` 預先檢查，避免檔案遺失時出現例外處理分支。
- **列舉目錄檔案**：使用 `GetFiles(path, searchPattern, searchOption)`，支援萬用字元與遞迴搜尋。
- **讀取 AssetBundle**：使用 `LoadAssetBundle` / `LoadAssetBundleAsync`，內部會根據 APK 偏移量定位資源。
- **在編輯器中測試 APK 讀取**：呼叫 `InitializeWithExternalApk(apkPath)` 切換至 APK 模式。
- **跨執行緒呼叫**：所有 API 皆為執行緒安全，可直接從工作執行緒呼叫。

```csharp
// 列舉目錄中的所有 XML 檔案
string[] xmls = BlankReadAssets.GetFiles("Config", "*.xml", SearchOption.TopDirectoryOnly);

// 遞迴列舉 StreamingAssets 中的所有 XML 檔案
string[] allXmls = BlankReadAssets.GetFiles("/", "*.xml", SearchOption.AllDirectories);
```

來源：[BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L214-L230)

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| 拋出 `ArgumentNullException("path")` | `path` 為 `null` | 傳入非空字串；使用前先進行 null 檢查 |
| 拋出 `ArgumentException("Empty path", "path")` | `path` 為空字串 | 傳入有效的相對路徑 |
| 拋出找不到檔案的例外 | 相對路徑不正確，或檔名大小寫與實際 StreamingAssets 不符 | 事先使用 `FileExists` 驗證；在 Android 上，檔名請保持小寫且不含非 ASCII 字元 |
| WebGL 平台上發生編譯錯誤 | 此程式庫不支援 WebGL | 切換至 PC/行動裝置/主機平台，或自行使用 `UnityWebRequest` 實作 |
| `GetFiles` 回傳空陣列 | `StreamingAssets` 目錄不存在或路徑拼寫錯誤 | 先使用 `DirectoryExists` 驗證目錄 |

## 背景說明（選讀）

- 首次呼叫任何 API 時，程式庫會自動呼叫 `BlankReadAssets.Initialize()` 完成平台專屬的初始化，無需手動處理。在 Android 上，底層使用 ZIP 中央目錄定位 `StreamingAssets` 檔案，避免將整個 APK 解壓縮到磁碟；在其他平台上則直接存取檔案系統。
- 所有讀取進入點（`ReadAllBytes`、`OpenRead`、`OpenText` 等）都會在取得結果前呼叫 `EnsureInitialized()`，因此從任何執行緒呼叫都是安全的。
- 關於程式庫安裝與平台支援的資訊，請參閱 `README.zh-CN.md`。
