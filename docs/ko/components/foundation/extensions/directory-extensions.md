# 디렉터리/경로 확장을 사용하는 방법

`DirectoryExtensions.CreateAsDirectory`는 `GameFrameX.Foundation.Extensions` 네임스페이스의 `string` 확장 메서드로, 디렉터리를 안전하게 생성(필요 시 상위 디렉터리를 재귀적으로 생성)하는 데 사용되며, 파일 경로를 직접 인수로 전달하여 파일이 위치할 디렉터리를 자동으로 생성하는 것도 지원합니다.

## 사전 조건

- `GameFrameX.Foundation.Extensions` 네임스페이스를 참조합니다.
- 런타임 환경은 .NET이며 대상 경로에 대해 파일 시스템 쓰기 권한이 있어야 합니다.

```csharp
using GameFrameX.Foundation.Extensions;
```

## 작업 단계

1. **일반 디렉터리 생성**: 디렉터리 경로에 대해 직접 `CreateAsDirectory()`를 호출합니다. 디렉터리가 이미 존재하는 경우 예외가 발생하지 않습니다. 중간 계층이 존재하지 않으면 모든 상위 디렉터리를 재귀적으로 생성합니다.

```csharp
using GameFrameX.Foundation.Extensions;

string dir = @"C:\temp\gfx\level1\level2\level3";
dir.CreateAsDirectory();
```

Source: [DirectoryExtensions.cs#L57-L75](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DirectoryExtensions.cs#L57-L75)

2. **파일을 쓰기 전에 해당 디렉터리를 미리 생성**: 파일 경로를 전달하고 `isFile: true`로 설정하면, 확장 메서드는 자동으로 파일이 있는 디렉터리를 가져와 생성하며 파일 자체를 디렉터리로 생성하지는 않습니다.

```csharp
using GameFrameX.Foundation.Extensions;

string filePath = @"C:\temp\gfx\subdir\testfile.txt";
filePath.CreateAsDirectory(isFile: true);
// 이 시점에는 C:\temp\gfx\subdir 가 존재하며, testfile.txt 는 아직 생성되지 않음
```

Source: [DirectoryExtensions.cs#L57-L75](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DirectoryExtensions.cs#L57-L75)

3. **`File.WriteAllText`와 함께 파일 쓰기 전에 사용**: 일반적인 사용법은 로그나 설정 파일을 쓰기 전에 확장 메서드를 먼저 호출하여 디렉터리가 존재함을 보장한 뒤 쓰는 것입니다.

```csharp
using GameFrameX.Foundation.Extensions;
using System.IO;

string logFile = Path.Combine(AppContext.BaseDirectory, "logs", "app.log");
logFile.CreateAsDirectory(isFile: true);
File.AppendAllText(logFile, $"[{DateTime.Now}] started\n");
```

4. **결과 검증**: 메서드 자체는 값을 반환하지 않으므로, `Directory.Exists` 또는 `File.Exists`를 사용하여 생성이 예상대로 이루어졌는지 확인합니다.

```csharp
Assert.True(Directory.Exists(@"C:\temp\gfx\level1\level2\level3"));
Assert.True(Directory.Exists(@"C:\temp\gfx\subdir"));
```

## 일반적인 변형

- **상대 경로**: 상대 경로를 전달해도 `Directory.CreateDirectory`의 의미대로 생성됩니다. 예를 들어 `"logs/output".CreateAsDirectory()`는 현재 작업 디렉터리에 생성됩니다.
- **Linux/macOS 경로**: `Path.Combine` 또는 슬래시(/)를 사용하여 연결합니다. 예를 들어 `"/var/log/gfx/sub".CreateAsDirectory(isFile: true)`이며, 메서드 자체는 플랫폼을 구분하지 않습니다.
- **멱등(Idempotent) 반복 호출**: 동일한 경로에 대해 여러 번 호출해도 예외가 발생하지 않으므로, 시작流程이나 쓰기 루프에서 안심하고 반복 실행할 수 있습니다.

## 일반적인 오류

| 현상 | 원인 | 처리 |
|------|------|------|
| `null`을 전달하면 `ArgumentNullException` 발생 | 메서드가 진입점에서 명시적으로 `path`를 검증함 | 호출 전에 null이 아닌지 확인하거나 `??` 연산자로 기본값 제공 |
| `isFile: true`로 파일이 생성될 것으로 기대함 | 이 모드는 디렉터리만 생성하며 파일은 생성하지 않음 | 디렉터리 생성 후 별도로 `File.Create` / `File.WriteAllText` 등을 사용 |
| 파일 이름만 포함된 문자열(예: `"plainfile.txt"`)을 `isFile: true`로 전달했을 때 오류도 발생하지 않고 생성도 되지 않음 | `Path.GetDirectoryName`이 빈 값을 반환하여 메서드가 바로 return | 최소한 디렉터리 세그먼트를 포함한 전체 경로를 전달 |

## 배경 (선택 사항)

`CreateAsDirectory`는 `Directory.CreateDirectory`에 대한 얇은 래퍼입니다. 기본 .NET API는 이미 재귀 생성과 "디렉터리가 이미 존재하면 건너뛰기" 의미를 갖추고 있으며, 확장 메서드는 이를 바탕으로 두 가지를 추가로 처리합니다. 즉, "파일 경로를 자동으로 디렉터리 경로로 변환"을 호출 지점에 인라인하는 것과 진입점에서 `ArgumentNullException`을 통일되게 던지는 것입니다. 전체 계약 및 단위 테스트 커버리지는 [DirectoryExtensionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Extensions/DirectoryExtensionsTests.cs#L21-L169)를 참조하세요.
