# EventComponent / IEventManager API 速查

本頁收錄 GameFrameX.Event 事件模組對外的全部公開 API：場景元件 `EventComponent` 與其背後的介面 `IEventManager`,包含真實簽章、事件參數基底類別與執行緒安全說明，可直接按表查用。

## 取得元件

`EventComponent` 是掛在場景中的 Unity 元件(選單路徑 `GameFrameX/Event`,`[DisallowMultipleComponent]`,元件優先順序 -7000),它會在 `Awake` 中透過 `GameFrameworkEntry.GetModule<IEventManager>()` 取得事件管理器，隨後所有公開方法都直接轉發給該管理器。日常業務程式碼只需使用 `EventComponent`,無需自行建立 `IEventManager` 實作。

## EventComponent 公開 API

| 名稱 | 簽章 | 說明 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | 取得事件處理函式的總數量 |
| EventCount | `int EventCount { get; }` | 取得事件數量 |
| Count | `int Count(string id)` | 取得指定事件編號的事件處理函式數量 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 檢查指定事件是否已訂閱該處理函式 |
| CheckSubscribe | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 不存在時才訂閱，避免重複訂閱 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 取消訂閱事件處理函式 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 檢查並取消訂閱；handler 不存在時不執行任何操作 |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | 設定預設事件處理函式(無訂閱者時作為備援) |
| Fire | `void Fire(object sender, GameEventArgs e)` | 拋出事件；執行緒安全，主執行緒回呼，下一幀分發 |
| Fire(多載) | `void Fire(object sender, string eventId)` | 用 `eventId` 建立 `EmptyEventArgs` 並拋出；內部呼叫 `GameFrameworkGuard.NotNullOrEmpty` 驗證非空 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | 拋出事件立即模式；非執行緒安全，立刻分發 |

Source: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L171)

注意 `CheckSubscribe` 是 `EventComponent` 獨有的便利方法(介面上沒有)：它會先呼叫 `Check`,未訂閱時才呼叫底層 `Subscribe`。

```csharp
if (!Check(id, handler))
{
    m_EventManager.Subscribe(id, handler);
}
```

## IEventManager 介面成員

`EventComponent` 未公開 `Subscribe` 的轉發方法，底層訂閱統一透過介面完成(元件層提供 `CheckSubscribe` 代替)。介面定義如下：

| 名稱 | 簽章 | 說明 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | 取得事件處理函式的數量 |
| EventCount | `int EventCount { get; }` | 取得事件數量 |
| Count | `int Count(string id)` | 取得指定事件編號的事件處理函式數量 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 檢查是否存在事件處理函式 |
| Subscribe | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | 訂閱事件處理函式 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 取消訂閱事件處理函式 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 檢查並取消訂閱；handler 不存在時不執行任何操作 |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | 設定預設事件處理函式 |
| Fire | `void Fire(object sender, GameEventArgs e)` | 拋出事件；執行緒安全，主執行緒回呼，事件在拋出後的下一幀分發 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | 拋出事件立即模式；不是執行緒安全的，事件會立刻分發 |

Source: [Runtime/Event/IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L38-L105)

與 `EventComponent` 的差異一覽：

- `EventComponent.CheckSubscribe(id, handler)` 對應 `IEventManager.Subscribe(id, handler)` 的「檢查後訂閱」版本。
- `EventComponent.Fire(object sender, string eventId)` 是元件獨有的字串多載，等同於 `Fire(sender, EmptyEventArgs.Create(eventId))`。
- 初始化失敗時元件會輸出 `Log.Fatal("Event manager is invalid.")`。

## 事件參數類型

| 類型 | 定義 | 說明 |
|------|------|------|
| `GameEventArgs` | `public abstract class GameEventArgs : BaseEventArgs` | 所有遊戲邏輯事件的抽象基底類別，自訂事件繼承它 |
| `EmptyEventArgs` | `public static EmptyEventArgs Create(string eventId)` | 無負載事件；從 `ReferencePool.Acquire<EmptyEventArgs>()` 取得並設定事件編號，搭配 `EventComponent.Fire(sender, eventId)` 使用 |

```csharp
public static EmptyEventArgs Create(string eventId)

    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();

}
```

## Fire 與 FireNow 選用

| 場景 | 用法 | 原因 |
|------|------|------|
| 子執行緒 / 非同步任務中拋出事件 | `Fire(sender, e)` | 執行緒安全，回呼保證在主執行緒執行，但會延後到下一幀分發 |
| 主執行緒內需要同步執行回呼 | `FireNow(sender, e)` | 立刻分發；非執行緒安全，不要在子執行緒呼叫 |
| 只需要觸發訊號、無附加資料 | `Fire(sender, eventId)` | 元件多載會自動建立 `EmptyEventArgs`(內部透過引用池) |

以上執行緒語意來自原始碼中兩處的註解說明:`Fire` 「這個操作是執行緒安全的，即使不在主執行緒中拋出，也可保證在主執行緒中回呼事件處理函式，但事件會在拋出後的下一幀分發」;`FireNow` 「這個操作不是執行緒安全的，事件會立刻分發」。
