# 저장 경로 설정 및 경로 구분符 문제

`SetSavePath`를 호출한 후 객체의 버킷 내 저장 경로가 예상과 다를 경우(구분자가 추가되거나 누락되거나, 플랫폼에 맞지 않는 슬래시가 나타나는 경우), 이는 보통 입력된 경로의 형식이 `Path.DirectorySeparatorChar` 처리 로직과 일치하지 않기 때문입니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 저장 경로 끝에서 한 문자가 추가로 잘림 (예: `mybucket/folder` → `mybucket/folde`) | 입력 경로가 역슬래시 `\`로 끝나지만 현재 플랫폼 구분자가 슬래시 `/`임 (Windows 경로를 Linux/Mac 대상에 쓰는 경우 흔히 발생) | 호출 전에 `\`를 플랫폼 구분자로 바꾸거나, `Path.Combine`/`Path.DirectorySeparatorChar`로 조합 |
| 저장 경로 끝에 여전히 구분자가 남아 있음 (예: `mybucket/folder/`), 이후 이어 붙이면서 `mybucket/folder//file`이 생성됨 | 호출 시 구분자로 끝나지 않는 문자열을 전달했지만, 사실 그 전에 이미 수동으로 잘려 있었음; 혹은 구분자 없이 전달했지만 이미 구분자가 있는 경로에 이어 붙인 경우 | 매번 호출 전에 전체 경로를 다시 전달하여 중복 잘림을 피함 |
| 경로 안에서 `/`와 `\`가 섞여 사용되어 원격 객체 경로가 `mybucket/folder\file`로 나타남 | Windows 스타일 경로를 직접 이어 붙이거나 문자열에 `/`를 하드코딩함 | `Path.DirectorySeparatorChar`만 사용하도록 통일하고, 원격 경로 안에서 두 종류의 슬래시를 섞지 말 것 |

## 수정 단계

### 1. `SetSavePath`가 한 번만 처리하도록 하기

`SetSavePath`의 로직은 다음과 같습니다. 입력 문자열이 `Path.DirectorySeparatorChar`로 끝날 때만 마지막 한 문자를 제거합니다.

```csharp
public void SetSavePath(string savePath)
{
    if (savePath.EndsWith(Path.DirectorySeparatorChar.ToString()))
    {
        savePath = savePath.Substring(0, savePath.Length - 1);
    }

    BucketSavePath = savePath;
}
```

Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

따라서 입력 경로의 마지막 문자가 현재 플랫폼의 `Path.DirectorySeparatorChar`가 아니라면(예: Windows에서 `\`로 끝나는 경로를 전달했지만 실제 실행 대상 플랫폼이 macOS/Linux인 경우), 끝의 구분자가 제거되지 않아 이후 이어 붙이면서 구분자가 하나 더 들어간 원격 경로가 만들어집니다.

### 2. 플랫폼에 맞는 구분자 사용하기

하드코딩된 `/` 또는 `\`를 `Path.DirectorySeparatorChar`로 바꾸거나, Windows에서 경로를 전달할 때는 `\`로 끝나도록 통일합니다. 예시:

```csharp
string remote = $"mybucket{Path.DirectorySeparatorChar}folder";
manager.SetSavePath(remote);
```

### 3. 중복 호출 피하기

`SetSavePath`은 매번 입력된 값을 기준으로 `BucketSavePath`를 통째로 다시 쓰기 때문에, 한 번 호출한 뒤 추가로 수동으로 이어 붙이지 말고 최종 경로를 한 번에 그대로 전달해야 합니다.

```csharp
manager.SetSavePath("mybucket/folder");
```

## 검증

1. 업로드 완료 후, 객체 스토리지 콘솔에 로그인하거나 List 인터페이스를 호출하여 객체 Key가 예상 경로와 일치하고, 불필요한 `/` 또는 `\`가 없는지 확인합니다.
2. 알려진 파일 하나를 단일 파일 업로드(`UploadFile`)로 수행하여, 원격 Key가 `BucketSavePath` + 로컬 상대 경로와 같은지 비교합니다.
3. 플랫폼을 전환한 뒤(에디터 플랫폼을 macOS/Linux로 바꿔 다시 실행) 경로를 다시 설정하여 구분자 처리가 여전히 올바른지 확인합니다.
