# 缺失索引鍵與文化特性後援的處理方式

當 `GetString` 在所有提供者、整條後援鏈中都找不到與索引鍵相符的值時，框架會回傳索引鍵本身、累積缺失計數，並觸發 `MissingKey` 事件。本頁說明如何訂閱事件以觀測缺失、如何調整後援鏈與預設文化特性，以及如何控制格式化失敗時的行為。

## 前置條件

- 已透過 `LocalizationService` 取得 `ResourceManager` 單例，或已自行 `new ResourceManager()`。
- 已參考命名空間 `GameFrameX.Foundation.Localization` 與 `GameFrameX.Foundation.Localization.Core`。

## 操作步驟

### 1. 訂閱 `MissingKey` 事件以觀測缺失索引鍵

```csharp
using GameFrameX.Foundation.Localization;
using GameFrameX.Foundation.Localization.Core;

LocalizationService.Manager.MissingKey += (sender, args) =>
{
    Console.WriteLine($"[Missing] key={args.Key}");
    Console.WriteLine($"  culture={args.Culture.Name}");
    Console.WriteLine($"  fallback={string.Join(" -> ", args.FallbackChain.Select(c => c.Name))}");
    Console.WriteLine($"  providers={string.Join(", ", args.ProviderNames)}");
};
```

事件的引數為 `MissingResourceEventArgs`,其中包含索引鍵、所要求的文化特性、後援鏈，以及已搜尋之提供者的組件名稱。關於事件的觸發時機，請參閱 [`ResourceManager.cs`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L95-L97)(定義) 與 [`ResourceManager.cs#L281-L294`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L281-L294)(觸發位置)。

Source:[GameFrameX.Foundation.Localization/Core/MissingResourceEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/MissingResourceEventArgs.cs#L8-L40)

### 2. 取得缺失計數

```csharp
var manager = LocalizationService.Manager;
var stats = manager.GetStatistics(); // 包含 MissingKeyCount、FormatFailureCount、各索引鍵的命中次數等
```

### 3. 調整後援鏈與預設文化特性

`ResourceManager` 有兩個相關的切換設定：

| 屬性 | 預設值 | 功能 |
|------|--------|------|
| `DefaultCulture` | `CultureInfo.InvariantCulture` | 作為最終後援目的地的文化特性，會附加至後援鏈的結尾 |
| `CultureFallbackEnabled` | `true` | 停用後僅會查詢 `CurrentUICulture` 目前的文化特性 |

停用後援的範例：

```csharp
LocalizationService.Manager.CultureFallbackEnabled = false;
```

關於後援鏈的產生邏輯，請參閱 [`ResourceManager.cs#L191-L221`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L191-L221)。它會從所要求的文化特性出發，沿著 `Parent` 向上追溯，最後附加 `DefaultCulture` 與 `InvariantCulture`。

### 4. 控制格式化失敗時的行為

呼叫 `FormatString(key, args)` 時，若範本與引數不一致(例如：預留位置 `{0}` 缺少實際引數)，將依 `FormatErrorBehavior` 的設定進行處理：

```csharp
using GameFrameX.Foundation.Localization.Core;

LocalizationService.Manager.FormatErrorBehavior = LocalizationFormatErrorBehavior.ReturnKey;
// LocalizationFormatErrorBehavior.Throw  — 擲回 FormatException
// LocalizationFormatErrorBehavior.ReturnTemplate — 回傳未替換的範本(預設)
```

列舉型別的定義位於 [`LocalizationFormatErrorBehavior.cs`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/LocalizationFormatErrorBehavior.cs#L6-L22),分支的實作則位於 [`ResourceManager.cs#L242-L259`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L242-L259)。

## 常見變化

- **隨選探索與載入的 GameFrameX 組件**：為了避免在執行階段由 JIT 載入的組件遺漏當地語系化資源，`ResourceManager` 的建構函式已訂閱 `AppDomain.CurrentDomain.AssemblyLoad`。無需手動操作。
- **只想確認缺失率、不需要事件回呼**：直接呼叫 `GetStatistics()` 並讀取 `MissingKeyCount` 即可，無需訂閱事件。
- **希望在缺失時擲回例外以利自我測試**：將 `FormatErrorBehavior` 設為 `Throw`,即可在單元測試中斷言已確實執行到「範本 + 引數不一致」的路徑。

## 常見錯誤

| 現象 | 原因 | 修正 |
|------|------|------|
| UI 顯示英文索引鍵名稱(例如:`Utility.Exceptions.TimestampOutOfRange`) | 目前的 UI 文化特性 + 所有父文化特性 + `DefaultCulture` + `InvariantCulture` 皆不相符，且也未訂閱 `MissingKey` 事件 | 確認資源 DLL 是否已包含在套件中，並確認 `Localization.*.resources` 是否已內嵌；或明確設定 `DefaultCulture` |
| 即使變更 `DefaultCulture` 仍會後援至 `en-US` | 組件的資源中存在 `en-US` 的項目，且優先於 `DefaultCulture` | 這是預期的行為。若要強制使用 `DefaultCulture`,請停用 `CultureFallbackEnabled` 或移除對應的資源 |
| 突然大量回報 `FormatException` 記錄 | 預留位置與引數的數量不一致。預設行為為 `ReturnTemplate`,不會擲回例外 | 僅在偵錯時將 `FormatErrorBehavior` 設為 `Throw`,發行時改回 `ReturnTemplate` |

## 背景(選用)

後援的順序位於 [`ResourceManager.cs#L162-L184`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L162-L184):針對後援鏈中的每個文化特性，會依提供者的順序查詢，並回傳第一個相符的結果。提供者的例外會被吸收並輸出至 `Debug`,以避免單一損壞的資源破壞整個查詢。若所有路徑皆找不到結果，則呼叫 `RecordMissingKey`:遞增計數、依各索引鍵彙總，然後觸發事件。最終回傳給呼叫端的是索引鍵名稱本身，因此 UI 永遠能取得非空字串。
