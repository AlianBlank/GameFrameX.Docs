# タイムアウトと同時接続数の設定方法

GameFrameX.Web では、タイムアウト時間 `Timeout` は Inspector のシリアライズフィールドまたはコードで設定できます(デフォルト 5 秒)。同時接続数 `MaxConnectionPerServer` はコード経由でのみ `IWebManager` 上で設定できます(デフォルト 8)。これは通常(JSON)リクエストとバイナリリクエストの 2 つのスケジューリングチャネルの同時処理数をそれぞれ制限します。

## 前提条件

- シーンに `WebComponent` コンポーネントがアタッチされていること(メニュー `GameFrameX/Web`)。
- コードでマネージャーにアクセスする必要がある場合は、名前空間 `GameFrameX.Web.Runtime` と `GameFrameX.Runtime` を参照してください。

## 設定項目クイックリファレンス

| 設定項目 | 型 | デフォルト値 | 適用場所 | 説明 |
|--------|------|--------|----------|------|
| `WebComponent.m_Timeout` | `float`(秒) | `5f` | Inspector シリアライズフィールド | コンポーネント初期化時にマネージャーへ書き込まれる |
| `WebComponent.Timeout` | `float`(秒) | マネージャー値を代理 | プロパティ | 同時にシリアライズフィールドへ書き戻す |
| `WebManager.Timeout` | `float`(秒) | `5f` | マネージャーのプロパティ | 設定時に `RequestTimeout` を同期的に更新 |
| `WebManager.RequestTimeout` | `TimeSpan` | `Timeout` から派生 | マネージャーのプロパティ | リクエストオブジェクトへ実際に適用されるタイムアウト |
| `WebManager.MaxConnectionPerServer` | `int` | `8` | マネージャーのプロパティ | 通常チャネルとバイナリチャネルそれぞれの同時処理上限 |

## 操作手順

### 1. Inspector でタイムアウト時間を設定する

`WebComponent` がアタッチされている GameObject を選択し、Inspector で **タイムアウト時間** フィールドを変更します(単位：秒、デフォルト 5):

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L59-L60)

コンポーネントの `Awake()` 時にこの値がマネージャーへ書き込まれます:

```csharp
m_WebManager = GameFrameworkEntry.GetModule<IWebManager>();
if (m_WebManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebManager.Timeout = m_Timeout;
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L88)

### 2. コードで実行時にタイムアウト時間を調整する

`WebComponent.Timeout` はマネージャーへ直接プロキシされ、同時に値をシリアライズフィールドへ書き戻します:

```csharp
public float Timeout
{
    get { return m_WebManager.Timeout; }
    set { m_WebManager.Timeout = m_Timeout = value; }
}
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L66-L70)

使用例：

```csharp
// コンポーネントの Awake 後に呼び出す(例:Start())
webComponent.Timeout = 15f; // グローバルのタイムアウトを 15 秒に変更
```

### 3. コードで同時接続数を設定する

`MaxConnectionPerServer` は `WebManager` / `IWebManager` にのみ存在し、`WebComponent` では公開されていないため、コードで変更する必要があります:

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// タイムアウト時間(秒)を取得または設定します
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>
/// サーバーごとの最大接続数を取得または設定します
/// </summary>
public int MaxConnectionPerServer { get; set; }
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L42-L70)

使用例(`WebComponent.Awake` でのモジュール取得方法と同じ):

```csharp
GameFrameworkEntry.GetModule<IWebManager>().MaxConnectionPerServer = 4; // 各チャネルで同時に最大 4 リクエスト
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L81)

## よくあるバリエーション

**2 つのチャネルの同時接続数を個別に制御**：通常(JSON)リクエストとバイナリリクエストは同じ `MaxConnectionPerServer` 値を共有しますが、それぞれ独立してカウントされます——スケジューリングの入口はそれぞれ `m_SendingNormalList`(通常)と `m_SendingBinaryList`(バイナリ)です:

```csharp
// 通常リクエストチャネル:Update 内で上限に応じて待機キューからタスクを取り出す
if (m_SendingNormalList.Count < MaxConnectionPerServer)
{
    if (m_WaitingNormalQueue.Count > 0)
    {
        var webJsonData = m_WaitingNormalQueue.Dequeue();
        // ...リクエストを発行して m_SendingNormalList に追加
    }
}
```

// バイナリリクエストチャネル:同じ上限判定
if (m_SendingBinaryList.Count < MaxConnectionPerServer)

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| Inspector のタイムアウトを変更したのに反映されない | コードが `Awake()` の後に `WebComponent.Timeout` や `m_WebManager.Timeout` で上書きしている | 一箇所で統一して設定する。実行時の値変更は `Start()` 以降に行う |
| Inspector で同時接続数を変更したいがフィールドが見つからない | `MaxConnectionPerServer` が `WebComponent` 上でシリアライズされていない | `GameFrameworkEntry.GetModule<IWebManager>()` を使ってコードで設定する |
| `Timeout = 0.5f` を設定してもリクエストが長時間タイムアウトしない | UnityWebRequest へ適用する際に `(int)RequestTimeout.TotalSeconds` で切り捨てられ、1 秒未満は `0` になる | タイムアウト値は少なくとも `1f` 以上の整数秒に設定する |
| `MaxConnectionPerServer` をグローバルの総同時接続数と解釈している | 通常/バイナリの 2 つのチャネルがそれぞれこの値で独立して判定する | 同時接続上限を評価する際はチャネルごとに計算する |

## 背景(任意)

`Timeout` の setter は `RequestTimeout = TimeSpan.FromSeconds(value)` を同期的に派生させ、リクエストが実際に作成される時に初めてこの値が低レベルの `UnityWebRequest.timeout`(秒)または `HttpWebRequest.Timeout`(ミリ秒)に書き込まれます。そのため、タイムアウトを変更しても、その後新しく発行されるリクエストにのみ影響します。同時接続については、リクエストはまず待機キューに入り、`WebManager.Update` が毎フレーム `m_SendingNormalList.Count < MaxConnectionPerServer` をチェックし、条件を満たした場合にのみデキューして発行され、超過分は引き続きキューで待機します。
