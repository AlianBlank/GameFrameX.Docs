# 如何上传单个文件

通过 `ObjectStorageUploadFactory.Create<T>` 创建上传管理器并调用 `UploadFile`,即可把本地单个文件上传到对象存储的指定路径,返回 `bool` 表示成功与否。

## 前置条件

- 已安装 `GameFrameX.ObjectStorage` 包及其对应的对象存储后端实现(例如阿里云 OSS、腾讯云 COS 等,这些后端提供继承 `BaseObjectStorageUploadManager` 的具体类型)。
- 已准备好 `accessKey`、`secretKey`、`bucketName`,如目标服务需要,还需要 `endpoint`。
- 待上传的文件在本地存在,且有可读的绝对路径。

## 操作步骤

1. 通过工厂创建并初始化上传管理器。`Create<T>` 内部会调用 `Init`,无需再手动初始化:

```csharp
using GameFrameX.ObjectStorage.Editor;

IObjectStorageUploadManager uploader = ObjectStorageUploadFactory.Create<YourUploader>(
    accessKey: "your-access-key",
    secretKey: "your-secret-key",
    bucketName: "your-bucket",
    endpoint: "https://oss-cn-hangzhou.aliyuncs.com" // 部分服务可传 null
);
```

2. (可选)使用 `SetSavePath` 设置存储桶内的目标子目录。传入路径若以分隔符结尾,会被自动去掉末尾分隔符:

```csharp
uploader.SetSavePath("assets/textures/");
```

3. 调用 `UploadFile` 上传单个文件,传入完整的本地文件路径:

```csharp
bool ok = uploader.UploadFile(@"D:\project\Assets\textures\logo.png");
if (ok)
{
    UnityEngine.Debug.Log("上传成功");
}
else
{
    UnityEngine.Debug.LogError("上传失败");
}
```

4. 根据返回值判断结果。`UploadFile` 返回 `true` 表示成功,`false` 表示失败。

## 常见变体

- **自定义存储路径**:如果希望文件落到存储桶下的某个子目录,在上传前调用 `uploader.SetSavePath("your/sub/path")`。
- **批量上传**:单次仅上传一个文件,如需批量请改用 `UploadDirectory(string localDirectory)`(详见接口定义)。
- **不同后端**:只需把 `Create<T>` 的泛型替换为对应后端的具体管理器类型,例如 `YourCosUploader`、`YourMinioUploader` 等。

## 常见错误

| 症状 | 可能原因 | 处理 |
|------|---------|------|
| `UploadFile` 返回 `false` | 本地路径不存在或没有读权限 | 确认 `localFilePathAndName` 是合法绝对路径,文件可读 |
| 工厂调用抛出异常 | 泛型类型未实现 `IObjectStorageUploadManager` | 确认 `T` 继承自 `BaseObjectStorageUploadManager` |
| 文件上传到了根目录而不是预期子目录 | 未调用 `SetSavePath` 或参数拼写错误 | 在 `UploadFile` 之前显式调用 `SetSavePath` |
| 路径末尾多余分隔符 | `SetSavePath` 末尾带 `/` | 框架已自动去除,无需手动处理,但避免传空字符串 |

## 背景(可选)

接口 `IObjectStorageUploadManager` 在 `BaseObjectStorageUploadManager` 中提供 `UploadFile` 的默认实现,实际逻辑由后端子类的 `UploadFileInternal` 完成;`Create<T>` 通过 `Activator.CreateInstance` 实例化并自动调用 `Init`,因此调用方只需关心文件路径与返回结果。
