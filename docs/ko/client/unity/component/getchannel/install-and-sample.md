# 설치 및 실행 예제

이 페이지에서는 GameFrameX GetChannel(`com.gameframex.unity.getchannel`)을 Unity 프로젝트에 설치하고, 채널 번호를 가져오는 첫 번째 예제를 실행해 보는 과정을 안내합니다. 이 패키지는 iOS / tvOS / visionOS / Android / Editor / PC / WebGL / UWP / 콘솔 플랫폼을 지원하며, Unity 2019.4 이상이 필요합니다.

## 빠른 시작

### 사전 조건

- Unity 2019.4 이상 버전([package.json](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/package.json#L5)의 `"unity": "2019.4"` 참조).
- GameFrameX UPM 레지스트리(`https://gameframex.upm.alianblank.uk`) 또는 GitHub에 접근할 수 있어야 합니다.

### 설치(네 가지 방법 중 하나 선택)

1. 프로젝트의 `Packages/manifest.json`을 편집하여 `scopedRegistries`를 추가하고 `dependencies`에 버전(현재 `1.3.2`)을 지정합니다:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.getchannel": "1.3.2"
  }
}
```

`scopes`는 이 레지스트리를 통해 어떤 패키지가 확인(resolve)되는지를 제어하며, `com.gameframex`로 시작하는 패키지만 이 레지스트리에서 가져옵니다.

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L36-L54)

2. `manifest.json`의 `dependencies` 노드에 직접 Git 주소를 추가합니다:

```json
{
  "dependencies": {
    "com.gameframex.unity.getchannel": "https://github.com/gameframex/com.gameframex.unity.getchannel.git"
  }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L56-L61)

3. Unity의 `Package Manager` 창에서 `Add package from git URL`을 선택하고 `https://github.com/gameframex/com.gameframex.unity.getchannel.git`을 입력합니다.
4. 리포지토리를 직접 다운로드하여 Unity 프로젝트의 `Packages` 디렉터리에 배치하면 Unity가 자동으로 로드하여 인식합니다.

**설치 확인**: `Window → Package Manager`를 열어 패키지 목록에서 `Game Frame X Get Channel`가 보이면(displayName은 [package.json](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/package.json#L2-L4) 참조) 설치가 성공한 것입니다.

### 첫 번째 예제 실행

1. `Package Manager`에서 해당 패키지를 선택하고 `Samples`를 펼친 후 `Import`를 클릭하여 예제를 가져옵니다(예제는 [package.json](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/package.json#L12-L18)에 정의되어 있으며, 경로는 `Samples~`이고 그 안에 예제 스크립트 [BlankGetChannelExample.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Sample~/BlankGetChannelExample.cs#L12)가 포함되어 있습니다).
2. 새 스크립트를 만들어 `BlankGetChannel.GetChannelName`을 호출합니다:

```csharp
using UnityEngine;

public class MyGameScript : MonoBehaviour
{
    void Start()
    {
        // 기본 채널 번호 가져오기 (키 이름은 "channel")
        string channel = BlankGetChannel.GetChannelName();
        Debug.Log("当前渠道号: " + channel);

        // 지정한 키의 채널 번호 가져오기
        string customChannel = BlankGetChannel.GetChannelName("channelName");
        Debug.Log("自定义渠道号: " + customChannel);

        // 채널 번호를 가져오면서 기본값 지정
        string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
        Debug.Log("子渠道号: " + subChannel);
    }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L103-L123)

API의 실제 시그니처는 다음과 같습니다(`channelKey` 기본값 `"channel"`, `defaultValue` 기본값 `"default"`):

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98)

3. `Play`를 누르면 Console에 현재 채널 번호가 출력됩니다. 어떤 채널 파일도 구성하지 않은 경우 `default`가 반환됩니다.

## 일반적인 변형: 각 플랫폼에서 채널 번호 제공

`GetChannelName(key)`을 호출할 때 `key`는 해당 플랫폼 구성의 키 이름과 반드시 일치해야 합니다.

| 플랫폼 | 구성 위치 | 예시 |
|------|----------|------|
| iOS / tvOS / visionOS | Xcode 프로젝트의 `Info.plist` | `<key>channel</key>` → `ios_cn_taptap` |
| Android | `AndroidManifest.xml`의 `<application>` 안에 있는 `<meta-data>` | `android:name="channel"` → `android_cn_taptap` |
| Editor / PC / WebGL / UWP / PS4 / PS5 / Xbox One / Nintendo Switch | `Resources/application_config.txt` | `channel=editor_cn_test` |

Android의 `AndroidManifest.xml` 작성 방법:

```xml
<application ...>
    <activity ...>
        ...
    </activity>

    <meta-data
        android:name="channel"
        android:value="android_cn_taptap" />

    <meta-data
        android:name="sub_channel"
        android:value="beta" />
</application>
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L150-L165)

Editor / PC / WebGL / UWP / 콘솔 플랫폼에서는 `Resources` 아래에 `application_config.txt`를 생성하며, 각 줄은 `键名=值` 형식입니다:

```
channel=editor_cn_test
sub_channel=beta
other_key=other_value
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L175-L179)

iOS에서는 수동으로 구성하지 않아도 실행할 수 있습니다. 빌드 후 처리기(post-processor)는 `Info.plist`에 `channel` 키가 **없는** 경우 자동으로 `channel = default`를 기록하며, 이미 존재하면 건너뜁니다:

```csharp
[PostProcessBuild(99)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        Run(path);
    }
    catch (Exception e)
    {
        Debug.LogException(e);
    }
}
```

출처: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L13-L29)

## 자주 발생하는 오류

- **반환값이 항상 `default`임**: `GetChannelName(key)`의 `key`가 플랫폼 구성의 키 이름과 일치하지 않는 경우입니다. iOS의 `Info.plist`, Android의 `<meta-data android:name="...">`, Editor/PC의 `application_config.txt` 키 이름을 각각 확인하세요.
- **iOS 패키징 후 채널이 덮어써짐**: 빌드 후 처리기는 `Info.plist`에 `channel` 키가 존재하지 않을 때만 `default`를 기록하며, 이미 존재하면 `已有渠道,跳过设置=>...` 로그를 출력하고 수정하지 않습니다([PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L39-L48) 참조). Xcode에서 수정한 것이 최종 패키징 프로젝트의 `Info.plist`인지 확인하세요.
- **PC / Editor 플랫폼에서 값을 읽지 못함**: `application_config.txt`는 반드시 Unity 프로젝트의 `Resources` 폴더 아래에 있어야 하며, 각 줄의 형식은 엄격하게 `键名=值`여야 합니다.
- **코드가 잘림(스트리핑)**: 패키지에는 Unity 코드 스트리핑으로 관련 API가 제거되지 않도록 `link.xml`이 포함되어 있습니다. 직접 작성한 스트리핑 구성으로 이를 덮어썼다면 해당 파일을 유지하세요([README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L191) 참조).

## 배경

`GetChannelName`은 읽은 결과를 캐시하여 구성 파일을 반복해서 읽는 것을 방지합니다. iOS 측은 `DllImport("__Internal")`의 `getChannelName(string channelKey)` 네이티브 호출을 통해 `Info.plist`를 읽습니다([BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L47-L48) 및 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm) 참조). 각 플랫폼의 채널 구성에 대한 전체 설명은 《채널 번호 구성 참조》를 참고하세요.
