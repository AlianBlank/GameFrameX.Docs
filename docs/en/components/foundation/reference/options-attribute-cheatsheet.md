# Command-Line Option Attributes Quick Reference

The `GameFrameX.Foundation.Options.Attributes` namespace provides four attributes for binding class properties to command-line arguments, environment variables, and diagnostic labels. This page covers each attribute's properties, usage, and applicable targets.

## Attribute Overview

| Attribute | Target | Inherits | Default Value Behavior | Use Case |
|------|------|------|------------|----------|
| [OptionAttribute](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/OptionAttribute.cs#L57-L134) | Property | `Attribute` | Explicitly specified via `DefaultValue` | Valued options, such as strings, numbers, paths |
| [FlagOptionAttribute](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/FlagOptionAttribute.cs#L56-L81) | Property | `OptionAttribute` | Forced to `false` at construction | Boolean switches that only indicate presence |
| [EnvironmentVariableAttribute](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/EnvironmentVariableAttribute.cs#L56-L77) | Property | `Attribute` | Not provided | Fields read only from environment variables |
| `GrafanaLokiLabelTagAttribute` | Property | `Attribute` | Not provided | Attaches a Loki label name to a property for log aggregation |

`OptionAttribute` and `FlagOptionAttribute` share the same parsing path: [`OptionsBuilder`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L334-L345) retrieves all derived attributes at once via `GetCustomAttributes<OptionAttribute>()` and then dispatches them for processing.

## OptionAttribute

### Properties

| Property | Type | Default | Description |
|------|------|------|------|
| `LongName` | `string` | `null` | The long name of the option, such as `"server"` or `"port"`. |
| `DefaultValue` | `object` | `null` | The default value used when no argument is passed; the type must match the property type. |
| `Description` | `string` | `null` | The description shown in help/debug output. |
| `Required` | `bool` | `false` | Enforces that the option be provided during validation; otherwise an error is thrown. |
| `EnvironmentVariable` | `string` | `null` | Allows the value to be read directly from an environment variable; see below for details. |
| `Sensitive` | `bool` | `false` | Marks the field as sensitive; diagnostic output will be redacted. |

### Constructors

```csharp
public OptionAttribute();
public OptionAttribute(string longName);
```

The parameterized constructor only accepts `longName`; the remaining fields are assigned via an object initializer.

### Usage Example

```csharp
public class MyOptions
{
    [Option("server", Required = true, Description = "Server address")]
    public string Server { get; set; }

    [Option("port", DefaultValue = 8080)]
    public int Port { get; set; }
}
```

## FlagOptionAttribute

`FlagOptionAttribute` inherits from `OptionAttribute` and is dedicated to boolean switches. **Both constructors fix `DefaultValue` to `false`** — in other words, as long as the option does not appear on the command line, the property remains `false`.

### Constructors

```csharp
public FlagOptionAttribute();
public FlagOptionAttribute(string longName);
```

### Usage Example

```csharp
public class MyOptions
{
    [FlagOption("verbose")]
    public bool Verbose { get; set; }

    [FlagOption("debug")]
    public bool Debug { get; set; }
}
```

Source: [FlagOptionAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/FlagOptionAttribute.cs#L43-L54)

Note: `FlagOptionAttribute` is only accepted by [`OptionsBuilder`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L345-L346) when the property type is `bool`; other types are ignored.

## EnvironmentVariableAttribute

Binds an environment variable name at construction; during the parsing phase, the value is read from `Environment.GetEnvironmentVariable(Name)`. **`Name` is a read-only property that can only be assigned in the constructor**.

### Properties

| Property | Type | Description |
|------|------|------|
| `Name` | `string` | The environment variable name, set via the constructor. |

### Constructors

```csharp
public EnvironmentVariableAttribute(string name);
```

### Usage Example

```csharp
public class MyOptions
{
    [EnvironmentVariable("DATABASE_URL")]
    public string DatabaseUrl { get; set; }

    [EnvironmentVariable("API_KEY")]
    public string ApiKey { get; set; }
}
```

`OptionAttribute.EnvironmentVariable` and `EnvironmentVariableAttribute` share the same environment variable mapping path: [`BuildEnvironmentVariableMappings`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L549-L560) collects both kinds of sources.

## GrafanaLokiLabelTagAttribute

Attaches a Loki label name to logging properties, used to carry dimensions such as `job`, `app`, and `env` in structured logs. Unlike the previous three attributes, it does not participate in command-line parsing; instead, it is read by [`OptionsDebugger`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs) during the log-writing phase and then output to Loki.

> The detailed signatures of `GrafanaLokiLabelTagAttribute`'s public properties and constructors were not found in the source code; for further confirmation, please consult [GrafanaLokiLabelTagAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/GrafanaLokiLabelTagAttribute.cs) directly.

## Parsing and Validation Rules (Excerpted from OptionsBuilder)

- Default value application: [`ApplyDefaultValues`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L322-L334) reads `DefaultValue` and writes it to the target property.
- Required option validation: [`ValidateRequiredOptions`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L428-L439) only checks `OptionAttribute.Required`; `EnvironmentVariableAttribute` is not included in the required list.
- Multiple attribute merging: [`BuildOptions`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L783-L785) uses `GetCustomAttributes(typeof(OptionAttribute), true).Cast<OptionAttribute>()` to collect all derived attributes together, ensuring that `FlagOptionAttribute` and custom derived classes also take effect.

## Selection Quick Reference

| Requirement | Recommended Attribute |
|------|----------|
| Key-value arguments in the `--name value` form | `OptionAttribute` |
| Presence-only switches such as `--verbose` | `FlagOptionAttribute` |
| Read only from environment variables, without appearing on the command line | `EnvironmentVariableAttribute` |
| Support both command line and environment variables, with command line taking priority | `OptionAttribute` + setting `EnvironmentVariable` |
| Need to attach specific labels to Loki logs | `GrafanaLokiLabelTagAttribute` |
| Values are sensitive fields such as passwords or tokens | `OptionAttribute` + `Sensitive = true` |

## Common Mistakes

- **Applying `FlagOptionAttribute` to a non-`bool` property**. [`OptionsBuilder`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L345-L346) simply skips it during the parsing phase, which is equivalent to the option not existing.
- **Setting `EnvironmentVariableAttribute` but forgetting to export the environment variable**. In this case, the property keeps its type's default value (e.g., `null` for `string`); no runtime error occurs, which can easily mask a missing configuration.
- **Setting `Required = true` but not passing the argument**. [`ValidateRequiredOptions`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L428-L439) throws an error at the validation stage; if you just want the command-line option to be optional with an environment variable fallback, use `OptionAttribute.EnvironmentVariable` instead of `Required`.
- **Failing to set `Sensitive = true`, causing passwords to be written in plain text**. Diagnostic logs and debug output print the value as-is; be sure to explicitly mark sensitive fields such as tokens and connection strings.
