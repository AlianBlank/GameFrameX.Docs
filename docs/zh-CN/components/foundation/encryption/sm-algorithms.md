# 如何使用国密 SM2/SM3/SM4

`GameFrameX.Foundation.Encryption` 提供国密三大算法的一站式入口：`Sm2Helper`（非对称加解密 / 密钥对生成）、`Sm4Helper`（对称加解密，支持 CBC / ECB）以及基于 BouncyCastle 的 `SM3Util.Hash`（SM3 摘要）。本页给出三种算法的最小可用代码示例与常见坑点。

## 前置条件

- 引入命名空间：`GameFrameX.Foundation.Encryption`、`GameFrameX.Foundation.Encryption.Sm`。
- 项目已引用 BouncyCastle（`Org.BouncyCastle.*`），框架默认带入。
- SM2 公私钥为十六进制字符串；SM4 密钥在非 hex 模式下长度为 16 字节，hex 模式下为 32 个十六进制字符。

## 操作步骤

### 1. SM3 哈希

SM3 是哈希算法，不是加密算法。`SM3Util.Hash` 接受字符串，返回固定长度（256 bit）的十六进制摘要，内部使用 UTF-8 编码以保证跨平台一致。

```csharp
using GameFrameX.Foundation.Encryption.Sm;

string hash = SM3Util.Hash("hello world");
// 同一输入多次调用结果一致,可用于完整性校验
```

Source: [SM3Util.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm/SM3Util.cs#L47-L69)

### 2. SM2 非对称加密

`Sm2Helper` 提供字符串与字节数组两套重载，并支持密钥对生成；底层基于 BouncyCastle。

```csharp
using GameFrameX.Foundation.Encryption;

// 生成密钥对
Sm2Helper.GenerateKeyPair(out string publicKey, out string privateKey);

// 公钥加密
string cipher = Sm2Helper.Encrypt(publicKey, "secret message");

// 私钥解密
string plain = Sm2Helper.Decrypt(privateKey, cipher);
```

字节数组重载（适合二进制数据 / 网络协议）：

```csharp
byte[] pubKeyBytes = Convert.FromHexString(publicKey);
byte[] data = System.Text.Encoding.UTF8.GetBytes("payload");
string cipherHex = Sm2Helper.Encrypt(pubKeyBytes, data);
byte[] plainBytes = Sm2Helper.Decrypt(Convert.FromHexString(privateKey), Convert.FromHexString(cipherHex));
```

Source: [Sm2Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm2Helper.cs#L62-L174)

### 3. SM4 对称加密

`Sm4Helper` 默认采用 CBC 模式；密钥长度规则：非 hex 模式 16 字节，hex 模式 32 个字符；不传 `iv` 时在 hex 模式下默认填全 0（`00000000000000000000000000000000`）。

CBC 加密 / 解密：

```csharp
using GameFrameX.Foundation.Encryption;

string key = "0123456789abcdef";        // 16 字节
string cipher = Sm4Helper.EncryptCbc(key, "明文文本");
string plain  = Sm4Helper.DecryptCbc(key, cipher);
```

ECB 模式（不需要 IV）：

```csharp
string cipher = Sm4Helper.EncryptEcb(key, "明文文本");
string plain  = Sm4Helper.DecryptEcb(key, cipher);
```

JavaScript 兼容模式（与前端 sm-crypto 等库互通的 padding 行为）：

```csharp
string cipher = Sm4Helper.EncryptCbc(key, "明文", forJavascript: true);
string plain  = Sm4Helper.DecryptCbc(key, cipher, forJavascript: true);
```

hex 密钥模式：

```csharp
string hexKey = "0123456789ABCDEF0123456789ABCDEF"; // 32 个十六进制字符
string cipher = Sm4Helper.EncryptCbc(hexKey, "明文", hexString: true);
```

## 常见变体

| 场景 | 推荐做法 |
|------|----------|
| 与前端 / Node 互通 | SM4 用 `forJavascript: true`，前端用 sm-crypto 同模式 |
| 长报文签名校验 | 先 `SM3Util.Hash` 得到摘要，再随业务字段一起传输对比 |
| 高频加解密二进制流 | 使用 SM2 / SM4 的字节数组重载，避免字符串编解码开销 |
| 持久化 SM2 密钥 | 直接存 `GenerateKeyPair` 输出的十六进制字符串；勿自行 Base64 |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `ArgumentException: KeyMustBe16Characters` | SM4 密钥在非 hex 模式下不是 16 字节 | 调整字符串长度，或改用 `hexString: true` 传 32 字符 hex |
| `ArgumentException: KeyMustBe32Characters` | hex 模式密钥长度不是 32 | 检查 hex 串是否被截断或补全了多余字符 |
| SM2 解密抛出 `CryptographicException(Sm2InvalidDataFormat)` | 公私钥不匹配，或密文被错误二次编码 | 确认加解密两侧十六进制大小写一致、未做多余 Base64 |
| SM3 哈希在不同平台结果不同 | 输入被 `Encoding.Default` 重新编码 | 必须用 UTF-8 编码传入；`SM3Util.Hash` 内部已统一使用 UTF-8 |
| `ArgumentException(PublicKeyStringCannotBeEmpty)` | SM2 公钥字符串为空 | 检查 `GenerateKeyPair` 输出未被截断 |

## 背景（可选）

`Sm2Helper` / `Sm4Helper` 是面向业务的薄封装，所有原始逻辑（椭圆曲线点运算、SM4 轮密钥扩展等）由 BouncyCastle 完成；`SM3Util` 直接复用 BouncyCastle 的 `Sm3Digest`。三类异常在 `Sm*Helper` 层被捕获后统一包装为 `CryptographicException`，便于上层按一种类型捕获。
