# WeChat通知が到着しない場合の対処法

ビルド完了後に企業微信ロボット通知が届かない場合、通常は `WeChatBotKey` が渡されていないか、ロボットが有効になっていないか、ビルドフローが `IsUpdateAssetPackageVersion` の成功分岐に到達していないことが原因です。修正前に以下の診断表と実際の現象を照らし合わせてください。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| コンソールに `System.Net.Http.HttpRequestException` またはタイムアウト例外が表示される | `qyapi.weixin.qq.com` にアクセスできない、またはプロキシでブロックされている | ビルドマシンのネットワーク/プロキシを確認し、`https://qyapi.weixin.qq.com/cgi-bin/webhook/send` へアクセスできるか確認する |
| WeChatグループに一切メッセージが届かない | コマンドラインに `-WeChatBotKey` が渡されておらず、`BuilderOptions.WeChatBotKey` が空文字列になっている | ビルドコマンドに `-WeChatBotKey <ロボットKey>` を追加する（大文字小文字に注意）|
| `{"errcode":40001,...}` または `errcode":40014` を受信する | ロボット Key が間違っているか無効になっている | 企業微信グループロボットの Webhook Key を再コピーする |
| `{"errcode":45009,...}` を受信する | メッセージ頻度が企業微信ロボットの制限（20件/分）を超えている | ビルド頻度を落とすか、複数のロボットに分割する |
| 通知が一度も呼び出されず、ログにも `Debug.Log(response)` がない | `IsUpdateAssetPackageVersion` が false、またはリソースバージョンの更新に失敗している | `-IsUpdateAssetPackageVersion true` を同時に渡し、`BuilderUpdateAssetPackageVersionHelper.Run` が `true` を返すようにする |
| Unity Console に `Debug.LogException(e)` のみ出力され、レスポンス本文がない | 例外が `catch (Exception e)` で握りつぶされている | 後述の「修正手順 - 握りつぶされた例外を確認する」を参照 |

## 修正手順

### 1. コマンドラインに `-WeChatBotKey` が渡されているか確認する

`BuilderOptions.WeChatBotKey` のデフォルト値は空文字列で、コマンドラインに `-WeChatBotKey` が指定された場合にのみ代入されます。

```csharp
else if (commandLineArg == "-WeChatBotKey")
{
    if (index + 1 < commandLineArgs.Length)
    {
        _builderOptions.WeChatBotKey = commandLineArgs[index + 1];
    }
}
```

ビルドコマンド例（Unity コマンドライン）:

```bash
-gameframex.builder -WeChatBotKey xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx -IsUpdateAssetPackageVersion true
```

パラメータの説明は [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L117) を参照してください。

### 2. ビルドが通知分岐に到達しているか確認する

通知は「リソースバージョンの更新が成功した」後にのみ送信されるため、`WeChatBotKey` だけを渡しても意味がありません。

```csharp
if (_builderOptions.IsUpdateAssetPackageVersion)
{
    var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
    if (result)
    {
        WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
    }
}
```

両方のスイッチを同時に指定します:

```bash
-IsUpdateAssetPackageVersion true -WeChatBotKey <key>
```

`BuilderUpdateAssetPackageVersionHelper.Run` が false を返した場合、通知はトリガーされないため、まずバージョン更新失敗の原因を調査してください。

### 3. Webhook Key が有効かどうかを検証する

Key が間違っている場合、企業微信は `errcode:40001`（secret エラー）または `40014`（不正な Key）を返します。`curl` で直接テストできます:

```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<あなたのKey>' \
  -H 'Content-Type: application/json' \
  -d '{"msgtype":"text","text":{"content":"hello"}}'
```

`errcode: 0` が返れば正常です。それ以外の場合は、企業微信グループでロボットを再度追加し、新しい Key を取得してください。

### 4. 握りつぶされた例外を確認する

`WeChatNotifyWorkHelper.Run` はすべての例外をキャッチして `Debug.LogException` で記録します。例外スタックだけが表示されている場合、HTTP 呼び出し自体が失敗しています（ネットワーク/DNS/タイムアウト）。

```csharp
try
{
    var httpResponseMessage = httpClient.PostAsync(url, stringContent).GetAwaiter().GetResult();
    var response = httpResponseMessage.Content.ReadAsStringAsync().GetAwaiter().GetResult();
    Debug.Log(response);
}
catch (Exception e)
{
    Debug.LogException(e);
}
```

対応方針: `httpClient.Timeout` は 30 秒のため、イントラネット環境では適切に長くしてください。HTTPS 証明書はシステムの信頼チェーンで処理されますが、ビルドマシンが自己署名プロキシを使用している場合は `HttpClientHandler` の追加設定が必要です。

### 5. Newtonsoft.Json の参照が存在することを確認する

CHANGELOG で `WeChatNotifyWorkHelper` に `Newtonsoft.Json` の参照が欠落していた問題が特にとりあげられています。コンパイル時に `The type or namespace name 'Newtonsoft' could not be found` が出る場合は、`Editor/GameFrameX.Builder.Editor.asmdef`（または対応するアセンブリ定義）に `Newtonsoft.Json` の参照を追加してください。

```text
* **builder:** WeChatNotifyWorkHelper に欠落していた Newtonsoft.Json の参照を追加
```

## 検証

1. ビルドを再実行し、Unity Console に `Debug.Log(response)` と正常な JSON レスポンス本文（`errcode: 0` を含む）が同時に出力されることを確認する。
2. 企業微信グループに `### 游戏资源版本更新` の markdown 通知が表示され、内容に時刻、リソースバージョン、ゲームバージョンなどのフィールドが含まれていることを確認する。
