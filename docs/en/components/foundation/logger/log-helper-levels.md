# How to Use LogHelper to Output Leveled Logs

`LogHelper` is a static class under the `GameFrameX.Foundation.Logger` namespace. Built on Serilog, it provides log output methods at six levels — Debug / Verbose / Info / Warning / Error / Fatal — supporting structured templates, console output, and exception logging. After reading this page, you will be able to write convention-compliant logs at each level in your own code.

## Prerequisites

- The .NET project references the `GameFrameX.Foundation.Logger` assembly (Serilog is already included as a transitive dependency).
- Inject a configured `Serilog.ILogger` via `LogHelper.SetLogger(...)` early during application startup; otherwise, `LogHelper` will use the built-in `InternalTempLogger` to buffer logs and flush them once the real logger is in place.

## Steps

### 1. Initialize the Logger

```csharp
using GameFrameX.Foundation.Logger;
using Serilog;

var logger = new LoggerConfiguration()
    .MinimumLevel.Verbose()      // Allow output down to the Verbose level
    .WriteTo.Console()
    .CreateLogger();

LogHelper.SetLogger(logger);
```

Source: [LogHelper.cs#L101-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L101-L112)

### 2. Call the Corresponding Method for Each Level

The entry methods for the six levels are named directly after the level names and share the same signatures: `(string messageTemplate, ...)` or `(object message)`, internally delegating to the same-named methods of the underlying `ILogger`.

```csharp
using GameFrameX.Foundation.Logger;

// Debugging / detailed information
LogHelper.Verbose("启动阶段:加载配置 {ConfigName}", configName);
LogHelper.Debug("用户 {Id} 命中缓存", userId);

// General information
LogHelper.Info("登录成功 user={Id} ip={Ip}", userId, ip);
LogHelper.Info(loginResult);

// Warning
LogHelper.Warning("接口 {Api} 响应耗时 {Ms}ms 超过阈值", apiName, elapsed);

// Error
LogHelper.Error("下单失败 orderId={Id}", orderId);

// Fatal
LogHelper.Fatal("数据库连接中断 {Conn}", connectionString);
```

### 3. Log Errors/Fatal Messages with Exceptions

The `Error` / `Fatal` overloads accept an `Exception` parameter and write the exception object into the log event:

```csharp
try
{
    DoWork();
}
catch (Exception ex)
{
    LogHelper.Error(ex, "执行失败 task={Name}", taskName);
    // Or use the Fatal level
    LogHelper.Fatal(ex, "致命错误 task={Name}", taskName);
}
```

Source: [LogHelper.Error.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Error.cs), [LogHelper.Fatal.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Fatal.cs)

### 4. Print Only to the Console

For scenarios where you don't need to write files or go through Serilog, use `LogHelper.Console`, which writes directly to `System.Console` with millisecond-precision timestamps:

```csharp
LogHelper.Console("服务器启动中...");
LogHelper.Console("加载资源 {Count} 个,耗时 {Ms}ms", count, ms);
```

Source: [LogHelper.Console.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Console.cs), [LogHelper.cs#L145-L156](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L145-L156)

### 5. Flush the Buffer Before the Application Exits

Call `FlushAndSave()` or `CloseAndFlushAsync()` before the program shuts down to write the buffered logs to file:

```csharp
LogHelper.FlushAndSave();
// Or
await LogHelper.CloseAndFlushAsync();
```

## Quick Reference for the Six Levels

| Level | Method | Typical Use | Corresponding Serilog Method |
|------|------|----------|------------------|
| Verbose | `LogHelper.Verbose(...)` | Finest-grained tracing information, details inside loops | `ILogger.Verbose` |
| Debug | `LogHelper.Debug(...)` | Diagnostic information during debugging, usually disabled in release builds | `ILogger.Debug` |
| Info | `LogHelper.Info(...)` | Key points in business flows (login, order placement, exit) | `ILogger.Information` |
| Warning | `LogHelper.Warning(...)` | Recoverable exceptions, threshold alerts, degradation | `ILogger.Warning` |
| Error | `LogHelper.Error(...)` / `Error(Exception, ...)` | Business failures, caught exceptions | `ILogger.Error` |
| Fatal | `LogHelper.Fatal(...)` / `Fatal(Exception, ...)` | Process-level fatal errors, unrecoverable | `ILogger.Fatal` |

## Common Variants

- **Structured property templates**: Each level has 1–8 generic overloads that bind objects directly as properties (rather than concatenating strings), making it easy for downstream Sinks to search by field:
  ```csharp
  LogHelper.Info<Player>("当前玩家 {Current}", player);
  LogHelper.Info<Player, int>("玩家 {Current} 击杀 {Kills}", player, kills);
  ```
  Source: [LogHelper.Info.cs#L87-L216](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L87-L216)

- **Object parameter**: When an `object` is passed, `Info` calls `ToString()`; if it is `null`, the string `"null object"` is logged:
  ```csharp
  LogHelper.Info(someObject); // outputs "null object" when someObject is null
  ```
  Source: [LogHelper.Info.cs#L48-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L48-L51)

- **Zero-parameter template**: Only a message template is provided with no formatting values, which is equivalent to printing the string directly.

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| `LogHelper.Info(...)` produces no output | `LogHelper.SetLogger(...)` was not called, and `MinimumLevel` was not configured to let this level through | Inject the Logger at startup and set `MinimumLevel.Verbose()` for debugging |
| Logs are lost when the process exits | `FlushAndSave()` / `CloseAndFlushAsync()` was not called | Call either of the above methods at the end of `OnExit` / `Main` |
| `{Name}` in the template is not replaced with a value | Extra placeholders were used in the string, or the argument count does not match | Use standard Serilog template syntax `{Property}`, with the number of arguments matching the number of placeholders |
| You want to know where files are written | The current methods do not expose the path directly; you need to configure a Serilog Sink yourself | Specify it yourself via `LoggerConfiguration().WriteTo.File(...)` |
| Crash when logging a `null` object | Only `Info(object)` has a `ToString()` fallback; how the other levels handle `null` depends on Serilog | Switch to the string-template version, or perform a null check yourself |

## Background (Optional)

`LogHelper` is a `public static partial class` whose methods for each level live in separate files (`LogHelper.Debug.cs`, etc.), all obtaining the current `Serilog.ILogger` via `GetLogger()`. If `SetLogger` has not yet been called, the internal `InternalTempLogger` is used to buffer logs, which are flushed over with `FlushTo` once the real logger is injected; therefore, **the initialization order does not have to strictly precede the first log call**. The further down the level, the more detailed the output; in production, `MinimumLevel` is usually set to `Information`, and lowered to `Debug` or `Verbose` for debugging. For overall Serilog integration, see "How to Configure LogHandler to Initialize the Logging System".
