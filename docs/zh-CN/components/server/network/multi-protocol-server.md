# 启用 TCP / WebSocket / HTTP 多协议监听

在 GameFrameX.Server 启动入口中按需开启 TCP、WebSocket、HTTP 三种网络监听,让同一套业务代码同时对外提供不同的协议端点,常用于多端融合(原生 TCP、网页/H5、小程序、外部 HTTP API)。

## 前置条件

- 已完成 [GameFrameX.Server](https://github.com/GameFrameX/GameFrameX.Server) 的本地构建与基础配置。
- 确认对外端口未被占用,防火墙已放行对应的 TCP 端口(框架默认监听端口见下表)。
- 已熟悉 `GameFrameX.StartUp` 命名空间下 `AppStartUpGame` 等启动类的调用顺序。

## 操作步骤

1. 打开启动入口文件 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`,框架的协议注册与启动流程集中在此处。

2. 按业务需要,在 `AppStartUpGame` 中调用 `UseServer` 或对应的扩展方法,同时传入 `tcpOptions`、`wsOptions`、`httpOptions` 三个配置节点。任一节点缺省即关闭对应协议。

3. 在配置文件(默认 `App.Config.json` 或环境变量覆盖)中写入以下结构,框架在启动时会自动按 `Enable*` 开关决定是否监听对应协议:

```json
{
  "Server": {
    "Tcp":    { "Enable": true,  "Host": "0.0.0.0", "Port": 30100 },
    "WebSocket": { "Enable": true, "Host": "0.0.0.0", "Port": 30101, "Path": "/" },
    "Http":   { "Enable": true,  "Host": "0.0.0.0", "Port": 30102 }
  }
}
```

4. 启动 `GameFrameX.Launcher`,运行日志会出现类似 `Tcp Server Started`, `WebSocket Server Started`, `Http Server Started` 的提示,表示三条链路已并行监听。

5. 在任意一处业务代码里通过 `INetSession` 或 `HttpContext` 处理消息,框架会根据连接进入的端口/路径自动派发到对应协议通道,无需在业务层区分协议。

```csharp
// 注册消息处理(对 TCP / WebSocket 一致)
[MessageHandler(MessageId.C2S_Login)]
public class C2S_LoginHandler : IMessageHandler
{
    public async Task HandleAsync(INetSession session, C2S_Login request)
    {
        // 业务逻辑
    }
}
```

来源:[GameFrameX.Launcher/StartUp/AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L1-L120)

## 常见变体

- **仅启用 TCP**:把 `Tcp.Enable` 设为 `true`,其余两项设为 `false`,常用于纯网关服。
- **WebSocket + HTTP 共存**:H5 页用 WebSocket,管理后台或回调通知走 HTTP,二者共用同一进程与同一套 Actor。
- **关停单个协议**:将对应节点的 `Enable` 置 `false` 即可,无需修改代码。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动报 `Address already in use` | 多协议使用了同一端口,或被其他进程占用 | 每个协议使用不同 `Port`,并确认 OS 端口空闲 |
| WebSocket 客户端连接后立即断开 | `Path` 或子协议不匹配 | 保持 `Path` 与客户端 URL 一致(如 `ws://host:port/` ) |
| HTTP 接口 404 | 未注入 `Enable*` 配置或缺控制器 | 检查 `Http.Enable=true` 并确保控制器已注册 |
| TCP 能连但收不到消息 | 启动顺序问题,业务 Actor 未注册 | 确认 `AppStartUpHotfixGameByEntry` 等被 `AppStartUpGame` 顺序调用 |

## 背景(可选)

`AppStartUpGame` 通过 `GameFrameX.StartUp` 提供的统一入口对应用服务器协议栈进行初始化,使用同一套消息路由与会话( `INetSession` )抽象承载三种协议,因此业务处理层(参见 `Component/ServerComponent.cs`)只需面向消息交互,不关心底层传输方式。

更多关于整体启动流程与 `ServerComponent` 的说明,见《Server 组件》。
