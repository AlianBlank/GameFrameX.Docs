# 檔案讀取錯誤：ArgumentNullException / ArgumentException(path)

呼叫 `BlankReadAssets` 的 `OpenRead`、`ReadAllBytes`、`GetFiles` 等方法時，若傳入的 `path` 參數為 `null` 或空字串，系統會立即擲回參數例外狀況。同樣地，在路徑元件缺漏的情況下呼叫 `PathUtil.CombineSlash` / `NormalizeRelativePath`,也會擲回相同類型的例外狀況。本頁面可協助您快速找出目前遇到的情況並加以修正。

## 修正步驟

### 1. `OpenRead` / `ReadAllBytes` 收到 `null`

原始碼進入點:[BlankReadAssets.OpenRead](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L132-L146) 與 [BlankReadAssets.ReadAllBytes](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L197-L211)。兩者都會先執行 `path == null` 的 null 檢查。

```csharp
using GameFrameX.Asset;

string path = ResolveConfigPath(); // 可能會回傳 null

if (string.IsNullOrEmpty(path))
{
    Debug.LogError("Config file path is not configured, skipping read");
    return;
}

byte[] data = BlankReadAssets.ReadAllBytes(path);
```

### 2. `OpenRead` / `ReadAllBytes` 收到空字串

原始碼:[BlankReadAssets.cs#L139-L142](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L139-L142)。當 `path.Length == 0` 時，會擲回 `ArgumentException("Empty path", "path")`。

```csharp
// 錯誤範例
string dir = "config/";
string file = ""; // 來自失敗的設定讀取
string full = dir + file; // -> "config/" 的子路徑可能仍然有效,但若 file 本身為空,將會擲回錯誤
byte[] data = BlankReadAssets.ReadAllBytes(full); // 取決於 full,無法依賴

// 修正:使用 PathUtil.CombineSlash 串接並驗證
string full = PathUtil.CombineSlash(dir, file);
if (string.IsNullOrEmpty(full) || full.EndsWith("/"))
{
    throw new InvalidOperationException("Invalid target file path: " + full);
}
```

### 3. `PathUtil.CombineSlash` 擲回 `ArgumentNullException`

原始碼:[PathUtil.CombineSlash](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75)。若 `a` 或 `b` 任一為 `null`,便會擲回例外狀況。

```csharp
string dir = settings.TryGetValue("assetDir", out var d) ? d : null;
string name = settings.TryGetValue("assetName", out var n) ? n : null;

if (dir == null || name == null)
{
    Debug.LogWarning("Asset path is incomplete, using default config");
    dir = "fallback";
    name = "default.bin";
}

string full = PathUtil.CombineSlash(dir, name);
```

### 4. `PathUtil.NormalizeRelativePath` 擲回 `ArgumentException("Empty or null", "relative")`

原始碼:[PathUtil.NormalizeRelativePath](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L83)。任何空值都會直接擲回例外狀況，即使是空字串也一樣。

```csharp
public static byte[] SafeRead(string relative)
{
    if (string.IsNullOrWhiteSpace(relative))
    {
        Debug.LogError("relative is empty, aborting read");
        return Array.Empty<byte>();
    }
    return BlankReadAssets.ReadAllBytes(relative);
}
```

### 5. APK 模式下 `GetFiles` 的 `path` 為 `null`

原始碼:[BlankReadAssets.ApkImpl.GetFiles](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L93-L116)。當 `path == null` 時，會在任何目錄索引檢查之前先擲回 `ArgumentNullException`。

```csharp
string dir = request.GetQueryParam("dir");
if (string.IsNullOrEmpty(dir))
{
    dir = "/"; // 回退至根目錄
}
string[] files = BlankReadAssets.GetFiles(dir, "*", SearchOption.TopDirectoryOnly);
```

### 6. APK 內部的 `ArgumentException()`(無訊息)

原始碼:[BlankReadAssets.ApkImpl.cs#L299-L306](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L299-L306)。這是 APK 實作中 `GetFiles`/`GetDirectories` 對目錄基礎路徑的二次驗證失敗，通常表示 `BlankReadAssetsImpl` 未正確初始化。

```csharp
// 編輯器端:確保呼叫 GetFiles 前已完成初始化
BlankReadAssets.InitializeWithExternalApk(apkPath);

// 執行階段:確保 streamingAssets 已掛載(BlankReadAssets 會透過 EnsureInitialized 自我檢查)
if (!BlankReadAssets.FileExists("manifest/index.txt"))
{
    throw new IOException("APK assets not mounted, unable to enumerate directories");
}
```

## 驗證

套用上述修正後，請使用以下最小驗證腳本重現原始錯誤情境，並確認不會再擲回任何例外狀況：

```csharp
using GameFrameX.Asset;
using System;

void AssertNoThrow(string label, Action act)
{
    try { act(); Console.WriteLine($"[OK] {label}"); }
    catch (ArgumentNullException) { Console.WriteLine($"[FAIL] {label}: ArgumentNullException"); }
    catch (ArgumentException)   { Console.WriteLine($"[FAIL] {label}: ArgumentException"); }
}

AssertNoThrow("null path", () => BlankReadAssets.OpenRead(null));
AssertNoThrow("empty path", () => BlankReadAssets.OpenRead(""));
AssertNoThrow("valid path", () =>
{
    using var s = BlankReadAssets.OpenRead("config/test.txt");
});
```

在預期的輸出中，前兩項應落入您自己的 `catch` 分支並被妥善處理，而第三項 `[OK] valid path` 必須正常通過。

## 常見錯誤

- **依賴 `path + ""` 字串串接**：空的檔名會使 `ReadAllBytes` 落入 `path.Length == 0` 分支並擲回 `ArgumentException`。請改用 `PathUtil.CombineSlash` 並驗證結果。
- **將 `null` 與 `""` 視為同一種情況**：原始碼在 `OpenRead` 中對 `null` 擲回 `ArgumentNullException`,對 `""` 則擲回 `ArgumentException`;兩者例外狀況類型不同，搜尋日誌時請特別留意。
- **在 APK 模式下忘記先初始化**：未初始化時，`EnsureInitialized` 會擲回 `InvalidOperationException` 而非參數例外狀況，容易造成誤導；請先確認初始化完成，再檢查參數驗證。
- **將根路徑或含引號的字串傳給 `PathUtil.NormalizeRelativePath`**:此方法對以 `"` 包裹的字串有特殊處理([PathUtil.cs#L93](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L93));路徑中內嵌未成對的雙引號可能導致解析例外狀況。
