# How to Read Generated Configuration in Unity / .NET

By following the steps on this page, you can directly read the configuration data generated by the `gen-client-*` / `gen-server-*` scripts in your Unity client or .NET server code, without writing any parsing code by hand.

## Prerequisites

- Excel tables have been prepared in `Excels/Tables/` as required by the documentation (see the naming rules below).
- The generation scripts have been run, and the C# classes (e.g., `TbItemConfig`, `TbAchievementConfig`) and data files already exist in the Unity project.
- The namespace of the `Tables` container class has been imported (by default, it is under the root namespace of the generation path).

## Steps

1. In the `Excels/Tables/` directory, create/confirm that Excel file names follow the `字母-英文名-中文名.xlsx` rule (Letter-EnglishName-ChineseName.xlsx), for example:

   ```
   D-ItemConfig-道具表-道具-1001.xlsx
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L94-L96)

2. Run the generation script (double-click the `.bat` on Windows, or use `sh` on Mac/Linux). Once it finishes, C# classes and data files will be generated in the Unity project:

   ```bash
   # Client (Unity)
   sh gen-client-json.sh
   # or gen-client-bin.sh

   # Server (.NET)
   sh gen-server-bin.sh
   # or gen-server-json.sh
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L136-L141)

3. In your code, get the corresponding table from the `tables` container and query a single record by primary key with `Get(id)`:

   ```csharp
   // Get the item whose id is 10001
   var item = tables.TbItemConfig.Get(10001);

   // The item name automatically switches to the current language (e.g., Chinese displays "钻石" [Diamond])
   Debug.Log(item.Name);
   Debug.Log(item.Price); // 10
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L152-L159)

4. In the tool-generated code, class names follow the `Tb英文名` rule (Tb followed by the English name). The table below shows the mapping between the Excel files currently in this repository and the generated class names:

   | Excel File Name | Generated C# Class Name |
   |--------------|---------------|
   | `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
   | `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
   | `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |
   | `L-Localization-成就.xlsx` | `TbLocalization` |

   Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L194-L199)

## Common Variants

- **Splitting large tables**: If a table contains a lot of data (thousands of rows), you only need to keep the **English names the same** and use any distinguishing Chinese names; the tool will automatically merge them into a single table. For example, `D-ItemConfig-道具表.xlsx` and `D-ItemConfig-道具表-1001.xlsx` will be merged into `TbItemConfig`.
- **For one side only**: Add the group marker `c` (client only) or `s` (server only) between the English name and the Chinese name; if omitted, code is generated for both sides.
  - `D-ItemConfig-c-道具表.xlsx` → only the client uses `TbItemConfig`
  - `D-ItemConfig-s-道具表.xlsx` → only the server uses `TbItemConfig`
- **Choosing data types**: `text` is a field that goes through multilingual translation (you fill in a key, and the actual text lives in `Local/`), while `string` is a plain string kept as-is without translation.

## Common Errors

| Error | Cause | Fix |
|------|------|------|
| Cannot find the `tables.TbXxx` class | The generation script was not run, or the English segment of the Excel file name is missing | Run `gen-client-json.sh` / `gen-client-bin.sh` and confirm the file name contains a valid English segment |
| The tool reports the error `不支持中文表名` (Chinese table names are not supported) | The English segment of the file name contains Chinese | Change that segment to pure English, e.g., `ItemConfig` instead of `道具表` |
| `Get(id)` returns null | The id is not in the table's data | First use `tables.TbXxx.GetAll()` or read all the data directly to confirm whether the id exists |
| The field value is a key instead of the translated text | The field type was set to `string` instead of `text` | Change the type in row 2 of the header from `string` to `text`, then regenerate |

## Background (optional)

`tables` is the master container generated by Luban; each `TbXxx` table corresponds to one Excel sheet. `text` type fields go through localization mapping for the current language at read time, so you need to provide key translations for every language under `Excels/Local/`.
