# AOT 보존 검증 오류 처리 방법

CI에서 `AotPreserveValidationRunner.ValidateGeneratedFiles()`를 실행하거나 Unity 메뉴에서 HybridCLR AOT 보존 생성을 트리거할 때, 생성 파일이 누락되었거나 현재 설정과 일치하지 않거나, 생성 디렉토리에 오래된 파일이 있으면 오류가 발생합니다. 이 페이지에서는 일반적인 오류 메시지에 대한 진단 표와 해당 수정 단계를 제공합니다.

## 빠른 진단

| 증상 (예외 메시지 원문) | 원인 | 수정 |
|------|------|------|
| `Generated file is missing: Assets/Generated/AotPreserve/link.xml` | `Assets/Generated/AotPreserve/` 디렉토리 또는 `link.xml`이 존재하지 않음 | 아래 "수정 단계 1"을 참조하여 생성 메뉴를 다시 실행 |
| `Generated file is out of date: Assets/Generated/AotPreserve/...` | 설정이 변경되었지만 생성된 `link.xml`/참조 코드/asmdef/보고서가 아직 새로 고쳐지지 않음 | 아래 "수정 단계 1"을 참조하여 생성을 다시 실행 |
| `Generated file is stale: Assets/Generated/AotPreserve/...` | 생성 디렉토리에 설정에서 제거된 이전 파일이 남아 있음 | 생성을 다시 실행 (디렉토리가 자동으로 비워짐), 아래 "수정 단계 1" 참조 |
| `Preserve type entry is null.` | `IAotPreserveSettingsProvider`의 `PreserveTypes`/`WrapTypes`/`PreserveGenericTypes`에 `null` 요소가 포함됨 | 설정 코드를 확인하고 null 항목을 제거, "수정 단계 2" 참조 |
| `Preserve generic type entry is null.` | 위와 동일, `PreserveGenericTypes`에서 발생 | 위와 동일 |
| `Preserve member entry is null.` | `PreserveMembers` 배열에 null 문자열이 있음 | 설정을 확인, "수정 단계 2" 참조 |
| `Hotfix AOT preserve generation failed: ...` | `GenerateAndWrite()`가 생성 단계에서 오류를 감지함 (예: 위의 몇 가지 유형) | 예외의 각 줄을 확장하고 이 표에 따라 하나씩 수정 |
| 검증이 `ValidateGeneratedFiles()`에서 빈 배열을 반환하지만 여전히 `InvalidOperationException`을 보고함 | 거의 발생하지 않음; 발생하면 예외 `Message` 전체를 붙여넣어 조사 | 예외 `Message` 전문을 수집하여 피드백 |

예외 발생 위치는 [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27)를 참조하고, 오류 메시지 조합 로직은 [`AotPreserveGenerator.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L103-L122)를 참조하세요.

## 수정 단계

### 1. AOT 보존 파일 재생성

대부분의 "missing/out of date/stale" 유형 오류는 직접 재생성하면 해결됩니다.

1. Unity 메뉴 바에서 **GameFrameX → HybridCLR Generate AOT Preserve**를 클릭합니다 (메뉴 상수는 [`AotPreserveConstants.MenuPath`](/src/Editor/AotPreserve/AotPreserveConstants.cs#L65) 참조).
2. 콘솔에 오류가 없을 때까지 기다립니다. 생성기는 먼저 전체 `Assets/Generated/AotPreserve/` 디렉토리를 삭제한 다음 다음 파일들을 작성합니다:
   - `Assets/Generated/AotPreserve/link.xml`
   - `Assets/Generated/AotPreserve/aot_preserve_report.md`
   - `Assets/Generated/AotPreserveReferences.cs`
   - `Assets/Generated/AotPreserve.Generated.asmdef`
   - 유형별로 분할된 `AotPreserveReference_*.cs` 시리즈 참조 플레이스홀더 파일
3. CI 시나리오에서는 코드 진입점을 사용합니다:

```csharp
using GameFrameX.Editor;
AotPreserveGenerator.GenerateAndWrite();
```

작성 로직과 실패 시 예외는 [`AotPreserveGenerator.GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L94)를 참조하세요: `result.HasErrors`가 true이면 먼저 `InvalidOperationException("Hotfix AOT preserve generation failed:\n...")`을 던지고, 이후 디스크 작업을 계속합니다; 디스크 쓰기가 실패하면 `IOException` 또는 `UnauthorizedAccessException`을 던집니다.

### 2. 설정에서 null 항목 정리

예외 메시지가 `Preserve type entry is null.`, `Preserve generic type entry is null.`, `Preserve member entry is null.`로 시작할 때, 사용자 정의 구현한 `IAotPreserveSettingsProvider`가 `null` 요소를 포함하는 배열을 반환했음을 의미합니다. 이러한 null은 분석 단계에서 `AotPreserveAnalysis.Errors`로 수집되어 결국 검증기에 의해 오류 메시지로 던져집니다.

수정 방법:

1. 프로젝트에서 [`IAotPreserveSettingsProvider`](/src/Editor/AotPreserve/IAotPreserveSettingsProvider.cs)를 구현하는 클래스를 찾습니다 (기본 구현은 [`DefaultAotPreserveSettingsProvider`](/src/Editor/AotPreserve/DefaultAotPreserveSettingsProvider.cs) 참조, [`AotPreserveSettingsProviderResolver`](/src/Editor/AotPreserve/AotPreserveSettingsProviderResolver.cs)에 의해 해석됨).
2. `PreserveTypes` / `WrapTypes` / `PreserveGenericTypes` / `PreserveMembers`를 반환하기 전에 `null`을 필터링합니다.
3. 생성 및 검증을 다시 실행합니다.

### 3. 남아 있는 오래된 파일 정리

`Generated file is stale: <경로>`가 표시되면, 일반적으로 이전 생성에서 출력된 파일이지만 이번 설정에서는 더 이상 필요하지 않은 파일입니다. 생성 메뉴를 직접 다시 실행하세요 — [`GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L80-L84)는 먼저 `Directory.Delete(GeneratedDirectory, true)`를 수행한 다음 다시 만듭니다.

`Assets/Generated/AotPreserve/` 아래의 파일을 수동으로 변경하지 마세요 — 이 파일들은 생성된 결과물이며 다음 생성 시 덮어쓰여집니다.

## 검증

수정 후 CI 또는 로컬에서 다음 방법 중 하나로 통과를 확인합니다:

- 코드 진입점:

```csharp
using GameFrameX.Editor;
AotPreserveValidationRunner.ValidateGeneratedFiles(); // 예외가 발생하지 않으면 통과
```

구현은 [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27)를 참조하세요: 내부적으로 `AotPreserveGenerator.ValidateGeneratedFiles()`를 호출하고 모든 오류를 줄 바꿈으로 연결한 후 `InvalidOperationException`을 던집니다.

- 생성기 검증 진입점을 직접 호출:

```csharp
var errors = AotPreserveGenerator.ValidateGeneratedFiles();
// errors.Length == 0 이면 통과
```

반환된 배열이 0이면 모든 생성 파일이 완비되어 있고 설정과 일치함을 의미합니다; 0이 아니면 배열의 각 문자열이 독립적인 오류이므로 위의 진단 표에 따라 하나씩 처리합니다.
