# 10 分钟跑通第一个游戏脚本

跟着本页,你能在 Unity 工程里把 GameFrameX 跑起来,让一个简单的游戏脚本(通过 `GameFrameworkLog` 输出日志)正常执行,作为后续使用框架其他模块的起点。

## 前置条件

- Unity 2019.4 或更高版本([README.md](/README.md#L57-L61))
- 项目启用了 .NET Standard 2.0+ API 兼容级别
- 通过 Unity Package Manager 或直接 clone 方式,把 `com.gameframex.unity` 加入工程

## 操作步骤

1. **在场景里创建启动脚本。** 新建一个 C# 脚本,例如 `MyGameEntry.cs`,挂到任意场景物体上:

   ```csharp
   using UnityEngine;
   using GameFrameX;

   public class MyGameEntry : MonoBehaviour
   {
       private void Start()
       {
           // 框架提供的统一日志入口,详见 GameFrameworkLog
           GameFrameworkLog.Info("Hello, GameFrameX!");
       }
   }
   ```

2. **确认命名空间。** 框架的运行时基类位于 `GameFrameX` 命名空间下,例如 `GameFrameworkEntry`、`GameFrameworkLog` 等(目录参考 [Runtime/Base](/Runtime/Base))。

3. **运行场景。** 在 Unity 中点击 Play,Console 窗口应输出 `Hello, GameFrameX!`,说明框架运行时已被正确加载并可被你的脚本调用。

4. **接入框架事件(可选,验证扩展能力)。** 如果你想继续验证事件/任务池,可以定义一个继承自框架事件基类的参数,并使用事件订阅 API 来监听它(详见《事件池》与《任务池》章节)。

## 常见变体

- **作为 UPM 包安装**:在 `Packages/manifest.json` 的 `dependencies` 中加入 `"com.gameframex.unity": "https://github.com/GameFrameX/com.gameframex.unity.git"`,然后回到本页步骤 1。
- **作为子模块 / 直接嵌入**:把仓库克隆到工程 `Assets/` 下任意目录,完成后同样从步骤 1 开始。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `GameFrameworkLog` 找不到 | 命名空间未引用或包未正确导入 | 在脚本顶部 `using GameFrameX;`,并确认包已加入 `Packages/manifest.json` |
| Console 无任何输出 | 脚本未挂载或 `Start` 未触发 | 把脚本挂到场景物体上,确保场景被加载 |
| 编译报 `.NET Standard` 相关错误 | 工程 API 兼容级别过低 | Player Settings → Api Compatibility Level 改为 `.NET Standard 2.1` |

## 背景(可选)

GameFrameX 采用 Runtime / Plugins / Editor 三层模块化架构,Runtime 模块下的 `Base/` 提供框架核心基座,包括日志、事件池、引用池、任务池、变量系统等子系统([README.md](/README.md#L65-L108))。完成本页脚本运行后,可继续阅读各子系统页面深入使用。
