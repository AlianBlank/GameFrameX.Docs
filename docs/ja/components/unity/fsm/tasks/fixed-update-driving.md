# FixedUpdate で FSM を駆動する方法

`FsmState<T>` で `OnFixedUpdate` をオーバーライドすれば、状態マシンを Unity の物理フレーム(`FixedUpdate`)で駆動できます。フレームワークの `FsmComponent` は Unity の `FixedUpdate` を自動的にすべての登録済み FSM に転送するため、手動で呼び出す必要はありません。

## 前提条件

- `FsmComponent` をゲームのエントリーポイントとなる GameObject にアタッチしていること(Add Component → `GameFrameX/FSM`)。フレームワークが `Awake` 内で `IFsmManager` を取得します。
- 業務側で状態マシンを作成済みであること:`GameFrameworkFsm` または `FsmComponent.CreateFsm`。詳細は `FsmComponent.cs` を参照してください。
- 少なくとも 1 つの `FsmState<T>` を継承した状態クラスを定義していること。

## 操作手順

1. 状態クラスで `OnFixedUpdate` をオーバーライドし、物理フレームの `elapseSeconds` と `realElapseSeconds` を受け取ります。

```csharp
using GameFrameX.Fsm;

public class PlayerRunState : FsmState<Player>
{
    protected internal override void OnFixedUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // elapseSeconds は Time.fixedDeltaTime、realElapseSeconds は Time.fixedTime
        var rb = fsm.Owner.GetComponent<Rigidbody>();
        rb.MovePosition(rb.position + fsm.Owner.MoveDirection * fsm.Owner.Speed * elapseSeconds);
    }
}
```

Source: [FsmState.cs#L75-L89](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L75-L89)

2. 状態マシンを作成する際に、この状態を状態集合に追加し、FSM をその状態から起動します。

```csharp
var fsm = GameEntry.GetComponent<FsmComponent>().CreateFsm<Player>(
    owner: this,
    states: new FsmState<Player>[]
    {
        new PlayerIdleState(),
        new PlayerRunState(),
        new PlayerJumpState(),
    });

fsm.Start<PlayerRunState>();
```

3. 業務コード側で `Update`/`FixedUpdate` の呼び出しを再度記述する必要はありません。`FsmComponent.FixedUpdate` が `Time.fixedDeltaTime` と `Time.fixedTime` をマネージャーに転送します:

```csharp
private void FixedUpdate()
{
    if (m_FsmManager == null) return;
    m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
}
```

Source: [FsmComponent.cs#L76-L84](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

4. マネージャー層がすべての破棄されていない FSM に対して `FixedUpdate` を呼び出し、最終的に現在の状態の `OnFixedUpdate` にルーティングされます:

```csharp
public void FixedUpdate(float fixedDeltaTime, float fixedTime)
{
    // ...m_Fsms を反復し、各破棄されていない FSM に対して FixedUpdate を呼び出す
}
```

Source: [FsmManager.cs#L110-L130](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L110-L130)

5. `Fsm<T>.FixedUpdate` は現在の状態のコールバックのみをトリガーし、他の状態は実行されません:

```csharp
internal override void FixedUpdate(float elapseSeconds, float realElapseSeconds)
{
    m_CurrentStateTime += elapseSeconds;
    m_CurrentState.OnFixedUpdate(this, elapseSeconds, realElapseSeconds);
}
```

Source: [Fsm.cs#L682-L690](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L682-L690)

## よくあるバリエーション

- `FixedUpdate` 内で状態を切り替えたい場合は、`ChangeState<TState>()` を呼び出します。切り替えのタイミングは `OnFixedUpdate` 内に配置し、ロジックフレームの `OnUpdate` と交互に発生するのを避けてください。
- ロジックフレームの動作も同時に必要な場合は、`OnUpdate` をオーバーライドしてください。両者は互いに影響せず、それぞれのフレームレートで呼び出されます。
- 物理に関連する計算(力の適用、速度の積分)は `OnFixedUpdate` 内に配置し、入力応答やアニメーションパラメータは `OnUpdate` 内に配置すると、タイミングがより安定します。

## よくあるエラー

- **手動で `fsm.FixedUpdate(...)` を再度呼び出す**:`FsmBase.FixedUpdate` は `internal` であり、マネージャーからのみトリガーできます。業務側で重複して駆動すると、1 フレーム内に状態が 2 回進行してしまう原因になります。
- **`Start<...>()` を忘れる**:起動されていない FSM には `CurrentState` が存在せず、`OnFixedUpdate` はトリガーされず、エラーも発生しません。
- **`OnFixedUpdate` 内で `Time.deltaTime` を読み取る**:`elapseSeconds` はすでに `Time.fixedDeltaTime` に固定されているため、`Time.deltaTime` を読み取るとロジックフレームのジッターが混入します。

## 背景(オプション)

フレームワークは Unity の `MonoBehaviour.FixedUpdate` をマネージャーにフックし、マネージャーは物理フレーム時間をすべての FSM にブロードキャストします。各 FSM はこのコールバックを現在の `FsmState<T>` にのみディスパッチすることで、「物理フレーム駆動 + 現在の状態が応答」を実現しています。`OnFixedUpdate` と `OnUpdate` は共存し、前者は `FsmComponent` の `FixedUpdate` によってトリガーされ、後者は `Update` によってトリガーされます。両者はパラメータのセマンティクスが異なりますが、呼び出しのエントリーポイントは対称になっています。
