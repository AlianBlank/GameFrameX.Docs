# Docker / docker-compose로 서버 배포하기

이 페이지의 단계를 따라 하면 몇 분 안에 `docker-compose`로 GameFrameX 서버와 MongoDB 데이터베이스를 실행하고, 컨테이너 볼륨 마운트를 통해 설정, 핫픽스 및 로그의 영속성을 구현할 수 있습니다.

## 사전 조건

- Docker Engine 20.10+ 및 Docker Compose v2가 설치되어 있어야 합니다(명령줄에서 `docker compose version` 실행으로 확인)
- 호스트 머신에서 다음 포트가 개방되어 있어야 합니다: `27017`(MongoDB), `28080`(HTTP), `29090`(APM), `29100`(TCP), `29110`(WebSocket)
- 프로젝트 저장소 루트 디렉터리에 `Dockerfile`과 `docker-compose.yml`이 존재해야 합니다(아래 참조)

## 설정 파일 구조

저장소 루트 디렉터리에는 바로 사용할 수 있는 두 개의 파일이 제공됩니다:

| 파일 | 용도 |
|------|------|
| [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48) | 다단계 빌드: `mcr.microsoft.com/dotnet/sdk:10.0`를 기반으로 프로젝트를 컴파일하고, `aspnet:10.0`를 기반으로 실행되며, 최종 이미지 진입점은 `/app/entrypoint.sh dotnet GameFrameX.Launcher.dll`입니다 |
| [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L1-L148) | `mongodb`와 `gameframex` 두 개의 서비스를 정의하고, `gameframex` bridge 네트워크를 공유하며, 호스트 머신의 `./running/*`를 컨테이너에 마운트하여 영속성을 구현합니다 |

## 작업 단계

### 1. 호스트 머신의 영속성 디렉터리 준비

`docker-compose.yml`은 다음 호스트 머신 디렉터리를 컨테이너에 마운트합니다(디렉터리가 없으면 `docker compose`가 자동으로 생성합니다):

| 호스트 머신 디렉터리 | 컨테이너 마운트 지점 | 용도 |
|------------|------------|------|
| `./running/database` | `/data/db` | MongoDB 데이터 파일 |
| `./running/hotfix` | `/app/hotfix` | 핫업데이트 DLL |
| `./running/json` | `/app/json` | JSON 설정 |
| `./running/logs` | `/app/data/logs` | 애플리케이션 로그 |
| `./running/GameAnalytics` | `/GameAnalytics` | 게임 분석 데이터 |

```bash
mkdir -p running/{database,hotfix,json,logs,GameAnalytics}
```

### 2. 서비스 시작

저장소 루트 디렉터리에서 실행합니다:

```bash
docker compose up -d --build
```

최초 실행 시 MongoDB 이미지를 가져온(pull) 후 [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L5-L23)에 따라 GameFrameX 이미지를 빌드합니다(`GameFrameX.Launcher` + `GameFrameX.Hotfix` 두 프로젝트 publish). 이미지 시작 진입점은 [entrypoint.sh](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L33-L42)에 의해 작성됩니다:

```sh
#!/bin/sh
if [ -z "$(ls -A /app/hotfix 2>/dev/null)" ]; then
    echo "hotfix directory is empty, copying defaults..."
    cp -r /app/hotfix-default/* /app/hotfix/
fi
if [ -z "$(ls -A /app/json 2>/dev/null)" ]; then
    echo "json directory is empty, copying defaults..."
    cp -r /app/json-default/* /app/json/
fi
exec "$@"
```

> 이 스크립트는 호스트 머신의 `./running/hotfix`, `./running/json`이 비어 있을 때 이미지에 내장된 기본값을 복사하므로, 최초 배포 시 수동 설정을 생략할 수 있습니다.

### 3. 서비스 상태 확인

```bash
docker compose ps
docker compose logs -f gameframex
```

데이터베이스 연결 문자열은 compose에 기본값으로 구성되어 있습니다:

```yaml
DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
DataBaseName=gameframex
```

성공적으로 시작된 후, 클라이언트는 `29100`(TCP), `29110`(WebSocket), `28080`(HTTP) 포트를 통해 접속할 수 있습니다.

## 주요 설정 항목 빠른 참조

[docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L14-L139)에 노출된 자주 사용되는 환경 변수:

| 환경 변수 | 기본값 | 설명 |
|----------|--------|------|
| `ServerType` | `Game` | 서버 유형, 다중 프로세스는 쉼표로 구분, 예: `Game,Social,Chat` |
| `ServerId` | `1000` | 서버 ID, 서버 병합 시 일치해야 함 |
| `InnerPort` / `OuterPort` | `29100` | 내부 통신 포트 / 외부 클라이언트 연결 포트 |
| `HttpPort` | `28080` | HTTP 서비스 포트 |
| `WsPort` | `29110` | WebSocket 포트(`IsEnableWebSocket=true`와 함께 사용 필요) |
| `APMPort` | `29090` | APM 성능 모니터링 포트 |
| `DataBaseUrl` | `mongodb://admin:admin@mongodb:27017/?authSource=admin` | MongoDB 연결 문자열 |
| `DataBaseName` | `gameframex` | 데이터베이스 이름 |
| `DiscoveryCenterIp` / `DiscoveryCenterPort` | `127.0.0.1` / `10001` | 서비스 디스커버리 센터 주소 |

주석 처리된 나머지 환경 변수(`IsEnableTcp`, `IsOpenTelemetry`, `LogIsGrafanaLoki` 등)는 모두 기본값을 유지하며, 필요에 따라 주석을 해제하여 사용할 수 있습니다.

## 일반적인 변형

- **단일 프로세스 모드**: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L33-L34)의 33번째 줄 주석을 해제하고, `IsSingleMode`를 `true`로 설정한 후, `ServerType`을 단일 값으로 조정합니다.
- **외부 MongoDB**: `DataBaseUrl`을 외부 주소로 변경하고(예: `mongodb://user:pass@your-mongo-host:27017/?authSource=admin`), compose에서 `mongodb` 서비스 블록을 삭제합니다.
- **HTTPS / WSS**: `HttpsPort`, `WssPort`, `WssCertFilePath` 세 가지 환경 변수를 활성화하고, 인증서를 컨테이너에 마운트합니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `gameframex` 시작 시 `Unable to connect to MongoDB` 오류 발생 | `DataBaseUrl`의 계정 또는 `mongodb` 서비스 이름 불일치 | 계정 `admin/admin`과 서비스 이름 `mongodb`가 compose에 정의된 내용과 일치하는지 확인 |
| `http://localhost:28080`에 접근할 수 없음 | 호스트 머신 방화벽에서 포트가 개방되지 않음 | 28080 포트를 개방하거나 compose의 `ports` 매핑 수정 |
| 핫픽스 파일이 적용되지 않음 | `./running/hotfix`가 마운트되지 않았거나 비어 있음 | entrypoint.sh가 이미지 기본 디렉터리에서 자동으로 한 번 복사하므로, 호스트 머신 디렉터리가 쓰기 가능한지 확인 |
| 빌드 단계에서 `dotnet restore` 실패 | 하위 프로젝트 csproj 경로 변경 | 프로젝트 구조를 수정한 경우 [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L9-L13)의 `COPY` 행도 함께 업데이트 |

## 배경(선택 사항)

[Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48)은 4단계 빌드를 사용합니다: `base`는 런타임 이미지를 준비하고, `build`는 의존성을 복원하고 컴파일하며, `publish`는 Launcher와 Hotfix 두 산출물을 생성하고, `final`은 런타임에 필요한 파일만 복사합니다. 이를 통해 최종 이미지를 간결하게 유지하고 핫픽스 디렉터리의 기본값 폴백을 지원합니다.
