# 구매를 시작하는 방법 (인앱 구매 및 구독)

`PaymentComponent.Buy(PurchaseParams)`를 호출하고 `OnPurchaseSuccess` / `OnPurchaseFailed` 이벤트를 수신하면 일회성 인앱 구매 상품과 구독 상품의 구매를 완료할 수 있으며, 서버 검증 통과 후 `ConsumePurchase`를 호출하여 주문을 소비합니다. 이전의 `BuyInApp` / `BuySubs` 인터페이스는 `[Obsolete]`로 표시되었으므로 `Buy(PurchaseParams)`로 통일하여 사용할 것을 권장합니다.

## 사전 조건

- 씬에 `PaymentComponent`가 부착되어 있어야 합니다(컴포넌트 메뉴 경로 `GameFrameX/Payment`). 이 컴포넌트는 자동으로 `GameFrameXPaymentCroppingHelper`를 함께 포함합니다:

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
public class PaymentComponent : GameFrameworkComponent
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

- 대상 플랫폼에 맞는 해당 채널 구현 패키지가 도입되어 있어야 합니다. `PaymentComponent.Awake()`는 컴파일 매크로에 따라 구현 클래스를 자동으로 선택합니다(Android → `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`, iOS → `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`, 나머지 플랫폼은 `DefaultPaymentManager`로 폴백).

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 작업 단계

1. **사전 정의 상품 ID 설정**(선택 사항이지만 권장). 상품 캐시를 미리 로드하는 데 사용되며, **반드시 `Init()` 이전에 호출해야 합니다**:

```csharp
payment.SetPredefinedProductIds(
    new List<string> { "gem_100", "gem_500" },      // 인앱 상품 ID 목록
    new List<string> { "vip_monthly" });             // 구독 상품 ID 목록
```

출처: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

2. **결제 시스템 초기화**:

```csharp
// isDebug: 샌드박스 모드 여부; isClientVerify: 클라이언트 구매 검증 수행 여부
payment.Init(isDebug: false, isClientVerify: false);
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

| 파라미터 | 타입 | 기본값 (컴포넌트 레이어) | 설명 |
|------|------|------------------|------|
| `isDebug` | `bool` | `false` | 샌드박스 구매 사용 여부 |
| `isClientVerify` | `bool` | `true` (`PaymentComponent`), `false` (`IPaymentManager`) | 클라이언트 구매 검증 여부; 서버 검증을 사용하는 경우 `false`로 설정해야 함 |

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L102-L102), [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

3. **구매 결과 이벤트 구독**(초기화 전후에 한 번에 등록해 두는 것을 권장):

```csharp
payment.OnPurchaseSuccess += (sender, e) =>
{
    Debug.Log($"구매 성공: {e.ProductId}, OrderId={e.OrderId}");
    // 서버 검증 통과 후 주문 소비:
    // payment.ConsumePurchase(e.PurchaseToken);
};
payment.OnPurchaseFailed += (sender, e) =>
    Debug.Log($"구매 실패: {e.ResultCode}, {e.ErrorMessage}");
```

이벤트 시그니처 출처: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L18-L26), 컴포넌트 레이어의 동일 이름 전달은 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L46) 참조

4. **결제 시스템이 준비되었는지 확인한 후 구매 시작**: `payment.IsReady()`를 호출하고, `false`가 반환되면 `Buy`를 계속 호출하지 마세요.

출처: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L45-L49)

5. **`PurchaseParams` 구성 및 `Buy` 호출**. `PurchaseParams`는 추상 기본 클래스이며(생성자가 `protected`) 직접 `new`할 수 없습니다. 각 채널은 하위 클래스를 사용하여 채널 고유의 파라미터(예: 구독에 필요한 `offerToken`)를 전달합니다. 채널 패키지가 하위 클래스를 제공하지 않는 경우 직접 상속할 수 있습니다:

```csharp
public sealed class MyPurchaseParams : PurchaseParams
{
    public MyPurchaseParams(string productId, string orderId, PaymentProductType productType)
        : base(productId, orderId, productType) { }
}

// 구매 시작 (productType는 인앱 구매/구독에 해당하는 열거형 값을 사용하며, 정의는 Runtime/PaymentProductType.cs 참조)
payment.Buy(new MyPurchaseParams("gem_100", "order_20240101_001", productType));
```

출처: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)(기본 클래스 정의), [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112)(권장 진입점)

6. **서버 검증 통과 후 구매 소비**. 일회성 상품은 반드시 소비한 후에야 다시 구매할 수 있습니다:

```csharp
payment.ConsumePurchase(e.PurchaseToken);   // PurchaseToken은 OnPurchaseSuccess의 PaymentEventArgs에서 가져옴
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L140-L152)

`PaymentEventArgs`가 전달하는 필드(서버 검증 회신용):

| 필드 | 타입 | 설명 |
|------|------|------|
| `ProductId` | `string` | 제품 ID |
| `OrderId` | `string` | 주문 ID |
| `PurchaseToken` | `string` | 구매 토큰 (주문 소비용) |
| `ResultCode` | `PaymentResultCode` | 결제 결과 코드 |
| `ErrorMessage` | `string` | 오류 메시지 |
| `PurchaseData` | `string` | 원본 구매 데이터 (JSON 형식) |
| `CustomData` | `string` | 커스텀 데이터 |

출처: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

## 일반적인 변형

- **구매 이력 조회 / 구매 복원**: `payment.QueryPurchases(PaymentProductType.열거형 값)`을 호출하면 결과는 `OnQueryPurchasesResult` 이벤트를 통해 반환되며, 이벤트 파라미터도 마찬가지로 `PaymentEventArgs`입니다.
  출처: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L51-L56), [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L28-L31)
- **이전 인터페이스 (폐기됨)**: `BuyInApp(productId, orderId, offerToken = "", customData = "")`와 `BuySubs(productId, orderId, offerToken = "", customData = "")`는 각각 일회성 상품과 구독 상품에 해당하며, 둘 다 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`로 표시되어 있으므로 새 코드에서는 사용하지 마세요.
  출처: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L72-L93)
- **커스텀 데이터 패스스루**: 이전 인터페이스는 `customData` 파라미터를 통해 전달하며, 이벤트 콜백에서 `PaymentEventArgs.CustomData`로 다시 읽을 수 있습니다. 새 `Buy(PurchaseParams)` 진입점은 각 채널 하위 클래스에서 해당 필드를 확장합니다.

## 자주 발생하는 오류

| 증상 / 로그 | 원인 | 해결 방법 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()`가 null 반환 | 플랫폼 구현 클래스 이름 설정(`PaymentComponent` Inspector의 `m_componentXxxType`)과 채널 패키지 도입 여부 확인 |
| `Log.Warning("Product ID is null or empty.")` | 이전 `Buy*` 인터페이스 호출 시 `productId`가 비어 있음 | 비어 있지 않은 상품 ID 전달 |
| `Log.Warning("Order ID is null or empty.")` | 이전 `Buy*` 인터페이스 호출 시 `orderId`가 비어 있음 | 비어 있지 않은 주문 ID 전달 |
| `Log.Warning("Purchase token is null or empty.")` | `ConsumePurchase`에 빈 token 전달 | `OnPurchaseSuccess` 이벤트의 `e.PurchaseToken` 사용 |
| `SetPredefinedProductIds` 미적용 | `Init()` 이후에 호출됨 | `Init()` 이전으로 이동 |
| 일회성 상품 재구매 실패 (`ItemAlreadyOwned`) | 이전 구매가 소비되지 않음 | 서버 검증 통과 후 `ConsumePurchase` 호출; `ItemNotOwned`, `VerifyFailed`, `NetworkError` 등 결과 코드는 `PaymentResultCode` 열거형 참조 |

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93), [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L117-L152), [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L14-L25)

## 배경

`PaymentComponent`는 퍼사드(facade)로서 파라미터 검증과 이벤트 전달만 수행하며, 실제 로직은 플랫폼별로 결정된 `IPaymentManager` 구현체가 수행합니다 (Google / Apple / WebGL / PC / Default). 구매 결과는 `PaymentEventArgs`를 통해 일관되게 전달되며, `PaymentResultCode`가 성공, 취소, 네트워크 오류, 이미 보유 중 등의 상황을 구분하므로 각 플랫폼에서 동일한 상위 처리 코드를 재사용하기 쉽습니다.
