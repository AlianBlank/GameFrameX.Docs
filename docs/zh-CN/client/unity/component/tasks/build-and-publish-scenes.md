# 如何构建与发布 Launcher / LauncherAuto 场景

本页面说明 GameFrameX.Unity 中 `Assets/Scenes/Launcher.unity` 和 `Assets/Scenes/LauncherAuto.unity` 两个启动场景的构建与发布要点,包括它们在 Build Settings 中的索引位置、所承载的 UI 组件,以及发布到独立平台时的常见处理。

## 前置条件

- 已安装 Unity Editor(与仓库 `ProjectSettings/` 中声明的版本一致)。
- 工程已通过 Unity Hub 打开,目录中存在 `Assets/Scenes/Launcher.unity` 和 `Assets/Scenes/LauncherAuto.unity` 两个场景文件。
- 已安装 GameFrameX 框架运行时,场景中预制的 `UILauncher` 组件脚本可用。

## 操作步骤

### 1. 打开 File → Build Settings

在 Unity 菜单栏选择 `File` → `Build Settings`,在 `Scenes In Build` 列表中确认 `Launcher` 与 `LauncherAuto` 已被添加,且 `Launcher` 通常作为索引 0 的首个启动场景。

### 2. 验证场景文件存在

确认以下两个文件在工程中存在,这是后续构建产物能包含启动场景的前提:

- [Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity)
- [Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity)

### 3. 检查 Launcher 场景中的 UILauncher 组件

`Launcher.unity` 中挂载了 `UILauncher` 脚本组件,负责启动器 UI 与版本检测逻辑。文件中保留了组件引用:

```yaml
propertyPath: m_Name
value: UILauncher
```

参考来源:[Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity#L1158)

打开场景后,在 Hierarchy 顶部 GameObject 上应能看到 `UILauncher` 组件,字段包括版本号、热更新地址、服务器列表等。若字段为空,需先在 Inspector 配置好再发布。

### 4. 处理 LauncherAuto 场景的 Build Settings

`LauncherAuto.unity` 内部以 YAML 形式声明了自身的 `m_BuildSettings` 段(序列化版本 3),Unity 依据此段记录场景参与构建的开关以及光照/Lightmap 设置。直接打开文件可看到:

```yaml
m_BuildSettings:
  serializedVersion: 3
```

参考来源:[Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity#L105-L107)

若需要在 Build Settings 中禁用该场景,可在 `m_BuildSettings` 下调整 `m_Scenes` 引用或直接在 Unity 编辑器中取消勾选。

### 5. 选择目标平台并构建

在 Build Settings 中选择目标平台(Windows、Android、iOS、macOS 等),点击 `Build` 或 `Build And Run`。Unity 会按 `Scenes In Build` 中的顺序,把 `Launcher` 与 `LauncherAuto` 一并打包到 Player 二进制中。

### 6. 验证产物

构建完成后,在输出目录检查:

- 可执行文件能正常启动并进入 `Launcher` 场景;
- `LauncherAuto` 在配置自动跳过 UI 时被加载;
- 启动器界面上的版本号、热更新地址显示正确。

## 常见变体

- **LauncherAuto 自动跳场景**:若希望启动后直接进入业务场景而不是显示 UI 启动器,可在 Player Settings → 其他设置中启用 `LauncherAuto`,该场景通常用于无 UI 的自动化启动流程。
- **按平台裁剪场景**:对 WebGL 等弱平台,可以从 Build Settings 中移除 `LauncherAuto`,只保留 `Launcher`;反之对独立客户端可同时勾选。
- **替换 UILauncher 字段**:不同发布渠道使用不同的热更新地址,在构建前临时切换 `UILauncher` 脚本上的配置即可。

## 常见错误

- **构建后启动黑屏**:通常是因为 `UILauncher` 组件字段未配置(版本号、热更新地址为空),导致启动器初始化失败。
- **Scenes In Build 缺失场景**:手动添加新场景时,把 `Launcher` 或 `LauncherAuto` 从列表中移除,运行时会跳过启动器直接报错。
- **场景 GUID 冲突**:直接复制 .unity 文件时若保留原 `m_SceneGUID`,会导致 Build Settings 引用错乱,务必让 Unity 重新导入并生成新 GUID。

## 背景(可选)

`Launcher` 与 `LauncherAuto` 是 GameFrameX 的双启动场景组合:`Launcher` 提供带 UI 的启动器,负责版本检查、热更新与服务器选择;`LauncherAuto` 为后台或自动化启动场景,跳过 UI 直接加载业务逻辑。`m_BuildSettings` 是 Unity 场景文件中描述参与构建状态的元数据段,被 Editor 与 Player 共同读取。
