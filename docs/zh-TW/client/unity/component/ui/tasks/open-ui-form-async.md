# 如何非同步開啟 UI 介面

呼叫 `OpenUIFormAsync` 可以非同步載入並開啟一個 UI 介面，並透過 `Task<IUIForm>` 在介面真正可互動後繼續後續邏輯；同時配合 `OpenUIFormSuccess` / `OpenUIFormFailure` 事件可以做全域監聽。

## 前置條件

- 已透過 `GameFrameX.UI.Runtime` 的入口取得 `BaseUIManager`(或其子類別 `UIManager`)實例。
- UI 介面資源已設定到框架的 UI 表中，能透過 `uiFormAssetPath` 解析到對應資產。
- 業務類別已實作 `IUIForm`(泛型多載)或已有對應的邏輯類型(非泛型多載)。

## 操作步驟

1. 在呼叫端取得 UI 管理器實例。例如：

```csharp
var uiManager = GameFrameworkEntry.GetModule<IUIComponent>().UIManager;
```

2. 使用泛型多載非同步開啟指定業務類型的介面，直接 `await` 取得 `IUIForm`:

```csharp
IUIForm form = await uiManager.OpenUIFormAsync<MyLoginForm>(
    "Assets/UI/Forms/LoginForm.prefab",
    pauseCoveredUIForm: true,
    userData: new { From = "Splash" },
    isFullScreen: false);
```

泛型簽章:[Open.cs#L100-L103](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L103)

3. 如果業務類型不在呼叫處靜態已知，使用 `Type` 多載：

```csharp
IUIForm form = await uiManager.OpenUIFormAsync(
    "Assets/UI/Forms/LoginForm.prefab",
    typeof(MyLoginForm),
    pauseCoveredUIForm: true,
    userData: null,
    isFullScreen: false);
```

非泛型簽章:[Open.cs#L114-L118](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L114-L118)

4. (可選)訂閱全域事件，統一記錄或上報：

```csharp
uiManager.OpenUIFormSuccess += (sender, e) =>
{
    Debug.Log($"[UI] 打开成功:{e.UIForm.UIFormAssetName},耗时{e.Duration:F2}s");
};

uiManager.OpenUIFormFailure += (sender, e) =>
{
    Debug.LogError($"[UI] 打开失败:{e.UIForm.UIFormAssetName},原因:{e.ErrorMessage}");
};
```

事件訂閱:[Open.cs#L50-L68](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L50-L68)

## 常見變體

- **同步等待並立即取得元件**：

```csharp
var form = await uiManager.OpenUIFormAsync<MyLoginForm>(assetPath, true, null);
var logic = form as MyLoginForm;
logic?.Init();
```

- **只關心開啟、不需要傳回值**：可以直接 `await` 後丟棄，事件回呼裡繼續業務。
- **全螢幕介面**：把 `isFullScreen` 設為 `true`,框架會按全螢幕規則處理覆蓋與暫停。
- **失敗處理**：失敗時 `Task` 不會拋出業務例外，而是透過 `OpenUIFormFailure` 事件傳遞 `ErrorMessage`,或由具體子類別的 `InnerOpenUIFormAsync` 自行拋出例外——呼叫端建議同時準備 `try/catch` 與事件監聽。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| `await OpenUIFormAsync` 始終不回傳 | `uiFormAssetPath` 在 UI 表中未註冊或資源未載入 | 確認資源路徑與 UI 表設定一致 |
| 回傳的 `IUIForm` 強制轉型失敗 | 傳入的 `T` 與介面 Prefab 綁定的邏輯類別不一致 | 使用 Prefab 上掛載的同名 `IUIForm` 實作類別 |
| 開啟後沒看到介面 | `pauseCoveredUIForm: true` 且已有同組介面遮擋，或分組設定錯誤 | 檢查 `UIGroup` 設定，確認介面應放在哪一組 |
| 失敗資訊裡 `ErrorMessage` 為空字串 | 資源未找到，框架僅回傳通用錯誤 | 檢查資源路徑與 `Assets/GameFrameX/...` 下的設定表 |

## 背景(可選)

`OpenUIFormAsync` 內部都委派給子類別實作的抽象方法 `InnerOpenUIFormAsync`,事件物件透過 `ReferencePool.Acquire` 建立以重複使用，詳見事件參數檔案；成功事件攜帶 `UIForm`、`Duration` 與 `UserData`,失敗事件攜帶 `SerialId`、`UIFormAssetName`、`PauseCoveredUIForm`、`ErrorMessage` 與 `UserData`。
