# 目錄/路徑擴充的使用方法

`DirectoryExtensions.CreateAsDirectory` 是 `GameFrameX.Foundation.Extensions` 命名空間下 `string` 的擴充方法，用於安全地建立目錄（必要時遞迴建立父目錄），也支援直接傳入檔案路徑作為引數，自動建立檔案所在的目錄。

## 前置條件

- 參考 `GameFrameX.Foundation.Extensions` 命名空間。
- 執行環境為 .NET，且對目標路徑具有檔案系統寫入權限。

```csharp
using GameFrameX.Foundation.Extensions;
```

## 操作步驟

1. **建立一般目錄**：對目錄路徑直接呼叫 `CreateAsDirectory()`。若目錄已存在，不會拋出例外。若中間層級不存在，則會遞迴建立所有父目錄。

```csharp
using GameFrameX.Foundation.Extensions;

string dir = @"C:\temp\gfx\level1\level2\level3";
dir.CreateAsDirectory();
```

來源：[DirectoryExtensions.cs#L57-L75](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DirectoryExtensions.cs#L57-L75)

2. **預先建立要寫入檔案的目錄**：傳入檔案路徑並設定 `isFile: true`，擴充方法會自動取得檔案所在的目錄並建立，不會將檔案本身建立為目錄。

```csharp
using GameFrameX.Foundation.Extensions;

string filePath = @"C:\temp\gfx\subdir\testfile.txt";
filePath.CreateAsDirectory(isFile: true);
// 此時 C:\temp\gfx\subdir 已存在，而 testfile.txt 尚未建立
```

來源：[DirectoryExtensions.cs#L57-L75](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DirectoryExtensions.cs#L57-L75)

3. **在寫入檔案前與 `File.WriteAllText` 搭配使用**：典型的用法是在寫入日誌或設定之前先呼叫一次擴充方法，確認目錄存在後再進行寫入。

```csharp
using GameFrameX.Foundation.Extensions;
using System.IO;

string logFile = Path.Combine(AppContext.BaseDirectory, "logs", "app.log");
logFile.CreateAsDirectory(isFile: true);
File.AppendAllText(logFile, $"[{DateTime.Now}] started\n");
```

4. **驗證結果**：方法本身不回傳值，因此使用 `Directory.Exists` 或 `File.Exists` 確認建立結果是否符合預期。

```csharp
Assert.True(Directory.Exists(@"C:\temp\gfx\level1\level2\level3"));
Assert.True(Directory.Exists(@"C:\temp\gfx\subdir"));
```

## 常見變化

- **相對路徑**：即使傳入相對路徑，也會依照 `Directory.CreateDirectory` 的語義來建立。例如 `"logs/output".CreateAsDirectory()` 會建立在目前工作目錄之下。
- **Linux/macOS 路徑**：使用 `Path.Combine` 或以斜線串接路徑。例如以 `"/var/log/gfx/sub".CreateAsDirectory(isFile: true)` 的方式呼叫。方法本身不會區分平台。
- **冪等的重複呼叫**：對同一個路徑多次呼叫也不會拋出例外，因此可以在啟動流程或寫入迴圈中放心地重複執行。

## 常見錯誤

| 現象 | 原因 | 處理方式 |
|------|------|------|
| 傳入 `null` 會拋出 `ArgumentNullException` | 方法會在入口處明確驗證 `path` | 呼叫前先判斷是否非 null，或使用 `??` 提供預設值 |
| 期待 `isFile: true` 會建立檔案 | 此模式只會建立目錄，不會建立檔案 | 建立目錄後另行使用 `File.Create` / `File.WriteAllText` 等方法 |
| 傳入僅含檔名的字串（例如 `"plainfile.txt"`）並設定 `isFile: true`，既不會發生錯誤，也不會建立任何東西 | `Path.GetDirectoryName` 回傳空值，方法直接 return | 傳入包含目錄區段的完整路徑 |

## 背景（可選）

`CreateAsDirectory` 是 `Directory.CreateDirectory` 的薄封裝。底層的 `.NET API` 本身已具備遞迴建立以及「目錄已存在則跳過」的語義。擴充方法在此基礎上額外做了兩件事：將「自動把檔案路徑轉換為目錄路徑」的處理內聯到呼叫點，以及在入口處統一拋出 `ArgumentNullException`。完整的契約與單元測試涵蓋範圍請參閱 [DirectoryExtensionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Extensions/DirectoryExtensionsTests.cs#L21-L169)。
