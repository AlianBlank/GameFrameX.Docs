# 소프트 삭제/활성화 필터 인터페이스 사용 방법

엔티티에서 `ISafeDeletedFilter`와 `ISafeEnabledFilter`를 활성화하면, 프레임워크는 기본 엔티티 `EntityBase`에서 자동으로 소프트 삭제 필드(`IsDeleted`, `DeleteTime`, `DeleteId`)와 활성화/비활성화 필드(`IsEnabled`)를 제공하여 "논리적 삭제"와 "활성화 상태"를 통합 관리합니다.

## 사전 조건

- 네임스페이스 `GameFrameX.Foundation.Orm.Entity` 참조(`EntityBase`, `EntityBase<TKey>` 제공).
- 네임스페이스 `GameFrameX.Foundation.Orm.Entity.Filter` 참조(필터 인터페이스 제공).
- 엔티티 클래스가 `EntityBase` 또는 `EntityBase<TKey>`를 상속. 프레임워크 기본 클래스는 이미 기본적으로 `ISafeDeletedFilter`와 `ISafeEnabledFilter`를 구현하므로 수동으로 추가 구현할 필요가 없습니다.

## 작업 단계

1. 비즈니스 엔티티가 `EntityBase`를 상속하면 소프트 삭제와 활성화 필터 필드를 동시에 얻을 수 있습니다.

```csharp
using GameFrameX.Foundation.Orm.Entity;
using GameFrameX.Foundation.Orm.Entity.Filter;

public class SysUser : EntityBase
{
    public string UserName { get; set; } = string.Empty;
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L46)

2. 엔티티 클래스는 이미 다음 소프트 삭제 필드를 자동으로 포함하고 있으며, 바로 사용할 수 있습니다:

| 필드 | 타입 | 기본값 | 의미 |
|------|------|--------|------|
| `IsDeleted` | `bool?` | `false` | 소프트 삭제 마크: `true` 삭제됨, `false` 삭제되지 않음, `null` 설정되지 않음(삭제되지 않은 것으로 처리) |
| `DeleteTime` | `long?` | `null` | 삭제 시간(타임스탬프) |
| `DeleteId` | `long?` | `null` | 삭제자 Id |

```csharp
// 사용자를 삭제됨으로 표시
sysUser.IsDeleted = true;
sysUser.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
sysUser.DeleteId = currentUserId;
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L120-L138)

3. 활성화 필터(`ISafeEnabledFilter`)는 기본 클래스 `EntityBase`에 의해 동시에 구현되며, 엔티티 활성화 상태를 기록하는 데 사용됩니다.

4. 리포지토리 계층에서 조회할 때, 필터 필드 `IsDeleted = false`를 통해 삭제된 데이터를 제외하여 소프트 삭제 조회를 구현합니다:

```csharp
// 예시: 삭제되지 않은 사용자 목록 조회
var users = await dbContext.Set<SysUser>()
    .Where(u => u.IsDeleted == false || u.IsDeleted == null)
    .ToListAsync();
```

5. 삭제 작업 시 물리적 삭제를 사용하지 말고, 대신 `IsDeleted`를 수정합니다:

```csharp
public void SoftDelete(SysUser user, long operatorId)
{
    user.IsDeleted = true;
    user.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
    user.DeleteId = operatorId;
}
```

## 일반적인 변형

- 제네릭 기본 키 기본 클래스 `EntityBase<TKey>`(예: `EntityBase<long>`)를 사용해도, 여전히 소프트 삭제와 활성화 필드를 자동으로 포함합니다.
- 기본 키 타입을 사용자 정의하려면, `EntityBase<TKey>`를 상속하고 제네릭 매개변수를 지정하면 됩니다:

```csharp
public class SysRole : EntityBase<long>
{
    public string RoleName { get; set; } = string.Empty;
}
```

- 선택 필터만 사용하고 감사 필드가 필요하지 않은 경우, `EntitySelectBase`를 상속할 수 있습니다(이는 `EntityBase`를 기반으로 `ISelectFilter`를 추가로 구현하지만, 여전히 `IsDeleted` 등의 소프트 삭제 필드를 포함합니다).

Source: [EntitySelectBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntitySelectBase.cs#L45-L45)

## 일반적인 오류

- 물리적 삭제 오용: `EntityBase`를 상속한 엔티티에 대해 ORM의 `Remove`/`Delete`를 호출하면, 소프트 삭제 마크를 우회하여 데이터가 실제로 사라지게 됩니다. 일관되게 `IsDeleted = true`로 재작성하도록 변경하세요.
- 조회 시 `IsDeleted` 필터 누락: `Where(u => u.IsDeleted == false)`를 추가하지 않으면, 삭제된 레코드도 함께 조회됩니다. 리포지토리 계층에서 필터 조건을 강제로 추가하세요.
- `IsDeleted`가 `bool`이 아닌 `bool?`이라는 점을 오해: 프레임워크는 nullable boolean을 사용하며, 기본값은 `false`입니다. 새로 추가된 엔티티가 명시적으로 값을 할당하지 않으면 "삭제되지 않음"으로 처리됩니다. 수동으로 `null`을 설정해도 마찬가지로 삭제되지 않은 것으로 간주됩니다.
