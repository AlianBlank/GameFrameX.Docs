# UI 패키지 로드 및 언로드

FairyGUI Unity 런타임에서 UI 패키지를 로드한다는 것은 `UIPackage.AddPackage` 계열의 정적 메서드를 호출하여 게시된 `_fui` 설명 파일과 해당 리소스를 전역 패키지 목록에 등록하는 것이며, 그 이후에야 `UIPackage.CreateObject`로 컴포넌트를 생성할 수 있습니다. 언로드는 `UIPackage.RemovePackage` / `RemoveAllPackages`를 호출하여 패키지 내 모든 리소스를 해제합니다. 모든 API는 [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L311)에 집중되어 있습니다.

## 사전 조건

- FairyGUI 에디터로 UI 패키지를 게시하여 `包名_fui.bytes` 설명 파일과 리소스 파일을 이미 확보한 상태입니다.
- 설명 파일을 Unity `Resources` 디렉터리 아래에 배치합니다(또는 AssetBundle / 커스텀 로더를 통해 제공).

## 작업 단계

1. **게시 산출물을 프로젝트에 넣기**: `包名_fui.bytes`(및 이미지, 사운드 등 리소스)를 `Resources` 디렉터리 아래의 하위 디렉터리, 예를 들어 `Assets/Resources/UI/Basics`에 넣습니다. 설명 파일명은 반드시 `_fui`로 끝나야 하며, 런타임은 `assetPath + "_fui"`와 `".bytes"`를 자동으로 이어붙여 로드합니다([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L324-L325) 참조).

2. **패키지 로드**: Resources 상대 경로로 `AddPackage(string descFilePath)`를 호출합니다. 경로에는 `_fui` 접미사를 붙이지 않습니다. 예:

```csharp
// 경로는 Resources 디렉터리 기준 상대 경로이며 _fui 접미사를 붙이지 않음
UIPackage.AddPackage("UI/Basics");
```

   이 오버로드의 전체 구현: 경로가 `Assets/`로 시작하면 Editor에서만 사용할 수 있습니다(`_loadFromAssetsPath` 경유). 그 외에는 Resources 상대 경로로 로드합니다. [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L298-L311) 참조.

3. **(선택) 먼저 중복 확인 후 로드**: `AddPackage`를 반복 호출하면 여러 패키지 인스턴스가 등록되므로, 먼저 이미 로드되었는지 확인합니다. 저장소 내 `UIPainter`가 정확히 이렇게 하고 있습니다:

```csharp
if (!string.IsNullOrEmpty(packagePath) && UIPackage.GetByName(packageName) == null)
    UIPackage.AddPackage(packagePath);
```

출처: [UIPainter.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPainter.cs#L64-L66)

4. **컴포넌트를 생성하여 로드 성공 확인**:

```csharp
public static GObject CreateObject(string pkgName, string resName)
{
    UIPackage pkg = GetByName(pkgName);
    if (pkg != null)
        return pkg.CreateObject(resName);
    else
        return null;
}
```

출처: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L512-L519)

   `UIPackage.CreateObject("Basics", "MainMenu")`와 같은 형태로 호출합니다. `CreateObjectFromURL("ui://Basics/MainMenu")`를 사용해도 됩니다([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L542-L547) 참조).

5. **패키지 언로드**: UI가 닫히고 리소스가 더 이상 필요 없을 때, 패키지명 또는 패키지 id로 언로드합니다:

```csharp
public static void RemovePackage(string packageIdOrName)
{
    UIPackage pkg = null;
    if (!_packageInstById.TryGetValue(packageIdOrName, out pkg))
    {
        if (!_packageInstByName.TryGetValue(packageIdOrName, out pkg))
            throw new Exception("FairyGUI: '" + packageIdOrName + "' is not a valid package id or name.");
    }

    pkg.Dispose();
    _packageInstById.Remove(pkg.id);
    ...
}
```

출처: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L458-L475)

   전달하는 값은 패키지 id **또는** 패키지명이며, 일치하는 것이 없으면 `FairyGUI: '...' is not a valid package id or name.` 예외가 바로 발생합니다. 모든 패키지를 한 번에 비우려면 `RemoveAllPackages()`를 사용합니다([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L480-L495) 참조).

## AddPackage 오버로드 빠른 참조

| 오버로드 | 시그니처 | 적용 시나리오 |
|------|------|----------|
| AssetBundle 단일 번들 | `AddPackage(AssetBundle bundle)` | 설명과 리소스가 동일한 bundle에 있음 | 
| AssetBundle 이중 번들 | `AddPackage(AssetBundle desc, AssetBundle res)` | 설명과 리소스를 분리하여 패키징 |
| AssetBundle + 메인 리소스명 | `AddPackage(AssetBundle desc, AssetBundle res, string mainAssetName)` | 설명 파일 리소스명 지정, 예: `Basics_fui` |
| Resources 경로 | `AddPackage(string descFilePath)` | 설명 파일이 Resources 아래에 있음 |
| 커스텀 로드 함수 | `AddPackage(string assetPath, LoadResource loadFunc)` | 자체 리소스 관리 시스템 연동; 동일 경로에 반복 호출하면 이미 로드된 패키지를 바로 반환 |
| 바이트 배열 | `AddPackage(byte[] descData, string assetNamePrefix, LoadResource loadFunc)` | 설명 데이터가 이미 메모리에 있음 |
| 비동기 | `AddPackageAsync(string assetPath, Action<UIPackage> callback)` | 비동기 로드, 먼저 `SetAsyncLoadResource` 필요 |

위 시그니처는 모두 [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L381)에서 가져온 것입니다.

관련 조회 인터페이스: `GetByName(string name)`, `GetById(string id)`, `GetPackages()`([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L190-L211) 참조).

## 일반적인 변형

**AssetBundle에서 로드**(설명과 리소스가 동일 번들):

```csharp
public static UIPackage AddPackage(AssetBundle bundle)
{
    return AddPackage(bundle, bundle, null);
}
```

출처: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L221)

bundle 내에서 `_fui` 설명 파일을 찾지 못하면 `FairyGUI: no package found in this bundle.` 예외를 던집니다. `desc`와 `res`가 서로 다른 두 bundle이고 `UIPackage.unloadBundleByFGUI`가 `true`(기본값)이면, 설명 파일 로드가 끝나는 즉시 `desc.Unload(true)`가 호출됩니다. [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L269-L273) 참조.

**커스텀 로드 함수**(프로젝트 리소스 프레임워크 연동), Editor 도구에서의 실제 사용법:

```csharp
UIPackage.AddPackage(assetPath,
    (string name, string extension, System.Type type, out DestroyMethod destroyMethod) =>
    {
        // 로드한 asset을 반환하고, out destroyMethod를 통해 언로드 방식을 지정
        ...
    });
```

출처: [EditorToolSet.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/EditorToolSet.cs#L118-L119)

`LoadResource` 델리게이트 시그니처는 [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L319-L325) 참조: `assetPath + "_fui"`, `".bytes"`, `typeof(TextAsset)`로 설명 파일을 요청하며, 구현 측이 `out DestroyMethod`를 통해 리소스 파괴 방식을 결정합니다.

## 자주 발생하는 오류

| 현상 | 원인 | 해결 |
|------|------|------|
| `FairyGUI: Cannot load ui package in '...'` 예외 발생 | `loadFunc`가 null을 반환함. 설명 파일 경로 오류 또는 패키지에 미포함 | 경로에 `_fui` 접미사가 없는지 확인; `Resources` 아래에 `路径_fui.bytes` 파일이 존재하는지 확인; 런타임(`Application.isPlaying`)에서는 예외가 바로 발생하고 Editor 비재생 모드에서는 경고만 출력([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L326-L332) 참조) |
| `FairyGUI: no package found in this bundle.` 예외 발생 | bundle 내에 `_fui`로 명명된 TextAsset이 없음 | 다시 게시하여 bundle에 `包名_fui` 설명 파일이 포함되어 있는지 확인하거나, `mainAssetName`을 명시적으로 전달([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L252-L270) 참조) |
| `FairyGUI: '...' is not a valid package id or name.` 예외 발생 | `RemovePackage`에 전달한 값이 패키지 id도 패키지명도 아니거나, 패키지가 이미 언로드됨 | `UIPackage.GetByName`으로 패키지가 존재하는지 먼저 확인한 뒤 언로드([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L460-L465) 참조) |
| Editor 실기기에서 `Assets/` 경로 로드 실패 및 경고 발생 | `AddPackage(string)`은 `Assets/`로 시작하는 경로에 대해 `UNITY_EDITOR`에서만 동작 | 실기기에서는 Resources 상대 경로, AssetBundle 또는 커스텀 로드 함수로 전환([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L300-L308) 참조) |
| 언로드 후 UI가 분홍색으로 변함/텍스처 소실 | 패키지가 이미 `Dispose`되었지만 여전히 컴포넌트가 패키지 내 리소스를 사용 중 | 먼저 해당 패키지를 사용하는 모든 UI를 파괴한 후 `RemovePackage` 호출 |

## 검증

- 로드 후 `UIPackage.GetByName("Basics")`가 null이 아닌 값을 반환하고, `UIPackage.CreateObject("Basics", "组件名")`로 null이 아닌 `GObject`를 얻을 수 있습니다.
- 언로드 후 `UIPackage.GetByName("Basics")`가 null을 반환하고, `GetPackages()` 목록에 더 이상 해당 패키지가 포함되지 않습니다.

## 배경

`AddPackage`의 모든 오버로드는 최종적으로 `包名_fui` 설명 파일을 `byte[]`로 읽어들여 `ByteBuffer`를 구성하고, `LoadPackage`가 리소스 목록을 파싱한 뒤, 패키지 id와 패키지명(및 assetPath)을 키로 하여 `_packageInstById` / `_packageInstByName` / `_packageList` 세 개의 정적 컬렉션에 등록합니다. `RemovePackage`는 먼저 `Dispose`한 다음 이 세 컬렉션에서 제거합니다([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L334-L346) 및 [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L466-L475) 참조). 이것이 "경로에 `_fui`를 붙이지 않기, 중복 로드 시 직접 중복 확인 필요"라는 규약 뒤에 있는 메커니즘입니다.
