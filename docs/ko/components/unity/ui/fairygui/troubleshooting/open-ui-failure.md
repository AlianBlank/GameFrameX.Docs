# UI 화면 열기 실패 시 대처 방법

`UIManager`를 호출하여 FairyGUI 화면을 열었는데 화면이 나타나지 않거나, 예외가 발생하거나 / `OpenUIFormFailure` 이벤트가 트리거되는 경우. 실패 지점은 거의 다음 세 곳에 있습니다: 리소스 경로 또는 패키지명 조합이 잘못된 경우, UI 패키지가 올바르게 로드되지 않은 경우, 화면 스크립트 타입과 컴포넌트가 일치하지 않는 경우. 먼저 아래 진단 표로 문제 위치를 파악한 다음, 해당하는 복구 단계에 따라 처리하세요.

## 복구 단계

### 복구 단계 1: 리소스 경로 및 패키지명 규칙 확인

화면을 열 때, 프레임워크는 다음 규칙에 따라 `uiFormAssetPath`와 화면 타입명에서 모든 주소를 추론합니다(`UIManager.InnerLoadUIFormAsync` 참조):

- `uiFormAssetName` = 화면 타입명 `uiFormType.Name`(**반드시 FairyGUI 에디터에서 내보내기한 컴포넌트명과 일치해야 함**);
- `assetPath` = `uiFormAssetPath/uiFormAssetName`;
- `packageName` = `uiFormAssetPath`에서 마지막 `/` 이후의 부분; 경로에 `/`가 없으면 전체 경로가 패키지명;
- Bundles로 로드할 때, 실제로 로드되는 리소스는 `uiFormAssetPath/packageName_fui`입니다.

```csharp
var uiFormAssetName = uiFormType.Name;
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);

var lastIndexOfStart = uiFormAssetPath.LastIndexOf("/", StringComparison.OrdinalIgnoreCase);
// 경로에 /가 없으면 전체 경로를 패키지명으로 사용(Resources 디렉터리 아래의 간단한 경로에 적용)
var packageName = lastIndexOfStart >= 0 ? uiFormAssetPath.Substring(lastIndexOfStart + 1) : uiFormAssetPath;
// UI 패키지가 이미 로드되었는지 확인
var hasUIPackage = FairyGuiPackage.Has(packageName);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L127-L136)

확인 포인트:

1. `uiFormAssetPath`의 마지막 디렉터리명이 FairyGUI에서 게시한 패키지명과 일치하는지 확인합니다(예: 경로 `Assets/Bundles/UI/MainUI`에서 패키지명 `MainUI`가 도출됨).
2. 화면 클래스명(`uiFormType.Name`)이 컴포넌트명과 완전히 일치하는지 확인합니다. 대소문자를 구분합니다.
3. Bundles를 사용할 때 `<uiFormAssetPath>/<packageName>_fui` 리소스가 존재하는지 확인합니다; 패키지명과 화면명이 다르면, 프레임워크는 `uiFormAssetPath/packageName`으로 경로를 다시 조합한 뒤 `_fui`를 추가합니다:

```csharp
// 일치하지 않으면 경로를 다시 조합
string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
await FairyGuiPackage.AddPackageAsync(newPackagePath);
...
newAssetPackagePath += "_fui";
// 패키지에서 로드
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L163-L178)

4. `assetPath`에 `Utility.Asset.Path.BundlesDirectoryName`(기본 Bundles 디렉터리명)이 포함되어 있지 않으면, 프레임워크는 **Resources 모드**로 패키지를 동기 로드하므로, 해당 경로가 Resources 아래에 실제로 존재하는지 확인합니다:

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Resources에서 로드
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

### 복구 단계 2: 실패 이벤트 등록으로 실제 오류 확인

로드 실패는 최종적으로 `LoadAssetFailureCallback`에 도달합니다. 오류 메시지 형식은 다음과 같이 고정되어 있습니다:

```text
Load UI form failure, asset name '{0}', error message '{1}'.
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L358-L368)

핵심 동작은 두 가지 경우로 나뉩니다:

- `OpenUIFormFailureEventHandler`를 구독한 경우: 오류가 `OpenUIFormFailureEventArgs`로 래핑되어 이벤트가 트리거되고, 메서드가 null을 반환하며 예외를 던지지 않습니다;
- 구독하지 않은 경우: `throw new GameFrameworkException(appendErrorMessage)`가 직접 실행되어, 예외가 호출한 곳으로 전파됩니다.

문제 해결 시 먼저 실패 이벤트를 구독하고 `errorMessage`를 로그에 출력하는 것을 권장합니다. 그 안의 YooAsset/리소스 오류 정보가 근본 원인입니다.

### 복구 단계 3: 화면 타입과 컴포넌트명 확인

`InternalOpenUIForm`에서 `IUIFormHelper.CreateUIForm`이 null을 반환하면 다음 예외가 발생합니다:

```csharp
IUIForm uiForm = m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData);
if (uiForm == null)
{
    throw new GameFrameworkException("Can not create UI form in UI form helper.");
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L211-L217)

이 예외 역시 `OpenUIFormFailure` 이벤트를 트리거한 후(`exception.ToString()` 포함) 다시 던져집니다. 다음을 확인하세요:

1. 전달된 `uiFormType`이 등록된/생성 가능한 `FUI` 하위 클래스인지;
2. 패키지 내에 같은 이름으로 내보내기된 컴포넌트가 존재하는지;
3. `OnOpen`/`BindEvent`/`LoadData` 단계에서 예외가 발생하면 동일하게 실패 이벤트 + 재던지기(rethrow) 경로를 따릅니다([Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L264-L273) 참조).

### 복구 단계 4: 싱글톤 열기 동작 이해

싱글톤 모드로 열린 화면은, 이미 열린 인스턴스를 찾으면 다시 로드하지 않고 그대로 재사용하고 포커스를 맞춥니다:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L84)

"연 뒤" 동작이 비정상이면, 먼저 `GetUIForm(uiFormAssetName)`으로 오래된 인스턴스인지 확인하세요; 로드 중인 같은 이름의 화면은 동일한 로드 Task를 재사용하며 중복 로드하지 않습니다. 실행 중 UI 요소 경로를 찾을 수 없을 때는 `FairyGUIPathFinderHelper`의 오류도 참조하세요: `error uiPath : can not found ui by this path :{path}` 및 `Invalid UI path: child not found`([Runtime/FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L141-L191)).

## 검증

1. 열기 API를 다시 호출하여 반환된 `IUIForm`이 null이 아니고 `SerialId > 0`인지 확인합니다;
2. `OpenUIFormSuccess` 이벤트가 트리거되는지 확인하고([Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L255-L260)), 동시에 `Load UI form failure` 로그가 더 이상 나타나지 않는지 확인합니다;
3. 실패 이벤트 콜백이 더 이상 트리거되지 않고, 콘솔에 `GameFrameworkException`이 없는지 확인합니다.
