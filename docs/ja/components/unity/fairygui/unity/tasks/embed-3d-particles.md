# UI にモデル、パーティクル、スケルタルアニメーションを埋め込む

FairyGUI の `GoWrapper` を使って任意の `GameObject`(3D モデル、パーティクルシステム、スケルタルアニメーションなど)を表示オブジェクトとしてラップし、UI 内の空のグラフィックコンポーネントに取り付けることで、FairyGUI の階層、オクルージョン、ソートに参加させることができます。追加のカメラや RenderTexture は不要です。

## 前提条件

- プロジェクトに本 FairyGUI パッケージ(`Runtime/Core/GoWrapper.cs` が含まれるアセンブリ)が導入済みであること。
- UI 画面にプレースホルダーとして**空のグラフィック(Graph)**コンポーネントを用意します。コード内で先に透明な矩形を描いてプレースホルダーとすることもできます。FairyGUI 自身も `GWindow` 内でまさにこの方法を使用しています:

```csharp
GGraph graph = _dragArea as GGraph;
if (graph != null && graph.shape.isEmpty)
    graph.DrawRect(_dragArea.width, _dragArea.height, 0, Color.clear, Color.clear);
```

出典： [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L159-L161)

## 操作手順

1. 表示したい `GameObject`(モデル、パーティクルのプレハブ、スケルタルアニメーションのホストなど)をインスタンス化します。
2. `GoWrapper` を構築してラップを完了させ、その結果を空のグラフィックコンポーネントに設定します:

```csharp
GameObject model = Instantiate(modelPrefab);
GoWrapper wrapper = new GoWrapper(model);   // 構築時にラップが完了する
holder.SetNativeObject(wrapper);            // holder は UI 内の空のグラフィック GGraph
```

`GoWrapper(GameObject go)` の実際のシグネチャは以下の通りで、構築時はデフォルトでマテリアルを**複製しません**:

```csharp
public GoWrapper(GameObject go) : this()
{
    SetWrapTarget(go, false);
}
```

出典： [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L47-L54)

3. マテリアルが他のオブジェクトと共有されている場合、またはマテリアルに UI 固有の処理を行う必要がある場合は、代わりにマテリアルを複製するモードでラップ対象を設定します:

```csharp
/// ラップ対象を設定します。元のラップ対象が存在する場合、新しいラップ対象を設定すると、元のラップ対象の参照は削除されるだけで、破棄はされないので注意してください。
/// オブジェクトに含まれるすべてのマテリアルは複製されません。マテリアルが既に共用されている場合、他のオブジェクトに影響を与える可能性があります。自動的に複製したい場合は、代わりにSetWrapTarget(target, true)を使用して設定してください。
public GameObject wrapTarget
{
    get { return _wrapTarget; }
    set { SetWrapTarget(value, false); }
}

public void SetWrapTarget(GameObject target, bool cloneMaterial)
```

出典： [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L56-L77)

4. ラップの内部実装では、対象オブジェクトを自身の配下に取り付けてレンダラーをキャッシュします。Canvas 以外のオブジェクトはサイズが 0 に設定され、表示はレンダラー自身が決定します:

```csharp
if (_wrapTarget != null)
{
    _wrapTarget.transform.SetParent(this.cachedTransform, false);
    _canvas = _wrapTarget.GetComponent<Canvas>();
    if (_canvas != null)
    {
        _canvas.renderMode = RenderMode.WorldSpace;
        _canvas.worldCamera = StageCamera.main;
        _canvas.overrideSorting = true;

        RectTransform rt = _canvas.GetComponent<RectTransform>();
        rt.pivot = new Vector2(0, 1);
        rt.position = new Vector3(0, 0, 0);
        this.SetSize(rt.rect.width, rt.rect.height);
    }
    else
    {
        CacheRenderers();
        this.SetSize(0, 0);
    }

    SetGoLayers(this.layer);
}
```

出典： [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L92-L114)

5. 毎フレーム、ラップ対象に追従した追加処理が必要な場合は `onUpdate` をサブスクライブします。マテリアルの置換ロジックを完全に引き継ぎたい場合は、`customCloneMaterials` / `customRecoverMaterials` デリゲートを提供します:

```csharp
public event Action<UpdateContext> onUpdate;
public Action<Dictionary<Material, Material>> customCloneMaterials;
public Action customRecoverMaterials;
```

出典： [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L16-L18)

## よくあるバリエーション

- **UGUI Canvas を埋め込む**:`SetWrapTarget` は対象に `Canvas` がアタッチされていることを検出すると、自動的に `RenderMode.WorldSpace` に切り替え、`StageCamera.main` を指定し、RectTransform のサイズで `SetSize` を行うため、UGUI パネルをそのまま FairyGUI に埋め込むことができます。
- **クリック検出が必要な 3D オブジェクト**:リポジトリでは複数のヒットテスト実装が提供されており、必要に応じて `GoWrapper`(`DisplayObject` を継承)のヒット領域と組み合わせて使用します:[ColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/ColliderHitTest.cs)、[MeshColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/MeshColliderHitTest.cs)、[PixelHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/PixelHitTest.cs)。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 共有マテリアルを使用する他のオブジェクトの色が意図せず変わる | ラップ時に `sharedMaterial` を直接使用している | 代わりに `SetWrapTarget(target, true)` でマテリアルを複製する |
| ラップ対象を変更した後も古いモデルが表示され続ける | `SetWrapTarget` は参照を削除するだけで、古いオブジェクトを**破棄しない** | 対象を変更する前に自分で古いオブジェクトを `Destroy` する |
| ブラーなど Layer に基づいて効く効果がラップ対象に対して正しく機能しない | ラップ対象とその子オブジェクトは UI と同じ Layer にする必要がある | `GoWrapper` は `_SetLayerDirect` 内で再帰的に Layer を設定済みなので、外部コードによって戻されていないか確認する |
| スケルタルアニメーション/パーティクルのレンダリングが更新されない、または描画漏れが発生する | 内部のレンダラーキャッシュが更新されていない | ラップ対象を再設定するか、`CacheRenderers()` を呼び出して再キャッシュする(上記の 92-114 行目の呼び出し箇所を参照)|

`_SetLayerDirect` の再帰的な Layer 処理(ソースコードのコメントによると、これは `GoWrapper` 内でブラー効果を使用するためのものです):

```csharp
override internal void _SetLayerDirect(int value)
{
    gameObject.layer = value;
    if (_wrapTarget != null)//このifはGoWrapper内でブラー効果を使用するためのもの
    {
        _wrapTarget.layer = value;
        foreach (Transform tf in _wrapTarget.GetComponentsInChildren<Transform>(true))
        {
            tf.gameObject.layer = value;
        }
    }
}
```

出典： [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L117-L128)

## 背景

`GoWrapper` は `DisplayObject` を継承しており(宣言は [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L8-L12) を参照)、`GoWrapper` という名前のホスト `GameObject` を作成し、ラップ対象を自身の `cachedTransform` の下に `SetParent` し、対象上のすべての `Renderer` をキャッシュします(構造体 `RendererInfo` は `renderer`、`materials`、`sortingOrder` を含みます。詳細は [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L27-L32) を参照)。これにより、通常の 3D コンテンツが FairyGUI の表示リストおよびバッチ処理/ソート体系に参加できるようになります。古い `supportStencil` フラグは既に `[Obsolete]` としてマークされており、ステンシルバッファの処理は現在自動的に行われるため、手動で設定する必要はありません。
