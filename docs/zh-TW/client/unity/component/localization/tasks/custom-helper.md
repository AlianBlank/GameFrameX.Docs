# 如何自訂本地化 Helper（重寫系統語言偵測）

自訂本地化 Helper 只需要兩步：撰寫一個繼承 `LocalizationHelperBase` 的類別並重寫 `SystemLanguage` 屬性，然後在 `LocalizationComponent` 面板上把 Helper 換成你的類型。預設實作使用 `CultureInfo.CurrentCulture` 偵測系統語言，重寫該屬性即可換成任意偵測策略（讀取存檔、讀取帳號設定、固定語言等）。

## 前置條件

- 已安裝 `com.gameframex.unity.localization` 套件。
- 場景中已存在掛有 `LocalizationComponent` 的物件。

## 操作步驟

### 1. 撰寫自訂 Helper 類別

先看基底類別定義——Helper 是一個 `MonoBehaviour`，唯一需要實作的是唯讀屬性 `SystemLanguage`：

```csharp
namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// 本地化輔助器基底類別。
    /// </summary>
    [Preserve]
    public abstract class LocalizationHelperBase : MonoBehaviour, ILocalizationHelper
    {
        /// <summary>
        /// 取得系統語言。
        /// </summary>
        [Preserve]
        public abstract string SystemLanguage { get; }
    }
}
```

來源： [LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L37-L48)

預設實作 `DefaultLocalizationHelper` 的寫法如下，它取得目前區域名稱並把 `-` 換成 `_`（例如 `zh-CN` → `zh_CN`）：

```csharp
using System.Globalization;
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// 預設本地化輔助器。
    /// </summary>
    [Preserve]
    public class DefaultLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public DefaultLocalizationHelper()
        {
        }

        /// <summary>
        /// 取得系統語言。
        /// </summary>
        [Preserve]
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
    }
}
```

來源： [DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L32-L57)

照著預設實作的骨架，撰寫一個自己的類別。下面範例把系統語言固定為 `zh_CN`（結構對照 `DefaultLocalizationHelper` 改寫，傳回值可換成你自己的偵測邏輯，注意保持 `xx_XX` 底線格式）：

```csharp
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    [Preserve]
    public class MyLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public override string SystemLanguage
        {
            get { return "zh_CN"; } // 在這裡實作自己的語言偵測
        }
    }
}
```

### 2. 在 LocalizationComponent 上設定自訂 Helper

`LocalizationComponent` 公開了兩個序列化欄位用於選擇 Helper：

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";

[SerializeField] private LocalizationHelperBase m_CustomLocalizationHelper = null;
```

來源： [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

- 在 Inspector 的 **Localization Helper** 下拉選單中選擇你的自訂類型（面板內部透過 `HelperInfo<LocalizationHelperBase>` 列出可選 Helper，見 [LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L46)）。
- `m_LocalizationHelperTypeName` 需要是**完整類型名稱**（含命名空間），參考預設值 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` 的寫法。

### 3. 執行階段確認 Helper 生效

元件在初始化時透過 `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)` 建立 Helper 實例（見 [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L250)）。執行後查詢 `LocalizationComponent` 的系統語言/語言相關屬性，傳回值應來自你的重寫邏輯。

## 常見變體

- **按 Unity 系統語言對應**：在 `SystemLanguage` 的 getter 中根據 Unity 的 `Application.systemLanguage` 對應到專案使用的語言碼（如 `zh_CN`、`en_US`）。
- **從存檔或帳號設定讀取**：getter 中讀取專案自身的存檔/雲端設定，傳回使用者上次選擇的語言，實作「首次跟隨系統、之後跟隨使用者設定」。
- **回退預設值**：`LocalizationComponent` 上的 `m_DefaultLanguage` 預設為 `zh_CN`，載入本地化失敗時會使用預設語言作為備援（見 [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L68)）。可將其與自訂 Helper 配合，確保未支援的語言也能顯示內容。

## 常見錯誤

| 現象 | 原因 | 修正 |
|------|------|------|
| Inspector 裡找不到自己的 Helper 類型 | 類別未繼承 `LocalizationHelperBase`，或不在編譯範圍內 | 確認類別宣告為 `public class Xxx : LocalizationHelperBase`，且已儲存並編譯通過 |
| 執行階段 Helper 為 null | `m_LocalizationHelperTypeName` 填錯（少命名空間、拼字錯誤） | 類型名稱必須為完整名稱（含命名空間），參考預設值 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` |
| 傳回語言不生效/對應不到字典 | 傳回的語言碼格式不對 | 保持 `xx_XX` 底線格式（預設實作會把 `-` 替換為 `_`），不要傳回 `zh-CN`、`Chinese` 等格式 |
| 自訂 Helper 類別被裁剪（IL2CPP/連結器裁剪） | 未標註保留特性 | 類別和屬性加上 `[Preserve]`（參考預設實作中的用法） |
| 語言切換後介面未重新整理 | 直接改 Helper 傳回值不觸發事件 | 透過 `LocalizationComponent.Language` 的 setter 設定語言，才會觸發語言變更事件（Before/Change/After） |

## 背景

`LocalizationComponent` 在初始化時透過 `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)` 按「類型名稱 + 可選自訂實例」兩種方式建立 Helper，因此自訂 Helper 既能透過 Inspector 面板選擇（寫入類型名稱字串），也能直接拖曳參考。語言取得走 `SystemLanguage` 屬性，語言設定與持久化則由元件的 `Language` / `DefaultLanguage` 屬性負責（配合 `SettingComponent` 儲存），並在切換時依序觸發 `LocalizationLanguageChangeBeforeEventArgs`、`LocalizationLanguageChangeEventArgs`、`LocalizationLanguageChangeAfterEventArgs` 三個事件。

關於本地化元件的整體用法，見本套件《LocalizationComponent》相關文件。
