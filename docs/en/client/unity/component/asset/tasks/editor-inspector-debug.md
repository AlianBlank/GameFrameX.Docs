# How to View and Debug the Asset Component in the Inspector

When a GameObject with `AssetComponent` attached is selected in the scene, the Unity Inspector displays debuggable fields such as the asset play mode and the currently configured list of resource packages; changes are disabled in Play Mode, making it easy to read out the currently effective settings directly.

## Prerequisites

- The GameFrameX asset component has been attached to a GameObject in the entry scene (usually created automatically along with the framework bootstrap script).
- The same GameObject also has a `GameFrameXAssetCroppingHelper` component (enforced via `[RequireComponent]`).
- Resource packages (default `DefaultPackage`) have been registered to the `m_assetResourcePackages` list through the editor tool or code.

## Steps

1. In the Hierarchy window, select the GameObject with `AssetComponent` attached.
2. At the top of the Inspector, you can see the "Resource Play Mode" dropdown and the "Package List" field:

   - "Resource Play Mode" corresponds to the serialized field `m_GamePlayMode`, with selectable values matching the `EPlayMode` enum (`EditorSimulateMode` / `HostPlayMode` / `WebPlayMode`, etc.).
   - "Package List" corresponds to `m_assetResourcePackages`, listing all currently registered `AssetResourcePackageInfo` items.

   ```csharp
   // Source: actual field definition in AssetComponent.cs
   [Tooltip("当目标平台为Web平台时，将会强制设置为" + nameof(EPlayMode.WebPlayMode))]
   [SerializeField]
   private EPlayMode m_GamePlayMode;

   #if UNITY_EDITOR
       [SerializeField] private List<AssetResourcePackageInfo> m_assetResourcePackages = new List<AssetResourcePackageInfo>();
   #endif
   ```

   Source: [Runtime/Asset/AssetComponent.cs#L23-L48](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L23-L48)

3. The custom Inspector is implemented by `AssetComponentInspector`, which inherits from `ComponentTypeComponentInspector` and automatically renders the component type dropdown corresponding to the `IAssetManager` interface:

   ```csharp
   // Source: Editor/Inspector/AssetComponentInspector.cs
   [CustomEditor(typeof(AssetComponent))]
   internal sealed class AssetComponentInspector : ComponentTypeComponentInspector
   {
       private GUIContent m_GamePlayModeGUIContent = new GUIContent("资源运行模式");
       private GUIContent m_AssetResourcePackagesGUIContent = new GUIContent("包列表");
       // ...
       protected override void RefreshTypeNames()
       {
           RefreshComponentTypeNames(typeof(IAssetManager));
       }
   }
   ```

   Source: [Editor/Inspector/AssetComponentInspector.cs#L39-L78](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Editor/Inspector/AssetComponentInspector.cs#L39-L78)

4. To switch the play mode, **exit Play Mode first**, then select the target enum value in "Resource Play Mode". This field is disabled in the Inspector during runtime via `EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode)` to prevent accidental changes at runtime.
5. After modifying the Inspector fields, Unity automatically calls `serializedObject.ApplyModifiedProperties()` to write back the changes; no manual save is required.
6. When debugging asset loading results, you can verify during runtime via console logs whether `IAssetManager` has obtained the correct package name, for example by printing `AssetComponent.BuildInPackageName`:

   ```csharp
   Debug.Log(AssetComponent.BuildInPackageName); // "DefaultPackage"
   ```

   Source: [Runtime/Asset/AssetComponent.cs#L57](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L57)

## Common Variations

- **Read-only, no modification**: fields are disabled but still readable in Play Mode, suitable for verifying the currently effective play mode and registered package names.
- **Custom asset manager implementation**: switch to a non-default `IAssetManager` implementation in the "Component Type" dropdown, and confirm whether the "Package List" in the Inspector refreshes accordingly.

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| Inspector does not show "Resource Play Mode" / "Package List" | The selected GameObject is not `AssetComponent`, or the resource package info has never been registered | Confirm that the selected object is an `AssetComponent` instance, and check whether `m_assetResourcePackages` is populated |
| Play mode can still be changed at runtime | Play Mode has not been entered, or the custom Inspector is not working | Confirm that Play Mode has been entered; if you have a custom editor, inherit the `AssetComponentInspector` logic |
| `Awake` reports `Asset manager is invalid.` | `IAssetManager` is not registered with `GameFrameworkEntry` | Register the asset manager implementation in code or the bootstrap script, then restart |

## Background (Optional)

`AssetComponent` is a wrapper around YooAsset. During the `Awake` phase, the play mode is forcefully overridden based on the platform (WebGL is forced to `WebPlayMode`; if it's still `EditorSimulateMode` outside the editor, it's switched to `HostPlayMode`), and `_assetManager.SetPlayMode(GamePlayMode)` is called. The "Resource Play Mode" in the Inspector is only a visualization of that field; the actual runtime logic lives in the `IAssetManager` implementation.
