# 主要/備份 URL 全部耗盡時該怎麼辦

啟動流程在請求全域資訊介面時，框架會依序遍歷 `StartupOptions.GlobalInfoUrls` 的主要/備份 URL 清單，並在每個 URL 內部重試 `MaxAttemptsPerUrl` 次。當所有 URL 皆失敗時，`UrlFailoverRunner` 會回傳 `UrlFailoverResult.Fail(...)`，啟動流程以 `StartupResult.Fail` 結束，並觸發 `StartupFailedEventArgs`。

## 快速診斷

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 啟動停留在「全域資訊」階段，且日誌輸出 `URL list must contain at least one URL.` | `GlobalInfoUrls` 為空陣列 | 在 `StartupOptions` 資產中輸入至少 1 個 URL |
| 啟動停留在「全域資訊」階段，且 UI 顯示「所有 URL 已耗盡 / All URLs exhausted」提示 | 主要/備份 URL 皆無法存取，但設定本身有效 | 依序檢查 URL、參數與重試上限（參考下方解決步驟） |
| 日誌出現 `ArgumentException: Max attempts per URL must be greater than zero.` | `MaxAttemptsPerUrl` 被設定為 0 或負數 | 將 `MaxAttemptsPerUrl` 改為 ≥1 |
| 日誌出現 `ArgumentException: Retry delay must be zero or greater.` | `RetryDelayMs` 被設定為負數 | 將 `RetryDelayMs` 改為 ≥0 |
| 單一 URL 在首次嘗試即回傳 200，卻被誤判為失敗 | `attempt` 委派未正確實作 `UrlAttemptResult.Success` | 檢查 `IStartupHttpParamsProvider` 回傳 HTTP 狀態碼的判斷邏輯 |

## 解決步驟

### 1. 確認 `GlobalInfoUrls` 至少包含 1 項以上設定

`UrlFailoverRunner.ExecuteAsync` 在清單為空時會立即拋出 `ArgumentException("URL list must contain at least one URL.", nameof(urls))`。請開啟專案中的 `StartupOptions.asset`，在 `Network → Global Info URLs` 輸入主要/備份 URL（主要在前，備份在後）：

```csharp
public string[] GlobalInfoUrls = new string[0]; // 啟動前必須至少包含 1 個項目
```

來源：[StartupOptions.cs#L22-L23](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### 2. 確認每個 URL 本身是否可存取

請依序逐一存取 `GlobalInfoUrls` 中的位址，確認是否回傳 2xx 回應：

1. 使用瀏覽器或 `curl` 測試 URL 是否回傳 JSON。
2. 確認協定（https / http）、連接埠與路徑的拼寫是否正確。
3. 確認伺服器已部署，且 CDN、防火牆、跨來源（CORS）與驗證標頭均已允許。
4. 若使用 `IStartupHttpParamsProvider` 注入共用參數，請確認 Provider 不會回傳 401/403。

### 3. 提高單一 URL 的重試上限

每個 URL 內部預設重試 3 次（含首次嘗試），您可以在 `StartupOptions` 資產中調高此值，以容許短暫的網路抖動：

```csharp
[Tooltip("每個 URL 內部的總嘗試次數上限（含初次）。")]
public int MaxAttemptsPerUrl = 3;
```

上限必須 ≥1，否則會觸發參數驗證例外：

```csharp
if (maxAttemptsPerUrl < 1)
{
    throw new ArgumentException(
        "Max attempts per URL must be greater than zero.",
        nameof(maxAttemptsPerUrl));
}
```

來源：[UrlFailoverRunner.cs#L27-L30](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L27-L30)

### 4. 調整重試間隔

`RetryDelayMs` 控制兩次重試之間的等待時間（毫秒），預設值為 3000ms。針對瞬間故障可適當調高；在路徑較長或網路不穩定的環境中，則可調低以縮短總耗時。此值必須 ≥0：

```csharp
if (retryDelayMs < 0)
{
    throw new ArgumentException(
        "Retry delay must be zero or greater.",
        nameof(retryDelayMs));
}
```

來源：[UrlFailoverRunner.cs#L32-L35](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L32-L35)

### 5. 讓 UI 引導使用者重試

`UrlFailoverRunner` 會透過 `onProgress(url, attempt, max)` 回呼將目前進度通知上層。整合端通常會將此進度資訊傳遞至啟動 UI 的「重試」按鈕。使用者無須結束流程即可重新觸發，通常會與「切換至備份 URL」提示一併使用。

```csharp
public static UniTask<UrlFailoverResult> ExecuteAsync(
    IReadOnlyList<string> urls,
    int maxAttemptsPerUrl,
    int retryDelayMs,
    Func<string, UniTask<UrlAttemptResult>> attempt,
    Action<string, int, int> onProgress = null,
    CancellationToken cancellationToken = default)
```

來源：[UrlFailoverRunner.cs#L14-L15](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L14-L15)

## 驗證

1. 故意將 `GlobalInfoUrls` 留空並執行遊戲，應出現 `ArgumentException: URL list must contain at least one URL.`，這表示驗證機制正常運作。
2. 將第一個 URL 改為無法存取的位址，其餘保持可存取，啟動時應自動切換至下一個可用的 URL，並成功進入下一個流程。
3. 將所有 URL 改為無法存取的位址後，啟動會以 `StartupResult.Fail` 結束，並透過 `StartupFailedEventArgs` 取得最後失敗的 URL 與錯誤訊息，可將其用於 UI 彈出提示。

## 背景說明（選用）

`UrlFailoverRunner` 的策略是「依序遍歷 URL × 每個 URL 重試 N 次」，失敗時只記錄最後失敗的 URL 與錯誤資訊，不會自動回到清單開頭，也不會隨機選擇備份。整體啟動協調流程請參閱《StartupProcedureUtility 完成失敗處理》文件。此處 `CompleteFailure` 會將 `failedUrl` 一併記錄至 `StartupFailedEventArgs` 並推送至 UI。
