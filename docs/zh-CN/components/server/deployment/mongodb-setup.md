# MongoDB 连接与持久化配置

本页面说明在 GameFrameX.Server 中如何为服务进程配置 MongoDB 连接字符串与数据库名,使 `GameDb` 在启动阶段完成连接、初始化集合并进入可持久化状态。

## 前置条件

- 准备一个可访问的 MongoDB 实例(本地服务或 Atlas 集群均可)。
- 拥有该实例的连接字符串(标准 URI 或 `mongodb+srv://` 形式)以及一个目标数据库名。
- 在启动项目(`GameFrameX.Launcher`)中已通过包引用引入 `MongoDB.Driver`,源码工程通过 `GameFrameX.Apps/GlobalUsings.cs`、`GameFrameX.Hotfix/GlobalUsings.cs` 中的 `global using` 引用 MongoDB 程序集,无需在业务代码再额外引入。

## 操作步骤

1. 在启动入口(默认 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`)的 `Init()` 中构造 `AppSetting`,填入两个数据库相关字段 `DataBaseUrl` 和 `DataBaseName`:

   ```csharp
   Setting = new AppSetting
   {
       // ... 其他服务器配置
       DataBaseUrl  = "mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority",
       DataBaseName = "<your_db_name>",
   };
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L97-L114)

2. 在服务器启动主循环的数据库初始化阶段,框架会调用 `GameDb.Init<MongoDbService>` 并把上面的两个字段传入 `DbOptions`:

   ```csharp
   LogHelper.Debug("开始启动数据库服务...");
   var initResult = await GameDb.Init<MongoDbService>(new DbOptions
   {
       ConnectionString = Setting.DataBaseUrl,
       Name             = Setting.DataBaseName,
   });
   if (initResult == false)
   {
       throw new InvalidOperationException("数据库服务启动失败");
   }
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67)

3. 启动进程。若日志出现 "启动数据库服务 结束..." 且未抛出 `InvalidOperationException`,则 MongoDB 连接与持久化层已就绪。

## 常见变体

- **使用本地 MongoDB**:将 `DataBaseUrl` 替换为 `mongodb://localhost:27017`,数据库名按需调整。
- **使用 Atlas 集群**:沿用默认示例形式 `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority`,只需把账户与集群主机替换为实际值。
- **多环境隔离**:在不同启动入口(例如 `AppStartUpGate`、`AppStartUpWorld` 等继承自 `AppStartUpGame` 的类)的 `Init()` 中按环境分别设置 `DataBaseUrl` / `DataBaseName`,从而为不同进程指向不同库。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 启动抛出 `InvalidOperationException("数据库服务启动失败")` | `GameDb.Init<MongoDbService>` 返回 `false`,通常是连接串不可达、账号错误或网络受限 | 核对 `DataBaseUrl` 的主机、端口、用户、密码;确认 Atlas IP 白名单已放行运行机 |
| 应用启动到数据库步骤前就卡住 | 连接字符串含有未编码的特殊字符(如 `@`、`%`) | 对用户名/密码使用百分号编码,例如 `p@ss` 改为 `p%40ss` |
| 连接成功但读写时报"集合不存在" | `DataBaseName` 与业务期望不一致 | 确认 `DbOptions.Name` 与业务代码中读取的库名一致 |

## 背景(可选)

`GameDb` 是框架统一的持久化门面,实际实现由泛型参数 `MongoDbService` 提供。启动阶段以 `DbOptions` 注入连接串与库名,完成客户端构造、库选择与默认序列化约定注册;业务层通过 `GameDb` 调用即可,不直接持有 `IMongoClient`,从而方便后续切换或替换底层。
