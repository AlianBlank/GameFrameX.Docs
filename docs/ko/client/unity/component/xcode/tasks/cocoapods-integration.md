# CocoaPods 의존성 통합

Unity가 iOS 프로젝트를 내보낸 후, 이 패키지는 JSON 설정에 따라 Podfile을 자동 생성(또는 복사)하고, `pod` 의존성을 주입하며, 빌드 출력 디렉터리에서 직접 `pod install`을 실행합니다. 전체 과정 동안 터미널을 수동으로 열 필요가 없습니다. 의존성을 선언하는 방법은 두 가지가 있습니다: `unityMain` / `unityFramework` 내에 `pods` 필드를 작성하는 방식(권장, 항목별 주입), 또는 `podfile`로 완전한 Podfile 파일 하나를 지정하는 방식(설정 시 `pods` 무시).

## 사전 조건

- 빌드 머신이 macOS이며 CocoaPods가 설치되어 있어야 합니다: `sudo gem install cocoapods`. 설치되어 있지 않으면 로그에서 `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)`를 볼 수 있습니다.
- 프로젝트에 이 패키지가 이미 추가되어 있고, Xcode 설정 JSON이 준비되어 있어야 합니다(템플릿과 예제는 패키지에 포함되어 제공됩니다: `Editor/XCodeConfigTemplate.json`, `Editor/XCodeConfigDemo.json`).

## 작업 단계

1. 설정 JSON의 `unityMain`(메인 프로젝트 target) 또는 `unityFramework`(UnityFramework target) 블록 내에 `pods` 필드를 추가합니다. `key`는 pod 이름, `value`는 버전 제약이며, 빈 문자열은 제약이 없음을 의미합니다:

   ```json
   "podSource": [
       "https://mirrors.tuna.tsinghua.edu.cn/git/CocoaPods/Specs.git"
   ],
   "podfile": "",
   "podInstall": true,
   ```

   최상위 필드는 위와 같습니다(Demo의 실제 값). `pods`는 대상 블록 내부에 작성하며, Demo 예시 값은 다음과 같습니다:

   ```json
   "pods": {
       "Ads-CN-Beta": ", :subspecs => ['CSJMediation']"
   }
   ```

2. (선택 사항) `podSource`를 설정하여 중국 내 미러 소스로 `pod install`을 가속화할 수 있습니다. 설정하지 않으면 자동 생성된 Podfile에 기본 소스 `https://github.com/CocoaPods/Specs.git`가 기록됩니다.

3. iOS 빌드를 트리거합니다. 빌드 후 처리는 다음 순서대로 CocoaPods 설정을 적용합니다:

   - `CopyPodfile`: `podfile` 경로가 설정되어 있으면 해당 파일을 빌드 출력 디렉터리로 직접 복사한 후, 그중 `source` 행만 다시 작성합니다.
   - 그렇지 않으면 주입 경로를 따릅니다: `EnsurePodfileExists`가 먼저 Podfile이 존재하는지 보장하고(존재하지 않으면 현재 `PlayerSettings.iOS.targetOSVersionString`에 따라 스켈레톤을 생성하며, 비어 있으면 `12.0`으로 대체), 이어서 `AddPodsForTarget`이 `Unity-iPhone`과 `UnityFramework` 두 target에 각각 `pod` 행을 주입합니다(이미 존재하는 동일한 이름의 pod는 자동으로 건너뜁니다).
   - 마지막으로 `RunPodInstall`이 빌드 출력 디렉터리에서 `pod install`을 실행합니다(`"podInstall": false`로 건너뛸 수 있음).

   ```csharp
   // PodFile
   var podSourceList = finalConfig.Get("podSource") as ArrayList;
   string podfileConfigPath = finalConfig.Get("podfile") as string;
   bool podfileCopied = CopyPodfile(path, podfileConfigPath);

   if (podfileCopied)
   {
       // 새 경로: 전체 Podfile이 복사되었으므로 source URL만 다시 작성하면 됨
       RunPodfile(path, podSourceList);
   }
   else
   {
       // 기존 경로(하위 호환): JSON 설정의 pods 필드에서 한 줄씩 주입
       var mainPods = finalConfig.Get<Hashtable>("unityMain")?.Get<Hashtable>("pods");
       var frameworkPods = finalConfig.Get<Hashtable>("unityFramework")?.Get<Hashtable>("pods");
       if ((mainPods != null && mainPods.Count > 0) || (frameworkPods != null && frameworkPods.Count > 0))
       {
           EnsurePodfileExists(path, podSourceList);
           AddPodsForTarget(path, "Unity-iPhone", mainPods);
           AddPodsForTarget(path, "UnityFramework", frameworkPods);
       }
   }
   ```

4. 결과 검증: Unity Console에서 `[Pods]` 및 `[PodInstall]` 접두사 로그를 확인하고(예: `[Pods] 已为 Unity-iPhone 添加 N 个 pod 依赖`, `[PodInstall] pod install 完成`), 빌드 출력 디렉터리에 `Podfile`과 `Pods` 디렉터리가 생성되었는지, `.xcworkspace`가 정상적으로 열리는지 확인합니다.

## 설정 항목 빠른 참조

| 설정 항목 | 타입 / 기본값 | 설명 |
|------|------|------|
| `podSource` | `string[]` / 미설정 시 `https://github.com/CocoaPods/Specs.git` 사용 | Podfile 상단에 기록되는 `source` 소스 목록이며, 중국 내 미러를 입력할 수 있음 |
| `podfile` | `string` / `""` | 완전한 Podfile 파일 경로, 상대 경로(Unity 프로젝트 루트 디렉터리 기준, 즉 Assets의 상위)와 절대 경로 지원; 설정 시 `pods` 무시 |
| `podInstall` | `bool` / `true` | 빌드 후 `pod install`을 자동 실행할지 여부, `false`로 설정하면 건너뛸 수 있음 |
| `unityMain.pods` / `unityFramework.pods` | `object` / `{}` | key는 pod 이름, value는 버전 제약; 빈 문자열은 제약 없음을 의미 |

## 버전 제약 작성 방법

`pods`의 value는 다음 규칙에 따라 Podfile의 `pod` 행으로 조합됩니다:

```csharp
// pod 행 생성
foreach (DictionaryEntry kv in pods)
{
    var podName = kv.Key.ToString().Trim();
    if (existingPods.Contains(podName)) continue;

    var version = kv.Value?.ToString()?.Trim();
    if (string.IsNullOrEmpty(version))
    {
        podLines.Add($"  pod '{podName}'");
    }
    else if (version.Contains("=>") || version.StartsWith(":"))
    {
        podLines.Add($"  pod '{podName}', {version}");
    }
    else
    {
        podLines.Add($"  pod '{podName}', '{version}'");
    }
}
```

대응 관계: `""` → `pod 'Name'`; `=>`를 포함하거나 `:`로 시작하는 경우(예: `:subspecs => [...]`, `:git => '...'`) → 쉼표 뒤에 따옴표 없이 그대로 조합; 그 외(예: `~> 1.0`) → 자동으로 작은따옴표가 추가되어 `pod 'Name', '~> 1.0'`이 됩니다.

## 일반적인 변형

- **완전한 Podfile 사용**: 의존성이 복잡할 때는 관리 중인 Podfile을 프로젝트 내에 두고 `"podfile": "MyPodfile"`(Unity 프로젝트 루트 디렉터리 기준 상대 경로) 또는 절대 경로로 설정합니다. 복사 성공 후에는 그중 `source` 행만 다시 작성되며 나머지 내용은 그대로 유지됩니다. 파일이 존재하지 않으면 로그에 `[Pods] 配置指定的 Podfile 不存在: {src}`가 출력되고 `pods` 주입 경로로 대체됩니다.
- **자동 pod install 건너뛰기**: CI에서 설치 시점을 직접 제어해야 할 때 `"podInstall": false`로 설정하면, 빌드 후 처리는 Podfile 생성/주입만 수행하고 `pod install`은 파이프라인의 후속 단계에서 실행됩니다.
- **프라이빗 소스 / 다중 소스**: `podSource`는 배열이므로 여러 `source` 행을 동시에 기록할 수 있습니다. 예를 들어 공식 Specs와 프라이빗 저장소를 동시에 유지할 수 있습니다.

## 일반적인 오류

| 현상(로그 원문) | 원인 | 해결 방법 |
|------|------|------|
| `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)` | 빌드 머신에 CocoaPods가 설치되지 않았거나, pod가 일반적인 경로(`.gem/ruby/bin`, Homebrew, `/usr/local/bin`, `/usr/bin`)에 없어 `which pod` 해석에 실패함 | CocoaPods 설치; 또는 pod를 `/usr/local/bin/pod` 등 탐지 가능한 경로로 심볼릭 링크 |
| `[Pods] 配置指定的 Podfile 不存在: {src}` | `podfile` 경로를 잘못 썼거나 파일이 이동됨 | 올바른 경로로 수정; 상대 경로는 Unity 프로젝트 루트 디렉터리(Assets 상위) 기준 |
| `[Pods] 未找到 target '{targetName}' do, 跳过设置` | 커스텀 Podfile의 target 행 형식이 일치하지 않음(`target 'Unity-iPhone' do` 형태여야 함) | target 행 작성 방법을 수정하거나, `pods` 주입 방식을 직접 사용 |
| `[PodInstall] pod install 失败 (退出码: {code}): {error}` | pod 버전 제약 충돌, 소스 접근 불가, Gem/Ruby 환경 문제 등 | error 출력에 따라 원인 파악; 먼저 미러 소스를 사용해 보고, 필요 시 `"podInstall": false`로 설정 후 수동으로 `pod install`을 실행하여 문제 재현 |
| `当前不是Pod 项目结构,跳过设置` | 빌드 출력 디렉터리에 `Podfile`이 없음 | `pods` 주입 방식으로 자동 생성하도록 하거나, `podfile` 설정 제공 |

## 검증

- Unity Console에 `修改PodFile 文件的源, 开始/结束`, `[Pods] ...`, `[PodInstall] 开始执行 pod install...`, `[PodInstall] pod install 完成`이 순서대로 나타납니다.
- 빌드 출력 디렉터리에 `Podfile`(내용에 설정된 `source` 행과 각 target의 `pod` 행 포함), `Pods/` 디렉터리 및 `Podfile.lock`이 존재합니다.
- 생성된 `.xcworkspace`(`.xcodeproj`가 아님)를 열면 의존성 라이브러리가 Pods 프로젝트에 나타나고 컴파일이 정상적으로 통과합니다.

## 배경

CocoaPods 관련 로직은 빌드 후 처리의 두 번째 단계에 집중되어 있으며, `PostProcessBuildHelper`의 부분 클래스(partial class) 파일로 구현되어 있습니다: [PostProcessBuildHelper.PodFile.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.PodFile.cs#L19)는 `RunPodfile`(source 행 다시 작성), `EnsurePodfileExists`(스켈레톤 생성), `CopyPodfile`(커스텀 Podfile 복사), `AddPodsForTarget`(target별 주입 및 중복 제거), `RunPodInstall` 및 `GetPodFullPath`를 제공합니다. 메인 흐름은 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156)에서 연결됩니다. `pod install` 실행 시 `LANG` / `LC_ALL`을 `en_US.UTF-8`로 명시적으로 설정하고(CocoaPods가 인코딩을 요구함), pod의 절대 경로를 해석합니다(Unity 하위 프로세스는 shell PATH를 상속받지 않음). 이것이 흔한 "터미널에서는 사용 가능하지만 빌드 시 pod를 찾을 수 없음" 문제의 근본 원인입니다. iOS 빌드 후 처리의 전체 흐름에 대해서는 《iOS 빌드 후 처리》를 참조하십시오.
