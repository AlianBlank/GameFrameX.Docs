# 로컬라이제이션 문자열을 가져오는 방법(1–16개 매개변수 포매팅 포함)

`LocalizationComponent.GetString` 시리즈 오버로드를 통해 사전 키로 로컬라이제이션 문자열을 가져올 수 있습니다. 포매팅이 필요한 경우 사전 값에 표준 .NET 플레이스홀더(`{0}`, `{1}` …)를 작성한 뒤, 1~16개의 매개변수를 해당 오버로드에 전달합니다. key가 존재하지 않으면 `<NoKey>{key}`를 반환하며, 플레이스홀더와 매개변수가 일치하지 않으면 결과가 `<Error>`로 시작합니다.

## 전제 조건

- 프로젝트에 `com.gameframex.unity.localization` 패키지가 설치되어 있고, 씬의 `LocalizationComponent` 초기화가 완료되어 있어야 합니다(사전이 로드됨).
- 스크립트에서 네임스페이스 `GameFrameX.Localization.Runtime`를 가져오고, `GameEntry`를 통해 컴포넌트를 가져옵니다:

```csharp
using GameFrameX.Localization.Runtime;

// 표준 방식: GameEntry를 통해
var localization = GameEntry.GetComponent<LocalizationComponent>();
```

출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L100-L105)

## 작업 단계

1. **컴포넌트 참조 가져오기**(위 코드와 같으며, 일반적으로 `Start`에서 캐시).
2. **간단한 값 조회**: key만 전달하면 해당 key에 대응하는 원본 번역문이 반환됩니다:

```csharp
// 간단한 key 조회
// key를 찾지 못하면 "<NoKey>{key}" 반환
string okText = localization.GetString("UI.Button.OK");
string cancelText = localization.GetString("UI.Button.Cancel");

// 값을 가져오기 전에 key 존재 여부 확인
if (localization.HasRawString("UI.Button.Confirm"))
{
    string confirmText = localization.GetString("UI.Button.Confirm");
}
```

출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L133-L144)

3. **매개변수를 사용한 포매팅**: 사전 값에 `{0}`, `{1}` 등의 플레이스홀더를 사용하고, 호출 시 매개변수를 순서대로 전달합니다.

```csharp
// 사전에 다음이 포함되어 있다고 가정:
// "UI.Message.Welcome" = "Welcome, {0}!"
// "UI.Info.Score"     = "Player {0} scored {1} points at level {2}!"
// "UI.Shop.Buy"       = "Buy {0} x {1} for {2} coins, discount {3:P}, total {4:C}"

// params object[] 오버로드 사용
string welcome = localization.GetString("UI.Message.Welcome", playerName);

// 타입 지정 제네릭 오버로드 사용(권장 — 값 타입은 박싱을 피할 수 있음)
string info = localization.GetString<string, int, int>("UI.Info.Score", playerName, score, level);

// 최대 16개의 타입 지정 매개변수 지원
string shopMsg = localization.GetString<string, int, int, float, decimal>(
    "UI.Shop.Buy", itemName, quantity, unitPrice, discount, total);
```

출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L150-L165)

4. **선택 사항: 원본 번역문 직접 읽기**. 포매팅을 트리거하고 싶지 않을 때 `GetRawString`을 사용합니다(key가 존재하지 않으면 `null` 반환):

```csharp
string rawText = localization.GetRawString("UI.Button.NewButton");
```

출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L173-L192)

컴포넌트의 `GetString`은 `m_LocalizationManager`의 동일한 이름 메서드에 대한 직접 전달이며, 실제 시그니처는 다음과 같습니다:

| 오버로드 | 설명 |
|------|------|
| `public string GetString(string key)` | 매개변수 없는 값 조회 |
| `public string GetString(string key, params object[] args)` | 임의 개수의 매개변수(object 배열) |
| `public string GetString<T>(string key, T arg)` | 타입 지정 매개변수 1개 |
| `public string GetString<T1, T2>(string key, T1 arg1, T2 arg2)` | 타입 지정 매개변수 2개 |
| `public string GetString<T1, …, T16>(string key, T1 arg1, …, T16 arg16)` | 이러한 방식으로 타입 지정 매개변수 16개까지 지원 |

```csharp
[Preserve]
public string GetString(string key)
{
    return m_LocalizationManager.GetString(key);
}

[Preserve]
public string GetString(string key, params object[] args)
{
    return m_LocalizationManager.GetString(key, args);
}

[Preserve]
public string GetString<T>(string key, T arg)
{
    return m_LocalizationManager.GetString(key, arg);
}

[Preserve]
public string GetString<T1, T2>(string key, T1 arg1, T2 arg2)
{
    return m_LocalizationManager.GetString(key, arg1, arg2);
}
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L283-L337)

## 일반적인 변형

- **언어 전환 후 텍스트 새로고침**: `localization.Language`를 전환하면 언어 변경 이벤트가 브로드캐스트되며, 이벤트 콜백에서 `GetString`을 다시 호출하여 UI 텍스트를 갱신합니다. 언어 전환 및 이벤트 리스닝에 대한 전체 방법은 《런타임 언어 전환 방법》을 참조하세요.
- **런타임 중 항목 추가/제거**: `AddRawString`으로 추가(key가 이미 존재하거나 비어 있으면 `false` 반환), `RemoveRawString`으로 개별 항목 삭제, `RemoveAllRawStrings`로 전체 삭제, `HasRawString`으로 존재 여부 확인.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| 결과가 `<NoKey>{key}` 형식 | 사전에 해당 key가 존재하지 않음 | 먼저 `HasRawString`으로 확인; 사전이 로드되었는지, key 철자가 올바른지 확인 |
| 결과가 `<Error>`로 시작하며 진단 정보가 함께 표시됨 | 포맷 문자열의 플레이스홀더와 전달된 매개변수 불일치 | 사전 값의 `{0}`, `{1}` …이 매개변수 개수·순서와 일치하는지 확인 |
| `GetRawString`이 `null` 반환 | key가 존재하지 않음 | `<NoKey>`와 동일하게 key와 사전 로드 상태 확인 |
| 화면에 여전히 이전 언어가 표시됨 | 언어 전환 후 값을 다시 가져오지 않음 | 언어 변경 이벤트 콜백에서 `GetString` 다시 호출 |

## 검증

- 매개변수 없는 호출: 알려진 key(예: `UI.Button.OK`)에 대해 `GetString`을 호출하면 반환값이 `<NoKey>...`가 아니라 현재 언어 사전의 번역문과 동일해야 합니다.
- 매개변수가 있는 호출: 플레이스홀더가 포함된 key(예: `UI.Info.Score` = `"Player {0} scored {1} points at level {2}!"`)에 대해 `GetString<string, int, int>("UI.Info.Score", playerName, score, level)`을 호출하면, 반환값에 플레이스홀더 치환이 완료되어 있고 `<Error>`로 시작하지 않아야 합니다.

## 배경

컴포넌트의 `GetString` 각 오버로드는 단순히 내부 `m_LocalizationManager`의 동일한 이름 메서드로 전달할 뿐입니다. 제네릭 오버로드의 의의는 값 타입 매개변수(`int`, `float` 등)가 `object` 박싱 오버헤드를 피할 수 있도록 하는 것이며, 매개변수 개수가 16개를 초과하거나 타입을 미리 알 수 없는 경우에는 `params object[]` 오버로드로 처리합니다. 포매팅은 표준 .NET 복합 서식 규칙(`{0}`, `{3:P}`, `{4:C}` 등)을 따르므로, 복합 서식 문자열 작성 방식을 그대로 사용할 수 있습니다.
