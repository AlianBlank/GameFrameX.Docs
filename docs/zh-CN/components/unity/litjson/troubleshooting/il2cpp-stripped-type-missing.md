# IL2CPP 发布后类型缺失或报错怎么办

IL2CPP 在构建时会做托管代码裁剪(Managed Code Stripping),LitJson 依赖反射生成读写器,被裁掉后会在 IL2CPP 运行时出现 `MissingMethodException`、`InvalidCastException`,或反序列化返回空对象。本页给出快速诊断与修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `MissingMethodException: ... LitJson ...` | IL2CPP 链接器裁掉了 LitJson 内部方法 | 添加 `link.xml` 并挂上 `LitJsonCroppingHelper` |
| 反序列化结果字段全为 `null`/默认值 | `JsonData`/`JsonMapper` 的导出器被裁剪 | 添加 `link.xml` |
| `JsonMapper.ToObject<T>` 返回对象但属性丢失 | 自定义 T 的字段/属性被裁剪 | 在 `link.xml` 中按程序集保留该 T 的类型 |
| `Type.GetType("...")` 返回 `null` | IL2CPP 不支持按字符串名查找未保留类型 | 使用泛型 `ToObject<T>()` 或在 `link.xml` 中保留对应类型 |
| `InvalidCastException` 在注册自定义 Importer/Exporter 时 | 委托目标方法被裁剪 | 在 `link.xml` 中保留你的程序集 |

## 修复步骤

### 1. 添加 link.xml 声明式保留

在 Unity 工程任意 `Assets` 子目录下创建 `link.xml`(通常放在 `Assets/link.xml`),内容如下,作用是显式保留 LitJson 程序集:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
</linker>
```

构建时会基于此文件跳过 LitJson 相关类型的裁剪,这是第一道防线。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md#L40-L50)

### 2. 挂上 LitJsonCroppingHelper 运行时防裁剪

仓库自带 `LitJsonCroppingHelper`,它在 `Start()` 中通过 `typeof(...)` 显式引用所有公共 LitJson 类型,作为第二道保险:

```csharp
[Preserve]
public class LitJsonCroppingHelper : UnityEngine.MonoBehaviour
{
    [Preserve]
    public void Start()
    {
        _ = typeof(ArrayMetadata);
        _ = typeof(Condition);
        _ = typeof(ExporterFunc);
        _ = typeof(ExporterFunc<>);
        _ = typeof(JsonIgnoreAttribute);
        _ = typeof(JsonPropertyAttribute);
        _ = typeof(FsmContext);
        _ = typeof(IJsonWrapper);
        _ = typeof(ImporterFunc);
        _ = typeof(ImporterFunc<,>);
        _ = typeof(JsonData);
        _ = typeof(JsonException);
        _ = typeof(JsonMapper);
        _ = typeof(JsonMockWrapper);
        _ = typeof(JsonReader);
        _ = typeof(JsonToken);
        _ = typeof(JsonType);
        _ = typeof(JsonWriter);
        _ = typeof(Lexer);
        _ = typeof(ObjectMetadata);
        _ = typeof(OrderedDictionaryEnumerator);
        _ = typeof(ParserToken);
        _ = typeof(PropertyMetadata);
        _ = typeof(UnityTypeBindings);
        _ = typeof(WrapperFactory);
        _ = typeof(WriterContext);
    }
}
```

把该组件挂到一个场景中**最早启动**的 GameObject 上(例如 `Bootstrap`),保证 `Start()` 在任何 `JsonMapper` 调用之前执行。

Source: [LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L12-L52)

### 3. 保留自定义数据类型

如果你用 `JsonMapper.ToObject<MyData>("...")` 反序列化自定义类,且 `MyData` 位于其他程序集,需要在 `link.xml` 中追加保留条目:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
  <assembly fullname="MyGame.Models" preserve="all"/>
</linker>
```

或者只保留特定类型以减小包体:

```xml
<linker>
  <assembly fullname="MyGame.Models">
    <type fullname="MyGame.Models.PlayerData" preserve="all"/>
    <type fullname="MyGame.Models.InventoryItem" preserve="all"/>
  </assembly>
</linker>
```

### 4. 避免依赖按字符串名加载类型

`Type.GetType("MyGame.Models.PlayerData, MyGame.Models")` 在 IL2CPP 下,若该类型未通过 `link.xml` 保留,会返回 `null`。建议:

- 使用泛型 `JsonMapper.ToObject<PlayerData>(json)`;
- 或在 `link.xml` 中显式保留该类型;
- 或调用 `JsonMapper.RegisterImporter<string, Type>(s => Type.GetType(s))` 注册自定义导入器时,确保目标类型已被保留。

Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L47)

### 5. 检查 Unity 构建设置

1. `Player Settings > Managed Stripping Level`:IL2CPP 下保持 `Low` 或更低;若使用 `High`/自定义规则,务必配合 `link.xml`。
2. `Player Settings > Strip Engine Code`:取消勾选或纳入 `link.xml` 例外。
3. 清理 Library/ScriptAssemblies 后重新出包,避免缓存掩盖配置变更。

## 验证

1. 用 IL2CPP 出包后,启动游戏触发一次完整的 `JsonMapper.ToJson` 与 `JsonMapper.ToObject` 双向流程,确认无 `MissingMethodException`。
2. 在 Xcode/Android log 中搜索关键字 `LitJson`、`MissingMethod`,确认无报错。
3. 反序列化结果对象的字段值与原始 JSON 一致(无 null/默认值)。
4. 临时把 `Managed Stripping Level` 调到 `High` 复测一次,验证 `link.xml` 与 `LitJsonCroppingHelper` 在最严格裁剪下仍生效。
