# 如何初始化廣告元件

完成本頁的步驟後，您的場景中將掛載一個 `AdvertisementComponent`，並透過它完成廣告管理器的初始化。之後即可直接呼叫播放與載入介面。

## 前置條件

- 已安裝 GameFrameX 框架主套件。
- 已匯入目前的 `com.gameframex.unity.advertisement` 套件，且已向 `GameFrameworkEntry` 註冊至少一個實作 `IAdvertisementManager` 的管理器（例如特定平台廣告 SDK 的轉接器）。
- 已準備好一個繼承自 `AdvertisementConfig` 的設定類別，用來承載廣告版位 ID、偵錯旗標等參數。

## 步驟

1. 在場景中建立新的 GameObject，選取它，點擊選單 `Component → GameFrameX → Advertisement` 新增該元件；或在 Inspector 的 `Add Component` 搜尋框中輸入 `Advertisement`，選擇 `GameFrameX/Advertisement`。

   ```csharp
   // 等同於透過選單新增
   [AddComponentMenu("GameFrameX/Advertisement")]
   [DisallowMultipleComponent]
   public class AdvertisementComponent : GameFrameworkComponent
   ```

   來源：[AdvertisementComponent.cs#L43-L45](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L43-L45)

2. 在 Inspector 中填入各平台的廣告版位 ID 與偵錯開關。元件會依據目前建置平台自動選取對應欄位：

   | 欄位 | 適用平台 |
   |------|----------|
   | `Ad Unit Id Android` | UNITY_ANDROID |
   | `Ad Unit Id iOS` | UNITY_IOS |
   | `Ad Unit Id WebGL` | UNITY_WEBGL（預設） |
   | `Ad Unit Id WebGLWeChat` | UNITY_WEBGL + ENABLE_WECHAT_MINI_GAME |
   | `Ad Unit Id WebGLDouYin` | UNITY_WEBGL + ENABLE_DOUYIN_MINI_GAME |
   | `Ad Unit Id WebGLKuaiShou` | UNITY_WEBGL + ENABLE_KUAISHOU_MINI_GAME |
   | `Debug` | 是否啟用偵錯模式 |

   平台欄位的自動選取邏輯是在 `Awake()` 內以前置處理器分支實作：

   ```csharp
   AdUnitId =
   #if UNITY_WEBGL
   #if ENABLE_WECHAT_MINI_GAME
           m_adUnitIdWebGLWeChat
   #elif ENABLE_DOUYIN_MINI_GAME
           m_adUnitIdWebGLDouYin
   #elif ENABLE_KUAISHOU_MINI_GAME
           m_adUnitIdWebGLKuaiShou
   #else
           m_adUnitIdWebGL
   #endif
   #elif UNITY_ANDROID
           m_adUnitIdAndroid
   #elif UNITY_IOS
           m_adUnitIdiOS
   #else
           string.Empty
   #endif
           ;
   ```

   來源：[AdvertisementComponent.cs#L99-L117](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)

3. 定義一個繼承自 `AdvertisementConfig` 的設定類別，並將上述欄位與其他額外參數放進其中：

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   [Preserve]
   public class MyAdConfig : AdvertisementConfig
   {
       public string AndroidAdUnitId;
       public string IosAdUnitId;
       public string WebGLAdUnitId;
   }
   ```

   `AdvertisementConfig` 是一個內建 `isDebug` 欄位的抽象基底類別：

   ```csharp
   [Preserve]
   [Serializable]
   public abstract class AdvertisementConfig
   {
       [Preserve]
       public bool isDebug;
   }
   ```

   來源：[AdvertisementConfig.cs#L43-L53](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L43-L53)

4. 在包含您設定類別的組件中，使用 `[AdvertisementConfig(typeof(MyAdConfig))]` 標註對應的廣告管理器實作，以供編輯器驗證與反射使用：

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   [AdvertisementConfig(typeof(MyAdConfig))]
   public sealed class MyAdManager : BaseAdvertisementManager
   {
   }
   ```

   ```csharp
   [AttributeUsage(AttributeTargets.Class)]
   public sealed class AdvertisementConfigAttribute : Attribute
   {
       public Type ConfigType { get; }
       public AdvertisementConfigAttribute(Type configType) { ConfigType = configType; }
   }
   ```

   來源：[AdvertisementConfigAttribute.cs#L41-L62](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfigAttribute.cs#L41-L62)

5. 在 Inspector 中保留 `AdvertisementComponent` 由 `Start()` 觸發的自動初始化行為（僅在 `m_config != null` 時生效），或從腳本手動呼叫 `Initialize` 並傳入設定實例：

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   var component = UnityEngine.Object.FindObjectOfType<AdvertisementComponent>();
   var cfg = new MyAdConfig { isDebug = true, AndroidAdUnitId = "android-id" };
   component.Initialize(cfg);
   ```

   ```csharp
   [Preserve]
   public void Initialize(AdvertisementConfig config)
   {
       m_config = config;
       _advertisementManager.Initialize(config);
   }
   ```

   來源：[AdvertisementComponent.cs#L135-L140](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L135-L140)

   `Start()` 內的等效呼叫：

   ```csharp
   private void Start()
   {
       if (m_config != null)
       {
           _advertisementManager.Initialize(m_config);
       }
   }
   ```

   來源：[AdvertisementComponent.cs#L120-L126](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)

6. 執行場景並留意主控台訊息。在 `Awake()` 中，若無法取得管理器，將以 `Log.Fatal("Advertisement manager is invalid.")` 中止初始化並提前返回；否則 `AdUnitId` 會被正確賦值，廣告管理器將進入可用狀態。

   ```csharp
   _advertisementManager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
   if (_advertisementManager == null)
   {
       Log.Fatal("Advertisement manager is invalid.");
       return;
   }
   ```

   來源：[AdvertisementComponent.cs#L92-L97](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L92-L97)

## 常見變化

- 僅設定 Inspector 欄位而不傳入 `AdvertisementConfig`：元件會在 `Start()` 中跳過初始化，您必須手動呼叫 `Initialize(config)`。
- 舊版 API：`Initialize(string adUnitId, bool isDebug = false)` 與 `Show/Load/Play(Action<bool>,string)` 仍可使用，但已標記為 `[Obsolete]`。新程式碼應使用 `Play(AdvertisementPlayOption)` 路徑。
- 您不需要填寫所有平台欄位——只需填寫目前目標平台對應的欄位即可，其餘保留為空字串；元件會自動選取對應平台的欄位。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 啟動後主控台出現 `Advertisement manager is invalid.` | 尚未註冊任何實作 `IAdvertisementManager` 的模組 | 匯入對應平台的廣告轉接套件，並確認其已向 `GameFrameworkEntry` 註冊管理器 |
| `Start()` 未觸發任何初始化 | Inspector 中的 `m_config` 為空 | 拖入 `AdvertisementConfig` 子類別實例，或從腳本呼叫 `Initialize(config)` |
| Android 播放使用了空 ID | 僅填寫了 iOS 或 WebGL 欄位 | 回到 Inspector 補齊 `Ad Unit Id Android` |
| 微信小遊戲使用了 WebGL 預設廣告版位 | 未啟用對應的指令碼定義符號 | 在 `Project Settings → Player → Scripting Define Symbols` 中加入 `ENABLE_WECHAT_MINI_GAME`（`ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 同理） |

## 背景（選用）

`AdvertisementComponent` 會使用 `Utility.Assembly.GetType(componentType)` 在框架模組中查找實作型別，並於 `Awake()` 內從 `GameFrameworkEntry` 取得管理器參考。在 `Start()` 或明確呼叫 `Initialize` 時，會將 `AdvertisementConfig` 子類別實例交給管理器。設定基底類別本身僅提供 `isDebug`；其餘與平台相關的欄位由您的子類別視需要擴充。因此，元件欄位（如 `m_adUnitIdAndroid`）與設定類別是兩個相對獨立的層次：前者用於 Inspector 顯示，後者才是實際傳遞給管理器的內容。
