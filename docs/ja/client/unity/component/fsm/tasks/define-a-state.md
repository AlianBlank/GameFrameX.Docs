# 状態の定義方法

GameFrameX FSM では、状態は抽象基底クラス `FsmState<T>` を継承することで実装されます。`T` はステートマシンの所有者型であり、継承後にライフサイクルコールバックをオーバーライドすることで状態定義が完了します。

## 前提条件

- `GameFrameX.Fsm.Runtime` アセンブリが導入済みであり、Unity プロジェクト内で直接参照できること。
- 後続のステートマシン作成のために、所有者型 `T`(`class` である必要があります)が存在すること。

## 操作手順

1. **ステートマシン所有者型の決定**

   例えばキャラクターコントローラーの `Player` を用意し、ジェネリックパラメータ `T` として指定します。

2. **`FsmState<T>` を継承し、必要なコールバックを実装する**

   `FsmState<T>` は抽象基底クラスであり、`OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy` の 6 つのライフサイクルフックを提供します。いずれも `protected internal virtual` であり、必要に応じてオーバーライドします。

   ```csharp
   using GameFrameX.Fsm.Runtime;

   public class IdleState : FsmState<Player>
   {
       protected internal override void OnEnter(IFsm<Player> fsm)
       {
           // 待機状態に入ったときのロジック
       }

       protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           // 毎フレームのポーリングロジック
       }

       protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
       {
           // 待機状態から離れるときのロジック
       }
   }
   ```

   出典: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L41-L108)

3. **状態内部からの状態遷移のトリガ**

   基底クラスが提供する `ChangeState<TState>(IFsm<T> fsm)` を通じて別の状態に切り替えます:

   ```csharp
   protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
   {
       if (/* トリガ条件 */)
       {
           ChangeState<RunState>(fsm);
       }
   }
   ```

   出典: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

4. **状態をステートマシンに追加する**

   ステートマシン作成時に `CreateFsm<T>` の `params FsmState<T>[]` パラメータで渡すか、作成後に `AddState` を呼び出して動的に追加します:

   ```csharp
   var fsm = FsmComponent.Instance.CreateFsm(player, new IdleState(), new RunState());
   // または
   fsm.AddState(new RunState());
   ```

   出典: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L205-L220)

## ライフサイクルコールバック一覧

| コールバック | トリガタイミング | 典型的な用途 |
|------|---------|---------|
| `OnInit(IFsm<T> fsm)` | 状態が初めてステートマシンに追加されたとき | 内部データの初期化 |
| `OnEnter(IFsm<T> fsm)` | その状態に入ったとき | アニメーション再生、フラグ設定 |
| `OnUpdate(IFsm<T> fsm, float, float)` | 毎フレームのポーリング | 遷移条件の検出 |
| `OnFixedUpdate(IFsm<T> fsm, float, float)` | 固定時間ステップでのポーリング | 物理関連のロジック |
| `OnLeave(IFsm<T> fsm, bool isShutdown)` | その状態から離れるとき | 状態のクリーンアップ、フラグ復元。`isShutdown` はステートマシン停止によるものかどうかを示す |
| `OnDestroy(IFsm<T> fsm)` | 状態が破棄されるとき | リソースの解放 |

## よくあるバリエーション

- **空状態の殻**:プレースホルダやグループ分けにのみ使用する場合、以下のようにどのメソッドもオーバーライドしません:

  ```csharp
  private class TestIdleState : FsmState<object>
  {
  }
  ```

  出典: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L128-L130)

- **タイプによる状態切り替え**:ジェネリック版 `ChangeState<TState>` の他に、基底クラスは `ChangeState(IFsm<T>, Type)` オーバーロードも提供しており、外部設定に基づいて動的に切り替えたい場合に適しています:

  ```csharp
  ChangeState(fsm, typeof(RunState));
  ```

  出典: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

## よくあるエラー

- **同じ型の状態の重複追加**:ステートマシンは型をキーとして状態を保存するため、同じ型に対して重複して `AddState` を呼び出すと `GameFrameworkException` がスローされます。
- **状態切り替え時に誤った型を渡す**:`ChangeState(fsm, stateType)` は `stateType` が `FsmState<T>` から派生しているかを検証し、そうでなければ `GameFrameworkException("State type '...' is invalid.")` をスローします。
- **`fsm` がすでに無効化された状態で `ChangeState` を直接呼び出す**:基底クラスが `GameFrameworkException("FSM is invalid.")` をスローします。

## 背景(任意)

`FsmState<T>` 抽象クラスはフックと状態切り替え機能のみを公開しており、ランタイムデータを一切保持しません——状態をまたいで共有されるデータはすべて `IFsm<T>` の `GetData` / `SetData` を通じてアクセスします。これにより状態実装を軽量でテストしやすいものに保てます。
