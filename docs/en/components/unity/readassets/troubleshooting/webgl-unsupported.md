# What to Do When WebGL Platform Is Unavailable

`com.gameframex.unity.readassets` does not have a dedicated implementation branch for the WebGL platform, and the Unity WebGL runtime sandbox cannot directly open files in StreamingAssets in a synchronous manner like a local disk or APK can. Therefore, this framework is **not officially supported** on the WebGL platform. Once you switch the Build Target to WebGL and call any API of `BlankReadAssets`, you will encounter missing functionality or loading failures in the editor or at runtime.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| After switching Build Target to WebGL, the compiler reports a "WebGL is not supported" warning, or files in StreamingAssets cannot be read in the WebGL build | The framework only provides dedicated implementation branches for `UNITY_EDITOR` and `UNITY_ANDROID`. WebGL and other platforms share `LooseFilesImpl`, and the WebGL sandbox does not support synchronous `File` I/O | Refer to the fix steps below to switch the solution |
| Calling `BlankReadAssets.ReadAllBytes / FileExists / LoadAssetBundle` returns empty or throws `FileNotFoundException` | On WebGL, `LooseFilesImpl` uses `Application.streamingAssetsPath`, but `AssetBundle.LoadFromFile` on WebGL must use `UnityWebRequest` instead | Replace with Unity WebGL native interfaces (see step 2) |
| Business logic needs to support both WebGL and Android, using a direct `if (Application.platform == RuntimePlatform.WebGLPlayer)` check | The framework does not provide a separate read path for WebGL | Call UnityWebRequest separately for the WebGL branch, and continue using `BlankReadAssets` for other platforms (see step 3) |

## Fix Steps

### 1. Use UnityWebRequest in WebGL Build

File access on the WebGL platform must go through `UnityWebRequest`, which is the only officially supported asset loading method in Unity's WebGL backend:

```csharp
using UnityEngine;
using UnityEngine.Networking;

public static class WebGLReadAssetsFallback
{
    public static UnityWebRequest ReadAllBytes(string relativePath)
    {
        // The URL of StreamingAssets on WebGL looks like http(s)://host/StreamingAssets/xxx
        var url = System.IO.Path.Combine(Application.streamingAssetsPath, relativePath);
        return UnityWebRequest.Get(url);
    }
}
```

### 2. Use Platform Conditional Compilation to Retain Old Calls

Use macros in business code to exclude WebGL, avoiding calls to unsupported APIs on WebGL:

```csharp
#if !UNITY_WEBGL || UNITY_EDITOR
    using GameFrameX.ReadAssets.Runtime;
#endif

public byte[] LoadConfig(string path)
{
#if !UNITY_WEBGL || UNITY_EDITOR
    return BlankReadAssets.ReadAllBytes(path);
#else
    using (var req = WebGLReadAssetsFallback.ReadAllBytes(path))
    {
        req.SendWebRequest();
        while (!req.isDone) { }
        return req.downloadHandler.data;
    }
#endif
}
```

> See the platform-based implementation selection in `Runtime/BlankReadAssets.cs`:

```csharp
#if UNITY_EDITOR
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.EditorImpl;
#elif UNITY_ANDROID
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.ApkImpl;
#else
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.LooseFilesImpl;
#endif
```

### 3. Additional Notes on AssetBundle

`BlankReadAssets.LoadAssetBundle` internally calls `AssetBundle.LoadFromFile`, and the behavior of this API on WebGL is undefined. If you need to load an AssetBundle on WebGL, you must use `UnityWebRequestAssetBundle.GetAssetBundle` instead. The framework does not currently provide an equivalent WebGL implementation, so you need to implement it yourself or remove the dependency on this path.

## Verification

- In the editor, switch Build Target to WebGL, trigger the scene initialization logic, and confirm that no runtime exceptions other than "WebGL is not supported" are printed.
- Open the browser developer tools in the WebGL Build, confirm that the `UnityWebRequest` request path points to the correct relative file under `StreamingAssets`, and the response is 200.
- Business path changed to: non-WebGL goes through `BlankReadAssets`, WebGL goes through `UnityWebRequest`, and run the same resource loading smoke test on both paths.

## Background (Optional)

The repository README explicitly states "WebGL is not supported" in the Platform Notes section. This framework does not provide a `UNITY_WEBGL` implementation branch. Other non-Android, non-Editor platforms are all mapped to `LooseFilesImpl`, which reads files from the physical disk and cannot meet the synchronous/asynchronous I/O requirements of the WebGL sandbox.
