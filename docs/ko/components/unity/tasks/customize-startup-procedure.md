# Startup 프로세스에서 커스텀 Procedure接入 방법

`ApplicationStartupEntry`에서 `StartupRunner.Run`을 호출하면, 프레임워크는 `startupOptions.ProcedureSettings`에 설정된 순서대로 각 Procedure를 차례로 실행합니다. 이 문서는 커스텀 Procedure를 새로 추가하여 이 시작 체인에 연결하는 방법을 설명합니다.

## 사전 조건

- `Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs` 시작 진입점이 이미 존재합니다.
- 프로젝트에 `GameFrameX.Startup.Runtime`(`StartupRunner`, `ProcedureBase`, `IStartupUIHandler` 제공)이 이미 도입되어 있습니다.
- `startupOptions` 자산이 `ApplicationStartupEntry`의 인스펙터 패널에 연결되어 있습니다.

## 작업 단계

1. **커스텀 Procedure 클래스를 새로 생성**하고, `ProcedureBase`를 상속받아 `OnEnter` / `OnLeave`를 구현합니다(필요에 따라 `OnUpdate`를 재정의합니다).

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   namespace GameFrameX.Startup.Application
   {
       /// <summary>
       /// 커스텀 시작 프로세스: 원격 계정 서비스에 로그인하고 플레이어 기본 데이터를 로드합니다.
       /// </summary>
       public sealed class ProcedureLogin : ProcedureBase
       {
           protected override async UniTask OnEnter(ProcedureContext context)
           {
               // 프로세스 진입: 시작 시 실행하려는 로직을 여기에 작성
               await LoginRemoteServiceAsync();
           }

           protected override UniTask OnLeave(ProcedureContext context)
           {
               // 프로세스 종료: 리소스 또는 상태 정리
               return UniTask.CompletedTask;
           }

           private UniTask LoginRemoteServiceAsync()
           {
               // 비즈니스 측에서 구현
               return UniTask.CompletedTask;
           }
       }
   }
   ```

   Source: [ApplicationStartupUIHandler.cs](Assets/Scripts/Framework/Procedure/ApplicationStartupUIHandler.cs#L1-L87)

2. **Procedure를 `StartupOptions`에 등록**합니다. `startupOptions.ProcedureSettings` 목록에 실행 순서대로 `ProcedureLogin`을 추가합니다(클래스 이름 또는 타입 식별자는 프레임워크 규약과 일치해야 하며, 일반적으로 `Type` 또는 리소스 키를 직접 사용합니다).

3. **(선택 사항)커스텀 시작 UI**. 시작 과정에서 UI 메시지를 새로 고쳐야 하는 경우, `IStartupUIHandler`를 구현하고 진입점에서 전달합니다:

   ```csharp
   var result = await StartupRunner.Run(
       startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   `IStartupUIHandler`에서 반드시 구현해야 하는 멤버: `StartAsync(uiResName)`, `SetTipText(text)`, `SetProgress(progress, sizeInfo)`, `SetProgressUpdateFinish()`, `ShowUpgradeAsync(upgradeInfo)`, `Dispose()`.

   Source: [ApplicationStartupEntry.cs](Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L14-L55)

4. **실패 응답 처리**. `StartupRunner.Run`은 `StartupResult`를 반환하며, `Success`, `FailedProcedureName`, `FailedUrl`, `ErrorMessage` 필드를 통해 어떤 Procedure가 실패했는지 판단하고 로그를 기록합니다:

   ```csharp
   if (!result.Success)
   {
       Log.Error($"Startup failed. Procedure: {result.FailedProcedureName}, Url: {result.FailedUrl}, Error: {result.ErrorMessage}");
   }
   ```

   Source: [ApplicationStartupEntry.cs](Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L45-L48)

## 일반적인 변형

| 시나리오 | 방법 |
|------|------|
| 로그 또는埋点만 추가하고 싶은 경우 | `OnEnter` / `OnLeave`를 재정의하고, 내부에서 `Log.Info`만 호출하며 IO를 수행하지 않습니다. |
| 비동기 네트워크 결과 대기가 필요한 경우 | `OnEnter`에서 `UniTask`를 반환하고, 내부에서 네트워크/리소스 로딩 메서드를 `await`합니다. |
| 시작 UI가 FairyGUI / UGUI를 사용하는 경우 | 프레임워크가 `ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI`를 통해 `LauncherUIResName`을 자동으로 전환하므로 Procedure에서 처리할 필요가 없습니다. |

## 일반적인 오류

- **`startupOptions`이 할당되지 않음**: 시작 진입점이 `Log.Error("StartupOptions is not assigned.")`를 출력한 후 바로 반환하며, 모든 Procedure가 실행되지 않습니다.
- **`OnLeave` 구현 잊어버림**: `OnEnter`에서 일종의 "시작 중" 상태로 진입한 경우, 후속 프로세스에서 올바른 컨텍스트를 가져오지 못할 수 있습니다. 최소한 `UniTask.CompletedTask`를 반환해야 합니다.
- **Procedure 순서 잘못 배치**: 로그인/리소스 검증을 핫 업데이트 이전에 배치하면, 핫 업데이트 실패 시 플레이어 컨텍스트를 가져올 수 없게 됩니다. "초기화 → 핫 업데이트 → 비즈니스 검증 → 메인 씬 진입" 순서로 정렬합니다.

## 배경(선택 사항)

`StartupRunner.Run`은 프레임워크 시작 체인의 통합 진입점으로, `StartupOptions`, UI 핸들러, 핫픽스 런처 세 부분을 받습니다. `startupOptions.ProcedureSettings`가 Procedure 체인의 토폴로지와 실행 순서를 결정하므로, 接入 작업은 사실상 선언적 설정이며 `StartupRunner` 내부 코드를 수정하는 것이 아닙니다.
