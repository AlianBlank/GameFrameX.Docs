# 상태 간 전환 방법

`FsmState<T>`를 상속하는 임의의 상태 클래스에서 `ChangeState<TState>(fsm)`을 호출하면 현재 FSM의 활성 상태가 즉시 전환되며, 프레임워크는 현재 상태의 `OnLeave`와 새 상태의 `OnEnter`를 순서대로 트리거합니다.

## 사전 조건

- `FsmComponent.CreateFsm(...)` 또는 `GameApp.Fsm.CreateFsm(...)`을 통해 대상 FSM이 생성되어 있고, 전환하려는 대상 상태가 매개변수로 전달되어 있어야 합니다.
- 대상 상태 타입은 반드시 `FsmState<T>`를 상속해야 하며, 여기서 `T`는 FSM의 제네릭 매개변수와 일치해야 합니다.

## 작업 단계

1. **상태 클래스 내부에서 전환 트리거**: `FsmState<T>` 파생 클래스 내부에서 protected로 선언된 `ChangeState<TState>(IFsm<T> fsm)`을 호출합니다.

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

2. **상태 외부에서 트리거해야 할 때**: `FsmState<T>`의 public 메서드인 `ChangeToState<TState>(IFsm<T> fsm)`를 사용하면, 내부적으로 `ChangeState<TState>(fsm)`로 전달됩니다.

   ```csharp
   fsm.CurrentState.ChangeToState<MoveState>(fsm);
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L119)

3. **대상 상태 타입만 알고 있을 때**: `Type` 오버로드를 사용하여 상태 클래스의 런타임 타입을 전달합니다.

   ```csharp
   ChangeState(fsm, typeof(MoveState));
   ```

   이 오버로드는 전달된 `Type`이 `FsmState<T>`에 할당 가능한지 검증하며, 그렇지 않으면 `GameFrameworkException("State type '{0}' is invalid.")`을 발생시킵니다.  
   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

4. **내부 실행 흐름**: `Fsm<T>.ChangeState(Type)`을 호출하면, 프레임워크는 먼저 이전 상태의 `OnLeave(this, false)`를 호출하고, `m_CurrentStateTime`을 재설정하며, `m_CurrentState`를 교체한 다음, 새 상태의 `OnEnter(this)`를 호출합니다.

   ```csharp
   m_CurrentState.OnLeave(this, false);
   m_CurrentStateTime = 0f;
   m_CurrentState = state;
   m_CurrentState.OnEnter(this);
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L726-L729)

## 일반적인 변형

- **문자열 이름으로 전환**: 먼저 `FsmComponent.HasState<T>(name)` 등의 이름 기반 API를 통해 상태를 찾은 다음, `Type` 오버로드를 사용하여 전환합니다. 이 저장소에서는 이름으로 직접 전환하는 public 제네릭 오버로드를 제공하지 않습니다.
- **체인 방식으로 여러 번 전환**: `OnEnter`에서 즉시 `ChangeState<NextState>(fsm)`를 호출하면 한 프레임 내에서 연쇄 전환이 가능합니다. 단, 무한 재귀를 피해야 합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GameFrameworkException: Current state is invalid.` | 아직 `Start<T>()`를 호출하지 않았거나 FSM이 이미 `Shutdown`된 상태에서 `ChangeState`를 호출함 | 먼저 `fsm.Start<IdleState>()`를 호출하여 FSM을 시작 |
| `FSM '...' can not change state to '...' which is not exist.` | 대상 상태 클래스가 `CreateFsm`의 `states` 배열에 전달되지 않음 | 대상 상태 인스턴스를 `CreateFsm(owner, new IdleState(), new MoveState())`에 추가 |
| `State type '...' is invalid.` | `Type` 오버로드를 통해 전달된 타입이 `FsmState<T>`의 파생 클래스가 아님 | 대상 타입이 `FsmState<T>`를 상속하고, `T`가 FSM과 일치하는지 확인 |
| 전환 후 `OnLeave` 알림을 받지 못함 | 전환이 `OnLeave` 이후에 작성되었거나 FSM이 이미 파괴됨 | 상태 생명주기 메서드 내에서 호출하고, FSM이 여전히 살아 있는지 확인 |

## 배경 (선택 사항)

`ChangeState<TState>`는 내부적으로 단순히 메서드만 전달하며, 실제 전환 로직은 `Fsm<T>.ChangeState(Type)`에 집중되어 있어 모든 오버로드가 동일한 `OnLeave → 타이머 재설정 → 교체 → OnEnter` 흐름을 따르도록 보장하여 분기 누락을 방지합니다.
