# DefaultPaymentManager 자리표시자 경고가 발생하면 어떻게 해야 하나요

Unity Console에서 `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).` 경고가 표시되면, 현재 `PaymentComponent`가 어느 채널(Google / Apple / WebGL / PC)의 결제 관리자도 찾지 못하고 자리표시자 구현인 `DefaultPaymentManager`로 폴백되었다는 의미입니다. 이것은 오류가 아니며, 자리표시자 구현은 경고만 출력하고 "미구현"을 반환할 뿐이지만, 모든 결제 호출이 실제로 동작하지는 않습니다. 해결 방법은 실행 플랫폼이 해당하는 채널 구현 타입에 정상적으로 매칭되도록 만드는 것입니다.

## 수정 단계

### 1. 현재 매칭되는 플랫폼 분기 확인

`PaymentComponent.Awake()`는 컴파일 매크로에 따라 구현 타입을 선택하며, 모든 매크로가 매칭되지 않을 때에만 `DefaultPaymentManager`로 떨어집니다:

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
            if (_paymentManager == null)
            {
                Log.Fatal("Pay Manager is invalid.");
                return;
            }
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L94)

위 표와 대조해 보면: 실기기 Android는 `UNITY_ANDROID`에, iOS는 `UNITY_IOS`에 매칭되어야 합니다. 채널 분기에 매칭되었는데도 경고가 계속 발생한다면 채널 타입 자체가 누락된 것입니다(3단계 참조).

### 2. 채널 타입 이름 설정 확인

`PaymentComponent`의 채널 타입 이름은 직렬화 필드이며, 기본값은 다음과 같습니다:

```csharp
private IPaymentManager _paymentManager;
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L23-L28)

Inspector에서 `PaymentComponent`가 부착된 오브젝트를 선택하고(컴포넌트 메뉴 경로 `GameFrameX/Payment`), 해당 플랫폼 필드가 잘못된 값으로 변경되지 않았는지 확인하세요. 수동으로 변경한 적이 있고 확실하지 않다면 위 표의 기본 전체 이름으로 복원하세요.

### 3. 해당 채널 결제 패키지 설치

기본 타입 이름은 독립된 채널 패키지의 클래스를 가리키며, 이 패키지는 인터페이스와 자리표시자 구현만 제공합니다:

| 플랫폼 매크로 | 예상되는 구현 타입 | 필요한 채널 패키지 |
|--------|----------------|------------|
| `UNITY_ANDROID` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` | Google 결제 패키지 |
| `UNITY_IOS` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple 결제 패키지 |
| `UNITY_WEBGL` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` | WebGL 결제 패키지 |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` | PC 결제 패키지 |
| `UNITY_STANDALONE_OSX` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple 결제 패키지 |
| 그 외(Editor 포함) | `GameFrameX.Payment.Runtime.DefaultPaymentManager` | 본 패키지에 기본 포함 |

채널 패키지가 설치되어 있지 않으면 `Utility.Assembly.GetType(componentType)`가 타입을 가져오지 못하므로, 런타임에는 자리표시자 구현만 얻게 되어 이 경고가 발생합니다. 채널 패키지를 설치한 후 Play 모드에 다시 진입하거나 다시 빌드하면 됩니다.

### 4. 로그 동작으로 자리표시자 구현 확인

자리표시자 구현의 메서드 동작은 다음과 같습니다(문제가 실제로 자리표시자 구현에서 발생하는지 역으로 확인하는 용도):

```csharp
public sealed class DefaultPaymentManager : BasePaymentManager
{
    private const string NotImplWarning = "You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).";

    public override void Init(bool isDebug = false, bool isClientVerify = false)
    {
        Log.Warning(NotImplWarning);
    }

    public override bool IsReady()
    {
        return false;
    }
```

Source: [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L17-L36)

나머지 메서드(`QueryPurchases`, `ConsumePurchase`, `BuyInApp`, `BuySubs`, `Buy`, `SetPredefinedProductIds`)도 `Init`와 마찬가지로 `Log.Warning(NotImplWarning)`만 출력합니다. [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L38-L81) 참조.

## 일반적인 변형

- **Editor에서 경고가 화면을 채우지 않게 하고 싶은 경우**: Editor 플랫폼 매크로는 `#else` 분기를 사용하므로 반드시 `DefaultPaymentManager`를 사용하며, 이 경고는 설정으로 제거할 수 없습니다. 로그 필터에서 해당 경고 텍스트를 차단하거나, 결제 인터페이스를 호출하기 전에 `IsReady()`로 가드를 설정하세요(자리표시자 구현은 항상 `false` 반환).
- **자체 서버/채널 연동**: `BasePaymentManager`를 상속하여 `IPaymentManager`의 추상 멤버를 구현하고(`Init`, `IsReady`, `SetPredefinedProductIds`, `QueryPurchases`, `ConsumePurchase`, `Buy` 계열, 추상 시그니처는 [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L61-L96) 참조), Inspector에서 해당 플랫폼의 `m_component*Type` 필드를 자신의 구현 클래스 전체 이름으로 변경하면 자리표시자 구현을 교체할 수 있습니다.

## 검증

1. Play 모드에 다시 진입하거나 다시 빌드하여 실행하면 Console에 더 이상 `You are using DefaultPaymentManager which is a stub. ...` 경고가 나타나지 않습니다.
2. `PaymentComponent.Init(...)`를 호출한 후 `IsReady()`를 호출하세요(컴포넌트가 관리자로 직접 전달됩니다. [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115) 참조): 자리표시자 구현은 항상 `false`이며, 채널 구현은 초기화 완료 후 준비되었을 때 `true`를 반환해야 합니다.
3. 테스트 결제를 한 번 시작해 보면 `OnPurchaseSuccess` / `OnPurchaseFailed` 이벤트 콜백이 발생해야 합니다. 자리표시자 구현에서는 이러한 이벤트가 절대 트리거되지 않습니다(`Raise*` 호출이 전혀 없음).

## 배경

`DefaultPaymentManager`는 프레임워크가 Editor 및 인식되지 않는 플랫폼에 대해 제공하는 폴백(fallback) 구현으로, 어떤 채널 패키지도 연동되지 않은 상태에서도 게임이 컴파일 및 시작될 수 있도록 보장하며, 결제 인터페이스를 잘못 사용할 때마다 경고 형태로 개발자에게 채널 구현을 통합하도록 알려줍니다(CHANGELOG에도 "모든 메서드에 미구현 경고 로그 추가", "`IsReady()`가 `false` 반환"이라는 두 가지 동작이 명확히 기록되어 있습니다). 구현 선택은 전적으로 컴파일 매크로와 직렬화 타입 이름으로 결정되며 런타임 환경과는 무관하므로, 설정을 수정하거나 패키지를 설치하는 것만으로 해결할 수 있고 프레임워크 코드를 변경할 필요가 없습니다.
