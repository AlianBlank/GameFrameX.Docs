# IL2CPP ビルド後に API が削除される場合は

IL2CPP バックエンドは、マネージドバイトコードリンカー（Unity Linker / IL2CPP stripping）によって、「コードから直接参照されていない」型やメンバーを削除します。IL2CPP でパッケージ化した後に本ライブラリの API を呼び出した際に、`MissingMethodException`、`NullReferenceException` が発生したり、「Editor では正常に動作するものの、ビルド後は動作しない」といった現象が起きた場合、削除が原因です。このページでは、迅速な診断と修復方法を説明します。

## 迅速な診断

| 症状 | 原因 | 修復方法 |
|------|------|------|
| Editor / Mono ビルドでは正常だが、IL2CPP ビルド後に `MissingMethodException: void BlankReadAssets::xxx` が発生する | リンカーがリフレクション / 動的呼び出しのエントリポイントを削除した | 依存パッケージに同梱されている `Runtime/link.xml` がパッケージに組み込まれていることを確認するか、任意の呼び出し元に `[Preserve]` を追加する |
| `BlankReadAssets.OpenRead` などの API の呼び出し結果が `null` になる、または null 参照例外が発生するが、リンカーからエラーは報告されない | 名前空間 / 内部クラスが削除され、実装の分岐が空の実装に置き換えられた | `link.xml` が `GameFrameX.ReadAssets.Runtime` 名前空間と `GameFrameX.ReadAssets.Runtime.ZipArchive` 名前空間をカバーしていることを確認する |
| パッケージ化後はすべてのプラットフォームで正常だが、Android IL2CPP の StreamingAssets 読み取り結果が空になる | `ApkImpl` / `LooseFilesImpl` の実装クラスが削除され、プラットフォーム分岐が実装なしのフォールバックに遷移した | Managed Stripping が有効になっていないか確認し、必要に応じて Player Settings で Strip Engine Code を無効にするか、`link.xml` を追加する |

## 修復手順

### 1. 依存パッケージ内の `link.xml` が存在し、パッケージに同梱されていることを確認する

本リポジトリでは、`Runtime/link.xml` で保持する必要のあるアセンブリと名前空間を明示的に宣言しています。Unity Linker はパッケージ化時にこれを自動的に読み取ります。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="BlankReadAssets.Runtime" preserve="all">
        <namespace fullname="GameFrameX.ReadAssets.Runtime" preserve="all"/>
        <namespace fullname="GameFrameX.ReadAssets.Runtime.ZipArchive" preserve="all"/>
    </assembly>
</linker>
```

Source: [Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/link.xml#L1-L7)

確認方法：`.apk` / `.ipa` / ビルド成果物を展開し、`*_Data/Managed` と同じ階層、または `Assets/` 配下に `link.xml` が存在し、その内容に `BlankReadAssets.Runtime` が含まれていることを確認します。UPM パッケージは、`package.json` の `samples` / 直接ファイル方式によってこのファイルをパッケージに組み込みます。

### 2. Player Settings の Strip レベルを確認する

`Project Settings → Player → Other Settings → Managed Stripping`：

| レベル | リスク | 推奨事項 |
|------|------|------|
| Disabled | 削除されませんが、パッケージサイズが大きくなります | 一時的な検証用 |
| Low | 明らかな未使用コードのみが削除されます | 通常は十分です |
| Medium / High | リフレクションや動的ロードの対象となるコードが削除される可能性があります | 必ず `link.xml` と併用する |

Managed Stripping を High に設定している場合は、手順 3 に進んでリフレクションの呼び出し元に `[Preserve]` を追加します。

### 3. 公開 API には `[Preserve]` が付与されており、新規に組み込むコードにも同様に付与できる

本ライブラリのすべての公開 API には `[Preserve]` が付与されています。以下に例を示します。

```csharp
[Preserve]
public static string Root
{
    get
    {
        EnsureInitialized();
        return BlankReadAssetsImpl.s_root;
    }
}

[Preserve]
public static void Initialize()
{
    BlankReadAssetsImpl.Initialize(Application.dataPath, Application.streamingAssetsPath);
    s_initialized = true;
}
```

Source: [Runtime/BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L37-L68)

ビジネス層でリフレクション（例：`Type.GetMethod("OpenRead")`）によって本ライブラリを呼び出す場合、Unity Linker からは呼び出し関係を認識できません。エントリポイントまたはラッパーメソッドに `[Preserve]` を追加することで、コードを保持できます。

```csharp
using UnityEngine.Scripting;

[Preserve]
public static Stream OpenAsset(string file)
{
    return BlankReadAssets.OpenRead(file);
}
```

### 4. カスタム link.xml によるフォールバック（唯一の手段としては非推奨）

プロジェクトの `Assets/link.xml` に以下を追加し、間接的に使用している名前空間も保持します。

```xml
<linker>
    <assembly fullname="YourGame" preserve="all"/>
</linker>
```

これは「特定のアセンブリをすべて保持する」ことを意味するため、最終手段としてのフォールバックとしてのみ使用し、長期的な依存は避けてください。

## 検証

修正を完了したら、次の順序で検証します。

1. **IL2CPP パッケージをローカルで再ビルドする**：`File → Build Settings → Player Settings → Other Settings → Configuration → Scripting Backend = IL2CPP` に設定し、Build And Run（または `Build`）を再実行します。
2. **Release ビルドで再現する**：Editor の IL2CPP バックエンドでは、パッケージ化後にのみリンカーが実行されるため、Editor では削除問題を再現できません。
3. **パッケージに残存するシンボルを確認する**：`il2cppdumper` / `ilspycmd` を使用して、`il2cpp.so` または `*_Data/Managed` 内の metadata を逆解析し、`BlankReadAssets` 型と呼び出しエントリポイントが残っていることを確認します。
4. **ログによるガードを追加する**：呼び出しの前後で `Debug.Log` を 1 行ずつ出力し、実行後に logcat / Player.log でエントリポイントまで処理が進んだか確認します。エントリポイントまで進んでいるにもかかわらずエラーが発生する場合、原因は削除ではなく、実行時のロジックにあります。

## 背景（オプション）

Unity Linkker はデフォルトで「コードからの直接参照」に基づいて削除を実行します。異なるアセンブリ間のリフレクション、`Activator.CreateInstance`、文字列名による型の検索では、呼び出しグラフが失われます。本ライブラリの `Runtime/link.xml` は、パッケージ化時に `BlankReadAssets.Runtime` アセンブリと `ZipArchive` 名前空間、および公開 API の `[Preserve]` を明示的に保持しており、二重の保護を実現しています。この 2 つが有効であれば、IL2CPP パッケージ化後に API が削除されることはありません。
