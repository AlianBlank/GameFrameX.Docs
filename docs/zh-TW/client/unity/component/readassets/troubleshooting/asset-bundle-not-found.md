# 載入 AssetBundle 時擲回 FileNotFoundException 的處理方式

呼叫 `BlankReadAssets.LoadAssetBundle` 或 `BlankReadAssets.LoadAssetBundleAsync` 時，若傳入的相對路徑未能對應到 StreamingAssets 中的任何資源，框架會直接擲回 `System.IO.FileNotFoundException("File not found", path)`。這是路徑解析失敗最常見的訊號。

## 快速診斷

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `FileNotFoundException: File not found`(訊息中包含傳入的 `path`)| 沒有任何檔案符合該路徑；常見原因為大小寫錯誤、斜線方向錯誤，或檔案未放置於 StreamingAssets 之下 | 先用 `FileExists` 預先檢查；統一使用以 `/` 為分隔符號的相對路徑；確認資源位於 `Assets/StreamingAssets/` 之下 |
| 在 Editor 中可正常運作，但建置後在 Android 裝置上失敗 | 資源被壓縮在 APK 內部，預設的 `AssetBundle.LoadFromFile` 無法讀取 | 呼叫 `BlankReadAssets.SetCompressedAssetBundleFileNames(...)` 註冊壓縮檔案清單 |
| 資源實際存在，卻在例外狀況擲回前被判定為不存在 | 路徑前綴寫成了 `StreamingAssets/xxx`,但框架已隱含移除該前綴 | 移除 `StreamingAssets/` 前綴，僅傳入相對子路徑 |

## 修正步驟

### 1. 先用 FileExists 預先檢查路徑

`BlankReadAssets.LoadAssetBundle` 內部會先呼叫 `GetInfoOrThrow`,若找不到檔案便會呼叫 `ThrowFileNotFound` 直接擲回例外狀況。先使用 `FileExists` 檢查，可快速判斷是路徑錯誤還是資源缺失：

```csharp
if (!BlankReadAssets.FileExists("ui/prefab/main.ab"))
{
    Debug.LogError("AssetBundle does not exist, please confirm it has been placed under StreamingAssets");
    return;
}
var bundle = BlankReadAssets.LoadAssetBundle("ui/prefab/main.ab");
```

原始例外狀況與觸發位置如下：

```csharp
private static void ThrowFileNotFound(string path)
{
    throw new FileNotFoundException("File not found", path);
}
```

來源:[BlankReadAssets.cs#L243-L246](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L243-L246)

### 2. 路徑必須是相對於 StreamingAssets 的子路徑，並使用 `/`

框架的 `LooseFilesImpl.TryGetInfo` 會將傳入路徑與 `s_root` 串接，再呼叫 `File.Exists`:

```csharp
var fullPath = s_root + path;
if ( !File.Exists(fullPath) )
{
    return false;
}
info.readPath = fullPath;
```

來源:[BlankReadAssets.LooseFilesImpl.cs#L57-L71](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L57-L71)

- 正確:`"ui/prefab/main.ab"`(對應到 `Assets/StreamingAssets/ui/prefab/main.ab`)
- 錯誤:`"StreamingAssets/ui/prefab/main.ab"`、`"ui\\prefab\\main.ab"`、絕對路徑
- 區分大小寫：Android 裝置的檔案系統會嚴格區分大小寫

### 3. 識別 APK 內的壓縮 AssetBundle

`AssetBundle.LoadFromFile` 預設只能讀取 APK 內未壓縮的檔案。若你的建置流程會將 `.ab` 檔案壓縮進 APK,需要在使用前註冊壓縮檔案清單；否則底層的 `LoadFromFile` 會擲回 `FileNotFoundException` 或回傳損壞的 bundle。註冊方式請參閱 `BlankReadAssets.SetCompressedAssetBundleFileNames`。此進入點透過 `AndroidIsCompressedFileStreamingAsset` partial 方法，讓宿主專案注入實際的檔案名稱清單：

```csharp
// 在宿主專案中依需求擴充
BlankReadAssets.SetCompressedAssetBundleFileNames(
    "ui/prefab/main.ab",
    "ui/prefab/login.ab"
);
```

來源:[BlankReadAssets.cs#L248](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L248)

### 4. 載入進入點

載入介面的簽章如下。例外狀況只會在路徑解析階段擲回；實際的 bundle 讀取失敗則是由 Unity 內部擲回：

```csharp
public static AssetBundleCreateRequest LoadAssetBundleAsync(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFileAsync(info.readPath, crc, (ulong)info.offset);
}

public static AssetBundle LoadAssetBundle(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFile(info.readPath, crc, (ulong)info.offset);
}
```

來源:[BlankReadAssets.cs#L119-L130](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L119-L130)

若 `GetInfoOrThrow` 找到了檔案，但 `AssetBundle.LoadFromFile` 仍然失敗，問題就出在建置產物本身(CRC 不符、offset 錯誤、已壓縮等)，需要回到建置端調查。

## 驗證

1. 在呼叫 `LoadAssetBundle` 之前，先呼叫 `BlankReadAssets.FileExists(path)`;預期回傳值為 `true`。
2. 對於在 Editor 中可正常載入的路徑，請原封不動地複製到裝置上：大小寫、分隔符號與目錄層級必須完全一致。
3. 在 Android 裝置上，若 `FileExists` 回傳 `true` 但載入仍失敗，請檢查 `.ab` 檔案是否在 APK 內被壓縮；若是，需要先用 `SetCompressedAssetBundleFileNames` 註冊。
