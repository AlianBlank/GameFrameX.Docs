# What to Do When Async Image Loading Fails

If the image does not display after calling `UIImage.icon` or `Image.SetIconAsync(...)`, the console shows a `Failed to load icon '<path>': ...` error, or the image only takes effect in the editor and is lost after packaging, follow the steps on this page to troubleshoot.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Console outputs `Failed to load icon 'xxx': ...` | `AssetComponent.LoadAssetAsync` throws an exception or the asset does not exist | See "Asset Path Errors" |
| Image is still blank after assigning `icon` | Asset was not included in the YooAsset package manifest | See "Asset Not Included in the YooAsset Manifest" |
| Works in the editor, image lost at runtime | Runtime is using editor-only assets (e.g. `AssetDatabase`) | See "Editor / Runtime Asset Separation" |
| Icon displays but is stretched/clipped incorrectly | `SetIconAsync` rebuilds the Sprite with `Rect(0,0,w,h)`, ignoring the source image's border | See "Sprite Border and 9-Slice Loss" |
| Old texture still resides in memory after switching `icon` | The `using` inside `SetIconAsync` has released the handle, but the old Sprite is not explicitly destroyed | See "Memory Leaks and Handle Release" |

## Fix Steps

### Asset Path Errors

`SetIconAsync` internally uses `AssetComponent.LoadAssetAsync<Texture2D>(icon)`; the path must exactly match the `Location` in the YooAsset manifest (case-sensitive, and without the file extension).

```csharp
[UnityEngine.Scripting.Preserve]
public static async Task SetIconAsync(this UnityEngine.UI.Image self, string icon)
{
    try
    {
        var assetComponent = GameEntry.GetComponent<AssetComponent>();
        using (var valueHandle = await assetComponent.LoadAssetAsync<Texture2D>(icon))
        {
            if (valueHandle.IsDone && valueHandle.Status == EOperationStatus.Succeed)
            {
                var texture2D = valueHandle.GetAssetObject<Texture2D>();
                self.sprite = Sprite.Create(texture2D, new Rect(0, 0, texture2D.width, texture2D.height), new Vector2(0.5f, 0.5f));
            }
        }
    }
    catch (System.Exception e)
    {
        Log.Error($"Failed to load icon '{icon}': {e.Message}");
    }
}
```

Source: [UGUIImageExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIImageExtension.cs#L56-L74)

Fix actions:

1. In the YooAsset asset management window (e.g. `Asset Bundle Collector`), search for the `icon` string and confirm that it exists as a `Texture2D`-typed Location.
2. Remove the file extension (e.g. write `Assets/UI/Icons/coin` instead of `.png`).
3. Debug once by passing the same string directly to `AssetComponent.LoadAssetAsync<Texture2D>` and see whether it still throws an exception.

### Asset Not Included in the YooAsset Manifest

The `UIImage.icon` setter performs runtime asset loading through `SetIconAsync`:

```csharp
[UnityEngine.Scripting.Preserve]
public string icon
{
    get { return m_icon; }
    set
    {
        if (m_icon != value)
        {
            m_icon = value;
            _ = this.SetIconAsync(m_icon);
        }
    }
}
```

Source: [UIImage.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIImage.cs#L60-L71)

Fix actions:

1. Open the YooAsset collector and confirm that the directory containing the icons is covered by a collection rule.
2. Rebuild the asset bundles, hot-update to the target platform, then launch the game.

### Editor / Runtime Asset Separation

`UIImage` is a script component that inherits from `UnityEngine.UI.Image` and can only be swapped in via a menu inside the editor:

```csharp
[CustomEditor(typeof(UnityEngine.UI.Image))]
public class UIImageReplaceHandler : UnityEditor.Editor
{
    [MenuItem("CONTEXT/Image/Replace To UIImage(替换为UIImage)", false, 10)]
    static void Run()
    {
        ...
    }
}
```

Source: [UIImageReplaceHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UIImageReplaceHandler.cs#L39-L76)

If you use `Resources.Load` directly at runtime to fetch editor paths, it will fail. Fix action: make sure all icons come from YooAsset's runtime manifest; do not mix in `Resources/` or editor built-in assets.

### Sprite Border and 9-Slice Loss

`SetIconAsync` constructs the Sprite directly with `Sprite.Create(texture2D, new Rect(0,0,w,h), ...)` and does not read the original Sprite's `border`. Fix action: if the source image is 9-sliced, switch to a `Sprite`-typed prefab in the `AssetBundle` instead of creating it at runtime via the `icon` string.

### Memory Leaks and Handle Release

`SetIconAsync` already uses `using (var valueHandle = ...)`, so the handle is returned automatically; however, if you switch `icon` multiple times, the old `Sprite` still hangs on the new `Texture2D` and may be considered still referenced. Fix action: manually set `self.sprite = null` before switching, so the old Sprite has no references and is garbage-collected together with the `Texture2D`.

## Verification

1. Assign `UIImage.icon` again and confirm the console no longer outputs `Failed to load icon`.
2. In the YooAsset asset browser, drag the same `Location` onto `UIImage.icon` and check that an image appears in the `Sprite Renderer` panel.
3. Profiler → Memory → Texture: confirm that the old texture's reference count drops to zero after switching.
4. After packaging for the target platform, run the same flow again on a real device.

## Background (Optional)

`UIImage` only adds an `icon` property to `UnityEngine.UI.Image`; the actual loading logic all goes through `UGUIImageExtension.SetIconAsync`, which calls YooAsset's async API via `GameEntry.GetComponent<AssetComponent>()` and only logs (without throwing) on failure.
