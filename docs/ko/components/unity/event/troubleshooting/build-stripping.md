# 빌드 후 이벤트 타입이 스트리핑되어 작동하지 않는 경우 해결 방법

Editor에서는 정상적으로 실행되지만, IL2CPP로 빌드한 후(특히 Managed Stripping Level을 Medium/High로 설정한 경우) 이벤트를 트리거해도 콜백이 실행되지 않거나 타입 이름 리플렉션으로 이벤트 타입을 가져올 수 없는 문제—이는 거의 대부분 매니지드 코드 스트리핑이 "문자열/리플렉션으로만 참조되는" 이벤트 타입을 삭제했기 때문입니다. 본 모듈의 핵심 타입은 이미 `GameFrameXEventCroppingHelper`와 `[Preserve]`로 보호되어 있으며, 직접 정의한 커스텀 `EventArgs` 타입은 아래 내용에 따라 보호를 추가해야 합니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| `Fire` 이후 구독한 콜백이 실행되지 않음, Editor에서는 정상 작동 | 커스텀 이벤트 `EventArgs` 타입이 스트리핑되어 `Type.FullName`을 해석할 수 없음 | 단계 1: 커스텀 이벤트 클래스에 `[Preserve]` 추가 |
| `Utility.Assembly.GetType(componentType)`로 구현 타입을 가져올 수 없어 컴포넌트 초기화 실패 | 구현 타입이 문자열로만 참조되어 linker에 의해 제거됨 | 단계 2: 스트리핑 보호 Helper가 씬/어셈블리에 존재하는지 확인 |
| 초기 패키지/핫업데이트 어셈블리의 모든 이벤트 타입이 전체적으로 작동하지 않음 | 어셈블리 전체가 스트리핑됨 | 단계 3: `link.xml`로 어셈블리 전체 보존 |
| 일일이 점검하고 싶지 않음 | 단지 빠르게 사용 가능하게 복구하고 싶음 | 단계 4: Managed Stripping Level 낮추기 |

## 해결 단계

### 1. 커스텀 이벤트 클래스에 `[Preserve]` 추가 (권장)

모듈의 이벤트 기반 클래스 자체가 이 방식으로 보호되고 있으므로, 이를 참고하여 각 커스텀 이벤트 클래스에 특성을 추가하세요:

```csharp
namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// 게임 로직 이벤트 기반 클래스.
    /// </summary>
    [UnityEngine.Scripting.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

이벤트 ID는 타입 전체 이름 문자열에 의존합니다(예: `EmptyEventArgs`는 내부적으로 `typeof(EmptyEventArgs).FullName`을 `_eventId`로 사용). 타입이 한번 스트리핑되면 구독과 트리거의 ID가 서로 일치하지 않게 되므로, 타입이 삭제되지 않도록 반드시 보장해야 합니다. [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L15-L21)를 참고하세요.

### 2. 모듈 내장 스트리핑 보호 Helper 적용 확인

모듈에는 참조 보호 컴포넌트가 내장되어 있어, 빌드 시 해당 어셈블리가 컴파일에 포함되기만 하면 핵심 타입은 스트리핑되지 않습니다:

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Event.Runtime
{
    [Preserve]
    public class GameFrameXEventCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(EventManager);
            _ = typeof(EventComponent);
            _ = typeof(GameEventArgs);
            _ = typeof(IEventManager);
        }
    }
}
```

Source: [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs#L1-L18)

점검 시 다음 두 가지를 확인하세요:

1. `GameFrameX.Event.Runtime` 어셈블리가 통째로 잘리지 않았는지 확인하세요(단계 3의 안전망 방안 참고).
2. 직접 추가한 타입은 위의 참조 목록에 없으므로, 여전히 단계 1에 따라 개별적으로 `[Preserve]`를 추가해야 합니다.

또한 `EventComponent`는 초기화 시 `Utility.Assembly.GetType(componentType)`를 사용해 문자열로 구현 타입을 해석하는데, 이 단계가 스트리핑에 가장 민감합니다. [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L67-L69)를 참고하세요.

### 3. `link.xml`로 어셈블리 전체 보존 (안전망)

`Assets` 하위 임의의 위치(예: `Assets/StreamingAssets`가 아닌 일반 디렉터리)에 `link.xml`을 새로 생성하고, 런타임 어셈블리를 전체 보존한 뒤 커스텀 이벤트가 포함된 어셈블리도 함께 추가하세요:

```xml
<linker>
  <assembly fullname="GameFrameX.Event.Runtime" preserve="all"/>
  <!-- 커스텀 이벤트 타입이 포함된 어셈블리, asmdef 이름으로 작성하세요 -->
  <assembly fullname="YourGame.Logic" preserve="all"/>
</linker>
```

어셈블리 이름은 저장소의 asmdef를 기준으로 합니다: 런타임 어셈블리 파일은 `Runtime/GameFrameX.Event.Runtime.asmdef`, 에디터 어셈블리는 `Editor/GameFrameX.Event.Editor.asmdef`입니다.

### 4. Managed Stripping Level 낮추기

`Project Settings → Player → Other Settings → Optimization → Managed Stripping Level`을 `Minimal` 또는 `Low`로 조정하세요. 스트리핑 강도가 낮아지면 대부분의 "문자열 참조가 삭제되는" 문제가 사라집니다. 대신 패키지 크기가 커지는 비용이 있으므로, 근본 원인이 스트리핑인지 빠르게 검증하는 용도로만 사용할 것을 권장합니다.

## 검증

1. 실기기 빌드를 다시 수행하세요(Editor는 스트리핑을 트리거하지 않으므로, 실제 빌드로 검증해야 합니다).
2. 씬에서 이벤트를 하나 구독하고 `Fire`하여 콜백이 실행되는지 확인하세요.
3. 이벤트 카운트 인터페이스로 프로그래밍 방식 검증도 가능합니다: `EventManager`는 `EventHandlerCount`, `EventCount` 속성과 `Count(string id)` 메서드를 제공하며, 구독 성공 후 해당 ID의 핸들러 수는 0보다 커야 합니다. [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L54-L65)와 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L98-L102)를 참고하세요.

## 배경

본 모듈의 이벤트는 "타입 전체 이름 문자열"을 ID로 사용하며, 구독, 트리거, 컴포넌트 구현 해석이 모두 문자열/리플렉션 경로를 거칩니다. IL2CPP의 매니지드 linker는 정적으로 보이는 참조만 추적하고 이러한 동적 참조는 볼 수 없으므로, 관련 타입을 "미사용"으로 판단하여 삭제합니다. `[Preserve]` 특성과 `link.xml`은 모두 linker에게 "이 타입은 반드시 보존해야 함"을 선언하는 표준 수단이며, `GameFrameXEventCroppingHelper.Start`의 명시적인 `typeof(...)` 참조도 같은 원리입니다.
