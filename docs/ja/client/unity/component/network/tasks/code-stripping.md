# ビルド時のコードストリッピングへの対処

Player Settings で **Managed Stripping Level**(特に High/Medium)を有効にした場合、または IL2CPP でビルドした後に、`NetworkComponent` やネットワークイベントクラスの欠落、`CreateNetworkChannel` での `MissingMethodException` / `TypeLoadException` といった問題が発生した場合、通常は Unity のマネージドコードストリッピングによって、静的に参照されていない型/メソッドが削除されていることが原因です。本パッケージは重要な型に `[UnityEngine.Scripting.Preserve]` を付与しており、ほとんどの場合は追加の対応は不要です。削除されるのは通常、あなた自身のプロジェクトでリフレクション/文字列によって登録している部分なので、以下の手順で保護を追加してください。

## 前提条件

- Unity のバージョンが 2019.4 以上であること(本パッケージの `package.json` で宣言されている最低バージョン)。
- `com.gameframex.unity.network`(現在のバージョン 2.6.10)およびその依存パッケージ `com.gameframex.unity`、`com.gameframex.unity.event`、`com.gameframex.unity.litjson` がインストール済みであること。
- ビルドターゲットプラットフォームが IL2CPP を使用している、または Player Settings で Managed Stripping Level(Low/Medium/High)が有効になっていること。

## 操作手順

1. まず、パッケージに同梱の保護が有効になっているかを確認します。本パッケージは、エントリコンポーネントと公開 API に一つずつ `[UnityEngine.Scripting.Preserve]` を付与しています。例えば `NetworkComponent` クラス自体：

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Network")]
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkComponent : GameFrameworkComponent
   ```
   出典:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L42-L45)

   公開メソッド(`CreateNetworkChannel`、`GetNetworkChannel` など)にも同様に `[Preserve]` が付与されています:

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   ```
   出典:[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L176)

   ネットワークイベント引数クラスにもすべて `[Preserve]` が付与されています(これらのクラスはイベントシステムによって型単位で配信されることが多く、ストリッピングされやすいです):

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkConnectedEventArgs : GameEventArgs
   ```
   出典:[NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L40-L41)

   同様に `NetworkClosedEventArgs`、`NetworkErrorEventArgs`、`NetworkMissHeartBeatEventArgs`、および `NetworkManager.HeartBeatState` のパラメータなしコンストラクタ(フレームワーク内部でリフレクションにより状態オブジェクトを生成します)も同じ処理が施されています:
   出典:[NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L43-L45)

2. **Edit → Project Settings → Player → Other Settings → Optimization → Managed Stripping Level** を開き、現在のストリッピングレベルを確認します。散発的に型が失われるだけの場合は、まずレベルを **Low(または Minimal)** に下げてビルドし、問題が確かにストリッピングに起因することを確認してください。

3. **あなた自身のプロジェクト**でストリッピングされた型を確認します。よくストリッピングされ、かつ本パッケージでは保護できないもの：
   - あなたが実装した `INetworkChannelHelper` の派生クラス(送信/受信パケットのヘッダーとボディのハンドラー);
   - `NetworkComponent` を通じて登録したが、文字列/リフレクションでのみ参照されるメッセージハンドラー;
   - シリアライズ用のデータモデル(LitJSON 関連の DTO など)。

4. 上記の独自型に対しては、クラスと公開メンバーに `[UnityEngine.Scripting.Preserve]` を付与することを優先してください(パッケージ内のやり方と同じです):

   ```csharp
   // あなたのプロジェクトでの記述例:属性の使用方法はパッケージ内の NetworkComponent と同じです
   [UnityEngine.Scripting.Preserve]
   public sealed class MyNetworkChannelHelper : INetworkChannelHelper
   {
       ...
   }
   ```

5. ストリッピングされる型が多数あり、一つずつ属性を付与するのが現実的でない場合は、プロジェクトの `Assets/` 配下に `link.xml` を新規作成し、アセンブリ単位で丸ごと保持します(これは Unity 公式の仕組みです。**本リポジトリには link.xml は同梱されていません**。使用側のプロジェクトで各自作成する必要があります):

   ```xml
   <linker>
     <!-- ネットワークアセンブリ全体を保持 -->
     <assembly fullname="GameFrameX.Network.Runtime" preserve="all"/>
     <!-- あなた自身のビジネス/プロトコルアセンブリを保持 -->
     <assembly fullname="YourAssemblyName" preserve="all"/>
   </linker>
   ```

6. 再ビルドし、ビルドログに `MissingMethodException`/`TypeLoadException` がないことを確認した上で、以下の「検証」セクションに従って実機での接続テストを一度行ってください。

## 検証

- ビルド後に実行し、シーンにアタッチされた `NetworkComponent`(メニューパス GameFrameX/Network)が正常に作成できること;
- `CreateNetworkChannel` の呼び出しで返されたチャンネルが接続を完了でき、`NetworkConnectedEventArgs` イベントを受信できること;
- ハートビートロジックが正常に動作すること(`HeartBeatState` がストリッピングされていないことを示します)。ネットワーク切断時に `NetworkMissHeartBeatEventArgs`/`NetworkErrorEventArgs` を受信できること。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| ビルド後に `TypeLoadException`/`MissingMethodException` が発生するが、エディターでは正常 | Managed Stripping により、リフレクションでのみ参照される型が削除された | Managed Stripping Level を下げる、または該当する型に `[UnityEngine.Scripting.Preserve]` を付与する |
| ハートビート状態オブジェクトの作成に失敗する | `HeartBeatState` のパラメータなしコンストラクタがストリッピングされた(フレームワーク内部でリフレクションにより生成) | パッケージ内では既に `[Preserve]` を付与済み。このファイルを fork/変更した場合は、この属性を必ず残すこと |
| `NetworkConnectedEventArgs` などのネットワークイベントを受信できない | イベント引数クラスがストリッピングされ、イベントシステムの逆シリアル化に失敗 | パッケージ内では既に `[Preserve]` を付与済み。fork による上書きや、独自の EventArgs への付与漏れがないか確認 |
| 独自の `INetworkChannelHelper` 派生クラスのメソッドが失われる | あなたのプロジェクトの型が静的に参照されていない | Helper クラスに `[Preserve]` を付与するか、link.xml を作成する |
| link.xml を追加してもストリッピングされる | ファイルが `Assets/` 内にない、または XML フォーマットのエラー | パスと `assembly fullname` のスペルを確認(asmdef 内のアセンブリ名を参照) |

## 背景

Unity は IL2CPP/High Stripping でのビルド時に、マネージドコードのエントリから静的に到達不可能な型とメンバーを削除します。ネットワークフレームワークは「インターフェース + リフレクション + イベント配信」のパターンを多用しています——例えば `INetworkManager` インターフェースを通じて実装を特定したり、イベントシステムを通じて `NetworkConnectedEventArgs` などの引数クラスを型単位で配信したりします——これらの参照はストリッパーからは見えないため、本パッケージはこれらの重要な箇所に一つずつ `[UnityEngine.Scripting.Preserve]` を付与しています(上記の手順 1 で参照しているソースコードを参照)。これによりパッケージ内のすべての公開型をカバーできますが、あなたのプロジェクト側でリフレクションによって登録される型はカバーできないため、そのような型は同じ方法で各自保護する必要があります。
