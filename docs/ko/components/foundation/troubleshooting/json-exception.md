# JSON 직렬화 예외 및 역직렬화 실패怎么办

`JsonHelper.Serialize`, `Deserialize` 또는 `TryDeserialize`가 예외를 발생시키거나, `false`를 반환하거나, 반환된 결과가 예상과 다를 때는 이 페이지의 진단 표에서 해당하는 항목을 찾아 구체적인 예외 메시지에 따라 적절한 수정 단계를 선택하세요. `JsonHelper`에서 제공하는 `Try*` API와 `JsonHelperError`는 예외를 발생시키지 않고도 오류 분류를 알려주므로, 문제를 파악할 때 우선적으로 사용하세요.

## 수정 단계

### 수정 1: 매개변수가 null 또는 빈 문자열

`JsonHelper`의 `Serialize` / `Deserialize` / `TryDeserialize`는 모두 먼저 매개변수 검증을 수행합니다. `Serialize`는 `obj`가 null일 때 직접 `ArgumentNullException`을 발생시키고, `Deserialize`는 `json`이 null이거나 빈 문자열 또는 순수 공백일 때 `ArgumentNullException` 또는 `ArgumentException`을 발생시킵니다. `TryDeserialize`는 예외를 발생시키지 않고 `false`를 반환하며 `JsonHelperError`를 제공합니다.

```csharp
using GameFrameX.Foundation.Json;

// 역직렬화 시 먼저 문자열 검증
if (string.IsNullOrWhiteSpace(json))
{
    return; // 또는 비즈니스 예외 발생
}

var user = JsonHelper.Deserialize<User>(json);
```

```csharp
using GameFrameX.Foundation.Json;

// 권장: 예외 오버헤드를 피하기 위해 TryDeserialize 사용
if (JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    // 성공
}
else if (error.Kind == JsonHelperErrorKind.InvalidInput)
{
    // 매개변수가 유효하지 않음
}
```

### 수정 2: JSON은 유효하지만 대상 타입과 일치하지 않음

일반적인 증상: `JsonException`에 `The JSON value could not be converted to <type>` 또는 `is not a valid value for <type>`이 포함됨. 일반적인 원인은 다음과 같습니다:

- 필드가 `int`이지만 JSON에서는 문자열 `"123"`임 (`AllowReadingFromString`이 활성화되지 않으면 실패하지만, `DefaultOptions`에서는 이미 활성화되어 있음).
- 필드가 `DateTime`이지만 JSON에서는 `"2024-01-01T00:00:00Z"`이고 시간대가 일치하지 않음.
- 필드가 `Guid`이지만 JSON에서는 빈 문자열이거나 따옴표가 누락됨.
- 다형성 타입: JSON이 하위 클래스이고 부모 클래스 필드에 `[JsonDerivedType]` 메타데이터가 없음.

수정 권장 사항:

1. `JsonHelper.DefaultOptions`를 사용하는지 확인 (`PropertyNameCaseInsensitive`, `AllowReadingFromString`, `AllowNamedFloatingPointLiterals`, `AllowTrailingCommas`가 이미 활성화되어 있음).
2. 의심스러운 JSON을 단독으로 `JsonHelper.Deserialize<Dictionary<string, object>>(json)`에 붙여넣어 구문이 유효한지 확인.
3. 문제가 발생하기 쉬운 `DateTime`/`Guid`/`decimal` 필드의 경우 DTO에 명시적으로 `[JsonConverter]`를 표시하거나 문자열 형식이 올바른지 확인.
4. 다형성 타입에는 `[JsonDerivedType(typeof(SubType), "sub")]`를 추가하고 JSON에 `"$type"` 필드를 포함.

```csharp
// 다형성 타입 예제
[JsonPolymorphic(TypeDiscriminatorPropertyName = "$type")]
[JsonDerivedType(typeof(Dog), "dog")]
[JsonDerivedType(typeof(Cat), "cat")]
public abstract class Animal { public string Name { get; set; } }

public class Dog : Animal { public string Breed { get; set; } }
```

### 수정 3: 열거형 값 또는 속성 이름 불일치

`JsonHelper.DefaultOptions`에는 내장된 `JsonStringEnumConverter`가 있어 열거형을 문자열로 직렬화합니다 (예: `0` 대신 `"Active"`). 커스텀 `JsonSerializerOptions`를 만들고 이 변환기를 추가하지 않으면 열거형이 숫자로 출력됩니다.

마찬가지로 `DefaultOptions`는 `PropertyNameCaseInsensitive = true`와 `PropertyNamingPolicy = null` (원래 속성 이름 유지)로 설정되어 있습니다. 직접 options를 새로 생성하면 이 두 스위치는 기본값이 false이므로, JSON의 필드 이름과 `PascalCase`로 엄격하게 일치시킵니다.

수정:

- 항상 `JsonHelper.DefaultOptions` 또는 `JsonHelper.CreateDefaultOptions()`를 통해 구성을 생성;
- `DefaultOptions`에서 `PropertyNamingPolicy`를 다시 설정하지 마세요. 그렇지 않으면 쓰기 측에서 대소문자가 변경됩니다.

```csharp
using GameFrameX.Foundation.Json;

// 권장 작성법
var opts = JsonHelper.CreateDefaultOptions();
var json = JsonHelper.Serialize(obj, opts);

// 역직렬화에도 DefaultOptions 또는 CreateDefaultOptions() 사용
var restored = JsonHelper.Deserialize<MyDto>(json, opts);
```

### 수정 4: 순환 참조

`System.Text.Json.JsonSerializer.Serialize`를 직접 호출하면 기본적으로 `InvalidOperationException` (`A possible object cycle was detected`)이 발생합니다. `JsonHelper.DefaultOptions`는 이미 `ReferenceHandler = ReferenceHandler.IgnoreCycles`로 설정되어 있어, 순환 참조가 발생할 경우 `$ref`와 같은 자리 표시자로 건너뜁니다.

수정: 항상 `JsonHelper` 진입점을 통해 직렬화를 수행하고, 우회하여 직접 `JsonSerializer.Serialize(obj)`를 호출하지 마세요.

```csharp
using GameFrameX.Foundation.Json;

// 올바름: 순환 참조가 자동으로 처리됨
var json = JsonHelper.Serialize(order); // order -> user -> orders -> ...

// 잘못됨: InvalidOperationException 발생
var raw = System.Text.Json.JsonSerializer.Serialize(order);
```

### 수정 5: NaN / Infinity 등 특수 부동 소수점 값

JSON이 Python(`json.dumps(... allow_nan=True)`) 또는 JavaScript에서 온 경우 `NaN` / `Infinity` / `-Infinity`를 포함할 수 있습니다. `System.Text.Json`은 기본적으로 `JsonException`을 발생시킵니다. `JsonHelper`는 `Deserialize<T>`에서 안전 장치를 마련했습니다: 예외를 포착한 후 `PreprocessSpecialFloatingPointValues`를 호출하여 문자열을 사전 처리하고 재시도합니다.

코드가 `JsonHelper`를 거치지 않고 직접 `JsonSerializer.Deserialize`를 호출하거나, 파싱 후 다른 단편을 다시 `Deserialize`해야 하는 경우 예외가 여전히 재현됩니다. `JsonHelper.Deserialize<T>(json)`을 일관되게 사용하세요.

```csharp
using GameFrameX.Foundation.Json;

// Python 출력: NaN / Infinity는 JsonHelper에 의해 자동으로 처리됨
var json = "{\"x\": NaN, \"y\": Infinity}";
var obj = JsonHelper.Deserialize<MyDto>(json); // 예외가 발생하지 않음
```

### 수정 6: 필드가 무시되거나 기본값으로 역직렬화됨

가능한 원인:

- 속성이 `private set` / `init`이고 `[JsonInclude]`가 없음.
- 속성이 `required`이지만 JSON에 필드가 누락됨.
- 속성이 `record` 주 생성자 매개변수이지만 `[JsonConstructor]`가 누락됨.
- 속성에 `[JsonIgnore]`가 표시되어 있음.
- 필드가 사전 / 컬렉션이지만 JSON은 배열이거나 그 반대임.

수정: DTO 속성이 쓰기 가능하고 반사를 통해 읽을 수 있는지 확인; 불변 타입에는 `[JsonConstructor]`를 추가; 비즈니스 필드에 `[JsonIgnore]`를 추가하지 마세요.

### 수정 7: TryDeserialize를 사용하여 오류 위치 파악

`TryDeserialize`는 절대 예외를 발생시키지 않으며, `JsonHelperError`를 통해 다음 정보를 알려줍니다:

| `Kind` | 의미 | 권장 처리 |
|--------|------|----------|
| `None` | 오류가 발생하지 않음 | 정상 경로 |
| `InvalidInput` | JSON 자체에 구문 오류가 있거나, null이거나, 빈 문자열이거나, options가 null임 | 매개변수를 확인하고, `JsonSerializer.Deserialize<JsonElement>`를 사용하여 JSON 구문 검증 |
| `TypeMismatch` | JSON은 유효하지만 필드 타입이 일치하지 않음 | [타입 불일치](#수정-2json은-유효하지만-대상-타입과-일치하지-않음)로 이동 |
| `Serialization` | 직렬화 단계 실패 (객체→JSON) | DTO에 직렬화할 수 없는 멤버 (포인터, COM 객체 등)가 있는지 확인 |
| `Unknown` | 분류되지 않은 오류, 일반적으로 런타임의 기타 예외 | `ExceptionType`과 `Message`를 읽고, `Path` / `LineNumber`를 통해 문제 위치 확인 |

`JsonHelperError`는 `Path`, `LineNumber`, `BytePositionInLine`도 제공하여 JSON의 구체적인 위치를 직접 찾을 수 있습니다:

```csharp
using GameFrameX.Foundation.Json;

if (!JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    Console.WriteLine($"Kind={error.Kind}, Type={error.ExceptionType.Name}");
    Console.WriteLine($"Message={error.Message}");
    Console.WriteLine($"Path={error.Path}, Line={error.LineNumber}, Pos={error.BytePositionInLine}");
}
```

### 수정 8: 스트림과 바이트 배열 작업

`SerializeAsync(Stream, ...)`는 `stream`이 null일 때 `ArgumentNullException` (`ArgumentNullException.ThrowIfNull(stream, nameof(stream))`)을 발생시킵니다. 쓰기 대상 스트림이 이미 `Dispose`된 경우에도 마찬가지로 실패합니다.

```csharp
using System.IO;
using GameFrameX.Foundation.Json;

await using var ms = new MemoryStream();
await JsonHelper.SerializeAsync(ms, user); // OK
var bytes = ms.ToArray();

// FileStream을 사용하는 경우 먼저 디렉토리가 존재하고 파일이 쓰기 가능한지 확인
await using var fs = File.Create("user.json");
await JsonHelper.SerializeAsync(fs, user);
```

## 검증

다음 순서대로 문제가 해결되었는지 확인:

1. `TryDeserialize`가 `true`를 반환하고, `error.Kind == JsonHelperErrorKind.None`임.
2. 역직렬화 후 객체 필드 값이 JSON의 문자열/숫자와 일치함 (출력하여 대조 가능).
3. 직렬화 후 다시 역직렬화하면 동일한 객체임 (`JsonHelper.Serialize(obj) → JsonHelper.Deserialize<T>(...) == obj`의 주요 필드가 같음).
4. 실패할 수 있는 매개변수 (빈 문자열, 비정상 JSON, NaN을 포함한 문자열)에 대해 각각 실행하여 예외가 발생하지 않는지 확인.

여전히 실패하는 경우 `JsonHelperError`의 `Path`, `LineNumber`, `Message`를 함께 티켓에 첨부하면 빠르게 문제를 파악할 수 있습니다.
