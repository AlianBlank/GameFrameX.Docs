# 如何正確取消註冊監聽器

正確取消註冊監聽器可以避免 MonoBehaviour 在被銷毀後仍被框架回呼，防止出現 NullReferenceException、記憶體流失和重複執行。本頁展示 GameFrameX Mono 模組提供的取消註冊 API 與使用規範。

## 前置條件

- 已透過 `GameFrameX.Mono.Runtime.MonoComponent` 或 `MonoManager` 註冊過監聽器
- 了解 C# 中 `Action` / `Action<T>` 委派的參考語意(取消註冊必須傳入同一實例)

## 操作步驟

### 1. 選擇對應的取消註冊 API

GameFrameX Mono 模組在 [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L120-L238) 中為每種生命週期事件都提供了成對的註冊 / 取消註冊方法：

| 生命週期 | 註冊方法 | 取消註冊方法 |
|---------|---------|---------|
| Update | `AddUpdateListener` | `RemoveUpdateListener` |
| FixedUpdate | `AddFixedUpdateListener` | `RemoveFixedUpdateListener` |
| LateUpdate | `AddLateUpdateListener` | `RemoveLateUpdateListener` |
| OnDestroy | `AddDestroyListener` | `RemoveDestroyListener` |
| OnApplicationPause | `AddOnApplicationPauseListener` | `RemoveOnApplicationPauseListener` |
| OnApplicationFocus | `AddOnApplicationFocusListener` | `RemoveOnApplicationFocusListener` |

### 2. 在 MonoBehaviour 的 OnDestroy / OnDisable 中取消註冊

取消註冊的建議位置是 `OnDestroy`(物件被銷毀時)或 `OnDisable`(物件被停用、銷毀前的統一時機)。將取消註冊寫在 `OnDestroy` 內，可確保監聽器在 GameObject 生命週期結束時被清理。

```csharp
using System;
using GameFrameX.Mono.Runtime;
using UnityEngine;

public class PlayerController : MonoBehaviour
{
    private Action<float, float> _onUpdate;
    private Action<float, float> _onLateUpdate;
    private Action _onDestroyCallback;

    private void OnEnable()
    {
        var monoComponent = MonoComponent.Instance;
        if (monoComponent == null) return;

        _onUpdate = HandleUpdate;
        _onLateUpdate = HandleLateUpdate;
        _onDestroyCallback = HandleDestroy;

        monoComponent.AddUpdateListener(_onUpdate);
        monoComponent.AddLateUpdateListener(_onLateUpdate);
        monoComponent.AddDestroyListener(_onDestroyCallback);
    }

    private void OnDestroy()
    {
        var monoComponent = MonoComponent.Instance;
        if (monoComponent == null) return;

        monoComponent.RemoveUpdateListener(_onUpdate);
        monoComponent.RemoveLateUpdateListener(_onLateUpdate);
        monoComponent.RemoveDestroyListener(_onDestroyCallback);
    }

    private void HandleUpdate(float elapse, float realElapse) { /* ... */ }
    private void HandleLateUpdate(float elapse, float realElapse) { /* ... */ }
    private void HandleDestroy() { /* ... */ }
}
```

來源： [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs) · [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L125-L136)

### 3. 取消註冊時傳入的委派必須與註冊時為同一個實例

`MonoManager` 的取消註冊實作是基於 `LinkedList<T>.Remove(action)` 的參考比較，因此傳入 `null`、匿名 lambda 或新方法都會失敗：

```csharp
// ✅ 正確:使用欄位儲存的同一個委派實例
monoComponent.RemoveUpdateListener(_onUpdate);

// ❌ 錯誤:新建立的 lambda,即使邏輯相同也無法匹配
monoComponent.RemoveUpdateListener((e, r) => HandleUpdate(e, r));

// ❌ 錯誤:傳入 null 會觸發例外狀況
monoComponent.RemoveUpdateListener(null);
```

取消註冊方法在傳入 `null` 時會擲回 `ArgumentNullException(nameof(action))`,見 [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L127-L131)。

## 常見變體

### 在 OnDisable 中依需求清理

如果物件會被反覆 Enable / Disable(例如集區化物件)，建議在 `OnDisable` 取消註冊，以便停用時立即停止回呼：

```csharp
private void OnDisable()
{
    if (_onUpdate != null)
    {
        MonoComponent.Instance?.RemoveUpdateListener(_onUpdate);
    }
}
```

### 直接使用 MonoManager(非 MonoComponent)

若不使用 `MonoComponent`,可以直接透過 `GameFrameworkEntry.GetModule<IMonoManager>()` 取得管理器進行取消註冊：

```csharp
var mono = GameFrameworkEntry.GetModule<IMonoManager>();
mono.RemoveUpdateListener(_onUpdate);
```

來源： [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs)

## 常見錯誤

- **未取消註冊監聽器導致 NullReferenceException**:物件銷毀後仍在 Update 佇列中，執行回呼時存取已銷毀物件的欄位會擲回例外狀況。務必在 `OnDestroy` / `OnDisable` 中取消註冊。
- **取消註冊時傳入不同的委派實例**:`LinkedList<T>.Remove` 按參考比較，新 lambda 或方法群組轉換會產生不同實例，導致取消註冊失敗。
- **多次註冊同一回呼**:`AddUpdateListener` 不會去重，重複加入同一欄位會讓回呼被執行多次；撤銷時也需要呼叫對應次數的 `RemoveUpdateListener`。
- **傳給取消註冊方法 `null`**:`MonoManager` 的所有 Remove 方法都會擲回 `ArgumentNullException`,取消註冊前需確保委派欄位非空。

## 背景(選用)

`MonoManager` 內部使用 `LinkedList<Action>` 儲存各類回呼，註冊時 `AddLast`、取消註冊時 `Remove(action)`,操作均在 `lock (Lock)` 內完成以確保執行緒安全。取消註冊失敗的本質原因是 `LinkedList<T>.Remove` 依賴參考相等性，這也是為什麼必須將委派儲存在欄位中、而非使用內嵌 lambda 的原因。
