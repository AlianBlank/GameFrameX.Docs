# クイックスタート

GameFrameX Setting を使えば、数分で Unity プロジェクトに型付きキーバリューストアを導入できます。インストールし、`SettingComponent` をシーンに配置して、`SetXxx` / `GetXxx` を呼び出すだけで、`bool` / `int` / `float` / `string` およびシリアライズ可能なオブジェクトを読み書きできます。

## 前提条件

- Unity 2019.4 以降。
- 依存パッケージ `com.gameframex.unity` 1.1.1。パッケージと共に自動解決されます。
- シーン内に `GameFramework` エントリが存在する必要があります(ランタイムは `GameFrameworkEntry.GetModule<ISettingManager>()` を通じてマネージャーを取得します)。

## インストール

Unity プロジェクトへのインストール方法は次のいずれかを選択してください:

1. `Packages/manifest.json` を編集し、scopedRegistries を追加:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.setting": "1.5.2"
     }
   }
   ```

2. `manifest.json` の `dependencies` に直接 Git 依存関係を追加:

   ```json
   {
     "com.gameframex.unity.setting": "https://github.com/gameframex/com.gameframex.unity.setting.git"
   }
   ```

3. Unity の `Package Manager` で **Add package from git URL** を使用し、上記の Git アドレスを貼り付けます。
4. リポジトリを Unity プロジェクトの `Packages` ディレクトリに直接配置すると、Unity が自動的に認識します。

## 操作手順

### 1. シーンに SettingComponent を追加

空の GameObject を作成し、コンポーネント **GameFrameX/Setting**(`SettingComponent`)を追加します。コンポーネントは `Awake` で自動的に `SettingManager` を作成し、永続化データを読み込みます。

コンポーネントにはデフォルトで `GameFrameXSettingCroppingHelper` が付属し、`[RequireComponent]` により必須となります。

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L43-L99)

### 2. ストレージバックエンドの選択

`SettingComponent` の 2 つのフィールドがストレージバックエンドを決定します:

| Inspector フィールド | 役割 | デフォルト値 |
|------|------|--------|
| `Setting Helper Type Name` | リフレクションで `ISettingHelper` のタイプフルネームを作成 | `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` |
| `Custom Setting Helper` | `SettingHelperBase` のサブクラスをシーンに直接ドラッグ | `null` |

利用可能な組み込みバックエンド:

- `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`(デフォルト)— Unity PlayerPrefs。抖音、微信、快手、支付宝ミニゲーム SDK に対応。
- `GameFrameX.Setting.Runtime.DefaultSettingHelper` — `Application.persistentDataPath` ベースのバイナリファイルストレージ。

切り替え方法:Inspector で `Setting Helper Type Name` フィールドを変更するか、`Custom Setting Helper` に独自の実装を指定します。

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L54)

### 3. 設定の書き込みと読み取り

`SettingComponent` が提供する型付き API を通じて設定を操作します。キーが存在しないかデータが破損している場合、`GetXxx` は渡されたデフォルト値を返し、警告を出力します(例外はスローされません)。

```csharp
using GameFrameX.Setting.Runtime;

SettingComponent setting = /* GetComponent または GameFramework エントリから取得 */;

// 設定の書き込み
setting.SetBool("FullScreen", true);
setting.SetInt("ResolutionWidth", 1920);
setting.SetFloat("Volume", 0.8f);
setting.SetString("PlayerName", "PlayerOne");

// 設定の読み取り(デフォルト値へのフォールバック付き)
float volume = setting.GetFloat("Volume", 0.5f);

// キーの存在確認
if (setting.HasSetting("PlayerName"))
{
    string name = setting.GetString("PlayerName");
}
```

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs) · [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L43-L73)

### 4. 永続化と削除

変更はデフォルトではメモリ内のみで有効で、`Save()` を呼び出した後にディスクに書き込まれます。削除操作は単一キーと全消去の両方をサポートしています。

```csharp
// ストレージへの永続化
setting.Save();

// 単一キーの削除
setting.RemoveSetting("PlayerName");

// すべての設定を消去
setting.RemoveAllSettings();
```

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

## よくあるバリエーション

- **シリアライズ可能なオブジェクトの保存** — `SetObject<T>(string, T)` / `GetObject<T>(string)` は内部的に JSON シリアライズを使用し、セーブデータや設定構造体に最適。
- **手動読み込み** — アプリ起動後に `setting.Load()` を呼び出して、保存先からすべての設定を再読み込み。
- **すべてのキー名を取得** — `setting.GetAllSettingNames()` は現在メモリ内にあるすべての設定キーの文字列配列を返します(注意:PlayerPrefs バックエンドはこの機能をサポートしていません)。
- **ミニゲームプラットフォーム** — 抖音、微信、快手、支付宝ミニゲームのビルドでは、PlayerPrefs バックエンドは自動的にプラットフォーム SDK のストレージにルーティングされます。`DefaultSettingHelper` は引き続き `Application.persistentDataPath` のファイル I/O を使用し、すべてのプラットフォームで一貫しています。

## よくあるエラー

| 症状 | 原因 | 回避方法 |
|------|------|----------|
| 起動後のログに `Setting manager is invalid.` と出力される | シーンに `GameFramework` エントリがないか、エントリが `SettingComponent` よりも先に初期化されていない | `GameFramework` の初期化完了後に `SettingComponent` を含むシーンを有効化する |
| `Log.Fatal` 後に設定が機能しない | `Awake` 段階で `ISettingManager` の取得に失敗した | `GameFramework` のコンポーネント链が完整か確認する |
| 変更後にゲームを再起動するとデータが失われる | メモリへの書き込み後に `Save()` が呼ばれていない | アプリ終了前または重要なタイミングで明示的に `setting.Save()` を呼び出す |
| カスタム Helper が機能しない | `Setting Helper Type Name` と実際のタイプフルネームが一致しない、または `Custom Setting Helper` が同時に設定されている | 優先度:`Custom Setting Helper` > `Setting Helper Type Name`。どちらか一方のみを選択 |
| 異なる言語環境で浮動小数点数の読み取り値が異常 | `SetFloat` は `CultureInfo.InvariantCulture` で書き込むが、読み取り側がローカライズされている | 常に `GetFloat` を使用し、基礎となる文字列を自分でデシリアライズしない |

## 背景(オプション)

`SettingComponent` は `GameFrameworkComponent` のサブクラスで、`Awake` 段階で `GameFrameworkEntry.GetModule<ISettingManager>()` を使って `SettingManager` を取得し、リフレクションまたはカスタムフィールドで `ISettingHelper` を作成して注入します。`SettingManager` はすべての `SetXxx` / `GetXxx` 呼び出しに対してキー名の検証を行い、空のキーに対しては `GameFrameworkException("Setting name is invalid.")` をスローします。データが破損した場合は `TryParse` を使用してデフォルト値にフォールバックし、`Log.Warning` を出力することで、実行が中断されないことを保証します。
