# 生成失敗/出現錯誤時的處理方法

執行 `gen-*.bat` / `gen-*.sh` 之後，若 Luban 擲出例外或未產生輸出檔案，請依照本頁的診斷表逐項確認。問題主要集中在腳本路徑、設定佔位符、Excel 表格結構這三種類型上。

## 快速診斷

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| `Could not find a part of the path ... Tools/Luban.dll` | 工具目錄不存在，或路徑撰寫錯誤 | 在儲存庫根目錄建立 `Tools/` 並放入 `Luban.dll`,或修正 `luban.conf` 中的 `toolPath` |
| `luban.conf not found` / `conf not loaded` | 目前目錄不正確，腳本未移動至儲存庫根目錄 | 在與 `Tools/` 同層的目錄執行腳本，或在腳本中以 `cd` 切換至設定檔所在的目錄 |
| 佔位符 `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` 未被展開 | `luban.conf` 內的兩個鍵值為空字串 | 將 `luban.conf` 內的 `UNITY_ASSETS_PATH` 與 `SERVER_PATH` 替換為絕對路徑 |
| 回報 `Excel ... __tables__.xlsx` 解析失敗 | 範本表頭損毀、欄位缺失，或多個表格合併錯誤 | 還原 `Excels/__tables__.xlsx`、`__beans__.xlsx`、`__enums__.xlsx`,且不要手動刪除欄位 |
| 回報 `Localization.xlsx not found` | 客戶端生成時在地化檔案被重新命名或缺失 | 指令中的 `localizationFileName` 預設為 `Localization.xlsx`,請視需要更改為儲存庫中的實際檔案名稱 |
| 指令瞬間結束，看不到錯誤 | 結尾缺少 `pause`(Windows) | 確認 `gen-*.bat` 的最後一行是否為 `pause`(可參考現有腳本) |
| 僅生成程式碼，未生成資料 | `dataTarget` 與 `codeTarget` 不一致，或 `outputDataDir` 的路徑無效 | 同時設定 `--dataTarget` 與 `--codeTarget`,並確認 `outputDataDir` 是否可寫入 |
| 回報 `validation failed` | 已設定 `--validationFailAsError true`,但資料未通過驗證 | 暫時移除 `--validationFailAsError true` 以確認具體警告，修正資料後再重新啟用 |

## 修正步驟

### 1. 找不到 Luban.dll

開啟 `luban.conf`,確認 `toolPath` 欄位:

```json
"toolPath": "/../Config/Tools/Luban.dll",
```

腳本實際上是以如下方式呼叫:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf
```

來源:[gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L2)

兩者必須一致：若腳本中撰寫的是 `./Tools/Luban.dll`,儲存庫中就必須存在 `Tools/Luban.dll`。如果您的專案將工具放置於 `Config/Tools/`,請同步修改 `toolPath` 與腳本中的路徑。

### 2. 佔位符未被展開

`luban.conf` 中預設將其設定為空字串:

```json
"UNITY_ASSETS_PATH": "",
"SERVER_PATH": "",
```

來源:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L62-L65)

`commands` 內的指令會參照這兩個變數，例如:

```json
"command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config"
```

來源:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L78)

直接執行腳本時，這些 `%XXX%` 將不會被展開，並在檔案系統層出現「路徑不存在」的錯誤。請先替換為您機器上的絕對路徑，再進行生成。

### 3. Excel 範本損毀

`luban.conf` 透過 `schemaFiles` 宣告了 4 個中繼資料表:

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

來源:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

若錯誤訊息中包含這 4 個檔案中的任一個，請先從儲存庫還原它們，接著確認 `Excels/Tables/` 與 `Excels/Local/` 之下的業務表格欄位名稱，是否與 `__tables__.xlsx` 的欄位一一對應。

### 4. 客戶端生成時找不到在地化表格

客戶端的指令附有獨立的 `localizationFileName`,預設期望的檔案名稱為 `Localization.xlsx`:

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

來源:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L72-L77)

若您重新命名了在地化表格(例如：儲存庫中只有 `L-Localization-UI.xlsx`、`L-Localization-成就.xlsx`、`L-Localization-文本.xlsx`),請將 `localizationFileName` 更改為實際的檔案名稱，或將表格名稱改回 `Localization.xlsx`。

### 5. 腳本瞬間結束而看不到錯誤

Windows 的所有 `gen-*.bat` 都應在結尾加上 `pause`:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf

pause
```

來源:[gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L3)

若從腳本中移除了 `pause`,錯誤訊息會隨著視窗關閉而消失，導致無法得知原因。請加上 `pause` 後再次執行。

### 6. 伺服器端二進位檔生成失敗

儲存庫提供的伺服器端 bin 生成腳本如下:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
pause
```

來源:[gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L2)

需要注意的是，此處雖名為 `gen-server-bin.sh`,但內容是 Windows 風格的 `dotnet ... && pause`,而且依賴相對路徑 `../Server/GameFrameX.Config/`。若出現路徑相關的錯誤，請確認以下事項：
- `Server/GameFrameX.Config/Json` 與 `Server/GameFrameX.Config/Config` 這兩個目錄存在且可寫入；
- 是在儲存庫根目錄下執行腳本，而非從其他目錄執行 `sh ./gen-server-bin.sh`。

## 驗證

完成上述修正後，請執行最小組態的指令，確認路徑是否可通：

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json \
  --xargs outputDataDir=./out/Json \
  --xargs outputCodeDir=./out/Config \
  --conf ./Luban.conf
```

若成功：
- `./out/Config/` 目錄下存在 `TablesComponent.cs` 等生成的程式碼；
- `./out/Json/` 目錄下存在 `Tb*.json` 資料檔案；
- 終端機中沒有例外的堆疊追蹤。

之後，請再次執行對應平台的腳本(如 `gen-server-json.bat` / `gen-client-json.sh` 等)，確認業務可端對端使用。
