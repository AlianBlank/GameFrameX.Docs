# Quick Start: Subscribe to Update per Frame

Register a callback through `MonoManager.AddUpdateListener`, and you will receive two parameters at the Update stage of each frame: `elapseSeconds` (elapsed time affected by time scaling) and `realElapseSeconds` (real elapsed time). No need to attach your own `MonoBehaviour` and write `Update()`.

## Prerequisites

- `MonoComponent` is already attached in the scene (menu `GameFrameX/Mono`), and the framework will automatically create the `MonoManager` module at startup.
- The business entry can obtain `IMonoManager`, typically through `GameFrameworkEntry.GetModule<IMonoManager>()`.

## Steps

1. Get the Mono manager instance.

```csharp
IMonoManager monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
if (monoManager == null)
{
    Log.Fatal("Mono manager is invalid.");
    return;
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L63)

2. Write an Update callback. The first parameter is elapsed time, and the second parameter is real elapsed time.

```csharp
void OnUpdate(float elapseSeconds, float realElapseSeconds)
{
    // Business logic, e.g., advance animations, poll state machines
}
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L41-L51)

3. Register the callback with `AddUpdateListener`.

```csharp
monoManager.AddUpdateListener(OnUpdate);
```

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L176-L187)

4. When no longer needed, unregister with the corresponding `RemoveUpdateListener`.

```csharp
monoManager.RemoveUpdateListener(OnUpdate);
```

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L193-L204)

## Common Variants

| Scenario | Method | Signature |
|------|------|------|
| LateUpdate stage per frame | `AddLateUpdateListener` | `Action<float, float>` |
| Fixed time step (FixedUpdate) | `AddFixedUpdateListener` | `Action<float, float>` |
| MonoBehaviour destroyed | `AddDestroyListener` | `Action` |
| Application pause/resume | `AddOnApplicationPauseListener` | `Action<bool>` |
| Application focus gained/lost | `AddOnApplicationFocusListener` | `Action<bool>` |

All methods follow the same rule: passing in `null` throws `ArgumentNullException("action")`.

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| Callback is never invoked | No `MonoComponent` in the scene, manager not initialized | Add the `GameFrameX/Mono` component to the startup scene |
| `ArgumentNullException` thrown when passing the callback | `null` was passed to Add/Remove methods | Perform a null check before registering, or initialize the callback before the lifecycle begins |
| The same callback is registered multiple times | Add/Remove not paired, or Add duplicated in different places | Register once with the same reference, and only Remove once during destruction |
| Duration parameters look abnormal | Using `elapseSeconds` as real time | The first parameter is affected by time scaling (`Time.timeScale`), the second is not |

## Background (Optional)

Internally, `MonoManager` uses a `LinkedList<Action<float, float>>` to store listeners, dispatched in order in `MonoComponent.Update`. All operations are serialized through `lock`, making Add and Remove thread-safe.
