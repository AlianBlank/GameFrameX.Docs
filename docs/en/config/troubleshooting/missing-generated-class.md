# What to Do If TbXxx Classes Cannot Be Found After Generation

After running `gen-client-json.bat` / `gen-client-json.sh`, you can't find classes like `TbMyItem` or `TbAchievement` in your Unity or .NET project — usually the tool isn't broken; rather, the file names, generation script, or output directory don't match up. This page provides a diagnostic table and fix steps organized by error symptom.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Can't find any `TbXxx` class at all, and there is no corresponding `.cs` file in the output directory | The Excel file name doesn't follow the `Letter-EnglishName-ChineseName.xlsx` rule, so the tool fails to recognize it | See "Fix Step 1" |
| Error `不支持中文表名` or `table name invalid` | The "English name" segment of the file name contains Chinese | See "Fix Step 2" |
| `TbXxx` exists in `TbClient` but not in `TbServer` (or vice versa) | The file name contains a group marker `c` / `s`, restricting the table to a single side | See "Fix Step 3" |
| The generation script flashes by when it finishes, and no `Tb` classes are visible | You ran the wrong script (ran the server-side one but searched in the client project), or the script didn't actually execute successfully | See "Fix Step 4" |
| Error saying `luban.conf` / `Tools/` directory cannot be found | The script was not run from the `Config/` root directory | See "Fix Step 5" |
| Class names are `TbXxx2`, `TbXxx_1` instead of the expected `TbXxx` | The same table was split into multiple parts with inconsistent English name spelling | See "Fix Step 6" |

## Fix Steps

### 1. Check Whether the Excel File Name Follows the Naming Rule

The tool only recognizes files that strictly follow the `Letter-EnglishName-ChineseName.xlsx` format; if the file name is wrong, no code will be generated.

Open the `Config/Excels/Tables/` folder and confirm the file name looks like:

```
D-ItemConfig-道具表.xlsx
```

The three segments mean:

| Segment | Purpose | Rule |
|----|------|------|
| Letter | A single letter used for sorting | Any letter or number |
| English name | **Becomes the code class name `TbEnglishName`** | Must be pure English; **Chinese is not allowed** |
| Chinese name | For designers/colleagues to read | Anything; may contain `-` |

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L164-L190)

Example reference table:

| File Name | Generated Class |
|--------|----------|
| `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
| `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
| `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |

### 2. The English Name Segment Must Not Contain Chinese

If you get the error `不支持中文表名` or `table name invalid`, it means the "English name" segment contains Chinese (e.g., `D-道具-我的道具表.xlsx`). Just change the middle segment to pure English:

```
Wrong: D-道具-我的道具表.xlsx
Right: D-Item-我的道具表.xlsx     → generates TbItem
```

### 3. Check the Group Marker in the File Name

If you want a table to be used only by the client or only by the server, you need to add a group marker between the English name and the Chinese name. **If you don't realize the marker is there, you'll think the class is "missing"**.

| File Name | Effect |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | Used by both client and server |
| `D-ItemConfig-c-道具表.xlsx` | **Only the client** has `TbItemConfig` |
| `D-ItemConfig-s-道具表.xlsx` | **Only the server** has `TbItemConfig` |

Confirm whether your target project is the client or the server, then choose the corresponding file name, or remove `-c-` / `-s-` so both sides get the generated class.

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

### 4. Confirm You Ran the Correct Generation Script

There are usually multiple generation scripts in the `Config/` root directory. **Running the wrong script is the most common reason for not finding classes**:

| Script | What It Generates |
|------|----------|
| `gen-client-json.bat` / `gen-client-json.sh` | JSON data + C# classes, for the client |
| `gen-server-bin.bat` / `gen-server-bin.sh` | Binary data + C# classes, for the server |

- Windows: Double-click the corresponding `.bat` in the `Config/` directory
- Mac / Linux: In a terminal, `cd Config` and then run `sh gen-*.sh`

After it finishes, check whether newly generated `.cs` files appear in the output directory — if they're there, it succeeded; they may just be in another project.

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L134-L148)

### 5. Run the Script from the Config Root Directory

`gen-*.bat` / `gen-*.sh` depend on `luban.conf` and the `Tools/` directory located in the same directory. If you run them from another directory, you'll get errors about the config or tools directory not being found, and generation will fail silently.

```bash
# Correct
cd Config
sh gen-client-json.sh

# Wrong (run from the parent directory)
sh Config/gen-client-json.sh   # may not find luban.conf
```

### 6. The English Name Must Be Exactly Identical When Splitting a Table into Multiple Files

If a table is too large, you can split it into multiple files; the tool merges them by "English name". **Inconsistent English name spelling will split it into two tables and generate two classes**:

```
Correct (both merge into TbItemConfig):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemConfig-道具表-1001-2000.xlsx

Wrong (inconsistent English name, generates TbItemConfig and TbItemConfig2):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemCongfig-道具表-1001-2000.xlsx   ← note that ItemCongfig is misspelled
```

Unify the English name, then re-run the generation script.

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L234-L248)

## Verification

After fixing things with the steps above, confirm with the following methods:

1. **Re-run the generation script**, making sure it finishes **without errors** (you see `pause` or `Press any key` instead of an error stack trace).
2. **Open the generation output directory** and confirm it contains `TbXxx.cs` and the corresponding data files (JSON or bin).
3. **In the Unity / .NET project, right-click → Regenerate/Refresh project** so the IDE recognizes the newly added `.cs` files.
4. **Verify with a minimal call**:

```csharp
// Assume the table name is ItemConfig and the id column contains 10001
var item = tables.TbItemConfig.Get(10001);
UnityEngine.Debug.Log(item.Name);
```

If it prints normally, the class has been loaded correctly; if `TbItemConfig` still doesn't exist, go back to the diagnostic table and keep troubleshooting.
