# 如何從子執行緒安全派發事件

在子執行緒（如網路執行緒、Task、非同步回呼）中呼叫 `Fire`（而不是 `FireNow`）即可安全派發事件：該操作是執行緒安全的，事件會被排入佇列，保證在主執行緒的下一幀回呼事件處理函式，處理函式裡可以放心存取 Unity API。

## 前置條件

- 場景中已存在掛載 `EventComponent` 的物件（或已透過模組系統取得 `EventManager`）。
- 在主執行緒上先完成事件訂閱（`Subscribe` / `CheckSubscribe`），子執行緒只負責 `Fire`。

## 操作步驟

1. 在主執行緒（如 `Awake`/`Start`）透過場景中 `EventComponent` 的參考訂閱事件。`Fire` 派發的事件沒有處理函式也不會報錯（事件池以 `AllowNoHandler | AllowMultiHandler` 模式建立）：

```csharp
private void Start()
{
    // CheckSubscribe：不存在時才訂閱，避免重複註冊
    eventComponent.CheckSubscribe(DownloadFinishedEventArgs.EventId, OnDownloadFinished);
}

private void OnDownloadFinished(object sender, GameEventArgs e)
{
    // Fire 派發的事件保證在主執行緒回呼，可以直接操作 Unity 物件
    Debug.Log("下載完成");
}
```

`CheckSubscribe` 的真實實作（不存在時才訂閱）：

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

2. 在子執行緒中呼叫執行緒安全的 `Fire` 派發事件（下面是呼叫方式示意，`EventComponent` 的真實介面見步驟末尾的原始碼摘錄）。事件會在拋出後的**下一幀**於主執行緒分發：

```csharp
// 子執行緒程式碼（例如 Task.Run / 網路程式庫回呼），eventComponent 為場景中 EventComponent 的參考
Task.Run(() =>
{
    byte[] data = DownloadFromNetwork(); // 耗時操作
    eventComponent.Fire(this, EmptyEventArgs.Create(DownloadFinishedEventArgs.EventId));
});
```

`EventComponent.Fire` 提供了兩個多載，其中按事件編號派發的多載內部使用 `EmptyEventArgs.Create(eventId)` 並對編號做非空驗證：

```csharp
public void Fire(object sender, GameEventArgs e)
{
    m_EventManager.Fire(sender, e);
}

public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L147-L161)

3. 需要攜帶自訂資料時，自訂一個繼承 `GameEventArgs` 的參數型別並在子執行緒填好資料後隨 `Fire` 拋出（下面是呼叫方式示意，`EmptyEventArgs` 是儲存庫內建的無參數事件，自訂參數類別按同樣思路實作）：

```csharp
public class DownloadFinishedEventArgs : GameEventArgs
{
    public const string EventId = "Download.Finished";
    public byte[] Data { get; set; }
}

// 子執行緒派發：
eventComponent.Fire(this, new DownloadFinishedEventArgs { Data = data });

// 主執行緒處理函式中讀取：
private void OnDownloadFinished(object sender, GameEventArgs e)
{
    var args = (DownloadFinishedEventArgs)e;
    UseBytes(args.Data);
}
```

`GameEventArgs` 是一個開放繼承的抽象基底類別，位於 `GameFrameX.Event.Runtime` 命名空間：

```csharp
public abstract class GameEventArgs : BaseEventArgs
{
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

## 常見變體

| 場景 | 做法 |
|------|------|
| 只需通知、無資料 | `Fire(sender, eventId)` 字串多載，內部用 `EmptyEventArgs.Create(eventId)` 建構空參數 |
| 直接持有 `IEventManager` | `IEventManager.Fire(object sender, GameEventArgs e)`，與元件封裝行為一致 |
| 事件僅在主執行緒、需要同幀生效 | 用 `FireNow`，但**絕不能在子執行緒呼叫**（見下） |

## 常見錯誤

| 錯誤 | 後果與規避 |
|------|-----------|
| 在子執行緒呼叫 `FireNow` | `FireNow` **不是執行緒安全的**，會立刻在呼叫執行緒上分發，處理函式會在子執行緒執行並可能造成 Unity 崩潰；子執行緒一律用 `Fire`。原始碼註解明確標註：[EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L167-L175) |
| 期望 `Fire` 同幀生效 | `Fire` 派發的事件在拋出後的下一幀才分發，依賴同幀時序的邏輯（如立即讀取狀態）需要改為在處理函式回呼後執行 |
| 在子執行緒裡 `Subscribe`/`Unsubscribe` | 訂閱表操作沒有執行緒安全保證，請只在主執行緒增刪處理函式 |
| 事件編號傳空字串 | `Fire(sender, eventId)` 內部 `GameFrameworkGuard.NotNullOrEmpty` 會直接擲回驗證例外 |

## 背景

`EventManager` 是一個 `GameFrameworkModule`（優先權 7）。`Fire` 把事件放入內部 `EventPool<GameEventArgs>` 佇列；模組每幀在主執行緒 `Update` 中呼叫 `m_EventPool.Update(elapseSeconds, realElapseSeconds)` 排空佇列並回呼處理函式，這就是「子執行緒拋出、主執行緒回呼、下一幀分發」的由來。相關實作見 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L76-L92) 與 [IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L93-L104)。
