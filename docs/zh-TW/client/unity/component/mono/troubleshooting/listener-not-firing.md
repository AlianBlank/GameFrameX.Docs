# 監聽器沒有觸發或回呼時機不對怎麼辦

當你透過 `MonoComponent.AddUpdateListener / AddFixedUpdateListener / AddLateUpdateListener / AddDestroyListener / AddOnApplicationFocusListener / AddOnApplicationPauseListener` 註冊了回呼,但執行後函式沒有執行，或執行順序與預期不符，可以按本頁流程排查。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 主控台輸出 `Mono manager is invalid.` | 場景裡沒有掛 `MonoComponent`,框架模組 `IMonoManager` 未註冊 | 見下方「場景缺少 MonoComponent」 |
| 主控台輸出 `Event manager is invalid.` | 場景裡沒有掛 `EventComponent`,`OnApplicationFocus/Pause` 事件無法派發 | 見下方「EventComponent 缺失」 |
| 監聽器從未觸發，無任何報錯 | 在 `Awake` 裡 `AddXxxListener` 時,`_monoManager` 仍為 `null` | 見下方「註冊時機早於 Awake」 |
| 監聽器只觸發一次，後續靜默 | 在回呼內部再次 `AddXxxListener` 時傳入了 `null`,`MonoComponent` 靜默 `return` | 見下方「回呼函式為 null」 |
| `AddOnApplicationFocusListener` 不觸發，但 Update 正常 | `EventComponent` 未掛載，`MonoComponent.OnApplicationFocus` 的事件分支直接跳過 | 見下方「EventComponent 缺失」 |
| 回呼裡拋出例外被吞掉，後續監聽器仍執行 | `QueueInvoking` 對每個 `action.Invoke()` 包了 `try/catch`,只寫 `Log.Error` | 見下方「回呼內部例外被靜默吞掉」 |
| LateUpdate 監聽器在 Update 之前執行 | 註冊位置在 `Update` 之後，管理器按 `LinkedList` 順序派發 | 見下方「監聽器註冊順序與執行順序」 |
| 在 `OnApplicationFocus(true)` 裡註冊，但同時失去焦點又獲得焦點時只回呼了一次 | Unity 在編輯器失焦/聚焦時可能合併事件 | 見下方「編輯器失焦行為」 |

## 修復步驟

### 場景缺少 MonoComponent

`MonoComponent.Awake()` 透過 `GameFrameworkEntry.GetModule<IMonoManager>()` 取得模組；取不到就呼叫 `Log.Fatal("Mono manager is invalid.")` 並直接 `return`,之後所有 Unity 回呼(`FixedUpdate / LateUpdate / OnDestroy / OnApplicationFocus / OnApplicationPause`)都因 `_monoManager == null` 被跳過：

```csharp
// Runtime/Mono/MonoComponent.cs
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IMonoManager);
    base.Awake();
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs#L52-L63](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L63)

修復：

1. 在遊戲啟動場景的 `GameFramework` 物件上點擊 `Add Component → GameFrameX/Mono` 新增 `MonoComponent`。
2. 確認該物件上還掛了 `BaseComponent`(框架入口)，否則模組鏈不會啟動。
3. 重新執行場景，確認主控台不再出現 `Mono manager is invalid.`。

### EventComponent 缺失

`OnApplicationFocus` 與 `OnApplicationPause` 除了呼叫 `_monoManager` 上的回呼，還會透過 `EventComponent.Fire` 把事件廣播給訂閱者。如果 `m_EventComponent == null`,事件分支直接跳過：

```csharp
// Runtime/Mono/MonoComponent.cs
private void OnApplicationFocus(bool focusStatus)
{
    if (_monoManager == null) { return; }
    _monoManager.OnApplicationFocus(focusStatus);
    if (m_EventComponent != null)
    {
        m_EventComponent.Fire(this, OnApplicationFocusChangedEventArgs.Create(focusStatus));
    }
}
```

Source: [MonoComponent.cs#L111-L123](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L111-L123)

修復：

1. 在同一 `GameFramework` 物件上新增 `EventComponent`(`Add Component → GameFrameX/Event`)。
2. 訂閱端使用 `EventComponent.Subscribe` 訂閱 `OnApplicationFocusChangedEventArgs.EventId`,而不是只呼叫 `AddOnApplicationFocusListener`。
3. 執行後應能在日誌中看到事件被派發。

### 註冊時機早於 Awake

`_monoManager` 在 `MonoComponent.Awake()` 才賦值。如果你在某個腳本自己的 `Awake` 裡就呼叫 `GameEntry.GetComponent<MonoComponent>().AddUpdateListener(...)`,由於腳本 `Awake` 順序未定義，可能拿到一個 `_monoManager` 尚未初始化的 `MonoComponent` 實例，後續即使賦值了，新註冊的回呼也會工作，但要注意：如果 `MonoComponent` 還沒 `Awake`,它內部的 `_monoManager` 是 `null`,所有 `AddXxxListener` 會因為 `_monoManager` 未初始化而無法排入佇列(實際表現為 `NullReferenceException` 或 `MonoComponent` 內的 `Log.Fatal` 輸出 `fun is invalid.`)。

修復：

- 把註冊邏輯放到 `Start` 中，或在拿到 `MonoComponent` 後加一個 `if (comp == null) return;`。
- 也可以直接透過 `GameFrameworkEntry.GetModule<IMonoManager>()` 拿到管理器，繞過 `MonoComponent`。

### 回呼函式為 null

`MonoComponent.AddXxxListener` 對 `null` 入參只寫 `Log.Fatal` 並 `return`,不會拋出例外，也不會排入佇列：

```csharp
// Runtime/Mono/MonoComponent.cs
public void AddUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddUpdateListener(fun);
}
```

Source: [MonoComponent.cs#L207-L216](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L207-L216)

而 `MonoManager.AddXxxListener` 對 `null` 會直接拋出 `ArgumentNullException`。兩層語意不同，寫程式碼時不要混淆。

修復：

- 註冊時確保 `fun` 是非空的方法群組或 lambda;不要傳入 `default(Action<float, float>)`。
- 如果主控台出現 `fun is invalid.`,就是這裡傳了 `null`。

### 回呼內部例外被靜默吞掉

`MonoManager.QueueInvoking` 在派發每個監聽器時都包了 `try/catch`,例外只透過 `Log.Error` 寫出，不會中斷後續監聽器：

```csharp
// Runtime/Mono/MonoManager.cs
foreach (var action in snapshot)
{
    try
    {
        UnityEngine.Profiling.Profiler.BeginSample($"QueueInvoking-{action.Method.Name}-{action.Target}");
        action.Invoke();
        UnityEngine.Profiling.Profiler.EndSample();
    }
    catch (Exception e)
    {
        Log.Error(e);
    }
}
```

Source: [MonoManager.cs#L319-L330](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L319-L330)

修復：

- 主控台搜尋 `QueueInvoking-` 前綴的 `Log.Error`,定位是哪個監聽器拋錯。
- 在回呼內部用 `try/catch` 自行保護關鍵邏輯，避免一條監聽器的例外被忽略後，看起來「什麼都沒發生」。

### 監聽器註冊順序與執行順序

`MonoManager` 用 `LinkedList<Action<...>>` 儲存監聽器，派發時按排入佇列的順序遍歷。`LateUpdate` 的派發在所有 `Update` 之後，但 `MonoComponent` 自身沒有 `Update` 方法(原始碼中只有 `FixedUpdate`、`LateUpdate`、`OnDestroy`、`OnApplicationFocus`、`OnApplicationPause`):

```csharp
// Runtime/Mono/MonoComponent.cs
private void FixedUpdate() { _monoManager.FixedUpdate(); }
private void LateUpdate()  { _monoManager.LateUpdate(); }
```

Source: [MonoComponent.cs#L81-L92](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L81-L92)

也就是說：**框架沒有 Update 掛鉤**。如果你以為有 `AddUpdateListener`,實際上是有的(`MonoManager._updateQueue` + `AddUpdateListener`),但驅動它的 `MonoBehaviour.Update` 沒有在 `MonoComponent` 中顯式宣告——這通常意味著專案裡需要透過別的方式觸發 `_monoManager.Update`(例如在自訂 `MonoBehaviour.Update` 裡手動呼叫，或確認是否存在繼承版本)。

修復：

- 確認專案裡實際有 `MonoBehaviour.Update` 呼叫 `_monoManager.Update()`;如果只有 `MonoComponent`,Update 監聽器不會觸發，需要自行補充。
- 監聽器之間的相對順序：先 `AddXxxListener` 的先執行，後註冊的後執行。需要嚴格順序時按順序註冊即可。
- 同一幀多次進入 / 離開焦點時，Unity 會按事件實際發生順序觸發，框架不合併。

### 編輯器失焦行為

`OnApplicationFocus` 在編輯器中會在以下情況觸發：視窗失焦、點擊 Play、Stop。開發期間頻繁觸發屬於正常現象。如果只是編輯器裡「看起來不觸發」，建議 Build 到真機或勾選 `Edit → Project Settings → Player → Run In Background` 後再觀察。

## 驗證

- 主控台不再出現 `Mono manager is invalid.`、`Event manager is invalid.`、`fun is invalid.`。
- 註冊一個最簡單的 `Debug.Log` 監聽器(例如 `AddUpdateListener((a, b) => Debug.Log("update " + a))`),執行後能看到逐幀日誌。
- `OnApplicationFocus/Pause` 切換視窗焦點時，日誌或事件訂閱者能收到對應事件。
- 回呼內部拋錯時，日誌中能看到 `QueueInvoking-YourMethod-YourTarget` 命中的例外，而不是完全靜默。
