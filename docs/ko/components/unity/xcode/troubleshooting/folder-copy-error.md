# 폴더 복사 오류 해결 방법

Unity iOS 빌드의 후처리 단계에서 `folders` 설정에 선언된 폴더는 Xcode 프로젝트로 복사되어 자동으로 컴파일에 포함됩니다. Unity Console에서 `DirectoryNotFoundException`, `IOException` 등의 예외가 발생하거나, 복사 후 파일/프레임워크가 누락된 경우 아래 진단 표를 통해 원인을 파악하고 수정하세요.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `DirectoryNotFoundException: Could not find a part of the path ...` | `folders`의 Key 소스 경로가 존재하지 않음: Key는 Unity 프로젝트 루트 디렉터리(`Assets`와 동일한 레벨) 기준 상대 경로이며, `Assets` 기준 경로가 아님 | 수정 단계 1 참조 |
| `IOException` / `UnauthorizedAccessException`, 대상 디렉터리 삭제 시 발생 | 대상 디렉터리가 Xcode 등의 프로그램에 의해 점유 중이거나, 읽기 전용 파일이 포함되어 있음 | 점유 중인 프로그램을 종료하거나 대상 디렉터리를 수동으로 삭제한 후 다시 빌드. 수정 단계 2 참조 |
| 복사는 성공했으나 일부 파일 누락 | 파일 이름이 `.`로 시작하거나 `.gitkeep` / `.DS_Store`인 경우 능동적으로 필터링됨 | 예상된 동작임. 수정 단계 3 참조 |
| `.framework` / `.bundle` / `.a` 복사 후 링크 오류(심볼을 찾을 수 없음) | 이전 버전의 폴더 복사 링크 버그 또는 확장자가 잘못되어 인식되지 않음 | 최신 버전으로 업그레이드. 수정 단계 4 참조 |

## 수정 단계

### 1. 소스 경로가 존재하지 않음(DirectoryNotFoundException)

복사 시 소스 경로는 아래 방식으로 조합되며, `Environment.CurrentDirectory`는 Unity 프로젝트 루트 디렉터리로 `Assets`와 동일한 레벨입니다:

```csharp
string src = Path.Combine(Environment.CurrentDirectory, map.Key.ToString().Trim());
string des = Path.Combine(xcodePath, map.Value.ToString().Trim());
CopyFolder(src, des);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L29-L31)

JSON 설정을 확인하고 수정하세요(경로 앞뒤의 공백은 `Trim()`으로 제거됨):

```json
{
  "folders": {
    "XC": "Classes/XC"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L191-L197)

- Key: 폴더의 Unity 프로젝트 루트 디렉터리 기준 경로이며, `Assets/`로 시작하도록 잘못 작성하지 않도록 주의
- Value: Xcode 프로젝트 내부로 복사될 상대 경로

### 2. 대상 디렉터리 삭제 실패(IOException)

`CopyFolder`는 복사 전에 이미 존재하는 대상 디렉터리와 동일한 이름의 파일을 먼저 삭제한 후 디렉터리를 다시 생성합니다:

```csharp
if (Directory.Exists(dstPath))
{
    Directory.Delete(dstPath, true);
}

if (File.Exists(dstPath))
{
    File.Delete(dstPath);
}

Directory.CreateDirectory(dstPath);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L174-L184)

`Directory.Delete(dstPath, true)`는 재귀적으로 삭제하며, 대상 내에 점유 중이거나 읽기 전용인 파일이 있을 때 예외가 발생합니다:

1. 해당 Xcode 프로젝트(또는 해당 디렉터리)를 열고 있는 프로그램을 종료합니다
2. Xcode 프로젝트 내의 대상 디렉터리를 수동으로 삭제합니다
3. Unity iOS 빌드를 다시 실행합니다

### 3. 일부 파일이 복사되지 않음

복사 및 컴파일 추가는 모두 `IsNeedCopy` 필터를 거칩니다:

```csharp
private static bool IsNeedCopy(string file)
{
    string fileName = Path.GetFileNameWithoutExtension(file);
    if (fileName.StartsWith(".") || file.EndsWith(".gitkeep") || file.EndsWith(".DS_Store"))
    {
        return false;
    }

    return true;
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L112-L121)

파일 이름(확장자 제외)이 `.`로 시작하거나 `.gitkeep`, `.DS_Store`인 경우 모두 건너뜁니다. 빈 디렉터리의 플레이스홀더 파일을 유지해야 한다면 점(.)이 아닌 접두사로 이름을 지정하세요.

### 4. framework / bundle / 정적 라이브러리 링크 오류

`AddFolderBuild`는 확장자에 따라 처리 방식을 구분하므로, 대상 경로(즉 `folders`의 Value)의 확장자가 올바른지 확인하세요:

| Value 끝 | 처리 방식 |
|------------|----------|
| `.framework` | `AddFile` + `AddFileToBuild` + `AddFrameworkToProject` |
| `.bundle` | UnityFramework 타깃과 메인 타깃에 모두 추가 |
| `.xcframework` / `.a` | `AddFile` + `AddFileToBuild` |
| 일반 디렉터리 | 하위 디렉터리와 파일을 재귀적으로 확장하고, 프레임워크/정적 라이브러리에 대해 검색 경로 자동 추가(`AutoAddSearchPath`) |

```csharp
if (root.EndsWith(".framework") || root.EndsWith(".bundle"))
{
    Debug.LogFormat("add framework/bundle to build:{0}->{1}", currDir, root);
    string fileGuid = proj.AddFile(currDir, root, PBXSourceTree.Source);
    proj.AddFileToBuild(targetGuid, fileGuid);
    if (root.EndsWith(".bundle"))
    {
        proj.AddFileToBuild(mainTargetGuid, fileGuid);
    }
    // linked framework로 추가
    proj.AddFrameworkToProject(targetGuid, root, false);
    return;
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L47-L59)

## 검증

1. Unity iOS 빌드를 다시 실행했을 때 Console에 `DirectoryNotFoundException` / `IOException` 예외가 없고, `add framework/bundle to build:...`, `add file to build:...` 로그가 보이는지 확인
2. 생성된 Xcode 프로젝트를 열어 `folders`의 Value가 가리키는 디렉터리가 존재하고 내용이 완전한지 확인
3. `.framework` / `.bundle`가 **General → Frameworks, Libraries, and Embedded Content** 또는 **Build Phases → Link Binary With Libraries**에 나타나고, 컴파일이 통과되는지 확인
