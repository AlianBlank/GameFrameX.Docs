# 如何定义 Proto 消息并接入编解码

通过为消息类添加特性标记并实现 `INetworkMessage` 接口,即可让自定义消息接入框架的 ProtoBuf 序列化与 ID 路由体系,实现收发两端的消息编解码。

## 前置条件

- 项目已引用 `GameFrameX.ProtoBuf.Net`(封装 ProtoBuf 的 `Serializer.Serialize` / `Deserialize` / `Merge`)。
- 项目已引用 `GameFrameX.NetWork.Abstractions`,用于消息 ID 注册与心跳/请求/响应分类。
- 程序集在启动阶段调用过一次 `MessageProtoHelper.Init(assemblies)`,让特性被扫描并写入字典。

## 操作步骤

### 1. 定义消息类型

消息类需要实现 `INetworkMessage` 接口,并通过 `MessageTypeHandlerAttribute` 注册一个全局唯一的 `MessageId` 与 `OperationType`。依据业务语义,可以选择性地实现 `IRequestMessage`、`IResponseMessage`、`INotifyMessage`、`IHeartBeatMessage`。

```csharp
using GameFrameX.NetWork.Abstractions;
using GameFrameX.NetWork.Abstractions.Interface;

[MessageTypeHandler(1001, (byte)MessageOperationType.Request)]
public sealed class LoginRequest : INetworkMessage, IRequestMessage
{
    public string UserName { get; set; }
    public string Password { get; set; }
}

[MessageTypeHandler(1002, (byte)MessageOperationType.Response)]
public sealed class LoginResponse : INetworkMessage, IResponseMessage
{
    public int Code { get; set; }
    public string Token { get; set; }
}

[MessageTypeHandler(9999, (byte)MessageOperationType.Notify)]
public sealed class HeartBeat : INetworkMessage, IHeartBeatMessage
{
    public long Timestamp { get; set; }
}
```

`MessageTypeHandlerAttribute` 携带 `MessageId` 与 `OperationType`,注册阶段会用它们填充 `MessageProtoHelper` 内部的字典。

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L218-L254)

### 2. 启动时初始化消息映射

在应用启动时,把含消息类的程序集交给 `MessageProtoHelper.Init`,它会扫描所有标了 `MessageTypeHandlerAttribute` 的类型,并按 ID 注册到 `AllMessageDictionary`、`RequestDictionary`、`ResponseDictionary`、`HeartBeatList`、`OperationType`。若 ID 重复,会抛出 `ArgumentAlreadyException`。

```csharp
using System.Reflection;
using GameFrameX.NetWork.Abstractions;

MessageProtoHelper.Init(
    Assembly.GetExecutingAssembly(),
    typeof(LoginRequest).Assembly
);
```

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L187-L208)

### 3. 使用 ProtoBuf 序列化与反序列化

`GameFrameX.ProtoBuf.Net.ProtoBufSerializerHelper` 封装了 ProtoBuf 的 `Serializer.Serialize` / `Deserialize` / `Merge`,可以直接用于消息体的字节流编解码。

```csharp
using GameFrameX.ProtoBuf.Net;

// 序列化(对象 -> 字节数组)
byte[] payload = ProtoBufSerializerHelper.Serialize(loginRequest);

// 反序列化(字节数组 -> 对象)
var message = ProtoBufSerializerHelper.Deserialize<LoginRequest>(payload);

// 合并模式:把字节流合并到已有实例,避免分配新对象
var merged = ProtoBufSerializerHelper.Deserialize(payload, existingInstance);
```

合并模式适用于增量更新场景,空字节数组会直接返回原实例而不抛异常。

Source: [ProtoBufSerializerHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.ProtoBuf.Net/ProtoBufSerializerHelper.cs#L17-L82)

### 4. 在收发流程中查询消息类型

网络层收到字节流后,可以先按 `MessageId` 查类型,再用 `ProtoBufSerializerHelper` 反序列化:

```csharp
int messageId = ReadMessageId(buffer);
Type messageType = MessageProtoHelper.GetMessageTypeById(messageId);
if (messageType != null)
{
    object message = ProtoBufSerializerHelper.Deserialize(buffer, messageType);
    // 分发到处理逻辑...
}
```

反方向发送时,先用 `MessageProtoHelper.SetMessageId(message)` 把 `MessageId` 写回对象,再走序列化。

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L60-L149)

## 常见变体

| 场景 | 写法 | 说明 |
|------|------|------|
| 心跳消息 | 实现 `IHeartBeatMessage` | 自动加入 `HeartBeatList`,`GetMessageOperationType` 直接返回 `HeartBeat` |
| 请求/响应配对 | 分别实现 `IRequestMessage` 与 `IResponseMessage` | 分别注册到 `RequestDictionary` / `ResponseDictionary`,便于 RPC 配对 |
| 增量更新 | `Deserialize<T>(byte[] data, T instance)` | 走 `Serializer.Merge`,复用实例以减少 GC |
| 枚举字段 | 使用 `ProtoEnumAttribute` | 由 `GameFrameX.ProtoBuf.Net` 提供,见源码目录 |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动抛出 `ArgumentAlreadyException(... MessageIdDuplicate ...)` | 两个类共用了同一个 `MessageId` | 修改 `MessageTypeHandler` 的第一个参数,保证全局唯一 |
| `GetMessageTypeById` 返回 `null` | 该 ID 没有调用 `Init` 或未被注册 | 启动阶段调用 `MessageProtoHelper.Init(assembly)` 并确保消息类已编译到该程序集 |
| `ProtoBufSerializerHelper.Serialize` 抛异常 | 字段未加 ProtoBuf `[ProtoMember]` / `[ProtoContract]` 等特性 | 检查消息类是否正确声明 ProtoBuf 序列化特性(在 `GameFrameX.ProtoBuf.Net` 中对应 `ProtoContractAttribute`、`ProtoIncludeAttribute` 等) |
| 心跳被当作普通消息处理 | 未实现 `IHeartBeatMessage` | 让心跳类实现该接口,`Init` 阶段会自动加入心跳表 |

## 背景(可选)

框架把"消息 ID↔类型"映射(`MessageProtoHelper`)与"对象↔字节"映射(`ProtoBufSerializerHelper`)解耦:前者负责按 ID 找到正确的 .NET 类型并区分请求/响应/通知/心跳,后者负责 ProtoBuf 格式的二进制读写。`GameFrameX.Proto/MessageProtoHandler` 作为命名空间占位,实际编解码入口是 `ProtoBufSerializerHelper`。关于传输层(TCP/KCP)如何封装这些字节,见网络层相关文档。
