# How to Use Network, Download, Web, and Protobuf Communication

GameFrameX exposes the network and download components through the `GameApp.Network` / `GameApp.Download` static accessors; Web requests and Protobuf communication are provided by the corresponding companion packages. Below are the minimal steps for integrating the four subsystems.

## Prerequisites

| Subsystem | Required Macro / Package | Purpose |
|--------|-------------|------|
| Network | `ENABLE_GAME_FRAME_X_NETWORK` + `GameFrameX.Network.Runtime` | TCP / UDP persistent connections based on the Protobuf protocol |
| Download | `ENABLE_GAME_FRAME_X_DOWNLOAD` + `GameFrameX.Download.Runtime` | HTTP/HTTPS file downloads, progress callbacks |
| Web | `GameFrameX.Web.Runtime` | One-off HTTP requests (REST / JSON) |
| Protobuf | `GameFrameX.ProtoBuf.Runtime` | Message encoding/decoding, used internally by Network |

> All four components are registered at GameEntry startup; obtain the singletons through static properties such as `GameApp.Network` and `GameApp.Download`.

## Steps

### 1. Enable the Network Component

Simply access `GameApp.Network` to get the singleton; internally the framework calls `GameEntry.GetComponent<NetworkComponent>()`.

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Runtime;

var network = GameApp.Network;
network.Connect("127.0.0.1", 7000);
#endif
```

Source: [Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L55)

### 2. Enable the Download Component

The download component is likewise accessed through the `GameApp.Download` singleton:

```csharp
#if ENABLE_GAME_FRAME_X_DOWNLOAD
using GameFrameX.Runtime;

var downloader = GameApp.Download;
downloader.DownloadAsync(url, savePath, (success, error) =>
{
    if (success) UnityEngine.Debug.Log("Download complete");
    else UnityEngine.Debug.LogError(error);
});
#endif
```

Source: [Runtime/GameApp.Download.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Download.cs#L32-L55)

### 3. Make a Web Request

The Web module is used for one-off HTTP calls (JSON, forms, etc.) and does not conflict with the persistent-connection Network:

```csharp
using GameFrameX.Web.Runtime;

WebComponent web = GameEntry.GetComponent<WebComponent>();
web.Post("https://api.example.com/login", "{\"user\":\"x\"}",
    (statusCode, body) => UnityEngine.Debug.Log($"{statusCode} -> {body}"));
```

### 4. Serialize Messages with Protobuf

Network already uses Protobuf internally; reuse the same ProtoBuf component for your custom messages:

```csharp
using GameFrameX.ProtoBuf.Runtime;

byte[] bytes = ProtoBufComponent.Serialize(myMessage);
var restored = ProtoBufComponent.Deserialize<MyMessage>(bytes);
```

### 5. Close and Reconnect

```csharp
GameApp.Network.Close();
GameApp.Network.Connect("127.0.0.1", 7000); // Re-establish the connection
```

## Common Variants

- **Multiple persistent-connection channels**: `NetworkComponent` supports multiple `NetworkChannel`s, each with an independent heartbeat / independent encoding and decoding.
- **Resumable downloads**: Save the downloaded bytes in the `DownloadAsync` callback and resume on startup via the `Range` header.
- **Protocols other than Protobuf**: Pass a custom `INetworkChannelHelper` when creating a new `NetworkChannel` to switch to JSON / MessagePack.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GameApp.Network` returns `null` | The `ENABLE_GAME_FRAME_X_NETWORK` macro is not defined | Add it under `Project Settings → Scripting Define Symbols`; install the `GameFrameX.Network` package |
| The download callback gets `success=false` but no `error` text | Invalid URL or no write permission on disk | Check `url` and `savePath`, and confirm that Application.persistentDataPath is writable |
| Web request returns status code 0 | The target domain is not allowed in Unity | Check Player Settings → Other Settings → Allow downloads over HTTP |
| Protobuf serialization throws an exception | The message class lacks `[ProtoContract]` / `[ProtoMember]` | Add the attributes to the message fields, or use protobuf-net's `ImplicitFields = ImplicitFields.AllPublic` |

## Background (Optional)

`GameApp` is a `partial class`, with each subsystem in its own file, all lazily loaded and cached into private static fields via `GameEntry.GetComponent<T>()`. This avoids scattering `GetComponent` calls everywhere and makes it easy to trim unneeded subsystems based on macros, reducing the published build size.
