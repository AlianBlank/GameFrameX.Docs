# How to Subscribe to Lifecycle Events

Through the five events exposed by `IEntityManager` (`ShowEntitySuccess` / `ShowEntityFailure` / `ShowEntityUpdate` / `ShowEntityDependencyAsset` / `HideEntityComplete`), you can receive callbacks at each stage of entity showing, updating, and hiding, without having to modify the entity's internal code.

## Prerequisites

- You have obtained an `IEntityManager` instance in your project (usually acquired via `GameEntry.GetComponent<EntityComponent>().EntityManager`).
- Reference the namespaces `GameFrameX.Entity.Runtime` (event arguments) and `System` (standard `EventHandler<T>`).

## Overview of Subscribable Events

| Event | Event Arguments | Trigger Timing |
|------|---------|---------|
| `ShowEntitySuccess` | `ShowEntitySuccessEventArgs` | Entity loaded and shown successfully |
| `ShowEntityFailure` | `ShowEntityFailureEventArgs` | Entity loading or showing failed |
| `ShowEntityUpdate` | `ShowEntityUpdateEventArgs` | Progress update during entity showing |
| `ShowEntityDependencyAsset` | `ShowEntityDependencyAssetEventArgs` | Starting to load entity dependency assets |
| `HideEntityComplete` | `HideEntityCompleteEventArgs` | Entity hiding completed |

## Steps

1. Store an `IEntityManager` reference in the class that needs to listen, and register event callbacks with `+=` (each event signature takes the form `EventHandler<TEventArgs>`, where the second parameter `e` is the corresponding event arguments).

```csharp
using System;
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

public class MyListener
{
    private readonly IEntityManager m_EntityManager;

    public MyListener(IEntityManager entityManager)
    {
        m_EntityManager = entityManager;
        // Subscribe to lifecycle events
        m_EntityManager.ShowEntitySuccess    += OnShowEntitySuccess;
        m_EntityManager.ShowEntityFailure    += OnShowEntityFailure;
        m_EntityManager.ShowEntityUpdate     += OnShowEntityUpdate;
        m_EntityManager.ShowEntityDependencyAsset += OnShowEntityDependencyAsset;
        m_EntityManager.HideEntityComplete   += OnHideEntityComplete;
    }

    private void OnShowEntitySuccess(object sender, ShowEntitySuccessEventArgs e)
    {
        // e.Entity / e.Duration / e.UserData / e.EntityLogicType
        Log.Info($"实体 {e.Entity.Id} 显示成功,耗时 {e.Duration:F2}s");
    }

    private void OnShowEntityFailure(object sender, ShowEntityFailureEventArgs e)
    {
        Log.Warning($"实体显示失败: {e.EntityId}");
    }

    private void OnShowEntityUpdate(object sender, ShowEntityUpdateEventArgs e)
    {
        // e.Progress / e.EntityId
    }

    private void OnShowEntityDependencyAsset(object sender, ShowEntityDependencyAssetEventArgs e)
    {
        // e.EntityId / e.DependencyAssetName / e.LoadedCount / e.TotalCount
    }

    private void OnHideEntityComplete(object sender, HideEntityCompleteEventArgs e)
    {
        // e.EntityId / e.EntityAssetName / e.EntityGroup / e.UserData
    }
}
```

Source: [EntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.cs#L105-L150)

2. When the listener's lifecycle ends (scene switching, `OnDestroy`, etc.), unsubscribe with `-=` to avoid memory leaks or redundant callbacks on destroyed objects.

```csharp
public void Dispose()
{
    m_EntityManager.ShowEntitySuccess    -= OnShowEntitySuccess;
    m_EntityManager.ShowEntityFailure    -= OnShowEntityFailure;
    m_EntityManager.ShowEntityUpdate     -= OnShowEntityUpdate;
    m_EntityManager.ShowEntityDependencyAsset -= OnShowEntityDependencyAsset;
    m_EntityManager.HideEntityComplete   -= OnHideEntityComplete;
}
```

3. Obtain the manager through `EntityComponent` and hand it to the listener for use.

```csharp
var entityManager = GameEntry.GetComponent<EntityComponent>().EntityManager;
var listener = new MyListener(entityManager);
```

## Common Variants

- **Only want to listen to a single event**: only `+=` the one you care about, e.g., if you only care about failures: `entityManager.ShowEntityFailure += OnFailed;`.
- **Filter by entity Id**: inside the callback, check `e.EntityId` (or `e.Entity?.Id`) to decide whether to handle this notification.
- **Only want progress feedback during the loading phase**: subscribe only to `ShowEntityUpdate` and `ShowEntityDependencyAsset`, and display `e.Progress` or `e.LoadedCount / e.TotalCount` in the UI.

## Common Mistakes

- **Destroying the listener without unsubscribing**: `EntityManager` is a long-lived module that keeps holding the callback delegates, preventing objects from being garbage collected. Always use `-=` in pairs in `OnDestroy` / `Dispose`.
- **Throwing uncaught exceptions inside a callback**: events are dispatched synchronously, so exceptions propagate up the call stack and interrupt subsequent processing; please use `try / catch` inside callbacks.
- **Confusing `EventId` with the C# `event`**: `ShowEntitySuccessEventArgs.EventId` is used for the global event bus (`GameFrameX.Event.Runtime`); what is introduced here is the `event EventHandler<T>` subscription on `IEntityManager`, and the two are not the same mechanism.

## Background (Optional)

`EntityManager` internally exposes the five callbacks above as standard .NET `event` fields, triggered at key points of each `Show`/`Hide` flow; the `EventArgs` are acquired and recycled through the `ReferencePool`, so do not hold onto these argument objects for the long term—they are returned to the pool after the event is dispatched.
