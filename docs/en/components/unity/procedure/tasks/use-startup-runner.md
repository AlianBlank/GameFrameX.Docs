# How to Take Over Startup with StartupRunner

`ProcedureComponent` automatically initializes and starts the procedure in `Start()` by default; when `Use Startup Runner` is checked, it only registers `IProcedureManager` in `Awake`, with the actual procedure initialization and startup handed off to `ApplicationStartupEntry` + `StartupRunner.Run`, avoiding the "Already exist FSM" conflict.

## Prerequisites

- GameFrameX procedure package (`com.gameframex.unity.procedure`) is installed.
- GameFrameX startup pipeline (`ApplicationStartupEntry` and `StartupRunner.Run`) is integrated into the project, otherwise the takeover flow will not be triggered.
- There is a GameObject in the scene with `ProcedureComponent` attached, which can be added via the menu `GameFrameX > Procedure`.

## Steps

1. Select the GameObject with `ProcedureComponent` attached in the scene, and check the `Use Startup Runner` checkbox (corresponding to field `m_UseStartupRunner`) in the Inspector.

2. After checking, `ProcedureComponent.Start()` will immediately `yield break`, and will not execute `Initialize` or call `StartProcedure`, retaining only the `IProcedureManager` registration from `Awake`:

   ```csharp
   private IEnumerator Start()
   {
       if (m_ProcedureManager == null)
       {
           yield break;
       }

       if (m_UseStartupRunner)
       {
           // Initialize and StartProcedure are taken over by ApplicationStartupEntry + StartupRunner.Run.
           // This component only handles registering IProcedureManager in Awake, avoiding duplicate Initialize calls reporting "Already exist FSM" with the new entry point.
           yield break;
       }
       // ...
   }
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L115-L168)

3. Start the procedure through `StartupRunner.Run` in `ApplicationStartupEntry`: construct the procedure array and specify the entry procedure, finally call `IProcedureManager.Initialize` and `StartProcedure`. The typical calling form is as follows (consistent with the inline code in the traditional `Start()` mode):

   ```csharp
   ProcedureBase[] procedures = new ProcedureBase[m_AvailableProcedureTypeNames.Length];
   for (int i = 0; i < m_AvailableProcedureTypeNames.Length; i++)
   {
       Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
       procedures[i] = (ProcedureBase)Activator.CreateInstance(procedureType);
       if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
       {
           m_EntranceProcedure = procedures[i];
       }
   }

   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L168)

4. Run the scene, confirm that the startup entry successfully launches the first procedure (e.g., `ProcedurePreload`), and no duplicate initialization-related errors appear in the console.

## Traditional Mode vs StartupRunner Mode

| Mode | Trigger Location | Entry Configuration | Applicable Scenario |
|------|---------|---------|---------|
| Traditional Mode (checkbox unchecked) | `ProcedureComponent.Start()` automatic | `Available Procedures` and `Entrance Procedure` in Inspector | Using the procedure component alone, not integrating with the unified startup entry |
| StartupRunner Mode (checkbox checked) | `ApplicationStartupEntry` + `StartupRunner.Run` | Determined by the startup entry's runtime code | Unified pipeline using GameFrameX unified startup entry |

## Common Errors

- **Already exist FSM**: Both modes are enabled simultaneously, causing `Initialize` to be called twice. Solution: Ensure initialization is only triggered in one mode, or keep the `Use Startup Runner` checkbox checked and remove the inline startup in `Start()`.
- **Entry procedure is null**: When no valid type name is specified in `m_EntranceProcedureTypeName`, traditional mode will print `Entrance procedure is invalid.` and exit; in StartupRunner mode, you need to specify the entry procedure in your own entry code.
- **Procedure type not found**: When `Utility.Assembly.GetType(...)` returns null, `Can not find procedure type '{0}'.` will be printed. Please check whether the type's full name includes the namespace and whether the assembly is loaded.

## Background

When `UseStartupRunner` is enabled, `Awake` still registers and holds a reference to the procedure manager through `GameFrameworkEntry.GetModule<IProcedureManager>()`, but defers the three steps of "construct procedure array → `Initialize` → `StartProcedure`" to `StartupRunner.Run` in `ApplicationStartupEntry`, thereby making procedure startup controlled by the unified startup entry orchestration, allowing serial/parallel startup with other subsystems in the unified pipeline.
