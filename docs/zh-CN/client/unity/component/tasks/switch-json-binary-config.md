# 如何在 JSON 与二进制配置之间切换

在 GameFrameX 中,`Hotfix/Config/Generate/Tables/` 下的表数据类(由 LuBan 工具生成)使用 `SimpleJSON.JSONNode` 作为反序列化入口;运行时由 `TablesComponent` 把每张表注册到 `ConfigComponent`。本页面说明在“JSON 配置”和“二进制配置”两种来源之间的切换方式。

## 前置条件

- 已在 `Packages/manifest.json` 中通过 GameFrameX scoped registry 引入 `com.gameframex.unity.json.simplejson`(参考 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/README.zh-CN.md#L40-L80))。
- 工程中已存在 `Assets/Hotfix/Config/Generate/Tables/TablesComponent.cs`,并通过 LuBan 工具生成 `ItemConfig`、`AchievementConfig`、`SoundsConfig` 等表类(见 [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86))。
- 运行时框架包 `com.gameframex.unity.config` 已安装,提供 `ConfigComponent` 与 `BaseDataTable<T>`(见 [link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28))。

## 操作步骤

1. 确认表类的反序列化构造函数签名。生成器产出的所有表类都提供一个接收 `SimpleJSON.JSONNode` 的构造函数,用于把 JSON 反序列化为表对象。

```csharp
// 来源:LuBan 生成代码
public ItemConfig(JSONNode _buf)
{
    { if(!_buf["id"].IsNumber) { throw new SerializationException(); }  Id = _buf["id"]; }
    { if(!_buf["Name"].IsString) { throw new SerializationException(); }  Name = _buf["Name"]; }
    // ... 省略其余字段
    PostInit();
}

public static ItemConfig DeserializeItemConfig(JSONNode _buf)
{
    return new Tables.ItemConfig(_buf);
}
```

Source: [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86)

2. 在 `TablesComponent` 中将每张表注册到 `ConfigComponent`。默认实现中,所有表都通过 `TbXxxConfig.LoadAsync()` 异步加载,并以表名作为键注册(见 [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L52-L70))。

```csharp
m_ConfigComponent.RemoveAllConfigs();
var loadTasks = new System.Collections.Generic.List<System.Threading.Tasks.Task>();
loadTasks.Add(TbItemConfig.LoadAsync());
m_ConfigComponent.Add(nameof(Tables.TbItemConfig), TbItemConfig);
```

3. 切换到 JSON 配置源(默认方案)。保持现有生成代码不变,只需把数据导出为 JSON 文件并交给 LuBan 加载。生成器生成的 `DeserializeXxxConfig(JSONNode)` 直接接受 JSON 文本,运行时无需额外转换。

4. 切换到二进制配置源(性能优先方案)。当热更新包或首包内只提供二进制数据时,先在加载入口把二进制流解码为 `JSONNode`,再走相同的 `DeserializeXxxConfig` 路径,以保证下游表类零改动。例如:

```csharp
using SimpleJSON;
using System.Text;

// 假设 bytes 是从 YooAsset 拿到的二进制配置包
JSONNode node = JSON.Parse(Encoding.UTF8.GetString(bytes));
var item = Tables.ItemConfig.DeserializeItemConfig(node);
```

关键点:反序列化入口仍然是 `DeserializeXxxConfig(JSONNode)`,所以 JSON 和二进制的切换等价于“在加载阶段把数据形态归一化为 JSONNode”。表类本身不需要重新生成。

5. 在运行时通过 `ConfigComponent.GetConfig<T>()` 取配置。无论底层是 JSON 还是二进制,只要表名在 `TablesComponent.Add` 时已经注册,业务层调用方式不变:

```csharp
var itemConfig = GameFrameX.Config.Runtime.ConfigComponent.Instance
    .GetConfig<Tables.ItemConfig>();
```

## 常见变体

- **热更阶段按平台切换**:Android 平台首包使用二进制压缩包以减小包体,iOS 平台或开发期使用 JSON 便于排查。只需在 `TablesComponent.Init` 之前按平台选择加载源,把得到的 `JSONNode` 传入 `DeserializeXxxConfig` 即可。
- **本地化配置**:已生成的表(例如 `TbLocalization`)走完全相同的注册流程,见 [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L70) 中 `m_ConfigComponent.Add(nameof(Local.TbLocalization), TbLocalization)`。

## 常见错误

- **直接修改生成的表类**:生成器会覆盖 `Assets/Hotfix/Config/Generate/Tables/*.cs`,所有定制逻辑应放在 `partial` 分部类或业务层。
- **修改字段名后未重新生成**:`_buf["xxx"]` 的字段名是大小写敏感的(注意 `id` 小写、`Name` 大写、`description` 小写),字段不一致会触发 `SerializationException`(见 [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L74))。
- **忘记调用 `m_ConfigComponent.Add`**:只调用 `LoadAsync()` 而未注册表名,`GetConfig<T>()` 将返回空。注册流程见 [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L69)。
- **HybridCLR AOT 裁剪问题**:新增了非泛型反射目标时,需确认 `ConfigComponent`/`BaseDataTable<T>` 已在 link.xml 中保留(见 [link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28))。

## 背景(可选)

LuBan 表生成器的产物统一以 `SimpleJSON.JSONNode` 作为反序列化入口,这一步把“数据来自 JSON 还是二进制”的差异收敛在加载层。`TablesComponent` 负责把每张表注册进 `ConfigComponent`,业务层则统一通过 `ConfigComponent.GetConfig<T>()` 拿数据,因此切换数据源不需要改动消费方。关于 LuBan 生成器与配置管线的整体位置,见工程内 `Assets/Hotfix/Config/Generate/`。
