# クライアント/サーバーのデータが分離されない場合の対処方法

次のような状況に遭遇した場合：クライアント専用のつもりのテーブルがサーバー側にも生成されてしまった、サーバー専用のテーブルなのにクライアント側にも取得された、ファイル名のプレフィックスを変更したのに両側のコード/データが分離されない——これらはいずれも「クライアント/サーバーのデータグループ化が有効になっていない」ことの典型的な症状です。このページが、迅速な問題の特定と修正をサポートします。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| サーバー側にクライアント専用のテーブルが生成された（その逆も同様） | Excel ファイル名にグループマーカーが付いておらず、デフォルトで両グループに生成される | ファイル名に `-c-`（クライアントのみ）または `-s-`（サーバーのみ）のグループセグメントを追加する |
| グループマーカーを追加したのに両側で生成される | `luban.conf` の `groups` 設定で `c` と `s` がどちらも `default: true` になっており、ファイル名からグループが解析されていない | ファイル名セグメントは `<字母>-<英文名>-<分组>-<中文名>.xlsx` の形式でなければならず、グループは `c` または `s` のみ使用可能 |
| グループを変更した後も古い生成コードが残っている | ファイル名を変更しただけで、生成スクリプトを再実行していない | `gen-client-*` と `gen-server-*` スクリプトを再実行する |
| クライアント/サーバー両方が動作しているが、片側専用にしたいフィールドがもう片側にも現れる | フィールドが側別にグループ化されていない（Excel でマークされていない）、ツールはデフォルトで両側に出力する | `__tables__.xlsx` または対応する Bean 内でフィールドに側別グループを追加する |

## 修正手順

### 1. ファイル名にグループマーカーを追加する

ファイル名の形式：`字母-英文名-分组-中文名.xlsx`。グループセグメントは `c`（クライアントのみ）または `s`（サーバーのみ）のみ使用可能です。グループを付けない場合は両側で使用することを意味します。

| ファイル名 | 効果 |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | クライアント、サーバー両方で使用（デフォルト） |
| `D-ItemConfig-c-道具表.xlsx` | クライアントのみ使用 |
| `D-ItemConfig-s-道具表.xlsx` | サーバーのみ使用 |

ファイルパスの例：[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

> `c` = client、`s` = server。中国語のグループ名や `cs`/`sc` のような2文字の組み合わせを書かないでください。ツールが認識するのは `c` と `s` だけです。

### 2. luban.conf の groups 設定を確認する

`luban.conf` の `groups` ノードは `c` と `s` の2つのグループを定義しており、両方とも `default: true` に設定されているため、**グループがマークされていない**ファイルは両側に生成されます：

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

`targets` ノードでは、`server` は `s` グループのみ、`client` は `c` グループのみ、`all` は両グループの和集合を取ります：

```json
"targets": [
    { "name": "server", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "groups": ["c","s"], "topModule": "cfg" }
]
```

完全な設定は [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L61) を参照してください。

つまり、**ファイル名によるグループ化だけでは不十分で、対応する生成スクリプトをそれぞれ実行する必要があり**、そうしてはじめて対応する側に正しく反映されるということです。

### 3. 生成スクリプトをそれぞれ実行する

- クライアント：`gen-client-json.bat` をダブルクリック（Mac/Linux：`sh gen-client-json.sh`）
- サーバー：`gen-server-json.bat` をダブルクリック（Mac/Linux：`sh gen-server-json.sh`）

スクリプトの説明は [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L265-L285) を参照してください。

### 4. フィールドレベルの側別グループ化（応用）

同じテーブル内の一部のフィールドを特定の側専用にしたい場合（例：価格はサーバーのみ、UI ヒントはクライアントのみ）、`__tables__.xlsx` / `__beans__.xlsx` 内でそのフィールドに `c` または `s` の側別グループマーカーを追加する必要があります。通常の `int`、`string` フィールドはデフォルトで両側に存在し、ツールが設定に従って自動的にトリミングします。

## 検証

上記の手順 1〜3 を完了したら、以下の方法でグループ化が有効になっていることを確認してください：

1. 出力ディレクトリを確認する：
   - クライアントのコード/データ：`Unity/Assets/Bundles/Config`（データ）、`Unity/Assets/Hotfix/Config/Generate`（コード）
   - サーバーのコード/データ：`Server/GameFrameX.Config/Json`（データ）、`Server/GameFrameX.Config/Config`（コード）
2. 出現すべきでない側のディレクトリで**テーブル名を検索**します（例：`TbItemConfig`）。見つからなければ、グループ化が有効になっていることを示します。
3. コード内でアクセスする：クライアントは `tables.TbXxx.Get(id)` を使用し、サーバーも同様に呼び出しますが、コードの名前空間が異なります（`Hotfix.Config` vs `GameFrameX.Config`）。名前空間が異なっていれば、グループ化が正しく機能していることを示します。
