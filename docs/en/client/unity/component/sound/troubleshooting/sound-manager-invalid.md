# What to Do About "Sound manager is invalid"

After running the game, the log prints `Fatal: Sound manager is invalid.`, and the sound component cannot play any audio effects. This error occurs because `SoundComponent.Awake()` gets `null` back when querying `GameFrameworkEntry` for the `ISoundManager` module, causing the subsequent initialization to return immediately.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| The log shows `Fatal: Sound manager is invalid.` after startup, and PlaySound has no effect | The `SoundManager` implementation class was not registered in the framework's module table | Set the correct `Component Type` on the `SoundComponent` Inspector (see Step 1 below) |
| The log shows `Fatal: Sound manager is invalid.` after startup, but `Component Type` is already configured | The configured class name is misspelled, or the class was stripped by code stripping / not compiled into the runtime assembly | Search the project for the class name `GameFrameX.Sound.SoundManager` and confirm the class exists and has not been removed by Stripping |
| Works fine in the Editor, but the error appears in builds | IL2CPP/Managed Stripping stripped out the `SoundManager` type | Preserve `GameFrameX.Sound.SoundManager` in `link.xml`, or disable Stripping |

## Fix Steps

### 1. Specify the implementation class on the SoundComponent Inspector

Open the scene object that has the `SoundComponent` attached, locate the `Component Type` field in the Inspector, and enter the fully qualified type name of the implementation class. `SoundComponent.Awake()` will load it reflectively by this name and register it with `GameFrameworkEntry`:

```csharp
// Runtime/Sound/SoundComponent.cs#L102-L118
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ISoundManager);
    base.Awake();
    EnsureAudioMixer();
    if (!IsRuntimeComponentReady)
    {
        return;
    }

    m_SoundManager = GameFrameworkEntry.GetModule<ISoundManager>();
    if (m_SoundManager == null)
    {
        Log.Fatal("Sound manager is invalid.");
        return;
    }
    ...
}
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L102-L132)

A typical value for `Component Type` is `GameFrameX.Sound.SoundManager` (namespace + class name; you can verify it in `Runtime/Sound/Sound/SoundManager.cs`).

### 2. Verify that the implementation class itself exists

Search for `SoundManager.cs` in the Project view and confirm that the implementation class shipped with the repository is still in the project:

```
Runtime/Sound/Sound/SoundManager.cs
```

Source: [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs)

If this file was accidentally deleted or renamed, the reflective `GetType(componentType)` will return `null`, the module table will not contain `ISoundManager`, and this error will be triggered.

### 3. Handle IL2CPP code stripping (build scenarios)

`Utility.Assembly.GetType(componentType)` relies on the runtime being able to find the type by name. IL2CPP + Managed Code Stripping may optimize away `SoundManager` during the build if it has no direct references, causing `GetType` to return `null`. Add the following to `Assets/link.xml`:

```xml
<linker>
  <assembly fullname="GameFrameX.Sound" preserve="all"/>
</linker>
```

Alternatively, set `Stripping Level` to `Low`, rebuild the package, and verify.

## Verification

1. Launch the scene and confirm that `Fatal: Sound manager is invalid.` no longer appears in the Console.
2. Call `GameEntry.GetComponent<SoundComponent>().PlaySound(...)`; you should hear the sound effect and there should be no `PlaySoundFailure` event.
3. Check whether `m_SoundManager` has been assigned: in the code path after `SoundComponent.Awake` (`Start`), `m_SoundManager != null` must hold, so that the subsequent `SetResourceManager` / `SetSoundHelper` calls can execute properly.
