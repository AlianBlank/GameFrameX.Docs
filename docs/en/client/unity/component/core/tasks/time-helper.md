# Handling Time and Date

`TimerHelper` is a static time utility class provided by the framework, split across multiple files based on `partial class`. It covers common scenarios such as Unix timestamps, timezone settings, and start/end/difference calculations by day/month/week. This article provides copy-paste-ready calling patterns.

## Prerequisites

- Namespace: `GameFrameX.Runtime`
- The target project references the `GameFrameX.Runtime` assembly ([GameFrameX.Runtime.asmdef](/Runtime/GameFrameX.Runtime.asmdef#L1-L20))
- Timezone settings require .NET `TimeZoneInfo` (internally calls `TimeZoneInfo.FindSystemTimeZoneById` when setting via ID string)

## Steps

### 1. Get Current Time

Get UTC or local time as needed. `GetNowWithUtc()` returns `DateTime.UtcNow` directly; for local time, use `DateTime.Now` or convert through the current timezone.

```csharp
using GameFrameX.Runtime;

// Current UTC time
DateTime utcNow = TimerHelper.GetNowWithUtc();

// Current UTC time string, default "yyyy-MM-dd HH:mm:ss.fff K"
string utcStr = TimerHelper.CurrentDateTimeWithUtcFormat();

// Current UTC time as HHmmss integer (e.g., 143045)
int utcInt = TimerHelper.CurrentTimeWithUtc();
```

Source: [TimerHelper.Current.UTC.cs](/Runtime/Time/TimerHelper.Current.UTC.cs#L21-L77)

### 2. Get Unix Timestamp

Choose seconds-level or milliseconds-level by precision; use the `WithTimeZoneOffset` variant when timezone offset is needed.

| Method | Return | Description |
|------|------|------|
| `UnixTimeSeconds()` | `long` | Seconds-level timestamp of current UTC time |
| `UnixTimeMilliseconds()` | `long` | Milliseconds-level timestamp of current UTC time |
| `UnixTimeSecondsWithTimeZoneOffset()` | `long` | UTC stamp + current timezone offset in seconds + `TimeOffsetSeconds` |
| `UnixTimeMillisecondsWithTimeZoneOffset()` | `long` | UTC stamp + current timezone offset in milliseconds + `TimeOffsetMilliseconds` |

```csharp
long sec  = TimerHelper.UnixTimeSeconds();          // seconds
long ms   = TimerHelper.UnixTimeMilliseconds();     // milliseconds
long sec2 = TimerHelper.UnixTimeSecondsWithTimeZoneOffset();
```

Source: [TimerHelper.cs](/Runtime/Time/TimerHelper.cs#L132-L216)

### 3. Set and Read Timezone

Set via ID string (e.g., `"China Standard Time"`, `"UTC"`); passing a `TimeZoneInfo` object is also supported. When the ID is invalid, the method returns `false` and falls back to UTC.

```csharp
// Set by ID
bool ok = TimerHelper.SetTimeZone("China Standard Time");

// Set by TimeZoneInfo
TimerHelper.SetTimeZone(TimeZoneInfo.Utc);

// Read the current timezone
TimeZoneInfo tz = TimerHelper.CurrentTimeZone;
```

Source: [TimerHelper.cs](/Runtime/Time/TimerHelper.cs#L51-L100)

### 4. Convert Between Unix Timestamp and DateTime

Convert timestamp (seconds/milliseconds) to `DateTime`, or convert in the opposite direction; the conversion is based on `EpochUtc = 1970-01-01 00:00:00 UTC`.

```csharp
long ts = TimerHelper.UnixTimeSeconds();

// Option 1: Use .NET native API
DateTime dt = DateTimeOffset.FromUnixTimeSeconds(ts).UtcDateTime;

// Option 2: Use the ticks provided by the framework
long ticks = TimerHelper.TimestampToTicks(ts);          // seconds -> Ticks
DateTime dt2 = new DateTime(ticks, DateTimeKind.Utc);

// Reverse: DateTime -> Unix timestamp (seconds)
long back = new DateTimeOffset(dt2).ToUnixTimeSeconds();
```

`TimestampToTicks` accepts a range of `-62135596800` to `253402300799` seconds; values outside this range throw `ArgumentOutOfRangeException("Timestamp is out of valid range")`.

Source: [TimerHelper.Timestamp.cs](/Runtime/Time/TimerHelper.Timestamp.cs#L96-L105)

### 5. Start/End and Difference by Day / Week / Month

Grouped methods like `Current`, `Day`, `Week`, `Month`, `Difference`, `Range`, `TimeOffset` are provided in separate files under `Runtime/Time/`; each capability comes in three flavors: UTC, Local, and by `CurrentTimeZone`. For example:

- `TimerHelper.Day.cs` / `TimerHelper.Day.UTC.cs` / `TimerHelper.Day.TimeZone.cs`
- `TimerHelper.Month.cs` / `TimerHelper.Month.UTC.cs` / `TimerHelper.Month.TimeZone.cs`
- `TimerHelper.Week.cs`
- `TimerHelper.Difference.cs` / `TimerHelper.Difference.UTC.cs` / `TimerHelper.Difference.TimeZone.cs`
- `TimerHelper.Range.cs`
- `TimerHelper.TimeOffset.cs` / `TimerHelper.TimeOffset.UTC.cs` / `TimerHelper.TimeOffset.TimeZone.cs`

When calling, match the scenario by suffix (`.UTC` uses UTC, `.TimeZone` uses `CurrentTimeZone`, no suffix uses local time).

## Common Variants

- **Timestamp with timezone offset**: When the business needs to display "UTC+8 time" as "UTC+0", use `UnixTimeSecondsWithTimeZoneOffset()` / `UnixTimeMillisecondsWithTimeZoneOffset()`. They add the offset of `CurrentTimeZone` and `TimeOffsetSeconds/Milliseconds` to the standard UTC stamp.
- **Custom time format**: Use `CurrentDateTimeWithUtcFormat(string format)` and pass a .NET standard date format string, e.g., `"yyyy/MM/dd"`, `"HH:mm"`.
- **Convert a specific time to timestamp**: `DateTimeToSecondsWithTimeZone(DateTime time)` accepts any `DateTime` and calculates based on the current timezone; when `Kind == Unspecified`, it is interpreted according to `CurrentTimeZone`.

## Common Errors

- **Misspelled timezone ID**: `SetTimeZone(string)` does not throw an exception when the ID is invalid; it returns `false` and falls back to UTC. Always check the return value to avoid silent fallback.
- **Timestamp out of range**: `TimestampToTicks` / `TimestampMillisToTicks` only accept values within the valid `DateTime` range (approximately `-62135596800` to `253402300799` seconds); passing `long.MaxValue` triggers `ArgumentOutOfRangeException`.
- **Confusing `EpochLocal` with `EpochUtc`**: `EpochLocal` is always based on the system's local timezone and does not change with `SetTimeZone`; use `EpochUtc` for UTC conversions.
- **Modifying timezone in multithreading**: `_currentTimeZone` is decorated with `volatile` to ensure visibility, but the timezone read across threads at the moment of switching may still be inconsistent; consider adding locks when switching at high frequency.

## Background

`TimerHelper` uses `partial class` to split the class with the same name across multiple files under `Runtime/Time/`, organized by "capability × timezone" — the capability dimension (Current / Timestamp / Day / Week / Month / Difference / Range / TimeZone) serves as the file prefix, and the timezone dimension (UTC / TimeZone / default Local) serves as the file suffix. All methods are marked with `[Preserve]` to prevent them from being stripped by Unity's code stripping.
