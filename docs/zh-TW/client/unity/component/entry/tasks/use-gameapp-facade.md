# 如何使用 GameApp 呼叫子系統（外觀層指南）

`GameApp` 是 GameFrameX 提供的靜態外觀類別（Facade），它將分散在各元件（Asset、Config、Event、Fsm、UI、Entity、Localization 等）中的子系統整合為靜態屬性。業務程式碼不再需要透過 `GameEntry.GetComponent<T>()` 反覆查找，只需直接呼叫 `GameApp.Asset.xxx` 即可。

## 前置需求

- 已安裝並初始化 GameFrameX 的 `GameEntry`；框架會在啟動時依照 `Enable` 清單建立各個 `Component`。
- 針對您使用的每個子系統，請確認已啟用對應的 `ENABLE_GAME_FRAME_X_*` 巨集（每個 `GameApp.*.cs` 檔案都會以該巨集包住整個 partial 區塊）；否則該屬性將不會被編譯進來。
- 業務程式碼不應持有 `Component` 的參考；請統一透過 `GameApp.xxx` 進行存取。

## 步驟

### 1. 透過靜態屬性取得子系統

每個 `GameApp.*.cs` 檔案都遵循相同的模式：內部持有一個私有的靜態欄位，對外公開一個唯讀的靜態屬性，並在首次存取時從 `GameEntry` 取得對應的 `Component` 並快取起來。

```csharp
// 取得基礎元件
var baseComp = GameApp.Base;

// 取得資源元件（需要 ENABLE_GAME_FRAME_X_ASSET 巨集）
var asset = GameApp.Asset;

// 取得設定元件（需要 ENABLE_GAME_FRAME_X_CONFIG 巨集）
var cfg = GameApp.Config;

// 取得事件元件（需要 ENABLE_GAME_FRAME_X_EVENT 巨集）
var evt = GameApp.Event;
```

### 2. 在業務程式碼中呼叫子系統方法

取得屬性後，直接呼叫對應 `Component` 的方法即可。例如，以下示範透過 `GameApp` 載入資源、讀取設定以及訂閱事件：

```csharp
// 載入資源
GameApp.Asset.LoadAsset<GameObject>("Assets/Prefabs/Hero.prefab", prefab =>
{
    // 使用 prefab ...
});

// 讀取設定
var heroHp = GameApp.Config.GetInt("Hero_HP", 100);

// 訂閱事件
GameApp.Event.Subscribe("OnPlayerLevelUp", payload =>
{
    // 處理升級事件
});
```

> 上方的 API 名稱（LoadAsset / GetInt / Subscribe）取自各元件的常見公開方法；確切的方法簽名請參閱 [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs)、[GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs) 與 [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) 中實際的 `Component` 實作。

### 3. 透過巨集開關裁減不需要的子系統

`GameApp` 中的每個子系統都以 `ENABLE_GAME_FRAME_X_<NAME>` 編譯巨集包裝。如果專案不需要某個子系統，關閉對應的巨集即可避免該屬性被編譯進來，從而有效縮減套件體積與相依性。

| 巨集（範例） | 受影響的屬性 | 檔案 |
|---|---|---|
| `ENABLE_GAME_FRAME_X_ASSET` | `GameApp.Asset` | [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs) |
| `ENABLE_GAME_FRAME_X_CONFIG` | `GameApp.Config` | [GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs) |
| `ENABLE_GAME_FRAME_X_EVENT` | `GameApp.Event` | [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) |

所有子系統都遵循相同的巨集命名慣例；確切的巨集名稱請查看每個 [Runtime/GameApp.*.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs) 檔案頂部的 `#if` 指示詞。

### 使用其他對外公開的子系統

儲存庫 `Runtime/` 目錄下的每個 `GameApp.*.cs` 檔案各對應一個子系統。常見的進入點包括：

- `GameApp.AdJust`、`GameApp.Advertisement` —— 推廣與廣告。
- `GameApp.AppleLogin`、`GameApp.FaceBookLogin`、`GameApp.GoogleLogin` —— 第三方登入。
- `GameApp.AppsFlyer`、`GameApp.GameAnalytics` —— 分析追蹤。
- `GameApp.Asset` —— 資源載入。
- `GameApp.Config` —— 設定讀取。
- `GameApp.Coroutine` —— 協程。
- `GameApp.Download` —— 下載。
- `GameApp.Entity` —— 實體。
- `GameApp.Event` —— 事件。
- `GameApp.FairyGUIPackage` —— FairyGUI 套件。
- `GameApp.Fsm` —— 狀態機。
- `GameApp.GlobalConfig` —— 全域設定。
- `GameApp.GUI` —— UI 介面。
- `GameApp.Guide` —— 新手教學。
- `GameApp.Localization` —— 本地化。

呼叫模式都相同：確認巨集已啟用後，即可使用 `GameApp.<Name>` 取得對應的 `Component`。

## 常見錯誤

- **找不到屬性／編譯錯誤指出 `GameApp` 不包含 `xxx` 的定義**：很可能是對應的 `ENABLE_GAME_FRAME_X_*` 巨集未啟用，或對應的 `GameApp.*.cs` 未被編譯進專案。請先在 `Scripting Define Symbols` 或 `asmdef` 中啟用該巨集。
- **在 `GameEntry` 啟動前存取屬性**：`GameApp` 透過 `GameEntry.GetComponent<T>()` 取得元件；若框架初始化尚未完成，將會取得 `null`，後續呼叫便會拋出 null 參考例外。請務必只在 `GameEntry` 完成啟動後才存取 `GameApp.xxx`。
- **自行 `new` 一個 `Component` 而非透過外觀層**：`GameApp` 的靜態欄位是快取，僅與透過 `GameEntry.GetComponent<T>()` 取得的實例保持一致；您自行 `new` 出來的實例無法透過外觀層取得，將造成兩份彼此不同步的狀態。
- **跨場景持有靜態欄位**：`GameApp` 中的欄位目前是處理序層級的靜態快取，設計上供整個處理序生命週期使用；請勿在場景切換時嘗試手動重置它們。

## 背景（選讀）

`GameApp` 由多個 `partial class` 檔案組成（每個 `Runtime/GameApp.*.cs` 實作一個子系統屬性）。它透過延遲載入 + `GameEntry.GetComponent<T>()` 統一取得元件實例，既保留了單例元件的全域存取能力，又避免了 `GameEntry.GetComponent<T>()` 樣板呼叫散落在整個業務層各處——這是外觀（Facade）模式在本框架中的典型應用。

有關框架整體啟動流程以及 `GameEntry` 的角色，請參閱「總覽」頁面。
