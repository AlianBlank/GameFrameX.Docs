# 如何执行生成脚本(客户端/服务端)

执行仓库根目录下的 `gen-*.bat` 或 `gen-*.sh` 脚本,即可把 `Excels/` 下的 Excel 表自动转成客户端(Unity)或服务端(.NET)能直接用的代码与数据文件。本页给出四类脚本的差异、最小执行步骤,以及常见出错的修法。

## 四个生成脚本一览

仓库自带 4 个生成入口,按 **目标端**(`client` / `server`)和 **输出格式**(`bin` / `json`)组合而成:

| 脚本 | 目标端 | 数据格式 | 代码格式 | 输出位置(数据 / 代码) |
|------|--------|----------|----------|------------------------|
| `gen-client-bin.sh` / `.bat` | 客户端 | 二进制(`bin`) | C# 二进制序列化(`cs-bin`) | `../Unity/Assets//Bundles/Config` / `../Unity/Assets//Hotfix/Config/Generate` |
| `gen-client-json.sh` / `.bat` | 客户端 | JSON | C# | `Unity/Assets/Bundles/Config` / `Unity/Assets/Hotfix/Config/Generate` |
| `gen-server-bin.sh` / `.bat` | 服务端 | 二进制(`bin`) | C# .NET 二进制序列化(`cs-dotnet-bin`) | `../Server/GameFrameX.Config/Json` / `../Server/GameFrameX.Config/Config` |
| `gen-server-json.sh` / `.bat` | 服务端 | JSON | C# | `Server/GameFrameX.Config/Json` / `Server/GameFrameX.Config/Config` |

> `c` = 客户端(client),`s` = 服务端(server),`bin` = 二进制,`json` = 文本。同一端下,`bin` 体积更小、加载更快;`json` 可读、便于排查数据。

## 前置条件

- 已安装 **.NET SDK**(因为脚本通过 `dotnet` 启动 `./Tools/Luban.dll`)。
- 仓库里的 `Tools/Luban.dll`、`luban.conf`、`Defines/builtin.xml`、`Excels/__tables__.xlsx`(及 `__beans__`、`__enums__`)必须在原位,不要移动。
- 表已按规则填好(`Excels/Tables/` 里的表名格式为 `字母-英文名-中文名.xlsx`,英文名不能含中文)。

## 操作步骤

1. 打开终端 / 命令行,**`cd` 到仓库根目录**(能看到 `gen-*.sh`、`gen-*.bat` 的那一层)。脚本里的相对路径都基于此目录,不要在子目录里跑。

2. 选择你的目标端和输出格式,执行对应脚本:

   - **客户端生成 JSON(最常用的入门命令):**

     ```bash
     sh gen-client-json.sh
     ```

     对应的 Windows 命令是双击 `gen-client-json.bat`。

   - **客户端生成二进制:**

     ```bash
     sh gen-client-bin.sh
     ```

     [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1) 的核心调用是:

     ```bash
     dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin \
       --xargs outputDataDir=../Unity/Assets//Bundles/Config \
       --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
       --xargs tableImporter.name=gameframex \
       -x l10n.provider=gameframex \
       -x l10n.textFile.keyFieldName=key \
       -x l10n.textFile.path=./Excels/Local/ \
       --conf ./Luban.conf
     ```

     Source: [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1)

   - **服务端生成二进制:**

     ```bash
     sh gen-server-bin.sh
     ```

     实际调用见 [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1):

     ```bash
     dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin \
       --xargs outputDataDir=../Server/GameFrameX.Config/Json \
       --xargs tableImporter.name=gameframex \
       --xargs outputCodeDir=../Server/GameFrameX.Config/Config \
       --conf ./Luban.conf
     ```

     Source: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1)

   - **服务端生成 JSON:** 执行 `sh gen-server-json.sh`(对应 `.bat`)。

3. 等待脚本跑完。如果最后停在 `pause`(Windows `.bat`)或没有红色报错就算成功。

4. 验证产物:
   - 客户端:`Unity/Assets/Hotfix/Config/Generate/` 下应有自动生成的 C# 类(如 `TbAchievementConfig.cs`),`Unity/Assets/Bundles/Config/` 下应有数据文件。
   - 服务端:`Server/GameFrameX.Config/Config/` 下是 C# 类,`Server/GameFrameX.Config/Json/` 下是数据文件。

## 常见变体

- **只想给某一端生成:** 给表名加分组标记即可,不需要换脚本。例如 `D-ItemConfig-道具表.xlsx` 客户端服务端都生成;`D-ItemConfig-c-道具表.xlsx` 只给客户端;`D-ItemConfig-s-道具表.xlsx` 只给服务端。详见 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md)。
- **改了多语言文本(Excels/Local/):** 直接重新跑同一个脚本即可,无需重启任何东西。
- **改了表头(字段名/类型):** 重跑脚本 → 重新生成代码 → 在调用方按新字段名编译。
- **bin 与 json 切换:** 同一目标端,把 `gen-client-bin.sh` 换成 `gen-client-json.sh` 再跑一遍即可。客户端运行时若切换格式,记得同步更新加载代码。

## 常见错误

- **`'dotnet' is not recognized` / `dotnet: command not found`**:未安装 .NET SDK,或终端没在 PATH 里找到。先安装 .NET 6+ SDK,再重新打开终端。
- **`Could not find ./Tools/Luban.dll`**:当前目录不对。`cd` 到包含 `Tools/` 的仓库根目录再跑。
- **`不支持中文表名` / 类名变怪字符**:文件名里英文段写了中文。改成 `字母-英文名-中文名.xlsx`,英文名只保留字母数字下划线。
- **输出目录里有旧文件残留、引用了已删的字段**:直接把 `outputCodeDir` 指向的目录(如 `Unity/Assets/Hotfix/Config/Generate/`)整体删除,然后重跑脚本。
- **`failed: conf file` / 配置报错**:动了 `luban.conf` 导致解析失败。从 Git 恢复该文件后重试,不要随意改顶层字段。
- **多语言 key 在 `text` 字段里读出来还是 key 本身**:确认执行的是 `gen-client-bin.sh` 或带 `-x l10n.provider=gameframex -x l10n.textFile.path=./Excels/Local/` 那一组参数,而不是只用了 `--conf ./Luban.conf` 的命令。

## 背景(可选)

四个脚本本质都是调用 `dotnet ./Tools/Luban.dll`,区别只在三个开关:`--target`(决定是 client 还是 server 的代码模板与数据类型映射)、`--dataTarget`(决定数据落盘格式 `bin` 或 `json`)、`--codeTarget`(决定生成的 C# 序列化方式,如 `cs-bin`、`cs-dotnet-bin`)。`outputDataDir` 与 `outputCodeDir` 控制产出落盘位置,`--conf ./Luban.conf` 指向工程级配置。`gen-client-bin.sh` 比 `gen-server-bin.sh` 多了几条 `-x l10n.*` 参数,是因为 Unity 端需要把 `text` 字段的多语言 key 直接解析成当前语言的字符串,所以脚本里显式注入了本地化提供者。
