# 씬 우선순위 설정 및 활성 씬 전환 방법

`SceneComponent.SetSceneOrder`를 통해 로드된 / 로드 중인 씬에 숫자 값을 할당하면, 프레임워크는 조정할 때마다 값이 가장 큰 씬을 Unity의 활성 씬(`SceneManager.SetActiveScene`)으로 자동 설정하고 `ActiveSceneChangedEventArgs` 이벤트를 발생시킵니다. 주로 Additive 모드에서 여러 씬이 공존할 때 어떤 씬을 논리적 메인 씬으로 할지 정확하게 제어하는 데 사용됩니다.

## 사전 조건

- 프로젝트에 GameFrameX 씬 컴포넌트(`[AddComponentMenu("GameFrameX/Scene")]`의 `SceneComponent`)와 YooAsset 에셋 관리가 연동되어 있어야 합니다.
- 씬 에셋 경로는 반드시 `Assets/`로 시작하고 `.unity`로 끝나야 합니다(프레임워크가 검증하며, 그렇지 않으면 `Scene asset name '{0}' is invalid.`를 출력합니다).
- `SetSceneOrder`를 호출하기 전에 해당 씬이 이미 '로드 중' 또는 '로드됨' 상태여야 합니다. 그렇지 않으면 프레임워크가 `Scene '{0}' is not loaded or loading.`를 출력하고 이번 설정을 무시합니다.
- 전환 결과를 수신해야 하는 경우 `ActiveSceneChangedEventArgs` 이벤트를 등록해야 합니다(《씬 로드 및 언로드 방법》 참조).

## 작업 단계

1. **씬 컴포넌트 가져오기**. `GameEntry`에 접근할 수 있는 임의의 스크립트에서:

```csharp
using GameFrameX.Scene.Runtime;

var sceneComponent = GameEntry.GetComponent<SceneComponent>();
```

출처: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L49-L50)

2. **Additive 모드로 씬 로드**. 활성 씬 전환은 여러 개의 로드된 씬이 공존해야 하므로, 일반적으로 `LoadSceneMode.Additive`를 사용합니다:

```csharp
await sceneComponent.LoadScene(
    "Assets/Scenes/Battle.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
```

출처: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L294-L322)

3. **씬에 우선순위 할당**. 값이 클수록 우선순위가 높으며, 값이 같을 때는 `m_SceneOrder`(`SortedDictionary<string,int>`)의 열거 순서로 우열이 결정됩니다:

```csharp
// Battle을 최고 우선순위로 설정하면 활성 씬으로 전환됩니다
sceneComponent.SetSceneOrder("Assets/Scenes/Battle.unity", 100);

// HUD 씬을 하나 더 로드하되, 우선순위는 조금 낮게 설정합니다
await sceneComponent.LoadScene(
    "Assets/Scenes/HUD.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
sceneComponent.SetSceneOrder("Assets/Scenes/HUD.unity", 10);
```

출처: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L352-L381)

4. **활성 씬 전환 이벤트 구독**(선택 사항, 전환 후 UI나 카메라를 새로고침하거나 메인 카메라 참조를 다시 전달할 때 사용):

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Scene.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    ActiveSceneChangedEventArgs.EventId,
    (sender, args) =>
    {
        var e = (ActiveSceneChangedEventArgs)args;
        UnityEngine.Debug.Log($"Active: {e.ActiveSceneName} (prev: {e.LastActiveSceneName})");
        sceneComponent.RefreshMainCamera(); // Camera.main을 다시 가져옵니다
    });
```

출처: [ActiveSceneChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/ActiveSceneChangedEventArgs.cs)

## 일반적인 변형

**순서 조정 즉시 적용**: `SetSceneOrder`는 내부의 `RefreshSceneOrder()`를 호출하여 우선순위가 가장 높고 로드된 씬을 활성 씬으로 설정합니다. 새 씬이 아직 `isLoaded==false` 비동기 윈도우 기간에 있다면, 프레임워크는 `RefreshSceneOrderWhenLoadedCo` 코루틴을 시작해 다음 프레임에 활성화합니다.

**활성 후보가 없을 때**: `m_SceneOrder`가 비어 있거나 등록된 모든 씬이 여전히 로드 중이라면, 프레임워크는 활성 씬을 GameFramework 자체 씬(`m_GameFrameworkScene`)으로 되돌립니다.

**여러 씬이 동등한 우선순위일 때**: 두 씬의 우선순위가 같으면 열거 순서가 뒤에 있는 씬이 이깁니다(`RefreshSceneOrder`가 `>` 비교 후 덮어쓰기 때문).

## 일반적인 오류

| 현상 | 원인 | 처리 방법 |
|------|------|------|
| `SetSceneOrder` 호출 후 적용되지 않고 로그에 `Scene '{0}' is not loaded or loading.` 출력 | 씬이 '로드 중'도 '로드됨' 상태도 아님 | 먼저 `await LoadScene(...)`를 실행한 후 순서 설정 |
| 경로를 잘못 입력하고 로그에 `Scene asset name '{0}' is invalid.` 출력 | 에셋 이름이 `Assets/`로 시작하지 않거나 `.unity`로 끝나지 않음 | 완전한 프로젝트 상대 에셋 경로 사용 |
| `ArgumentException: sceneHandle.IsValid` 유형의 예외 발생 | YooAsset `await` 완료 시점이 Unity 씬 `isLoaded==true`보다 빠름 | 프레임워크가 이미 `RefreshSceneOrder` 내부에서 코루틴으로 다음 프레임까지 지연 처리하므로 직접 재시도할 필요 없음 |
| `SetSceneOrder`를 반복 연속 호출해도 이전 코루틴이 계속 실행됨 | 프레임워크는 이전 코루틴을 `StopCoroutine`한 후 새 코루틴을 시작함 | 수동 관리 불필요. 사용자 정의 로직에서 다른 활성화 방식을 혼용하는 경우 프레임워크와 경합하지 않도록 주의 |
| 활성 씬 전환 후에도 `Camera.main`이 여전히 이전 카메라를 가리킴 | 전환은 Scene만 교체할 뿐 새 카메라를 능동적으로 찾지 않음 | `sceneComponent.RefreshMainCamera()` 호출, 또는 `ActiveSceneChangedEventArgs` 구독 후 새로고침 |

## 배경(선택 사항)

`m_SceneOrder`는 키를 `Ordinal`로 비교하는 `SortedDictionary<string, int>`입니다. `RefreshSceneOrder`는 이를 순회하며 최대값을 찾은 다음, private 메서드 `SetActiveScene(...)`을 호출하여 씬을 Unity `SceneManager.SetActiveScene`에 넘기고, `m_EventComponent.Fire(this, ActiveSceneChangedEventArgs.Create(...))`를 통해 이벤트를 발생시킵니다. Single 모드에서는 YooAsset/Unity가 활성 씬을 자체적으로 관리하며, 프레임워크는 대상 Scene 핸들이 무효가 된 것을 감지하면 이번 설정을 건너뛰어 비동기 윈도우 기간에 `ArgumentException`이 발생하는 것을 방지합니다.
