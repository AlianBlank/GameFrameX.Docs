# 小游戏平台宏定义错误怎么办

当你调用 `ApplicationHelper.IsWebGLWeChatMiniGame`（或其它 `IsWebGLXxxMiniGame` 系列属性）时，无论当前是否真的在某个小游戏平台下运行，都返回 `false`——这通常意味着对应的宏定义没有正确生效。本文给出常见的报错症状、根因与修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `IsWebGLWeChatMiniGame` 等属性在真机里始终为 `false` | 没有在 **Project Settings → Player → Other Settings → Scripting Define Symbols** 添加对应的 `ENABLE_*_MINI_GAME` 宏 | 按平台宏名称表把对应宏加入 Scripting Define Symbols |
| 添加了宏，但属性仍为 `false`（WebGL 平台） | 没有切到 WebGL 平台；宏仅在 `UNITY_WEBGL` 下生效 | File → Build Settings → Switch Platform → WebGL |
| 编译报错：`The type or namespace name 'EnableWebglMiniGame' could not be found` | 直接写成了 `#define ENABLE_WEBGL_MINI_GAME`，但宏应通过 Scripting Define Symbols 配置 | 改用 Project Settings 配置，不要在源码里 `#define` |
| 编译警告或代码被错误地剥离（IL2CPP / AOT） | 用 `#if` 直接判断宏却忘了同步标记 `[UnityEngine.Scripting.Preserve]` | 确认调用方已被保留，参考 `ApplicationHelper.MiniGame.cs` 的属性写法 |
| 切换平台后宏未生效 | Unity 需要触发一次脚本重编译，IDE 缓存未刷新 | 关闭并重开 IDE / `Assets → Reimport All` |

## 修复步骤

### 1. 打开 Scripting Define Symbols 配置

`Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`。选择目标平台后，在文本框里添加需要的宏；多个宏用英文分号分隔，例如：

```text
ENABLE_WEBGL_MINI_GAME;ENABLE_WECHAT_MINI_GAME
```

来源：见 [ApplicationHelper.MiniGame.cs#L17-L23](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L17-L23) 中使用的宏 `ENABLE_WEBGL_MINI_GAME`。

### 2. 确认平台已切到 WebGL

所有 `IsWebGL*MiniGame` 属性的判断都是 `#if UNITY_WEBGL && ENABLE_<PLATFORM>_MINI_GAME`，若当前 Active Build Target 不是 WebGL，预处理器分支会直接返回 `false`。

打开 `File → Build Settings`，在左侧平台列表中选择 **WebGL**，然后点击 **Switch Platform**。完成后 Unity 会触发一次全量重编译。

### 3. 按平台选择正确的宏名称

框架支持的所有小游戏宏名称如下（均需搭配 `UNITY_WEBGL`）：

| 平台 | 宏名称 | 对应属性 |
|------|--------|----------|
| WebGL 小游戏（通用） | `ENABLE_WEBGL_MINI_GAME` | `IsWebGLMiniGame` |
| 微信小游戏 | `ENABLE_WECHAT_MINI_GAME` | `IsWebGLWeChatMiniGame` |
| 支付宝小游戏 | `ENABLE_ALIPAY_MINI_GAME` | `IsWebGLAlipayMiniGame` |
| 抖音小游戏 | `ENABLE_DOUYIN_MINI_GAME` | `IsWebGLDouYinMiniGame` |
| 快手小游戏 | `ENABLE_KUAISHOU_MINI_GAME` | `IsWebGLKuaiShouMiniGame` |
| 百度小游戏 | `ENABLE_BAIDU_MINI_GAME` | `IsWebGLBaiduMiniGame` |
| 京东小游戏 | `ENABLE_JINGDONG_MINI_GAME` | `IsWebGLJingDongMiniGame` |
| 淘宝小程序 | `ENABLE_TAOBAO_MINI_GAME` | `IsWebGLTaobaoMiniGame` |
| 美团小游戏 | `ENABLE_MEITUAN_MINI_GAME` | `IsWebGLMeituanMiniGame` |
| Bilibili 小游戏 | `ENABLE_BILIBILI_MINI_GAME` | `IsWebGLBilibiliMiniGame` |
| Discord 小游戏 | `ENABLE_DISCORD_MINI_GAME` | `IsWebGLDiscordMiniGame` |
| YouTube 小游戏 | `ENABLE_YOUTUBE_MINI_GAME` | `IsWebGLYouTubeMiniGame` |
| Facebook 小游戏 | `ENABLE_FACEBOOK_MINI_GAME` | `IsWebGLFacebookMiniGame` |
| Google Play 小游戏 | `ENABLE_GOOGLE_PLAY_MINI_GAME` | `IsWebGLGooglePlayMiniGame` |

来源：[ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs) 中各属性的 `#if UNITY_WEBGL && ENABLE_*_MINI_GAME` 定义。

### 4. 在代码中调用对应属性

不要自己再用 `#if` 嵌套判断宏——这样容易遗漏。直接调用 `ApplicationHelper` 上的属性即可：

```csharp
using GameFrameX.Runtime;

if (ApplicationHelper.IsWebGLWeChatMiniGame)
{
    // 微信小游戏专用逻辑
}
else if (ApplicationHelper.IsWebGLDouYinMiniGame)
{
    // 抖音小游戏专用逻辑
}
```

源码示例（微信小游戏分支）：

```csharp
[UnityEngine.Scripting.Preserve]
public static bool IsWebGLWeChatMiniGame
{
    get
    {
#if UNITY_WEBGL && ENABLE_WECHAT_MINI_GAME
        return true;
#else
        return false;
#endif
    }
}
```

Source: [ApplicationHelper.MiniGame.cs#L33-L43](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L33-L43)

## 验证

1. 在 `Awake()` 或调试按钮里加一行 `Debug.Log($"WeChat={ApplicationHelper.IsWebGLWeChatMiniGame}")`，运行后查看 Console。
2. 切换 WebGL 与非 WebGL 平台分别打 Log，预期非 WebGL 下全部为 `false`；WebGL 下应仅当前配置宏的平台为 `true`。
3. 仍为 `false` 时回到诊断表逐项核对：平台是否 WebGL、宏名是否拼写正确、是否触发重编译。

## 背景

框架为每个小游戏平台暴露一个静态属性（统一位于 `GameFrameX.Runtime.ApplicationHelper`），通过 `UNITY_WEBGL` 与各平台宏的组合在编译期决定返回 `true`/`false`，从而在 IL2CPP / AOT 裁剪时也能正确生效。属性的真实源文件可参考 [ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs)。
