# 连接失败或连接中断怎么办

连接失败或连接中断时，GameFrameX Network 会通过 `NetworkErrorEventArgs`（含 `ErrorCode`、`SocketErrorCode`、`ErrorMessage`）以及 `NetworkConnectedEventArgs` / `NetworkClosedEventArgs` 连接状态事件，把错误码与 `NetworkCloseReason` 关闭原因抛给上层。先订阅这些事件拿到错误码，再对照下表的错误码/关闭原因定位并修复。

## 快速诊断

| 症状（错误码 / 关闭原因） | 根因 | 修复 |
|------|------|------|
| 关闭原因为 `ConnectAddressError` | 服务器地址或端口格式错误（如 URL 缺少 scheme、端口越界） | 核对连接地址，见下文「检查地址与端口」 |
| 关闭原因为 `ConnectAddressExceptionError` | 地址解析抛出异常（如非法 IP 字符串、DNS 失败） | 换成合法地址并验证解析，见下文「检查地址与端口」 |
| 错误码 `AddressFamilyError` | 配置的 `AddressFamily` 与地址实际族不匹配（IPv4/IPv6 不一致） | 让通道的 AddressFamily 与服务器地址一致，见下文「核对 AddressFamily」 |
| 错误码 `ConnectError`，`SocketErrorCode` 为 `ConnectionRefused` / `TimedOut` | 服务器未监听、防火墙拦截或网络不可达 | 确认服务端已启动并放行端口 |
| 错误码 `SocketError` / `SendError` / `ReceiveError` | 底层 Socket 在收发阶段出错 | 按 `SocketErrorCode` 定位，常见为连接已被对端关闭后继续收发 |
| 关闭原因为 `MissHeartBeat`，错误码 `MissHeartBeatError` | 心跳超时被判定掉线 | 调整心跳间隔并检查「焦点控制心跳」配置，见下文「排查心跳掉线」 |
| 关闭原因为 `Timeout`（WebSocket） | WebSocket 建连超时触发保护关闭 | 检查 ws/wss 地址与服务端握手耗时，必要时升级到含连接超时保护的版本（见 CHANGELOG） |

以上错误码与关闭原因均为源码中的真实定义，完整取值见 [NetworkErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkErrorCode.cs#L38-L136)：

## 修复步骤

### 第一步：订阅错误与关闭事件，拿到真实错误码

`NetworkComponent` 初始化时已把通道事件桥接到 `m_NetworkManager` 的 `NetworkConnected` / `NetworkClosed` 等事件上：

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L108-L110)

错误事件携带三个诊断字段，`SocketErrorCode` 是 `System.Net.Sockets.SocketError` 原始值：

```csharp
public INetworkChannel NetworkChannel { get; private set; }
public NetworkErrorCode ErrorCode { get; private set; }
public SocketError SocketErrorCode { get; private set; }
public string ErrorMessage { get; private set; }

public static NetworkErrorEventArgs Create(INetworkChannel networkChannel, NetworkErrorCode errorCode, SocketError socketErrorCode, string errorMessage)
```

Source: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L71-L104)

在错误回调里打印 `ErrorCode`、`SocketErrorCode`、`ErrorMessage` 三个值，再对照上方诊断表。

### 检查地址与端口

1. 若关闭原因出现 `ConnectAddressError` 或 `ConnectAddressExceptionError`，先确认地址字符串本身合法：TCP 用 `IP:端口`，WebSocket 用 `ws://host:port` 或 `wss://host:port`。
2. 在与 Unity 同网的机器上用 `telnet host port`（TCP）或浏览器直接访问（WebSocket）验证服务端可达；不通则先解决服务端监听或防火墙问题。
3. 确认没有同时发起多个使用同一地址的通道实例导致服务端主动拒绝。

### 核对 AddressFamily

`AddressFamilyError` 表示配置的地址族与实际地址不匹配。常见于服务器地址是 IPv6（或域名解析为 IPv6），而通道按 IPv4（`InterNetwork`）去连接。让通道初始化时使用的 `NetworkAddressFamily` 与服务器地址实际族一致即可消除该错误。可选族定义见 [NetworkAddressFamily.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkAddressFamily.cs)。

### 排查心跳掉线

1. 出现 `MissHeartBeat` / `MissHeartBeatError` 时，说明通道在预期时间内未收到心跳回复，组件按"缺失心跳"关闭了连接。
2. 本包支持"焦点控制心跳"（应用切后台暂停心跳、回前台恢复），确认发后台/回前台逻辑与服务器超时阈值匹配：切后台太久会被服务端判超时。
3. 适当加大心跳间隔上限或服务器侧超时时间，再复测。

## 验证

- 重新连接后，`NetworkConnected` 事件正常触发，且一段时间内不再收到 `NetworkErrorEventArgs` 或 `NetworkClosedEventArgs`（原因非 `Normal`）。
- 对 WebSocket 通道，长时间挂起（切后台再回前台）不再出现 `Timeout` 关闭。
- 心跳场景下不再触发 `NetworkMissHeartBeatEventArgs` 事件（见 [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs)）。

## 背景

错误与关闭被拆成两条事件链：瞬时错误走 `NetworkErrorEventArgs`（细粒度错误码 + 原始 `SocketError`），连接生命周期走 `NetworkConnectedEventArgs` / `NetworkClosedEventArgs`（含 `NetworkCloseReason`）。CHANGELOG 中已修复过 WebSocket 连接超时保护、连接事件顺序、`SystemTcpNetworkChannel` 接收失败处理等问题，遇到诡异掉线先确认包版本为最新，详见 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md)。
