# Bot クライアントを使った連携テストと負荷テストの方法

`GameFrameX.Client` は独立した .NET コンソールプログラムで、ロボットプレイヤー群を同時にゲームサーバーへ接続させ、「アカウントログイン → キャラクター一覧 → キャラクター作成/ログイン」の全フローを自動的に実行します。`EnableDisconnectLoop` と組み合わせることで再接続のループも可能で、連携テストの検証や負荷テストによく使われます。

## 前提条件

- ログイン可能なゲームサーバー（デフォルトでは `127.0.0.1:49100` をリッスンする TCP ゲートウェイを想定）。
- HTTP ログインゲートウェイが有効化されていること（デフォルトは `http://127.0.0.1:48080/game/api/`、`BotRunOptions.LoginUrl` で指定）。
- .NET SDK 10 がインストールされていること（スクリプトは `dotnet run --framework net10.0` を呼び出します）。
- アカウントのパスワードはテストフィクスチャのデフォルトパスワード `12312`（定数 `DefaultBotLoginSecret`）を使用し、すべてのロボットで共有されます。`--login-password` で上書き可能です。

## 手順

1. **リポジトリのルートディレクトリに移動する**（スクリプトが相対パスでプロジェクトファイルを特定します）：

   ```bash
   cd GameFrameX.Server.Source
   ```

2. **マルチ Bot スクリプトを直接実行する**（負荷テスト用の推奨エントリポイントで、デフォルト値が自動設定され、実行パラメータが出力されます）：

   ```bash
   bash scripts/multi/run-bots-rpc.sh
   ```

   スクリプト内部で最終的に `dotnet run` を呼び出し、環境変数をコマンドライン引数として透過します。

   Source: [scripts/multi/run-bots-rpc.sh](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/scripts/multi/run-bots-rpc.sh#L1-L37)

3. **`dotnet run` で手動起動する**（連携テスト時はより柔軟に対応できます）：

   ```bash
   dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
     --bot-count=50 \
     --tcp-host=127.0.0.1 \
     --tcp-port=49100 \
     --login-url=http://127.0.0.1:48080/game/api/ \
     --scenario=login
   ```

   `--scenario` はカンマ区切りで複数のシナリオ名を受け付けます（例：`login,friend`）。有効化の判定は `BotRunOptions.HasScenario` で行います。

   Source: [GameFrameX.Client/Bot/BotRunOptions.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotRunOptions.cs#L31-L70)

4. **出力ログを観察する**：各 Bot がログインフローを完了すると、`[METRICS] connect=… auth=… list=… create=… login=… total=…`（ミリ秒）という行を出力し、各段階の所要時間を評価できます。

   Source: [GameFrameX.Client/Bot/BotClient.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotClient.cs#L184-L187)

## よくあるバリエーション

- **小規模な連携テスト（業務フローの検証）**：Bot 数を 5〜10 に減らし、`--run-seconds=60`、切断ループを無効化 `--disconnect-loop=false` にして、ログを人の目で確認しやすくします。

  ```bash
  dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
    --bot-count=5 --run-seconds=60 --disconnect-loop=false
  ```

- **接続型負荷テスト（ゲートウェイを満杯にする）**：デフォルトの切断ループを維持し、stagger 間隔を 5〜10ms に短縮して、Bot に継続的に再接続させゲートウェイの安定性を検証します：

  ```bash
  bash scripts/multi/run-bots-rpc.sh
  # デフォルト BOT_COUNT=100、CONNECT_STAGGER_MS=10、RUN_SECONDS=180
  ```

- **カスタム環境での負荷テスト**：環境変数でスクリプトのデフォルトパラメータを上書きします。例えばテストサーバーへ接続して 300 秒実行する場合：

  ```bash
  BOT_COUNT=200 RUN_SECONDS=300 TCP_HOST=10.0.0.5 TCP_PORT=49100 \
    bash scripts/multi/run-bots-rpc.sh
  ```

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| Bot 起動後すぐに `EntryAsync Error: …` を出力する | TCP ゲートウェイに到達できない、またはポートが占有されている | `TcpHost`/`TcpPort` を確認し、ゲームサーバーが起動してリッスンしていることを確認 |
| ログに `账号登录失败，错误码:非0` が繰り返し表示される | ログインゲートウェイが有効化されていない、またはパスワードが一致していない | `LoginUrl` にアクセスできるか、`--login-password` がサーバー側の検証と一致しているか確認 |
| `[METRICS]` のフィールドが常に欠落している（例：`list=-1`） | その段階に進んでいない（アカウントや前段の処理が失敗） | 直前の ERROR ログを遡って上流の失敗原因を特定 |
| サーバー側の接続数がすぐに上限に達する | stagger 間隔が小さすぎる、または Bot 数が多すぎる | `--connect-stagger-ms` を大きくするか、`--bot-count` を減らす |

## 補足（任意）

`BotClient` は内部で `BotTcpClient` を使ってゲームサーバー TCP ゲートウェイへの長接続を 1 本維持します。接続確立後すぐに `ReqLogin` を送信し、サーバーから `RespLogin` が返るとキャラクター一覧の要求をトリガーし、必要に応じて `ReqPlayerCreate` / `ReqPlayerLogin` を実行します。ログイン成功後は `EnableDisconnectLoop=true` の場合に切断・再接続を 1 回スケジュールします。すべての Bot は同じ `BotRunOptions`（接続アドレス、ポート、パスワード、シナリオの有効/無効など）を共有し、`BotRunOptions.Parse` を通じてコマンドラインからの上書き値を読み込みます。指標は `LogHelper.Info` で `[METRICS]` プレフィックス付きで出力され、スクリプトでの集計が容易になっています。
