# 설정 저장 및 불러오기

GameFrameX 설정 컴포넌트를 사용하여 게임 설정(플레이어 환경설정, 레벨 매개변수 등)을 영구 백엔드에 저장하고, 필요할 때 다시 읽어옵니다. 이 페이지에서는 Unity 프로젝트 내에서 저장 및 불러오기를 수행하는 최소 경로를 안내합니다.

## 사전 조건

- `com.gameframex.unity.setting` 패키지를 Unity 프로젝트로 가져왔습니다.
- 씬에 `GameFrameX/Setting` 컴포넌트(`SettingComponent`)가 부착되어 있어야 합니다. 이 컴포넌트는 `Start` 시 자동으로 `Load()`를 호출하며, `m_SettingHelperTypeName`을 통해 기본 `PlayerPrefsSettingHelper`를 선택합니다.

## 작업 단계

1. **기본 Helper 타입 확인**. `SettingComponent`는 기본적으로 `PlayerPrefsSettingHelper`를 사용하므로 별도 수정 없이 PlayerPrefs에서 읽고 쓸 수 있습니다. 미니게임 플랫폼으로 전환하려면 Inspector에서 `Setting Helper Type Name`을 해당 `AlipayMiniGameSettingStorage` / `DouYinMiniGameSettingStorage` / `KuaiShouMiniGameSettingStorage` / `WeChatMiniGameSettingStorage`로 변경하세요.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L100)

2. **설정 쓰기**. `SettingComponent`의 `SetXxx` 시리즈 메서드를 통해 값을 메모리에 저장합니다:

   ```csharp
   using GameFrameX.Setting.Runtime;

   var setting = GameFrameXEntry.GetComponent<SettingComponent>();
   setting.SetBool("MusicOn", true);
   setting.SetInt("Level", 3);
   setting.SetString("PlayerName", "Alice");
   setting.SetFloat("Volume", 0.8f);
   ```

   쓰기 메서드는 메모리만 수정하며 즉시 디스크에 저장되지 않습니다.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L225-L228)

3. **Save() 호출하여 디스크에 저장**. 적절한时机(예: 게임 종료, 씬 전환 전)에 다음을 실행합니다:

   ```csharp
   setting.Save();
   ```

   `PlayerPrefsSettingHelper.Save()`는 현재 플랫폼의 `ISettingStorageBackend.Save()`에 위임하여 실제 쓰기를 수행합니다. 반환값은 저장 성공 여부를 나타내며, 디버깅 시 로그를 출력하여 확인할 수 있습니다.

   Source: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L99-L102)

4. **설정 읽기**. `SettingComponent.Start()`에서 이미 `Load()`를 호출했으므로, 다음에 씬에 진입하면 `GetXxx`를 사용하여 읽을 수 있습니다:

   ```csharp
   bool musicOn = setting.GetBool("MusicOn", true);     // 기본값 포함
   int level   = setting.GetInt("Level", 1);
   string name = setting.GetString("PlayerName", "");
   float vol   = setting.GetFloat("Volume", 1.0f);
   ```

   각 `GetXxx`는 기본값을 포함한 오버로드를 제공하며, 키가 존재하지 않을 경우 기본값을 반환합니다.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L102-L108)

5. **키 관리**. 개별 또는 모든 설정 항목을 조회 및 삭제합니다:

   ```csharp
   if (setting.HasSetting("Level")) { /* ... */ }
   setting.RemoveSetting("Level");
   setting.RemoveAllSettings();
   ```

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L157-L185)

## 일반적인 변형

- **크로스 플랫폼 쓰기**. `m_SettingHelperTypeName`을 미니게임 플랫폼에 해당하는 `*MiniGameSettingStorage`로 변경하면, 읽기/쓰기 로직은 수정할 필요가 없습니다.
- **사용자 지정 백엔드**. `ISettingStorageBackend`를 구현하고 `PlayerPrefsSettingHelper.SetStorageBackendForTests`를 통해 주입합니다(사용자 지정 `SettingHelperBase` 서브클래스에서 `SettingStorageBackendFactory.Create()`를 사용할 수도 있습니다).
- **일괄 업데이트**. 한 번의 비즈니스 이벤트 끝에 `Save()`를集中적으로 호출하여 항목을 변경할 때마다 디스크에 쓰는 것을 방지합니다.

## 일반적인 오류

- **Save() 호출을 잊는 경우**: `SetXxx`는 메모리만 수정하므로 `Save()`를 호출하지 않으면 데이터가 영구 저장되지 않아 재시작 후 손실됩니다.
- **시작 시점에 읽기**: `Awake`에서 읽지 마세요. `SettingComponent`는 `Start`에서 `Load()`를 실행합니다. 읽기 로직은 `Start` 이후에 배치해야 합니다.
- **모든 키 열거에 의존**: PlayerPrefs는 `GetAllSettingNames()`를 지원하지 않으므로, 호출하면 `null`이 반환되고 `GetAllSettingNames is not supported.` 경고가 출력됩니다. 대신 비즈니스 레이어에서 알려진 키 목록을 자체적으로 유지하세요.

## 배경 (선택 사항)

`SettingComponent`는 MonoBehaviour 진입점이고, `SettingManager`는 의존성이 없는 모듈 핵심이며, `SettingHelperBase`는 읽기/쓰기를 구체적인 백엔드로分发합니다. `PlayerPrefsSettingHelper`는 기본적으로 `SettingStorageBackendFactory`를 통해 해당 플랫폼의 백엔드 구현을 선택하여, 동일한 API 세트로 PlayerPrefs와 미니게임 플랫폼 저장을 모두 호환합니다.
