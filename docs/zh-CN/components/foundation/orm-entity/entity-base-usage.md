# 如何继承 EntityBase / EntityBaseId 编写实体

通过继承框架的 `EntityBase` / `EntityBaseId` 实体基类,你的实体类会自动获得主键、审计字段、软删除标记、乐观锁版本号和启用开关等通用字段,无需在每个实体里重复声明。

## 前置条件

- 项目已引用 `GameFrameX.Foundation.Orm.Entity` 程序集。
- 使用支持 C# `Key`/`Required` 等数据注解特性的 ORM(如 SqlSugar / Entity Framework)。

## 操作步骤

### 1. 仅需主键字段:继承 `EntityBaseId` / `EntityBaseId<TKey>`

如果你的实体只想要一个主键,不关心创建人、更新时间、软删除等审计字段,继承 `EntityBaseId` 即可。默认主键类型为 `long`,带 `Key` 和 `Required` 特性。

```csharp
using System.ComponentModel.DataAnnotations;
using GameFrameX.Foundation.Orm.Entity;

public class Dictionary
{
    // 业务字段
    public string Code { get; set; }
    public string Name { get; set; }
}
```

如果主键不是 `long`,使用泛型版本并指定主键类型(`TKey` 必须为非空类型):

```csharp
public class Dictionary<TKey>
    where TKey : notnull
{
    // 主键 Id 已由基类声明
    public string Code { get; set; }
    public string Name { get; set; }
}
```

Source: [EntityBaseId.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L44-L82)

### 2. 完整审计字段:继承 `EntityBase` / `EntityBase<TKey>`

大多数业务实体都需要审计、软删除、乐观锁、启用开关等字段,直接继承 `EntityBase`。基类已经实现了 `ISafeDeletedFilter`、`IVersionedEntity`、`ISafeEnabledFilter`、`ISafeCreatedFilter`、`ISafeUpdateFilter` 等接口,框架会自动应用这些过滤条件。

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class PlayerEntity : EntityBase
{
    // 基类已提供:Id、CreatedId、CreatedTime、CreatedName、
    //            UpdateCount、UpdateTime、UpdatedId、UpdatedName、
    //            IsDeleted、DeleteTime、DeletedId、DeletedName、
    //            RowVersion、IsEnabled
    public string Name { get; set; }
    public int Level { get; set; }
}
```

非 `long` 主键时使用泛型版本:

```csharp
public class PlayerEntity<TKey> : EntityBase<TKey>
    where TKey : notnull
{
    public string Name { get; set; }
    public int Level { get; set; }
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L180)

### 3. 按需覆盖基类属性

基类字段全部使用 `virtual` 修饰,你可以在子类中通过 `override` 调整默认值或附加特性,例如让 `IsDeleted` 在新建时为 `null`:

```csharp
public class OrderEntity : EntityBase
{
    public override bool? IsDeleted { get; set; }

    public string OrderNo { get; set; }
}
```

## 常见变体

| 场景 | 基类 | 关键能力 |
|------|------|----------|
| 仅需主键 | `EntityBaseId` / `EntityBaseId<TKey>` | `Id` 主键字段 |
| 完整审计 + 软删除 + 乐观锁 + 启用开关 | `EntityBase` / `EntityBase<TKey>` | 上面全部基类能力 |
| 还需要租户隔离 | `EntityTenantBase` / `EntityTenantBase<TKey>` | 在 `EntityBase` 基础上增加 `TenantId` 过滤 |
| 还需要扩展查询过滤 | `EntitySelectBase` / `EntitySelectBase<TKey>` | 在 `EntityBase` 基础上增加 `Select` 过滤 |

## 常见错误

- **没写 `where TKey : notnull`**:使用泛型基类时必须加上该约束,否则编译失败,基类本身也强制该约束([EntityBaseId.cs L67-L68](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L67-L68))。
- **手动重复声明 `Id` 字段**:`Id` 已经由基类提供,不要在子类里再次声明,否则会出现隐藏基类成员的编译警告并破坏 ORM 映射。
- **把实体类写成非 `abstract`**:基类是 `abstract`,推荐把具体实体也标记为 `abstract` 或保持可实例化,但业务类应避免再被继承。
- **自定义主键类型时漏掉 `[Key]`**:`Id` 已带 `[Key]`、`[Required]`,如果你的 ORM 依赖特性识别主键,无需额外标注;只有重写时才需重新加 `[Key]`。

## 背景(可选)

`EntityBase` 在 `EntityBaseId` 之上聚合了 5 个过滤器接口(`ISafeDeletedFilter`、`ISafeEnabledFilter`、`ISafeCreatedFilter`、`ISafeUpdateFilter`、`IVersionedEntity`),框架在生成 SQL 时会读取这些接口并自动追加 `IsDeleted = 0`、`IsEnabled = 1`、乐观锁等条件,业务侧无需手动处理。`EntityTenantBase` 与 `EntitySelectBase` 是在此基础上再叠加租户隔离和扩展查询过滤的场景化基类。
