# 軟刪除/啟用篩選器介面的使用方法

在實體上啟用 `ISafeDeletedFilter` 與 `ISafeEnabledFilter` 後，框架會在基礎實體 `EntityBase` 內自動提供軟刪除欄位(`IsDeleted`、`DeleteTime`、`DeleteId`)與啟用/停用欄位(`IsEnabled`),實現「邏輯刪除」與「啟用狀態」的統一管理。

## 前提條件

- 參考命名空間 `GameFrameX.Foundation.Orm.Entity`(提供 `EntityBase`、`EntityBase<TKey>`)。
- 參考命名空間 `GameFrameX.Foundation.Orm.Entity.Filter`(提供篩選器介面)。
- 實體類別繼承 `EntityBase` 或 `EntityBase<TKey>`。框架基礎類別已預設實作 `ISafeDeletedFilter` 與 `ISafeEnabledFilter`,因此無需手動新增實作。

## 操作步驟

1. 讓業務實體繼承 `EntityBase`,即可同時取得軟刪除與啟用篩選器的欄位。

```csharp
using GameFrameX.Foundation.Orm.Entity;
using GameFrameX.Foundation.Orm.Entity.Filter;

public class SysUser : EntityBase
{
    public string UserName { get; set; } = string.Empty;
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L46)

2. 實體類別會自動包含以下軟刪除欄位，可直接使用：

| 欄位 | 型別 | 預設值 | 意義 |
|------|------|--------|------|
| `IsDeleted` | `bool?` | `false` | 軟刪除旗標:`true` 已刪除、`false` 未刪除、`null` 未設定(視為未刪除) |
| `DeleteTime` | `long?` | `null` | 刪除時間(時間戳記) |
| `DeleteId` | `long?` | `null` | 刪除者 Id |

```csharp
// 將使用者標記為已刪除
sysUser.IsDeleted = true;
sysUser.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
sysUser.DeleteId = currentUserId;
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L120-L138)

3. 啟用篩選器(`ISafeEnabledFilter`)同樣已在基礎類別 `EntityBase` 中實作，用於記錄實體的啟用狀態。

4. 在儲存庫層執行查詢時，透過篩選欄位 `IsDeleted = false` 排除已刪除的資料，實現軟刪除查詢：

```csharp
// 範例:查詢未刪除的使用者清單
var users = await dbContext.Set<SysUser>()
    .Where(u => u.IsDeleted == false || u.IsDeleted == null)
    .ToListAsync();
```

5. 刪除操作請勿執行實體刪除，改為修改 `IsDeleted`:

```csharp
public void SoftDelete(SysUser user, long operatorId)
{
    user.IsDeleted = true;
    user.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
    user.DeleteId = operatorId;
}
```

## 常見變化

- 使用泛型主鍵基礎類別 `EntityBase<TKey>` 時(例如 `EntityBase<long>`),軟刪除與啟用欄位仍會自動包含。
- 若想自訂主鍵型別，請繼承 `EntityBase<TKey>` 並指定泛型參數：

```csharp
public class SysRole : EntityBase<long>
{
    public string RoleName { get; set; } = string.Empty;
}
```

- 若只想使用選擇篩選器而不需要稽核欄位，可以繼承 `EntitySelectBase`(以 `EntityBase` 為基礎額外實作 `ISelectFilter`,但仍包含 `IsDeleted` 等軟刪除欄位)。

Source: [EntitySelectBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntitySelectBase.cs#L45-L45)

## 常見錯誤

- 誤用實體刪除：對繼承 `EntityBase` 的實體呼叫 ORM 的 `Remove`/`Delete`,會繞過軟刪除旗標導致資料實際消失。請統一改為設定 `IsDeleted = true`。
- 查詢時遺漏 `IsDeleted` 篩選條件：若未加上 `Where(u => u.IsDeleted == false)`,已刪除的記錄也會一併被取得。請在儲存庫層強制附加篩選條件。
- 誤解 `IsDeleted` 為 `bool` 而非 `bool?`:框架使用可為 null 的布林值，預設為 `false`。新增實體時若未明確賦值，會視為「未刪除」處理。手動設定為 `null` 時同樣視為未刪除。
