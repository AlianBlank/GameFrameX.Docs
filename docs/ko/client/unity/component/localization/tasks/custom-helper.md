# 로컬라이제이션 Helper 커스터마이징 방법(시스템 언어 감지 재정의)

로컬라이제이션 Helper 커스터마이징은 두 단계만 거치면 됩니다: `LocalizationHelperBase`를 상속하는 클래스를 작성하고 `SystemLanguage` 속성을 재정의한 다음, `LocalizationComponent` 패널에서 Helper를 자신의 타입으로 교체하면 됩니다. 기본 구현은 `CultureInfo.CurrentCulture`를 사용하여 시스템 언어를 감지하며, 이 속성을 재정의하면 임의의 감지 전략(세이브 데이터 읽기, 계정 설정 읽기, 고정 언어 등)으로 교체할 수 있습니다.

## 사전 조건

- `com.gameframex.unity.localization` 패키지가 설치되어 있어야 합니다.
- 씬에 `LocalizationComponent`가 부착된 오브젝트가 이미 존재해야 합니다.

## 작업 단계

### 1. 커스텀 Helper 클래스 작성

먼저 기본 클래스 정의를 살펴보겠습니다. Helper는 `MonoBehaviour`이며, 구현해야 할 유일한 것은 읽기 전용 속성 `SystemLanguage`입니다:

```csharp
namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// 로컬라이제이션 헬퍼 기본 클래스.
    /// </summary>
    [Preserve]
    public abstract class LocalizationHelperBase : MonoBehaviour, ILocalizationHelper
    {
        /// <summary>
        /// 시스템 언어를 가져옵니다.
        /// </summary>
        [Preserve]
        public abstract string SystemLanguage { get; }
    }
}
```

출처: [LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L37-L48)

기본 구현인 `DefaultLocalizationHelper`의 작성 방식은 다음과 같으며, 현재 문화권 이름을 가져와 `-`를 `_`로 교체합니다(예: `zh-CN` → `zh_CN`):

```csharp
using System.Globalization;
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// 기본 로컬라이제이션 헬퍼.
    /// </summary>
    [Preserve]
    public class DefaultLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public DefaultLocalizationHelper()
        {
        }

        /// <summary>
        /// 시스템 언어를 가져옵니다.
        /// </summary>
        [Preserve]
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
    }
}
```

출처: [DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L32-L57)

기본 구현의 골격을 참고하여 자신만의 클래스를 작성합니다. 아래 예제는 시스템 언어를 `zh_CN`으로 고정합니다(`DefaultLocalizationHelper` 구조를 참고해 수정했으며, 반환 값은 자신만의 감지 로직으로 교체할 수 있습니다. `xx_XX` 언더스코어 형식을 유지하십시오):

```csharp
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    [Preserve]
    public class MyLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public override string SystemLanguage
        {
            get { return "zh_CN"; } // 여기에 자신만의 언어 감지 로직을 구현
        }
    }
}
```

### 2. LocalizationComponent에 커스텀 Helper 구성

`LocalizationComponent`는 Helper를 선택하기 위한 두 개의 직렬화 필드를 노출합니다:

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";

[SerializeField] private LocalizationHelperBase m_CustomLocalizationHelper = null;
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

- Inspector의 **Localization Helper** 드롭다운에서 자신의 커스텀 타입을 선택합니다(패널 내부에서 `HelperInfo<LocalizationHelperBase>`를 통해 선택 가능한 Helper를 나열합니다. [LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L46) 참조).
- `m_LocalizationHelperTypeName`은 **전체 타입 이름**(네임스페이스 포함)이어야 합니다. 기본값인 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper`의 작성 방식을 참고하십시오.

### 3. 런타임에 Helper 적용 확인

컴포넌트는 초기화 시 `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)`를 통해 Helper 인스턴스를 생성합니다([LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L250) 참조). 실행 후 `LocalizationComponent`의 시스템 언어/언어 관련 속성을 조회하면 반환 값이 자신의 재정의 로직에서 나와야 합니다.

## 일반적인 변형

- **Unity 시스템 언어 매핑**: `SystemLanguage`의 getter에서 Unity의 `Application.systemLanguage`에 따라 프로젝트에서 사용하는 언어 코드(`zh_CN`, `en_US` 등)로 매핑합니다.
- **세이브 데이터 또는 계정 설정에서 읽기**: getter에서 프로젝트 자체의 세이브/클라우드 설정을 읽어 사용자가 마지막으로 선택한 언어를 반환함으로써 "처음에는 시스템 언어를 따르고 이후에는 사용자 설정을 따르는" 방식을 구현합니다.
- **기본값 폴백**: `LocalizationComponent`의 `m_DefaultLanguage`는 기본적으로 `zh_CN`이며, 로컬라이제이션 로드에 실패하면 기본 언어로 대체합니다([LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L68) 참조). 커스텀 Helper와 함께 사용하면 지원되지 않는 언어에서도 콘텐츠를 표시할 수 있습니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| Inspector에서 자신의 Helper 타입을 찾을 수 없음 | 클래스가 `LocalizationHelperBase`를 상속하지 않았거나 컴파일 범위에 포함되지 않음 | 클래스가 `public class Xxx : LocalizationHelperBase`로 선언되어 있고, 저장 후 컴파일이 통과되었는지 확인 |
| 런타임에 Helper가 null임 | `m_LocalizationHelperTypeName`을 잘못 입력함(네임스페이스 누락, 철자 오류) | 타입 이름은 전체 이름(네임스페이스 포함)이어야 하며, 기본값 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` 참조 |
| 반환한 언어가 적용되지 않음/사전과 매칭되지 않음 | 반환한 언어 코드 형식이 잘못됨 | `xx_XX` 언더스코어 형식을 유지(기본 구현은 `-`를 `_`로 대체). `zh-CN`, `Chinese` 등의 형식을 반환하지 마십시오 |
| 커스텀 Helper 클래스가 제거됨(IL2CPP/링커 스트리핑) | `[Preserve]` 특성이 지정되지 않음 | 클래스와 속성에 `[Preserve]`를 추가(기본 구현의 사용법 참조) |
| 언어 전환 후 UI가 새로고침되지 않음 | Helper 반환 값을 직접 변경해도 이벤트가 트리거되지 않음 | `LocalizationComponent.Language`의 setter를 통해 언어를 설정해야 언어 변경 이벤트(Before/Change/After)가 트리거됨 |

## 배경

`LocalizationComponent`는 초기화 시 `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)`를 통해 "타입 이름 + 선택적 커스텀 인스턴스"라는 두 가지 방식으로 Helper를 생성합니다. 따라서 커스텀 Helper는 Inspector 패널을 통해 선택하거나(타입 이름 문자열 기록), 참조를 직접 드래그하여 지정할 수 있습니다. 언어 가져오기는 `SystemLanguage` 속성을 통해 이루어지며, 언어 설정과 영속화는 컴포넌트의 `Language` / `DefaultLanguage` 속성이 담당합니다(`SettingComponent`와 함께 저장). 전환 시 `LocalizationLanguageChangeBeforeEventArgs`, `LocalizationLanguageChangeEventArgs`, `LocalizationLanguageChangeAfterEventArgs` 세 가지 이벤트가 순차적으로 트리거됩니다.

로컬라이제이션 컴포넌트의 전체적인 사용법에 대해서는 이 패키지의 《LocalizationComponent》 관련 문서를 참조하십시오.
