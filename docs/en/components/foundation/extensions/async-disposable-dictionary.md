# How to Use the Async Disposable Dictionary

`AsyncDisposableDictionary<TKey, TValue>` is a dictionary container that requires its values to implement `IAsyncDisposable`, and it inherits from `NullableDictionary<TKey, TValue>`. When the dictionary itself is disposed via `DisposeAsync()`, it automatically iterates through and asynchronously disposes of all non-null values, making it suitable for managing a set of resources that require asynchronous cleanup (such as database connections, network sessions, long-lived clients, etc.).

## Prerequisites

- `TValue` must implement `IAsyncDisposable`.
- Import the namespace `GameFrameX.Foundation.Extensions`.
- Requires a .NET version that supports `IAsyncDisposable` (.NET Standard 2.1+ / .NET 5+).

## Steps

1. **Create a dictionary instance and add values**

   Simply add resource objects directly via a collection initializer or the indexer:

   ```csharp
   using GameFrameX.Foundation.Extensions;

   var dictionary = new AsyncDisposableDictionary<string, MyAsyncResource>
   {
       ["conn-1"] = new MyAsyncResource(),
       ["conn-2"] = new MyAsyncResource()
   };
   ```

   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L6-L37)

2. **(Optional) Set a disposal error handler**

   When a value's `DisposeAsync()` throws an exception, the dictionary invokes `DisposalErrorHandler`, letting you decide how to log or handle it:

   ```csharp
   dictionary.DisposalErrorHandler = (value, ex) =>
   {
       Console.WriteLine($"Failed to dispose {value}: {ex.Message}");
   };
   ```

   Exceptions thrown by the handler itself are swallowed, so that the remaining values can still be disposed.  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L92-L102)

3. **Call `DisposeAsync()` to asynchronously dispose of all values**

   ```csharp
   await dictionary.DisposeAsync();
   ```

   The disposal process is idempotent: calling `DisposeAsync()` repeatedly will not dispose values again. You can query the state via `dictionary.IsDisposed`.  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L71-L90)

4. **Do not write or modify after disposal**

   After disposal, calling the indexer `set`, `Add`, or `Remove` throws an `ObjectDisposedException`. Reads (get) are still available because it inherits from the base dictionary.

## Common Variants

- **Concurrency scenarios**: If you need concurrent reads and writes in a multi-threaded environment, use the thread-safe version `AsyncDisposableConcurrentDictionary<TKey, TValue>`, which is used the same way as described on this page.
- **Disposing an empty dictionary**: Even if the dictionary contains no values, calling `await dictionary.DisposeAsync()` directly is safe and simply returns.
- **Partial disposal failures**: A failure to dispose one value does not block the disposal of the others; every `IAsyncDisposable` value will be attempted once.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ObjectDisposedException` | `Add`, `Remove`, or the indexer `set` was called after `DisposeAsync()` | Stop writing after disposal; only read-only access is allowed |
| Values are not disposed | `null` values were stored | `DisposeAsync` skips `null`; make sure actual resource instances are stored |
| Disposal is interrupted and subsequent resources are not cleaned up | Old code manually threw unhandled exceptions | Always use `DisposalErrorHandler` as a fallback and rely on the dictionary's internal try/catch to continue iterating |
| Type compilation error | `TValue` does not implement `IAsyncDisposable` | Confirm the resource type implements `IAsyncDisposable`, e.g., a custom wrapper around `DbConnection` or `HttpClient` |

## Verification

- After calling `await dictionary.DisposeAsync()`, `dictionary.IsDisposed` is `true`.
- Every non-null value's `DisposeAsync()` is called exactly once (the test cases verify this).  
  Source: [AsyncDisposableDictionaryTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Tests/Extensions/AsyncDisposableDictionaryTests.cs#L28-L45)
- Calling `DisposeAsync()` again after disposal does not throw, and values are not disposed a second time.

## Background (Optional)

`AsyncDisposableDictionary` guarantees that even if `DisposeAsync` is blocked by or throws on a value during iteration, subsequent values can still be disposed, by marking `_isDisposed` as `true` before iterating over `Values`. Error handling is exposed to the caller via a callback delegate, so the framework does not force a dependency on a logging system.
