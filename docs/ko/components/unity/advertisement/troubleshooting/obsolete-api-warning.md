# 기존 API 컴파일 경고 처리 방법

코드에서 `[Obsolete]` 표시가 있는 인터페이스를 호출하면 Unity 컴파일러가 콘솔에 `CS0618` 경고를 출력하고 대체 API를 안내합니다. 이 페이지에서는 이러한 호출을 빠르게 찾아내고 새로운 API로 전환하는 방법을 설명합니다.

## 빠른 진단

| 경고 원문 | 트리거되는 기존 API | 권장 대체 |
|---|---|---|
| `Use Initialize(AdvertisementConfig) instead.` | `AdvertisementComponent.Initialize(string adUnitId, bool isDebug)`, `IAdvertisementManager.Initialize(...)`, `BaseAdvertisementManager.Initialize(...)` | `Initialize(AdvertisementConfig config)` |
| `Use Play(AdvertisementPlayOption) instead.` | `AdvertisementComponent.Show(Action<string>, Action<string>, Action<bool>)`, `AdvertisementComponent.Play(Action<bool>, string)` 및 `IAdvertisementManager` / `BaseAdvertisementManager`의 해당 `Play` 오버로드 | `Play(AdvertisementPlayOption option)` |

`[Obsolete]` 표시의 실제 위치는 [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L150-L191), [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L62-L122), [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L144-L236)을 참조하세요.

## 수정 단계

### 1. `Initialize(string, bool)`을 `Initialize(AdvertisementConfig)`로 교체

기존 시그니처는 광고 단위 ID와 디버그 스위치만 받지만, 새 시그니처는 `AdvertisementConfig` 파생 설정 객체를 받아 더 많은 매개변수를 전달할 수 있습니다(하위 클래스는 구체적인 광고 SDK 구현에서 제공하며, 예: `PangleAdvertisementConfig` 등).

```csharp
// 기존 작성법 —— CS0618 트리거됨
[Obsolete("Use Initialize(AdvertisementConfig) instead.")]
adComponent.Initialize("ad-unit-id-xxx", isDebug: true);

// 새 작성법
var config = new MyAdSdkConfig // 구체적인 하위 클래스는 사용하는 광고 SDK에서 제공
{
    adUnitId = "ad-unit-id-xxx",
    isDebug = true,
};
adComponent.Initialize(config);
```

`AdvertisementConfig` 기본 클래스 정의는 [AdvertisementConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L41-L53)을 참조하세요.

### 2. `Show` / 다중 매개변수 `Play`를 `Play(AdvertisementPlayOption)`로 교체

기존 `Show(success, fail, onShowResult)`와 `Play(onShowResult, customData)`는 분산된 매개변수를 사용하지만, 새 인터페이스는 모든 콜백과 확장 데이터를 `AdvertisementPlayOption` 객체에集中시킵니다.

```csharp
// 기존 작성법 —— CS0618 트리거됨
[Obsolete("Use Play(AdvertisementPlayOption) instead.")]
adComponent.Show(
    success: info => Debug.Log($"成功:{info}"),
    fail: err => Debug.LogError($"失败:{err}"),
    onShowResult: shown => Debug.Log($"展示:{shown}"));

// 새 작성법
var option = new AdvertisementPlayOption
{
    OnSuccess = info => Debug.Log($"成功:{info}"),
    OnFail = err => Debug.LogError($"失败:{err}"),
    OnShowResult = shown => Debug.Log($"展示:{shown}"),
    customData = "reward-key-001",
};
adComponent.Play(option);
```

`AdvertisementPlayOption` 필드 정의는 [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L80)을 참조하세요.

### 3. 임시로 기존 호출을 유지해야 할 경우, CS0618을局部적으로 억제

프레임워크 내부에서 기존 호출을 전달할 때 이미 다음과 같이 처리하고 있습니다:

```csharp
#pragma warning disable CS0618
_advertisementManager.Initialize(AdUnitId, isDebug);
#pragma warning restore CS0618
```

마이그레이션 기간 동안, 즉시 교체할 수 없는极少数의 외부 의존성 지점에 한해서만 `#pragma warning disable CS0618`을 사용하고, 가능한 한 빨리 새 버전에서 제거하세요.

## 검증

1. Unity에서 콘솔을 `Clear`하고 광고 초기화 및 재생을 한 번 트리거합니다.
2. 콘솔에 `Use Initialize(AdvertisementConfig) instead.` 또는 `Use Play(AdvertisementPlayOption) instead.`에 대한 `CS0618` 경고가 더 이상 나타나지 않는지 확인합니다.
3. 전체 "초기화 → 재생 → 콜백"流程를 한 번 실행하여 `OnSuccess` / `OnFail` / `OnShowResult`이 모두 정상적으로 트리거되는지 확인합니다.
