# 定时器不触发或查询返回 -1 怎么办

定时器不回调,或 `GetRemaining` / `GetElapsed` / `GetRepeatLeft` 返回 `-1`,通常属于以下几类:回调为 null 导致 `Add` 直接失败并返回 0、定时器刚 `Add` 完还没被 `Update` 刷新进 `_items`、重复次数已耗尽或已被 `Remove`、被 `Pause` 后未 `Resume`、`Scaled` 模式下 `Time.timeScale` 为 0。本页按症状给出诊断表与对应修复步骤(以下示例假定你已持有 `TimerManager` / `ITimerManager` 实例,Unity 侧经 `TimerComponent` 转发同名方法)。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `Add` 返回 0,控制台输出 `timer callback is null, {interval},{repeat}` | `callback` 参数为 null,注册被拒绝 | 检查回调非空再注册,见[修复 1](#1-add-返回-0-回调为-null) |
| 刚 `Add` 完立即查询 `GetRemaining`/`GetElapsed`/`GetRepeatLeft` 返回 -1 | 定时器还在 `_toAdd` 队列,要等下一次 `Update` 末尾才刷入 `_items` | 等一帧再查,或先用 `Exists(id)` 判断,见[修复 2](#2-刚-add-完查询返回--1定时器尚未被-update-刷新) |
| `AddOnce` 触发一次后再查询返回 -1 | `repeat` 减到 0 后定时器被删除并从 `_ids` 移除,属正常行为 | 需要再次触发就重新 `Add`,见[修复 3](#3-重复次数耗尽或已被-remove) |
| `Exists(id)` 为 true 但一直不触发 | 曾调用 `Pause(id)` 未 `Resume`;或 `Scaled` 模式且 `Time.timeScale = 0` | 调用 `Resume(id)`;或改用默认 `Unscaled`,见[修复 4](#4-被-pause-后未恢复)、[修复 5](#5-scaled-模式且-timetimescale-为-0) |
| 同一回调注册第二个定时器后,第一个计时"归零重来" | 回调委托是字典键,重复 `Add` 会原地重置(`Elapsed = 0`) | 每个定时器用独立回调/lambda,见[修复 6](#6-同一回调重复注册导致计时被重置) |
| 某个回调抛异常后,后续回调都不执行 | `TimerManager.CatchCallbackExceptions` 默认 `false`,异常直接抛出中断本轮分发 | 设为 `true` 定位问题回调,见[修复 7](#7-回调抛异常吞掉后续回调) |

## 修复步骤

### 1. `Add` 返回 0:回调为 null

`Add` 的完整签名与失败分支如下,`callback == null` 时只打印警告并返回 0,该 ID 永远不会触发:

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
{
    lock (Locker)
    {
        if (callback == null)
        {
            Debug.LogWarning("timer callback is null, " + interval + "," + repeat);
            return 0;
        }
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L225)

注册后先校验返回值:

```csharp
int id = timerManager.Add(1f, 0, OnTick);
if (id == 0)
{
    // 回调为 null,注册失败,这里不应继续持有该 id
}
```

### 2. 刚 `Add` 完查询返回 -1:定时器尚未被 `Update` 刷新

新定时器先进入 `_toAdd`,在 `Update` 末尾才被刷入 `_items`;而查询方法只有在 `_items` 中找到未删除的条目才返回有效值,否则返回 -1:

```csharp
public float GetRemaining(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return -1f;
        }

        if (_items.TryGetValue(callback, out var t) && !t.Deleted)
        {
            // ...返回剩余时间
        }

        // Timer is in _toAdd (not yet flushed)
        return -1f;
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L552-L575)

刷入发生在 `Update` 的最后一步,所以"本帧注册、本帧查询"必然得到 -1:

```csharp
if (_toAdd.Count > 0)
{
    var enumerator = _toAdd.GetEnumerator();
    while (enumerator.MoveNext())
    {
        _items.Add(enumerator.Current.Key, enumerator.Current.Value);
    }

    enumerator.Dispose();
    _toAdd.Clear();
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L153-L163)

**修复方式**:把查询挪到下一帧(协程 `yield return null`、或放到另一个每帧回调里),或先判断 `Exists(id)`——它同时检查 `_toAdd` 与 `_items`,对"尚未刷新"的定时器返回 true。

### 3. 重复次数耗尽或已被 `Remove`

`repeat > 0` 的定时器每次触发递减,减到 0 即被标记删除;删除时会把 ID 从 `_ids` 移除,之后所有按 ID 的查询都返回 -1。`AddOnce` 内部就是 `repeat = 1`,触发一次即销毁;`repeat = 0` 表示无限循环。

```csharp
if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)

**修复方式**:这是设计行为,不是 bug。需要周期性触发就传 `repeat = 0`;一次性任务结束后的 -1 属正常,不要复用旧 ID,重新 `Add` 获取新 ID 即可。

### 4. 被 `Pause` 后未恢复

`Pause(id)` 置 `IsPaused = true`,此后 `Update` 直接 `continue`,不累积时间、不触发回调,但定时器仍留在 `_items` 中(`Exists(id)` 仍为 true)。`Resume(id)` 会把 `IsPaused` 置回 false 并继续计时:

```csharp
if (timerItem.IsPaused)
{
    continue;
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L75-L78)

**修复方式**:调用 `Resume(id)`;确认没有代码路径只 `Pause` 不 `Resume`。可用 Inspector 或日志检查当前是否存在被暂停的定时器。

### 5. `Scaled` 模式且 `Time.timeScale` 为 0

时间源按 `TimeScaleMode` 选择,默认是 `Unscaled`(不受 `timeScale` 影响);若注册时传了 `TimerTimeScale.Scaled`,暂停游戏(`Time.timeScale = 0`)时 delta 为 0,定时器将永远不会到达触发条件:

```csharp
// Select time source based on TimeScaleMode
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L80-L81)

**修复方式**:UI、掉线重连等暂停期间也要运行的逻辑,保持默认 `Unscaled` 不传 `timeScale` 参数;确认需要随游戏暂停的才传 `TimerTimeScale.Scaled`。

### 6. 同一回调重复注册导致计时被重置

内部以回调委托作为字典键。对已存在的回调再次 `Add` 不会创建新定时器,而是原地重置(`Elapsed = 0`)并复用旧 ID——表现通常是"第一个定时器莫名其妙从头计时":

```csharp
// Re-add existing callback: update in-place
if (_items.TryGetValue(callback, out var t))
{
    UpdateTagIndex(t, tag);
    t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete);
    t.Elapsed = 0;
    t.Deleted = false;
    t.IsPaused = false;
    return t.Id;
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L236)

**修复方式**:同一对象上的多个定时器各自使用独立的方法或 lambda(每个 lambda 是不同委托实例);需要更新参数时,可有意利用这个"重注册即重置"行为。

### 7. 回调抛异常吞掉后续回调

回调在锁外集中分发。`TimerManager.CatchCallbackExceptions` 默认为 `false`,某个回调抛出的异常会中断本轮 for 循环,同帧排在后面的回调全部不执行。把它设为 `true` 可捕获并只打印 `Timer callback error > {message}`:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L172-L186)

**修复方式**:排障期设 `TimerManager.CatchCallbackExceptions = true` 并观察警告定位抛异常的回调;根因修复后建议恢复默认,避免吞掉异常。

## 验证

按上述修复操作后,逐条确认:

1. `Add` 返回非 0 的 ID,且 `Exists(id)` 为 true(注册成功,包括"尚未刷新"阶段)。
2. 等待一帧后再查 `GetRemaining(id)` / `GetElapsed(id)`,不再返回 -1 且数值随时间推进。
3. 到达 `interval` 后回调被调用;`GetRepeatLeft(id)` 返回 0 表示无限循环,其余正数为剩余次数。
4. `Pause(id)` 后 `GetElapsed(id)` 不再增长,`Resume(id)` 后恢复增长。
5. 设 `TimerManager.CatchCallbackExceptions = true` 后无 `Timer callback error >` 警告,说明没有回调在抛异常。
