# 文件夹复制报错怎么办

在 Unity iOS 出包的后处理阶段,`folders` 配置声明的文件夹会被复制到 Xcode 工程并自动加入编译;当 Unity Console 报出 `DirectoryNotFoundException`、`IOException` 等异常,或复制后文件/框架缺失时,按下方诊断表定位原因并修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `DirectoryNotFoundException: Could not find a part of the path ...` | `folders` 的 Key 源路径不存在:Key 是相对 Unity 工程根目录(与 `Assets` 同级),不是相对 `Assets` 的路径 | 见修复步骤 1 |
| `IOException` / `UnauthorizedAccessException`,删除目标目录时抛出 | 目标目录被 Xcode 等程序占用,或其中有只读文件 | 关闭占用程序或手工删除目标目录后重新出包,见修复步骤 2 |
| 复制成功但个别文件缺失 | 文件名以 `.` 开头、或为 `.gitkeep` / `.DS_Store`,会被主动过滤 | 属预期行为,见修复步骤 3 |
| `.framework` / `.bundle` / `.a` 复制后链接报错(符号找不到) | 历史版本的文件夹复制链接 bug,或后缀名不对未被识别 | 升级到最新版本,见修复步骤 4 |

## 修复步骤

### 1. 源路径不存在(DirectoryNotFoundException)

复制时源路径按下面方式拼接,`Environment.CurrentDirectory` 即 Unity 工程根目录,与 `Assets` 同级:

```csharp
string src = Path.Combine(Environment.CurrentDirectory, map.Key.ToString().Trim());
string des = Path.Combine(xcodePath, map.Value.ToString().Trim());
CopyFolder(src, des);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L29-L31)

检查并修正 JSON 配置(路径前后的空白会被 `Trim()` 去掉):

```json
{
  "folders": {
    "XC": "Classes/XC"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L191-L197)

- Key:文件夹在 Unity 工程根目录下的路径,不要误写成 `Assets/` 开头
- Value:复制到 Xcode 工程内的相对路径

### 2. 删除目标目录失败(IOException)

`CopyFolder` 在复制前会先删除已存在的目标目录与同名文件,再重建目录:

```csharp
if (Directory.Exists(dstPath))
{
    Directory.Delete(dstPath, true);
}

if (File.Exists(dstPath))
{
    File.Delete(dstPath);
}

Directory.CreateDirectory(dstPath);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L174-L184)

`Directory.Delete(dstPath, true)` 递归删除,目标内有文件被占用或只读时抛异常:

1. 关闭正在打开该 Xcode 工程(或占用该目录)的程序
2. 手工删除 Xcode 工程内的目标目录
3. 重新执行 Unity iOS 构建

### 3. 个别文件没有被复制

复制与加入编译都会经过 `IsNeedCopy` 过滤:

```csharp
private static bool IsNeedCopy(string file)
{
    string fileName = Path.GetFileNameWithoutExtension(file);
    if (fileName.StartsWith(".") || file.EndsWith(".gitkeep") || file.EndsWith(".DS_Store"))
    {
        return false;
    }

    return true;
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L112-L121)

文件名(不含扩展名)以 `.` 开头、`.gitkeep`、`.DS_Store` 一律跳过。若需要保留空目录占位文件,请改用非点前缀命名。

### 4. framework / bundle / 静态库链接报错

`AddFolderBuild` 按后缀区分处理方式,确认目标路径(即 `folders` 的 Value)后缀正确:

| Value 结尾 | 处理方式 |
|------------|----------|
| `.framework` | `AddFile` + `AddFileToBuild` + `AddFrameworkToProject` |
| `.bundle` | 同时加入 UnityFramework target 与主 target |
| `.xcframework` / `.a` | `AddFile` + `AddFileToBuild` |
| 普通目录 | 递归展开子目录与文件,并对框架/静态库自动补搜索路径(`AutoAddSearchPath`) |

```csharp
if (root.EndsWith(".framework") || root.EndsWith(".bundle"))
{
    Debug.LogFormat("add framework/bundle to build:{0}->{1}", currDir, root);
    string fileGuid = proj.AddFile(currDir, root, PBXSourceTree.Source);
    proj.AddFileToBuild(targetGuid, fileGuid);
    if (root.EndsWith(".bundle"))
    {
        proj.AddFileToBuild(mainTargetGuid, fileGuid);
    }
    // 添加为 linked framework
    proj.AddFrameworkToProject(targetGuid, root, false);
    return;
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L47-L59)

## 验证

1. 重新执行 Unity iOS 构建,Console 无 `DirectoryNotFoundException` / `IOException` 异常,且能看到 `add framework/bundle to build:...`、`add file to build:...` 日志
2. 打开生成的 Xcode 工程,`folders` 中 Value 指向的目录已存在且内容齐全
3. `.framework` / `.bundle` 出现在 **General → Frameworks, Libraries, and Embedded Content** 或 **Build Phases → Link Binary With Libraries** 中,编译通过
