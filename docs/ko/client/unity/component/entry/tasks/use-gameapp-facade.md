# GameApp으로 각 하위 시스템을 호출하는 방법(파사드 계층 가이드)

`GameApp`은 GameFrameX에서 제공하는 정적 파사드 클래스(Facade)로, 각 컴포넌트에 분산되어 있는 하위 시스템(Asset, Config, Event, Fsm, UI, Entity, Localization 등)을 정적 속성으로 통합하여 제공합니다. 비즈니스 코드는 더 이상 `GameEntry.GetComponent<T>()`를 통해 반복적으로 조회할 필요 없이 `GameApp.Asset.xxx`로 바로 호출할 수 있습니다.

## 사전 조건

- GameFrameX의 `GameEntry`가 설치 및 초기화되어 있어야 하며, 프레임워크는 시작 시 `Enable` 목록에 따라 각 `Component`를 생성합니다.
- 사용하려는 하위 시스템에 해당하는 `ENABLE_GAME_FRAME_X_*` 매크로가 활성화되어 있는지 확인해야 합니다(각 `GameApp.*.cs` 파일은 매크로로 전체 partial 블록을 감싸고 있습니다). 그렇지 않으면 해당 속성이 컴파일되지 않습니다.
- 비즈니스 코드는 `Component` 참조를 직접 보유하지 말고, `GameApp.xxx`를 통해 통일되게 접근해야 합니다.

## 작업 단계

### 1. 정적 속성을 통해 하위 시스템 가져오기

각 `GameApp.*.cs` 파일은 동일한 패턴을 따릅니다: 내부에 하나의 정적 private 필드를 보유하고, 읽기 전용 정적 속성을 공개하며, 첫 접근 시 `GameEntry`에서 해당 `Component`를 가져와 캐시합니다.

```csharp
// 기본 컴포넌트 가져오기
var baseComp = GameApp.Base;

// 에셋 컴포넌트 가져오기(ENABLE_GAME_FRAME_X_ASSET 매크로 활성화 필요)
var asset = GameApp.Asset;

// 설정 컴포넌트 가져오기(ENABLE_GAME_FRAME_X_CONFIG 매크로 활성화 필요)
var cfg = GameApp.Config;

// 이벤트 컴포넌트 가져오기(ENABLE_GAME_FRAME_X_EVENT 매크로 활성화 필요)
var evt = GameApp.Event;
```

### 2. 비즈니스 코드에서 하위 시스템 메서드 호출하기

속성을 가져온 후 해당 `Component`의 메서드를 직접 호출하면 됩니다. 예를 들어 아래 코드는 리소스 로드, 설정 읽기, 이벤트 구독을 보여주며, 모두 `GameApp`을 거칩니다:

```csharp
// 에셋 로드
GameApp.Asset.LoadAsset<GameObject>("Assets/Prefabs/Hero.prefab", prefab =>
{
    // prefab 사용 ...
});

// 설정 읽기
var heroHp = GameApp.Config.GetInt("Hero_HP", 100);

// 이벤트 구독
GameApp.Event.Subscribe("OnPlayerLevelUp", payload =>
{
    // 레벨업 이벤트 처리
});
```

> 위 API 이름(LoadAsset / GetInt / Subscribe)은 각 컴포넌트의 일반적인 공개 메서드에서 가져온 것이며, 구체적인 시그니처는 [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs), [GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs), [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs)에 해당하는 `Component` 구현을 기준으로 합니다.

### 3. 매크로 스위치를 통해 불필요한 하위 시스템 제거하기

`GameApp`의 각 하위 시스템은 `ENABLE_GAME_FRAME_X_<NAME>` 컴파일 매크로로 감싸져 있습니다. 프로젝트에서 특정 하위 시스템이 필요 없다면 해당 매크로를 끄면 그 속성이 컴파일에서 제외되어 패키지 크기와 의존성을 효과적으로 줄일 수 있습니다.

| 매크로(예시) | 영향을 받는 속성 | 파일 |
|---|---|---|
| `ENABLE_GAME_FRAME_X_ASSET` | `GameApp.Asset` | [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs) |
| `ENABLE_GAME_FRAME_X_CONFIG` | `GameApp.Config` | [GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs) |
| `ENABLE_GAME_FRAME_X_EVENT` | `GameApp.Event` | [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) |

모든 하위 시스템은 동일한 매크로 명명 규칙을 사용하며, 구체적인 매크로 이름은 각 [Runtime/GameApp.*.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs) 파일 상단의 `#if` 지시문에서 확인할 수 있습니다.

## 일반적인 변형

### 기타 노출된 하위 시스템 사용하기

저장소 `Runtime/` 디렉터리의 각 `GameApp.*.cs` 파일은 하나의 하위 시스템에 대응하며, 자주 사용되는 진입점은 다음과 같습니다:

- `GameApp.AdJust`, `GameApp.Advertisement` —— 프로모션 및 광고.
- `GameApp.AppleLogin`, `GameApp.FaceBookLogin`, `GameApp.GoogleLogin` —— 서드파티 로그인.
- `GameApp.AppsFlyer`, `GameApp.GameAnalytics` —— 데이터 트래킹.
- `GameApp.Asset` —— 에셋 로드.
- `GameApp.Config` —— 설정 읽기.
- `GameApp.Coroutine` —— 코루틴.
- `GameApp.Download` —— 다운로드.
- `GameApp.Entity` —— 엔티티.
- `GameApp.Event` —— 이벤트.
- `GameApp.FairyGUIPackage` —— FairyGUI 리소스 패키지.
- `GameApp.Fsm` —— 상태 머신.
- `GameApp.GlobalConfig` —— 전역 설정.
- `GameApp.GUI` —— UI.
- `GameApp.Guide` —— 신규 사용자 가이드.
- `GameApp.Localization` —— 로컬라이제이션.

호출 방식은 동일합니다: 매크로가 활성화되어 있는지 확인한 후 `GameApp.<Name>`을 사용하면 해당 `Component`를 가져올 수 있습니다.

## 일반적인 오류

- **속성을 찾을 수 없음 / 컴파일 오류로 `GameApp`에 `xxx` 정의가 포함되어 있지 않음**: 대부분 해당 `ENABLE_GAME_FRAME_X_*` 매크로가 활성화되지 않았거나, 해당 `GameApp.*.cs`가 프로젝트에 컴파일되지 않은 경우입니다. 먼저 `Scripting Define Symbols` 또는 `asmdef`에서 매크로를 활성화하세요.
- **`GameEntry`가 시작되기 전에 속성에 접근함**: `GameApp`은 `GameEntry.GetComponent<T>()`로 컴포넌트를 가져오므로, 프레임워크 초기화가 완료되지 않았다면 `null`을 받게 되고 이후 호출에서 null 참조 예외가 발생합니다. `GameEntry`가 시작을 완료한 후에 `GameApp.xxx`에 접근하세요.
- **파사드 호출 대신 `Component`를 직접 `new`로 생성함**: `GameApp`의 정적 필드는 캐시이며, `GameEntry.GetComponent<T>()`로 가져온 인스턴스 간에만 일관성이 유지됩니다. 직접 `new`로 생성한 인스턴스는 파사드를 통해 얻을 수 없어 두 상태가 동기화되지 않는 문제가 발생합니다.
- **씬 간 정적 필드 보유**: 현재 `GameApp`의 필드는 프로세스 수준의 정적 캐시로, 프로세스 수명 주기에 맞춰 사용하도록 설계되어 있으므로 씬 전환 시 수동으로 재설정하지 마세요.

## 배경(선택 사항)

`GameApp`은 여러 개의 `partial class`로 구성되어 있으며(`Runtime/GameApp.*.cs`가 각각 하나의 하위 시스템 속성을 구현), 지연 로딩 + `GameEntry.GetComponent<T>()` 방식으로 컴포넌트 인스턴스를 통일되게 가져옵니다. 이는 싱글톤 컴포넌트의 전역 접근 능력을 유지하면서도 비즈니스 계층에 `GameEntry.GetComponent<T>()` 보일러플레이트 코드가 흩어지는 것을 방지하는, 프레임워크에서 전형적인 Facade 패턴의 적용 사례입니다.

프레임워크 전체 시작 흐름과 `GameEntry`의 역할에 대해서는 《개요》 페이지를 참고하세요.
