# 設定 UI 分組與層級深度

UI 分組在 FairyGUI 中對應一個掛載在 `GRoot` 下的全螢幕 `GComponent` 容器，同一分組的介面都作為它的子節點疊放；分組之間的前後次序由 `FairyGUIUIGroupHelper.SetDepth(int depth)` 決定——深度值會被換算成 Z 座標(`depth * 100`),數值越大的分組離鏡頭越近、顯示在更上層。

## 前置條件

- 已按儲存庫 README 安裝 `com.gameframex.unity.ui.fairygui` 套件(Unity 3.3.2 及以上)，參見 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L69-L100) 的安裝一節。
- 場景中已存在 GameFrameX 的 `UIComponent`(FairyGUI 套件元件所在根節點)，建立分組時會從它向上查找設計解析度設定。
- 專案已引用 GameFrameX 核心 UI 套件(`GameFrameX.UI.Runtime`),`OptionUIGroupAttribute`、`GetUIGroup` 等入口在那裡定義；本套件負責 FairyGUI 側的分組實作。

## 操作步驟

1. **確定分組清單與深度值**。為每類介面規劃一個分組名稱和深度，例如一般介面用較小值、彈出視窗/提示用較大值。分組深度只影響分組容器整體的 Z 位置，組內介面按加入順序疊放。

2. **由 UI 管理器建立分組**，建立時會呼叫 `FairyGUIUIGroupHelper.Handler`,並把深度傳入。該輔助器會：設定深度、套用設計解析度、建立一個與 `GRoot` 同寬高的全螢幕 `GComponent` 並以分組名稱命名：

   ```csharp
   public override IUIGroupHelper Handler(Transform root, string groupName, string uiGroupHelperTypeName, IUIGroupHelper customUIGroupHelper, int depth = 0)
   {
       SetDepth(depth);
       ApplyDesignResolution(root.GetComponentInParent<UIComponent>()?.DesignResolution);
       var component = new GComponent();
       GRoot.inst.AddChild(component);
       var comName = groupName;
       component.displayObject.name = comName;
       component.gameObjectName = comName;
       component.name = comName;
       component.opaque = false;
       component.AddRelation(GRoot.inst, RelationType.Width);
       component.AddRelation(GRoot.inst, RelationType.Height);
       component.MakeFullScreen();
       return GameFrameX.Runtime.Helper.CreateHelper(component.displayObject.gameObject, uiGroupHelperTypeName, (UIGroupHelperBase)customUIGroupHelper, 0);
   }
   ```

   Source: [FairyGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIUIGroupHelper.cs#L83-L98)

   注意分組容器 `opaque = false`:分組本身不攔截事件，事件命中取決於組內各介面自身。

3. **理解深度如何生效**。`SetDepth` 把深度寫入 `Depth` 屬性，並把輔助器所在 GameObject 的 `localPosition.z` 設為 `depth * 100`,間隔 100 是為組內介面留出 Z 偏移空間：

   ```csharp
   public override void SetDepth(int depth)
   {
       Depth = depth;
       transform.localPosition = new Vector3(0, 0, depth * 100);
   }
   ```

   Source: [FairyGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIUIGroupHelper.cs#L64-L68)

   關鍵成員速查：

   | 成員 | 簽名 | 說明 |
   |------|------|------|
   | `Depth` | `public override int Depth { get; protected set; }` | 當前分組深度，對外唯讀、由 `SetDepth` 寫入 |
   | `SetDepth` | `public override void SetDepth(int depth)` | 記錄深度並設定 `localPosition = (0, 0, depth * 100)` |
   | `Handler` | `public override IUIGroupHelper Handler(Transform root, string groupName, string uiGroupHelperTypeName, IUIGroupHelper customUIGroupHelper, int depth = 0)` | 建立分組容器並回傳實際輔助器實例 |

4. **把介面歸入分組**。介面類別透過 `OptionUIGroupAttribute` 宣告分組名稱；建立介面時若 `uiForm.UIGroup` 為空，`FairyGUIFormHelper` 會反射讀取該特性並按 `GroupName` 查找分組：

   ```csharp
   var uiGroup = uiForm.UIGroup;

   if (uiGroup == null)
   {
       var attribute = uiFormType.GetCustomAttribute(typeof(OptionUIGroupAttribute));
       if (attribute is OptionUIGroupAttribute optionUIGroup)
       {
           uiGroup = m_UIComponent.GetUIGroup(optionUIGroup.GroupName);
       }

       uiForm.UIGroup = uiGroup;
   }
   ```

   Source: [FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L104-L115)

   分組名稱必須與第 1 步規劃、且已建立的分組完全一致，否則查不到分組。

5. **介面掛載到分組容器**。介面建立成功後，`FairyGUIFormHelper` 取出分組對應的 `GComponent` 並把介面元件 `AddChild` 進去，組內疊放順序即加入順序：

   ```csharp
   DisplayObjectInfo displayObjectInfo = ((MonoBehaviour)uiGroup.Helper).gameObject.GetComponent<DisplayObjectInfo>();
   ...
   var uiGroupComponent = displayObjectInfo.displayObject.gOwner as GComponent;
   ...
   uiGroupComponent.AddChild(component);
   ```

   Source: [FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L145-L159)

## 常見變體

- **動態調整分組層級**：分組建立後仍可呼叫該分組輔助器的 `SetDepth(int depth)` 重新設定深度，GameObject 的 Z 座標會立即更新為 `depth * 100`,無需重建分組。
- **自訂介面組輔助器**:`Handler` 的 `customUIGroupHelper` 參數允許傳入自訂輔助器，最終由 `GameFrameX.Runtime.Helper.CreateHelper(...)` 決定實例化哪一個——傳入自訂實例時優先使用它，否則按 `uiGroupHelperTypeName` 反射建立。
- **執行階段按需建立分組**：未在初始化時預先建立的分組，只要在介面開啟前透過 UI 元件建立即可;`FairyGUIFormHelper` 在建立介面時按 `OptionUIGroupAttribute.GroupName` 即時呼叫 `m_UIComponent.GetUIGroup(...)` 查找。

## 常見錯誤

| 症狀(日誌原文) | 原因 | 修復 |
|------|------|------|
| `UI group is invalid.` | 介面類別的 `OptionUIGroupAttribute.GroupName` 對應的分組不存在，或未掛特性導致分組為空 | 核對特性中的分組名稱與已建立分組完全一致，並提前建立該分組 |
| `UI group component is invalid.` | 分組輔助器物件上的 `DisplayObjectInfo.displayObject.gOwner` 不是 `GComponent` | 確認使用的是 `FairyGUIUIGroupHelper` 建立的分組，不要用其他實作的輔助器 |
| `Display object info is invalid.` | 分組容器 GameObject 缺少 `DisplayObjectInfo` 元件 | 使用 `FairyGUIUIGroupHelper.Handler` 正常建立分組，避免手動拼裝容器 |
| 修改深度後介面層級未變化 | 只改了 `Depth` 屬性所在腳本數值，沒有實際呼叫 `SetDepth` | 呼叫 `SetDepth` 才會同步更新 `transform.localPosition` |

以上錯誤日誌均出自 [FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L139-L157)。

## 驗證

- 執行場景後，在 Hierarchy 中找到分組容器(名稱即分組名)，檢查其 `localPosition.z` 是否等於 `深度 × 100`,見 [FairyGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIUIGroupHelper.cs#L64-L68)。
- 開啟兩個不同深度的介面，確認深度大的分組覆蓋在深度小的分組之上；同一分組內後開啟的介面顯示在前。
- 開啟帶 `OptionUIGroupAttribute` 的介面，Console 未出現 `UI group is invalid.` 等錯誤日誌，且介面節點位於對應分組容器之下。

## 背景

FairyGUI 的 `GRoot` 是所有 UI 的根，各分組以平級全螢幕容器掛在其下，透過 Z 座標(深度 × 100)由相機透視關係決定前後，這就是本套件「介面組深度支援」的實作方式(見 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/CHANGELOG.md#L115))。關於 FairyGUI 適配層各元件的分工，見《FairyGUI 適配層概覽》。
