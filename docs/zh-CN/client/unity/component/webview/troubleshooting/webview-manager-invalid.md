# 启动时报 “Web View manager is invalid” 怎么办

该报错来自 `WebViewComponent.Awake()`:`GameFrameworkEntry.GetModule<IWebViewManager>()` 返回了 `null`,说明框架中没有任何实现了 `IWebViewManager` 的具体模块被注册/加载。出现后 WebView 组件不会调用 `Initialize()`,后续 `Show` / `Hide` 等调用都会空引用。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动即输出 `Log.Fatal("Web View manager is invalid.")` | `GameFrameworkEntry.GetModule<IWebViewManager>()` 返回 `null`,具体实现模块未被加载 | 确认项目中存在 `BaseWebViewManager` 的具体实现模块,见[修复步骤 1](#修复步骤) |
| 之后调用 `Show(url)` 抛 `NullReferenceException` | 上一步失败后 `_webViewManager` 保持为 `null`,组件直接跳过初始化 | 先解决上面的 Fatal,见[验证](#验证) |
| Inspector 中组件的实现类型下拉为空 | 实现类型未选择,或对应程序集未编译进项目 | 见[修复步骤 2](#修复步骤) |

报错触发点源码:

```csharp
_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L32-L37)

初始化被跳过的连带后果:

```csharp
private void Start()
{
    if (_webViewManager == null)
    {
        return;
    }

    _webViewManager.Initialize();
}
```

## 修复步骤

### 1. 确认项目里有 `IWebViewManager` 的具体实现

本仓库只提供抽象层:`BaseWebViewManager` 是抽象类,不含任何平台实现(目录中仅有 `BaseWebViewManager`、`IWebViewManager`、`WebViewComponent` 等)。具体实现必须由配套的运行时模块提供:

```csharp
public abstract partial class BaseWebViewManager : GameFrameworkModule, IWebViewManager
{
    public abstract void Initialize();
    public abstract void Show(string url);
    public abstract void MakeFullScreen();
    public abstract void ExecuteJavaScript(string javaScript);
    public abstract void Hide();
}
```

Source: [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39)

排查方法:在工程内全局搜索 `: BaseWebViewManager`,确认存在至少一个非抽象派生类;没有则安装/引入对应的运行时实现包后重试。

### 2. 检查组件上的实现类型是否已选择

`WebViewComponent` 在 `Awake()` 里通过反射解析实现类型,再取接口模块:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IWebViewManager);
base.Awake();
if (!IsRuntimeComponentReady)
{
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L30)

`componentType` 的取值由 Inspector 提供,编辑器脚本会把所有实现了 `IWebViewManager` 的类型刷进下拉列表:

```csharp
internal sealed class WebViewComponentInspector : ComponentTypeComponentInspector
{
    ...
    RefreshComponentTypeNames(typeof(IWebViewManager));
}
```

Source: [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L14-L19)

操作:选中挂载 `WebView` 组件的游戏对象,在 Inspector 中确认实现类型不为空;为空说明对应程序集没有被编译进当前构建目标(常见于平台实现包只支持特定平台)。修正后保存场景再运行。

### 3. 确认运行时程序集参与编译

本包的程序集定义为 `Runtime/GameFrameX.WebView.Runtime.asmdef` 与 `Editor/GameFrameX.WebView.Editor.asmdef`。检查 Unity Console 是否有关于这两个程序集(或实现模块程序集)的编译报错;编译失败会导致 `GetModule` 拿不到实现,表现为同样的 Fatal。

## 验证

1. 重新进入 Play 模式,Console 不再出现 `Web View manager is invalid.` 的 Fatal 日志。
2. 执行一次完整调用链,能正常拉起页面:

```csharp

```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L51-L58)

## 背景

`WebViewComponent` 是 `GameFrameworkComponent`,自身不实现任何 WebView 逻辑,只负责在 `Awake()` 里从 `GameFrameworkEntry` 取出 `IWebViewManager` 模块并转发调用(`Show`、`MakeFullScreen`、`ExecuteJavaScript`、`Hide`)。抽象与实现分离意味着接口层与各平台实现可独立打包;当实现模块缺失时,取模块这一步就会失败并输出本页的 Fatal 日志。
