# 如何訂閱生命週期事件

透過 `IEntityManager` 所公開的五個事件（`ShowEntitySuccess` / `ShowEntityFailure` / `ShowEntityUpdate` / `ShowEntityDependencyAsset` / `HideEntityComplete`），您可以在實體顯示、更新與隱藏的各個階段接收回呼，而無須修改實體的內部程式碼。

## 前置條件

- 您已在專案中取得 `IEntityManager` 實例（通常透過 `GameEntry.GetComponent<EntityComponent>().EntityManager` 取得）。
- 引用命名空間 `GameFrameX.Entity.Runtime`（事件引數）與 `System`（標準 `EventHandler<T>`）。

## 可訂閱事件總覽

| 事件 | 事件引數 | 觸發時機 |
|------|---------|---------|
| `ShowEntitySuccess` | `ShowEntitySuccessEventArgs` | 實體載入並顯示成功 |
| `ShowEntityFailure` | `ShowEntityFailureEventArgs` | 實體載入或顯示失敗 |
| `ShowEntityUpdate` | `ShowEntityUpdateEventArgs` | 實體顯示過程中的進度更新 |
| `ShowEntityDependencyAsset` | `ShowEntityDependencyAssetEventArgs` | 開始載入實體相依資源 |
| `HideEntityComplete` | `HideEntityCompleteEventArgs` | 實體隱藏完成 |

來源：[IEntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/IEntityManager.cs#L55-L80)

## 步驟

1. 在需要監聽的類別中保存 `IEntityManager` 的參考，並使用 `+=` 註冊事件回呼（每個事件的簽章形式為 `EventHandler<TEventArgs>`，其中第二個參數 `e` 為對應的事件引數）。

```csharp
using System;
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

public class MyListener
{
    private readonly IEntityManager m_EntityManager;

    public MyListener(IEntityManager entityManager)
    {
        m_EntityManager = entityManager;
        // 訂閱生命週期事件
        m_EntityManager.ShowEntitySuccess    += OnShowEntitySuccess;
        m_EntityManager.ShowEntityFailure    += OnShowEntityFailure;
        m_EntityManager.ShowEntityUpdate     += OnShowEntityUpdate;
        m_EntityManager.ShowEntityDependencyAsset += OnShowEntityDependencyAsset;
        m_EntityManager.HideEntityComplete   += OnHideEntityComplete;
    }

    private void OnShowEntitySuccess(object sender, ShowEntitySuccessEventArgs e)
    {
        // e.Entity / e.Duration / e.UserData / e.EntityLogicType
        Log.Info($"實體 {e.Entity.Id} 顯示成功，耗時 {e.Duration:F2}s");
    }

    private void OnShowEntityFailure(object sender, ShowEntityFailureEventArgs e)
    {
        Log.Warning($"實體顯示失敗: {e.EntityId}");
    }

    private void OnShowEntityUpdate(object sender, ShowEntityUpdateEventArgs e)
    {
        // e.Progress / e.EntityId
    }

    private void OnShowEntityDependencyAsset(object sender, ShowEntityDependencyAssetEventArgs e)
    {
        // e.EntityId / e.DependencyAssetName / e.LoadedCount / e.TotalCount
    }

    private void OnHideEntityComplete(object sender, HideEntityCompleteEventArgs e)
    {
        // e.EntityId / e.EntityAssetName / e.EntityGroup / e.UserData
    }
}
```

來源：[EntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.cs#L105-L150)

2. 當監聽器的生命週期結束時（場景切換、`OnDestroy` 等），請使用 `-=` 取消訂閱，以避免記憶體洩漏或在已銷毀的物件上收到多餘的回呼。

```csharp
public void Dispose()
{
    m_EntityManager.ShowEntitySuccess    -= OnShowEntitySuccess;
    m_EntityManager.ShowEntityFailure    -= OnShowEntityFailure;
    m_EntityManager.ShowEntityUpdate     -= OnShowEntityUpdate;
    m_EntityManager.ShowEntityDependencyAsset -= OnShowEntityDependencyAsset;
    m_EntityManager.HideEntityComplete   -= OnHideEntityComplete;
}
```

3. 透過 `EntityComponent` 取得管理器，並將其交給監聽器使用。

```csharp
var entityManager = GameEntry.GetComponent<EntityComponent>().EntityManager;
var listener = new MyListener(entityManager);
```

## 常見變體

- **只想監聽單一事件**：只對您關心的那一個事件執行 `+=`，例如只關心失敗情境時：`entityManager.ShowEntityFailure += OnFailed;`。
- **依實體 Id 過濾**：在回呼內檢查 `e.EntityId`（或 `e.Entity?.Id`），以決定是否要處理該通知。
- **只需要載入階段的進度回饋**：僅訂閱 `ShowEntityUpdate` 與 `ShowEntityDependencyAsset`，並在 UI 上顯示 `e.Progress` 或 `e.LoadedCount / e.TotalCount`。

## 常見錯誤

- **銷毀監聽器前未取消訂閱**：`EntityManager` 是長生命週期的模組，會持續持有回呼委派，導致物件無法被垃圾回收。請務必在 `OnDestroy` / `Dispose` 中成對使用 `-=`。
- **在回呼中拋出未捕捉的例外狀況**：事件是以同步方式分發的，例外狀況會沿著呼叫堆疊向上傳播並中斷後續處理；請在回呼內使用 `try / catch`。
- **將 `EventId` 與 C# 的 `event` 混為一談**：`ShowEntitySuccessEventArgs.EventId` 用於全域事件匯流排（`GameFrameX.Event.Runtime`）；本文介紹的是 `IEntityManager` 上的 `event EventHandler<T>` 訂閱，兩者並非同一種機制。

## 背景說明（選讀）

`EntityManager` 內部將上述五個回呼以標準 .NET `event` 欄位的形式公開，並在每個 `Show`/`Hide` 流程的關鍵節點觸發；這些 `EventArgs` 會透過 `ReferencePool` 取得與回收，因此請勿長期持有這些引數物件——它們會在事件分發完畢後歸還到物件池中。
