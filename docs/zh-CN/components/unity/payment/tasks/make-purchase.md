# 如何发起购买（内购与订阅）

调用 `PaymentComponent.Buy(PurchaseParams)` 并监听 `OnPurchaseSuccess` / `OnPurchaseFailed` 事件，即可完成一次性内购与订阅商品的购买；服务器验证通过后再调用 `ConsumePurchase` 消耗订单。旧的 `BuyInApp` / `BuySubs` 接口已标记 `[Obsolete]`，推荐统一走 `Buy(PurchaseParams)`。

## 前置条件

- 场景中已挂载 `PaymentComponent`（组件菜单路径 `GameFrameX/Payment`），它会自动附带 `GameFrameXPaymentCroppingHelper`：

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
public class PaymentComponent : GameFrameworkComponent
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

- 已按目标平台引入对应渠道实现包。`PaymentComponent.Awake()` 会按编译宏自动选择实现类（Android → `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`，iOS → `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`，其余平台回退到 `DefaultPaymentManager`）。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 操作步骤

1. **设置预定义商品 ID**（可选但推荐）。用于预加载商品缓存，**必须在 `Init()` 之前调用**：

```csharp
payment.SetPredefinedProductIds(
    new List<string> { "gem_100", "gem_500" },      // 内购商品ID列表
    new List<string> { "vip_monthly" });             // 订阅商品ID列表
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

2. **初始化支付系统**：

```csharp
// isDebug：是否沙盒模式；isClientVerify：是否执行客户端购买验证
payment.Init(isDebug: false, isClientVerify: false);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

| 参数 | 类型 | 默认值（组件层） | 说明 |
|------|------|------------------|------|
| `isDebug` | `bool` | `false` | 是否使用沙盒购买 |
| `isClientVerify` | `bool` | `true`（`PaymentComponent`）；`false`（`IPaymentManager`） | 是否客户端验证购买；走服务器验证时应设为 `false` |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L102-L102)、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

3. **订阅购买结果事件**（建议在初始化前后一次性挂好）：

```csharp
payment.OnPurchaseSuccess += (sender, e) =>
{
    Debug.Log($"购买成功: {e.ProductId}, OrderId={e.OrderId}");
    // 服务器验证通过后消耗订单：
    // payment.ConsumePurchase(e.PurchaseToken);
};
payment.OnPurchaseFailed += (sender, e) =>
    Debug.Log($"购买失败: {e.ResultCode}, {e.ErrorMessage}");
```

事件签名来源：[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L18-L26)，组件层同名转发见 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L46)

4. **确认支付系统就绪后再发起购买**：调用 `payment.IsReady()`，返回 `false` 时不要继续调用 `Buy`。

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L45-L49)

5. **构造 `PurchaseParams` 并调用 `Buy`**。`PurchaseParams` 是抽象基类（构造函数为 `protected`），不能直接 `new`；各渠道使用其子类传入渠道特有参数（如订阅所需的 `offerToken`）。若渠道包未提供子类，可自行继承：

```csharp
public sealed class MyPurchaseParams : PurchaseParams
{
    public MyPurchaseParams(string productId, string orderId, PaymentProductType productType)
        : base(productId, orderId, productType) { }
}

// 发起购买（productType 取内购/订阅对应的枚举值，定义见 Runtime/PaymentProductType.cs）
payment.Buy(new MyPurchaseParams("gem_100", "order_20240101_001", productType));
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)（基类定义）、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112)（推荐入口）

6. **服务器验证通过后消耗购买**。一次性商品必须消耗后才能再次购买：

```csharp
payment.ConsumePurchase(e.PurchaseToken);   // PurchaseToken 来自 OnPurchaseSuccess 的 PaymentEventArgs
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L140-L152)

`PaymentEventArgs` 携带的字段（用于回传服务器验证）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ProductId` | `string` | 产品 ID |
| `OrderId` | `string` | 订单 ID |
| `PurchaseToken` | `string` | 购买令牌（消耗订单用） |
| `ResultCode` | `PaymentResultCode` | 支付结果代码 |
| `ErrorMessage` | `string` | 错误消息 |
| `PurchaseData` | `string` | 原始购买数据（JSON 格式） |
| `CustomData` | `string` | 自定义数据 |

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

## 常见变体

- **查询历史订单 / 恢复购买**：调用 `payment.QueryPurchases(PaymentProductType.枚举值)`，结果通过 `OnQueryPurchasesResult` 事件返回，事件参数同样是 `PaymentEventArgs`。
  Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L51-L56)、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L28-L31)
- **旧接口（已废弃）**：`BuyInApp(productId, orderId, offerToken = "", customData = "")` 与 `BuySubs(productId, orderId, offerToken = "", customData = "")` 分别对应一次性商品与订阅商品，两者均标记 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`，新代码请勿使用。
  Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L72-L93)
- **自定义数据透传**：旧接口通过 `customData` 参数透传，事件回调用 `PaymentEventArgs.CustomData` 读回；新 `Buy(PurchaseParams)` 入口由各渠道子类扩展对应字段。

## 常见错误

| 症状 / 日志 | 原因 | 修复 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` 返回空 | 检查平台实现类名配置（`PaymentComponent` Inspector 中的 `m_componentXxxType`）与渠道包是否已引入 |
| `Log.Warning("Product ID is null or empty.")` | 调用旧 `Buy*` 接口时 `productId` 为空 | 传入非空商品 ID |
| `Log.Warning("Order ID is null or empty.")` | 调用旧 `Buy*` 接口时 `orderId` 为空 | 传入非空订单 ID |
| `Log.Warning("Purchase token is null or empty.")` | `ConsumePurchase` 传入空 token | 使用 `OnPurchaseSuccess` 事件中的 `e.PurchaseToken` |
| `SetPredefinedProductIds` 未生效 | 在 `Init()` 之后才调用 | 移到 `Init()` 之前 |
| 一次性商品重复购买失败（`ItemAlreadyOwned`） | 上一次购买未消耗 | 服务器验证通过后调用 `ConsumePurchase`；`ItemNotOwned`、`VerifyFailed`、`NetworkError` 等结果码见 `PaymentResultCode` 枚举 |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93)、[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L117-L152)、[PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L14-L25)

## 背景

`PaymentComponent` 是门面，只做参数校验与事件转发，实际逻辑由按平台解析出的 `IPaymentManager` 实现完成（Google / Apple / WebGL / PC / Default）。购买结果统一通过 `PaymentEventArgs` 抛出，`PaymentResultCode` 区分成功、取消、网络错误、已拥有等情形，便于各端复用同一套上层处理代码。
