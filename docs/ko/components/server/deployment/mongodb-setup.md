# MongoDB 연결 및 영속화 설정

이 페이지에서는 GameFrameX.Server에서 서비스 프로세스를 위해 MongoDB 연결 문자열과 데이터베이스 이름을 구성하여, `GameDb`가 시작 단계에서 연결을 완료하고 컬렉션을 초기화하여 영속화 가능한 상태로 진입하는 방법을 설명합니다.

## 사전 조건

- 접근 가능한 MongoDB 인스턴스를 준비합니다(로컬 서비스 또는 Atlas 클러스터 모두 가능).
- 해당 인스턴스의 연결 문자열(표준 URI 또는 `mongodb+srv://` 형식)과 대상 데이터베이스 이름을 확보합니다.
- 시작 프로젝트(`GameFrameX.Launcher`)에서 패키지 참조를 통해 `MongoDB.Driver`를 이미 도입했으며, 소스 코드 프로젝트는 `GameFrameX.Apps/GlobalUsings.cs`, `GameFrameX.Hotfix/GlobalUsings.cs`의 `global using`을 통해 MongoDB 어셈블리를 참조하므로, 비즈니스 코드에서 별도로 추가 도입할 필요가 없습니다.

## 작업 단계

1. 시작 진입점(기본 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`)의 `Init()`에서 `AppSetting`을 구성하고, 데이터베이스 관련 두 필드 `DataBaseUrl`과 `DataBaseName`을 입력합니다:

   ```csharp
   Setting = new AppSetting
   {
       // ... 기타 서버 설정
       DataBaseUrl  = "mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority",
       DataBaseName = "<your_db_name>",
   };
   ```

   출처: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L97-L114)

2. 서버 시작 메인 루프의 데이터베이스 초기화 단계에서 프레임워크는 `GameDb.Init<MongoDbService>`를 호출하고 위의 두 필드를 `DbOptions`에 전달합니다:

   ```csharp
   LogHelper.Debug("开始启动数据库服务...");
   var initResult = await GameDb.Init<MongoDbService>(new DbOptions
   {
       ConnectionString = Setting.DataBaseUrl,
       Name             = Setting.DataBaseName,
   });
   if (initResult == false)
   {
       throw new InvalidOperationException("数据库服务启动失败");
   }
   ```

   출처: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67)

3. 프로세스를 시작합니다. 로그에 "启动数据库服务 结束..."가 출력되고 `InvalidOperationException`이 발생하지 않으면 MongoDB 연결과 영속화 계층이 준비된 것입니다.

## 일반적인 변형

- **로컬 MongoDB 사용**: `DataBaseUrl`을 `mongodb://localhost:27017`로 교체하고, 데이터베이스 이름은 필요에 따라 조정합니다.
- **Atlas 클러스터 사용**: 기본 예시 형식인 `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority`를 그대로 사용하며, 계정과 클러스터 호스트만 실제 값으로 교체하면 됩니다.
- **다중 환경 격리**: 서로 다른 시작 진입점(예: `AppStartUpGame`을 상속받는 `AppStartUpGate`, `AppStartUpWorld` 등의 클래스)의 `Init()`에서 환경별로 `DataBaseUrl` / `DataBaseName`을 각각 설정하여, 서로 다른 프로세스가 서로 다른 데이터베이스를 가리키도록 합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 시작 시 `InvalidOperationException("数据库服务启动失败")` 발생 | `GameDb.Init<MongoDbService>`가 `false`를 반환함. 일반적으로 연결 문자열에 접근 불가, 계정 오류 또는 네트워크 제한 때문 | `DataBaseUrl`의 호스트, 포트, 사용자, 비밀번호를 확인하고, Atlas IP 허용 목록에 실행 머신이 허용되어 있는지 확인 |
| 애플리케이션이 데이터베이스 단계 전에 멈춤 | 연결 문자열에 인코딩되지 않은 특수 문자(예: `@`, `%`)가 포함됨 | 사용자 이름/비밀번호에 퍼센트 인코딩 사용. 예: `p@ss`를 `p%40ss`로 변경 |
| 연결은 성공하지만 읽기/쓰기 시 "컬렉션이 존재하지 않음" 오류 발생 | `DataBaseName`이 비즈니스 기대값과 일치하지 않음 | `DbOptions.Name`이 비즈니스 코드에서 읽는 데이터베이스 이름과 일치하는지 확인 |

## 배경(선택 사항)

`GameDb`는 프레임워크의 통합된 영속화 퍼사드(facade)이며, 실제 구현은 제네릭 매개변수인 `MongoDbService`에서 제공합니다. 시작 단계에서 `DbOptions`로 연결 문자열과 데이터베이스 이름을 주입하여 클라이언트 생성, 데이터베이스 선택 및 기본 직렬화 규칙 등록을 완료합니다. 비즈니스 계층은 `GameDb`를 통해 호출하면 되며 `IMongoClient`를 직접 소유하지 않으므로, 이후 기반 기술을 전환하거나 교체하기 쉽습니다.
