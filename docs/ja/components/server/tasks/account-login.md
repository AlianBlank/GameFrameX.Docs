# アカウントログインの実装(Account / Login フロー)

このドキュメントでは、クライアントから送信されるアカウントログインメッセージの接続を行い、`ReqPlayerLogin` からキャラクターデータの反映までの最小ループを完成させます。完了後、クライアントは `RespPlayerLogin` を取得し、ゲームのビジネスロジックに入ります。

## 前提条件

- `GameFrameX.Server` ゲートウェイと中央サーバーがデプロイ済みで、Actor タイプ `ActorTypeServer` が利用可能であること。
- データベースに `PlayerState` テーブルが存在し、主キーフィールドが `Id` であること(ログインメッセージは `Id` で検索します)。
- クライアントが `ReqPlayerLogin` メッセージを送信でき、`RespPlayerLogin` を受信できること。
- 以下の名前空間が参照されていること:`GameFrameX.Apps.Account.Login.Component`、`GameFrameX.Apps.Account.Login.Entity`、`GameFrameX.Apps.Player.Player.Entity`、`GameFrameX.Monitor.Player`。

## 操作手順

1. **中央サーバーにログインコンポーネントを登録する**。`LoginComponent` は `[ComponentType(GlobalConst.ActorTypeServer)]` を介して `ActorTypeServer` にバインドされ、アカウント/キャラクタログインのキャリアコンポーネントとして機能します。

   ```csharp
   [ComponentType(GlobalConst.ActorTypeServer)]
   public sealed class LoginComponent : StateComponent<LoginState>
   {
       protected override bool IsCreateDefaultState { get; set; } = false;
   }
   ```

   Source: [GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L36-L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L36-L41)

2. **キャラクター ID によるプレイヤー検索を実装する**。`LoginComponent` に `OnPlayerLogin(ReqPlayerLogin)` を公開し、内部で `GameDb.FindAsync<PlayerState>` を用いて主キー検索を行います。また、呼び出しごとにログインカウンターを記録します。

   ```csharp
   public async Task<PlayerState> OnPlayerLogin(ReqPlayerLogin reqLogin)
   {
       MetricsPlayerHelper.LoginCounterOptions.Inc();
       return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
   }
   ```

   Source: [GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47)

3. **バインディングと転送を行う Agent を実装する**。`LoginComponentAgent.OnPlayerLogin` は次の役割を担います。コンポーネントを呼び出してプレイヤーを検索し、プレイヤー `Id` を `NetWorkChannel` に書き込む(キー名は `GlobalConst.ActorIdKey`)。次に `ActorManager` を介してプレイヤー Actor の `PlayerComponentAgent` を取得し、ログイン処理を実際のプレイヤーコンポーネントに引き渡します。

   ```csharp
   public async Task OnPlayerLogin(INetWorkChannel workChannel, ReqPlayerLogin reqLogin, RespPlayerLogin response)
   {
       var playerState = await OwnerComponent.OnPlayerLogin(reqLogin);
       if (playerState == null)
       {
           //キャラクターが見つからない？
           return;
       }

       // プレイヤーIDをバインド
       workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id);
       var playerComponentAgent = await ActorManager.GetComponentAgent<PlayerComponentAgent>(playerState.Id);
       await playerComponentAgent.OnPlayerLogin(workChannel, playerState, response);
   }
   ```

   Source: [GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58)

4. **メッセージハンドラーを登録する**。`ReqPlayerLoginHandler` は `[MessageMapping(typeof(ReqPlayerLogin))]` でアノテーションされ、`GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>` を継承します。`ActionAsync` 内でリクエストを直接 Agent に転送します。

   ```csharp
   [MessageMapping(typeof(ReqPlayerLogin))]
   internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
   {
       protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
       {
           await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
       }
   }
   ```

   Source: [GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L34-L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L34-L41)

5. **クライアントからログインを送信する**。クライアントは `ReqPlayerLogin` プロトコル(`Id` を含む)に従ってリクエストを送信し、`RespPlayerLogin` の応答を待ちます。その後のビジネスメッセージはプレイヤー Actor 上で処理できます。

## 一般的なバリエーション

- **HTTP ログインエントリ**:リポジトリには別途 `GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs` があり、HTTP リクエストを同じログインフローに変換します。フロントエンドが TCP ではなく HTTP を使用する必要がある場合は、直接使用できます。
- **サンプルコードの無効化**:`GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs` は現在 `/* … */` でコメントアウトされており、旧バージョンの `ReqLogin` 実装のリファレンスとなっています。実際の連携には `ReqPlayerLogin` フローを使用してください。

## よくあるエラー

- **`playerState == null` で直接 return する**:この場合 `response` に値が設定されないため、クライアントは待機し続けるか timeout します。Agent でビジネスプロトコルに応じて `response` にエラーコードを設定するか、明示的な例外をスローするようにしてください。
- **`workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id)` の呼び忘れ**:後続のメッセージがプレイヤー Actor にルーティングされず、ビジネスプッシュが届きません。
- **`IsCreateDefaultState = false` と `PlayerState` の欠落**:プレイヤーが初回ログインし、データベースにレコードが存在しない場合、`OnPlayerLogin` で先に `PlayerState` を作成する必要があります。そうしないと常に `null` が返されます。

## 背景(任意)

- `LoginComponent` に `ActorTypeServer` がマークされているのは、ログインロジックが中央サーバーの Actor 上で実行され、特定のプレイヤー Actor に結合しないことを示しています。
- `LoginComponentAgent` は状態コンポーネントエージェントであり、Actor をまたぐメッセージを `LoginComponent` に集約し、プレイヤー ID に応じて対応する `PlayerComponentAgent` にディスパッチします。
