# 文件读取报错:ArgumentNullException / ArgumentException(path)

调用 `BlankReadAssets` 的 `OpenRead`、`ReadAllBytes`、`GetFiles` 等方法时,如果传入的 `path` 参数为 `null` 或空字符串,会立即抛出参数异常;调用 `PathUtil.CombineSlash` / `NormalizeRelativePath` 时,若路径分量缺失也会抛出同类异常。本页帮你快速定位是哪种情况并修复。

## 修复步骤

### 1. `OpenRead` / `ReadAllBytes` 传入 `null`

源码入口:[BlankReadAssets.OpenRead](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L132-L146) 与 [BlankReadAssets.ReadAllBytes](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L197-L211)。两者都会先做 `path == null` 判空。

```csharp
using GameFrameX.Asset;

string path = ResolveConfigPath(); // 可能返回 null

if (string.IsNullOrEmpty(path))
{
    Debug.LogError("配置文件路径未配置,跳过读取");
    return;
}

byte[] data = BlankReadAssets.ReadAllBytes(path);
```

### 2. `OpenRead` / `ReadAllBytes` 传入空串

源码:[BlankReadAssets.cs#L139-L142](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L139-L142)。当 `path.Length == 0` 时抛出 `ArgumentException("Empty path", "path")`。

```csharp
// 错误示例
string dir = "config/";
string file = ""; // 来自配置读取失败
string full = dir + file; // -> "config/" 的子路径可能仍有效,但 file 自身为空就会报错
byte[] data = BlankReadAssets.ReadAllBytes(full); // 取决于 full,不能依赖

// 修正:用 PathUtil.CombineSlash 拼接并校验
string full = PathUtil.CombineSlash(dir, file);
if (string.IsNullOrEmpty(full) || full.EndsWith("/"))
{
    throw new InvalidOperationException("目标文件路径无效: " + full);
}
```

### 3. `PathUtil.CombineSlash` 抛出 `ArgumentNullException`

源码:[PathUtil.CombineSlash](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75)。`a` 或 `b` 任一为 `null` 都会抛。

```csharp
string dir = settings.TryGetValue("assetDir", out var d) ? d : null;
string name = settings.TryGetValue("assetName", out var n) ? n : null;

if (dir == null || name == null)
{
    Debug.LogWarning("资源路径不完整,使用默认配置");
    dir = "fallback";
    name = "default.bin";
}

string full = PathUtil.CombineSlash(dir, name);
```

### 4. `PathUtil.NormalizeRelativePath` 抛出 `ArgumentException("Empty or null", "relative")`

源码:[PathUtil.NormalizeRelativePath](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L83)。任何空值都会直接抛,即使是空串。

```csharp
public static byte[] SafeRead(string relative)
{
    if (string.IsNullOrWhiteSpace(relative))
    {
        Debug.LogError("relative 为空,放弃读取");
        return Array.Empty<byte>();
    }
    return BlankReadAssets.ReadAllBytes(relative);
}
```

### 5. APK 模式下 `GetFiles` 的 `path` 为 `null`

源码:[BlankReadAssets.ApkImpl.GetFiles](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L93-L116)。`path == null` 时先抛 `ArgumentNullException`,然后才会做目录索引检查。

```csharp
string dir = request.GetQueryParam("dir");
if (string.IsNullOrEmpty(dir))
{
    dir = "/"; // 根目录兜底
}
string[] files = BlankReadAssets.GetFiles(dir, "*", SearchOption.TopDirectoryOnly);
```

### 6. APK 内部 `ArgumentException()`(无消息)

源码:[BlankReadAssets.ApkImpl.cs#L299-L306](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L299-L306)。这是在 APK 实现的 `GetFiles`/`GetDirectories` 中对目录基路径的二次校验失败,通常意味着 `BlankReadAssetsImpl` 没有正确初始化。

```csharp
// 编辑器侧:在调用 GetFiles 前确保完成初始化
BlankReadAssets.InitializeWithExternalApk(apkPath);

// 运行时:确保 streamingAssets 已挂载(BlankReadAssets 会通过 EnsureInitialized 自行检查)
if (!BlankReadAssets.FileExists("manifest/index.txt"))
{
    throw new IOException("APK 资源未挂载,无法枚举目录");
}
```

## 验证

执行完上述修复后,用下面这段最小验证脚本复现原报错场景,确认不再抛出:

```csharp
using GameFrameX.Asset;
using System;

void AssertNoThrow(string label, Action act)
{
    try { act(); Console.WriteLine($"[OK] {label}"); }
    catch (ArgumentNullException) { Console.WriteLine($"[FAIL] {label}: ArgumentNullException"); }
    catch (ArgumentException)   { Console.WriteLine($"[FAIL] {label}: ArgumentException"); }
}

AssertNoThrow("null path", () => BlankReadAssets.OpenRead(null));
AssertNoThrow("empty path", () => BlankReadAssets.OpenRead(""));
AssertNoThrow("valid path", () =>
{
    using var s = BlankReadAssets.OpenRead("config/test.txt");
});
```

预期输出中前两项应进入你自己的 `catch` 分支并被妥善处理,第三项 `[OK] valid path` 必须正常通过。

## 常见错误

- **依赖 `path + ""` 拼接**:空文件名会让 `ReadAllBytes` 走到 `path.Length == 0` 分支而抛 `ArgumentException`。改用 `PathUtil.CombineSlash` 并校验结果。
- **把 `null` 与 `""` 当作同一情况处理**:源码中 `OpenRead` 对 `null` 抛 `ArgumentNullException`,对 `""` 抛 `ArgumentException`,异常类型不同,日志检索时注意区分。
- **在 APK 模式下忘记先初始化**:未初始化时 `EnsureInitialized` 会抛 `InvalidOperationException` 而非参数异常,容易误判;先确认初始化,再看参数校验。
- **对 `PathUtil.NormalizeRelativePath` 传根路径或带引号字符串**:该方法对以 `"` 包裹的字符串有特殊处理([PathUtil.cs#L93](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L93)),路径中夹带未配对的双引号可能导致解析异常。
