# How to Use Entity, Coroutine, Sound, Scene, and Mono Management

`GameFrameX` exposes its runtime subsystem components—including Entity, Coroutine, Sound, Scene, and Mono—through the `GameApp` static facade in a lazy-loading fashion. Each subsystem corresponds to a component instance obtained via `GameEntry.GetComponent<T>()`; to use one, you simply access `GameApp.{SubsystemName}` in code. This page explains how to integrate these subsystems and their typical usage.

## Prerequisites

1. The `com.gameframex.unity.entry` package is installed, and the `GameEntry` launcher is mounted in the scene.
2. The runtime packages corresponding to each subsystem have been installed via the Package Manager:
   - `com.gameframex.unity.entity` (Entity)
   - `com.gameframex.unity.coroutine` (Coroutine)
   - `com.gameframex.unity.sound` (Sound)
   - `com.gameframex.unity.scene` (Scene)
   - The built-in Mono manager is provided with the entry package
3. The project has defined the corresponding enable macros: `ENABLE_GAME_FRAME_X_ENTITY`, `ENABLE_GAME_FRAME_X_COROUTINE`, etc. (each component's source code is guarded by `#if`; without the macro, the relevant fields will not compile—see "Common Errors" below).

## Instructions

### 1. Access Subsystems via GameApp

All subsystems are exposed in the `GameApp` class in the form `public static {ComponentClass} {SubsystemName}`, created and cached via `GameEntry.GetComponent<T>()` on first access. No manual `new` or registration is required.

```csharp
using GameFrameX.Runtime;

public static partial class GameApp
{
    public static EntityComponent Entity
    {
        get
        {
            if (_entity == null)
            {
                _entity = GameEntry.GetComponent<EntityComponent>();
            }
            return _entity;
        }
    }

    private static EntityComponent _entity;
}
```

Source: [Runtime/GameApp.Entity.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Entity.cs#L36-L55)

The Coroutine component follows exactly the same pattern:

### 2. Key Points for Using Entities

After obtaining `EntityComponent` via `GameApp.Entity`, you can use the entity creation, query, and destruction interfaces provided by the framework. Entity lifecycles are managed uniformly by `EntityComponent`, commonly used together with the `Entity` base class and `EntityLogic` logic scripts. For detailed interface signatures, refer to the `EntityComponent` source code; this repository does not directly contain its implementation—consult the documentation inside the `com.gameframex.unity.entity` package.

### 3. Key Points for Using Coroutines

Obtain `CoroutineComponent` via `GameApp.Coroutine` to start coroutine tasks in any non-MonoBehaviour context. The coroutine component wraps Unity's `Coroutine` mechanism underneath, allowing you to safely start delayed and frame-by-frame operations in non-Mono classes. The calling entry typically looks like:

```csharp
GameApp.Coroutine.StartCoroutine(MyRoutine());

GameApp.Coroutine.StopCoroutine(handle);
```

Refer to the `CoroutineComponent` source file for the exact overloads.

### 4. Key Points for Using Sound

The Sound subsystem uses the same static facade entry. In this repository, `Runtime/GameApp.Sound.cs` provides `GameApp.Sound`, guarded by `#if`, returning a `SoundComponent` instance. Common operations include playing BGM, playing sound effects, pausing/resuming, and setting volume; refer to the `SoundComponent` implementation for the exact APIs.

```csharp
// Illustrative only: see SoundComponent for actual signatures
GameApp.Sound.PlayMusic(musicId);
GameApp.Sound.PlaySound(soundId);
```

### 5. Key Points for Using Scenes

`Runtime/GameApp.Scene.cs` likewise exposes `SceneComponent` as `GameApp.Scene`. You can use this component to load and unload scenes, as well as retrieve information about currently loaded scene assets. Typical flow: pass in the scene asset name → trigger an async load → once loading completes, attach and switch the active scene.

```csharp
// Illustrative only
GameApp.Scene.LoadScene("MainCity", onComplete: () => { /* Scene entry complete */ });
```

### 6. Key Points for Using the Mono Manager

The `Mono` manager is used to obtain `Mono`-like capabilities (polling, coroutines, timers, etc.) in non-MonoBehaviour classes, working in tandem with `GameApp.Coroutine`. It can be obtained directly via the Mono-related properties on `GameApp`; subsequent calls to lifecycle hooks such as `Update`/`OnDestroy` require no inheritance from `MonoBehaviour`.

## Common Variants

- **Cross-platform trimming**: Every `GameApp.*.cs` uses `#if ENABLE_GAME_FRAME_X_{NAME}` conditional compilation, so subsystems can be enabled/disabled as needed in the project's `csc.rsp` or `Player Settings`. Once disabled, the corresponding `GameApp.{Name}` field disappears.
- **Dependency injection alternative**: If you prefer not to use the static facade, you can directly call `GameEntry.GetComponent<EntityComponent>()` etc. to obtain the raw component reference; the two approaches are equivalent.
- **Subsystem naming differences**: For example, some versions use `Mono` rather than `MonoManager` as the name; refer to the source code of the current runtime package version.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Properties such as `GameApp.Entity` / `GameApp.Coroutine` do not exist | The corresponding subsystem package is not installed, or macros such as `ENABLE_GAME_FRAME_X_ENTITY` / `ENABLE_GAME_FRAME_X_COROUTINE` are not defined | Install the corresponding package in the Package Manager and add the macro definitions in the project's `csc.rsp` or `Scripting Define Symbols` |
| Returns `null` or throws a null reference when called | `GameEntry` is not mounted in the scene, or the subsystem is not registered as a component on `GameEntry` | Add the `GameEntry` prefab to the startup scene and verify the target component is checked in the Inspector |
| Coroutine does not execute | The method passed to `StartCoroutine` does not return an `IEnumerator`, or the call was made after the `Mono` context was destroyed | Verify the method signature and avoid starting coroutines on destroyed objects |
| Sound/Scene interfaces cannot be found | The subsystem package has not been upgraded to a version matching the current entry package | Upgrade the corresponding runtime package, or refer to the actual signatures of the target version's `SoundComponent` / `SceneComponent` |

## Background (Optional)

`GameApp` is a `partial class`; each subsystem corresponds to a `Runtime/GameApp.{Name}.cs` file, each guarded by `#if` and decoupled from the others, for the purpose of trimming the package as needed. All components are obtained via the lazy-loading pattern of `GameEntry.GetComponent<T>()`; on first access, `GameEntry` instantiates and caches them in `GameApp`'s private static fields, and subsequent calls directly return the cached instances—ensuring global uniqueness while avoiding module load-order issues.
