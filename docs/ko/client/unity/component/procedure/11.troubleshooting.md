# 자주 묻는 질문

이 문서는 GameFrameX Procedure 프로시저 관리 컴포넌트 사용 시 발생할 수 있는 일반적인 문제, 오류 및 해결책을 정리합니다.

## 개요

Procedure 프로시저 관리 컴포넌트는 Game Framework의 유한 상태 머신(FSM) 기반으로 구현된 게임 프로시저 관리 시스템입니다. 통합 및 사용 과정에서 개발자는 구성 오류, 의존성 누락, 유형 분석 실패 등의 문제에 직면할 수 있습니다. 이 문서는 개발자가这些问题를 빠르게 파악하고 해결할 수 있도록 도와줍니다.

## 의존성 문제

### FSMComponent가 올바르게 구성되지 않음

**증상**: 게임 시작 후 응답이 없거나 `Procedure manager is invalid.` 오류 발생

**원인**: ProcedureComponent는 `IProcedureManager` 모듈에 의존하며, 해당 모듈은 `GameFrameworkEntry`를 통해 가져와야 합니다. FSMComponent가 올바르게 초기화되지 않으면 모듈 가져오기에 실패할 수 있습니다.

**해결책**:
1. 씬에 `FSMComponent` 컴포넌트가 추가되어 있는지 확인
2. `GameFrameworkEntry`가 모든 필수 모듈을 올바르게 초기화했는지 확인
3. GameFramework의 초기화 순서를 확인하여 기본 컴포넌트가 먼저 초기화되도록 함

> Source: [ProcedureComponent.cs#L64-L68](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L64-L68)

---

### 필수 GameFramework 컴포넌트 누락

**증상**: 실행 시 NullReferenceException 또는 모듈 가져오기 실패 발생

**원인**: GameFramework는 완전한 컴포넌트 체계로, Procedure 컴포넌트는 여러底層 모듈에 의존합니다

**해결책**:
1. GameFrameX 핵심 라이브러리가 설치되어 있는지 확인
2. 프로젝트에 다음 의존성이 포함되어 있는지 확인:
   - `GameFrameX.Fsm.Runtime` - 유한 상태 머신 모듈
   - `GameFrameX.Runtime` - 핵심 실행 시 모듈

## 구성 문제

### 프로시저 유형 이름 구성 오류

**증상**: 콘솔에 `Can not find procedure type '{0}'.` 오류 표시

**원인**: `m_AvailableProcedureTypeNames` 배열에 구성된 프로시저 유형 이름이 실제 클래스명과 일치하지 않음

**해결책**:
1. Inspector 패널의 `Available Procedure Type Names` 구성 확인
2. 유형 이름에 완전한 클래스명(네임스페이스 포함) 사용 확인
3. 프로시저 클래스가 `ProcedureBase`에서 상속되는지 확인

```csharp
// 올바른 예시
namespace MyGame.Procedure
{
    public class ProcedureLaunch : ProcedureBase
    {
        // 프로시저 구현
    }
}
```

구성 시 입력: `MyGame.Procedure.ProcedureLaunch`

> Source: [ProcedureComponent.cs#L76-L81](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L76-L81)

---

### 진입 프로시저 미설정

**증상**: 콘솔에 `Entrance procedure is invalid.` 오류 표시

**원인**: `m_EntranceProcedureTypeName`이 설정되지 않았거나 설정된 값이 `m_AvailableProcedureTypeNames` 목록에 없음

**해결책**:
1. Inspector 패널에서 `Entrance Procedure Type Name` 설정
2. 진입 프로시저 이름이 `Available Procedure Type Names`의 프로시저와 완전히 일치하는지 확인
3. 진입 프로시저는 게임 시작 후 가장 먼저 실행되는 프로시저

> Source: [ProcedureComponent.cs#L90-L100](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L90-L100)

---

### 프로시저 배열이 비어 있음

**증상**: 시작 시 어떤 프로시저도 실행되지 않거나 배열 범위 초과 오류 발생

**원인**: `m_AvailableProcedureTypeNames`가 구성되지 않았거나 비어 있음

**해결책**:
1. ProcedureComponent의 Inspector 패널에서 최소 하나의 프로시저 유형 추가
2. 다음 기본 프로시저를 포함할 것을 권장:
   - 시작 프로시저 (ProcedureLaunch)
   - 핫 업데이트 프로시저 (ProcedureCheckVersion)
   - 로그인 프로시저 (ProcedureLogin)
   - 게임 프로시저 (ProcedureGame)

## 유형 분석 문제

### 어셈블리 유형 가져오기 실패

**증상**: `Utility.Assembly.GetType()`이 null을 반환하여 프로시저 생성 실패

**원인**:
1. 유형 이름 철자 오류
2. 프로시저 클래스가 어셈블리에 컴파일되지 않음
3. 잘못된 어셈블리 구성 사용

**해결책**:
1. 프로시저 클래스가 올바르게 컴파일되었는지 확인
2. 완전한 유형 이름(네임스페이스 포함) 사용
3. 난독화된 코드의 경우 관련 어셈블리 구성이 올바른지 확인

```csharp
// 잘못된 유형 이름
m_AvailableProcedureTypeNames = new[] { "ProcedureLaunch" };

// 올바른 유형 이름
m_AvailableProcedureTypeNames = new[] { "GameFrameX.Procedure.Runtime.ProcedureLaunch" };
```

> Source: [ProcedureComponent.cs#L83-L88](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L83-L88)

---

### 프로시저 인스턴스 생성 실패

**증상**: `Can not create procedure instance '{0}'.` 오류

**원인**:
1. 프로시저 클래스에 인자 없는 생성자가 없음
2. 생성자가 예외를 발생시킴
3. 프로시저 클래스의 생성자가 아직 초기화되지 않은 시스템에 접근

**해결책**:
1. 프로시저 클래스에 인자 없는 생성자가 있는지 확인
2. 생성자에서 ProcedureManager或其他 GameFramework 컴포넌트에 접근하지 말 것
3. `OnInit`, `OnEnter` 등의 생명 주기 메서드를 사용하여 초기화 수행

```csharp
// 권장: OnEnter에서 초기화 수행
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 여기서 초기화 작업 수행
    }
}
```

## 실행 시 문제

### 프로시저 관리자 미초기화

**증상**: `CurrentProcedure` 또는 `CurrentProcedureTime` 호출 시 예외 발생 `You must initialize procedure first.`

**원인**: ProcedureManager 초기화 완료 전에 관련 속성에 접근

**해결책**:
1. `Start()` 메서드 실행 완료 후 프로시저 관리자에 접근하도록 함
2. 코루틴 또는 이벤트 시스템을 사용하여 초기화 완료 대기

```csharp
// 잘못된 예시: Awake에서 즉시 접근
private void Awake()
{
    var current = CurrentProcedure; // 예외 발생
}

// 올바른 예시: 코루틴에서 대기
private IEnumerator Start()
{
    yield return new WaitForEndOfFrame();
    var current = CurrentProcedure; // 이제 정상 접근 가능
}
```

> Source: [ProcedureManager.cs#L48-L55](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L48-L55)

---

### 프로시저 전환 실패

**증상**: `StartProcedure<T>()` 호출 후 프로시저가 전환되지 않음

**원인**:
1. 지정된 프로시저 유형이 초기화 시 등록되지 않음
2. FSM 상태 머신이 이미销毁됨
3. 프로시저 전환 로직에死循环 존재

**해결책**:
1. 전환 대상 프로시저가 `m_AvailableProcedureTypeNames`에 있는지 확인
2. 전환 시 즉시 이전 프로시저로 복귀하는 코드가 있는지 확인
3. 전환 호출이 실행되는지 디버그 로그로 확인

> Source: [ProcedureManager.cs#L116-L124](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L116-L124)

---

### 프로시저 상태 메서드가 호출되지 않음

**증상**: 사용자 정의 `OnEnter`, `OnUpdate`, `OnLeave` 등의 메서드가 실행되지 않음

**원인**: 프로시저 클래스가 `ProcedureBase`를 올바르게 상속하지 않았거나 메서드를 올바르게 재정의하지 않음

**해결책**:
1. 프로시저 클래스가 `ProcedureBase`에서 상속되는지 확인
2. `override` 키워드를 사용하여 基類 메서드 재정의
3. `base.OnEnter()` 등의 메서드를 호출하여 基類 로직이 실행되도록 함

```csharp
// 올바른 예시
public class ProcedureLogin : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner); // 반드시 호출
        // 사용자 정의 로직
    }
}
```

> Source: [ProcedureBase.cs#L31-L35](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L31-L35)

## 일반적인 오류 코드 참고

| 오류 정보 | 원인 | 해결책 |
|---------|------|---------|
| Procedure manager is invalid. | IProcedureManager 모듈 가져오기 실패 | GameFramework 초기화 및 FSMComponent 확인 |
| Can not find procedure type '{0}'. | 유형 이름 구성 오류 | m_AvailableProcedureTypeNames 구성 확인 |
| Can not create procedure instance '{0}'. | 프로시저 클래스 인스턴스화 실패 | 생성자 및 유형 정의 확인 |
| Entrance procedure is invalid. | 진입 프로시저 미설정 | m_EntranceProcedureTypeName 설정 |
| You must initialize procedure first. | 프로시저 관리자 미초기화 | 초기화 완료 후 접근 |

## 디버깅 기법

### 디버그 로그 활성화

개발 과정에서 상세한 로그 출력을 추가하여 문제 파악에 도움을 받을 수 있습니다:

```csharp
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        Debug.Log("ProcedureLaunch 프로시저 진입");
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        Debug.Log($"ProcedureLaunch가 {procedureOwner.CurrentStateTime:F2}초 실행됨");
    }
}
```

### 프로시저 상태 확인

`ProcedureComponent`가 제공하는 메서드를 사용하여 프로시저 상태를 확인할 수 있습니다:

```csharp
// 지정된 프로시저가 존재하는지 확인
bool hasLogin = procedureComponent.HasProcedure<ProcedureLogin>();

// 현재 프로시저 가져오기
ProcedureBase current = procedureComponent.CurrentProcedure;

// 프로시저 지속 시간 가져오기
float duration = procedureComponent.CurrentProcedureTime;
```
