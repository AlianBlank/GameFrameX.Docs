# How to Query Purchase Records and Consume Purchases

Call `QueryPurchases(PaymentProductType productType)` via `PaymentComponent` to fetch the unconsumed purchase records of the current account; the result is returned through the `OnQueryPurchasesResult` event callback. After obtaining the `PurchaseToken`, call `ConsumePurchase(string purchaseToken)` to complete the consumption; the result is returned through the `OnConsumePurchaseResult` event callback. Both are asynchronous and return no value; results can only be obtained through events.

## Prerequisites

- The `GameFrameX/Payment` component (`PaymentComponent`) has been added to the scene, and the corresponding `IPaymentManager` implementation has been automatically assembled for the platform.
- Initialization has been completed by calling `Init(bool isDebug = false, bool isClientVerify = true)`, and the query should only be initiated after `IsReady()` returns `true`.

## API Overview

| Name | Signature | Description |
|------|------|------|
| Query purchase records | `void QueryPurchases(PaymentProductType productType)` | Query unconsumed purchase records by product type |
| Consume purchase | `void ConsumePurchase(string purchaseToken)` | Consume a purchase with the purchase token |
| Query result event | `event EventHandler<PaymentEventArgs> OnQueryPurchasesResult` | Triggered when the query completes (including failure) |
| Consume result event | `event EventHandler<PaymentEventArgs> OnConsumePurchaseResult` | Triggered when the consumption completes (including failure) |
| Is ready | `bool IsReady()` | Whether the payment system has finished initializing |

## Steps

1. Subscribe to the query and consume result events. Events on `PaymentComponent` are forwarded directly to the internal `IPaymentManager`:

```csharp
public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult
{
    add { _paymentManager.OnQueryPurchasesResult += value; }
    remove { _paymentManager.OnQueryPurchasesResult -= value; }
}

public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult
{
    add { _paymentManager.OnConsumePurchaseResult += value; }
    remove { _paymentManager.OnConsumePurchaseResult -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L48-L64)

2. After initializing and confirming readiness, initiate the query by product type:

```csharp
paymentComponent.Init(isDebug: false, isClientVerify: true);

if (paymentComponent.IsReady())
{
    // Query the unconsumed purchase records of the current account by product type (in-app purchase / subscription)
    paymentComponent.QueryPurchases(productType);
}
```

3. Read the result in the `OnQueryPurchasesResult` callback. On success, the token of each record is in `PaymentEventArgs.PurchaseToken`:

```csharp
private void OnQueryPurchasesResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"Failed to query purchase records: {e.ResultCode} {e.ErrorMessage}");
        return;
    }

    // Raw purchase data (JSON format), which can be sent to the server for verification
    // e.PurchaseData / e.ProductId / e.OrderId / e.PurchaseToken / e.CustomData
}
```

Complete fields of `PaymentEventArgs`:

```csharp
public sealed class PaymentEventArgs : EventArgs
{
    public string ProductId { get; set; }      // Product ID
    public string OrderId { get; set; }        // Order ID
    public string PurchaseToken { get; set; }  // Purchase token
    public PaymentResultCode ResultCode { get; set; } // Payment result code
    public string ErrorMessage { get; set; }   // Error message
    public string PurchaseData { get; set; }   // Raw purchase data (JSON format)
    public string CustomData { get; set; }     // Custom data
}
```

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

4. (After the server verification passes) consume the purchase with the queried token, and confirm the result in `OnConsumePurchaseResult`:

```csharp
paymentComponent.ConsumePurchase(e.PurchaseToken);

private void OnConsumePurchaseResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"Failed to consume purchase: {e.ResultCode} {e.ErrorMessage}");
        return;
    }
    // Consumed; items can be granted/re-issued
}
```

## Common Variants

- **Reconnect/pending order recovery**: On startup or when returning to the foreground, first call `QueryPurchases` to iterate over the unconsumed records returned by `OnQueryPurchasesResult`, and after verification passes, call `ConsumePurchase` on each record to complete the recovery of dropped orders.
- **Subscription products**: Subscription purchases are also queried via `QueryPurchases`, but they are usually not consumed with `ConsumePurchase` (consumption semantics apply to one-time consumable products); whether to consume depends on the channel implementation.
- **Server verification**: If `isClientVerify` is set to `false` during `Init`, send the `PurchaseData` and `PurchaseToken` from the callback to your own server for verification before consuming.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| No callback at all after calling | The call was made without subscribing to `OnQueryPurchasesResult` / `OnConsumePurchaseResult` first | Subscribe to the events before calling query/consume |
| Log shows `Pay Manager is invalid.` | The platform-specific `IPaymentManager` implementation class was not found or not wired up | Check the platform implementation class names on `PaymentComponent` and whether the corresponding channel packages are imported |
| Query/consume callback `ResultCode` is `Failed` or `NetworkError` | Channel service is not connected or a network exception occurred | Retry later; for `NetworkError`, restore the network and query again |
| Consume fails with `ItemNotOwned` | The purchase corresponding to the token has already been consumed or does not exist | Run `QueryPurchases` again to get the latest token; do not reuse old values |
| `VerifyFailed` | Purchase verification did not pass (client-side or server-side verification failed) | Check the verification logic and credentials; consume only after verification passes |

All values of `PaymentResultCode`: `Success`, `Failed`, `Cancelled`, `NetworkError`, `ServiceUnavailable`, `ItemAlreadyOwned`, `ItemNotOwned`, `VerifyFailed`, `Unknown`.

## Verification

- `QueryPurchases` triggers `OnQueryPurchasesResult` once, with `ResultCode == PaymentResultCode.Success`.
- `ConsumePurchase(token)` triggers `OnConsumePurchaseResult` once, with `ResultCode == PaymentResultCode.Success`.
- Querying the same product type again no longer returns the record that was consumed.

## Background

`PaymentComponent` selects the implementation class based on the compilation platform in `Awake` (Android uses `GooglePaymentManager`, iOS/Mac uses `ApplePaymentManager`, WebGL/PC each have their own implementations, and other platforms fall back to `DefaultPaymentManager`), then obtains the instance via `GameFrameworkEntry.GetModule<IPaymentManager>()`; the events and methods are direct forwards to that instance. `RaiseQueryPurchasesResult` / `RaiseConsumePurchaseResult` in `BasePaymentManager` are responsible for dispatching the results of each channel implementation to the above events. For the overall structure of the payment system, see the overview page.
