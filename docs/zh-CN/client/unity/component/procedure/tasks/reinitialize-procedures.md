# 如何重置流程列表

在运行时销毁当前流程状态机并使用新的流程数组重新初始化,通过一次调用即可完成"清空 + 重建"。本文档介绍 `ReinitializeProcedures` 的两种入口与正确用法。

## 前置条件

- 已通过 `GameEntry.GetComponent<ProcedureComponent>()` 获取流程组件实例
- 已定义至少一个继承自 `ProcedureBase` 的流程类
- 框架已完成初始化(`m_ProcedureFsm` 存在或不存在均可)

## 操作步骤

1. **构建新的流程数组**:实例化所有要注册到新状态机的流程对象。

   ```csharp
   var procedures = new ProcedureBase[]
   {
       new LaunchProcedure(),
       new LoginProcedure(),
       new GameProcedure(),
   };
   ```

2. **指定入口流程**:从同一组流程中选一个作为入口流程。

   ```csharp
   var entrance = procedures[1]; // LoginProcedure
   ```

3. **调用重置方法**:通过流程组件执行重置,框架会先销毁旧状态机,再用新数组重建。

   ```csharp
   ProcedureComponent procedureComponent = GameEntry.GetComponent<ProcedureComponent>();
   procedureComponent.ReinitializeProcedures(procedures, entrance);
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

4. **(可选)启动入口流程**:如需立即进入流程,调用 `StartProcedure`。

   ```csharp
   procedureComponent.StartProcedure(entrance.GetType());
   ```

## 常见变体

### 直接使用流程管理器

如果不经过 `ProcedureComponent` 包装,可在管理器层直接调用 `ReinitializeProcedures(params ProcedureBase[] procedures)`,签名只接受流程数组,不包含入口流程入口设置。

```csharp
m_ProcedureManager.ReinitializeProcedures(new ProcedureBase[]
{
    new LaunchProcedure(),
    new LoginProcedure(),
});
```

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L260-L271)

### 仅销毁(不清空重建)

若只想清空现有流程而不重建,使用 `DestroyProcedures()`:

```csharp
procedureComponent.DestroyProcedures();
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L107-L111)

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 抛出 `GameFrameworkException("Procedures is invalid.")` | 传入的 `procedures` 数组长度为 0 | 至少传入一个 `ProcedureBase` 实例 |
| 重置后旧流程的 `OnDestroy` 未触发 | 旧流程引用仍被外部持有,状态机销毁回调未执行 | 不要在外部长期缓存 `ProcedureBase` 实例 |
| 调用后 `CurrentProcedure` 抛异常 | 重建后未调用 `StartProcedure` | 重置后调用 `StartProcedure` 指定入口 |
| `NullReferenceException` | `ProcedureComponent` 未注册到框架 | 确保场景中已挂载并启用了 `ProcedureComponent` |

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L264-L270)

## 背景(可选)

`ReinitializeProcedures` 内部顺序为:先调用 `DestroyProcedures()` 销毁旧状态机,再校验新数组非空,最后用 `m_FsmManager.CreateFsm(this, procedures)` 重建 FSM。`ProcedureComponent` 包装层在此基础上额外保存 `m_EntranceProcedure`,供后续 `StartProcedure` 使用。

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L260-L271)
