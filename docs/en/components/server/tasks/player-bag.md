# Implementing the Player Bag Module

After completing this task, you will have a working player bag component: it supports adding, removing, and using items, as well as querying all bag data. Data is automatically persisted via Actor state, and clients are proactively notified when items change.

## Prerequisites

- The framework's Actor/Component system has been set up, and you understand the basic usage of `StateComponent` and `StateComponentAgent`.
- The item configuration table `TbItemConfig` has been registered via `ConfigComponent` (the code verifies item existence via `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(itemId, out _)`).
- The client/server has generated message types such as `ReqBagInfo`, `RespBagInfo`, `ReqAddItem`, `RespAddItem`, `ReqRemoveItem`, `RespRemoveItem`, `ReqUseItem`, `RespUseItem`, `NotifyBagInfoChanged`, and `NotifyBagItem` based on the ProtoBuf protocol `Proto/_0100_Bag.cs`.

### 3. Implement BagComponentAgent in the Hotfix Layer

In `GameFrameX.Hotfix/Logic/Player/Bag/BagComponentAgent.cs`, inherit from `StateComponentAgent<BagComponent, BagState>` and implement the four core methods: "Add / Remove / Use / Query". All methods first verify item existence via `ConfigComponent`, then modify the state and persist it via `OwnerComponent.WriteStateAsync()`.

```csharp
using GameFrameX.Apps.Player.Bag.Component;
using GameFrameX.Apps.Player.Bag.Entity;
using GameFrameX.Config;
using GameFrameX.Config.Tables;

namespace GameFrameX.Hotfix.Logic.Player.Bag;

public class BagComponentAgent : StateComponentAgent<BagComponent, BagState>
{
    public async Task<BagState> UpdateChanged(INetWorkChannel netWorkChannel, Dictionary<int, long> itemDic)
    {
        var bagState = OwnerComponent.State;
        var notifyBagInfoChanged = new NotifyBagInfoChanged();
        foreach (var item in itemDic)
        {
            var notifyBagItem = new NotifyBagItem() { ItemId = item.Key };
            if (bagState.List.TryGetValue(item.Key, out var value))
            {
                value.Count += item.Value;
                notifyBagItem.Count = value.Count;
                notifyBagItem.Value = item.Value;
            }
            else
            {
                bagState.List[item.Key] = new BagItemState() { Count = item.Value, ItemId = item.Key };
                notifyBagItem.Count = item.Value;
                notifyBagItem.Value = item.Value;
            }

            notifyBagInfoChanged.ItemDic[item.Key] = notifyBagItem;
        }

        // A null netWorkChannel means offline granting: only persist the bag, do not push a client notification
        if (netWorkChannel != null)
        {
            await netWorkChannel.WriteAsync(notifyBagInfoChanged);
        }

        await OwnerComponent.WriteStateAsync();
        return bagState;
    }
}
```

The entry method for adding items validates each item against the configuration table; on failure it sets `response.ErrorCode = (int)OperationStatusCode.NotFound`.

```csharp
public async Task OnAddBagItem(INetWorkChannel netWorkChannel, ReqAddItem message, RespAddItem response)
{
    foreach (var item in message.ItemDic)
    {
        if (!ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(item.Key, out var itemConfigState))
        {
            response.ErrorCode = (int)OperationStatusCode.NotFound;
            return;
        }
    }

    var result = await UpdateChanged(netWorkChannel, message.ItemDic);
    if (result.IsNull())
    {
        response.ErrorCode = (int)OperationStatusCode.Unprocessable;
    }
}
```

### 5. Implement the Query Logic

`OnReqBagInfoAsync` converts the item list in the state into the response message's `Dictionary<int, long>(ItemId -> Count)`, allowing the client to fetch the complete bag in a single request.

```csharp
public async Task OnReqBagInfoAsync(INetWorkChannel netWorkChannel, ReqBagInfo message, RespBagInfo response)
{
    var bagState = OwnerComponent.State;
    if (bagState.IsNotNull())
    {
        response.ItemDic = bagState.List.ToDictionary(x => x.Key, x => x.Value.Count);
    }

    await Task.CompletedTask;
}
```

## Common Variants

- **Offline rewards**: Call `UpdateChanged(netWorkChannel: null, itemDic)`. When `netWorkChannel` is `null`, the client push is skipped and only persistence is performed — suitable for unified reward-granting interfaces such as mail attachments and login rewards.
- **Item consumption on use**: In `OnUseBagItem`, when the count drops to 0, remove the item directly from `bagState.List` and reset `value.Count` to 0; at the same time, push the change to the client via `NotifyBagInfoChanged`.
- **Removal validation**: `OnRemoveBagItem` returns `OperationStatusCode.Unprocessable` directly when the item count is insufficient, and returns `OperationStatusCode.NotFound` when the item does not exist.

## Common Mistakes

- **Component not registered**: `BagComponent` must be annotated with `[ComponentType(GlobalConst.ActorTypePlayer)]`; otherwise the player Actor will not mount the component and `OwnerComponent.State` will have no data.
- **Item not configured in the config table**: `OnAddBagItem` / `OnRemoveBagItem` / `OnUseBagItem` all validate items via `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)`; an unconfigured item returns `NotFound` directly and no state is written.
- **Passing a network channel for offline rewards**: This causes a client that should not see the change while online to receive the push, leading to data synchronization issues; pass `null` in offline scenarios.
- **Forgetting to persist after deduction**: Any branch that modifies `bagState.List` must call `await OwnerComponent.WriteStateAsync();`; otherwise the state only exists in memory and is lost after a process restart.

## Background (Optional)

- `BagComponent` is a `StateComponent<BagState>`; serialization and persistence are handled by the Actor framework, and the Hotfix layer's `BagComponentAgent` obtains the `BagState` instance via `OwnerComponent` and modifies it in place.
- After adding / using items, the server proactively calls `WriteAsync(notifyBagInfoChanged)` to push incremental changes to the client, avoiding client-side polling.
