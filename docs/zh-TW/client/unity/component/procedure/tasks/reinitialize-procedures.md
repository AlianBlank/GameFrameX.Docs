# 如何重設流程組件

本文檔說明如何在執行階段銷毀當前的流程狀態機，並使用新的流程陣列重新初始化，在單次呼叫中完成「清除 + 重建」。文中介紹 `ReinitializeProcedures` 的兩個入口點及其正確用法。

## 前置條件

- 已透過 `GameEntry.GetComponent<ProcedureComponent>()` 取得流程組件實例
- 已定義至少一個繼承自 `ProcedureBase` 的流程類別
- 框架已完成初始化(`m_ProcedureFsm` 是否存在皆可)

## 步驟

1. **建構新的流程陣列**：將所有要註冊到新狀態機的流程物件實例化。

   ```csharp
   var procedures = new ProcedureBase[]
   {
       new LaunchProcedure(),
       new LoginProcedure(),
       new GameProcedure(),
   };
   ```

2. **指定入口流程**：從同一組流程中選擇一個作為入口流程。

   ```csharp
   var entrance = procedures[1]; // LoginProcedure
   ```

3. **呼叫重設方法**：透過流程組件執行重設。框架會先銷毀舊的狀態機，再以新陣列重建。

   ```csharp
   ProcedureComponent procedureComponent = GameEntry.GetComponent<ProcedureComponent>();
   procedureComponent.ReinitializeProcedures(procedures, entrance);
   ```

   來源:[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

4. **(可選)啟動入口流程**：如果需要立即進入該流程，請呼叫 `StartProcedure`。

   ```csharp
   procedureComponent.StartProcedure(entrance.GetType());
   ```

## 常見變體

### 直接使用流程管理器

如果不使用 `ProcedureComponent` 包裝，可以直接在管理器層級呼叫 `ReinitializeProcedures(params ProcedureBase[] procedures)`。該方法簽章僅接受流程陣列，不包含入口流程的設定。

```csharp
m_ProcedureManager.ReinitializeProcedures(new ProcedureBase[]
{
    new LaunchProcedure(),
    new LoginProcedure(),
});
```

來源:[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L260-L271)

### 僅銷毀(不重建)

如果只想清除現有流程而不重建，請使用 `DestroyProcedures()`:

```csharp
procedureComponent.DestroyProcedures();
```

來源:[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L107-L111)

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 拋出 `GameFrameworkException("Procedures is invalid.")` | 傳入的 `procedures` 陣列長度為 0 | 傳入至少一個 `ProcedureBase` 實例 |
| 重設後舊流程的 `OnDestroy` 未觸發 | 舊流程的參考仍被外部持有，導致狀態機銷毀回呼未執行 | 不要長時間在外部快取 `ProcedureBase` 實例 |
| 呼叫後 `CurrentProcedure` 拋出例外 | 重建後未呼叫 `StartProcedure` | 重設後呼叫 `StartProcedure` 以指定入口 |
| `NullReferenceException` | `ProcedureComponent` 未在框架中註冊 | 確認 `ProcedureComponent` 已掛載於場景中並處於啟用狀態 |

來源:[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L264-L270)

## 背景說明(可選)

`ReinitializeProcedures` 的內部執行順序為：先呼叫 `DestroyProcedures()` 銷毀舊狀態機，接著驗證新陣列不為空，最後使用 `m_FsmManager.CreateFsm(this, procedures)` 重建 FSM。`ProcedureComponent` 包裝在此基礎上額外儲存了 `m_EntranceProcedure`,供後續的 `StartProcedure` 呼叫使用。

來源:[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L260-L271)
