# 如何配置 ProcedureComponent

`ProcedureComponent` 是 GameFrameX 流程系统的入口组件，负责注册 `IProcedureManager`、收集可用的流程类，并在启动时进入指定的入口流程。本页介绍如何在 Unity 中配置它，让游戏按预期从入口流程开始运行。

## 前置条件

- 已将 `GameFrameX.Procedure` 程序集添加到项目中。
- 已准备好一个继承自 [ProcedureBase](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L80) 的流程类（例如入口流程 `ProcedureLaunch`）。
- 场景中存在 `GameFramework` 预制体（包含 `GameFrameXEntry` / `GameFrameworkEntry`），用于承载 `GameFrameworkComponent` 派生组件。

## 操作步骤

1. 在场景中挂载 `GameFramework` 预制体，使用 **Add Component → GameFrameX → Procedure** 添加 `ProcedureComponent`。

   组件属性会通过 `ProcedureComponentInspector` 在 Inspector 中以可视化方式呈现：

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Procedure")]
   [GameFrameXAutoComponent(-1000)]
   public sealed class ProcedureComponent : GameFrameworkComponent
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L43-L46)

2. 在 Inspector 的 **Available Procedures** 区域勾选需要启用的所有流程类（必须继承 `ProcedureBase`）。Inspector 通过反射 `typeof(ProcedureBase)` 自动收集候选类型：

   ```csharp
   m_ProcedureTypeNames = TypeHelper.GetRuntimeTypeNames(typeof(ProcedureBase));
   ```

   Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L162-L165)

3. 在 **Entrance Procedure** 下拉框中选择入口流程。该值会写入序列化字段 `m_EntranceProcedureTypeName`，启动时通过类型匹配找到入口实例：

   ```csharp
   if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
   {
       m_EntranceProcedure = procedures[i];
   }
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L152-L155)

4. 进入 Play 模式后，组件会在 `Start` 协程中调用 `Initialize` 与 `StartProcedure`：

   ```csharp
   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   yield return new WaitForEndOfFrame();
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

5. 运行后可在 Inspector 顶部的 **Current Procedure** 字段看到当前流程：

   ```csharp
   EditorGUILayout.LabelField("Current Procedure", currentProcedureName);
   ```

   Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L83)

## 常见变体

- **使用 StartupRunner 接管启动**：勾选 Inspector 中的 **Use Startup Runner**。该模式仅在 `Awake` 中注册 `IProcedureManager`，不再调用 `Initialize` 与 `StartProcedure`，由 `ApplicationStartupEntry` 通过 `StartupRunner.Run` 统一接管：

  ```csharp
  if (m_UseStartupRunner)
  {
      // 由 ApplicationStartupEntry + StartupRunner.Run 接管 Initialize 和 StartProcedure，
      // 本组件仅承担 Awake 注册 IProcedureManager 的职责，避免与新入口重复 Initialize 报 Already exist FSM。
      yield break;
  }
  ```

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L122-L127)

  勾选后 Inspector 会显示提示信息，并忽略下方的 **Available Procedures** 与 **Entrance Procedure** 配置：

  ```csharp
  EditorGUILayout.HelpBox("流程启动已委托给 StartupRunner.Run。Available Procedures 与 Entrance Procedure 配置将被忽略。", MessageType.Info);
  ```

  Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L59)

- **运行时重建流程**：调用 `ReinitializeProcedures` 销毁现有状态机并以新的流程数组重新初始化，常用于热更新或自定义启动顺序：

  ```csharp
  [Preserve]
  public void ReinitializeProcedures(ProcedureBase[] procedures, ProcedureBase entranceProcedure)
  {
      m_ProcedureManager.ReinitializeProcedures(procedures);
      m_EntranceProcedure = entranceProcedure;
  }
  ```

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

## 常见错误

| 现象 | 日志原文 | 原因与修复 |
|------|----------|-----------|
| 流程没有启动 | `Available procedure type names is empty. Procedure auto start skipped.` | Inspector 中 **Available Procedures** 为空，勾选至少一个流程类后再运行。 |
| 无法创建实例 | `Can not find procedure type '{0}'.` | 类型名不在运行时程序集中，确认流程类已被编译、且命名空间完整。 |
| 创建失败 | `Can not create procedure instance '{0}'.` | 流程类缺少无参构造函数或未继承 `ProcedureBase`。 |
| 没有入口 | `Entrance procedure is invalid.` | **Entrance Procedure** 未选择，或选择项不在 **Available Procedures** 列表中。 |
| 启动报 FSM 重复 | 启用 StartupRunner 后仍由旧路径 `Initialize` 触发 | 检查是否同时存在两个入口（`ApplicationStartupEntry` 与旧 `ProcedureComponent.Start`），保留其一。 |

## 背景（可选）

`ProcedureComponent` 在 `Awake` 中通过 `GameFrameworkEntry.GetModule<IProcedureManager>()` 获取流程管理器；只有 `IsRuntimeComponentReady` 为真时才会继续，从而避免 Editor 模式下的误初始化。当 `m_UseStartupRunner` 为 `false`（默认）时，`Start` 协程按反射类型名数组构建 `ProcedureBase` 实例并以匹配到的入口流程启动；为 `true` 时仅注册模块，把初始化与启动完全交给 `StartupRunner.Run`，避免重复 `Initialize` 导致 `Already exist FSM` 错误。
