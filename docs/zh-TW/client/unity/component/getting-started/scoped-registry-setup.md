# 如何設定 Scoped Registry 並按需引入元件

透過在 `Packages/manifest.json` 中宣告 `GameFrameX` 的 scoped registry(作用域註冊來源)，你就可以讓 Unity Package Manager 解析所有以 `com.gameframex` 開頭的套件，然後按專案需要挑選要引入的元件。

## 前置條件

- Unity 2019.4 或更高版本(已內建 Package Manager 對 scoped registry 的支援)。
- 專案根目錄下存在 `Packages/manifest.json`(Unity 建立專案時自動產生)。

## 操作步驟

1. 開啟專案根目錄下的 `Packages/manifest.json`,在檔案結尾的 `"scopedRegistries"` 陣列中加入 GameFrameX 註冊來源(若陣列已存在，直接附加一項即可)：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L72)

2. 在同一檔案的 `"dependencies"` 中，先加入核心執行階段套件 `com.gameframex.unity`(其餘元件都相依於它)：

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

3. 按需加入其他元件的相依項目，例如資源管理、UI、網路、流程管理等。完整的 `dependencies` 寫法如下(節錄自本儲存庫 `Packages/manifest.json`):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0",
    "com.gameframex.unity.asset": "3.1.0",
    "com.gameframex.unity.config": "1.2.0",
    "com.gameframex.unity.coroutine": "1.1.0",
    "com.gameframex.unity.entity": "2.4.5",
    "com.gameframex.unity.entry": "1.3.0",
    "com.gameframex.unity.event": "1.3.0",
    "com.gameframex.unity.fsm": "1.2.0",
    "com.gameframex.unity.network": "2.6.10",
    "com.gameframex.unity.procedure": "1.4.0",
    "com.gameframex.unity.sound": "1.3.0",
    "com.gameframex.unity.ui": "2.11.0",
    "com.gameframex.unity.ui.fairygui": "3.4.2"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

4. 儲存檔案後回到 Unity 編輯器，Package Manager 會自動抓取新增的註冊來源與相依套件；等待清單重新整理完成，左側即可看到 `GameFrameX - Scoped Registry` 分類下的所有可用套件。

5. 版本號以 [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) 頁面或 [GameFrameX UPM Registry](https://gameframex.upm.alianblank.uk) 為準；將 `"1.11.0"`、`"2.0.0"` 這類佔位版本替換為實際目標版本即可。

## 常見變體

- **透過 Unity 編輯器新增**：在 `Edit ▸ Project Settings ▸ Package Manager ▸ Scoped Registries` 頁面點擊 `+`,填入 `Name=GameFrameX`、`URL=https://gameframex.upm.alianblank.uk`、`Scopes=com.gameframex`。儲存後效果與直接編輯 `manifest.json` 一致。
- **同時使用多個註冊來源**:`scopedRegistries` 是陣列，可在其中並列多個物件。本儲存庫就同時宣告了 GameFrameX 和 `package.openupm.com`(用於 `io.sentry` 作用域)：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    },
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["io.sentry"]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L80)

- **透過 Git URL 直接安裝第三方元件**：對於未發佈到 UPM 的套件(例如 HybridCLR),可在 `dependencies` 中直接填寫 Git 位址，繞過 scoped registry:

```json
{
  "dependencies": {
    "com.code-philosophy.hybridclr": "https://gitee.com/focus-creative-games/hybridclr_unity.git"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L3-L3)

- **只引入最小集合**：刪除不需要的相依套件即可，GameFrameX 各元件按模組化拆分，無強制綁定關係；只保留 `com.gameframex.unity` 與 `com.gameframex.unity.entry` 也能正常啟動。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| Package Manager 回報 `Unable to find package com.gameframex.unity` | `scopedRegistries` 未宣告，或 `scopes` 寫成 `com.gameframex.unity` | 在 `scopedRegistries` 中加入 `scopes: ["com.gameframex"]` |
| 套件能下載但 `assembly definition` 找不到命名空間 | 只引入了 `com.gameframex.unity` 沒有引入 `com.gameframex.unity.entry`,或漏裝子模組 | 補齊缺失的 `com.gameframex.unity.*` 相依套件，確認 `com.gameframex.unity.entry` 已加入 |
| 編輯器一直卡在 "Resolving packages" | 多個註冊來源的 `scopes` 互相重疊，觸發重複解析 | 讓每個 scoped registry 的 `scopes` 互不重疊，例如 GameFrameX 用 `com.gameframex`、OpenUPM 用 `io.sentry` |
| 升級到新版本後 `dll` 缺失 | `dependencies` 裡仍固定在舊版本，且新版本調整了套件結構 | 在 [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) 查閱遷移說明後，統一更新版本號 |

## 背景(可選)

Scoped registry 是 Unity Package Manager 自 2019.3 起的官方機制：它透過 URL + 命名空間作用域(`scopes`)把私有/公用 npm 風格的 UPM 註冊來源接入專案，而不影響官方套件和既有相依套件。本儲存庫把 `com.gameframex.*` 全部託管在自建的 UPM registry `https://gameframex.upm.alianblank.uk`,因此只要作用域相符，Package Manager 就能按版本解析到對應的 tarball。
