# How to Play Rewarded Video Ads

Follow the steps on this page to call the GameFrameX Advertisement component to play rewarded video ads, and after the user has watched the ad completely, receive the reward grant callback through `AdvertisementPlayOption.OnShowResult` to distribute in-game items such as coins and revival attempts.

## Prerequisites

1. The `com.gameframex.unity.advertisement` package has been integrated into the project, and the underlying ad SDKs (such as Pangle, Tencent Ads, and various WebGL mini-game ad aggregations) have been integrated and initialized.
2. There is a GameObject in the scene with the [AdvertisementComponent](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L45-L46) attached, and the ad slot ID for the corresponding platform (Android/iOS/WebGL/WeChat/DouYin/KuaiShou) is filled in the Inspector.
3. If calling via script, you need to obtain the component reference first:

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;

public class RewardAdCaller : MonoBehaviour
{
    private AdvertisementComponent _adComponent;

    private void Awake()
    {
        _adComponent = GetComponent<AdvertisementComponent>();
    }
}
```

## Steps

1. Fill in the rewarded video ad slot ID for each platform in the Inspector. The component will automatically select the corresponding ID based on the current build platform (see [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)).

2. (Optional) Before `Start`, configure the extra fields required for the server callback of the rewarded ad, such as user ID, order number, etc.:

```csharp
_adComponent.SetExtraData("userId", "10001");
_adComponent.SetExtraData("orderId", "20240101001");
```

The implementation of `SetExtraData` is available at [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L173-L189). When `value` is `null`, the key will be removed.

3. When the player clicks the "Watch Ad for Reward" button, construct a [AdvertisementPlayOption](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L85) instance and fill in three callbacks:

```csharp
public void OnClickWatchAd()
{
    var option = new AdvertisementPlayOption
    {
        OnSuccess = msg => Debug.Log($"Rewarded video success: {msg}"),
        OnFail    = err => Debug.LogWarning($"Rewarded video failure: {err}"),
        OnShowResult = watched =>
        {
            // watched == true means the user watched completely, rewards can be granted
            if (watched)
            {
                GrantReward();
            }
        },
        extraData  = "{\"orderId\":\"20240101001\"}", // Only passed through to the server during the Load phase
        customData = "reward_coins_100"               // Passed through to the callback during playback
    };

    _adComponent.Play(option);
}
```

4. Call `Play(AdvertisementPlayOption)` to play the ad. The definition of this method is available at [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L216-L219):

```csharp
_adComponent.Play(option);
```

5. In the `OnShowResult` callback, decide whether to grant the reward based on `watched` (for example, +100 coins). Only the callback after a complete view is considered a valid impression.

## Common Variants

- **Legacy API (marked as `[Obsolete]`)**: The old `Show`/`Load` methods that directly take three `Action` parameters are still available, but the compiler will issue a `CS0618` warning. It is recommended to migrate to `Play(AdvertisementPlayOption)` as soon as possible. The definitions are available at [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L85-L124).
- **Direct call via the manager**: If you don't want to go through `AdvertisementComponent`, you can also call `GameFrameworkEntry.GetModule<IAdvertisementManager>()` and then directly call `Play(AdvertisementPlayOption)`. The signature is available at [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L97-L97).
- **WebGL multi-platform branches**: When targeting WebGL, the rewarded video ad slot ID is determined by the `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` compilation macros respectively. You need to apply for and fill in the ID for each mini-game separately.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Log.Fatal("Advertisement manager is invalid.")` | No `IAdvertisementManager` implementation registered | Integrate the corresponding platform's ad SDK package, or ensure `GameFrameworkEntry` has been initialized before `Awake` |
| `ArgumentNullException: config` | The `AdvertisementConfig` passed to `Initialize` is null | First `new` a configuration object, or assign a value to `m_config` in the Inspector and let `Start` automatically initialize |
| Ad shows but `OnShowResult` is always `false` | The user closed it midway or the underlying SDK reported an error | Print error information in `OnFail` for troubleshooting, and confirm that `extraData`/`customData` did not trigger server-side validation failure |
| WebGL build fails with ad slot not found | Compilation macros not enabled or the corresponding mini-game ID is not filled in | Check the Scripting Define Symbols in Player Settings, and fill in fields such as `m_adUnitIdWebGLWeChat` for that mini-game |

## Background (Optional)

`AdvertisementPlayOption` simultaneously carries the success/failure/display result callbacks as well as two extra fields, `extraData` and `customData`: `extraData` is only serialized into JSON and passed through to the server for reward validation during the `Load` phase, and is invalid after loading is complete; `customData` is passed through to the underlying SDK callback during playback. `BaseAdvertisementManager` uses a `_delegating` mutex to prevent mutual recursion between old and new `Initialize` calls. For details, see [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L111-L163).
