# 热更新加载失败或版本不匹配怎么办

当服务器启动或热更新触发时,热更 DLL(`GameFrameX.Hotfix.dll`)加载、版本校验或运行初始化失败,通常表现为进程直接退出、日志抛出异常,或客户端/管理端提示版本不一致。本页给出常见症状的快速对照与修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `ArgumentException: dllPath` 或 `hotfixDllName` 抛空 | 传入的 `dllPath` 或 `hotfixDllName` 为空字符串 | 按默认值传参,详见"修复步骤-路径与文件名" |
| 找不到 `GameFrameX.Hotfix.dll`,提示文件不存在 | DLL 未拷贝到运行目录,或版本目录与实际目录不一致 | 把 DLL 放到 `dllVersion/dllPath` 对应目录 |
| 加载报 `OnLoadSuccess` 返回 false | 热更桥接实现初始化失败(依赖服务未启动、配置缺失等) | 检查启动顺序与 `AppSetting` 完整性 |
| 客户端提示"版本不匹配" | `dllVersion` 参数指向的目录里 DLL 与框架版本不一致 | 用同一份源码重新编译热更工程后覆盖 DLL |
| 热更后旧模块仍被引用导致类找不到 | 重载期间旧模块被并发请求命中,代理类型已切换 | 等 `DoingHotfix=false` 后再发压或排查日志 |
| 重启服务时偶发 `HotfixAssembly` 为空 | 启动顺序在 `LoadHotfix` 之前调用了 `HotfixManager.HotfixAssembly` | 确认先调用 `LoadHotfix` 再访问程序集 |

## 修复步骤

### 路径与文件名

`HotfixManager.LoadHotfix` / `LoadHotfixModule` 会对 `dllPath`、`hotfixDllName` 做空值校验,并按 `dllVersion` 是否为空来决定实际加载的子目录。

- 默认参数:`dllPath="hotfix"`、`hotfixDllName="GameFrameX.Hotfix.dll"`、`dllVersion=""`。
- 当 `dllVersion` 非空时,会忽略 `dllPath`,改为按版本号子目录加载 DLL。

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
public static bool LoadHotfix(AppSetting setting,
    string dllVersion = "",
    string dllPath = "hotfix",
    string hotfixDllName = "GameFrameX.Hotfix.dll")
{
    ArgumentException.ThrowIfNullOrEmpty(dllPath, nameof(dllPath));
    ArgumentException.ThrowIfNullOrEmpty(hotfixDllName, nameof(hotfixDllName));
    // ...
    var path = Path.Combine(Environment.CurrentDirectory,
        string.IsNullOrEmpty(dllVersion) ? dllPath : $"{dllVersion}",
        hotfixDllName);
    var hotfixModule = new HotfixModule(path);
    var reload = _module != null;
    var success = hotfixModule.Init(reload);
    if (!success) { return false; }
    _module = hotfixModule;
    return true;
}
```

Source: [HotfixManager.cs#L95-L116](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L95-L116)

操作:

1. 确认运行目录下确实存在 `hotfix/GameFrameX.Hotfix.dll`(或 `<dllVersion>/GameFrameX.Hotfix.dll`)。
2. 不要手动把 `dllPath` 传成空字符串;若用版本目录,把 `dllVersion` 设为版本字符串并保留默认 `dllPath`。
3. 若自定义 DLL 名,确保 `hotfixDllName` 与构建产物一致。

### 版本号与 DLL 不一致

当 `dllVersion` 指向的目录里 DLL 与框架宿主版本对不上时,会出现"能加载但行为错乱"或接口签名不一致导致的 `MissingMethodException`。

1. 删除旧版本目录,基于当前分支 `main` 的 `GameFrameX.Hotfix` 工程重新编译。
2. 将新 DLL 拷贝到目标 `dllVersion` 目录(如 `1.0.0/GameFrameX.Hotfix.dll`),与宿主进程指向的版本号保持一致。
3. 启动服务器,在日志中确认 `ReloadTime` 已更新(说明新模块被初始化)。

`ReloadTime` 由 `LoadHotfixModule` 内部刷新:

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
private static async Task<bool> Load(HotfixModule newModule, AppSetting setting, bool reload)
{
    ReloadTime = TimerHelper.GetNowWithUtc();
    if (reload)
    {
        // ... 旧模块延迟 10 分钟后 Unload
    }
    _module = newModule;
    if (_module.HotfixBridge != null)
    {
        return await _module.HotfixBridge.OnLoadSuccess(setting, reload);
    }
    return true;
}
```

### `OnLoadSuccess` 返回 false

热更桥接接口在加载成功后会调用 `OnLoadSuccess`,返回 `false` 即视为加载失败。

```csharp
// GameFrameX.Core/Hotfix/IHotfixBridge.cs
Task<bool> OnLoadSuccess(AppSetting setting, bool reload);
```

Source: [IHotfixBridge.cs#L45](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/IHotfixBridge.cs#L45)

操作:

1. 打开 `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`(或 `ByMain` / `ByHeart`),查看 `OnLoadSuccess` 的实现,定位第一步失败的依赖。
2. 确认该实现依赖的服务(如数据库、Redis、HTTP 注册)在调用前已经初始化完成。
3. 在 `OnLoadSuccess` 内对每个步骤增加更详细的日志,重新触发一次热更,根据新增日志定位失败点。

### 重载期间的并发请求

`HotfixManager` 在重载时会缓存旧模块最多 10 分钟,期间新旧模块会按"请求来自哪个程序集"分别路由。如果旧模块已经 `Unload`,代理查找会失败。

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
if (reload)
{
    var oldModule = _module;
    DoingHotfix = true;
    var oldModuleHash = oldModule.GetHashCode();
    OldModuleMap.TryAdd(oldModuleHash, oldModule);
    _ = Task.Run(async () =>
    {
        await Task.Delay(TimeSpan.FromMinutes(10));
        OldModuleMap.TryRemove(oldModuleHash, out _);
        oldModule.Unload();
        DoingHotfix = !OldModuleMap.IsEmpty;
    });
}
```

Source: [HotfixManager.cs#L158-L172](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L158-L172)

操作:

1. 热更触发后 10 分钟内避免重启服务器或大规模压测旧模块依赖的接口。
2. 若日志出现 "Agent/Component type not found",检查请求是来自旧模块程序集(旧 DLL 残留)还是新模块程序集。
3. 确认旧的 `hotfix` 目录已整体替换,避免 `Environment.CurrentDirectory` 下出现多份 DLL。

## 验证

1. 启动服务器,日志出现 `ReloadTime` 写入且无异常,说明新模块已生效。
2. 调用一次 `HotfixManager.GetAgent<T>(...)` 与 `GetComponentType(...)`,确认新模块代理能正常解析。
3. 在重载场景下观察 `DoingHotfix` 标志位:应先为 `true`,10 分钟后回落为 `false`,旧模块被释放。
4. 客户端/管理端版本号与 `dllVersion` 子目录一致,且能正常登录、收发消息。
