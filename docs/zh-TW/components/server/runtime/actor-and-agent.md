# 使用 Actor / ComponentAgent 排程並行任務

Actor 將「玩家/場景/全域」等業務實體包裝成單執行緒循序執行的排程單元；ComponentAgent 是 Actor 上可重複使用的業務元件,所有跨實體呼叫都透過 `ActorManager` 取得,從而避免鎖並保證資料一致。本頁示範如何取得並呼叫 ComponentAgent 來排程並行任務。

## 前置條件

- 已接入 GameFrameX Actor 框架，`ActorManager` 在執行環境內可存取。
- 已存在一個繼承 `ComponentAgent<TComponent>` 或 `StateComponentAgent<TComponent, TState>` 的元件 Agent。
- 業務實體已具備 `ActorId`(`long` 型別)，無 `ActorId` 的全域 Agent 呼叫使用 `GetComponentAgent<T>()`。

## 操作步驟

1. 在任意可存取 Actor 的位置，透過 `ActorManager` 取得目標元件 Agent。

```csharp
// 全域共享元件(無 ActorId 維度)
var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
await serverComp.RemoveOnlineRole(ActorId);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L46-L53)

2. 需要操作某個玩家的元件時，把玩家 `ActorId` 作為第二個參數傳入，框架會路由到對應 Actor 的循序佇列。

```csharp
var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
await attributeComponentAgent.InitializeDefaultsSilent();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L77-L78)

3. 對同一 Actor 下的多個 Agent 進行循序排程時，按業務順序 `await` 呼叫即可，框架保證同一 Actor 內呼叫循序執行。

```csharp
// 全部落在同一個玩家 ActorId 上,按順序循序執行
var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
await mailAgent.SyncAsync();

var bagAgent = await ActorManager.GetComponentAgent<BagComponentAgent>(playerState.Id);
await bagAgent.SomeBusiness();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L91-L92)

4. 當 Agent 的工作完成後，在持有 Actor 參考的位置設定自動回收，避免常駐。

```csharp
// 下線後會被自動回收
SetAutoRecycle(true);
QuartzTimer.Remove(ScheduleIdSet);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L50-L52)

## 常見變體

| 場景 | 寫法 | 說明 |
|------|------|------|
| 全域單例元件 | `await ActorManager.GetComponentAgent<T>()` | 不傳 `ActorId`,取得處理序層級共享 Agent |
| 玩家私有元件 | `await ActorManager.GetComponentAgent<T>(actorId)` | 框架按 `actorId` 路由到對應玩家 Actor |
| 房間/場景元件 | `await ActorManager.GetComponentAgent<RoomComponentAgent>()` | 通常為全域 Agent,內部再按房間 Key 索引 |

## 常見錯誤

- 直接 `new T()` 建立 Agent:Agent 必須由 `ActorManager` 建立並託管，手動實例化會繞過循序佇列與回收機制。
- 在不持有 `ActorId` 的地方呼叫玩家私有 Agent:會因找不到 Actor 而拋出錯誤；全域元件請使用無參數 `GetComponentAgent<T>()`。
- 忘記在玩家下線時呼叫 `SetAutoRecycle(true)`:Agent 會持續駐留，佔用佇列與計時器資源(參考 [PlayerComponentAgent.OnLogout](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L45-L53))。

## 背景(可選)

Actor 模型將「對同一玩家/場景的並行存取」轉化為循序訊息佇列，ComponentAgent 則是掛在 Actor 上的業務單元;`ActorManager` 同時承擔元件生命週期與跨 Actor 路由，這也是登入流程裡所有初始化操作都能在單一 `await` 鏈中完成而無需鎖的原因。
