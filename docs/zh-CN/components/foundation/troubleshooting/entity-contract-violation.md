# 实体契约校验失败怎么办

当 `EntityContractValidator.Validate<T>()` 返回非空列表、或运行期 ORM 报接口属性不一致时，说明实体类没有满足它所实现接口（如 `IEntity`、`IVersionedEntity`、`IAuditableEntity`）的契约。本页按错误信息给出定位与修复方法。

## 快速诊断

| 症状（`Reason` 文本片段） | 根因 | 修复 |
|------|------|------|
| `Property 'XXX' not found on type 'YYY'` | 实体类缺少接口要求的属性 | 在实体类中添加同名同类型属性 |
| `Property 'XXX' type mismatch: expected 'A', actual 'B'` | 属性类型与接口声明不一致 | 将属性类型改为接口要求类型（或可空兼容类型） |
| `Property 'XXX' is missing a getter` | 属性声明为 `set` 而无 `get`（或 `private get`） | 补上 public getter |
| `Property 'XXX' is missing a setter` | 属性只有 `get` 没有 `set`（或 `private set`） | 补上 public setter |
| `Property 'XXX' has multiple declarations on type 'YYY' (possible 'new' keyword shadowing)` | 用 `new` 关键字遮蔽了继承来的接口属性 | 移除 `new`，或合并为单一属性 |
| 调用 `Validate(null)` 抛 `ArgumentNullException` | 传入了 null 的 `Type` | 传入非 null 的实体类型 |

## 修复步骤

### 1. 缺少属性

接口要求某字段（如 `IVersionedEntity.Version`）而实体类没有声明。直接在实体类中补上对应属性即可：

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class Player : IVersionedEntity
{
    public long Version { get; set; } // 补齐接口要求的属性
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118)

### 2. 类型不匹配

接口声明 `DateTime`，实体却写成了 `DateTimeOffset` 或 `string`。把类型改回接口要求；接口是值类型时，实体可以使用对应的 `Nullable<T>`，验证器会通过 `Nullable.GetUnderlyingType` 做兼容判断。

```csharp
public interface IAuditableEntity
{
    DateTime CreatedAt { get; set; }
}

public class Order : IAuditableEntity
{
    public DateTime CreatedAt { get; set; } // 类型必须匹配；DateTime? 也可以
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

### 3. 缺少 getter / setter

ORM 经常需要读写两侧。补全访问器：

```csharp
public DateTime UpdatedAt { get; set; } // get 与 set 都必须 public
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144)

### 4. `new` 关键字遮蔽

从基类继承的属性被 `new` 重新声明，导致 `GetProperty` 命中多个匹配并触发 `AmbiguousMatchException`。删除 `new` 并合并为单一属性：

```csharp
// 错误：new 关键字遮蔽
public new long Version { get; set; }

// 正确：直接沿用基类声明
// （删除整段 new 声明，或使用 override/显式接口实现）
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108)

### 5. 自动校验调用

在应用启动或单元测试中调用验证器，把违反项一次性打出来：

```csharp
using GameFrameX.Foundation.Orm.Entity;

var violations = EntityContractValidator.Validate<Player>();
foreach (var v in violations)
{
    Console.WriteLine($"{v.InterfaceType.Name}.{v.PropertyName}: {v.Reason}");
}
```

返回的 `EntityContractViolation` 包含三个字段：`InterfaceType`、`PropertyName`、`Reason`。

## 验证

修复后再次调用 `Validate<T>()`：

- 返回的 `IList<EntityContractViolation>` 长度为 0，表示契约全部满足。
- 若仍返回非空项，按上面的诊断表对照 `Reason` 继续修正，直到列表清空。

## 验证器不会检查什么

`EntityContractValidator` 只校验接口中显式声明的属性：

- 接口继承自其他接口的属性，会随 `Type.GetInterfaces()` 一并纳入校验。
- 字段（`public int Foo;`）、静态成员、私有成员不会被检查。
- 仅当接口本身用属性语法声明该成员时才会校验；用方法表达的契约不在范围内。
