# 빌드 실패 및 핫업데이트 예외 발생 시 대처 방법

이 페이지는 GameFrameX의 `BuildProduct`(빌드 제품) 및 `BuildHotfix`(핫업데이트 빌드) 메뉴 사용 시 흔히 발생하는 문제를 증상에 따라对照 점검하고, 소스 코드와 일치하는 수정 방법을 제시합니다.

## 빠른 진단

| 증상(로그 원문) | 원인 | 수정 방법 |
|------|------|------|
| `当前构建目标不是 Windows` | 메뉴에서 요구하는 현재 `BuildTarget`과 메뉴 대상이 일치하지 않음. 다른 플랫폼으로 전환한 경우 | `File → Build Settings`를 열고 플랫폼을 해당 대상으로 전환한 후 메뉴 실행 |

## 수정 단계

### 1. 플랫폼 불일치("当前构建目标不是 XXX")

`BuildProductHelper`는 각 플랫폼 진입점에서 먼저 `EditorUserBuildSettings.activeBuildTarget`을 검증하며, 일치하지 않으면 바로 `Debug.LogError`를 출력하고 `return`합니다:

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    Debug.Log(EditorUserBuildSettings.activeBuildTarget);
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("当前构建目标不是 Windows");
        return;
    }
    ...
}
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L101-L110)

**조작 방법:**

1. Unity 메뉴 `File → Build Settings…`
2. 진입점에 해당하는 `Target Platform`(Windows64 / macOS / WebGL / Android)으로 전환
3. `Switch Platform`을 클릭하여 플랫폼 전환이 완료될 때까지 대기
4. `GameFrameX → Build → <해당 플랫폼>` 재실행

### 2. AOT 메타데이터 복사 실패("未找到HybridCLR数据目录")

`CopyAOTCode`는 `<Project>/HybridCLRData/AssembliesPostIl2CppStrip/<activeBuildTarget>`에서 `*.dll`을 `Assets/Bundles/AOTCode/`로 복사합니다. 해당 디렉터리가 존재하지 않으면 오류를 출력하고 return합니다:

```csharp
DirectoryInfo aotCodeDir = new DirectoryInfo(path);
if (!aotCodeDir.Exists)
{
    Debug.LogError($"未找到HybridCLR数据目录:{path}");
    return;
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L84-L92)

**조작 방법:**

1. Unity에서 `HybridCLR → Generate`(또는 해당 프로젝트의 `HybridCLR/Generate` 절차)를 열어 Strip 처리된 AOT DLL 생성
2. `HybridCLRData/AssembliesPostIl2CppStrip/<Target>` 아래에 `*.dll`이 나타나는지 확인
3. `GameFrameX → Build → Copy AOT Code` 재실행

### 3. `Unity.HotFix.dll`을 찾을 수 없음

`BuildHotfixHelper.CopyHotfixCode()`는 기본적으로 `Library/ScriptAssemblies/Unity.HotFix.dll`에서 `Assets/Bundles/Code/Unity.HotFix.dll.bytes`로 복사합니다:

```csharp
private const string HotFixAssembliesDir = "Library/ScriptAssemblies";
private static readonly string[] HotfixDlls = new string[] { "Unity.HotFix.dll" };
private const string CodeDir = "Assets/Bundles/Code/";

foreach (var hotfix in HotfixDlls)
{
    var srcPath = Path.Combine(HotFixAssembliesDir, hotfix);
    if (!File.Exists(srcPath))
    {
        continue;
    }
    File.Copy(srcPath, Path.Combine(CodeDir, hotfix + Utility.Const.FileNameSuffix.Binary), true);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L21-L65)

`Library/ScriptAssemblies` 아래에 해당 DLL이 없으면 코드가 조용히 `continue`되며, 최종적으로 `Assets/Bundles/Code/`가 비어 있게 됩니다. **조작 방법:**

1. 프로젝트에 `Unity.HotFix`의 `asmdef`(핫업데이트 어셈블리)가 존재하는지 확인하고, 이름은 반드시 정확하게 `Unity.HotFix.dll`이어야 함
2. 해당 빌드 대상으로 전환한 후 Unity가 다시 컴파일하도록 하여 `Library/ScriptAssemblies/Unity.HotFix.dll`이 생성되는지 확인
3. `GameFrameX → Build → Copy HotFix Code(复制热更新代码到Assets>Bundles>Code)` 재실행
4. `Assets/Bundles/Code/` 아래에 `Unity.HotFix.dll.bytes`가 생성되었는지 확인

### 4. AAB 출력 경로 예외

Android AAB 진입점은 출력 디렉터리를 검증할 때 다음을 출력합니다:

```csharp
Debug.LogError("输出路径异常,取消打包AAB");
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L421)

**조작 방법:**

1. `GameFrameX/Build` 메뉴를 실행하기 전에 빌드 출력 디렉터리를 미리 설정하여 경로가 존재하고 현재 사용자가 쓸 수 있는지 확인
2. 이전 빌드의 잔여물 정리(같은 이름의 이전 AAB 점유, 읽기 전용 파일 등)
3. 해당 Android AAB 진입점 재실행

### 5. 일시적으로 HybridCLR을 끄고 싶을 때

소스 코드에서 매크로 스위치 `DISABLE_HYBRIDCLR`을 제공하며, 메뉴에서 원클릭으로 전환할 수 있습니다:

```csharp
public const string HybridCLRScriptingDefineSymbol = "DISABLE_HYBRIDCLR";

[MenuItem("GameFrameX/Scripting Define Symbols/Disable HybridCLR(关闭HybridCLR适配)", false, 5000)]
public static void DisableHybridCLR()
{
    ScriptingDefineSymbols.AddScriptingDefineSymbol(HybridCLRScriptingDefineSymbol);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L107-L116)

핫업데이트 체인으로 인해 패키징流程 전체가 실패하고 반드시 일단 산출물을 만들어야 할 때, 일시적으로 `GameFrameX → Scripting Define Symbols → Disable HybridCLR`을 거쳐 핫업데이트 관련 단계를 건너뛰어 문제를 파악한 다음, 이후 `Enable HybridCLR`로 복구할 수 있습니다.

## 검증

빌드/핫업데이트 문제 수정 후, 아래 순서로 자가 점검:

1. `BuildProductHelper` 진입점이 더 이상 `当前构建目标不是 XXX` 류의 LogError를 출력하지 않으며, 빌드 보고가 `BuildResult.Succeeded`
2. `Assets/Bundles/Code/Unity.HotFix.dll.bytes`와 `Assets/Bundles/AOTCode/` 아래에 이번 대상의 AOT DLL이 존재
3. 빌드 산출물을 실행했을 때, HybridCLR 핫업데이트 진입점이 정상적으로 핫업데이트 어셈블리를 로드할 수 있는지 확인
