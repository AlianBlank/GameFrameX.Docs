# 如何从旧版 Show/Load 迁移到 Play(option)

把旧的 `Show(success, fail, onShowResult, customData)` 与 `Load(success, fail, customData)` 三参数调用,以及仅传 `Action<bool> onShowResult` 的 `Play`,统一替换为带 `AdvertisementPlayOption` 的 `Play(AdvertisementPlayOption option)` 入口;旧方法已标记 `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`,编译时会发出 `CS0618` 警告,继续使用将被未来版本移除。

## 前置条件

- 已引入 `GameFrameX.Advertisement.Runtime` 命名空间,并能拿到 `IAdvertisementManager` 或组件 `AdvertisementComponent`。
- 了解你当前在用哪个广告渠道的 `BaseAdvertisementManager` 子类,因为新 API 是抽象方法,需要由对应渠道实现覆写。

## 操作步骤

1. **新建一个 `AdvertisementPlayOption` 实例**,把原本散落在参数里的成功/失败/展示结果回调与 `customData` 全部装进它的字段里。

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   var option = new AdvertisementPlayOption
   {
       OnSuccess     = msg => Debug.Log($"成功:{msg}"),
       OnFail        = err => Debug.LogError($"失败:{err}"),
       OnShowResult  = watched => Debug.Log($"是否完整观看:{watched}"),
       customData    = "level=1",
   };
   ```

   Source: [AdvertisementPlayOption.cs#L36-L85](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L36-L85)

2. **用 `Play(option)` 替换旧入口**。在 `AdvertisementComponent` 或 `BaseAdvertisementManager` 上调用,签名完全统一:

   ```csharp
   GameFrameX.Advertisement.Runtime.AdvertisementComponent.Instance.Play(option);
   ```

   Source: [AdvertisementComponent.cs#L215-L219](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L215-L219)

   ```csharp
   public abstract void Play(AdvertisementPlayOption option);
   ```

   Source: [BaseAdvertisementManager.cs#L210-L211](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L210-L211)

3. **按映射表把旧字段搬到 `option` 上**,确认旧代码里没有遗漏的回调被丢掉:

   | 旧 API 参数 / 字段 | 新 `AdvertisementPlayOption` 字段 |
   |--------------------|-----------------------------------|
   | `Show(success, fail, onShowResult, customData)` 中的 `success` | `OnSuccess`(`Action<string>`) |
   | `Show(...)` 中的 `fail` | `OnFail`(`Action<string>`) |
   | `Show(...)` / `Play(playResult, customData)` 中的 `onShowResult` / `playResult` | `OnShowResult`(`Action<bool>`) |
   | `Show(...)` / `Load(...)` / `Play(...)` 中的 `customData` | `customData`(`string`) |
   | 服务端奖励验证所需的扩展数据 | `extraData`(仅在 `Load` 阶段透传,加载后设置无效) |

4. **删掉旧调用点**。如果项目里还有 `Show(success, fail, onShowResult)` 或 `Load(success, fail)` 的用法,逐个替换为 `Play(option)` 即可;编译器会以 `CS0618` 警告提醒你。

## 常见变体

- **只想知道“是否完整观看”**:只填 `OnShowResult`,其他回调保持 `null`。

  ```csharp
  var option = new AdvertisementPlayOption
  {
      OnShowResult = watched => GiveReward(watched),
  };
  ```

- **需要传扩展数据给服务端奖励验证**:使用 `extraData`,注意仅在加载阶段有效。

  ```csharp
  option.extraData = "user_id=42";
  ```

- **自定义渠道需要 `customData`**:直接给 `option.customData` 赋值,等价于旧版同名参数。

## 常见错误

- **把 `extraData` 当成 `customData` 用**:`extraData` 只在 `Load` 阶段透传到服务端奖励验证,广告播放时不生效;面向业务回传请用 `customData`。
- **继续用旧 `Show`/`Load`**:它们已带 `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`,继续使用只是收到警告,但未来版本会移除;同时旧 `Show` 内部用 `#pragma warning disable CS0618` 转发,迁移后可以一并删除。
- **`option` 字段未赋值就调用 `Play`**:如果某个回调(如 `OnFail`)留空,失败时上层不会得到通知,排查问题时容易误判为“广告未触发”。
- **在 `Load` 之后再修改 `extraData`**:文档明确写明“加载后设置无效”,需要服务端验证扩展信息时,务必在调用 `Play(option)` 之前设置。

## 背景(可选)

迁移后,所有渠道管理器只需要覆写一个抽象入口 `Play(AdvertisementPlayOption option)`,回调与扩展数据集中在一处维护,旧 `Show`/`Load`/`Play(Action<bool>, string)` 都标记为过时方法,由组件层转发到新方法,保证 API 表面收敛而调用方零侵入。
