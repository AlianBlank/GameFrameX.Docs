# シーンリソース名が無効な場合の対処法

`LoadScene(string sceneAssetName, ...)` を呼び出す際、渡されたリソース名(パス)が YooAsset リソースリストに存在しない場合、シーンの読み込みは直接失敗します。一般的な症状としては、`LoadSceneFailure` イベントのトリガー、`await` で返される `Task` からの例外スロー、またはエディタログに「リソースが存在しません / asset not found」というメッセージが出力されます。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `LoadSceneFailure` イベントがトリガーされ、`SceneAssetName` が渡した文字列になっている | YooAsset リソースリストにこの `sceneAssetName` が存在しない | 正しい「アセット名/アセットパス」で再試行し、パッケージ出力に登録されていることを確認する |
| `sceneAssetName` が空または null というエラーが出る | 呼び出し前にパスが正しく組み立てられていない、または設定テーブルから空文字列を読み込んでいる | 呼び出し前に null チェックを行い、設定テーブルの完全な `Assets/...` パスを使用する |
| 非同期 `Task` が `OperationCanceledException` をスローする、または戻ってこない | 同じリソース名が既に `m_LoadingSceneAssetNames` に存在し、重複した読み込みが無視されている | 先に `UnloadScene` を呼び出すか、前回の完了を待って、同時実行による重複読み込みを避ける |
| エディタでは正常だが、パッケージ化後にシーンが見つからない | そのシーンが YooAsset リソースパッケージに含まれていない、またはパッケージ名と読み込みパスが一致していない | YooAsset コレクターにシーンファイルを追加し、リソースパッケージを再ビルドする |

## 修正手順

### 1. リソース名が空でないこと、リストと一致していることを確認する

`LoadScene` は内部で `sceneAssetName` を YooAsset シーン検索の key として使用するため、文字列は YooAsset コレクターが生成するアセットパスと完全に一致する必要があります(通常は `Assets/Scenes/xxx.unity`)。

```csharp
// 推奨：呼び出し前に検証する
if (string.IsNullOrWhiteSpace(sceneAssetName))
{
    GameFrameworkLog.Error("[Scene] sceneAssetName を空にすることはできません");
    return;
}
var handle = await GameEntry.Scene.LoadScene(sceneAssetName,
    UnityEngine.SceneManagement.LoadSceneMode.Single);
```

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L337-L348) では 4 つの `LoadScene` オーバーロードが公開されており、シグネチャはそれぞれ `(string)`、`(string, LoadSceneMode)`、`(string, object)`、`(string, LoadSceneMode, object)` で、どのオーバーロードでも有効な `sceneAssetName` を渡す必要があります。

### 2. 失敗イベントを監視して実際のリソース名を特定する

`LoadSceneFailure` イベントを登録すると、イベントパラメータから実行時に実際に読み込もうとした `SceneAssetName` を取得できます:

```csharp
GameEntry.Scene.LoadSceneFailure += (sender, e) =>
{
    Debug.LogError($"シーン読み込み失敗: {e.SceneAssetName}, エラー情報: {e.ErrorMessage}");
};
```

イベントソースは [LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs) にあります。ログに出力された `SceneAssetName` を YooAsset リソースリスト(`AssetBundle` / `AssetPackage` リスト)と照合すれば、通常はスペルや大文字小文字のエラーをすぐに特定できます。

### 3. YooAsset がそのシーンを収集してビルド済みであることを確認する

シーンが読み込み可能になるには、次の 2 つの条件を満たす必要があります:

1. YooAsset コレクタルールにこの `.unity` ファイルを含めること;
2. YooAsset のビルド処理(パッケージ/ローカルビルド)を再実行し、実行モード(Run Mode)で最新の生成されたリソースパッケージを使用すること。

Unity エディタでのみ読み込めて、パッケージ化後に失敗する場合は、基本的にこの手順が実行されていません。

### 4. 同じリソース名の同時読み込みを避ける

`GameSceneManager` は内部で `m_LoadingSceneAssetNames` を使用して読み込み中のリソースを追跡しており、同じ `sceneAssetName` で `LoadScene` を繰り返すと新しい `Task` が取得できず、「無効」と見えます。解決方法は、読み込みロジックごとにリソース名を排他的にするか、前回の `LoadScene` が返した `Task` の完了を待ってから次回を開始することです。

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L371) の完全な実装は 4 パラメータのオーバーロードにあり、`SceneHandle` と `UserData` を `m_LoadingSceneAssetNames` に格納し、成功または失敗のコールバックまで削除しないことが確認できます。

## 検証

正常に読み込めるシーンで対照実験を行います:

1. 確実に存在するシーン(例: `Assets/Scenes/Init.unity`)で `LoadScene` を呼び出し、`LoadSceneSuccess` イベントがトリガーされることを確認する;
2. `sceneAssetName` を意図的に存在しない文字列に変更し、`LoadSceneFailure` がトリガーされ、ログに実際に試行されたリソース名が出力されることを確認する;
3. 存在しない文字列を正しいパスに戻して再度 `LoadScene` を呼び出し、成功することを確認する。

手順 1 と 3 が成功し、中間の手順の失敗イベントが预期通りトリガーされる場合、「シーンリソース名が無効」なのは文字列/パスの問題であり、フレームワーク側の API 呼び出し方法の問題ではないと特定できます。
