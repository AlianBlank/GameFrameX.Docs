# HTTP 共通パラメータの設定方法

起動フロー内のすべての HTTP リクエストに統一された共通パラメータ(チャネル、言語、デバイス識別子など)を注入します。`IStartupHttpParamsProvider` を実装してフローコンテキストに登録するだけで有効になります。

## 前提条件

- プロジェクトに `GameFrameX.Startup` パッケージが導入済みであり、起動フロー内で `IFsm<IProcedureManager>` にアクセスできること。
- 起動オプション `StartupOptions` の各フィールドの意味(パッケージ名、チャネル、サブチャネルなど)を理解していること。

## 操作手順

1. **パラメータ保持クラスの実装(省略可能)**

   デフォルトのフィールドをそのまま再利用するだけであれば、`StartupHttpParams` を直接使用できます。新しいフィールドを追加する必要がある場合は、新しいクラスを派生させ、`IStartupHttpParams.ToJson()` と `ToDictionary()` を実装します。

   ```csharp
   using GameFrameX.Startup.Runtime;
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MyStartupHttpParams : StartupHttpParams
   {
       public string ServerId = string.Empty;

       public override string ToJson()
       {
           ServerId = ServerId ?? string.Empty;
           return Utility.Json.ToJson(this);
       }

       public override Dictionary<string, object> ToDictionary()
       {
           var dict = base.ToDictionary();
           dict["ServerId"] = ServerId ?? string.Empty;
           return dict;
       }
   }
   ```

   Source: [Runtime/Http/StartupHttpParams.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L19-L151)

2. **`IStartupHttpParamsProvider` の実装**

   `Create` メソッド内で、`StartupOptions`(および必要なランタイムコンテキスト)をパラメータオブジェクトにマッピングします。

   ```csharp
   using GameFrameX.Startup.Runtime;

   public class MyStartupHttpParamsProvider : DefaultStartupHttpParamsProvider
   {
       public override IStartupHttpParams Create(StartupOptions options)
       {
           var p = (MyStartupHttpParams)base.Create(options);
           p.ServerId = "cn-east-1";
           p.AppVersion = Application.version;
           p.Platform = Application.platform.ToString();
           p.DeviceUniqueIdentifier = SystemInfo.deviceUniqueIdentifier;
           return p;
       }
   }
   ```

   Source: [Runtime/Http/DefaultStartupHttpParamsProvider.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/DefaultStartupHttpParamsProvider.cs#L9-L23)

3. **起動フローへの登録**

   `GameFrameX.Startup` のフローマネージャを作成した後、プロバイダのインスタンスをブラックボードキー `StartupHttpParamsProvider`(型 `VarObject`)に書き込みます。フロー内部では `StartupProcedureUtility.GetHttpParamsProvider` を通じて読み取られ、未登録の場合は自動的に `DefaultStartupHttpParamsProvider` にフォールバックします。

   ```csharp
   var provider = new MyStartupHttpParamsProvider();
   var providerBox = VarObject.Create(provider);
   procedureOwner.SetData(BlackBoardKeys.StartupHttpParamsProvider, providerBox);
   ```

   Source: [Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L71-L76)

4. **HTTP リクエストで共通パラメータを取得**

   `GetHttpParams(procedureOwner)` を使って現在アクティブなパラメータインスタンスを取得し、`ToJson()` または `ToDictionary()` を呼び出して HTTP クライアント/Body に注入します。

   ```csharp
   var httpParams = StartupProcedureUtility.GetHttpParams(procedureOwner);
   var dict = httpParams.ToDictionary();
   // dict を POST フォームまたは JSON ボディにマージする
   ```

   Source: [Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L78-L99)

## 共通パラメータのフィールド早見表

| フィールド | 型 | ソース | 説明 |
|------|------|------|------|
| `PackageName` | string | `StartupOptions.PackageName` | アプリのパッケージ名 |
| `Channel` | string | `StartupOptions.Channel` | メインチャネル |
| `SubChannel` | string | `StartupOptions.SubChannel` | サブチャネル |
| `AppVersion` | string | 通常は `Application.version` から取得 | アプリのバージョン |

| `DeviceUniqueIdentifier` | string | 通常は `SystemInfo.deviceUniqueIdentifier` から取得 | デバイスの一意識別子 |

| `UserLanguage` | string | 手動設定 | ユーザー言語 |

## よくあるバリエーション

- **完全にカスタムのフィールドセット**:`StartupHttpParams` を継承せず、`IStartupHttpParams` インターフェースを直接実装し、`ToJson()` / `ToDictionary()` で独自のフィールドを返します。
- **ランタイムでのプラットフォーム別分岐**:`Provider.Create` 内で `Application.platform` に応じて異なるパラメータオブジェクトを返します(例：コンソール機のみ `ConsoleId` を追加)。
- **パラメータの動的更新**：特定のフィールド(サーバーリージョンなど)が途中で変わる必要がある場合は、パラメータオブジェクトを再構築して `SetData(BlackBoardKeys.StartupHttpParamsProvider, ...)` で上書きするだけです。

## よくあるエラー

- **ブラックボードへの登録忘れ**:`GetHttpParamsProvider` は未登録の場合にデフォルトのプロバイダを返すため、業務エラーは発生しませんが、カスタムフィールドがすべて失われます。登録前に、`SetData` がパラメータを最初に使用するフローよりも前に実行されていることを確認してください。
- **`options` が null の場合**:`StartupHttpParams.FromOptions` は `null` に対して `ArgumentNullException` をスローします。カスタム Provider では先に null チェックを行うか、`FromOptions` を呼び出す前に `StartupOptions` が確実に設定済みであることを保証してください。
- **派生クラスでの `ToDictionary` 実装漏れ**:`ToJson` のみをオーバーライドして `ToDictionary` をオーバーライドしないと、追加したフィールドが辞書形式のリクエストボディに含まれず、サーバー側で受け取れない可能性があります。両方を必ず同時に実装してください。
- **フィールド名がバックエンドの規約と不一致**:`ToDictionary` のキー(例:`"Channel"`)はバックエンドへ送信されるフィールド名であり、名前を変更した場合はバックエンド側の契約との同期が必要です。

## 背景(省略可能)

起動フレームワークは HTTP リクエストを直接発行するのではなく、「共通パラメータをどのように生成するか」を `IStartupHttpParamsProvider` として抽象化し、「パラメータをどのように消費するか」を上位の HTTP モジュールに委ねています。フレームワークはフロー内で `IStartupHttpParams` インスタンスを取得できることのみを保証し、それを Header、Query、Body、Form のどこに入れるかは呼び出し側が決定します。この設計により、HTTP 実装(GameFrameX.Network、BestHTTP、UnityWebRequest など)を自由に置き換えられる一方で、共通パラメータは常に一貫性を保ちます。
