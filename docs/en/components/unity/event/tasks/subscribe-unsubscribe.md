# How to Subscribe to and Unsubscribe from Events

Subscribe to events via the `EventComponent` in the scene (menu `GameFrameX/Event`): call `CheckSubscribe(id, handler)` to subscribe, and call `Unsubscribe(id, handler)` or `CheckUnsubscribe(id, handler)` to unsubscribe. The handler signature is `EventHandler<GameEventArgs>`, and the event ID `id` is a `string`.

## Prerequisites

- A GameFrameX entry exists in the scene and the `EventComponent` is attached (`[AddComponentMenu("GameFrameX/Event")]`).
- If custom event arguments are needed, prepare an argument class that inherits from `GameEventArgs`; for parameterless events, you can directly use a `string` event ID.

## Subscription and Unsubscription APIs

| Method | Actual Signature | Behavior |
|------|----------|------|
| `EventComponent.CheckSubscribe` | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | Subscribes only if not already subscribed; safe to call repeatedly |
| `EventComponent.Unsubscribe` | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | Unsubscribes (directly forwards to the manager) |
| `EventComponent.CheckUnsubscribe` | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | Does nothing if the handler does not exist |
| `EventComponent.Check` | `bool Check(string id, EventHandler<GameEventArgs> handler)` | Checks whether the handler exists |
| `EventComponent.Count` | `int Count(string id)` | The number of handlers under this event ID |
| `IEventManager.Subscribe` | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | Native subscription at the manager layer; no deduplication |

The methods on the component are all forwarded to `IEventManager`; the actual implementation of `CheckSubscribe` is "first `Check`, then `Subscribe`":

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

## Steps

1. Keep a reference to `EventComponent` in your script (via a serialized reference in the Inspector or by finding the component in the scene). The component automatically acquires the `IEventManager` module in `Awake`:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

2. Write the event handler; its signature must be `void (object sender, GameEventArgs e)`, i.e., `EventHandler<GameEventArgs>`. Custom argument classes directly inherit from `GameEventArgs` (itself an empty abstract base class inheriting from `BaseEventArgs`):

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class GameEventArgs : BaseEventArgs
{
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

3. Subscribe to the event at initialization time (e.g., `OnEnable`); using `CheckSubscribe` is recommended to avoid duplicate subscriptions: `m_EventComponent.CheckSubscribe("Player.HealthChanged", OnHealthChanged);`.
4. Unsubscribe at destruction/disable time (e.g., `OnDisable`/`OnDestroy`): `m_EventComponent.CheckUnsubscribe("Player.HealthChanged", OnHealthChanged);`. The corresponding implementation:

```csharp
public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.Unsubscribe(id, handler);
}

public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L118-L131)

5. Inside the handler, cast `e` to your custom argument type as needed to read the data. After unsubscribing, you can verify the subscription has been removed by checking that `m_EventComponent.Check(id, handler)` returns `false` and `Count(id)` returns `0`.

## Common Variants

- **Repeated initialization scenarios**: When entering the same logic multiple times, use `CheckSubscribe` / `CheckUnsubscribe` directly; both check first and then execute internally, so repeated calls will not throw errors. The implementation of `CheckUnsubscribe` does nothing at the manager layer if the `handler` does not exist:

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (m_EventPool.Check(id, handler))
    {
        m_EventPool.Unsubscribe(id, handler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L140-L146)

- **Parameterless events**: When you only need an event ID and no data to be carried, you can use `Fire(object sender, string eventId)` to fire directly with a string. The component automatically creates an `EmptyEventArgs` internally:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

`EmptyEventArgs.Create` acquires the object from the reference pool and sets the event ID:

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

- **Fallback handling**: Call `SetDefaultHandler(EventHandler<GameEventArgs> handler)` to set the default event handler, which is used to receive events that have no subscribers.

## Common Errors

| Error | Cause | Fix |
|------|------|------|
| Component initialization fails, with the log output `Event manager is invalid.` | The scene lacks an available `IEventManager` module / the GameFrameX entry was not initialized | Ensure a GameFrameX entry exists in the scene and the `EventComponent` is attached |
| The same handler is triggered multiple times | `IEventManager.Subscribe` was used (no deduplication) and called repeatedly | Use `EventComponent.CheckSubscribe` instead |
| An error occurs when unsubscribing | An unsubscribed `handler` was passed, or the `id` does not match | Use `EventComponent.CheckUnsubscribe` instead |
| Handler signature mismatch | `EventHandler<GameEventArgs>` (`void (object, GameEventArgs)`) was not used | Write the handler according to this signature |
| Event firing timing does not match expectations | `Fire` is thread-safe but dispatches events on the next frame; `FireNow` dispatches immediately but is not thread-safe | Choose `Fire` / `FireNow` as needed |

## Background

`EventComponent` is a facade component on the Unity scene; all subscription APIs are forwarded to `IEventManager` (`EventManager`), which in turn delegates to its internal `m_EventPool` for actual event pool maintenance. Therefore, callers only need to deal with the `Subscribe`/`Unsubscribe`/`Check` semantics of `EventComponent` without having to worry about the underlying event pool.
