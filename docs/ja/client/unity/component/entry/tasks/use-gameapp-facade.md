# GameApp を使用して各サブシステムを呼び出す方法(ファサード層ガイド)

`GameApp` は GameFrameX が提供する静的ファサードクラス(Facade)であり、各コンポーネントに分散しているサブシステム(Asset、Config、Event、Fsm、UI、Entity、Localization など)を静的プロパティとして統一的に集約します。ビジネスコードは `GameEntry.GetComponent<T>()` を通じて繰り返し検索する必要がなく、直接 `GameApp.Asset.xxx` で呼び出せます。

## 前提条件

- GameFrameX の `GameEntry` がインストールされ、初期化済みであること。フレームワークは起動時に `Enable` リストに従って各 `Component` を作成します。
- 使用するサブシステムに対応する `ENABLE_GAME_FRAME_X_*` マクロが有効になっていることを確認してください(各 `GameApp.*.cs` ファイルはマクロで partial ブロック全体を囲んでいます)。有効でない場合、プロパティはコンパイルされません。
- ビジネスコードは `Component` への参照を保持せず、統一的に `GameApp.xxx` を通じてアクセスしてください。

## 操作手順

### 1. 静的プロパティを通じてサブシステムを取得する

各 `GameApp.*.cs` ファイルは同一のパターンに従っています:内部に静的プライベートフィールドを保持し、読み取り専用の静的プロパティを公開し、初回アクセス時に `GameEntry` から対応する `Component` を取得してキャッシュします。

```csharp
// 基本コンポーネントを取得
var baseComp = GameApp.Base;

// アセットコンポーネントを取得(ENABLE_GAME_FRAME_X_ASSET マクロの有効化が必要)
var asset = GameApp.Asset;

// コンフィグコンポーネントを取得(ENABLE_GAME_FRAME_X_CONFIG マクロの有効化が必要)
var cfg = GameApp.Config;

// イベントコンポーネントを取得(ENABLE_GAME_FRAME_X_EVENT マクロの有効化が必要)
var evt = GameApp.Event;
```

### 2. ビジネスコード内でサブシステムのメソッドを呼び出す

プロパティを取得した後、対応する `Component` のメソッドを直接呼び出すだけです。以下の例は、アセットのロード、設定の読み取り、イベントの購読をすべて `GameApp` 経由で行うデモです:

```csharp
// アセットをロード
GameApp.Asset.LoadAsset<GameObject>("Assets/Prefabs/Hero.prefab", prefab =>
{
    // prefab を使用 ...
});

// 設定を読み取る
var heroHp = GameApp.Config.GetInt("Hero_HP", 100);

// イベントを購読
GameApp.Event.Subscribe("OnPlayerLevelUp", payload =>
{
    // レベルアップイベントを処理
});
```

> 上記の API 名(LoadAsset / GetInt / Subscribe)は各コンポーネントの一般的な公開メソッドからのものです。具体的なシグネチャは [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs)、[GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs)、[GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) に対応する `Component` の実装を基準としてください。

### 3. マクロスイッチで不要なサブシステムを除外する

`GameApp` の各サブシステムは `ENABLE_GAME_FRAME_X_<NAME>` コンパイルマクロで囲まれています。プロジェクトで不要なサブシステムがある場合、対応するマクロを無効にすると、そのプロパティはコンパイルされず、パッケージサイズと依存関係を効果的に削減できます。

| マクロ(例) | 影響を受けるプロパティ | ファイル |
|---|---|---|
| `ENABLE_GAME_FRAME_X_ASSET` | `GameApp.Asset` | [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs) |
| `ENABLE_GAME_FRAME_X_CONFIG` | `GameApp.Config` | [GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs) |
| `ENABLE_GAME_FRAME_X_EVENT` | `GameApp.Event` | [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) |

すべてのサブシステムは同一のマクロ命名規則を採用しています。具体的なマクロ名は各 [Runtime/GameApp.*.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs) ファイル先頭の `#if` ディレクティブを参照してください。

## 一般的なバリエーション

### その他の公開済みサブシステムを使用する

リポジトリの `Runtime/` ディレクトリ下の各 `GameApp.*.cs` ファイルはそれぞれ 1 つのサブシステムに対応しています。よく使用されるエントリは以下の通りです:

- `GameApp.AdJust`、`GameApp.Advertisement` —— プロモーションと広告。
- `GameApp.AppleLogin`、`GameApp.FaceBookLogin`、`GameApp.GoogleLogin` —— サードパーティログイン。
- `GameApp.AppsFlyer`、`GameApp.GameAnalytics` —— データトラッキング。
- `GameApp.Asset` —— アセットロード。
- `GameApp.Config` —— 設定読み取り。
- `GameApp.Coroutine` —— コルーチン。
- `GameApp.Download` —— ダウンロード。
- `GameApp.Entity` —— エンティティ。
- `GameApp.Event` —— イベント。
- `GameApp.FairyGUIPackage` —— FairyGUI リソースパッケージ。
- `GameApp.Fsm` —— ステートマシン。
- `GameApp.GlobalConfig` —— グローバル設定。
- `GameApp.GUI` —— UI。
- `GameApp.Guide` —— チュートリアル。
- `GameApp.Localization` —— ローカライズ。

呼び出し方法は同一です:マクロが有効になっていることを確認した後、`GameApp.<Name>` を使用するだけで対応する `Component` を取得できます。

## よくあるエラー

- **プロパティが見つからない / `GameApp` に `xxx` の定義が含まれないというコンパイルエラー**:ほとんどの場合、対応する `ENABLE_GAME_FRAME_X_*` マクロが有効になっていないか、対応する `GameApp.*.cs` がプロジェクトにコンパイルされていないことが原因です。まず `Scripting Define Symbols` または `asmdef` でマクロを有効にしてください。
- **`GameEntry` が起動していない状態でプロパティにアクセスする**:`GameApp` は `GameEntry.GetComponent<T>()` を通じてコンポーネントを取得するため、フレームワークの初期化が完了していない場合は `null` が取得され、その後の呼び出しで NullReferenceException がスローされます。`GameEntry` の起動完了後に `GameApp.xxx` へアクセスしてください。
- **手動で `Component` を `new` してファサード呼び出しの代わりにする**:`GameApp` の静的フィールドはキャッシュであり、`GameEntry.GetComponent<T>()` で取得したインスタンスとのみ一貫性を保ちます。自分で `new` したインスタンスはファサードから取得できないため、2 つの状態が同期しなくなります。
- **シーンをまたいで静的フィールドを保持する**:現在、`GameApp` のフィールドはプロセスレベルの静的キャッシュであり、設計上プロセスのライフサイクルに沿って使用されます。シーン切り替え時に手動でリセットしようとしないでください。

## 背景(オプション)

`GameApp` は複数の `partial class` で構成され(`Runtime/GameApp.*.cs` がそれぞれ 1 つのサブシステムプロパティを実装)、レイジーローディング + `GameEntry.GetComponent<T>()` の方式で統一的にコンポーネントインスタンスを取得します。シングルトンコンポーネントのグローバルアクセス能力を保持しつつ、ビジネス層に `GameEntry.GetComponent<T>()` のボイラープレートコードが散在するのを防ぎます。これはフレームワークにおける典型的な Facade パターンの応用です。

フレームワーク全体の起動フローと `GameEntry` の役割については、「概要」ページを参照してください。
