# ライフサイクルイベントを購読する方法

`IEntityManager` が公開する5つのイベント(`ShowEntitySuccess` / `ShowEntityFailure` / `ShowEntityUpdate` / `ShowEntityDependencyAsset` / `HideEntityComplete`)を使用すると、エンティティの表示・更新・非表示の各段階でコールバックを受け取ることができ、エンティティ内部のコードを変更する必要はありません。

## 前提条件

- プロジェクト内で `IEntityManager` のインスタンスを取得済みであること(通常は `GameEntry.GetComponent<EntityComponent>().EntityManager` で取得します)。
- 名前空間 `GameFrameX.Entity.Runtime`(イベント引数)と `System`(標準の `EventHandler<T>`)を参照していること。

## 購読可能なイベント一覧

| イベント | イベント引数 | 発生タイミング |
|------|---------|---------|
| `ShowEntitySuccess` | `ShowEntitySuccessEventArgs` | エンティティのロードと表示に成功 |
| `ShowEntityFailure` | `ShowEntityFailureEventArgs` | エンティティのロードまたは表示に失敗 |
| `ShowEntityUpdate` | `ShowEntityUpdateEventArgs` | エンティティ表示中の進捗更新 |
| `ShowEntityDependencyAsset` | `ShowEntityDependencyAssetEventArgs` | エンティティの依存リソースのロード開始 |
| `HideEntityComplete` | `HideEntityCompleteEventArgs` | エンティティの非表示完了 |

出典:[IEntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/IEntityManager.cs#L55-L80)

## 操作手順

1. 監視が必要なクラスで `IEntityManager` の参照を保持し、`+=` でイベントコールバックを登録します(各イベントのシグネチャは `EventHandler<TEventArgs>` のような形で、第2引数 `e` が対応するイベント引数です)。

```csharp
using System;
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

public class MyListener
{
    private readonly IEntityManager m_EntityManager;

    public MyListener(IEntityManager entityManager)
    {
        m_EntityManager = entityManager;
        // ライフサイクルイベントを購読
        m_EntityManager.ShowEntitySuccess    += OnShowEntitySuccess;
        m_EntityManager.ShowEntityFailure    += OnShowEntityFailure;
        m_EntityManager.ShowEntityUpdate     += OnShowEntityUpdate;
        m_EntityManager.ShowEntityDependencyAsset += OnShowEntityDependencyAsset;
        m_EntityManager.HideEntityComplete   += OnHideEntityComplete;
    }

    private void OnShowEntitySuccess(object sender, ShowEntitySuccessEventArgs e)
    {
        // e.Entity / e.Duration / e.UserData / e.EntityLogicType
        Log.Info($"实体 {e.Entity.Id} 显示成功,耗时 {e.Duration:F2}s");
    }

    private void OnShowEntityFailure(object sender, ShowEntityFailureEventArgs e)
    {
        Log.Warning($"实体显示失败: {e.EntityId}");
    }

    private void OnShowEntityUpdate(object sender, ShowEntityUpdateEventArgs e)
    {
        // e.Progress / e.EntityId
    }

    private void OnShowEntityDependencyAsset(object sender, ShowEntityDependencyAssetEventArgs e)
    {
        // e.EntityId / e.DependencyAssetName / e.LoadedCount / e.TotalCount
    }

    private void OnHideEntityComplete(object sender, HideEntityCompleteEventArgs e)
    {
        // e.EntityId / e.EntityAssetName / e.EntityGroup / e.UserData
    }
}
```

出典:[EntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.cs#L105-L150)

2. リスナーのライフサイクル終了時(シーン切り替えや `OnDestroy` など)には、`-=` を使って購読を解除し、メモリリークや破棄済みオブジェクトへの不要なコールバックを回避します。

```csharp
public void Dispose()
{
    m_EntityManager.ShowEntitySuccess    -= OnShowEntitySuccess;
    m_EntityManager.ShowEntityFailure    -= OnShowEntityFailure;
    m_EntityManager.ShowEntityUpdate     -= OnShowEntityUpdate;
    m_EntityManager.ShowEntityDependencyAsset -= OnShowEntityDependencyAsset;
    m_EntityManager.HideEntityComplete   -= OnHideEntityComplete;
}
```

3. `EntityComponent` を通じてマネージャーを取得し、リスナーに渡して使用します。

```csharp
var entityManager = GameEntry.GetComponent<EntityComponent>().EntityManager;
var listener = new MyListener(entityManager);
```

## よくあるバリエーション

- **単一のイベントのみを監視したい場合**：関心のあるイベントだけを `+=` します。例えば失敗のみを知りたい場合は `entityManager.ShowEntityFailure += OnFailed;`。
- **エンティティ Id でフィルタリングする場合**：コールバック内で `e.EntityId`(または `e.Entity?.Id`)に基づいて、この通知を処理するかどうかを判断します。
- **ロード段階だけで進捗をフィードバックしたい場合**:`ShowEntityUpdate` と `ShowEntityDependencyAsset` のみを購読し、UI 上に `e.Progress` や `e.LoadedCount / e.TotalCount` を表示します。

## よくある間違い

- **購読を解除せずにリスナーを破棄する**:`EntityManager` は長いライフサイクルを持つモジュールであり、コールバックデリゲートを保持し続けるため、オブジェクトが GC されなくなります。`OnDestroy` / `Dispose` 内で対になる `-=` を必ず記述してください。
- **コールバック内で未捕捉の例外をスローする**:イベントは同期的に配信されるため、例外はコールスタックを遡って伝播し、以降の処理を中断します。コールバック内で `try / catch` を行ってください。
- **`EventId` と C# の `event` の混同**:`ShowEntitySuccessEventArgs.EventId` はグローバルイベントバス(`GameFrameX.Event.Runtime`)用です。ここで説明しているのは `IEntityManager` 上の `event EventHandler<T>` の購読であり、両者は同じ仕組みではありません。

## 背景(任意)

`EntityManager` は内部で標準 .NET の `event` フィールドとして上記の5つのコールバックを公開しており、トリガーポイントは各 `Show`/`Hide` フローの重要なノードにあります。`EventArgs` は `ReferencePool` を通じて取得・回収されるため、これらの引数オブジェクトを長期にわたって保持しないでください。イベント配信後、それらはプールに返却されます。
