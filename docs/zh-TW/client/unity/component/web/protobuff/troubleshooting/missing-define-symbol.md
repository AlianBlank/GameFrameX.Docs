# Post 方法不存在或編譯報錯怎麼辦(巨集未定義)

當你呼叫 `WebProtoBuffComponent.Post<T>()` 時提示方法不存在，或者編譯器報 `GameFrameX.Network.Runtime.MessageObject` 類型找不到，幾乎都是同一個原因：專案裡沒有安裝 `com.gameframex.unity.network` 套件，導致 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 巨集沒有被自動定義，`Post` 相關程式碼被條件編譯整體裁剪掉了。

## 快速診斷

| 症狀(報錯原文/現象) | 原因 | 修復 |
|------|------|------|
| `'WebProtoBuffComponent' does not contain a definition for 'Post'`(CS1061) | `Post<T>` 整個方法被 `#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 包裹，巨集未定義時方法不存在 | 安裝 `com.gameframex.unity.network` 套件，讓巨集自動生效，見下方[修復步驟](#1-確認網路套件已安裝) |
| `The type or namespace name 'MessageObject' could not be found` | `MessageObject` / `IResponseMessage` 定義在 `GameFrameX.Network.Runtime` 組件中，該套件缺失時類型不存在 | 安裝 `com.gameframex.unity.network` 套件 |
| 編輯器左下角提示組件 `GameFrameX.Web.ProtoBuff.Runtime` 編譯失敗 | asmdef 引用了 `GameFrameX.Network.Runtime`,網路套件未安裝時引用解析失敗 | 安裝 `com.gameframex.unity.network` 套件 |
| 已安裝網路套件但 `Post` 仍不可用 | asmdef 的 `versionDefines` 未被 Unity 重新整理，巨集未寫入 | 在 Player Settings 手動新增巨集或重新啟動 Unity,見[步驟 3](#3-手動定義巨集作為後備方案) |

巨集的裁剪邏輯在原始碼中可以看到——`Post` 方法整體被條件編譯包裹：

```csharp
#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
        /// <summary>
        /// 傳送Post請求，用於傳送和接收Protocol Buffer訊息。
        /// 此方法僅在啟用ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK巨集定義時可用。
        /// </summary>
        public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
        {
            return m_WebProtoBuffManager.Post<T>(url, message);
        }
#endif
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

介面 `IWebProtoBuffManager` 中的 `Post` 也是同樣的寫法([IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L11-L24)),而 `Timeout` 屬性始終可用、不受巨集影響。

## 修復步驟

### 1. 確認網路套件已安裝

巨集不是手動設定的，而是由執行階段組件定義檔案中的 `versionDefines` 自動控制：只要專案中存在 `com.gameframex.unity.network` 套件，Unity 就會自動定義 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`。

```json
  "versionDefines": [
    {
      "name": "com.gameframex.unity.network",
      "expression": "",
      "define": "ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK"
    }
  ]
```

Source: [GameFrameX.Web.ProtoBuff.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L17-L23)

檢查與安裝方式：

1. 開啟 Unity 選單 `Window → Package Manager`,切換到 `Packages: In Project` 檢視；
2. 尋找 `com.gameframex.unity.network`(顯示名稱通常為 GameFrameX Network);
3. 若不存在，切換到 `+ → Add package from git URL...`,輸入網路套件的儲存庫位址以新增；
4. 相依的組件還包括 `GameFrameX.Runtime`、`GameFrameX.Web.Runtime`、`ProtoBuffer.Runtime`(見 [asmdef 引用清單](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L4-L9)),正常情況下它們會作為相依項被一併拉取。

### 2. 讓 Unity 重新整理腳本定義

套件安裝完成後 Unity 會自動重新整理 `versionDefines` 並觸發重新編譯。如果沒有：

1. 選單 `Assets → Reimport All`,或刪除專案根目錄下的 `Library/ScriptAssemblies` 資料夾後重新開啟 Unity;
2. 等待編譯完成，確認 Console 無報錯。

### 3. 手動定義巨集作為後備方案

如果網路套件已安裝但巨集仍未生效(例如舊版本 Unity 對 `versionDefines` 支援異常)：

1. 開啟 `Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`;
2. 新增 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`(多個巨集用分號分隔)；
3. 按下 Enter 儲存，等待重新編譯。

注意：手動定義巨集只是後備方案。網路套件真正缺失時，`Post` 內部引用的 `MessageObject`、`IResponseMessage` 類型依舊不存在，仍會編譯失敗——所以請優先完成步驟 1。

## 驗證

1. 在任意腳本中輸入 `webProtoBuffComponent.Post<`,IDE 能補全出 `Post<T>(string url, MessageObject message)` 多載；
2. `Project Settings → Player → Script Compilation` 中能看到(或可手動核對)`ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 已生效；
3. 場景中掛有 `WebProtoBuff Component` 的物件 Inspector 正常顯示，Console 無 `Web manager is invalid.` 致命日誌(該日誌表示元件未正確初始化，與巨集問題不同)。

## 背景

`Post` 相依於網路層的 protobuf 訊息類型，而網路套件是可選相依項，所以本元件用 asmdef 的 `versionDefines` 實作「裝了網路套件才暴露 Post 方法」的按需裁剪：`expression` 為空表示該套件任意版本都滿足條件。這也是為什麼報錯點經常出現在元件類別上而不是介面上——兩處的 `#if` 是同時存在的。
