# How to Customize JSON Key Names with JsonProperty

The `JsonProperty` attribute can map a C# field or property to any JSON key name, solving issues of inconsistent naming styles (underscores, camelCase, prefixes, etc.) and alignment with third-party protocol fields.

## Prerequisites

- The `GameFrameX.LitJson.Runtime` namespace has been imported.
- The target member must be an **instance** field or property, and must be visible for JSON read/write (by default, non-public fields will not be serialized; if you need to enable them, please use the accompanying options, see "How to Ignore Fields with JsonIgnore").

## Steps

1. Add `[JsonProperty("custom key name")]` to the field or property.
2. During serialization, `JsonMapper.ToJson` will automatically output using the key name specified by the attribute.
3. During deserialization, `JsonMapper.ToObject<T>` will also match the input JSON by that key name.

Example code:

```csharp
using GameFrameX.LitJSON.Runtime;

public class Player
{
    [JsonProperty("player_id")]
    public int Id;

    [JsonProperty("nick_name")]
    public string NickName;

    [JsonProperty("vip_level")]
    public int VipLevel = 1;
}

var p = new Player { Id = 1001, NickName = "Alice", VipLevel = 3 };
string json = JsonMapper.ToJson(p);
// Output:{"player_id":1001,"nick_name":"Alice","vip_level":3}

var back = JsonMapper.ToObject<Player>(json);
```

The attribute definition can be found in the source file, and it only supports a constructor with a single `propertyName` parameter:

```csharp
[AttributeUsage(AttributeTargets.Field | AttributeTargets.Property, AllowMultiple = false)]
public sealed class JsonPropertyAttribute : Attribute
{
    public JsonPropertyAttribute(string propertyName)
    {
        PropertyName = propertyName;
    }

    public string PropertyName { get; private set; }
}
```

## Common Variants

### Lowercase Key Names with PascalCase Field Names

```csharp
public class Account
{
    [JsonProperty("uid")]
    public long UserId;

    [JsonProperty("createdAt")]
    public DateTime CreatedAt;
}
```

### Case-Insensitive Fallback During Deserialization

If the key name in the JSON text differs from the key name declared in the attribute only by case (for example, the JSON provides `Player_Id`, while the attribute declares `player_id`), deserialization will perform fallback matching using `OrdinalIgnoreCase`, requiring no additional configuration.

The fallback logic is in `JsonMapper`'s `TryGetProperty`:

```csharp
foreach (var pair in metadata.Properties)
{
    if (string.Equals(pair.Key, name, StringComparison.OrdinalIgnoreCase))
    {
        prop = pair.Value;
        return true;
    }
}
```

## Common Errors

- **Attribute without parameters or `propertyName` is empty**: During serialization/deserialization, it will fall back to the C# member name itself. When checking, you can see in the implementation of `GetJsonPropertyName` that an empty string goes through the `info.Name` branch.
- **Reusing the attribute**: `AttributeUsage` has restricted `AllowMultiple = false`, so applying it repeatedly on the same field will only take the first one.
- **Applying to non-Field/Property targets** (such as classes, methods) will fail to compile or be ignored — `AttributeUsage` only allows `Field | Property`.
- **Missing key when deserialization field is null**: If the key is not present in the JSON at all, and the member is a value type, you will get the default value; reference types remain `null`. This is a general framework behavior and is not within the control of `JsonProperty`.

## Background (Optional)

`JsonMapper` internally uses reflection to read `JsonPropertyAttribute`, determining the property name when writing JSON and the key for building the deserialization dictionary. See `GetJsonPropertyName` and `TryGetProperty` for the reading process. This mechanism, combined with `JsonIgnore`, can achieve complete field-level control.
