# インストールと依存関係解析の失敗時の対処方法

Unity で Package Manager または `manifest.json` を介して `com.gameframex.unity.coroutine` を導入する際に、依存関係エラー、バージョンの競合、パッケージが見つからないなどの問題が発生した場合は、本ページの診断表に従って修復してください。

## クイック診断

| 症状 | 原因 | 修復方法 |
|------|------|------|
| `Package 'com.gameframex.unity.coroutine' could not be found` または対応するバージョンが見つからない | `manifest.json` に `scopedRegistries` が設定されていないため、Unity はデフォルトで `com.gameframex.*` で始まるパッケージを npm レジストリでのみ検索する | `manifest.json` の先頭に `scopedRegistries` を追加し GameFrameX ソースを指定する(後述の修復手順 1 を参照) |
| `Unable to resolve dependency 'com.gameframex.unity: 2.5.1'` というエラーが表示される | ランタイム依存関係 `com.gameframex.unity` が不足しているか、バージョンがインストール済みの他の GameFrameX パッケージと一致していない | まずパッケージが要求する `com.gameframex.unity` のバージョン(`package.json` の依存関係に記載)を単独でアップグレードまたはダウングレードする |
| Unity が `Requires Unity 2019.4 or higher` を報告する | 現在のプロジェクトの Unity バージョンがパッケージの最低要件を下回っている | Unity を 2019.4 以降にアップグレードするか、対応する旧バージョンのパッケージを使用する |
| パッケージはダウンロード済みだが `The type or namespace 'GameFrameX' could not be found` でコンパイルエラーが発生する | Unity のキャッシュが更新されていない、依存関係が実際に `Library/PackageCache` に書き込まれていない | `Library/PackageCache` と `Packages/packages-lock.json` を削除してから Unity を再起動する |
| Git URL でインストールするときに `Could not read Username for 'https://github.com'` が発生する | ネットワークが GitHub にアクセスできない、またはプライベートリポジトリの認証に失敗している | 代わりに UPM scoped registry 方式を使用するか、このリポジトリ用に SSH/HTTPS の認証情報を設定する |
| パッケージのインポートは成功したが `CoroutineComponent` で `[DisallowMultipleComponent]` の競合が発生する | 同じ GameObject に既に `CoroutineComponent` がアタッチされている | 重複する同じ種類のコンポーネントを削除し、1 つだけ残す |

## 修復手順

### 1. scopedRegistries の設定(GameFrameX 公式ソース)

プロジェクトルートディレクトリにある `Packages/manifest.json` を開き、`scopedRegistries` セクションが存在することを確認してください。以下のサンプルはリポジトリの README のインストール説明からのものです:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.coroutine": "1.0.3"
  }
}
```

出典: [README.zh-CN.md#快速开始](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L40-L77)

要点:
- `scopes` は必ず `com.gameframex` と記述してください。そうでないと `com.gameframex.*` パッケージはこのソースで解決されず、Unity はデフォルトの npm ソースにフォールバックし、「パッケージが見つからない」と直接報告されます。
- `url` は UPM レジストリアドレスであり、通常の Web ページではありません。お使いのネットワークがアクセスできない場合は、後述の「Git URL 代替案」を参照してください。

### 2. ランタイム依存関係 `com.gameframex.unity` の確認

`com.gameframex.unity.coroutine` は `com.gameframex.unity` に依存しており、リポジトリの [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L22-L24) で以下のように宣言されています:

```json
"dependencies": {
  "com.gameframex.unity": "2.5.1"
}
```

プロジェクト内ですでに古いバージョンの `com.gameframex.unity` が明示的に宣言されている場合、Unity は解決を拒否します。対応:
- `com.gameframex.unity` を `2.5.1` または互換性のある新しいバージョンにアップグレードする。または
- 明示的な宣言を削除し、`com.gameframex.unity.coroutine` に正しいバージョンを自動的に持たせる。

### 3. Unity バージョンは 2019.4 以上必須

`package.json` の `unity` フィールドは `2019.4` です:

```json
"version": "1.2.0",
"unity": "2019.4",
```

出典: [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L6-L7)

2019.4 未満のプロジェクトは Package Manager に直接「Requires Unity 2019.4 or higher」と表示されるため、まず Unity エディタをアップグレードする必要があります。

### 4. 必要に応じてキャッシュをクリアして再起動する

パッケージ明明示済みであるにもかかわらずコンパイルエラーが発生したり、名前空間が見つからない場合は、まず次の手順を実行してください:
1. Unity を閉じる。
2. プロジェクトディレクトリから `Library/PackageCache` フォルダを削除する。
3. `Packages/packages-lock.json` を削除する。
4. Unity を再度開き、`manifest.json` に基づいて再取得させる。

### 5. 代替インストール方法(GitHub にアクセスできない場合)

- `manifest.json` の `dependencies` に直接 Git URL を記述する:

```json
{
  "dependencies": {
    "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
  }
}
```

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L70-L75)

- または Unity の `Package Manager` → `Add package from git URL…` に `https://github.com/gameframex/com.gameframex.unity.coroutine.git` を貼り付ける。
- またはリポジトリをダウンロードしてプロジェクトの `Packages/` ディレクトリに直接配置する。

## 検証

修復後、以下のいずれかの方法で確認してください:

1. Unity Console を確認する:「could not be found / Unable to resolve dependency」といったエラーが発生しなくなる。
2. Inspector で `Add Component` から `Coroutine Component` を検索でき、GameObject に正常に追加できる。
3. 最小コードスニペットで名前空間が利用可能であることを確認する:

```csharp
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(yourEnumerator);
```

参考例の出典 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L82-L91)。
