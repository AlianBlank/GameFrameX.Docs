# LocalizationCode Language Code Quick Reference

This page collects all language code constants from the `LocalizationCode` static class in `Runtime/Localization/LocalizationCode.cs`. The code format is `[language code]_[country/region code]` (e.g., `zh_CN` for Simplified Chinese in mainland China), following the ISO 639-1 and ISO 3166-1 standards. All are `public const string` and can be referenced directly without writing strings by hand.

## Usage Example

All constants are under the namespace `GameFrameX.Localization.Runtime`, so you can reference them directly:

```csharp
using GameFrameX.Localization.Runtime;

// Reference constants directly to avoid errors from handwriting language codes
string simplifiedChinese = LocalizationCode.Chinese;                 // "zh_CN"
string traditionalChineseTW = LocalizationCode.ChineseTraditionalTW; // "zh_TW"
string english = LocalizationCode.English;                           // "en_US"
string japanese = LocalizationCode.Japanese;                         // "ja_JP"
```

## Easily Confused Points

| Case | Description |
|------|------|
| `Chinese` vs. `ChineseSimplified` | Both are `zh_CN`, aliases of each other; the source comment explicitly marks them as "equivalent to" |
| `Hebrew` vs. `HebrewIL` | Both are `he_IL`, aliases of each other |
| `Filipino` vs. `Tagalog` | Both are `tl_PH`, aliases of each other |
| `English` default value | Defaults to `en_US` (American English); for British English use `EnglishUK` (`en_GB`) |
| `Norwegian` | Defaults to Bokmål `nb_NO`; for Nynorsk use `NorwegianNN` (`nn_NO`) |
| Number of `Spanish` variants | Spanish has the most variants, 18 in total (including the `es_ES` default), distinguished by the `es_` prefix |
| `UzbekBE` naming | The constant is named `UzbekBE` but the source comment says "Uyghur language code"; its value is `uz_BE`; Uyghur also has its own `Uyghur` (`ug_CN`) |
| `Bengali` region | `Bengali` points to India's `bn_IN`; for Bangladesh use `BengaliBD` (`bn_BD`) |

## Background

`LocalizationCode` is a pure constant class (marked with `[Preserve]` to prevent code stripping) and contains no logic. All codes follow the `[language]_[region]` format and align with `LocalizationManager`'s language configuration and dictionary file naming — when setting a language or naming localization resource files, using these constants guarantees the strings are exactly the same as those used internally by the framework, avoiding language matching failures caused by handwritten typos.
