# 如何在类上使用特性映射参数与环境变量

通过在类的属性上添加 `Option`、`EnvironmentVariable`、`FlagOption` 等特性,可以让 `OptionsBuilder` 自动把命令行参数和环境变量绑定到强类型属性,无需手写解析代码。

## 前置条件

- 引入 `GameFrameX.Foundation.Options` 程序集。
- `using GameFrameX.Foundation.Options.Attributes;`(可选,只为使用简短名称)。
- 你的选项类必须具备无参构造函数(约束 `where TOptions : class, new()`)。

## 可用特性速览

| 特性 | 作用 | 关键属性 |
|------|------|----------|
| [`OptionAttribute`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/OptionAttribute.cs#L57-L134) | 标记属性为命令行选项 | `LongName`、`ShortName`(在参数转换器中)、`DefaultValue`、`Required`、`EnvironmentVariable`、`Sensitive` |
| [`EnvironmentVariableAttribute`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/EnvironmentVariableAttribute.cs#L55-L77) | 直接把属性绑定到指定环境变量 | `Name`(构造参数,环境变量名) |
| [`FlagOptionAttribute`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/FlagOptionAttribute.cs) | 标记布尔属性为开关,无需传值 | `LongName` |

## 操作步骤

### 1. 定义带特性的选项类

`Option` 的 `EnvironmentVariable` 属性直接声明该选项对应的环境变量名;`EnvironmentVariable` 特性则用于“只从环境变量读取、不暴露为命令行参数”的场景。

```csharp
using GameFrameX.Foundation.Options.Attributes;

public class MyOptions
{
    // 命令行选项 + 环境变量: --port 或 TEST_PORT
    [Option("port", DefaultValue = 8080, EnvironmentVariable = "TEST_PORT")]
    public int Port { get; set; }

    // 长名称 + 环境变量 + 默认值
    [Option(LongName = "host", EnvironmentVariable = "TEST_HOST", DefaultValue = "localhost")]
    public string Host { get; set; }

    // 布尔开关,无需传值
    [FlagOption(LongName = "verbose")]
    public bool Verbose { get; set; }

    // 必需项
    [Option(LongName = "api-key", Required = true)]
    public string ApiKey { get; set; }
}
```

Source: [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L12-L26)

### 2. 用 `OptionsBuilder` 一行构建

`OptionsBuilder` 提供多种静态入口,从命令行、环境变量、两者混合或仅默认值构建对象。

```csharp
using GameFrameX.Foundation.Options;

// 仅命令行参数
var opts1 = OptionsBuilder.Create<MyOptions>(args);

// 命令行 + 环境变量混合(默认行为)
var opts2 = OptionsBuilder.Create<MyOptions>(
    args,
    boolFormat: BoolArgumentFormat.TrueFalse,
    ensurePrefixedKeys: true,
    useEnvironmentVariables: true);

// 仅环境变量
var opts3 = OptionsBuilder.CreateFromEnvironmentOnly<MyOptions>();

// 仅命令行,忽略环境变量
var opts4 = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);

// 仅默认值(适合测试)
var opts5 = OptionsBuilder.CreateDefault<MyOptions>();
```

Source: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L122)

### 3. 用 `EnvironmentVariable` 特性绑定纯环境变量属性

当某个属性只希望从环境变量读取、不希望出现在命令行帮助里时,用 `EnvironmentVariable` 特性更直接。

```csharp
public class MyOptions
{
    [EnvironmentVariable("DATABASE_URL")]
    public string DatabaseUrl { get; set; }

    [EnvironmentVariable("API_KEY")]
    public string ApiKey { get; set; }
}

var options = OptionsBuilder.CreateFromEnvironmentOnly<MyOptions>();
Console.WriteLine(options.DatabaseUrl);
```

Source: [EnvironmentVariableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/EnvironmentVariableAttribute.cs#L43-L54)

### 4. 验证必需项

`Build(skipValidation: false)` 会校验所有标了 `Required = true` 的属性是否已被赋值(通过命令行或环境变量)。

```csharp
// 没有提供 --api-key,这里会抛异常
var options = OptionsBuilder.Create<MyOptions>(new[] { "--port", "9090" });

// 跳过必需项检查,适用于配置默认值场景
var defaults = OptionsBuilder.CreateDefault<MyOptions>();
```

## 常见变体

- **布尔开关**:`[FlagOption]` 让布尔属性仅以 `--verbose` 形式出现,无需传 `true`/`false`。Source: [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L20)
- **敏感信息脱敏**:在 `Option` 上加 `Sensitive = true`,`OptionsDebugger` 输出时会自动遮蔽值。Source: [OptionAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/OptionAttribute.cs#L104-L112)
- **多特性组合**:同一属性同时被 `Option` 和其它特性修饰,构建器按 `Option` 主特性处理。Source: [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L28-L32)

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `Build()` 抛 “缺少必需选项” | `Required = true` 的属性没有从命令行或环境变量获得值 | 补充传参,或在测试场景下调用 `Build(skipValidation: true)` |
| 环境变量没生效 | 构造 `OptionsBuilder` 时显式传 `useEnvironmentVariables: false`,或用了 `CreateFromArgsOnly` | 改用 `Create<TOptions>(args)`(默认 `true`)或 `CreateFromEnvironmentOnly<TOptions>()` |
| 未加特性的属性被忽略 | 框架只解析带特性的属性,普通属性保留类型默认值 | 给需要绑定的属性加上 `Option`、`FlagOption` 或 `EnvironmentVariable` |

## 背景(可选)

`OptionsBuilder<T>` 通过反射遍历 `T` 的公共属性,根据特性元数据决定从命令行参数、环境变量或默认值中取值;`EnvironmentVariableAttribute` 与 `OptionAttribute.EnvironmentVariable` 是同一机制的两种入口,前者适合“仅环境变量”属性,后者适合“命令行 + 环境变量”可覆盖属性。
