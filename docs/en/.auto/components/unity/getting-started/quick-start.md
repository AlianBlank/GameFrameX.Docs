# Get Your First Game Script Running in 10 Minutes

Follow this page to get GameFrameX up and running in your Unity project and have a simple game script (logging output via `GameFrameworkLog`) execute properly, serving as a starting point for using other framework modules.

## Prerequisites

- Unity 2019.4 or higher ([README.md](/README.md#L57-L61))
- The project has .NET Standard 2.0+ API compatibility level enabled
- Add `com.gameframex.unity` to the project via Unity Package Manager or by cloning it directly

## Steps

1. **Create the startup script in the scene.** Create a new C# script, for example `MyGameEntry.cs`, and attach it to any scene object:

   ```csharp
   using UnityEngine;
   using GameFrameX;

   public class MyGameEntry : MonoBehaviour
   {
       private void Start()
       {
           // The unified logging entry provided by the framework, see GameFrameworkLog for details
           GameFrameworkLog.Info("Hello, GameFrameX!");
       }
   }
   ```

2. **Confirm the namespace.** The framework's runtime base classes are under the `GameFrameX` namespace, such as `GameFrameworkEntry`, `GameFrameworkLog`, etc. (directory reference [Runtime/Base](/Runtime/Base)).

3. **Run the scene.** Click Play in Unity. The Console window should output `Hello, GameFrameX!`, indicating that the framework runtime has been loaded correctly and can be called by your script.

4. **Hook into framework events (optional, to verify extensibility).** If you want to further verify events/task pools, you can define a parameter that inherits from the framework event base class, and use the event subscription API to listen to it (refer to the "Event Pool" and "Task Pool" chapters for details).

## Common Variants

- **Install as a UPM package**: Add `"com.gameframex.unity": "https://github.com/GameFrameX/com.gameframex.unity.git"` to the `dependencies` in `Packages/manifest.json`, then return to step 1 on this page.
- **As a submodule / directly embedded**: Clone the repository into any directory under `Assets/` in the project, then proceed from step 1 after completion.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GameFrameworkLog` cannot be found | Namespace not referenced or package not imported correctly | Add `using GameFrameX;` at the top of the script, and confirm the package is added to `Packages/manifest.json` |
| Console shows no output | Script not attached or `Start` not triggered | Attach the script to a scene object and ensure the scene is loaded |
| Compilation errors related to `.NET Standard` | Project API compatibility level is too low | Change Player Settings → Api Compatibility Level to `.NET Standard 2.1` |

## Background (Optional)

GameFrameX adopts a three-tier modular architecture of Runtime / Plugins / Editor. The `Base/` under the Runtime module provides the core foundation of the framework, including subsystems such as logging, event pool, reference pool, task pool, and variable system ([README.md](/README.md#L65-L108)). After completing the script run on this page, you can continue reading each subsystem's page for in-depth usage.
