# 動作原理：スレッドセーフな更新ループとオブジェクトプール

`TimerManager` は毎フレームの `Update` 内で、グローバルロック(`Locker`)を用いて「アクティブなタイマーのスキャン → 期限切れ項目の回収 → 新規項目のマージ」という三段階の更新を直列に実行します。すべての期限切れコールバックはまず `_pendingCallbacks` に収集され、ロック外で一括実行されます。これにより、コールバック内で再び Add/Remove を呼び出してデッドロックが発生するのを防ぎます。削除された `TimerItem` は破棄されず、参照をクリアした上で `Stack<TimerItem>` オブジェクトプールに戻して再利用されます。

## コアデータ構造早見表

| メンバー | 実際の型/デフォルト値 | 役割 |
|------|-----------------|------|
| `_items` | `Dictionary<Action<object>, TimerItem>` | アクティブなタイマーテーブル。**コールバックデリゲートを key とする**(同一コールバックには 1 つのタイマーのみ) |
| `_toAdd` | `Dictionary<Action<object>, TimerItem>` | マージ待ちの新規タイマー。`Add()` はまずここに書き込み、フレーム末に `_items` へ統合 |
| `_toRemove` | `List<TimerItem>` | 回収待ち項目。Update 内で一括クリーンアップ |
| `_pool` | `Stack<TimerItem>`、初期容量 100 | `TimerItem` オブジェクトプール。回収して再利用 |
| `_pendingCallbacks` | `List<(Action<object> Callback, object Param)>` | 当フレームの期限切れコールバックのキャッシュ。ロック外で実行 |
| `_ids` | `Dictionary<int, Action<object>>` | タイマー ID → コールバック のインデックス |
| `_tags` | `Dictionary<string, List<int>>` | タグ → ID リスト のグループインデックス |
| `_nextId` | `int`、1 からインクリメント | ID アロケーター |
| `Locker` | `static readonly object` | グローバルロックオブジェクト。すべての読み書きパスで共用 |
| `CatchCallbackExceptions` | `static bool`、デフォルト `false` | `true` の場合、コールバックの例外は握りつぶされ警告の出力のみ行う |

## 毎フレームの更新ループ

`Update(float elapseSeconds, float realElapseSeconds)` は `GameFrameworkModule` を継承しており、フレームワークによって毎フレーム 1 回駆動されます。状態スキャン全体は `lock (Locker)` 内で完了します:

1. **削除済み・一時停止中の項目のスキップ**:`Deleted` の項目は `_toRemove` に入ります。`IsPaused` の項目は累積をスキップしますが `_items` には残ります。
2. **タイムスケールモードに応じた時間ソースの選択**:`TimerTimeScale.Scaled` は `elapseSeconds`、それ以外は `realElapseSeconds` を使用。
3. **毎フレームタイマー**(interval <= 0)は時間を累積せず、そのフレームで即座に発火。
4. **通常タイマー**は `Elapsed` を累積し、`Elapsed >= Interval` のとき `Interval` を減算して `_pendingCallbacks` に追加。
5. **繰り返し回数の減算**:`Repeat > 0` の場合、発火のたびに `Repeat--` し、0 になったら `Deleted` をマークして `_toRemove` に入る。
6. **回収**:`_toRemove` を走査し、`OnComplete` を発火、`_items`/`_ids`/`_tags` から取り除き、オブジェクトプールに返却。
7. **マージ**:`_toAdd` を `_items` に統合してクリア。

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    lock (Locker)
    {
        if (_items.Count > 0)
        {
            var enumerator = _items.GetEnumerator();
            while (enumerator.MoveNext())
            {
                var timerItem = enumerator.Current.Value;
                if (timerItem.Deleted)
                {
                    _toRemove.Add(timerItem);
                    continue;
                }

                // Paused timer: skip elapsed accumulation but remain in _items
                if (timerItem.IsPaused)
                {
                    continue;
                }

                // Select time source based on TimeScaleMode
                float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

時間の累積と発火判定(`Elapsed` の余剰が 0.03 秒を超えると 0 にクランプされ、フレーム落ち後の連続発火を防止します):

```csharp
timerItem.Elapsed += delta;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}

timerItem.Elapsed -= timerItem.Interval;
if (timerItem.Elapsed < 0 || timerItem.Elapsed > 0.03f)
    timerItem.Elapsed = 0;

if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}

if (timerItem.Callback != null)
{
    _pendingCallbacks.Add((timerItem.Callback, timerItem.Param));
}
```

## コールバックはロック外で実行される(スレッドセーフの鍵)

`_pendingCallbacks` の実行は `lock` ブロックの**外側**で行われます。これは意図的な設計です。コールバック内部で再び `Add`/`Remove`/`Exists` を呼び出す場合(これらはそれぞれ `lock (Locker)` を行います)、ロック内で実行すると即座にデッドロックとなります——C# の `lock`/Monitor は同一スレッドに対しては再入可能ですが、本当のリスクはロックを長時間保持することで他のスレッド(非同期/バックグラウンドスレッドの継続など)をブロックすることにあります。コールバックをロック外に移すことで、コールバック内で安全にタイマーを追加・削除できるようになります。

```csharp
// Execute callbacks outside lock to avoid blocking other threads
if (_pendingCallbacks.Count > 0)
{
    for (int i = 0; i < _pendingCallbacks.Count; i++)
    {
        var (callback, param) = _pendingCallbacks[i];
        if (CatchCallbackExceptions)
        {
            try
            {
                callback(param);
            }
            catch (Exception e)
            {
                Debug.LogWarning("Timer callback error > " + e.Message);
            }
        }
        else
        {
            callback(param);
        }
    }

    _pendingCallbacks.Clear();
}
```

出典:[TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L166-L190)

注意：コールバック実行時に例外がスローされ、かつ `CatchCallbackExceptions == false`(デフォルト)の場合、例外は上位に伝播し、`_pendingCallbacks` はクリアされません——以降のフレームでもこのリストへの追加が続き、同じコールバック群が重複実行される可能性があります。ゲームの初期化時に `TimerManager.CatchCallbackExceptions = true` を有効にすることを推奨します。

## オブジェクトプール:GetFromPool / ReturnToPool

`TimerItem` はプライベートなネストクラスであり、取得時はまず `_pool` からポップしてすべての実行状態フィールドをリセットし、プールが空のときのみ `new` します。返却時はすべてのデリゲートとパラメータの参照をクリアしてからプッシュし戻し、オブジェクトの保持(Object Retention)を防止します。

```csharp
private TimerItem GetFromPool()
{
    TimerItem t;
    if (_pool.Count > 0)
    {
        t = _pool.Pop();
        t.Deleted = false;
        t.Elapsed = 0;
        t.IsPaused = false;
        t.PausedElapsed = 0;
        t.TimeScaleMode = TimerTimeScale.Unscaled;
        t.Tag = null;
        t.OnComplete = null;
    }
    else
    {
        t = new TimerItem();
    }

    return t;
}

private void ReturnToPool(TimerItem t)
{
    t.Callback = null;
    t.Param = null;
    t.Tag = null;
    t.OnComplete = null;
    _pool.Push(t);
}
```

返却の入口は 2 か所あり、いずれもロック内で呼び出されます:

| 返却タイミング | 場所 | `OnComplete` を発火する? |
|----------|------|---------------------|
| Update での期限切れ/削除項目の回収(`Repeat` 使い切りまたは `Deleted` マーク) | `Update` 内の `_toRemove` クリーンアップループ | はい。`i.OnComplete?.Invoke()` は返却前に呼び出される |
| `Remove(callback)` がまだ `_toAdd` に存在し未マージの項目にヒット | `Remove(Action<object>)` | はい。まず `t.OnComplete?.Invoke()` を呼び出してから返却 |

## Add の 3 つのパス

`Add(...)` は `lock` 内で以下の順序で処理され、同じ呼び出しでも異なる分岐にヒットする可能性があります:

| 順序 | 条件 | 動作 |
|------|------|------|
| 1 | `callback == null` | 警告 `timer callback is null, {interval},{repeat}` を出力し、`0` を返す |
| 2 | コールバックが既に `_items` に存在 | **インプレース更新**:`Set(...)` でパラメータを再設定、`Elapsed = 0`、`Deleted/IsPaused` をクリアし、元の `Id` を返す |
| 3 | コールバックが既に `_toAdd` に存在 | 同様にインプレース更新し、元の `Id` を返す |
| 4 | 完全に新しいコールバック | `_nextId++` で ID を割り当て、`GetFromPool()` でオブジェクトを取得、`_toAdd`/`_ids`/`_tags` に書き込み、新しい `Id` を返す |

```csharp
int id = _nextId++;
t = GetFromPool();
t.Id = id;
t.Interval = interval;
t.Repeat = repeat;
t.Callback = callback;
t.Param = callbackParam;
t.Tag = tag;
t.TimeScaleMode = timeScale;
t.OnComplete = onComplete;
_toAdd[callback] = t;
_ids[id] = callback;
AddToTagIndex(t);
return id;
```

出典:[TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L260)

key がコールバックデリゲートそのものであるため、**同じ lambda/メソッドに対して `Add` を繰り返しても 2 つ目のタイマーは作成されず**、既存のものがリセットされます——`Elapsed` のゼロリセットや一時停止の解除も含まれます。

## Remove の 2 段階処理

`Remove(callback)` は `_toAdd` にヒットした場合、直接削除してオブジェクトプールに返却します(そのタイマーはまだスキャンループに入っていません)。`_items` にヒットした場合は `t.Deleted = true` の遅延マークのみを行い、実際の回収は次フレームの `Update` における `_toRemove` クリーンアップループで実行されます。`Remove(int id)` も同様で、まず `_ids` からコールバックを検索し、その後同じロジックを実行します。

```csharp
public void Remove(Action<object> callback)
{
    lock (Locker)
    {
        if (_toAdd.TryGetValue(callback, out var t))
        {
            _toAdd.Remove(callback);
            _ids.Remove(t.Id);
            RemoveFromTagIndex(t);
            t.OnComplete?.Invoke();
            ReturnToPool(t);
            return;
        }

        if (_items.TryGetValue(callback, out t))
        {
            t.Deleted = true;
        }
    }
}
```

## Shutdown の動作

`Shutdown` はロック内で `_toRemove`、`_toAdd`、`_items`、`_ids`、`_tags`、`_pendingCallbacks` をクリアします——ただし**オブジェクトを `_pool` に返却せず、`OnComplete` も一切発火しない**点に注意してください。コンポーネント破棄後、プール内オブジェクトはマネージャーとともに解放されます。

## 外側のコンポーネントと駆動方式

`TimerComponent` は Unity 側の `GameFrameworkComponent` であり、`Awake` 内で `GameFrameworkEntry.GetModule<ITimerManager>()` によって `TimerManager` インスタンスを取得し、自身のすべての API は 1 行の転送のみを行います。実際の毎フレームの駆動はフレームワーク基底クラス `GameFrameworkModule` による `Update` の呼び出しから行われ、`TimerComponent` には `[GameFrameXAutoComponent(-5000)]` が付与されており、自動登録の順序が決まります。

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");
        return;
    }
}
```
