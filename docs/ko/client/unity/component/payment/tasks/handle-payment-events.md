# 결제 결과 이벤트 처리 방법

`PaymentComponent`에서 4개의 결제 이벤트(구매 성공, 구매 실패, 구매 기록 조회 결과, 구매 소비 결과)를 구독하고, 콜백에서 `PaymentEventArgs.ResultCode`에 따라 분기 처리하며, `PurchaseToken`으로 소비를 완료합니다. 모든 API는 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64)와 [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)에 정의되어 있습니다.

## 사전 조건

- 씬에 GameFrameX 루트 오브젝트가 존재하고 `PaymentComponent`가 연결되어 있어야 합니다(메뉴 `GameFrameX/Payment`, 해당 컴포넌트는 `GameFrameXPaymentCroppingHelper`가 동시에 존재해야 합니다).
- `Init()`을 호출하여 결제 관리자를 초기화했고, `IsReady()`가 `true`를 반환한 후에 구매를 시작합니다:

```csharp
// 시그니처: public void Init(bool isDebug = false, bool isClientVerify = true)
// 시그니처: public bool IsReady()
paymentComponent.Init(isDebug: false, isClientVerify: true);
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115)

## 작업 단계

1. `PaymentComponent` 참조를 가져옵니다(예: GameFrameX 모듈 진입점을 통해).
2. 게임 시작 단계에서 이벤트를 구독하고, 파괴 단계에서 대칭적으로 구독을 해제합니다(`PaymentComponent`는 내부 `IPaymentManager`로 직접 전달됩니다):

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseSuccess += OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed += OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult += OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult += OnConsumePurchaseResult;

// 종료/파괴 시
paymentComponent.OnPurchaseSuccess -= OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed -= OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult -= OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult -= OnConsumePurchaseResult;
```

컴포넌트에서 이벤트의 실제 선언은 다음과 같습니다(`add`/`remove`가 관리자로 직접 전달됨):

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}

public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L64)

3. 콜백에서 `ResultCode`에 따라 분기 처리하고, `PaymentEventArgs`의 필드를 통해 데이터를 가져옵니다:

```csharp
private void OnPurchaseSuccess(object sender, PaymentEventArgs e)
{
    // e.ProductId / e.OrderId / e.PurchaseToken / e.PurchaseData / e.CustomData
}

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    switch (e.ResultCode)
    {
        case PaymentResultCode.Cancelled:
            // 사용자가 직접 취소한 경우, 일반적으로 별도 안내 없이 처리
            break;
        case PaymentResultCode.NetworkError:
        case PaymentResultCode.ServiceUnavailable:
            // 나중에 다시 시도하도록 안내
            break;
        case PaymentResultCode.ItemAlreadyOwned:
        case PaymentResultCode.VerifyFailed:
        default:
            // e.ErrorMessage로 표시하거나 보고
            break;
    }
}
```

4. 일회성 상품 지급에 성공한 후, 콜백의 `PurchaseToken`으로 `ConsumePurchase`를 호출하여 구매를 소비하며, 그 결과는 마찬가지로 `OnConsumePurchaseResult` 이벤트를 통해 반환됩니다:

```csharp
// 시그니처: public void ConsumePurchase(string purchaseToken)
paymentComponent.ConsumePurchase(e.PurchaseToken);
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L133-L152)

### PaymentEventArgs 필드 빠른 참조

| 필드 | 타입 | 설명 |
|------|------|------|
| `ProductId` | `string` | 제품 ID |
| `OrderId` | `string` | 주문 ID |
| `PurchaseToken` | `string` | 구매 토큰(구매 소비 시 사용) |
| `ResultCode` | `PaymentResultCode` | 결제 결과 코드 |
| `ErrorMessage` | `string` | 오류 메시지 |
| `PurchaseData` | `string` | 원본 구매 데이터(JSON 형식) |
| `CustomData` | `string` | 사용자 지정 데이터(구매 시 전달) |

출처: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

### PaymentResultCode 값

| 값 | 의미 |
|------|------|
| `Success` | 성공 |
| `Failed` | 실패 |
| `Cancelled` | 사용자 취소 |
| `NetworkError` | 네트워크 오류 |
| `ServiceUnavailable` | 서비스 사용 불가 |
| `ItemAlreadyOwned` | 상품을 이미 보유함 |
| `ItemNotOwned` | 상품을 보유하지 않음 |
| `VerifyFailed` | 검증 실패 |
| `Unknown` | 알 수 없음 |

## 일반적인 변형

- **미지급 주문 처리/구매 복원**: `QueryPurchases(PaymentProductType)` 호출 후 `OnQueryPurchasesResult`를 수신하고, `ResultCode == PaymentResultCode.Success`인 과거 주문을 하나씩 지급한 뒤 `ConsumePurchase(e.PurchaseToken)`를 호출합니다.
- **결과 코드만 필요한 경우**: `OnPurchaseSuccess`와 `OnPurchaseFailed` 모두 동일한 `PaymentEventArgs` 구조를 전달하며, 실패 시나리오에서는 추가로 `ErrorMessage`를 사용합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 로그에 `You are using DefaultPaymentManager which is a stub...` 표시됨 | Editor/모바일이 아닌 플랫폼이 플레이스홀더 구현으로 처리되어 이벤트가 트리거되지 않음 | 채널 구현(예: Google/Apple)을 연결하거나 실제 기기에서 검증 |
| 로그에 `Pay Manager is invalid.` 표시됨 | 관리자 모듈이 올바르게 로드되지 않음 | `PaymentComponent`와 크로핑 보조 컴포넌트가 모두 갖춰져 있는지 확인 |
| 로그에 `Purchase token is null or empty.` 표시됨 | `ConsumePurchase` 호출 시 빈 토큰을 전달함 | 콜백에서 반환된 `e.PurchaseToken` 사용 |

위 경고/오류 원문은 [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L48)와 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L152)에서 확인할 수 있습니다.

## 검증

- 구독 후 `Buy(new PurchaseParams(...))`를 한 번 실행하여, `OnPurchaseSuccess` 또는 `OnPurchaseFailed`가 최소 한 번 트리거되고, `e.ProductId`, `e.OrderId`가 요청 시 파라미터와 일치하는지 확인합니다.
- `ConsumePurchase` 호출 후 `OnConsumePurchaseResult`가 반환되고 `ResultCode == PaymentResultCode.Success`인지 확인합니다.

## 배경

`PaymentComponent`는 얇은 래퍼입니다. 4개의 이벤트는 `add`/`remove` 접근자를 통해 플랫폼 구현으로 직접 전달됩니다(Android은 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`, iOS/macOS는 `Apple.Runtime.ApplePaymentManager`, WebGL/PC는 각각 대응하는 구현이 있으며, 나머지 플랫폼은 `DefaultPaymentManager` 플레이스홀더로 대체됩니다). 따라서 이벤트 처리 로직은 플랫폼과 무관하며, 컴포넌트 계층에서 통일되게 구독하면 됩니다.
