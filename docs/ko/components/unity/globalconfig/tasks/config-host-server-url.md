# 호스트 서버 주소 구성 방법

`GlobalConfigComponent`에 `HostServerUrl`을 설정하면, 클라이언트는 시작 시 백엔드 루트 주소를 가져와 버전 검사, 리소스 업데이트 등의 인터페이스를 조합하는 데 활용할 수 있습니다.

## 사전 조건

- `GameFrameX.GlobalConfig` 컴포넌트가 게임 진입 씬에 마운트되어 있으며, 컴포넌트 타입은 `GlobalConfigComponent`입니다.
- 사용 가능한 HTTP/HTTPS 호스트 주소를 준비합니다(`http://` 또는 `https://`로 시작하며, 끝에 `/`를 추가할 필요 없음).

## 작업 단계

1. 씬에서 `GlobalConfigComponent`가 마운트된 GameObject를 찾아 선택합니다. Inspector에서 "主机服务地址" 필드를 볼 수 있습니다. 이 필드는 직렬화 필드 `m_hostServerUrl`에 해당합니다.

   ```csharp
   // Runtime/GlobalConfig/GlobalConfigComponent.cs:L98-L112
   /// <summary>
   /// 主机服务地址
   /// </summary>
   [SerializeField] private string m_hostServerUrl = string.Empty;

   /// <summary>
   /// 主机服务地址
   /// </summary>
   public string HostServerUrl
   {
       get { return m_hostServerUrl; }
       set { m_hostServerUrl = value; }
   }
   ```

2. Inspector의 "主机服务地址" 입력란에 전체 URL을 입력합니다(예: `https://api.example.com`).

3. 런타임 중(예: 데이터 읽기 또는 핫 업데이트 센터에서下发 후) 주소를 수정해야 하는 경우, `GlobalConfigComponent` 인스턴스의 속성에 값을 할당하면 됩니다:

   ```csharp
   var globalConfig = GameEntry.GetComponent<GlobalConfigComponent>();
   globalConfig.HostServerUrl = "https://api.example.com";
   ```

4. 검증: 게임을 시작한 후, Inspector의 "原始数据"(해당 `OriginalData`) 또는 콘솔 로그에서 해당 필드가 적용된 것을 확인할 수 있습니다. 이후 해당 주소 조합에 의존하는 모든 다운스트림 인터페이스(버전 검사, 리소스 버전 검사)는 자동으로 새 값을 사용합니다.

## 일반적인 변형

- `CheckAppVersionUrl` / `CheckResourceVersionUrl`과 함께 사용: "主机服务地址"가 루트 도메인 역할만 하고 버전 검사는 독립적인 CDN을 사용할 경우, 해당 필드에 각각 입력하여 호스트 주소로 덮어쓰이지 않도록 합니다.
- `OriginalData`를 통한 일괄下发: 서버가 반환한 전체 JSON 세그먼트는 역직렬화되어 `m_originalData`에 다시 기록되며, 비즈니스 로직은 이 원본 문자열을 읽어 각 하위 시스템에 배포할 수 있습니다.

## 일반적인 오류

| 현상 | 원인 | 해결 |
|------|------|------|
| 설정 후에도 인터페이스가 여전히 이전 주소를 사용 | 씬이 이미 활성화되었지만 다운스트림이 이전 값을 캐시한 이후에 필드 할당이 발생 | `GameEntry` 시작 흐름의 가장 초기 단계 또는 다운스트림이 읽기 전에 할당 |
| 주소 끝에 `/`가 추가되어 요청 경로가 `//api/...`가 됨 | 습관적으로 도메인 뒤에 슬래시를 추가 | 끝의 `/`를 제거하고, 필요에 따라 호출자가 조합 |
| Inspector에서 필드가 회색으로 표시되어 편집할 수 없음 | 현재 Play 모드에 있어 런타임 변경 손실을 방지하기 위해 Inspector에서 편집이 비활성화됨 | Play 모드를 종료한 후 수정하거나 속성 할당을 사용 |
