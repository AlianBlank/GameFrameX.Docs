# 시작 UI가 표시되지 않거나 멈추는 경우怎么办

시작 플로우에서 전달한 `IStartupUIHandler` 구현이 진행률이나 안내 텍스트를 표시하지 않거나, 특정 단계에서 멈춰 있을 때는 보통 handler가 FSM에 주입되지 않았거나, 인터페이스 메서드를 구현하지 않았거나, 구현부에서 메인 스레드를 차단했기 때문입니다. 이 페이지에서는 문제 해결 경로와 수정 방법을 안내합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 시작 과정 전체에서 UI가 전혀 보이지 않음 | `IStartupUIHandler`가 FSM BlackBoard에 주입되지 않음 | `StartupRunner` 호출 시 handler 인스턴스를 시작 파라미터로 전달 |
| UI는 표시되지만 안내 텍스트/진행률이 계속 비어 있음 | handler의 `SetTipText` / `SetProgress`가 실제로 UI 컨트롤에 반영되지 않음 | 구현부에서 파라미터를 보이는 Text/Slider 컴포넌트에 동기화 |
| 시작이 특정 procedure에서 멈추고 UI가 움직이지 않음 | handler 구현부에서 블로킹 작업을 수행했거나 메인 스레드에서 UI에 접근하지 않음 | 메인 스레드로 돌아와서 새로고침(`UnitySynchronizationContext`), `SetProgress` 안에서 await/Thread.Sleep 사용 금지 |
| 실패 시 UI에 오류 메시지가 표시되지 않음 | handler에서 예외가 발생해 `?.SetTipText` 이후 체인이 끊김 | handler 내부에서 try/catch 처리, 또는 `CompleteFailure` 호출 스택 확인 |
| 시작 종료 후 UI가 파괴되지 않음 | `Dispose()`를 구현하지 않았거나 `Dispose()`가 실제로 GameObject를 파괴하지 않음 | `Dispose()` 안에서 `Destroy(gameObject)` 실행 후 참조 정리 |

## 수정 단계

### 1. handler가 FSM에 주입되었는지 확인

시작 플로우는 `IStartupUIHandler`를 FSM BlackBoard에 저장하며, key는 `"__startup_ui_handler__"`로 고정되어 있습니다. 모든 procedure는 `StartupProcedureUtility.GetUIHandler`를 통해 읽어오며, `null`을 읽으면 코드가 `?.SetTipText(...)`로 실행되어 UI가 전혀 트리거되지 않습니다.

```csharp
public const string StartupUIHandler = "__startup_ui_handler__";
```

출처: [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs#L17)

```csharp
public static IStartupUIHandler GetUIHandler(IFsm<IProcedureManager> procedureOwner)
{
    return procedureOwner.GetData<VarObject>(BlackBoardKeys.StartupUIHandler).Value as IStartupUIHandler;
}
```

출처: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L46-L49)

**수정**: handler 인스턴스를 시작 파라미터로 `StartupRunner.RunAsync(options)`에 전달하면, Runner가 BlackBoard에 씁니다. Runner를 거치지 않고 직접 FSM을 구성하는 경우, 반드시 `fsm.SetData(BlackBoardKeys.StartupUIHandler, new VarObject() { Value = handler })`를 호출하세요.

### 2. 인터페이스 메서드가 모두 구현되었는지 확인

`IStartupUIHandler`는 총 4개의 메서드로 구성되며, 시작 플로우는 그중 3개를 호출합니다. 하나라도 구현하지 않으면 UI 동작이 불완전해집니다.

```csharp
public interface IStartupUIHandler
{
    void SetTipText(string text);
    void SetProgress(float progress, string sizeInfo);
    void SetProgressUpdateFinish();
    void Dispose();
}
```

출처: [IStartupUIHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/UI/IStartupUIHandler.cs)

**수정**: 4개 메서드를 모두 구현하세요. `SetProgress(progress, sizeInfo)`의 `progress`는 `0~1` 부동소수점 값이고, `sizeInfo`는 `"5.2MB / 100MB"` 형태의 문자열이므로 그대로 표시하면 됩니다.

### 3. 메인 스레드에서 UI를 새로고침하는지 확인

시작 플로우의 procedure는 기본적으로 메인 스레드에서 진행되지만, `IStartupUIHandler` 구현부에서 새로고침 동작을 백그라운드 스레드/비동기 작업으로 넘기면 Unity가 `Text`/`Slider` 접근 시 예외를 던지거나 조용히 실패하여 '멈춘 것처럼' 보입니다.

**수정**:
- `SetTipText` / `SetProgress` 내부에서는 `text.text = ...`, `slider.value = ...`만 수행하고 `await`를 사용하지 마세요.
- 비동기 리소스 로딩이 꼭 필요하다면 `UniTask.RunOnThreadPool`을 사용한 후 `UniTask.SwitchToMainThread()`로 메인 스레드로 돌아와서 값을 할당하세요.
- handler 진입부에서 try/catch를 처리하여 구현부의 예외가 이후 procedure를 중단시키지 않도록 하세요.

### 4. 실패 정보가 표시되지 않는 경우

시작이 실패하면 프레임워크가 `SetTipText(errorMessage)`를 한 번 호출하여 오류를 UI에 전달합니다:

```csharp
public static void CompleteFailure(IFsm<IProcedureManager> procedureOwner, string procedureName, string failedUrl, string errorMessage)
{
    var result = StartupResult.Fail(procedureName, failedUrl, errorMessage);
    GetUIHandler(procedureOwner)?.SetTipText(errorMessage);
    ...
}
```

출처: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L162-L168)

**수정**: UI에 상시 표시되는 "안내 텍스트" 노드를 유지하여 `SetTipText`가 기록한 내용을 플레이어가 즉시 볼 수 있도록 하세요. 동시에 `StartupFailedEventArgs`를 구독하여 실패 원인을 로그에 남기거나 리포트하세요.

### 5. 시작 완료 후 UI가 파괴되지 않는 경우

`IProcedureManager`는 시작 완료 후 `handler.Dispose()`를 호출합니다. handler 내부에 `GameObject`를持有하고 있는 경우(흔한 방식), `Dispose()` 안에서 실제로 파괴해야 합니다. 그렇지 않으면 다음 시작 시 여러 UI가 겹쳐 쌓입니다.

**수정**:
```csharp
public void Dispose()
{
    if (gameObject != null) UnityEngine.Object.Destroy(gameObject);
}
```

## 검증

1. handler 생성 시 임시로 `Debug.Log("UIHandler created");`를 추가하여, 실제로 Runner에 전달되어 FSM에 진입하는지 확인하세요.
2. `SetTipText` / `SetProgress` 내부에서 입력 파라미터를 `Debug.Log`로 출력하여, procedure가 실제로 호출하는지 검증하세요.
3. 일부러 예외를 던져 `CompleteFailure`를 트리거시키고, UI에 오류 텍스트가 표시되는지 확인하세요.
4. 시작 성공 후 씬을 관찰하여, 이전 UI GameObject가 파괴되었고 다음 시작 시 UI가 새로 생성되는지 확인하세요.
