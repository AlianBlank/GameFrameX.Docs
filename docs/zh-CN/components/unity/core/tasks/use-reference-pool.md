# 使用引用池减少 GC 分配

引用池(`ReferencePool`)用于缓存实现了 `IReference` 接口的对象实例,通过 `Acquire` 获取、`Release` 归还复用,避免反复 `new` 造成的 GC 压力。本页给出在 GameFrameX 中接入引用池并用于自定义类型的完整步骤。

## 前置条件

- 项目已引入 `GameFrameX.Runtime.Base.ReferencePool` 与 `GameFrameX.Runtime.ReferencePoolComponent`(随框架默认打包)。
- 场景里挂有 `ReferencePoolComponent`(菜单 `Add Component → GameFrameX → ReferencePool`),或在代码里直接通过静态类 `ReferencePool` 访问。

## 操作步骤

1. **让自定义类型实现 `IReference`**。类型必须有无参构造函数,并在 `Clear()` 中把字段复位,保证下一次取出时是干净状态。

   ```csharp
   using GameFrameX.Runtime;

   public sealed class DamageInfo : IReference
   {
       public int AttackerId { get; private set; }
       public int TargetId   { get; private set; }
       public float Amount  { get; private set; }

       public void Clear()
       {
           AttackerId = 0;
           TargetId   = 0;
           Amount     = 0f;
       }

       internal void Fill(int attackerId, int targetId, float amount)
       {
           AttackerId = attackerId;
           TargetId   = targetId;
           Amount     = amount;
       }
   }
   ```

   Source: [Tests/ReferencePoolTests.cs#L11-L29](/src/Tests/ReferencePoolTests.cs#L11-L29)

2. **Acquire 获取实例**。使用泛型版本无需手动转型;池空时框架会调用无参构造函数新建。

   ```csharp
   DamageInfo info = ReferencePool.Acquire<DamageInfo>();
   ```

   签名:`public static T Acquire<T>() where T : class, IReference, new()`,见 [Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132)。

3. **Release 归还实例**。归还时会自动调用 `Clear()`,但字段级重置仍由你的 `Clear()` 负责。

   ```csharp
   ReferencePool.Release(info);
   ```

   签名:`public static void Release(IReference reference)`,见 [Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167)。传入 `null` 会抛出 `GameFrameworkException("Reference is invalid.")`,见 [Tests/ReferencePoolTests.cs#L79](/src/Tests/ReferencePoolTests.cs#L79)。

4. **(可选)启动前预热池容量**。在战斗/关卡开始时调用 `Add<T>(count)`,避免运行时即时扩容。

   ```csharp
   ReferencePool.Add<DamageInfo>(64);
   ```

   签名:`public static void Add<T>(int count) where T : class, IReference, new()`,见 [Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181)。

5. **(可选)查看池状态**。在调试面板或 Profiler 钩子里读取各类型缓存信息。

   ```csharp
   ReferencePoolInfo[] infos = ReferencePool.GetAllReferencePoolInfos();
   foreach (var info in infos)
   {
       UnityEngine.Debug.Log($"{info.Type.Name}: using={info.UsingReferenceCount} unused={info.UnusedReferenceCount}");
   }
   ```

   签名见 [Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98)。

## 常见变体

- **运行时按 `Type` 获取**(无法使用泛型时):

  ```csharp
  IReference info = ReferencePool.Acquire(typeof(DamageInfo));
  ```

  见 [Runtime/Base/ReferencePool/ReferencePool.cs#L142-L147](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L142-L147)。
- **按 `Type` 预热**:

  ```csharp
  ReferencePool.Add(typeof(DamageInfo), 64);
  ```
- **整体清空**(场景切换、退出战斗时):

  ```csharp

  ```

  见 [Runtime/Base/ReferencePool/ReferencePool.cs#L106-L118](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L106-L118)。
- **移除某类型多余缓存**:`ReferencePool.Remove<DamageInfo>(count)` 或 `RemoveAll<DamageInfo>()`,签名见 [ReferencePool.cs#L206-L249](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L206-L249)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameFrameworkException: Reference is invalid.` | 把 `null` 传给了 `Release` | Release 前做非空判断,或在 `using`/`try-finally` 块内归还 |
| 取出对象残留上次数据 | `Clear()` 没把字段复位 | 在 `Clear()` 中显式把所有字段重置为默认值 |
| 类型无法 `Acquire` | 类型未实现 `IReference` 或没有 `public` 无参构造函数 | 实现接口、补齐无参构造函数 |
| Profiler 显示池爆涨 | 一直 Acquire 不 Release | 在使用结束路径(异常分支也算)确保 Release;可用 `try { ... } finally { Release(info); }` |
| 开启严格检查后性能下降 | `ReferencePool.EnableStrictCheck = true` 启用了反射校验 | 仅在调试期打开,发布版关闭 |

## 背景(可选)

每个 CLR 类型在池内有一个独立的 `ReferenceCollection`,内部维护 `Stack<IReference>`。`Acquire` 优先出栈,栈空才 `new`;`Release` 调用 `Clear()` 后压栈。开启 `EnableStrictCheck` 会通过反射校验类型,影响性能,仅用于调试。
