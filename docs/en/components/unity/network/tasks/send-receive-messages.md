# Sending and Receiving Network Messages (Defining Messages and Registering Handlers)

In GameFrameX Network, sending and receiving messages takes only three steps: define a message class that inherits from `MessageObject`, write a handler class that implements the corresponding `IPacket*Handler` interface, and send via `INetworkChannel.Send(...)`. Handlers **do not need to be registered manually** — `DefaultNetworkChannelHelper.Initialize` reflection-scans the assemblies and automatically calls `RegisterHandler` to complete registration.

## Prerequisites

- A network channel has been created and connected (`NetworkManager` is ready).
- The message base class `MessageObject` comes from the framework foundation library; this package's serialization constraint is `where T : MessageObject`.
- Handler classes must be **non-abstract classes**, implement the marker interface `IPacketHandler`, and provide a public parameterless constructor (reflection instantiates them via `Activator.CreateInstance`).

## Steps

1. **Define the message class**: Make the message inherit from `MessageObject`. The send queue maintained internally by the channel is `GameFrameworkLinkedList<MessageObject>`, and the generic constraint at the serialization entry point is also `MessageObject`:

   ```csharp
   public bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject
   ```

   > This repository only contains the network component itself, without concrete game-side message definitions (such as protobuf message classes); you need to define them yourself in your game project.

2. **Implement handlers**: Choose the interfaces to implement based on the send/receive phase. All handlers must implement the marker interface `IPacketHandler` (defined in [IPacketHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketHandler.cs#L4), with the comment "Marker interface, used to identify network packet handlers"):

   | Interface | Registration API (called automatically via reflection) | Responsibility |
   |------|---------------------------|------|
   | `IPacketReceiveHeaderHandler` | `RegisterHandler(IPacketReceiveHeaderHandler)` | Parses received packet headers |
   | `IPacketReceiveBodyHandler` | `RegisterHandler(IPacketReceiveBodyHandler)` | Deserializes packet body into a `MessageObject` |
   | `IPacketSendHeaderHandler` | `RegisterHandler(IPacketSendHeaderHandler)` | Serializes packet headers |
   | `IPacketSendBodyHandler` | `RegisterHandler(IPacketSendBodyHandler)` | Serializes packet bodies |
   | `IPacketHeartBeatHandler` | `RegisterHeartBeatHandler(IPacketHeartBeatHandler)` | Generates/validates heartbeat packets |
   | `IMessageCompressHandler` / `IMessageDecompressHandler` | `RegisterMessageCompressHandler` / `RegisterMessageDecompressHandler` | Packet body compression/decompression |

   Default implementations are provided in the package, which you can inherit from or replace directly: [DefaultPacketReceiveHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveHeaderHandler.cs#L9), [DefaultPacketReceiveBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveBodyHandler.cs#L7), [DefaultPacketSendHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendHeaderHandler.cs#L10), [DefaultPacketSendBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendBodyHandler.cs#L9), [BasePacketHeartBeatHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/BasePacketHeartBeatHandler.cs#L7).

3. **Confirm automatic registration**: During channel initialization, `DefaultNetworkChannelHelper.Initialize` scans all assembly types; every non-abstract class that implements `IPacketHandler` is instantiated and registered to the channel:

   ```csharp
   var types = Utility.Assembly.GetTypes();
   foreach (var type in types)
   {
       if (!type.IsClass || type.IsAbstract)
       {
           continue;
       }

       if (!type.IsImplWithInterface(packetHandlerBaseType))
       {
           continue;
       }

       if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
       {
           var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       else if (type.IsImplWithInterface(packetReceiveBodyHandlerBaseType))
       {
           var handler = (IPacketReceiveBodyHandler)Activator.CreateInstance(type);
           InjectChannelSerializer(handler, type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       // ...subsequently matches SendHeader / SendBody / HeartBeat / Compress / Decompress in order
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L73-L107)

4. **Send messages**: Call the channel's `Send` method. The way heartbeats are sent inside the package is the standard usage:

   ```csharp
   public bool SendHeartBeat()
   {
       if (m_NetworkChannel == null)
       {
           return false;
       }

       var message = m_NetworkChannel.PacketHeartBeatHandler.Handler();
       m_NetworkChannel.Send(message);
       return true;
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L146-L156)

5. **Receive messages**: After a packet is received, the receive handler chain completes the parsing; received packet body deserialization restores the concrete `MessageObject` based on `messageId`:

   ```csharp
   public bool DeserializePacketHeader(byte[] source)
   public bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L179-L189)

6. **(Optional) Listen for network events**: Connection, closure, heartbeat-miss, and error events are already subscribed uniformly by the Helper (`NetworkConnectedEventArgs`, `NetworkClosedEventArgs`, `NetworkMissHeartBeatEventArgs`, `NetworkErrorEventArgs`); on the game side, simply subscribe via the event component. See [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128).

## Common Variants

## Common Variants

- **Custom heartbeat**: Inherit from `BasePacketHeartBeatHandler` (which implements both `IPacketHeartBeatHandler` and `IPacketHandler`), and implement `Handler()` to return the heartbeat message object; when the heartbeat is sent, `m_NetworkChannel.Send(message)` is called, same as with regular messages.
- **Custom compression**: Implement `IMessageCompressHandler` / `IMessageDecompressHandler` respectively and add the `IPacketHandler` marker; once registered, they are called automatically by the `SerializePacketHeader` / `DeserializePacketBody` flows. See the default implementations at [DefaultMessageCompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageCompressHandler.cs#L10) and [DefaultMessageDecompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageDecompressHandler.cs#L10).
- **Manual handler registration**: `INetworkChannel` also exposes various `RegisterHandler` overloads (including the heartbeat overload already marked `[Obsolete("Use RegisterHeartBeatHandler instead")]`). See [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L150-L181).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Handler is never called | The class is abstract, or does not implement the `IPacketHandler` marker interface; the reflection scan skips it directly via `continue` | Declare the class as non-abstract and add `IPacketHandler` |
| Exception thrown when instantiating a handler at runtime | Reflection uses `Activator.CreateInstance(type)`, but a public parameterless constructor is missing | Add a public parameterless constructor to the handler |
| A class matches the wrong registration branch | Registration follows the `ReceiveHeader → ReceiveBody → SendHeader → SendBody → HeartBeat → Compress → Decompress` order in `if / else if` chains and takes the **first match** | Implement only one handler interface per class; split into multiple classes |
| Send/receive packet header/body parsing behavior doesn't match expectations | Missing serializer injection (only the `ReceiveBody` and `SendHeader` branches call `InjectChannelSerializer(handler, type)`) | Configure the channel serializer for the corresponding handler, or use the package's default handlers directly |
| Serialization calls throw null-argument exceptions | `SerializePacketHeader` / `SerializePacketBody` internally validate `m_NetworkChannel`, `PacketSendHeaderHandler`, `PacketSendBodyHandler`, `messageObject`, and `destination` with `GameFrameworkGuard.NotNull` | Complete handler registration before sending, and ensure the message and destination stream are non-null |

## Verification

- Sender side: Watch the channel statistics properties `SendPacketCount` / `SentPacketCount` (send queue count / sent count), displayed as "Send Packet" in the Unity Inspector panel. See [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L108).
- Receiver side: Set a breakpoint in your `IPacketReceiveBodyHandler` implementation and confirm that `DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` is called back and `messageObject` is restored successfully.

## Background

By design, send/receive packet handling is split into "header / body" segments, with the send and receive directions each having their own independent interfaces. When sending, `SerializePacketHeader` writes the header and produces the body buffer, then `SerializePacketBody` writes the body; receiving performs the reverse: `DeserializePacketHeader` → `DeserializePacketBody`. The marker interface `IPacketHandler`, combined with assembly reflection, allows new messages and handlers to be automatically wired in without modifying framework code (see [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L60-L71)). The channel-layer send queue and handler registration implementation are located in [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L525-L572).
