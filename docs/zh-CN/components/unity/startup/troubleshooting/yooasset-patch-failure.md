# YooAsset 补丁流程失败怎么办

当 YooAsset 补丁流程在 `ProcedurePatchInit` → `ProcedureUpdateStaticVersion` → `ProcedureUpdateManifest` → `ProcedureCreateDownloader` → `ProcedureDownloadWebFiles` → `ProcedurePatchDone` 这一链路中任意一步异常时,启动流程会被卡住或被引导回上游流程,本文按现象给出定位与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 卡在 `ProcedurePatchInit`,资源包初始化失败 | `packageUrl` 为空或 CDN 不可达 | 检查 `procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName)` 是否被正确写入;确认 CDN 可访问 |
| 卡在 `ProcedureUpdateStaticVersion`,提示版本不一致 | 远端静态版本号与本地不一致 | 重新构建并发布远端静态版本文件;确保 `StaticVersion.txt` 已上传 |
| `ProcedureUpdateManifest` 报清单错误 | 远端清单文件未发布或签名错误 | 重新发布资源清单(`PackageManifest_{ver}.hash` / `.bytes`)并核对 YooAsset 加密密钥 |
| 进入 `ProcedureDownloadWebFiles` 后进度不动 | 下载器为空或 HTTP 限流 | 检查 `ProcedureCreateDownloader` 产物是否包含 `VarObject` 键 `"Downloader"`;检查代理/带宽 |
| 下载到一半跳回 `ProcedureCreateDownloader` | 单个文件下载失败,触发 `OnDownloadErrorCallback` | 查看 `AssetWebFileDownloadFailedEventArgs` 的 `FileName` 与 `ErrorInfo`,定位远端缺失文件 |
| `ProcedureDownloadWebFiles` 完成后未进入 `ProcedurePatchDone` | `downloader.Status != EOperationStatus.Succeed` | 检查上一条 `OnDownloadError` 日志,补全缺失资源后再启动 |

## 修复步骤

### 1. 资源包初始化失败

`ProcedurePatchInit` 根据 `GamePlayMode` 选择初始化分支:EditorSimulate/Offline 走空 URL,其余模式使用 `BuildInPackageName` 拉取的包地址。

```csharp
// ProcedurePatchInit.InitPatchAsync (Runtime/Procedures/Patch/ProcedurePatchInit.cs)
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode || assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, string.Empty, string.Empty, true);
    ChangeState<ProcedureUpdateStaticVersion>(procedureOwner);
    return;
}

var packageUrl = procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName);
await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, packageUrl.Value, packageUrl.Value, true);
```

Source: [ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L33-L48)

修复操作:

1. 在调试模式(EditorSimulate)复现,排除 CDN 网络问题。
2. 在 `ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState` 中确认 `packageUrl` 已写入 BlackBoard。
3. 真机模式下检查 `StartupOptions.PlayMode` 是否被 `NormalizeAssetPlayMode` 改写(WebGL 强制 `WebPlayMode`,非编辑器下 `EditorSimulateMode` 强制改写为 `HostPlayMode`)。

### 2. 静态版本/清单更新失败

`ProcedureUpdateStaticVersion` 与 `ProcedureUpdateManifest` 由 YooAsset 内置流程驱动。常见失败原因:

- 远端只上传了 `StaticVersion.txt` 没上传 `PackageManifest_*.bytes`。
- YooAsset 加密密钥与编辑器不一致,导致清单解析失败。

修复操作:

1. 用构建工具(Builtin Build Pipeline)重新出包,把整套 `ServerData/{Platform}` 全部上传,不要遗漏 `StaticVersion.txt`。
2. 在编辑器内 `YooAsset > AssetBundle Builder` 出包后,本地起一个 HTTP 服务器,先用同一份 `PlayMode` 验证一遍。
3. 关掉清单加密或确认密钥一致。

### 3. 下载器为空或下载中断

`ProcedureDownloadWebFiles` 直接消费 `ProcedureCreateDownloader` 写入的 `VarObject` 键 `"Downloader"`(`ResourceDownloaderOperation`),并通过回调监听错误:

```csharp
// ProcedureDownloadWebFiles.BeginDownload (Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs)
var downloader = (ResourceDownloaderOperation)procedureOwner.GetData<VarObject>("Downloader").GetValue();

downloader.OnDownloadErrorCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetWebFileDownloadFailedEventArgs.Create(data.PackageName, data.FileName, data.ErrorInfo));
    ChangeState<ProcedureCreateDownloader>(procedureOwner);
};
downloader.OnDownloadProgressCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetDownloadProgressUpdateEventArgs.Create(
        data.PackageName, data.TotalDownloadCount, data.CurrentDownloadCount,
        data.TotalDownloadBytes, data.CurrentDownloadBytes));
    StartupProcedureUtility.SetDownloadProgress(
        StartupProcedureUtility.GetUIHandler(procedureOwner),
        data.CurrentDownloadBytes, data.TotalDownloadBytes);
};

downloader.BeginDownload();
yield return downloader;

if (downloader.Status == EOperationStatus.Succeed)
{
    ChangeState<ProcedurePatchDone>(procedureOwner);
}
```

Source: [ProcedureDownloadWebFiles.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs#L36-L61)

修复操作:

1. 订阅 `AssetWebFileDownloadFailedEventArgs` 拿到 `FileName` 与 `ErrorInfo`,在 CDN 上确认该文件存在且能匿名下载。
2. HTTPS 证书不信任时,YooAsset 会在 `ErrorInfo` 报 SSL 错误,可在 YooAsset 设置里给 HostPlayMode 配置证书或回退 HTTP。
3. 单文件失败会触发 `ChangeState<ProcedureCreateDownloader>` 重试,无需手动干预;若连续失败,把 `ClearCacheWhenDownloadFailure` 之类的 YooAsset 开关清掉本地缓存再启动一次。

### 4. 启动后停在 `ProcedureGameLauncherState` 之前

`ProcedurePatchDone` 是补丁完成的最后一步,若流程停在这里:

- 检查 `ProcedureDownloadWebFiles` 是否成功把 `ChangeState<ProcedurePatchDone>` 触发(只有 `downloader.Status == EOperationStatus.Succeed` 时才会跳转)。
- 检查是否有订阅 `AssetPatchStatesChangeEventArgs` 的自定义 Procedure 把流程拦下了。

## 验证

1. 重新进入游戏,观察 `ProcedureGetGlobalInfoState` → `ProcedurePatchDone` 之间是否有 `EPatchStates.DownloadWebFiles` 事件上报。
2. 在编辑器使用 `EditorSimulateMode`,把 `StartupOptions.GlobalInfoUrls` 指向本地,确认补丁链路走得通。
3. 真机模式下,打开 YooAsset 的沙盒目录(`Application.persistentDataPath/yoo/{PackageName}`),确认 `PackageManifest_*.bytes` 与资源文件都已落地。
4. 若以上都正常但仍然卡住,清理 YooAsset 沙盒后再启动一次,排除脏缓存导致的清单校验失败。
