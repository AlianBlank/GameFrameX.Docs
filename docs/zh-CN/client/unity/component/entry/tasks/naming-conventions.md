# 如何理解命名规范与缩写映射(Component / FUI / GUI)

`GameApp` 是 Game Frame X 的静态门面类,把 `GameApp.{Name}` 映射到 `GameEntry.GetComponent<{Name}Component>()`。理解命名规则就能直接通过 `GameApp.XXX` 拿到任意内置组件,无需查文档。

## 命名映射规则

绝大多数组件遵循"去掉 `Component` 后缀"的直译规则;只有 `FUI` 与 `GUI` 是缩写特例。

| GameApp 属性 | 等价调用 | 类型 |
|---|---|---|
| `GameApp.Event` | `GameEntry.GetComponent<EventComponent>()` | 普通映射 |
| `GameApp.UI` | `GameEntry.GetComponent<UIComponent>()` | 普通映射 |
| `GameApp.Asset` | `GameEntry.GetComponent<AssetComponent>()` | 普通映射 |
| `GameApp.FUI` | `GameEntry.GetComponent<FairyGUIComponent>()` | 缩写特例(FUI=FairyGUI) |
| `GameApp.GUI` | `GameEntry.GetComponent<UGUIComponent>()` | 缩写特例(GUI=uGUI) |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L30-L38)

## 缩写特例说明

`FUI` 和 `GUI` 是两个 UI 子系统的历史简称,保留了首字母大写的紧凑写法,与"去掉 `Component` 后缀"规则不一致,使用时需要特别注意:

- **FUI** → `FairyGUIComponent`(基于 FairyGUI 方案的 UI 组件,已根据 [CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6) 移除 fairygui 依赖)
- **GUI** → `UGUIComponent`(基于 Unity 原生 UGUI 的 UI 组件,定义在 `GameApp.GUI.cs`,受编译宏 `ENABLE_GAME_FRAME_X_L_UGUI` 控制)

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
public static partial class GameApp
{
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }
            return _gui;
        }
    }
}
#endif
```

Source: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

## 操作步骤

在自己的脚本里按以下步骤使用映射:

1. **确认命名**:先在 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L32-L38) 的对照表里查 `GameApp.{Name}`,找到对应的 `*Component` 类型。
2. **普通组件**:直接写 `GameApp.Event`、`GameApp.UI`、`GameApp.Asset` 等。
3. **UI 组件**:UI 子系统区分两种,按引擎方案选 `GameApp.FUI`(FairyGUI)或 `GameApp.GUI`(UGUI)。
4. **按需启用宏**:`GameApp.GUI` 需开启 `ENABLE_GAME_FRAME_X_L_UGUI` 编译宏才存在;`GameApp.FUI` 依赖 FairyGUI 包,移除该依赖后该属性随之失效。

```csharp
// 普通映射示例
var evt = GameApp.Event;
var asset = GameApp.Asset;

// UI 子系统:按引擎方案选其一
var fairygui = GameApp.FUI;   // FairyGUIComponent(需 FairyGUI 包)
var ugui = GameApp.GUI;       // UGUIComponent(需 ENABLE_GAME_FRAME_X_L_UGUI 宏)
```

## 常见错误

| 症状 | 原因 | 修复 |
|---|---|---|
| `GameApp.FUI` 编译报"未定义"或返回 null | 已移除 fairygui 依赖([CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6)) | 改用 `GameApp.GUI` 或安装 FairyGUI 包 |
| `GameApp.GUI` 不可访问 | 缺少编译宏 `ENABLE_GAME_FRAME_X_L_UGUI` | 在 Player Settings 的 Scripting Define Symbols 添加该宏 |
| 误把 `GameApp.FUI` 当成 `UIComponent` | `FUI` 是 `FairyGUIComponent`,`UI` 才是 `UIComponent` | 区分两个 UI 子系统,通用 UI 用 `GameApp.UI`,引擎 UI 用 `GameApp.FUI`/`GameApp.GUI` |
| `GameApp.GameApp` 之类的重名误用 | 属性名是去掉 `Component` 后的名字,而不是组件原名 | 按"XxxComponent → Xxx"的规则写,如 `AssetComponent → Asset` |

## 背景

`GameApp` 用 C# `partial class` 分文件组织,每个组件对应一份 `GameApp.{Name}.cs`,内部用懒加载的静态字段缓存首次调用结果,后续访问直接返回缓存,避免重复查找。`FUI` 与 `GUI` 的简写是为兼容历史代码与缩短 UI 调用路径而保留,新代码若不需要区分引擎方案,优先使用通用 `GameApp.UI`(`UIComponent`)。
