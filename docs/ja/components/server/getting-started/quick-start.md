# クイックスタート:GameFrameX サーバーをゼロから起動する

このページでは、最小限の手順で GameFrameX Server を起動する方法を説明します:.NET 10 と MongoDB を準備し、起動方法(Docker / コマンドライン / Rider / Visual Studio)のいずれかを選択し、ヘルスチェックとテストインターフェースが正常に返ってくれば起動成功と見なします。

## 前提条件

| 依存関係 | バージョン要件 |
| :--- | :--- |
| [.NET SDK](https://dotnet.microsoft.com/download) | 10.0+ |
| [MongoDB](https://www.mongodb.com/try/download/community) | 4.x+ |
| IDE(任意) | Visual Studio 2022 / JetBrains Rider / VS Code |
| Docker(任意) | ワンクリック起動またはローカルで MongoDB を起動するために使用 |

ソースコードのルートディレクトリは [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L1-L150) を参照してください。

## 操作手順

### 方法 1:Docker ワンクリック起動

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
docker compose up -d --build
```

ローカルに .NET 10 SDK をインストールしたくないユーザー向け;Compose は MongoDB とサーバーコンテナを同時に起動します。

### 方法 2:コマンドラインでローカル起動

1. MongoDB を単独で起動:

```bash
docker compose up -d mongodb
```

2. コンパイルして出力ディレクトリから Launcher を起動:

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
dotnet restore
dotnet build Server.sln
cd bin/app_debug
dotnet GameFrameX.Launcher.dll
```

`GameFrameX.Launcher.dll` はフレームワークのエントリアセンブリで、対応するプロジェクトファイルは [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L1-L41) を参照してください。そのうち `Debug` 構成の `OutputPath` は `bin\app_debug`、`Release` は `bin\app` です。

### 方法 3:JetBrains Rider でデバッグ

1. `Server.slnx` を開く;Rider のバージョンが `.slnx` をサポートしていない場合は、`Server.sln` を開いてください。
2. MongoDB を起動:`docker compose up -d mongodb`。
3. `GameFrameX.Launcher` に対して `.NET Project` 実行構成を作成または編集。
4. `Working directory` を `$SolutionDir$/bin/app_debug` に設定。
5. `Program arguments` は空のままにしておく(デフォルト構成は [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs) を参照)。
6. Debug をクリック。`bin/app_debug` が存在しない場合は、先に `dotnet build Server.sln` を実行してください。

### 方法 4:Visual Studio でデバッグ

1. `Server.slnx` を開く;Visual Studio のバージョンが `.slnx` をサポートしていない場合は、`Server.sln` を開いてください。
2. `GameFrameX.Launcher` をスタートアッププロジェクトに設定。
3. MongoDB を起動:`docker compose up -d mongodb`。
4. `Working directory` をソリューションディレクトリ下の `bin\app_debug` に設定。
5. `Command line arguments` は空のままにしておく。
6. F5 を押してデバッグを開始。初回デバッグ時に出力ディレクトリが存在しない場合は、まず Build Solution を実行してください。

## よくあるバリエーション

デフォルト構成(ポート、データベース接続など)を上書きする必要がある場合は、コマンドラインで起動パラメータを追加します:

```bash
dotnet GameFrameX.Launcher.dll \
    --ServerId=1000 \
    --ServerType=Game \
    --IsEnableTcp=true \
    --InnerPort=29100 \
    --MetricsPort=29090 \
    --IsEnableHttp=true \
    --HttpPort=28080 \
    --IsEnableWebSocket=true \
    --WsPort=29110 \
    --HttpIsDevelopment=true \
    --MinModuleId=10 \
    --MaxModuleId=9999 \
    --TagName=GameFrameX \
    --DataBaseUrl="mongodb://localhost:27017" \
    --DataBaseName=gameframex
```

| パラメータ | 意味 |
| :--- | :--- |
| `--ServerId` `--ServerType` | サーバーの一意な番号と種類(例:Game) |
| `--IsEnableTcp` `--InnerPort` | TCP 内部ネットワークポートの有効化 |
| `--IsEnableHttp` `--HttpPort` `--HttpIsDevelopment` | HTTP リスニングと開発モードかどうか |
| `--IsEnableWebSocket` `--WsPort` | WebSocket リスニングの有効化 |
| `--MetricsPort` | Prometheus メトリクスとヘルスチェック用ポート |
| `--MinModuleId` `--MaxModuleId` | 業務モジュール ID の範囲 |
| `--TagName` | 起動タグ。`AppStartUpGame` などのスターターへのルーティングに使用 |
| `--DataBaseUrl` `--DataBaseName` | MongoDB 接続文字列とデータベース名 |

ローカルデバッグ時は**パラメータを空のまま**にしておけばよく、デフォルト値は `GameFrameX.Launcher/StartUp/AppStartUpGame.cs` にあります。

## デプロイの検証

起動が成功したら、以下のエンドポイントでサービスが正常であることを確認してください:

| エンドポイント | アドレス | 説明 |
| :--- | :--- | :--- |
| ヘルスチェック | `http://localhost:29090/health` | サービスのヘルス状態 |
| メトリクス監視 | `http://localhost:29090/metrics` | Prometheus メトリクス |
| テストインターフェース | `http://localhost:28080/game/api/test` | HTTP 接続テスト |

いずれか 3 つの項目のいずれかが正常に返ってくれば、フレームワークが正しく起動したことを示します。

## よくあるエラー

| 症状 | 原因 | 修正 |
| :--- | :--- | :--- |
| 起動時に MongoDB 接続失敗と表示される | MongoDB が起動していない、または接続文字列とデータベース名が間違っている | 先に `docker compose up -d mongodb` を実行するか、`--DataBaseUrl` `--DataBaseName` を調整する |
| Rider / VS のデバッグで `bin/app_debug` が見つからない | 初回ビルドが実行されていない | 先に `dotnet build Server.sln` を実行し、その後デバッグを開始する |
| `Server.slnx` が開けない | IDE のバージョンが古い | 代わりに `Server.sln` を使用する |
| ポートが既に使用されている | デフォルトの 28080 / 29090 / 29100 / 29110 が既に使用されている | 「よくあるバリエーション」セクションを参照してパラメータで上書きする |
| HTTP テストインターフェースが 404 を返す | フレームワークで HTTP が有効になっていない、またはポート構成が競合している | `--IsEnableHttp=true --HttpPort=28080` がスターターと一致していることを確認する |

## 背景(任意)

GameFrameX Server は Actor モデルと状態/ロジック分離を採用しています:永続化データは `GameFrameX.Apps` に、業務ロジックは `GameFrameX.Hotfix` にあり、サービスを停止せずにホットリプレースが可能です。スターター `AppStartUpGame` は `[StartUpTag(GameServerConst.Game.Name)]` と `--TagName` パラメータをマッチングすることで、ネットワークプロトコル、コンポーネントプロキシ、設定表の装配を完了させます。ソースコードの構成についての詳細は [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L180-L260) を参照してください。
