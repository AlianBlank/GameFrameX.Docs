# 핫픽스 시작이 실패를 반환하면 어떻게 해야 하나요

`IHotfixLauncher.StartAsync`가 반환한 `HotfixLaunchResult`가 실패로 표시되거나, 시작 프로세스가 `ProcedureGameLauncherState`에서 `StartupFailedEventArgs`를 트리거하는 경우가 이 페이지에서 다루는 상황입니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `HotfixLaunchResult.IsSuccess == false`, 로그에서 어셈블리를 찾을 수 없다고 표시됨 | `StartupOptions.HotfixAssemblyName`이 실제 컴파일 결과물과 일치하지 않음 | Inspector 필드 값을 확인하고 빌드 스크립트가 출력한 dll과 일치하도록 보장 |
| `HotfixLaunchResult.IsSuccess == false`, 로그에서 진입 타입을 찾을 수 없다고 표시됨 | `HotfixEntryTypeName` 철자 또는 네임스페이스 오류 | 타입 전체 이름(네임스페이스 포함)을 확인하고 dll 디컴파일 결과와 대조 |
| `StartupFailedEventArgs` 수신 결과 `FailedProcedureName == "ProcedureGameLauncherState"` | 핫픽스 launcher가 예외를 throw하거나 실패를 반환함 | `IHotfixLauncher` 구현에서 try/catch를 사용하고 `ErrorMessage`를 채운 후 실패 결과 반환 |
| 프로세스가 `ProcedureGameLauncherState`에서 멈춰 진행되지 않음 | `IHotfixLauncher`가 BlackBoard에 주입되지 않음 | `StartupRunner` 호출 전에 `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, ...)` 실행 |
| `StartupFailedEventArgs`를 수신했지만 `ErrorMessage`가 빈 문자열임 | 비즈니스 구현이 규약대로 `ErrorMessage`를 채우지 않음 | launcher 실패 시 `HotfixLaunchResult.ErrorMessage`를 명시적으로 할당 |

`HotfixLaunchResult`와 `StartupFailedEventArgs`의 필드 정의는 아래 참조 표를 확인하세요.

## 수정 단계

### 1. StartupOptions 설정 확인

핫픽스 진입 3요소(어셈블리 이름 / 진입 타입 전체 이름 / 진입 메서드 이름)는 `StartupOptions`를 통해 주입되며, 한 항목이라도 일치하지 않으면 `StartAsync`는 실패를 반환합니다:

```csharp
// StartupOptions.cs의 기본값
public string HotfixAssemblyName = "Unity.Hotfix";
public string HotfixEntryTypeName = "Hotfix.HotfixLauncher";
public string HotfixEntryMethodName = "Run"; // StartupOptions.cs의 필드 선언 참조
```

`StartupOptions` 에셋에서 이 세 항목의 값이 핫픽스 프로젝트의 컴파일 출력 및 IL2CPP/HybridCLR 로드 목록과 일치하는지 확인하세요. Source: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L33-L40)

### 2. StartupFailedEventArgs 구독

시작 실패 이벤트를 구독하여 `ProcedureGameLauncherState`에서 발생한 실패 메시지를 플레이어에게 표시합니다:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(StartupFailedEventArgs.EventId, e =>
{
    var args = (StartupFailedEventArgs)e;
    // args.FailedProcedureName / args.FailedUrl / args.ErrorMessage
});
```

이벤트 트리거 위치는 `StartupProcedureUtility.NotifyFailure`에서 통일 호출되며, UI 안내 텍스트 외에 `StartupFailedEventArgs`를 한 번 더 fire합니다. Source: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L160-L170),[StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L40-L60)

### 3. IHotfixLauncher 구현이 구조화된 실패를 반환하도록 하기

`IHotfixLauncher` 계약은 **성공 또는 실패 모두 `HotfixLaunchResult`를 반환하며 예외를 throw하지 않는 것**으로 규정됩니다. 구현 측에서는 반드시 모든 예외를 catch한 후 `ErrorMessage`에 넣어야 합니다:

```csharp
public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    try
    {
        // 로드 + 리플렉션으로 진입 메서드 호출
        return HotfixLaunchResult.Success();
    }
    catch (Exception ex)
    {
        return HotfixLaunchResult.Failure(ex.Message);
    }
}
```

Source: [IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L8-L16),[HotfixLaunchResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/HotfixLaunchResult.cs#L1-L40)

### 4. IHotfixLauncher가 BlackBoard에 주입되었는지 확인

`ProcedureGameLauncherState`는 FSM BlackBoard를 통해 `IHotfixLauncher`를 읽습니다. 주입이 누락되면 프로세스가 해당 Procedure에서 멈춥니다. 주입 규약은 다음과 같습니다:

```csharp
// BlackBoardKeys에 정의된 상수
public const string StartupHotfixLauncher = "__startup_hotfix_launcher__";
```

시작기는 FSM을 생성할 때 반드시 `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, hotfixLauncher)`를 호출해야 합니다. Source: [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs#L19-L23),[StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L80-L100)

| 타입 | 필드 / 멤버 | 설명 |
|------|-------------|------|
| `IHotfixLauncher.StartAsync(StartupOptions)` | `UniTask<HotfixLaunchResult>` 반환 | 핫픽스 로드 진입점, 성공/실패 모두 결과를 반환하며 예외를 throw하지 않음 |
| `HotfixLaunchResult.IsSuccess` | `bool` | true는 로드 및 시작 성공을 의미 |

| `HotfixLaunchResult.Success()` / `.Failure(msg)` | 정적 팩토리 | 성공 또는 실패 결과 생성 |

## 검증

위 수정을 완료한 후 항목별로 확인하세요:

1. `HotfixLaunchResult.IsSuccess == true`이며 `ErrorMessage`가 비어 있음.
2. `StartupFailedEventArgs`가 더 이상 트리거되지 않음(또는 `FailedProcedureName`이 다른 고장 지점으로 바뀌어 더 이상 `ProcedureGameLauncherState`가 아님).
3. 이후 프로세스가 게임 메인 씬으로 진행되고 `StartupCompletedEventArgs`가 정상적으로 fire됨.
