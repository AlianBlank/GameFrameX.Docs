# What to Do When Configuration Loading Fails

When `m_SettingManager.Load()` returns `false` in `SettingComponent.Start()`, the console outputs `Load settings failure.`, indicating that the configuration loading process has failed. This page helps you quickly locate the cause of the failure and fix it.

## Quick Diagnosis

| Symptom (Log Text) | Cause | Fix |
|------|------|------|
| `Setting manager is invalid.` | `ISettingManager` module is not registered, or GameFramework has not started | See [Module Not Registered](#module-not-registered-setting-manager-is-invalid) |
| `Can not create setting helper.` | `SettingHelper` type name is misconfigured, the assembly is not included in the runtime, or the custom Helper class cannot be found | See [Helper Creation Failure](#helper-creation-failure-can-not-create-setting-helper) |
| `Load settings failure.` | `ISettingHelper.Load()` implementation returns `false` (read/deserialization failure) | See [Load Implementation Returns false](#load-implementation-returns-false-load-settings-failure) |
| `Setting helper is invalid.` exception | `SetSettingHelper()` was not called before invoking `Load()` / `Save()` | See [Helper Not Set Throws Exception](#helper-not-set-throws-exception-setting-helper-is-invalid) |
| No data in platform mini-game storage | PlayerPrefs / mini-game storage backend is empty, no loadable content | See [Storage Backend Empty](#storage-backend-empty) |

## Module Not Registered (Setting manager is invalid)

`SettingComponent.Awake()` retrieves the manager via `GameFrameworkEntry.GetModule<ISettingManager>()`. If it returns `null`, `Setting manager is invalid.` is printed and the method returns directly; subsequent `Start()` will no longer trigger Load.

Fix steps:

1. Confirm that `GameFrameX.Runtime.GameFrameworkEntry` (or its equivalent startup component) exists in the scene, and the framework entry must start before `SettingComponent`.
2. Confirm that the `SettingManager` module is in the framework's assembly list (it is located at `Runtime/Setting/Setting/SettingManager.cs`, namespace `GameFrameX.Setting.Runtime`), and has not been excluded from the build.
3. If you use a custom GameFramework startup process, you need to add `SettingManager` to the startup module list.

## Helper Creation Failure (Can not create setting helper)

`SettingComponent.Awake()` calls `Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper)`; if it returns `null`, `Can not create setting helper.` is printed.

```csharp
// Source: Runtime/Setting/SettingComponent.cs#L87-L92
SettingHelperBase settingHelper = Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper);
if (settingHelper == null)
{
    Log.Error("Can not create setting helper.");
    return;
}
```

Fix steps:

1. Check the `Setting Helper Type Name` of `SettingComponent` in the Inspector; the default value is `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`.
2. If you use a custom Helper, confirm that the custom class inherits from `SettingHelperBase` (`Runtime/Setting/SettingHelperBase.cs#L43`), and the fully qualified type name (including namespace) is spelled correctly.
3. Confirm that the assembly containing the custom Helper is included in the Player / mini-game runtime build and has not been stripped.
4. If you switch to injecting via the `m_CustomSettingHelper` field, drag it onto the Inspector and ensure there is only one `SettingComponent` in the scene.

## Load Implementation Returns false (Load settings failure)

When the Helper is created successfully but the internal `Load()` fails, `SettingComponent.Start()` prints `Load settings failure.`:

```csharp
// Source: Runtime/Setting/SettingComponent.cs#L102-L108
private void Start()
{
    if (!m_SettingManager.Load())
    {
        Log.Error("Load settings failure.");
    }
}
```

`SettingManager.Load()` internally only delegates to the current Helper:

```csharp
// Source: Runtime/Setting/Setting/SettingManager.cs#L145-L150
public bool Load()
{
    EnsureSettingHelper();
    return m_SettingHelper.Load();
}
```

Handle by Helper type:

- **PlayerPrefsSettingHelper**: `Load()` always returns `true` ([source](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L86-L89)). If you see this error, first confirm that the Helper class actually in effect is not a custom implementation.
- **Custom Helper**: In `Load()`, troubleshoot one by one whether the file exists, read permissions, and deserialization exceptions; it is recommended to add detailed logs to confirm the failing step.
- **Mini-game platform Helper** (WeChat / DouYin / KuaiShou / Alipay): Obtain `ISettingStorageBackend` via `SettingStorageBackendFactory.Create()`, and confirm that the target platform macro is defined and the corresponding SDK is properly integrated.

## Helper Not Set Throws Exception (Setting helper is invalid)

`SettingManager` throws `GameFrameworkException("Setting helper is invalid.")` when `Load()` / `Save()` / `GetAllSettingNames()` is called without first calling `SetSettingHelper()`:

```csharp
// Source: Runtime/Setting/Setting/SettingManager.cs#L130
throw new GameFrameworkException("Setting helper is invalid.");
```

This may only be encountered when you bypass `SettingComponent` and directly `new SettingManager`. Fix: call `SetSettingHelper(yourHelper)` first, then call `Load()`; or directly use `SettingComponent`, which automatically injects it in `Awake()`.

## Storage Backend Empty

`PlayerPrefsSettingHelper` lazily loads `ISettingStorageBackend` via `SettingStorageBackendFactory.Create()`. If the factory returns `null` or the platform SDK is not initialized, calling `GetString` / `SetString` and other interfaces throws an exception, which is then propagated as `false` by `Load()` / `Save()`.

Fix steps:

1. Check whether the corresponding platform macro is enabled (`UNITY_WEBGL`, mini-game platform macros, etc.).
2. Confirm that the platform SDK has been initialized before `Awake()` / `Start()`.
3. Inject a test `ISettingStorageBackend` before `PlayerPrefsSettingHelper`; refer to the usage of `SetStorageBackendForTests(...)`.

## Verification

After completing the fix, verify in the following order:

1. Launch the game; the console no longer shows `Load settings failure.` or the error logs listed above.
2. Calling `SettingComponent.GetAllSettingNames()` returns normally (the PlayerPrefs implementation always returns an empty array, which is expected).
3. After using `SettingComponent.Save()`, restart the game, and calling `HasSetting(name)` / `GetString(name)` reads back the previously written values.
4. If the exception still persists, keep the complete stack trace and confirm that the issue is not in the specific class derived from `SettingHelperBase`.
