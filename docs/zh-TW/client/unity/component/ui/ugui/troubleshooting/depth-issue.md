# 當 UI 圖層/深度出現異常時

UI 圖層/深度異常通常表現為：開啟新 UI 時被先前的 UI 遮擋、同一 UI 群組內多個 UI 互相交錯顯示、模態彈窗穿透下層、3D 場景物件穿透到 UI 上方。本文件將依症狀引導診斷與修正方法。

## 快速診斷

| 症狀 | 原因 | 修正 |
|------|------|------|
| 新開啟的 UI 被先前的 UI 遮擋而看不見 | 將新 UI 加入 UI 群組時，群組深度 `Depth` 未變更，Camera 在 `ScreenSpaceCamera` 模式下被先前的群組遮擋 | 請參考下方「深度值未生效」 |
| 同一群組內多個 UI 互相交錯，圖層關係錯亂 | UGUI 使用 `localPosition.z = depth * 1000` 作為偽深度，但 Prefab 的 `localPosition.z` 被任意修改導致 UI 錯位 | 請參考下方「UI Z 值被錯誤修改」 |
| 3D 場景物件穿透顯示在 UI 上方 | UI 攝影機的 `clearFlags` 與 `cullingMask` 設定錯誤，3D 物件被渲染至 UI 圖層 | 請參考下方「3D 物件穿透 UI 的問題」 |
| 彈窗的點擊事件穿透至下層 UI | 根 `Canvas` 的 `overrideSorting`/`sortingOrder` 與 `GraphicRaycaster` 受損 | 請參考下方「射線穿透下層」 |
| 開啟第一個 UI 後，出現 `UGUI runtime root is invalid.` 錯誤 | `UI` 圖層不存在，導致 `LayerMask.NameToLayer("UI")` 回傳 `-1` | 請參考下方「UI 圖層缺失」 |
| 關閉同一 UI 後再次開啟，圖層順序改變 | UI 群組內 UI 的順序由 Hierarchy 的兄弟索引決定，卻被其他系統變更 | 請參考下方「兄弟索引被變更」 |

## 修正步驟

### 深度值未生效

`UGUIUIGroupHelper.SetDepth` 是套用圖層的唯一進入點，其簽章如下：

```csharp
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

Source: [UGUIUIGroupHelper.cs#L66-L70](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

檢查要點：

1. 確認在呼叫 `UIComponent.AddUIGroup` 後框架會呼叫 `SetDepth`,且業務層不應手動設定 `localPosition.z`。若業務層將 `localPosition.z` 重新設回 `0`,圖層就會還原。
2. 確認根 `Canvas` 為 `ScreenSpaceCamera` 模式，且根攝影機的 `depth` 不得小於場景中其他攝影機的 `depth`(框架預設值為 `uiCamera.depth = 10f`)。

### UI Z 值被錯誤修改

UI 掛載至 UI 群組節點後，該節點的 `localPosition.z` 會被框架強制寫入為 `depth * 1000`。Prefab 中設定的所有 `localPosition.z` 都會在執行階段被覆寫。反之，若業務層在 `OnOpen`/`OnShow` 中將此值重新寫回 `0`,就會出現「時對時錯」的閃爍現象。

正確做法：請勿在 UI 腳本中更動 `transform.localPosition.z`;若需要「圖層內的進一步分類」，請使用子節點或新增 UI 群組，切勿變更 Z 值。

### 3D 物件穿透 UI 的問題

UI 攝影機在框架初始化時會進行以下設定：

```csharp
uiCamera.clearFlags = CameraClearFlags.Depth;
uiCamera.cullingMask = uiLayer >= 0 ? 1 << uiLayer : uiCamera.cullingMask;
```

Source: [UGUIUIGroupHelper.cs#L159-L165](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L159-L165)

若場景中的 3D 物件出現在 UI 上方，通常是下列原因：

- 3D 物件所在的圖層與 UI 圖層同名或衝突，被錯誤地納入 `cullingMask`。
- 3D 攝影機的 `depth` 大於 UI 攝影機的 `depth`(預設值 `10f`),因此 3D 物件較晚繪製，但深度未以 `clearFlags.Depth` 清除，而出現「疊加」。

處理方式：請將 3D 物件置於獨立的圖層(例如 `Default`),切勿重複使用 `UI` 圖層。

### 射線穿透下層

`EnsureCanvas` 中會明確啟用以下項目：

```csharp
canvas.overrideSorting = true;
canvas.sortingOrder = 0;
canvasObject.GetOrAddComponent<GraphicRaycaster>();
```

Source: [UGUIUIGroupHelper.cs#L199-L212](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L199-L212)

若在 Inspector 中手動刪除 `GraphicRaycaster` 或關閉 `overrideSorting`,就會出現「看得到但無法點擊」或「點到下層圖層」的現象。建議將根 Canvas 視為唯讀，圖層問題請透過新增 UI 群組或子 Canvas 來解決。

### UI 圖層缺失

`UGUIUIGroupHelper` 在整個流程中依賴 `LayerMask.NameToLayer("UI")`;若專案中沒有名為 `UI` 的 Tag/Layer,將觸發所有相關的 `Log.Error`,且圖層與遮罩關係全部失效。

修正方式：請在 `Edit ▸ Project Settings ▸ Tags and Layers` 中新增 `UI` 圖層(建議為第 5 層)，並保持名稱為 `UI`。

### 兄弟索引被變更

UI 群組內的多個 UI 在 Hierarchy 中以兄弟節點形式存在，後開啟者會顯示在上方。若呼叫端使用 `transform.SetSiblingIndex`、`SetAsLastSibling` 等方法將特定彈窗「推到後面」，就會發生圖層閃爍。

建議事項：UI 圖層僅以 `Depth`(UI 群組)控制，請勿在 UI 腳本中變更兄弟索引。

## 驗證

修正完成後，請依以下順序驗證：

1. 連續開啟分屬 3 個不同 UI 群組的 UI,後開啟者應顯示在先開啟者之上。
2. 開啟同一群組內的 2 個 UI,後開啟者應在上方，且彼此不會互相穿透。
3. 開啟全螢幕模態彈窗，點擊彈窗外的空白處不應觸發下層按鈕。
4. 在 Hierarchy 中選取根 `UGUICanvas`,確認子節點的 `localPosition.z` 依序為 `0`、`1000`、`2000`。
5. 在 Scene 檢視中切換至 UI 攝影機，確認 `cullingMask` 僅勾選 `UI` 圖層。
