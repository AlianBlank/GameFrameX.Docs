# Quick Start: Launch the GameFrameX Server from Scratch

This page walks you through getting the GameFrameX Server up and running with minimal steps: prepare .NET 10 and MongoDB, choose a launch method (Docker / command line / Rider / Visual Studio), and consider the startup successful once the health check and test endpoints return normal responses.

## Prerequisites

| Dependency | Version Requirement |
| :--- | :--- |
| [.NET SDK](https://dotnet.microsoft.com/download) | 10.0+ |
| [MongoDB](https://www.mongodb.com/try/download/community) | 4.x+ |
| IDE (optional) | Visual Studio 2022 / JetBrains Rider / VS Code |
| Docker (optional) | For one-click startup or spinning up MongoDB locally |

See [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L1-L150) for the source root directory.

## Steps

### Method 1: One-Click Docker Startup

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
docker compose up -d --build
```

Ideal for users who don't want to install the local .NET 10 SDK; Compose will spin up both MongoDB and the server containers.

### Method 2: Local Command-Line Startup

1. Start MongoDB separately:

```bash
docker compose up -d mongodb
```

2. Build and start the Launcher from the output directory:

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
dotnet restore
dotnet build Server.sln
cd bin/app_debug
dotnet GameFrameX.Launcher.dll
```

`GameFrameX.Launcher.dll` is the framework's entry assembly; see [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L1-L41) for the corresponding project file. In the `Debug` configuration, `OutputPath` is `bin\app_debug`; in `Release`, it is `bin\app`.

### Method 3: JetBrains Rider Debugging

1. Open `Server.slnx`; if your Rider version does not support `.slnx`, open `Server.sln` instead.
2. Start MongoDB: `docker compose up -d mongodb`.
3. Create or edit a `.NET Project` run configuration for `GameFrameX.Launcher`.
4. Set `Working directory` to `$SolutionDir$/bin/app_debug`.
5. Leave `Program arguments` empty (see [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs) for the default configuration).
6. Click Debug. If `bin/app_debug` does not exist, run `dotnet build Server.sln` first.

### Method 4: Visual Studio Debugging

1. Open `Server.slnx`; if your Visual Studio version does not support `.slnx`, open `Server.sln` instead.
2. Set `GameFrameX.Launcher` as the startup project.
3. Start MongoDB: `docker compose up -d mongodb`.
4. Set `Working directory` to `bin\app_debug` under the solution directory.
5. Leave `Command line arguments` empty.
6. Press F5 to start debugging. If the output directory does not exist before the first debug session, build the solution first.

## Common Variants

To override the default configuration (ports, database connection, etc.), append startup arguments on the command line:

```bash
dotnet GameFrameX.Launcher.dll \
    --ServerId=1000 \
    --ServerType=Game \
    --IsEnableTcp=true \
    --InnerPort=29100 \
    --MetricsPort=29090 \
    --IsEnableHttp=true \
    --HttpPort=28080 \
    --IsEnableWebSocket=true \
    --WsPort=29110 \
    --HttpIsDevelopment=true \
    --MinModuleId=10 \
    --MaxModuleId=9999 \
    --TagName=GameFrameX \
    --DataBaseUrl="mongodb://localhost:27017" \
    --DataBaseName=gameframex
```

| Parameter | Description |
| :--- | :--- |
| `--ServerId` `--ServerType` | Unique server ID and type (e.g., Game) |
| `--IsEnableTcp` `--InnerPort` | TCP internal port toggle |
| `--IsEnableHttp` `--HttpPort` `--HttpIsDevelopment` | HTTP listener and whether development mode is enabled |
| `--IsEnableWebSocket` `--WsPort` | WebSocket listener toggle |
| `--MetricsPort` | Prometheus metrics and health check port |
| `--MinModuleId` `--MaxModuleId` | Business module ID range |
| `--TagName` | Startup tag used to route to launchers such as `AppStartUpGame` |
| `--DataBaseUrl` `--DataBaseName` | MongoDB connection string and database name |

For local debugging, simply **leave the arguments empty**; the default values are in `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`.

## Verifying the Deployment

After a successful startup, confirm the service is healthy via the following endpoints:

| Endpoint | Address | Description |
| :--- | :--- | :--- |
| Health check | `http://localhost:29090/health` | Service health status |
| Metrics monitoring | `http://localhost:29090/metrics` | Prometheus metrics |
| Test endpoint | `http://localhost:28080/game/api/test` | HTTP connectivity test |

If any of the three returns a normal response, the framework has been launched correctly.

## Common Errors

| Symptom | Cause | Fix |
| :--- | :--- | :--- |
| Startup reports MongoDB connection failure | MongoDB not started, or wrong connection string/database name | Run `docker compose up -d mongodb` first, or adjust `--DataBaseUrl` `--DataBaseName` |
| Rider / VS debugging cannot find `bin/app_debug` | Initial build not executed | Run `dotnet build Server.sln` first, then start debugging |
| `Server.slnx` cannot be opened | IDE version too old | Use `Server.sln` instead |
| Port already in use | Default ports 28080 / 29090 / 29100 / 29110 are occupied | Override via arguments as described in the "Common Variants" section |
| HTTP test endpoint returns 404 | HTTP not enabled in the framework, or port configuration conflict | Confirm `--IsEnableHttp=true --HttpPort=28080` matches the launcher |

## Background (Optional)

GameFrameX Server adopts the Actor model with state/logic separation: persistent data lives in `GameFrameX.Apps`, while business logic lives in `GameFrameX.Hotfix`, allowing hot replacement without server downtime. The launcher `AppStartUpGame` is matched via `[StartUpTag(GameServerConst.Game.Name)]` and the `--TagName` argument, completing the assembly of network protocols, component proxies, and configuration tables. See [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L180-L260) for details on source code organization.
