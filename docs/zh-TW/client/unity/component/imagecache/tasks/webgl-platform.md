# WebGL 平台上的使用方法

在 WebGL 平台上使用 `ImageCacheComponent` 載入遠端圖片時，元件會自動切換至由瀏覽器管理的 `UnityRequestTexture` 通道，與本機磁碟快取相關的 API 會成為 no-op，因此無需撰寫額外的 WebGL 分支程式碼。

## 前置條件

- 已將 `GameFrameXImageCacheCroppingHelper` 與 `ImageCacheComponent` 加入場景或執行階段進入點。
- WebGL 建置已允許跨網域載入遠端圖片（伺服器會回傳 CORS 標頭，或已在 Player Settings 中設定 `Allow downloads over HTTP` / `Use default CORS`）。
- 遠端圖片 URL 必須以 `http://` 或 `https://` 開頭，元件會驗證該前綴。

## 操作步驟

1. 將 `ImageCacheComponent` 掛載到場景後，依照平常的方式呼叫 `LoadImageAsync`。在 WebGL 中，元件會呼叫 `LoadImageWebGLAsync` 並使用 `UnityRequestTexture`，由瀏覽器自身的 HTTP 快取負責管理。

   ```csharp
   using System.Threading;
   using System.Threading.Tasks;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   public class WebGLSample : MonoBehaviour
   {
       public ImageCacheComponent imageCache;

       public async Task<Sprite> LoadRemoteIcon(string url, CancellationToken ct = default)
       {
           Texture2D tex = await imageCache.LoadImageAsync(url, ct);
           if (tex == null)
           {
               Debug.LogWarning($"読み込み失敗：{url}");
               return null;
           }
           return Sprite.Create(tex, new Rect(0, 0, tex.width, tex.height), Vector2.one * 0.5f);
       }
   }
   ```

   來源：[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L115)

2. 在 WebGL 中，`IsCached`、`RemoveCache`、`ClearCache` 一律無法使用。前者在 WebGL 中一律回傳 `false`，後兩者則不直接支援磁碟快取。請在呼叫前先判斷平台，避免業務邏輯輸出誤導性的日誌。

   ```csharp
   if (Application.platform != RuntimePlatform.WebGLPlayer)
   {
       bool hit = imageCache.IsCached(url);
       // …僅在非 WebGL 平台時進行磁碟快取判斷
   }
   ```

   來源：[IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L28-L47)

3. 跨網域與 Mixed Content 的處理：瀏覽器預設禁止跨網域載入紋理。遠端伺服器必須回傳 `Access-Control-Allow-Origin`，或將圖片託管在相同網域。HTTPS 網站請使用 HTTPS 的圖片 URL，否則瀏覽器會封鎖請求。

4. 紋理的釋放：`UnityRequestTexture.GetContent` 回傳的 `Texture2D` 不會由框架自動銷毀。在元件卸載或場景切換時，請呼叫 `Object.Destroy(texture)`，以避免 VRAM 洩漏。

5. 取消權杖僅在非 WebGL 平台上有效。在 WebGL 中，傳入的 `CancellationToken` 會被忽略，因此請在 UI 層（例如：關閉面板時）直接丟棄回傳的 `Task`。

   來源：[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L66-L89)

## 常見變化

- **在編輯器中模擬 WebGL**：在 Editor 中執行時，仍會使用磁碟快取邏輯。若要驗證 WebGL 的行為，請從 `File → Build Settings → WebGL → Build And Run` 建置並除錯。
- **直接使用 UnityRequest**：若需要進度處理或自訂標頭，可以在 WebGL 分支中直接呼叫 `UnityRequestTexture.GetTexture`，無需經過 `ImageCacheComponent`。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| 出現 `url must start with http:// or https://.` 警告 | URL 缺少通訊協定標頭，或使用了相對路徑 | 補上 `https://` 前綴 |
| 瀏覽器回報 CORS / Mixed Content 錯誤 | 遠端伺服器未回傳 CORS 標頭，或通訊協定不一致 | 在伺服器加入 `Access-Control-Allow-Origin`，或以相同網域 / 相同協定託管資源 |
| 呼叫 `RemoveCache` / `ClearCache` 沒有效果 | WebGL 沒有磁碟快取 | 在業務層隱藏這兩個項目，改為交由瀏覽器自身的快取清除策略處理 |
| `IsCached` 一律回傳 `false` | 在 WebGL 中無法感知瀏覽器快取 | 直接呼叫 `LoadImageAsync`，將命中判斷交給瀏覽器 |
| 反覆切換場景導致 VRAM 增加 | WebGL 回傳的 `Texture2D` 未被釋放 | 在場景卸載 / 圖片替換之前呼叫 `Object.Destroy(texture)` |

## 背景（選用）

在非 WebGL 平台上，`ImageCacheComponent.Awake` 會透過 `IDownloadManager` 取得檔案，並以 URL 的 MD5 作為檔名儲存到磁碟。在 WebGL 中，由於 `#if !UNITY_WEBGL` 的整個程式碼區塊都會被移除，`IDownloadManager` 在 WebGL 中既不會被引用，也不會被注入。WebGL 平台僅依賴 `UnityEngine.Networking.UnityRequestTexture`，所有快取邏輯都由瀏覽器管理。因此，元件在 WebGL 中既不需要也無法介入磁碟。

關於相關元件的整體流程，請參閱 [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L1-L100)。
