# エンティティがライフサイクルメソッドをトリガーしない場合の対処方法

`ShowEntity` / `HideEntity` を呼び出した後、エンティティ内の `OnInit` / `OnShow` / `OnUpdate` / `OnHide` のいずれにも入らない場合、通常は `EntityLogicType` が正しく渡されていない、プレハブに同名のスクリプトが既にアタッチされている、または `EntityComponent` が初期化されていないことが原因です。このページでは「ログエラー → 根本原因 → ワンライン修正」の形式で素早く調べられます。

## クイック診断

| 症状(ログ/現象) | 根本原因 | 修正 |
|---|---|---|
| `Entity '{0}' OnInit userData is not ShowEntityInfo.` | `ShowEntity` 時に `ShowEntityInfo`(`EntityLogicType` を含む)が `userData` として渡されていない | `ShowEntity<T>` ジェネリックオーバーロードを使用するか、カスタム `userData` 内に `ShowEntityInfo` をラップする |
| `Entity logic type is invalid.` または `Entity '{0}' can not add entity logic.` | `ShowEntityInfo.EntityLogicType` が `null` である、またはその型が `EntityLogic` のサブクラスでない、`MonoBehaviour` でない | `EntityLogicType` に `EntityLogic` を継承した具象 `MonoBehaviour` サブクラスの `Type` を代入する |
| `Entity group is inconsistent for non-new-instance entity.` | 同じエンティティオブジェクトが異なる `EntityGroup` に再利用された | `ShowEntity` 時に最初と同じ `EntityGroup` を渡すか、オブジェクトプールを空にする |
| `Entity '{0}' On{Init/Show/Hide} with exception ...` | あなたの `OnInit/OnShow/OnHide` が例外をスローし、フレームワークの `try/catch` に飲み込まれた | オーバーライドしたメソッド内で自分で `try/catch` してデバッグし、まず `base.OnXxx(...)` が例外をスローしないことを確認する |
| プレハブに自分のスクリプトが既にアタッチされており、フレームワークが新しいものを追加していない | プレハブに同じ `EntityLogicType` のスクリプトが既に存在し、`Entity.OnInit` で再利用されたが、エントリロジックは別のスクリプトに書かれている | ビジネスロジックを `EntityLogic` を継承して実装し、別途 `MonoBehaviour` をアタッチしない |
| `OnUpdate` に入らない | `EntityLogic` の `enabled` が `OnRecycle` 内で `false` に設定され、再度 `ShowEntity` した後に復元されていない;または `HideEntity` 後にオブジェクトが回収された | サブクラス内で手動で `enabled = false` としない;`ShowEntity` が `OnInit` パスを通ることを確認し、オブジェクトプールをチェックする |

## 修正手順

### 1. ジェネリック `ShowEntity` を使ってフレームワークに `EntityLogicType` を自動注入させる

フレームワークは `Entity.OnInit` 内で `userData as ShowEntityInfo` の `EntityLogicType` フィールドを読み取ります([Entity.cs#L112-L124](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L112-L124))。最もエラーが起きにくい方法は、直接 `EntityComponent.ShowEntity<T>` を使うことです:

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;

// MyEntityLogic : EntityLogic であり、EntityId に対応するプレハブにアタッチされていると仮定
GameEntry.GetComponent<EntityComponent>()
    .ShowEntity<MyEntityLogic>(entityId, "Assets/Prefabs/MyEntity.prefab", "Default", userData);
```

出典:[Runtime/Entity/EntityComponent.cs#L48](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L48)

### 2. `EntityLogic` サブクラスが `MonoBehaviour` であり、型が追加可能であることを確認する

`Entity.OnInit` は `gameObject.AddComponent(entityLogicType)` によって注入します([Entity.cs#L141](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L141-L146))。したがって:

```csharp
using UnityEngine;
using GameFrameX.Entity.Runtime;

public sealed class MyEntityLogic : EntityLogic   // MonoBehaviour である必要がある
{
    protected internal override void OnInit(object userData)
    {
        base.OnInit(userData);
        // 初期化ロジック
    }

    protected internal override void OnShow(object userData)
    {
        base.OnShow(userData);
        // ShowEntity のたびにここに入る
    }

    protected internal override void OnHide(bool isShutdown, object userData)
    {
        base.OnHide(isShutdown, userData);
        // 非表示ロジック
    }

    protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(elapseSeconds, realElapseSeconds);
        // 毎フレームのロジック
    }
}
```

出典:[Runtime/Entity/EntityLogic.cs#L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L40)、[Runtime/Entity/EntityLogic.cs#L133](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L133)、[Runtime/Entity/EntityLogic.cs#L196](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L196)

注意:`EntityLogic` のライフサイクルメソッドはすべて `protected internal virtual` として宣言されており、`public` / `private` ではなく `override` でオーバーライドする必要があります。

### 3. `OnUpdate` がトリガーされない一般的な原因を調査する

`Entity.OnRecycle` は `m_EntityLogic.enabled = false` を呼び出します([Entity.cs#L173-L174](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L173-L174))。オブジェクトがオブジェクトプールから取り出され再度 `ShowEntity` されると、`Entity.OnInit` は `m_EntityLogic != null` かつ型が一致することを検出し、`enabled` を `true` にリセットするだけです([Entity.cs#L130](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L130-L131))。サブクラス内で手動で `enabled = false` と書くと、再利用時に `OnUpdate` が呼ばれなくなります——これを削除してください。

### 4. ログで呼び出しチェーンを検証する

以上がすべて正常でもメソッドに入らない場合は、各 `override` の最初の行に `Debug.Log` を追加し、`ShowEntity` の後 1 フレーム以内に `OnInit` / `OnShow` に到達するかを確認してください。注意：各異常ケースで `Entity` は `Log.Error` で具体的な原因を出力します([Entity.cs#L149-L156](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity.cs#L149-L156))。コードを見るより Console を確認する方が早いです。

## 検証

1. シーンを実行し、最初の `ShowEntity` の後に `OnInit` → `OnShow` の `Debug.Log` が表示され、その後毎フレーム `OnUpdate` に入ることを確認します。
2. `HideEntity` を呼び出すと、`OnHide` がトリガーされ、オブジェクトが依然としてオブジェクトプールに存在すること(シーンには見えないが、プールのカウントが +1)を確認します。
3. 同じ `EntityId` に対して再度 `ShowEntity` すると、`OnInit` ではなく `OnShow` のみがトリガーされること(非再利用の前提で)を確認します(この時はオブジェクトプールの再利用分岐を通ります)。
4. `OnInit/OnShow/OnHide` 内で一度 `Exception` をスローしてテストし、`Log.Error` のメッセージが診断表の 1 行目と一致することを確認します。

## 背景(オプション)

`Entity` は `MonoBehaviour` であり、`EntityLogic` のホストとして機能します:`ShowEntity` → リソース読み込み → `ShowEntityInfo.EntityLogicType` を通じてゲームオブジェクトに `AddComponent<EntityLogic>` し、その後順番に `OnInit` → `OnShow` → 毎フレーム `OnUpdate` → `HideEntity` 時に `OnHide` → 回収時に `OnRecycle` がコールバックされます。よくあるエラー箇所は `EntityLogicType` という 1 つのパラメータに集中しており、ジェネリック `ShowEntity<T>` がすでに処理してくれています。
