# 导出脚本运行报错怎么办

执行仓库内置的 `Proto2CsExport*.bat`、`Proto2CsExport*.sh`、`Proto2CppExport*.bat` 等导出脚本时,如果命令立即退出、抛异常或没有生成代码,通常是参数、运行时或路径问题。本页按报错症状给出定位与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `dotnet: command not found` 或 `'dotnet' 不是内部或外部命令` | 当前终端未安装或未配置 .NET SDK | 安装 .NET SDK 后重新执行,见 [修复 1](#修复-1补全-dotnet-运行环境) |
| `Could not load file or assembly 'ProtoExport.dll'` / `找不到 ProtoExport.dll` | 脚本里的相对路径 `./Tools/ProtoExport.dll` 找不到产物 | 确认 `Tools/ProtoExport.dll` 存在,见 [修复 2](#修复-2补全-toolsprotoexportdll) |
| 退出码非 0,日志含 `proto file parse error` / `--inputPath` 相关 | `--inputPath` 指向的目录里没有 `.proto` 文件 | 把工作目录切换到 `*.proto` 所在目录,见 [修复 3](#修复-3确认-inputpath-指向-proto-目录) |
| 退出码非 0,日志含 `cannot write file` / 目标目录拒绝访问 | `--outputPath` 路径不存在、只读或被占用 | 检查目标目录并关闭占用进程,见 [修复 4](#修复-4确认-outputpath-可写) |
| 期望生成多种语言(同时导出 Unity 客户端、Unreal 服务端等),只生成了其中一种 | 多个脚本需要分别执行 | 依次执行对应脚本或使用 `All` 汇总脚本,见 [修复 5](#修复-5按目标语言选择对应脚本) |

## 修复步骤

### 修复 1:补全 dotnet 运行环境

脚本通过 `dotnet ./Tools/ProtoExport.dll` 调用导出器,必须先具备 .NET SDK。

1. 在终端执行 `dotnet --info`,若提示找不到命令,前往微软官网安装 .NET SDK(仓库脚本未指定版本,使用当前 LTS 即可)。
2. 重新打开终端,再次执行 `dotnet --version`,确认能输出版本号。
3. 在仓库根目录运行任一导出脚本,确认报错消失。

### 修复 2:补全 `Tools/ProtoExport.dll`

脚本通过相对路径 `./Tools/ProtoExport.dll` 加载导出程序集:

```bat
dotnet ./Tools/ProtoExport.dll --mode csharp --usingStatements "using System|using ProtoBuf|using System.Collections.Generic|using GameFrameX.Network.Runtime" --inputPath ./ --outputPath ../Unity/Assets/Hotfix/Proto --namespaceName Hotfix.Proto --isGenerateErrorCode true
```

Source: [Proto2CsExport_Client.bat](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Client.bat#L1-L1)

1. 确认当前所在目录是仓库根目录(脚本里写的是 `./Tools/...`)。
2. 确认 `Tools/ProtoExport.dll` 存在;若不存在,需先编译导出工具项目得到 `ProtoExport.dll` 后再放回 `Tools/`。
3. 重新执行脚本。

### 修复 3:确认 `--inputPath` 指向 `.proto` 目录

```bash
dotnet ./Tools/ProtoExport.dll  --mode csharp --usingStatements "using System|using ProtoBuf|using System.Collections.Generic|using GameFrameX.Network.Runtime" --inputPath ./ --outputPath ../Unity/Assets/Hotfix/Proto --namespaceName Hotfix.Proto --isGenerateErrorCode true
```

Source: [Proto2CsExport_Client.sh](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Client.sh#L3-L3)

1. 脚本默认 `--inputPath ./`,表示在当前目录读取 `.proto`。如果当前目录没有 `.proto`,导出器会无可读输入。
2. 切到仓库根目录(含 `_-0120_Inner_Social.proto` 等源文件的目录)再执行脚本。
3. 如果你把 `.proto` 放到别处,改为 `--inputPath /绝对/路径/到/proto`。

### 修复 4:确认 `--outputPath` 可写

```bash
dotnet ./Tools/ProtoExport.dll  --mode cpp --usingStatements "#include <cstdint>|#include <string>|#include <vector>|#include <unordered_map>" --inputPath ./ --outputPath ../Unreal/Source/Proto --namespaceName GameFrameX.Proto --isGenerateErrorCode true
```

Source: [Proto2CppExport.sh](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CppExport.sh#L3-L3)

1. C# 客户端脚本默认输出到 `../Unity/Assets/Hotfix/Proto`,C++ 脚本默认输出到 `../Unreal/Source/Proto`。相对路径基于执行目录,**先确认 `../Unity/...` 或 `../Unreal/...` 已存在且有写权限**。
2. 若 Unity/Unreal 工程尚未克隆,把 `--outputPath` 改为一个本地测试目录验证脚本本身能否跑通。
3. Windows 下若输出目录被 IDE 占用,关闭 Unity / Unreal Editor 后重试。

### 修复 5:按目标语言选择对应脚本

仓库内置脚本按语言和用途拆分:

| 脚本 | 用途 | 关键参数 |
|------|------|---------|
| `Proto2CsExport_Client.bat` / `.sh` | 生成 Unity 客户端 C# 代码 | `--mode csharp` `--namespaceName Hotfix.Proto` |
| `Proto2CsExport_Server.bat` / `.sh` | 生成服务端 C# 代码 | `--mode csharp` `--namespaceName Hotfix.Proto` |
| `Proto2CsExport_All.bat` | 同时启动 Client + Server 脚本 | start 两条子命令 |
| `Proto2CsExport_All.bat` | 一次性导出两端 C# | — |
| `Proto2CppExport.bat` / `.sh` | 生成 Unreal C++ 代码 | `--mode cpp` `--namespaceName GameFrameX.Proto` |

```bat
@echo off
start Proto2CsExport_Client.bat
start Proto2CsExport_Server.bat
```

Source: [Proto2CsExport_All.bat](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_All.bat#L1-L2)

如果只想导出一端,直接跑对应的单脚本;如果想一次出两端,使用 `Proto2CsExport_All.bat`。## 验证

执行修复后,用以下方法确认导出脚本已恢复正常:

1. 命令退出码为 0,终端不再打印红色异常堆栈。
2. `--outputPath` 指向的目录里出现新生成的 `.cs` 或 `.h/.cpp` 文件,文件名与输入的 `.proto` 一一对应。
3. 用 `dotnet --info` / `dotnet --version` 仍能正常返回版本号,排除一次性环境问题。
4. 如果只是想知道脚本是否健康,可把 `--outputPath` 临时指向一个空目录,看到产物出现即视为成功。

## 常见错误

- **在错误的目录执行脚本**:`./Tools/ProtoExport.dll` 是相对路径,`cd` 到仓库根目录再运行,否则会报 `Could not load file or assembly`。
- **把脚本参数写到多行却忘了行尾反斜杠**:`.sh` 脚本里所有参数写在一行,用空格分隔;`.bat` 同理。手动改写时不要拆行。
- **重复指定 `--usingStatements`**:多个 using 仍写在同一个 `--usingStatements` 中,用 `|` 分隔,例如 `"using System|using ProtoBuf|using System.Collections.Generic|using GameFrameX.Network.Runtime"`,不要再额外加 `--using` 之类的同义参数(脚本未提供)。
- **只跑 `All` 脚本却缺一端输出**:`Proto2CsExport_All.bat` 用 `start` 并行启动两端,若任一端前置环境未就绪,该端仍会失败;请分别跑 `Client` 与 `Server` 脚本定位。
- **忘了 `--isGenerateErrorCode`**:脚本已默认开启,如果手动重写命令时漏掉,可能导致生成的 C# 代码缺少错误码相关类型。

## 背景(可选)

脚本只是把 `*.proto` 的扫描与代码生成工作交给 `Tools/ProtoExport.dll`(一个 .NET 命令行工具);所有真正的解析、模板渲染都在该 dll 内部完成。所以"脚本报错"多数是 dll 启动前的环境/路径问题,真正的协议解析报错通常出现在 dll 运行后输出的日志里。
