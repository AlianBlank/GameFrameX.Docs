# Troubleshooting

This document summarizes common issues and their solutions when using the Timer component.

## Overview

The Timer component is a timer functionality module provided by the GameFrameX framework, providing timed task, delayed execution, and frame update functionality for Unity projects. During use, users may encounter some issues, and this document provides detailed diagnosis and solutions.

## Common Issues and Solutions

### 1. Timer Not Executing

#### Symptoms
After adding a timed task, the callback function is never executed.

#### Possible Causes
- Timer component not correctly added to GameObject in the scene
- GameFramework framework not correctly initialized
- TimerManager module not registered

#### Solutions

**Check if component is added:**

```csharp
// Ensure TimerComponent exists in the scene
var timerComponent = FindObjectOfType<TimerComponent>();
if (timerComponent == null)
{
    Debug.LogError("TimerComponent not found, please add component first");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

**Check framework initialization:**
Ensure GameFramework framework is correctly initialized at game startup. TimerComponent obtains ITimerManager instance from GameFrameworkEntry in Awake():

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");
        return;
    }
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

### 2. Callback Function Parameter Issues

#### Symptoms
The parameter passed to the callback function is null, or the parameter cannot be obtained correctly.

#### Possible Causes
- callbackParam parameter not passed correctly
- Mistakenly used the single-parameter overload of AddOnce

#### Solutions

The Timer component's callback function signature is `Action<object>`, parameters are passed through callbackParam:

```csharp
// Correct way to pass parameters
timerComponent.Add(1.0f, 1, OnTimerComplete, "This is the data being passed");

// Callback function receives parameters
private void OnTimerComplete(object param)
{
    Debug.Log($"Timer completed, parameter: {param}");  // Output: Timer completed, parameter: This is the data being passed
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

### 3. Interval Time Unit Confusion

#### Symptoms
Timer execution interval does not match expectations, e.g., setting 1000 but executing multiple times per second.

#### Possible Causes
**Important: The Timer component's interval parameter unit is seconds, not milliseconds!**

There is an error in the README documentation; in actual code, interval is a float in seconds:

```csharp
// interval parameter unit is seconds
public void Add(float interval, int repeat, Action<object> callback, object callbackParam = null)
{
    _timerManager.Add(interval, repeat, callback, callbackParam);
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

#### Solutions

```csharp
// Incorrect: Interpreting 1000 as milliseconds
timerComponent.Add(1000f, 1, callback);  // Actually executes at 1000 second intervals

// Correct: Interpret interval as seconds
timerComponent.Add(1.0f, 1, callback);  // Execute once after 1 second
timerComponent.Add(0.5f, 5, callback); // Execute once every 0.5 seconds, 5 times total

// Correct way to convert milliseconds
float intervalInSeconds = 1000f / 1000f;  // 1000 milliseconds = 1 second
timerComponent.AddOnce(intervalInSeconds, callback);
```

### 4. Duplicate Timed Task Addition

#### Symptoms
After calling Add method multiple times with the same callback, timer behavior becomes abnormal.

#### Possible Causes
TimerManager uses callback function as the dictionary key. When adding a timer with the same callback, it updates the existing timer instead of creating a new one:

```csharp
// Code implementation: If callback already exists, update existing timer
if (_items.TryGetValue(callback, out var t))
{
    t.Set(interval, repeat, callback, callbackParam);
    t.Elapsed = 0;
    t.Deleted = false;
    return;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L173)

#### Solutions

Check if timer already exists before adding:

```csharp
// Check if timer exists
if (!timerComponent.Exists(MyCallback))
{
    timerComponent.Add(1.0f, 5, MyCallback);
}
else
{
    Debug.LogWarning("Timer already exists, please remove before adding");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 5. Timer Crash Caused by Callback Exception

#### Symptoms
After an exception occurs in a timer callback, the entire timer system stops working.

#### Possible Causes
By default, exceptions in callback functions interrupt timer execution.

#### Solutions

TimerManager provides `CatchCallbackExceptions` static property to control exception handling:

```csharp
// Enable exception catching to prevent callback exceptions from crashing the timer
TimerManager.CatchCallbackExceptions = true;

// Add timed task
timerComponent.Add(1.0f, 0, OnTimerTick);

// Even if an exception occurs in the callback, it will not terminate the timer
private void OnTimerTick(object param)
{
    // Code that may throw exceptions
    throw new Exception("Simulated exception");
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L41-L43)

When exception catching is enabled, exceptions are caught and warning logs are recorded, and the timer is marked as deleted:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        timerItem.Callback(timerItem.Param);
    }
    catch (Exception e)
    {
        timerItem.Deleted = true;
        Debug.LogWarning("Timer: timer(internal=" + timerItem.Interval + ", repeat=" + timerItem.Repeat + ") callback error > " + e.Message);
    }
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L86-L97)

### 6. Timer Memory Leak

#### Symptoms
Memory usage continues to grow after long runtime.

#### Possible Causes
- Timed task not correctly removed after completion
- Frame update tasks added with AddUpdate not manually removed

#### Solutions

**For timed tasks with limited repeats:**
Repeat = 0 means infinite repeat, Repeat > 0 auto-removes after specified number of executions:

```csharp
// Repeat = 0 repeats infinitely, requires manual removal
timerComponent.Add(1.0f, 0, repeatingCallback);

// Manually remove at appropriate time
timerComponent.Remove(repeatingCallback);

// Repeat > 0 auto-removes after specified executions
timerComponent.Add(1.0f, 5, limitedCallback);  // Auto-removes after 5 executions
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L73-L81)

**For frame update tasks (AddUpdate):**
AddUpdate essentially uses a repeating timer with an extremely small interval (0.001 seconds), must be manually removed:

```csharp
// Add frame update task
timerComponent.AddUpdate(OnUpdate);

// Remove when object is destroyed or no longer needed
timerComponent.Remove(OnUpdate);
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L206-L219)

### 7. Timer Precision Issues

#### Symptoms
Timer execution time is imprecise with significant errors.

#### Possible Causes
- Using an interval that is too small
- Unstable game frame rate
- Unity's time system changes when switching to background

#### Solutions

TimerManager uses `realElapseSeconds` (actual elapsed time) to calculate timers:

```csharp
// Internally uses realElapseSeconds to calculate elapsed time
timerItem.Elapsed += realElapseSeconds;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L63-L71)

**Optimization suggestions:**

```csharp
// Avoid using intervals that are too small
timerComponent.Add(0.0001f, 0, callback);  // May cause performance issues

// Recommended: Minimum interval should not be lower than 0.01 seconds (10 milliseconds)
timerComponent.Add(0.01f, 0, callback);

// For scenarios requiring higher precision, consider using Unity's Update or Coroutine
```

### 8. Using Timers in Coroutines

#### Symptoms
Timers created in coroutines behave abnormally.

#### Solutions

The Timer component can be used in coroutines, but lifecycle management should be noted:

```csharp
IEnumerator StartTimerInCoroutine()
{
    // Use timer in coroutine
    timerComponent.AddOnce(2.0f, OnDelayComplete, "Coroutine data");

    yield return new WaitForSeconds(2.0f);
    // Coroutine ends, but timer task may still be running
}

private void OnDelayComplete(object param)
{
    Debug.Log($"Delay complete: {param}");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L48-L51)

## Diagnostic Tools

### Checking Timer Status

Use Exists method to check if a timer exists:

```csharp
// Check if timer for specific callback exists
bool isRunning = timerComponent.Exists(MyCallback);

if (isRunning)
{
    Debug.Log("Timer is running");
}
else
{
    Debug.Log("Timer is not running or has completed");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### Listing All Active Timers

Since TimerManager uses a dictionary to store timers, you can extend to get the active timer list:

```csharp
// Note: TimerManager's _items field is private
// For debugging, enable log output
Debug.Log($"Current active timer count: {count}");
```

## Performance Considerations

### 1. Callback Function Delegate Creation

When adding a timer, avoid using anonymous lambda expressions as callbacks, as this creates new delegate instances, making it impossible to correctly remove timers:

```csharp
// Incorrect: Anonymous methods cannot be removed
timerComponent.Add(1.0f, 1, (param) => Debug.Log("test"));

// Correct: Use named methods
timerComponent.Add(1.0f, 1, OnTimerTick);

// Can be correctly removed later
timerComponent.Remove(OnTimerTick);

private void OnTimerTick(object param)
{
    Debug.Log("Timer tick");
}
```

### 2. Large Number of Timers

TimerManager uses dictionary and lock implementation; for thousands of simultaneous timers, there may be performance impact. Consider consolidating multiple timed tasks or using other management methods.
