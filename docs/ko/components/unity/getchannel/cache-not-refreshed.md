# 채널 설정을 수정한 후에도 여전히 이전 값이 읽힐 때 대처 방법

`application_config.txt`, AndroidManifest의 meta-data 또는 iOS의 Info.plist를 수정했는데도 `BlankGetChannel.GetChannelName()`이 여전히 이전 값을 반환한다면, 원인은 거의 대부분 두 가지입니다: 프로세스 내 정적 캐시 `ChannelCache`가 히트된 후 다시 읽지 않거나, 설정이 빌드 시점에 패키지에 이미 포함되어 빌드된 애플리케이션에는 디스크 파일 수정이 무효한 경우입니다.

## 빠른 진단

| Editor에서 파일을 수정하고 Play Mode를 재시작했는데도 여전히 이전 값 | Unity가 아직 해당 TextAsset을 다시 가져오지 않아 `Resources.Load`가 여전히 이전 리소스를 반환함 | Editor 창으로 전환하여 다시 가져오기가 완료될 때까지 기다리거나, 해당 파일을 우클릭하여 `Reimport` 실행 후 Play Mode에 진입 |

## 해결 단계

### 프로세스 내 캐시 비우기(가장 흔한 근본 원인)

`GetChannelName`이 가장 먼저 하는 일은 정적 캐시를 조회하는 것이며, 히트되면 즉시 반환하고 이후의 읽기 로직은 완전히 건너뜁니다:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
{
    if (ChannelCache.TryGetValue(channelKey, out var value))
    {
        return value;
    }

    string channelName = defaultValue;
    ...
    ChannelCache[channelKey] = channelName;
    return channelName;
}
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98-L141)

캐시 사전은 `private static readonly`이며, 저장소에는 캐시를 비우는 공개 API가 전혀 제공되지 않으므로 **런타임 중에는 갱신할 수 없고**, 정적 필드가 도메인/프로세스와 함께 재구성되도록 하는 수밖에 없습니다:

1. Editor에서: Play Mode 종료 → 컴파일/도메인 리로드 완료 대기 → Play Mode에 다시 진입한 후 읽기.
2. 실기기/독립 실행 버전: 애플리케이션 프로세스를 종료한 후 재시작(캐시 문제만 해결됨; 설정 자체가 패키지 내부에 있다면 아래 섹션에 따라 다시 빌드해야 함).

또한 한 가지 부작용에 유의하십시오: Editor/PC 분기에서는 첫 번째 읽기 시 `application_config.txt`의 **모든** `key=value`가 한 번에 캐시에 기록됩니다([BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L107-L121) 참조). 따라서 파일을 수정한 후 다른 channelKey로 조회하더라도 여전히 처음 로드 시점의 이전 내용을 받게 됩니다.

### Editor/PC/WebGL: Resources가 다시 로드되도록 하기

이러한 플랫폼에서는 `Resources.Load<TextAsset>("application_config")`, 즉 `Assets/Resources/application_config.txt`를 읽습니다:

1. 파일 경로가 `Assets/Resources/application_config.txt`인지 확인(확장자가 없어도 로드 가능하며, 내용은 행 단위 `key=value`).
2. 수정하여 저장한 후, Unity 창을 클릭하여 다시 가져오기를 트리거(또는 파일 우클릭 → `Reimport`).
3. '프로세스 내 캐시 비우기'에 따라 Play Mode를 재시작.
4. 이미 빌드된 패키지: 디스크에서 파일을 수정하는 것은 무효이며, 반드시 `Assets/Resources/application_config.txt`를 수정한 후 다시 빌드해야 합니다.

### Android: meta-data 수정 후 다시 빌드

Android 채널은 네이티브 클래스의 정적 호출에서 얻으며, 첫 번째 결과 역시 캐시에 들어갑니다:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

AndroidManifest.xml에서 해당 meta-data를 수정한 후, APK/AAB를 다시 빌드하여 덮어쓰기 설치해야 합니다; 프로세스 내에서 자동으로 갱신되지 않습니다.

### iOS: PostProcessBuild의 '건너뛰기 설정' 처리

iOS 빌드 후 처리는 Info.plist에 `channel` 키가 없을 때만 `default`를 기록하며, 기존 값이 있으면 바로 건너뜁니다:

```csharp
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

출처: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

채널 값을 변경하려면: Xcode 프로젝트의 Info.plist에서 `channel` 키를 직접 수정하거나 삭제한 후(삭제하면 이 처리 로직에 의해 다시 기록됨) 실기기로 다시 빌드하십시오. 또한 네이티브 계층의 기본 반환 값은 `unknown`이라는 점에 유의하십시오:

```objc
char * getChannelName(char * channel_name) {
    NSString* channel_name_String=  [NSString stringWithUTF8String:channel_name];
    NSString* File = [[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"];
    NSMutableDictionary* dict = [[NSMutableDictionary alloc] initWithContentsOfFile:File];
    NSString * channel_value =  [dict objectForKey:channel_name_String];
    if (channel_value != nil) {
        return StringToCharArray(channel_value);
    }
    channel_value = @"unknown";
    return StringToCharArray(channel_value);
}
```

출처: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

### 값이 잘리는 경우: 설정 행 형식 확인

파싱 로직은 각 행을 `=`로 분할한 후 두 번째 세그먼트만 취하고 `Trim()`을 적용합니다:

```csharp
var split = line.Split(new string[] { "=" }, StringSplitOptions.RemoveEmptyEntries);
if (split.Length > 1)
{
    var key = split[0].Trim();
    var channelValue = split[1].Trim();
    ChannelCache[key] = channelValue;
}
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120)

`channel=a=b`는 `a`로 파싱됩니다. 값에서 `=`를 제거하거나(또는 다른 구분 문자를 사용하는 인코딩 방식으로 변경한 후) '프로세스 내 캐시 비우기'에 따라 재시작한 뒤 다시 확인하십시오.

## 확인

1. 설정을 수정하고 Play Mode를 재시작 / 다시 빌드한 후 다음을 호출합니다:

```csharp
string channel = BlankGetChannel.GetChannelName();
string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

2. 반환 값이 설정 파일의 새 값과 일치하는지 확인합니다; iOS에서 키가 없을 때는 `unknown`이 관찰되어야 합니다(C# 기본 매개변수 `default`가 아님).
3. 여전히 이전 값이라면, 먼저 캐시가 비워지지 않았을 것을 의심하고(Play Mode / 프로세스 재시작), 다음으로 읽고 있는 설정이 생각한 것과 다를 가능성을 의심하십시오(Editor는 `Assets/Resources/application_config.txt` 확인, Android는 manifest meta-data 확인, iOS는 Info.plist 확인).
