# 實作遊戲房間(Room)模組

Room 模組負責管理伺服器上的房間清單、玩家加入/離開、斷線處理與房間定時維護。跟隨本頁步驟，你可以在既有 GameFrameX 專案中串接並擴展自己的 Room 業務。

## 前置條件

- 已完成 `GameFrameX.Server` 專案的本地建置與啟動。
- 已存在 Player 模組，Room 需要透過 `PlayerRoleId` 關聯玩家。
- 熟悉 Actor 模式：`RoomComponent` 綁定 `GlobalConst.ActorTypeServer`,請求透過 `ReqXxxHandler` 進入對應的 `RoomComponentAgent` 方法。

### 4. 實作建立/加入/離開請求

`RoomComponentAgent` 暴露 `OnCreateRoomAsync`、`OnJoinRoomAsync`、`OnLeaveRoomAsync` 等入口，完成校驗、狀態寫入與廣播。

```csharp
public async Task OnCreateRoomAsync(long roleId, ReqCreateRoom request, RespCreateRoom response)
{
    if (!CheckRoleId(roleId, response)) return;
    if (!TryGetRule(request.GameType, response, out var rule)) return;
    if (!TryResolvePlayerCount(request.MinPlayerCount, request.MaxPlayerCount,
            rule, response, out var min, out var max)) return;

    var now = TimerHelper.UnixTimeSeconds();
    var roomId = State.NextRoomId++;
    var room = new RoomState
    {
        RoomId = roomId,
        Name = string.IsNullOrWhiteSpace(request.Name) ? $"{rule.DefaultNamePrefix}{roomId}" : request.Name.Trim(),
        GameType = request.GameType,
        OwnerRoleId = roleId,
        Status = RoomStatus.Waiting,
        MinPlayerCount = min,
        MaxPlayerCount = max,
        Round = 1,
        CreatedTime = now,
        UpdatedTime = now,
    };
    room.PlayerIds.Add(roleId);
    State.Rooms[roomId] = room;
    State.PlayerRoomMap[roleId] = roomId;

    response.Room = await ToMessageAsync(room);
    await OwnerComponent.WriteStateAsync();
    await NotifyRoomChangedAsync(room, RoomChangeType.Created);
}
```

[Service]
public virtual Task MarkPlayerDisconnected(long roleId)
{
    if (roleId <= 0 || !TryGetActiveRoom(roleId, out _)) return Task.CompletedTask;
    State.DisconnectedPlayerTimeMap[roleId] = TimerHelper.UnixTimeSeconds();
    return OwnerComponent.WriteStateAsync();
}

## 常見變體

- 新增遊戲類型：在 `RoomRuleMap` 中追加條目，同時擴展 `GameType` 列舉與協定欄位。
- 房間觀戰：複用 `RoomState.PlayerIds` 之外的 `SpectatorIds` 清單，在 `OnJoinRoomAsync` 中依請求參數區分。
- 房主遷移:`LeaveRoom` 中偵測房主離開後，把 `OwnerRoleId` 轉移給清單中第一個仍在場的玩家。
- 私密房間：在 `RoomState` 增加 `PasswordHash` 欄位，`OnJoinRoomAsync` 入口處校驗。

## 常見錯誤

- 忘記呼叫 `OwnerComponent.WriteStateAsync()`:狀態只在記憶體生效，重啟後遺失。
- 在房間進入 `Playing` 後仍允許加入:`OnJoinRoomAsync` 已校驗 `Status` 只能在 `Waiting`/`Ready`,新增玩法時不要繞過這個判斷。
- 建立新房間前未關閉舊房間：必須先呼叫 `CloseRoomAsync(activeRoom, RoomChangeType.Closed)`,否則 `State.PlayerRoomMap` 會出現一對多映射。
- 斷線立即踢人：應只呼叫 `MarkPlayerDisconnected` 記錄時間，讓 `RoomMaintenanceTimer` 統一清理。

## 背景(選用)

`RoomComponent` 透過 Actor 模型綁定到伺服器實例，所有房間操作都進入同一個 Actor 的序列佇列，避免並行修改 `RoomListState`。`NotifyRoomChangedAsync` 走事件匯流排向訂閱者(大廳、聊天、好友)廣播；具體的事件類型由 `RoomChangeType` 列舉區分。
