# 빌드 산출물을 객체 스토리지에 업로드하는 방법

Unity 명령줄에서 객체 스토리지 관련 파라미터를 전달하면, 빌드 파이프라인이 패키징 후 로그, 리소스 또는 APK를 S3 호환 객체 스토리지(OSS/S3/COS 등)에 자동으로 업로드할 수 있습니다. 이 페이지에서는 본 저장소에서 제공하는 설정 스위치와 트리거 지점을 설명하여, 빌드 산출물을 원격 버킷으로 전송하는 데 도움을 드립니다.

## 사전 조건

- [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md)에 따라 `com.gameframex.unity.builder`를 Unity 프로젝트에 설치해야 합니다.
- `ObjectStorageUploadManager.UploadFile(string)`을 구현한 객체 스토리지 SDK 패키지를 도입해야 합니다(본 저장소는 컴파일 매크로 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`을 통해 연동되며, 해당 SDK를 도입하지 않으면 업로드 코드는 컴파일되지 않습니다).
- 객체 스토리지 버킷의 `Key`, `Secret`, `BucketName`, `EndPoint`(리전/Endpoint)를 준비해야 합니다.

## 작업 단계

1. 빌드 머신에서 객체 스토리지 파라미터를 준비합니다. 아래 네 개의 필드는 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40)에서 파싱됩니다:

   | 필드 | 의미 |
   |------|------|
   | `ObjectStorageKey` | 액세스 Key(계정 AccessKey) |
   | `ObjectStorageSecret` | 액세스 Secret |
   | `ObjectStorageBucketName` | 버킷(Bucket) 이름 |
   | `ObjectStorageEndPoint` | 버킷이 위치한 리전의 Endpoint |

2. Unity 명령줄에서 `-ObjectStorageKey`, `-ObjectStorageSecret`, `-ObjectStorageBucketName`, `-ObjectStorageEndPoint`을 통해 위 네 가지 값을 전달합니다. 빌드 스크립트는 `Builder.BuildParamsParse` 리플렉션을 통해 `_builderOptions`에 다시 채워 넣습니다.

3. 해당 업로드 스위치를 켭니다. 저장소는 서로 충돌하지 않는 세 개의 불리언 스위치를 제공하며, 자세한 내용은 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L62-L125)를 참조하세요:

   | 스위치 | 기본값 | 역할 |
   |------|--------|------|
   | `IsUploadLogFile` | `false` | 빌드 준비 단계에서 로그 업로드 |
   | `IsUploadAsset` | `false` | 빌드 리소스 후 에셋 패키지 업로드 |
   | `IsUploadApk` | `false` | APK 생성 후 설치 패키지 업로드 |

4. `BuildReady`를 예로 들면, 로그 업로드의 실제 트리거 코드는 [Builder.BuildReady.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49)에 있습니다:

   ```csharp
   AssetDatabase.Refresh();
   if (_builderOptions.IsUploadLogFile)
   {
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.UploadFile(_builderOptions.LogFilePath);
   #endif
   }
   ```

   Source: [Editor/Builder.BuildReady.cs#L43-L49](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49)

   `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 컴파일 심볼이 정의된 경우에만 `UploadFile` 호출이 빌드에 포함되며, 그렇지 않으면 해당 블록 전체가 전처리기에 의해 제거되어 작업은 오류를 발생시키지 않습니다.

5. 빌드를 트리거합니다. 아무 진입 명령이나 선택하여 스위치가 켜져 있는지 확인하세요:

   ```bash
   Unity -batchmode -quit -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildReady \
         -ObjectStorageKey <your-key> \
         -ObjectStorageSecret <your-secret> \
         -ObjectStorageBucketName <your-bucket> \
         -ObjectStorageEndPoint <your-endpoint> \
         -IsUploadLogFile true \
         -IsUploadAsset true \
         -IsUploadApk true \
         -logFile -
   ```

   파라미터는 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L127-L130)에서 리플렉션을 통해 모델에 기록되며, 로그에서 `ToString()`을 출력하여 검증할 수 있습니다.

## 일반적인 변형

- **로그만 업로드하고 싶을 때**: `-IsUploadLogFile true`만 전달하고, 나머지 두 업로드 스위치는 기본값 `false`로 유지합니다.
- **에셋 패키지만 업로드하고 싶을 때**: `BuildAsset` 파이프라인을 호출할 때 `-IsUploadAsset true`를 전달합니다.
- **APK만 업로드하고 싶을 때**: `BuildApk` 파이프라인을 호출할 때 `-IsUploadApk true`를 전달합니다.
- **환경별 격리**: 네 개의 스토리지 파라미터를 CI의 환경 변수에 넣은 뒤, 빌드 스크립트에서 다시 명령줄로 채워 넣습니다.

## 일반적인 오류

- **실행 시 "ObjectStorageUploadManager을(를) 찾을 수 없습니다"라는 오류 발생**: 본 저장소는 업로드 스위치만 보유하며, 실제 업로드 클래스는 외부 객체 스토리지 SDK에서 제공됩니다. `Packages/manifest.json`에 해당 구현 패키지를 설치하고, Player Settings의 `Scripting Define Symbols`에 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`을 추가해야 합니다. 그렇지 않으면 `#if` 분기가 제거됩니다.
- **버킷에 파일이 보이지 않을 때**: `ObjectStorageEndPoint`이(가) 버킷이 위치한 리전의 Endpoint인지(콘솔 도메인이 아닌지) 확인하고, 버킷의 ACL이 해당 Key의 쓰기를 허용하는지 확인하세요.
- **여러 빌드가 동시에 업로드되어 충돌 발생**: 빌드 번호 `BuildNumber`은(는) 원격 경로에参与(외부 SDK 내에서 조립)하며, 동시 실행 시나리오에서는 `BuildNumber`의 유일성을 보장해야 합니다.

## 배경(선택 사항)

저장소는 "스위치 + 컴파일 매크로"의 최소 결합으로 설계되었습니다. `BuilderOptions`은(는) 명령줄 파라미터를 모델로 전달하는 역할만 하며, `ObjectStorageUploadManager`을(를) 실제로 호출하는 위치는 `BuildReady`, `BuildAsset`, `BuildApk` 세 가지 파이프라인의 업로드 분기에만 나타납니다. `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`이(가) 정의되지 않은 경우 업로드 코드는 컴파일에 전혀 참여하지 않으므로, 객체 스토리지 의존성이 없는 프로젝트도 본 도구를 바로 사용할 수 있습니다.
