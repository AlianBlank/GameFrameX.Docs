# 如何使用工廠建立上傳管理器

使用 `ObjectStorageUploadFactory.Create<T>` 靜態方法，可以基於 `IObjectStorageUploadManager` 介面型別快速取得一個**已初始化**的上傳管理器實例，無需手動 `new` 和呼叫 `Init`。

## 前置條件

- 引用 `GameFrameX.ObjectStorage.Editor` 命名空間
- 已有一個實作 `IObjectStorageUploadManager` 介面的具體類別 `T`（可直接繼承 [BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)）
- 準備好物件儲存的 `accessKey`、`secretKey`、`bucketName`；若物件儲存需要自訂位址，再準備 `endpoint`

## 操作步驟

1. 引入命名空間。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L1-L25)

2. 呼叫 `Create<T>` 靜態工廠方法，傳入憑證並取得已初始化的管理器。

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create<MyObjectStorageUploadManager>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: null
   );
   ```

   工廠內部會執行兩步操作：

   ```csharp
   var manager = Activator.CreateInstance<T>();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   return manager;
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. （可選）設定上傳的目標路徑。

   ```csharp
   uploader.SetSavePath("assets/uploads/");
   ```

   Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9)

4. 呼叫上傳方法，上傳單一檔案或整個目錄。

   ```csharp
   bool ok = uploader.UploadFile("D:/build/asset.bundle");
   uploader.UploadDirectory("D:/build");
   ```

   Source: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L15-L21)

## 關鍵簽章速查

| 成員 | 簽章 | 說明 |
|------|------|------|
| `ObjectStorageUploadFactory.Create<T>` | `static IObjectStorageUploadManager Create<T>(string accessKey, string secretKey, string bucketName, string endpoint = null) where T : IObjectStorageUploadManager` | 透過 `Activator.CreateInstance<T>()` 建立實例並立即呼叫 `Init` |
| `IObjectStorageUploadManager.SetSavePath` | `void SetSavePath(string savePath)` | 設定上傳到物件儲存中的目標路徑（自動去除結尾分隔符號） |
| `IObjectStorageUploadManager.UploadFile` | `bool UploadFile(string localFilePathAndName)` | 上傳單一檔案，成功回傳 `true` |
| `IObjectStorageUploadManager.UploadDirectory` | `void UploadDirectory(string localDirectory)` | 上傳整個目錄 |

## 常見變體

- **不傳入 endpoint**：對於不需要位址的物件儲存，`endpoint` 留空即可。參數預設值為 `null`，無需明確傳入。
- **自訂實作類別**：若不直接繼承 [BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)，只要類別實作 `IObjectStorageUploadManager` 即可作為 `T` 傳入；需自行實作 `Init`、`UploadDirectoryInternal`、`UploadFileInternal`。

## 常見錯誤

- **未實作介面就傳入**：若 `T` 沒有實作 `IObjectStorageUploadManager`，編譯器會在 `where T : IObjectStorageUploadManager` 處直接產生錯誤。
- **重複初始化**：工廠已經呼叫過 `Init`，無需再手動呼叫一次，否則可能覆寫已設定的憑證。
- **`endpoint` 誤傳**：部分物件儲存使用 `endpoint` 串接請求位址，傳錯會導致上傳失敗；不需要時保持 `null`。

## 背景

工廠模式將「建立實例 + 初始化」封裝成一步，呼叫端只需關心傳入憑證與最終介面，避免直接依賴具體實作類別。關於整體架構，見《概述》。
