# What to Do About UI Layer/Depth Anomalies

UI layer/depth anomalies typically manifest as: a newly opened UI being covered by an older one, multiple UIs within the same UI group interleaving with each other, modal popups being penetrated by the underlying layer, or 3D scene objects showing through above the UI. This page provides diagnosis and fixes organized by symptom.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| A newly opened UI is covered by a previous UI and cannot be seen | When the new UI is added to a UI group, the group depth `Depth` does not change, and the Camera is occluded by an older group in `ScreenSpaceCamera` mode | See "Depth value not taking effect" below |
| Multiple UIs in the same group interleave with each other, with disordered layering | UGUI uses `localPosition.z = depth * 1000` as a pseudo-depth; manually modifying the prefab's `localPosition.z` misplaces the UI | See "UI Z value mistakenly modified" below |
| 3D scene objects show through above the UI | The UI camera's `clearFlags` and `cullingMask` are misconfigured, causing 3D objects to be rendered into the UI layer | See "3D objects penetrating the UI" below |
| Popup click events pass through to UIs below | The root `Canvas`'s `overrideSorting`/`sortingOrder` and `GraphicRaycaster` have been broken | See "Raycasts passing through to lower layers" below |
| After opening the first UI, the error `UGUI runtime root is invalid.` occurs | The `UI` Layer does not exist, so `LayerMask.NameToLayer("UI")` returns `-1` | See "UI Layer missing" below |
| After closing and reopening the same UI, the layer order changes | The order of UIs within a UI group is determined by sibling indices in the Hierarchy, which have been modified by another system | See "Sibling index modified" below |

## Fix Steps

### Depth value not taking effect

`UGUIUIGroupHelper.SetDepth` is the only entry point through which layering takes effect; its signature is as follows:

```csharp
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

Source: [UGUIUIGroupHelper.cs#L66-L70](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

Key points to check:

1. Confirm that the framework calls `SetDepth` after `UIComponent.AddUIGroup`, rather than the business layer manually setting `localPosition.z`. If the business layer changes `localPosition.z` back to `0`, the layering reverts to its original state.
2. Confirm that the root `Canvas` is in `ScreenSpaceCamera` mode and that the root camera's `depth` is not less than the `depth` of other cameras in the scene (the framework default is `uiCamera.depth = 10f`).

### UI Z value mistakenly modified

After a UI is attached to a UI group node, that node's `localPosition.z` is forcibly written by the framework as `depth * 1000`. Any `localPosition.z` set in the prefab will be overwritten at runtime; conversely, if the business layer writes this value back to `0` in `OnOpen`/`OnShow`, you will see flickering where the layering is "sometimes right, sometimes wrong."

Correct approach: do not touch `transform.localPosition.z` in UI scripts; when you need "sub-levels within a layer," use child nodes or add a new UI group instead of changing the Z value.

### 3D objects penetrating the UI

The UI camera is constructed as follows during framework initialization:

```csharp
uiCamera.clearFlags = CameraClearFlags.Depth;
uiCamera.cullingMask = uiLayer >= 0 ? 1 << uiLayer : uiCamera.cullingMask;
```

Source: [UGUIUIGroupHelper.cs#L159-L165](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L159-L165)

If 3D objects in the scene appear above the UI, it is usually because:

- The Layer of the 3D objects has the same name as / conflicts with the UI Layer, and is incorrectly included in the `cullingMask`.
- The 3D camera's `depth` is greater than the UI camera's `depth` (default `10f`), so the 3D objects are drawn later and "stack" on top because `clearFlags.Depth` does not clear the depth buffer.

Solution: put 3D objects on a separate Layer (e.g., `Default`), and do not reuse the `UI` Layer.

### Raycasts passing through to lower layers

`EnsureCanvas` explicitly enables:

```csharp
canvas.overrideSorting = true;
canvas.sortingOrder = 0;
canvasObject.GetOrAddComponent<GraphicRaycaster>();
```

Source: [UGUIUIGroupHelper.cs#L199-L212](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L199-L212)

If you manually delete the `GraphicRaycaster` in the Inspector, or turn off `overrideSorting`, you will get "visible but unclickable" behavior or "clicks hitting the layer below." It is recommended to treat the root Canvas as read-only and solve layering problems by creating a new UI group or a child Canvas.

### UI Layer missing

`UGUIUIGroupHelper` relies on `LayerMask.NameToLayer("UI")` throughout; if the project has no Tag/Layer named `UI`, all related `Log.Error` calls will be triggered, and all layering and masking relationships will fail.

Fix: add a `UI` Layer in `Edit ▸ Project Settings ▸ Tags and Layers` (layer 5 is recommended), keeping the name `UI`.

### Sibling index modified

Multiple UIs within a UI group exist as sibling nodes in the Hierarchy; the one opened later is displayed on top. If the caller uses methods such as `transform.SetSiblingIndex` or `SetAsLastSibling` to "push" a popup back down, layer flickering will occur.

Recommendation: control UI layering only with `Depth` (UI groups), and do not change sibling indices in UI scripts.

## Verification

After completing the fixes, verify in the following order:

1. Open 3 UIs from different UI groups in sequence; the one opened later should cover the earlier ones.
2. Open 2 UIs in the same group; the one opened later should be on top, and they should not penetrate each other.
3. Open a fullscreen modal popup; clicking the blank area outside the popup should not trigger buttons underneath.
4. Select the root `UGUICanvas` in the Hierarchy and confirm that the child nodes' `localPosition.z` values are `0`, `1000`, and `2000` in order.
5. Switch to the UI camera in the Scene view and confirm that the `cullingMask` has only the `UI` Layer checked.

For related entry points and extension points, see [UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs) and [UGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs).
