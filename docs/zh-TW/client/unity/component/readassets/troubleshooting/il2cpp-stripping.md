# IL2CPP 建置後 API 被裁剪時該怎麼辦

IL2CPP 後端會透過受管理位元組碼連結器(Unity Linker / IL2CPP 裁剪)剔除「未被程式碼直接參考」的型別與成員。如果在 IL2CPP 建置後呼叫本程式庫的 API 時出現 `MissingMethodException`、`NullReferenceException`,或發生「編輯器中正常但建置後不正常」的情況，即為裁剪所致。本頁提供快速診斷與修正方法。

## 快速診斷

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 編輯器 / Mono 建置一切正常，但 IL2CPP 建置後回報 `MissingMethodException: void BlankReadAssets::xxx` | 連結器剔除了透過反射 / 動態呼叫的進入點 | 確認相依套件的 `Runtime/link.xml` 已被納入；或在自訂呼叫點加上 `[Preserve]` |
| 呼叫 `BlankReadAssets.OpenRead` 之類的 API 回傳 `null` 或擲回 null 參考例外，但連結器未回報錯誤 | 命名空間 / 內部類別被剔除，導致實作分支淪為空殼 | 再次確認 `link.xml` 已涵蓋 `GameFrameX.ReadAssets.Runtime` 與 `GameFrameX.ReadAssets.Runtime.ZipArchive` 命名空間 |
| 建置後所有平台都正常，但 Android IL2CPP 的 StreamingAssets 讀取內容為空 | `ApkImpl` / `LooseFilesImpl` 實作類別被剔除，平台分支回退至無實作路徑 | 檢查是否啟用了 Managed Stripping;必要時在 Player Settings 中停用 Strip Engine Code,或新增 link.xml |

## 修正步驟

### 1. 確認相依套件中的 `link.xml` 存在，且會隨建置一併發佈

本儲存庫已在 `Runtime/link.xml` 中明確宣告要保留的組件與命名空間，Unity Linker 會在打包時自動套用：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="BlankReadAssets.Runtime" preserve="all">
        <namespace fullname="GameFrameX.ReadAssets.Runtime" preserve="all"/>
        <namespace fullname="GameFrameX.ReadAssets.Runtime.ZipArchive" preserve="all"/>
    </assembly>
</linker>
```

來源:[Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/link.xml#L1-L7)

確認方法：解壓縮 `.apk` / `.ipa` / 建置輸出，檢查在 `*_Data/Managed` 旁邊或 `Assets/` 底下是否找得到 `link.xml`,且內容包含 `BlankReadAssets.Runtime`。UPM 套件會透過 `package.json` 中的 `samples` 欄位或直接納入檔案的方式包含此檔案。

### 2. 檢查 Player Settings 中的 Strip 等級

`Project Settings → Player → Other Settings → Managed Stripping`:

| 等級 | 風險 | 建議 |
|------|------|------|
| Disabled | 不會被裁剪，但套件體積會變大 | 用於臨時驗證 |
| Low | 僅裁剪明顯未使用的程式碼 | 通常已足夠 |
| Medium / High | 反射與動態載入的程式碼可能被裁剪 | 必須搭配 `link.xml` |

如果你的專案將 Managed Stripping 設為 High,請接著進行步驟 3,在反射呼叫點加上 `[Preserve]`。

### 3. 公開 API 已內建 `[Preserve]`,新整合的程式碼也可用同樣方式標註

本程式庫所有公開 API 皆已加上 `[Preserve]` 標註。範例：

```csharp
[Preserve]
public static string Root
{
    get
    {
        EnsureInitialized();
        return BlankReadAssetsImpl.s_root;
    }
}

[Preserve]
public static void Initialize()
{
    BlankReadAssetsImpl.Initialize(Application.dataPath, Application.streamingAssetsPath);
    s_initialized = true;
}
```

來源:[Runtime/BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L37-L68)

當你的業務層透過反射呼叫本程式庫(例如 `Type.GetMethod("OpenRead")`)時，Unity Linker 看不見呼叫關係；請在進入點或包裝方法加上 `[Preserve]` 以保留：

```csharp
using UnityEngine.Scripting;

[Preserve]
public static Stream OpenAsset(string file)
{
    return BlankReadAssets.OpenRead(file);
}
```

### 4. 透過自訂 link.xml 作為後備(不建議作為唯一做法)

在專案的 `Assets/link.xml` 中附加一段內容，以保留間接使用的命名空間：

```xml
<linker>
    <assembly fullname="YourGame" preserve="all"/>
</linker>
```

這等同於「保留整個組件」；僅作為最後手段的後備方案，避免長期依賴。

## 驗證

完成修正後，請依以下順序驗證：

1. **以 IL2CPP 在本機重新打包**:`File → Build Settings → Player Settings → Other Settings → Configuration → Scripting Backend = IL2CPP`,然後再次 Build And Run(或 `Build`)。
2. **以 Release 建置重現**：編輯器的 IL2CPP 後端只有在打包後才會執行連結器，因此裁剪問題無法在編輯器中重現。
3. **檢查建置輸出中的剩餘符號**：使用 `il2cppdumper` / `ilspycmd` 反編譯 `il2cpp.so` 或 `*_Data/Managed` 中的中繼資料，確認 `BlankReadAssets` 型別與進入點仍然存在。
4. **加入日誌柵欄**：在呼叫前後各寫一行 `Debug.Log`,執行後檢查 logcat / Player.log,確認是否抵達進入點。若已抵達進入點但錯誤仍出現，問題就不是裁剪，而是執行階段邏輯。

## 背景說明(選用)

Unity Linker 預設依「直接程式碼參考」進行裁剪；跨組件反射、`Activator.CreateInstance` 以及依字串名稱查找型別，都會遺失其呼叫圖。本程式庫的 `Runtime/link.xml` 在打包時明確保留 `BlankReadAssets.Runtime` 組件與 `ZipArchive` 命名空間，與公開 API 上的 `[Preserve]` 屬性共同形成雙重保險；只要這兩者皆生效，IL2CPP 建置後 API 就不會被裁剪。
