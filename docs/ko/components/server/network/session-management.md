# 클라이언트 세션 관리(Session / 연결 끊김)

GameFrameX는 `Session`과 `SessionManager`를 통해 각 네트워크 연결의 세션 상태를 유지 관리하며, 로그인 후 캐릭터 바인딩, 중복 로그인 시 기존 접속 강제 종료, 연결 끊김 시 정리 등의 동작을 포함합니다. 이 페이지를 다 읽고 나면 로그인, 강제 종료, 접속 끊김 등의 시나리오에서 Session을 올바르게 읽고 쓸 수 있으며, `EventId.SessionRemove` 이벤트를 받아 로그아웃 마무리 처리를 할 수 있습니다.

## 사전 조건

- `GameFrameX.Apps.Common.Session` 네임스페이스를 이미 가져왔습니다(코드는 [Session.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs) 및 [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs)에 위치).
- 프레임워크의 `AppStartUp`으로 프로토콜에 연결했으며, `IAppSession`을 통해 연결 정보를 가져왔습니다.
- 플레이어 Actor가 `ActorManager`를 통해 등록되어 있습니다(그렇지 않으면 `GetByRoleId`가 null을 반환함).

## 작업 단계

### 1. 핸드셰이크/로그인 성공 후 Session 생성 및 등록

로그인 성공 시 `AppStartUp`이 `SessionManager.Add`를 호출하여 현재 연결을 전역 딕셔너리에 등록합니다. 하위 계층에서는 `SessionId`를 채널 데이터에 기록하여, 프로토콜 계층에서 콜백 발생 시 ID로 역조회할 수 있도록 합니다.

```csharp
using GameFrameX.Apps.Common.Session;

// netWorkChannel은 프로토콜 계층의 INetWorkChannel에서 가져온 것입니다
var session = new Session(sessionId, netWorkChannel);
SessionManager.Add(session);
```

출처: [SessionManager.cs#L186-L191](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L186-L191)

### 2. 로그인 성공 후 캐릭터 ID 및 서명 바인딩

`UpdateSession`을 통해 `roleId`와 `sign`을 현재 연결에 기록합니다. 해당 `roleId`가 이미 다른 기기에서 로그인 중이라면, 프레임워크는 이전 세션에 "계정이 다른 기기에서 로그인되었습니다" 알림을 전송하고 강제로 로그아웃시킵니다.

```csharp
SessionManager.UpdateSession(sessionId, roleId, sign);
```

내부 동작(소스 코드 발췌):

1. `GetByRoleId(roleId)`로 이전 세션을 찾습니다.
2. `RespPrompt { Type = 5, Content = "你的账号已在其他设备上登陆" }`를 구성하여 `oldSession.WriteAsync`로 전송합니다.
3. `oldSession.WorkChannel.ClearData()` + `Close()`를 호출하고, `Remove(oldSession.SessionId)`를 실행합니다.
4. 현재 세션에 대해 `SetPlayerId(roleId)` / `SetSign(sign)`를 호출합니다.

출처: [SessionManager.cs#L200-L229](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L200-L229)

### 3. Session을 통해 클라이언트에 메시지 회신

`Session.WriteAsync`는 하위 네트워크 채널에 전송을 위임하며, 오류 코드를 함께 첨부할 수 있습니다.

```csharp
var session = SessionManager.Get(sessionId);
if (session != null)
{
    await session.WriteAsync(messageObject, errorCode: 0);
}
```

출처: [Session.cs#L99-L105](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs#L99-L105)

### 4. 연결 끊김 감시(능동적 강제 종료 / 네트워크 접속 끊김)

연결 끊김은 `AppStartUp` 훅에서 일괄 처리되며, 소스 코드 예시(발췌):

```csharp
protected override async ValueTask OnDisconnected(IAppSession appSession, CloseEventArgs disconnectEventArgs)
{
    var session = SessionManager.Get(appSession.Id);
    if (session != null)
    {
        var roomAgent = await ActorManager.GetComponentAgent<RoomComponentAgent>();
        await roomAgent.MarkPlayerDisconnected(session.PlayerId);
    }
}
```

`RoomComponentAgent`에는 120초의 접속 끊김 유예 시간(`DisconnectedPlayerAutoLeaveSeconds`)이 마련되어 있으며, 시간 초과 시에만 실제로 방에서 퇴장시킵니다.

출처: [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76), [RoomComponentAgent.cs#L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L45)

### 5. SessionRemove 이벤트에 응답하여 로그아웃 마무리

`SessionManager`는 다음 세 가지 상황에서 `EventId.SessionRemove`(값=1000)를 발행합니다:

- `Remove(sessionId)`
- `KickOffLineByUserId(roleId)`
- `RemoveAll()`
- `UpdateSession` 중복 로그인 발생 시 이전 세션 제거

프레임워크는 `[Event(EventId.SessionRemove)]` 특성을 사용해 리스너를 플레이어 Agent에 바인딩하며, 기본 구현은 `agent.OnLogout()`을 호출합니다. 비즈니스에 맞게 확장할 수 있습니다:

```csharp
[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

출처: [SessionRemoveEventListener.cs#L39-L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L39-L45), [EventId.cs#L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Event/EventId.cs#L41)

## 일반적인 변형

### 캐릭터 ID로 능동적으로 강제 종료

```csharp
SessionManager.KickOffLineByUserId(roleId);
```

내부적으로 `SessionRemove`를 발행하여 `OnLogout`을 트리거합니다. 출처: [SessionManager.cs#L79-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L79-L89).

### 종료 시 모든 세션 정리

```csharp
await SessionManager.RemoveAll();
```

각 세션에 대해 `SessionRemove`를 발행한 후 딕셔너리를 `Clear()` 합니다. 출처: [SessionManager.cs#L158-L170](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L158-L170).

### 페이지네이션으로 온라인 플레이어 조회

`GetPageList(pageSize, pageIndex)`는 `ActorManager`에 더 이상 존재하지 않는 Actor를 필터링하여, 실제로 온라인인 플레이어만 반환합니다. 출처: [SessionManager.cs#L65-L73](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L65-L73).

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GetByRoleId(roleId)`가 항상 null을 반환함 | 플레이어 Actor가 등록되지 않았거나, `SessionMap`이 이미 비동기적으로 정리됨 | 로그인 흐름에서 `ActorManager`가 플레이어를 등록했는지 확인하고, 호출 측이 Session 수명 주기 내에 접근하도록 함 |
| 중복 로그인 알림 전송 후 이전 연결이 즉시 닫히지 않음 | `WriteAsync`만 호출하고 `WorkChannel.Close()`를 호출하지 않음 | 프레임워크 기본 제공 `SessionManager.UpdateSession` 흐름을 사용하고, 이전 세션을 직접 수동으로 관리하지 마세요 |
| 접속이 끊긴 플레이어가 자동으로 방을 나가지 않음 | `OnDisconnected`에서 `MarkPlayerDisconnected`를 호출하지 않음 | [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76) 템플릿을 참고하여 연결 끊김을 방 Agent로 전달 |

## 배경(선택 사항)

`SessionManager`는 `ConcurrentDictionary<string, Session>`을 전역 저장소로 사용하며, 연결마다 하나의 `SessionId`가 부여됩니다. `Session` 내부에는 데이터 송수신을 위한 `INetWorkChannel`을 보유하고 있습니다. `UpdateSession`의 "먼저 제거한 후 Disconnected 대기" 주석([L217](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L217))은 중복 로그인 시 연결 끊김 콜백에만 의존해 정리하면 지연이 발생하므로, 이전 항목을 동기적으로 `Remove`하여 상태 일관성을 보장한다는 것을 설명합니다.
