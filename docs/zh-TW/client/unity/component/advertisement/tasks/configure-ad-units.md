# 如何設定廣告單元 ID（多平台）

`AdvertisementComponent` 內建了 6 個平台的廣告單元 ID 欄位。在執行時，它會根據目前的建置平台自動選擇對應的 ID 並寫入 `AdUnitId`，無需撰寫分支程式碼。

## 前置條件

- 已安裝 `com.gameframex.unity.advertisement` 套件。
- 場景中已存在 `AdvertisementComponent`（透過選單 `GameFrameX/Advertisement` 新增）。
- 已選擇實作 `IAdvertisementManager` 的具體廣告管理器（於 Inspector 的 `Component Type` 欄位中指定）。

## 步驟

1. **開啟 AdvertisementComponent Inspector**
   在場景中選取掛載了 `AdvertisementComponent` 的 GameObject。Inspector 會依區段顯示三組欄位：「Debug Mode」、「Config」與「Ad Unit ID (Legacy)」。

2. **填入各平台的廣告單元 ID**
   在「Ad Unit ID (Legacy)」標題下，填入從各平台廣告後台取得的 ID：

   | Inspector 顯示名稱 | 序列化欄位 | 目標平台 |
   |------------------------|------------------|----------------|
   | Android 广告位ID | `m_adUnitIdAndroid` | `UNITY_ANDROID` |
   | IOS 广告位ID | `m_adUnitIdiOS` | `UNITY_IOS` |
   | WebGL 广告位ID | `m_adUnitIdWebGL` | 標準瀏覽器 `UNITY_WEBGL` |
   | WebGL 微信 广告位ID | `m_adUnitIdWebGLWeChat` | 微信小遊戲（巨集 `ENABLE_WECHAT_MINI_GAME`） |
   | WebGL 抖音 广告位ID | `m_adUnitIdWebGLDouYin` | 抖音小遊戲（巨集 `ENABLE_DOUYIN_MINI_GAME`） |
   | WebGL 快手 广告位ID | `m_adUnitIdWebGLKuaiShou` | 快手小遊戲（巨集 `ENABLE_KUAISHOU_MINI_GAME`） |

   這些欄位在原始碼中的定義可在 [AdvertisementComponent.cs#L47-L57](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57) 中查看，Inspector 顯示名稱則見於 [AdvertisementComponentInspector.cs#L26-L31](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L26-L31)。

3. **了解 ID 在執行時的選取方式**
   在 `Awake` 階段，元件會使用前處理器指令依平台選擇 ID，並將其寫入 `AdUnitId` 屬性：

   ```csharp
   AdUnitId =
   #if UNITY_WEBGL
   #if ENABLE_WECHAT_MINI_GAME
       m_adUnitIdWebGLWeChat
   #elif ENABLE_DOUYIN_MINI_GAME
       m_adUnitIdWebGLDouYin
   #elif ENABLE_KUAISHOU_MINI_GAME
       m_adUnitIdWebGLKuaiShou
   #else
       m_adUnitIdWebGL
   #endif
   #elif UNITY_ANDROID
       m_adUnitIdAndroid
   #elif UNITY_IOS
       m_adUnitIdiOS
   #else
       string.Empty
   #endif
       ;
   ```
   來源：[AdvertisementComponent.cs#L99-L117](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)

   選擇優先順序：WebGL 小遊戲巨集 → 一般 WebGL → Android → iOS。不符合的平台會回傳空字串。

4. **確認初始化時使用的設定物件**
   在元件的 `Start` 期間，若 `Config` 不為 null，則會呼叫 `IAdvertisementManager.Initialize(config)`（請參閱 [AdvertisementComponent.cs#L120-L126](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)）。各管理器實作會在內部從 `AdUnitId` 讀取具體的廣告單元 ID。

## 常見變化

- **透過程式碼在執行時指定 ID（已棄用）**  
  您可以呼叫 `Initialize(string adUnitId, bool isDebug = false)`，但此多載已標記為 `[Obsolete("Use Initialize(AdvertisementConfig) instead.")]`。新程式碼應改用 `Initialize(AdvertisementConfig)` 的設定物件方式。
- **分別設定不同的 WebGL 小遊戲渠道**  
  微信／抖音／快手的 ID 是獨立儲存的，因此無需在同一個字串中手動撰寫渠道前綴。只要在編譯時啟用對應的巨集，元件就會自動選取正確的 ID。
- **透過 `Config` 子類別攜帶廣告單元 ID**  
  當為 `Component Type` 選擇的管理器宣告了 `[AdvertisementConfigAttribute(typeof(YourConfig))]` 時，Inspector 會根據該 Config 型別動態渲染欄位（請參閱 [AdvertisementComponentInspector.cs#L127-L139](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L127-L139)）。您可以直接在 Config 子類別中新增平台欄位，以取代 6 個舊版的 `m_adUnitIdXxx` 欄位。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|---------|-------|-----|
| `AdUnitId` 為空字串 | 目前的建置平台沒有對應的 `#if` 分支（例如桌面版 Standalone） | 當桌面平台需要廣告時，在 Config 子類別中提供預設值，或在程式碼中手動設定 `AdUnitId` |
| 微信小遊戲讀取到 `WebGL 广告位ID` | 未啟用編譯巨集 `ENABLE_WECHAT_MINI_GAME` | 在「Project Settings → Player → WebGL → Publishing Settings」中啟用對應的小遊戲平台支援 |
| Inspector 中看不到 6 個廣告單元 ID 欄位 | 已在程式碼中透過 `HideInInspector` 或自訂編輯器隱藏 | 請確認您使用的是預設 Inspector `GameFrameX/Advertisement/AdvertisementComponentInspector` |
| 呼叫 `Initialize(string, bool)` 時出現警告 | 該多載已標記為 `[Obsolete]` | 改用 `Initialize(AdvertisementConfig)` 並將 ID 放入 Config 子類別 |

## 驗證

1. 在 Inspector 中為每個目標平台填入非空的 ID（自行檢查時可使用佔位字串）。
2. 切換 Build Target（Android、iOS、WebGL）並逐一建置。執行後，使用 `Debug.Log(adComponent.AdUnitId)` 檢查輸出是否符合該平台的 ID。
3. 針對 WebGL 小遊戲：請分別在微信開發者工具／抖音開發者工具中建置，以確認對應的巨集已啟用且讀取到正確的欄位值。

## 背景（選用）

`AdvertisementComponent` 將平台分支整合至單次 `Awake` 呼叫中，在執行時僅公開單一個 `AdUnitId` 值，以簡化下游廣告管理器處理 ID 的方式。`AdvertisementConfig` 基底類別僅公開 `isDebug`；平台專屬參數由各管理器在透過 `[AdvertisementConfigAttribute]` 指定的 Config 子類別中定義，並與這 6 個舊版平台欄位並存。
