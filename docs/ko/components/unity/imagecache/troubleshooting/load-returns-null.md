# 이미지 로드 시 null이 반환될 때怎么办

`LoadImageAsync`을 호출했는데 `null`이 반환되면 이미지 로드가 실패한 것입니다. 아래에서는 현상별로 흔한 원인,排查 방법 및 수정 단계를 정리합니다.

## 빠른 진단

| 증상 (로그 원문) | 원인 | 해결 방법 |
|------------------|------|------|
| `ImageCache: url is null or empty.` | 전달된 URL이 빈 문자열이거나 `null`임 | 호출 전에 URL을 확인하고 유효한 주소를 전달 |
| `ImageCache: url must start with http:// or https://. url: {0}` | URL이 `http://` 또는 `https://`로 시작하지 않음 | URL 프로토콜 헤더를 수정 |
| `ImageCache: download failed. url: {0}` | 원격 서버에 접근할 수 없거나, 404 또는 네트워크 제한 | 네트워크와 주소 확인, 자세한 내용은 아래 "다운로드 실패" 참조 |
| `Download manager is invalid.` (시작 시 치명적 로그) | `IDownloadManager` 모듈이 설치되지 않음 | `Download` 컴포넌트 등록 |
| `ImageCache manager is invalid.` (시작 시 치명적 로그) | 컴포넌트가 `GameFrameworkEntry`에 등록되지 않음 | 프레임워크 절차에 따라 컴포넌트 추가 |
| 로그가 전혀 없고 `null` 반환 | 캐시 파일이 손상됨 / `Texture2D.LoadImage` 실패 | 캐시를 정리한 후 재시도, 자세한 내용은 아래 참조 |

## 수정 단계

### URL이 유효하지 않음

URL이 비어 있거나 `http(s)://`로 시작하지 않으면 `LoadImageAsync`는 직접 `null`을 반환하고 해당 경고 로그를 출력합니다.

```csharp
// 错误写法
await component.LoadImageAsync(null);                 // 空
await component.LoadImageAsync("ftp://example.com/a.png"); // 错误协议
await component.LoadImageAsync("/local/path/a.png");   // 本地路径无效

// 正确写法
await component.LoadImageAsync("https://example.com/a.png");
```

출처: [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

### 시작 시 모듈 누락

`ImageCacheComponent.Awake`는 `IImageCacheManager`와 `IDownloadManager`를 가져오며, 둘 중 하나라도 누락되면 `Fatal` 로그를 기록하고 일찍 반환하여 이후의 모든 로드가 `null`이 됩니다.

```csharp
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
// ...
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
```

해결 방법:

1. 씬의 `GameFramework` 노드 아래에 `ImageCache` 컴포넌트를 추가합니다 (메뉴 `GameFrameX/Image Cache`).
2. 동시에 `Download` 컴포넌트를 추가하고, `Download Component` 필드가 `IDownloadManager`를 구현한 구체적인 클래스를 가리키도록 합니다.
3. 씬을 다시 시작하여 콘솔에 위의 `Fatal` 로그가 더 이상 나타나지 않는지 확인합니다.

출처: [ImageCacheComponent.cs#L37-L65](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L37-L65)

### 다운로드 실패

WebGL이 아닌 플랫폼에서 디스크에 캐시가 없으면 `IDownloadManager.AddDownload`을 호출합니다. 다운로드가 실패하면 `DownloadFailure` 이벤트가 트리거되고, 메서드는 `ImageCache: download failed. url: {0}`을 기록한 후 `null`을 반환합니다.

```csharp
private async Task<Texture2D> LoadImageDiskCacheAsync(string url, CancellationToken cancellationToken)
{
    // ...
    var downloadSuccess = await tcs.Task;
    if (!downloadSuccess)
    {
        Log.Warning("ImageCache: download failed. url: {0}", url);
        return null;
    }
    // ...
}
```

排查 순서:

1. 브라우저나 `curl`을 사용하여 해당 URL에 직접 접근하여 200이 반환되고 이미지 바이트 스트림이 반환되는지 확인합니다.
2. 런타임 샌드박스 권한을 확인합니다 (iOS ATS, Android 네트워크 권한, WebGL CORS).
3. WebGL 플랫폼에는 디스크 캐시가 없으므로 브라우저는 `UnityWebRequestTexture.GetTexture`을 사용하여 직접 가져오며, 실패 시 로그는 `ImageCache: download failed. url: {0}, error: {1}`입니다. — 크로스 도메인과 HTTPS 설정을 우선적으로 확인합니다.
4. 이미 다운로드된 적이 있는데 다시 실패하는 경우, `RemoveCache(url)`을 호출한 후 재시도합니다.

출처: [ImageCacheManager.cs#L97-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L97-L171)

### 캐시 파일 손상 / 디코딩 실패

다운로드가 성공했지만 후속 읽기 또는 디코딩이 실패하면 메서드는 조용히 `null`을 반환하며 전용 경고 로그는 출력되지 않습니다.

```csharp
var buffer = FileHelper.ReadAllBytes(cachePath);
if (buffer == null || buffer.Length == 0)
{
    return null;
}

var texture = new Texture2D(1, 1, TextureFormat.RGBA32, false, false);
if (!texture.LoadImage(buffer))
{
    Object.Destroy(texture);
    return null;
}
```

해결 방법:

1. `RemoveCache(url)` 또는 `ClearCache()`를 호출하여 로컬 캐시를 정리한 후 다시 로드합니다.
2. `CachePath`가 Inspector에서 쓰기 가능하고 디스크가 가득 차지 않았는지 확인합니다 (`MaxDiskSize`에 의해 회수될 때 오래된 파일이 지워질 수 있음).
3. 원격에서 반환되는 것이 HTML 오류 페이지가 아닌 PNG / JPG 바이트 스트림인지 확인합니다.

출처: [ImageCacheManager.cs#L152-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L152-L171)

### 취소 토큰 트리거

호출자가 전달한 `CancellationToken`이 취소를 트리거하면 메서드도 `null`을 반환하며 실패 로그를 기록하지 않습니다.

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return null;
}
```

`await` 이후에는 반드시 `cancellationToken.IsCancellationRequested`를 다시 확인하여 "취소됨"을 "로드 실패"로 처리하지 않도록 합니다.

출처: [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149)

## 검증

1. 콘솔에 더 이상 `ImageCache: ...` 경고 또는 `Fatal` 로그가 나타나지 않습니다.
2. `LoadImageAsync`가 비어 있지 않은 `Texture2D`를 반환하여 UI / `Sprite`에 바인딩하여 정상적으로 표시할 수 있습니다.
3. 두 번째 로드 시 콘솔에서 더 이상 네트워크 요청이 트리거되지 않으며, `Config.CachePath` 아래에서 URL의 MD5로 명명된 캐시 파일을 볼 수 있습니다.
