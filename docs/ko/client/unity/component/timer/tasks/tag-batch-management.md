# 태그별 타이머 일괄 관리

`Add()`로 타이머를 생성할 때 `tag` 문자열을 전달하면, 이후 `PauseByTag` / `ResumeByTag` / `RemoveByTag` / `HasTag` 네 가지 메서드로 같은 태그 아래의 모든 타이머를 한 번에 조작할 수 있어, 타이머 ID를 하나씩 보유할 필요가 없습니다.

## 전제 조건

- 씬에 `TimerComponent` 컴포넌트가 이미 존재해야 합니다(메뉴 경로 `GameFrameX/Timer`). 이 컴포넌트는 `Awake`에서 `GameFrameworkEntry.GetModule<ITimerManager>()`를 통해 매니저를 가져옵니다.

## 작업 단계

1. `Add()`로 타이머를 생성하고, 그룹 이름을 다섯 번째 파라미터인 `tag`에 전달합니다. `tag`의 기본값은 `null`이며, 명시적으로 전달된 타이머만 해당 태그 그룹에 포함됩니다:

```csharp
using System;
using GameFrameX.Timer.Runtime;
using UnityEngine;

public class BattleScene : MonoBehaviour
{
    TimerComponent _timer;

    void Start()
    {
        // Add(interval, repeat, callback, callbackParam, tag, ...)
        _timer.Add(1f, 0, OnEnemyTick, null, "Battle");    // 매초 갱신, 무한 반복
        _timer.Add(5f, 10, OnBuffRefresh, null, "Battle"); // 5초마다 한 번, 총 10회
        _timer.Add(30f, 1, OnBossRoar, null, "Battle");    // 30초 후 한 번 실행
    }

    void OnEnemyTick(object param) { /* ... */ }
    void OnBuffRefresh(object param) { /* ... */ }
    void OnBossRoar(object param) { /* ... */ }
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

2. 그룹 전체를 일시정지해야 할 때 `PauseByTag`를 호출하며, 일시정지 중에는 시간이 누적되지 않습니다:

```csharp
_timer.PauseByTag("Battle"); // 예: 일시정지 메뉴를 열 때
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L152-L155)

3. 재개할 때 `ResumeByTag`를 호출하면, 일시정지 지점부터 누적이 이어집니다:

```csharp
_timer.ResumeByTag("Battle"); // 예: 일시정지 메뉴를 닫을 때
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L161-L164)

4. 그룹이 끝날 때 `RemoveByTag`를 호출하여 모든 멤버를 한 번에 제거합니다:

```csharp
_timer.RemoveByTag("Battle"); // 예: 전투 종료 시 일괄 정리
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L170-L173)

5. `HasTag`로 해당 태그에 아직 활성 타이머가 있는지 확인한 뒤 후속 로직을 수행합니다:

```csharp
if (_timer.HasTag("Battle"))
{
    Debug.Log("전투 타이머가 아직 실행 중입니다");
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L180-L183)

태그 관련 메서드 요약:

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| `PauseByTag` | `void PauseByTag(string tag)` | 해당 태그 아래의 삭제되지 않은 모든 타이머를 일시정지합니다 |
| `ResumeByTag` | `void ResumeByTag(string tag)` | 해당 태그 아래의 모든 타이머를 재개합니다 |
| `RemoveByTag` | `void RemoveByTag(string tag)` | 해당 태그 아래의 모든 타이머를 제거합니다 |
| `HasTag` | `bool HasTag(string tag)` | 해당 태그 아래에 하나 이상의 타이머가 존재하면 `true`를 반환합니다 |

위 메서드는 `ITimerManager` 인터페이스와 `TimerComponent` 양쪽에 모두 정의되어 있으며, 두 구현의 동작은 동일합니다.

## 일반적인 변형

- **한 번만 실행되는 작업도 그룹화해야 하는 경우**: `AddOnce`와 `AddUpdate`는 `tag` 파라미터를 제공하지 않습니다. 태그별로 관리해야 한다면 `Add(interval, 1, callback, param, tag)`를 사용해 단일 트리거를 동등하게 구현하세요.
- **ID로 개별 멤버를 정밀하게 조작하는 경우**: `Add()`의 반환값은 타이머 ID이므로, `Pause(int id)` / `Resume(int id)` / `Remove(int id)` / `IsPaused(int id)`와 조합해 그룹 내 특정 항목만 개별적으로 제어할 수 있습니다. 자세한 내용은 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L105-L146)를 참고하세요.

## 흔히 발생하는 실수

- **태그에 `null`이나 빈 문자열을 전달한 경우**: `Add`의 `tag` 파라미터 기본값은 `null`이므로, 전달을 빠뜨리면 타이머가 어떤 그룹에도 속하지 않아 이후 `PauseByTag` 등의 호출이 적용되지 않습니다. 다만 오류는 발생하지 않습니다. 멤버가 없는 태그에 대해 호출하는 것은 안전한 no-op입니다.
- **`RemoveByTag`가 `onComplete`를 트리거한다고 생각하는 경우**: 태그 조작은 `Remove(id)`와 동일한 제거 경로를 따릅니다([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)). 제거만 수행하므로, 씬 전환 같은 핵심 로직을 완료 콜백에 의존해 처리하지 마세요.
- **콜백 내에서 현재 태그를 곧바로 `RemoveByTag`하는 경우**: 구현에서는 ID 컬렉션을 임시 리스트에 먼저 복사한 뒤 하나씩 제거하여 순회 중 컬렉션이 수정되는 문제를 피하므로, 콜백 내에서 호출해도 안전합니다. 그래도 논리를 명확하게 유지하기 위해 제거는 콜백이 반환된 후로 미루는 것을 권장합니다.

## 배경

`TimerManager`는 내부적으로 `_tags`(`tag -> ID 컬렉션`)로 그룹을 기록하며, `TimerItem`에는 `Tag` 문자열이 저장됩니다. 모든 태그 조작은 `lock (Locker)` 안에서 수행되어 멀티스레드 환경에서 안전성을 보장합니다. `PauseByTag`는 삭제되지 않은 항목에만 적용되어 `IsPaused = true`로 설정하고, `ResumeByTag`는 무조건 일시정지 플래그를 해제하며, `HasTag`는 `ids.Count > 0`이면 `true`를 반환합니다. 타이머 모듈의 전체 구조에 대해서는 《타이머 컴포넌트 개요》를 참고하세요.
