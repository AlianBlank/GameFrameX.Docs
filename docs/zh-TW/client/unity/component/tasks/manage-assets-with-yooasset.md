# 如何使用 AssetBundle 與 YooAsset 資源載入

本頁面指導你在 GameFrameX.Unity 專案中透過 YooAsset 完成資源打包、設定和載入：把待打包資源放進 `Assets/Bundles` 對應的分組目錄，使用 `YooAssetSettings` 控制清單檔名與預設輸出資料夾，然後執行建置產生 `PackageManifest` 清單與 `yoo` 資源包，執行時按位址載入即可。

## 前置條件

- Unity 專案已透過 Package Manager 安裝 YooAsset(由 `YooAssetSettings.asset` 參照腳本 GUID `9753568a72b014c7092614d3be8b353f`)。
- 專案根目錄存在 `Assets/AssetBundleSetting/` 資料夾，包含兩個核心設定檔：
  - [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset)
  - [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml)
- 資源按分組放到 `Assets/Bundles/{GroupName}` 下(AOTCode / Code / UI / Config / Image / Sprites)。

## 操作步驟

### 1. 準備資源目錄

YooAsset 的收集器已固定為 `Assets/Bundles` 下的六個分組(AOTCode、Code、UI、Config、Image、Sprites)。把要打包進 AssetBundle 的資源按用途放入對應資料夾，例如：

- `Assets/Bundles/UI` —— UI Prefab、圖集、字型
- `Assets/Bundles/Config` —— 設定表、二進位資源
- `Assets/Bundles/Sprites` / `Assets/Bundles/Image` —— 美術貼圖

收集規則見 [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L5-L22):

```xml
<Group GroupActiveRule="EnableGroup" GroupName="UI" GroupDesc="" AssetTags="">
  <Collector CollectPath="Assets/Bundles/UI" CollectGUID="4010ac95965b3164e83fa268b290dbf4"
            CollectType="MainAssetCollector" AddressRule="AddressByFileName"
            PackRule="PackDirectory" FilterRule="CollectAll" UserData="" AssetTags="" />
</Group>
```

> 每條 `<Collector>` 表示「收集哪個目錄 → 用什麼規則產生位址 → 如何打包」。目前專案統一使用 `AddressByFileName`(以檔名作為載入位址)+ `PackDirectory`(按目錄打包成一個包)。

### 2. 確認 YooAsset 全域設定

開啟 [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L12-L16) 核對兩個欄位：

| 欄位 | 目前值 | 含義 |
|------|--------|------|
| `ManifestFileName` | `PackageManifest` | 執行時載入清單的檔名 |
| `DefaultYooFolderName` | `yoo` | 建置產出的預設輸出目錄名 |

如果你的專案用了不同名稱的清單或輸出目錄，需要在此修改並確保執行時與建置端一致。

### 3. 觸發 YooAsset 建置

YooAsset 會在 Unity 選單 `YooAsset → Build` 下提供建置入口(由 `YooAssetSettings.asset` 的 `m_Script` 參照的編輯器腳本提供)。建置產出會輸出到 `DefaultYooFolderName` 設定的 `yoo` 資料夾下，主要包含：

- `PackageManifest`(清單檔案，記錄所有包名、版本、資源位址)
- 各分組的 AssetBundle 檔案(命名遵循 `UniqueBundleName="True"`,見 [AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3))

### 4. 執行時按位址載入資源

建置完成後，把 `yoo` 目錄下的清單與 AssetBundle 部署到 `StreamingAssets`(或遠端 CDN)。啟動時由 YooAsset 初始化系統讀取 `PackageManifest`,業務端按 `AddressByFileName` 產生的位址載入即可：

```csharp
// 虛擬碼:與 YooAsset 公用 API 對齊,實際類型以你安裝的 YooAsset 版本為準
var package = YooAssets.GetPackage("DefaultPackage");
var op = package.LoadAssetAsync<GameObject>("Assets/Bundles/UI/LoginPanel.prefab");
yield return op;
var go = op.InstantiateObject;
```

## 常見變體

- **新增資源分組**：在 [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml) 的 `<Package>` 內新增一條 `<Group>` 與對應的 `<Collector CollectPath="Assets/Bundles/你的分組">`,重新啟動編輯器後 YooAsset 會自動識別。
- **修改打包粒度**：把 `<Collector>` 的 `PackRule` 從 `PackDirectory` 改為 `PackSeparately`(每個資源獨立成一包)或 `PackTogether`(整組打包成一個包)。
- **切換位址規則**：把 `AddressRule` 改為 `AddressByGroupAndFileName` 或自訂規則，執行時按新位址載入即可。

## 常見錯誤

- **執行時找不到資源**：先確認 `ManifestFileName` 與 `DefaultYooFolderName` 在建置端和執行時一致([YooAssetSettings.asset L15-L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L15-L16));再確認資源確實放在 `Assets/Bundles/<GroupName>` 下,且分組 `GroupActiveRule="EnableGroup"`。
- **重複打包或包名衝突**：確保 `<Common>` 節點的 `UniqueBundleName="True"`(見 [AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3)),否則同名目錄會互相覆蓋。
- **修改設定後沒生效**：YooAsset 的收集設定只在編輯器重新啟動或重新開啟 YooAsset 視窗後才會被重新解析；改完 XML 後切回 Editor 主視窗再建置。

## 背景(選擇性)

專案採用 YooAsset 作為統一的資源管理方案:`AssetBundleCollectorConfig.xml` 描述「哪些資源 → 走哪個位址 → 打哪個包」,`YooAssetSettings.asset` 描述「清單怎麼命名 → 產出放哪裡」。兩端解耦後，既能在不重寫程式碼的前提下調整打包粒度，也能在不改資源結構的情況下切換執行模式(本機 / CDN)。
