# How to Configure Multi-Language Localization (text field)

In an Excel configuration table, declaring a field's type as `text` connects that column to the `TbLocalization` localization table; at runtime, the actual text for the current language is retrieved by key, enabling a single configuration set to switch between languages.

## Prerequisites

- The .NET SDK is installed (a runtime dependency of the Luban tool).
- The repository root contains an `Excels/Local/` directory for placing `L-` prefixed localization files.
- You already know how to run the generation scripts (`gen-client-json.sh` / `gen-server-json.sh`, etc.); after generation, the `TbLocalization` class will be produced in `Hotfix/Config/Generate` or `Server.Config/Config`.

## Steps

1. **Declare the field type as `text`**. In the `##type` row of any business table (such as an achievement or item table), set the field type to `text` instead of `string`. `text` means the column holds a key, and the actual text is looked up in the localization table at runtime; `string` is used as-is and will not be translated.

   Example: the achievement table's `name` and `achievement_content` fields both use the `text` type and only contain a key:

   | ##var | id | image | name | achievement_content |
   |-------|----|-------|------|---------------------|
   | ##type | int | int | text | text |
   | ##group | | | | |
   | ## | ID | Icon id | Achievement Key | Achievement Content Key |
   | | 900001 | 101 | achievement_001 | achievement_001_desc |

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L227-L232)

2. **Understand the difference between `text` and `string`**. `text` is multi-language text that requires localization (it holds a key); `string` is plain text that will not be translated (the content is written directly). If a field that needs translation is mistakenly declared as `string`, you will get the raw string at runtime and no translation will occur.

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L223)

3. **Prepare the localization Excel files**. The repository already provides three examples under `Excels/Local/`, all of which are merged into the same `TbLocalization` table:

   | Localization Category | File | Content |
   |------------|------|------|
   | Localization - Achievements | `Excels/Local/L-Localization-成就.xlsx` | Achievement text |
   | Localization - Text | `Excels/Local/L-Localization-文本.xlsx` | General text |
   | Localization - UI | `Excels/Local/L-Localization-UI.xlsx` | UI text |

   Multiple `L-Localization-*.xlsx` files are automatically merged as long as their English part is identical (`Localization`):

   ```
   L-Localization-成就.xlsx    ┐
   L-Localization-文本.xlsx    ├→ merged into a single TbLocalization
   L-Localization-UI.xlsx      ┘
   ```

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L199), [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L250-L254)

4. **Split the localization table by module (optional)**. When the volume of text is large, split it into multiple `L-Localization-XXX.xlsx` files by module (achievements, UI, general text, etc.); just keep the English name prefix as `L-Localization` — the Chinese part can be named freely (the tool does not parse it).

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L256)

5. **Verify that `localizationFileName` is enabled in the generation command**. In `luban.conf`, the `client` target command includes `"localizationFileName": "Localization.xlsx"`; without this entry, `TbLocalization` will not be generated.

   ```json
   {
     "localizationFileName": "Localization.xlsx",
     "command": "--target client --dataTarget json --codeTarget cs-simple-json ...",
     "target": "client",
     "active": true
   }
   ```

   Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

6. **Run the generation script**. On Windows, double-click `gen-client-json.bat`; on Mac/Linux, run `sh gen-client-json.sh`. Once generation completes, the `text` fields in business tables are mapped to `TbLocalization`, so the current language's text can be retrieved by key at runtime.

## Common Variants

- **Group by client/server**: Add `c-` or `s-` after the English name of a localization file (e.g., `L-Localization-c-UI.xlsx`) so that only the corresponding side receives it.
- **Add custom localization files**: As long as they are placed under `Excels/Local/` and their English name prefix is `L-Localization`, they will be automatically merged into `TbLocalization`.
- **Split large tables by entry count**: Just like regular tables, use the same English name + different Chinese names (e.g., `L-Localization-UI-1.xlsx`, `L-Localization-UI-2.xlsx`), and the tool will merge them automatically.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The text retrieved at runtime is the key literal | `##type` was set to `string` instead of `text` | Change the field type to `text` |
| The generated `TbLocalization` cannot be found | The `client` target command in `luban.conf` is missing `localizationFileName` | Add it to the command JSON as described in step 5 above |
| The table's English name contains Chinese | The tool requires that English names contain no Chinese characters, otherwise it errors out directly | Rename `L-本地化-成就.xlsx` to a form like `L-Localization-成就.xlsx` |
| The text does not take effect; only the key is shown | The `L-Localization-*.xlsx` files were not placed under the `Excels/Local/` directory | Move the files to `Excels/Local/`, then rerun the generation script |

## Background (optional)

A `text` field is essentially a key that references `TbLocalization`; all `L-Localization-*.xlsx` files are merged into the same localization table; `string` skips translation and is used directly as the original string. `localizationFileName` in `luban.conf` is the switch that enables client-side localization generation.
