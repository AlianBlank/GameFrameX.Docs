## 各平台設定範例

**Android** — 在主執行 Activity 內宣告 `meta-data`(該 Activity 即為 Java 端的 `com.alianhome.getchannel.MainActivity`):

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

出處:[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

**iOS/tvOS/visionOS** — 在 Info.plist 中加入 String 型別的鍵值對：

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

出處:[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)

**Editor/PC/WebGL/UWP/遊戲主機** — 在 `Resources` 目錄下建立 `application_config.txt`,並於每行撰寫一個 `key=value`:

```text
channel=editor_cn_test
sub_channel=test
```

出處:[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L28-L33)

## 讀取行為要點

- **可自訂鍵名**：呼叫 `GetChannelName("sub_channel", "unknown")` 即可讀取子渠道。Android/iOS 端同樣會以傳入的 `channelKey` 查詢 `meta-data` 或 Info.plist。
- **txt 解析規則**：僅允許 `split.Length > 1` 的行，換句話說，必須包含 `=`。第一個 `=` 之前為鍵、之後為值，兩側 Trim 後記錄至快取。詳情請參閱 [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120)。
- **TextAsset 缺失時**：會將 `defaultValue` 原樣記錄至快取並回傳。
- **iOS 原生端後備值**：若在 Info.plist 中找不到鍵，將回傳硬編碼的 `unknown` 而非 C# 端的 `defaultValue`。詳情請參閱 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L31-L35)。
- **iOS 建置後備**:[PostProcessBuildHandler](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49) 會在 iOS 建置後檢查 Info.plist,若無 `channel` 鍵則自動寫入 `default` 並輸出 `配置渠道成功=>default` 日誌；若已存在則輸出 `已有渠道,跳过设置=>{value}`。
- **快取策略**：所有平台首次讀取的結果會記錄到 `ChannelCache` 字典(初始容量 32),程序內重複呼叫也不會再次讀取原生設定。詳情請參閱 [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L57)。
