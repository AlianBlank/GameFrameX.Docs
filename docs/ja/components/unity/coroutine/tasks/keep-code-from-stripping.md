# パッケージビルド時のコードストリッピングでコルーチンコンポーネントを保護する方法

`GameFrameXCoroutineCroppingHelper` を Unity シーン内の GameObject にアタッチするだけで、IL2CPP / Managed Stripping が有効化されたパッケージビルド環境でも `CoroutineComponent` がストリッピングされず、コルーチン API を正常に呼び出すことができます。

## 前提条件

- 本コルーチンパッケージ(`com.gameframex.unity.coroutine`)がインストール済みであること
- 対象プラットフォームでマネージドコードストリッピング(Managed Stripping または IL2CPP)が有効化されている、または link.xml / Preserve 仕組みを使用しているプロジェクトであること
- 常駐シーンが存在すること(ビルド後も GameObject が破棄されない)

## 操作手順

1. 任意の常駐シーン(例:起動シーン)に新しい GameObject を作成し、例えば `GameFrameXCoroutineCroppingHelper` という名前を付けます。
2. その GameObject に `GameFrameXCoroutineCroppingHelper` コンポーネントを追加します。

   ```csharp
   using GameFrameX.Coroutine.Runtime;
   ```
   Source: [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

3. `DontDestroyOnLoad` にアタッチする必要はありません。このコンポーネントの `Start` は任意のシーンで一度実行されれば、ストリッパーが `CoroutineComponent` の型参照を保持するのに十分です。
4. 再ビルド後、ゲームを実行すれば `GameEntry.GetComponent<CoroutineComponent>().StartCoroutine(...)` を通常通り使用できます。

## よくあるバリエーション

- **CroppingHelper を使用しない場合**:プロジェクトに `link.xml` を追加し、`GameFrameX.Coroutine.Runtime` 名前空間全体を保持することができます。
- **追加の GameObject を避けたい場合**:既存の任意のコンポーネントスクリプト内に `private void Start() { _ = typeof(GameFrameX.Coroutine.Runtime.CoroutineComponent); }` と記述し、そのクラスに `[Preserve]` を付与すれば、同等の効果が得られます。
- **AOT プラットフォーム(IL2CPP + iOS/Android)**:CroppingHelper のアタッチを強く推奨します。さもないと、`StartCoroutine` / `StopCoroutine` の `new` オーバーロードが一部のストリッピングレベルで対応するメソッドを見つけられなくなる可能性があります。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| ビルド後に `StartCoroutine` を呼び出すと `MissingMethodException` が発生する | `CoroutineComponent` の `new` オーバーロードメソッドがストリッパーによって削除された | `GameFrameXCoroutineCroppingHelper` をアタッチするか、`link.xml` を追加して名前空間を保持する |
| 実行時に `GameFrameXCoroutineCroppingHelper` 型が見つからない | 当該スクリプトが AOT で一緒にストリッピングされてしまった | `link.xml` で誤って `GameFrameX.Coroutine.Runtime.*` を除外しないこと。CroppingHelper 自体には既に `[Preserve]` が付与されている |
| コンポーネント追加後、シーンに空のオブジェクトが増える | `Start` の参照をトリガーするためだけのもので、視覚的・論理的な副作用はない | `MeshRenderer` を非表示にするか、既存の常駐シングルトンオブジェクトに統合する |

## 背景(オプション)

`GameFrameXCoroutineCroppingHelper` の内部には `Start` が一つだけあり、`typeof(CoroutineComponent)` を参照しています。クラスとメソッドの両方に `[Preserve]`(`UnityEngine.Scripting` 由来)が付けられているため、Unity の Stripping 段階でこの参照チェーンが保持され、`CoroutineComponent` とその `new` で隠されたメソッドが保護されます。
