# 如何使用網路、下載、Web 與 Protobuf 通訊

GameFrameX 透過 `GameApp.Network` / `GameApp.Download` 靜態存取器公開網路與下載元件；Web 請求與 Protobuf 通訊則由對應的配套套件提供。以下是整合這四個子系統的最精簡步驟。

## 前置需求

| 子系統 | 必要巨集 / 套件 | 用途 |
|--------|-------------|------|
| 網路 | `ENABLE_GAME_FRAME_X_NETWORK` + `GameFrameX.Network.Runtime` | 基於 Protobuf 協定的 TCP / UDP 持久連線 |
| 下載 | `ENABLE_GAME_FRAME_X_DOWNLOAD` + `GameFrameX.Download.Runtime` | HTTP/HTTPS 檔案下載、進度回呼 |
| Web | `GameFrameX.Web.Runtime` | 一次性 HTTP 請求(REST / JSON)|
| Protobuf | `GameFrameX.ProtoBuf.Runtime` | 訊息編碼/解碼,供 Network 內部使用 |

> 這四個元件都會在 GameEntry 啟動時註冊；可透過 `GameApp.Network`、`GameApp.Download` 等靜態屬性取得單例。

## 步驟

### 1. 啟用網路元件

只要存取 `GameApp.Network` 即可取得單例；框架內部會呼叫 `GameEntry.GetComponent<NetworkComponent>()`。

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Runtime;

var network = GameApp.Network;
network.Connect("127.0.0.1", 7000);
#endif
```

原始碼:[Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L55)

### 2. 啟用下載元件

下載元件同樣透過 `GameApp.Download` 單例來存取:

```csharp
#if ENABLE_GAME_FRAME_X_DOWNLOAD
using GameFrameX.Runtime;

var downloader = GameApp.Download;
downloader.DownloadAsync(url, savePath, (success, error) =>
{
    if (success) UnityEngine.Debug.Log("Download complete");
    else UnityEngine.Debug.LogError(error);
});
#endif
```

原始碼:[Runtime/GameApp.Download.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Download.cs#L32-L55)

### 3. 發送 Web 請求

Web 模組用於一次性 HTTP 呼叫(JSON、表單等)，與採用持久連線的 Network 並不衝突：

```csharp
using GameFrameX.Web.Runtime;

WebComponent web = GameEntry.GetComponent<WebComponent>();
web.Post("https://api.example.com/login", "{\"user\":\"x\"}",
    (statusCode, body) => UnityEngine.Debug.Log($"{statusCode} -> {body}"));
```

### 4. 使用 Protobuf 序列化訊息

Network 內部已在使用 Protobuf;自訂訊息可直接重用同一個 ProtoBuf 元件：

```csharp
using GameFrameX.ProtoBuf.Runtime;

byte[] bytes = ProtoBufComponent.Serialize(myMessage);
var restored = ProtoBufComponent.Deserialize<MyMessage>(bytes);
```

### 5. 關閉並重新連線

```csharp
GameApp.Network.Close();
GameApp.Network.Connect("127.0.0.1", 7000); // 重新建立連線
```

## 常見變體

- **多個持久連線通道**:`NetworkComponent` 支援多個 `NetworkChannel`,每個通道都有獨立的心跳 / 獨立的編解碼。
- **斷點續傳**：在 `DownloadAsync` 回呼中儲存已下載的位元組，並於啟動時透過 `Range` 標頭續傳。
- **Protobuf 以外的協定**：建立新的 `NetworkChannel` 時傳入自訂的 `INetworkChannelHelper`,即可切換為 JSON / MessagePack。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `GameApp.Network` 回傳 `null` | 未定義 `ENABLE_GAME_FRAME_X_NETWORK` 巨集 | 在 `Project Settings → Scripting Define Symbols` 底下加入該巨集；並安裝 `GameFrameX.Network` 套件 |
| 下載回呼收到 `success=false` 但沒有 `error` 文字 | URL 無效或磁碟沒有寫入權限 | 檢查 `url` 與 `savePath`,並確認 Application.persistentDataPath 可寫入 |
| Web 請求回傳狀態碼 0 | Unity 不允許該目標網域 | 檢查 Player Settings → Other Settings → Allow downloads over HTTP |
| Protobuf 序列化擲回例外狀況 | 訊息類別缺少 `[ProtoContract]` / `[ProtoMember]` | 在訊息欄位加上這些屬性，或使用 protobuf-net 的 `ImplicitFields = ImplicitFields.AllPublic` |

## 背景說明(選讀)

`GameApp` 是一個 `partial class`,每個子系統各自位於獨立的檔案中，全部透過 `GameEntry.GetComponent<T>()` 延遲載入並快取到私用靜態欄位。如此可避免 `GetComponent` 呼叫散落各處，也便於根據巨集裁減不需要的子系統，縮減發佈建置的大小。
