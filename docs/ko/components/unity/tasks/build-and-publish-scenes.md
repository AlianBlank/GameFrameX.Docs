# Launcher / LauncherAuto 씬 구축 및 배포 방법

이 페이지에서는 GameFrameX.Unity의 `Assets/Scenes/Launcher.unity`와 `Assets/Scenes/LauncherAuto.unity` 두 개의 런처 씬 구축 및 배포 요점을 설명합니다. 여기에는 Build Settings의 인덱스 위치, 포함된 UI 컴포넌트, 독립 플랫폼으로 배포할 때의 일반적인 처리 방법이 포함됩니다.

## 사전 조건

- Unity Editor가 설치되어 있어야 합니다(저장소의 `ProjectSettings/`에 선언된 버전과 일치).
- 프로젝트가 Unity Hub를 통해 열려 있어야 하며, 디렉터리에 `Assets/Scenes/Launcher.unity`와 `Assets/Scenes/LauncherAuto.unity` 두 개의 씬 파일이 존재해야 합니다.
- GameFrameX 프레임워크 런타임이 설치되어 있어야 하며, 씬에 사전 제작된 `UILauncher` 컴포넌트 스크립트를 사용할 수 있어야 합니다.

## 작업 단계

### 1. File → Build Settings 열기

Unity 메뉴 바에서 `File` → `Build Settings`를 선택하고, `Scenes In Build` 목록에서 `Launcher`와 `LauncherAuto`가 추가되었는지 확인합니다. 일반적으로 `Launcher`는 인덱스 0의 첫 번째 런처 씬입니다.

### 2. 씬 파일 존재 확인

다음 두 파일이 프로젝트에 존재하는지 확인합니다. 이는 후속 빌드 결과물에 런처 씬이 포함되기 위한 전제 조건입니다.

- [Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity)
- [Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity)

### 3. Launcher 씬의 UILauncher 컴포넌트 확인

`Launcher.unity`에는 `UILauncher` 스크립트 컴포넌트가 마운트되어 있으며, 런처 UI와 버전 감지 로직을 담당합니다. 파일에는 컴포넌트 참조가 보존되어 있습니다.

```yaml
propertyPath: m_Name
value: UILauncher
```

참조 출처:[Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity#L1158)

씬을 연 후 Hierarchy 상단의 GameObject에서 `UILauncher` 컴포넌트를 볼 수 있으며, 필드에는 버전 번호, 핫 업데이트 주소, 서버 목록 등이 포함됩니다. 필드가 비어 있으면 Inspector에서 먼저 구성한 후 배포해야 합니다.

### 4. LauncherAuto 씬의 Build Settings 처리

`LauncherAuto.unity`는 자체 `m_BuildSettings` 섹션을 YAML 형식으로 선언합니다(직렬화 버전 3). Unity는 이 섹션을 기준으로 씬의 빌드 참여 여부 및 조명/Lightmap 설정을 기록합니다. 파일을 직접 열면 다음을 볼 수 있습니다.

```yaml
m_BuildSettings:
  serializedVersion: 3
```

참조 출처:[Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity#L105-L107)

Build Settings에서 이 씬을 비활성화해야 하는 경우, `m_BuildSettings` 아래에서 `m_Scenes` 참조를 조정하거나 Unity 편집기에서 직접 체크를 해제할 수 있습니다.

### 5. 대상 플랫폼 선택 및 빌드

Build Settings에서 대상 플랫폼(Windows, Android, iOS, macOS 등)을 선택하고 `Build` 또는 `Build And Run`을 클릭합니다. Unity는 `Scenes In Build`의 순서에 따라 `Launcher`와 `LauncherAuto`를 Player 바이너리에 함께 패키징합니다.

### 6. 결과물 확인

빌드가 완료되면 출력 디렉터리에서 다음을 확인합니다.

- 실행 파일이 정상적으로 시작되어 `Launcher` 씬으로 진입할 수 있는지;
- `LauncherAuto`가 UI 자동 건너뛰기를 구성할 때 로드되는지;
- 런처 인터페이스의 버전 번호, 핫 업데이트 주소가 올바르게 표시되는지.

## 일반적인 변형

- **LauncherAuto 자동 씬 전환**:시작 후 UI 런처를 표시하는 대신 비즈니스 씬으로 직접 진입하려면 Player Settings → 기타 설정에서 `LauncherAuto`를 활성화할 수 있습니다. 이 씬은 일반적으로 UI가 없는 자동화된 시작 프로세스에 사용됩니다.
- **플랫폼별 씬 다듬기**:WebGL과 같은 저성능 플랫폼의 경우 Build Settings에서 `LauncherAuto`를 제거하고 `Launcher`만 유지할 수 있습니다. 반면 독립 클라이언트의 경우 동시에 체크할 수 있습니다.
- **UILauncher 필드 교체**:다양한 배포 채널에서 다른 핫 업데이트 주소를 사용하므로, 빌드 전에 `UILauncher` 스크립트의 구성을 임시로 전환하면 됩니다.

## 일반적인 오류

- **빌드 후 시작 시 검은 화면 표시**:일반적으로 `UILauncher` 컴포넌트의 필드가 구성되지 않아(버전 번호, 핫 업데이트 주소가 비어 있음) 런처 초기화에 실패한 경우입니다.
- **Scenes In Build에서 씬 누락**:수동으로 새 씬을 추가할 때 `Launcher` 또는 `LauncherAuto`를 목록에서 제거하면 런타임 시 런처를 건너뛰고 직접 오류가 발생합니다.
- **씬 GUID 충돌**:.unity 파일을 직접 복사할 때 원본 `m_SceneGUID`를 그대로 유지하면 Build Settings 참조가 꼬이게 됩니다. Unity가 다시 가져와 새 GUID를 생성하도록 해야 합니다.

## 배경(선택 사항)

`Launcher`와 `LauncherAuto`는 GameFrameX의 듀얼 런처 씬 조합입니다. `Launcher`는 UI가 있는 런처를 제공하여 버전 확인, 핫 업데이트 및 서버 선택을 담당하며, `LauncherAuto`는 백그라운드 또는 자동화된 런처 씬으로 UI를 건너뛰고 비즈니스 로직을 직접 로드합니다. `m_BuildSettings`는 Unity 씬 파일에서 빌드 참여 상태를 설명하는 메타데이터 섹션이며, Editor와 Player가 모두 읽습니다.
