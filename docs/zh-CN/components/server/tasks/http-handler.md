# 添加 HTTP 接口(Bag / Mail / Player 等)

本页教你如何在 `GameFrameX.Hotfix` 程序集中新增一个 HTTP 接口,用于对外提供 Bag、Mail、Player 等业务能力。完成后框架会自动把这个接口注册到内置 HTTP 服务,你用 URL 直接调用即可。

## 前置条件

- 已熟悉解决方案中的 `GameFrameX.Hotfix` 工程结构,知道业务代码放在 `GameFrameX.Hotfix/Logic/Http/<模块>/`。
- 已经在协议工程(`GameFrameX.Proto`)中定义好了 `HttpMessageRequestBase` / `HttpMessageResponseBase` 的请求 / 响应类型,以及 `ErrorCode` 枚举。
- 了解框架的 HTTP 启动入口:[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L40-L52) 通过 `HotfixManager.GetListHttpHandler()` 自动扫描所有继承 `BaseHttpHandler` 的类。

## 操作步骤

1. **创建 Handler 类**:在 `GameFrameX.Hotfix/Logic/Http/<模块>/` 下新增一个 `sealed class`,继承 `BaseHttpHandler`。类必须位于 `GameFrameX.Hotfix` 程序集,否则会被架构分析器 `GFX0003` 拒绝编译([HttpHandlerAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HttpHandlerAssemblyAnalyzer.cs#L10-L20))。

2. **打上三个特性**:类上必须同时标注 `HttpMessageMapping`(路由)、`HttpMessageRequest`(请求类型),`HttpMessageResponse`(响应类型,可省但强烈建议带上)。Mail 系列还要求使用强类型 `HttpMessageRequestBase` 重载:

```csharp
namespace GameFrameX.Hotfix.Logic.Http.Mail;

[HttpMessageMapping(typeof(QueryMailCampaignHttpHandler))]
[HttpMessageRequest(typeof(QueryMailCampaignRequest))]
[HttpMessageResponse(typeof(QueryMailCampaignResponse))]
[Description("Admin 查询运营邮件 Campaign 发布状态")]
public sealed class QueryMailCampaignHttpHandler : BaseHttpHandler
{
    public override async Task<string> Action(string ip, string url, HttpMessageRequestBase requestBase)
    {
        var request = (QueryMailCampaignRequest)requestBase;
        var response = new QueryMailCampaignResponse { Code = MailCampaignErrorCode.Ok };
        // ...业务逻辑...
        return HttpJsonResult.SuccessString(response);
    }
}
```

Source: [QueryMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/QueryMailCampaignHttpHandler.cs#L44-L70)

3. **重写 `Action` 方法**:根据是否需要反序列化请求体,选择两种签名之一:
   - 简单接口(`ReloadHttpHandler`、`TestHttpHandler`):接收 `Dictionary<string, object> parameters`,自行解析查询参数。
   - 强类型接口(Mail、Bag):接收 `HttpMessageRequestBase requestBase`,框架已替你反序列化。

   返回值必须是 `string`,统一通过 `HttpJsonResult` 工具方法序列化(`SuccessString` / `ParamErrorString` 等):

```csharp
public override Task<string> Action(string ip, string url, Dictionary<string, object> parameters)
{
    if (parameters.TryGetValue("version", out var version))
    {
        await HotfixManager.LoadHotfixModule(null, version.ToString());
        return Task.FromResult(HttpJsonResult.SuccessString(null));
    }
    return Task.FromResult(HttpJsonResult.ParamErrorString());
}
```

Source: [ReloadHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/ReloadHttpHandler.cs#L40-L60)

4. **构建并启动**:在仓库根目录执行构建,框架会自动扫描所有 `BaseHttpHandler` 子类并向 `HttpServer.Start(Setting.HttpPort, Setting.HttpsPort, HotfixManager.GetListHttpHandler(), HotfixManager.GetHttpHandler, null, Setting.HttpUrl)` 注册([AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L49-L51))。启动后即可用注释里标注的 URL 调试。

## 常见变体

- **无请求 / 无响应体**(`TestHttpHandler`):只标 `HttpMessageMapping`,需要返回数据时手写一个继承 `HttpMessageResponseBase` 的类即可。
- **需要事件分发**(Bag 道具发放):在 Handler 内调用 `EventDispatcher.Dispatch(...)`,异步等 `BagComponentAgent` 完成,最后用 `HttpJsonResult.SuccessString` 返回汇总结果([ReqPlayerSendItemHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Bag/ReqPlayerSendItemHttpHandler.cs#L45-L80))。
- **GM 类只读接口**(Player 在线列表):同样走 `Dictionary<string, object> parameters`,Handler 内部去查 SessionManager,模板可直接参考 `GetOnlinePlayerListHttpHandler`。
- **运营邮件四件套**:`PreviewMailCampaignHttpHandler` / `PublishMailCampaignHttpHandler` / `QueryMailCampaignHttpHandler` / `RevokeMailCampaignHttpHandler` 演示了同一模块下多接口的标准写法。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 编译报 `GFX0003` | `BaseHttpHandler` 子类没有放在 `GameFrameX.Hotfix` 程序集 | 把 Handler 类移到 `GameFrameX.Hotfix/Logic/Http/...` 下 |
| 启动后访问 404 | 没有标 `[HttpMessageMapping]`,或类型自身未作为泛型实参传入特性 | 确认特性参数是 `typeof(YourHandler)` 本身 |
| 拿不到请求参数 | 用了 `Dictionary<string, object>` 签名但前端传的是 JSON Body | 改用 `HttpMessageRequestBase` 重载并加 `[HttpMessageRequest]` |
| 返回 `null` 序列化失败 | 直接返回对象而不是字符串 | 用 `HttpJsonResult.SuccessString(response)` 包一层 |
| 路由被 GM 后台识别不到 | `[Description]` 为空,工具无法归类 | 加上语义化中文 `Description("...")` |

## 背景(可选)

`BaseHttpHandler` 是 `GameFrameX.NetWork.HTTP` 提供的事件式基类;启动时 `HotfixManager.GetListHttpHandler()` 会反射出所有非抽象子类,交给 `HttpServer` 完成路由注册。Mail / Bag / Player 模块按目录拆分子命名空间,便于 GM 后台和自动化扫描按模块归类。
