# 빠른 시작: 설치 및 첫 번째 컴포넌트 호출

이 페이지의 작업을 완료하면 Unity 프로젝트에서 `GameApp` 정적 파사드를 통해 등록된 GameFrameX 컴포넌트를 한 줄로 호출하고, 이벤트 구독과 트리거를 한 번씩 수행할 수 있습니다.

## 사전 조건

- Unity 2019.4 이상(README에 표시된 최소 버전).
- 대상 플랫폼에서 해당 컴포넌트의 매크로 스위치가 활성화되어 있어야 합니다(예: 이벤트 컴포넌트에는 `ENABLE_GAME_FRAME_X_EVENT` 필요).
- 사용 가능한 GameFrameX 프레임워크 런타임(`com.gameframex.unity.runtime`)과 최소 하나의 기능 컴포넌트 패키지(예: `com.gameframex.unity.event`)가 이미 준비되어 있어야 합니다.

## 작업 단계

### 1. 엔트리 컴포넌트 설치

Unity 프로젝트의 `Packages/manifest.json`을 열고 `dependencies` 노드 아래에 엔트리 컴포넌트를 추가합니다:

```json
{
  "dependencies": {
    "com.gameframex.unity.entry": "1.2.1"
  }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L46-L62)

Unity의 `Package Manager`에서 Git URL 방식으로 추가할 수도 있습니다: `https://github.com/gameframex/com.gameframex.unity.entry.git`(README.zh-CN.md#L66-L73).

### 2. `GameApp` 사용 가능 확인

설치가 완료되면 Unity는 `Runtime/GameApp.cs`와 해당 partial 클래스들을 자동으로 프로젝트에 컴파일합니다. `GameApp`은 `public static partial class`이며, 각 속성은 필요할 때 대상 컴포넌트를 지연 로딩합니다:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }

    private static BaseComponent _base;
}
```

출처: [GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L52)

### 3. 첫 번째 컴포넌트 호출(이벤트 컴포넌트 예시)

실행 가능한 코드 어디에서든 `GameApp.Event`를 통해 직접 컴포넌트를 가져와 구독을 수행합니다:

```csharp
// 표준 방식: GameEntry를 통해(com.gameframex.unity.entry에 의존하지 않음)
var component = GameEntry.GetComponent<EventComponent>();

// 빠른 방식: GameApp을 통해(com.gameframex.unity.entry 필요)
GameApp.Event.Subscribe(eventId, handler);
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L76-L82)

이벤트 컴포넌트의 partial 클래스 구현이 이 매핑 관계를 확인해 줍니다:

```csharp
#if ENABLE_GAME_FRAME_X_EVENT
public static partial class GameApp
{
    public static EventComponent Event
    {
        get
        {
            if (_event == null)
            {
                _event = GameEntry.GetComponent<EventComponent>();
            }
            return _event;
        }
    }

    private static EventComponent _event;
}
#endif
```

출처: [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs#L32-L55)

## 일반적인 변형

`GameApp`의 속성 이름은 통일된 규칙을 따릅니다: 속성 이름 = 컴포넌트 클래스 이름에서 `Component` 접미사를 제거한 것. 두 가지 예외는 `FUI` → `FairyGUIComponent`, `GUI` → `UGUIComponent`입니다(README.zh-CN.md#L38).

| GameApp 속성 | 동등한 호출 |
|---|---|
| `GameApp.Event` | `GameEntry.GetComponent<EventComponent>()` |
| `GameApp.UI` | `GameEntry.GetComponent<UIComponent>()` |
| `GameApp.Asset` | `GameEntry.GetComponent<AssetComponent>()` |

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L30-L37)

## 자주 발생하는 오류

- **해당 기능 패키지를 도입하지 않고 `GameApp.XXX` 호출**: `GameApp.XXX`는 실제로 partial 클래스이므로, 해당 컴포넌트 패키지가 존재하고 매크로 스위치가 활성화된 경우에만 `GameApp.Event.cs` 같은 파일이 컴파일에 포함됩니다. 예를 들어 `com.gameframex.unity.event`가 설치되어 있지 않으면 `GameApp.Event`가 존재하지 않습니다. 패키지를 설치하고 매크로 스위치(`ENABLE_GAME_FRAME_X_EVENT`)를 활성화한 후 다시 컴파일하세요.
- **1.3.0부터 `GameApp.FairyGUI`와 `GameApp.ShareSDK` 제거됨**: 1.3.0으로 업그레이드한 후에는 이 두 가지 빠른 접근 방식을 더 이상 사용할 수 없으므로, 해당 기능 패키지의 API를 대신 사용하세요([CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L8-L14) 참조).
- **GameEntry만 사용하고 엔트리 컴포넌트를 도입하지 않으려는 경우**: `GameEntry.GetComponent<T>()`는 `com.gameframex.unity.runtime`에서 제공되며 이 패키지와는 독립적입니다. `GameApp.*` 문법적 설탕이 필요할 때만 이 패키지를 반드시 설치해야 합니다(README.zh-CN.md#L77-L82).

## 배경(선택 사항)

`GameApp`은 단순한 정적 파사드 계층으로, `GameEntry.GetComponent<T>()`를 속성으로 감싸고 지연 로딩으로 캐시합니다. 실제 컴포넌트 등록과 수명 주기는 `GameFrameX` 런타임이 관리합니다. 이름 지정은 `Component` 접미사 제거 규칙을 따르므로 기억하기 쉽고, 매번 제네릭을 직접 작성하는 수고도 덜 수 있습니다.
