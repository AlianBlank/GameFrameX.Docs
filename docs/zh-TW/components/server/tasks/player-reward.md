# 實作玩家獎勵(Reward)模組

本頁面說明如何在玩家 Actor 上使用 `RewardGrantComponentAgent.GrantAsync` 統一發放獎勵,涵蓋呼叫前置條件、請求/結果結構、路由規則與冪等帳本行為。

## 前置條件

- 目標玩家 Actor 已上線,`RewardGrantComponent` 由框架按 `[ComponentType(GlobalConst.ActorTypePlayer)]` 自動掛載,無需手動註冊。
- 已存在 `TbItemConfig` 道具表設定(`GameFrameX.Config.Tables`),普通道具路由會用 `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)` 驗證 `ItemId` 是否存在。
- 呼叫端位於能解析玩家 Actor 的伺服器端上下文(例如熱更新層 `GameFrameX.Hotfix.Logic.Player.Reward` 命名空間下的程式碼)。
- `BagComponentAgent` 已就緒，普通道具發放最終會呼叫 `BagComponentAgent.UpdateChanged(...)` 寫背包(線上 push notify,離線只持久化)。

## 操作步驟

1. **建構 `RewardGrantRequest`。** `RoleId` 必須是目標玩家的 `ActorId`,`SourceType` / `SourceId` / `TraceId` 三者共同唯一，共同組成冪等鍵 `RoleId:SourceType:SourceId:TraceId`。`Rewards` 是要下發的條目清單。

   ```csharp
   using GameFrameX.Apps.Player.Reward.Entity;

   var request = new RewardGrantRequest
   {
       RoleId    = playerActorId,
       SourceType = RewardSourceType.Mail,            // 業務來源,禁止 None
       SourceId  = $"mail:{mailId}:attachment:{attachmentId}",
       TraceId   = Guid.NewGuid().ToString("N"),      // 唯一追蹤編號
       Rewards   = new List<RewardItem>
       {
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1001, Count = 5 },
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1002, Count = 1 },
       },
   };
   ```
   Source: [RewardGrantRequest.cs#L41-L67](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L41-L67)

2. **透過元件代理呼叫 `GrantAsync`。** 入口為 `RewardGrantComponentAgent.GrantAsync`,標註了 `[Service]`,可被同 Actor 內其他代理元件或上層業務直接 await。

   ```csharp
   using GameFrameX.Hotfix.Logic.Player.Reward;

   var agent = await ActorManager.GetComponentAgent<RewardGrantComponentAgent>(playerActorId);
   var result = await agent.GrantAsync(request);
   ```
   Source: [RewardGrantComponentAgent.cs#L51-L91](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L51-L91)

3. **讀取 `RewardGrantResult`。** `Items` 給出逐項成功/失敗與錯誤碼;`AllSuccess` 表示是否全部成功;`ErrorCode` 是整體聚合碼(`Ok` / `PartialSuccess` / 首個失敗項錯誤碼)。

   ```csharp
   if (result.AllSuccess)
   {
       // 全部獎勵已寫入背包或冪等命中
   }
   else
   {
       foreach (var item in result.Items)
       {
           if (!item.Success)
           {
               // item.ErrorCode 取值見 OperationStatusCode
           }
       }
   }
   ```
   Source: [RewardGrantRequest.cs#L72-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L72-L89)

4. **按需擴充路由。** 一期僅 `RewardType.NormalItem` 真正落地(寫 `BagState`),其他類型(HiddenItem / MonthCard / LifetimeCard / VipPoint / Equity 等)在 `DispatchAsync` 中回傳 `OperationStatusCode.Unsupported`,不會污染普通背包。新增類型時，在 `DispatchAsync` 的 `switch` 分支中加入對應的子路由實作即可。
   Source: [RewardGrantComponentAgent.cs#L96-L172](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L96-L172)

## 常見變體

- **營運補償 / 兌換碼 / 活動獎勵：** 業務來源不同時，只需要換 `SourceType` 與 `SourceId` 的串接方式，`GrantAsync` 是唯一的資產發放入口，不要直接繞過它寫背包。
- **離線玩家發獎：** `BagComponentAgent.UpdateChanged(channel, ...)` 在 `channel` 為空時只持久化、不推送 notify,業務側無需額外分支。
- **請求攜帶擴充欄位：** `RewardItem.ExtraData` 是預留欄位，當前發放流程不解析，但會隨冪等帳本原樣持久化，後續路由可讀取。

## 常見錯誤

| 症狀 | 原因 | 規避 |
|------|------|------|
| 整筆請求 `ErrorCode = Unsupported` | `RewardType` 不在已實作路由(除 `NormalItem` 外均不支援) | 一期只發普通道具；擴充前先在 `DispatchAsync` 補路由 |
| 單項 `ErrorCode = InvalidReward` | `RewardItem.Count <= 0` | 呼叫前驗證 `Count > 0` |
| 單項 `ErrorCode = NotFound` | `ItemId` 在 `TbItemConfig` 不存在 | 設定表先建表，再由策劃填表 |
| 整筆 `ErrorCode = Unprocessable` | 背包元件更新失敗(`bagState.IsNull()`) | 檢查 `BagComponentAgent` 與玩家 Actor 狀態 |
| 重複發獎 | 冪等鍵 `RoleId:SourceType:SourceId:TraceId` 不唯一 | 同一筆業務保持三欄位穩定，需要重試時直接重複使用 `TraceId` |
