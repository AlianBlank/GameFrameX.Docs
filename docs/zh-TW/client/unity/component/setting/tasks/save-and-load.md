# 設定的儲存與讀取

使用 GameFrameX 的設定元件，將遊戲設定（玩家環境設定、關卡參數等）寫入持久化後端，並在需要時讀回。本頁面說明在 Unity 專案中完成儲存與讀取所需的最小步驟。

## 前置條件

- `com.gameframex.unity.setting` 套件已匯入 Unity 專案。
- 場景中已附加 `GameFrameX/Setting` 元件（`SettingComponent`）。它會在 `Start` 時自動呼叫 `Load()`，並透過 `m_SettingHelperTypeName` 選擇預設的 `PlayerPrefsSettingHelper`。

## 操作步驟

1. **確認預設的 Helper 類型**。`SettingComponent` 預設使用 `PlayerPrefsSettingHelper`，因此無需修改即可讀寫 PlayerPrefs。若要切換至小遊戲平台，請在 Inspector 中為 `Setting Helper Type Name` 指定對應的 `AlipayMiniGameSettingStorage` / `DouYinMiniGameSettingStorage` / `KuaiShouMiniGameSettingStorage` / `WeChatMiniGameSettingStorage`。

   來源：[SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L100)

2. **寫入設定**。使用 `SettingComponent` 的 `SetXxx` 系列方法將值寫入記憶體：

   ```csharp
   using GameFrameX.Setting.Runtime;

   var setting = GameFrameXEntry.GetComponent<SettingComponent>();
   setting.SetBool("MusicOn", true);
   setting.SetInt("Level", 3);
   setting.SetString("PlayerName", "Alice");
   setting.SetFloat("Volume", 0.8f);
   ```

   寫入方法僅修改記憶體，不會立即寫入磁碟。

   來源：[SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L225-L228)

3. **呼叫 Save() 以寫入磁碟**。在適當的時機（遊戲結束時、場景切換前等）執行以下操作：

   ```csharp
   setting.Save();
   ```

   `PlayerPrefsSettingHelper.Save()` 會委派給目前平台的 `ISettingStorageBackend.Save()` 執行實際的寫入。回傳值表示儲存是否成功，可在除錯時輸出日誌進行確認。

   來源：[PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L99-L102)

4. **讀取設定**。`SettingComponent.Start()` 已經呼叫了 `Load()`，因此可在進入下一個場景時使用 `GetXxx` 讀取：

   ```csharp
   bool musicOn = setting.GetBool("MusicOn", true);     // 附帶預設值
   int level   = setting.GetInt("Level", 1);
   string name = setting.GetString("PlayerName", "");
   float vol   = setting.GetFloat("Volume", 1.0f);
   ```

   各 `GetXxx` 皆提供附帶預設值的多載，當鍵值不存在時會回傳預設值。

   來源：[SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L102-L108)

5. **管理鍵值**。對個別或所有設定項目進行查詢與刪除：

   ```csharp
   if (setting.HasSetting("Level")) { /* ... */ }
   setting.RemoveSetting("Level");
   setting.RemoveAllSettings();
   ```

   來源：[SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L157-L185)

## 常見變化

- **跨平台寫入**。將 `m_SettingHelperTypeName` 變更為對應小遊戲平台的 `*MiniGameSettingStorage`，即無需修改讀寫邏輯。
- **自訂後端**。實作 `ISettingStorageBackend`，並透過 `PlayerPrefsSettingHelper.SetStorageBackendForTests` 注入（也可以在自訂的 `SettingHelperBase` 子類別中使用 `SettingStorageBackendFactory.Create()`）。
- **批次更新**。在一個業務事件結束時集中呼叫一次 `Save()`，避免每次修改都寫入磁碟。

## 常見錯誤

- **忘記呼叫 Save()**：`SetXxx` 僅修改記憶體，若未呼叫 `Save()`，資料將不會持久化，重新啟動後即會遺失。
- **在啟動時讀取**：請勿在 `Awake` 內讀取。`SettingComponent` 會在 `Start` 中執行 `Load()`。請將讀取邏輯放置在 `Start` 之後。
- **依賴列舉所有鍵值**：PlayerPrefs 不支援 `GetAllSettingNames()`，呼叫時會回傳 `null`，並輸出 `GetAllSettingNames is not supported.` 警告。請改為在業務層維護一份已知鍵值清單。

## 背景（選讀）

`SettingComponent` 是 MonoBehaviour 的進入點，`SettingManager` 是無外部依賴的模組核心，而 `SettingHelperBase` 負責將讀寫分派至特定後端。`PlayerPrefsSettingHelper` 預設會透過 `SettingStorageBackendFactory` 選擇對應平台的後端實作，因此能以相同的 API 相容地處理 PlayerPrefs 與小遊戲平台的儲存。
