# 일반 오류 빠른 참조

`GameFrameX.Procedure` 플로우 모듈을 사용할 때, 거의 모든 런타임 예외는 동일한 근본 원인에서 발생합니다 —— **`ProcedureManager.Initialize` 이전에 플로우 작업을 호출한 것**. 아래에 자주 발생하는 오류를 한 번에 정리했으니, 증상을 보면 바로 수정 위치를 파악할 수 있습니다.

## 빠른 진단

| 증상(예외/로그 원문) | 원인 | 수정 |
|------|------|------|
| `GameFrameworkException: You must initialize procedure first.`(`CurrentProcedure`, `CurrentProcedureTime`, `StartProcedure`, `HasProcedure`, `GetProcedure` 접근 시) | 비즈니스 코드가 `ProcedureManager.Initialize` 이전에 플로우 API를 호출하여, 내부 `m_ProcedureFsm`이 여전히 `null`임 | `ProcedureComponent`가 부착된 GameObject에 `Available Procedure Type Names`와 `Entrance Procedure Type Name`을 올바르게 설정하여, 컴포넌트가 `Initialize`를 완료한 후에 호출 |
| `GameFrameworkException: Procedures is invalid.`(`Initialize` 시 발생) | `Initialize`에 전달된 `procedures` 배열이 `null`이거나 길이가 0임 | 최소 하나 이상의 `ProcedureBase` 서브클래스 인스턴스 전달 |
| `Log.Fatal("Procedure manager is invalid.")`(컴포넌트 `Awake` 단계) | 프레임워크에 `IProcedureManager` 구현이 등록되지 않아, `GameFrameworkEntry.GetModule<IProcedureManager>()`가 `null`을 반환함 | 플로우 모듈이 포함된 어셈블리가 프로젝트에 올바르게 패키징되었는지, 잘리지 않았는지 확인; 일반적으로 `GameFrameXAutoComponent`가 자동으로 등록하나, 제거된 경우 asmdef 확인 필요 |
| `Log.Warning("Available procedure type names is empty. Procedure auto start skipped.")` | `ProcedureComponent.m_AvailableProcedureTypeNames` 필드가 빈 배열이거나 미입력 | Inspector에서 최소 하나 이상의 플로우 타입 전체 이름 추가(예: `MyGame.Procedure.LaunchProcedure, MyGame`) |
| `Log.Error("Can not find procedure type '{0}'.")` | `m_AvailableProcedureTypeNames`의 타입 전체 이름 오타, 네임스페이스 오류 또는 대상 어셈블리가 로드되지 않음 | `Utility.Assembly.GetType`으로 해석 가능한 전체 한정 이름을 사용하고, 타입이 로드된 어셈블리에 실제로 존재하는지 확인 |
| `Log.Error("Can not create procedure instance '{0}'.")` | 타입은 찾을 수 있으나 `ProcedureBase`의 서브클래스가 아니거나 매개변수 없는 생성자가 없음 | 커스텀 플로우가 `ProcedureBase`를 상속하고 `public` 매개변수 없는 생성자를 유지 |
| `Log.Error("Entrance procedure is invalid.")` | `m_EntranceProcedureTypeName`이 `m_AvailableProcedureTypeNames`의 어느 항목과도 일치하지 않음 | 진입점 플로우 타입 이름이 `Available Procedure Type Names`의 항목 중 하나와 정확히 일치해야 함 |
| 런타임에 `Already exist FSM.` 발생(`StartupRunner`와 함께 사용할 때) | 구버전 자동 초기화와 새 버전 `StartupRunner`이 동시에 활성화되어 `Initialize`가 두 번 호출됨 | `ProcedureComponent.m_UseStartupRunner`를 `true`로 설정하여 `ApplicationStartupEntry + StartupRunner.Run`이 초기화를 인계받도록 함 |

## 수정 단계

### 1. 초기화 전에 플로우 API 호출

예외 발생 지점은 모두 `ProcedureManager`에서 `m_ProcedureFsm`에 대한 null 체크 분기에 있으며, 예를 들어 `StartProcedure<T>()`:

```csharp
[Preserve]
public void StartProcedure<T>() where T : ProcedureBase
{
    if (m_ProcedureFsm == null)
    {
        throw new GameFrameworkException("You must initialize procedure first.");
    }

    m_ProcedureFsm.Start<T>();
}
```

Source: [ProcedureManager.cs#L148-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L148-L156)

`CurrentProcedure`, `CurrentProcedureTime`, `HasProcedure`, `GetProcedure`도 동일한 null 체크 로직을 거칩니다:

```csharp
if (m_ProcedureFsm == null)
{
    throw new GameFrameworkException("You must initialize procedure first.");
}
```

Source: [ProcedureManager.cs#L72-L78](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L72-L78)

수정 방법: `ProcedureComponent`를 부착한 후, 컴포넌트가 `Start` 코루틴에서 `Initialize`와 `StartProcedure`를 완료하도록 합니다:

```csharp
m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);

yield return new WaitForEndOfFrame();

m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
```

Source: [ProcedureComponent.cs#L164-L168](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

비즈니스 측에서는 씬 로드가 완료되고 `CurrentProcedure`가 `null`이 아닌 값을 반환한 후에 플로우 전환을 시작해야 합니다.

### 2. `Initialize`에 빈 플로우 배열 전달

```csharp
public void Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)
{
    GameFrameworkGuard.NotNull(fsmManager, nameof(fsmManager));
    GameFrameworkGuard.NotNull(procedures, nameof(procedures));
    if (procedures.Length <= 0)
    {
        throw new GameFrameworkException("Procedures is invalid.");
    }

    m_FsmManager = fsmManager;
    m_ProcedureFsm = m_FsmManager.CreateFsm(this, procedures);
}
```

Source: [ProcedureManager.cs#L130-L141](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)

수정 방법: `procedures`는 최소 1개 이상 전달해야 하며, 반드시 `ProcedureBase`를 상속해야 합니다:

```csharp
public abstract class ProcedureBase : FsmState<IProcedureManager>
{
    // 서브클래스에서 OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy 재정의
}
```

Source: [ProcedureBase.cs#L38-L98](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

### 3. Inspector 플로우 타입 이름 설정 오류

`ProcedureComponent.Start`는 타입 이름으로 리플렉션하여 인스턴스를 생성하며, 어느 단계든 실패하면 시작이 중단됩니다:

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

Source: [ProcedureComponent.cs#L135-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L156)

수정 방법: Inspector에서 `네임스페이스.클래스명, 어셈블리명` 형식으로 입력하고, 진입점 이름이 사용 가능 목록에 포함되어야 합니다. 그렇지 않으면 아래의 `Entrance procedure is invalid.` 오류로 이어집니다:

```csharp
if (m_EntranceProcedure == null)
{
    Log.Error("Entrance procedure is invalid.");
    yield break;
}
```

Source: [ProcedureComponent.cs#L158-L162](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L158-L162)

### 4. `StartupRunner`과의 중복 초기화

새 버전 시작 체인에서는 컴포넌트가 초기화 권한을 양보해야 합니다:

```csharp
[SerializeField] private bool m_UseStartupRunner = false;
...
if (m_UseStartupRunner)
{
    // ApplicationStartupEntry + StartupRunner.Run이 Initialize와 StartProcedure를 인계받아,
    // 본 컴포넌트는 Awake에서 IProcedureManager 등록 역할만 수행하여, 새 진입점과의 중복 Initialize로 인한 Already exist FSM을 방지
    yield break;
}
```

Source: [ProcedureComponent.cs#L65-L127](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L65-L127)

수정 방법: `StartupRunner`를 활성화할 때 `Use Startup Runner`를 체크하여 `ApplicationStartupEntry`가 통합 스케줄링을 담당하도록 합니다.

## 검증

아래 순서대로 하나씩 확인하고, 어느 항목이든 실패하면 위 표의 해당 행을 다시 참조하세요:

1. 시작 후 Console에 `GameFrameworkException: You must initialize procedure first.`가 없고, `ProcedureComponent.CurrentProcedure`가 `null`이 아님.
2. 씬 전환 또는 재로그인 후 로그에 중복된 `Already exist FSM.`이 없음.
3. 커스텀 `ProcedureBase` 서브클래스의 `OnEnter`에서 `Debug.Log`를 출력하여, 예외에 의해 삼켜지지 않고 실제로 호출되는지 확인.
4. `m_AvailableProcedureTypeNames`에 최소 1개 이상의 항목이 있고, `m_EntranceProcedureTypeName`이 그 중 하나와 정확히 일치.
