# 訂閱下載事件（開始/進度/成功/失敗）

透過 `EventComponent` 訂閱 `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` 四個事件，你可以在下載任務生命週期的任意階段收到回呼，從而驅動 UI 進度條、提示訊息與失敗重試邏輯。

## 前置條件

- 已安裝 `com.gameframex.unity.download` 套件，並在 `GameEntry` 上掛載了 `DownloadComponent`。
- 專案內已啟用 GameFrameX 的 `EventComponent`（`DownloadComponent` 透過它派發所有下載事件）。
- 已有合法的本機儲存路徑與遠端下載位址。

## 操作步驟

1. 取得 `DownloadComponent` 與 `EventComponent` 實例：

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   var eventComponent    = GameEntry.GetComponent<EventComponent>();
   ```

2. 透過 `EventComponent.Subscribe` 訂閱四個事件，回呼簽章固定為 `void Handler(object sender, GameEventArgs e)`：

   ```csharp
   eventComponent.Subscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Subscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

3. 新增下載任務，記錄回傳的 `serialId`，用於在回呼裡區分是哪一次下載：

   ```csharp
   int serialId = downloadComponent.AddDownload(
       "/本機儲存路徑/file.zip",      // downloadPath
       "https://example.com/file.zip" // downloadUri
   );
   ```

4. 在四個回呼裡將 `GameEventArgs` 強制轉型為對應型別，讀取欄位：

   ```csharp
   void OnDownloadStart(object sender, GameEventArgs e)
   {
       var args = (DownloadStartEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadUpdate(object sender, GameEventArgs e)
   {
       var args = (DownloadUpdateEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadSuccess(object sender, GameEventArgs e)
   {
       var args = (DownloadSuccessEventArgs)e;
       if (args.SerialId == serialId)
       {
           // 下載完成：args.DownloadPath / args.DownloadUri / args.CurrentLength / args.UserData
       }
   }

   void OnDownloadFailure(object sender, GameEventArgs e)
   {
       var args = (DownloadFailureEventArgs)e;
       Debug.LogError($"下載失敗：{args.ErrorMessage}");
   }
   ```

5. 用完記得 `Unsubscribe`，避免記憶體洩漏與誤觸發：

   ```csharp
   eventComponent.Unsubscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Unsubscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Unsubscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

## 常見變體

- **按 SerialId 過濾**：同一個 `DownloadComponent` 可能併發多個任務，回呼裡用 `args.SerialId == serialId` 區分是哪一次下載。
- **帶 UserData 的任務**：呼叫 `AddDownload` 的多載可附帶 `userData`，四個事件參數都會原樣回傳，便於把業務上下文一起帶到回呼裡。
- **只想拿到完成結果**：不想寫四個回呼時，可改用 `await downloadComponent.Download(...)`，詳見 README 的「非同步用法」小節。

## 常見錯誤

- **EventId 寫錯**：必須使用 `XxxEventArgs.EventId` 常數，不要自行拼湊字串。原始碼中四個 `EventId` 均為 `typeof(XxxEventArgs).FullName`，寫錯會導致訂閱不到事件。
- **回呼收到但 SerialId 對不上**：併發下載時未在回呼裡過濾 `args.SerialId`，把別人的結果當成自己的。
- **忘了 `Unsubscribe`**：腳本銷毀或場景切換後未取消訂閱，回呼仍會被舊實例持有，容易引起記憶體洩漏或重複觸發。
- **使用 `WWWDownloadAgentHelper` 時拿到的是舊版事件鏈**：四個 `DownloadXxxEventArgs` 是 `DownloadComponent` 層的統一事件，與底層 `DownloadAgentHelper` 的事件不同；UI 進度請訂閱前者，不要直接訂閱 Helper 層事件。

## 背景（可選）

四個 `DownloadXxxEventArgs` 均繼承 `GameFrameX.Event.Runtime.GameEventArgs`，由 `DownloadComponent` 在內部狀態機切換時透過 `EventComponent.Fire(this, ...)` 派發：`AddDownload` 後派發 Start，下載過程中派發 Update，最終派發 Success 或 Failure。事件機制讓呼叫端無需持有 `DownloadComponent` 的回傳物件即可收到非同步通知。
