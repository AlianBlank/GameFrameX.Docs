## IObjectStorageManager

유일한 초기화 진입점으로, 모든 객체 스토리지 구현체는 이 인터페이스를 반드시 구현해야 합니다.

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| `Init` | `void Init(string accessKey, string secretKey, string bucketName, string endpoint = null)` | `accessKey` 는 키, `secretKey` 는 비밀 키, `bucketName` 은 스토리지 풀 이름, `endpoint` 는 주소 (일부 객체 스토리지는 필요 없음) |

## IObjectStorageUploadManager

`IObjectStorageManager` 를 상속받아 초기화를 기반으로 업로드 관련 메서드를 선언합니다.

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| `SetSavePath` | `void SetSavePath(string savePath)` | 객체 스토리지에 업로드할 대상 경로 (디렉터리 접두사) |
| `UploadDirectory` | `void UploadDirectory(string localDirectory)` | 로컬 디렉터리 업로드 |
| `UploadFile` | `bool UploadFile(string localFilePathAndName)` | 단일 로컬 파일 업로드, 성공 여부 반환 |

## BaseObjectStorageUploadManager

`IObjectStorageUploadManager` 를 구현하여 공통 로직을 캡슐화합니다. 자식 클래스는 두 개의 추상 메서드만 구현하면 됩니다.

### 구현된 멤버

| 멤버 | 시그니처 | 동작 |
|------|------|------|
| `SetSavePath` | `void SetSavePath(string savePath)` | 끝의 디렉터리 구분 기호를 자동으로 제거한 후 `BucketSavePath` 에 기록 |
| `UploadDirectory` | `void UploadDirectory(string localDirectory)` | `localDirectory` 를 `UploadRootPath` 에 기록한 후 `UploadDirectoryInternal` 호출 |
| `UploadFile` | `bool UploadFile(string localFilePathAndName)` | `UploadFileInternal` 로 직접 전달 |

### 필드

| 필드 | 유형 | 설명 |
|------|------|------|
| `BucketSavePath` | `protected string` | `SetSavePath` 로 설정된 대상 경로 |
| `UploadRootPath` | `protected string` | `UploadDirectory` 로 설정된 로컬 디렉터리, 초기값 `string.Empty` |

### 자식 클래스가 반드시 구현해야 하는 추상 멤버

| 멤버 | 시그니처 | 설명 |
|------|------|------|
| `Init` | `public abstract void Init(string accessKey, string secretKey, string bucketName, string endpoint = null)` | 계정/연결 등 초기화 |
| `UploadDirectoryInternal` | `protected abstract void UploadDirectoryInternal(string localDirectory)` | 디렉터리 업로드를 실제로 수행하는 로직 |
| `UploadFileInternal` | `protected abstract bool UploadFileInternal(string localFilePathAndName)` | 단일 파일 업로드를 실제로 수행하며 성공 여부 반환 |

최소 커스텀 구현 예시:

```csharp
using GameFrameX.ObjectStorage.Editor;

public sealed class MyUploadManager : BaseObjectStorageUploadManager
{
    public override void Init(string accessKey, string secretKey, string bucketName, string endpoint = null)
    {
        // 여기에서 구체적인 SDK 클라이언트를 초기화
    }

    protected override void UploadDirectoryInternal(string localDirectory)
    {
        // localDirectory 를 순회하며 업로드
    }

    protected override bool UploadFileInternal(string localFilePathAndName)
    {
        // 단일 파일 업로드
        return true;
    }
}
```

## ObjectStorageUploadFactory

제네릭 제약 `where T : IObjectStorageUploadManager` 을 통해 리플렉션으로 인스턴스를 생성하고 자동으로 `Init` 를 호출하여, 이미 초기화된 업로드 관리자를 반환합니다.

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| `Create<T>` | `static IObjectStorageUploadManager Create<T>(string accessKey, string secretKey, string bucketName, string endpoint = null) where T : IObjectStorageUploadManager` | `Activator.CreateInstance<T>()` 로 인스턴스를 생성하고 즉시 `Init` 를 호출하여 관리자 반환 |

호출 예시:

```csharp
var upload = ObjectStorageUploadFactory.Create<MyUploadManager>(
    accessKey: "AKID...",
    secretKey: "SECRET...",
    bucketName: "my-bucket",
    endpoint: "https://oss-cn-hangzhou.aliyuncs.com");

upload.SetSavePath("/release/1.0.0/");
upload.UploadFile("C:/build/Windows/game.exe");
```

## 구현 포인트 빠른 참조

| 시나리오 | 해야 할 일 |
|------|-----------|
| 완전한 업로드 흐름을 실행하고 싶음 | `BaseObjectStorageUploadManager` 의 세 가지 추상 멤버를 구현한 다음 `ObjectStorageUploadFactory.Create<T>` 로 인스턴스를 획득 |
| 기존 `Init`/업로드 로직을 유지하면서底层 SDK만 교체하고 싶음 | `BaseObjectStorageUploadManager` 를 상속받아 `UploadFileInternal` 과 `UploadDirectoryInternal` 을 재정의하면 됩니다, `SetSavePath` 는 끝 구분 기호를 이미 자동으로 처리 |
| 커스텀 구현에서 기각의 `SetSavePath` 처리를 재사용하지 않으려는 경우 | `IObjectStorageUploadManager` 를 직접 구현하고 경로 형식을 직접 보장 |
