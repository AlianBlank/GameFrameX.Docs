# GetData/SetData 資料讀取異常快速參考

本頁面針對 `IFsm<T>` 中呼叫 `GetData` / `SetData` 過程中常見的例外及非正常回傳情況，提供症狀對照與問題定位步驟。狀態機的使用方式請參閱《Fsm 快速入門》。

## 快速診斷

| 症狀 | 原因 | 解決 |
|------|------|------|
| 擲出 `GameFrameworkException("Data name is invalid.")` | `name` 為 `null` 或空字串 | 使用非 null 的鍵名，建議採用字串常數 |
| `GetData` 一律回傳 `null` | 該鍵從未以 `SetData` 寫入；或狀態機已被 `Reset` / `Shutdown` 清空 | 首次讀取前明確呼叫 `SetData`，或在進入點以 `HasData` 判斷 |
| `SetData` 後立即讀取，但欄位值仍為預設值 | 重複呼叫 `SetData` 時，前一個值被 `ReferencePool` 回收，新值實際上未被替換 | 先呼叫 `RemoveData` 再呼叫 `SetData`，或僅呼叫一次 `SetData` |
| 型別轉換時發生 `InvalidCastException` | `GetData<TData>` 的泛型參數與寫入時實際的 `Variable` 子類別不一致 | 讀取/寫入兩側使用相同的 `Variable` 子類別（例如：`VarInt`、`VarString`） |
| 狀態機銷毀後呼叫 `GetData` 時發生例外 | 當 `m_IsDestroyed == true` 時，`Reset` 等內部流程會拒絕存取 | 銷毀後應停止所有存取，或重新建立新的 FSM |

## 解決步驟

### 1. 名稱無效（`Data name is invalid`）

`GetData(string)` 與 `SetData(string, Variable)` 會在第一個步驟驗證名稱：

```csharp
if (string.IsNullOrEmpty(name))
{
    throw new GameFrameworkException("Data name is invalid.");
}
```

來源：[Fsm.cs#L469-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L527)

**解決**：鍵名請使用穩定的字串常數，例如：`"Hp"`、`"Owner"`。請勿傳遞由字串拼接產生的空字串。

### 2. 讀取時回傳 `null`

`GetData` 在內部字典為空或鍵不存在時，不會擲出例外，而是直接回傳 `null`：

```csharp
if (m_Datas == null)
{
    return null;
}

Variable data = null;
if (m_Datas.TryGetValue(name, out data))
{
    return data;
}

return null;
```

來源：[Fsm.cs#L469-L488](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488)

**解決**：
1. 在狀態的 `OnEnter` 或狀態機建立後，立即呼叫一次 `SetData` 以完成初始化。
2. 讀取前先以 `HasData(name)` 判斷是否存在。若為 `false`，則以預設值進行初始化。
3. `Reset()` 會清空所有資料（`m_Datas.Clear()`）。`Shutdown` 之後字典會變為 `null`，因此必須重新初始化。

### 3. 重複呼叫 `SetData` 後前一個值被回收

`SetData` 內部會先取出前一個值，若不為 null 則歸還至參考池：

```csharp
Variable oldData = GetData(name);
if (oldData != null)
{
    ReferencePool.Release(oldData);
}

m_Datas[name] = data;
```

來源：[Fsm.cs#L508-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L508-L527)

**解決**：
- `Variable` 子類別的執行個體由框架內部透過 `ReferencePool` 取得並管理其生命週期。請勿在外部以 `new` 建立後傳入狀態機。
- 若要替換鍵名，請先以 `RemoveData(name)` 明確歸還前一個值，再以 `SetData` 設定新的鍵。

### 4. 泛型型別不一致

`GetData<TData>` 會直接執行強制轉型，因此 `TData : Variable` 且必須與寫入時的子類別一致：

```csharp
public TData GetData<TData>(string name) where TData : Variable
{
    return (TData)GetData(name);
}
```

來源：[Fsm.cs#L458-L461](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

**解決**：呼叫端請明確使用 `VarInt`、`VarFloat`、`VarString`、`VarBool`、`VarObject` 等內建子類別。請勿以 `object` 或 `Variable` 基底類別作為 `TData`，否則轉型會失敗。

### 5. 銷毀後存取

`Fsm.Shutdown` 之後 `m_IsDestroyed` 會變為 `true`，再次存取時會被 `Reset()` 等內部流程拒絕：

```csharp
if (m_IsDestroyed)
{
    throw new GameFrameworkException("FSM is destroyed, can not reset.");
}
```

來源：[Fsm.cs#L560-L565](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L560-L565)

**解決**：在銷毀 FSM 之前，請先清理所有外部參考。`OnDestroy` 之後請勿繼續呼叫 `GetData`/`SetData`。

## 驗證

請執行下列步驟以確認問題是否已解決：

1. 在狀態的 `OnEnter` 中輸出 `HasData("Hp")` 與 `GetData<VarInt>("Hp").Value`，確認讀取結果是否符合預期。
2. 呼叫 `SetData("Hp", hpVar)` 之後，以 `GetData` 對照值是否一致。
3. 呼叫 `Reset()` 之後再次以 `GetData` 讀取（只要 `name` 不為空），應在不發生例外的情況下回傳 `null`。
