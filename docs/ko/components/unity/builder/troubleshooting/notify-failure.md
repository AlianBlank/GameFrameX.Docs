# WeChat 알림이 도착하지 않을 때怎么办

构建完成后没有收到企业微信机器人通知,通常是因为没有传 `WeChatBotKey`、机器人未开启、或者构建流程没有走到 `IsUpdateAssetPackageVersion` 成功分支。修复前先按下面的诊断表对照实际现象。

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 콘솔에 `System.Net.Http.HttpRequestException` 또는 시간 초과 예외가 표시됨 | 네트워크가 `qyapi.weixin.qq.com`에 접근할 수 없거나, 프록시가 차단함 | 빌드 머신의 네트워크/프록시를 확인하고, `https://qyapi.weixin.qq.com/cgi-bin/webhook/send`에 접근할 수 있는지 확인 |
| WeChat 그룹에 아무 메시지도 오지 않음 | 명령줄에 `-WeChatBotKey`가 전달되지 않아 `BuilderOptions.WeChatBotKey`가 빈 문자열임 | 빌드 명령에 `-WeChatBotKey <봇 Key>` 추가 (대소문자 주의) |
| `{"errcode":40001,...}` 또는 `errcode":40014`를 받음 | 봇 Key가 잘못되었거나 만료됨 | 企业微信 그룹 봇의 Webhook Key를 다시 복사 |
| `{"errcode":45009,...}`를 받음 | 메시지 빈도가 企业微信 봇 제한(분당 20개)을 초과함 | 빌드 빈도를 줄이거나 여러 봇으로 분할 |
| 알림이 전혀 호출되지 않고, 로그에도 `Debug.Log(response)`가 없음 | `IsUpdateAssetPackageVersion`이 false이거나 리소스 버전 업데이트 실패 | 동시에 `-IsUpdateAssetPackageVersion true`를 전달하고 `BuilderUpdateAssetPackageVersionHelper.Run`이 `true`를 반환하도록 보장 |
| Unity Console에 `Debug.LogException(e)`만 출력되고 응답 본문이 없음 | 예외가 `catch (Exception e)`에 의해 삼켜짐 | 아래 "해결 단계 - 삼켜진 예외 확인" 참조 |

## 해결 단계

### 1. 명령줄에 `-WeChatBotKey`가 전달되었는지 확인

`BuilderOptions.WeChatBotKey`의 기본값은 빈 문자열이며, 명령줄에 `-WeChatBotKey`가 포함된 경우에만 값이 할당됩니다.

```csharp
else if (commandLineArg == "-WeChatBotKey")
{
    if (index + 1 < commandLineArgs.Length)
    {
        _builderOptions.WeChatBotKey = commandLineArgs[index + 1];
    }
}
```

빌드 명령 예시 (Unity 명령줄):

```bash
-gameframex.builder -WeChatBotKey xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx -IsUpdateAssetPackageVersion true
```

매개변수 설명은 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L117)를 참조하세요.

### 2. 빌드가 알림 분기를 거치는지 확인

알림은 "리소스 버전 업데이트 성공" 이후에만 발송되므로, `WeChatBotKey`만 단독으로 전달해서는 효과가 없습니다.

```csharp
if (_builderOptions.IsUpdateAssetPackageVersion)
{
    var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
    if (result)
    {
        WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
    }
}
```

두 스위치를 동시에 전달하세요:

```bash
-IsUpdateAssetPackageVersion true -WeChatBotKey <key>
```

`BuilderUpdateAssetPackageVersionHelper.Run`이 false를 반환하면 알림이 트리거되지 않으므로, 먼저 버전 업데이트 실패 원인을排查해야 합니다.

### 3. Webhook Key의 유효성 검증

Key가 잘못된 경우 企业微信은 `errcode:40001`(secret 오류) 또는 `40014`(잘못된 Key)를 반환합니다. `curl`로 직접 테스트할 수 있습니다:

```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<당신의Key>' \
  -H 'Content-Type: application/json' \
  -d '{"msgtype":"text","text":{"content":"hello"}}'
```

`errcode: 0`이 반환되면 정상이며, 그렇지 않으면 企业微信 그룹에서 봇을 다시 추가하여 새 Key를 받으세요.

### 4. 삼켜진 예외 확인

`WeChatNotifyWorkHelper.Run`은 모든 예외를 잡아 `Debug.LogException`으로 기록합니다. 예외 스택만 보이는 경우 HTTP 호출 자체가 실패한 것(네트워크/DNS/시간 초과)입니다.

```csharp
try
{
    var httpResponseMessage = httpClient.PostAsync(url, stringContent).GetAwaiter().GetResult();
    var response = httpResponseMessage.Content.ReadAsStringAsync().GetAwaiter().GetResult();
    Debug.Log(response);
}
catch (Exception e)
{
    Debug.LogException(e);
}
```

처리 방향: `httpClient.Timeout`은 30초이므로, 내부 네트워크 환경에 맞게 적절히 늘릴 수 있습니다. HTTPS 인증서는 시스템 신뢰 체인에 의해 처리되며, 빌드 머신이 자체 서명 프록시를 사용하는 경우 `HttpClientHandler`를 추가로 구성해야 합니다.

### 5. Newtonsoft.Json 참조 존재 확인

CHANGELOG에서 `WeChatNotifyWorkHelper`의 `Newtonsoft.Json` 참조 누락 문제가 특별히 언급된 적이 있습니다. 컴파일 시 `The type or namespace name 'Newtonsoft' could not be found` 오류가 발생하면, `Editor/GameFrameX.Builder.Editor.asmdef`(또는 해당 어셈블리 정의)에 `Newtonsoft.Json` 참조를 추가하면 됩니다.

```text
* **builder:** 补充 WeChatNotifyWorkHelper 缺失的 Newtonsoft.Json 引用
```

## 검증

1. 빌드를 다시 실행하여 Unity Console에 `Debug.Log(response)`와 함께 `errcode: 0`이 포함된 정상 JSON 응답 본문이 출력되는지 확인합니다.
2. 企业微信 그룹에서 `### 游戏资源版本更新` 마크다운 알림이 표시되며, 내용에 시간, 리소스 버전, 게임 버전 등의 필드가 포함되어 있는지 확인합니다.
