# 웹페이지가 표시되지 않거나 표시 영역이 어긋나는 경우 대처 방법

`WebViewComponent.Show(url)` 호출 후 화면에 웹페이지가 전혀 나타나지 않거나, 웹페이지는 나타났지만 표시 영역이 어긋나거나/화면에 가득 차지 않는 경우, 이 페이지의 빠른 진단표로 원인을 파악하고 해당 복구 단계를 실행하십시오. 본 컴포넌트는 [gree/unity-webview](https://github.com/gree/unity-webview)의 래퍼이며 Android 및 iOS 플랫폼만 지원하므로, 문제 해결 시에는 항상 실기기/시뮬레이터를 기준으로 하십시오.

## 빠른 진단

## 복구 단계

### 1. 지원되는 플랫폼에서 실행 중인지 확인

본 패키지의 `Features`는 "Android and iOS platform support"로 명시되어 있으며, 렌더링은 기반이 되는 네이티브 WebView가 수행합니다. Editor 또는 Standalone 플랫폼에서 `Show()`를 호출해도 웹페이지가 표시되지 않는 것은 고장이 아닙니다.

확인 방법: Android/iOS 실기기 또는 시뮬레이터로 빌드한 후 `Show(url)`를 다시 호출합니다.

### 2. 씬에 WebViewComponent가 존재하고 매니저 초기화가 성공했는지 확인

`WebViewComponent`는 씬에 추가하는 프레임워크 컴포넌트입니다(메뉴 경로 `Game Framework/WebView`). 이 컴포넌트는 `Awake()`에서 매니저 모듈을 가져오며, 가져오지 못하면 치명적 로그를 출력합니다:

```csharp
_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

출처: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L32-L37)

`_webViewManager`가 null이면 이후 `Start()`에서 `Initialize()`를 실행하지 않으며, `Show()` 내부에서 전달할 때 `NullReferenceException`이 바로 발생합니다:

```csharp
private void Start()
{
    if (_webViewManager == null)
    {
        return;
    }

    _webViewManager.Initialize();
}
```

출처: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L40-L48)

복구 작업:

1. 시작 씬에 `Game Framework/WebView` 컴포넌트를 추가합니다(이 컴포넌트에는 `[DisallowMultipleComponent]`가 표시되어 있어 씬당 하나만 있으면 됩니다).
2. 의존성 패키지 `com.gameframex.unity`(≥ 1.0.0)가 `manifest.json` 방식으로 설치되었는지 확인합니다.
3. 시작 후 로그에 더 이상 `Web View manager is invalid.`가 나타나지 않는지 확인합니다.

### 3. 표시 후 MakeFullScreen()을 호출하여 표시 영역 수정

래퍼 계층에서 공개하는 네 가지 API는 `Show(string url)`, `MakeFullScreen()`, `ExecuteJavaScript(string javaScript)`, `Hide()`입니다. 영역이 어긋나거나/화면에 가득 차지 않는 경우 `Show` 이후에 `MakeFullScreen()`을 한 번 더 호출합니다:

```csharp
using GameFrameX.WebView.Runtime;
using UnityEngine;

public class Example : MonoBehaviour
{
    void Start()
    {
        var webView = FindObjectOfType<WebViewComponent>();
        webView.Show("https://gameframex.doc.alianblank.com");
        webView.MakeFullScreen(); // 화면을 가득 채워 표시 영역을 수정
    }
}
```

출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/README.md#L104-L116) · [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L55-L66)

참고: 본 래퍼는 마진(margin), 사용자 정의 사각형 등 위치 지정 파라미터를 공개하지 않습니다. 표시 영역을 세밀하게 제어하려면 기반이 되는 [gree/unity-webview](https://github.com/gree/unity-webview)를 직접 사용해야 합니다.

### 4. 내용이 비어 있을 때 URL 및 페이지 문제 배제

먼저 확실히 접근 가능한 URL(예: `https://gameframex.doc.alianblank.com`)로 변경하여 확인합니다. 페이지에 스크립트를 주입하여 진단을 돕고 싶다면 `ExecuteJavaScript`를 사용할 수 있습니다:

```csharp
webView.ExecuteJavaScript("console.log('probe from unity');");
```

출처: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L72-L75)

## 확인

1. Android/iOS 기기로 빌드하여 실행합니다.
2. 콘솔에 `Web View manager is invalid.` 로그가 없고 `Show(url)` 호출 시 null 참조가 발생하지 않는지 확인합니다.
3. 웹페이지가 기기 화면에 나타나고 대상 사이트의 콘텐츠가 로드되는지 확인합니다.
4. `MakeFullScreen()` 호출 후 웹페이지가 화면 전체를 가득 채우고 네 면에 잔여 어긋남이 없는지 확인합니다. 화면을 회전한 후 `MakeFullScreen()`을 다시 한 번 호출하여 영역이 다시 정렬되는지 확인합니다.
5. `Hide()` 호출로 정상적으로 숨겨지고, 다시 `Show(url)` 호출로 정상적으로 다시 나타나는지 확인합니다.

## 배경

`WebViewComponent`는 GameFrameworkComponent의 얇은 래퍼입니다. `Awake()`에서 `GameFrameworkEntry.GetModule&lt;IWebViewManager&gt;()`로 매니저를 가져오고, `Start()`에서 해당 매니저의 `Initialize()`를 호출하며, `Show/MakeFullScreen/ExecuteJavaScript/Hide`는 모두 한 줄로 `IWebViewManager`에 전달됩니다. `BaseWebViewManager`는 단순한 추상 기본 클래스로 이 인터페이스 집합을 추상 메서드로 정의하며, 실제 네이티브 렌더링은 gree/unity-webview가 각 플랫폼 하위 클래스에서 수행합니다. 이것이 Editor/데스크톱 플랫폼에서 웹페이지가 보이지 않고 본 패키지가 영역의 세밀한 제어를 제공하지 않는 근본적인 이유입니다.
