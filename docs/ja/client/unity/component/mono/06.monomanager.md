# MonoManager

MonoManager 是 GameFrameX フレームワーク中的コア模块，负责统一管理 Unity MonoBehaviour 的生命周期イベント，包括 Update、FixedUpdate、LateUpdate、OnDestroy、OnApplicationPause 和 OnApplicationFocus 等。

## 概要

MonoManager 提供します一种集中管理 Unity 生命周期イベント的机制。在传统的 Unity 开发中，開発者通常必要在每个 MonoBehaviour 脚本中分别実装这些生命周期メソッド，这导致代码分散且难以维护。MonoManager を通じて观察者模式（监听器模式），允许開発者在任意位置注册和注销对特定生命周期イベント的监听，从而実装代码的解耦。

该模块を継承 `GameFrameworkModule`，是 GameFrameX フレームワーク的コアコンポーネント之一。它を通じて `MonoComponent` 与 Unity 引擎的 MonoBehaviour 生命周期进行桥接，将 Unity 的生命周期イベント统一收集并分发给已注册的监听器。

### コア機能

- **统一的イベント管理**：集中管理所有 MonoBehaviour 生命周期イベント
- **线程安全**：使用锁机制确保多线程环境下的安全访问
- **性能优化**：使用 Unity Profiler 进行性能分析
- **イベント转发**：サポートを通じて EventComponent 将应用焦点和暂停イベント作为フレームワークイベント发布

## 使用例

### 基本使用

を通じて `MonoComponent` 添加 Update 监听器：

```csharp
using UnityEngine;
using GameFrameX.Mono.Runtime;

public class ExampleScript : MonoBehaviour
{
    private MonoComponent _monoComponent;

    private void Awake()
    {
        // 取得 MonoComponent コンポーネント（需在シーン中已添加）
        _monoComponent = GetComponent<MonoComponent>();
    }

    private void OnEnable()
    {
        // 添加 Update 监听器
        _monoComponent.AddUpdateListener(OnUpdate);
    }

    private void OnDisable()
    {
        // 移除 Update 监听器
        _monoComponent.RemoveUpdateListener(OnUpdate);
    }

    private void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        // 在每帧 Update 时执行
        Debug.Log($"Update: {elapseSeconds:F2}s");
    }
}
```
> Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L186-L195)


## API 参考

### IMonoManager インターフェース

`IMonoManager` インターフェース定义了 MonoManager 的所有公开メソッド。

#### Update 监听器

```csharp
void AddUpdateListener(Action<float, float> action)
```
添加一个在 Update 期间呼び出し的监听器。

**参数：**
- `action` (Action<float, float>)：监听器函数。第一个参数是流逝时间，第二个参数是真实流逝时间。

```csharp
void RemoveUpdateListener(Action<float, float> action)
```
从 Update 中移除一个监听器。

**参数：**
- `action` (Action<float, float>)：监听器函数。

### MonoManager 内部メソッド

以下メソッド由 MonoComponent 呼び出し，不建议直接使用：

```csharp
void FixedUpdate()
```
在固定的帧率下呼び出し。

```csharp
void LateUpdate()
```
在所有 Update 函数呼び出し后每帧呼び出し。

```csharp
void OnDestroy()
```
当 MonoBehaviour 将被销毁时呼び出し。

```csharp
void OnApplicationFocus(bool focusStatus)
```
当应用程序失去或获得焦点时呼び出し。

**参数：**
- `focusStatus` (bool)：应用程序的焦点ステータス。true 表示获得焦点，false 表示失去焦点。

```csharp
void OnApplicationPause(bool pauseStatus)
```
当应用程序暂停或恢复时呼び出し。

**参数：**
- `pauseStatus` (bool)：应用程序的暂停ステータス。true 表示暂停，false 表示恢复。

## 设计意图

### 为什么使用监听器模式而非继承

传统的 Unity 开发中，開発者通常必要让脚本继承 MonoBehaviour 并重写其生命周期メソッド。这种方法存在以下问题：
1. **代码耦合**：业务逻辑与 Unity 生命周期メソッド紧密耦合
2. **难以测试**：难以对业务逻辑进行单元测试
3. **维护困难**：生命周期逻辑散落在各个脚本中

MonoManager を通じて监听器模式解决了这些问题，允许在任意位置注册监听器，実装更好的代码解耦。

### 线程安全的考虑

MonoManager 使用 `lock` 关键字保护所有监听器队列的修改操作，确保在多线程环境下（如使用 Job System 或多线程脚本时）仍然能够安全地添加和移除监听器。

### 性能优化

1. **Unity Profiler 集成**：使用 `Profiler.BeginSample` 和 `Profiler.EndSample` 标记关键性能路径，便于在 Unity Profiler 中分析性能瓶颈。
2. **異常隔离**：每个监听器的呼び出し都包含在 try-catch 块中，确保单个监听器的異常不会影响其他监听器的执行。
3. **LinkedList 优化**：使用 LinkedList 存储监听器，相比 List 具有 O(1) 的添加和移除时间复杂度。
