# How to Update the Remote Asset Package Version

After the build completes, this tool uploads metadata such as the current Asset package's version number, platform, channel, and language to a remote endpoint you specify via HTTP POST. This is used by the server to record/distribute the latest version. This page explains how to enable and configure this feature.

## Prerequisites

- The Asset package build-related fields in `BuilderOptions` (build parameters) have been configured: `PackageName`, `PackageVersion`, build pipeline, etc.
- An HTTP endpoint that accepts version reporting is ready (POST JSON), and the `Authorization` header is agreed upon on the gateway side.
- The remote service is deployed and accessible from the build machine.

## Steps

1. Enable `IsUpdateAssetPackageVersion` in `BuilderOptions`, and fill in the endpoint and authorization information:

   ```csharp
   _builderOptions.IsUpdateAssetPackageVersion = true;
   _builderOptions.UpdateAssetPackageVersionUrl = "https://your-server/api/asset/version";
   _builderOptions.UpdateAssetPackageVersionAuthorization = "Bearer your-token";
   ```

   Field definitions are located at [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L82-L95).

2. Make sure the build output is successfully generated. Version reporting is executed immediately after the build and upload. See the trigger logic at [Builder.BuildAsset.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L134-L141):

   ```csharp
   if (_builderOptions.IsUpdateAssetPackageVersion)
   {
       var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
       if (result)
       {
           WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
       }
   }
   ```

3. Start the build. `BuilderUpdateAssetPackageVersionHelper.Run` will POST the following fields as JSON to `UpdateAssetPackageVersionUrl`:

   | Field | Source |
   |------|------|
   | `AppVersion` | `Application.version` |
   | `PackageName` | `Application.identifier` |
   | `AssetPackageVersion` | `buildParameters.PackageVersion` |
   | `AssetPackageName` | `buildParameters.PackageName` |
   | `Platform` | `buildParameters.BuildTarget.ToString()` |
   | `Language` | `builderOptions.Language` |
   | `Channel` | `builderOptions.ChannelName` |

   See the implementation at [BuilderUpdateAssetPackageVersionHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderUpdateAssetPackageVersionHelper.cs#L51-L86).

4. When the server returns success, the tool will further call `WeChatNotifyWorkHelper.Run` to send a WeCom (enterprise WeChat) notification (if configured).

## Common Variations

- **Local upload only, no version reporting**: Keep `IsUpdateAssetPackageVersion` as `false` to skip the HTTP call.
- **Use a timestamp as the version number**: Leave `PackageVersion` empty, and the build will automatically fill it with a timestamp ([BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L98-L100)).
- **Report per platform separately**: Run a build for each `BuildTarget`; each run will report with the corresponding platform string as the `Platform` field.

## Common Errors

- **HTTP call throws an exception**: The request defaults to a 30-second timeout (`httpClient.Timeout = TimeSpan.FromSeconds(30)`). Exceptions are caught and logged via `Debug.LogException`. The build flow will not be interrupted, but the version will not have been reported successfully. Check the server-side logs or Unity Console for the stack trace.
- **Authorization not set**: When `UpdateAssetPackageVersionAuthorization` is an empty string, `httpClient.DefaultRequestHeaders.Add("Authorization", "")` will send an empty authorization header, which is usually rejected by the server. Please fill in the token agreed upon on the gateway side.
- **Remote URL is empty**: When `UpdateAssetPackageVersionUrl` is an empty string, a POST will be made to an invalid address, which will inevitably throw an exception.

## Background (Optional)

Version reporting is an optional final step in the build flow, disabled by default (`IsUpdateAssetPackageVersion = false`). It runs sequentially after the YooAsset build output is generated and uploaded to object storage; only on a successful response will it trigger the WeCom notification, so it can serve as a simple signal that the "build chain ultimately succeeded."
