# 진행 중인 이미지 로드를 취소하는 방법

`CancellationToken`을 통해 로드 작업을 취소하면 `LoadImageAsync`가 적절한 시점에 후속 처리를 중단하고 `null`을 반환합니다. 취소 메커니즘은 WebGL이 아닌 플랫폼에서만 유효하며, 다운로드 과정에서는 네트워크 요청을 즉시 중단하지 않습니다.

## 사전 조건

- `GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>()`를 통해 이미지 캐시 컴포넌트를 가져왔어야 합니다.
- 대상 컴파일 플랫폼이 WebGL이 아니어야 합니다(WebGL에서는 `cancellationToken`이 무시됩니다. 아래 「일반적인 오류」 참조).

## 작업 단계

1. **취소 가능한 토큰 소스 생성**. `CancellationTokenSource`를 사용하여 토큰을 생성하고 `Token` 속성을 통해 로드 인터페이스에 전달합니다.

   ```csharp
   using System.Threading;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   var component = GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>();
   var cts = new CancellationTokenSource();
   ```

2. **로드를 시작하고 토큰 전달**. `LoadImageAsync(url, cts.Token)`을 호출하여 `Task<Texture2D>`를 얻습니다.

   ```csharp
   var task = component.LoadImageAsync("https://example.com/foo.png", cts.Token);
   ```

3. **적절한 시점에 `Cancel()` 호출**. 페이지가 닫히거나 리스트 항목이回收되는 등의 상황에서 취소를 트리거합니다:

   ```csharp
   cts.Cancel();
   ```

4. **반환 결과 처리**. 취소된 작업은 `null`을 반환합니다(예외를 던지지 않음). 실패 분기를 따라 처리하면 됩니다:

   ```csharp
   var tex = await task; // 취소된 경우 null 반환
   if (tex == null) return;
   ```

   Source: [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## 일반적인 변형

- **`MonoBehaviour` 생명 주기에 자동 취소 연결**: `CancellationTokenSource`를 GameObject 생명 주기에 바인딩하고(예: 사용자 정의 `MonoBehaviour`의 `OnDestroy`에서 `cts.Cancel()` 호출), 장면 전환 시 수동으로 관리할 필요가 없습니다.
- **시간 초과 취소**: `cts.CancelAfter(TimeSpan.FromSeconds(5))`로 시간 초과 자동 취소를 설정합니다.
- **조건에 따라 여러 작업 취소**: 동일한 `CancellationTokenSource`를 사용하여 여러 `LoadImageAsync` 호출에 토큰을 공유하고, 한 번의 `Cancel()`로 모두 중단합니다.

## 일반적인 오류

| 현상 | 원인 | 수정 |
|------|------|------|
| WebGL 플랫폼에서 `Cancel()` 호출 후에도 작업이 계속 완료됨 | `LoadImageAsync`의 `#if UNITY_WEBGL` 분기에서는 `cancellationToken`을 받지 않음, [ImageCacheManager.cs#L84-L85](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L85) 참조 | WebGL에서는 비즈니스 계층 플래그를 통해 반환된 Texture2D를 직접 폐기해야 함 |
| 취소 후에도 다운로드가 백그라운에서 계속되고 디스크에 캐시 파일이 생성됨 | 현재 구현은 다운로드 **성공 완료 후**에만 토큰을 확인하므로 진행 중인 다운로드를 중단하지 않음, [ImageCacheManager.cs#L139-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L139-L149) 참조 | 요청을 완전히 중지하려면 취소 전에 `_downloadManager`를 통해 작업을 능동적으로 제거하거나, 비즈니스 계층에서 다운로드 결과를 무시해야 함 |
| `Cancel()` 후 await 작업에서 `OperationCanceledException` 발생 | 본 인터페이스는 `ThrowIfCancellationRequested`를 사용하지 않으며, 취소 시 일괄적으로 `null`을 반환함, [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149) 참조 | `if (tex == null)`로 취소를 판단하고 `OperationCanceledException`을 잡지 말 것 |

## 검증

취소가 성공하면 다음 두 조건을 만족하면 정상입니다:

- `await LoadImageAsync(...)`가 `null`을 반환함.
- `OperationCanceledException`이 발생하지 않으며, 후속 이미지 디코딩 로그도 없음(취소 확인 후 직접 `return null`을 수행하기 때문).

## 배경 (선택 사항)

WebGL이 아닌 분기의 `LoadImageDiskCacheAsync`는 「다운로드 완료 → 로컬 파일 읽기 준비」 사이에서 한 번만 `IsCancellationRequested`를 확인합니다. 따라서 취소의 실제 의미는 "다운로드 종료 후 해당 결과를放弃"하는 것이며, 네트워크 요청을 중단하는 것이 아닙니다. WebGL 플랫폼은 `UnityWebRequestTexture` + 브라우저 캐시를 통해 구현되므로 메서드 시그니처에 토큰이 노출되지 않아, 호출자는 결과를 받은 후에 자체적으로 사용할지 여부를 결정해야 합니다.
