# 동시성 제한 큐 사용 방법

`ConcurrentLimitedQueue<T>`는 스레드 안전을 보장하는 고정 길이 큐로, 요소 수가 용량上限에 도달하면 지정된 전략에 따라 자동으로 요소를 버리고, 버릴 때 콜백을 통해 호출자에게 알릴 수 있습니다.

## 사전 조건

- `GameFrameX.Foundation.Extensions` 네임스페이스를 가져옵니다.
- .NET 환경에서 사용 가능 (`System.Collections.Concurrent`에 의존).

## 작업 단계

### 1. 지정된 용량의 큐 생성

최대 길이를 전달하며, 기본값은 `DropOldest` 전략입니다(가득 찼을 때 가장 오래된 요소를 제거하고 새 요소를 추가).

```csharp
using GameFrameX.Foundation.Extensions;

var queue = new ConcurrentLimitedQueue<int>(limit: 3);
queue.Enqueue(1);
queue.Enqueue(2);
queue.Enqueue(3);
queue.Enqueue(4); // 이때 1이 자동으로 제거되어 큐에 [2, 3, 4]가 남음
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L91-L110)

### 2. 오버플로 전략 선택

`LimitedQueueOverflowStrategy`를 통해 큐가 가득 찼을 때의 처리 방식을 선택합니다.

| 전략 | 동작 |
|------|------|
| `DropOldest` | 가장 오래된 요소를 제거하고 새 요소를 추가 (기본값) |
| `DropNewest` | 새 요소를 버리고 큐를 그대로 유지 |
| `RejectNewItem` | 새 요소를 거부하며 버림 알림을 트리거하지 않음 |
| `Throw` | `InvalidOperationException`을 던짐 |

```csharp
var queue = new ConcurrentLimitedQueue<string>(limit: 2, LimitedQueueOverflowStrategy.DropNewest);
queue.Enqueue("a");
queue.Enqueue("b");
queue.Enqueue("c"); // "c"가 버려지고 큐에는 여전히 ["a", "b"]가 있음
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L245-L266)

### 3. 버림 이벤트 구독

`ItemDiscarded` 콜백을 통해 버려진 요소를 모니터링하여, 카운팅, 로그 기록 또는 보상 처리에 사용할 수 있습니다.

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 2, LimitedQueueOverflowStrategy.DropOldest)
{
    ItemDiscarded = item =>
    {
        Console.WriteLine($"버려진 요소 {item.Item}, 사유 {item.Reason}");
    }
};
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L138-L140)

### 4. 용량上限 조정

`Limit` 할당 또는 `SetLimit` 메서드를 통해 용량을 동적으로 조정합니다. 용량을 줄일 때 제거된 요소는 콜백에서 `LimitReduced` 사유로 알림이 발생합니다.

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 5);
for (var i = 0; i < 5; i++) queue.Enqueue(i);

queue.SetLimit(2); // 초과 요소를 제거하고 콜백에서 Reason이 LimitReduced로 전달됨
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L276-L296)

### 5. 디큐 및 조회

표준 동시성 큐 의미를 사용합니다. `TryDequeue` / `TryPeek` / `ToArray` / `Clear`를 모두 사용할 수 있습니다.

```csharp
if (queue.TryPeek(out var head))
{
    Console.WriteLine($"대기열 머리: {head}");
}

if (queue.TryDequeue(out var first))
{
    Console.WriteLine($"디큐: {first}");
}
```

## 일반적인 변형

- **기존 컬렉션에서 초기화**: `new ConcurrentLimitedQueue<int>(new List<int> { 1, 2, 3 })` 또는 암시적 변환 `ConcurrentLimitedQueue<int> q = new List<int> { 1, 2, 3 };`을 사용하면, 용량이 자동으로 컬렉션 크기로 설정됩니다.
- **`IProducerConsumerCollection<T>`로 사용**: `TryAdd` / `TryTake`를 직접 호출할 수 있으며, 내부적으로 `TryEnqueue` / `TryDequeue`를 거칩니다.
- **콜백 내에서 동일한 큐에 다시 접근하지 않기**: `ItemDiscarded`는 내부 잠금 밖에서 트리거되므로 콜백 내의 인큐/디큐는 안전하지만, 장시간 차단하는 것은 피해야 합니다.

## 일반적인 오류

| 오류 | 설명 |
|------|------|
| `limit <= 0`일 때 생성 시 `ArgumentOutOfRangeException` 던짐 | 용량은 0보다 커야 함 |
| 빈 컬렉션을 전달하여 생성 시 `ArgumentOutOfRangeException` 던짐 | 컬렉션 요소 수는 0보다 커야 함 |
| `OverflowStrategy.Throw`가 가득 찬 큐에 인큐할 때 `InvalidOperationException("The limited queue has reached its capacity.")` 던짐 | 호출자가 예외를 잡거나 다른 전략을 사용해야 함 |
| `RejectNewItem`을 사용하면서 `DropOldest`가 `ItemDiscarded`에서 트리거되길 기대함 | `RejectNewItem`은 버림 알림을 트리거하지 않음 |

## 배경 지식 (선택 사항)

`ConcurrentLimitedQueue<T>`는 내부적으로 `ConcurrentQueue<T>`를 캡슐화하며, 독립적인 `_syncRoot`를 사용하여 용량 카운트와 인큐 오버플로 로직을 보호합니다. 이를 통해 용량 조정과 인큐 전략 판정을 동일한 임계 영역 내에서 원자적으로 완료합니다.底层의 `ConcurrentQueue` 자체는 스레드 안전 요소 접근을 보장합니다.
