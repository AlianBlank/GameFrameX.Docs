# 使用 Luban 設定表與 TablesComponent 載入

`TablesComponent` 是 GameFrameX.Config 中由 Luban 工具自動產生的設定表容器,負責在執行階段將所有 `.json` 設定表載入 `ConfigComponent`,並解析各表之間的參考關係。讀完本頁，你將能在伺服器端或用戶端啟動時一次性載入所有 Luban 表，並視需要存取具體條目。

## 前置條件

- 已透過 Luban 工具產生 `GameFrameX.Config` 專案，產出中包含 `TablesComponent.cs` 與 `Tables/*.cs`、`Local/*.cs`。
- 專案已參考 `GameFrameX.Core.Abstractions`(提供 `ConfigComponent` 與 `BeanBase`)。
- 準備好 Luban 匯出的 JSON 檔案(`tables_tbxxx`、`local_tblocalization` 等命名慣例)，部署到可被 `loader` 回呼讀取的位置(本機檔案、AssetBundle、遠端下載皆可)。

## 操作步驟

1. **具現化設定管理員**。`ConfigComponent` 內部已建立好 `TablesComponent`,直接使用即可：

   ```csharp
   var configComponent = new ConfigComponent();
   var tables = configComponent.Tables; // 私有屬性,需要經由下方 Init 注入
   ```

   Source: [ConfigComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/ConfigComponent.cs#L14-L19)

2. **呼叫 `Init` 注入 `ConfigComponent`**。這一步將表註冊入口交給 `ConfigComponent`,後續 `Add` 時會將表寫入統一容器：

   ```csharp
   tables.Init(configComponent);
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

3. **提供 `loader` 回呼並非同步載入**。`loader` 接收表名，回傳該表 JSON 的 `JsonElement`。所有表並行載入，完成後自動 `Refresh` 解析參考：

   ```csharp
   await tables.LoadAsync(async tableName =>
   {
       var json = await File.ReadAllTextAsync($"Configs/{tableName}.json");
       return JsonDocument.Parse(json).RootElement.Clone();
   });
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L56)

4. **讀取特定表與條目**。載入完成後，透過 `TablesComponent` 的強型別屬性取得特定表物件。例如：

   ```csharp
   var itemConfig = tables.TbItemConfig;
   var oneItem = itemConfig.Get(1001); // 由 Luban 產生的索引/查詢方法
   ```

   `TablesComponent` 目前公開的表屬性:`TbLocalization`、`TbAchievementConfig`、`TbItemConfig`、`TbSoundsConfig`。

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L18-L21)

5. **(選用)在熱更新場景重新載入**。再次呼叫 `LoadAsync` 前不需要 `Init`;`loader` 會再次讀取每個表的最新 JSON,`Refresh()` 會重新執行 `PostInit` 與 `ResolveRef`,覆寫之前的參考關係。

## 常見變體

- **遠端下載 + 本機快取**：將 `loader` 實作成「先查本機快取，未命中走 HTTP,下載後寫入磁碟並解析 JSON」,即可讓 Luban 表支援 CDN 熱更。
- **從 AssetBundle 讀取**：在用戶端將 `loader` 替換為 `Resources.LoadAsync<TextAsset>(tableName).Result.text`,保持函式簽章一致即可，無需改動 `TablesComponent`。
- **部分表延遲載入**：將不需要啟動時載入的表從 `LoadAsync` 中註解掉(註解程式碼已保留在產生的檔案中)，改由業務端視需要 `new TbXxx(...)` 載入。

## 常見錯誤

- **找不到表 JSON**:`loader` 拋出例外會讓 `Task.WhenAll` 失敗，整個 `LoadAsync` 會跟著拋出；確保檔案命名嚴格遵循 `tables_xxx` / `local_xxx` 前綴。
- **參考解析失敗**:`Refresh()` 內部會呼叫每個表的 `ResolveRef(this)`;若 `PostInit` 或 `ResolveRef` 中存取尚未載入的表，會觸發空值參考，需確保所有相關表都透過 `LoadAsync` 走過一遍。
- **重複 `Init`**:再次呼叫 `Init` 會再次執行 `RemoveAllConfigs()`,會清空已載入的表參考，通常只在重設場景使用。
- **修改產生的檔案**:`TablesComponent.cs` 與 `Tables/*.cs` 頂端都標記了 `// <auto-generated>`,任何手寫改動會在下次 Luban 重新產生時被覆寫。

## 背景(選用)

`TablesComponent` 是 Luban `gen_cs_server_json` / `gen_cs_client_json` 範本的產出：每張表對應一個 `BeanBase` 子類別(如 [`ItemConfig`](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Tables/ItemConfig.cs#L15-L76)),建構函式從 `JsonElement` 反序列化欄位，`ResolveRef` 用於在表之間將 `xxx_ref` 欄位連結回具體的資料列物件。
