# 如何实现自定义对象存储提供方

通过实现 `IObjectStorageManager` 与 `IObjectStorageUploadManager` 两个接口并接入 `ObjectStorageUploadFactory`,你可以在 GameFrameX 对象存储框架里加入任意一种新的后端(例如自建 MinIO、华为 OBS、七牛、又拍、内部文件服务器等),让上传流程像内置提供方一样被工厂统一调度。

## 前置条件

- 已在 Unity 工程中安装 `com.gameframex.unity.objectstorage` 包。
- 你要对接的后端具备:accessKey / secretKey / bucketName / endpoint 四项基本参数,并能响应标准对象存储协议(分片/上传/进度回调)。
- 准备一个放置自定义提供方实现的 Editor 程序集(放在任意 `Editor/` 目录下的 `.asmdef` 中),避免污染运行时。

## 操作步骤

1. **创建提供方实现类**,同时实现 `IObjectStorageManager` 和 `IObjectStorageUploadManager` 两个接口。`IObjectStorageManager.Init` 用于接收凭据和桶信息,`IObjectStorageUploadManager` 负责实际的上传、分片与进度回调。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;

   namespace GameFrameX.ObjectStorage.Editor
   {
       public sealed class MyCustomObjectStorageManager
           : IObjectStorageManager, IObjectStorageUploadManager
       {
           public void Init(string accessKey, string secretKey,
                            string bucketName, string endpoint = null)
           {
               // 保存到内部字段,供上传方法使用
           }

           // 实现 IObjectStorageUploadManager 的上传方法 ...
       }
   }
   ```

   `IObjectStorageManager` 接口定义见 [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13),`Init` 方法签名如下:

   ```csharp
   void Init(string accessKey, string secretKey, string bucketName, string endpoint = null);
   ```
   Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L12)

2. **实现上传与进度回调逻辑**。参考 `BaseObjectStorageUploadManager` 的职责划分:基类负责通用的分片、重试、进度聚合;你的子类只需要把"鉴权头构造"和"分片 PUT/POST"换成自家后端协议即可。基类入口在 [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs)。

3. **注册到工厂**。打开 [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs),在工厂的创建/选择分支里加入你的提供方类型,使工厂可以根据配置返回你的实现实例。

4. **在调用方按工厂获取**。上传侧不需要改动,通过 `ObjectStorageUploadFactory` 取到 `IObjectStorageUploadManager` 即可:

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create(providerName);
   ((IObjectStorageManager)uploader).Init(accessKey, secretKey, bucketName, endpoint);
   uploader.Upload(localPath, remoteKey, onProgress, onComplete);
   ```

## 常见变体

- **同一协议、不同厂商**:例如 AWS S3、阿里 OSS、腾讯 COS 都兼容 S3 协议,可以让一个实现类支持多个 `endpoint`,在 `Init` 时区分签名区域。
- **无 endpoint 的内网存储**:把 `endpoint` 留空,实现内部根据 `bucketName` 拼出内网地址。
- **多凭据轮询**:在 `Init` 里允许传入凭据列表,上传时分片前自动续签 token。

## 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| 工厂返回的是内置提供方 | 没有把自己的类型注册到 `ObjectStorageUploadFactory` | 在工厂选择分支里加入新 provider 名 |
| `Init` 后上传报 401/403 | accessKey/secretKey 与 endpoint 区域不匹配 | 在 `Init` 里校验区域并打印实际请求地址 |
| 进度永远停在 0 | 实现类没把分片回调转换为 `IObjectStorageUploadManager` 的进度事件 | 参考 `BaseObjectStorageUploadManager` 的进度聚合点 |
| Unity 运行时找不到类型 | 实现类放进了运行时程序集而不是 Editor 程序集 | 把代码放到任意 `Editor/` 目录,并确认 `.asmdef` 包含 `Editor` 平台 |

## 背景(可选)

框架把"管理凭据"和"执行上传"分成两个接口:`IObjectStorageManager` 只关心凭据初始化,`IObjectStorageUploadManager` 关心实际的网络分片与进度;两者通常由同一个类实现,工厂根据 provider 名选出一个实例,既统一了调用入口,也便于替换后端。
