# 如何使用 Snowflake 生成分布式唯一 ID

通过 `SnowFlakeIdHelper.Instance.NextId()` 一行即可生成全局唯一、有序递增的 64 位整数 ID,并可在需要时把 ID 反解为时间戳、WorkerId、DataCenterId 与序列号。

## 前置条件

- 引用命名空间:`GameFrameX.Foundation.Utility.DistributedSystem.Snowflake`
- 项目已引用 `GameFrameX.Foundation.Utility` 程序集
- 若是多实例部署,需要为每个节点配置互不相同的 `WorkId`(0~31)和 `DataCenterId`(0~31),否则会生成重复 ID

## 操作步骤

1. **最简用法:直接取单例生成 ID**

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   long id = SnowFlakeIdHelper.Instance.NextId();
   ```

   `Instance` 内部采用双重检查锁定的单例,首次访问时按当前 `WorkId=1`、`DataCenterId=1`、`BaseTime=2025-01-01 UTC` 初始化 `IdWorker`。
   Source: [SnowFlakeIdHelper.cs#L181-L204](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L181-L204)

2. **手动指定节点 ID(单实例或测试)**

   必须在第一次访问 `Instance` **之前**设置,否则不会生效。

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   SnowFlakeIdHelper.WorkId = 2;
   SnowFlakeIdHelper.DataCenterId = 3;
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L133-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L133-L145)

3. **使用 WorkerIdProvider 自动分配节点 ID**

   框架内置了基于主机名、IP、进程号等策略,只需在首次访问 `Instance` 前注入即可。

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   // 例:用 IP 哈希自动得到 WorkId(0~31)
   SnowFlakeIdHelper.SetWorkerIdProvider(new IpAddressWorkerIdProvider());
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L97-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L97-L100)

4. **(可选)修改基准时间或位宽**

   当默认的 `2025-01-01 UTC` 起点需要调整,或希望自定义 WorkerId/序列号位宽时,在首次访问前修改:

   ```csharp
   SnowFlakeIdHelper.BaseTime = new DateTime(2020, 1, 1, 0, 0, 0, DateTimeKind.Utc).Ticks / 10000;
   SnowFlakeIdHelper.WorkerIdBits = 5;        // 默认 5
   SnowFlakeIdHelper.DatacenterIdBits = 5;    // 默认 5,可设为 0 表示不使用数据中心维度
   SnowFlakeIdHelper.SequenceBits = 12;       // 默认 12,单毫秒最多 4096 个 ID
   ```
   Source: [SnowFlakeIdHelper.cs#L64-L160](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L64-L160)

5. **(可选)反解 ID 查看其组成**

   ```csharp
   long id = SnowFlakeIdHelper.Instance.NextId();

   // 使用默认 BaseTime 解析
   SnowFlakeIdInfo info = SnowFlakeIdParser.Parse(id);

   // 或自定义 BaseTime/位宽
   SnowFlakeIdInfo custom = SnowFlakeIdParser.Parse(
       id,
       baseTimeMs: SnowFlakeIdHelper.BaseTime,
       workerIdBits: 5,
       datacenterIdBits: 5,
       sequenceBits: 12);

   Console.WriteLine($"时间={info.Timestamp:o}, Worker={info.WorkerId}, DC={info.DataCenterId}, Seq={info.Sequence}");
   ```

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 不同机器/进程生成出重复 ID | 双方 `WorkId` 或 `DataCenterId` 相同 | 用 `SetWorkerIdProvider` 自动分配,或为每台机器配置唯一编号 |
| 调整 `WorkId` / `BaseTime` / 位宽后没生效 | 已经在某处访问过 `Instance`,单例已创建 | 在程序启动早期、所有调用前完成配置,或在测试间用独立的 `IdWorker` 实例 |
| 解析旧 ID 时时间戳异常 | 用错了 `BaseTime` 或位宽 | 解析时显式传入与生成时一致的 `baseTimeMs` 与 `workerIdBits`/`datacenterIdBits`/`sequenceBits` |
| `Parse` 报 `ArgumentOutOfRangeException` | ID 为负数 | Snowflake ID 必须非负,检查是否与其它 ID 类型混用 |
| 系统时间回拨导致生成阻塞或异常 | 雪花算法对时钟回拨敏感 | 保证 NTP 同步、回拨时使用自定义 `IdWorker` 捕获 `InvalidSystemClock`,避免直接抛错 |

## 背景(可选)

默认位宽布局为 `1 符号位 | 41 时间戳位 | 5 数据中心位 | 5 工作节点位 | 12 序列号位`,单节点单毫秒可生成 4096 个 ID。基准时间设为 `2025-01-01 UTC`,在 41 位时间戳下可使用约 69 年。`SnowFlakeIdParser` 使用完全相同的位运算公式,因此只要 `BaseTime` 与位宽一致,即可无损反解。关于其它分布式 ID 方案的对比,见《分布式 ID 选型》。
