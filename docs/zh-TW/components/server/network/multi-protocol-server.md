# 啟用 TCP / WebSocket / HTTP 多協定監聽

在 GameFrameX.Server 啟動進入點中視需要開啟 TCP、WebSocket、HTTP 三種網路監聽，讓同一套業務程式碼同時對外提供不同的協定端點，常用於多端整合(原生 TCP、網頁/H5、小程式、外部 HTTP API)。

## 前置條件

- 已完成 [GameFrameX.Server](https://github.com/GameFrameX/GameFrameX.Server) 的本機建置與基礎設定。
- 確認對外連接埠未被佔用，防火牆已放行對應的 TCP 連接埠(框架預設監聽連接埠見下表)。
- 已熟悉 `GameFrameX.StartUp` 命名空間下 `AppStartUpGame` 等啟動類別的呼叫順序。

## 操作步驟

1. 開啟啟動進入點檔案 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`,框架的協定註冊與啟動流程集中於此。

2. 依業務需要，在 `AppStartUpGame` 中呼叫 `UseServer` 或對應的擴充方法，同時傳入 `tcpOptions`、`wsOptions`、`httpOptions` 三個設定節點。任一節點省略即關閉對應協定。

3. 在設定檔(預設 `App.Config.json` 或由環境變數覆寫)中寫入以下結構，框架在啟動時會自動依 `Enable*` 開關決定是否監聽對應協定：

```json
{
  "Server": {
    "Tcp":    { "Enable": true,  "Host": "0.0.0.0", "Port": 30100 },
    "WebSocket": { "Enable": true, "Host": "0.0.0.0", "Port": 30101, "Path": "/" },
    "Http":   { "Enable": true,  "Host": "0.0.0.0", "Port": 30102 }
  }
}
```

4. 啟動 `GameFrameX.Launcher`,執行日誌會出現類似 `Tcp Server Started`、`WebSocket Server Started`、`Http Server Started` 的提示，表示三條鏈路已並行監聽。

5. 在任意一處業務程式碼中透過 `INetSession` 或 `HttpContext` 處理訊息，框架會根據連線進入的連接埠/路徑自動派發到對應的協定通道，無需在業務層區分協定。

```csharp
// 註冊訊息處理(對 TCP / WebSocket 一致)
[MessageHandler(MessageId.C2S_Login)]
public class C2S_LoginHandler : IMessageHandler
{
    public async Task HandleAsync(INetSession session, C2S_Login request)
    {
        // 業務邏輯
    }
}
```

來源:[GameFrameX.Launcher/StartUp/AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L1-L120)

## 常見變體

- **僅啟用 TCP**:把 `Tcp.Enable` 設為 `true`,其餘兩項設為 `false`,常用於純閘道服。
- **WebSocket + HTTP 共存**：H5 頁使用 WebSocket,管理後台或回呼通知走 HTTP,兩者共用同一行程與同一套 Actor。
- **關停單一協定**：將對應節點的 `Enable` 設為 `false` 即可，無需修改程式碼。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 啟動時報 `Address already in use` | 多個協定使用了同一連接埠，或被其他行程佔用 | 每個協定使用不同 `Port`,並確認 OS 連接埠空閒 |
| WebSocket 用戶端連線後立即斷線 | `Path` 或子協定不相符 | 保持 `Path` 與用戶端 URL 一致(如 `ws://host:port/` ) |
| HTTP 介面 404 | 未注入 `Enable*` 設定或缺少控制器 | 檢查 `Http.Enable=true` 並確保控制器已註冊 |
| TCP 能連線但收不到訊息 | 啟動順序問題，業務 Actor 未註冊 | 確認 `AppStartUpHotfixGameByEntry` 等被 `AppStartUpGame` 依序呼叫 |

## 背景(可選)

`AppStartUpGame` 透過 `GameFrameX.StartUp` 提供的統一入口對應用伺服器協定堆疊進行初始化，使用同一套訊息路由與工作階段(`INetSession`)抽象承載三種協定，因此業務處理層(參見 `Component/ServerComponent.cs`)只需面向訊息互動，不關心底層傳輸方式。

更多關於整體啟動流程與 `ServerComponent` 的說明，見《Server 元件》。
