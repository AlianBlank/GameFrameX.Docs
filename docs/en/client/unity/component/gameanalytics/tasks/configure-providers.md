# How to Add and Configure Analytics Providers

In the Inspector of the `GameAnalyticsComponent` component, add types that implement `IGameAnalyticsManager` to the "Game Analytics Component List (Report in Order)" list, and fill in the `Setting` key-value pairs for each entry; at runtime, the component automatically instantiates all Providers via reflection and calls their `Init`, after which all reporting APIs are forwarded to each Provider in list order.

## Prerequisites

- The package `com.gameframex.unity.gameanalytics` is installed.
- A `GameAnalyticsComponent` already exists in the scene (can be added via `Add Component → Game Framework → GameAnalytics`).
- The scene contains at least one analytics implementation class implementing the `IGameAnalyticsManager` interface (usually provided by each third-party SDK adapter package); otherwise, the Inspector dropdown will only show None.

## Steps

1. Select the GameObject with `GameAnalyticsComponent` attached; the Inspector will be drawn by `GameAnalyticsComponentInspector` as a reorderable list titled "Game Analytics Component List (Report in Order)".

2. Click the `+` at the bottom right of the list to add a new entry. Each entry corresponds to a `GameAnalyticsComponentProvider`, whose serialized fields are as follows:

| Field | Type | Description |
|------|------|------|
| `ComponentType` | `string` | Full type name of the class implementing `IGameAnalyticsManager`, automatically written by the dropdown |
| `ComponentTypeNameIndex` | `int` | Current index of the editor dropdown, not used at runtime |
| `Setting` | `List<GameAnalyticsComponentParamKV>` | Initialization parameters passed to this Provider, each item is a pair of `Key`/`Value` strings |

```csharp
[Serializable]
public class GameAnalyticsComponentProvider
{
    /// <summary>
    /// Implemented component type
    /// </summary>
    public string ComponentType;

    /// <summary>
    /// This is used by the editor
    /// </summary>
    public int ComponentTypeNameIndex = 0;

    /// <summary>
    /// Parameters
    /// </summary>
    public List<GameAnalyticsComponentParamKV> Setting = new List<GameAnalyticsComponentParamKV>();
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L361-L378)

3. Select the target implementation class in the `ComponentType` dropdown. Dropdown items are generated by the Inspector by collecting all runtime types of `IGameAnalyticsManager` via reflection; once selected, the type name is written to the `ComponentType` string:

```csharp
managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

4. Fill in the initialization parameters required by this Provider in `Setting` (such as AppKey, Channel, and other keys defined by the specific SDK implementation). If the implementation assembly contains a class inheriting from `BaseGameAnalyticsSetting`, the Inspector will automatically fill in the Setting entries based on its public fields; you only need to fill in the Values:

5. Enter Play mode. The component calls `Init()` in `OnEnable`, creating an instance via reflection for each entry and converting `Setting` into a dictionary to pass in:

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L79)

6. Use the list's drag handle to adjust the order. The order only affects forwarding order, not functionality; `Init` and all subsequent reporting calls execute in list order.

## Common Variants

- **SDKs requiring supplementary initialization after login**: Some Providers implement `IsManualInit()`; after obtaining user information, call the component's `ManualInit(Dictionary<string, string> extraArgs)`, and the component will forward `extraArgs` to all Providers requiring manual initialization:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

- **Setting Player ID / Common properties**: Calls to `SetPlayerId(string playerId)`, `SetPublicProperties(string key, object value)`, `ClearPublicProperties()` are synchronously forwarded to all Providers in the list, no need to call each one individually.
- **Custom Providers**: Create a new class implementing `IGameAnalyticsManager` (see the interface definition in [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8)); it must provide a parameterless constructor (the component instantiates it with `Activator.CreateInstance`); if you want the Inspector to automatically generate Setting keys, also define a class inheriting from `BaseGameAnalyticsSetting` in the same assembly and declare each configuration item as a public field.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Log `Can not find component type 'XXX'.`, the entry is skipped | The `ComponentType` type name cannot be resolved via `Utility.Assembly.GetType`: the assembly containing the implementation class was not included in the build, or the serialized value was manually edited | Confirm the implementation package is imported and re-select the type in the Inspector dropdown |
| Log `GameAnalyticsManager is not init.` | A reporting API was called before the component's `Init` (e.g., the component was disabled so `OnEnable` did not run) | Ensure `GameAnalyticsComponent` is enabled; call `Init()` manually if necessary |
| An entry is silently ignored with no errors at all | `ComponentType` is left empty; the `IsNotNullOrWhiteSpace` check in `Init` fails and the entry is skipped directly | Select an implementation type in the dropdown for that entry |
| `ManualInit` call has no effect | `ManualInit` returns directly when `m_IsInit` is false; or that Provider's `IsManualInit()` returns false | First confirm `Init` was triggered after entering Play, then check the implementation's `IsManualInit` logic |
| After modifying Inspector configuration, the old configuration is still used at runtime | `Init` is guarded by `m_IsInit` and only takes effect on the first call | Restart Play mode; do not expect repeated `Init` calls during runtime to take effect |

## Verification

- After entering Play, no `Can not find component type` errors appear in the Console, meaning all entries' types resolved successfully.
- No `GameAnalyticsManager is not init.` warnings appear when calling forwarding APIs such as `SetPlayerId`, meaning the Provider list has finished initializing.
- Set breakpoints or add logs inside each Provider implementation's `Init(Dictionary<string, string>)` to confirm the key-values in `Setting` are passed in as configured.

## Background

The component does not directly depend on any specific SDK: during `Init`, it uses reflection to create instances based on `ComponentType`, converts the `Setting` list into a `Dictionary<string, string>` and passes it to `Init(args)`; afterwards, all public APIs (set/reporting, etc.) iterate over `m_GameAnalyticsManager` and forward one by one, enabling multiple analytics SDKs to report simultaneously in order.
