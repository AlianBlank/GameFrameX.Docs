# How to Define Entity Business Logic (EntityLogic)

By inheriting from the `EntityLogic` base class and overriding lifecycle methods, a Unity `MonoBehaviour` can be integrated into GameFrameX's entity management system, automatically receiving callbacks for show/hide/update/parent-child attachment and more.

## Prerequisites

- The `com.gameframex.unity.entity` package is installed (see "Quick Start").
- The prefab must have the `Entity` component attached; the `EntityLogic` subclass script should be attached to the same GameObject.

## Steps

1. **Create a script and inherit from `EntityLogic`**. The file name must match the class name and can be placed anywhere under `Assets/Scripts/`.

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
   }
   ```

   Source: [Runtime/Entity/EntityLogic.cs#L35-L40](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L35-L40)

2. **Override lifecycle methods**. `EntityLogic` provides 7 `protected internal virtual` callbacks; override them as needed, and remember to call the `base` methods to preserve base class behavior.

   ```csharp
   using GameFrameX.Entity.Runtime;
   using UnityEngine;

   public class PlayerEntity : EntityLogic
   {
       protected internal override void OnInit(object userData)
       {
           base.OnInit(userData);
           // Initialize component references, etc.
       }

       protected internal override void OnShow(object userData)
       {
           base.OnShow(userData);
           // Called when the entity is shown
       }

       protected internal override void OnHide(bool isShutdown, object userData)
       {
           base.OnHide(isShutdown, userData);
           // Called when the entity is hidden
       }

       protected internal override void OnUpdate(float elapseSeconds, float realElapseSeconds)
       {
           base.OnUpdate(elapseSeconds, realElapseSeconds);
           // Per-frame update logic
       }
   }
   ```

   Source: [Runtime/Entity/EntityLogic.cs#L110-L198](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityLogic.cs#L110-L198)

3. **Attach the script to the prefab**. Open the prefab in the Unity editor and drag the `PlayerEntity` component onto the same GameObject as the `Entity` component (or attach it to any child object; it can still be found by `Entity` via `GetComponentInChildren`).

4. **Show the entity via `EntityComponent`**. `EntityLogic` is automatically instantiated by the framework when the entity is shown; the business side only needs to call `ShowEntityAsync<T>`.

   ```csharp
   var entityComponent = GameEntry.GetComponent<EntityComponent>();

   IEntity entity = await entityComponent.ShowEntityAsync<PlayerEntity>(
       entityId: 1,
       entityAssetName: "Assets/Prefabs/Player.prefab",
       entityGroupName: "PlayerGroup"
   );
   ```

   Source: [README.zh-CN.md#L99-L145](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/README.zh-CN.md#L99-L145)

## Overridable Lifecycle Methods

| Method | Trigger Timing | Notes |
|------|----------|------|
| `OnInit(object userData)` | First initialization of the entity | Caches the `Transform`, saves the original `Layer`, and obtains the `Entity` reference |
| `OnShow(object userData)` | Entity enters the shown state | The framework automatically sets `Available` to `true` and sets `Visible = true` |
| `OnHide(bool isShutdown, object userData)` | Entity is hidden | `isShutdown=true` indicates it was triggered by the manager shutdown; the framework restores the original `Layer` |
| `OnUpdate(float, float)` | Every frame while shown | Parameters are logical elapsed seconds and real elapsed seconds |
| `OnRecycle()` | Entity is returned to the object pool | Used to release external resource references |
| `OnAttached` / `OnAttachTo` | A child entity is attached to this entity | By default, sets `CachedTransform.SetParent(parentTransform)` |
| `OnDetached` / `OnDetachFrom` | A child entity is detached | By default, restores the `Transform` to its original parent |
| `InternalSetVisible(bool)` | When visibility changes | By default, calls `gameObject.SetActive(visible)`; can be overridden to customize toggle logic |

## Common Properties

| Property | Type | Description |
|------|------|------|
| `Entity` | `Entity` | Reference to the associated entity component |
| `Name` | `string` | Reads/writes `gameObject.name` |
| `Available` | `bool` | Whether the entity is available; controlled by `OnShow`/`OnHide` |
| `Visible` | `bool` | Whether the entity is visible; assigning a value while unavailable outputs `Log.Warning("Entity '{0}' is not available.", Name)` |
| `CachedTransform` | `Transform` | Cached `Transform`, assigned during the first `OnInit` |

## Common Mistakes

- **Not calling `base`**. The base class's `OnInit` caches the `Transform` and saves the original `Layer`, `OnShow` sets `Available=true`, and `OnHide` restores the `Layer`; skipping `base` can cause abnormal visibility, layer, and child node states.
- **Accessing `Available` outside the lifecycle**. When the entity is not shown, `Available` is `false`; writing to `Visible` at that point is intercepted by the base class with a warning, and the logic will not execute.
- **Directly using `new` on an `EntityLogic` subclass**. It must be attached to a prefab and created by `EntityComponent` through the object pool; manually using `new` bypasses the framework's event dispatch and object pool recycling.

## Background (Optional)

`EntityLogic` has its corresponding `protected internal` virtual methods triggered by the `partial` `EntityManager` on show/hide/recycle, allowing business classes to remain unaware of object pooling, resource loading, and hierarchy management. All methods have the `protected internal` access modifier, meaning they can only be triggered within the same assembly or when explicitly called by `EntityManager`, and should not be called manually in business code.
