# 엔티티에 감사/소프트 삭제/캐시 기능을 적용하는 방법

`AuditTableAttribute`, `SoftDeleteAttribute`, `CacheTableAttribute` 세 가지 특성을 사용하면 엔티티 클래스에서 한 줄로 ORM의 감사 추적, 소프트 삭제, 쿼리 캐시 기능을 선언하여 활성화할 수 있으며, 비즈니스 코드를 변경하지 않고도 ORM 프레임워크가 인식할 수 있습니다.

## 사전 조건

- 프로젝트에서 `GameFrameX.Foundation.Orm.Attribute` 어셈블리(세 가지 특성 클래스 포함)와 `GameFrameX.Foundation.Orm.Entity`(`IAuditableEntity` 인터페이스 포함)를 참조합니다.
- 엔티티 클래스에서 `GameFrameX.Foundation.Orm.Attribute` 네임스페이스의 특성을 사용하며, 파일에 `using GameFrameX.Foundation.Orm.Attribute;`를 추가합니다.
- 자동 채워지는 "생성/수정 시간/작업자" 필드를 얻으려면 엔티티가 `IAuditableEntity` 인터페이스(`GameFrameX.Foundation.Orm.Entity` 네임스페이스)를 구현하도록 합니다.

## 작업 단계

### 1. 감사 추적 활성화

엔티티 클래스에 `[AuditTable]`을 지정하기만 하면 됩니다. 기본값은 `Enabled = true`, `AuditLevel = ChangesOnly`, `IncludeUserInfo = true`이며, INSERT/UPDATE/DELETE의 변경 이력을 기록합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[AuditTable(AuditLevel = AuditLevel.Full, IncludeUserInfo = true, IncludeIpAddress = true)]
public class UserAccount
{
    public int Id { get; set; }
    public string Username { get; set; }
    public decimal Balance { get; set; }
    public DateTime LastLoginTime { get; set; }
}
```

Source: [AuditTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/AuditTableAttribute.cs#L74-L143)

감사 테이블 이름을 사용자 정의하려면 `AuditTableName`을 구체적인 테이블 이름으로 설정하고, 감사를 비활성화하려면 `Enabled`를 `false`로 설정하세요.

### 2. 소프트 삭제 활성화

생성자에서 최소한 "소프트 삭제 표시 필드"를 전달하고, 필요에 따라 "삭제 시간 필드"와 "삭제 사용자 필드"를 전달합니다. 기본값은 `AutoFilter = true`이며, 쿼리 시 자동으로 삭제된 레코드를 제외합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[SoftDelete("IsDeleted", "DeletedTime", "DeletedBy")]
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }
    public string? DeletedBy { get; set; }
}
```

Source: [SoftDeleteAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SoftDeleteAttribute.cs#L74-L175)

표시 필드가 `bool`이 아닌 경우, 속성에서 `DeletedValue`와 `NotDeletedValue`를 사용자 정의할 수 있습니다. 예를 들어 문자열 `"DELETED"` / `"ACTIVE"`로 상태를 식별할 수 있습니다.

### 3. 쿼리 캐시 활성화

엔티티 클래스에 `[CacheTable]`을 지정하면, ORM 프레임워크가 `CacheType` + `ExpireMinutes`에 따라 해당 캐시 전략을 활성화합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[CacheTable(CacheType = "Redis", ExpireMinutes = 30, KeyPrefix = "ProductInfo:")]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public DateTime LastModified { get; set; }
}
```

Source: [CacheTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/CacheTableAttribute.cs#L74-L137)

### 4. 조합 사용: 감사 + 소프트 삭제 + 감사 가능 필드

엔티티가 동시에 `IAuditableEntity`를 구현하도록 하면, ORM이 쓰기 시 `CreateTime`, `UpdateTime`, `CreateUserId/Name`, `UpdateUserId/Name` 필드를 자동으로 유지 관리하며, `[AuditTable]`과 함께 완전한 감사闭环를 형성합니다.

```csharp
using GameFrameX.Foundation.Orm.Attribute;
using GameFrameX.Foundation.Orm.Entity;

[AuditTable(AuditLevel = AuditLevel.ChangesOnly)]
[SoftDelete("IsDeleted", "DeletedTime")]
[CacheTable(CacheType = "Memory", ExpireMinutes = 10)]
public class OrderInfo : IAuditableEntity
{
    public int Id { get; set; }
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }

    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }

    public DateTime? CreateTime { get; set; }
    public DateTime? UpdateTime { get; set; }
    public long? CreateUserId { get; set; }
    public string? CreateUserName { get; set; }
    public long? UpdateUserId { get; set; }
    public string? UpdateUserName { get; set; }
}
```

## 일반적인 변형

- **필드만 감사하고 사용자는 기록하지 않음**: `IncludeUserInfo`를 `false`로 설정하여 사용자로 추적할 필요가 없는 시나리오에서 중복 필드를 저장하지 않도록 합니다.
- **쿼리 자동 필터링 비활성화**: 소프트 삭제 시나리오에서 삭제된 데이터를 포함한 모든 데이터를 확인해야 할 때, `AutoFilter`를 `false`로 설정하고 호출자가 직접 `WHERE`를 추가합니다.
- **문자열 상태 필드로 소프트 삭제**: `DeletedValue` / `NotDeletedValue`를 `"DELETED"` / `"ACTIVE"`로 변경하여 상태 머신 방식 필드에 적응시킵니다.
- **여러 캐시 백엔드 공존**: 서로 다른 엔티티가 서로 다른 `CacheType`을 선택합니다(예: 핫 데이터는 `Memory`, 프로세스 간 공유는 `Redis`). `KeyPrefix`를 통해 키 충돌을 방지합니다.
- **런타임 임시 비활성화**: 단위 테스트 또는 마이그레이션 스크립트에서 해당 특성의 `Enabled`를 `false`로 설정하면 현재 엔티티의 감사/캐시를 비활성화할 수 있습니다.

## 일반적인 오류

- **`DeletedField` 생성 매개변수 누락**: 세 개의 `SoftDeleteAttribute` 생성자는 모두 `deletedField`를 필수로 표시하므로, `null`을 전달하면 바로 `ArgumentNullException`이 발생합니다. 반드시 유효한 열 이름을 전달해야 합니다.
- **표시 필드 타입과 `DeletedValue` 불일치**: 기본값은 `DeletedValue = true`, `NotDeletedValue = false`입니다. 표시 필드가 `string` 또는 `int`인 경우, 반드시 문자열/정수 값을 명시적으로 지정해야 하며, 그렇지 않으면 ORM이 생성한 SQL에서 타입 변환 오류가 발생합니다.
- **동일한 클래스에 여러 특성 중복 적용**: 세 가지 특성 모두 `AllowMultiple = false`로 설정되어 있어, 동일한 엔티티에 중복으로 지정하면 컴파일 오류가 발생합니다. 다른 동작이 필요한 경우 속성 매개변수로 구분하세요.
- **캐시 키 충돌**: `KeyPrefix`가 설정되지 않은 경우, 여러 엔티티가 기본 접두사를 공유하여 키 충돌이 발생하고 적중률이 떨어집니다. 엔티티 이름에 따라 `"{EntityName}:"` 접두사를 설정할 것을 권장합니다.
- **감사를 백업으로 사용**: 감사는 변경 이력만 기록하며 삭제 전의 완전한 스냅샷을 저장하지 않습니다. "임의 시점의 데이터를 복원"하는 기능이 필요한 경우, 소프트 삭제 또는 사용자 정의 스냅샷 메커니즘을 함께 사용하세요.

## 배경 (선택 사항)

세 가지 특성은 모두 `AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = true)`로 표시되어 있어, 클래스에만 지정할 수 있고 각 클래스에는 하나만 지정할 수 있으며 파생 클래스에서 상속됩니다. ORM은 엔티티 등록 단계에서 리플렉션을 통해 이러한 특성을 읽어 감사 인터셉터를 생성할지, `WHERE`에 소프트 삭제 조건을 추가할지, 캐시 채널을 사용할지 결정합니다. `IAuditableEntity` 인터페이스의 필드는 ORM이 감사所需 컨텍스트 정보를 자동으로 쓰도록 하는 데 사용됩니다.
