# FAQ

This document compiles common issues and their solutions when using the GameFrameX Event event system plugin.

## Overview

GameFrameX Event is an event system plugin based on Game Framework, providing type-safe event subscription, dispatch, and management functionality. During usage, developers may encounter some common issues. This document provides detailed troubleshooting guides and solutions.

## Common Issues and Solutions

### 1. Events Not Received

#### Symptoms
After publishing an event, subscribers did not receive event notification.

#### Cause Analysis
- Event ID mismatch
- Subscription too early (event manager not yet initialized)
- Subscriber was destroyed but not unsubscribed
- Wrong event dispatch method used

#### Solutions

**Check event ID consistency:**

```csharp
// Ensure publishing and subscribing use the same event ID
public class GameStartEventArgs : GameEventArgs
{
    public override string Id => "game_start";  // Define unified event ID
}

// When subscribing
eventComponent.CheckSubscribe("game_start", OnGameStart);

// When publishing
eventComponent.Fire(this, GameStartEventArgs.Create("game_start"));
```

> Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L98-L101)

**Ensure correct subscription timing:**

```csharp
public class MyComponent : MonoBehaviour
{
    private void Start()
    {
        // Subscribe to event in Awake or Start, at this point the event system is initialized
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        eventComponent.CheckSubscribe("game_start", OnGameStart);
    }

    private void OnDestroy()
    {
        // Unsubscribe when component is destroyed to prevent memory leaks
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        if (eventComponent != null)
        {
            eventComponent.Unsubscribe("game_start", OnGameStart);
        }
    }

    private void OnGameStart(object sender, GameEventArgs e)
    {
        // Handle event
    }
}
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L82-L88)

### 2. Memory Leaks

#### Symptoms
Memory usage continuously increases as game runs, or abnormalities appear after scene switching.

#### Cause Analysis
- Not unsubscribed after subscribing to events
- Event handlers hold large number of object references
- Event args objects not properly released back to object pool

#### Solutions

**Always unsubscribe at appropriate locations:**

```csharp
public class PlayerController : MonoBehaviour
{
    private EventHandler<GameEventArgs> _onGameStartHandler;

    private void Awake()
    {
        // Save delegate reference for later unsubscription
        _onGameStartHandler = OnGameStart;
    }

    private void Start()
    {
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        eventComponent.CheckSubscribe("game_start", _onGameStartHandler);
    }

    private void OnDestroy()
    {
        // Important: Unsubscribe when destroying!
        var eventComponent = GameEntry.GetComponent<EventComponent>();
        if (eventComponent != null)
        {
            eventComponent.Unsubscribe("game_start", _onGameStartHandler);
        }
    }

    private void OnGameStart(object sender, GameEventArgs e)
    {
        // Handle event
    }
}
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L106-L114)

**Use object pool correctly:**

```csharp
// Use object pool when creating custom event args
public class ScoreEventArgs : GameEventArgs
{
    public int Score { get; private set; }

    public static ScoreEventArgs Create(int score)
    {
        var args = ReferencePool.Acquire<ScoreEventArgs>();
        args.Score = score;
        return args;
    }

    public override void Clear()
    {
        Score = 0;
    }

    public override string Id => "score_changed";
}

// Publish event
eventComponent.Fire(this, ScoreEventArgs.Create(100));

// Note: Fire method will automatically release args back to pool in next frame
// If using FireNow, need to manually release
```

> Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L32-L37)

### 3. Event System Initialization Failure

#### Symptoms
"Event manager is invalid" error appears at runtime, or event functionality is completely unavailable.

#### Cause Analysis
- Missing required dependency `GameFrameX.Runtime`
- EventComponent not correctly added to scene
- GameFrameworkEntry not correctly initialized

#### Solutions

**Install dependency package:**

Ensure `GameFrameX.Runtime` dependency is installed. Install via:

```json
// Add to dependencies in manifest.json
{
  "com.gameframex.unity.runtime": "https://github.com/GameFrameX/com.gameframex.unity.runtime.git"
}
```

> Source: [GameFrameX.Event.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameX.Event.Runtime.asmdef#L2-L5)

**Configure EventComponent correctly:**

```csharp
// Create an empty object in scene, add EventComponent
public class GameEntry : MonoBehaviour
{
    public static EventComponent EventComponent { get; private set; }

    private void Awake()
    {
        // Ensure EventComponent exists in scene
        EventComponent = gameObject.GetOrAddComponent<EventComponent>();
    }
}
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L43-L54)

### 4. Event Dispatch Timing Issues

#### Symptoms
- Event triggered earlier or later than expected
- Incorrect event handling order in async operations

#### Cause Analysis
- Confused difference between `Fire()` and `FireNow()`
- Insufficient understanding of thread safety mechanism

#### Solutions

**Understand difference between two dispatch modes:**

| Method | Thread Safe | Dispatch Timing | Applicable Scenarios |
|--------|-------------|-----------------|----------------------|
| `Fire()` | Yes | Next frame | Most cases, especially cross-thread calls |
| `FireNow()` | No | Immediate | Urgent events, sync callbacks |

```csharp
public class NetworkManager
{
    // Network callbacks may be called from child threads, use Fire to ensure thread safety
    public void OnReceiveData(byte[] data)
    {
        // Receive data in child thread
        var eventComponent = GameEntry.GetComponent<EventComponent>();

        // Use Fire to process in main thread next frame
        eventComponent.Fire(this, new NetworkDataEventArgs(data));
    }

    // Local sync events can use FireNow
    public void TriggerImmediateEvent()
    {
        var eventComponent = GameEntry.GetComponent<EventComponent>();

        // Immediate dispatch, for scenarios requiring immediate feedback
        eventComponent.FireNow(this, new ImmediateEventArgs());
    }
}
```

> Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L127-L140)

### 5. Duplicate Subscription Issues

#### Symptoms
The same event handler is called multiple times, causing logic to execute repeatedly.

#### Cause Analysis
- Subscription method called repeatedly in `Start()`
- Subscribed again without checking if already subscribed

#### Solutions

**Use CheckSubscribe for auto-check:**

```csharp
private void Start()
{
    var eventComponent = GameEntry.GetComponent<EventComponent>();

    // CheckSubscribe checks if already subscribed to avoid duplicate subscriptions
    eventComponent.CheckSubscribe("score_changed", OnScoreChanged);
}

// Don't use old Subscribe method (marked as obsolete)
// eventComponent.Subscribe("score_changed", OnScoreChanged);  // Not recommended
```

> Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L82-L88)

### 6. Custom Event Args Issues

#### Symptoms
Custom event args cannot be correctly dispatched or received.

#### Cause Analysis
- Not correctly inheriting `GameEventArgs`
- Not implementing required `Id` property and `Clear()` method
- Not using object pool correctly for lifecycle management

#### Solutions

**Create custom event args correctly:**

```csharp
// 1. Inherit GameEventArgs
public class PlayerDieEventArgs : GameEventArgs
{
    // 2. Implement Id property
    public override string Id => "player_die";

    // 3. Add event data
    public int PlayerId { get; private set; }
    public string Reason { get; private set; }

    // 4. Use static Create method to wrap object pool acquisition
    public static PlayerDieEventArgs Create(int playerId, string reason)
    {
        var args = ReferencePool.Acquire<PlayerDieEventArgs>();
        args.PlayerId = playerId;
        args.Reason = reason;
        return args;
    }

    // 5. Implement Clear method to release data
    public override void Clear()
    {
        PlayerId = 0;
        Reason = null;
    }
}
```

> Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L16-L18)

> Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L18-L25)

## Debugging Tips

### View Current Event Status

```csharp
// View event handler count
var eventComponent = GameEntry.GetComponent<EventComponent>();
Debug.Log($"Event handler count: {eventComponent.EventHandlerCount}");
Debug.Log($"Event type count: {eventComponent.EventCount}");

// Check specific event
int handlerCount = eventComponent.Count("game_start");
Debug.Log($"game_start event handler count: {handlerCount}");
```
