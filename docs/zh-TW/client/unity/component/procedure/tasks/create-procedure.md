# 如何撰寫流程（Procedure）

本章說明如何撰寫自訂流程（Procedure）並將其與 `ProcedureComponent` 整合，讓框架在啟動後自動進入該流程。每個流程皆繼承自 `ProcedureBase`，並由 `ProcedureManager` 透過有限狀態機（FSM）排程執行。

## 前置條件

- 已安裝 `com.gameframex.unity.procedure` 套件，且場景中存在 `ProcedureComponent`（掛載於 `GameFramework` 啟動物件上，並帶有 `[GameFrameXAutoComponent(-1000)]` 以進行自動註冊）。
- 已匯入 `GameFrameX.Procedure.Runtime` 與 `GameFrameX.Fsm.Runtime` 命名空間。
- 至少準備一個繼承自 `ProcedureBase` 的具體型別；框架會使用 `Activator.CreateInstance` 反射來建立實例，因此流程類別必須具有無參數（或參數可省略）的建構函式。

## 步驟

### 1. 建立流程類別並繼承 ProcedureBase

`ProcedureBase` 本身繼承自 `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`，提供六個生命週期回呼：`OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy`。預設實作皆為空，可依需求覆寫。

來源：[ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L30-L98)

最小可運作範例（可參考單元測試中的實際用法）：

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

internal class ProcedurePreload : ProcedureBase { }

internal class ProcedureLogin : ProcedureBase { }

internal class ProcedureMain : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // 初始化資源、設定、熱更新等
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 進入主場景邏輯
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // 釋放資源
    }
}
```

來源：[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L13-L40)

### 2. 在 Inspector 中註冊流程

在場景中選取掛載了 `ProcedureComponent` 的物件，然後在 Inspector 中：

- `Available Procedure Type Names`：填入所有可用流程的完整型別名稱（包含命名空間），例如 `GameFrameX.Procedure.ProcedurePreload`、`GameFrameX.Procedure.ProcedureLogin`、`GameFrameX.Procedure.ProcedureMain`。
- `Entrance Procedure Type Name`：填入啟動入口流程的完整型別名稱，必須與上方陣列中的其中一項完全相符；否則 `Start()` 協程會因 `m_EntranceProcedure == null` 而直接返回，並印出 `Entrance procedure is invalid.`。

`ProcedureComponent.Start()` 會依上述配置以反射方式建立流程實例，並呼叫 `ProcedureManager.Initialize(...)` 與 `StartProcedure(...)`。

來源：[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L51-L169)

### 3. 在流程內切換至下一個流程

在每個流程中，都可以透過 `procedureOwner` 取得所屬的 `IProcedureManager`，再呼叫 `procedureOwner.StartProcedure<T>()`（或 `StartProcedure(typeof(T))`）來切換至下一個狀態。例如，在 `ProcedureLogin` 中登入完成後跳轉至 `ProcedureMain`：

```csharp
protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
{
    base.OnEnter(procedureOwner);
    // ...登入成功邏輯...
    procedureOwner.StartProcedure<ProcedureMain>();
}
```

也可以透過元件存取：

```csharp
GameEntry.GetComponent<ProcedureComponent>().StartProcedure(typeof(ProcedureMain));
```

來源：[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L202-L240)

### 4. 透過 Startup Runner 接管啟動流程（選用）

若專案採用 `ApplicationStartupEntry` + `StartupRunner.Run` 的全新啟動方式，需要在 `ProcedureComponent` 上將 `Use Startup Runner` 勾選為 `true`。此時 `ProcedureComponent` 只會在 `Awake` 中註冊 `IProcedureManager`，不再呼叫 `Initialize` 與 `StartProcedure`。StartupRunner 會負責組裝各流程並啟動入口流程，避免重複 `Initialize` 導致回報 `Already exist FSM`。

來源：[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L55-L127)

## 常見變化

| 情境 | 做法 |
|------|------|
| 不使用元件，僅使用 `ProcedureManager` API | 呼叫 `new ProcedureManager().Initialize(fsmManager, procs)`，再呼叫 `StartProcedure<T>()` |
| 需要輪詢（`OnUpdate`） | 在對應的流程類別中覆寫 `OnUpdate(IFsm<IProcedureManager>, float, float)`；框架會每幀輪詢 |
| 需要固定間隔輪詢 | 覆寫 `OnFixedUpdate(IFsm<IProcedureManager>, float, float)` |
| 離開流程前需要清理 | 覆寫 `OnLeave(IFsm<IProcedureManager>, bool isShutdown)`，並依據 `isShutdown` 區分正常切換與狀態機關閉 |
| 檢查／取得已註冊的流程實例 | 使用 `HasProcedure<T>()` / `GetProcedure<T>()` |

來源：[ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L41-L273)

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `You must initialize procedure first.` | 在呼叫 `Initialize` 之前就存取了 `CurrentProcedure` / `StartProcedure` / `HasProcedure` / `GetProcedure` | 先呼叫 `ProcedureManager.Initialize(fsmManager, procedures)`，再存取上述 API |
| `ArgumentNullException`（參數為 `fsmManager`） | 傳給 `Initialize` 的是 `null` | 傳入有效的 `IFsmManager`（例如 `GameFrameworkEntry.GetModule<IFsmManager>()`） |
| `Procedures is invalid.` | `procedures` 陣列為空 | 至少傳入一個流程實例 |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` 與 `Available Procedure Type Names` 中任何項目都不相符 | 確保入口型別的完整名稱與陣列中的其中一項完全相同 |
| `Can not find procedure type '{0}'.` | 完整型別名稱拼寫錯誤，或對應的組件尚未載入 | 檢查命名空間與組件參考 |
| `Already exist FSM` | 同時啟用了 `ProcedureComponent` 與 `StartupRunner` 兩種啟動流程方式 | 將 `ProcedureComponent` 的 `Use Startup Runner` 設為 `true`，或不要讓 StartupRunner 再次呼叫 `Initialize` |

## 背景說明（選用）

`ProcedureBase` 是對 `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>` 的輕量封裝，`ProcedureManager` 內部以 `IFsm<IProcedureManager>` 的形式持有這些狀態。預設情況下，`ProcedureComponent` 會在 `Start()` 協程中以反射方式建立流程實例、呼叫 `Initialize`，然後跳轉至入口流程；當 `Use Startup Runner` 為 `true` 時，它只註冊 `IProcedureManager`，改由 `ApplicationStartupEntry` 接管初始化與啟動，適用於熱更新與資源分包等場景。
