# Troubleshooting

This document summarizes troubleshooting, errors, and solutions that may be encountered when using the GameFrameX Procedure workflow management component.

## Overview

The Procedure workflow management component is a game workflow management system implemented based on Game Framework's Finite State Machine (FSM). During integration and usage, developers often encounter configuration errors, missing dependencies, type parsing failures, and other issues. This document aims to help developers quickly locate and resolve these issues.

## Dependency Issues

### FSMComponent Not Configured Correctly

**Symptom**: No response after game starts or error `Procedure manager is invalid.` is reported

**Cause**: ProcedureComponent depends on `IProcedureManager` module, which needs to be obtained through `GameFrameworkEntry`. If FSMComponent is not properly initialized, module retrieval may fail.

**Solution**:
1. Ensure `FSMComponent` component has been added to the scene
2. Confirm `GameFrameworkEntry` has correctly initialized all required modules
3. Check GameFramework initialization sequence, ensure base components are initialized first

> Source: [ProcedureComponent.cs#L64-L68](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L64-L68)

---

### Missing Required GameFramework Components

**Symptom**: NullReferenceException or module retrieval failure at runtime

**Cause**: GameFramework is a complete component system. The Procedure component depends on multiple underlying modules

**Solution**:
1. Ensure GameFrameX core library is installed
2. Check if the project contains the following dependencies:
   - `GameFrameX.Fsm.Runtime` - Finite state machine module
   - `GameFrameX.Runtime` - Core runtime module

## Configuration Issues

### Workflow Type Name Configuration Error

**Symptom**: Console displays error `Can not find procedure type '{0}'.`

**Cause**: Workflow type name configured in `m_AvailableProcedureTypeNames` array does not match the actual class name

**Solution**:
1. Check the `Available Procedure Type Names` configuration in the Inspector panel
2. Ensure type name uses the complete class name (including namespace)
3. Workflow class must inherit from `ProcedureBase`

```csharp
// Correct example
namespace MyGame.Procedure
{
    public class ProcedureLaunch : ProcedureBase
    {
        // Workflow implementation
    }
}
```

Configuration should be: `MyGame.Procedure.ProcedureLaunch`

> Source: [ProcedureComponent.cs#L76-L81](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L76-L81)

---

### Entrance Workflow Not Set

**Symptom**: Console displays error `Entrance procedure is invalid.`

**Cause**: `m_EntranceProcedureTypeName` is not set or the set value is not in the `m_AvailableProcedureTypeNames` list

**Solution**:
1. Set `Entrance Procedure Type Name` in the Inspector panel
2. Ensure entrance workflow name exactly matches one of the workflows in `Available Procedure Type Names`
3. The entrance workflow is the first workflow to execute after the game starts

> Source: [ProcedureComponent.cs#L90-L100](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L90-L100)

---

### Workflow Array Empty

**Symptom**: No workflow executes at startup, or array out of bounds error occurs

**Cause**: `m_AvailableProcedureTypeNames` is not configured or is empty

**Solution**:
1. In the ProcedureComponent Inspector panel, add at least one workflow type
2. It is recommended to include at least the following basic workflows:
   - Launch workflow (ProcedureLaunch)
   - Hot update workflow (ProcedureCheckVersion)
   - Login workflow (ProcedureLogin)
   - Game workflow (ProcedureGame)

## Type Parsing Issues

### Assembly Type Get Failure

**Symptom**: `Utility.Assembly.GetType()` returns null, causing workflow creation failure

**Cause**:
1. Type name spelling error
2. Workflow class not compiled into assembly
3. Wrong assembly configuration used

**Solution**:
1. Confirm workflow class has been correctly compiled
2. Use complete type name (including namespace)
3. For obfuscated code, ensure related assembly configuration is correct

```csharp
// Wrong type name
m_AvailableProcedureTypeNames = new[] { "ProcedureLaunch" };

// Correct type name
m_AvailableProcedureTypeNames = new[] { "GameFrameX.Procedure.Runtime.ProcedureLaunch" };
```

> Source: [ProcedureComponent.cs#L83-L88](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L83-L88)

---

### Workflow Instance Creation Failure

**Symptom**: Error `Can not create procedure instance '{0}'.`

**Cause**:
1. Workflow class lacks parameterless constructor
2. Constructor throws exception
3. Workflow class constructor accesses system that has not been initialized yet

**Solution**:
1. Ensure workflow class has a parameterless constructor
2. Do not access ProcedureManager or other GameFramework components in the constructor
3. Use lifecycle methods such as `OnInit`, `OnEnter` for initialization

```csharp
// Recommended: Initialize in OnEnter
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // Perform initialization operations here
    }
}
```

## Runtime Issues

### Workflow Manager Not Initialized

**Symptom**: Exception `You must initialize procedure first.` thrown when calling `CurrentProcedure` or `CurrentProcedureTime`

**Cause**: Accessed relevant properties before ProcedureManager initialization is complete

**Solution**:
1. Ensure not to access workflow manager until `Start()` method execution is complete
2. Use coroutines or Event System to wait for initialization to complete

```csharp
// Wrong example: Immediate access in Awake
private void Awake()
{
    var current = CurrentProcedure; // Will throw exception
}

// Correct example: Wait in coroutine
private IEnumerator Start()
{
    yield return new WaitForEndOfFrame();
    var current = CurrentProcedure; // Now can be accessed normally
}
```

> Source: [ProcedureManager.cs#L48-L55](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L48-L55)

---

### Workflow Switching Failure

**Symptom**: Workflow does not switch after calling `StartProcedure<T>()`

**Cause**:
1. Specified workflow type not registered during initialization
2. FSM state machine has been destroyed
3. Workflow switching logic has an infinite loop

**Solution**:
1. Ensure target workflow for switching is in `m_AvailableProcedureTypeNames`
2. Check if any code immediately switches back to original workflow during workflow switching
3. Use debug logs to confirm if switching call is executed

> Source: [ProcedureManager.cs#L116-L124](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L116-L124)

---

### Workflow State Methods Not Called

**Symptom**: Custom `OnEnter`, `OnUpdate`, `OnLeave` and other methods are not executed

**Cause**: Workflow class does not correctly inherit `ProcedureBase`, or methods are not correctly overridden

**Solution**:
1. Ensure workflow class inherits from `ProcedureBase`
2. Use `override` keyword to override parent class methods
3. Call `base.OnEnter()` and other methods to ensure parent class logic executes

```csharp
// Correct example
public class ProcedureLogin : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner); // Must call
        // Custom logic
    }
}
```

> Source: [ProcedureBase.cs#L31-L35](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L31-L35)

## Common Error Code Reference

| Error Information | Cause | Solution |
|---------|------|---------|
| Procedure manager is invalid. | IProcedureManager module retrieval failure | Check GameFramework Initialize and FSMComponent |
| Can not find procedure type '{0}'. | Type name configuration error | Check m_AvailableProcedureTypeNames configuration |
| Can not create procedure instance '{0}'. | Workflow class instantiation failure | Check constructor and type definition |
| Entrance procedure is invalid. | Entrance workflow not set | Set m_EntranceProcedureTypeName |
| You must initialize procedure first. | Workflow manager not initialized | Access after initialization is complete |

## Debugging Tips

### Enable Debug Log

During development, you can add detailed log output to help locate issues:

```csharp
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        Debug.Log("Entering ProcedureLaunch workflow");
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        Debug.Log($"ProcedureLaunch has been running for {procedureOwner.CurrentStateTime:F2} seconds");
    }
}
```

### Check Workflow State

You can use methods provided by `ProcedureComponent` to check workflow state:

```csharp
// Check if specified workflow exists
bool hasLogin = procedureComponent.HasProcedure<ProcedureLogin>();

// Get current workflow
ProcedureBase current = procedureComponent.CurrentProcedure;

// Get workflow duration
float duration = procedureComponent.CurrentProcedureTime;
```
