# `quick_start-game.bat` を使用してローカル起動

`quick_start-game.bat` は `GameFrameX.Launcher` ディレクトリにあるゲームサーバーのワンクリック起動スクリプトです。実行すると、ローカルで `ServerType=Game` のゲートウェイプロセスが起動し、内蔵のディスカバリセンターに自動接続して MongoDB データベースに接続します。開発段階でサービスが正常に起動できるかどうかをすばやく検証するのに適しています。

## 前提条件

- Windows システムで、.NET 10.0 SDK またはランタイム(`TargetFramework=net10.0`)がインストール済みであること
- 本リポジトリをクローンまたはダウンロードし、`GameFrameX.Launcher` の Release ビルドが完了していること。成果物は `bin\app\GameFrameX.Launcher.dll` に配置されます
- ローカル `127.0.0.1` の `21001` ポートが `DiscoveryCenter`(ディスカバリセンター)でリッスン可能であり、`29090/29100/29010/29110` が未使用であること
- スクリプトに指定された MongoDB Atlas アドレスにネットワーク経由でアクセスできること(アカウント `gameframex` / パスワードが利用可能であることを確認する必要があります)

## 操作手順

1. コマンドラインを開き、`GameFrameX.Launcher` ディレクトリに移動します:

   ```bat
   cd GameFrameX.Launcher
   ```

2. `quick_start-game.bat` を直接ダブルクリックするか、コマンドラインで実行します:

   ```bat
   quick_start-game.bat
   ```

   スクリプトが実際に呼び出す内容は次のとおりです:

   ```bat
   start dotnet GameFrameX.Launcher.dll --ServerType=Game --ServerId=9000 --APMPort=29090 --InnerIp=127.0.0.1 --InnerPort=29100 --OuterIp=127.0.0.1 --OuterPort=29010 --MinModuleId=1 --MaxModuleId=9999 --WsPort=29110 --DiscoveryCenterIp=127.0.0.1 --DiscoveryCenterPort=21001 --HttpCode=inner_httpcode --DataBaseUrl="mongodb+srv://gameframex:f9v42aU9DVeFNfAF@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority" --DataBaseName=gameframex
   ```

   Source: [quick_start-game.bat](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/quick_start-game.bat#L1-L1)

3. スクリプトは `start` を通じて新しいコンソールウィンドウを起動し、`GameFrameX.Launcher.dll` を読み込みます。プログラムエントリは `GameApp.Entry` を呼び出して初期化を完了します。

   ```csharp
   internal static class Program
   {
       private static async Task Main(string[] args)
       {
   #if DEBUG
           LogOptions.Default.IsConsole = true;
   #endif
           await GameApp.Entry(args, () =>
           {
               CacheStateTypeManager.Init();
               MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
           }, LogAction);
       }
   ```

   Source: [Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L5-L17)

4. 新しく表示されたコンソールウィンドウでログを観察します:APM、Inner、Outer、Ws の 4 つのポートが順番にリッスンを開始し、エラースタックトレースが出力されていなければ、ゲームサーバーがローカルで正常に起動していることを示します。

## 起動パラメータの説明

| パラメータ | 値 | 意味 |
|------|-----|------|
| `--ServerType` | `Game` | プロセス種別はゲームサーバー(ゲートウェイ) |
| `--ServerId` | `9000` | 現在のサーバー一意番号 |
| `--APMPort` | `29090` | APM(アプリケーションパフォーマンス管理)/管理ポート |
| `--InnerIp` / `--InnerPort` | `127.0.0.1` / `29100` | 内部ネットワーク通信アドレス |
| `--OuterIp` / `--OuterPort` | `127.0.0.1` / `29010` | 外部ネットワーククライアントアクセスアドレス |
| `--MinModuleId` / `--MaxModuleId` | `1` / `9999` | メッセージモジュール ID の割り当て範囲 |
| `--WsPort` | `29110` | WebSocket ポート |
| `--DiscoveryCenterIp` / `--DiscoveryCenterPort` | `127.0.0.1` / `21001` | レジストリセンターアドレス |
| `--HttpCode` | `inner_httpcode` | HTTP ルートコーディング |
| `--DataBaseUrl` | Atlas 接続文字列 | MongoDB 接続アドレス |
| `--DataBaseName` | `gameframex` | データベース名 |

## よくあるエラー

- **`GameFrameX.Launcher.dll` が見つからない**:まだコンパイルされていないか、出力ディレクトリがスクリプトが想定している `bin\app` ではありません。`csproj` の Release 設定の出力先は `..\bin\app\` であるため、まずソリューションのルートディレクトリで `dotnet build -c Release` を実行するか、`GameFrameX.Launcher` ディレクトリでビルドしてください。

  Source: [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L20-L23)

- **`dotnet` が内部コマンドまたは外部コマンドとして認識されない**:.NET 10 SDK がインストールされていないか、インストール後に `dotnet.exe` が PATH に追加されていません。

- **`127.0.0.1:21001` への接続に失敗する**:ディスカバリセンターが起動していません。`quick_start-game.bat` は Game サーバーのみを起動するため、本スクリプトを実行する前に `DiscoveryCenter` サービスを個別に起動する必要があります。

- **MongoDB 接続エラー**:スクリプトにはアカウント `gameframex` とパスワードがハードコードされています。そのアカウントが削除されていたり、ネットワークが制限されている場合は、スクリプトの `--DataBaseUrl` を利用可能な接続文字列に変更してください。

## 背景

`GameFrameX.Launcher` は Game サーバーのエントリとしての役割と、ビルド成果物の配置場所(`bin\app\GameFrameX.Launcher.dll`)としての役割を兼ね備えています。起動パラメータを変えることで、同じプロセスモデルを再利用して異なる種別のサーバーを起動できます。`quick_start-game.bat` は、よく使われる Game サーバーのパラメータを 1 つの `start dotnet ...` コマンドに固定することで、毎回手動でパラメータを組み立てる手間を省いています。
