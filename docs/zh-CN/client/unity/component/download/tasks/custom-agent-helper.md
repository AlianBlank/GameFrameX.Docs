# 自定义下载代理助手

通过实现 `IDownloadAgentHelper` 接口，可以替换或扩展默认的下载后端（代理获取、文件落盘、流式读取等行为）。

## 前置条件

- 已将 `Microsoft.Kiota.Authentication.Azure` 或相关 Kiota 认证包添加到项目。
- 目标项目使用 C# / .NET，理解依赖注入与 `IHttpClient` 生命周期。
- 已有一个可用的 `IAuthenticationProvider` 实例作为下游调用源。

## 操作步骤

1. 新建类实现 `IDownloadAgentHelper` 接口的三个成员（具体签名以源码为准）。
2. 在构造函数中注入所需的依赖（如 `IHttpClient`、`IAuthenticationProvider`、`ILogger` 等）。
3. 将实现的实例以单例或作用域方式注册到 `IServiceCollection` 中。
4. 在请求执行前，将该帮助器传给需要它的调用方（例如 `KiotaClientFactory` 的相关重载）。
5. 发起一次最小化下载请求，验证自定义逻辑（日志、断点、文件路径）是否生效。

## 常见变体

- **日志包装**：在原有实现外套一层，仅添加日志/遥测，其余转发。
- **路径重写**：根据租户或用户上下文把临时文件落到隔离目录。
- **流式分块**：自定义分块大小与并发度，覆盖默认的 `BufferSize` 行为。

## 常见错误

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 注册后未生效 | 未替换默认注册或作用域不一致 | 检查 `services.AddSingleton<>` / `AddScoped<>` 选择 |
| 下载失败无错误信息 | 未捕获并转发 `HttpRequestException` | 在 `DownloadAsync` 中包装 `try/catch` 并记录 |
| 文件被占用 | 未释放流 | `await using` 或显式 `Dispose()` |
| 认证头缺失 | 未在 `GetAuthenticationProvider` 中调用下游 provider | 转发而非替换 |

## 背景（可选）

`IDownloadAgentHelper` 是 Kiota 抽象的下载能力扩展点：默认实现走 `HttpClient`，自定义实现可以接入鉴权、重试、落盘策略等横切关注点。本页只描述如何挂载，认证提供器的整体设计不在此处展开。
