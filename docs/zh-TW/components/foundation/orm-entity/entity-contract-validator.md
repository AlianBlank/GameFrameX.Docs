# 如何使用 EntityContractValidator 驗證合約

`EntityContractValidator` 用於驗證實體型別與其所實作介面之間的屬性一致性。針對介面中宣告的每個屬性，實體類別中都必須存在同名屬性、型別必須相容(支援 `Nullable<T>` 與指派共變性)，並提供介面所要求的 `getter` / `setter`。

## 必要條件

- 專案已參考 `GameFrameX.Foundation.Orm.Entity` 組件。
- 目標框架支援 `System.Reflection`(所有 .NET 版本皆可使用)。
- 待驗證的型別是 `class`,且實作了至少擁有一個屬性的介面。

## 操作步驟

1. **選擇驗證入口**。提供 2 種多載，兩者結果完全相同：

   ```csharp
   using GameFrameX.Foundation.Orm.Entity;

   // 泛型版多載(編譯時期即已知型別)
   var violations = EntityContractValidator.Validate<MyEntity>();

   // 非泛型版多載(執行時期以反射取得 Type)
   var violations = EntityContractValidator.Validate(typeof(MyEntity));
   ```

   Source: [EntityContractValidator.cs#L57-L87](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L57-L87)

2. **逐一查看違規項目以釐清原因**。傳回型別為 `IList<EntityContractViolation>`,每筆記錄包含 3 個欄位：

   | 欄位 | 型別 | 意義 |
   |------|------|------|
   | `InterfaceType` | `Type` | 遭違反的介面型別 |
   | `PropertyName` | `string` | 遺漏或不相符的屬性名稱 |
   | `Reason` | `string` | 以中英兩種語言描述的具體原因 |

   Source: [EntityContractViolation.cs#L38-L79](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractViolation.cs#L38-L79)

3. **典型的最小呼叫**：

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       foreach (var v in violations)
       {
           Console.WriteLine($"[{v.InterfaceType.Name}.{v.PropertyName}] {v.Reason}");
       }
   }
   ```

4. **在 CI / 啟動時加入斷言檢查**(建議做法)：

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       throw new InvalidOperationException(
           $"エンティティ MyEntity がコントラクトに違反しています:{string.Join("; ", violations.Select(v => v.Reason))}");
   }
   ```

## 所檢測的 4 種違規

`ValidateInterface` 會依序檢查介面上的每個屬性，一旦命中即 `continue`,因此每種違規只會觸發一次：

| 順序 | 觸發條件 | `Reason` 關鍵字 | 原始碼行 |
|------|----------|------------------|--------|
| 1 | `GetProperty` 擲出 `AmbiguousMatchException`(多重繼承或以 `new` 遮蔽) | “存在多个声明(可能使用了 new 关键字遮蔽)” | [L100-L108](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108) |
| 2 | 實體類別中不存在同名的公用屬性 | “不存在” | [L110-L118](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118) |
| 3 | 屬性型別不相容(`IsTypeCompatible` 傳回 false) | “类型不匹配：期望 … 实际 …” | [L120-L128](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L120-L128) |
| 4 | 介面要求 `get` / `set`,但實作沒有對應的存取子 | “缺少 getter” / “缺少 setter” | [L130-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144) |

`IsTypeCompatible` 的判斷規則(支援 `Nullable<T>` 與共變性)：

- 完全相同 → 相容；
- 去除 `Nullable` 包裝後相同 → 相容；
- 其他情況則使用 `expected.IsAssignableFrom(actual)`。

Source: [EntityContractValidator.cs#L148-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

## 常見變化

- **驗證泛型實體基底類別**:`Validate<EntityBase<Guid>>()`、`Validate<EntityTenantBase<Guid>>()` 等全都會傳回空清單。框架內建的基底類別皆具備自我一致性。Source: [EntityContractValidatorComprehensiveTests.cs#L78-L94](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/EntityContractValidatorComprehensiveTests.cs#L78-L94)
- **驗證非實體型別**：可正常呼叫，但若型別所實作介面的屬性屬於明確介面實作(例如： `int.IConvertible.TypeCode`),則會觸發 “属性不存在” 違規。Source: [L42-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/EntityContractValidatorComprehensiveTests.cs#L42-L51)
- **多層繼承 + `new` 遮蔽**：即使在多層繼承鏈中發生 `AmbiguousMatchException`,同一個屬性名稱也只會產生一筆違規(命中後即 `continue`)。Source: [OrmEntityBoundaryTests.cs#L60-L67](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Orm/OrmEntityBoundaryTests.cs#L60-L67)

## 常見錯誤

| 錯誤的使用方式 | 現象 | 修正方式 |
|----------|------|------|
| 將 `null` 傳入 `Validate(Type)` | 擲出 `ArgumentNullException`,且 `ParamName = "entityType"` | 傳入非空 `Type`,或使用泛型版多載 |
| 使用 `explicit interface implementation` 來實作介面屬性 | 驗證時會回報 “属性不存在” — `GetProperty(Public|Instance)` 找不到明確實作 | 將屬性改為公用屬性，或只在介面上宣告介面本身必要的成員 |
| 使用 `new` 關鍵字遮蔽介面的同名屬性 | 觸發 `AmbiguousMatchException`,並回報 “存在多个声明(可能使用了 new 关键字遮蔽)” | 移除 `new`,或重新命名使其在實體類別內唯一 |
| 以 `string` 實作 `string?`,或反向為之 | 會回報 “类型不匹配” | `Nullable<T>` 與非 nullable 的 T 會被視為相容，其餘差異請務必保持一致 |

## 背景(選用)

`ValidateInterface` 會使用 `entityType.GetInterfaces()` 列舉所有介面，並以 `BindingFlags.Public | BindingFlags.Instance` 在實體類別上依序搜尋每個介面的屬性。一旦命中，就會記錄一筆 `EntityContractViolation` 並執行 `continue`,因此單一介面屬性所產生的違規最多一筆。若因多重繼承或 `new` 遮蔽導致 `GetProperty` 擲出 `AmbiguousMatchException`,該例外會被攔截並以專屬文字回報，而不會向外拋出。`IsTypeCompatible` 會先確認嚴格的型別相符，接著確認去除 `Nullable` 包裝後的相符，最後使用 `IsAssignableFrom` 處理共變性的情況。
