# 列舉型別、結構與複合欄位的定義方法

當某個欄位只想允許「固定的幾個值」（例如：道具類型），或想將多個欄位合併為 1 個複合欄位（例如：座標、價格區間）時，可使用 `__enums__.xlsx` 與 `__beans__.xlsx` 這 2 張「進階定義表格」。本文將說明如何從零開始定義列舉型別與結構，並在資料表中引用它們。

## 前置條件

- 已依照「設定表格的新建方法」的步驟，在 `Excels/Tables/` 目錄下建立至少 1 張一般資料表（並理解開頭 4 行表頭的意義）。
- 本機已安裝 Excel、WPS 或可編輯 `.xlsx` 檔案的工具。
- 已確認過 `Excels/` 目錄下的 `__enums__.xlsx` 與 `__beans__.xlsx`（即使內容為空，也至少曾開啟過一次）。

> 只要定義好這 2 張表格一次，即可在所有資料表的 `##type` 行直接填入列舉型別名稱或結構名稱，作為欄位型別使用。

## 操作步驟

### 步驟 1：開啟「列舉型別定義表格」

開啟 `Excels/__enums__.xlsx`。這張表格的用途只有一個：將所有「列舉型別」集中在此定義。

這張表格的表頭同樣是固定的 4 行：

| 行 | 標記 | 填寫內容 |
|----|------|--------|
| 1 | `##var` | 列舉型別各值的英文名稱 |
| 2 | `##type` | 全部填入 `int` |
| 3 | `##group` | 保持空白 |
| 4 | `##` | 中文說明 |

> 工具以**英文欄名（`##var` 行）**識別列舉型別。命名規則：`EnumName.Member`，例：`ItemType.Consumable`。

### 步驟 2：定義列舉型別

例如，假設要為「道具類型」建立列舉型別 `ItemType`，包含消耗品、裝備、素材 3 種類型。在 `__enums__.xlsx` 中填寫如下：

| ##var | ItemType.Consumable | ItemType.Equipment | ItemType.Material |
|-------|---------------------|--------------------|-------------------|
| ##type | int | int | int |
| ##group | | | |
| ## | 消耗品 | 裝備 | 素材 |

**命名要點：**

| 寫法 | 意義 |
|------|------|
| `ItemType.Consumable` | 列舉型別名稱 = `ItemType`、成員 = `Consumable` |
| `Color.R` / `Color.G` / `Color.B` | 可在同一張表格內定義多個列舉型別，以欄名區分 |

定義完成後，只要在所有資料表的 `##type` 行填入 `ItemType`，即可引用此列舉型別。

### 步驟 3：在資料表中使用列舉型別

只要新增（或開啟）道具表格，在「類型」欄的型別填入列舉型別名稱即可：

| ##var | id | name | type |
|-------|----|------|------|
| ##type | int | text | ItemType |
| ##group | | | |
| ## | 道具ID | 道具名稱 | 類型 |
| | 10001 | diamond | ItemType.Consumable |
| | 10002 | sword | ItemType.Equipment |

工具驗證：儲存格中必須填入以 `ItemType.` 開頭的成員名稱，否則生成時會發生「未定義的列舉值」錯誤。

### 步驟 4：開啟「結構定義表格」

開啟 `Excels/__beans__.xlsx`。這張表格的用途：將多個欄位整合為可重複使用的複合型別（例如：`vec3` 座標、`Reward` 獎勵包）。

表頭同樣為固定的 4 行標記，意義與一般表格相同：

| 行 | 標記 | 填寫內容 |
|----|------|--------|
| 1 | `##var` | 欄位名稱（英文） |
| 2 | `##type` | 欄位型別（可指定 `int`、`string`、列舉型別名稱，甚至是其他結構的名稱） |
| 3 | `##group` | 保持空白 |
| 4 | `##` | 中文說明 |

> 結構以 `##var` 行的**欄名（含 `.`）**識別。例如 `Reward.ItemId`、`Reward.Count` 代表同一個結構 `Reward` 的 2 個欄位。

### 步驟 5：定義結構

例如，定義一個包含道具 ID 與數量的獎勵包 `Reward`：

| ##var | Reward.ItemId | Reward.Count |
|-------|---------------|--------------|
| ##type | int | int |
| ##group | | | |
| ## | 道具ID | 數量 |

如此一來，便宣告了一個名為 `Reward` 的結構，擁有 `ItemId`（int）與 `Count`（int）2 個欄位。

**複合欄位中還可以進一步巢狀結構或列舉型別：**

| ##var | Reward.ItemId | Reward.ItemType | Reward.Pos.x | Reward.Pos.y |
|-------|---------------|------------------|--------------|--------------|
| ##type | int | ItemType | float | float |
| ##group | | | | |
| ## | 道具ID | 道具類型 | X座標 | Y座標 |

上面的範例定義了 2 個結構：`Reward`（包含 `ItemId`、`ItemType`、`Pos`）與 `Pos`（包含 `x`、`y`）。

### 步驟 6：在資料表中使用結構

直接在 `##type` 行填入結構名稱，儲存格中則依欄位順序填入值（分隔字元為 `,` 或 `;`，工具會依照宣告順序讀取）：

| ##var | id | first_reward |
|-------|----|--------------|
| ##type | int | Reward |
| ##group | | | |
| ## | 成就ID | 首次通關獎勵 |
| | 900001 | 10001,1 |
| | 900002 | 10002,5 |

> 行內的分隔字元依工具的實際設定而定（預設為逗號 `,`）。欄位順序必須與 `__beans__.xlsx` 中 `##var` 的順序一致。

## 常見變化

| 情境 | 寫法 |
|------|------|
| 清單型欄位（多個相同結構） | 型別填入 `list,Reward`，儲存格中以 `;` 分隔各個 Reward |
| 映射型欄位 | 型別填入 `map,int,Reward`（鍵型別在前，值型別在後） |
| 將多語系欄位納入結構 | 只要將欄位型別填為 `text` 即可 |
| 再利用內建座標型別 | 直接在 `##type` 填入 `vec2` / `vec3` / `vec4`（標準內建於 [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml)） |

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 生成時顯示 *未定義的列舉型別* | `__enums__.xlsx` 中未填寫該列舉型別名稱 | 以 `EnumName.Member` 格式補寫至 `__enums__.xlsx` |
| 生成時顯示 *不支援的中文表格名稱* | 欄名／列舉型別名稱使用了中文 | 列舉型別名稱、成員名稱、欄位名稱必須使用英文 |
| 結構的欄位不一致 | 儲存格的填寫順序與 `__beans__.xlsx` 的欄位順序不一致 | 嚴格依照 `##var` 行的順序填寫 |
| 資料欄完全無法讀取 | `__var` / `##type` / `##group` / `##` 標記寫錯 | 這 4 個標記是固定字串，請原封不動地正確填寫 |
| 相同列舉型別衝突 | 在 `__enums__.xlsx` 的同一欄填入了不同前綴的成員 | 每個列舉型別獨立使用 1 欄，不要混用 |

## 背景（選讀）

`__enums__.xlsx` 與 `__beans__.xlsx` 本質上是將「在程式碼中撰寫 `enum` / `class`」的工作轉移到 Excel 上。當企劃填寫表頭後，工具會生成對應的 C# 列舉型別與類別，用戶端（Unity）與伺服器（.NET）則各自取得型別一致的程式碼。內建型別（如座標）由 [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml) 提供，會自動適配各平台的座標實作。
