# ホストサーバーアドレスの設定方法

`GlobalConfigComponent` に `HostServerUrl` を設定すると、クライアントは起動時にバックエンドのベースアドレスを取得し、バージョン検出やリソース更新などのインターフェースを連結するために使用できます。

## 前提条件

- `GameFrameX.GlobalConfig` コンポーネントをゲームのエントリシーンにマウントし、コンポーネントの種類を `GlobalConfigComponent` にしていること。
- 利用可能な HTTP/HTTPS のホストアドレスを用意する（`http://` または `https://` で始まり、末尾に `/` は不要）。

## 操作手順

1. シーン内で `GlobalConfigComponent` がアタッチされている GameObject を見つけ、選択すると Inspector に「主机服务地址」フィールドが表示されます。このフィールドはシリアル化フィールド `m_hostServerUrl` に対応します。

   ```csharp
   // Runtime/GlobalConfig/GlobalConfigComponent.cs:L98-L112
   /// <summary>
   /// 主机服务地址
   /// </summary>
   [SerializeField] private string m_hostServerUrl = string.Empty;

   /// <summary>
   /// 主机服务地址
   /// </summary>
   public string HostServerUrl
   {
       get { return m_hostServerUrl; }
       set { m_hostServerUrl = value; }
   }
   ```

2. Inspector の「主机服务地址」入力欄に完全な URL（例：`https://api.example.com`）を入力します。

3. 実行時（例：セーブデータ読込後、動的更新センターからの配布後）にアドレスを変更する必要がある場合は、`GlobalConfigComponent` インスタンスのプロパティに代入します：

   ```csharp
   var globalConfig = GameEntry.GetComponent<GlobalConfigComponent>();
   globalConfig.HostServerUrl = "https://api.example.com";
   ```

4. 検証：ゲーム起動後、Inspector の「原始数据」（`OriginalData` に対応）またはコンソールログでフィールドが有効になっていることを確認できます。これにより、このアドレスに依存するすべての下流インターフェース（バージョンチェック、リソースバージョンチェック）が自動的に新しい値を使用します。

## よくあるバリエーション

- `CheckAppVersionUrl` / `CheckResourceVersionUrl` と組み合わせて使用：「主机服务地址」がルートドメインのみであり、バージョンチェックが独立した CDN 経由で行われる場合は、それぞれのフィールドに別途入力することで、ホストアドレスによって上書きされるのを防げます。
- `OriginalData` 経由での一括配布：サーバーが返した JSON 全体が逆シリアル化されて `m_originalData` に書き戻されるため、業務ロジックはこの生データを読み取って各サブシステムに配信できます。

## よくあるエラー

| 現象 | 原因 | 修復方法 |
|------|------|------|
| 設定後もインターフェースが古いアドレスを参照する | シーンが既にアクティブ化された後、または下流が古い値をキャッシュした後にフィールドが代入された | `GameEntry` の起動フローの最も早い段階、または下流が読み取る前に代入する |
| アドレス末尾に `/` が余分についてしまい、リクエストパスが `//api/...` になる | ドメイン名の後に無意識にスラッシュを追加してしまう | 末尾の `/` を取り除き、必要に応じて呼び出し側で連結する |
| Inspector のフィールドがグレー表示で編集できない | 現在 Play モードであり、Inspector が実行時の編集による消失を防ぐために編集を無効化している | Play モードを終了してから変更するか、プロパティへの代入を使用する |
