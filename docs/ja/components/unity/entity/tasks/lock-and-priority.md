# エンティティのロックと回収優先度の制御方法

エンティティフレームワークはオブジェクトプールを通じてエンティティインスタンスを再利用します。特定のエンティティインスタンスをロックして自動回収を防いだり、エンティティグループの作成時にオブジェクトプールの優先度を設定して回収順序に影響を与えたりすることができます。このページでは、この 2 つの機能の呼び出し方法と動作メカニズムについて説明します。

## 前提条件

- `EntityComponent` をシーンにアタッチし、Inspector またはコードでエンティティグループを追加済みであること。
- エンティティグループが存在して初めて、そのグループ配下のエンティティに対してロック/ロック解除操作を実行できます。

## 操作手順

### 1. エンティティインスタンスをロック/ロック解除する

`EntityComponent.SetEntityInstanceLocked(Entity entity, bool locked)` を使用して設定します。ロックすると、基盤となるオブジェクトプールは自動解放時にこのインスタンスを回収しません。ロック解除すると、再び回収可能な状態に戻ります。

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

public class MyBehaviour : MonoBehaviour
{
    [SerializeField] private EntityComponent entityComponent;

    // エンティティをロックして自動回収を防ぐ(例:重要な演出を再生中など)
    public void LockEntity(Entity entity)
    {
        entityComponent.SetEntityInstanceLocked(entity, true);
    }

    // 演出終了後にロック解除し、オブジェクトプールによる通常の回収を許可する
    public void UnlockEntity(Entity entity)
    {
        entityComponent.SetEntityInstanceLocked(entity, false);
    }
}
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L1140-L1170)

### 2. エンティティグループの追加時にオブジェクトプールの優先度を設定する

`AddEntityGroup` の完全なオーバーロードは `instancePriority` パラメータを受け取り、値が大きいほど、基盤となるオブジェクトプールの自動解放時に後回しにされて回収されます。`0` がデフォルト値で、定数 `DefaultPriority` に対応します。

```csharp
using GameFrameX.Entity.Runtime;

public class MyBootstrap
{
    public void Setup(EntityComponent entityComponent)
    {
        // 容量 32、有効期限 60 秒、優先度 10(デフォルトの 0 より高く、より遅く回収される)
        entityComponent.AddEntityGroup(
            entityGroupName: "Boss",
            instanceAutoReleaseInterval: 60f,
            instanceCapacity: 32,
            instanceExpireTime: 60f,
            instancePriority: 10);

        // デフォルト優先度(0)を使用する簡易オーバーロード
        entityComponent.AddEntityGroup("Bullet", 30f);
    }
}
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L246-L290)

### 3. Inspector で優先度を設定する

`EntityComponent` の `EntityGroup` シリアライズクラスは `InstancePriority` フィールドを公開しており、Inspector で直接調整できます。実行時の優先度は `AddEntityGroup` とともに基盤となるオブジェクトプールへ登録されます。

```csharp
[SerializeField] private int m_InstancePriority = 0; // デフォルト 0

public int InstancePriority
{
    get { return m_InstancePriority; }
}
```

## 主要 API クイックリファレンス

| インターフェース | 場所 | 機能 |
|------|------|------|
| `EntityComponent.SetEntityInstanceLocked(Entity, bool)` | `EntityComponent.cs` | 指定したエンティティインスタンスをロック/ロック解除する |
| `EntityComponent.AddEntityGroup(string, float, int, float, int)` | `EntityComponent.cs` | 優先度付きのエンティティグループを作成する |
| `IEntityGroup.SetEntityInstanceLocked(object, bool)` | `IEntityGroup.cs` | エンティティグループレベルのロックインターフェース |
| `EntityGroup.InstancePriority` | `EntityComponent.EntityGroup.cs` | Inspector での優先度フィールド |
| `DefaultPriority` 定数 | `EntityComponent.cs` | デフォルト優先度、値は `0` |

## よくあるバリエーション

- 簡易版 `AddEntityGroup(string, float)`:グループ名と自動解放間隔のみを指定し、容量、有効期限、優先度はすべてデフォルト値を使用します。
- シリアライズ設定:`EntityComponent` の Inspector でエンティティグループを追加すると、`m_InstancePriority` が `AddEntityGroup` のパラメータとして渡されるため、コードによる介入は不要です。
- `IEntityGroup` を介した直接呼び出し:カスタムのエンティティグループヘルパーやマネージャー拡張では、`IEntityGroup` を取得した後で `SetEntityInstanceLocked` を呼び出すこともできます。

## よくある間違い

- `null` エンティティのロック:`SetEntityInstanceLocked` は `entity.gameObject` にアクセスするため、`null` を渡すと null 参照例外がスローされます。事前に `GetEntity(entityId)` で有効なエンティティを取得してください。
- ロックすれば `HideEntity` で回収されないと思い込む:ロックはオブジェクトプールの自動回収にのみ影響し、`HideEntity` は引き続き即座にエンティティをプールへ戻します。ビジネスロジックの判断と組み合わせて使用してください。
- 優先度の数値が大きいほど「良い」と思い込む：ここでの「高優先度」= 後から回収されるという意味であり、より高品質という意味ではありません。設定前に「重要なアセットは最後に回収する」という意図に合致しているかどうかを確認してください。
- ロック解除の忘れ：ロックされたエンティティインスタンスはオブジェクトプールに残り続け、未解除のロックが大量に蓄積するとオブジェクトプールの容量が枯渇し、後続のエンティティの `ShowEntity` に影響します。

## 背景(オプション)

ロックは最終的に基盤の `IObjectPool<EntityInstanceObject>.SetLocked` へ転送され、オブジェクトプールは `AutoReleaseInterval` がトリガーされた際にロック済みのオブジェクトをスキップします。一方、優先度は `EntityGroup` の構築時に `CreateSingleSpawnObjectPool` へ渡され、オブジェクトプール自身が複数のグループ間で回収対象を選択する際の基準となります。
