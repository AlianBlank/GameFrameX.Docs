# 如何隱藏與回收實體

呼叫 `EntityManager` 的隱藏介面會將實體置於「隱藏」狀態。框架會自動回收實例物件、釋放其佔用的實體群組槽位，並在隱藏完成後觸發 `HideEntityCompleteEventArgs` 事件。隱藏不會銷毀設定資料，實體可隨時透過 `ShowEntity` 再次顯示。

## 前置條件

- 實體管理器已透過 `EntityComponent` 初始化，且實體群組註冊已完成。
- 你已取得要隱藏之實體的實體 ID(`int entityId`)或 `IEntity` 參考。

## 步驟

1. 透過實體元件取得 `IEntityManager`:

```csharp
IEntityManager entityManager = GameEntry.GetComponent<EntityComponent>().EntityManager;
```

2. 依實體 ID 隱藏(最常見)：

```csharp
// 不傳入 userData
entityManager.HideEntity(entityId);

// 附帶業務上下文
entityManager.HideEntity(entityId, userData);
```

其實作會先檢查實體是否仍在載入佇列中；若仍在載入中(`IsLoadingEntity` 為 true),實體會被加入 `m_EntitiesToReleaseOnLoad`,並在載入回呼中回收；否則會從 `m_EntityInfos` 取得 `EntityInfo`,並呼叫 `InternalHideEntity` 完成隱藏。

來源： [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L46-L72)

3. 你也可以直接傳入 `IEntity` 參考：

```csharp
entityManager.HideEntity(entity);
entityManager.HideEntity(entity, userData);
```

當參考為 `null` 時，會拋出 `GameFrameworkException("Entity is invalid.")`。

來源： [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L78-L96)

4. 批次隱藏(常用於切換場景或離開關卡時)：

```csharp
// 隱藏所有已載入的實體
entityManager.HideAllLoadedEntities(userData);

// 隱藏所有載入中的實體(取消未完成的載入)
entityManager.HideAllLoadingEntities();
```

`HideAllLoadedEntities` 會先複製目前 `m_EntityInfos` 的鍵值，再逐一呼叫 `InternalHideEntity`,以避免在迭代期間修改集合;`HideAllLoadingEntities` 則會將所有仍在載入中的實體 ID 加入待釋放集合，並清空載入佇列。

來源： [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L101-L135)

5. 監聽隱藏完成事件，並在回呼中回收自訂資源(可選)：

```csharp
EventComponent.Subscribe(HideEntityCompleteEventArgs.EventId, (sender, args) =>
{
    var e = (HideEntityCompleteEventArgs)args;
    // 可使用 e.EntityId / e.EntityAssetName
    // 在此釋放此實體獨佔持有的資源,例如紋理與 AudioClip
});
```

`HideEntityCompleteEventArgs` 是在 `GameFrameXEntityCroppingHelper` 中被參考的執行階段型別；框架會在 `InternalHideEntity` 結尾發布該事件。

來源： [GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L1-L20)

## 常見變體

- **隱藏並解除父子關係**：先呼叫 `DetachEntity(childEntityId, userData)` 或 `DetachChildEntities(parentEntityId, userData)`,再呼叫 `HideEntity`。`DetachEntity` 會在執行隱藏流程之前，對父實體呼叫 `OnDetached`,並對子實體呼叫 `OnDetachFrom`。
- **附帶使用者資料**：所有 `HideEntity` / `HideAllLoadedEntities` / `DetachEntity` 方法皆有 `object userData` 多載，可將業務上下文傳遞至 `IEntity.OnHide` 與事件參數。
- **隱藏後再次顯示**:`HideEntity` 僅將實體設為隱藏並回收實例;`EntityInfo` 會被保留。只需再次呼叫 `ShowEntity(entityId, ...)` 即可重複使用。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `Log.Error("Can not find entity '{0}'.")` | `entityId` 未註冊或已被隱藏 | 呼叫前確認實體處於 `WillShow` / `Show` 狀態 |
| `GameFrameworkException: Entity is invalid.` | 傳入了 `null` 的 `IEntity` | 改用 `HideEntity(entityId, ...)`,或先進行空值參考檢查 |
| 隱藏後實體仍在場景中 | 僅呼叫了 `HideEntity` 而未監聽 `HideEntityCompleteEventArgs`,導致自訂邏輯未被觸發 | 在事件回呼中釋放自行持有的資源，或確認 `EntityGroupHelper.ReleaseEntity` 已自動回收 |

## 背景說明(選讀)

`HideEntity` 中的回收包含兩部分：框架層在 `InternalHideEntity` 中將 `EntityInfo.Status` 切換為隱藏狀態，呼叫 `EntityGroupHelper.ReleaseEntity` 將物件歸還物件池，並發布 `HideEntityCompleteEventArgs`;業務層則在事件回呼中釋放獨佔持有的資源。兩者共同完成實體實例的回收，且不會銷毀設定。
