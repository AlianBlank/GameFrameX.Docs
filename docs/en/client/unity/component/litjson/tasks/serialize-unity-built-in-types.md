# How to Serialize Unity Built-in Types (Vector3, Quaternion, Color, etc.)

`UnityTypeBindings` has registered JSON exporters for `Vector2 / Vector3 / Vector4 / Quaternion / Color / Color32 / Bounds / Rect / RectOffset / Type`. You can directly call `JsonMapper.ToJson(obj)` in your business code to write these built-in types out as JSON objects. When deserializing, these built-in types will be restored as `JsonData` (because only `Type` has an importer registered in the registry), so you need to manually reconstruct the struct after obtaining the `JsonData`.

## Prerequisites

- The `GameFrameX.LitJSON.Runtime` assembly has been imported (included by default in the Unity Package).
- The static constructor will automatically call `Register()` the first time the type is accessed, no manual triggering is required.

## Steps

1. **Directly call `JsonMapper.ToJson` to serialize the struct**

   Any type registered by `UnityTypeBindings.Register()`, whether as a field of an object or passed directly to `ToJson`, will be written out according to the schema below:

   ```csharp
   using GameFrameX.LitJSON.Runtime;
   using UnityEngine;

   var player = new
   {
       position = new Vector3(1f, 2f, 3f),
       rotation = Quaternion.identity,
       tint     = new Color(0.1f, 0.2f, 0.3f, 1f),
       hp       = 100
   };

   string json = JsonMapper.ToJson(player);
   // {"position":{"x":1.0,"y":2.0,"z":3.0},
   //  "rotation":{"x":0.0,"y":0.0,"z":0.0,"w":1.0},
   //  "tint":{"r":0.1,"g":0.2,"b":0.3,"a":1.0},
   //  "hp":100}
   ```

   Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L50-L114)

2. **View the written field names**

   The table below shows the corresponding field names in JSON for each built-in type (determined by the exporter registered by `UnityTypeBindings`):

   | Type | Written Fields |
   |------|----------|
   | `Vector2` | `x`, `y` |
   | `Vector3` | `x`, `y`, `z` |
   | `Vector4` | `x`, `y`, `z`, `w` |
   | `Quaternion` | `x`, `y`, `z`, `w` |
   | `Color` / `Color32` | `r`, `g`, `b`, `a` |
   | `Bounds` | `center` (nested Vector3), `size` (nested Vector3) |
   | `Rect` | `x`, `y`, `width`, `height` |
   | `RectOffset` | `top`, `left`, `bottom`, `right` |
   | `Type` | Full type name (`FullName`) |

   Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L44-L150)

3. **Manually restore during deserialization**

   `UnityTypeBindings` only registers an importer for `Type`; struct types currently have no importer, so `JsonMapper.ToObject<Vector3>(json)` will throw an exception. The safe approach is to first use `ToObject<JsonData>` to get the dictionary, then reconstruct by fields:

   ```csharp
   using GameFrameX.LitJSON.Runtime;
   using UnityEngine;

   string json = "{\"x\":1.0,\"y\":2.0,\"z\":3.0}";
   JsonData data = JsonMapper.ToObject<JsonData>(json);

   Vector3 v = new Vector3(
       (float)data["x"],
       (float)data["y"],
       (float)data["z"]
   );
   ```

   When containing nested structures (e.g., `Bounds`), simply expand `JsonData` layer by layer:

   ```csharp
   string boundsJson = "{\"center\":{\"x\":0,\"y\":0,\"z\":0},\"size\":{\"x\":1,\"y\":1,\"z\":1}}";
   JsonData bd = JsonMapper.ToObject<JsonData>(boundsJson);

   Bounds bounds = new Bounds(
       new Vector3((float)bd["center"]["x"], (float)bd["center"]["y"], (float)bd["center"]["z"]),
       new Vector3((float)bd["size"]["x"],    (float)bd["size"]["y"],    (float)bd["size"]["z"])
   );
   ```

## Common Variants

- **Built-in types in nested objects**: When using `Vector3` as a field/property of some class, the serializer will automatically follow the `RegisterExporter<Vector3>` path without any additional configuration.
- **Custom ScriptableObject or MonoBehaviour**: When using built-in types as `SerializeField` fields, `JsonMapper.ToJson` will also write them out according to the table above.
- **Want to write only a single field**: Simply use `JsonMapper.ToJson(new { pos = transform.position })`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `JsonException: Can't assign object ... to ...` when calling `ToObject<Vector3>` | Unity built-in types only have an exporter registered, no importer | Change to first `ToObject<JsonData>`, then manually construct by fields |
| JSON shows `{}` instead of fields | `ToJson` was called before registration, or same-named fields in custom class were ignored | Confirm that the `UnityTypeBindings` assembly is referenced (the static constructor will provide fallback registration) |
| Field names differ from Unity defaults | This binding uses lowercase field names (`x`/`y`/`r`/`g`...) | Read/write according to the field names in this table, do not assume `X`/`R` |
| `Type` field deserializes to `null` | `Type.GetType` cannot find that FullName (cross-assembly/dynamic assembly) | Use `Type.GetType(s + ", AssemblyName")` instead, or register an importer yourself |

## Background (Optional)

`UnityTypeBindings` ensures that registration only happens once through a static constructor and the `_registered` flag; it maps each built-in type as a JSON object rather than an array for human readability and version evolution (reordering `x`/`y`/`z` will not break deserialization). For the overall architecture of `JsonMapper`, see the "Overview" page.
