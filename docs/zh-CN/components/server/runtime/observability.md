# 配置 OpenTelemetry / Prometheus 指标与健康检查

本节演示如何开启 GameFrameX.Server 内置的 OpenTelemetry 遥测，并将 Prometheus 指标(`/metrics`)与健康检查(`/health`)暴露给监控系统使用。

## 前置条件

- 已部署 GameFrameX.Server,并能正常启动。
- 监控系统能访问到服务器上由 `MetricsPort` 指定的端口(默认 `29090`)。

## 操作步骤

1. 在启动参数或环境变量中开启 OpenTelemetry 总开关。

   ```bash
   --IsOpenTelemetry=true
   ```

   启动命令示例(`docker-compose.yml` 中的 `MetricsPort` 与 `APMPort` 行可以借鉴):

   ```bash
   --InnerPort=29100 \
   --MetricsPort=29090 \
   --IsEnableHttp=true
   ```

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L115-L121)

2. 开启 Prometheus 指标导出(默认 `false`,需要 `IsOpenTelemetry=true`)。

   ```bash
   --IsOpenTelemetryMetrics=true
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

3. (可选)开启分布式追踪。

   ```bash
   --IsOpenTelemetryTracing=true
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

4. 设置指标收集端口。如未设置,使用默认值 `0`(即关闭对外端口)。

   ```bash
   --MetricsPort=29090
   ```

   默认值与示例值见下表,Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

5. 重启服务,验证两个端点可用:

   | 端点 | URL | 说明 |
   |------|-----|------|
   | 健康检查 | `http://<host>:29090/health` | 服务存活与就绪状态 |
   | Prometheus 指标 | `http://<host>:29090/metrics` | Prometheus 抓取的指标文本 |

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L175-L177)

## 常见变体

- **Docker Compose 部署**:在 `docker-compose.yml` 的环境变量区追加以下行即可,无需改动镜像。
  参考 [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)
- **仅启用健康检查、不导出指标**:保持 `IsOpenTelemetryMetrics=false`,只需把 `/health` 端点接入负载均衡器或 K8s readiness 探针。
- **导出到远端 OTLP 收集器**:在 `IsOpenTelemetry=true` 基础上开启 `IsOpenTelemetryTracing` 即可输出链路数据(具体收集器地址按部署需要再行配置)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 访问 `/metrics` 返回连接拒绝 | `IsOpenTelemetry` 未开启 | 加上 `--IsOpenTelemetry=true` 后重启 |
| 开启 `IsOpenTelemetryMetrics` 后仍无指标 | 缺少总开关 | 该参数依赖 `IsOpenTelemetry=true` |
| 端口冲突 | `MetricsPort` 与 `APMPort` 占用同一端口 | 显式设置 `MetricsPort=29090`,并确保宿主机端口空闲 |
| Prometheus 抓不到数据 | 防火墙未放行端口 | 在安全组/防火墙中放行 `MetricsPort` |

## 配置项速查

| 名称 | 类型/默认值 | 说明 |
|------|-------------|------|
| `IsOpenTelemetry` | `bool`,默认 `false` | OpenTelemetry 遥测总开关 |
| `IsOpenTelemetryMetrics` | `bool`,默认 `false` | 启用 Prometheus 指标导出,需 `IsOpenTelemetry=true` |
| `IsOpenTelemetryTracing` | `bool`,默认 `false` | 启用分布式追踪,需 `IsOpenTelemetry=true` |
| `MetricsPort` | `int`,默认 `0` | 指标收集端口,示例值 `29090` |

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)、[README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

## 背景

OpenTelemetry 是 CNCF 毕业的可观测性标准,GameFrameX.Server 通过总开关 + 子开关的两层设计,把指标与追踪拆开,方便在不需要全量遥测时只暴露健康检查,降低对宿主机的端口与资源占用。
