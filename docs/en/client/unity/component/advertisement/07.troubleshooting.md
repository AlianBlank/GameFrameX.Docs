# Troubleshooting

This document collects common issues and their solutions when using the GameFrameX Advertisement module.

## Overview

The GameFrameX Advertisement module provides a unified ad integration abstraction layer for Unity projects. Since ad functionality involves multiple platforms (Android, iOS, WebGL) and multiple ad network SDKs (AdMob, Unity Ads, IronSource, etc.), you may encounter various configuration and runtime issues during actual use. This document aims to help developers quickly identify and resolve these common issues.

> **Tip**: When troubleshooting issues, please first confirm that you have correctly installed and configured the ad module. For basic usage instructions, please refer to the [Getting Started](../3-getting-started) and [Core Concepts](../4-core-concepts) documentation.

## Core Architecture

Before diving into troubleshooting, understanding the module's core architecture will help you better understand the root causes of issues:

```mermaid
flowchart TD
    subgraph Unity["Unity Scene Layer"]
        GameObj[GameObject + AdvertisementComponent]
    end

    subgraph Framework["GameFrameX Framework Layer"]
        GFX[GameFrameworkEntry]
        AdComp[AdvertisementComponent]
    end

    subgraph Interface["Interface Abstraction Layer"]
        IAM[IAdvertisementManager]
        BAM[BaseAdvertisementManager]
    end

    subgraph Impl["Concrete Implementation Layer"]
        ADM[Ad Manager Implementation<br/>AdMob/IronSource/UnityAds...]
    end

    GameObj --> AdComp
    AdComp --> GFX
    GFX -->|GetModule| IAM
    IAM <|.. BAM
    BAM <|-- ADM
```

**Workflow:**
1. The developer adds `AdvertisementComponent` to a GameObject in the scene
2. `AdvertisementComponent` gets the ad manager through `GameFrameworkEntry.GetModule<IAdvertisementManager>()` in `Awake()`
3. Calls `Initialize()` to initialize the ad manager in `Start()`
4. Interacts with the ad system through `Load()`, `Show()`, and `Play()` methods

## Common Issues and Solutions

### Issue 1: Ad Manager Initialization Failure

#### Symptoms

When running the game, the console displays the following error:
```
Log.Fatal: Advertisement manager is invalid.
```

#### Cause Analysis

This error indicates that `GameFrameworkEntry.GetModule<IAdvertisementManager>()` returned `null`, meaning the framework could not find an implementation of the `IAdvertisementManager` interface.

Possible root causes:
1. **Ad manager implementation not registered**: No module in the framework implements the `IAdvertisementManager` interface
2. **Assembly stripping issue**: Unity's IL2CPP or code stripping removes the ad manager implementation class
3. **Module loading order issue**: The ad module is loaded before other dependent modules

#### Solution

**Step 1: Confirm ad manager implementation exists**

Ensure that a concrete implementation class of the `IAdvertisementManager` interface exists in your project. For example:

```csharp
using GameFrameX.Advertisement.Runtime;
using GameFrameX.Runtime;
using UnityEngine;
using UnityEngine.Scripting;

[Preserve]
public class MyAdsManager : BaseAdvertisementManager
{
    public override void Initialize(string adUnitId, bool debug = false)
    {
        // Implement ad SDK initialization logic
    }

    public override void Play(System.Action<bool> playResult, string customData = null)
    {
        // Implement ad playback logic
    }

    public override void Show(System.Action<string> success, System.Action<string> fail, 
        System.Action<bool> onShowResult, string customData = null)
    {
        // Implement ad display logic
    }

    public override void Load(System.Action<string> success, System.Action<string> fail, 
        string customData = null)
    {
        // Implement ad loading logic
    }
}
```

> Source: [BaseAdvertisementManager.cs]({{file_base_url}}/Runtime/Advertisement/BaseAdvertisementManager.cs#L11-L88)

**Step 2: Resolve assembly stripping issue**

If using IL2CPP or code stripping, ensure the `[Preserve]` attribute is added (Unity preserves classes with this attribute):

```csharp
[Preserve]
public class MyAdsManager : BaseAdvertisementManager
{
    // ...
}
```

Also add preservation rules in `link.xml` (located in the `Assets/Plugins/` directory):

```xml
<linker>
    <assembly fullname="YourAssemblyName" preserve="all">
        <type fullname="YourNamespace.MyAdsManager" preserve="all"/>
    </assembly>
</linker>
```

**Step 3: Check module registration**

Ensure the ad manager is correctly registered at game startup. The specific method depends on your GameFrameX framework configuration.

### Issue 2: Ad Unit ID is Empty

#### Symptoms

The console outputs a warning or error indicating the ad unit ID is not set:
```
AdvertisementComponent: AdUnitId is empty!
```

#### Cause Analysis

This issue occurs when `AdvertisementComponent` tries to select an ad unit ID based on the current platform but cannot find the corresponding configuration.

Check the code logic (see AdvertisementComponent.cs lines 69-87):

```csharp
AdUnitId =
#if UNITY_WEBGL
#if ENABLE_WECHAT_MINI_GAME
        m_adUnitIdWebGLWeChat
#elif ENABLE_DOUYIN_MINI_GAME
        m_adUnitIdWebGLDouYin
#elif ENABLE_KUAISHOU_MINI_GAME
        m_adUnitIdWebGLKuaiShou
#else
        m_adUnitIdWebGL
#endif
#elif UNITY_ANDROID
        m_adUnitIdAndroid
#elif UNITY_IOS
        m_adUnitIdiOS
#else
        string.Empty
#endif
        ;
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L69-L87)

#### Solution

**Step 1: Configure ad unit IDs in Inspector**

1. In the Unity scene, select the GameObject with `AdvertisementComponent`
2. In the Inspector panel, fill in the corresponding ad unit ID based on the target platform:
   - **Android Ad Unit ID**: Fill in the ID from Google AdMob or other Android ad networks
   - **IOS Ad Unit ID**: Fill in the ID from iOS ad networks
   - **WebGL Ad Unit ID**: Fill in the Web platform ad ID
   - **WebGL WeChat/Douyin/Kuaishou Ad Unit ID**: Fill in the ad ID for the corresponding mini-game platform

> Source: [AdvertisementComponentInspector.cs]({{file_base_url}}/Editor/Inspector/AdvertisementComponentInspector.cs#L41-L47)

**Step 2: Verify platform macro definitions**

If the ad unit ID is still empty, check the project's compilation macro definitions:
- Open `Edit > Project Settings > Player`
- Check **Scripting Define Symbols** in **Other Settings**
- Ensure the correct macros are defined for the WebGL platform: `ENABLE_WECHAT_MINI_GAME`, `ENABLE_DOUYIN_MINI_GAME`, or `ENABLE_KUAISHOU_MINI_GAME`

**Step 3: Use code to set dynamically**

If you need to dynamically set the ad unit ID at runtime:

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;

public class AdInitializer : MonoBehaviour
{
    public AdvertisementComponent adComponent;
    
    void Start()
    {
        // Dynamically set ad unit ID
        string customAdUnitId = "your_ad_unit_id_here";
        adComponent.Initialize(customAdUnitId, isDebug: true);
    }
}
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L100-L105)

### Issue 3: Ad Loading Failure

#### Symptoms

After calling the `Load()` method, the `fail` callback is triggered with error messages like:
```
Ad load failed: No ad available
Ad load failed: Network error
```

#### Cause Analysis

Ad loading failure can have multiple causes:

1. **Ad SDK not properly initialized**: Ad SDK not correctly configured in `Initialize()`
2. **Network issues**: Device network connection abnormal
3. **Ad unit configuration error**: Ad unit ID not properly configured in the ad platform backend
4. **Empty ad inventory**: No available ads from the current ad platform
5. **SDK version issues**: Ad SDK version too old or incompatible

#### Solution

**Step 1: Check initialization code**

Ensure the ad SDK is properly initialized before displaying ads:

```csharp
void Start()
{
    var adComponent = GetComponent<AdvertisementComponent>();
    // AdvertisementComponent automatically calls Initialize in Start
    // If manual initialization is needed:
    // adComponent.Initialize("your_ad_unit_id", isDebug: true);
    
    // Recommended: preload ads in advance
    adComponent.Load(
        (message) => Debug.Log("Ad loaded successfully: " + message),
        (error) => Debug.LogError("Ad load failed: " + error)
    );
}
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L163-L167)

**Step 2: Use test mode**

During development, enable debug mode to get test ads:

```csharp
// Check "Debug Mode" in Inspector
// Or via code:
adComponent.Initialize("your_ad_unit_id", isDebug: true);
```

**Step 3: Check network connection**

Ensure the device has a valid network connection. For mobile devices, note:
- Cellular data may be restricted by the ad SDK
- Network permissions need to be declared in `AndroidManifest.xml` (Android) or `Info.plist` (iOS)

**Step 4: Verify ad unit configuration**

Log in to the ad platform developer console and confirm:
- Ad unit has been created and activated
- Ad unit ID matches the configuration in code
- Ad unit type (rewarded video/interstitial/banner) matches your request

### Issue 4: Ad Display Failure

#### Symptoms

After calling the `Show()` method, the `fail` callback is triggered with error messages like:
```
Ad display failed: Ad not ready
Ad display failed: Show() called before Load()
```

#### Cause Analysis

1. **Ad not preloaded**: `Load()` was not called to load the ad before calling `Show()`
2. **Loaded ad expired**: Ad was loaded but not displayed for a long time, cache expired
3. **Ad skipped**: Internal ad SDK error

#### Solution

**Correct ad display flow:**

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;

public class AdCaller : MonoBehaviour
{
    private AdvertisementComponent adComponent;

    void Start()
    {
        adComponent = GetComponent<AdvertisementComponent>();
        
        // Step 1: Load ad
        LoadAd();
    }

    public void LoadAd()
    {
        adComponent.Load(
            (message) => 
            { 
                Debug.Log("Ad loaded successfully, can call Show"); 
                // Can show after successful load
                ShowAd();
            },
            (error) => { Debug.LogError("Ad load failed: " + error); }
        );
    }

    public void ShowAd()
    {
        adComponent.Show(
            (message) => Debug.Log("Ad displayed successfully: " + message),
            (error) => Debug.LogError("Ad display failed: " + error),
            (reward) => 
            {
                if (reward)
                {
                    Debug.Log("User watched ad completely, granting reward");
                    // Add reward granting logic here
                }
                else
                {
                    Debug.Log("User skipped ad, no reward granted");
                }
            }
        );
    }

    // Simplified version using Play method
    public void PlayAd()
    {
        adComponent.Play(
            (reward) => 
            {
                if (reward)
                {
                    Debug.Log("Ad playback complete, granting reward");
                }
            },
            "custom_data_for_ad"
        );
    }
}
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L121-L151)

**Key Points:**
- You must call `Load()` first to load the ad, then call `Show()` after the `success` callback
- Ads have an expiration time after loading; they should be displayed as soon as possible
- It is recommended to preload ads at game startup

### Issue 5: Platform-Specific Issues

#### 5.1 WebGL Platform Issues

**Problem: Ads don't display after WebGL build**

Possible causes and solutions:

1. **Browser ad blockers**: Some browsers or ad blocker plugins prevent ad requests
   - Use private/incognito mode for testing

2. **Cross-origin issues**: Ad SDK requires correct CORS configuration
   - Ensure server response headers include the correct `Access-Control-Allow-Origin`

3. **Mini-game platform macro definitions**: WeChat/Douyin/Kuaishou mini-games require corresponding macros
   - Add in Player Settings: `ENABLE_WECHAT_MINI_GAME` or `ENABLE_DOUYIN_MINI_GAME` or `ENABLE_KUAISHOU_MINI_GAME`

#### 5.2 Android Platform Issues

**Problem: App crashes after Android build**

Possible causes and solutions:

1. **Missing permissions**: Ensure `AndroidManifest.xml` includes necessary permissions:
   ```xml
   <uses-permission android:name="android.permission.INTERNET"/>
   <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>
   ```

2. **SDK version conflicts**: Check for conflicts between multiple ad SDK versions
   - Use Gradle dependency resolution tools to view and exclude conflicts

3. **ProGuard/R8 rules**: If code obfuscation is enabled, you may need to add preservation rules:
   ```properties
   -keep class com.your.ad.provider.** { *; }
   -dontwarn com.your.ad.provider.**
   ```

#### 5.3 iOS Platform Issues

**Problem: Ads don't display after iOS build**

Possible causes and solutions:

1. **Advertising Identifier (IDFA)**: iOS 14+ requires user authorization for tracking
   - Add `NSUserTrackingUsageDescription` in `Info.plist`

2. **App Transport Security (ATS)**: Ensure HTTP connections to ad domains are allowed
   - Configure `NSAppTransportSecurity` in `Info.plist`

3. **Swift version compatibility**: Some ad SDKs require specific Swift versions
   - Check the Swift version in Xcode project settings

### Issue 6: Reward Timing Issues

#### Symptoms

After users watch a rewarded video, rewards are not correctly granted; or users exit halfway through the ad playback, but rewards are still granted.

#### Cause Analysis

The reward granting logic for rewarded video ads needs to be determined based on the boolean value of the `onShowResult` callback:

- `true`: User watched the ad completely, reward should be granted
- `false`: User skipped the ad or interrupted playback, reward should not be granted

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L126-L127)

#### Solution

Ensure rewards are correctly handled in the `onShowResult` callback:

```csharp
public void ShowRewardAd()
{
    adComponent.Show(
        // success callback: ad starts displaying
        (message) => Debug.Log("Ad starts displaying: " + message),
        
        // fail callback: ad display failed
        (error) => 
        {
            Debug.LogError("Ad display failed: " + error);
            // Do not grant reward
        },
        
        // onShowResult callback: ad closed
        (shouldReward) => 
        {
            if (shouldReward)
            {
                // User watched ad completely, grant reward
                Debug.Log("Granting reward: Coins + 100");
                AddCoins(100);
            }
            else
            {
                // User did not watch completely, no reward
                Debug.Log("User skipped ad, no reward granted");
            }
        }
    );
}
```

**Secure Reward Granting Recommendations:**

1. **Server-side verification**: For high-value rewards, server-side reward verification is recommended
2. **Use ad platform server callbacks**: Most ad platforms provide server-to-server reward callbacks
3. **Prevent duplicate granting**: Use flags to prevent the same ad from granting rewards multiple times

### Issue 7: Component Not Working in Editor Mode

#### Symptoms

When running in the Unity Editor, ad functionality does not work properly.

#### Cause Analysis

1. **Editor doesn't support certain ad SDKs**: Most ad SDKs only support real devices or specific build platforms
2. **Module not initialized in Editor mode**

#### Solution

**Create an Editor-specific mock ad manager:**

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;
using System;

[CreateAssetMenu(menuName = "GameFrameX/Editor Mock Ads Manager")]
public class EditorMockAdsManager : BaseAdvertisementManager
{
    [SerializeField] private bool simulateSuccess = true;
    [SerializeField] private float simulatedDelay = 1.0f;

    public override void Initialize(string adUnitId, bool debug = false)
    {
        Debug.Log($"[Editor] Mock Ads Manager initialized: {adUnitId}");
    }

    public override void Play(Action<bool> playResult, string customData = null)
    {
        Debug.Log($"[Editor] Mock Play called, customData: {customData}");
        playResult?.Invoke(simulateSuccess);
    }

    public override void Show(Action<string> success, Action<string> fail, 
        Action<bool> onShowResult, string customData = null)
    {
        Debug.Log($"[Editor] Mock Show called, customData: {customData}");
        
        if (simulateSuccess)
        {
            success?.Invoke("Mock ad shown successfully");
            onShowResult?.Invoke(true);
        }
        else
        {
            fail?.Invoke("Mock ad failed");
        }
    }

    public override void Load(Action<string> success, Action<string> fail, 
        string customData = null)
    {
        Debug.Log($"[Editor] Mock Load called");
        
        if (simulateSuccess)
        {
            success?.Invoke("Mock ad loaded successfully");
        }
        else
        {
            fail?.Invoke("Mock ad failed to load");
        }
    }
}
```

**Select Editor mock implementation in Inspector:**

1. Select the AdvertisementComponent object in the scene
2. Find the ad manager implementation type selector in the Inspector
3. Select the Editor mock manager

## Diagnostic Tools and Logging

### Enabling Debug Mode

Debug mode outputs detailed ad operation logs to help troubleshoot issues:

```csharp
// Method 1: Check "Debug Mode" in Inspector

// Method 2: Set via code
adComponent.Initialize("your_ad_unit_id", isDebug: true);
```

### Key Log Tags

Filtering the following tags in the console can help locate issues:

| Log Tag | Meaning |
|---------|---------|
| `Advertisement manager is invalid` | Ad manager not registered |
| `Ad loaded successfully/failed` | Load operation result |
| `Ad displayed successfully/failed` | Display operation result |
| `Granting reward` | Reward granting logic |

## Common Error Code Reference

| Error Code | Meaning | Solution |
|------------|---------|----------|
| `No ad available` | No ad inventory currently available | Wait and retry, or contact the ad platform |
| `Network error` | Network connection issue | Check network connection |
| `Ad not ready` | Ad not loaded | Call Load() method first |
| `Show() called before Load()` | Display sequence error | Ensure Load before Show |
| `Invalid ad unit ID` | Ad unit ID is invalid | Check ad unit ID configuration |
| `SDK not initialized` | SDK not initialized | Check Initialize() call |
