# WebProtoBuff API 빠른 참조(Post / Timeout / 연결 수)

이 페이지에는 WebProtoBuff 모듈의 공개 API가 수록되어 있습니다: `Post<T>` 요청 메서드, `Timeout` / `RequestTimeout` / `MaxConnectionPerServer` 세 가지 설정의 기본값과 의미, 그리고 요청 과정에서 발생할 수 있는 예외입니다. 모든 항목은 소스 코드의 실제 시그니처에서 가져온 것입니다.

## Post 요청 메서드

| 이름 | 시그니처 | 설명 |
|------|------|------|
| `IWebProtoBuffManager.Post<T>` | `Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage` | Protobuf 메시지를 담은 POST 요청을 보내고 응답을 `T`로 파싱합니다; `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` 매크로가 활성화된 경우에만 사용할 수 있습니다 |
| `WebProtoBuffComponent.Post<T>` | `Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage` | Unity 컴포넌트 계층의 동명 전달 메서드로, 내부적으로 관리자의 `Post<T>`를 호출합니다 |

인터페이스 정의는 [IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L9-L29)에서, 컴포넌트 전달은 [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108)에서 확인할 수 있습니다.

`Post<T>` 내부 흐름: 메시지를 `MessageHttpObject`(`Id`, `UniqueId`, `Body` 포함)로 감싸고 직렬화한 후 대기 큐에 넣습니다; 응답이 반환되면 먼저 `Id`로 응답 타입을 역조회하여, `T`와 일치하지 않으면 오류 로그를 남기고 `default`를 반환합니다:

```csharp
public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
{
    DebugSendLog(message);
    var webBufferResult = await PostInner(url, message);
    if (webBufferResult.IsNotNull())
    {
        var messageObjectHttp = SerializerHelper.Deserialize<MessageHttpObject>(webBufferResult.Result);
        if (messageObjectHttp.IsNotNull() && messageObjectHttp.Id != default)
        {
            var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
            if (messageType != typeof(T))
            {
                Log.Error($"Response message type is invalid. Expected '{typeof(T).FullName}', actual '{messageType.FullName}'.");
                return default;
            }

            var messageObject = SerializerHelper.Deserialize<T>(messageObjectHttp.Body);
            DebugReceiveLog(messageObject);
            return messageObject;
        }
    }

    return default;
}
```

## 설정 속성(Timeout / 연결 수)

| 이름 | 타입 | 기본값 | 정의 위치 | 설명 |
|------|------|--------|--------|------|
| `Timeout` | `float` | `5f`(초) | `IWebProtoBuffManager` / `WebProtoBuffManager` / `WebProtoBuffComponent` | POST 요청 타임아웃 시간, 단위는 초; 값을 설정하면 `RequestTimeout`이 함께 갱신됩니다 |
| `RequestTimeout` | `TimeSpan` | `TimeSpan.FromSeconds(5)` | `WebProtoBuffManager` | `Timeout`에서 환산된 요청 타임아웃 시간으로, 실제 요청 전송 시 사용됩니다 |
| `MaxConnectionPerServer` | `int` | `8` | `WebProtoBuffManager` | 서버당 최대 동시 연결 수; 동시에 전송 중인 요청 수가 이 값에 도달하면 이후 요청은 대기 큐에 머무릅니다 |
| `m_Timeout`(직렬화 필드) | `float` | `5f` | `WebProtoBuffComponent` | Inspector의 "타임아웃 시간. 단위: 초"이며, `Awake` 시 관리자에 기록됩니다 |

```csharp
public WebProtoBuffManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

public int MaxConnectionPerServer { get; set; }

public TimeSpan RequestTimeout { get; set; }
```

## 런타임 동작 빠른 참조

| 동작 | 근거 |
|------|------|
| 요청 Content-Type은 `application/x-protobuf`로 고정 | `ProtoBufContentType` 상수 |
| WebGL이 아닌 플랫폼은 `HttpWebRequest`를 사용하며, `request.Timeout`은 `RequestTimeout.TotalMilliseconds` 값 사용 | `MakeProtoBufBytesRequest` |
| WebGL 플랫폼은 `UnityWebRequest`를 사용하며, `unityWebRequest.timeout`은 `(int)RequestTimeout.TotalSeconds` 값 사용 | `MakeProtoBufBytesRequest` |
| 타임아웃이 캐치되면 `TimeoutException`으로 작업이 종료됨 | `WebExceptionStatus.Timeout` 분기 |
| 동시 처리 상한은 `MaxConnectionPerServer`가 제어: `m_SendingProtoBufList.Count < MaxConnectionPerServer`인 경우에만 대기 큐에서 요청 하나를 꺼냄 | `UpdateProtoBuf` |
| 종료(Shutdown) 시 대기 큐와 전송 목록의 모든 `WebProtoBuffData`가 참조 풀에 반환됨 | `ShutdownProtoBuf` |

## 컴포넌트 초기화

`WebProtoBuffComponent`는 Unity 씬에 부착하는 래퍼 컴포넌트로, `Awake`에서 `GameFrameworkEntry`를 통해 모듈을 가져와 Inspector에 직렬화된 타임아웃을 관리자에 기록합니다; 모듈을 가져올 수 없으면 `Log.Fatal("Web manager is invalid.")`를 출력합니다:

```csharp
m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
if (m_WebProtoBuffManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebProtoBuffManager.Timeout = m_Timeout;
```
