# 実行環境変数と起動引数の設定

`XCodeConfig.json` のトップレベルフィールド `environmentVariables`（XcScheme 環境変数、キーと値はいずれも文字列）と `launcherArgs`（XcScheme 起動引数リスト）を使用することで、生成された Xcode プロジェクトの Run Scheme に対して実行環境変数と起動引数を設定できます。ビルド完了後、`PostProcessBuildHelper` によって `Unity-iPhone.xcscheme` に自動的に書き込まれるため、Xcode を手動で変更する必要はありません。

## 前提条件

- プロジェクトに `com.gameframex.unity.xcode` パッケージがインストールされていること（Unity iOS プラットフォーム）。
- ビルド出力ディレクトリに `Unity-iPhone.xcodeproj` が存在すること（つまり、iOS ビルドを一度完了していること）。
- 設定ファイルの名前は `XCodeConfig.json` とし、プロジェクト内の任意の場所に配置できます。複数ファイルの共存（自動マージ）もサポートされます。

## 操作手順

1. プロジェクト内の任意の場所で `XCodeConfig.json` を作成または開きます。
2. `environmentVariables` と `launcherArgs` の 2 つのトップレベルフィールドを追加します：

```json
{
  "environmentVariables": {
    "IDEPreferLogStreaming": "YES",
    "OS_ACTIVITY_MODE": "disable"
  },
  "launcherArgs": ["-debug"]
}
```

3. iOS ビルドを実行します。ビルド終了後、`PostProcessBuildHelper.OnPostprocessBuild` が以下を順に呼び出します：

```csharp
// 起動環境変数
RunEnvironmentVariables(path, finalConfig.Get<Hashtable>("environmentVariables"));
// 実行起動引数
RunArgument(path, finalConfig.Get("launcherArgs") as ArrayList);
```

4. 生成された Xcode プロジェクトを開き、`Product → Scheme → Edit Scheme → Run` に進むと、`Arguments Passed On Launch` と `Environment Variables` に書き込まれた内容が表示されます。

## フィールド説明

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `environmentVariables` | object | XcScheme 環境変数、キーと値はいずれも文字列 |
| `launcherArgs` | string[] | XcScheme 起動引数リスト |

- 環境変数は `EnvironmentVariable` ノードとして書き込まれ、`key`/`value` は設定内のキーと値で、常に `isEnabled="YES"` が付加されます。
- 起動引数は 1 つずつ書き込まれ、空白文字列（空白文字のみ）はスキップされます。
- 両フィールドが空または存在しない場合はそのままスキップされ、エラーは発生しません（ログに「パラメータが空またはデータが空のため、設定をスキップします」と出力されます）。

## よくあるバリエーション

- **起動引数のみを設定し、環境変数を設定しない**：2 つのトップレベルフィールドは相互に独立しているため、どちらか一方のみを記述できます：

```json
{
  "launcherArgs": ["-debug", "-stage"]
}
```

- **複数設定ファイルのマージ**：異なる場所にある `XCodeConfig.json` は自動的にマージされるため、環境変数と起動引数を別々のファイルに分けて管理できます。
- **よく使う環境変数の例**：`IDEPreferLogStreaming=YES`（コンソールログのストリーミング出力）、`OS_ACTIVITY_MODE=disable`（システムログ出力の無効化）。リポジトリの README もこの例を使用しています。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| ログに「[XcScheme-EnvironmentVariables] パラメータが空またはデータが空のため、設定をスキップします」と出力される | 設定内の `environmentVariables` が空オブジェクトまたは存在しない | トップレベルフィールドのスペルが `environmentVariables` であり、少なくとも 1 つのキーと値のペアが含まれていることを確認してください |
| ログに「[XcScheme-Argument] パラメータが空またはデータが空のため、設定をスキップします」と出力される | `launcherArgs` が空配列または存在しない | トップレベルフィールドのスペルが `launcherArgs` であり、配列型であることを確認してください |
| 例外 "The xcscheme document does not contain build configuration setting" がスローされる | scheme ファイルに `LaunchAction` ノードが存在しない | ビルド出力ディレクトリ内の `Unity-iPhone.xcodeproj/xcshareddata/xcschemes/Unity-iPhone.xcscheme` が Unity からエクスポートされた有効な scheme ファイルであることを確認してください |
| Xcode で環境変数/起動引数が確認できない | 書き込まれるのは Run Scheme の `LaunchAction` ノードである | Build Configuration や他の Scheme ではなく、`Edit Scheme → Run` 配下の Arguments タブで確認してください |

## 検証

- Unity iOS パッケージのビルド後、Editor ログを確認すると、`设置项目[XcScheme-EnvironmentVariables]开始/结束` と `设置项目[XcScheme-Argument]开始/结束` が順に出力されるはずです。
- テキストエディタで `Unity-iPhone.xcodeproj/xcshareddata/xcschemes/Unity-iPhone.xcscheme` を開くと、`LaunchAction` ノード配下に以下のようなノードが確認できます：

```xml
<EnvironmentVariables>
  <EnvironmentVariable key="OS_ACTIVITY_MODE" value="disable" isEnabled="YES"/>
</EnvironmentVariables>
```

対応するソースコードの書き込みロジック（`AddEnvironmentVariablesPassedOnLaunch` からの抜粋）：

```csharp
xElement?.Add(new XElement("EnvironmentVariable", new object[3]
{
    new XAttribute("key", key),
    new XAttribute("value", value),
    new XAttribute("isEnabled", "YES")
}));
```

## 背景

`RunArgument` は Unity 内蔵の `UnityEditor.iOS.Xcode.XcScheme` API を基に scheme ファイルを読み書きします。`RunEnvironmentVariables` は `XDocument` で直接 scheme XML を解析し、`LaunchAction` 配下の `EnvironmentVariables` ノードを検索または作成してからエントリを追加します。両者の書き込み先ファイルはいずれも `Unity-iPhone.xcodeproj/xcshareddata/xcschemes/Unity-iPhone.xcscheme` です。
