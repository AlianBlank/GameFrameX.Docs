# 如何使用 MurmurHash3/xxHash 等高性能哈希

`GameFrameX.Foundation.Hash` 提供 MurmurHash3 与 xxHash 两种非加密型高性能哈希算法的开箱即用 API,直接调用静态方法即可对字符串、字节数组、Type 计算 32/64/128 位哈希值,常用于哈希表键、布隆过滤器、负载均衡分片等非安全场景。

## 前置条件

- 项目目标框架需为 .NET(代码使用 `uint`/`ulong`/`ArgumentNullException.ThrowIfNull` 等 BCL API)。
- 项目引用 `GameFrameX.Foundation.Hash` 程序集;xxHash 实现依赖 NuGet 包 `Standart.Hash.xxHash`。

## 操作步骤

### 1. 计算字符串/字节数组的 MurmurHash3

`MurmurHash3Helper` 提供两个重载,默认种子为 `27`:

```csharp
using GameFrameX.Foundation.Hash;

// 字符串版本:UTF-8 编码后哈希,seed 可省略(默认 27)
uint hash1 = MurmurHash3Helper.Hash("hello");
uint hash2 = MurmurHash3Helper.Hash("hello", seed: 1234u);

// 字节数组版本:显式指定 length 与 seed
byte[] data = System.Text.Encoding.UTF8.GetBytes("hello");
uint hash3 = MurmurHash3Helper.Hash(data, (uint)data.Length, seed: 27u);
```

Source: [MurmurHash3Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/MurmurHash3Helper.cs#L62-L68)

### 2. 计算 xxHash 32/64/128 位哈希

`XxHashHelper` 同时提供 `byte[]`、`string`、`Type` 和泛型重载,返回类型分别为 `uint`、`ulong`、`uint128`:

```csharp
using GameFrameX.Foundation.Hash;
using Standart.Hash.xxHash;

// 32 位
uint h32 = XxHashHelper.Hash32("hello");
uint h32Type = XxHashHelper.Hash32<MyClass>();

// 64 位
ulong h64 = XxHashHelper.Hash64("hello");

// 128 位(返回 uint128,含 high64 / low64)
uint128 h128 = XxHashHelper.Hash128("hello");
bool zero = XxHashHelper.IsDefault(h128); // high64 与 low64 都为 0 时返回 true
```

> ⚠️ 注意命名:`Hash32(byte[])` 返回 `ulong`、`Hash32(string)` 返回 `uint`,是 SDK 的真实签名,不是笔误。

Source: [XxHashHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/XxHashHelper.cs#L62-L100)

### 3. 在分片键/哈希表键中使用

把用户 ID、请求 ID、玩家 ID 等作为分片或哈希表键时,直接喂字符串即可,无需先转字节:

```csharp
// 根据用户 ID 选分片
int shardIndex = (int)(MurmurHash3Helper.Hash(userId) % shardCount);

// 64 位哈希放进哈希桶
ulong bucketKey = XxHashHelper.Hash64($"player:{playerId}");
```

## 常见变体

| 场景 | 推荐 API | 返回类型 |
|------|---------|----------|
| 小数据量、需要可重现种子 | `MurmurHash3Helper.Hash(str, seed)` | `uint` |
| 高吞吐、字节数组、跨语言兼容 | `XxHashHelper.Hash32/64/128(buffer)` | `uint`/`ulong`/`uint128` |
| 对类型元数据做稳定哈希(分发表) | `XxHashHelper.Hash64<T>()` | `ulong` |
| 部分长度哈希(流式/分片数据) | `XxHashHelper.Hash128(buffer, length)` | `uint128` |

## 常见错误

- **把 MurmurHash3 当加密哈希用**:MurmurHash3 是非加密哈希,无法抵御碰撞/预映像攻击,不要用于密码、Token、签名。
- **忽略种子一致性**:同一份数据用不同 `seed` 得到的哈希完全不同;若上下游需要一致,必须使用相同种子(默认 `27`)。
- **混淆 `Hash32(byte[])` 与 `Hash32(string)` 的返回类型**:前者返回 `ulong`、后者返回 `uint`,这是 SDK 的真实签名差异。
- **传入 `null`**:所有重载都会抛 `ArgumentNullException`,先用 `??` 兜底或提前校验。
- **将 MD5/SHA-1 用于安全场景**:`HashAlgorithmKind` 枚举里 `Md5`、`Sha1` 仅适用于兼容与非安全校验,密码场景应使用 `PasswordHashHelper`。

## 背景(可选)

MurmurHash3 在本 SDK 中以纯托管方式实现,核心是 4 字节块循环 + 尾部合并 + `Fmix32` 终结混合,典型应用是哈希表键、缓存分片。xxHash 通过 NuGet 包 `Standart.Hash.xxHash` 调用原生实现,32/64 位在多数硬件上吞吐显著高于 MD5/SHA 系列;两者都不是加密算法,任何"防篡改"用途都需要 SHA-2/3 或 HMAC。
