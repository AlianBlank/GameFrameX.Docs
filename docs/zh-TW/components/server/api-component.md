# 公開 API 與元件註冊快速參考

本頁彙整了 GameFrameX 框架對外公開的核心 API、元件介面與元件註冊慣例，可供撰寫業務模組時快速參考。

## 元件介面

| 名稱 | 型別/簽章 | 說明 |
|------|-----------|------|
| `IComponent` | `interface IComponent { IActor Actor { get; set; } }` | 所有自訂元件都必須實作的基礎元件介面，持有其所屬的 Actor。 |
| `IComponentAgent` | `interface IComponentAgent : IWorker` | 元件 Agent 介面，負責代理元件並提供非同步呼叫的進入點。 |

## 元件 Agent 公開成員

下表列出了 `IComponentAgent` 的關鍵成員，便於在實作或呼叫時直接查閱：

| 成員 | 簽章 | 說明 |
|------|------|------|
| `ActorId` | `long ActorId { get; }` | 目前 Agent 所綁定 Actor 的唯一識別碼。 |
| `Owner` | `IComponent Owner { get; }` | Agent 所屬的父元件實例。 |
| `OwnerType` | `ushort OwnerType { get; }` | 所屬元件的型別識別碼（ushort）。 |
| `SetOwner(IComponent)` | `void SetOwner(IComponent owner)` | 設定/變更元件的擁有者。 |
| `BeforeActivation` | `Task<bool> BeforeActivation()` | 啟用前回呼；回傳 `bool` 表示是否繼續。 |
| `Active` | `Task<bool> Active()` | 啟用元件 Agent。 |
| `AfterActivation` | `Task<bool> AfterActivation()` | 啟用後回呼。 |
| `BeforeInActivation` | `Task<bool> BeforeInActivation()` | 停用前回呼。 |
| `Inactive` | `Task Inactive()` | 停用並清理資源。 |
| `AfterInActivation` | `Task<bool> AfterInActivation()` | 停用後回呼。 |
| `GetComponentAgent(Type, bool)` | `Task<IComponentAgent> GetComponentAgent(Type agentType, bool isNew = true)` | 依型別取得或建立子 Agent。 |
| `GetComponentAgent<T>(bool)` | `Task<T> GetComponentAgent<T>(bool isNew = true) where T : IComponentAgent` | 泛型版本。 |

## 元件型別與生命週期慣例

元件的啟用流程按以下順序串接；業務程式碼可在覆寫鉤子方法時按需填入邏輯：

1. `BeforeActivation` —— 前置處理；回傳 `false` 會中止啟用。
2. `Active` —— 實際執行初始化。
3. `AfterActivation` —— 初始化收尾。

停用則依相反方向進行：

1. `BeforeInActivation` —— 狀態儲存/資源釋放。
2. `Inactive` —— 執行停用。
3. `AfterInActivation` —— 清理確認。

來源：[IComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Abstractions/Agent/IComponentAgent.cs#L70-L121)
