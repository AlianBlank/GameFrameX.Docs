# async/await로 초 수와 프레임 수 대기하기

`TimerComponent`는 직접 `await`할 수 있는 세 가지 대기 메서드를 노출합니다: `WaitForSecondsAsync`(초 수 대기), `WaitForNextFrameAsync`(다음 프레임 대기), `WaitForFramesAsync`(지정된 프레임 수 대기). 이들은 모두 타이머 관리자를 기반으로 구현되어 있으며, 대기와 연속(continuation)은 모두 Unity 메인 스레드에서 완료되므로, 코루틴 외부에서도 `async` 메서드로 선형 흐름을 작성할 수 있습니다.

## 사전 조건

- 씬/프로젝트에 `TimerComponent`가 이미 연결되어 있어야 합니다(타이머 관리자는 컴포넌트와 함께 초기화됨).
- 호출자가 `async` 메서드여야 합니다(`async void`는 `Start`와 같은 Unity 이벤트 함수에만 사용을 권장).

## API 빠른 참조

| 메서드 | 시그니처 | 동작 |
|------|------|------|
| 초 수 대기 | `Task WaitForSecondsAsync(float seconds, CancellationToken cancellationToken = default)` | `seconds`초 후 태스크 완료 |
| 다음 프레임 대기 | `Task WaitForNextFrameAsync(CancellationToken cancellationToken = default)` | 다음 프레임 업데이트 후 태스크 완료 |
| 프레임 수 대기 | `Task WaitForFramesAsync(int frameCount, CancellationToken cancellationToken = default)` | `frameCount`프레임 경과 후 완료; `frameCount <= 0`이면 즉시 완료(`Task.CompletedTask` 반환) |

`TimerComponent`의 동일한 이름의 인스턴스 메서드는 내부의 `ITimerManager`로 직접 전달됩니다([TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L245) 참조). 또한 `TimerAsyncExtensions`는 확장 메서드 형태로 임의의 `ITimerManager`에 동일한 세 가지 기능을 제공합니다:

```csharp
public static Task WaitForSecondsAsync(this ITimerManager timer, float seconds, CancellationToken cancellationToken = default)
public static Task WaitForNextFrameAsync(this ITimerManager timer, CancellationToken cancellationToken = default)
public static Task WaitForFramesAsync(this ITimerManager timer, int frameCount, CancellationToken cancellationToken = default)
```

출처: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L20-L72)

## 작업 단계

1. 스크립트에 네임스페이스를 참조합니다(프로젝트의 실제 참조 방식에 따라 조정):

```csharp
using System.Threading;
using System.Threading.Tasks;
```

2. `TimerComponent` 인스턴스를 가져와서(아래 예제에서는 필드 `timerComponent`가 프로젝트의 컴포넌트 참조를 지칭), `await`로 초를 대기합니다:

```csharp
public async void Start()
{
    // 2초 대기(TimerComponent가 내부 timerManager로 전달)
    await timerComponent.WaitForSecondsAsync(2f);
    UnityEngine.Debug.Log("2 秒后执行到这里");
}
```

3. 프레임 수를 대기하거나, 한 프레임만 대기합니다:

```csharp
// 60프레임 대기 후 계속
await timerComponent.WaitForFramesAsync(60);

// 다음 프레임만 대기
await timerComponent.WaitForNextFrameAsync();
```

4. `ITimerManager` 참조를 가지고 있다면 확장 메서드를 직접 호출할 수도 있습니다:

```csharp
await timerManager.WaitForSecondsAsync(1.5f);
```

## 일반적인 변형

- **취소 토큰을 사용한 대기**(객체 파괴, 게임플레이 취소 시 조기 종료):

```csharp
var cts = new CancellationTokenSource();
await timerComponent.WaitForSecondsAsync(5f, cts.Token);
```

취소 후 해당 태스크를 다시 `await`하면 취소 상태로 완료됩니다; 호출 전에 토큰이 이미 취소된 경우, 메서드는 `Task.FromCanceled(cancellationToken)`를 즉시 반환하며 어떤 타이머도 등록하지 않습니다:

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return Task.FromCanceled(cancellationToken);
}
```

출처: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L22-L28)

- **여러 대기의 순차 연결**: `await`는 본질적으로 선형이므로 순서대로 작성하면 되며, 콜백 중첩이 필요 없습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| `WaitForFramesAsync(0)` 또는 음수 전달 시 대기하지 않음 | `frameCount <= 0`이면 `Task.CompletedTask`를 즉시 반환하며, 이는 문서화된 동작임 | 최소한 `1`을 전달할 것; "즉시 양보"가 필요하면 `WaitForNextFrameAsync()` 사용 |
| 토큰이 이미 취소되었는데도 대기 흐름에 진입함 | 의도된 설계임: 이미 취소된 경우 즉시 `Task.FromCanceled`를 반환하고 타이머를 등록하지 않음 | 토큰 수명 주기를 점검하고 필요 시 새 토큰으로 교체 |
| 연속(continuation)에서 Unity 객체 접근 시 메인 스레드 외 예외 발생 | 모든 대기와 연속은 Unity 메인 스레드에서 완료됨(클래스 주석에 명확히 선언됨) | 대기 태스크에 `ConfigureAwait(false)` 등 컨텍스트를 변경하는 방식을 호출하지 말 것 |

## 배경

세 메서드는 모두 `TaskCompletionSource<bool>`로 한 번의 타이머 콜백을 래핑합니다: `WaitForSecondsAsync`는 `timer.AddOnce(seconds, ...)`를 사용하며, 한 번 트리거된 후 자동으로 제거됩니다; `WaitForNextFrameAsync`는 `AddOnce(0, ...)`를 사용하며, `interval=0`은 매 프레임, `repeat=1`은 한 번만 실행을 의미합니다; `WaitForFramesAsync`는 `timer.Add(0, frameCount, ...)`를 사용하며, 매 프레임 실행되어 총 `frameCount`회 후 제거됩니다. 취소는 `cancellationToken.Register`를 통해 태스크를 취소 상태로 만들고, 콜백이 트리거되면 등록을 해제합니다. 구현은 [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L27-L94)를 참조하세요.
