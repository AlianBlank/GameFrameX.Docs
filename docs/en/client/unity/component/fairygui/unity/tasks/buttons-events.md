# Buttons and Event Handling

This page explains how to register click, touch, and other events for FairyGUI components (focusing on `GButton`), as well as how to use button features such as selected state toggling, click sound effects, and linked popup components. Events for all components are exposed as `EventListener` instances and managed uniformly through `Add` / `Remove` / `Set` / `Reset`.

## Prerequisites

- The project has this FairyGUI Unity package installed (the button class is located at `Runtime/UI/GButton.cs`, and the event base class is located at `Runtime/Event/EventListener.cs`).
- You can already load components and obtain a `GButton` reference (e.g., retrieved from a panel/component).

## Steps

1. Get a `GButton` instance and register a click callback with `onClick.Add`. `onClick` is defined on all `GObject`s, so any component can listen for it:

```csharp
public EventListener onClick
{
    get { return _onClick ?? (_onClick = new EventListener(this, EventName.onClick)); }
}

public EventListener onRightClick
{
    get { return _onRightClick ?? (_onRightClick = new EventListener(this, EventName.onRightClick)); }
}
```

Source: [GObject.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GObject.cs#L189-L199)

A typical registration pattern (use the `EventCallback0` overload when the callback takes no parameters):

```csharp
button.onClick.Add(() => Debug.Log("clicked"));
```

2. When you need the event context (`EventContext`), use the `EventCallback1` overload. `EventListener` provides two `Add` overloads:

```csharp
public void Add(EventCallback1 callback)
{
    _bridge.Add(callback);
}

public void Remove(EventCallback1 callback)
{
    _bridge.Remove(callback);
}

public void Add(EventCallback0 callback)
{
    _bridge.Add(callback);
}
```

Source: [EventListener.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Event/EventListener.cs#L51-L75)

3. Remove listeners when a panel is destroyed or a callback becomes invalid. Three common approaches:

```csharp
public void Reset(EventCallback0 callback)
{
    _bridge.Remove(callback);
    _bridge.Add(callback);
}

public void Set(EventCallback1 callback)
{
    _bridge.Clear();
    if (callback != null)
        _bridge.Add(callback);
}
```

Source: [EventListener.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Event/EventListener.cs#L89-L118)

- `Remove(callback)`: Precisely removes a single callback (you must pass the same delegate reference—do not use a newly written lambda).
- `Reset(callback)`: Removes and then re-adds, suitable for situations where duplicate registration may occur.
- `Set(callback)`: Clears all callbacks on the event and keeps only the one passed in, suitable for "exclusive callback" scenarios.

4. Set the button title and icon (the selected state has its own title/icon; once configured in the editor, the button switches automatically):

```csharp
public string title
{
    get { return _title; }
    set
    {
        _title = value;
        if (_titleObject != null)
            _titleObject.text = (_selected && _selectedTitle != null) ? _selectedTitle : _title;
        UpdateGear(6);
    }
}
```

Source: [GButton.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GButton.cs#L101-L114)

`icon` / `selectedIcon` / `selectedTitle` work the same way; see [GButton.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GButton.cs#L82-L158) respectively.

## Common Variants

### Single-select / Multi-select (Radio / Check)

`GButton` provides `mode` (`ButtonMode`) to distinguish normal, radio, and check buttons. `onChanged` fires when the selected state changes:

```csharp
radio.onChanged.Add(() => Debug.Log("selected = " + radio.selected));
```

If you don't want the selected state to toggle automatically when the player clicks (and prefer to control it via code), set `changeStateOnClick` to `false`; the default is `true`:

```csharp
public bool changeStateOnClick;
```

## Common Mistakes

- **Passed a newly written lambda to `Remove`, so the listener was not removed**: `Remove` matches by delegate reference. When registering, save the callback as a field/method reference and pass that same reference when removing; alternatively, use `Set` to replace it in one step.
- **Duplicate registration causes the callback to run multiple times**: Adding the same lambda multiple times registers multiple copies. Use `Reset` instead of `Add`, or call `Remove` first before registering.
- **Radio/check buttons "won't toggle" or their state is uncontrollable**: Check `changeStateOnClick` — the default `true` means clicking toggles automatically; once set to `false`, you must change `selected` via code.
- **Sound conflict between global and per-button settings**: A button's `sound` and `soundVolumeScale` take their default values from `UIConfig.buttonSound` and `UIConfig.buttonSoundVolumeScale` at construction time; to override for a single button, just modify its own fields.

## Background

Each `onXxx` property on `GObject` is a lazily created `EventListener` that internally holds the `EventBridge` returned by `EventDispatcher.GetEventBridge(type)`; `Add/Remove` are actually forwarded to the bridge ([EventListener.cs L15-L19](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Event/EventListener.cs#L15-L19)). When `GButton` enters the stage, it bridges `displayObject.onClick` to its internal `__click` handler, which then calls `onClick.Call()` to fire the component-level click event ([GButton.cs L337](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GButton.cs#L337), [GButton.cs L495-L497](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GButton.cs#L495-L497)).
