# 如何使用 AssetBundle 与 YooAsset 资源加载

本页面指导你在 GameFrameX.Unity 工程中通过 YooAsset 完成资源打包、配置和加载:把待打包资源放进 `Assets/Bundles` 对应的分组目录,使用 `YooAssetSettings` 控制清单文件名与默认输出文件夹,然后运行构建生成 `PackageManifest` 清单与 `yoo` 资源包,运行时按地址加载即可。

## 前置条件

- Unity 工程已通过 Package Manager 安装 YooAsset(由 `YooAssetSettings.asset` 引用脚本 GUID `9753568a72b014c7092614d3be8b353f`)。
- 工程根目录存在 `Assets/AssetBundleSetting/` 文件夹,包含两个核心配置:
  - [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset)
  - [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml)
- 资源按分组放到 `Assets/Bundles/{GroupName}` 下(AOTCode / Code / UI / Config / Image / Sprites)。

## 操作步骤

### 1. 准备资源目录

YooAsset 的收集器已固定为 `Assets/Bundles` 下的六个分组(AOTCode、Code、UI、Config、Image、Sprites)。把要打进 AssetBundle 的资源按用途放入对应文件夹,例如:

- `Assets/Bundles/UI` —— UI Prefab、图集、字体
- `Assets/Bundles/Config` —— 配置表、二进制资源
- `Assets/Bundles/Sprites` / `Assets/Bundles/Image` —— 美术贴图

收集规则见 [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L5-L22):

```xml
<Group GroupActiveRule="EnableGroup" GroupName="UI" GroupDesc="" AssetTags="">
  <Collector CollectPath="Assets/Bundles/UI" CollectGUID="4010ac95965b3164e83fa268b290dbf4"
            CollectType="MainAssetCollector" AddressRule="AddressByFileName"
            PackRule="PackDirectory" FilterRule="CollectAll" UserData="" AssetTags="" />
</Group>
```

> 每条 `<Collector>` 表示「收集哪个目录 → 用什么规则生成地址 → 如何打包」。当前工程统一使用 `AddressByFileName`(以文件名作为加载地址)+ `PackDirectory`(按目录打成一个包)。

### 2. 确认 YooAsset 全局设置

打开 [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L12-L16) 校对两个字段:

| 字段 | 当前值 | 含义 |
|------|--------|------|
| `ManifestFileName` | `PackageManifest` | 运行时加载清单的文件名 |
| `DefaultYooFolderName` | `yoo` | 构建产物的默认输出目录名 |

如果你的项目用了不同名字的清单或输出目录,需要在此修改并保证运行时与构建端一致。

### 3. 触发 YooAsset 构建

YooAsset 会在 Unity 菜单 `YooAsset → Build` 下提供构建入口(由 `YooAssetSettings.asset` 的 `m_Script` 引用的编辑器脚本提供)。构建产物输出到 `DefaultYooFolderName` 配置的 `yoo` 文件夹下,主要包含:

- `PackageManifest`(清单文件,记录所有包名、版本、资源地址)
- 各分组的 AssetBundle 文件(命名遵循 `UniqueBundleName="True"`,见 [AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3))

### 4. 运行时按地址加载资源

构建完成后,把 `yoo` 目录下的清单与 AssetBundle 部署到 `StreamingAssets`(或远端 CDN)。启动时由 YooAsset 初始化系统读取 `PackageManifest`,业务侧按 `AddressByFileName` 生成的地址加载即可:

```csharp
// 伪代码:与 YooAsset 公共 API 对齐,具体类型以你安装的 YooAsset 版本为准
var package = YooAssets.GetPackage("DefaultPackage");
var op = package.LoadAssetAsync<GameObject>("Assets/Bundles/UI/LoginPanel.prefab");
yield return op;
var go = op.InstantiateObject;
```

## 常见变体

- **新增资源分组**:在 [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml) 的 `<Package>` 内追加一条 `<Group>` 与对应的 `<Collector CollectPath="Assets/Bundles/你的分组">`,重启编辑器后 YooAsset 会自动识别。
- **修改打包粒度**:把 `<Collector>` 的 `PackRule` 从 `PackDirectory` 改为 `PackSeparately`(每个资源独立包)或 `PackTogether`(整组打成一个包)。
- **切换地址规则**:把 `AddressRule` 改为 `AddressByGroupAndFileName` 或自定义规则,运行时按新地址加载即可。

## 常见错误

- **运行时找不到资源**:先确认 `ManifestFileName` 与 `DefaultYooFolderName` 在构建端和运行时一致([YooAssetSettings.asset L15-L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L15-L16));再确认资源确实放在 `Assets/Bundles/<GroupName>` 下,且分组 `GroupActiveRule="EnableGroup"`。
- **重复打包或包名冲突**:保证 `<Common>` 节点的 `UniqueBundleName="True"`(见 [AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3)),否则同名目录会互相覆盖。
- **修改配置后没生效**:YooAsset 的收集配置只在编辑器重启或重新打开 YooAsset 窗口后才会被重新解析;改完 XML 后切回 Editor 主窗口再构建。

## 背景(可选)

工程采用 YooAsset 作为统一的资源管理方案:`AssetBundleCollectorConfig.xml` 描述「哪些资源 → 走哪个地址 → 打哪个包」,`YooAssetSettings.asset` 描述「清单怎么命名 → 产物放哪里」。两端解耦后,既能在不重写代码的前提下调整打包粒度,也能在不改资源结构的情况下切换运行模式(本地 / CDN)。
