# Get the Launcher Scene Running in 5 Minutes

Complete the full workflow of the Launcher scene—from cloning the repository to reaching the login screen—within 5 minutes, verifying that the framework can start up, load the UI, and read configuration tables properly in your environment.

## Prerequisites

- Unity 2019.4 or higher (LTS recommended)
- Git installed
- GameFrameX scoped registry configured in `Packages/manifest.json`; see [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/README.zh-CN.md#L38-L57) for details
- When opening the project for the first time, Unity needs to automatically pull dependency packages, so keep your network connection stable

## Steps

### 1. Clone and Open the Project

```bash
git clone https://github.com/GameFrameX/GameFrameX.Unity.git
```

Open the cloned project directory with Unity Hub and wait for the initial import and dependency resolution to complete.

### 2. Open the Launcher Scene

The Launcher scene is already provided in the project. Search for `Launcher` in the `Project` window and double-click to open the scene. This is the first scene entered when the game starts.

### 3. Verify the Hotfix Entry Point

The hotfix entry point is fixed as `Hotfix.HotfixLauncher.Main()`, which the framework invokes via reflection during the startup flow:

```csharp
var entryTypeName = options == null || string.IsNullOrEmpty(options.HotfixEntryTypeName)
    ? "Hotfix.HotfixLauncher"
    : options.HotfixEntryTypeName;
```

Source: [HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L64-L68)

### 4. Verify the Main Initialization Logic

`HotfixLauncher.Main()` performs three tasks in sequence: protocol registration, configuration loading, and loading the login UI:

```csharp
public static void Main()
{
    Log.Info("Hello World HybridCLR");
    ProtoMessageIdHandler.Init(HotfixProtoHandler.CurrentAssembly);
    LoadConfig();
    LoadUI();
}
```

Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L28-L34)

### 5. Run and Observe the Logs

Click Unity's `Play` button to run the Launcher scene. You should see the following in the Console in order:

1. `Hello World HybridCLR`
2. The log indicating configuration table loading is complete
3. The log indicating the login UI opened successfully

If you can see the login screen in the UI, the scene is considered to be running successfully.

## Common Variants

- **Multiple UI options**: The project supports both FairyGUI and UGUI. `LoadUI` distinguishes between them using the macro `ENABLE_UI_FAIRYGUI`:

  ```csharp
  #if ENABLE_UI_FAIRYGUI
      GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommon));
      ...
  #endif
      await GameApp.UI.OpenAsync<UILogin>();
  ```

  Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L46)

  When FairyGUI is enabled, the common UI package is preloaded; in UGUI mode, the login window is opened directly.

- **Binary configuration tables**: When the macro `ENABLE_BINARY_CONFIG` is enabled, `ConfigBufferLoader` is used for loading; otherwise, the JSON path `ConfigLoader` is used.

## Common Issues

| Symptom | Cause | Fix |
|---------|-------|-----|
| Console reports `Hotfix.HotfixLauncher` not found | Hotfix assembly not generated or not compiled into the build | Trigger HybridCLR to generate supplementary metadata, or confirm that `HotfixLauncher.cs` exists under `Assets/Hotfix/` |
| `OpenAsync<UILogin>` fails, UI not displayed | UI package not registered, or FairyGUI/UGUI macro not enabled | Check the macro `ENABLE_UI_FAIRYGUI`, or confirm that the `UILauncher` component is attached in the Launcher scene |
| Configuration table loading hangs | The `ENABLE_BINARY_CONFIG` macro doesn't match the actual table format | Switch to the JSON or binary loader based on the table source |
| Black screen after startup, no Launcher UI | Launcher scene not set as the first item in Build Settings | Go to `File → Build Settings` and drag the Launcher scene to position 0 |

## Background (Optional)

The Launcher scene is the framework's runtime entry point. `ApplicationHotfixLauncher` adapts `HotfixHelper` to the `IHotfixLauncher` interface to uniformly drive the hotfix flow; the UI layer displays the progress bar, status text, and forced-update dialog through the `LauncherUIHandler` and `UILauncher` components.
