# 主機伺服器位址設定方式

若在 `GlobalConfigComponent` 中設定 `HostServerUrl`,客戶端可在啟動時取得後端根位址，用於組合版本檢查、資源更新等介面。

## 前置條件

- `GameFrameX.GlobalConfig` 元件已掛載於遊戲入口場景，且元件類型為 `GlobalConfigComponent`。
- 準備一個可用的 HTTP/HTTPS 主機位址(以 `http://` 或 `https://` 開頭，結尾無需加上 `/`)。

## 操作步驟

1. 在場景中尋找並選取掛載了 `GlobalConfigComponent` 的 GameObject。您可以在 Inspector 中看到「主机服务地址」欄位。此欄位對應至序列化欄位 `m_hostServerUrl`。

   ```csharp
   // Runtime/GlobalConfig/GlobalConfigComponent.cs:L98-L112
   /// <summary>
   /// 主机服务地址
   /// </summary>
   [SerializeField] private string m_hostServerUrl = string.Empty;

   /// <summary>
   /// 主机服务地址
   /// </summary>
   public string HostServerUrl
   {
       get { return m_hostServerUrl; }
       set { m_hostServerUrl = value; }
   }
   ```

2. 在 Inspector 的「主机服务地址」輸入框中輸入完整網址(例如:`https://api.example.com`)。

3. 若需要在執行階段(例如：資料讀取後，或由熱更新中心下發後)修改位址，只需將值指派給 `GlobalConfigComponent` 實例的屬性即可：

   ```csharp
   var globalConfig = GameEntry.GetComponent<GlobalConfigComponent>();
   globalConfig.HostServerUrl = "https://api.example.com";
   ```

4. 驗證：啟動遊戲後，您可以在 Inspector 的「原始数据」(對應 `OriginalData`)或主控台日誌中確認該欄位已生效。之後所有依賴此位址組合的下游介面(版本檢查、資源版本檢查)都會自動使用新值。

## 常見變化

- 與 `CheckAppVersionUrl` / `CheckResourceVersionUrl` 搭配使用：當「主机服务地址」僅作為根網域，而版本檢查使用獨立的 CDN 時，請分別在對應欄位輸入，以避免被主機位址覆蓋。
- 透過 `OriginalData` 批次下發：伺服器回傳的完整 JSON 區段會被反序列化並重新寫入 `m_originalData`,業務邏輯可讀取此原始字串，並將其分發至各子系統。

## 常見錯誤

| 現象 | 原因 | 解決方法 |
|------|------|------|
| 設定後介面仍使用舊位址 | 場景已啟用，但欄位指派發生在下游已快取舊值之後 | 在 `GameEntry` 啟動流程的最早期階段，或下游讀取之前完成指派 |
| 位址結尾多出 `/`,導致請求路徑變成 `//api/...` | 習慣性地在網域後加上斜線 | 移除結尾的 `/`,並視需要由呼叫端自行組合 |
| Inspector 中欄位顯示為灰色，無法編輯 | 目前處於 Play 模式，為避免執行階段變更遺失，Inspector 中的編輯功能已停用 | 結束 Play 模式後再修改，或改用屬性指派 |
