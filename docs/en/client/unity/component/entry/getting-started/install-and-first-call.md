# Quick Start: Installation and Your First Component Call

After completing the steps on this page, you will be able to call any registered GameFrameX component with a single line through the `GameApp` static facade in your Unity project, and complete an event subscription and trigger.

## Prerequisites

- Unity 2019.4 or higher (the minimum version indicated in the README).
- The macro switch for the corresponding component is enabled on the target platform (for example, the event component requires `ENABLE_GAME_FRAME_X_EVENT`).
- A working GameFrameX framework runtime (`com.gameframex.unity.runtime`) and at least one feature component package, such as `com.gameframex.unity.event`, are already in place.

## Steps

### 1. Install the Entry Component

Open your Unity project's `Packages/manifest.json` and add the entry component under the `dependencies` node:

```json
{
  "dependencies": {
    "com.gameframex.unity.entry": "1.2.1"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L46-L62)

Alternatively, you can add it via Git URL in Unity's `Package Manager`: `https://github.com/gameframex/com.gameframex.unity.entry.git` (README.zh-CN.md#L66-L73).

### 2. Verify `GameApp` Is Available

After installation, Unity will automatically compile `Runtime/GameApp.cs` and its partial classes into the project. `GameApp` is a `public static partial class` where each property lazily loads the target component on demand:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }

    private static BaseComponent _base;
}
```

Source: [GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L52)

### 3. Call Your First Component (Using the Event Component as an Example)

In any executable code, retrieve the component directly via `GameApp.Event` and perform a subscription:

```csharp
// Standard approach: via GameEntry (no dependency on com.gameframex.unity.entry)
var component = GameEntry.GetComponent<EventComponent>();

// Shortcut: via GameApp (requires com.gameframex.unity.entry)
GameApp.Event.Subscribe(eventId, handler);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L76-L82)

The event component's partial class implementation confirms this mapping:

```csharp
#if ENABLE_GAME_FRAME_X_EVENT
public static partial class GameApp
{
    public static EventComponent Event
    {
        get
        {
            if (_event == null)
            {
                _event = GameEntry.GetComponent<EventComponent>();
            }
            return _event;
        }
    }

    private static EventComponent _event;
}
#endif
```

Source: [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs#L32-L55)

## Common Variants

The property naming of `GameApp` follows a consistent rule: property name = component class name with the `Component` suffix removed. The two exceptions are `FUI` → `FairyGUIComponent` and `GUI` → `UGUIComponent` (README.zh-CN.md#L38).

| GameApp Property | Equivalent Call |
|---|---|
| `GameApp.Event` | `GameEntry.GetComponent<EventComponent>()` |
| `GameApp.UI` | `GameEntry.GetComponent<UIComponent>()` |
| `GameApp.Asset` | `GameEntry.GetComponent<AssetComponent>()` |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L30-L37)

## Common Errors

- **Calling `GameApp.XXX` without importing the corresponding feature package**: `GameApp.XXX` is actually a partial class; files like `GameApp.Event.cs` are only compiled when the corresponding component package exists and the macro switch is enabled. For example, `GameApp.Event` does not exist if `com.gameframex.unity.event` is not installed. Install the package and enable the macro switch (`ENABLE_GAME_FRAME_X_EVENT`) before compiling again.
- **`GameApp.FairyGUI` and `GameApp.ShareSDK` have been removed as of 1.3.0**: After upgrading to 1.3.0, these two shortcut accesses are no longer available; use the corresponding feature package APIs instead (see [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L8-L14)).
- **Only wanting to use GameEntry without importing the entry component**: `GameEntry.GetComponent<T>()` comes from `com.gameframex.unity.runtime` and is independent of this package; you only need to install this package when you want the `GameApp.*` syntactic sugar (README.zh-CN.md#L77-L82).

## Background (Optional)

`GameApp` is merely a static facade layer that wraps `GameEntry.GetComponent<T>()` into properties with lazy-loaded caching; the actual component registration and lifecycle are managed by the `GameFrameX` runtime. The naming follows the `Component` suffix stripping rule, which makes it easy to remember and avoids writing out the generic call by hand every time.
