# How to Use Assets, Config, Localization, and Global Config

GameFrameX consolidates four categories of data requirements—"asset loading, hot updates, localized strings, and business config tables"—into four independent subsystems, uniformly accessed via the `GameApp.{Subsystem}` static properties. This page teaches you how to obtain these four components in your business code and perform the most common operations: reading config tables / reading configs / retrieving localized text / loading assets.

## Prerequisites

- The `com.gameframex.unity.entry` package is installed, and the corresponding runtime sub-packages are installed as needed: `GameFrameX.Asset.Runtime`, `GameFrameX.Config.Runtime`, `GameFrameX.GlobalConfig.Runtime`, `GameFrameX.Localization.Runtime`.
- The corresponding symbols have been enabled in Unity's **Project Settings → Player → Scripting Define Symbols** (each component is controlled independently, see the table below).

| Subsystem | Enabling Symbol | Namespace |
|--------|--------|----------|
| Asset | `ENABLE_GAME_FRAME_X_ASSET` | `GameFrameX.Asset.Runtime` |
| Config | `ENABLE_GAME_FRAME_X_CONFIG` | `GameFrameX.Config.Runtime` |
| Global Config | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` | `GameFrameX.GlobalConfig.Runtime` |
| Localization | `ENABLE_GAME_FRAME_X_LOCALIZATION` | `GameFrameX.Localization.Runtime` |

When a symbol is not enabled, the entire corresponding `GameApp.{Name}` property definition is excluded from compilation, and business code will directly throw errors such as "`Asset` not found".

## Steps

### 1. Get the Subsystem Accessor

The entry structure of the four subsystems is identical: directly access the static property `GameApp.{Subsystem}` in any business class; on first access, the corresponding component is lazily loaded from `GameEntry`.

```csharp
// Asset
var asset = GameApp.Asset;
// Config
var config = GameApp.Config;
// Global Config
var globalConfig = GameApp.GlobalConfig;
// Localization
var localization = GameApp.Localization;
```

### 2. Load Assets with the Asset Component

`AssetComponent` is provided by the `GameFrameX.Asset.Runtime` package and obtained via `GameApp.Asset`. Before calling it, make sure the component has already been registered in the `GameEntry` startup process.

```csharp
using GameFrameX.Asset.Runtime;

var asset = GameApp.Asset;
// The actual available API depends on the version of the Asset sub-package you installed.
// This only shows the entry call pattern; see the sub-package documentation for specific signatures.
asset.LoadAssetAsync<GameObject>("Assets/Prefabs/Player.prefab", (prefab) =>
{
    Instantiate(prefab);
});
```

## Common Variants

- **Asynchronous asset loading**: Call the `GameApp.Asset.LoadAssetAsync<T>` family of methods in callbacks that need to wait for loading to complete; do not block synchronously on the main thread.
- **Language switching**: After switching languages, UI text usually needs to be refreshed. The specific refresh method is determined by the Localization sub-package, but the entry always goes through `GameApp.Localization`.
- **Config table hot reload**: If you use the Config sub-package, you usually need to use the `Reload` interface provided by the sub-package instead of directly manipulating the underlying files.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Compilation error: `GameApp` does not contain definitions such as `Asset` / `Config` | The corresponding symbol is not enabled in Player Settings, so the corresponding partial class is excluded from compilation | Add the `ENABLE_GAME_FRAME_X_*` symbols according to the "Prerequisites" table |
| `GameApp.Asset` is `null` at runtime | `GameEntry` has not registered `AssetComponent` | Add the corresponding component during the `RegisterComponent` phase of the startup process |
| Business code cannot read localization / config fields | Wrong subsystem entry used | Note the distinction: `GameApp.Config` reads business config tables, `GameApp.GlobalConfig` reads global parameters, `GameApp.Localization` reads localized text |

## Background (Optional)

All four entry properties are lazily loaded properties of `static partial class GameApp`. On first access, they retrieve the registered component instance via `GameEntry.GetComponent<T>()`; subsequent accesses directly return the cached field. Each file wraps its entire definition with the corresponding `ENABLE_GAME_FRAME_X_*` symbol, so business projects can trim subsystems as needed without compiling the entire framework into the package.
