# Protobuf POST リクエストを送信してレスポンスを受信する方法

Unity シーンの `WebProtoBuffComponent` において `await WebComponent.Post<TResponse>(url, request)` を呼び出すだけで、`MessageObject` リクエストを protobuf バイナリにシリアライズして HTTP POST として送信し、サーバーから返されたバイト列を型付きの `TResponse`（`MessageObject + IResponseMessage`）へデシリアライズできます。

## 前提条件

- Package Manager で `com.gameframex.unity.web.protobuff` をインストール済みであること（scoped registry `https://gameframex.upm.alianblank.uk`、スコープは `com.gameframex`）。`dependencies` に以下を追加します：

```json
{
  "dependencies": {
    "com.gameframex.unity.web.protobuff": "1.1.3"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L97-L103)

- プロジェクトで `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` コンパイルマクロが定義済みであること。未定義の場合、`WebProtoBuffComponent.Post<T>` はコンパイル対象になりません：

```csharp
#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
        public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
        {
            return m_WebProtoBuffManager.Post<T>(url, message);
        }
#endif
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

- リクエストメッセージは `GameFrameX.Network.Runtime.MessageObject` を継承し、レスポンスメッセージは `MessageObject` を継承して `GameFrameX.Network.Runtime.IResponseMessage` を実装していること。
- Unity シーンに `WebProtoBuffComponent` がアタッチされていること（Inspector メニュー `GameFrameX/Web ProtoBuff`）。このコンポーネントは同時に `GameFrameXWebProtoBuffCroppingHelper` が存在することを要求します。

## 操作手順

1. シーンに `WebProtoBuffComponent` を追加し、必要に応じて Inspector でタイムアウト時間（`Timeout`、単位：秒、デフォルト 5）を設定します：

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;

public float Timeout
{
    get { return m_WebProtoBuffManager.Timeout; }
    set { m_WebProtoBuffManager.Timeout = m_Timeout = value; }
}
```

2. ビジネスコード内で `using GameFrameX.Web.ProtoBuff.Runtime;` を宣言します。
3. リクエストメッセージオブジェクトを構築し、`await` で `Post<T>` を呼び出します：

```csharp
using GameFrameX.Web.ProtoBuff.Runtime;

// リクエストを送信して結果を待機します
LoginResponse response = await WebComponent.Post<LoginResponse>(url, request);
```

4. リクエストはキューに入った後、`WebProtoBuffManager` によって `Update` 内で `MaxConnectionPerServer` に従い 1 つずつディスパッチされます。`Content-Type` は `application/x-protobuf` に固定されています：


## よくあるバリエーション

- **非 WebGL プラットフォーム**：`HttpWebRequest` を使用し、タイムアウトはミリ秒（`(int)RequestTimeout.TotalMilliseconds`）で指定します。POST ボディは `request.ContentLength = postData.Length` を設定した後、リクエストストリームへ書き込みます：

```csharp
HttpWebRequest request = WebRequest.CreateHttp(webData.URL);
request.Method = webData.IsGet ? WebRequestMethods.Http.Get : WebRequestMethods.Http.Post;
request.Timeout = (int)RequestTimeout.TotalMilliseconds; // リクエストのタイムアウト時間を設定
request.ContentType = ProtoBufContentType;
byte[] postData = webData.SendData;
request.ContentLength = postData.Length;
using (Stream requestStream = request.GetRequestStream())
{
    await requestStream.WriteAsync(postData, 0, postData.Length);
}
```

Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L120-L131)

- **WebGL プラットフォーム**：代わりに `UnityEngine.Networking.UnityWebRequest` を使用し、POST は `UploadHandlerRaw` でバイナリボディを送り、`completed` コールバック内で Task を完了します：

```csharp
var asyncOperation = unityWebRequest.SendWebRequest();
asyncOperation.completed += (asyncOperation2) =>
{
    try
    {
        m_SendingProtoBufList.Remove(webData);
        if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)
        {
            webData.Task.TrySetException(new Exception(unityWebRequest.error));
            return;
        }

        webData.Task.SetResult(new WebBufferResult(webData.UserData, unityWebRequest.downloadHandler.data));
    }
    finally
    {
        unityWebRequest.Dispose();
        ReferencePool.Release(webData);
    }
};
```

Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L99-L118)

## よくあるエラー

- **`Post<T>` がコンパイルエラーになる / 存在しない**：`ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` マクロが未定義で、メソッド全体が `#if` の内側にあります。
- **`Fatal: Web manager is invalid.`**（`Log.Fatal("Web manager is invalid.")`）：`GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` が空を返しています。GameFramework の初期化順序を確認してください。
- **リクエストがなかなか送信されない**：`WebProtoBuffManager.UpdateProtoBuf` は `m_SendingProtoBufList.Count < MaxConnectionPerServer` のときにのみ新規リクエストをデキューするため、同時接続が上限に達すると以降のリクエストは待機キューに滞留します。
- **サーバーが 415 を返す / パースに失敗する**：クライアントの `Content-Type` は `application/x-protobuf` に固定されており、サーバー側は JSON やフォームではなく protobuf バイナリとして処理する必要があります。
- **レスポンスのデシリアライズで例外が発生**：`T` は `MessageObject` と `IResponseMessage` のジェネリック制約を同時に満たし、かつサーバーが実際に返す proto メッセージの構造と一致している必要があります。

## 背景

`WebProtoBuffComponent` は `IWebProtoBuffManager` の薄いラッパーにすぎません。`WebProtoBuffManager`（partial クラス）は `m_WaitingProtoBufQueue`（容量 256）と `m_SendingProtoBufList`（容量 16）を管理し、毎フレームの `UpdateProtoBuf` でリクエストをデキューし、`MessageObject` をバイト列にシリアライズして、プラットフォーム固有の HTTP クライアントで送信します（WebGL は `UnityWebRequest`、その他のプラットフォームは `HttpWebRequest`）。レスポンスのバイト配列は最終的に `WebBufferResult` にラップされ、型付きの `IResponseMessage` としてデシリアライズされます。パッケージ全体の説明については、リポジトリの [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md) を参照してください。
