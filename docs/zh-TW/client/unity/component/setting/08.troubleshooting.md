# 常見問題

本文件彙總了使用 GameFrameX Setting 配置組件時可能遇到的常見問題、錯誤資訊及其解決方案。

## 概述

GameFrameX Setting 配置組件是遊戲框架的核心組件，負責管理遊戲的配置資訊。在使用過程中，開發者可能遇到初始化失敗、資料無法儲存、平臺相容性等問題。本文件提供詳細的問題診斷和解決方案，幫助開發者快速定位和解決問題。

## 初始化問題

### 問題 1：Setting manager is invalid

**錯誤資訊：**
```
Log.Fatal("Setting manager is invalid.");
```

**原因分析：**
此錯誤表示 `SettingComponent` 在 `Awake()` 階段無法從 `GameFrameworkEntry` 獲取 `ISettingManager` 模組。這通常是因為 GameFramework 核心組件未正確初始化。

**解決方案：**

1. 確保場景中存在 GameFrameX 核心入口組件
2. 檢查 `GameFrameworkEntry` 是否已正確初始化
3. 確保 SettingComponent 掛載在正確的 GameObject 上

```csharp
// 正確的初始化順序
// 1. 先初始化 GameFrameworkEntry
GameFrameworkEntry.Initialize();

// 2. 然後 SettingComponent 會自動透過 Awake 獲取管理器
var settingComponent = gameObject.AddComponent<SettingComponent>();
```

### 問題 2：Can not create setting helper

**錯誤資訊：**
```
Log.Error("Can not create setting helper.");
```

**原因分析：**
此錯誤表示無法根據配置的型別名稱建立設定輔助器例項。可能原因：
- 配置的 Helper 型別名稱不正確
- 指定的 Helper 類不存在或未正確引用
- Helper 型別沒有無參建構函式

**解決方案：**

1. 檢查 `SettingComponent` Inspector 面板上的 `Setting Helper Type Name` 配置
2. 確保型別名稱完整且正確（包括名稱空間）

```csharp
// 預設配置
// Setting Helper Type Name: GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper
// 或
// Setting Helper Type Name: GameFrameX.Setting.Runtime.DefaultSettingHelper
```

3. 可用的 Helper 型別：
   - `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` - 基於 Unity PlayerPrefs
   - `GameFrameX.Setting.Runtime.DefaultSettingHelper` - 基於本地檔案儲存

### 問題 3：缺少必需的依賴組件

**錯誤資訊：**
Unity 執行時錯誤或組件無法正常工作

**原因分析：**
`SettingComponent` 使用了 `[RequireComponent(typeof(GameFrameXSettingCroppingHelper))]`，必須配合 `GameFrameXSettingCroppingHelper` 組件使用。

**解決方案：**

1. SettingComponent 會自動新增 GameFrameXSettingCroppingHelper 依賴組件
2. 如果出現依賴問題，手動新增 GameFrameXSettingCroppingHelper 到同一 GameObject

## 資料操作問題

### 問題 4：Load settings failure

**錯誤資訊：**
```
Log.Error("Load settings failure.");
```

**原因分析：**
載入設定失敗，可能原因：
- 配置檔案損壞
- 儲存介質不可用
- 檔案路徑不存在
- 序列化/反序列化錯誤

**解決方案：**

1. **對於 DefaultSettingHelper：**
```csharp
// 檢查檔案是否存在
var helper = settingComponent.GetComponent<DefaultSettingHelper>();
string filePath = helper.FilePath;
Debug.Log($"Settings file path: {filePath}");
```

2. **異常處理：**
```csharp
try
{
    settingComponent.Save();
}
catch (Exception ex)
{
    Debug.LogError($"Save failed: {ex.Message}");
}
```

3. **檢查檔案許可權：**
   - 確保 Application.persistentDataPath 可寫
   - 檢查磁碟空間是否充足

### 問題 5：設定值未正確儲存

**問題描述：**
呼叫 `Save()` 方法後，設定值在重新載入時丟失

**可能原因：**

1. **未呼叫 Save()**：設定值只在記憶體中修改，未持久化
2. **PlayerPrefs 未同步**：在某些平臺上 PlayerPrefs.Save() 需要手動呼叫
3. **WebGL 平臺限制**：小程式平臺有特殊的儲存機制

**解決方案：**

```csharp
// 1. 修改設定後必須呼叫 Save()
settingComponent.SetString("PlayerName", "NewName");
settingComponent.Save();  // 必須呼叫

// 2. 使用 DefaultSettingHelper 確保資料持久化
// 其會自動儲存到 Application.persistentDataPath/GameFrameworkSetting.dat
```

### 問題 6：GetAllSettingNames 返回 null 或不支援

**錯誤資訊：**
```
Log.Warning("GetAllSettingNames is not supported.");
```

**原因分析：**
`PlayerPrefsSettingHelper` 不支援獲取所有設定項名稱的功能，因為 Unity PlayerPrefs 本身不提供列舉所有鍵的 API。

> Source: [PlayerPrefsSettingHelper.cs#L96-L100](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L96-L100)

**解決方案：**

1. **使用 DefaultSettingHelper 替代**：該 Helper 支援完整的列舉功能

```csharp
// 在 SettingComponent Inspector 中將 Helper 型別改為：
// GameFrameX.Setting.Runtime.DefaultSettingHelper
```

2. **自行維護設定鍵列表**：如果必須使用 PlayerPrefs，需要自行記錄所有設定的鍵名

### 問題 7：Count 屬性返回 -1

**問題描述：**
呼叫 `settingComponent.Count` 返回 -1

**原因分析：**
`PlayerPrefsSettingHelper` 的 Count 屬性始終返回 -1，因為 Unity PlayerPrefs 不提供獲取設定項數量的介面。

> Source: [PlayerPrefsSettingHelper.cs#L52-L55](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L52-L55)

```csharp
public override int Count
{
    get { return -1; }  // PlayerPrefs 不支援獲取數量
}
```

**解決方案：**

1. 使用 `DefaultSettingHelper` 可以獲取準確的設定項數量
2. 或者自行維護計數變數

## 平臺相容性問題

### 問題 8：WebGL 小程式平臺儲存問題

**問題描述：**
在抖音、微信、快手等小程式平臺上，設定無法正常儲存或讀取

**原因分析：**
小程式平臺有各自的儲存 API，不支援 Unity 原生 PlayerPrefs。框架針對這些平臺做了適配：

> Source: [PlayerPrefsSettingHelper.cs#L80-L86](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L80-L86)

```csharp
public override bool Save()
{
#if UNITY_WEBGL && (ENABLE_DOUYIN_MINI_GAME || ENABLE_WECHAT_MINI_GAME || ENABLE_KUAISHOU_MINI_GAME)
    return true;  // 小程式平臺無需手動儲存
#else
    UnityEngine.PlayerPrefs.Save();
    return true;
#endif
}
```

**解決方案：**

1. 確保定義了正確的平臺宏：
   - `ENABLE_DOUYIN_MINI_GAME` - 抖音小程式
   - `ENABLE_WECHAT_MINI_GAME` - 微信小程式
   - `ENABLE_KUAISHOU_MINI_GAME` - 快手小程式

2. 在 Unity Build Settings 中正確配置釋出平臺

### 問題 9：物件序列化失敗

**問題描述：**
使用 `SetObject()` 或 `GetObject()` 時，物件資料無法正確儲存或讀取

**可能原因：**

1. 物件型別不支援 JSON 序列化
2. 物件包含不可序列化的成員（如 delegate、EventHandler）
3. 迴圈引用導致序列化失敗

**解決方案：**

1. 確保物件類標記為 `[Serializable]`
2. 使用可序列化的資料結構
3. 處理迴圈引用

```csharp
[Serializable]
public class PlayerData
{
    public string Name;
    public int Level;
    public List<Item> Items;
}

[Serializable]
public class Item
{
    public int Id;
    public int Count;
}

// 使用示例
var playerData = new PlayerData
{
    Name = "Player1",
    Level = 10,
    Items = new List<Item>()
};

settingComponent.SetObject("PlayerData", playerData);
settingComponent.Save();

// 讀取資料
var loadedData = settingComponent.GetObject<PlayerData>("PlayerData");
```

## API 使用問題

### 問題 10：Setting name is invalid

**錯誤資訊：**
丟擲 `GameFrameworkException("Setting name is invalid.")`

**原因分析：**
所有設定 API 都會檢查設定名稱是否為空。如果傳入 null 或空字串，將丟擲異常。

> Source: [SettingManager.cs#L215-L218](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L215-L218)

```csharp
if (string.IsNullOrEmpty(settingName))
{
    throw new GameFrameworkException("Setting name is invalid.");
}
```

**解決方案：**

```csharp
// 錯誤用法
settingComponent.SetBool("", true);  // 丟擲異常

// 正確用法
settingComponent.SetBool("IsFullScreen", true);
```

### 問題 11：空值返回問題

**問題描述：**
使用無預設值的方法獲取不存在的設定時，返回意外的值

**原因分析：**
不同的資料型別在沒有預設值引數時的預設返回值不同：

| 資料型別 | 無預設值方法返回值 |
|----------|-------------------|
| bool | false |
| int | 0 |
| float | 0f |
| string | null |

**解決方案：**

1. **始終使用帶預設值的方法**：
```csharp
// 不推薦
bool isFullScreen = settingComponent.GetBool("IsFullScreen");

// 推薦
bool isFullScreen = settingComponent.GetBool("IsFullScreen", false);
```

2. **先檢查設定是否存在**：
```csharp
if (settingComponent.HasSetting("PlayerName"))
{
    string name = settingComponent.GetString("PlayerName");
}
else
{
    // 處理不存在的情況
}
```

## 除錯技巧

### 除錯日誌

啟用詳細日誌來診斷問題：

```csharp
// 在程式碼中新增除錯資訊
Debug.Log($"Settings Count: {settingComponent.Count}");
Debug.Log($"Has PlayerName: {settingComponent.HasSetting("PlayerName")}");

// 獲取所有設定名稱（僅 DefaultSettingHelper 支援）
string[] allNames = settingComponent.GetAllSettingNames();
foreach (var name in allNames)
{
    Debug.Log($"Setting: {name}");
}
```

### 檢查 Helper 配置

```csharp
// 獲取當前使用的 Helper 資訊
var helper = settingComponent.GetComponent<SettingHelperBase>();
Debug.Log($"Helper Type: {helper.GetType().Name}");
Debug.Log($"Helper FilePath: {(helper is DefaultSettingHelper dh ? dh.FilePath : "N/A")}");
```

## 常見錯誤對照表

| 錯誤資訊 | 原因 | 解決方案 |
|----------|------|----------|
| Setting manager is invalid | GameFramework 未初始化 | 確保 GameFrameworkEntry 已初始化 |
| Can not create setting helper | Helper 型別名稱錯誤 | 檢查 Inspector 配置 |
| Load settings failure | 配置檔案損壞或路徑錯誤 | 檢查檔案路徑和許可權 |
| Save settings failure | 儲存介質不可用 | 檢查磁碟空間和許可權 |
| GetAllSettingNames is not supported | 使用了 PlayerPrefsHelper | 改用 DefaultSettingHelper |
| Setting name is invalid | 設定名稱為空 | 使用非空字串作為鍵名 |
| Count returns -1 | PlayerPrefs 不支援計數 | 使用 DefaultSettingHelper |
