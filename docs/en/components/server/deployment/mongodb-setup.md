# MongoDB Connection and Persistence Configuration

This page explains how to configure the MongoDB connection string and database name for service processes in GameFrameX.Server, so that `GameDb` completes the connection, initializes collections, and enters a persistable state during the startup phase.

## Prerequisites

- Prepare an accessible MongoDB instance (either a local service or an Atlas cluster works).
- Have the connection string for that instance (standard URI or the `mongodb+srv://` form) as well as a target database name.
- The launcher project (`GameFrameX.Launcher`) already references `MongoDB.Driver` via a package reference; source code projects reference the MongoDB assemblies through the `global using` entries in `GameFrameX.Apps/GlobalUsings.cs` and `GameFrameX.Hotfix/GlobalUsings.cs`, so no additional reference is needed in business code.

## Steps

1. In the startup entry point (by default `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`), construct `AppSetting` inside `Init()` and fill in the two database-related fields `DataBaseUrl` and `DataBaseName`:

   ```csharp
   Setting = new AppSetting
   {
       // ... other server configuration
       DataBaseUrl  = "mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority",
       DataBaseName = "<your_db_name>",
   };
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L97-L114)

2. During the database initialization phase of the server startup main loop, the framework calls `GameDb.Init<MongoDbService>` and passes the two fields above into `DbOptions`:

   ```csharp
   LogHelper.Debug("开始启动数据库服务...");
   var initResult = await GameDb.Init<MongoDbService>(new DbOptions
   {
       ConnectionString = Setting.DataBaseUrl,
       Name             = Setting.DataBaseName,
   });
   if (initResult == false)
   {
       throw new InvalidOperationException("数据库服务启动失败");
   }
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67)

3. Start the process. If the log shows "启动数据库服务 结束..." and no `InvalidOperationException` is thrown, the MongoDB connection and persistence layer is ready.

## Common Variants

- **Using a local MongoDB**: Replace `DataBaseUrl` with `mongodb://localhost:27017` and adjust the database name as needed.
- **Using an Atlas cluster**: Keep the default example form `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority` and simply replace the account and cluster host with real values.
- **Multi-environment isolation**: Set `DataBaseUrl` / `DataBaseName` per environment in the `Init()` of different startup entry points (e.g., `AppStartUpGate`, `AppStartUpWorld`, and other classes inheriting from `AppStartUpGame`), so that different processes point to different databases.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Startup throws `InvalidOperationException("数据库服务启动失败")` | `GameDb.Init<MongoDbService>` returned `false`, usually because the connection string is unreachable, the credentials are wrong, or the network is restricted | Check the host, port, user, and password in `DataBaseUrl`; confirm the Atlas IP allowlist permits the machine running the service |
| The application hangs before reaching the database step | The connection string contains unencoded special characters (e.g., `@`, `%`) | Percent-encode the username/password, e.g., change `p@ss` to `p%40ss` |
| The connection succeeds but reads/writes report "collection does not exist" | `DataBaseName` does not match what the business expects | Confirm that `DbOptions.Name` matches the database name used by the business code |

## Background (Optional)

`GameDb` is the framework's unified persistence facade; the actual implementation is provided by the generic parameter `MongoDbService`. During startup, the connection string and database name are injected via `DbOptions`, which completes client construction, database selection, and registration of the default serialization conventions; the business layer simply calls through `GameDb` and never holds `IMongoClient` directly, making it easy to switch or replace the underlying implementation later.
