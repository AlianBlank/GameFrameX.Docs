# 파일 및 디렉터리 존재 여부 확인

`BlankReadAssets`는 `FileExists`와 `DirectoryExists` 두 개의 정적 메서드를 제공하며, 런타임에 `StreamingAssets` 아래의 파일 또는 디렉터리 존재 여부를 판단하는 데 사용됩니다. 이 메서드들은 Android(APK 직접 읽기), 에디터, 기타 플랫폼(느슨한 파일) 등 다양한 환경에서 정상적으로 동작하며, 첫 호출 시 자동으로 `Initialize`를 호출합니다.

## 사전 조건

- `com.gameframex.unity.readassets` 패키지가 설치되어 있어야 합니다.
- `StreamingAssets` 디렉터리가 프로젝트 내에 존재해야 합니다(런타임 시 수동 초기화가 필요 없으며, 첫 API 호출 시 자동으로 완료됩니다).

## 작업 단계

1. 파일 존재 여부를 판단할 때는 `StreamingAssets` 기준 상대 경로를 전달합니다:

```csharp
using GameFrameX.ReadAssets.Runtime;

bool exists = BlankReadAssets.FileExists("configs/level1.json");
if (exists)
{
    // OpenRead / LoadAssetBundle 등을 안전하게 계속 진행
}
```

2. 디렉터리 존재 여부를 판단할 때도 동일한 방식으로 상대 경로를 사용합니다(앞이나 뒤에 `/`가 있어도 무관하며, 내부에서 정규화 처리됩니다):

```csharp
using GameFrameX.ReadAssets.Runtime;

bool dirExists = BlankReadAssets.DirectoryExists("configs/");
```

## API 빠른 참조

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| `FileExists` | `static bool FileExists(string path)` | `StreamingAssets` 기준 상대 경로의 파일 존재 여부 확인 |
| `DirectoryExists` | `static bool DirectoryExists(string path)` | `StreamingAssets` 기준 상대 경로의 디렉터리 존재 여부 확인 |

두 메서드 모두 `[Preserve]`로 표시되어 있으며, `EnsureInitialized()`를 통해 자동으로 초기화된 후 플랫폼 구현체(`EditorImpl` / `ApkImpl` / `LooseFilesImpl`)에 위임됩니다.

## 일반적인 변형

- 에디터에서 외부 APK 내부의 `StreamingAssets` 존재 여부를 확인하려면 먼저 `InitializeWithExternalApk(apkPath)`를 호출한 후 동일한 `FileExists` / `DirectoryExists`를 사용해야 합니다.
- Android에서 APK 내부의 경로 판단은 APK의 디렉터리 트리를 스캔합니다(`ApkImpl.DirectoryExists` 내부에서 `GetDirectoryIndex` 사용), 따라서 대소문자와 압축 상태에 대해 걱정할 필요가 없습니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 항상 `false`를 반환하지만 파일이 실제로 존재함 | 경로가 절대 경로로 전달되었거나 `Application.streamingAssetsPath` 접두사가 포함됨 | `StreamingAssets` 기준 상대 경로만 전달합니다. 예: `Application.streamingAssetsPath + "/config.json"`이 아닌 `"config.json"` |
| 경로에 역슬래시 또는 불필요한 `/`가 포함되어 오판단 발생 | 플랫폼별 경로 구분자 차이 | `/`로 구분된 상대 경로를 직접 전달하며, 도구 내부에서 `PathUtil.NormalizeRelativePath`를 통해 정규화됩니다 |
| Android에서 `true`를 반환하지만 후속 `OpenRead`에서 예외 발생 | 파일이 APK 내부에서 Unity에 의해 압축됨으로 표시됨 | `BlankReadAssets.CompressedStreamingAssetFound` 이벤트를 수신하여 `UnityWebRequest`로 읽도록 변경 |

## 배경 지식 (선택 사항)

플랫폼 배포는 `BlankReadAssets.cs` 상단의 조건부 컴파일에 의해 선택됩니다: `UNITY_EDITOR`는 `EditorImpl`(APK 모드/외부 디렉터리 지원), `UNITY_ANDROID`는 `ApkImpl`(APK 내부에서 바이너리 검색으로 위치 파악), 기타 플랫폼은 `LooseFilesImpl`(파일 시스템 직접 사용)을 거칩니다. APK 내부의 `DirectoryExists`는 미리 구축된 경로 인덱스인 `GetDirectoryIndex`를 통해 판단하므로 실제 압축 해제를 유발하지 않습니다.
