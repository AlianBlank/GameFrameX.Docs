# アプリ起動時にデバッグ情報を出力する方法

`OptionsBuilder.CreateWithDebug<T>` を使用するか、`OptionsDebugger.PrintParsedOptions` を直接呼び出すことで、アプリの起動時に解析済みのコマンドライン引数、値、型、デフォルト値、必須かどうかなどの情報をテーブル形式でコンソールに出力できます。これにより、起動時の設定問題のトラブルシューティングが容易になります。

## 前提条件

- NuGet から `GameFrameX.Foundation.Options` を参照していること。
- `class` 設定型が定義されており、各プロパティに `OptionAttribute` が付与されていること(`OptionAttribute` の使用方法を参照)。

## 操作手順

1. 設定型 `AppOptions` を定義し、各プロパティに `OptionAttribute` を付与します:

```csharp
using GameFrameX.Foundation.Options.Attributes;

public sealed class AppOptions
{
    [Option(LongName = "host", Description = "服务监听地址", Required = true)]
    public string Host { get; set; } = "127.0.0.1";

    [Option(LongName = "port", Description = "服务端口", DefaultValue = 8080)]
    public int Port { get; set; }

    [Option(LongName = "token", Sensitive = true, Description = "访问令牌")]
    public string Token { get; set; }
}
```

Source: [AppOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/OptionsDebuggerSensitiveOutputTests.cs#L1-L40)

2. `Main`/`Program` で `CreateWithDebug` を使って 1 行でビルドと出力を行います:

```csharp
using GameFrameX.Foundation.Options;

var options = OptionsBuilder.CreateWithDebug<AppOptions>(
    args: args,
    skipValidation: false);

Console.WriteLine($"使用 Host = {options.Host}");
```

`CreateWithDebug` の内部ではすでに `OptionsDebugger.PrintParsedOptions(result)` が呼び出され、解析結果がテーブル形式で出力されます。

Source: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L175-L184)

3. `OptionsBuilder<T>.Build()` や `OptionsProvider.Get<T>()` を使用する場合も、成功パス内で自動的に `PrintParsedOptions` が呼び出されるため、追加で出力する必要はありません。

Source: [OptionsProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsProvider.cs#L185-L218)

4. 出力タイミングを自分で制御したい場合は、直接呼び出します:

```csharp
OptionsDebugger.PrintParsedOptions(options);
```

出力内容には、ヘッダー `Command-line parameter and parsed configuration object information` と、6 列のテーブル(オプション、値、必須、型、説明、デフォルト値)が含まれます。機密フィールド(`Sensitive = true`)の値はマスクされます。

Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L70-L91)
Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L161-L172)

## よくあるバリエーション

- **例外を手動でキャッチして出力する**:`TryCreate` が失敗した場合、`result` はデフォルト値オブジェクトにフォールバックします。catch 後に `PrintParsedOptions` を呼び出してエラーコンテキストを出力できます。
- **ビルド済みのオブジェクトのみを出力する**:起動時以外のデバッグでは、どこかで `TOptions` インスタンスを取得し、直接 `OptionsDebugger.PrintParsedOptions(options)` を呼び出すだけです。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| コンソールの列が崩れる、全角文字の位置がずれる | コンソール幅が `DefaultConsoleWidth`(120)未満で、列幅が圧縮されている | 起動時にコンソール幅を広げるか、全角文字対応のターミナルで実行する |
| テーブルの特定の列が切れる | 説明テキストが長すぎて `MaxDisplayElements` の制限に達する | `Description` のテキストを短くするか、複数のプロパティに分割する |
| 機密フィールドが平文で表示される | `OptionAttribute.Sensitive` が有効になっていない | キーを含むプロパティに明示的に `Sensitive = true` を付ける |
| テーブル形式で出力されない | 型が `class` ではない、または公開インスタンスプロパティがない | `where T : class, new()` の設定型を使用する |

## 背景(オプション)

`OptionsDebugger` はリフレクションで `T` の公開プロパティを列挙し、文字の表示幅(中国語は全角幅)でコンソール幅に適応させ、機密フィールドをマスクします。起動時の出力は `CreateWithDebug` と `OptionsProvider` の内部で統一的に呼び出されるため、各所で定型コードの繰り返しを避けることができます。
