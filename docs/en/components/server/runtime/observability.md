# Configuring OpenTelemetry / Prometheus Metrics and Health Checks

This section demonstrates how to enable the built-in OpenTelemetry telemetry of GameFrameX.Server, and expose the Prometheus metrics (`/metrics`) and health check (`/health`) endpoints to monitoring systems.

## Prerequisites

- GameFrameX.Server has been deployed and can start normally.
- The monitoring system can access the port specified by `MetricsPort` on the server (default `29090`).

## Steps

1. Enable the OpenTelemetry master switch via startup parameters or environment variables.

   ```bash
   --IsOpenTelemetry=true
   ```

   Example startup command (the `MetricsPort` and `APMPort` lines in `docker-compose.yml` can be used as a reference):

   ```bash
   --InnerPort=29100 \
   --MetricsPort=29090 \
   --IsEnableHttp=true
   ```

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L115-L121)

2. Enable Prometheus metrics export (default `false`, requires `IsOpenTelemetry=true`).

   ```bash
   --IsOpenTelemetryMetrics=true
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

3. (Optional) Enable distributed tracing.

   ```bash
   --IsOpenTelemetryTracing=true
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)

4. Set the metrics collection port. If not set, the default value `0` is used (i.e., the external port is disabled).

   ```bash
   --MetricsPort=29090
   ```

   See the table below for default and example values. Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

5. Restart the service and verify that both endpoints are available:

   | Endpoint | URL | Description |
   |------|-----|------|
   | Health check | `http://<host>:29090/health` | Service liveness and readiness status |
   | Prometheus metrics | `http://<host>:29090/metrics` | Metrics text scraped by Prometheus |

   Source: [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L175-L177)

## Common Variants

- **Docker Compose deployment**: Simply append the following lines to the environment variables section of `docker-compose.yml`; no image changes are required.
  See [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82)
- **Enable health check only, without exporting metrics**: Keep `IsOpenTelemetryMetrics=false`, and simply wire the `/health` endpoint into your load balancer or K8s readiness probe.
- **Export to a remote OTLP collector**: With `IsOpenTelemetry=true` enabled, turn on `IsOpenTelemetryTracing` to output trace data (configure the specific collector address as needed for your deployment).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Accessing `/metrics` returns connection refused | `IsOpenTelemetry` is not enabled | Add `--IsOpenTelemetry=true` and restart |
| No metrics even after enabling `IsOpenTelemetryMetrics` | Master switch missing | This parameter depends on `IsOpenTelemetry=true` |
| Port conflict | `MetricsPort` and `APMPort` occupy the same port | Explicitly set `MetricsPort=29090` and make sure the host port is free |
| Prometheus cannot scrape data | Firewall does not allow the port | Allow `MetricsPort` in the security group/firewall |

## Configuration Quick Reference

| Name | Type/Default | Description |
|------|-------------|------|
| `IsOpenTelemetry` | `bool`, default `false` | Master switch for OpenTelemetry telemetry |
| `IsOpenTelemetryMetrics` | `bool`, default `false` | Enables Prometheus metrics export; requires `IsOpenTelemetry=true` |
| `IsOpenTelemetryTracing` | `bool`, default `false` | Enables distributed tracing; requires `IsOpenTelemetry=true` |
| `MetricsPort` | `int`, default `0` | Metrics collection port; example value `29090` |

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L78-L82), [README.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.md#L519-L520)

## Background

OpenTelemetry is a CNCF-graduated observability standard. GameFrameX.Server uses a two-tier design of master switch + sub-switches to separate metrics from tracing, making it easy to expose only the health check when full telemetry is not needed, reducing port and resource usage on the host machine.
