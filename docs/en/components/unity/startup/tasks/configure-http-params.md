# How to Configure HTTP Common Parameters

To inject unified common parameters (such as channel, language, device identifier, etc.) into all HTTP requests in the startup procedure, implement `IStartupHttpParamsProvider` and register it into the procedure context to take effect.

## Prerequisites

- The project has referenced the `GameFrameX.Startup` package and can access `IFsm<IProcedureManager>` within the startup procedure.
- Understand the meaning of the fields in the startup options `StartupOptions` (package name, channel, sub-channel, etc.).

## Steps

1. **Implement the parameter carrier (optional)**

   If you only need to reuse the default fields, you can use `StartupHttpParams` directly; when you need to add fields, derive a new class and implement `IStartupHttpParams.ToJson()` and `ToDictionary()`.

   ```csharp
   using GameFrameX.Startup.Runtime;
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MyStartupHttpParams : StartupHttpParams
   {
       public string ServerId = string.Empty;

       public override string ToJson()
       {
           ServerId = ServerId ?? string.Empty;
           return Utility.Json.ToJson(this);
       }

       public override Dictionary<string, object> ToDictionary()
       {
           var dict = base.ToDictionary();
           dict["ServerId"] = ServerId ?? string.Empty;
           return dict;
       }
   }
   ```

   Source: [Runtime/Http/StartupHttpParams.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L19-L151)

2. **Implement `IStartupHttpParamsProvider`**

   In the `Create` method, map `StartupOptions` (along with any runtime context you want) into a parameter object.

   ```csharp
   using GameFrameX.Startup.Runtime;

   public class MyStartupHttpParamsProvider : DefaultStartupHttpParamsProvider
   {
       public override IStartupHttpParams Create(StartupOptions options)
       {
           var p = (MyStartupHttpParams)base.Create(options);
           p.ServerId = "cn-east-1";
           p.AppVersion = Application.version;
           p.Platform = Application.platform.ToString();
           p.DeviceUniqueIdentifier = SystemInfo.deviceUniqueIdentifier;
           return p;
       }
   }
   ```

   Source: [Runtime/Http/DefaultStartupHttpParamsProvider.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/DefaultStartupHttpParamsProvider.cs#L9-L23)

3. **Register into the startup procedure**

   After creating the `GameFrameX.Startup` procedure manager, write the provider instance to the blackboard key `StartupHttpParamsProvider` (of type `VarObject`). The procedure reads it internally via `StartupProcedureUtility.GetHttpParamsProvider`; if not registered, it automatically falls back to `DefaultStartupHttpParamsProvider`.

   ```csharp
   var provider = new MyStartupHttpParamsProvider();
   var providerBox = VarObject.Create(provider);
   procedureOwner.SetData(BlackBoardKeys.StartupHttpParamsProvider, providerBox);
   ```

   Source: [Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L71-L76)

4. **Read the common parameters in HTTP requests**

   Use `GetHttpParams(procedureOwner)` to obtain the currently active parameter instance, then call `ToJson()` or `ToDictionary()` to inject it into your HTTP client/body.

   ```csharp
   var httpParams = StartupProcedureUtility.GetHttpParams(procedureOwner);
   var dict = httpParams.ToDictionary();
   // Merge dict into your POST form or JSON body
   ```

   Source: [Runtime/Procedures/StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L78-L99)

## Common Variants

- **Fully custom field set**: Instead of inheriting from `StartupHttpParams`, implement the `IStartupHttpParams` interface directly and return your own fields in `ToJson()` / `ToDictionary()`.
- **Platform branching at runtime**: In `Provider.Create`, return different parameter objects based on `Application.platform` (for example, appending `ConsoleId` only for consoles).
- **Dynamically refreshing parameters**: If a field (such as the server region) needs to change midway, simply reconstruct the parameter object and overwrite it via `SetData(BlackBoardKeys.StartupHttpParamsProvider, ...)`.

## Common Mistakes

- **Forgetting to register to the blackboard**: `GetHttpParamsProvider` returns the default provider when nothing is registered; the business logic will not throw errors, but all custom fields will be lost. Before registering, make sure `SetData` has been executed before the first procedure that uses the parameters.
- **`options` is null**: `StartupHttpParams.FromOptions` throws `ArgumentNullException` for `null`. In a custom Provider, add a null check first, or make sure `StartupOptions` has been assigned before calling `FromOptions`.
- **Derived class missing `ToDictionary`**: If you only override `ToJson` but not `ToDictionary`, the newly added fields will not appear in the dictionary-form request body, and the server may not receive them. Both must be implemented together.
- **Field names inconsistent with backend conventions**: The keys in `ToDictionary` (for example, `"Channel"`) are the field names sent to the backend; after renaming them, the backend contract must be updated accordingly.

## Background (optional)

The startup framework does not directly initiate HTTP requests; instead, it abstracts "how to produce common parameters" into `IStartupHttpParamsProvider` and leaves "how to consume the parameters" to the upper-level HTTP module. The framework only guarantees that an `IStartupHttpParams` instance is available within the procedure; whether it goes into the Header, Query, Body, or Form is decided by the caller. This design allows the HTTP implementation to be freely swapped (GameFrameX.Network, BestHTTP, UnityWebRequest, etc.) while the common parameters remain consistent.
