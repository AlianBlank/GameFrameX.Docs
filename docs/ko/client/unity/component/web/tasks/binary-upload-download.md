# 바이너리 데이터 업로드 및 다운로드 방법

`WebComponent`의 `GetToBytes` / `PostToBytes` 계열 메서드를 사용하면 `byte[]` 바이너리 데이터를 송수신할 수 있으며, 이들은 모두 `Task<WebBufferResult>`를 반환하므로 `async/await`를 통해 바이트 배열 결과를 직접 얻을 수 있습니다.

## 사전 조건

- 씬에 `WebComponent` 컴포넌트가 추가되어 있어야 합니다(GameFrameX Web 모듈의 진입점).
- `await`를 사용하는 메서드는 `async`로 표시되어야 하며, `GameFrameX.Web.Runtime` 네임스페이스가 using 되어 있어야 합니다.
- 서버는 `application/octet-stream` 콘텐츠 타입을 지원해야 합니다. 프레임워크는 바이너리 요청을 전송할 때 이 Content-Type을 고정적으로 사용합니다.

## 작업 단계

1. `WebComponent` 인스턴스를 가져옵니다(예: GameEntry 모듈 매니저를 통해).

2. 바이너리 다운로드: `GetToBytes`를 호출하고, 반환된 `WebBufferResult.Result`에서 바이트 배열을 가져옵니다.

```csharp
WebBufferResult result = await GameEntry.Web.GetToBytes("https://example.com/assets/avatar.png");
byte[] bytes = result.Result; // 서버가 반환한 원본 바이너리 내용
```

`IWebManager` 인터페이스에서 `GetToBytes`의 실제 시그니처:

```csharp
Task<WebBufferResult> GetToBytes(string url, object userData = null);
Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, object userData = null);
```

출처: [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L26-L45)

3. 바이너리 업로드: `PostToBytes`를 호출하고 `byte[]` 폼 데이터를 전달합니다.

```csharp
byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello");
WebBufferResult result = await GameEntry.Web.PostToBytes(
    "https://example.com/api/upload",
    payload,
    null,   // queryString, null 가능
    null,   // header, null 가능
    "myTag" // userData, 콜백 시 그대로 전달됨
);
```

출처: [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L199-L209)

4. 결과를 읽습니다. `WebBufferResult`는 두 개의 속성만 포함합니다:

| 속성 | 타입 | 설명 |
|------|------|------|
| `Result` | `byte[]` | 서버가 반환한 원본 바이트 배열 |
| `UserData` | `object` | 요청 시 전달된 커스텀 데이터, 그대로 반환됨 |

출처: [WebBufferResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebBufferResult.cs#L11-L19)

## 일반적인 변형

**쿼리 파라미터 및 요청 헤더 포함**: 두 개의 딕셔너리가 URL과 HTTP 헤더에 병합됩니다.

```csharp
var queryString = new Dictionary<string, string> { { "id", "1001" } };
var header = new Dictionary<string, string> { { "Authorization", "Bearer token" } };
WebBufferResult result = await GameEntry.Web.GetToBytes("https://example.com/file", queryString);
```

**Post 객체 폼**: `byte[]` 오버로드 외에도 `PostToBytes`는 `Dictionary<string, object>` 폼도 지원합니다(프레임워크 내부에서 직렬화한 후 전송):

```csharp
Task<WebBufferResult> PostToBytes(string url, Dictionary<string, object> from, object userData = null);
```

출처: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L506-L508)

**WebGL 플랫폼**: 동일한 API가 WebGL 환경에서 자동으로 `UnityWebRequest`를 사용하도록 전환되고 `DefaultBypassCertificate` 인증서 핸들러가 장착되므로, 호출 코드를 수정할 필요가 없습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `TimeoutException` 발생 | WebGL이 아닌 플랫폼에서 요청 시간 초과(`WebExceptionStatus.Timeout`이 `TimeoutException`으로 변환됨) | 네트워크 및 서버 가용성을 확인하거나, 매니저의 `RequestTimeout` 설정 값을 늘리십시오 |
| `Exception` 발생(내용은 `unityWebRequest.error` 원문) | WebGL에서 `isNetworkError` / `isHttpError`가 true | error 텍스트를 기준으로 원인 파악: 404이면 URL 확인, `crossdomain`이면 크로스 도메인 설정 확인 |
| `WebException` / `IOException` 발생 | WebGL이 아닌 플랫폼에서 응답 스트림 읽기 실패 또는 연결 중단 | try/catch로 캡처한 후 재시도; 서버가 바이너리 스트림을 반환하는지 확인 |
| 서버가 깨진 데이터를 수신함 | 서버 측에서 `application/octet-stream`으로 파싱하지 않음 | 프레임워크는 이 Content-Type을 고정적으로 전송하므로, 서버는 요청 본문을 원시 바이트로 읽어야 합니다 |

타임아웃 및 예외 변환 로직의 소스 코드:

```csharp
// 타임아웃 예외 캡처
if (e.Status == WebExceptionStatus.Timeout)
{
    webData.TaskSource.SetException(new TimeoutException(e.Message));
    return;
}
```

출처: [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L161-L170)

## 배경

바이너리 요청은 `WebManager`의 partial 구현인 `WebManager.Binary.cs`에서 처리됩니다: 요청은 먼저 대기 큐 `m_WaitingBinaryQueue`에 들어가고, `UpdateBinary`가 `MaxConnectionPerServer` 동시 실행 상한에 따라 하나씩 꺼내어 실행합니다. WebGL이 아닌 플랫폼에서는 `HttpWebRequest` + 메모리 스트림 복사 방식을 사용하고, WebGL 플랫폼에서는 `UnityWebRequest`를 사용합니다. `WebBinaryData` 객체는 참조 풀을 통해 재사용되며, 완료 후 자동으로 `Release`됩니다. Web 모듈의 전체 구조에 대해서는 《Web 모듈 소개》를 참고하십시오.
