# UI フォームが開けない場合の対処方法

`UIManager.OpenUIForm` / `OpenUIFormAsync` を呼び出した後に UI が表示されない、例外がスローされる、または失敗コールバックのみが発火する場合は、このページの手順で根本原因を迅速に特定し、修正してください。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `OpenUIFormFailureEventArgs` コールバック内のエラーメッセージが `Resources.Load failed for path: <path>` | リソースパスが `BundlesDirectoryName` 配下になく、Resources ロードが実行されたがパスが存在しない | 「Resources パスのリソースロード失敗」を参照 |
| `OpenUIFormFailureEventArgs` に `assetHandle.LastError` が含まれる | バンドル内ロードが実行されたが、`LoadAssetAsync` が `Failed` ステータスを返した | 「バンドル内リソースロード失敗」を参照 |
| 例外 `GameFrameworkException: Can not create UI form in UI form helper.` | `UGUIFormHelper.CreateUIForm` が `null` を返した | 「ロジックスクリプトの型不一致 / スクリプト未アタッチ」を参照 |
| 例外 `GameFrameworkException: Open UI form info is invalid.` | `LoadAssetSuccess/FailureCallback` 内で `openUIFormInfo` が空 | 「ハンドルとコールバックのライフサイクル異常」を参照 |
| 例外 `ArgumentNullException`(`GameFrameworkGuard.NotNull` によってスローされる) | 渡された `m_AssetManager` / `m_UIFormHelper` / `uiFormType` が null | 「キーパラメータが null」を参照 |
| コンソールに `UI form instance type Xxx is invalid.` と出力されるが例外はない | プレハブに `IUIForm` を継承したロジックスクリプトがアタッチされていない | 「ロジックスクリプトの型不一致 / スクリプト未アタッチ」を参照 |
| リソースプール再利用分岐で複数回のオープン要求が発生しているのに 1 つしか表示されない | シングルトンオープンモード(`UseSingletonOpenMode`)に該当し、以降のリクエストがマージされた | 「シングルトンオープンがマージされる」を参照 |

## 修正手順

### Resources パスのリソースロード失敗

`InnerLoadUIFormAsync` は、パスに `BundlesDirectoryName` が含まれていない場合に `Resources.Load` を使用します。見つからない場合は失敗メッセージを構築して返します:

```csharp
if (uiFormAssetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    var original = (GameObject)Resources.Load(assetPath);
    if (original == null)
    {
        return LoadAssetFailureCallback(assetPath, $"Resources.Load failed for path: {assetPath}", openUIFormInfo);
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L144-L155](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L144-L155)

修正:

1. `uiFormAssetPath + uiFormType.Name` が実際にいずれかの `Resources/` ディレクトリ配下に存在することを確認してください(大文字・小文字は区別されます)。
2. リソースが AssetBundle 内にある場合は、`BundlesDirectoryName` を含むパスに変更し(デフォルトは `Assets/AssetBundle/` またはゲームが独自に定義したサブディレクトリ名)、バンドル内ロード分岐が使われるようにしてください。
3. 失敗コールバックを登録して、具体的なパスを取得します:

```csharp
m_UIManager.OpenUIFormFailureEvent += (sender, args) =>
{
    Debug.LogError($"OpenFail [{args.UIFormAssetName}] {args.ErrorMessage}");
};
```

### バンドル内リソースロード失敗

バンドル内分岐では `AssetManager.LoadAssetAsync` を使用し、ステータスが `Succeed` 以外であれば失敗とみなされます:

```csharp
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(assetPath);
if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    ...
    return LoadAssetSuccessCallback(assetPath, gameObject, assetHandle.Progress, openUIFormInfo);
}
return LoadAssetFailureCallback(assetPath, assetHandle.LastError, openUIFormInfo);
```

Source: [Runtime/UIManager.Open.cs#L158-L169](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L158-L169)

修正：

1. `assetHandle.LastError` を確認してください。よくある原因:AssetBundle マニフェストに該当 UI が含まれていない、ビルド時のパスとロード時のパスの不一致、依存パッケージのロード完了前に Open を呼び出した。
2. `m_AssetManager` が初期化済みであることを確認してください(「キーパラメータが null」を参照)。
3. 起動フローでの AssetBundle マニフェストの解析が完了してから、オープン要求を発行してください。

### ロジックスクリプトの型不一致 / スクリプト未アタッチ

`UGUIFormHelper.CreateUIForm` は、インスタンスが `GameObject` でない場合、または `IUIForm` スクリプトがアタッチされていない場合に `null` を返し、その後 `InternalOpenUIForm` が `Can not create UI form in UI form helper.` をスローします:

```csharp
var componentType = uiGameObject.GetOrAddComponent(uiFormType);
if (!(componentType is IUIForm uiForm))
{
    Log.Error($"UI form instance type {uiFormType} is invalid.");
    return null;
}
```

Source: [Runtime/UGUIFormHelper.cs#L91-L105](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L91-L105)

修正：

1. オープン失敗時の Preload の挙動:Preload では引き続き UI フォームが作成され OnAwake が呼ばれるため、ロジックスクリプトが未初期化のデータに依存しないようにしてください。
2. Preload のリソースパスとオープン時のパスが完全に一致することを確認してください。一致しない場合、2 つのプールが異なるプレハブを指すことになります。

### ハンドルとコールバックのライフサイクル異常

`LoadAssetSuccessCallback` / `LoadAssetFailureCallback` が受け取った `openUIFormInfo` が空の場合、`Open UI form info is invalid.` がスローされます。この情報は `UIFormLoadingObject.Create` によって `InnerOpenUIFormAsync` 内で作成されます:

```csharp
UIFormLoadingObject uiFormLoadingObject = UIFormLoadingObject.Create(uiFormAssetPath, uiFormAssetName, uiFormType, uiForm);
m_LoadingUIForms.Add(uiFormLoadingObject);
```

Source: [Runtime/UIManager.Open.cs#L108-L110](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L108-L110)

この異常は通常、カスタム `UIFormHelper` が規約どおりに `OpenUIFormInfo` を構築していない場合に発生します。必要がない限り、リソースロードのコールバックを上書きしないでください。

### キーパラメータが null

`InnerOpenUIFormAsync` の入口ではキーフィールドに対して `GameFrameworkGuard.NotNull` の検証が行われており、いずれか一つでも null であれば直ちに `ArgumentNullException` がスローされます:

```csharp
GameFrameworkGuard.NotNull(m_AssetManager, nameof(m_AssetManager));
GameFrameworkGuard.NotNull(m_UIFormHelper, nameof(m_UIFormHelper));
GameFrameworkGuard.NotNull(uiFormType, nameof(uiFormType));
```

Source: [Runtime/UIManager.Open.cs#L72-L74](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L72-L74)

修正：

1. `OpenUIForm` を呼び出す前に、`UIManager` の初期化が完了していることを確認してください(フレームワークの `GameFramework` 起動フロー)。
2. 呼び出し側が渡す `Type` は、null 以外であり、かつ `IUIForm` を実装している必要があります。
3. `UIFormHelper` を差し替えた場合は、それが `UIManager` に登録されていることを確認してください。

## 検証

修正後、最小構成のユースケースで検証します:

```csharp
var form = await m_UIManager.OpenUIFormAsync<MyUIFomLogic>("Assets/AssetBundle/UI/");
if (form == null)
{
    Debug.LogError("Open failed, see OpenUIFormFailureEvent for details.");
}
```

確認事項:

- `OpenUIFormSuccessEvent` が発火され、コールバック内の `duration > 0` であること。
- 失敗イベントが発生しなくなり、対象の UI が UI カメラに表示されていること。
- `IsLoadingUIForm(assetName)` が `false` を返し、`GetUIForm(assetName)` が null 以外のインスタンスを返すこと。## シングルトンオープンがマージされる

UI クラスが `[OptionUIGroup]` によって、またはフレームワークによってシングルトンオープンモード(`UseSingletonOpenMode`)と判定された場合、同一リソース名の重複オープンは既存のインスタンスを返し、`RefocusUIForm` が発火され、新しいインスタンスは作成されません:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L77-L97](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L77-L97)

修正：

1. 毎回新しいインスタンスを作成したい場合は、このモードのシングルトンフラグをオフにしてください(またはビジネス層でインスタンスのライフサイクルを独自に管理)。
2. 同時実行のオープン要求は同一のロード Task にマージされ、同じロード結果を待機します:

```csharp
foreach (var loadingUIForm in m_LoadingUIForms)
{
    if (loadingUIForm.UIFormAssetPath == uiFormAssetPath &&
        loadingUIForm.UIFormAssetName == uiFormAssetName &&
        loadingUIForm.UIFormType == uiFormType)
    {
        return await loadingUIForm.Task;
    }
}
```

Source: [Runtime/UIManager.Open.cs#L88-L96](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L88-L96)

同時実行による二回目のオープンでは新しい失敗コールバックは発火されず、最初のリクエストの失敗/成功イベントのみが発火されます。
