# 시작 동기 매개변수 검증 예외 발생 시 대처 방법

`StartupRunner.Run(...)`을(를) 호출할 때 전달된 매개변수가 요구 사항을 충족하지 않으면(예: `options`가 null, `GlobalInfoUrls`가 빈 배열 등) 비동기 상태 머신에 진입하기 전에 실패 결과를 반환하는 대신 `ArgumentNullException` 또는 `ArgumentException`을(를) **동기적으로** throw합니다. 이러한 예외는 "개발 단계 구성 오류"에 해당하므로, 검증 단계에서 즉시 드러나도록 하여 이후 코루틴 흐름이 오염되지 않도록 해야 합니다.

## 빠른 진단

| 예외 유형 | 대표 메시지 원문 | 발생 위치 | 수정 방향 |
|----------|--------------|----------|----------|
| `ArgumentNullException` | (메시지 없음, `ParamName`=`options`) | `StartupRunner.Run` 진입점 | 유효한 `StartupOptions` 인스턴스 전달 |
| `ArgumentNullException` | (메시지 없음, `ParamName`=`uiHandler`) | `StartupRunner.Run` 진입점 | `IStartupUIHandler`를 구현하여 전달 |
| `ArgumentNullException` | (메시지 없음, `ParamName`=`hotfixLauncher`) | `StartupRunner.Run` 진입점 | `IHotfixLauncher`를 구현하여 전달 |
| `ArgumentException` | 메시지에 `"GlobalInfoUrls"` 포함 | `StartupRunner.Run` 진입점 | `StartupOptions`에 최소 하나의 전역 정보 인터페이스 URL 입력 |
| `ArgumentNullException` | (메시지 없음, `ParamName`=`urls`) | `UrlFailoverRunner` 생성 | URL 배열 객체 자체가 null이 아닌지 확인 |

| `ArgumentException` | `"Retry delay must be zero or greater."` | `UrlFailoverRunner` 생성 | `retryDelayMs`을(를) `>= 0`으로 변경 |
| `ArgumentNullException` | (메시지 없음, `ParamName`=`options`) | `StartupHttpParams.FromOptions` | null이 아닌 `StartupOptions` 전달 |

## 수정 단계

### 1. `ArgumentNullException` 수정(options/uiHandler/hotfixLauncher)

`StartupRunner.Run`은(는) 코루틴에 진입하기 전에 세 가지 입력 매개변수가 null인지 동기적으로 검사합니다:

```csharp
public static UniTask<StartupResult> Run(
    StartupOptions options,
    IStartupUIHandler uiHandler,
    IHotfixLauncher hotfixLauncher)
```

해당 구현([Runtime/Startup/StartupRunner.cs#L45-L60](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L45-L60)):

```csharp
if (options == null)        throw new ArgumentNullException(nameof(options));
if (uiHandler == null)      throw new ArgumentNullException(nameof(uiHandler));
if (hotfixLauncher == null) throw new ArgumentNullException(nameof(hotfixLauncher));
```

수정 방법: 호출 진입점 전에 항목별로 검사하거나, Inspector / DI 컨테이너를 통해 null이 아닌 인스턴스가 주입되었는지 확인합니다. 예를 들어:

```csharp
if (StartupOptions.Instance == null)
{
    Debug.LogError("StartupOptions가 구성되지 않았습니다");
    return;
}
if (uiHandler == null || hotfixLauncher == null)
{
    Debug.LogError("UI/Hotfix 런처가 등록되지 않았습니다");
    return;
}
await StartupRunner.Run(StartupOptions.Instance, uiHandler, hotfixLauncher);
```

### 2. `ArgumentException` 수정(`GlobalInfoUrls` 비어 있음)

세 가지 null 검사를 통과한 후, `Run`은(는) `options.GlobalInfoUrls`도 검증합니다(해당 구현은 [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L37-L60) 참조). 이 필드가 null이거나 길이가 0이면 메시지에 `"GlobalInfoUrls"`가 포함된 `ArgumentException`이(가) 동기적으로 throw됩니다.

수정 방법: Unity에서 `Create > GameFrameX > Startup Options`로 에셋을 생성한 후, Inspector의 `GlobalInfoUrls` 필드에 접근 가능한 전역 정보 인터페이스 주소를 최소 하나 이상 입력합니다(기본/백업 URL은 배열 요소로 구분).

### 3. `UrlFailoverRunner`가 throw하는 검증 예외 수정

`UrlFailoverRunner`는 생성 시 URL 목록과 재시도 매개변수에 대해 전체 검증을 수행합니다([Runtime/Failover/UrlFailoverRunner.cs#L19-L34](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L34)):

```csharp
if (urls == null)
    throw new ArgumentNullException(nameof(urls));
if (urls.Length == 0)
    throw new ArgumentException("URL list must contain at least one URL.", nameof(urls));
if (maxAttemptsPerUrl <= 0)
    throw new ArgumentException("Max attempts per URL must be greater than zero.", nameof(maxAttemptsPerUrl));
if (retryDelayMs < 0)
    throw new ArgumentException("Retry delay must be zero or greater.", nameof(retryDelayMs));
```

수정 방법:

- `UrlFailoverRunner` 생성자에 전달하는 배열 참조가 null이 아니며 최소 하나의 URL을 포함하도록 합니다.
- `maxAttemptsPerUrl`은(는) 반드시 ≥ 1이어야 합니다.
- `retryDelayMs`은(는) 반드시 ≥ 0이어야 합니다(0은 재시도 지연 없음을 의미하며 유효한 값입니다).

### 4. `StartupHttpParams.FromOptions`가 throw하는 null 예외 수정

`FromOptions`는 `options`가 null일 때 `ArgumentNullException`을(를) throw합니다([Runtime/Http/StartupHttpParams.cs#L94-L99](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L94-L99)). `IStartupHttpParamsProvider`를 재정의한 경우, `FromOptions`를 호출하기 전에 직접 null 여부를 검사하십시오.

## 검증

- `StartupRunner.Run` 호출부를 `try/catch (ArgumentException)` / `try/catch (ArgumentNullException)`으로 감싸 예외를 캡처하고, 예외 유형과 `ParamName`/`Message`가 위 표와 일치하는지 확인합니다.
- `StartupOptions` 에셋을 수정한 후 Editor에서 다시 PlayMode에 진입하면 시작 프로세스가 `ProcedureGetAppVersionInfoState` 등 후속 노드로 정상 진입해야 하며, 더 이상 첫 프레임에서 동기적으로 예외가 throw되지 않아야 합니다.
- `UrlFailoverRunner`를 직접 생성하여 사용하는 경우, 단위 테스트에서 빈 배열, 음수 재시도 매개변수 등의 경계값을 전달하여 위 표의 예외 메시지가 재현되는지 확인한 후 수정합니다.

## 배경(선택 사항)

`StartupRunner.Run`은(는) 동기 검증과 비동기 흐름을 분리합니다. "명백하게 잘못 작성된" 모든 입력 매개변수는 검증 단계에서 동기적으로 throw되어, 유효하지 않은 상태가 `UniTask` 상태 머신에 진입하지 못하도록 합니다. 실제로 네트워크, 패치, 원격 서비스에서 발생하는 문제만 `StartupResult` / `StartupFailedEventArgs`를 통해 비동기적으로 보고됩니다. 이 규약은 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/CHANGELOG.md#L103)에도 명확히 기록되어 있습니다: "Synchronous validation throws `ArgumentException` for empty `GlobalInfoUrls` before entering async state machine."
