# 빠른 시작: 설치 및 첫 번째 코루틴 실행

이 가이드는 GameFrameX 코루틴 패키지를 Unity 프로젝트에 통합하고 "시작→중지→프레임 끝 콜백"이라는 세 가지 가장 일반적으로 사용되는 인터페이스를 실행하는 방법을 안내합니다. 이 컴포넌트는 Unity 네이티브 코루틴의 얇은 래퍼이며, 내부적으로 `ConcurrentDictionary`를 사용하여 시작된 모든 코루틴을 추적하여 중지 누락으로 인한 매달린 참조를 방지합니다.

## 사전 요구 사항

- Unity 2017.1 이상(테스트 대상은 Unity 2019.4)
- 정상적으로 열 수 있는 Unity 프로젝트
- 프로젝트에 `com.gameframex.unity.runtime`이 설치되어 있어야 함(이 컴포넌트는 해당 패키지의 `GameFrameworkComponent`에서 상속됨)

## 설치

다음 방법 중 하나를 선택하여 패키지를 프로젝트에 추가하세요:

1. **Scoped Registry를 통해(권장)** —— `Packages/manifest.json`을 편집하여 `scopedRegistries`에 GameFrameX 레지스트리를 추가하고 의존성을 선언하세요:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.coroutine": "1.0.3"
     }
   }
   ```

2. **Git URL을 통해** —— `dependencies` 아래에 직접 작성하세요:

   ```json
   "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
   ```

3. **Package Manager를 통해** —— `Add package from Git URL`을 사용하여 위의 저장소 주소를 입력하세요.

4. **수동 배치** —— 전체 저장소를 프로젝트의 `Packages/` 디렉터리에 복사하면 Unity가 자동으로 인식합니다.

## 작업 단계

1. **CoroutineComponent 인스턴스 가져오기.** 이 컴포넌트에는 `[DisallowMultipleComponent]` 및 `[GameFrameXAutoComponent(-6500)]` 특성이 있으므로 일반적으로 GameFrameX 프레임워크에 의해 `GameFrameworkEntry`가 부착된 GameObject에 자동으로 등록됩니다. 수동 방식은 다음과 같습니다:

   ```csharp
   var coroutineComponent = gameObject.AddComponent<GameFrameX.Coroutine.Runtime.CoroutineComponent>();
   ```

   출처: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L21)

2. **코루틴 메서드 작성.** 코루틴 시그니처는 반드시 `IEnumerator`를 반환해야 하며, 내부에서 `yield return`을 사용하여 진행 속도를 제어합니다:

   ```csharp
   IEnumerator HelloCoroutine()
   {
       Debug.Log("Hello");
       yield return null;            // 한 프레임 대기
       Debug.Log("Next frame");
   }
   ```

3. **코루틴 시작.** `StartCoroutine`을 호출하고 나중에 중지할 수 있도록 반환된 이터레이터 인스턴스를 저장하세요:

   ```csharp
   IEnumerator routine = HelloCoroutine();
   coroutineComponent.StartCoroutine(routine);
   ```

   주의: 반드시 `CoroutineComponent` 타입 참조를 통해 `StartCoroutine`을 호출해야 합니다. 이는 `new` 키워드를 사용하여 기본 클래스 메서드를 숨겨 추적 딕셔너리에 기록되도록 보장하기 때문입니다.

   출처: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

4. **단일 코루틴 중지(선택 사항).** 시작 시 저장한 동일한 `IEnumerator` 인스턴스를 다시 전달하세요:

   ```csharp
   coroutineComponent.StopCoroutine(routine);
   ```

   이 오버로드는 먼저 딕셔너리에서 해당 `UnityEngine.Coroutine`을 찾아 중지한 후 딕셔너리에서 제거합니다. 찾지 못하면 `base.StopCoroutine(enumerator)`로 폴백합니다.

   출처: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

5. **모든 코루틴 중지(선택 사항).** 씬 전환이나 로직 재설정 시 호출하세요:

   ```csharp
   coroutineComponent.StopAllCoroutines();
   ```

   구현은 먼저 딕셔너리에서 추적 중인 코루틴을 하나씩 중지하고 딕셔너리를 비운 다음, `base.StopAllCoroutines()`를 호출하여 추적되지 않은 코루틴까지 정리합니다.

   출처: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

6. **프레임 끝 콜백(선택 사항).** 현재 프레임의 모든 렌더링이 완료된 후 작업(예: 스크린샷, 보고)을 수행해야 할 때 사용하세요:

   ```csharp
   coroutineComponent.WaitForEndOfFrameFinish(() =>
   {
       Debug.Log("End of frame");
   });
   ```

   내부적으로 재사용 가능한 일회용 `WaitForEndOfFrame` 객체를 재사용하여 매번 호출 시 GC 할당이 발생하지 않도록 합니다.

   출처: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

## 일반적인 변형

- **`UnityEngine.Coroutine` 오버로드를 통한 중지**: Unity가 반환한 코루틴 핸들만 보유한 경우, `StopCoroutine(UnityEngine.Coroutine coroutine)` 오버로드를 사용하세요. 내부적으로 딕셔너리를 역방향으로 탐색하여 해당 이터레이터를 찾아 정리합니다.
- **`WaitForEndOfFrameFinish` 콜백에서 예외를 던지지 마세요**: 프레임이 끝나기 전에 `StopCoroutine`으로 해당 코루틴을 중지하면 콜백이 실행되지 않으므로 방어적인 null 검사를 할 필요가 없습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|----------|
| `StartCoroutine` 후 딕셔너리에서 찾을 수 없음 | `MonoBehaviour.StartCoroutine`을 호출했고 `CoroutineComponent.StartCoroutine`이 아님 | 항상 `CoroutineComponent` 타입 참조를 통해 호출하여 `new`로 숨겨진 버전이 사용되도록 하세요 |
| `StopCoroutine`이 작동하지 않음 | **새로 생성된** `IEnumerator`를 전달함(예: `HelloCoroutine()`을 다시 호출) | 시작 시 저장한 동일한 `IEnumerator` 인스턴스를 재사용하세요. 딕셔너리는 참조 동등성을 key로 사용합니다 |
| `StopAllCoroutines` 후에도 코루틴이 계속 실행됨 | 일반 `MonoBehaviour.StopAllCoroutines()`를 호출함 | `CoroutineComponent.StopAllCoroutines()`를 호출하여 추적 딕셔너리도 함께 비워지도록 하세요 |
| 프레임 끝 콜백이 트리거되지 않음 | 콜백이 실행되어야 하기 전에 `StopCoroutine`/`StopAllCoroutines`를 호출함 | 콜백에서 수행할 로직을 다음 프레임에 배치하거나 `yield return new WaitForEndOfFrame()` 이후에 판단하세요 |
