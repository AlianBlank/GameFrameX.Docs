# How to Register a Network Protocol Message Handler

By applying the `[MessageHandler]` attribute to a manager class that inherits `IMessageHandler` and calling `ProtoMessageHandler.Add(this)` during initialization, GameFrameX will automatically dispatch incoming protocol messages to the target methods — no manual `switch` dispatching required.

## Prerequisites

- A protocol message class imported from `GameFrameX.Network.Runtime` (generated by Proto, e.g., `NotifyBagInfoChanged`).
- The manager class inherits `GameFrameworkSingleton<T>` and implements the `IMessageHandler` interface.

## Steps

1. **Make the manager implement `IMessageHandler` and inherit the singleton base class**. The whole class only needs a single instance, and the network layer dispatches only to this one object.

   ```csharp
   using GameFrameX.Network.Runtime;
   using GameFrameX.Runtime;

   namespace Hotfix.Manager
   {
       public sealed class BagManager : GameFrameworkSingleton<BagManager>, IMessageHandler
       {
           // ...
       }
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L16)

2. **Apply the `[MessageHandler(typeof(MessageClass), nameof(MessageClass))]` attribute to the handler method**. The first attribute parameter specifies the protocol message type, while the second is a descriptive name for logging/debugging purposes, corresponding one-to-one with the method signature.

   ```csharp
   /// <summary>
   /// Listen for item change notifications
   /// </summary>
   /// <param name="msg"></param>
   [MessageHandler(typeof(NotifyBagInfoChanged), nameof(NotifyBagInfoChanged))]
   private void NotifyBagInfoChanged(NotifyBagInfoChanged msg)
   {
       // Handle the message body
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L29-L30)

3. **Implement `Register()` and call `ProtoMessageHandler.Add(this)` inside it**. This registers the current manager with the protocol dispatcher; during the framework's reflection scan, all methods on that instance marked with the `[MessageHandler]` attribute are read.

   ```csharp
   /// <summary>
   /// Register messages. Do not call multiple times
   /// </summary>
   public void Register()
   {
       ProtoMessageHandler.Add(this);
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L126-L129)

4. **Call `Register()` once at an appropriate time**. This is usually triggered in `Awake` or on the first `GetInstance()` call, for example:

   ```csharp
   private void Awake()
   {
       Register();
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L120)

## Common Variants

- **One manager handling multiple protocols**: Apply a separate `[MessageHandler(typeof(DifferentMessage), nameof(DifferentMessage))]` to each method; `ProtoMessageHandler.Add(this)` only needs to be called once to register all of them. `PlayerAttributeManager` handling both `NotifyPlayerAttributeSync` and `NotifyPlayerAttributeChanged` is an example of this usage. ([PlayerAttributeManager.cs#L79](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L79), [PlayerAttributeManager.cs#L109](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L109))

- **Different managers handling different protocols**: Each manager implements `IMessageHandler` and calls its own `Register()` independently, without interfering with one another. For example, `RoomDataManager` handles `NotifyRoomChanged`, and `RockPaperScissorsDataManager` handles rock-paper-scissors related protocols. ([RoomDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RoomDataManager.cs#L16), [RockPaperScissorsDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RockPaperScissorsDataManager.cs#L16))

## Common Mistakes

- **Forgetting to call `ProtoMessageHandler.Add(this)` inside `Register()`**: The attribute is just metadata and does not take effect automatically; messages will arrive but no method will be invoked.
- **Calling `Register()` repeatedly**: The comment explicitly states "Do not call multiple times"; registering the same instance multiple times causes duplicate dispatching.
- **Method signature not matching the message type in the attribute**: The `X` in `[MessageHandler(typeof(X), ...)]` must exactly match the method's parameter type; otherwise the reflection binding fails.
- **Putting `Register()` in the constructor**: When `GameFrameworkSingleton` is constructed, other subsystems may not be fully initialized yet; it is recommended to call it in `Awake` or explicitly via `GetInstance().Register()`.

## Background (Optional)

`[MessageHandler]` is a reflection-based protocol routing marker. After receiving a protocol packet, the framework performs a table lookup and dispatches across the set of instances registered via `ProtoMessageHandler.Add(this)`. This is why each handler only needs a single instance, and also why it inherits `GameFrameworkSingleton`.
