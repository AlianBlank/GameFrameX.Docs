# MVVM Binding and Automatic Event Cleanup

When using `BindableProperty<T>` for data binding in FairyGUI UIs, you only need to call a single extension method, `ClearWithGObjectDestroyed`, to hook event cleanup onto the `GObject`'s `onRemovedFromStage` — when the GObject leaves the display list (including destruction), `bindableProperty.Clear` is executed automatically, so you no longer need to hand-write unsubscription logic, avoiding leftover events and memory leaks.

## Prerequisites

- The `com.gameframex.unity.fairygui` package is installed (see the README dependency table: `com.gameframex.unity` 1.1.1, `com.gameframex.unity.ui` 1.0.0, etc.).
- `BindableProperty<T>` comes from the GameFrameX core package with the namespace `GameFrameX.Runtime`; the extension method itself lives in `GameFrameX.UI.FairyGUI.Runtime`.
- The UI class inherits from `FUI` (which exposes the `GObject` property, see [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L43-L53)).

## Steps

1. Create bindable properties in your UI/logic classes, such as `BindableProperty<int>`, `BindableProperty<string>`, etc., and subscribe to their events to complete the data binding.

2. Once you have the `GObject` whose lifecycle matches the UI's, call the extension method to register automatic cleanup:

```csharp
// Automatically unregister events when the GObject is destroyed
myProperty.ClearWithGObjectDestroyed(gObject);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L123-L128)

3. Afterwards, simply close/destroy the UI as usual — no need to manually unsubscribe from the bindable property's events.

The full implementation of the extension method is as follows (the entire mechanism is just a one-line registration):

```csharp
[UnityEngine.Scripting.Preserve]
public static void ClearWithGObjectDestroyed<T>(this BindableProperty<T> bindableProperty, GObject gObject)
{
    gObject.onRemovedFromStage.Add(bindableProperty.Clear);
}
```

Source: [BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L52-L56)

## Common Variants

- **Binding in FUI subclasses**: UIs inheriting from `FUI` can directly use their own `GObject` as the lifecycle anchor, e.g. call `myProperty.ClearWithGObjectDestroyed(GObject);` where bindings are initialized; the events are then cleared when the UI is destroyed.
- **Works with any generic type**: The method is a generic extension, so any `T` — `BindableProperty<int>`, `BindableProperty<string>`, etc. — can call it directly; there is no need to write separate cleanup code for each type.

## Common Errors

| Symptom | Cause | How to Avoid |
|------|------|----------|
| Bound events still fire after the UI is destroyed and objects cannot be collected | Forgot to call `ClearWithGObjectDestroyed`; subscriptions remain on the bindable property | After every subscription to a bindable property's events, immediately call this extension method once with the same GObject |
| `NullReferenceException` | The passed-in `gObject` is null (the call happens before the UI has created its GObject) | Make sure to call it only after the GObject has finished initializing; the implementation of `FUI.Visible` also shows that `GObject` may be null ([FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L135-L149)) |
| Events get cleared while the object "doesn't appear to be destroyed yet" | The trigger hook is `onRemovedFromStage` (leaving the display list), not just destruction; any operation that removes the object from the display list will trigger `Clear` | If you dynamically remove the GObject from the display list and reuse it later, re-bind after adding it back to the display list and call this method again |

## Verification

- After closing the UI, change the bindable property's value and confirm that no UI callbacks fire anymore.
- Compare with a memory profiler (e.g. Unity Memory Profiler) before and after `Clear` takes effect to confirm that UI-related objects can be collected.

## Background

This mechanism is deliberately minimal: it leverages the FairyGUI `GObject.onRemovedFromStage` event and registers `BindableProperty.Clear` as its callback ([BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L55)). The bindable property itself belongs to the GameFrameX core package (namespace `GameFrameX.Runtime`); the UI layer only establishes the "destroy means cleanup" relationship between it and the GObject lifecycle. The method is marked with `[UnityEngine.Scripting.Preserve]` to prevent removal by code stripping.
