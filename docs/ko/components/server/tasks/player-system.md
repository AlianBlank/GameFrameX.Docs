# 플레이어 기본 정보 구현(Player 엔티티와 로그인)

이 페이지의 작업을 완료하면 클라이언트가 캐릭터 ID 기반으로 로그인할 수 있으며, 서버는 로그인 시 플레이어 속성을 초기화하고 온라인 목록에 추가한 후, 속성 스냅샷과 플레이어 정보를 클라이언트에 반환합니다.

## 사전 조건

- `LoginComponentAgent`와 로그인 체인이 이미 존재함(계정 검증 통과, `playerState.Id` 획득).
- `PlayerComponent`가 `[ComponentType(GlobalConst.ActorTypePlayer)]`를 통해 플레이어 Actor에 등록되어 있음.
- `PlayerAttributeComponent`가 장착되어 있음(로그인 후 읽어서 스냅샷을 푸시함).

3. 로그인 핸들러에서 `PlayerComponentAgent.OnPlayerLogin`을 호출하여 전체 로그인 플로우를 트리거:

```csharp
public async Task OnPlayerLogin(INetWorkChannel workChannel, PlayerState playerState, RespPlayerLogin response)
{
    SessionManager.UpdateSession(workChannel.GameAppSession.SessionID, playerState.Id, playerState.Id.ToString());
    response.Code = playerState.State;
    response.CreateTime = playerState.CreatedTime;
    response.PlayerInfo = new PlayerInfo
    {
        Id = playerState.Id,
        Name = playerState.Name,
        Level = playerState.Level,
        State = playerState.State,
        Avatar = playerState.Avatar,
    };

    var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
    await attributeComponentAgent.InitializeDefaultsSilent();

    var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
    await serverComp.AddOnlineRole(ActorId);

    var roomComp = await ActorManager.GetComponentAgent<RoomComponentAgent>();
    await roomComp.MarkPlayerReconnected(ActorId);

    await workChannel.WriteAsync(attributeComponentAgent.BuildSyncSnapshot());

    var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
    await mailAgent.SyncAsync();
}
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L62-L93)

{
    var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();

}

## 일반적인 변형

- 로그인 없이 캐릭터 목록만 조회: 저장소 내 `ReqPlayerListHandler`가 진입점임(`GameFrameX.Hotfix/Logic/Account/Login/ReqPlayerListHandler.cs` 참조), 로그인 전에 먼저 캐릭터를 나열하는 데 사용.
- HTTP를 통해 캐릭터 생성/목록 조회: `GameFrameX.Hotfix/Logic/Http/Player/ReqPlayerCreateHttpHandler.cs`와 `ReqPlayerListHttpHandler.cs`를 사용.
- 플레이어 강제 로그아웃: `GameFrameX.Hotfix/Logic/Http/Player/KickOffLineByUserIdPlayerHttpHandler.cs` 사용.

## 일반적인 오류

- `ReqPlayerCreateHandler`는 현재 소스 코드에서 전체가 주석 처리된 상태임([ReqPlayerCreateHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Account/Login/ReqPlayerCreateHandler.cs) 참조), 해당 클래스를 기반으로 클라이언트 프로토콜을 직접 구현하지 마세요. HTTP 핸들러를 사용하거나 `LoginComponentAgent`에서 확장하세요.
- 로그인 시 `InitializeDefaultsSilent()` 호출을 잊으면 속성 스냅샷이 초기화되지 않아 클라이언트가 기본 속성을 읽지 못할 수 있음.
- 로그아웃 처리에서 `SetAutoRecycle(true)`을 누락하면 플레이어 Actor가 장기간 남아 있어 메모리를 회수할 수 없음.

## 배경(선택)

`PlayerComponent`는 `StateComponent<PlayerState>`로 플레이어 상태를 담으며, 로그인 시 `PlayerComponentAgent.OnPlayerLogin`이 속성 초기화, 온라인 목록 추가, 방 재접속 표시, 속성 스냅샷 푸시, 메일 지연 동기화를 연결하여 로그인 후 모든 플레이어 하위 시스템 초기화의 통합 진입점 역할을 합니다.
