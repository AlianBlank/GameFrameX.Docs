# 如何非同步載入遠端圖片

使用 `IImageCacheManager.LoadImageAsync` 可以非同步載入遠端圖片:在非 WebGL 平台上會優先使用磁碟快取，未命中時會先下載再從本機載入；在 WebGL 平台上則直接透過 `UnityWebRequestTexture` 載入，由瀏覽器管理快取。

## 前置條件

- 已安裝 `com.gameframex.unity.imagecache` 套件，且場景中已掛載 `ImageCacheComponent`。
- 已安裝 `com.gameframex.unity.download` 套件(非 WebGL 平台必備，用於檔案下載)。
- 遠端圖片位址必須以 `http://` 或 `https://` 開頭。
- `ImageCacheConfig.CachePath` 已指定可寫入的本機目錄(非 WebGL 平台必備)。

## 操作步驟

1. 取得圖片快取管理器的實例。由於 `ImageCacheComponent` 已封裝生命週期，可直接從元件欄位或 `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IImageCacheManager>()` 取得。

    ```csharp
    using GameFrameX.ImageCache.Runtime;
    using UnityEngine;

    public class MyImageLoader : MonoBehaviour
    {
        [SerializeField] private ImageCacheComponent imageCacheComponent;

        private IImageCacheManager _manager;

        private void Start()
        {
            _manager = imageCacheComponent; // 元件本身實作了 IImageCacheManager
        }
    }
    ```

    來源:[ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs)

2. 呼叫 `LoadImageAsync`,並 `await` 其回傳的 `Task<Texture2D>`。此方法會自動處理磁碟快取命中、檔案下載、`Texture2D` 解碼的完整流程；載入成功時回傳 `Texture2D`,失敗時回傳 `null`。

    ```csharp
    using System.Threading;
    using System.Threading.Tasks;
    using UnityEngine;

    public async Task<Sprite> LoadHeadIconAsync(string url, CancellationToken ct)
    {
        var texture = await _manager.LoadImageAsync(url, ct);
        if (texture == null)
        {
            Debug.LogWarning($"読み込み失敗:{url}");
            return null;
        }

        var sprite = Sprite.Create(
            texture,
            new Rect(0, 0, texture.width, texture.height),
            new Vector2(0.5f, 0.5f));
        sprite.name = url;
        return sprite;
    }
    ```

    來源:[IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L18-L26)

3. 在呼叫前驗證 URL。`LoadImageAsync` 內部會對空字串或非 `http(s)://` 開頭的位址輸出警告並回傳 `null`。業務端若也事先進行防禦性驗證，可避免無意義的 `await`。

    ```csharp
    if (string.IsNullOrEmpty(url) ||
        (!url.StartsWith("http://") && !url.StartsWith("https://")))
    {
        Debug.LogWarning("URL が不正です");
        return null;
    }

    var tex = await _manager.LoadImageAsync(url);
    ```

    來源:[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

4. (選用)使用 `CancellationToken` 取消進行中的載入。僅在非 WebGL 平台有效，適合在頁面銷毀或使用者切換場景等情況下釋放未完成的載入。

    ```csharp
    private CancellationTokenSource _cts;

    public async void Reload(string url)
    {
        _cts?.Cancel();
        _cts = new CancellationTokenSource();

        var tex = await _manager.LoadImageAsync(url, _cts.Token);
        // 若元件已被銷毀,tex 可能為 null
    }
    ```

    來源:[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L122-L150)

5. 載入完成後，將 `Texture2D` 套用至 UI。可直接賦值給 `RawImage.texture`,或如步驟 2 所示包裝成 `Sprite` 後供 `Image` 使用。

    ```csharp
    [SerializeField] private UnityEngine.UI.RawImage target;

    public async Task ApplyAsync(string url)
    {
        var tex = await _manager.LoadImageAsync(url);
        if (tex != null) target.texture = tex;
    }
    ```

## 常見變化

- **預先下載與快取**：對同一 URL 多次呼叫 `await LoadImageAsync` 時，首次下載完成後檔案會以 URL 的 MD5 雜湊名稱快取到 `CachePath`,之後的呼叫會直接從磁碟載入，因此無需重新下載。可在進入場景時對一般圖片進行預熱。

    ```csharp
    // 非 WebGL 平台:IsCached 可用來判斷是否已下載
    if (_manager.IsCached(url))
    {
        Debug.Log("ローカルキャッシュにヒットしました");
    }
    ```

    來源:[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L180-L194)

- **在 WebGL 平台上載入**：「`LoadImageAsync` 在 `UNITY_WEBGL` 下會走 `UnityWebRequestTexture` 的分支，不會寫入磁碟;`IsCached` 一律回傳 `false`,`RemoveCache`/`ClearCache` 會輸出警告。業務端無需區分平台,API 的行為是一致的。

    ```csharp
    // 在 WebGL 上同樣呼叫,內部會自動走 UnityWebRequestTexture 的分支
    var tex = await _manager.LoadImageAsync(url);
    ```

    來源:[ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L91-L115)

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| `LoadImageAsync` 回傳 `null`,且日誌顯示 `url is null or empty` | URL 為空 | 呼叫前先以 `string.IsNullOrEmpty` 驗證 |
| 回傳 `null`,且日誌顯示 `url must start with http:// or https://` | URL 不是以 http(s) 開頭 | 使用完整的 URL,不要傳入本機路徑或 `file://` |
| 非 WebGL 平台下載失敗，且日誌顯示 `download failed` | `DownloadManager` 未註冊，或網路無法連通 | 確認 `GameFrameX` 的下載管理器已初始化,且事件回呼已正確註冊 |
| 以 `CancellationToken` 取消後 `Task` 仍未立即結束 | 取消邏輯僅在非 WebGL 平台生效，且只在快取讀取/檔案存在判斷之後才作用 | 取消後請自行判斷 `tex == null`,不要預期 `Task` 會擲出例外 |

## 背景(選用)

- 非 WebGL 平台:`ImageCacheManager` 以 `Utility.Hash.MD5.Hash(url)` 作為快取檔名，副檔名固定為 `.png`;首次未命中時會透過 `IDownloadManager.AddDownload` 啟動下載，並以 `TaskCompletionSource` 等待 `DownloadSuccess` / `DownloadFailure` 事件。
- WebGL 平台:啟用 `UNITY_WEBGL` 巨集時，`LoadImageAsync` 會改為 `UnityWebRequestTexture.GetTexture` + `SendWebRequest()`,快取完全交由瀏覽器的 HTTP Cache 處理，因此 `IsCached`、`RemoveCache`、`ClearCache` 全部停用。

關於元件的初始化與生命週期，請參閱《ImageCacheComponent 概覽》；關於快取設定欄位的含義，請參閱 `ImageCacheConfig`。
