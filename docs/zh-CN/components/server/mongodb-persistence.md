# 如何使用 MongoDB 持久化玩家数据

本章帮助你把 `GameFrameX.DataBase.Mongo` 接入游戏服务端，完成玩家数据的添加、查询、更新、删除与事务写入。读完本页你能直接在服务器里跑通基于 MongoDB 的玩家数据落库。

## 前置条件

- 已安装 MongoDB（本地或集群均可），并准备好形如 `mongodb://user:password@host:27017` 的连接字符串与目标数据库名。
- 服务器工程中已添加 `GameFrameX.DataBase.Mongo` 包（命名空间 `GameFrameX.DataBase.Mongo`），并可访问到 `GameFrameX.DataBase.Abstractions` 中的 `IDatabaseService`、`DbOptions`。
- 玩家数据类型必须继承自 `BaseCacheState`，MongoDB 会以 `typeof(T).Name` 作为集合名。

## 操作步骤

### 1. 创建并打开服务

`MongoDbService` 是核心入口，实现 `IDatabaseService`。通过 `Open(DbOptions)` 建立连接，内部会执行 `ping` 校验并按 `300 / 700 / 1500 ms` 退避重试 3 次，失败后自动切换到不健康状态并启动恢复任务。

```csharp
using GameFrameX.DataBase.Mongo;
using GameFrameX.DataBase.Abstractions;

var mongo = new MongoDbService();
var options = new DbOptions
{
    ConnectionString = "mongodb://localhost:27017",
    Name = "GameFrameX",
};
bool ok = await mongo.Open(options);
if (!ok) throw new InvalidOperationException("MongoDB 初始化失败");
```

配置项 `Options.ConnectionString` 与 `Options.Name` 必须同时提供，重复调用 `Open` 时若目标相同会复用现有连接并重新 `ping`，否则会重置连接。

### 2. 定义玩家数据类型

玩家数据需继承 `BaseCacheState`，框架在写入时会自动维护 `CreatedTime` 与 `UpdateTime`，集合名默认为类型名。

```csharp
using GameFrameX.DataBase.Abstractions;

public sealed class PlayerState : BaseCacheState
{
    public string Name { get; set; }
    public int Level { get; set; }
    public long Gold { get; set; }
}
```

集合来源于 `MongoDbContext.GetCollection<T>()`，返回的 `IMongoCollection<T>` 以 `typeof(T).Name` 命名。

### 3. 新增玩家数据

新增接口位于 `MongoDbService.Add.cs`，会自动填充时间戳并走带重试的写入通道：

```csharp
var player = new PlayerState { Id = "p_1001", Name = "Alice", Level = 1, Gold = 0 };
await mongo.AddAsync(player);
await mongo.AddListAsync(new[] { player, anotherPlayer }); // 批量，IsOrdered=false
```

`BulkWriteOptions` 默认 `{ IsOrdered = false }`，批量插入可并行执行。

### 4. 查询与更新

服务以 `MongodbService.Query.cs`、`MongoDbService.Update.cs` 分别承担读路径与写路径，读操作默认延迟退避为 `{120, 300, 700} ms`，幂等写为 `{150, 400, 900} ms`，事务为 `{200, 500, 1000} ms`。常见用法：

```csharp
// 单条更新
await mongo.UpdateAsync(player);

// 按 Id 判断存在，不存在则插入；存在则更新字段集合（幂等）
await mongo.AddOrUpdateAsync(player);
await mongo.AddOrUpdateListAsync(manyPlayers);
```

### 5. 软删除与事务

删除接口支持软删与硬删；多步写入可放进事务：

```csharp
await mongo.DeleteAsync(player);                 // 软删
await mongo.HardDeleteAsync(player);             // 物理删除
await mongo.RestoreAsync(player);                // 恢复软删
await mongo.ExecuteInTransactionAsync(token =>
{
    // 在此处对 collection 做多个写操作
    return Task.CompletedTask;
});
```

### 6. 健康检查与优雅关闭

模块自带 `MongoDbHealthCheck`：

```csharp
services.AddHealthChecks()
    .AddCheck<MongoDbHealthCheck>("mongodb");
```

服务关闭时调用 `await mongo.Close()` 释放连接；运行期可通过 `mongo.AvailabilityState` 读取 `Healthy / Degraded / Unhealthy` 状态。

## 常见变体

- **换数据库**：再次调用 `Open(...)` 并传入不同的 `ConnectionString` / `Name`，内部会自动重置 `MongoClient` 与 `MongoDbContext`。
- **运行时调参**：`DbOptions.RuntimeOptions` 可配合 `ApplyRuntimeOptions` 调整超时等运行参数（见 `MongoDbService.Connection.cs` 第 69-84 行）。
- **自定义集合名**：`MongoDbContext.GetCollection<T>()` 固定使用类型名，若需自定义可派生并复用 `IMongoDatabase`。
- **指标埋点**：模块使用 `System.Diagnostics.Metrics` 暴露 `db_open_retry_total`、`db_operation_latency_ms`、`db_health_status` 等指标，可接入 OpenTelemetry。

## 常见错误

- **忘写 `await mongo.Open(options)` 就调用增删改**：`EnsureInitialized()` 会抛异常，必须先 `Open` 成功。
- **`ConnectionString` 或 `Name` 为空**：`Open` 会抛 `ArgumentNullException`，启动时即崩溃。
- **玩家类型未继承 `BaseCacheState`**：泛型约束 `where TState : BaseCacheState` 会在编译期拦截。
- **事务里跑非事务操作**：`ExecuteInTransactionAsync` 要求 MongoDB 部署为副本集/分片集群，单机 `mongod` 会失败。
- **忽略失败状态**：`Open` 失败会把服务置为 `Unhealthy` 并启动后台恢复任务，应同时检查 `AvailabilityState` 与日志 `MongoDbService.Open Exception`。

## 背景（可选）

`MongoDbService` 是 `sealed partial class`，按职责拆为 `Add / Update / Delete / Query / Collection / Connection / Index / Retry / Recovery / UpsertTransaction / Availability` 等分文件实现；可用性通过私有计数器与白名单（`NonCriticalReadOperationWhiteList`、`CoreWriteOperationWhiteList`）决定读写降级策略，并通过 `System.Threading.Volatile` 暴露可观测指标。
