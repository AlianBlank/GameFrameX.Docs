# 如何在 Startup 流程中接入自定义 Procedure

在 `ApplicationStartupEntry` 调用 `StartupRunner.Run` 时,框架会按 `startupOptions.ProcedureSettings` 中配置的顺序依次执行每一个 Procedure。本页演示如何新增一个自定义 Procedure 并接入这条启动链路。

## 前置条件

- 已存在 `Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs` 启动入口。
- 项目中已引入 `GameFrameX.Startup.Runtime`(提供 `StartupRunner`、`ProcedureBase`、`IStartupUIHandler`)。
- `startupOptions` 资产已挂到 `ApplicationStartupEntry` 的检视面板。

## 操作步骤

1. **新建自定义 Procedure 类**,继承 `ProcedureBase`,并实现 `OnEnter` / `OnLeave`(视情况重写 `OnUpdate`)。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   namespace GameFrameX.Startup.Application
   {
       /// <summary>
       /// 自定义启动流程:登录远端账号服务,加载玩家基础数据。
       /// </summary>
       public sealed class ProcedureLogin : ProcedureBase
       {
           protected override async UniTask OnEnter(ProcedureContext context)
           {
               // 进入流程:这里写你希望在启动时执行的逻辑
               await LoginRemoteServiceAsync();
           }

           protected override UniTask OnLeave(ProcedureContext context)
           {
               // 离开流程:清理资源或状态
               return UniTask.CompletedTask;
           }

           private UniTask LoginRemoteServiceAsync()
           {
               // 由业务侧实现
               return UniTask.CompletedTask;
           }
       }
   }
   ```

   Source: [ApplicationStartupUIHandler.cs](Assets/Scripts/Framework/Procedure/ApplicationStartupUIHandler.cs#L1-L87)

2. **把 Procedure 注册到 `StartupOptions`**。在 `startupOptions.ProcedureSettings` 列表中按执行顺序添加 `ProcedureLogin`(类名或类型标识需与框架约定一致,通常直接是 `Type` 或资源键)。

3. **(可选)自定义启动 UI**。如果需要在启动过程中刷新 UI 提示,实现 `IStartupUIHandler` 并在入口处传入:

   ```csharp
   var result = await StartupRunner.Run(
       startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   `IStartupUIHandler` 必须实现的成员:`StartAsync(uiResName)`、`SetTipText(text)`、`SetProgress(progress, sizeInfo)`、`SetProgressUpdateFinish()`、`ShowUpgradeAsync(upgradeInfo)`、`Dispose()`。

   Source: [ApplicationStartupEntry.cs](Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L14-L55)

4. **处理失败回执**。`StartupRunner.Run` 返回 `StartupResult`,通过 `Success`、`FailedProcedureName`、`FailedUrl`、`ErrorMessage` 字段判断哪个 Procedure 失败并写入日志:

   ```csharp
   if (!result.Success)
   {
       Log.Error($"Startup failed. Procedure: {result.FailedProcedureName}, Url: {result.FailedUrl}, Error: {result.ErrorMessage}");
   }
   ```

   Source: [ApplicationStartupEntry.cs](Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L45-L48)

## 常见变体

| 场景 | 做法 |
|------|------|
| 只想加日志或埋点 | 重写 `OnEnter` / `OnLeave`,内部只调用 `Log.Info`,不做 IO。 |
| 需要异步等待网络结果 | 在 `OnEnter` 返回 `UniTask`,内部 `await` 你的网络/资源加载方法。 |
| 启动 UI 用 FairyGUI / UGUI | 框架已通过 `ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI` 自动切换 `LauncherUIResName`,无需在 Procedure 里处理。 |

## 常见错误

- **`startupOptions` 未赋值**:启动入口会在 `Log.Error("StartupOptions is not assigned.")` 后直接返回,Procedure 全部不会执行。
- **忘记实现 `OnLeave`**:若 `OnEnter` 进入了某种"启动中"状态,后续流程可能拿不到正确的上下文;至少返回 `UniTask.CompletedTask`。
- **Procedure 顺序错乱**:把登录/资源校验放到热更新之前,会导致热更新失败时拿不到玩家上下文;按"初始化 → 热更新 → 业务校验 → 进入主场景"的顺序排列。

## 背景(可选)

`StartupRunner.Run` 是框架启动链路的统一入口,接收 `StartupOptions`、UI 处理器、热修复启动器三部分;`startupOptions.ProcedureSettings` 决定了 Procedure 链的拓扑与执行顺序,所以接入工作实际上是声明式配置,而不是改 `StartupRunner` 内部代码。
