# Proto 메시지를 정의하고 인코딩/디코딩에 연결하는 방법

메시지 클래스에 특성(Attribute) 마커를 추가하고 `INetworkMessage` 인터페이스를 구현하면, 사용자 정의 메시지를 프레임워크의 ProtoBuf 직렬화 및 ID 라우팅 체계에 연결하여 송수신 양단에서 메시지 인코딩/디코딩을 구현할 수 있습니다.

## 사전 조건

- 프로젝트가 `GameFrameX.ProtoBuf.Net`(ProtoBuf의 `Serializer.Serialize` / `Deserialize` / `Merge` 래핑)을 참조해야 합니다.
- 프로젝트가 메시지 ID 등록 및 하트비트/요청/응답 분류를 위해 `GameFrameX.NetWork.Abstractions`를 참조해야 합니다.
- 시작 단계에서 어셈블리가 `MessageProtoHelper.Init(assemblies)`를 한 번 호출하여 특성이 스캔되고 사전에 기록되도록 해야 합니다.

## 작업 단계

### 1. 메시지 타입 정의

메시지 클래스는 `INetworkMessage` 인터페이스를 구현해야 하며, `MessageTypeHandlerAttribute`를 통해 전역적으로 고유한 `MessageId`와 `OperationType`을 등록해야 합니다. 비즈니스 의미에 따라 `IRequestMessage`, `IResponseMessage`, `INotifyMessage`, `IHeartBeatMessage`를 선택적으로 구현할 수 있습니다.

```csharp
using GameFrameX.NetWork.Abstractions;
using GameFrameX.NetWork.Abstractions.Interface;

[MessageTypeHandler(1001, (byte)MessageOperationType.Request)]
public sealed class LoginRequest : INetworkMessage, IRequestMessage
{
    public string UserName { get; set; }
    public string Password { get; set; }
}

[MessageTypeHandler(1002, (byte)MessageOperationType.Response)]
public sealed class LoginResponse : INetworkMessage, IResponseMessage
{
    public int Code { get; set; }
    public string Token { get; set; }
}

[MessageTypeHandler(9999, (byte)MessageOperationType.Notify)]
public sealed class HeartBeat : INetworkMessage, IHeartBeatMessage
{
    public long Timestamp { get; set; }
}
```

`MessageTypeHandlerAttribute`는 `MessageId`와 `OperationType`을 가지고 있으며, 등록 단계에서 이들을 사용하여 `MessageProtoHelper` 내부의 사전을 채웁니다.

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L218-L254)

### 2. 시작 시 메시지 매핑 초기화

애플리케이션 시작 시, 메시지 클래스가 포함된 어셈블리를 `MessageProtoHelper.Init`에 전달하면, `MessageTypeHandlerAttribute`가 표시된 모든 타입을 스캔하여 ID별로 `AllMessageDictionary`, `RequestDictionary`, `ResponseDictionary`, `HeartBeatList`, `OperationType`에 등록합니다. ID가 중복되면 `ArgumentAlreadyException`이 발생합니다.

```csharp
using System.Reflection;
using GameFrameX.NetWork.Abstractions;

MessageProtoHelper.Init(
    Assembly.GetExecutingAssembly(),
    typeof(LoginRequest).Assembly
);
```

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L187-L208)

### 3. ProtoBuf 직렬화 및 역직렬화 사용

`GameFrameX.ProtoBuf.Net.ProtoBufSerializerHelper`는 ProtoBuf의 `Serializer.Serialize` / `Deserialize` / `Merge`를 래핑하며, 메시지 본문의 바이트 스트림 인코딩/디코딩에 직접 사용할 수 있습니다.

```csharp
using GameFrameX.ProtoBuf.Net;

// 직렬화(객체 -> 바이트 배열)
byte[] payload = ProtoBufSerializerHelper.Serialize(loginRequest);

// 역직렬화(바이트 배열 -> 객체)
var message = ProtoBufSerializerHelper.Deserialize<LoginRequest>(payload);

// 병합 모드: 바이트 스트림을 기존 인스턴스에 병합하여 새 객체 할당을 피함
var merged = ProtoBufSerializerHelper.Deserialize(payload, existingInstance);
```

병합 모드는 증분 업데이트 시나리오에 적합하며, 빈 바이트 배열은 예외를 발생시키지 않고 원래 인스턴스를 그대로 반환합니다.

Source: [ProtoBufSerializerHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.ProtoBuf.Net/ProtoBufSerializerHelper.cs#L17-L82)

### 4. 송수신 흐름에서 메시지 타입 조회

네트워크 계층이 바이트 스트림을 수신한 후, 먼저 `MessageId`로 타입을 조회한 다음 `ProtoBufSerializerHelper`로 역직렬화할 수 있습니다:

```csharp
int messageId = ReadMessageId(buffer);
Type messageType = MessageProtoHelper.GetMessageTypeById(messageId);
if (messageType != null)
{
    object message = ProtoBufSerializerHelper.Deserialize(buffer, messageType);
    // 처리 로직으로 디스패치...
}
```

반대 방향으로 전송할 때는, 먼저 `MessageProtoHelper.SetMessageId(message)`로 `MessageId`를 객체에 다시 기록한 후 직렬화를 진행합니다.

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L60-L149)

## 일반적인 변형

| 시나리오 | 작성 방법 | 설명 |
|------|------|------|
| 하트비트 메시지 | `IHeartBeatMessage` 구현 | 자동으로 `HeartBeatList`에 추가되며, `GetMessageOperationType`이 `HeartBeat`를 직접 반환 |
| 요청/응답 페어링 | `IRequestMessage`와 `IResponseMessage`를 각각 구현 | 각각 `RequestDictionary` / `ResponseDictionary`에 등록되어 RPC 페어링에 편리 |
| 증분 업데이트 | `Deserialize<T>(byte[] data, T instance)` | `Serializer.Merge`를 사용하며, 인스턴스를 재사용하여 GC 감소 |
| 열거형 필드 | `ProtoEnumAttribute` 사용 | `GameFrameX.ProtoBuf.Net`에서 제공하며, 소스 코드 디렉토리 참조 |

## 일반적인 오류

| 증상 | 원인 | 수정 방법 |
|------|------|------|
| 시작 시 `ArgumentAlreadyException(... MessageIdDuplicate ...)` 발생 | 두 클래스가 동일한 `MessageId`를 공유함 | `MessageTypeHandler`의 첫 번째 매개변수를 수정하여 전역적으로 고유하게 보장 |
| `GetMessageTypeById`가 `null` 반환 | 해당 ID로 `Init`가 호출되지 않았거나 등록되지 않음 | 시작 단계에서 `MessageProtoHelper.Init(assembly)`를 호출하고 메시지 클래스가 해당 어셈블리에 컴파일되었는지 확인 |
| `ProtoBufSerializerHelper.Serialize`가 예외 발생 | 필드에 ProtoBuf `[ProtoMember]` / `[ProtoContract]` 등의 특성이 없음 | 메시지 클래스가 ProtoBuf 직렬화 특성을 올바르게 선언했는지 확인(`GameFrameX.ProtoBuf.Net`에서는 `ProtoContractAttribute`, `ProtoIncludeAttribute` 등에 해당) |
| 하트비트가 일반 메시지로 처리됨 | `IHeartBeatMessage`를 구현하지 않음 | 하트비트 클래스가 해당 인터페이스를 구현하도록 하면, `Init` 단계에서 자동으로 하트비트 테이블에 추가됨 |

## 배경(선택 사항)

프레임워크는 "메시지 ID↔타입" 매핑(`MessageProtoHelper`)과 "객체↔바이트" 매핑(`ProtoBufSerializerHelper`)을 분리(decoupling)합니다: 전자는 ID로 올바른 .NET 타입을 찾고 요청/응답/알림/하트비트를 구분하는 역할을 하고, 후자는 ProtoBuf 형식의 바이너리 읽기/쓰기를 담당합니다. `GameFrameX.Proto/MessageProtoHandler`는 네임스페이스 자리 표시자 역할을 하며, 실제 인코딩/디코딩 진입점은 `ProtoBufSerializerHelper`입니다. 전송 계층(TCP/KCP)이 이러한 바이트를 어떻게 캡슐화하는지에 대해서는 네트워크 계층 관련 문서를 참조하십시오.
