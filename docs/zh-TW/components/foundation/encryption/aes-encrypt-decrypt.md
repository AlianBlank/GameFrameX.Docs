# AES 加密/解密的使用方式

`AesHelper` 提供基於 AES-GCM 的帶驗證加密/解密功能。只需傳入明文與金鑰即可取得 Base64 密文，使用相同金鑰解密即可還原為原始明文。由於每次加密都會隨機產生 Salt 與 Nonce，呼叫端無需自行管理。

## 前置條件

- 專案需參考 NuGet 套件 `GameFrameX.Foundation.Encryption`。
- 目標 Framework 需支援 `System.Security.Cryptography.AesGcm`（.NET 5+ / .NET Standard 2.1 平台實作）。
- `using GameFrameX.Foundation.Encryption;` 與 `using System.Text;`。

## 操作步驟

### 1. 字串的加密/解密（Base64 輸出）

```csharp
using GameFrameX.Foundation.Encryption;

string plain = "Hello, World! 这是一个测试字符串。";
string key = "MySecretKey123456";

string cipher = AesHelper.Encrypt(plain, key);
string back = AesHelper.Decrypt(cipher, key);
// back == plain
```

### 2. 位元組陣列的加密/解密（適用於二進位資料）

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

byte[] data = Encoding.UTF8.GetBytes("任意二进制数据");
byte[] cipherBytes = AesHelper.Encrypt(data, "MySecretKey123456");
byte[] plainBytes = AesHelper.Decrypt(cipherBytes, "MySecretKey123456");
```

Source: [AesHelper.cs#L140-L178](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/AesHelper.cs#L140-L178)

### 3. 加密/解密後進行磁碟儲存或傳輸

將 `cipher`（Base64 字串）或 `cipherBytes`（二進位）儲存至資料庫、設定檔，或透過網路傳送。接收端使用相同金鑰呼叫 `Decrypt`，即可還原為原始資料。

```csharp
// 偽代碼：將密文儲存到檔案
File.WriteAllText("secret.bin", cipher);

// 偽代碼：讀取並解密
string read = File.ReadAllText("secret.bin");
string original = AesHelper.Decrypt(read, key);
```

## 常見變化

- **不同長度的金鑰**：原始碼使用 PBKDF2(SHA256, 600,000 次) 將任意字串金鑰衍生為 32 位元組的金鑰，因此從 `"ShortKey"` 到 `"VeryLongKeyThatExceedsNormalLength123456789"`，全部都能正確地加密/解密。
- **包含 Unicode/Emoji 的明文**：明文會先以 UTF-8 編碼後再加密，因此 `"🚀🌟💻🎮🔥"` 等 4 位元組字元也能正常往返。
- **相同明文 + 相同金鑰加密 2 次**：由於 Salt/Nonce 為隨機產生，兩次結果會不同，但兩者皆可解密還原為原始明文 — 這是 AES-GCM 的語義安全性特性。

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|----------|
| `ArgumentException: Plain text cannot be null or empty` | 明文為 `null` 或 `""` | 加密前確認字串不為空 |
| `ArgumentException: Encryption key cannot be null or empty` | 金鑰為空 | 提供長度 ≥ 1 的非空字串金鑰 |
| `ArgumentException: Cipher text byte array is too short to be valid.` | 密文長度小於 45 位元組（1+16+12+16 標頭） | 確認傳入的是 `Encrypt` 的完整輸出 |
| `CryptographicException: Unsupported AES payload format version.` | 密文標頭的版本 Byte 不為 `2` | 升級至目前版本的程式庫，或使用舊版本解密 |
| `CryptographicException`（解密時） | 金鑰與加密時不同，或資料遭到竄改 | 確認加密與解密使用相同金鑰，並驗證傳輸的完整性 |

> 在加密/解密的呼叫中，若有任一參數為 `null` / 空字串，將立即拋出 `ArgumentException`。可在呼叫前進行斷言，或在外層以 `try/catch` 處理。

## 背景（選用）

實作採用 AES-GCM 帶驗證加密：使用每次隨機產生的 16 位元組 Salt 與 12 位元組 Nonce，搭配以 PBKDF2(SHA256, 600k 次) 衍生的 32 位元組工作階段金鑰。輸出格式為 `Version(1) | Salt(16) | Nonce(12) | Tag(16) | 密文`，Tag 用於完整性驗證。竄改或金鑰錯誤會在解密階段以 `CryptographicException` 拋出。
