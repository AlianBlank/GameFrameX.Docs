# How to Integrate the TrackId Middleware in ASP.NET

After integrating the `TrackIdMiddleware` provided by `GameFrameX.Foundation.Http.Normalization`, every HTTP request receives a `TrackId` that spans the entire call chain: it is written to the `X-Track-Id` response header, passed back into the `TrackIdContext` async context, and pushed into Serilog's `LogContext`, so that trace logs naturally carry the same TrackId property.

## Prerequisites

- An ASP.NET Core 6.0 or above project
- The NuGet package `GameFrameX.Foundation.Http.Normalization` must be referenced; the project also needs `Serilog` for the log context (the middleware uses `Serilog.Context.LogContext.PushProperty`)

## Steps

1. In the pipeline setup in `Program.cs`, call `UseTrackId` at the very front, ensuring it runs before the unified result wrapper and business middleware:

```csharp
using GameFrameX.Foundation.Http.Normalization;

var builder = WebApplication.CreateBuilder(args);

// Register Serilog
builder.Host.UseSerilog((ctx, lc) => lc.ReadFrom.Configuration(ctx.Configuration));

var app = builder.Build();

// Enable the TrackId middleware at the very front of the pipeline
app.UseTrackId();

app.UseSerilogRequestLogging();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

app.Run();
```

Source: [TrackIdMiddlewareExtensions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/TrackIdMiddlewareExtensions.cs#L44-L57)

2. The middleware does four things in `InvokeAsync`: resolves or generates a TrackId, writes it to the async context, writes back the response header, and pushes it into the log context:

```csharp
public async Task InvokeAsync(HttpContext context)
{
    var trackId = ResolveTrackId(context.Request.Headers[HeaderName]);
    TrackIdContext.Set(trackId);
    context.Response.Headers[HeaderName] = trackId;

    using (LogContext.PushProperty(LogContextTrackIdProperty, trackId))
    {
        await _next(context);
    }
}
```

Source: [TrackIdMiddleware.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/TrackIdMiddleware.cs#L89-L99)

3. Read the current TrackId in business code or in the unified result wrapper (for backfilling the response body, propagating across services, etc.):

```csharp
using GameFrameX.Foundation.Http.Normalization;

var id = TrackIdContext.Current;          // Returns null when not set
if (id is not null)
{
    result.TrackId = id;
}
```

## Key Constants and Default Behavior

| Name | Value/Rule | Source |
|------|---------|------|
| Response/request header name | `X-Track-Id` (the `HeaderName` constant) | `TrackIdMiddleware.HeaderName` |

## Common Variants

- **Force generating a new TrackId, ignoring the upstream header**: append a middleware after `UseTrackId` that clears the `X-Track-Id` header before the rest of the pipeline handles it (or use a custom middleware subclass that overrides `ResolveTrackId`).
- **Manually generate a TrackId**: call `TrackIdContext.Generate()` anywhere in the call chain; this method only generates a value and does not write it into the current context.
- **Read the TrackId in a custom middleware**: simply get it via `TrackIdContext.Current`, with no need to depend directly on `HttpContext.Items`.

## Common Mistakes

- **`UseTrackId` registered after business middleware**: downstream middleware may read `TrackIdContext.Current` as `null`, and the response headers may already have been sent, making backfilling impossible. Always place it at the very front of the pipeline.
- **Project does not reference Serilog**: `LogContext.PushProperty` comes from the `Serilog.Context` namespace; a missing reference will cause a compilation failure.
- **Expecting `TrackIdContext` to persist across processes**: it is based on `AsyncLocal` and is only shared within the async call chain of a single request; it does not propagate across requests or services. For cross-service propagation, pass it via the `X-Track-Id` response header.

## Background (Optional)

`TrackIdMiddleware` brings "pass-through / generation / log instrumentation / response backfill" together at a single pipeline entry point, eliminating the boilerplate code that each business layer would otherwise need to parse trace identifiers on its own; meanwhile, `TrackIdContext` uses `AsyncLocal<string>` to guarantee that `await` continuations read a consistent value, with the unified result wrapper and Serilog sharing the same storage.
