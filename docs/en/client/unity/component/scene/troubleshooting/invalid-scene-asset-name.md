# What to Do When a Scene Asset Name Is Invalid

When calling `LoadScene(string sceneAssetName, ...)`, if the asset name (path) passed in cannot be found in the YooAsset manifest, scene loading will fail directly. Common symptoms include the `LoadSceneFailure` event being triggered, the `Task` returned by `await` throwing an exception, or the editor log reporting "资源不存在 / asset not found".

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `LoadSceneFailure` event triggered, `SceneAssetName` is your passed-in string | YooAsset manifest does not contain this `sceneAssetName` | Retry with the correct "asset name / asset path", and confirm it has been registered in the build output |
| Error reports `sceneAssetName` as empty or null | Path was not properly concatenated before calling, or an empty string was read from the config table | Perform null/empty validation before calling, and use the complete `Assets/...` path from the config table |
| Async `Task` throws `OperationCanceledException` or never returns | The same asset name is already in `m_LoadingSceneAssetNames`, and duplicate load was ignored | Call `UnloadScene` first or wait for the previous one to complete, avoiding concurrent duplicate loads |
| Works in editor but scene not found after build | The scene was not packaged into the YooAsset bundle, or the bundle name does not match the load path | Add the scene file to the YooAsset collector and rebuild the bundle |

## Fix Steps

### 1. Validate the asset name is non-empty and matches the manifest

`LoadScene` internally uses `sceneAssetName` as the key for YooAsset scene queries, so the string must exactly match the asset path generated by the YooAsset collector (usually `Assets/Scenes/xxx.unity`).

```csharp
// Recommended: Validate before calling
if (string.IsNullOrWhiteSpace(sceneAssetName))
{
    GameFrameworkLog.Error("[Scene] sceneAssetName cannot be empty");
    return;
}
var handle = await GameEntry.Scene.LoadScene(sceneAssetName,
    UnityEngine.SceneManagement.LoadSceneMode.Single);
```

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L337-L348) exposes four `LoadScene` overloads with signatures `(string)`, `(string, LoadSceneMode)`, `(string, object)`, and `(string, LoadSceneMode, object)`. All overloads require a valid `sceneAssetName`.

### 2. Listen to the failure event to identify the actual asset name

Subscribe to the `LoadSceneFailure` event to retrieve the actual `SceneAssetName` that was attempted at runtime from the event arguments:

```csharp
GameEntry.Scene.LoadSceneFailure += (sender, e) =>
{
    Debug.LogError($"Scene load failed: {e.SceneAssetName}, Error: {e.ErrorMessage}");
};
```

The event source is in [LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs). Compare the `SceneAssetName` printed in the log with the YooAsset manifest (`AssetBundle` / `AssetPackage` list) — this usually immediately pinpoints spelling or casing errors.

### 3. Confirm YooAsset has collected and built the scene

For a scene to be loadable, two conditions must be met:

1. The `.unity` file is included in the YooAsset collector rules;
2. The YooAsset build process (build/local build) has been re-executed, and the latest bundle output is used in Run Mode.

If it only works in the Unity editor but fails after build, this step is almost always the cause.

### 4. Avoid concurrent loads with the same asset name

`GameSceneManager` internally uses `m_LoadingSceneAssetNames` to track assets being loaded. Repeated `LoadScene` calls with the same `sceneAssetName` will not get a new `Task`, appearing as "invalid". The solution is to let each load logic exclusively use an asset name, or wait for the `Task` returned by the previous `LoadScene` to complete before initiating the next one.

The complete implementation in [GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L371) is in the four-parameter overload, where you can see it stores `SceneHandle` and `UserData` in `m_LoadingSceneAssetNames`, and only removes them upon success or failure callbacks.

## Verification

Run a comparison with a scene that loads normally:

1. Call `LoadScene` with a known-existing scene (e.g. `Assets/Scenes/Init.unity`) and confirm the `LoadSceneSuccess` event is triggered;
2. Intentionally change `sceneAssetName` to a non-existent string, confirm `LoadSceneFailure` is triggered and the log outputs the actual attempted asset name;
3. Correct the non-existent string back to the proper path, call `LoadScene` again, and confirm success.

If steps 1 and 3 both succeed while the failure event in the intermediate step triggers as expected, it indicates that the "invalid scene asset name" issue has been identified as a string/path problem, rather than an issue with how the framework's API is being called.
