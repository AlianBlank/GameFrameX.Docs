# 역직렬화 시 필드가 누락되거나 비어 있는 경우怎么办

`JsonMapper.ToObject<T>`를 호출한 후, 대상 타입의 일부 필드 값이 `null`, `0`, 빈 문자열 또는 기본값인 경우, 이는 보통 필드 매핑 규칙 또는 JSON 텍스트 자체가 일치하지 않아서 발생합니다. 이 페이지에서는 일반적인 원인과 해당 수정 방법을 제공합니다.

## 수정 단계

### 필드명 대소문자 불일치

LitJson은 JSON 키와 C# 멤버를 매칭할 때 기본적으로 대소문자를 구분하지 않는 방식으로 읽습니다. 하지만 JSON 필드명과 C# 필드명의 철자가 완전히 일치하지 않는 경우(예: `userId` vs `UserId`, 또는 철자 오류), 해당 필드는 기록되지 않습니다.

수정 방법: JSON의 키와 C#의 속성명 철자가 일치하는지 확인합니다. JSON을 수정할 수 없는 경우, 사용자 정의 exporter/importer 매핑을 사용하거나 `JsonData`를 사용하여 키 이름으로 직접 값을 가져옵니다.

### 비공개 필드가 기록되지 않음

LitJson은 기본적으로 공개 인스턴스 속성/필드만 읽습니다. 데이터 타입의 필드가 `private`, `internal`로 선언되어 있거나, 속성에 `private set`만 있는 경우 역직렬화기는 이를 무시하고 타입의 기본값을 유지합니다.

수정 방법: 역직렬화가 필요한 필드/속성을 `public`으로 변경하거나, `public` 접근자를 제공합니다.

```csharp
public class PlayerData
{
    // 반드시 public이어야 합니다. 그렇지 않으면 ToObject<PlayerData>가 기록하지 않습니다.
    public int id;
    public string name;
}
```

### 컨테이너 타입 불일치

LitJson은 배열/객체를 강 타입으로 역직렬화할 때, 대상 타입이 `IList<T>` / `IDictionary<TKey, TValue>`과 같은 제네릭 인터페이스를 구현하거나, `RegisterImporter`로 등록된 타입 매핑과 일치해야 합니다. 필드 타입이 일반 클래스(예: 사용자 정의 `MyList`)인 경우, JSON 배열은 건너뛰어지고 해당 필드는 비어 있는 상태로 유지됩니다.

수정 방법: 필드 타입을 `List<T>`, `Dictionary<string, T>` 등 내장 컨테이너로 변경하거나, 사용자 정의 컨테이너에서 해당 인터페이스를 구현하고 `RegisterImporter`를 통해 등록합니다.

### JSON 텍스트 자체에 따옴표가 있거나 없는 경우

일반적인 오류: 숫자를 문자열로 작성했거나(예: `"score": "100"`), 문자열을 따옴표 없는 리터럴로 작성한 경우(예: `"name": foo`). LitJson은 자동으로 변환하지 않으며, 이러한 필드는 조용히 무시되거나 `JsonException`이 발생합니다.

수정 방법: 임의의 JSON 온라인 검증 도구를 사용하여 텍스트의 유효성을 확인합니다. 숫자에는 따옴표를 추가하지 말고, 문자열에는 반드시 큰따옴표를, 필드명에도 반드시 큰따옴표를 추가합니다.

### JSON 텍스트가 잘못됨

일반적인 원인: 파일 읽기가 불완전함(네트워크 잘림, 바이트 순서 오류, BOM 미처리), 쉼표가 불필요하게 추가됨, 작은따옴표 문자열. JSON 파싱이 중간에 실패하면 일부 필드가 아예 읽히지 않을 수 있지만, `ToObject<T>`는 "부분 성공"하지 않고 직접 예외를 던집니다.

수정 방법: `ToObject<T>`를 호출하기 전에 `JsonReader`를 사용하여 단계별로 시작과 끝을 확인합니다. 입력이 UTF-8 문자열이며 BOM이 제거되었는지 확인합니다.

### `JsonData`와 강 타입 혼용

`JsonMapper.ToObject(string)`(제네릭 없음)은 "당신이 생각하는" 특정 클래스가 아닌 `JsonData`를 반환합니다. `JsonData`는 문자열 키를 통해 접근합니다(예: `data["name"]`). 직접 `data.name`으로 접근하면 기대하는 값을 얻을 수 없습니다.

수정 방법: `ToObject<T>`(강 타입) 또는 `ToObject()`(`JsonData` 반환)을 명확하게 사용하고, 혼용하지 마십시오.

```csharp
// 강 타입
PlayerData p = JsonMapper.ToObject<PlayerData>(json);

// 약 타입
JsonData d = JsonMapper.ToObject(json);
string name = (string)d["name"];
```

## 검증

1. `JsonMapper.ToObject(json)`(`JsonData` 반환)을 사용하여 전체 트리를 출력하고, JSON 텍스트에 예상한 키가 있는지 확인합니다.
2. 그런 다음 `JsonMapper.ToObject<T>(json)`을 사용하여 대상 타입으로 역직렬화하고 필드별로 비교합니다.
3. 여전히 필드를 찾을 수 없는 경우, 임시로 대상 타입을 `JsonData`로 변경하여 JSON의 키가 실제 무엇인지 확인합니다. 이를 통해 즉시 "JSON에 없음"과 "C# 필드명 불일치" 두 가지 경우를 구분할 수 있습니다.
