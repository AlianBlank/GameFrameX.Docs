# Plugin Introduction

GameFrameX Procedure 流程Manages组件是 Unity 游戏框架的核心模块之一，专门used forManages游戏的流程状态。该组件基于有限状态机（FSM）Implements，provides了一套完整的游戏流程生命周期Manages方案。

## 概述

Procedure 流程Manages组件主要used for组织和控制游戏的整体流程逻辑。在游戏开发中，典型的游戏流程including：start流程（Loading）、主菜单流程（Menu）、游戏流程（Game）、pause流程（Pause）和结算流程（Settlement）等。该组件帮助开发者将这些复杂的流程逻辑模块化，使得游戏状态的切换更加清晰、可控和易于维护。

该组件的核心设计思想是将每个游戏流程视为有限状态机中的一个状态，through统一的接口进行Manages。这种设计模式不仅简化了流程切换的逻辑，还为开发者provides了丰富的钩子Method，使其能够在流程的各个生命周期阶段插入自定义逻辑。

作为 GameFrameX 框架的核心子模块，Procedure 组件Depends on于 FSMComponent（有限状态机组件）来Implements底层的状态Manages功能。开发者可以throughInherits `ProcedureBase` 类来CreatesCustom Procedures，并将其register到流程Manages器中。

## Architecture Design

该组件adopts了分层Architecture Design，从上到下依次为：Unity Component Layer、Procedure Management Layer、Finite State Machine Layer。这种分层设计ensure了各层之间的Responsibility清晰，耦合度低，便于扩展和维护。

### 核心组件Description

**ProcedureComponent** 是整个流程系统的入口点，它是一个 Unity Component，挂载在场景中的 GameObject 上。该组件responsible for在游戏start时Initialize所有可用的流程，并自动切换到入口流程。through Inspector 面板，开发者可以configuration可用流程的Type名称数组and入口流程的Type名称。

**IProcedureManager** 定义了流程Manages器的标准接口，contains了get当前流程、Initialize流程Manages器、开始流程、判断流程存在性andget流程等核心操作。所有流程Manages相关的功能都through这个接口对外provides。

**ProcedureManager** 是 IProcedureManager 接口的具体Implements类，它内部Uses有限状态机来Manages所有的流程状态。开发者通常不需要直接操作这个类，而是through ProcedureComponent 或 IProcedureManager 接口来间接Uses。

**ProcedureBase** 是Base class for all custom procedures，它Inherits from FsmState<IProcedureManager>。开发者需要CreatesInherits自 ProcedureBase 的子类来Implements具体的流程逻辑。基类provides了 OnInit、OnEnter、OnUpdate、OnFixedUpdate、OnLeave 和 OnDestroy 等生命周期钩子Method。

### 工作原理

当游戏start时，ProcedureComponent 会在 Awake Method中get IProcedureManager 模块实例。然后在 Start Method中，它会iterate所有configuration的可用流程Type，through反射Create Procedure Instance，并找到入口流程。最后，它会调用流程Manages器的 Initialize MethodInitialize有限状态机，并调用 StartProcedure Method开始入口流程。

流程一旦start，就会进入有限状态机的Manages状态。每个流程都会按照其生命周期钩子sequential执行：OnInit（Initialize）→ OnEnter（进入）→ OnUpdate/OnFixedUpdate（轮询）→ OnLeave（离开）→ OnDestroy（destroy）。开发者可以在这些钩子中编写各自的业务逻辑。

## Core Concepts

### 流程（Procedure）

流程代表游戏中的一个独立状态或阶段。每个流程都应该有明确的Responsibility，for exampleload资源、显示菜单、processGame Logic等。流程之间可以相互切换，切换时会触发相应的生命周期钩子Method。

### 入口流程（Entrance Procedure）

入口流程是游戏start后第一个执行的流程。在 ProcedureComponent 的 Inspector 面板中，可以through m_EntranceProcedureTypeName Property进行configuration。这个流程通常是load流程或主菜单流程。

### 流程Manages器（Procedure Manager）

流程Manages器responsible forManages所有已register的流程，including流程的Creates、Initialize、切换和destroy等操作。它内部Uses有限状态机来Implements这些功能，对外provides统一的接口供上层调用。

### 有限状态机（Finite State Machine）

有限状态机是整个流程系统的底层Implements。每个流程都被视为有限状态机中的一个状态，状态之间的切换由状态机统一Manages。这种设计使得流程切换逻辑变得简单可靠。

## Dependencies

Procedure 组件Depends on于以下 GameFrameX 核心模块：

| Depends on模块 | Description | 作用 |
|---------|------|------|
| FSMComponent | 有限状态机组件 | provides有限状态机的Creates和Manages功能 |
| GameFrameworkEntry | 框架入口 | provides模块register和get功能 |
| GameFrameworkComponent | 组件基类 | provides组件Initialize和configuration功能 |

在Uses Procedure 组件之前，Please ensure项目中已经正确configuration了这些Depends on组件。GameFrameX 框架会自动process模块之间的Dependencies，开发者只需在 Unity 场景中add相应的组件即可。

## Getting Started

1. 在 Unity 场景中Creates一个空 GameObject
2. add ProcedureComponent 组件到该 GameObject
3. 在 Inspector 面板中configuration可用流程Type和入口流程
4. CreatesInherits自 ProcedureBase 的Custom Procedures类
5. 将Custom Procedures的类名add到可用流程列表中
6. 运行游戏，系统将自动Start Entrance Procedure
