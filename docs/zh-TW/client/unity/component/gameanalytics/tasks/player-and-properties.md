# 如何設定玩家 ID 與公用屬性

透過 `IGameAnalyticsManager` 介面的 `SetPlayerId(string playerId)` 與 `SetPublicProperties(string key, object value)` 兩個呼叫，即可在遊戲執行期間為所有後續上報事件附加玩家識別與公用屬性。框架在初始化時已自動寫入一組裝置公用屬性，您只需追加業務欄位。

## 前置條件

- 專案已安裝 `com.gameframex.unity.gameanalytics` 套件並掛載 `GameAnalyticsComponent` 元件。
- 已呼叫 `Init` / `ManualInit` 完成初始化(可用 `IsInit()` 確認)。

## 操作步驟

1. 取得管理器實例(透過 `GameAnalyticsComponent` 公開的管理器介面)。
2. 在玩家登入成功後設定玩家 ID:

```csharp
// 玩家登入成功後,綁定玩家 ID(後續所有事件都會攜帶該 ID)
GameAnalyticsComponent.Instance.SetPlayerId("123456789");
```

`SetPlayerId` 的介面簽章為 `void SetPlayerId(string playerId)`,定義在 `IGameAnalyticsManager` 中，基類 `BaseGameAnalyticsManager` 中宣告為抽象方法，由具體平台子類實作：

```csharp
/// <summary>
/// 設定玩家ID
/// </summary>
/// <param name="playerId">玩家ID</param>
void SetPlayerId(string playerId);
```

Source: [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L100-L104)

3. 追加業務公用屬性，每次設定一個鍵值對：

```csharp
// 每次呼叫寫入一個 Key,重複設定同一 Key 會覆蓋舊值
GameAnalyticsComponent.Instance.SetPublicProperties("server_id", "s1001");
GameAnalyticsComponent.Instance.SetPublicProperties("vip_level", 5);
```

基類實作會忽略空 Key 並寫入內部字典 `m_PublicProperties`:

```csharp
public virtual void SetPublicProperties(string key, object value)
{
    if (string.IsNullOrEmpty(key))
    {
        return;
    }

    m_PublicProperties[key] = value;
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L53-L65)

4. (可選)讀取或清空公用屬性：

```csharp
// 讀取:傳回內部字典的副本,修改副本不影響真實公用屬性
Dictionary<string, object> props = GameAnalyticsComponent.Instance.GetPublicProperties();

// 清空業務屬性;隨後會自動重新寫入裝置資訊公用屬性
GameAnalyticsComponent.Instance.ClearPublicProperties();
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L67-L83)

## 內建的裝置公用屬性

初始化階段框架會透過 `AddDeviceInfoToPublicProperties()` 自動寫入以下公用屬性，您無需手動設定，且 `ClearPublicProperties()` 後會自動還原：

| 分類 | 屬性 Key |
|------|----------|
| 裝置 | `device_id`、`device_model`、`device_type` |
| 作業系統 | `os` |
| 應用程式 | `app_version`、`unity_version`、`platform` |
| 硬體 | `processor_type`、`processor_count`、`processor_frequency`、`system_memory_size` |
| 圖形 | `graphics_device_name`、`graphics_device_type`、`graphics_memory_size`、`graphics_device_version`、`graphics_shader_level` |
| 螢幕 | `screen_width`、`screen_height`、`screen_dpi`、`screen_refresh_rate` |
| 在地化 | `system_language`、`current_culture` |
| 網路 | `network_type`(取值 `No Network` / `Mobile Data` / `WiFi` / `Unknown`) |

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L86-L144)

## 常見變體

- **切換帳號**：先 `ClearPublicProperties()` 清除舊帳號業務欄位，再重新 `SetPlayerId` 與 `SetPublicProperties`。清空後會自動還原裝置資訊屬性。
- **覆蓋內建屬性**：自訂 Key 與上表相同時會直接覆蓋內建值(寫入同一字典)；一般建議避免這樣做，以免遺失裝置維度資訊。

## 常見錯誤

- **空 Key 會被靜默忽略**:`SetPublicProperties` 對 `string.IsNullOrEmpty(key)` 直接 `return`,不會拋出例外也不會寫入，設定無效時先檢查 Key 是否為空。
- **`ClearPublicProperties` 不會清空玩家 ID**:該方法只清空公用屬性字典並重建裝置屬性，玩家 ID 需要另外重新 `SetPlayerId`。
- **`GetPublicProperties` 傳回的是副本**:`return new Dictionary<string, object>(m_PublicProperties);`,直接修改傳回值不會影響真實上報的公用屬性。

## 背景

公用屬性儲存在基類的 `m_PublicProperties` 字典中，事件上報時會隨所有事件一起攜帶，適合放置相對穩定的維度欄位(通路、伺服器、會員等級等)；頻繁變動的數值更適合用事件的自訂欄位 `Event(string eventName, Dictionary<string, object> customF)` 上報。
