# 連線失敗或連線中斷的處理方式

當連線失敗或中斷時，GameFrameX Network 會透過 `NetworkErrorEventArgs`（包含 `ErrorCode`、`SocketErrorCode`、`ErrorMessage`）以及連線狀態事件 `NetworkConnectedEventArgs` / `NetworkClosedEventArgs`，向上一層回報錯誤碼與 `NetworkCloseReason` 關閉原因。請先訂閱這些事件以取得錯誤碼，再與下表中的錯誤碼 / 關閉原因對照，定位並修復問題。

## 快速診斷

| 症狀（錯誤碼 / 關閉原因） | 根本原因 | 修復方式 |
|------|------|------|
| 關閉原因為 `ConnectAddressError` | 伺服器位址或連接埠格式無效（例如 URL 缺少 scheme、連接埠超出範圍） | 檢查連線位址；參見下方「檢查位址與連接埠」 |
| 關閉原因為 `ConnectAddressExceptionError` | 位址解析拋出例外（例如 IP 字串無效、DNS 解析失敗） | 改用有效位址並驗證解析結果；參見下方「檢查位址與連接埠」 |
| 錯誤碼 `AddressFamilyError` | 設定的 `AddressFamily` 與實際位址家族不符（IPv4/IPv6 不一致） | 讓通道的 AddressFamily 與伺服器位址一致；參見下方「驗證 AddressFamily」 |
| 錯誤碼 `ConnectError`，且 `SocketErrorCode` 為 `ConnectionRefused` / `TimedOut` | 伺服器未監聽、防火牆阻擋或網路無法連通 | 確認伺服器正在執行且連接埠已放行 |
| 錯誤碼 `SocketError` / `SendError` / `ReceiveError` | 底層 Socket 在傳送/接收時發生失敗 | 依 `SocketErrorCode` 定位問題；常見原因是對端關閉連線後仍繼續傳送/接收 |
| 關閉原因為 `MissHeartBeat`，錯誤碼 `MissHeartBeatError` | 因心跳逾時被判定為斷線 | 調整心跳間隔並檢查「焦點控制心跳」設定；參見下方「排查心跳斷線」 |
| 關閉原因為 `Timeout`（WebSocket） | WebSocket 連線建立逾時，觸發保護性關閉 | 檢查 ws/wss 位址與伺服器交握耗時；必要時升級至包含連線逾時保護的版本（參見 CHANGELOG） |

上述錯誤碼與關閉原因皆為原始碼中的實際定義。完整數值請見 [NetworkErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkErrorCode.cs#L38-L136)：

```csharp
public static class NetworkCloseReason
{
    public const string Normal = "Normal";
    public const string Timeout = "Timeout";
    public const string Dispose = "Dispose";
    public const string ConnectClose = "ConnectClose";
    public const string ConnectAddressError = "ConnectAddressError";
    public const string ConnectAddressExceptionError = "ConnectAddressExceptionError";
    public const string MissHeartBeat = "MissHeartBeat";
}

public enum NetworkErrorCode : byte
{
    Unknown = 0,
    AddressFamilyError,
    SocketError,
    ConnectError,
    SendError,
    ReceiveError,
    SerializeError,
    DeserializePacketHeaderError,
    DeserializePacketError,
    MissHeartBeatError,
    DisposeError,
}
```

來源：[NetworkErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkErrorCode.cs#L38-L136)

## 修復步驟

### 步驟 1：訂閱錯誤與關閉事件以取得實際錯誤碼

在初始化期間，`NetworkComponent` 已將通道事件橋接至 `m_NetworkManager` 的 `NetworkConnected` / `NetworkClosed` 等事件：

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
```

來源：[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L108-L110)

錯誤事件帶有三個診斷欄位；`SocketErrorCode` 為原始的 `System.Net.Sockets.SocketError` 值：

```csharp
public INetworkChannel NetworkChannel { get; private set; }
public NetworkErrorCode ErrorCode { get; private set; }
public SocketError SocketErrorCode { get; private set; }
public string ErrorMessage { get; private set; }

public static NetworkErrorEventArgs Create(INetworkChannel networkChannel, NetworkErrorCode errorCode, SocketError socketErrorCode, string errorMessage)
```

來源：[NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L71-L104)

在錯誤回呼中，印出 `ErrorCode`、`SocketErrorCode` 與 `ErrorMessage` 三個值，再與上方的診斷表對照。

### 檢查位址與連接埠

1. 若關閉原因為 `ConnectAddressError` 或 `ConnectAddressExceptionError`，請先確認位址字串本身是否有效：TCP 使用 `IP:port`，WebSocket 使用 `ws://host:port` 或 `wss://host:port`。
2. 在與 Unity 相同網路的機器上，使用 `telnet host port`（TCP）或直接以瀏覽器存取（WebSocket）驗證伺服器是否可連通；若無法連通，請先解決伺服器監聽或防火牆問題。
3. 確認沒有同時以相同位址開啟多個通道實例，否則可能導致伺服器主動拒絕連線。

### 驗證 AddressFamily

`AddressFamilyError` 表示設定的位址家族與實際位址不符。這常見於伺服器位址為 IPv6（或網域解析為 IPv6），而通道以 IPv4（`InterNetwork`）連線的情況。將通道初始化時使用的 `NetworkAddressFamily` 設為與伺服器位址的實際家族一致，即可消除此錯誤。可用的家族定義請見 [NetworkAddressFamily.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkAddressFamily.cs)。

### 排查心跳斷線

1. 當發生 `MissHeartBeat` / `MissHeartBeatError` 時，表示通道未在預期時間內收到心跳回應，元件因此以「心跳遺失」為由關閉連線。
2. 本套件支援「焦點控制心跳」（應用程式進入背景時暫停心跳，回到前景時恢復）。請確保您的背景/前景切換邏輯與伺服器的逾時門檻相符：在背景停留過久，會導致伺服器將連線判定為逾時。
3. 適當調高心跳間隔上限或伺服器端逾時時間，然後重新測試。

## 驗證

- 重新連線後，`NetworkConnected` 事件正常觸發，且一段時間內不再收到 `NetworkErrorEventArgs` 或（原因非 `Normal` 的）`NetworkClosedEventArgs`。
- 對 WebSocket 通道而言，長時間懸置（進入背景後再回到前景）不再導致 `Timeout` 關閉。
- 在心跳情境下，不再觸發 `NetworkMissHeartBeatEventArgs` 事件（參見 [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs)）。

## 背景

錯誤與關閉分為兩條事件鏈：暫時性錯誤走 `NetworkErrorEventArgs`（細粒度錯誤碼 + 原始 `SocketError`），連線生命週期則走 `NetworkConnectedEventArgs` / `NetworkClosedEventArgs`（含 `NetworkCloseReason`）。WebSocket 連線逾時保護、連線事件順序、`SystemTcpNetworkChannel` 接收失敗處理等問題已在 CHANGELOG 中修復。若遇到異常斷線，請先確認您使用的是最新套件版本；詳情請見 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md)。
