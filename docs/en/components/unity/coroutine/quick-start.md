# Quick Start: Install and Launch Your First Coroutine

This guide walks you through integrating the GameFrameX Coroutine package into your Unity project and exercising the three most commonly used interfaces: "start → stop → end-of-frame callback." This component is a thin wrapper around Unity's native coroutines. Internally, it tracks all started coroutines using a `ConcurrentDictionary` to prevent dangling references caused by missed stops.

## Prerequisites

- Unity 2017.1 or higher (tested target is Unity 2019.4)
- A Unity project that opens normally
- `com.gameframex.unity.runtime` already installed in the project (this component inherits from its `GameFrameworkComponent`)

## Installation

Choose any of the following methods to add the package to your project:

1. **Via Scoped Registry (recommended)** — Edit `Packages/manifest.json`, add the GameFrameX registry under `scopedRegistries`, and declare the dependency:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.coroutine": "1.0.3"
     }
   }
   ```

2. **Via Git URL** — Write directly under `dependencies`:

   ```json
   "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
   ```

3. **Via Package Manager** — Use `Add package from Git URL` and enter the repository URL above.

4. **Manual placement** — Copy the entire repository into your project's `Packages/` directory, and Unity will detect it automatically.

## Steps

1. **Get a CoroutineComponent instance.** Since this component carries the `[DisallowMultipleComponent]` and `[GameFrameXAutoComponent(-6500)]` attributes, it is usually auto-registered by the GameFrameX framework onto a GameObject that has `GameFrameworkEntry` attached. The manual approach is as follows:

   ```csharp
   var coroutineComponent = gameObject.AddComponent<GameFrameX.Coroutine.Runtime.CoroutineComponent>();
   ```

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L21)

2. **Write a coroutine method.** The coroutine signature must return `IEnumerator`, with `yield return` used internally to control pacing:

   ```csharp
   IEnumerator HelloCoroutine()
   {
       Debug.Log("Hello");
       yield return null;            // Wait one frame
       Debug.Log("Next frame");
   }
   ```

3. **Start the coroutine.** Call `StartCoroutine` and save the returned iterator instance so you can stop it later:

   ```csharp
   IEnumerator routine = HelloCoroutine();
   coroutineComponent.StartCoroutine(routine);
   ```

   Note: You must call `StartCoroutine` through a `CoroutineComponent`-typed reference, because it hides the base method using the `new` keyword to ensure the tracking dictionary is written to.

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

4. **Stop a single coroutine (optional).** Pass back the same `IEnumerator` instance you saved at start:

   ```csharp
   coroutineComponent.StopCoroutine(routine);
   ```

   This overload first looks up the corresponding `UnityEngine.Coroutine` in the dictionary, stops it, then removes it from the dictionary. If not found, it falls back to `base.StopCoroutine(enumerator)`.

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

5. **Stop all coroutines (optional).** Call this when switching scenes or resetting logic:

   ```csharp
   coroutineComponent.StopAllCoroutines();
   ```

   The implementation first iterates through and stops every coroutine tracked in the dictionary, clears the dictionary, and then calls `base.StopAllCoroutines()` as a fallback to clean up any untracked coroutines.

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

6. **End-of-frame callback (optional).** When you need to do something after all rendering for the current frame is complete (such as taking a screenshot or uploading a report), use:

   ```csharp
   coroutineComponent.WaitForEndOfFrameFinish(() =>
   {
       Debug.Log("End of frame");
   });
   ```

   Internally, it reuses a single `WaitForEndOfFrame` one-shot object to avoid GC allocation on every call.

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

## Common Variations

- **Stopping via the `UnityEngine.Coroutine` overload**: When you only hold the coroutine handle returned by Unity, use the `StopCoroutine(UnityEngine.Coroutine coroutine)` overload. Internally, it iterates the dictionary in reverse to find the matching iterator and cleans it up.
- **Don't throw exceptions inside the `WaitForEndOfFrameFinish` callback**: If the coroutine is stopped via `StopCoroutine` before the frame ends, the callback will not execute, so no defensive null checks are needed.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| After `StartCoroutine`, the entry is not found in the dictionary | Called `MonoBehaviour.StartCoroutine` instead of `CoroutineComponent.StartCoroutine` | Always call through a `CoroutineComponent`-typed reference to ensure the `new`-hidden version is used |
| `StopCoroutine` does nothing | A **re-constructed** `IEnumerator` was passed in (e.g., calling `HelloCoroutine()` again) | Reuse the same `IEnumerator` instance saved at start, because the dictionary uses reference equality as the key |
| Coroutines are still running after `StopAllCoroutines` | The regular `MonoBehaviour.StopAllCoroutines()` was called instead | Call `CoroutineComponent.StopAllCoroutines()` to ensure the tracking dictionary is cleared as well |
| End-of-frame callback was not triggered | `StopCoroutine`/`StopAllCoroutines` was called before the callback should have executed | Move the work inside the callback to the next frame, or wait for `yield return new WaitForEndOfFrame()` before checking |
