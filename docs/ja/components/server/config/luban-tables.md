# Luban 設定表と TablesComponent による読み込み

`TablesComponent` は GameFrameX.Config 内で Luban ツールによって自動生成された設定表コンテナです。実行時にすべての `.json` 設定表を `ConfigComponent` に読み込み、表間の参照関係を解析する役割を担います。このページを読み終えると、サーバー側またはクライアント側の起動時にすべての Luban 表を一括読み込みし、必要に応じて個別項目にアクセスできるようになります。

## 前提条件

- Luban ツールによって `GameFrameX.Config` プロジェクトを生成済みであること。成果物には `TablesComponent.cs`、`Tables/*.cs`、`Local/*.cs` が含まれます。
- プロジェクトが `GameFrameX.Core.Abstractions` を参照していること(`ConfigComponent` と `BeanBase` を提供します)。
- Luban によってエクスポートされた JSON ファイル(`tables_tbxxx`、`local_tblocalization` などの命名規約)を準備し、`loader` コールバックから読み取れる場所にデプロイしておくこと(ローカルファイル、AssetBundle、リモートダウンロードいずれも可)。

## 操作手順

1. **設定マネージャーのインスタンス化**。`ConfigComponent` の内部では既に `TablesComponent` が作成されているため、そのまま使用できます:

   ```csharp
   var configComponent = new ConfigComponent();
   var tables = configComponent.Tables; // プライベートプロパティのため、下記の Init で注入が必要
   ```

   Source: [ConfigComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/ConfigComponent.cs#L14-L19)

2. **`Init` を呼び出して `ConfigComponent` を注入**。このステップで表の登録エントリを `ConfigComponent` に渡し、その後の `Add` で表を統一コンテナに書き込みます:

   ```csharp
   tables.Init(configComponent);
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

3. **`loader` コールバックを提供して非同期読み込み**。`loader` は表名を受け取り、その表の JSON の `JsonElement` を返します。すべての表は並列読み込みされ、完了後に自動的に `Refresh` で参照を解析します:

   ```csharp
   await tables.LoadAsync(async tableName =>
   {
       var json = await File.ReadAllTextAsync($"Configs/{tableName}.json");
       return JsonDocument.Parse(json).RootElement.Clone();
   });
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L56)

4. **具体的な表と項目の読み出し**。読み込み完了後、`TablesComponent` の強く型付けされたプロパティを介して具体的な表オブジェクトを取得します。例:

   ```csharp
   var itemConfig = tables.TbItemConfig;
   var oneItem = itemConfig.Get(1001); // Luban によって生成されたインデックス/クエリメソッド
   ```

   `TablesComponent` が現在公開している表プロパティ:`TbLocalization`、`TbAchievementConfig`、`TbItemConfig`、`TbSoundsConfig`。

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L18-L21)

5. **(オプション)ホット更新シナリオでの再読み込み**。再度 `LoadAsync` を呼び出す際に `Init` は不要です。`loader` が各表の最新の JSON を再読込し、`Refresh()` が `PostInit` と `ResolveRef` を再実行して、以前の参照関係を上書きします。

## よくあるバリエーション

- **リモートダウンロード + ローカルキャッシュ**:`loader` を「まずローカルキャッシュを参照し、ミスしたら HTTP 経由で取得、ダウンロード後にディスクへ書き出してから JSON を解析する」という実装にすれば、Luban 表で CDN ホット更新をサポートできます。
- **AssetBundle からの読み込み**:クライアント側で `loader` を `Resources.LoadAsync<TextAsset>(tableName).Result.text` に置き換え、関数シグネチャを統一するだけでよく、`TablesComponent` を変更する必要はありません。
- **一部の表の遅延読み込み**:起動時に読み込む必要のない表を `LoadAsync` からコメントアウトし(コメントコードは生成ファイル内に保持されています)、業務側で必要に応じて `new TbXxx(...)` で読み込むように変更します。

## よくあるエラー

- **表 JSON が見つからない**:`loader` が例外を投げると `Task.WhenAll` が失敗し、`LoadAsync` 全体が例外を投げます。ファイル命名が `tables_xxx` / `local_xxx` プレフィックスに厳密に従っていることを確認してください。
- **参照解析の失敗**:`Refresh()` の内部で各表の `ResolveRef(this)` が呼び出されます。`PostInit` または `ResolveRef` 内でまだ読み込まれていない表にアクセスすると null 参照が発生するため、関連するすべての表が `LoadAsync` 経由であることを確認してください。
- **重複した `Init`**:`Init` を再度呼び出すと `RemoveAllConfigs()` が再実行され、既に読み込まれた表の参照がクリアされます。通常はリセットシナリオでのみ使用します。
- **生成ファイルの変更**:`TablesComponent.cs` と `Tables/*.cs` の冒頭にはいずれも `// <auto-generated>` が付与されています。手動で加えた変更は次回 Luban が再生成する際に上書きされます。

## 背景(オプション)

`TablesComponent` は Luban の `gen_cs_server_json` / `gen_cs_client_json` テンプレートの成果物です。各表は `BeanBase` のサブクラス(例: [`ItemConfig`](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Tables/ItemConfig.cs#L15-L76))に対応し、コンストラクタで `JsonElement` からフィールドをデシリアライズし、`ResolveRef` で表間の `xxx_ref` フィールドを具体的な行オブジェクトへ接続します。
