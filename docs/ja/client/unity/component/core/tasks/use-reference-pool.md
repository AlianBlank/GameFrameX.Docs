# 参照プールで GC アロケーションを削減

参照プール(`ReferencePool`)は `IReference` インターフェースを実装したオブジェクトインスタンスをキャッシュし、`Acquire` で取得・`Release` で返却して再利用することで、繰り返しの `new` による GC 圧力を回避します。本ページでは GameFrameX で参照プールを導入しカスタム型に利用する完全な手順を示します。

## 前提条件

- プロジェクトに `GameFrameX.Runtime.Base.ReferencePool` と `GameFrameX.Runtime.ReferencePoolComponent` が導入済みであること(フレームワークに同梱)。
- シーンに `ReferencePoolComponent` がアタッチされていること(メニュー `Add Component → GameFrameX → ReferencePool`)、またはコードから静的クラス `ReferencePool` で直接アクセスすること。

## 操作手順

1. **カスタム型に `IReference` を実装する**。型は引数なしコンストラクターを持つ必要があり、`Clear()` 内でフィールドをリセットして、次に取り出したときにクリーンな状態になるようにしてください。

   ```csharp
   using GameFrameX.Runtime;

   public sealed class DamageInfo : IReference
   {
       public int AttackerId { get; private set; }
       public int TargetId   { get; private set; }
       public float Amount  { get; private set; }

       public void Clear()
       {
           AttackerId = 0;
           TargetId   = 0;
           Amount     = 0f;
       }

       internal void Fill(int attackerId, int targetId, float amount)
       {
           AttackerId = attackerId;
           TargetId   = targetId;
           Amount     = amount;
       }
   }
   ```

   出典: [Tests/ReferencePoolTests.cs#L11-L29](/src/Tests/ReferencePoolTests.cs#L11-L29)

2. **Acquire でインスタンスを取得する**。ジェネリック版を使用すれば手動でキャストする必要はありません。プールが空のときはフレームワークが引数なしコンストラクターを呼び出して新規生成します。

   ```csharp
   DamageInfo info = ReferencePool.Acquire<DamageInfo>();
   ```

   シグネチャ:`public static T Acquire<T>() where T : class, IReference, new()`、[Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132) を参照。

3. **Release でインスタンスを返却する**。返却時には自動的に `Clear()` が呼ばれますが、フィールド単位のリセットはあなたの `Clear()` の責任です。

   ```csharp
   ReferencePool.Release(info);
   ```

   シグネチャ:`public static void Release(IReference reference)`、[Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167) を参照。`null` を渡すと `GameFrameworkException("Reference is invalid.")` がスローされます、[Tests/ReferencePoolTests.cs#L79](/src/Tests/ReferencePoolTests.cs#L79) を参照。

4. **(任意)起動前にプール容量をプリウォームする**。戦闘/レベルの開始時に `Add<T>(count)` を呼び出し、ランタイムでの即時拡張を回避します。

   ```csharp
   ReferencePool.Add<DamageInfo>(64);
   ```

   シグネチャ:`public static void Add<T>(int count) where T : class, IReference, new()`、[Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181) を参照。

5. **(任意)プールの状態を確認する**。デバッグパネルや Profiler フックから各型のキャッシュ情報を読み取ります。

   ```csharp
   ReferencePoolInfo[] infos = ReferencePool.GetAllReferencePoolInfos();
   foreach (var info in infos)
   {
       UnityEngine.Debug.Log($"{info.Type.Name}: using={info.UsingReferenceCount} unused={info.UnusedReferenceCount}");
   }
   ```

   シグネチャは [Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98) を参照。

## よくあるバリエーション

- **ランタイムで `Type` により取得する**(ジェネリックを使用できない場合):

  ```csharp

  ```

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `GameFrameworkException: Reference is invalid.` | `null` を `Release` に渡した | Release 前に null チェックを行うか、`using`/`try-finally` ブロック内で返却する |
| 取得したオブジェクトに前回のデータが残っている | `Clear()` でフィールドをリセットしていない | `Clear()` ですべてのフィールドを明示的に既定値にリセットする |
| 型が `Acquire` できない | 型が `IReference` を実装していない、または `public` の引数なしコンストラクターがない | インターフェースを実装し、引数なしコンストラクターを補完する |
| Profiler でプールが膨らんで表示される | Acquire だけで Release していない | 利用終了経路(例外分岐も含む)で必ず Release する。`try { ... } finally { Release(info); }` の使用を推奨 |
| 厳格チェックを有効にするとパフォーマンスが低下する | `ReferencePool.EnableStrictCheck = true` でリフレクション検証が有効になる | デバッグ期間中のみ有効化し、リリースビルドではオフにする |

## 背景(任意)

各 CLR 型はプール内に独立した `ReferenceCollection` を持ち、内部で `Stack<IReference>` を管理します。`Acquire` はまずスタックから取り出し、スタックが空の場合のみ `new` します。`Release` は `Clear()` を呼んだ後にスタックにプッシュします。`EnableStrictCheck` を有効にするとリフレクションで型を検証するためパフォーマンスに影響し、デバッグ専用です。
