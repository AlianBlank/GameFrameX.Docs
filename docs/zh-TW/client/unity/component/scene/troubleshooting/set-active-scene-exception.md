# 當 SetActiveScene 擲出 ArgumentException 時該如何處理

呼叫 `SetActiveScene` 時，如果傳入的 `Scene` 尚未被 Unity 完整載入，Unity 將會擲出 `ArgumentException`。本框架已在內部捕捉此例外並做了優雅降級（僅記錄一條 `Warning`），但訂閱者或自訂程式碼仍可能遇到相同的根本原因。以下是診斷與修復此問題的步驟。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| 日誌顯示 `SetActiveScene failed (will be retried by Unity internally): Scene ... is not loaded.` | 在 `Scene.isLoaded` 仍為 `false` 時呼叫了 `SetActiveScene`（典型情境：YooAsset 的 `await` 比 Unity 實際載入完成更早結束） | 等待場景真正達到 `isLoaded == true` 後再啟用，詳見下方「等待 isLoaded」 |
| 正在啟用快取的 `m_GameFrameworkScene` 控制代碼，但該場景已被 Unity 卸載 | 首次 Single 載入後，框架場景被卸載，快取控制代碼的 `IsValid()` 傳回 `false` | 透過 `GetSceneByName` 重新取得控制代碼後再啟用，詳見下方「控制代碼無效」 |
| 主控台擲出 `ArgumentException: SceneManager.SetActiveScene ... is not loaded` | 自訂程式碼直接呼叫 `SceneManager`，繞過了框架的 try/catch | 使用框架入口或自行加入防護檢查，詳見下方「直接呼叫繞過框架」 |
| 連續切換場景期間，新舊協程競爭 `SetActiveScene` | 啟動新協程前未先停止先前的重新整理協程 | 在啟動新協程前先執行 `StopCoroutine`，詳見下方「協程衝突」 |

## 修復步驟

### 等待 isLoaded

框架已在 `SceneComponent.SetActiveScene` 中以 try/catch 包裹了 `ArgumentException`，但你在監聽 `LoadSceneSuccess` 事件後的自身回呼中仍可能遇到它。設定目標場景前請先確認其已 `isLoaded`：

```csharp
var scene = UnityEngine.SceneManagement.SceneManager.GetSceneByName(sceneName);
if (scene.IsValid() && scene.isLoaded)
{
    UnityEngine.SceneManagement.SceneManager.SetActiveScene(scene);
}
```

如果在當前幀尚未 `isLoaded`，請使用協程延遲到下一幀並重試，直到逾時後回退至框架場景——請參考 [SceneComponent.cs#L480-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L480-L509) 中的 `RefreshSceneOrderWhenLoadedCo` 實作。

### 控制代碼無效

在 `Single` 模式下，快取的 `Scene` 控制代碼會隨舊場景一起被 Unity 卸載。框架在 [SceneComponent.cs#L449-L457](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L449-L457) 中以 `IsValid()` 進行防禦：

```csharp
if (!activeScene.IsValid())
{
    // 當控制代碼已過期時跳過設定；一旦新的 Single 場景載入完成，Unity 會自行啟用它
    RefreshMainCamera();
    return;
}
```

在自己的程式碼中重複使用 `Scene` 控制代碼時，呼叫前請先驗證 `IsValid()`；否則需要再次呼叫 `GetSceneByName`。

### 直接呼叫繞過框架

請勿在訂閱者回呼中直接呼叫 `UnityEngine.SceneManagement.SceneManager.SetActiveScene`，因為這會繞過框架的例外吞沒邏輯。建議優先使用框架入口，例如 `GameSceneComponent.SetActiveScene`；如果必須在事件回呼中切換作用中場景，請用自己的 try/catch 包裹，並遵循上述「等待 isLoaded」的檢查方式。

### 協程衝突

連續多次切換場景時，如果沒有先停止先前的重新整理協程，新舊協程會在同一幀內競爭 `SetActiveScene`，進而觸發 `ArgumentException`。請參考框架在 [SceneComponent.cs#L430-L435](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L430-L435) 中的修復模式：

```csharp
if (m_RefreshSceneOrderCo != null)
{
    StopCoroutine(m_RefreshSceneOrderCo);
    m_RefreshSceneOrderCo = null;
}
m_RefreshSceneOrderCo = StartCoroutine(RefreshSceneOrderWhenLoadedCo(maxSceneName));
```

記得在 `finally` 區塊中將控制代碼設為 `null`（見 [SceneComponent.cs#L505-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L505-L509)），以避免下一次 `RefreshSceneOrder` 誤以為舊協程仍在執行。

## 驗證

- 日誌中不再出現 `ArgumentException: SceneManager.SetActiveScene ... is not loaded`。
- 載入回呼傳回時，`SceneManager.GetActiveScene()` 等於目標場景。
- 觸發兩次連續場景切換後，主控台中不會出現任何 `SetActiveScene failed` 警告。
