# 實體顯示失敗時的處理方式

呼叫 `ShowEntity` / `ShowEntityAsync` 之後，如果實體未出現在場景中，或日誌顯示已觸發 `ShowEntityFailure` 事件，通常是由於實體分組、資源或輔助元件配置錯誤所致。本頁面將根據常見原因提供快速診斷與修正步驟。

## 快速診斷

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `ShowEntityFailure` 事件立即被觸發，且日誌中出現 `Entity group name is invalid.` | 傳入的 `entityGroupName` 為 `null` / 空字串，或實體分組未註冊 | 事先在 `EntityComponent` 的 `m_EntityGroups` 中加入同名的實體分組 |
| 出現 `Entity group is invalid.` 訊息 | 實體分組存在，但其內部 `EntityGroup` 實例未初始化或已被銷毀 | 先使用 `HasEntityGroup` 確認分組存在，再呼叫 `ShowEntity` |
| 出現 `Can not create entity helper.` 訊息 | `EntityComponent.Awake`/`Start` 無法依據 `m_EntityHelperTypeName` 反射建立 `EntityHelperBase` 實例 | 檢查 `m_EntityHelperTypeName` 是否為 `GameFrameX.Entity.Runtime.DefaultEntityHelper` 或自訂輔助類別的完整型別名稱；自訂輔助類別必須掛載到 `m_CustomEntityHelper` 欄位 |
| `ShowEntityFailure` 事件持續觸發且資源載入失敗 | `m_AssetManager` 未設定，或資源位址（`entityAssetName`）不存在於 YooAsset 資源清單中 | 確認 `EntityComponent.Start` 已呼叫 `SetResourceManager`；在 YooAsset 中正確設定實體 Prefab 的標籤與位址 |
| 實體建立成功但 GameObject 未顯示 | `m_InstanceRoot` 未掛載到可見的場景根節點，或 Prefab 自身的 Layer/可見性被停用 | 在場景中為 `EntityComponent` 指定可見的 `m_InstanceRoot`；檢查 Prefab 的 `MeshRenderer` 狀態 |
| 非同步 API `ShowEntityAsync` 一直未回傳 | 資源載入卡住，或 `m_EntitiesBeingLoaded` 收到同一實體的重複請求 | 避免在同一幀內對同一個 `EntityId` 發出多次 Show 呼叫；確認資源管理器未被外部阻塞 |

## 修正步驟

### 1. 確認實體分組已註冊

當實體分組名稱為空時，`EntityManager` 會直接拋出 `GameFrameworkException("Entity group name is invalid.")`。在任何 `ShowEntity` 呼叫之前，必須先透過 `EntityComponent.AddEntityGroup` 加入分組。

```csharp
// 來源：Runtime/Entity/Entity/EntityManager.Get.cs#L53-L61
public bool HasEntityGroup(string entityGroupName)
{
    if (string.IsNullOrEmpty(entityGroupName))
    {
        throw new GameFrameworkException("Entity group name is invalid.");
    }
    return m_EntityGroups.ContainsKey(entityGroupName);
}
```

步驟：

1. 開啟掛載了 `EntityComponent` 的場景物件的 Inspector。
2. 在 `Entity Groups` 清單中加入要使用的分組（填寫 `Name`、`InstanceAutoReleaseInterval`、`InstanceCapacity`、`InstanceExpireTime`、`InstancePriority`）。
3. 在程式碼中使用分組名稱之前，先呼叫 `HasEntityGroup` 進行驗證。

### 2. 確認實體輔助類別可用

`EntityComponent.Start` 會呼叫 `Helper.CreateHelper` 來建立實體輔助類別；如果回傳 `null`，將輸出 `Log.Error("Can not create entity helper.")` 並中止初始化。

```csharp
// 來源：Runtime/Entity/EntityComponent.cs#L171-L183
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
    return;
}
entityHelper.name = "Entity Helper";
Transform transform = entityHelper.transform;
transform.SetParent(this.transform);
transform.localScale = Vector3.one;
m_EntityManager.SetEntityHelper(entityHelper);
```

步驟：

1. 確認 `Entity Helper Type Name` 欄位所指向的類別存在（預設為 `GameFrameX.Entity.Runtime.DefaultEntityHelper`）。
2. 自訂輔助類別必須繼承自 `EntityHelperBase` 並實作實體實例化邏輯；將該實例拖曳到 `Entity Component` 的 `Custom Entity Helper` 欄位。
3. 如果輔助類別位於單獨的組件中，請確認該組件已包含在建置中，並可透過反射解析。

### 3. 確認資源管理器已注入

`EntityManager` 在載入實體 Prefab 時依賴 `IAssetManager`（透過 `SetResourceManager` 注入）；若未注入，`ShowEntityFailure` 將在載入階段失敗。

```csharp
// 來源：Runtime/Entity/EntityComponent.cs#L167-L169
m_EntityManager.SetResourceManager(GameFrameworkEntry.GetModule<IAssetManager>());
m_EntityManager.SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>());
```

步驟：

1. 確認場景中已掛載 `Asset Component` 與 `Object Pool Component`，且其 Awake 順序早於 `EntityComponent`。
2. 確認 YooAsset 已正確初始化，且傳入的 `entityAssetName`（路徑或標籤）存在於資源清單中。
3. 必要時啟用 `Enable Show Entity Dependency Asset Event`，並透過事件觀察相依資源是否已完成下載。

### 4. 監聽失敗事件以定位根本原因

`EntityComponent` 在 Awake 中已預設訂閱 `ShowEntityFailure`。除錯時，您可以在自己的腳本中額外訂閱，以取得 `EntityId`、`EntityAssetName`、`EntityGroupName`、`ErrorMessage` 等資訊。

```csharp
// 來源：Runtime/Entity/Entity/EntityManager.cs#L118-L122
public event EventHandler<ShowEntityFailureEventArgs> ShowEntityFailure
{
    add { m_ShowEntityFailureEventHandler += value; }
    remove { m_ShowEntityFailureEventHandler -= value; }
}
```

```csharp
// 來源：Runtime/Entity/EntityComponent.cs#L130-L131
m_EntityManager.ShowEntitySuccess += OnShowEntitySuccess;
m_EntityManager.ShowEntityFailure += OnShowEntityFailure;
```

步驟：在失敗回呼中列印 `EventArgs.ErrorMessage` 與 `EventArgs.EntityId`，並根據訊息回溯到上述第 1–3 項。

### 5. 檢查執行階段實例根節點

實體輔助類別會建立一個 `GameObject("Entity Instances")` 作為 `m_InstanceRoot`；如果此根節點被停用或不在場景中，實體雖然建立成功，但在視覺上不可見。

```csharp
// 來源：Runtime/Entity/EntityComponent.cs#L185-L190
if (m_InstanceRoot == null)
{
    m_InstanceRoot = new GameObject("Entity Instances").transform;
    m_InstanceRoot.SetParent(gameObject.transform);
    m_InstanceRoot.localScale = Vector3.one;
}
```

步驟：

1. 在 Hierarchy 中找到 `Entity Instances` 節點，確認其處於啟用狀態。
2. 如果 `m_InstanceRoot` 是自訂的，請確認其父節點與自身皆處於啟用狀態，且未被攝影機剔除（例如 `Layer` 設定、`Culling Mask` 等）。

## 驗證

1. 在測試場景中呼叫 `ShowEntity<MyEntityLogic>(entityId, "Default", "MyPrefab", userData)`。
2. 觀察 Console：應出現 `ShowEntitySuccess` 事件，且 `OnShowEntitySuccess` 被呼叫一次。
3. 在 Hierarchy 中確認 `Entity Instances` 下方出現以實體 `EntityId` 命名的 GameObject，且位置/縮放/可見性符合預期。
4. 呼叫 `HideEntity(entityId)` 後，確認物件已回收至物件池，且 `HideEntityComplete` 事件正常觸發。

## 背景說明（選讀）

`EntityManager` 內部維護 `m_EntityInfos`、`m_EntityGroups`、`m_EntitiesBeingLoaded` 等字典與佇列；資源載入透過 `IAssetManager` 以非同步方式進行，完成後呼叫 `IEntityHelper` 實例化實體並發出 `ShowEntitySuccess`；任何步驟拋出的錯誤都會走 `ShowEntityFailure` 路徑，並重複使用 `ShowEntityInfo` 參考物件（[ShowEntityInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.ShowEntityInfo.cs#L38-L106)）。
