# 串接平台通路

在 `PaymentComponent` 上設定各平台的實作型別字串，框架會在啟動時依平台自動實例化對應的通路 `PaymentManager`(Google / Apple / WebGL / PC),業務程式碼只需針對 `IPaymentManager` 介面進行程式設計；若要串接自有通路，繼承 `BasePaymentManager` 並將型別名稱填入 Inspector 即可。

## 前置條件

- 已安裝本支付核心套件(`GameFrameX.Payment.Runtime`)。
- 場景中已掛載 `PaymentComponent`,它會透過 `RequireComponent` 自動附加 `GameFrameXPaymentCroppingHelper`。
- 目標平台的通路實作套件已安裝(見下文「通路型別對照表」，各通路實作分佈於對應命名空間的獨立套件中)。

## 操作步驟

1. 在場景物件上新增元件：選單路徑為 `GameFrameX/Payment`(來自 `AddComponentMenu`):

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
{
    private IPaymentManager _paymentManager;
    [SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
    [SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
    [SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
    [SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
    [SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L28)

2. 安裝目標平台對應的通路實作套件(套件名稱與下表命名空間一致，例如 Google 通路位於 `GameFrameX.Payment.Google.Runtime`)。

3. 確認通路型別名稱與實際安裝的實作一致；如需替換為自有實作，直接在 Inspector 中修改對應平台的型別字串。

4. 啟動後框架依平台巨集自動選擇實作：

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

## 串接自有通路

1. 繼承 `BasePaymentManager`(它已實作 `GameFrameworkModule, IPaymentManager`,並內建四個事件的 `Raise*` 觸發方法)，補齊抽象成員：

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    /// <summary>
    /// 購買成功事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;

    /// <summary>
    /// 購買失敗事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;

    /// <summary>
    /// 查詢購買記錄結果事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

    /// <summary>
    /// 消耗購買結果事件
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    protected void RaisePurchaseFailed(PaymentEventArgs e)
    {
        OnPurchaseFailed?.Invoke(this, e);
    }

    protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
    {
        OnQueryPurchasesResult?.Invoke(this, e);
    }

    protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
    {
        OnConsumePurchaseResult?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);
}
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L67)

其餘抽象成員 `IsReady()`、`SetPredefinedProductIds(List<string>, List<string>)`、`QueryPurchases(PaymentProductType)`、`ConsumePurchase(string)`、`BuyInApp`/`BuySubs`/`Buy`(已標記 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`)與建議使用的 `Buy(PurchaseParams)` 均需在子類別中實作，完整簽章見 [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L69-L137)。

2. 如通路需要額外購買參數，繼承 `PurchaseParams` 以擴充欄位(原始碼註解：「各通路可繼承並擴充自有欄位」):

```csharp
/// <summary>
/// 購買參數基底類別，各通路可繼承並擴充自有欄位
/// </summary>
public abstract class PurchaseParams
{
    /// <summary>產品ID或SKU</summary>
    public string ProductId { get; set; }

    /// <summary>訂單ID</summary>
    public string OrderId { get; set; }

    /// <summary>產品型別</summary>
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

3. 將你的實作類別完整名稱(含命名空間)填入 `PaymentComponent` 對應平台的 Inspector 欄位，執行後以 `IsReady()` 驗證通路是否初始化成功。

## 常見變體

- **將 Android 通路替換為自有 SDK**:保持 `m_componentAndroidType` 欄位不變，將值改為你的實作類別完整名稱(含命名空間)，重新打包即可，無需修改 `PaymentComponent` 程式碼。
- **Mac 與 iOS 共用 Apple 通路**：預設設定已如此——`m_componentIOSType` 與 `m_componentMacType` 均指向 `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`。
- **編輯器/未支援平台**：命中 `#else` 分支時使用本套件內建的 `DefaultPaymentManager` 作為備援，便於在編輯器中驗證業務流程。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` 回傳 null,通常是通路實作類別名稱寫錯或對應組件尚未編譯 | 核對 Inspector 中平台型別字串與實際類別完整名稱、命名空間是否一致，並確認通路實作套件已安裝 |
| `Utility.Assembly.GetType(componentType)` 找不到型別 | 型別名稱與組件中的完整名稱不符(拼字/命名空間錯誤) | 在通路實作套件中確認 `namespace` 與類別名稱後，填入完整名稱如 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` |
| 在編輯器中呼叫購買無回應 | 命中 `#else` 分支，使用 `DefaultPaymentManager` 備援實作 | 切換至實機/目標平台建置驗證，或串接自訂通路實作 |
| `Log.Warning("Product ID is null or empty.")` / `"Order ID is null or empty."` | 舊版 `BuyInApp`/`BuySubs`/`Buy(productId, ...)` 傳入了空 `productId` 或 `orderId` | 傳入有效值，或改用建議的 `Buy(PurchaseParams)` 多載 |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93)(Fatal 日誌位置)；其餘警告訊息見 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L163-L204)

> 說明:`BuyInApp`、`BuySubs`、`Buy(productId, productType, orderId, ...)` 均已標記 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`,新串接請直接使用 `Buy(PurchaseParams)`([IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112))。

## 背景

`PaymentComponent` 在 `Awake` 中依據編譯巨集決定 `componentType`,再經 `Utility.Assembly.GetType` 反射取得 `ImplementationComponentType`,並以 `IPaymentManager` 作為介面型別註冊到 `GameFrameworkEntry`,隨後透過 `GameFrameworkEntry.GetModule<IPaymentManager>()` 取得實例。如此業務層只需依賴介面，通路實作透過 Inspector 字串於執行階段注入，實現「一套業務程式碼、多平台通路」的切換方式。關於支付元件的整體架構與完整 API,請見框架概述頁與 API 參考頁。
