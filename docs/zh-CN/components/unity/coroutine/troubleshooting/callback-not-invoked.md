# 帧结束回调没有被执行怎么办

`CoroutineComponent.WaitForEndOfFrameFinish` 注入的回调依赖一个内部协程跑到 `yield return new WaitForEndOfFrame()` 之后才会触发;如果协程在帧结束前被停止、被覆盖或根本没有跑起来，回调都不会执行。本页给出常见场景的诊断与修复方法。

关于协程组件的整体说明,见《协程组件》。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 注册的回调一次都没触发,日志里没有异常 | 协程被 `StopCoroutine` / `StopAllCoroutines` 提前终止,等待帧结束的 `WaitForEndOfFrame` 没机会执行 | 不要在回调应触发的同一帧停掉协程,或改用其它同步点 |
| 同一个回调被注册多次却只触发一次 | `WaitForEndOfFrameFinishInternal` 是 `IEnumerator` 迭代器方法,传入 `System.Action` 后返回的是**新**迭代器实例,被框架的引用相等性 key 覆盖了旧的跟踪记录 | 把同一个 `WaitForEndOfFrameFinish` 调用视为一次性使用,或在业务层自己排队合并回调 |
| 进入 Play 后协程根本没启动 | 调用方拿到的是父类 `MonoBehaviour` 引用,而 `StartCoroutine` 在该组件上用 `new` 关键字被重写并跟踪,父类调用会绕过跟踪;同时,如果 GameObject 已经 `Destroy` 也无法启动 | 通过 `CoroutineComponent` 类型引用调用,确认组件对象仍处于活动状态 |
| 场景切换 / 退出播放模式后回调再也没触发 | 组件随 GameObject 一同销毁,内部 `m_CoroutineMap` 被清空 | 不要把帧结束回调挂在会被销毁的对象上,而是放到常驻的 `CoroutineComponent` 上 |

## 修复步骤

### 1. 检查是否被 `StopCoroutine` 提前终止

`WaitForEndOfFrameFinish` 的实现是一次性协程:

```csharp
private readonly WaitForEndOfFrame _waitForEndOfFrame = new WaitForEndOfFrame();

private IEnumerator WaitForEndOfFrameFinishInternal(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke();
}

public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(WaitForEndOfFrameFinishInternal(callback));
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

`yield return _waitForEndOfFrame` 必须等到当前帧的渲染结束才会恢复,期间任何 `StopCoroutine` / `StopAllCoroutines` 都会让 `callback?.Invoke()` 这行永远跑不到。

修复:

1. 在 `StopCoroutine` / `StopAllCoroutines` 之前,把回调里要做的副作用改为 `Time.timeScale`、`Application.targetFrameRate` 或对事件的主动发布,而不是依赖 `WaitForEndOfFrameFinish`。
2. 如果一定要取消,先在业务代码里手动执行一次回调,再停掉协程:

```csharp
GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()
    .StopCoroutine(coroutineEnumerator); // 之后再处理自己的清理
```

### 2. 确认调用的是 `CoroutineComponent` 的 `StartCoroutine`

`StartCoroutine` 被 `new` 重写并维护 `m_CoroutineMap`,父类 `MonoBehaviour` 调用会绕过跟踪。`StopCoroutine` 一旦拿不到 key,就找不到要停的协程,看似“没启动成功”:

```csharp
public new UnityEngine.Coroutine StartCoroutine(IEnumerator enumerator)
{
    var ret = base.StartCoroutine(enumerator);
    m_CoroutineMap[enumerator] = ret;
    return ret;
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

修复:所有调用统一通过 `GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()` 取到的实例发起,不要把它隐式转成 `MonoBehaviour`。

### 3. 避免 `StopAllCoroutines` 误清

`StopAllCoroutines` 会清空 `m_CoroutineMap` 并停掉所有已跟踪协程,正在等待帧结束的回调也会被一起丢弃:

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

修复:

1. 调 `StopAllCoroutines` 之前确保没有尚未结算的 `WaitForEndOfFrameFinish` 回调。
2. 把帧结束级别的同步改用 `Update` / `LateUpdate` 或自定义事件,而不是 `WaitForEndOfFrame`。

### 4. 检查对象生命周期

`CoroutineComponent` 是 `MonoBehaviour`,跟随 GameObject 一起销毁;一旦对象 `Destroy` 或所在场景被卸载,等待帧结束的协程随之中断,回调不会再触发。

修复:

1. 把帧结束回调交给常驻的全局 `CoroutineComponent`(由 `GameFrameX` 框架自动创建)执行。
2. 若必须挂在自己脚本上,确保回调在 `OnDestroy` 之前已经触发完成,或自己处理兜底逻辑。

## 验证

1. 在 `WaitForEndOfFrameFinish` 的回调里加一行 `Debug.Log`,Play 模式下确认每帧打印一次,或在回调里触发一次本应执行的逻辑来观察效果。
2. 在协程执行期间主动调用 `StopAllCoroutines`,观察日志:如果回调不再打印,说明问题出在第 1 步;如果正常打印,说明是回调逻辑本身失效。
3. 切换场景或退出 Play,确认 `CoroutineComponent` 实例是否仍然存在 (`GameFrameXEntry` 是否被释放),据此判断是第 4 步的对象生命周期问题。
