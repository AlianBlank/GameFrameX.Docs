# 하트비트 손실 경고 대처 방법

`NetworkMissHeartBeatEventArgs` 이벤트가 반복적으로 트리거되거나 `MissHeartBeatCount`가 지속적으로 증가하면, 하트비트 패킷이 간격 시간 내에 전달되지 못했음을 의미합니다. 이 페이지는 간격 설정, 애플리케이션 포커스, 연결 품질 중 무엇이 손실을 일으켰는지 빠르게 판단하도록 돕고, 해당하는 조치 및 검증 방법을 제공합니다.

## 빠른 진단

| 증상 | 원인 | 조치 |
|------|------|------|
| 모든 하트비트 주기마다 `NetworkMissHeartBeatEventArgs`가 트리거됨 | `HeartBeatInterval` 설정값이 왕복 지연 시간보다 작게 설정됨 | 하트비트 간격을 늘림("하트비트 간격 조정" 참조) |
| 앱이 백그라운드로 전환/포커스 손실 후 하트비트 손실이 집중적으로 발생 | 포커스 손실 시 하트비트 전송이 일시 중지되고, 포커스 복구 후 일괄 전송됨 | 포커스 관련 하트비트 설정 확인("포커스 손실 하트비트 전략" 참조) |
| 하트비트 손실 횟수가 상한에 도달한 후 연결이 닫힘 | 허용된 최대 손실 횟수에 도달하여 채널이 능동적으로 연결을 끊음 | 손실 횟수 상한과 네트워크 품질 확인 |
| 간헐적 손실 후 자체 복구되어 재연결 불필요 | 일회성 네트워크 지터, `Reset`이 카운트를 0으로 초기화함 | 처리 불필요, 경고 빈도 모니터링만 수행 |

## 하트비트 손실 보고 방법

하트비트 손실로 판정될 때마다 프레임워크는 이벤트 시스템을 통해 `NetworkMissHeartBeatEventArgs`를 발생시키며, 이벤트 ID는 `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs`입니다. 이벤트는 두 개의 필드를 포함합니다:

```csharp
public sealed class NetworkMissHeartBeatEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(NetworkMissHeartBeatEventArgs).FullName;

    public override string Id
    {
        get { return EventId; }
    }

    /// <summary>네트워크 채널을 가져옵니다.</summary>
    public INetworkChannel NetworkChannel { get; private set; }

    /// <summary>하트비트 패킷 손실 횟수를 가져옵니다.</summary>
    public int MissCount { get; private set; }

    public static NetworkMissHeartBeatEventArgs Create(INetworkChannel networkChannel, int missCount)
    {
        NetworkMissHeartBeatEventArgs networkMissHeartBeatEventArgs = ReferencePool.Acquire<NetworkMissHeartBeatEventArgs>();
        networkMissHeartBeatEventArgs.NetworkChannel = networkChannel;
        networkMissHeartBeatEventArgs.MissCount = missCount;
        return networkMissHeartBeatEventArgs;
    }
}
```

출처: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L41-L87)

이 이벤트를 처리할 때는 `NetworkChannel`로 어떤 명명된 연결에 문제가 발생했는지 판단하고, `MissCount`로 손실 누적 정도를 판단합니다.

## 조치 단계

### 1. 이벤트 구독 및 손실 출처 확인

네트워크 컴포넌트 초기화 후 하트비트 손실 이벤트를 구독하여 먼저 `NetworkChannel`과 `MissCount`를 확인한 뒤 후속 조치를 결정합니다:

```csharp
// 하트비트 손실 이벤트 구독(이벤트 Id는 NetworkMissHeartBeatEventArgs.EventId)
GameEntry.Event.AddListener(NetworkMissHeartBeatEventArgs.EventId, OnMissHeartBeat);

private void OnMissHeartBeat(object sender, GameEventArgs e)
{
    var args = (NetworkMissHeartBeatEventArgs)e;
    UnityEngine.Debug.LogWarning($"[网络] {args.NetworkChannel.Name} 心跳丢失,累计 {args.MissCount} 次");
}
```

> 참고: 이벤트 객체는 `ReferencePool`에서 가져오며, 프레임워크는 디스패치 완료 후 `Clear()`를 호출하여 `NetworkChannel`과 `MissCount`를 0으로 초기화합니다. 따라서 반드시 콜백 내에서 값을 가져오고, 이벤트 객체를 캐시하지 마세요.

### 2. 하트비트 간격 조정

하트비트는 채널 메인 루프에 의해 구동됩니다. 매 프레임 `ProcessHeartBeat(realElapseSeconds)`를 호출하여 `HeartBeatState.HeartBeatElapseSeconds`를 누적하고, 간격에 도달하면 하트비트를 한 번 전송합니다. `HeartBeatInterval`이 클라이언트에서 서버까지의 왕복 시간보다 작으면 거의 모든 주기에서 손실로 판정됩니다. 진단 및 조치:

1. 클라이언트에서 서버까지의 RTT를 기록합니다(Ping 또는 비즈니스 계층에서 측정 가능).
2. 하트비트 간격을 RTT의 3~5배 이상으로 설정합니다.
3. `HeartBeatInterval`에는 음수 값 검증이 적용되어 있으므로 음수를 전달하지 마세요(CHANGELOG의 "HeartBeatInterval 음수 값 검증 추가" 항목 참조).

하트비트 간격의 경과 시간과 손실 카운트는 모두 `HeartBeatState`에 저장됩니다:

```csharp
public sealed class HeartBeatState
{
    private float _heartBeatElapseSeconds;
    private int _missHeartBeatCount;

    /// <summary>하트비트 간격 시간</summary>
    public float HeartBeatElapseSeconds { get; set; }

    /// <summary>하트비트 손실 횟수</summary>
    public int MissHeartBeatCount { get; set; }

    /// <summary>하트비트 데이터 초기화=>연결 유지</summary>
    public void Reset(bool resetHeartBeatElapseSeconds)
    {
        if (resetHeartBeatElapseSeconds)
        {
            _heartBeatElapseSeconds = 0f;
        }

        _missHeartBeatCount = 0;
    }
}
```

출처: [NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L39-L82)

### 3. 포커스 손실 하트비트 전략 점검

이 패키지의 README에는 "하트비트 패킷 메커니즘(애플리케이션 포커스 획득/손실 시 전송 설정 지원)"이 명시적으로 지원됩니다. 모바일에서 백그라운드로 전환하면 Unity 메인 루프가 제한(throttle)되거나 일시 중지될 수 있어, 하트비트가 간격에 맞춰 전송되지 못하고 포그라운드 복귀 후 손실이 집중적으로 보고될 수 있습니다. 점검 요점:

| 점검 항목 | 권장 방법 |
|--------|----------|
| 포커스 손실 시 하트비트 전송 계속 여부 | 비즈니스가 허용하는 경우 포커스 손실 시 전송을 중지하고, 포커스 복귀 후 `HeartBeatState.Reset(true)`을 호출하여 카운트를 0으로 초기화한 뒤 재개 |
| 포커스 복귀 후 카운트 | 먼저 재설정한 후 전송을 재개하여, 기존 카운트가 즉시 종료 로직을 트리거하지 않도록 함 |
| 서버와의 협의 | 서버 측에서 포커스를 잃은 클라이언트에 대해 하트비트 타임아웃 임계값 완화 |

> CHANGELOG에는 "애플리케이션 포커스 획득 시 하트비트 패킷의 기본 동작 수정"과 "ProcessHeartBeat의 Close 호출을 락 밖으로 이동하여 중첩 락으로 인한 교착 상태 위험 방지"라는 두 가지 수정 사항이 이미 포함되어 있습니다. 구버전에서 포커스 손실 후 손실로 잘못 판정되거나 하트비트 처리가 멈추는 현상이 발생하면 먼저 최신 버전으로 업그레이드하세요.

### 4. 채널 종료 로직 점검

하트비트 처리는 채널 메인 루프 내에 있으며, 매 프레임 `ProcessHeartBeat(realElapseSeconds)`와 `ProcessReceivedMessage()`를 순서대로 실행합니다. 누적 손실이 상한에 도달하면 채널을 닫습니다. 사용 중인 버전에서 이 종료 로직이 멈춤 현상을 일으키는 경우, `Close` 호출을 락 밖으로 이동한 버전으로 업그레이드하세요. 업그레이드 후 하트비트 손실 이후에도 여전히 중단되는지 다시 확인합니다.

## 검증

- 이벤트 콜백에서 `MissCount`를 출력합니다. 정상 네트워크 환경에서는 장기간 0이어야 하며, 간헐적으로 +1된 후 `Reset`으로 0으로 초기화되는 것은 정상적인 지터에 해당합니다.
- 하트비트 간격을 임시로 1초로 설정한 뒤 약한 네트워크 환경에서 테스트하여, 간격을 늘릴수록 경고 빈도가 현저히 감소하는지 확인합니다.
- 백그라운드로 30초 전환했다가 포그라운드로 복귀하여, 집중적인 경고 없이 연결이 사용 가능한 상태로 유지되는지 확인합니다(필요 시 `Reset`으로 카운트를 0으로 초기화).
- 연결 로그를 관찰합니다. 하트비트 손실이 상한에 도달하면 멈춤 현상이나 무한 경고가 아니라 채널 종료 및 연결 끊김 이벤트가 트리거되어야 합니다.
