# IL2CPP 构建后 API 被裁剪怎么办

IL2CPP 后端会通过托管字节码链接器（Unity Linker / IL2CPP stripping）裁剪"未被直接代码引用"的类型与成员。如果在 IL2CPP 打包后调用本库的 API 出现 `MissingMethodException`、`NullReferenceException` 或"明明能跑 Editor 却跑不起来"的现象，就是裁剪导致的。本页给出快速诊断与修复办法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| Editor / Mono 构建正常，IL2CPP 构建后报 `MissingMethodException: void BlankReadAssets::xxx` | 链接器裁剪掉了被反射 / 动态调用的入口 | 确认依赖包随附 `Runtime/link.xml` 已打入；或为自定义调用点补 `[Preserve]` |
| 调用 `BlankReadAssets.OpenRead` 等 API 返回 `null` 或抛空引用，但链接器未报错 | 命名空间 / 内部类被裁，导致实现分支被剥成空壳 | 重新确认 `link.xml` 覆盖 `GameFrameX.ReadAssets.Runtime` 和 `GameFrameX.ReadAssets.Runtime.ZipArchive` 命名空间 |
| 出包后所有平台正常，但 Android IL2CPP StreamingAssets 读取返回空 | `ApkImpl` / `LooseFilesImpl` 实现类被剥，平台分支走到无实现的兜底 | 检查是否启用了 Managed Stripping，必要时在 Player Settings 关闭 Strip Engine Code 或补 link.xml |

## 修复步骤

### 1. 确认依赖包里的 `link.xml` 已经存在并随包发布

本仓库在 `Runtime/link.xml` 中显式声明了需要保留的程序集与命名空间，Unity Linker 在打包时自动拾取：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="BlankReadAssets.Runtime" preserve="all">
        <namespace fullname="GameFrameX.ReadAssets.Runtime" preserve="all"/>
        <namespace fullname="GameFrameX.ReadAssets.Runtime.ZipArchive" preserve="all"/>
    </assembly>
</linker>
```

Source: [Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/link.xml#L1-L7)

确认方式：解压出 `.apk` / `.ipa` / 构建产物，在 `*_Data/Managed` 同级或 `Assets/` 下能找到一份 `link.xml`，且其内容含 `BlankReadAssets.Runtime`。UPM 包通过 `package.json` 的 `samples` / 直接文件方式打入此文件。

### 2. 检查 Player Settings 里的 Strip 等级

`Project Settings → Player → Other Settings → Managed Stripping`：

| 等级 | 风险 | 建议 |
|------|------|------|
| Disabled | 不会被裁，但包体更大 | 临时验证用 |
| Low | 仅裁明显无用代码 | 通常够用 |
| Medium / High | 反射、动态加载的代码可能被裁 | 必须配套 `link.xml` |

如果你的工程把 Managed Stripping 设为 High，再走第 3 步为反射点补 `[Preserve]`。

### 3. 公开 API 自带 `[Preserve]`，新接入代码可同样标注

本库所有公开 API 已标注 `[Preserve]`，示例如下：

```csharp
[Preserve]
public static string Root
{
    get
    {
        EnsureInitialized();
        return BlankReadAssetsImpl.s_root;
    }
}

[Preserve]
public static void Initialize()
{
    BlankReadAssetsImpl.Initialize(Application.dataPath, Application.streamingAssetsPath);
    s_initialized = true;
}
```

Source: [Runtime/BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L37-L68)

当你的业务层通过反射（例如 `Type.GetMethod("OpenRead")`）调用本库时，Unity Linker 看不到调用关系；给入口或包装方法加 `[Preserve]` 即可保留：

```csharp
using UnityEngine.Scripting;

[Preserve]
public static Stream OpenAsset(string file)
{
    return BlankReadAssets.OpenRead(file);
}
```

### 4. 通过自定义 link.xml 兜底（不推荐作为唯一手段）

在工程的 `Assets/link.xml` 追加一段，把你间接用到的命名空间也保留：

```xml
<linker>
    <assembly fullname="YourGame" preserve="all"/>
</linker>
```

这等同于"全保留某个程序集"，仅作为最后兜底，避免长期依赖。

## 验证

完成修复后，按以下顺序验证：

1. **本地重打 IL2CPP 出包**：`File → Build Settings → Player Settings → Other Settings → Configuration → Scripting Backend = IL2CPP`，重新 Build And Run（或 `Build`）。
2. **用 Release 构建复现**：Editor IL2CPP 后端仅在打包后才会执行链接器，Editor 中无法复现裁剪问题。
3. **检查出包里残留符号**：用 `il2cppdumper` / `ilspycmd` 反解 `il2cpp.so` 或 `*_Data/Managed` 中的 metadata，确认 `BlankReadAssets` 类型与调用入口仍在。
4. **加日志围栏**：在调用前后写一行 `Debug.Log`，运行后查看 logcat / Player.log 是否走到了入口。若走到入口仍报错，问题就不在裁剪，而在运行期逻辑。

## 背景（可选）

Unity Linker 默认按"代码直接引用"裁剪，跨程序集的反射、`Activator.CreateInstance`、字符串名查类型都会丢失调用图。本库的 `Runtime/link.xml` 在打包阶段显式保留 `BlankReadAssets.Runtime` 程序集与 `ZipArchive` 命名空间，连同公开 API 上的 `[Preserve]` 形成双保险；只要这两条都生效，IL2CPP 出包后 API 不会被裁。
