# How to Manually Initialize (ManualInit Use Cases)

After the GameAnalytics component's automatic initialization completes, calling `GameAnalyticsComponent.ManualInit(extraArgs)` can pass supplementary **parameters that are only available at runtime**, such as the logged-in player ID and channel number, to data analytics managers that support manual initialization. Typical scenario: an SDK needs to wait until the player logs in and an account is available before it can actually report data; in this case, simply call `ManualInit` once in the login success callback.

## Prerequisites

- The scene already contains a `GameAnalyticsComponent` (menu `Game Framework/GameAnalytics`), and at least one `ComponentType` with its `Setting` key-value pairs has been configured in the Inspector's "Game analytics component list, reported in order".
- The target manager implements `IsManualInit()` and returns `true` when manual initialization is needed — only these kinds of managers will receive the parameters passed to `ManualInit`.

## Steps

1. **Keep the component's automatic initialization available.** The component automatically executes `Init()` once in `OnEnable()`, uses reflection to create each manager based on the Inspector configuration and calls their `Init(args)` (parameters come from the `Setting` key-value pairs), then sets the internal flag `m_IsInit` to `true`:

    ```csharp
    private void OnEnable()
    {
        Init();
    }
    ```

    Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L27-L30)

2. **Confirm that automatic initialization has taken effect.** Check that the Console shows no `Can not find component type '...'` error; this error indicates that the `ComponentType` in the Inspector is filled in incorrectly, in which case the corresponding manager will not be created, and subsequent `ManualInit` calls will never reach it either.

3. **Call `ManualInit` at an appropriate time, passing in runtime parameters.** For example, after the player logs in successfully and the account ID/channel information has been obtained, call it once via the `GameAnalyticsComponent` instance in the scene:

    ```csharp
    Dictionary<string, string> extraArgs = new Dictionary<string, string>();
    // Fill in data that can only be determined at runtime, such as account, channel, etc.
    gameAnalyticsComponent.ManualInit(extraArgs);
    ```

    The actual implementation at the component level is as follows — note that it first checks `m_IsInit`, then only forwards parameters to managers whose `IsManualInit()` is `true`:

    ```csharp
    public void ManualInit(Dictionary<string, string> extraArgs)
    {
        if (!m_IsInit)
        {
            return;
        }

        foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
        {
            if (gameAnalyticsManager.IsManualInit())
            {
                gameAnalyticsManager.ManualInit(extraArgs);
            }
        }
    }
    ```

    Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L82-L100)

4. **(Optional) Add common information such as the player ID after manual initialization.** `ManualInit` only passes parameters through and is not responsible for subsequent properties; after login, you can continue to call `SetPlayerId(playerId)` / `SetPublicProperties(key, value)`, which likewise require `m_IsInit == true`.

## Common Variants

- **No extra parameters, only triggering each SDK's "ready" callback**: just call `gameAnalyticsComponent.ManualInit(new Dictionary<string, string>());` with an empty dictionary; the manager side decides how to handle it on its own.
- **Integrating a custom manager with manual initialization**: inherit from `BaseGameAnalyticsManager` and implement the two abstract methods; returning `true` from `IsManualInit()` is enough for the component to forward `extraArgs` to you:

    ```csharp
    public abstract void Init(Dictionary<string, string> args);
    public abstract void ManualInit(Dictionary<string, string> args);
    ...
    public abstract bool IsManualInit();
    ```

    Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L28-L50)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Calling `ManualInit` has no effect | The component's `Init()` has not executed yet, `m_IsInit` is `false`, and the method returns directly on the first line | Wait until the component's `OnEnable()` has completed automatic initialization before calling (login callbacks and similar timings usually already satisfy this) |
| A manager does not receive `extraArgs` | That manager's `IsManualInit()` returns `false` | Make `IsManualInit()` return `true` in the manager implementation |
| Console outputs `Can not find component type '...'` | The `ComponentType` type name in the Inspector is filled in incorrectly, or the assembly is not compiled | Fix `ComponentType` and make sure the type implements `IGameAnalyticsManager` |
| SDK parameters still show the old values from the Inspector's `Setting` | The parameters passed to `ManualInit` are supplementary and do not replace the base parameters provided by `Setting` during `Init` | Keep base configuration in the Inspector's `Setting`; use `ManualInit` for runtime data |

## Background

GameAnalytics uses a "two-layer initialization": `Init(args)` executes automatically with the static configuration from the Inspector's `Setting` when the component's `OnEnable()` runs, and is responsible for creating the managers; `ManualInit(extraArgs)` is aimed at SDKs that need runtime data (such as the account after login), is explicitly triggered by the business at a well-defined time, and only affects managers that declare `IsManualInit() == true`. See [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L28) for the complete interface definition.
