# 生命周期回调

`ProcedureBase` 继承自 `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`,每个流程(Procedure)按有限状态机(FSM)的约定,在创建、进入、轮询、离开、销毁阶段各自触发一个虚方法,这些就是流程的**生命周期回调**。子类重写即可挂载业务逻辑。

## 回调速查

| 回调 | 签名 | 触发时机 |
|------|------|----------|
| `OnInit` | `protected override void OnInit(IFsm<IProcedureManager> procedureOwner)` | 状态机初始化时(每个流程实例一次) |
| `OnEnter` | `protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)` | 切换到本流程时 |
| `OnUpdate` | `protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 每帧轮询(逻辑流逝/真实流逝) |
| `OnFixedUpdate` | `protected override void OnFixedUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 固定步长轮询 |
| `OnLeave` | `protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)` | 离开本流程时;`isShutdown=true` 表示是状态机关闭引发的离开 |
| `OnDestroy` | `protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)` | 状态机销毁时(每个流程实例一次) |

全部方法默认实现都只是 `base.Xxx(...)`,可重写但**应保留 `base` 调用**以维持基类行为。

## 参数说明

| 参数 | 含义 |
|------|------|
| `procedureOwner` | 持有本流程的状态机对象,类型为 `IFsm<IProcedureManager>`。可通过它访问流程管理器(`procedureOwner.Owner`)、切换流程等。 |
| `elapseSeconds` | 受时间缩放影响的逻辑流逝时间(秒)。 |
| `realElapseSeconds` | 不受时间缩放影响的真实流逝时间(秒)。 |
| `isShutdown` | 在 `OnLeave` 中为 `true` 时,表示本次离开是因为状态机被关闭,而非正常切换。 |

## 触发时机(与管理器 API 对应)

| 管理器操作 | 触发的回调(在该流程实例上) |
|------------|----------------------------|
| `Initialize(fsmManager, procedures...)` | 每个传入的流程依次 `OnInit` |
| `StartProcedure<T>()` / `StartProcedure(Type)` | 目标流程 `OnEnter`;若已有当前流程,则先对旧流程 `OnLeave(isShutdown=false)` |
| 状态机心跳(每帧) | 当前流程 `OnUpdate` 与 `OnFixedUpdate` |
| `DestroyProcedures()` | 当前流程 `OnLeave(isShutdown=true)`,随后所有已注册流程依次 `OnDestroy` |
| `ReinitializeProcedures(procedures...)` | 等同于先 `DestroyProcedures()`,再用新流程数组重新 `Initialize` |

## 最小用法

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

public class MyProcedure : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // 初始化本流程所需的资源、缓存等
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 进入本流程时启动 UI、注册事件等
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner,
        float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        // 每帧业务逻辑(达到条件时通过 procedureOwner 切换流程)
    }

    protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)
    {
        base.OnLeave(procedureOwner, isShutdown);
        // 清理 UI、注销事件
        // isShutdown == true 时表示状态机被整体关闭
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // 释放本流程持有的资源
    }
}
```

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 重写后忘记 `base.OnXxx(...)`,导致状态机内部状态异常 | 基类可能维护了状态统计、计时器等隐式行为 | 始终在重写末尾调用 `base.OnXxx(...)` |
| 在 `OnInit` 里调用 `StartProcedure` 切换流程 | `Initialize` 阶段流程尚未 `OnEnter`,提前切换会让状态机处于不一致状态 | 改在 `OnEnter` 或后续 `OnUpdate` 中切换 |
| 在 `OnDestroy` 里访问 `procedureOwner` 的其他流程 | 销毁阶段状态机内部状态正在回收 | 跨流程引用改为在 `OnEnter` 时缓存,`OnLeave` 时清理 |
| 用 `OnUpdate` 做一次性初始化 | `OnUpdate` 每帧调用,会重复触发 | 一次性逻辑放在 `OnInit` 或 `OnEnter` |
| 期望 `OnEnter` 在每次 `Initialize` 时都被调用 | `OnInit` 才是初始化时唯一调用,`OnEnter` 只在状态切换时调用 | 启动逻辑放 `OnEnter`,数据准备放 `OnInit` |
