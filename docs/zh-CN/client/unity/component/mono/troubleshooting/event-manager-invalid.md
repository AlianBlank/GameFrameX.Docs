# 日志报 "Event manager is invalid." 怎么办

当 `MonoComponent` 在场景中启动后无法从 `GameEntry` 取得 `EventComponent` 实例时,会在日志中打印 `Event manager is invalid.` 并中止后续初始化流程,导致 Mono 模块的事件订阅/发布全部失效。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动时报 `Event manager is invalid.` | 启动场景里没有挂载 `EventComponent` | 在启动场景的 `GameFramework` 节点上添加 `EventComponent`,见下文修复步骤 1 |
| 启动时报 `Event manager is invalid.` | 启动场景挂载了 `EventComponent`,但 `MonoComponent` 的脚本执行顺序早于 `EventComponent.Awake` | 在 Project Settings 中把 `MonoComponent` 的 Script Execution Order 调到 `Default` 之后,见修复步骤 2 |
| 启动时报 `Event manager is invalid.` | 同一组件上额外挂了重复的 `EventComponent`,导致 `GameEntry` 中保存的实例被覆盖/释放 | 移除多余的 `EventComponent`,确保框架入口节点上只有一份 |

## 修复步骤

### 1. 在启动场景添加 EventComponent

`MonoComponent.Start()` 通过 `GameEntry.GetComponent<EventComponent>()` 获取事件组件;只有挂在 GameFramework 启动对象上的组件才能被 `GameEntry` 索引到。

1. 打开工程中的启动场景(例如 `Assets/GameFrameX/Launch/Launch.unity`)。
2. 选中 `GameFramework` 根 GameObject。
3. Inspector → Add Component → 搜索并添加 `GameFrameX.Event.EventComponent`。
4. 重新运行,日志应不再出现 `Event manager is invalid.`。

参考报错位置:

```csharp
// 来源:Runtime/Mono/MonoComponent.cs
private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76)

### 2. 检查脚本执行顺序

`MonoComponent.Start()` 在所有组件 `Awake` 之后才执行,但若项目自定义了 Script Execution Order 把 `MonoComponent` 提前,可能拿到尚未注册到 `GameEntry` 的 `EventComponent`。

1. Edit → Project Settings → Script Execution Order。
2. 把 `MonoComponent` 拖到 `Default Time` 之后,或显式指定一个晚于 `EventComponent` 的 Order 值。
3. 重新运行验证。

### 3. 检查重复挂载或场景残留

如果同一个 GameObject 上被手动添加了多个 `EventComponent`,或者旧场景里残留了旧的 `EventComponent` 而新代码在另一对象上实例化了它,`GameEntry.GetComponent` 会因为类型重复返回空引用。

1. 在 Hierarchy 中搜索 `t:EventComponent`,确认只有一处实例。
2. 删除多余实例后再次运行。

## 验证

1. 运行场景,打开 Console,搜索 `Event manager is invalid.`,应不再出现。
2. 在 `MonoComponent` 所在对象上挂一个测试脚本,在 `Start` 中调用 `GameEntry.GetComponent<EventComponent>()` 并断言非空。
3. 走通一次完整的事件订阅/发布流程(`Subscribe` → `Fire` → `Unsubscribe`),确认事件能正常到达监听者。

## 背景(可选)

`MonoComponent` 把 `EventComponent` 的引用缓存在 `m_EventComponent` 字段,后续 `OnApplicationFocus` 等生命周期回调都会复用它。一旦 `Start` 阶段拿不到引用,字段保持 null,后续事件相关的初始化会被静默跳过——这也是为什么错误只出现一次、但功能却不工作的原因。

关于 Mono 模块的整体接入流程,见《如何接入 Mono 模块》。
