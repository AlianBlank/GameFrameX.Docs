# Troubleshooting

This document summarizes在Uses GameFrameX Procedure 流程Manages组件时可能遇到的Troubleshooting、error及其解决方案。

## 概述

Procedure 流程Manages组件是基于 Game Framework 的有限状态机（FSM）Implements的游戏流程Manages系统。在集成和Uses过程中，开发者经常会遇到configurationerror、Depends on缺失、Typeparsefailure等问题。本文档旨在帮助开发者快速定位和解决这些问题。

## Depends on问题

### FSMComponent 未正确configuration

**症状**: 游戏start后无响应或报 `Procedure manager is invalid.` error

**原因**: ProcedureComponent Depends on `IProcedureManager` 模块，该模块需要through `GameFrameworkEntry` get。如果 FSMComponent 未正确Initialize，可能导致模块getfailure。

**解决方案**:
1. ensure场景中已add `FSMComponent` 组件
2. 确认 `GameFrameworkEntry` 已正确Initialize所有必需模块
3. check GameFramework 的Initializesequential，ensure先Initialize基础组件

> Source: [ProcedureComponent.cs#L64-L68](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L64-L68)

---

### 缺少必要的 GameFramework 组件

**症状**: 运行时出现 NullReferenceException 或模块getfailure

**原因**: GameFramework 是一套完整的组件体系，Procedure 组件Depends on多个底层模块

**解决方案**:
1. ensure已installation GameFrameX 核心库
2. check项目是否contains以下Depends on:
   - `GameFrameX.Fsm.Runtime` - 有限状态机模块
   - `GameFrameX.Runtime` - 核心运行时模块

## configuration问题

### 流程Type名称configurationerror

**症状**: 控制台显示 `Can not find procedure type '{0}'.` error

**原因**: `m_AvailableProcedureTypeNames` 数组中configuration的流程Type名称与实际类名不匹配

**解决方案**:
1. check Inspector 面板中的 `Available Procedure Type Names` configuration
2. ensureType名称Uses完整的类名（includingNamespace）
3. 流程类必须Inherits自 `ProcedureBase`

```csharp
// 正确示例
namespace MyGame.Procedure
{
    public class ProcedureLaunch : ProcedureBase
    {
        // 流程实现
    }
}
```

configuration时填入: `MyGame.Procedure.ProcedureLaunch`

> Source: [ProcedureComponent.cs#L76-L81](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L76-L81)

---

### 入口流程未set

**症状**: 控制台显示 `Entrance procedure is invalid.` error

**原因**: `m_EntranceProcedureTypeName` 未set或set的值不在 `m_AvailableProcedureTypeNames` 列表中

**解决方案**:
1. 在 Inspector 面板中set `Entrance Procedure Type Name`
2. ensure入口流程名称与 `Available Procedure Type Names` 中的某个流程完全匹配
3. 入口流程是游戏start后第一个执行的流程

> Source: [ProcedureComponent.cs#L90-L100](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L90-L100)

---

### 流程数组为空

**症状**: start时无任何流程执行，或出现数组越界error

**原因**: `m_AvailableProcedureTypeNames` 未configuration或为空

**解决方案**:
1. 在 ProcedureComponent 的 Inspector 面板中，至少add一个流程Type
2. 建议至少contains以下基础流程:
   - start流程 (ProcedureLaunch)
   - 热update流程 (ProcedureCheckVersion)
   - 登录流程 (ProcedureLogin)
   - 游戏流程 (ProcedureGame)

## Typeparse问题

### 程序集Typegetfailure

**症状**: `Utility.Assembly.GetType()` 返回 null，导致流程Createsfailure

**原因**:
1. Type名称拼写error
2. 流程类未编译到程序集中
3. Uses了error的程序集configuration

**解决方案**:
1. 确认流程类已正确编译
2. Uses完整的Type名称（includingNamespace）
3. 对于混淆后的代码，ensure相关程序集configuration正确

```csharp
// 错误的类型名称
m_AvailableProcedureTypeNames = new[] { "ProcedureLaunch" };

// 正确的类型名称
m_AvailableProcedureTypeNames = new[] { "GameFrameX.Procedure.Runtime.ProcedureLaunch" };
```

> Source: [ProcedureComponent.cs#L83-L88](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L83-L88)

---

### 流程实例Createsfailure

**症状**: `Can not create procedure instance '{0}'.` error

**原因**:
1. 流程类缺少无参构造函数
2. 构造函数抛出Exception
3. 流程类的构造函数Access了尚未Initialize的系统

**解决方案**:
1. ensure流程类具有无参构造函数
2. 不要在构造函数中Access ProcedureManager 或其他 GameFramework 组件
3. Uses `OnInit`、`OnEnter` 等生命周期Method进行Initialize

```csharp
// 推荐: 在 OnEnter 中进行初始化
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 在这里进行初始化操作
    }
}
```

## 运行时问题

### 流程Manages器未Initialize

**症状**: 调用 `CurrentProcedure` 或 `CurrentProcedureTime` 时抛出Exception `You must initialize procedure first.`

**原因**: 在 ProcedureManager Initializecomplete之前Access了相关Property

**解决方案**:
1. ensure在 `Start()` Method执行完毕后再Access流程Manages器
2. Uses协程或Event System等待Initializecomplete

```csharp
// 错误示例: 在 Awake 中立即访问
private void Awake()
{
    var current = CurrentProcedure; // 会抛出异常
}

// 正确示例: 在协程中等待
private IEnumerator Start()
{
    yield return new WaitForEndOfFrame();
    var current = CurrentProcedure; // 现在可以正常访问
}
```

> Source: [ProcedureManager.cs#L48-L55](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L48-L55)

---

### 流程切换failure

**症状**: 调用 `StartProcedure<T>()` 后流程未切换

**原因**:
1. 指定的流程Type未在Initialize时register
2. FSM 状态机已被destroy
3. 流程切换逻辑存在死循环

**解决方案**:
1. ensure要切换的目标流程在 `m_AvailableProcedureTypeNames` 中
2. check是否有代码在流程切换时立即切回原流程
3. Usesdebuglog确认切换调用是否执行

> Source: [ProcedureManager.cs#L116-L124](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L116-L124)

---

### 流程状态Method未被调用

**症状**: 自定义的 `OnEnter`、`OnUpdate`、`OnLeave` 等Method未被执行

**原因**: 流程类未正确Inherits `ProcedureBase`，或Method未正确重写

**解决方案**:
1. ensure流程类Inherits自 `ProcedureBase`
2. Uses `override` 关键字重写父类Method
3. 调用 `base.OnEnter()` 等Method以ensure父类逻辑执行

```csharp
// 正确示例
public class ProcedureLogin : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner); // 必须调用
        // 自定义逻辑
    }
}
```

> Source: [ProcedureBase.cs#L31-L35](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L31-L35)

## Debugging Tips

### 启用debuglog

在开发过程中，可以add详细的log输出来帮助定位问题:

```csharp
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        Debug.Log("进入 ProcedureLaunch 流程");
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        Debug.Log($"ProcedureLaunch 已运行 {procedureOwner.CurrentStateTime:F2} 秒");
    }
}
```

### check流程状态

可以Uses `ProcedureComponent` provides的Methodcheck流程状态:

```csharp
// 检查是否存在指定流程
bool hasLogin = procedureComponent.HasProcedure<ProcedureLogin>();

// 获取当前流程
ProcedureBase current = procedureComponent.CurrentProcedure;

// 获取流程持续时间
float duration = procedureComponent.CurrentProcedureTime;
```
