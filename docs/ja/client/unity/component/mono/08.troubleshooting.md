# 常见问题解答

本文档汇总了使用 GameFrameX Unity Mono 生命周期コンポーネント时常见的疑问解答。

## 概要

Mono 生命周期コンポーネント是 GameFrameX フレームワーク的コア模块之一，に使用统一管理 Unity MonoBehaviour 的各种生命周期イベント，包括 Update、FixedUpdate、LateUpdate、OnDestroy、OnApplicationFocus 和 OnApplicationPause。本文档旨在帮助開発者快速解决使用过程中遇到的常见问题。

## 依赖问题

### Q1: 编译报错找不到 GameFrameX.Runtime 名前空間

**问题説明：**
在プロジェクト中添加 Mono コンポーネント后，编译出现クラス似以下错误：
```
The type or namespace name 'Runtime' does not exist in the namespace 'GameFrameX'
```

**原因分析：**
Mono コンポーネント依赖于 GameFrameX コア运行时库。该库是整个 GameFrameX フレームワーク的基础，必須首先安装。

**解決策：**
必要安装 `com.alianblank.gameframex.unity.runtime` 包。安装方法是在プロジェクト的 `manifest.json` 中添加依赖：

```json
{
  "dependencies": {
    "com.alianblank.gameframex.unity.runtime": "https://github.com/GameFrameX/com.alianblank.gameframex.unity.runtime.git"
  }
}
```

> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/README.md#L42)

### Q2: 编译报错找不到 Event コンポーネント

**问题説明：**
编译时出现以下错误：
```
The type or namespace name 'Event' does not exist in the namespace 'GameFrameX'
```

**原因分析：**
MonoComponent 在 `OnApplicationFocus` 和 `OnApplicationPause` イベント触发时，会を通じて EventComponent 发布ゲームイベント。因此必要安装 Event コンポーネント。

**解決策：**
安装 Event コンポーネント包：

```json
{
  "dependencies": {
    "com.alianblank.gameframex.unity.event": "https://github.com/GameFrameX/com.alianblank.gameframex.unity.event.git"
  }
}
```

## 使用问题

### Q3: 如何注册 Update 监听器？

**问题説明：**
開発者想要在ゲーム每帧执行特定逻辑，但不想作成额外的 MonoBehaviour 脚本。

**解決策：**
使用 MonoComponent 提供的监听器メソッド。首先必要在シーン中确保有 MonoComponent コンポーネント（通常由 GameFramework 自动作成），然后を通じて该コンポーネント注册监听器：

```csharp
// 取得 MonoComponent インスタンス（を通じて Unity コンポーネント或 GameEntry）
var monoComponent = GameEntry.GetComponent<MonoComponent>();

// 注册 Update 监听器
monoComponent.AddUpdateListener(OnGameUpdate);

// 定义回调メソッド
private void OnGameUpdate(float elapseSeconds, float realElapseSeconds)
{
    // elapseSeconds: 流逝时间
    // realElapseSeconds: 真实流逝时间
    Debug.Log($"Update called, elapsed: {elapseSeconds}");
}

// 重要：不再使用时必要移除监听器
monoComponent.RemoveUpdateListener(OnGameUpdate);
```

> Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L186-L210)

### Q4: Update、FixedUpdate、LateUpdate 有什么区别？

**问题説明：**
这三个メソッド都有对应的监听器，開発者不清楚べき选择哪一个。

**技术説明：**
- **Update**：每帧呼び出し一次，呼び出し间隔不固定，受帧率影响。适合大多数ゲーム逻辑。
- **FixedUpdate**：固定时间间隔呼び出し（默认 0.02 秒，即 50 次/秒）。适合物理関連的逻辑。
- **LateUpdate**：在所有 Update 呼び出し完成后呼び出し。适合跟随摄像机等必要在其他更新后执行的逻辑。

**使用建议：**
- 普通ゲーム逻辑 → 使用 Update
- 物理计算関連 → 使用 FixedUpdate
- 相机跟随、UI 更新等 → 使用 LateUpdate

```csharp
// Update 示例 - 每帧执行
monoComponent.AddUpdateListener((elapsed, realElapsed) => {
    // ゲーム主逻辑
});

// FixedUpdate 示例 - 固定间隔执行
monoComponent.AddFixedUpdateListener((elapsed, fixedElapsed) => {
    // 物理逻辑
});

// LateUpdate 示例 - 最后执行
monoComponent.AddLateUpdateListener((elapsed, fixedElapsed) => {
    // 相机跟随等
});
```

> Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L63-L76)

### Q5: 监听器传入 null 会发生什么？

**问题説明：**
開発者在注册监听器时不小心传入了 null，想知道会发生什么。

**代码行为：**
查看源代码可能发现，系统会对 null 参数进行检测并抛出異常：

```csharp
public void AddUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + "is invalid.");
        return;
    }
    _monoManager.AddUpdateListener(fun);
}
```

MonoComponent 中传入 null 会记录致命日志并直接返回，不会抛出異常。而 MonoManager 中传入 null 会抛出 `ArgumentNullException`。

> Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L176-L187)

### Q6: 如何监听应用程序暂停/恢复イベント？

**问题説明：**
開発者必要在玩家切换到后台或恢复ゲーム时执行特定操作。

**解決策：**
使用 `OnApplicationPause` 监听器：

```csharp
// 注册暂停监听器
monoComponent.AddOnApplicationPauseListener(OnApplicationPauseChanged);

// 回调メソッド
private void OnApplicationPauseChanged(bool isPaused)
{
    if (isPaused)
    {
        Debug.Log("ゲーム已暂停");
        // 保存ゲーム数据
    }
    else
    {
        Debug.Log("ゲーム已恢复");
        // 恢复ゲームステータス
    }
}
```

同样地，可能使用 `OnApplicationFocusListener` 监听焦点变化：

```csharp
monoComponent.AddOnApplicationFocusListener(OnApplicationFocusChanged);

private void OnApplicationFocusChanged(bool hasFocus)
{
    Debug.Log($"应用程序焦点: {hasFocus}");
}
```

> Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L246-L270)

### Q7: 为什么推荐使用 MonoComponent 而不是直接使用 MonoManager？

**问题説明：**
開発者可能直接を通じて `GameFrameworkEntry.GetModule<IMonoManager>()` 取得 MonoManager，为什么还要使用 MonoComponent？

**设计説明：**
MonoComponent を継承 Unity 的 MonoBehaviour，具有以下优势：

1. **自动生命周期绑定**：MonoComponent 自动绑定到 Unity 的生命周期メソッド（Update、OnDestroy 等），无需手动呼び出し。
2. **与 GameFramework 无缝集成**：MonoComponent 是 GameFramework 的コンポーネント体系的一部分，可能方便地を通じて GameEntry 访问。
3. **编辑器友好**：MonoComponent 带有 `[DisallowMultipleComponent]` 和 `[AddComponentMenu("GameFrameX/Mono")]` プロパティ，在 Unity 编辑器中易于查找和管理。

```csharp
// を通じて GameEntry 取得 MonoComponent
var monoComponent = GameEntry.GetComponent<MonoComponent>();

// 或者直接在シーン中的 GameObject 上取得
var monoComponent = someGameObject.GetComponent<MonoComponent>();
```

> Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L42-L70)

## 生命周期管理问题

### Q8: 不移除监听器会有什么后果？

**问题説明：**
開発者在シーン切换或对象销毁时忘记移除监听器，想知道会产生什么问题。

**可能后果：**
1. **内存泄漏**：监听器引用的对象无法被垃圾回收。
2. **空引用異常**：监听器回调尝试访问已销毁的对象。
3. **逻辑错误**：过期的监听器可能执行不正确的ゲーム逻辑。

**最佳实践：**
始终在适当的时机移除监听器，例如：

```csharp
public class MyController : MonoBehaviour
{
    private MonoComponent _monoComponent;

    private void OnEnable()
    {
        _monoComponent = GameEntry.GetComponent<MonoComponent>();
        _monoComponent.AddUpdateListener(OnUpdate);
        _monoComponent.AddDestroyListener(OnDestroy);
    }

    private void OnDisable()
    {
        if (_monoComponent != null)
        {
            _monoComponent.RemoveUpdateListener(OnUpdate);
            _monoComponent.RemoveDestroyListener(OnDestroy);
        }
    }

    private void OnUpdate(float elapse, float realElapse) { }
    private void OnDestroy() { }
}
```

### Q9: MonoManager 是线程安全的吗？

**问题説明：**
開発者在多线程环境下使用监听器，想知道是否存在线程安全问题。

**技术説明：**
是的，MonoManager 是线程安全的。所有监听器的添加和移除操作都使用了 `lock` 锁来保护：

```csharp
public void AddUpdateListener(Action<float, float> action)
{
    if (action == null)
    {
        throw new ArgumentNullException(nameof(action));
    }

    lock (Lock)
    {
        _updateQueue.AddLast(action);
    }
}
```

但お願いします注意，监听器回调本身的执行是在 Unity 主线程中呼び出し的，因此不必要担心回调中的线程安全问题。

> Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L364-L380)

## イベント系统问题

### Q10: 如何を通じてイベント系统监听应用程序ステータス变化？

**问题説明：**
除了使用监听器回调，開発者还想を通じてイベント系统（EventSystem）来响应应用程序ステータス变化。

**解決策：**
MonoComponent 在触发 OnApplicationFocus 和 OnApplicationPause 时会同时发布ゲームイベント。可能を通じて订阅这些イベント来响应：

```csharp
// 订阅イベント
EventComponent eventComponent = GameEntry.GetComponent<EventComponent>();
eventComponent.Subscribe<OnApplicationFocusChangedEventArgs>(OnFocusChanged);
eventComponent.Subscribe<OnApplicationPauseChangedEventArgs>(OnPauseChanged);

// イベント处理メソッド
private void OnFocusChanged(object sender, OnApplicationFocusChangedEventArgs e)
{
    Debug.Log($"焦点变化: {e.IsFocus}");
}

private void OnPauseChanged(object sender, OnApplicationPauseChangedEventArgs e)
{
    Debug.Log($"暂停ステータス: {e.IsPause}");
}

// 取消订阅
eventComponent.Unsubscribe<OnApplicationFocusChangedEventArgs>(OnFocusChanged);
eventComponent.Unsubscribe<OnApplicationPauseChangedEventArgs>(OnPauseChanged);
```

> Source: [OnApplicationFocusChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationFocusChangedEventArgs.cs#L40-L87)

## 安装问题

### Q11: 如何安装 Mono コンポーネント？

**问题説明：**
初次使用该插件，不清楚如何正确安装。

**解決策：**
有三种安装方法可供选择：

**方法一：を通じて manifest.json 安装（推荐）**
在プロジェクト的 `Packages/manifest.json` ファイル中添加依赖：

```json
{
  "dependencies": {
    "com.gameframex.unity.mono": "https://github.com/GameFrameX/com.gameframex.unity.mono.git"
  }
}
```

**方法二：を通じて Unity Package Manager**
1. 打开 Unity 编辑器
2. 进入 Window → Package Manager
3. 点击 + 按钮，选择 "Add package from git URL"
4. 输入：`https://github.com/GameFrameX/com.gameframex.unity.mono.git`

**方法三：直接ダウンロード放置**
直接从 GitHub ダウンロード仓库，将内容复制到 Unity プロジェクト的 `Packages` ディレクトリ下，系统会自动识别加载。

> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/README.md#L44-L51)

## 架构图

以下图表展示了 Mono コンポーネント的内部架构和イベント流：

```mermaid
flowchart TD
    subgraph Unity["Unity 引擎层"]
        Update["Update()"]
        FixedUpdate["FixedUpdate()"]
        LateUpdate["LateUpdate()"]
        OnDestroy["OnDestroy()"]
        OnAppFocus["OnApplicationFocus()"]
        OnAppPause["OnApplicationPause()"]
    end

    subgraph MonoComponent["MonoComponent"]
        Awake["Awake()"]
        Listeners["监听器メソッド<br/>AddXXXListener<br/>RemoveXXXListener"]
    end

    subgraph MonoManager["MonoManager"]
        Queues["监听器队列<br/>LinkedList&lt;Action&gt;"]
        Invoke["QueueInvoking()"]
    end

    subgraph EventSystem["Event 系统"]
        EventComp["EventComponent"]
        FocusEvent["OnApplicationFocusChangedEventArgs"]
        PauseEvent["OnApplicationPauseChangedEventArgs"]
    end

    Unity --> MonoComponent
    MonoComponent --> Listeners
    Listeners --> MonoManager
    MonoManager --> Queues
    MonoManager --> Invoke
    MonoComponent --> EventComp
    EventComp --> FocusEvent
    EventComp --> PauseEvent
```

**图解説明：**
1. Unity 引擎的生命周期メソッド自动呼び出し到 MonoComponent
2. MonoComponent 暴露公共监听器メソッド供外部呼び出し
3. MonoManager 内部使用线程安全的 LinkedList 存储监听器
4. OnApplicationFocus 和 OnApplicationPause イベント还会发布到 Event 系统
