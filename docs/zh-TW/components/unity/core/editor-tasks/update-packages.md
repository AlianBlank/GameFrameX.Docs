# 批量更新項目依賴

透過 `UpdateAllPackageHelper` 一鍵批次更新 `Packages/manifest.json` 中所有以 `.git` 結尾的 Git 依賴,免去手動逐個操作的繁瑣流程。

## 前置條件

- 專案根目錄存在 `Packages/manifest.json`,且其中包含至少一個 `*.git` 形式的依賴位址。
- 已透過 Unity 開啟本專案。
- Git 命令在系統 PATH 中可用(UPM 的 `Client.Add` 會呼叫本地 Git 拉取遠端)。

## 操作步驟

### 方式一:選單一鍵批次更新

1. 在 Unity 編輯器頂部選單選擇 `GameFrameX → Update All Packages(更新所有git包)`。
2. 彈出確認框 `是否更新所有包?` 後點 **是**。
3. 工具會讀取 `Packages/manifest.json`,把所有以 `.git` 結尾的依賴加入更新佇列,並顯示可取消的進度條。
4. 更新完成後,**重啟 Unity** 讓 UPM 套用變更。

入口實作見 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L20-L32):

```csharp
[MenuItem("GameFrameX/Update All Packages(更新所有git包)", false, 2000)]
public static void UpdatePackages()
{
    var result = EditorUtility.DisplayDialog("更新包提示", "是否更新所有包?\n 更新完成之後需要[重啟、重啟、重啟]Unity", "是", "否");
    if (result)
    {
        var manifestPath = Path.Combine(Application.dataPath, "..", "Packages", "manifest.json");
        UpdatePackagesFromManifest(manifestPath);
    }
}
```

### 方式二:在 Package Manager 視窗內更新到指定版本

1. 開啟編輯器視窗 `GameFrameX → Package Manager`。
2. 在清單中選擇要更新的包,在工具列中點擊 **Update To Version**。
3. 工具會改寫該包的 URL,把 `#<version>` 後綴拼接好,並透過 `UpdateAllPackageHelper.UpdatePackages(name, url)` 立即觸發更新流程。

實作見 [PackageManagerWindow.cs](/src/Editor/PackageManager/PackageManagerWindow.cs#L233-L274):

```csharp
saveManifest.Dependencies[dependency.Key] = url;
UpdateAllPackageHelper.UpdatePackages(packageName, url);
continue;
...
UpdateAllPackageHelper.StartUpdate();
AssetDatabase.Refresh();
```

工具列入口見 [PackageManagerWindow.ToolBar.cs](/src/Editor/PackageManager/PackageManagerWindow.ToolBar.cs#L60-L70),點擊按鈕直接呼叫 `UpdateAllPackageHelper.UpdatePackages()`。

### 方式三:程式碼層呼叫

如果要在自訂編輯器腳本裡複用同一套邏輯,直接呼叫兩個靜態方法即可:

```csharp
using GameFrameX.Editor;

// 入隊單個 Git 依賴
UpdateAllPackageHelper.UpdatePackages("com.gameframex.runtime", "https://example.com/repo.git");

// 真正開始拉取(從佇列裡依序 Client.Add)
UpdateAllPackageHelper.StartUpdate();
```

簽章定義見 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L34-L42):

```csharp
/// <summary>
/// 更新指定包
/// </summary>
/// <param name="packageName">包名</param>
/// <param name="packageUrl">包位址</param>
public static void UpdatePackages(string packageName, string packageUrl)
{
    PackagesToUpdate.Enqueue((packageName, packageUrl));
}
```

## manifest 掃描與佇列填充邏輯

`UpdatePackages()` 會呼叫私有方法 `UpdatePackagesFromManifest` 解析 `manifest.json`,只把以 `.git` 結尾的依賴入隊,其餘形式的版本號/本地路徑會被忽略。見 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L44-L64):

```csharp
foreach (var package in dependencies)
{
    string packageName = package.Key;
    string packageUrl = package.Value.ToString();
    if (packageUrl.EndsWith(".git"))
    {
        UpdatePackages(packageName, packageUrl);
    }
}
StartUpdate();
```

## 常見變體

| 場景 | 做法 |
|------|------|
| 只想更新某一個包到固定版本 | 開啟 Package Manager 視窗,使用 Update To Version 功能(自動拼接 `#<tag>`) |
| 只想批次更新但保留版本號 | 確保 manifest.json 中 URL 形如 `https://.../repo.git#v1.2.0`,UPM 會拉取該 tag |
| 想從程式碼裡擴充更新更多來源 | 自行入隊更多 `(name, url)` 後呼叫 `StartUpdate()` |

## 常見錯誤

- **更新後控制台報錯**:進度條被取消會導致佇列被 `PackagesToUpdate.Clear()` 清空,見 [UpdateAllPackageHelper.cs](/src/Editor/UpdatePackages/UpdateAllPackageHelper.cs#L92-L99);若需要繼續,重新觸發選單。
- **manifest.json 改動後未生效**:選單提示明確要求 **重啟、重啟、重啟 Unity**,否則 UPM 緩存未刷新。
- **依賴不是 `.git` 位址被忽略**:例如 `file:./...` 或 OpenUPM 連結會被跳過,需要用 Package Manager 視窗的 Update To Version 處理。
- **`Client.Add` 呼叫頻率過快**:佇列實作 `Queue<(name, url)>` 序列處理,避免並發請求異常。

## 背景(可選)

`UpdateAllPackageHelper` 內部用 `AddRequest` + `EditorApplication.update` 事件驅動進度,逐個包呼叫 `UnityEditor.PackageManager.Client.Add`,並透過 `EditorUtility.DisplayCancelableProgressBar` 給出可取消的進度回饋。所有狀態(`_addRequest`、`PackagesToUpdate`、`_allPackagesCount`、`_updatingPackagesIndex`)都是 `static` 欄位,跨呼叫保持,適合多次入隊後一次性啟動。
