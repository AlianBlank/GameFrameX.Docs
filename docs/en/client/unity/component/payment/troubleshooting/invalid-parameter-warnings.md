# No Response on API Calls: Quick Reference for Null/Empty Parameter Warnings

When calling purchase, consume, or similar interfaces and getting "no response at all" (no payment dialog pops up, no events triggered), it is usually because a passed-in parameter is empty or null. `PaymentComponent` intercepts this at the entry point, outputs only a Warning log, and then directly `return`s — the request is never sent out at all. Match the warning text from your logs against the table below to pinpoint which parameter is missing.

## Quick Diagnosis

| Symptom (Log Text) | Trigger Location/Cause | Fix |
|------|------|------|
| `Product ID is null or empty.` | When calling `Buy` / `BuyInApp` / `BuySubs`, `productId` (or `PurchaseParams.ProductId`) is null or an empty string | Pass in the real product ID/SKU configured in the store console; see "Fix Step 1" below |
| `Order ID is null or empty.` | When calling `Buy` / `BuyInApp` / `BuySubs`, `orderId` (or `PurchaseParams.OrderId`) is null or an empty string | Generate the order number on your own server first before initiating the purchase; see "Fix Step 2" |
| `Purchase token is null or empty.` | When calling `ConsumePurchase(purchaseToken)`, the purchase token is empty | Retrieve the real `PurchaseToken` from the `OnQueryPurchasesResult` / `OnPurchaseSuccess` event arguments before consuming; see "Fix Step 3" |
| `Purchase params is null.` | When calling `Buy(PurchaseParams)`, the entire parameter object is null | Construct and populate a `PurchaseParams` subclass before passing it in; see "Fix Step 2" |
| `Pay Manager is invalid.`(Fatal) | In `Awake`, `GameFrameworkEntry.GetModule<IPaymentManager>()` returns null; the platform implementation class was not loaded correctly | Check that the platform component type field on the `PaymentComponent` Inspector is correct and that the corresponding channel package has been imported; see "Fix Step 4" |

All of the above warnings just `Log.Warning` and immediately `return` — no exception is thrown, and `OnPurchaseFailed` is not triggered — hence the symptom of "no response to the call". Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L259).

## Fix Steps

### 1. Product ID is Empty

The product ID must exactly match the SKU configured in the store console (case-sensitive; watch out for leading/trailing spaces). It is recommended to construct it with a `PurchaseParams` subclass:

```csharp
// ProductId is still validated after construction; if empty, a Warning is likewise logged and it returns directly
var param = new SomeChannelPurchaseParams(productId: "coin_pack_100", orderId: orderNo, productType: PaymentProductType.InApp);
paymentComponent.Buy(param);
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

Troubleshooting tips:

- If the product ID is read from a config table/server, first print the actual value to confirm it is non-empty: `Debug.Log($"[{productId}]");`
- Make sure you haven't mixed up the positions of "optional default parameters" such as `offerToken` and `customData`.
- The validation order of `Buy(PurchaseParams)` is: parameter object null → `ProductId` empty → `OrderId` empty; whichever log appears first tells you where the problem is.

### 2. Order ID is Empty or the Parameter Object is null

`OrderId` is the order number from your own server; it is used for purchase verification and must not be empty. `PurchaseParams` is an abstract base class (`public abstract class PurchaseParams`), so it cannot be instantiated directly with `new` — you must use a channel-specific subclass; the three fields (`ProductId`, `OrderId`, `ProductType`) are assigned through the constructor:

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

Common pitfalls:

- The order number is generated by an asynchronous interface, but the purchase button was clicked before the callback fired — enable the purchase button only inside the callback.
- The legacy interfaces `BuyInApp` / `BuySubs` / `Buy(string, PaymentProductType, ...)` are marked `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`, but their validation behavior is identical; when migrating, you must likewise ensure `productId` and `orderId` are non-empty.

### 3. Purchase Token is Empty (Consume Purchase Has No Response)

`ConsumePurchase` only accepts a non-empty `purchaseToken`:

```csharp
public void ConsumePurchase(string purchaseToken)
{
    if (string.IsNullOrEmpty(purchaseToken))
    {
        Log.Warning("Purchase token is null or empty.");
        return;
    }

    _paymentManager.ConsumePurchase(purchaseToken);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L152)

The correct approach is to subscribe to the `OnPurchaseSuccess` or `OnQueryPurchasesResult` event, retrieve the real token from `PaymentEventArgs`, and then call consume.

### 4. Pay Manager is invalid (Fatal)

`PaymentComponent.Awake` selects the implementation class type based on the platform (`m_componentAndroidType`, `m_componentIOSType`, `m_componentWebGLType`, `m_componentPCType`, `m_componentMacType`), with all other platforms falling back to `DefaultPaymentManager`. If `GetModule<IPaymentManager>()` returns null, it logs `Log.Fatal("Pay Manager is invalid.")`. Check:

- Whether the platform type string on the Inspector has been corrupted (defaults such as `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`);
- Whether the corresponding channel package has been imported into the project (if the type does not exist, `Utility.Assembly.GetType` fails to resolve it);
- Whether the current running platform falls into one of the `UNITY_*` branches; otherwise it goes to the `DefaultPaymentManager` empty implementation, and payment itself will also be unresponsive.

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## Verification

- Before making calls, filter Warnings in the Unity Console and confirm that none of the log entries in the table above appear anymore.
- When the parameters are valid, the call proceeds to `_paymentManager.Buy(...)` / `ConsumePurchase(...)`; you can then subscribe to the `OnPurchaseSuccess` / `OnPurchaseFailed` events to confirm the payment flow is actually triggered (the events are forwarded in [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64)).
- Use `IsReady()` to confirm the payment system is ready before showing the purchase entry point, which can avoid many false "no response" reports.
