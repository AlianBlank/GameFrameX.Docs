# 设置 Build Properties 与链接器标志

在 `XCodeConfig.json` 的 `unityMain` / `unityFramework` 段落下填写 `properties`(Build Settings)与 `otherLinkerFlag`(链接器标志,如 `OTHER_LDFLAGS`),Unity 导出 iOS 工程后会由构建后处理自动写入生成的 Xcode 工程,无需手工打开 Xcode 修改 Build Settings。

## 前置条件

- Unity 已切换到 iOS 平台。
- 工程中存在名为 `XCodeConfig.json` 的配置文件(文件名必须一致,后处理按该文件名扫描);可复制仓库自带的 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) 或 [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json) 改名后使用。

## 操作步骤

1. 在工程中创建 `XCodeConfig.json`(内容参考仓库自带模板与示例)。
2. 确定目标 target:主可执行程序 Unity-iPhone 写在 `unityMain` 段,动态库写在 `unityFramework` 段,两段结构完全相同。
3. 用 `properties` 字段修改 Build Settings,支持三种操作符:

| 操作符 | 实际调用的 PBXProject API | 作用 |
|--------|---------------------------|------|
| `=` | `SetBuildProperty(targetGuid, key, value)` | 直接覆盖某项 Build Setting 的值 |
| `+` | `UpdateBuildProperty(targetGuid, key, list, null)` | 向列表型 Build Setting 追加值 |
| `-` | `UpdateBuildProperty(targetGuid, key, null, list)` | 从列表型 Build Setting 移除值 |

   三种操作符的解析逻辑(节选自 `SetBuildProperties`):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}

Hashtable addTable = table.Get<Hashtable>("+");
// ... 省略 ArrayList 转 List<string> ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), list, null);

Hashtable removeTable = table.Get<Hashtable>("-");
// ... 省略 ArrayList 转 List<string> ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), null, list);
```

Source: [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L58)

4. 按上表结构写 JSON(键 `=`/`+`/`-` 下的键值即为 Build Setting 名称与值,`+`/`-` 的值必须是数组):

```json
{
  "unityFramework": {
    "properties": {
      "=": { "ENABLE_BITCODE": "NO" },
      "+": { "OTHER_LDFLAGS": ["-lxml2"] },
      "-": { "OTHER_LDFLAGS": ["-ObjC"] }
    }
  }
}
```

5. 用 `otherLinkerFlag` 字段添加链接器标志,与 `properties` 平级。示例文件中的真实写法:

```json
"otherLinkerFlag": {
  "OTHER_LDFLAGS": ["-ObjC"]
}
```

Source: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L152-L154)

   标志会被逐条追加到对应 Build Setting 上(每条调用一次 `AddBuildProperty`):

```csharp
foreach (DictionaryEntry kv in table)
{
    var keyStr = kv.Key.ToString().Trim();
    if (kv.Value is ArrayList list)
    {
        // 数组:逐条 AddBuildProperty
        foreach (var part in parts)
        {
            proj.AddBuildProperty(targetGuid, keyStr, part);
        }
    }
    else
    {
        // 字符串:直接 AddBuildProperty
        proj.AddBuildProperty(targetGuid, keyStr, kv.Value.ToString().Trim());
    }
}
```

Source: [PostProcessBuildHelper.OtherLinkFlag.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.OtherLinkFlag.cs#L15-L47)

6. 触发 iOS 构建。`[PostProcessBuild(888)]` 的 `OnPostProcessBuild` 会读取所有 `XCodeConfig.json` 合并为一份配置,依次对 `GetUnityMainTargetGuid()` 与 `GetUnityFrameworkTargetGuid()` 应用配置,最后写回 `Unity-iPhone.xcodeproj/project.pbxproj`。

```csharp
Run(project, project.GetUnityMainTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityMain"), path);
Run(project, project.GetUnityFrameworkTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityFramework"), path);
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L104)

## 常见变体

- **数组或单字符串均可**:`otherLinkerFlag` 的值写成数组(如 `["-ObjC", "-lxml2"]`)会逐条追加;写成单个字符串则整体添加一次,两种写法在源码中都有处理分支。
- **多份配置合并**:所有扫描到的 `XCodeConfig.json` 会按顺序合并,后合并的覆盖先合并的;若启用了渠道(`SettingLoader.GetChannel()`),`XCodeConfig.{channel}.json` 最后合并、优先级最高。
- **同段其他字段**:`unityMain` / `unityFramework` 段内还可同时配置 `frameworks`、`libs`、`files`、`folders`、`filesCompileFlag`、`runPathSearchPaths` 等字段,由同一次 `Run` 依次应用。

## 常见错误

| 现象 / 日志原文 | 原因 | 修复 |
|-----------------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 文件名不是 `XCodeConfig.json`,或所在位置无法被扫描到 | 改成正确文件名并放到可扫描位置 |
| `{jsonPath} 解析失败, 跳过合并` | JSON 语法错误 | 用 JSON 校验工具修正后再构建 |
| `合并后的配置为空，跳过设置` | 所有文件均解析失败 | 检查各配置文件语法 |
| 改了 `properties` / `otherLinkerFlag` 但 Xcode 里没生效 | 字段写在了 JSON 顶层 | 这两个字段必须写在 `unityMain` 或 `unityFramework` 段内,`Run` 只从这两个段读取 |
| `+` / `-` 操作不生效 | 值写成了字符串 | 源码以 `i.Value as ArrayList` 读取,字符串会得到空列表,必须写成数组 |

## 背景

`properties` 最终落到 `SetBuildProperty` / `UpdateBuildProperty`,`otherLinkerFlag` 落到 `AddBuildProperty`,都是 Unity 自带 `UnityEditor.iOS.Xcode.PBXProject` 的标准接口,区别在于前者支持覆盖与增删,后者只做追加。整个流程挂在 `[PostProcessBuild(888)]` 回调上,仅在 `target == BuildTarget.iOS` 时执行。
