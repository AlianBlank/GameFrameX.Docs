# 핫업데이트 방법: 버전 검사, 매니페스트 업데이트 및 패치 다운로드

핫업데이트는 `EPatchStates` 열거형에 정의된 5개의 상태로 구동됩니다: `UpdateStaticVersion`(정적 리소스 버전 업데이트)→ `UpdateManifest`(패치 매니페스트 업데이트)→ `CreateDownloader`(다운로더 생성)→ `DownloadWebFiles`(원격 파일 다운로드)→ `PatchDone`(패치 프로세스 완료). 본 작업은 "패치 시작 → 상태 변경 구독 → 실패 롤백 → 메인 프로세스 진입"을 연결하여 비즈니스 코드에서 완전한 핫업데이트 체인을 실행할 수 있게 합니다.

## 사전 조건

- `GameFrameX.Runtime`의 `GameEntry`를 통해 `AssetComponent` 인스턴스를 가져왔는지 확인(프레임워크 진입 관련은 《빠른 시작》 참조).
- 원격 서버가 YooAsset의 디렉터리 구조에 따라 배포되어 있어야 합니다: 루트 디렉터리의 `{platform}/{version}/{packageName}`는 반드시 `GameVersion.txt`, `{packageName}_PatchManifest_{version}.bytes`, `{packageName}_StaticVersion_{version}.bytes` 등의 파일을 포함해야 합니다.
- 프로젝트에서 `AssetPatchStatesChangeEventArgs` 등 이벤트 타입을 유지해야 합니다(코드에는 이미 `[UnityEngine.Scripting.Preserve]`가 있어 잘림 방지).

## 작업 단계

### 1. 패치 상태 변경 이벤트 구독

`GameFrameX` 이벤트 버스를 통해 `AssetPatchStatesChangeEventArgs`를 구독하면, 다음 상태로 진입할 때마다 콜백을 받아 진행 표시줄 UI를 새로 고치는 데 사용할 수 있습니다.

```csharp
GameEntry.Event.Subscribe(AssetPatchStatesChangeEventArgs.EventId, OnPatchStatesChange);

private void OnPatchStatesChange(object sender, GameEventArgs e)
{
    var args = (AssetPatchStatesChangeEventArgs)e;
    // args.PackageName: 현재 업데이트 중인 리소스 패키지명
    // args.CurrentStates: EPatchStates 열거형(아래 표 참조)
    Debug.Log($"[{args.PackageName}] 단계 진입:{args.CurrentStates}");
}
```

Source: [AssetPatchStatesChangeEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchStatesChangeEventArgs.cs#L18-L46)

### 2. "업데이트 파일 발견" 및 "다운로드 진행률" 이벤트 구독(선택 사항이지만 권장)

이 두 이벤트는 UI에서 "총 다운로드해야 할 파일 수""현재 몇 번째 파일 / 총 크기"를 표시하는 데 사용됩니다.

| 이벤트 EventId | 이벤트 매개변수 | 트리거 시점 | 주요 필드 |
|---|---|---|---|
| `AssetFoundUpdateFilesEventArgs.EventId` | `AssetFoundUpdateFilesEventArgs` | CreateDownloader 이후, DownloadWebFiles 이전 | 다운로드할 파일 총수, 총 크기 |
| `AssetDownloadProgressUpdateEventArgs.EventId` | `AssetDownloadProgressUpdateEventArgs` | 각 파일 다운로드 과정 중 | 현재 진행률, 다운로드됨/총 크기, 남은 크기 |

### 3. 실패 이벤트 구독 및 롤백 처리

핫업데이트 과정에서 어느 단계든 실패하면 해당 이벤트 매개변수가 발생하므로, 구독 위치에서 재시도 또는 다운그레이드 처리를 해야 합니다:

```csharp
GameEntry.Event.Subscribe(AssetStaticVersionUpdateFailedEventArgs.EventId, OnStaticVersionFailed);
GameEntry.Event.Subscribe(AssetPatchManifestUpdateFailedEventArgs.EventId, OnManifestFailed);
GameEntry.Event.Subscribe(AssetWebFileDownloadFailedEventArgs.EventId, OnFileDownloadFailed);
```

### 4. 핫업데이트 프로세스 시작

`AssetComponent`에서 제공하는 업데이트 진입점을 호출합니다(실제 시그니처는 현재 저장소의 `Runtime/Asset/AssetComponent.cs`를 기준으로 하세요). 완전한 패치 세션은 순서대로 다음 5개의 상태로 진입합니다:

```csharp
// Boot 단계에서(GameEntry 시작 후) 한 번만 호출
var assetComponent = GameEntry.GetComponent<AssetComponent>();
assetComponent.UpdatePackages(); // 버전 번호 가져오기 → 매니페스트 비교 → 다운로더 생성 → 다운로드 → PatchDone 콜백
```

트리거 후, 이벤트 버스가 순서대로 브로드캐스트합니다:
1. `EPatchStates.UpdateStaticVersion` —— 원격 `GameVersion.txt`와 로컬 캐시 버전을 비교합니다.
2. `EPatchStates.UpdateManifest` —— `{packageName}_PatchManifest_{version}.bytes`를 가져와 로컬 매니페스트와 차분 비교합니다.
3. `EPatchStates.CreateDownloader` —— `AssetDownloadProgressUpdateEventArgs` 등 다운로더에 필요한 객체를 구성합니다.
4. `EPatchStates.DownloadWebFiles` —— 실제로 차분 파일을 다운로드하며, 각 파일마다 `AssetDownloadProgressUpdateEventArgs`를 한 번씩 콜백합니다.
5. `EPatchStates.PatchDone` —— 프로세스가 종료되며, 안전하게 메인 씬으로 진입할 수 있습니다.

## 일반적인 변형

| 시나리오 | 방법 |
|---|---|
| 검사 건너뛰고 로컬 리소스 직접 사용 | `AssetComponent`의 "로컬 전용" 초기화 오버로드를 호출하여 `UpdatePackages`에 진입하지 않음 |
| 단일 리소스 패키지만 업데이트 | `UpdatePackages` 이전에 `SetForceUpdateAllPackageVersions(true)` 등의 스위치로 범위를 제어 |
| 중단된 지점부터 재개 | 이벤트 `AssetDownloadProgressUpdateEventArgs`에 다운로드된 바이트 수가 유지되며, `UpdatePackages`를 다시 호출하면 프레임워크가 미완료 파일을 자동으로 이어서 다운로드함 |

## 일반적인 오류

| 증상 | 가능한 원인 | 회피 방법 |
|---|---|---|
| `EPatchStates.PatchDone`이 계속 트리거되지 않음 | 이벤트가 구독되지 않았거나 구독한 EventId의 철자가 틀림 | `typeof(AssetPatchStatesChangeEventArgs).FullName`을 EventId로 사용하고, 문자열을 직접 작성하지 말 것 |
| 중간에 다운로드가 응답하지 않음 | `AssetDownloadProgressUpdateEventArgs`를 구독하지 않아 다운로더가 메인 스레드에서 대기 중일 수 있음 | 다운로더에 별도의 비동기 컨텍스트를 열고 UI에 진행률을 표시 |
| 원격 매니페스트 404 | 서버에 `{packageName}_PatchManifest_{version}.bytes`가 배포되지 않음 | 프레임워크 제공 업로드 도구(YooAsset 공식 Builder 참조)를 사용하여 다시 업로드; 이벤트 `AssetPatchManifestUpdateFailedEventArgs`에 오류 정보가 포함됨 |
| 정적 버전 파일 다운로드 실패 | 서버에 `{platform}/GameVersion.txt`가 없거나 캐시 디렉터리가 읽기 전용 | `Application.persistentDataPath` 쓰기 권한 확인; `AssetStaticVersionUpdateFailedEventArgs` 모니터링 |

## 배경(선택 사항)

`EPatchStates`는 YooAsset의 전체 패치 수명 주기를 5개의 열거형 값으로 추상화하며, 프레임워크 레이어는 상태 전환 시 `AssetPatchStatesChangeEventArgs`를 `GameFrameX` 이벤트 버스로 던지는 역할만 담당합니다. 비즈니스 측은 EventId를 구독하여 결합도를 낮추므로, UI, 네트워크 재시도, 다운그레이드 전략을 비침습적으로 교체할 수 있으며 패치 메인 프로세스는 안정적으로 유지됩니다.
