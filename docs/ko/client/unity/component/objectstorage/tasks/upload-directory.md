# 전체 디렉토리를 업로드하는 방법

`IObjectStorageUploadManager.UploadDirectory(localDirectory)`를 호출하면 로컬 디렉토리(및 그 아래의 모든 파일)를 객체 스토리지 버킷에 업로드할 수 있으며, 루트 경로는 `SetSavePath`로 지정됩니다.

## 사전 조건

- `BaseObjectStorageUploadManager`를 상속하는 업로드 매니저 구현체가 이미 있어야 합니다(예: 특정 클라우드 서비스 SDK 기반 구현).
- `Init(accessKey, secretKey, bucketName, endpoint)`을 호출하여 자격 증명과 버킷 초기화를 완료해야 합니다.
- `SetSavePath(savePath)`를 호출하여 버킷 내 저장 디렉토리를 설정해야 합니다(끝에 구분자를 붙이든 안 붙이든 무관하며, 구현체 내부에서 자동으로 끝 구분자를 제거합니다).

## 작업 단계

1. **업로드 매니저 초기화**. `ObjectStorageUploadFactory`를 통해 구체적인 구현체를 가져와 자격 증명과 버킷 이름 설정을 완료합니다.

```csharp
IObjectStorageUploadManager uploader = ObjectStorageUploadFactory.Create();
// 내부에서 구체적인 구현체의 Init(accessKey, secretKey, bucketName, endpoint)을 호출합니다
uploader.Init("your-access-key", "your-secret-key", "your-bucket-name");
```

2. **버킷 내 저장 경로 설정**. `savePath`는 버킷에서 파일의 루트 디렉토리 접두사입니다.

```csharp
uploader.SetSavePath("/assets/Resources");
```

3. **`UploadDirectory` 호출하여 전체 디렉토리 업로드**. 로컬 절대 또는 상대 디렉토리 경로를 전달하면, 디렉토리 아래의 모든 파일이 상대 경로에 따라 `savePath` 아래로 업로드됩니다.

```csharp
uploader.UploadDirectory("Assets/StreamingAssets/configs");
```

`UploadDirectory`는 내부적으로 전달된 경로를 `UploadRootPath`로 기록한 후, 추상 메서드 `UploadDirectoryInternal(localDirectory)`로 전달합니다:

```csharp
public void UploadDirectory(string localDirectory)
{
    UploadRootPath = localDirectory;
    UploadDirectoryInternal(localDirectory);
}
```

## 일반적인 변형

- **단일 파일만 업로드**: 대신 `uploader.UploadFile("Assets/StreamingAssets/configs/a.json")`을 사용하면 지정된 파일만 `savePath`에 들어갑니다.
- **원본 디렉토리 계층 구조 유지**: `UploadDirectoryInternal`을 구현할 때 `UploadRootPath`를 기준으로 하위 디렉토리 경로로 객체 키를 생성하면 로컬 구조를 유지할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Init` 전에 `UploadDirectory`를 호출하여 NRE 또는 인증 실패 발생 | 자격 증명이 주입되지 않음 | 먼저 `Init`을 호출하고, 그 다음 `SetSavePath`, 마지막으로 `UploadDirectory` 순서로 호출하도록 보장 |
| 업로드 후 버킷 내 파일이 모두 루트 디렉토리에 쌓이고 계층 구조가 없음 | `UploadDirectoryInternal`이 하위 디렉토리에 따라 객체 키를 생성하지 않음 | `UploadRootPath`를 기준으로 상대 경로를 계산하여 객체 키 접미사로 사용 |
| `savePath` 끝의 구분자로 인해 경로 연결 시 `//`가 발생 | `SetSavePath` 정규화를 거치지 않음 | 항상 `SetSavePath`를 통해 대상 경로를 설정하며, 구현체에서 끝 구분자가 제거됨 |

## 배경 (선택 사항)

`UploadDirectory`는 루트 디렉토리를 기록하고 추상 메서드를 트리거하는 역할만 담당하며, 실제 순회 및 업로드 로직은 구체적인 구현체(`BaseObjectStorageUploadManager`를 상속)가 `UploadDirectoryInternal`에서 완료합니다. 일반적으로 로컬 파일을 재귀적으로 읽고 `UploadRootPath` 외부의 상대 경로를 객체 키의 일부로 사용합니다.
