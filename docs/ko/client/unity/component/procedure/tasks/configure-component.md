# ProcedureComponent 설정 방법

`ProcedureComponent`는 GameFrameX 프로시저 시스템의 진입 컴포넌트로, `IProcedureManager` 등록, 사용 가능한 프로시저 클래스 수집, 그리고 시작 시 지정된 진입 프로시저 진입을 담당합니다. 이 페이지에서는 Unity에서 이를 설정하여 게임이预期的대로 진입 프로시저에서 시작되도록 하는 방법을 설명합니다.

## 사전 조건

- 프로젝트에 `GameFrameX.Procedure` 어셈블리가 추가되어 있어야 합니다.
- [ProcedureBase](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L80)를 상속하는 프로시저 클래스(예: 진입 프로시저 `ProcedureLaunch`)가 준비되어 있어야 합니다.
- `GameFrameworkComponent` 파생 컴포넌트를承载하기 위해 `GameFramework` 프리팹(`GameFrameXEntry` / `GameFrameworkEntry` 포함)이 씬에 존재해야 합니다.

## 작업 단계

1. 씬에 `GameFramework` 프리팹을 마운트하고 **Add Component → GameFrameX → Procedure**를 사용하여 `ProcedureComponent`를 추가합니다.

   컴포넌트 속성은 `ProcedureComponentInspector`를 통해 Inspector에서 시각적으로 표시됩니다:

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Procedure")]
   [GameFrameXAutoComponent(-1000)]
   public sealed class ProcedureComponent : GameFrameworkComponent
   ```

   출처: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L43-L46)

2. Inspector의 **Available Procedures** 영역에서 활성화할 모든 프로시저 클래스(`ProcedureBase`를 상속해야 함)를 체크합니다. Inspector는 리플렉션 `typeof(ProcedureBase)`를 통해 후보 타입을 자동 수집합니다:

   ```csharp
   m_ProcedureTypeNames = TypeHelper.GetRuntimeTypeNames(typeof(ProcedureBase));
   ```

   출처: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L162-L165)

3. **Entrance Procedure** 드롭다운에서 진입 프로시저를 선택합니다. 이 값은 시리얼라이즈된 필드 `m_EntranceProcedureTypeName`에 기록되며, 시작 시 타입 매칭을 통해 진입 인스턴스를 찾습니다:

   ```csharp
   if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
   {
       m_EntranceProcedure = procedures[i];
   }
   ```

   출처: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L152-L155)

4. Play 모드에 진입한 후 컴포넌트는 `Start` 코루틴에서 `Initialize`와 `StartProcedure`를 호출합니다:

   ```csharp
   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   yield return new WaitForEndOfFrame();
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   출처: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

5. 실행 후 Inspector 상단의 **Current Procedure** 필드에서 현재 프로시저를 확인할 수 있습니다:

   ```csharp
   EditorGUILayout.LabelField("Current Procedure", currentProcedureName);
   ```

   출처: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L83)

## 일반적인 변형

- **StartupRunner이 시작을 인계받도록 사용**: Inspector의 **Use Startup Runner**를 체크합니다. 이 모드는 `Awake`에서 `IProcedureManager`만 등록하며, 더 이상 `Initialize`와 `StartProcedure`를 호출하지 않고, `ApplicationStartupEntry`가 `StartupRunner.Run`을 통해统一적으로 인계받습니다:

  ```csharp
  if (m_UseStartupRunner)
  {
      // ApplicationStartupEntry + StartupRunner.Run에 의해 Initialize 및 StartProcedure를 인계받아,
      // 본 컴포넌트는 Awake에서 IProcedureManager 등록만 담당하여 새로운 진입에서의 중복 Initialize로 인한 Already exist FSM 오류를 방지합니다.
      yield break;
  }
  ```

  출처: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L122-L127)

  체크 후 Inspector는 힌트 메시지를 표시하며 아래의 **Available Procedures**와 **Entrance Procedure** 설정을 무시합니다:

  ```csharp
  EditorGUILayout.HelpBox("프로시저 시작이 StartupRunner.Run에 위임되었습니다. Available Procedures 및 Entrance Procedure 설정은 무시됩니다.", MessageType.Info);
  ```

  출처: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L59)

- **런타임 프로시저 재구축**: `ReinitializeProcedures`를 호출하여 기존 상태 머신을销毁하고 새로운 프로시저 배열로 재초기화하며, 주로 핫 업데이트나 맞춤 시작 순서에 사용됩니다:

  ```csharp
  [Preserve]
  public void ReinitializeProcedures(ProcedureBase[] procedures, ProcedureBase entranceProcedure)
  {
      m_ProcedureManager.ReinitializeProcedures(procedures);
      m_EntranceProcedure = entranceProcedure;
  }
  ```

  출처: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

## 일반적인 오류

| 현상 | 로그 원문 | 원인과 해결 |
|------|----------|-----------|
| 프로시저가 시작되지 않음 | `Available procedure type names is empty. Procedure auto start skipped.` | Inspector의 **Available Procedures**가 비어 있습니다. 최소 하나의 프로시저 클래스를 체크한 후 실행하세요. |
| 인스턴스를 생성할 수 없음 | `Can not find procedure type '{0}'.` | 타입 이름이 런타임 어셈블리에 없습니다. 프로시저 클래스가 컴파일되었고 네임스페이스가 완전한지 확인하세요. |
| 생성 실패 | `Can not create procedure instance '{0}'.` | 프로시저 클래스에 매개변수 없는 생성자가 없거나 `ProcedureBase`를 상속하지 않았습니다. |
| 진입점이 없음 | `Entrance procedure is invalid.` | **Entrance Procedure**가 선택되지 않았거나 선택 항목이 **Available Procedures** 목록에 없습니다. |
| 시작 시 FSM 중복 보고 | StartupRunner 활성화 후에도 이전 경로 `Initialize`가触发됨 | 두 진입점(`ApplicationStartupEntry`와 이전 `ProcedureComponent.Start`)이 동시에 존재하는지 확인하고 하나만 유지하세요. |

## 배경 (선택)

`ProcedureComponent`는 `Awake`에서 `GameFrameworkEntry.GetModule<IProcedureManager>()`를 통해 프로시저 매니저를 가져옵니다. `IsRuntimeComponentReady`가 true인 경우에만 계속 진행하여 Editor 모드에서의 잘못된 초기화를 방지합니다. `m_UseStartupRunner`가 `false`(기본값)일 때, `Start` 코루틴은 리플렉션 타입 이름 배열을 통해 `ProcedureBase` 인스턴스를 생성하고 매칭된 진입 프로시저로 시작합니다. `true`일 때는 모듈만 등록하며 초기화와 시작을 완전히 `StartupRunner.Run`에 맡겨 중복 `Initialize`로 인한 `Already exist FSM` 오류를 방지합니다.
