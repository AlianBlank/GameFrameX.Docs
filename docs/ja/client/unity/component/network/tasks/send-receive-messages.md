# ネットワークメッセージの送受信(メッセージの定義とハンドラーの登録)

GameFrameX Network でメッセージを送受信するには 3 ステップだけです:`MessageObject` を継承するメッセージクラスを定義し、対応する `IPacket*Handler` インターフェースを実装するハンドラークラスを記述し、`INetworkChannel.Send(...)` で送信します。ハンドラーは**手動で登録する必要はありません**――`DefaultNetworkChannelHelper.Initialize` がリフレクションでアセンブリをスキャンし、`RegisterHandler` を自動的に呼び出して登録を完了します。

## 前提条件

- ネットワークチャネルが作成・接続済みであること(`NetworkManager` が準備完了している)。
- メッセージ基底クラス `MessageObject` はフレームワーク基盤ライブラリに由来します。本パッケージのシリアライズ制約は `where T : MessageObject` です。
- ハンドラークラスは**非抽象 class** でなければならず、マーカーインターフェース `IPacketHandler` を実装し、パブリックな引数なしコンストラクターを提供する必要があります(リフレクションで `Activator.CreateInstance` によりインスタンス化されます)。

## 操作手順

1. **メッセージクラスを定義する**:メッセージに `MessageObject` を継承させます。チャネル内部で管理される送信キューは `GameFrameworkLinkedList<MessageObject>` であり、シリアライズ入口のジェネリック制約も `MessageObject` です:

   ```csharp
   public bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject
   ```

   > 本リポジトリにはネットワークコンポーネント本体のみが含まれ、具体的なゲーム側のメッセージ定義(protobuf メッセージクラスなど)は含まれていません。ゲームプロジェクト側で独自に定義する必要があります。

2. **ハンドラーを実装する**:送受信の段階に応じて実装するインターフェースを選択します。すべてのハンドラーはマーカーインターフェース `IPacketHandler` を実装する必要があります([IPacketHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketHandler.cs#L4) で定義、コメントは「マーカーインターフェース、ネットワークメッセージパケットハンドラーを識別するために使用」):

   | インターフェース | 登録 API(リフレクションにより自動呼び出し) | 役割 |
   |------|---------------------------|------|
   | `IPacketReceiveHeaderHandler` | `RegisterHandler(IPacketReceiveHeaderHandler)` | 受信パケットヘッダーの解析 |
   | `IPacketReceiveBodyHandler` | `RegisterHandler(IPacketReceiveBodyHandler)` | パケットボディを `MessageObject` にデシリアライズ |
   | `IPacketSendHeaderHandler` | `RegisterHandler(IPacketSendHeaderHandler)` | パケットヘッダーのシリアライズ |
   | `IPacketSendBodyHandler` | `RegisterHandler(IPacketSendBodyHandler)` | パケットボディのシリアライズ |
   | `IPacketHeartBeatHandler` | `RegisterHeartBeatHandler(IPacketHeartBeatHandler)` | ハートビートパケットの生成/検証 |
   | `IMessageCompressHandler` / `IMessageDecompressHandler` | `RegisterMessageCompressHandler` / `RegisterMessageDecompressHandler` | パケットボディの圧縮/解凍 |

   パッケージ内にはデフォルト実装が既に用意されており、直接継承または差し替えが可能です:[DefaultPacketReceiveHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveHeaderHandler.cs#L9)、[DefaultPacketReceiveBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveBodyHandler.cs#L7)、[DefaultPacketSendHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendHeaderHandler.cs#L10)、[DefaultPacketSendBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendBodyHandler.cs#L9)、[BasePacketHeartBeatHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/BasePacketHeartBeatHandler.cs#L7)。

3. **自動登録を確認する**：チャネルの初期化時に `DefaultNetworkChannelHelper.Initialize` がすべてのアセンブリタイプをスキャンし、`IPacketHandler` を実装する非抽象クラスはすべてインスタンス化されてチャネルに登録されます：

   ```csharp
   var types = Utility.Assembly.GetTypes();
   foreach (var type in types)
   {
       if (!type.IsClass || type.IsAbstract)
       {
           continue;
       }

       if (!type.IsImplWithInterface(packetHandlerBaseType))
       {
           continue;
       }

       if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
       {
           var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       else if (type.IsImplWithInterface(packetReceiveBodyHandlerBaseType))
       {
           var handler = (IPacketReceiveBodyHandler)Activator.CreateInstance(type);
           InjectChannelSerializer(handler, type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       // ...以降、SendHeader / SendBody / HeartBeat / Compress / Decompress の順に照合
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L73-L107)

4. **メッセージを送信する**:チャネルの `Send` メソッドを呼び出します。パッケージ内のハートビートの送信方法がそのまま標準的な使用例です:

   ```csharp
   public bool SendHeartBeat()
   {
       if (m_NetworkChannel == null)
       {
           return false;
       }

       var message = m_NetworkChannel.PacketHeartBeatHandler.Handler();
       m_NetworkChannel.Send(message);
       return true;
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L146-L156)

5. **メッセージを受信する**:パケット受信後は受信ハンドラーチェーンによって解析が完了し、受信ボディのデシリアライズでは `messageId` に基づいて具体的な `MessageObject` に復元されます:

   ```csharp
   public bool DeserializePacketHeader(byte[] source)
   public bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L179-L189)

6. **(任意)ネットワークイベントを監視する**:接続、クローズ、ハートビート喪失、エラーの各イベントは Helper によって一括で購読済みです(`NetworkConnectedEventArgs`、`NetworkClosedEventArgs`、`NetworkMissHeartBeatEventArgs`、`NetworkErrorEventArgs`)。ゲーム側ではイベントコンポーネント経由で購読するだけでよく、[DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128) を参照してください。

## 一般的なバリエーション

## 一般的なバリエーション

- **カスタムハートビート**:`BasePacketHeartBeatHandler` を継承し(`IPacketHeartBeatHandler` と `IPacketHandler` を同時に実装)、`Handler()` を実装してハートビート用メッセージオブジェクトを返すだけで OK です。ハートビート送信時には `m_NetworkChannel.Send(message)` が呼び出され、通常のメッセージと同一です。
- **カスタム圧縮**:`IMessageCompressHandler` / `IMessageDecompressHandler` をそれぞれ実装し、`IPacketHandler` マーカーを付与します。登録後は `SerializePacketHeader` / `DeserializePacketBody` のフローから自動的に呼び出されます。デフォルト実装は [DefaultMessageCompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageCompressHandler.cs#L10) と [DefaultMessageDecompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageDecompressHandler.cs#L10) を参照してください。
- **ハンドラーの手動登録**:`INetworkChannel` は各 `RegisterHandler` オーバーロードも公開しています(`[Obsolete("Use RegisterHeartBeatHandler instead")]` が付与されたハートビート用オーバーロードを含む)。[INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L150-L181) を参照してください。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| ハンドラーが一度も呼び出されない | クラスが抽象クラス、またはマーカーインターフェース `IPacketHandler` を実装していないため、リフレクションスキャンが `continue` でスキップする | クラスを非抽象として宣言し、`IPacketHandler` を追加する |
| 実行時にハンドラーのインスタンス化で例外がスローされる | リフレクションで `Activator.CreateInstance(type)` を使用するため、パブリックな引数なしコンストラクターがない | ハンドラーにパブリックな引数なしコンストラクターを追加する |
| 1 つのクラスが誤った登録ブランチにマッチする | 登録は `ReceiveHeader → ReceiveBody → SendHeader → SendBody → HeartBeat → Compress → Decompress` の `if / else if` 順で**最初にマッチしたもの**を採用する | 各クラスには 1 つの処理インターフェースのみを実装し、複数のクラスに分割する |
| 送信/受信のヘッダー・ボディ解析の動作が期待どおりでない | シリアライザーの注入がない(`ReceiveBody`、`SendHeader` のブランチのみ `InjectChannelSerializer(handler, type)` を呼び出す) | 対応するハンドラーにチャネルシリアライザーを設定するか、パッケージ内のデフォルトハンドラーをそのまま使用する |
| シリアライズ呼び出しで引数 null の例外がスローされる | `SerializePacketHeader` / `SerializePacketBody` の内部で `m_NetworkChannel`、`PacketSendHeaderHandler`、`PacketSendBodyHandler`、`messageObject`、`destination` に対して `GameFrameworkGuard.NotNull` 検証が行われている | 先にハンドラー登録を完了してから送信し、メッセージと宛先ストリームが null でないことを確認する |

## 検証

- 送信側：チャネルの統計プロパティ `SendPacketCount` / `SentPacketCount`(送信キュー数 / 送信済み数)を確認します。Unity Inspector パネルでは "Send Packet" と表示されます。[NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L108) を参照してください。
- 受信側:`IPacketReceiveBodyHandler` の実装にブレークポイントを設定し、`DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` がコールバックされ、`messageObject` が正常に復元されることを確認します。

## 背景

設計上、送受信パケット処理は「ヘッダー / ボディ」の 2 段階に分割され、送受信の方向ごとに独立したインターフェースとなっています。送信時は `SerializePacketHeader` がヘッダーを書き込んでボディバッファを生成し、続いて `SerializePacketBody` がボディを書き込みます。受信は逆方向に `DeserializePacketHeader` → `DeserializePacketBody` の順で実行されます。マーカーインターフェース `IPacketHandler` とアセンブリリフレクションの組み合わせにより、新しいメッセージやハンドラーはフレームワークコードを修正することなく自動的に組み込まれます([DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L60-L71) を参照)。チャネル層の送信キューおよびハンドラー登録の実装は [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L525-L572) にあります。
