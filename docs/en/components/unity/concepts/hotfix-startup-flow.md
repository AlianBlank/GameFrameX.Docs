# How It Works: Hotfix Entry and Startup Flow

Hotfix startup is handled by [`HotfixHelper`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs) within the framework: it loads the AOT DLLs and hotfix DLLs at runtime, locates the conventional entry type and method, and triggers the initialization of hotfix code via reflection. The application layer adapts this logic to the startup pipeline's `IHotfixLauncher` interface through [`ApplicationHotfixLauncher`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs).

## Startup Entry Overview

| Entry | Type | Purpose |
|------|------|------|
| `HotfixHelper.StartHotfix()` | `async void` | Triggered with default options, discards the return result |
| `HotfixHelper.StartHotfixAsync(StartupOptions)` | `async UniTask<HotfixLaunchResult>` | Loads asynchronously and returns the startup result |
| `ApplicationHotfixLauncher.StartAsync(StartupOptions)` | `UniTask<HotfixLaunchResult>` | `IHotfixLauncher` adapter, forwards to `HotfixHelper.StartHotfixAsync` |

Default parameters (applied when `options == null` or fields are empty):

| Field | Default Value |
|------|--------|
| `HotfixAssemblyName` | `Unity.Hotfix` |
| `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` |
| `HotfixEntryMethodName` | `Main` |

## Startup Steps

1. Call `HotfixHelper.StartHotfixAsync(options)`; the method enters the internal implementation `StartHotfixInternalAsync` wrapped in `try/catch`.
2. Resolve the final `assemblyName` / `entryTypeName` / `entryMethodName`, with default values of `Unity.Hotfix`, `Hotfix.HotfixLauncher`, and `Main` respectively.
3. Select the loading path based on the macro `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR`:
   - **HybridCLR enabled (and not Editor)**: First iterate over `AOTGenericReferences.PatchedAOTAssemblyList`, loading each AOT DLL via `GameApp.Asset.LoadAssetAsync<UnityEngine.Object>` and calling `RuntimeApi.LoadMetadataForAOTAssembly`; then load `Unity.Hotfix.dll` and call `Assembly.Load`.
   - **Editor or HybridCLR not enabled**: Go directly to `RunNative`, invoking the entry via reflection through `Utility.Assembly.GetType`.
4. After reflection locates the target type and method, `method.Invoke(null, null)` hands control over to the hotfix layer.
5. On success, returns `HotfixLaunchResult.Succeed()`; on exception, logs the error via `Log.Error` and returns `HotfixLaunchResult.Fail(e.Message)`.

public static async UniTask<HotfixLaunchResult> StartHotfixAsync(StartupOptions options)
{
    try
    {
        await StartHotfixInternalAsync(options);
        return HotfixLaunchResult.Succeed();
    }
    catch (Exception e)
    {
        Log.Error(e);
        return HotfixLaunchResult.Fail(e.Message);
    }
}

## Key Loading Paths

| Stage | Call | Description |
|------|------|------|
| AOT metadata loading | `RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet)` | In HybridCLR mode, all AOT DLLs must be loaded first; otherwise generic sharing in hotfix code will fail |
| Hotfix DLL loading | `Assembly.Load(assemblyDataHotfixDll, null)` | Loads a byte array as a runtime assembly |
| Entry reflection | `assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | Invokes the parameterless static entry via reflection |
| Native fallback | `Utility.Assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | In non-HybridCLR mode, looks up the entry type from the loaded AppDomain |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `entryType` is `null`, reflection throws `NullReferenceException` | The provided `HotfixEntryTypeName` does not match the type in the DLL, or `Unity.Hotfix.dll` was not packaged into assets | Verify that `options.HotfixEntryTypeName` exactly matches the namespace/class name in the DLL; check whether `Utility.Asset.Path.GetCodePath("Unity.Hotfix.dll")` resolves to the asset |
| Generic method calls throw `MissingMethodException` or `TypeLoadException` | In HybridCLR mode, the AOT DLLs in `AOTGenericReferences.PatchedAOTAssemblyList` were not loaded | Check whether the `ENABLE_GAME_FRAME_X_HYBRID_CLR` macro is enabled, and confirm that `AOTGenericReferences` has been generated and shipped with the package |
| `Unity.Hotfix` assembly cannot be loaded in the Editor | `StartHotfixInternalAsync` in the Editor iterates via `Utility.Assembly.GetAssemblies()` and fails to match due to case-sensitive names | Explicitly pass the correct name in `StartupOptions.HotfixAssemblyName`, or confirm the assembly name `Unity.Hotfix` matches the DLL |
| No error callback after `StartHotfix()` throws | `StartHotfix` is `async void`; exceptions are only logged | Switch to `StartHotfixAsync(options)` to receive the `HotfixLaunchResult`, and check the `Succeed` / `Fail` fields |
