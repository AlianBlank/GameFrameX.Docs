# 서비스 시작 시 GameApp.Entry / Init 초기화 실패가 발생하면 어떻게 하나요

서비스가 시작 입구 `GameFrameX.Launcher/Program.cs`에서 `GameApp.Entry`를 호출할 때 예외가 발생하거나, `Init` 콜백의 초기화 로직에서 오류가 발생하여 프로세스가 즉시 종료됩니다. 이 페이지는 오류 메시지를 기준으로 설정, 컴포넌트 등록, 프로토콜 스캔 중 어디에 문제가 있는지 빠르게 파악하도록 돕습니다.

## 빠른 진단

| 증상 / 오류 키워드 | 원인 | 수정 |
|-------------------|------|------|
| `EntryPointNotFoundException` / `GameApp.Entry`를 찾을 수 없음 | 시작 프로젝트가 `GameFrameX.Launcher`를 참조하지 않거나 기준 패키지가 복원되지 않음 | 아래 "수정 단계 - 1. 진입점을 찾을 수 없음" 참조 |

## 수정 단계

### 1. 진입점 `GameApp.Entry`를 찾을 수 없음

`GameApp.Entry`는 기준 엔진 패키지에 있으며, 런처는 이를 시작 총 진입점으로 사용합니다.

```csharp
// GameFrameX.Launcher/Program.cs
internal static class Program
{
    private static async Task Main(string[] args)
    {
#if DEBUG
        LogOptions.Default.IsConsole = true;
#endif
        await GameApp.Entry(args, () =>
        {
            CacheStateTypeManager.Init();
            MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
        }, LogAction);
    }
}
```

출처: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L1-L28)

처리 방법:

1. 시작 프로젝트 루트 디렉터리에서 `dotnet restore`를 실행하고, NuGet 소스에 접근 가능한지 확인합니다.
2. `.csproj`에 `GameFrameX.Launcher`(또는 해당 기준 패키지)가 참조되어 있는지 확인합니다.
3. 출력 디렉터리를 정리한 후 다시 빌드합니다: `dotnet clean && dotnet build`.

### 2. `CacheStateTypeManager.Init` 단계에서 예외 발생

`CacheStateTypeManager.Init`는 `AppsHandler`가 있는 어셈블리에서 `ICacheState`를 구현하는 모든 타입을 스캔하고, 해당 타입들의 Bson 매핑을 MongoDB 드라이버에 등록합니다.

```csharp
// GameFrameX.Apps/CacheStateTypeManager.cs
public static void Init()
{
    var assembly = typeof(AppsHandler).Assembly;
    BsonClassMapHelper.SetConvention();

    var types = assembly.GetTypes();
    foreach (var type in types)
    {
        var isImplWithInterface = type.IsImplWithInterface(typeof(ICacheState));
        if (isImplWithInterface)
        {
            HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
            BsonClassMapHelper.RegisterClass(type);
        }
    }
}
```

출처: [GameFrameX.Apps/CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L12-L45)

일반적인 원인 및 처리:

| 세부 증상 | 처리 |
|--------|------|
| `ReflectionTypeLoadException` | 어셈블리에 의존성이 누락된 어셈블리가 존재함, NuGet을 정리한 후 다시 빌드 |
| `BsonClassMap already registered for type` | `Init`가 중복 호출됨, 시작 진입점에서 한 번만 호출되는지 확인 |
| 일부 엔티티 직렬화 실패 | 엔티티 클래스에 `[BsonIgnoreExtraElements]`를 사용하거나 문서에 따라 필드를 보완 |

### 3. `MessageProtoHelper.Init` 프로토콜 초기화 실패

`Program.cs`에서 `MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly)`를 통해 모든 프로토콜 메시지 클래스를 디스패치 시스템에 등록합니다.

```csharp
MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
```

출처: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L12-L16)

처리 방법:

1. 프로토콜 생성기가 실행되었고, 프로젝트에 `MessageProtoHandler` 등의 클래스가 생성되었는지 확인합니다.
2. 프로토콜 클래스를 별도 프로젝트로 분리한 경우, 프로토콜 프로젝트를 시작 프로젝트에 참조하고, `typeof(MessageProtoHandler)`를 프로토콜 프로젝트의 해당 진입 타입으로 교체해야 합니다.
3. `Initialize`가 "중복 요청 ID / 작업 번호 충돌"을 발생시키면 클라이언트/서버 프로토콜 버전이 일치하지 않는 것이므로, 프로토콜을 다시 생성하고 버전을 동기화해야 합니다.

### 4. 설정 파일 관련

시작 프로세스는 `GameFrameX.Config`가 생성한 설정 테이블에 의존합니다(예: `Property`, `PropItem`, `TablesComponent` 등). 이 클래스들은 생성자 끝에서 `partial void PostInit();`를 호출합니다. 설정 테이블 파일이 누락되면 `TablesComponent.ResolveRef()` 이전에 이미 "테이블을 찾을 수 없음" 오류가 발생합니다.

처리 방법:

1. 먼저 설정 생성 도구를 실행합니다(일반적인 진입점은 `GameFrameX.Config.Tools` 또는 저장소 문서에 설명된 `dotnet run --project ...` 같은 명령), 모든 `*.cs`를 다시 생성합니다.
2. `appsettings.json`이 존재하고, MongoDB, Redis, 네트워크 리스닝 포트 등의 노드를 포함하는지 확인합니다.
3. 다시 생성한 후 시작 프로젝트를 컴파일합니다.

### 5. 시작 멈춤

`GameApp.Entry`가 계속 반환되지 않는다면:

- `Init` 콜백에 블로킹 호출이나 동기 대기가 있는지 확인합니다(예: `Thread.Sleep`, 동기 HttpClient).
- 네트워크 리스닝 설정이 올바르고, Mongo/Redis 연결에 접근 가능하며, 네트워크 컴포넌트가 재시도로 인해 멈추지 않는지 확인합니다.
- 디버그 모드에서 `LogOptions.Default.IsConsole = true`를 유지하여 멈춤 직전의 로그를 확인하기 쉽게 합니다.

## 검증

아래 순서대로 시작이 정상으로 복구되었는지 검증합니다:

1. `dotnet build`를 다시 실행하여 새로운 컴파일 오류가 없는지 확인합니다.
2. 프로그램을 시작하고, 로그에 `Server started` 또는 유사한 "리스닝 중" 알림이 나타나는지 확인합니다.
3. `mongosh` 등의 도구로 Mongo의 엔티티 컬렉션을 조회하여, `BsonClassMap` 등록이 성공했는지 확인합니다(시작 기간 중 예외 없음).
4. 클라이언트가 첫 번째 메시지를 보내면 해당 `MessageProtoHandler` 처리 함수에 올바르게 진입하는지 확인합니다.

위 사항이 모두 통과되었는데도 시작할 수 없다면, 전체 시작 로그와 스택을 수집하여 프레임워크 유지 보수 담당자에게 연락하고, 오류 컨텍스트에 있는 `Program.cs`의 `GameApp.Entry` 호출 소스 코드 버전을 첨부하세요.
