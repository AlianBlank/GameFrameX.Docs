# 常见问题

本文档汇总了使用 GlobalConfig コンポーネント过程中可能遇到的常见问题及解決策。

## 概要

GlobalConfigComponent 是 GameFrameX フレームワーク中的グローバル設定管理コンポーネント，主要に使用管理ゲーム应用的グローバル設定信息，包括应用版本检查地址、リソース版本检查地址、服务器地址等。该コンポーネント采用 Unity コンポーネント的形式実装，可能灵活地配置和使用。

> コンポーネント的详细機能説明お願いします参考 [GlobalConfig コンポーネント简介](./1-overview.1-introduction)。
> コンポーネント的完整 API お願いします参考 [GlobalConfigComponent](./4-core-component.1-global-config-component)。

## 安装与設定

### Q1: 如何安装 GlobalConfig コンポーネント？

GlobalConfig コンポーネント可能を通じて以下方法安装：

1. **を通じて manifest.json 安装**：在プロジェクト的 `manifest.json` ファイル中添加依赖：
   ```json
   {"com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git"}
   ```

2. **を通じて Unity Package Manager**：在 Unity 中选择 `Window > Package Manager`，然后点击 `+` 号添加 Git URL：
   ```
   https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git
   ```

3. **手动安装**：直接ダウンロード仓库并放置到 Unity プロジェクト的 `Packages` ディレクトリ下。

> 详细的安装手順お願いします参考 [安装方法](./2-installation.1-install-methods)。

### Q2: 安装后报 "Assembly has reference to missing assembly" 错误？

这是因为 GlobalConfig コンポーネント依赖以下包：
- `com.gameframex.unity` (版本 1.1.1)
- `com.gameframex.unity.web` (版本 1.1.2)

**解決策**：确保这些依赖包已正确安装。可能在 `manifest.json` 中添加完整依赖：

```json
{
  "dependencies": {
    "com.gameframex.unity": "1.1.1",
    "com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git",
    "com.gameframex.unity.web": "1.1.2"
  }
}
```

### Q3: Unity 版本兼容性如何？

に基づいて package.json，コンポーネントサポート的最低 Unity 版本为 **2017.1**。如果使用更低版本的 Unity，可能会出现兼容性问题。

## コンポーネント使用

### Q4: 如何将 GlobalConfigComponent 添加到シーン？

1. 在 Unity 编辑器中，作成或选择一个 GameObject
2. 在 Inspector 面板中，点击 **Add Component** 按钮
3. 搜索并选择 **Game Framework > Global Config**
4. コンポーネント将添加到选定的 GameObject 上

> 详细的添加手順お願いします参考 [添加到シーン](./3-getting-started.1-add-to-scene)。

### Q5: 可能在シーン中添加多个 GlobalConfigComponent 吗？

**不建议**。コンポーネント使用了 `[DisallowMultipleComponent]` 特性，这限制了同一 GameObject 上只能添加一个インスタンス。虽然技术上可能将コンポーネント添加到不同的 GameObject，但フレームワーク设计为单例模式，建议只在シーン中保留一个グローバル設定コンポーネント。

### Q6: 如何在代码中访问 GlobalConfigComponent？

由于コンポーネント使用了 `IsAutoRegister = false`，コンポーネント不会自动注册。典型的访问方法是在シーン中查找或を通じて引用访问：

```csharp
// を通じて FindObjectOfType 查找
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
if (globalConfig != null)
{
    string appVersionUrl = globalConfig.CheckAppVersionUrl;
    string resourceVersionUrl = globalConfig.CheckResourceVersionUrl;
}
```

> 详细的代码访问方法お願いします参考 [代码访问](./3-getting-started.3-code-access)。

### Q7: 如何を通じて代码动态設定配置？

可能在运行时を通じて代码設定各个プロパティ：

```csharp
var globalConfig = FindObjectOfType<GlobalConfigComponent>();

// 設定各种 URL
globalConfig.CheckAppVersionUrl = "https://example.com/check-app-version";
globalConfig.CheckResourceVersionUrl = "https://example.com/check-resource-version";
globalConfig.HostServerUrl = "https://example.com/server";

// 設定附加内容
globalConfig.Content = "{\"key\": \"value\"}";

// 設定グローバル設定信息
ResponseGlobalInfo globalInfo = new ResponseGlobalInfo
{
    // 配置プロパティ
};
globalConfig.SetGlobalConfig(globalInfo);
```

## プロパティ配置

### Q8: 各个プロパティ有什么作用？

| プロパティ | 説明 |
|------|------|
| **主机服务地址 (HostServerUrl)** | 后端服务器的地址，に使用连接ゲーム服务器 |
| **检测App版本地址インターフェース (CheckAppVersionUrl)** | 检查应用程序新版本的 URL 地址 |
| **检测リソース版本地址インターフェース (CheckResourceVersionUrl)** | 检查ゲームリソース更新的 URL 地址 |
| **补充程序集列表 (AOTCodeList)** | AOT 编译时必要补充的程序集列表（JSON 格式） |
| **附加内容 (Content)** | 其他附加的配置内容 |
| **补充元数据列表 (AOTCodeLists)** | AOT 补充元数据列表 |

> 详细的プロパティ配置説明お願いします参考 [配置プロパティ](./3-getting-started.2-configure-properties)。

### Q9: AOTCodeList 和 AOTCodeLists 有什么区别？

- **AOTCodeList** (字符串クラス型)：に使用在 Inspector 中以 JSON 字符串格式输入 AOT 代码列表
- **AOTCodeLists** (列表クラス型)：解析后的 AOT 代码列表，供运行时使用

設定 AOTCodeList 时，系统会自动解析 JSON 并填充到 AOTCodeLists：

```csharp
// 設定 JSON 格式的 AOT 代码列表
globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\", \"Assembly3\"]";

// 自动解析，可能在 AOTCodeLists 中取得解析结果
List<string> aotCodeLists = globalConfig.AOTCodeLists;
```

## AOT 配置関連

### Q10: 什么是 AOT 代码列表？为什么要配置它？

AOT (Ahead-of-Time) 编译是 .NET 的一种编译模式，主要に使用 IL2CPP 等平台。某些泛型クラス型和反射代码在 AOT 编译时可能无法正确生成，必要を通じて AOT 代码列表来指定必要额外处理的程序集。

> 详细的 AOT 配置説明お願いします参考 [AOT 代码列表配置](./7-aot-configuration.1-aot-code-list)。

### Q11: 設定 AOTCodeList 时出现 JSON 解析错误？

如果在設定 AOTCodeList 时遇到解析错误，可能的原因和解決策：

1. **JSON 格式错误**：确保 JSON 格式正确
   ```csharp
   // 错误示例
   globalConfig.AOTCodeList = "Assembly1, Assembly2"; // 错误的格式

   // 正确示例
   globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\"]"; // 正确的 JSON 数组格式
   ```

2. **特殊字符转义**：如果字符串中包含特殊字符，确保正确转义

### Q12: AOT 代码列表为空会导致什么问题？

如果 AOT 代码列表为空，某些使用泛型或反射的機能可能在 IL2CPP 平台上无法正常工作。具体表现包括：
- 泛型クラス型序列化失败
- 反射取得クラス型失败
- 某些动态代码执行異常

## 编辑器関連

### Q13: 在 Play 模式下无法编辑プロパティ？

这是正常行为。Inspector 中的プロパティ在 **Play 模式**下是只读的，这是为了保护运行时配置不被意外修改。

```csharp
// GlobalConfigComponentInspector.cs 中的実装
EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode & Application.isPlaying);
{
    // プロパティ编辑区域
}
EditorGUI.EndDisabledGroup();
```

### Q14: 原始数据 (OriginalData) 是只读的？

是的，原始数据プロパティ在 Inspector 中是只读的。该プロパティに使用存储从服务器取得的原始配置数据，通常在运行时を通じて代码設定：

```csharp
// 設定原始数据
globalConfig.SetOriginalData(jsonString);

// 读取原始数据
string originalData = globalConfig.OriginalData;
```

## 运行时関連

### Q15: コンポーネント的 Awake メソッド有什么特殊处理？

コンポーネント重写了 `Awake` メソッド，并将 `IsAutoRegister` 設定为 `false`：

```csharp
protected override void Awake()
{
    IsAutoRegister = false;
    base.Awake();
}
```

这意味着コンポーネント不会自动注册到フレームワーク的コンポーネント管理系统中，必要開発者手动管理或を通じて其他方法访问。

### Q16: 如何从服务器取得并設定グローバル設定？

典型的工作フロー如下：

1. 使用配置的 URL 向服务器发送お願いします求
2. 服务器返回配置数据（JSON 格式）
3. 解析响应数据到 ResponseGlobalInfo 对象
4. 呼び出し SetGlobalConfig 設定グローバル設定

```csharp
// 伪代码示例
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
string url = globalConfig.HostServerUrl;

// 发送网络お願いします求取得配置
// ...
ResponseGlobalInfo response = ParseServerResponse(data);
globalConfig.SetGlobalConfig(response);

// 访问配置信息
ResponseGlobalInfo info = globalConfig.GlobalInfo;
```

## 故障排查

### Q19: 常见问题排查手順

1. **检查依赖**：确认所有依赖包已正确安装
2. **检查 Unity 版本**：确保使用 Unity 2017.1 或更高版本
3. **检查コンポーネント添加**：确认 GlobalConfigComponent 已正确添加到シーン
4. **检查プロパティ配置**：确认必要的 URL プロパティ已配置
5. **查看日志**：检查 Unity 控制台是否有错误或警告信息

### Q20: 运行时找不到 GlobalConfigComponent？

如果 `FindObjectOfType<GlobalConfigComponent>()` 返回 null，可能原因：
1. コンポーネント未添加到任何 GameObject
2. コンポーネント添加到了未激活的 GameObject
3. シーン未正确加载

**解決策**：
- 确认コンポーネント已添加到シーン中的活动 GameObject
- 确保 GlobalConfig 所在的シーン已被加载

## 設定ファイル为空或未加载

**原因**：未在 Inspector 中配置 GlobalConfigComponent 或配置ファイル路径不正确。

**解決策**：在 Unity 编辑器中選択挂载 GlobalConfigComponent 的 GameObject，在 Inspector 面板中检查配置项是否已正确填写。

## 版本检查 URL 无法访问

**原因**：服务器地址配置错误或网络不可达。

**解決策**：检查 `AppVersionCheckUrl` 和 `ResourceVersionCheckUrl` 是否为有效的 HTTP/HTTPS 地址，确保设备网络连通。
