# How to Set Player ID and Public Properties

By calling `SetPlayerId(string playerId)` and `SetPublicProperties(string key, object value)` on the `IGameAnalyticsManager` interface, you can attach the player identifier and public properties to all subsequent reported events during game runtime. The framework automatically writes a set of device public properties at initialization, so you only need to append your business fields.

## Prerequisites

- The project has the `com.gameframex.unity.gameanalytics` package installed and the `GameAnalyticsComponent` component attached.
- `Init` / `ManualInit` has been called to complete initialization (you can confirm with `IsInit()`).

## Steps

1. Get the manager instance (via the manager interface exposed by `GameAnalyticsComponent`).
2. Set the player ID after a successful player login:

```csharp
// After a successful player login, bind the player ID (all subsequent events will carry this ID)
GameAnalyticsComponent.Instance.SetPlayerId("123456789");
```

The interface signature of `SetPlayerId` is `void SetPlayerId(string playerId)`. It is defined in `IGameAnalyticsManager`, declared as an abstract method in the base class `BaseGameAnalyticsManager`, and implemented by concrete platform subclasses:

```csharp
/// <summary>
/// Set player ID
/// </summary>
/// <param name="playerId">Player ID</param>
void SetPlayerId(string playerId);
```

Source: [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L100-L104)

3. Append business public properties, setting one key-value pair at a time:

```csharp
// Each call writes one Key; setting the same Key repeatedly overwrites the old value
GameAnalyticsComponent.Instance.SetPublicProperties("server_id", "s1001");
GameAnalyticsComponent.Instance.SetPublicProperties("vip_level", 5);
```

The base class implementation ignores empty keys and writes into the internal dictionary `m_PublicProperties`:

```csharp
public virtual void SetPublicProperties(string key, object value)
{
    if (string.IsNullOrEmpty(key))
    {
        return;
    }

    m_PublicProperties[key] = value;
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L53-L65)

4. (Optional) Read or clear public properties:

```csharp
// Read: returns a copy of the internal dictionary; modifying the copy does not affect the actual public properties
Dictionary<string, object> props = GameAnalyticsComponent.Instance.GetPublicProperties();

// Clear business properties; device information public properties will be automatically re-written afterwards
GameAnalyticsComponent.Instance.ClearPublicProperties();
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L67-L83)

## Built-in Device Public Properties

During initialization, the framework automatically writes the following public properties via `AddDeviceInfoToPublicProperties()`. You do not need to set them manually, and they are automatically restored after `ClearPublicProperties()`:

| Category | Property Key |
|------|----------|
| Device | `device_id`, `device_model`, `device_type` |
| Operating System | `os` |
| Application | `app_version`, `unity_version`, `platform` |
| Hardware | `processor_type`, `processor_count`, `processor_frequency`, `system_memory_size` |
| Graphics | `graphics_device_name`, `graphics_device_type`, `graphics_memory_size`, `graphics_device_version`, `graphics_shader_level` |
| Screen | `screen_width`, `screen_height`, `screen_dpi`, `screen_refresh_rate` |
| Localization | `system_language`, `current_culture` |
| Network | `network_type` (possible values: `No Network` / `Mobile Data` / `WiFi` / `Unknown`) |

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L86-L144)

## Common Variants

- **Switching accounts**: First call `ClearPublicProperties()` to clear the old account's business fields, then call `SetPlayerId` and `SetPublicProperties` again. Device information properties are automatically restored after clearing.
- **Overriding built-in properties**: If a custom Key matches one in the table above, it directly overwrites the built-in value (written into the same dictionary); it is generally recommended to avoid this so you don't lose device dimension information.

## Common Errors

- **Empty Keys are silently ignored**: `SetPublicProperties` directly returns on `string.IsNullOrEmpty(key)` without throwing an exception or writing anything; if a setting doesn't take effect, first check whether the Key is empty.
- **`ClearPublicProperties` does not clear the player ID**: This method only clears the public properties dictionary and rebuilds the device properties; the player ID must be set again separately via `SetPlayerId`.
- **`GetPublicProperties` returns a copy**: `return new Dictionary<string, object>(m_PublicProperties);` — modifying the returned value directly does not affect the public properties actually reported.

## Background

Public properties are stored in the base class's `m_PublicProperties` dictionary and are carried along with all events at reporting time, making them suitable for relatively stable dimension fields (channel, server, membership level, etc.); frequently changing values are better reported using an event's custom fields via `Event(string eventName, Dictionary<string, object> customF)`.
