# How to Listen to Update / FixedUpdate / LateUpdate

Through the `AddUpdateListener` / `AddFixedUpdateListener` / `AddLateUpdateListener` methods of `IMonoManager`, you can hook your own callbacks into the Mono frame loop managed by the GameFrameX framework, without needing to place an additional `MonoBehaviour` subclass in the scene.

## Prerequisites

- The framework's `MonoManager` module has been initialized (loaded by the framework launcher, usually no manual handling required).
- The project references the `GameFrameX.Mono.Runtime` assembly.
- After `using GameFrameX.Mono.Runtime;`, obtain the manager instance via the framework's `GameFrameworkEntry.GetModule<IMonoManager>()`.

## Steps

1. Obtain the Mono manager instance.

```csharp
using GameFrameX.Mono.Runtime;

IMonoManager mono = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IMonoManager>();
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L39-L51)

2. Register an Update listener. The callback signature is `Action<float, float>`, where the first parameter is the elapsed time `elapseSeconds`, and the second parameter is the real elapsed time `realElapseSeconds`.

```csharp
mono.AddUpdateListener((elapseSeconds, realElapseSeconds) =>
{
    // Per-frame logic
});
```

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L142-L156)

3. Register a FixedUpdate listener. The two floating-point parameters passed in are `Time.fixedDeltaTime` and `Time.fixedUnscaledDeltaTime`.

```csharp
mono.AddFixedUpdateListener((fixedDeltaTime, fixedUnscaledDeltaTime) =>
{
    // Fixed-step logic (commonly used for physics-related tasks)
});
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L87-L97)

4. Register a LateUpdate listener. This callback is executed after all `Update` calls, making it suitable for logic that needs a final pass, such as camera following.

```csharp
mono.AddLateUpdateListener((deltaTime, unscaledDeltaTime) =>
{
    // Executed after all Updates
});
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L75-L85)

5. When no longer needed, use the corresponding `RemoveXxxListener` to remove the listener. The delegate passed in must be the same instance as the one used during registration.

```csharp
Action<float, float> handler = (a, b) => { /* ... */ };
mono.AddUpdateListener(handler);
// Later:
mono.RemoveUpdateListener(handler);
```

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L157-L180)

## Common Variants

- **Capture local variables in a Lambda**: Suitable for simple logic, but you cannot get the same delegate instance when removing the listener, so you can only skip handling uniformly when the object is destroyed.
- **Cache as a field**: Store the `Action<float, float>` in a member field so that you can call `Remove` repeatedly later, avoiding duplicate registrations.

```csharp
private Action<float, float> _tick;

private void OnEnable()
{
    var mono = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IMonoManager>();
    _tick = (a, b) => DoWork(a, b);
    mono.AddUpdateListener(_tick);
}

private void OnDisable()
{
    var mono = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IMonoManager>();
    if (_tick != null) mono.RemoveUpdateListener(_tick);
}
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentNullException: action` | `AddXxxListener` is passed `null` | Do not pass `null`; check for null first if necessary |
| Listener is not called | Module is not initialized, or the wrong instance is obtained | Use `GameFrameworkEntry.GetModule<IMonoManager>()` to get the manager |
| Callback is executed multiple times per frame | The same delegate has been added repeatedly | Register in `OnEnable`, remove in `OnDisable`, or use a field cache |
| Still executing after removal | A new lambda was passed during removal, so the references are not equal | Cache the delegate instance used during registration before calling `Remove` |

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L142-L156)

## Background (Optional)

`MonoManager` internally maintains a `LinkedList<Action<float, float>>` for each of the three frame loops. When `Update` / `FixedUpdate` / `LateUpdate` is triggered, it iterates through the list and passes in the corresponding time parameters (using `Time.deltaTime`, `Time.fixedDeltaTime`, etc.). Listener registration and removal are protected by `lock`, making them safe to call in multithreaded environments.
