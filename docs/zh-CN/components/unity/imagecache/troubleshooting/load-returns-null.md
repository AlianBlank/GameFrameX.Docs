# 图片加载返回 null 怎么办

调用 `LoadImageAsync` 拿到 `null`，说明图片加载失败。下面按现象列出常见原因、排查方法和修复步骤。

## 快速诊断

| 症状（日志原文） | 原因 | 修复 |
|------------------|------|------|
| `ImageCache: url is null or empty.` | 传入的 URL 为空字符串或 `null` | 调用前检查 URL，传入有效地址 |
| `ImageCache: url must start with http:// or https://. url: {0}` | URL 不是以 `http://` 或 `https://` 开头 | 修正 URL 协议头 |
| `ImageCache: download failed. url: {0}` | 远端服务器不可达、404 或网络受限 | 检查网络与地址，详见下文「下载失败」 |
| `Download manager is invalid.`（启动时致命日志） | 未安装 `IDownloadManager` 模块 | 注册 `Download` 组件 |
| `ImageCache manager is invalid.`（启动时致命日志） | 组件未注册到 `GameFrameworkEntry` | 按框架流程添加组件 |
| 无任何日志且返回 `null` | 缓存文件被改坏 / `Texture2D.LoadImage` 失败 | 清理缓存后重试，详见下文 |

## 修复步骤

### URL 无效

`LoadImageAsync` 在 URL 为空或不是 `http(s)://` 开头时直接返回 `null`，并打印对应警告日志。

```csharp
// 错误写法
await component.LoadImageAsync(null);                 // 空
await component.LoadImageAsync("ftp://example.com/a.png"); // 错误协议
await component.LoadImageAsync("/local/path/a.png");   // 本地路径无效

// 正确写法
await component.LoadImageAsync("https://example.com/a.png");
```

Source: [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

### 启动时模块缺失

`ImageCacheComponent.Awake` 会获取 `IImageCacheManager` 与 `IDownloadManager`，任一缺失都会写 `Fatal` 日志并提前返回，使后续所有加载返回 `null`。

```csharp
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
// ...
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
```

修复方式：

1. 在场景的 `GameFramework` 节点下添加 `ImageCache` 组件（菜单 `GameFrameX/Image Cache`）。
2. 同时添加 `Download` 组件，并保证 `Download Component` 字段指向实现了 `IDownloadManager` 的具体类。
3. 重启场景，确认控制台不再出现上述 `Fatal` 日志。

Source: [ImageCacheComponent.cs#L37-L65](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L37-L65)

### 下载失败

非 WebGL 平台，磁盘未命中时会调用 `IDownloadManager.AddDownload`。下载失败会触发 `DownloadFailure` 事件，方法写入 `ImageCache: download failed. url: {0}` 并返回 `null`。

```csharp
private async Task<Texture2D> LoadImageDiskCacheAsync(string url, CancellationToken cancellationToken)
{
    // ...
    var downloadSuccess = await tcs.Task;
    if (!downloadSuccess)
    {
        Log.Warning("ImageCache: download failed. url: {0}", url);
        return null;
    }
    // ...
}
```

排查顺序：

1. 用浏览器或 `curl` 直接访问该 URL，确认 200 且返回图片字节流。
2. 检查运行时沙盒权限（iOS ATS、Android 网络权限、WebGL CORS）。
3. WebGL 平台没有磁盘缓存，浏览器直接用 `UnityWebRequestTexture.GetTexture` 拉取，失败时日志为 `ImageCache: download failed. url: {0}, error: {1}`——优先排查跨域与 HTTPS 配置。
4. 若已下载过但再次失败，调用 `RemoveCache(url)` 后重试。

Source: [ImageCacheManager.cs#L97-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L97-L171)

### 缓存文件损坏 / 解码失败

下载成功但后续读取或解码失败时，方法静默返回 `null`，不会有专属警告日志。

```csharp
var buffer = FileHelper.ReadAllBytes(cachePath);
if (buffer == null || buffer.Length == 0)
{
    return null;
}

var texture = new Texture2D(1, 1, TextureFormat.RGBA32, false, false);
if (!texture.LoadImage(buffer))
{
    Object.Destroy(texture);
    return null;
}
```

修复方式：

1. 调用 `RemoveCache(url)` 或 `ClearCache()` 清理本地缓存后重新加载。
2. 确认 `CachePath` 在 Inspector 中可写且磁盘未满（`MaxDiskSize` 触发回收时旧文件可能被清掉）。
3. 确认远端返回的就是 PNG / JPG 字节流，不是 HTML 错误页。

Source: [ImageCacheManager.cs#L152-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L152-L171)

### 取消令牌触发

调用方传入的 `CancellationToken` 触发取消时，方法也会返回 `null`，且不会写失败日志。

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return null;
}
```

在 `await` 之后务必再次检查 `cancellationToken.IsCancellationRequested`，避免把「被取消」当作「加载失败」处理。

Source: [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149)

## 验证

1. 控制台不再出现 `ImageCache: ...` 警告或 `Fatal` 日志。
2. `LoadImageAsync` 返回非空 `Texture2D`，可绑定到 UI / `Sprite` 上正常显示。
3. 二次加载时控制台不再触发网络请求，并能在 `Config.CachePath` 下看到以 URL 的 MD5 命名的缓存文件。
