# 언어 전환이 적용되지 않거나 저장되지 않음: 시스템 언어 폴백과 Setting 영속화 검사

`Language`가 여전히 센티널 값 `"zxx"`(`UnknownLocalization`)인 경우, 프레임워크는 런타임에 **자동으로 시스템 언어로 폴백**하며, `LocalizationComponent`를 통해 언어를 설정할 때마다 Setting에 쓰고 `Save()`로 영속화합니다. 언어가 "적용 안 됨/저장 안 됨"이 되는 원인의 대부분은 `LocalizationManager.Language`를 직접 수정한 것(Setting 쓰기 우회), 에디터 모드에서 `m_IsEnableEditorMode` + `EditorLanguage`로 덮어씌워진 것, 또는 `"zxx"`를 전달해 거부된 것입니다. 아래에서 증상별로 하나씩 확인합니다.

## 해결 단계

### 해결 1: `LocalizationComponent.Language`로 전환 및 영속화

영속화는 `LocalizationComponent` 계층의 setter에서만 발생합니다: Setting 키 `LocalizationComponent.Language`를 쓰고 즉시 `Save()`를 호출한 뒤, Before / Change / After 세 가지 언어 이벤트를 순서대로 발생시킵니다. `LocalizationManager.Language`를 직접 수정하면 Setting에 쓰지 않으므로 재시작 시 손실됩니다.

```csharp
// 올바른 예: 컴포넌트 계층을 통해 할당 —— Setting 쓰기 + Save + 세 가지 언어 이벤트 트리거
GameEntry.GetComponent<LocalizationComponent>().Language = "en_US";

// 잘못된 예: 컴포넌트 계층을 우회하면 재시작 후 손실됨 (Setting을 쓰지 않고, 이벤트도 발생하지 않음)
// GameFrameXEntry.GetModule<ILocalizationManager>().Language = "en_US";
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L140-L171)

해당 Setting 키와 읽기 순서(getter는 먼저 Setting을 조회하고, 여전히 알 수 없을 때만 폴백):

```csharp
get
{
    if (m_LocalizationManager.Language == UnknownLocalization)
    {
        var value = m_SettingComponent.GetString(nameof(LocalizationComponent) + "." + nameof(Language));
        if (value.IsNotNullOrWhiteSpace())
        {
            m_LocalizationManager.Language = value;
        }
    }

    return m_LocalizationManager.Language;
}
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L143-L153)

`DefaultLanguage`의 동작도 완전히 동일하며, 키 이름만 `LocalizationComponent.DefaultLanguage`로 바뀝니다: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L104-L128)

### 해결 2: 에디터에서 언어가 `EditorLanguage`로 덮어씌워짐

`Start()`에서는 에디터 모드에 따라 두 가지 경로로 나뉩니다: `m_IsEnableEditorMode`가 체크되어 있으면 에디터 내 언어가 `EditorLanguage`로 강제 설정되고, 빌드 환경(또는 체크되어 있지 않은 경우)에서는 `Language == UnknownLocalization`일 때만 시스템 언어로 폴백합니다.

```csharp
#if UNITY_EDITOR
            if (m_IsEnableEditorMode)
            {
                Language = EditorLanguage != UnknownLocalization ? EditorLanguage : m_LocalizationManager.SystemLanguage;
            }
#else
            if (Language == UnknownLocalization)
            {
                Language = m_LocalizationManager.SystemLanguage;
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L270)

조작 방법:

1. 씬에서 Localization 컴포넌트를 선택하고 **Is Enable Editor Mode**가 체크되어 있는지 확인합니다.
2. 체크되어 있으면, Inspector의 **Editor Language**(기본값 `zh_CN`)가 매번 Play할 때 이전에 저장된 언어를 덮어씁니다. 체크를 해제하거나 검증하려는 언어로 변경하세요.
3. 기본 직렬화 값 참고(`m_EditorLanguage`/`m_DefaultLanguage` 모두 `"zh_CN"`이며, 에디터 모드는 기본적으로 비활성화):

```csharp
        [SerializeField] private string m_EditorLanguage = "zh_CN";

        [SerializeField] private string m_DefaultLanguage = "zh_CN";

        [SerializeField] private bool m_EnableLoadDictionaryUpdateEvent = false;
        [SerializeField] private bool m_IsEnableEditorMode = false;
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L71)

### 해결 3: `zxx` 전달로 인한 `Language is invalid.` 발생

`"zxx"`는 "알 수 없는 현지화"를 나타내는 센티널 값이며, 두 setter 모두 이를 거부합니다:

```csharp
            set
            {
                if (value == UnknownLocalization)
                {
                    throw new GameFrameworkException("Language is invalid.");
                }

                _language = value;
            }
```

출처: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L100-L108)

| 속성 | 예외 메시지 원문 | 트리거 값 |
|------|--------------|--------|
| `LocalizationManager.Language` | `Language is invalid.` | `"zxx"` |
| `LocalizationManager.DefaultLanguage` | `default Language is invalid.` | `"zxx"` |

`default Language is invalid.`의 출처는 [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L71-L83)를 참조하세요. 할당 시 실제 언어 코드를 사용하면 됩니다.

### 해결 4: Helper 생성 실패로 인한 `SystemLanguage` 사용 불가

`Start()`은 순서대로 `BaseComponent`, `EventComponent`, `SettingComponent`에 의존하며, 하나라도 없으면 `Log.Fatal` 후 `return`하여 언어 읽기/쓰기가 모두 마비됩니다. 이어서 `m_LocalizationHelperTypeName`에 따라 Helper를 생성하며, 실패하면 로그에 `Can not create localization helper.`가 출력됩니다. 그리고 `SystemLanguage` 내부에는 널 가드가 있어 Helper가 null이면 즉시 예외를 던집니다:

```csharp
        public string SystemLanguage
        {
            get
            {
                GameFrameworkGuard.NotNull(_localizationHelper, nameof(_localizationHelper));
                return _localizationHelper.SystemLanguage;
            }
        }
```

출처: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L115-L122)

조작 방법:

1. 씬에 Setting/Event 컴포넌트가 존재하는지 확인합니다(로그에 `Setting component is invalid.` / `Event component is invalid.`가 나타나면 누락된 것입니다). 출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227-L246)
2. Inspector의 **Localization Helper Type Name**이 여전히 기본 전체 이름인지 확인합니다:

```csharp
        [SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

3. 기본 Helper의 시스템 언어는 `CultureInfo.CurrentCulture`에서 가져오며, `-`를 `_`로 교체합니다(예: `zh-CN` → `zh_CN`). 기기의 지역 형식이 사전 이름 규칙과 일치하지 않으면 "폴백 언어가 영원히 맞지 않는" 근본 원인이 됩니다:

```csharp
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
```

출처: [DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L52-L55)

`LocalizationHelperBase`를 상속해 `SystemLanguage`를 재정의하고(추상 정의는 [LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L47) 참조), **Custom Localization Helper** 슬롯을 통해 기본 구현을 교체할 수 있습니다.

### 해결 5: 언어 전환 후 텍스트가 갱신되지 않음

`LocalizationComponent.Language`의 setter는 저장 후 순서대로 세 가지 이벤트를 트리거합니다: `LocalizationLanguageChangeBeforeEventArgs`, `LocalizationLanguageChangeEventargs`(Change), `LocalizationLanguageChangeAfterEventArgs`이며, 모두 `oldLanguage`와 새 언어를 담고 있습니다. 사전 재로드와 UI 갱신은 이러한 이벤트를 구독하여 수행해야 하며, 일반적인 시점은 After입니다:

```csharp
var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventargs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
```

출처: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L163-L168)

이벤트 인자 정의는 [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41)를 참조하세요.

## 검증

1. **언어 값**: Inspector에서 Localization 컴포넌트를 선택하면 패널에 `Language`, `System Language` 두 개의 읽기 전용 필드가 바로 표시됩니다([LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L70-L72)). 언어 전환 후 `Language`가 새 값이 되고 `System Language`가 기기 지역 값인지 확인합니다.
2. **영속성**: 언어 설정 → Play 중지 → 다시 Play 시 `Language`는 새 값을 유지해야 합니다(getter가 Setting 키 `LocalizationComponent.Language`에서 다시 읽어옵니다).
3. **폴백 로직**: 로컬 Setting을 지운 상태에서 다시 Play하면 `Language`는 `SystemLanguage`와 같아야 합니다. `LocalizationManager.Language`가 설정되지 않았을 때 시스템 언어를 반환하기 때문입니다:

```csharp
            get
            {
                if (_language == UnknownLocalization)
                {
                    return SystemLanguage;
                }

                return _language;
            }
```

출처: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L91-L99)

4. **사전**: 정상적으로 값을 가져오면 더 이상 `<NoKey>{key}` 플레이스홀더가 출력되지 않습니다([LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L168-L177)). 여전히 나타난다면 현재 언어의 사전이 로드되지 않았거나 Key가 누락된 것이므로, 해당 언어의 사전을 보완하세요.

## 배경

`Language`는 센티널 값 `"zxx"`(`LocalizationManager.UnknownLocalization` 상수, [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L53) 참조)으로 "설정되지 않음"을 나타내며, 세 곳의 폴백 체인은 다음과 같습니다: 컴포넌트 계층 getter → Setting 영속 값; 매니저 getter → `SystemLanguage`; `Start()` → 시스템 언어 최종 폴백 대입. 언어 코드는 RFC 5646 스타일을 따릅니다(컴포넌트의 `[HelpURL]`이 바로 해당 규격을 가리킵니다). 내부적으로는 `-` 대신 `_`를 통일하여 사용합니다.
