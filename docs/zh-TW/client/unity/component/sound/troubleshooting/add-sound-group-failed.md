# 音效群組已存在 / 新增失敗時的處理方法

當呼叫 `SoundComponent` 的 `AddSoundGroup` 時傳回 `false` 或擲出 `GameFrameworkException`,通常表示群組名稱重複或名稱無效。本頁面將引導您快速找出原因並提供修正步驟。

## 快速診斷

| 症狀 | 原因 | 修正 |
|------|------|------|
| `AddSoundGroup` 傳回 `false` 且無例外 | 已存在相同名稱的音效群組 | 先以 `HasSoundGroup` 確認，若已存在則不再新增 |
| 發生 `GameFrameworkException: Sound group name is invalid.` 例外 | 音效群組名稱為 `null`、空字串或全為空白 | 傳入去除前後空白後仍非空的群組名稱 |
| 在編輯器 Inspector 中看不到剛新增的群組 | 群組是在執行階段以程式碼新增，不會寫回 Inspector | 僅供執行階段除錯用途使用；若需永久儲存，請在 Inspector 中預先設定 |
| 新增後立即播放仍無聲音 | 新增已成功，但 `AgentHelperCount` 未設定或音量被靜音 | 檢查參數 `soundGroupMute` / `soundGroupVolume` |

## 修正步驟

### 1. 新增前先確認是否存在

`AddSoundGroup` 在已存在相同名稱的群組時會直接傳回 `false`。建議先以 `HasSoundGroup` 進行防護檢查：

```csharp
using GameFrameX.Sound.Runtime;

const string groupName = "UI";

if (!GameEntry.Sound.HasSoundGroup(groupName))
{
    GameEntry.Sound.AddSoundGroup(groupName, false, false, 1f, new DefaultSoundGroupHelper());
}
```

API 簽名請參閱 [ISoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Interface/ISoundManager.cs#L77-L104):

- `bool HasSoundGroup(string soundGroupName)`
- `bool AddSoundGroup(string soundGroupName, ISoundGroupHelper soundGroupHelper)`
- `bool AddSoundGroup(string soundGroupName, bool soundGroupAvoidBeingReplacedBySamePriority, bool soundGroupMute, float soundGroupVolume, ISoundGroupHelper soundGroupHelper)`

實作位於 [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L167-L255)。

### 2. 處理「群組名稱無效」例外

原始碼會在群組名稱為空時立即擲出例外：

```csharp
if (string.IsNullOrWhiteSpace(soundGroupName))
{
    throw new GameFrameworkException("Sound group name is invalid.");
}
```

修正方法：呼叫前先進行驗證：

```csharp
string groupName = inputName?.Trim();
if (string.IsNullOrEmpty(groupName))
{
    // 執行您自己的後備邏輯。例如：使用預設群組 "Sound"
    groupName = "Sound";
}
GameEntry.Sound.AddSoundGroup(groupName, new DefaultSoundGroupHelper());
```

例外擲出位置請參閱 [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L171-L186)。

### 3. 處理因大小寫或前後空白導致「看似不存在」的現象

`HasSoundGroup` / `AddSoundGroup` 內部以字面字串作為 Key(參閱 [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L167-L186))。`"UI"`、`"ui"` 與 `" UI "` 會被視為不同的群組，因此看起來像新增失敗，實際上是新增了重複的群組。

修正方法：呼叫前統一執行 `Trim()` 並制定大小寫規則。例如全部使用 `ToLowerInvariant()`,或遵循專案制定的命名規範。

### 4. 防止重複初始化的常見模式

將「確保存在」封裝為單一輔助方法，集中處理：

```csharp
public static void EnsureSoundGroup(string name, bool mute = false, float volume = 1f)
{
    var sound = GameEntry.Sound;
    if (sound.HasSoundGroup(name))
    {
        return;
    }
    sound.AddSoundGroup(name, false, mute, volume, new DefaultSoundGroupHelper());
}
```

在場景切換、模組啟動等進入點統一呼叫 `EnsureSoundGroup("Music")`、`EnsureSoundGroup("SFX")`、`EnsureSoundGroup("UI")`,避免各個業務程式碼自行新增而產生重複。

## 驗證

1. 在新增邏輯前後分別留下日誌，確認 `HasSoundGroup` 的傳回值與預期一致(新增前為 `false`,新增後為 `true`)。
3. 對相同名稱的群組再次呼叫 `AddSoundGroup` 時，應傳回 `false` 且不擲出例外。
2. 以空字串 / `null` 觸發一次例外路徑，確認例外訊息為 `Sound group name is invalid.`。這有助於日後排查問題時的識別。
