# Tag 태그를 사용하여 다운로드 작업 그룹 관리

`AddDownload`에 `tag` 문자열을 전달하면 같은 종류의 다운로드 작업을 하나의 그룹으로 묶을 수 있고, `GetDownloadInfos(tag)`로 해당 그룹의 모든 작업 상태를 한 번에 조회할 수 있습니다. 이 페이지에서는 작업에 Tag를 지정하는 방법, Tag별로 조회하는 방법, 그리고 일반적인 오류를 설명합니다.

## 사전 조건

- `com.gameframex.unity.download` 패키지가 설치되어 있고, 씬에 `DownloadComponent`가 추가되어 있어야 합니다.
- `DownloadComponent` 참조를 이미 가져온 상태여야 합니다. 예: `GameEntry.GetComponent<DownloadComponent>()`.
- `AddDownload`의 기본 호출 방법을 이미 알고 있어야 합니다(컴포넌트의 `AddDownload(string, string)` 오버로드 참조).

## 작업 단계

### 1. 다운로드 작업에 Tag 지정

`tag` 매개변수가 있는 `AddDownload` 오버로드를 호출합니다. Tag는 일반 문자열이며, 그 의미는 직접 정의합니다. 예: `"asset-bundle"`, `"lua-3.2.0"`, `"res-avatar"`.

```csharp
// tag만 지정, 기본 우선순위 및 null userData 사용
int id1 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/a.png",
    downloadUri:  "https://example.com/a.png",
    tag:          "asset-bundle");

// tag + 우선순위 지정
int id2 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/b.png",
    downloadUri:  "https://example.com/b.png",
    tag:          "asset-bundle",
    priority:     10);

// tag + 우선순위 + userData 지정(전체 버전)
int id3 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/c.png",
    downloadUri:  "https://example.com/c.png",
    tag:          "asset-bundle",
    priority:     10,
    userData:     myCallback);
```

### 2. Tag로 그룹의 모든 작업을 한 번에 조회

`GetDownloadInfos(string tag)`로 해당 그룹의 `TaskInfo[]`를 얻거나, `GetDownloadInfos(string tag, List<TaskInfo> results)`로 기존 리스트를 재사용해 GC를 피할 수 있습니다.

```csharp
// TaskInfo[] 반환
TaskInfo[] infos = downloadComponent.GetDownloadInfos("asset-bundle");
foreach (var info in infos)
{
    Debug.Log($"tag={info.Tag} status={info.Status} progress={info.Progress}");
}

// List를 재사용하여 매 프레임 새 배열 할당 방지
var buffer = new List<TaskInfo>();
downloadComponent.GetDownloadInfos("asset-bundle", buffer);
```

출처: [DownloadComponent.cs#L230-L245](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L230-L245), [DownloadManager.cs#L225-L243](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L225-L243)

### 3. Tag별 진행률 집계

Tag를 "배치" 차원으로 삼아 UI에서 전체 배치의 진행률을 표시합니다:

```csharp
void Update()
{
    var infos = downloadComponent.GetDownloadInfos("asset-bundle");
    if (infos.Length == 0) return;

    long downloaded = 0, total = 0;
    foreach (var info in infos)
    {
        downloaded += info.DownloadedLength;
        total      += info.TotalLength;
    }
    progressBar.value = total > 0 ? (float)downloaded / total : 0f;
}
```

> `TaskInfo`의 필드(`Status`, `Progress`, `DownloadedLength`, `TotalLength`, `Tag`, `SerialId` 등)는 `DownloadManager`가 작업 수명 주기 동안 갱신합니다.

### 4. Editor Inspector에서 Tag 확인

`DownloadComponent`의 Inspector를 열면 "Download Infos" 리스트에서 `Tag` 열을 직접 확인할 수 있으며, 작업이 의도한 그룹에 지정되었는지 검증하는 데 사용합니다.

## 일반적인 변형

| 시나리오 | 사용 방법 |
|------|------|
| 같은 배치의 리소스, 우선순위가 다름 | 동일한 `tag`, 다른 `priority`를 사용하면 함께 조회하고 별도로 스케줄링 가능 |
| 리소스 버전 번호를 Tag로 사용 | 예: `tag = "v1.2.3"`, 버전별 전체 배치 업그레이드에 편리함 |
| 전체 배치 작업 취소 | `TaskInfo[]`의 `SerialId`를 꺼내 각각 `RemoveDownload(serialId)` 호출 |
| 콜백 컨텍스트 전달 | `userData` 매개변수로 콜백을 작업에 넣고, Tag는 여전히 비즈니스별로 분류 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GetDownloadInfos(tag)`가 항상 빈 결과를 반환 | 작업 추가 시 Tag를 전달하지 않았거나 Tag 문자열이 일치하지 않음(대소문자, 공백) | `AddDownload`가 `tag`가 있는 오버로드를 사용했는지 확인하고, Tag를 상수로 저장 |
| 같은 파일에 여러 Tag가 지정되어 중복 다운로드됨 | 서로 다른 Tag는 독립적인 작업이며, 프레임워크가 자동으로 중복 제거하지 않음 | 전역 딕셔너리로 `downloadUri` 중복을 확인하거나, 동일한 Tag를 고정해 사용 |
| `AddDownload` 호출 시 `Download path is invalid.` / `Download uri is invalid.` 예외 발생 | `downloadPath` 또는 `downloadUri`가 빈 문자열 또는 null | 호출 전에 null 확인, Tag는 이 두 매개변수의 검증에 영향을 주지 않음 |

오류 메시지 원문: [DownloadManager.cs#L360-L368](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L360-L368)

## 배경(선택 사항)

`DownloadTask`는 내부적으로 Tag를 `TaskBase.Tag`(문자열 필드)로 저장하고, `m_TaskPool`은 Tag별로 작업 집합을 유지관리하며, `GetDownloadInfos(tag)`는 실제로 `m_TaskPool.GetTaskInfos(tag)`에 위임됩니다. Tag는 "그룹화 + 조회"에만 사용되며, 다운로드 우선순위, 동시 실행 수 또는 실패 재시도 정책에는 영향을 주지 않습니다. 이러한 동작은 `priority`와 `DownloadComponent`의 전역 매개변수에 의해 결정됩니다. 출처: [DownloadTask.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs)
