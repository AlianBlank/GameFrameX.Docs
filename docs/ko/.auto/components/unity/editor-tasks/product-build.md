# 제품 빌드 프로세스 구성

Unity 상단 메뉴 `GameFrameX/Build/*`를 통해 다양한 플랫폼의 배포 가능한 버전을 한 번에 내보내고, 빌드 전후에 훅을 통해 사용자 정의 단계(예: 설정 복사, 핫픽스 프로젝트 주입, 임시 디렉터리 정리)를 주입할 수 있습니다.

## 사전 조건

- Unity 편집기가 설치되어 있고, 프로젝트가 Unity Hub를 통해 열려 있어야 합니다.
- `File → Build Settings`에서 패키징할 씬을 미리 선택해야 합니다. 그렇지 않으면 `EditorBuildSettings.scenes`이 비어 있어 결과물에 씬이 포함되지 않습니다.
- Android 플랫폼을 패키징해야 할 경우, 해당 Build Support 모듈이 설치되어 있고 JDK / Android SDK가 설정되어 있는지 확인하세요.
- 핫픽스 프로세스가 필요한 경우 `GameFrameX` 관련 HotFix 편집기 확장(`HotFixEditorCompilerHelper.AddEditor()` 명령이 자동으로 호출됨)이 설치되어 있는지 확인하세요.
- 출력 디렉터리의 디스크에 쓰기 권한이 있어야 합니다. Windows 플랫폼의 기본 결과물 경로는 아래를 참조하세요.

## 작업 단계

### 1. 빌드 플랫폼 전환

Unity 상단 메뉴에서 `File → Build Settings`를 클릭하고, `Platform` 목록에서 대상 플랫폼을 선택한 후 `Switch Platform`을 클릭합니다. 메뉴 항목은 현재 활성 빌드 대상을 검증하며, 플랫폼이 일치하지 않으면 `현재 빌드 대상이 XXX이 아닙니다`를 출력하고 바로 반환합니다.

### 2. 메뉴 선택하여 빌드 트리거

대상 플랫폼에 따라 Unity 상단 메뉴에서 `GameFrameX → Build → <플랫폼 이름>`을 차례로 클릭합니다. 각 메뉴 항목은 `BuildProductHelper`의 정적 메서드에 해당합니다.

| 메뉴 항목 | 대응 메서드 | BuildTarget | 출력 위치 |
|--------|----------|-------------|----------|
| `GameFrameX/Build/Windows X64` | `BuildPlayerToWindows64BuildTarget` | `StandaloneWindows64` | `_buildPath/PlayerSettings.productName.exe` |
| `GameFrameX/Build/Windows X32` | `BuildPlayerToWindows32BuildTarget` | `StandaloneWindows` | 동일(디렉터리명 다름) |
| `GameFrameX/Build/Mac Os` | `BuildPlayerToMacBuildTarget` | `StandaloneOSX` | 동일 |
| `GameFrameX/Build/WebGL` | `BuildPlayerToWebGLBuildTarget` | `WebGL` | `BuildOutputPath()`에 의해 결정됨 |
| `GameFrameX/Build/Android(APK)` | `BuildPlayerToAndroid` | `Android` | `apkPath`(APK) |
| `GameFrameX/Build/Android(AAB)` | `BuildPlayerToAndroidAAB` | `Android` | `aabFilePath`(AAB) |
| `GameFrameX/Build/Android Studio Project` | `BuildPlayerToAndroidStudio` | `Android` | `_buildPath`(Gradle 프로젝트 디렉터리) |
| `GameFrameX/Build/Android(Development)` | `BuildPlayerToAndroidDevelopment` | `Android` | `AllowDebugging \| Development \| ConnectWithProfiler` 포함 |
| `GameFrameX/Build/iOS` | `BuildPlayerToIOS` | `iOS` | Xcode 프로젝트 디렉터리 |

호출 진입점 발췌:

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("현재 빌드 대상이 Windows가 아닙니다");
        return;
    }
    try
    {
        HotFixEditorCompilerHelper.AddEditor();
        PlayerSettings.fullScreenMode = FullScreenMode.Windowed;
        PlayerSettings.defaultScreenHeight = 720;
        PlayerSettings.defaultScreenWidth = 1280;
        EditorUserBuildSettings.selectedStandaloneTarget = BuildTarget.StandaloneWindows64;
        UpdateBuildTime();
        AssetDatabase.SaveAssets();
        _buildPath = BuildOutputPath();
        var resultDirectory = _buildPath + Path.DirectorySeparatorChar;
        RunPreHookBuild();
        var buildReport = BuildPipeline.BuildPlayer(EditorBuildSettings.scenes, resultDirectory + PlayerSettings.productName + ".exe", EditorUserBuildSettings.activeBuildTarget, BuildOptions.None);
        // ...
    }
    finally
    {
        HotFixEditorCompilerHelper.RemoveEditor();
        RunPostHookBuild();
    }
}
```

출처: [BuildProductHelper.cs](/src/Editor/BuildProduct/BuildProductHelper.cs#L101-L152)

### 3. 빌드 완료 대기 및 출력 확인

빌드 과정에서 `BuildPipeline.BuildPlayer`는 `BuildReport`를 반환하며, `summary.result == BuildResult.Succeeded`인 경우에만 후속 정리 및 복사 단계가 계속됩니다. 그렇지 않으면 메서드가 조기 반환됩니다. 콘솔에는 최종 결과물 경로 뒤에 `Build Output Path:`가 출력됩니다. Android 플랫폼은 또한 `EditorUserBuildSettings.selectedStandaloneTarget` / 해당 API를 자동으로 호출하여 서명 관련 매개변수를 설정합니다(소스 파일 [BuildProductHelper.cs](/src/Editor/BuildProduct/BuildProductHelper.cs#L360-L450) 참조).

### 4. 빌드 전후 훅 연결(선택 사항)

각 빌드 전후에 단계를 자동 실행해야 하는 경우 `IBuilderPreHookHandler` 또는 `IBuilderPostHookHandler`를 구현하면 됩니다. 프레임워크는 결과물을 구성하기 전후에 모든 구현 클래스를 호출하며, `Priority` 오름차순으로 실행합니다.

```csharp
using UnityEditor;
using GameFrameX.Editor;

public sealed class CopyExtraConfigsPreHook : IBuilderPreHookHandler
{
    // 값이 클수록 실행 순서가 늦어집니다
    public int Priority => 100;

    public void Run(BuildTarget target, string path)
    {
        // target: 현재 BuildPipeline.BuildPlayer의 대상 플랫폼
        // path:   프레임워크가 준비한 출력 경로(실행 파일명 또는 디렉터리 포함)
        // 리소스 복사, PlayerSettings 변경 등 사용자 정의 로직 작성
    }
}
```

출처: [IBuilderPreHookHandler.cs](/src/Editor/BuildProduct/IBuilderPreHookHandler.cs#L36-L52)

## 일반적인 변형

- 사용자 정의 출력 경로: 각 메서드는 먼저 `_buildPath = BuildOutputPath()`(클래스 내 정적 필드)를 설정한 다음 `BuildPipeline.BuildPlayer`에 전달합니다. 이름 변경이나 디렉터리 변경이 필요한 경우 메뉴 호출 전에 `PlayerSettings.productName`을 수정하거나 `BuildOutputPath()`를 확장하세요.
- 핫픽스 프로세스 임베드: `HotFixEditorCompilerHelper.AddEditor()`는 각 플랫폼 진입점의 `try` 시작에서 이미 호출되며, `finally`에서 `HotFixEditorCompilerHelper.RemoveEditor()`를 호출하여 프로젝트 파일을 복원합니다. 핫픽스가 필요하지 않은 경우 무시할 수 있습니다.
- 사용자 정의 후처리: Steamworks 설정 파일은 `CopySteamWorksConfig`를 통해 결과물 디렉터리로 자동 복사됩니다. 유사한 도구를 새로 추가하려면 해당 호출을 직접 복사하거나 `IBuilderPostHookHandler`를 등록하세요.
- 디버그 버전 빌드: Android 플랫폼은 전용 `BuildPlayerToAndroidDevelopment` 진입점을 제공하며, `AllowDebugging | Development | ConnectWithProfiler`이 포함된 APK를 생성하여 Profiler 디버깅에 사용됩니다.

## 일반적인 오류

| 현상 | 원인 | 해결 |
|------|------|------|
| 메뉴 클릭 후 즉시 `현재 빌드 대상이 XXX이 아닙니다`를 출력하고 종료 | 현재 활성 플랫폼과 메뉴 항목에 해당하는 `BuildTarget`이 일치하지 않음 | 먼저 `Build Settings`에서 해당 플랫폼으로 전환한 후 메뉴를 트리거 |
| 빌드 결과물에 `*_Data` 디렉터리만 있고 실행 파일이 없음 | `EditorBuildSettings.scenes`이 비어 있거나 일부 씬만 선택됨 | `Build Settings → Scenes In Build`에서 패키징할 씬을 모두 선택 |
| 최종 디렉터리에 `BackUpThisFolder_ButDontShipItWithYourGame`이 남아 있음 | 프레임워크에서 해당 디렉터리를 이미 능동적으로 삭제했지만, 일부 파일이 점유 중이어서 잔류 가능 | 점유 중인 프로세스를 닫은 후 재시도; 유지가 필요한 경우 사용자 정의 훅에서 해당 정리 로직을 건너뛰기 |
| 훅이 예상대로 순서대로 실행되지 않음 | `Priority`가 설정되지 않았거나 여러 구현에서 동일한 값을 사용 | 각 구현에 명시적으로 값을 할당하고, 값이 클수록 정렬이 뒤로 |
| 빌드 후 Unity에 편집 매크로 또는 편집기 프로젝트 파일이 남아 있음 | `HotFixEditorCompilerHelper.RemoveEditor()`가 트리거되지 않음 | 메뉴의 `try/finally`를 수동으로 건너뛰지 말고, 복사 방식이 아닌 메뉴를 통해 트리거 |

## 배경(선택 사항)

`BuildProductHelper`는 `BuildPipeline.BuildPlayer` 전에 `RunPreHookBuild()`를 호출하고, `finally`에서 `RunPostHookBuild()`를 호출합니다. 두 메서드 모두 내부적으로 리플렉션을 통해 `Utility.Assembly.GetTypes()`에서 해당 인터페이스를 구현한 구체 타입을 스캔한 다음, `Priority` 오름차순으로 인스턴스화하고 `Run(BuildTarget, string)`을 호출합니다. 이 메커니즘을 통해 사용자 비즈니스 로직은 프레임워크 소스 코드를 수정하지 않고도 빌드 전후 로직을 주입할 수 있습니다.
