# 如何自定义 Helper 替换默认实现

通过自定义 `EntityHelperBase` 与 `EntityGroupHelperBase` 派生类，可以接管实体的实例化、创建与释放逻辑；`EntityComponent` 提供了反射类型名（`m_EntityHelperTypeName` / `m_EntityGroupHelperTypeName`）与 Inspector 直接拖拽（`m_CustomEntityHelper` / `m_CustomEntityGroupHelper`）两种替换方式。

## 前置条件

- 已安装 GameFrameX Entity 组件包并能在场景中找到 `EntityComponent`。
- 了解 C# 继承与 Unity `MonoBehaviour` 基本用法。
- 自定义 Helper 类必须放在能被反射加载的程序集中（避免被代码裁剪工具裁掉）。

## 操作步骤

1. **新建自定义实体 Helper 类**，继承 `EntityHelperBase`，实现三个抽象方法。

```csharp
using GameFrameX.Entity.Runtime;
using GameFrameX.Runtime;
using UnityEngine;
using YooAsset;

namespace MyGame.Entity
{
    public class MyEntityHelper : EntityHelperBase
    {
        public override object InstantiateEntity(object entityAsset)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return null;
            }
            return handle.InstantiateSync();
        }

        public override IEntity CreateEntity(object entityInstance, IEntityGroup entityGroup, object userData)
        {
            var go = entityInstance as GameObject;
            if (go == null)
            {
                Log.Error("Entity instance is invalid.");
                return null;
            }
            go.transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform);
            return go.GetOrAddComponent<Entity>();
        }

        public override void ReleaseEntity(object entityAsset, object entityInstance)
        {
            var handle = entityAsset as AssetHandle;
            if (handle == null)
            {
                Log.Error("entityAsset is AssetOperationHandle invalid.");
                return;
            }
            handle.Release();
            Destroy((Object)entityInstance);
        }
    }
}
```

Source: [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L41-L101)

2. **（可选）新建自定义实体组 Helper 类**，继承 `EntityGroupHelperBase`；该基类本身无抽象成员，按需挂载子物体管理逻辑即可。

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

namespace MyGame.Entity
{
    public class MyEntityGroupHelper : EntityGroupHelperBase
    {
        // 在此扩展实体组节点管理
    }
}
```

Source: [EntityGroupHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityGroupHelperBase.cs#L39-L41)

3. **在场景中打开 `EntityComponent`，选择替换方式（二选一）**：

   - **方式 A（反射类型名）**：修改 `Entity Helper Type Name` 或 `Entity Group Helper Type Name` 字段为完整类名（含命名空间），例如 `MyGame.Entity.MyEntityHelper`。
   - **方式 B（Inspector 直接拖拽）**：把实现了上述 Helper 的 `MonoBehaviour` 预制体挂到 `Custom Entity Helper` 或 `Custom Entity Group Helper` 字段。

```csharp
// 来自 EntityComponent 的相关字段声明
[SerializeField] private string m_EntityHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityHelper";
[SerializeField] private EntityHelperBase m_CustomEntityHelper = null;

[SerializeField] private string m_EntityGroupHelperTypeName = "GameFrameX.Entity.Runtime.DefaultEntityGroupHelper";
[SerializeField] private EntityGroupHelperBase m_CustomEntityGroupHelper = null;
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L62-L68)

4. **运行场景验证**。`EntityComponent.Start()` 会按以下优先级创建 Helper：先看 Inspector 上的 `m_CustomEntityHelper` 是否被赋值，未赋值再用 `m_EntityHelperTypeName` 通过 `Helper.CreateHelper` 反射创建，仍为空则报 `Can not create entity helper.`。

```csharp
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
}
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L171-L175)

## 常见变体

| 场景 | 做法 |
|------|------|
| 仅替换实体组节点挂载策略 | 派生 `EntityGroupHelperBase`，保持 `EntityHelperBase` 用默认实现 |
| 想在 Helper 内访问 Unity 生命周期 | 直接使用基类继承的 `MonoBehaviour` 方法（`Awake/OnEnable/...`）|
| 程序集被裁剪导致反射失败 | 在 `link.xml` 或 `[Preserve]` 标记中保留自定义 Helper 类（参考 [GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L6-L24) 的保留方式）|

## 常见错误

| 错误现象 | 原因 | 修复 |
|----------|------|------|
| 启动日志 `Can not create entity helper.` | 反射类型名为空或拼写错误，且未拖拽 `CustomEntityHelper` | 确认类型名包含命名空间，例如 `MyGame.Entity.MyEntityHelper` |
| 自定义 Helper 内 `Awake` 不触发 | 走的是反射创建路径而不是 Inspector 拖拽 | 改为方式 B 把 Helper 挂到 `m_CustomEntityHelper` 字段，或在 `CreateEntity` 里自行调用 `Instantiate` 关联 |
| `ReleaseEntity` 后对象未真正销毁 | 重写时遗漏 `Object.Destroy` 调用 | 在 `ReleaseEntity` 末尾调用 `Destroy((Object)entityInstance)` |
| 发布版出现 `MissingReferenceException` | 自定义类被代码裁剪 | 用 `[Preserve]` 标注或写入 `link.xml` |

## 背景（可选）

`EntityComponent` 内置字段默认指向 `DefaultEntityHelper` / `DefaultEntityGroupHelper`，其内部依赖 YooAsset 的 `AssetHandle` 完成实例化与释放（参见 [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L48-L100)）。自定义 Helper 的存在意义是让你在不改框架的前提下，替换为 Addressables、自研资源管线或带对象池的实例化方案。
