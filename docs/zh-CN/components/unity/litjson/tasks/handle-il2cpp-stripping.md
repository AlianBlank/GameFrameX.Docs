# 如何应对 Unity IL2CPP 托管代码裁剪

启用 IL2CPP + Managed Code Stripping 后,`GameFrameX.LitJSON` 通过三层互补机制保护自身类型不被裁掉。本页说明这些机制如何协同工作,以及在遇到裁剪引发的 `MissingMethodException` / `TypeLoadException` 时如何补全保护。

## 前置条件

- Unity 2019.4 或更高版本(参见 [package.json](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/package.json#L5))
- 已通过 Scoped Registry 或 Git URL 方式安装 `com.gameframex.unity.litjson`(详见 README)
- 项目使用 IL2CPP 后端(Android/iOS 等发布平台默认开启)

## 操作步骤

### 1. 确认裁剪保护已默认启用

包内已内置三层保护,**大多数项目无需任何额外配置**:

| 机制 | 作用 | 来源 |
|------|------|------|
| `link.xml` | 声明式保留命名空间内全部类型 | 包级过滤文件 |
| `LitJsonCroppingHelper` | 启动时通过 `typeof()` 触达关键类型 | `Runtime/LitJsonCroppingHelper.cs` |
| `[Preserve]` 特性 | 标注反射敏感的构造函数、属性 getter、导出器 | 各 Runtime 类 |

只要 `LitJsonCroppingHelper` 的某个实例在场景里处于激活状态,第三层保护就会在 `Start()` 中生效。

### 2. 把 `LitJsonCroppingHelper` 挂到场景里

打开任意**首场景**(Bootstrap / Loading 场景),创建一个空 GameObject 并添加组件 `LitJson Cropping Helper`:

```csharp
// Runtime/LitJsonCroppingHelper.cs 中 Start() 的实际实现
[Preserve]
public void Start()
{
    _ = typeof(ArrayMetadata);
    _ = typeof(Condition);
    _ = typeof(ExporterFunc);
    _ = typeof(ExporterFunc<>);
    _ = typeof(JsonIgnoreAttribute);
    _ = typeof(JsonPropertyAttribute);
    _ = typeof(FsmContext);
    _ = typeof(IJsonWrapper);
    _ = typeof(ImporterFunc);
    _ = typeof(ImporterFunc<,>);
    _ = typeof(JsonData);
    _ = typeof(JsonException);
    _ = typeof(JsonMapper);
    _ = typeof(JsonMockWrapper);
    _ = typeof(JsonReader);
    _ = typeof(JsonToken);
    _ = typeof(JsonType);
    _ = typeof(JsonWriter);
    _ = typeof(Lexer);
    _ = typeof(ObjectMetadata);
    _ = typeof(OrderedDictionaryEnumerator);
    _ = typeof(ParserToken);
    _ = typeof(PropertyMetadata);
    _ = typeof(UnityTypeBindings);
    _ = typeof(WrapperFactory);
    _ = typeof(WriterContext);
}
```

Source: [LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L23-L52)

每个 `_ = typeof(...)` 都是 C# 7.0 discard 语法,目的是让 IL2CPP 链接器认定这些类型"被使用过",从而保留它们。

### 3. 用 `[Preserve]` 标注你自己的反射类(可选)

LitJson 通过反射读写自定义 POCO 时,若类型未在代码中显式 new 过,仍可能被裁掉。在你的数据类上加 `[Preserve]` 即可:

```csharp
using UnityEngine.Scripting;

[Preserve]
public class PlayerData
{
    public string Name;
    public int Level;
    public Vector3 Position;
}
```

### 4. 触发 IL2CPP 构建并核对二进制

1. File → Build Settings → 切换平台到 iOS 或 Android
2. Player Settings → Other Settings → Scripting Backend = `IL2CPP`,Managed Stripping Level 保持默认 `High` 或显式设为 `Low`/`Medium` 复测
3. Build And Run
4. 在设备/模拟器上跑一次反序列化(如 `JsonMapper.ToObject<PlayerData>(text)`),确认无异常

## 常见变体

- **代码热更新场景**:如果用 HybridCLR / ILRuntime,需要在宿主工程里对热更 DLL 也放一份 link.xml,否则热更代码引用的 LitJson 类型可能仍被裁掉。
- **Addressables 远端资源**:运行时从远端加载的 `AssemblyDefinition` 不受主工程 link.xml 约束,需在远端程序集自身的 asmdef 旁再放一份。
- **不使用 `LitJsonCroppingHelper`**:可以手动写 link.xml 替代第三层保护(见下一节)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 运行时 `MissingMethodException: void LitJson.JsonMapper::.cctor()` | `JsonMapper` 的 cctor 被裁掉 | 确认 `LitJsonCroppingHelper` 已挂场景并激活 |
| `TypeLoadException: Could not load type LitJson.Lexer` | `Lexer` 类型被裁掉 | 同上,或在自己的数据类上加 `[Preserve]` |
| `[Preserve]` 标注后仍报错 | 用了 source-only `link.xml` 但被托管剥离忽略 | 把 link.xml 放在 `Assets/` 根目录或包根目录,而非 `Assets/Plugins/` 子层 |
| iOS 构建未触发 `Start()` | `LitJsonCroppingHelper` 组件被挂在未加载的子场景 | 把它直接挂在首场景里、或在自定义 `RuntimeInitializeOnLoadMethod` 里手动调用 |

## 背景(可选)

LitJson 大量使用反射(`JsonMapper.ToObject<T>` 通过反射读字段、写 setter)。IL2CPP 静态分析只能识别直接调用的代码,反射调用链无法追溯,于是未被 `new` 过的类型会被裁掉。包内采用**三重防护**:link.xml 做白名单、`LitJsonCroppingHelper` 运行时 `typeof` 触达、`[Preserve]` 标注反射入口——任意一层失效,另外两层仍能兜底。

关于 LitJson 的整体使用方式,见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md)。
