# 如何新增與設定統計 Provider

在 `GameAnalyticsComponent` 元件的 Inspector 中,把實作了 `IGameAnalyticsManager` 的型別加入「遊戲資料分析元件清單，按序上報」，並為每個項目填寫 `Setting` 鍵值對；執行階段元件會自動反射實例化所有 Provider 並呼叫其 `Init`,後續所有上報介面會按清單順序轉發給每一個 Provider。

## 前置條件

- 已安裝本套件 `com.gameframex.unity.gameanalytics`。
- 場景中已存在 `GameAnalyticsComponent`(可透過 `Add Component → Game Framework → GameAnalytics` 新增)。
- 場景中至少有一個實作了 `IGameAnalyticsManager` 介面的統計實作類別(通常由各個第三方 SDK 配接套件提供)，否則 Inspector 的下拉選單裡只有 None。

## 操作步驟

1. 選取掛有 `GameAnalyticsComponent` 的 GameObject,Inspector 會由 `GameAnalyticsComponentInspector` 繪製一個可排序清單，標題為「遊戲資料分析元件清單，按序上報」。

2. 點擊清單右下角的 `+` 新增一個項目。每個項目對應一個 `GameAnalyticsComponentProvider`,其序列化欄位如下：

| 欄位 | 型別 | 說明 |
|------|------|------|
| `ComponentType` | `string` | 實作 `IGameAnalyticsManager` 的型別完整名稱，由下拉選單自動寫入 |
| `ComponentTypeNameIndex` | `int` | 編輯器下拉選單目前索引，執行階段不使用 |
| `Setting` | `List<GameAnalyticsComponentParamKV>` | 傳給該 Provider 的初始化參數，每項為一對 `Key`/`Value` 字串 |

```csharp
[Serializable]
public class GameAnalyticsComponentProvider
{
    /// <summary>
    /// 實作元件型別
    /// </summary>
    public string ComponentType;

    /// <summary>
    /// 這個是給編輯器用的
    /// </summary>
    public int ComponentTypeNameIndex = 0;

    /// <summary>
    /// 參數
    /// </summary>
    public List<GameAnalyticsComponentParamKV> Setting = new List<GameAnalyticsComponentParamKV>();
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L361-L378)

3. 在 `ComponentType` 下拉選單中選擇目標實作類別。下拉項目由 Inspector 透過反射收集所有 `IGameAnalyticsManager` 的執行階段型別產生，選取後會把型別名稱寫入 `ComponentType` 字串：

```csharp
managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

4. 在 `Setting` 中填寫該 Provider 需要的初始化參數(如 AppKey、Channel 等由具體 SDK 實作定義的鍵)。如果實作組件中存在繼承自 `BaseGameAnalyticsSetting` 的類別，Inspector 會按其公用欄位自動補齊 Setting 項目，只需填 Value:

```csharp
var types = type.Assembly.GetTypes();
foreach (var typeImpl in types)
{
    if (typeImpl.BaseType != typeof(BaseGameAnalyticsSetting))
    {
        continue;
    }

    var fieldInfos = typeImpl.GetFields();
    ...
}
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L148-L158)

5. 進入 Play 模式。元件在 `OnEnable` 中呼叫 `Init()`,對每個項目反射建立實例並把 `Setting` 轉成字典傳入：

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L79)

6. 利用清單的拖曳控點調整順序。順序只影響轉發順序，不影響功能;`Init` 與後續所有上報呼叫都按清單順序執行。

## 常見變體

- **需要登入後補充初始化的 SDK**:部分 Provider 實作了 `IsManualInit()`,在取得使用者資訊後呼叫元件的 `ManualInit(Dictionary<string, string> extraArgs)`,元件會把 `extraArgs` 轉發給所有需要手動初始化的 Provider:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

- **設定玩家 ID / 公用屬性**：呼叫 `SetPlayerId(string playerId)`、`SetPublicProperties(string key, object value)`、`ClearPublicProperties()` 會同步轉發給清單中的所有 Provider,無需逐一呼叫。
- **自訂 Provider**:新建類別實作 `IGameAnalyticsManager`(介面定義見 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8)),必須提供無參數建構函式(元件以 `Activator.CreateInstance` 實例化)；如希望 Inspector 自動產生 Setting 鍵，再在同一組件定義一個繼承 `BaseGameAnalyticsSetting` 的類別，並以公用欄位宣告各設定項。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| 日誌 `Can not find component type 'XXX'.`,該項目被跳過 | `ComponentType` 型別名稱無法透過 `Utility.Assembly.GetType` 解析：實作類別所在組件未參與建置，或手動修改了序列化值 | 確認實作套件已引入，並在 Inspector 下拉選單中重新選擇型別 |
| 日誌 `GameAnalyticsManager is not init.` | 元件尚未 `Init` 就呼叫了上報介面(如元件被停用導致 `OnEnable` 未執行) | 確保 `GameAnalyticsComponent` 處於啟用狀態；必要時手動呼叫 `Init()` |
| 某個項目被靜默忽略，無任何錯誤訊息 | `ComponentType` 留空，`Init` 中 `IsNotNullOrWhiteSpace` 檢查未通過直接跳過 | 為該項目在下拉選單選擇實作型別 |
| `ManualInit` 呼叫沒有效果 | `m_IsInit` 為 false 時 `ManualInit` 直接 return;或該 Provider 的 `IsManualInit()` 回傳 false | 先確認 Play 後已觸發 `Init`,再檢查實作的 `IsManualInit` 邏輯 |
| 修改 Inspector 設定後執行仍用舊設定 | `Init` 由 `m_IsInit` 保護，只在首次呼叫時生效 | 重新啟動 Play 模式；不要期望執行中重複呼叫 `Init` 會生效 |

## 驗證

- Play 後 Console 無 `Can not find component type` 錯誤，表示所有項目的型別解析成功。
- 呼叫 `SetPlayerId` 等轉發介面時無 `GameAnalyticsManager is not init.` 警告，表示 Provider 清單已完成初始化。
- 在各 Provider 實作的 `Init(Dictionary<string, string>)` 內設定中斷點或加上日誌，確認 `Setting` 中的鍵值已按設定傳入。

## 背景

元件不直接依賴任何具體 SDK:它在 `Init` 時用反射按 `ComponentType` 建立實例、把 `Setting` 清單轉成 `Dictionary<string, string>` 傳給 `Init(args)`,之後所有公用介面(set/上報等)都會走訪 `m_GameAnalyticsManager` 逐一轉發，從而實現多套統計 SDK 同時按序上報。
