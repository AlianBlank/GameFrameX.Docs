# 命名規則と略称マッピングの理解(Component / FUI / GUI)

`GameApp` は Game Frame X の静的ファサードクラスであり、`GameApp.{Name}` を `GameEntry.GetComponent<{Name}Component>()` にマッピングします。命名規則を理解すれば、ドキュメントを調べることなく `GameApp.XXX` を通じて任意の組み込みコンポーネントを直接取得できます。

## 命名マッピング規則

ほとんどのコンポーネントは「`Component` サフィックスを除去する」という単純な規則に従いますが、`FUI` と `GUI` のみが略称の特例です。

| GameApp プロパティ | 等価な呼び出し | 種類 |
|---|---|---|
| `GameApp.Event` | `GameEntry.GetComponent<EventComponent>()` | 通常マッピング |
| `GameApp.UI` | `GameEntry.GetComponent<UIComponent>()` | 通常マッピング |
| `GameApp.Asset` | `GameEntry.GetComponent<AssetComponent>()` | 通常マッピング |
| `GameApp.FUI` | `GameEntry.GetComponent<FairyGUIComponent>()` | 略称の特例(FUI=FairyGUI) |
| `GameApp.GUI` | `GameEntry.GetComponent<UGUIComponent>()` | 略称の特例(GUI=uGUI) |

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L30-L38)

## 略称特例の説明

`FUI` と `GUI` は 2 つの UI サブシステムの歴史的な略称で、頭文字を大文字にしたコンパクトな表記のまま維持されています。「`Component` サフィックスを除去する」規則とは一致しないため、使用時には特に注意が必要です:

- **FUI** → `FairyGUIComponent`(FairyGUI 方式の UI コンポーネント。[CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6) により fairygui への依存は削除済み)
- **GUI** → `UGUIComponent`(Unity 標準の UGUI ベースの UI コンポーネント。`GameApp.GUI.cs` で定義され、コンパイルマクロ `ENABLE_GAME_FRAME_X_L_UGUI` によって制御される)

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
public static partial class GameApp
{
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }
            return _gui;
        }
    }
}
#endif
```

出典: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

## 操作手順

自分のスクリプトで以下の手順に従ってマッピングを使用します:

1. **命名の確認**:まず [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L32-L38) の対応表で `GameApp.{Name}` を調べ、対応する `*Component` 型を見つけます。
2. **通常コンポーネント**:`GameApp.Event`、`GameApp.UI`、`GameApp.Asset` などをそのまま記述します。
3. **UI コンポーネント**:UI サブシステムは 2 種類に分かれており、エンジン方式に応じて `GameApp.FUI`(FairyGUI)または `GameApp.GUI`(UGUI)を選択します。
4. **必要に応じたマクロの有効化**:`GameApp.GUI` は `ENABLE_GAME_FRAME_X_L_UGUI` コンパイルマクロを有効にした場合にのみ存在します。`GameApp.FUI` は FairyGUI パッケージに依存しており、その依存を削除するとこのプロパティも無効になります。

```csharp
// 通常マッピングの例
var evt = GameApp.Event;
var asset = GameApp.Asset;

// UI サブシステム:エンジン方式に応じてどちらかを選択
var fairygui = GameApp.FUI;   // FairyGUIComponent(FairyGUI パッケージが必要)
var ugui = GameApp.GUI;       // UGUIComponent(ENABLE_GAME_FRAME_X_L_UGUI マクロが必要)
```

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|---|---|---|
| `GameApp.FUI` のコンパイル時に「未定義」エラーが出る、または null を返す | fairygui への依存は削除済み([CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6)) | `GameApp.GUI` に切り替えるか、FairyGUI パッケージをインストールする |
| `GameApp.GUI` にアクセスできない | コンパイルマクロ `ENABLE_GAME_FRAME_X_L_UGUI` が不足している | Player Settings の Scripting Define Symbols にこのマクロを追加する |
| `GameApp.FUI` を `UIComponent` と誤解する | `FUI` は `FairyGUIComponent` であり、`UI` こそが `UIComponent` | 2 つの UI サブシステムを区別し、汎用 UI には `GameApp.UI`、エンジン UI には `GameApp.FUI`/`GameApp.GUI` を使用する |
| `GameApp.GameApp` のような名前の重複による誤用 | プロパティ名は `Component` を除去した名前であり、コンポーネントの元の名前ではない | 「XxxComponent → Xxx」の規則に従って記述する(例:`AssetComponent → Asset`) |

## 背景

`GameApp` は C# の `partial class` によってファイル単位で整理されており、各コンポーネントは 1 つの `GameApp.{Name}.cs` に対応します。内部では遅延ロードされる静的フィールドによって初回呼び出しの結果をキャッシュし、以降のアクセスではキャッシュをそのまま返すことで、重複した検索を回避しています。`FUI` と `GUI` の略称は、歴史的なコードとの互換性維持と UI 呼び出しパスの短縮のために残されています。新しいコードでエンジン方式を区別する必要がない場合は、汎用の `GameApp.UI`(`UIComponent`)を優先的に使用してください。
