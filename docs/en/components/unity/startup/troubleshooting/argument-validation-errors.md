# How to Handle Synchronous Parameter Validation Exceptions During Startup

When calling `StartupRunner.Run(...)`, if the passed-in parameters do not meet the requirements (e.g., `options` is null, `GlobalInfoUrls` is an empty array, etc.), an `ArgumentNullException` or `ArgumentException` is thrown **synchronously** before entering the async state machine, rather than returning a failure result. These exceptions are "development-time configuration errors" and need to be exposed immediately at the validation stage, to avoid polluting the subsequent coroutine flow.

## Quick Diagnosis

| Exception Type | Typical Message Text | Trigger Location | Fix Direction |
|----------|--------------|----------|----------|
| `ArgumentNullException` | (no message, `ParamName`=`options`) | `StartupRunner.Run` entry | Pass in a valid `StartupOptions` instance |
| `ArgumentNullException` | (no message, `ParamName`=`uiHandler`) | `StartupRunner.Run` entry | Implement and pass in an `IStartupUIHandler` |
| `ArgumentNullException` | (no message, `ParamName`=`hotfixLauncher`) | `StartupRunner.Run` entry | Implement and pass in an `IHotfixLauncher` |
| `ArgumentException` | message contains `"GlobalInfoUrls"` | `StartupRunner.Run` entry | Fill in at least one global info endpoint URL in `StartupOptions` |
| `ArgumentNullException` | (no message, `ParamName`=`urls`) | `UrlFailoverRunner` constructor | Ensure the URL array object itself is not null |
| `ArgumentException` | `"URL list must contain at least one URL."` | `UrlFailoverRunner` constructor | The URL array must contain at least one element |
| `ArgumentException` | `"Max attempts per URL must be greater than zero."` | `UrlFailoverRunner` constructor | Change `maxAttemptsPerUrl` to `>= 1` |
| `ArgumentException` | `"Retry delay must be zero or greater."` | `UrlFailoverRunner` constructor | Change `retryDelayMs` to `>= 0` |
| `ArgumentNullException` | (no message, `ParamName`=`options`) | `StartupHttpParams.FromOptions` | Pass in a non-null `StartupOptions` |

The original exception messages and parameter names come directly from the source code; see [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L34-L60) and [Runtime/Failover/UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L40).

## Fix Steps

### 1. Fixing `ArgumentNullException` (options/uiHandler/hotfixLauncher)

`StartupRunner.Run` synchronously checks whether the three input parameters are null before entering the coroutine:

```csharp
public static UniTask<StartupResult> Run(
    StartupOptions options,
    IStartupUIHandler uiHandler,
    IHotfixLauncher hotfixLauncher)
```

Corresponding implementation ([Runtime/Startup/StartupRunner.cs#L45-L60](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L45-L60)):

```csharp
if (options == null)        throw new ArgumentNullException(nameof(options));
if (uiHandler == null)      throw new ArgumentNullException(nameof(uiHandler));
if (hotfixLauncher == null) throw new ArgumentNullException(nameof(hotfixLauncher));
```

Fix: Check each item before the call entry point, or ensure non-null instances are injected via the Inspector / DI container. For example:

```csharp
if (StartupOptions.Instance == null)
{
    Debug.LogError("StartupOptions is not configured");
    return;
}
if (uiHandler == null || hotfixLauncher == null)
{
    Debug.LogError("UI/Hotfix launcher not registered");
    return;
}
await StartupRunner.Run(StartupOptions.Instance, uiHandler, hotfixLauncher);
```

### 2. Fixing `ArgumentException` (`GlobalInfoUrls` is empty)

After the three null checks pass, `Run` also validates `options.GlobalInfoUrls` (see the corresponding implementation at [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L37-L60)). When this field is null or has a length of 0, an `ArgumentException` whose message contains `"GlobalInfoUrls"` is thrown synchronously.

Fix: After creating the asset in Unity via `Create > GameFrameX > Startup Options`, fill in at least one accessible global info endpoint URL in the Inspector's `GlobalInfoUrls` field (use array elements to distinguish primary and backup URLs).

### 3. Fixing validation exceptions thrown by `UrlFailoverRunner`

The `UrlFailoverRunner` constructor performs full validation of the URL list and retry parameters ([Runtime/Failover/UrlFailoverRunner.cs#L19-L34](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L34)):

```csharp
if (urls == null)
    throw new ArgumentNullException(nameof(urls));
if (urls.Length == 0)
    throw new ArgumentException("URL list must contain at least one URL.", nameof(urls));
if (maxAttemptsPerUrl <= 0)
    throw new ArgumentException("Max attempts per URL must be greater than zero.", nameof(maxAttemptsPerUrl));
if (retryDelayMs < 0)
    throw new ArgumentException("Retry delay must be zero or greater.", nameof(retryDelayMs));
```

Fix:

- Ensure the array reference passed to the `UrlFailoverRunner` constructor is non-null and contains at least one URL.
- `maxAttemptsPerUrl` must be ≥ 1.
- `retryDelayMs` must be ≥ 0 (0 means no retry delay, which is valid).

### 4. Fixing the null exception thrown by `StartupHttpParams.FromOptions`

`FromOptions` throws an `ArgumentNullException` when `options` is null ([Runtime/Http/StartupHttpParams.cs#L94-L99](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L94-L99)). If you have overridden `IStartupHttpParamsProvider`, perform your own null check before calling `FromOptions`.

## Verification

- Wrap `StartupRunner.Run` with `try/catch (ArgumentException)` / `try/catch (ArgumentNullException)` at the outer layer, and confirm that the exception type and `ParamName`/`Message` match the table above.
- After correcting the `StartupOptions` asset, re-enter PlayMode in the Editor; the startup flow should proceed normally into subsequent nodes such as `ProcedureGetAppVersionInfoState`, no longer throwing synchronously on the first frame.
- If you construct `UrlFailoverRunner` directly, you can pass edge-case values such as empty arrays or negative retry parameters in unit tests, confirm that the exception messages in the table above can be reproduced, and then fix them.

## Background (Optional)

`StartupRunner.Run` separates synchronous validation from the async flow: all "obviously incorrect" input parameters are thrown synchronously at the validation stage, preventing invalid states from entering the `UniTask` state machine; only issues that actually occur in networking, patching, or remote services are reported asynchronously via `StartupResult` / `StartupFailedEventArgs`. This convention is also explicitly documented in [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/CHANGELOG.md#L103): "Synchronous validation throws `ArgumentException` for empty `GlobalInfoUrls` before entering async state machine."
