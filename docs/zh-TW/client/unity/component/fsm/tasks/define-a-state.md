# 狀態定義方式

在 GameFrameX FSM 中，狀態是透過繼承抽象基底類別 `FsmState<T>` 來實作。`T` 是狀態機的擁有者型別，繼承後覆寫生命週期回呼即可完成狀態定義。

## 前置條件

- 已引入 `GameFrameX.Fsm.Runtime` 組件，可在 Unity 專案中直接參考。
- 已存在擁有者型別 `T`（必須為 `class`），之後將用於建立狀態機。

## 操作步驟

1. **決定狀態機擁有者型別**

   例如，使用角色控制器 `Player` 作為泛型參數 `T`。

2. **繼承 `FsmState<T>` 並實作必要的回呼**

   `FsmState<T>` 是抽象基底類別，提供 `OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy` 共 6 個生命週期鉤子，全部皆為 `protected internal virtual`，因此依需要覆寫即可。

   ```csharp
   using GameFrameX.Fsm.Runtime;

   public class IdleState : FsmState<Player>
   {
       protected internal override void OnEnter(IFsm<Player> fsm)
       {
           // 進入待機狀態時的邏輯
       }

       protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           // 每幀輪詢的邏輯
       }

       protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
       {
           // 離開待機狀態時的邏輯
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L41-L108)

3. **在狀態內部觸發狀態轉換**

   透過基底類別提供的 `ChangeState<TState>(IFsm<T> fsm)` 轉換至其他狀態：

   ```csharp
   protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
   {
       if (/* 觸發條件 */)
       {
           ChangeState<RunState>(fsm);
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

4. **將狀態加入狀態機**

   建立狀態機時，可透過 `CreateFsm<T>` 的 `params FsmState<T>[]` 參數傳入，或在建立後呼叫 `AddState` 動態加入：

   ```csharp
   var fsm = FsmComponent.Instance.CreateFsm(player, new IdleState(), new RunState());
   // 或
   fsm.AddState(new RunState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L205-L220)

## 生命週期回呼摘要

| 回呼 | 觸發時機 | 常見用途 |
|------|---------|---------|
| `OnInit(IFsm<T> fsm)` | 狀態首次加入狀態機時 | 初始化內部資料 |
| `OnEnter(IFsm<T> fsm)` | 進入該狀態時 | 播放動畫、設定旗標 |
| `OnUpdate(IFsm<T> fsm, float, float)` | 每幀輪詢 | 偵測轉換條件 |
| `OnFixedUpdate(IFsm<T> fsm, float, float)` | 固定時間步進輪詢 | 物理相關邏輯 |
| `OnLeave(IFsm<T> fsm, bool isShutdown)` | 離開該狀態時 | 清理狀態、還原旗標；`isShutdown` 表示是否因狀態機終止而觸發 |
| `OnDestroy(IFsm<T> fsm)` | 狀態銷毀時 | 釋放資源 |

## 常見變體

- **空狀態外殼**：若僅作為佔位或分組用途，可不覆寫任何方法，如下方測試案例所示：

  ```csharp
  private class TestIdleState : FsmState<object>
  {
  }
  ```

  Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L128-L130)

- **依型別轉換狀態**：除了泛型 `ChangeState<TState>` 之外，基底類別還提供 `ChangeState(IFsm<T>, Type)` 多載，適合根據外部設定動態轉換：

  ```csharp
  ChangeState(fsm, typeof(RunState));
  ```

  Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

## 常見錯誤

- **重複加入相同型別的狀態**：狀態機以型別作為索引鍵來儲存狀態，因此若對相同型別重複呼叫 `AddState`，會拋出 `GameFrameworkException`。
- **狀態轉換時傳入錯誤的型別**：`ChangeState(fsm, stateType)` 會驗證 `stateType` 必須衍生自 `FsmState<T>`，否則會拋出 `GameFrameworkException("State type '...' is invalid.")`。
- **直接呼叫 `ChangeState` 時 `fsm` 已失效**：基底類別會拋出 `GameFrameworkException("FSM is invalid.")`。

## 背景（選用）

`FsmState<T>` 抽象類別僅公開鉤子與狀態轉換功能，本身不持有任何執行階段資料 — 狀態之間共享的所有資料皆透過 `IFsm<T>` 的 `GetData` / `SetData` 存取。如此可讓狀態實作保持輕量且易於測試。
