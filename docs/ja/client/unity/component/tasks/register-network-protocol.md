# ネットワークプロトコルメッセージハンドラーの登録方法

`IMessageHandler` を継承したマネージャークラスに `[MessageHandler]` 属性を付与し、初期化時に `ProtoMessageHandler.Add(this)` を呼び出すことで、GameFrameX は対応するプロトコルを受信した際にターゲットメソッドへ自動的にディスパッチします。手動で `switch` によるディスパッチを行う必要はありません。

## 前提条件

- `GameFrameX.Network.Runtime` から導入されたプロトコルメッセージクラス（Proto によって生成されたもの、例：`NotifyBagInfoChanged`）が存在すること。
- マネージャークラスが `GameFrameworkSingleton<T>` を継承し、`IMessageHandler` インターフェースを実装していること。

## 操作手順

1. **マネージャーに `IMessageHandler` を実装させ、シングルトン基底クラスを継承させる**。クラス全体でインスタンスは1つだけ必要で、ネットワーク層はこの1つのオブジェクトにのみディスパッチします。

   ```csharp
   using GameFrameX.Network.Runtime;
   using GameFrameX.Runtime;

   namespace Hotfix.Manager
   {
       public sealed class BagManager : GameFrameworkSingleton<BagManager>, IMessageHandler
       {
           // ...
       }
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L16)

2. **ハンドラーメソッドに `[MessageHandler(typeof(メッセージクラス), nameof(メッセージクラス))]` 属性を付与する**。属性の1番目の引数はプロトコルメッセージのタイプを指定し、2番目の引数はログ・デバッグ用の説明名で、メソッドシグネチャと一対一で対応します。

   ```csharp
   /// <summary>
   /// アイテム変更通知の監視
   /// </summary>
   /// <param name="msg"></param>
   [MessageHandler(typeof(NotifyBagInfoChanged), nameof(NotifyBagInfoChanged))]
   private void NotifyBagInfoChanged(NotifyBagInfoChanged msg)
   {
       // メッセージボディを処理
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L29-L30)

3. **`Register()` を実装し、その中で `ProtoMessageHandler.Add(this)` を呼び出す**。現在のマネージャーをプロトコルディスパッチャーに登録すると、フレームワークのリフレクションスキャン時にこのインスタンス上のすべての `[MessageHandler]` 属性付きメソッドが読み取られます。

   ```csharp
   /// <summary>
   /// メッセージを登録します。複数回呼び出さないでください
   /// </summary>
   public void Register()
   {
       ProtoMessageHandler.Add(this);
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L126-L129)

4. **適切なタイミングで `Register()` を1回呼び出す**。一般的には `Awake` または初回 `GetInstance()` 時にトリガーします。例：

   ```csharp
   private void Awake()
   {
       Register();
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L120)

## よくあるバリエーション

- **同じマネージャーで複数のプロトコルを処理する**：各メソッドにそれぞれ `[MessageHandler(typeof(異なるメッセージ), nameof(異なるメッセージ))]` を付与し、`ProtoMessageHandler.Add(this)` を1回呼び出すだけで全メソッドを登録できます。`PlayerAttributeManager` が `NotifyPlayerAttributeSync` と `NotifyPlayerAttributeChanged` を同時に処理しているのがこのパターンです。（[PlayerAttributeManager.cs#L79](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L79)、[PlayerAttributeManager.cs#L109](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L109)）

- **異なるマネージャーが異なるプロトコルを処理する**：各マネージャーはそれぞれ `IMessageHandler` を実装し、それぞれ `Register()` を呼び出しますが、相互に影響しません。例えば `RoomDataManager` は `NotifyRoomChanged` を、`RockPaperScissorsDataManager` はじゃんけん関連のプロトコルを処理します。（[RoomDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RoomDataManager.cs#L16)、[RockPaperScissorsDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RockPaperScissorsDataManager.cs#L16)）

## よくあるエラー

- **`Register()` 内で `ProtoMessageHandler.Add(this)` の呼び出し忘れ**：属性はあくまでメタデータであり、自動的に有効にはなりません。これにより、メッセージが届いてもメソッドが一切呼び出されない原因となります。
- **`Register()` の複数回呼び出し**：コメントに「複数回呼び出さないでください」と明記されている通り、同じインスタンスを複数回登録すると重複してディスパッチされます。
- **メソッドシグネチャと属性内のメッセージタイプが一致していない**：`[MessageHandler(typeof(X), ...)]` の `X` はメソッド引数のタイプと完全に一致している必要があり、一致しない場合はリフレクションバインディングが失敗します。
- **`Register()` をコンストラクター内に配置している**：`GameFrameworkSingleton` の構築時には他のサブシステムがまだ初期化されていない可能性があるため、`Awake` または明示的に `GetInstance().Register()` を呼び出すタイミングで配置することをお勧めします。

## 背景（オプション）

`[MessageHandler]` はリフレクションベースのプロトコルルーティングマーカーです。フレームワークはプロトコルパケットを受信した後、`ProtoMessageHandler.Add(this)` で登録されたインスタンス群のテーブルを引いてディスパッチします。そのため、各ハンドラーにはインスタンスが1つだけ必要です。これが `GameFrameworkSingleton` を継承している理由でもあります。
