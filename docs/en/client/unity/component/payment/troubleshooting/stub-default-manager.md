# What to Do About the DefaultPaymentManager Stub Warning

When you see the warning `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).` in the Unity Console, it means the current `PaymentComponent` did not resolve a payment manager for any channel (Google / Apple / WebGL / PC) and instead fell back to the stub implementation `DefaultPaymentManager`. This is not an error — the stub implementation only logs a warning and returns "not implemented", but none of the payment calls will actually work; the fix is to make the running platform hit the corresponding channel implementation type.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Console prints `You are using DefaultPaymentManager which is a stub. ...` | No platform macro branch is hit in `PaymentComponent.Awake()`, so `componentType` falls to `typeof(DefaultPaymentManager).FullName` | Check the current running platform macro and the `m_component*Type` field configuration; see [Fix Steps](#fix-steps) below |
| Any call such as `Init(...)`, `Buy(...)`, `QueryPurchases(...)`, `ConsumePurchase(...)` prints the same warning | All methods of `DefaultPaymentManager` are empty implementations that only call `Log.Warning(NotImplWarning)` | Integrate the channel package and call again; see [Fix Steps](#fix-steps) |
| `IsReady()` always returns `false` and a purchase can never be initiated | `DefaultPaymentManager.IsReady()` is hardcoded to return `false` | This is the expected behavior of the stub implementation; it recovers automatically once a channel implementation is integrated |
| The warning appears when running in the Editor | Editor / non-mobile platforms take the `#else` branch and always use `DefaultPaymentManager` | Expected behavior; to test in the Editor, see [Common Variants](#common-variants) |
| The warning still appears on real devices (Android / iOS) | The channel implementation assembly is not installed; `Utility.Assembly.GetType(componentType)` returns null or the type is missing | Install the corresponding channel package (Google / Apple / WebGL / PC), or manually correct the type name in the Inspector |

## Fix Steps

### 1. Confirm Which Platform Branch Is Currently Hit

`PaymentComponent.Awake()` selects the implementation type based on compile-time macros; it only falls to `DefaultPaymentManager` when none of the macros are hit:

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
            if (_paymentManager == null)
            {
                Log.Fatal("Pay Manager is invalid.");
                return;
            }
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L94)

Compare against the table above: a real Android device should hit `UNITY_ANDROID`, and iOS should hit `UNITY_IOS`; if a channel branch is hit but the warning still appears, it means the channel type itself is missing (see Step 3).

### 2. Check the Channel Type Name Configuration

The channel type names on `PaymentComponent` are serialized fields with the following default values:

```csharp
private IPaymentManager _paymentManager;
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L23-L28)

In the Inspector, select the GameObject that has `PaymentComponent` attached (component menu path `GameFrameX/Payment`) and check whether the platform-specific field has been changed to an invalid value; if you edited it manually and are unsure, restore it to the default full name shown above.

### 3. Install the Corresponding Channel Payment Package

The default type names point to classes in separate channel packages; this package only provides the interface and the stub implementation:

| Platform Macro | Expected Implementation Type | Required Channel Package |
|--------|----------------|------------|
| `UNITY_ANDROID` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` | Google payment package |
| `UNITY_IOS` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple payment package |
| `UNITY_WEBGL` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` | WebGL payment package |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` | PC payment package |
| `UNITY_STANDALONE_OSX` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple payment package |
| Others (including Editor) | `GameFrameX.Payment.Runtime.DefaultPaymentManager` | Included in this package |

If the channel package is not installed, `Utility.Assembly.GetType(componentType)` cannot obtain the type, so at runtime you only get the stub implementation, which triggers this warning. After installing the channel package, re-enter Play Mode / rebuild to resolve it.

### 4. Confirm the Stub Implementation Through Log Behavior

The behavior of all stub implementation methods is as follows (for reverse-confirming that the problem really lies in the stub implementation):

```csharp
public sealed class DefaultPaymentManager : BasePaymentManager
{
    private const string NotImplWarning = "You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).";

    public override void Init(bool isDebug = false, bool isClientVerify = false)
    {
        Log.Warning(NotImplWarning);
    }

    public override bool IsReady()
    {
        return false;
    }
```

Source: [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L17-L36)

The remaining methods (`QueryPurchases`, `ConsumePurchase`, `BuyInApp`, `BuySubs`, `Buy`, `SetPredefinedProductIds`) only print `Log.Warning(NotImplWarning)` just like `Init`; see [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L38-L81).

## Common Variants

- **Only want to stop the log spam in the Editor**: The Editor platform macro takes the `#else` branch and necessarily uses `DefaultPaymentManager`, so the warning cannot be removed through configuration; you can filter out the warning text in your log filtering, or guard with `IsReady()` before calling the payment interfaces (the stub implementation always returns `false`).
- **Integrating your own server/channel**: Inherit `BasePaymentManager` and implement the abstract members of `IPaymentManager` (`Init`, `IsReady`, `SetPredefinedProductIds`, `QueryPurchases`, `ConsumePurchase`, the `Buy` series; for the abstract signatures see [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L61-L96)), then change the `m_component*Type` field for the corresponding platform in the Inspector to the full name of your implementation class to replace the stub implementation.

## Verification

1. Re-enter Play Mode or rebuild and run; the Console no longer shows the `You are using DefaultPaymentManager which is a stub. ...` warning.
2. Call `PaymentComponent.Init(...)` and then call `IsReady()` (the component passes through directly to the manager; see [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115)): the stub implementation is always `false`, while a channel implementation should return `true` once ready after initialization completes.
3. Initiate a test purchase; the `OnPurchaseSuccess` / `OnPurchaseFailed` events should be called back; under the stub implementation these events will never be triggered (there are no `Raise*` calls).

## Background

`DefaultPaymentManager` is the fallback implementation the framework provides for the Editor and unrecognized platforms, ensuring the game can still compile and launch when no channel package is integrated, and every misuse of a payment interface warns the developer to integrate a channel implementation (the CHANGELOG also explicitly records these two behaviors: "added not-implemented warning logs to all methods" and "`IsReady()` returns `false`"). Implementation selection is determined entirely by compile-time macros plus serialized type names and is independent of the runtime environment, so fixing the configuration or installing a package is enough — no framework code changes are required.
