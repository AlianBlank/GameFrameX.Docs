# 起動完了イベントと起動失敗イベントの購読方法

`StartupCompletedEventArgs` と `StartupFailedEventArgs` を使用すると、起動フローの完了/失敗時に通知を受け取れます。シーン遷移、ローディング UI の解放、計測ポイントの報告、プレイヤーへのリトライ案内などに利用できます。

## 前提条件

- プロジェクトに `GameFrameX.Startup.Runtime` が導入済みであり、`GameEntry` を通じてイベントコンポーネント `EventComponent` を取得していること。
- GameFrameX のイベント購読パターン(`EventComponent.Subscribe`)に習熟していること。

## イベント ID とフィールド

| イベント | EventId | 読み取り可能なフィールド | 発火タイミング |
|------|---------|----------|----------|
| 起動成功 | `typeof(StartupCompletedEventArgs).FullName` | なし | `ProcedureGameLauncherState` がホットアップデートを完了し UI を Dispose した後 |
| 起動失敗 | `typeof(StartupFailedEventArgs).FullName` | `FailedProcedureName`、`FailedUrl`、`ErrorMessage` | いずれかの Procedure がネットワークまたはビジネス上の失敗によりフローを停止した時 |

`StartupFailedEventArgs.Create(procedureName, url, errorMessage)` は `StartupProcedureUtility` によって呼び出されます。`procedureName` は失敗が発生した Procedure のステート名、`url` はネットワーク系以外の失敗の場合は空文字列です。

## 操作手順

### 1. 起動成功イベントを購読する

`GameEntry` の初期化完了後、起動フローの開始前に `Subscribe` を呼び出し、handler を `EventComponent` に登録します:

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;
using GameFrameX.Startup.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupCompletedEventArgs.EventId,
    OnStartupCompleted);

static void OnStartupCompleted(object sender, GameEventArgs e)
{
    var args = e as StartupCompletedEventArgs;
    // メインシーンへの遷移、ログインアニメーションの再生など
}
```

`StartupCompletedEventArgs` には追加フィールドがないため、そのまま `Clear()` するだけで参照プールに返却できます。

Source: [StartupCompletedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupCompletedEventArgs.cs#L1-L38)

### 2. 起動失敗イベントを購読する

失敗イベントは Procedure 名、最後に失敗した URL、エラーの説明を保持しており、UI 表示と計測ポイントの報告に適しています:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);

static void OnStartupFailed(object sender, GameEventArgs e)
{
    var args = (StartupFailedEventArgs)e;
    Debug.LogError($"启动失败 [{args.FailedProcedureName}] {args.FailedUrl} {args.ErrorMessage}");
    // リトライボタンの表示、計測ポイントの報告
}
```

Source: [StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L1-L62)

### 3. 購読を解除する

不要になった時点で `Unsubscribe` を呼び出し、同一のデリゲート参照を渡します。そうしないと `EventComponent` がコールバックを保持し続けます。

```csharp
GameEntry.GetComponent<EventComponent>().Unsubscribe(
    StartupFailedEventArgs.EventId,
    OnStartupFailed);
```

## よくあるバリエーション

- **失敗のみを監視したい**:`StartupFailedEventArgs.EventId` のみを購読し、成功イベントは購読しません。
- **同一コールバックで成功/失敗を処理する**:`GameEventArgs e` に対して `is StartupCompletedEventArgs` / `is StartupFailedEventArgs` で分岐判定します。
- **ホットアップデート層でビジネス失敗を判定する**:`IHotfixLauncher.StartAsync` が `Result.Success == false` を返した場合、`ProcedureGameLauncherState` は `CompleteFailure` を呼び出して失敗イベントを発火し、`FailedProcedureName` を `"ProcedureGameLauncherState"` に固定し、`FailedUrl` を空文字列にします。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動完了後にコールバックが発火しない | 購読タイミングが遅く、イベントがすでに Fire 済みだった | `GameEntry` の起動前または入口スクリプトの `Awake` 内で `Subscribe` する |
| 失敗コールバックで URL が読み取れない | `StartupFailedEventArgs.FailedUrl` はネットワーク系の失敗時にのみ値が入る | `FailedProcedureName` + `ErrorMessage` でフォールバック表示を行う |
| コールバック受信後に再度購読して重複発火する | 重複排除をしていない、または 2 回の起動で handler が二重に登録されている | `Unsubscribe` した後に `Subscribe` する、または `GameEntry` 再起動時にまとめてクリーンアップする |
| 直接 `new StartupCompletedEventArgs()` して送信している | イベントはフレームワーク内部で統一的に Fire されるべきもので、外部から発火すべきではない | 手動で Fire しない。`EventComponent.Subscribe` 側でのみ消費する |

## 背景

2 つのイベントはどちらも `StartupProcedureUtility.CompleteSuccess` / `CompleteFailure` 内で発火されます:

- `CompleteFailure` は `EventComponent.Fire(procedureOwner, StartupFailedEventArgs.Create(...))` を呼び出します。
- `CompleteSuccess` は `EventComponent.Fire(procedureOwner, StartupCompletedEventArgs.Create())` を呼び出します。

イベント ID は `typeof(X).FullName` パターンを踏襲しており、GameFrameX ファミリー全体と一貫性を保っています。イベントオブジェクトは参照プール `ReferencePool.Acquire` から取得され、フレームワーク内部が `Clear` と回収を担当します。
