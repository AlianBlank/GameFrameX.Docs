# 出现 Invalid token 解析异常怎么办

当 LitJSON 在解析 JSON 字符串时遇到无法识别的词法单元(`ParserToken`),会抛出消息为 `"Invalid token '{0}' in input string"` 的 `JsonException`。本页帮你快速定位这种异常的根因并修复。

## 快速诊断

| 症状(异常消息) | 原因 | 修复 |
|----------------|------|------|
| `Invalid token 'X' in input string`(token 为单字符) | JSON 中出现了未预期的字符(如未转义的引号、注释、尾随逗号) | 删除或转义非法字符,确保符合 JSON 规范 |
| `Invalid token 'X' in input string`(token 为数字) | 数字字面量写错(如 `1.`、`0x1A`、多余符号) | 修正数字格式,只使用十进制,可带可选小数点和指数 |
| `Invalid token 'True' / 'False' / 'Null'` | 布尔或 null 写成了 PascalCase,例如 `True` | 改用 JSON 要求的全小写 `true` / `false` / `null` |
| `Invalid token 'CharSeq'` | 字符串内出现了非法字符(如未配对的转义符、控制字符) | 检查字符串转义,常见合法转义为 `\" \\ \/ \b \f \n \r \t \uXXXX` |
| `Invalid token 'End'` 或解析提前结束 | JSON 提前截断——括号/引号未闭合 | 在编辑器中补齐缺失的 `{` `}` `[` `]` `"` |

异常消息模板定义如下,大括号内是 Lexer 阶段的 `ParserToken` 枚举值:

```csharp
// Runtime/JsonException.cs
internal JsonException(ParserToken token) :
    base(string.Format(
             "Invalid token '{0}' in input string", token))
{
}
```

## 修复步骤

### 1. 定位出错的字符位置

把异常中的 token(单字符情况)与原始 JSON 字符串对照,即可定位到第一个不合法字符。LitJSON 的 `JsonReader` 会从左到右扫描,遇到第一个不能识别的字符就抛错。

```csharp
// Runtime/JsonReader.cs
TableAddCol(parse_table, ParserToken.ArrayPrime, '[',
            (int)ParserToken.Value,
            (int)ParserToken.ValueRest,
            ']');
```

Source: [JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs#L266-L274)

### 2. 修正常见的非法字符

下面这些写法在标准 JSON 中都不合法,LitJSON 会直接抛 `Invalid token`:

- 单引号字符串 `'foo'` —— 必须改成双引号 `"foo"`
- 注释 `// xxx` 或 `/* xxx */` —— JSON 不支持注释,需要去除
- 尾随逗号 `{ "a": 1, }` —— 逗号后必须还有元素
- PascalCase 布尔/空值 `True` / `False` / `Null` —— 必须为 `true` / `false` / `null`
- 未转义的控制字符或裸换行 —— 字符串内部的换行需要用 `\n` 转义

### 3. 修正常见的非法数字

`ParserToken.Number` 触发的 `Invalid token` 通常是数字格式问题。合法数字必须是十进制,可带可选的小数点和指数:

- 合法:`0`、`-1`、`3.14`、`-2.5e10`、`1.0E+3`
- 非法:`1.`(小数点后无数字)、`01`(前导零)、`0x1A`(十六进制)、`NaN`、`Infinity`、`+1`(多余符号)、`1,000`(千分位逗号)

### 4. 用最小可复现用例验证

修复后,用一个最小可执行片段验证你的 JSON 能正确解析:

```csharp
using GameFrameX.LitJSON.Runtime;

string json = "{\"name\":\"litjson\",\"v\":1}";
JsonData data = JsonMapper.ToObject(json);
Debug.Log(data["name"]); // 输出: litjson
Debug.Log(data["v"]);    // 输出: 1
```

如果仍报 `Invalid token`,请把异常消息中的 token 值和原始字符串片段(包含出错位置前后各若干字符)反馈给上游数据来源方。

## 验证

1. 在 Unity Editor 的 Console 中运行修复后的 JSON 解析代码,确认不再抛出 `JsonException`。
2. 用在线 JSON 校验工具(例如 jsonlint.com)校验输入字符串,得到 "Valid JSON" 结果。
3. 若 JSON 来自网络或外部文件,加上 try/catch 并打印 `e.Message`,便于定位具体出错位置:

```csharp
try
{
    var data = JsonMapper.ToObject(rawJson);
}
catch (JsonException e)
{
    Debug.LogError($"解析失败:{e.Message}");
}
```
