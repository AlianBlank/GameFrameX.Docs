# 欠落キーとカルチャフォールバックの取り扱い方法

`GetString` がすべてのプロバイダー、すべてのフォールバックチェーン内でキーに一致する値を見つけられなかった場合、フレームワークはキーそのものを返し、欠落カウントを累積し、`MissingKey` イベントを発火します。本ページでは、イベントを購読して欠落を観測する方法、フォールバックチェーンと既定のカルチャを調整する方法、およびフォーマット失敗時の動作を制御する方法を説明します。

## 前提条件

- `LocalizationService` を介して `ResourceManager` シングルトンを取得済み、または自身で `new ResourceManager()` していること。
- 名前空間 `GameFrameX.Foundation.Localization` と `GameFrameX.Foundation.Localization.Core` を参照していること。

## 操作手順

### 1. `MissingKey` イベントを購読して欠落キーを観測する

```csharp
using GameFrameX.Foundation.Localization;
using GameFrameX.Foundation.Localization.Core;

LocalizationService.Manager.MissingKey += (sender, args) =>
{
    Console.WriteLine($"[Missing] key={args.Key}");
    Console.WriteLine($"  culture={args.Culture.Name}");
    Console.WriteLine($"  fallback={string.Join(" -> ", args.FallbackChain.Select(c => c.Name))}");
    Console.WriteLine($"  providers={string.Join(", ", args.ProviderNames)}");
};
```

イベントの引数は `MissingResourceEventArgs` であり、キー、要求されたカルチャ、フォールバックチェーン、検索されたプロバイダーのアセンブリ名を含みます。イベントの発火タイミングについては [`ResourceManager.cs`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L95-L97)(定義) と [`ResourceManager.cs#L281-L294`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L281-L294)(発火箇所) を参照してください。

Source:[GameFrameX.Foundation.Localization/Core/MissingResourceEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/MissingResourceEventArgs.cs#L8-L40)

### 2. 欠落カウントを取得する

```csharp
var manager = LocalizationService.Manager;
var stats = manager.GetStatistics(); // MissingKeyCount、FormatFailureCount、キーごとのヒットカウントなどを含む
```

### 3. フォールバックチェーンと既定のカルチャを調整する

`ResourceManager` には関連する2つのスイッチがあります:

| プロパティ | 既定値 | 役割 |
|------|--------|------|
| `DefaultCulture` | `CultureInfo.InvariantCulture` | 最終的なフォールバック先のカルチャ。フォールバックチェーンの末尾に追加される |
| `CultureFallbackEnabled` | `true` | 無効化すると `CurrentUICulture` の現在のカルチャのみを照会する |

フォールバックを無効化する例:

```csharp
LocalizationService.Manager.CultureFallbackEnabled = false;
```

フォールバックチェーンの生成ロジックについては [`ResourceManager.cs#L191-L221`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L191-L221) を参照してください。要求されたカルチャから出発し、`Parent` をさかのぼり、最後に `DefaultCulture` と `InvariantCulture` を追加します。

### 4. フォーマット失敗時の動作を制御する

`FormatString(key, args)` を呼び出した際にテンプレートと引数が一致しない場合(例: プレースホルダー `{0}` に実引数がない)、`FormatErrorBehavior` の設定に従って処理されます:

```csharp
using GameFrameX.Foundation.Localization.Core;

LocalizationService.Manager.FormatErrorBehavior = LocalizationFormatErrorBehavior.ReturnKey;
// LocalizationFormatErrorBehavior.Throw  — FormatException をスローする
// LocalizationFormatErrorBehavior.ReturnTemplate — 置換されていないテンプレートを返す(既定)
```

列挙型の定義は [`LocalizationFormatErrorBehavior.cs`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/LocalizationFormatErrorBehavior.cs#L6-L22) に、分岐の実装は [`ResourceManager.cs#L242-L259`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L242-L259) にあります。

## よくあるバリエーション

- **オンデマンドで発見・読み込みされる GameFrameX アセンブリ**:実行時に JIT で読み込まれるアセンブリがローカライズリソースを見落とさないようにするため、`ResourceManager` のコンストラクタは `AppDomain.CurrentDomain.AssemblyLoad` を購読済みです。手動操作は不要です。
- **欠落率のみを確認したい、イベントコールバックは不要**:直接 `GetStatistics()` を呼び出して `MissingKeyCount` を読み取ればよく、イベントを購読する必要はありません。
- **欠落時に例外をスローして自己テストしやすくしたい**: `FormatErrorBehavior` を `Throw` に設定すると、単体テストで「テンプレート + 引数が一致しない」パスを確実に通ったことをアサートできます。

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| UI に英語のキー名(例: `Utility.Exceptions.TimestampOutOfRange`)が表示される | 現在の UI カルチャ + すべての親カルチャ + `DefaultCulture` + `InvariantCulture` のいずれも一致せず、また `MissingKey` イベントの購読も行われていない | リソース DLL がパッケージに含まれているか確認し、`Localization.*.resources` が埋め込まれているか確認する。または `DefaultCulture` を明示的に設定する |
| `DefaultCulture` を変更しても `en-US` にフォールバックされる | アセンブリのリソースに `en-US` のエントリが存在し、`DefaultCulture` よりも優先される | これは想定通りの動作である。`DefaultCulture` を強制したい場合は、`CultureFallbackEnabled` を無効化するか、対応するリソースを削除する |
| 突然 `FormatException` のログが大量に報告される | プレースホルダーと引数の数が一致していない。既定の動作は `ReturnTemplate` で例外をスローしない | デバッグ時にのみ `FormatErrorBehavior` を `Throw` に設定し、リリース時は `ReturnTemplate` に戻す |

## 背景(任意)

フォールバックの順序は [`ResourceManager.cs#L162-L184`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L162-L184) にあります:フォールバックチェーン内の各カルチャについて、プロバイダーの順に照会し、最初に一致したものを返します。プロバイダーの例外は吸収されて `Debug` に出力されるため、単一の壊れたリソースがクエリ全体を壊すことを防ぎます。すべてのパスで結果が見つからない場合 `RecordMissingKey` を呼び出します:カウントをインクリメントし、キーごとに集計し、その後イベントを発火します。最终的に呼び出し側にはキー名そのものが返されるため、UI は常に空でない文字列を取得できます。
