# Waiting for Seconds and Frames with async/await

`TimerComponent` exposes three wait methods that can be directly `await`ed: `WaitForSecondsAsync` (wait for seconds), `WaitForNextFrameAsync` (wait for the next frame), and `WaitForFramesAsync` (wait for a specified number of frames). They are all implemented on top of the timer manager, with both the wait and the continuation completing on the Unity main thread, allowing you to write linear flows in `async` methods outside of coroutines.

## Prerequisites

- `TimerComponent` is already integrated into the scene/project (the timer manager is initialized along with the component).
- The caller is an `async` method (`async void` is only recommended for Unity event functions, such as `Start`).

## API Quick Reference

| Method | Signature | Behavior |
|------|------|------|
| Wait for seconds | `Task WaitForSecondsAsync(float seconds, CancellationToken cancellationToken = default)` | Completes the task after `seconds` seconds |
| Wait for next frame | `Task WaitForNextFrameAsync(CancellationToken cancellationToken = default)` | Completes the task after the next frame update |
| Wait for frames | `Task WaitForFramesAsync(int frameCount, CancellationToken cancellationToken = default)` | Completes after `frameCount` frames have elapsed; completes immediately when `frameCount <= 0` (returns `Task.CompletedTask`) |

The same-named instance methods on `TimerComponent` forward directly to the internal `ITimerManager` (see [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L245)). In addition, `TimerAsyncExtensions` provides the same three capabilities as extension methods for any `ITimerManager`:

```csharp
public static Task WaitForSecondsAsync(this ITimerManager timer, float seconds, CancellationToken cancellationToken = default)
public static Task WaitForNextFrameAsync(this ITimerManager timer, CancellationToken cancellationToken = default)
public static Task WaitForFramesAsync(this ITimerManager timer, int frameCount, CancellationToken cancellationToken = default)
```

Source: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L20-L72)

## Steps

1. Reference the namespaces in your script (adjust according to your project's actual referencing approach):

```csharp
using System.Threading;
using System.Threading.Tasks;
```

2. Get the `TimerComponent` instance (the example below uses the field `timerComponent` to refer to your project's component reference), then use `await` to wait for a number of seconds:

```csharp
public async void Start()
{
    // Wait for 2 seconds (TimerComponent forwards to the internal timerManager)
    await timerComponent.WaitForSecondsAsync(2f);
    UnityEngine.Debug.Log("Execution reaches here after 2 seconds");
}
```

3. Wait for a number of frames, or just one frame:

```csharp
// Continue after waiting 60 frames
await timerComponent.WaitForFramesAsync(60);

// Wait only for the next frame
await timerComponent.WaitForNextFrameAsync();
```

4. If you hold an `ITimerManager` reference, you can also call the extension methods directly:

```csharp
await timerManager.WaitForSecondsAsync(1.5f);
```

## Common Variants

- **Waiting with a cancellation token** (end early on object destruction or gameplay cancellation):

```csharp
var cts = new CancellationTokenSource();
await timerComponent.WaitForSecondsAsync(5f, cts.Token);
```

If the token is canceled, awaiting the task again will complete it in a canceled state; if the token is already canceled before the call, the method directly returns `Task.FromCanceled(cancellationToken)` without registering any timers:

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return Task.FromCanceled(cancellationToken);
}
```

Source: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L22-L28)

- **Chaining multiple waits sequentially**: `await` is naturally linear — just write them in order, no nested callbacks required.

## Common Mistakes

| Symptom | Cause | Fix |
|------|------|------|
| `WaitForFramesAsync(0)` or passing a negative number does not wait | Returns `Task.CompletedTask` directly when `frameCount <= 0`; this is documented behavior | Pass at least `1`; to "yield immediately", use `WaitForNextFrameAsync()` |
| The token is already canceled but the wait flow is still entered | By design: when already canceled, it returns `Task.FromCanceled` immediately without registering a timer | Check the token's lifecycle and replace it with a new one if necessary |
| Accessing Unity objects in the continuation throws an off-main-thread exception | All waits and continuations complete on the Unity main thread (explicitly declared in the class comments) | Do not use `ConfigureAwait(false)` or other context-changing patterns on the awaited task |

## Background

All three methods wrap a timer callback with a `TaskCompletionSource<bool>`: `WaitForSecondsAsync` uses `timer.AddOnce(seconds, ...)`, which is automatically removed after firing once; `WaitForNextFrameAsync` uses `AddOnce(0, ...)`, where `interval=0` means every frame and `repeat=1` means execute once; `WaitForFramesAsync` uses `timer.Add(0, frameCount, ...)`, executing every frame and being removed after `frameCount` total executions. Cancellation uses `cancellationToken.Register` to set the task to the canceled state, and the registration is disposed when the callback fires. See the implementation in [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L27-L94).
