# Scoped Registry の設定とコンポーネントの選択的導入方法

`Packages/manifest.json` で `GameFrameX` の scoped registry(スコープ登録ソース)を宣言することで、Unity Package Manager が `com.gameframex` で始まるすべてのパッケージを解析し、プロジェクトの必要に応じて導入するコンポーネントを選べるようになります。

## 前提条件

- Unity 2019.4 以降(Package Manager の scoped registry サポートを内蔵)。
- プロジェクトルートに `Packages/manifest.json` が存在する(Unity がプロジェクト作成時に自動生成)。

## 操作手順

1. プロジェクトルートの `Packages/manifest.json` を開き、ファイル末尾の `"scopedRegistries"` 配列に GameFrameX 登録ソースを追加します(配列が既に存在する場合は、項目を一つ追加してください):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L72)

2. 同じファイルの `"dependencies"` に、まずコアランタイムパッケージ `com.gameframex.unity` を追加します(他のすべてのコンポーネントがこれに依存します):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

3. 必要に応じて他のコンポーネントの依存関係を追加します。例えば、リソース管理、UI、ネットワーク、フロー管理など。完全な `dependencies` の記述は以下の通りです(本リポジトリの `Packages/manifest.json` からの抜粋):

```json
{
  "dependencies": {
    "com.gameframex.unity": "2.5.0",
    "com.gameframex.unity.asset": "3.1.0",
    "com.gameframex.unity.config": "1.2.0",
    "com.gameframex.unity.coroutine": "1.1.0",
    "com.gameframex.unity.entity": "2.4.5",
    "com.gameframex.unity.entry": "1.3.0",
    "com.gameframex.unity.event": "1.3.0",
    "com.gameframex.unity.fsm": "1.2.0",
    "com.gameframex.unity.network": "2.6.10",
    "com.gameframex.unity.procedure": "1.4.0",
    "com.gameframex.unity.sound": "1.3.0",
    "com.gameframex.unity.ui": "2.11.0",
    "com.gameframex.unity.ui.fairygui": "3.4.2"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L2-L64)

4. ファイルを保存して Unity エディタに戻ると、Package Manager が自動的に新しい登録ソースと依存関係を取得します。リストの更新が完了するまで待ち、左側に `GameFrameX - Scoped Registry` カテゴリ内の利用可能なすべてのパッケージが表示されます。

5. バージョン番号は [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) ページまたは [GameFrameX UPM Registry](https://gameframex.upm.alianblank.uk) を参照してください。`"1.11.0"`、`"2.0.0"` のようなプレースホルダーバージョンを実際の対象バージョンに置き換えます。

## よくあるバリエーション

- **Unity エディタ経由で追加**: `Edit ▸ Project Settings ▸ Package Manager ▸ Scoped Registries` ページで `+` をクリックし、`Name=GameFrameX`、`URL=https://gameframex.upm.alianblank.uk`、`Scopes=com.gameframex` を入力します。保存後の効果は `manifest.json` を直接編集した場合と同じです。
- **複数の登録ソースを併用する**: `scopedRegistries` は配列なので、複数のオブジェクトを並列に記述できます。本リポジトリでは GameFrameX と `package.openupm.com`(`io.sentry` スコープ用)を同時に宣言しています:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    },
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["io.sentry"]
    }
  ]
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L65-L80)

- **Git URL でサードパーティ製コンポーネントを直接インストールする**: UPM に未公開のパッケージ(例: HybridCLR)の場合は、`dependencies` に Git アドレスを直接記入することで、scoped registry を経由せずにインストールできます:

```json
{
  "dependencies": {
    "com.code-philosophy.hybridclr": "https://gitee.com/focus-creative-games/hybridclr_unity.git"
  }
}
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L3-L3)

- **最小限のセットのみを導入する**: 不要な依存関係を削除するだけで OK です。GameFrameX の各コンポーネントはモジュール化されており、強制的なバンドル関係はありません。`com.gameframex.unity` と `com.gameframex.unity.entry` のみを残しても正常に起動できます。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| Package Manager が `Unable to find package com.gameframex.unity` を報告する | `scopedRegistries` が宣言されていない、または `scopes` が `com.gameframex.unity` になっている | `scopedRegistries` に `scopes: ["com.gameframex"]` を追加する |
| パッケージはダウンロードできるが `assembly definition` で名前空間が見つからない | `com.gameframex.unity` のみを導入し `com.gameframex.unity.entry` を導入していない、またはサブモジュールが漏れている | 不足している `com.gameframex.unity.*` 依存関係を補完し、`com.gameframex.unity.entry` が追加されていることを確認する |
| エディタが "Resolving packages" で止まったままになる | 複数の登録ソースの `scopes` が互いに重複し、重複解析が発生している | 各 scoped registry の `scopes` が重複しないようにする(例: GameFrameX は `com.gameframex`、OpenUPM は `io.sentry`) |
| 新バージョンへのアップグレード後に `dll` が欠落する | `dependencies` のバージョンが古いまま固定されており、新バージョンでパッケージ構造が変更された | [Releases](https://github.com/GameFrameX/GameFrameX.Unity/releases) で移行説明を確認した後、バージョン番号を一括更新する |

## 背景(任意)

Scoped registry は Unity Package Manager が 2019.3 から提供している公式メカニズムです。URL + 名前空間スコープ(`scopes`)によって、プライベート/パブリックの npm スタイルの UPM 登録ソースをプロジェクトに統合しつつ、公式パッケージや既存の依存関係に影響を与えません。本リポジトリは `com.gameframex.*` すべてを自社構築の UPM registry `https://gameframex.upm.alianblank.uk` でホストしているため、スコープが一致していれば、Package Manager はバージョンに応じて対応する tarball を解決できます。
