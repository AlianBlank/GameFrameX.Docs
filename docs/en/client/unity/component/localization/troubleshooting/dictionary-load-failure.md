# What to Do When Dictionary Loading Fails (LoadDictionaryFailureEventArgs)

When a localization dictionary asset fails to load, the framework throws the `LoadDictionaryFailureEventArgs` event. This event carries three fields — `DictionaryAssetName` (the name of the dictionary asset that failed), `ErrorMessage` (the error message), and `UserData` (the custom data passed in when the load was initiated) — reading these three fields first during troubleshooting lets you pinpoint whether the cause is a "misconfigured asset name" or a "missing asset / load exception".

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `ErrorMessage` indicates the asset does not exist / cannot be found | The dictionary asset was not generated or was not built into the asset bundle | Follow Fix Step 1 below to verify whether the asset is loadable |
| `DictionaryAssetName` is empty or does not match expectations | A wrong asset name was passed in when calling the load | Follow Fix Step 2 below to check the asset name passed in at the call site |
| `UserData` is empty, making it impossible to tell which load failed | No custom data was attached when initiating the load | Follow Fix Step 3 below to pass a marker object at the load call site |
| The event never fires, and no success event appears either | The event is not subscribed, or the load process was never started | Follow Fix Step 4 below to confirm the subscription and the load call |

Field descriptions (taken from the actual definition of the event class):

| Property | Type | Default Value at Construction | Description |
|------|------|--------------|------|
| `DictionaryAssetName` | `string` | `null` | The name of the dictionary asset that failed to load |
| `ErrorMessage` | `string` | `null` | Error message (the specific text is returned by the underlying loading pipeline) |
| `UserData` | `object` | `null` | User-defined data |

## Fix Steps

### 1. Use ErrorMessage to Confirm Whether the Asset Is Loadable

Print the three fields in the event callback and check the specific content of `ErrorMessage` first; if it says the asset does not exist, it means the dictionary asset corresponding to `DictionaryAssetName` was not generated or was not built into the package — go check the asset's generation / packaging configuration instead of changing the code.

```csharp
private void OnLoadDictionaryFailure(object sender, GameEventArgs e)
{
    var args = (LoadDictionaryFailureEventArgs)e;
    UnityEngine.Debug.LogError(
        $"字典加载失败: {args.DictionaryAssetName}, 错误: {args.ErrorMessage}");
}
```

Note: The subscribe / unsubscribe interfaces are provided by the GameFrameX event component; when subscribing, use `LoadDictionaryFailureEventArgs.EventId` as the event identifier. The callback parameter type is `GameEventArgs`; cast it to this event type before reading the fields (both the event base class and `using GameFrameX.Event.Runtime;` come from the actual references in the event class file).

### 2. Check Where DictionaryAssetName Comes From

The value of `DictionaryAssetName` equals the `dataAssetName` passed in when the load was initiated (see the `Create` factory method below). Therefore, when the "name is wrong", go back to the line of code that initiates the load and verify the asset name string passed in (pay attention to casing, path prefixes, and suffixes).

```csharp
public static LoadDictionaryFailureEventArgs Create(string dataAssetName, string errorMessage, object userData)
{
    LoadDictionaryFailureEventArgs loadDictionaryFailureEventArgs = ReferencePool.Acquire<LoadDictionaryFailureEventArgs>();
    loadDictionaryFailureEventArgs.DictionaryAssetName = dataAssetName;
    loadDictionaryFailureEventArgs.ErrorMessage = errorMessage;
    loadDictionaryFailureEventArgs.UserData = userData;
    return loadDictionaryFailureEventArgs;
}
```

### 3. Use UserData to Distinguish Multiple Loads

If multiple dictionaries are loading in the same frame, `DictionaryAssetName` alone may not be enough to pinpoint the call site. Pass an identifiable `userData` (such as the caller object or an enum marker) each time you initiate a load; it will be returned as-is in the failure event, so you can determine exactly which call failed.

### 4. Confirm That the Event Is Actually Subscribed and the Load Is Actually Initiated

If there is neither a failure event nor a success event (`LoadDictionarySuccessEventArgs`), first confirm:

1. The event listener has been subscribed (using `LoadDictionaryFailureEventArgs.EventId` as the identifier);
2. The dictionary load call is actually executed (you can add logs before and after the call);
3. The assemblies in use have not been stripped — this component explicitly preserves types through `GameFrameXLocalizationCroppingHelper`; if you have customized the stripping configuration, make sure `LoadDictionaryFailureEventArgs` is not removed:

```csharp
_ = typeof(ILocalizationManager);
_ = typeof(LoadDictionaryFailureEventArgs);
_ = typeof(LoadDictionarySuccessEventArgs);
```

## Verification

- After re-triggering the dictionary load, the failure callback is no longer entered, or the console no longer outputs the failure log you printed;
- The corresponding dictionary asset produces `LoadDictionarySuccessEventArgs` (the success event, with fields `DictionaryAssetName`, `Duration`, and `UserData`), indicating that the loading pipeline has recovered;
- Reading the localized text from `LocalizationComponent` again now retrieves the entries from the dictionary.

For the overall usage of load success / progress events and the localization component, see the repository's Chinese README [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.zh-CN.md#L311-L313).

## Background

This event inherits from `GameEventArgs`; instances are acquired from the `ReferencePool` reference pool (`ReferencePool.Acquire<LoadDictionaryFailureEventArgs>()`) and returned to the pool after the three fields are reset to `null` in `Clear()`. Therefore, do not cache the event object itself in the callback — only read or copy the field values, because the object will be reused after the event is dispatched.
