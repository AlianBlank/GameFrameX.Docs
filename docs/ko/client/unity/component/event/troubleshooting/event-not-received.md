# 이벤트가 수신되지 않거나 트리거되지 않을 때 어떻게 해야 하나요

이벤트를 구독했는데도 콜백이 수신되지 않는 경우, 일반적으로 **구독과 발생시킨 이벤트 id가 일치하지 않음**, **Fire의 "다음 프레임 분배" 의미가 잘못 이해됨**, 또는 **씬에 `EventComponent`가 없음**이 원인입니다. 아래 진단 표에서 자신의 상황에 해당하는 항목을 찾은 후, 해당 복구 단계로 이동하면 원인을 파악할 수 있습니다.

## 복구 단계

### 1. 이벤트 id가 완전히 일치하는지 확인

`Subscribe`와 `Fire`가 매칭되는 유일한 근거는 `string` 타입의 이벤트 번호이며, 양쪽이 일치하지 않아도 이벤트 풀은 오류를 보고하지 않습니다(`EventManager`는 `EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler` 모드로 생성됨). 이벤트는 조용히 폐기됩니다:

```csharp
m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
```

소스: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L46-L49)

권장 방법: 이벤트 번호를 동일한 상수 또는 `typeof(X).FullName`으로 통일하고, 구독과 발생 양쪽이 같은 소스를 참조하도록 합니다. 매개변수 없는 이벤트를 사용할 때 `Fire(sender, eventId)`는 내부적으로 `EmptyEventArgs`를 생성하여 해당 번호를 기록합니다:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

소스: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

`EmptyEventArgs`는 회수될 때 번호를 `typeof(EmptyEventArgs).FullName`으로 재설정하므로, 이벤트 인수 오브젝트가 분배 후에도 커스텀 번호를 유지한다고 가정하지 마세요.

### 2. 먼저 구독한 후 이벤트를 발생시키고, 구독 성공 여부를 자체 확인

이벤트는 반드시 먼저 구독한 후 발생시켜야 합니다. 구독 체인에 문제가 있다고 의심될 때는 `Count(id)` / `Check(id, handler)`로 이벤트 풀의 현재 상태를 직접 확인합니다:

```csharp
public int Count(string id)
{
    return m_EventManager.Count(id);
}

public bool Check(string id, EventHandler<GameEventArgs> handler)
{
    return m_EventManager.Check(id, handler);
}
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L98)

중복 초기화로 인해 동일한 handler가 여러 번 구독되기 쉽습니다(`AllowMultiHandler`는 중복 구독을 허용하며 콜백이 중복 실행됨). 프레임워크는 중복 방지 버전을 제공합니다:

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

대칭적으로, 존재하지 않는 handler를 구독 해제할 때는 `CheckUnsubscribe`를 사용하며, 이 함수는 handler가 존재하지 않으면 그냥 건너뜁니다:

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L128-L131)

### 3. Fire의 "다음 프레임" 분배 의미 이해

`Fire`는 스레드 안전하지만, 이벤트는 큐에 들어간 후 `EventManager.Update`에서 다음 프레임에 분배됩니다; `FireNow`는 즉시 분배하지만 스레드 안전하지 않습니다:

```csharp
/// 이벤트를 발생시킵니다. 이 작업은 스레드 안전하며, 메인 스레드가 아닌 곳에서 발생시키더라도 메인 스레드에서 이벤트 처리 함수가 콜백되는 것이 보장되지만, 이벤트는 발생 후 다음 프레임에 분배됩니다.
public void Fire(object sender, GameEventArgs e)
{
    m_EventPool.Fire(sender, e);
}

/// 이벤트 즉시 발생 모드입니다. 이 작업은 스레드 안전하지 않으며, 이벤트가 즉시 분배됩니다.
public void FireNow(object sender, GameEventArgs e)
{
    m_EventPool.FireNow(sender, e);
}
```

소스: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L158-L175)

큐의 이벤트는 매 프레임 폴링을 통해 소비됩니다:

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_EventPool.Update(elapseSeconds, realElapseSeconds);
}
```

소스: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L81-L84)

여기서 두 가지 점검 포인트를 도출할 수 있습니다:
1. `Fire` 후 같은 프레임에 콜백이 이미 실행되었다고 단언하면 실패합니다 — 다음 프레임을 기다리거나 `FireNow`로 변경하세요.
2. 이벤트 발생 직후 구독 오브젝트를 파괴하거나 게임 일시정지로 `Update`가 멈추면, 큐의 이벤트가 영원히 분배되지 않을 수 있습니다.

### 4. 씬에 EventComponent가 있는지 확인

`EventComponent`는 `Awake`에서 `GameFrameworkEntry.GetModule<IEventManager>()`를 통해 모듈을 가져오며, 실패하면 `Log.Fatal`을 출력하고 바로 반환하므로 이후 모든 이벤트 API를 사용할 수 없습니다:

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

복구: 씬에 `GameFrameX/Event` 컴포넌트(`[AddComponentMenu("GameFrameX/Event")]`)를 추가하고, 초기화 순서가 모듈 우선순위를 만족하는지 확인하세요(`EventManager.Priority`는 7).

### 5. 기본 처리 함수로 구독자가 없는 이벤트 폴백 진단

기본 처리 함수를 설정하면 구독자가 없는 모든 이벤트가 해당 콜백으로 전달되므로, 진단 단계에서 "이벤트가 발생했지만 처리하는 곳이 없음"을 출력하기에 적합합니다:

```csharp
public void SetDefaultHandler(EventHandler<GameEventArgs> handler)
{
    m_EventManager.SetDefaultHandler(handler);
}
```

소스: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L137-L140)

## 검증

1. 로그만 출력하는 handler를 구독하고 `Count(eventId)`를 기록하면, 반환값은 1 이상이어야 합니다.
2. `Fire(sender, eventId)` 후 다음 프레임을 기다린 후(또는 직접 `FireNow` 사용) 로그 출력을 확인합니다.
3. `Check(eventId, handler)`는 `true`를 반환해야 합니다; `CheckUnsubscribe` 실행 후 `Count(eventId)`는 0으로 돌아가야 하며, 다시 `Fire`하면 이벤트가 기본 처리 함수로 진입합니다(설정한 경우).
4. 에디터에서 `EventComponent`가 부착된 오브젝트를 선택하면 Inspector에서 이벤트와 처리 함수 수를 확인할 수 있습니다(`EventHandlerCount` / `EventCount`).
