# 国密 SM2/SM3/SM4 の使用方法

`GameFrameX.Foundation.Encryption` は国密三大アルゴリズムへのワンストップ入口を提供します：`Sm2Helper`（非対称暗号化 / 復号化 / 鍵ペア生成）、`Sm4Helper`（対称暗号化 / 復号化、CBC / ECB 対応）、および BouncyCastle ベースの `SM3Util.Hash`（SM3 ダイジェスト）。このページでは、3 つのアルゴリズムの最小限の使用コード例とよくある落とし穴を説明します。

## 前提条件

- 名前空間を参照する：`GameFrameX.Foundation.Encryption`、`GameFrameX.Foundation.Encryption.Sm`。
- プロジェクトが BouncyCastle（`Org.BouncyCastle.*`）を参照していること。フレームワークにデフォルトで含まれています。
- SM2 の公開鍵 / 秘密鍵は 16 進数文字列です。SM4 の鍵は非 hex モードでは 16 バイト、hex モードでは 32 個の 16 進数文字である必要があります。

## 操作手順

### 1. SM3 ハッシュ

SM3 はハッシュアルゴリズムであり、暗号化アルゴリズムではありません。`SM3Util.Hash` は文字列を受け取り、固定長（256 ビット）の 16 進数ダイジェストを返します。内部では UTF-8 エンコーディングを使用して、プラットフォーム間の一貫性を保証しています。

```csharp
using GameFrameX.Foundation.Encryption.Sm;

string hash = SM3Util.Hash("hello world");
// 同一入力に対して複数回呼び出した結果は一貫しており、整合性検証に使用可能
```

出典: [SM3Util.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm/SM3Util.cs#L47-L69)

### 2. SM2 非対称暗号化

`Sm2Helper` は文字列とバイト配列の 2 セットのオーバーロードを提供し、鍵ペア生成もサポートします。内部的には BouncyCastle に基づいています。

```csharp
using GameFrameX.Foundation.Encryption;

// 鍵ペア生成
Sm2Helper.GenerateKeyPair(out string publicKey, out string privateKey);

// 公開鍵で暗号化
string cipher = Sm2Helper.Encrypt(publicKey, "secret message");

// 秘密鍵で復号化
string plain = Sm2Helper.Decrypt(privateKey, cipher);
```

バイト配列のオーバーロード（バイナリデータ / ネットワークプロトコルに適しています）：

```csharp
byte[] pubKeyBytes = Convert.FromHexString(publicKey);
byte[] data = System.Text.Encoding.UTF8.GetBytes("payload");
string cipherHex = Sm2Helper.Encrypt(pubKeyBytes, data);
byte[] plainBytes = Sm2Helper.Decrypt(Convert.FromHexString(privateKey), Convert.FromHexString(cipherHex));
```

出典: [Sm2Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm2Helper.cs#L62-L174)

### 3. SM4 対称暗号化

`Sm4Helper` はデフォルトで CBC モードを採用しています。鍵長ルール：非 hex モードで 16 バイト、hex モードで 32 文字。`iv` を渡さない場合、hex モードではデフォルトで全 0（`00000000000000000000000000000000`）が埋められます。

CBC 暗号化 / 復号化：

```csharp
using GameFrameX.Foundation.Encryption;

string key = "0123456789abcdef";        // 16 バイト
string cipher = Sm4Helper.EncryptCbc(key, "明文テキスト");
string plain  = Sm4Helper.DecryptCbc(key, cipher);
```

ECB モード（IV 不要）：

```csharp
string cipher = Sm4Helper.EncryptEcb(key, "明文テキスト");
string plain  = Sm4Helper.DecryptEcb(key, cipher);
```

JavaScript 互換モード（フロントエンドの sm-crypto などのライブラリと相互運用するためのパディング動作）：

```csharp
string cipher = Sm4Helper.EncryptCbc(key, "明文", forJavascript: true);
string plain  = Sm4Helper.DecryptCbc(key, cipher, forJavascript: true);
```

hex 鍵モード：

```csharp
string hexKey = "0123456789ABCDEF0123456789ABCDEF"; // 32 個の 16 進数文字
string cipher = Sm4Helper.EncryptCbc(hexKey, "明文", hexString: true);
```

出典: [Sm4Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm4Helper.cs#L163-L195)

## よくあるバリエーション

| シナリオ | 推奨される方法 |
|------|----------|
| フロントエンド / Node との相互運用 | SM4 は `forJavascript: true` を使用し、フロントエンドでは sm-crypto の同じモードを使用 |
| 長いメッセージの署名検証 | まず `SM3Util.Hash` でダイジェストを取得し、業務フィールドと一緒に送信して比較 |
| 高頻度のバイナリストリーム暗号化 / 復号化 | SM2 / SM4 のバイト配列オーバーロードを使用し、文字列エンコード / デコードのオーバーヘッドを回避 |
| SM2 鍵の永続化 | `GenerateKeyPair` が出力した 16 進数文字列をそのまま保存。Base64 は自前で処理しない |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `ArgumentException: KeyMustBe16Characters` | 非 hex モードでの SM4 鍵が 16 バイトでない | 文字列長を調整するか、`hexString: true` で 32 文字の hex に変更 |
| `ArgumentException: KeyMustBe32Characters` | hex モードの鍵長が 32 でない | hex 文字列が切り詰められていないか、余分な文字が追加されていないか確認 |
| SM2 復号化が `CryptographicException(Sm2InvalidDataFormat)` をスロー | 公開鍵 / 秘密鍵が一致していない、または暗号文が誤って二重エンコードされている | 暗号化 / 復号化の両側で 16 進数の大文字小文字が一致しており、不要な Base64 変換が行われていないことを確認 |
| SM3 ハッシュが異なるプラットフォームで結果が異なる | 入力が `Encoding.Default` で再エンコードされている | 必ず UTF-8 エンコーディングで渡すこと。`SM3Util.Hash` は内部で UTF-8 を使用するように統一されている |
| `ArgumentException(PublicKeyStringCannotBeEmpty)` | SM2 公開鍵文字列が空 | `GenerateKeyPair` の出力が切り詰められていないか確認 |

## 背景（オプション）

`Sm2Helper` / `Sm4Helper` は業務向けの薄いラッパーであり、すべての原始ロジック（楕円曲線ポイント演算、SM4 ラウンド鍵拡張など）は BouncyCastle によって処理されます。`SM3Util` は BouncyCastle の `Sm3Digest` を直接再利用します。3 種類の例外は `Sm*Helper` 層でキャッチされ、`CryptographicException` として統一的にラップされるため、上層で 1 つの型としてまとめてキャッチできます。
