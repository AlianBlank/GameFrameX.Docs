# 如何在状态间共享数据 (Variable)

通过 `Fsm<T>` 自带的 `SetData` / `GetData` 方法,以字符串为 Key 存取 `Variable` 实例,即可在任意两个 `FsmState<T>` 之间安全地传递运行时数据。

## 前置条件

- 已通过 `FsmComponent.CreateFsm<T>` 创建好有限状态机,并至少注册了两个状态。
- 状态类继承自 `FsmState<T>`,能在 `OnEnter` / `OnUpdate` / `OnExit` 中通过 `fsm` 参数访问 FSM。
- 共享的数据类型必须继承自 `Variable`(内置或自定义均可)。

## 操作步骤

1. **确认共享数据的类型**:框架要求数据派生自 `Variable`,这是因为 FSM 通过对象池(`ReferencePool`)复用 `Variable` 实例以避免 GC。

   ```csharp
   // 共享一个整数进度(0~100)
   public sealed class ProgressVar : Variable
   {
       private int m_Value;
       public int Value
       {
           get => m_Value;
           set => m_Value = value;
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L46)

2. **在状态 A 写入数据**:调用 `SetData<TData>(name, data)`。同名数据再次写入时,旧实例会被自动回收到 `ReferencePool`。

   ```csharp
   public class LoadingState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = new ProgressVar { Value = 0 };
           fsm.SetData("Progress", progress);
       }

       protected override void OnUpdate(IFsm<MyOwner> fsm, float elapseSeconds, float realElapseSeconds)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress != null)
           {
               progress.Value += 1; // 直接修改 Value,无需重新 Set
           }
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L497-L500)

3. **在状态 B 读取数据**:使用强类型 `GetData<TData>(name)` 直接拿到派生类实例;若键不存在或类型不匹配,返回 `null`。

   ```csharp
   public class PlayState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress == null)
           {
               // 状态机未携带该数据,按需兜底
               return;
           }
           fsm.Owner.Ui.ShowProgress(progress.Value);
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

4. **不再需要时清理数据**:调用 `RemoveData(name)`,数据对象会被回收到对象池。

   ```csharp
   fsm.RemoveData("Progress");
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L535)

## 常见变体

| 场景 | 用法 | 备注 |
|------|------|------|
| 不知道确切类型,只关心存不存在 | `fsm.GetData("Progress")` 返回 `Variable` 基类 | 见 [Fsm.cs#L469](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488) |
| 多个状态反复覆写同一键 | 直接再次 `SetData` | 旧实例会自动 `ReferencePool.Release`([Fsm.cs#L521-L524](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L521-L524)) |
| 共享数据不要求 GC 复用 | 也可传任意 `Variable` 子类 | 框架只强制基类为 `Variable`,字段自由 |

## 常见错误

| 错误现象 | 原因 | 修复 |
|----------|------|------|
| 传入 `name` 为空字符串,抛出 `GameFrameworkException("Data name is invalid.")` | API 要求 `name` 非空 | 使用常量或枚举作为 key |
| `GetData<TData>` 返回 `null`,NRE | 该 Key 从未写入,或类型不匹配 | 在写入端 `SetData` 后再读取,或先用 `GetData(name)` 检查存在 |
| 同名数据反复 `new` 导致内存上涨 | 没有复用 `Variable` 对象 | 复用同一个实例,只修改其内部字段;仅在必要时才 `SetData` 覆盖 |
| FSM 销毁后仍访问 `GetData` | FSM 已被销毁 | 在 `OnExit` 内清理引用,不要缓存 `IFsm<T>` 句柄 |

## 背景(可选)

`m_Datas` 是 `Dictionary<string, Variable>`,由 `Fsm<T>` 在第一次 `SetData` 时按需创建([Fsm.cs#L515-L518](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L515-L518))。覆盖同名键时调用 `ReferencePool.Release` 回收入池,所以 `Variable` 必须实现引用池协议(继承 `Variable` 已自带)。
