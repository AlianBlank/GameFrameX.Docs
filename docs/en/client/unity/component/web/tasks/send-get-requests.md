# How to Send a GET Request (Query Parameters and Request Headers)

You can send GET requests using the `GetToString` / `GetToBytes` family of methods on `IWebManager`: query parameters are passed in as a `Dictionary<string, string>` (the framework automatically appends them to the URL), request headers are passed in as another `Dictionary<string, string>`, and the methods return a `Task<WebStringResult>` or `Task<WebBufferResult>` to be `await`ed.

## Prerequisites

- The project has imported this package's Web runtime (`Runtime/Web`, with the entry component being [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs)).
- You have obtained an `IWebManager` instance (implemented by the `partial` class in [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs)).

## GET Method Quick Reference

The following signatures are excerpted from [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L18-L67):

| Method | Signature | Description |
|------|------|------|
| Simplest GET (text) | `Task<WebStringResult> GetToString(string url, object userData = null)` | No parameters, no custom headers |
| Simplest GET (bytes) | `Task<WebBufferResult> GetToBytes(string url, object userData = null)` | Ideal for downloading binary data |
| GET with query parameters (text) | `Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, object userData = null)` | Parameters are automatically appended to the URL |
| GET with query parameters (bytes) | `Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, object userData = null)` | Same as above, but returns bytes |
| GET with parameters and headers (text) | `Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | Parameters come after, headers come first |
| GET with parameters and headers (bytes) | `Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | Same as above, but returns bytes |

All overloads support an optional `userData`, which is returned as-is in the result object (see "Background" below).

## Steps

1. Call the target overload of `GetToString` / `GetToBytes`, passing in the `url`; pass in the corresponding dictionaries as well when query parameters or request headers are needed.
2. `await` the returned `Task` to obtain a `WebStringResult` (response text) or a `WebBufferResult` (byte array).
3. On failure, the task throws an exception (network/HTTP error or `TimeoutException`); simply wrap the `await` in a `try/catch`.

The actual implementation of the simplest form (the no-parameter overload directly delegates to the "parameters + headers" overload):

```csharp
public Task<WebStringResult> GetToString(string url, object userData = null)
{
    return GetToString(url, null, null, userData);
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L133-L136)

The full overload with query parameters and request headers (the framework internally handles parameter merging, URL building, and queuing):

```csharp
public Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)
{
    var uniTaskCompletionSource = new TaskCompletionSource<WebStringResult>();
    queryString = MergeQueryString(queryString);
    header = MergeHeader(header);
    url = UrlHandler(url, queryString);

    WebJsonData webJsonData = WebJsonData.Create(url, header, true, uniTaskCompletionSource, userData);
    m_WaitingNormalQueue.Enqueue(webJsonData);
    return uniTaskCompletionSource.Task;
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L184-L195)

Based on the above signatures, typical usage (consuming the returned Task with `await`):

```csharp
// 1) Simplest GET
WebStringResult r1 = await webManager.GetToString("https://example.com/api/info");

// 2) With query parameters
var query = new Dictionary<string, string> { { "page", "1" }, { "size", "20" } };
WebStringResult r2 = await webManager.GetToString("https://example.com/api/list", query);

// 3) With query parameters + request headers
var header = new Dictionary<string, string> { { "Authorization", "Bearer <token>" } };
WebStringResult r3 = await webManager.GetToString("https://example.com/api/user", query, header);
```

## Common Variants

- **Returning a byte array (downloading files, images)**: Use `GetToBytes` instead, which returns a `WebBufferResult`. See the signatures in [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L26-L67).
- **Query parameter order wrong?** The overload's parameter order is fixed as `(url, queryString, header, userData)`; when passing only request headers, you must still pass `null` as a placeholder for `queryString`.
- **Only passing query parameters, no headers needed**: Call the two-parameter overload directly; there is no need to build the URL manually.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `await` throws a `TimeoutException` | The request timed out; converted by the `WebExceptionStatus.Timeout` branch in [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L300) | Increase the timeout or check the network; handle it separately with `catch (TimeoutException)` |
| The task throws a general `Exception` (with the error text as its message) | On non-WebGL platforms the request goes through `HttpWebRequest`, and network/HTTP errors call `SetException` directly (see [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L305)) | Check the URL, the parameters, and the server status code |
| Under WebGL, `unityWebRequest.error` is reported | The WebGL branch checks `isNetworkError / isHttpError / error` and then calls `TrySetException` (see [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L239-L247)) | Verify the cross-origin policy and server configuration accessible from the WebGL platform |
| Request headers have no effect | The `header` dictionary passed in is empty, or it is affected by the global default header override logic | Make sure the keys and values are non-empty; headers are written one by one via `SetRequestHeader` / `request.Headers[key] = value` (see [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L227-L233), [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L273-L279)) |

## Background (Optional)

The data carrier for GET requests is the internal `WebJsonData` (see [WebManager.WebJsonData.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.WebJsonData.cs#L12-L98)), which stores the URL, the `Header` dictionary, and the result `TaskCompletionSource`. A request first enters `m_WaitingNormalQueue` to wait its turn, and is then sent by the send flow using `UnityWebRequest.Get` on WebGL and `HttpWebRequest` (`WebRequestMethods.Http.Get`) on other platforms; query parameters are appended to the URL by `UrlHandler(url, queryString)`, and custom headers are written into the request one by one. `userData` is returned along with the result object, making it easy to distinguish concurrent requests.
