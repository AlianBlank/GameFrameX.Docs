# 統計 Provider の追加と設定方法

`GameAnalyticsComponent` コンポーネントの Inspector で、`IGameAnalyticsManager` を実装した型を「ゲームデータ分析コンポーネントリスト、順次レポート」に追加し、各エントリに対して `Setting` のキーと値のペアを入力します。実行時、コンポーネントはリフレクションによってすべての Provider を自動的にインスタンス化してその `Init` を呼び出し、それ以降のすべてのレポートインターフェースはリストの順序どおりに各 Provider へ転送されます。

## 前提条件

- 本パッケージ `com.gameframex.unity.gameanalytics` がインストール済みであること。
- シーン内に `GameAnalyticsComponent` が既に存在すること(`Add Component → Game Framework → GameAnalytics` から追加できます)。
- シーン内に `IGameAnalyticsManager` インターフェースを実装した統計実装クラスが少なくとも 1 つ存在すること(通常は各サードパーティ SDK アダプターパッケージによって提供されます)。存在しない場合、Inspector のドロップダウンリストには None のみが表示されます。

## 操作手順

1. `GameAnalyticsComponent` がアタッチされた GameObject を選択すると、Inspector には `GameAnalyticsComponentInspector` によってタイトルが「ゲームデータ分析コンポーネントリスト、順次レポート」の並べ替え可能なリストが描画されます。

2. リスト右下の `+` をクリックして新しいエントリを追加します。各エントリは 1 つの `GameAnalyticsComponentProvider` に対応し、そのシリアライズ可能なフィールドは以下のとおりです:

| フィールド | 型 | 説明 |
|------|------|------|
| `ComponentType` | `string` | `IGameAnalyticsManager` を実装した型の完全名。ドロップダウンから自動的に書き込まれます |
| `ComponentTypeNameIndex` | `int` | エディターのドロップダウンの現在のインデックス。実行時には使用されません |
| `Setting` | `List<GameAnalyticsComponentParamKV>` | この Provider に渡される初期化パラメータ。各項目は `Key`/`Value` の文字列ペアです |

```csharp
[Serializable]
public class GameAnalyticsComponentProvider
{
    /// <summary>
    /// 実装コンポーネントの型
    /// </summary>
    public string ComponentType;

    /// <summary>
    /// これはエディター用です
    /// </summary>
    public int ComponentTypeNameIndex = 0;

    /// <summary>
    /// パラメータ
    /// </summary>
    public List<GameAnalyticsComponentParamKV> Setting = new List<GameAnalyticsComponentParamKV>();
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L361-L378)

3. `ComponentType` のドロップダウンで対象の実装クラスを選択します。ドロップダウンの項目は、Inspector がリフレクションで `IGameAnalyticsManager` のすべてのランタイム型を収集して生成します。選択すると、型名が `ComponentType` 文字列に書き込まれます:

```csharp
managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

4. `Setting` に、この Provider が必要とする初期化パラメータ(AppKey、Channel など、具体的な SDK 実装で定義されるキー)を入力します。実装のアセンブリ内に `BaseGameAnalyticsSetting` を継承するクラスが存在する場合、Inspector はそのパブリックフィールドに基づいて Setting エントリを自動的に補完するため、Value を入力するだけで済みます:

```csharp
var types = type.Assembly.GetTypes();
foreach (var typeImpl in types)
{
    if (typeImpl.BaseType != typeof(BaseGameAnalyticsSetting))
    {
        continue;
    }

    var fieldInfos = typeImpl.GetFields();
    ...
}
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L148-L158)

5. Play モードに入ります。コンポーネントは `OnEnable` 内で `Init()` を呼び出し、各エントリに対してリフレクションでインスタンスを作成し、`Setting` を辞書に変換して渡します:

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L79)

6. リストのドラッグハンドルを使って順序を調整します。順序は転送の順序にのみ影響し、機能には影響しません。`Init` とそれ以降のすべてのレポート呼び出しはリストの順序で実行されます。

## 一般的なバリエーション

- **ログイン後に追加の初期化が必要な SDK**:一部の Provider は `IsManualInit()` を実装しており、ユーザー情報を取得した後にコンポーネントの `ManualInit(Dictionary<string, string> extraArgs)` を呼び出すと、コンポーネントは `extraArgs` を手動初期化が必要なすべての Provider に転送します:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

- **プレイヤー ID / 共通プロパティの設定**:`SetPlayerId(string playerId)`、`SetPublicProperties(string key, object value)`、`ClearPublicProperties()` を呼び出すと、リスト内のすべての Provider に同期して転送されるため、個別に呼び出す必要はありません。
- **カスタム Provider**:新しいクラスを作成して `IGameAnalyticsManager` を実装します(インターフェースの定義は [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8) を参照)。パラメーターなしのコンストラクターを必ず提供してください(コンポーネントは `Activator.CreateInstance` でインスタンス化します)。Inspector に Setting キーを自動生成させたい場合は、さらに同じアセンブリ内に `BaseGameAnalyticsSetting` を継承するクラスを定義し、各設定項目をパブリックフィールドで宣言します。

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| ログに `Can not find component type 'XXX'.` と表示され、該当エントリがスキップされる | `ComponentType` の型名が `Utility.Assembly.GetType` で解決できない:実装クラスのアセンブリがビルドに含まれていない、またはシリアライズされた値を手動で書き換えた | 実装パッケージが導入されていることを確認し、Inspector のドロップダウンで型を再選択する |
| ログに `GameAnalyticsManager is not init.` と表示される | コンポーネントがまだ `Init` されていない状態でレポートインターフェースが呼び出された(例:コンポーネントが無効化されて `OnEnable` が実行されなかった) | `GameAnalyticsComponent` が有効になっていることを確認する。必要に応じて手動で `Init()` を呼び出す |
| 特定のエントリがエラーなしに黙って無視される | `ComponentType` が空で、`Init` 内の `IsNotNullOrWhiteSpace` チェックを通らずそのままスキップされた | 該当エントリのドロップダウンで実装型を選択する |
| `ManualInit` の呼び出しが効果がない | `m_IsInit` が false のとき `ManualInit` は即座に return する。またはその Provider の `IsManualInit()` が false を返す | Play 後に `Init` が実行されたことを確認してから、実装の `IsManualInit` のロジックを確認する |
| Inspector の設定を変更しても実行時に旧設定が使われる | `Init` は `m_IsInit` によって保護されており、初回呼び出し時のみ有効 | Play モードを再起動する。実行中に `Init` を繰り返し呼び出しても有効になると期待しないこと |

## 検証

- Play 後に Console に `Can not find component type` のエラーが出ない場合、すべてのエントリの型解決が成功しています。
- `SetPlayerId` などの転送インターフェースを呼び出したときに `GameAnalyticsManager is not init.` の警告が出ない場合、Provider リストの初期化が完了しています。
- 各 Provider 実装の `Init(Dictionary<string, string>)` 内にブレークポイントを設定するかログを追加し、`Setting` のキーと値が設定どおりに渡されていることを確認します。

## 背景

コンポーネントは特定の SDK に直接依存しません。`Init` 時にリフレクションで `ComponentType` に従ってインスタンスを作成し、`Setting` リストを `Dictionary<string, string>` に変換して `Init(args)` に渡します。その後、すべてのパブリックインターフェース(set/レポートなど)は `m_GameAnalyticsManager` を巡回して順に転送するため、複数の統計 SDK を同時に順序どおりレポートすることが実現されています。
