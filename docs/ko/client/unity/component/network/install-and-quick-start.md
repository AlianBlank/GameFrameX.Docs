# 설치 및 빠른 시작

GameFrameX Network는 Unity 장기 연결 네트워크 컴포넌트 패키지로, TCP / WebSocket 연결, RPC 호출, 하트비트, 메시지 직렬화 등의 기능을 제공합니다. 이 페이지에서는 설치를 완료하고 "네트워크 채널 생성 → 서버 연결 → 메시지 송수신"의 최소 흐름을 진행해 봅니다.

## 사전 조건

- Unity 2019.4 이상 버전(`package.json`의 `"unity": "2019.4"`).
- GameFrameX 기본 패키지가 설치되어 있어야 하며, 이 패키지는 다음 컴포넌트에 의존합니다([package.json](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/package.json#L22-L26) 참조):

| 의존 패키지 | 버전 | 설명 |
|--------|------|------|
| `com.gameframex.unity` | 1.1.1 | GameFrameX 기본 프레임워크 |
| `com.gameframex.unity.event` | 1.0.0 | 이벤트 시스템 |
| `com.gameframex.unity.litjson` | 1.2.0 | JSON 직렬화 |

- 대상 플랫폼 지원: Windows / macOS / Linux / Android / iOS / WebGL([README.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/README.md#L74-L81) 참조).

## 작업 단계

### 1. 패키지 설치

아래 방법 중 하나를 선택하세요([README.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/README.md#L40-L71) 참조):

**방법 A: Scoped Registry(권장, 의존성 자동 해결 가능)**

Unity 프로젝트의 `Packages/manifest.json`을 편집합니다:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.network": "2.6.6"
  }
}
```

`scopes`는 어떤 패키지를 해당 registry에서 해석할지 결정합니다 — `com.gameframex`로 시작하는 패키지만 여기서 가져옵니다.

**방법 B: Git URL 의존성**

```json
{
  "com.gameframex.unity.network": "https://github.com/gameframex/com.gameframex.unity.network.git"
}
```

**방법 C: Package Manager → Add package from git URL**

```
https://github.com/gameframex/com.gameframex.unity.network.git
```

**방법 D: 직접 클론**

저장소를 프로젝트의 `Packages` 디렉터리에 클론하면 Unity가 자동으로 로드합니다.

### 2. 네트워크 매니저 가져오기

모든 네트워크 기능은 `INetworkManager` 인터페이스를 통해 사용하며, 진입 API는 다음과 같습니다(소스 코드는 [INetworkManager.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkManager.cs#L40-L114) 참조):

| 이름 | 시그니처 | 설명 |
|------|------|------|
| 채널 수 | `int NetworkChannelCount { get; }` | 현재 네트워크 채널 수 |
| 연결 성공 이벤트 | `event EventHandler<NetworkConnectedEventArgs> NetworkConnected` | 연결이 설정될 때 트리거 |
| 연결 종료 이벤트 | `event EventHandler<NetworkClosedEventArgs> NetworkClosed` | 연결이 종료될 때 트리거 |
| 하트비트 유실 이벤트 | `event EventHandler<NetworkMissHeartBeatEventArgs> NetworkMissHeartBeat` | 하트비트 타임아웃 시 트리거 |
| 네트워크 오류 이벤트 | `event EventHandler<NetworkErrorEventArgs> NetworkError` | 오류 발생 시 트리거 |
| 채널 존재 확인 | `bool HasNetworkChannel(string channelName)` | 이름으로 채널 확인 |
| 채널 가져오기 | `INetworkChannel GetNetworkChannel(string channelName)` | 이름으로 채널 가져오기 |
| 전체 채널 가져오기 | `INetworkChannel[] GetAllNetworkChannels()` | 모든 채널 반환 |
| 채널 생성 | `INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper, int rpcTimeout)` | 이름 있는 채널을 생성하며, 헬퍼와 RPC 타임아웃(밀리초)을 전달 |
| 채널 제거 | `bool DestroyNetworkChannel(string channelName)` | 이름으로 채널 제거 |
| 포커스 하트비트 스위치 | `void SetFocusHeartbeat(bool hasFocus)` | 앱이 포커스를 얻거나 잃을 때 하트비트 전송 여부 제어 |

소스 코드에서 매니저 인스턴스를 가져오는 호출자 예제를 찾을 수 없습니다. 연동 시 GameFrameX 컴포넌트 체계를 통해 이 인터페이스를 구현한 `NetworkManager`를 가져오세요(구현 위치: [NetworkManager.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.cs) 및 동일 이름의 partial 파일).

### 3. 네트워크 채널 생성

`CreateNetworkChannel`은 3개의 매개변수를 필요로 합니다: 채널 이름(여러 개의 이름 있는 연결을 동시에 유지 가능), `INetworkChannelHelper` 헬퍼(패킷 헤더/본문 처리, 하트비트, 압축 등 파이프라인 구성 담당), RPC 타임아웃(밀리초).

```csharp
// channelHelper는 INetworkChannelHelper를 구현해야 하며, 패킷 헤더/본문 인코딩·디코딩 및 하트비트 규칙을 정의합니다
INetworkChannel channel = networkManager.CreateNetworkChannel("main", channelHelper, rpcTimeout: 10000);
```

### 4. 네트워크 이벤트 구독

```csharp
networkManager.NetworkConnected += (sender, e) => { /* 연결 성공 */ };
networkManager.NetworkClosed   += (sender, e) => { /* 연결 종료 */ };
networkManager.NetworkError    += (sender, e) => { /* 네트워크 오류 */ };
networkManager.NetworkMissHeartBeat += (sender, e) => { /* 하트비트 유실 */ };
```

### 5. 연결 및 송수신

`INetworkChannel`에서 연결을 시작하고 메시지를 송수신하며, 구체적인 메서드 시그니처는 채널 인터페이스를 참조하세요. 이후 매 프레임마다 매니저 업데이트를 호출하여 송수신 루프를 구동합니다. 송수신 상태, 하트비트, RPC 등의 내부 상태는 `NetworkManager`의 partial 파일(`NetworkManager.ReceiveState.cs`, `NetworkManager.SendState.cs`, `NetworkManager.HeartBeatState.cs`, `NetworkManager.RpcState.cs`)로 구현되어 있으며, [Runtime/Network/Network/](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.cs)를 참조하세요.

### 6. 사용 후 채널 제거

```csharp
networkManager.DestroyNetworkChannel("main");
```

## 일반적인 변형

- **WebSocket 채널**: 패키지에 WebSocket 채널 구현이 기본 포함되어 있으며(`NetworkManager.WebSocketNetworkChannel` / `NetworkManager.WebSocketNetSocket`), TCP 측은 `NetworkManager.SystemTcpNetworkChannel` / `NetworkManager.SystemNetSocket`이고, [Runtime/Network/Network/](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/SystemSocket/NetworkManager.SystemTcpNetworkChannel.cs)에 위치합니다.
- **커스텀 직렬화**: `IMessageSerializer` 인터페이스를 구현하면 메시지 직렬화를 삽입할 수 있으며, 2단계 등록(전역 기본값 + 단일 채널 오버라이드)을 지원합니다.
- **포커스 하트비트 제어**: `SetFocusHeartbeat(bool)`을 호출하면 앱이 포커스를 얻거나 잃을 때 하트비트를 계속 전송할지 여부를 구성할 수 있습니다.

## 일반적인 오류

- **의존성 누락으로 인한 설치 실패**: `com.gameframex.unity`(1.1.1), `com.gameframex.unity.event`(1.0.0), `com.gameframex.unity.litjson`(1.2.0)이 먼저 사용 가능해야 합니다. Git URL 방식으로 설치하면 UPM이 이러한 의존성을 자동으로 가져오지 않으므로 Scoped Registry(방법 A) 사용을 권장합니다.
- **Unity 버전이 너무 낮음**: 이 패키지는 Unity 2019.4+가 필요하며, 해당 버전 미만인 경우 먼저 프로젝트를 업그레이드하세요.
- **채널 이름 중복**: `CreateNetworkChannel`로 같은 이름을 다시 생성하기 전에 `HasNetworkChannel(channelName)`으로 먼저 확인하세요.
- **`INetworkChannelHelper` 구현 누락**: 채널 생성 시 반드시 헬퍼를 전달해야 하며, 헬퍼가 패킷 헤더/본문 인코딩·디코딩, 하트비트 및 압축 파이프라인을 결정합니다.

## 배경

이 패키지는 네트워크 기능을 "여러 개의 이름 있는 채널"로 구성하며, 각 채널은 데이터 패킷 처리 파이프라인(송신/수신 헤더 및 본문 프로세서, 하트비트, 압축/해제)을 독립적으로 구성할 수 있고, 연결 상태는 이벤트 시스템을 통해 보고됩니다(자세한 내용은 [package.json](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/package.json#L5) 설명 참조). 매니저 인터페이스 `INetworkManager`와 구현체 `NetworkManager`가 분리되어 있어 교체나 mock이 용이합니다.
