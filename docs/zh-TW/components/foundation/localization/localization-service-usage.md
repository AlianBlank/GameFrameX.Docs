# 使用 LocalizationService 讀取當地語系化資源的方法

`LocalizationService` 是當地語系化系統的靜態進入點，能夠以執行緒安全且延遲載入的方式取得當地語系化字串。只要呼叫靜態方法，即可讀取與索引鍵繫結的多語系文字，無須在意底層 `ResourceManager` 或各個 `IResourceProvider` 的細節。

## 前置條件

- 已參考 `GameFrameX.Foundation.Localization` 組件，並將對應的當地語系化資源（預設/英文 `Resources.resx`、中文 `Resources.zh-CN.resx` 等）匯入至專案。
- 資源索引鍵已存在於上述 `.resx` 中，且索引鍵名稱以 `Namespace.SubModule.KeyName` 格式管理（例如：`Encryption.InvalidKeySize`、`Utility.Exceptions.TimestampOutOfRange`）。
- 專案啟動的 .NET 版本與 `GameFrameX.Foundation.Localization` 一致。

## 操作步驟

1. **取得一筆當地語系化字串（遵循目前的 UI 文化特性）**。這是最基本的用法，只需傳入資源索引鍵。若找不到，將傳回索引鍵本身。

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   var message = LocalizationService.GetString("Utility.Exceptions.TimestampOutOfRange");
   ```

   Source: [LocalizationService.cs#L114-L122](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L114-L122)

2. **明確指定文化特性進行讀取**。若需要取得特定文化特性的值，請傳入 `CultureInfo`。查詢會沿著 `zh-Hans-CN → zh-Hans → zh → `（空＝預設）的後援鏈結解析，且不會影響 `CultureInfo.CurrentUICulture`。

   ```csharp
   using System.Globalization;
   using GameFrameX.Foundation.Localization.Core;

   var message = LocalizationService.GetString(
       "Utility.Exceptions.TimestampOutOfRange",
       new CultureInfo("zh-Hans-CN"));
   ```

   Source: [LocalizationService.cs#L130-L138](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L130-L138)

3. **讀取含預留位置的格式字串**。資源範本使用 `string.Format` 的預留位置（`{0}`、`{1}` …），並透過 `params object[]` 傳入引數。

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // 範本範例:"Invalid key size: {0}. Expected length: {1}."
   var formatted = LocalizationService.GetString(
       "Encryption.InvalidKeySize", 128, 256);
   ```

   Source: [LocalizationService.cs#L161-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L161-L164)

   也可以先明確指定文化特性再進行格式化：

   ```csharp
   LocalizationService.FormatString(
       "Encryption.InvalidKeySize",
       CultureInfo.InvariantCulture,
       128, 256);
   ```

   Source: [LocalizationService.cs#L184-L187](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L184-L187)

4. **於應用程式啟動時預先載入資源（選用）**。延遲載入機制已足以應付大多數情境，但若想在啟動階段就完成資源偵測，請明確呼叫一次 `EnsureLoaded()`。

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // 於應用程式啟動階段進行預熱
   LocalizationService.EnsureLoaded();
   var message = LocalizationService.GetString("Utility.Exceptions.TimestampOutOfRange");
   ```

   Source: [LocalizationService.cs#L207-L210](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L207-L210)

5. **整合 `IStringLocalizer`（ASP.NET Core / 泛用 .NET 主機）**。使用 `GameFrameXStringLocalizer` 將本服務的 `ResourceManager` 包裝為 `IStringLocalizer`，使其可用於相依性插入與 `Microsoft.Extensions.Localization` 生態系統。

   ```csharp
   using GameFrameX.Foundation.Localization.Core;
   using Microsoft.Extensions.Localization;

   var manager = LocalizationService.Instance;
   IStringLocalizer localizer = new GameFrameXStringLocalizer(manager);

   var found    = localizer["Known.Key"];      // LocalizedString.Value = "Known value"
   var missing  = localizer["Missing.Key"];    // .ResourceNotFound == true
   var argument = localizer["Known.Key", "ignored"]; // 經由格式化路徑
   ```

   Source: [GameFrameXStringLocalizer.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/GameFrameXStringLocalizer.cs)、[LocalizationHighPriorityFeatureTests.cs#L84-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationHighPriorityFeatureTests.cs#L84-L100)

## 常見變化

- **註冊自訂資源提供者（高優先順序）**。以手動方式透過 `RegisterProvider` 註冊的提供者會以 LIFO 順序排在最前端，因此適合用於測試或資料庫／遠端資源的整合。

  ```csharp
  LocalizationService.RegisterProvider(new DatabaseResourceProvider(/* ... */));
  var message = LocalizationService.GetString("Custom.Message");
  ```

  Source: [LocalizationService.cs#L258-L261](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L258-L261)

- **監視遺漏的索引鍵**。訂閱 `MissingKey` 事件，即可在執行階段捕捉未當地語系化的索引鍵，並寫入遙測／日誌。

  ```csharp
  LocalizationService.MissingKey += (sender, args) =>
  {
      Console.WriteLine($"Missing localization key: {args.Key} (culture={args.Culture.Name})");
  };
  ```

  Source: [LocalizationService.cs#L79-L89](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L79-L89)、[LocalizationHighPriorityFeatureTests.cs#L42-L58](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationHighPriorityFeatureTests.cs#L42-L58)

- **查看執行階段統計資料**。呼叫 `GetStatistics()` 可取得提供者數量、遺漏索引鍵計數、格式化失敗計數等資訊，有助於診斷。

  ```csharp

  Console.WriteLine($"Providers loaded: {stats.ProvidersLoaded}");
  Console.WriteLine($"Total providers: {stats.TotalProviderCount}");
  ```

  Source: [LocalizationService.cs#L234-L237](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L234-L237)

- **列舉已註冊的提供者**。`GetProviders()` 會傳回依優先順序排序的唯讀清單。索引愈小，優先順序愈高。

  ```csharp

      Console.WriteLine($"Provider: {provider.GetType().Name}");
  ```

## 常見錯誤

- **索引鍵不存在時不會顯示錯誤**。`GetString` 在找不到索引鍵時不會擲回例外，而是直接傳回索引鍵字串本身（測試已明確涵蓋此行為）。若 UI 上顯示 `Unknown.Test.Key` 之類的字串，通常是 `.resx` 未編譯進組件，或索引鍵名稱拼字錯誤。可訂閱 `MissingKey` 事件，或使用 `GetStatistics().MissingKeys` 找出原因。

  Source: [LocalizationServiceTests.cs#L40-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationServiceTests.cs#L40-L51)

- **將 `CultureInfo.CurrentUICulture` 與「明確指定的文化特性」混淆**。以 `GetString(key)` 這種不傳入文化特性引數的方式呼叫時，會直接使用 `CurrentUICulture`。一旦明確傳入文化特性，查詢便遵循 `GetCultureFallbackChain`（例如：`zh-Hans-CN → zh-Hans → zh → ` 預設），`CurrentUICulture` 不會再疊加其上。因此，即使切換執行緒的 UI 文化特性，也不會影響已傳入文化特性之呼叫的結果。

  Source: [LocalizationHighPriorityFeatureTests.cs#L11-L40](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationHighPriorityFeatureTests.cs#L11-L40)

- **格式化範本書寫錯誤時例外會被吞掉**。當範本缺少 `}` 或預留位置索引不一致時，系統不會擲回 `FormatException`，而是傳回範本原文，並將失敗次數記錄到 `GetStatistics().FormatFailureCount`。必須主動監視。

  Source: [LocalizationHighPriorityFeatureTests.cs#L71-L82](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationHighPriorityFeatureTests.cs#L71-L82)

- **重複建立 `ResourceManager`**。`LocalizationService.Instance` 以 `Lazy<T>` 保證單一實例。若自行執行 `new ResourceManager()`，所註冊的自訂提供者、統計資料與事件訂閱將不會與全域服務連動。請務必透過 `LocalizationService` 進行操作。

  Source: [LocalizationService.cs#L60-L74](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L60-L74)、[LocalizationServiceTests.cs#L14-L23](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationServiceTests.cs#L14-L23)

## 背景（選用）

`LocalizationService` 內部使用 `Lazy<ResourceManager>` 保存唯一實例，`GetString` 等方法只是將呼叫轉送至 `Instance` 的對應方法。實際的查詢由 `IResourceProvider` 鏈依優先順序執行，預設會掃描已載入組件內的 `Localization/Messages/Resources.*.resx`。若傳入文化特性，會先呼叫 `GetCultureFallbackChain` 產生後援鏈結，並逐階段嘗試，直到預設（`""`）文化特性為止。`FormatString` 使用統一的格式化 API。即使範本剖析失敗也不會擲回例外，而是以範本作為後援傳回，並將失敗計數寫入 `ResourceManagerStatistics`，因此適合在上層進行遙測或傳送警示。`GameFrameXStringLocalizer` 是與 `Microsoft.Extensions.Localization` 生態系統之間的配接器層，適合在相依性插入容器中重複使用同一個 `ResourceManager` 的情境。
