# トラブルシューティング

本ドキュメントでは、CoroutineComponent コルーチンコンポーネントを使用する際に频繁に发生する問題と解決策を収集しています。

## 概要

CoroutineComponent は GameFrameX フレームワークのコルーチン管理コンポーネントであり、Unity 内蔵コルーチン機能を拡張し、より良いコルーチンライフサイクル管理与メモリ安全制御を提供します。このコンポーネントは `ConcurrentDictionary` スレッドセーフ辞書を 사용하여すべての実行中のコルーチンを追跡し、いつでもコルーチンを管理和停止できるようにします。

> 詳細な使用说明は [使用ガイド](../3-getting-started.index) と [API リファレンス](../4-api-reference.coroutine-component) を参照してください。

## よくある質問リスト

### Q1：同じ GameObject に複数の CoroutineComponent を追加できない理由は？

**問題の説明：**
同じ GameObject に2番目の CoroutineComponent を追加しようとすると、Unity エディターがエラーまたは追加できないと報告します。

**原因：**
CoroutineComponent は `[DisallowMultipleComponent]` 属性を使用しており、この属性は同じ GameObject に複数。同じタイプのコンポーネントを追加することを禁止します。

**解決策：**
- 各 GameObject には1つの CoroutineComponent インスタンスのみが存在することを確認します
- 複数のコルーチンを管理する必要がある場合は、同じ CoroutineComponent インスタンスで複数のコルーチンを起動します
- `StopAllCoroutines()` メソッドを使用してすべてのコルーチンを停止します

```csharp
// 正しい用法：同じコンポーネントで複数のコルーチンを管理
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(CoroutineA());
coroutineComponent.StartCoroutine(CoroutineB());
coroutineComponent.StopAllCoroutines(); // すべてのコルーチンを停止
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L10-L11)

### Q2：StartCoroutine に null イテレータを渡すとどうなりますか？

**問題の説明：**
`StartCoroutine` メソッドに `null` 値の IEnumerator を渡すと会发生什么？

**原因：**
`StartCoroutine` に null イテレータを渡すと、Unity 底层は空参照例外をスローします。

**解決策：**
- コルーチンを起動する前に、常には null かどうかを確認します
- 空値保護ロジックを追加します

```csharp
IEnumerator myCoroutine = GetSomeCoroutine(); // null の可能性

if (myCoroutine != null)
{
    coroutineComponent.StartCoroutine(myCoroutine);
}
```

### Q3：実行中のコルーチンを正しく停止する方法は？

**問題の説明：**
`StopCoroutine` を呼び出した後もコルーチンが実行続けているように見えます。または、コルーチンを停止できません。

**原因：**
- 渡された IEnumerator と起動時のイテレータが同じ参照でない
- コルーチンが既に実行完毕
- コルーチンが StopCoroutine 呼び出し前に既に終了している

**解決策：**
- コルーチンを起動する時に返された IEnumerator 参照を保存します
- `StopAllCoroutines()` を使用してすべてのコルーチンを停止します
- コルーチン実行中に适时に停止することを確保します

```csharp
// コルーチン参照を保存
IEnumerator myCoroutine = coroutineComponent.StartCoroutine(MyLongRunningTask());

// 適切なタイミングで停止
coroutineComponent.StopCoroutine(myCoroutine);

// またはすべてのコルーチンを停止
coroutineComponent.StopAllCoroutines();
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L32-L45)

### Q4：コンポーネントがマウントされた GameObject が破棄された後に会发生しますか？

**問題の説明：**
CoroutineComponent を含む GameObject が破棄された場合、実行中のコルーチンはどうなりますか？

**原因：**
GameObject が破棄されると、Unity は自動的にその GameObject 上のすべてのコルーチンを停止します。CoroutineComponent は MonoBehaviour を継承しているため、この動作에도従います。

**提案：**
- シーン切り替えまたはオブジェクト破棄前に、手動で `StopAllCoroutines()` を呼び出してコルーチンが干净に停止することを確保します
- OnDestroy ライフサイクルフックを使用して清理を実行します

```csharp
private void OnDestroy()
{
    // オブジェクト破棄前にすべてのコルーチンを停止することを確保
    if (coroutineComponent != null)
    {
        coroutineComponent.StopAllCoroutines();
    }
}
```

### Q5：WaitForEndOfFrameFinish に null コールバックを渡すとクラッシュしますか？

**問題の説明：**
`WaitForEndOfFrameFinish` メソッドに null コールバックを渡すと会发生しますか？

**原因：**
CoroutineComponent は null合体演算子 `callback?.Invoke()` を使用しているため、null コールバックを渡してもクラッシュせず、呼び出しは安全に無視されます。

**源码検証：**
```csharp
public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(_WaitForEndOfFrameFinish(callback));
}

private IEnumerator _WaitForEndOfFrameFinish(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke(); // ?. 操作子で安全に呼び出し
}
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L97)

### Q6：フレームレンダリング完了後にロジックを実行する方法は？

**問題の説明：**
Unity の毎フレームレンダリング完了後に特定の操作を実行する必要があり如何使用しますか？

**解決策：**
`WaitForEndOfFrameFinish` メソッドを使用します。このメソッドは現在のフレームのレンダリング完了後にコールバックを実行します。

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    // このコールバックはフレームレンダリング完了後に実行される
    Debug.Log("フレームレンダリング完了、ロジックを実行");
});
```

**適用シナリオ：**
- UI レンダリング後にスクリーンショットを取得
- 物理計算完了後に特定の操作を実行
- フレーム末尾で状態同期を行う必要がある

### Q7：CoroutineComponent はスレッドセーフですか？

**問題の説明：**
CoroutineComponent はマルチスレッド環境で使用できますか？

**原因：**
はい、CoroutineComponent は `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` を使用してコルーチンマッピングを存储し、このデータ構造はスレッドセーフです。

**注意事項：**
- 内部存储はスレッドセーフですが、コルーチン自体は Unity メインスレッドで実行されます
- マルチスレッドアクセス時は、主に IEnumerator 参照の正しい传递を考慮する必要があります

### Q8：コルーチンが正しく停止されずメモリリークが発生した場合の対処方法是？

**問題の説明：**
コルーチンが正しく停止されないとメモリリークが発生する可能性があります。どのように予防しますか？

**原因：**
コルーチンを正しく停止しないと、特に無限ループや長時間待機を含むコルーチンは、メモリリークを引き起こす可能性があります。CoroutineComponent はコルーチンマッピングテーブルを維持することでこの問題を解決します。

**解決策：**
- `StopAllCoroutines()` を使用してすべてのコルーチンを清理
- コンポーネント破棄時に `StopAllCoroutines()` を呼び出すことを確保
- 明確な終了条件を持つコルーチンを使用します

```csharp
private void OnDestroy()
{
    // 重要：メモリリークを防ぐためにすべてのコルーチンを停止
    StopAllCoroutines();
}
```

### Q10：CoroutineComponent は手動で GameObject に追加する必要がありますか？

**問題の説明：**
コンポーネントがシーンに自動追加されないのはなぜですか？

**原因：**
CoroutineComponent は `Awake` メソッドで `IsAutoRegister = false` を設定ため、コンポーネントはフレームワークの自動登録システムに自動登録されません。

**解決策：**
CoroutineComponent を GameObject に手動で追加する必要があります：

```csharp
// コンポーネントを手動で追加
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();

// または Unity エディターで手動で追加
// 1. GameObject を選択
// 2. Add Component をクリック
// 3. "Game Framework/Coroutine" を検索
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L99-L103)

### Q11：Unity エディターで CoroutineComponent を見つける方法は？

**問題の説明：**
Unity エディターで CoroutineComponent を追加する方法は？

**解決策：**
コンポーネントは `[AddComponentMenu("Game Framework/Coroutine")]` 属性を使用しているため、以下の方法で追加できます：

1. Unity エディターで GameObject を選択
2. Inspector パネルを右クリック → Add Component
3. 検索框に "Coroutine" または "Game Framework/Coroutine" を入力
4. CoroutineComponent を選択

> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12)

## 診断手順

解决できない问题に遭遇した場合は、以下の手順で診断を実行してください：

1. **GameObject 状態を確認**：GameObject とコンポーネントがアクティブになっていることを確認します
2. **コルーチン参照を確認**：コルーチンを停止するために使用する IEnumerator 参照が正しいことを確認します
3. **Unity コンソールを確認**：エラーまたは警告情報があるかどうかを確認します
4. **StopAllCoroutines を使用**：デバッグ手段として、まずすべてのコルーチンを停止して問題を排查します
5. **シーン切り替えを確認**：シーン切り替え時にコルーチンが正しく清理されていることを確認します
