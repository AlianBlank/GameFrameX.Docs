# 如何重置与重启 FSM

通过 `Start<TState>()` 重置当前状态并从指定状态重新进入 FSM；需要完全销毁时再用 `Clear()`。框架没有名为 `Reset` 的方法,所谓"重置"靠的是重新 `Start`,"重启"靠的是销毁后重建。

## 前置条件

- 已通过 `FsmManager` 创建出 `IFsm<T>`,可以拿到当前 FSM 引用。
- 状态集合 `FsmStateCount > 0`,且目标状态类型已经注册到 FSM(用 `HasState<TState>()` 校验)。

## 操作步骤

### 1. 重置回初始状态(常用)

由于 `Fsm<T>.Start` 在 `IsRunning == true` 时会抛 `GameFrameworkException("FSM is running, can not start again.")`([Fsm.cs#L272-L277](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L277)),"重置"做法是先转移到占位状态再 `Start` 初始态。最简单的占位状态是再切一次相同状态,触发 `OnLeave`、清零 `CurrentStateTime`,再调用 `Start`。

```csharp
// owner 是当前持有者引用
void ResetToInitial(IFsm<MyOwner> fsm, MyOwner owner)
{
    if (fsm == null || fsm.IsDestroyed) return;

    // 进入一个等价状态以触发 OnLeave、清零计时器
    if (fsm.HasState<IdleState>())
    {
        fsm.Start<IdleState>();
        fsm.Start<IdleState>();
    }
}
```

Source: [Fsm.cs#L272-L288](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L288)

### 2. 重启(完整销毁 + 重建)

彻底重置需要调用 `Clear()` 把所有状态、所有者、数据都清空([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265)),然后通过 `FsmManager.CreateFsm` 重建并 `Start`。

```csharp
// 拿到 manager 与 owner
var fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());

fsm.Start<IdleState>();
// ... 之后想整体重启:
GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>().DestroyFsm(fsm);
fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());
fsm.Start<IdleState>();
```

`Clear()` 内部先调 `m_CurrentState.OnLeave(this, true)`,再遍历所有状态调 `OnDestroy`,并把 `m_CurrentState` 置 `null`、`m_CurrentStateTime` 置 `0`、`m_IsDestroyed` 设为 `true`([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265)。

## 常见变体

- **重置到任意状态**:把步骤 1 中的 `IdleState` 换成目标 `TState`。前提是 `HasState<TState>()` 返回 `true`。
- **只想重置数据、不换状态**:清空用户数据字典,保留当前状态继续运行(参考 [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs) 中 `m_Datas` 的清空方式)。
- **Editor 中观察状态**:Inspector 会显示 `fsm.CurrentStateName` 与 `CurrentStateTime`,状态名为 `null` 表示未运行([FsmComponentInspector.cs#L72](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Editor/Inspector/FsmComponentInspector.cs#L72))。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 抛 `FSM is running, can not start again.` | 在 `IsRunning == true` 时直接调用 `Start` | 先让 `IsRunning` 变 `false`(切到其他状态再切回,或先 `Clear` 再 `CreateFsm`) |
| 抛 `FSM 'X' can not start state 'Y' which is not exist.` | `TState` 未注册到 FSM | 调用前用 `fsm.HasState<TState>()` 校验,缺失则重建 FSM |
| 抛 `State type 'X' is invalid.` | 传入非 `FsmState<T>` 派生类的 `Type` | 确保 `stateType` 继承自当前 FSM 对应的 `FsmState<T>` |
| `Start` 后状态没变化 | 重复 `Start` 同一状态被判定为"已在运行"前的那一次 `Start` 已生效 | 用前述"先切一次等价再切回"绕开,或新建 FSM |

## 背景(可选)

`Start` 把 `m_CurrentState` 直接覆盖并调 `OnEnter`,所以"重置到自身"看似无效,真正生效的是 `OnLeave(..., true)` 与 `m_CurrentStateTime = 0f` 的副作用。完整销毁走引用池 `ReferencePool`,见 `Fsm<T>.Clear` 的实现。
