# WebGL 플랫폼 사용 방법

WebGL 플랫폼에서 `ImageCacheComponent`를 사용하여 원격 이미지를 로드할 때, 컴포넌트는 브라우저가 호스팅하는 `UnityWebRequestTexture` 채널로 자동 전환되며, 로컬 디스크 캐시 관련 API는 빈 작업(no-op)이 됩니다. WebGL을 위해 별도의 분기 코드를 작성할 필요가 없습니다.

## 사전 조건

- `GameFrameXImageCacheCroppingHelper`와 `ImageCacheComponent`를 씬 또는 런타임 진입점에 추가했습니다.
- WebGL 빌드에서 원격 이미지의 교차 출처 로드를 허용합니다(서버에서 CORS 헤더를 반환하거나 Player Settings에서 `Allow downloads over HTTP` / `Use default CORS` 설정).
- 원격 이미지 URL은 반드시 `http://` 또는 `https://`로 시작해야 하며, 컴포넌트가 접두사를 검증합니다.

## 작업 단계

1. 씬에 `ImageCacheComponent`를 마운트한 후, 정상적으로 `LoadImageAsync`를 호출합니다. WebGL에서 컴포넌트는 `LoadImageWebGLAsync`를 호출하여 `UnityWebRequestTexture`를 거치며, 브라우저 자체의 HTTP 캐시가 호스팅합니다.

   ```csharp
   using System.Threading;
   using System.Threading.Tasks;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   public class WebGLSample : MonoBehaviour
   {
       public ImageCacheComponent imageCache;

       public async Task<Sprite> LoadRemoteIcon(string url, CancellationToken ct = default)
       {
           Texture2D tex = await imageCache.LoadImageAsync(url, ct);
           if (tex == null)
           {
               Debug.LogWarning($"로드 실패: {url}");
               return null;
           }
           return Sprite.Create(tex, new Rect(0, 0, tex.width, tex.height), Vector2.one * 0.5f);
       }
   }
   ```

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L115)

2. WebGL에서 `IsCached`, `RemoveCache`, `ClearCache`는 항상 사용할 수 없습니다. 첫 번째는 WebGL에서 항상 `false`를 반환하고, 나머지 두 개는 디스크 캐시를 지원하지 않습니다. 호출 전에 플랫폼을 확인하여 비즈니스 로직에 잘못된 로그가 발생하지 않도록 하세요.

   ```csharp
   if (Application.platform != RuntimePlatform.WebGLPlayer)
   {
       bool hit = imageCache.IsCached(url);
       // …WebGL이 아닌 경우에만 디스크 캐시 판정 수행
   }
   ```

   Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L28-L47)

3. 교차 출처(CORS) 및 혼합 콘텐츠 처리: 브라우저는 기본적으로 교차 출처 텍스처를 금지합니다. 원격 서버가 `Access-Control-Allow-Origin`을 반환하거나 동일한 도메인에서 이미지를 호스팅해야 합니다. HTTPS 사이트에서는 HTTPS 이미지 URL을 사용하세요. 그렇지 않으면 브라우저가 요청을 차단합니다.

4. 텍스처 해제: `UnityWebRequestTexture.GetContent`가 반환하는 `Texture2D`는 프레임워크에서 자동으로 파괴되지 않습니다. 컴포넌트 언로드 또는 씬 전환 시 `Object.Destroy(texture)`를 호출하여 비디오 메모리 누수를 방지하세요.

5. 취소 토큰은 WebGL이 아닌 플랫폼에서만 적용됩니다. WebGL에서 전달된 `CancellationToken`은 무시되므로, UI 레이어(예: 패널 닫기)에서 반환된 `Task`를 직접 버리면 됩니다.

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L66-L89)

## 일반적인 변형

- **에디터에서 WebGL 시뮬레이션**: 에디터에서 실행하면 여전히 디스크 캐시 로직이 사용됩니다. WebGL 동작을 검증하려면 `File → Build Settings → WebGL → Build And Run`을 통해 빌드한 후 디버깅하세요.
- **UnityWebRequest 직접 호출 사용**: 진행률 처리나 사용자 정의 헤더 등 추가 처리가 필요한 경우, WebGL 분기에서 별도로 `UnityWebRequestTexture.GetTexture`를 사용할 수 있으며, `ImageCacheComponent`를 거칠 필요가 없습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `url must start with http:// or https://.` 경고 | URL에 프로토콜 헤더가 없거나 상대 경로 사용 | `https://` 접두사 추가 |
| 브라우저에서 CORS / Mixed Content 오류 발생 | 원격 서버가 CORS 헤더를 반환하지 않거나 프로토콜 불일치 | 서버에 `Access-Control-Allow-Origin` 추가, 또는 동일 도메인 / 동일 프로토콜로 리소스 호스팅 |
| `RemoveCache` / `ClearCache` 호출이 적용되지 않음 | WebGL에는 디스크 캐시가 없음 | 비즈니스 레이어에서 이 두 진입점을 숨김. 브라우저 자체의 캐시 정리 전략 사용 |
| `IsCached`가 항상 `false`를 반환함 | WebGL에서는 브라우저 캐시를 인식하지 못함 | 직접 `LoadImageAsync`를 호출하여 브라우저가 적중 여부를 결정하도록 함 |
| 씬 전환 반복 후 비디오 메모리 증가 | WebGL에서 반환된 `Texture2D`가 해제되지 않음 | 씬 언로드 / 이미지 교체 전에 `Object.Destroy(texture)` 호출 |

## 배경 (선택 사항)

WebGL이 아닌 플랫폼에서 `ImageCacheComponent.Awake`는 `IDownloadManager`를 통해 파일을 가져와 URL의 MD5를 파일 이름으로 디스크에 저장합니다. WebGL에서는 `#if !UNITY_WEBGL`의 전체 코드 블록이 제거되므로 `IDownloadManager`는 WebGL에서 참조되거나 주입되지 않습니다. WebGL 플랫폼은 `UnityEngine.Networking.UnityWebRequestTexture`에만 의존하며, 브라우저가 모든 캐시 로직을 처리합니다. 따라서 컴포넌트는 WebGL에서 디스크를 조작할 필요도 없고 조작할 수도 없습니다.

관련 컴포넌트의 전체 흐름은 [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L1-L100)를 참조하세요.
