# JSON 配置热更新（localization / achievement / item / sounds）

GameFrameX 通过监听 `GameFrameX.Config/json/` 下的 JSON 文件变更,把 localization、achievement、item、sounds 等本地配置在运行时热加载,无需重启进程即可让最新文案/数值在游戏中生效。

## 前置条件

- 配置文件位于仓库根 `GameFrameX.Config/json/` 目录下(如 `local_tblocalization.json`、`tables_tbachievementconfig.json`)。
- 配置类由 Luban + 源码生成器自动生成到 `GameFrameX.Config/Config/Local/` 与 `GameFrameX.Config/Config/Tables/`,改动 JSON 后必须重新生成代码,否则新增字段不会被读取。

## 操作步骤

1. **定位 JSON 配置目录**:所有可热更新的本地表 JSON 文件都放在 `GameFrameX.Config/json/`,文件名前缀 `local_` 表示本地表,`tables_` 表示 Luban 主表。

2. **修改配置内容**:直接编辑对应 JSON。例如改一段多语言文案:

   ```json
   [
     {
       "key": "ui_welcome",
       "ChineseSimplified": "欢迎回来",
       "ChineseTraditional": "歡迎回來",
       "English": "Welcome back",
       "Japanese": "おかえりなさい",
       "Korean": "환영합니다",
       "Thai": "ขอต้อนรับกลับมา",
       "Indonesian": "Selamat datang kembali",
       "French": "Bienvenue",
       "German": "Willkommen zurück",
       "Russian": "Добро пожаловать",
       "Italian": "Ben tornato",
       "PortuguesePortugal": "Bem-vindo de volta",
       "Spanish": "Bienvenido de vuelta",
       "Vietnamese": "Chào mừng trở lại"
     }
   ]
   ```

   字段定义见自动生成的实体类:
   [Localization.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Local/Localization.cs#L39-L56)

3. **触发热加载**:运行时进程会监听该目录的写入事件;保存 JSON 文件后服务端会在不重启的情况下重新读取并覆盖内存中的表。

4. **让代码使用最新值**:业务侧通过自动生成的表访问器(如 `TbLocalization`、`TbAchievementConfig`)获取数据,无需改动调用代码——只需保证生成器已基于最新 JSON 重新生成。

## 常见变体

- **新增语言列**:在 JSON 中追加列并对应修改 Luban 表结构,重新生成代码后热更新才能识别新列。
- **新增条目**:直接在 JSON 数组中追加对象,键值必须符合 `BeanBase` 子类的字段命名(`Key`、`English` 等)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 保存 JSON 后游戏内文案没变 | 没重新生成实体类代码,新增字段未被识别 | 重新执行 Luban + 源码生成器生成 `Localization.cs` 等 |
| 启动报 `JsonElement` 反序列化异常 | JSON 字段名或大小写与生成类不匹配 | 按 `Localization.cs` 中 `GetProperty("...")` 的字段名修正 |
| 热更新后旧条目消失 | 直接覆盖整个数组文件而非追加/修改 | 仅修改目标条目,保留数组结构 |

## 背景(可选)

JSON 表由 Luban 在编译期生成 C# 实体类(标记 `<auto-generated>`),运行时通过 `JsonElement` 解析到 `BeanBase` 子类实例。热更新通过文件系统监听实现,所以 **JSON 必须写在 `GameFrameX.Config/json/` 下并保证与生成代码同源**,否则反序列化会失败。
