# Advertisement manager is invalid 怎么办

运行时控制台出现 `Log.Fatal("Advertisement manager is invalid.")` 时,说明 `AdvertisementComponent.Awake()` 无法通过 `GameFrameworkEntry.GetModule<IAdvertisementManager>()` 拿到广告管理器实例,组件会直接 return,后续 `Start`、`Initialize` 等流程都不会执行。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志报错 `Advertisement manager is invalid.` | `GameFrameworkEntry` 中没有注册任何 `IAdvertisementManager` 实现 | 在场景里挂一个 `AdvertisementComponent`,并在 Inspector 里填写继承 `BaseAdvertisementManager` 的具体管理器类全名 |
| 报错同上,组件已挂载但仍报错 | `componentType` 字段填错(类名拼写错误、命名空间缺失、未继承 `BaseAdvertisementManager`) | 填入完整的「命名空间.类名」,确保类继承 `BaseAdvertisementManager` 并实现 `IAdvertisementManager` |
| 报错同上,运行时某平台管理器为 `null` | 该平台的广告 SDK 包未引入,程序集中找不到实现类 | 安装对应平台 SDK(见下方"修复步骤")或临时切换到已安装平台的 `componentType` |
| 报错同上,只有 Debug 构建报错 | Player Settings 中 IL2CPP / 托管代码剥离排除了管理器类 | 在 `link.xml` 或 Player Settings 的 `Managed Stripping Level` 中保留管理器所在程序集 |

报错原文与触发位置:

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L85-L97
private IAdvertisementManager _advertisementManager;

protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IAdvertisementManager);
    base.Awake();
    _advertisementManager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
    if (_advertisementManager == null)
    {
        Log.Fatal("Advertisement manager is invalid.");
        return;
    }

}
```

## 修复步骤

### 1. 确认场景中存在 AdvertisementComponent

`AdvertisementComponent` 是广告系统入口组件,缺少它就不会驱动框架注册广告管理器模块。挂载方法:

1. 在首个启动场景里创建一个空 GameObject(常用名 `GameFrameX`)。
2. `Add Component → GameFrameX/Advertisement`,挂上 `AdvertisementComponent`。

### 2. 在 Inspector 中正确填写 componentType

`AdvertisementComponent` 通过反射加载广告管理器,**必须**填写继承 `BaseAdvertisementManager` 的具体实现类全名(命名空间 + 类名),否则 `Utility.Assembly.GetType(componentType)` 返回 `null`,模块不会被注册。

常见实现类(以官方仓库为准):

| 平台 | 典型实现类 |
|------|-----------|
| Android | `YourNamespace.AndroidAdvertisementManager` |
| iOS | `YourNamespace.IOSAdvertisementManager` |
| WebGL 通用 | `YourNamespace.WebGLAdvertisementManager` |
| WebGL 微信小游戏 | `YourNamespace.WebGLWeChatAdvertisementManager` |
| WebGL 抖音小游戏 | `YourNamespace.WebGLDouYinAdvertisementManager` |
| WebGL 快手小游戏 | `YourNamespace.WebGLKuaiShouAdvertisementManager` |

填写要点:

- 必须是 **完整类型名**,包含命名空间。
- 类必须 `public`,且继承 `BaseAdvertisementManager`(间接实现 `IAdvertisementManager`)。
- `BaseAdvertisementManager` 自身继承 `GameFrameworkModule`,这是 `GameFrameworkEntry.GetModule<T>()` 识别模块的前提。

### 3. 确认目标平台 SDK 已安装

`componentType` 指向的实现类依赖对应平台的广告 SDK(如穿山甲、AdMob、微信小游戏广告 SDK 等)。如果只在 Android 项目里挂载了 WebGL 平台的管理器,Android 出包仍会找不到实现,触发同一条错误。处理方式:

- 安装目标平台对应的 SDK 包(`Packages/manifest.json` 或 `.unitypackage`)。
- 或者暂时在 Inspector 里把 `componentType` 切到已安装平台的实现。

### 4. 检查代码剥离与程序集包含

iOS / IL2CPP 构建会做托管代码剥离,可能被错误移除。两种处理方式:

- Project Settings → Player → Other Settings → `Managed Stripping Level` 设为 `Low` 或更低。
- 或者在 `Assets/link.xml` 中显式保留管理器所在程序集:

```xml
<linker>
  <assembly fullname="YourAdvertisementImpl" preserve="all"/>
</linker>
```

### 5. 检查 `m_config` 与广告位 ID

报错本身与配置无关,但 `Start()` 会调用 `_advertisementManager.Initialize(m_config)`,如果此时管理器为空(`_advertisementManager == null`),会立刻 `NullReferenceException`。因此管理器恢复后,请同时确认:

- 当前平台对应的 `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` 已填写。
- `m_config`(`AdvertisementConfig` 实例)不为 `null`,否则 `Start` 中初始化会被跳过:

```csharp
// Runtime/Advertisement/AdvertisementComponent.cs#L120-L126
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

## 验证

按上述步骤修复后,做以下检查确认问题解决:

1. 运行游戏,Console 不再出现 `Advertisement manager is invalid.`。
2. 在 `Awake` 之后打断点,确认 `_advertisementManager != null`。
3. 检查 `Start` 中 `_advertisementManager.Initialize(m_config)` 能正常进入并完成广告 SDK 初始化回调。
4. 调用一次广告播放接口(如激励视频),能正常返回展示结果。

## 常见错误

- **只填类名不写命名空间**:`Utility.Assembly.GetType(componentType)` 返回 `null`,模块不会被注册。
- **管理器类没有继承 `BaseAdvertisementManager`**:即使实现了 `IAdvertisementManager`,也不会作为 `GameFrameworkModule` 注册。
- **多平台切换时未更新 `componentType`**:从 Android 切到 iOS 出包时,`componentType` 仍指向 Android 实现类,导致管理器缺失。
- **重复挂载多个 `AdvertisementComponent`**:`[DisallowMultipleComponent]` 会阻止重复挂载,但场景里如果出现多个 GameObject 各挂一份,只有先 `Awake` 的那个会生效。
