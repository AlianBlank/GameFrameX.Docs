# Procedure パッケージのインストール

本ガイドでは、`com.gameframex.unity.procedure` を Unity プロジェクトにインストールして、FSM ベースのゲームフロー管理機能を有効化する方法を説明します。インストール完了後は、`ProcedureComponent`、`ProcedureManager`、`ProcedureBase` を使用してゲームライフサイクルの各段階を駆動できます。

## 前提条件

- Unity **2019.4** 以降(本パッケージが宣言する Unity バージョンについては [package.json](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/package.json#L7) を参照)。
- プロジェクトには `com.gameframex.unity`(`2.5.1`)と `com.gameframex.unity.fsm`(`1.2.0`)の 2 つの依存関係が必要です。本リポジトリからのインストール方法を使用する場合、Unity Package Manager が自動的に依存関係を解決して取得します。

```json
"dependencies": {
  "com.gameframex.unity.fsm": "1.2.0",
  "com.gameframex.unity": "2.5.1"
}
```
出典: [package.json](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/package.json#L22-L25)

## 操作手順

いずれかの方法を選択してインストールを完了してください。

### 方法 1:Scoped Registry(UPM レジストリ)

1. Unity プロジェクトの `Packages/manifest.json` を開きます。
2. ファイルの最上位に `scopedRegistries` ノードを追加し、`dependencies` に本パッケージを追加します:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.procedure": "1.4.1"
  }
}
```

3. 保存後 Unity に戻ると、Package Manager が自動的に `GameFrameX` レジストリから `com.gameframex` で始まるパッケージを解決します。

> `scopes` はどのパッケージがそのレジストリを経由するかを決定し、`com.gameframex.*` のみを解決するため、他のソースには影響しません。

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L57-L75)

### 方法 2:Git URL 依存

`Packages/manifest.json` の `dependencies` ノードに Git リモートアドレスを直接追加します:

```json
{
  "dependencies": {
    "com.gameframex.unity.procedure": "https://github.com/gameframex/com.gameframex.unity.procedure.git"
  }
}
```

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L77-L82)

### 方法 3:Unity Package Manager で Git URL を追加

1. Unity を開き、メニューの `Window > Package Manager` を選択します。
2. 左上隅の `+` をクリックし、`Add package from git URL...` を選択します。
3. アドレスを入力: `https://github.com/gameframex/com.gameframex.unity.procedure.git`、`Add` をクリックします。

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L83-L83)

### 方法 4:Packages ディレクトリに直接配置

本リポジトリを直接クローンまたはダウンロードして、Unity プロジェクトの `Packages/` ディレクトリ(例: `Packages/com.gameframex.unity.procedure`)に配置します。Unity が自動的にローカルパッケージとして認識してロードします。

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L84-L84)

## よくあるバリエーション

- **特定バージョンの固定**:manifest で `"com.gameframex.unity.procedure": "1.4.1"` のように正確なバージョン番号を指定し、自動アップグレードによってフロー処理が壊れるのを防ぎます。`package.json` の現在のバージョンは `1.4.1` です。
- **Git タグ/ブランチへの固定**:Git URL 形式の後ろに `#1.4.1` または `#main` を追加します。例: `https://github.com/gameframex/com.gameframex.unity.procedure.git#1.4.1`。ロールバックや開発ブランチの追跡に便利です。
- **ローカルパスでのデバッグ**:リポジトリをローカルパスパッケージとして manifest に記述します(`"file:../com.gameframex.unity.procedure"`)。開発と並行したデバッグが容易になります。

## よくあるエラー

- **`scopedRegistries` を宣言せずに直接依存関係を記述**:UPM がデフォルトの npm から `com.gameframex.*` を解決しようとしてインストールに失敗します。先に方法 1 に従ってレジストリを追加してから依存関係を記述してください。
- **scope の記述ミス**:`com.gameframex` を使用する必要があり、`package.json` の `name` プレフィックスと一致している必要があります。一致していないとパッケージはそのレジストリから解決されません。
- **複数の ProcedureComponent コピーの同時導入**:`Packages/` 内に本パッケージのソースが 1 つだけ存在することを確認し、`Already exist FSM` のような競合を避けてください。
- **Unity バージョンが低すぎる**:`unity` フィールドは `2019.4` と宣言されており、これより低いバージョンの Unity ではパッケージ内のスクリプトをコンパイルまたは実行できない可能性があります。

## 検証

1. Unity で `Window > Package Manager` を開き、リストに `Game Frame X Procedure` が表示され、バージョンが想定通りであることを確認します。
2. プロジェクト内で任意の C# スクリプトを作成し、`using GameFrameX.Procedure;` を入力します。コンパイルが通れば、パッケージが正しく配置されています。
3. メニュー `GameFrameX > Procedure` から `ProcedureComponent` を追加し、Inspector に設定項目が表示されれば、ランタイムで利用可能です。
