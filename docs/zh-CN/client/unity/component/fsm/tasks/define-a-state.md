# 如何定义一个状态

在 GameFrameX FSM 中,状态通过继承抽象基类 `FsmState<T>` 实现。`T` 是状态机的持有者类型,继承后重写生命周期回调即可完成状态定义。

## 前置条件

- 已引入 `GameFrameX.Fsm.Runtime` 程序集,可在 Unity 工程中直接引用。
- 已有一个持有者类型 `T`(必须为 `class`),用于后续创建状态机。

## 操作步骤

1. **确定状态机持有者类型**

   例如角色控制器 `Player`,将其作为泛型参数 `T`。

2. **继承 `FsmState<T>` 并实现所需回调**

   `FsmState<T>` 是抽象基类,提供 `OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy` 六个生命周期钩子,均为 `protected internal virtual`,按需重写即可。

   ```csharp
   using GameFrameX.Fsm.Runtime;

   public class IdleState : FsmState<Player>
   {
       protected internal override void OnEnter(IFsm<Player> fsm)
       {
           // 进入待机状态时的逻辑
       }

       protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           // 每帧轮询逻辑
       }

       protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
       {
           // 离开待机状态时的逻辑
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L41-L108)

3. **在状态内部触发状态切换**

   通过基类提供的 `ChangeState<TState>(IFsm<T> fsm)` 切换到另一个状态:

   ```csharp
   protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
   {
       if (/* 触发条件 */)
       {
           ChangeState<RunState>(fsm);
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

4. **将状态加入状态机**

   创建状态机时通过 `CreateFsm<T>` 的 `params FsmState<T>[]` 参数传入,或创建后调用 `AddState` 动态加入:

   ```csharp
   var fsm = FsmComponent.Instance.CreateFsm(player, new IdleState(), new RunState());
   // 或
   fsm.AddState(new RunState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L205-L220)

## 生命周期回调一览

| 回调 | 触发时机 | 典型用途 |
|------|---------|---------|
| `OnInit(IFsm<T> fsm)` | 状态首次加入状态机时 | 初始化内部数据 |
| `OnEnter(IFsm<T> fsm)` | 进入该状态时 | 播放动画、设置标志位 |
| `OnUpdate(IFsm<T> fsm, float, float)` | 每帧轮询 | 检测转换条件 |
| `OnFixedUpdate(IFsm<T> fsm, float, float)` | 固定时间步轮询 | 物理相关逻辑 |
| `OnLeave(IFsm<T> fsm, bool isShutdown)` | 离开该状态时 | 清理状态、还原标志位;`isShutdown` 表示是否因状态机关闭触发 |
| `OnDestroy(IFsm<T> fsm)` | 状态销毁时 | 释放资源 |

## 常见变体

- **空状态壳**:若仅用于占位或分组,可不重写任何方法,如下方测试用例:

  ```csharp
  private class TestIdleState : FsmState<object>
  {
  }
  ```

  Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L128-L130)

- **按类型切换状态**:除泛型 `ChangeState<TState>` 外,基类还提供 `ChangeState(IFsm<T>, Type)` 重载,适合根据外部配置动态切换:

  ```csharp
  ChangeState(fsm, typeof(RunState));
  ```

  Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

## 常见错误

- **重复添加相同类型的状态**:状态机以类型为键存储状态,重复 `AddState` 同一类型会抛出 `GameFrameworkException`。
- **在状态切换时传入错误类型**:`ChangeState(fsm, stateType)` 会校验 `stateType` 必须派生自 `FsmState<T>`,否则抛出 `GameFrameworkException("State type '...' is invalid.")`。
- **直接调用 `ChangeState` 但 `fsm` 已无效**:基类会抛出 `GameFrameworkException("FSM is invalid.")`。

## 背景(可选)

`FsmState<T>` 抽象类仅暴露钩子和状态切换能力,不持有任何运行期数据——所有跨状态共享的数据通过 `IFsm<T>` 上的 `GetData` / `SetData` 访问。这样可以让状态实现保持轻量、易测试。
