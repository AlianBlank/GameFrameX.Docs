# Editor で外部 APK/カスタムディレクトリから初期化(Android ビルドのテスト)

Unity Editor で外部 APK ファイルまたはカスタムディレクトリから `BlankReadAssets` を初期化し、実機ビルドを行わずに Android StreamingAssets の読み取り動作をシミュレートします。AssetBundle、ホットアップデートリソース、Android 専用パスのロジックをローカルデバッグするために使用します。

## 前提条件

- プロジェクトに `GameFrameX.ReadAssets` パッケージが導入されており、`Runtime/BlankReadAssets.cs` が存在する。
- `UNITY_EDITOR` でのみ有効:この 2 つの API は `#if UNITY_EDITOR` で囲まれており、実機ビルドには含まれません。
- テスト対象の APK は StreamingAssets が `assets/` にある標準的な Android パッケージ(Unity のデフォルトエクスポート形式)である必要があります。

## 操作手順

`BlankReadAssets` は Editor 専用の 2 つのエントリポイントを公開しており、デバッグ対象に応じてどちらかを選択します。

### 方法 A:外部 APK で初期化

```csharp
using GameFrameX.ReadAssets.Runtime;

// 形式:Application.dataPath + "/../test.apk"
BlankReadAssets.InitializeWithExternalApk(apkPath);
```

ソースコードのエントリとシグネチャ:

```csharp
[Preserve]
public static void InitializeWithExternalApk(string apkPath)
{
    BlankReadAssetsImpl.ApkMode = true;
    BlankReadAssetsImpl.Initialize(apkPath, "jar:file://" + apkPath + "!/assets/");
    s_initialized = true;
}
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

この呼び出しにより `EditorImpl.ApkMode` が `true` に設定され、その後の `FileExists` / `OpenRead` / `ReadAllBytes` / `GetFiles` はすべて `ApkImpl`(つまり APK 内の `jar:file://...!/assets/` パスを読み取る)を経由するようになります。

### 方法 B:カスタムディレクトリで初期化

```csharp
using GameFrameX.ReadAssets.Runtime;

// dataPath:StreamingAssets のファイルシステム上の親ディレクトリルート
// streamingAssetsPath:StreamingAssets 自身の実際のパス(任意のディレクトリが使用可能)
BlankReadAssets.InitializeWithExternalDirectories(dataPath, streamingAssetsPath);
```

ソースコードのエントリとシグネチャ:

```csharp
[Preserve]
public static void InitializeWithExternalDirectories(string dataPath, string streamingAssetsPath)
{
    BlankReadAssetsImpl.ApkMode = false;
    BlankReadAssetsImpl.Initialize(dataPath, streamingAssetsPath);
    s_initialized = true;
}
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

ビルド済みの StreamingAssets を任意のディレクトリにコピーした後、Editor で「ファイルディレクトリ」形式として直接読み取りをシミュレートする場合に適しています。

### ステップ 3:読み取り API を呼び出して検証

```csharp
if (BlankReadAssets.FileExists("config/game.json"))
{
    byte[] bytes = BlankReadAssets.ReadAllBytes("config/game.json");
    // または AssetBundle を読み取る
    var bundle = BlankReadAssets.LoadAssetBundle("bundles/ui.bundle");
}
```

初期化フラグ `s_initialized` は 1 回呼び出された後に `true` に設定され、その後のすべての API で再度初期化されることはありません。

## よくあるバリエーション

| シナリオ | 推奨方法 | 説明 |
|------|----------|------|
| 実際の Android ビルドの StreamingAssets 読み取りを検証 | 方法 A(APK) | パスプレフィックスは `jar:file://<apk>!/assets/` で固定され、実機と一致する |
| ローカルの StreamingAssets ディレクトリでデバッグ | 方法 B(カスタムディレクトリ) | `streamingAssetsPath` はプロジェクトの `Assets/StreamingAssets` 以外のカスタムディレクトリを指す |
| `Awake` 前にプリウォーム | どちらかを手動で呼び出す | `s_initialized = true` が設定されるため、その後の `EnsureInitialized` でモードが再設定されることはない |

モードを切り替える場合(APK ↔ カスタムディレクトリ)は、対応する初期化メソッドを再度呼び出す必要があります。`ApkMode` は静的フラグであるためです。

## よくあるエラー

- Player ビルドでこれらの 2 つのメソッドを呼び出す:`#if UNITY_EDITOR` で除外されるため、コンパイル失敗または実行時にシンボルが見つからないエラーが発生する。
- モード切り替え後に再度初期化するのを忘れる:前回の呼び出しの `ApkMode` が `true` のままになり、すべての読み取りが引き続き APK ブランチを経由する。
- `InitializeWithExternalApk` に存在しない APK パスを渡す:`ApkImpl.Initialize` はエラーを主动的にスローしませんが、その後の `FileExists` / `OpenRead` でファイルが見つかりません。先に `File.Exists(apkPath)` で自己チェックする必要があります。
- `Application.streamingAssetsPath` と APK 内部パスを混同する:APK モードでは `streamingAssetsPath` は内部的に `jar:file://...!/assets/` に置き換えられるため、`Application.streamingAssetsPath` を手動で渡してはいけない。

## 背景(オプション)

Editor 内の `BlankReadAssetsImpl` は条件付きコンパイルで実装を選択します。`UNITY_EDITOR` は `EditorImpl`、Android は `ApkImpl`、その他の平台は `LooseFilesImpl` を経由します。`EditorImpl` は内部で `ApkMode` フラグに応じてリクエストを `ApkImpl` または `LooseFilesImpl` に転送し、エディタプロセス内で異なるプラットフォームの読み取り動作をシミュレートします。
