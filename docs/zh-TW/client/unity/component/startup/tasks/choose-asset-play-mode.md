# 如何選擇資源執行模式（PlayMode）

資源執行模式（`EPlayMode`）決定 YooAsset 在啟動時載入資產的方式。只需在 `StartupOptions` 資產中設定 `GamePlayMode` 欄位，啟動流程就會在載入資源前自動同步至 `AssetComponent`。

## 前置條件

- 已透過 `GameFrameX/Startup Options` 選單建立 `StartupOptions` 資產。
- 已安裝 `GameFrameX.Asset` 元件並註冊至 `GameEntry`（框架會預設註冊）。
- 專案中使用 YooAsset（框架的 `EPlayMode` 隸屬於 `YooAsset` 命名空間）。

## 操作步驟

1. 在專案中開啟 `StartupOptions` 資產（位於 `Assets/` 下任意位置）。
2. 找到 **Asset** 分類下的 **GamePlayMode** 欄位。
3. 選擇所需的列舉值。主要值與用途請參考下表。

| 列舉值 | 意義 | 常見情境 |
|---|---|---|
| `EditorSimulateMode` | 編輯器模擬模式，直接讀取專案內的 AssetDatabase 資源，不經過資源包 | Unity Editor 內的純本機除錯 |
| `OfflinePlayMode` | 離線模式，載入已建置的本機資源包，不連線至網路 | 獨立發佈、無後端的內部網路 |
| `HostPlayMode` | 主機模式，從遠端 CDN 下載資源包 + 使用本機快取 | 一般可熱更新的行動裝置/PC 發佈 |
| `WebPlayMode` | Web 模式，適用於 WebGL 的資源載入 | WebGL 平台 |

欄位定義位置（含原始碼連結）：

```csharp
[Header("Asset")] [Tooltip("资源运行模式。启动流程会在加载资源前同步到 Asset 组件。")]
public EPlayMode GamePlayMode = EPlayMode.EditorSimulateMode;
```

來源：[StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L19-L20)

啟動時框架會讀取該欄位並同步至 `AssetComponent`：

```csharp
private static void ApplyAssetPlayMode(StartupOptions options)
{
    GameEntry.GetComponent<AssetComponent>().GamePlayMode = NormalizeAssetPlayMode(options.GamePlayMode);
}
```

來源：[StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L127-L130)

## 常見變化

### 在編輯器中選擇 EditorSimulateMode，建置後自動變更

在編輯器內除錯時通常選擇 `EditorSimulateMode`。`NormalizeAssetPlayMode` 會在非 Editor 環境中自動將其降級為 `HostPlayMode`，因此無需手動切換。

```csharp
private static EPlayMode NormalizeAssetPlayMode(EPlayMode playMode)
{
#if !UNITY_EDITOR
    if (playMode == EPlayMode.EditorSimulateMode)
    {
        playMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    playMode = EPlayMode.WebPlayMode;
#endif
#endif
    return playMode;
}
```

來源：[StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L132-L144)

### 流程分支區分：Offline 與 EditorSimulate

啟動流程中不同的 `PlayMode` 會遵循不同的更新/修補路徑，因此無需在業務程式碼中手動判斷：

- `OfflinePlayMode`：在 [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L42) 中跳過遠端清單更新。
- `EditorSimulateMode`：在 [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L71) 中遵循模擬清單分支。

### 在 WebGL 中強制切換為 WebPlayMode

只要編譯目標是 WebGL，無論設定為何，`NormalizeAssetPlayMode` 都會強制變更為 `WebPlayMode`（參考上方程式碼片段中的 `#if UNITY_WEBGL` 區塊）。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|---|---|---|
| 玩家建置啟動後找不到資源 | 誤以為 `EditorSimulateMode` 也能用於發佈建置 | 在非 Editor 環境中會自動降級為 `HostPlayMode`，請確認 CDN URL 與資源包版本流程已正確設定 |
| 在 WebGL 中載入資源失敗 | 仍持續使用 `HostPlayMode` 等非 Web 模式 | 將編譯目標切換為 WebGL 後，框架會自動變更為 `WebPlayMode`，無需手動修改 |
| 已設定離線模式卻仍嘗試連線網路 | 將 `OfflinePlayMode` 設定於需要熱更新的情境 | 僅在無後端/獨立執行的情境下使用 `OfflinePlayMode` |
| 在 `StartupOptions` 中找不到 `GamePlayMode` 欄位 | 未使用最新資產或欄位名稱已變更 | 透過 `GameFrameX/Startup Options` 重新產生資產 |

## 背景（選擇性）

欄位名稱 `GamePlayMode` 旨在避免與 `AssetComponent` 內建的同名屬性衝突。由於預設值為 `EditorSimulateMode`，開發者可在 Unity Editor 中直接執行完整流程，而建置後 `NormalizeAssetPlayMode` 會自動降級為可發佈的模式，防止「開發者便利性」被錯誤地納入玩家建置中。`StartupOptions` 透過 `[CreateAssetMenu]` 以 SO 形式在專案中直接維護管理。
