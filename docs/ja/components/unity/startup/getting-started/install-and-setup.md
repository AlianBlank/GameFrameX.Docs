# GameFrameX Startup パッケージのインストールと設定

本ガイドでは、GameFrameX Startup パッケージを Unity プロジェクトに組み込み、初回実行に必要な最小限の設定（scoped registry の宣言、`StartupOptions` アセットの作成、UI とホットフィックスの注入インターフェースの実装）を完了させます。完了後、`await StartupRunner.Run(...)` を呼び出すことで完全なスタートアップフローを起動できます。

## 前提条件

- Unity 2019.4 以上（[package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L7) の `unity` フィールドを参照）
- プロジェクトで UniTask などの GameFrameX シリーズの依存関係が有効になっていること（同一リポジトリの npm レジストリ経由で自動解決されるため、手動での宣言は不要）
- ネットワークから GameFrameX のプライベート npm レジストリ `https://gameframex.upm.alianblank.uk` にアクセスできること

## 操作手順

### 1. manifest.json にパッケージと scoped registry を追加

プロジェクト配下の `Packages/manifest.json` を開き、パッケージの依存関係と scoped レジストリを両方追加します（`scopes` が `com.gameframex` に限定されている場合のみ、このレジストリが使用されます）：

```json
{
  "dependencies": {
    "com.gameframex.unity.startup": "1.1.0"
  },
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ]
}
```

出典： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L22-L37)

保存すると、Unity Package Manager が `package.json` にリストされたすべての依存関係を自動的に取得します（[package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L28-L40)）。

### 2. StartupOptions 設定アセットの作成

Unity Editor で `Assets > Create > GameFrameX > Startup Options` を選択し、`StartupOptions` ScriptableObject アセットを生成します。

最小限で入力が必要なフィールド：

| フィールド | 説明 |
|------|------|
| `GlobalInfoUrls` | グローバル情報インターフェースのプライマリ／バックアップ URL リスト（順次フェイルオーバー） |
| `GamePlayMode` | リソース実行モード（スタートアップフローはリソースをロードする前に Asset コンポーネントへ同期します） |
| `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` | ホットフィックス入口のアセンブリ / 型 / メソッド |
| `PackageName` / `Channel` / `SubChannel` | HTTP 共通パラメータ |
| `LauncherUIResName` | スタートアップ UI のリソースパス（デフォルトは `UI/UILauncher`） |
| `SkipRemoteStartupRequests` | true の場合、すべてのリモートスタートアップリクエスト（グローバル情報 / App バージョン / リソースパッケージバージョン）をスキップします。WebGL スタンドアロンやバックエンドなしのデプロイに適しています |

フィールドの定義と説明は [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L1-L120) を参照してください。

### 3. UI ハンドラーの実装（IStartupUIHandler）

UI バックエンドは問わず、FairyGUI / UGUI / カスタム実装のいずれでも使用できます。以下のメンバーを実装する必要があります：

```csharp
public class GameStartupUIHandler : IStartupUIHandler
{
    public UniTask StartAsync(string uiResName) { /* UI をロード */ }
    public void SetTipText(string text) { /* ヒントテキストを更新 */ }
    public void SetProgress(float progress, string sizeInfo) { /* プログレスバーを更新 */ }
    public void SetProgressUpdateFinish() { /* 完了をマーク */ }
    public void Dispose() { /* UI を閉じ、購読を解放 */ }
}
```

出典： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L57-L65)

### 4. ホットフィックスランチャーの実装（IHotfixLauncher）

ホットフィックス方式は問わず、HybridCLR やその他の方式に対応しています。`options` に指定されたアセンブリ / 型 / メソッド名に従ってロードして呼び出します：

```csharp
public class HybridClrHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        // options.HotfixAssemblyName に従ってホットフィックスアセンブリをロード
        // options.HotfixEntryTypeName.options.HotfixEntryMethodName を呼び出し
        return HotfixLaunchResult.Succeed();
    }
}
```

出典： [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L70-L78)

### 5. スタートアップの実行

ゲームのエントリースクリプトで `StartupRunner.Run(options, uiHandler, hotfixLauncher)` を呼び出し、返される `UniTask<StartupResult>` を待機するか、`StartupCompleted` / `FailedEventArgs` イベントを購読するだけで済みます。

エントリーポイントの位置は [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L1-L80) を参照してください。

## よくあるバリエーション

- **WebGL / スタンドアロンのデプロイ**：`SkipRemoteStartupRequests` を `true` に設定すると、グローバル情報 / App バージョン / リソースパッケージバージョンの 3 つのリモートリクエストをスキップできます。
- **PlayMode の切り替え**：対象プラットフォームに応じて `StartupOptions.GamePlayMode` で `EditorSimulateMode` / `OfflinePlayMode` / `HostPlayMode` / `WebPlayMode` を選択すると、スタートアップフローが自動的に分岐処理を行います。
- **プライベート npm レジストリ**：パッケージの `publishConfig.registry` は `https://npm.cnb.cool/GameFrameX/npm/-/packages/` を指しています（[package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L41-L44) を参照）。独自のリリースパイプラインを構築する場合にのみ注意が必要です。

## よくあるエラー

| 症状 | 考えられる原因 | 修正方法 |
|------|----------|------|
| Package Manager で `com.gameframex.unity.startup` が見つからない | `scopedRegistries` が宣言されていない、または `scopes` の記述が誤っている | `scopes` に `com.gameframex` が含まれ、URL が `https://gameframex.upm.alianblank.uk` であることを確認 |
| スタートアップが「グローバル情報の取得」で止まる | `GlobalInfoUrls` がすべて失敗し、`MaxAttemptsPerUrl` を使い切った | URL の到達可能性を確認し、必要に応じてリトライ回数を増やす |
| ホットフィックス入口がトリガーされない | `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` が実際のアセンブリと一致しない | 3 つすべてがホットフィックス DLL 内の名前空間.クラス.メソッド名と完全に一致している必要がある |
| WebGL デプロイ時にバックエンドへのリクエストが失敗する | `SkipRemoteStartupRequests` が有効になっていない | スタンドアロンのデプロイ環境では `true` に設定する |

## 背景

パッケージ名は `com.gameframex.unity.startup`、現在のバージョンは 1.4.3 です（[package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L1-L6)）。設計方針：可変項目を `StartupOptions` アセットと 2 つのインターフェース（`IStartupUIHandler` / `IHotfixLauncher`）に集約し、業務プロジェクト側は UI とホットフィックス両側の注入を実装するだけで済みます。
