# ビルド設定が反映されない場合の対処方法

`XCodeConfig.json` に記述したビルド設定、Plist、署名、Capabilities が出力された Xcode プロジェクトに反映されていない場合、通常は次のいずれかです:設定ファイルが見つかっていない、JSON の解析に失敗した、他の同名設定やチャネル設定によって上書きされた、または対象ノードの記述を間違えた。本ページでは、ログの手がかりに沿って原因を一つずつ特定し、修正します。

すべての設定のエントリポイントは [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L25) の `OnPostProcessBuild` です。`[PostProcessBuild(888)]` の優先度で、`BuildTarget.iOS` のときのみ実行され、ファイル全体が `#if UNITY_IOS` の条件付きコンパイル配下にあります。内部で発生した例外はすべて `Debug.LogException` によって握りつぶされ、**ビルドは失敗せず、サイレントにスキップされるだけ**なので、まず最初に Unity Console を確認してください。

## 修正手順

### 修正 1:設定ファイルが見つかることを確認

読み込みロジックは [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58-L77) にあります。すべての `t:textasset` リソースを走査し、**ファイル名が `XCodeConfig.json` と完全に一致する**(大文字・小文字は区別しない)ファイルのみにマッチします。配置ディレクトリは関係ありません。

1. ファイル名が正確に `XCodeConfig.json` であることを確認してください(`XCodeConfig.json.txt`、`xcodeconfig.json.bak` では不可)。
2. ファイルが Unity にインポート済みであることを確認してください:Project ウィンドウで選択すると Inspector に Text Asset と表示されるはずです。ディレクトリには同名の `.meta` ファイルが存在するはずです。
3. iOS ビルドであることを確認してください:`OnPostProcessBuild` では `target != BuildTarget.iOS` の場合すぐに return します([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L17-L20)を参照)。
4. 現在のプラットフォームマクロが `#if UNITY_IOS` を満たしていることを確認してください──プロジェクトが一度も iOS プラットフォームに切り替えられていなければ、アセンブリ全体の内容はコンパイルに含まれません。

### 修正 2:JSON 構文を検証する

各ファイルは `json.HashtableFromJson()` で解析され、失敗した場合は `解析失败, 跳过合并` を出力して continue します([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L39-L45)を参照)。パーサーは軽量な実装であり、コメント、末尾カンマ、シングルクォート文字列はサポートしていません。任意の JSON バリデーター(VS Code の JSON 言語サービスなど)でファイルをチェックし、エラーログに出力された `{jsonPath}` がどのファイルかを重点的に確認してください。

### 修正 3:同名ファイルによる上書きを調査する

ツールはプロジェクト内の `XCodeConfig.json` という名前のファイルを**すべて**収集し、ソートして順にマージします([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L34-L49)を参照):

```csharp
Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    ...
    finalConfig.Merge(table);
}
```

ソース: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L35-L49)

1. Console で `[MergeConfig] 正在合并配置:` を検索すると、ログにマージに参加する各ファイルのパスと順序が列挙されます。
2. サードパーティ製プラグインが `XCodeConfig.json` を同梱している場合、後にマージされる同名キーがあなたの値を上書きします──削除、リネーム(リネームすればマージ対象から外れます)、または自分の値をチャネルファイルへ移動(チャネルファイルは最後にマージされます)のいずれかを行ってください。

### 修正 4:チャネル設定と残留チャネルを確認する

チャネル識別子の読み取り順序は、コマンドライン引数 `-channel` → EditorPrefs キー `XCodeBuild_Channel` → null です([SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)を参照):

```csharp
public static string GetChannel()
{
    var args = Environment.GetCommandLineArgs();
    for (int i = 0; i < args.Length - 1; i++)
    {
        if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
        {
            return args[i + 1];
        }
    }

    string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
    if (!string.IsNullOrEmpty(editorChannel))
    {
        return editorChannel;
    }

    return null;
}
```

ソース: [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)

1. チャネルファイルの命名は `XCodeConfig.{channel}.json`(`XCodeConfig.ioschina.json` など)でなければなりません([SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111)を参照)。
2. チャネルファイルは最後にマージされ、上書きの優先度が最も高い──「期待した値が書き換えられていた」場合は、まずどこかのチャネルファイルにヒットしていないか確認してください。Console には `[MergeConfig] 检测到渠道: {channel}` と `[MergeConfig] 正在合并渠道配置: {path}` が出力されます。
3. **EditorPrefs はプロジェクトやセッションをまたいで残留します**。以前 `SetChannel("xxx")` で設定したチャネルは次回のビルド時にも有効のままなので、意図しないチャネル設定がマージされることがあります。消去方法:空文字列を渡して該当キーを削除します([SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51)を参照)。

```csharp
GameFrameX.Xcode.Editor.SettingLoader.SetChannel(null); // または空文字列を渡して、残留チャネルをクリアする
```

ソース: [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51)

### 修正 5:キーの構造を確認する

第 1 フェーズでは、決められた最上位キーのみを読み取り、対象に振り分けます([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L126)を参照):

| 最上位キー | 書き込み先 | 説明 |
|------|---------|------|
| `unityMain` | UnityMain(メイン)target | properties / frameworks / libs / files / folders / filesCompileFlag / otherLinkerFlag / runPathSearchPaths / pods |
| `unityFramework` | UnityFramework target | 同上 |
| `signing` | メイン target | 署名。同時に `bundleId` を取得して Capabilities に使用 |
| `plist` | Info.plist | `RunPlist` を参照 |
| `environmentVariables` | scheme の環境変数 | `RunEnvironmentVariables` を参照 |
| `launcherArgs` | scheme の起動引数(配列) | `RunArgument` を参照 |
| `capabilities` | メイン target | Capabilities |
| `localizations` | プロジェクト(配列) | ローカライズリソース |
| `podfile` / `podSource` | Podfile | 完全な Podfile パス / ソースアドレスのリスト |
| `swiftBridging` | bool、デフォルト true | Swift ブリッジング |
| `podInstall` | bool、デフォルト true | `pod install` を自動実行するかどうか |

`properties` の内部はさらに `"="`(直接 set)、`"+"`(リストへの追加)、`"-"`(リストからの削除)の 3 つのサブテーブルで処理されます([PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L57)を参照):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}
```

ソース: [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L20-L25)

よくある記述ミス:`properties` を `unityMain.properties` 配下ではなく最上位に置く。`"+"` に入れるべきリスト値を `"="` に書いてしまう。キー名のスペルの大文字・小文字が一致していない(Hashtable のキーは大文字・小文字を区別します)。

### 修正 6:例外スタックトレースを読み取る

フロー全体は `try/catch` で囲まれており、例外は `Debug.LogException` するだけでビルドを中断しません([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L158-L161)を参照)。Console に例外が出た場合、例外発生箇所の**後**のすべての設定は実行されません──例えば `plist` の前に例外が投げられると、`capabilities`、`podfile`、`pod install` はすべてスキップされます。スタックトレースから該当キーを特定してください。多くは型不一致(オブジェクトを配列に書いた、文字列を数値に書いた)です。

### 修正 7:より高い優先度のプラグインによる上書きを排除する

本ツールは `[PostProcessBuild(888)]` で実行され、大半の後処理より後に動作します([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L15)を参照)。他のプラグインのコールバックの優先度が 888 より大きい場合、または本ツールが書き込んだ後の内容に基づかずに `project.pbxproj` / Info.plist を直接編集した場合、設定が上書きされてしまいます。また、Capabilities は `ProjectCapabilityManager` によって独立して書き込まれ、本ツールはその後で `project.pbxproj` を再読み込みしてから Localization の書き込みを続けます([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L121-L123)を参照)。この後にサードパーティのコードがプロジェクトファイルを書き換えていないことを確認してください。

## 検証

1. iOS ビルドをもう一度実行すると、Console に以下が順に出力されるはずです:
   - 参加する各ファイルの `[MergeConfig] 正在合并配置: {path}`;
   - チャネルがある場合:`[MergeConfig] 检测到渠道: {channel}`;
   - `[PBXProject] 正在应用最终合并配置...` と `[OtherSettings] 正在应用最终合并配置...`;
   - 赤い例外が一切出ないこと。
2. 出力ディレクトリの `Unity-iPhone.xcodeproj/project.pbxproj` を開き、設定したビルド属性名を検索して、値が更新されていることを確認します。
3. `Info.plist` の `plist` ノードで書き込まれたキーと値を確認します。
4. Xcode でメインの target を選択すると、Signing & Capabilities ページに `capabilities` で設定した項目が表示され、`project.entitlements` に対応するエントリが存在するはずです。
