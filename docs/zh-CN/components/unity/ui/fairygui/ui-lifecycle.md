# 工作原理：界面生命周期与加载队列

本页说明调用 `UIManager` 打开一个 FairyGUI 界面后，框架内部依次发生什么：单例去重 → 实例池复用 → 异步加载队列 → 生命周期回调 → 分组刷新，以及关闭时的回收逻辑。理解这条链路，可以解释"为什么重复打开同一界面不会加载两次""为什么关闭后界面不立即销毁"等现象。

## 打开界面时的生命周期时序

`InternalOpenUIForm` 是所有界面（无论新加载还是池复用）真正"诞生"的地方，回调按以下顺序执行，全部来自真实源码：

1. `m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData)` 创建 `IUIForm`；返回 `null` 时抛出 `GameFrameworkException("Can not create UI form in UI form helper.")`。
2. `uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen)` 完成初始化；其中 `OnInitAction` 会在初始化回调里为 `FUI` 类型界面调用 `fui.SetGObject(uiFormInstance as GObject)` 绑定 GObject。
3. 界面加入 UI 分组：若 `uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm)` 为假，则 `uiGroup.AddUIForm(uiForm)`。
4. `uiForm.OnOpen(userData)` —— 业务侧在打开瞬间收到的回调。
5. `uiForm.BindEvent()`、`uiForm.LoadData()`、`uiForm.UpdateLocalization()` 依次执行。
6. 若 `uiForm.EnableShowAnimation` 为真，`uiForm.Show(m_UIFormShowHandler, null)` 播放显示动画（见下文 FUI 的 `Show` 实现）。
7. `uiGroup.Refresh()` 刷新分组深度与暂停状态。
8. 触发 `OpenUIFormSuccessEventArgs` 成功事件；任一步抛异常则触发 `OpenUIFormFailureEventArgs` 并重新抛出。

```csharp
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);

void OnInitAction(IUIForm obj)
{
    if (obj is FUI fui)
    {
        fui.SetGObject(uiFormInstance as GObject);
    }
}

if (!uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm))
{
    uiGroup.AddUIForm(uiForm);
}

uiForm.OnOpen(userData);
uiForm.BindEvent();
uiForm.LoadData();
uiForm.UpdateLocalization();
if (uiForm.EnableShowAnimation)
{
    uiForm.Show(m_UIFormShowHandler, null);
}

uiGroup.Refresh();
```

## 加载队列与去重

`InnerOpenUIFormAsync` 在真正发起加载前会做三层去重，避免同一界面被并发加载：

1. **单例模式命中已打开界面**：`UseSingletonOpenMode(uiFormType)` 为真时，先 `GetUIForm(uiFormAssetName)` 查找已打开实例，命中则 `RefocusUIForm(openedUIForm, userData)` 后直接返回，不再加载。
2. **命中加载中队列**：遍历 `m_LoadingUIForms`（容量 64 的 `List<UIFormLoadingObject>`），若资源路径、资源名、类型三者都匹配，则 `await value.Task` 复用同一次加载结果。
3. **命中实例池**：`m_InstancePool.Spawn(uiFormAssetName)` 取回可复用实例，成功则分配新的 `++m_Serial` 序列号后直接走 `InternalOpenUIForm`（`isNewInstance: false`）。

只有三层都未命中，才调用 `InnerLoadUIFormAsync` 发起真正的资源加载，并把结果包装成 `UIFormLoadingObject` 加入 `m_LoadingUIForms`；`await` 结束后在 `finally` 中移除并 `ReferencePool.Release`，保证队列不泄漏。

```csharp
foreach (var value in m_LoadingUIForms)
{
    if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
    {
        return await value.Task;
    }
}
```

## 资源加载路径：Resources 与 Bundles

`InnerLoadUIFormAsync` 每次加载分配新序列号，并登记到 `m_UIFormsBeingLoaded`，随后按路径特征分流：

- **包名推导**：取 `uiFormAssetPath` 最后一个 `/` 之后的部分作为 `packageName`；路径中没有 `/` 时整个路径即包名。
- **已加载的包**：`FairyGuiPackage.Has(packageName)` 为真则直接走 `LoadAssetSuccessCallback` 创建界面，不重复加载包。
- **Resources 目录**：`assetPath` 不包含 `Utility.Asset.Path.BundlesDirectoryName` 时，若包未加载则 `FairyGuiPackage.AddPackageSync(assetPath)` 同步加载后创建界面。
- **Bundle 目录**：包名与资源名一致时 `await FairyGuiPackage.AddPackageAsync(assetPath)`；不一致则用 `PathHelper.Combine(uiFormAssetPath, packageName)` 重拼路径异步加载，然后加载 `路径 + "_fui"` 资源（`m_AssetManager.LoadAssetAsync<UnityEngine.Object>`），成功才 `openUIFormInfo.SetAssetHandle(assetHandle)` 并创建界面。

```csharp
newAssetPackagePath += "_fui";
// 从包中加载
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

### 加载成功 / 失败回调

| 回调 | 行为 |
|------|------|
| `LoadAssetSuccessCallback` | 检查 `m_UIFormsToReleaseOnLoad`（加载期间被取消的请求则直接释放资源）；否则用 `m_UIFormHelper.InstantiateUIForm` 实例化并 `m_InstancePool.Register` 注册到实例池，再走 `InternalOpenUIForm`（`isNewInstance: true`） |
| `LoadAssetFailureCallback` | 拼接错误信息 `Utility.Text.Format("Load UI form failure, asset name '{0}', error message '{1}'.", ...)`，触发 `OpenUIFormFailureEventArgs`；无失败处理器时直接 `throw new GameFrameworkException(appendErrorMessage)` |

两处对无效 `OpenUIFormInfo` 均抛出 `GameFrameworkException("Open UI form info is invalid.")`。

## 显示 / 隐藏动画

`FUI`（FairyGUI 界面基类，继承自 `UIForm`）把可见性操作转发给关联的 `GObject`：

- `Show(handler, complete)`：有 handler 时调用 `handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete)`，否则直接 `complete?.Invoke()`。
- `Hide(handler, complete)`：对称地使用 `EnableHideAnimation` 与 `HideAnimationName`。
- `Visible`：读取 `GObject.visible`；`GObject == null` 时恒为 `false`。`InternalSetVisible` 修改 `GObject.visible` 后依次触发 `OnVisibleChanged` 回调与 `UIFormVisibleChangedEventArgs` 事件。
- `MakeFullScreen()`：`GObject?.asCom?.MakeFullScreen()`。

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

## 关闭与实例回收

`RecycleUIForm(uiForm, isDispose)` 负责关闭后的回收，步骤为：

1. `uiForm.OnRecycle()` 先触发业务回收回调。
2. 取 `uiForm.Handle as GameObject`；为空直接返回（无可回收的显示对象）。
3. 从 GameObject 上取 `DisplayObjectInfo` 组件，再取 `displayObject.gOwner as GComponent`；任一为空直接返回。
4. `m_InstancePool.Unspawn(component)` 把实例还回实例池等待复用；`isDispose == true` 时额外 `m_InstancePool.ReleaseObject(component)` 彻底销毁。

也就是说默认关闭只是"回池"，下次 `m_InstancePool.Spawn` 命中即可免加载复用；实例池回收间隔下限为 `10`（`m_RecycleInterval < 10` 时被强制改为 `10`）。

```csharp
m_InstancePool.Unspawn(component);
if (isDispose)
{
    m_InstancePool.ReleaseObject(component);
}
```

## 常见问题排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 重复打开同一界面，只有第一次走加载 | 单例模式下命中 `GetUIForm` 或 `m_LoadingUIForms` 去重 | 属预期行为；需要新实例请关闭单例打开模式 |
| 打开界面抛出 `Can not create UI form in UI form helper.` | `m_UIFormHelper.CreateUIForm` 返回 `null` | 检查 `uiFormType` 与注册的 `FairyGUIFormHelper` 是否能创建该类型 |
| 抛出 `Load UI form failure, asset name '...', error message '...'` | `_fui` 资源或 UI 包加载失败且未注册失败处理器 | 核对包名推导结果与 `uiFormAssetPath`，确认 `路径_fui` 资源存在 |
| 抛出 `Open UI form info is invalid.` | 成功/失败回调收到的 `OpenUIFormInfo` 为 `null` | 属框架内部数据异常，检查是否有外部误用回调 |
| 关闭界面后内存不降 | `RecycleUIForm` 默认仅 `Unspawn` 回池 | 需要彻底销毁时使用带 `isDispose` 的关闭路径 |
