# 動作原理：UI ライフサイクルとロードキュー

本ページでは、`UIManager` を呼び出して FairyGUI の UI を開いた後、フレームワーク内部で順次何が起こるかを説明します：シングルトン重複排除 → インスタンスプール再利用 → 非同期ロードキュー → ライフサイクルコールバック → グループ更新、およびクローズ時のリサイクルロジック。この流れを理解すると、「なぜ同じ UI を繰り返し開いても 2 回ロードされないのか」「なぜクローズ後も UI がすぐに破棄されないのか」といった現象を説明できます。

## UI を開く際のライフサイクルシーケンス

`InternalOpenUIForm` は、すべての UI（新規ロード・プール再利用を問わず）が実際に「誕生」する場所であり、コールバックは以下の順序で実行されます。すべて実際のソースコードからのものです：

1. `m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData)` が `IUIForm` を作成します。`null` を返した場合は `GameFrameworkException("Can not create UI form in UI form helper.")` をスローします。
2. `uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen)` が初期化を完了します。このうち `OnInitAction` は初期化コールバック内で `FUI` 型の UI に対して `fui.SetGObject(uiFormInstance as GObject)` を呼び出し、GObject をバインドします。
3. UI を UI グループに追加：`uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm)` が false の場合、`uiGroup.AddUIForm(uiForm)` を実行します。
4. `uiForm.OnOpen(userData)` —— ビジネス側がオープンされた瞬間に受け取るコールバックです。
5. `uiForm.BindEvent()`、`uiForm.LoadData()`、`uiForm.UpdateLocalization()` が順番に実行されます。
6. `uiForm.EnableShowAnimation` が true の場合、`uiForm.Show(m_UIFormShowHandler, null)` が表示アニメーションを再生します（下記の FUI の `Show` 実装を参照）。
7. `uiGroup.Refresh()` がグループの深度と一時停止状態を更新します。
8. `OpenUIFormSuccessEventArgs` の成功イベントを発火します。いずれかのステップで例外がスローされた場合は `OpenUIFormFailureEventArgs` を発火し、再スローします。

```csharp
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);

void OnInitAction(IUIForm obj)
{
    if (obj is FUI fui)
    {
        fui.SetGObject(uiFormInstance as GObject);
    }
}

if (!uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm))
{
    uiGroup.AddUIForm(uiForm);
}

uiForm.OnOpen(userData);
uiForm.BindEvent();
uiForm.LoadData();
uiForm.UpdateLocalization();
if (uiForm.EnableShowAnimation)
{
    uiForm.Show(m_UIFormShowHandler, null);
}

uiGroup.Refresh();
```

## ロードキューと重複排除

`InnerOpenUIFormAsync` は実際にロードを開始する前に 3 層の重複排除を行い、同じ UI が並行してロードされるのを防ぎます：

1. **シングルトンモードでオープン済み UI にヒット**：`UseSingletonOpenMode(uiFormType)` が true の場合、まず `GetUIForm(uiFormAssetName)` でオープン済みインスタンスを検索し、ヒットすれば `RefocusUIForm(openedUIForm, userData)` を実行してそのまま返り、ロードを行いません。
2. **ロード中キューにヒット**：`m_LoadingUIForms`（容量 64 の `List<UIFormLoadingObject>`）を走査し、アセットパス・アセット名・タイプの 3 つすべてが一致する場合、`await value.Task` で同じロード結果を再利用します。
3. **インスタンスプールにヒット**：`m_InstancePool.Spawn(uiFormAssetName)` で再利用可能なインスタンスを取得し、成功した場合は新しい `++m_Serial` シリアル番号を割り当てた後、直接 `InternalOpenUIForm` に進みます（`isNewInstance: false`）。

3 層すべてにヒットしなかった場合にのみ `InnerLoadUIFormAsync` を呼び出して実際のアセットロードを開始し、結果を `UIFormLoadingObject` にラップして `m_LoadingUIForms` に追加します。`await` 終了後は `finally` 内で削除して `ReferencePool.Release` を実行し、キューがリークしないことを保証します。

```csharp
foreach (var value in m_LoadingUIForms)
{
    if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
    {
        return await value.Task;
    }
}
```

## アセットロードパス：Resources と Bundles

`InnerLoadUIFormAsync` はロードのたびに新しいシリアル番号を割り当て、`m_UIFormsBeingLoaded` に登録した後、パスの特徴に応じて処理を振り分けます：

- **パッケージ名の推導**：`uiFormAssetPath` の最後の `/` 以降の部分を `packageName` として使用します。パスに `/` が含まれない場合、パス全体がパッケージ名になります。
- **ロード済みパッケージ**：`FairyGuiPackage.Has(packageName)` が true の場合は直接 `LoadAssetSuccessCallback` に進んで UI を作成し、パッケージを重複ロードしません。
- **Resources ディレクトリ**：`assetPath` に `Utility.Asset.Path.BundlesDirectoryName` が含まれない場合、パッケージが未ロードであれば `FairyGuiPackage.AddPackageSync(assetPath)` で同期ロードしてから UI を作成します。
- **Bundle ディレクトリ**：パッケージ名とアセット名が一致する場合は `await FairyGuiPackage.AddPackageAsync(assetPath)`。一致しない場合は `PathHelper.Combine(uiFormAssetPath, packageName)` でパスを再構築して非同期ロードし、その後 `パス + "_fui"` アセット（`m_AssetManager.LoadAssetAsync<UnityEngine.Object>`）をロードし、成功した場合のみ `openUIFormInfo.SetAssetHandle(assetHandle)` を実行して UI を作成します。

```csharp
newAssetPackagePath += "_fui";
// パッケージからロード
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

### ロード成功 / 失敗コールバック

| コールバック | 動作 |
|------|------|
| `LoadAssetSuccessCallback` | `m_UIFormsToReleaseOnLoad` をチェックし（ロード中にキャンセルされたリクエストはアセットを直接解放）、そうでなければ `m_UIFormHelper.InstantiateUIForm` でインスタンス化して `m_InstancePool.Register` でインスタンスプールに登録し、その後 `InternalOpenUIForm` に進みます（`isNewInstance: true`） |
| `LoadAssetFailureCallback` | エラーメッセージ `Utility.Text.Format("Load UI form failure, asset name '{0}', error message '{1}'.", ...)` を組み立てて `OpenUIFormFailureEventArgs` を発火します。失敗ハンドラーが未登録の場合は直接 `throw new GameFrameworkException(appendErrorMessage)` します |

両方の場所で、無効な `OpenUIFormInfo` に対しては `GameFrameworkException("Open UI form info is invalid.")` をスローします。

## 表示 / 非表示アニメーション

`FUI`（FairyGUI の UI 基底クラス。`UIForm` を継承）は、可視性操作を関連付けられた `GObject` に転送します：

- `Show(handler, complete)`：handler がある場合は `handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete)` を呼び出し、ない場合は直接 `complete?.Invoke()` を実行します。
- `Hide(handler, complete)`：対称的に `EnableHideAnimation` と `HideAnimationName` を使用します。
- `Visible`：`GObject.visible` を読み取ります。`GObject == null` の場合は常に `false` です。`InternalSetVisible` は `GObject.visible` を変更した後、`OnVisibleChanged` コールバックと `UIFormVisibleChangedEventArgs` イベントを順に発火します。
- `MakeFullScreen()`：`GObject?.asCom?.MakeFullScreen()`。

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

## クローズとインスタンスリサイクル

`RecycleUIForm(uiForm, isDispose)` はクローズ後のリサイクルを担当します。手順は以下の通りです：

1. `uiForm.OnRecycle()` が最初にビジネス側のリサイクルコールバックを発火します。
2. `uiForm.Handle as GameObject` を取得します。null の場合はそのまま返ります（リサイクル可能な表示オブジェクトなし）。
3. GameObject から `DisplayObjectInfo` コンポーネントを取得し、さらに `displayObject.gOwner as GComponent` を取得します。いずれかが null の場合はそのまま返ります。
4. `m_InstancePool.Unspawn(component)` でインスタンスをインスタンスプールに返して再利用を待ちます。`isDispose == true` の場合は追加で `m_InstancePool.ReleaseObject(component)` を実行して完全に破棄します。

つまり、デフォルトのクローズは「プール返却」のみであり、次回 `m_InstancePool.Spawn` がヒットすればロードなしで再利用できます。インスタンスプールのリサイクル間隔の下限は `10` です（`m_RecycleInterval < 10` の場合、強制的に `10` に変更されます）。

```csharp
m_InstancePool.Unspawn(component);
if (isDispose)
{
    m_InstancePool.ReleaseObject(component);
}
```

## よくある問題のトラブルシューティング

| 現象 | 原因 | 対処 |
|------|------|------|
| 同じ UI を繰り返し開いても、最初の 1 回しかロードされない | シングルトンモードで `GetUIForm` または `m_LoadingUIForms` の重複排除にヒット | 期待される動作です。新しいインスタンスが必要な場合はシングルトンオープンモードを無効にしてください |
| UI を開くと `Can not create UI form in UI form helper.` がスローされる | `m_UIFormHelper.CreateUIForm` が `null` を返す | `uiFormType` と登録済みの `FairyGUIFormHelper` がそのタイプを作成できるか確認してください |
| `Load UI form failure, asset name '...', error message '...'` がスローされる | `_fui` アセットまたは UI パッケージのロードに失敗し、失敗ハンドラーが未登録 | パッケージ名の推導結果と `uiFormAssetPath` を照合し、`パス_fui` アセットが存在することを確認してください |
| `Open UI form info is invalid.` がスローされる | 成功/失敗コールバックが受け取った `OpenUIFormInfo` が `null` | フレームワーク内部のデータ異常です。外部からのコールバックの誤用がないか確認してください |
| UI を閉じてもメモリが減らない | `RecycleUIForm` はデフォルトで `Unspawn` によるプール返却のみ行う | 完全に破棄する必要がある場合は `isDispose` 付きのクローズパスを使用してください |
