# 如何使用资源、配置、本地化与全局配置

GameFrameX 把"资源加载、热更新、本地化字符串、业务配置表"这四类数据需求收敛到四个独立子系统,通过 `GameApp.{子系统}` 静态属性统一访问。本页教你在业务代码里获取这四个组件并完成最常见的读表 / 读配置 / 取多语言文案 / 加载资源操作。

## 前置条件

- 已安装 `com.gameframex.unity.entry` 包,并按需安装对应的运行时子包:`GameFrameX.Asset.Runtime`、`GameFrameX.Config.Runtime`、`GameFrameX.GlobalConfig.Runtime`、`GameFrameX.Localization.Runtime`。
- 已在 Unity 的 **Project Settings → Player → Scripting Define Symbols** 中启用对应的宏(各组件独立控制,见下表)。

| 子系统 | 启用宏 | 命名空间 |
|--------|--------|----------|
| 资源 | `ENABLE_GAME_FRAME_X_ASSET` | `GameFrameX.Asset.Runtime` |
| 配置 | `ENABLE_GAME_FRAME_X_CONFIG` | `GameFrameX.Config.Runtime` |
| 全局配置 | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` | `GameFrameX.GlobalConfig.Runtime` |
| 本地化 | `ENABLE_GAME_FRAME_X_LOCALIZATION` | `GameFrameX.Localization.Runtime` |

未启用宏时,对应的 `GameApp.{Name}` 属性整段不会参与编译,业务代码会直接报"找不到 `Asset`"等错误。

## 操作步骤

### 1. 获取子系统访问器

四个子系统的入口结构完全一致:在任意业务类里直接访问静态属性 `GameApp.{子系统}`,首次访问时会从 `GameEntry` 中懒加载对应组件。

```csharp
// 资源
var asset = GameApp.Asset;
// 配置
var config = GameApp.Config;
// 全局配置
var globalConfig = GameApp.GlobalConfig;
// 本地化
var localization = GameApp.Localization;
```

### 2. 用 Asset 组件加载资源

`AssetComponent` 由 `GameFrameX.Asset.Runtime` 包提供,通过 `GameApp.Asset` 拿到。调用前请确保该组件已经在 `GameEntry` 启动流程中注册过。

```csharp
using GameFrameX.Asset.Runtime;

var asset = GameApp.Asset;
// 实际可用 API 取决于你安装的 Asset 子包版本,
// 这里只展示入口调用方式,具体签名请参见子包文档。
asset.LoadAssetAsync<GameObject>("Assets/Prefabs/Player.prefab", (prefab) =>
{
    Instantiate(prefab);
});
```

## 常见变体

- **异步加载资源**:在需要等加载完成的回调中调用 `GameApp.Asset.LoadAssetAsync<T>` 系列方法,不要在主线程同步阻塞。
- **多语言切换**:切换语言后通常需要刷新 UI 文本,具体刷新方式由 Localization 子包决定,但入口始终走 `GameApp.Localization`。
- **配置表热重载**:如使用 Config 子包,通常需要走子包提供的 `Reload` 接口,不要直接操作底层文件。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 编译报错:`GameApp` 不包含 `Asset` / `Config` 等定义 | 未在 Player Settings 中启用对应宏,对应 partial 类未参与编译 | 按"前置条件"表格添加 `ENABLE_GAME_FRAME_X_*` 宏 |
| 运行时 `GameApp.Asset` 为 `null` | `GameEntry` 未注册 `AssetComponent` | 在启动流程的 `RegisterComponent` 阶段加入对应组件 |
| 业务代码读不到多语言 / 配置字段 | 用错了子系统入口 | 注意区分:`GameApp.Config` 读业务配置表,`GameApp.GlobalConfig` 读全局参数,`GameApp.Localization` 读多语言文案 |

## 背景(可选)

四个入口属性都是 `static partial class GameApp` 的懒加载属性,首次访问时通过 `GameEntry.GetComponent<T>()` 拉取已注册的组件实例,后续访问直接返回缓存字段。每个文件都用对应的 `ENABLE_GAME_FRAME_X_*` 宏包住整段定义,这样业务项目可以按需裁剪子系统,无需把整个框架都编译进包体。
