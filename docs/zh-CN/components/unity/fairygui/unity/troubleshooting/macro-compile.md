# 宏开关不生效或冲突怎么办

本包的功能宏(`FAIRYGUI_TMPRO`、`FAIRYGUI_SPINE`、`FAIRYGUI_INPUT_SYSTEM`、`WECHAT_MINI_GAME`、`DOUYIN_MINI_GAME`)**不是在 Player Settings 的 Scripting Define Symbols 里手工定义的**,而是由 `Fairygui.Runtime.asmdef` 的 `versionDefines` 根据对应包是否安装自动开关。宏"不生效"绝大多数情况是:对应的包没装/包名不匹配,或你在全局符号里手工补了宏但缺依赖导致冲突报错。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 用了 Input System 包但触摸/点击不响应 | `FAIRYGUI_INPUT_SYSTEM` 未定义(包名与 versionDefines 不匹配或未安装),`Stage` 走了旧输入分支 | 确认已安装 `com.unity.inputsystem`,见下文步骤 1 |
| TMP 相关代码(如下划线、faceDilate)不生效 | `FAIRYGUI_TMPRO` 未定义,`com.unity.textmeshpro` 不在工程中 | 安装 TextMeshPro 包,触发重编译 |
| `GLoader3D` 加载 Spine 资源无效 / `case PackageItemType.Spine` 分支被编译裁剪 | `FAIRYGUI_SPINE` 未定义,两个 spine 包名都未命中 | 安装 spine 包(任一命中即可),见步骤 1 的包名清单 |
| 手工在 Player Settings 加了 `FAIRYGUI_SPINE` 后编译报 CS0246(找不到 `Spine.Unity.SkeletonDataAsset` 等) | 宏被强制打开但 spine 依赖不在工程,`UIPackage`/`GLoader3D` 里的 Spine 代码无法编译 | 删掉手工加的全局宏,改为安装对应包让 versionDefines 自动打开 |
| 微信/抖音小游戏的 `GTextInputWeChat` / `GTextInputDouYin` 整个文件不编译 | 条件是 `UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME`(抖音同理),三个条件缺一不可 | 切到 WebGL 平台 + 装对应 SDK 包 + 由 Wx/StarkWebGL 侧启用 `ENABLE_*` 宏 |
| Editor 程序集里 `#if` 永远为 false | `Fairygui.Editor.asmdef` 的 `versionDefines` 为空,编辑器程序集不感知这些宏 | 不要在 Editor 代码里依赖这些宏;只在 Runtime 程序集使用 |

## 宏与包名对照表

宏的真实来源在 [Fairygui.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Fairygui.Runtime.asmdef#L20-L51) 的 `versionDefines`:

| 宏 | 由哪个包触发 | 源码中控制什么 |
|----|--------------|----------------|
| `FAIRYGUI_INPUT_SYSTEM` | `com.unity.inputsystem` | `Stage` 的输入读取(新/旧输入系统切换) |
| `FAIRYGUI_TMPRO` | `com.unity.textmeshpro` | `GTextField` 的 TMP 渲染与属性序列化 |
| `FAIRYGUI_SPINE` | `com.gameframex.unity.esotericsoftware.spine.spine-unity` 或 `com.esotericsoftware.spine.spine-csharp`(任一) | `GLoader3D` 的 Spine 加载/更新/释放、`UIPackage` 的 Spine 资源绑定 |
| `WECHAT_MINI_GAME` | `com.qq.weixin.minigame` | 与 `UNITY_WEBGL`、`ENABLE_WECHAT_MINI_GAME` 一起启用微信小游戏输入框 |
| `DOUYIN_MINI_GAME` | `com.bytedance.starksdk` | 与 `UNITY_WEBGL`、`ENABLE_DOUYIN_MINI_GAME` 一起启用抖音小游戏输入框 |

关键源码片段(宏实际生效的位置):

```csharp

using UnityEngine.InputSystem;
#endif
```

```csharp

using UnityEngine;
```

## 修复步骤

1. **先确认包是否真的装了。** 打开 `Packages/manifest.json` 或 Package Manager,核对下表中的包名必须**完全一致**(versionDefines 按包名精确匹配,大小写敏感):
   - `FAIRYGUI_SPINE` → `com.gameframex.unity.esotericsoftware.spine.spine-unity` **或** `com.esotericsoftware.spine.spine-csharp`
   - `FAIRYGUI_TMPRO` → `com.unity.textmeshpro`
   - `FAIRYGUI_INPUT_SYSTEM` → `com.unity.inputsystem`
   - `WECHAT_MINI_GAME` → `com.qq.weixin.minigame`
   - `DOUYIN_MINI_GAME` → `com.bytedance.starksdk`
   注意:`Runtime/Fairygui.Runtime.asmdef` 的 `references` 里同时引用了 `spine-unity.Runtime`、`spine-unity`、`spine-csharp` 等,只要其中一个 spine 包存在即可让宏打开;若全部缺失,建议连 `FAIRYGUI_SPINE` 一起关闭(即不要手工补宏)。
2. **清掉手工加的全局宏。** 打开 *Edit → Project Settings → Player → Scripting Define Symbols*,确认里面**没有**自己手写的 `FAIRYGUI_*`、`WECHAT_MINI_GAME`、`DOUYIN_MINI_GAME`。这些宏由 asmdef 版本约束管理,手工写死会在卸载包后继续强制编译相关代码,产生 CS0246 之类的找不到类型错误。
3. **触发重编译。** 安装/卸载包后 Unity 会自动刷新;如果没有,右键项目窗口 *Reimport All* 或重启 Unity。versionDefines 在域重载时重新求值。
4. **小游戏平台按三条件核对。** 微信/抖音输入框类只在 `UNITY_WEBGL && <平台宏> && ENABLE_*` 同时成立时编译:
   - 切换到 WebGL 构建平台(`UNITY_WEBGL` 才为真);
   - 对应平台宏已由 SDK 包自动定义(见上表);
   - `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` 由 Wx / StarkWebGL 相关包提供,若你的 SDK 版本不提供该宏,则该文件保持关闭属正常现象,请勿手写补上。
5. **Editor 代码不要依赖这些宏。** [Fairygui.Editor.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/Fairygui.Editor.asmdef#L15-L15) 中 `versionDefines` 为空数组,编辑器程序集对上述宏一律不可见;需要按宏分支的代码必须放进 `Runtime` 程序集。

## 验证

- 在任意 Runtime 脚本中临时加一段编译期自检(检查完删除):

```csharp
#if FAIRYGUI_INPUT_SYSTEM
        Debug.Log("FAIRYGUI_INPUT_SYSTEM on");
#endif
#if FAIRYGUI_SPINE
        Debug.Log("FAIRYGUI_SPINE on");
#endif
```

- 打开 [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L11) 或 [GTextField.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextField.cs#L45-L46),IDE 中 `#if` 内代码不再灰显(未激活时会被置灰)即说明宏已生效。
- 之前因手写宏产生的 CS0246 / CS0103 编译错误在删除全局宏后消失,且控制台无新增错误。
