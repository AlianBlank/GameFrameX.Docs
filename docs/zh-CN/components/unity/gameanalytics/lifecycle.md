# 工作原理：组件初始化与事件分发流程

`GameAnalyticsComponent` 是一个挂在场景中的 Unity 组件：它在 `Awake` 里关闭自动注册、在 `OnEnable` 里读取 Inspector 上配置的 Provider 列表，用反射实例化每个 `IGameAnalyticsManager` 并传入配置字典完成初始化；之后所有上报调用（`Event` / 计时器 / 公共属性）都会遍历这些管理器逐一分发，并带初始化守卫与警告日志。本页说明这两条链路的真实执行顺序与代码位置。

## 初始化流程（从挂载到可用）

1. **组件挂载**：`GameAnalyticsComponent` 继承自 `GameFrameworkComponent`，带有 `[DisallowMultipleComponent]` 与 `[AddComponentMenu("Game Framework/GameAnalytics")]`，同一 GameObject 只能挂一个。
2. **`Awake` 阶段**：创建管理器列表，并关闭组件的自动注册（`IsAutoRegister = false`），再调用基类 `Awake()`：

```csharp
protected override void Awake()
{
    m_GameAnalyticsManager = new List<IGameAnalyticsManager>();
    IsAutoRegister = false;
    base.Awake();
}

private void OnEnable()
{
    Init();
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L20-L30)

3. **`OnEnable` 触发 `Init()`**：`Init()` 以 `m_IsInit` 做幂等保护，重复调用直接返回。
4. **逐个处理 Provider**：遍历序列化字段 `m_gameAnalyticsComponentProviders`（在 Inspector 中配置），对每一项：
   - `ComponentType` 为空白字符串时跳过该条目；
   - 通过 `Utility.Assembly.GetType` 按类型名解析 `System.Type`，解析失败时记录错误日志并 `continue`（错误原文：`Can not find component type '{类型名}'.`）；
   - 用 `Activator.CreateInstance` 反射创建实例，并要求它实现 `IGameAnalyticsManager`；
   - 把 Provider 的 `Setting` 键值对收集为 `Dictionary<string, string>` 作为 `args`，调用 `gameAnalyticsManager.Init(args)`，然后加入 `m_GameAnalyticsManager` 列表。
5. **置位 `m_IsInit = true`**，初始化完成，后续所有事件调用开始生效。

```csharp
public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }

            if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
            {
                Dictionary<string, string> args = new Dictionary<string, string>();
                foreach (var param in gameAnalyticsComponentProvider.Setting)
                {
                    args[param.Key] = param.Value;
                }

                gameAnalyticsManager.Init(args);
                m_GameAnalyticsManager.Add(gameAnalyticsManager);
            }
        }
    }

    m_IsInit = true;
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L47-L80)

6. **（可选）手动初始化**：对于 `IsManualInit()` 返回 `true` 的管理器（例如需要运行时才拿到的参数，如登录后的票据），在组件已初始化后调用 `ManualInit(extraArgs)` 二次注入：

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

## 事件分发流程

以 `Event(string eventName)` 为例，每次上报经过四层：

1. `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))`：事件名为空直接抛守卫异常；
2. 组件级守卫：`m_IsInit == false` 时静默返回（组件未初始化，事件被丢弃）；
3. 遍历 `m_GameAnalyticsManager`，对每个管理器检查 `IsInit()`；
4. 管理器已初始化则调用其同名方法完成真正上报；否则输出警告 `GameAnalyticsManager is not init.` 并跳过该管理器（不影响其他管理器继续分发）。

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

`StartTimer` / `StopTimer` 走完全相同的守卫与警告逻辑（见 [GameAnalyticsComponent.cs#L160-L179](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179) 与 [#L221-L240](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L221-L240)）；`PauseTimer` / `ResumeTimer` / `SetPlayerId` 只做非空守卫与组件级 `m_IsInit` 检查，不做单个管理器的 `IsInit()` 判断。`Event` 有四个重载：`Event(string)`、`Event(string, float)`、`Event(string, Dictionary<string, object>)`、`Event(string, float, Dictionary<string, object>)`，分发方式一致。

## 守卫与日志速查

| 触发条件 | 行为 / 日志原文 | 位置 |
|------|------|------|
| Provider 的 `ComponentType` 解析不到类型 | `Log.Error($"Can not find component type '{...}'.")`，跳过该 Provider | `Init()` 内 |
| `eventName` 为空/null | `GameFrameworkGuard.NotNullOrEmpty` 抛出 | 各计时器/事件方法开头 |
| 组件未初始化（`m_IsInit == false`） | 静默返回，不报错 | 所有分发方法 |
| 某个管理器未初始化（`IsInit() == false`） | `Log.Warning("GameAnalyticsManager is not init.")`，跳过该管理器 | `Event` / `StartTimer` / `StopTimer` |
| `SetPublicProperties` 的 key 为空 | 子类中直接 `return`，不写入 | `BaseGameAnalyticsManager` |

## 公共属性的注入与分发

管理器基类 `BaseGameAnalyticsManager` 继承自 `GameFrameworkModule`（因此每个管理器本身也是框架模块，拥有 `Update` / `Shutdown` 生命周期钩子，基类中为空实现），并维护一个 `m_PublicProperties` 字典：

- `SetPublicProperties(key, value)`：key 为空直接返回，否则写入字典；
- `ClearPublicProperties()`：清空字典后**立即重新注入设备信息**；
- `GetPublicProperties()`：返回字典的浅拷贝。

```csharp
public virtual void ClearPublicProperties()
{
    m_PublicProperties.Clear();
    AddDeviceInfoToPublicProperties();
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L70-L74)

`AddDeviceInfoToPublicProperties()` 是 `protected virtual`，默认注入的公共属性包括：设备（`device_id` / `device_model` / `device_type`）、系统（`os` / `system_language` / `current_culture`）、应用（`app_version` / `unity_version` / `platform`）、CPU 与内存（`processor_type` / `processor_count` / `processor_frequency` / `system_memory_size`）、显卡（`graphics_device_name` 等 5 项）、屏幕（`screen_width` / `screen_height` / `screen_dpi` / `screen_refresh_rate`）以及根据 `Application.internetReachability` 推导的 `network_type`（取值 `No Network` / `Mobile Data` / `WiFi` / `Unknown`）。子类可覆写它来增删属性。完整实现见 [BaseGameAnalyticsManager.cs#L88-L144](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L88-L144)。

组件层的 `GetPublicProperties()` 只返回**第一个**管理器的属性字典（遍历中首个命中即 `return`），多个 Provider 并存时以列表最前面的为准。

## 自定义 Provider 的接入点

新增一个分析平台时需要实现 `IGameAnalyticsManager`（或直接继承 `BaseGameAnalyticsManager` 复用公共属性逻辑），接口要求实现：`Init(Dictionary<string, string>)`、`ManualInit(Dictionary<string, string>)`、`IsInit()`、`IsManualInit()`、公共属性三件套、`StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer`、四个 `Event` 重载以及 `SetPlayerId`。完整接口定义见 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L46)。然后在 Inspector 里把实现类的类型名填进 Provider 列表并配置 `Setting` 键值对，即可被上述初始化流程自动实例化并纳入事件分发。

## 常见错误

- **Provider 配置后没有任何事件上报**：先检查 Console 是否出现 `Can not find component type '...'`——类型名拼写错误或程序集未参与打包都会导致该 Provider 被跳过；再确认实现类有无参数构造函数（`Activator.CreateInstance` 走默认构造）。
- **反复收到 `GameAnalyticsManager is not init.` 警告**：说明组件层已初始化（`m_IsInit == true`），但某个管理器自身 `Init(args)` 后未把内部状态置为已初始化，属于实现类的问题，与组件无关。
- **登录前调用 `Event` 被静默丢弃**：组件未初始化时所有分发方法直接 `return`，不产生日志；确认 `OnEnable` 是否已执行、`Init()` 是否被调用过。
- **`ClearPublicProperties` 后公共属性"清不干净"**：这是设计行为——清空后会自动重新写入设备信息，设备相关字段始终存在。

## 背景

组件用 `IsAutoRegister = false` 阻止 GameFrameX 的组件自动注册机制提前介入，保证初始化时机完全由 `OnEnable` 控制；用"反射 + 类型名字符串"加载 Provider，使本包无需引用任何具体平台 SDK 即可配置多平台并行上报，事件一次调用即广播到全部已初始化管理器。
