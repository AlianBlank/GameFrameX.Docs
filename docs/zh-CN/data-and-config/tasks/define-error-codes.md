# 如何定义业务错误码

在 `proto` 文件中通过 `enum` 定义业务错误码;通用返回码直接复用 `Common.OperationStatusCode`,业务专有错误码按 6 位规则(`模块ID + 3 位编号`)扩展,客户端通过 `ErrorCode` 字段透传。

## 前置条件

- 已在 `_0020_Common.proto` 中存在 `Common.OperationStatusCode` 通用错误码;
- 明确当前业务所属模块及其 `option module = N;` 编号(参见各业务文件的模块头);
- 新建文件遵循命名规范:`_0xxx_<业务名>.proto`(三位模块号,前导 0)。

## 操作步骤

1. 在 `option module = N;` 的业务文件顶部,声明业务错误码 `enum`,文件头加注释说明 6 位编码规则与客户端 `ErrorCode` 透传约定。

   ```protobuf
   // 邮件业务错误码(6 位 = 模块ID 500 + 3 位编号)。客户端协议 ErrorCode 以 int 透传:发生错误时赋具体码,成功不赋值(框架默认 0)。
   enum MailErrorCode
   {
     MailNone = 0;          // 无错误
     MailNotFound = 500001; // 邮件不存在
   }
   ```

   Source: [_0500_Mail.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0500_Mail.proto#L5-L10)

2. 需要通用返回码(如 `Success / Failed`)时,直接复用 `Common.ResultCode`,不要重复定义。

   ```protobuf
   // 返回码
   enum ResultCode
   {
     Success = 0; // 成功
     Failed = 1;  // 失败
   }
   ```

   Source: [_0020_Common.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0020_Common.proto#L5-L10)

3. 通用业务错误(配置错误、参数错误、消耗不足、未开通服务等)同样直接引用 `Common.OperationStatusCode`,仅在 `Ok = 0` 之外的业务专有场景新增枚举值。

   ```protobuf
   // 操作错误代码(客户端与服务器之间的业务错误码)
   enum OperationStatusCode
   {
     Ok = 0;                 // 成功
     ConfigErr = 1;          // 配置表错误
     ParamErr = 2;           // 客户端传递参数错误
     CostNotEnough = 3;      // 消耗不足
     Forbidden = 4;          // 未开通服务
     NotFound = 5;           // 不存在
     HasExist = 6;           // 已经存在
     AccountCannotBeNull = 7;
     Unprocessable = 8;
     UnknownPlatform = 9;
     Notice = 10;
     FuncNotOpen = 11;
     Other = 12;
     InternalServerError = 13;
     ServerFullyLoaded = 14;
     Unsupported = 15;
     InvalidReward = 16;
     PartialSuccess = 17;
   }
   ```

   Source: [_0020_Common.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0020_Common.proto#L12-L33)

4. 在面向客户端的应答/通知消息中,使用 `int64 ErrCode` 字段承载错误码(0 表示无错误,非 0 时 `Desc` 给出可读描述),保持与 `_0300_User.proto` 的 `RespErrorCode` 一致。

   ```protobuf
   // 客户端每次请求都会回复错误码
   message RespErrorCode
   {
     int64 ErrCode = 1; // 0:表示无错误
     string Desc = 2;   // 错误描述(不为 0 时有效)
   }
   ```

   Source: [_0300_User.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0300_User.proto#L76-L81)

5. 成功响应消息复用 `ResultCode.Code` 字段携带 `Common.ResultCode`(常见取值 `0` 成功 / `1` 失败)。

   ```protobuf
   message RespLogin
   {
     int32 Code = 1;       // 返回码(ResultCode)
     string RoleName = 2;  // 账号名
   }
   ```

   Source: [_0300_User.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0300_User.proto#L18-L20)

## 常见变体

- 通用错误优先:能落到 `OperationStatusCode` 的语义就不要新增业务码,例如“邮件不存在”既可以用 `OperationStatusCode.NotFound`,也可以像示例那样给出 `MailNotFound = 500001`。需要客户端按业务分支处理时才使用专有码。
- 通知类响应:某些主消息会屏蔽(`FuncNotOpen = 11`)或推送(`Notice = 10`),直接复用 `OperationStatusCode` 即可。
- 数量限制:邮件奖励发放支持部分成功,使用 `OperationStatusCode.PartialSuccess = 17` 而非自定义码。

## 常见错误

| 错误做法 | 后果 |
|----------|------|
| 在业务文件里重新定义 `Success / Failed` 或 `Ok` | 与 `Common` 冲突,客户端无法统一处理 |
| 业务错误码使用 `int32` 而非 `int64` | 6 位模块码会被截断,扩展性受限(`RespErrorCode.ErrCode` 为 `int64`) |
| 自定义码编号不遵守“模块ID + 3 位”规则 | 与日志/监控联动的错误码解析会错位 |
| `Ok = 0` 之外枚举值未给中文注释 | 客户端 i18n 表无法自动生成 |
| 成功响应忘了赋 `ErrCode = 0` | 客户端默认 0 即可,不需要额外赋值(框架默认) |

## 背景(可选)

仓库约定 `ResultCode` 面向“调用是否成功”的协议层判断,`OperationStatusCode` 面向业务级错误语义;各业务模块在此之上扩展专有错误码,采用 `模块ID * 1000 + 序号` 的 6 位方案,便于按模块聚合统计。
