# "Event manager is invalid." 致命错误怎么办

这条 `Log.Fatal("Event manager is invalid.")` 来自 `EventComponent.Awake()`：当 `GameFrameworkEntry.GetModule<IEventManager>()` 返回 `null` 时打印，随后组件直接 `return`，`m_EventManager` 保持为空，之后任何事件订阅/派发调用都会抛 NullReferenceException。核心原因是 **`IEventManager` 的实现类型没有被框架找到并注册**（实现类型名配置错误、被改名/移动命名空间，或被代码裁剪剔除）。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 进入 Play / 启动场景即打印 `Fatal: Event manager is invalid.`，随后调用 `Subscribe`/`Fire` 抛 `NullReferenceException` | `GetModule<IEventManager>()` 返回 null，实现类型未被注册 | 见 [修复步骤 1](#1-检查-eventcomponent-上的实现类型配置) |
| 升级包版本或改动命名空间后开始出现 | `EventComponent` 上保存的 `componentType` 字符串仍指向旧类型名，`Utility.Assembly.GetType(componentType)` 找不到 | 在 Inspector 中重新选择 `EventManager` 实现并保存场景，见 [修复步骤 1](#1-检查-eventcomponent-上的实现类型配置) |
| 编辑器正常，打包（IL2CPP / 托管裁剪）后出现 | 实现类型 `EventManager` 被裁剪剔除，反射找不到 | 保留 `[Preserve]` 标注与裁剪保护配置，见 [修复步骤 2](#2-确认-eventmanager-实现类型未被裁剪) |
| 组件是手工拼的预制体、从别的项目拷贝来的 | 预制体上 `componentType` 序列化值为空或不属于当前工程 | 删除后通过 `GameFrameX/Event` 菜单重新添加，见 [修复步骤 3](#3-重建-gameframex-event-组件) |

错误抛出的位置（真实源码）：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

## 修复步骤

### 1. 检查 EventComponent 上的实现类型配置

`EventComponent` 在 `Awake()` 里用反射 `Utility.Assembly.GetType(componentType)` 解析实现类型，再由 `GameFrameworkEntry.GetModule<IEventManager>()` 取模块。`componentType` 是在 Inspector 上序列化保存的字符串，编辑器侧由 `EventComponentInspector` 填充候选列表：

```csharp
[CustomEditor(typeof(EventComponent))]
internal sealed class EventComponentInspector : ComponentTypeComponentInspector
{
    // ...
    RefreshComponentTypeNames(typeof(IEventManager));
}
```

Source: [EventComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Editor/Inspector/EventComponentInspector.cs#L36-L63)

操作：

1. 选中挂有 `EventComponent` 的 GameObject（默认是 GameFrameX 根物体，组件菜单为 `GameFrameX/Event`）。
2. 在 Inspector 中查看组件类型下拉框，确认选中的是 `GameFrameX.Event.Runtime.EventManager`（本包内唯一实现）。
3. 若显示为空或为红色/丢失（Missing），重新选择 `EventManager` 并保存场景与相关预制体。
4. 再次进入 Play 模式验证。

### 2. 确认 EventManager 实现类型未被裁剪

本包的实现类同时带有 `[UnityEngine.Scripting.Preserve]` 保护：

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class EventManager : GameFrameworkModule, IEventManager
{
    private readonly EventPool<GameEventArgs> m_EventPool;

    public EventManager()
    {
        m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L38-L49)

操作：

1. 若你在 Player Settings 中开启了 `Managed Stripping Level` 或使用 IL2CPP，确认包内的 `Preserve` 特性未被移除（不要改动程序集的裁剪豁免配置）；本包同时提供 [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs) 用于裁剪场景下的辅助处理。
2. 确认 `Runtime` 程序集（`GameFrameX.Event.Runtime` 命名空间）确实参与了构建（asmdef 的平台勾选、未被手动从 Build 中排除）。

### 3. 重建 GameFrameX/Event 组件

如果组件来自拷贝的预制体且序列化数据已失效：

1. 在 GameObject 上移除当前的 `EventComponent`（组件标记了 `[DisallowMultipleComponent]`，同物体不允许重复挂载）。
2. 通过 `Add Component → GameFrameX → Event` 重新添加，组件定义见：

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Event")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-7000)]
public sealed class EventComponent : GameFrameworkComponent
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)

3. 确认 `GameFrameworkEntry` 所在的 GameFrameX 基础运行时包已安装并被引用（`GetModule<T>` 依赖它完成模块注册扫描）。
4. 保存场景后重新进入 Play 模式。

## 验证

- 启动时 Console 不再出现 `Fatal: Event manager is invalid.`。
- 在任意脚本中访问事件组件的只读属性不再抛空引用，例如 `EventCount` / `EventHandlerCount`（内部直接转发到 `m_EventManager`，见 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L50-L61)）。
- 调用一次 `Check(id, handler)` 或 `Subscribe(id, handler)`，能正常返回/登记，且 `Count(id)` 计数符合预期。
