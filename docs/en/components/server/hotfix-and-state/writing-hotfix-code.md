# Writing Hot-Updatable Business Code (Hotfix Layer Specification)

This page explains how to write hot-replaceable business code in the `GameFrameX.Hotfix` assembly while following the framework's bridging and layering constraints.

## Prerequisites

- The `GameFrameX.Hotfix` assembly project has been created (see [GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj) in the repository).
- References to `GameFrameX.StartUp`, `GameFrameX.SuperSocket.*`, `GameFrameX.Apps.Common.Session`, and other dependencies are included.
- The `GameFrameX.Architecture.Analyzers` rule set is enabled at compile time (`GFX0004`, etc.).

## Core Conventions of the Hotfix Layer

1. **Bridge classes must implement `IHotfixBridge`**: All entry classes that need to bridge between the state layer (Apps) and the logic layer (Hotfix) must implement this interface, and the class must be defined within the `GameFrameX.Hotfix` assembly. `HotfixBridgeAssemblyAnalyzer` enforces this rule with the `GFX0004` error.
2. **Entry classes must use `partial`**: Because the startup lifecycle is spread across multiple files (`AppStartUpHotfixGameByEntry.cs`, `AppStartUpHotfixGameByMain.cs`, etc.), the class must remain `partial`; otherwise, compilation will fail during the startup stage.
3. **Keep the `HotfixHandler` marker type**: `HotfixHandler` is an empty static class used only to be located via reflection. Deleting it will cause the entry point to be missing during hot updates.

## Steps

### Step 1: Declare the startup bridge class in the Hotfix assembly

Create or modify `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`, declare the class as `partial` and implement `IHotfixBridge`:

```csharp
using GameFrameX.StartUp;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge
{
    public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
    {
        if (reload)
        {
            ActorManager.ClearAgent();
            return true;
        }

        Init(setting.ServerType, setting);
        await RunServer();
        // Start timers
        await QuartzTimer.Start();
        GlobalTimer.Start();
        await ComponentRegister.ActiveGlobalComponents();
        return true;
    }

    public async Task Stop(string message = "")
    {
        await StopAsync(message);
    }
}
```

### Step 2: Extend message dispatch and lifecycle in another file

Since the class is declared as `partial`, you can override network and lifecycle hooks such as `StartAsync`, `PackageHandler`, `OnConnected`, `OnDisconnected`, and `StopAsync` in another file:

```csharp
using GameFrameX.Apps.Common.Session;
using GameFrameX.SuperSocket.Connection;
using GameFrameX.SuperSocket.Server.Abstractions.Session;
using GameFrameX.SuperSocket.WebSocket.Server;

namespace GameFrameX.Hotfix.StartUp;

internal partial class AppStartUpHotfixGame
{
    public override async Task StartAsync()
    {
        await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
            new DefaultMessageCompressHandler(),
            new DefaultMessageDecompressHandler(),
            HotfixManager.GetListHttpHandler(),
            HotfixManager.GetHttpHandler);
    }

    protected override async ValueTask PackageHandler(IAppSession appSession, IMessage message)
    {
        if (message is NetworkMessagePackage messagePackage)
        {
            var netWorkChannel = SessionManager.GetChannel(appSession.SessionID);
            if (netWorkChannel.IsNull()) return;

            var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
            if (handler == null)
            {
                LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
                return;
            }

            try
            {
                await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
            }
            catch (Exception exception)
            {
                LogHelper.Fatal(exception);
            }
        }
    }

    public override async Task StopAsync(string message = "")
    {
        await base.StopAsync(message);
        await SessionManager.RemoveAll();
        await QuartzTimer.Stop();
        await ActorManager.AllFinish();
        await GlobalTimer.Stop();
        await ActorManager.RemoveAll();
    }
}
```

### Step 3: Do not delete the `HotfixHandler` marker type

The hot update framework relies on reflection to locate the `HotfixHandler` class as the entry marker; simply keep it as is, no members need to be added:

```csharp
namespace GameFrameX.Hotfix;

/// <summary>
/// This class documentation is used for handling hot update markers. It must not be deleted. Used for reflection invocation
/// </summary>
public static class HotfixHandler
{
}
```

### Step 4: Ensure the IHotfixBridge implementation is located in the Hotfix assembly

If you add a new bridge implementation (e.g., `MyHotfixBridge : IHotfixBridge`), the file must be placed under the `GameFrameX.Hotfix` project; otherwise, `HotfixBridgeAssemblyAnalyzer` will report `GFX0004`:

```text
Type 'MyHotfixBridge' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not '<YourAssembly>'
```

## Common Variants

- **Gateway-based startup**: Provide gateway-side overrides in `AppStartUpHotfixGameByGateWay.cs`.
- **Heartbeat-based startup**: Provide heartbeat-side overrides in `AppStartUpHotfixGameByHeart.cs`.
- **Reload scenario (`reload == true`)**: In `OnLoadSuccess`, only call `ActorManager.ClearAgent()` and return; do not re-initialize the network and global components.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| Compilation reports `Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix'` | The `IHotfixBridge` implementation class is placed in the wrong assembly | Move the class file to the `GameFrameX.Hotfix` project |
| Startup reports "hot update entry not found" | The `HotfixHandler` static class was accidentally deleted | Re-declare `public static class HotfixHandler {}` |
| `partial` error: `AppStartUpHotfixGame` definition not found | The `partial` modifier was omitted in the new file | Add `internal partial class AppStartUpHotfixGame` to all partial class declarations |
| State not cleaned up after hot update | `ActorManager.ClearAgent()` was not called in the `OnLoadSuccess(reload=true)` branch | Follow the template and clear Agents first in the reload branch |

## Background (Optional)

`IHotfixBridge` is the bridging contract through which the state layer invokes the logic layer. It constrains its implementation to reside within the `GameFrameX.Hotfix` assembly, thereby ensuring that the entire bridging logic can be replaced as a whole during hot updates; the architecture analyzer `HotfixBridgeAssemblyAnalyzer` enforces this rule at compile time with `GFX0004`.
