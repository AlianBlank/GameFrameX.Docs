# 因未安裝相依子套件導致編譯失敗時的處理方式

當 `com.gameframex.unity.entry` 參考了某個子套件(例如 Network、UI、FairyGUI、Asset、Procedure 等)，但該子套件未安裝或版本不符時，Unity 主控台會回報 `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Xxx.Runtime' which is not in the project` 或 `The type or namespace name 'X' could not be found`,導致編譯中斷。本頁面提供依據錯誤訊息定位缺少的子套件並恢復編譯的步驟。

## 快速診斷

| 症狀(主控台訊息)| 原因 | 修正方式 |
|---|---|---|
| `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Network.Runtime' which is not in the project.` | 專案中未安裝 `com.gameframex.unity.network` 子套件 | 透過 Package Manager 安裝對應的相依套件 |
| `The type or namespace name 'GameApp' could not be found` | 未安裝 `com.gameframex.unity.entry` 或已被移除 | 重新安裝入口套件 |
| 編譯錯誤訊息提及 `GameFrameX.UI.Runtime`、`GameFrameX.Asset.Runtime`、`GameFrameX.FSM.Runtime` 等，但專案中不存在這些組件 | 缺少對應的選用子套件(未安裝選用相依套件)| 評估是否需要該子系統；若不需要，移除對它的參考，否則予以安裝 |
| 已安裝子套件但仍回報 `assembly references ... which is not in the project` | 子套件版本與 `package.json` 中宣告的版本範圍不符 | 將子套件升級/降級至相依清單所要求的版本 |
| 型別找不到的錯誤僅在啟用特定子系統(例如廣告、登入)時出現 | 對應的 `versionDefines` 巨集未啟用；程式碼被 `#if` 排除但指令碼仍被載入 | 確認安裝子套件後巨集會自動注入；若仍未生效，請重新啟動 Unity 並重新整理 Assets |

### 2. 安裝缺少的子套件

開啟 Unity → `Window` → `Package Manager`,點選左上角的 `+` 按鈕 → `Add package by name...`,然後填入上表中的 `name` 與 `version` 並安裝。例如，要新增 Network:

1. 開啟 Package Manager。
2. 選擇 `Add package by name`。
3. 名稱:`com.gameframex.unity.network`,版本:`2.6.10`。
4. 點選 `Add`,並等待 Unity 解析與下載。

安裝完成後，Package Manager 會自動寫入 `Packages/manifest.json`,並注入對應的 `versionDefines` 巨集。

### 3. 處理版本不符

`package.json` 中指定的相依版本是經過測試的相容組合。如果您手動鎖定較低或較高的版本，`asmdef` 所參考的組件可能會找不到。

- 檢查 `Packages/manifest.json` 或 `Packages/packages-lock.json` 中對應套件的版本。
- 與 `package.json` 中的 `dependencies` 欄位比對，並對齊至目標版本。
- 若是 Git URL 參考(例如 `com.gameframex.unity.network`),請在 URL 結尾加上 `#2.6.10` 以鎖定標籤。

來源:[package.json](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/package.json#L22-L42)

### 4. 不需要該子系統時的簡化做法

如果您不需要某個選用子系統，可以不安裝它，同時避免 `GameFrameX.Entry.Runtime` 參考對應的組件。具體做法是在您自己的 asmdef 中停止透過 `GameFrameX.Entry` 觸發該路徑，或移除對該子系統的程式碼參考。`GameFrameX.Entry.Runtime.asmdef` 會依據對應子套件是否存在，透過 `versionDefines` 自動啟用/停用程式碼分支。

```text
範例:若您只使用 Procedure + UI + Network,只需安裝
  com.gameframex.unity.procedure@1.4.0
  com.gameframex.unity.ui@2.11.0
  com.gameframex.unity.network@2.6.10
其他選用子套件(廣告、登入、分析、XLua 等)無需安裝;對應程式碼會透過巨集自動剔除。
```

### 5. 安裝後錯誤仍未解決時的清理步驟

1. 關閉 Unity。
2. 刪除專案根目錄下的 `Library/ScriptAssemblies/` 與 `Library/PlayerScriptAssemblies/`。
3. 刪除 `Library/PackageCache/` 底下與缺少之子套件相關的殘留快取。
4. 重新開啟 Unity,並等待初始匯入完成。

完成後，主控台應不會再顯示缺少組件的訊息。

## 驗證

- Unity 主控台不再出現 `Assembly ... references ... which is not in the project` 錯誤。
- 在 `Window` → `Package Manager` 中，`dependencies` 宣告的所有子套件皆顯示為 `Installed`。
- 在任指令碼中，`using GameFrameX.Entry.Runtime;` 可成功編譯，且可存取 `GameApp.Procedure` 與 `GameApp.Network` 等靜態存取器。

## 背景說明(選讀)

入口套件 `com.gameframex.unity.entry` 透過 `GameFrameX.Entry.Runtime.asmdef` 集中宣告對所有子系統組件的參考，並依據子套件是否存在，在 `versionDefines` 中注入 `ENABLE_GAME_FRAME_X_*` 巨集，使未安裝子套件的程式碼區段被 `#if` 排除，實現按需編譯。`package.json` 的 `dependencies` 欄位是版本對齊的唯一事實來源——當編譯回報「找不到組件」時，請先檢查此處的版本，而不是手動修改 asmdef。
