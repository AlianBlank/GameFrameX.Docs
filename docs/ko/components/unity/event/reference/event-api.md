# EventComponent / IEventManager API 빠른 참조

이 페이지는 GameFrameX.Event 이벤트 모듈이 외부에 공개하는 모든 공개 API를 수록합니다: 씬 컴포넌트 `EventComponent`와 그 이면의 인터페이스 `IEventManager`를 다루며, 실제 시그니처, 이벤트 인자 기본 클래스 및 스레드 안전성 설명을 포함하여 표를 통해 바로 조회하여 사용할 수 있습니다.

## 컴포넌트 가져오기

`EventComponent`는 씬에 배치되는 Unity 컴포넌트입니다(메뉴 경로 `GameFrameX/Event`, `[DisallowMultipleComponent]`, 컴포넌트 우선순위 -7000). 이 컴포넌트는 `Awake`에서 `GameFrameworkEntry.GetModule<IEventManager>()`를 통해 이벤트 매니저를 가져오며, 이후 모든 공개 메서드는 해당 매니저로 직접 전달됩니다. 일상적인 비즈니스 코드에서는 `EventComponent`만 사용하면 되며, 직접 `IEventManager` 구현을 만들 필요가 없습니다.

출처: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L77)

## EventComponent 공개 API

| 이름 | 시그니처 | 설명 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | 이벤트 핸들러의 총 개수를 가져옵니다 |
| EventCount | `int EventCount { get; }` | 이벤트 개수를 가져옵니다 |
| Count | `int Count(string id)` | 지정된 이벤트 ID의 이벤트 핸들러 개수를 가져옵니다 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 지정된 이벤트가 해당 핸들러를 이미 구독했는지 확인합니다 |
| CheckSubscribe | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 존재하지 않을 때만 구독하여 중복 구독을 방지합니다 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 이벤트 핸들러 구독을 해제합니다 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 확인 후 구독을 해제합니다; handler가 존재하지 않으면 아무 작업도 수행하지 않습니다 |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | 기본 이벤트 핸들러를 설정합니다(구독자가 없을 때 폴백) |
| Fire | `void Fire(object sender, GameEventArgs e)` | 이벤트를 발생시킵니다; 스레드 안전, 메인 스레드 콜백, 다음 프레임에 디스패치 |
| Fire (오버로드) | `void Fire(object sender, string eventId)` | `eventId`로 `EmptyEventArgs`를 생성하여 발생시킵니다; 내부적으로 `GameFrameworkGuard.NotNullOrEmpty`를 호출하여 비어 있지 않은지 검증합니다 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | 이벤트를 즉시 모드로 발생시킵니다; 스레드 안전하지 않으며 즉시 디스패치됩니다 |

출처: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L171)

`CheckSubscribe`는 `EventComponent`에만 존재하는 편의 메서드입니다(인터페이스에는 없음): 먼저 `Check`를 호출하고, 구독되어 있지 않을 때만 하위의 `Subscribe`를 호출합니다.

```csharp
if (!Check(id, handler))
{
    m_EventManager.Subscribe(id, handler);
}
```

출처: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

## IEventManager 인터페이스 멤버

`EventComponent`는 `Subscribe`에 대한 전달 메서드를 공개하지 않으며, 하위 구독은 통일적으로 인터페이스를 통해 이루어집니다(컴포넌트 계층에서는 대신 `CheckSubscribe`를 제공). 인터페이스 정의는 다음과 같습니다:

| 이름 | 시그니처 | 설명 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | 이벤트 핸들러의 개수를 가져옵니다 |
| EventCount | `int EventCount { get; }` | 이벤트 개수를 가져옵니다 |
| Count | `int Count(string id)` | 지정된 이벤트 ID의 이벤트 핸들러 개수를 가져옵니다 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 이벤트 핸들러가 존재하는지 확인합니다 |
| Subscribe | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | 이벤트 핸들러를 구독합니다 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 이벤트 핸들러 구독을 해제합니다 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 확인 후 구독을 해제합니다; handler가 존재하지 않으면 아무 작업도 수행하지 않습니다 |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | 기본 이벤트 핸들러를 설정합니다 |
| Fire | `void Fire(object sender, GameEventArgs e)` | 이벤트를 발생시킵니다; 스레드 안전, 메인 스레드 콜백, 이벤트는 발생 후 다음 프레임에 디스패치됩니다 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | 이벤트를 즉시 모드로 발생시킵니다; 스레드 안전하지 않으며, 이벤트는 즉시 디스패치됩니다 |

출처: [Runtime/Event/IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L38-L105)

`EventComponent`와의 차이점 요약:

- `EventComponent.CheckSubscribe(id, handler)`는 `IEventManager.Subscribe(id, handler)`의 "확인 후 구독" 버전에 해당합니다.
- `EventComponent.Fire(object sender, string eventId)`는 컴포넌트에만 존재하는 문자열 오버로드로, `Fire(sender, EmptyEventArgs.Create(eventId))`와 동일합니다.
- 초기화에 실패하면 컴포넌트가 `Log.Fatal("Event manager is invalid.")`를 출력합니다.

출처: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

## 이벤트 인자 타입

| 타입 | 정의 | 설명 |
|------|------|------|
| `GameEventArgs` | `public abstract class GameEventArgs : BaseEventArgs` | 모든 게임 로직 이벤트의 추상 기본 클래스이며, 커스텀 이벤트는 이를 상속합니다 |
| `EmptyEventArgs` | `public static EmptyEventArgs Create(string eventId)` | 페이로드가 없는 이벤트; `ReferencePool.Acquire<EmptyEventArgs>()`에서 가져와 이벤트 ID를 설정하며, `EventComponent.Fire(sender, eventId)`와 함께 사용합니다 |

출처: [Runtime/EventArgs/GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L33-L40)

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

## Fire와 FireNow 선택 가이드

| 시나리오 | 사용법 | 이유 |
|------|------|------|
| 서브 스레드 / 비동기 작업에서 이벤트 발생 | `Fire(sender, e)` | 스레드 안전하며 콜백이 메인 스레드에서 실행됨을 보장하지만, 다음 프레임으로 디스패치가 지연됩니다 |
| 메인 스레드에서 콜백의 동기 실행이 필요한 경우 | `FireNow(sender, e)` | 즉시 디스패치; 스레드 안전하지 않으므로 서브 스레드에서 호출하지 마세요 |
| 트리거 신호만 필요하고 추가 데이터가 없는 경우 | `Fire(sender, eventId)` | 컴포넌트 오버로드가 자동으로 `EmptyEventArgs`를 생성합니다(내부적으로 참조 풀을 거침) |

위의 스레드 동작 의미는 소스 코드 내 두 곳의 주석 설명에서 비롯됩니다: `Fire` "이 작업은 스레드 안전하며, 메인 스레드가 아닌 곳에서 발생시키더라도 이벤트 핸들러가 메인 스레드에서 콜백됨을 보장하지만, 이벤트는 발생 후 다음 프레임에 디스패치됩니다"; `FireNow` "이 작업은 스레드 안전하지 않으며, 이벤트는 즉시 디스패치됩니다".

출처: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L143-L171)
