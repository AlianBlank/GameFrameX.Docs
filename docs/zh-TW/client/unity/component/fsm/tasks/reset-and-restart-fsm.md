# FSM 重設與重新啟動方法

透過 `Start<TState>()` 可重設目前狀態，並從指定狀態重新進入 FSM。只有在需要完全銷毀時才使用 `Clear()`。框架中沒有名為 `Reset` 的方法。所謂「重設」即是重新 `Start`,而「重新啟動」則是銷毀後重建。

## 前置條件

- 已透過 `FsmManager` 建立 `IFsm<T>`,可取得目前 FSM 的參考。
- 狀態集合滿足 `FsmStateCount > 0`,且目標狀態類型必須已註冊至 FSM(以 `HasState<TState>()` 驗證)。

## 操作步驟

### 1. 重設為初始狀態(一般用法)

由於 `Fsm<T>.Start` 在 `IsRunning == true` 時會拋出 `GameFrameworkException("FSM is running, can not start again.")`([Fsm.cs#L272-L277](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L277)),因此「重設」的做法是先切換到佔位(placeholder)狀態，再 `Start` 初始狀態。最簡單的佔位狀態，是再次切換到同一狀態以觸發 `OnLeave` 並將 `CurrentStateTime` 初始化為 0,然後呼叫 `Start`。

```csharp
// owner is the current holder reference
void ResetToInitial(IFsm<MyOwner> fsm, MyOwner owner)
{
    if (fsm == null || fsm.IsDestroyed) return;

    // Enter an equivalent state to trigger OnLeave and clear the timer
    if (fsm.HasState<IdleState>())
    {
        fsm.Start<IdleState>();
        fsm.Start<IdleState>();
    }
}
```

來源： [Fsm.cs#L272-L288](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L288)

### 2. 重新啟動(完全銷毀 + 重建)

完整的重設必須呼叫 `Clear()` 以清空所有狀態、持有者與資料([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265)),接著透過 `FsmManager.CreateFsm` 重建並 `Start`。

```csharp
// Get manager and owner
var fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());

fsm.Start<IdleState>();
// ... 之後若需要完整重新啟動:
GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>().DestroyFsm(fsm);
fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());
fsm.Start<IdleState>();
```

`Clear()` 內部會先呼叫 `m_CurrentState.OnLeave(this, true)`,接著走訪所有狀態並呼叫 `OnDestroy`,再將 `m_CurrentState` 設為 `null`、`m_CurrentStateTime` 設為 `0`、`m_IsDestroyed` 設為 `true`([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265))。

## 常見變化

- **重設為任意狀態**：將步驟 1 的 `IdleState` 替換為目標 `TState`。前提條件是 `HasState<TState>()` 回傳 `true`。
- **僅重設資料、不變更狀態**：清空使用者資料字典，保留目前狀態並繼續執行(參考 [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs) 中清空 `m_Datas` 的方式)。
- **在 Editor 中觀察狀態**：Inspector 會顯示 `fsm.CurrentStateName` 與 `CurrentStateTime`。狀態名稱為 `null` 時表示未執行([FsmComponentInspector.cs#L72](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Editor/Inspector/FsmComponentInspector.cs#L72))。

## 常見錯誤

| 現象 | 原因 | 修正 |
|------|------|------|
| 拋出 `FSM is running, can not start again.` | 在 `IsRunning == true` 時直接呼叫 `Start` | 先將 `IsRunning` 變更為 `false`(先切換到其他狀態再切換回來，或先 `Clear` 再 `CreateFsm`) |
| 拋出 `FSM 'X' can not start state 'Y' which is not exist.` | `TState` 未註冊至 FSM | 呼叫前先以 `fsm.HasState<TState>()` 驗證，若有遺漏則重建 FSM |
| 拋出 `State type 'X' is invalid.` | 傳入的 `Type` 並非 `FsmState<T>` 的衍生類別 | 確認 `stateType` 有繼承目前 FSM 對應的 `FsmState<T>` |
| `Start` 後狀態未變更 | 重複對同一狀態 `Start`,在判定為「已在執行中」之前，第一次 `Start` 就已生效 | 改用前述「先切換到同一狀態一次再切換回來」的做法繞過，或建立新的 FSM |

## 背景(選用)

`Start` 會直接覆寫 `m_CurrentState` 並呼叫 `OnEnter`,因此「自我重設」看似無效，但實際生效的是 `OnLeave(..., true)` 與 `m_CurrentStateTime = 0f` 的副作用。完整的銷毀會經過參考池 `ReferencePool`,詳情請參考 `Fsm<T>.Clear` 的實作。
