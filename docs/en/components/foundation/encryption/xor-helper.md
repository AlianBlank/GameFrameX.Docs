# How to Use XOR for Simple Encryption and Decryption

`XorHelper` provides a lightweight encryption/decryption utility based on the XOR operation. Applying XOR to the data twice with the same key restores the original text, making it suitable for simple obfuscation of configuration files and temporary in-memory byte streams. Note: it is not a cryptographically secure scheme and must not be used in scenarios that require confidentiality.

## Prerequisites

- Reference the NuGet package `GameFrameX.Foundation.Encryption` (or directly reference `GameFrameX.Foundation.Encryption/XorHelper.cs`).
- Import the namespace with `using GameFrameX.Foundation.Encryption;`.

## Steps

### 1. Simplest Encryption and Decryption

Call `XorHelper.GetXorBytes(byte[], byte[])` to perform one XOR pass, then call it again with the same key to decrypt. The two calls are fully symmetric; there is no distinction between encrypt and decrypt methods.

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

var keyBytes = Encoding.UTF8.GetBytes("MySecretKey123");
var dataBytes = Encoding.UTF8.GetBytes("Hello, World! 这是一个测试字符串。");

// Encrypt
var encrypted = XorHelper.GetXorBytes(dataBytes, keyBytes);
// Decrypt (call again with the same key)
var decrypted = XorHelper.GetXorBytes(encrypted, keyBytes);

Console.WriteLine(Encoding.UTF8.GetString(decrypted)); // Outputs the original text
```

### 2. Choose the "In-Place Modification" Version to Save Memory

If the input array's original content no longer needs to be preserved afterward, use `GetSelfXorBytes` to rewrite the input array directly, without allocating an extra new byte stream.

```csharp
var dataBytes = Encoding.UTF8.GetBytes("payload");
var keyBytes = Encoding.UTF8.GetBytes("key");

// XOR directly on dataBytes; no new array is returned
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
// Call once more to restore
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
```

Source: [XorHelper.cs#L158-L169](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L158-L169)

### 3. Encrypt Only the First 220 Bytes of the Data (Quick Mode)

When you need lightweight obfuscation on a large byte stream (such as a protocol header) but do not want to iterate over the entire array, use `GetQuickXorBytes` / `GetQuickSelfXorBytes`. Both apply XOR only to the first `QuickEncryptLength` (default 220) bytes; the portion beyond is left unchanged.

```csharp
var buffer = new byte[1024];           // protocol header + subsequent payload
var key = Encoding.UTF8.GetBytes("k");

// Only obfuscate the first 220 bytes; subsequent bytes are left unchanged
var encrypted = XorHelper.GetQuickXorBytes(buffer, key);
// Restoration likewise processes only the first 220 bytes
var restored = XorHelper.GetQuickXorBytes(encrypted, key);
```

### 4. Encrypt Only a Segment of the Array

Use the overloads with `startIndex` and `length` parameters to apply XOR only to a specified range, suitable for scenarios such as "obfuscate only the head / a middle section".

```csharp
var data = new byte[] { 1, 2, 3, 4, 5, 6, 7, 8 };
var key  = Encoding.UTF8.GetBytes("MySecretKey123");

// Encrypt only the 4 bytes starting at index 2
var result = XorHelper.GetXorBytes(data, 2, 4, key);
// data[0..2] and data[6..8] remain unchanged
```

## Quick Reference of Common Methods

| Method | Allocates new array | Encryption range | Use case |
|------|----------------|----------|----------|
| `GetXorBytes(bytes, code)` | Yes | Entire array | Regular encryption/decryption where the original data must be preserved |
| `GetSelfXorBytes(bytes, code)` | No (in-place modification) | Entire array | Original data no longer needed; saves one allocation |
| `GetQuickXorBytes(bytes, code)` | Yes | First 220 bytes | Quick obfuscation of large headers |
| `GetQuickSelfXorBytes(bytes, code)` | No | First 220 bytes | In-place quick obfuscation of large headers |
| `GetXorBytes(bytes, startIndex, length, code)` | Yes | Specified range | Obfuscate only the head/middle section |
| `GetSelfXorBytes(bytes, startIndex, length, code)` | No | Specified range | Obfuscate only the head/middle section, in-place |

## Common Variants

### Key Longer than Data / Shorter than Data / Single-Character Key

The XOR algorithm has no restriction on key length; both long and short keys encrypt and decrypt correctly. Tests cover keys of various lengths, such as a single character, 3 bytes, 14 bytes, and 34 bytes; as long as the key is non-empty, round-trip restoration works.

Source: [XorHelperTests.cs#L82-L116](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Encryption/XorHelperTests.cs#L82-L116)

### String Round-Trip

Convert a string with `Encoding.UTF8.GetBytes`, pass it in, then convert the result back with `Encoding.UTF8.GetString`; suitable for sensitive fields in configuration files.

## Common Mistakes

| Wrong practice | Symptom | Correct practice |
|----------|------|----------|
| Treating the result returned by `GetXorBytes` as a new array and modifying it again | Obfuscation range misaligned | Use the return value of `GetXorBytes`, or explicitly `Array.Copy` before passing it to `GetSelfXorBytes` |
| Passing `Array.Empty<byte>()` as `code` | Throws `ArgumentException("KeyArrayCannotBeEmpty")` | Use a key of at least 1 byte |
| Assuming the portion beyond the first 220 bytes is also encrypted when using `GetQuickXorBytes` on complete data within 220 bytes | The latter part of the data is left unchanged | Use `GetXorBytes` if full encryption is needed |
| `startIndex + length` exceeds the array length | Throws `ArgumentOutOfRangeException` | Validate `startIndex + length <= bytes.Length` first |
| Using it for account passwords / transport keys | Easily broken via known-plaintext attacks | Use only for obfuscation against accidental reading; use a real symmetric encryption algorithm for confidentiality |

## Background (Optional)

The XOR operation naturally satisfies `(A ^ K) ^ K == A`, so the same interface can be used for both encryption and decryption. `QuickEncryptLength = 220` is an empirical value chosen for protocol header scenarios, a trade-off between security and performance. All public methods first perform `ArgumentNullException.ThrowIfNull` and `code.Length == 0` checks; overloads with offset/length also validate `startIndex + length <= bytes.Length`.
