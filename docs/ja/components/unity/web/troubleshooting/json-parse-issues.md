# JSON の解析結果が正しくない場合の対処法

`WebManager` が返す JSON 文字列を `ToHttpJsonResultData<T>()` で解析した後に `IsSuccess == false`、`Data == null`、`Code` が常に 0、またはフィールドの欠落が発生する場合、通常はレスポンス構造が `{"code":0,"message":"...","data":"..."}` の規約に従っていない、`data` がネストされたオブジェクトである、または `T` 型にパラメータなしコンストラクタがない／フィールド名が一致しないことが原因です。下記の診断表の項目を順に確認することで原因を特定できます。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `IsSuccess == false` かつ `Code` が 0 以外の値 | サーバー側が返したビジネスエラーコード。`data` は解析されない（ソースコードでは `Code != 0` の場合、失敗結果をそのまま返す） | ログを開いて `message` を確認し、ビジネスエラーとして処理する。下記の「Code 非 0」を参照 |
| `IsSuccess == false`、`Code == 0`、`Data == null` | 解析中に発生した例外が `catch` で飲み込まれ、`Log.Error(e)` のみが出力され、デフォルトの失敗結果が返る | Console の `Log.Error` に出力された例外スタックトレースを確認する。JSON 構造と `T` の一致をチェックする |
| `Data` が `new T()` の全デフォルト値のインスタンス | サーバーが返す `data` が空文字列で、ソースコードは `data` が空の場合にそのまま `new T()` を返す | インターフェースが実際に空の `data` を返しているか確認する。意図していない場合はレスポンス原文をチェックする |
| `Data` 内のフィールドがすべてデフォルト値だが、エラーは出ない | `data` がオブジェクトであるのに `string` として処理されて失敗、または `T` のプロパティ名と JSON フィールド名が不一致 | `T` のプロパティに `[JsonProperty("字段名")]` を追加する。下記の修正手順を参照 |
| ログにレスポンス原文がまったく表示されない | マクロ `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` が未定義 | Player Settings / スクリプトのマクロに `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` を追加して再コンパイルする |
| 逆シリアル化で直接 `JsonMapper` 例外がスローされる | `T` が `class, new()` 制約を満たさない場合や、フィールド型の誤り（日付形式、ネストされた辞書など）によるもの | `T` を最小限の再現可能なモデルに簡略化し、フィールドを一つずつ戻しながら調査する |

## 修正手順

### 1. まずレスポンスログを有効にして、生の JSON を取得する

`WebManager` はレスポンスを受信した際に生の内容をログへ出力しますが、マクロによる有効化が必要です：

- リクエストログ：`ENABLE_GAMEFRAMEX_WEB_SEND_LOG`
- レスポンスログ：`ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`

ソースコード内のレスポンスログ実装（`unityWebRequest.downloadHandler.text` が生のレスポンスボディ）：

```csharp
#if ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
                    Log.Debug($"Web Response: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)} \n Content: {unityWebRequest.downloadHandler.text}");
#endif
```

ソース: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L248-L250)

生の JSON を取得したら、統一レスポンス構造と比較してください。このステップで大部分の「解析が正しくない」問題を解決できます。

### 2. レスポンスが統一構造 `{"code", "message", "data"}` に準拠していることを確認する

パーサーはこの 3 つのフィールド名に強く依存しており、`JsonProperty` によってバインドされます：

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class HttpJsonResult
{
    /// <summary>
    /// レスポンスコード。0 は成功
    /// </summary>
    [JsonProperty("code")]
    public int Code { get; set; }

    /// <summary>
    /// レスポンスメッセージ
    /// </summary>
    [JsonProperty("message")]
    public string Message { get; set; }

    /// <summary>
    /// レスポンスデータ。
    /// </summary>
    [JsonProperty("data")]
    public string Data { get; set; }
}
```

ソース: [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L8-L27)

確認ポイント：

| 確認項目 | 期待値 | 不一致の場合の現れ方 |
|--------|------|--------------|
| フィールド名 | 必ず `code` / `message` / `data` であること | フィールドの欠落または常にデフォルト値になる |
| `code` | 0 は成功を示す | 0 以外の場合 `IsSuccess` は常に `false` になる |
| `data` | 文字列であることが期待される（ネストされた JSON の文字列形式） | オブジェクトリテラルが直接来る場合、`Data` の解析で異常が発生する可能性がある |

サーバーが返すトップレベルのフィールド名が異なる場合（例：`status`/`msg`/`result`）、まずサーバー側にこの規約に従って返させるか、独自にカスタム構造へ逆シリアル化する必要があり、`ToHttpJsonResultData<T>()` をそのまま使用することはできません。

### 3. `T` を制約に適合させ、フィールドを正しくマッピングする

`ToHttpJsonResultData<T>` の拡張メソッドのシグネチャと内部の解析ロジック：

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // JSON文字列をHttpJsonResultオブジェクトに逆シリアル化する
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // レスポンスコードが成功を示しているか確認する
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // デフォルトの失敗結果を返す
        }

        resultData.IsSuccess = true; // 成功フラグを設定する
        // データ部分を逆シリアル化する。データが空の場合は型Tのデフォルトインスタンスを返す
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // 例外を捕捉してエラー情報を出力する
        Log.Error(e);
    }

    return resultData; // 結果データを返す
}
```

ソース: [HttpJsonResultHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultHelper.cs#L20-L48)

`T` を調査する際のチェックリスト：

1. `T` は `class` であり、パラメータなしコンストラクタを持つ必要があります（`where T : class, new()`）。構造体や抽象クラスは使用できません。
2. `T` のプロパティ名は `data` 内の JSON フィールド名と一致している必要があります。一致しない場合は `[JsonProperty("字段名")]`（LitJSON が提供する `GameFrameX.LitJSON.Runtime.JsonProperty`）を追加します。
3. `data` が空文字列の場合に得られるのは `new T()` です。「全フィールドがデフォルト値」を解析失敗と誤判断しないでください――これは実際にはソースコードの既定の動作です。
4. 解析中の例外は `catch` された後、`Log.Error(e)` のみが出力され、`IsSuccess` は `false` のまま、`Code` は 0 のままになります。この組み合わせが見られた場合は、まず Console の例外ログを確認してください。

### 4. `Code 非 0` の場合はビジネスエラーとして処理する

`HttpJsonResultData<T>` が呼び出し元に返すフィールドの意味：

| フィールド | 型 | 説明 |
|------|------|------|
| `IsSuccess` | `bool` | 成功したかどうか。デフォルトは `false` |
| `Code` | `int` | レスポンスコード。0 は成功、0 以外はサーバー側のビジネスエラーコード |
| `Data` | `T` | 成功時は逆シリアル化されたデータ。失敗時はデフォルト値または `null` |

ソース: [HttpJsonResultData.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultData.cs#L8-L28)

`Code` が 0 以外の場合、それはサーバーが返したビジネスエラーを意味し、`Data` は解析されません。`Code` と `message`（生のレスポンスログから確認可能）に基づいて、適切な通知やリトライを行う必要があります。

## 検証

1. `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` マクロを定義してリクエストを再送し、ログ内のレスポンス原文が `{"code":0,"message":"...","data":"..."}` 構造に準拠していることを確認する。
2. レスポンス原文に対して `.ToHttpJsonResultData<T>()` を呼び出し、`IsSuccess == true` になることを検証する。
3. `Data` のプロパティ値が `data` フィールドの内容と一致しているかをフィールドごとに確認する（ネストされたオブジェクトを含む）。
4. リクエスト／レスポンスのマクロを同時に有効にすると、`WebManager` は完全なリクエストヘッダーとフォームを出力するため、「リクエストパラメータの誤りによってサーバーが誤った構造を返す」という可能性をさらに排除できます。
