# How to Choose the Resource Play Mode (PlayMode)

The resource play mode (`EPlayMode`) determines how YooAsset loads assets at startup. Simply set the `GamePlayMode` field in the `StartupOptions` asset, and the startup flow will automatically sync it to `AssetComponent` before loading resources.

## Prerequisites

- The `StartupOptions` asset has been created via the `GameFrameX/Startup Options` menu.
- The `GameFrameX.Asset` component is installed and registered to `GameEntry` (registered by default by the framework).
- The project uses YooAsset (the framework's `EPlayMode` comes from the `YooAsset` namespace).

## Steps

1. Open the `StartupOptions` asset in the project (anywhere under `Assets/`).
2. Find the **GamePlayMode** field under the **Asset** category.
3. Select the target enum value; see the table below for common values and their uses.

| Enum Value | Meaning | Typical Scenario |
|---|---|---|
| `EditorSimulateMode` | Editor simulate mode, reads resources directly from the in-project AssetDatabase without using resource packages | Purely local debugging inside the Unity Editor |
| `OfflinePlayMode` | Offline mode, loads pre-built local resource packages without network access | Standalone releases, intranets without a backend |
| `HostPlayMode` | Host mode, pulls resource packages from a remote CDN + local caching | Regular hot-updatable mobile/PC releases |
| `WebPlayMode` | Web mode, resource loading adapted for WebGL | WebGL platform |

Field definition location (with source code link):

```csharp
[Header("Asset")] [Tooltip("Resource play mode. The startup flow will sync it to the Asset component before loading resources.")]
public EPlayMode GamePlayMode = EPlayMode.EditorSimulateMode;
```

At startup, the framework reads this field and syncs it to `AssetComponent`:

```csharp
private static void ApplyAssetPlayMode(StartupOptions options)
{
    GameEntry.GetComponent<AssetComponent>().GamePlayMode = NormalizeAssetPlayMode(options.GamePlayMode);
}
```

## Common Variants

### Select EditorSimulateMode in the Editor, Automatically Rewritten After Building

When debugging in the editor, `EditorSimulateMode` is usually selected. `NormalizeAssetPlayMode` automatically downgrades it to `HostPlayMode` in non-Editor environments, so no manual switching is needed.

```csharp
private static EPlayMode NormalizeAssetPlayMode(EPlayMode playMode)
{
#if !UNITY_EDITOR
    if (playMode == EPlayMode.EditorSimulateMode)
    {
        playMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    playMode = EPlayMode.WebPlayMode;
#endif
#endif
    return playMode;
}
```

Source: [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L132-L144)

### Differentiating Flow Branches: Offline vs EditorSimulate

In the startup flow, different `PlayMode` values take different update/patch paths; no manual branching is needed in business code:

- `OfflinePlayMode`: skips remote manifest updates in [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L42).
- `EditorSimulateMode`: takes the simulated manifest branch in [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L71).

### WebGL Forces WebPlayMode

As long as the build target is WebGL, no matter what you set, `NormalizeAssetPlayMode` will force-rewrite it to `WebPlayMode` (see the `#if UNITY_WEBGL` block in the code snippet above).

## Common Errors

| Symptom | Cause | Fix |
|---|---|---|
| Resources not found after the player build starts | Mistakenly assuming `EditorSimulateMode` can also be used for release builds | Non-Editor environments automatically downgrade to `HostPlayMode`; make sure the CDN URL and resource package version flow are correctly configured |
| WebGL resource loading fails | Still using a non-Web mode such as `HostPlayMode` | After switching the build target to WebGL, the framework automatically changes it to `WebPlayMode`; no manual change needed |
| Offline mode still attempts to connect to the network | `OfflinePlayMode` configured for a scenario that requires hot updates | Only use `OfflinePlayMode` in standalone/no-backend scenarios |
| `GamePlayMode` field not found in `StartupOptions` | Not using the latest asset, or the field was renamed | Re-create the asset via `GameFrameX/Startup Options` |

## Background (Optional)

The field name `GamePlayMode` was chosen to avoid clashing with the same-named property on `AssetComponent`. The default value `EditorSimulateMode` lets developers run the flow directly in the Unity Editor; after building, `NormalizeAssetPlayMode` automatically downgrades it to a publishable mode, preventing "developer conveniences" from accidentally shipping in player builds. `StartupOptions` is maintained directly in the project as a ScriptableObject (SO) via `[CreateAssetMenu]`.
