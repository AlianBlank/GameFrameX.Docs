# Querying Whether Files and Directories Exist

`BlankReadAssets` provides two static methods, `FileExists` and `DirectoryExists`, used to determine at runtime whether a file or directory under `StreamingAssets` exists. They work correctly on Android (directly reading the APK), in the editor, and on other platforms (loose files). The first call will automatically invoke `Initialize`.

## Prerequisites

- The `com.gameframex.unity.readassets` package is installed.
- The `StreamingAssets` directory exists in the project (no manual initialization is required at runtime; the first API call completes it automatically).

## Steps

1. To check whether a file exists, pass in a path relative to `StreamingAssets`:

```csharp
using GameFrameX.ReadAssets.Runtime;

bool exists = BlankReadAssets.FileExists("configs/level1.json");
if (exists)
{
    // Safely proceed with OpenRead / LoadAssetBundle etc.
}
```

2. To check whether a directory exists, use a relative path as well (starting or ending with `/` is fine; it will be normalized internally):

```csharp
using GameFrameX.ReadAssets.Runtime;

bool dirExists = BlankReadAssets.DirectoryExists("configs/");
```

## API Quick Reference

| Method | Signature | Description |
|------|------|------|
| `FileExists` | `static bool FileExists(string path)` | Checks whether a file relative to `StreamingAssets` exists |
| `DirectoryExists` | `static bool DirectoryExists(string path)` | Checks whether a directory relative to `StreamingAssets` exists |

Both methods are marked with `[Preserve]` and are delegated to the platform implementation (`EditorImpl` / `ApkImpl` / `LooseFilesImpl`) after automatic initialization via `EnsureInitialized()`.

## Common Variations

- In the editor, if you want to check the existence of `StreamingAssets` inside an external APK, you need to call `InitializeWithExternalApk(apkPath)` first, and then use the same `FileExists` / `DirectoryExists`.
- On Android, the path check inside the APK scans the APK's directory tree (`ApkImpl.DirectoryExists` internally uses `GetDirectoryIndex`), so there is no need to worry about case sensitivity or compression status.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Always returns `false`, but the file does exist | The path was passed as an absolute path or includes the `Application.streamingAssetsPath` prefix | Only pass a path relative to `StreamingAssets`, e.g. `"config.json"` instead of `Application.streamingAssetsPath + "/config.json"` |
| Paths with backslashes or extra `/` cause misjudgment | Differences in platform path separators | Directly pass a relative path separated by `/`; the utility internally normalizes via `PathUtil.NormalizeRelativePath` |
| Returns `true` on Android but subsequent `OpenRead` throws an exception | The file is marked as compressed by Unity inside the APK | Listen for the `BlankReadAssets.CompressedStreamingAssetFound` event and use `UnityWebRequest` to read instead |

## Background (Optional)

Platform dispatch is selected by the conditional compilation at the top of `BlankReadAssets.cs`: `UNITY_EDITOR` goes through `EditorImpl` (supports APK mode / external directory), `UNITY_ANDROID` goes through `ApkImpl` (locates via binary search inside the APK), and other platforms go through `LooseFilesImpl` (directly accesses the file system). `DirectoryExists` determines inside the APK by using the pre-built path index `GetDirectoryIndex`, so it does not trigger actual decompression.
