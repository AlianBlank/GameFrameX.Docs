# What to Do When Parameters Are Null

When calling methods of `GlobalConfigComponent` or accessing fields of response objects, you may frequently encounter `ArgumentNullException` or read `null` values. This page explains the source of each null, how to identify it, and how to fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Calling `SetOriginalData(null)` throws `ArgumentNullException: data` | The parameter is `null`; the method explicitly rejects it | Check for non-null before calling, or pass an empty string `""` |
| Calling `SetGlobalConfig(null)` throws `ArgumentNullException: globalInfo` | The parameter is `null`; the method explicitly rejects it | Use deserialization to obtain a non-null object first, then pass it in |
| Reading fields like `ResponseGlobalInfo.CheckAppVersionUrl` returns `null` | The field does not exist in the JSON; the deserialization result defaults to `null` | Check for null before accessing; agree with the server that the field is non-null, or fill in default values after deserialization |
| `RequestBase.Language / AppVersion / Platform` and other fields are `null` | The request object's properties are not assigned | Assign values to `RequestBase` subclass properties before making the request |

## Fix Steps

### 1. `SetOriginalData` throws `ArgumentNullException: data`

`GlobalConfigComponent.SetOriginalData` directly throws an exception when the parameter is `null`.

```csharp
public void SetOriginalData(string data)
{
    if (data == null)
    {
        throw new ArgumentNullException(nameof(data));
    }
    m_originalData = data;
}
```

Fix:

```csharp
if (!string.IsNullOrEmpty(rawJson))
{
    component.SetOriginalData(rawJson);
}
```

### 2. `SetGlobalConfig` throws `ArgumentNullException: globalInfo`

`SetGlobalConfig` also throws an exception when the parameter is `null`.

Fix: Ensure the object passed in is obtained via deserialization, not `null`. If it is retrieved from the network, perform a non-null check before assignment.

### 3. Response object fields are `null`

All string properties of `ResponseGlobalInfo`, `ResponseGameAppVersion`, and `ResponseGameAssetPackageVersion` default to `null`; only fields actually returned by the server will have values.


### 4. `RequestBase` fields are `null`

All properties of `RequestBase` have no default values and need to be assigned by the caller before making the request.

## Verification

- Before calling `SetOriginalData` / `SetGlobalConfig`, guard with `string.IsNullOrEmpty` or `!= null` to confirm that `ArgumentNullException` is no longer thrown.
- Use `?.` and `string.IsNullOrEmpty` on response fields to confirm that null values are handled correctly instead of triggering `NullReferenceException`.
- For `RequestBase` subclasses, iterate through all `string` properties to confirm there are no `null`s before making the request.
