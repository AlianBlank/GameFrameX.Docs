# 注册并处理客户端消息(MessageId / Handler)

本文展示如何在 GameFrameX.Server 中通过 `MessageId` 注册并处理客户端发来的消息——只需要新建一个继承自 `BaseMessageHandler` 的类,并用 `[MessageMapping]` 标注请求消息类型即可,框架启动时会自动扫描并完成派发。

## 前置条件

- 消息处理类必须定义在 `GameFrameX.Hotfix` 项目中(架构分析器会强制校验,违反时编译报错 `GFX0006`)。
- 类必须标记为 `sealed`(违反时报告 `GFX0010`),且类型名必须以 `Handler` 结尾(违反时报告 `GFX0012`)。
- 已通过 `.proto` 文件生成请求/响应的消息类型(例如 `ReqLogin`、`RespLogin`),且在目标项目里能被引用。

## 操作步骤

1. 在 `GameFrameX.Hotfix` 下创建处理器类,继承 `BaseMessageHandler<Req, Resp>`,并在类上用 `[MessageMapping(typeof(Req))]` 指明要处理的请求类型。

```csharp
// GameFrameX.Hotfix/Logic/Login/LoginHandler.cs
using GameFrameX.Net;
using GameFrameX.Hotfix;

[MessageMapping(typeof(ReqLogin))]
[MessageResponse(typeof(RespLogin))]
internal sealed class LoginHandler : BaseMessageHandler<ReqLogin, RespLogin>
{
    public override async Task<RespLogin> Handle(ReqLogin request, NetWorkChannel channel)
    {
        var resp = new RespLogin { Code = 0, Message = "ok" };
        return await Task.FromResult(resp);
    }
}
```

Source: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L130-L140)

2. 框架启动后,`AppStartUpHotfixGameByMain` 会在收到消息包时从 `HotfixManager` 取出对应的 `Handler`,并把 `MessageId` 解析出来的请求对象传给你:

```csharp
// 框架侧的派发核心逻辑
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
if (handler == null)
{
    LogHelper.Error($"找不到[{messagePackage.Header.MessageId}][{messagePackage.MessageType}]对应的handler");
    return;
}
await InvokeMessageHandler(handler, messagePackage.DeserializeMessageObject(), netWorkChannel);
```

Source: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L130-L141)

3. 网关服务(`AppStartUpHotfixGameByGateWay`)的派发同样使用 `HotfixManager.GetTcpHandler(message.MessageId)`,保证客户端到后端的消息处理路径一致:

```csharp
var handler = HotfixManager.GetTcpHandler(message.MessageId);
if (handler == null)
{
    LogHelper.Error($"找不到[{message.MessageId}][{messageObject.GetType()}]对应的handler");
    return;
}
```

Source: [AppStartUpHotfixGameByGateWay.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs#L123-L128)

## 常见变体

- **玩家级消息**(绑定到具体玩家 Actor):用 `[MessageMapping]` + 继承 `BaseMessageHandler`,由框架把消息路由到对应玩家的 Mailbox。
- **全局级消息**(绑定到服务器 Actor):同样用 `[MessageMapping]`,但处理器里通常只做无状态处理,例如心跳。

```csharp
// 玩家级(示例来自 README.ja.md)
// Player-level message (bound to a specific player Actor)
[MessageMapping(typeof(ReqAddItem))]
internal sealed class AddItemHandler

// 全局级(示例来自 README.ja.md)
// Global-level message (bound to the server Actor)
[MessageMapping(typeof(ReqHeartBeat))]
internal sealed class HeartBeatHandler
```

Source: [README.ja.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.ja.md#L362-L376)

- **RPC 双向调用**:在请求/响应双方都标注 `[MessageRpcMapping]`,由 `MessageRpcMappingAssemblyAnalyzer` 在编译期校验。处理器必须定义在 `GameFrameX.Hotfix`,违反时报告 `GFX0007`。

## 常见错误

| 症状 / 报错码 | 原因 | 修复 |
|---|---|---|
| 运行时日志:`找不到[xxx][yyy]对应的handler` | `[MessageMapping]` 未扫描到处理器 | 确认类在 `GameFrameX.Hotfix` 且以 `Handler` 结尾,重新编译 |
| 编译报错 `GFX0006` | 处理器不在 `GameFrameX.Hotfix` | 将类文件移到 `GameFrameX.Hotfix` 项目 |
| 编译报错 `GFX0007` | RPC 处理器不在 `GameFrameX.Hotfix` | 将 `[MessageRpcMapping]` 处理器移到 `GameFrameX.Hotfix` |
| 编译报错 `GFX0010` | 处理器未标记 `sealed` | 给类加上 `sealed` |
| 编译报错 `GFX0012` | 类名不以 `Handler` 结尾 | 把类名改为 `XxxHandler` |

## 背景(可选)

`GameFrameX.Architecture.Analyzers` 在编译期通过 `MessageMappingAssemblyAnalyzer`、`MessageMappingNameAnalyzer`、`MessageMappingSealedAnalyzer`、`MessageRpcMappingAssemblyAnalyzer` 四个分析器强制校验处理器放置位置、命名规范和密封性,确保运行时 `HotfixManager.GetTcpHandler(MessageId)` 一定能找到目标。
