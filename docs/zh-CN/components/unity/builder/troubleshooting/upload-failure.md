# 对象存储上传失败怎么办

当构建流程触发了 `-IsUploadLogFile` 或 `-IsUploadAsset`,但日志/资源没有出现在对象存储桶里时,按本页诊断表逐项排查。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志出现 `The type or namespace name 'ObjectStorageUploadManager' could not be found` | 工程未启用对象存储模块 | 在 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 宏对应的 Package Manager 中安装并启用对象存储组件 |
| 命令行未传凭证,执行后无任何上传行为 | `-IsUploadLogFile` 漏传,或对应宏未启用 | 见下文"开关未开"小节 |
| 上传调用抛出 403 / SignatureDoesNotMatch | 凭证不匹配或读写权限不足 | 见下文"凭证或权限错误"小节 |
| 抛出 `NoSuchBucket` / `InvalidBucketName` | 桶名拼写错误或桶未在指定区域创建 | 见下文"桶名或 Endpoint 错误"小节 |
| 上传完成但桶里看不到文件 | Endpoint 区域错配,文件传到另一区域 | 见下文"区域错配"小节 |
| 构建过程中断在 `BuildReady` 阶段 | 调用 `UploadFile` 时抛出未捕获异常 | 见下文"异常被吞掉"小节 |

## 修复步骤

### 1. 开关未开(最常见)

构建脚本只在两个条件同时满足时才会调用上传:[`Builder.BuildReady.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L44-L49) 里 `if (_builderOptions.IsUploadLogFile)` 包裹了 `#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE`。也就是说,即便你传了 `-IsUploadLogFile`,如果项目未定义 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 宏,代码会被编译器完全剔除,运行时无任何输出。

确认方式:

1. 确认命令行里包含 `-IsUploadLogFile`(无需值,见 [`Builder.BuildParamsParse.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L94-L96))。
2. 确认 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 已在项目的 `Scripting Define Symbols` 中定义。
3. 确认 `GameFrameX.ObjectStorage` 包已通过 Package Manager 安装,否则 `ObjectStorageUploadManager` 类型找不到。

```text
-ExecuteMethod GameFrameX.Builder.Editor.Builder.BuildReady \
-IsUploadLogFile \
-ObjectStorageKey <your-key> \
-ObjectStorageSecret <your-secret> \
-ObjectStorageBucketName <your-bucket> \
-ObjectStorageEndPoint <your-endpoint>
```

参数定义见 [`BuilderOptions.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40)。四个对象存储字段全部默认为空字符串,缺一会让 SDK 在请求时直接抛异常。

### 2. 凭证或权限错误

`ObjectStorageUploadManager.UploadFile` 内部使用传入的 Key/Secret 拼签名。如果密钥复制时少字符、多了空格,或者子账号没有该桶的 `PutObject` 权限,会直接抛 `403 SignatureDoesNotMatch` 或 `AccessDenied`。

1. 重新从对象存储控制台复制 Key 和 Secret,避免手工输入。
2. 给该子账号授予桶的读写权限(阿里云 OSS / 腾讯云 COS / MinIO 概念一致)。
3. 如果使用的是临时 STS 凭证,确认 `ObjectStorageKey/Secret` 是 STS 三元组的 `AccessKeyId/SecretAccessKey`,而不是 `SessionToken`。

### 3. 桶名或 Endpoint 错误

`ObjectStorageBucketName` 必须是桶在控制台里的全名,`ObjectStorageEndPoint` 必须是该桶所在区域的外网/内网域名。两者不匹配时会抛 `NoSuchBucket` 或 `InvalidBucketName`。

1. 登录对象存储控制台,核对桶名与所在地域。
2. 把 `ObjectStorageEndPoint` 改为该地域官方文档给出的 Endpoint(例如阿里云华东 1:`oss-cn-hangzhou.aliyuncs.com`)。
3. 重新触发一次构建,确认控制台 `Object Storage → 文件管理` 能看到上传的日志文件。

### 4. 区域错配

请求成功、控制台返回 200,但桶里看不到文件——通常是 Endpoint 指向另一个区域,文件被传到"对"的桶在另一个区域的同名桶(私有云/跨区复制场景下常见)。

1. 核对 `ObjectStorageEndPoint` 与桶所属 Region 完全一致。
2. 在控制台"桶列表"按区域筛选,确认目标桶在本区域内存在。

### 5. 异常被吞掉

`BuildReady` 中调用 `UploadFile` 时如果发生异常,默认会让构建流程中断,日志里能看到 `ObjectStorageUploadManager` 抛出的原始异常堆栈。把堆栈第一行关键字贴进诊断表对应行,按上面 1-4 步处理。

如果异常被外部 Jenkins/CI 脚本吞掉看不到堆栈,可以临时在 `BuildReady` 之后追加一行 `Debug.Log($"Upload finished: {_builderOptions.LogFilePath}")`,验证代码是否真的进入上传分支。

## 验证

1. 重新跑一次构建,确保命令行带齐 `-IsUploadLogFile` 与四个对象存储参数。
2. 在对象存储控制台的对应桶里,按上传时间排序,确认日志文件出现。
3. 下载该日志文件,内容应包含本次构建的 `BuildReady Start` / `BuildReady End` 行,与本地 Unity 控制台输出一致。

## 背景(可选)

上传调用全部委托给外部 `GameFrameX.ObjectStorage` 包的 `ObjectStorageUploadManager.UploadFile`。本仓库只负责透传四个命令行参数到 [`BuilderOptions`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40),并不直接操作任何 SDK。
