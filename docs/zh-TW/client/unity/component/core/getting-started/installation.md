# 安裝與專案接入

本指南介紹如何把 GameFrameX Unity 核心包接入到一個 Unity 專案中，並在場景腳本裡取得框架元件。完成後，你可以在 `GameManager` 中透過 `GameEntry.GetComponent<T>()` 拿到物件池、引用池等元件並直接使用擴充方法。

## 前置條件

| 項目 | 要求 |
|------|------|
| Unity 版本 | 2019.4 或更高([package.json](/package.json#L7)) |
| .NET 版本 | .NET Standard 2.0+ |
| 平台 | Windows / macOS / Linux / iOS / Android / WebGL |
| 專案類型 | Unity 標準工程（已產生 `Packages/manifest.json`） |

## 操作步驟

### 方式一：Unity Package Manager 圖形介面（推薦）

1. 開啟 Unity 編輯器，開啟目標專案。
2. 頂部選單選擇 `Window` → `Package Manager`。
3. 點擊左上角 `+` 按鈕，選擇 `Add package from git URL...`。
4. 在輸入框中貼上：`https://github.com/GameFrameX/com.gameframex.unity.git`
5. 點擊 `Add`，等待 Unity 下載並完成匯入。

Source: [README.zh-CN.md](/README.zh-CN.md#L353-L359)

### 方式二：手動下載 Release 包

1. 開啟 [Releases 頁面](https://github.com/GameFrameX/com.gameframex.unity/releases) 下載最新的 `.zip` 或 `.tar.gz`。
2. 把壓縮包解壓縮到 Unity 工程的根目錄下的 `Packages/` 資料夾中。
3. 返回 Unity 編輯器，Unity 會自動識別並匯入。

Source: [README.zh-CN.md](/README.zh-CN.md#L361-L364)

### 方式三：透過 scopedRegistries 引入（UPM）

編輯工程根目錄的 `Packages/manifest.json`，加入 scoped registry 設定，再在 `dependencies` 中宣告版本：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity": "1.10.1"
  }
}
```

`scopes` 控制透過此註冊表解析的命名空間：只有以 `com.gameframex` 開頭的套件才會從 GameFrameX 註冊表取得，其他依賴仍走 Unity 預設註冊表。

Source: [README.zh-CN.md](/README.zh-CN.md#L366-L387)

### 驗證安裝

在任意 `MonoBehaviour` 的 `Start()` 裡呼叫一次元件取得，能正常返回即表示接入成功：

```csharp
using GameFrameX.Runtime;

public class GameManager : MonoBehaviour
{
    void Start()
    {
        var objectPool = GameEntry.GetComponent<ObjectPoolComponent>();
        var referencePool = GameEntry.GetComponent<ReferencePoolComponent>();

        transform.SetPositionX(10f);
        gameObject.SetActiveOptimized(true);
    }
}
```

## 常見變體

| 場景 | 調整方式 |
|------|---------|
| 鎖定到具體版本 | 在 `manifest.json` 的 `dependencies` 中將 `"com.gameframex.unity"` 寫為精確版本號，例如 `"1.10.1"`，避免跟隨 Git URL 的 HEAD。 |
| 接入國內/海外小遊戲平台 | 保留 Editor 模組下的 MiniGame 工具與 `BuildProduct` 管線，不要在 iOS/Android 之外的平台把它們排除。 |
| 內網/離線環境 | 優先使用方式二，把 Release 包拷貝到內網再解壓縮到 `Packages/`。 |
| 需要 LiteJSON | 無需額外安裝，框架在 `dependencies` 中已宣告 `com.gameframex.unity.litjson: 1.2.0` 作為傳遞依賴。 |

Source: [package.json](/package.json#L21-L30)

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| UPM 新增 Git URL 後報 `Unable to find package` | URL 寫錯或網路無法存取 GitHub | 核對 URL 為 `https://github.com/GameFrameX/com.gameframex.unity.git`，或在 `scopedRegistries` 方式中把 `scopes` 設為 `com.gameframex` |
| 透過 UPM 解析不到對應版本 | 沒有新增 `scopedRegistries`，或 `scopes` 拼錯 | 按方式三補全 `scopedRegistries`，確認 `scopes` 是 `["com.gameframex"]` |
| `GameEntry.GetComponent<...>()` 報空引用 | 場景中沒有掛載框架入口預製體，或入口元件未啟用 | 在場景裡加上框架啟動元件後再呼叫，詳見《快速上手》 |
| 編譯報缺 LitJSON | 刪除依賴或版本衝突 | 重新引入框架或單獨恢復 `com.gameframex.unity.litjson: 1.2.0` |
| Unity 版本低於 2019.4 | 框架最低支援版本不符 | 升級 Unity 至 2019.4 或更高([package.json](/package.json#L7)) |

## 背景（選用）

`com.gameframex.unity` 是 GameFrameX 框架的核心包，透過 UPM 同時宣告了執行階段依賴（`com.gameframex.unity.litjson`）以及若干 Unity 內建模組（`assetbundle`、`audio`、`jsonserialize`、`unitywebrequest`、`androidjni`、`animation`、`imgui`）。Unity 2019.4+ 是 `package.json` 中明確要求的最低版本；不滿足時 UPM 會拒絕解析依賴。
