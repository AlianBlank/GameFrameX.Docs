# 執行模式不支援或初始化失敗怎麼辦

`AssetManager` 在初始化資源包時會按 `EPlayMode` 分派到四個具體初始化方法(Editor 模擬/單機/連線/WebGL);模式值不在列舉內會直接擲出例外，模式與平台不匹配、URL 缺失或 YooAsset 未先初始化也會導致初始化失敗。下面給出常見症狀與對應修復。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `ArgumentOutOfRangeException: Unsupported play mode: <值>` | `PlayMode` 不在 `EPlayMode` 四個合法值內 | 見下文「修復步驟 1」 |
| 打包/真機上使用 `EditorSimulateMode`,資源載入報錯 | 非編輯器環境自動被強制改為 `HostPlayMode`,但 URL 未設定 | 見下文「修復步驟 2」 |
| WebGL 平台選了 `HostPlayMode` 等非 Web 模式，初始化失敗 | WebGL 強制使用 `WebPlayMode`,非 Web 模式不被支援 | 見下文「修復步驟 3」 |
| `hostServerURL is null` 或資源包無法建立 | 連線/Web 模式下 URL 未傳入；YooAsset 未先初始化 | 見下文「修復步驟 4」 |
| `Asset manager is invalid.` | `_assetManager` 模組未註冊 | 見下文「修復步驟 5」 |

## 修復步驟

### 1. `PlayMode` 取值非法

`AssetManager.CreateInitializationOperationHandler` 用 `switch` 匹配四種合法模式，預設分支直接擲出例外：

```csharp
default:
{
    throw new ArgumentOutOfRangeException(nameof(PlayMode), PlayMode, $"Unsupported play mode: {PlayMode}");
}
```

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L42-L46)

確認 `AssetComponent.GamePlayMode` 欄位(Inspector 中名為 `m_GamePlayMode`)的值在 `EditorSimulateMode / OfflinePlayMode / HostPlayMode / WebPlayMode` 四個列舉值之內，且沒有被外部腳本錯誤地賦成 `(EPlayMode)999` 之類的整數。

### 2. 執行時誤用 `EditorSimulateMode`

`AssetComponent.Awake` 在非編輯器環境會把 `EditorSimulateMode` 強制改成 `HostPlayMode`,而連線模式必須提供下載 URL:

```csharp
#if !UNITY_EDITOR
    if (GamePlayMode == EPlayMode.EditorSimulateMode)
    {
        GamePlayMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    GamePlayMode = EPlayMode.WebPlayMode;
#endif
#endif
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L65-L73)

修復：出包前把 `GamePlayMode` 改成與目標平台匹配的合法值(單機版用 `OfflinePlayMode`,連線版用 `HostPlayMode` 並填好 `hostServerURL`)。

### 3. WebGL 平台選了非 Web 模式

WebGL 會被強制改寫為 `WebPlayMode`;若仍要按 `HostPlayMode` 走 CDN/小遊戲方案，需要在呼叫 `InitPackageAsync` 時傳入正確的 `hostServerURL` 與 `fallbackHostServerURL`,並確保對應小遊戲平台巨集(`ENABLE_DOUYIN_MINI_GAME`、`ENABLE_WECHAT_MINI_GAME`、`ENABLE_KUAISHOU_MINI_GAME` 等)被啟用，以走相應的 `ByteGame/Wechat/Kuaishou` 檔案系統分支(參見 `InitializeYooAssetWebPlayMode`)。

### 4. URL 缺失或 YooAsset 未初始化

`AssetManager.Initialize` 必須先於 `InitPackageAsync` 呼叫，否則 YooAsset 內部狀態不完整：

```csharp
public void Initialize()
{
    Log.Info($"资源系统运行模式：{PlayMode}");
    YooAssets.Initialize();
    YooAssets.SetOperationSystemMaxTimeSlice(Milliseconds > 0 ? Milliseconds : 30);
    Log.Info("Asset Init Over");
}
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L45-L54)

`InitPackageAsync` 會對入參做 `NotNull` 驗證，任一為空會擲出 `ArgumentNullException`:

```csharp
GameFrameworkGuard.NotNull(packageName, nameof(packageName));
GameFrameworkGuard.NotNull(hostServerURL, nameof(hostServerURL));
GameFrameworkGuard.NotNull(fallbackHostServerURL, nameof(fallbackHostServerURL));
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L69-L71)

修復：確認 `AssetComponent.Start` 已觸發(它會呼叫 `_assetManager.Initialize()`),再呼叫 `InitPackageAsync(packageName, host, fallbackHost, isDefaultPackage:true)` 時傳入合法 URL。

### 5. `Asset manager is invalid.`

`AssetComponent.Awake` 取不到 `IAssetManager` 模組時列印致命日誌並直接傳回：

```csharp
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L82)

修復：確認 GameFrameX 框架入口(`GameEntry`)已在場景中，且 `AssetComponent` 的 `ImplementationComponentType`/`InterfaceComponentType` 設定正確，框架能反射建構出 `AssetManager` 實作類別。

## 驗證

1. 在 Unity Console 中確認能看到日誌 `资源系统运行模式：<PlayMode>` 和 `Asset Init Over`,兩者都出現說明 `Initialize()` 走完。
2. 呼叫 `InitPackageAsync` 後，等待 `InitializationOperation` 完成；若傳回 `true` 且 `Status == EOperationStatus.Succeed`,表示資源包初始化成功。
3. 觸發一次 `LoadAssetAsync`,確認能取得 `AssetHandle`,且 `LastError` 為空。
4. 在出包平台(WebGL/Android/iOS)重複上述步驟，確認沒有再擲出 `Unsupported play mode` 或 `hostServerURL is null`。
