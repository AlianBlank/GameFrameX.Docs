# 設定程式碼簽署

在 `XCodeConfig.json` 設定檔的 `signing` 節點填入 Team ID、套件名稱、簽署身分等欄位，Unity 匯出 iOS 專案後，建置後處理會自動把這些值寫入 Xcode 主 Target(Unity-iPhone)的建置設定，無需手動在 Xcode 裡修改簽署。

## 前置條件

- Unity iOS 平台已可正常打包(PostProcessBuildPlayer 階段會執行本元件)。
- 已在專案中放置 `XCodeConfig.json` 設定檔；沒有的話可參考儲存庫中的 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) 或 [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json) 建立。
- 手動簽署(Manual)模式需要事先在 Apple Developer 後台建立好 Provisioning Profile,並在本機安裝對應憑證。

## 操作步驟

1. 開啟(或新增)專案中的 `XCodeConfig.json`,在頂層加入 `signing` 節點。儲存庫內建 Demo 的寫法如下：

```json
{
  "swiftBridging": true,
  "signing": {
    "teamId": "XXXXXXXXXX",
    "codeSignStyle": "Automatic",
    "provisioningProfileSpecifier": ""
  }
}
```

Source: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L2-L9)

2. 按下表填寫 `signing` 內的欄位。全部欄位都是可選的，留空或缺失時該建置設定保持 Unity 匯出時的預設值;`signing` 節點只在主專案(Unity-iPhone Target)上生效。

| 欄位 | 對應建置設定 | 說明 |
|------|--------------|------|
| `teamId` | `DEVELOPMENT_TEAM` | Apple Developer Team ID |
| `bundleId` | `PRODUCT_BUNDLE_IDENTIFIER` | 應用程式套件名稱 |
| `codeSignIdentity` | `CODE_SIGN_IDENTITY` | 簽署憑證身分 |
| `codeSignStyle` | `CODE_SIGN_STYLE` | 簽署方式，`Automatic` 或 `Manual` |
| `provisioningProfileSpecifier` | `PROVISIONING_PROFILE_SPECIFIER` | 描述檔名稱(僅 Manual 模式需要) |

欄位含義與映射關係均來自範本檔案中的註解與 `SetSigning` 的實作：

```csharp
private static void SetSigning(PBXProject proj, string targetGuid, Hashtable signing)
{
    if (signing == null) return;

    var teamId = signing.Get<string>("teamId");
    if (!string.IsNullOrEmpty(teamId))
    {
        proj.SetBuildProperty(targetGuid, "DEVELOPMENT_TEAM", teamId);
    }

    var bundleId = signing.Get<string>("bundleId");
    if (!string.IsNullOrEmpty(bundleId))
    {
        proj.SetBuildProperty(targetGuid, "PRODUCT_BUNDLE_IDENTIFIER", bundleId);
    }
    // codeSignIdentity / codeSignStyle / provisioningProfileSpecifier 同樣只在非空時才寫入
}
```

Source: [PostProcessBuildHelper.Signing.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Signing.cs#L15-L48)

3. 使用自動簽署時，只需 `teamId` + `codeSignStyle: "Automatic"`,Xcode 會自動管理憑證和描述檔。

4. 使用手動簽署時，補全憑證與描述檔資訊：

```json
{
  "signing": {
    "teamId": "你的TeamID",
    "bundleId": "com.yourcompany.yourapp",
    "codeSignStyle": "Manual",
    "provisioningProfileSpecifier": "你的描述檔名稱"
  }
}
```

描述檔名稱需與 Apple Developer 後台建立的 Profile 名稱一致，範本註解明確標註該欄位「僅 Manual 模式需要」(見 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json#L14-L15))。

5. 匯出 iOS 專案(或執行建置)。後處理讀取所有 `XCodeConfig.json` 並合併，隨後在主 Target 上呼叫簽署設定：

```csharp
// 設定簽署設定（只在主專案上設定）
SetSigning(project, project.GetUnityMainTargetGuid(), finalConfig.Get<Hashtable>("signing"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L96-L97)

6. 驗證：開啟產生的 Xcode 專案，選取 Unity-iPhone Target → Signing & Capabilities,確認 Team、Bundle Identifier、Provisioning Profile 與設定一致；或直接在終端機執行 `xcodebuild -showBuildSettings | grep -E "DEVELOPMENT_TEAM|CODE_SIGN"` 查看。

## 常見變體

**按渠道覆蓋簽署設定。** 後處理會先合併所有通用的 `XCodeConfig.json`,再合併渠道專屬設定 `XCodeConfig.{channel}.json`,渠道設定優先順序最高、最後合併覆蓋。因此可以為不同渠道(如不同套件名稱的馬甲包)各放一個渠道檔案，只寫 `signing` 裡的差異欄位：

```json
{
  "signing": {
    "bundleId": "com.yourcompany.app.channelA"
  }
}
```

渠道檔案命名格式與合併順序見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L76) 與 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L80-L83)。

**透過 ScriptableObject 設定。** 儲存庫還提供 `XcodeConfig` ScriptableObject(選單 `XcodeConfig/Create Settings`),可用於在 Inspector 中維護環境變數、Plist、Capabilities 等設定，見 [XcodeConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XcodeConfig.cs#L10-L31)。簽署相關的 JSON 欄位仍以 `signing` 節點為準。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 主控台輸出 `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 專案內沒有可被掃描到的 `XCodeConfig.json` | 按範本放置設定檔後再匯出 |
| 主控台輸出 `合并后的配置为空，跳过设置` | 設定檔存在但 JSON 解析結果為空 | 檢查 JSON 語法是否正確 |
| `未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json`(僅 Log) | 設定了渠道但沒有對應渠道檔案 | 屬提示資訊；需要差異設定時補建 `XCodeConfig.{channel}.json` |
| 匯出後 Xcode 中 Team 仍為空 | `teamId` 留空或寫錯欄位名(欄位非空才會寫入) | 核對欄位名拼字與大小寫:`teamId`、`bundleId`、`codeSignIdentity`、`codeSignStyle`、`provisioningProfileSpecifier` |
| 手動簽署時回報描述檔不符 | `provisioningProfileSpecifier` 與實際 Profile 名稱不一致，或本機未安裝對應憑證 | 核對 Profile 名稱並安裝憑證 |

上表中的日誌原文來自設定載入與合併流程，見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83)。

## 背景

簽署設定發生在 Unity 的 PostProcessBuild 階段：元件讀取專案內所有 `XCodeConfig.json` 合併成最終設定，解析產生的 `Unity-iPhone.xcodeproj/project.pbxproj`,僅在主 Target(UnityMainTarget)上寫入簽署相關建置設定，然後把專案寫回磁碟。所有簽署欄位都遵循「非空才寫入」的原則，因此可以只設定需要的欄位。另外，`signing.bundleId` 還會被傳給 Capabilities 處理，用於配合 entitlements 的設定(見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L116-L119))。
