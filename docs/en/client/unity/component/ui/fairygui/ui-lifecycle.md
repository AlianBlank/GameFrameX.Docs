# How It Works: UI Form Lifecycle and Loading Queue

This page explains what happens inside the framework, in order, after calling `UIManager` to open a FairyGUI UI form: singleton deduplication → instance pool reuse → asynchronous loading queue → lifecycle callbacks → group refresh, as well as the recycling logic when closing. Understanding this chain explains behaviors such as "why opening the same UI form repeatedly does not load it twice" and "why a UI form is not destroyed immediately after being closed."

## Lifecycle Sequence When Opening a UI Form

`InternalOpenUIForm` is where every UI form (whether newly loaded or reused from the pool) is truly "born". Callbacks are executed in the following order, all taken from real source code:

1. `m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData)` creates the `IUIForm`; if it returns `null`, a `GameFrameworkException("Can not create UI form in UI form helper.")` is thrown.
2. `uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen)` completes initialization; within it, `OnInitAction` calls `fui.SetGObject(uiFormInstance as GObject)` in the initialization callback to bind the GObject for `FUI`-type UI forms.
3. The UI form joins a UI group: if `uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm)` is false, `uiGroup.AddUIForm(uiForm)` is called.
4. `uiForm.OnOpen(userData)` — the callback the business side receives at the moment of opening.
5. `uiForm.BindEvent()`, `uiForm.LoadData()`, and `uiForm.UpdateLocalization()` are executed in sequence.
6. If `uiForm.EnableShowAnimation` is true, `uiForm.Show(m_UIFormShowHandler, null)` plays the show animation (see the FUI `Show` implementation below).
7. `uiGroup.Refresh()` refreshes group depth and pause state.
8. The `OpenUIFormSuccessEventArgs` success event is fired; if any step throws an exception, `OpenUIFormFailureEventArgs` is fired and the exception is rethrown.

```csharp
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);

void OnInitAction(IUIForm obj)
{
    if (obj is FUI fui)
    {
        fui.SetGObject(uiFormInstance as GObject);
    }
}

if (!uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm))
{
    uiGroup.AddUIForm(uiForm);
}

uiForm.OnOpen(userData);
uiForm.BindEvent();
uiForm.LoadData();
uiForm.UpdateLocalization();
if (uiForm.EnableShowAnimation)
{
    uiForm.Show(m_UIFormShowHandler, null);
}

uiGroup.Refresh();
```

## Loading Queue and Deduplication

`InnerOpenUIFormAsync` performs three layers of deduplication before actually initiating a load, preventing the same UI form from being loaded concurrently:

1. **Singleton mode hits an already-open UI form**: When `UseSingletonOpenMode(uiFormType)` is true, it first calls `GetUIForm(uiFormAssetName)` to find an open instance; on a hit it calls `RefocusUIForm(openedUIForm, userData)` and returns directly without loading again.
2. **Hit in the loading queue**: It iterates `m_LoadingUIForms` (a `List<UIFormLoadingObject>` with capacity 64); if asset path, asset name, and type all match, it does `await value.Task` to reuse the same loading result.
3. **Hit in the instance pool**: `m_InstancePool.Spawn(uiFormAssetName)` retrieves a reusable instance; on success, a new `++m_Serial` serial number is assigned and `InternalOpenUIForm` is executed directly (`isNewInstance: false`).

Only when all three layers miss does it call `InnerLoadUIFormAsync` to initiate the actual asset load, wrapping the result in a `UIFormLoadingObject` added to `m_LoadingUIForms`; after the `await` completes, it is removed and released via `ReferencePool.Release` in a `finally` block, ensuring the queue does not leak.

```csharp
foreach (var value in m_LoadingUIForms)
{
    if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
    {
        return await value.Task;
    }
}
```

## Asset Loading Paths: Resources vs. Bundles

`InnerLoadUIFormAsync` assigns a new serial number for each load, registers it in `m_UIFormsBeingLoaded`, then branches based on path characteristics:

- **Package name derivation**: The portion of `uiFormAssetPath` after the last `/` is used as the `packageName`; if the path contains no `/`, the entire path is the package name.
- **Already-loaded package**: If `FairyGuiPackage.Has(packageName)` is true, it goes straight to `LoadAssetSuccessCallback` to create the UI form without reloading the package.
- **Resources directory**: When `assetPath` does not contain `Utility.Asset.Path.BundlesDirectoryName`, if the package is not loaded, `FairyGuiPackage.AddPackageSync(assetPath)` loads it synchronously before creating the UI form.
- **Bundle directory**: When the package name equals the asset name, `await FairyGuiPackage.AddPackageAsync(assetPath)`; otherwise it rebuilds the path with `PathHelper.Combine(uiFormAssetPath, packageName)` and loads asynchronously, then loads the `path + "_fui"` asset (`m_AssetManager.LoadAssetAsync<UnityEngine.Object>`); only on success does it call `openUIFormInfo.SetAssetHandle(assetHandle)` and create the UI form.

```csharp
newAssetPackagePath += "_fui";
// Load from the package
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

### Load Success / Failure Callbacks

| Callback | Behavior |
|------|------|
| `LoadAssetSuccessCallback` | Checks `m_UIFormsToReleaseOnLoad` (requests cancelled during loading release their assets directly); otherwise instantiates via `m_UIFormHelper.InstantiateUIForm` and registers it in the instance pool with `m_InstancePool.Register`, then proceeds to `InternalOpenUIForm` (`isNewInstance: true`) |
| `LoadAssetFailureCallback` | Builds the error message `Utility.Text.Format("Load UI form failure, asset name '{0}', error message '{1}'.", ...)` and fires `OpenUIFormFailureEventArgs`; with no failure handler registered, it directly does `throw new GameFrameworkException(appendErrorMessage)` |

Both throw `GameFrameworkException("Open UI form info is invalid.")` when the `OpenUIFormInfo` is invalid.

## Show / Hide Animations

`FUI` (the FairyGUI UI form base class, inheriting from `UIForm`) forwards visibility operations to the associated `GObject`:

- `Show(handler, complete)`: When a handler is present, calls `handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete)`; otherwise invokes `complete?.Invoke()` directly.
- `Hide(handler, complete)`: Symmetrically uses `EnableHideAnimation` and `HideAnimationName`.
- `Visible`: Reads `GObject.visible`; it is always `false` when `GObject == null`. After `InternalSetVisible` modifies `GObject.visible`, it triggers the `OnVisibleChanged` callback followed by the `UIFormVisibleChangedEventArgs` event.
- `MakeFullScreen()`: `GObject?.asCom?.MakeFullScreen()`.

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

## Closing and Instance Recycling

`RecycleUIForm(uiForm, isDispose)` handles recycling after closing, with the following steps:

1. `uiForm.OnRecycle()` first fires the business-side recycle callback.
2. It takes `uiForm.Handle as GameObject`; if null, it returns directly (no display object to recycle).
3. It gets the `DisplayObjectInfo` component from the GameObject, then `displayObject.gOwner as GComponent`; if either is null, it returns directly.
4. `m_InstancePool.Unspawn(component)` returns the instance to the instance pool awaiting reuse; when `isDispose == true`, it additionally calls `m_InstancePool.ReleaseObject(component)` to destroy it completely.

In other words, a default close merely "returns to the pool"; the next `m_InstancePool.Spawn` hit reuses it without loading. The instance pool recycle interval has a lower bound of `10` (`m_RecycleInterval < 10` is forced to `10`).

```csharp
m_InstancePool.Unspawn(component);
if (isDispose)
{
    m_InstancePool.ReleaseObject(component);
}
```

## Troubleshooting Common Issues

| Symptom | Cause | Resolution |
|------|------|------|
| Opening the same UI form repeatedly; only the first open performs a load | Singleton mode hit via `GetUIForm` or `m_LoadingUIForms` deduplication | Expected behavior; disable singleton open mode if a new instance is required |
| Opening a UI form throws `Can not create UI form in UI form helper.` | `m_UIFormHelper.CreateUIForm` returned `null` | Check whether `uiFormType` can be created by the registered `FairyGUIFormHelper` |
| Throws `Load UI form failure, asset name '...', error message '...'` | The `_fui` asset or UI package failed to load and no failure handler was registered | Verify the derived package name against `uiFormAssetPath`, and confirm the `path_fui` asset exists |
| Throws `Open UI form info is invalid.` | The `OpenUIFormInfo` received by the success/failure callback is `null` | This is an internal framework data anomaly; check for external misuse of the callbacks |
| Memory does not drop after closing a UI form | `RecycleUIForm` by default only does `Unspawn` back to the pool | Use the close path with `isDispose` when complete destruction is needed |
