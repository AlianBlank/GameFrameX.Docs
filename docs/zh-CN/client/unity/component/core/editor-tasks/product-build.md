# 配置产品构建流程

通过 Unity 顶部菜单 `GameFrameX/Build/*` 一键导出不同平台的可发布版本,并在构建前后通过钩子注入自定义步骤(如拷贝配置、注入热更新工程、清理临时目录)。

## 前置条件

- 已安装 Unity 编辑器,工程已通过 Unity Hub 打开。
- 在 `File → Build Settings` 中预先勾选要打包的场景,否则 `EditorBuildSettings.scenes` 为空,产物不会包含任何场景。
- 需要打 Android 平台时,确保已安装对应 Build Support 模块并设置好 JDK / Android SDK。
- 如需热修复流程,确认已安装 `GameFrameX` 相关的 HotFix 编辑器扩展(命令 `HotFixEditorCompilerHelper.AddEditor()` 会自动调用)。
- 输出目录所在磁盘有写权限;Windows 平台默认产物路径见下文。

## 操作步骤

### 1. 切换构建平台

在 Unity 顶部菜单点击 `File → Build Settings`,在 `Platform` 列表中选择目标平台并点击 `Switch Platform`。菜单项会校验当前活动构建目标,平台不匹配会输出 `当前构建目标不是 XXX` 并直接返回。

### 2. 选择菜单触发构建

按目标平台,在 Unity 顶部菜单依次点击 `GameFrameX → Build → <平台名称>`,每个菜单项对应 `BuildProductHelper` 中的一个静态方法。

| 菜单项 | 对应方法 | BuildTarget | 输出位置 |
|--------|----------|-------------|----------|
| `GameFrameX/Build/Windows X64` | `BuildPlayerToWindows64BuildTarget` | `StandaloneWindows64` | `_buildPath/PlayerSettings.productName.exe` |
| `GameFrameX/Build/Windows X32` | `BuildPlayerToWindows32BuildTarget` | `StandaloneWindows` | 同上(目录名不同) |
| `GameFrameX/Build/Mac Os` | `BuildPlayerToMacBuildTarget` | `StandaloneOSX` | 同上 |
| `GameFrameX/Build/WebGL` | `BuildPlayerToWebGLBuildTarget` | `WebGL` | 由 `BuildOutputPath()` 决定 |
| `GameFrameX/Build/Android(APK)` | `BuildPlayerToAndroid` | `Android` | `apkPath`(APK) |
| `GameFrameX/Build/Android(AAB)` | `BuildPlayerToAndroidAAB` | `Android` | `aabFilePath`(AAB) |
| `GameFrameX/Build/Android Studio Project` | `BuildPlayerToAndroidStudio` | `Android` | `_buildPath`(Gradle 工程目录) |
| `GameFrameX/Build/Android(Development)` | `BuildPlayerToAndroidDevelopment` | `Android` | 含 `AllowDebugging \| Development \| ConnectWithProfiler` |
| `GameFrameX/Build/iOS` | `BuildPlayerToIOS` | `iOS` | Xcode 工程目录 |

调用入口摘录:

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("当前构建目标不是 Windows");
        return;
    }
    try
    {
        HotFixEditorCompilerHelper.AddEditor();
        PlayerSettings.fullScreenMode = FullScreenMode.Windowed;
        PlayerSettings.defaultScreenHeight = 720;
        PlayerSettings.defaultScreenWidth = 1280;
        EditorUserBuildSettings.selectedStandaloneTarget = BuildTarget.StandaloneWindows64;
        UpdateBuildTime();
        AssetDatabase.SaveAssets();
        _buildPath = BuildOutputPath();
        var resultDirectory = _buildPath + Path.DirectorySeparatorChar;
        RunPreHookBuild();
        var buildReport = BuildPipeline.BuildPlayer(EditorBuildSettings.scenes, resultDirectory + PlayerSettings.productName + ".exe", EditorUserBuildSettings.activeBuildTarget, BuildOptions.None);
        // ...
    }
    finally
    {
        HotFixEditorCompilerHelper.RemoveEditor();
        RunPostHookBuild();
    }
}
```

### 3. 等待构建并查看输出

构建过程中 `BuildPipeline.BuildPlayer` 返回 `BuildReport`,只有当 `summary.result == BuildResult.Succeeded` 时才会继续后续清理与拷贝步骤;否则方法提前返回。控制台会打印 `Build Output Path:` 后跟最终产物路径。Android 平台还会自动调用 `EditorUserBuildSettings.selectedStandaloneTarget` / 对应 API 设置签名相关参数(参见源文件 [BuildProductHelper.cs](/src/Editor/BuildProduct/BuildProductHelper.cs#L360-L450))。

### 4. 接入构建前后钩子(可选)

如需在每次构建前后自动执行步骤,实现 `IBuilderPreHookHandler` 或 `IBuilderPostHookHandler` 即可,框架会在构造产物前后调用所有实现类,并按 `Priority` 升序执行。

```csharp
using UnityEditor;
using GameFrameX.Editor;

public sealed class CopyExtraConfigsPreHook : IBuilderPreHookHandler
{
    // 数值越大,执行顺序越靠后
    public int Priority => 100;

    public void Run(BuildTarget target, string path)
    {
        // target: 当前 BuildPipeline.BuildPlayer 的目标平台
        // path:   框架准备好的输出路径(含可执行文件名或目录)
        // 这里写拷贝资源、改 PlayerSettings 等自定义逻辑
    }
}
```

## 常见变体

- 自定义输出路径:每个方法都先把 `_buildPath = BuildOutputPath()`(类内静态字段)再传入 `BuildPipeline.BuildPlayer`,如需改名或换目录,在调用菜单前修改 `PlayerSettings.productName` 或扩展 `BuildOutputPath()`。
- 嵌入热修复流程:`HotFixEditorCompilerHelper.AddEditor()` 已在每个平台入口的 `try` 起手调用,`finally` 中调用 `HotFixEditorCompilerHelper.RemoveEditor()` 还原工程文件,无热修需求可忽略。
- 自定义后处理:Steamworks 配置文件会通过 `CopySteamWorksConfig` 自动拷贝到产物目录;新增同类工具可直接拷贝该调用或注册 `IBuilderPostHookHandler`。
- 调试版构建:Android 平台提供专门的 `BuildPlayerToAndroidDevelopment` 入口,产出带 `AllowDebugging | Development | ConnectWithProfiler` 的 APK,用于 Profiler 调试。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 菜单点击后立刻打印 `当前构建目标不是 XXX` 并退出 | 当前活动平台与菜单项对应的 `BuildTarget` 不一致 | 先在 `Build Settings` 切到对应平台再触发菜单 |
| 构建产物只有 `*_Data` 目录,缺可执行文件 | `EditorBuildSettings.scenes` 为空,只勾选了一部分场景 | 在 `Build Settings → Scenes In Build` 勾全需要打包的场景 |
| 最终目录里多出 `BackUpThisFolder_ButDontShipItWithYourGame` | 框架已主动删除该目录,但部分文件可能因占用而残留 | 关闭占用进程后重试;若需保留可在自定义钩子中跳过对应清理逻辑 |
| 钩子没有按预期顺序执行 | 未设置 `Priority`,或多个实现使用相同数值 | 给每个实现显式赋值,数值越大排序越靠后 |
| 构建后 Unity 仍残留编辑宏或编辑器工程文件 | `HotFixEditorCompilerHelper.RemoveEditor()` 未触发 | 不要手动跳过菜单的 `try/finally`,应通过菜单而非拷贝方式触发 |

## 背景(可选)

`BuildProductHelper` 在 `BuildPipeline.BuildPlayer` 之前调用 `RunPreHookBuild()`,在 `finally` 中调用 `RunPostHookBuild()`,二者内部都通过反射扫描所有 `Utility.Assembly.GetTypes()` 中实现了对应接口的具体类型,然后按 `Priority` 升序实例化并调用 `Run(BuildTarget, string)`。这一机制让用户业务无需修改框架源码即可注入构建前后逻辑。
