# 场景资源名无效怎么办

当调用 `LoadScene(string sceneAssetName, ...)` 时,如果传入的资源名(路径)在 YooAsset 资源清单里查不到,场景加载会直接失败,常见表现是 `LoadSceneFailure` 事件被触发、`await` 返回的 `Task` 抛异常,或者编辑器日志报 "资源不存在 / asset not found"。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `LoadSceneFailure` 事件触发,`SceneAssetName` 是你传入的字符串 | YooAsset 资源清单里没有这个 `sceneAssetName` | 用正确的"资产名/资产路径"重试,确认已在打包输出里登记 |
| 报 `sceneAssetName` 为空或 null | 调用前没有拼接好路径,或从配置表读到了空字符串 | 在调用前做空值校验,使用配置表中完整的 `Assets/...` 路径 |
| 异步 `Task` 抛 `OperationCanceledException` 或一直不返回 | 同一资源名已在 `m_LoadingSceneAssetNames` 里,重复加载被忽略 | 先 `UnloadScene` 或等待上一个完成,避免并发重复加载 |
| 编辑器正常,打包后找不到场景 | 该场景没有被打进 YooAsset 资源包,或包名与加载路径不一致 | 在 YooAsset 收集器里把场景文件加进去,重新构建资源包 |

## 修复步骤

### 1. 校验资源名非空且与清单一致

`LoadScene` 内部以 `sceneAssetName` 作为 YooAsset 场景查询的 key,所以字符串必须与 YooAsset 收集器生成的资产路径完全一致(通常是 `Assets/Scenes/xxx.unity`)。

```csharp
// 推荐：在调用前先校验
if (string.IsNullOrWhiteSpace(sceneAssetName))
{
    GameFrameworkLog.Error("[Scene] sceneAssetName 不能为空");
    return;
}
var handle = await GameEntry.Scene.LoadScene(sceneAssetName,
    UnityEngine.SceneManagement.LoadSceneMode.Single);
```

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L337-L348) 暴露了四个 `LoadScene` 重载,签名分别是 `(string)`、`(string, LoadSceneMode)`、`(string, object)`、`(string, LoadSceneMode, object)`,任一重载都需要传入有效的 `sceneAssetName`。

### 2. 监听失败事件定位真正的资源名

挂上 `LoadSceneFailure` 事件,可以从事件参数里拿到运行时实际尝试加载的 `SceneAssetName`:

```csharp
GameEntry.Scene.LoadSceneFailure += (sender, e) =>
{
    Debug.LogError($"场景加载失败: {e.SceneAssetName}, 错误信息: {e.ErrorMessage}");
};
```

事件源在 [LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs)。把日志里打印出来的 `SceneAssetName` 和 YooAsset 资源清单(`AssetBundle` / `AssetPackage` 列表)对照,通常就能立刻定位拼写或大小写错误。

### 3. 确认 YooAsset 已经收集并构建了该场景

场景要能被加载,必须满足两个条件:

1. 在 YooAsset 收集器规则里把这个 `.unity` 文件包含进来;
2. 重新执行了 YooAsset 构建流程(打包/本地构建),并在运行模式(Run Mode)下使用最新产出的资源包。

如果只在 Unity 编辑器里能加载、打包后失败,基本都是这一步没做。

### 4. 避免同一个资源名并发加载

`GameSceneManager` 内部用 `m_LoadingSceneAssetNames` 跟踪正在加载的资源,同一个 `sceneAssetName` 重复 `LoadScene` 会拿不到新的 `Task`,表现为"无效"。解决方式是让每次加载逻辑独占资源名,或者等待上一次 `LoadScene` 返回的 `Task` 完成后再发起下一次。

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L371) 中的完整实现位于四参重载,可以看到它会把 `SceneHandle` 与 `UserData` 存入 `m_LoadingSceneAssetNames`,直到成功或失败回调才移除。

## 验证

执行一次能正常加载的场景对照:

1. 用一个确定存在的场景(例如 `Assets/Scenes/Init.unity`)调用 `LoadScene`,确认 `LoadSceneSuccess` 事件触发;
2. 把 `sceneAssetName` 故意改成一个不存在的字符串,确认 `LoadSceneFailure` 被触发、日志能输出实际尝试的资源名;
3. 把不存在的字符串修正回正确路径,再次 `LoadScene`,确认能成功。

如果第 1、3 步都成功而中间步骤的失败事件按预期触发,说明 "场景资源名无效" 已被定位为字符串/路径问题,而不是框架侧 API 调用方式有误。
