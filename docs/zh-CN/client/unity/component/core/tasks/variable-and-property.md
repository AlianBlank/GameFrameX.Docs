# 使用变量与可绑定属性做数据驱动

在 GameFrameX 中,`Variable<T>` 是带引用计数的强类型数据容器(用于跨子系统传递弱类型值),`BindableProperty<T>` 是带值变更回调的响应式属性(用于 UI 与逻辑的数据绑定)。本页演示两者在数据驱动场景中的典型用法。

## 前置条件

- 已引入 `GameFrameX.Runtime` 命名空间。
- 已了解 GameFrameX 的引用池 / `IReference` 概念(仅 `Variable<T>` 需要)。

## 操作步骤

### 1. 用 `Variable<T>` 承载跨模块数据

继承 `Variable<T>` 实现一个具体类型,即可在事件、参数表中以弱类型 `object` 传递,又能在拿到实例时强类型取值。

```csharp
using GameFrameX.Runtime;

public class IntVariable : Variable<int>
{
    public IntVariable() { }
    public IntVariable(int value) { SetValue(value); }
}
```

使用方式:

```csharp
var v = ReferencePool.Acquire<IntVariable>();
v.SetValue(42);
int actual = v.Value;                // 强类型取值
object boxed = v.GetValue();         // 弱类型装箱(用于事件参数)
ReferencePool.Release(v);            // 归还引用池,会回调 Clear()
```

设置类型不匹配时,`SetValue(object)` 会抛出 `GameFrameworkException`,消息原文为:

```
Cannot set value of type '{0}' to variable of type '{1}'.
```

> 关于引用池与 `IReference` 的整体工作流程,见《IReference 与引用池》。

### 2. 用 `BindableProperty<T>` 做值变更通知

`BindableProperty<T>` 在赋值时若新旧值不相等,会自动调用已注册的回调,常用于驱动 UI 刷新。

```csharp
using System;
using GameFrameX.Runtime;

public sealed class PlayerStats
{
    public readonly BindableProperty<int> Hp = new BindableProperty<int>(100);
    public readonly BindableProperty<string> Name = new BindableProperty<string>("Hero");
}
```

订阅与反订阅:

```csharp
var stats = new PlayerStats();

Action<int> onHp = newHp => Debug.Log($"HP -> {newHp}");
stats.Hp.Add(onHp);                       // 注册回调
stats.Hp.Value = 80;                       // 触发回调,日志输出 "HP -> 80"
stats.Hp.Value = 80;                       // 相等值不会触发
stats.Hp.Remove(onHp);                     // 移除回调
stats.Hp.Clear();                          // 清空所有回调
```

### 3. 需要立即拿到当前值时使用 `RegisterWithInitValue`

若订阅时希望回调立即被调用一次(传入当前值),使用 `RegisterWithInitValue`:

```csharp
stats.Hp.RegisterWithInitValue(newHp => UpdateHpBar(newHp));
```

## 常见变体

| 场景 | 选型 | 关键 API |
|------|------|----------|
| 事件 / 任务的弱类型参数 | `Variable<T>` 子类 | `SetValue(object)` / `GetValue()` |
| UI 绑定 / 多观察者同步 | `BindableProperty<T>` | `Add` / `Remove` / `RegisterWithInitValue` |
| 想避免重复触发 | `BindableProperty<T>` | 内部已用 `Equals` 比较,同值不触发 |
| 想池化复用变量 | `Variable<T>` | `ReferencePool.Acquire / Release` |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `Cannot set value of type 'X' to variable of type 'Y'.` | 给 `Variable<T>` 的 `SetValue(object)` 传入非 `T` 类型 | 在调用点做类型转换,或改用匹配的子类 |
| 赋值后回调没执行 | 新值与旧值相等,`BindableProperty` 内部 `Equals` 比较后跳过 | 这是预期行为;若需要强制通知,改用 `Equals` 返回 false 的新实例 |
| `Add(null)` 抛异常 | `BindableProperty.Add` 用 `GameFrameworkGuard.NotNull` 校验 | 传入具体 `Action<T>` 方法或 lambda |
| 归还引用池后回调仍触发 | `Variable<T>` 已被池回收但外部仍持有引用 | 在持有者自身 `Clear()` 或释放时同步清空引用 |## 背景(可选)

- `Variable` 实现 `IReference`,支持通过 `ReferencePool` 获取 / 释放,`Clear()` 会把值重置为 `default(T)`,适合在事件、任务参数这种"用完即弃"的场景里减少 GC。
- `BindableProperty<T>` 内部用 `Equals` 比较新旧值,只有真正变化时才回调;`Add` 支持链式返回自身,`Remove` 必须传入同一个委托引用才能正确解绑。
