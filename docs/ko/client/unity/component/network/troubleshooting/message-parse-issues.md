# 메시지가 수신되지 않거나 파싱 오류가 발생하면 어떻게 해야 하나요

네트워크 메시지가 수신되지 않거나, 수신 후 역직렬화/디스패치가 실패하는 경우, 문제는 거의 항상 네 가지 지점에 있습니다: 메시지 직렬화기 미등록, 패킷 헤더 길이와 프로토콜 불일치, `INetworkChannelHelper`의 패킷 파싱 구현 오류, 메시지 핸들러 미등록. 아래 진단 표로 문제 위치를 파악한 후 해당 단계에 따라 수정하십시오.

## 수정 단계

### 1. 메시지 직렬화기 등록

폴백 역할을 하는 `DefaultMessageSerializer`는 실제 직렬화기가 없을 때 `Deserialize`에서 반드시 `InvalidOperationException`을 던집니다:

```csharp
/// <exception cref="InvalidOperationException">메시지 직렬화기가 등록되지 않았을 때 발생 / Thrown when no message serializer is registered</exception>
public object Deserialize(byte[] data, Type targetType)
{
```

출처: [DefaultMessageSerializer.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageSerializer.cs#L49-L51)

점검 사항:

1. 시작 프로세스에서 `IMessageSerializer`를 구현한 직렬화기(예: Protobuf/JSON/MessagePack 구현)를 네트워크 모듈에 등록했는지 확인합니다.
2. `IMessageSerializer`의 계약은 `object Deserialize(byte[] data, Type targetType)`이며, 대상 타입 `targetType`이 송신 측 타입과 일치하는지 확인합니다.
3. 다시 연결한 후 요청을 전송하여 `InvalidOperationException`이 더 이상 발생하지 않는지 확인합니다.

### 2. 패킷 헤더 길이와 패킷 파싱 구현 확인

수신 버퍼는 기본적으로 `ReceiveState.PacketHeaderLength = 14` 바이트 단위로 패킷 헤더를 읽으며, 패킷 헤더 핸들러의 선언은 `ushort PacketHeaderLength { get; }`입니다. 양쪽은 반드시 일치해야 합니다:

| 설정 항목 | 위치 | 기본값/타입 |
|--------|------|-----------|
| `ReceiveState.PacketHeaderLength` | [NetworkManager.ReceiveState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.ReceiveState.cs#L42-L43) | `14` 바이트(상수) |
| `ReceiveState.DefaultBufferLength` | 위와 동일 | `1024 * 64` |
| `IPacketReceiveHeaderHandler.PacketHeaderLength` | [IPacketReceiveHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketReceiveHeaderHandler.cs#L47) | `ushort` |
| 패킷 헤더 파싱 진입점 | [INetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannelHelper.cs#L86) | `bool DeserializePacketHeader(byte[] source)` |
| 패킷 본문 파싱 진입점 | [INetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannelHelper.cs#L95) | `bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` |

점검 사항:

1. 패킷 캡처/서버 로그로 실제 패킷 헤더 바이트 수를 확인하고, 14 바이트가 아닌 경우 `IPacketReceiveHeaderHandler.PacketHeaderLength` 구현이 그와 일치하는지 확인합니다.
2. `DeserializePacketHeader`의 필드 읽기 순서와 바이트 순서(빅/리틀 엔디언)가 서버 측 인코딩과 일치하는지 확인합니다. 여기서 `false`를 반환하면 해당 패킷이 바로 폐기됩니다.
3. `DeserializePacketBody`에 전달된 `messageId`가 올바른 `MessageObject` 파생 타입으로 매핑될 수 있는지 확인합니다. `out` 결과가 `null`이면 마찬가지로 파싱 실패로 간주됩니다.
4. 서버가 패킷 본문을 암호화하는 경우, 복호화가 `DeserializePacketBody` 이전에 수행되는지, 키/알고리즘이 일치하는지 확인합니다.

### 3. 메시지 핸들러 등록 확인

메시지 디스패치는 메시지 타입에 표시된 핸들러 특성(Attribute)에 의존하며, 저장소에서는 두 가지를 제공합니다:

- `MessageHandlerAttribute` — 메시지 타입을 기준으로 핸들러를 바인딩, [MessageHandlerAttribute.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/MessageHandlerAttribute.cs) 참조
- `MessageTypeHandlerAttribute` — 메시지 타입 코드를 기준으로 핸들러를 바인딩, [MessageTypeHandlerAttribute.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/MessageTypeHandlerAttribute.cs) 참조

점검 사항: 메시지 클래스에 해당 특성이 표시되어 있고, 해당 타입이 속한 어셈블리가 스캔되어 등록되었는지 확인합니다. `messageId`는 특성에 선언된 타입 코드와 일치해야 합니다.

### 4. 빈 메시지 본문 시나리오 확인

패킷 헤더에서 파싱된 메시지 본문 길이가 0이면 `ReceiveState`는 `IsEmptyBody = true`로 표시하며, 이는 오류가 아닙니다:

```csharp
Stream.Position = 0L;
Stream.SetLength(targetLength);

if (targetLength == 0)
{
    // 내용 길이가 비어 있음을 발견. 빈 메시지이거나 내용이 기본값임을 의미.
    IsEmptyBody = true;
}
else
{
    IsEmptyBody = false;
}
```

출처: [NetworkManager.ReceiveState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.ReceiveState.cs#L104-L115)

비즈니스상 비어 있으면 안 되는 상황이라면, 서버가 패킷 본문을 채우지 않았거나 패킷 헤더의 길이 필드를 잘못 읽은 것이므로 2단계로 돌아갑니다.

## 검증

1. 요청-응답을 한 번 전송합니다. `InvalidOperationException`과 `GameFrameworkException: Target length is invalid.`가 더 이상 발생하지 않아야 합니다(후자는 `ReceiveState.Reset`의 음수 길이 검사에서 발생, [NetworkManager.ReceiveState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.ReceiveState.cs#L99-L102) 참조).
2. 응답 메시지가 도착할 때 `DeserializePacketHeader` / `DeserializePacketBody`가 모두 `true`를 반환하고 `messageObject`가 `null`이 아닌지 확인합니다.
3. 핸들러 특성이 표시된 비즈니스 콜백이 실행되고, 메시지 필드 값이 서버가 전송한 값과 일치하는지 확인합니다.

## 배경

수신 측은 `ReceiveState`를 단위로 반복해서 읽습니다. 먼저 패킷 헤더 길이(기본 14 바이트)만큼 패킷 헤더를 읽고, 이어서 패킷 헤더에 선언된 패킷 본문 길이만큼 패킷 본문을 읽은 뒤 `INetworkChannelHelper`에 넘겨 역직렬화하고 메시지 특성을 통해 핸들러로 디스패치합니다. 대부분의 "수신 안 됨/파싱 오류" 문제는 이 흐름의 앞 두 단계(길이 불일치)와 뒤 두 단계(직렬화기/핸들러 미등록)에 있습니다. 네트워크 모듈의 전체 구조에 대해서는 공식 문서 https://gameframex.doc.alianblank.com/ 를 참조하십시오.
