# カスタムストレージ Helper の実装

[SettingHelperBase](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44) を継承し、`ISettingHelper` のすべてのメンバーを実装して、読み書きを実際のストレージメディア（データベース、暗号化ファイル、リモートインターフェースなど）に接続します。フレームワークは起動時に `SettingComponent` を通じて Helper を呼び出し、読み込みと保存を行います。

## 前提条件

- `com.gameframex.unity.setting` パッケージがインストールされ、Inspector で `SettingComponent` が確認できること。
- C# の抽象クラスと `MonoBehaviour` のライフサイクルを理解していること。Helper はシーン内の GameObject にアタッチする必要があります。
- 独自のストレージメディア（SQLite、ローカル暗号化ファイル、リモート Key-Value サービスなど）。

## 操作手順

1. **Helper クラスを作成し、基底クラスを継承する**。
   新規スクリプト `Assets/Scripts/MySettingHelper.cs` を作成し、`GameFrameX.Setting.Runtime.SettingHelperBase` を継承します。基底クラス自体が抽象 `MonoBehaviour` であり、フレームワークはこれを通じてすべての `ISettingHelper` メンバーを取得します。

   ```csharp
   using GameFrameX.Setting.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
   }
   ```

   出典: [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44)

2. **必ずオーバーライドする必要がある抽象メンバーを実装する**。基底クラスで宣言されている抽象メンバーの対応表は以下の通りです。すべて `override` で実装してください：

   | メンバー | シグネチャ | 推奨動作 |
   |------|------|---------|
   | `Count` | `int Count { get; }` | サポートしない場合は `-1` を返す（`PlayerPrefsSettingHelper` の実装を参照） |
   | `Load()` | `bool Load()` | 事前読み込みが不要な場合はそのまま `true` を返す |
   | `Save()` | `bool Save()` | 実際に永続化を行った後に返す |
   | `GetAllSettingNames()` | `string[] GetAllSettingNames()` | サポートしない場合は `Log.Warning` 後に `null` を返す |
   | `GetAllSettingNames(List<string>)` | `void GetAllSettingNames(List<string> results)` | `results == null` の場合は `GameFrameworkException("Results is invalid.")` をスローし、そうでなければ `results.Clear()` |
   | `HasSetting` / `RemoveSetting` / `RemoveAllSettings` | インターフェース参照 | 独自のストレージに委譲する |
   | `GetBool/Int/Float/String`、`SetBool/Int/Float/String` | インターフェース参照 | 独自のストレージに委譲する。存在しない場合は規定のデフォルト値を返す |

   完全なシグネチャについては [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L42-L42) と [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L43-L43) を参照してください。

3. **読み書きを具体的なストレージに委譲する**。最小例：メモリ辞書でストレージを模擬する。

   ```csharp
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
       private readonly Dictionary<string, string> _store = new Dictionary<string, string>();

       public override int Count => _store.Count;

       public override bool Load() { return true; }

       public override bool Save() { /* ファイル/データベースへの書き戻し */ return true; }

       public override bool HasSetting(string settingName) => _store.ContainsKey(settingName);

       public override bool RemoveSetting(string settingName) => _store.Remove(settingName);

       public override void RemoveAllSettings() => _store.Clear();

       public override void SetString(string settingName, string value) => _store[settingName] = value;

       public override string GetString(string settingName, string defaultValue)
           => _store.TryGetValue(settingName, out var v) ? v : defaultValue;

       // Bool/Int/Float も同様。Bool は SetInt/GetInt で 0/1 として保存可能（PlayerPrefsSettingHelper を参照）。
   }
   ```

   出典: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L42-L42)（基底クラスの標準実装例。`GetBool`/`SetBool` を下層の `StorageBackend.GetInt/SetInt` に委譲する方法を実演）

4. **スクリプトをシーン内の GameObject にアタッチする**。`SettingHelperBase` は `MonoBehaviour` を継承しているため、`SettingComponent` に検出されインスタンス化されるには GameObject にアタッチする必要があります。

5. **`SettingComponent` の Inspector で `Custom Setting Helper` を選択する**。`Setting Helper Type` をあなたの `MySettingHelper` に設定すると、フレームワーク起動時にリフレクションで Helper が生成されます。

   出典: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)（`SettingComponent` は `ISettingHelper` インスタンスの生成と保持を担当）

## よくあるバリエーション

- **Helper を変更せず、下層ストレージバックエンドのみ切り替える**：`PlayerPrefsSettingHelper` を引き続き使用しつつ、下層を SQLite/WeChat ミニゲーム SDK などにしたい場合は、`ISettingStorageBackend` を実装し、起動時に `SettingStorageBackendFactory.RegisterMiniGameBackend` を通じて登録します。`PlayerPrefsSettingHelper` の内部では `StorageBackend` プロパティによりこのバックエンドが遅延ロードされます。

  ```csharp
  // プラットフォーム起動時（UNITY_EDITOR 下でのみ有効）
  SettingStorageBackendFactory.RegisterMiniGameBackend(() => new MySqliteBackend());
  ```

  出典: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

- **ミニゲームプラットフォームの実装参考**：`WeChatMiniGameSettingStorage`、`AlipayMiniGameSettingStorage` などは、すでに `ISettingStorageBackend` インターフェースに従ってプラットフォームネイティブ API をラップしており、最小限の実装例として参照できます。

  出典: [WeChatMiniGameSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/MiniGame/WeChat/WeChatMiniGameSettingStorage.cs)、[Storage/ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs)

## よくあるエラー

- **`SettingHelperBase` を継承していない**：`ISettingHelper` を直接実装することもできますが、`SettingComponent` は通常 `SettingHelperBase` 派生クラスとしてスキャンします。継承関係を維持するほうがより安全です。
- **Helper がシーンオブジェクトにアタッチされていない**：`SettingHelperBase` は `MonoBehaviour` であり、アタッチされていないとフレームワークがインスタンス化できず、実行時にデフォルト実装が取得されるか例外がスローされます。
- **`GetAllSettingNames(List<string>)` で `results == null` のチェック漏れ**：基底クラスは `GameFrameworkException("Results is invalid.")` のスローを期待しており、フレームワークの他モジュールはこの規約に依存しています。
- **Helper のコンストラクタで `UnityEngine.PlayerPrefs` などの実行時 API にアクセス**：静的コンストラクタやフィールド初期化段階で Unity API にアクセスしないでください。`Load()` 内または初回アクセス時に実行してください。
- **保存ロジックで例外を握り潰す**：書き込みに失敗した場合は `false` を返し、`SettingComponent` が失敗を検知して通知できるようにしてください。`try/catch` で静かに受け取って `true` を返してはいけません。

## 背景（オプション）

`PlayerPrefsSettingHelper` はすべての読み書きを `ISettingStorageBackend` に委譲しており、`SettingStorageBackendFactory` は `UNITY_EDITOR` 下では `UnityPlayerPrefsSettingStorage` を、実機のミニゲームプラットフォーム下では各プラットフォームのアダプタが登録したファクトリを使用します。これは「Helper を再実装せずに下層ストレージを切り替える」ためのクイックパスです。ビジネスロジックが本当に新しい Helper の挙動（リモート取得、暗号化、プロセス間同期など）を必要とする場合にのみ、このページの手順に従ってカスタム `SettingHelperBase` 派生クラスを実装してください。
