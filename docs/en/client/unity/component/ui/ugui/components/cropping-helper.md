# How to Use the UI Cropping Helper Tool

`GameFrameXUIToUGUICroppingHelper` is a MonoBehaviour attached to the UI root node. It is used at runtime to register the key types that the UGUI module needs to preserve with Unity's code stripping process, preventing the built runtime package from throwing `MissingMethodException` or null reference exceptions due to types being stripped.

## Prerequisites

- The Unity project has integrated the GameFrameX UGUI package (this repository).
- A UI root node exists in the scene (usually a Canvas or a GameObject at the same level).
- "Managed Stripping Level" or "Engine Code Stripping" is enabled in Player Settings, which triggers code stripping.

## Steps

1. **Find or create a persistent GameObject**: Prepare a GameObject in the scene that will not be destroyed when the UI is closed (for example, `UIRoot`, the Canvas itself, or a node named `~UIKeepAlive`).
2. **Attach the script**: In the Inspector, click `Add Component`, then search for and add the `GameFrameXUIToUGUICroppingHelper` component.

   ![Add Component illustration](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/GameFrameXUICroppingHelper.cs#L37-L37)

3. **No parameters to configure**: This component has no public fields; it takes effect once attached. Its `Start()` method writes the following types into the stripping whitelist at runtime:

```csharp
m_Types = new[]
{
    typeof(RectTransformExtension),
    typeof(UIManager),
    typeof(UGUIFormHelper),
    typeof(UGUI),
    typeof(UGUIButtonExtension),
    typeof(UGUIElementPropertyAttribute),
    typeof(UGUIUIGroupHelper),
    typeof(UIImage),
    typeof(UGUIImageExtension),
};
```

Source: [GameFrameXUICroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/GameFrameXUICroppingHelper.cs#L43-L57)

4. **Build verification**: Enable Code Stripping in Build Settings, then build an IL2CPP package. Run the game and confirm that opening any UI interface does not trigger `MissingMethodException` or `NullReferenceException`.

## Common Variants

- **Not using code stripping**: If your project's `Managed Stripping Level` is set to `Disabled` or `Low`, this component can be omitted without causing errors.
- **Preserving only some types**: Edit the `m_Types` array directly (modify it in the source code and rebuild the assembly), keeping only the extension types actually used by your project.
- **Using Link.xml**: A more robust approach is to write these types into `Assets/link.xml`, so you don't need to rely on a runtime component. This component is suitable for scenarios where editing `link.xml` is inconvenient.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `UIManager` throws `MissingMethodException` after building | Stripping removed the UGUI types | Attach `GameFrameXUIToUGUICroppingHelper` to the UI root node |
| An extra "ghost" component appears in the scene after attaching, which is visually unpleasant | Prefer a code-based solution rather than a component | Manually list the types to preserve in `Assets/link.xml`, see the example below |

`link.xml` example:

```xml
<linker>
  <assembly fullname="GameFrameX.UI.UGUI.Runtime">
    <type fullname="GameFrameX.UI.UGUI.Runtime.UIManager" preserve="all"/>
    <type fullname="GameFrameX.UI.UGUI.Runtime.UGUI" preserve="all"/>
  </assembly>
</linker>
```

## Background

When Unity builds an IL2CPP package, it performs managed code stripping, which by default removes types that "appear unreferenced." UGUI extension methods (`RectTransformExtension`, `UGUIButtonExtension`, `UGUIImageExtension`) are typically invoked via reflection or runtime binding, so static analysis can easily miss them, resulting in methods not being found at runtime. `GameFrameXUIToUGUICroppingHelper` uses the `[Preserve]` attribute + explicit `typeof()` references to mark key types as must-preserve, thereby bypassing stripping.
