# パスワードハッシュの使い方:PBKDF2/Bcrypt/Scrypt/Argon2id

`PasswordHashHelper` の一行呼び出しで、PBKDF2、Bcrypt、Scrypt、Argon2id の 4 種類のパスワードハッシュアルゴリズムを切り替えることができ、ログイン検証時には PHC プレフィックスに基づいて自動的にアルゴリズムを識別するため、どのアルゴリズムを使用したかを記録する必要はありません。

## 前提条件

- プロジェクトが `GameFrameX.Foundation.Hash` アセンブリを参照していること。
- `using GameFrameX.Foundation.Hash;`(Bcrypt/Scrypt/Argon2id は `BCrypt.Net-NNext.StrongName` と BouncyCastle が提供するため、追加インストール不要)。
- 現在のアルゴリズム種類は列挙型 `PasswordHashAlgorithmKind` で選択:`Pbkdf2` / `Bcrypt` / `Scrypt` / `Argon2id`。

## 操作手順

### 1. 統一ファサードで新しいパスワードをハッシュする(Argon2id を例に)

```csharp
using GameFrameX.Foundation.Hash;

string phc = PasswordHashHelper.Hash(PasswordHashAlgorithmKind.Argon2id, "P@ssw0rd-テスト-🔑");
// phc は $argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash> の形式
// phc の文字列をそのままデータベースに保存すればよい
```

出典: [PasswordHashHelper.cs#L57-L74](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L57-L74)

### 2. パスワードを検証する

以前どのアルゴリズムを使用したかを記録する必要はなく、ファサードが PHC プレフィックスに基づいて自動的に振り分けます:

```csharp
bool ok = PasswordHashHelper.Verify(inputPassword, phcStoredInDb);
if (ok) { /* ログイン成功 */ }
```

出典: [PasswordHashHelper.cs#L84-L102](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L84-L102)

### 3. アルゴリズム種類を切り替える

手順 1 の `PasswordHashAlgorithmKind.Argon2id` を `Pbkdf2` / `Bcrypt` / `Scrypt` に置き換えるだけでよく、`Verify` は依然としてデータベース内の古い PHC 文字列を識別できます。

### 4. アルゴリズムが OWASP 推奨かどうかを判定する

```csharp
bool isOwaspFirstChoice = PasswordHashHelper.IsRecommended(PasswordHashAlgorithmKind.Argon2id); // true
```

出典: [PasswordHashHelper.cs#L109-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L109-L112)

### 5. PHC プレフィックスを能動的に識別する

```csharp
PasswordHashAlgorithmKind? kind = PasswordHashHelper.DetectAlgorithm(storedHash);
// 識別表:$pbkdf2-sha256$、$2a$/$2b$/$2y$(bcrypt)、$scrypt$、$argon2id$
```

出典: [PasswordHashHelper.cs#L120-L147](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L120-L147)

## よくあるバリエーション

- **PBKDF2 を小さなパラメータで高速デバッグ**:直接 `Pbkdf2Helper.Hash(password, 100, 16)` を呼び出す(テストではこのようにディスパッチロジックの負荷テストを行っている)、本番環境ではファサードのデフォルトパラメータを使用してください。
- **Bcrypt を小さな作業因子で**:テストでは `BcryptHelper.Hash(password, 4)` で生成;本番ではファサードのデフォルト安全パラメータの使用を推奨。
- **Scrypt / Argon2id を小さなパラメータでスモークテスト**:`ScryptHelper.Hash(password, 1024, 1, 1)`、`Argon2idHelper.Hash(password, 16, 1, 1)` はテストでの最小パラメータ組み合わせで、ユニットテストの高速ラウンドトリップに使用。

## よくあるエラー

| 現象 | 原因 | 回避策 |
|------|------|------|
| `Hash(未知の列挙値, pwd)` が `ArgumentOutOfRangeException` をスロー | 渡された値が 4 種類の既知アルゴリズムではない | `Pbkdf2` / `Bcrypt` / `Scrypt` / `Argon2id` のみを使用する |
| `Hash(Bcrypt, 超長パスワード)` が `ArgumentOutOfRangeException` をスロー | bcrypt のハードリミットは 72 バイト(UTF-8) | 72 バイトを超えるパスワードは Argon2id / Scrypt に変更するか、先にダイジェストを取ってからハッシュする |
| `Verify` が `false` を返すがパスワードは正しい | 保存文字列が 4 種類の PHC プレフィックスのいずれでもない、またはフォーマットが破損している | `DetectAlgorithm(storedHash)` で調査し、プレフィックスが完全であることを確認する |
| 「72 バイト制限でアルゴリズムを切り替えたい」のに `Argon2id` 以外のアルゴリズムを使用 | OWASP の第一選択肢は Argon2id で、他は必ずしも第一選択肢ではない | `PasswordHashHelper.IsRecommended(kind)` で判定する |

## 背景(オプション)

`PasswordHashHelper` は薄いファサードで、実際の実装はそれぞれ `Pbkdf2Helper`(BCL `Rfc2898DeriveBytes`)、`BcryptHelper`(`BCrypt.Net-Next.StrongName`、72 バイトのハード上限)、`ScryptHelper`、`Argon2idHelper`(BouncyCastle)が担っています。`Verify` は PHC 文字列プレフィックス($pbkdf2-sha256$ / $2a$|$2b$|$2y$ / $scrypt$ / $argon2id$)でディスパッチを行うため、将来データベース内の歴史的な PBKDF2 を Argon2id にアップグレードしても、古い PHC 文字列は依然として識別可能です。列挙型 `PasswordHashAlgorithmKind` と検証和用の `HashAlgorithmKind` はセマンティクスが異なるため、パスワードのシナリオでは前者を使用してください。
