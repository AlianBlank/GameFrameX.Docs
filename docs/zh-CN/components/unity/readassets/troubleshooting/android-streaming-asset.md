# Android 平台上 StreamingAsset 读不到怎么办(文件名/压缩/字符)

在 Android 设备上,本库不会把 APK 内的 `assets/` 当作普通文件夹读取,而是通过读取 APK 的 ZIP End-of-Central-Directory 与 Central Directory,按 `offset/size` 直接打开 `FileStream` 切片访问。所以"读不到"几乎都源于:**路径不匹配**、**APK 内条目被压缩**、**文件名包含特殊字符**、或**被打成了 split APK / patch 包而没命中 `base.apk`**。本文给出快速诊断表与对应修复步骤。

## 快速诊断

| 症状 | 直接原因 | 修复入口 |
|------|----------|----------|
| `TryGetInfo` 返回 `false` / `OpenRead` 抛 `FileNotFoundException` | 传入的相对路径与 APK 内 `assets/` 下条目不匹配(大小写、空格、`/` 或 `\` 写法) | [修复路径大小写与分隔符](#修复路径大小写与分隔符) |
| `Debug.Assert` 触发:`CompressedSize != UncompressedSize` | APK 构建时勾选了 Compression,或插件/Gradle 重新压缩了 `assets` | [强制 APK 内 assets 不压缩](#强制-apk-内-assets-不压缩) |
| `paths duplicate! <file>` 运行时异常 | 同时打出了主 APK 与 split/patch,且两者都包含同名 `assets` 条目 | [处理 split APK / OBB patch](#处理-split-apk--obb-patch) |
| 中文/日文文件名打不开或大小写诡异的资源找不到 | ZIP 标准要求文件名要么 ASCII,要么用 UTF-8 标志位;APK 默认不带 UTF-8 标志 | [统一文件名命名规范](#统一文件名命名规范) |
| 装了 64 位插件、Mono 升级后崩在 `stream.CanSeek == false` 或 APK 路径无效 | `dataPath` 没正确解析到 `base.apk`(比如处于 split 子包) | [确认 APK 主包路径](#确认-apk-主包路径) |

## 修复步骤

### 修复路径大小写与分隔符

`BlankReadAssets.ApkImpl.TryGetInfo` 内部会调用 `PathUtil.NormalizeRelativePath`,并以 `StringComparer.OrdinalIgnoreCase` 对 `s_paths` 做二分查找,所以路径必须与打包进 APK 的真实文件名一一对应,且必须使用正斜杠 `/`。

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L58-L84
public static bool TryGetInfo(string path, out ReadInfo info)
{
    path = PathUtil.NormalizeRelativePath(path);
    info = new ReadInfo();

    var index = Array.BinarySearch(s_paths, path, StringComparer.OrdinalIgnoreCase);
    if ( index < 0 )
    {
        return false;
    }
    ...
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L58-L84)

操作:

1. 拿到真实打包后的 APK(可在 `Library/` 或 `Build/` 目录),使用 `unzip -l your.apk | head` 查看 `assets/` 下条目的精确大小写。
2. 代码中统一使用 `/`,不要混用 `\`,也不要带前缀 `StreamingAssets` 或 `jar:file://...`。
3. 资源名尽量只用 `A–Z`、`a–z`、`0–9`、`_`、`-`、`.`、单层 `/`。

### 强制 APK 内 assets 不压缩

本库定位条目时做了如下断言(开发期会报警):

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L325-L340 (节选)
while ( ZipCentralDirectoryFileHeader.TryReadBlock(reader, out header) )
{
    if ( header.CompressedSize != header.UncompressedSize )
    {
#if UNITY_ASSERTIONS
        // 不压缩 -> 切片读取才正确
#endif
        continue;
    }
    ...
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L325-L340)

后果:被压缩的条目会被跳过,看似"读不到"。修复:

1. Unity:Player Settings → Publishing Settings → **Build APK(s) without compression** 不勾选,但要确认 Gradle/AAPT 不重新压缩。
2. 自定义 Gradle(主模板 `unityLibrary` 的 `build.gradle`)在 `android` 节点添加,使 `assets/**/*.bundle`、`StreamingAssets/**` 等热点目录不压缩:

```groovy
android {
    aaptOptions {
        noCompress 'bundle','unitydefaultresources','StreamingAssets','bin','config.json'
    }
}
```

3. 重新打包后,用 `unzip -lv your.apk | grep -E "Method|---"` 确认热点文件 `Method` 列是 `Stored`(而非 `Defl:N`)。

### 处理 split APK / OBB patch

Initialize 会判断 `dataPath` 末尾,决定走 patch 目录还是回退到 `base.apk`:

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L27-L56
public static void Initialize(string dataPath, string streamingAssetsPath)
{
    s_root = dataPath;
    if (dataPath.EndsWith("pram-shadow-files"))
    {
        Debug.Assert(streamingAssetsPath.EndsWith("pram-shadow-files/assets"));
        GetStreamingAssetsFromPatch(dataPath, paths, parts);
    }
    else
    {
        GetStreamingAssetsInfoFromJar(s_root, paths, parts);
        if (paths.Count == 0 && !Application.isEditor && Path.GetFileName(dataPath) != "base.apk")
        {
            var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
            if (File.Exists(newDataPath))
            {
                s_root = newDataPath;
                GetStreamingAssetsInfoFromJar(newDataPath, paths, parts);
            }
        }
    }
}
```

Source: [Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

如果你是托管多 split 的应用,需要:

1. 把真正的 `assets` 集中打到 `base.apk`,避免 split 包内还残留 `assets/` 子目录。
2. 若用了 Play Asset Delivery / 自定义 patch 目录,确认调用方传进来的 `dataPath` 是 `.../pram-shadow-files`(逻辑分支会走 `GetStreamingAssetsFromPatch`)。

### 统一文件名命名规范

ZIP Central Directory 中文件名长度受 `[ushort]` 限制,且 Unicode 编码处理依赖 General Purpose Bit Flag 位 11(UTF-8)。部分 Android 工具链不会写该标志位,导致多字节字符文件名解析失败。操作:

1. 资源名一律 ASCII:`game_config`、`map_01.bin`、`lang_zh.json`。
2. 禁用 `+`、`%`、`空格`、表情符号。
3. 若必须支持多语言资源,用目录区分(`assets/i18n/zh/...`),而非嵌在文件名里。

### 确认 APK 主包路径

在 split 场景下,Unity 给的 `Application.streamingAssetsPath` 不会指向 `base.apk`,Initialize 会自动 fallback:

```csharp
var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
if (File.Exists(newDataPath)) { s_root = newDataPath; }
```

(Source 同上) 但如果项目做了 App Bundle 合并或自定义 aapt,把 `assets` 重定向到了非 `base.apk` 文件中,fallback 会失效。修复:

1. 在设备端 `adb shell pm path <your.package>` 找到当前 Package 的 `base.apk` 真实路径。
2. 与 `Application.streamingAssetsPath` 比对,如不一致,检查 Gradle/AGP 是否启用了 `--split-by-abi` / `--split-resources`,并避免把 `assets` 一并拆分。

## 验证

1. **离线核对清单**:把生成的 APK 用 `unzip -l` 列出 `assets/` 前 50 条;与代码中传入的相对路径逐条对照(大小写、分隔符、`.bin` 后缀)。
2. **Editor vs Device 同源**:`BlankReadAssets.LooseFilesImpl`(非 Android)与 `BlankReadAssets.ApkImpl`(Android)都遵循同一份 `PathUtil`,所以先用 Editor 跑通 `OpenRead`,再到设备上验证。
3. **打开读取冒烟**:

```csharp
using (var s = BlankReadAssets.OpenRead("config/game_config.json"))
{
    Debug.Assert(s.Length > 0, "size == 0,说明 APK 内被压缩或路径错了");
}
```

4. **真机日志**:把上面 `Debug.Assert` 替换为 `Debug.LogError` 看完整堆栈;若提示 `Method != Stored`,直接回 [强制 APK 内 assets 不压缩](#强制-apk-内-assets-不压缩)。

## 背景(可选)

Android 上 Unity 把 `Assets/StreamingAssets/` 整体塞进 APK 的 `assets/` 段;ZIP 容器末尾能找到索引,因此不用像 iOS/Jar 那套 `UnityWebRequest` 取 `jar:file://...`。本库直接 `File.OpenRead(apkPath)` + `SubReadOnlyStream`,走零拷贝切片路径,所以"压不压缩"与"路对不对"会直接决定读不到还是读到错。
