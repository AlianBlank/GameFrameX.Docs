# UI 라이프사이클 이벤트 처리 방법

`UIForm`은 열기, 닫기, 가려짐, 일시정지 등 주요 시점마다 가상 메서드 집합을 호출하며, 서브클래스에서 이 메서드들을 재정의하면 커스텀 비즈니스 로직을 연결할 수 있습니다. 또한 `UIEventSubscriber`를 통해 프레임워크 수준에서 발급되는 이벤트를 수신할 수도 있습니다.

## 사전 조건

- 프로젝트에 `GameFrameX.UI` 모듈이 추가되어 있고, `GameFrameX.UI.UIComponent`를 통해 UI를 열고/닫아야 합니다.
- 비즈니스 UI 스크립트가 `UIForm`을 상속(또는 `IUIForm`을 구현)해야 합니다.
- 열기/닫기 이벤트를 수신하려면 `GameFrameX.UI.UIComponent` 인스턴스(프레임워크 진입점)를 확보해야 합니다.

## 작업 단계

### 1. `UIForm` 라이프사이클 가상 메서드 재정의

`UIForm`은 모든 라이프사이클 훅을 `virtual` 형태로 노출하며, 기본 구현은 비어 있습니다. 서브클래스는 필요에 따라 override하면 되며, 호출 순서를 신경 쓸 필요가 없습니다.

```csharp
using GameFrameX.UI.Runtime;
using UnityEngine;

public class MyMainForm : UIForm
{
    public override void OnInit()
    {
        // 최초 인스턴스화 시 실행: 자식 컨트롤 찾기, 컴포넌트 바인딩
        base.OnInit();
    }

    public override void OnOpen(object userData)
    {
        // 열릴 때마다 트리거됨: 외부에서 전달된 데이터 수신
        base.OnOpen(userData);
    }

    public override void OnClose(bool isShutdown, object userData)
    {
        // 닫힐 때 정리
        base.OnClose(isShutdown, userData);
    }

    public override void OnPause()
    {
        // 새 UI에 덮여 일시정지됨
        base.OnPause();
    }

    public override void OnResume()
    {
        // 덮인 상태에서 복구됨
        base.OnResume();
    }

    public override void OnCover()
    {
        // 덮임(반드시 일시정지되는 것은 아님)
    }

    public override void OnReveal()
    {
        // 덮임 상태에서 복구
    }

    public override void OnRefocus(object userData)
    {
        // 다시 포커스(동일 UI를 여러 번 표시)
    }

    public override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        // 매 프레임 폴링
    }

    public override void OnDepthChanged(int uiGroupDepth, int depthInUIGroup)
    {
        // 깊이 변경(그룹 내 계층)
    }

    public override void OnRecycle()
    {
        // UI가 회수됨
    }
}
```

Source: [UIForm.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIForm.cs#L600-L900)

### 2. 열기 전에 초기화 델리게이트 주입(선택 사항)

`UIForm.Init`은 `Action<IUIForm>` 델리게이트를 받으며, `OnInit` 이전에 호출되므로 파라미터 주입이나 동적 초기화에 적합합니다:

```csharp
var form = uiComponent.OpenUIForm("Assets/UI/MyMainForm.prefab", "MyMainForm",
    uiGroup: UIGroupNameConstants.Default,
    pauseCoveredUIForm: true,
    userData: myPayload,
    onInitAction: form =>
    {
        // OnInit 이전에 실행
        ((MyMainForm)form).Initialize(myPayload);
    });
```

### 3. 프레임워크에서 발급하는 열기/닫기 이벤트 수신

`UIForm`을 상속하고 싶지 않다면 `GameFrameX.Event`의 이벤트 인자를 구독할 수도 있습니다:

```csharp
using GameFrameX.UI.Runtime;
using GameFrameX.Event.Runtime;

// 열기 성공 이벤트 구독
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnOpenSuccess);
GameEntry.Event.Subscribe(CloseUIFormCompleteEventArgs.EventId, OnCloseComplete);
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnOpenFailure);

private void OnOpenSuccess(object sender, GameEventArgs e)
{
    var args = (OpenUIFormSuccessEventArgs)e;
    // args.UIForm / args.Duration
}

private void OnCloseComplete(object sender, GameEventArgs e)
{
    var args = (CloseUIFormCompleteEventArgs)e;
    // args.SerialId / args.UIFormAssetName
}
```

사용 가능한 이벤트 유형은 아래 표를 참고하세요.

| 이벤트 유형 | 트리거 시점 | 주요 필드 |
|---|---|---|
| `OpenUIFormSuccessEventArgs` | UI 열기 성공 | `UIForm`, `Duration` |
| `OpenUIFormFailureEventArgs` | UI 열기 실패 | `ErrorMessage`, `UIFormAssetName` |
| `OpenUIFormDependencyAssetEventArgs` | 의존 리소스 로드 시 | `DependencyAssetName`, `LoadedCount`, `TotalCount` |
| `CloseUIFormCompleteEventArgs` | UI 닫기 완료 | `SerialId`, `UIFormAssetName` |

Sources: [OpenUIFormSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormSuccessEventArgs.cs), [CloseUIFormCompleteEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/CloseUIFormCompleteEventArgs.cs)

## 일반적인 변형

- **`UIEventSubscriber`를 사용한 디커플링**: [UIEventSubscriber.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIEventSubscriber.cs)를 참고하세요. `Awake`/`OnDestroy`에서 `Subscribe/Unsubscribe`를 통해 구독을 중앙에서 관리하여 흩어진 lambda를 방지할 수 있습니다.
- **`Show`와 `Hide` 재정의**: 이 두 메서드는 `abstract`이므로, 서브클래스는 커스텀 표시/숨김 애니메이션(`IUIFormShowHandler` / `IUIFormHideHandler`)을 반드시 구현해야 합니다.
- **공통 이벤트 바인딩**: `BindEvent()`를 재정의하여 버튼 클릭 등을 중앙에서 등록하고, `LoadData()` 및 `UpdateLocalization()`과 함께 단계별로 처리할 수 있습니다.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `OnInit`을 재정의했지만 적용되지 않음 | `base.OnInit()`을 호출하지 않아 기반 클래스 초기화가 건너뛰어짐 | 재정의 시 첫 줄에서 `base.OnInit()` 호출 |
| 닫은 후에도 로직이 계속 실행됨 | `OnClose`를 재정의하지 않고 Unity의 파괴에만 의존함 | `OnClose`에서 코루틴, 타이머, 네트워크 요청 중지 |
| UI가 덮인 후에도 입력에 계속 반응함 | `OnPause` / `OnCover`를 재정의하여 상호작용 컴포넌트를 끄는 것을 잊음 | 이 두 메서드를 재정의하여 버튼 비활성화 또는 `interactable = false` 설정 |
| 동일 UI를 반복해서 열 때 데이터가 갱신되지 않음 | `OnInit`은 최초 1회만 호출됨 | 실제 갱신 로직은 `OnOpen`에 두고, `userData`에서 최신 데이터 가져오기 |

## 배경(선택 사항)

`UIForm`은 `BaseUIManager`에 의해 통합 관리되며, 라이프사이클 메서드는 매니저가 상태 전환 시점에 호출합니다: `Open` → `OnInit` → `OnOpen`; 새 UI가 열려 기존 UI를 덮을 때 `OnCover`/`OnPause`가 트리거되고, 반대 방향으로는 `OnReveal`/`OnResume`이 트리거됩니다. 프레임워크는 어떤 메서드의 재정의도 강제하지 않으며, 비즈니스는 필요에 따라 연결 지점을 선택하면 되고, 빈 구현은 기반 클래스가 제공합니다.
