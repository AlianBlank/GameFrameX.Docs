# 如何在類別上使用屬性來對應參數與環境變數

在類別的屬性上加入 `Option`、`EnvironmentVariable`、`FlagOption` 等屬性後，`OptionsBuilder` 會自動將命令列引數與環境變數繫結至強型別屬性，省去手動撰寫解析程式碼的工作。

## 前置條件

- 參考 `GameFrameX.Foundation.Options` 組件。
- `using GameFrameX.Foundation.Options.Attributes;`(選用，僅在使用簡短名稱時需要)。
- 選項類別必須具有無參數建構函式(條件約束 `where TOptions : class, new()`)。

## 可用屬性概觀

| 屬性 | 用途 | 主要屬性 |
|------|------|----------|
| [`OptionAttribute`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/OptionAttribute.cs#L57-L134) | 將屬性標記為命令列選項 | `LongName`、`ShortName`(於引數轉換器內)、`DefaultValue`、`Required`、`EnvironmentVariable`、`Sensitive` |
| [`EnvironmentVariableAttribute`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/EnvironmentVariableAttribute.cs#L55-L77) | 將屬性直接繫結至指定的環境變數 | `Name`(建構函式引數，環境變數名稱) |

## 操作步驟

### 1. 定義帶有屬性的選項類別

`Option` 的 `EnvironmentVariable` 屬性可直接宣告該選項對應的環境變數名稱。`EnvironmentVariable` 屬性適用於「僅從環境變數讀取、不公開為命令列引數」的案例。

```csharp
using GameFrameX.Foundation.Options.Attributes;

public class MyOptions
{
    // 命令列選項 + 環境變數: --port 或 TEST_PORT
    [Option("port", DefaultValue = 8080, EnvironmentVariable = "TEST_PORT")]
    public int Port { get; set; }

    // 長名稱 + 環境變數 + 預設值
    [Option(LongName = "host", EnvironmentVariable = "TEST_HOST", DefaultValue = "localhost")]
    public string Host { get; set; }

    // 布林切換,不需指定值
    [FlagOption(LongName = "verbose")]
    public bool Verbose { get; set; }

    // 必要項目
    [Option(LongName = "api-key", Required = true)]
    public string ApiKey { get; set; }
}
```

來源： [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L12-L26)

### 2. 使用 `OptionsBuilder` 以一行程式碼完成建置

`OptionsBuilder` 提供多個靜態進入點，可從命令列、環境變數、兩者混合或僅預設值來建置物件。

```csharp
using GameFrameX.Foundation.Options;

// 僅命令列引數
var opts1 = OptionsBuilder.Create<MyOptions>(args);

// 命令列 + 環境變數混合(預設行為)
var opts2 = OptionsBuilder.Create<MyOptions>(
    args,
    boolFormat: BoolArgumentFormat.TrueFalse,
    ensurePrefixedKeys: true,
    useEnvironmentVariables: true);

// 僅環境變數
var opts3 = OptionsBuilder.CreateFromEnvironmentOnly<MyOptions>();

// 僅命令列,忽略環境變數
var opts4 = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);

// 僅預設值(適合測試使用)
var opts5 = OptionsBuilder.CreateDefault<MyOptions>();
```

來源： [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L122)

### 3. 使用 `EnvironmentVariable` 屬性繫結純環境變數屬性

若希望某個屬性僅從環境變數讀取，且不顯示在命令列說明中，使用 `EnvironmentVariable` 屬性會更為直接。

```csharp
public class MyOptions
{
    [EnvironmentVariable("DATABASE_URL")]
    public string DatabaseUrl { get; set; }

    [EnvironmentVariable("API_KEY")]
    public string ApiKey { get; set; }
}

var options = OptionsBuilder.CreateFromEnvironmentOnly<MyOptions>();
Console.WriteLine(options.DatabaseUrl);
```

來源： [EnvironmentVariableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/EnvironmentVariableAttribute.cs#L43-L54)

### 4. 驗證必要項目

`Build(skipValidation: false)` 會驗證所有標記為 `Required = true` 的屬性是否已(透過命令列或環境變數)設定值。

```csharp
// 因未指定 --api-key,此處會擲回例外狀況
var options = OptionsBuilder.Create<MyOptions>(new[] { "--port", "9090" });

// 略過必要項目檢查,適合設定預設值的案例
var defaults = OptionsBuilder.CreateDefault<MyOptions>();
```

來源： [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L67)、[AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L36-L52)

## 常見變化

- **布林切換**:`[FlagOption]` 使布林型別屬性僅以 `--verbose` 形式出現，無需指定 `true`/`false`。來源： [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L20)
- **敏感資訊遮罩**：在 `Option` 上加入 `Sensitive = true` 後，`OptionsDebugger` 輸出時會自動隱藏該值。來源： [OptionAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/Attributes/OptionAttribute.cs#L104-L112)
- **多個屬性的組合**：當同一個屬性同時以 `Option` 與其他屬性修飾時，建置器會將 `Option` 作為主要屬性處理。來源： [AttributeOptionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/AttributeOptionsTests.cs#L28-L32)

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| `Build()` 擲回「缺少必要選項」例外狀況 | 標記為 `Required = true` 的屬性未從命令列或環境變數設定值 | 加入引數，或在測試案例中呼叫 `Build(skipValidation: true)` |
| 環境變數未生效 | 建構 `OptionsBuilder` 時明確傳入 `useEnvironmentVariables: false`,或使用了 `CreateFromArgsOnly` | 使用 `Create<TOptions>(args)`(預設為 `true`)或 `CreateFromEnvironmentOnly<TOptions>()` |
| 未標記屬性的屬性遭到忽略 | 架構僅解析帶有屬性的屬性，一般屬性會保留型別預設值 | 在需要繫結的屬性上加入 `Option`、`FlagOption` 或 `EnvironmentVariable` |

## 背景說明(選擇性)

`OptionsBuilder<T>` 會使用反映遍歷 `T` 的公用屬性，並依據屬性中繼資料決定要從命令列引數、環境變數或預設值取得值。`EnvironmentVariableAttribute` 與 `OptionAttribute.EnvironmentVariable` 是相同機制的兩個進入點，前者適用於「僅環境變數」的屬性，後者適用於可由「命令列 + 環境變數」覆寫的屬性。
