# 환경 준비 및 로컬 빌드

이 섹션에서는 GameFrameX 서버를 실행하는 데 필요한 환경과 도구를 로컬에서 준비하고, 콘솔에서 서버 시작 로그를 확인할 수 있을 때까지 첫 빌드를 완료하는 과정을 안내합니다.

## 사전 조건

| 도구/구성 요소 | 요구 사항 | 비고 |
|----------|------|------|
| .NET SDK | .NET 10.0 SDK만 지원 | .NET 8/9와 호환되지 않음 |
| 데이터베이스 | MongoDB 4.x 이상 | 로컬 설치 또는 Docker로 실행 가능 |
| IDE | Visual Studio 2022 또는 JetBrains Rider | .NET 10을 인식할 수 있는 편집기라면 무엇이든 사용 가능 |
| 선택 사항 | Docker | MongoDB 컨테이너를 빠르게 띄우는 데 사용 |
| 선택 사항 | Git | 저장소 클론용 |

> 위 버전 요구 사항은 프로젝트 README의 "환경 요구 사항" 섹션([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L168-L172))에서 가져온 것입니다. 배지에도 `.NET-10.0`이 명시되어 있습니다([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L8)).

## 작업 단계

1. **저장소를 클론하고 서버 디렉터리로 이동**

   ```bash
   git clone https://github.com/GameFrameX/GameFrameX.git
   cd GameFrameX/Server
   ```

2. **NuGet 종속성 복원**

   ```bash
   dotnet restore
   ```

   이 명령은 `GameFrameX.AppHost` 등의 프로젝트에 있는 `Aspire.Hosting.*` 등의 NuGet 패키지를 가져옵니다([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L9-L12)).

3. **솔루션 빌드**

   ```bash
   dotnet build
   ```

   첫 빌드에서는 모든 모듈(핫픽스 레이어 `Hotfix` 및 퍼시스턴스 레이어 `Apps` 포함)이 컴파일되며, 빌드 결과물은 각 프로젝트의 `bin/` 디렉터리에 출력됩니다.

4. **MongoDB 시작**

   아래 방법 중 하나를 선택하면 됩니다:

   ```bash
   # 방법 1: 로컬 mongod
   mongod --dbpath /path/to/data

   # 방법 2: Docker
   docker run -d -p 27017:27017 --name mongo mongo:8.2
   ```

   시작에 성공하면 MongoDB는 기본적으로 `127.0.0.1:27017`에서 수신 대기합니다.

5. **Launcher를 실행하여 서버 시작**

   명령줄 인수로 서비스 유형과 포트를 지정합니다(자세한 인수는 "시작 매개변수" 참조 페이지 참고):

   ```bash
   dotnet run --project GameFrameX.Launcher -- \
       --ServerType=Game \
       --ServerId=1000 \
       --OuterPort=29100 \
       --HttpPort=28080 \
       --DataBaseUrl=mongodb://127.0.0.1:27017 \
       --DataBaseName=gameframex
   ```

   위 명령은 README에서 제공하는 "최소 시작" 경로([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L203-L210))에 해당합니다.

6. **시작 확인**

   - 브라우저 또는 curl로 `http://localhost:28080/game/api/health`에 접속하여 헬스 상태가 반환되는지 확인합니다.
   - Launcher 콘솔에서 로그를 확인하여 Actor와 네트워크 수신 대기가 모두 준비되었는지 확인합니다.

## 일반적인 변형

### Aspire AppHost로 원클릭 오케스트레이션

저장소 루트 디렉터리에는 `.NET Aspire` SDK를 사용하며 MongoDB 구성 요소를 참조하는 `GameFrameX.AppHost` 프로젝트가 있습니다([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19)). AppHost를 F5로 직접 실행하면 Aspire Dashboard가 MongoDB와 Launcher를 자동으로 띄웁니다:

```bash
dotnet run --project GameFrameX.AppHost
```

### IDE에서 디버깅

Rider/VS에서 `GameFrameX.Launcher`를 시작 프로젝트로 설정하고, 위의 명령줄 인수를 "실행 구성 → Program arguments"에 붙여넣으면 중단점을 사용해 시작 흐름을 디버깅할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `dotnet restore` 시 `NETSDK1045` 오류 발생, .NET 10 미설치 표시 | .NET 8/9는 설치되어 있으나 .NET 10이 없음 | [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)를 설치하고 기본 SDK로 설정 |
| 빌드 시 `NU1605` / 패키지 충돌 발생 | 하위 프로젝트가 호환되지 않는 전이 종속성을 고정함 | `bin/`, `obj/` 삭제 후 다시 `dotnet restore` 실행 |
| 시작 시 `MongoDB connection refused` 오류 발생 | MongoDB가 시작되지 않았거나 포트가 사용 중임 | `mongod`가 실행 중인지 확인하거나 `--DataBaseUrl` 조정 |
| 헬스 체크 404 / 포트 응답 없음 | `--HttpPort`가 사용 중이거나 `--OuterPort`가 기존 프로세스와 충돌함 | 포트를 변경한 후 다시 시작 |

## 배경(선택 사항)

프로젝트는 .NET 10 SDK + .NET Aspire 13.4.6를 기반으로 로컬 종속성을 오케스트레이션합니다([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19)). Launcher(`GameFrameX.Launcher`)는 실제로 Actor와 네트워크 수신 대기를 담당하는 프로세스 진입점으로, 명령줄 인수를 `StartupOptions`에 매핑한 다음 `GameFrameX.StartUp`을 구동하여 호스트를 시작합니다.

런타임 구성 항목의 전체 목록은 "시작 매개변수 참조"를 참고하십시오.
