# 코드 서명 구성

`XCodeConfig.json` 설정 파일의 `signing` 노드에 Team ID, 패키지명, 서명 아이덴티티 등의 필드를 입력하면, Unity가 iOS 프로젝트를 내보낸 후 빌드 후처리가 자동으로 이 값들을 Xcode 메인 Target(Unity-iPhone)의 빌드 설정에 기록하므로, Xcode에서 수동으로 서명을 수정할 필요가 없습니다.

## 사전 조건

- Unity iOS 플랫폼에서 정상적으로 빌드가 가능한 상태여야 합니다(PostProcessBuildPlayer 단계에서 이 컴포넌트가 실행됩니다).
- 프로젝트에 `XCodeConfig.json` 설정 파일이 배치되어 있어야 합니다. 없는 경우 저장소의 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) 또는 [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json)을 참고하여 생성할 수 있습니다.
- 수동 서명(Manual) 모드에서는 사전에 Apple Developer 콘솔에서 Provisioning Profile을 생성하고, 로컬 머신에 해당 인증서를 설치해 두어야 합니다.

## 작업 단계

1. 프로젝트의 `XCodeConfig.json`을 열고(또는 새로 생성하여) 최상위에 `signing` 노드를 추가합니다. 저장소에 포함된 Demo의 작성 예시는 다음과 같습니다:

```json
{
  "swiftBridging": true,
  "signing": {
    "teamId": "XXXXXXXXXX",
    "codeSignStyle": "Automatic",
    "provisioningProfileSpecifier": ""
  }
}
```

Source: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L2-L9)

2. 아래 표에 따라 `signing` 내의 필드를 작성합니다. 모든 필드는 선택 사항이며, 비어 있거나 누락된 경우 해당 빌드 설정은 Unity 내보내기 시의 기본값을 유지합니다. `signing` 노드는 메인 프로젝트(Unity-iPhone Target)에만 적용됩니다.

| 필드 | 대응되는 빌드 설정 | 설명 |
|------|--------------|------|
| `teamId` | `DEVELOPMENT_TEAM` | Apple Developer Team ID |
| `bundleId` | `PRODUCT_BUNDLE_IDENTIFIER` | 앱 패키지명(번들 ID) |
| `codeSignIdentity` | `CODE_SIGN_IDENTITY` | 서명 인증서 아이덴티티 |
| `codeSignStyle` | `CODE_SIGN_STYLE` | 서명 방식, `Automatic` 또는 `Manual` |
| `provisioningProfileSpecifier` | `PROVISIONING_PROFILE_SPECIFIER` | 프로비저닝 프로파일 이름(Manual 모드에서만 필요) |

각 필드의 의미와 매핑 관계는 템플릿 파일의 주석과 `SetSigning`의 구현에서 가져온 것입니다:

```csharp
private static void SetSigning(PBXProject proj, string targetGuid, Hashtable signing)
{
    if (signing == null) return;

    var teamId = signing.Get<string>("teamId");
    if (!string.IsNullOrEmpty(teamId))
    {
        proj.SetBuildProperty(targetGuid, "DEVELOPMENT_TEAM", teamId);
    }

    var bundleId = signing.Get<string>("bundleId");
    if (!string.IsNullOrEmpty(bundleId))
    {
        proj.SetBuildProperty(targetGuid, "PRODUCT_BUNDLE_IDENTIFIER", bundleId);
    }
    // codeSignIdentity / codeSignStyle / provisioningProfileSpecifier 역시 비어 있지 않은 경우에만 기록됩니다
}
```

Source: [PostProcessBuildHelper.Signing.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Signing.cs#L15-L48)

3. 자동 서명을 사용하는 경우 `teamId` + `codeSignStyle: "Automatic"`만 설정하면 되며, Xcode가 인증서와 프로비저닝 프로파일을 자동으로 관리합니다.

4. 수동 서명을 사용하는 경우 인증서와 프로비저닝 프로파일 정보를 완성합니다:

```json
{
  "signing": {
    "teamId": "당신의 TeamID",
    "bundleId": "com.yourcompany.yourapp",
    "codeSignStyle": "Manual",
    "provisioningProfileSpecifier": "당신의 프로비저닝 프로파일 이름"
  }
}
```

프로비저닝 프로파일 이름은 Apple Developer 콘솔에서 생성한 Profile 이름과 일치해야 하며, 템플릿 주석에는 이 필드가 "Manual 모드에서만 필요"하다고 명시되어 있습니다([XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json#L14-L15) 참조).

5. iOS 프로젝트를 내보냅니다(또는 빌드를 실행합니다). 후처리가 모든 `XCodeConfig.json`을 읽어 병합한 후, 메인 Target에서 서명 설정을 호출합니다:

```csharp
// 서명 설정 구성 (메인 프로젝트에만 설정)
SetSigning(project, project.GetUnityMainTargetGuid(), finalConfig.Get<Hashtable>("signing"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L96-L97)

6. 확인: 생성된 Xcode 프로젝트를 열고 Unity-iPhone Target → Signing & Capabilities를 선택하여 Team, Bundle Identifier, Provisioning Profile이 구성 내용과 일치하는지 확인합니다. 또는 터미널에서 직접 `xcodebuild -showBuildSettings | grep -E "DEVELOPMENT_TEAM|CODE_SIGN"`을 실행하여 확인할 수 있습니다.

## 일반적인 변형

**채널별로 서명 구성 재정의.** 후처리는 먼저 모든 공통 `XCodeConfig.json`을 병합한 다음, 채널 전용 설정인 `XCodeConfig.{channel}.json`을 병합하며, 채널 설정의 우선순위가 가장 높아 마지막에 병합되어 덮어씁니다. 따라서 서로 다른 채널(예: 패키지명이 다른 클론 앱)별로 채널 파일을 하나씩 배치하고, `signing`에서 차이가 있는 필드만 작성하면 됩니다:

```json
{
  "signing": {
    "bundleId": "com.yourcompany.app.channelA"
  }
}
```

채널 파일의 명명 형식과 병합 순서는 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L76)와 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L80-L83)를 참조하십시오.

**ScriptableObject를 통한 구성.** 저장소에서는 `XcodeConfig` ScriptableObject(메뉴 `XcodeConfig/Create Settings`)도 제공하며, Inspector에서 환경 변수, Plist, Capabilities 등의 설정을 관리하는 데 사용할 수 있습니다([XcodeConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XcodeConfig.cs#L10-L31) 참조). 서명 관련 JSON 필드는 여전히 `signing` 노드를 기준으로 합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 콘솔에 `未找到任何 XCodeConfig 相关配置文件, 跳过设置` 출력 | 프로젝트 내에 스캔 가능한 `XCodeConfig.json`이 없음 | 템플릿에 따라 설정 파일을 배치한 후 다시 내보내기 |
| 콘솔에 `合并后的配置为空，跳过设置` 출력 | 설정 파일은 존재하지만 JSON 파싱 결과가 비어 있음 | JSON 문법이 올바른지 확인 |
| `未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json`(Log 전용) | 채널을 설정했지만 해당 채널 파일이 없음 | 안내 메시지에 해당함; 차이 설정이 필요한 경우 `XCodeConfig.{channel}.json`을 추가로 생성 |
| 내보낸 후 Xcode에서 Team이 여전히 비어 있음 | `teamId`가 비어 있거나 필드명을 잘못 작성함(필드는 비어 있지 않을 때만 기록됨) | 필드명의 철자와 대소문자 확인: `teamId`, `bundleId`, `codeSignIdentity`, `codeSignStyle`, `provisioningProfileSpecifier` |
| 수동 서명 시 프로비저닝 프로파일 불일치 오류 발생 | `provisioningProfileSpecifier`가 실제 Profile 이름과 일치하지 않거나, 로컬 머신에 해당 인증서가 설치되어 있지 않음 | Profile 이름을 확인하고 인증서를 설치 |

위 표의 로그 원문은 설정 로드 및 병합 프로세스에서 가져온 것으로, [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83)를 참조하십시오.

## 배경

서명 설정은 Unity의 PostProcessBuild 단계에서 수행됩니다: 컴포넌트가 프로젝트 내의 모든 `XCodeConfig.json`을 읽어 최종 설정으로 병합하고, 생성된 `Unity-iPhone.xcodeproj/project.pbxproj`를 파싱하여 메인 Target(UnityMainTarget)에만 서명 관련 빌드 설정을 기록한 다음 프로젝트를 디스크에 다시 기록합니다. 모든 서명 필드는 "비어 있지 않을 때만 기록" 원칙을 따르므로 필요한 필드만 구성하면 됩니다. 또한 `signing.bundleId`는 Capabilities 처리에도 전달되어 entitlements 설정과 함께 사용됩니다([PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L116-L119) 참조).
