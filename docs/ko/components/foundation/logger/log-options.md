# Logger 동작 구성 방법(LogOptions)

`LogOptions`를 통해 로그 출력 위치, 레벨, 롤링 정책 및 외부 저장소(파일, MongoDB, GrafanaLoki)의 모든 스위치를 중앙에서 제어할 수 있습니다. 이 페이지를 읽으면 몇 줄의 코드로 사용자 정의 구성을 완료할 수 있습니다.

## 사전 조건

- `GameFrameX.Foundation` 어셈블리를 참조하고, 대상 프레임워크가 .NET을 지원해야 합니다.
- 파일에 로그를 쓰려면 프로세스에 `AppDomain.CurrentDomain.BaseDirectory/data/<logPathName>`에 대한 쓰기 권한이 있어야 합니다.
- MongoDB에 쓰려면 액세스 가능한 MongoDB 서비스가 필요하며, GrafanaLoki에 쓰려면 액세스 가능한 Loki 서비스가 필요합니다.
- 타입이 위치한 네임스페이스: `GameFrameX.Foundation.Logger`, 주요 타입: `LogOptions`, `RollingInterval`(Serilog), `LogEventLevel`(Serilog.Events).

## 구성 항목 빠른 참조

| 속성 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `LogSavePath` | `string` | `<BaseDir>/data/logs` | 로그 파일 절대 경로, 생성 시 `logPathName`을 연결하여 생성 |
| `LogFileName` | `string` | `""`(기본 이름) | 로그 파일 이름, 비워두면 기본값 사용 |
| `LogType` | `string` | `null` | 로그 출처를 식별하는 서버 타입 |
| `LogTagName` | `string` | `""` | 분류에 사용되는 로그 태그 |
| `IsWriteToFile` | `bool` | `true` | 파일에 쓸지 여부 |
| `IsConsole` | `bool` | `true` | 동시에 콘솔에 출력할지 여부 |
| `IsFileSizeLimit` | `bool` | `true` | 단일 파일 크기를 제한할지 여부 |
| `FileSizeLimitBytes` | `int` | `100 * 1024 * 1024` | 단일 파일 바이트 상한, 도달하면 롤링 |
| `RetainedFileCountLimit` | `int?` | `31` | 보존할 과거 로그 수, `null`은 제한 없음을 의미 |
| `RollingInterval` | `RollingInterval` | `Day` | 롤링 간격(Hour/Day/Month 등) |
| `LogEventLevel` | `LogEventLevel` | `Debug` | 최소 출력 레벨, 이 레벨보다 낮으면 기록하지 않음 |
| `IsWriteToMongoDb` | `bool` | `false` | MongoDB에 쓸지 여부 |
| `MongoDbDatabaseUrl` | `string` | `mongodb://127.0.0.1:27017/gameserver?authSource=admin` | MongoDB 연결 문자열 |
| `MongoDbCappedMaxSizeMb` | `int` | `50` | MongoDB 상한 컬렉션 최대 MB |
| `MongoDbCappedMaxDocuments` | `int` | `50000` | MongoDB 상한 컬렉션 최대 문서 수 |
| `IsGrafanaLoki` | `bool` | `false` | GrafanaLoki로 출력할지 여부 |
| `GrafanaLokiUrl` | `string` | `http://localhost:3100` | Loki 서비스 주소 |
| `GrafanaLokiLabels` | `Dictionary<string,string>` | 비어 있음 | Loki 레이블 |
| `GrafanaLokiProperty` | `Dictionary<string,string>` | 비어 있음 | Loki 추가 속성 |
| `GrafanaLokiUserName` / `GrafanaLokiPassword` | `string` | `null` | Loki 인증 |
| `GrafanaLokiCompressionEnabled` | `bool` | `true` | Loki 푸시 시 압축 활성화 여부 |
| `GrafanaLokiBatchSizeLimit` | `int` | `1000` | 배치 임계값, 도달하면 푸시 |
| `GrafanaLokiQueueLimit` | `int` | `100000` | 메모리 큐 상한, 가득 차면 로그 삭제 |
| `GrafanaLokiPeriod` | `int`(초) | `2` | 강제 푸시 주기; `<=0`을 전달하면 2로 폴백 |

속성 기본값 및 시그니처 출처는 [LogOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L47-L289)를 참조하세요.

## 작업 단계

1. **네임스페이스를 가져오고 인스턴스 생성**. 기본 인스턴스는 `LogOptions.Default`를 직접 사용할 수 있으며, `CreateDefault()`을 통해 독립적으로 수정 가능한 복사본을 얻을 수도 있습니다.

```csharp
using GameFrameX.Foundation.Logger;

// 기본 구성을 직접 재사용(읽기 전용 권장 시나리오)
var defaults = LogOptions.Default;

// 수정 가능한 복사본을 가져오기
var options = LogOptions.CreateDefault();
options.LogTagName = "GameServer-01";
```

출처: [LogOptions.cs#L69-L82](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L69-L82)

2. **필요에 따라 출력 대상 및 파일 정책 조정**. 일반적인 조합: 파일 비활성화, Loki로만 출력; 또는 그 반대.

```csharp
var options = LogOptions.CreateDefault();

// 파일 정책
options.IsWriteToFile = true;
options.RollingInterval = RollingInterval.Day;   // 매일 롤링
options.IsFileSizeLimit = true;
options.FileSizeLimitBytes = 50 * 1024 * 1024;   // 50MB
options.RetainedFileCountLimit = 14;             // 14일만 보존

// 콘솔
options.IsConsole = true;

// 레벨
options.LogEventLevel = LogEventLevel.Information;
```

출처: [LogOptions.cs#L243-L277](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L243-L277)

3. **MongoDB 연동**(선택 사항).

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToMongoDb = true;
options.MongoDbDatabaseUrl = "mongodb://user:password@192.168.1.100:27017/gameserver?authSource=admin";
options.MongoDbCappedMaxSizeMb = 200;
options.MongoDbCappedMaxDocuments = 100000;
```

`IsWriteToMongoDb=true`일 때 유효한 `MongoDbDatabaseUrl`을 반드시 구성해야 합니다; 연결 문자열 형식은 소스 파일의 예제를 참조하세요. 출처: [LogOptions.cs#L108-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L108-L145)

4. **GrafanaLoki 연동**(선택 사항). Loki를 활성화한 후에는 서비스 주소, 레이블 및 인증을 구성해야 합니다; 배치 매개변수 조정을 통해 처리량과 백프레셔를 제어할 수 있습니다.

```csharp
var options = LogOptions.CreateDefault();
options.IsGrafanaLoki = true;
options.GrafanaLokiUrl = "http://loki.internal:3100";
options.GrafanaLokiUserName = "loki";
options.GrafanaLokiPassword = "secret";
options.GrafanaLokiLabels["app"] = "gameserver";
options.GrafanaLokiLabels["env"] = "prod";
options.GrafanaLokiBatchSizeLimit = 2000;     // 2000개 모은 후 푸시
options.GrafanaLokiQueueLimit = 200000;       // 메모리 큐 상한
options.GrafanaLokiPeriod = 5;                // 5초마다 강제 푸시
options.GrafanaLokiCompressionEnabled = true;
```

`GrafanaLokiPeriod`에 `<=0`을 전달하면 2초로 강제 폴백됩니다; 큐가 가득 차면 새 로그는 삭제됩니다(백프레셔 보호). 출처: [LogOptions.cs#L168-L235](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L168-L235)

5. **`LogOptions`를 로그 컴포넌트 초기화 진입점에 전달**, 그런 다음 `LogHelper.Info/Debug/...`을 사용하여 출력합니다.

```csharp
// 로그 진입점에 LogOptions가 필요하다고 가정
LogHelper.Init(options);

LogHelper.Info("서비스 시작 완료");
LogHelper.Debug("디버그 정보:플레이어 {0}가 인스턴스에 진입", playerId);
```

> 호출 진입점 이름은 프로젝트에서 참조하는 초기화 메서드를 기준으로 하세요(이 저장소의 `LogOptions` 클래스 자체는 로그 채널 초기화를 담당하지 않습니다).

## 일반적인 변형

- **다중 테넌트/다중 서버 로그 구분**: `LogType`과 `LogTagName`을 설정하면 파일 경로가 `LogSavePath` 아래에 위치하여 서버별로 디렉토리를 구분하기 편리합니다.
- **생성 시 루트 디렉토리 사용자 정의**: `new LogOptions("gateway-logs")`는 로그를 `<BaseDir>/data/gateway-logs`에 배치하며, 비워두면 `logs`로 폴백됩니다.

```csharp
var options = new LogOptions("gateway-logs");
options.LogType = "Gateway";
options.LogTagName = "GW-01";
```

출처: [LogOptions.cs#L53-L61](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L53-L61)

- **파일 비활성화, Loki만 사용**: 컨테이너화된 배포에 적합하며, 로그를 통합 수집합니다.

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToFile = false;
options.IsConsole = false;
options.IsGrafanaLoki = true;
```

- **보존 파일 수 제한 없음**: `options.RetainedFileCountLimit = null;`.

## 일반적인 오류

| 증상/오용 | 원인 | 수정 |
|----------|------|------|
| 로그 파일이 예상 디렉토리에 나타나지 않음 | `LogSavePath`의 기본값이 현재 디렉토리라고 잘못 인식 | 실제 기본값은 `<AppDomain.BaseDirectory>/data/logs`이며, 생성 매개변수 `logPathName`으로 조정 가능 |
| MongoDB 활성화 후 쓰기 실패 | `MongoDbDatabaseUrl`이 구성되지 않았거나 MongoDB가 리스닝하지 않음 | 소스 파일 예제에 따라 연결 문자열을 입력하고 서비스 사용 가능 여부 확인 |
| Loki 푸시가 거의 움직이지 않음 | `GrafanaLokiBatchSizeLimit`이 너무 크고 `Period`도 매우 큼 | 배치 임계값을 줄이거나 `Period`를 줄임; `Period<=0`은 2초로 강제 폴백됨 |
| 디스크 폭증 | `RetainedFileCountLimit`이 설정되지 않았거나 `IsFileSizeLimit=false` | 적절한 보존 수(예: 14/31)를 설정하고 단일 파일 크기 제한 활성화 |
| `LogOptions.Default` 수정이 적용되지 않음 | `Default`는 읽기 전용 정적 인스턴스로, 동일한 것을 공유 | `CreateDefault()`을 사용하여 독립적인 복사본을 얻은 후 수정 |

## 배경(선택 사항)

`LogOptions`는 POCO(순수 속성 객체)이며, 자체적으로 직접 Serilog 파이프라인을 구성하지 않습니다; 이러한 스위치를 실제로 사용하는 초기화 로직은 로그 진입점 구현에 있습니다. 설계상 "어떻게 기록할지"와 "어디에 기록할지"를 분리합니다: 레벨, 롤링, 압축은 일반 정책이고, 파일/MongoDB/Loki는 독립적으로 활성화할 수 있는 sink입니다.

로그의 전체 초기화 및 `LogHelper` 사용법은 《Logger 빠른 시작》을 참조하세요.
