# 服務啟動報 GameApp.Entry / Init 初始化失敗怎麼辦

服務在啟動進入點 `GameFrameX.Launcher/Program.cs` 呼叫 `GameApp.Entry` 時擲回例外狀況，或 `Init` 回呼中的初始化邏輯報錯，導致處理程序直接結束。本頁協助你依報錯訊息快速定位是組態、元件註冊還是協定掃描出了問題。

## 快速診斷

| 症狀 / 報錯關鍵字 | 原因 | 修復 |
|-------------------|------|------|
| `EntryPointNotFoundException` / 找不到 `GameApp.Entry` | 啟動專案未參考 `GameFrameX.Launcher` 或基準套件未還原 | 見下方「修復步驟 - 1. 進入點找不到」 |
| `CacheStateTypeManager.Init` 階段擲回例外狀況 | 實體類別未實作 `ICacheState` 介面，或組件未正確載入 | 見下方「修復步驟 - 2. 實體類別掃描失敗」 |
| `MessageProtoHelper.Init` 擲回 `NullReferenceException` / 找不到協定 | 協定類別庫未產生，或傳入的 `Assembly` 不包含 `MessageProtoHandler` | 見下方「修復步驟 - 3. 協定初始化失敗」 |
| `BsonClassMap` 註冊衝突(重複註冊同一類型) | 重複呼叫 `Init`,或多個組件包含同名實體 | 確認僅在啟動時呼叫一次 `Init`,移除重複實體類別 |
| `appsettings.json` 剖析失敗 / 連線字串為空 | 組態遺漏或 `GameFrameX.Config` 組態表未產生 | 見下方「修復步驟 - 4. 組態檔相關」 |
| 啟動卡住不結束，也無報錯 | `Init` 回呼中封鎖呼叫，或背景執行緒未啟動 | 見下方「修復步驟 - 5. 啟動卡死」 |

## 修復步驟

### 1. 進入點找不到 `GameApp.Entry`

`GameApp.Entry` 位於基準引擎套件中，啟動器相依於它作為啟動總進入點。

```csharp
// GameFrameX.Launcher/Program.cs
internal static class Program
{
    private static async Task Main(string[] args)
    {
#if DEBUG
        LogOptions.Default.IsConsole = true;
#endif
        await GameApp.Entry(args, () =>
        {
            CacheStateTypeManager.Init();
            MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
        }, LogAction);
    }
}
```

來源:[GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L1-L28)

處理方式：

1. 在啟動專案根目錄執行 `dotnet restore`,確認 NuGet 來源可存取。
2. 檢查 `.csproj` 中是否參考了 `GameFrameX.Launcher`(或對應的基準套件)。
3. 清理輸出目錄後重新建置:`dotnet clean && dotnet build`。

### 2. `CacheStateTypeManager.Init` 階段擲回例外狀況

`CacheStateTypeManager.Init` 會掃描 `AppsHandler` 所在組件中所有實作 `ICacheState` 的類型，並將它們的 Bson 對應註冊到 MongoDB 驅動程式。

```csharp
// GameFrameX.Apps/CacheStateTypeManager.cs
public static void Init()
{
    var assembly = typeof(AppsHandler).Assembly;
    BsonClassMapHelper.SetConvention();

    var types = assembly.GetTypes();
    foreach (var type in types)
    {
        var isImplWithInterface = type.IsImplWithInterface(typeof(ICacheState));
        if (isImplWithInterface)
        {
            HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
            BsonClassMapHelper.RegisterClass(type);
        }
    }
}
```

來源:[GameFrameX.Apps/CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L12-L45)

常見原因及處理：

| 子症狀 | 處理 |
|--------|------|
| `ReflectionTypeLoadException` | 組件中存在相依性遺漏的組件，清理 NuGet 後重新建置 |
| `BsonClassMap already registered for type` | 重複呼叫 `Init`,確認啟動進入點只呼叫一次 |
| 某些實體序列化失敗 | 在實體類別上使用 `[BsonIgnoreExtraElements]` 或依文件補齊欄位 |

### 3. `MessageProtoHelper.Init` 協定初始化失敗

`Program.cs` 中透過 `MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly)` 將所有協定訊息類別註冊到分發系統。

```csharp
MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
```

來源:[GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L12-L16)

處理方式：

1. 確認協定產生器已執行，專案中已產生 `MessageProtoHandler` 等類別。
2. 如果你把協定類別拆到獨立專案，需要把協定專案參考到啟動專案中，並將 `typeof(MessageProtoHandler)` 取代為協定專案中對應的進入點類型。
3. 若 `Initialize` 擲回「重複請求 ID / 操作編號衝突」，表示用戶端/伺服器端協定版本不一致，需重新產生協定並保持版本同步。

### 4. 組態檔相關

啟動流程相依於 `GameFrameX.Config` 產生的組態表(例如 `Property`、`PropItem`、`TablesComponent` 等)。這些類別會在建構函式結尾呼叫 `partial void PostInit();`。若組態表檔案遺漏，會在 `TablesComponent.ResolveRef()` 之前就已經報「找不到表」。

處理方式：

1. 先執行組態產生工具(常見進入點是 `GameFrameX.Config.Tools` 或存放庫文件中說明的 `dotnet run --project ...` 之類的命令)，把所有 `*.cs` 重新產生。
2. 確認 `appsettings.json` 存在，且包含 MongoDB、Redis、網路接聽連接埠等節點。
3. 重新產生後再編譯啟動專案。

### 5. 啟動卡死

如果 `GameApp.Entry` 一直沒有傳回：

- 檢查 `Init` 回呼中是否有封鎖呼叫或同步等待(例如 `Thread.Sleep`、同步 HttpClient)。
- 確認網路接聽組態正確，Mongo/Redis 連線可達，網路元件不會因重試而卡死。
- 在偵錯模式下保留 `LogOptions.Default.IsConsole = true`,便於看到卡死前的日誌。

## 驗證

按下面順序驗證啟動是否恢復正常：

1. 重新執行 `dotnet build`,確保沒有重新出現的編譯錯誤。
2. 啟動程式，確認日誌中出現 `Server started` 或類似的「接聽中」提示。
3. 用 `mongosh` 等工具查詢 Mongo 中的實體集合，確認 `BsonClassMap` 註冊成功(無啟動期間例外狀況)。
4. 用戶端傳送第一則訊息，能正確進入對應的 `MessageProtoHandler` 處理函式。

如果以上均通過，但仍無法啟動，請收集完整啟動日誌與堆疊，聯絡框架維護人員並附上報錯上下文中 `Program.cs` 呼叫 `GameApp.Entry` 的原始碼版本。
