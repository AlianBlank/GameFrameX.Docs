# What to Do When Load or Unload Events Are Not Triggered

When you call `SceneComponent.LoadScene` / `UnloadScene` and find that none of the events `LoadSceneSuccess`, `LoadSceneFailure`, `UnloadSceneSuccess`, `UnloadSceneFailure`, or `LoadSceneUpdate` are received, follow the troubleshooting steps on this page one by one.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| No event callbacks throughout the entire load/unload process | `EventComponent` is not registered to `GameEntry`, or `Event component is invalid.` is printed when the scene component starts | Confirm that `EventComponent` is attached to `GameEntry` and is initialized before `SceneComponent` |
| Only `LoadSceneUpdate` is not received | The `Enable Load Scene Update Event` option in `SceneComponent` is unchecked | Check `Enable Load Scene Update Event` in the Inspector, or set `m_EnableLoadSceneUpdateEvent` back to `true` in the Prefab |
| `LoadSceneFailure` is received but `UserData` is null | The load failure occurred before obtaining the `YooAsset` handle | Check whether `sceneAssetName` starts with `Assets/` and exists in the build manifest. See details below |
| Events are received but the business-side handler is not executed | The `EventId` is incorrect in `Subscribe`, or the subscription happens before `Awake` | Use `typeof(...).FullName` as the `EventId`, and confirm the subscription timing is after `GameEntry` startup |
| Loading the same scene repeatedly, the second time `LoadSceneSuccess` is not received | After the first success, the scene has been added to `LoadedScenes`, so calling `LoadScene` again goes through the YooAsset synchronous path | See the "Common Variants" section |

## Fix Steps

### 1. Confirm SceneComponent Is Attached and Started

`SceneComponent` checks the scene manager and event component in `Awake`. If either is missing, it logs `Fatal` and returns directly, after which no events will be dispatched:

```csharp
// Runtime/Scene/SceneComponent.cs
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IGameSceneManager);
    base.Awake();
    _gameSceneManager = GameFrameworkEntry.GetModule<IGameSceneManager>();
    if (_gameSceneManager == null)
    {
        Log.Fatal("Scene manager is invalid.");
        return;
    }
    // ... subscribe events
    m_GameFrameworkScene = UnityEngine.SceneManagement.SceneManager.GetSceneAt(GameEntry.GameFrameworkSceneId);
    if (!m_GameFrameworkScene.IsValid())
    {
        Log.Fatal("Game Framework scene is invalid.");
        return;
    }
}
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L79-L113)

Operations:
1. Select the GameFramework root node of the entry scene and confirm that `Scene Component` exists (menu path `GameFrameX/Scene`).
2. Check the Console after running to see if there are any fatal logs such as `Scene manager is invalid.` or `Game Framework scene is invalid.`.
3. If any of these appear, it means `SceneComponent` failed to complete the subscription, and this must be resolved first.

### 2. Confirm EventComponent Is Attached

The `Start` phase re-validates `EventComponent`. If it is missing, `Fatal` is logged and the method returns directly. At this point, the event subscription is already hooked on `_gameSceneManager`, but it will no longer be `Fire`d to the upper layer:

```csharp
// Runtime/Scene/SceneComponent.cs
private void Start()
{
    BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
    if (baseComponent == null)
    {
        Log.Fatal("Base component is invalid.");
        return;
    }

    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event component is invalid.");
        return;
    }
    // ...
}
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L115-L139)

Operation: Add an `Event Component` to the GameFramework root node and ensure its priority is earlier than that of `SceneComponent` (the `GameFrameXAutoComponent` priority of `SceneComponent` is `-4000`, see [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L48)).

### 3. Subscribe to Events Correctly on the Business Side

Events are dispatched through `EventComponent.Fire`. The subscriber must use the `EventId` of the corresponding `EventArgs` type (i.e., `typeof(...).FullName`):

```csharp
// Runtime/EventArgs/LoadSceneSuccessEventArgs.cs
public sealed class LoadSceneSuccessEventArgs : GameEventArgs { /* ... */ }

// Runtime/EventArgs/LoadSceneFailureEventArgs.cs
public static readonly string EventId = typeof(LoadSceneFailureEventArgs).FullName;
```

Source: [LoadSceneSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneSuccessEventArgs.cs#L40-L41), [LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs#L46)

Subscription example (using the standard API of `GameFrameX.Event.Runtime.EventComponent`):

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    LoadSceneSuccessEventArgs.EventId,
    OnLoadSceneSuccess);

private void OnLoadSceneSuccess(object sender, GameEventArgs e)
{
    var args = (LoadSceneSuccessEventArgs)e;
    // args.SceneAssetName / args.Duration / args.UserData
}
```

Common pitfalls:

| Incorrect写法 | Result |
|----------|------|
| Using string literal `LoadSceneSuccessEventArgs.EventId` with typos or missing spaces | Events will never be received |
| Using the `Subscribe<LoadSceneSuccessEventArgs>(handler)` overload but the type does not expose `EventId` | Compile-time error or silent runtime failure |
| Subscription is written in a static constructor or domain initialization, after the event is fired | This callback is missed |

### 4. Check Whether LoadSceneUpdate Is Disabled by a Toggle

`SceneComponent` subscribes to `LoadSceneUpdate` by default, but the corresponding field can be turned off in the Inspector:

```csharp
// Runtime/Scene/SceneComponent.cs
[SerializeField] private bool m_EnableLoadSceneUpdateEvent = true;
if (m_EnableLoadSceneUpdateEvent)
{
    _gameSceneManager.LoadSceneUpdate += OnLoadGameSceneUpdate;
}
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L63-L97)

If only `LoadSceneUpdate` is missing, select the `Scene Component` in the scene and check `Enable Load Scene Update Event`.

### 5. Check Whether SceneAssetName Is Valid

`HasScene` will reject names that do not start with `Assets/`:

```csharp
// Runtime/Scene/SceneComponent.cs
public bool HasScene(string sceneAssetName)
{
    if (string.IsNullOrEmpty(sceneAssetName))
    {
        Log.Error("Scene asset name is invalid.");
        return false;
    }
    if (!sceneAssetName.StartsWith("Assets/", StringComparison.Ordinal) ||
        // ...
        )
    {
        Log.Error("Scene asset name '{0}' is invalid.", sceneAssetName);
        return false;
    }
    // ...
}
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L271-L295)

Passing an incorrect name will trigger `LoadSceneFailure`, and the error message is usually `Scene asset name 'xxx' is invalid.`.

### 6. Check the State of the Underlying YooAsset Handle

`GameSceneManager` dispatches success/failure through `YooAsset.SceneHandle`. If handle creation fails, the scene will not enter `m_LoadingSceneAssetNames`, and naturally no subsequent events will be triggered:

```csharp
// Runtime/Scene/Scene/GameSceneManager.cs
private readonly Dictionary<string, YooAsset.SceneHandle> m_LoadedSceneAssetNames;
private readonly Dictionary<string, SceneHandleData> m_LoadingSceneAssetNames;
private readonly Dictionary<string, YooAsset.SceneHandle> m_UnloadingSceneAssetNames;
```

Source: [GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L59-L61)

Call `SceneComponent.GetLoadingSceneAssetNames()` and `GetUnloadingSceneAssetNames()` in the error scenario. If they return empty, it means the asynchronous queue was never entered and events will not be triggered—go back to step 5 to check the resource name.

## Verification

After completing the above steps, confirm according to the following table:

| Verification Item | Expected |
|--------|------|
| Console has no Fatal logs such as `Scene manager is invalid.` | Yes |
| The business-side `LoadSceneSuccessEventArgs` callback is hit, and `SceneAssetName` equals the requested value | Yes |
| `LoadSceneFailure` is triggered only when an incorrect name is intentionally passed, and carries `ErrorMessage` | Yes |
| `LoadSceneUpdate` progress is triggered continuously from 0 to 1, and finally hits `LoadSceneSuccess` | Yes |
| `UnloadSceneSuccess` is hit after an active `UnloadScene` | Yes |

If only individual events are missing, go back to the "Quick Diagnosis" table to locate the specific row. If all events are missing and there are no Fatal logs, it can almost certainly be confirmed that `EventComponent` is not attached or the subscription timing is too early.
