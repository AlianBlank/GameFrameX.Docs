# YooAsset 補丁流程失敗時的處理方法

YooAsset 補丁流程在 `ProcedurePatchInit` → `ProcedureUpdateStaticVersion` → `ProcedureUpdateManifest` → `ProcedureCreateDownloader` → `ProcedureDownloadWebFiles` → `ProcedurePatchDone` 鏈中的任何一個階段發生例外時，啟動流程會停止或返回上層流程。本文件按症狀提供原因排查與修復方法。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 卡在 `ProcedurePatchInit` 且資源套件初始化失敗 | `packageUrl` 為空或無法存取 CDN | 確認 `procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName)` 是否已正確寫入；確認 CDN 是否可存取 |
| 卡在 `ProcedureUpdateStaticVersion` 且顯示版本不一致訊息 | 遠端靜態版本號與本機不一致 | 重新建置後發布遠端靜態版本檔案；確認 `StaticVersion.txt` 已上傳 |
| `ProcedureUpdateManifest` 發生清單錯誤 | 遠端清單檔案未發布或簽章錯誤 | 重新發布資源清單（`PackageManifest_{ver}.hash` / `.bytes`）並確認 YooAsset 加密金鑰 |
| 進入 `ProcedureDownloadWebFiles` 後進度停滯 | 下載器為空或 HTTP 速度限制 | 確認 `ProcedureCreateDownloader` 的產出中是否包含 `VarObject` 鍵 `"Downloader"`；確認代理伺服器/頻寬 |
| 下載中途返回 `ProcedureCreateDownloader` | 單一檔案下載失敗觸發 `OnDownloadErrorCallback` | 檢查 `AssetWebFileDownloadFailedEventArgs` 的 `FileName` 與 `ErrorInfo`，找出遠端遺漏的檔案 |
| `ProcedureDownloadWebFiles` 完成後未進入 `ProcedurePatchDone` | `downloader.Status != EOperationStatus.Succeed` | 檢查先前的 `OnDownloadError` 日誌，補齊遺漏的資源後重新啟動 |

## 修復步驟

### 1. 資源套件初始化失敗

`ProcedurePatchInit` 依 `GamePlayMode` 選擇初始化分支：EditorSimulate/Offline 使用空 URL，其餘模式使用以 `BuildInPackageName` 取得的套件位址。

```csharp
// ProcedurePatchInit.InitPatchAsync (Runtime/Procedures/Patch/ProcedurePatchInit.cs)
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode || assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, string.Empty, string.Empty, true);
    ChangeState<ProcedureUpdateStaticVersion>(procedureOwner);
    return;
}

var packageUrl = procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName);
await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, packageUrl.Value, packageUrl.Value, true);
```

來源：[ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L33-L48)

修復操作：

1. 在除錯模式（EditorSimulate）中重現問題，以排除 CDN 網路問題。
2. 確認 `ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState` 是否已將 `packageUrl` 寫入 BlackBoard。
3. 在實機模式下確認 `StartupOptions.PlayMode` 是否被 `NormalizeAssetPlayMode` 變更（WebGL 會被強制為 `WebPlayMode`，編輯器以外的環境中 `EditorSimulateMode` 會被強制變更為 `HostPlayMode`）。

### 2. 靜態版本/清單更新失敗

`ProcedureUpdateStaticVersion` 與 `ProcedureUpdateManifest` 由 YooAsset 內建流程驅動。常見失敗原因：

- 遠端只上傳了 `StaticVersion.txt`，未上傳 `PackageManifest_*.bytes`。
- YooAsset 加密金鑰與編輯器不一致，導致清單解析失敗。

修復操作：

1. 使用建置工具（Builtin Build Pipeline）重新建置後，將 `ServerData/{Platform}` 整個目錄全部上傳，並確保不遺漏 `StaticVersion.txt`。
2. 在編輯器中使用 `YooAsset > AssetBundle Builder` 建置後，在本機啟動 HTTP 伺服器，先以相同 `PlayMode` 進行驗證。
3. 關閉清單加密或確認金鑰一致。

### 3. 下載器為空或下載中斷

`ProcedureDownloadWebFiles` 直接消費 `ProcedureCreateDownloader` 寫入的 `VarObject` 鍵 `"Downloader"`（`ResourceDownloaderOperation`），並透過回呼監視錯誤：

```csharp
// ProcedureDownloadWebFiles.BeginDownload (Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs)
var downloader = (ResourceDownloaderOperation)procedureOwner.GetData<VarObject>("Downloader").GetValue();

downloader.OnDownloadErrorCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetWebFileDownloadFailedEventArgs.Create(data.PackageName, data.FileName, data.ErrorInfo));
    ChangeState<ProcedureCreateDownloader>(procedureOwner);
};
downloader.OnDownloadProgressCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetDownloadProgressUpdateEventArgs.Create(
        data.PackageName, data.TotalDownloadCount, data.CurrentDownloadCount,
        data.TotalDownloadBytes, data.CurrentDownloadBytes));
    StartupProcedureUtility.SetDownloadProgress(
        StartupProcedureUtility.GetUIHandler(procedureOwner),
        data.CurrentDownloadBytes, data.TotalDownloadBytes);
};

downloader.BeginDownload();
yield return downloader;

if (downloader.Status == EOperationStatus.Succeed)
{
    ChangeState<ProcedurePatchDone>(procedureOwner);
}
```

來源：[ProcedureDownloadWebFiles.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs#L36-L61)

修復操作：

1. 訂閱 `AssetWebFileDownloadFailedEventArgs` 檢查 `FileName` 與 `ErrorInfo`，確認該檔案存在於 CDN 且可匿名下載。
2. 若 HTTPS 憑證不受信任，YooAsset 會在 `ErrorInfo` 中回報 SSL 錯誤。可在 YooAsset 設定中為 HostPlayMode 設定憑證，或改回 HTTP。
3. 單一檔案失敗會觸發 `ChangeState<ProcedureCreateDownloader>` 進行重試，因此無需手動介入。若連續失敗，可使用 `ClearCacheWhenDownloadFailure` 等 YooAsset 開關清理本機快取後重新啟動。

### 4. 啟動後在 `ProcedureGameLauncherState` 之前卡住

`ProcedurePatchDone` 是補丁完成的最後一個階段。若流程在此卡住：

- 確認 `ProcedureDownloadWebFiles` 是否成功觸發 `ChangeState<ProcedurePatchDone>`（僅在 `downloader.Status == EOperationStatus.Succeed` 時才會轉換）。
- 確認是否有訂閱 `AssetPatchStatesChangeEventArgs` 的自訂 Procedure 攔截了流程。

## 驗證

1. 重新進入遊戲，觀察在 `ProcedureGetGlobalInfoState` → `ProcedurePatchDone` 之間是否回報 `EPatchStates.DownloadWebFiles` 事件。
2. 在編輯器中使用 `EditorSimulateMode` 並將 `StartupOptions.GlobalInfoUrls` 指定為本機位址，確認補丁鏈正常運作。
3. 在實機模式下開啟 YooAsset 的沙盒目錄（`Application.persistentDataPath/yoo/{PackageName}`），確認 `PackageManifest_*.bytes` 與資源檔案均已儲存。
4. 若以上均正常但仍卡住，清理 YooAsset 沙盒後重新啟動，以排除因髒快取導致的清單驗證失敗。
