# 작동 원리: 컴포넌트 초기화와 이벤트 분배 흐름

`GameAnalyticsComponent`는 씬에 부착되는 Unity 컴포넌트입니다. 이 컴포넌트는 `Awake`에서 자동 등록을 비활성화하고, `OnEnable`에서 Inspector에 구성된 Provider 목록을 읽어 리플렉션으로 각 `IGameAnalyticsManager`를 인스턴스화한 뒤 설정 딕셔너리를 전달해 초기화를 완료합니다. 이후 모든 리포트 호출(`Event` / 타이머 / 공용 속성)은 이 관리자들을 순회하며 하나씩 분배하며, 초기화 가드와 경고 로그가 함께 작동합니다. 이 페이지에서는 이 두 흐름의 실제 실행 순서와 코드 위치를 설명합니다.

## 초기화 흐름(부착부터 사용 가능까지)

1. **컴포넌트 부착**: `GameAnalyticsComponent`는 `GameFrameworkComponent`를 상속하며, `[DisallowMultipleComponent]`와 `[AddComponentMenu("Game Framework/GameAnalytics")]` 어트리뷰트가 붙어 있어 같은 GameObject에는 하나만 부착할 수 있습니다.
2. **`Awake` 단계**: 관리자 목록을 생성하고 컴포넌트의 자동 등록을 끈 뒤(`IsAutoRegister = false`), 기본 클래스의 `Awake()`를 호출합니다:

```csharp
protected override void Awake()
{
    m_GameAnalyticsManager = new List<IGameAnalyticsManager>();
    IsAutoRegister = false;
    base.Awake();
}

private void OnEnable()
{
    Init();
}
```

출처: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L20-L30)

3. **`OnEnable`이 `Init()`을 트리거**: `Init()`은 `m_IsInit`로 멱등성을 보장하여 중복 호출 시 즉시 반환됩니다.
4. **Provider 개별 처리**: 직렬화 필드 `m_gameAnalyticsComponentProviders`(Inspector에서 구성)를 순회하며 각 항목에 대해:
   - `ComponentType`가 공백 문자열이면 해당 항목을 건너뜁니다;
   - `Utility.Assembly.GetType`으로 타입 이름에서 `System.Type`을 해석하며, 해석에 실패하면 오류 로그를 기록하고 `continue`합니다(오류 원문: `Can not find component type '{타입 이름}'.`);
   - `Activator.CreateInstance`로 리플렉션을 통해 인스턴스를 생성하며, `IGameAnalyticsManager`를 구현해야 합니다;
   - Provider의 `Setting` 키-값 쌍을 `Dictionary<string, string>`으로 수집하여 `args`로 사용하고, `gameAnalyticsManager.Init(args)`를 호출한 뒤 `m_GameAnalyticsManager` 목록에 추가합니다.
5. **`m_IsInit = true`로 설정**되면 초기화가 완료되고, 이후 모든 이벤트 호출이 유효해집니다.

```csharp
public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }

            if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
            {
                Dictionary<string, string> args = new Dictionary<string, string>();
                foreach (var param in gameAnalyticsComponentProvider.Setting)
                {
                    args[param.Key] = param.Value;
                }

                gameAnalyticsManager.Init(args);
                m_GameAnalyticsManager.Add(gameAnalyticsManager);
            }
        }
    }

    m_IsInit = true;
}
```

출처: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L47-L80)

6. **(선택) 수동 초기화**: `IsManualInit()`가 `true`를 반환하는 관리자(예: 로그인 후 티켓처럼 런타임에야 얻을 수 있는 매개변수가 필요한 경우)의 경우, 컴포넌트 초기화 이후에 `ManualInit(extraArgs)`를 호출하여 2차 주입합니다:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

출처: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

## 이벤트 분배 흐름

`Event(string eventName)`을 예로 들면, 매번 리포트 시 네 단계를 거칩니다:

1. `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))`: 이벤트 이름이 비어 있으면 즉시 가드 예외를 던집니다;
2. 컴포넌트 수준 가드: `m_IsInit == false`이면 조용히 반환합니다(컴포넌트가 초기화되지 않아 이벤트가 버려짐);
3. `m_GameAnalyticsManager`를 순회하며 각 관리자의 `IsInit()`를 확인합니다;
4. 관리자가 초기화되어 있으면 동일한 이름의 메서드를 호출해 실제 리포트를 수행하고, 그렇지 않으면 `GameAnalyticsManager is not init.` 경고를 출력하고 해당 관리자를 건너뜁니다(다른 관리자의 분배에는 영향을 주지 않음).

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

출처: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

`StartTimer` / `StopTimer`는 완전히 동일한 가드 및 경고 로직을 따릅니다([GameAnalyticsComponent.cs#L160-L179](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179) 및 [#L221-L240](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L221-L240) 참조); `PauseTimer` / `ResumeTimer` / `SetPlayerId`는 비어 있지 않음 가드와 컴포넌트 수준의 `m_IsInit` 검사만 수행하며, 개별 관리자의 `IsInit()` 판단은 하지 않습니다. `Event`에는 네 가지 오버로드가 있습니다: `Event(string)`, `Event(string, float)`, `Event(string, Dictionary<string, object>)`, `Event(string, float, Dictionary<string, object>)`이며, 분배 방식은 모두 동일합니다.

## 가드 및 로그 빠른 참조

| 발생 조건 | 동작 / 로그 원문 | 위치 |
|------|------|------|
| Provider의 `ComponentType`에서 타입을 해석할 수 없음 | `Log.Error($"Can not find component type '{...}'.")`, 해당 Provider 건너뜀 | `Init()` 내부 |
| `eventName`이 비어 있음/null | `GameFrameworkGuard.NotNullOrEmpty`가 예외를 던짐 | 각 타이머/이벤트 메서드 시작 부분 |
| 컴포넌트가 초기화되지 않음(`m_IsInit == false`) | 조용히 반환, 오류 없음 | 모든 분배 메서드 |
| 특정 관리자가 초기화되지 않음(`IsInit() == false`) | `Log.Warning("GameAnalyticsManager is not init.")`, 해당 관리자 건너뜀 | `Event` / `StartTimer` / `StopTimer` |
| `SetPublicProperties`의 key가 비어 있음 | 하위 클래스에서 바로 `return`, 기록하지 않음 | `BaseGameAnalyticsManager` |

## 공용 속성의 주입과 분배

관리자 기본 클래스 `BaseGameAnalyticsManager`는 `GameFrameworkModule`을 상속합니다(따라서 각 관리자 자체도 프레임워크 모듈이며 `Update` / `Shutdown` 라이프사이클 훅을 가지지만, 기본 클래스에서는 빈 구현입니다), 그리고 `m_PublicProperties` 딕셔너리를 유지 관리합니다:

- `SetPublicProperties(key, value)`: key가 비어 있으면 즉시 반환하고, 그렇지 않으면 딕셔너리에 기록합니다;
- `ClearPublicProperties()`: 딕셔너리를 비운 뒤 **즉시 기기 정보를 다시 주입합니다**;
- `GetPublicProperties()`: 딕셔너리의 얕은 복사본을 반환합니다.

```csharp
public virtual void ClearPublicProperties()
{
    m_PublicProperties.Clear();
    AddDeviceInfoToPublicProperties();
}
```

출처: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L70-L74)

`AddDeviceInfoToPublicProperties()`는 `protected virtual`이며, 기본적으로 주입되는 공용 속성은 다음과 같습니다: 기기(`device_id` / `device_model` / `device_type`), 시스템(`os` / `system_language` / `current_culture`), 애플리케이션(`app_version` / `unity_version` / `platform`), CPU 및 메모리(`processor_type` / `processor_count` / `processor_frequency` / `system_memory_size`), 그래픽 카드(`graphics_device_name` 등 5개 항목), 화면(`screen_width` / `screen_height` / `screen_dpi` / `screen_refresh_rate`), 그리고 `Application.internetReachability`로부터 도출되는 `network_type`(가능한 값: `No Network` / `Mobile Data` / `WiFi` / `Unknown`). 하위 클래스는 이를 오버라이드하여 속성을 추가하거나 제거할 수 있습니다. 전체 구현은 [BaseGameAnalyticsManager.cs#L88-L144](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L88-L144)에서 확인할 수 있습니다.

컴포넌트 계층의 `GetPublicProperties()`는 **첫 번째** 관리자의 속성 딕셔너리만 반환합니다(순회 중 첫 번째로 만나면 즉시 `return`). 여러 Provider가 공존할 경우 목록의 가장 앞에 있는 것이 기준이 됩니다.

## 커스텀 Provider 연동 지점

새로운 분석 플랫폼을 추가하려면 `IGameAnalyticsManager`를 구현해야 합니다(또는 `BaseGameAnalyticsManager`를 직접 상속하여 공용 속성 로직을 재사용). 인터페이스는 다음의 구현을 요구합니다: `Init(Dictionary<string, string>)`, `ManualInit(Dictionary<string, string>)`, `IsInit()`, `IsManualInit()`, 공용 속성 3종, `StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer`, 네 가지 `Event` 오버로드, `SetPlayerId`. 전체 인터페이스 정의는 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L46)에서 확인할 수 있습니다. 그 후 Inspector에서 구현 클래스의 타입 이름을 Provider 목록에 입력하고 `Setting` 키-값 쌍을 구성하면, 위 초기화 흐름에 의해 자동으로 인스턴스화되어 이벤트 분배에 포함됩니다.

## 자주 발생하는 오류

- **Provider를 구성했는데 이벤트 리포트가 전혀 없음**: 먼저 Console에 `Can not find component type '...'`이 표시되는지 확인하세요 — 타입 이름 철자 오류나 어셈블리가 빌드에 포함되지 않은 경우 해당 Provider가 건너뛰어집니다. 이어서 구현 클래스에 매개변수 없는 생성자가 있는지 확인하세요(`Activator.CreateInstance`는 기본 생성자를 사용).
- **`GameAnalyticsManager is not init.` 경고가 반복적으로 발생함**: 컴포넌트 계층은 초기화되었지만(`m_IsInit == true`), 특정 관리자가 자체 `Init(args)` 이후 내부 상태를 초기화됨으로 설정하지 않았다는 의미입니다. 구현 클래스의 문제이며 컴포넌트와는 무관합니다.
- **로그인 전 `Event` 호출이 조용히 버려짐**: 컴포넌트가 초기화되지 않은 상태에서는 모든 분배 메서드가 즉시 `return`되며 로그가 발생하지 않습니다; `OnEnable`이 실행되었는지, `Init()`이 호출되었는지 확인하세요.
- **`ClearPublicProperties` 후에도 공용 속성이 "깨끗이 지워지지 않음"**: 이는 의도된 설계 동작입니다 — 비운 후 기기 정보가 자동으로 다시 기록되므로 기기 관련 필드는 항상 존재합니다.

## 배경

컴포넌트는 `IsAutoRegister = false`를 사용해 GameFrameX의 컴포넌트 자동 등록 메커니즘이 미리 개입하는 것을 차단함으로써, 초기화 시점이 완전히 `OnEnable`에 의해 제어되도록 보장합니다. "리플렉션 + 타입 이름 문자열" 방식으로 Provider를 로드하기 때문에, 이 패키지는 구체적인 플랫폼 SDK를 전혀 참조하지 않고도 멀티 플랫폼 병렬 리포트를 구성할 수 있으며, 이벤트 한 번의 호출로 초기화된 모든 관리자에게 브로드캐스트됩니다.
