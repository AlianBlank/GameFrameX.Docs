# 初始化報錯 "Can not find component type" 怎麼辦

這個錯誤由 `GameAnalyticsComponent.Init()` 拋出：Inspector 中設定的某個分析元件，其 `ComponentType` 字串在執行階段無法被 `Utility.Assembly.GetType()` 解析為真實型別，該 Provider 會被直接跳過(`continue`),對應的統計渠道完全不會上報資料。修復核心是讓 `ComponentType` 與實際存在的、實作了 `IGameAnalyticsManager` 的類別的完整型別名稱(含命名空間)一致。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `Can not find component type 'XXX'` 且該渠道無任何上報 | `ComponentType` 字串與真實類別名稱/命名空間不一致(手動修改過文字、類別被重新命名) | 在 Inspector 下拉式選單中重新選擇正確型別，見下方步驟 1 |
| 編輯器正常、實機打包後報錯 | 實作類別所在的組件/程式碼被裁剪或未打包進建置 | 確認實作類別的組件參與建置、未被程式碼裁剪移除 |
| 設定中的類別確實存在但仍報錯 | 型別名稱未包含完整命名空間，`Utility.Assembly.GetType` 找不到 | 使用完整型別名稱，如 `GameFrameX.GameAnalytics.Runtime.XXXManager` |
| 下拉清單中根本沒有想要的型別 | 該類別沒有實作 `IGameAnalyticsManager` 介面，不會被 Inspector 列出 | 讓類別實作 `IGameAnalyticsManager`(通常繼承 `BaseGameAnalyticsManager`) |

錯誤來源的判定邏輯(注意：即使型別能找到但不實作 `IGameAnalyticsManager`,也只是靜默不生效，不會報錯):

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }
```

## 修復步驟

### 1. 用 Inspector 下拉式選單重新選擇型別，不要手動填寫字串

選取場景中的 GameAnalytics 元件(`AddComponentMenu("Game Framework/GameAnalytics")`),在 Inspector 的「遊戲資料分析元件列表，依序上報」列表中為出錯的條目重新選擇 ComponentType。

下拉式選單中的候選清單由 `GameAnalyticsComponentInspector.RefreshTypeNames()` 生成：它會掃描所有實作了 `IGameAnalyticsManager` 的執行階段型別，外加一個 `NoneOptionName` 空選項。

```csharp
protected override void RefreshTypeNames()
{
    List<string> managerTypeNameList = new List<string>
    {
        NoneOptionName
    };
    managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
    m_ManagerTypeNames = managerTypeNameList.ToArray();
}
```

Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

如果下拉式選單中看得到目標型別，直接選取即可——Inspector 寫入的是與執行階段解析一致的型別名稱，能根治手寫拼字/命名空間錯誤。

### 2. 下拉式選單中沒有目標型別時，檢查類別定義

實作類別必須是 `IGameAnalyticsManager` 的實作，最簡單的做法是繼承框架提供的抽象基底類別 `BaseGameAnalyticsManager` 並實作其抽象成員：

```csharp
public abstract class BaseGameAnalyticsManager : GameFrameworkModule, IGameAnalyticsManager
{
    public abstract void Init(Dictionary<string, string> args);
    public abstract void ManualInit(Dictionary<string, string> args);
    public abstract bool IsManualInit();
    ...
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L10-L36)

### 3. 確認設定資料本身有效

`ComponentType` 存在於序列化類別 `GameAnalyticsComponentProvider`(定義於 `Runtime/GameAnalytics/GameAnalyticsComponent.cs` 第 362 行附近)中，會隨場景/預製物件一起序列化。以下情況會產生「殘留的失效型別名稱」：

- 實作類別被刪除或重新命名後，舊場景/預製物件中的序列化字串沒有同步更新；
- 複製別人的場景或預製物件，但其相依的分析 SDK 套件沒有匯入到目前專案。

處理方式：開啟對應的場景/預製物件，把出錯的 Provider 條目改為有效型別，或直接刪除該條目。

## 驗證

1. 重新進入 Play 模式(或重新啟用元件觸發 `OnEnable` → `Init()`),Console 不再出現 `Can not find component type '...'`。
2. 呼叫一次公開 API(如 `GameAnalyticsComponent.SetPlayerId("test")`),確認無異常且資料能到達對應渠道;`Init()` 會遍歷所有已成功建立的 `IGameAnalyticsManager` 並呼叫其 `Init(args)`。

```csharp
var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
{
    Dictionary<string, string> args = new Dictionary<string, string>();
    foreach (var param in gameAnalyticsComponentProvider.Setting)
    {
        args[param.Key] = param.Value;
    }

    gameAnalyticsManager.Init(args);
    m_GameAnalyticsManager.Add(gameAnalyticsManager);
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L65-L75)

注意 `Init()` 有 `m_IsInit` 防重入保護，重複呼叫並不會重新解析型別；驗證時需在全新的一次初始化(重新 Play 或重新啟用元件)中觀察。

## 背景

`GameAnalyticsComponent` 會在 `Awake` 中建構 Provider 列表，`OnEnable` 時呼叫 `Init()`,透過反射 `Utility.Assembly.GetType` + `Activator.CreateInstance` 按字串實例化各分析渠道的管理器，並把 Inspector 中該條目的 `Setting` 字典透傳給 `Init(Dictionary<string, string> args)`。這種「字串 + 反射」的設計讓元件設定可以脫離編譯期相依，代價就是型別名稱失效時只能在執行期發現，表現為本頁的報錯。
