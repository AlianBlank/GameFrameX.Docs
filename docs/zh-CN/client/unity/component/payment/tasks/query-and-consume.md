# 如何查询购买记录与消耗购买

通过 `PaymentComponent` 调用 `QueryPurchases(PaymentProductType productType)` 拉取当前账号未消耗的购买记录，结果通过 `OnQueryPurchasesResult` 事件回调返回；拿到 `PurchaseToken` 后调用 `ConsumePurchase(string purchaseToken)` 完成消耗，结果通过 `OnConsumePurchaseResult` 事件回调返回。两者均为异步、无返回值，只能通过事件获取结果。

## 前置条件

- 场景中已添加 `GameFrameX/Payment` 组件（`PaymentComponent`），并按平台自动装配了对应的 `IPaymentManager` 实现。
- 已调用 `Init(bool isDebug = false, bool isClientVerify = true)` 完成初始化，且 `IsReady()` 返回 `true` 后再发起查询。

## API 一览

| 名称 | 签名 | 说明 |
|------|------|------|
| 查询购买记录 | `void QueryPurchases(PaymentProductType productType)` | 按产品类型查询未消耗的购买记录 |
| 消耗购买 | `void ConsumePurchase(string purchaseToken)` | 用购买令牌消耗一笔购买 |
| 查询结果事件 | `event EventHandler<PaymentEventArgs> OnQueryPurchasesResult` | 查询完成（含失败）时触发 |
| 消耗结果事件 | `event EventHandler<PaymentEventArgs> OnConsumePurchaseResult` | 消耗完成（含失败）时触发 |
| 是否就绪 | `bool IsReady()` | 支付系统是否已初始化完成 |

以上签名定义于 `IPaymentManager`：

```csharp
/// <summary>
/// 查询购买记录结果事件
/// </summary>
event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

/// <summary>
/// 消耗购买结果事件
/// </summary>
event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

/// <summary>
/// 查询购买记录
/// </summary>
/// <param name="productType">产品类型</param>

void QueryPurchases(PaymentProductType productType);

/// <summary>
/// 消耗购买
/// </summary>
/// <param name="purchaseToken">购买令牌</param>
[UnityEngine.Scripting.Preserve]
void ConsumePurchase(string purchaseToken);
```

## 操作步骤

1. 订阅查询与消耗两个结果事件。`PaymentComponent` 上的事件会直接转发给内部 `IPaymentManager`：

```csharp
public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult
{
    add { _paymentManager.OnQueryPurchasesResult += value; }
    remove { _paymentManager.OnQueryPurchasesResult -= value; }
}

public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult
{
    add { _paymentManager.OnConsumePurchaseResult += value; }
    remove { _paymentManager.OnConsumePurchaseResult -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L48-L64)

2. 初始化并确认就绪后，按产品类型发起查询：

```csharp
paymentComponent.Init(isDebug: false, isClientVerify: true);

if (paymentComponent.IsReady())
{
    // 按产品类型（内购 / 订阅）查询当前账号未消耗的购买记录
    paymentComponent.QueryPurchases(productType);
}
```

3. 在 `OnQueryPurchasesResult` 回调中读取结果。成功时每条记录的令牌在 `PaymentEventArgs.PurchaseToken` 中：

```csharp
private void OnQueryPurchasesResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"查询购买记录失败: {e.ResultCode} {e.ErrorMessage}");
        return;
    }

    // 原始购买数据（JSON 格式），可交给服务器校验
    // e.PurchaseData / e.ProductId / e.OrderId / e.PurchaseToken / e.CustomData
}
```

`PaymentEventArgs` 的完整字段：

```csharp
public sealed class PaymentEventArgs : EventArgs
{
    public string ProductId { get; set; }      // 产品ID
    public string OrderId { get; set; }        // 订单ID
    public string PurchaseToken { get; set; }  // 购买令牌
    public PaymentResultCode ResultCode { get; set; } // 支付结果代码
    public string ErrorMessage { get; set; }   // 错误消息
    public string PurchaseData { get; set; }   // 原始购买数据（JSON格式）
    public string CustomData { get; set; }     // 自定义数据
}
```

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

4. （服务器校验通过后）用查询到的令牌消耗购买，并在 `OnConsumePurchaseResult` 中确认结果：

```csharp
paymentComponent.ConsumePurchase(e.PurchaseToken);

private void OnConsumePurchaseResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"消耗购买失败: {e.ResultCode} {e.ErrorMessage}");
        return;
    }
    // 已消耗，可发放/补发道具
}
```

## 常见变体

- **断线重连/补单**：在启动或回到前台时先 `QueryPurchases` 遍历 `OnQueryPurchasesResult` 返回的未消耗记录，校验通过后逐条 `ConsumePurchase`，即可完成掉单补发。
- **订阅商品**：订阅类购买同样通过 `QueryPurchases` 查询，但通常不做 `ConsumePurchase` 消耗（消耗语义针对一次性消耗型商品），是否消耗以渠道实现为准。
- **服务器校验**：若 `Init` 时 `isClientVerify` 设为 `false`，请把回调中的 `PurchaseData` 与 `PurchaseToken` 发给自有服务器验证后再消耗。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 调用后无任何回调 | 未订阅 `OnQueryPurchasesResult` / `OnConsumePurchaseResult` 就发起调用 | 先订阅事件再调用查询/消耗 |
| 日志出现 `Pay Manager is invalid.` | 平台对应的 `IPaymentManager` 实现类未找到或未装配 | 检查 `PaymentComponent` 上各平台实现类名与对应渠道包是否引入 |
| 查询/消耗回调 `ResultCode` 为 `Failed` 或 `NetworkError` | 渠道服务未连接或网络异常 | 稍后重试；`NetworkError` 需恢复网络后重新查询 |
| 消耗失败 `ItemNotOwned` | 令牌对应的购买已被消耗或不存在 | 重新 `QueryPurchases` 拿最新令牌，不要复用旧值 |
| `VerifyFailed` | 购买校验未通过（客户端或服务器验证失败） | 检查校验逻辑与凭证，校验通过后再消耗 |

`PaymentResultCode` 全部取值：`Success`、`Failed`、`Cancelled`、`NetworkError`、`ServiceUnavailable`、`ItemAlreadyOwned`、`ItemNotOwned`、`VerifyFailed`、`Unknown`。

## 验证

- `QueryPurchases` 触发一次 `OnQueryPurchasesResult`，且 `ResultCode == PaymentResultCode.Success`。
- `ConsumePurchase(token)` 触发一次 `OnConsumePurchaseResult`，且 `ResultCode == PaymentResultCode.Success`。
- 再次查询同一产品类型，不再返回已消耗的那条记录。

## 背景

`PaymentComponent` 在 `Awake` 中按编译平台选择实现类（Android 用 `GooglePaymentManager`，iOS/Mac 用 `ApplePaymentManager`，WebGL/PC 各有对应实现，其余平台落到 `DefaultPaymentManager`），再通过 `GameFrameworkEntry.GetModule<IPaymentManager>()` 取得实例；事件与方法都是对该实例的直接转发。`BasePaymentManager` 中的 `RaiseQueryPurchasesResult` / `RaiseConsumePurchaseResult` 负责把各渠道实现的结果分发到上述事件。关于支付系统整体结构，见概述页。
