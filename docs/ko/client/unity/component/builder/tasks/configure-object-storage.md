# 객체 스토리지 구성 방법(텐센트 클라우드/치니우/알리 클라우드)

명령줄 인수와 스크립트 매크로 스위치를 통해 객체 스토리지 자격 증명과 버킷 정보를 GameFrameX 빌드 파이프라인에 연결하여, 빌드 산출물(APK, 로그, 리소스 패키지 등)이 패키징 후 자동으로 텐센트 클라우드 COS, 치니우 클라우드 KODO 또는 알리 클라우드 OSS에 업로드되도록 합니다.

## 사전 조건

1. `com.gameframex.unity.builder` 패키지가 설치되어 있어야 합니다.
2. 프로젝트에 최소 하나의 객체 스토리지 하위 패키지와 해당 Editor 업로드 구현을 도입해야 합니다:
   - 텐센트 클라우드: `GameFrameX.ObjectStorage.Tencent.Editor`
   - 치니우 클라우드: `GameFrameX.ObjectStorage.QiNiu.Editor`
   - 알리 클라우드: `GameFrameX.ObjectStorage.ALiYun.Runtime`
3. `Assets/GameFrameX/GameFrameX.Runtime.Editor/Scripts/EditorSettings/GameFrameXSettings.asset`에서 해당 플랫폼의 활성화 스위치를 켭니다(`ENABLE_GAME_FRAME_X_OBJECT_STORAGE_*` 매크로로 제어).
4. 객체 스토리지 접근 자격 증명과 버킷 정보를 준비합니다: `Key`(SecretId/AK), `Secret`(SecretKey/SK), `BucketName`, `EndPoint`(리전 노드).

## 작업 단계

1. 명령줄을 통해 네 가지 객체 스토리지 매개변수를 빌더에 전달합니다:

| 매개변수 | 설명 |
|------|------|
| `-ObjectStorageKey` | 객체 스토리지 접근 Key |
| `-ObjectStorageSecret` | 객체 스토리지 접근 비밀 키 |
| `-ObjectStorageBucketName` | 객체 스토리지 버킷 이름 |
| `-ObjectStorageEndPoint` | 객체 스토리지 리전 노드 |

매개변수 정의는 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40) 참조:

```csharp
/// <summary>
/// 객체 스토리지의 Key
/// </summary>
public string ObjectStorageKey { get; set; } = string.Empty;

/// <summary>
/// 객체 스토리지의 비밀 키
/// </summary>
public string ObjectStorageSecret { get; set; } = string.Empty;

/// <summary>
/// 객체 스토리지 버킷의 이름
/// </summary>
public string ObjectStorageBucketName { get; set; } = string.Empty;

/// <summary>
/// 객체 스토리지 버킷의 리전 이름
/// </summary>
public string ObjectStorageEndPoint { get; set; } = string.Empty;
```

2. Unity에서 대상 클라우드 공급업체에 따라 해당 스크립트 매크로를 활성화합니다. Builder.cs는 `#if` 분기를 통해 업로드 관리자를 선택합니다:

```csharp
#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_QI_NIU
            ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<QiNiuYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT
            ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<TencentCloudObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif

#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE_A_LI_YUN
            ObjectStorageUploadManager = ObjectStorageUploadFactory.Create<ALiYunObjectStorageUploadManager>(_builderOptions.ObjectStorageKey, _builderOptions.ObjectStorageSecret, _builderOptions.ObjectStorageBucketName, _builderOptions.ObjectStorageEndPoint);
#endif
ObjectStorageUploadManager.SetSavePath($"builder/{PlayerSettings.productName}/{EditorUserBuildSettings.activeBuildTarget.ToString()}/{_builderOptions.JobName}/{Application.version}/{_builderOptions.BuildNumber}");
```

3. 업로드 스위치를 활성화하고 업로드할 콘텐츠를 선택합니다. 예를 들어 리소스 패키지와 로그만 업로드하는 경우:

```
-IsUploadLogFile -IsUploadAsset
```

업로드 로직 트리거 위치는 [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L62-L78) 참조.

## 일반적인 변형

### 텐센트 클라우드 COS

- 콘솔에서 COS 버킷을 생성하고 버킷 이름(`BucketName`)과 **소속 리전의 액세스 도메인**(`EndPoint`, 예: `cos.ap-shanghai.myqcloud.com`)을 기록합니다.
- 콘솔 → 액세스 관리(CAM) → API 키 관리에서 새로운 `SecretId`와 `SecretKey`를 생성하여 각각 `-ObjectStorageKey`, `-ObjectStorageSecret`에 입력합니다.
- 매크로 활성화: `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT`.

### 치니우 클라우드 KODO

- 객체 스토리지 공간을 생성하여 **스토리지 공간 이름**과 **액세스 도메인**(화동 `upload.qiniup.com`, 화남 `upload-z2.qiniup.com` 등, `-ObjectStorageEndPoint`에 입력)을 얻습니다.
- 개인 센터 → 키 관리에서 `AK` / `SK`를 가져와 각각 Key / Secret으로 사용합니다.
- 매크로 활성화: `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_QI_NIU`.

### 알리 클라우드 OSS

- OSS Bucket을 생성하고 `BucketName`과 **외부 네트워크 액세스 EndPoint**(예: `oss-cn-hangzhou.aliyuncs.com`)를 기록합니다.
- RAM 액세스 제어 → 사용자 → AccessKey 생성에서 `AccessKeyId`와 `AccessKeySecret`를 얻어 각각 Key / Secret에 입력합니다.
- 매크로 활성화: `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_A_LI_YUN`.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 빌드 후 업로드 로그가 전혀 없고, `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`가 활성화되지 않았다고 표시됨 | 총 스위치 매크로가 활성화되지 않음 | `GameFrameXSettings.asset`에서 "객체 스토리지 활성화" 체크 |
| `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT` 등의 매크로가 정의되지 않았다고 보고됨 | 하위 패키지가 설치되지 않았거나 매크로가 활성화되지 않음 | 해당 Editor 하위 패키지가 `Packages/manifest.json`에 있는지 확인하고 해당 매크로를 활성화 |
| 업로드가 403 / SignatureDoesNotMatch 반환 | Key/Secret 순서가 바뀌었거나 자격 증명이 버킷과 일치하지 않음 | Key에 액세스 키 ID(AK/SecretId)를, Secret에 키(SK/SecretKey)를 입력합니다. 버킷이 있는 계정과 일치하는지 확인 |
| 업로드가 `NoSuchBucket` 반환 | 버킷 이름 또는 EndPoint 리전이 일치하지 않음 | 버킷 이름은 대소문자를 엄격히 구분합니다. EndPoint는 버킷이 있는 리전의 액세스 도메인을 사용해야 합니다 |
| 업로드 경로를 찾을 수 없음/이전 패키지를 덮어씀 | `JobName`과 `BuildNumber`가 설정되지 않음 | `SetSavePath`에서 `{JobName}/{Application.version}/{BuildNumber}` 세 부분으로 경로를 조합합니다. 하나라도 빠지면 기본값으로 돌아갑니다 |

## 배경(선택 사항)

Builder는 정적 생성자에서 네 가지 명령줄 매개변수를 읽고 활성화된 매크로 분기에 따라 해당 공급업체의 업로드 관리자 인스턴스를 생성하며, `IObjectStorageUploadManager`를 통해 `UploadFile` 인터페이스를 통합적으로 노출합니다. 따라서 클라우드 공급업체를 전환하려면 활성화 매크로와 명령줄 매개변수만 교체하면 됩니다. 저장 경로 템플릿은 `PlayerSettings.productName` / `activeBuildTarget` / `JobName` / `Application.version` / `BuildNumber`의 조합으로 구성되어 버전별로 과거 빌드 산출물을 분리하는 데 용이합니다. 전체 진입점은 [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L32-L48)를 참조하세요.
