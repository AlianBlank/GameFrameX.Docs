# TCP/WebSocket/KCP/HTTP クライアント接入方法

`GameFrameX.NetWork` の `INetWorkChannel` と `NetWorkSenderFactory` を利用することで、業務側では TCP、WebSocket、KCP、HTTP の各クライアントメッセージを透過的に送受信でき、底层プロトコルの差異を気にする必要はありません。

## 前提条件

- `GameFrameX.NetWork.Abstractions`、`GameFrameX.NetWork` パッケージがインストールされていること。KCP クライアントは `GameFrameX.NetWork.Kcp` を、HTTP クライアントは `GameFrameX.NetWork.HTTP` を追加で参照する必要があります。
- `GameFrameX.SuperSocket.Server.Abstractions.Session.IGameAppSession`(SuperSocket セッション) にすでに接入されていること。
- 対応するプロトコルのリスナー(TCP / WebSocket / KCP / HTTP) が設定済みであること。

## 操作手順

### 1. ネットワークチャネルを取得する

業務プロセッサ内でセッションから `INetWorkChannel` を取得し、その後の送受信はすべてチャネル経由で行います。プロトコルには直接触れません。

```csharp
using GameFrameX.NetWork;
using GameFrameX.NetWork.Abstractions;
using GameFrameX.SuperSocket.Server.Abstractions.Session;

// SuperSocket メッセージ処理コンテキスト内
IGameAppSession session = /* 接続イベントまたはメッセージ処理から取得 */;
INetWorkChannel channel = NetWorkSenderFactory.Create(session);
// NetWorkSenderFactory は session の実際の型に応じて WebSocket または TCP 送信側を自動的に選択します
```

Source: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L12-L17)

### 2. クライアントへメッセージを送信する

`INetworkMessage` を構築し、`WriteAsync` を呼び出して非同期送信します。`errorCode` のデフォルトは `0` で、業務側はエラー発生時にエラーコードを返送できます。

```csharp
using GameFrameX.NetWork.Abstractions;

await channel.WriteAsync(message, errorCode: 0);
```

`INetWorkChannel.WriteAsync` はネットワークチャネルが既に閉じている場合例外をスローするため、呼び出し前に `IsClosed()` でチェックしてください。

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L96-L108)

### 3. 接続を閉じる

```csharp
channel.Close();
```

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L110-L116)

### 4. チャネル上でカスタムデータを保存・取得する

`SetData` / `GetData<T>` / `RemoveData` / `ClearData` は、チャネルのライフサイクル内でユーザ状態データ(プレイヤオブジェクトやログイン状態など)をアタッチするために使用します。追加の Map は不要です。

```csharp
channel.SetData("playerId", 10001);
var pid = channel.GetData<long>("playerId");
channel.RemoveData("playerId");
// channel.ClearData(); // 切断時またはリセットが必要な場合
```

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L118-L155)

## よくあるバリエーション

### TCP / WebSocket

`NetWorkSenderFactory.BuildProviders()` には `WebSocketNetWorkSenderProvider` と `SessionNetWorkSenderProvider` が組み込まれており、それぞれ WebSocket と TCP(および `IGameAppSession` を共有する KCP などのプロトコル) のセッションタイプをカバーします。追加登録は不要で、`session.GetType()` で自動的にマッチングされます。

Source: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L19-L36)

### KCP

KCP セッションも `IGameAppSession` を実装しているため、`SessionNetWorkSenderProvider` の送信パスを再利用します。カスタムコーデックが必要な場合は、KCP リスナー側で接入してください。

### HTTP

HTTP は `GameFrameX.NetWork.HTTP` の独立チャネルを通り、リクエスト処理完了後に `Close()` を呼び出します。`GetData`/`SetData` はリクエスト処理チェーン内でコンテキストを受け渡すために使用できます。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| `WriteAsync` が例外をスローする | チャネルが既に閉じている(`IsClosed()` が `true` を返す) | 送信前に `if (!channel.IsClosed())` でガードする |
| `GetData<T>` が例外をスローする | Key が存在しない、または型が一致しない | 書き込み時に型を統一する。読み込み前に `ContainsKey` 風の判定を行うか、例外をキャッチする |
| WebSocket メッセージ送信失敗 | `NetWorkSenderFactory` を通さず、TCP 送信側を直接使用した | 常に `NetWorkSenderFactory.Create(session)` 経由でチャネルを取得する。ファクトリがセッションタイプに応じて振り分ける |
| KCP パケットは到達しているが業務側で受信できない | KCP リスナー側で `INetWorkChannel` パイプラインに接入していない | KCP セッションが `IGameAppSession` をラップしていること、およびファクトリでチャネルが作成されていることを確認する |

## 背景(オプション)

`NetWorkSenderFactory` は `SenderProviders` 辞書によってプロトコルセッションタイプを `INetWorkSenderProvider` にマッピングします。`ResolveProvider` はまず精确一致を試み、次に代入可能な関係にフォールバックするため、新しいプロトコルを追加するには対応する `Provider` + `Sender` 実装を追加して登録するだけで済み、業務側の `WriteAsync` 呼び出しに変更は不要です。`INetWorkChannel` はバイト/パケット数、ハートビート時刻、カスタムデータ、閉じ処理などの機能をすべて同一インターフェースに集約しているため、業務コードはプロトコルに依存しない単一のチャネルビューだけを見ればよくなります。
