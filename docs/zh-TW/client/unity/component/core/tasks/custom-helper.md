# 接入自訂 Helper 替換預設實作

透過 GameFrameX 提供的 `Helper.CreateHelper<T>` 入口,你可以在框架啟動時用自訂 Helper 替換預設實作(如日誌、壓縮、版本、JSON、文字輔助器等),用於對接專案內部的工具鏈或第三方 SDK。

## 前置條件

- 已按快速開始文件初始化 `GameFrameX` 框架,並能在 `Awake/Start` 中拿到 `GameFrameXComponent`。
- 自訂 Helper 類別已實作對應的介面(例如 `GameFrameworkLog.ILogHelper`、`Utility.Compression.ICompressionHelper`、`Utility.Json.IJsonHelper`、`Utility.Text.ITextHelper`、`GameVersion.IVersionHelper`),且在 Unity 組件能被反射找到。
- 自訂 Helper 為 `MonoBehaviour` 衍生類別(框架透過 `GameObject.AddComponent` 建立)。

## 操作步驟

### 1. 實作自訂 Helper

新增一個類別,實作框架內建介面。以下以替換預設日誌輔助器為例:

```csharp
using UnityEngine;
using GameFrameX;

namespace GameFrameX.Runtime
{
    [UnityEngine.Scripting.Preserve]
    public class MyLogHelper : GameFrameworkLog.ILogHelper
    {
        public void Log(GameFrameworkLogLevel level, object message)
        {
            // 接入專案自有日誌 SDK,例如上傳到伺服器或寫入本地檔案
            MyLogger.Write(level, message);
        }
    }
}
```

Source: [Runtime/Helper/DefaultLogHelper.cs](/Runtime/Helper/DefaultLogHelper.cs#L42-L83)

### 2. 透過字串型別名稱註冊

把自訂 Helper 的完整類別名稱(含命名空間)傳給 `Helper.CreateHelper<T>`。框架會用反射查找該型別並 `AddComponent` 到一個新 `GameObject` 上:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: "GameFrameX.Runtime.MyLogHelper",
    customHelper: null);
```

字串方式的好處是不需要在場景裡預先放好元件,適合純程式碼工程。

### 3. 透過預製元件註冊

把自訂 Helper 做成 `MonoBehaviour` 腳本掛到一個預製體上,然後直接傳給 `customHelper` 參數。框架會判斷元件是否已在場景中,決定直接複用還是 `Instantiate` 複製:

```csharp
// myLogHelperPrefab 是預製體上的 MyLogHelper 元件引用
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: string.Empty,
    customHelper: myLogHelperPrefab);
```

`helperTypeName` 留空、`customHelper` 非空時,優先使用 `customHelper`;反之則按字串查型別;兩者都為空時框架會輸出警告並回傳 `null`。

### 4. 在框架入口掛接

在 `GameFrameXComponent.Awake` 或初始化流程裡,把建立好的 Helper 注入到對應子系統。以 `Log` 模組為例:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    "GameFrameX.Runtime.MyLogHelper", null);
GameFrameworkLog.SetLogHelper(logHelper);
```

原始碼註冊入口參見 [Runtime/Helper/Helper.cs](/Runtime/Helper/Helper.cs#L57-L106)。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| 警告 `Can not find helper type 'XXX'.` | 字串類別名稱拼錯、命名空間缺失,或組件未啟用反射 | 用 `Type.FullName` 核對;確認類別所在組件未被 IL2CPP 裁剪 |
| 警告 `Type 'A' is not assignable from 'B'.` | 自訂類別沒實作目標介面 | 讓自訂類別 `implements` 對應的 `IXxxHelper` |
| 警告 `You must set custom helper with '...' type first.` | `helperTypeName` 留空且 `customHelper` 也為 `null` | 二選一填一個,或先 `AddComponent` 再傳入 |
| 自訂邏輯沒生效 | 沒有呼叫對應子系統的 `SetXxxHelper` 注入 | 在框架初始化早期完成 `CreateHelper` + `SetHelper` 注入 |

## 背景(選用)

`Helper.CreateHelper<T>` 內部透過 `Utility.Assembly.GetType` 按字串查找型別,找到後用 `new GameObject().AddComponent` 實例化;當傳入 `customHelper` 時,按元件是否已在場景決定複用或 `Instantiate`。兩個參數互為備援,讓配置驅動的工程和無配置工程都能接入。
