# 작동 원리: UI 라이프사이클과 로딩 큐

이 페이지에서는 `UIManager`를 호출하여 FairyGUI UI를 열면 프레임워크 내부에서 순차적으로 일어나는 일을 설명합니다: 싱글톤 중복 제거 → 인스턴스 풀 재사용 → 비동기 로딩 큐 → 라이프사이클 콜백 → 그룹 새로고침, 그리고 닫을 때의 회수 로직. 이 흐름을 이해하면 "같은 UI를 반복해서 열어도 로딩이 두 번 일어나지 않는 이유", "닫은 후에도 UI가 즉시 파괴되지 않는 이유" 등의 현상을 설명할 수 있습니다.

## UI를 열 때의 라이프사이클 순서

`InternalOpenUIForm`은 모든 UI(신규 로딩이든 풀 재사용이든)가 실제로 "탄생"하는 곳이며, 콜백은 다음 순서대로 실행됩니다. 모두 실제 소스 코드에서 가져온 내용입니다:

1. `m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData)`가 `IUIForm`을 생성합니다; `null`을 반환하면 `GameFrameworkException("Can not create UI form in UI form helper.")`을 throw합니다.
2. `uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen)`로 초기화를 완료합니다; 이때 `OnInitAction`은 초기화 콜백에서 `FUI` 타입 UI에 대해 `fui.SetGObject(uiFormInstance as GObject)`를 호출하여 GObject를 바인딩합니다.
3. UI를 UI 그룹에 추가합니다: `uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm)`이 거짓이면 `uiGroup.AddUIForm(uiForm)`을 호출합니다.
4. `uiForm.OnOpen(userData)` —— 비즈니스 측에서 열리는 순간 받게 되는 콜백입니다.
5. `uiForm.BindEvent()`, `uiForm.LoadData()`, `uiForm.UpdateLocalization()`이 순서대로 실행됩니다.
6. `uiForm.EnableShowAnimation`이 참이면 `uiForm.Show(m_UIFormShowHandler, null)`이 표시 애니메이션을 재생합니다(아래의 FUI `Show` 구현 참조).
7. `uiGroup.Refresh()`가 그룹의 깊이와 일시정지 상태를 새로고침합니다.
8. `OpenUIFormSuccessEventArgs` 성공 이벤트를 트리거합니다; 어느 단계에서든 예외가 발생하면 `OpenUIFormFailureEventArgs`를 트리거한 후 다시 throw합니다.

```csharp
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, OnInitAction, pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);

void OnInitAction(IUIForm obj)
{
    if (obj is FUI fui)
    {
        fui.SetGObject(uiFormInstance as GObject);
    }
}

if (!uiGroup.InternalHasInstanceUIForm(uiFormAssetName, uiForm))
{
    uiGroup.AddUIForm(uiForm);
}

uiForm.OnOpen(userData);
uiForm.BindEvent();
uiForm.LoadData();
uiForm.UpdateLocalization();
if (uiForm.EnableShowAnimation)
{
    uiForm.Show(m_UIFormShowHandler, null);
}

uiGroup.Refresh();
```

## 로딩 큐와 중복 제거

`InnerOpenUIFormAsync`는 실제 로딩을 시작하기 전에 3단계 중복 제거를 수행하여 동일한 UI가 동시에 로딩되는 것을 방지합니다:

1. **싱글톤 모드에서 이미 열린 UI에 적중**: `UseSingletonOpenMode(uiFormType)`이 참이면 먼저 `GetUIForm(uiFormAssetName)`으로 이미 열린 인스턴스를 찾고, 적중하면 `RefocusUIForm(openedUIForm, userData)`을 수행한 뒤 바로 반환하여 더 이상 로딩하지 않습니다.
2. **로딩 중 큐 적중**: `m_LoadingUIForms`(용량 64의 `List<UIFormLoadingObject>`)를 순회하여 에셋 경로, 에셋 이름, 타입 세 가지가 모두 일치하면 `await value.Task`로 동일한 로딩 결과를 재사용합니다.
3. **인스턴스 풀 적중**: `m_InstancePool.Spawn(uiFormAssetName)`으로 재사용 가능한 인스턴스를 꺼내오며, 성공하면 새 `++m_Serial` 시리얼 번호를 할당한 후 바로 `InternalOpenUIForm`으로 진행합니다(`isNewInstance: false`).

3단계 모두 적중하지 않은 경우에만 `InnerLoadUIFormAsync`를 호출하여 실제 에셋 로딩을 시작하고, 결과를 `UIFormLoadingObject`로 래핑하여 `m_LoadingUIForms`에 추가합니다; `await`가 끝난 후 `finally`에서 제거하고 `ReferencePool.Release`를 호출하여 큐가 누수되지 않도록 보장합니다.

```csharp
foreach (var value in m_LoadingUIForms)
{
    if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
    {
        return await value.Task;
    }
}
```

## 에셋 로딩 경로: Resources와 Bundles

`InnerLoadUIFormAsync`는 로딩할 때마다 새로운 시리얼 번호를 할당하고 `m_UIFormsBeingLoaded`에 등록한 후, 경로 특성에 따라 분기합니다:

- **패키지 이름 추론**: `uiFormAssetPath`에서 마지막 `/` 이후의 부분을 `packageName`으로 사용합니다; 경로에 `/`가 없으면 전체 경로가 곧 패키지 이름입니다.
- **이미 로딩된 패키지**: `FairyGuiPackage.Has(packageName)`이 참이면 바로 `LoadAssetSuccessCallback`으로 진행하여 UI를 생성하며, 패키지를 다시 로딩하지 않습니다.
- **Resources 디렉터리**: `assetPath`에 `Utility.Asset.Path.BundlesDirectoryName`가 포함되어 있지 않으면, 패키지가 로딩되지 않았을 때 `FairyGuiPackage.AddPackageSync(assetPath)`로 동기 로딩한 후 UI를 생성합니다.
- **Bundle 디렉터리**: 패키지 이름과 에셋 이름이 일치하면 `await FairyGuiPackage.AddPackageAsync(assetPath)`; 일치하지 않으면 `PathHelper.Combine(uiFormAssetPath, packageName)`으로 경로를 다시 조합하여 비동기 로딩한 후, `경로 + "_fui"` 에셋(`m_AssetManager.LoadAssetAsync<UnityEngine.Object>`)을 로딩하고, 성공했을 때만 `openUIFormInfo.SetAssetHandle(assetHandle)`을 호출하고 UI를 생성합니다.

```csharp
newAssetPackagePath += "_fui";
// 패키지에서 로드
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

### 로딩 성공 / 실패 콜백

| 콜백 | 동작 |
|------|------|
| `LoadAssetSuccessCallback` | `m_UIFormsToReleaseOnLoad`를 확인합니다(로딩 도중 취소된 요청은 에셋을 바로 해제); 그렇지 않으면 `m_UIFormHelper.InstantiateUIForm`으로 인스턴스화하고 `m_InstancePool.Register`로 인스턴스 풀에 등록한 뒤 `InternalOpenUIForm`으로 진행합니다(`isNewInstance: true`) |
| `LoadAssetFailureCallback` | 오류 메시지 `Utility.Text.Format("Load UI form failure, asset name '{0}', error message '{1}'.", ...)`을 조합하고 `OpenUIFormFailureEventArgs`를 트리거합니다; 실패 핸들러가 없으면 `throw new GameFrameworkException(appendErrorMessage)`를 직접 실행합니다 |

두 곳 모두 유효하지 않은 `OpenUIFormInfo`에 대해 `GameFrameworkException("Open UI form info is invalid.")`을 throw합니다.

## 표시 / 숨기기 애니메이션

`FUI`(FairyGUI UI 기반 클래스, `UIForm`에서 상속)는 가시성 관련 작업을 연결된 `GObject`에 전달합니다:

- `Show(handler, complete)`: handler가 있으면 `handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete)`를 호출하고, 그렇지 않으면 `complete?.Invoke()`를 바로 호출합니다.
- `Hide(handler, complete)`: 대칭적으로 `EnableHideAnimation`과 `HideAnimationName`을 사용합니다.
- `Visible`: `GObject.visible`을 읽습니다; `GObject == null`이면 항상 `false`입니다. `InternalSetVisible`은 `GObject.visible`을 수정한 후 `OnVisibleChanged` 콜백과 `UIFormVisibleChangedEventArgs` 이벤트를 차례로 트리거합니다.
- `MakeFullScreen()`: `GObject?.asCom?.MakeFullScreen()`.

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

## 닫기와 인스턴스 회수

`RecycleUIForm(uiForm, isDispose)`는 닫은 후의 회수를 담당하며, 단계는 다음과 같습니다:

1. `uiForm.OnRecycle()`이 먼저 비즈니스 회수 콜백을 트리거합니다.
2. `uiForm.Handle as GameObject`를 가져옵니다; null이면 바로 반환합니다(회수할 표시 객체가 없음).
3. GameObject에서 `DisplayObjectInfo` 컴포넌트를 가져온 다음 `displayObject.gOwner as GComponent`를 가져옵니다; 둘 중 하나라도 null이면 바로 반환합니다.
4. `m_InstancePool.Unspawn(component)`이 인스턴스를 인스턴스 풀에 돌려보내 재사용을 대기하게 합니다; `isDispose == true`이면 추가로 `m_InstancePool.ReleaseObject(component)`를 호출하여 완전히 파괴합니다.

즉, 기본 닫기는 단순히 "풀에 반환"하는 것일 뿐이며, 다음 번 `m_InstancePool.Spawn`에서 적중하면 로딩 없이 재사용할 수 있습니다; 인스턴스 풀의 회수 간격 하한은 `10`입니다(`m_RecycleInterval < 10`이면 `10`으로 강제 변경됨).

```csharp
m_InstancePool.Unspawn(component);
if (isDispose)
{
    m_InstancePool.ReleaseObject(component);
}
```

## 자주 발생하는 문제 해결

| 현상 | 원인 | 처리 |
|------|------|------|
| 같은 UI를 반복해서 열었을 때 첫 번째만 로딩 발생 | 싱글톤 모드에서 `GetUIForm` 또는 `m_LoadingUIForms` 중복 제거에 적중 | 예상된 동작입니다; 새 인스턴스가 필요하면 싱글톤 열기 모드를 비활성화하세요 |
| UI를 열 때 `Can not create UI form in UI form helper.` 예외 발생 | `m_UIFormHelper.CreateUIForm`이 `null` 반환 | `uiFormType`과 등록된 `FairyGUIFormHelper`가 해당 타입을 생성할 수 있는지 확인 |
| `Load UI form failure, asset name '...', error message '...'` 예외 발생 | `_fui` 에셋 또는 UI 패키지 로딩 실패 및 실패 핸들러 미등록 | 패키지 이름 추론 결과와 `uiFormAssetPath`를 대조하고, `경로_fui` 에셋이 존재하는지 확인 |
| `Open UI form info is invalid.` 예외 발생 | 성공/실패 콜백이 받은 `OpenUIFormInfo`가 `null`임 | 프레임워크 내부 데이터 이상이므로, 외부에서 콜백을 잘못 사용했는지 확인 |
| UI를 닫은 후에도 메모리가 줄어들지 않음 | `RecycleUIForm`은 기본적으로 `Unspawn`으로만 풀에 반환 | 완전히 파괴해야 할 때는 `isDispose`가 있는 닫기 경로를 사용 |
