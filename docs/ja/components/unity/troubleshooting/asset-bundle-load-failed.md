# AssetBundle のリソース読み込みが失敗した場合の対処法

エディタまたは実行時に `AssetBundle.LoadFromFile` / `LoadFromMemoryAsync` / `LoadAssetAsync` が `null` を返したり、例外をスローしたり、間違ったリソースを読み込んだりした場合、問題のほとんどは「マニフェスト設定」「パスとプラットフォーム」「リソースパッケージング」の 3 つに集中しています。本ページでは、症状ごとの早見表と修復手順を説明します。

## クイック診断

| 症状 | 原因 | 修復 |
|------|------|------|
| `AssetBundle` の読み込みが `null` を返す、または `IOException` をスローする | 実行時に `.bundle` / `.ab` ファイルが見つからない、パスがリリースプラットフォームと一致しない | [パスとプラットフォームの不一致](#修復手順) を参照 |
| リソースは読み込めるが、`LoadAsset<T>` で取得したものがデフォルトリソースになる / テクスチャが紫色になる | そのリソースがどの Bundle にも収集されていない、または参照が失われている | [リソースが収集されていない](#修复步骤) を参照 |
| パッケージ化後のマニフェストと実行時が一致せず、一部リソースが 404 になる | `AssetBundleCollectorConfig.xml` が保存されていない、または最新マニフェストが生成されていない | [マニフェストとビルド設定](#修复步骤) を参照 |
| Android 実機で WebRequest の読み込みが失敗する | `UnityWebRequestAssetBundle` モジュールが足りない | [依存モジュールの不足](#修复步骤) を参照 |
| エディタでは正常に読み込めるが、パッケージ化後の初回起動に失敗する | `StreamingAssets` ディレクトリがパッケージに含まれていない / コピーされていない | [StreamingAssets がリリースされていない](#修复步骤) を参照 |

## 修復手順

### パスとプラットフォームの不一致

1. `Application.streamingAssetsPath`(読み取り専用のパッケージ内)または `Application.persistentDataPath`(書き込み可能なダウンロードディレクトリ)配下の `.bundle` ファイルが存在し、ファイル名が実行時と一致していることを確認します。
2. ファイル名は `Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml` の `PackRule` によって決定されるため、読み込み時には同じルールで生成された名前を使用し、プラットフォームのサフィックス(例: `_android`、`_ios`、`_windows`)を付ける必要があります。

Source: [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L1-L40)

3. `AssetBundle.LoadFromFile(path)` を呼び出す前に `File.Exists(path)` で検証し、存在しない場合は `path` と現在の `Application.platform` を記録します。

### リソースが収集されていない

1. `Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml` を開き、対象リソースが配置されているディレクトリが `CollectPath` に追加されており、`Filter` ルールで除外されていないことを確認します。
2. エディタメニューから Bundle ビルドを 1 回実行し、`Library/com.unity.addressables` またはカスタム出力ディレクトリで、リソースが対応する `.bundle` に含まれていることを確認します。
3. 再度読み込みます。

### マニフェストとビルド設定

1. `AssetBundleCollectorConfig.xml` を変更したら、ビルド前に必ず `Save` を実行します。そうしないと実行時に古いマニフェストが取得されます。
2. `AssetBundleCollectorSetting.asset` は ScriptableObject であり、フィールド変更には `Apply` のクリックが必要です。

Source: [AssetBundleCollectorSetting.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorSetting.asset)

3. ビルド成果物(`.bundle`、マニフェストファイル、バージョンファイル)全体を対象のリリースディレクトリにコピーし、単一ファイルのみを上書きしないようにします。

### 依存モジュールの不足

`Packages/manifest.json` で以下のモジュールが存在することを確認します:

```json
"com.unity.modules.assetbundle": "1.0.0",
"com.unity.modules.unitywebrequest": "1.0.0",
"com.unity.modules.unitywebrequestassetbundle": "1.0.0",
"com.unity.modules.unitywebrequestaudio": "1.0.0"
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L47-L60)

`unitywebrequestassetbundle` が不足していると、Android/iOS で `UnityWebRequestAssetBundle.GetAssetBundle()` が `null` を返します。

### StreamingAssets がリリースされていない

1. リソースを `Assets/StreamingAssets/` に配置すると、Unity はそのままパッケージに含めます。`Assets/AssetBundleSetting/` 以外のディレクトリに配置しても自動的にはパッケージ化されません。
2. `Project Settings > Player > Other Settings` で、対象プラットフォームの `StreamingAssets` にターゲットの `.bundle` が含まれていることを確認します。

## 検証

- エディタの `Play Mode` で `LoadFromFile` により `assetBundle != null` まで読み込める。
- 実機 / エミュレータの初回起動後、ログの `Loaded bundle:` の後にリソース名が表示され、`ArgumentException` が出ない。
- リソース参照カウント / `LoadAsset<T>` がデフォルト以外の値を返し、`Instantiate` が成功する。
