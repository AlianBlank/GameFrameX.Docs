# 빌드 시 코드 스트리핑 처리

Player Settings에서 **Managed Stripping Level**(특히 High/Medium)을 활성화했거나 IL2CPP로 빌드한 후 `NetworkComponent`나 네트워크 이벤트 클래스가 사라지거나, `CreateNetworkChannel`에서 `MissingMethodException` / `TypeLoadException`과 같은 문제가 발생한다면, 이는 보통 Unity의 관리 코드 스트리핑이 정적으로 참조되지 않는 타입/메서드를 잘라냈기 때문입니다. 본 패키지는 핵심 타입에 이미 `[UnityEngine.Scripting.Preserve]`를 명시해 두었으므로 대부분의 경우 추가 처리가 필요 없습니다. 잘려나가는 것은 대개 직접 작성한 프로젝트에서 리플렉션/문자열로 등록한 부분이며, 아래 단계에 따라 보호를 보완하면 됩니다.

## 사전 조건

- Unity 버전이 2019.4 이상(본 패키지의 `package.json`에 선언된 최소 버전)이어야 합니다.
- `com.gameframex.unity.network`(현재 버전 2.6.10)과 그 의존성인 `com.gameframex.unity`, `com.gameframex.unity.event`, `com.gameframex.unity.litjson`이 설치되어 있어야 합니다.
- 빌드 대상 플랫폼이 IL2CPP를 사용하거나 Player Settings에서 Managed Stripping Level(Low/Medium/High)이 활성화되어 있어야 합니다.

## 작업 단계

1. 먼저 패키지에 내장된 보호가 이미 적용되어 있는지 확인합니다. 본 패키지는 진입점 컴포넌트와 공개 API에 하나하나 `[UnityEngine.Scripting.Preserve]`를 명시했으며, 예를 들어 `NetworkComponent` 클래스 자체는 다음과 같습니다:

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Network")]
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkComponent : GameFrameworkComponent
   ```
   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L42-L45)

   공개 메서드(예: `CreateNetworkChannel`, `GetNetworkChannel`)에도 마찬가지로 `[Preserve]`가 붙어 있습니다:

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   ```
   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L176)

   네트워크 이벤트 인자 클래스에도 모두 `[Preserve]`가 붙어 있습니다(이 클래스들은 이벤트 시스템을 통해 타입 단위로 디스패치되는 경우가 많아 잘려나가기 쉽습니다):

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkConnectedEventArgs : GameEventArgs
   ```
   Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L40-L41)

   동일하게 처리된 것으로는 `NetworkClosedEventArgs`, `NetworkErrorEventArgs`, `NetworkMissHeartBeatEventArgs`, 그리고 `NetworkManager.HeartBeatState`의 매개변수 없는 생성자가 있습니다(프레임워크 내부에서 리플렉션으로 상태 객체를 생성합니다):
   Source: [NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L43-L45)

2. **Edit → Project Settings → Player → Other Settings → Optimization → Managed Stripping Level**을 열어 현재 스트리핑 레벨을 확인합니다. 간헐적으로 일부 타입만 사라지는 현상이라면, 먼저 레벨을 **Low(또는 Minimal)**로 낮춰 빌드해 검증함으로써 문제가 실제로 스트리핑에서 비롯된 것인지 확인합니다.

3. **직접 작성한 프로젝트**에서 잘려나간 타입을 점검합니다. 흔히 잘려나가면서도 본 패키지가 대신 보호해 줄 수 없는 것들:
   - 직접 구현한 `INetworkChannelHelper` 파생 클래스(송신/수신 패킷의 헤더 및 바디 핸들러);
   - `NetworkComponent`를 통해 등록했지만 문자열/리플렉션으로만 참조되는 메시지 핸들러;
   - 직렬화용 데이터 모델(예: LitJSON 관련 DTO).

4. 위와 같은 자체 타입에는 클래스와 공개 멤버에 `[UnityEngine.Scripting.Preserve]`를 추가하는 것을 우선으로 합니다(패키지 내부 방식과 동일):

   ```csharp
   // 사용자 프로젝트에서의 작성 예: 특성 사용법은 패키지 내 NetworkComponent와 동일
   [UnityEngine.Scripting.Preserve]
   public sealed class MyNetworkChannelHelper : INetworkChannelHelper
   {
       ...
   }
   ```

5. 잘려나간 타입이 많아 하나씩 특성을 추가하는 것이 비현실적이라면, 프로젝트의 `Assets/` 아래에 `link.xml`을 새로 만들어 어셈블리 단위로 전체를 보존합니다(Unity 공식 메커니즘이며, **본 리포지토리에는 link.xml이 포함되어 있지 않으므로** 사용하는 쪽 프로젝트에서 직접 생성해야 합니다):

   ```xml
   <linker>
     <!-- 전체 네트워크 어셈블리 보존 -->
     <assembly fullname="GameFrameX.Network.Runtime" preserve="all"/>
     <!-- 자체 비즈니스/프로토콜 어셈블리 보존 -->
     <assembly fullname="YourAssemblyName" preserve="all"/>
   </linker>
   ```

6. 다시 빌드한 뒤 빌드 로그에 `MissingMethodException`/`TypeLoadException`이 없는지 확인하고, 아래 "검증" 섹션에 따라 실기기 연결 테스트를 한 번 수행합니다.

## 검증

- 빌드 후 실행 시, 씬에 추가되어 있는 `NetworkComponent`(메뉴 경로 GameFrameX/Network)가 정상적으로 생성되는지 확인;
- `CreateNetworkChannel` 호출로 반환된 채널이 연결을 완료하고, `NetworkConnectedEventArgs` 이벤트를 받을 수 있는지 확인;
- 하트비트 로직이 정상 동작하는지(`HeartBeatState`가 잘려나가지 않았음을 의미) 확인하고, 네트워크가 끊어졌을 때 `NetworkMissHeartBeatEventArgs`/`NetworkErrorEventArgs`를 받을 수 있는지 확인.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 빌드 후 `TypeLoadException`/`MissingMethodException` 발생, 에디터에서는 정상 | Managed Stripping이 리플렉션으로만 참조되는 타입을 잘라냄 | Managed Stripping Level을 낮추거나 해당 타입에 `[UnityEngine.Scripting.Preserve]` 추가 |
| 하트비트 상태 객체 생성 실패 | `HeartBeatState`의 매개변수 없는 생성자가 잘림(프레임워크 내부에서 리플렉션으로 생성) | 패키지에는 이미 `[Preserve]`가 추가되어 있음. 이 파일을 fork/수정한 경우 해당 특성이 유지되도록 주의 |
| `NetworkConnectedEventArgs` 등 네트워크 이벤트를 받지 못함 | 이벤트 인자 클래스가 잘려 이벤트 시스템 역직렬화 실패 | 패키지에는 이미 `[Preserve]`가 추가되어 있음. fork로 덮어씌워졌거나 자체 EventArgs에 누락되지 않았는지 확인 |
| 자체 `INetworkChannelHelper` 파생 클래스의 메서드가 사라짐 | 사용자 프로젝트의 타입이 정적으로 참조되지 않음 | Helper 클래스에 `[Preserve]`를 추가하거나 link.xml 작성 |
| link.xml을 추가했는데도 잘림 | 파일이 `Assets/` 안에 없거나 XML 형식 오류 | 경로와 `assembly fullname`의 철자 확인(asmdef의 어셈블리 이름 참조) |

## 배경

Unity는 IL2CPP/High Stripping 빌드 시 관리 코드 진입점에서 정적으로 도달할 수 없는 타입과 멤버를 삭제합니다. 네트워크 프레임워크는 "인터페이스 + 리플렉션 + 이벤트 디스패치" 패턴을 많이 사용하는데, 예를 들어 `INetworkManager` 인터페이스로 구현체를 찾거나 이벤트 시스템을 통해 `NetworkConnectedEventArgs` 같은 인자 클래스를 타입 단위로 디스패치하는 방식이 그것입니다. 이러한 참조는 스트리퍼(stripper)에 보이지 않기 때문에, 본 패키지는 이러한 핵심 위치에 하나씩 `[UnityEngine.Scripting.Preserve]`를 명시했습니다(위 단계 1에서 인용한 소스 코드 참조). 이를 통해 패키지 내 모든 공개 타입은 커버되지만, 사용자 프로젝트 쪽에서 리플렉션으로 등록한 타입까지는 커버할 수 없으므로, 그런 타입은 동일한 방식으로 직접 보호해야 합니다.
