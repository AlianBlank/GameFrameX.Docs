# 如何透過 AssemblyResourceProvider 設定資源提供

`AssemblyResourceProvider` 是 GameFrameX 當地語系化框架的組件層級資源提供者，負責從內嵌於 .NET 組件的 `.resources` 檔案讀取當地語系化字串。首次存取時會進行延遲載入，完成後即可像內建資源一樣透過 `LocalizationService.GetString(...)` 取得字串。本頁面將說明如何在自訂組件中準備資源檔案、如何建構此提供者，以及如何將其整合至 `ResourceManager`。

## 前提條件

- 已安裝 `GameFrameX.Foundation.Localization` NuGet 套件。
- 目標專案為 .NET 組件，且 `.resx` 已作為 `EmbeddedResource` 內嵌至組件資訊清單(若未內嵌，`GetManifestResourceNames()` 將不會傳回這些項目，提供者也無法掃描到任何內容)。

## 操作步驟

1. 在專案內依照慣例路徑建立 `.resx` 檔案。預設慣例是放置於 `Localization/Messages/` 目錄之下，並依文化特性分割檔案名稱(具體命名規則詳見後述)。

   ```text
   {AssemblyName}/
   └── Localization/
       └── Messages/
           ├── Resources.resx         # 預設/英文的後援
           ├── Resources.zh-CN.resx   # 簡體中文
           └── Resources.en-US.resx   # 美式英文
   ```

   Source: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L216-L223)

2. 在 `.csproj` 中明確地將 `.resx` 標記為 `EmbeddedResource`,並視需要關閉預設的隱含內嵌，以避免依賴編譯器的自動行為：

   ```xml
   <PropertyGroup>
     <EnableDefaultEmbeddedResourceItems>false</EnableDefaultEmbeddedResourceItems>
   </PropertyGroup>

   <ItemGroup>
     <EmbeddedResource Include="Localization\Messages\*.resx" />
   </ItemGroup>
   ```

   Source: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L110-L118)

3. 依照命名規則為資源檔案命名，讓提供者能正確解析 `baseName`。框架可識別的資訊清單資源名稱規則如下(取自 `TryGetBaseName`):

   | 資訊清單資源名稱範例 | 解析後的 baseName | 用途 |
   |---|---|---|
   | `MyApp.Localization.Messages.Resources.resources` | `MyApp.Localization.Messages.Resources` | 預設文化特性 |
   | `MyApp.Localization.Messages.Resources.zh-CN.resources` | `MyApp.Localization.Messages.Resources` | 特定文化特性 `zh-CN` |
   | `MyApp.CustomPath.Resources.resources` | `MyApp.CustomPath.Resources` | 自訂路徑的預設文化特性 |
   | `MyApp.CustomPath.Resources.en.resources` | `MyApp.CustomPath.Resources` | 自訂路徑的中性文化特性 |
   | `MyApp.Category.resources` | `MyApp.Category` | 供回溯相容使用的 3 段式格式 |

   規則要點：必須以 `.resources` 結尾，且倒數第二個區段為 `Resources` 或有效的文化特性名稱(包含 `-`,或可由 `CultureInfo.GetCultureInfo` 識別)。區段數量至少需為 3 個，否則無法被識別。

   Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L282-L330)

4. 在程式碼中建構提供者並觸發載入。`AssemblyResourceProvider` 實作了 `IDisposable`,因此使用後應予以釋放。

   ```csharp
   using System.Reflection;
   using GameFrameX.Foundation.Localization.Providers;

   var assembly = Assembly.GetExecutingAssembly();
   using var provider = new AssemblyResourceProvider(assembly);

   // 選用:為避免首次存取時的延遲，可事先觸發延遲載入
   provider.EnsureLoaded();

   string message = provider.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L104-L138)

5. 將其整合至 `ResourceManager`,納入統一的解析鏈。`ResourceManager` 會依照「自訂 → 組件 → 預設」的順序搜尋。您可以讓框架自動偵測所有組件提供者，也可以在初始化後手動註冊指定的組件：

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // 方式 1:讓 ResourceManager 自動掃描目前已載入的組件
   LocalizationService.EnsureLoaded();

   // 方式 2:手動新增指定的組件
   LocalizationService.AddAssembly(Assembly.GetExecutingAssembly());

   var msg = LocalizationService.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   Source: [ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L370-L450)

## 常見變化

- **中性文化特性名稱**(例： `zh`、`fr`):當倒數第二個區段為中性文化特性名稱時，`IsCultureSegment` 會以 `CultureInfo.GetCultureInfo` 驗證其有效性，以避免將 `MyApp` 之類的類別名稱誤判為文化特性名稱。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L332-L360)

- **自訂路徑**(`Localization/Messages/` 以外)：只要符合 `{AssemblyName}.{任意のパス}.Resources[.{culture}].resources` 的區段結構即可被識別。例如 `MyApp.LangPack.Resources.zh-CN.resx` → baseName 為 `MyApp.LangPack.Resources`。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L256-L268)

- **找不到索引鍵時的後援**：當所有 `ResourceManager` 的 `GetString` 呼叫皆無相符項目時，會原樣傳回傳入的 `key` 字串，且不會擲回例外狀況。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L146-L178)

## 常見錯誤

- **資源未生效**：最常見的原因是 `.resx` 未以 `EmbeddedResource` 內嵌，或檔案名稱未遵循上述命名規則。請執行 `assembly.GetManifestResourceNames()`,確認資訊清單中是否包含預期的名稱。
- **同一組件內相同 baseName 重複**:`LoadResources` 會依 `BaseName` 進行去重，僅保留第一個相符的 `ResourceManager`,後續同名項目將被忽略。
- **`GetString` 擲回 `MissingManifestResourceException`**:程式碼會攔截此例外狀況並繼續搜尋其他 `ResourceManager`,因此通常不會向外傳播。如果記錄中顯示 `Failed to load resource '{key}'`,即表示所有比對皆失敗，將以 `key` 作為後援傳回。
- **組件掃描失敗**：整個掃描程序以 `try/catch` 包裝並寫入 `Debug.WriteLine`,不會擲回例外狀況。但為了避免重複嘗試，`_isInitialized` 會被標記為 `true`,因此您需要檢查偵錯輸出以找出根本原因。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L204-L279)

## 背景(選用)

`AssemblyResourceProvider` 實作了 `ILazyResourceProvider`、`ICultureResourceProvider` 與 `IDisposable`。建構時不會立即載入資源，而是在首次呼叫 `EnsureLoaded()` 或 `GetString()` 時掃描組件資訊清單，依 `baseName` 去重後建立 `ResourceManager`。`ResourceManager` 會維護一個以 `assembly.FullName` 為索引鍵的 `ConcurrentDictionary<string, AssemblyResourceProvider>`,對外提供「自訂提供者 > 組件提供者 > 預設提供者」的優先順序鏈。關於完整的資源解析鏈與統計介面，請參閱 [ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs)。
