# 启动同步参数校验异常怎么办

调用 `StartupRunner.Run(...)` 时,如果传入的参数不符合要求(例如 `options` 为 null、`GlobalInfoUrls` 为空数组等),会在进入异步状态机之前**同步**抛出 `ArgumentNullException` 或 `ArgumentException`,而不是返回失败结果。这类异常属于"开发期配置错误",需要在校验阶段就立刻暴露出来,避免污染后续的协程流程。

## 快速诊断

| 异常类型 | 典型消息原文 | 触发位置 | 修复方向 |
|----------|--------------|----------|----------|
| `ArgumentNullException` | (无消息,`ParamName`=`options`) | `StartupRunner.Run` 入口 | 传入有效的 `StartupOptions` 实例 |
| `ArgumentNullException` | (无消息,`ParamName`=`uiHandler`) | `StartupRunner.Run` 入口 | 实现并传入 `IStartupUIHandler` |
| `ArgumentNullException` | (无消息,`ParamName`=`hotfixLauncher`) | `StartupRunner.Run` 入口 | 实现并传入 `IHotfixLauncher` |
| `ArgumentException` | 消息含 `"GlobalInfoUrls"` | `StartupRunner.Run` 入口 | 在 `StartupOptions` 中填写至少一个全局信息接口 URL |
| `ArgumentNullException` | (无消息,`ParamName`=`urls`) | `UrlFailoverRunner` 构造 | 确保 URL 数组对象本身不为 null |
| `ArgumentException` | `"URL list must contain at least one URL."` | `UrlFailoverRunner` 构造 | URL 数组至少包含一个元素 |
| `ArgumentException` | `"Max attempts per URL must be greater than zero."` | `UrlFailoverRunner` 构造 | `maxAttemptsPerUrl` 改为 `>= 1` |
| `ArgumentException` | `"Retry delay must be zero or greater."` | `UrlFailoverRunner` 构造 | `retryDelayMs` 改为 `>= 0` |
| `ArgumentNullException` | (无消息,`ParamName`=`options`) | `StartupHttpParams.FromOptions` | 传入非 null 的 `StartupOptions` |

异常消息原文与参数名均直接来自源码,见 [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L34-L60) 与 [Runtime/Failover/UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L40)。

## 修复步骤

### 1. 修复 `ArgumentNullException`(options/uiHandler/hotfixLauncher)

`StartupRunner.Run` 在进入协程之前会同步检查三个入参是否为 null:

```csharp
public static UniTask<StartupResult> Run(
    StartupOptions options,
    IStartupUIHandler uiHandler,
    IHotfixLauncher hotfixLauncher)
```

对应实现([Runtime/Startup/StartupRunner.cs#L45-L60](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L45-L60)):

```csharp
if (options == null)        throw new ArgumentNullException(nameof(options));
if (uiHandler == null)      throw new ArgumentNullException(nameof(uiHandler));
if (hotfixLauncher == null) throw new ArgumentNullException(nameof(hotfixLauncher));
```

修复方法:在调用入口前逐项检查,或确保通过 Inspector / DI 容器注入了非空实例。例如:

```csharp
if (StartupOptions.Instance == null)
{
    Debug.LogError("StartupOptions 未配置");
    return;
}
if (uiHandler == null || hotfixLauncher == null)
{
    Debug.LogError("UI/Hotfix 启动器未注册");
    return;
}
await StartupRunner.Run(StartupOptions.Instance, uiHandler, hotfixLauncher);
```

### 2. 修复 `ArgumentException`(`GlobalInfoUrls` 为空)

在三个 null 检查通过后,`Run` 还会校验 `options.GlobalInfoUrls`(对应实现见 [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L37-L60))。该字段为 null 或长度为 0 时会同步抛出消息含 `"GlobalInfoUrls"` 的 `ArgumentException`。

修复方法:在 Unity 中通过 `Create > GameFrameX > Startup Options` 创建资产后,在 Inspector 的 `GlobalInfoUrls` 字段中至少填入一个可访问的全局信息接口地址(主备 URL 用数组元素区分)。

### 3. 修复 `UrlFailoverRunner` 抛出的校验异常

`UrlFailoverRunner` 构造时会对 URL 列表与重试参数做完整校验([Runtime/Failover/UrlFailoverRunner.cs#L19-L34](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L34)):

```csharp
if (urls == null)
    throw new ArgumentNullException(nameof(urls));
if (urls.Length == 0)
    throw new ArgumentException("URL list must contain at least one URL.", nameof(urls));
if (maxAttemptsPerUrl <= 0)
    throw new ArgumentException("Max attempts per URL must be greater than zero.", nameof(maxAttemptsPerUrl));
if (retryDelayMs < 0)
    throw new ArgumentException("Retry delay must be zero or greater.", nameof(retryDelayMs));
```

修复方法:

- 确保传给 `UrlFailoverRunner` 构造的数组引用非 null 且至少含一个 URL。
- `maxAttemptsPerUrl` 必须 ≥ 1。
- `retryDelayMs` 必须 ≥ 0(0 表示不延迟重试,合法)。

### 4. 修复 `StartupHttpParams.FromOptions` 抛出的 null 异常

`FromOptions` 会在 `options` 为 null 时抛出 `ArgumentNullException`([Runtime/Http/StartupHttpParams.cs#L94-L99](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L94-L99))。如果你重写了 `IStartupHttpParamsProvider`,请先自行判空再调用 `FromOptions`。

## 验证

- 在 `StartupRunner.Run` 外层用 `try/catch (ArgumentException)` / `try/catch (ArgumentNullException)` 捕获,确认异常类型与 `ParamName`/`Message` 与上表一致。
- 修正 `StartupOptions` 资产后,Editor 中重新进入 PlayMode,启动流程应正常进入 `ProcedureGetAppVersionInfoState` 等后续节点,不再在第一帧同步抛出。
- 如使用 `UrlFailoverRunner` 直接构造,可在单元测试中传入空数组、负数重试参数等边界值,确认能复现上表的异常消息后再修正。

## 背景(可选)

`StartupRunner.Run` 把同步校验与异步流程拆开:所有"显然写错了"的入参在校验阶段就同步抛出,不让无效状态进入 `UniTask` 状态机;只有真正发生在网络、补丁、远端服务上的问题才会通过 `StartupResult` / `StartupFailedEventArgs` 异步回报。这一约定也在 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/CHANGELOG.md#L103) 中明确记录:"Synchronous validation throws `ArgumentException` for empty `GlobalInfoUrls` before entering async state machine."
