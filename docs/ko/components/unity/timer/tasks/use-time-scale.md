# 시간 스케일 사용: 타이머를 Time.timeScale의 영향을 받게/받지 않게 하기

각 타이머는 독립적으로 시간 스케일을 선택할 수 있습니다: `TimerTimeScale.Unscaled`(실제 시간, 기본값) 또는 `TimerTimeScale.Scaled`(`UnityEngine.Time.timeScale`의 영향을 받음). `Add` 호출 시 `timeScale` 매개변수로 지정하기만 하면 됩니다.

## 사전 조건

- 프로젝트에 GameFrameX Timer 패키지가 이미 도입되어 있고, `ITimerManager` / `TimerManager` 인스턴스를 이미 확보한 상태입니다(예: `TimerComponent`를 통해 획득).

## 시간 스케일 열거형 빠른 참조

`TimerTimeScale`은 `byte` 열거형이며, 정의는 다음과 같습니다:

| 이름 | 값 | 동작 |
|------|----|------|
| `Unscaled` | 0 | `Time.timeScale`의 영향을 받지 않음(기본값, 기존 동작과 호환) |
| `Scaled` | 1 | `Time.timeScale`의 영향을 받음 |

```csharp
public enum TimerTimeScale : byte
{
    /// <summary><see cref="UnityEngine.Time.timeScale"/>의 영향을 받지 않음(기본값, 기존 동작과 호환).</summary>
    Unscaled = 0,

    /// <summary><see cref="UnityEngine.Time.timeScale"/>의 영향을 받음.</summary>
    Scaled = 1,
}
```

출처: [TimerTimeScale.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerTimeScale.cs#L6-L13)

## 작업 단계

1. `Add`의 전체 시그니처를 확인합니다. `timeScale`은 6번째 매개변수이며 기본값은 `Unscaled`입니다:

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217) (인터페이스 선언은 [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L22) 참조)

2. `Time.timeScale`의 영향을 **받지 않는** 타이머를 추가합니다(예: UI 카운트다운, 연결 끊김 후 재접속 카운트다운) — `timeScale`을 전달하지 않거나, 명시적으로 `Unscaled`를 전달합니다:

```csharp
// 기본값이 Unscaled임: 게임 일시정지(timeScale = 0) 시에도 이 타이머는 계속 진행됨
timer.Add(1000f, 0, callback);
```

3. `Time.timeScale`의 영향을 **받는** 타이머를 추가합니다(예: 슬로우 모션, 일시정지 메뉴 등의 시나리오에서 게임 로직 타이밍) — 명시적으로 `timeScale: TimerTimeScale.Scaled`를 전달합니다:

```csharp
// Time.timeScale의 영향을 받음(슬로우 모션, 일시정지 메뉴 등의 시나리오에 적합)
timer.Add(1000f, 0, callback, timeScale: TimerTimeScale.Scaled);
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L165-L167)

4. 다른 매개변수와 조합하여 사용합니다(콜백 매개변수, 태그, 완료 콜백 모두 `timeScale`과 동시에 지정 가능):

```csharp
// 단위 테스트의 실제 호출 예시: 1초 간격, 1회 반복, Scaled 모드
_timerManager.Add(1f, 1, _ => callCount++, timeScale: TimerTimeScale.Scaled);
```

출처: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L588-L589)

## 일반적인 변형

- **일시정지 메뉴**: `Time.timeScale`을 0으로 설정하고, 게임 로직에는 `Scaled` 타이머를 사용(함께 멈춤), 팝업 애니메이션/카운트다운에는 `Unscaled` 타이머를 사용(계속 진행).
- **슬로우 모션**: `Time.timeScale`을 0.5로 설정하면 `Scaled` 타이머의 실제 진행 속도도 원래의 절반이 되며, `Unscaled` 타이머는 영향을 받지 않습니다.
- **동일한 관리자에서 혼용**: 두 모드는 동일한 `TimerManager`에서 혼용할 수 있으며, 업데이트 루프는 각 타이머의 모드에 따라 시간 소스를 선택합니다:

```csharp
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L81)

## 흔한 실수

- **기본적으로 timeScale의 영향을 받는다고 생각함**: `Add`의 `timeScale` 매개변수 기본값은 `Unscaled`입니다. `Time.timeScale`을 변경하지 않으면 두 모드의 동작이 동일합니다(`timeScale = 1`). 하지만 일시정지/슬로우 재생 시 명시적으로 `Scaled`를 전달하지 않은 타이머는 느려지지 않습니다. 게임 시간을 따라가야 할 때는 반드시 명시적으로 `timeScale: TimerTimeScale.Scaled`를 작성해야 합니다.
- **`timeScale = 0` 이후 Scaled 타이머가 "사라짐"**: 타이머가 제거된 것이 아니라 매 프레임 증분 delta가 0일 뿐입니다. `Time.timeScale`을 복원하면 다시 진행됩니다.
- **위치 기반 인수 전달 실수**: `timeScale`은 `callbackParam`, `tag` 뒤, `onComplete` 앞에 위치합니다. 위치 오류를 방지하려면 항상 명명된 인수 `timeScale: TimerTimeScale.Scaled`를 사용하는 것이 좋습니다.

## 배경

`TimerManager`의 업데이트 메서드는 스케일된 시간과 실제 시간 두 가지 증분을 동시에 받으며, 각 타이머를 업데이트할 때 해당 `TimeScaleMode`에 따라 선택합니다: `Scaled`는 `elapseSeconds`를, `Unscaled`는 `realElapseSeconds`를 사용하므로 두 모드는 서로 간섭하지 않습니다. 타이머 객체가 회수되어 재사용될 때 `TimeScaleMode`는 `Unscaled`로 재설정됩니다([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L633) 참조).
