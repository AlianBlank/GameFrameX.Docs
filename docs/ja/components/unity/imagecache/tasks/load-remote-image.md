# リモート画像を非同期で読み込む方法

`IImageCacheManager.LoadImageAsync` を使用することで、リモート画像を非同期に読み込めます:非 WebGL プラットフォームではディスクキャッシュが優先的に使用され、ミス時にダウンロードしてローカルから読み込みます;WebGL プラットフォームでは `UnityWebRequestTexture` で直接読み込まれ、ブラウザがキャッシュを管理します。

## 前提条件

- `com.gameframex.unity.imagecache` パッケージがインストール済みで、シーンに `ImageCacheComponent` がアタッチされていること。
- `com.gameframex.unity.download` パッケージがインストール済みであること(非 WebGL プラットフォームで必須、ファイルダウンロード用)。
- リモート画像アドレスは `http://` または `https://` で始まっている必要があります。
- `ImageCacheConfig.CachePath` に書き込み可能なローカルディレクトリが指定されていること(非 WebGL プラットフォームで必須)。

## 操作手順

1. 画像キャッシュマネージャーのインスタンスを取得します。`ImageCacheComponent` はライフサイクルをすでにカプセル化しているため、コンポーネントフィールドまたは `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IImageCacheManager>()` から直接取得します。

    ```csharp
    using GameFrameX.ImageCache.Runtime;
    using UnityEngine;

    public class MyImageLoader : MonoBehaviour
    {
        [SerializeField] private ImageCacheComponent imageCacheComponent;

        private IImageCacheManager _manager;

        private void Start()
        {
            _manager = imageCacheComponent; // コンポーネント自体が IImageCacheManager を実装している
        }
    }
    ```

    Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs)

2. `LoadImageAsync` を呼び出し、返された `Task<Texture2D>` を `await` します。このメソッドはディスクキャッシュヒット、ファイルダウンロード、`Texture2D` デコードの全フローを自動的に処理します;読み込み成功時は `Texture2D` を返し、失敗時は `null` を返します。

    ```csharp
    using System.Threading;
    using System.Threading.Tasks;
    using UnityEngine;

    public async Task<Sprite> LoadHeadIconAsync(string url, CancellationToken ct)
    {
        var texture = await _manager.LoadImageAsync(url, ct);
        if (texture == null)
        {
            Debug.LogWarning($"読み込み失敗:{url}");
            return null;
        }

        var sprite = Sprite.Create(
            texture,
            new Rect(0, 0, texture.width, texture.height),
            new Vector2(0.5f, 0.5f));
        sprite.name = url;
        return sprite;
    }
    ```

    Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L18-L26)

3. 呼び出し前に URL を検証します。`LoadImageAsync` の内部では、空文字列または `http(s)://` で始まらないアドレスに対して警告を出力し `null` を返します。業務側でも事前に防御的な検証を行うことで、無意味な `await` を回避できます。

    ```csharp
    if (string.IsNullOrEmpty(url) ||
        (!url.StartsWith("http://") && !url.StartsWith("https://")))
    {
        Debug.LogWarning("URL が不正です");
        return null;
    }

    var tex = await _manager.LoadImageAsync(url);
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

4. (オプション)`CancellationToken` を使用して進行中の読み込みをキャンセルします。非 WebGL プラットフォームでのみ有効で、ページの破棄やユーザーのシーン切り替えなどの場面で未完了の読み込みを解放するのに適しています。

    ```csharp
    private CancellationTokenSource _cts;

    public async void Reload(string url)
    {
        _cts?.Cancel();
        _cts = new CancellationTokenSource();

        var tex = await _manager.LoadImageAsync(url, _cts.Token);
        // コンポーネントが破棄済みの場合、tex は null になる可能性がある
    }
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L122-L150)

5. 読み込み完了後、`Texture2D` を UI に適用します。`RawImage.texture` に直接代入するか、手順 2 のように `Sprite` にラップして `Image` で使用できます。

    ```csharp
    [SerializeField] private UnityEngine.UI.RawImage target;

    public async Task ApplyAsync(string url)
    {
        var tex = await _manager.LoadImageAsync(url);
        if (tex != null) target.texture = tex;
    }
    ```

## よくあるバリエーション

- **プリダウンロードとキャッシュ**:同じ URL に対して複数回 `await LoadImageAsync` を呼び出すと、初回ダウンロード後にファイルが URL の MD5 ハッシュ名で `CachePath` にキャッシュされ、以降の呼び出しではディスクから直接読み込まれるため、再ダウンロードは不要です。シーン進入時に通常の画像をプリウォームすることができます。

    ```csharp
    // 非 WebGL プラットフォーム:IsCached はダウンロード済みかどうかの判定に使用可能
    if (_manager.IsCached(url))
    {
        Debug.Log("ローカルキャッシュにヒットしました");
    }
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L180-L194)

- **WebGL プラットフォームでの読み込み**:「`LoadImageAsync` は `UNITY_WEBGL` 下では `UnityWebRequestTexture` の分岐をたどり、ディスクへの書き込みは行われません;`IsCached` は常に `false` を返し、`RemoveCache`/`ClearCache` は警告を出力します。業務側でプラットフォームを区別する必要はなく、API の動作は一貫しています。

    ```csharp
    // WebGL でも同様に呼び出すと、内部で自動的に UnityWebRequestTexture の分岐をたどる
    var tex = await _manager.LoadImageAsync(url);
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L91-L115)

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `LoadImageAsync` が `null` を返し、ログに `url is null or empty` と表示される | URL が空である | 呼び出し前に `string.IsNullOrEmpty` で検証する |
| `null` を返し、ログに `url must start with http:// or https://` と表示される | URL が http(s) で始まっていない | 完全な URL を使用する。ローカルパスや `file://` は渡さない |
| 非 WebGL でダウンロードが失敗し、ログに `download failed` と表示される | `DownloadManager` が登録されていない、またはネットワーク到達不能 | `GameFrameX` のダウンロードマネージャーが初期化され、イベントコールバックが正しく登録されていることを確認する |
| `CancellationToken` でキャンセル後も `Task` がすぐに終了しない | キャンセルロジスは非 WebGL プラットフォーム、かつキャッシュ読み取り/ファイル存在判定の後에만作用する | キャンセル後は `tex == null` かどうかを自分で判断し、`Task` が例外をスローするとは想定しないこと |

## 背景(オプション)

- 非 WebGL プラットフォーム:`ImageCacheManager` は `Utility.Hash.MD5.Hash(url)` をキャッシュファイル名として使用し、拡張子は固定で `.png`;初回ミス時には `IDownloadManager.AddDownload` でダウンロードを開始し、`TaskCompletionSource` により `DownloadSuccess` / `DownloadFailure` イベントを待ちます。
- WebGL プラットフォーム:`UNITY_WEBGL` マクロが有効な場合、`LoadImageAsync` は `UnityWebRequestTexture.GetTexture` + `SendWebRequest()` に変更され、キャッシュは完全にブラウザの HTTP Cache に委ねられるため、`IsCached`、`RemoveCache`、`ClearCache` はすべて無効化されます。

コンポーネントの初期化とライフサイクルについては、《ImageCacheComponent 概要》を参照してください;キャッシュ設定フィールドの意味については、`ImageCacheConfig` を参照してください。
