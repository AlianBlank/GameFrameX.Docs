# 用戶端傳來訊息但找不到對應的 Handler 怎麼辦

當用戶端發出請求而伺服端日誌出現 `找不到[xxx][yyy]对应的handler` 時，表示框架沒有找到能處理該訊息 ID 的 Handler 類別。這通常是訊息類別與 Handler 命名/標註不匹配、組件未載入、或路由表未更新所造成的。

## 快速診斷

| 症狀(日誌原文) | 原因 | 修復 |
|---|---|---|
| `找不到[{MessageId}][{Type}]对应的handler` | 用戶端發送的 `MessageId` 在伺服端沒有註冊過對應的 `ReqXxxHandler` | 新增 Handler 並確認 `MessageMapping` 與訊息 ID 一致 |
| 用戶端傳來某訊息，伺服端沒有任何日誌，連線被靜默關閉 | 組件未啟動 / 熱更未發佈新版本，Handler 沒有被反射載入 | 重新發佈或重新啟動 `GameFrameX.Hotfix` |
| 日誌出現 MessageType 但執行時報出 "Handler not found",重新啟動後恢復 | 路由快取(`MessageProtoHandler`)初始化時未掃描到該類型，後續伺服端未觸發重新初始化 | 在 `Launcher` 啟動流程中再次執行 `MessageProtoHelper.Init` |
| 重新命名 Handler 類別後報錯 | 類別名稱不再符合約定 `Req<消息名>Handler`,且缺少特性標註 | 改回命名約定，或為類別加上 `[MessageMapping]` |

> 日誌範例請見儲存庫:`AppStartUpHotfixGameByGateWay.cs` 第 126 行、`AppStartUpHotfixGameByMain.cs` 第 133 行。

## 修復步驟

### 1. 確認伺服端真的沒有這個 Handler

在 `GameFrameX.Hotfix` 專案中搜尋 `Req<消息名>Handler`。例如訊息 ID 對應 `ReqLogin`,應存在：

```csharp
// 原始碼路徑:GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs
[MessageMapping(typeof(ReqLogin))]
internal class ReqLoginHandler : GlobalComponentHandler<LoginComponentAgent>
{
    protected override async Task ActionAsync()
    {
        await ComponentAgent.OnLogin(NetWorkChannel, Message as ReqLogin);
    }
}
```

來源:[ReqLoginHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs#L32-L44)

注意要點：
- 類別名稱必須為 `Req<MessageName>Handler`(以 `Req` 開頭，以 `Handler` 結尾)。
- 必須繼承自框架基底類別(如 `GlobalComponentHandler<...>`、`MessageHandler<...>`),否則反射不會註冊。
- 必須帶有 `[MessageMapping(typeof(对应消息类))]` 特性，明確宣告它處理哪個訊息類別。

### 2. 確認訊息類型已加入協定組件

Handler 引用的訊息類別(如 `ReqLogin`)定義在 `GameFrameX.Proto` 專案中。如果你在 `Proto` 中新增了訊息，需要在 `Launcher` 啟動時讓 `MessageProtoHelper` 重新掃描該組件：

```csharp
// 原始碼路徑:GameFrameX.Launcher/Program.cs
CacheStateTypeManager.Init();
MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
```

來源:[Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L14-L16)

`MessageProtoHandler` 類別本身是個靜態佔位類別，目的是提供一個 `Assembly` 控制代碼給 `MessageProtoHelper.Init`,用於把 `Proto` 中的 `MessageId` 全部登錄到路由表：

來源:[MessageProtoHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/MessageProtoHandler.cs#L1-L8)

### 3. 確認 `Hotfix` / `Apps` 組件存在標記類別

框架透過反射掃描 `GameFrameX.Hotfix.HotfixHandler` 與 `GameFrameX.Apps.AppsHandler` 這兩個空類別所在的組件，來發現所有 Handler 類型。修改或精簡專案時不要刪除它們，否則新加的 Handler 不會被載入：

```csharp
// 原始碼路徑:GameFrameX.Hotfix/HotfixHandler.cs
namespace GameFrameX.Hotfix;
public static class HotfixHandler { }
```

```csharp
// 原始碼路徑:GameFrameX.Apps/AppsHandler.cs
namespace GameFrameX.Apps;
public class AppsHandler { }
```

來源:[HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8), [AppsHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/AppsHandler.cs#L32-L38)

### 4. 編譯並重新啟動伺服端

如果執行的是熱更新模式，改完 Handler 後重新發佈 `Hotfix` DLL,並重新啟動伺服端處理程序，讓 `CacheStateTypeManager` 重新執行一遍反射初始化：

```csharp
// 原始碼路徑:GameFrameX.Apps/CacheStateTypeManager.cs
var assembly = typeof(AppsHandler).Assembly;
BsonClassMapHelper.SetConvention();
```

來源:[CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L18-L22)

## 驗證

修復後按照下列順序確認問題已解決：

1. **看日誌**：重新啟動伺服端，用戶端再次傳送該訊息，日誌不應再出現 `找不到[…]对应的handler`,而應進入對應 Handler 的 `ActionAsync`。
2. **中斷點驗證**：在新建 Handler 的 `ActionAsync` 中設定中斷點，用戶端傳送請求時命中即表示路由成功。
3. **看回應**：用戶端若期望收到回應封包，確認收到正確訊息 ID 的回應內容(訊息 ID 由 `GameFrameX.Proto` 的 `MessageProto` 工具類別產生)。
4. **對照同目錄其他 Handler**:將新建檔案與能正常運作的 Handler(例如 `ReqCreateRoomHandler`)逐字比對，確認命名空間、基底類別、特性三者一致。

如果日誌中出現的 `MessageId` 在 `GameFrameX.Proto` 也搜尋不到，表示問題出在協定端(用戶端傳送的協定是另一套)，需先同步協定再處理 Handler。
