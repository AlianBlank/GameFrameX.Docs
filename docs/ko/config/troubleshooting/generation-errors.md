# 생성 실패/오류 발생 시 대처 방법

`gen-*.bat` / `gen-*.sh` 실행 후 Luban이 예외를 던지거나 출력 파일이 없을 때, 이 페이지의 진단표에 따라 항목별로 점검하세요. 문제는 대부분 스크립트 경로, 설정 플레이스홀더, Excel 표 구조 세 가지에 집중되어 있습니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| `Could not find a part of the path ... Tools/Luban.dll` | 도구 디렉터리가 없거나 경로가 잘못됨 | 저장소 루트 아래에 `Tools/`를 만들고 `Luban.dll`을 넣거나, `luban.conf`의 `toolPath`를 수정 |
| `luban.conf not found` / `conf not loaded` | 현재 디렉터리가 잘못되어 스크립트가 저장소 루트로 전환되지 않음 | `Tools/`와 같은 레벨의 디렉터리에서 스크립트를 실행하거나, 스크립트가 설정 파일이 있는 디렉터리로 `cd` 하도록 수정 |
| 플레이스홀더 `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%`가 확장되지 않음 | `luban.conf`에서 두 키가 빈 문자열임 | `luban.conf`에서 `UNITY_ASSETS_PATH`와 `SERVER_PATH`를 절대 경로로 교체 |
| `Excel ... __tables__.xlsx` 구문 분석 실패 오류 발생 | 템플릿 헤더 손상, 열 누락 또는 여러 표 병합 오류 | `Excels/__tables__.xlsx`, `__beans__.xlsx`, `__enums__.xlsx`를 복원하고, 열을 수동으로 삭제하지 마세요 |
| `Localization.xlsx not found` 오류 발생 | 클라이언트 생성 시 로컬라이제이션 파일명 변경/누락 | 명령의 `localizationFileName` 기본값은 `Localization.xlsx`이며, 필요 시 저장소의 실제 파일명으로 변경 |
| 명령창이 바로 닫혀 오류를 볼 수 없음 | 끝에 `pause`가 없음(Windows) | `gen-*.bat`의 마지막 줄이 `pause`인지 확인(기존 스크립트 참조) |
| 코드만 생성되고 데이터가 생성되지 않음 | `dataTarget`과 `codeTarget`이 일치하지 않거나 `outputDataDir` 경로가 유효하지 않음 | `--dataTarget`과 `--codeTarget`을 함께 설정하고, `outputDataDir`이 쓰기 가능한지 확인 |
| `validation failed` 오류 발생 | `--validationFailAsError true`가 설정되어 있는데 데이터가 검증을 통과하지 못함 | 일시적으로 `--validationFailAsError true`를 제거해 구체적인 경고를 확인하고, 데이터를 수정한 뒤 다시 활성화 |

## 해결 단계

### 1. Luban.dll을 찾을 수 없음

`luban.conf`를 열어 `toolPath` 필드를 확인하세요:

```json
"toolPath": "/../Config/Tools/Luban.dll",
```

스크립트는 실제로 다음과 같이 호출합니다:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf
```

출처: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L2)

두 곳은 반드시 일치해야 합니다: 스크립트에 `./Tools/Luban.dll`로 쓰여 있으면 저장소에 `Tools/Luban.dll`이 존재해야 합니다. 프로젝트에서 도구를 `Config/Tools/` 아래에 둔다면 `toolPath`와 스크립트 경로를 함께 그에 맞게 수정하세요.

### 2. 플레이스홀더가 확장되지 않음

`luban.conf`에는 기본적으로 빈 문자열이 설정되어 있습니다:

```json
"UNITY_ASSETS_PATH": "",
"SERVER_PATH": "",
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L62-L65)

`commands` 안의 명령은 이 두 변수를 참조합니다. 예를 들어:

```json
"command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config"
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L78)

스크립트를 직접 실행할 때 이 `%XXX%`는 확장되지 않으며, 파일 시스템 계층에서 "경로가 존재하지 않음" 오류가 발생합니다. 이들을 자신의 머신의 절대 경로로 교체한 후 다시 생성하세요.

### 3. Excel 템플릿 손상

`luban.conf`는 `schemaFiles`를 통해 네 개의 메타데이터 표를 선언합니다:

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

오류 메시지에 이 네 개의 파일이 언급되면 우선 저장소에서 복원하고, `Excels/Tables/`와 `Excels/Local/` 아래의 비즈니스 표 열 이름이 `__tables__.xlsx`의 필드와 하나하나 일치하는지 확인하세요.

### 4. 클라이언트 생성 시 로컬라이제이션 표를 찾을 수 없음

클라이언트 명령에는 별도의 `localizationFileName`이 있으며, 기본적으로 `Localization.xlsx`라는 파일명을 기대합니다:

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L72-L77)

로컬라이제이션 표 이름을 변경했다면(예: 저장소에 `L-Localization-UI.xlsx`, `L-Localization-成就.xlsx`, `L-Localization-文本.xlsx`만 있는 경우), `localizationFileName`을 실제 파일명으로 변경하거나 표 이름을 `Localization.xlsx`로 되돌리세요.

### 5. 스크립트 창이 바로 닫혀 오류를 볼 수 없음

Windows의 `gen-*.bat`는 모두 끝에 `pause`를 추가해야 합니다:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf

pause
```

출처: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L3)

스크립트에서 `pause`를 제거했다면 오류 메시지가 닫힌 창과 함께 사라져 원인을 알 수 없습니다. `pause`를 추가한 후 다시 실행하면 됩니다.

### 6. 서버 바이너리 생성 실패

저장소에서 제공하는 서버 bin 생성 스크립트는 다음과 같습니다:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
pause
```

출처: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L2)

여기서는 파일명이 `gen-server-bin.sh`이지만 내용은 Windows 스타일의 `dotnet ... && pause`이고, 상대 경로 `../Server/GameFrameX.Config/`에 의존한다는 점에 유의하세요. 경로 관련 오류가 발생하면 다음을 확인하세요:
- `Server/GameFrameX.Config/Json`과 `Server/GameFrameX.Config/Config` 두 디렉터리가 존재하거나 쓰기 가능한지;
- 다른 디렉터리에서 `sh ./gen-server-bin.sh`를 실행한 것이 아니라 저장소 루트 디렉터리에서 스크립트를 실행했는지.

## 검증

위와 같이 수정한 후, 최소 명령을 실행하여 전체 파이프라인이 동작하는지 확인하세요:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json \
  --xargs outputDataDir=./out/Json \
  --xargs outputCodeDir=./out/Config \
  --conf ./Luban.conf
```

성공 시:
- `./out/Config/` 아래에 `TablesComponent.cs` 등의 생성된 코드가 있어야 합니다;
- `./out/Json/` 아래에 `Tb*.json` 데이터 파일이 있어야 합니다;
- 터미널에 예외 스택 트레이스가 없어야 합니다.

그다음 해당 플랫폼 스크립트(`gen-server-json.bat` / `gen-client-json.sh` 등)를 한 번 실행하여 비즈니스가 엔드 투 엔드로 동작하는지 확인하세요.
