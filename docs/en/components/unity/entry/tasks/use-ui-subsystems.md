# How to Use the Three UI Entry Points: UI, GUI, and FairyGUI

The GameFrameX entry package exposes the three major UI components—UI, UGUI, and FairyGUI—through three static properties: `GameApp.UI`, `GameApp.GUI`, and `GameApp.FUIPackage`; simply enable the corresponding modules via compilation defines, and you can directly use these components anywhere in your business code to open/manage interfaces.

## Prerequisites

- The project has imported the GameFrameX entry package [com.gameframex.unity.entry](https://github.com/GameFrameX/com.gameframex.unity.entry).
- Enable the corresponding compilation defines below in the project's `Assembly Definition` or project settings (choose one or combine):
  - `ENABLE_GAME_FRAME_X_UI`: enables `GameApp.UI` (UI subsystem).
  - `ENABLE_GAME_FRAME_X_L_UGUI`: enables `GameApp.GUI` (UGUI subsystem).
  - `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`: enables `GameApp.FUIPackage` (FairyGUI package management).
- The corresponding runtime components (`UIComponent`, `UGUIComponent`, `FairyGUIPackageComponent`) have been registered via `GameEntry`.

## Overview of the Three Entry Points

| Entry Point | Compilation Define | Returned Component | Typical Use |
|------|--------|----------|----------|
| `GameApp.UI` | `ENABLE_GAME_FRAME_X_UI` | `UIComponent` | Unified entry point for GameFrameX's own UI subsystem |
| `GameApp.GUI` | `ENABLE_GAME_FRAME_X_L_UGUI` | `UGUIComponent` | Entry point for the traditional UGUI-based interface component |
| `GameApp.FUIPackage` | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` | `FairyGUIPackageComponent` | Entry point for FairyGUI asset package/interface management |

## Steps

### 1. Enable the UI Subsystem (`GameApp.UI`)

After enabling the define `ENABLE_GAME_FRAME_X_UI` at the project level, you can obtain the `UIComponent` instance via `GameApp.UI` from anywhere in your code:

```csharp
#if ENABLE_GAME_FRAME_X_UI
var ui = GameApp.UI;   // Lazily loaded via GameEntry.GetComponent<UIComponent>() on first access
ui.SomeApi();
#endif
```

### 4. Safe Access in Business Code

All three entry points use lazy loading: on first access, `GameEntry.GetComponent<T>()` is called to obtain and cache the component; afterwards, the static field is reused directly. Since the properties internally use `if (_xxx == null)` null checks, it is recommended to only read (never write) them in business systems, to avoid resetting static fields in multithreaded contexts.

```csharp
var ui = GameApp.UI;
var gui = GameApp.GUI;
var pkg = GameApp.FUIPackage;
```

## Common Variants

- Enabling multiple UI systems simultaneously: You can enable `ENABLE_GAME_FRAME_X_UI`, `ENABLE_GAME_FRAME_X_L_UGUI`, and `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` together in the same project; the `GameApp` class merges the three extensions as `partial` without interfering with one another.
- Enabling only FairyGUI: If the project uses only FairyGUI, simply check `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`; code generation will trim the other two properties.
- Mixing UGUI + FairyGUI: Enable both `ENABLE_GAME_FRAME_X_L_UGUI` and `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`; use `GameApp.GUI` for the UGUI workflow and `GameApp.FUIPackage` to manage FairyGUI asset packages.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Compile error `GameApp 不包含 UI 的定义` | The `ENABLE_GAME_FRAME_X_UI` compilation define is not enabled | Add `ENABLE_GAME_FRAME_X_UI` to the Scripting Define Symbols of the project or asmdef |
| Compile error `GameApp 不包含 GUI 的定义` | `ENABLE_GAME_FRAME_X_L_UGUI` is not enabled | Add `ENABLE_GAME_FRAME_X_L_UGUI` |
| Compile error `GameApp 不包含 FUIPackage 的定义` | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` is not enabled | Add `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` |
| `GameApp.UI` returns a `null` component at runtime | `UIComponent` is not registered with `GameEntry` | Register the `UIComponent` instance via `GameEntry.RegisterComponent` in the startup flow |

## Background (Optional)

The entry package uses `partial class GameApp` to split the access entry points of different subsystems into separate files, wrapping them with compilation defines to achieve on-demand compilation and avoid hard dependencies on UI systems that are not enabled. All three properties internally use the singleton lazy-loading pattern `if (_x == null) _x = GameEntry.GetComponent<T>()`, staying consistent with the `GameEntry` component registration mechanism.
