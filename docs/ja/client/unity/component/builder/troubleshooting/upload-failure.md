# オブジェクトストレージへのアップロードに失敗した場合の対処法

ビルド処理が `-IsUploadLogFile` または `-IsUploadAsset` をトリガーしたにもかかわらず、ログ/アセットがオブジェクトストレージのバケットに表示されない場合は、本ページの診断表に従って各項目を確認してください。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| ログに `The type or namespace name 'ObjectStorageUploadManager' could not not be found` が表示される | プロジェクトでオブジェクトストレージモジュールが有効化されていない | `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` マクロに対応する Package Manager でオブジェクトストレージコンポーネントをインストールし、有効化する |
| コマンドラインで認証情報を渡していないため、実行後にアップロードが行われない | `-IsUploadLogFile` が漏れている、または対応するマクロが未启用 | 後述の「スイッチがオンになっていない」セクションを参照 |
| アップロード呼び出しが 403 / SignatureDoesNotMatch をスローする | 認証情報が一致しないか、読み書き権限が不足している | 後述の「認証情報または権限エラー」セクションを参照 |
| `NoSuchBucket` / `InvalidBucketName` がスローされる | バケット名のスペルミス、または指定されたリージョンにバケットが作成されていない | 後述の「バケット名または Endpoint エラー」セクションを参照 |
| アップロードは完了したがバケット内にファイルが見当たらない | Endpoint とリージョンが一致せず、別のリージョンにファイルがアップロードされている | 後述の「リージョン不一致」セクションを参照 |
| ビルド処理が `BuildReady` 段階で中断する | `UploadFile` 呼び出し時に未捕获の例外がスローされる | 後述の「例外が握りつぶされている」セクションを参照 |

## 修正手順

### 1. スイッチがオンになっていない(最も一般的)

ビルドスクリプトは、2 つの条件が同時に満たされた場合にのみアップロードを呼び出します:[`Builder.BuildReady.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L44-L49) の `if (_builderOptions.IsUploadLogFile)` が `#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE` で囲まれています。つまり、`-IsUploadLogFile` を指定したとしても、プロジェクトで `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` マクロが定義されていない場合、コードはコンパイラによって完全に除去され、実行時には何も出力されません。

確認方法:

1. コマンドラインに `-IsUploadLogFile` が含まれていることを確認する(値は不要です。[`Builder.BuildParamsParse.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L94-L96) を参照)。
2. `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` がプロジェクトの `Scripting Define Symbols` に定義されていることを確認する。
3. `GameFrameX.ObjectStorage` パッケージが Package Manager 経由でインストールされていることを確認する。インストールされていないと `ObjectStorageUploadManager` 型が見つからない。

```text
-ExecuteMethod GameFrameX.Builder.Editor.Builder.BuildReady \
-IsUploadLogFile \
-ObjectStorageKey <your-key> \
-ObjectStorageSecret <your-secret> \
-ObjectStorageBucketName <your-bucket> \
-ObjectStorageEndPoint <your-endpoint>
```

パラメータの定義は [`BuilderOptions.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40) を参照。4 つのオブジェクトストレージフィールドはすべてデフォルトで空文字列で、1 つでも欠けると SDK がリクエスト時に直接例外をスローします。

### 2. 認証情報または権限エラー

`ObjectStorageUploadManager.UploadFile` は内部で渡された Key/Secret を使用して署名を組み立てます。キーのコピー時に文字が欠落していたり、余分なスペースが含まれていたり、サブアカウントが該当バケットに対する `PutObject` 権限を持っていない場合、`403 SignatureDoesNotMatch` または `AccessDenied` が直接スローされます。

1. オブジェクトストレージコンソールから Key と Secret を再コピーし、手入力は避ける。
2. 該当サブアカウントにバケットの読み書き権限を付与する(Alibaba Cloud OSS / Tencent Cloud COS / MinIO で概念は同じ)。
3. 一時 STS 認証情報を使用している場合は、`ObjectStorageKey/Secret` が STS 3 つ組の `AccessKeyId/SecretAccessKey` であり、`SessionToken` ではないことを確認する。

### 3. バケット名または Endpoint エラー

`ObjectStorageBucketName` はコンソールに表示されるバケットのフルネームでなければならず、`ObjectStorageEndPoint` は該当バケットが存在するリージョンの外部ネットワーク/内部ネットワークドメインでなければなりません。両者が一致しない場合、`NoSuchBucket` または `InvalidBucketName` がスローされます。

1. オブジェクトストレージコンソールにログインし、バケット名と所在リージョンを確認する。
2. `ObjectStorageEndPoint` を該当リージョンの公式ドキュメントに記載された Endpoint に変更する(例:Alibaba Cloud 华东 1:`oss-cn-hangzhou.aliyuncs.com`)。
3. 再度ビルドをトリガーし、コンソールの `Object Storage → ファイル管理` でアップロードされたログファイルが表示されることを確認する。

### 4. リージョン不一致

リクエストは成功し、コンソールは 200 を返すが、バケット内にファイルが見当たらない——通常は Endpoint が別のリージョンを指しており、ファイルが「正しい」バケットの別リージョンにある同名バケットにアップロードされています(プライベートクラウド/クロスリージョンレプリケーションのシナリオでよく発生します)。

1. `ObjectStorageEndPoint` とバケットの所属リージョンが完全に一致していることを確認する。
2. コンソールの「バケット一覧」でリージョンごとにフィルタリングし、ターゲットバケットが該当リージョン内に存在することを確認する。

### 5. 例外が握りつぶされている

`BuildReady` 内で `UploadFile` を呼び出した際に例外が発生した場合、デフォルトではビルド処理が中断され、ログには `ObjectStorageUploadManager` がスローした元の例外スタックトレースが表示されます。スタックトレースの最初の行のキーワードを診断表の該当行に転記し、上記の 1〜4 の手順に従って処理してください。

例外が外部の Jenkins/CI スクリプトに握りつぶされてスタックトレースが見えない場合は、一時的に `BuildReady` の後に `Debug.Log($"Upload finished: {_builderOptions.LogFilePath}")` を追記することで、コードが本当にアップロード分岐に入ったかを確認できます。

## 検証

1. 再度ビルドを実行し、コマンドラインに `-IsUploadLogFile` と 4 つのオブジェクトストレージパラメータがすべて揃っていることを確認する。
2. オブジェクトストレージコンソールの該当バケットで、アップロード時間でソートしてログファイルが表示されることを確認する。
3. 該当ログファイルをダウンロードし、内容に今回のビルドの `BuildReady Start` / `BuildReady End` 行が含まれており、ローカル Unity コンソールの出力と一致していることを確認する。

## 背景(任意)

アップロード呼び出しはすべて外部の `GameFrameX.ObjectStorage` パッケージの `ObjectStorageUploadManager.UploadFile` に委譲されています。本リポジトリは 4 つのコマンドラインパラメータを [`BuilderOptions`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40) に透過的に渡すだけであり、SDK を直接操作することはありません。
