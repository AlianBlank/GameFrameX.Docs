# 타임아웃 시간 및 연결 수 설정 가이드

이 페이지에서는 Web ProtoBuff 네트워크 모듈의 **요청 타임아웃 시간**과 **서버당 최대 연결 수**를 설정하는 방법을 설명합니다. 타임아웃 시간의 기본값은 `5f`초이며, Inspector에서 슬라이더로 조정(0–120초)하거나 런타임에 코드로 수정할 수 있습니다. `MaxConnectionPerServer`의 기본값은 `8`이며, Inspector 필드가 없어 매니저를 통해서만 코드로 설정할 수 있습니다.

## 사전 조건

- `com.gameframex.unity.web.protobuff` 패키지가 설치되어 있어야 합니다.
- 씬에 **Web ProtoBuff** 컴포넌트(`AddComponentMenu("GameFrameX/Web ProtoBuff")`)가 부착된 GameObject가 존재해야 합니다.

## 설정 항목 빠른 참조

| 설정 항목 | 타입 / 기본값 | 설정 방법 |
|--------|--------------|----------|
| `Timeout` | `float`, 단위는 초, 기본값 `5f` | Inspector 슬라이더(0–120), 컴포넌트 속성, 매니저 속성 |
| `RequestTimeout` | `TimeSpan`, `Timeout`에서 자동 동기화됨(`TimeSpan.FromSeconds(value)`) | 매니저 속성, 직접 할당 가능 |
| `MaxConnectionPerServer` | `int`, 기본값 `8`(생성자에서 설정) | 코드 전용, `IWebProtoBuffManager`를 통해 설정 |

## 작업 단계

### 방법 1: Inspector에서 타임아웃 시간 설정

1. 씬에서 **Web ProtoBuff** 컴포넌트가 부착된 GameObject를 선택합니다.
2. 컴포넌트의 커스텀 Inspector에서 `Timeout` 슬라이더를 드래그합니다. 값 범위는 `0f`–`120f`초입니다.
3. 이 값은 직렬화 필드 `m_Timeout`에 기록되며, 게임 시작 시 `Awake`에서 매니저에 적용됩니다.

에디터 슬라이더의 구현:

```csharp
float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
```

출처: [WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Editor/Inspector/WebComponentInspector.cs#L23)

컴포넌트 측의 해당 직렬화 필드:

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;

public float Timeout
{
    get { return m_WebProtoBuffManager.Timeout; }
    set { m_WebProtoBuffManager.Timeout = m_Timeout = value; }
}
```

출처: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L60-L71)

### 방법 2: 런타임에 코드로 수정

컴포넌트 속성을 통해 타임아웃 수정(직렬화 필드와 매니저에 동시에 기록됨):

```csharp
var component = GetComponent<GameFrameX.Web.ProtoBuff.Runtime.WebProtoBuffComponent>();
component.Timeout = 15f;
```

### 방법 3: 최대 연결 수 설정

`MaxConnectionPerServer`는 컴포넌트에 직렬화 필드로 노출되어 있지 않으므로, 모듈 인터페이스를 통해 코드에서 설정해야 합니다:

```csharp
var manager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<GameFrameX.Web.ProtoBuff.Runtime.IWebProtoBuffManager>();
manager.MaxConnectionPerServer = 16;
manager.Timeout = 10f;
```

`GameFrameworkEntry.GetModule<IWebProtoBuffManager>()`는 바로 컴포넌트의 `Awake`에서 매니저 인스턴스를 가져오는 방식입니다:

```csharp
m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
if (m_WebProtoBuffManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebProtoBuffManager.Timeout = m_Timeout;
```

출처: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L82-L90)

## 일반적인 변형

- **1초 미만 또는 `TimeSpan` 정밀도의 타임아웃이 필요한 경우**: 매니저의 `RequestTimeout`(타입 `TimeSpan`)을 직접 설정합니다. `Timeout`(float 초)을 설정하면 `RequestTimeout`이 자동으로 덮어써지므로 주의하세요:

```csharp
// 타임아웃 시간(초)
private float m_Timeout = 5f;

/// <summary>타임아웃 시간(초)을 가져오거나 설정합니다</summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>서버당 최대 연결 수를 가져오거나 설정합니다</summary>
public int MaxConnectionPerServer { get; set; }

/// <summary>요청 타임아웃 시간을 가져오거나 설정합니다</summary>
public TimeSpan RequestTimeout { get; set; }
```

출처: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L20-L54)

- **기본값으로 복원**: 매니저 생성자의 기본값은 `MaxConnectionPerServer = 8; Timeout = 5f;`이며, 두 속성을 이 값으로 되돌리면 됩니다.

출처: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L27-L31)

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 코드에서 설정한 `Timeout`이 시작 후 "적용되지 않음" | 다른 스크립트의 초기화가 먼저 실행된 후 컴포넌트의 `Awake`가 다시 `m_WebProtoBuffManager.Timeout = m_Timeout`을 실행하여, Inspector 직렬화 값이 코드 설정을 덮어씀 | 컴포넌트의 `Awake` 이후에 수정하거나 Inspector의 값을 직접 수정 |
| Inspector에서 `MaxConnectionPerServer`를 찾을 수 없음 | 해당 항목은 컴포넌트의 직렬화 필드가 아니라 매니저에만 존재 | `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()`를 사용하여 코드에서 설정 |
| 120초를 초과하는 타임아웃을 설정하려 해도 슬라이더가 움직이지 않음 | 에디터 슬라이더의 범위가 `0f`–`120f`로 하드코딩되어 있음 | 대신 코드로 `component.Timeout = 150f;` 설정 |
| `RequestTimeout`을 직접 수정했지만 곧 무효화됨 | 이후 `Timeout`에 대한 어떠한 할당도 `TimeSpan.FromSeconds(value)`로 `RequestTimeout`을 덮어씀 | `Timeout`으로만 조정하거나, `RequestTimeout`을 마지막에 설정 |

## 검증

- 수정 후 `component.Timeout` / `manager.Timeout`를 읽어 새 값이 반환되는지 확인합니다.
- `manager.Timeout = x` 설정 후 `manager.RequestTimeout`을 읽으면 `TimeSpan.FromSeconds(x)`와 같아야 합니다.

## 배경

`Timeout`은 외부에 통일된 "초" 단위 설정 진입점입니다. 이를 설정하면 요청 측에서 사용할 `TimeSpan` 형태의 `RequestTimeout`이 동기 생성됩니다. `MaxConnectionPerServer`는 서버당 최대 연결 수를 나타내며 기본값은 8입니다. 모듈의 전체 구조에 대해서는 개요 페이지를 참조하세요.
