# 介面載入依賴資源異常怎麼辦

當你在開啟介面（`OpenUIFormAsync`）時遇到依賴資源載入失敗，包括依賴資產不存在、載入回呼未觸發、依賴計數長時間不變，或開啟流程被中斷，可以透過本頁的診斷表定位根因並修復。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `OpenUIFormFailure` 事件觸發，`ErrorMessage` 提示資源不存在 | 傳入的 `uiFormAssetPath` 與實際資產路徑不一致，或資產未被 AssetBundle / Addressables 收錄 | 核對路徑字串與 `UIFormAssetName`，重新建置依賴清單 |
| `LoadedCount` 始終為 0,`TotalCount` 大於 0 | 依賴資源載入回呼未正確註冊，或被並行開啟請求搶佔 | 將開啟同一資源的操作序列化，確認 `OpenUIFormDependencyAssetEventArgs` 監聽鏈路 |
| `DependencyAssetName` 為 `null` | 介面本身沒有宣告依賴資產，或依賴中繼資料未產生 | 重新產生 UI 設定，確認依賴資產清單非空 |
| `Task` 長時間未回傳 `IUIForm` | 依賴載入鏈未完成，非同步流程被 `await` 卡住 | 檢查是否在 `OpenUIFormAsync` 呼叫端遺漏 `await`，確認資源管理器已初始化 |
| `UIFormAssetPath` / `UIFormAssetName` 為 `null` | 上層呼叫沒有傳入有效路徑 | 在呼叫 `OpenUIFormAsync` 前驗證參數，使用 `GameFrameworkGuard.NotNull` |

事件物件的核心欄位定義如下，可結合日誌核對：

## 修復步驟

### 1. 資源路徑或名稱不相符

`OpenUIFormAsync` 接受兩個關鍵參數：資源路徑 `uiFormAssetPath` 與資源名稱 `uiFormAssetName`(在載入物件內)。如果任意一個不對應專案內實際存在的資產，載入會立即失敗並透過 `OpenUIFormFailure` 拋出。

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class UIFormLoadingObject : IReference
{
    public string UIFormAssetPath { get; private set; }
    public string UIFormAssetName { get; private set; }
    public Type UIFormType { get; private set; }
    public Task<IUIForm> Task { get; private set; }

    public static UIFormLoadingObject Create(string uiFormAssetPath, string uiFormAssetName, Type uiFormType, Task<IUIForm> task)
    {
        var uiFormLoadingObject = ReferencePool.Acquire<UIFormLoadingObject>();
        uiFormLoadingObject.UIFormAssetPath = uiFormAssetPath;
        uiFormLoadingObject.UIFormAssetName = uiFormAssetName;
        uiFormLoadingObject.UIFormType = uiFormType;
        uiFormLoadingObject.Task = task;
        return uiFormLoadingObject;
    }
}
```

Source: [BaseUIManager.UIFormLoadingObject.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.UIFormLoadingObject.cs#L43-L86)

操作步驟：

1. 在 Unity 中定位該 UI 預製體，複製其 `Addressables` 位址或 AssetBundle 路徑。
2. 呼叫 `OpenUIFormAsync` 時使用完全相同的字串(區分大小寫)。
3. 在 `OpenUIFormFailure` 回呼內輸出 `UIFormAssetName` 與 `ErrorMessage`,逐字元比對。

### 2. 非同步流程未等待

`OpenUIFormAsync` 回傳 `Task<IUIForm>`,內部實作 `InnerOpenUIFormAsync` 是抽象方法，由子類別完成依賴載入。

```csharp
[UnityEngine.Scripting.Preserve]
public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}

[UnityEngine.Scripting.Preserve]
protected abstract Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false);
```

Source: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L114-L130)

如果呼叫端遺漏 `await`,`Task` 會進入未完成狀態被靜默丟棄，後續操作讀取 `uiForm` 時得到 `null`。修復方式：

1. 呼叫處統一使用 `await uiManager.OpenUIFormAsync<MyForm>(path, true, userData);`。
2. 在協程或回呼風格的程式碼中使用 `.ContinueWith(...)` 或 `await` 同步上下文。
3. 配合 `OpenUIFormSuccess` / `OpenUIFormFailure` 事件確認流程已結束。

### 3. 依賴計數不變 / 回呼未觸發

`OpenUIFormDependencyAssetEventArgs` 目前在 `BaseUIManager` 中以註解形式保留(`m_OpenUIFormDependencyAssetEventHandler` 已註解)，如果你的專案曾訂閱該事件，需要重新啟用並由子類別在依賴載入過程中呼叫 `EventId` 分發。當 `LoadedCount` / `TotalCount` 長時間不變，通常是依賴載入回呼沒有被驅動，或 `TotalCount` 在初始化前已被讀取為 0。

建議在自訂 `BaseUIManager` 子類別內：

1. 在 `InnerOpenUIFormAsync` 中取得依賴資產清單，得到 `totalCount`。
2. 每完成一個依賴載入，呼叫 `OpenUIFormDependencyAssetEventArgs.Create(...)` 並透過事件匯流排廣播。
3. 監聽端讀取 `LoadedCount` / `TotalCount` 驅動進度條。

### 4. 失敗事件未註冊

`OpenUIFormFailure` 事件用於捕捉例外，簽章如下：

```csharp
[UnityEngine.Scripting.Preserve]
public event EventHandler<OpenUIFormFailureEventArgs> OpenUIFormFailure
{
    add { m_OpenUIFormFailureEventHandler += value; }
    remove { m_OpenUIFormFailureEventHandler -= value; }
}
```

Source: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L63-L68)

如果應用程式沒有訂閱該事件，例外只能透過 `Task` 拋出，可能在上層被靜默吞掉。修復方式：在 UI 框架啟動後第一時間註冊 `OpenUIFormFailure` 與 `OpenUIFormSuccess`,將錯誤日誌統一寫入磁碟或上報。

## 驗證

1. 觸發一次正常開啟流程，確認 `OpenUIFormSuccess` 被觸發且 `SerialId` 與請求一致。
2. 觸發一次故意寫錯路徑的開啟請求，確認 `OpenUIFormFailure.ErrorMessage` 包含可讀取的資訊。
3. 觸發一次帶依賴資產的介面，確認 `LoadedCount` 最終等於 `TotalCount`。
4. 在偵錯工具內觀察 `UIFormLoadingObject.Task.Status`,確保其由 `WaitingForActivation` 進入 `RanToCompletion` 或 `Faulted`。
