# UI Form Helper 사용자 정의 방법

`UIFormHelperBase`를 상속하고 `IUIFormHelper`의 세 가지 메서드를 구현하면 UI 리소스의 인스턴스화, `IUIForm` 비즈니스 객체 생성, UI 해제 흐름을 직접 제어할 수 있습니다. 이후 `UIComponent`가 클래스 이름 문자열 또는 프리팹 참조를 통해 해당 구현을 사용하도록 설정하면 적용됩니다.

## 사전 조건

- GameFrameX UI 하위 시스템의 기본 흐름을 숙지하고 있어야 합니다(전체 아키텍처에 대해서는 관련 설명 참조).
- 프로젝트에 `com.gameframex.unity.ui` 패키지가 설치되어 있고, 씬에 `UIComponent`가 연결되어 있어야 합니다.

## 작업 단계

1. **`IUIFormHelper` 인터페이스를 구현하거나 `UIFormHelperBase`를 상속합니다.**

   `UIFormHelperBase`는 이미 `MonoBehaviour` 라이프사이클과 `Scripting.Preserve]` 표시를 처리해 주므로, 이를 상속하고 세 가지 추상 메서드만 구현하면 됩니다.

   인터페이스 정의는 [IUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIFormHelper.cs#L40-L76)에, 추상 기반 클래스는 [UIFormHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)에 있습니다.

   ```csharp
   using System;
   using GameFrameX.UI.Runtime;
   using UnityEngine;

   public class MyUIFormHelper : UIFormHelperBase
   {
       public override object InstantiateUIForm(object uiFormAsset)
       {
           // 사용하는 UI 방식(FairyGUI / UGUI / 기타)에 따라 UI 리소스를 인스턴스화합니다
           var prefab = uiFormAsset as GameObject;
           if (prefab == null) return null;
           return Instantiate(prefab);
       }

       public override IUIForm CreateUIForm(object uiFormInstance, Type uiFormType, object userData)
       {
           // uiFormInstance를 uiFormType에 해당하는 비즈니스 로직 스크립트에 바인딩하고 IUIForm을 반환합니다
           var go = uiFormInstance as GameObject;
           var form = go.GetComponent(uiFormType) as IUIForm;
           if (form != null)
           {
               (form as Component).gameObject.SetActive(true);
           }
           return form;
       }

       public override void ReleaseUIForm(object uiFormAsset, object uiFormInstance, object assetHandle,
                                          string uiFormAssetPath, string uiFormAssetName)
       {
           // 인스턴스를 파괴하고 필요에 따라 리소스 핸들을 반환합니다
           var go = uiFormInstance as GameObject;
           if (go != null) Destroy(go);
       }
   }
   ```
   Source: [Runtime/UIFormHelperBase.cs#L42-L81](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)

2. **`UIComponent`가 사용자의 Helper를 사용하도록 합니다.**

   `UIComponent`는 "타입 이름 리플렉션 생성"과 "사용자 정의 Helper 프리팹 직접 드래그" 두 가지 방식을 모두 지원합니다. 둘 중 하나를 선택하세요:

   - **방식 A —— 타입 이름 사용**: `UIComponent` Inspector의 `UI Form Helper Type Name`을 클래스 전체 이름(네임스페이스 포함)으로 변경합니다. 기본값은 `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`입니다.
   - **방식 B —— 프리팹 사용**: `MyUIFormHelper`를 GameObject에 연결해 프리팹으로 만든 뒤 `UIComponent`의 `Custom UI Form Helper` 필드로 드래그합니다. 런타임에 `Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper)`는 이 참조를 우선 사용합니다.

   ```csharp
   // Runtime/UIComponent.cs에서 사용자 정의 Helper를 읽어오는 로직
   UIFormHelperBase uiFormHelper = Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper);
   if (uiFormHelper == null)
   {
       Log.Error("Can not create UI form helper.");
       return;
   }
   uiFormHelper.name = "UIFormHelper";
   transform = uiFormHelper.transform;
   transform.SetParent(this.transform);
   transform.localScale = Vector3.one;
   m_UIManager.SetUIFormHelper(uiFormHelper);
   ```
   Source: [Runtime/UIComponent.cs#L526-L538](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L526-L538)

3. **타입 이름의 네임스페이스가 ComponentType와 일치하도록 합니다.**

   시작 시 `UIComponent`는 `m_UIFormHelperTypeName`이 현재 UI 시스템에 해당하는 네임스페이스로 시작해야 한다는 검증을 수행합니다. 그렇지 않으면 콘솔에 `UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.` 오류가 출력되고 해당 컴포넌트가 비활성화됩니다.

   ```csharp
   if (!m_UIFormHelperTypeName.StartsWithFast(namespaceName))
   {
       Debug.LogError("UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.");
       enabled = false;
       return;
   }
   ```
   Source: [Runtime/UIComponent.cs#L437-L442](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L437-L442)

4. **런타임에 Helper를 수동으로 교체합니다(선택 사항).**

   게임 실행 중 Helper를 전환하려면 `BaseUIManager.SetUIFormHelper(IUIFormHelper)`를 직접 호출하세요:

   ```csharp
   m_UIManager.SetUIFormHelper(new MyUIFormHelper());
   ```
   Source: [Runtime/BaseUIManager.cs#L313-L320](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L313-L320)

## 일반적인 변형

| 시나리오 | 방법 |
|------|------|
| FairyGUI 연동 | Helper 내부에서 `uiFormAsset`를 FairyGUI 컴포넌트로 파싱하여 `GComponent`를 반환하고, `CreateUIForm`에서 해당 `GComponent`를 래핑한 `IUIForm` 구현을 반환합니다. |
| UGUI 연동 | `GameObject`를 범용 컨테이너로 직접 사용하며, `InstantiateUIForm` 내에서 `Object.Instantiate`를 호출하고, `CreateUIForm` 내에서 `GetComponent(uiFormType)`로 로직 스크립트를 바인딩합니다. |
| 런타임 중 실시간 교체 | `BaseUIManager.SetUIFormHelper`를 통해 새 Helper 인스턴스로 교체하지만, 기존 인스턴스의 파괴는 직접 관리해야 합니다. |

## 자주 발생하는 오류

| 오류 | 원인 | 해결 방법 |
|------|------|------|
| 시작 후 콘솔에 `UI组件的 UI Form Helper 设置错误。` 오류 발생 | `UI Form Helper Type Name`의 네임스페이스가 현재 `ComponentType`와 일치하지 않습니다. | 네임스페이스를 선택한 UI 시스템과 일치하도록 변경합니다(예: FairyGUI는 `GameFrameX.UI.FairyGUI.Runtime`, `UGUI`는 `GameFrameX.UI.UGUI.Runtime`) 또는 올바른 프리팹을 드래그합니다. |
| UI를 열 때 `Can not create UI form helper.` 오류 발생 | 타입 이름 철자 오류 또는 사용자 정의 프리팹에 스크립트가 연결되지 않음 | `m_UIFormHelperTypeName`의 전체 클래스 이름을 확인하거나, `m_CustomUIFormHelper` 프리팹에 `UIFormHelperBase` 하위 클래스가 연결되어 있는지 확인합니다. |
| `SetUIFormHelper(null)` 시 예외 발생 | `BaseUIManager` 내부에서 매개변수에 대해 null이 아닌지 검증합니다. | 항상 null이 아닌 인스턴스를 전달하며, 비워야 할 때는 기본 구현으로 교체합니다. |

## 배경(선택 사항)

`IUIFormHelper`는 "리소스를 GameObject / GComponent로 만드는 방법"과 "이를 로직 스크립트와 바인딩하는 방법"이라는 두 가지 작업을 UI 관리자에서 분리해 내어, 동일한 `BaseUIManager`가 다양한 UI 방식에 대응할 수 있도록 합니다. `UIComponent`는 `Start`에서 "타입 이름 → 사용자 정의 프리팹" 우선순위로 Helper를 생성한 뒤 `BaseUIManager.SetUIFormHelper`를 호출하여 프레임워크에 등록합니다.
