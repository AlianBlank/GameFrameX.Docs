# ホット更新の読み込み失敗またはバージョン不一致が発生した場合

サーバーの起動やホット更新のトリガー時に、ホット更新 DLL（`GameFrameX.Hotfix.dll`）の読み込み、バージョン検証、または実行の初期化が失敗すると、通常はプロセスが直接終了したり、ログに例外がスローされたり、クライアント/管理ツールにバージョンの不一致が表示されます。このページでは、一般的な症状の早見表と修復手順を示します。

## クイック診断

| 症状 | 原因 | 修復 |
|------|------|------|
| `ArgumentException: dllPath` または `hotfixDllName` が null をスロー | 渡された `dllPath` または `hotfixDllName` が空文字列 | デフォルト値でパラメータを渡す。詳細は「修復手順 - パスとファイル名」を参照 |
| `GameFrameX.Hotfix.dll` が見つからず、ファイルが存在しないと表示される | DLL が実行ディレクトリにコピーされていない、またはバージョンディレクトリと実際のディレクトリが一致していない | DLL を `dllVersion/dllPath` に対応するディレクトリに配置する |
| 読み込み時に `OnLoadSuccess` が false を返す | ホット更新ブリッジ実装の初期化失敗（依存サービスの未起動、設定の欠落など） | 起動順序と `AppSetting` の整合性を確認する |
| クライアントが「バージョン不一致」を表示 | `dllVersion` パラメータが指すディレクトリの DLL がフレームワークのバージョンと一致していない | 同じソースコードでホット更新プロジェクトを再ビルドし、DLL を上書きする |
| ホット更新後に古いモジュールが参照され、クラスが見つからない | リロード中に古いモジュールが並行リクエストにヒットし、プロキシタイプが切り替わった | `DoingHotfix=false` になってから負荷テストを実行するか、ログを調査する |
| サービス再起動時に `HotfixAssembly` が空になることがある | `LoadHotfix` の前に `HotfixManager.HotfixAssembly` が呼び出されている | 必ず先に `LoadHotfix` を呼び出してからアセンブリにアクセスする |

## 修復手順

### パスとファイル名

`HotfixManager.LoadHotfix` / `LoadHotfixModule` は `dllPath` と `hotfixDllName` に対して null チェックを行い、`dllVersion` が空かどうかによって実際にロードされるサブディレクトリを決定します。

- デフォルトパラメータ：`dllPath="hotfix"`、`hotfixDllName="GameFrameX.Hotfix.dll"`、`dllVersion=""`。
- `dllVersion` が空でない場合、`dllPath` は無視され、バージョン番号のサブディレクトリから DLL がロードされます。

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
public static bool LoadHotfix(AppSetting setting,
    string dllVersion = "",
    string dllPath = "hotfix",
    string hotfixDllName = "GameFrameX.Hotfix.dll")
{
    ArgumentException.ThrowIfNullOrEmpty(dllPath, nameof(dllPath));
    ArgumentException.ThrowIfNullOrEmpty(hotfixDllName, nameof(hotfixDllName));
    // ...
    var path = Path.Combine(Environment.CurrentDirectory,
        string.IsNullOrEmpty(dllVersion) ? dllPath : $"{dllVersion}",
        hotfixDllName);
    var hotfixModule = new HotfixModule(path);
    var reload = _module != null;
    var success = hotfixModule.Init(reload);
    if (!success) { return false; }
    _module = hotfixModule;
    return true;
}
```

Source: [HotfixManager.cs#L95-L116](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L95-L116)

操作:

1. 実行ディレクトリに `hotfix/GameFrameX.Hotfix.dll`（または `<dllVersion>/GameFrameX.Hotfix.dll`）が実際に存在することを確認します。
2. `dllPath` に手動で空文字列を渡さないでください。バージョンディレクトリを使用する場合は、`dllVersion` をバージョン文字列に設定し、デフォルトの `dllPath` をそのまま使用してください。
3. DLL 名をカスタマイズする場合は、`hotfixDllName` がビルド成果物と一致していることを確認してください。

### バージョン番号と DLL の不一致

`dllVersion` が指すディレクトリの DLL がフレームワークのホストバージョンと一致しない場合、「ロードはできるが動作が異常」になったり、インターフェースのシグネチャ不一致による `MissingMethodException` が発生したりします。

1. 古いバージョンディレクトリを削除し、現在のブランチ `main` の `GameFrameX.Hotfix` プロジェクトから再ビルドします。
2. 新しい DLL をターゲットの `dllVersion` ディレクトリ（例：`1.0.0/GameFrameX.Hotfix.dll`）にコピーし、ホストプロセスが指すバージョン番号と一致させます。
3. サーバーを起動し、ログで `ReloadTime` が更新されたことを確認します（新しいモジュールが初期化されたことを示します）。

`ReloadTime` は `LoadHotfixModule` の内部で更新されます：

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
private static async Task<bool> Load(HotfixModule newModule, AppSetting setting, bool reload)
{
    ReloadTime = TimerHelper.GetNowWithUtc();
    if (reload)
    {
        // ... 旧モジュールを 10 分遅延させて Unload
    }
    _module = newModule;
    if (_module.HotfixBridge != null)
    {
        return await _module.HotfixBridge.OnLoadSuccess(setting, reload);
    }
    return true;
}
```

### `OnLoadSuccess` が false を返す

ホット更新ブリッジインターフェースは、読み込み成功後に `OnLoadSuccess` を呼び出し、`false` を返した場合は読み込み失敗と見なされます。

```csharp
// GameFrameX.Core/Hotfix/IHotfixBridge.cs
Task<bool> OnLoadSuccess(AppSetting setting, bool reload);
```

Source: [IHotfixBridge.cs#L45](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/IHotfixBridge.cs#L45)

操作:

1. `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`（または `ByMain` / `ByHeart`）を開き、`OnLoadSuccess` の実装を確認して、最初のステップで失敗している依存関係を特定します。
2. その実装が依存しているサービス（データベース、Redis、HTTP 登録など）が呼び出し前にすでに初期化されていることを確認します。
3. `OnLoadSuccess` 内の各ステップにより詳細なログを追加し、もう一度ホット更新をトリガーして、追加されたログに基づいて失敗箇所を特定します。

### リロード中の並行リクエスト

`HotfixManager` はリロード時に古いモジュールを最大 10 分間キャッシュし、その間新旧モジュールは「リクエストがどのアセンブリから来たか」に基づいてそれぞれルーティングされます。古いモジュールがすでに `Unload` されている場合、プロキシの検索は失敗します。

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
if (reload)
{
    var oldModule = _module;
    DoingHotfix = true;
    var oldModuleHash = oldModule.GetHashCode();
    OldModuleMap.TryAdd(oldModuleHash, oldModule);
    _ = Task.Run(async () =>
    {
        await Task.Delay(TimeSpan.FromMinutes(10));
        OldModuleMap.TryRemove(oldModuleHash, out _);
        oldModule.Unload();
        DoingHotfix = !OldModuleMap.IsEmpty;
    });
}
```

Source: [HotfixManager.cs#L158-L172](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L158-L172)

操作:

1. ホット更新トリガー後 10 分間は、サーバーの再起動や古いモジュールに依存するインターフェースへの大規模な負荷テストを避けてください。
2. ログに "Agent/Component type not found" が表示される場合は、リクエストが古いモジュールアセンブリ（古い DLL の残留）からのものか、新しいモジュールアセンブリからのものかを調査します。
3. 古い `hotfix` ディレクトリが完全に置き換えられていることを確認し、`Environment.CurrentDirectory` 配下に複数の DLL が存在しないようにしてください。

## 検証

1. サーバーを起動し、ログに `ReloadTime` が書き込まれて例外がないことを確認します。これは新しいモジュールが有効になったことを示します。
2. `HotfixManager.GetAgent<T>(...)` と `GetComponentType(...)` をそれぞれ呼び出し、新しいモジュールのプロキシが正常に解決できることを確認します。
3. リロードシナリオで `DoingHotfix` フラグを観察します。最初は `true` になり、10 分後に `false` に戻り、古いモジュールが解放されます。
4. クライアント/管理ツールのバージョン番号が `dllVersion` サブディレクトリと一致しており、ログイン、メッセージの送受信が正常にできることを確認します。
