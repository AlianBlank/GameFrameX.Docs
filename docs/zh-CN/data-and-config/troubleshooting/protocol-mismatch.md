# 客户端与服务器协议不一致怎么办

当客户端与服务端之间出现解析失败、字段读不到、报错"协议版本不一致"或推送收不到时,通常意味着两端的 `.proto` 源文件或导出产物已经不同步。本页给出快速诊断、定位步骤与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 反序列化报 `Invalid wire-type` / `Unknown field` | 客户端字段号或字段类型与服务端不一致 | 见下文"统一字段号与类型" |
| 推送丢失 / `Resp` 缺少 `ErrorCode` 字段 | 服务端单独导出,客户端用了过期的导出产物 | 见下文"两端重新导出" |
| 路由不到对应处理器 | 模块 ID(`option module = N`)与文件名 `_<N:0000>_<Domain>.proto` 不一致 | 见下文"对齐模块 ID" |
| 客户端收到了不应看到的内部协议 | 把内部(`Inner` 前缀 / 负 ID)协议当外部协议导出 | 见下文"区分外部与内部协议" |
| 字段号 ≥ 800 导致解析错误 | 占用了系统保留号 | 见下文"避开保留字段号" |

## 修复步骤

### 1. 确认 `.proto` 源是同一份

所有客户端与服务端必须基于仓库同一份 `.proto` 源文件导出。仓库根目录下的协议模块结构如下:

| Proto 文件 | Module | 说明 |
|------------|--------|------|
| `_0002_InnerBasic.proto` | 2 | 内部基础协议 |
| `_0010_Basic.proto` | 10 | 基础协议 |
| `_0020_Common.proto` | 20 | 公共协议(错误码、共享类型) |
| `_0100_Bag.proto` | 100 | 背包协议 |
| `_0120_Social.proto` | 120 | 社交协议 |
| `_-0120_Inner_Social.proto` | -120 | 内部社交协议(仅服务端) |
| `_0300_User.proto` | 300 | 用户/账号协议 |
| `_0310_Attribute.proto` | 310 | 玩家属性同步协议 |
| `_0400_Room.proto` | 400 | 房间协议 |
| `_0410_RockPaperScissors.proto` | 410 | 猜拳小游戏协议 |
| `_0500_Mail.proto` | 500 | 邮件协议 |

来源:[README.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.md#L36-L50)

### 2. 两端重新导出

最稳的修复方式是让两端都用同一份源再导出一次:

- **CI 方式**:直接下载 [latest Release](https://github.com/GameFrameX/GameFrameX.Protobuf/releases/latest) 的产物,`push` 后会自动重新发布。
- **Docker 方式**:
  ```bash
  docker run --rm \
    -v ./Protobuf:/protos \
    -v ./Server/GameFrameX.Proto/Proto:/output \
    gameframex/gameframex-tools:latest \
    --mode csharp --isServer true \
    --usingStatements "using System|using ProtoBuf|using System.Collections.Generic|using GameFrameX.NetWork.Abstractions|using GameFrameX.NetWork.Messages" \
    --isGenerateDescription true \
    --inputPath /protos --outputPath /output --namespaceName GameFrameX.Proto.Proto
  ```
- **本地脚本**:`Proto2CsExport_Server.sh/.bat` 服务端,`Proto2CsExport_Client.sh/.bat` 客户端。

来源:[README.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.md#L309-L336)

### 3. 统一字段号与类型

字段号(`= 1`、`= 2` …)是两端对齐的唯一依据,字段名只是给人看的。修改时遵循:

- **只能新增字段,不能修改或删除已有字段的编号与类型**,否则历史消息会反序列化失败。
- 字段号必须 **小于 800**(`>= 800` 是系统保留,会导致解析错误)。
- `Resp` 消息里的 `ErrorCode` 字段是工具自动生成的保留字段,**不要在 `.proto` 里手工定义**。

来源:[README.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.md#L285-L290)

### 4. 对齐模块 ID

文件名里的数字必须和文件里的 `option module = N;` 一致,且文件名格式必须是 `_<ModuleID:0000>_<Domain>.proto`:

```protobuf
// _0100_Bag.proto
syntax = "proto3";
package Bag;
option module = 100;  // 与文件名 0100 完全一致
```

模块 ID 范围:

| ID 范围 | 用途 |
|---------|------|
| `0` ~ `32767` | 客户端 ↔ 服务端 |
| `-32768` ~ `-1` | 服务端 ↔ 服务端(内部) |

来源:[README.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.md#L62-L84)

### 5. 区分外部与内部协议

**外部协议**(客户端可见)与**内部协议**(服务端之间)绝不能混用:

- 内部文件用 `Inner` 前缀搭配**负模块 ID**,例如 `_-0120_Inner_Social.proto`。
- 也可以用 `-s` 或 `_s` 后缀(如 `player-s.proto`),并在导出时加 `--isServer true`;默认 `--isServer false` 会跳过这些文件,避免泄漏到客户端。

来源:[README.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.md#L301-L307)

### 6. 验证导出参数一致

确认两端的 `ProtoExport` 命令使用的 `--namespaceName`、`--usingStatements`、`--isGenerateDescription` 完全一致,否则命名空间或属性元数据会出现差异。

## 验证

完成以上步骤后,请逐项确认:

1. 两端拉取同一份 `.proto` 源(对比 git commit hash 或文件内容哈希)。
2. 重新执行导出,产物时间戳为最新。
3. 客户端启动并发送 `Req<Name>`,服务端能正常解析并回包。
4. 主动推送 `Notify<Name>`,客户端能收到并解析。
5. 检查 `Resp<Name>` 中是否包含自动生成的 `ErrorCode` 字段(由工具注入,不是手写)。

## 常见错误

- **改了字段号或类型**:线上会立刻出现大量反序列化失败。新增字段用新编号,旧字段保留。
- **手工在 `Resp` 里写了 `ErrorCode`**:会和工具自动生成的字段冲突,导致字段冲突报错。
- **客户端拉了带 `Inner` 前缀或 `-s`/`_s` 后缀的文件导出**:把内部协议泄漏到客户端,可能被恶意调用。
- **`syntax = "proto2";` 或未写 `syntax`**:ProtoExport 工具会直接拒绝。
- **服务端导出了但客户端没有用 latest Release**:版本错位,需要重新下载并替换客户端协议 SDK。
