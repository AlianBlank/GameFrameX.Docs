# 如何初始化物件儲存管理器

透過 `ObjectStorageUploadFactory.Create<T>` 建立並初始化一個物件儲存上傳管理器實例，完成後即可呼叫 `UploadFile` / `UploadDirectory` 等介面上傳檔案。

## 前置條件

- 已安裝 `com.gameframex.unity.objectstorage` 套件。
- 已引入一個實作 `IObjectStorageUploadManager` 的具體型別(本套件僅提供抽象基底類別 `BaseObjectStorageUploadManager`,具體雲端廠商的實作需另行引入)。
- 已準備好四項參數:`accessKey`、`secretKey`、`bucketName`,以及選填的 `endpoint`。

## 操作步驟

1. 在程式碼中加入命名空間引用：

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   來源:[IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13)

2. 呼叫 `ObjectStorageUploadFactory.Create<T>` 靜態方法，傳入泛型參數(實作類別)與四項憑證。工廠內部會呼叫 `Activator.CreateInstance<T>()` 並自動執行 `Init`,無需手動初始化：

   ```csharp
   // 假設已引入某個具體實作,例如 MyCloudUploader : IObjectStorageUploadManager
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create<MyCloudUploader>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: "https://oss-cn-hangzhou.aliyuncs.com" // 選填,部分物件儲存無需該值
   );
   ```

   來源:[ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. 如需自訂遠端儲存路徑，呼叫 `SetSavePath`(注意傳入路徑不要以目錄分隔符號結尾，基底類別會自動去除尾部的斜線)：

   ```csharp
   manager.SetSavePath("uploads/build/v1");
   ```

   來源:[BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

4. 完成以上步驟後，管理器即處於「已初始化」狀態，可直接呼叫 `UploadFile` 或 `UploadDirectory` 執行上傳。

## 常見變體

- 不使用工廠，自行 `new` 一個實作類別並手動呼叫 `Init`:

  ```csharp
  var manager = new MyCloudUploader();
  manager.Init("ak", "sk", "bucket", "endpoint");
  ```

  `Init` 的簽章來自介面 `IObjectStorageManager`,`endpoint` 為可空參數，預設為 `null`。

  來源:[IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L13)

- 直接繼承 `BaseObjectStorageUploadManager` 實作自訂上傳邏輯：僅需覆寫 `Init`、`UploadDirectoryInternal` 與 `UploadFileInternal` 三個 `protected`/ `public abstract` 方法。

  來源:[BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L10-L34)

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `Create<T>` 編譯錯誤，提示 `T` 不滿足條件約束 | 泛型 `T` 未實作 `IObjectStorageUploadManager` | 傳入具體上傳管理器類別(繼承自 `BaseObjectStorageUploadManager` 或直接實作介面) |
| 呼叫 `SetSavePath` 後路徑被截斷 | 傳入路徑以目錄分隔符號結尾 | 基底類別會自動去除尾部的 `Path.DirectorySeparatorChar`,無需手動處理，但需確保傳入有效的目錄名稱 |
| 上傳時仍以預設路徑為準 | 建立實例後忘記呼叫 `SetSavePath` | 在上傳前明確設定 `BucketSavePath` |

## 背景(選填)

`ObjectStorageUploadFactory.Create<T>` 會在內部一次性完成 `new` 與 `Init` 呼叫，目的是避免呼叫端遺漏初始化步驟。`endpoint` 在不同雲端廠商之間含義不同，介面以選擇性參數的形式相容。
