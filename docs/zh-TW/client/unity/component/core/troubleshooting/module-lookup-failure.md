# 模組查找失敗怎麼辦

呼叫 `GameFrameX.Runtime.GameFrameworkEntry.GetModule<T>()` 查找模組時，框架會按介面名透過反射定位實作類別；查找過程會因為介面約束、命名規則、自動註冊失敗等原因拋出 `GameFrameworkException`。本頁按例外訊息列出根因與修復步驟。

## 快速診斷

| 症狀（例外訊息原文） | 根因 | 修復 |
|---|---|---|
| `You must get module by interface, but 'X' is not.` | 泛型 `T` 不是介面，框架強制使用介面取得 | [改成傳介面類型](#修復1-必須用介面取得) |
| `You must get a Game Framework module, but 'X' is not.` | 傳入的介面未以 `GameFrameX.` 命名空間開頭 | [修正命名空間](#修復2-命名空間必須以-gameframex-開頭) |
| `Can not find Game Framework module type 'X.Y.Z'.` | 自動按命名慣例查不到實作類別，需要明確註冊 | [呼叫 RegisterModule 或補上實作類別](#修復3-找不到模組實作類別) |
| `You must register module by interface, but 'X' is not.` | `RegisterModule` 的第一個參數傳成了類別 | [傳入介面類型](#修復4-註冊時第一個參數必須是介面) |
| `You must register module by Class and not Interface and Abstract, but 'X' is not.` | 第二個參數不是具體類別（介面、抽象類別或非類別類型） | [傳入具體實作類別](#修復5-註冊時第二個參數必須是具體類別) |
| `Can not create module 'X'.` | 實作類別缺少無參數建構函式或 `Activator.CreateInstance` 失敗 | [補齊無參數建構函式](#修復6-實作類別缺少無參數建構函式) |

## 修復步驟

### 修復1 必須用介面取得

`GetModule<T>` 的第一件事就是判斷 `typeof(T).IsInterface`，非介面直接拋錯。

```csharp
// 錯誤：傳實作類別
var foo = GameFrameworkEntry.GetModule<FooImpl>();

// 正確：傳介面
var foo = GameFrameworkEntry.GetModule<IFoo>();
```

Source: [GameFrameworkEntry.cs#L95-L120](/src/Runtime/Base/GameFrameworkEntry.cs#L95-L120)

### 修復2 命名空間必須以 `GameFrameX.` 開頭

框架要求介面的 `FullName` 以 `GameFrameX.` 起始，否則拋第二條例外。

```csharp
// 錯誤：命名空間不在 GameFrameX 下
namespace MyGame { public interface IBar {} }

// 正確
namespace GameFrameX.Runtime { public interface IBar {} }
```

Source: [GameFrameworkEntry.cs#L104-L107](/src/Runtime/Base/GameFrameworkEntry.cs#L104-L107)

### 修復3 找不到模組實作類別

查找實作類別時，框架會按慣例把介面名去掉前綴 `I` 後拼到同一命名空間去反射（如 `GameFrameX.Runtime.IFoo` → `GameFrameX.Runtime.Foo`）。失敗則要求明確 `RegisterModule`。

```csharp
// 慣例查找（同名空間下存在 Foo 類別即可）
public class Foo : GameFrameworkModule, IFoo { /* ... */ }

// 或者明確註冊：傳入的第二個 Type 可以來自任意命名空間
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(MyGame.Modules.FooImpl));
```

呼叫入口在 `GetModule<T>` 內的 `Type.GetType(moduleName)` 邏輯，見 [GameFrameworkEntry.cs#L109-L119](/src/Runtime/Base/GameFrameworkEntry.cs#L109-L119)；註冊邏輯見 [GameFrameworkEntry.cs#L153-L169](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L169)。

### 修復4 註冊時第一個參數必須是介面

`RegisterModule` 第一行就校驗 `interfaceType.IsInterface`。

```csharp
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(Foo));   // 正確
GameFrameworkEntry.RegisterModule(typeof(Foo), typeof(Foo));     // 拋例外
```

Source: [GameFrameworkEntry.cs#L153-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L163)

### 修復5 註冊時第二個參數必須是具體類別

要求 `implType.IsClass && !implType.IsInterface && !implType.IsAbstract`。

- 介面 → 拋 `by Class and not Interface ... is not.`
- 抽象類別 → 拋同上
- 用具體類別註冊即可

Source: [GameFrameworkEntry.cs#L160-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L160-L163)

### 修復6 實作類別缺少無參數建構函式

`CreateModule` 使用 `Activator.CreateInstance(moduleType)` 實例化，找不到無參數建構式或建構拋錯時會得到 `Can not create module 'X'.`。

```csharp
public class Foo : GameFrameworkModule
{
    public Foo() { }  // 必須保留一個可存取的無參數建構函式
    protected internal override int Priority => 0;
    protected internal override void Update(float a, float b) { }
    protected internal override void Shutdown() { }
}
```

## 驗證

- 在 `Awake` 或 `Start` 裡捕捉 `GameFrameworkException`：
  ```csharp
  try
  {
      var ui = GameFrameworkEntry.GetModule<IFooModule>();
  }
  catch (GameFrameworkException ex)
  {
      Debug.LogError(ex.Message);
  }
  ```
  不再拋出即表示註冊與命名空間均正確。
- 控制台不再出現 `Can not find Game Framework module type` 字樣，說明自動按慣例查找成功；若仍查找失敗，請確認組件已編譯進 Player Settings 且介面與實作類別命名空間一致。
