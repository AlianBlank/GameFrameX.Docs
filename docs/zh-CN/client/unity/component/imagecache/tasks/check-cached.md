# 如何判断图片是否已缓存

通过 `IsCached(string url)` 可以判断指定 URL 的图片是否已经下载到本地缓存,命中缓存可避免重复网络请求。WebGL 平台始终返回 `false`,其余平台会以 URL 的 MD5 值作为文件名检查缓存文件是否存在。

## 前置条件

- 已将 `ImageCacheComponent` 挂到游戏框架的组件管理器中(或持有 `IImageCacheManager` 实例)。
- 当前构建平台**不是 WebGL**(WebGL 下缓存无意义,接口恒为 `false`)。

## 操作步骤

1. 获取缓存组件实例:

```csharp
var cache = GameEntry.GetComponent<ImageCacheComponent>();
```

2. 调用 `IsCached` 并传入远程图片地址:

```csharp
string url = "https://example.com/avatar.png";
bool cached = cache.IsCached(url);
if (cached)
{
    // 已命中缓存,可直接走本地加载逻辑或跳过下载提示
}
else
{
    // 走下载流程,例如 cache.LoadImageAsync(url)
}
```

3. `IImageCacheManager` 上同样暴露了该方法,可直接通过接口调用:

```csharp
IImageCacheManager manager = cache;
bool cached = manager.IsCached(url);
```

接口签名见 `IImageCacheManager.cs` 第 34 行,实现见 `ImageCacheManager.cs` 第 180 行,组件封装见 `ImageCacheComponent.cs` 第 83 行。

## 常见变体

- **传空 URL**:`IsCached(string url)` 在 `url` 为 `null` 或空字符串时直接返回 `false`,不会抛异常。
- **WebGL 平台**:受 `#if UNITY_WEBGL` 编译分支控制,无论是否已下载都会返回 `false`,不要据此判断"未缓存"。
- **结合异步加载**:可在 `LoadImageAsync` 前先 `IsCached` 做 UI 占位/进度提示,避免空白闪烁。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| WebGL 下 `IsCached` 永远返回 `false` | WebGL 不支持本地文件缓存,源码固定返回 `false` | 在 WebGL 跳过该检查或视为"未缓存"流程 |
| 同一 URL 不同尺寸/裁剪参数判定结果不同 | 缓存以**原始 URL** 的 MD5 作为键,带 query string 的 URL 视作不同资源 | 保持 URL 字符串与下载时一致 |
| 修改了 `CachePath` 配置后旧文件失效 | 路径变了,旧缓存文件不在新路径下 | 清理旧目录或迁移后再判断 |

## 背景(可选)

实现位于 `ImageCacheManager.cs`,核心是 `Utility.Hash.MD5.Hash(url)` 加 `Utility.Const.FileNameSuffix.PNG` 拼出缓存路径,再用 `FileHelper.IsExists` 判断文件存在性。整个判定是同步的、纯本地 IO,开销极低,适合在 UI 逻辑前置调用。
