# 监听网络事件(连接/断开/错误/心跳丢失)

本页说明如何订阅并处理网络模块抛出的四类事件:`NetworkConnectedEventArgs`(连接成功)、`NetworkClosedEventArgs`(连接关闭)、`NetworkErrorEventArgs`(网络错误)、`NetworkMissHeartBeatEventArgs`(心跳丢失)。这些事件均继承自 `GameFrameX.Event.Runtime.GameEventArgs`,通过各自类型的静态字段 `EventId`(值等于类型全名)注册订阅,处理回调中直接读取事件携带的字段即可。

## 前置条件

- 已引入 GameFrameX 网络组件(命名空间 `GameFrameX.Network.Runtime`)。
- 事件订阅入口由 **GameFrameX.Event 组件**提供(`GameEventArgs` 基类位于 `GameFrameX.Event.Runtime`,该组件不在本仓库内),请确认项目中已启用事件组件后再订阅本页列出的事件 Id。

## 操作步骤

1. 确认你要监听的事件及其携带字段(全部位于 `GameFrameX.Network.Runtime` 命名空间):

| 事件类 | 触发时机 | 携带字段 | EventId 值 |
|--------|----------|----------|------------|
| `NetworkConnectedEventArgs` | 网络连接成功 | `NetworkChannel`(`INetworkChannel`)、`UserData`(`object`,连接时传入的自定义数据) | `GameFrameX.Network.Runtime.NetworkConnectedEventArgs` |
| `NetworkClosedEventArgs` | 网络连接关闭 | `NetworkChannel`(完整字段见源文件) | `GameFrameX.Network.Runtime.NetworkClosedEventArgs` |
| `NetworkErrorEventArgs` | 网络错误 | `NetworkChannel`、`ErrorCode`(`NetworkErrorCode`)、`SocketErrorCode`(`System.Net.Sockets.SocketError`)、`ErrorMessage`(`string`) | `GameFrameX.Network.Runtime.NetworkErrorEventArgs` |
| `NetworkMissHeartBeatEventArgs` | 心跳包丢失 | `NetworkChannel`、`MissCount`(`int`,已丢失次数) | `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs` |

2. 用各事件类的**静态字段** `EventId` 向事件组件注册回调,不要手写字符串——`EventId` 的定义就是类型全名:

```csharp
/// <summary>
/// 网络连接成功事件编号。
/// </summary>
public static readonly string EventId = typeof(NetworkConnectedEventArgs).FullName;

/// <summary>
/// 获取网络连接成功事件编号。
/// </summary>
public override string Id
{
    get { return EventId; }
}
```

Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L44-L54)

3. 在回调中按事件类型读取字段。以错误事件为例,可同时拿到框架层错误码、Socket 层错误码与错误消息:

```csharp
/// <summary>
/// 获取网络频道。
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// 获取错误码。
/// </summary>
public NetworkErrorCode ErrorCode { get; private set; }

/// <summary>
/// 获取 Socket 错误码。
/// </summary>
public SocketError SocketErrorCode { get; private set; }

/// <summary>
/// 获取错误信息。
/// </summary>
public string ErrorMessage { get; private set; }
```

Source: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L68-L86)

4. 心跳丢失时用 `MissCount` 判断严重程度(该计数随连续丢失递增),配合 `NetworkChannel` 定位是哪个频道:

```csharp
/// <summary>
/// 获取网络频道。
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// 获取心跳包已丢失次数。
/// </summary>
public int MissCount { get; private set; }
```

Source: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L65-L73)

5. 回调返回后**不要缓存事件对象**。事件实例来自引用池(`ReferencePool.Acquire` 创建、`Clear()` 复位字段),字段会在事件派发后被清空:

```csharp
public static NetworkConnectedEventArgs Create(INetworkChannel networkChannel, object userData)
{
    NetworkConnectedEventArgs networkConnectedEventArgs = ReferencePool.Acquire<NetworkConnectedEventArgs>();
    networkConnectedEventArgs.NetworkChannel = networkChannel;
    networkConnectedEventArgs.UserData = userData;
    return networkConnectedEventArgs;
}

/// <summary>
/// 清理网络连接成功事件。
/// </summary>
public override void Clear()
{
    NetworkChannel = null;
    UserData = null;
}
```

Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L77-L96)

## 常见变体

- **断线重连**:在 `NetworkMissHeartBeatEventArgs`(`MissCount` 超过阈值)或 `NetworkClosedEventArgs` 回调中记录频道信息(地址等从 `NetworkChannel` 获取),延迟后重新发起连接;连接结果再由 `NetworkConnectedEventArgs` 确认。
- **区分多个频道**:同时维护多条连接时,在所有回调里先比较 `NetworkChannel`(如频道名)再处理,避免把 A 频道的错误当成 B 频道的。
- **错误分级展示**:用 `ErrorCode` 做业务分支,用 `SocketErrorCode`/`ErrorMessage` 做日志与提示文案。

## 常见错误

| 现象 | 原因 | 规避方法 |
|------|------|----------|
| 订阅字符串手写后收不到事件 | 字符串与实际 `EventId` 不一致(注意命名空间全名 `GameFrameX.Network.Runtime.` 前缀) | 永远用 `NetworkConnectedEventArgs.EventId` 这类静态字段订阅 |
| 回调里读到的字段是 `null` / `0` | 事件对象来自引用池,派发后 `Clear()` 已复位字段 | 在回调内立即读取并拷贝需要的值,不缓存事件实例 |
| `SocketErrorCode` / `ErrorMessage` 引用不到 | 未引入 `System.Net.Sockets` 命名空间 | 在订阅类文件顶部添加 `using System.Net.Sockets;`(错误事件源文件即如此引用) |
| 编译报找不到 `GameEventArgs` | 事件基类在 GameFrameX.Event 组件,非本仓库 | 先安装/启用事件组件 |

## 背景

四个事件参数类均为 `sealed class ... : GameEventArgs`,并标注 `[UnityEngine.Scripting.Preserve]` 以防被代码裁剪;通过静态 `Create(...)` 从引用池获取实例、`Clear()` 归还前复位字段,这是框架统一的"引用池事件"模式,也因此要求回调内即时消费数据。事件类源码位于 `Runtime/EventArgs/` 目录([NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs)、[NetworkClosedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkClosedEventArgs.cs)、[NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs)、[NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs));错误码枚举见 `Runtime/Network/Base/NetworkErrorCode.cs`,心跳处理相关基类见 `Runtime/Network/Helper/BasePacketHeartBeatHandler.cs` 与 `Runtime/Network/Base/IHeartBeatMessage.cs`。事件的派发与订阅 API 属于 GameFrameX.Event 组件,关于事件组件整体用法,见其对应文档。
