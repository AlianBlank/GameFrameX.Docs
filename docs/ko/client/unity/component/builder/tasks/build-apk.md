# APK 설치 패키지 빌드 방법

`GameFrameX.Builder.Editor.Builder.BuildApk()` 를 호출하면 Unity 프로젝트를 원클릭으로 Android APK로 패키징하고, 필요에 따라 객체 스토리지에 업로드할 수 있습니다. 이 페이지에서는 명령줄 호출, 매개변수 설명 및 일반적인 오류 처리 방법을 제공합니다.

## 사전 조건

1. Unity 편집기에 본 패키지(`com.gameframex.unity.builder`)가 설치되어 있고, Unity 편집기 플랫폼이 **Android** 로 전환되어 있어야 합니다.
2. Android 서명, SDK, NDK, JDK 등 환경이 구성되어 있어야 합니다(Unity 공식 Android Player Settings 참조).
3. APK를 객체 스토리지에 업로드해야 하는 경우, `BuildPipeline → PlayerSettings → Scripting Define Symbols` 에 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 를 추가하고, 필요에 따라 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT` / `_QI_NIU` / `_A_LI_YUN` 중 하나를 활성화해야 합니다.

## 작업 단계

### 1. Unity 편집기에서 직접 호출

`Window → General → Search` 를 열고, 메뉴 항목 `Builder/BuildApk` 을 실행하거나, 임의의 편집기 스크립트에서 호출합니다:

```csharp
using GameFrameX.Builder.Editor;

public static class MyBuildEntry
{
    public static void BuildApk()
    {
        GameFrameX.Builder.Editor.Builder.BuildApk();
    }
}
```

Source: [Editor/Builder.cs#L59-L78](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L59-L78)

### 2. CI에서 명령줄을 통해 호출

`Unity.exe -batchmode -executeMethod` 를 사용하여 패키징 진입점을 트리거하고, 명령줄 매개변수를 통해 빌드 동작을 제어합니다. 일반적으로 사용되는 매개변수는 아래 표를 참조하세요.

| 명령줄 매개변수 | 의미 | 기본값 |
|------------|------|--------|
| `-executeMethod` | 실행할 메서드의 전체 이름, 여기에는 `GameFrameX.Builder.Editor.Builder.BuildApk` 입력 | 없음 |
| `-logFile` | Unity 로그 출력 경로, 로그 끝의 `/Unity/` 가 `/` 로 대체됨 | 없음 |
| `-BUILD_NUMBER` | 빌드 번호 | 없음 |
| `-JOB_NAME` | Jenkins 등 CI의 작업 이름 | 없음 |
| `-PackageName` | YooAsset 리소스 패키지 이름 | 없음 |
| `-ChannelName` | 채널 이름 | 없음 |
| `-BundleId` | Android 패키지 이름(BundleId) | 없음 |
| `-AppVersion` | 애플리케이션 버전 | 없음 |
| `-PackageVersion` | 리소스 패키지 버전 | 없음 |
| `-BuildPipeline` | 패키징 파이프라인 유형 | 없음 |
| `-Language` | 언어 | 없음 |
| `-IsUploadApk` | 스위치: 빌드 완료 후 APK를 객체 스토리지에 업로드 | `false` |
| `-IsUploadLogFile` | 스위치: 로그 파일 업로드 | `false` |
| `-IsUploadAsset` | 스위치: 리소스 업로드 | `false` |
| `-IsUpdateAssetPackageVersion` | 스위치: 원격 리소스 패키지 버전 번호 업데이트 | `false` |
| `-UpdateAssetPackageVersionUrl` | 버전 번호 업데이트 인터페이스 주소 | 없음 |
| `-UpdateAssetPackageVersionAuthorization` | 버전 번호 업데이트 인터페이스 인증 헤더 | 없음 |
| `-WeChatBotKey` | Enterprise WeChat 로봇 Webhook Key(패키징 결과 알림) | 없음 |
| `-ObjectStorageKey / -ObjectStorageSecret / -ObjectStorageBucketName / -ObjectStorageEndPoint` | 객체 스토리지 액세스 자격 증명 | 없음 |

매개변수 파싱 로직은 `Builder.BuildParamsParse` 에 위치하며, 각 `-xxx` 바로 뒤에 값이 오면 `BuilderOptions` 의 해당 필드에 할당됩니다.

```text
Unity.exe -batchmode -nographics -quit \
  -projectPath <ProjectPath> \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
  -logFile <LogPath>/builder.log \
  -BUILD_NUMBER 100 \
  -JOB_NAME nightly \
  -BundleId com.example.game \
  -AppVersion 1.0.0 \
  -PackageVersion 100 \
  -ChannelName official \
  -IsUploadApk \
  -WeChatBotKey <WeChatKey>
```

Source: [Editor/Builder.BuildParamsParse.cs#L13-L160](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L13-L160)

### 3. 산출물 및 업로드 경로

`BuildApk` 은 내부적으로 `BuildProductHelper.BuildPlayerAndroid()` 를 통해 실제 패키징을 실행하며, APK 파일 경로를 산출합니다:

- APK는 기본적으로 `Library/PlayerDataCache/...` 외부의 프로젝트 빌드 디렉터리에 위치하며, 구체적인 경로는 `BuildProductHelper` 출력을 기준으로 합니다.
- `-IsUploadApk` 가 전달되면, 객체 스토리지에 업로드되는 저장 경로는 다음과 같습니다:
  `builder/{productName}/{activeBuildTarget}/{JobName}/{Application.version}/{BuildNumber}`.

Source: [Editor/Builder.cs#L47](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L47),[Editor/Builder.cs#L62-L78](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L62-L78)

## 일반적인 변형

- **로컬 빌드만 수행, 업로드하지 않음**: `-IsUploadApk` 를 추가하지 않으면 됩니다.
- **로그도 함께 업로드**: `-IsUploadLogFile` 을 추가하면, `-logFile` 에 지정된 로그가 동일한 객체 스토리지 경로에 업로드됩니다.
- **객체 스토리지 지원 활성화**: 패키징에 사용되는 Editor 프로젝트에서 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 매크로를 활성화하고, 클라우드 공급업체에 따라 `_TENCENT` / `_QI_NIU` / `_A_LI_YUN` 중 하나를 추가합니다. `Builder` 정적 생성자에서 매크로에 따라 해당 `IObjectStorageUploadManager` 구현을 선택합니다.
- **Enterprise WeChat 알림**: `-WeChatBotKey` 를 통해 로봇 Webhook Key를 전달하면, 패키징 종료 후 결과를 푸시할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Exception: InvalidOperationException` 이 보고되고 로그에 객체 스토리지가 활성화되지 않았다는 메시지가 표시됨 | `-IsUploadApk` 를 전달했지만 프로젝트에 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 매크로가 없음 | PlayerSettings Scripting Define Symbols에 해당 매크로를 추가하거나, `-IsUploadApk` 를 제거 |
| `Android` 플랫폼으로 전환한 후에도 "Build target not supported" 가 계속 표시됨 | `BuildApk` 호출 시 현재 `BuildTarget` 이 Android가 아님 | `EditorUserBuildSettings.activeBuildTarget == Android` 인지 확인 |
| 매개변수가 적용되지 않음(예: `BundleId` 가 대체되지 않음) | 명령줄 매개변수 이름의 철자가 틀렸거나 값이 누락됨 | 위 표를 참조하여 `-BundleId <value>` 형식을 사용하고, 값은 매개변수 이름 바로 뒤에 와야 함 |
| `GameFrameX.Builder.Editor.Builder.BuildApk` 을 찾을 수 없음 | 패키지가 가져와지지 않았거나 클래스 이름의 철자가 틀림 | Package Manager에서 해당 패키지가 설치되었는지 확인하고, 전체 클래스 이름은 `GameFrameX.Builder.Editor.Builder` |

## 배경(선택 사항)

`Builder` 는 `partial class` 이며, 매개변수 파싱은 `Builder.BuildParamsParse` 에서, 실제 APK 생성은 프레임워크 내부의 `BuildProductHelper.BuildPlayerAndroid()` 에서 처리합니다. 업로드 부분은 `IObjectStorageUploadManager` 로 추상화되어 있으며, 현재 Tencent Cloud, Alibaba Cloud, Qiniu Cloud의 세 가지 구현이 내장되어 있고, 해당 컴파일 매크로가 사용될 때만 컴파일에 참여합니다.
