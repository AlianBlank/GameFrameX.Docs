# 如何在应用启动时打印调试信息

用 `OptionsBuilder.CreateWithDebug<T>` 或直接调用 `OptionsDebugger.PrintParsedOptions`,即可在应用启动时把已解析的命令行参数、值、类型、默认值、是否必需等信息以表格形式打印到控制台,便于排查启动期配置问题。

## 前置条件

- 已通过 NuGet 引用 `GameFrameX.Foundation.Options`。
- 已定义一个 `class` 配置类型,属性使用 `OptionAttribute` 标注(参考 `OptionAttribute` 用法)。

## 操作步骤

1. 定义配置类型 `AppOptions`,为每个属性加上 `OptionAttribute`:

```csharp
using GameFrameX.Foundation.Options.Attributes;

public sealed class AppOptions
{
    [Option(LongName = "host", Description = "服务监听地址", Required = true)]
    public string Host { get; set; } = "127.0.0.1";

    [Option(LongName = "port", Description = "服务端口", DefaultValue = 8080)]
    public int Port { get; set; }

    [Option(LongName = "token", Sensitive = true, Description = "访问令牌")]
    public string Token { get; set; }
}
```

Source: [AppOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Options/OptionsDebuggerSensitiveOutputTests.cs#L1-L40)

2. 在 `Main`/`Program` 中用 `CreateWithDebug` 一行构建并打印:

```csharp
using GameFrameX.Foundation.Options;

var options = OptionsBuilder.CreateWithDebug<AppOptions>(
    args: args,
    skipValidation: false);

Console.WriteLine($"使用 Host = {options.Host}");
```

`CreateWithDebug` 内部已经会调用 `OptionsDebugger.PrintParsedOptions(result)` 把解析结果按表格输出。

Source: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L175-L184)

3. 如果你使用的是 `OptionsBuilder<T>.Build()` 或 `OptionsProvider.Get<T>()`,也已经在成功路径里自动调用了 `PrintParsedOptions`,无需额外打印。

Source: [OptionsProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsProvider.cs#L185-L218)

4. 想自己控制打印时机时,直接调用:

```csharp
OptionsDebugger.PrintParsedOptions(options);
```

打印内容包含表头 `Command-line parameter and parsed configuration object information` 与六列表格:选项、值、必需、类型、描述、默认值。敏感字段(`Sensitive = true`)的值会被遮罩。

Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L70-L91)
Source: [OptionsDebugger.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsDebugger.cs#L161-L172)

## 常见变体

- **手动捕获异常并打印**:`TryCreate` 失败时 `result` 会回退到默认值对象,可在 catch 后再调用 `PrintParsedOptions` 输出错误上下文。
- **只打印已构建好的对象**:非启动期调试时,在任意位置拿到 `TOptions` 实例,直接调用 `OptionsDebugger.PrintParsedOptions(options)` 即可。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台乱列、宽字符错位 | 控制台宽度小于 `DefaultConsoleWidth`(120),且列宽被压缩 | 在启动时把控制台宽度调大,或在支持宽字符的终端运行 |
| 表格里某列被截断 | 描述文本过长触发 `MaxDisplayElements` 限制 | 缩短 `Description` 文本,或拆分到多个属性 |
| 敏感字段显示了明文 | `OptionAttribute.Sensitive` 未开启 | 给含密钥的属性显式加 `Sensitive = true` |
| 打印无表格 | 类型不是 `class`,或没有公开实例属性 | 使用 `where T : class, new()` 的配置类型 |

## 背景(可选)

`OptionsDebugger` 使用反射枚举 `T` 的公开属性,在表格中按字符显示宽度(中文按双宽度)自适应控制台宽度,并对敏感字段做遮罩。启动期打印由 `CreateWithDebug` 与 `OptionsProvider` 内部统一调用,避免各处重复样板代码。
