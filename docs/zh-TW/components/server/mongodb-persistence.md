# 如何使用 MongoDB 持久化儲存玩家資料

本章節將協助您將 `GameFrameX.DataBase.Mongo` 整合到您的遊戲伺服器中，完成玩家資料的新增、查詢、更新、刪除以及交易寫入操作。閱讀完本頁後，您可以直接在伺服器中執行基於 MongoDB 的玩家資料持久化。

## 前置條件

- 已安裝 MongoDB（本機或叢集），並準備好類似 `mongodb://user:password@host:27017` 的連線字串以及目標資料庫名稱。
- 伺服器專案已加入 `GameFrameX.DataBase.Mongo` 套件（命名空間 `GameFrameX.DataBase.Mongo`），且可存取 `GameFrameX.DataBase.Abstractions` 中的 `IDatabaseService`、`DbOptions`。
- 玩家資料類型必須繼承自 `BaseCacheState`，MongoDB 將使用 `typeof(T).Name` 作為集合名稱。

## 操作步驟

### 1. 建立並開啟服務

`MongoDbService` 是核心進入點，實作了 `IDatabaseService`。使用 `Open(DbOptions)` 建立連線。內部會執行 `ping` 驗證，並以 `300 / 700 / 1500 ms` 的指數退避重試 3 次。失敗時會自動切換為不健康狀態並啟動復原工作。

```csharp
using GameFrameX.DataBase.Mongo;
using GameFrameX.DataBase.Abstractions;

var mongo = new MongoDbService();
var options = new DbOptions
{
    ConnectionString = "mongodb://localhost:27017",
    Name = "GameFrameX",
};
bool ok = await mongo.Open(options);
if (!ok) throw new InvalidOperationException("MongoDB initialization failed");
```

設定項目 `Options.ConnectionString` 與 `Options.Name` 必須一併提供。當以相同目標重複呼叫 `Open` 時，將重複使用現有連線並再次執行 `ping`；否則將重設連線。

### 2. 定義玩家資料類型

玩家資料需要繼承 `BaseCacheState`。框架會在寫入時自動維護 `CreatedTime` 與 `UpdateTime`，集合名稱預設為類型名稱。

```csharp
using GameFrameX.DataBase.Abstractions;

public sealed class PlayerState : BaseCacheState
{
    public string Name { get; set; }
    public int Level { get; set; }
    public long Gold { get; set; }
}
```

集合來自 `MongoDbContext.GetCollection<T>()`，回傳的 `IMongoCollection<T>` 以 `typeof(T).Name` 命名。

### 3. 新增玩家資料

新增介面位於 `MongoDbService.Add.cs`，會自動填入時間戳記，並透過帶重試機制的寫入通道執行：

```csharp
var player = new PlayerState { Id = "p_1001", Name = "Alice", Level = 1, Gold = 0 };
await mongo.AddAsync(player);
await mongo.AddListAsync(new[] { player, anotherPlayer }); // 批次，IsOrdered=false
```

`BulkWriteOptions` 預設為 `{ IsOrdered = false }`，批次插入可並行執行。

### 4. 查詢與更新

服務分別使用 `MongodbService.Query.cs` 與 `MongoDbService.Update.cs` 處理讀取與寫入路徑。讀取操作預設延遲退避為 `{120, 300, 700} ms`，冪等寫入為 `{150, 400, 900} ms`，交易為 `{200, 500, 1000} ms`。常見用法：

```csharp
// 單筆更新
await mongo.UpdateAsync(player);

// 依 Id 檢查是否存在；不存在則插入，存在則更新欄位集合（冪等）
await mongo.AddOrUpdateAsync(player);
await mongo.AddOrUpdateListAsync(manyPlayers);
```

### 5. 軟刪除與交易

刪除介面支援軟刪除與硬刪除；多步驟寫入可放入交易中：

```csharp
await mongo.DeleteAsync(player);                 // 軟刪除
await mongo.HardDeleteAsync(player);             // 實體刪除
await mongo.RestoreAsync(player);                // 還原軟刪除
await mongo.ExecuteInTransactionAsync(token =>
{
    // 在此對集合執行多個寫入操作
    return Task.CompletedTask;
});
```

### 6. 健康檢查與優雅關閉

模組內建 `MongoDbHealthCheck`：

```csharp
services.AddHealthChecks()
    .AddCheck<MongoDbHealthCheck>("mongodb");
```

服務關閉時呼叫 `await mongo.Close()` 釋放連線；執行期間可讀取 `mongo.AvailabilityState` 取得 `Healthy / Degraded / Unhealthy` 狀態。

## 常見變體

- **切換資料庫**：使用不同的 `ConnectionString` / `Name` 再次呼叫 `Open(...)`，內部的 `MongoClient` 與 `MongoDbContext` 將自動重設。
- **執行階段參數調校**：`DbOptions.RuntimeOptions` 可搭配 `ApplyRuntimeOptions` 使用，以調整逾時等執行階段參數（詳見 `MongoDbService.Connection.cs` 第 69-84 行）。
- **自訂集合名稱**：`MongoDbContext.GetCollection<T>()` 一律使用類型名稱。如需自訂，請繼承並重複使用 `IMongoDatabase`。
- **計量檢測**：模組使用 `System.Diagnostics.Metrics` 公開 `db_open_retry_total`、`db_operation_latency_ms`、`db_health_status` 等計量指標，可與 OpenTelemetry 整合。

## 常見錯誤

- **未呼叫 `await mongo.Open(options)` 即執行 CRUD 操作**：`EnsureInitialized()` 將拋出例外；必須先成功呼叫 `Open`。
- **`ConnectionString` 或 `Name` 為空**：`Open` 將拋出 `ArgumentNullException`，導致啟動時當機。
- **玩家類型未繼承 `BaseCacheState`**：泛型約束 `where TState : BaseCacheState` 將在編譯時期攔截。
- **在交易內執行非交易操作**：`ExecuteInTransactionAsync` 需要 MongoDB 以複本集／分片叢集方式部署；單機模式的 `mongod` 將會失敗。
- **忽略失敗狀態**：當 `Open` 失敗時，服務將被設定為 `Unhealthy` 並啟動背景復原工作。您也應檢查 `AvailabilityState` 與日誌 `MongoDbService.Open Exception`。

## 背景說明（選讀）

`MongoDbService` 是一個 `sealed partial class`，依職責拆分為多個檔案：`Add / Update / Delete / Query / Collection / Connection / Index / Retry / Recovery / UpsertTransaction / Availability` 等。可用性由私有計數器與白名單（`NonCriticalReadOperationWhiteList`、`CoreWriteOperationWhiteList`）決定讀寫降級策略，並透過 `System.Threading.Volatile` 公開可觀測的計量指標。
