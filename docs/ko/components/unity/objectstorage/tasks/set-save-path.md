# 객체 저장 경로 설정 방법

`SetSavePath(string)`을 호출하여 객체 저장소의 대상 저장 경로를 설정할 수 있으며, 이후 `UploadDirectory`와 `UploadFile`로 업로드된 파일은 모두 해당 경로에 저장됩니다.

## 사전 조건

- `ObjectStorageUploadFactory`를 통해 `IObjectStorageUploadManager` 인스턴스를 획득해야 합니다(구체적인 타입은 팩토리가 현재 플랫폼/설정에 따라 생성하며, `BaseObjectStorageUploadManager`를 상속받음).
- 쓸 버킷(`bucketName`)을 확인하고 `Init(accessKey, secretKey, bucketName, endpoint)`를 완료해야 합니다.

## 작업 단계

1. 업로드 매니저 인스턴스를 가져옵니다.

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs)

2. `SetSavePath`를 호출하여 버킷 내 객체 저장 경로를 지정합니다(끝에 구분자가 있거나 없는 형태 모두 지원).

   ```csharp
   // 작성법 A: 끝에 구분자를 쓰지 않음
   manager.SetSavePath("game/assets/textures");
   
   // 작성법 B: 끝에 구분자를 포함, 구현 내부에서 마지막 구분자를 자동으로 제거함
   manager.SetSavePath("game/assets/textures/");
   ```

   구현은 먼저 `savePath`가 `Path.DirectorySeparatorChar`로 끝나는지 판단하고, 만약 그렇다면 `Substring(0, savePath.Length - 1)`으로 잘라낸 뒤 `BucketSavePath`에 할당합니다. 두 가지 작성법은 동등합니다.

   Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

3. 경로 설정이 완료되면 업로드 인터페이스를 호출하면 파일이 `BucketSavePath` 아래에 저장됩니다.

   ```csharp
   // 전체 디렉터리 업로드
   manager.UploadDirectory("/로컬/Assets/Textures");
   
   // 또는 단일 파일 업로드
   bool ok = manager.UploadFile("/로컬/Assets/Textures/icon.png");
   ```

   Source: [IObjectStorageUploadManager.cs#L9-L21](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9-L21)

## 일반적인 변형

- **매 업로드 전에 경로 재설정**: 동일한 세션 내에서 `SetSavePath`를 반복 호출하여 다른 하위 디렉터리로 업로드를 전환할 수 있습니다. `BucketSavePath`는 보호된 필드이며, 매 호출마다 덮어씌워집니다.
- **상대 경로 vs 절대 키 접두사**: `SetSavePath`가 받는 것은 객체 키(Key)의 접두사이며, 예를 들어 `"game/v1"`과 같은 형태로 로컬 파일 시스템 경로가 아닙니다. 로컬 경로는 `UploadDirectory` / `UploadFile`에서 별도로 전달됩니다.

## 일반적인 오류

- **경로를 역슬래시로 끝냄(Windows 습관)**: `SetSavePath`는 `Path.DirectorySeparatorChar`(플랫폼 기본 구분자)만 검사하므로, Windows의 `"a\\b\\"`처럼 입력하면 역슬래시가 그대로 유지됩니다. 슬래시(/)를 사용하거나 구분자를 포함하지 않는 형태로 통일하는 것을 권장합니다.
- **`Init`을 먼저 하지 않고 `SetSavePath`를 호출**: `SetSavePath` 자체는 `Init` 상태를 검증하지 않지만, 이후 업로드에는 유효한 자격 증명이 필요하므로 `Init`을 하지 않으면 업로드가 실패합니다. `Init` → 경로 설정 → 업로드 순서로 진행하세요.
- **호출 순서가 잘못됨**: `SetSavePath`는 반드시 `UploadDirectory` / `UploadFile` 이전에 호출해야 합니다; 그렇지 않으면 이미 진행 중인 업로드는 이전에 설정된 `BucketSavePath`(기본값 `string.Empty`)를 그대로 사용합니다.

## 배경(선택 사항)

`BucketSavePath`는 `BaseObjectStorageUploadManager`의 보호된 필드이며, 구체적인 구현 클래스(예: 각 클라우드 공급자 어댑터)에서 객체 Key의 접두사로 업로드 요청에拼接되므로, 본질적으로 "로컬 디스크 경로"가 아니라 "객체 키 접두사"입니다.
