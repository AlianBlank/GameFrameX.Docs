# AssetBundle 리소스 로드 실패 시 대처 방법

에디터 또는 런타임에서 `AssetBundle.LoadFromFile` / `LoadFromMemoryAsync` / `LoadAssetAsync` 호출이 `null`을 반환하거나 예외를 던지거나 잘못된 리소스를 로드할 때, 문제는 거의 "매니페스트 설정", "경로 및 플랫폼", "리소스 패키징" 세 가지 범주로 집중됩니다. 이 페이지에서는 증상에 따른 빠른 진단 표와 수정 단계를 제공합니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| `AssetBundle` 로드가 `null`을 반환하거나 `IOException` 발생 | 런타임에서 `.bundle` / `.ab` 파일을 찾을 수 없거나, 경로와 배포 플랫폼이 일치하지 않음 | [경로 및 플랫폼 불일치](#수정-단계) 참조 |
| 리소스는 로드되지만, `LoadAsset<T>`로 가져온 값이 기본 리소스이거나 텍스처가 보라색으로 표시됨 | 해당 리소스가 어떤 Bundle에도 수집되지 않았거나 참조가 손실됨 | [리소스가 수집되지 않음](#수정-단계) 참조 |
| 패키징 후 매니페스트와 런타임이 일치하지 않고 일부 리소스가 404 | `AssetBundleCollectorConfig.xml`이 저장되지 않았거나 최신 매니페스트가 생성되지 않음 | [매니페스트 및 빌드 설정](#수정-단계) 참조 |
| Android 실제 기기에서 WebRequest 로드 실패 | `UnityWebRequestAssetBundle` 모듈 누락 | [필수 모듈 누락](#수정-단계) 참조 |
| 에디터에서는 정상적으로 로드되지만 패키징 후 첫 시작 시 실패 | `StreamingAssets` 디렉토리가 패키지에 포함되지 않았거나 복사되지 않음 | [StreamingAssets 미배포](#수정-단계) 참조 |

## 수정 단계

### 경로 및 플랫폼 불일치

1. `Application.streamingAssetsPath`(읽기 전용 패키지 내부) 또는 `Application.persistentDataPath`(쓰기 가능한 다운로드 디렉토리) 아래에 `.bundle` 파일이 존재하고, 파일명이 런타임과 일치하는지 확인합니다.
2. 파일명은 `Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml`의 `PackRule`에 의해 결정되며, 로드 시 동일한 규칙으로 생성된 이름(플랫폼 접미사 포함, 예: `_android`, `_ios`, `_windows`)을 사용해야 합니다.

Source: [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L1-L40)

3. `AssetBundle.LoadFromFile(path)`를 호출하기 전에 먼저 `File.Exists(path)`로 검증하고, 파일이 없을 경우 `path`와 현재 `Application.platform`을 기록합니다.

### 리소스가 수집되지 않음

1. `Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml`을 열고, 대상 리소스가 있는 디렉토리가 `CollectPath`에 추가되어 있으며 `Filter` 규칙으로 필터링되지 않았는지 확인합니다.
2. 에디터 메뉴에서 Bundle 빌드를 한 번 실행하고, `Library/com.unity.addressables` 또는 사용자 지정 출력 디렉토리에서 리소스가 해당 `.bundle`에 나타나는지 확인합니다.
3. 다시 로드합니다.

### 매니페스트 및 빌드 설정

1. `AssetBundleCollectorConfig.xml`을 수정한 후, 먼저 `Save`를 한 다음 빌드합니다. 그렇지 않으면 런타임에서 이전 매니페스트를 가져옵니다.
2. `AssetBundleCollectorSetting.asset`은 ScriptableObject이므로 필드를 변경하려면 `Apply`를 클릭해야 합니다.

Source: [AssetBundleCollectorSetting.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorSetting.asset)

3. 빌드 산출물(`.bundle`, 매니페스트 파일, 버전 파일)을 전체적으로 대상 배포 디렉토리로 복사하고, 단일 파일만 덮어쓰지 않도록 합니다.

### 필수 모듈 누락

`Packages/manifest.json`에서 다음 모듈이 존재하는지 확인합니다:

```json
"com.unity.modules.assetbundle": "1.0.0",
"com.unity.modules.unitywebrequest": "1.0.0",
"com.unity.modules.unitywebrequestassetbundle": "1.0.0",
"com.unity.modules.unitywebrequestaudio": "1.0.0"
```

Source: [Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L47-L60)

`unitywebrequestassetbundle`이 누락되면 `UnityWebRequestAssetBundle.GetAssetBundle()`은 Android/iOS에서 `null`을 반환합니다.

### StreamingAssets 미배포

1. 리소스가 `Assets/StreamingAssets/`에 배치되면 Unity는 그대로 패키지에 포함하지만, `Assets/AssetBundleSetting/` 외부의 디렉토리에 있으면 자동으로 패키징되지 않습니다.
2. `Project Settings > Player > Other Settings`에서 대상 플랫폼의 `StreamingAssets`에 대상 `.bundle`이 포함되어 있는지 확인합니다.

## 검증

- 에디터 `Play Mode`에서 `LoadFromFile`을 사용하여 `assetBundle != null`까지 로드되는지 확인합니다.
- 실제 기기/에뮬레이터에서 첫 시작 후 로그에 `Loaded bundle:` 다음에 리소스 이름이 나타나고, `ArgumentException`이 없는지 확인합니다.
- 리소스 참조 카운트 / `LoadAsset<T>`가 기본값이 아닌 값을 반환하고 `Instantiate`가 성공하는지 확인합니다.

## 관련 링크

- AssetBundle 수집 설정에 대해서는 `Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml`을 참조하세요.
- 런타임 모듈 의존성에 대해서는 `Packages/manifest.json`을 참조하세요.
