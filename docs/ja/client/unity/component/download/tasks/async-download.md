# await を使って非同期でダウンロード完了を待機する

`DownloadComponent` は `Task<bool>` を返す `Download` メソッドを提供しており、コルーチンや非同期メソッド内で直接 `await` を使ってファイルのダウンロード完了を待機できます。イベントコールバックを購読する必要はありません。

## 前提条件

- シーンに `DownloadComponent` コンポーネントがアタッチされていること(`[GameFrameXAutoComponent(-4000)]` により自動登録)。
- ビジネスコードが `DownloadComponent` のインスタンスを取得できること。通常は `GameEntry.GetComponent<DownloadComponent>()` で取得します。

## 操作手順

1. `DownloadComponent.Download(downloadPath, downloadUri)` を呼び出し、`Task<bool>` を取得します。
2. `async` メソッド内でこのタスクを `await` します。値が `true` ならダウンロード成功、`false` なら失敗またはダウンロードが開始されなかったことを示します。
3. 戻り値に応じて後続のロジックを決定します(リソースの読み込み、エラーの表示など)。

最小構成のサンプル:

```csharp
using System.Threading.Tasks;
using GameFrameX.Download.Runtime;

public async Task LoadRemoteConfigAsync()
{
    var download = GameEntry.GetComponent<DownloadComponent>();
    bool ok = await download.Download(
        downloadPath: Application.persistentDataPath + "/config.json",
        downloadUri:  "https://example.com/config.json");

    if (ok)
    {
        // ローカルファイルを読み込んで後続のロジックを続行する
    }
    else
    {
        // ダウンロード失敗時のフォールバック処理
    }
}
```

## よくあるバリエーション

- タグや優先度を伴うバージョンは、引き続き従来の `AddDownload` フローを使用します。`Download` メソッドは現在最もよく使われる `(path, uri)` オーバーロードのみを公開しています。カスタムのタグや優先度が必要な場合は、引き続き `AddDownload` + イベント方式を使用できます。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `await` が永遠に返らず、値がずっと `false` のまま | ダウンロードタスクがまだダウンロードマネージャーに入っておらず、`m_Downloads.TryGetValue` が失敗して、既に `TrySetResult(false)` されたタスクがそのまま返されている | パスと URI が有効であることを確認し、`DownloadComponent` が `Start` 済みであることを確認する(`EventComponent` と `m_DownloadManager` に依存) |
| 呼び出し箇所で `NullReferenceException` が発生 | ビジネス側で `DownloadComponent` がシーンに存在しない、またはまだ Awake されていない | `GameEntry.GetComponent<DownloadComponent>()` で取得し、先に null チェックを行う |
| 複数タスクの並行実行時に、返された `Task` が互いに上書きされる | `Download` メソッドは `serialId` に基づいて内部ディクショナリから対応する `TaskCompletionSource<bool>` を検索する | 異なるダウンロードはそれぞれ独立した `await` 変数で受け取り、戻り値の混用を避ける |

## 背景(任意)

内部では `ConcurrentDictionary<int, DownloadData>` を使用して `serialId` から `TaskCompletionSource<bool>` へのマッピングを管理しています。`Awake` で `DownloadSuccess` / `DownloadFailure` イベントを購読し、コールバック内で `TrySetResult(true/false)` を呼び出すことで、イベント駆動型 API を `Task` API に変換しています。
