# Bot 클라이언트를 사용하여 통합 테스트 및 부하 테스트를 수행하는 방법

`GameFrameX.Client`는 독립 실행형 .NET 콘솔 프로그램으로, 다수의 봇 플레이어가 동시에 게임 서버에 접속하는 상황을 시뮬레이션하고 "계정 로그인 → 캐릭터 목록 → 캐릭터 생성/로그인"의 전체 흐름을 자동으로 완료합니다. `EnableDisconnectLoop`와 함께 사용하면 반복 재접속도 가능하며, 주로 통합 테스트 검증과 부하 테스트에 사용됩니다.

## 사전 조건

- 로그인 가능한 게임 서버 한 대(기본적으로 `127.0.0.1:49100`을 리스닝하는 TCP 게이트웨이를 가정).
- 활성화된 HTTP 로그인 게이트웨이(기본값 `http://127.0.0.1:48080/game/api/`, `BotRunOptions.LoginUrl`로 지정).
- .NET SDK 10 설치 완료(스크립트는 `dotnet run --framework net10.0`을 호출).
- 계정 비밀번호는 테스트 픽스처의 기본 비밀번호 `12312`(상수 `DefaultBotLoginSecret`)를 사용하며, 모든 봇이 공유하고 `--login-password`로 재정의할 수 있습니다.

## 작업 단계

1. **저장소 루트 디렉터리로 이동**(스크립트는 상대 경로를 통해 프로젝트 파일을 찾음):

   ```bash
   cd GameFrameX.Server.Source
   ```

2. **멀티 Bot 스크립트 직접 실행**(부하 테스트 진입점으로 권장되며, 기본값을 자동으로 설정하고 실행 파라미터를 출력함):

   ```bash
   bash scripts/multi/run-bots-rpc.sh
   ```

   스크립트 내부에서 최종적으로 `dotnet run`을 호출하며, 환경 변수를 명령줄 인수로 전달합니다.

   출처: [scripts/multi/run-bots-rpc.sh](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/scripts/multi/run-bots-rpc.sh#L1-L37)

3. **수동으로 `dotnet run` 실행**(통합 테스트 시 더 유연함):

   ```bash
   dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
     --bot-count=50 \
     --tcp-host=127.0.0.1 \
     --tcp-port=49100 \
     --login-url=http://127.0.0.1:48080/game/api/ \
     --scenario=login
   ```

   `--scenario`는 쉼표로 구분된 여러 시나리오 이름(예: `login,friend`)을 받으며, `BotRunOptions.HasScenario`가 활성화 여부를 판단합니다.

   출처: [GameFrameX.Client/Bot/BotRunOptions.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotRunOptions.cs#L31-L70)

4. **출력 로그 확인**: 각 봇이 로그인 흐름을 완료하면 `[METRICS] connect=… auth=… list=… create=… login=… total=…`(밀리초) 한 줄을 출력하여 각 단계별 소요 시간을 평가할 수 있습니다.

   출처: [GameFrameX.Client/Bot/BotClient.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotClient.cs#L184-L187)

## 명령줄 파라미터 빠른 참조

| 파라미터 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `--bot-count` | int | 50 | 동시에 시작되는 봇 수 |
| `--bot-prefix` | string | `BotClient` | 봇 이름 접두사, 번호는 `_1`부터 증가 |
| `--tcp-host` | string | `127.0.0.1` | 게임 서버 TCP 게이트웨이 주소 |
| `--tcp-port` | int | 49100 | 게임 서버 TCP 게이트웨이 포트 |
| `--login-url` | string | `http://127.0.0.1:48080/game/api/` | HTTP 로그인 게이트웨이 기본 주소, 끝의 `/` 자동 보완 |
| `--login-password` | string | `12312` | 모든 봇이 공유하는 로그인 비밀번호 |
| `--connect-stagger-ms` | int | 20 | 각 봇 시작 간격, 순간적인 연결 포화 방지 |
| `--disconnect-loop` | bool | true | 로그인 완료 후 자동 연결 끊기 루프 여부 |
| `--disconnect-after-login-seconds` | int | 15 | 로그인 성공 후 몇 초 후에 연결을 끊을지 |
| `--run-seconds` | int | 0 | 총 실행 시간, 0은 수동 중지 시까지 계속 실행을 의미 |
| `--scenario` | string | `login` | 활성화할 시나리오, 쉼표로 구분 |

## 일반적인 변형

- **소규모 통합 테스트(비즈니스 흐름 검증)**: 봇 수를 5~10개로 줄이고, `--run-seconds=60`, 연결 끊기 루프 비활성화 `--disconnect-loop=false`를 적용하여 로그를 육안으로 확인하기 쉽게 합니다.

  ```bash
  dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
    --bot-count=5 --run-seconds=60 --disconnect-loop=false
  ```

- **연결형 부하 테스트(게이트웨이 포화)**: 기본 연결 끊기 루프를 유지하고 stagger 간격을 5~10ms로 단축하여, 봇이 지속적으로 재접속하게 함으로써 게이트웨이 안정성을 검증합니다:

  ```bash
  bash scripts/multi/run-bots-rpc.sh
  # 기본값 BOT_COUNT=100, CONNECT_STAGGER_MS=10, RUN_SECONDS=180
  ```

- **사용자 정의 환경 부하 테스트**: 환경 변수를 통해 스크립트 기본 파라미터를 재정의합니다. 예를 들어 테스트 서버에 연결하여 300초 동안 실행:

  ```bash
  BOT_COUNT=200 RUN_SECONDS=300 TCP_HOST=10.0.0.5 TCP_PORT=49100 \
    bash scripts/multi/run-bots-rpc.sh
  ```

## 일반적인 오류

| 현상 | 원인 | 처리 |
|------|------|------|
| 봇 시작 직후 `EntryAsync Error: …` 발생 | TCP 게이트웨이에 접근할 수 없거나 포트가 사용 중 | `TcpHost`/`TcpPort` 확인, 게임 서버가 시작되어 리스닝 중인지 확인 |
| 로그에 `账号登录失败，错误码:非0` 반복 출력 | 로그인 게이트웨이가 활성화되지 않았거나 비밀번호 불일치 | `LoginUrl` 접근 가능 여부, `--login-password`가 서버 측 검증과 일치하는지 확인 |
| `[METRICS]`에 항상 필드 누락(예: `list=-1`) | 해당 단계에 진입하지 못함(계정 또는 선행 흐름 실패) | 이전 ERROR 로그를 따라 상위 실패 원인 파악 |
| 서버 측 연결 수가 빠르게 포화됨 | stagger 간격이 너무 짧거나 봇 수가 너무 많음 | `--connect-stagger-ms` 값을 늘리거나 `--bot-count` 값을 줄임 |

## 배경(선택)

`BotClient`는 내부적으로 `BotTcpClient`를 사용하여 게임 서버 TCP 게이트웨이로의 긴 연결 하나를 유지합니다. 연결이 설정되면 즉시 `ReqLogin`을 전송하고, 서버가 `RespLogin`을 반환하면 캐릭터 목록 요청이 트리거되며, 필요에 따라 `ReqPlayerCreate` / `ReqPlayerLogin`을 진행합니다. 로그인 성공 후 `EnableDisconnectLoop=true`인 경우 연결 끊기 및 재접속을 한 번 예약합니다. 모든 봇은 동일한 `BotRunOptions`(연결 주소, 포트, 비밀번호, 시나리오 스위치 등)를 공유하며, `BotRunOptions.Parse`를 통해 명령줄에서 재정의 값을 읽습니다. 지표는 `LogHelper.Info`를 통해 `[METRICS]` 접두사로 출력되어 스크립트 집계에 용이합니다.
