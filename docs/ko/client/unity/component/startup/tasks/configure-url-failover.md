# URL 기본-백업 failover 전략 구성 방법

`UrlFailoverRunner.ExecuteAsync`를 사용하면 URL 그룹이 순서대로 기본-백업 전환을 수행하고, 각 URL에 대해 최대 N번 재시도할 수 있습니다. 이 페이지에서는 바로 복사하여 실행할 수 있는 최소 사용법, 파라미터 의미, 그리고 흔히 겪는 함정을 소개합니다.

## 사전 조건

- 프로젝트에 `com.gameframex.unity.startup` 패키지가 설치되어 있고, `GameFrameX.Startup.Runtime` 네임스페이스를 참조하고 있어야 합니다.
- 비즈니스 측에서 `Func<string, UniTask<UrlAttemptResult>>` 대리자를 구현하여 단일 URL에 실제 요청(GET/POST 등)을 보내고, 응답에 따라 `UrlAttemptResult.Succeed()` 또는 `UrlAttemptResult.Fail(errorMessage)`를 반환해야 합니다.
- `Cysharp.Threading.Tasks`와 `UniTask` 비동기 메커니즘이 도입되어 있어야 합니다(`using Cysharp.Threading.Tasks;`).

## 작업 단계

1. **URL 목록 준비**. 후보 URL을 "기본—백업—백업…" 순서로 `IReadOnlyList<string>`에 넣고, 런타임에 배열 인덱스 순서대로 시도합니다.

2. **단일 URL 시도 대리자 구현**. 각 URL에 요청을 한 번 보내고, HTTP 상태 코드 또는 비즈니스 코드에 따라 성공 또는 실패 결과를 반환합니다.

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;
   using UnityEngine.Networking;

   UniTask<UrlAttemptResult> TryFetchAsync(string url)
   {
       return UniTask.RunOnThreadPool(async () =>
       {
           using var req = UnityWebRequest.Get(url);
           await req.SendWebRequest();
           if (req.result == UnityWebRequest.Result.Success)
           {
               return UrlAttemptResult.Succeed();
           }
           return UrlAttemptResult.Fail(req.error ?? "unknown error");
       });
   }
   ```

   출처: [UrlAttemptResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlAttemptResult.cs#L6-L27)

3. **`UrlFailoverRunner.ExecuteAsync` 호출**. URL 목록, 각 URL의 최대 시도 횟수, 재시도 간격(밀리초), 그리고 이전 단계의 대리자를 전달합니다.

   ```csharp
   using System.Collections.Generic;
   using System.Threading;
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   public async UniTask<UrlFailoverResult> RunAsync(CancellationToken ct = default)
   {
       var urls = new[] { "https://api-primary.example.com", "https://api-backup.example.com" };

       return await UrlFailoverRunner.ExecuteAsync(
           urls,
           maxAttemptsPerUrl: 3,
           retryDelayMs: 500,
           attempt: TryFetchAsync,
           onProgress: (url, attempt, total) =>
               UnityEngine.Debug.Log($"try {attempt}/{total} -> {url}"),
           cancellationToken: ct);
   }
   ```

   출처: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L14-L43)

4. **반환된 `UrlFailoverResult` 처리**. 성공 시 비즈니스 데이터를 사용하고, 실패 시 `FailedUrl`과 `ErrorMessage`를 기준으로 폴백(fallback) 로직을 수행할지 또는 트래킹 이벤트를 보고할지 결정합니다.

   ```csharp
   var result = await RunAsync(this.GetCancellationTokenOnDestroy());
   if (!result.Success)
   {
       UnityEngine.Debug.LogError($"all URLs failed. last={result.FailedUrl}, err={result.ErrorMessage}");
       return;
   }
   ```

   출처: [UrlFailoverResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverResult.cs#L6-L30)

## 일반적인 변형

- **동기식 작성법(단위 테스트에서 흔함)**. 대리자가 즉시 `UniTask.FromResult(...)`를 반환하도록 작성하여 대기할 필요가 없습니다.

  ```csharp
  var result = await UrlFailoverRunner.ExecuteAsync(
      new[] { "http://a", "http://b" },
      maxAttemptsPerUrl: 2,
      retryDelayMs: 0,
      attempt: url => UniTask.FromResult(
          url == "http://b" ? UrlAttemptResult.Succeed() : UrlAttemptResult.Fail("down")));
  ```

  출처: [UrlFailoverRunnerTests.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Tests/Runtime/UrlFailoverRunnerTests.cs#L63-L85)

- **재시도 없이 기본-백업 전환만 수행**. `maxAttemptsPerUrl`을 `1`로, `retryDelayMs`를 `0`으로 설정하면 "한 번 실패 시 즉시 다음 URL로 전환"되며 지연이 없습니다.

  ```csharp
  await UrlFailoverRunner.ExecuteAsync(urls, maxAttemptsPerUrl: 1, retryDelayMs: 0, attempt: TryFetchAsync);
  ```

  출처: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L68-L71)

- **진행률 콜백 사용**. `onProgress(url, attempt, total)`은 매 시도 전에 트리거되며, `attempt`는 `1`부터 카운트되므로 UI 진행률 표시줄을 구동하기에 적합합니다.

  출처: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L57-L57)

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 동기적으로 `ArgumentNullException` 발생, 파라미터 이름 `urls` | URL 목록에 `null`을 전달함 | `new string[0]`이 아닌 목록을 전달해야 함; 빈 배열은 `ArgumentException`을 발생시킴 |
| 동기적으로 `ArgumentException` 발생, 메시지 "URL list must contain at least one URL." | 빈 배열 `new string[0]`을 전달함 | 최소 1개의 URL을 포함해야 함 |
| 동기적으로 `ArgumentException` 발생, 메시지 "Max attempts per URL must be greater than zero." | `maxAttemptsPerUrl < 1` | URL당 시도 횟수를 ≥ 1로 설정 |
| 동기적으로 `ArgumentException` 발생, 메시지 "Retry delay must be zero or greater." | `retryDelayMs < 0` | `0` 또는 양의 정수로 설정 |
| 동기적으로 `ArgumentNullException` 발생, 파라미터 이름 `attempt` | 시도 대리자에 `null`을 전달함 | `attempt`에 유효한 `Func<string, UniTask<UrlAttemptResult>>`를 전달 |
| 모든 URL이 실패했을 때 비즈니스 측이 `result.Success == false`를 받지만 `FailedUrl`이 빈 문자열임 | 어떤 URL에서도 실패 경로가 호출된 적이 없거나(거의 발생하지 않음), 모든 실패가 무시됨 | 대리자 내에서 항상 `UrlAttemptResult.Fail(...)`을 반환하는지 확인 |

이러한 파라미터 제약 조건을 검증하는 구현은 `UrlFailoverRunner.ExecuteAsync`의 진입점에 위치합니다.

출처: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L14-L43)

## 배경(선택 사항)

`UrlFailoverRunner`는 "URL 순서 × URL당 시도 횟수"의 2중 루프로 실행되는 정적 유틸리티 클래스입니다. 외부 루프는 `urls`를 순회하고, 내부 루프는 단일 URL에 대해 전달된 `attempt` 대리자를 성공하거나 `maxAttemptsPerUrl`이 소진될 때까지 반복 호출합니다. 특정 URL이 성공하면 즉시 `UrlFailoverResult.Succeed()`를 반환하고 이후 URL은 시도하지 않습니다. 모든 URL의 모든 재시도가 실패한 경우에만 마지막으로 실패한 URL과 오류 정보를 포함하는 `UrlFailoverResult.Fail(...)`을 반환합니다. `retryDelayMs > 0`이면 동일한 URL의 두 번의 시도 사이에 `UniTask.Delay`로 대기하며, `maxAttemptsPerUrl == 1`이면 대기도 재시도도 하지 않습니다.
