# 安装与项目接入

本指南介绍如何把 GameFrameX Unity 核心包接入到一个 Unity 项目中，并在场景脚本里获取框架组件。完成后，你可以在 `GameManager` 中通过 `GameEntry.GetComponent<T>()` 拿到对象池、引用池等组件并直接使用扩展方法。

## 前置条件

| 项目 | 要求 |
|------|------|
| Unity 版本 | 2019.4 或更高([package.json](/package.json#L7)) |
| .NET 版本 | .NET Standard 2.0+ |
| 平台 | Windows / macOS / Linux / iOS / Android / WebGL |
| 项目类型 | Unity 标准工程（已生成 `Packages/manifest.json`） |

## 操作步骤

### 方式一：Unity Package Manager 图形界面（推荐）

1. 打开 Unity 编辑器，打开目标工程。
2. 顶部菜单选择 `Window` → `Package Manager`。
3. 点击左上角 `+` 按钮，选择 `Add package from git URL...`。
4. 在输入框中粘贴：`https://github.com/GameFrameX/com.gameframex.unity.git`
5. 点击 `Add`，等待 Unity 下载并完成导入。

Source: [README.zh-CN.md](/README.zh-CN.md#L353-L359)

### 方式二：手动下载 Release 包

1. 打开 [Releases 页面](https://github.com/GameFrameX/com.gameframex.unity/releases) 下载最新的 `.zip` 或 `.tar.gz`。
2. 把压缩包解压到 Unity 工程的根目录下的 `Packages/` 文件夹中。
3. 返回 Unity 编辑器，Unity 会自动识别并导入。

Source: [README.zh-CN.md](/README.zh-CN.md#L361-L364)

### 方式三：通过 scopedRegistries 引入（UPM）

编辑工程根目录的 `Packages/manifest.json`，加入 scoped registry 配置，再在 `dependencies` 中声明版本：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity": "1.10.1"
  }
}
```

`scopes` 控制通过此注册表解析的命名空间：只有以 `com.gameframex` 开头的包才会从 GameFrameX 注册表获取，其他依赖仍走 Unity 默认注册表。

Source: [README.zh-CN.md](/README.zh-CN.md#L366-L387)

### 验证安装

在任意 `MonoBehaviour` 的 `Start()` 里调用一次组件获取，能正常返回即表示接入成功：

```csharp
using GameFrameX.Runtime;

public class GameManager : MonoBehaviour
{
    void Start()
    {
        var objectPool = GameEntry.GetComponent<ObjectPoolComponent>();
        var referencePool = GameEntry.GetComponent<ReferencePoolComponent>();

        transform.SetPositionX(10f);
        gameObject.SetActiveOptimized(true);
    }
}
```

## 常见变体

| 场景 | 调整方式 |
|------|---------|
| 锁定到具体版本 | 在 `manifest.json` 的 `dependencies` 中将 `"com.gameframex.unity"` 写为精确版本号，例如 `"1.10.1"`，避免跟随 Git URL 的 HEAD。 |
| 接入国内/海外小游戏平台 | 保留 Editor 模块下的 MiniGame 工具与 `BuildProduct` 管线，不要在 iOS/Android 之外的平台把它们排除。 |
| 内网/离线环境 | 优先使用方式二，把 Release 包拷贝到内网再解压到 `Packages/`。 |
| 需要 LiteJSON | 无需额外安装，框架在 `dependencies` 中已声明 `com.gameframex.unity.litjson: 1.2.0` 作为传递依赖。 |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| UPM 添加 Git URL 后报 `Unable to find package` | URL 写错或网络无法访问 GitHub | 核对 URL 为 `https://github.com/GameFrameX/com.gameframex.unity.git`，或在 `scopedRegistries` 方式中把 `scopes` 设为 `com.gameframex` |
| 通过 UPM 解析不到对应版本 | 没有添加 `scopedRegistries`，或 `scopes` 拼错 | 按方式三补全 `scopedRegistries`，确认 `scopes` 是 `["com.gameframex"]` |
| `GameEntry.GetComponent<...>()` 报空引用 | 场景中没有挂载框架入口预制体，或入口组件未启用 | 在场景里加上框架启动组件后再调用，详见《快速上手》 |
| 编译报缺 LitJSON | 删除依赖或版本冲突 | 重新引入框架或单独恢复 `com.gameframex.unity.litjson: 1.2.0` |
| Unity 版本低于 2019.4 | 框架最低支持版本不符 | 升级 Unity 至 2019.4 或更高([package.json](/package.json#L7)) |

## 背景（可选）

`com.gameframex.unity` 是 GameFrameX 框架的核心包，通过 UPM 同时声明了运行时依赖（`com.gameframex.unity.litjson`）以及若干 Unity 内置模块（`assetbundle`、`audio`、`jsonserialize`、`unitywebrequest`、`androidjni`、`animation`、`imgui`）。Unity 2019.4+ 是 `package.json` 中明确要求的最低版本；不满足时 UPM 会拒绝解析依赖。
