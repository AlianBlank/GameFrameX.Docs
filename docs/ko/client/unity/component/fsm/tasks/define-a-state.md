# 상태 정의 방법

GameFrameX FSM에서 상태는 추상 기본 클래스 `FsmState<T>`를 상속하여 구현합니다. `T`는 상태 머신의 소유자 타입이며, 상속 후 생명주기 콜백을 재정의하면 상태 정의가 완료됩니다.

## 사전 조건

- `GameFrameX.Fsm.Runtime` 어셈블리를 이미引入했으며, Unity 프로젝트에서 직접 참조할 수 있습니다.
- 소유자 타입 `T`(반드시 `class`)가 이미 존재하여 이후 상태 머신을 생성하는 데 사용됩니다.

## 작업 단계

1. **상태 머신 소유자 타입 결정**

   예컨대 캐릭터 컨트롤러 `Player`를 제네릭 매개변수 `T`로 사용합니다.

2. **`FsmState<T>` 상속 및 필요한 콜백 구현**

   `FsmState<T>`는 추상 기본 클래스로, `OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy`의 6개 생명주기 훅을 제공하며, 모두 `protected internal virtual`이므로 필요에 따라 재정의하면 됩니다.

   ```csharp
   using GameFrameX.Fsm.Runtime;

   public class IdleState : FsmState<Player>
   {
       protected internal override void OnEnter(IFsm<Player> fsm)
       {
           // 대기 상태 진입 시 로직
       }

       protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           // 매 프레임 폴링 로직
       }

       protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
       {
           // 대기 상태 이탈 시 로직
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L41-L108)

3. **상태 내부에서 상태 전환 트리거**

   기본 클래스에서 제공하는 `ChangeState<TState>(IFsm<T> fsm)`을 통해 다른 상태로 전환합니다:

   ```csharp
   protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
   {
       if (/* 트리거 조건 */)
       {
           ChangeState<RunState>(fsm);
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

4. **상태를 상태 머신에 추가**

   상태 머신을 생성할 때 `CreateFsm<T>`의 `params FsmState<T>[]` 매개변수를 통해 전달하거나, 생성 후 `AddState`를 호출하여 동적으로 추가합니다:

   ```csharp
   var fsm = FsmComponent.Instance.CreateFsm(player, new IdleState(), new RunState());
   // 또는
   fsm.AddState(new RunState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L205-L220)

## 생명주기 콜백 요약

| 콜백 | 트리거 시점 | 일반적인 용도 |
|------|---------|---------|
| `OnInit(IFsm<T> fsm)` | 상태가 상태 머신에 처음 추가될 때 | 내부 데이터 초기화 |
| `OnEnter(IFsm<T> fsm)` | 해당 상태로 진입할 때 | 애니메이션 재생, 플래그 설정 |
| `OnUpdate(IFsm<T> fsm, float, float)` | 매 프레임 폴링 | 전환 조건 감지 |
| `OnFixedUpdate(IFsm<T> fsm, float, float)` | 고정 시간 스텝 폴링 | 물리 관련 로직 |
| `OnLeave(IFsm<T> fsm, bool isShutdown)` | 해당 상태를 이탈할 때 | 상태 정리, 플래그 복원; `isShutdown`은 상태 머신 종료로 인한 트리거 여부를 나타냄 |
| `OnDestroy(IFsm<T> fsm)` | 상태가 파괴될 때 | 리소스 해제 |

## 일반적인 변형

- **빈 상태 셸**: 자리 표시나 그룹화 용도로만 사용하는 경우, 아래 테스트 케이스와 같이 어떤 메서드도 재정의하지 않을 수 있습니다:

  ```csharp
  private class TestIdleState : FsmState<object>
  {
  }
  ```

  Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L128-L130)

- **타입별 상태 전환**: 제네릭 `ChangeState<TState>` 외에도, 기본 클래스에서는 `ChangeState(IFsm<T>, Type)` 오버로드를 제공하여 외부 설정에 따라 동적으로 전환하는 데 적합합니다:

  ```csharp
  ChangeState(fsm, typeof(RunState));
  ```

  Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

## 일반적인 오류

- **동일한 타입의 상태 중복 추가**: 상태 머신은 타입을 키로 상태를 저장하므로, 동일한 타입을 중복해서 `AddState`하면 `GameFrameworkException`이 발생합니다.
- **상태 전환 시 잘못된 타입 전달**: `ChangeState(fsm, stateType)`은 `stateType`이 반드시 `FsmState<T>`에서 파생되어야 함을 검증하며, 그렇지 않을 경우 `GameFrameworkException("State type '...' is invalid.")`이 발생합니다.
- **`ChangeState` 직접 호출 시 `fsm`이 이미 무효화된 경우**: 기본 클래스에서 `GameFrameworkException("FSM is invalid.")`을 발생시킵니다.

## 배경(선택 사항)

`FsmState<T>` 추상 클래스는 훅과 상태 전환 기능만 노출하며, 어떤 런타임 데이터도 보유하지 않습니다 — 상태 간 공유되는 모든 데이터는 `IFsm<T>`의 `GetData` / `SetData`를 통해 접근합니다. 이를 통해 상태 구현을 가볍고 테스트하기 쉽게 유지할 수 있습니다.
