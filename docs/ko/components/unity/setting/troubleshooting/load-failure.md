# 설정 로드 실패 시 대처법

`SettingComponent.Start()`에서 `m_SettingManager.Load()`가 `false`를 반환하면 콘솔에 `Load settings failure.`이 출력되며, 이는 설정 로드 프로세스가 실패했음을 나타냅니다. 이 페이지는 실패 원인을 빠르게 파악하고 수정할 수 있도록 도와줍니다.

## 빠른 진단

| 증상 (원본 로그) | 원인 | 해결 방법 |
|------|------|------|
| `Setting manager is invalid.` | `ISettingManager` 모듈이 등록되지 않았거나 GameFramework가 시작되지 않음 | [모듈 미등록](#모듈-미등록-setting-manager-is-invalid) 참조 |
| `Can not create setting helper.` | `SettingHelper`의 타입 이름 설정 오류, 어셈블리가 런타임에 포함되지 않음, 또는 커스텀 Helper 클래스를 찾을 수 없음 | [Helper 생성 실패](#helper-생성-실패-can-not-create-setting-helper) 참조 |
| `Load settings failure.` | `ISettingHelper.Load()` 구현이 `false` 반환 (읽기 / 역직렬화 실패) | [Load 구현이 false 반환](#load-구현이-false-반환-load-settings-failure) 참조 |
| `Setting helper is invalid.` 예외 | `Load()` / `Save()` 호출 전에 `SetSettingHelper()`를 호출하지 않음 | [Helper 미설정 예외 발생](#helper-미설정-예외-발생-setting-helper-is-invalid) 참조 |
| 플랫폼 미니게임 저장소에 데이터 없음 | PlayerPrefs / 미니게임 저장소 백엔드가 비어 있어 로드할 내용 없음 | [저장소 백엔드 비어있음](#저장소-백엔드-비어있음) 참조 |

## 모듈 미등록 (Setting manager is invalid)

`SettingComponent.Awake()`는 `GameFrameworkEntry.GetModule<ISettingManager>()`를 통해 매니저를 가져옵니다. `null`이 반환되면 `Setting manager is invalid.`를 출력하고 바로 return하며, 이후 `Start()`에서 Load가 다시 호출되지 않습니다.

해결 단계:

1. 씬에 `GameFrameX.Runtime.GameFrameworkEntry`(또는 동등한 시작 컴포넌트)가 존재하는지 확인합니다. 프레임워크 진입점은 반드시 `SettingComponent`보다 먼저 시작되어야 합니다.
2. `SettingManager` 모듈이 프레임워크의 어셈블리 목록에 포함되어 있는지 확인합니다 (`Runtime/Setting/Setting/SettingManager.cs`에 위치하며 네임스페이스는 `GameFrameX.Setting.Runtime`). 패키지 외부로 빠져 있지 않아야 합니다.
3. 커스텀 GameFramework 시작 프로세스를 사용하는 경우 `SettingManager`를 시작 모듈 목록에 추가해야 합니다.

## Helper 생성 실패 (Can not create setting helper)

`SettingComponent.Awake()`에서 `Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper)`를 호출합니다. `null`이 반환되면 `Can not create setting helper.`를 출력합니다.

```csharp
// 출처: Runtime/Setting/SettingComponent.cs#L87-L92
SettingHelperBase settingHelper = Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper);
if (settingHelper == null)
{
    Log.Error("Can not create setting helper.");
    return;
}
```

해결 단계:

1. Inspector에서 `SettingComponent`의 `Setting Helper Type Name`을 확인합니다. 기본값은 `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`입니다.
2. 커스텀 Helper를 사용하는 경우, 커스텀 클래스가 `SettingHelperBase`를 상속하는지(`Runtime/Setting/SettingHelperBase.cs#L43`), 타입 전체 이름(네임스페이스 포함)의 철자가 정확한지 확인합니다.
3. 커스텀 Helper가 포함된 어셈블리가 Player / 미니게임의 런타임 빌드에 포함되어 있고, 제거되지 않았는지 확인합니다.
4. `m_CustomSettingHelper` 필드 주입을 사용하는 경우 Inspector에 드래그하여 할당하고, 씬에 `SettingComponent`가 하나만 존재하는지 확인합니다.

## Load 구현이 false 반환 (Load settings failure)

Helper 생성은 성공했지만 `Load()` 내부에서 실패하면 `SettingComponent.Start()`에서 `Load settings failure.`를 출력합니다:

```csharp
// 출처: Runtime/Setting/SettingComponent.cs#L102-L108
private void Start()
{
    if (!m_SettingManager.Load())
    {
        Log.Error("Load settings failure.");
    }
}
```

`SettingManager.Load()`는 내부적으로 현재 Helper에만 위임합니다:

```csharp
// 출처: Runtime/Setting/Setting/SettingManager.cs#L145-L150
public bool Load()
{
    EnsureSettingHelper();
    return m_SettingHelper.Load();
}
```

Helper 타입별로 처리합니다:

- **PlayerPrefsSettingHelper**: `Load()`는 항상 `true`를 반환합니다([출처](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L86-L89)). 이 오류가 표시되면 먼저 실제로 적용된 Helper 클래스가 커스텀 구현이 아닌지 확인하세요.
- **커스텀 Helper**: `Load()`에서 파일 존재 여부, 읽기 권한, 역직렬화 예외를 하나씩 점검하세요. 실패 단계를 확인할 수 있도록 상세 로그 추가를 권장합니다.
- **미니게임 플랫폼 Helper**(WeChat / DouYin / KuaiShou / Alipay): `SettingStorageBackendFactory.Create()`를 통해 `ISettingStorageBackend`를 가져오며, 대상 플랫폼 매크로가 정의되어 있고 해당 SDK가 올바르게 통합되었는지 확인하세요.

## Helper 미설정 예외 발생 (Setting helper is invalid)

`SettingManager`에서 `SetSettingHelper()`를 호출하지 않은 상태에서 `Load()` / `Save()` / `GetAllSettingNames()`를 호출하면 `GameFrameworkException("Setting helper is invalid.")`이 발생합니다:

```csharp
// 출처: Runtime/Setting/Setting/SettingManager.cs#L130
throw new GameFrameworkException("Setting helper is invalid.");
```

이는 `SettingComponent`를 우회하고 직접 `SettingManager`를 new한 경우에만 발생할 수 있습니다. 해결 방법: 먼저 `SetSettingHelper(yourHelper)`를 호출한 뒤 `Load()`를 호출하거나, `SettingComponent`를 직접 사용하세요. `SettingComponent`는 `Awake()`에서 자동으로 주입합니다.

## 저장소 백엔드 비어있음

`PlayerPrefsSettingHelper`는 `SettingStorageBackendFactory.Create()`를 통해 `ISettingStorageBackend`를 지연 로드합니다. 팩토리가 `null`을 반환하거나 플랫폼 SDK가 초기화되지 않은 경우, `GetString` / `SetString` 등의 인터페이스 호출이 예외를 발생시키고, 이는 `Load()` / `Save()`를 통해 `false`로 전파됩니다.

해결 단계:

1. 해당 플랫폼 매크로가 활성화되어 있는지 확인합니다 (`UNITY_WEBGL`, 미니게임 플랫폼 매크로 등).
2. 플랫폼 SDK가 `Awake()` / `Start()` 이전에 초기화되었는지 확인합니다.
3. `PlayerPrefsSettingHelper` 이전에 테스트용 `ISettingStorageBackend`를 주입합니다. `SetStorageBackendForTests(...)`의 사용법을 참고하세요.

## 검증

수정 완료 후 다음 순서로 검증합니다:

1. 게임을 시작했을 때 콘솔에 `Load settings failure.` 또는 위에서 언급한 오류 로그가 더 이상 표시되지 않는지 확인합니다.
2. `SettingComponent.GetAllSettingNames()` 호출이 정상적으로 반환되는지 확인합니다 (PlayerPrefs 구현은 항상 빈 배열을 반환하며 이는 정상입니다).
3. `SettingComponent.Save()` 호출 후 게임을 재시작하고, `HasSetting(name)` / `GetString(name)` 호출 시 이전에 작성한 값을 읽어올 수 있는지 확인합니다.
4. 여전히 예외가 발생하면 전체 스택 정보를 보존하고, 문제가 `SettingHelperBase`에서 파생된 구체적인 클래스에 있지 않은지 확인하세요.
