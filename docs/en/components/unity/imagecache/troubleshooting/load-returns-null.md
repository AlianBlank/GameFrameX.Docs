# What to Do When Image Loading Returns `null`

When `LoadImageAsync` returns `null`, the image has failed to load. Below are common causes, troubleshooting methods, and fix steps organized by symptom.

## Quick Diagnosis

| Symptom (log text) | Cause | Fix |
|--------------------|-------|-----|
| `ImageCache: url is null or empty.` | The passed URL is an empty string or `null` | Check the URL before calling, pass a valid address |
| `ImageCache: url must start with http:// or https://. url: {0}` | The URL does not start with `http://` or `https://` | Correct the URL protocol scheme |
| `ImageCache: download failed. url: {0}` | Remote server unreachable, 404, or network restricted | Check the network and address, see "Download Failure" below |
| `Download manager is invalid.` (fatal log at startup) | The `IDownloadManager` module is not installed | Register the `Download` component |
| `ImageCache manager is invalid.` (fatal log at startup) | The component is not registered with `GameFrameworkEntry` | Add the component following the framework process |
| No logs at all and returns `null` | Cache file is corrupted / `Texture2D.LoadImage` failed | Clear the cache and retry, see below |

## Fix Steps

### Invalid URL

`LoadImageAsync` returns `null` directly when the URL is empty or does not start with `http(s)://`, and prints the corresponding warning log.

```csharp
// Incorrect usage
await component.LoadImageAsync(null);                 // empty
await component.LoadImageAsync("ftp://example.com/a.png"); // wrong protocol
await component.LoadImageAsync("/local/path/a.png");   // local path is invalid

// Correct usage
await component.LoadImageAsync("https://example.com/a.png");
```

### Missing Module at Startup

`ImageCacheComponent.Awake` obtains `IImageCacheManager` and `IDownloadManager`. If either is missing, it writes a `Fatal` log and returns early, causing all subsequent loads to return `null`.

```csharp
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
// ...
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
```

Fix:

1. Add the `ImageCache` component under the `GameFramework` node in the scene (menu `GameFrameX/Image Cache`).
2. Also add the `Download` component, and make sure the `Download Component` field points to the concrete class implementing `IDownloadManager`.
3. Restart the scene and confirm the above `Fatal` logs no longer appear in the console.

Source: [ImageCacheComponent.cs#L37-L65](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L37-L65)

### Download Failure

On non-WebGL platforms, when the disk cache misses, `IDownloadManager.AddDownload` is called. A download failure triggers the `DownloadFailure` event; the method writes `ImageCache: download failed. url: {0}` and returns `null`.

```csharp
private async Task<Texture2D> LoadImageDiskCacheAsync(string url, CancellationToken cancellationToken)
{
    // ...
    var downloadSuccess = await tcs.Task;
    if (!downloadSuccess)
    {
        Log.Warning("ImageCache: download failed. url: {0}", url);
        return null;
    }
    // ...
}
```

Troubleshooting order:

1. Access the URL directly with a browser or `curl` to confirm it returns 200 and image bytes.
2. Check runtime sandbox permissions (iOS ATS, Android network permission, WebGL CORS).
3. The WebGL platform has no disk cache; the browser fetches directly with `UnityWebRequestTexture.GetTexture`. On failure, the log is `ImageCache: download failed. url: {0}, error: {1}`—prioritize checking CORS and HTTPS configuration.
4. If it was downloaded before but fails again, call `RemoveCache(url)` and retry.

Source: [ImageCacheManager.cs#L97-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L97-L171)

### Cache File Corruption / Decode Failure

When the download succeeds but subsequent reading or decoding fails, the method silently returns `null` without a dedicated warning log.

```csharp
var buffer = FileHelper.ReadAllBytes(cachePath);
if (buffer == null || buffer.Length == 0)
{
    return null;
}

var texture = new Texture2D(1, 1, TextureFormat.RGBA32, false, false);
if (!texture.LoadImage(buffer))
{
    Object.Destroy(texture);
    return null;
}
```

Fix:

1. Call `RemoveCache(url)` or `ClearCache()` to clear the local cache and reload.
2. Confirm `CachePath` is writable in the Inspector and the disk is not full (old files may be removed when `MaxDiskSize` triggers eviction).
3. Confirm the remote response is actually PNG / JPG bytes, not an HTML error page.

Source: [ImageCacheManager.cs#L152-L171](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L152-L171)

### Cancellation Token Triggered

When the `CancellationToken` passed by the caller is triggered, the method also returns `null` and does not write a failure log.

```csharp
if (cancellationToken.IsCancellationRequested)
{
    return null;
}
```

After `await`, be sure to check `cancellationToken.IsCancellationRequested` again to avoid treating "cancelled" as "load failed".

Source: [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149)

## Verification

1. No more `ImageCache: ...` warnings or `Fatal` logs in the console.
2. `LoadImageAsync` returns a non-null `Texture2D` that can be bound to UI / `Sprite` and display normally.
3. On the second load, no network request is triggered in the console, and you can see cache files named with the URL's MD5 under `Config.CachePath`.
