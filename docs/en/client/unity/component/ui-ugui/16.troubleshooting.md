# Troubleshooting

This document summarizes common issues and their solutions that may be encountered when using the GameFrameX UGUI plugin.

## Overview

When using the GameFrameX UGUI plugin for Unity UI development, developers may encounter issues in areas such as dependency configuration, code generation, and UI lifecycle management. This document aims to help developers quickly locate and resolve these issues, improving development efficiency.

## Dependency Issues

### Dependency Package Not Installed Correctly

**Problem Description:**
Compilation errors showing missing namespaces such as `GameFrameX.UI.Runtime`, `GameFrameX.Asset.Runtime`, or errors like `The type or namespace name 'GameFrameX' could not be found`.

**Cause Analysis:**
GameFrameX core dependency packages are not installed correctly.

**Solution:**

Ensure all dependencies are correctly configured in `manifest.json`:

```json
{
  "dependencies": {
    "com.gameframex.unity": "1.1.1",
    "com.gameframex.unity.ui": "1.0.0",
    "com.gameframex.unity.asset": "1.0.6",
    "com.gameframex.unity.event": "1.0.0",
    "com.gameframex.unity.ui.ugui": "https://github.com/gameframex/com.gameframex.unity.ui.ugui.git"
  }
}
```
> Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/package.json#L21-L26)

**Notes:**
- It is recommended to add packages through Unity Package Manager using Git URL method
- Ensure all dependency package versions are compatible
- Restart Unity Editor after installation to ensure assemblies are loaded correctly

## Code Generator Issues

### Code Generator Menu Item Not Displaying

**Problem Description:**
The "Generate UGUI Code" option does not appear in the Unity Editor right-click menu.

**Cause Analysis:**
Possible reasons include:
1. Plugin not installed correctly
2. Editor scripts not compiled
3. Current selected object is not a prefab

**Solution:**

1. Ensure the plugin package is installed correctly
2. Trigger assembly recompilation in Unity (any script save operation)
3. Ensure a valid UGUI prefab object is selected

---

### Code Generation Failed - Please select a valid UGUI prefab

**Problem Description:**
Error message "Please select a valid UGUI prefab" appears when clicking code generation menu.

**Cause Analysis:**
The selected object is not a prefab (Prefab), or prefab type detection failed.

**Solution:**

1. Ensure the selected object is a saved prefab asset (Prefab Asset), not an instance in the scene
2. Select the prefab in the Project window, then execute: `GameObject/UI/Generate UGUI Code`

> Source: [UGUICodeGenerator.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UGUICodeGenerator.cs#L56-L73)

---

### Cannot Find Generated Code File After Code Generation

**Problem Description:**
Code generation succeeded but cannot find the generated file, or the file was generated in the wrong location.

**Cause Analysis:**
The code generator determines the generation location based on prefab path:
- If the path contains `Resources`, code is generated to `Assets/Scripts/Game/UGUI/`
- Otherwise, generated to `Assets/Hotfix/UI/UGUI/`

**Solution:**

Check the output log during code generation to confirm the file generation path. If you need to modify the generation path, refer to the path logic in the code generator:

> Source: [UGUICodeGenerator.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UGUICodeGenerator.cs#L117-L127)

## UI Manager Issues

### UI Form Cannot Open - Resources.Load Failed

**Problem Description:**
UI form opening failed, with log showing `Resources.Load failed for path: xxx`.

**Cause Analysis:**
- Prefab path configuration error
- Prefab not placed in Resources directory
- Resource name does not match type name

**Solution:**

1. Ensure UI prefab is placed in the correct path
2. Check resource path logic in `UIManager.Open.cs`:

> Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L131-L163)

3. Ensure prefab name matches the type name used when opening:
```csharp
var uiFormAssetName = uiFormType.Name;
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);
```

---

### UI Form Opened Successfully But Displayed Incorrectly

**Problem Description:**
UI form opened but form content is not displayed correctly or layout is distorted.

**Cause Analysis:**
- RectTransform configuration incorrect
- `MakeFullScreen()` method not called correctly
- Parent container Canvas setting issue

**Solution:**

1. Ensure UGUI base class correctly calls the full-screen method:
```csharp
protected override void MakeFullScreen()
{
    gameObject?.GetOrAddComponent<RectTransform>()?.MakeFullScreen();
}
```
> Source: [UGUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUI.cs#L175-L178)

2. Check prefab's RectTransform anchor settings

## UGUI Base Class Issues

### Lifecycle Methods Not Executing After Inheriting UGUI

**Problem Description:**
`OnInit`, `OnOpen`, `OnClose` and other methods were overridden but not executed.

**Cause Analysis:**
Base class methods not called correctly.

**Solution:**

Ensure to call base class methods in each lifecycle method:

```csharp
public class MainMenuUI : UGUI
{
    protected override void OnInit(object userData)
    {
        base.OnInit(userData);  // Must call
        // Initialize UI logic
    }

    protected override void OnOpen(object userData)
    {
        base.OnOpen(userData);  // Must call
        // Logic when UI opens
    }

    protected override void OnClose(bool isShutdown, object userData)
    {
        base.OnClose(isShutdown, userData);  // Must call
        // Logic when UI closes
    }
}
```
> Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/README.md#L78-L101)

---

### UI Visibility Control Not Working

**Problem Description:**
Form display state did not change after setting `Visible = true/false`.

**Cause Analysis:**
State checking logic in the `InternalSetVisible` method may be preventing state updates.

**Solution:**

Check visibility control implementation in `UGUI.cs`:

> Source: [UGUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUI.cs#L99-L107)

Ensure `gameObject` is not null:
```csharp
protected override void InternalSetVisible(bool value)
{
    if (gameObject.activeSelf == value)
    {
        return;
    }
    gameObject.SetActive(value);
}
```

**Solution:**

## UIImage Component Issues

### Image Not Displaying After Setting Icon

**Problem Description:**
Image is not displayed after using the `UIImage` component to set the `icon` property.

**Cause Analysis:**
- Resource path error
- Resource loading failed
- AssetComponent not initialized correctly

**Solution:**

1. Check if the resource path is correct
2. Check if there are loading error messages in the log
3. Ensure AssetComponent is initialized correctly:

```csharp
public static async Task SetIconAsync(this UnityEngine.UI.Image self, string icon)
{
    try
    {
        var assetComponent = GameEntry.GetComponent<AssetComponent>();
        using (var valueHandle = await assetComponent.LoadAssetAsync<Texture2D>(icon))
        {
            if (valueHandle.IsDone && valueHandle.Status == EOperationStatus.Succeed)
            {
                var texture2D = valueHandle.GetAssetObject<Texture2D>();
                self.sprite = Sprite.Create(texture2D, new Rect(0, 0, texture2D.width, texture2D.height), new Vector2(0.5f, 0.5f));
            }
        }
    }
    catch (System.Exception e)
    {
        Log.Error($"Failed to load icon '{icon}': {e.Message}");
    }
}
```
> Source: [UGUIImageExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIImageExtension.cs#L56-L74)

**Notes:**
- UIImage uses asynchronous loading; the Sprite will be set via callback after loading succeeds
- If loading fails, error log will be output to Console

---

### Performance Issues from Repeatedly Setting Icon

**Problem Description:**
Setting the `icon` property frequently leads to performance degradation or resource leaks.

**Cause Analysis:**
Each setting triggers asynchronous loading, without considering resource caching and release.

**Solution:**

Check if the value has changed before setting:

```csharp
public string icon
{
    get { return m_icon; }
    set
    {
        if (m_icon != value)  // Only load when value changes
        {
            m_icon = value;
            _ = this.SetIconAsync(m_icon);
        }
    }
}
```
> Source: [UIImage.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIImage.cs#L60-L71)

## Resource Loading Issues

### YooAsset Resource Loading Failed

**Problem Description:**
UI prefab loading failed when using YooAsset, with error indicating resource does not exist.

**Cause Analysis:**
- Resource not added to YooAsset asset package
- Resource path incorrect
- Asset package not built correctly

**Solution:**

1. Ensure UI prefab has been added to YooAsset resource system
2. Check if the resource path matches the path in YooAsset
3. Confirm asset package has been built and deployed correctly
4. Check error information in `LoadAssetFailureCallback`:

## Editor Tool Issues

### Component Inspector Not Displaying

**Problem Description:**
Custom Inspector panel not displayed or displayed abnormally after selecting UGUI prefab.

**Cause Analysis:**
- Editor script not compiled
- Inspector script not attached correctly

**Solution:**

1. Ensure Editor script has no compilation errors
2. Try restarting Unity Editor
3. Check if `UGUIComponentInspector.cs` is implemented correctly

---

### Image Replace Handler Not Working

**Problem Description:**
Image in the prefab was not replaced as expected after using the image replace function.

**Cause Analysis:**
- Replace handler configuration issue
- Selected object incorrect

**Solution:**

1. Ensure the correct prefab or scene object is selected
2. Execute replace operation through menu `GameObject/UI/Replace Image`
3. Check `UIImageReplaceHandler.cs` implementation logic

## Debug Tips

### Enable Debug Logging

During development, you can view detailed logs through the following methods:

1. **Unity Console Window**: View all `Debug.Log` outputs
2. **UI Manager Logs**: Operations in UIManager will output logs
3. **Resource Loading Logs**: View YooAsset resource loading status

### Common Error Code Reference

| Error Message | Possible Cause | Solution |
|---------|---------|---------|
| `Resources.Load failed` | Resource path error or resource does not exist | Check prefab path configuration |
| `Can not create UI form` | UIFormHelper creation failed | Check UGUI component attachment |
| `Load UI form failure` | YooAsset loading failed | Check asset package configuration |
| `Open UI form info is invalid` | Opening info is null or already released | Check lifecycle management |
