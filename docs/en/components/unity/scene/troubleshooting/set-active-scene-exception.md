# What to Do When SetActiveScene Throws ArgumentException

When calling `SetActiveScene`, if the passed `Scene` hasn't been fully loaded by Unity yet, Unity will throw an `ArgumentException`. This framework has already caught and gracefully degraded the exception internally (only logging a `Warning`), but subscribers or custom code may still encounter the same root cause. Below are the steps to diagnose and fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Log shows `SetActiveScene failed (will be retried by Unity internally): Scene ... is not loaded.` | `SetActiveScene` was called while `Scene.isLoaded` was still `false` (typical scenario: YooAsset's `await` completes earlier than Unity's actual load completion) | Wait until the scene is truly `isLoaded == true` before activating, see "Waiting for isLoaded" below |
| The cached `m_GameFrameworkScene` handle is being activated, but that scene has been unloaded by Unity | After the first Single load, the framework scene is unloaded, and the cached handle's `IsValid()` returns `false` | Re-fetch the handle via `GetSceneByName` and then activate, see "Invalid Handle" below |
| Console throws `ArgumentException: SceneManager.SetActiveScene ... is not loaded` | Custom code calls directly on `SceneManager`, bypassing the framework's try/catch | Use the framework entry point or add your own guard, see "Bypassing the Framework with Direct Calls" below |
| During consecutive scene switches, old and new coroutines race for `SetActiveScene` | The previous refresh coroutine wasn't stopped before a new one started | `StopCoroutine` before starting a new coroutine, see "Coroutine Conflicts" below |

## Fix Steps

### Waiting for isLoaded

The framework has already wrapped `ArgumentException` in a try/catch at `SceneComponent.SetActiveScene`, but you may still encounter it in your own callback after listening to the `LoadSceneSuccess` event. Confirm that the target scene is `isLoaded` before setting it:

```csharp
var scene = UnityEngine.SceneManagement.SceneManager.GetSceneByName(sceneName);
if (scene.IsValid() && scene.isLoaded)
{
    UnityEngine.SceneManagement.SceneManager.SetActiveScene(scene);
}
```

If it's not `isLoaded` in the current frame, use a coroutine to delay to the next frame and retry, until timeout falls back to the framework scene—refer to the `RefreshSceneOrderWhenLoadedCo` implementation at [SceneComponent.cs#L480-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L480-L509).

### Invalid Handle

Cached `Scene` handles will be unloaded by Unity along with the old scene in `Single` mode. The framework defends against this with `IsValid()` at [SceneComponent.cs#L449-L457](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L449-L457):

```csharp
if (!activeScene.IsValid())
{
    // Skip setting when the handle is expired; Unity itself will activate it once the new Single scene finishes loading
    RefreshMainCamera();
    return;
}
```

When reusing a `Scene` handle in your own code, verify `IsValid()` before calling; otherwise, you need to call `GetSceneByName` again.

### Bypassing the Framework with Direct Calls

Do not call `UnityEngine.SceneManagement.SceneManager.SetActiveScene` directly in subscriber callbacks, as this bypasses the framework's exception swallowing logic. Prefer using the framework entry point such as `GameSceneComponent.SetActiveScene`; if you must switch the active scene inside an event callback, wrap it in your own try/catch and follow the "Waiting for isLoaded" check above.

### Coroutine Conflicts

When switching scenes consecutively multiple times, if you don't stop the previous refresh coroutine first, the old and new coroutines will race for `SetActiveScene` in the same frame, triggering `ArgumentException`. See the framework's fix pattern at [SceneComponent.cs#L430-L435](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L430-L435):

```csharp
if (m_RefreshSceneOrderCo != null)
{
    StopCoroutine(m_RefreshSceneOrderCo);
    m_RefreshSceneOrderCo = null;
}
m_RefreshSceneOrderCo = StartCoroutine(RefreshSceneOrderWhenLoadedCo(maxSceneName));
```

Remember to set the handle to `null` in the `finally` block (see [SceneComponent.cs#L505-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L505-L509)) to prevent the next `RefreshSceneOrder` from incorrectly assuming the old coroutine is still running.

## Verification

- `ArgumentException: SceneManager.SetActiveScene ... is not loaded` no longer appears in the logs.
- `SceneManager.GetActiveScene()` equals the target scene when the load callback returns.
- Triggering two consecutive scene switches produces no `SetActiveScene failed` warnings in the console.
