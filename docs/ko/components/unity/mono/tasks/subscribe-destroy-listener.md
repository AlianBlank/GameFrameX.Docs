# OnDestroy 리스닝 방법

`MonoComponent.AddDestroyListener(Action)` 를 통해 콜백을 등록하면, `MonoComponent` 가 부착된 `GameObject` 가销毁될 때 알림을 받을 수 있으므로, 직접 `MonoBehaviour` 를 상속하여 `OnDestroy()` 를 재정의할 필요가 없습니다.

## 사전 조건

- `MonoComponent` 가 부착된 `GameObject` 가 씬에 존재해야 합니다 (컴포넌트 메뉴: `GameFrameX/Mono`).
- 프레임워크가 `IMonoManager` 와 `EventComponent` 를 초기화해야 합니다 (둘 다 `MonoComponent.Awake()` / `Start()` 에서 자동으로 획득).

## 작업 단계

1. 销毁를 리스닝해야 하는 스크립트에서 `MonoComponent` 참조를持有합니다 (`GetComponent` 또는 `FindObjectOfType` 사용).
2. `AddDestroyListener` 를 호출하고, 매개변수가 없는 `Action` 델리게이트를 전달합니다.
3. 컴포넌트를承载하는 `GameObject` 가 销毁되면, `MonoComponent.OnDestroy()` 가 `_monoManager.OnDestroy()` 를 호출하고, 이는 등록한 콜백을触发합니다.

```csharp
using System;
using GameFrameX.Mono.Runtime;
using UnityEngine;

public class DestroyWatcher : MonoBehaviour
{
    private MonoComponent _monoComponent;

    private void Awake()
    {
        _monoComponent = GetComponent<MonoComponent>();
    }

    private void OnEnable()
    {
        if (_monoComponent != null)
        {
            _monoComponent.AddDestroyListener(OnMonoDestroyed);
        }
    }

    private void OnDisable()
    {
        if (_monoComponent != null)
        {
            _monoComponent.RemoveDestroyListener(OnMonoDestroyed);
        }
    }

    private void OnMonoDestroyed()
    {
        Debug.Log("MonoComponent가 파괴되었습니다");
    }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L97-L105)

리스닝 제거에 대응하는 메서드:

```csharp
public void RemoveDestroyListener(Action fun)
```

등록할 때와 **동일한 델리게이트 인스턴스** 를 전달하면 바인딩이 해제됩니다; `null` 을 전달하면 `fun is invalid.` 치명적 로그가 기록되고 바로 반환됩니다.

## 일반적인 변형

- **수동 `Destroy(gameObject)`**: `MonoComponent` 를承载하는 `GameObject` 가 销毁되면 콜백이 触发됩니다 — `Destroy` 호출인지 씬 언로드인지를 구분하지 않습니다.
- **씬 전환 언로드**: 씬 전환으로 인해 `MonoComponent` 가 销毁될 때도同样하게 触发되며, 씬 간 캐시를 정리하는 데 사용할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 등록 시 `fun is invalid.` 가 출력됨 | 전달된 `Action` 이 `null` 임 | 메서드 그룹 또는 lambda를 전달하여 null이 아님을 보장 |
| 销毁 시 콜백이 触发되지 않음 | `_monoManager` 가 `null` 임 (컴포넌트의 `Awake` 가 매니저 준비보다 빠름) | `MonoComponent` 가 정상적인 흐름으로 초기화되었는지, 그리고 `Awake` 가 비활성화되지 않았는지 확인 |
| 동일한 콜백이 여러 번 触发됨 | 동일한 델리게이트로 `AddDestroyListener` 를 여러 번 호출함 | `OnEnable`/`OnDisable` 페어로 생명주기를 관리하거나, 중복 등록 전에 먼저 제거 |

## 배경 (선택 사항)

`MonoComponent.OnDestroy()` 는 Unity의 네이티브 생명주기 훅이며, 프레임워크는 여기서 销毁 이벤트를 `IMonoManager` 에 전달합니다. 따라서 비즈니스 측은 각 클래스가 각각 `MonoBehaviour` 를 상속하는 대신, 일반 이벤트를 구독하는 것처럼 销毁를 구독할 수 있습니다.
