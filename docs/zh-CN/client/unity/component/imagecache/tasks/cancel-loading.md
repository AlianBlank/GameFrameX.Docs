# 如何取消进行中的图片加载

通过 `CancellationToken` 取消加载任务即可让 `LoadImageAsync` 在合适的时机中止后续处理并返回 `null`；取消机制只在非 WebGL 平台生效，下载过程中不会立即打断网络请求。

## 前置条件

- 已通过 `GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>()` 取得图片缓存组件。
- 目标编译平台非 WebGL（WebGL 下 `cancellationToken` 会被忽略，见下文「常见错误」）。

## 操作步骤

1. **创建可取消的令牌源**。使用 `CancellationTokenSource` 生成令牌，并通过 `Token` 属性传给加载接口。

   ```csharp
   using System.Threading;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   var component = GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>();
   var cts = new CancellationTokenSource();
   ```

2. **发起加载并传入令牌**。调用 `LoadImageAsync(url, cts.Token)`，得到 `Task<Texture2D>`。

   ```csharp
   var task = component.LoadImageAsync("https://example.com/foo.png", cts.Token);
   ```

3. **在合适的时机调用 `Cancel()`**。当页面关闭、列表项被回收等情况下触发取消：

   ```csharp
   cts.Cancel();
   ```

4. **处理返回结果**。被取消的任务会返回 `null`（不抛异常），按失败分支走即可：

   ```csharp
   var tex = await task; // 已取消时返回 null
   if (tex == null) return;
   ```

   Source: [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## 常见变体

- **关联 `MonoBehaviour` 生命周期自动取消**：把 `CancellationTokenSource` 与 GameObject 生命周期绑定（例如自定义 `MonoBehaviour` 在 `OnDestroy` 中调用 `cts.Cancel()`），切换场景时无需手动管理。
- **超时取消**：`cts.CancelAfter(TimeSpan.FromSeconds(5))` 设置超时自动取消。
- **按条件取消多个任务**：用同一个 `CancellationTokenSource` 给一组 `LoadImageAsync` 调用共用令牌，统一一次 `Cancel()` 全部中止。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| WebGL 平台调用 `Cancel()` 后任务仍然完成 | `LoadImageAsync` 在 `#if UNITY_WEBGL` 分支不接收 `cancellationToken`，见 [ImageCacheManager.cs#L84-L85](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L85) | WebGL 下需要自行通过业务层标志位丢弃返回的 Texture2D |
| 取消后下载仍在后台跑、磁盘上出现缓存文件 | 当前实现只在下载**成功完成后**检查令牌，不会中断进行中的下载，见 [ImageCacheManager.cs#L139-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L139-L149) | 若需彻底停止请求，请在取消前通过 `_downloadManager` 主动移除任务，或在业务层忽略下载结果 |
| `Cancel()` 后 await 任务报 `OperationCanceledException` | 本接口不使用 `ThrowIfCancellationRequested`，被取消统一返回 `null`，见 [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149) | 用 `if (tex == null)` 判断取消，不要捕获 `OperationCanceledException` |

## 验证

取消成功后，满足以下两条即为正常：

- `await LoadImageAsync(...)` 返回 `null`。
- 没有抛出 `OperationCanceledException`，也没有后续的图片解码日志（因为在检查到取消后直接 `return null`）。

## 背景（可选）

非 WebGL 分支的 `LoadImageDiskCacheAsync` 仅在「下载完成 → 准备读取本地文件」之间检查一次 `IsCancellationRequested`，因此取消的实际语义是「下载结束后放弃本次结果」，并非打断网络请求。WebGL 平台由于通过 `UnityWebRequestTexture` + 浏览器缓存实现，方法签名未暴露令牌，调用方只能在拿到结果后自行决定是否使用。

关于整体架构与下载管理器接入方式，见《概述》。
