# 微信通知未送达怎么办

构建完成后没有收到企业微信机器人通知,通常是因为没有传 `WeChatBotKey`、机器人未开启、或者构建流程没有走到 `IsUpdateAssetPackageVersion` 成功分支。修复前先按下面的诊断表对照实际现象。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台看到 `System.Net.Http.HttpRequestException` 或超时异常 | 网络无法访问 `qyapi.weixin.qq.com`,或代理阻挡 | 检查构建机网络/代理,确认能访问 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send` |
| 微信群完全没有任何消息 | 命令行未传 `-WeChatBotKey`,`BuilderOptions.WeChatBotKey` 为空字符串 | 构建命令加上 `-WeChatBotKey <机器人Key>`(注意大小写) |
| 收到 `{"errcode":40001,...}` 或 `errcode":40014` | 机器人 Key 错误或已失效 | 重新复制企业微信群机器人的 Webhook Key |
| 收到 `{"errcode":45009,...}` | 消息频率超出企业微信机器人限制(20 条/分钟) | 降低构建频次或拆分多个机器人 |
| 通知从未被调用,日志里也没有 `Debug.Log(response)` | `IsUpdateAssetPackageVersion` 为 false 或更新资源版本失败 | 同时传 `-IsUpdateAssetPackageVersion true` 并保证 `BuilderUpdateAssetPackageVersionHelper.Run` 返回 `true` |
| Unity Console 只打印 `Debug.LogException(e)` 没有响应体 | 抛出异常被 `catch (Exception e)` 吞掉 | 见下文"修复步骤 - 查看被吞掉的异常" |

## 修复步骤

### 1. 确认命令行传入了 `-WeChatBotKey`

`BuilderOptions.WeChatBotKey` 默认值为空字符串,只有命令行带上 `-WeChatBotKey` 时才会被赋值。

```csharp
else if (commandLineArg == "-WeChatBotKey")
{
    if (index + 1 < commandLineArgs.Length)
    {
        _builderOptions.WeChatBotKey = commandLineArgs[index + 1];
    }
}
```

构建命令示例(Unity 命令行):

```bash
-gameframex.builder -WeChatBotKey xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx -IsUpdateAssetPackageVersion true
```

参数说明见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L117)。

### 2. 确认构建走到了通知分支

通知只在"更新资源版本成功"后才会发送,所以单独传 `WeChatBotKey` 没有用。

```csharp
if (_builderOptions.IsUpdateAssetPackageVersion)
{
    var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
    if (result)
    {
        WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
    }
}
```

同时传两个开关:

```bash
-IsUpdateAssetPackageVersion true -WeChatBotKey <key>
```

若 `BuilderUpdateAssetPackageVersionHelper.Run` 返回 false,通知不会触发,需先排查版本更新失败原因。

### 3. 验证 Webhook Key 是否有效

Key 错误时企业微信会返回 `errcode:40001`(secret 错误)或 `40014`(非法 Key)。可以直接 `curl` 测试:

```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<你的Key>' \
  -H 'Content-Type: application/json' \
  -d '{"msgtype":"text","text":{"content":"hello"}}'
```

返回 `errcode: 0` 即正常,否则重新在企业微信群中添加机器人获取新 Key。

### 4. 查看被吞掉的异常

`WeChatNotifyWorkHelper.Run` 把所有异常都捕获并通过 `Debug.LogException` 记录,如果只看到异常堆栈说明 HTTP 调用本身失败(网络/DNS/超时)。

```csharp
try
{
    var httpResponseMessage = httpClient.PostAsync(url, stringContent).GetAwaiter().GetResult();
    var response = httpResponseMessage.Content.ReadAsStringAsync().GetAwaiter().GetResult();
    Debug.Log(response);
}
catch (Exception e)
{
    Debug.LogException(e);
}
```

处理方向:`httpClient.Timeout` 是 30 秒,可在内网环境适当调长;HTTPS 证书由系统信任链处理,如构建机使用了自签名代理则需要额外配置 `HttpClientHandler`。

### 5. 确认 Newtonsoft.Json 引用存在

CHANGELOG 中专门提到过 `WeChatNotifyWorkHelper` 缺失 `Newtonsoft.Json` 引用的问题。如果编译报 `The type or namespace name 'Newtonsoft' could not be found`,在 `Editor/GameFrameX.Builder.Editor.asmdef`(或对应程序集定义)里加上 `Newtonsoft.Json` 引用即可。

```text
* **builder:** 补充 WeChatNotifyWorkHelper 缺失的 Newtonsoft.Json 引用
```

## 验证

1. 重新执行构建,确认 Unity Console 同时打印 `Debug.Log(response)` 与正常的 JSON 响应体(包含 `errcode: 0`)。
2. 在企业微信群里看到一条 `### 游戏资源版本更新` 的 markdown 通知,内容包含时间、资源版本、游戏版本等字段。
