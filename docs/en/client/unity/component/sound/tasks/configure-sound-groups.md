# How to Configure Sound Groups (BGM / SFX / Voice)

This page describes how to configure sound groups (SoundGroup) in the GameFrameX sound system. Once complete, you can create three types of sound groups—BGM, SFX, and Voice—on `SoundComponent`, and set volume, mute, priority, and concurrent playback limits for each group.

## Prerequisites

- The `com.gameframex.unity.sound` package is installed, and a GameObject with the [SoundComponent](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs) attached exists in the scene.
- You are familiar with the basic sound playback workflow (see the related task page on playing sounds).

## Steps

1. **Locate `SoundComponent` in the scene**. Sound groups are configured directly in the Inspector as its serialized fields.

2. **Expand the `SoundGroups` list in the Inspector**. Each entry corresponds to a sound group. The serializable fields of `SoundGroup` are as follows:

| Field | Type | Default | Purpose |
|------|------|------|------|
| `m_Name` | `string` | `null` | Unique identifier of the sound group, e.g. `BGM`, `SFX`, `Voice`; `GetSoundGroup` uses this name for lookup |
| `m_AvoidBeingReplacedBySamePriority` | `bool` | `false` | Whether sounds of the same priority avoid being replaced |
| `m_Mute` | `bool` | `false` | Whether to mute the group as a whole (runtime changes automatically refresh all agents) |
| `m_Volume` | `float` (`Range 0f-1f`) | `1f` | Group volume |
| `m_AgentHelperCount` | `int` | `1` | Number of concurrent playback agents for this group (how many sounds can play simultaneously) |

   Source: [SoundComponent.SoundGroup.cs#L44-L70](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.SoundGroup.cs#L44-L70)

3. **Add the three sound groups by purpose**. Example of a minimal working configuration:

| Name | Mute | Volume | AgentHelperCount | AvoidBeingReplacedBySamePriority |
|------|------|--------|------------------|-----------------------------------|
| `BGM` | `false` | `0.8` | `2` | `true` (background music tracks do not interrupt each other) |
| `SFX` | `false` | `1.0` | `8` | `false` (same-priority sounds can replace each other) |
| `Voice` | `false` | `1.0` | `1` | `true` (dialogue lines do not interrupt each other) |

4. **Access and adjust by name at runtime**. Sound groups are implemented as `ISoundGroup` at runtime, and mute/volume can be changed at any time:

```csharp
using GameFrameX.Sound.Runtime;

// Get the configured SFX group
ISoundGroup sfx = GameEntry.Sound.GetSoundGroup("SFX");

// Toggle mute
sfx.Mute = true;

// Adjust the volume of the whole group (refreshes all SoundAgents in sync)
sfx.Volume = 0.5f;
```

   Source: [SoundManager.SoundGroup.cs#L99-L129](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.SoundGroup.cs#L99-L129)

5. **Set priority and replacement policy for the group**. `ISoundGroup.AvoidBeingReplacedBySamePriority` controls the replacement behavior of same-priority sounds. When enabled, same-priority play requests are ignored (returning `PlaySoundErrorCode.IgnoredDueToLowPriority`); it is commonly used for BGM and Voice:

```csharp
// Make BGM same-priority sounds not replace each other
GameEntry.Sound.GetSoundGroup("BGM").AvoidBeingReplacedBySamePriority = true;
```

   Source: [SoundManager.SoundGroup.cs#L194-L207](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.SoundGroup.cs#L194-L207)

6. **Verify**. After running the scene, check the logs via `SoundComponent` in the Inspector or call `GameEntry.Sound.HasSoundGroup("BGM")` in code to confirm the group has been registered successfully.

## Common Variants

- **Dynamically adding groups at runtime**: Use `SoundManager.AddSoundGroup(name, soundGroupHelper, agentHelperCount)` to add a group on the fly, e.g. dynamically adding a `UI` group for interface sound effects.
- **Centralized initialization in code**: Write a `SoundConfigInitializer` script that calls `AddSoundGroup` in `Awake` instead of configuring in the Inspector, making it easy to share the same set of groups across multiple scenes.
- **Tuning for different game types**: For bullet-hell/STG games, an SFX `AgentHelperCount = 16+` is recommended; puzzle/narrative games do not need that many.

## Common Mistakes

- **Misspelled group name**: `GetSoundGroup("bgm")` will not match the configured `BGM` and returns `null`; if the group cannot be found, go back to the Inspector and check `m_Name`.
- **Setting `m_AgentHelperCount` to 0**: This causes all play requests for that group to be ignored because no free agent can be found; it is recommended to set it to at least 1.
- **Accidentally enabling `m_AvoidBeingReplacedBySamePriority`**: Once enabled, same-priority requests are discarded; if you want "same-priority round-robin replacement", keep the default `false`.
- **Passing an empty name or null helper during construction**: If `name` is empty or `soundGroupHelper` is `null` when constructing `SoundGroup`, it throws `GameFrameworkException("Sound group name is invalid.")` or `"Sound group helper is invalid."`.
  Source: [SoundManager.SoundGroup.cs#L57-L67](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.SoundGroup.cs#L57-L67)

## Background (Optional)

`soundGroup` is the "sound category management" abstraction of the GameFrameX framework: each group has a number of `SoundAgent` instances attached (the concurrency limit is determined by `AgentHelperCount`), and when `Mute/Volume` is toggled at the group level, all agents' `RefreshMute`/`RefreshVolume` are called so the change takes effect immediately. When a play request arrives, `SoundGroup.PlaySound` selects an agent within the group by "idle → higher priority → earliest among same priority".
