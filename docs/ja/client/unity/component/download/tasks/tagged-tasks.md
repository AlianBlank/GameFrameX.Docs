# Tag ラベルによるダウンロードタスクのグループ管理

`AddDownload` に `tag` 文字列を渡すことで、同じ種類のダウンロードタスクを1つのグループにまとめ、`GetDownloadInfos(tag)` を使ってそのグループ内のすべてのタスクの状態を一度に取得できます。このページでは、タスクへの Tag の付け方、Tag による照会方法、およびよくあるエラーについて説明します。

## 前提条件

- `com.gameframex.unity.download` パッケージがインストール済みで、シーンに `DownloadComponent` がアタッチされていること。
- `DownloadComponent` の参照を取得済みであること。例:`GameEntry.GetComponent<DownloadComponent>()`。
- `AddDownload` の基本的な呼び出し方法を理解していること(コンポーネントの `AddDownload(string, string)` オーバーロードを参照)。

## 操作手順

### 1. ダウンロードタスクに Tag を付ける

`tag` パラメータ付きの `AddDownload` オーバーロードを呼び出します。Tag は通常の文字列で、その意味は自分で定義します。例:`"asset-bundle"`、`"lua-3.2.0"`、`"res-avatar"`。

```csharp
// tag のみ指定。デフォルト優先度と null userData を使用
int id1 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/a.png",
    downloadUri:  "https://example.com/a.png",
    tag:          "asset-bundle");

// tag + 優先度を指定
int id2 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/b.png",
    downloadUri:  "https://example.com/b.png",
    tag:          "asset-bundle",
    priority:     10);

// tag + 優先度 + userData を指定(完全版)
int id3 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/c.png",
    downloadUri:  "https://example.com/c.png",
    tag:          "asset-bundle",
    priority:     10,
    userData:     myCallback);
```

### 2. Tag でグループ内のすべてのタスクを一括照会

`GetDownloadInfos(string tag)` でそのグループ内の `TaskInfo[]` を取得するか、`GetDownloadInfos(string tag, List<TaskInfo> results)` で既存のリストを再利用して GC を回避します。

```csharp
// TaskInfo[] を返す
TaskInfo[] infos = downloadComponent.GetDownloadInfos("asset-bundle");
foreach (var info in infos)
{
    Debug.Log($"tag={info.Tag} status={info.Status} progress={info.Progress}");
}

// List を再利用し、毎フレームの新規配列割り当てを回避
var buffer = new List<TaskInfo>();
downloadComponent.GetDownloadInfos("asset-bundle", buffer);
```

### 3. Tag ごとに進捗を集計

Tag を「バッチ」という次元として扱い、UI 上でバッチ全体の進捗を表示します:

```csharp
void Update()
{
    var infos = downloadComponent.GetDownloadInfos("asset-bundle");
    if (infos.Length == 0) return;

    long downloaded = 0, total = 0;
    foreach (var info in infos)
    {
        downloaded += info.DownloadedLength;
        total      += info.TotalLength;
    }
    progressBar.value = total > 0 ? (float)downloaded / total : 0f;
}
```

> `TaskInfo` のフィールド(`Status`、`Progress`、`DownloadedLength`、`TotalLength`、`Tag`、`SerialId` など)は、`DownloadManager` によってタスクのライフサイクル中に更新されます。

### 4. Editor Inspector で Tag を確認する

`DownloadComponent` の Inspector を開くと、"Download Infos" リスト内に `Tag` 列が直接表示され、タスクが意図したグループに振り分けられているかどうかを確認できます。

## よくあるバリエーション

| シナリオ | 使用方法 |
|------|------|
| 同じリソースのバッチで優先度が異なる | 同じ `tag`、異なる `priority` を使用。まとめて照会し、個別にスケジューリング可能 |
| リソースのバージョン番号を Tag にする | 例:`tag = "v1.2.3"`。バージョン単位でバッチ全体をアップグレードしやすい |
| バッチ全体のタスクをキャンセル | `TaskInfo[]` から `SerialId` を取り出し、1つずつ `RemoveDownload(serialId)` を呼び出す |
| コールバックコンテキストを持たせる | `userData` パラメータでコールバックをタスクに付随させる。Tag は引き続き業務分類として使用 |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GetDownloadInfos(tag)` が常に空を返す | タスク追加時に Tag を渡していない、または Tag 文字列が一致しない(大文字・小文字、スペース) | `AddDownload` で `tag` 付きのオーバーロードを使用していることを確認し、Tag を定数として保存する |
| 同じファイルに複数の Tag が付けられ重複ダウンロードされる | 異なる Tag は独立したタスクであり、フレームワークは自動的に重複を除去しない | グローバル辞書で `downloadUri` による重複チェックを行うか、同じ Tag に固定する |
| `AddDownload` の呼び出しで `Download path is invalid.` / `Download uri is invalid.` がスローされる | `downloadPath` または `downloadUri` が空文字列または null | 呼び出し前に null チェックを行う。Tag はこれら2つのパラメータの検証には影響しない |

## 背景(オプション)

`DownloadTask` 内部では Tag は `TaskBase.Tag`(文字列フィールド)として保存され、`m_TaskPool` が Tag ごとにタスクのコレクションを管理します。`GetDownloadInfos(tag)` は実際には `m_TaskPool.GetTaskInfos(tag)` に委譲されます。Tag は「グループ化 + 照会」にのみ使用され、ダウンロードの優先度、同時実行数、失敗時の再試行ポリシーには影響しません。これらの動作は `priority` と `DownloadComponent` のグローバルパラメータによって決まります。Source: [DownloadTask.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs)
