# シリアライズ可能なオブジェクト設定のアクセス

`SettingComponent` の `GetObject<T>` と `SetObject<T>` インターフェースを使用して、`[Serializable]` マーク付きの任意のオブジェクトを単一の文字列キーとしてゲーム設定ストレージに読み書きします。

## 前提条件

- プロジェクトに `GameFrameXSettingCroppingHelper` と `SettingComponent` がアタッチされていること(後者は `[RequireComponent]` で前者を自動的に要求します)。
- 保存する型に `[System.Serializable]` マークが付いていること。フィールドは `UnityEngine.JsonUtility` によってシリアライズされます。
- `GameFrameworkEntry.GetModule<ISettingManager>()` でマネージャーインスタンスを取得するか、`SettingComponent.Awake()` の完了後にストレージ API を呼び出してください。

## 操作手順

1. **シリアライズ可能な設定クラスを定義する**。型には `[Serializable]` を付け、フィールドは `public` または `[SerializeField]` 付きである必要があります:

   ```csharp
   using System;
   using UnityEngine;

   [Serializable]
   public class PlayerProfile
   {
       public string playerId;
       public int level;
       public bool vip;
       public Vector3 lastPosition;
   }
   ```

2. **設定マネージャーを取得する**。コンポーネントの初期化完了後、コンポーネントインスタンスから直接アクセスします:

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingComponent = UnityEngine.Object.FindObjectOfType<SettingComponent>();
   ISettingManager settingManager = settingComponent.GetComponent<SettingComponent>() != null
       ? GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>()
       : null;
   ```

   コンポーネントへの参照をキャッシュしておき、必要時に `settingComponent` 上の `ISettingManager` モジュールを直接読み取ることもできます。

3. **オブジェクトを書き込む**。`SetObject<T>(string settingName, T value)` を呼び出すと、フレームワーク内部で `JsonUtility.ToJson` によって文字列に変換され、基幹ストレージに書き込まれます:

   ```csharp
   var profile = new PlayerProfile
   {
       playerId = "p-1001",
       level = 12,
       vip = true,
       lastPosition = new Vector3(1.5f, 0f, -3.2f),
   };

   settingManager.SetObject("profile.current", profile);
   settingManager.Save();
   ```

   Source: [SettingManager.cs#L300-L320](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L300-L320)

4. **オブジェクトを読み取る**。`GetObject<T>(string settingName)` で取得します。キーが存在しない場合は `null` を返します(デフォルト値付きのオーバーロード `GetObject<T>(string settingName, T defaultValue)` は、欠落時にデフォルト値を返します):

   ```csharp
   if (settingManager.HasSetting("profile.current"))
   {
       PlayerProfile loaded = settingManager.GetObject<PlayerProfile>("profile.current");
       Debug.Log($"おかえりなさい,{loaded.playerId},レベル {loaded.level}");
   }
   ```

5. **削除とクリア**。オブジェクトと基本型は同じストレージを共有します:

   ```csharp
   settingManager.RemoveSetting("profile.current");  // 単一のキーを削除
   settingManager.RemoveAllSettings();                // すべてクリア
   ```

## よくあるバリエーション

| シナリオ | 使い方 | 説明 |
|------|------|------|
| デフォルト値でのフォールバック | `GetObject<PlayerProfile>("profile.current", defaultProfile)` | キーが存在しない場合、渡されたデフォルト値のオブジェクトを返す |
| すべてのキーの列挙 | `string[] keys = settingManager.GetAllSettingNames();` | デバッグ時に保存済みのオブジェクト名をすばやく特定 |
| ミニゲームプラットフォーム横断 | `WeChatMiniGameSettingStorage` などのプラットフォーム実装を使用 | `SettingStorageBackendFactory` でバックエンドを切り替え、API は一貫性を保つ |
| 複雑なネスト | `[Serializable] class Wrapper { public PlayerProfile profile; public Settings settings; }` | `JsonUtility` はネストされた `[Serializable]` 型をサポートするが、辞書/インターフェースはサポートしない |

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | `SettingComponent.Awake()` の前に `GetObject`/`SetObject` を呼び出した | コンポーネントの初期化完了を待つか、読み書きロジックを業務モジュールの `Start`/`Awake` 段階に配置する |
| `GameFrameworkException: Setting name is invalid.` | 渡された `settingName` が `null` または空文字列 | 呼び出し前に `string.IsNullOrEmpty` チェックを行う |
| 読み出したフィールドがすべてデフォルト値になる | フィールドが `private` で `[SerializeField]` が付いていない | フィールドに `[SerializeField]` を付けるか、`public` に変更する |
| 辞書/インターフェースメンバーが失われる | `JsonUtility` は `Dictionary`、インターフェース、プロパティをサポートしない | `List<T>` またはカスタム シリアライズ可能なラッパークラスを使用する |
| 変更がディスクに保存されない | 書き込み後に `Save()` を呼び忘れた | 書き込み完了後に `settingManager.Save()` を呼び出す;フレームワークは `Shutdown` 時に自動的に `Save` する |

## 背景(オプション)

`SettingManager` はオブジェクトと基本型を基幹の `ISettingHelper` に統一的にマッピングし、後者は文字列を `JsonUtility.ToJson` でシリアライズしてから `ISettingStorageBackend`(デフォルトは `UnityPlayerPrefsSettingStorage`)に永続化を委譲します。読み込み時は逆順に `JsonUtility.FromJson<T>` で復元するため、`JsonUtility` で処理できるオブジェクトのみがアクセス可能です。基幹ストレージバックエンドの切り替えについては、《カスタム設定ストレージバックエンド》を参照してください。
