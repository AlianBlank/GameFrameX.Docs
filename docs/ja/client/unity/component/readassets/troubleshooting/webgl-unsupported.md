# WebGL プラットフォームが利用できない場合の対処法

`com.gameframex.unity.readassets` には WebGL プラットフォーム専用の実装分岐がなく、Unity WebGL のランタイムサンドボックスはローカルディスクや APK のように StreamingAssets 内のファイルを同期的に直接開くことができないため、本フレームワークは WebGL プラットフォームで**サポートされていません**。Build Target を WebGL に切り替えた後に `BlankReadAssets` の任意の API を呼び出した場合、エディタまたはランタイムで機能不足や読み込み失敗が発生します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| Build Target を WebGL に切り替えた後、コンパイル時に "WebGL is not supported" 関連の警告が出る、または WebGL ビルドで StreamingAssets ファイルが読み込めない | フレームワークは `UNITY_EDITOR`、`UNITY_ANDROID` 専用の実装分岐のみを提供しており、WebGL とその他のプラットフォームは `LooseFilesImpl` を共有しているが、WebGL サンドボックスは同期 `File` I/O をサポートしていない | 下記の修正手順に従って代替手段に切り替える |
| `BlankReadAssets.ReadAllBytes / FileExists / LoadAssetBundle` を呼び出した後、空が返されるか `FileNotFoundException` がスローされる | WebGL では `LooseFilesImpl` は `Application.streamingAssetsPath` 経由となるが、`AssetBundle.LoadFromFile` は WebGL では `UnityWebRequest` に変更する必要がある | Unity WebGL のネイティブインターフェースに置き換える(手順 2 を参照) |
| ビジネスロジックで WebGL と Android の両方をサポートする必要があるため、`if (Application.platform == RuntimePlatform.WebGLPlayer)` で直接判定している | フレームワークは WebGL 専用の読み込みパスを提供していない | WebGL 分岐は個別に UnityWebRequest を呼び出し、その他のプラットフォームは引き続き `BlankReadAssets` を使用する(手順 3 を参照) |

## 修正手順

### 1. WebGL Build で UnityWebRequest を使用する

WebGL プラットフォームでのファイルアクセスは必ず `UnityWebRequest` 経由で行う必要があります。これは Unity 公式が WebGL バックエンドで唯一サポートしているアセット読み込み方式です:

```csharp
using UnityEngine;
using UnityEngine.Networking;

public static class WebGLReadAssetsFallback
{
    public static UnityWebRequest ReadAllBytes(string relativePath)
    {
        // StreamingAssets の WebGL 上の URL 形式は http(s)://host/StreamingAssets/xxx
        var url = System.IO.Path.Combine(Application.streamingAssetsPath, relativePath);
        return UnityWebRequest.Get(url);
    }
}
```

### 2. プラットフォーム条件コンパイルで旧呼び出しを維持する

ビジネスコードでマクロを使用して WebGL を除外し、WebGL 上でサポートされていない API が呼び出されないようにします:

```csharp
#if !UNITY_WEBGL || UNITY_EDITOR
    using GameFrameX.ReadAssets.Runtime;
#endif

public byte[] LoadConfig(string path)
{
#if !UNITY_WEBGL || UNITY_EDITOR
    return BlankReadAssets.ReadAllBytes(path);
#else
    using (var req = WebGLReadAssetsFallback.ReadAllBytes(path))
    {
        req.SendWebRequest();
        while (!req.isDone) { }
        return req.downloadHandler.data;
    }
#endif
}
```

> `Runtime/BlankReadAssets.cs` 内のプラットフォームごとに実装を選択する記述を参照してください:

```csharp
#if UNITY_EDITOR
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.EditorImpl;
#elif UNITY_ANDROID
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.ApkImpl;
#else
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.LooseFilesImpl;
#endif
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L11-L17)

### 3. AssetBundle に関する補足説明

`BlankReadAssets.LoadAssetBundle` は内部的に `AssetBundle.LoadFromFile` を呼び出しますが、この API の WebGL 上での動作は未定義です。WebGL で AssetBundle を読み込む必要がある場合は、必ず `UnityWebRequestAssetBundle.GetAssetBundle` を使用してください。フレームワークは WebGL 用の同等実装を提供していないため、独自にラップするか、このパスへの依存を削除する必要があります。

## 検証

- エディタで Build Target を WebGL に切り替え、シーン初期化ロジックをトリガーし、"WebGL is not supported" 以外のランタイム例外が出力されないことを確認します。
- WebGL Build でブラウザの開発者ツールを開き、`UnityWebRequest` のリクエストパスが `StreamingAssets` 配下の正しい相対ファイルを指していること、およびレスポンスが 200 であることを確認します。
- ビジネスパスを以下のように変更します:WebGL 以外では `BlankReadAssets` を、WebGL では `UnityWebRequest` を使用し、両方のパスで同じリソース読み込みのスモークテストを実行します。

## 背景(任意)

リポジトリの README の Platform Notes セクションには "WebGL is not supported" と明記されており、本フレームワークは `UNITY_WEBGL` の実装分岐を提供していません。Android および Editor 以外の他のプラットフォームはすべて `LooseFilesImpl` にマッピングされ、この実装は物理ディスクからファイルを読み取るため、WebGL サンドボックスの同期/非同期 I/O 要件を満たすことができません。
