# How to Build Parent-Child Hierarchy Relationships

Using the `AttachEntity` family of methods, you can attach an existing entity to another entity. The framework records the parent-child mapping, automatically synchronizes the `Transform` parent-child relationship, and triggers the `OnAttached` / `OnDetached` callbacks on `EntityLogic`.

## Prerequisites

- The parent entity and child entity have already been created via `ShowEntity` or `CreateEntity` and are in a shown state.
- The `GameFrameX.Entity.Runtime.EntityComponent` has been mounted and accessed via `GameEntry.Entity`.
- The child entity's root `Transform` (i.e., the GameObject where its `EntityLogic` resides) will be used as the object controlled by the parent.

## Steps

### 1. Establish the Parent-Child Relationship via Entity ID

```csharp
// Attach the child entity childEntityId under parentEntityId
GameEntry.Entity.AttachEntity(childEntityId, parentEntityId);
```

Source: [EntityComponent.cs#L756-L765](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L756-L765)

### 2. Attach via Entity Objects

```csharp
Entity childEntity = GameEntry.Entity.GetEntity(childEntityId);
Entity parentEntity = GameEntry.Entity.GetEntity(parentEntityId);
GameEntry.Entity.AttachEntity(childEntity, parentEntity);
```

### 3. Specify the Parent Transform and Attachment Data

When you need to attach the child entity to a specific node of the parent entity (e.g., a weapon socket) rather than the root Transform, use the overload with `parentTransform` and `userData`, and bind it in one step at creation time via `AttachToEntity`:

```csharp
GameEntry.Entity.AttachToEntity(
    childEntityId, parentEntityId,
    "WeaponSocket01",   // Name of the parent entity's child node
    userData: payload); // Custom data
```

Here, `AttachEntityInfo` stores the parent `Transform` and the user data:

### 4. Receive Attachment Events on the Parent Entity

Override `EntityLogic.OnAttached` to be notified when a child entity is attached; `userData` is passed back as-is:

```csharp
protected internal override void OnAttached(EntityLogic childEntity, Transform parentTransform, object userData)
{
    base.OnAttached(childEntity, parentTransform, userData);
    Debug.Log($"child {childEntity.Id} attached under {parentTransform.name}");
}
```

## Detaching Parent-Child Relationships

Override `OnDetached` in the parent entity's `EntityLogic`; the framework calls back this method when a child entity is detached, passing in the original `userData`:

```csharp
protected internal override void OnDetached(EntityLogic childEntity, object userData)
{
    base.OnDetached(childEntity, userData);
    // Cleanup logic such as returning references, stopping drivers, etc.
}
```

## Common Variants

- **Attach to a parent at creation time**: Use `AttachToEntity` to specify the parent entity ID, parent node name, and `userData` within the same `ShowEntity` flow, avoiding an additional `AttachEntity` call.
- **Change the parent**: Call `AttachEntity(child, newParent)` again; the framework overwrites the previous parent entity binding.
- **Batch queries at runtime**: Get the child entity array via `GetChildEntities(parentEntityId)` and iterate over it for processing.

## Common Errors

- **Attaching without calling ShowEntity first**: Both the parent and child entities must be in a loaded and visible state; otherwise, a null reference will be thrown.
- **Misusing the entity group Helper's Transform**: The `parentTransform` in `AttachToEntity` is the name of a child `Transform` under the parent entity (e.g., a socket), not the entity group's root node.
- **Forgetting to override OnAttached**: If the attachment success callback is not overridden in the parent entity's `EntityLogic`, it may appear that "the logic was never triggered"; the default implementation is empty.
- **Circular parent-child attachment**: Attaching a grandparent under a child causes an infinite callback chain; make sure the hierarchy is strictly one-directional.

## Background (Optional)

Internally, the framework records `AttachEntityInfo` (`ParentTransform` + `UserData`) per child entity; the parent-child mapping and `Transform.SetParent` are maintained by `EntityManager`; `OnAttached` / `OnDetached` are exposed by `EntityLogic` as `protected internal virtual`, and only hooks needed at runtime require overriding.
