# 如何在 JSON 與二進位設定之間切換

在 GameFrameX 中，`Hotfix/Config/Generate/Tables/` 下的表資料類別(由 LuBan 工具產生)使用 `SimpleJSON.JSONNode` 作為反序列化入口；執行階段由 `TablesComponent` 把每張表註冊到 `ConfigComponent`。本頁面說明在「JSON 設定」和「二進位設定」兩種來源之間的切換方式。

## 前置條件

- 已在 `Packages/manifest.json` 中透過 GameFrameX scoped registry 引入 `com.gameframex.unity.json.simplejson`(參考 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/README.zh-CN.md#L40-L80))。
- 專案中已存在 `Assets/Hotfix/Config/Generate/Tables/TablesComponent.cs`,並透過 LuBan 工具產生 `ItemConfig`、`AchievementConfig`、`SoundsConfig` 等表類別(見 [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86))。
- 執行階段框架套件 `com.gameframex.unity.config` 已安裝，提供 `ConfigComponent` 與 `BaseDataTable<T>`(見 [link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28))。

## 操作步驟

1. 確認表類別的反序列化建構函式簽章。產生器產出的所有表類別都提供一個接收 `SimpleJSON.JSONNode` 的建構函式，用於把 JSON 反序列化為表物件。

```csharp
// 來源:LuBan 產生的程式碼
public ItemConfig(JSONNode _buf)
{
    { if(!_buf["id"].IsNumber) { throw new SerializationException(); }  Id = _buf["id"]; }
    { if(!_buf["Name"].IsString) { throw new SerializationException(); }  Name = _buf["Name"]; }
    // ... 省略其餘欄位
    PostInit();
}

public static ItemConfig DeserializeItemConfig(JSONNode _buf)
{
    return new Tables.ItemConfig(_buf);
}
```

來源:[ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86)

2. 在 `TablesComponent` 中將每張表註冊到 `ConfigComponent`。預設實作中，所有表都透過 `TbXxxConfig.LoadAsync()` 非同步載入，並以表名作為索引鍵註冊(見 [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L52-L70))。

```csharp
m_ConfigComponent.RemoveAllConfigs();
var loadTasks = new System.Collections.Generic.List<System.Threading.Tasks.Task>();
loadTasks.Add(TbItemConfig.LoadAsync());
m_ConfigComponent.Add(nameof(Tables.TbItemConfig), TbItemConfig);
```

3. 切換到 JSON 設定來源(預設方案)。保持現有產生的程式碼不變，只需把資料匯出為 JSON 檔案並交給 LuBan 載入。產生器產生的 `DeserializeXxxConfig(JSONNode)` 直接接受 JSON 文字，執行階段無需額外轉換。

4. 切換到二進位設定來源(效能優先方案)。當熱更新包或首包內只提供二進位資料時，先在載入入口把二進位串流解碼為 `JSONNode`,再走相同的 `DeserializeXxxConfig` 路徑，以確保下游表類別零改動。例如：

```csharp
using SimpleJSON;
using System.Text;

// 假設 bytes 是從 YooAsset 取得的二進位設定包
JSONNode node = JSON.Parse(Encoding.UTF8.GetString(bytes));
var item = Tables.ItemConfig.DeserializeItemConfig(node);
```

關鍵重點：反序列化入口仍然是 `DeserializeXxxConfig(JSONNode)`,所以 JSON 和二進位的切換等價於「在載入階段把資料形態歸一化為 JSONNode」。表類別本身不需要重新產生。

5. 在執行階段透過 `ConfigComponent.GetConfig<T>()` 取得設定。無論底層是 JSON 還是二進位，只要表名在 `TablesComponent.Add` 時已經註冊，業務層呼叫方式不變：

```csharp
var itemConfig = GameFrameX.Config.Runtime.ConfigComponent.Instance
    .GetConfig<Tables.ItemConfig>();
```

## 常見變體

- **熱更階段按平台切換**：Android 平台首包使用二進位壓縮包以縮小包體，iOS 平台或開發期使用 JSON 便於除錯。只需在 `TablesComponent.Init` 之前按平台選擇載入來源，把取得的 `JSONNode` 傳入 `DeserializeXxxConfig` 即可。
- **在地化設定**：已產生的表(例如 `TbLocalization`)走完全相同的註冊流程，見 [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L70) 中 `m_ConfigComponent.Add(nameof(Local.TbLocalization), TbLocalization)`。

## 常見錯誤

- **直接修改產生的表類別**：產生器會覆寫 `Assets/Hotfix/Config/Generate/Tables/*.cs`,所有客製化邏輯應放在 `partial` 部分類別或業務層。
- **修改欄位名稱後未重新產生**:`_buf["xxx"]` 的欄位名稱是區分大小寫的(注意 `id` 小寫、`Name` 大寫、`description` 小寫)，欄位不一致會觸發 `SerializationException`(見 [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L74))。
- **忘記呼叫 `m_ConfigComponent.Add`**:只呼叫 `LoadAsync()` 而未註冊表名，`GetConfig<T>()` 將回傳空。註冊流程見 [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L69)。
- **HybridCLR AOT 裁剪問題**：新增了非泛型反射目標時，需確認 `ConfigComponent`/`BaseDataTable<T>` 已在 link.xml 中保留(見 [link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28))。

## 背景(選用)

LuBan 表產生器的產物統一以 `SimpleJSON.JSONNode` 作為反序列化入口，這一步把「資料來自 JSON 還是二進位」的差異收斂在載入層。`TablesComponent` 負責把每張表註冊進 `ConfigComponent`,業務層則統一透過 `ConfigComponent.GetConfig<T>()` 取得資料，因此切換資料來源不需要改動消費方。關於 LuBan 產生器與設定管線的整體位置，見專案內 `Assets/Hotfix/Config/Generate/`。
