# Using Lists: Virtual Lists, Looping Lists, and Trees

In FairyGUI, `GList` provides two ways to build lists: regular lists (adding items one by one via `AddItemFromPool`) and virtual lists (creating only the items visible within the viewport via `SetVirtual` / `SetVirtualAndLoop`, and refreshing their appearance with the `itemRenderer` callback). The latter is suitable for large data volumes and infinite loop scrolling scenarios. Tree structures are implemented by `GTree` / `GTreeNode` (see the related links at the end of this document).

## Prerequisites

- The list component must have **scrolling enabled** (mandatory for virtual lists; otherwise an error is thrown).
- A virtual list must have a **default item resource** (the default list item resource set in the editor), which is used to calculate item sizes.

## Steps

### 1. Regular List: Adding Items from the Object Pool

`GList` internally uses `GObjectPool` to reuse items; simply add them one by one:

```csharp
// The parameterless version uses the default item resource; the version with a url uses the specified resource
public GObject AddItemFromPool()
public GObject AddItemFromPool(string url)
public GObject GetFromPool(string url)
```

Source: [GList.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GList.cs#L346-L378)

Usage example:

```csharp
// "list" is a GList whose default item has already been configured in the editor
GObject item = list.AddItemFromPool();
// Set the item's appearance and data here...
```

### 2. Virtual List: SetVirtual + numItems + itemRenderer

A virtual list does not create an actual object for each entry of data; instead, it creates the minimum number of display objects based on the viewport size, and reuses and refreshes them via the `itemRenderer` callback while scrolling:

```csharp
public delegate void ListItemRenderer(int index, GObject item);
public delegate string ListItemProvider(int index);
```

Source: [GList.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GList.cs#L8-L20)

```csharp
list.SetVirtual();          // Enable virtual list mode
list.itemRenderer = (index, item) =>
{
    // Set the item's appearance and data based on index (items are reused; make sure to assign values every time)
};
list.numItems = dataCount;  // Set the total data count; the list automatically creates items as needed
```

The actual implementation for enabling virtual mode (with mandatory validation):

```csharp
public void SetVirtual()
{
    SetVirtual(false);
}

public void SetVirtualAndLoop()
{
    SetVirtual(true);
}
```

Source: [GList.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GList.cs#L1480-L1505)

### 3. Looping List: SetVirtualAndLoop

To enable infinite loop scrolling on top of virtual mode, simply call `SetVirtualAndLoop()`. Once enabled, the framework automatically disables the scroll pane's bounceback effect (`bouncebackEffect = false`).

Source: [GList.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GList.cs#L1496-L1518)

### 4. Refreshing and Index Conversion

- Refresh after data changes: set `numItems` again, or call `RefreshVirtualList()`.
- Convert between item index and child index (the two differ in virtual/looping mode):

```csharp
// Converts an item's index to a child object's index
public int ItemIndexToChildIndex(int index)
```

## Common Errors

| Error/Symptom | Cause | Fix |
|------|------|------|
| `FairyGUI: Virtual list must be scrollable!` | `SetVirtual` was called without scrolling enabled on the list | Enable scrolling on the list component in the editor |
| `FairyGUI: Virtual List must have a default list item resource.` | The virtual list has no default item resource, so item sizes cannot be calculated (the framework falls back to 100x100) | Set the default list item resource in the editor |
| `FairyGUI: Loop list is not supported for FlowHorizontal or FlowVertical layout!` | `SetVirtualAndLoop` does not support Flow layouts | Switch to a single-row/single-column/grid layout, or use `SetVirtual` instead |
| Items show stale data | Virtual list items are reused | Fully assign values for every index in the `itemRenderer` callback; do not just assign initial values |
| `AddChild` / `RemoveChild` have no effect in virtual mode | Virtual lists can only manage data length via `numItems` | Use `numItems` to control the number of entries and `itemRenderer` to refresh appearance |
| Child index conversion is wrong in looping lists | Item index and child index differ in looping mode | Convert using `ItemIndexToChildIndex` / `ChildIndexToItemIndex` |

## Common Variants

- **Mixing different resources**: All layouts except the "Pagination" layout support building list items with different resources; return the corresponding resource url in `itemProvider`; if not provided, `defaultItem` is used by default.
- **Variable-height items**: List layouts using "single row" or "single column" can support list items with different heights (quoted from source code comments).
- **Pagination mode**: When virtual mode is enabled for the `ListLayoutType.Pagination` layout, the framework immediately executes `RefreshVirtualList` once inside `SetVirtual` to avoid a division-by-zero error caused by layout adaptation timing.

## Background

The core idea of a virtual list is to replace "creating an entity for each entry" with "a minimal set of display objects + callback-based refreshing": `GList` internally maintains state such as `List<ItemInfo> _virtualItems`, `_numItems`, and `_firstIndex`; while scrolling, it reuses items from the object pool according to `scrollStep` (automatically taken from the item size) and uses `itemInfoVer` to mark items that have already been reused in the current pass, avoiding duplicate refreshes. A looping list additionally sets `scrollPane._loop` to 1 (horizontal) or 2 (vertical) to achieve infinite scrolling.
