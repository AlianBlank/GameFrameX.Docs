# 모듈 조회 실패 시 대처 방법

`GameFrameX.Runtime.GameFrameworkEntry.GetModule<T>()`를 호출하여 모듈을 조회할 때, 프레임워크는 인터페이스 이름을 통해 리플렉션으로 구현 클래스를 찾습니다. 조회 과정에서 인터페이스 제약, 네이밍 규칙, 자동 등록 실패 등의 이유로 `GameFrameworkException`이 발생합니다. 이 페이지에서는 예외 메시지별로 근본 원인과 해결 단계를 정리합니다.

## 해결 단계

### 해결1: 반드시 인터페이스로 조회

`GetModule<T>`의 첫 번째 작업은 `typeof(T).IsInterface`를 검사하는 것이며, 인터페이스가 아니면 즉시 예외를 발생시킵니다.

```csharp
// 오류: 구현 클래스 전달
var foo = GameFrameworkEntry.GetModule<FooImpl>();

// 올바름: 인터페이스 전달
var foo = GameFrameworkEntry.GetModule<IFoo>();
```

Source: [GameFrameworkEntry.cs#L95-L120](/src/Runtime/Base/GameFrameworkEntry.cs#L95-L120)

### 해결2: 네임스페이스는 `GameFrameX.`로 시작해야 함

프레임워크는 인터페이스의 `FullName`이 `GameFrameX.`로 시작해야 하며, 그렇지 않으면 두 번째 예외를 발생시킵니다.

```csharp
// 오류: 네임스페이스가 GameFrameX 아래에 있지 않음
namespace MyGame { public interface IBar {} }

// 올바름
namespace GameFrameX.Runtime { public interface IBar {} }
```

Source: [GameFrameworkEntry.cs#L104-L107](/src/Runtime/Base/GameFrameworkEntry.cs#L104-L107)

### 해결3: 모듈 구현 클래스를 찾을 수 없음

구현 클래스를 찾을 때 프레임워크는 규약에 따라 인터페이스 이름에서 접두사 `I`를 제거한 후 동일한 네임스페이스에 결합하여 리플렉션합니다 (예: `GameFrameX.Runtime.IFoo` → `GameFrameX.Runtime.Foo`). 실패하면 명시적인 `RegisterModule`을 요구합니다.

```csharp
// 규약에 의한 조회 (동일 네임스페이스에 Foo 클래스가 존재하면 됨)
public class Foo : GameFrameworkModule, IFoo { /* ... */ }

// 또는 명시적 등록: 전달되는 두 번째 Type은 임의의 네임스페이스에서 가져올 수 있음
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(MyGame.Modules.FooImpl));
```

호출 진입점은 `GetModule<T>` 내부의 `Type.GetType(moduleName)` 로직에 있으며, [GameFrameworkEntry.cs#L109-L119](/src/Runtime/Base/GameFrameworkEntry.cs#L109-L119)를 참조하세요. 등록 로직은 [GameFrameworkEntry.cs#L153-L169](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L169)를 참조하세요.

### 해결4: 등록 시 첫 번째 인자는 반드시 인터페이스여야 함

`RegisterModule`의 첫 줄에서 `interfaceType.IsInterface`를 검증합니다.

```csharp
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(Foo));   // 올바름
GameFrameworkEntry.RegisterModule(typeof(Foo), typeof(Foo));     // 예외 발생
```

Source: [GameFrameworkEntry.cs#L153-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L163)

### 해결5: 등록 시 두 번째 인자는 반드시 구체 클래스여야 함

`implType.IsClass && !implType.IsInterface && !implType.IsAbstract`을 요구합니다.

- 인터페이스 → `by Class and not Interface ... is not.` 예외 발생
- 추상 클래스 → 동일하게 예외 발생
- 구체 클래스로 등록하면 해결됨

Source: [GameFrameworkEntry.cs#L160-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L160-L163)

### 해결6: 구현 클래스에 매개변수 없는 생성자가 없음

`CreateModule`은 `Activator.CreateInstance(moduleType)`을 사용하여 인스턴스를 생성하며, 매개변수 없는 생성자를 찾을 수 없거나 생성 중 오류가 발생하면 `Can not create module 'X'.`이 발생합니다.

```csharp
public class Foo : GameFrameworkModule
{
    public Foo() { }  // 접근 가능한 매개변수 없는 생성자를 반드시 유지해야 함
    protected internal override int Priority => 0;
    protected internal override void Update(float a, float b) { }
    protected internal override void Shutdown() { }
}
```

## 검증

- `Awake` 또는 `Start`에서 `GameFrameworkException`을 캐치합니다:
  ```csharp
  try
  {
      var ui = GameFrameworkEntry.GetModule<IFooModule>();
  }
  catch (GameFrameworkException ex)
  {
      Debug.LogError(ex.Message);
  }
  ```
  더 이상 예외가 발생하지 않으면 등록과 네임스페이스가 모두 올바른 것입니다.
- 콘솔에 `Can not find Game Framework module type`이라는 메시지가 더 이상 나타나지 않으면 규약에 의한 자동 조회가 성공한 것입니다. 여전히 조회가 실패한다면, 어셈블리가 Player Settings에 컴파일되었는지, 그리고 인터페이스와 구현 클래스의 네임스페이스가 일치하는지 확인하세요.
