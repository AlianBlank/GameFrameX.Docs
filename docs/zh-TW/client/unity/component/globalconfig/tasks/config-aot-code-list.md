# AOT 程式碼清單設定方式

若在 `GlobalConfigComponent` 中設定 `AOTCodeList` 欄位，框架會將其解析為組件清單，讓 hybridclr 之類的熱更新解決方案能在執行階段載入額外中繼資料時使用。設定完成後，即可透過 `AOTCodeLists` 屬性取得實際的組件陣列。

## 前置條件

- 專案必須已安裝 `com.gameframex.unity.globalconfig` 套件。
- 場景中必須存在附加了 `GlobalConfigComponent` 的 GameObject(由 `GameFrameX` 框架進入點自動生成)。

## 操作步驟

1. 在 Hierarchy 中選取附加了 `GlobalConfigComponent` 的 GameObject,並在 Inspector 中找到 **輔助組件清單** 欄位(AOTCodeList)。
2. 在該欄位輸入 JSON 字串。陣列中的每個項目皆為要載入的 AOT 組件名稱(通常與 `HybridCLR` 的 `AOTMetadataLoader` 搭配使用)。
3. 編譯完成後，Inspector 底部的唯讀 **輔助中繼資料清單** 會顯示解析後的組件陣列(由 setter 在反序列化時填入)。
4. 執行階段程式碼可直接讀取此陣列並傳遞給 `RuntimeApi.LoadMetadataForAOTAssembly`。

## 欄位對應

| Inspector 名稱 | 欄位名稱 | 類型 | 讀取/寫入 | 作用 |
|----------------|--------|------|-----------|------|
| 輔助組件清單 | `m_aotCodeList` | `string` | 讀取/寫入 | JSON 字串，永久儲存於原始碼中的進入點 |
| 輔助中繼資料清單 | `m_aotCodeLists` | `List<string>` | 唯讀 | 解析後的組件名稱清單 |
| 原始資料 | `m_originalData` | `string` | 唯讀 | 遠端回傳的原始回應 |

欄位定義位於 `GlobalConfigComponent`:

```csharp
[SerializeField] private string m_aotCodeList = string.Empty;

[SerializeField] private List<string> m_aotCodeLists = new List<string>();

public List<string> AOTCodeLists
{
    get { return m_aotCodeLists; }
}

public string AOTCodeList
{
    get { return m_aotCodeList; }
    set
    {
        m_aotCodeList = value;
        try
        {
            m_aotCodeLists = Utility.Json.ToObject<List<string>>(value);
        }
        catch (Exception e)
        {
            Log.Error(e);
        }
    }
}
```

## 執行階段讀取

`GlobalConfigComponent` 單例可透過 `GameEntry` 取得：

```csharp
var aotList = GameEntry.GlobalConfig.AOTCodeLists;
foreach (var asm in aotList)
{
    // 傳遞給 hybridclr:RuntimeApi.LoadMetadataForAOTAssembly(...)
}
```

遠端介面的 `ResponseGlobalInfo.AOTCodeList` 同樣是 JSON 字串，因此將值指派給組件時，組件的 setter 會自動進行反序列化：

```csharp
public class ResponseGlobalInfo
{
    public string CheckAppVersionUrl { get; set; }
    public string CheckResourceVersionUrl { get; set; }
    public string AOTCodeList { get; set; }
    public string Content { get; set; }
}
```

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|-----------|
| 設定 `AOTCodeList` 後 `AOTCodeLists` 仍為空 | JSON 格式不正確，導致 `Utility.Json.ToObject` 擲回例外狀況，並由 `Log.Error` 處理 | 在主控台中尋找 `Log.Error` 的輸出並修正 JSON(檢查引號、逗號、方括號) |
| 執行模式下無法編輯 | 播放時整個 Inspector 會被停用 | 結束播放模式後再修改 |
| 修改後清單未更新 | setter 僅在指派時解析，直接修改 `m_aotCodeList` 不會重新解析 | 重新為 `AOTCodeList` 屬性指派值，或重新開啟 Inspector |

## 背景

`AOTCodeList` 為字串而 `AOTCodeLists` 為 `List<string>` 的原因，是為了將序列化欄位保持為基本類型(便於 Inspector 編輯與網路傳輸)，同時在執行階段將 JSON 反序列化為可用的清單。`m_aotCodeLists` 欄位設為唯讀，以防止外部繞過 JSON 驗證而直接繞過 setter。
