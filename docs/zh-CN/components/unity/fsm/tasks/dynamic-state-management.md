# 如何动态添加与移除状态

在有限状态机运行期间,你可以随时为已创建的 FSM 追加新状态,或移除不再需要的状态。本页展示如何在运行时调用 `AddState` / `RemoveState`,以及容易踩到的限制。

## 前置条件

- 已有 `IFsm<T>` 实例(通过 `FsmManager.CreateFsm` 创建,详见创建流程)
- 准备好继承自 `FsmState<T>` 的状态类

## 操作步骤

1. **确认状态不存在**(避免重复添加)。使用 `HasState<TState>()` 判定,内部按 `Type` 作为字典键检查。

   ```csharp
   if (!fsm.HasState<RunState>())
   {
       fsm.AddState(new RunState());
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L328-L332)

2. **添加状态**:调用 `AddState(FsmState<T>)`。重复添加同一类型的状态会抛出 `GameFrameworkException`。

   ```csharp
   fsm.AddState(new RunState());
   Assert.AreEqual(2, fsm.FsmStateCount);
   ```

   Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L78-L91)

3. **启动新增的状态**(可选):用 `Start<TState>()` 立刻切换到刚加入的状态。

   ```csharp
   fsm.Start<RunState>();
   ```

   Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L89-L90)

4. **移除状态**:调用 `RemoveState<TState>()`。返回 `true` 表示移除成功,`false` 表示该状态不存在。

   ```csharp
   if (fsm.RemoveState<RunState>())
   {
       // 已移除
   }
   ```

   Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L94-L107)

## 常见变体

### 跨 FSM 共用同一个状态实例

`AddState` 接收已构造的 `FsmState<T>` 实例。同一实例不要重复注册到多个 FSM,否则状态内的回调会作用于多个 `Owner`,造成状态污染。

### 通过 `Type` 调用(泛型不可用时)

`IFsm<T>` 还提供 `HasState(Type)`、`GetState(Type)` 的非泛型重载,签名见接口定义:

```csharp
bool HasState(Type stateType);
FsmState<T> GetState(Type stateType);
```

Source: [IFsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsm.cs#L128-L144)

## 常见错误

| 错误表现 | 原因 | 修复 |
|----------|------|------|
| 添加已存在类型的状态时抛出 `GameFrameworkException` | 同类型的状态已注册,FSM 内部以 `Type` 为键去重 | 先用 `HasState<TState>()` 判断,或仅添加一次 |
| `RemoveState` 移除当前正在运行的状态时抛出 `GameFrameworkException` | 框架禁止移除当前状态,以避免当前状态引用悬空 | 先 `Start<OtherState>()` 切换,再 `RemoveState` |
| `RemoveState` 返回 `false` | 该类型的状态尚未注册 | 先确认 `HasState<TState>()` 为 `true` |
| `HasState(null)` / `HasState(非 FsmState 类型)` 抛异常 | 接口约定状态类型必须派生自 `FsmState<T>` | 传入有效的状态类型 |

异常来源参考: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L109-L126)

## 背景(可选)

FSM 内部以 `Dictionary<Type, FsmState<T>>` 维护状态集合,`AddState` / `RemoveState` 直接操作该字典;为保证运行时安全,框架在移除前会校验目标状态不是 `CurrentState`。
