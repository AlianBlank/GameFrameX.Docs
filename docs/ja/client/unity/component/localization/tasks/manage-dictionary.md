# 翻訳辞書の管理：キーと値のペアの追加・照会・削除

GameFrameX.Localization では、翻訳キーと値のペアの**照会**は `LocalizationComponent` 上の `GetString` シリーズ API によって行われます;一方、辞書コンテンツの**追加と削除**は辞書リソースのロードフローによって駆動され、`LoadDictionarySuccessEventArgs` などのイベントを通じて結果を確認できます。本ページでは、これらの API の実際のシグネチャと使用方法への入口を示します。

## 前提条件

- プロジェクトに本パッケージが導入済みであること(ランタイムアセンブリ `GameFrameX.Localization.Runtime`)。
- シーンに `LocalizationComponent` コンポーネントがアタッチ済みであること。

## キーと値のペアの照会:GetString シリーズ

`LocalizationComponent` は、引数なしのオーバーロード 1 つと、フォーマット引数付きオーバーロードのグループ(最大 10 個の強く型付けされた引数をサポートし、内部では `string.Format` のセマンティクスに従ってプレースホルダーを埋め込みます)を提供します:

| シグネチャ | 説明 |
|------|------|
| `public string GetString(string key)` | `key` に基づいて現在の言語の辞書から元のテキストを取得する |
| `public string GetString(string key, params object[] args)` | テキストを取得してフォーマットする。引数は配列として渡す |
| `public string GetString<T>(string key, T arg)` | 単一引数のフォーマット(強い型指定によりボックス化を回避) |
| `public string GetString<T1, T2>(string key, T1 arg1, T2 arg2)` | 2 引数のフォーマット |
| `public string GetString<T1, ..., T10>(string key, T1 arg1, ..., T10 arg10)` | 同様に続き、合計 10 個の強く型付けされた引数バージョンが存在する |

以下はソースコード中の実際のシグネチャ(抜粋)です:

```csharp
[Preserve]
public string GetString(string key)
```

呼び出し時に辞書内のキー名を渡すだけで翻訳テキストを取得できます。`args` 付きのオーバーロードは `{0}`、`{1}` などのプレースホルダーを含むテンプレートテキストに適しています。その他の強く型付けされたオーバーロードのシグネチャの位置:`T1,T2` は 334 行目、`T1..T3` は 354 行目、`T1..T4` は 376 行目、`T1..T5` は 400 行目、`T1..T6` は 426 行目、`T1..T7` は 454 行目、`T1..T8` は 484 行目、`T1..T9` は 516 行目、`T1..T10` は 550 行目です([LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L334-L550) を参照)。

## 辞書コンテンツの追加と削除

本リポジトリの `LocalizationComponent` ソースコードには、`AddDictionary` / `RemoveDictionary` のような実行時のキーと値のペアの追加・削除に関する公開実装の詳細は見つかりませんでした。辞書のロードと削除は辞書リソースのロードフローを経由して行われ、結果はイベントを通じて通知されるため、それによって「どの辞書がロードされ、どれが失敗したか」を確認できます:

| イベントクラス | 主要メンバー | 用途 |
|--------|----------|------|
| `LoadDictionarySuccessEventArgs` | `EventId`、`DictionaryAssetName`、`Duration` | 辞書リソースのロード成功。`DictionaryAssetName` が辞書アセット名 |
| `LoadDictionaryFailureEventArgs` | ソースファイルを参照 | 辞書リソースのロード失敗 |
| `LoadDictionaryUpdateEventArgs` | ソースファイルを参照 | 辞書リソースのロード進捗の更新 |

成功イベントの実際の定義(抜粋):

```csharp
[Preserve] public static readonly string EventId = typeof(LoadDictionarySuccessEventArgs).FullName;

[Preserve]
public string DictionaryAssetName { get; private set; }

[Preserve]
public static LoadDictionarySuccessEventArgs Create(string dataAssetName, float duration, object userData)
{
    LoadDictionarySuccessEventArgs loadDictionarySuccessEventArgs = ReferencePool.Acquire<LoadDictionarySuccessEventArgs>();
    loadDictionarySuccessEventArgs.DictionaryAssetName = dataAssetName;
    loadDictionarySuccessEventArgs.Duration = duration;
    loadDictionarySuccessEventArgs.UserData = userData;
    return loadDictionarySuccessEventArgs;
}
```

出典: [LoadDictionarySuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionarySuccessEventArgs.cs#L47-L101)

つまり、新しい翻訳キーと値のペアのセットを追加するには、それらを辞書リソースとして作成してロードリストに加え、上記のイベントを監視してロードを確認します。その後は `GetString(key)` で照会できます。実行時に個々のキーと値のペアを動的に追加・削除する API が必要な場合、本リポジトリのソースコードには実装の詳細が見つからないため、上流の GameFramework ローカリゼーションマネージャーの同名インターフェースを参照してください。

## よくあるエラー

- **キーが存在しない、または辞書のロードが完了する前に `GetString` を呼び出す**:対応する辞書が `LoadDictionarySuccessEventArgs` を発生させたことを確認してから照会し、ロード完了前に値を取得しないようにしてください。
- **言語切り替えをキーと値のペアの操作として扱う**:言語切り替えには独立したイベント `LocalizationLanguageChangeBeforeEventArgs` / `LocalizationLanguageChangeAfterEventArgs` があり、辞書の追加・削除と混在させないでください。切り替え後は再度 `GetString` で照会すれば問題ありません。

## 検証

`GetString(key)` の呼び出しで返される文字列が辞書内のそのキーの翻訳テキストと一致し、引数付きオーバーロードのプレースホルダーが正しく埋め込まれていれば、キーと値のペアが有効になっていることを示します。
