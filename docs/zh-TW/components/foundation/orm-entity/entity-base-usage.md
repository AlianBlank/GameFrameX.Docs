# 如何透過繼承 EntityBase / EntityBaseId 來建立實體

透過繼承框架的 `EntityBase` / `EntityBaseId` 實體基底類別，實體類別可自動取得主鍵、稽核欄位、邏輯刪除旗標、樂觀鎖定版本號碼、啟用旗標等通用欄位，無需在各個實體中重複宣告。

## 前置條件

- 專案已參考 `GameFrameX.Foundation.Orm.Entity` 組件。
- 使用支援 C# `Key` / `Required` 等資料註解屬性的 ORM（如 SqlSugar / Entity Framework）。

## 操作步驟

### 1. 僅需要主鍵欄位：繼承 `EntityBaseId` / `EntityBaseId<TKey>`

如果實體只需要主鍵，不關心建立者、更新時間、邏輯刪除等稽核欄位，請繼承 `EntityBaseId`。預設的主鍵型別為 `long`，並已附帶 `Key` 與 `Required` 屬性。

```csharp
using System.ComponentModel.DataAnnotations;
using GameFrameX.Foundation.Orm.Entity;

public class Dictionary
{
    // 業務欄位
    public string Code { get; set; }
    public string Name { get; set; }
}
```

如果主鍵不是 `long`，請使用泛型版本來指定主鍵型別（`TKey` 必須是非 null 型別）：

```csharp
public class Dictionary<TKey>
    where TKey : notnull
{
    // 主鍵 Id 已在基底類別中宣告
    public string Code { get; set; }
    public string Name { get; set; }
}
```

來源：[EntityBaseId.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L44-L82)

### 2. 需要完整的稽核欄位：繼承 `EntityBase` / `EntityBase<TKey>`

大多數業務實體都需要稽核、邏輯刪除、樂觀鎖定、啟用旗標等欄位，因此請直接繼承 `EntityBase`。基底類別已實作 `ISafeDeletedFilter`、`IVersionedEntity`、`ISafeEnabledFilter`、`ISafeCreatedFilter`、`ISafeUpdateFilter` 等介面，框架會自動套用這些篩選條件。

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class PlayerEntity : EntityBase
{
    // 基底類別已提供：Id、CreatedId、CreatedTime、CreatedName、
    //                UpdateCount、UpdateTime、UpdatedId、UpdatedName、
    //                IsDeleted、DeleteTime、DeletedId、DeletedName、
    //                RowVersion、IsEnabled
    public string Name { get; set; }
    public int Level { get; set; }
}
```

如果使用 `long` 以外的主鍵，請使用泛型版本：

```csharp
public class PlayerEntity<TKey> : EntityBase<TKey>
    where TKey : notnull
{
    public string Name { get; set; }
    public int Level { get; set; }
}
```

來源：[EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L180)

### 3. 視需要覆寫基底類別的屬性

基底類別的所有欄位皆帶有 `virtual` 修飾詞，因此可在子類別中使用 `override` 來調整預設值或額外屬性。例如，可在新建時將 `IsDeleted` 設為 `null`：

```csharp
public class OrderEntity : EntityBase
{
    public override bool? IsDeleted { get; set; }

    public string OrderNo { get; set; }
}
```

## 常見變體

| 情境 | 基底類別 | 主要功能 |
|------|------|----------|
| 僅需要主鍵 | `EntityBaseId` / `EntityBaseId<TKey>` | `Id` 主鍵欄位 |
| 完整稽核 + 邏輯刪除 + 樂觀鎖定 + 啟用旗標 | `EntityBase` / `EntityBase<TKey>` | 上述所有基底類別的功能 |
| 另需租戶隔離 | `EntityTenantBase` / `EntityTenantBase<TKey>` | 在 `EntityBase` 上新增 `TenantId` 篩選器 |
| 另需擴充查詢篩選器 | `EntitySelectBase` / `EntitySelectBase<TKey>` | 在 `EntityBase` 上新增 `Select` 篩選器 |

來源：[EntityTenantBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantBase.cs#L44-L65),[EntitySelectBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntitySelectBase.cs#L45-L77)

## 常見錯誤

- **忘記撰寫 `where TKey : notnull`**：使用泛型基底類別時，必須加入此條件約束，否則會導致編譯失敗。基底類別本身也強制要求此約束（[EntityBaseId.cs L67-L68](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBaseId.cs#L67-L68)）。
- **手動重複宣告 `Id` 欄位**：`Id` 已由基底類別提供，請勿在子類別中再次宣告，否則會產生隱藏基底類別成員的編譯警告，並可能破壞 ORM 對應。
- **將實體類別設為 `abstract` 以外的形式**：基底類別是 `abstract`，因此建議具體實體也設為 `abstract`，但業務類別應確保不再被繼承。
- **自訂主鍵型別時忘記 `[Key]`**：`Id` 已附帶 `[Key]`、`[Required]`。如果使用的 ORM 需依賴屬性來識別主鍵，則無需額外的註解。只有在重新定義時，才需要再次加上 `[Key]`。

## 背景資訊（選用）

`EntityBase` 在 `EntityBaseId` 的基礎上聚合了 5 個篩選介面（`ISafeDeletedFilter`、`ISafeEnabledFilter`、`ISafeCreatedFilter`、`ISafeUpdateFilter`、`IVersionedEntity`）。框架在產生 SQL 時會讀取這些介面，自動附加 `IsDeleted = 0`、`IsEnabled = 1`、樂觀鎖定等條件，因此業務端無需手動處理。`EntityTenantBase` 與 `EntitySelectBase` 則是以此為基礎，進一步疊加租戶隔離與擴充查詢篩選器的不同情境專用基底類別。
