# UI 닫기가 트리거되지 않을 때 어떻게 해야 하나요

`CloseUIForm`을 호출했는데 UI가 닫히지 않거나, `OnClose`가 호출되지 않거나, `CloseUIFormComplete` 이벤트가 발생(dispatch)되지 않는 경우, 대개는 전달한 시리얼 번호가 유효하지 않거나, UI가 로딩 중이거나, 패널 자체가 닫기 금지 상태이거나, 닫기 콜백이 애니메이션·리사이클 비활성화 스위치에 의해 차단되었기 때문입니다. 이 페이지에서는 증상별로 원인을 파악하는 진단 표와 수정 단계를 제공합니다.

## 빠른 진단

| 증상(콘솔/화면 표시) | 원인 | 수정 |
|---|---|---|
| 로그에 `Can not find UI form '{serialId}'.`가 출력됨 | 전달한 `serialId`가 현재 유효하지 않음(이미 닫힘, 열리지 않음, 또는 오타) | `GetAllLoadedUIForms()`로 실제 `SerialId`를 가져온 뒤 다시 전달 |
| 화면이 사라지지 않은 것처럼 보이지만 콘솔에 오류 없음 | UI가 아직 로딩 중이며, 로딩 큐의 "닫기 대기 리사이클" 목록에 병합됨 | 로딩 완료 후 자동 리사이클 대기; 또는 매니저의 이후 프레임에서 `ReleaseAllLoadedUIForms()` 호출 |
| `OnClose`가 호출되지 않았지만 이벤트는 이미 트리거됨 | UI에 `IsDisableClosing` 플래그가 설정됨 | 스크립트에서 `SetDisableClosing(true)`를 호출한 적이 있는지 점검하고, 닫기 전에 해제 |
| `CloseUIForm<T>` 호출 후 아무 반응 없음 | 제네릭 오버로드는 `FullName`으로 매칭되며, 다중 인스턴스 시나리오에서 매칭 실패 | `IUIForm` 참조를 직접 유지하거나, `serialId`로 닫도록 변경 |
| 닫은 후 UI가 다시 나타남 | `IsDisableRecycling = true`이면 인스턴스가 리사이클되지 않고 바로 오브젝트 풀로 돌아감 | 설정/스크립트에서 `IsDisableRecycling` 설정 확인 |
| 닫기 애니메이션 재생이 끝나도 UI가 사라지지 않음 | `EnableHideAnimation = true`일 때 `Hide` 콜백이 트리거되지 않음 | 커스텀 `Hide` 구현이 `Action onComplete`를 올바르게 콜백하는지 확인 |

> 위의 오류 메시지와 판단 분기는 모두 [BaseUIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L79-L223)에서 가져온 것입니다.

## 수정 단계

### 1. 전달한 `serialId` 또는 UI 참조가 유효한지 확인

`CloseUIForm(int serialId, ...)`는 먼저 `GetUIForm(serialId)`를 호출하며, 찾지 못하면 `Can not find UI form '{serialId}'.`를 출력하고 `return`합니다. **예외를 던지지 않습니다**. 구체적인 참조를 사용해 닫도록 변경하세요:

```csharp
// OpenUIForm 반환값으로 실제 SerialId 획득
int serialId = GameEntry.UI.OpenUIForm("UIPrefabs/LoginForm");
// 닫아야 할 때:
GameEntry.UI.CloseUIForm(serialId);
```

또는 `IUIForm` 참조를 직접 유지한 채 닫기 메서드를 호출하여, 외부에서 관리하는 ID에 의존하는 것을 피하세요.

출처: [BaseUIManager.Close.cs#L94-L104](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L94-L104)

### 2. UI가 아직 로딩 중인 경우

닫기 메서드를 호출할 때 대상 UI가 '로딩 중' 컬렉션(`IsLoadingUIForm(serialId)`가 참)에 속해 있으면, 매니저는 이를 `m_UIFormsToReleaseOnLoad`에 넣고 **바로 return하며, `OnClose`와 이벤트 콜백을 실행하지 않습니다**. 이 경우 나중에 `ReleaseAllLoadedUIForms()`를 호출하여 비동기 로딩이 완료된 직후 리사이클되도록 해야 합니다:

```csharp
GameEntry.UI.CloseUIForm(serialId);          // 이 시점에는 큐에 들어가기만 하고 실제로 닫히지 않을 수 있음
// Update에서 감지
GameEntry.UI.ReleaseAllLoadedUIForms(false);  // 로딩 완료 후 다시 리사이클 트리거
```

출처: [BaseUIManager.Close.cs#L161-L170](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L161-L170) 및 [BaseUIManager.Close.cs#L287-L299](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L287-L299)

### 3. 패널에서 닫기가 비활성화됨(`IsDisableClosing`)

닫기 로직은 이벤트를 발생시키기 전에 다음을 검사합니다:

```csharp
if (uiForm.IsDisableClosing)
{
    return;
}
```

스크립트에서 `SetDisableClosing(true)`가 잘못 남아 있는 경우(예: 팝업 확인 흐름에서 임시로 비활성화한 뒤 복원을 잊은 경우), `CloseUIForm`은 **아무런 반응 없이 조용히 종료됩니다**. 닫기 전에 직접 복원해 주세요:

```csharp
uiForm.SetDisableClosing(false);
GameEntry.UI.CloseUIForm(uiForm);
```

출처: [BaseUIManager.Close.cs#L172-L175](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L172-L175)

### 4. 제네릭 오버로드 `CloseUIForm<T>`가 매칭되지 않음

`CloseUIForm<T>`는 `typeof(T).FullName`으로 매칭하며, `HasUIFormFullName`이 매칭될 때만 실제로 닫습니다. 다중 인스턴스 시나리오에서는 첫 번째 매칭 인스턴스에 가로채진 후 바로 `break`될 수 있습니다. 비즈니스 측에서 `IUIForm` 참조를 직접 유지하는 것을 권장합니다.

```csharp
// 권장: 인터페이스 인스턴스를 직접 사용
IUIForm form = ...;
GameEntry.UI.CloseUIForm(form, userData: null, isNowRecycle: true);
```

출처: [BaseUIManager.Close.cs#L130-L149](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L130-L149)

### 5. 이벤트 구독이 트리거되지 않음

`CloseUIFormComplete`는 일반 .NET 이벤트로, 닫힐 때 콜백을 받으려면 먼저 `+=`로 구독해야 합니다. 이벤트 인자는 참조 풀에서 가져오며 사용 후 자동으로 회수되므로, 비즈니스 코드에서 `CloseUIFormCompleteEventArgs`를 캐싱하지 마세요:

```csharp
GameEntry.UI.CloseUIFormComplete += (sender, e) =>
{
    Debug.Log($"关闭界面: {e.UIFormAssetName}, SerialId={e.SerialId}");
};
```

출처: [BaseUIManager.Close.cs#L43-L57](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L43-L57) 및 [CloseUIFormCompleteEventArgs.cs#L43-L157](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/CloseUIFormCompleteEventArgs.cs#L43-L157)

### 6. 닫기 애니메이션과 리사이클의 연계

`EnableHideAnimation = true`이면, 닫을 때 먼저 `Hide(...)`를 호출하고 콜백 안에서 `OnClose`와 `Refresh`를 호출합니다. 커스텀 `Hide` 구현이 전달받은 `onComplete` 콜백 호출을 잊으면 `OnClose`와 이벤트 모두 실행되지 않습니다. 애니메이션과 함께 닫는 전체 흐름은 다음과 같습니다:

```csharp
uiGroup.RemoveUIForm(uiForm, true);   // 숨김으로 표시
uiForm.Hide(m_UIFormHideHandler, () =>
{
    uiForm.OnClose(m_IsShutdown, userData);
    uiGroup.Refresh();
    if (isNowRecycle)
        RecycleUIForm(uiForm, true);
});
```

단순히 즉시 파괴하고 싶다면(GameObject 포함) `isNowRecycle`을 `true`로 설정하세요. 매니저가 `RecycleUIForm`을 동기적으로 호출하여 리사이클 큐를 건너뜁니다.

출처: [BaseUIManager.Close.cs#L180-L202](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs#L180-L202)

## 검증

1. 닫기 인터페이스 호출 후, 로그에 `Can not find UI form '{serialId}'.`가 **더 이상** 나타나지 않아야 합니다.
2. `CloseUIFormComplete` 구독 함수가 최소 한 번 트리거되고, `OnClose` 라이프사이클이 호출되어야 합니다.
3. 닫은 후 다음 번 `GetAllLoadedUIForms()`에 해당 `SerialId`가 더 이상 포함되지 않아야 합니다(`IsDisableRecycling = true`인 경우 제외).
4. `m_UIFormsBeingLoaded`와 `m_UIFormsToReleaseOnLoad`가 비워졌는지 확인합니다(`CloseAllLoadingUIForms` / `ReleaseAllLoadedUIForms` 동작이 예상대로인지).
