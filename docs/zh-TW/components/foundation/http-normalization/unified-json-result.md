# 統一 JSON 回應格式的使用方法

`GameFrameX.Foundation.Http.Normalization` 提供 `HttpJsonResultData<T>` 作為 HTTP 介面的統一 JSON 回應包裝器。所有成功與失敗的回應都使用相同的欄位規約（`code` / `message` / `data` / `trackId` / `errorCode` / `type` / `time` / `extras`），前端只要依欄位名稱解析，即可取得一致的結構。

## 前置條件

- 在 .NET 專案中引用 `GameFrameX.Foundation.Http.Normalization`（命名空間 `GameFrameX.Foundation.Http.Normalization`）。
- 序列化請使用儲存庫隨附的 `GameFrameX.Foundation.Json.JsonHelper`，它會自動保留中文與 Emoji，避免被轉義。

## 操作步驟

### 1. 回傳成功回應（附帶資料）

呼叫泛型工廠方法 `HttpJsonResultData<T>.Success(data)`，並從控制器 / 處理常式直接回傳。

```csharp
using GameFrameX.Foundation.Http.Normalization;

[HttpGet("{id}")]
public HttpJsonResultData<UserInfo> GetUser(int id)
{
    var user = _repository.Find(id);
    return HttpJsonResultData<UserInfo>.Success(user);
}
```

序列化後大致如下：

```json
{
  "code": 0,
  "message": "",
  "data": { "id": 1, "name": "Alice" },
  "trackId": "",
  "time": 1714000000
}
```

> `code == 0` 即視為成功。`IsSuccess` 屬性會依此規則自動計算（不會包含在序列化結果中）。

來源：[HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L213-L220)

### 2. 回傳失敗回應（附帶錯誤訊息）

使用 `Fail(message)` / `Fail(code, message)` 工廠方法，或依語意選擇 `ParamError`、`Unauthorized`、`NotFound`、`ServerError` 等預先定義的錯誤工廠。

```csharp
[HttpGet("{id}")]
public HttpJsonResultData<UserInfo> GetUser(int id)
{
    if (id <= 0)
    {
        return HttpJsonResultData<UserInfo>.ParamError("id は 0 より大きくなければなりません");
    }

    var user = _repository.Find(id);
    if (user == null)
    {
        return HttpJsonResultData<UserInfo>.NotFound();
    }
    return HttpJsonResultData<UserInfo>.Success(user);
}
```

失敗回應範例：

```json
{
  "code": 403,
  "message": "id は 0 より大きくなければなりません",
  "trackId": "",
  "errorCode": "PARAM.ERROR",
  "type": "error",
  "time": 1714000000
}
```

來源：[HttpJsonResultConstants.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultConstants.cs#L31-L115)

### 3. 附加追蹤 ID 與業務錯誤碼

`TrackId` 用於將回應、日誌與下游呼叫關聯起來。`ErrorCode` 是穩定的業務錯誤碼字串（與 `Code` 在語意上相互正交）。兩者皆可在建立後賦值。

```csharp
var result = HttpJsonResultData<OrderDto>.Fail(HttpJsonResultConstants.ValidationErrorCode, "注文は既に閉じられています");
result.TrackId = Activity.Current?.TraceId.ToString();
result.ErrorCode = "ORDER.CLOSED";
result.Type = "error";
result.Extras = new { orderId = 42, closedAt = DateTime.UtcNow };
return result;
```

> `extras` 僅在非 null 時才會包含於序列化結果。`errorCode` / `type` 亦同。

來源：[HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L128-L186)

### 4. 直接取得 JSON 字串

當介面需要直接輸出 JSON 文字時（中介軟體 / 舊框架），可使用 `SuccessString()` / `FailString()`，或先建構再呼叫 `.ToString()`。內部會使用 `JsonHelper.Serialize`。

```csharp
return HttpJsonResultData<UserInfo>.SuccessString();
// 或
return HttpJsonResultData<UserInfo>.Fail("サービスは一時的に利用できません").ToString();
```

來源：[HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L229-L232)

## 常見變化情境

| 情境 | 建議用法 | 說明 |
|------|----------|------|
| 只關心成功/失敗布林值時 | `IsSuccess` 屬性 | `JsonIgnore`，專供伺服器端短路判斷使用 |
| 需要包裝既有任意型別時 | `HttpJsonResultData<T>.Success(obj)` | 泛型 `T` 無任何約束，可傳入任意參考/實值型別 |
| 將第三方 API 回應轉換為統一結構 | `IHttpJsonResult` 介面 | `Data` 回傳序列化後的 JSON 字串，便於跨型別使用 |
| 失敗但仍想保留部分資料時 | `Fail(code, message, data)` 多載 | `data` 欄位會回傳給前端 |

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `IsSuccess` 永遠為 `false` | 在 `Code` 設定了業務錯誤碼字串或非 0 的整數 | 成功僅使用 `0`，其他值一律視為失敗 |
| 中文被轉義為 `\uXXXX` | 未使用 `JsonHelper.Serialize` | 一律透過 `.ToString()` 或工廠方法回傳，交由內部統一序列化 |
| 用戶端無法取得 `extras` | 欄位值為 `null` | 明確賦予非 null 物件；若為 null 則不進行序列化屬預期行為 |
| `code` 與 `errorCode` 混淆 | 將 HTTP 狀態碼寫入 `ErrorCode` | `Code` 使用 HTTP/狀態的語意（數值），`ErrorCode` 使用穩定的業務字串 |

## 驗證

1. 介面啟動後以 `curl` 呼叫，確認回傳的 JSON 同時包含 `code`、`message`、`data` 三個核心欄位。
2. 觸發失敗分支，確認 `code` 不為 0、`message` 含有易讀的說明文字，且 `IsSuccess` 在伺服器端短路判斷中回傳 `false`。
3. 若已啟用 `TrackId`，確認回應、日誌與呼叫鏈中出現相同的 `trackId` 值。

## 背景

- `IHttpJsonResult` 會將 `HttpJsonResultData<T>` 的 `Data` 序列化為 JSON 字串，藉此吸收泛型差異，使其可在非泛型情境（中介軟體、日誌攔截器等）中統一處理。
- `HttpJsonResultConstants` 統一管理 `SuccessCode=0`、`FailCode=-1`、`ValidationErrorCode=400`、`UnauthorizedCode=401`、`ParamErrorCode=403`、`NotFoundCode=404`、`ServerErrorCode=500` 等數值與預設訊息常數，避免魔術數字散落於業務端。
- `IsSuccess` 已改為唯讀屬性並由 `Code` 自動計算，因此建構時無須手動管理成功旗標。
