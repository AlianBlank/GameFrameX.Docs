# 如何配置 AssemblyResourceProvider 提供资源

`AssemblyResourceProvider` 是 GameFrameX 本地化框架中的程序集级资源提供者,负责从 .NET 程序集嵌入的 `.resources` 文件里加载本地化字符串,并在首次访问时懒加载,完成后即可像内置资源一样通过 `LocalizationService.GetString(...)` 取出字符串。本页说明如何在自定义程序集里准备资源文件、构造该提供者并接入 `ResourceManager`。

## 前置条件

- 已安装 `GameFrameX.Foundation.Localization` NuGet 包。
- 目标项目是 .NET 程序集,且 `.resx` 需要作为 `EmbeddedResource` 内嵌进程序集清单(否则 `GetManifestResourceNames()` 不会返回这些条目,提供者扫描不到任何内容)。

## 操作步骤

1. 在项目中按约定路径创建 `.resx` 文件。默认约定放在 `Localization/Messages/` 目录下,文件名按文化拆分(具体命名规则见下文)。

   ```text
   {AssemblyName}/
   └── Localization/
       └── Messages/
           ├── Resources.resx         # 默认/英文兜底
           ├── Resources.zh-CN.resx   # 简体中文
           └── Resources.en-US.resx   # 美式英语
   ```

   Source: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L216-L223)

2. 在 `.csproj` 中显式将 `.resx` 标记为 `EmbeddedResource`,并按需关闭默认的隐式嵌入,避免依赖编译器自动行为:

   ```xml
   <PropertyGroup>
     <EnableDefaultEmbeddedResourceItems>false</EnableDefaultEmbeddedResourceItems>
   </PropertyGroup>

   <ItemGroup>
     <EmbeddedResource Include="Localization\Messages\*.resx" />
   </ItemGroup>
   ```

   Source: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L110-L118)

3. 按命名约定命名资源文件,使提供者能正确解析 `baseName`。框架识别的清单资源名规则如下(取自 `TryGetBaseName`):

   | 清单资源名示例 | 解析后的 baseName | 用途 |
   |---|---|---|
   | `MyApp.Localization.Messages.Resources.resources` | `MyApp.Localization.Messages.Resources` | 默认文化 |
   | `MyApp.Localization.Messages.Resources.zh-CN.resources` | `MyApp.Localization.Messages.Resources` | 特定文化 `zh-CN` |
   | `MyApp.CustomPath.Resources.resources` | `MyApp.CustomPath.Resources` | 自定义路径默认文化 |
   | `MyApp.CustomPath.Resources.en.resources` | `MyApp.CustomPath.Resources` | 自定义路径中性文化 |
   | `MyApp.Category.resources` | `MyApp.Category` | 向后兼容的三段式 |

   规则要点:以 `.resources` 结尾、倒数第二段是 `Resources` 或合法文化名(含 `-` 或能被 `CultureInfo.GetCultureInfo` 识别)。段数 ≥ 3 才能被识别。

   Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L282-L330)

4. 在代码里构造提供者并触发加载。`AssemblyResourceProvider` 是 `IDisposable`,使用完后应释放。

   ```csharp
   using System.Reflection;
   using GameFrameX.Foundation.Localization.Providers;

   var assembly = Assembly.GetExecutingAssembly();
   using var provider = new AssemblyResourceProvider(assembly);

   // 可选: 提前触发懒加载,避免首次访问延迟
   provider.EnsureLoaded();

   string message = provider.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L104-L138)

5. 接入 `ResourceManager` 以纳入统一解析链。`ResourceManager` 会按"自定义 → 程序集 → 默认"顺序查找,你可以让框架自动发现所有程序集提供者,或在初始化后手动注册指定程序集:

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // 方式一: 让 ResourceManager 自动扫描当前已加载程序集
   LocalizationService.EnsureLoaded();

   // 方式二: 手动追加指定程序集
   LocalizationService.AddAssembly(Assembly.GetExecutingAssembly());

   var msg = LocalizationService.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   Source: [ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L370-L450)

## 常见变体

- **中性文化名**(如 `zh`、`fr`):当倒数第二段是中性文化名时,`IsCultureSegment` 通过 `CultureInfo.GetCultureInfo` 校验其有效性,避免把 `MyApp` 这种类别名误判为文化名。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L332-L360)

- **自定义路径**(非 `Localization/Messages/`):只要满足 `{AssemblyName}.{任意路径}.Resources[.{culture}].resources` 的段结构,就会被识别。例如 `MyApp.LangPack.Resources.zh-CN.resx` → baseName `MyApp.LangPack.Resources`。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L256-L268)

- **未找到键时的兜底**:任何 `GetString` 调用在所有 `ResourceManager` 中都没有匹配时,直接返回传入的 `key` 字符串,不会抛出异常。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L146-L178)

## 常见错误

- **资源没生效**:最常见原因是 `.resx` 没有作为 `EmbeddedResource` 嵌入,或者文件名不符合上述命名约定。运行 `assembly.GetManifestResourceNames()` 验证清单里是否包含期望的名字。
- **同一程序集里出现多个同名 baseName**:`LoadResources` 会按 `BaseName` 去重,只保留第一个匹配的 `ResourceManager`,后续同名条目会被忽略。
- **`GetString` 抛 `MissingManifestResourceException`**:代码已捕获并继续查找其他 `ResourceManager`,通常不会冒泡;若日志看到 `Failed to load resource '{key}'`,说明所有匹配者都失败,会返回 `key` 作为兜底。
- **程序集扫描失败**:整个扫描被 `try/catch` 包裹并写入 `Debug.WriteLine`,不会抛出;但 `_isInitialized` 会被标记为 `true` 防止反复重试,需检查调试输出定位根因。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L204-L279)

## 背景(可选)

`AssemblyResourceProvider` 实现了 `ILazyResourceProvider`、`ICultureResourceProvider`、`IDisposable`。构造时不立即加载资源,首次调用 `EnsureLoaded()` 或 `GetString()` 时才扫描程序集清单并按 `baseName` 去重创建 `ResourceManager`。`ResourceManager` 维护一个以 `assembly.FullName` 为键的 `ConcurrentDictionary<string, AssemblyResourceProvider>`,对外呈现"自定义提供者 > 程序集提供者 > 默认提供者"的优先级链。关于整体资源解析链与统计接口,见 [ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs)。
