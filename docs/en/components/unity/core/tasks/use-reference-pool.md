# Using Reference Pool to Reduce GC Allocation

The reference pool (`ReferencePool`) caches object instances that implement the `IReference` interface. You can acquire them via `Acquire` and return them via `Release` for reuse, avoiding the GC pressure caused by repeated `new`. This page provides the complete steps for integrating the reference pool into GameFrameX and using it for custom types.

## Prerequisites

- The project has imported `GameFrameX.Runtime.Base.ReferencePool` and `GameFrameX.Runtime.ReferencePoolComponent` (included with the framework by default).
- A `ReferencePoolComponent` is attached in the scene (via menu `Add Component → GameFrameX → ReferencePool`), or you can access it directly through the static class `ReferencePool` in code.

## Steps

1. **Make your custom type implement `IReference`**. The type must have a parameterless constructor and reset its fields in `Clear()` to ensure a clean state when retrieved next time.

   ```csharp
   using GameFrameX.Runtime;

   public sealed class DamageInfo : IReference
   {
       public int AttackerId { get; private set; }
       public int TargetId   { get; private set; }
       public float Amount  { get; private set; }

       public void Clear()
       {
           AttackerId = 0;
           TargetId   = 0;
           Amount     = 0f;
       }

       internal void Fill(int attackerId, int targetId, float amount)
       {
           AttackerId = attackerId;
           TargetId   = targetId;
           Amount     = amount;
       }
   }
   ```

   Source: [Tests/ReferencePoolTests.cs#L11-L29](/src/Tests/ReferencePoolTests.cs#L11-L29)

2. **Acquire an instance**. The generic version requires no manual cast; when the pool is empty, the framework calls the parameterless constructor to create a new instance.

   ```csharp
   DamageInfo info = ReferencePool.Acquire<DamageInfo>();
   ```

   Signature: `public static T Acquire<T>() where T : class, IReference, new()`, see [Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L128-L132).

3. **Release the instance**. `Clear()` is automatically called when releasing, but field-level reset is still handled by your `Clear()`.

   ```csharp
   ReferencePool.Release(info);
   ```

   Signature: `public static void Release(IReference reference)`, see [Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L156-L167). Passing `null` throws `GameFrameworkException("Reference is invalid.")`, see [Tests/ReferencePoolTests.cs#L79](/src/Tests/ReferencePoolTests.cs#L79).

4. **(Optional) Pre-warm the pool capacity before startup**. Call `Add<T>(count)` at the start of a battle/level to avoid runtime expansion.

   ```csharp
   ReferencePool.Add<DamageInfo>(64);
   ```

   Signature: `public static void Add<T>(int count) where T : class, IReference, new()`, see [Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L177-L181).

5. **(Optional) Inspect pool status**. Read the cache information for each type in the debug panel or Profiler hook.

   ```csharp
   ReferencePoolInfo[] infos = ReferencePool.GetAllReferencePoolInfos();
   foreach (var info in infos)
   {
       UnityEngine.Debug.Log($"{info.Type.Name}: using={info.UsingReferenceCount} unused={info.UnusedReferenceCount}");
   }
   ```

   Signature see [Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L80-L98).

## Common Variants

- **Acquire by `Type` at runtime** (when generics are not available):

  ```csharp
  IReference info = ReferencePool.Acquire(typeof(DamageInfo));
  ```

  See [Runtime/Base/ReferencePool/ReferencePool.cs#L142-L147](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L142-L147).
- **Pre-warm by `Type`**:

  ```csharp

  ```
- **Clear all** (when switching scenes or exiting battle):

  ```csharp
  ReferencePool.ClearAll();
  ```

  See [Runtime/Base/ReferencePool/ReferencePool.cs#L106-L118](/src/Runtime/Base/ReferencePool/ReferencePool.cs#L106-L118).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GameFrameworkException: Reference is invalid.` | Passed `null` to `Release` | Check for null before Release, or return within `using`/`try-finally` block |
| Retrieved object retains data from last use | `Clear()` did not reset fields | Explicitly reset all fields to default values in `Clear()` |
| Type cannot be `Acquire`d | Type does not implement `IReference` or lacks a `public` parameterless constructor | Implement the interface and add a parameterless constructor |
| Profiler shows pool growing out of control | Keep acquiring without releasing | Ensure Release on all usage-completion paths (including exception branches); use `try { ... } finally { Release(info); }` |
| Performance drops after enabling strict check | `ReferencePool.EnableStrictCheck = true` enables reflection validation | Enable only during debugging; disable for release builds |

## Background (Optional)

Each CLR type has its own `ReferenceCollection` within the pool, internally maintaining a `Stack<IReference>`. `Acquire` pops from the stack first, and only `new`s when the stack is empty; `Release` calls `Clear()` then pushes onto the stack. Enabling `EnableStrictCheck` validates types via reflection, affecting performance, and is intended for debugging only.
