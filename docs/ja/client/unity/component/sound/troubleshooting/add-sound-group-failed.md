# サウンドグループが既に存在する / 追加に失敗する場合の対処法

`SoundComponent` の `AddSoundGroup` を呼び出した際に `false` が返される、または `GameFrameworkException` がスローされる場合、通常はグループ名の重複または名前の不正が原因です。このページでは、迅速な切り分けと修正手順を紹介します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `AddSoundGroup` が `false` を返す(例外なし)| 同名のサウンドグループが既に存在する | まず `HasSoundGroup` で判定し、既に存在する場合は追加しない |
| `GameFrameworkException: Sound group name is invalid.` がスローされる | サウンドグループ名が `null`、空文字列、または空白のみ | 前後の空白を除去した空でないグループ名を渡す |
| エディターの Inspector に追加したばかりのグループが表示されない | グループは実行時にコードで追加されたものであり、Inspector には反映されない | 実行時デバッグ専用。永続化が必要な場合は Inspector で事前に設定する |
| 追加後すぐに再生しても音が出ない | 追加には成功したが `AgentHelperCount` が未設定、または音量がミュートされている | パラメーター `soundGroupMute` / `soundGroupVolume` を確認する |

## 修正手順

### 1. 追加前に既に存在するか判定する

`AddSoundGroup` は同名のグループが既に存在する場合、直接 `false` を返します。まず `HasSoundGroup` でガードすることをおすすめします:

```csharp
using GameFrameX.Sound.Runtime;

const string groupName = "UI";

if (!GameEntry.Sound.HasSoundGroup(groupName))
{
    GameEntry.Sound.AddSoundGroup(groupName, false, false, 1f, new DefaultSoundGroupHelper());
}
```

API シグネチャは [ISoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Interface/ISoundManager.cs#L77-L104) を参照してください:

- `bool HasSoundGroup(string soundGroupName)`
- `bool AddSoundGroup(string soundGroupName, ISoundGroupHelper soundGroupHelper)`
- `bool AddSoundGroup(string soundGroupName, bool soundGroupAvoidBeingReplacedBySamePriority, bool soundGroupMute, float soundGroupVolume, ISoundGroupHelper soundGroupHelper)`

実装は [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L167-L255) にあります。

### 2. 「グループ名が不正」例外への対処

ソースコードでは、グループ名が空の場合に直接例外をスローします:

```csharp
if (string.IsNullOrWhiteSpace(soundGroupName))
{
    throw new GameFrameworkException("Sound group name is invalid.");
}
```

修正方法：呼び出し前に検証を行います:

```csharp
string groupName = inputName?.Trim();
if (string.IsNullOrEmpty(groupName))
{
    // 独自のフォールバックロジックに従う。例えばデフォルトグループ "Sound" を使用する
    groupName = "Sound";
}
GameEntry.Sound.AddSoundGroup(groupName, new DefaultSoundGroupHelper());
```

例外のスロー箇所については [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L171-L186) を参照してください。

### 3. 大文字小文字や前後の空白による「存在しないように見える」問題への対処

`HasSoundGroup` / `AddSoundGroup` は内部でリテラル文字列をキーとして使用します([SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L167-L186) を参照)。`"UI"` と `"ui"`、`" UI "` は異なるグループとして扱われるため、追加に失敗したと思い込んでしまいますが、実際には重複したグループが追加されています。

修正方法：呼び出し前に `Trim()` を統一的に行い、大文字小文字のルールを決めます。例えば、すべて `ToLowerInvariant()` を使用するか、プロジェクトで定めた命名規則に従います。

### 4. 重複初期化を避ける一般的なパターン

「存在を保証する」処理をヘルパーメソッドとしてカプセル化し、一元管理します:

```csharp
public static void EnsureSoundGroup(string name, bool mute = false, float volume = 1f)
{
    var sound = GameEntry.Sound;
    if (sound.HasSoundGroup(name))
    {
        return;
    }
    sound.AddSoundGroup(name, false, mute, volume, new DefaultSoundGroupHelper());
}
```

シーン切り替えやモジュール起動などの入口で `EnsureSoundGroup("Music")`、`EnsureSoundGroup("SFX")`、`EnsureSoundGroup("UI")` を統一的に呼び出し、業務コードがそれぞれ個別に追加して重複が発生するのを防ぎます。

## 動作確認

1. 追加ロジックの前後でそれぞれログを出力し、`HasSoundGroup` の戻り値が想定どおりであることを確認します(追加前は `false`、追加後は `true`)。
3. 同名のグループに対して再度 `AddSoundGroup` を呼び出すと、`false` が返され、例外はスローされないはずです。
2. 空文字列 / `null` で一度例外パスを発生させ、例外メッセージが `Sound group name is invalid.` であることを確認します。これにより、後のトラブルシューティングで識別しやすくなります。
