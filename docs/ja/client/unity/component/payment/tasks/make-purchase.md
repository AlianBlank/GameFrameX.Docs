# 購入を開始する方法（アプリ内課金とサブスクリプション）

`PaymentComponent.Buy(PurchaseParams)` を呼び出し、`OnPurchaseSuccess` / `OnPurchaseFailed` イベントを監視することで、一回限りのアプリ内課金とサブスクリプション商品の購入を行えます。サーバー検証が通った後に `ConsumePurchase` を呼び出して注文を消費します。旧来の `BuyInApp` / `BuySubs` インターフェースは `[Obsolete]` としてマークされているため、`Buy(PurchaseParams)` への統一使用を推奨します。

## 前提条件

- シーンに `PaymentComponent` がアタッチされていること（コンポーネントメニューのパスは `GameFrameX/Payment`）。これにより `GameFrameXPaymentCroppingHelper` が自動的に付属します：

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
public class PaymentComponent : GameFrameworkComponent
```

出典： [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

- ターゲットプラットフォームに応じた対応チャネル実装パッケージが導入済みであること。`PaymentComponent.Awake()` はコンパイルマクロに基づいて実装クラスを自動的に選択します（Android → `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`、iOS → `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`、その他のプラットフォームは `DefaultPaymentManager` にフォールバック）。

出典： [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 操作手順

1. **定義済み商品 ID を設定する**（任意ですが推奨）。商品キャッシュのプリロードに使用されます。**`Init()` の前に必ず呼び出してください**：

```csharp
payment.SetPredefinedProductIds(
    new List<string> { "gem_100", "gem_500" },      // アプリ内課金商品IDのリスト
    new List<string> { "vip_monthly" });             // サブスクリプション商品IDのリスト
```

出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

2. **決済システムを初期化する**：

```csharp
// isDebug：サンドボックスモードかどうか。isClientVerify：クライアント側で購入検証を行うかどうか
payment.Init(isDebug: false, isClientVerify: false);
```

出典： [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

| パラメータ | 型 | デフォルト値（コンポーネント層） | 説明 |
|------|------|------------------|------|
| `isDebug` | `bool` | `false` | サンドボックス購入を使用するかどうか |
| `isClientVerify` | `bool` | `true`（`PaymentComponent`）；`false`（`IPaymentManager`） | クライアント側で購入を検証するかどうか。サーバー検証を使用する場合は `false` に設定してください |

出典： [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L102-L102)、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

3. **購入結果イベントを購読する**（初期化の前後で一度に設定しておくことを推奨）：

```csharp
payment.OnPurchaseSuccess += (sender, e) =>
{
    Debug.Log($"购买成功: {e.ProductId}, OrderId={e.OrderId}");
    // サーバー検証が通った後に注文を消費します：
    // payment.ConsumePurchase(e.PurchaseToken);
};
payment.OnPurchaseFailed += (sender, e) =>
    Debug.Log($"购买失败: {e.ResultCode}, {e.ErrorMessage}");
```

イベントシグネチャの出典：[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L18-L26)。コンポーネント層での同名の転送は [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L46) を参照してください。

4. **決済システムの準備を確認してから購入を開始する**：`payment.IsReady()` を呼び出し、`false` が返された場合は `Buy` を呼び出さないでください。

出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L45-L49)

5. **`PurchaseParams` を構築して `Buy` を呼び出す**。`PurchaseParams` は抽象基底クラス（コンストラクタは `protected`）であり、直接 `new` することはできません。各チャネルはそのサブクラスを使用してチャネル固有のパラメータ（サブスクリプションに必要な `offerToken` など）を渡します。チャネルパッケージがサブクラスを提供していない場合は、独自に継承できます：

```csharp
public sealed class MyPurchaseParams : PurchaseParams
{
    public MyPurchaseParams(string productId, string orderId, PaymentProductType productType)
        : base(productId, orderId, productType) { }
}

// 購入を開始（productType にはアプリ内課金/サブスクリプションに対応する列挙値を指定。定義は Runtime/PaymentProductType.cs を参照）
payment.Buy(new MyPurchaseParams("gem_100", "order_20240101_001", productType));
```

出典： [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)（基底クラスの定義）、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112)（推奨エントリーポイント）

6. **サーバー検証が通った後に購入を消費する**。一回限りの商品は、消費しないと再度購入できません：

```csharp
payment.ConsumePurchase(e.PurchaseToken);   // PurchaseToken は OnPurchaseSuccess の PaymentEventArgs から取得します
```

出典： [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L140-L152)

`PaymentEventArgs` が保持するフィールド（サーバー検証への送信に使用）：

| フィールド | 型 | 説明 |
|------|------|------|
| `ProductId` | `string` | 商品 ID |
| `OrderId` | `string` | 注文 ID |
| `PurchaseToken` | `string` | 購入トークン（注文の消費用） |
| `ResultCode` | `PaymentResultCode` | 決済結果コード |
| `ErrorMessage` | `string` | エラーメッセージ |
| `PurchaseData` | `string` | 生の購入データ（JSON 形式） |
| `CustomData` | `string` | カスタムデータ |

出典： [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

## よくあるバリエーション

- **履歴注文の照会 / 購入の復元**：`payment.QueryPurchases(PaymentProductType.枚举值)` を呼び出すと、結果は `OnQueryPurchasesResult` イベントで返され、イベント引数も同じく `PaymentEventArgs` です。
  出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L51-L56)、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L28-L31)
- **旧インターフェース（非推奨）**：`BuyInApp(productId, orderId, offerToken = "", customData = "")` と `BuySubs(productId, orderId, offerToken = "", customData = "")` はそれぞれ一回限りの商品とサブスクリプション商品に対応します。両者とも `[Obsolete("请使用 Buy(PurchaseParams) 替代")]` とマークされており、新しいコードでは使用しないでください。
  出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L72-L93)
- **カスタムデータのパススルー**：旧インターフェースでは `customData` パラメータでパススルーし、イベントコールバックで `PaymentEventArgs.CustomData` として読み戻します。新しい `Buy(PurchaseParams)` エントリーポイントでは、対応するフィールドは各チャネルのサブクラスによって拡張されます。

## よくあるエラー

| 症状 / ログ | 原因 | 修正 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` が空を返す | プラットフォーム実装クラス名の設定（`PaymentComponent` の Inspector 内の `m_componentXxxType`）とチャネルパッケージの導入状況を確認してください |
| `Log.Warning("Product ID is null or empty.")` | 旧 `Buy*` インターフェースの呼び出し時に `productId` が空 | 空でない商品 ID を渡してください |
| `Log.Warning("Order ID is null or empty.")` | 旧 `Buy*` インターフェースの呼び出し時に `orderId` が空 | 空でない注文 ID を渡してください |
| `Log.Warning("Purchase token is null or empty.")` | `ConsumePurchase` に空の token を渡した | `OnPurchaseSuccess` イベントの `e.PurchaseToken` を使用してください |
| `SetPredefinedProductIds` が有効にならない | `Init()` の後に呼び出している | `Init()` の前に移動してください |
| 一回限りの商品の再購入が失敗する（`ItemAlreadyOwned`） | 前回の購入が未消費 | サーバー検証が通った後に `ConsumePurchase` を呼び出してください。`ItemNotOwned`、`VerifyFailed`、`NetworkError` などの結果コードは `PaymentResultCode` 列挙型を参照してください |

出典： [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93)、[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L117-L152)、[PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L14-L25)

## 背景

`PaymentComponent` はファサードであり、パラメータの検証とイベントの転送のみを行い、実際のロジックはプラットフォームに応じて解決された `IPaymentManager` 実装（Google / Apple / WebGL / PC / Default）によって処理されます。購入結果は `PaymentEventArgs` を通じて統一的に送出され、`PaymentResultCode` が成功、キャンセル、ネットワークエラー、所有済みなどの状況を区別するため、各プラットフォームで同一の上位層処理コードを再利用しやすくなっています。
