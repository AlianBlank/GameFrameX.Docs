# 如何在 FixedUpdate 中驱动 FSM

在 `FsmState<T>` 中重写 `OnFixedUpdate` 即可让状态机在 Unity 的物理帧(`FixedUpdate`)中被驱动;框架的 `FsmComponent` 已经把 Unity 的 `FixedUpdate` 自动转发到所有已注册 FSM,无需手动调用。

## 前置条件

- 已将 `FsmComponent` 挂到游戏入口 GameObject 上(Add Component → `GameFrameX/FSM`),框架会在 `Awake` 中获取 `IFsmManager`。
- 业务侧已经创建好状态机:`GameFrameworkFsm` 或 `FsmComponent.CreateFsm`,见 `FsmComponent.cs`。
- 至少定义了一个继承 `FsmState<T>` 的状态类。

## 操作步骤

1. 在状态类中重写 `OnFixedUpdate`,接收物理帧的 `elapseSeconds` 与 `realElapseSeconds`。

```csharp
using GameFrameX.Fsm;

public class PlayerRunState : FsmState<Player>
{
    protected internal override void OnFixedUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // elapseSeconds 即 Time.fixedDeltaTime,realElapseSeconds 即 Time.fixedTime
        var rb = fsm.Owner.GetComponent<Rigidbody>();
        rb.MovePosition(rb.position + fsm.Owner.MoveDirection * fsm.Owner.Speed * elapseSeconds);
    }
}
```

Source: [FsmState.cs#L75-L89](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L75-L89)

2. 创建状态机时把这个状态加入状态集合,并让 FSM 启动到该状态。

```csharp
var fsm = GameEntry.GetComponent<FsmComponent>().CreateFsm<Player>(
    owner: this,
    states: new FsmState<Player>[]
    {
        new PlayerIdleState(),
        new PlayerRunState(),
        new PlayerJumpState(),
    });

fsm.Start<PlayerRunState>();
```

3. 无需在业务代码中再写 `Update`/`FixedUpdate` 调用。`FsmComponent.FixedUpdate` 会把 `Time.fixedDeltaTime` 与 `Time.fixedTime` 转发给管理器:

```csharp
private void FixedUpdate()
{
    if (m_FsmManager == null) return;
    m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
}
```

Source: [FsmComponent.cs#L76-L84](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

4. 管理器层会对所有未销毁的 FSM 调用 `FixedUpdate`,最终路由到当前状态的 `OnFixedUpdate`:

```csharp
public void FixedUpdate(float fixedDeltaTime, float fixedTime)
{
    // ...遍历 m_Fsms,对每个未销毁的 FSM 调用 FixedUpdate
}
```

Source: [FsmManager.cs#L110-L130](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L110-L130)

5. `Fsm<T>.FixedUpdate` 仅触发当前状态的回调,其它状态不会执行:

```csharp
internal override void FixedUpdate(float elapseSeconds, float realElapseSeconds)
{
    m_CurrentStateTime += elapseSeconds;
    m_CurrentState.OnFixedUpdate(this, elapseSeconds, realElapseSeconds);
}
```

## 常见变体

- 想在 `FixedUpdate` 中切换状态,调用 `ChangeState<TState>()` 即可;切换时机应放在 `OnFixedUpdate` 内,避免与逻辑帧的 `OnUpdate` 交错。
- 同时需要逻辑帧行为时,重写 `OnUpdate`;两者互不影响,各自按各自帧率被调用。
- 物理相关计算(施力、速度积分)放在 `OnFixedUpdate`;输入响应、动画参数放在 `OnUpdate`,时序更稳定。

## 常见错误

- **手动再次调用 `fsm.FixedUpdate(...)`**:`FsmBase.FixedUpdate` 是 `internal`,只能由管理器触发;业务侧重复驱动会导致状态在一帧内被推进两次。
- **忘了 `Start<...>()`**:未启动的 FSM 没有 `CurrentState`,`OnFixedUpdate` 不会被触发,也不会报错。
- **在 `OnFixedUpdate` 里读 `Time.deltaTime`**:`elapseSeconds` 已经固定为 `Time.fixedDeltaTime`,读 `Time.deltaTime` 会引入逻辑帧抖动。

## 背景(可选)

框架把 Unity 的 `MonoBehaviour.FixedUpdate` 钩到管理器,管理器再把物理帧时间广播给所有 FSM;每个 FSM 只把这次回调派发给当前 `FsmState<T>`,从而实现"物理帧驱动 + 当前态响应"。`OnFixedUpdate` 与 `OnUpdate` 共存,前者由 `FsmComponent` 的 `FixedUpdate` 触发,后者由 `Update` 触发,二者参数语义不同但调用入口对称。
