# What to Do When You Still Read Old Values After Modifying Channel Configuration

When you've modified `application_config.txt`, AndroidManifest meta-data, or the iOS Info.plist, but `BlankGetChannel.GetChannelName()` still returns the old value, it's almost always one of two causes: the in-process static cache `ChannelCache` hits and no longer re-reads, or the configuration was baked into the package at build time, so modifying the disk file has no effect on the built application.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Changed `application_config.txt` under Editor/PC/WebGL, but `GetChannelName()` still returns the old value | The static dictionary `ChannelCache` returns directly on a hit and no longer reads the file | Exit Play Mode and re-enter (triggering a script domain reload); see "Clear the In-Process Cache" below |
| Changed the file in Editor, still old value after restarting Play Mode | Unity has not re-imported the TextAsset yet; `Resources.Load` still gets the old asset | Switch back to the Editor window and wait for re-import, or right-click the file and `Reimport`, then enter Play Mode |
| Modified the config file after building (Standalone/WebGL), but the channel in the app doesn't change | `Resources/application_config.txt` was baked into the package at build time | Modify `Assets/Resources/application_config.txt`, rebuild, and reinstall over the existing installation |
| Changed AndroidManifest meta-data on Android but it didn't take effect | The meta-data is already compiled into the APK, and the first read result is already cached | Rebuild and install the package after modifying the manifest; cannot be refreshed at runtime |
| After rebuilding for iOS, the channel is still `default` or the old value | `PostProcessBuildHandler` only writes when the `channel` key **does not exist** in Info.plist; existing values are skipped | Delete or modify the `channel` key in Info.plist in Xcode, then rebuild; see below |
| On iOS, returns `unknown` when the key isn't configured, instead of the C#-side `default` | The native `getChannelName` always returns `unknown` when the key is not found | Add the corresponding key to Info.plist |
| Config value contains `=`, and the read value is truncated | The parser splits on `=` and only takes the second segment | Avoid using `=` in values; see "Truncated Value" below |

## Fix Steps

### Clear the In-Process Cache (the most common root cause)

The first thing `GetChannelName` does is check the static cache; on a hit it returns immediately, and the subsequent reading logic is completely skipped:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
{
    if (ChannelCache.TryGetValue(channelKey, out var value))
    {
        return value;
    }

    string channelName = defaultValue;
    ...
    ChannelCache[channelKey] = channelName;
    return channelName;
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98-L141)

The cache dictionary is `private static readonly`, and the repository provides no public API to clear the cache, so **it cannot be refreshed at runtime**. The only option is to let the static field be rebuilt along with the domain/process:

1. In Editor: exit Play Mode → wait for compilation/domain reload to finish → re-enter Play Mode and read again.
2. On device/Standalone: quit the application process and restart it (this only resolves the cache issue; if the configuration itself is inside the package, you also need to rebuild per the sections below).

Also note a side effect: under the Editor/PC branch, the first read writes **all** `key=value` pairs from `application_config.txt` into the cache at once (see [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L107-L121)). Therefore, after modifying the file, even if you query with a different channelKey, you'll still get the old content from the first load.

### Editor/PC/WebGL: Get Resources to Reload

These platforms read via `Resources.Load<TextAsset>("application_config")`, i.e. `Assets/Resources/application_config.txt`:

1. Confirm the file path is `Assets/Resources/application_config.txt` (it can load without an extension; content is line-based `key=value`).
2. After saving your changes, click the Unity window to trigger re-import (or right-click the file → `Reimport`).
3. Restart Play Mode per "Clear the In-Process Cache".
4. Built packages: modifying the file on disk has no effect; you must modify `Assets/Resources/application_config.txt` and rebuild.

### Android: Rebuild the Package After Modifying meta-data

The Android channel comes from a static call to a native class, and the first result likewise goes into the cache:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

After modifying the corresponding meta-data in AndroidManifest.xml, you need to rebuild the APK/AAB and reinstall it; it will not refresh automatically in-process.

### iOS: Handling PostProcessBuild's "Skip Setting"

The iOS post-build process only writes `default` when Info.plist lacks the `channel` key; if a value already exists, it skips directly:

```csharp
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

To change the channel value: directly modify or delete the `channel` key in the Xcode project's Info.plist (after deletion, this handler logic will write it again), then rebuild to the device. Also note that the native layer's default return value is `unknown`:

```objc
char * getChannelName(char * channel_name) {
    NSString* channel_name_String=  [NSString stringWithUTF8String:channel_name];
    NSString* File = [[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"];
    NSMutableDictionary* dict = [[NSMutableDictionary alloc] initWithContentsOfFile:File];
    NSString * channel_value =  [dict objectForKey:channel_name_String];
    if (channel_value != nil) {
        return StringToCharArray(channel_value);
    }
    channel_value = @"unknown";
    return StringToCharArray(channel_value);
}
```

Source: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

### Truncated Value: Check the Configuration Line Format

The parsing logic splits each line on `=`, takes only the second segment, and `Trim()`s it:

```csharp
var split = line.Split(new string[] { "=" }, StringSplitOptions.RemoveEmptyEntries);
if (split.Length > 1)
{
    var key = split[0].Trim();
    var channelValue = split[1].Trim();
    ChannelCache[key] = channelValue;
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120)

`channel=a=b` will be parsed as `a`. Remove the `=` from the value (or switch to an encoding scheme using a different delimiter character), then restart per "Clear the In-Process Cache" and verify again.

## Verification

1. After modifying the configuration and restarting Play Mode / rebuilding the package, call:

```csharp
string channel = BlankGetChannel.GetChannelName();
string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

2. Confirm the returned value matches the new value in the configuration file; on iOS, when the key is missing you should observe `unknown` (not the C# default parameter `default`).
3. If it's still the old value, first suspect that the cache wasn't cleared (restart Play Mode / the process), then suspect that you're not reading the configuration file you think you are (Editor: check `Assets/Resources/application_config.txt`; Android: check manifest meta-data; iOS: check Info.plist).
