# 如何避免程式碼裁剪導致的介面遺失

Unity 在打包時會執行託管程式碼裁剪（Managed Code Stripping），IL2CPP 編譯後會刪除未被參考的型別、方法和屬性。當你的業務程式碼透過反射、字串或動態載入存取 GameFrameX 資源介面時，被裁剪的擴充方法（如 `LoadTexture2DAsync`、`LoadPrefabSync`）會直接消失，執行階段擲回 `MissingMethodException`。本頁提供本儲存庫已在使用的防護方案，以及新增自訂擴充時必須遵循的寫法。

## 前置條件

- 專案使用 Unity IL2CPP 後端（Android / iOS / WebGL 預設開啟）。
- 已啟用 Player Settings → Managed Stripping Level 高於 Low，或啟用了 Engine Code Stripping。
- 已將 `GameFrameX.Asset` 套件匯入專案。

## 操作步驟

### 1. 沿用儲存庫已標記的擴充方法

儲存庫已在所有公開擴充類別和成員上加上 `[UnityEngine.Scripting.Preserve]`，直接呼叫即可，裁剪器會保留它們。例如下面的 `LoadTexture2DAsync` 擴充：

```csharp
[UnityEngine.Scripting.Preserve]
public static class AssetComponentTexture2DExtensions
{
    [UnityEngine.Scripting.Preserve]
    public static Task<AssetHandle> LoadTexture2DAsync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetAsync<Texture2D>(path);
    }

    [UnityEngine.Scripting.Preserve]
    public static AssetHandle LoadTexture2DSync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetSync<Texture2D>(path);
    }
}
```

Source: [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs#L13-L44)

`AssetComponent` 自身和 `GamePlayMode` 屬性也帶有 `[Preserve]`：

```csharp
[RequireComponent(typeof(GameFrameXAssetCroppingHelper))]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-4000)]
public sealed class AssetComponent : GameFrameworkComponent
{
    [UnityEngine.Scripting.Preserve]
    public EPlayMode GamePlayMode { get; set; }
}
```

Source: [Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L18-L45)

### 2. 新增自訂擴充時也加上 Preserve 特性

在自己的專案裡繼續撰寫 `AssetComponent` 的擴充方法時，必須為靜態類別和每個公用成員都加上 `[Preserve]`，否則裁剪器會視為「無人參考」並刪除。

```csharp
using UnityEngine;
using UnityEngine.Scripting;
using GameFrameX.Asset.Runtime;

[Preserve]
public static class MyAssetComponentExtensions
{
    [Preserve]
    public static AssetHandle LoadMyAssetSync(this AssetComponent self, string path)
    {
        return self.LoadAssetSync<Object>(path);
    }
}
```

放置位置建議：與 `AssetComponent` 同目錄或同組件，便於裁剪器在建置時一起掃描。

### 3. 確認專案中存在輔助元件

`AssetComponent` 透過 `[RequireComponent]` 強制掛載一個 `GameFrameXAssetCroppingHelper`，專門用於在場景裡保活相關型別：

```csharp
[Preserve]
public class GameFrameXAssetCroppingHelper : MonoBehaviour
{
}
```

Source: [Runtime/GameFrameXAssetCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/GameFrameXAssetCroppingHelper.cs)

只要 `AssetComponent` 實例存在於執行場景中（`GameFrameXAutoComponent` 啟動框架時會自動建立），裁剪器就會保留這條參考鏈上的所有標記成員。

### 4. 必要時提供 link.xml 作為保底方案

如果你的業務端透過反射（例如基於字串名稱呼叫 `LoadPrefabAsync`）存取資源介面，編譯期的參考無法被分析器識別，請額外在 `Assets/` 下放置 `link.xml`，強制保留整個組件：

```xml
<linker>
  <assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>
</linker>
```

`link.xml` 必須放在任意 `Resources` 目錄之外的 `Assets` 子目錄下，Unity 才會處理。

## 常見變體

| 場景 | 做法 |
|------|------|
| 通用泛型入口 `LoadAssetAsync<T>` | 直接呼叫，T 由呼叫端提供，參考鏈會被靜態分析識別，無需額外 `[Preserve]`。 |
| 自訂非同步包裝層 | 在包裝方法外層加上 `[Preserve]`，並確保包裝方法至少被一處程式碼靜態呼叫。 |
| WebGL 平台 | 強制走 `EPlayMode.WebPlayMode`，`AssetComponent.Awake` 已內建該分支。 |
| 透過 Addressables / YooAsset 間接反射呼叫 | 同時提供 `link.xml` 保底。 |

## 常見錯誤

| 現象 | 原因 | 處理 |
|------|------|------|
| 打包後呼叫 `LoadXxxAsync` 擲回 `MissingMethodException` | 該擴充方法未被任何程式碼靜態參考，被 IL2CPP 裁剪。 | 給擴充類別和方法補上 `[UnityEngine.Scripting.Preserve]`。 |
| 反射呼叫 `GameFrameX.Asset.Runtime` 組件裡的型別失敗 | 整個組件被裁剪。 | 在 `Assets/link.xml` 裡加上 `<assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>`。 |
| WebGL 打包後資源載入報錯 `Asset manager is invalid.` | 執行模式被還原成 `EditorSimulateMode`。 | `AssetComponent.Awake` 已處理，確認 `m_GamePlayMode` 在建置產物裡被序列化。 |
| 刪除場景中的 `AssetComponent` 後所有資源介面消失 | `RequireComponent(GameFrameXAssetCroppingHelper)` 一起被移除。 | 不要單獨刪除 `AssetComponent`，如需替換請同時把 `CroppingHelper` 保留下來或重新掛上。 |

## 驗證

1. 在 Unity Editor → Build Settings 建置 IL2CPP 包（Android 或 iOS）。
2. 在實機/模擬器上執行 `await assetComponent.LoadTexture2DAsync("Assets/Textures/xxx.png");`，確認無 `MissingMethodException`。
3. 使用 `il2cppdumper` 或 `Unity Symbol` 工具反查包內 dll，確認 `GameFrameX.Asset.Runtime` 組件裡的擴充型別仍存在。
4. 若仍失敗，逐步移除自訂 `link.xml` / `[Preserve]` 標記，定位被裁剪的成員。

## 背景（可選）

`[UnityEngine.Scripting.Preserve]` 是 Unity 官方提供給託管程式碼裁剪器的「白名單」標記，等同於在 link.xml 中按成員逐一保留。儲存庫在所有公開擴充 API 上加該標記，是因為這些方法多用於反射或泛型間接呼叫，編譯期參考圖無法涵蓋。本節涉及原始碼：[Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs) 與 [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs)。
