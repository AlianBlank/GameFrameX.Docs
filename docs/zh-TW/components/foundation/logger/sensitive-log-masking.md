# 機密日誌欄位的遮罩方法

透過使用 `SensitiveLogEventEnricher` + `SensitiveLogPropertyPolicy`,可在日誌事件到達 Sink 之前，將 `token`、`password`、`authorization` 等機密欄位統一替換為佔位符，防止驗證資訊被直接寫入日誌檔案。

## 前置條件

- 已參考 `GameFrameX.Foundation.Logger`(預設會與日誌模組一同載入，框架自身的 `LogHandler` 會自動套用預設策略)。
- 使用 Serilog 的結構化日誌屬性(`LogContext.PushProperty` 或範本佔位符)來接收值。本機制依據屬性名稱的比對進行判定，因此不會解析整個訊息字串。

## 操作步驟

### 1. 使用框架的預設策略(零設定)

`LogHandler` 在建構 Serilog pipeline 時會自動加入 `SensitiveLogEventEnricher()`,因此預設會對內建的 10 個欄位名稱執行遮罩。

```csharp
// 框架已預設內建,無需手動註冊
.Enrich.With(new SensitiveLogEventEnricher())
```

來源： [GameFrameX.Foundation.Logger/LogHandler.cs#L119](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHandler.cs#L119)

預設涵蓋的欄位名稱(不區分大小寫)：

| 欄位名稱 |
|--------|
| `token`、`access_token`、`refresh_token` |
| `password`、`passwd` |
| `authorization`、`cookie` |
| `apiKey`、`secret`、`clientSecret` |

來源： [GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53)

替換文字的預設值為 `[REDACTED]`(即使向 `replacement` 傳入空字串，也會回退為 `[REDACTED]`)。

### 2. 自訂機密欄位名稱

可透過傳入額外的欄位集合來覆寫預設策略(集合為「傳入的內容即為完整集合」，因此若想在預設之外額外新增，請先串接 `SensitiveLogPropertyPolicy.Default` 的欄位名稱)：

```csharp
using GameFrameX.Foundation.Logger;

var policy = new SensitiveLogPropertyPolicy(
    new[] { "IdCard", "Phone", "BankAccount" },
    replacement: "***");

var enricher = new SensitiveLogEventEnricher(policy);

// 整合至自訂的 LoggerConfiguration
Log.Logger = new LoggerConfiguration()
    .Enrich.With(enricher)
    .WriteTo.Console()
    .CreateLogger();
```

來源： [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53)

欄位名稱比對使用 `StringComparer.OrdinalIgnoreCase`,因此 `Password` 與 `password` 兩者皆會命中。

### 3. 確認遮罩已生效

寫入包含 `Password` 屬性的日誌，並確認輸出變為 `[REDACTED]`:

```csharp
using Serilog.Context;

using (LogContext.PushProperty("Password", "my-secret-password"))
{
    Log.Information("Login attempt for {UserId}", 42);
}
```

在預期的輸出中，`Password` 欄位的值會是 `[REDACTED]`,而非實際的密碼。Enricher 會遞迴處理 `StructureValue`、`SequenceValue`、`DictionaryValue`,因此結構化物件內巢狀的機密欄位也會被替換。

來源： [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103)

## 常見變化

- **模型欄位層級的遮罩**：若想為 ORM 實體加上標註(在列表/匯出/序列化時統一處理)，請使用 `GameFrameX.Foundation.Orm.Attribute` 的 `[SensitiveField(MaskingStrategy.Phone)]`。策略涵蓋 Phone、IdCard、Email、BankCard、Name、Address、Custom。這是與日誌 Enricher 相互獨立的機制，因此需要另行整合至序列化層。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }
}
```

來源： [GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

- **替換為自訂佔位符**：在建構 `SensitiveLogPropertyPolicy` 時傳入第二個引數(例如： `"***"`、`"已脫敏"`)。若傳入空字串，則會回退為 `[REDACTED]`。
- **巢狀物件的遮罩**：Enricher 預設會遞迴處理 `StructureValue` / `SequenceValue` / `DictionaryValue`,因此無需額外設定。僅在屬性名稱符合策略時，值才會被整體替換。

## 常見錯誤

| 現象 | 原因 | 處理方式 |
|------|------|------|
| 日誌中仍然出現明文的 token | 驗證資訊被寫在訊息範本內(例如： `Log.Info("token={0}", token)`),因此未成為結構化屬性 | 改為使用結構化屬性，例如 `Log.Information("token={Token}", token)` |
| 自訂欄位名稱未生效 | 欄位名稱包含空格，或與策略的拼寫不一致 | `_propertyNames` 是以 `OrdinalIgnoreCase` 進行完全比對，請確認名稱 |
| 向策略傳入 `null` 集合 | 建構函式會拋出 `ArgumentNullException` | 至少傳入 `Array.Empty<string>()`,或在自訂集合端進行 null 檢查 |
| 模型欄位未被遮罩 | `[SensitiveField]` 僅作用於 ORM 序列化層，不會自動連動至 Serilog | 日誌端也應併用 `SensitiveLogEventEnricher` |

## 背景(選讀)

`SensitiveLogEventEnricher` 實作了 Serilog 的 `ILogEventEnricher`,會在 `Enrich` 階段就地替換 `LogEvent.Properties`。策略物件管理「機密欄位名稱的集合 + 替換文字」。這一系列處理會在事件到達 Sink 之前完成，因此無論是檔案、主控台、遠端傳送等所有下游，都無法看到原始值。
