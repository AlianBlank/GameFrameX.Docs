# What to Do When Configuration Item Parsing Fails

When `GameFrameX.Setting` throws an exception, returns a default value, or `Load()` returns `false` during loading or reading configuration, it usually indicates that the underlying storage file is corrupted, the helper is not set, or the key name is invalid. This page provides quick diagnosis and fix methods based on the exception symptom.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | `ISettingHelper` is not set for `SettingManager`, or `null` is passed in | First instantiate a concrete Helper (default `DefaultSettingHelper` or `PlayerPrefsSettingHelper`), then call `SetSettingHelper` |
| `GameFrameworkException: Setting name is invalid.` | `settingName` is `null` or an empty string | Make sure `settingName` is non-empty before calling methods such as `HasSetting / GetBool / GetInt / GetFloat / GetString` |
| Startup log shows `Load settings failure with exception '{0}'.` | Configuration file `GameFrameworkSetting.dat` is missing, corrupted, or lacks permissions | Delete the corrupted file or restore permissions then reinitialize, see "Fix Steps" below |
| Startup log shows `Save settings failure with exception '{0}'.` | Configuration directory is read-only, disk is full, or path is invalid | Check the writability of the directory pointed to by `FilePath`, repoint to `Application.persistentDataPath` |
| The value read is always the type default (`false / 0 / 0f / null`) | Key name is misspelled or the key has not been written by the new version | Use `GetAllSettingNames()` to list all keys and verify, or first call the overload with `defaultValue` |

## Fix Steps

### 1. `Setting helper is invalid` Caused by Helper Not Set

`SettingManager` calls `EnsureSettingHelper()` before each read/write. If `m_SettingHelper` is `null`, this exception is thrown.

Source: [SettingManager.cs#L47-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L47-L61)

```csharp
private void EnsureSettingHelper()
{
    if (m_SettingHelper == null)
    {
        throw new GameFrameworkException("Setting helper is invalid.");
    }
}
```

Fix:

1. Create a Helper instance that inherits from `SettingHelperBase` (the framework includes `DefaultSettingHelper`, `PlayerPrefsSettingHelper`).
2. Inject it via `GameFrameworkEntry.GetModule<ISettingManager>().SetSettingHelper(helper)`.
3. `SetSettingHelper(null)` itself throws the same exception, ensure a non-null value is passed in.

Source: [SettingManager.cs#L126-L134](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L126-L134)

### 2. Configuration File Parsing Failure (`Load settings failure`)

`DefaultSettingHelper.Load()` wraps the deserialization process in a try/catch. Any exception is converted to a log and returns `false`, without throwing, but the configuration items will return to an empty set.

Source: [DefaultSettingHelper.cs#L126-L146](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L126-L146)

```csharp
public override bool Load()
{
    try
    {
        if (!File.Exists(m_FilePath))
        {
            return true;
        }

        using (FileStream fileStream = new FileStream(m_FilePath, FileMode.Open, FileAccess.Read))
        {
            m_Serializer.Deserialize(fileStream);
            return true;
        }
    }
    catch (Exception exception)
    {
        Log.Warning("Load settings failure with exception '{0}'.", exception);
        return false;
    }
}
```

Fix:

1. **File does not exist**: Normal on first launch, no handling required; if the business needs preset default values, call `SetBool/SetInt/...` to fill in after `Load()` returns `false`.
2. **File header mismatch**: The `Header` of `DefaultSettingSerializer` is `{'G','F','S'}`. If the file is modified by another program, parsing will fail. Delete the `GameFrameworkSetting.dat` and restart.

Source: [DefaultSettingSerializer.cs#L41-L67](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingSerializer.cs#L41-L67)
3. **Disk/permission issues**: Confirm that the directory where `FilePath` (derived from `Application.persistentDataPath`, etc.) is located is readable and writable; check if it is quarantined by antivirus software on Windows / macOS.

### 3. `Setting name is invalid` Caused by Empty Key Name

`HasSetting / RemoveSetting` validates in `EnsureSettingName`.

Source: [SettingManager.cs#L55-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L55-L61)

```csharp
private void EnsureSettingName(string settingName)
{
    if (string.IsNullOrEmpty(settingName))
    {
        throw new GameFrameworkException("Setting name is invalid.");
    }
}
```

Fix: Perform `string.IsNullOrEmpty` validation when fetching key names from the configuration center, or use overloads with default values such as `GetString(name, defaultValue)` / `GetInt(name, defaultValue)` to avoid empty key exceptions.

### 4. Save Failure (`Save settings failure`)

`Save()` is also wrapped with try/catch. On exception, it returns `false` and prints `Save settings failure with exception '{0}'.`.

Source: [DefaultSettingHelper.cs#L156-L170](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L156-L170)

Fix:

1. Confirm that `FilePath` has been initialized (Helper assigns via `SetFilePath` or during initialization).
2. Check the write permissions of the target directory; `FileMode.Create` requires write access.
3. Capture specific exceptions such as `IOException`, `UnauthorizedAccessException` from the `Log.Warning` output, and handle accordingly.

## Verification

Confirm the issue is resolved in the following order:

1. `GameFrameworkEntry.GetModule<ISettingManager>().Load()` returns `true`, and the startup log no longer contains `Load settings failure` / `Save settings failure`.
2. The array returned by `GetAllSettingNames()` contains all the keys you expect; use `HasSetting("your.key")` to check that a specific key exists.
3. Write a configuration (`SetInt("score", 100)` → `Save()`), and after exit and restart, `GetInt("score")` can still read 100.
4. Use cases such as `SetSettingHelper(null)`, passing in an empty key name to confirm that the exception path throws `GameFrameworkException` as expected and is not swallowed.
