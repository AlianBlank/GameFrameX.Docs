# HttpClientRequestException 抛出与响应异常怎么办

当通过 `GameFrameX.Foundation.Http.Extension` 发起的 HTTP 请求收到非成功状态码、网络层异常或 JSON 反序列化失败时,框架会抛出 `HttpClientRequestException`。本页面告诉你怎么识别它、定位原因并选择正确的修复方式。

## 快速诊断

| 症状(异常消息) | 原因 | 修复 |
|---|---|---|
| `HTTP request failed with status code {code} ({StatusCode}) for {uri}.` | 服务端返回 4xx / 5xx 响应,且调用方调用了 `EnsureSuccessStatusCode()` 或触发了内部状态码检查 | 见 [修复步骤 - 状态码失败](#修复步骤-状态码失败) |
| `HTTP request failed for {method} {uri}.` | 底层抛出 `HttpRequestException`(DNS、连接、超时、TLS 等网络层错误)且不在重试范围内,或通用 `Exception` 落入 `HttpRequestException / JsonException` 分支 | 见 [修复步骤 - 网络层 / 通用异常](#修复步骤-网络层--通用异常) |
| `HTTP JSON response could not be deserialized for {uri}.` | 响应体不是合法的 JSON,或与目标类型不匹配 | 见 [修复步骤 - JSON 反序列化失败](#修复步骤-json-反序列化失败) |

异常类型本身继承自 `HttpRequestException`,并额外携带以下诊断字段:

| 字段 | 类型 | 说明 |
|---|---|---|
| `StatusCode` | `HttpStatusCode?` | 服务端返回的 HTTP 状态码(若有响应) |
| `RequestUri` | `Uri?` | 出错的请求 URI |
| `ResponseSummary` | `string?` | 响应体的有界摘要(失败时填充) |
| `RawException` | `Exception?` | 触发此异常的原始异常(若有) |

```csharp
public sealed class HttpClientRequestException : HttpRequestException
{
    public HttpClientRequestException(
        string message,
        HttpStatusCode? statusCode,
        Uri? requestUri,
        string? responseSummary,
        Exception? rawException = null)
        : base(message, rawException, statusCode)
    {
        StatusCode = statusCode;
        RequestUri = requestUri;
        ResponseSummary = responseSummary;
        RawException = rawException;
    }

    public new HttpStatusCode? StatusCode { get; }
    public Uri? RequestUri { get; }
    public string? ResponseSummary { get; }
    public Exception? RawException { get; }
}
```

## 修复步骤

### 修复步骤:状态码失败

1. 在调用方使用 `try / catch` 捕获 `HttpClientRequestException`,并通过 `StatusCode` 判断具体失败类型(401、404、500 等)。

```csharp
try
{
    var response = await httpClient.SendJsonAsync<MyDto>(request, options);
    response.EnsureSuccessStatusCode();
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    // 资源不存在,走业务降级分支
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.Unauthorized)
{
    // 刷新令牌或提示重新登录
}
```

2. 如果请求本应容错(例如 GET 列表允许 404 返回空),不要调用 `EnsureSuccessStatusCode()`,直接读取 `IsSuccessStatusCode` 与 `Body` 自行处理。

```csharp
public HttpClientResponse EnsureSuccessStatusCode()
{
    if (IsSuccessStatusCode)
    {
        return this;
    }

    throw new HttpClientRequestException(
        $"HTTP request failed with status code {(int)StatusCode} ({StatusCode}) for {RequestUri}.",
        StatusCode,
        RequestUri,
        Body);
}
```

Source: [HttpClientResponse.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientResponse.cs#L80-L92)

3. 检查重试配置。框架默认会对 `HttpRequestException` 进行有限次重试,当 `attempt <= options.Retry.MaxRetries` 时不会抛 `HttpClientRequestException`,而是触发退避重试。

```csharp
catch (HttpRequestException exception) when (allowRetry && attempt <= options.Retry.MaxRetries)
{
    await DelayBeforeRetryAsync(method, request.RequestUri, attempt, null, exception, options, effectiveToken);
    return (null, true);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L358-L362)

如果状态码失败但重试次数已耗尽,会在 `CreateStatusException` 处抛出带状态的异常:

```csharp
private static HttpClientRequestException CreateStatusException(
    HttpStatusCode statusCode,
    Uri? requestUri,
    string responseText)
{
    return new HttpClientRequestException(
        $"HTTP request failed with status code {(int)statusCode} ({statusCode}) for {requestUri}.",
        statusCode,
        requestUri,
        Summarize(responseText));
}
```

### 修复步骤:网络层 / 通用异常

1. 网络层(DNS、TCP、TLS、超时)通常表现为底层 `HttpRequestException`。当重试次数耗尽或非 `HttpRequestException / JsonException` 的 `Exception` 出现时,会被包装为:

```csharp
catch (Exception exception) when (exception is HttpRequestException or JsonException)
{
    throw new HttpClientRequestException(
        $"HTTP request failed for {method} {request.RequestUri}.",
        null,
        request.RequestUri,
        null,
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L363-L371)

2. 排查思路:
   - 优先读 `ex.RawException?.Message`,里面通常是底层真正的原因(例如 `The requested name is valid, but no data of the requested type was found`)。
   - 若为超时,提高 `HttpClientRequestOptions` 中的超时阈值或调整 `Retry.MaxRetries / Retry.Delay` 让重试更充分。
   - 若为 TLS / 证书错误,确认目标地址证书链与服务端 SNI 配置。
   - 若在自定义 `HttpMessageHandler` 链路下抛出其它异常,框架只会在 `is HttpRequestException or JsonException` 时包装;其余异常会按原样冒泡,需要单独捕获。

### 修复步骤:JSON 反序列化失败

1. 当响应体不是合法 JSON、或字段类型与目标类型不匹配时,会抛出:

```csharp
catch (JsonException exception)
{
    throw new HttpClientRequestException(
        $"HTTP JSON response could not be deserialized for {requestUri}.",
        null,
        requestUri,
        Summarize(responseText),
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L430-L438)

2. 排查思路:
   - 通过 `ex.RawException` 拿到原始 `JsonException`,定位到具体字段路径与行号。
   - 检查 `ex.ResponseSummary`,查看响应体摘要,确认服务端返回的格式(`application/json` vs `text/html`)。
   - 必要时在 `HttpClientRequestOptions.JsonSerializerOptions` 中配置 `PropertyNameCaseInsensitive`、`NumberHandling`、`AllowTrailingCommas` 等,让反序列化更宽容。

## 验证

1. 故意构造一个会失败的请求(指向不存在的地址或返回 500 的端点),确认捕获到 `HttpClientRequestException`,且 `StatusCode` / `RequestUri` / `ResponseSummary` 三个字段值与预期一致。
2. 反序列化失败场景下,把 `RawException` 转为 `JsonException`,确认其 `Path` 指向导致失败的字段。
3. 在打开 `Retry.MaxRetries > 0` 的配置下,临时让目标接口返回一次 5xx,确认日志中出现退避重试记录,最终仍按业务预期抛出 `HttpClientRequestException`。
