# オブジェクト保存パスの設定方法

`SetSavePath(string)` を呼び出すことで、オブジェクトストレージ内のオブジェクトの保存先パスを設定できます。以降の `UploadDirectory` と `UploadFile` でアップロードされたファイルは、すべてこのパス配下へ保存されます。

## 前提条件

- `ObjectStorageUploadFactory` から `IObjectStorageUploadManager` インスタンスを取得済みであること（具体的な型はファクトリが現在のプラットフォーム/設定に応じて作成し、`BaseObjectStorageUploadManager` を継承しています）。
- 書き込み対象のバケット (`bucketName`) を確認し、`Init(accessKey, secretKey, bucketName, endpoint)` の呼び出しが完了していること。

## 操作手順

1. アップロードマネージャーのインスタンスを取得します。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs)

2. `SetSavePath` を呼び出して、バケット内のオブジェクト保存パスを指定します（末尾のセパレーターはあってもなくても構いません）。

   ```csharp
   // 書き方 A:末尾セパレーターなし
   manager.SetSavePath("game/assets/textures");
   
   // 書き方 B:末尾セパレーター付き。実装内部で自動的に最後のセパレーターが除去されます
   manager.SetSavePath("game/assets/textures/");
   ```

   実装はまず `savePath` が `Path.DirectorySeparatorChar` で終わるかをチェックし、もしそうであれば `Substring(0, savePath.Length - 1)` で切り出し、最後に `BucketSavePath` に代入します。どちらの書き方も等価です。

   Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

3. パスの設定完了後、アップロードインターフェースを呼び出すと、ファイルは `BucketSavePath` 配下へ保存されます。

   ```csharp
   // ディレクトリ全体をアップロード
   manager.UploadDirectory("/ローカル/Assets/Textures");
   
   // もしくは単一ファイルをアップロード
   bool ok = manager.UploadFile("/ローカル/Assets/Textures/icon.png");
   ```

   Source: [IObjectStorageUploadManager.cs#L9-L21](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9-L21)

## よくあるバリエーション

- **アップロードごとにパスをリセットする**:同一セッション内で `SetSavePath` を何度でも呼び出して、異なるサブディレクトリへのアップロードを切り替えることができます。`BucketSavePath` は保護されたフィールドですが、呼び出しのたびに上書きされます。
- **相対パス vs 絶対キープレフィックス**:`SetSavePath` が受け取るのはオブジェクトキー(Key)のプレフィックスであり、例えば `"game/v1"` のようなものです。ローカルファイルシステムのパスではありません。ローカルパスは `UploadDirectory` / `UploadFile` に別途渡します。

## よくあるエラー

- **パスの末尾がバックスラッシュになっている(Windows の慣習)**:`SetSavePath` は `Path.DirectorySeparatorChar`(プラットフォームのネイティブセパレーター)のみをチェックするため、Windows の `"a\\b\\"` を渡すとバックスラッシュが残ったままになります。スラッシュ、またはセパレーターを含まない形式に統一することをお勧めします。
- **`Init` を呼び出す前に `SetSavePath` を呼んでしまう**:`SetSavePath` 自体は `Init` の状態を検証しませんが、以降のアップロードには有効な認証情報が必要です。`Init` していない状態ではアップロードは失敗します。先に `Init` し、次にパスを設定し、そしてアップロードを行います。
- **呼び出し順序の誤り**:`SetSavePath` は `UploadDirectory` / `UploadFile` の前に呼び出さなければなりません。そうでないと、すでに発行されたアップロードは前回設定された `BucketSavePath`(デフォルトは `string.Empty`)を引き続き使用します。

## 背景(オプション)

`BucketSavePath` は `BaseObjectStorageUploadManager` の保護されたフィールドであり、具体的な実装クラス（各クラウドベンダー向けのアダプタなど）はこれをオブジェクトキーのプレフィックスとしてアップロードリクエストに連結します。したがって、本質的には「オブジェクトキープレフィックス」であり、「ローカルディスクパス」ではありません。
