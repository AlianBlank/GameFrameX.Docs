# 이벤트가 보고되지 않음: "GameAnalyticsManager is not init." 경고 해결 방법

`GameAnalyticsComponent`의 `Event` / `StartTimer` / `StopTimer` 등 인터페이스를 호출할 때, 해당 분석 SDK 관리자 인스턴스 내부의 초기화가 아직 완료되지 않았다면 컴포넌트는 `GameAnalyticsManager is not init.`를 출력하고 이번 보고를 건너뜁니다. 이 경고는 `GameAnalyticsComponent`의 초기화 가드에서 발생하며, "Provider가 `IGameAnalyticsManager` 인스턴스를 생성했지만 해당 인스턴스 자신의 `m_IsInit`가 여전히 false"임을 나타냅니다.

## 해결 단계

### 1. 구현 클래스의 Init 또는 ManualInit에서 isinit 설정

경고의 판정 기준은 `IGameAnalyticsManager.IsInit()`이며, 이는 기본 클래스 `BaseGameAnalyticsManager`가 제공하고 보호된 필드 `m_IsInit`를 반환합니다:

```csharp
protected bool m_IsInit = false;

/// <summary>
/// 초기화 여부
/// </summary>
/// <returns></returns>
public bool IsInit()
{
    return m_IsInit;
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L12-L45)

`Init(Dictionary<string, string> args)`와 `ManualInit(Dictionary<string, string> args)`는 추상 메서드로, 각 분석 SDK의 구현 클래스에서 자체적으로 구현합니다. 본인의 구현을 확인하세요:

- SDK에 사용자 동의 등의 사전 조건이 필요 없다면, `Init(args)`에서 SDK 초기화를 완료한 후 `m_IsInit = true;`를 작성해야 합니다.
- SDK에 `ManualInit`(개인정보 보호 규정 준수 절차)이 필요하다면, `IsManualInit()`가 true를 반환하는 구현은 먼저 `GameAnalyticsComponent.ManualInit(extraArgs)`를 호출하고 그 안에서 `m_IsInit`를 설정해야 합니다. 컴포넌트 측 가드에 유의하세요:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

`ManualInit`는 `IsManualInit()`가 true인 구현에만 전달되며, 컴포넌트 자신이 이미 `Init()`되었어야 합니다.

### 2. Provider가 Inspector에 설정되어 있는지 확인

컴포넌트는 `OnEnable()`에서 `Init()`를 호출하여 `m_gameAnalyticsComponentProviders`를 순회하고, 리플렉션으로 구현 클래스 인스턴스를 생성한 뒤 그 `Init(args)`를 호출합니다:

```csharp
private void OnEnable()
{
    Init();
}

public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }
            // ...인스턴스를 생성하고, args를 조립하여 gameAnalyticsManager.Init(args)를 호출
        }
    }

    m_IsInit = true;
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L27-L80)

씬에 있는 `GameAnalyticsComponent`의 Inspector에서(메뉴 `Game Framework/GameAnalytics`) "게임 데이터 분석 컴포넌트 리스트, 순서대로 보고"라는 제목의 리스트를 편집하세요: 요소를 추가하고, `ComponentType` 드롭다운에서 `IGameAnalyticsManager`를 구현한 타입을 선택하며(드롭다운 옵션은 `Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager))`에서 가져옴), `Setting`에 해당 구현에 필요한 Key/Value 파라미터(예: AppId, SecretKey 등, 구체적인 구현에 따름)를 입력하세요.

Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

### 3. 조용한 폐기 점검(경고 없이 보고되지도 않는 경우)

컴포넌트 수준의 가드는 조용합니다: `!m_IsInit`이면 바로 `return`하며 어떤 로그도 출력하지 않습니다. 경고조차 없다면 다음을 순서대로 확인하세요:

1. 호출 시점이 컴포넌트의 `OnEnable`보다 이른지(`Awake` 단계에는 `m_IsInit`가 여전히 false임).
2. `m_gameAnalyticsComponentProviders`가 빈 리스트이거나 `ComponentType`이 공백인지 — 이 경우 오류도 발생하지 않고 인스턴스도 생성되지 않습니다.
3. 콘솔에 `Can not find component type '...'`라는 `Log.Error`가 있는지 — 해당 Provider는 `continue`로 건너뛰어집니다.

## 검증

1. 게임을 시작하고, 콘솔에 더 이상 `Can not find component type` 빨간색 오류가 나타나지 않는지 확인하세요(이 오류는 해당 Provider가 곧바로 건너뛰어지게 만듭니다).
2. 임의의 `Event(...)` / `StartTimer(...)`를 호출하여, `GameAnalyticsManager is not init.` 노란색 경고가 사라졌는지 확인하세요.
3. 해당 분석 플랫폼(예: ThinkingData, Shushu 등, 구현 클래스에 따라 다름)의 백오피스에서 이벤트가 도착했는지 확인하거나, 구현 클래스의 `Init` 안에 임시 로그를 추가하여 `m_IsInit`가 true로 설정되었는지 확인하세요.

## 배경

경고는 두 계층의 가드로 구성됩니다: `GameAnalyticsComponent.m_IsInit`(컴포넌트 수준, `OnEnable` 시 true로 설정되며 초기화되지 않았을 때 조용히 버림)과 각 `IGameAnalyticsManager.IsInit()`(인스턴스 수준, 초기화되지 않았을 때 이 경고를 출력). `BaseGameAnalyticsManager`는 단지 `m_IsInit` 필드를 보유하고 `IsInit()` / `SetPublicProperties` 등의 공통 기능을 노출할 뿐이며, 설정 시점은 전적으로 구체적인 SDK 구현에 따라 결정됩니다. 따라서 이 경고는 거의 항상 구현 클래스의 `Init`/`ManualInit`가 `m_IsInit`를 true로 설정하지 않았거나, 호출이 수동 초기화 절차 이전에 발생했음을 가리킵니다.

컴포넌트의 각 보고 인터페이스에 대한 전체 시그니처는 《GameAnalyticsComponent 레퍼런스》를 참조하세요.
