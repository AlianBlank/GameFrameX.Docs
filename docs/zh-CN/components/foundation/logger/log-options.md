# 如何配置 Logger 行为(LogOptions)

通过 `LogOptions` 可以集中控制日志输出位置、级别、滚动策略与外部存储(文件、MongoDB、GrafanaLoki)的所有开关,读完本页即可在几行代码内完成自定义配置。

## 前置条件

- 已引用 `GameFrameX.Foundation` 程序集,且目标框架支持 .NET。
- 日志写入文件需要进程对 `AppDomain.CurrentDomain.BaseDirectory/data/<logPathName>` 有写权限。
- 写入 MongoDB 需要可访问的 MongoDB 服务;写入 GrafanaLoki 需要可访问的 Loki 服务。
- 类型所在命名空间:`GameFrameX.Foundation.Logger`,关键类型:`LogOptions`、`RollingInterval`(Serilog)、`LogEventLevel`(Serilog.Events)。

## 配置项速查

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `LogSavePath` | `string` | `<BaseDir>/data/logs` | 日志文件绝对路径,构造时由 `logPathName` 拼接生成 |
| `LogFileName` | `string` | `""`(默认名) | 日志文件名,留空走默认 |
| `LogType` | `string` | `null` | 标识日志来源的服务器类型 |
| `LogTagName` | `string` | `""` | 日志标签,用于分类 |
| `IsWriteToFile` | `bool` | `true` | 是否写入文件 |
| `IsConsole` | `bool` | `true` | 是否同时输出到控制台 |
| `IsFileSizeLimit` | `bool` | `true` | 是否限制单个文件大小 |
| `FileSizeLimitBytes` | `int` | `100 * 1024 * 1024` | 单文件字节上限,达到后滚动 |
| `RetainedFileCountLimit` | `int?` | `31` | 历史日志保留数量,`null` 表示不限制 |
| `RollingInterval` | `RollingInterval` | `Day` | 滚动间隔(Hour/Day/Month 等) |
| `LogEventLevel` | `LogEventLevel` | `Debug` | 最低输出级别,低于此级别不记录 |
| `IsWriteToMongoDb` | `bool` | `false` | 是否写入 MongoDB |
| `MongoDbDatabaseUrl` | `string` | `mongodb://127.0.0.1:27017/gameserver?authSource=admin` | MongoDB 连接串 |
| `MongoDbCappedMaxSizeMb` | `int` | `50` | MongoDB 上限集合最大 MB |
| `MongoDbCappedMaxDocuments` | `int` | `50000` | MongoDB 上限集合最大文档数 |
| `IsGrafanaLoki` | `bool` | `false` | 是否输出到 GrafanaLoki |
| `GrafanaLokiUrl` | `string` | `http://localhost:3100` | Loki 服务地址 |
| `GrafanaLokiLabels` | `Dictionary<string,string>` | 空 | Loki 标签 |
| `GrafanaLokiProperty` | `Dictionary<string,string>` | 空 | Loki 附加属性 |
| `GrafanaLokiUserName` / `GrafanaLokiPassword` | `string` | `null` | Loki 鉴权 |
| `GrafanaLokiCompressionEnabled` | `bool` | `true` | Loki 推送是否启用压缩 |
| `GrafanaLokiBatchSizeLimit` | `int` | `1000` | 攒批阈值,达到即推送 |
| `GrafanaLokiQueueLimit` | `int` | `100000` | 内存队列上限,满则丢日志 |
| `GrafanaLokiPeriod` | `int`(秒) | `2` | 强制推送周期;传入 `<=0` 回退为 2 |

属性默认值与签名来源见 [LogOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L47-L289)。

## 操作步骤

1. **引入命名空间并创建实例**。默认实例可直接使用 `LogOptions.Default`,或通过 `CreateDefault()` 拿到一份可独立修改的副本。

```csharp
using GameFrameX.Foundation.Logger;

// 直接复用默认配置(只读推荐场景)
var defaults = LogOptions.Default;

// 拿到一份可修改的副本
var options = LogOptions.CreateDefault();
options.LogTagName = "GameServer-01";
```

Source: [LogOptions.cs#L69-L82](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L69-L82)

2. **按需调整输出目标与文件策略**。常见组合:关闭文件、只输出到 Loki;或反之。

```csharp
var options = LogOptions.CreateDefault();

// 文件策略
options.IsWriteToFile = true;
options.RollingInterval = RollingInterval.Day;   // 每天滚动
options.IsFileSizeLimit = true;
options.FileSizeLimitBytes = 50 * 1024 * 1024;   // 50MB
options.RetainedFileCountLimit = 14;             // 仅保留 14 天

// 控制台
options.IsConsole = true;

// 级别
options.LogEventLevel = LogEventLevel.Information;
```

Source: [LogOptions.cs#L243-L277](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L243-L277)

3. **接入 MongoDB**(可选)。

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToMongoDb = true;
options.MongoDbDatabaseUrl = "mongodb://user:password@192.168.1.100:27017/gameserver?authSource=admin";
options.MongoDbCappedMaxSizeMb = 200;
options.MongoDbCappedMaxDocuments = 100000;
```

`IsWriteToMongoDb=true` 时必须配置有效的 `MongoDbDatabaseUrl`;连接串格式参考源文件中的示例。Source: [LogOptions.cs#L108-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L108-L145)

4. **接入 GrafanaLoki**(可选)。启用 Loki 后,需配置服务地址、标签与鉴权;批量参数调整可控制吞吐与背压。

```csharp
var options = LogOptions.CreateDefault();
options.IsGrafanaLoki = true;
options.GrafanaLokiUrl = "http://loki.internal:3100";
options.GrafanaLokiUserName = "loki";
options.GrafanaLokiPassword = "secret";
options.GrafanaLokiLabels["app"] = "gameserver";
options.GrafanaLokiLabels["env"] = "prod";
options.GrafanaLokiBatchSizeLimit = 2000;     // 攒 2000 条再推
options.GrafanaLokiQueueLimit = 200000;       // 内存队列上限
options.GrafanaLokiPeriod = 5;                // 每 5 秒强制推一次
options.GrafanaLokiCompressionEnabled = true;
```

注意 `GrafanaLokiPeriod` 传入 `<=0` 会被强制回退为 2 秒;队列写满后新日志会被丢弃(背压保护)。Source: [LogOptions.cs#L168-L235](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L168-L235)

5. **传递 `LogOptions` 给日志组件初始化入口**,然后用 `LogHelper.Info/Debug/...` 输出。

```csharp
// 假设日志入口需要 LogOptions
LogHelper.Init(options);

LogHelper.Info("服务启动完成");
LogHelper.Debug("调试信息:玩家 {0} 进入副本", playerId);
```

> 调用入口名称请以你工程内引用的初始化方法为准(本仓库 `LogOptions` 类本身不负责初始化日志通道)。

## 常见变体

- **多租户/多服区分日志**:设置 `LogType` 与 `LogTagName`,文件路径会落在 `LogSavePath` 之下,便于按服分目录。
- **构造时自定义根目录**:`new LogOptions("gateway-logs")` 会把日志放到 `<BaseDir>/data/gateway-logs`,留空会回退为 `logs`。

```csharp
var options = new LogOptions("gateway-logs");
options.LogType = "Gateway";
options.LogTagName = "GW-01";
```

Source: [LogOptions.cs#L53-L61](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L53-L61)

- **关闭文件、只走 Loki**:适合容器化部署,日志统一汇聚。

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToFile = false;
options.IsConsole = false;
options.IsGrafanaLoki = true;
```

- **不限制保留文件数**:`options.RetainedFileCountLimit = null;`。

## 常见错误

| 症状/误用 | 原因 | 修复 |
|----------|------|------|
| 日志文件没出现在预期目录 | 误以为 `LogSavePath` 默认就是当前目录 | 真实默认是 `<AppDomain.BaseDirectory>/data/logs`,可通过构造参数 `logPathName` 调整 |
| 启用 MongoDB 后写入失败 | `MongoDbDatabaseUrl` 未配置或 MongoDB 未监听 | 按源文件示例填入连接串并确认服务可用 |
| Loki 推送几乎不动 | `GrafanaLokiBatchSizeLimit` 设得过大且 `Period` 也很大 | 调小批量阈值或调小 `Period`;`Period<=0` 会被强制回退为 2 秒 |
| 磁盘爆涨 | `RetainedFileCountLimit` 未设置或 `IsFileSizeLimit=false` | 设置合理保留数(如 14/31)并启用单文件大小限制 |
| 修改 `LogOptions.Default` 不生效 | `Default` 是只读静态实例,共享同一份 | 用 `CreateDefault()` 取得独立副本再修改 |

## 背景(可选)

`LogOptions` 是一个 POCO(纯属性对象),自身不直接构造 Serilog 管道;真正使用这些开关的初始化逻辑位于日志入口实现中。设计上把"怎么记"与"记到哪"解耦:级别、滚动、压缩是通用策略,文件/MongoDB/Loki 是可独立开启的 sink。

关于日志的整体初始化与 `LogHelper` 用法,见《Logger 快速开始》。
