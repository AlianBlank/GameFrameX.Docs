# FixedUpdate에서 FSM을 구동하는 방법

`FsmState<T>`에서 `OnFixedUpdate`를 재정의하면 상태 머신을 Unity의 물리 프레임(`FixedUpdate`)에서 구동할 수 있습니다. 프레임워크의 `FsmComponent`는 Unity의 `FixedUpdate`를 모든 등록된 FSM에 자동으로 전달하므로 수동으로 호출할 필요가 없습니다.

## 사전 조건

- `FsmComponent`를 게임 진입점 GameObject에 부착합니다(Add Component → `GameFrameX/FSM`). 프레임워크는 `Awake`에서 `IFsmManager`를 가져옵니다.
- 비즈니스 측에서 상태 머신을 이미 생성했습니다: `GameFrameworkFsm` 또는 `FsmComponent.CreateFsm`. 자세한 내용은 `FsmComponent.cs`를 참조하세요.
- `FsmState<T>`를 상속하는 상태 클래스를 최소 하나 이상 정의했습니다.

## 작업 단계

1. 상태 클래스에서 `OnFixedUpdate`를 재정의하여 물리 프레임의 `elapseSeconds`와 `realElapseSeconds`를 수신합니다.

```csharp
using GameFrameX.Fsm;

public class PlayerRunState : FsmState<Player>
{
    protected internal override void OnFixedUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // elapseSeconds는 Time.fixedDeltaTime이고, realElapseSeconds는 Time.fixedTime입니다.
        var rb = fsm.Owner.GetComponent<Rigidbody>();
        rb.MovePosition(rb.position + fsm.Owner.MoveDirection * fsm.Owner.Speed * elapseSeconds);
    }
}
```

Source: [FsmState.cs#L75-L89](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L75-L89)

2. 상태 머신을 생성할 때 이 상태를 상태 집합에 추가하고, FSM을 해당 상태로 시작합니다.

```csharp
var fsm = GameEntry.GetComponent<FsmComponent>().CreateFsm<Player>(
    owner: this,
    states: new FsmState<Player>[]
    {
        new PlayerIdleState(),
        new PlayerRunState(),
        new PlayerJumpState(),
    });

fsm.Start<PlayerRunState>();
```

3. 비즈니스 코드에서 더 이상 `Update`/`FixedUpdate` 호출을 작성할 필요가 없습니다. `FsmComponent.FixedUpdate`가 `Time.fixedDeltaTime`과 `Time.fixedTime`을 관리자에게 전달합니다:

```csharp
private void FixedUpdate()
{
    if (m_FsmManager == null) return;
    m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
}
```

Source: [FsmComponent.cs#L76-L84](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

4. 관리자 계층은 파괴되지 않은 모든 FSM에 대해 `FixedUpdate`를 호출하고, 최종적으로 현재 상태의 `OnFixedUpdate`로 라우팅합니다:

```csharp
public void FixedUpdate(float fixedDeltaTime, float fixedTime)
{
    // ...m_Fsms를 순회하며, 파괴되지 않은 각 FSM에 대해 FixedUpdate 호출
}
```

Source: [FsmManager.cs#L110-L130](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L110-L130)

5. `Fsm<T>.FixedUpdate`는 현재 상태의 콜백만 트리거하며, 다른 상태는 실행되지 않습니다:

```csharp
internal override void FixedUpdate(float elapseSeconds, float realElapseSeconds)
{
    m_CurrentStateTime += elapseSeconds;
    m_CurrentState.OnFixedUpdate(this, elapseSeconds, realElapseSeconds);
}
```

## 일반적인 변형

- `FixedUpdate`에서 상태를 전환하려면 `ChangeState<TState>()`를 호출하면 됩니다. 전환 시점은 `OnFixedUpdate` 내부에 두어 로직 프레임의 `OnUpdate`와 엉키지 않도록 합니다.
- 로직 프레임 동작도 필요한 경우 `OnUpdate`를 재정의하세요. 두 메서드는 서로 영향을 주지 않으며, 각자의 프레임 속도에 따라 호출됩니다.
- 물리 관련 계산(힘 적용, 속도 적분)은 `OnFixedUpdate`에 두고, 입력 응답, 애니메이션 파라미터는 `OnUpdate`에 두면 타이밍이 더 안정적입니다.

## 일반적인 오류

- **수동으로 `fsm.FixedUpdate(...)`를 다시 호출**: `FsmBase.FixedUpdate`는 `internal`이며 관리자에 의해서만 트리거됩니다. 비즈니스 측에서 중복으로 구동하면 상태가 한 프레임 내에 두 번 진행됩니다.
- **`Start<...>()` 호출 잊기**: 시작되지 않은 FSM에는 `CurrentState`이 없으므로 `OnFixedUpdate`가 트리거되지 않으며 오류도 발생하지 않습니다.
- **`OnFixedUpdate`에서 `Time.deltaTime` 읽기**: `elapseSeconds`는 이미 `Time.fixedDeltaTime`로 고정되어 있으므로, `Time.deltaTime`을 읽으면 로직 프레임의 지터가 도입됩니다.

## 배경(선택 사항)

프레임워크는 Unity의 `MonoBehaviour.FixedUpdate`를 관리자에 후크하고, 관리자는 다시 물리 프레임 시간을 모든 FSM에 브로드캐스트합니다. 각 FSM은 이 콜백을 현재 `FsmState<T>`에만 디스패치하여 "물리 프레임 구동 + 현재 상태 응답"을 구현합니다. `OnFixedUpdate`와 `OnUpdate`는 공존하며, 전자는 `FsmComponent`의 `FixedUpdate`에 의해 트리거되고 후자는 `Update`에 의해 트리거됩니다. 두 매개변수의 의미는 다르지만 호출 진입점은 대칭입니다.
