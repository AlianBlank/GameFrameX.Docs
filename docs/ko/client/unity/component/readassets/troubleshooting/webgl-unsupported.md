# WebGL 플랫폼을 사용할 수 없는 경우怎么办

`com.gameframex.unity.readassets`은(는) WebGL 플랫폼 전용 구현 분기가 없으며, Unity WebGL의 런타임 샌드박스는 로컬 디스크나 APK처럼 StreamingAssets의 파일을 동기 방식으로 직접 열 수 없기 때문에 해당 프레임워크는 WebGL 플랫폼에서 **공식적으로 지원되지 않습니다**. Build Target을 WebGL로 전환한 후 `BlankReadAssets`의 임의 API를 호출하면, 에디터나 런타임에서 기능 누락 또는 로드 실패 상황이 발생합니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| Build Target을 WebGL로 전환한 후 컴파일 시 "WebGL is not supported" 관련 경고가 발생하거나, WebGL 빌드에서 StreamingAssets 파일을 읽을 수 없음 | 프레임워크는 `UNITY_EDITOR`, `UNITY_ANDROID`에 대해서만 전용 구현 분기를 제공하며, WebGL과 기타 플랫폼은 `LooseFilesImpl`을 공유합니다. 또한 WebGL 샌드박스는 동기 `File` I/O를 지원하지 않음 | 아래 해결 단계를 참고하여 방식 전환 |

## 해결 단계

### 1. WebGL Build에서 UnityWebRequest 사용으로 전환

WebGL 플랫폼에서 파일 접근은 반드시 `UnityWebRequest`를 통해 이루어져야 하며, 이는 Unity가 WebGL 백엔드에서 유일하게 지원하는 자산 로드 방식입니다:

```csharp
using UnityEngine;
using UnityEngine.Networking;

public static class WebGLReadAssetsFallback
{
    public static UnityWebRequest ReadAllBytes(string relativePath)
    {
        // StreamingAssets의 WebGL URL 형식은 http(s)://host/StreamingAssets/xxx
        var url = System.IO.Path.Combine(Application.streamingAssetsPath, relativePath);
        return UnityWebRequest.Get(url);
    }
}
```

### 2. 플랫폼 조건부 컴파일로 기존 호출 보존

비즈니스 코드에서 매크로를 사용하여 WebGL을 제외하여, WebGL에서 지원되지 않는 API가 호출되는 것을 방지합니다:

```csharp
#if !UNITY_WEBGL || UNITY_EDITOR
    using GameFrameX.ReadAssets.Runtime;
#endif

public byte[] LoadConfig(string path)
{
#if !UNITY_WEBGL || UNITY_EDITOR
    return BlankReadAssets.ReadAllBytes(path);
#else
    using (var req = WebGLReadAssetsFallback.ReadAllBytes(path))
    {
        req.SendWebRequest();
        while (!req.isDone) { }
        return req.downloadHandler.data;
    }
#endif
}
```

> 플랫폼별로 구현을 선택하는 작성 방법은 `Runtime/BlankReadAssets.cs`에서 자세한 내용을 확인할 수 있습니다:

```csharp
#if UNITY_EDITOR
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.EditorImpl;
#elif UNITY_ANDROID
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.ApkImpl;
#else
    using BlankReadAssetsImpl = GameFrameX.ReadAssets.Runtime.BlankReadAssets.LooseFilesImpl;
#endif
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L11-L17)

### 3. AssetBundle에 대한 추가 설명

`BlankReadAssets.LoadAssetBundle`은 내부적으로 `AssetBundle.LoadFromFile`을 호출하며, 해당 API의 WebGL 동작은 정의되어 있지 않습니다. WebGL에서 AssetBundle을 로드해야 하는 경우, 반드시 `UnityWebRequestAssetBundle.GetAssetBundle`을 사용해야 합니다. 프레임워크는 현재 WebGL 등가 구현을 제공하지 않으므로, 직접 래핑하거나 해당 경로에 대한 의존성을 제거해야 합니다.

## 검증

- 에디터에서 Build Target을 WebGL로 전환하여 씬 초기화 로직을 트리거하고, "WebGL is not supported" 외의 런타임 예외가 더 이상 출력되지 않는지 확인합니다.
- WebGL Build에서 브라우저 개발자 도구를 열고, `UnityWebRequest` 요청 경로가 `StreamingAssets` 하위의 올바른 상대 파일을 가리키며 응답 코드가 200인지 확인합니다.
- 비즈니스 경로를 다음과 같이 변경합니다: 비 WebGL은 `BlankReadAssets`를, WebGL은 `UnityWebRequest`를 사용하고, 두 경로에서 동일한 자원 로드 스모크 테스트를 각각 실행합니다.

## 배경 (선택 사항)

저장소 README의 Platform Notes 섹션에는 "WebGL is not supported"라는 문구가 명시되어 있으며, 본 프레임워크는 `UNITY_WEBGL` 구현 분기를 제공하지 않습니다. Android도 Editor도 아닌 다른 플랫폼은 모두 `LooseFilesImpl`에 매핑되며, 이 구현은 물리 디스크에서 파일을 읽기 때문에 WebGL 샌드박스의 동기/비동기 I/O 요구 사항을 충족할 수 없습니다.
