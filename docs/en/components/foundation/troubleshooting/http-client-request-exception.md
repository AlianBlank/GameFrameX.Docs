# What to Do When HttpClientRequestException Is Thrown or Response Errors Occur

When an HTTP request initiated through `GameFrameX.Foundation.Http.Extension` receives a non-success status code, hits a network-layer exception, or fails JSON deserialization, the framework throws `HttpClientRequestException`. This page shows you how to identify it, locate the cause, and choose the correct fix.

## Quick Diagnosis

| Symptom (Exception Message) | Cause | Fix |
|---|---|---|
| `HTTP request failed with status code {code} ({StatusCode}) for {uri}.` | The server returned a 4xx / 5xx response, and the caller invoked `EnsureSuccessStatusCode()` or triggered the internal status code check | See [Fix Steps - Status Code Failure](#fix-steps-status-code-failure) |
| `HTTP request failed for {method} {uri}.` | The underlying layer threw an `HttpRequestException` (DNS, connection, timeout, TLS, and other network-layer errors) that was not eligible for retry, or a general `Exception` fell into the `HttpRequestException / JsonException` branch | See [Fix Steps - Network Layer / General Exceptions](#fix-steps-network-layer--general-exceptions) |
| `HTTP JSON response could not be deserialized for {uri}.` | The response body is not valid JSON, or it does not match the target type | See [Fix Steps - JSON Deserialization Failure](#fix-steps-json-deserialization-failure) |

The exception type itself inherits from `HttpRequestException` and additionally carries the following diagnostic fields:

| Field | Type | Description |
|---|---|---|
| `StatusCode` | `HttpStatusCode?` | The HTTP status code returned by the server (if there was a response) |
| `RequestUri` | `Uri?` | The URI of the failed request |
| `ResponseSummary` | `string?` | A bounded summary of the response body (populated on failure) |
| `RawException` | `Exception?` | The original exception that triggered this exception (if any) |

```csharp
public sealed class HttpClientRequestException : HttpRequestException
{
    public HttpClientRequestException(
        string message,
        HttpStatusCode? statusCode,
        Uri? requestUri,
        string? responseSummary,
        Exception? rawException = null)
        : base(message, rawException, statusCode)
    {
        StatusCode = statusCode;
        RequestUri = requestUri;
        ResponseSummary = responseSummary;
        RawException = rawException;
    }

    public new HttpStatusCode? StatusCode { get; }
    public Uri? RequestUri { get; }
    public string? ResponseSummary { get; }
    public Exception? RawException { get; }
}
```

## Fix Steps

### Fix Steps: Status Code Failure

1. In the caller, use `try / catch` to catch `HttpClientRequestException` and use `StatusCode` to determine the specific failure type (401, 404, 500, etc.).

```csharp
try
{
    var response = await httpClient.SendJsonAsync<MyDto>(request, options);
    response.EnsureSuccessStatusCode();
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    // Resource not found; take the business fallback path
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.Unauthorized)
{
    // Refresh the token or prompt the user to log in again
}
```

2. If the request is meant to be fault-tolerant (for example, a GET list allows 404 to return empty), do not call `EnsureSuccessStatusCode()`; instead, read `IsSuccessStatusCode` and `Body` directly and handle them yourself.

```csharp
public HttpClientResponse EnsureSuccessStatusCode()
{
    if (IsSuccessStatusCode)
    {
        return this;
    }

    throw new HttpClientRequestException(
        $"HTTP request failed with status code {(int)StatusCode} ({StatusCode}) for {RequestUri}.",
        StatusCode,
        RequestUri,
        Body);
}
```

Source: [HttpClientResponse.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientResponse.cs#L80-L92)

3. Check the retry configuration. By default, the framework retries `HttpRequestException` a limited number of times; when `attempt <= options.Retry.MaxRetries`, it does not throw `HttpClientRequestException` but instead triggers a backoff retry.

```csharp
catch (HttpRequestException exception) when (allowRetry && attempt <= options.Retry.MaxRetries)
{
    await DelayBeforeRetryAsync(method, request.RequestUri, attempt, null, exception, options, effectiveToken);
    return (null, true);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L358-L362)

If the status code indicates failure but the retry budget is exhausted, an exception carrying the status is thrown at `CreateStatusException`:

### Fix Steps: Network Layer / General Exceptions

1. Network-layer problems (DNS, TCP, TLS, timeout) usually surface as an underlying `HttpRequestException`. When the retry budget is exhausted, or an `Exception` that is not an `HttpRequestException / JsonException` occurs, it is wrapped as:

```csharp
catch (Exception exception) when (exception is HttpRequestException or JsonException)
{
    throw new HttpClientRequestException(
        $"HTTP request failed for {method} {request.RequestUri}.",
        null,
        request.RequestUri,
        null,
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L363-L371)

2. Troubleshooting approach:
   - Read `ex.RawException?.Message` first; it usually contains the real underlying cause (for example, `The requested name is valid, but no data of the requested type was found`).
   - If it is a timeout, raise the timeout threshold in `HttpClientRequestOptions` or adjust `Retry.MaxRetries / Retry.Delay` so retries are more thorough.
   - If it is a TLS / certificate error, verify the certificate chain of the target address and the server-side SNI configuration.
   - If other exceptions are thrown under a custom `HttpMessageHandler` pipeline, the framework only wraps them when they satisfy `is HttpRequestException or JsonException`; all other exceptions bubble up unchanged and must be caught separately.

### Fix Steps: JSON Deserialization Failure

1. When the response body is not valid JSON, or a field type does not match the target type, the following is thrown:

```csharp
catch (JsonException exception)
{
    throw new HttpClientRequestException(
        $"HTTP JSON response could not be deserialized for {requestUri}.",
        null,
        requestUri,
        Summarize(responseText),
        exception);
}
```

Source: [HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L430-L438)

2. Troubleshooting approach:
   - Get the original `JsonException` from `ex.RawException` to pinpoint the exact field path and line number.
   - Inspect `ex.ResponseSummary` to view the response body summary and confirm the format returned by the server (`application/json` vs `text/html`).
   - If necessary, configure `PropertyNameCaseInsensitive`, `NumberHandling`, `AllowTrailingCommas`, etc. in `HttpClientRequestOptions.JsonSerializerOptions` to make deserialization more lenient.

## Verification

1. Deliberately construct a request that will fail (pointing to a non-existent address or an endpoint that returns 500), and confirm that `HttpClientRequestException` is caught and that the values of the `StatusCode` / `RequestUri` / `ResponseSummary` fields match expectations.
2. In a deserialization failure scenario, cast `RawException` to `JsonException` and confirm that its `Path` points to the field that caused the failure.
3. With `Retry.MaxRetries > 0` enabled, temporarily make the target endpoint return a 5xx once, and confirm that backoff retry records appear in the logs and that `HttpClientRequestException` is finally thrown as expected by the business logic.
