# How to Use AES Encryption and Decryption

`AesHelper` provides authenticated encryption and decryption based on AES-GCM: pass in plaintext and a key to get a Base64 ciphertext, then decrypt with the same key to restore the original text. A Salt and Nonce are randomly generated on every encryption, so callers don't need to manage them.

## Prerequisites

- The project references the NuGet package `GameFrameX.Foundation.Encryption`.
- The target framework supports `System.Security.Cryptography.AesGcm` (.NET 5+ / .NET Standard 2.1 platform implementation).
- `using GameFrameX.Foundation.Encryption;` and `using System.Text;`.

## Steps

### 1. String Encryption and Decryption (Base64 Output)

```csharp
using GameFrameX.Foundation.Encryption;

string plain = "Hello, World! 这是一个测试字符串。";
string key = "MySecretKey123456";

string cipher = AesHelper.Encrypt(plain, key);
string back = AesHelper.Decrypt(cipher, key);
// back == plain
```

### 2. Byte Array Encryption and Decryption (for Binary Data)

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

byte[] data = Encoding.UTF8.GetBytes("任意二进制数据");
byte[] cipherBytes = AesHelper.Encrypt(data, "MySecretKey123456");
byte[] plainBytes = AesHelper.Decrypt(cipherBytes, "MySecretKey123456");
```

### 3. Persisting or Transmitting the Ciphertext

Store `cipher` (a Base64 string) or `cipherBytes` (binary) in a database or configuration file, or send it over the network; the receiver calls `Decrypt` with the same key to restore the original.

```csharp
// Pseudocode: save the ciphertext to a file
File.WriteAllText("secret.bin", cipher);

// Pseudocode: read and decrypt
string read = File.ReadAllText("secret.bin");
string original = AesHelper.Decrypt(read, key);
```

## Common Variants

- **Keys of different lengths**: The source code uses PBKDF2(SHA256, 600,000 iterations) to derive a 32-byte key from any string key; passing anything from `"ShortKey"` to `"VeryLongKeyThatExceedsNormalLength123456789"` encrypts and decrypts correctly.
- **Plaintext containing Unicode/Emoji**: The plaintext is UTF-8 encoded before encryption, so 4-byte characters such as `"🚀🌟💻🎮🔥"` round-trip correctly.
- **Encrypting the same plaintext + same key twice**: The two results differ (because the Salt/Nonce is random), but both results decrypt back to the original text — this is the semantic security property of AES-GCM.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentException: Plain text cannot be null or empty` | Plaintext is `null` or `""` | Check that the string is non-empty before encrypting |
| `ArgumentException: Encryption key cannot be null or empty` | Key is empty | Provide a non-empty string key of length ≥ 1 |
| `ArgumentException: Cipher text byte array is too short to be valid.` | Ciphertext length is less than 45 bytes (1+16+12+16 header) | Confirm you are passing the complete output of `Encrypt` |
| `CryptographicException: Unsupported AES payload format version.` | The ciphertext header version byte is not `2` | Upgrade to the current version of the library, or decrypt using the old version |
| `CryptographicException` (during decryption) | Key differs from the one used for encryption, or the data was tampered with | Confirm encryption and decryption use the same key, and verify transmission integrity |

> Passing `null` / an empty string for any parameter to the encryption/decryption calls will immediately throw an `ArgumentException`; you can assert before calling or handle it in an outer `try/catch`.

## Background (Optional)

The implementation uses AES-GCM authenticated encryption: a random 16-byte Salt and 12-byte Nonce are generated each time, combined with PBKDF2(SHA256, 600k iterations) to derive a 32-byte session key from the string key. The output format is `Version(1) | Salt(16) | Nonce(12) | Tag(16) | Ciphertext`, where the Tag is used for integrity verification; tampering or a wrong key will throw a `CryptographicException` during decryption.
