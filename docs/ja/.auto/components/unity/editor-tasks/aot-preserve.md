# AOT 保持設定と検証の使用

Unity メニュー `GameFrameX/HybridCLR Generate AOT Preserve` からワンクリックで `link.xml`、参照集約コード、型ごとに分割された参照コードファイルを生成し、検証エグゼキュータによって CI 上で生成ファイルが常に最新設定と一致することを保証し、HybridCLR ホット更新時に AOT メタデータが欠落するのを防ぎます。

## 前提条件

- プロジェクトに HybridCLR がインストールされていること（ランタイムはホット更新 AOT メタデータに依存します）。
- `IAotPreserveSettingsProvider` のカスタム実装が提供されているか、デフォルト実装下で構成エントリが配置されていること（デフォルト実装は [IAotPreserveSettingsProvider.cs](/Editor/AotPreserve/IAotPreserveSettingsProvider.cs) にあります）。
- Unity エディタでプロジェクトが開かれており、`Assets/Generated/` ディレクトリへの書き込み権限があること。

## 操作手順

1. **生成をトリガーする**。Unity エディタのトップメニューから `GameFrameX > HybridCLR Generate AOT Preserve` を選択すると、`AotPreserveGenerator.GenerateAndWrite()` が呼び出され、ログがコンソールに出力されます。

   メニューエントリの実装は [AotPreserveMenu.cs#L20-L25](/Editor/AotPreserve/AotPreserveMenu.cs#L20-L25) を参照してください：

   ```csharp
   [MenuItem(AotPreserveConstants.MenuPath)]
   public static void Generate()
   {
       AotPreserveGenerator.GenerateAndWrite();
       Debug.Log("Hotfix AOT preserve files generated under " + AotPreserveConstants.GeneratedDirectory);
   }
   ```

2. **生成パスを確認する**。生成ルートディレクトリのデフォルトは `Assets/Generated/AotPreserve` で、コア成果物のパスは定数で一元管理されています。[AotPreserveConstants.cs#L17-L65](/Editor/AotPreserve/AotPreserveConstants.cs#L17-L65) を参照してください：

   | 成果物 | パス定数 | 実際のパス |
   |------|----------|----------|
   | `link.xml`（マネージコード stripping 保持） | `LinkXmlPath` | `Assets/Generated/AotPreserve/link.xml` |
   | 参照集約コード | `ReferencesPath` | `Assets/Generated/AotPreserveReferences.cs` |
   | 型ごと分割参照ファイル名のプレフィックス | `ReferenceTypeFilePrefix` | `AotPreserveReference_<TypeName>.cs` |
   | 生成コード所属 asmdef | `GeneratedAsmdefPath` | `Assets/Generated/AotPreserve.Generated.asmdef` |
   | 生成レポート Markdown | `ReportPath` | `Assets/Generated/AotPreserve/aot_preserve_report.md` |

3. **CI で検証を呼び出す**。CI またはユニットテストから直接 `AotPreserveValidationRunner.ValidateGeneratedFiles()` を呼び出せます。ファイルが欠落または期限切れの場合は `InvalidOperationException` がスローされ、例外メッセージにすべてのエラーが集約されます。[AotPreserveValidationRunner.cs#L20-L27](/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27) を参照してください：

   ```csharp
   public static void ValidateGeneratedFiles()
   {
       var errors = AotPreserveGenerator.ValidateGeneratedFiles();
       if (errors.Length > 0)
       {
           throw new InvalidOperationException(string.Join("\n", errors));
       }
   }
   ```

4. **エラー処理**。生成プロセスでエラーが発生した場合（設定が無効、書き込み失敗など）、`GenerateAndWrite()` は `InvalidOperationException` をスローし、`"Hotfix AOT preserve generation failed:\n"` で始まるメッセージにエラーが一行ずつ列挙されます。[AotPreserveGenerator.cs#L72-L78](/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L78) を参照してください。ディスクへの書き込みが失敗した場合は `IOException` または `UnauthorizedAccessException` もスローされます。

## よくあるバリエーション

- **プログラムからのトリガー**：メニュークリックが不要な場合は、エディタスクリプト内で `AotPreserveGenerator.GenerateAndWrite()` を直接呼び出せます。
- **純粋なビルド（ディスク書き込みなし）**：カスタムパイプラインでプレビューだけしたい場合は、`AotPreserveGenerator.Build()` を使用して `AotPreserveBuildResult`（`LinkXml`、`ReferencesCode`、`GeneratedAsmdef`、`Report`、`ReferenceFiles`、`Errors` を含む）を取得します。[AotPreserveGenerator.cs#L29-L61](/Editor/AotPreserve/AotPreserveGenerator.cs#L29-L61) を参照してください。
- **カスタム設定プロバイダ**：`IAotPreserveSettingsProvider` を実装し、`AotPreserveSettingsProviderResolver` 経由で注入することで、デフォルト設定の出所をオーバーライドできます。

## よくあるエラー

- **メニュークリック後コンソールに `Hotfix AOT preserve generation failed: ...` が表示される**：`Build()` が返す `AotPreserveBuildResult.Errors` が空ではないことを意味します。通常は `IAotPreserveSettingsProvider` の設定が無効か、分析段階で失敗しています。例外メッセージに従って一つずつ修正し、再生成してください。
- **CI で検証が `InvalidOperationException` をスローし複数のエラーを列挙する**：`link.xml`、参照コード、または `asmdef` が現在の分析結果と一致していないことを示します。メニューから生成を一度実行すればリフレッシュされます。
- **`UnauthorizedAccessException`**：`Assets/Generated/AotPreserve/` ディレクトリの書き込み権限と、`Assets/Generated/AotPreserve.Generated.asmdef` が他のプロセスにロックされていないか確認してください。
- **生成ファイルが欠落している**：`Assets/Generated/AotPreserve` を手动で删除したのにメニューを再トリガーしていない場合に発生します。メニューから生成を一度実行すれば成果物一式が再構築されます。

## 背景（オプション）

生成エントリ `AotPreserveGenerator.GenerateAndWrite()` は、まず `AotPreserveAnalyzer.Analyze()` を呼び出して保持が必要な型を集約し、それぞれ `link.xml`（マネージ stripping 時のアセンブリレベル保持用）、集約および型ごとに分割された参照コード（ランタイムで明示的に AOT メタデータ読み込みをトリガーするため）、監査用の `aot_preserve_report.md` レポートを出力します。`ValidateGeneratedFiles()` は最新の分析結果と照合することでファイルが期限切れかどうかを検出します。
