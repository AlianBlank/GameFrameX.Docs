# 커스텀 통계 Provider 구현 방법 (BaseGameAnalyticsManager 상속)

`BaseGameAnalyticsManager`를 상속하고 모든 추상 멤버를 구현하면, `GameAnalyticsComponent`에 의해 자동으로 발견·초기화되고 모든 이벤트 리포팅을 전달해 주는 커스텀 통계 Provider가 완성됩니다. 프레임워크에는 구체적인 Provider가 내장되어 있지 않으므로, ThinkingData, 우망(Umeng) 또는 자체 구축한 트래킹 서비스 연동은 모두 이 페이지의 방식대로 직접 구현해야 합니다.

## 사전 조건

- 프로젝트에 GameFrameX 런타임이 설치되어 있어야 합니다（`GameFrameworkModule`, `GameFrameworkComponent`는 `GameFrameX.Runtime`에서 제공）.
- 씬에 GameAnalytics 컴포넌트가 이미 존재해야 합니다（메뉴 `Game Framework/GameAnalytics`, 컴포넌트는 `[DisallowMultipleComponent]`）.

## 작업 단계

### 1. 새 클래스를 만들고 BaseGameAnalyticsManager 상속

`BaseGameAnalyticsManager`는 추상 클래스로, `GameFrameworkModule`를 상속하고 `IGameAnalyticsManager`를 구현하며, 공용 속성 딕셔너리 `m_PublicProperties`와 초기화 플래그 `m_IsInit`가 내장되어 있습니다:

```csharp
public abstract class BaseGameAnalyticsManager : GameFrameworkModule, IGameAnalyticsManager
{
    protected bool m_IsInit = false;
    protected readonly Dictionary<string, object> m_PublicProperties = new Dictionary<string, object>();
```

### 2. 모든 추상 멤버 구현

아래 멤버들은 기본 구현이 없으므로 서브클래스에서 반드시 모두 구현해야 합니다（시그니처는 기본 클래스에서 직접 가져온 것입니다）:

| 멤버 | 시그니처 | 설명 |
|------|------|------|
| `Init` | `public abstract void Init(Dictionary<string, string> args)` | 자동 초기화, args는 Inspector의 Setting 키-값 쌍에서 전달됨 |
| `ManualInit` | `public abstract void ManualInit(Dictionary<string, string> args)` | 수동 초기화, `IsManualInit()`가 `true`를 반환할 때만 컴포넌트가 호출 |
| `IsManualInit` | `public abstract bool IsManualInit()` | 수동 초기화 모드 사용 여부 |
| `StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer` | `public abstract void Xxx(string eventName)` | 이벤트 타이머 4종 세트 |
| `Event` | `public abstract void Event(string eventName)` | 이벤트 리포트 |
| `Event` | `public abstract void Event(string eventName, float eventValue)` | 수치값이 있는 이벤트 리포트 |
| `Event` | `public abstract void Event(string eventName, Dictionary<string, object> customF)` | 커스텀 필드가 있는 이벤트 리포트 |
| `Event` | `public abstract void Event(string eventName, float eventValue, Dictionary<string, object> customF)` | 수치값과 커스텀 필드가 있는 이벤트 리포트 |
| `SetPlayerId` | `public abstract void SetPlayerId(string playerId)` | 플레이어 ID 설정 |

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L31-L202)、[IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L105)

아래 스켈레톤은 기본 클래스의 실제 시그니처에 맞춰 구성한 것으로, 메서드 본문은 실제 SDK를 연동하면서 채워 넣으세요:

```csharp
using System.Collections.Generic;
using GameFrameX.GameAnalytics.Runtime;

namespace YourGame.Analytics
{
    public class MyAnalyticsProvider : BaseGameAnalyticsManager
    {
        public override void Init(Dictionary<string, string> args)
        {
            // args의 키-값 쌍은 GameAnalyticsComponent Inspector의 Setting에서 전달됨
            m_IsInit = true;
        }

        public override void ManualInit(Dictionary<string, string> args) { }
        public override bool IsManualInit() { return false; }

        public override void StartTimer(string eventName) { /* 타이머 시작 */ }
        public override void PauseTimer(string eventName) { }
        public override void ResumeTimer(string eventName) { }
        public override void StopTimer(string eventName) { /* 소요 시간 이벤트 리포트 */ }

        public override void Event(string eventName) { /* 대상 SDK로 전달 */ }
        public override void Event(string eventName, float eventValue) { }
        public override void Event(string eventName, Dictionary<string, object> customF) { }
        public override void Event(string eventName, float eventValue, Dictionary<string, object> customF) { }

        public override void SetPlayerId(string playerId) { /* 계정 바인딩 */ }
    }
}
```

### 3. GameAnalyticsComponent에 Provider 등록

컴포넌트는 타입 전체 이름 문자열로 리플렉션하여 인스턴스를 생성하므로, 여러분의 클래스에는 **반드시 매개변수 없는 생성자**가 있어야 하고, Provider 항목의 `ComponentType`에 전체 타입 이름（네임스페이스 포함）을 입력해야 합니다:

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L77)

구체적인 조작: Inspector에서 `GameAnalyticsComponent`의 Provider 리스트를 펼치고 항목을 추가합니다:

| 필드 | 입력 내용 |
|------|----------|
| `ComponentType` | `YourGame.Analytics.MyAnalyticsProvider`（네임스페이스를 포함한 타입 전체 이름） |
| `Setting` | `Init(args)`에 전달할 키-값 쌍, 예: `app_id`, `server_url` 등 |

### 4. 컴포넌트를 통해 통합 호출

초기화는 `OnEnable()` 시점에 자동으로 `Init()`을 한 번 호출하며, 이후 모든 리포팅은 컴포넌트 레이어를 거치며, 컴포넌트가 호출을 리스트의 모든 Provider에게 전달합니다:

```csharp
// 이벤트 리포트 (컴포넌트 레이어에서 파라미터 검증 및 미초기화 보호 수행)
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

비즈니스 코드에서의 전형적인 사용법: `GameEntry.GameAnalytics.Event("level_complete")`, `StartTimer("battle")` / `StopTimer("battle")`, `SetPlayerId(userId)`.

## 일반적인 변형

- **수동 초기화**: `IsManualInit()`가 `true`를 반환하도록 하면, 컴포넌트의 `ManualInit(Dictionary<string, string> extraArgs)`가 적절한 시점（예: 플레이어 로그인 후）에 추가 파라미터를 여러분의 `ManualInit` 구현으로 전달합니다; `false`를 반환하면 컴포넌트는 해당 Provider의 수동 초기화 호출을 건너뜁니다.
- **여러 Provider 공존**: Provider 리스트에는 여러 항목을 설정할 수 있으며（예: ThinkingData + 자체 로그 동시 연동）, 컴포넌트 레이어의 모든 `Event` / 타이머 / `SetPlayerId` 호출이 초기화된 모든 Provider에게 루프를 돌며 전달됩니다.
- **커스텀 디바이스 공용 속성**: 기본 디바이스 정보（`device_id`, `os`, `app_version`, `network_type` 등）는 `AddDeviceInfoToPublicProperties()`가 작성합니다; 해당 `protected virtual` 메서드를 `override`하여 필드를 추가하거나 제거할 수 있습니다. `SetPublicProperties(key, value)`로 언제든 커스텀 공용 속성을 추가할 수 있습니다.

```csharp
protected override void AddDeviceInfoToPublicProperties()
{
    base.AddDeviceInfoToPublicProperties();
    m_PublicProperties["channel"] = "your_channel";
}
```

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 콘솔에 `Can not find component type 'xxx'.` 출력 | `ComponentType`에 입력한 타입 전체 이름의 오타 또는 어셈블리가 리플렉션 스캔 대상이 아님 | 네임스페이스와 타입 이름 확인; 클래스가 `public`이고 매개변수 없는 생성자를 가지는지 확인 |
| 콘솔에 `GameAnalyticsManager is not init.` 반복 출력 | 서브클래스의 `Init(args)`에서 `m_IsInit`를 `true`로 설정하는 것을 잊음 | `Init` 성공 후 `m_IsInit = true` 설정 |
| `Event` 호출 시 파라미터 예외 발생 | 이벤트 이름이 비어 있음 | `GameFrameworkGuard.NotNullOrEmpty`는 이벤트 이름이 비어 있지 않아야 하므로 유효한 문자열 전달 |
| `ManualInit`의 파라미터를 받지 못함 | 해당 Provider의 `IsManualInit()`가 `false`를 반환함 | `true`를 반환해야 컴포넌트의 전달을 받을 수 있음 |
| `SetPublicProperties(key, value)`가 동작하지 않음 | `key`가 빈 문자열이면 기본 클래스가 바로 `return`함 | 비어 있지 않은 key 사용 |

## 배경

`GameAnalyticsComponent`는 `Awake`에서 `IsAutoRegister = false`를 설정하고 `OnEnable`에서 `Init()`을 한 번 수행합니다: `ComponentType` 문자열로 리플렉션하여 `IGameAnalyticsManager` 인스턴스를 생성하고, Inspector의 `Setting` 키-값 쌍을 `Dictionary<string, string>`으로 묶어 `Init(args)`에 전달한 뒤, 이후 모든 리포팅 호출을 "브로드캐스트" 방식으로 전체 Provider에게 전달합니다. 기본 클래스 `BaseGameAnalyticsManager`는 `m_IsInit`와 `m_PublicProperties`（디바이스/시스템/네트워크 공용 속성）를 통일되게 관리하며, 서브클래스는 각자의 SDK 리포팅 세부 사항에만 집중하면 됩니다.
