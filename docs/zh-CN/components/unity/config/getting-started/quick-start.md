# 5 分钟加载第一个配置表

跟着本页操作，你将在 5 分钟内安装 GameFrameX Config 配置表包，并通过 `ConfigComponent` 在 Unity 中加载并读取你的第一张配置表。

## 前置条件

- Unity 2019.4 或更高版本
- 项目中已引入 `com.gameframex.unity`（GameFrameX 核心框架）
- 依赖项：`com.gameframex.unity.asset`、`com.gameframex.unity.event`
- 一个用于挂载 `GameFrameworkEntry` 的场景对象（GameFrameX 入口组件）

## 操作步骤

### 1. 安装配置表包

编辑 Unity 项目根目录的 `Packages/manifest.json`，加入 GameFrameX scoped registry，并在 `dependencies` 中声明配置表包（推荐方式，可解析后续更新版本）：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.config": "1.1.5"
  }
}
```

如果你的网络无法访问 scoped registry，可以改用 Git URL 直接安装，在 `dependencies` 中添加：

```json
{
  "com.gameframex.unity.config": "https://github.com/gameframex/com.gameframex.unity.config.git"
```

Source: [README.zh-CN.md](/src/README.zh-CN.md#L56-L61)

安装完成后 Unity 会刷新包列表，确认在 Package Manager 中能看到 `com.gameframex.unity.config`。

### 2. 让场景里挂上入口与配置组件

确保场景中存在 `GameFrameworkEntry`（或通过 `com.gameframex.unity.entry` 启动），`ConfigComponent` 通过特性自动注册到框架，无需手动添加：

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Config")]
[GameFrameXAutoComponent(-5000)]
public sealed class ConfigComponent : GameFrameworkComponent
```

Source: [ConfigComponent.cs](/src/Runtime/Config/ConfigComponent.cs#L46-L49)

只要 GameFrameX 启动，`Awake()` 会自动创建内部 `IConfigManager`，你不需要自己 new 它。

### 3. 通过 GameEntry 拿到 ConfigComponent 并加载配置

使用 `GameEntry.GetComponent<ConfigComponent>()` 取得全局组件，并调用 `LoadConfig` 加载你的第一张表：

```csharp
// 标准方式：通过 GameEntry（不依赖 com.gameframex.unity.entry）
var configComponent = GameEntry.GetComponent<ConfigComponent>();
configComponent.LoadConfig("ConfigPath");
```

Source: [README.zh-CN.md](/src/README.zh-CN.md#L66-L70)

> 提示：`ConfigPath` 是配置表资源的加载键，由你的项目资源管理约定决定；具体路径请按项目实际情况替换。

### 4. 实现一张配置表并读取

你的配置数据类型必须实现 `IDataTable` 接口，框架通过类型名作为键管理它们。随后使用 `GetConfig<T>` 读取：

```csharp
public class MyConfigTable : IDataTable
{
    // 你的字段与读取逻辑
}

[Preserve]
public T GetConfig<T>() where T : IDataTable
{
    var configName = GetTypeName<T>();
    var config = m_ConfigManager.GetConfig(configName);
    if (config != null)
    {
        return (T)config;
    }
    return default;
}
```

```csharp
var table = configComponent.GetConfig<MyConfigTable>();

}
```

### 5. 注册成功 / 失败回调（可选）

通过框架事件订阅加载结果：

| 事件 | 用途 |
|------|------|
| `LoadConfigSuccessEventArgs` | 配置加载成功时触发 |
| `LoadConfigFailureEventArgs` | 配置加载失败时触发 |
| `LoadConfigUpdateEventArgs` | 配置热更新时触发 |

订阅方式遵循 GameFrameX 的 `GameEntry.GetComponent<EventComponent>()` 标准模式。

## 常见变体

- **通过类型键加载**：使用 `HasConfig<T>()` / `RemoveConfig<T>()` 进行存在性判断与移除，键为 `typeof(T).Name`：

```csharp
[Preserve]
public bool HasConfig<T>() where T : IDataTable
{
    var configName = GetTypeName<T>();
    return m_ConfigManager.HasConfig(configName);
}
```

Source: [ConfigComponent.cs](/src/Runtime/Config/ConfigComponent.cs#L138-L143)

- **运行时动态添加配置**：调用 `Add(configName, dataTable)` 把已构造的 `IDataTable` 注册进管理器：

```csharp
configComponent.Add("MyConfig", myDataTableInstance);
```

Source: [ConfigComponent.cs](/src/Runtime/Config/ConfigComponent.cs#L181-L185)

- **清空所有配置**：`RemoveAllConfigs()` 会同时清空类型映射与所有表项。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `Log.Fatal("Config manager is invalid.")` | `Awake()` 中没能通过 `GameFrameworkEntry.GetModule<IConfigManager>()` 取到管理器 | 确认 `com.gameframex.unity` 已安装，且 `ConfigComponent` 已被框架正常初始化 |
| `GetConfig<T>()` 返回 `default` | 表尚未加载或名称不匹配 | 确认 `LoadConfig` 已传入正确资源键；确认数据类型实现 `IDataTable` |
| 编辑器找不到 `GameFrameX/Config` 菜单 | 包未正确导入 | 重启 Unity 或在 Package Manager 中重新解析 `com.gameframex.unity.config` |

## 背景（可选）

`ConfigComponent` 通过 `[GameFrameXAutoComponent(-5000)]` 在 GameFrameX 启动时自动注册，优先级较低以便其他资源/事件组件先就绪。内部把类型映射缓存在 `ConcurrentDictionary<Type, string>`，键为 `typeof(T).Name`，避免每次反射取名。所有表项统一由 `IConfigManager` 维护，多线程安全。
