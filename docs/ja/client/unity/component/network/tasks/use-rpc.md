# RPC 呼び出しとタイムアウト処理の使用

このページの手順に従うことで、RPC 方式でリクエストメッセージを送信し、サーバーからの応答を `await` できます。設定されたタイムアウト時間(デフォルト 5000 ミリ秒)を超えても応答が受信されない場合、タスクは `TimeoutException` 例外で終了します。また、グローバルな開始/タイムアウト/エラーコードイベントにフックして一括処理を行うこともできます。

## 前提条件

- シーンに `NetworkComponent` がアタッチされており、`CreateNetworkChannel` によってネットワークチャンネルが作成済みであること(タイムアウト時間はチャンネル作成時に合わせて渡されます)。
- リクエストメッセージは `IRequestMessage` を実装し、レスポンスメッセージは `IResponseMessage` を実装していること。また、レスポンスメッセージの `UniqueId` は対応するリクエストと一致していること——RPC の応答マッチングは、`UniqueId` によって待機テーブルを検索して行われます。

## 操作手順

1. **RPC タイムアウト時間を設定する**。Inspector の NetworkComponent パネルで `RPC Timeout Time In Milliseconds` を調整する(スライダーの範囲は 3000–50000、非実行時にのみ変更可能)、またはシリアライズフィールドを直接変更する(デフォルトは 5000):

```csharp
/// <summary>
/// RPCタイムアウト時間(ミリ秒単位、デフォルトは5秒)
/// </summary>
[SerializeField] private int m_rpcTimeout = 5000;
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L60-L63)

この値は、チャンネル作成時に RPC ステートへ渡されます:

```csharp
var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L179)

2. **リクエスト/レスポンスメッセージペアを定義する**。リクエストは `IRequestMessage` を実装し、レスポンスは対応する `IResponseMessage` を実装します。

3. **RPC 呼び出しを発行して結果を待機する**。`RpcState.Call` を呼び出して `Task<IResponseMessage>` を取得し、それを `await` することで、レスポンスを受信した時点で処理を続行できます:

```csharp
public Task<IResponseMessage> Call(MessageObject messageObject, bool isIgnoreErrorCode)
{
    if (_waitingReplyHandlingObjects.TryGetValue(messageObject.UniqueId, out var messageActorObject))
    {
        return messageActorObject.Task;
    }

    var defaultMessageActorObject = RpcMessageData.Create(messageObject as IRequestMessage, _rpcTimeout, isIgnoreErrorCode);
    if (!_waitingReplyHandlingObjects.TryAdd(messageObject.UniqueId, defaultMessageActorObject))
    {
        return defaultMessageActorObject.Task;
    }
    try
    {
        _rpcStartHandler?.Invoke(this, messageObject);
    }
    catch (Exception e)
    {
        Log.Fatal(e);
    }

    return defaultMessageActorObject.Task;
}
```

Source: [NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L140-L162)

同一の `UniqueId` での重複呼び出しは、既に存在する待機タスクをそのまま返し、再度発行されることはありません。

4. **タイムアウト例外を処理する**。タイムアウト判定は毎フレームの `Update` で実時間(ミリ秒)を累積することによって行われ、期限切れになるとタスクに以下の例外を設定して待機テーブルから取り除きます:

```csharp
internal bool IncrementalElapseTime(long time)
{
    ElapseTime += time;
    if (ElapseTime >= Timeout)
    {
        m_Tcs.TrySetException(new TimeoutException($"Rpc call timeout! Message FullName:{RequestMessage.GetType().FullName} is :{RequestMessage}"));
        return true;
    }

    return false;
}
```

Source: [NetworkManager.RpcState.RpcMessageData.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.RpcMessageData.cs#L64-L74)

呼び出し側でのキャッチ例(前のステップで返された Task に基づく):

```csharp
try
{
    var response = await rpcTask; // rpcTask は Call が返す Task<IResponseMessage>
}
catch (TimeoutException)
{
    // m_rpcTimeout 経過しても応答を受信できない場合は、ユーザーに通知するか再試行を行う
}
```

5. **(任意)グローバル RPC イベントにフックする**。UI に「リクエスト中」を表示したり、タイムアウトの通知を一括で表示したりする用途に使用します:

```csharp
[UnityEngine.Scripting.Preserve]
public void SetRPCErrorHandler(EventHandler<MessageObject> handler)
{
    GameFrameworkGuard.NotNull(handler, nameof(handler));
    _rpcErrorHandler = handler;
}
```

## よくあるバリエーション

- **エラーコードを無視する**:`Call` の第二引数に `true` を渡す(`isIgnoreErrorCode`)と、レスポンスの `ErrorCode != 0` であってもグローバルエラーコードイベントはトリガーされず、レスポンスの内容はビジネス側で独自に処理します。判定ロジックは `TryReply` を参照:

```csharp
if (responseMessage?.ErrorCode != 0 && !messageActorObject.IsIgnoreErrorCode)
{
    _rpcErrorCodeHandler?.Invoke(this, message);
}
```

Source: [NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L115-L118)

- **グローバルイベントの三種セット**:`SetRPCStartHandler`(呼び出しの発行)、`SetRPCErrorHandler`(タイムアウト)、`SetRPCErrorCodeHandler`(ビジネスエラーコード)。いずれも handler が非 null であることが必要で、そうでない場合は `GameFrameworkGuard.NotNull` が引数の例外をスローします。
- **再接続シナリオ**:切断からの再接続に成功した後、`RpcState.Reset()` を呼び出します。これにより、待機中のすべてのタスクが Dispose され(対応する Task はキャンセルとして終了します)、待機テーブルがクリアされます:

```csharp
public void Reset()
{
    foreach (var kvp in _waitingReplyHandlingObjects)
    {
        kvp.Value.Dispose();
    }

    _waitingReplyHandlingObjects.Clear();
    _disposed = false;
}
```

Source: [NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L86-L95)

## よくあるエラー

| 症状/エラーメッセージ原文 | 原因 | 修正 |
|------|------|------|
| コンストラクター実行時に `ArgumentOutOfRangeException` がスローされる: `RPC超时时间不能小于3000毫秒` | `m_rpcTimeout` が 3000 未満に変更された | タイムアウトを 3000–50000 の範囲に調整する |
| `await` が `TimeoutException` をスローする: `Rpc call timeout! Message FullName:...` | タイムアウト時間を過ぎてもマッチするレスポンスを受信しなかった | サーバーが応答を返しているか、レスポンスの `UniqueId` がリクエストと一致しているかを確認する。必要に応じて `m_rpcTimeout` を大きくする |
| `await` が `TaskCanceledException` をスローする | `RpcState` が `Dispose()`/`Reset()` され、待機タスクが `TrySetCanceled` された | 再接続後に改めて呼び出しを発行する |
| レスポンスを受信したが `TryReply` が false を返し、Task がずっと保留状態のまま | レスポンスが `IResponseMessage` を実装していない、またはその `UniqueId` がリクエストと一致しない | レスポンスメッセージに `IResponseMessage` を実装させ、`UniqueId` を一致させる |
| レスポンスの `ErrorCode != 0` であるにもかかわらずグローバルエラーコードイベントがトリガーされない | 呼び出し時に `isIgnoreErrorCode` に `true` を渡した | グローバル処理が必要な場合は `false` を渡す |

タイムアウト下限の検証は `RpcState` のコンストラクターにあります:

```csharp
public RpcState(int timeout)
{
    _rpcTimeout = timeout;
    if (_rpcTimeout < 3000)
    {
        throw new ArgumentOutOfRangeException(nameof(timeout), "RPC超时时间不能小于3000毫秒");
    }
}
```

Source: [NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L58-L65)

## 背景

内部実装:`RpcState` は `ConcurrentDictionary<long, RpcMessageData>`(`_waitingReplyHandlingObjects`)を使用して、`UniqueId` ごとに待機中の呼び出しを保持します。各呼び出しは `RpcMessageData.Create(IRequestMessage, int timeout = 5000, bool isIgnoreErrorCode = false)` によって作成され、内部で `TaskCompletionSource<IResponseMessage>` を保持します。毎フレームの `Update` で `realElapseSeconds` をミリ秒に換算して `ElapseTime` に累積し、期限切れの呼び出しはまず `_rpcErrorHandler` をトリガーし、その後まとめて削除されます。一連の処理全体を通じて、事前割り当てされた `_timeoutIds` リストを使用することで毎フレームの GC を回避しています。
