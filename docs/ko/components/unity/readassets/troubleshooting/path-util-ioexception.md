# PathUtil에서 IOException 발생: Invalid path: double dot error / Invalid characters

`PathUtil.NormalizeRelativePath`를 호출할 때, 전달된 상대 경로에 범위를 벗어나는 `..` 세그먼트나非法 문자가 포함되어 있으면 `System.IO.IOException`이 발생하며, 일반적인 메시지는 두 가지입니다: `Invalid path: double dot error (before N)` 그리고 `Invalid characters`.

## 빠른 진단

| 증상 (예외 메시지 원문) | 원인 | 수정 방법 |
|---|---|---|
| `Invalid path: double dot error (before <N>)` | 이미 "가상 루트 `/`"에 도달한 이후에도 `..`을 사용하여 한 단계 더 위로 올라가려 할 때 | 불필요한 `../`을 제거하고, 경로가 진입 루트 디렉터리를 넘어가지 않도록 보장 |
| `Invalid characters` | 경로에 `IsValidCharacter`이 거부하는 문자가 포함됨 (`\"`, `<`, `>`, `|`, 제어 문자 `<32`, `:`, `*`, `?`) | 불법 문자를 제거하거나 대체 |

두 예외 모두 `Runtime/PathUtil.cs`의 `NormalizeRelativePath`에서 발생합니다.

## 수정 단계

### 1. `Invalid path: double dot error` 처리

발생 조건: 파싱 과정에서 `..`이 이미 정규화된 "루트 `output`"을 넘어가려 할 때. 소스 코드 일부:

```csharp
// Runtime/PathUtil.cs#L107-L112
else if ( state == NormalizeState.PrevDoubleDot )
{
    if ( output.Length == 1 )
    {
        throw new System.IO.IOException("Invalid path: double dot error (before " + i + ")");
    }
    ...
}
```

즉, `..`이 나타났을 때 현재 누적된 출력이开头의 루트 슬래시뿐이면 즉시 예외가 발생합니다.

수정 방법:

1. 전달된 상대 경로를 출력하여 문제가 되는 `..`을 찾습니다.
2. 실제로 위로 갈 수 있는 층수(경로 접두사에 있는 `..`이 아닌 세그먼트 수)를 계산하고, 불필요한 `../`를 삭제합니다.
3. 호출자가 `Path.Combine`을 사용하여 절대 경로와 `../`가 포함된 상대 경로를 결합한 경우, `PathUtil.CombineSlash`를 사용하거나 먼저 `NormalizeRelativePath`를 사용한 후 결합합니다.

```csharp
// NormalizeRelativePath를 사용하기 전에 ../를 합리적인 범위로 축소
var safe = relative.Replace("..\\", "").Replace("../", "");
var normalized = PathUtil.NormalizeRelativePath(safe);
```

`NormalizeRelativePath`는 시작과 끝에 큰따옴표로 감싼 형태도 지원합니다. 소스 코드에서开头와 끝이 모두 `"`인 것을 감지하면 자동으로 제거한 후 파싱합니다(`Runtime/PathUtil.cs#L93-L97`). 이를 불법 문자를 우회하는 "출구"로 사용하지 마십시오. 아래의 예외는 여전히 발생합니다.

### 2. `Invalid characters` 처리

발생 조건: 경로에 `IsValidCharacter`가 허용하지 않는 문자가 나타날 때:

```csharp
// Runtime/PathUtil.cs#L173-L180
public static bool IsValidCharacter(char c)
{
    if (c == '\"' || c == '<' || c == '>' || c == '|' || c < 32 || c == ':' || c == '*' || c == '?')
    {
        return false;
    }
    return true;
}
```

소스 코드에서 예외를 발생시키는 위치:

```csharp
// Runtime/PathUtil.cs#L159-L162
if (!IsValidCharacter(relative[i]))
{
    throw new System.IO.IOException("Invalid characters");
}
```

수정 방법:

1. `NormalizeRelativePath`를 호출하기 전에 위의 8가지 유형 문자를 필터링하거나 대체합니다. 기존 판단 로직을 재사용할 수 있습니다:

```csharp
// 호출자가 먼저 자체 검사하여 IOException을 직접 트리거하지 않도록 함
foreach (var ch in relative)
{
    if (!PathUtil.IsValidCharacter(ch))
    {
        // 오류 보고 또는 대체
        throw new ArgumentException($"불법 문자: {ch}");
    }
}
```

2. Windows 스타일 드라이브 문자(`C:`, 콜론)는 불법 문자로 간주됩니다. 경로가 사용자 입력이나 외부 리소스 이름에서 올 경우, 먼저 화이트리스트 검증을 수행하는 것을 권장합니다.
3. 파일 와일드카드 시나리오인 경우, `PathUtil.WildcardToRegex`(`Runtime/PathUtil.cs#L183-L186` 참조)를 사용하십시오. 이 함수는 `*`와 `?`만 메타 문자로 허용하며, 나머지 불법 문자는 `Regex.Escape`로 이스케이프되어 여기서 IOException이 다시 발생하지 않습니다.

## 검증

수정 후 `NormalizeRelativePath`가 정상적으로 반환되는지 확인합니다:

```csharp
// 유효한 경로: 정규화된 결과 반환, 예외가 발생하지 않아야 함
var ok = PathUtil.NormalizeRelativePath("a/b/../c");   // -> "/a/c"
var ok2 = PathUtil.NormalizeRelativePath("\"a/b\"");   // 따옴표 자동 제거 -> "/a/b"

// 여전히 불법인 반례, 예외 경로가 여전히捕获되는지 확인하는 데 사용
try
{
    PathUtil.NormalizeRelativePath("../a");
    PathUtil.NormalizeRelativePath("a:b");
}
catch (System.IO.IOException ex)
{
    Debug.LogWarning(ex.Message); // double dot / Invalid characters가 표시되어야 함
}
```

두 예외가 더 이상 발생하지 않으면 문제가 해결된 것입니다.

## 배경 (선택 사항)

`NormalizeRelativePath`는 내부적으로 경로를 `/`로 시작하는 상대 가상 루트로 취급하여 문자 단위로 스캔하고 `PrevSlash / PrevDot / PrevDoubleDot / NothingSpecial` 네 가지 상태를 유지합니다(`Runtime/PathUtil.cs#L11-L17`). `..`은 이미 기록된 세그먼트를 되돌리는 방식으로 구현되며, 루트 슬래시만 남을 때까지 되돌리면 범위를 벗어난 것으로 간주됩니다. 불법 문자는 문자 기록 전(`Append`)에 화이트리스트 검증을 수행하며, 이것이 두 예외가 발생하는 시점입니다.
