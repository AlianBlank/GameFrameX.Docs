# 如何查詢購買紀錄與消耗購買

透過 `PaymentComponent` 呼叫 `QueryPurchases(PaymentProductType productType)` 拉取當前帳號未消耗的購買紀錄，結果透過 `OnQueryPurchasesResult` 事件回呼回傳；拿到 `PurchaseToken` 後呼叫 `ConsumePurchase(string purchaseToken)` 完成消耗，結果透過 `OnConsumePurchaseResult` 事件回呼回傳。兩者均為非同步、無回傳值，只能透過事件取得結果。

## 前置條件

- 場景中已加入 `GameFrameX/Payment` 元件（`PaymentComponent`），並按平台自動裝配了對應的 `IPaymentManager` 實作。
- 已呼叫 `Init(bool isDebug = false, bool isClientVerify = true)` 完成初始化，且 `IsReady()` 回傳 `true` 後再發起查詢。

## API 一覽

| 名稱 | 簽章 | 說明 |
|------|------|------|
| 查詢購買紀錄 | `void QueryPurchases(PaymentProductType productType)` | 按產品類型查詢未消耗的購買紀錄 |
| 消耗購買 | `void ConsumePurchase(string purchaseToken)` | 用購買權杖消耗一筆購買 |
| 查詢結果事件 | `event EventHandler<PaymentEventArgs> OnQueryPurchasesResult` | 查詢完成（含失敗）時觸發 |
| 消耗結果事件 | `event EventHandler<PaymentEventArgs> OnConsumePurchaseResult` | 消耗完成（含失敗）時觸發 |
| 是否就緒 | `bool IsReady()` | 支付系統是否已初始化完成 |

以上簽章定義於 `IPaymentManager`：

```csharp
/// <summary>

event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

/// <summary>

/// </summary>

/// <param name="purchaseToken">購買權杖</param>
[UnityEngine.Scripting.Preserve]

```

## 操作步驟

1. 訂閱查詢與消耗兩個結果事件。`PaymentComponent` 上的事件會直接轉發給內部 `IPaymentManager`：

```csharp
public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult
{
    add { _paymentManager.OnQueryPurchasesResult += value; }
    remove { _paymentManager.OnQueryPurchasesResult -= value; }
}

public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult
{
    add { _paymentManager.OnConsumePurchaseResult += value; }
    remove { _paymentManager.OnConsumePurchaseResult -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L48-L64)

2. 初始化並確認就緒後，按產品類型發起查詢：

```csharp
paymentComponent.Init(isDebug: false, isClientVerify: true);

if (paymentComponent.IsReady())
{
    // 按產品類型（內購 / 訂閱）查詢當前帳號未消耗的購買紀錄
    paymentComponent.QueryPurchases(productType);
}
```

3. 在 `OnQueryPurchasesResult` 回呼中讀取結果。成功時每條紀錄的權杖在 `PaymentEventArgs.PurchaseToken` 中：

```csharp
private void OnQueryPurchasesResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"查詢購買紀錄失敗: {e.ResultCode} {e.ErrorMessage}");
        return;
    }

    // 原始購買資料（JSON 格式），可交給伺服器驗證
    // e.PurchaseData / e.ProductId / e.OrderId / e.PurchaseToken / e.CustomData
}
```

`PaymentEventArgs` 的完整欄位：

```csharp
public sealed class PaymentEventArgs : EventArgs
{
    public string ProductId { get; set; }      // 產品ID
    public string OrderId { get; set; }        // 訂單ID
    public string PurchaseToken { get; set; }  // 購買權杖
    public PaymentResultCode ResultCode { get; set; } // 支付結果代碼
    public string ErrorMessage { get; set; }   // 錯誤訊息
    public string PurchaseData { get; set; }   // 原始購買資料（JSON格式）
    public string CustomData { get; set; }     // 自訂資料
}
```

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

4. （伺服器驗證通過後）用查詢到的權杖消耗購買，並在 `OnConsumePurchaseResult` 中確認結果：

```csharp
paymentComponent.ConsumePurchase(e.PurchaseToken);

private void OnConsumePurchaseResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"消耗購買失敗: {e.ResultCode} {e.ErrorMessage}");
        return;
    }
    // 已消耗，可發放/補發道具
}
```

## 常見變體

- **斷線重連/補單**：在啟動或回到前景時先 `QueryPurchases` 遍歷 `OnQueryPurchasesResult` 回傳的未消耗紀錄，驗證通過後逐條 `ConsumePurchase`，即可完成掉單補發。
- **訂閱商品**：訂閱類購買同樣透過 `QueryPurchases` 查詢，但通常不做 `ConsumePurchase` 消耗（消耗語意針對一次性消耗型商品），是否消耗以通路實作為準。
- **伺服器驗證**：若 `Init` 時 `isClientVerify` 設為 `false`，請把回呼中的 `PurchaseData` 與 `PurchaseToken` 發給自有伺服器驗證後再消耗。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 呼叫後無任何回呼 | 未訂閱 `OnQueryPurchasesResult` / `OnConsumePurchaseResult` 就發起呼叫 | 先訂閱事件再呼叫查詢/消耗 |
| 日誌出現 `Pay Manager is invalid.` | 平台對應的 `IPaymentManager` 實作類別未找到或未裝配 | 檢查 `PaymentComponent` 上各平台實作類別名稱與對應通路包是否引入 |
| 查詢/消耗回呼 `ResultCode` 為 `Failed` 或 `NetworkError` | 通路服務未連線或網路異常 | 稍後重試；`NetworkError` 需恢復網路後重新查詢 |
| 消耗失敗 `ItemNotOwned` | 權杖對應的購買已被消耗或不存在 | 重新 `QueryPurchases` 拿最新權杖，不要重複使用舊值 |
| `VerifyFailed` | 購買驗證未通過（用戶端或伺服器驗證失敗） | 檢查驗證邏輯與憑證，驗證通過後再消耗 |

`PaymentResultCode` 全部取值：`Success`、`Failed`、`Cancelled`、`NetworkError`、`ServiceUnavailable`、`ItemAlreadyOwned`、`ItemNotOwned`、`VerifyFailed`、`Unknown`。

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L14-L25)

## 驗證

- `QueryPurchases` 觸發一次 `OnQueryPurchasesResult`，且 `ResultCode == PaymentResultCode.Success`。
- `ConsumePurchase(token)` 觸發一次 `OnConsumePurchaseResult`，且 `ResultCode == PaymentResultCode.Success`。
- 再次查詢同一產品類型，不再回傳已消耗的那筆紀錄。

## 背景

`PaymentComponent` 在 `Awake` 中按編譯平台選擇實作類別（Android 用 `GooglePaymentManager`，iOS/Mac 用 `ApplePaymentManager`，WebGL/PC 各有對應實作，其餘平台落到 `DefaultPaymentManager`），再透過 `GameFrameworkEntry.GetModule<IPaymentManager>()` 取得實例；事件與方法都是對該實例的直接轉發。`BasePaymentManager` 中的 `RaiseQueryPurchasesResult` / `RaiseConsumePurchaseResult` 負責把各通路實作的結果分發到上述事件。關於支付系統整體結構，見概述頁。
