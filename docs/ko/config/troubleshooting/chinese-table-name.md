# 테이블 이름에 중국어가 포함되어 오류가 발생하면 어떻게 하나요

`gen-*.bat` 또는 `gen-*.sh` 생성 스크립트를 실행할 때 *"중국어 테이블 이름은 지원하지 않습니다"*, *"invalid table name"* 같은 오류가 표시되거나 생성된 클래스 이름이 깨진 문자로 변하는 오류가 발생한다면, 거의 대부분 Excel 파일 이름의 「영문 이름」 부분에 중국어를 작성했기 때문입니다. 이 페이지에서는 빠른 진단과 수정 방법을 안내합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `不支持中文表名` 또는 `invalid table name` 오류 발생 | 파일 이름의 「영문 이름」 부분에 중국어가 작성됨(예: `D-道具-道具表.xlsx`) | 두 번째 부분을 순수 영문으로 바꾸고, 중국어는 세 번째 부분에 작성 |
| 생성된 코드의 클래스 이름이 `Tb道具` 또는 깨진 문자로 변함 | 위와 동일, 영문 이름 부분이 중국어임 | 순수 영문 이름 사용(예: `ItemConfig`) |
| 같은 이름의 여러 파일 중 하나만 병합 결과가 생성되고 한 테이블이 누락됨 | 영문 이름 부분에 중국어를 작성해 도구가 서로 다른 영문 이름으로 인식하여 당연히 병합하지 않음 | 영문 이름 부분을 완전히 동일하게 유지(순수 영문) |
| 파일 이름에 공백, `/`, `\`, `#` 등의 문자 포함 | 명명 규칙은 `字母-英文名-(分组)-中文名` 형식만 허용함 | 특수 문자를 제거하고 영문자, 숫자, `-`만 사용 |
| 테이블 헤더 필드 이름(`##var` 행)에 중국어 작성 | 필드 이름도 영문이어야 하며, 도구가 이를 사용해 C# 필드 이름을 생성함 | `##var` 행을 영문으로 변경(예: `id`, `name`) |

## 수정 단계

### 1. 파일 이름 규칙 확인

파일 이름은 반드시 `字母-英文名-中文名.xlsx` 형식의 3단 구조여야 하며, 각 부분은 반각 하이픈 `-`으로 구분합니다:

```
D-ItemConfig-道具表.xlsx
│  │          │
│  │          └─ 세 번째 부분: 중국어 이름(자유롭게 작성, 사람이 보기 위한 것)
│  └──────────── 두 번째 부분: 영문 이름(순수 영문, 클래스 이름 TbItemConfig이 됨)
└─────────────── 첫 번째 부분: 단일 영문자(정렬용)
```

한쪽에만 생성되도록 제한하고 싶다면, 영문 이름과 중국어 이름 사이에 `c` 또는 `s` 그룹 표시를 추가합니다:

```
D-ItemConfig-c-道具表.xlsx   ← 클라이언트 전용
D-ItemConfig-s-道具表.xlsx   ← 서버 전용
```

### 2. 영문 이름 부분을 순수 영문으로 변경

**잘못된 예**(영문 이름이 중국어 `道具`):

```
D-道具-道具表.xlsx
```

**올바른 예**(영문 이름은 `ItemConfig`, 중국어 이름은 `道具表`):

```
D-ItemConfig-道具表.xlsx
```

수정한 후 생성되는 C# 클래스 이름은 `TbItemConfig`가 되며, 코드에서 다음과 같이 사용할 수 있습니다:

```csharp
// 클라이언트(Unity)
var item = tables.TbItemConfig.Get(10001);
Debug.Log(item.Name);

// 서버(.NET)
var item = tables.TbItemConfig.Get(10001);
Console.WriteLine(item.Name);
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L163-L200)

### 3. 여러 파일로 분할할 때, 영문 이름은 완전히 동일해야 함

한 테이블의 데이터가 너무 많으면 여러 파일로 나누어 관리합니다. **영문 이름 부분이 완전히 동일하기만 하면** 도구가 자동으로 병합합니다. 중국어 이름 부분은 자유롭게 작성해도 되며, 도구가 이를 해석하지 않습니다:

```
D-ItemConfig-道具表-1-1000.xlsx      ┐
D-ItemConfig-道具表-1001-2000.xlsx    ├→ 하나의 TbItemConfig로 병합
D-ItemConfig-道具表-2001-3000.xlsx    ┘
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L234-L256)

### 4. 테이블 헤더 필드 이름도 함께 확인

파일 이름뿐만 아니라 테이블의 첫 번째 행 `##var`의 필드 이름도 반드시 영문이어야 합니다. 도구가 이를 사용해 C#의 속성 이름을 생성하기 때문입니다:

| ##var | id | name | price |
|-------|----|------|-------|
| ##type | int | text | int |
| ##group | | | |
| ## | 아이템ID | 아이템명 | 가격 |

필드 이름은 `id`, `name`, `price`(영문)로 작성하고, 설명은 네 번째 행 `##` 뒤에 작성합니다.

## 검증

수정한 후 아래 순서대로 검증합니다:

1. **파일 이름 확인**: 파일 탐색기에서 파일 이름이 3단 구조인지, 영문 이름 부분에 영문자와 숫자만 있고 중국어, 공백, 특수 문자가 없는지 확인합니다.
2. **생성 스크립트 실행**: `gen-client-json.bat`(클라이언트) 또는 `gen-server-json.bat`(서버)를 다시 더블 클릭합니다.
3. **생성된 코드 확인**: `../Unity/Assets/Hotfix/Config/Generate` 또는 `../Server/GameFrameX.Config/Config`를 열어 `TbItemConfig.cs`와 같은 파일을 찾고, 클래스 이름이 영문인지 확인합니다.
4. **코드에서 호출**: `tables.Tb你的英文名.Get(id)`로 시도해 보아 더 이상 오류가 발생하지 않으면 OK입니다.

## 배경(선택 사항)

파일 이름 규칙은 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L163-L200)에 정리되어 있습니다: 영문 이름 부분은 C#의 클래스 이름(`Tb英文名`)이 되는데, C# 식별자는 영문자, 숫자, 밑줄로만 구성할 수 있으므로 도구는 영문 이름 부분에 중국어가 들어가는 것을 허용하지 않습니다. 중국어 이름 부분은 파일 이름 정렬과 표시에만 사용되며 도구가 이를 해석하지 않으므로, 중국어, 분류, 번호는 어떻게 작성해도 됩니다.
