# JSON 解析結果不正確時該怎麼辦

當 `WebManager` 回傳的 JSON 字串經 `ToHttpJsonResultData<T>()` 解析後出現 `IsSuccess == false`、`Data == null`、`Code` 始終為 0 或欄位遺失的情況時，通常是由於回應結構未遵循 `{"code":0,"message":"...","data":"..."}` 規範、`data` 為巢狀物件、`T` 型別缺少無參數建構函式或欄位名稱不一致所導致。逐項查看下方診斷表即可找出原因。

## 快速診斷

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `IsSuccess == false` 且 `Code` 為非 0 值 | 伺服器回傳的業務錯誤代碼，`data` 不會被解析(原始碼在 `Code != 0` 時會直接回傳失敗結果) | 開啟日誌查看 `message` 並以業務錯誤處理；參考下方「Code 非 0 的情況」 |
| `IsSuccess == false`、`Code == 0`、`Data == null` | 解析過程中發生的例外被 `catch` 吞掉，僅輸出 `Log.Error(e)` 並回傳預設失敗結果 | 在 Console 查看 `Log.Error` 輸出的例外堆疊追蹤；檢查 JSON 結構與 `T` 是否相符 |
| `Data` 為 `new T()` 全預設值實例 | 伺服器回傳的 `data` 為空字串，而原始碼在 `data` 為空時直接回傳 `new T()` | 確認介面是否確實回傳空的 `data`;若與預期不符，請檢查回應原文 |
| `Data` 的欄位皆為預設值但無錯誤 | `data` 為物件但以 `string` 處理失敗，或 `T` 的屬性名與 JSON 欄位名不一致 | 在 `T` 的屬性加上 `[JsonProperty("欄位名")]`,參考下方修復步驟 |
| 日誌中完全看不到回應原文 | 未定義巨集 `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` | 在 Player Settings / 腳本巨集加入 `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 後重新編譯 |
| 反序列化時立即拋出 `JsonMapper` 例外 | `T` 在 `class, new()` 約束情境下存在無法滿足的欄位型別錯誤(例如日期格式、巢狀字典) | 將 `T` 簡化為最小重現模型，逐一新增欄位進行檢查 |

## 修復步驟

### 1. 先開啟回應日誌以取得原始 JSON

`WebManager` 收到回應時會將原始內容輸出至日誌，但需要巨集開關：

- 請求日誌： `ENABLE_GAMEFRAMEX_WEB_SEND_LOG`
- 回應日誌： `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`

原始碼中的回應日誌實作(`unityWebRequest.downloadHandler.text` 為原始回應內容)：

```csharp
#if ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
                    Log.Debug($"Web Response: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)} \n Content: {unityWebRequest.downloadHandler.text}");
#endif
```

來源： [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L248-L250)

取得原始 JSON 後與統一的回應結構進行比較，僅此一步即可解決大多數「解析不正確」的問題。

### 2. 確認回應是否遵循統一結構 `{"code", "message", "data"}`

解析器高度依賴這三個欄位名，並透過 `JsonProperty` 進行綁定：

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class HttpJsonResult
{
    /// <summary>
    /// 回應代碼,0 為成功
    /// </summary>
    [JsonProperty("code")]
    public int Code { get; set; }

    /// <summary>
    /// 回應訊息
    /// </summary>
    [JsonProperty("message")]
    public string Message { get; set; }

    /// <summary>
    /// 回應資料。
    /// </summary>
    [JsonProperty("data")]
    public string Data { get; set; }
}
```

來源： [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L8-L27)

檢查重點：

| 檢查項目 | 預期 | 不一致時的症狀 |
|--------|------|--------------|
| 欄位名 | 必須為 `code` / `message` / `data` | 欄位遺失或始終為預設值 |
| `code` | 0 表示成功 | 非 0 時 `IsSuccess` 始終為 `false` |
| `data` | 必須為字串(巢狀 JSON 的字串形式) | 若為直接的物件字面值,`Data` 解析可能出現異常 |

若伺服器回傳的最上層欄位名不同(例如 `status`/`msg`/`result`),應先請伺服器依此規範回傳，或自行以自訂結構進行反序列化，無法直接使用 `ToHttpJsonResultData<T>()`。

### 3. 確保 `T` 滿足約束條件並正確映射欄位

`ToHttpJsonResultData<T>` 的擴充方法簽名與內部解析邏輯：

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // 將 JSON 字串反序列化為 HttpJsonResult 物件
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // 檢查回應代碼是否表示成功
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // 回傳預設失敗結果
        }

        resultData.IsSuccess = true; // 設定成功旗標
        // 反序列化資料部分,若資料為空則回傳 T 型別的預設實例
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // 捕獲並輸出例外
        Log.Error(e);
    }

    return resultData; // 回傳結果資料
}
```

來源： [HttpJsonResultHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultHelper.cs#L20-L48)

`T` 檢查清單：

1. `T` 必須是 `class` 且須具有無參數建構函式(`where T : class, new()`)。結構、抽象類別皆不可使用。
2. `T` 的屬性名必須與 `data` 內的 JSON 欄位名一致，不一致時請加上 `[JsonProperty("欄位名")]`(LitJSON 提供的 `GameFrameX.LitJSON.Runtime.JsonProperty`)。
3. 若 `data` 為空字串會回傳 `new T()`,請勿將「全為預設值」誤判為解析失敗。這實際上是原始碼的預期行為。
4. 解析例外被 `catch` 後僅輸出 `Log.Error(e)`,且 `IsSuccess` 保持 `false`、`Code` 保持 0。若看到此組合，請優先查看 Console 中的例外日誌。

### 4. `Code` 非 0 時以業務錯誤處理

`HttpJsonResultData<T>` 回傳給呼叫者的欄位意義：

| 欄位 | 型別 | 說明 |
|------|------|------|
| `IsSuccess` | `bool` | 是否成功，預設值 `false` |
| `Code` | `int` | 回應代碼，0 為成功，非 0 則為伺服器的業務錯誤代碼 |
| `Data` | `T` | 成功時為反序列化後的資料；失敗時為預設值或 `null` |

來源： [HttpJsonResultData.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultData.cs#L8-L28)

`Code` 非 0 表示伺服器回傳的業務錯誤，`Data` 不會被解析。應根據 `Code` 與 `message`(可從原始回應日誌中查看)顯示提示或進行重試。

## 驗證

1. 定義 `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 巨集後重新發送請求，確認日誌中的回應原文是否遵循 `{"code":0,"message":"...","data":"..."}` 結構。
2. 對回應原文呼叫 `.ToHttpJsonResultData<T>()` 並確認(斷言)`IsSuccess == true`。
3. 確認 `Data` 的屬性值與 `data` 欄位內容逐欄位一致(包含巢狀物件)。
4. 同時開啟請求/回應巨集時，`WebManager` 會輸出完整的請求標頭與表單，可進一步排除「因請求參數錯誤導致伺服器回傳錯誤結構」的可能性。
