# What to Do When Client/Server Data Isn't Separated

If you run into a situation like this: a table meant only for the client also gets generated on the server; or a table meant only for the server ends up on the client as well; or you changed the filename prefix but the code/data on both sides still isn't separated — these are all typical symptoms of "client/server data grouping not taking effect". This page helps you quickly locate and fix the issue.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| The server generated a table meant only for the client (or vice versa) | The Excel filename has no group marker, so both groups are generated by default | Add a `-c-` (client only) or `-s-` (server only) group segment to the filename |
| A group marker was added, but the table is still generated for both sides | In `luban.conf`, the `groups` config marks both `c` and `s` as `default: true`, and no group was parsed from the filename | The filename segments must be `<字母>-<英文名>-<分组>-<中文名>.xlsx`, and the group can only be `c` or `s` |
| After changing the group, the old generated code is still there | Only the filename was changed; the generation scripts weren't re-run | Re-run the `gen-client-*` and `gen-server-*` scripts |
| Both client/server run fine, but fields meant for only one side also appear on the other | Fields aren't grouped per side (not marked in Excel), and the tool outputs to all sides by default | Add per-side grouping to the fields in `__tables__.xlsx` or the corresponding Bean |

## Fix Steps

### 1. Add a group marker to the filename

Filename format: `字母-英文名-分组-中文名.xlsx`. The group segment can only be `c` (client only) or `s` (server only); omitting the group means both sides are included.

| Filename | Effect |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | Used by both client and server (default) |
| `D-ItemConfig-c-道具表.xlsx` | Client only |
| `D-ItemConfig-s-道具表.xlsx` | Server only |

Example file paths: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

> `c` = client, `s` = server. Do not use Chinese group names or two-letter combinations like `cs`/`sc`; the tool only recognizes `c` and `s`.

### 2. Check the groups configuration in luban.conf

The `groups` node in `luban.conf` defines two groups, `c` and `s`, both set to `default: true`, so files **without a group marker** are generated for both sides:

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

In the `targets` node, `server` takes only the `s` group, `client` takes only the `c` group, and `all` takes the union of both groups:

```json
"targets": [
    { "name": "server", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "groups": ["c","s"], "topModule": "cfg" }
]
```

See [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L61) for the complete configuration.

This means: **filename-based grouping alone is not enough — you must also run the corresponding generation scripts separately** for the output to actually land on each side.

### 3. Run the generation scripts separately

- Client: double-click `gen-client-json.bat` (Mac/Linux: `sh gen-client-json.sh`)
- Server: double-click `gen-server-json.bat` (Mac/Linux: `sh gen-server-json.sh`)

See [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L265-L285) for script details.

### 4. Field-level per-side grouping (advanced)

If certain fields in the same table are meant for only one side (e.g., prices only on the server, UI hints only on the client), you need to add a `c` or `s` per-side group marker to those fields in `__tables__.xlsx` / `__beans__.xlsx`. Plain `int` and `string` fields exist on both sides by default, and the tool trims them automatically according to the configuration.

## Verification

After completing steps 1-3 above, confirm that grouping is in effect as follows:

1. Check the output directories:
   - Client code/data: `Unity/Assets/Bundles/Config` (data), `Unity/Assets/Hotfix/Config/Generate` (code)
   - Server code/data: `Server/GameFrameX.Config/Json` (data), `Server/GameFrameX.Config/Config` (code)
2. **Search for the table name** (e.g., `TbItemConfig`) in the directory of the side where it should not appear; if nothing is found, grouping is in effect.
3. Access in code: the client uses `tables.TbXxx.Get(id)`; the server calls it the same way but with a different code namespace (`Hotfix.Config` vs `GameFrameX.Config`) — differing namespaces indicate correct grouping.
