# 非同步圖片載入例外處理方法

呼叫 `UIImage.icon` 或 `Image.SetIconAsync(...)` 後圖片未顯示、主控台出現 `Failed to load icon '<path>': ...` 錯誤，或圖片在編輯器中正常運作但打包後消失時，請依照本頁步驟解決問題。

## 快速診斷

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 主控台輸出 `Failed to load icon 'xxx': ...` | `AssetComponent.LoadAssetAsync` 擲出例外或資源不存在 | 參考「資源路徑錯誤」 |
| 指派 `icon` 後圖片仍為空白 | 資產未包含在 YooAsset 打包清單中 | 參考「資源未包含在 YooAsset 清單中」 |
| 編輯器正常，執行後圖片遺失 | 執行階段使用了編輯器專用資源(例如:`AssetDatabase`) | 參考「編輯器 / 執行階段資源分離」 |
| 圖示有顯示但出現拉伸/裁切 | `SetIconAsync` 以 `Rect(0,0,w,h)` 重新建立 Sprite,忽略了原始邊框 | 參考「Sprite 邊框與 9-slice 遺失」 |
| 切換 `icon` 後先前的紋理殘留在記憶體中 | `SetIconAsync` 中的 `using` 雖已釋放控制代碼，但未明確銷毀先前的 Sprite | 參考「記憶體洩漏與控制代碼釋放」 |

## 解決步驟

### 資源路徑錯誤

`SetIconAsync` 內部使用 `AssetComponent.LoadAssetAsync<Texture2D>(icon)`,路徑必須與 YooAsset 清單中的 `Location` 完全一致(區分大小寫、不含副檔名)。

```csharp
[UnityEngine.Scriptive.Preserve]
public static async Task SetIconAsync(this UnityEngine.UI.Image self, string icon)
{
    try
    {
        var assetComponent = GameEntry.GetComponent<AssetComponent>();
        using (var valueHandle = await assetComponent.LoadAssetAsync<Texture2D>(icon))
        {
            if (valueHandle.IsDone && valueHandle.Status == EOperationStatus.Succeed)
            {
                var texture2D = valueHandle.GetAssetObject<Texture2D>();
                self.sprite = Sprite.Create(texture2D, new Rect(0, 0, texture2D.width, texture2D.height), new Vector2(0.5f, 0.5f));
            }
        }
    }
    catch (System.Exception e)
    {
        Log.Error($"Failed to load icon '{icon}': {e.Message}");
    }
}
```

來源:[UGUIImageExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIImageExtension.cs#L56-L74)

修正操作：

1. 在 YooAsset 資源管理視窗(例如:`Asset Bundle Collector`)中搜尋該 `icon` 字串，確認其是否以 `Texture2D` 類型的 Location 存在。
2. 移除副檔名(例如:寫成 `Assets/UI/Icons/coin` 而非帶有 `.png`)。
3. 將相同字串傳遞給 `AssetComponent.LoadAssetAsync<Texture2D>` 進行直接偵錯，確認例外是否仍會發生。

### 資源未包含在 YooAsset 清單中

`UIImage.icon` 的 setter 透過 `SetIconAsync` 執行執行階段的資源載入：

```csharp
[UnityEngine.Scripting.Preserve]
public string icon
{
    get { return m_icon; }
    set
    {
        if (m_icon != value)
        {
            m_icon = value;
            _ = this.SetIconAsync(m_icon);
        }
    }
}
```

來源:[UIImage.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIImage.cs#L60-L71)

修正操作：

1. 開啟 YooAsset 收集器，確認存放圖示的目錄是否已納入某個收集規則。
2. 重新建置資源套件並熱更新至目標平台後啟動遊戲。

### 編輯器 / 執行階段資源分離

`UIImage` 是繼承自 `UnityEngine.UI.Image` 的腳本元件，僅會在編輯器中透過選單進行替換：

```csharp
[CustomEditor(typeof(UnityEngine.UI.Image))]
public class UIImageReplaceHandler : UnityEditor.Editor
{
    [MenuItem("CONTEXT/Image/Replace To UIImage(替换为UIImage)", false, 10)]
    static void Run()
    {
        ...
    }
}
```

來源:[UIImageReplaceHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UIImageReplaceHandler.cs#L39-L76)

若在執行階段直接以 `Resources.Load` 取用編輯器路徑將會失敗。修正操作：請確保所有圖示皆由 YooAsset 的執行階段清單提供，勿混用 `Resources/` 或編輯器內建資產。

### Sprite 邊框與 9-slice 遺失

`SetIconAsync` 使用 `Sprite.Create(texture2D, new Rect(0,0,w,h), ...)` 直接建立 Sprite,不會讀取原始 Sprite 的 `border`。修正操作：若原始圖片為 9-slice,請使用 `AssetBundle` 中 `Sprite` 類型的 Prefab,避免透過 `icon` 字串在執行階段動態生成。

### 記憶體洩漏與控制代碼釋放

`SetIconAsync` 內部已使用 `using (var valueHandle = ...)`,控制代碼會自動歸還，但多次切換 `icon` 時，先前的 `Sprite` 可能仍連結至新的 `Texture2D` 而殘留參考。修正操作：在切換前手動設定 `self.sprite = null`,讓先前的 Sprite 在未被參考的狀態下與 `Texture2D` 一併被 GC 回收。

## 驗證

1. 重新指派 `UIImage.icon`,確認主控台不再輸出 `Failed to load icon`。
2. 在 YooAsset 資源瀏覽器中將相同的 `Location` 拖曳至 `UIImage.icon`,確認 `Sprite Renderer` 面板有顯示圖片。
3. 在 Profiler → Memory → Texture 中，確認切換後先前紋理的參考計數是否歸零。
4. 打包至目標平台後，在實機上重新執行相同流程。

## 背景(選用)

`UIImage` 僅在 `UnityEngine.UI.Image` 上新增 `icon` 屬性，實際的載入邏輯皆透過 `UGUIImageExtension.SetIconAsync` 呼叫 `GameEntry.GetComponent<AssetComponent>()` 使用 YooAsset 的非同步介面。失敗時不會擲出例外，僅記錄日誌。
