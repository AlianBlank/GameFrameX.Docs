# 如何解析 JSON 响应

在 GameFrameX.Web 中，解析 JSON 响应的核心是对响应字符串调用扩展方法 `ToHttpJsonResultData<T>()`：它把服务端统一结构（`code`/`message`/`data`）反序列化为 `HttpJsonResultData<T>`，并自动根据 `code` 设置 `IsSuccess`。框架底层使用 LitJSON（`GameFrameX.LitJSON.Runtime.JsonMapper`）完成反序列化。

## 前置条件

- 项目已引入 `GameFrameX.Web` 与 `GameFrameX.LitJSON` 运行时模块。
- 服务端返回统一 JSON 结构，字段为小写的 `code`、`message`、`data`：

```json
{
  "code": 0,
  "message": "ok",
  "data": "{\"id\":1,\"name\":\"Player\"}"
}
```

其中 `code == 0` 表示成功，`data` 是一段嵌套的 JSON 字符串（会被二次反序列化为 `T`）。

## 操作步骤

1. 定义业务数据模型 `T`：必须是 `class` 且含无参构造函数（扩展方法签名约束为 `where T : class, new()`）。字段名与 JSON 不一致时用 `[JsonProperty("...")]` 标注。

```csharp
using GameFrameX.LitJSON.Runtime;

public sealed class PlayerInfo
{
    [JsonProperty("id")]
    public int Id { get; set; }

    [JsonProperty("name")]
    public string Name { get; set; }
}
```

2. 拿到响应字符串后，调用扩展方法得到结果对象：

```csharp
using GameFrameX.Web.Runtime;

HttpJsonResultData<PlayerInfo> result = responseText.ToHttpJsonResultData<PlayerInfo>();
```

3. 按 `IsSuccess` / `Code` 处理结果：

```csharp
if (result.IsSuccess)
{
    PlayerInfo player = result.Data;
    Debug.Log($"玩家：{player.Id} {player.Name}");
}
else
{
    // Code 非 0 时为服务端错误码；Code 为 0 且 IsSuccess 为 false 说明反序列化抛了异常
    Log.Error($"请求失败，Code={result.Code}");
}
```

`ToHttpJsonResultData<T>` 的完整逻辑（先解析外壳、再二次解析 `data`）如下：

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // 反序列化JSON字符串为HttpJsonResult对象
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // 检查响应码是否表示成功
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // 返回默认的失败结果
        }

        resultData.IsSuccess = true; // 设置成功标志
        // 反序列化数据部分，如果数据为空则返回类型T的默认实例
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // 捕获并输出异常信息
        Log.Error(e);
    }

    return resultData; // 返回结果数据
}
```

## 常见变体

- **只关心外壳结构、不需要强类型 Data**：直接用 `JsonMapper.ToObject<HttpJsonResult>(json)` 获取 `Code` / `Message` / `Data` 三个字段（`Data` 此时是原始字符串）。

```csharp
var shell = JsonMapper.ToObject<HttpJsonResult>(responseText);
Debug.Log($"code={shell.Code}, message={shell.Message}");
```

Source: [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L9-L33)

- **请求阶段获取字符串响应**：`WebManager` 内部通过 `WebJsonData`（私有请求描述类）挂接 `TaskCompletionSource<WebStringResult>` / `TaskCompletionSource<WebBufferResult>`，分别对应字符串结果与字节数组结果；字符串结果即可直接喂给 `ToHttpJsonResultData<T>`。关于如何发起 Web 请求，见《如何发起 HTTP 请求》。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `IsSuccess == false` 且 `Code != 0` | 服务端返回非 0 响应码，`Data` 保持 `null` | 按 `Code` 处理业务错误；`Code` 的取值含义由服务端约定 |
| `IsSuccess == false` 且 `Code == 0` | 反序列化抛异常，被 `catch (Exception e)` 吞掉并 `Log.Error(e)` | 查看控制台错误日志；检查 JSON 格式与字段名映射 |
| 抛编译错误：缺少 `new()` 约束 | `T` 是结构体或没有无参构造函数 | 把模型改为含无参构造的 `class` |
| `Data` 里的字段全是默认值 | 字段名与 JSON 键不一致且未标注 `[JsonProperty]` | 用 `[JsonProperty("原始键名")]` 显式映射 |
| `Data` 是全默认实例但 `IsSuccess == true` | 服务端返回的 `data` 为空字符串，此时返回 `new T()` | 服务端确保成功时携带有效 `data`，或前端按需判空 |
| 解析不到任何字段 | 外壳字段名不是小写 `code`/`message`/`data` | 与服务端约定统一外壳结构，见 [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L14-L27) |

## 验证

- 构造 `{"code":0,"message":"ok","data":"{\"id\":1,\"name\":\"a\"}"}` 字符串调用 `ToHttpJsonResultData<PlayerInfo>()`，应得到 `IsSuccess == true` 且 `Data.Id == 1`。
- 把 `code` 改为非 0（如 `1001`），应得到 `IsSuccess == false`、`Code == 1001`、`Data == null`。
- 把字符串改为非法 JSON，应得到 `IsSuccess == false`、`Code == 0`，并在日志中看到异常输出。

## 背景

`HttpJsonResultData<T>` 只是对「统一外壳 + 业务数据」的薄封装：`IsSuccess`（默认 `false`）、`Code`（int，0 为成功）、`Data`（`T`，失败时为 `null`）。扩展方法内部先反序列化为 `HttpJsonResult` 检查 `code`，成功后对 `data` 做二次反序列化，全程异常被捕获、不向外抛出，因此调用方只需关心 `IsSuccess` 与 `Code` 两个标志位。
