# How to Integrate the Project via FsmComponent

`FsmComponent` is the unified entry component for the Finite State Machine (FSM) under the GameFrameX framework. It inherits from `GameFrameworkComponent`. Once attached to a scene, it obtains the underlying FSM manager through `GameFrameworkEntry.GetModule<IFsmManager>()`, and is responsible for creating, querying, and destroying all FSMs as well as driving the `FixedUpdate` polling.

## Prerequisites

- The `com.gameframex.unity.fsm` package has been installed (referenced via `manifest.json`).
- The GameFrameX framework entry exists in the scene (provided by `com.gameframex.unity.runtime`); `FsmComponent` relies on it to resolve `IFsmManager`.
- State definitions inherit from `FsmState<T>`, and the owner type `T` must be a reference type (`class`).

## Steps

1. **Add the FSM component to the scene entry GameObject.** On the same GameObject where the GameFrameX framework entry component (e.g., `GameEntry`) is attached, click `Add Component`, search for `GameFrameX/FSM`, and add it. The component class is annotated with `[AddComponentMenu("GameFrameX/FSM")]`, so the menu item can be located directly.

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/FSM")]
   [GameFrameXAutoComponent(-6000)]
   public sealed class FsmComponent : GameFrameworkComponent
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L43-L47)

2. **Obtain the component instance.** At runtime, get a reference through `GameEntry.GetComponent<FsmComponent>()`; if the `com.gameframex.unity.entry` shortcut package is also included, you can directly use `GameApp.Fsm`.

   ```csharp
   // Standard way
   FsmComponent fsmComponent = GameEntry.GetComponent<FsmComponent>();

   // Shortcut way (depends on com.gameframex.unity.entry)
   IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L47)

3. **Define state classes.** Inherit from `FsmState<T>`, write the state logic in virtual methods; trigger transitions through `ChangeState<TState>(fsm)`.

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnEnter(IFsm<Player> fsm) { }

       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }

       protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
   }
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L101-L123)

4. **Create and start the FSM.** Call `CreateFsm<T>` passing the owner and the collection of states, then call `Start<TState>()` to launch. Inside `Awake()`, the manager binding is completed through `GameFrameworkEntry.GetModule<IFsmManager>()`; if acquisition fails, it logs `Log.Fatal("FSM manager is invalid.")`.

   ```csharp
   var player = new Player();
   IFsm<Player> fsm = fsmComponent.CreateFsm(
       player,
       new FsmState<Player>[] { new IdleState(), new MoveState() }
   );
   fsm.Start<IdleState>();
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L63-L74) · [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L204-L222)

5. **No manual driving of the loop is required.** `FsmComponent.FixedUpdate()` will call `m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime)` according to Unity's physics cadence, so once the component is attached, the FSM is driven automatically; do not tick it again in business scripts.

   ```csharp
   private void FixedUpdate()
   {
       if (m_FsmManager == null) return;
       m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
   }
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

6. **Destroy the FSM when needed.** Clean up through the `DestroyFsm` overloads (by owner type, by `IFsm<T>` reference, by ownerType+name, etc.).

   ```csharp
   fsmComponent.DestroyFsm(fsm);     // Destroy the specified instance
   fsmComponent.DestroyFsm<Player>(); // Destroy the unnamed FSM under that owner type
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L304-L318)

## Common Variations

- **Named FSM (multiple machines coexisting under the same owner type)**: Distinguish through the `CreateFsm` overload with `name`, then access via `HasFsm<T>(name)` / `GetFsm<T>(name)`. For example, when a character simultaneously has a "Combat FSM" and an "AI Behavior Tree FSM", different names can be used to differentiate them.

  ```csharp
  IFsm<Player> combat = fsmComponent.CreateFsm("Combat", player, new AttackState(), new HurtState());
  IFsm<Player> ai     = fsmComponent.CreateFsm("AI", player, new PatrolState(), new ChaseState());
  combat.Start<AttackState>();
  ai.Start<PatrolState>();
  ```

  Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L218-L222)

- **Adding/removing states at runtime**: Dynamically adjust through `IFsm<T>.AddState` / `RemoveState<TState>()`. Note that the currently running state cannot be removed.

  ```csharp
  fsm.AddState(new JumpState());
  fsm.RemoveState<IdleState>();
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L153-L158)

- **Cross-state data access**: Use `SetData(name, value)` / `GetData<TData>(name)` / `HasData(name)` / `RemoveData(name)`. The underlying implementation uses an object pool, resulting in zero GC during runtime.

  ```csharp
  fsm.SetData("Health", 100);
  int hp = fsm.GetData<int>("Health");
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L141-L149)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Console reports `FSM manager is invalid.` | `FsmComponent.Awake()` did not find the `IFsmManager` module at the framework entry | Confirm that the GameFrameX entry component exists in the scene and is initialized before `FsmComponent`; confirm the FSM package is installed |
| After `CreateFsm`, `Start` reports "State does not exist" | The state is not registered, or the passed owner type does not match `T` | Check that the `T` in `CreateFsm<T>` matches the `T` of the `FsmState<T>` subclass, and add all states to the `states` array |
| Only one FSM can be created per owner type | Misuse of the `name`-less overload, which gets overridden by the implicit naming rule | Use `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` with `name` instead |
| FSM does not update | `FixedUpdate` is manually disabled in business scripts / `FsmComponent` is not attached | Confirm there is one and only one `FsmComponent` in the scene; do not call `m_FsmManager.FixedUpdate` again inside states |

## Background (Optional)

`FsmComponent` is only a facade; it forwards requests to `IFsmManager` (obtained through `GameFrameworkEntry.GetModule<IFsmManager>()`). The `[GameFrameXAutoComponent(-6000)]` attribute controls the automatic registration order of the component. `Count` exposes the current number of FSM instances, facilitating editor and runtime monitoring; the `[Preserve]` annotation ensures that public APIs are not erroneously stripped during IL2CPP trimming.
