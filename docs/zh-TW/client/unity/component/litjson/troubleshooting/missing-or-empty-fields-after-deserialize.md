# 反序列化時欄位遺失或為空該怎麼辦

呼叫 `JsonMapper.ToObject<T>` 之後，如果目標型別的某些欄位結果為 `null`、`0`、空字串或預設值，通常是欄位對應規則不符或 JSON 文字本身的問題所導致。本頁列出常見原因與對應的修正方式。

## 快速診斷

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| JSON 中存在的欄位在反序列化後變成預設值 | 欄位名稱大小寫與 JSON 不符 | 請見下方「欄位名稱大小寫不符」 |
| 私有欄位或只有 `private set` 的屬性在反序列化後為空 | LitJson 預設只對應 `public` 成員 | 請見下方「非公用欄位未被寫入」 |
| 反序列化後字典/清單為空，但 JSON 實際上包含資料 | 使用了非泛型介面，或目標型別不是 `IDictionary<TKey,TValue>` / `IList<T>` | 請見下方「容器型別不符」 |
| 數字欄位在反序列化後變成 `0`,但它在 JSON 中是字串 | JSON 中的數字被引號包住 | 請見下方「JSON 文字有引號或缺少引號」 |
| 部分欄位正確，部分欄位遺失 | JSON 文字無效或被截斷 | 請見下方「無效的 JSON 文字」 |
| 沒有任何欄位被寫入，但未擲出例外 | 目標型別是 `JsonData`,但你卻以物件成員的方式存取它 | 請見下方「`JsonData` 與強型別混用」 |

## 修正步驟

### 欄位名稱大小寫不符

當 LitJson 將 JSON 鍵與 C# 成員比對時，預設會以不區分大小寫的方式讀取。然而，當 JSON 欄位名稱與 C# 欄位名稱在拼寫上完全不同時(例如 `userId` 與 `UserId`,或是拼字錯誤)，該欄位將不會被寫入。

修正方式：確保 JSON 中的鍵與 C# 的屬性名稱完全一致；如果無法修改 JSON,請使用自訂匯出器/匯入器對應，或使用 `JsonData` 直接依鍵取值。

### 非公用欄位未被寫入

LitJson 預設只會讀取公用的執行個體屬性/欄位。如果你的資料型別將欄位宣告為 `private`、`internal`,或屬性只有 `private set`,反序列化器會忽略它們並保留型別的預設值。

修正方式：將需要反序列化的欄位/屬性改為 `public`,或為它們提供 `public` 存取子。

```csharp
public class PlayerData
{
    // 必須是 public,否則 ToObject<PlayerData> 不會寫入它們
    public int id;
    public string name;
}
```

### 容器型別不符

當 LitJson 將陣列/物件反序列化為強型別目標時，目標型別必須實作 `IList<T>` / `IDictionary<TKey, TValue>` 等泛型介面，或符合透過 `RegisterImporter` 註冊的型別對應。如果欄位型別是普通類別(例如自訂的 `MyList`),JSON 陣列會被跳過，該欄位將保持為空。

修正方式：將欄位型別改為 `List<T>`、`Dictionary<string, T>` 等內建容器，或在自訂容器上實作對應介面並透過 `RegisterImporter` 註冊。

### JSON 文字有引號或缺少引號

常見錯誤：將數字寫成字串(例如 `"score": "100"`),或將字串寫成裸字面值(例如 `"name": foo`)。LitJson 不會自動轉換這些內容；此類欄位會被悄悄跳過，或擲出 `JsonException`。

修正方式：使用任何線上 JSON 驗證工具確認文字是否有效；數字不應加引號，字串必須使用雙引號，欄位名稱也必須使用雙引號。

### 無效的 JSON 文字

常見原因：檔案讀取不完整(網路截斷、位元組順序問題、未處理的 BOM)、尾端逗號、單引號字串。如果 JSON 解析中途失敗，某些欄位可能根本沒有被讀取，但 `ToObject<T>` 會直接擲出例外，而不是「部分成功」。

修正方式：在呼叫 `ToObject<T>` 之前，使用 `JsonReader` 逐步檢視開頭與結尾；確保輸入是已移除 BOM 的 UTF-8 字串。

### `JsonData` 與強型別混用

`JsonMapper.ToObject(string)`(不帶泛型參數)回傳的是 `JsonData`,而不是「你假設的某個類別」。`JsonData` 是透過字串鍵來存取，例如 `data["name"]`;直接存取 `data.name` 不會得到你預期的值。

修正方式：明確使用 `ToObject<T>`(強型別)或 `ToObject()`(回傳 `JsonData`),不要混用。

```csharp
// 強型別
PlayerData p = JsonMapper.ToObject<PlayerData>(json);

// 弱型別
JsonData d = JsonMapper.ToObject(json);
string name = (string)d["name"];
```

## 驗證

1. 使用 `JsonMapper.ToObject(json)`(回傳 `JsonData`)印出整棵樹狀結構，確認 JSON 文字中包含你期望的鍵。
2. 接著使用 `JsonMapper.ToObject<T>(json)` 反序列化為目標型別，並逐欄位比對。
3. 如果仍然找不到欄位，暫時將目標型別改為 `JsonData`,看看 JSON 中的鍵實際上是什麼——這能立即區分「JSON 沒有它」與「C# 欄位名稱不符」。
