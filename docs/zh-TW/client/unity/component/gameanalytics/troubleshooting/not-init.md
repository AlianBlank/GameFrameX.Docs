# 事件沒有上報：「GameAnalyticsManager is not init.」警告怎麼辦

當你呼叫 `GameAnalyticsComponent` 的 `Event` / `StartTimer` / `StopTimer` 等介面時，如果對應的分析 SDK 管理器實例內部尚未完成初始化，元件會印出 `GameAnalyticsManager is not init.` 並跳過這一次上報。這條警告來自 `GameAnalyticsComponent` 的空初始化防護，表示「Provider 已建立出 `IGameAnalyticsManager` 實例，但該實例自己的 `m_IsInit` 仍是 false」。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 每次 `Event`/`StartTimer`/`StopTimer` 都印出 `GameAnalyticsManager is not init.` | 元件 `Init()` 已執行並建立了 `IGameAnalyticsManager` 實例，但實作類別內部的 `m_IsInit` 沒有被設為 `true`（`Init(args)` 沒有完成初始化，或該實作是「手動初始化」型而還沒呼叫 `ManualInit`） | 見下方[修復步驟 1](#1-在實作類別的-init-或-manualinit-中設定-isinit) |
| 主控台出現 `Log.Error`：`Can not find component type 'XXX'.` | Inspector 中設定的 `ComponentType` 類型名稱無法被 `Utility.Assembly.GetType` 解析（類型不存在、命名空間/組件不正確） | 核對類型名稱的拼字與所在組件，該筆 Provider 會被 `continue` 跳過 |
| 沒有任何警告，但事件也沒有上報 | `m_gameAnalyticsComponentProviders` 清單為空，或某項的 `ComponentType` 為空白字串（此時迴圈直接跳過，不會建立實例）；也可能元件層級的 `m_IsInit` 尚為 false，所有呼叫靜默 `return` | 在元件 Inspector 的「遊戲資料分析元件列表，按序上報」中新增 Provider 並選擇實作類型；確認呼叫發生在元件 `OnEnable` 之後 |
| 只在遊戲剛啟動的極早階段上報失敗、無警告 | 元件的 `Init()` 在 `OnEnable()` 中才執行，`Awake` 階段 `m_IsInit` 為 false，呼叫被靜默丟棄 | 將上報邏輯移到元件啟用之後 |

觸發這條警告的完整防護邏輯（以 `Event(string)` 為例，其餘多載與計時介面結構相同）：

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

## 修復步驟

### 1. 在實作類別的 Init 或 ManualInit 中設定 isinit

警告的判定依據是 `IGameAnalyticsManager.IsInit()`，它由基類 `BaseGameAnalyticsManager` 提供並回傳受保護欄位 `m_IsInit`：

```csharp
protected bool m_IsInit = false;

/// <summary>
/// 是否初始化
/// </summary>
/// <returns></returns>
public bool IsInit()
{
    return m_IsInit;
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L12-L45)

`Init(Dictionary<string, string> args)` 和 `ManualInit(Dictionary<string, string> args)` 是抽象方法，由每個分析 SDK 的實作類別自行實作。檢查你的實作：

- 若 SDK 無需使用者同意等前置條件，應在 `Init(args)` 完成 SDK 初始化後寫入 `m_IsInit = true;`；
- 若 SDK 需要 `ManualInit`（隱私合規流程），`IsManualInit()` 回傳 true 的實作要先呼叫 `GameAnalyticsComponent.ManualInit(extraArgs)`，並在其中設定 `m_IsInit`。注意元件端的防護：

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

`ManualInit` 只會轉發給 `IsManualInit()` 為 true 的實作，且要求元件自身已 `Init()`。

### 2. 確認 Provider 已在 Inspector 中設定

元件在 `OnEnable()` 呼叫 `Init()`，遍歷 `m_gameAnalyticsComponentProviders`，透過反射建立實作類別的實例並呼叫其 `Init(args)`：

```csharp
private void OnEnable()
{
    Init();
}

public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }
            // ...建立實例、組裝 args 並呼叫 gameAnalyticsManager.Init(args)
        }
    }

    m_IsInit = true;
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L27-L80)

在場景中的 `GameAnalyticsComponent` Inspector 裡（選單 `Game Framework/GameAnalytics`），編輯標題為「遊戲資料分析元件列表，按序上報」的清單：新增元素，在 `ComponentType` 下拉選單中選取實作了 `IGameAnalyticsManager` 的類型（下拉選項來自 `Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager))`），並在 `Setting` 中補充該實作所需的 Key/Value 參數（如 AppId、SecretKey 等，以具體實作為準）。

Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

### 3. 排查靜默丟棄（無警告但也沒上報）

元件層級的防護是靜默的：`!m_IsInit` 時直接 `return`，不印出任何日誌。若連警告都沒有，依序檢查：

1. 呼叫時機是否早於元件 `OnEnable`（`Awake` 階段 `m_IsInit` 仍為 false）；
2. `m_gameAnalyticsComponentProviders` 是否為空清單或 `ComponentType` 為空白——這種情況既不報錯也不建立實例；
3. 主控台是否有 `Can not find component type '...'` 的 `Log.Error`——該筆 Provider 會被 `continue` 跳過。

## 驗證

1. 啟動遊戲，確認主控台不再出現 `Can not find component type` 的紅色錯誤（該錯誤會直接導致對應 Provider 被跳過）。
2. 呼叫任意 `Event(...)` / `StartTimer(...)`，確認 `GameAnalyticsManager is not init.` 黃色警告消失。
3. 在對應的分析平台（如 ThinkingData、數數等，取決於實作類別）後台查看事件是否到達；或在實作類別的 `Init` 內加上臨時日誌，確認 `m_IsInit` 已設為 true。

## 背景

警告分兩層防護：`GameAnalyticsComponent.m_IsInit`（元件層級，`OnEnable` 時設為 true，未初始化時靜默丟棄）與各 `IGameAnalyticsManager.IsInit()`（實例層級，未初始化時印出本條警告）。`BaseGameAnalyticsManager` 只是持有 `m_IsInit` 欄位並對外提供 `IsInit()` / `SetPublicProperties` 等通用能力，設定的時機完全由具體 SDK 實作決定——因此該警告幾乎總是指向實作類別的 `Init`/`ManualInit` 沒有把 `m_IsInit` 設為 true，或呼叫發生在手動初始化流程之前。
