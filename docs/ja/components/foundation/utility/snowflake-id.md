# Snowflake を使用して分散一意 ID を生成する方法

`SnowFlakeIdHelper.Instance.NextId()` を一行呼び出すだけで、グローバルで一意かつ昇順に増加する 64 ビット整数 ID を生成でき、必要に応じて ID をタイムスタンプ、WorkerId、DataCenterId、シーケンス番号に逆解析できます。

## 前提条件

- 名前空間を参照:`GameFrameX.Foundation.Utility.DistributedSystem.Snowflake`
- プロジェクトが `GameFrameX.Foundation.Utility` アセンブリを参照していること
- マルチインスタンスデプロイメントの場合は、各ノードに互いに異なる `WorkId`(0~31)と `DataCenterId`(0~31)を設定する必要があります。さもないと重複した ID が生成されます

## 操作手順

1. **最も簡単な使い方:シングルトンから直接 ID を生成**

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   long id = SnowFlakeIdHelper.Instance.NextId();
   ```

   `Instance` は内部でダブルチェックロックによるシングルトンを採用しており、`WorkId=1`、`DataCenterId=1`、`BaseTime=2025-01-01 UTC` で初回アクセス時に `IdWorker` を初期化します。
   Source: [SnowFlakeIdHelper.cs#L181-L204](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L181-L204)

2. **ノード ID を手動で指定(単一インスタンスまたはテスト)**

   必ず `Instance` に**初めて**アクセスする前に設定してください。さもないと有効になりません。

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   SnowFlakeIdHelper.WorkId = 2;
   SnowFlakeIdHelper.DataCenterId = 3;
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L133-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L133-L145)

3. **WorkerIdProvider を使用してノード ID を自動割り当て**

   フレームワークにはホスト名、IP、プロセス番号などの戦略が組み込まれており、`Instance` に初めてアクセスする前に注入するだけです。

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   // 例:IP ハッシュで WorkId(0~31)を自動取得
   SnowFlakeIdHelper.SetWorkerIdProvider(new IpAddressWorkerIdProvider());
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L97-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L97-L100)

4. **(オプション)基準時刻またはビット幅を変更**

   デフォルトの `2025-01-01 UTC` 開始点を変更する必要がある場合、または WorkerId/シーケンス番号のビット幅をカスタマイズしたい場合は、初回アクセス前に変更してください:

   ```csharp
   SnowFlakeIdHelper.BaseTime = new DateTime(2020, 1, 1, 0, 0, 0, DateTimeKind.Utc).Ticks / 10000;
   SnowFlakeIdHelper.WorkerIdBits = 5;        // デフォルト 5
   SnowFlakeIdHelper.DatacenterIdBits = 5;    // デフォルト 5、データセンター次元を使用しない場合は 0 に設定可能
   SnowFlakeIdHelper.SequenceBits = 12;       // デフォルト 12、1 ミリ秒あたり最大 4096 個の ID
   ```
   Source: [SnowFlakeIdHelper.cs#L64-L160](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L64-L160)

5. **(オプション)ID を逆解析して構成要素を確認**

   ```csharp
   long id = SnowFlakeIdHelper.Instance.NextId();

   // デフォルトの BaseTime を使用して解析
   SnowFlakeIdInfo info = SnowFlakeIdParser.Parse(id);

   // または BaseTime/ビット幅をカスタマイズ
   SnowFlakeIdInfo custom = SnowFlakeIdParser.Parse(
       id,
       baseTimeMs: SnowFlakeIdHelper.BaseTime,
       workerIdBits: 5,
       datacenterIdBits: 5,
       sequenceBits: 12);

   Console.WriteLine($"時間={info.Timestamp:o}, Worker={info.WorkerId}, DC={info.DataCenterId}, Seq={info.Sequence}");
   ```
   Source: [SnowFlakeIdParser.cs#L63-L110](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdParser.cs#L63-L110),[SnowFlakeIdInfo.cs#L42-L94](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdInfo.cs#L42-L94)

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| 異なるマシン/プロセスで重複した ID が生成される | 双方の `WorkId` または `DataCenterId` が同じ | `SetWorkerIdProvider` で自動割り当てするか、各マシンに一意の番号を設定 |
| `WorkId` / `BaseTime` / ビット幅の調整が反映されない | すでにどこかで `Instance` にアクセス済みで、シングルトンが作成済み | プログラム起動の早い段階、すべての呼び出し前に設定を完了させるか、テスト間で独立した `IdWorker` インスタンスを使用 |
| 古い ID を解析するとタイムスタンプが異常 | `BaseTime` またはビット幅を間違えている | 解析時に生成時と一致する `baseTimeMs` と `workerIdBits`/`datacenterIdBits`/`sequenceBits` を明示的に指定 |
| `Parse` が `ArgumentOutOfRangeException` をスロー | ID が負数 | Snowflake ID は非負である必要があります。他の ID タイプと混在していないか確認 |
| システム時刻の巻き戻しにより生成がブロックまたは異常 | 雪花アルゴリズムはクロックの巻き戻しに敏感 | NTP 同期を確保し、巻き戻し時はカスタム `IdWorker` を使用して `InvalidSystemClock` を捕捉、直接エラーをスローしないようにする |

## 背景(オプション)

デフォルトのビット幅レイアウトは `1 符号ビット | 41 タイムスタンプビット | 5 データセンタービット | 5 ワーカーノードビット | 12 シーケンス番号ビット` で、単一ノードで 1 ミリ秒あたり 4096 個の ID を生成できます。基準時刻は `2025-01-01 UTC` に設定されており、41 ビットタイムスタンプの下で約 69 年使用可能です。`SnowFlakeIdParser` は完全に同じビット演算式を使用しているため、`BaseTime` とビット幅が一致していれば、ロスなしで逆解析できます。その他の分散 ID 方案との比較については、《分散 ID 選定》を参照してください。
