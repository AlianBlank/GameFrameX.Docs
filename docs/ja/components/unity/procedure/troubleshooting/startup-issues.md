# 起動に関する問題の対処法

このページでは `ProcedureComponent` の起動段階で最も一般的なエラーや例外を集約し、[ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs) と [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs) の実際の動作に基づいて修復方法を示します。

## クイック診断

| 症状（コンソール原文） | 原因 | 修復 |
|------|------|------|
| `Procedure manager is invalid.` | フレームワークが `GameFrameworkEntry` から `IProcedureManager` を取得できなかった。通常は `ProcedureComponent` がアタッチされていないか、コンポーネントの `Awake` が実行されていない。 | [修復 1](#修復-1procedure-manager-is-invalid) を参照 |
| `Available procedure type names is empty. Procedure auto start skipped.` | Inspector の `Available Procedure Type Names` 配列が空である。 | [修復 2](#修復-2available-procedure-type-names-is-empty) を参照 |
| `Can not find procedure type '{0}'.` | `Available Procedure Type Names` 内の型名文字列が、現在のアセンブリで対応する `Type` を検索できない。 | [修復 3](#修復-3can-not-find-procedure-type) を参照 |
| `Can not create procedure instance '{0}'.` | 型名は検索できるが、`Activator.CreateInstance` でインスタンス化できない（抽象クラス / パブリックコンストラクタなし）。 | [修復 4](#修復-4can-not-create-procedure-instance) を参照 |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` が `Available Procedure Type Names` 内に存在しない。 | [修復 5](#修復-5entrance-procedure-is-invalid) を参照 |
| `You must initialize procedure first.` | `Initialize` の前に `StartProcedure` / `HasProcedure` / `GetProcedure` / `CurrentProcedure` / `CurrentProcedureTime` を呼び出した。 | [修復 6](#修復-6you-must-initialize-procedure-first) を参照 |
| `Procedures is invalid.` | `m_ProcedureManager.Initialize(..., procedures)` を呼び出す際に空の配列を渡した。 | [修復 7](#修復-7procedures-is-invalid) を参照 |
| `Already exist FSM.` 起動後に再度シーンに入った | `Use Startup Runner` を有効にしているのに `ProcedureComponent` に旧ロジックを実行させ、`ApplicationStartupEntry` で重複初期化された。 | [修復 8](#修復-8already-exist-fsm) を参照 |

## 修復手順

### 修復 1:Procedure manager is invalid

`ProcedureComponent.Awake` で以下を実行:

```csharp
m_ProcedureManager = GameFrameworkEntry.GetModule<IProcedureManager>();
if (m_ProcedureManager == null)
{
    Log.Fatal("Procedure manager is invalid.");
    return;
}
```

調査方向:

1. シーンに `ProcedureComponent` がアタッチされた GameObject が存在することを確認する。コンポーネントのメニューは `GameFrameX/Procedure`。
2. `GameFrameworkEntry` が正常に初期化されていることを確認する（他の `GameFrameworkComponent` もアタッチされ `Awake` が実行済みであること）。
3. 他のコンポーネントが `IProcedureManager` の実装を登録していないか確認する。登録されている場合は、インターフェースが占有されているため競合が発生する —— 同一インターフェースには一つの実装しか登録できない。
4. IL2CPP / ストリッピング処理時には `[Preserve]` 属性がマネージャークラスに宣言されている。それでも消失する場合は、独自の `link.xml` が `GameFrameX.Procedure.Runtime` をカバーしているか確認する。

### 修復 2:Available procedure type names is empty

`ProcedureComponent.Start` 内のチェック:

```csharp
if (m_AvailableProcedureTypeNames == null || m_AvailableProcedureTypeNames.Length <= 0)
{
    Log.Warning("Available procedure type names is empty. Procedure auto start skipped.");
    yield break;
}
```

修復方法:Inspector の `Available Procedure Type Names` 配列に、フロー（プロシージャ）クラスの完全名（名前空間 + クラス名）を少なくとも 1 項目入力する。

### 修復 3:Can not find procedure type

対応するコード:

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

修復方法:

1. 文字列は `Type.FullName` と完全に一致させる必要がある、例如 `GameFrameX.Procedure.Runtime.ProcedureLaunch`。
2. フロー（プロシージャ）クラスを独自のアセンブリに配置する場合は、そのアセンブリがロードされていることを確認する（ビルド設定 → Player Settings →「Disable Domain Reload」をチェックしない場合でも、コードがプロジェクトにコンパイルされていることを確認する）。
3. クラス名変更 / 名前空間の移動後に Inspector の同期を忘れた場合に最も発生しやすい。クラス名を変更した後は、必ず Inspector に戻って文字列を同期する。

### 修復 4:Can not create procedure instance

対応するコード:

```csharp
procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

修復方法:フロー（プロシージャ）クラスが `public` であり、パブリックなパラメータレスコンストラクタを持ち、抽象クラスやインターフェースでないことを確認する。`ProcedureBase` の標準的な書き方:

```csharp
public sealed class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
    }
}
```

### 修復 5:Entrance procedure is invalid

`Start` 内でエントリフローをマッチング:

```csharp
if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

ループ終了時に `m_EntranceProcedure` が依然として `null` の場合、`Entrance procedure is invalid.` が出力される。修復方法:`Entrance Procedure Type Name` フィールドを `Available Procedure Type Names` 内の項目と**完全に同一**の値にする。

### 修復 6:You must initialize procedure first

`ProcedureManager` の複数のメンバーが `m_ProcedureFsm == null` のときにこの例外をスローする、例えば:

```csharp
public ProcedureBase CurrentProcedure
{
    get
    {
        if (m_ProcedureFsm == null)
        {
            throw new GameFrameworkException("You must initialize procedure first.");
        }
        return (ProcedureBase)m_ProcedureFsm.CurrentState;
    }
}
```

発生条件:`CurrentProcedure` / `CurrentProcedureTime` / `StartProcedure` / `HasProcedure` / `GetProcedure` のいずれかが `Initialize` の前に呼び出された。

修復方法:

1. デフォルトでは、`ProcedureComponent.Start` が自動的に `Initialize` + `StartProcedure` を実行するため、手動で呼び出す必要はない。
2. 独自に `IProcedureManager` を保持し先にアクセスする場合は、他のメンバーにアクセスする前に `Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)` を呼び出す。
3. `Use Startup Runner` を有効にした場合、コンポーネントの `Start` はフローを自動起動しない —— この場合、`ApplicationStartupEntry` / `StartupRunner.Run` が初期化を担当するため、それが実際に実行されることを確認する。

### 修復 7:Procedures is invalid

`ProcedureManager.Initialize` のチェック:

```csharp
if (procedures.Length <= 0)
{
    throw new GameFrameworkException("Procedures is invalid.");
}
```

修復方法:`Initialize` に空の配列を渡さない。少なくとも 1 つの `ProcedureBase` インスタンスを渡す。

### 修復 8:Already exist FSM

`Use Startup Runner = true` のとき、`ProcedureComponent.Start` は即座に終了する:

```csharp
if (m_UseStartupRunner)
{
    yield break;
}
```

この分岐の存在理由は、`ApplicationStartupEntry` + `StartupRunner.Run` と重複して `Initialize` し、`Already exist FSM`（同一の `IProcedureManager` 保持者が繰り返し `CreateFsm` を呼び出される）がトリガーされるのを避けるためである。

修復方法:以下のどちらか一方を選択し、混在させない:

- 旧モード:`Use Startup Runner = false`、Inspector の配列による自動起動に依存する。
- 新モード:`Use Startup Runner = true`、`ApplicationStartupEntry` が `StartupRunner.Run` を通じて起動フローを引き継ぐ。

## 検証

上記の修復を適用した後、以下の方法で問題が解決されたことを確認できる:

1. Play Mode に再度入り、コンソールに対応するエラーが出力されず、`ProcedureComponent.CurrentProcedure` が `null` でないことを確認する。
2. 最初のフロー（例: `ProcedureLaunch`）の `OnEnter` 内でログを出力し、ログが出現することで `StartProcedure` が実際に有効になっていることを確認する。
3. 2 番目のフロー内で `ChangeState<ProcedureXxx>()` を呼び出し、状態遷移が期待通りであるかを観察し、FSM 全体が正しく初期化されていることを検証する。
4. `Use Startup Runner` を有効にしている場合は、`ApplicationStartupEntry` 内で実際に `StartupRunner.Run` が呼び出され、エントリフロータイプが渡されていることを確認する。そうでなければ、フローは永遠に起動しない（`Awake` でマネージャーが登録されるのみ）。
