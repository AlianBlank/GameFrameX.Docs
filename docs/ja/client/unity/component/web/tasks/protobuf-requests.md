# Protocol Buffers リクエストの使用方法

`WebManager` が提供する `GetProtoBuf` / `PostProtoBuf` ジェネリックメソッドを使用すると、protobuf-net のメッセージオブジェクトで HTTP リクエストを送信し、逆シリアル化されたレスポンスオブジェクトを直接取得できます。メッセージ型は `IExtensible` を実装し、`ProtoContract`/`ProtoMember` で属性付けされている必要があります。

## 前提条件

- `com.gameframex.unity.web` パッケージがインストール済みであり、シーン内に `WebComponent` が存在し、`IWebManager`（`WebManager`）のインスタンスを保持していること。
- メッセージ型が protobuf-net のルールに従って属性付け（`ProtoContract` + `ProtoMember`）されており、`class, IExtensible` のジェネリック制約を満たしていること。

## API クイックリファレンス

| メソッド | シグネチャ | 説明 |
|------|------|------|
| `GetProtoBuf` | `Task<T> GetProtoBuf<T>(string url) where T : class, IExtensible;` | GET で protobuf メッセージを取得し、`T` に逆シリアル化します |
| `PostProtoBuf` | `Task<T> PostProtoBuf<T>(string url, IExtensible requestData) where T : class, IExtensible;` | リクエストボディを protobuf にシリアル化して POST 送信し、レスポンスを `T` に逆シリアル化します |

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L196-L198)

## 操作手順

1. protobuf のリクエスト/レスポンスメッセージクラスを定義します。フィールドの番号は `[ProtoMember(n)]` で指定します：

```csharp
[ProtoContract]
public class UserResponse
{
    [ProtoMember(1)]
    public string UserName { get; set; }

    [ProtoMember(2)]
    public string Email { get; set; }
}
```

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L116-L124)

2. 業務コード内で `PostProtoBuf`（または `GetProtoBuf`）を呼び出し、返される Task を `await` することでレスポンスオブジェクトを取得します：

```csharp
public async Task<UserResponse> GetUserProtoBufAsync(string userId)
{
    var request = new UserRequest { UserId = userId };
    return await webManager.PostProtoBuf<UserResponse>(
        "https://api.example.com/user/protobuf",
        request
    );
}
```

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L126-L133)

3. 必要に応じてエラー処理をラップします。例として、タイムアウトやネットワーク IO の例外をキャッチします：

```csharp
try
{
    return await webManager.GetToString(url);
}
catch (WebException ex) when (ex.Status == WebExceptionStatus.Timeout)
{
    Debug.LogError("请求超时: " + ex.Message);
    return null;
}
catch (IOException ex)
{
    Debug.LogError("网络IO错误: " + ex.Message);
    return null;
}
```

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.zh-CN.md#L138-L154)

## よくあるバリエーション

- **カスタムリクエストヘッダー**：protobuf リクエストは `WebBinaryData` の `Header` ディクショナリを使用し、送信時に各項目がリクエストヘッダーへ書き込まれます（ネイティブプラットフォームでは `request.Headers` に書き込み、WebGL プラットフォームでは `SetRequestHeader` を呼び出します）。詳細は [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L104-L110) および [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L140-L146) を参照してください。
- **WebGL プラットフォーム**：同一の API が `UNITY_WEBGL` 下では `UnityWebRequest` + `UploadHandlerRaw` を使ってバイト列をアップロードし、その他のプラットフォームでは `HttpWebRequest` でリクエストストリームに書き込みます。詳細は [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L83-L101) を参照してください。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| リクエスト送信後、一向にレスポンスが返らない | protobuf リクエストはまず待機キューに入り、`UpdateBinary` によって毎フレームデキューされます。`WebManager` が更新されていない（コンポーネントが非アクティブな）場合や、送信済み数が `MaxConnectionPerServer` に達している場合、リクエストはキューで待機し続けます | `WebComponent` が正常に動作しており `WebManager` が更新状態にあることを確認し、同時接続数の上限を適切に設定してください |
| 逆シリアル化結果のフィールドが空 | メッセージ型に `[ProtoContract]` / `[ProtoMember(n)]` の属性付けが不足している、または型が `class, IExtensible` 制約を満たしていない | リクエスト/レスポンス型に protobuf-net の属性を追加します |
| サーバー側で解析に失敗する | リクエストの `Content-Type` は `application/octet-stream` に固定されており、サーバー側は protobuf バイナリとして解析する必要があります | サーバー側でテキスト形式ではなくバイナリ protobuf として処理します |

## 検証

- `PostProtoBuf` 呼び出し後にレスポンスオブジェクトのフィールド（例： `response.UserName`）をログ出力し、サーバーからの戻り値を取得できれば、リクエストと逆シリアル化が成功しています。
- ネットワークエラーが発生すると例外がスローされます（ネイティブプラットフォームでは `HttpWebRequest` 関連の例外、WebGL プラットフォームでは `unityWebRequest.error` をラップした `Exception`）。これによって失敗原因を確認できます。

## 背景

protobuf リクエストはフレームワーク内部で「Binary リクエスト」として処理されます。`GetProtoBuf`/`PostProtoBuf` を呼び出すと、リクエストは `WebBinaryData` にラップされて `m_WaitingBinaryQueue` に入ります。毎フレーム、`UpdateBinary` は同時接続数が上限に達していない場合にデキューし、`MakeBinaryBytesRequest` を呼び出して送信します。レスポンスのバイト列は `WebBufferResult` にカプセル化され、コールバックが完了します。関連実装は [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L17-L55) を参照してください。
