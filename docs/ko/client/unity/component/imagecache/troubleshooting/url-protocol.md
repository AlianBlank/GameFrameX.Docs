# URL 프로토콜 검증 실패 시 대처 방법

`LoadImageAsync`를 호출할 때, 전달된 URL이 `http://` 또는 `https://`로 시작하지 않으면 컴포넌트가 즉시 로드를 거부하고 콘솔에 경고를 출력합니다. 이 경우 해당 호출은 `null`을 반환하며, 다운로드나 캐시 프로세스는 실행되지 않습니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 콘솔에 `ImageCache: url must start with http:// or https://. url: ...` 메시지가 표시되고, `LoadImageAsync`가 `null`을 반환함 | URL에 프로토콜 접두사가 없거나 프로토콜이 http/https가 아님 (예: `ftp://`, `file://`, `data:`, 상대 경로, `www.example.com/x.png` 등) | URL 문자열 앞에 `http://` 또는 `https://` 접두사를 붙여주세요 |
| URL이 올바르게 보이지만 검증 실패 | URL 앞뒤에 불필요한 공백, 줄바꿈 또는 보이지 않는 문자가 포함되어 있음 | 호출 전에 `Trim()`을 사용하여 앞뒤 공백을 제거하세요 |
| URL이 검증을 통과했지만 여전히 로드 실패 | URL 프로토콜은 유효하지만 리소스를 사용할 수 없거나, 네트워크 문제 또는 서버에서 오류가 발생함 | 아래 "검증 통과 후에도 로드 실패" 섹션을 참조하세요 |

## 해결 절차

### 1. URL에 프로토콜 접두사가 없는 경우

검증 로직은 `http://`와 `https://` 두 가지 접두사만 허용하며, 다른 프로토콜이나 도메인 단독 사용은 거부됩니다.

```csharp
// 잘못된 예 — 도메인 단독 사용은 거부됨
string bad1 = "www.example.com/img.png";
string bad2 = "example.com/img.png";

// 올바른 예
string good1 = "http://www.example.com/img.png";
string good2 = "https://www.example.com/img.png";
```

### 2. URL 앞뒤에 불필요한 공백이 있는 경우

`StartsWith` 검증은 대소문자를 구분하며 공백을 제거하지 않습니다. 앞쪽에 공백만 있어도 접두사 비교에 실패합니다. 호출 전에 명시적으로 `Trim`을 사용하는 것을 권장합니다.

```csharp
string rawUrl = "  https://example.com/img.png  ";
string url = rawUrl.Trim();

var tex = await ImageCacheComponent.Instance.LoadImageAsync(url);
```

### 3. URL이 검증을 통과했지만 여전히 로드 실패하는 경우

검증은 프로토콜 접두사만 확인하며, 리소스가 실제로 다운로드 가능한지는 검증하지 않습니다. 로그에 "url must start with ..." 메시지가 나타나지 않는다면, 다음 순서대로 확인하세요:

- 콘솔에 `ImageCache: url is null or empty.` 메시지가 표시되는 경우 — 전달된 문자열이 `null`이거나 빈 문자열이므로, 유효한 URL을 전달해야 합니다.
- 콘솔에 다운로드 실패 이벤트(`DownloadFailure`)가 발생하는 경우 — 서버에서 404/403을 반환했거나, 네트워크 타임아웃, CORS 제한이 있을 수 있으므로 서버 상태와 HTTPS 인증서를 점검해야 합니다.
- WebGL 플랫폼: 검증 통과 후 `LoadImageWebGLAsync`가 호출되며 브라우저가 캐시를 담당합니다. 브라우저에서 CORS 오류가 발생하면 서버에서 적절한 CORS 헤더를 반환해야 합니다.

## 검증

1. 호출 전에 로그를 출력하거나 중단점을 설정하여 URL이 `http://` 또는 `https://`로 시작하고 앞뒤에 공백이 없는지 확인하세요.
2. `LoadImageAsync` 호출 후, `null`이 아닌 `Texture2D`를 반환하고 콘솔에 "url must start with" 경고가 없으면 검증 통과와 로드 성공이 모두 완료된 것입니다.
3. 여전히 `null`이 반환된다면, 위의 진단 표에서 로그 키워드를 확인하여 구체적인 실패 단계를 파악하세요.
