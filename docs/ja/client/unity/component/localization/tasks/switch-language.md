# 言語の切り替え方法：システム言語の検出、デフォルト言語へのフォールバックと設定の永続化

本ページでは、GameFrameX Unity Localization パッケージで言語切り替えを完了させるまでの完全なフローについて説明します：システム言語の読み取り、未対応の場合のデフォルト言語へのフォールバック、ユーザーの選択の永続化、そして次回起動時にユーザー設定を優先的に復元すること。

> **重要な説明**：今回のドキュメント作成時にソースコードの読み取り予算が尽きたため（SOURCE_TOOL_BUDGET_REACHED）、リポジトリから実際の実装コードと API シグネチャを抽出できませんでした。そのため本ページには現在表示できるコード例がなく、文中に具体的なクラス名・メソッド名・設定キーは一切登場しません——リポジトリのソースコードを確認のうえ使用してください。以下の手順は、本パッケージのタイトルが示す機能の標準的な使用フローであり、ソースコードを読む際の照合・特定にご活用ください。

## 前提条件

- Unity プロジェクトに `com.gameframex.unity.localization` パッケージがインストールされていること。
- 少なくとも 1 つのターゲット言語に対してローカライズリソース（言語テーブル/言語パック）が準備されており、その中にデフォルト言語が含まれていること。
- ランタイムに入り、本パッケージが外部に公開するローカライズ管理のエントリーポイントにアクセスできること（具体的な型はパッケージのエントリースクリプトを参照してください）。

## 操作手順

1. **言語リソースの準備確認**：起動時に、すべての候補言語のローカライズデータがロード済みであることを先に確認します。そうでないと、切り替え後にテキストを取得できません。
2. **永続化されたユーザー設定の読み取り**：起動時に、前回保存された言語設定を優先的に読み取ります（通常は `PlayerPrefs` またはパッケージ内独自の永続化ラッパー）。
   - 有効な設定が存在しその言語が利用可能な場合は、そのまま適用し、手順 3、4 をスキップします。
   - 設定がない場合は、手順 3 に進みます。
3. **システム言語の検出**：Unity エンジンが提供するシステム言語情報（エンジンレベルでは `Application.systemLanguage`、パッケージ内には通常対応するラッパーがあります）を通じて、現在のデバイスの言語を取得します。
4. **マッチングとフォールバック**：システム言語をパッケージがサポートする言語にマッピングします：
   - サポートリストにヒット → その言語を適用。
   - ヒットしない（例：システム言語に対応する言語パックがない）→ デフォルト言語にフォールバックし、UI に常に表示できるテキストがあることを保証します。
5. **切り替えの実行**：本パッケージの言語切り替えエントリーポイントを呼び出し、テキストの更新をトリガーします（UI 上のローカライズコンポーネントは言語の変化に応じて値を再取得する必要があります）。
6. **設定の永続化**：ユーザーが能動的に言語を選択した後、直ちに設定ストアに書き込み、次回起動時に手順 2 に従って復元されるようにします。
7. **検証**：切り替え後、UI に表示済みのローカライズテキストが新しい言語に更新されているかを確認します。アプリ再起動後、言語がユーザーの前回の選択のままであることを確認します。

## よくあるエラー

| 症状 | 考えられる原因 | 回避方法 |
|------|----------|----------|
| 言語切り替え後に UI テキストが更新されない | ローカライズコンポーネントが言語変更イベントを購読していない、または切り替え時点で新しい言語データのロードが完了していない | 言語データを先にロードしてから切り替えることを確認。コンポーネントが言語変更をリッスンしているか確認 |
| 起動のたびにシステム言語に戻る | 切り替え後に設定が書き込まれていない、または起動時にシステム言語を先に検出してから設定を読み取っている | 「設定の読み取りがシステム言語の検出より優先」という順序を保証し、ユーザーの選択後は直ちに永続化する |
| UI に空白や Key の原文が表示される | システム言語がサポートリストに含まれず正しくフォールバックされていない、または現在の言語に対応するエントリが不足している | デフォルト言語へのフォールバックロジックが有効であることを確認し、欠落しているエントリを補完する |
| 保存された設定の言語がパッケージ交換/データクリア後に無効になる | 設定ストアがアプリデータとともに削除され、耐障害処理がされていない | 設定読み取り時に言語が引き続きサポートされているか検証し、未対応ならフォールバック経路に入る |

## 背景

この「設定優先 → システム言語 → デフォルト言語」という 3 段階の順序は、ローカライズパッケージにおける一般的な設計です：デフォルト言語によるフォールバックは、いかなる場合でも UI にテキストがあることを保証します。システム言語により、初回起動時にユーザーの環境へ自動的に適合します。永続化された設定はユーザーの能動的な選択を尊重し、起動のたびにシステム言語で上書きされることを防ぎます。具体的な検出・マッチング・永続化の実装（`PlayerPrefs` を使用するかどうか、サポート言語リストがどこで定義されているか、デフォルト言語をどのように設定するかを含む）については、リポジトリのソースコードを直接参照してください。
