# AOT Preserve Validation Errors: Troubleshooting

When you run `AotPreserveValidationRunner.ValidateGeneratedFiles()` in CI, or trigger HybridCLR AOT preserve generation from the Unity menu, errors occur if generated files are missing, inconsistent with the current configuration, or there are stale files in the generated directory. This page provides a diagnostic table for common error messages and corresponding fix steps.

## Quick Diagnosis

| Symptom (raw exception message) | Cause | Fix |
|------|------|------|
| `Generated file is missing: Assets/Generated/AotPreserve/link.xml` | `Assets/Generated/AotPreserve/` directory or `link.xml` does not exist | Re-run the generation menu, see "Fix Step 1" below |
| `Generated file is out of date: Assets/Generated/AotPreserve/...` | Configuration changed, but the generated `link.xml`/reference code/asmdef/report hasn't been refreshed | Re-run generation, see "Fix Step 1" below |
| `Generated file is stale: Assets/Generated/AotPreserve/...` | Stale files from a removed configuration remain in the generated directory | Re-run generation (it will automatically empty the directory), see "Fix Step 1" below |
| `Preserve type entry is null.` | A `null` element was placed in `PreserveTypes`/`WrapTypes`/`PreserveGenericTypes` of `IAotPreserveSettingsProvider` | Check the configuration code and remove null entries, see "Fix Step 2" |
| `Preserve generic type entry is null.` | Same as above, occurring in `PreserveGenericTypes` | Same as above |
| `Preserve member entry is null.` | `PreserveMembers` array contains null strings | Check the configuration, see "Fix Step 2" |
| `Hotfix AOT preserve generation failed: ...` | `GenerateAndWrite()` detected errors during the generation phase (e.g., the categories above) | Expand each line in the exception and fix them one by one using this table |
| Validation passes: `ValidateGeneratedFiles()` returns an empty array but still throws `InvalidOperationException` | This almost never happens; if it does, paste the full exception `Message` for investigation | Collect the complete exception `Message` for feedback |

Where exceptions are thrown: [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27). Error message assembly logic: [`AotPreserveGenerator.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L103-L122).

## Fix Steps

### 1. Regenerate AOT Preserve Files

For most "missing/out of date/stale" errors, simply regenerating will fix them.

1. In the Unity menu bar, click **GameFrameX → HybridCLR Generate AOT Preserve** (see the menu constant at [`AotPreserveConstants.MenuPath`](/src/Editor/AotPreserve/AotPreserveConstants.cs#L65)).
2. Wait until the console reports no errors. The generator first deletes the entire `Assets/Generated/AotPreserve/` directory, then writes:
   - `Assets/Generated/AotPreserve/link.xml`
   - `Assets/Generated/AotPreserve/aot_preserve_report.md`
   - `Assets/Generated/AotPreserveReferences.cs`
   - `Assets/Generated/AotPreserve.Generated.asmdef`
   - A series of `AotPreserveReference_*.cs` reference placeholder files split by type
3. In CI scenarios, use the code entry instead:

```csharp
using GameFrameX.Editor;
AotPreserveGenerator.GenerateAndWrite();
```

See the write logic and failure exceptions at [`AotPreserveGenerator.GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L94): if `result.HasErrors` is true, an `InvalidOperationException("Hotfix AOT preserve generation failed:\n...")` is thrown first, then subsequent disk operations continue; if a disk write fails, an `IOException` or `UnauthorizedAccessException` is thrown.

### 2. Clean Up null Entries in Configuration

When the exception message starts with `Preserve type entry is null.`, `Preserve generic type entry is null.`, or `Preserve member entry is null.`, it means your custom implementation of `IAotPreserveSettingsProvider` returned an array containing `null` elements. These nulls are collected into `AotPreserveAnalysis.Errors` during the analysis phase and ultimately thrown by the validator as error messages.

How to fix:

1. Find the class in your project that implements [`IAotPreserveSettingsProvider`](/src/Editor/AotPreserve/IAotPreserveSettingsProvider.cs) (see the default implementation at [`DefaultAotPreserveSettingsProvider`](/src/Editor/AotPreserve/DefaultAotPreserveSettingsProvider.cs), resolved by [`AotPreserveSettingsProviderResolver`](/src/Editor/AotPreserve/AotPreserveSettingsProviderResolver.cs)).
2. Filter out `null` before returning `PreserveTypes` / `WrapTypes` / `PreserveGenericTypes` / `PreserveMembers`.
3. Re-run generation and validation.

### 3. Clean Up Stale Residual Files

If you see `Generated file is stale: <path>`, it's typically a leftover from a previous generation that the current configuration no longer needs. Simply re-run the generation menu — [`GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L80-L84) will first `Directory.Delete(GeneratedDirectory, true)` and then rebuild.

Do not manually modify any files under `Assets/Generated/AotPreserve/` — they are generated artifacts and will be overwritten on the next generation.

## Verification

After fixing, confirm success in CI or locally using either of the following:

- Code entry:

```csharp
using GameFrameX.Editor;
AotPreserveValidationRunner.ValidateGeneratedFiles(); // Passes if no exception is thrown
```

See the implementation at [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27): internally it calls `AotPreserveGenerator.ValidateGeneratedFiles()`, joins all errors with newline characters, and throws `InvalidOperationException`.

- Direct call to the generator validation entry:

```csharp
var errors = AotPreserveGenerator.ValidateGeneratedFiles();
// Passes if errors.Length == 0
```

When the returned array has 0 elements, it means all generated files are complete and consistent with the configuration; when it is non-zero, each string in the array is an independent error — handle them one by one according to the diagnostic table above.
