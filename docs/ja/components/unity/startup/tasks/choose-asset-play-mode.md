# リソース実行モード（PlayMode）の選択方法

リソース実行モード（`EPlayMode`）は、YooAsset が起動時にアセットをどのようにロードするかを決定します。`StartupOptions` アセット内の `GamePlayMode` フィールドを設定するだけで、起動フローがリソースをロードする前に `AssetComponent` へ自動的に同期します。

## 前提条件

- `GameFrameX/Startup Options` メニューから `StartupOptions` アセットを作成済みであること。
- `GameFrameX.Asset` コンポーネントがインストールされ、`GameEntry` に登録済みであること（フレームワークによりデフォルトで登録されます）。
- プロジェクトが YooAsset を使用していること（フレームワークの `EPlayMode` は `YooAsset` 名前空間由来です）。

## 操作手順

1. プロジェクト内の `StartupOptions` アセットを開きます（`Assets/` 配下の任意の場所）。
2. **Asset** カテゴリ配下にある **GamePlayMode** フィールドを見つけます。
3. 目的の列挙値を選択します。主な値と用途は下表の通りです。

| 列挙値 | 意味 | 典型的なシーン |
|---|---|---|
| `EditorSimulateMode` | エディターのシミュレーションモード。プロジェクト内の AssetDatabase リソースを直接読み込み、リソースパッケージを経由しない | Unity Editor 内での純粋なローカルデバッグ |
| `OfflinePlayMode` | オフラインモード。ビルド済みのローカルリソースパッケージをロードし、ネットワークに接続しない | スタンドアロン公開、バックエンドのないイントラネット |
| `HostPlayMode` | ホストモード。リモート CDN からリソースパッケージを取得 + ローカルキャッシュ | ホットアップデート可能な通常のモバイル/PC 向け公開 |
| `WebPlayMode` | Web モード。WebGL 向けのリソースロード | WebGL プラットフォーム |

フィールドの定義箇所（ソースコードリンク付き）：

```csharp
[Header("Asset")] [Tooltip("リソース実行モード。起動フローがリソースをロードする前に Asset コンポーネントへ同期します。")]
public EPlayMode GamePlayMode = EPlayMode.EditorSimulateMode;
```

出典： [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L19-L20)

起動時、フレームワークはこのフィールドを読み取り、`AssetComponent` へ同期します：

```csharp
private static void ApplyAssetPlayMode(StartupOptions options)
{
    GameEntry.GetComponent<AssetComponent>().GamePlayMode = NormalizeAssetPlayMode(options.GamePlayMode);
}
```

出典： [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L127-L130)

## よくあるバリエーション

### エディターでは EditorSimulateMode を選択し、ビルド後は自動書き換え

エディター内でのデバッグでは通常 `EditorSimulateMode` を選択します。`NormalizeAssetPlayMode` は非 Editor 環境下で自動的にこれを `HostPlayMode` へ降格するため、手動で切り替える必要はありません。

```csharp
private static EPlayMode NormalizeAssetPlayMode(EPlayMode playMode)
{
#if !UNITY_EDITOR
    if (playMode == EPlayMode.EditorSimulateMode)
    {
        playMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    playMode = EPlayMode.WebPlayMode;
#endif
#endif
    return playMode;
}
```

出典： [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L132-L144)

### フローの分岐の区別：Offline と EditorSimulate

起動フローでは、異なる `PlayMode` がそれぞれ異なる更新/パッチパスを通ります。ビジネスコード内で手動判定する必要はありません：

- `OfflinePlayMode`：[ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L42) 内でリモートマニフェストの更新をスキップします。
- `EditorSimulateMode`：[ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L71) 内でシミュレーションマニフェストの分岐を通ります。

### WebGL では WebPlayMode が強制される

コンパイルターゲットが WebGL である限り、何を設定しても `NormalizeAssetPlayMode` は `WebPlayMode` へ強制的に書き換えます（上記コードスニペット内の `#if UNITY_WEBGL` ブロックを参照）。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|---|---|---|
| プレイヤービルドの起動後にリソースが見つからない | `EditorSimulateMode` が公開ビルドでも使用できると思い込んでいる | 非 Editor 環境では自動的に `HostPlayMode` へ降格されます。CDN URL とリソースパッケージのバージョンフローが正しく設定されていることを確認してください |
| WebGL でリソースのロードに失敗する | `HostPlayMode` などの非 Web モードを引き続き使用している | コンパイルターゲットを WebGL に切り替えれば、フレームワークが自動的に `WebPlayMode` へ変更します。手動での変更は不要です |
| オフラインモードなのにネットワーク接続を試みる | `OfflinePlayMode` をホットアップデートが必要なシーンに設定している | バックエンドなし/スタンドアロンのシーンでのみ `OfflinePlayMode` を使用してください |
| `StartupOptions` に `GamePlayMode` フィールドが見つからない | 最新のアセットを使用していない、またはフィールド名が変更されている | `GameFrameX/Startup Options` からアセットを再作成してください |

## 背景（任意）

フィールド名 `GamePlayMode` は、`AssetComponent` 自身が持つ同名プロパティとの競合を避けるためのものです。デフォルト値 `EditorSimulateMode` により、開発者は Unity Editor 内で直接フローを完走でき、ビルド後は `NormalizeAssetPlayMode` によって公開可能なモードへ自動的に降格されるため、「開発者向けの利便性」が誤ってプレイヤービルドに持ち込まれることを防ぎます。`StartupOptions` は `[CreateAssetMenu]` を通じて、プロジェクト内で SO 形式として直接管理されます。
