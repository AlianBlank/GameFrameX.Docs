# How to Handle Player Login and Sessions (Session)

This page helps you accomplish two things: let players complete login through client messages, and correctly manage the player's network session on account replacement/disconnection. After completion, players can enter the game logic, and the server can correctly clean up offline players.

## Prerequisites

- The client uses the framework network layer (KCP/HTTP) to initiate requests, and login messages use Protobuf protocol numbers `ReqPlayerLogin` / `RespPlayerLogin`.
- The server has started `GameApp` and registered `SessionManager` (automatically loaded when the framework starts).
- The account service `LoginComponent` exists (located at [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs)) and can obtain `roleId` through the account Token.

## Operation Steps

### 1. Implement the Login Request Handler

Create a new `ReqPlayerLoginHandler`, inheriting from `GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>`. The framework will automatically route messages based on `[MessageMapping]`.

```csharp
using GameFrameX.Hotfix.Logic.Player.Login;
using GameFrameX.Apps.Player.Login.Component;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[MessageMapping(typeof(ReqPlayerLogin))]
internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
{
    protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
    {
        await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
    }
}
```

Source: [ReqPlayerLoginHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L30-L38)

### 2. Complete the Binding in LoginComponentAgent

`OnPlayerLogin` internally performs four things in order: verify account/signature → obtain `roleId` → write `roleId` and `sign` to the current `Session` → call `SessionManager.UpdateSession` to complete binding and trigger the account replacement logic.

```csharp
// Pseudocode, showing the call order, real signature see LoginComponentAgent
var loginResult = await LoginComponent.LoginByToken(request.AccountToken); // Returns roleId / sign
NetWorkChannel.Session.SetPlayerId(loginResult.RoleId);
NetWorkChannel.Session.SetSign(loginResult.Sign);
await SessionManager.UpdateSession(NetWorkChannel.Session.SessionId, loginResult.RoleId, loginResult.Sign);
```

The actual signature is provided by `LoginComponentAgent.OnPlayerLogin(NetWorkChannel, request, response)`, see [LoginComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs).

### 3. Listen to the Session Removal Event to Complete Offline Cleanup

Implement `SessionRemoveEventListener`. When a session is removed (actively `Remove` or cleared when replaced), the framework will dispatch the `EventId.SessionRemove` event, triggering the player offline logic.

```csharp
using GameFrameX.Apps.Common.Event;
using GameFrameX.Core.Abstractions.Events;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

Source: [SessionRemoveEventListener.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L30-L42)

### 4. Account Replacement and Session Substitution (Implemented by the Framework)

`SessionManager.UpdateSession` internally first calls `GetByRoleId(roleId)` to find the old session, then sends a `Type=5` prompt message (`Apps.SessionManager.AccountAlreadyLoggedIn` localized text) to the old connection via `WriteAsync`, then `ClearData()` + `Close()`, and finally `Remove(oldSession.SessionId)`. There is no need to re-implement account replacement on the business side, just ensure `UpdateSession` is called.

```csharp
// Excerpted from SessionManager.UpdateSession
var oldSession = GetByRoleId(roleId);
if (oldSession != null)
{
    var msg = new RespPrompt { Type = 5,
        Content = LocalizationService.GetString(Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn) };
    await oldSession.WriteAsync(msg);
    oldSession.WorkChannel.ClearData();
    oldSession.WorkChannel.Close();
    Remove(oldSession.SessionId);
}
```

Source: [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L216-L240)

## Common Variants

| Scenario | Approach |
|------|------|
| The same player logs in repeatedly on the same device | `Session.Sign` is the same, directly go through `UpdateSession` to replace the binding, do not kick the old connection |
| The same player logs in on a different device | `Sign` is different, the old session is closed and receives a `Type=5` prompt message |
| Login via HTTP | Handled by [ReqLoginHttpHandler](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs), after the business side obtains `roleId`, it goes through the client `ReqPlayerLogin` to complete binding |
| GM force kick | Call `SessionManager.KickOffLineByUserId(roleId)`, which will automatically dispatch the `SessionRemove` event |

## Common Errors

- **Forgot to call `UpdateSession`**: Login verification passes but `roleId` is not bound, subsequent queries by `PlayerId` cannot find the session, all player logic fails.
- **Did not listen to `SessionRemove`**: Player objects are not cleaned up after disconnection, resulting in resource leaks and stale data upon reconnection.
- **Account replacement text not localized**: Using hardcoded strings, bypassing `LocalizationService.GetString` directly, will cause incorrect prompts in multilingual environments.
- **Manually `Remove` session and then manually `Close`**: The framework has already handled the closing of the old connection inside `UpdateSession`, calling it again on the business side will trigger `SessionRemove` repeatedly.

## Background (Optional)

- `Session` is a connection-level object that internally holds `INetWorkChannel`, and is mutually bound with the network channel through `SetData(GlobalConst.SessionIdKey, ...)`.
- `SessionManager` uses `ConcurrentDictionary<string, Session>` to store sessions, and maintains `PlayerRouteMap` for cross-server routing; during account replacement, cleanup delays are avoided by first `Remove` and then waiting for the `Disconnected` callback.
- The account replacement prompt message `Type=5` is carried by the `RespPrompt` protocol, with text from `Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn`.
