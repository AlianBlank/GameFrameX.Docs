# AOT 保留検証エラーが発生した場合の対処方法

CI で `AotPreserveValidationRunner.ValidateGeneratedFiles()` を実行する際、または Unity メニューから HybridCLR AOT 保留生成を起動する際に、生成ファイルが欠落している、現在の構成と一致しない、生成ディレクトリに古いファイルが残っているなどの問題が発生すると、エラーが発生します。本ページでは、一般的なエラーメッセージの診断表と対応する修復手順を説明します。

## クイック診断

| 症状(例外メッセージ原文) | 原因 | 修復 |
|------|------|------|
| `Generated file is missing: Assets/Generated/AotPreserve/link.xml` | `Assets/Generated/AotPreserve/` ディレクトリまたは `link.xml` が存在しない | 生成メニューを再実行する。詳細は後述の「修復手順 1」 |
| `Generated file is out of date: Assets/Generated/AotPreserve/...` | 構成を変更したが、生成された `link.xml`/参照コード/asmdef/レポートがまだ更新されていない | 再生成する。詳細は後述の「修復手順 1」 |
| `Generated file is stale: Assets/Generated/AotPreserve/...` | 生成ディレクトリに、構成から既に削除された古いファイルが残っている | 再生成する(ディレクトリは自動的にクリアされる)。詳細は後述の「修復手順 1」 |
| `Preserve type entry is null.` | `IAotPreserveSettingsProvider` の `PreserveTypes`/`WrapTypes`/`PreserveGenericTypes` に `null` 要素が含まれている | 構成コードを確認し、null 項目を削除する。詳細は「修復手順 2」 |
| `Preserve generic type entry is null.` | 同上、`PreserveGenericTypes` で発生 | 同上 |
| `Preserve member entry is null.` | `PreserveMembers` 配列に null 文字列が含まれている | 構成を確認する。詳細は「修復手順 2」 |
| `Hotfix AOT preserve generation failed: ...` | `GenerateAndWrite()` が生成段階でエラーを検出した(例:上記の種類) | 例外の各行を展開し、本表に従って一つずつ修復する |
| 検証で `ValidateGeneratedFiles()` が空配列を返したのに `InvalidOperationException` が発生する | ほぼ発生しない;発生した場合は例外の `Message` を完全に貼り付けて調査する | 例外 `Message` の全文を収集してフィードバックする |

例外のスロー位置については [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27)、エラーメッセージの連結ロジックについては [`AotPreserveGenerator.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L103-L122) を参照してください。

## 修復手順

### 1. AOT 保留ファイルを再生成する

ほとんどの「missing/out of date/stale」類のエラーは、単に再生成するだけで修復できます。

1. Unity メニューバーで **GameFrameX → HybridCLR Generate AOT Preserve** をクリックします(メニュー定数は [`AotPreserveConstants.MenuPath`](/src/Editor/AotPreserve/AotPreserveConstants.cs#L65) を参照)。
2. コンソールにエラーが表示されなくなるまで待ちます。ジェネレーターはまず `Assets/Generated/AotPreserve/` ディレクトリ全体を削除した、以下のファイルを書き出します:
   - `Assets/Generated/AotPreserve/link.xml`
   - `Assets/Generated/AotPreserve/aot_preserve_report.md`
   - `Assets/Generated/AotPreserveReferences.cs`
   - `Assets/Generated/AotPreserve.Generated.asmdef`
   - 型ごとに分割された `AotPreserveReference_*.cs` シリーズの参照用プレースホルダファイル
3. CI シナリオでは、コードエントリを使用します:

```csharp
using GameFrameX.Editor;
AotPreserveGenerator.GenerateAndWrite();
```

書き込みロジックと失敗時の例外については [`AotPreserveGenerator.GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L94) を参照してください:`result.HasErrors` が true の場合、まず `InvalidOperationException("Hotfix AOT preserve generation failed:\n...")` がスローされ、その後にディスク操作が続行されます。ディスク書き込みが失敗した場合は、`IOException` または `UnauthorizedAccessException` がスローされます。

### 2. 構成内の null エントリをクリーンアップする

例外メッセージが `Preserve type entry is null.`、`Preserve generic type entry is null.`、`Preserve member entry is null.` で始まる場合は、カスタム実装した `IAotPreserveSettingsProvider` が `null` 要素を含む配列を返していることを意味します。これらの null は解析段階で `AotPreserveAnalysis.Errors` に収集され、最終的にバリデーターによってエラーメッセージとしてスローされます。

修復方法:

1. プロジェクト内で [`IAotPreserveSettingsProvider`](/src/Editor/AotPreserve/IAotPreserveSettingsProvider.cs) を実装しているクラスを見つけます(デフォルト実装は [`DefaultAotPreserveSettingsProvider`](/src/Editor/AotPreserve/DefaultAotPreserveSettingsProvider.cs) を参照。[`AotPreserveSettingsProviderResolver`](/src/Editor/AotPreserve/AotPreserveSettingsProviderResolver.cs) によって解決されます)。
2. `PreserveTypes` / `WrapTypes` / `PreserveGenericTypes` / `PreserveMembers` を返す前に `null` を除外します。
3. 生成と検証を再実行します。

### 3. 残留している古いファイルをクリーンアップする

`Generated file is stale: <パス>` が表示される場合は、通常、前回の生成で出力されたファイルですが、今回の構成では不要になったものです。生成メニューを直接再実行してください——[`GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L80-L84) はまず `Directory.Delete(GeneratedDirectory, true)` を実行してから再構築します。

`Assets/Generated/AotPreserve/` 配下のファイルは手動で変更しないでください——これらは生成成果物であり、次回の生成時に上書きされます。

## 検証

修復後、CI またはローカル環境で以下のいずれかの方法で合格を確認します:

- コードエントリ:

```csharp
using GameFrameX.Editor;
AotPreserveValidationRunner.ValidateGeneratedFiles(); // 例外がスローされなければ合格
```

実装については [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27) を参照してください:内部で `AotPreserveGenerator.ValidateGeneratedFiles()` を呼び出し、すべてのエラーを改行で連結して `InvalidOperationException` をスローします。

- ジェネレーターの検証エントリを直接呼び出す:

```csharp
var errors = AotPreserveGenerator.ValidateGeneratedFiles();
// errors.Length == 0 で合格
```

返される配列が 0 の場合は、すべての生成ファイルが齐全しており、構成と一致していることを意味します。0 ではない場合、配列内の各文字列が独立したエラーとなるため、上記の診断表に従って一つずつ処理してください。
