# 启动 UI 不显示或卡住怎么办

当你在启动流程里传入的 `IStartupUIHandler` 实现没有显示进度、提示文本,或卡在某一步不动时,通常是因为 handler 没被注入 FSM、没实现接口方法,或实现里阻塞了主线程。本页给出排查路径与修复方法。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 整个启动过程看不到任何 UI | `IStartupUIHandler` 未注入 FSM BlackBoard | 在调用 `StartupRunner` 时把 handler 实例传给启动参数 |
| UI 显示出来,但提示文本/进度一直是空的 | handler 的 `SetTipText` / `SetProgress` 未真正刷新到 UI 控件 | 在实现里把参数同步给可见的 Text/Slider 组件 |
| 启动在某个 procedure 卡住,UI 不动 | handler 实现里做了阻塞操作或未在主线程访问 UI | 切回主线程刷新(`UnitySynchronizationContext`),不要在 `SetProgress` 里 await/Thread.Sleep |
| 失败时 UI 不显示错误信息 | handler 抛了异常,导致 `?.SetTipText` 后链路中断 | 在 handler 内部 try/catch,或检查 `CompleteFailure` 调用栈 |
| 启动结束后 UI 没销毁 | 未实现 `Dispose()` 或 `Dispose()` 没真正销毁 GameObject | 在 `Dispose()` 里 `Destroy(gameObject)` 并清空引用 |

## 修复步骤

### 1. 确认 handler 已注入 FSM

启动流程把 `IStartupUIHandler` 存入 FSM BlackBoard,key 固定为 `"__startup_ui_handler__"`。所有 procedure 通过 `StartupProcedureUtility.GetUIHandler` 读取,读取到 `null` 时代码会走 `?.SetTipText(...)`,UI 就完全不会触发。

```csharp
public const string StartupUIHandler = "__startup_ui_handler__";
```

Source: [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs#L17)

```csharp
public static IStartupUIHandler GetUIHandler(IFsm<IProcedureManager> procedureOwner)
{
    return procedureOwner.GetData<VarObject>(BlackBoardKeys.StartupUIHandler).Value as IStartupUIHandler;
}
```

Source: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L46-L49)

**修复**:把 handler 实例作为启动参数传给 `StartupRunner.RunAsync(options)`,由它写入 BlackBoard。如果直接绕过 Runner 自己造 FSM,记得 `fsm.SetData(BlackBoardKeys.StartupUIHandler, new VarObject() { Value = handler })`。

### 2. 确认接口方法都已实现

`IStartupUIHandler` 一共 4 个方法,启动流程会调用其中 3 个。漏实现任何一个,UI 行为就不完整。

```csharp
public interface IStartupUIHandler
{
    void SetTipText(string text);
    void SetProgress(float progress, string sizeInfo);
    void SetProgressUpdateFinish();
    void Dispose();
}
```

Source: [IStartupUIHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/UI/IStartupUIHandler.cs)

**修复**:实现全部 4 个方法。`SetProgress(progress, sizeInfo)` 的 `progress` 是 `0~1` 浮点,`sizeInfo` 是形如 `"5.2MB / 100MB"` 的字符串,直接展示即可。

### 3. 检查是否在主线程刷新 UI

启动流程的 procedure 默认在主线程推进,但如果你在 `IStartupUIHandler` 实现里把刷新动作扔到后台线程/异步任务,Unity 会在访问 `Text`/`Slider` 时抛异常或静默失败,看起来像"卡住"。

**修复**:
- `SetTipText` / `SetProgress` 内只做 `text.text = ...`、`slider.value = ...`,不要 `await`。
- 真的需要异步加载资源,使用 `UniTask.RunOnThreadPool` 后通过 `UniTask.SwitchToMainThread()` 回到主线程再赋值。
- 在 handler 入口 `try/catch`,避免实现里的异常中断后续 procedure。

### 4. 失败信息没显示

启动失败时,框架会调一次 `SetTipText(errorMessage)` 把错误推到 UI:

```csharp
public static void CompleteFailure(IFsm<IProcedureManager> procedureOwner, string procedureName, string failedUrl, string errorMessage)
{
    var result = StartupResult.Fail(procedureName, failedUrl, errorMessage);
    GetUIHandler(procedureOwner)?.SetTipText(errorMessage);
    ...
}
```

Source: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L162-L168)

**修复**:在 UI 上保留一个常驻的"提示文本"节点,确保 `SetTipText` 写入后能立即被玩家看到;同时订阅 `StartupFailedEventArgs` 把失败原因写到日志或上报。

### 5. 启动完成后 UI 不销毁

`IProcedureManager` 完成启动后会调 `handler.Dispose()`。如果 handler 内部持有一个 `GameObject`(常见做法),需要在 `Dispose()` 里真正销毁它,否则下一次启动会叠出多个 UI。

**修复**:
```csharp
public void Dispose()
{
    if (gameObject != null) UnityEngine.Object.Destroy(gameObject);
}
```

## 验证

1. 临时在 handler 构造时 `Debug.Log("UIHandler created");`,确认它确实被传给 Runner 并进入 FSM。
2. 在 `SetTipText` / `SetProgress` 内 `Debug.Log` 输入参数,验证 procedure 真的有调到。
3. 主动抛一次异常让 `CompleteFailure` 触发,看 UI 是否显示出错误文本。
4. 启动成功后观察场景,确认旧 UI GameObject 已销毁,下一次启动 UI 是新建的。
