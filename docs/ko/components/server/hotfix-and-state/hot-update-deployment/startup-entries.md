# 엔트리 포인트별 핫픽스 로딩(Main / Entry / GateWay / Heart)

GameFrameX.Server는 "엔트리 포인트별 핫픽스 로딩"을 네 개의 partial 클래스 파일로 나누며, 모두 `AppStartUpBase`를 상속하고 `AppStartUpHotfixGame`을 partial 컨테이너로 사용합니다: `Main`은 비즈니스 서버의 네트워크 계층과 메시지 분배를 담당하고, `Entry`는 최초 시작/리로드 및 전역 컴포넌트 활성화를 담당하며, `GateWay`는 게이트웨이 연결과 하트비트를 담당하고, `Heart`는 클라이언트 하트비트 응답을 담당합니다.

## 엔트리 포인트 파일 개요

| 엔트리 포인트 partial | 파일 | 트리거 시나리오 |
|---|---|---|
| Main | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs` | `AppStartUpHotfixGame.StartAsync()`, `RunServer()`, `OnConnected`/`OnDisconnected`/`PackageHandler`, `StopAsync` |
| Entry | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs` | `OnLoadSuccess(setting, reload)`(최초 시작 및 리로드), `Stop(message)` |
| GateWay | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs` | 게이트웨이 서버와의 TCP 연결 설정, 연결 끊김 시 재연결, 하트비트 유지, 메시지 업링크 |
| Heart | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByHeart.cs` | 클라이언트 하트비트 메시지 `ReqHeartBeat`의 파싱과 `NotifyHeartBeat` 응답 |

네 개의 파일은 C# `partial class` 메커니즘을 통해 동일한 하나의 `AppStartUpHotfixGame`으로 합쳐지며, 별도의 등록이 필요 없습니다.

## 시작 순서(코드에서 직접 대조 가능)

1. `Entry.OnLoadSuccess(AppSetting setting, bool reload)` — `AppSetting`을 받아 핫 리로드 여부를 판정합니다.
   - `reload == true`: `ActorManager.ClearAgent()` 호출 후 바로 반환합니다.
   - `reload == false`: 전체 최초 시작 프로세스를 진행합니다.
2. `Entry.Init(setting.ServerType, setting)` — 프레임워크 기반 인프라를 초기화합니다.
3. `Entry.RunServer()` → `Main.StartAsync()` — SuperSocket 서버를 시작하고, 압축/압축 해제, HTTP 핸들러, 모든 TcpHandler를 구성합니다.
4. `Entry`가 `QuartzTimer.Start()`, `GlobalTimer.Start()`, `ComponentRegister.ActiveGlobalComponents()`를 시작합니다.
5. `Main.PackageHandler`가 클라이언트 메시지를 수신하면: 하트비트 메시지는 `Heart.ReplyHeartBeat`로 넘기고, 비즈니스 메시지는 `HotfixManager.GetTcpHandler`를 통해 분배합니다.

출처: [AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L37-L60) 및 [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L43-L65).

## 각 엔트리 포인트의 역할

### Main — 네트워크 계층과 메시지 분배

`StartAsync()`는 네트워크 서비스를 시작하고 HTTP 핸들러를 장착합니다:

```csharp
public override async Task StartAsync()
{
    await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
        new DefaultMessageCompressHandler(),
        new DefaultMessageDecompressHandler(),
        HotfixManager.GetListHttpHandler(),
        HotfixManager.GetHttpHandler);
}
```

출처: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L45-L52)

`RunServer(bool reload = false)`는 매번 `ConfigComponent.Instance.LoadConfig()`를 실행합니다; `reload`일 때는 Actor를 정리한 뒤 바로 반환하고, 그렇지 않으면 `StartAsync()`로 진입합니다.

`PackageHandler`에서는 먼저 `NetworkMessagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat`인 메시지를 `ReplyHeartBeat`로 분기하고, 나머지는 `MessageId`에 따라 분배합니다:

```csharp
if (messagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat)
{
    ReplyHeartBeat(netWorkChannel, (MessageObject)messagePackage.DeserializeMessageObject());
    return;
}
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
```

출처: [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L113-L135)

`OnConnected`에서는 `SessionManager.Count()`와 `Setting.MaxClientCount`를 통해 최대 동시 접속자 수를 제어하며, `OnDisconnected`는 `RoomComponentAgent.MarkPlayerDisconnected`를 호출합니다.

### Entry — 최초 시작 / 리로드

`OnLoadSuccess`는 핫픽스 프레임워크가 호출하는 엔트리 포인트로, "핫 리로드"와 "최초 시작"을 구분합니다:

```csharp
public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
{
    if (reload)
    {
        ActorManager.ClearAgent();
        return true;
    }

    Init(setting.ServerType, setting);
    await RunServer();
    await QuartzTimer.Start();
    GlobalTimer.Start();
    await ComponentRegister.ActiveGlobalComponents();
    return true;
}
```

출처: [AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L39-L54)

`Stop(message)`는 핫픽스 프레임워크의 정지 콜백으로, `Main.StopAsync(message)`로 바로 전달됩니다.

### GateWay — 게이트웨이와의 통신

파일에는 `AsyncTcpSession _gatewayClient`, `_gateWayReconnectionTimer`, `_gateWayHeartBeatTimer`가 포함되어 있으며, 연결이 끊기면 `_gateWayReconnectionTimer`가 재연결을 트리거하고, 메시지를 성공적으로 전달할 때마다 `_gateWayHeartBeatTimer.Reset()`이 하트비트 타이머를 재설정합니다.

`SendToGatewayMessage`는 게이트웨이로 업링크하는 통합 채널입니다: 연결이 설정되어 있으면 `_gatewayClient.TrySend(span)`를 호출하여 메시지를 전달합니다.

### Heart — 클라이언트 하트비트 응답

`PackageHandler`는 하트비트를 `ReplyHeartBeat`에 넘기며, partial 파일 안에서 `NotifyHeartBeat`를 생성해 채널로 다시 기록합니다:

```csharp
if (messageObject is ReqHeartBeat req)
{
    netWorkChannel.UpdateReceiveMessageTime();
    NotifyHeartBeat notifyHeartBeat = MessageObjectPoolHelper.Get<NotifyHeartBeat>();
    notifyHeartBeat.Timestamp = TimerHelper.UnixTimeMilliseconds();
    notifyHeartBeat.UniqueId = req.UniqueId;
    await netWorkChannel.WriteAsync(notifyHeartBeat);
}
```

출처: [AppStartUpHotfixGameByHeart.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByHeart.cs#L43-L52)

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 핫 리로드 후 이전 비즈니스 로직이 계속 실행됨 | `OnLoadSuccess`의 `reload == true` 분기에서 `ActorManager.ClearAgent()` 호출 누락 | 기존 `ClearAgent()` 호출을 유지하여 이전 Actor 캐시가 확실히 비워지도록 함 |
| 클라이언트가 계속 연결이 끊기고 `NotifyServerFullyLoaded` 이후 강제로 연결 해제됨 | `Setting.MaxClientCount` 제한이 적용되어 새 연결이 상한을 초과함 | `appsettings.json`에서 `MaxClientCount`를 높이거나 비정상 연결을 점검 |
| `找不到[xxx][yyy]对应的handler` 로그 | `messagePackage.Header.MessageId`가 `HotfixManager`에 등록되지 않음 | 해당 핫픽스 모듈의 Handler 등록 테이블에 `MessageId`를 추가 |

## 배경(선택)

네 개의 파일을 "단계"가 아닌 "역할" 기준으로 나눈 것은, Main의 네트워크 계층과 Entry의 라이프사이클이 각각 하나의 partial을 차지하게 하고, GateWay / Heart 같은 횡단 관심사도 별도 파일로 독립시키기 위함입니다. 모든 partial이 하나의 `AppStartUpHotfixGame`으로 병합된 후에는 기반 클래스 `AppStartUpBase`와 `IHotfixBridge`가 컴파일 시점에 하나의 타입 엔트리만 필요로 하므로, 핫픽스 프레임워크와의 결합 범위가 줄어듭니다.
