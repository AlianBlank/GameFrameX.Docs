# 常見錯誤快速參考

使用 `GameFrameX.Procedure` 模組時，幾乎所有執行階段例外都源自同一個根本原因——**在 `ProcedureManager.Initialize` 之前呼叫任何流程操作**。以下是高頻錯誤清單；只要看到徵狀，就能定位修正方式。

## 快速診斷

| 徵狀（例外/日誌文字） | 原因 | 修正方式 |
|------|------|------|
| `GameFrameworkException: You must initialize procedure first.`（存取 `CurrentProcedure`、`CurrentProcedureTime`、`StartProcedure`、`HasProcedure`、`GetProcedure` 時） | 業務程式碼在 `ProcedureManager.Initialize` 之前呼叫流程 API，導致內部的 `m_ProcedureFsm` 為 `null` | 在掛載 `ProcedureComponent` 的 GameObject 上設定 `Available Procedure Type Names` 與 `Entrance Procedure Type Name`，待元件完成 `Initialize` 之後再呼叫 |
| `GameFrameworkException: Procedures is invalid.`（在 `Initialize` 中拋出） | 傳遞給 `Initialize` 的 `procedures` 陣列為 `null` 或長度為 0 | 至少傳入一個 `ProcedureBase` 子類別實例 |
| `Log.Fatal("Procedure manager is invalid.")`（元件 `Awake` 期間） | 框架未註冊 `IProcedureManager` 實作；`GameFrameworkEntry.GetModule<IProcedureManager>()` 回傳 `null` | 確保包含流程模組的組件已正確打包進專案且未被裁剪；通常會由 `GameFrameXAutoComponent` 自動註冊——若被裁剪，請檢查 asmdef |
| `Log.Warning("Available procedure type names is empty. Procedure auto start skipped.")` | `ProcedureComponent.m_AvailableProcedureTypeNames` 欄位為空或未填寫 | 在 Inspector 中至少加入一個流程型別完整名稱（例如 `MyGame.Procedure.LaunchProcedure, MyGame`） |
| `Log.Error("Can not find procedure type '{0}'.")` | `m_AvailableProcedureTypeNames` 中的型別完整名稱拼寫錯誤、命名空間錯誤，或目標組件未載入 | 使用 `Utility.Assembly.GetType` 可解析的完整限定名稱，並確認該型別確實存在於已載入的組件中 |
| `Log.Error("Can not create procedure instance '{0}'.")` | 型別可以找到，但不是 `ProcedureBase` 的子類別，或缺少無參數建構函式 | 讓自訂流程繼承自 `ProcedureBase` 並保留 `public` 無參數建構函式 |
| `Log.Error("Entrance procedure is invalid.")` | `m_EntranceProcedureTypeName` 與 `m_AvailableProcedureTypeNames` 中的任何項目都不相符 | 入口流程型別名稱必須與 `Available Procedure Type Names` 中的某一項完全相符 |
| 執行階段出現 `Already exist FSM.`（與 `StartupRunner` 一起使用時） | 舊有的自動初始化與新的 `StartupRunner` 同時啟用，導致 `Initialize` 被呼叫兩次 | 將 `ProcedureComponent.m_UseStartupRunner` 設為 `true`，讓 `ApplicationStartupEntry + StartupRunner.Run` 接管初始化 |

## 修正步驟

### 1. 在初始化前呼叫流程 API

所有拋出位置都在 `ProcedureManager` 內針對 `m_ProcedureFsm` 的空值檢查分支中，例如 `StartProcedure<T>()`：

```csharp
[Preserve]
public void StartProcedure<T>() where T : ProcedureBase
{
    if (m_ProcedureFsm == null)
    {
        throw new GameFrameworkException("You must initialize procedure first.");
    }

    m_ProcedureFsm.Start<T>();
}
```

來源：[ProcedureManager.cs#L148-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L148-L156)

`CurrentProcedure`、`CurrentProcedureTime`、`HasProcedure` 與 `GetProcedure` 都會經過相同的空值檢查邏輯：

```csharp
if (m_ProcedureFsm == null)
{
    throw new GameFrameworkException("You must initialize procedure first.");
}
```

來源：[ProcedureManager.cs#L72-L78](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L72-L78)

修正方式：掛載 `ProcedureComponent` 後，讓它在 `Start` 協程內完成 `Initialize` 與 `StartProcedure`：

```csharp
m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);

yield return new WaitForEndOfFrame();

m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
```

來源：[ProcedureComponent.cs#L164-L168](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

在業務端，只有場景載入完成且 `CurrentProcedure` 回傳非 `null` 值之後，才開始切換流程。

### 2. `Initialize` 接收到空的流程陣列

```csharp
public void Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)
{
    GameFrameworkGuard.NotNull(fsmManager, nameof(fsmManager));
    GameFrameworkGuard.NotNull(procedures, nameof(procedures));
    if (procedures.Length <= 0)
    {
        throw new GameFrameworkException("Procedures is invalid.");
    }

    m_FsmManager = fsmManager;
    m_ProcedureFsm = m_FsmManager.CreateFsm(this, procedures);
}
```

來源：[ProcedureManager.cs#L130-L141](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)

修正方式：為 `procedures` 至少傳入 1 個項目，且它們必須繼承自 `ProcedureBase`：

```csharp
public abstract class ProcedureBase : FsmState<IProcedureManager>
{
    // 子類別覆寫 OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy
}
```

來源：[ProcedureBase.cs#L38-L98](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

### 3. Inspector 中的流程型別名稱不正確

`ProcedureComponent.Start` 依型別名稱透過反射建立實例；任何失敗都會中斷啟動：

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

來源：[ProcedureComponent.cs#L135-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L156)

修正方式：以 `Namespace.ClassName, AssemblyName` 格式填寫 Inspector，並確保入口名稱出現在可用清單中；否則會落入 `Entrance procedure is invalid.` 錯誤：

```csharp
if (m_EntranceProcedure == null)
{
    Log.Error("Entrance procedure is invalid.");
    yield break;
}
```

來源：[ProcedureComponent.cs#L158-L162](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L158-L162)

### 4. 使用 `StartupRunner` 時重複初始化

在新的啟動管線下，元件需要讓出初始化權限：

```csharp
[SerializeField] private bool m_UseStartupRunner = false;
...
if (m_UseStartupRunner)
{
    // ApplicationStartupEntry + StartupRunner.Run 接管 Initialize 與 StartProcedure；
    // 此元件僅在 Awake 中處理 IProcedureManager 的註冊，避免與新進入點重複 Initialize 而觸發 Already exist FSM。
    yield break;
}
```

來源：[ProcedureComponent.cs#L65-L127](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L65-L127)

修正方式：啟用 `StartupRunner` 時，勾選 `Use Startup Runner`，讓 `ApplicationStartupEntry` 統一處理排程。

## 驗證

按以下順序確認各項；若有任何一項失敗，請回頭參考上表對應的資料列：

1. 啟動後，Console 中沒有 `GameFrameworkException: You must initialize procedure first.`，且 `ProcedureComponent.CurrentProcedure` 不為 `null`。
2. 切換場景或重新登入後，日誌中沒有重複出現 `Already exist FSM.`。
3. 在自訂 `ProcedureBase` 子類別的 `OnEnter` 中加入 `Debug.Log`，確認它確實被呼叫且未被例外吞掉。
4. `m_AvailableProcedureTypeNames` 至少有 1 個項目，且 `m_EntranceProcedureTypeName` 與其中一項完全相符。
