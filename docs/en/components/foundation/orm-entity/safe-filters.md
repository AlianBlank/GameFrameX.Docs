# How to Use the Soft Delete/Enable Filter Interfaces

After enabling `ISafeDeletedFilter` and `ISafeEnabledFilter` on an entity, the framework automatically provides soft delete fields (`IsDeleted`, `DeleteTime`, `DeleteId`) and enable/disable fields (`IsEnabled`) in the base entity `EntityBase`, achieving unified management of "logical deletion" and "enabled status".

## Prerequisites

- Import the namespace `GameFrameX.Foundation.Orm.Entity` (provides `EntityBase`, `EntityBase<TKey>`).
- Import the namespace `GameFrameX.Foundation.Orm.Entity.Filter` (provides filter interfaces).
- Entity classes inherit from `EntityBase` or `EntityBase<TKey>`. The framework base class already implements `ISafeDeletedFilter` and `ISafeEnabledFilter` by default, so no manual implementation is needed.

## Steps

1. Have your business entity inherit from `EntityBase` to get both the soft delete and enable filter fields.

```csharp
using GameFrameX.Foundation.Orm.Entity;
using GameFrameX.Foundation.Orm.Entity.Filter;

public class SysUser : EntityBase
{
    public string UserName { get; set; } = string.Empty;
}
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L46-L46)

2. The entity class automatically includes the following soft delete fields, ready for direct use:

| Field | Type | Default Value | Description |
|------|------|--------|------|
| `IsDeleted` | `bool?` | `false` | Soft delete flag: `true` means deleted, `false` means not deleted, `null` means not set (treated as not deleted) |
| `DeleteTime` | `long?` | `null` | Deletion time (timestamp) |
| `DeleteId` | `long?` | `null` | Deleter Id |

```csharp
// Mark the user as deleted
sysUser.IsDeleted = true;
sysUser.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
sysUser.DeleteId = currentUserId;
```

Source: [EntityBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityBase.cs#L120-L138)

3. The enable filter (`ISafeEnabledFilter`) is also implemented by the base class `EntityBase`, and is used to record the entity's enabled status.

4. When querying in the repository layer, use the filter field `IsDeleted = false` to exclude deleted data, implementing soft delete queries:

```csharp
// Example: query the list of non-deleted users
var users = await dbContext.Set<SysUser>()
    .Where(u => u.IsDeleted == false || u.IsDeleted == null)
    .ToListAsync();
```

5. For delete operations, do not perform physical deletion; instead, modify `IsDeleted`:

```csharp
public void SoftDelete(SysUser user, long operatorId)
{
    user.IsDeleted = true;
    user.DeleteTime = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
    user.DeleteId = operatorId;
}
```

## Common Variants

- Use the generic primary key base class `EntityBase<TKey>` (e.g., `EntityBase<long>`), which still automatically includes the soft delete and enable fields.
- To customize the primary key type, simply inherit from `EntityBase<TKey>` and specify the generic parameter:

```csharp
public class SysRole : EntityBase<long>
{
    public string RoleName { get; set; } = string.Empty;
}
```

- If you only need select filtering without audit fields, you can inherit from `EntitySelectBase` (which additionally implements `ISelectFilter` on top of `EntityBase`), and it still includes soft delete fields such as `IsDeleted`.

Source: [EntitySelectBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntitySelectBase.cs#L45-L45)

## Common Mistakes

- Misusing physical deletion: Calling the ORM's `Remove`/`Delete` on entities inheriting from `EntityBase` bypasses the soft delete flag, causing the data to be truly removed. Please consistently use `IsDeleted = true` instead.
- Omitting the `IsDeleted` filter in queries: Without `Where(u => u.IsDeleted == false)`, deleted records will also be returned. Please enforce the filter condition in the repository layer.
- Assuming `IsDeleted` is `bool` instead of `bool?`: The framework uses a nullable boolean, defaulting to `false`. New entities that are not explicitly assigned a value will be treated as "not deleted"; manually setting `null` is also treated as not deleted.
