# コールバックが例外をスローした場合の対処法

タイマーコールバック内部で例外(null参照や`InvalidOperationException`など)がスローされた場合、デフォルトの動作では例外がそのまま上方へ伝播し、`Update`内の後続コールバックの実行が中断される可能性があります。`TimerManager.CatchCallbackExceptions`を`true`に設定すると、マネージャーが例外をキャッチして警告ログに格下げし、残りのタイマーは影響を受けずに動作を続けられます。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| コールバックが例外をスローした後、コンソールに赤いエラーが直接表示され、後続のタイマーコールバックが実行されない | `TimerManager.CatchCallbackExceptions`がデフォルト値`false`のままで、例外がそのまま上方へ伝播する | 下記の手順に従って`true`に設定し、その後コールバック自体のロジックを調査する |
| コンソールに`Timer callback error > {例外メッセージ}`という警告が表示される | `CatchCallbackExceptions = true`のときにキャッチされた例外が`Debug.LogWarning`で出力される | 警告の内容がコールバック内で実際に発生した例外そのものであり、これに基づいてコールバックのコードを特定できる |
| テスト中に例外が`TargetInvocationException`の形でスローされる | リフレクション経由で`Update`を呼び出す際、未キャッチの例外が`TargetInvocationException`にラップされる | 正常な伝播動作であり、タイマーの欠陥ではない。キャッチを有効にするか、コールバックを修正すればよい |

## 修正手順

### 1. コールバック例外のキャッチを有効にする

ゲームの初期化段階(コールバックを設定する前)に静的なスイッチをオンにします:

```csharp
TimerManager.CatchCallbackExceptions = true;
```

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L204-L206)

このスイッチのデフォルト値は`false`です:

```csharp
/// <summary>
/// コールバック例外をキャッチするかどうか
/// </summary>
public static bool CatchCallbackExceptions = false;
```

出典: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L53-L56)

### 2. キャッチ後の動作を理解する

有効にすると、マネージャーはコールバックの実行時に`try/catch`で呼び出しをラップし、例外をキャッチしても警告を出力するだけで、ループを中断しません:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

出典: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L190)

注意：すべてのコールバックはロック外でまとめて実行されるため、1つのコールバックの例外が握りつぶされても、**同一フレーム内の残りの実行待ちコールバックは引き続き正常に発火します**。

### 3. テストで両モードの動作を再現する

リポジトリのユニットテストはスイッチの両状態での違いを示しており、そのままトラブルシュートの参考として利用できます:

```csharp
[Test]
public void CatchCallbackExceptions_On_DoesNotThrow_OnException()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = true;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.DoesNotThrow(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Should catch exception silently");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}

[Test]
public void CatchCallbackExceptions_Off_ThrowsToCaller()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = false;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.Throws<TargetInvocationException>(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Exception should propagate through reflection as TargetInvocationException");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}
```

出典: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L286-L318)

## 検証

- スイッチを有効にした後、例外をスローするコールバック(例:`_ => throw new InvalidOperationException("test")`)を作成してタイマーを登録します。
- `Update`を駆動して時間を進め、未処理の例外がスローされず、コンソールに`Timer callback error > test`形式の黄色い警告のみが表示されることを確認します。
- 同一フレームに登録された他のタイマーコールバックが期待どおりに実行されることを確認します。
- 本番環境では、最終的には例外キャッチをオフにして**コールバック自体を修正**することが常に推奨されます。スイッチは障害の切り分けや、単一のコールバックがフレーム全体を壊すのを防ぐためだけに使用してください。

## 背景

コールバックはすべてロック外の`_pendingCallbacks`キューで一括実行されます。これは、ビジネスロジックのコールバックが長時間ロックを占有して他のスレッドをブロックするのを避けるためです。すべてのコールバックが直列に実行されるため、未キャッチの例外が1つでも発生するとコールバックのバッチ全体が終了してしまいます。そのため、フレームワークはフォールトトレランスのセーフティネットとしてこのグローバルスイッチを提供しています。
