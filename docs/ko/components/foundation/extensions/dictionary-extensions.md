# 사전 확장을 사용하는 방법(양방향 사전, 해제 가능한 사전)

이 페이지에서는 `GameFrameX.Foundation.Extensions` 네임스페이스의 세 가지 사전 컨테이너와 확장 메서드 사용법을 소개합니다: `BidirectionalDictionary<TKey, TValue>`(키↔값 양방향 매핑), `DisposableDictionary<TKey, TValue>` / `DisposableConcurrentDictionary<TKey, TValue>`(값 자동 해제), 그리고 `IDictionaryExtensions`의 `AddOrUpdate` / `TryAdd` 등 확장 메서드.读完后你能在自己的类型上以最小改动用上双向映射和托管资源回收.读完后 자신의 타입에서 최소한의 수정으로 양방향 매핑과 관리 리소스回收를 사용할 수 있습니다.

## 사전 조건

- .NET 프로젝트가 `GameFrameX.Foundation.Extensions` 어셈블리를 참조해야 합니다.
- 소스 위치: `GameFrameX.Foundation.Extensions/`. 네임스페이스는 `GameFrameX.Foundation.Extensions`입니다.
- 모든 해제 가능한 사전의 `TValue`는 반드시 `System.IDisposable`을 구현해야 합니다.

## 작업 단계

### 1. `BidirectionalDictionary`를 사용하여 키↔값 양방향 매핑 수행

양방향 사전은 내부에 두 개의 `Dictionary`를 사용하여 정방향과 역방향 매핑을 동시에 유지하며, 어느 쪽에서든 조회는 O(1)입니다. **키와 값이 모두 고유해야 합니다**.

```csharp
using GameFrameX.Foundation.Extensions;

var map = new BidirectionalDictionary<int, string>(initialCapacity: 16);

map.TryAdd(1, "Alice");
map.TryAdd(2, "Bob");

// 정방향: 키 -> 값
if (map.TryGetValue(1, out var name))
{
    Console.WriteLine(name); // Alice
}

// 역방향: 값 -> 키
if (map.TryGetKey("Bob", out var id))
{
    Console.WriteLine(id); // 2
}
```

키-값 비교자를 사용자 정의하고, 양방향에서 기존 매핑을 업데이트할 수 있습니다:

```csharp
var map = new BidirectionalDictionary<string, int>(
    initialCapacity: 8,
    keyComparer: StringComparer.OrdinalIgnoreCase,
    valueComparer: null);

// 키로 값을 업데이트(역방향 매핑도 동기화)
map.TryUpdateByKey("score", 99);

// 값으로 키를 업데이트(정방향 매핑도 동기화)
map.TryUpdateByValue(99, "Score");
```

출처: [BidirectionalDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/BidirectionalDictionary.cs#L47-L204)

자주 사용하는 API:

| 메서드 | 역할 |
|------|------|
| `TryAdd(key, value)` | 키와 값이 모두 존재하지 않을 때만 추가하며, 실패 시 `false` 반환 |
| `TryGetValue(key, out value)` | 정방향 조회 |
| `TryGetKey(value, out key)` | 역방향 조회 |
| `TryUpdateByKey(key, newValue)` | 키를 통해 값 변경, 역방향 동기화 |
| `TryUpdateByValue(value, newKey)` | 값을 통해 키 변경, 정방향 동기화 |
| `ContainsKey` / `ContainsValue` | 존재 여부 확인 |
| `Clear()` | 양방향 매핑 비우기 |

### 2. `DisposableDictionary`를 사용하여 값이 컨테이너와 함께 해제되도록 하기

`DisposableDictionary<TKey, TValue>`는 `NullableDictionary<TKey, TValue>`를 상속하며, `TValue : IDisposable` 제약 조건을 가집니다. `Dispose()` 시 null이 아닌 모든 값에 대해 하나씩 `Dispose()`를 호출하고, 예외는 `DisposalErrorHandler`에 전달하여 하나의 값 해제 실패가 후속 값의 해제를 차단하지 않도록 합니다.

```csharp
using GameFrameX.Foundation.Extensions;

public sealed class MyHandle : IDisposable
{
    public void Dispose() { /* 기본 리소스 해제 */ }
}

// using 블록이 끝나면 모든 값이 Dispose됩니다
using var cache = new DisposableDictionary<string, MyHandle>
{
    DisposalErrorHandler = (value, ex) =>
        Console.WriteLine($"해제 실패: {ex.Message}")
};

cache.Add("session-1", new MyHandle());
cache["session-2"] = new MyHandle();

// 이후 이미 해제된 객체에 대해 Add/Remove/할당/열거를 수행하면 ObjectDisposedException이 발생합니다
```

출처: [DisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DisposableDictionary.cs#L11-L219)

스레드 안전 시나리오에서는 `DisposableConcurrentDictionary<TKey, TValue>`를 대신 사용하세요. API 사용법은 동일합니다.

### 3. `IDictionaryExtensions`의 `AddOrUpdate` 사용

확장 메서드는 `IDictionary<TKey, TValue>`, `NullableDictionary<TKey, TValue>`, `NullableConcurrentDictionary<TKey, TValue>` 모두에 대해 오버로드를 제공합니다.

```csharp
using GameFrameX.Foundation.Extensions;

var dict = new Dictionary<int, string>();
dict.AddOrUpdate(new Dictionary<int, string>
{
    [1] = "one",
    [2] = "two",
});

// 단일 AddOrUpdate: 키가 없으면 추가, 있으면 팩토리 함수가 반환한 새 값으로 업데이트
var current = dict.AddOrUpdate(
    key: 3,
    addValue: "three",
    updateValueFactory: (k, old) => old + "!");

// 팩토리 없는 오버로드: 키가 있으면 고정 값으로 직접 덮어쓰기
dict.AddOrUpdate(key: 1, addValue: "ONE", updateValue: "uno");
```

출처: [IDictionaryExtensions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/IDictionaryExtensions.cs#L55-L207)

## 일반적인 변형

| 시나리오 | 권장 타입 | 이유 |
|------|----------|------|
| 값으로 키를 역방향 조회해야 함 | `BidirectionalDictionary<TKey, TValue>` | O(1) 역방향 조회 |
| 값이 관리 리소스이며 일괄 해제가 필요함 | `DisposableDictionary<TKey, TValue>` | `Dispose` 시 모든 값을 자동 해제 |
| 멀티스레드 환경에서 사용하며 값 해제가 필요함 | `DisposableConcurrentDictionary<TKey, TValue>` | 동시성 안전 및 자동 해제 |
| null 키를 허용하거나 fallback 기본값이 필요함 | `NullableDictionary<TKey, TValue>` | null 키와 `FallbackValue` 지원 |
| 일반 Dictionary에 upsert 의미론을 적용하고 싶음 | `IDictionary.AddOrUpdate` | 새 컬렉션으로 대체하지 않음 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `BidirectionalDictionary.TryAdd`가 항상 `false` 반환 | 키 또는 값이 다른 쪽 매핑에 이미 존재함 | 먼저 `Remove` 후 `TryAdd`를 호출하거나 `TryUpdateByKey` / `TryUpdateByValue` 사용 |
| `DisposableDictionary`가 `Dispose` 후 `ObjectDisposedException` 발생 | 해제 후 `Add` / `Remove` / 인덱서 set / `GetEnumerator`를 호출함 | `Dispose` 후 더 이상 접근하지 않도록 하거나, 접근이 끝날 때까지 수명을 연장 |
| `NullableDictionary(int)` 호출 모호성 | `TValue`가 `int`일 때 컴파일러가 `capacity`와 `fallbackValue`를 구분할 수 없음 | `NullableDictionary<int, int>.WithCapacity(n)` 사용 |
| `AddOrUpdate`가 `ArgumentNullException` 발생 | `self`, `key` 또는 `updateValueFactory`가 null임 | 명시적으로 non-null 인자를 전달 |

## 배경 지식 (선택 사항)

`BidirectionalDictionary`는 두 개의 `Dictionary`를 서로 미러링하여 O(1) 양방향 조회를 달성하며, 대가로 삽입 시 양쪽에 쓰기를 수행하고 실패 시 롤백해야 합니다. `DisposableDictionary`는 `IDisposable`의 해제 의미론을 사전 의미론과 결합하며, `DisposalErrorHandler`를 통해 단일 값의 해제 실패를 흐름을 중단시키는 대신 콜백으로 전환하여 일부 리소스가 실패하더라도 나머지 리소스가 계속 해제되도록 합니다.
