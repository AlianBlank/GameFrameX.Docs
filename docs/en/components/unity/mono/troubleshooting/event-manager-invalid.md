# What to Do When the Log Reports "Event manager is invalid."

When `MonoComponent` cannot retrieve an `EventComponent` instance from `GameEntry` after starting in the scene, it will print `Event manager is invalid.` in the log and abort the subsequent initialization process, causing all event subscription/publishing in the Mono module to fail.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Event manager is invalid.` reported at startup | No `EventComponent` attached in the startup scene | Add an `EventComponent` to the `GameFramework` node in the startup scene, see Fix Step 1 below |
| `Event manager is invalid.` reported at startup | `EventComponent` is attached in the startup scene, but the script execution order of `MonoComponent` is earlier than `EventComponent.Awake` | In Project Settings, adjust the Script Execution Order of `MonoComponent` to after `Default`, see Fix Step 2 |
| `Event manager is invalid.` reported at startup | A duplicate `EventComponent` is attached to the same node, causing the instance stored in `GameEntry` to be overwritten/released | Remove the extra `EventComponent` and ensure only one instance exists on the framework entry node |

## Fix Steps

### 1. Add EventComponent to the Startup Scene

`MonoComponent.Start()` retrieves the event component via `GameEntry.GetComponent<EventComponent>()`; only components attached to the GameFramework startup object can be indexed by `GameEntry`.

1. Open the startup scene in the project (for example, `Assets/GameFrameX/Launch/Launch.unity`).
2. Select the `GameFramework` root GameObject.
3. Inspector → Add Component → search for and add `GameFrameX.Event.EventComponent`.
4. Re-run; the log should no longer show `Event manager is invalid.`.

Reference error location:

```csharp
// Source: Runtime/Mono/MonoComponent.cs
private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76)

### 2. Check Script Execution Order

`MonoComponent.Start()` runs after all components' `Awake`, but if the project has customized the Script Execution Order to prioritize `MonoComponent`, it may obtain an `EventComponent` that has not yet been registered to `GameEntry`.

1. Edit → Project Settings → Script Execution Order.
2. Drag `MonoComponent` after `Default Time`, or explicitly specify an Order value later than `EventComponent`.
3. Re-run to verify.

### 3. Check for Duplicate Attachments or Scene Residuals

If multiple `EventComponent`s are manually added to the same GameObject, or if an old `EventComponent` is left over in an old scene while the new code instantiates it on another object, `GameEntry.GetComponent` will return a null reference due to duplicate types.

1. Search for `t:EventComponent` in the Hierarchy and confirm there is only one instance.
2. Delete the extra instances and run again.

## Verification

1. Run the scene, open the Console, search for `Event manager is invalid.`; it should no longer appear.
2. Attach a test script to the object where `MonoComponent` resides, and in `Start` call `GameEntry.GetComponent<EventComponent>()` and assert it is non-null.
3. Walk through a complete event subscription/publishing flow (`Subscribe` → `Fire` → `Unsubscribe`) to confirm that events can reach listeners normally.

## Background (Optional)

`MonoComponent` caches the reference to `EventComponent` in the `m_EventComponent` field, which is reused in subsequent lifecycle callbacks such as `OnApplicationFocus`. Once the reference cannot be obtained during the `Start` phase, the field remains null, and subsequent event-related initialization will be silently skipped—this is also why the error only appears once, but the functionality stops working.
