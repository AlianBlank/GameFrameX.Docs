# How to Skip Remote Requests for WebGL Standalone or Backend-less Scenarios

For WebGL standalone builds or scenarios without a business backend, use `StartupOptions.SkipRemoteStartupRequests` or `EPlayMode.OfflinePlayMode` to skip remote requests for global info, App version, asset bundle versions, and so on, going straight into local asset initialization. This prevents the startup from getting stuck waiting on the network or failing with errors.

## Prerequisites

- The `StartupOptions` asset has been created (`Assets > Create > GameFrameX > Startup Options`).
- The asset play mode (`GamePlayMode`) is not `EditorSimulateMode`; otherwise, global info is skipped by default in the editor.
- The `StartupOptions` asset has been injected into the startup flow (via `StartupRunner` / the bootstrap component's `SetOptions` or default loading).

## Steps

### Option A: Enable Only the Skip Switch (Recommended for WebGL Standalone)

Select the `StartupOptions` asset in the Inspector, expand the **Network** category, and check **Skip Remote Startup Requests**.

```csharp
// Runtime/Startup/StartupOptions.cs
[Tooltip("Whether to skip remote startup requests (global info, App version, asset bundle versions). Enable this for backend-less scenarios such as WebGL standalone to go straight into local asset initialization.")]
public bool SkipRemoteStartupRequests = false;
```

Source: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31)

You can also toggle it at runtime from code:

```csharp
using GameFrameX.Startup.Runtime;

var options = Resources.Load<StartupOptions>("StartupOptions");
options.SkipRemoteStartupRequests = true;
```

The startup flow reads this switch in `ProcedureGetGlobalInfoState.OnEnter`; if it is `true`, remote requests are skipped and the flow goes directly into `ProcedurePatchInit`:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var options = StartupProcedureUtility.GetOptions(procedureOwner);
if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

Source: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L42-L48)

### Option B: Switch the Play Mode to Offline

Set `StartupOptions.GamePlayMode` to `EPlayMode.OfflinePlayMode` (YooAsset's offline mode, which uses locally built assets). `ProcedureGetGlobalInfoState` matches OfflinePlayMode before checking the skip switch:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

Source: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L35-L40)

In Offline mode, the subsequent Patch flow is also short-circuited: `ProcedurePatchInit`, `ProcedureUpdateManifest`, and `ProcedureUpdateStaticVersion` all handle `OfflinePlayMode` with a direct skip, so no remote manifest is requested.

## Common Variants

| Scenario | Recommended Approach | Key Switch |
|----------|----------|----------|
| WebGL standalone (with YooAsset assets but no version service) | `SkipRemoteStartupRequests = true`, keep `GamePlayMode` in standalone mode | SkipRemoteStartupRequests |
| Fully offline WebGL (local build output) | `GamePlayMode = OfflinePlayMode` | GamePlayMode |
| In-editor debugging without a backend | `GamePlayMode = EditorSimulateMode` | GamePlayMode |

The three modes are matched in the following order in `ProcedureGetGlobalInfoState.OnEnter`: EditorSimulateMode → OfflinePlayMode → `SkipRemoteStartupRequests` → actual remote requests.

## Common Mistakes

- **Only checked Skip while GamePlayMode is still an online mode**: The skip switch only skips remote requests during the "startup phase"; if the Patch flow points to a remote CDN and there is no local manifest, the game will keep waiting for network responses at the `ProcedureUpdateManifest` / `ProcedureUpdateStaticVersion` stage.
- **Local assets not prepared in Offline mode**: OfflinePlayMode assumes YooAsset already has a complete set of assets prepared in `StreamingAssets`; otherwise, subsequent loading will fail with errors like "package not found" or "manifest is empty".
- **Runtime changes to the SO not taking effect**: Runtime modifications to `StartupOptions` must be completed before the startup flow begins (before component initialization); if assigned after the FSM has started, you need to reload the scene or call `StartupRunner.Restart()`.
- **WebGL cross-origin policy not configured**: Even for a standalone build, WebGL still needs to respond to CORS correctly; if you want to keep an "optional" remote URL, make sure to configure `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` on the web server or use a server-side proxy.

## Verification

Launch the game; you should see one of the following logs in the Console (depending on the option chosen), and you should not see network-waiting prompts like "Loading... (x/y)":

- `Skip remote startup requests option enabled, skip remote startup requests.`
- `Offline play mode, skip remote startup requests.`
- `Editor simulate mode, skip global info request.`

The flow should then go directly into local asset initialization (opening UI assets, loading the local manifest, etc.) and finally enter the gameplay scene.

## Background (Optional)

By default, the startup flow executes in the order `ProcedureGetGlobalInfoState → ProcedureGetAppVersionInfoState → ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState → ProcedurePatchInit`, and the first three nodes all send HTTP requests to the remote. WebGL standalone or demo scenarios often have no available backend, so intercepting at the earliest node (`ProcedureGetGlobalInfoState`) avoids a chain of pointless failed retries and shortens the time to first screen.

For the overall architecture of the startup flow, see the procedure source code under the `Runtime/Procedures/Startup` directory.
