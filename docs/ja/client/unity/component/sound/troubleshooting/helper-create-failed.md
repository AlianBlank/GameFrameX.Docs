# Can not create sound helper / sound group helper の対処方法

ゲーム実行時にエディターまたはランタイムログに `Can not create sound helper.` または `Can not create sound group helper.` が出力される場合、通常は `SoundComponent` が初期化段階で Inspector に設定された型名/カスタムコンポーネントから対応するヘルパーを作成できなかったことを意味します。以下では、症状ごとに原因を特定し、修正するための完全な手順を示します。

## クイック診断

| エラーログ原文 | 直接的な原因 | 修正入口 |
|--------------|----------|----------|
| `Can not create sound helper.` | `Helper.CreateHelper(m_SoundHelperTypeName, m_CustomSoundHelper)` が `null` を返す | 下記の「Sound Helper の修正」を参照 |
| `Can not create sound group helper.` | `Helper.CreateHelper(m_SoundGroupHelperTypeName, m_CustomSoundGroupHelper, SoundGroupCount)` が `null` を返す | 下記の「Sound Group Helper の修正」を参照 |
| 同時に `Sound manager is invalid.` も出力される | `ISoundManager` モジュールが未登録 | エントリーモジュールの初期化を確認、詳細は下記の説明を参照 |

エラーのスロー箇所は `SoundComponent.cs` にあります(行番号は `main` ブランチ基準):

```csharp
SoundHelperBase soundHelper = Helper.CreateHelper(m_SoundHelperTypeName, m_CustomSoundHelper);
if (soundHelper == null)
{
    Log.Error("Can not create sound helper.");
    return;
}
```

```csharp
SoundGroupHelperBase soundGroupHelper = Helper.CreateHelper(m_SoundGroupHelperTypeName, m_CustomSoundGroupHelper, SoundGroupCount);
```

## 修正手順

### 1. Scene 上に SoundComponent が存在し、スクリプトが正しくロードされていることを確認

`SoundComponent` はフレームワークのエントリーであり、シーン内にこのコンポーネントをアタッチした GameObject が必ず存在する必要があります。コンポーネントが存在しない場合や `Awake` が実行されていない場合、そもそも上記の 2 つのコードは呼び出されず、これら 2 つのログも出力されません——この場合はまずエントリーと `ISoundManager` の登録フローを確認してください。

### 2. Sound Helper の修正(対応ログ `Can not create sound helper.`)

デフォルトの型名設定(`SoundComponent.cs`):

```csharp
[SerializeField] private string m_SoundHelperTypeName = "GameFrameX.Sound.Runtime.DefaultSoundHelper";
[SerializeField] private SoundHelperBase m_CustomSoundHelper = null;
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L69-L71)

以下の順序で確認します:

1. **カスタマイズしていない場合**:`m_CustomSoundHelper` を `null` のままにし、`m_SoundHelperTypeName` は `GameFrameX.Sound.Runtime.DefaultSoundHelper` と等しく、かつそのデフォルト実装がビルド対象のアセンブリに存在する必要があります。
2. **カスタマイズしている場合**:`SoundHelperBase` を継承したコンポーネントを `m_CustomSoundHelper` にドラッグして設定します(リフレクションより優先されます);`m_SoundHelperTypeName` にはそのカスタムクラスの**完全な型名**(名前空間を含む)を入力する必要があります。
3. **型名の誤り / アセンブリのストリッピング**:IL2CPP やコードストリッピングによりリフレクションが失敗します。該当する型を `link.xml` に追加して保持するか、アセンブリをストリッピング対象外の範囲に配置してください。

### 3. Sound Group Helper の修正(対応ログ `Can not create sound group helper.`)

デフォルトの型名設定:

```csharp
[SerializeField] private string m_SoundGroupHelperTypeName = "GameFrameX.Sound.Runtime.DefaultSoundGroupHelper";
[SerializeField] private SoundGroupHelperBase m_CustomSoundGroupHelper = null;
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L73-L75)

確認のポイント:

1. `m_SoundGroups` には少なくとも 1 つの有効なエントリが必要です。そうでない場合 `AddSoundGroup` は呼び出されず、当然このログも出力されません——このログが出力されている場合、`AddSoundGroup` がすでに helper 作成失敗の分岐まで到達していることを意味します。
2. カスタマイズしている場合、型名は `SoundGroupHelperBase` を継承したサブクラスの完全な名前と一致させる必要があります。
3. デフォルト実装の `DefaultSoundGroupHelper` も、helper インターフェースが未登録の場合に失敗することがあります——フレームワークのデフォルト型名を優先的に保持し、デフォルト実装が解決可能であることを確認してください。

### 4. リソースと AudioMixer の確認

`EnsureAudioMixer()` は helper 作成の前に実行されます:

```csharp
m_AudioMixer = Resources.Load<AudioMixer>(DefaultAudioMixerResourceName);
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L140-L151)

mixer の欠如自体が helper 作成を失敗させることは**ありません**(`Default audio mixer ... is missing.` 警告が出力されるだけです)が、カスタム helper が `AudioMixerGroup` に強く依存している場合は、Resources 下に対応する mixer リソースが存在することを確認してください。

## よくあるバリエーション

- **同時に `Can not create sound agent helper.` も出力される**:`m_SoundAgentHelperTypeName` / `m_CustomSoundAgentHelper` の設定ミスです。確認方法は上記と同じです。トリガーとなるのは `AddSoundAgentHelper` です([SoundComponent.cs#L730-L735](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L730-L735) を参照)。
- **ランタイムエラーはないが音が聞こえない**:helper は作成済みですが、その後 `Can not find sound 'X'` がスローされます——`SoundManager.cs#L617` の `GameFrameworkException` を参照し、リソースパスを確認する必要があります。

## 検証

1. `Library/` をクリアしてから Play モードに再入し、ログに `Can not create sound helper.` / `Can not create sound group helper.` が表示されなくなったことを確認します。
2. `SoundComponent` の Inspector で `Add Sound Group` をクリックするか、コードで `AddSoundGroup("Music", ...)` を呼び出します。`true` が返されれば、helper 作成のフローが正常であることを示します。
3. `PlaySound` を呼び出して存在するリソースを再生し、`OnPlaySoundSuccess` がトリガーされるかを確認します(対応するイベントは [PlaySoundSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/EventArgs/PlaySoundSuccessEventArgs.cs) で定義されています)。
