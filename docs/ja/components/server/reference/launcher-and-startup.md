# ランチャーとスタートアップ項目リファレンス(Program.cs / AppStartUpGame)

このページはゲームサーバーの起動エントリおよびそのデフォルトスタートアップ項目の設定を調べるためのものです。`Program.cs` はプロセスエントリとログ戦略を定義し、`AppStartUpGame` はゲームサーバーのスタートアップ項目であり、Actor 制限、データベース、コンポーネント、ホットアップデートモジュールを順に初期化し、メインループに入る役割を担います。

## 起動エントリ(Program.cs)

起動エントリは `GameFrameX.Launcher` アセンブリにあり、`Main` の内部では 3 つのことだけを行います:コンパイルモードに応じてログオプションを設定する、フレームワークエントリ `GameApp.Entry` を呼び出す、コールバックを渡してキャッシュとプロトコルの初期化を完了する。

```csharp
internal static class Program
{
    private static async Task Main(string[] args)
    {
#if DEBUG
        LogOptions.Default.IsConsole = true;
#endif
        await GameApp.Entry(args, () =>
        {
            CacheStateTypeManager.Init();
            MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
        }, LogAction);
    }

    private static void LogAction(LogOptions options)
    {
#if DEBUG
        options.IsConsole = true;
#else
        options.IsConsole = false;
#endif
    }
}
```

## スタートアップ項目(AppStartUpGame)

`AppStartUpGame` は特性 `[StartUpTag(GameServerConst.Game.Name)]` で `Game` タイプのサーバーであることを示し、`AppStartUpBase` を継承している。`StartAsync` が起動のメインラインであり、`Init` は必要に応じてデフォルトの `AppSetting` を構築するために使われる。

```csharp
[StartUpTag(GameServerConst.Game.Name)]
internal sealed class AppStartUpGame : AppStartUpBase
{
    public override async Task StartAsync() { /* 下記のステップ順序を参照 */ }

    protected override void Init()
    {
        if (Setting == null)
        {
            Setting = new AppSetting { /* デフォルト値は下記の表を参照 */ };
        }
        base.Init();
    }
}
```

### StartAsync の起動順序

| ステップ | アクション | 主要呼び出し |
|------|------|----------|
| 1 | `hotfix` ディレクトリを準備 | `Directory.Exists` / `Directory.CreateDirectory` |
| 2 | Actor 制限を初期化 | `ActorLimit.Init(ActorLimit.RuleType.None)` |
| 3 | データベースサービスを起動 | `GameDb.Init<MongoDbService>(...)`、失敗時は `InvalidOperationException("数据库服务启动失败")` をスロー |
| 4 | コンポーネントを登録 | `ComponentRegister.Init(typeof(AppsHandler).Assembly)` |
| 5 | ホットアップデートモジュールを読み込み | `HotfixManager.LoadHotfixModule(Setting)` |
| 6 | ランタイムが起動済みとマーク | `GameAppRuntime.MarkStarted(...)` |
| 7 | 終了シグナルを待機 | `await AppExitToken` |
| 8 | ホットアップデートを停止 | `await HotfixManager.Stop(exitMessage)` |

例外パス:任意のステップがスローされた場合は `catch (Exception e)` で捕捉され、ログを記録した後ステップ 8 でホットアップデートを停止してからプロセスが終了する。

### デフォルトの AppSetting フィールド

`Init()` は `Setting == null` のときにデフォルトの `AppSetting` を構築し、フィールドの意味とデフォルト値は以下の通り:

| フィールド | 型/値 | デフォルト値 | 意味 |
|------|-----------|--------|------|
| `ServerId` | `int` | `GameServerConst.Game.Id` | サーバー一意 ID |
| `ServerType` | `string` | `GameServerConst.Game.Name` | サーバータイプ名(`[StartUpTag]` に対応) |
| `IsEnableTcp` | `bool` | `true` | TCP を有効化 |
| `InnerPort` | `int` | `29100` | 内部 TCP ポート |
| `MetricsPort` | `int` | `29090` | 監視ポート |
| `IsEnableHttp` | `bool` | `true` | HTTP を有効化 |
| `HttpPort` | `int` | `28080` | HTTP ポート |
| `IsEnableWebSocket` | `bool` | `true` | WebSocket を有効化 |
| `WsPort` | `int` | `29110` | WebSocket ポート |
| `HttpIsDevelopment` | `bool` | `true` | HTTP 開発モード |
| `MinModuleId` | `int` | `10` | モジュールメッセージ ID の下限 |
| `MaxModuleId` | `int` | `9999` | モジュールメッセージ ID の上限 |
| `TagName` | `string` | `"GameFrameX"` | ログ/トレースタグ |
| `DataBaseUrl` | `string` | リポジトリ内蔵の MongoDB 接続文字列 | Mongo 接続 URL |
| `DataBaseName` | `string` | `"gameframex"` | Mongo データベース名 |

## よくあるエラー

| 現象 | 発生条件 | 調査方向 |
|------|----------|----------|
| 起動時に `InvalidOperationException: 数据库服务启动失败` をスロー | `GameDb.Init<MongoDbService>` が `false` を返す | `DataBaseUrl` / `DataBaseName` が接続可能か、また Mongo ネットワークの到達性を確認する |
| Release パッケージでコンソールにログが表示されない | `DEBUG` 以外のコンパイル | `Program.LogAction` が `IsConsole` を強制的に `false` に設定するため、これは想定動作 |
| ホットアップデートディレクトリが存在しない | `hotfix` が存在しない | 起動フローで自動的に `CreateDirectory` されるため、手動で作成する必要はない。権限不足の場合は例外がスローされる |
| `AppSetting` が外部で上書きされる | 呼び出し側が `Init()` 前にすでに代入済み | `Init()` は `Setting == null` のときのみデフォルト値を埋めるため、先に注入してから起動すると渡した値が優先される |
