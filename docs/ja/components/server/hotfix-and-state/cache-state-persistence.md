# CacheState + BsonClassMap を使用したエンティティの永続化

`CacheStateTypeManager.Init()` を通じて `ICacheState` を実装するすべてのエンティティクラスを一括スキャンし、フレームワークはそれらを同時に `BsonClassMap` に登録します。これにより、以降の MongoDB シリアライズで直接読み書きが可能になり、各エンティティに手動でマッピングを記述する必要がなくなります。

## 前提条件

- `GameFrameX.Apps` アセンブリ（`BsonClassMapHelper`、`CacheStateTypeManager` を含む）を参照していること。
- エンティティクラスは `ICacheState` インターフェイスを実装している必要があります（キャッシュ可能/永続化可能なエンティティとしてマークされる）。
- プロセス起動時に `Init()` を 1 回呼び出していること。通常は `Program.Main` の中で他のコンポーネントの初期化より前に配置します。

## 操作手順

1. **エンティティに `ICacheState` インターフェイスを実装させる**

   永続化（典型的には MongoDB への書き込み）が必要なエンティティはすべて `ICacheState` を実装しなければなりません。フレームワークはそのインターフェイスを実装した型のみをスキャンします。

2. **起動エントリで `CacheStateTypeManager.Init()` を 1 回呼び出す**

   `Init()` は `AppsHandler` が存在するアセンブリをスキャンし、`ICacheState` を実装するすべての型をフィルタリングし、`XxHash32(型の完全名)` を id として内部の `ConcurrentDictionary<long, Type>` に書き込み、さらに各型に対して `BsonClassMapHelper.RegisterClass` を呼び出して MongoDB ドライバに登録します。

   ```csharp
   // GameFrameX.Launcher/Program.cs
   static void Main(string[] args)
   {
       CacheStateTypeManager.Init();
       MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
       // ... その他の起動ロジック
   }
   ```

   Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L10-L20)

3. **`Init()` の内部では 2 つの BSON Convention が同時に登録される**

   - `DictionaryRepresentationConvention`:`IDictionary` の BSON 表現を `ArrayOfDocuments` に固定し、ドライババージョンによってデフォルト動作が異なる問題を回避します。
   - `EmptyContainerSerializeMethodConvention`:`List<T>`、`Dictionary<,>`、`ConcurrentDictionary<,>` などのコンテナについて、要素数が 0 の場合はシリアライズをスキップし、空フィールドの書き込みを削減します。

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   ConventionRegistry.Register(nameof(DictionaryRepresentationConvention),
                               new ConventionPack { new DictionaryRepresentationConvention(), }, _ => true);

   ConventionRegistry.Register(nameof(EmptyContainerSerializeMethodConvention),
                               new ConventionPack { new EmptyContainerSerializeMethodConvention(), }, _ => true);
   ```

   Source: [GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L102-L111)

4. **各エンティティに対して `BsonClassMap.AutoMap` を実行し、余分なフィールドを無視する**

   フレームワークは型の完全名の `XxHash32` をディクショナリの主キーとして使用し、異なるプロセス/再起動後でも `GetType(id)` で安定して元の型を取り戻せるようにしています。`AutoMap` + `SetIgnoreExtraElements(true)` により、新しいフィールドが追加されても既存データのデシリアライズが失敗しなくなります。

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   public static void RegisterClass(Type t)
   {
       var bsonClassMap = new BsonClassMap(t);
       bsonClassMap.AutoMap();
       bsonClassMap.SetIgnoreExtraElements(true);
       bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
       BsonClassMap.RegisterClassMap(bsonClassMap);
   }
   ```

   Source: [GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

5. **実行時に `GetType(id)` で型を逆引きし、多態デシリアライズを完了する**

   BSON ドキュメントに型 id のみが格納されている場合、`CacheStateTypeManager.GetType(id)` を呼び出すことで具体的な `Type` を取得し、それを MongoDB ドライバに渡してオブジェクトを構築します。

   ```csharp
   // GameFrameX.Apps/CacheStateTypeManager.cs
   public static Type GetType(long id)
   {
       HashMap.TryGetValue(id, out var value);
       return value;
   }
   ```

   Source: [GameFrameX.Apps/CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L41-L45)

## よくあるバリエーション

- **`ICacheState` を実装するエンティティクラスを新規追加した場合**:プロセスを再起動するだけでよく、手動で登録 API を呼び出す必要はありません。`Init()` が自動的にスキャンします。
- **エンティティが `AppsHandler` のアセンブリに存在しない場合**:`BsonClassMapHelper.RegisterAllClass(assembly)` を呼び出し、対象アセンブリを登録フローに手動で渡すことで追加スキャンを完了します。
- **空コンテナのシリアライズスキップを一時的に無効化したい場合**:`EmptyContainerSerializeMethodConvention` を登録しないか、自分のエンティティで個別に `SetShouldSerializeMethod` を設定してください。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動時に `BsonClassMap already registered` が出る | 同じ型が重複登録されている | `RegisterClass` 内に `IsClassMapRegistered` ガードがあります。`Init()` 以外で `RegisterClassMap` を手動で呼び出していないか確認してください |
| デシリアライズ時にフィールドが失われる、または `Element ... does not match any field` が出る | `SetIgnoreExtraElements` を呼び出していない | `BsonClassMapHelper.RegisterClass` の経路を通っているか確認してください |
| `CacheStateTypeManager.GetType(id)` が `null` を返す | エンティティクラスが `ICacheState` を実装しておらず、`Init` 時に登録されていない | エンティティに `ICacheState` インターフェイスを追加し、プロセスを再起動してください |
| `Dictionary` が BSON で `Document` として表現される | `DictionaryRepresentationConvention` が登録されていない | `Init()` がすべての MongoDB 操作の前に実行されていることを確認してください |

## 背景

フレームワークが `XxHash32(type.ToString())` を型 id として採用しているのは、id を安定させ .NET の型完全名と一対一で対応させつつ、占有空間を小さくするためです。`SetIgnoreExtraElementsIsInherited` を有効にしているのは、サブクラスが継承したフィールドを新規追加する際に既存のドキュメントを破壊しないためです。Convention のグローバル登録には `_ => true` を使用しており、明示的にマッピングされていないすべてのクラスに適用されるため、業務側の認知負荷を軽減します。
