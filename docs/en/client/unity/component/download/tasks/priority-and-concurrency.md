# Setting Download Priority and Concurrent Agent Count

This task page explains how to set the **priority** for download tasks, and how to adjust the component's **download agent (concurrent coroutine) count**, thereby controlling the upper limit of tasks downloading simultaneously.

## Prerequisites

- `GameFrameX.Download.Runtime` has been imported and `DownloadComponent` has been attached to the scene (menu: GameFrameX / Download).
- You know the local save path (`downloadPath`) and remote address (`downloadUri`) of the target download task.

## Steps

### 1. Set the Priority of a Single Task

`DownloadComponent.AddDownload` provides multiple overloads that accept a `priority` parameter (`int`; the higher the value, the higher the priority; the default is `0`). The two most commonly used:

```csharp
using GameFrameX.Download.Runtime;

// Specify priority only
int serialId = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, priority: 100);

// Specify both tag and priority
int serialId2 = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, tag: "asset-bundle", priority: 100);
```

### 2. Configure the Concurrent Agent Count

Concurrent download capability is determined by `DownloadComponent.m_DownloadAgentHelperCount`, which defaults to `3`, meaning at most 3 download coroutines are working at the same time. You can adjust it in the Inspector, or extend it at runtime through code:

- **Inspector**: After attaching the component, modify the `Download Agent Helper Count` field directly in the Inspector (corresponds to `m_DownloadAgentHelperCount`). When the component's `Start()` runs, it creates all agents at once based on this value.
- **Runtime addition**: If you need to increase it dynamically, you can continue calling the component's internal entry points or customize extensions based on `DownloadAgentHelperBase` (see [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs)).

Source code (agent creation):

```csharp
// Runtime/Download/DownloadComponent.cs
[SerializeField] private int m_DownloadAgentHelperCount = 3;
...
private void Start()
{
    ...
    for (int i = 0; i < m_DownloadAgentHelperCount; i++)
    {
        AddDownloadAgentHelper(i);
    }
}
```

## Common Variants

- **Critical resources first**: Use a higher `priority` for first-screen resources (e.g., `100`), and `0` or negative values for background pre-downloads.
- **Pause and resume**: Use `DownloadComponent.Paused = true/false` to temporarily stop dispatching new tasks; running agents will not be interrupted.
- **Changes to `m_DownloadAgentHelperCount` taking effect immediately**: Only when the value increases will all agents be pre-created at component startup; decreasing it while running will not destroy existing agents — you need custom logic to reclaim them.

## Common Mistakes

- **Confusing "concurrent coroutines" with "concurrent threads"**: Download agents are `UnityWebRequest` coroutines; the value only controls the number of simultaneous HTTP requests and has nothing to do with threads. Do not set it too high on restricted platforms such as WebGL.
- **Tasks stuck and never starting**: If `WaitingTaskCount` keeps growing while `FreeAgentCount` stays at 0, it means the concurrency is too low or the tasks' network is slow — you can increase `m_DownloadAgentHelperCount` accordingly.
- **Assuming an unspecified priority means high priority**: `DefaultPriority = 0`; if other tasks are given negative values, your "default" tasks will actually be queued behind them.

## Background (Optional)

The download manager internally uses `TaskPool<DownloadTask>` to schedule tasks ([DownloadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs)). Higher-priority tasks get idle agents first, thereby controlling the order in which network egress is occupied.
