# What to Do When Installation and Dependency Resolution Fail

When you encounter dependency errors, version conflicts, or unable-to-find-package issues while importing `com.gameframex.unity.coroutine` through Unity's Package Manager or `manifest.json`, use the diagnostic table on this page to troubleshoot and fix the issue.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Package 'com.gameframex.unity.coroutine' could not be found` or the corresponding version cannot be found | `manifest.json` does not have `scopedRegistries` configured, and Unity only searches the npm registry by default for packages starting with `com.gameframex.*` | Add `scopedRegistries` at the top of `manifest.json` and specify the GameFrameX source. See fix step 1 below |
| Error `Unable to resolve dependency 'com.gameframex.unity: 2.5.1'` | Missing runtime dependency `com.gameframex.unity`, or the version is inconsistent with other installed GameFrameX packages | First, independently upgrade or roll back to the `com.gameframex.unity` version required by the package (see dependencies in `package.json`) |
| Unity reports `Requires Unity 2019.4 or higher` | The current project's Unity version is lower than the minimum version required by the package | Upgrade Unity to 2019.4 or higher, or use an older version of the package that matches your version |
| Package downloaded but compilation reports `The type or namespace 'GameFrameX' could not be found` | Unity cache not refreshed, dependencies not actually written to `Library/PackageCache` | Delete `Library/PackageCache` and `Packages/packages-lock.json`, then restart Unity |
| Installing via Git URL reports `Could not read Username for 'https://github.com'` | Network cannot access GitHub or private repository authentication failed | Switch to the UPM scoped registry method, or configure SSH/HTTPS credentials for this repository |
| Package imported successfully but `CoroutineComponent` reports `[DisallowMultipleComponent]` conflict | The same GameObject already has `CoroutineComponent` attached | Remove redundant components of the same type, keeping only one |

## Fix Steps

### 1. Configure scopedRegistries (GameFrameX Official Source)

Open `Packages/manifest.json` in the project's root directory and confirm the `scopedRegistries` section exists. The example below is from the repository README installation instructions:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.coroutine": "1.0.3"
  }
}
```

Source: [README.zh-CN.md#Quick Start](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L40-L77)

Key points:
- `scopes` must be `com.gameframex`; otherwise, `com.gameframex.*` packages will not be resolved by this source. Unity will fall back to the default npm source and report "package not found" directly.
- `url` is the UPM registry address, not a regular web page; if your network cannot access it, continue reading the "Git URL Alternative Method" section below.

### 2. Check Runtime Dependency `com.gameframex.unity`

`com.gameframex.unity.coroutine` itself depends on `com.gameframex.unity`, declared in the repository's [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L22-L24):

```json
"dependencies": {
  "com.gameframex.unity": "2.5.1"
}
```

If the project already explicitly declares a lower version of `com.gameframex.unity`, Unity will refuse to resolve it. How to handle:
- Upgrade `com.gameframex.unity` to `2.5.1` or a compatible higher version; or
- Remove the explicit declaration and let `com.gameframex.unity.coroutine` automatically bring the correct version.

### 3. Unity Version Must Be ≥ 2019.4

The `unity` field in `package.json` is `2019.4`:

```json
"version": "1.2.0",
"unity": "2019.4",
```

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/package.json#L6-L7)

Projects below 2019.4 will directly display "Requires Unity 2019.4 or higher" in Package Manager, and you must first upgrade the Unity editor.

### 4. Clear Cache and Restart When Necessary

When the package is clearly declared but compilation errors occur or the namespace is missing, do this first:
1. Close Unity.
2. Delete the `Library/PackageCache` folder in the project directory.
3. Delete `Packages/packages-lock.json`.
4. Reopen Unity and let it re-fetch according to `manifest.json`.

### 5. Alternative Installation Methods (When GitHub is Unreachable)

- Write the Git URL directly under `dependencies` in `manifest.json`:

```json
{
  "dependencies": {
    "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/README.zh-CN.md#L70-L75)

- Or in Unity's `Package Manager` → `Add package from git URL…`, paste `https://github.com/gameframex/com.gameframex.unity.coroutine.git`.
- Or download the repository and place it directly in the project's `Packages/` directory.

## Verification

After fixing, confirm using any of the following methods:

1. Check the Unity Console: errors such as "could not be found / Unable to resolve dependency" no longer appear.
2. In the Inspector, `Add Component` can find `Coroutine Component`, and it can be successfully added to a GameObject.
3. Use a minimal code snippet to verify the namespace is available:

```csharp
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(yourEnumerator);
```
