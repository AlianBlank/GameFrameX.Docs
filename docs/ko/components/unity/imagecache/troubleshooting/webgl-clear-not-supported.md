# WebGL 플랫폼에서 RemoveCache / ClearCache가 작동하지 않을 때 해결 방법

WebGL 플랫폼에서 `RemoveCache(url)` 또는 `ClearCache()`를 호출하면 실제로는 어떤 캐시도 정리되지 않고 경고 로그만 출력됩니다. 이는 WebGL 런타임이 로컬 파일 시스템에 직접 접근할 수 없기 때문입니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `RemoveCache(url)` 호출 후에도 이미지가 여전히 히트됨 | WebGL에서 이미지는 브라우저 HTTP 캐시에 의해 관리되며, 프레임워크 내에 삭제할 로컬 사본이 없음 | 브라우저 측 캐시 제어를 사용하세요 (URL에 버전 번호 추가 / Cache-Control) |
| `ClearCache()` 호출 후에도 디스크 공간이 변하지 않음 | WebGL에는 "디스크 캐시"라는 개념이 없으며, 메서드가 즉시 반환됨 | 브라우저 측에서 정리하세요. WebGL이 아닌 플랫폼에서만 `ClearCache`를 호출하세요 |
| Console에서 `ImageCache: RemoveCache is not supported on WebGL.` 또는 `ImageCache: ClearCache is not supported on WebGL.` 경고가 표시됨 | WebGL 플랫폼 코드 분기에서 해당 작업이 명시적으로 비활성화됨 | 호출 전에 `#if !UNITY_WEBGL`로 감싸거나, 브라우저 측 방식을 사용하세요 |

## 수정 단계

### 1. 플랫폼 분기가预期的 동작인지 확인

소스 코드에서 `RemoveCache`와 `ClearCache`는 모두 `#if UNITY_WEBGL`을 통해 직접 경고를 반환합니다:

```csharp
public void RemoveCache(string url)
{
    if (string.IsNullOrEmpty(url)) { return; }

#if UNITY_WEBGL
    Log.Warning("ImageCache: RemoveCache is not supported on WebGL.");
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    if (FileHelper.IsExists(cachePath))
    {
        FileHelper.Delete(cachePath);
    }
#endif
}

public void ClearCache()
{
#if UNITY_WEBGL
    Log.Warning("ImageCache: ClearCache is not supported on WebGL.");
#else
    if (!Directory.Exists(_config.CachePath)) { return; }
    FileHelper.CleanDirectory(_config.CachePath);
#endif
}
```

Source: [ImageCacheManager.cs#L196-L236](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L196-L236)

즉, WebGL에서 `RemoveCache` / `ClearCache`는 **"失效"가 아니라 소스 코드 레벨에서 비활성화된 것**입니다. "로컬 캐시 정리" 시도는 모두 효과가 없습니다.

### 2. WebGL에서 두 메서드 호출 피하기

코드가 크로스 플랫폼으로 실행된다면, 조건부 컴파일로 호출을 건너뛰면 됩니다:

```csharp
public void OnUserClickClearCache()
{
#if !UNITY_WEBGL
    GameFrameX.ImageCache.Runtime.ImageCacheManager.Instance.ClearCache();
#endif
}
```

### 3. WebGL에서 "동등한" 정리 수행

WebGL 플랫폼에서 이미지는 `UnityWebRequestTexture`로 로드되며 캐시는 브라우저가 관리합니다. "이전 이미지"가 더 이상 히트되지 않도록 하려면, 일반적인 방법은 다음과 같습니다:

1. **URL에 버전 번호나 해시 추가**: 리소스가 변경될 때마다 URL 쿼리 매개변수를 변경하세요 (예: `?v=2`). 브라우저가 이를 새 리소스 요청으로 처리합니다.
2. **서버에서 적절한 `Cache-Control` 헤더 반환**: 브라우저 측의 만료 시간을 제어합니다.
3. **브라우저 측 `Caching.ClearCache()` 호출 (브라우저 자체 저장소 정리 API)** — 이 컴포넌트는 이 경로를 처리하지 않습니다.

### 4. `IsCached` 동작도 함께 확인

WebGL에서 `IsCached(url)`은 항상 `false`를 반환합니다. 프레임워크 내부에 캐시 사본을 보유하지 않기 때문입니다. WebGL의 히트 상태를 판단하는 데 사용하지 마세요:

```csharp
public bool IsCached(string url)
{
    if (string.IsNullOrEmpty(url)) { return false; }

#if UNITY_WEBGL
    return false;
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    return FileHelper.IsExists(cachePath);
#endif
}
```

## 검증

- Editor 또는 Standalone 플랫폼에서 `ClearCache()` 호출 후, 캐시 디렉터리(`ImageCacheConfig.CachePath`)의 PNG 파일이 비워져야 합니다.
- WebGL 빌드에서 `ClearCache()` 호출 시, Console에 `ImageCache: ClearCache is not supported on WebGL.` 경고가 표시되어야 하며 IO 오류가 없어야 합니다 — 이는 예상 분기로 진입했음을 의미합니다.
- WebGL에서 수정 단계 3에 따라 URL 쿼리 매개변수를 변경한 후 다시 로드하여 브라우저가 새 리소스를 가져왔는지 확인합니다 (이전 이미지가 더 이상 히트되지 않음).

## 배경 지식 (선택 사항)

WebGL 샌드박스에는 진정한 "로컬 디스크"라는 개념이 없으며, `System.IO`는 해당 플랫폼에서 잘립니다. 따라서 `ImageCacheManager`는 WebGL 분기에서 직접 `UnityWebRequestTexture`를 사용하여 캐시를 브라우저에 위임합니다. 이와 연관된 `IsCached` / `RemoveCache` / `ClearCache`는 모두 정리 가능한 로컬 사본을 보유하지 않으므로, 모두 "false 반환 / 경고 출력"이라는 조기 종료 경로를 따릅니다.
