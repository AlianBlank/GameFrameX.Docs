# What to Do When Object Storage Upload Fails

When the build pipeline triggers `-IsUploadLogFile` or `-IsUploadAsset` but the logs/assets don't appear in the object storage bucket, follow the diagnostic table on this page to troubleshoot step by step.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Log shows `The type or namespace name 'ObjectStorageUploadManager' could not be found` | The project does not have the object storage module enabled | Install and enable the object storage component in the Package Manager corresponding to the `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` macro |
| No credentials passed on the command line, no upload behavior after execution | `-IsUploadLogFile` was omitted, or the corresponding macro is not enabled | See the "Switch Not Turned On" section below |
| Upload call throws 403 / SignatureDoesNotMatch | Credential mismatch or insufficient read/write permissions | See the "Credential or Permission Error" section below |
| Throws `NoSuchBucket` / `InvalidBucketName` | Bucket name misspelled or bucket was not created in the specified region | See the "Bucket Name or Endpoint Error" section below |
| Upload completed but file is not visible in the bucket | Endpoint region mismatch; file was uploaded to another region | See the "Region Mismatch" section below |
| Build process interrupted at the `BuildReady` stage | Uncaught exception thrown when calling `UploadFile` | See the "Exception Swallowed" section below |

## Fix Steps

### 1. Switch Not Turned On (Most Common)

The build script only invokes the upload when two conditions are met simultaneously: [`Builder.BuildReady.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L44-L49) wraps `#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE` with `if (_builderOptions.IsUploadLogFile)`. That is, even if you pass `-IsUploadLogFile`, if the project does not define the `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` macro, the code will be completely stripped out by the compiler, resulting in no output at runtime.

How to verify:

1. Confirm that the command line includes `-IsUploadLogFile` (no value required; see [`Builder.BuildParamsParse.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L94-L96)).
2. Confirm that `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` has been defined in the project's `Scripting Define Symbols`.
3. Confirm that the `GameFrameX.ObjectStorage` package has been installed via the Package Manager; otherwise the `ObjectStorageUploadManager` type cannot be found.

```text
-ExecuteMethod GameFrameX.Builder.Editor.Builder.BuildReady \
-IsUploadLogFile \
-ObjectStorageKey <your-key> \
-ObjectStorageSecret <your-secret> \
-ObjectStorageBucketName <your-bucket> \
-ObjectStorageEndPoint <your-endpoint>
```

See [`BuilderOptions.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40) for parameter definitions. All four object storage fields default to empty strings; missing any one will cause the SDK to throw an exception directly when making the request.

### 2. Credential or Permission Error

`ObjectStorageUploadManager.UploadFile` internally uses the passed Key/Secret to construct the signature. If characters are missing or extra spaces are added when copying the secret, or if the sub-account does not have `PutObject` permission for the bucket, it will directly throw `403 SignatureDoesNotMatch` or `AccessDenied`.

1. Re-copy the Key and Secret from the object storage console to avoid manual input.
2. Grant the sub-account read/write permissions for the bucket (the concept is consistent across Alibaba Cloud OSS, Tencent Cloud COS, and MinIO).
3. If using temporary STS credentials, confirm that `ObjectStorageKey/Secret` is the `AccessKeyId/SecretAccessKey` from the STS triplet, not the `SessionToken`.

### 3. Bucket Name or Endpoint Error

`ObjectStorageBucketName` must be the full name of the bucket in the console, and `ObjectStorageEndPoint` must be the public/internal network domain for the region where the bucket resides. When the two do not match, `NoSuchBucket` or `InvalidBucketName` will be thrown.

1. Log into the object storage console and verify the bucket name and its region.
2. Change `ObjectStorageEndPoint` to the Endpoint provided in the official documentation for that region (e.g., Alibaba Cloud East China 1: `oss-cn-hangzhou.aliyuncs.com`).
3. Trigger the build again and confirm that the uploaded log file is visible under `Object Storage → File Management` in the console.

### 4. Region Mismatch

The request succeeded, the console returned 200, but the file is not visible in the bucket—usually this happens because the Endpoint points to another region, and the file was uploaded to a same-named bucket of the "correct" bucket in another region (common in private cloud / cross-region replication scenarios).

1. Verify that `ObjectStorageEndPoint` exactly matches the Region where the bucket resides.
2. In the console's "Bucket List", filter by region and confirm that the target bucket exists in this region.

### 5. Exception Swallowed

If an exception occurs when `UploadFile` is called in `BuildReady`, by default it will interrupt the build pipeline, and the original exception stack trace thrown by `ObjectStorageUploadManager` will be visible in the logs. Paste the keywords from the first line of the stack trace into the corresponding row of the diagnostic table and follow steps 1-4 above.

If the exception is swallowed by an external Jenkins/CI script and the stack trace cannot be seen, you can temporarily append a line `Debug.Log($"Upload finished: {_builderOptions.LogFilePath}")` after `BuildReady` to verify whether the code actually entered the upload branch.

## Verification

1. Run the build again, ensuring the command line includes `-IsUploadLogFile` and all four object storage parameters.
2. In the corresponding bucket of the object storage console, sort by upload time and confirm that the log file appears.
3. Download that log file; its content should include the `BuildReady Start` / `BuildReady End` lines from this build, consistent with the local Unity console output.

## Background (Optional)

The upload call is entirely delegated to the `ObjectStorageUploadManager.UploadFile` of the external `GameFrameX.ObjectStorage` package. This repository is only responsible for passing through the four command-line parameters to [`BuilderOptions`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40), and does not directly operate any SDK.
