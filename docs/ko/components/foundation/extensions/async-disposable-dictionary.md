# 비동기 폐기 가능 사전 사용 방법

`AsyncDisposableDictionary<TKey, TValue>`는 값이 `IAsyncDisposable`을 구현해야 하는 사전 컨테이너로, `NullableDictionary<TKey, TValue>`를 상속합니다. 사전 자체가 `DisposeAsync()`로 폐기되면 모든 비어 있지 않은 값을 자동으로 순회하며 비동기적으로 해제하므로, 비동기 정리가 필요한 리소스(예: 데이터베이스 연결, 네트워크 세션, 장시간 연결 클라이언트 등)를 관리하는 데 적합합니다.

## 사전 조건

- `TValue`는 반드시 `IAsyncDisposable`을 구현해야 합니다.
- 네임스페이스 `GameFrameX.Foundation.Extensions`를 가져옵니다.
- 적용할 .NET 버전은 `IAsyncDisposable`을 지원해야 합니다(.NET Standard 2.1+ / .NET 5+).

## 작업 단계

1. **사전 인스턴스를 생성하고 값 쓰기**

   컬렉션 이니셜라이저 또는 인덱서를 통해 리소스 객체를 직접 쓰면 됩니다.

   ```csharp
   using GameFrameX.Foundation.Extensions;

   var dictionary = new AsyncDisposableDictionary<string, MyAsyncResource>
   {
       ["conn-1"] = new MyAsyncResource(),
       ["conn-2"] = new MyAsyncResource()
   };
   ```

   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L6-L37)

2. **(선택 사항)폐기 오류 처리기 설정**

   특정 값의 `DisposeAsync()`가 예외를 발생시키면 사전은 `DisposalErrorHandler`를 호출하며, 이를 통해 기록 또는 대체 처리 방식을 결정할 수 있습니다.

   ```csharp
   dictionary.DisposalErrorHandler = (value, ex) =>
   {
       Console.WriteLine($"{value} 폐기 실패: {ex.Message}");
   };
   ```

   처리기 자체가 발생시키는 예외는 삼켜져 나머지 값이 계속 해제되도록 보장됩니다.  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L92-L102)

3. **`DisposeAsync()`를 호출하여 모든 값을 비동기적으로 폐기**

   ```csharp
   await dictionary.DisposeAsync();
   ```

   폐기 과정은 멱등성을 가집니다. `DisposeAsync()`를 반복 호출해도 값이 중복 해제되지는 않습니다. `dictionary.IsDisposed`로 상태를 확인할 수 있습니다.  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L71-L90)

4. **폐기 후에는 쓰거나 수정하지 않기**

   폐기 후 인덱서 `set`, `Add`, `Remove`를 호출하면 `ObjectDisposedException`이 발생합니다. 상속받은 기본 클래스 사전의 동작이므로 읽기(get)는 계속 사용할 수 있습니다.

## 일반적인 변형

- **동시성 시나리오**: 멀티스레드 환경에서 동시에 읽고 써야 하는 경우 스레드 안전 버전인 `AsyncDisposableConcurrentDictionary<TKey, TValue>`를 사용합니다. 사용 방법은 이 페이지와 동일합니다.
- **빈 사전 폐기**: 사전에 값이 없어도 `await dictionary.DisposeAsync()`를 직접 호출하는 것이 안전하며, 즉시 반환됩니다.
- **일부 값의 폐기 실패**: 특정 값의 폐기 실패가 다른 값의 폐기를 막지 않으며, 모든 `IAsyncDisposable`은 한 번씩 해제를 시도합니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `ObjectDisposedException` | `DisposeAsync()` 이후에 `Add`, `Remove` 또는 인덱서 `set`을 다시 호출함 | 폐기 후 쓰기를 중단하고 읽기 전용 접근만 허용 |
| 값이 해제되지 않음 | `null` 값을 저장함 | `DisposeAsync`는 `null`을 건너뜁니다. 실제 리소스 인스턴스가 저장되었는지 확인 |
| 폐기가 중단되고 후속 리소스가 정리되지 않음 | 이전 코드가 처리되지 않은 예외를 직접 발생시킴 | 항상 `DisposalErrorHandler`를 사용해 대체 처리하고, 사전 내부의 try/catch에 의존해 계속 반복 |
| 타입 컴파일 오류 | `TValue`가 `IAsyncDisposable`을 구현하지 않음 | 리소스 타입이 `IAsyncDisposable`을 구현하는지 확인합니다. 예를 들어 `DbConnection`, `HttpClient`의 사용자 지정 래퍼를 사용 |

## 검증

- `await dictionary.DisposeAsync()`를 호출한 후 `dictionary.IsDisposed`는 `true`가 됩니다.
- 모든 비어 있지 않은 값의 `DisposeAsync()`는 한 번만 호출됩니다(테스트 케이스로 검증됨).  
  Source: [AsyncDisposableDictionaryTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Tests/Extensions/AsyncDisposableDictionaryTests.cs#L28-L45)
- 폐기 후 `DisposeAsync()`를 다시 호출해도 예외가 발생하지 않으며 값도 중복 해제되지 않습니다.

## 배경(선택 사항)

`AsyncDisposableDictionary`는 `_isDisposed`를 `true`로 표시한 후 `Values`를 순회하여 다음을 보장합니다. 즉, 반복 과정에서 특정 값에서 `DisposeAsync`가 차단되거나 오류를 발생시켜도 후속 값의 해제를 계속 진행할 수 있습니다. 오류 처리는 콜백 대리자를 통해 호출자에게 노출되므로 프레임워크가 특정 로깅 시스템에 종속되지 않습니다.
