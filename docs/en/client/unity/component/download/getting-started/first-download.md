# Run Your First Download Task in 5 Minutes

Follow the steps on this page, and within 5 minutes you can fully download a file from a URL to your local disk and receive success/failure callbacks via events.

## Prerequisites

- Unity 2019.4 or higher
- This package installed (choose any one of the three methods; see the README):
  - Add the GameFrameX registry to `scopedRegistries` in `Packages/manifest.json`, and add `com.gameframex.unity.download` to `dependencies`
  - Or add `https://github.com/gameframex/com.gameframex.unity.download.git` via Git URL in the Package Manager
  - Or place the repository directly into the `Packages/` directory
- A `GameFramework` startup entry exists in the scene, and `DownloadComponent` is attached (the component is automatically registered to `GameEntry` by default)

## Steps

1. **Confirm the component is attached**. `DownloadComponent` is automatically registered via `[GameFrameXAutoComponent(-4000)]`; after startup you can retrieve it from `GameEntry`:

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L44-L46)

2. **Add your first download task**. The minimal working call takes only two parameters: the local save path `downloadPath` and the remote address `downloadUri`; it returns the task's serial ID:

   ```csharp
   int serialId = downloadComponent.AddDownload(
       "/本地保存路径/file.zip",      // downloadPath
       "https://example.com/file.zip"  // downloadUri
   );
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L280)

3. **Subscribe to success/failure events** (recommended). Listen for `DownloadSuccess` and `DownloadFailure` through `EventComponent`:

   ```csharp
   var eventComponent = GameEntry.GetComponent<EventComponent>();
   eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);

   void OnDownloadSuccess(object sender, GameEventArgs e)
   {
       var args = (DownloadSuccessEventArgs)e;
       if (args.SerialId == serialId) { /* Download complete */ }
   }

   void OnDownloadFailure(object sender, GameEventArgs e)
   {
       var args = (DownloadFailureEventArgs)e;
       Debug.LogError($"下载失败:{args.ErrorMessage}");
   }
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/README.zh-CN.md#L98-L127)

4. **Or go the async route**. If you would rather not subscribe to events, you can directly `await` the return value of `Download(...)`:

   ```csharp
   bool success = await downloadComponent.Download(
       "/本地保存路径/file.zip",
       "https://example.com/file.zip"
   );

   if (success) { /* Download complete */ }
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L312)

5. **Verify**. Run the scene and check the target path; if the file exists and `OnDownloadSuccess` fires, it succeeded. If it never fires, see "Common Errors" below.

## Common Variants

- **With priority and tag** — a higher value means higher priority; you can query tasks grouped by tag or remove them in bulk:

  ```csharp
  int id = downloadComponent.AddDownload(
      downloadPath, downloadUri,
      tag: "assets",
      priority: 10
  );
  TaskInfo[] infos = downloadComponent.GetDownloadInfos("assets");
  downloadComponent.RemoveDownloads("assets");
  ```

  Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L339-L348)

- **Global pause / resume** — toggling the `Paused` property applies to all agents:

  ```csharp
  downloadComponent.Paused = true;   // Pause
  downloadComponent.Paused = false;  // Resume
  ```

  Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L69-L73)

- **Only care about a single result** (lightweight approach) — directly await the `Task<bool>` returned by `Download(path, uri)`; no event subscription needed.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GetComponent<DownloadComponent>()` returns null | The scene is missing the `GameFramework` startup component, or the package was not imported correctly | Confirm the dependency in `Packages/manifest.json` has taken effect, and check the startup entry |
| Download callbacks never fire | Only `AddDownload` was called without subscribing to `DownloadSuccessEventArgs` / `DownloadFailureEventArgs`, or the callback did not match on `SerialId` | Subscribe to both events and filter with `args.SerialId == serialId` in the callback |
| The file was written to an unexpected location | `downloadPath` used a relative path; Unity's base path differs across platforms | Use an absolute path (e.g., `Application.persistentDataPath + "/file.zip"`) |
| The download gets stuck and never finishes | `Paused` was set to `true`, globally pausing downloads | Set `downloadComponent.Paused = false` |

## Background (Optional)

Internally, `DownloadComponent` uses `IDownloadManager` to manage a pool of download agents with a configurable count; by default, 3 agents execute concurrently, and tasks are dispatched by priority. At the lower level, it communicates with Unity's `UnityWebRequest` through `UnityWebRequestDownloadAgentHelper`, which you can replace with a custom `IDownloadAgentHelper` implementation via the Inspector. `FlushSize` (default 1 MB) controls the flush-to-disk threshold, used for resumable downloads.
