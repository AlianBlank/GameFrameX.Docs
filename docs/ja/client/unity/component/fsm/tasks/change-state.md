# 状態間の切り替え方法

`FsmState<T>` を継承した任意の状態クラス内で `ChangeState<TState>(fsm)` を呼び出すと、現在の FSM のアクティブ状態を即座に切り替えられます。フレームワークは現在の状態の `OnLeave` と新しい状態の `OnEnter` を順番にトリガーします。

## 前提条件

- `FsmComponent.CreateFsm(...)` または `GameApp.Fsm.CreateFsm(...)` を介して対象の FSM を作成済みであり、切り替え先の対象状態が引数として渡されていること。
- 対象状態の型は `FsmState<T>` を継承しており、`T` は FSM のジェネリックパラメータと一致していること。

## 操作手順

1. **状態クラス内部での切り替えトリガー**:`FsmState<T>` の派生クラス内部から、プロテクトメソッドの `ChangeState<TState>(IFsm<T> fsm)` を呼び出します。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

2. **状態の外部からトリガーする必要がある場合**:`FsmState<T>` のパブリックメソッド `ChangeToState<TState>(IFsm<T> fsm)` を使用できます。これは内部的に `ChangeState<TState>(fsm)` に転送されます。

   ```csharp
   fsm.CurrentState.ChangeToState<MoveState>(fsm);
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L119)

3. **対象状態の型のみが分かっている場合**:`Type` によるオーバーロードを使用し、状態クラスのランタイム型を渡します。

   ```csharp
   ChangeState(fsm, typeof(MoveState));
   ```

   このオーバーロードは、渡された `Type` が `FsmState<T>` に代入可能かどうかを検証し、そうでない場合は `GameFrameworkException("State type '{0}' is invalid.")` をスローします。  
   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

4. **内部実行フロー**:`Fsm<T>.ChangeState(Type)` を呼び出すと、フレームワークはまず旧状態の `OnLeave(this, false)` を呼び出し、`m_CurrentStateTime` をリセットし、`m_CurrentState` を置き換えてから、新状態の `OnEnter(this)` を呼び出します。

   ```csharp
   m_CurrentState.OnLeave(this, false);
   m_CurrentStateTime = 0f;
   m_CurrentState = state;
   m_CurrentState.OnEnter(this);
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L726-L729)

## よくあるバリエーション

- **文字列名による切り替え**:まず `FsmComponent.HasState<T>(name)` などの名前指定 API で状態を見つけ、次に `Type` オーバーロードを使用して切り替えます。本リポジトリのパブリックなジェネリックオーバーロードには、名前を直接指定して切り替えるエントリは提供されていません。
- **連続的な複数回切り替え**:`OnEnter` 内で即座に `ChangeState<NextState>(fsm)` を呼び出すことで、1 フレーム内でのカスケード切り替えが可能です。ただし、無限再帰には注意が必要です。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GameFrameworkException: Current state is invalid.` | まだ `Start<T>()` を呼び出していないか、FSM が既に `Shutdown` されている時に `ChangeState` を呼び出した | まず `fsm.Start<IdleState>()` を呼び出して FSM を起動する |
| `FSM '...' can not change state to '...' which is not exist.` | 対象状態クラスが `CreateFsm` の `states` 配列に渡されていない | 対象状態のインスタンスを `CreateFsm(owner, new IdleState(), new MoveState())` に追加する |
| `State type '...' is invalid.` | `Type` オーバーロードに渡された型が `FsmState<T>` の派生クラスではない | 対象型が `FsmState<T>` を継承しており、`T` が FSM と一致していることを確認する |
| 切り替え後に `OnLeave` が通知されない | 切り替えが `OnLeave` の後に書かれているか、FSM が既に破棄されている | 状態のライフサイクルメソッド内で呼び出し、FSM がまだ生存していることを確認する |

## 背景(オプション)

`ChangeState<TState>` は内部的にメソッドの転送を 1 回行うだけで、実際の切り替えロジックは `Fsm<T>.ChangeState(Type)` に集中しています。これにより、すべてのオーバーロードが同一の `OnLeave → タイマーリセット → 置き換え → OnEnter` フローを経由することが保証され、ブランチの漏れを防ぎます。
