# 네트워크 이벤트 수신(연결/연결 끊김/오류/하트비트 손실)

이 페이지에서는 네트워크 모듈이 발생시키는 네 가지 유형의 이벤트를 구독하고 처리하는 방법을 설명합니다: `NetworkConnectedEventArgs`(연결 성공), `NetworkClosedEventArgs`(연결 종료), `NetworkErrorEventArgs`(네트워크 오류), `NetworkMissHeartBeatEventArgs`(하트비트 손실). 이 이벤트들은 모두 `GameFrameX.Event.Runtime.GameEventArgs`를 상속하며, 각 타입의 정적 필드 `EventId`(값은 타입의 전체 이름과 동일)를 통해 구독을 등록하고, 처리 콜백에서 이벤트가 담고 있는 필드를 바로 읽으면 됩니다.

## 사전 조건

- GameFrameX 네트워크 컴포넌트(`GameFrameX.Network.Runtime` 네임스페이스)가 도입되어 있어야 합니다.
- 이벤트 구독 진입점은 **GameFrameX.Event 컴포넌트**에서 제공합니다(`GameEventArgs` 기본 클래스는 `GameFrameX.Event.Runtime`에 위치하며, 해당 컴포넌트는 이 리포지토리에 포함되어 있지 않음). 이 페이지에 나열된 이벤트 Id를 구독하기 전에 프로젝트에서 이벤트 컴포넌트가 활성화되어 있는지 확인하십시오.

## 작업 단계

1. 수신하려는 이벤트와 그에 담긴 필드를 확인합니다(모두 `GameFrameX.Network.Runtime` 네임스페이스에 위치):

| 이벤트 클래스 | 발생 시점 | 담고 있는 필드 | EventId 값 |
|--------|----------|----------|------------|
| `NetworkConnectedEventArgs` | 네트워크 연결 성공 | `NetworkChannel`(`INetworkChannel`), `UserData`(`object`, 연결 시 전달되는 사용자 정의 데이터) | `GameFrameX.Network.Runtime.NetworkConnectedEventArgs` |
| `NetworkClosedEventArgs` | 네트워크 연결 종료 | `NetworkChannel`(전체 필드는 소스 파일 참조) | `GameFrameX.Network.Runtime.NetworkClosedEventArgs` |
| `NetworkErrorEventArgs` | 네트워크 오류 | `NetworkChannel`, `ErrorCode`(`NetworkErrorCode`), `SocketErrorCode`(`System.Net.Sockets.SocketError`), `ErrorMessage`(`string`) | `GameFrameX.Network.Runtime.NetworkErrorEventArgs` |
| `NetworkMissHeartBeatEventArgs` | 하트비트 패킷 손실 | `NetworkChannel`, `MissCount`(`int`, 손실된 횟수) | `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs` |

2. 각 이벤트 클래스의 **정적 필드** `EventId`를 사용하여 이벤트 컴포넌트에 콜백을 등록합니다. 문자열을 직접 작성하지 마십시오. `EventId`의 정의가 바로 타입의 전체 이름입니다:

```csharp
/// <summary>
/// 네트워크 연결 성공 이벤트 번호.
/// </summary>
public static readonly string EventId = typeof(NetworkConnectedEventArgs).FullName;

/// <summary>
/// 네트워크 연결 성공 이벤트 번호를 가져옵니다.
/// </summary>
public override string Id
{
    get { return EventId; }
}
```

Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L44-L54)

3. 콜백에서 이벤트 타입에 따라 필드를 읽습니다. 오류 이벤트를 예로 들면, 프레임워크 계층 오류 코드, Socket 계층 오류 코드, 오류 메시지를 동시에 얻을 수 있습니다:

```csharp
/// <summary>
/// 네트워크 채널을 가져옵니다.
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// 오류 코드를 가져옵니다.
/// </summary>
public NetworkErrorCode ErrorCode { get; private set; }

/// <summary>
/// Socket 오류 코드를 가져옵니다.
/// </summary>
public SocketError SocketErrorCode { get; private set; }

/// <summary>
/// 오류 정보를 가져옵니다.
/// </summary>
public string ErrorMessage { get; private set; }
```

Source: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L68-L86)

4. 하트비트 손실 시 `MissCount`로 심각도를 판단하고(이 카운트는 연속 손실 시 증가), `NetworkChannel`과 함께 어떤 채널인지 파악합니다:

```csharp
/// <summary>
/// 네트워크 채널을 가져옵니다.
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// 하트비트 패킷 손실 횟수를 가져옵니다.
/// </summary>
public int MissCount { get; private set; }
```

Source: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L65-L73)

5. 콜백이 반환된 후에는 **이벤트 객체를 캐시하지 마십시오**. 이벤트 인스턴스는 참조 풀에서 가져온 것으로(`ReferencePool.Acquire`로 생성, `Clear()`로 필드 초기화), 필드는 이벤트가 디스패치된 후 비워집니다:

```csharp
public static NetworkConnectedEventArgs Create(INetworkChannel networkChannel, object userData)
{
    NetworkConnectedEventArgs networkConnectedEventArgs = ReferencePool.Acquire<NetworkConnectedEventArgs>();
    networkConnectedEventArgs.NetworkChannel = networkChannel;
    networkConnectedEventArgs.UserData = userData;
    return networkConnectedEventArgs;
}

/// <summary>
/// 네트워크 연결 성공 이벤트를 정리합니다.
/// </summary>
public override void Clear()
{
    NetworkChannel = null;
    UserData = null;
}
```

Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L77-L96)

## 일반적인 변형

- **연결 끊김 후 재연결**: `NetworkMissHeartBeatEventArgs`(`MissCount`가 임계값 초과) 또는 `NetworkClosedEventArgs` 콜백에서 채널 정보를 기록하고(주소 등은 `NetworkChannel`에서 획득), 지연 후 다시 연결을 시도합니다. 연결 결과는 다시 `NetworkConnectedEventArgs`로 확인합니다.
- **여러 채널 구분**: 여러 연결을 동시에 유지할 때는 모든 콜백에서 먼저 `NetworkChannel`(예: 채널 이름)을 비교한 뒤 처리하여, A 채널의 오류를 B 채널의 오류로 잘못 처리하는 일을 방지합니다.
- **오류 등급별 표시**: `ErrorCode`는 비즈니스 분기에 사용하고, `SocketErrorCode`/`ErrorMessage`는 로그와 안내 문구에 사용합니다.

## 자주 발생하는 오류

| 현상 | 원인 | 회피 방법 |
|------|------|----------|
| 구독 문자열을 직접 작성했는데 이벤트를 받지 못함 | 문자열이 실제 `EventId`와 일치하지 않음(네임스페이스 전체 이름 `GameFrameX.Network.Runtime.` 접두사 주의) | 항상 `NetworkConnectedEventArgs.EventId` 같은 정적 필드로 구독 |
| 콜백에서 읽은 필드가 `null` / `0`임 | 이벤트 객체가 참조 풀에서 온 것으로, 디스패치 후 `Clear()`가 이미 필드를 초기화함 | 콜백 내에서 필요한 값을 즉시 읽어 복사하고, 이벤트 인스턴스를 캐시하지 않음 |
| `SocketErrorCode` / `ErrorMessage`를 참조할 수 없음 | `System.Net.Sockets` 네임스페이스를 가져오지 않음 | 구독 클래스 파일 상단에 `using System.Net.Sockets;` 추가(오류 이벤트 소스 파일에서도 동일하게 참조함) |
| 컴파일 시 `GameEventArgs`를 찾을 수 없다는 오류 발생 | 이벤트 기본 클래스는 GameFrameX.Event 컴포넌트에 있으며 이 리포지토리가 아님 | 먼저 이벤트 컴포넌트를 설치/활성화 |

## 배경

네 개의 이벤트 인자 클래스는 모두 `sealed class ... : GameEventArgs`이며, 코드 스트리핑으로부터 제거되지 않도록 `[UnityEngine.Scripting.Preserve]`가 표시되어 있습니다. 정적 `Create(...)`를 통해 참조 풀에서 인스턴스를 획득하고, `Clear()`로 반환하기 전에 필드를 초기화하는 것은 프레임워크 전체에서 통일된 "참조 풀 이벤트" 패턴이며, 그렇기 때문에 콜백 내에서 데이터를 즉시 소비해야 합니다. 이벤트 클래스 소스 코드는 `Runtime/EventArgs/` 디렉터리에 위치합니다([NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs), [NetworkClosedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkClosedEventArgs.cs), [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs), [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs)). 오류 코드 열거형은 `Runtime/Network/Base/NetworkErrorCode.cs`에서, 하트비트 처리 관련 기본 클래스는 `Runtime/Network/Helper/BasePacketHeartBeatHandler.cs`와 `Runtime/Network/Base/IHeartBeatMessage.cs`에서 확인할 수 있습니다. 이벤트의 디스패치 및 구독 API는 GameFrameX.Event 컴포넌트에 속하며, 이벤트 컴포넌트의 전체적인 사용법은 해당 문서를 참조하십시오.
