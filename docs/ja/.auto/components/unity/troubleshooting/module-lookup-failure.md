# モジュール検索に失敗した場合の対処

`GameFrameX.Runtime.GameFrameworkEntry.GetModule<T>()` を呼び出してモジュールを検索する際、フレームワークはインターフェース名を通じてリフレクションで実装クラスを特定します。検索プロセスはインターフェース制約、命名規則、自動登録の失敗などにより `GameFrameworkException` をスローします。このページでは例外メッセージごとに根本原因と修正手順を一覧します。

## クイック診断

| 症状（例外メッセージ原文） | 根本原因 | 修正 |
|---|---|---|
| `You must get module by interface, but 'X' is not.` | ジェネリック `T` がインターフェースではないため、フレームワークはインターフェースでの取得を強制している | [インターフェース型を渡すように変更](#修正1-インターフェースで取得する必要がある) |
| `You must get a Game Framework module, but 'X' is not.` | 渡されたインターフェースが `GameFrameX.` 名前空間で始まっていない | [名前空間を修正](#修正2-名前空間は-gameframex-で始まる必要がある) |
| `Can not find Game Framework module type 'X.Y.Z'.` | 命名規約に従って自動的に実装クラスが見つからないため、明示的な登録が必要 | [RegisterModule を呼び出すか実装クラスを追加](#修正3-モジュール実装クラスが見つからない) |
| `You must register module by interface, but 'X' is not.` | `RegisterModule` の最初の引数にクラスが渡されている | [インターフェース型を渡す](#修正4-登録時の最初の引数はインターフェースである必要がある) |
| `You must register module by Class and not Interface and Abstract, but 'X' is not.` | 2 番目の引数が具象クラスではない（インターフェース、抽象クラス、またはクラス以外の型） | [具象実装クラスを渡す](#修正5-登録時の2番目の引数は具象クラスである必要がある) |
| `Can not create module 'X'.` | 実装クラスにパラメーターなしのコンストラクターがないか、`Activator.CreateInstance` が失敗した | [パラメーターなしのコンストラクターを追加](#修正6-実装クラスにパラメーターなしのコンストラクターがない) |

## 修正手順

### 修正1 インターフェースで取得する必要がある

`GetModule<T>` の最初の処理は `typeof(T).IsInterface` の判定で、インターフェースでなければ直接エラーをスローします。

```csharp
// 错误：传实现类
var foo = GameFrameworkEntry.GetModule<FooImpl>();

// 正确：传接口
var foo = GameFrameworkEntry.GetModule<IFoo>();
```

Source: [GameFrameworkEntry.cs#L95-L120](/src/Runtime/Base/GameFrameworkEntry.cs#L95-L120)

### 修正2 名前空間は `GameFrameX.` で始まる必要がある

フレームワークはインターフェースの `FullName` が `GameFrameX.` で始まることを要求しており、そうでない場合は 2 番目の例外をスローします。

```csharp
// 错误：命名空间不在 GameFrameX 下
namespace MyGame { public interface IBar {} }

// 正确
namespace GameFrameX.Runtime { public interface IBar {} }
```

Source: [GameFrameworkEntry.cs#L104-L107](/src/Runtime/Base/GameFrameworkEntry.cs#L104-L107)

### 修正3 モジュール実装クラスが見つからない

実装クラスを検索する際、フレームワークは規約に従ってインターフェース名からプレフィックス `I` を取り除き、同じ名前空間に結合してリフレクションします（例：`GameFrameX.Runtime.IFoo` → `GameFrameX.Runtime.Foo`）。失敗した場合は明示的な `RegisterModule` が必要になります。

```csharp
// 约定查找（同名空间下存在 Foo 类即可）
public class Foo : GameFrameworkModule, IFoo { /* ... */ }

// 或者显式注册：传入的第二个 Type 可以来自任意命名空间
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(MyGame.Modules.FooImpl));
```

呼び出しエントリは `GetModule<T>` 内の `Type.GetType(moduleName)` ロジックにあります。詳細は [GameFrameworkEntry.cs#L109-L119](/src/Runtime/Base/GameFrameworkEntry.cs#L109-L119) を参照してください。登録ロジックは [GameFrameworkEntry.cs#L153-L169](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L169) を参照してください。

### 修正4 登録時の最初の引数はインターフェースである必要がある

`RegisterModule` の最初の行で `interfaceType.IsInterface` を検証します。

```csharp
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(Foo));   // 正确
GameFrameworkEntry.RegisterModule(typeof(Foo), typeof(Foo));     // 抛异常
```

Source: [GameFrameworkEntry.cs#L153-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L163)

### 修正5 登録時の2番目の引数は具象クラスである必要がある

`implType.IsClass && !implType.IsInterface && !implType.IsAbstract` であることが要求されます。

- インターフェース → `by Class and not Interface ... is not.` をスロー
- 抽象クラス → 同上をスロー
- 具象クラスで登録してください

Source: [GameFrameworkEntry.cs#L160-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L160-L163)

### 修正6 実装クラスにパラメーターなしのコンストラクターがない

`CreateModule` は `Activator.CreateInstance(moduleType)` を使用してインスタンス化するため、パラメーターなしのコンストラクターが見つからない場合、またはコンストラクターでエラーが発生した場合に `Can not create module 'X'.` が返されます。

```csharp
public class Foo : GameFrameworkModule
{
    public Foo() { }  // 必须保留一个可访问的无参构造函数
    protected internal override int Priority => 0;
    protected internal override void Update(float a, float b) { }
    protected internal override void Shutdown() { }
}
```

## 検証

- `Awake` または `Start` で `GameFrameworkException` をキャッチします：
  ```csharp
  try
  {
      var ui = GameFrameworkEntry.GetModule<IFooModule>();
  }
  catch (GameFrameworkException ex)
  {
      Debug.LogError(ex.Message);
  }
  ```
  例外がスローされなくなれば、登録と名前空間の両方が正しいことを示します。
- コンソールに `Can not find Game Framework module type` というメッセージが表示されなくなった場合、規約に従った自動検索が成功したことを示します。それでも検索が失敗する場合は、アセンブリが Player Settings にコンパイルされていること、およびインターフェースと実装クラスの名前空間が一致していることを確認してください。
