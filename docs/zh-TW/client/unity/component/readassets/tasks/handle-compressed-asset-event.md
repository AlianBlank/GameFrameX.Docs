# 處理 Android 壓縮 StreamingAsset 事件

當 `StreamingAssets` 目錄下的檔案在 APK 建置中以壓縮形式儲存時(尤其是在 App Bundle 中),Unity 無法透過檔案偏移量直接讀取它們。本框架會在初始化期間掃描 APK 的 Central Directory,並在發現此類檔案時觸發 `CompressedStreamingAssetFound` 事件,讓您可以在執行階段攔截並處理它們。

## 前置需求

- 事件簽章僅在 `UNITY_ANDROID` 或 `UNITY_EDITOR`(使用 `InitializeWithExternalApk` 時)平台下才真正存在；在其他平台上,`add`/`remove` 為無操作(no-op)。
- 專案必須已透過 `BlankReadAssets.Initialize()` 或 `BlankReadAssets.Root` 完成初始化(首次存取任何 API 時會自動觸發)。

## 步驟

1. **訂閱事件**。事件簽章為 `Func<string, bool>`,它會接收 APK 中的完整檔案名稱(例如 `"assets/config/data.json"`),並回傳 `true` 表示您已處理該檔案，如此框架就不會發出任何警告：

```csharp
using GameFrameX.ReadAssets.Runtime;

BlankReadAssets.CompressedStreamingAssetFound += fileName =>
{
    // fileName 類似 "assets/xxx.bin"
    if (fileName.EndsWith(".json"))
    {
        // 您的備援邏輯：從遠端下載 / 從 persistentDataPath 複製 / 使用內建預設值等
        Debug.Log($"Handled compressed StreamingAsset: {fileName}");
        return true;
    }
    return false;
};
```

2. **在初始化之前訂閱**。事件會在 `ApkImpl.Initialize` → `GetStreamingAssetsInfoFromJar` 掃描 APK 時觸發，因此訂閱必須早於第一次讀取。建議將其放在 `RuntimeInitializeOnLoadMethod` 中：

```csharp
using UnityEngine;
using GameFrameX.ReadAssets.Runtime;

public static class Bootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSplashScreen)]
    private static void Init()
    {
        BlankReadAssets.CompressedStreamingAssetFound += OnCompressed;
    }

    private static bool OnCompressed(string fileName)
    {
        // 回傳 true 表示「已處理」，框架將保持靜默
        return false;
    }
}
```

3. **(可選)在編輯器中驗證**。透過 `InitializeWithExternalApk` 載入真實的 APK,即可在編輯器中觸發相同事件，方便聯合除錯：

```csharp
BlankReadAssets.InitializeWithExternalApk(@"C:\builds\game.apk");
```

此事件與 `InitializeWithExternalApk` 共用相同的 `ApkImpl` 掃描邏輯([BlankReadAssets.ApkImpl.cs#L294-L354](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L294-L354))。

## 常見變體

- **不想訂閱，只想保持靜默**。實作部分方法 `AndroidIsCompressedFileStreamingAsset`,回傳 `false` 讓框架直接忽略該檔案——跳過事件分發且不記錄任何日誌：

```csharp
using GameFrameX.ReadAssets.Runtime;
using UnityEngine;

public partial class BlankReadAssets
{
    static partial void AndroidIsCompressedFileStreamingAsset(string fileName, ref bool isStreamingAsset)
    {
        // 例如：抑制某類資源
        if (fileName.StartsWith("assets/internal/")) isStreamingAsset = false;
    }
}
```

部分方法的宣告請參閱 [BlankReadAssets.ApkImpl.cs#L334](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L334)。

- **App Bundle 場景**。如果專案本身是上傳至 Google Play、之後被展開成多個 `.apk` 分割檔的 App Bundle(`*.aab`),當 `dataPath` 不是 `base.apk` 時，框架會自動回退為掃描同目錄下的 `base.apk`([BlankReadAssets.ApkImpl.cs#L43-L51](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L43-L51));此分支同樣會觸發該事件，訂閱程式碼無需任何修改。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `Debug.LogAssertionFormat` 持續回報 `BlankReadAssets: file ... is where Streaming Assets are put, but is compressed.` | 沒有任何人訂閱事件，也未實作部分方法篩選器 | 訂閱 `CompressedStreamingAssetFound` 或實作 `AndroidIsCompressedFileStreamingAsset` |
| 在 iOS / Standalone 下撰寫 `BlankReadAssets.CompressedStreamingAssetFound += ...` 會直接導致編譯錯誤 | 事件僅在 `UNITY_EDITOR \|\| UNITY_ANDROID` 下才有實際簽章 | 使用 `#if UNITY_ANDROID || UNITY_EDITOR` 包裹訂閱程式碼；或直接忽略(在其他平台上為無操作) |
| 訂閱時機太晚，啟動後立即觸發一次 | 事件會在 `Initialize` 內部同步觸發 | 在 `[RuntimeInitializeOnLoadMethod(BeforeSplashScreen)]` 或更早的啟動程序中訂閱 |
| 誤以為回傳 `false` 會拋出例外 | 回傳 `false` 僅表示「未處理」；框架會沿未訂閱路徑繼續執行(可能觸發斷言) | 一旦實際處理完成，請回傳 `true` |

## 背景說明(可選)

在打包 Android 版本時，Unity 預設會壓縮 APK 中超過門檻值的 `assets/` 檔案；然而 `BlankReadAssets` 是直接透過 ZIP Central Directory 來定位 `StreamingAssets` 內檔案的偏移量與未壓縮大小。這種「依偏移量讀取原始位元組」的策略，只有在 APK 內的檔案已被壓縮(`CompressedSize != UncompressedSize`)時才會失效。此事件機制正是為此而設計：讓業務端自行決定壓縮資產的備援方式([BlankReadAssets.cs#L70-L78](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L70-L78))。
