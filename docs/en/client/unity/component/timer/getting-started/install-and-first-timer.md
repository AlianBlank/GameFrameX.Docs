# Installing and Running Your First Timer

GameFrameX Timer is a lightweight Unity timer/scheduler package (package name `com.gameframex.unity.timer`) that supports repeating timers (with a configurable count), one-shot timers, and per-frame update callbacks. This page walks you through the installation from scratch and getting your first timer callback up and running.

## Quick Start

### Prerequisites

- Unity `2019.4` or higher (see `"unity": "2019.4"` in package.json).
- The dependency package `com.gameframex.unity` (version `2.5.1`) is installed; this package's `TimerComponent` inherits from its `GameFrameworkComponent`.

### Step 1: Install the Package

In Unity, open **Window → Package Manager → + → Add package from git URL** and enter:

```text
https://github.com/gameframex/com.gameframex.unity.timer.git
```

This URL comes from the `repository.url` field in the package configuration:

```json
{
  "name": "com.gameframex.unity.timer",
  "displayName": "Game Frame X Timer",
  "version": "1.3.1",
  "unity": "2019.4",
  "dependencies": {
    "com.gameframex.unity": "2.5.1"
  }
}
```

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/package.json#L1-L27)

### Step 2: Add the Timer Component

`TimerComponent` is a Unity component with the menu path **GameFrameX/Timer**, and it carries `[DisallowMultipleComponent]` (only one can be attached to the same GameObject):

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Timer")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-5000)]
public class TimerComponent : GameFrameworkComponent
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L12-L16)

Simply add it to a scene GameObject (such as GameFrameX's bootstrap GameObject) via **Add Component → GameFrameX → Timer**; if you use GameFrameX's automatic component mechanism (`GameFrameXAutoComponent`), it will be attached automatically.

### Step 3: Write Your First Timer

Create a new script, attach it to any GameObject, get the component via `GetComponent<TimerComponent>()`, and call `AddOnce` to create a timer that fires once after 1 second:

```csharp
using GameFrameX.Timer.Runtime;
using UnityEngine;

public class FirstTimerDemo : MonoBehaviour
{
    void Start()
    {
        var timer = GetComponent<TimerComponent>();

        // One-shot timer: executes once after 1 second
        int id = timer.AddOnce(1f, param => Debug.Log("一次性定时器触发"));

        // Repeating timer: executes every 1 second, 3 times in total (0 means repeat indefinitely)
        timer.Add(1f, 3, param => Debug.Log("重复定时器触发"));

        // Per-frame update
        timer.AddUpdate(param => { /* Called every frame */ });
    }
}
```

These three calls correspond to the component's actual API signatures:

```csharp
public int AddOnce(float interval, Action<object> callback, object callbackParam = null)
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
public int AddUpdate(Action<object> callback)
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L80)

### Step 4: Run and Verify

Click Unity Play; you should see the following in the Console, in order:
1. `一次性定时器触发` is logged after 1 second;
2. `重复定时器触发` appears once per second, 3 times in total.

Timers use `TimerTimeScale.Unscaled` by default (unaffected by `Time.timeScale`), so even when the game is in slow-motion/paused state, `AddOnce`/`Add` still fire based on real time; pass `TimerTimeScale.Scaled` explicitly when you need them to follow game time.

## Common Variants

**Wait for a period of time before executing (async/await)**: The component also provides async wait APIs with the following signatures:

```csharp
public Task WaitForSecondsAsync(float seconds, CancellationToken cancellationToken = default)
public Task WaitForNextFrameAsync(CancellationToken cancellationToken = default)
public Task WaitForFramesAsync(int frameCount, CancellationToken cancellationToken = default)
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L245)

Usage example:

```csharp
var timer = GetComponent<TimerComponent>();
await timer.WaitForSecondsAsync(2f);
Debug.Log("2 秒后执行");
```

**Grouped management with tags**: The `tag` parameter of `Add` can be used for batch pause/resume/removal. For example, after calling `timer.Add(1f, 0, cb, null, "battle")`, calling `timer.RemoveByTag("battle")` clears all battle-related timers at once.

## Common Mistakes

- **Forgetting `using GameFrameX.Timer.Runtime;`**: Both the component and the manager live in this namespace; without it, compilation fails with a "type TimerComponent not found" error.
- **Attaching multiple Timer components fails**: `TimerComponent` is marked with `[DisallowMultipleComponent]`, so Unity blocks adding it more than once to the same GameObject.
- **Misunderstanding the `repeat` semantics**: `repeat` of `0` means repeat indefinitely (the source comment explicitly states "0 means repeat indefinitely"), `1` means execute once, and so on; `AddOnce(interval, callback)` is internally a convenience wrapper equivalent to executing exactly once.
- **Assuming timers are controlled by `Time.timeScale`**: `Add`/`AddOnce` default to `TimerTimeScale.Unscaled` and use `realElapseSeconds` (real time); pass `TimerTimeScale.Scaled` explicitly if you need them to follow game time scaling.
