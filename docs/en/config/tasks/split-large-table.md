# How to Split a Large Table into Multiple Files

When a single Excel configuration table has too many rows (several thousand or more), frequent conflicts arise during multi-person collaboration, or when it needs to be maintained separately by business/value range, you can split it into multiple files that Luban merges and generates. This page explains the naming rules and configuration methods for splitting large tables in the GameFrameX.Config project.

## Prerequisites

- Confirmed the target table to split (this page uses `D-ItemConfig-道具表.xlsx` as an example)
- Understand Luban's file prefix rules: `c` for client, `s` for server, `d` for all ends (`c/s/d` are used as group names in the configuration, see [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L15))
- All split files must be placed in the `Excels/Tables/` directory

## Steps

1. **Keep the original header, only split the data rows**

   Keep the original header row unchanged (column order, field names, comments, and default values must be exactly identical), and split the data rows into different files by business/value range. Place the new files under `Excels/Tables/`.

2. **Name files according to the naming rules**

   File name format: `<group前缀>-<bean名>-<表名>-<分段标识>.xlsx`. It is recommended to use a data range or business subcategory for the segment identifier. For example, splitting the `道具表` by item ID segments:

   ```text
   Excels/Tables/D-ItemConfig-道具表-道具-1001.xlsx
   Excels/Tables/D-ItemConfig-道具表-道具-2001.xlsx
   Excels/Tables/D-ItemConfig-道具表-道具-3001.xlsx
   ```

   An example already exists in the repository: `Excels/Tables/D-ItemConfig-道具表-道具-1001.xlsx` represents segment 1001 of the item table.

3. **Declare the main table name only once in `__tables__.xlsx`**

   The table name (`ItemConfig`) in `Excels/__tables__.xlsx` only needs to be registered once; all segment files with the same table name will be merged automatically. There is no need to register each segment separately.

4. **Run the generation script to verify**

   Run the corresponding script in the project root directory (using server JSON output as an example):

   ```bash
   gen-server-json.bat   # Windows
   ./gen-server-json.sh  # Linux/macOS
   ```

   For the generation script configuration, see [gen-server-json.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-json.sh); the corresponding command template comes from [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94). If there are no errors and the output JSON contains all segment IDs, the split was successful.

## Common Variants

| Variant | Naming Example | Applicable Scenario |
|------|----------|----------|
| Split by group | `C-AchievementConfig-成就表.xlsx` + `S-AchievementConfig-成就表.xlsx` | Client/server fields differ significantly and are maintained separately |
| Split by value range | `D-ItemConfig-道具表-道具-1001.xlsx`, etc. | Data is divided by ID segments and assigned to different designers for maintenance |
| Split by business subcategory | `D-ItemConfig-道具表-装备.xlsx` / `D-ItemConfig-道具表-消耗品.xlsx` | Data within the table is naturally categorized by business |

## Common Errors

- **Inconsistent headers**: The column definitions in row 1 of each segment file must be exactly identical (including column order, comments, and types); otherwise Luban will report errors or the fields will be misaligned.
- **Duplicate registration in `__tables__.xlsx`**: Do not register each segment file individually; register the main table name (`ItemConfig`) only once.
- **Segment identifier contains special characters**: Do not use spaces, `#`, `/`, etc. in segment identifiers within file names; only use Chinese characters, letters, numbers, and `-`.
- **Mixing fields across groups**: Multiple segments of the same table must be attached to the same group (`c`/`s`/`d`); otherwise the generation target will miss data.
- **Forgetting to change the group prefix**: Accidentally naming a client table `S-...` will make the client target unable to read fields.

## Background (Optional)

Luban scans all xlsx files under `Excels/Tables/` that match the prefixes and table names registered in `Excels/__tables__.xlsx`, merges them, and outputs the result to the target directory. The group prefix (`c`/`s`/`d`) corresponds to the groups defined in `luban.conf`, which determines which segment files go into which target.
