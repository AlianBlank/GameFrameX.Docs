# ホットアップデート後にプレイヤーデータや Actor 状態が異常になった場合の対処法

ホットアップデートは `IHotfixBridge` ブリッジインターフェースを通じて、ステータス層(Apps)の呼び出しをロジック層(Hotfix)に転送します。ブリッジ実装が正しいアセンブリに配置されていない場合や、ホットアップデート後に旧バージョンの DLL がアンロードされていない場合、プレイヤーデータの不整合や Actor 状態の異常が発生します。このページでは、エラーメッセージから修正箇所までを直接特定する手順を示します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| コンパイル時に `GFX0004: Type 'X' implements IHotfixBridge and must be defined in assembly 'GameFrameX.Hotfix', not 'Y'` が出る | `IHotfixBridge` 実装クラスが `GameFrameX.Hotfix` アセンブリ以外に配置されている | ブリッジクラスを `GameFrameX.Hotfix` プロジェクトに移動する(後述「修正手順 1」を参照) |
| ホットアップデート後にプレイヤーデータが消失し、属性がデフォルト値に戻る | ホットアップデート用アセンブリが差し替えられず、ステータス層が旧バージョンのブリッジを呼び続けている | `bin/` 下の旧 DLL を削除し、ホットアップデートを再実行する(後述「修正手順 2」を参照) |
| Actor は呼び出しを受信するがメソッドのバージョンが不整合(一部の呼び出しは新ロジック、一部は旧ロジックを通る) | AppDomain 内に複数の `IHotfixBridge` 実装が残っている | プロジェクト全体で `IHotfixBridge` 実装が 1 つだけであること、かつ `GameFrameX.Hotfix` に配置されていることを確認する(後述「修正手順 3」を参照) |
| 実行時に `HotfixHandler` のリフレクションが見つからないエラーが出る | マーカークラスが削除されたか、namespace が変更された | `GameFrameX.Hotfix.HotfixHandler` 静的クラスを保持し、名前を変更しないこと |

## 修正手順

### 1. ブリッジクラスは `GameFrameX.Hotfix` アセンブリに配置する

アーキテクチャアナライザーはコンパイル時に `IHotfixBridge` の実装場所を検証し、ルール違反の場合は `GFX0004` を直接エラーとして報告します:

```csharp
// GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs
private static readonly DiagnosticDescriptor SDescriptor = new DiagnosticDescriptor(
    "GFX0004",
    "IHotfixBridge must be defined in GameFrameX.Hotfix",
    "Type '{0}' implements IHotfixBridge and must be defined in assembly '{1}', not '{2}'",
    ArchitectureAnalyzerConstants.Category,
    DiagnosticSeverity.Error,
    true);
```

Source: [HotfixBridgeAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HotfixBridgeAssemblyAnalyzer.cs#L22-L28)

修正方法:

1. ソリューション内でエラーが出ている実装クラスが含まれる `.cs` ファイルを開きます。
2. そのファイルを `GameFrameX.Hotfix/StartUp/` ディレクトリに移動し、ファイル冒頭の namespace を `GameFrameX.Hotfix.StartUp` に変更します。
3. ファイル先頭に `internal partial class AppStartUpHotfixGame : AppStartUpBase, IHotfixBridge` が含まれていることを確認します(既存のエントリーポイントを参照してください)。
4. ソリューションを再ビルドし、`GFX0004` エラーが消えたことを確認します。

### 2. ホットアップデート用 DLL を実際に差し替える

ステータス層(Apps)からロジック層(Hotfix)への呼び出しは完全に `IHotfixBridge` に依存しています。旧バージョンの DLL がアンロードされないままだと、プレイヤーデータのシリアライズ/デシリアライズには旧スキーマが使用され、「ホットアップデート後に状態が異常」というように見えます。修正手順:

1. 稼働中のすべての GameFrameX.Server プロセスを停止します。
2. サービスの出力ディレクトリから `GameFrameX.Hotfix.dll`(および対応する `.pdb`)と `hotfix/` リソースディレクトリを削除します。
3. 新しくコンパイルした `GameFrameX.Hotfix.dll` をホットアップデート用ディレクトリにコピーします(バージョン番号は現在のオンライン版より大きいものにします)。
4. サービスを起動し、ホットアップデート処理を 1 回トリガーします。ログでロードされた DLL のバージョン番号を確認します。
5. テストアカウントでログインし、ブリッジ呼び出しを含む操作をトリガーして、データが正しく DB に書き込まれることを確認します。

### 3. プロジェクト全体で `IHotfixBridge` 実装を 1 つだけにする

複数のクラスが `IHotfixBridge` を実装している場合(新旧バージョンが併存する場合など)、Actor はそのうちの 1 つにランダムにバインドされ、ステータス層から見えるメソッドのバージョンとロジック層のバージョンが不整合になります。修正手順:

1. プロジェクト全体を検索し、`: IHotfixBridge` の実装が 1 か所だけであることを確認します:

   ```bash
   grep -rn "IHotfixBridge" --include="*.cs"
   ```

2. 複数見つかった場合は、`GameFrameX.Hotfix/StartUp/AppStartUpHotfixGame*.cs` 内の実装を残し、それ以外を削除または統合します。
3. 再コンパイルし、`GFX0004` で「重複定義」が報告されないことを確認します。

### 4. `HotfixHandler` マーカークラスを削除しない

`HotfixHandler` は空のクラスですが、リフレクションのエントリーポイントとしての役割を担っています。これを削除すると、ホットアップデートエンジンがマーカーを検出できなくなります:

```csharp
// GameFrameX.Hotfix/HotfixHandler.cs
namespace GameFrameX.Hotfix;

/// <summary>
/// このクラスのドキュメントはホットアップデートマーカーの処理用です。削除しないでください。リフレクション呼び出しに使用されます
/// </summary>
public static class HotfixHandler
{
}
```

Source: [HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8)

ログに「`HotfixHandler` が見つからない」や「リフレクションマーカーが存在しない」が出力された場合は、上記のコードどおりに空のクラスを `GameFrameX.Hotfix` プロジェクトに追加し直してください。

## 検証

修正完了後、以下の順序で検証します:

1. ソリューションをビルドし、`GFX0004` および他の `GFX####` エラーが出ていないことを確認します。
2. サービスを起動し、起動ログでホットアップデートモジュールの DLL バージョン番号を確認し、ローカルビルドのバージョンと一致していることを確認します。
3. テストアカウントでログインし、`IHotfixBridge` メソッドを呼び出すビジネスロジック(例:ログイン、メール報酬受け取り、属性変更)をトリガーして、DB のレコードが期待どおりであるかを確認します。
4. 1 回ホットアップデートを模擬し(DLL を差し替え)、手順 3 を繰り返します。ホットアップデート前後で動作が一貫しており、データが巻き戻っていないことを確認します。

## 背景

`IHotfixBridge` はステータス層(Apps)とロジック層(Hotfix)の唯一の呼び出しチャネルです。アーキテクチャアナライザー(`HotfixBridgeAssemblyAnalyzer`)は実装を `GameFrameX.Hotfix` アセンブリに限定し、ホットアップデート時にまとめて差し替えられることを保証します。ステータス層はインターフェースへの参照のみを保持するため、差し替え処理はプレイヤーには感知されません。ブリッジが破壊されたり、旧 DLL が残留したりすると、Actor とプレイヤーデータに「新ロジック書き込み・新読み出し」や「新旧混在」のような不整合が発生します。本手順はこれら 2 種類の根本原因に対応しています。
