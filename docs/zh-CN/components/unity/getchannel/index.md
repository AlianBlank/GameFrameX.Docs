# 安装与运行示例

本页带你把 GameFrameX GetChannel（`com.gameframex.unity.getchannel`）安装进 Unity 项目，并跑通第一个获取渠道号的示例。该包支持 iOS / tvOS / visionOS / Android / Editor / PC / WebGL / UWP / 主机平台，要求 Unity 2019.4 及以上。

## 快速开始

### 前置条件

- Unity 2019.4 或更高版本（见 [package.json](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/package.json#L5) 中 `"unity": "2019.4"`）。
- 能访问 GameFrameX UPM 注册表（`https://gameframex.upm.alianblank.uk`）或 GitHub。

### 安装（四种方式任选其一）

1. 编辑项目 `Packages/manifest.json`，添加 `scopedRegistries` 并在 `dependencies` 中指定版本（当前为 `1.3.2`）：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.getchannel": "1.3.2"
  }
}
```

`scopes` 控制哪些包通过此注册表解析，只有以 `com.gameframex` 开头的包才会从这个注册表获取。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L36-L54)

2. 直接在 `manifest.json` 的 `dependencies` 节点下添加 Git 地址：

```json
{
  "dependencies": {
    "com.gameframex.unity.getchannel": "https://github.com/gameframex/com.gameframex.unity.getchannel.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L56-L61)

3. 在 Unity 的 `Package Manager` 窗口选择 `Add package from git URL`，输入 `https://github.com/gameframex/com.gameframex.unity.getchannel.git`。
4. 直接下载仓库放置到 Unity 项目的 `Packages` 目录下，Unity 会自动加载识别。

**验证安装**：打开 `Window → Package Manager`，在包列表中能看到 `Game Frame X Get Channel`（displayName 见 [package.json](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/package.json#L2-L4)）即安装成功。

### 运行第一个示例

1. 在 `Package Manager` 中选中该包，展开 `Samples`，点击 `Import` 导入示例（示例定义于 [package.json](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/package.json#L12-L18)，路径 `Samples~`，其中包含示例脚本 [BlankGetChannelExample.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Sample~/BlankGetChannelExample.cs#L12)）。
2. 新建脚本调用 `BlankGetChannel.GetChannelName`：

```csharp
using UnityEngine;

public class MyGameScript : MonoBehaviour
{
    void Start()
    {
        // 获取默认渠道号（键名为 "channel"）
        string channel = BlankGetChannel.GetChannelName();
        Debug.Log("当前渠道号: " + channel);

        // 获取指定键的渠道号
        string customChannel = BlankGetChannel.GetChannelName("channelName");
        Debug.Log("自定义渠道号: " + customChannel);

        // 获取渠道号，并指定默认值
        string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
        Debug.Log("子渠道号: " + subChannel);
    }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L103-L123)

API 真实签名为（`channelKey` 默认 `"channel"`，`defaultValue` 默认 `"default"`）：

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98)

3. 按 `Play`，Console 中会输出当前渠道号；若未配置任何渠道文件，则返回 `default`。

## 常见变体：各平台提供渠道号

调用 `GetChannelName(key)` 时，`key` 必须与对应平台配置中的键名一致。

| 平台 | 配置位置 | 示例 |
|------|----------|------|
| iOS / tvOS / visionOS | Xcode 项目的 `Info.plist` | `<key>channel</key>` → `ios_cn_taptap` |
| Android | `AndroidManifest.xml` 中 `<application>` 内的 `<meta-data>` | `android:name="channel"` → `android_cn_taptap` |
| Editor / PC / WebGL / UWP / PS4 / PS5 / Xbox One / Nintendo Switch | `Resources/application_config.txt` | `channel=editor_cn_test` |

Android 的 `AndroidManifest.xml` 写法：

```xml
<application ...>
    <activity ...>
        ...
    </activity>

    <meta-data
        android:name="channel"
        android:value="android_cn_taptap" />

    <meta-data
        android:name="sub_channel"
        android:value="beta" />
</application>
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L150-L165)

Editor / PC / WebGL / UWP / 主机平台在 `Resources` 下创建 `application_config.txt`，每行 `键名=值`：

```
channel=editor_cn_test
sub_channel=beta
other_key=other_value
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L175-L179)

iOS 端无需手动配置也能跑通：构建后处理器会在 `Info.plist` 中**没有** `channel` 键时自动写入 `channel = default`，已存在则跳过：

```csharp
[PostProcessBuild(99)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        Run(path);
    }
    catch (Exception e)
    {
        Debug.LogException(e);
    }
}
```

Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L13-L29)

## 常见错误

- **返回值总是 `default`**：`GetChannelName(key)` 的 `key` 与平台配置中的键名不一致。请分别核对 iOS 的 `Info.plist`、Android 的 `<meta-data android:name="...">`、Editor/PC 的 `application_config.txt` 键名。
- **iOS 打包后渠道被覆盖**：构建后处理器只在 `Info.plist` 中不存在 `channel` 键时写入 `default`，已存在则输出日志 `已有渠道,跳过设置=>...` 并不做修改（见 [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L39-L48)）。确认你在 Xcode 中修改的是最终打包工程的 `Info.plist`。
- **PC / Editor 平台读不到值**：`application_config.txt` 必须放在 Unity 项目的 `Resources` 文件夹下，且每行格式严格为 `键名=值`。
- **代码被裁剪**：包内已带 `link.xml` 防止 Unity 代码裁剪移除相关 API；若你自行裁剪配置覆盖了它，请保留该文件（见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.zh-CN.md#L191)）。

## 背景

`GetChannelName` 会对读取结果做缓存，避免重复读取配置文件。iOS 侧通过 `DllImport("__Internal")` 的 `getChannelName(string channelKey)` 原生调用读取 `Info.plist`（见 [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L47-L48) 与 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm)）。关于各平台渠道配置的完整说明，见《渠道号配置参考》。
