# How to Create Named FSMs (Multiple Instances of the Same Type)

When the same owner type needs to have multiple independent state machines (for example, multiple NPCs in a scene each running their own AI, or multiple projectiles each running their own state flow), use the **named overload** of `CreateFsm`, distinguishing instances by different `name` values, and access them by name via `GetFsm<T>(name)` / `DestroyFsm<T>(name)`.

## Prerequisites

- The `com.gameframex.unity.fsm` package has been installed and `FsmManager` has been started with `FsmComponent` (see "Fsm Introduction" for details).
- Several `FsmState<T>` subclasses have been defined for the owner type.

## Steps

1. **Create a named FSM using `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)`**. Creating a duplicate named FSM will throw `GameFrameworkException("Already exist FSM '{0}'.")`s, so each instance's `name` must be unique.

```csharp
using GameFrameX.Fsm.Runtime;

// owner can be different objects, or different instances of the same type
var npcAi1 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_001", new MyNpc(), idleState, patrolState, attackState);

var npcAi2 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_002", new MyNpc(), idleState, patrolState, attackState);
```

Source: [FsmManager.cs#L319-L330](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L319-L330)

2. **Retrieve and start the FSM by name**. The nameless overload `GetFsm<T>()` only returns the "default" FSM under the same owner type; named FSMs must use `GetFsm<T>(string name)`.

```csharp
var fsm = GameEntry.GetModule<IFsmManager>().GetFsm<MyNpc>("NPC_001");
fsm.Start<PatrolState>();
```

Source: [FsmManager.cs#L239-L242](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L239-L242)

3. **Check or destroy by name**. `HasFsm<T>(name)` / `DestroyFsm<T>(name)` correspond one-to-one with creation; call `DestroyFsm` before the object is destroyed, otherwise the dictionary inside `FsmManager` will hold stale references.

```csharp
var mgr = GameEntry.GetModule<IFsmManager>();
if (mgr.HasFsm<MyNpc>("NPC_001"))
{
    mgr.DestroyFsm<MyNpc>("NPC_001");
}
```

Source: [FsmManager.cs#L182-L186](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L182-L186) · [FsmManager.cs#L397-L401](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L397-L401)

4. **Debug and locate via `FullName`**. `FsmBase.FullName` returns the string representation of `TypeNamePair`, which can be used in logs to distinguish multiple instances.

```csharp
Debug.Log(npcAi1.FullName); // for example "MyNpc(NPC_001)"
```

Source: [FsmBase.cs#L67-L70](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs#L67-L70)

## Common Variations

**State collection in List form**: The same naming rules apply to the `CreateFsm<T>(string name, T owner, List<FsmState<T>> states)` overload.

```csharp
var states = new List<FsmState<MyNpc>> { idleState, patrolState, attackState };
GameEntry.GetModule<IFsmManager>().CreateFsm<MyNpc>("NPC_003", new MyNpc(), states);
```

Source: [FsmManager.cs#L354-L365](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L354-L365)

**Access by `Type` (without generics)**: You can use `GetFsm(Type ownerType, string name)` / `HasFsm(Type ownerType, string name)` / `DestroyFsm(Type ownerType, string name)` in scenarios where only `Type` information is available.

## Common Errors

| Symptom | Cause | Workaround |
|------|------|------|
| `Already exist FSM 'MyNpc(NPC_001)'` | An FSM with the same name already exists; the nameless overload defaults `name = string.Empty`, so nameless calls are mutually exclusive | Use a unique `name` for each instance; destroy the old one before creating |
| `GetFsm<MyNpc>()` returns `null` | Without passing `name`, it only matches the FSM with an empty name | Use `GetFsm<MyNpc>("NPC_001")` instead |
| `Owner type is invalid` | Passing `null` when using the `Type` overload | Check for non-`null` before calling |
