# NetworkComponent API クイックリファレンス

本ページでは、`GameFrameX.Network.Runtime.NetworkComponent`（Unity シーン内の GameFramework オブジェクトにアタッチされるネットワークコンポーネント）が外部に公開するすべての公開 API、Inspector シリアライズ設定項目、および転送されるイベントを収録しており、導入時に素早く参照できます。コンポーネントはメニュー `GameFrameX/Network` にあり、`[DisallowMultipleComponent]` 属性が付与されており、シーンごとに 1 インスタンスのみ存在します。内部では `INetworkManager` を通じて実際の処理を行い、マネージャーイベントを `EventComponent` のイベントブロードキャストに変換します。

## 公開 API

| 名称 | シグネチャ | 説明 |
|------|------|------|
| NetworkChannelCount | `public int NetworkChannelCount { get; }` | ネットワークチャンネル数を取得します |
| HasNetworkChannel | `public bool HasNetworkChannel(string channelName)` | 指定されたネットワークチャンネルが存在するかを確認します。`channelName` は空にできず、空の場合は `GameFrameworkGuard.NotNullOrEmpty` によって例外がスローされます |
| GetNetworkChannel | `public INetworkChannel GetNetworkChannel(string channelName)` | 指定されたネットワークチャンネルを取得します |
| GetAllNetworkChannels | `public INetworkChannel[] GetAllNetworkChannels()` | すべてのネットワークチャンネルを取得します（配列を返します） |
| GetAllNetworkChannels | `public void GetAllNetworkChannels(List<INetworkChannel> results)` | すべてのネットワークチャンネルを取得します（呼び出し元のリストに格納し、割り当てを回避します） |
| CreateNetworkChannel | `public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)` | ネットワークチャンネルを作成し、コンポーネントに設定されたログ無視 ID リストと RPC タイムアウトをチャンネルに渡します |
| DestroyNetworkChannel | `public bool DestroyNetworkChannel(string channelName)` | ネットワークチャンネルを破棄し、成否を返します |

上記のシグネチャはすべて [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L71-L194) から引用しています。

ネットワークチャンネルの作成は最もよく使われるエントリーポイントです。実際のコードは以下の通りです（作成後にログ無視 ID と RPC タイムアウトが自動的に適用される点に注意）：

```csharp
[UnityEngine.Scripting.Preserve]
public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
{
    GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
    var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
    networkChannel.SetIgnoreLogNetworkIds(m_IgnoredSendNetworkIds, m_IgnoredReceiveNetworkIds);
    return networkChannel;
}
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L182)

## Inspector シリアライズ設定項目

| 設定項目 | 型 | デフォルト値 | 説明 |
|--------|------|--------|------|
| m_IgnoredSendNetworkIds | `List<int>` | 空 | 送信ネットワークメッセージ ID のログ出力を無視します |
| m_IgnoredReceiveNetworkIds | `List<int>` | 空 | 受信ネットワークメッセージ ID のログ出力を無視します |
| m_rpcTimeout | `int` | `5000` | RPC タイムアウト時間（ミリ秒）。チャンネル作成時に `INetworkManager.CreateNetworkChannel` へ渡されます |
| m_FocusHeartbeat | `bool` | `false` | アプリケーションがフォーカスを取得/失った際にハートビートパケットを送信するかどうか |

出典：[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L50-L68)。`m_FocusHeartbeat` の有効化ロジックは `OnApplicationFocus` 内で `m_NetworkManager.SetFocusHeartbeat(hasFocus)` を呼び出し、`SetFocusHeartbeat: {hasFocus}` のログを出力します（[L83-L92](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L83-L92)）。

## 初期化とイベント転送

コンポーネントは `Awake` 内で `GameFrameworkEntry.GetModule<INetworkManager>()` を通じてネットワークマネージャーモジュールを取得します。null の場合は `Log.Fatal("Network manager is invalid.")` が出力され、その後 4 つのマネージャーイベントを購読します。`Start` では `EventComponent` を取得し、null の場合は `Log.Fatal("Event component is invalid.")` が出力されます。

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L97-L123)

マネージャーイベントからゲームイベントへの転送マッピング（いずれも `m_EventComponent.Fire(this, ...)` でブロードキャストされ、`m_EventComponent == null` の場合はスキップされます）：

| マネージャーイベント（INetworkManager） | ブロードキャストされるゲームイベント（GameFrameX.Event） | 付随データ |
|------|------|------|
| NetworkConnected | `NetworkConnectedEventArgs` | `NetworkChannel`、`UserData` |
| NetworkClosed | `NetworkClosedEventArgs` | `NetworkChannel`、`Reason`、`ErrorCode` |
| NetworkMissHeartBeat | `NetworkMissHeartBeatEventArgs` | `NetworkChannel`、`MissCount` |
| NetworkError | `NetworkErrorEventArgs` | ソースコードには完全には記載されていません（転送ロジックは上記と同じです） |

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
m_NetworkManager.NetworkMissHeartBeat += OnNetworkMissHeartBeat;
m_NetworkManager.NetworkError += OnNetworkError;
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L109-L112)

`NetworkClosed` を例とした転送の実装：

```csharp
private void OnNetworkClosed(object sender, NetworkClosedEventArgs eventArgs)
{
    if (m_EventComponent == null)
    {
        return;
    }

    var networkClosedEventArgs = NetworkClosedEventArgs.Create(eventArgs.NetworkChannel, eventArgs.Reason, eventArgs.ErrorCode);
    m_EventComponent.Fire(this, networkClosedEventArgs);
}
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L207-L216)

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| ログに `Network manager is invalid.`（Fatal）が出力される | `Awake` 内で `INetworkManager` モジュールを取得できなかった | GameFrameX モジュールの登録/初期化順序を確認し、`GameFrameworkEntry` にネットワークモジュールが含まれていることを確認します |
| ログに `Event component is invalid.`（Fatal）が出力される | シーンに `EventComponent` が存在しない | GameFramework オブジェクト上で Event コンポーネントが存在すること、および本コンポーネントの `Start` より前に利用可能であることを確認します |
| API 呼び出しで引数の例外がスローされる | `channelName` が null または空文字列 | 空でないチャンネル名を渡します。チャンネル名を引数に取るすべての API には `GameFrameworkGuard.NotNullOrEmpty` による検証があります |
| ネットワークイベントのブロードキャストを受け取れない | `m_EventComponent` が null の場合、転送処理が即座に return する | 上記と同様、EventComponent が利用可能であることを保証します。ゲーム側は `EventComponent` を使用して対応する EventArgs を購読するように変更します |
