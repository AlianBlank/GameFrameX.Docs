# iOS / tvOS / visionOS 渠道配置

在 iOS、tvOS、visionOS 平台上，渠道資訊儲存於 Xcode 專案的 `Info.plist` 中。本套件會在建置時自動檢查 `Info.plist`，若不存在 `channel` 鍵，便會自動寫入預設值 `default`。在 Xcode 中將此值變更為實際渠道名稱後，即可於執行階段以 `BlankGetChannel.GetChannelName()` 讀取。

## 前置條件

- Unity 專案中必須已安裝本套件 `com.gameframex.unity.getchannel`（Unity 2019.4+）。
- 必須已切換至 iOS 建置目標（`File > Build Settings > iOS > Switch Platform`）。附註：建置後處理腳本以 `#if UNITY_IOS` 編譯，僅在 `BuildTarget.iOS` 時套用。

## 作業步驟

1. 在 Unity 中執行 iOS 建置（`Build` 或 `Build And Run`）以產生 Xcode 專案。建置完成後，腳本會自動處理產生的 `Info.plist`：

   ```csharp
   private static void Run(string path)
   {
       const string channelKey = "channel";
       const string channelValue = "default";

       string plistPath = path + "/Info.plist";
       PlistDocument plist = new PlistDocument();
       plist.ReadFromString(File.ReadAllText(plistPath));
       if (!plist.root.values.TryGetValue(channelKey, out var value))
       {
           plist.root.SetString(channelKey, channelValue);
           plist.WriteToFile(plistPath);
           Debug.Log("配置渠道成功=>" + channelValue);
       }
       else
       {
           Debug.Log("已有渠道,跳过设置=>" + value);
       }
   }
   ```

   來源：[PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

   此回呼掛鉤於 `[PostProcessBuild(99)]`，僅套用於 `BuildTarget.iOS`。處理過程中發生的例外會被捕捉，並以 `Debug.LogException` 輸出，不會中斷建置。

2. 開啟產生的 Xcode 專案，將 `Info.plist` 中 `channel` 的值變更為實際渠道名稱。視需要可新增其他鍵（例如：`sub_channel`）：

   ```xml
   <key>channel</key>
   <string>ios_cn_taptap</string>

   <key>sub_channel</key>
   <string>beta</string>
   ```

   來源：[README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L133-L141)

3. 在 C# 程式碼中讀取渠道：

   ```csharp
   using UnityEngine;

   public class MyGameScript : MonoBehaviour
   {
       void Start()
       {
           // Get default channel (key name is "channel")
           string channel = BlankGetChannel.GetChannelName();
           Debug.Log("Current channel: " + channel);

           // Get channel with a specific key
           string customChannel = BlankGetChannel.GetChannelName("channelName");
           Debug.Log("Custom channel: " + customChannel);

           // Get channel with a default fallback value
           string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
           Debug.Log("Sub channel: " + subChannel);
       }
   }
   ```

   來源：[README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L103-L123)

4. 於實機／模擬器上執行，確認 Console 輸出的渠道值與 `Info.plist` 中的值一致。

## 常見變化

- **自訂鍵名**：不一定需要使用預設鍵 `channel`，只要在 `Info.plist` 中定義任意鍵（例如：`channelName`），再呼叫 `BlankGetChannel.GetChannelName("channelName")` 即可。該鍵必須實際存在於 `Info.plist` 中。
- **多層渠道**：同時維護 `channel` 與 `sub_channel` 兩個鍵，並分別讀取主渠道與子渠道。
- **以備援值讀取**：API 的完整簽章如下

  ```csharp
  public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
  ```

  來源：[BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98)

  第二個參數用於指定在 C# 層讀取失敗時回傳的預設值。若未傳入，則為 `default`。

## 常見錯誤

- **Console 輸出 `unknown`**：原生層讀取 `Info.plist` 時若找不到對應的鍵，會回傳字串 `unknown`。請確認該鍵確實存在於 Xcode 專案的 `Info.plist` 中，且拼字與 C# 呼叫中的 `channelKey` 完全一致。相關實作請參考 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)。
- **變更渠道名稱後，重新建置又被覆寫回 `default`**：腳本只在鍵不存在時才會寫入。若在 Xcode 專案中變更 `channel` 後，又從 Unity 重新 Build 而覆寫了整個 Xcode 專案目錄，則需再次修改。若是增量建置且該鍵已存在，腳本會略過並輸出 `已有渠道,跳过设置=>...`。
- **tvOS / visionOS 建置後 `Info.plist` 未寫入**：後處理腳本以 `BuildTarget.iOS` 為判斷依據，因此請確認該平台是透過 iOS 建置管線進行轉換並產生專案後才套用。若鍵未被寫入，可直接在 Xcode 中手動新增 `channel` 鍵。

## 驗證

- 若 Unity Console 出現 `配置渠道成功=>default`（首次）或 `已有渠道,跳过设置=>xxx`（已存在），即表示後處理腳本已執行。請參考 [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L43-L48)。
- 可在 Xcode 中開啟 `Info.plist`，檢查 `channel` 鍵及其目前的值。
- 執行 App 時，`BlankGetChannel.GetChannelName()` 回傳的值會與 `Info.plist` 中的值一致。若鍵不存在，則回傳 `unknown`。

## 背景

iOS 原生外掛程式會從 `[[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"]` 讀取主要 Bundle 的 `Info.plist` 字典，以傳入的鍵名取得值，轉換為 C 字串後回傳給 C# 層。若無法取得值，則回傳 `unknown`。這就是渠道值必須配置於 `Info.plist`、且鍵名必須與呼叫參數一致的原因。實作請參考 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)。

關於 Android 渠道配置，請參考《Android 渠道配置》。Editor/PC/WebGL 等平台使用 `Resources/application_config.txt`，詳細內容請參閱 README。
