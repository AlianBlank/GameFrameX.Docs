# 우선순위와 동시성으로 재생 요청을 제어하는 방법

`PlaySoundParams.Priority`와 사운드 그룹의 `AvoidBeingReplacedBySamePriority` 스위치를 통해, 동일한 사운드 그룹 내 여러 동시 재생 요청 간의 선점 동작을 제어할 수 있습니다: 우선순위 숫자가 클수록 우선되며, 선점이 발생하면 새 요청으로 교체됩니다.

## 사전 조건

- `GameFrameX.Sound.Runtime`을 통해 사운드 그룹을 등록하고, 사운드 그룹에 하나 이상의 사운드 에이전트(`SoundAgent`)를 할당했습니다.
- 호출자가 `ISoundManager` 인스턴스를 가져올 수 있습니다(보통 `GameEntry.Sound`를 통해).

## 작업 단계

1. 재생 전에 참조 풀을 통해 매개변수 객체를 생성하고, 우선순위를 설정한 후 `PlaySound` 오버로드에 전달합니다:

```csharp
using GameFrameX.Sound.Runtime;

var p = PlaySoundParams.Create(isLoop: false);
p.Priority = 100; // 숫자가 클수록 우선됨
p.FadeInSeconds = 0.1f;

int serialId = GameEntry.Sound.PlaySound("sfx/click", "SoundEffect", p);
```

출처: [PlaySoundParams.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundParams.cs#L105-L239)

2. 사운드 그룹에 동일 우선순위 간 상호 선점 허용 여부를 설정합니다. 기본적으로, 새 요청의 우선순위가 현재 재생 중인 사운드보다 **엄격히 큰 경우에만** 교체됩니다; 동일 우선순위도 새 사운드로 교체되기를 원한다면 스위치를 켜세요:

```csharp
ISoundGroup group = GameEntry.Sound.GetSoundGroup("SoundEffect");
group.AvoidBeingReplacedBySamePriority = false; // 동일 우선순위도 선점됨
```

출처: [ISoundGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Interface/ISoundGroup.cs#L50-L53)

3. 재생 실패 이벤트를 수신하여 "우선순위로 인해 무시된" 요청을 캡처하고, 추적 또는 폴백 로직에 사용합니다:

```csharp
GameEntry.Sound.PlaySoundFailure += (sender, args) =>
{
    if (args.ErrorCode == PlaySoundErrorCode.IgnoredDueToLowPriority)
    {
        // 현재 그룹 내 에이전트가 가득 차 있고, 우선순위가 선점하기에 부족하여 폐기됨
    }
};
```

출처: [PlaySoundErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundErrorCode.cs#L60-L64)

## 일반적인 변형

- **핵심 음성은 절대 중단되지 않도록 하기**: 대사/스토리 음성 재생 시, `Priority`를 일반 음향 효과보다 훨씬 높은 값(예: 1000)으로 설정하고, 해당 그룹의 `AvoidBeingReplacedBySamePriority`를 `true`로 유지하면, 동일 우선순위 BGM이 이를 밀어내지 못합니다.
- **동일 그룹 내 다중 에이전트로 높은 동시성**: `SoundEffect` 그룹에 여러 `SoundAgent`(예: 8~16개)를 할당하여 대부분의 짧은 음향 효과가 병렬로 재생되도록 하고, 새 요청이 에이전트조차 확보하지 못할 때만 우선순위 판정을 진행합니다.
- **동시성 상한만 설정**: 우선순위를 구분하지 않고 동일 그룹 내 동시 재생 수량만 제한하려면, 모든 요청이 기본 우선순위(`Constant.DefaultPriority`)를 사용하게 하고 `AvoidBeingReplacedBySamePriority = true`를 유지하면, 가장 먼저 추가된 사운드가 새 요청에 의해 밀려납니다.

## 흔한 실수

- **우선순위를 볼륨이나 음조로 착각**: `Priority`는 정수형이며, 선점 판정에만 사용되고 `VolumeInSoundGroup`, `Pitch`와는 무관합니다.
- **동일 우선순위도 교체되기를 기대하지만 스위치를 변경하지 않음**: 기본값은 `AvoidBeingReplacedBySamePriority = true`이며, 새 사운드의 우선순위가 재생 중인 사운드보다 엄격히 높아야 선점할 수 있고, 그렇지 않으면 `IgnoredDueToLowPriority`를 반환합니다.
- **매개변수 객체 반환 잊음**: `PlaySoundParams`는 참조 풀에서 가져오는 것이므로, 사용 후 즉시 `ReferencePool.Release(p)`를 호출하여 장기 보유로 인한 상태 오염을 피해야 합니다.
- **그룹 내 사용 가능한 에이전트 없이 재생 트리거**: 그룹에 에이전트가 할당되지 않은 경우에도 마찬가지로 실패하므로, 먼저 `SoundGroup.SoundAgentCount > 0`인지 확인하세요.

## 배경(선택 사항)

`ISoundAgent`와 `ISoundAgentHelper`는 모두 매 프레임 `Priority`를 하위 `AudioSource`에 동기화하며, 관리자는 "에이전트 + 우선순위" 모델로 선점을 판정합니다; 우선순위 수치는 상대적인 개념이므로, 비즈니스 측에서는 핵심 사운드 소스가 일반 사운드 소스보다 높다는 것만 보장하면 됩니다.
