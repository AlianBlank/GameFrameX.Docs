# JSON Configuration Hot Update (localization / achievement / item / sounds)

GameFrameX monitors changes to the JSON files under `GameFrameX.Config/json/` to hot-load local configurations such as localization, achievement, item, and sounds at runtime, allowing the latest copy/values to take effect in the game without restarting the process.

## Prerequisites

- Configuration files are located in the `GameFrameX.Config/json/` directory at the repository root (e.g., `local_tblocalization.json`, `tables_tbachievementconfig.json`).
- Configuration classes are automatically generated by Luban + the source generator into `GameFrameX.Config/Config/Local/` and `GameFrameX.Config/Config/Tables/`. After modifying the JSON, you must regenerate the code; otherwise, newly added fields will not be read.

## Steps

1. **Locate the JSON configuration directory**: All hot-updatable local table JSON files are placed in `GameFrameX.Config/json/`. The filename prefix `local_` indicates a local table, while `tables_` indicates a Luban main table.

2. **Modify the configuration content**: Edit the corresponding JSON directly. For example, to change a piece of multilingual copy:

   ```json
   [
     {
       "key": "ui_welcome",
       "ChineseSimplified": "欢迎回来",
       "ChineseTraditional": "歡迎回來",
       "English": "Welcome back",
       "Japanese": "おかえりなさい",
       "Korean": "환영합니다",
       "Thai": "ขอต้อนรับกลับมา",
       "Indonesian": "Selamat datang kembali",
       "French": "Bienvenue",
       "German": "Willkommen zurück",
       "Russian": "Добро пожаловать",
       "Italian": "Ben tornato",
       "PortuguesePortugal": "Bem-vindo de volta",
       "Spanish": "Bienvenido de vuelta",
       "Vietnamese": "Chào mừng trở lại"
     }
   ]
   ```

   See the auto-generated entity class for field definitions:
   [Localization.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Local/Localization.cs#L39-L56)

3. **Trigger hot loading**: The runtime process listens for write events in this directory; after saving the JSON file, the server re-reads and overwrites the in-memory tables without restarting.

4. **Make the code use the latest values**: The business side retrieves data through the auto-generated table accessors (such as `TbLocalization`, `TbAchievementConfig`), so no changes to the calling code are needed — just ensure the generator has been re-run based on the latest JSON.

## Common Variants

- **Add a new language column**: Append the column to the JSON and modify the Luban table structure accordingly. The hot update can only recognize the new column after the code is regenerated.
- **Add a new entry**: Append objects directly to the JSON array. The key names must follow the field naming of `BeanBase` subclasses (`Key`, `English`, etc.).

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| In-game copy does not change after saving the JSON | Entity class code was not regenerated, so newly added fields were not recognized | Re-run Luban + the source generator to regenerate `Localization.cs` etc. |
| Startup reports a `JsonElement` deserialization exception | JSON field names or casing do not match the generated class | Correct them according to the field names used in `GetProperty("...")` within `Localization.cs` |
| Old entries disappear after a hot update | The entire array file was overwritten instead of appending/modifying | Only modify the target entries and preserve the array structure |

## Background (Optional)

JSON tables are used by Luban to generate C# entity classes (marked `<auto-generated>`) at compile time; at runtime, they are parsed into `BeanBase` subclass instances via `JsonElement`. Hot updates are implemented through file system watching, so **the JSON must be written under `GameFrameX.Config/json/` and kept in sync with the generated code**; otherwise, deserialization will fail.
