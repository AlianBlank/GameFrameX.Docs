# 呼叫沒反應:參數為空警告速查

呼叫購買、消耗等介面後「沒有任何反應」(不彈出支付、不觸發事件)，通常是因為傳入參數為空或 null,`PaymentComponent` 在入口處就攔截並僅輸出一條 Warning 日誌後直接 `return`,請求根本沒發出去。對照下表找到日誌裡對應的警告原文，即可定位是哪個參數沒傳。

## 快速診斷

| 症狀(日誌原文) | 觸發位置/原因 | 修復 |
|------|------|------|
| `Product ID is null or empty.` | 呼叫 `Buy` / `BuyInApp` / `BuySubs` 時 `productId`(或 `PurchaseParams.ProductId`)為 null 或空字串 | 傳入商店後台設定的真實商品 ID/SKU,見下文「修復步驟 1」 |
| `Order ID is null or empty.` | 呼叫 `Buy` / `BuyInApp` / `BuySubs` 時 `orderId`(或 `PurchaseParams.OrderId`)為 null 或空字串 | 先在自家伺服器產生訂單編號再發起購買，見「修復步驟 2」 |
| `Purchase token is null or empty.` | 呼叫 `ConsumePurchase(purchaseToken)` 時購買權杖為空 | 從 `OnQueryPurchasesResult` / `OnPurchaseSuccess` 事件參數中取出真實 `PurchaseToken` 再消耗，見「修復步驟 3」 |
| `Purchase params is null.` | 呼叫 `Buy(PurchaseParams)` 時整個參數物件是 null | 用 `PurchaseParams` 子類別建構並賦值後再傳入，見「修復步驟 2」 |
| `Pay Manager is invalid.`(Fatal) | `Awake` 中 `GameFrameworkEntry.GetModule<IPaymentManager>()` 傳回 null,平台實作類別未正確載入 | 檢查 `PaymentComponent` Inspector 上平台元件類型欄位與對應通路包是否已引入，見「修復步驟 4」 |

以上警告都只 `Log.Warning` 後立即 `return`,不會拋出例外、也不會觸發 `OnPurchaseFailed` —— 所以現象就是「呼叫沒反應」。來源:[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L259)。

## 修復步驟

### 1. Product ID 為空

商品 ID 必須與商店後台設定的 SKU 完全一致(區分大小寫、注意前後空格)。建議用 `PurchaseParams` 子類別建構：

```csharp
// ProductId 在建構後仍會被驗證,為空同樣會打 Warning 並直接 return
var param = new SomeChannelPurchaseParams(productId: "coin_pack_100", orderId: orderNo, productType: PaymentProductType.InApp);
paymentComponent.Buy(param);
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

排查要點：

- 若是從設定表/伺服器讀商品 ID,先列印實際值確認非空:`Debug.Log($"[{productId}]");`
- 確認沒有把 `offerToken`、`customData` 這些「可空預設參數」的位置傳錯。
- `Buy(PurchaseParams)` 的驗證順序是：參數物件 null → `ProductId` 空 → `OrderId` 空，看日誌先出現哪條就能定位。

### 2. Order ID 為空或參數物件為 null

`OrderId` 是你自家伺服器的訂單編號，購買驗證會用到它，不允許為空。`PurchaseParams` 是抽象基底類別(`public abstract class PurchaseParams`),不能直接 `new`,必須使用各通路子類別；三個欄位(`ProductId`、`OrderId`、`ProductType`)透過建構函式賦值：

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)

常見陷阱：

- 訂單編號由非同步介面產生，購買按鈕在回呼前就被點了 —— 在回呼裡再啟用購買按鈕。
- 舊介面 `BuyInApp` / `BuySubs` / `Buy(string, PaymentProductType, ...)` 已標記 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`,但驗證行為一致，遷移時同樣要保證 `productId`、`orderId` 非空。

### 3. Purchase token 為空(消耗購買沒反應)

`ConsumePurchase` 只接受非空 `purchaseToken`:

```csharp
public void ConsumePurchase(string purchaseToken)
{
    if (string.IsNullOrEmpty(purchaseToken))
    {
        Log.Warning("Purchase token is null or empty.");
        return;
    }

    _paymentManager.ConsumePurchase(purchaseToken);
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L152)

正確做法是訂閱 `OnPurchaseSuccess` 或 `OnQueryPurchasesResult` 事件，從 `PaymentEventArgs` 中拿到真實權杖後再呼叫消耗。

### 4. Pay Manager is invalid(Fatal)

`PaymentComponent.Awake` 按平台選擇實作類別類型(`m_componentAndroidType`、`m_componentIOSType`、`m_componentWebGLType`、`m_componentPCType`、`m_componentMacType`),其餘平台回退到 `DefaultPaymentManager`。若 `GetModule<IPaymentManager>()` 傳回 null 會輸出 `Log.Fatal("Pay Manager is invalid.")`。檢查：

- Inspector 上平台類型字串是否被改壞(預設如 `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`);
- 對應通路包是否已匯入專案(類型不存在時 `Utility.Assembly.GetType` 解析失敗);
- 目前執行平台是否落在某個 `UNITY_*` 分支內，否則走 `DefaultPaymentManager` 空實作，支付本身也不會有反應。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 驗證

- 發起呼叫前在 Unity Console 篩選 Warning,確認不再出現上表任何一條日誌。
- 參數合法時，呼叫會繼續走到 `_paymentManager.Buy(...)` / `ConsumePurchase(...)`,隨後可訂閱 `OnPurchaseSuccess` / `OnPurchaseFailed` 事件確認支付鏈路被真正觸發(事件在 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64) 上透傳)。
- 用 `IsReady()` 確認支付系統已就緒再顯示購買入口，可避免大量「沒反應」類誤報。
