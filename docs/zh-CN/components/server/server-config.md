# 服务器启动参数与配置文件参考

服务器通过 `GameFrameX.AppHost` 入口读取命令行参数 `StartupOptions`，结合 `GameFrameX.Launcher` 内的 `AppSetting` 配置与 `GlobalSettings` 全局设置完成进程编排与启动。本页汇总启动参数、运行模式标志和日志相关配置项的真实签名与取值范围。

## 启动入口与运行模式

AppHost 入口解析参数后，根据 `IsSingleMode` 选择单进程或多进程编排：

```csharp
startupOptions = Foundation.Options.OptionsBuilder.CreateWithDebug<StartupOptions>(args);
if (startupOptions.IsSingleMode) { /* 单进程 */ }
else { /* 多进程 */ }
```

## 命令行参数速查（`StartupOptions`）

下表中的参数均通过 `Foundation.Options.OptionsBuilder.CreateWithDebug<StartupOptions>(args)` 绑定到 `StartupOptions` 实例，名称以 `--` 前缀传入。

| 参数 | 必填 | 说明 |
|------|------|------|
| `--ServerType` | 是 | 服务类型。单进程模式传单个值（如 `Game`），多进程模式传逗号分隔列表（如 `Game,Social`）。 |
| `--IsSingleMode` | 否 | 置为 `true` 时进入单进程模式，只允许一个 `--ServerType`。 |
| `--ServerId` | 否 | 业务服务器 ID；>0 时会写入日志 `LogTagName`。 |
| `--ServerInstanceId` | 否 | 服务器实例 ID；>0 时与 `ServerId` 组合成 `LogTagName`。 |
| `--TagName` / `--Note` / `--Label` / `--Description` | 否 | 四个备用标识，按优先级回退设置 `LogOptions.LogTagName`。 |
| `--LogIsConsole` | 否 | 是否输出到控制台，默认读取 `LogOptions.Default.IsConsole`。 |
| `--LogIsGrafanaLoki` | 否 | 是否启用 Grafana Loki 上报。 |
| `--LogGrafanaLokiUrl` | 否 | Loki 接收地址。 |
| `--LogGrafanaLokiUserName` / `--LogGrafanaLokiPassword` | 否 | Loki 凭据。 |
| `--LogRetainedFileCountLimit` | 否 | 保留的日志文件数量。 |
| `--LogIsFileSizeLimit` | 否 | 是否启用单文件大小限制。 |
| `--LogFileSizeLimitBytes` | 否 | 单文件大小阈值（字节）。 |
| `--LogEventLevel` | 否 | 最低日志等级。 |
| `--LogRollingInterval` | 否 | 日志滚动间隔。 |

带有 `GrafanaLokiLabelTagAttribute` 标记且非 `ServerType` 的属性，会被反射读取并写入 `LogOptions.Default.GrafanaLokiLabels`。

## 运行模式与报错原文

`StartupOptions` 中 `ServerType` 与 `IsSingleMode` 的取值会触发以下三类异常：

| 触发条件 | 异常原文 |
|----------|----------|
| 单进程模式未传 `--ServerType` | `单进程模式必须通过 --ServerType 指定服务类型，例如 --ServerType=Game` |
| 单进程模式传多个 `--ServerType`（含逗号） | `单进程模式不支持多个服务类型，请仅传一个 --ServerType 值，例如 --ServerType=Game` |
| 多进程模式未传或解析为空 | `多进程模式必须通过 --ServerType 指定服务列表，例如 --ServerType=Game,Social` 或 `ServerType 未解析到有效服务类型，请使用逗号分隔列表，例如 --ServerType=Game,Social` |

## 进程编排：单进程 vs 多进程

- **单进程（`IsSingleMode=true`）**：注册单个 `GameFrameX_Launcher` 项目，资源名为 `single-service`。
- **多进程（默认）**：按逗号拆分 `--ServerType`，每个类型注册一个 `{type}-service` 资源（如 `game-service`、`social-service`），并按顺序串接 `WaitFor`，形成启动链。

两者都会注入 MongoDB 资源 `mongo`（库名 `mongodb`）并 `WithReference`/`WaitFor`。

```csharp
var mongoDb = builder.AddMongoDB("mongo").WithLifetime(ContainerLifetime.Persistent);
mongoDb.AddDatabase("mongodb");
```

## 应用配置：`AppSetting` 与 `GlobalSettings`

Launcher 启动时通过 `GlobalSettings.GetSettings()` 获取配置集合，再按 `ServerType` 精确匹配：

```csharp
var appSettings = GlobalSettings.GetSettings();
var appSetting = appSettings.FirstOrDefault(m => m.ServerType == serverType);
if (appSetting != null) { /* 使用对应 AppSetting */ }
else { appSetting = launcherOptions; /* 回退到 StartupOptions 默认值 */ }
```

匹配失败时使用 `StartupOptions` 兜底，保证至少有默认配置可用。

Source: [GameFrameX.StartUp/GameApp.cs#L356-L399](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.StartUp/GameApp.cs#L356-L399)

未指定 `serverType` 时，会按 `sortedStartUpTypes` 顺序挑选首个存在 `AppSetting` 的启动类型执行。

## 启动项目与本地调试配置

| 项目 | 启动主机 | 备注 |
|------|----------|------|
| `GameFrameX.AppHost` | Aspire 分布式应用主机 | 读取 `StartupOptions`，按 `IsSingleMode` 编排。 |
| `GameFrameX.Launcher` | 单进程 / 多进程目标进程 | 每个服务类型最终都注册为 `GameFrameX_Launcher` 子进程。 |

`launchSettings.json` 用于 Visual Studio / `dotnet run` 的本地调试；可通过 `--ServerType` 与 `applicationUrl` 调试单个进程。

## 常见错误

| 现象 | 排查方向 |
|------|----------|
| 启动直接抛出 `单进程模式必须通过 --ServerType 指定服务类型` | 命令行漏传 `--ServerType`，或 `IsSingleMode=true` 但参数被 IDE 吞掉。 |
| `ServerType 未解析到有效服务类型` | `--ServerType` 全是空白或分隔符，需传至少一个有效类型。 |
| 多进程只启动一个服务 | `--ServerType` 未使用逗号，解析为单值；检查是否带空格或换行。 |
| Loki 标签缺失 | 属性未打 `GrafanaLokiLabelTagAttribute`，或反射时被 `ServerType` 名跳过。 |
