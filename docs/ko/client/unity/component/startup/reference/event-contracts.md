# 이벤트 및 알림 계약

시작 프로세스는 주요 노드에서 GameFrameX 이벤트 버스를 통해 결과를 브로드캐스트하며, 구독자는 StartupManager 내부 상태를 건드리지 않는 전제 하에 알림을 수신합니다. 이 페이지에는 모든 공개 이벤트 매개변수 유형, 이벤트 ID 및 사용 계약이 수록되어 있습니다.

## 이벤트 계약 빠른 참조 표

| 이벤트 매개변수 유형 | 이벤트 ID(EventId) | 트리거 시점 | 주요 필드 |
|--------------|------------------|----------|----------|
| `StartupCompletedEventArgs` | `GameFrameX.Startup.Runtime.Events.StartupCompletedEventArgs` | `ProcedureGameLauncherState`가 핫업데이트와 UI Dispose를 완료한 후 프로세스가 성공적으로 종료됨 | 없음 |
| `StartupFailedEventArgs` | `GameFrameX.Startup.Runtime.Events.StartupFailedEventArgs` | 임의의 Procedure가 네트워크 또는 비즈니스 실패로 인해 프로세스가 중단됨 | `FailedProcedureName`, `FailedUrl`, `ErrorMessage` |

이벤트 ID는 `typeof(X).FullName` 패턴을 채택하여 GameFrameX 전체 제품군과 일관성을 유지합니다. 구독 시 정적 필드 `EventId`를 사용하고, 문자열을 하드코딩하지 마세요.

## StartupCompletedEventArgs

시작이 성공적으로 완료되었음을 알리는 이벤트입니다. 프로세스가 `ProcedureGameLauncherState`에 도달하여 핫업데이트 로드와 UI Dispose를 완료한 후 한 번 트리거됩니다.

```csharp
public sealed class StartupCompletedEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(StartupCompletedEventArgs).FullName;
    public override string Id => EventId;

    public static StartupCompletedEventArgs Create()
    {
        return ReferencePool.Acquire<StartupCompletedEventArgs>();
    }

    public override void Clear()
    {
        // 필드 없음, 빈 구현
    }
}
```

구독 예시:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupCompletedEventArgs.EventId,
    (sender, args) =>
    {
        // 메인 씬 진입 또는 다음 모듈 로드
    });
```

## StartupFailedEventArgs

시작 실패 이벤트입니다. 임의의 Procedure가 네트워크 또는 비즈니스 실패로 인해 프로세스가 중단될 때 트리거됩니다.

```csharp
public sealed class StartupFailedEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(StartupFailedEventArgs).FullName;
    public override string Id => EventId;

    public string FailedProcedureName { get; private set; }
    public string FailedUrl { get; private set; }
    public string ErrorMessage { get; private set; }

    public static StartupFailedEventArgs Create(string procedureName, string url, string errorMessage)
    {
        var args = ReferencePool.Acquire<StartupFailedEventArgs>();
        args.FailedProcedureName = procedureName ?? string.Empty;
        args.FailedUrl = url ?? string.Empty;
        args.ErrorMessage = errorMessage ?? string.Empty;
        return args;
    }

    public override void Clear()
    {
        FailedProcedureName = string.Empty;
        FailedUrl = string.Empty;
        ErrorMessage = string.Empty;
    }
}
```

필드 설명:

| 필드 | 유형 | 설명 |
|------|------|------|
| `FailedProcedureName` | `string` | 실패가 발생한 위치의 Procedure 상태 이름입니다. `null`은 빈 문자열로 정규화됩니다 |
| `FailedUrl` | `string` | 마지막으로 시도하여 실패한 URL이며, 네트워크 실패가 아닌 경우 빈 문자열입니다 |
| `ErrorMessage` | `string` | 오류 설명 |

구독 예시:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(
    StartupFailedEventArgs.EventId,
    (sender, args) =>
    {
        var failed = (StartupFailedEventArgs)args;
        Debug.LogError($"启动失败:{failed.FailedProcedureName} {failed.ErrorMessage}");
    });
```

## 트리거 위치

이벤트는 `StartupProcedureUtility`를 통해 프로세스 종료 노드에서 일괄적으로 트리거됩니다:

```csharp
// 실패 경로
GameEntry.GetComponent<EventComponent>().Fire(
    procedureOwner,
    StartupFailedEventArgs.Create(procedureName, failedUrl, errorMessage));

// 성공 경로
GameEntry.GetComponent<EventComponent>().Fire(
    procedureOwner,
    StartupCompletedEventArgs.Create());
```

## 사용 계약

1. **new로 인스턴스를 생성하지 마세요**: 두 이벤트 매개변수 모두 `Create(...)` 정적 메서드를 통해 `ReferencePool`에서 획득하여 GC를 피합니다.
2. **Id를 수정하지 마세요**: 이벤트 ID는 `typeof(T).FullName`이며, GameFrameX 전체 제품군의 이벤트 프로토콜과 일치합니다.
3. **빈 문자열로 통일**: 실패 이벤트의 세 필드는 `Create` 시점에 `null`을 빈 문자열로 정규화하므로, 구독 측에서 별도의 null 체크가 필요 없습니다.
4. **수동으로 Clear하지 마세요**: 구독자는 이벤트 매개변수 참조를 보유해서는 안 됩니다. 이벤트 트리거 후 프레임워크가 참조 풀로 회수합니다.
