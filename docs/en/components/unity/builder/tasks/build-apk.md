# How to Build an APK Installer

By calling `GameFrameX.Builder.Editor.Builder.BuildApk()`, you can one-click package a Unity project into an Android APK and upload it to object storage on demand. This page provides command-line invocation, parameter descriptions, and troubleshooting for common errors.

## Prerequisites

1. This package (`com.gameframex.unity.builder`) is installed in the Unity Editor, and the Unity Editor platform has been switched to **Android**.
2. Android signing, SDK, NDK, JDK, and other environments are configured (see Unity's official Android Player Settings).
3. If you want to upload the APK to object storage, you need to add `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` to `BuildPipeline → PlayerSettings → Scripting Define Symbols`, and enable one of `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_TENCENT` / `_QI_NIU` / `_A_LI_YUN` as needed.

## Steps

### 1. Invoke directly in the Unity Editor

Open `Window → General → Search`, execute the menu item `Builder/BuildApk`, or call it from any editor script:

```csharp
using GameFrameX.Builder.Editor;

public static class MyBuildEntry
{
    public static void BuildApk()
    {
        GameFrameX.Builder.Editor.Builder.BuildApk();
    }
}
```

### 2. Invoke via command line in CI

Use `Unity.exe -batchmode -executeMethod` to trigger the build entry point, and control the build behavior through command-line arguments. See the table below for commonly used arguments.

| Command-line Argument | Meaning | Default Value |
|------------|------|--------|
| `-executeMethod` | The fully qualified name of the method to execute; here fill in `GameFrameX.Builder.Editor.Builder.BuildApk` | None |
| `-logFile` | Unity log output path; `/Unity/` will be replaced with `/` at the end of the log | None |
| `-BUILD_NUMBER` | Build number | None |
| `-JOB_NAME` | CI task name such as Jenkins | None |
| `-PackageName` | YooAsset package name | None |
| `-ChannelName` | Channel name | None |
| `-BundleId` | Android package name (BundleId) | None |
| `-AppVersion` | Application version | None |
| `-PackageVersion` | Asset package version | None |
| `-BuildPipeline` | Build pipeline type | None |
| `-Language` | Language | None |
| `-IsUploadApk` | Toggle: upload APK to object storage after build | `false` |
| `-IsUploadLogFile` | Toggle: upload log file | `false` |
| `-IsUploadAsset` | Toggle: upload assets | `false` |
| `-IsUpdateAssetPackageVersion` | Toggle: update remote asset package version number | `false` |
| `-UpdateAssetPackageVersionUrl` | URL of the version number update API | None |
| `-UpdateAssetPackageVersionAuthorization` | Authorization header for the version number update API | None |
| `-WeChatBotKey` | Enterprise WeChat bot Webhook Key (build result notification) | None |
| `-ObjectStorageKey / -ObjectStorageSecret / -ObjectStorageBucketName / -ObjectStorageEndPoint` | Object storage access credentials | None |

The parameter parsing logic is located in `Builder.BuildParamsParse`. Each `-xxx` is assigned to the corresponding field of `BuilderOptions` when immediately followed by a value.

```text
Unity.exe -batchmode -nographics -quit \
  -projectPath <ProjectPath> \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
  -logFile <LogPath>/builder.log \
  -BUILD_NUMBER 100 \
  -JOB_NAME nightly \
  -BundleId com.example.game \
  -AppVersion 1.0.0 \
  -PackageVersion 100 \
  -ChannelName official \
  -IsUploadApk \
  -WeChatBotKey <WeChatKey>
```

Source: [Editor/Builder.BuildParamsParse.cs#L13-L160](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L13-L160)

### 3. Output and Upload Path

`BuildApk` internally executes the actual packaging through `BuildProductHelper.BuildPlayerAndroid()`, producing the APK file path:

- The APK by default lands in the project build directory outside `Library/PlayerDataCache/...`. The specific path is determined by the `BuildProductHelper` output.
- When `-IsUploadApk` is passed, the save path uploaded to object storage is:
  `builder/{productName}/{activeBuildTarget}/{JobName}/{Application.version}/{BuildNumber}`.

Source: [Editor/Builder.cs#L47](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L47),[Editor/Builder.cs#L62-L78](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L62-L78)

## Common Variants

- **Local build only, no upload**: just omit `-IsUploadApk`.
- **Upload log simultaneously**: append `-IsUploadLogFile`, which uploads the log specified by `-logFile` to the same object storage path.
- **Enable object storage support**: enable the `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` macro in the Editor project used for packaging, and append one of `_TENCENT` / `_QI_NIU` / `_A_LI_YUN` according to the cloud vendor. The static constructor of `Builder` selects the corresponding `IObjectStorageUploadManager` implementation based on the macro.
- **Enterprise WeChat notification**: pass the bot Webhook Key via `-WeChatBotKey` to push the result after the build is complete.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Reports `Exception: InvalidOperationException` and the log indicates object storage is not enabled | `-IsUploadApk` was passed but the project does not have the `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` macro | Add the corresponding macro in PlayerSettings Scripting Define Symbols, or remove `-IsUploadApk` |
| Still reports "Build target not supported" after switching to the `Android` platform | The current `BuildTarget` is not Android when `BuildApk` is called | Ensure `EditorUserBuildSettings.activeBuildTarget == Android` |
| Parameters did not take effect, e.g., `BundleId` was not replaced | Command-line argument name misspelled or missing value | Use the format `-BundleId <value>` according to the table above; the value must immediately follow the argument name |
| Cannot find `GameFrameX.Builder.Editor.Builder.BuildApk` | Package not imported or class name misspelled | Confirm the package is installed in Package Manager; the full class name is `GameFrameX.Builder.Editor.Builder` |

## Background (Optional)

`Builder` is a `partial class`. Parameter parsing is in `Builder.BuildParamsParse`, and the actual APK generation is handled by the framework's internal `BuildProductHelper.BuildPlayerAndroid()`. The upload part is abstracted through `IObjectStorageUploadManager`. Currently three built-in implementations are provided: Tencent Cloud, Alibaba Cloud, and Qiniu Cloud, which only participate in compilation when the corresponding compilation macros are used.
