# 리소스를 로드할 수 없거나, 비어 있거나, 경로가 잘못된 경우 어떻게 해야 하나요

`AssetComponent.LoadAssetAsync`, `LoadAssetSync`, 각 타입의 확장 메서드(예: `LoadPrefabAsync`/`LoadAudioAsync`) 및 `AssetManager`의 인터페이스가 반환한 `AssetHandle`에서 유효한 객체를 가져올 수 없을 때, 이 페이지의 단계에 따라 문제를 진단하세요.

## 빠른 진단

| 증상 | 가능한 원인 | 해결 방법 |
|------|----------|------|
| `AssetHandle.AssetObject`이(가) `null`이거나 `GetAssetObject<T>()`이(가) `null`을 반환 | 리소스 경로 오류 / 리소스가 패키징되지 않음 / 리소스 패키지가 초기화되지 않음 | 「리소스 패키지 미초기화」「경로 오류」 해결 단계 참조 |
| `Asset manager is invalid.` 치명적 로그 출력 | `_assetManager`를 가져오지 못함 (모듈 누락 또는 타입 미등록) | 「리소스 매니저 미준비」 참조 |
| WebGL 플랫폼에서 로드 실패 | `EPlayMode`가 `WebPlayMode`로 전환되지 않음 | 「실행 모드 불일치」 참조 |
| 에디터에서는 로드되지만 배포 후 로드 실패 | 실행 모드 불일치 (예: 여전히 `EditorSimulateMode`) | 「실행 모드 불일치」 참조 |
| 비동기 로드 완료 콜백에서 `handle.Status`이(가) `Succeed`가 아님 | 리소스 존재하지 않음 / 타입 불일치 / 네트워크 다운로드 실패 | 「경로 오류」「타입 불일치」 참조 |
| 객체는 반환되었지만 빈 머티리얼/누락된 텍스처 | 리소스 의존성이 패키지에 포함되지 않았거나 하위 리소스에 `LoadSubAssetsAsync`를 사용하지 않음 | 「의존성과 하위 리소스」 참조 |

## 해결 단계

### 리소스 패키지 미초기화

`AssetComponent.Awake`는 실행 모드만 설정하며, 실제 초기화는 `Start`에서 `_assetManager.Initialize()`를 호출하여 수행됩니다. 그리고 구체적인 리소스 패키지는 명시적으로 `InitPackageAsync`를 호출해야만 사용 가능한 상태가 됩니다. 초기화되지 않은 패키지로 리소스를 로드하면 빈 핸들이 반환됩니다.

```csharp
// 리소스 컴포넌트가 처음 시작될 때, 사용할 각 리소스 패키지에 대해 한 번 초기화 실행
bool ok = await GameEntry.GetComponent<AssetComponent>()
    .InitPackageAsync("DefaultPackage", hostServer, fallbackHostServer, isDefaultPackage: true);
if (!ok)
{
    // 초기화 실패, host/fallbackHostServer 설정이 올바른지 확인
}
```

출처: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L100-L120)

### 경로 오류

경로는 반드시 YooAssets 수집 단계에서 기록한 위치 지정 주소(일반적으로 `assets/...` 전부 소문자)를 사용해야 하며, 파일 확장자도 포함해야 합니다. `LoadPrefabAsync` 같은 확장 메서드는 내부적으로 `LoadAssetAsync<GameObject>(path)`를 호출하기 때문에 경로가 잘못되면 GameObject를 가져올 수 없습니다.

```csharp
// 올바름: 패키징 시 수집된 리소스 위치 지정 주소 사용
var handle = await assetComponent.LoadPrefabAsync("assets/game/prefabs/player.prefab");
var go = handle.GetAssetObject<GameObject>();

// 잘못됨: Unity 자산 경로로 작성 / 확장자 누락 / 대소문자 불일치
var bad = await assetComponent.LoadPrefabAsync("Assets/Prefabs/Player"); // ❌
```

출처: [AssetComponent.Prefab.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Prefab.cs#L26-L29)

### 실행 모드 불일치

`AssetComponent.Awake`에서 에디터가 아니거나 WebGL인 경우 `GamePlayMode`를 강제로 덮어쓰는데, `EditorSimulateMode`는 `HostPlayMode`로, WebGL은 무조건 `WebPlayMode`로 변경됩니다. 에디터에서는 리소스가 보이는데 배포 후 가져올 수 없다면, 99%는 모드가 제대로 전환되지 않은 경우입니다.

```csharp
// Inspector 또는 코드에서 실행 모드를 명시적으로 지정
assetComponent.GamePlayMode = EPlayMode.HostPlayMode;
// WebGL 플랫폼은 수동 설정 불필요, Awake에서 WebPlayMode로 강제 설정됨
```

출처: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L62-L85)

### 타입 불일치

제네릭 버전 `LoadAssetAsync<T>`은(는) `T` 타입에 따라 리소스를 필터링합니다. 실제 리소스가 `Texture2D`인데 `LoadAssetAsync<Sprite>(path)`을 사용하면 빈 객체가 반환됩니다. 비제네릭 오버로드를 사용하여 원본 객체를 가져온 후 `GetAssetObject<T>()`로 올바른 타입을 추출할 수 있습니다.

```csharp
// 비제네릭 인터페이스를 통해 AssetInfo를 가져온 후 로드하여 타입 추측 오류 방지
var assetInfo = YooAssets.GetAssetInfo("assets/ui/icon.png");
var handle = assetComponent.LoadAssetAsync(assetInfo);
var sprite = handle.GetAssetObject<Sprite>();
```

출처: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L357-L361)

### 리소스 매니저 미준비

`AssetComponent.Awake`에서 `GameFrameworkEntry.GetModule<IAssetManager>()`이(가) `null`을 반환하면, 치명적 로그 `Asset manager is invalid.`을(를) 출력하고 직접 return합니다. 이 경우 이후의 `LoadAssetAsync`는 모두 무효한 핸들을 반환합니다. 이는 보통 `AssetComponent`의 `componentType`이(가) 해당 구현 클래스를 해석하지 못한 경우입니다.

```csharp
// Awake 내의 판정
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

출처: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L83)

### 의존성과 하위 리소스

SpriteAtlas, 아틀라스의 하위 이미지, Material이 참조하는 텍스처는 모두 의존성 또는 하위 리소스에 해당합니다. 주 리소스를 로드한 후 의존성 객체를 가져오려고 하면 가져올 수 없습니다. 다음이 필요합니다.

- 주 리소스 + 의존성을 함께 로드: `LoadSubAssetsAsync<T>(path)` 사용 또는 의존성을 같은 패키지로 패키징하여 YooAssets가 자동으로 수집하도록 함.
- 아틀라스 하위 이미지 가져오기: `LoadSubAssetsAsync<Sprite>(atlasPath)` 사용 후 `SubAssetsHandle`에서 이름으로 가져오기.

```csharp
var subHandle = await assetComponent.LoadSubAssetsAsync<Sprite>("assets/ui/atlas/mainAtlas.png");
foreach (var sprite in subHandle.AllAssetObjects)
{
    // 각 sub asset은 모두 Sprite임
}
```

출처: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L148-L165)

## 검증

다음 순서대로 문제가 해결되었는지 확인하세요.

1. `LoadAssetAsync`이(가) 반환한 `AssetHandle.AssetObject`의 타입과 이름을 출력하여 예상한 객체인지 확인합니다.
2. `handle.Status`이(가) `Succeed`인지 확인합니다. 그렇지 않다면 `handle.LastError`에서 YooAssets의 원본 오류 메시지를 확인할 수 있습니다.
3. 대상 플랫폼에서 `AssetComponent.GamePlayMode`의 값을 확인합니다 (에디터에서는 시뮬레이션 모드, WebGL에서는 `WebPlayMode`여야 함).
4. YooAssets 리소스 수집기(AssetBundle Collector)에서 해당 경로를 검색하여 초기화된 리소스 패키지에 속하고 현재 버전으로 빌드되었는지 확인합니다.
