# Editor / PC / WebGL / 콘솔 채널 구성 (application_config.txt)

Unity 프로젝트의 `Assets/Resources` 아래에 `application_config.txt`라는 이름의 텍스트 파일을 생성하고, `键名=值` 형식으로 채널 정보를 한 줄씩 작성하면, 플러그인이 Editor, PC(Windows/Mac/Linux), WebGL, UWP, PS4, PS5, Xbox One, Nintendo Switch 등의 플랫폼에서 `BlankGetChannel.GetChannelName()`을 통해 해당 파일을 자동으로 읽습니다.

## 사전 조건

- Unity 프로젝트에 `com.gameframex.unity.getchannel` 패키지가 설치되어 있어야 합니다 (`Runtime/BlankGetChannel.cs` 포함).
- 대상 플랫폼이 다음 매크로 범위에 속해야 합니다: `UNITY_STANDALONE`, `UNITY_EDITOR`, `UNITY_WEBGL`, `UNITY_WSA`, `UNITY_PS4`, `UNITY_PS5`, `UNITY_XBOXONE`, `UNITY_SWITCH`. Android / iOS / tvOS / visionOS는 이 파일을 사용하지 않으므로, 각각 `AndroidManifest.xml`의 `<meta-data>` 태그와 `Info.plist`를 사용하십시오.

## 작업 단계

1. Unity 프로젝트에 `Assets/Resources` 폴더를 생성합니다 (이미 존재하는 경우 건너뜁니다).

2. 해당 폴더 아래에 새 텍스트 파일을 만들고 이름을 `application_config.txt`로 지정합니다 (Unity가 자동으로 이를 `TextAsset`로 임포트합니다).

3. 각 줄을 `键名=值` 형식으로 구성 정보를 작성합니다. 예를 들어:

   ```
   channel=editor_cn_test
   sub_channel=beta
   other_key=other_value
   ```

4. C# 코드에서 `BlankGetChannel.GetChannelName()`을 호출하여 읽습니다:

   ```csharp
   // 기본 파라미터로 메인 채널을 가져옵니다 (키 이름은 "channel")
   string channel = BlankGetChannel.GetChannelName();

   // 지정된 키의 채널을 가져오며, 구성되지 않은 경우 "unknown"을 반환합니다
   string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
   ```

   출처: [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L98)

   메서드의 전체 시그니처는 다음과 같습니다:

   ```csharp
   public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
   ```

   출처: [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L97-L98)

5. 읽기 결과를 검증합니다 (임시 스크립트에서 출력 가능):

   ```csharp
   UnityEngine.Debug.Log($"channel={BlankGetChannel.GetChannelName()}");
   ```

## 일반적인 변형

- **여러 커스텀 키**: 파일에 원하는 만큼의 키-값 쌍을 작성할 수 있으며, `GetChannelName`은 전체 파일을 파싱하여 `ChannelCache`에 캐시한 뒤, 이후 임의의 키 이름으로 조회할 수 있습니다. 예: `BlankGetChannel.GetChannelName("other_key")`.
- **메인 채널과 하위 채널만 구분**: 가장 일반적인 방법은 `channel`과 `sub_channel` 두 줄만 남기고, `GetChannelName()`과 `GetChannelName("sub_channel")`으로 각각 읽는 것입니다.
- **패키징 채널별로 다른 파일 생성**: 빌드 스크립트에서 채널에 따라 `Resources/application_config.txt`의 내용을 덮어쓴 후 패키징하면, 동일한 패키지의 구성이 채널에 따라 달라지도록 할 수 있습니다.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GetChannelName()`이 항상 `default`를 반환함 | 파일이 `Resources` 폴더 아래에 없거나, 파일 이름이 `application_config.txt`가 아님 | 파일을 `Assets/Resources/application_config.txt`에 배치합니다. 플러그인은 `Resources.Load<TextAsset>("application_config")`로 로드합니다 |
| `GetChannelName()`이 항상 `default`를 반환함 | 어떤 줄에 `=`가 없거나, 해당 줄에서 파싱된 세그먼트 수가 1 이하이면 줄 전체가 건너뛰어짐 | 모든 줄이 `键名=值` 형식인지 확인하십시오. 키만 있고 값이 없는 줄은 무시됩니다 |
| txt 파일을 수정했는데도 읽히는 값이 여전히 이전 값임 | `ChannelCache`가 첫 번째 읽기 결과를 캐시함; 파일이 없을 때도 `defaultValue`가 캐시에 기록됨 | 첫 번째 호출 전에 파일 내용이 올바른지 확인하십시오. 다시 읽어야 하는 경우 실행을 재시작합니다 (캐시 비우기 인터페이스는 제공되지 않음) |
| 값에서 `=` 이후의 내용이 손실됨 | 파싱이 `=` 기준으로 분할하며 두 번째 세그먼트만 사용하므로, `key=a=b`는 `a`를 얻게 됨 | 값에 `=` 문자를 사용하지 마십시오 |
| 런타임에서 읽을 수 없음 (WebGL/스트리핑 후 빌드에서 예외 발생) | 코드가 Unity에 의해 스트리핑됨 | 플러그인에 스트리핑 방지용 `link.xml`이 포함되어 있으므로, 해당 파일이 삭제되지 않았는지 확인하십시오 |

파싱 로직 원문 (형식 확인용):

```csharp
var textAsset = Resources.Load<TextAsset>("application_config");
if (textAsset != null)
{
    var lines = textAsset.text.Split(new string[] { "\n", "\r", "\r\n" }, StringSplitOptions.RemoveEmptyEntries);
    foreach (var line in lines)
    {
        var split = line.Split(new string[] { "=" }, StringSplitOptions.RemoveEmptyEntries);
        if (split.Length > 1)
        {
            var key = split[0].Trim();
            var channelValue = split[1].Trim();
            ChannelCache[key] = channelValue;
        }
    }
}
else
{
    ChannelCache[channelKey] = defaultValue;
}
```

## 배경

이러한 플랫폼에서는 Android의 `AndroidManifest.xml`이나 iOS의 `Info.plist`를 사용할 수 없기 때문에, 플러그인은 채널 정보를 Unity의 `Resources` 디렉터리에 넣어 패키지에 포함하여 로드하도록 선택했습니다. `GetChannelName`을 처음 호출할 때 전체 파일을 파싱하여 `ChannelCache` 딕셔너리에 기록하고, 이후 호출은 캐시에 바로 적중되어 파일을 반복해서 읽는 것을 방지합니다. 키와 값은 파싱 시 모두 `Trim()`되므로, 줄 앞뒤의 공백은 결과에 영향을 주지 않습니다.
