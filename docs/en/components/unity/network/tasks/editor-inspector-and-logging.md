# Enabling Network Logs and Using the Inspector Panel

By enabling the send/receive log macros via the Unity menu `GameFrameX/Scripting Define Symbols`, the network component will print the ID, type, and JSON content of every sent/received message to the console; additionally, in Play mode, selecting the GameObject with `NetworkComponent` attached lets you view each network channel's connection status, sent/received packet counts, and heartbeat progress in real time in the Inspector panel, with support for one-click disconnection.

## Prerequisites

- The GameFrameX Network package is installed in the project, and `NetworkComponent` is attached in the scene.
- Logs are output via `Log.Debug`; make sure Debug-level logging of the GameFrameX log component is enabled, otherwise nothing will appear in the console.

## Steps

### 1. Enabling/Disabling Network Logs

1. Find the `GameFrameX/Scripting Define Symbols` group in Unity's top menu bar.
2. Click the following menu items as needed (clicking writes the corresponding macro into the Scripting Define Symbols in Player Settings, and Unity recompiles automatically):

| Menu Item | Purpose | Corresponding Macro |
|------|------|--------|
| `Enable Network Send Logs(开启网络发送日志打印)` | Print sent messages | `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Disable Network Send Logs(关闭网络发送日志打印)` | Turn off send logs | Remove `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Enable Network Receive Logs(开启网络接收日志打印)` | Print received messages | `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |
| `Disable Network Receive Logs(关闭网络接收日志打印)` | Turn off receive logs | Remove `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |

The menu implementation comes from [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L67-L98), and the macro constants are defined as follows:

3. After enabling, run the game; the console will output logs such as `发送消息 ID:[10001,0,xxxReq] 消息内容:{...}` and `收到消息 ID:[...] 消息内容:{...}`. The actual printing logic is:

```csharp
protected void DebugSendLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG
    var messageId = ProtoMessageIdHandler.GetReqMessageIdByType(messageObject.GetType());
    if (!IgnoreSendIds.Contains(messageId))
    {
        Log.Debug($"发送消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}

protected void DebugReceiveLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG
    var messageId = ProtoMessageIdHandler.GetRespMessageIdByType(messageObject.GetType());
    if (!IgnoreReceiveIds.Contains(messageId))
    {
        Log.Debug($"收到消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}
```

### 2. Configuring Message IDs to Ignore in Logs

High-frequency messages (such as heartbeats) can flood the console; you can exclude them from the logs in the Inspector:

1. Select the GameObject with `NetworkComponent` attached in the scene.
2. Find the following two fields in the Inspector panel (**editable only outside Play mode**):
   - `Ignore Log Printing For Sent Message IDs`: The list of message IDs ignored on the send side.
   - `Ignore Log Printing Of Received Message IDs`: The list of message IDs ignored on the receive side.
3. Fill in the message IDs you do not want printed; the change takes effect upon entering Play mode. Messages matching the list will not execute the `Log.Debug` above.

If you need to set this dynamically in code, the channel base class provides a public method:

```csharp
public void SetIgnoreLogNetworkIds(List<int> sendIds, List<int> receiveIds)
{
    IgnoreSendIds = sendIds;
    IgnoreReceiveIds = receiveIds;
}
```

### 3. Viewing Runtime Status in the Inspector Panel

1. Enter Play mode and select the scene's `NetworkComponent` GameObject in the Hierarchy.
2. The top of the Inspector displays `Network Channel Count`, followed by one group per network channel, containing:

| Panel Field | Meaning |
|------|------|
| Channel name + `Connected`/`Disconnected` | Channel name and connection status |
| `Address Family` | Address family (IPv4/IPv6, etc.) |
| `Local Address` / `Remote Address` | Local/remote socket addresses; shows `Unavailable` when not connected |
| `Send Packet` | `sent packet count / pending packet count` |
| `Miss Heart Beat Count` | Number of missed heartbeats |
| `Heart Beat` | `elapsed time / heartbeat interval` (seconds, two decimal places) |
| `Disconnect` button | Disconnects that channel |

The core panel drawing code is as follows; the `Disconnect` button internally calls `Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError)`:

```csharp
EditorGUILayout.LabelField(networkChannel.Name, networkChannel.Connected ? "Connected" : "Disconnected");
EditorGUILayout.LabelField("Address Family", networkChannel.AddressFamily.ToString());
EditorGUILayout.LabelField("Send Packet", Utility.Text.Format("{0} / {1}", networkChannel.SendPacketCount, networkChannel.SentPacketCount));
EditorGUILayout.LabelField("Miss Heart Beat Count", networkChannel.MissHeartBeatCount.ToString());
EditorGUILayout.LabelField("Heart Beat", Utility.Text.Format("{0:F2} / {1:F2}", networkChannel.HeartBeatElapseSeconds, networkChannel.HeartBeatInterval));
EditorGUI.BeginDisabledGroup(!networkChannel.Connected);
{
    if (GUILayout.Button("Disconnect"))
    {
        networkChannel.Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError);
    }
}
```

Source: [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L95-L123)

In addition, outside Play mode the Inspector lets you edit two runtime settings: `RPC Timeout Time In Milliseconds` (slider range 3000–50000 milliseconds) and `Focus Send Heartbeat`. Outside Play mode, the panel shows only the configuration section along with the hint `Available during runtime only.`; the runtime status section is not rendered.

## Common Variants

- **Force WebSocket channel**: The same menu group also includes `Enable Force WebSocket(开启强制使用WebSocket网络)` / `Disable Force WebSocket(关闭强制使用WebSocket网络)`, which control the macro `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` and force the network to go through WebSocket.
- **Inspecting one-way traffic only**: Enable only `Enable Network Receive Logs` and turn off Send, then combine it with the receive ignore list to filter out heartbeats, so you only see downstream messages from the server.

## Common Issues

- **No logs at all after enabling the macros**: The log level is `Log.Debug`; nothing will be printed if the GameFrameX log component suppresses Debug-level logs, or if the message ID hits the ignore lists (`IgnoreSendIds`/`IgnoreReceiveIds`).
- **Cannot modify fields in the Inspector**: `RPC Timeout`, `Focus Heartbeat`, and the two ignore lists are disabled in Play mode (`EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode)`); exit Play mode before changing them.
- **Channel status not visible in the panel**: The runtime status is drawn only in Play mode and when the GameObject is in the scene Hierarchy; outside Play mode, or when a Prefab asset is selected, only a hint message is shown.
- **Macro not taking effect / compilation errors**: Unity triggers a recompile after the macro is written. If logs still do not print, check that the macro actually exists in `Project Settings > Player > Scripting Define Symbols` (the menu only adds or removes it).

## Background

The log switches use conditional compilation (`#if`) instead of runtime boolean switches so that logging incurs zero overhead when disabled — the entire `Log.Debug` call and the JSON serialization never make it into the build output. The Inspector is provided by `NetworkComponentInspector` marked with `[CustomEditor(typeof(NetworkComponent))]`, and it calls `Repaint()` every frame to refresh the runtime data, so the data updates continuously in Play mode.
