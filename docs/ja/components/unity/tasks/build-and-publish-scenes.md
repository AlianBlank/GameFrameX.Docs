# Launcher / LauncherAuto シーンのビルドと公開方法

このページでは、GameFrameX.Unity の `Assets/Scenes/Launcher.unity` と `Assets/Scenes/LauncherAuto.unity` の 2 つの起動シーンのビルドと公開における要点を説明します。Build Settings でのインデックス位置、搭載されている UI コンポーネント、および独立プラットフォームへの公開時の一般的な処理を含みます。

## 前提条件

- Unity Editor がインストール済みであること（リポジトリの `ProjectSettings/` で宣言されているバージョンと一致していること）。
- プロジェクトが Unity Hub 経由で開かれており、ディレクトリ内に `Assets/Scenes/Launcher.unity` と `Assets/Scenes/LauncherAuto.unity` の 2 つのシーンファイルが存在すること。
- GameFrameX フレームワークのランタイムがインストール済みで、シーンにプレハブ化された `UILauncher` コンポーネントスクリプトが利用可能であること。

## 操作手順

### 1. File → Build Settings を開く

Unity のメニューバーから `File` → `Build Settings` を選択し、`Scenes In Build` リストで `Launcher` と `LauncherAuto` が追加されていることを確認します。通常、`Launcher` はインデックス 0 の最初の起動シーンとなります。

### 2. シーンファイルの存在を確認する

後続のビルド成果物に起動シーンを含めるために、以下の 2 つのファイルがプロジェクト内に存在することを確認してください:

- [Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity)
- [Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity)

### 3. Launcher シーンの UILauncher コンポーネントを確認する

`Launcher.unity` には `UILauncher` スクリプトコンポーネントがアタッチされており、起動 UI とバージョン検出ロジックを担当します。ファイルにはコンポーネント参照が保持されています:

```yaml
propertyPath: m_Name
value: UILauncher
```

参考元:[Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity#L1158)

シーンを開いた後、Hierarchy の上部にある GameObject に `UILauncher` コンポーネントが表示されるはずです。フィールドにはバージョン番号、ホットアップデートアドレス、サーバーリストなどが含まれます。フィールドが空の場合は、公開前に Inspector で設定を完了させておく必要があります。

### 4. LauncherAuto シーンの Build Settings を処理する

`LauncherAuto.unity` は内部で YAML 形式により自身の `m_BuildSettings` セクションを宣言しており（シリアライズバージョン 3）、Unity はこのセクションに基づいてシーンがビルドに含まれるかどうかやライティング / Lightmap 設定を記録します。ファイルを直接開くと次のように表示されます:

```yaml
m_BuildSettings:
  serializedVersion: 3
```

参考元:[Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity#L105-L107)

Build Settings でこのシーンを無効化する必要がある場合は、`m_BuildSettings` 配下で `m_Scenes` 参照を調整するか、Unity エディタで直接チェックを外すことができます。

### 5. ターゲットプラットフォームを選択してビルドする

Build Settings でターゲットプラットフォーム（Windows、Android、iOS、macOS など）を選択し、`Build` または `Build And Run` をクリックします。Unity は `Scenes In Build` の順序に従って、`Launcher` と `LauncherAuto` を Player バイナリにまとめてパッケージングします。

### 6. 成果物を検証する

ビルド完了後、出力ディレクトリで以下を確認します:

- 実行可能ファイルが正常に起動し、`Launcher` シーンに入ること。
- 設定で UI を自動スキップする場合には `LauncherAuto` が読み込まれること。
- 起動画面のバージョン番号、ホットアップデートアドレスが正しく表示されること。

## よくあるバリエーション

- **LauncherAuto 自動シーン遷移**: 起動後に UI ランチャーを表示せず直接ビジネスシーンに進みたい場合は、Player Settings → その他の設定で `LauncherAuto` を有効にします。このシーンは通常、UI を持たない自動化された起動フローに使用されます。
- **プラットフォーム別のシーン削減**: WebGL などの弱いプラットフォームでは、Build Settings から `LauncherAuto` を削除して `Launcher` のみを残せます。逆に独立クライアント向けには両方をチェックできます。
- **UILauncher フィールドの差し替え**: 異なる公開チャネルでは異なるホットアップデートアドレスが使用されるため、ビルド前に `UILauncher` スクリプト上の設定を一時的に切り替えるだけで対応できます。

## よくあるエラー

- **ビルド後に起動画面が黒くなる**: 通常、`UILauncher` コンポーネントのフィールド（バージョン番号、ホットアップデートアドレスなど）が未設定であるためにランチャーの初期化に失敗したことが原因です。
- **Scenes In Build からシーンが欠落している**: 新規シーンを手動追加する際に `Launcher` または `LauncherAuto` をリストから削除してしまうと、起動器がスキップされて実行時に直接エラーが発生します。
- **シーン GUID の競合**: `.unity` ファイルを直接コピーする際に `m_SceneGUID` をそのまま保持してしまうと、Build Settings の参照が混乱します。必ず Unity に再インポートさせて新しい GUID を生成させてください。

## 背景情報（任意）

`Launcher` と `LauncherAuto` は GameFrameX のデュアル起動シーンの組み合わせです。`Launcher` は UI 付きのランチャーとしてバージョン検査、ホットアップデート、サーバー選択を担当します。`LauncherAuto` はバックグラウンドまたは自動化された起動シーンで、UI をスキップして直接ビジネスロジックを読み込みます。`m_BuildSettings` は Unity のシーンファイル内でビルド参加状態を記述するメタデータセクションであり、Editor と Player の両方から読み取られます。
