# 自定义消息序列化与压缩

通过实现 `IMessageSerializer` 并调用 `MessageSerializerRegistry.RegisterGlobal()` 注册,即可把网络层的消息编解码换成你自己的方案(Protobuf、JSON、MemoryPack 等);压缩与解压则通过实现 `IMessageCompressHandler` / `IMessageDecompressHandler` 接口替换。未注册序列化器时框架会抛出明确异常提示。

## 前置条件

- 已安装 `com.gameframex.unity.network` 包并完成网络组件配置。
- 自定义消息类型需继承 `MessageObject`(序列化方法的泛型约束要求)。

## 核心接口一览

| 名称 | 真实签名 | 说明 |
|------|----------|------|
| `IMessageSerializer.Serialize<T>` | `byte[] Serialize<T>(T message) where T : MessageObject` | 序列化消息对象 |
| `IMessageSerializer.Deserialize` | `object Deserialize(byte[] data, Type targetType)` | 反序列化为目标消息类型 |
| `IMessageCompressHandler.Handler` | `byte[] Handler(byte[] message)` | 压缩消息数据 |
| `MessageSerializerRegistry.RegisterGlobal` | `void RegisterGlobal(IMessageSerializer serializer)` | 注册全局序列化器 |
| `MessageSerializerRegistry.Global` | `IMessageSerializer Global { get; }` | 获取全局序列化器,未注册时返回兜底实现 |
| `MessageSerializerRegistry.Reset` | `void Reset()` | 重置为默认兜底实现 |

压缩接口的完整定义如下,解压接口 `IMessageDecompressHandler` 与之成对存在:

```csharp
namespace GameFrameX.Network.Runtime
{
    /// <summary>
    /// 消息压缩器接口定义，用于压缩消息数据
    /// </summary>
    public interface IMessageCompressHandler
    {

        /// 压缩处理
        /// </summary>
        /// <param name="message">消息未压缩内容</param>
        /// <returns></returns>
        byte[] Handler(byte[] message);
    }
}
```

2. **注册为全局序列化器**:在游戏初始化阶段(建网络通道之前)调用注册表,传入你的实现实例:

```csharp
public static void RegisterGlobal(IMessageSerializer serializer)
{

    }
```

即业务侧写一句 `MessageSerializerRegistry.RegisterGlobal(new MyProtobufSerializer());` 即完成接入。

3. **实现压缩与解压处理器**:分别实现 `IMessageCompressHandler` 与 `IMessageDecompressHandler`,在 `Handler(byte[] message)` 中返回压缩/解压后的字节数组。框架自带默认实现 `DefaultMessageCompressHandler` 与 `DefaultMessageDecompressHandler`(位于 `Runtime/Network/Helper/`),可作为自定义时的参照。源码中未在本次核实范围内找到压缩器的独立注册入口,替换方式请参照上述默认实现的调用方确认。

4. **验证**:发送一条自定义消息并在对端打印收到的字段,确认序列化与压缩链路生效。

## 常见错误

| 症状/报错原文 | 原因 | 修复 |
|------|------|------|
| `InvalidOperationException: No IMessageSerializer registered. Call MessageSerializerRegistry.RegisterGlobal() or provide a channel-level serializer.` | 未注册任何序列化器,全局落到兜底实现 `DefaultMessageSerializer`,其方法始终抛出该异常 | 在初始化阶段调用 `MessageSerializerRegistry.RegisterGlobal(...)`,或为通道提供通道级序列化器 |
| `ArgumentNullException` (参数名 `serializer`) | 向 `RegisterGlobal` 传入了 `null` | 传入非空实现实例 |
| 注册后仍走旧逻辑 | 注册时机晚于首次收发消息 | 将注册提前到创建网络通道之前;必要时调用 `MessageSerializerRegistry.Reset()` 后重新注册 |

## 背景

`MessageSerializerRegistry` 内部用 `volatile` 字段持有全局实例;`Global` 属性在未注册时返回 `DefaultMessageSerializer.Instance` 兜底,该兜底实现的方法体只有一句抛异常,专门用于提示用户注册真实序列化器——因此"忘注册"会在第一次收发消息时以明确报错暴露,而不是静默失败。
