# 이름 있는 FSM을 만드는 방법(동일 타입의 다중 인스턴스)

동일한 보유자 타입이 서로 독립적인 여러 상태 머신이 존재해야 하는 경우(예: 씬에 여러 NPC가 각자의 AI를 실행하고, 여러 발사체가 각자의 상태 흐름을 실행하는 경우), `CreateFsm`의 **이름이 있는 오버로드**를 사용하고, 서로 다른 `name`으로 인스턴스를 구분하며, `GetFsm<T>(name)` / `DestroyFsm<T>(name)`로 이름별로 접근합니다.

## 사전 조건

- `com.gameframex.unity.fsm` 패키지가 설치되어 있고 `FsmManager`가 `FsmComponent`로 시작되어 있어야 합니다(자세한 내용은 《Fsm 소개》 참조).
- 보유자 타입에 대해 여러 `FsmState<T>` 서브클래스가 정의되어 있어야 합니다.

## 작업 단계

1. **`CreateFsm<T>(string name, T owner, params FsmState<T>[] states)`로 이름 있는 FSM 생성**. 동일한 이름의 FSM을 중복 생성하면 `GameFrameworkException("Already exist FSM '{0}'.")`이 발생하므로 각 인스턴스의 `name`은 반드시 고유해야 합니다.

```csharp
using GameFrameX.Fsm.Runtime;

// owner는 서로 다른 객체 또는 동일 타입의 서로 다른 인스턴스일 수 있습니다
var npcAi1 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_001", new MyNpc(), idleState, patrolState, attackState);

var npcAi2 = GameEntry.GetModule<IFsmManager>()
    .CreateFsm<MyNpc>("NPC_002", new MyNpc(), idleState, patrolState, attackState);
```

출처: [FsmManager.cs#L319-L330](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L319-L330)

2. **이름으로 FSM을 가져와 시작**. 이름 없는 오버로드 `GetFsm<T>()`는 동일 보유자 타입의 "기본" FSM 하나만 반환하며, 이름 있는 FSM은 반드시 `GetFsm<T>(string name)`을 사용해야 합니다.

```csharp
var fsm = GameEntry.GetModule<IFsmManager>().GetFsm<MyNpc>("NPC_001");
fsm.Start<PatrolState>();
```

출처: [FsmManager.cs#L239-L242](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L239-L242)

3. **이름으로 확인 또는 제거**. `HasFsm<T>(name)` / `DestroyFsm<T>(name)`은 생성과 일대일로 대응됩니다; 객체 파괴 전에 `DestroyFsm`을 호출하세요. 그렇지 않으면 `FsmManager` 내부의 사전이 유효하지 않은 참조를 보유하게 됩니다.

```csharp
var mgr = GameEntry.GetModule<IFsmManager>();
if (mgr.HasFsm<MyNpc>("NPC_001"))
{
    mgr.DestroyFsm<MyNpc>("NPC_001");
}
```

출처: [FsmManager.cs#L182-L186](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L182-L186) · [FsmManager.cs#L397-L401](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L397-L401)

4. **`FullName`을 통해 디버그 위치 확인**. `FsmBase.FullName`은 `TypeNamePair`의 문자열을 반환하며, 여러 인스턴스를 구분하기 위한 로그에 사용할 수 있습니다.

```csharp
Debug.Log(npcAi1.FullName); // 예: "MyNpc(NPC_001)"
```

출처: [FsmBase.cs#L67-L70](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs#L67-L70)

## 일반적인 변형

**List 형태의 상태 집합**: 동일한 이름 지정 규칙은 `CreateFsm<T>(string name, T owner, List<FsmState<T>> states)` 오버로드에도 적용됩니다.

```csharp
var states = new List<FsmState<MyNpc>> { idleState, patrolState, attackState };
GameEntry.GetModule<IFsmManager>().CreateFsm<MyNpc>("NPC_003", new MyNpc(), states);
```

출처: [FsmManager.cs#L354-L365](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L354-L365)

**`Type`으로 접근(제네릭 미사용)**: `Type` 정보만 있는 시나리오에서는 `GetFsm(Type ownerType, string name)` / `HasFsm(Type ownerType, string name)` / `DestroyFsm(Type ownerType, string name)`를 사용하여 작업할 수 있습니다.

출처: [IFsmManager.cs#L71-L73](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsmManager.cs#L71-L73) · [IFsmManager.cs#L99-L103](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsmManager.cs#L99-L103) · [IFsmManager.cs#L177-L183](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsmManager.cs#L177-L183)

## 일반적인 오류

| 현상 | 원인 | 회피 방법 |
|------|------|------|
| `Already exist FSM 'MyNpc(NPC_001)'` | 동일한 이름의 FSM이 이미 존재함; 이름 없는 오버로드의 기본값은 `name = string.Empty`이므로 이름 없는 호출은 서로 충돌함 | 각 인스턴스에 고유한 `name` 사용; 기존 것을 제거한 후 다시 생성 |
| `GetFsm<MyNpc>()`가 `null`을 반환 | `name`을 전달하지 않으면 이름이 비어 있는 FSM만 매칭됨 | 대신 `GetFsm<MyNpc>("NPC_001")` 사용 |
| `Owner type is invalid` | `Type` 오버로드 사용 시 `null`을 전달함 | 호출 전에 `null`이 아닌지 확인 |
