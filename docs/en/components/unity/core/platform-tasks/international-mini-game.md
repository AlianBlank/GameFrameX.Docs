# One-Click Switching for International Mini Game Platforms

From the menu item under the Unity editor menu `GameFrameX/Scripting Define Symbols/International Mini Games(海外小游戏)`, you can enable or disable the macro definition for an international mini game platform with a single click. The macro definitions for all other mini game platforms (domestic, international, and device manufacturers) are automatically disabled on a mutually exclusive basis.

## Prerequisites

- The current build platform must be switched to `WebGL` (all macro definition operations take effect only under `UNITY_WEBGL`; see the conditional compilation at the top of `MiniGameDefineSymbolHelper.cs`).
- The project containing the editor extension must include the `GameFrameX` package; the menu path is registered by `[MenuItem]` in each `MiniGameDefineSymbolHelper.*.cs` file.

## Steps

1. Switch the build platform to **WebGL** in Unity: `File → Build Settings → Platform → WebGL → Switch Platform`.
2. Open the target menu: **GameFrameX → Scripting Define Symbols → International Mini Games(海外小游戏)**.
3. Select the target platform to enable (for example, `Enable CrazyGames Mini Game(开启[CrazyGames]适配)`).
4. The editor calls the platform's `EnableXxxMiniGame()` method. It first calls `DisableOtherMiniGameScriptingDefineSymbols(...)` to disable all other mini game macro definitions, then enables the current platform's macro definition and adds the unified `ENABLE_WEBGL_MINI_GAME` macro.
5. To disable a platform, select `Disable Xxx Mini Game(关闭[Xxx]适配)` in the same directory. The menu item priority is adjacent to the Enable item (for example, 3400/3401 for CrazyGames).

Minimal executable example—refer to the menu registration and toggle implementation in the CrazyGames adaptation file:

```csharp
[MenuItem("GameFrameX/Scripting Define Symbols/International Mini Games(海外小游戏)/Enable CrazyGames Mini Game(开启[CrazyGames]适配)", false, 3400)]
public static void EnableCrazyGamesMiniGame()
{
    DisableOtherMiniGameScriptingDefineSymbols(EnableCrazyGamesMiniGameScriptingDefineSymbol);

    foreach (var define in EnableCrazyGamesMiniGameScriptingDefineSymbol)
    {
        if (!ScriptingDefineSymbols.HasScriptingDefineSymbol(BuildTargetGroup.WebGL, define))
        {
            ScriptingDefineSymbols.AddScriptingDefineSymbol(define);
        }
        Debug.Log($"CrazyGames 平台宏定义 [{define}] 已经打开");
    }

    EnableUnifiedMiniGameScriptingDefineSymbol();
}
```

When a platform is enabled, the framework iterates through all 21 mini game macro definition arrays and disables the other platforms on a mutually exclusive basis. It also prints logs (see `DisableOtherMiniGameScriptingDefineSymbols`):

```csharp
foreach (var defineSymbols in GetAllMiniGameScriptingDefineSymbols())
{
    if (defineSymbols == null) continue;
    if (object.ReferenceEquals(defineSymbols, currentMiniGameScriptingDefineSymbols)) continue;

    foreach (var define in defineSymbols)
    {
        if (!ScriptingDefineSymbols.HasScriptingDefineSymbol(BuildTargetGroup.WebGL, define)) continue;
        ScriptingDefineSymbols.RemoveScriptingDefineSymbol(define);
        closedCount++;
        UnityEngine.Debug.Log($"小游戏宏定义 [{define}] 已经关闭");
    }
}
UnityEngine.Debug.Log($"小游戏宏定义互斥清理完成，共关闭 {closedCount} 个宏定义");
```

## Common Variations

- **Enabling multiple international platforms simultaneously**: The current implementation does not allow macro definitions from multiple platforms to coexist. `DisableOtherMiniGameScriptingDefineSymbols` skips the current platform's array through `ReferenceEquals` and disables all other platform macro definitions. If you need to build multiple platforms in parallel, you must enable them separately in different project branches.
- **Coexistence of international platforms with device manufacturers or domestic mini games**: When an international platform is enabled, all macro definitions under `DeviceOEMs/` (Vivo/OPPO/Xiaomi/Huawei) and `DomesticMiniGames/` (WeChat/Douyin/Alipay, etc.) are also disabled.

## Common Errors

- **The menu item is grayed out and cannot be clicked**: The build platform is not WebGL. All international mini game macro definition helpers are wrapped in `#if UNITY_WEBGL`, so both the menu registration and implementation are stripped out. Switch to WebGL before proceeding.
- **No mutual-exclusion logs are displayed**: Confirm that the project's `Assembly Definition` or compilation configuration has not excluded the `GameFrameX.Editor` assembly.
- **The settings do not take effect at runtime after building**: The unified `ENABLE_WEBGL_MINI_GAME` macro is maintained separately by `EnableUnifiedMiniGameScriptingDefineSymbol()`. If all international platforms are disabled but the unified macro remains, trigger `RefreshUnifiedMiniGameScriptingDefineSymbol()` in the corresponding `DisableXxxMiniGame()` method to clear it.

## Background (Optional)

The international mini game macro definition helpers are multiple partial files of `partial class MiniGameDefineSymbolHelper`, with one file for each platform. They are located in `Editor/MiniGame/InternationalMiniGames/`. Their `[MenuItem]` priorities (starting from 3400 in this directory) distinguish them from domestic and other international directories. All international platforms add the unified `ENABLE_WEBGL_MINI_GAME` macro when enabled, and the unified macro is refreshed when they are disabled.
