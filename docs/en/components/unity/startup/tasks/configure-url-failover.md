# How to Configure URL Primary/Backup Failover Strategy

Use `UrlFailoverRunner.ExecuteAsync` to make a group of URLs fail over from primary to backup in order, with up to N retries per URL. This page provides a minimal copy-and-run usage example, parameter meanings, and common pitfalls.

## Prerequisites

- The project has the `com.gameframex.unity.startup` package installed and references the `GameFrameX.Startup.Runtime` namespace.
- The business side implements a `Func<string, UniTask<UrlAttemptResult>>` delegate responsible for making the actual request (GET/POST, etc.) against a single URL, and returns `UrlAttemptResult.Succeed()` or `UrlAttemptResult.Fail(errorMessage)` based on the response.
- The `Cysharp.Threading.Tasks` and `UniTask` async mechanism is already imported (`using Cysharp.Threading.Tasks;`).

## Steps

1. **Prepare the URL list**. Put the candidate URLs into an `IReadOnlyList<string>` in "primary—backup—backup…" order; at runtime they are tried sequentially by array index.

2. **Implement the single-URL attempt delegate**. Make one request per URL and return a success or failure result based on the HTTP status code or business code.

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;
   using UnityEngine.Networking;

   UniTask<UrlAttemptResult> TryFetchAsync(string url)
   {
       return UniTask.RunOnThreadPool(async () =>
       {
           using var req = UnityWebRequest.Get(url);
           await req.SendWebRequest();
           if (req.result == UnityWebRequest.Result.Success)
           {
               return UrlAttemptResult.Succeed();
           }
           return UrlAttemptResult.Fail(req.error ?? "unknown error");
       });
   }
   ```

   Source: [UrlAttemptResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlAttemptResult.cs#L6-L27)

3. **Call `UrlFailoverRunner.ExecuteAsync`**. Pass in the URL list, the maximum number of attempts per URL, the retry interval in milliseconds, and the delegate from the previous step.

   ```csharp
   using System.Collections.Generic;
   using System.Threading;
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   public async UniTask<UrlFailoverResult> RunAsync(CancellationToken ct = default)
   {
       var urls = new[] { "https://api-primary.example.com", "https://api-backup.example.com" };

       return await UrlFailoverRunner.ExecuteAsync(
           urls,
           maxAttemptsPerUrl: 3,
           retryDelayMs: 500,
           attempt: TryFetchAsync,
           onProgress: (url, attempt, total) =>
               UnityEngine.Debug.Log($"try {attempt}/{total} -> {url}"),
           cancellationToken: ct);
   }
   ```

   Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L14-L43)

4. **Handle the returned `UrlFailoverResult`**. On success, use the business data; on failure, decide whether to fall back to degraded logic or report analytics based on `FailedUrl` and `ErrorMessage`.

   ```csharp
   var result = await RunAsync(this.GetCancellationTokenOnDestroy());
   if (!result.Success)
   {
       UnityEngine.Debug.LogError($"all URLs failed. last={result.FailedUrl}, err={result.ErrorMessage}");
       return;
   }
   ```

   Source: [UrlFailoverResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverResult.cs#L6-L30)

## Common Variants

- **Synchronous style (common in unit tests)**. Simply write the delegate to immediately return `UniTask.FromResult(...)`, with no waiting.

  ```csharp
  var result = await UrlFailoverRunner.ExecuteAsync(
      new[] { "http://a", "http://b" },
      maxAttemptsPerUrl: 2,
      retryDelayMs: 0,
      attempt: url => UniTask.FromResult(
          url == "http://b" ? UrlAttemptResult.Succeed() : UrlAttemptResult.Fail("down")));
  ```

  Source: [UrlFailoverRunnerTests.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Tests/Runtime/UrlFailoverRunnerTests.cs#L63-L85)

- **No retries, failover only**. Set `maxAttemptsPerUrl` to `1` and `retryDelayMs` to `0`, meaning "switch to the next URL immediately after a single failure", with no delay.

  ```csharp
  await UrlFailoverRunner.ExecuteAsync(urls, maxAttemptsPerUrl: 1, retryDelayMs: 0, attempt: TryFetchAsync);
  ```

  Source: [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L68-L71)

- **With a progress callback**. `onProgress(url, attempt, total)` fires before each attempt, with `attempt` counting from `1`, making it easy to drive a UI progress bar.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Throws `ArgumentNullException` synchronously, parameter name `urls` | `null` was passed as the URL list | Pass a list other than `new string[0]`; an empty array throws `ArgumentException` |
| Throws `ArgumentException` synchronously with the message "URL list must contain at least one URL." | An empty array `new string[0]` was passed | Include at least 1 URL |
| Throws `ArgumentException` synchronously with the message "Max attempts per URL must be greater than zero." | `maxAttemptsPerUrl < 1` | Set attempts per URL to ≥ 1 |
| Throws `ArgumentException` synchronously with the message "Retry delay must be zero or greater." | `retryDelayMs < 0` | Set it to `0` or a positive integer |
| Throws `ArgumentNullException` synchronously, parameter name `attempt` | `null` was passed as the attempt delegate | Pass a valid `Func<string, UniTask<UrlAttemptResult>>` to `attempt` |
| The caller receives `result.Success == false` when all URLs fail, but `FailedUrl` is an empty string | The failure path was never invoked on any URL (extremely rare), or all failures were swallowed | Check whether the delegate always returns `UrlAttemptResult.Fail(...)` |

The implementation that validates these parameter constraints is located at the entry point of `UrlFailoverRunner.ExecuteAsync`.

## Background (Optional)

`UrlFailoverRunner` is a static utility class that executes a two-level loop of "URL order × attempts per URL": the outer loop iterates over `urls`, and the inner loop repeatedly invokes the passed-in `attempt` delegate for a single URL until it succeeds or `maxAttemptsPerUrl` is exhausted. As soon as any URL succeeds, it immediately returns `UrlFailoverResult.Succeed()` without trying subsequent URLs; only when all retries across all URLs have failed does it return a `UrlFailoverResult.Fail(...)` containing the last failed URL and the error message. When `retryDelayMs > 0`, it waits with `UniTask.Delay` between two attempts on the same URL; when `maxAttemptsPerUrl == 1`, there is no waiting and no retry.
