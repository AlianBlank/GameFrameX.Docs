# タイマー状態の照会:残り時間、経過時間と残り回数

タイマー ID で `GetRemaining` / `GetElapsed` / `GetRepeatLeft` を呼び出すことで現在の状態を照会できます。さらに `IsPaused` / `Exists` を組み合わせると、タイマーが存続しているか、一時停止中かを判断できます。3つの照会インターフェースは、タイマーが存在しない場合に一律 `-1` を返します。

## 前提条件

- シーンに使用可能な `TimerComponent` が既に存在すること(内部で `ITimerManager` の同名メソッドをラップしています)。
- タイマー作成時に返されたタイマー ID(`Add` シリーズのメソッドの戻り値)を保持していること。

## 照会インターフェース一覧

| メソッド | シグネチャ | 戻り値 |
|------|------|--------|
| 残り時間 | `float GetRemaining(int id)` | 残り秒数。タイマーが存在しない場合は `-1` を返す |
| 経過時間 | `float GetElapsed(int id)` | 累積秒数。タイマーが存在しない場合は `-1` を返す |
| 残り回数 | `int GetRepeatLeft(int id)` | 残りの繰り返し回数(`0` は無限ループを示す)。タイマーが存在しない場合は `-1` を返す |
| 一時停止中か | `bool IsPaused(int id)` | 一時停止中は `true`、それ以外は `false` |
| 存在するか | `bool Exists(int id)` | 存続している場合は `true`、それ以外は `false` |
| タグ照会 | `bool HasTag(string tag)` | そのタグに少なくとも1つのタイマーが存在する場合は `true` |

以上のシグネチャはインターフェース定義とコンポーネントのラップ層によるものです:

```csharp
float GetRemaining(int id);
float GetElapsed(int id);
int GetRepeatLeft(int id);
```

## 操作手順

1. タイマーを作成し、返された ID を保存します(例:`int id = ...` は `Add` シリーズの登録呼び出しから取得)。
2. UI やロジックを更新する必要があるタイミングで、保持している `TimerComponent` インスタンスを通じて照会メソッドを呼び出します:
   - カウントダウン表示には `GetRemaining(id)`;
   - プログレスバーの充填には `GetElapsed(id)`(総時間で割ることで進捗を取得);
   - 回数表示には `GetRepeatLeft(id)`。
3. 照会のたびに、まず `Exists(id)` でタイマーがまだ存在するかを確認することをお勧めします——タイマーは発火完了後に削除され、その後の照会は `-1` のみを返します。
4. タイマーが `Pause`/`PauseByTag` で一時停止される可能性がある場合は、`IsPaused(id)` を使って「一時停止中」と「終了済み」を区別します。
5. UI 上では `-1` を「タイマーが既に存在しない」として扱い、負の数をそのまま表示しないようにします。

## 一般的なバリエーション

- **一括一時停止後の照会**：同じタグを持つ一連のタイマーに対して `PauseByTag(tag)` を呼び出した後、`GetRemaining` は減少しません(一時停止中は時間が累積されません)、`IsPaused` は `true` を返します。再開には `ResumeByTag(tag)` を使用します。
- **無限ループタイマー**:`GetRepeatLeft` が `0` を返す場合は無限ループを示しており、「終了済み」と判断しないでください。
- **async/await のケース**:状態を照会せずに直接待機する場合は、`WaitForSecondsAsync(seconds, cancellationToken)` などの非同期メソッドが使用できます。[TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L224) を参照してください。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `GetRemaining` が `-1` を返す | タイマーが既に削除されている(発火完了、`Remove`/`RemoveByTag` の呼び出し、または ID の記載ミス) | まず `Exists(id)` で確認。タイマーを再登録する |
| 残り時間が「進まない」 | タイマーが一時停止状態にある | `IsPaused(id)` を確認し、必要に応じて `Resume(id)` を実行 |
| `GetRepeatLeft` が `0` を返すのにコールバックがまだ発火する | `0` は無限ループを示し、終了ではない | 存在確認には回数ではなく `Exists(id)` を使用する |
| 負の数が表示される | `-1` をそのまま秒数として描画している | UI 層で `-1` を「終了済み/存在しない」にマッピングする |

## 検証

ユニットテストリポジトリには `GetRemaining_ReturnsCorrectValue` などのテストケースが既に存在し([UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L619))、Unity Test Runner で実行して照会の動作を確認できます。自分で検証する場合は、5秒のタイマーを登録し、連続する2フレームで `GetElapsed` が増加し、`GetRemaining` が減少することを確認します。

## 背景(オプション)

内部では各タイマーは `TimerManager` のプライベート `Timer` クラスに記録されており、その `Elapsed` フィールドが経過時間を継続的に累積します。照会インターフェースはこの内部データに基づいて残りの値を計算します([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L21-L22))。`TimerComponent` は `ITimerManager` の薄いラップ層にすぎず、両方の入口の照会結果は一致します。
