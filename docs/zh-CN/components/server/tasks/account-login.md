# 实现账号登录(Account / Login 流程)

本页带你接好客户端发起的账号登录消息,完成从 `ReqPlayerLogin` 进入到角色数据落地的最小闭环。完成后,客户端会拿到 `RespPlayerLogin` 并进入游戏业务。

## 前置条件

- 已部署 `GameFrameX.Server` 网关与中心服,Actor 类型 `ActorTypeServer` 可用。
- 数据库中已存在 `PlayerState` 表,主键字段为 `Id`(登录消息按 `Id` 查找)。
- 客户端能发送 `ReqPlayerLogin` 消息,并能收到 `RespPlayerLogin`。
- 已引用以下命名空间:`GameFrameX.Apps.Account.Login.Component`、`GameFrameX.Apps.Account.Login.Entity`、`GameFrameX.Apps.Player.Player.Entity`、`GameFrameX.Monitor.Player`。

1. **在中心服注册登录组件**。`LoginComponent` 通过 `[ComponentType(GlobalConst.ActorTypeServer)]` 绑定到 `ActorTypeServer`,作为账号/角色登录的承载组件。

       protected override bool IsCreateDefaultState { get; set; } = false;

2. **实现按角色 ID 查询玩家**。在 `LoginComponent` 中暴露 `OnPlayerLogin(ReqPlayerLogin)`,内部使用 `GameDb.FindAsync<PlayerState>` 按主键查询;每次调用前先打点登录计数器。

   ```csharp
   public async Task<PlayerState> OnPlayerLogin(ReqPlayerLogin reqLogin)
   {
       MetricsPlayerHelper.LoginCounterOptions.Inc();
       return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
   }
   ```

   Source: [GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L43-L47)

3. **编写 Agent 完成绑定与转发**。`LoginComponentAgent.OnPlayerLogin` 负责:调用组件查询玩家、把玩家 `Id` 写入 `NetWorkChannel`(键名 `GlobalConst.ActorIdKey`),再通过 `ActorManager` 拿到玩家 Actor 上的 `PlayerComponentAgent`,把登录交给真正的玩家组件。

   ```csharp
   public async Task OnPlayerLogin(INetWorkChannel workChannel, ReqPlayerLogin reqLogin, RespPlayerLogin response)
   {
       var playerState = await OwnerComponent.OnPlayerLogin(reqLogin);
       if (playerState == null)
       {
           //角色找不到？
           return;
       }

       // 绑定玩家ID
       workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id);
       var playerComponentAgent = await ActorManager.GetComponentAgent<PlayerComponentAgent>(playerState.Id);
       await playerComponentAgent.OnPlayerLogin(workChannel, playerState, response);
   }
   ```

   Source: [GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs#L37-L58)

4. **注册消息处理器**。`ReqPlayerLoginHandler` 通过 `[MessageMapping(typeof(ReqPlayerLogin))]` 标注,继承 `GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>`,在 `ActionAsync` 中直接把请求转发给 Agent。

   ```csharp
   [MessageMapping(typeof(ReqPlayerLogin))]
   internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
   {
       protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
       {
           await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
       }
   }
   ```

5. **在客户端发送登录**。客户端按 `ReqPlayerLogin` 协议(包含 `Id`)发起请求,等待 `RespPlayerLogin` 返回,后续业务消息即可在玩家 Actor 上处理。

## 常见变体

- **HTTP 登录入口**:仓库另有 `GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs`,用于把 HTTP 请求转换成同一条登录链路;前端需要走 HTTP 而非 TCP 时可直接使用。
- **关闭示例代码**:`GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs` 当前整段被 `/* … */` 注释掉,作为旧版 `ReqLogin` 实现的参考,实际接入请使用 `ReqPlayerLogin` 链路。

## 常见错误

- **`playerState == null` 直接返回**:此时 `response` 没有被赋值,客户端会一直等待或超时。务必在 Agent 中根据业务协议给 `response` 写入错误码,或抛出明确异常。
- **忘记 `workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id)`**:后续消息无法路由到玩家 Actor,玩家收不到业务推送。
- **`IsCreateDefaultState = false` 与 `PlayerState` 缺失**:当玩家首次登录且库里无记录时,需要先在 `OnPlayerLogin` 里创建 `PlayerState`,否则永远返回 `null`。

## 背景(可选)

- `LoginComponent` 标记 `ActorTypeServer`,表明登录逻辑跑在中心服 Actor 上,不与具体玩家 Actor 耦合。
- `LoginComponentAgent` 是状态组件代理,负责把跨 Actor 的消息收敛到 `LoginComponent`,再按玩家 ID 派发到对应的 `PlayerComponentAgent`。
