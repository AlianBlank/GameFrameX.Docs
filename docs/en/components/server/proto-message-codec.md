# How to Define Proto Messages and Integrate Encoding/Decoding

By adding attribute markers to message classes and implementing the `INetworkMessage` interface, custom messages can be integrated into the framework's ProtoBuf serialization and ID routing system, enabling message encoding and decoding on both the sending and receiving ends.

## Prerequisites

- The project references `GameFrameX.ProtoBuf.Net` (which wraps ProtoBuf's `Serializer.Serialize` / `Deserialize` / `Merge`).
- The project references `GameFrameX.NetWork.Abstractions`, used for message ID registration and heartbeat/request/response categorization.
- The assembly calls `MessageProtoHelper.Init(assemblies)` once during startup, so that the attributes are scanned and written into the dictionary.

## Steps

### 1. Define the Message Type

The message class needs to implement the `INetworkMessage` interface and register a globally unique `MessageId` and `OperationType` via `MessageTypeHandlerAttribute`. Depending on the business semantics, you can optionally implement `IRequestMessage`, `IResponseMessage`, `INotifyMessage`, or `IHeartBeatMessage`.

```csharp
using GameFrameX.NetWork.Abstractions;
using GameFrameX.NetWork.Abstractions.Interface;

[MessageTypeHandler(1001, (byte)MessageOperationType.Request)]
public sealed class LoginRequest : INetworkMessage, IRequestMessage
{
    public string UserName { get; set; }
    public string Password { get; set; }
}

[MessageTypeHandler(1002, (byte)MessageOperationType.Response)]
public sealed class LoginResponse : INetworkMessage, IResponseMessage
{
    public int Code { get; set; }
    public string Token { get; set; }
}

[MessageTypeHandler(9999, (byte)MessageOperationType.Notify)]
public sealed class HeartBeat : INetworkMessage, IHeartBeatMessage
{
    public long Timestamp { get; set; }
}
```

`MessageTypeHandlerAttribute` carries `MessageId` and `OperationType`, which are used during registration to populate the internal dictionary of `MessageProtoHelper`.

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L218-L254)

### 2. Initialize Message Mapping at Startup

At application startup, hand over the assemblies containing message classes to `MessageProtoHelper.Init`. It will scan all types marked with `MessageTypeHandlerAttribute` and register them by ID into `AllMessageDictionary`, `RequestDictionary`, `ResponseDictionary`, `HeartBeatList`, and `OperationType`. If the ID is duplicated, an `ArgumentAlreadyException` will be thrown.

```csharp
using System.Reflection;
using GameFrameX.NetWork.Abstractions;

MessageProtoHelper.Init(
    Assembly.GetExecutingAssembly(),
    typeof(LoginRequest).Assembly
);
```

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L187-L208)

### 3. Use ProtoBuf for Serialization and Deserialization

`GameFrameX.ProtoBuf.Net.ProtoBufSerializerHelper` wraps ProtoBuf's `Serializer.Serialize` / `Deserialize` / `Merge`, and can be used directly for byte stream encoding/decoding of message bodies.

```csharp
using GameFrameX.ProtoBuf.Net;

// Serialize (object -> byte array)
byte[] payload = ProtoBufSerializerHelper.Serialize(loginRequest);

// Deserialize (byte array -> object)
var message = ProtoBufSerializerHelper.Deserialize<LoginRequest>(payload);

// Merge mode: merge the byte stream into an existing instance, avoiding allocation of a new object
var merged = ProtoBufSerializerHelper.Deserialize(payload, existingInstance);
```

The merge mode is suitable for incremental update scenarios. An empty byte array will return the original instance directly without throwing an exception.

Source: [ProtoBufSerializerHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.ProtoBuf.Net/ProtoBufSerializerHelper.cs#L17-L82)

### 4. Query the Message Type During the Send/Receive Process

After the network layer receives a byte stream, you can first look up the type by `MessageId`, then deserialize it using `ProtoBufSerializerHelper`:

```csharp
int messageId = ReadMessageId(buffer);
Type messageType = MessageProtoHelper.GetMessageTypeById(messageId);
if (messageType != null)
{
    object message = ProtoBufSerializerHelper.Deserialize(buffer, messageType);
    // Dispatch to handling logic...
}
```

When sending in the reverse direction, first use `MessageProtoHelper.SetMessageId(message)` to write the `MessageId` back to the object, then proceed with serialization.

Source: [MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L60-L149)

## Common Variants

| Scenario | Approach | Description |
|------|------|------|
| Heartbeat message | Implement `IHeartBeatMessage` | Automatically added to `HeartBeatList`; `GetMessageOperationType` directly returns `HeartBeat` |
| Request/Response pairing | Implement `IRequestMessage` and `IResponseMessage` respectively | Registered to `RequestDictionary` / `ResponseDictionary` respectively, facilitating RPC pairing |
| Incremental update | `Deserialize<T>(byte[] data, T instance)` | Goes through `Serializer.Merge`, reusing instances to reduce GC |
| Enum field | Use `ProtoEnumAttribute` | Provided by `GameFrameX.ProtoBuf.Net`, see the source directory |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentAlreadyException(... MessageIdDuplicate ...)` is thrown at startup | Two classes share the same `MessageId` | Modify the first parameter of `MessageTypeHandler` to ensure global uniqueness |
| `GetMessageTypeById` returns `null` | `Init` was not called for this ID, or it was not registered | Call `MessageProtoHelper.Init(assembly)` at startup and ensure the message class is compiled into that assembly |
| `ProtoBufSerializerHelper.Serialize` throws an exception | Fields lack ProtoBuf attributes such as `[ProtoMember]` / `[ProtoContract]` | Check whether the message class correctly declares ProtoBuf serialization attributes (in `GameFrameX.ProtoBuf.Net`, these correspond to `ProtoContractAttribute`, `ProtoIncludeAttribute`, etc.) |
| Heartbeat is treated as a regular message | `IHeartBeatMessage` is not implemented | Have the heartbeat class implement this interface; the `Init` phase will automatically add it to the heartbeat table |

## Background (Optional)

The framework decouples the "message ID ↔ type" mapping (`MessageProtoHelper`) from the "object ↔ bytes" mapping (`ProtoBufSerializerHelper`): the former is responsible for finding the correct .NET type by ID and distinguishing request/response/notify/heartbeat, while the latter handles binary read/write in ProtoBuf format. `GameFrameX.Proto/MessageProtoHandler` serves as a namespace placeholder; the actual encoding/decoding entry point is `ProtoBufSerializerHelper`. For how the transport layer (TCP/KCP) encapsulates these bytes, refer to the network layer documentation.
