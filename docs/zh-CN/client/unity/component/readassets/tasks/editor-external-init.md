# 在 Editor 中以外部 APK/自定义目录初始化(测试 Android 构建)

在 Unity Editor 中通过外部 APK 文件或自定义目录初始化 `BlankReadAssets`,无需打包真机即可模拟 Android StreamingAssets 的读取行为,用于本地调试 AssetBundle、热更资源或 Android 专属路径逻辑。

## 前置条件

- 工程已引入 `GameFrameX.ReadAssets` 包,且存在 `Runtime/BlankReadAssets.cs`。
- 仅在 `UNITY_EDITOR` 下生效:这两个 API 包裹在 `#if UNITY_EDITOR` 中,真机打包不会包含。
- 待测试的 APK 必须是 StreamingAssets 位于 `assets/` 的标准 Android 包(Unity 默认导出形式)。

## 操作步骤

`BlankReadAssets` 暴露了两个仅 Editor 可用的入口,根据调试目标二选一。

### 方式 A:以外部 APK 初始化

```csharp
using GameFrameX.ReadAssets.Runtime;

// 形如:Application.dataPath + "/../test.apk"
BlankReadAssets.InitializeWithExternalApk(apkPath);
```

源码入口与签名:

```csharp
[Preserve]
public static void InitializeWithExternalApk(string apkPath)
{
    BlankReadAssetsImpl.ApkMode = true;
    BlankReadAssetsImpl.Initialize(apkPath, "jar:file://" + apkPath + "!/assets/");
    s_initialized = true;
}
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

该调用会把 `EditorImpl.ApkMode` 置为 `true`,使后续 `FileExists` / `OpenRead` / `ReadAllBytes` / `GetFiles` 全部走 `ApkImpl`(即读取 APK 内的 `jar:file://...!/assets/` 路径)。

### 方式 B:以自定义目录初始化

```csharp
using GameFrameX.ReadAssets.Runtime;

// dataPath:StreamingAssets 在文件系统中的父目录根
// streamingAssetsPath:StreamingAssets 本身的实际路径(可用任意目录)
BlankReadAssets.InitializeWithExternalDirectories(dataPath, streamingAssetsPath);
```

源码入口与签名:

```csharp
[Preserve]
public static void InitializeWithExternalDirectories(string dataPath, string streamingAssetsPath)
{
    BlankReadAssetsImpl.ApkMode = false;
    BlankReadAssetsImpl.Initialize(dataPath, streamingAssetsPath);
    s_initialized = true;
}
```

Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

适用于把构建好的 StreamingAssets 拷贝到任意目录后,在 Editor 里直接以"文件目录"形式模拟读取。

### 步骤 3:调用读取 API 验证

```csharp
if (BlankReadAssets.FileExists("config/game.json"))
{
    byte[] bytes = BlankReadAssets.ReadAllBytes("config/game.json");
    // 或读取 AssetBundle
    var bundle = BlankReadAssets.LoadAssetBundle("bundles/ui.bundle");
}
```

初始化标志 `s_initialized` 会在调用一次后置 `true`,后续所有 API 不再重复初始化。

## 常见变体

| 场景 | 推荐方式 | 说明 |
|------|----------|------|
| 验证真实 Android 构建的 StreamingAssets 读取 | 方式 A(APK) | 路径前缀固定为 `jar:file://<apk>!/assets/`,与真机一致 |
| 用本地 StreamingAssets 目录调试 | 方式 B(自定义目录) | `streamingAssetsPath` 指向工程 `Assets/StreamingAssets` 之外的自定义目录 |
| 在 `Awake` 之前预热 | 任选其一手动调用 | 设置了 `s_initialized = true`,后续 `EnsureInitialized` 不会再重置模式 |

切换模式时(APK ↔ 自定义目录)必须重新调用对应初始化方法,因为 `ApkMode` 是静态标志位。

## 常见错误

- 在 Player 构建调用这两个方法:会被 `#if UNITY_EDITOR` 剥离,导致编译失败或运行时找不到符号。
- 切换模式后忘了再次初始化:前一次调用的 `ApkMode` 仍为 `true`,所有读取会继续走 APK 分支。
- 给 `InitializeWithExternalApk` 传入不存在的 APK 路径:`ApkImpl.Initialize` 不会主动抛错,但后续 `FileExists` / `OpenRead` 会找不到文件,需先用 `File.Exists(apkPath)` 自检。
- 混淆 `Application.streamingAssetsPath` 与 APK 内部路径:APK 模式下 `streamingAssetsPath` 内部被替换为 `jar:file://...!/assets/`,不要手动传 `Application.streamingAssetsPath`。

## 背景(可选)

Editor 内 `BlankReadAssetsImpl` 通过条件编译选择实现:`UNITY_EDITOR` 走 `EditorImpl`,Android 走 `ApkImpl`,其他平台走 `LooseFilesImpl`。`EditorImpl` 内部再根据 `ApkMode` 标志决定把请求转发给 `ApkImpl` 还是 `LooseFilesImpl`,从而在编辑器进程里模拟不同平台的读取行为。
