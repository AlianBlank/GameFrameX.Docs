# XCodeConfig.json 설정 필드 빠른 참조

이 페이지에는 `XCodeConfig.json`의 모든 설정 필드에 대한 타입, 기본값 및 값 설명이 수록되어 있어 표를 바로 조회하며 작성할 수 있습니다. 설정 파일은 반드시 `XCodeConfig.json`으로 명명되어야 하며, 프로젝트 내 임의의 위치에 배치할 수 있고 여러 개를 함께 두는 것도 지원합니다(빌드 시 자동으로 깊이 병합). 해당 데이터 구조 정의는 [XcodeConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XcodeConfig.cs#L11-L48)를 참조하세요.

## 최상위 필드

```json
{

  "podSource": [],
  "podfile": "",
  "podInstall": true,
  "localizations": [],
  "capabilities": {},
  "unityFramework": {},

```

## unityFramework / unityMain

두 구조는 완전히 동일하며, 각각 UnityFramework와 Unity-iPhone 두 target에 적용됩니다:

```json
{
  "libs": { "+": [], "-": [] },
  "frameworks": { "+": [], "-": [] },
  "properties": { "=": {}, "+": {}, "-": {} },
  "files": {},
  "folders": {},
  "filesCompileFlag": {},
  "otherLinkerFlag": {},
  "runPathSearchPaths": {},
  "pods": {}
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L117-L129)

| 필드 | 타입 | 설명 |
| :--- | :--- | :--- |
| `libs` | object:`{"+" : [], "-" : []}` | 시스템 라이브러리 추가/제거, 예: `libz.tbd`; `+` 추가, `-` 제거 |
| `frameworks` | object:`{"+" : [], "-" : []}` | 시스템 Framework 추가/제거, 예: `WebKit.framework` |
| `properties` | object:`{"=" : {}, "+" : {}, "-" : {}}` | 빌드 속성. `=` 덮어쓰기 설정, `+` 추가(배열은 기존 목록에 연결됨), `-` 제거 |
| `files` | object | 파일 복사. 키 = Unity 프로젝트 내 파일 경로(`Assets`와 동일한 레벨), 값 = Xcode 프로젝트 내 대상 상대 경로; 대상이 이미 존재하면 먼저 삭제 후 복사 |
| `folders` | object | 폴더 복사, `.framework`와 `.bundle` 자동 인식; 대상이 이미 존재하면 오류 발생 |
| `filesCompileFlag` | object | 키 = Xcode 프로젝트 내 파일 경로, 값 = 설정할 컴파일 플래그, 예: `-fobjc-arc` |
| `otherLinkerFlag` | object | 링크 플래그, 예: `{"OTHER_LDFLAGS": ["-ObjC"]}`; 값은 문자열 또는 배열 지원, 배열 권장(다중 설정 병합에 유리) |
| `runPathSearchPaths` | object | 런타임 검색 경로, 예: `{"LD_RUNPATH_SEARCH_PATHS": ["@executable_path/Frameworks"]}`; 마찬가지로 배열 형식 권장 |
| `pods` | object | 해당 target의 CocoaPods 의존성. 키 = pod 이름, 값 = 버전 제약; 빈 값은 `pod 'Name'` 생성, 비어 있지 않은 값은 `pod 'Name', 'Value'` 생성; 동일한 이름의 pod는 자동으로 건너뜀 |

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L131-L239)

`properties` 추가/제거/수정 예시:

```json
{
  "properties": {
    "=": { "ENABLE_BITCODE": "NO" },
    "+": { "OTHER_CFLAGS": ["-flag1", "-flag2"] },
    "-": { "UNUSED_FLAG": [""] }
  }
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L160-L173)

```json
{

    "pods": {
      "FirebaseAnalytics": "",
      "FBSDKLoginKit": "~> 14.0"
    }
  },
  "unityMain": {
    "pods": {
      "SomePod": "~> 1.0"
    }
  }
}
```

## swiftBridging — Swift 브리징 헤더 파일

Unity-iPhone(메인) target에만 적용됩니다. 기본값은 `true`이며, Swift 파일과 브리징 헤더를 자동으로 생성하고 Xcode 팝업이 없어 CI 환경에 적합합니다; `false`로 설정하면 비활성화됩니다. 활성화되면 `gameframex_swift_bridging.swift`와 `Unity-iPhone-Bridging-Header.h`를 생성하고, `SWIFT_VERSION`을 `5.0`으로 설정하며 `SWIFT_OBJC_BRIDGING_HEADER`를 구성합니다.

## localizations — 현지화

`.lproj/InfoPlist.strings`를 자동으로 생성하고 Xcode 프로젝트에 추가합니다:

```json
{
  "localizations": [
    {
      "languageCode": "en",
      "validMap": [
        { "key": "CFBundleDisplayName", "value": "My Game" }
      ]
    },
    {
      "languageCode": "zh-Hans",
      "validMap": [
        { "key": "CFBundleDisplayName", "value": "我的游戏" }
      ]
    }
  ]
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.md#L325-L345)

| 필드 | 타입 | 설명 |
| :--- | :--- | :--- |
| `languageCode` | string | ISO 639-1 언어 코드; 간체 중국어는 `zh-Hans`, 번체 중국어는 `zh-Hant` 사용 |
| `validMap` | array | 키-값 쌍 배열, 각 항목은 `key`와 `value` 포함 |

자주 사용되는 언어 코드: `en`, `zh`, `ja`, `ko`, `es`, `fr`, `de`, `it`, `pt`(`pt-BR`/`pt-PT`), `ru`, `ar`, `hi`, `tr`, `vi`, `th`, `id`; 기타는 `code-Region` 조합으로 사용 가능, 예: `en-GB`, `fr-CA`.

## 실수하기 쉬운 점

- 설정 파일 이름은 반드시 `XCodeConfig.json`이어야 하며, 다른 이름은 인식되지 않습니다.
- `otherLinkerFlag`와 `runPathSearchPaths`의 값은 문자열과 배열을 모두 지원하지만, 다중 설정 병합 시 올바르게 병합되려면 배열 형식을 권장합니다.
- `folders`는 복사 시 대상 경로가 이미 존재하면 오류가 발생합니다; `files`는 먼저 삭제 후 복사합니다.
- C# 측 `XcodeConfigData`의 필드 이름은 `library`(JSON에서는 `libs`)이고, `XcodeConfigCapabilities`의 iCloud 필드 이름은 `iCloudKeyValueStorage` / `iCloudDocuments`(JSON에서는 `iCloud.keyValueStorage` / `iCloud.iCloudDocument`)이므로 양쪽을 혼동하지 마세요.
