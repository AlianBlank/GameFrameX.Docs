# Helper 型が見つからない、または作成に失敗した場合の対処法

コード内で `Helper.Create` が `null` を返したり、リフレクション読み込み時に `cannot find Helper type` / `missing type` が発生したりする場合、通常は対応する Helper クラスがビルド時に削除（ストリッピング）されたか、名前空間／アセンブリの参照設定が不完全であることを意味します。このページでは、症状別の特定方法と修復手順を説明します。

## クイック診断

| 症状 | 原因 | 修復 |
|------|------|------|
| `Helper.Create<XXHelper>()` が `GameFrameworkException: ...` をスロー | 当該 Helper の `Create` ファクトリが未登録、またはファクトリがコンストラクタを見つけられない | リフレクションでそのクラスに引数なしコンストラクタがあるかを確認し、[修復 1](#修復-1-引数なしコンストラクタが見つからない) を参照 |
| iOS/Android IL2CPP ビルド後に特定の API で `MissingMethodException` または `TypeLoadException` が発生 | コードストリッピングにより Helper 型が削除された | シーンに `GameFrameXCroppingHelper` をアタッチするか、`link.xml` で保持する。[修復 2](#修復-2-ビルド後にストリッピングされる) を参照 |
| `typeof(GameFrameX.Runtime.DoTweenHelper)` でコンパイルエラー | 対応するプラグインがインストールされていない、またはマクロが有効化されていない | マクロを有効化するか、参照を削除する。[修復 3](#修復-3-オプションモジュールのヘルパークラス) を参照 |
| エディタ拡張で `HotFixAssemblyDefinitionHelper` などの型が見つからない | 名前空間エラー、または Editor アセンブリがコンパイルされていない | `Editor/` ディレクトリと asmdef を確認する。[修復 4](#修復-4-editor-ヘルパークラス) を参照 |
| カスタム Helper サブクラスが `not registered` をスロー | `Helper.Create` または `Register` を呼び出していない | フレームワーク規約のファクトリパターンに従って登録する。[修復 5](#修復-5-カスタム-helper) を参照 |

## 修復 1:引数なしコンストラクタが見つからない

`Helper` クラスのすべての具象実装（例：`DefaultLogHelper`、`DefaultCompressionHelper`、`DefaultTextHelper`、`DefaultVersionHelper`）には**引数なしコンストラクタ**が必要です。これは `Helper.Create<T>()` がリフレクションの `Activator.CreateInstance` 経由で呼び出されるためです。

1. Helper サブクラスを確認します：

```csharp
// 誤った例 — Helper.Create<MyHelper>() は失敗する
public class MyHelper : ILogHelper
{
    public MyHelper(string name) { /* ... */ }
}

// 正しい例
public class MyHelper : ILogHelper
{
    public MyHelper() { }
    // ...
}
```

2. Unity Console でスローされた例外の原文が `GameFrameworkException` であることを確認してください。例外のメッセージには通常、型の完全名が含まれています。

3. 修正後、`Helper.Create<MyHelper>()` を再度呼び出して検証します。

ソースコード内の具象 Helper 型のリストについては、[GameFrameXCroppingHelper.cs#L21-L60](Runtime/GameFrameXCroppingHelper.cs#L21-L60) を参照してください。

## 修復 2:ビルド後にストリッピングされる

`Runtime/GameFrameXCroppingHelper.cs` の存在目的は、IL2CPP/AOT ビルド時にフレームワーク内部の型が削除されるのを防ぐことです。すべての参照は `typeof()` で表現されています。ランタイム（エディタ以外）では、このスクリプトがシーン内にインスタンス化されていることを保証する必要があります：

1. 最初の起動シーンで、空の `GameObject` を作成し、`GameFrameXCroppingHelper` コンポーネントをアタッチして `DontDestroyOnLoad` に設定します。

```csharp
// 起動スクリプト内
var go = new GameObject("GameFrameXCroppingHelper");
go.AddComponent<GameFrameXCroppingHelper>();
DontDestroyOnLoad(go);
```

2. HybridCLR / ILRuntime などのホットアップデート方式を使用している場合、メインパッケージの AOT アセンブリの `link.xml` にこれらの型を追加する必要があります：

```xml
<linker>
  <assembly fullname="GameFrameX.Runtime" preserve="all"/>
</linker>
```

3. Build Settings で Stripping 時にこのスクリプトが削除されないことを確認します（Managed Stripping を一時的に無効にして検証することも可能です）。

参考：[GameFrameXCroppingHelper.cs#L1-L12](Runtime/GameFrameXCroppingHelper.cs#L1-L12)。

## 修復 3:オプションモジュールのヘルパークラス

`DoTweenHelper` は `#if ENABLE_GAME_FRAME_X_DO_TWEEN` で括られています（[GameFrameXCroppingHelper.cs#L9-L11](Runtime/GameFrameXCroppingHelper.cs#L9-L11)）。DOTween プラグインを導入していないのにこのマクロを有効にしている、またはその逆の場合：

| 状況 | 対処 |
|------|------|
| DOTween を使用していないのに `ENABLE_GAME_FRAME_X_DO_TWEEN` が有効 | マクロを無効化するか、`DoTweenHelper` への参照を削除する |
| DOTween を使用しているがマクロが未有効 | `Project Settings → Player → Scripting Define Symbols` で `ENABLE_GAME_FRAME_X_DO_TWEEN` を追加する |
| 他のオプショナルプラグイン（YooAsset、HybridCLR など）を使用 | 対応するプラグインのドキュメントを参照し、マクロが未有効のときは `typeof()` を記述しない |

## 修復 4:Editor ヘルパークラス

リポジトリの `Editor/` ディレクトリには `*Helper.cs`（例：`BuildHotfixHelper.cs`、`BuildPostProcessHelper.cs`、`MiniGameDefineSymbolHelper.*.cs`）が複数あり、これらは Editor アセンブリでのみ利用可能です：

1. スクリプトが `Editor/` フォルダ下にあること、または対応する `.asmdef` に `includePlatforms: ["Editor"]` が設定されていることを確認してください。
2. **ランタイムコード内で `using` や `typeof()` を記述しないでください** —— 配布パッケージに見つからずエラーになります。
3. 新しいプラットフォームのミニゲーム（`InternationalMiniGames` / `DomesticMiniGames` / `GamePlatforms`）を追加した場合は、対応するプラットフォームの `MiniGameDefineSymbolHelper.<Platform>.cs` を新規作成または補完する必要があります。

参考：[Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs](Editor/MiniGame/DeviceOEMs/MiniGameDefineSymbolHelper.Huawei.cs)、[Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs](Editor/BuildHotfix/HotFixAssemblyDefinitionHelper.cs)。

## 修復 5:カスタム Helper

フレームワーク内の `Helper` は静的ファサードクラスです（[Runtime/Helper/Helper.cs#L44](Runtime/Helper/Helper.cs#L44)）。`Helper.Create<T>()` は規約に従って `T.Create()` または同名のファクトリメソッドを探します。カスタム Helper が見つからない場合は：

1. 規約通りのファクトリメソッドが実装されていることを確認してください：

```csharp
public class MyJsonHelper : IJsonHelper
{
    public static IJsonHelper Create()
    {
        return new MyJsonHelper();
    }

    private MyJsonHelper() { } // プライベートコンストラクタ、Create 経由でのみインスタンスを取得可能
}
```

2. `GameEntry` 起動後、返されたインスタンスをフレームワークに登録します：

```csharp
Utility.Json.IJsonHelper json = MyJsonHelper.Create();
GameEntry.RegisterHelper(json);
```

3. エディタでブレークポイントを設定し、`Helper.Create<T>` 内でカスタム分岐に到達していることを確認してください。

## 検証

上記の修復を完了したら、以下の手順で問題が解決したことを確認します：

1. **エディタ**：Play モードに入り、すべての `Helper.Create` 呼び出しが例外をスローしないことを確認します。
2. **IL2CPP 実機**：Player をビルドし、対象デバイスで起動して Console に `MissingMethodException` / `TypeLoadException` が出現しないことを確認します。
3. **リフレクションスキャン**：リフレクションで `GameFrameX.Runtime` アセンブリ内のすべての `*Helper` 型を列挙し、件数が [GameFrameXCroppingHelper.cs#L21-L165](Runtime/GameFrameXCroppingHelper.cs#L21-L165) のリストと一致することを確認します。
4. **ストリッピングレポート**：IL2CPP の `Strip Engine Code` 出力を有効化し、`Library/Il2cppBuildCache` で対象の型がストリッピング対象リストに含まれていないことを確認します。
