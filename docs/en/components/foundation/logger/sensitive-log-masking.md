# How to Redact Sensitive Log Fields

By using `SensitiveLogEventEnricher` + `SensitiveLogPropertyPolicy`, sensitive fields such as `token`, `password`, and `authorization` are uniformly replaced with placeholders before log events enter the Sink, preventing credentials from being written directly to log files.

## Prerequisites

- `GameFrameX.Foundation.Logger` is referenced (it is loaded by default along with the logging module; the framework's own `LogHandler` has already attached the default policy automatically).
- Use Serilog's structured logging properties (`LogContext.PushProperty` or template placeholders) to pass values; this mechanism matches by property name and does not parse the entire message string.

## Steps

### 1. Use the Framework Default Policy (Zero Configuration)

`LogHandler` automatically appends `SensitiveLogEventEnricher()` when building the Serilog pipeline, so the built-in 10 field names are redacted by default.

```csharp
// Already loaded by default in the framework, no manual registration needed
.Enrich.With(new SensitiveLogEventEnricher())
```

Source: [GameFrameX.Foundation.Logger/LogHandler.cs#L119](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHandler.cs#L119)

Field names covered by default (case-insensitive):

| Field Name |
|--------|
| `token`, `access_token`, `refresh_token` |
| `password`, `passwd` |
| `authorization`, `cookie` |
| `apiKey`, `secret`, `clientSecret` |

Source: [GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53)

The replacement text defaults to `[REDACTED]` (it also falls back to `[REDACTED]` when the passed-in `replacement` is an empty string).

### 2. Customize Sensitive Field Names

Pass in an additional field collection to override the default policy (the collection you pass in is treated as the complete set; if you want to append to the defaults, first concatenate the field names from `SensitiveLogPropertyPolicy.Default`):

```csharp
using GameFrameX.Foundation.Logger;

var policy = new SensitiveLogPropertyPolicy(
    new[] { "IdCard", "Phone", "BankAccount" },
    replacement: "***");

var enricher = new SensitiveLogEventEnricher(policy);

// Hook it into a custom LoggerConfiguration
Log.Logger = new LoggerConfiguration()
    .Enrich.With(enricher)
    .WriteTo.Console()
    .CreateLogger();
```

Source: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53)

Field name matching uses `StringComparer.OrdinalIgnoreCase`, so both `Password` and `password` will match.

### 3. Verify Redaction Takes Effect

Write a log entry with a `Password` property and check whether the output becomes `[REDACTED]`:

```csharp
using Serilog.Context;

using (LogContext.PushProperty("Password", "my-secret-password"))
{
    Log.Information("Login attempt for {UserId}", 42);
}
```

In the expected output, the `Password` field value is `[REDACTED]` instead of the real password. The Enricher recursively processes `StructureValue`, `SequenceValue`, and `DictionaryValue`, so sensitive fields nested inside structured objects are also replaced.

Source: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103)

## Common Variants

- **Model field-level redaction**: If you want to annotate ORM entities (for unified handling in lists/exports/serialization), use `[SensitiveField(MaskingStrategy.Phone)]` from `GameFrameX.Foundation.Orm.Attribute`; the strategy covers Phone, IdCard, Email, BankCard, Name, Address, and Custom. It is a separate chain from the logging Enricher and must be wired up separately at the serialization layer.

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }
}
```

Source: [GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

- **Replace with a custom placeholder**: Pass the second argument when constructing `SensitiveLogPropertyPolicy`, such as `"***"` or `"已脱敏"`; an empty string falls back to `[REDACTED]`.
- **Nested object redaction**: The Enricher recursively processes `StructureValue` / `SequenceValue` / `DictionaryValue` by default, requiring no extra configuration; replacement only occurs when a property name matches the policy.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Plaintext token still appears in logs | The credential is written into the message template (e.g., `Log.Info("token={0}", token)`) instead of as a structured property | Change to `Log.Information("token={Token}", token)` to use a structured property |
| Custom field names not taking effect | Field names contain spaces or their spelling doesn't match the policy | `_propertyNames` uses exact `OrdinalIgnoreCase` matching; double-check the names |
| Passing a `null` collection to the policy | The constructor throws `ArgumentNullException` | Pass at least `Array.Empty<string>()`, or add a null check on the custom collection |
| Model fields not redacted | `[SensitiveField]` only applies to the ORM serialization layer and is not automatically wired into Serilog | Also use `SensitiveLogEventEnricher` on the logging side |

## Background (Optional)

`SensitiveLogEventEnricher` implements Serilog's `ILogEventEnricher` and performs in-place replacement on `LogEvent.Properties` during the `Enrich` stage; the policy object is responsible for maintaining the "set of sensitive field names + replacement text". The entire chain completes before the event reaches the Sink, so all downstream consumers—files, console, remote reporting, etc.—will never see the original values.
