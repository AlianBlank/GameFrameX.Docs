# 使用 AOT 保留配置與校驗

透過 Unity 選單 `GameFrameX/HybridCLR Generate AOT Preserve` 一鍵產生 `link.xml`、參考彙總程式碼與按類型拆分的參考程式碼檔案,並透過校驗執行器在 CI 中確保產生檔案始終與最新配置一致,避免 HybridCLR 熱更新時缺失 AOT 元資料。

## 前置條件

- 專案已安裝 HybridCLR(執行時依賴熱更新 AOT 元資料)。
- 已為 `IAotPreserveSettingsProvider` 提供自訂實作,或在預設實作下放置好配置入口(預設實作位於 [IAotPreserveSettingsProvider.cs](/Editor/AotPreserve/IAotPreserveSettingsProvider.cs))。
- Unity 編輯器已開啟專案,且對 `Assets/Generated/` 目錄具備寫入權限。

## 操作步驟

1. **觸發產生**。在 Unity 編輯器頂部選單中選擇 `GameFrameX > HybridCLR Generate AOT Preserve`,會呼叫 `AotPreserveGenerator.GenerateAndWrite()`,並把日誌輸出到控制台。

   選單入口實作見 [AotPreserveMenu.cs#L20-L25](/Editor/AotPreserve/AotPreserveMenu.cs#L20-L25):

   ```csharp
   [MenuItem(AotPreserveConstants.MenuPath)]
   public static void Generate()
   {
       AotPreserveGenerator.GenerateAndWrite();
       Debug.Log("Hotfix AOT preserve files generated under " + AotPreserveConstants.GeneratedDirectory);
   }
   ```

2. **查看產生路徑**。產生根目錄預設為 `Assets/Generated/AotPreserve`,核心產物路徑由常數統一管理,見 [AotPreserveConstants.cs#L17-L65](/Editor/AotPreserve/AotPreserveConstants.cs#L17-L65):

   | 產物 | 路徑常數 | 實際路徑 |
   |------|----------|----------|
   | `link.xml`(託管程式碼 stripping 保留) | `LinkXmlPath` | `Assets/Generated/AotPreserve/link.xml` |
   | 參考彙總程式碼 | `ReferencesPath` | `Assets/Generated/AotPreserveReferences.cs` |
   | 按類型拆分參考檔名前綴 | `ReferenceTypeFilePrefix` | `AotPreserveReference_<TypeName>.cs` |
   | 產生程式碼所屬 asmdef | `GeneratedAsmdefPath` | `Assets/Generated/AotPreserve.Generated.asmdef` |
   | 產生報告 Markdown | `ReportPath` | `Assets/Generated/AotPreserve/aot_preserve_report.md` |

3. **在 CI 中呼叫校驗**。CI 或單元測試可直接呼叫 `AotPreserveValidationRunner.ValidateGeneratedFiles()`,當檔案缺失或過期時會拋出 `InvalidOperationException`,例外訊息聚合全部錯誤,見 [AotPreserveValidationRunner.cs#L20-L27](/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27):

   ```csharp
   public static void ValidateGeneratedFiles()
   {
       var errors = AotPreserveGenerator.ValidateGeneratedFiles();
       if (errors.Length > 0)
       {
           throw new InvalidOperationException(string.Join("\n", errors));
       }
   }
   ```

4. **錯誤處理**。產生過程出錯時(例如配置無效、寫入失敗),`GenerateAndWrite()` 會拋出 `InvalidOperationException`,提示以 `"Hotfix AOT preserve generation failed:\n"` 開頭並逐行列出錯誤,見 [AotPreserveGenerator.cs#L72-L78](/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L78);寫入磁碟失敗時還會拋出 `IOException` 或 `UnauthorizedAccessException`。

## 常見變體

- **程式化觸發**:不需要選單點擊時,可在編輯器腳本裡直接呼叫 `AotPreserveGenerator.GenerateAndWrite()`。
- **純建置(不寫盤)**:在自訂流水線裡只想預覽產物時,使用 `AotPreserveGenerator.Build()` 得到 `AotPreserveBuildResult`(含 `LinkXml`、`ReferencesCode`、`GeneratedAsmdef`、`Report`、`ReferenceFiles`、`Errors`),見 [AotPreserveGenerator.cs#L29-L61](/Editor/AotPreserve/AotPreserveGenerator.cs#L29-L61)。
- **自訂配置提供者**:實作 `IAotPreserveSettingsProvider` 並透過 `AotPreserveSettingsProviderResolver` 注入,可覆寫預設配置的來源。

## 常見錯誤

- **選單點擊後控制台報 `Hotfix AOT preserve generation failed: ...`**:說明 `Build()` 回傳的 `AotPreserveBuildResult.Errors` 非空,通常是 `IAotPreserveSettingsProvider` 配置不合法或分析階段失敗;按例外訊息逐條修復並重新產生。
- **CI 中校驗拋 `InvalidOperationException` 且列出多條錯誤**:表示 `link.xml`、參考程式碼或 `asmdef` 與目前分析結果比對不一致;執行一次選單產生即可重新整理。
- **`UnauthorizedAccessException`**:檢查 `Assets/Generated/AotPreserve/` 目錄的寫入權限,以及 `Assets/Generated/AotPreserve.Generated.asmdef` 是否被其他程序鎖定。
- **產生檔案缺失**:手動刪除 `Assets/Generated/AotPreserve` 後未重新觸發選單——執行一次選單產生即可重建整套產物。

## 背景(選用)

產生入口 `AotPreserveGenerator.GenerateAndWrite()` 會先呼叫 `AotPreserveAnalyzer.Analyze()` 彙總需要保留的類型,再分別產出 `link.xml`(用於託管 stripping 時的組件級保留)、聚合與按類型拆分的參考程式碼(用於在執行階段明確觸發 AOT 元資料載入),以及一份 `aot_preserve_report.md` 報告用於稽核;`ValidateGeneratedFiles()` 透過比對最新分析結果來偵測檔案是否過期。
