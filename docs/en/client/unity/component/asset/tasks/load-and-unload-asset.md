# How to Load and Release Regular Assets (Sync / Async)

This page teaches you how to use `AssetComponent` (or the underlying `AssetManager`) to load a regular asset (Prefab, Texture2D, TextAsset, etc.) by path, retrieve the object from the returned `AssetHandle`, and properly release it after use to avoid assets staying in memory.

## Prerequisites

- The asset package must be initialized. Package initialization is done via `InitPackageAsync`, with the following signature:

```csharp
public Task<bool> InitPackageAsync(string packageName, string hostServerURL, string fallbackHostServerURL, bool isDefaultPackage = false)
```

> Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L65-L98)

- When no package name is specified, the unload interface uses the default package `DefaultPackageName` / `ConstDefaultPackageName`.
- An `AssetComponent` must be attached to the scene (it forwards all loading interfaces to the internal `_assetManager`).

## Steps

### 1. Async Loading (Recommended)

Pass in the asset path, `await` to get an `AssetHandle`, then use `AssetObject` to retrieve the object. The async interface has 4 overloads:

```csharp
public Task<AssetHandle> LoadAssetAsync(string path)
public Task<AssetHandle> LoadAssetAsync<T>(string path) where T : UnityEngine.Object
public Task<AssetHandle> LoadAssetAsync(string path, Type type)
public Task<AssetHandle> LoadAssetAsync(AssetInfo assetInfo)
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L283-L399)

Example call (the generic overload is most commonly used, as it can directly constrain the asset type):

```csharp
// Asynchronously load a Prefab and instantiate it
var handle = await assetComponent.LoadAssetAsync<GameObject>("Assets/Res/Prefabs/Player.prefab");
var go = UnityEngine.Object.Instantiate((GameObject)handle.AssetObject);
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L324-L327)

### 2. Sync Loading

For initialization flow and small startup assets, you can use the sync interface. The return value is not a `Task`, but a direct `AssetHandle`:

```csharp
public AssetHandle LoadAssetSync(string path)
public AssetHandle LoadAssetSync<T>(string path) where T : UnityEngine.Object
public AssetHandle LoadAssetSync(string path, Type type)
public AssetHandle LoadAssetSync(AssetInfo assetInfo)
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L491-L547)

```csharp
var handle = assetComponent.LoadAssetSync<TextAsset>("Assets/Res/Config/level.txt");
var text = ((TextAsset)handle.AssetObject).text;
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L544-L547)

### 3. Release After Use

There are three levels of granularity for releasing—choose based on what you have:

```csharp
// A. Only know the asset path (default package)
assetComponent.UnloadAsset("Assets/Res/Prefabs/Player.prefab");

// B. Multi-package scenario, specify package name
assetComponent.UnloadAsset("MyPackage", "Assets/Res/Prefabs/Player.prefab");

// C. Have a handle on hand
assetComponent.UnloadAssetHandle(handle);
```

> Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L766-L795)

Under the hood, unloading by path uses `TryUnloadUnusedAsset`, meaning "try to unload unreferenced assets"—it won't actually unload if still referenced:

```csharp
public void UnloadAsset(string assetPath)
{
    GameFrameworkGuard.NotNull(assetPath, nameof(assetPath));
    var package = YooAssets.GetPackage(DefaultPackageName);
    package.TryUnloadUnusedAsset(assetPath);
}
```

> Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L100-L124)

### 4. Bulk Recycling (When Switching Scenes)

```csharp
// Unload assets with no current references (default package; pass null for packageName to use the default package)
assetComponent.UnloadUnusedAssetsAsync();

// Forcefully recycle all assets in the package (ensure no objects are still in use)
assetComponent.UnloadAllAssetsAsync("MyPackage");
```

> Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L126-L163)

## Common Variations

| Need | Which Interface to Use | Return Type |
|------|-----------|---------|
| Just one asset, async | `LoadAssetAsync<T>(string path)` | `Task<AssetHandle>` |
| Just one asset, sync | `LoadAssetSync<T>(string path)` | `AssetHandle` |
| Type determined at runtime | `LoadAssetAsync(string path, Type type)` / `LoadAssetSync(string path, Type type)` | `Task<AssetHandle>` / `AssetHandle` |
| Already have an `AssetInfo` | `LoadAssetAsync(AssetInfo)` / `LoadAssetSync(AssetInfo)` | `Task<AssetHandle>` / `AssetHandle` |
| Load all objects in an asset bundle | `LoadAllAssetsAsync<T>(string path)` / `LoadAllAssetsSync<T>(string path)` | `Task<AllAssetsHandle>` / `AllAssetsHandle` |
| Load sub-asset objects (e.g. Sprites in an atlas) | `LoadSubAssetsAsync(string path)` / `LoadSubAssetsSync(string path)` | `SubAssetsHandle` |
| Load raw files (binary/text original) | `LoadRawFileAsync(string path)` / `LoadRawFileSync(string path)` | `Task<RawFileHandle>` / `RawFileHandle` |
| Load a scene | `LoadSceneAsync(string path, LoadSceneMode sceneMode, bool activateOnLoad = true)` | `Task<SceneHandle>` |

### Check Whether Download Is Needed Before Loading

When remote assets haven't been downloaded yet, direct loading will stall because it needs to download first. You can probe in advance:

```csharp
if (assetComponent.IsNeedDownload("Assets/Res/Prefabs/Boss.prefab"))
{
    // Run the download/update flow first, then load
}
```

The repository splits out separate partial class files for common Unity types (`AssetComponent.Prefab.cs`, `AssetComponent.Sprite.cs`, `AssetComponent.Texture2D.cs`, `AssetComponent.TextAsset.cs`, `AssetComponent.AudioClip.cs`, `AssetComponent.Material.cs`, `AssetComponent.Shader.cs`, etc.). ## Common Mistakes

| Wrong Practice | Consequence | Correct Practice |
|---------|------|---------|
| Pass `null` to `path` | Underlying `GameFrameworkGuard.NotNull(assetPath, nameof(assetPath))` throws an exception | Ensure the path is non-empty before calling |
| Load/unload before package is initialized | `YooAssets.GetPackage(...)` can't find the package | `await InitPackageAsync(...)` successfully first, then load |
| Forget to pass package name when unloading multi-package assets | Uses `DefaultPackageName`; the target asset is actually not unloaded | Use the `UnloadAsset(packageName, assetPath)` overload |
| Expect `UnloadAsset` to release memory immediately | Underlying method is `TryUnloadUnusedAsset`; won't unload if still referenced | Destroy instantiated objects/break references first, then unload; call `UnloadUnusedAssetsAsync()` if needed |
| Heavy use of sync loading in the main game thread | Frame stutter | Always use `LoadAssetAsync` during runtime; sync only for startup/initialization |
| Use `handle` directly as the asset object | Type mismatch | Use `handle.AssetObject` and cast to the target type |
| Call `UnloadAllAssetsAsync` on a package still in use | Referenced objects lost, textures turn purple | Only call when switching scenes and after confirming nothing is referencing |

## Background (Optional)

Internally, the async interface uses `TaskCompletionSource` to bridge YooAssets' `Completed` callback into a `Task`, so you can directly `await` it. This is also why all loading interfaces return handles (`AssetHandle`, etc.) instead of bare objects—the handle carries the reference count, and unloading depends on it.
