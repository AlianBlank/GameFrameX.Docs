# 巨集開關未生效或發生衝突時該怎麼辦

此套件的功能巨集(`FAIRYGUI_TMPRO`, `FAIRYGUI_SPINE`, `FAIRYGUI_INPUT_SYSTEM`, `WECHAT_MINI_GAME`, `DOUYIN_MINI_GAME`)**並非在 Player Settings 的 Scripting Define Symbols 中手動定義**，而是由 `Fairygui.Runtime.asmdef` 的 `versionDefines` 根據對應套件的安裝與否自動開啟和關閉。巨集「未生效」的情況，大多是對應套件未安裝、套件名稱不一致，或是手動在全域符號中加入巨集但缺少相依性而導致衝突錯誤。

## 快速診斷

| 症狀 | 原因 | 解決方案 |
|------|------|------|
| 使用 Input System 套件但觸控/點擊無反應 | `FAIRYGUI_INPUT_SYSTEM` 未定義(套件名稱與 versionDefines 不一致或未安裝)，`Stage` 使用了舊輸入分支 | 確認已安裝 `com.unity.inputsystem`,參考下方步驟 1 |
| TMP 相關程式碼(底線、faceDilate 等)未生效 | `FAIRYGUI_TMPRO` 未定義，專案中沒有 `com.unity.textmeshpro` | 安裝 TextMeshPro 套件並觸發重新編譯 |
| `GLoader3D` 的 Spine 資源載入無法運作 / `case PackageItemType.Spine` 分支在編譯時被移除 | `FAIRYGUI_SPINE` 未定義，兩個 spine 套件名稱皆不匹配 | 安裝 spine 套件(只需匹配其中之一即可)，參考步驟 1 的套件名稱清單 |
| 在 Player Settings 手動加入 `FAIRYGUI_SPINE` 後，編譯時發生 CS0246 錯誤(找不到 `Spine.Unity.SkeletonDataAsset` 等) | 巨集被強制開啟，但專案中沒有 spine 相依性，導致 `UIPackage`/`GLoader3D` 的 Spine 程式碼無法編譯 | 刪除手動加入的全域巨集，並安裝對應套件，讓 versionDefines 自動開啟 |
| 微信/抖音小遊戲的 `GTextInputWeChat` / `GTextInputDouYin` 整個檔案未被編譯 | 條件為 `UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME`(抖音亦同)，三個條件必須全部成立 | 切換至 WebGL 平台 + 安裝對應 SDK 套件 + 在 Wx/StarkWebGL 端啟用 `ENABLE_*` 巨集 |
| Editor 組件中 `#if` 永遠為 false | `Fairygui.Editor.asmdef` 的 `versionDefines` 為空，導致編輯器組件無法辨識這些巨集 | 請勿在 Editor 程式碼中依賴這些巨集；僅在 Runtime 組件中使用 |

## 巨集與套件名稱對照表

巨集的實際來源是 [Fairygui.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Fairygui.Runtime.asmdef#L20-L51) 的 `versionDefines`:

| 巨集 | 觸發的套件 | 在原始碼中控制的內容 |
|----|--------------|----------------|
| `FAIRYGUI_INPUT_SYSTEM` | `com.unity.inputsystem` | `Stage` 的輸入讀取(新/舊輸入系統切換) |
| `FAIRYGUI_TMPRO` | `com.unity.textmeshpro` | `GTextField` 的 TMP 渲染與屬性序列化 |
| `FAIRYGUI_SPINE` | `com.gameframex.unity.esotericsoftware.spine.spine-unity` 或 `com.esotericsoftware.spine.spine-csharp`(兩者之一) | `GLoader3D` 的 Spine 載入/更新/釋放，`UIPackage` 的 Spine 資源綁定 |
| `WECHAT_MINI_GAME` | `com.qq.weixin.minigame` | 與 `UNITY_WEBGL`、`ENABLE_WECHAT_MINI_GAME` 一起啟用微信小遊戲輸入框 |
| `DOUYIN_MINI_GAME` | `com.bytedance.starksdk` | 與 `UNITY_WEBGL`、`ENABLE_DOUYIN_MINI_GAME` 一起啟用抖音小遊戲輸入框 |

核心原始碼片段(巨集實際生效的位置)：

```csharp
#if FAIRYGUI_INPUT_SYSTEM
using UnityEngine.InputSystem;
#endif
```

出處:[Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L12)

```csharp
#if UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME
using UnityEngine;
```

出處:[GTextInputWeChat.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputWeChat.cs#L1-L2)

```csharp
#if UNITY_WEBGL && DOUYIN_MINI_GAME && ENABLE_DOUYIN_MINI_GAME
```

出處:[GTextInputDouYin.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputDouYin.cs#L1-L1)

## 修復步驟

1. **首先確認套件是否確實已安裝。** 開啟 `Packages/manifest.json` 或 Package Manager,確認下方清單中的套件名稱是否**完全一致**(versionDefines 以套件名稱為基準進行精確匹配，且區分大小寫)：
   - `FAIRYGUI_SPINE` → `com.gameframex.unity.esotericsoftware.spine.spine-unity` **或** `com.esotericsoftware.spine.spine-csharp`
   - `FAIRYGUI_TMPRO` → `com.unity.textmeshpro`
   - `FAIRYGUI_INPUT_SYSTEM` → `com.unity.inputsystem`
   - `WECHAT_MINI_GAME` → `com.qq.weixin.minigame`
   - `DOUYIN_MINI_GAME` → `com.bytedance.starksdk`
   備註:`Runtime/Fairygui.Runtime.asmdef` 的 `references` 同時參考了 `spine-unity.Runtime`、`spine-unity`、`spine-csharp` 等，只要其中一個 spine 套件存在，巨集就會開啟。若全都沒有，建議將 `FAIRYGUI_SPINE` 也一併保持關閉(即不要手動加入巨集)。
2. **移除手動加入的全域巨集。** 開啟 *Edit → Project Settings → Player → Scripting Define Symbols*,確認**沒有**自行撰寫的 `FAIRYGUI_*`、`WECHAT_MINI_GAME`、`DOUYIN_MINI_GAME`。這些巨集由 asmdef 版本約束管理，若手動硬編碼，即使移除套件後相關程式碼仍會持續被強制編譯，導致 CS0246 之類找不到型別的錯誤。
3. **觸發重新編譯。** 安裝/移除套件時 Unity 會自動重新整理。若沒有，請在專案視窗中以滑鼠右鍵執行 *Reimport All*,或重新啟動 Unity。versionDefines 會在網域重新載入時重新評估。
4. **小遊戲平台需確認三個條件。** 微信/抖音輸入框類別只有在 `UNITY_WEBGL && <平台巨集> && ENABLE_*` 同時成立時才會編譯：
   - 切換至 WebGL 建置平台(只有此時 `UNITY_WEBGL` 才為真)；
   - 對應的平台巨集由 SDK 套件自動定義(參考上表)；
   - `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` 由 Wx / StarkWebGL 相關套件提供。若您使用的 SDK 版本未提供這些巨集，則該檔案保持關閉是正常現象，請勿手動撰寫加入。
5. **請勿在 Editor 程式碼中依賴這些巨集。** [Fairygui.Editor.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/Fairygui.Editor.asmdef#L15-L15) 的 `versionDefines` 是空陣列，因此在編輯器組件中完全看不到上述巨集。需要以巨集進行分支的程式碼，務必放入 `Runtime` 組件中。

## 驗證

- 在任一 Runtime 腳本中暫時加入編譯時期的自我檢查程式碼(確認後請刪除)：

```csharp
#if FAIRYGUI_INPUT_SYSTEM
        Debug.Log("FAIRYGUI_INPUT_SYSTEM on");
#endif
#if FAIRYGUI_SPINE
        Debug.Log("FAIRYGUI_SPINE on");
#endif
```

- 開啟 [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L11) 或 [GTextField.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextField.cs#L45-L46),若在 IDE 中 `#if` 內部的程式碼不再以灰色顯示(停用時會顯示為灰色)，即表示巨集已生效。
- 確認先前因手動撰寫巨集而產生的 CS0246 / CS0103 編譯錯誤，在刪除全域巨集後已消失，且主控台中沒有出現新的錯誤。
