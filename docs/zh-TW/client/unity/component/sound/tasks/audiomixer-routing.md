# AudioMixer 連接與聲音群組路由方式

將 `AudioMixer` 資產連接至 `SoundComponent` 後，聲音會依 `SoundGroup` 自動路由至對應的 `AudioMixerGroup`,即可透過混音器統一控制音量、效果與靜音。

## 前置條件

- 場景中必須已存在 `SoundComponent`(新增方式:`GameObject → Add Component → GameFrameX/Sound`)。
- `Assets/Resources/` 下必須已有名為 `MainAudioMixer.mixer` 的 `AudioMixer` 資產，或已準備好建立該資產。

## 操作步驟

1. **準備 AudioMixer 資產**

   將混音器檔案放置於 `Assets/Resources/MainAudioMixer.mixer`。`SoundComponent` 預設會從此處以 `Resources.Load<AudioMixer>("MainAudioMixer")` 載入。若該資源不存在，元件會在編輯器環境中自動建立預設值。

   ```csharp
   private const string DefaultAudioMixerResourceName = "MainAudioMixer";
   private const string DefaultAudioMixerAssetPath = "Assets/Resources/MainAudioMixer.mixer";
   ```

   來源:[SoundComponent.cs#L54-L59](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L54-L59)

2. **將 AudioMixer 連接至 SoundComponent**

   在 Inspector 中，將準備好的 `MainAudioMixer` 資產拖曳至 `Audio Mixer` 欄位。若留空，會在 `Awake` 中自動嘗試載入。

   ```csharp
   [SerializeField] private AudioMixer m_AudioMixer = null;
   ```

   載入與備援邏輯：

   ```csharp
   private void EnsureAudioMixer()
   {
       if (m_AudioMixer != null) { return; }
       m_AudioMixer = Resources.Load<AudioMixer>(DefaultAudioMixerResourceName);
   #if UNITY_EDITOR
       if (m_AudioMixer == null)
       {
           m_AudioMixer = CreateDefaultAudioMixer();
       }
   #endif
       if (m_AudioMixer == null)
       {
           Log.Warning("Default audio mixer '{0}' is missing. Sound will use Unity default audio output.", DefaultAudioMixerResourceName);
       }
   }
   ```

   來源:[SoundComponent.cs#L67](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L67), [SoundComponent.cs#L134-L152](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L134-L152)

3. **在 AudioMixer 中為各聲音群組建立同名的 AudioMixerGroup**

   在 `MainAudioMixer` 中建立新的 `AudioMixerGroup`。**Group 名稱必須與 `SoundComponent.SoundGroups` 中的群組名稱完全一致**(例如:`Music`、`SFX`、`UI`)。群組名稱是路由的唯一依據。

4. **在 SoundComponent 中設定 SoundGroups**

   在 Inspector 的 `Sound Groups` 陣列中新增項目，每個項目對應一個群組：

   | 欄位 | 用途 |
   |------|------|
   | `Name` | 必須與 `AudioMixerGroup` 同名，用於自動路由 |
   | `AvoidBeingReplacedBySamePriority` | 在相同優先順序下是否允許被取代 |
   | `Mute` | 群組靜音 |
   | `Volume` | 群組音量 |
   | `Agent Helper Count` | 代理器數量 |

5. **確認執行階段路由已生效**

   `SoundComponent.Awake` 呼叫 `EnsureAudioMixer` 之後，會為每個 `SoundGroup` 建立對應的代理器。`DefaultSoundAgentHelper.AudioMixerGroup` 會直接橋接至 `AudioSource.outputAudioMixerGroup`,播放時便會依群組路由。

   ```csharp
   public override AudioMixerGroup AudioMixerGroup
   {
       get { return m_AudioSource.outputAudioMixerGroup; }
       set { m_AudioSource.outputAudioMixerGroup = value; }
   }
   ```

   來源:[DefaultSoundAgentHelper.cs#L167-L171](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/DefaultSoundAgentHelper.cs#L167-L171)

## 常見變化

- **不放置於 Resources 下**：直接在 Inspector 中手動拖曳混音器資產，略過 `Resources.Load` 步驟。
- **多個混音器**：可針對不同的 `SoundGroup`,在 `AddSoundGroup` 之後指定 `AudioMixerGroup`。目前的預設實作會匹配與 `SoundGroup.Name` 同名的 `AudioMixerGroup`。
- **自訂 Helper**:將 `SoundGroup Helper Type Name` 替換為自己的實作，直接管理群組建立邏輯。

## 常見錯誤

| 現象 | 原因 | 解決方式 |
|------|------|------|
| `Log.Warning("Default audio mixer 'MainAudioMixer' is missing.")` | 在 `Resources` 下找不到 `MainAudioMixer`,且因非編輯器環境而不會自動建立 | 確認資產位於 `Assets/Resources/MainAudioMixer.mixer`,或在 Inspector 中手動拖曳放入 |
| 聽不到聲音但沒有錯誤 | 場景中沒有 `AudioListener` | `SoundComponent` 啟動時會呼叫 `RefreshAudioListener`,請確認場景中有攝影機或 `AudioListener` |
| 特定群組的靜音無效 | `AudioMixerGroup` 名稱與 `SoundGroup.Name` 不一致 | 在 `AudioMixer` 中將 Group 名稱變更為與群組名稱完全一致 |

## 背景說明(選用)

`EnsureAudioMixer` 只負責取得 `AudioMixer` 的控制代碼，實際的「群組→混音器群組」映射是由 `DefaultSoundAgentHelper.AudioMixerGroup` 透過 `AudioSource.outputAudioMixerGroup` 執行。因此只要名稱對齊，Unity 就會自行處理路由，無需額外的綁定程式碼。
