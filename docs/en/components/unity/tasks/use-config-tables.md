# How to Load and Use Config Tables (Config Center)

This page explains how to load and use config table data in GameFrameX.Unity that is generated by the LuBan tool and hosted under the `Hotfix.Config` assembly. Config tables are provided in the `TbXxxConfig` form; after unified initialization via the `TablesComponent` component, entries can be queried by `Id` or string key.

## Prerequisites

- Config table code has been generated via the LuBan editor extension (default output directory: `Assets/Hotfix/Config/Generate/`).
- The project has imported the `GameFrameX.Config.Runtime` and `SimpleJSON` runtime dependencies.
- The business side has agreed on the resource loading method for config tables (local StreamingAssets / remote CDN) and provides a `Func<Task<JSONNode>>` to the `TbXxxConfig` constructor.

## Steps

1. Confirm that the entity class and table class for the config table have been generated. Each table corresponds to two files: the entity class `XxxConfig` (fields + constructor + `Deserialize`) and the table class `TbXxxConfig` (inheriting `BaseDataTable<XxxConfig>`).

   Example: the `AchievementConfig` entity class is defined in [AchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L16-L50), and the table container is in [TbAchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L60). `TbAchievementConfig` inherits `BaseDataTable<Tables.AchievementConfig>` and injects `_loadFunc` through its constructor.

   ```csharp
   // Source: Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L38
   public partial class TbAchievementConfig : BaseDataTable<Tables.AchievementConfig>
   {
       private readonly System.Func<System.Threading.Tasks.Task<JSONNode>> _loadFunc;
       public TbAchievementConfig(System.Func<System.Threading.Tasks.Task<JSONNode>> loadFunc)
       {
           _loadFunc = loadFunc;
       }
       public override async System.Threading.Tasks.Task LoadAsync()
       {
           var jsonNode = await _loadFunc();
           StringDataMaps.Clear();
           DataList.Clear();
           foreach(var _ele in jsonNode.Children)
           {
               Tables.AchievementConfig _v;
               { if(!_ele.IsObject) { throw new SerializationException(); }
                 _v = Tables.AchievementConfig.DeserializeAchievementConfig(_ele); }
               DataList.Add(_v);
               LongDataMaps.Add(_v.Id, _v);
               StringDataMaps.Add(_v.Id.ToString(), _v);
           }
           PostInit();
       }
   }
   ```

2. Provide a `loadFunc` for each table, which internally reads JSON from local/remote resources and deserializes it into a `JSONNode`.

   ```csharp
   // loadFunc example: asynchronously read and parse JSON from StreamingAssets
   Func<Task<JSONNode>> loadAchievement = async () =>
   {
       var text = await File.ReadAllTextAsync(
           Path.Combine(Application.streamingAssetsPath, "AchievementConfig.json"));
       return JSON.Parse(text);
   };

   var tbAchievement = new TbAchievementConfig(loadAchievement);
   await tbAchievement.LoadAsync();
   ```

3. Register all `TbXxxConfig` tables with `TablesComponent`, which uniformly manages loading, cross-table reference resolution (`ResolveRef`), and localization key translation (`TranslateText`).

   ```csharp
   // Add table instances to TablesComponent and perform initialization
   var tables = new TablesComponent();
   tables.Add(tbAchievement);   // Other TbXxxConfig tables work the same way
   await tables.InitAsync();    // Internally calls each table's LoadAsync + ResolveRef in dependency order
   ```

4. Query data by `Id` or key in business code. `BaseDataTable<T>` provides three collections — `LongDataMaps`, `StringDataMaps`, and `DataList` — which can be read directly by key.

   ```csharp
   // Example of fields exposed by the entity class (read-only properties)
   // Source: Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L51-L80
   var row = tables.Achievement.Get(1001);   // LongDataMaps["1001"]
   var nameKey = row.Name;                   // Localization Key
   var conditions = row.AchievementUnlockCondition;  // List<int>
   ```

5. Handle cross-table references and localization: after all tables have finished `LoadAsync`, call `ResolveRef(tables)` so entries can resolve references to other tables; then call `TranslateText(translator)` to complete the localization of `xxx_Localization_Key` fields.

   ```csharp
   // Source: TbAchievementConfig.cs#L40-L54
   tbAchievement.ResolveRef(tables);
   tbAchievement.TranslateText((key, defaultText) => Localization.Get(key) ?? defaultText);
   ```

## Common Variants

- **Local resources vs. remote resources**: `loadFunc` can implement either reading from `Application.streamingAssetsPath` or downloading via `UnityWebRequest.Get`; as long as it ultimately returns a `JSONNode`, either approach works.
- **Localization keys**: During construction, `AchievementConfig` copies localization fields to `Name_Localization_Key`, `AchievementContent_Localization_Key`, and `LockText_Localization_Key`, which are replaced via the `TranslateText` callback.
- **Extended type mapping**: Enums and external types can be registered in [ExternalTypeUtil.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Extension/ExternalTypeUtil.cs), so LuBan can reference them during deserialization.

## Common Errors

- **JSON field type mismatch**: `Deserialize` throws `SerializationException` when types do not match (the assertion at lines 31–36 of `AchievementConfig.cs`). Check that the Excel/JSON export script and the entity class field types are consistent.
- **Forgetting to call `ResolveRef`**: Cross-table reference fields will keep their default/empty values; be sure to call it after all tables have finished `LoadAsync`.
- **Repeated `LoadAsync`**: Failing to call `Clear()` first will cause duplicate keys in `LongDataMaps`/`StringDataMaps`; the generated code calls `Clear()` at the beginning, but caution is still needed when manually reusing `loadFunc`.
- **Directly modifying generated files**: `XxxConfig.cs` and `TbXxxConfig.cs` both carry the `<auto-generated>` marker at the top; any changes will be overwritten the next time code is generated. Custom logic should be placed in another part of the `partial` file.

## Background (Optional)

LuBan is an Excel→JSON→C# code generation tool that ships alongside GameFrameX: Excel defines the table structure, and the tool produces JSON data files plus the entity + container code in the `BeanBase` / `BaseDataTable<T>` form shown above. `TablesComponent` acts as the config center, uniformly loading tables and resolving references during the startup phase and triggering localization on demand, so the business side only programs against strongly-typed objects.
