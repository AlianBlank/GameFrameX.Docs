# MongoDB 接続失敗またはエンティティシリアライズエラーが発生した場合の対処法

サービス起動時に `MongoDB connection failed`、`データベースサービス起動失敗`、`No serializer found for ...`、`An error occurred while deserializing ...` などのエラーが発生した場合、本ページの診断表で原因を特定し、対応するセクションに従って修復してください。

## クイック診断

| 症状（コンソール/ログ原文） | 根本原因 | 修復方法 |
|---|---|---|
| `データベースサービス起動失敗` / `MongoDB connection failed` / `TimeoutException` | `DataBaseUrl` に到達できない、アカウント/パスワードの誤り、`authSource` の不一致、シングルマシン直接接続で `directConnection` が有効化されていない | 「接続設定エラー」を参照 |
| `MongoCommandException: Authentication failed` | ユーザー名/パスワードの誤り、または対象データベースにアカウントが作成されていない | 「認証失敗」を参照 |
| `No serializer found for type X` / `An error occurred while deserializing the X bson element ...` | エンティティクラスに BsonClassMap が登録されていない、または基底クラスの `BaseCacheState` フィールドが無視されていない | 「エンティティシリアライズ失敗」を参照 |
| 起動時にハング、または初回 `Insert`/`Find` で `MongoConnectionException` | Docker コンテナが起動していない、ポートが占有されている、またはサービスが Mongo より先に起動している | 「サービス依存関係とポート」を参照 |
| 書き込み後、フィールドがすべて `_t` discriminator になるが、読み出すと `null` になる | 複数のアセンブリで同じ完全クラス名を使用し `Discriminator` が設定されていない、またはサブクラスが登録されていない | 「エンティティシリアライズ失敗 → Discriminator 競合」を参照 |

## 修復手順

### 接続設定エラー

1. 設定キー `DataBaseUrl` の記述を確認します。デフォルトでは [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L61-L65) の `Setting.DataBaseUrl` から `GameDb.Init<MongoDbService>` に渡され、接続文字列の形式は MongoDB Driver の要件に準拠する必要があります。

2. ローカル Docker を起動する際は [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L2-L13) に付属のコンテナ設定を使用します：

   ```yaml
   mongodb:
     image: mongo
     container_name: mongodb
     ports:
       - "27017:27017"
     volumes:
       - ./running/database:/data/db
     environment:
       - MONGO_INITDB_ROOT_USERNAME=admin
       - MONGO_INITDB_ROOT_PASSWORD=admin
   ```

   対応する接続文字列の例（compose の環境変数と一致）：

   ```bash
   DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L60-L72)

3. [MongoDB Atlas](https://www.mongodb.com/atlas) などのクラウドサービスを使用する場合は、`mongodb+srv://` 形式を維持し、`retryWrites=true&w=majority` を付加してください：

   ```csharp
   DataBaseUrl = "mongodb+srv://gameframex:***@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority",
   DataBaseName = "gameframex",
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L112-L113)

4. ローカルで `127.0.0.1` に直接接続する際に `No routing to host` が発生した場合は、`directConnection=true` を追加してください：

   ```text
   mongodb://admin:admin@127.0.0.1:27017/?authSource=admin&directConnection=true
   ```

### 認証失敗

1. `MONGO_INITDB_ROOT_USERNAME`/`MONGO_INITDB_ROOT_PASSWORD` と接続文字列内のアカウントが一致しているか確認します。
2. アカウントが `admin` に作成され、対象データベースが `gameframex` の場合、接続文字列には必ず `?authSource=admin` を付ける必要があります。付けないと driver がデフォルトデータベースで検証し、`Authentication failed` が発生します。
3. カスタムアカウント作成後に単一データベースのみに権限を付与する場合：`authSource` はそのデータベース名と等しくなければなりません。

### サービス依存関係とポート

1. `docker compose up mongodb -d` でまずコンテナが正常であることを確認します：

   ```bash
   docker ps --filter name=mongodb
   docker logs mongodb --tail 50
   ```

2. コンテナとゲームプロセスは同じ `gameframex` ネットワーク下にある必要があります。ゲームプロセスを単独で実行する場合は、`DataBaseUrl` のホスト名を `localhost` または対応する IP に変更してください。
3. ホストのポート `27017` が占有されている場合は、compose のマッピングを変更し（例：`"27018:27017"`）、接続文字列も `27018` に同期して変更します。

### エンティティシリアライズ失敗

1. 起動時にアセンブリ内のすべての `BaseCacheState`/`CacheState` を継承するエンティティをスキャンし、BsonClassMap を登録します。登録のエントリーポイントは [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33) を参照してください：

   ```csharp
   var assembly = typeof(AppsHandler).Assembly;
   BsonClassMapHelper.SetConvention();
   foreach (var type in assembly.GetTypes())
   {
       if (!typeof(BaseCacheState).IsAssignableFrom(type)) continue;
       HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
       BsonClassMapHelper.RegisterClass(type);
   }
   ```

   Source: [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)

2. `BsonClassMapHelper` は自動的にマッピングし、余分なフィールドを無視します。実装は [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143) を参照してください：

   ```csharp
   var bsonClassMap = new BsonClassMap(t);
   bsonClassMap.AutoMap();
   bsonClassMap.SetIgnoreExtraElements(true);
   bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
   BsonClassMap.RegisterClassMap(bsonClassMap);
   ```

   Source: [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

3. `No serializer found for type X` が発生した場合の一般的な原因と対応：
   - エンティティクラスが `BaseCacheState` を継承しておらず、登録フローでスキップされている — エンティティに `BaseCacheState` を継承させるか、呼び出し前に手動で `BsonClassMap.RegisterClassMap<T>()` を実行してください。
   - エンティティが別アセンブリ（例：`GameFrameX.Hotfix`）で定義されているが、`CacheStateTypeManager` は `AppsHandler` アセンブリのみをスキャンしている — ホット更新エントリポイントで同期的に登録処理を呼び出すか、スキャナを拡張して Hotfix アセンブリをカバーしてください。
   - エンティティが未具体化のジェネリック引数を使用している — 登録前にジェネリック実引数を補完してください。

4. **Discriminator 競合**：異なるサブタイプで同じ名前、アセンブリを跨いで同じ完全クラス名があると、デシリアライズ時に `null` になります。エンティティクラスで明示的に指定してください：

   ```csharp
   [BsonDiscriminator("player_attr_v1")]
   public sealed class PlayerAttributeState : BaseCacheState { /* ... */ }
   ```

5. **基底クラスフィールドの混入**：`BaseCacheState` に付属の辞書/バージョン番号フィールドを MongoDB に書き込まない場合は、フィールドに `[BsonIgnore]` を追加してください。`SetIgnoreExtraElements(true)` は読み取り方向の無視のみであるため、書き込みは明示的に無視する必要があります。

6. 起動順序は [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67) で保証されています：`GameDb.Init` → `ComponentRegister.Init` → `HotfixManager.LoadHotfixModule`。ホット更新内で直接 Mongo を読み取るコードは、必ず最後のステップより後に配置してください。そうでないとシリアライザがまだ登録されておらず `No serializer found` が発生します。

## 検証

1. サービスを再起動し、起動ログに順次 `データベースサービス起動開始...` → `データベースサービス起動 終了...` → `コンポーネント登録 開始/終了` → `ホット更新モジュールのロード 終了` が表示されることを確認します。
2. Mongo Shell または Compass で `db.runCommand({ ping: 1 })` を実行し、`{ ok: 1 }` が返されることを確認します。
3. 任意のエンティティクラスで `Insert`/`Find` による読み書きフローを実行し、読み出したフィールドが書き込み内容と一致することをアサートします。
4. 故意に `DataBaseUrl` を誤ったアドレスに変更して再度起動し、即座に `データベースサービス起動失敗` がスローされ、根本原因のスタックが出力されることを確認します — これにより例外伝播チェーンが正常に通っていることを確認できます。
