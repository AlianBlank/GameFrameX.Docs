# 앱 일시 정지 및 포커스 변경 모니터링 방법

이 패키지를 통해 MonoBehaviour가 아닌 시스템에서도 Unity의 `OnApplicationPause` 및 `OnApplicationFocus` 콜백을 모니터링할 수 있으므로, 앱이 백그라운드로 전환되거나 다시 포어그라운드로 복귀할 때 음악 일시 정지, 진행 상황 저장, 포커스 UI 새로 고침 등의 작업을 수행할 수 있습니다.

## 사전 조건

- `com.gameframex.unity.mono` 패키지가 설치되어 있어야 하며, 버전 ≥ 1.1.4.
- 프로젝트에 `GameFrameX.Event.Runtime` 이벤트 시스템이 포함되어 있어야 함(이 패키지의 의존성).

## 작업 단계

### 1. 이벤트 시스템을 통해 구독(권장)

이벤트 시스템 방식은 결합도가 가장 낮아, 비즈니스 로직이 여러 관리자에 분산되어 있는 시나리오에 적합합니다.

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Mono.Runtime;

private void OnFocusChanged(object sender, GameEventArgs e)
{
    var args = (OnApplicationFocusChangedEventArgs)e;
    if (args.IsFocus)
    {
        // 앱이 포어그라운드로 복귀
    }
    else
    {
        // 앱이 백그라운드로 전환
    }
}

private void OnPauseChanged(object sender, GameEventArgs e)
{
    var args = (OnApplicationPauseChangedEventArgs)e;
    if (args.IsPause)
    {
        // 앱이 시스템에 의해 일시 정지됨
    }
    else
    {
        // 앱이 일시 정지에서 복구됨
    }
}

// 구독
GameFrameXEntry.GetModule<EventComponent>().Subscribe(OnApplicationFocusChangedEventArgs.EventId, OnFocusChanged);
GameFrameXEntry.GetModule<EventComponent>().Subscribe(OnApplicationPauseChangedEventArgs.EventId, OnPauseChanged);
```

이벤트 ID는 `OnApplicationFocusChangedEventArgs.EventId` / `OnApplicationPauseChangedEventArgs.EventId`로 식별됩니다.

### 2. Mono 컴포넌트를 통해 직접 모니터링

로직이 특정 MonoBehaviour 파생 클래스에 작성되어 있거나, 원본 Unity 콜백을 수신하고자 하는 경우, 이 패키지의 Mono 브리지 컴포넌트를 부착하고 모니터링 메서드를 추가할 수 있습니다.

```csharp
private void OnApplicationFocus(bool isFocus)
{
    // isFocus: true는 포어그라운드 진입, false는 백그라운드 진입
}

private void OnApplicationPause(bool isPause)
{
    // isPause: true는 시스템에 의해 일시 정지됨, false는 일시 정지에서 복구됨
}

// 등록
monoComponent.AddOnApplicationFocusListener(OnApplicationFocus);
monoComponent.AddOnApplicationPauseListener(OnApplicationPause);

// 더 이상 필요하지 않을 때 제거
monoComponent.RemoveOnApplicationFocusListener(OnApplicationFocus);
monoComponent.RemoveOnApplicationPauseListener(OnApplicationPause);
```

## 이벤트 매개변수 비교

| 이벤트 클래스 | 필드 | 의미 |
|--------|------|------|
| [OnApplicationFocusChangedEventArgs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationFocusChangedEventArgs.cs#L40-L87) | `bool IsFocus` | true는 앱이 포커스를 획득(포어그라운드로 복귀)함을 의미하고, false는 포커스 상실(백그라운드 전환)을 의미함 |
| [OnApplicationPauseChangedEventArgs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/EventArgs/OnApplicationPauseChangedEventArgs.cs#L40-L88) | `bool IsPause` | true는 시스템에 의해 일시 정지됨을 의미하고, false는 복구됨을 의미함 |

두 이벤트 클래스 모두 `GameEventArgs`를 상속하며, 참조 풀의 `ReferencePool.Acquire<T>()`에서 가져오고 사용 후 프레임워크가 통합적으로 회수합니다.

## 일반적인 변형

- **백그라운드/포어그라운드 전환에만 관심이 있는 경우**: `OnApplicationFocusChangedEventArgs`만 구독하며, `IsFocus=false`는 백그라운드로 전환됨을 의미합니다.
- **일시 정지와 포커스 상실 구분**: 모바일에서 화면 잠금은 일반적으로 `OnApplicationPause=true`를 트리거하고, 시스템 레벨 대화 상자弹出 시에는 일반적으로 `OnApplicationFocus=false`만 트리거됩니다. 각각 처리해야 하는 경우 두 이벤트를 동시에 구독합니다.
- **이벤트 객체 생성**: 프레임워크 내부에서는 `OnApplicationPauseChangedEventArgs.Create(bool)` / `OnApplicationFocusChangedEventArgs.Create(bool)`을 사용하며, 비즈니스 측에서는 일반적으로 수동으로 생성할 필요가 없습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 모니터링 메서드가 호출되지 않음 | `Subscribe` / `AddOnApplicationFocusListener`를 호출하지 않음 | 모듈 초기화 시 한 번 명시적으로 등록 |
| 이벤트를 수신했지만 `IsFocus`가 항상 `false`임 | 구독 시 두 이벤트의 `EventId`를 잘못 기입 | `Focus` 이벤트는 `IsFocus`를 반환하고, `Pause` 이벤트는 `IsPause`를 반환함에 주의 |
| 여러 번 중복 트리거됨 | Mono 컴포넌트 모니터링과 이벤트 시스템 구독이 동시에 설정되어 있어, 동일한 신호가 두 경로를 통해 전달됨 | 둘 중 하나만 선택하거나,分发 지점에서 비즈니스 측 중복 제거 추가 |
| 모니터링 제거가无效함 | 제거 시 다른 메서드 참조를 전달 | `Add` / `Remove`는 반드시 동일한 `Action` / 메서드 참조를 전달해야 함 |

## 배경(선택 사항)

`OnApplicationPause`와 `OnApplicationFocus`는 Unity 엔진이 MonoBehaviour에서 제공하는 콜백입니다. 이 패키지는 이를 GameFrameX 이벤트 버스 메시지로转发하여 순수 C# 시스템(`MonoBehaviour` 파생이 없는)도 앱 수명 주기 변화에 응답할 수 있도록 합니다. 이벤트 인스턴스는 참조 풀을 통해 재사용되어 GC를 줄입니다.
