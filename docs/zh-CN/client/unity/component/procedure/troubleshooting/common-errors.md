# 常见错误速查

使用 `GameFrameX.Procedure` 流程模块时,几乎所有运行时异常都来自同一个根因 —— **在 `ProcedureManager.Initialize` 之前调用了任何流程操作**。下面把高频错误一次性列出,看到症状就能定位修复点。

## 快速诊断

| 症状(异常/日志原文) | 原因 | 修复 |
|------|------|------|
| `GameFrameworkException: You must initialize procedure first.`(访问 `CurrentProcedure`、`CurrentProcedureTime`、`StartProcedure`、`HasProcedure`、`GetProcedure`) | 业务代码在 `ProcedureManager.Initialize` 之前就调用了流程 API,内部 `m_ProcedureFsm` 仍为 `null` | 在挂载 `ProcedureComponent` 的 GameObject 上配置好 `Available Procedure Type Names` 与 `Entrance Procedure Type Name`,让组件完成 `Initialize` 后再调用 |
| `GameFrameworkException: Procedures is invalid.`(在 `Initialize` 时抛出) | 传入 `Initialize` 的 `procedures` 数组为 `null` 或长度为 0 | 至少传入一个 `ProcedureBase` 子类实例 |
| `Log.Fatal("Procedure manager is invalid.")`(组件 `Awake` 阶段) | 框架未注册 `IProcedureManager` 实现,`GameFrameworkEntry.GetModule<IProcedureManager>()` 返回 `null` | 确认流程模块所在程序集被正确打包进项目,且未被裁剪;通常由 `GameFrameXAutoComponent` 自动注册,若被剥离需检查 asmdef |
| `Log.Warning("Available procedure type names is empty. Procedure auto start skipped.")` | `ProcedureComponent.m_AvailableProcedureTypeNames` 字段为空数组或未填 | 在 Inspector 至少添加一个流程类型全名(如 `MyGame.Procedure.LaunchProcedure, MyGame`) |
| `Log.Error("Can not find procedure type '{0}'.")` | `m_AvailableProcedureTypeNames` 中的类型全名拼错、命名空间错误或目标程序集未被加载 | 改用 `Utility.Assembly.GetType` 能解析的全限定名,确认类型确实存在于已加载程序集 |
| `Log.Error("Can not create procedure instance '{0}'.")` | 类型能被找到,但不是 `ProcedureBase` 的子类或缺少无参构造函数 | 自定义流程继承 `ProcedureBase` 并保留 `public` 无参构造 |
| `Log.Error("Entrance procedure is invalid.")` | `m_EntranceProcedureTypeName` 没有匹配 `m_AvailableProcedureTypeNames` 中的任意一项 | 入口流程类型名必须与 `Available Procedure Type Names` 中的某一项完全一致 |
| 运行时报 `Already exist FSM.`(与 `StartupRunner` 配合时) | 同时启用了旧版自动初始化和新版 `StartupRunner`,导致 `Initialize` 被调用两次 | 将 `ProcedureComponent.m_UseStartupRunner` 置为 `true`,让 `ApplicationStartupEntry + StartupRunner.Run` 接管初始化 |

## 修复步骤

### 1. 未初始化就调用流程 API

抛出点全部位于 `ProcedureManager` 中对 `m_ProcedureFsm` 的判空分支,例如 `StartProcedure<T>()`:

```csharp
[Preserve]
public void StartProcedure<T>() where T : ProcedureBase
{
    if (m_ProcedureFsm == null)
    {
        throw new GameFrameworkException("You must initialize procedure first.");
    }

    m_ProcedureFsm.Start<T>();
}
```

Source: [ProcedureManager.cs#L148-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L148-L156)

`CurrentProcedure`、`CurrentProcedureTime`、`HasProcedure`、`GetProcedure` 走的是同一段判空逻辑:

```csharp
if (m_ProcedureFsm == null)
{
    throw new GameFrameworkException("You must initialize procedure first.");
}
```

Source: [ProcedureManager.cs#L72-L78](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L72-L78)

修复方法:挂上 `ProcedureComponent` 后由其在 `Start` 协程里完成 `Initialize` 与 `StartProcedure`:

```csharp
m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);

yield return new WaitForEndOfFrame();

m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
```

Source: [ProcedureComponent.cs#L164-L168](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

业务侧应在场景加载完成、`CurrentProcedure` 已经返回非 `null` 后再发起流程切换。

### 2. `Initialize` 收到空流程数组

```csharp
public void Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)
{
    GameFrameworkGuard.NotNull(fsmManager, nameof(fsmManager));
    GameFrameworkGuard.NotNull(procedures, nameof(procedures));
    if (procedures.Length <= 0)
    {
        throw new GameFrameworkException("Procedures is invalid.");
    }

    m_FsmManager = fsmManager;
    m_ProcedureFsm = m_FsmManager.CreateFsm(this, procedures);
}
```

Source: [ProcedureManager.cs#L130-L141](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L130-L141)

修复方法:`procedures` 至少传 1 个,且必须继承 `ProcedureBase`:

```csharp
public abstract class ProcedureBase : FsmState<IProcedureManager>
{
    // 子类重写 OnInit / OnEnter / OnUpdate / OnFixedUpdate / OnLeave / OnDestroy
}
```

### 3. Inspector 流程类型名配错

`ProcedureComponent.Start` 会按类型名反射创建实例,任意一步失败都会中断启动:

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}

if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

Source: [ProcedureComponent.cs#L135-L156](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L135-L156)

修复方法:在 Inspector 中按 `命名空间.类名, 程序集名` 填写,且保证入口名出现在可用列表里,否则会落到下面的 `Entrance procedure is invalid.` 错误:

```csharp
if (m_EntranceProcedure == null)
{
    Log.Error("Entrance procedure is invalid.");
    yield break;
}
```

Source: [ProcedureComponent.cs#L158-L162](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L158-L162)

### 4. 与 `StartupRunner` 重复初始化

新版启动链路下,组件需要让出初始化权:

```csharp
[SerializeField] private bool m_UseStartupRunner = false;
...
if (m_UseStartupRunner)
{
    // 由 ApplicationStartupEntry + StartupRunner.Run 接管 Initialize 和 StartProcedure,
    // 本组件仅承担 Awake 注册 IProcedureManager 的职责,避免与新入口重复 Initialize 报 Already exist FSM。
    yield break;
}
```

Source: [ProcedureComponent.cs#L65-L127](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L65-L127)

修复方法:启用 `StartupRunner` 时把 `Use Startup Runner` 勾上,让 `ApplicationStartupEntry` 统一调度。

## 验证

按下面的顺序逐项确认,任一项失败回查上表对应行:

1. 启动后 Console 无 `GameFrameworkException: You must initialize procedure first.`,且 `ProcedureComponent.CurrentProcedure` 不为 `null`。
2. 切换场景或重新登录后,日志里没有重复的 `Already exist FSM.`。
3. 在自定义 `ProcedureBase` 子类的 `OnEnter` 里打 `Debug.Log`,确认它真的被调用,而不是被异常吞掉。
4. `m_AvailableProcedureTypeNames` 至少 1 项,`m_EntranceProcedureTypeName` 与其中某项精确匹配。
