# Invalid character 예외가 발생하면 어떻게 해야 할까요

`JsonMapper.ToObject` / `JsonReader`를 호출하여 입력을 파싱할 때, `JsonException`이 발생하고 메시지가 `Invalid character '{0}' in input string` 형태라면, 어휘 분석기가 입력 문자열에서 JSON 어휘 표에 없는 문자를 만났다는 의미입니다. 이 페이지는 원인을 빠르게 파악하고 수정하도록 도와줍니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Invalid character 'x' in input string`(x는 영문자) | 입력이 유효한 JSON이 아닙니다. 예를 들어 첫 문자가裸 `xyz`, 裸 `true`이거나, JSON이 아닌 텍스트(XML / YAML / 주석 등)입니다. | JSON 온라인 검증 도구로 형식을 확인하고, 텍스트가 `{`, `[`, 숫자, 문자열, `true`/`false`/`null` 중 하나로 시작하도록 보장합니다. |
| 예외 메시지가 숫자 / 제어 문자인 경우(예: `Invalid character '\0'`) | 문자열 끝의 BOM(`\uFEFF`), 줄 끝의 `\r`, 남아있는 이진 바이트 | 파싱 전에 `Trim` / `Trim('\uFEFF')`을 사용하고, 스트림을 읽을 때는 `StreamReader`의 기본 UTF-8 BOM 제거를 사용합니다. |
| 예외 메시지에 `\`(백슬래시) 다음에非法 문자가 있는 경우 | 문자열 안의 이스케이프 시퀀스가 잘못되었습니다(예: `"\x"`, `"\u00"`, `"\u12"` 길이 부족) | 이스케이프 시퀀스는 `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`, `\uXXXX`(16진수 4자리)만 허용됩니다. |
| 예외 메시지에 `'`(작은따옴표) 또는 `,` 뒤의 줄바꿈이 있는 경우 | JSON에 JavaScript / Python 스타일 구문이 혼합되어 있습니다(작은따옴표 문자열, 주석, 끝에 쉼표). | 작은따옴표를 제거하고 큰따옴표를 사용하며, `//`, `/* */` 주석과 객체/배열 끝의多余한 쉼표를 제거합니다. |
| 예외 메시지에 중국어 문자가 있는 경우 | `null` / `undefined` / C# 기본 `ToString()` 등을 파서에 직접 전달한 경우 | 먼저 응답 본문이 정말 JSON인지 확인합니다(`Content-Type` / 첫 문자). 그렇지 않으면 `JsonMapper.ToObject`를 호출하지 마십시오. |

예외 메시지의 원본 템플릿은 `JsonException(int c)` 생성자에서 가져옵니다:

```csharp
internal JsonException(int c) :
    base(string.Format(
             "Invalid character '{0}' in input string", (char)c))
{
}
```

## 수정 단계

### 1. 먼저 원본 입력을 출력합니다

로그에 `e.Message`만 붙여 넣지 말고, 실제로 파서에 전달된 문자열을 출력하세요. 예외 메시지의 문자가 바로 문제 문자의 위치입니다.

```csharp
try
{
    var obj = GameFrameX.LitJSON.Runtime.JsonMapper.ToObject<Dictionary<string, object>>(rawText);
}
catch (GameFrameX.LitJSON.Runtime.JsonException ex)
{
    Debug.LogError($"LitJSON 파싱 실패: {ex.Message} | 원본 입력 길이={rawText?.Length} | 앞 64자=[{rawText?.Substring(0, System.Math.Min(64, rawText?.Length ?? 0))}]");
}
```

### 2. BOM 및 숨겨진 문자 처리

서버에서 UTF-8 with BOM을 반환하거나, 파일이 Windows 메모장에서 저장된 경우 문자열 시작 부분에 `\uFEFF`가 남아 어휘 분석기가 "非法 첫 문자"로 던집니다.

```csharp
using GameFrameX.LitJSON.Runtime;

string rawText = File.ReadAllText(path);
// 시작 부분의 BOM 제거
if (!string.IsNullOrEmpty(rawText) && rawText[0] == '\uFEFF')
    rawText = rawText.Substring(1);

var data = JsonMapper.ToObject<MyData>(rawText);
```

참조 출처: [Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs)의 상태 머신은 표에 없는 코드 포인트를 만나면 `JsonException(c)`를 던집니다.

### 3. 이스케이프 시퀀스 수정

JSON 문자열은 다음 이스케이프만 지원합니다. 그 외의 `\'`, `\x`, `\v`, `\u{}`, 4자리가 채워지지 않은 `\u` 등은 모두 `Invalid character` 예외를 유발합니다(`\` 다음 문자 위치에서 발생).

| 유효한 이스케이프 | 설명 |
|----------|------|
| `\"` | 큰따옴표 |
| `\\` | 백슬래시 |
| `\/` | 슬래시 |
| `\b` `\f` `\n` `\r` `\t` | 제어 문자 |
| `\uXXXX` | 반드시 16진수 4자리(예: `\u4E2D`) |

### 4.非法 JSON 구문 수정

LitJSON은 엄격한 JSON 파서이며, JavaScript / JSON5 스타일의 확장을 **지원하지 않습니다**.

- 문자열은 큰따옴표만 사용할 수 있으며, 작은따옴표 `'…'`는 사용할 수 없습니다.
- `//`, `/* */` 주석은 허용되지 않습니다.
- 객체 / 배열의 마지막 요소 뒤에 `,` 끝 쉼표를 사용할 수 없습니다.
- 숫자는 앞에 0이 붙는 리터럴이나 16진수 리터럴(`0x1A`)을 허용하지 않습니다.

```csharp
// 잘못된 작성법 —— JSON이 아님
var bad = "{ name: 'Tom', age: 18, }";

// 수정 후
var good = "{\"name\":\"Tom\",\"age\":18}";
var obj = JsonMapper.ToObject<Dictionary<string, object>>(good);
```

### 5. 호출 진입점 확인

`JsonMapper.ToObject` 진입점 시그니처는 [Runtime/JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs), `JsonReader` 스트림 진입점은 [Runtime/JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs)를 참조하세요. 어느 진입점을 사용하든 어휘 오류는 동일한 유형의 `JsonException`으로 래핑됩니다.

## 검증

다음 순서대로 문제가 해결되었는지 확인합니다:

1. 예외를 유발한 입력을 임의의 온라인 JSON 검증 도구(예: jsonlint)에 복사하여 형식이 유효한지 확인한 후 코드로 돌아갑니다.
2. 프로그램을 다시 실행하여 `JsonException`이 더 이상 발생하지 않고, `JsonMapper.ToObject<T>`가 정상적으로 결과를 반환하는지 확인합니다.
3. 데이터가 네트워크 응답에서 온 경우, 응답 헤더 `Content-Type: application/json`과 응답 본문의 첫 문자도 함께 확인하여 HTML 오류 페이지나 빈 응답이 파서에 입력되지 않도록 합니다.

## 배경(선택 사항)

LitJSON의 어휘 분석은 유한 상태 머신을 기반으로 합니다 ([Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs)). 파싱 표 `parse_table`은 JSON이 아닌 문자를 허용하지 않으며, 읽자마자 `JsonException(int c)`를 통해 `Invalid character '{0}' in input string`을 던집니다. 예외 메시지의 문자가 바로 문제 문자이므로, 진단 시 문자열 내용보다 이 문자를 우선적으로 살펴보십시오.
