# 如何加载配置表

通过 `ConfigComponent` 把一个或多个 `IDataTable` 配置表加载进全局配置管理器，并在游戏任意位置按类型或名称读取。

## 前置条件

- 场景中已挂载 `GameFramework` 启动组件（框架自带），`ConfigComponent` 会由 `[GameFrameXAutoComponent(-5000)]` 自动注入，无需手动添加。
- 自定义配置类需要实现 `IDataTable` 接口（见 [IDataTable.cs](/Runtime/Config/Config/IDataTable.cs)）。
- 已有 `IDataTable` 实例可通过 `Add` 注入；若需要从资产文件加载，请配合框架的 `GameFrameX.Asset` 模块读取 ScriptableObject / 二进制后再 `Add`。

## 操作步骤

1. **拿到组件引用**。通过 `GameEntry.GetComponent<ConfigComponent>()` 获取组件，再拿到内部的 `IConfigManager`：

   ```csharp
   var configComponent = GameEntry.GetComponent<ConfigComponent>();
   var configManager   = GameFrameworkEntry.GetModule<IConfigManager>();
   ```

   Source: [ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85)

2. **注册加载事件**（可选，但推荐）。框架会在加载流程中派发以下事件，订阅它们以拿到成功 / 失败回调：

   ```csharp
   GameFrameXEntry.GetSubscriber().Subscribe(LoadConfigSuccessEventArgs.EventId, OnLoadConfigSuccess);
   GameFrameXEntry.GetSubscriber().Subscribe(LoadConfigFailureEventArgs.EventId, OnLoadConfigFailure);
   GameFrameXEntry.GetSubscriber().Subscribe(LoadConfigUpdateEventArgs.EventId,   OnLoadConfigUpdate);
   ```

   Source: [LoadConfigSuccessEventArgs.cs#L52](/Runtime/EventArgs/LoadConfigSuccessEventArgs.cs#L52), [LoadConfigFailureEventArgs.cs#L52](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L52)

3. **加载并注入配置表**。先用资源模块把 `IDataTable` 实例读到内存，再调用 `Add` 写入管理器。例如加载一个二进制 / 文本配置表：

   ```csharp
   // 1) 用 AssetComponent 把资产读到内存（不同项目加载方式不同）
   var dataTable = LoadMyConfigTable(); // 返回一个实现 IDataTable 的实例

   // 2) 注入到全局配置管理器，名称与类型名保持一致便于后续 GetConfig<T>()
   configComponent.Add(nameof(MyConfigTable), dataTable);
   ```

   Source: [ConfigComponent.cs#L182-L185](/Runtime/Config/ConfigComponent.cs#L182-L185), [ConfigManager.cs#L124-L127](/Runtime/Config/Config/ConfigManager.cs#L124-L127)

4. **读取配置表**。推荐使用泛型版本，会按 `typeof(T).Name` 自动匹配配置名：

   ```csharp
   if (configComponent.HasConfig<MyConfigTable>())
   {
       var cfg = configComponent.GetConfig<MyConfigTable>();
       // 使用 cfg ...
   }
   ```

   也可以按字符串名称取：

   ```csharp
   var cfg = (MyConfigTable)configManager.GetConfig("MyConfigTable");
   ```

   Source: [ConfigComponent.cs#L118-L143](/Runtime/Config/ConfigComponent.cs#L118-L143), [ConfigManager.cs#L152-L161](/Runtime/Config/Config/ConfigManager.cs#L152-L161)

5. **按需移除 / 清空**。卸载某张表或退出场景时清理：

   ```csharp
   configComponent.RemoveConfig<MyConfigTable>(); // 移除单张
   configComponent.RemoveAllConfigs();             // 清空全部
   ```

   Source: [ConfigComponent.cs#L154-L171](/Runtime/Config/ConfigComponent.cs#L154-L171)

## 常见变体

- **批量预加载**：在进入主场景前循环 `Add` 多张表，统一由成功事件回调推进流程。
- **热更新替换**：用 `Add` 覆盖同名项即可；`AddConfig` 内部走 `TryAdd`，如需强制替换请先 `RemoveConfig` 再 `Add`。
- **不通过组件**：直接 `GameFrameworkEntry.GetModule<IConfigManager>()` 拿到 `IConfigManager`，调用 `AddConfig / GetConfig` 同样可用。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GetConfig<T>()` 返回 `null` | 名称与 `typeof(T).Name` 不一致，或未调用 `Add` | 确认 `Add` 时传入的名称与类型名一致；或改用按名称 `GetConfig("Name")` |
| 重复 `Add` 后旧表仍生效 | `AddConfig` 走 `TryAdd`，同名不会被覆盖 | 先 `RemoveConfig`，再 `Add` |
| 事件没有触发 | 没有 `Subscribe` 事件 ID | 订阅 `LoadConfigSuccessEventArgs.EventId` 等 |
| `Config manager is invalid.` | 框架模块未注册或被销毁 | 确认 `GameFramework` 已启动且未被 `Shutdown` |

## 背景（可选）

`ConfigComponent` 自身不直接解析资产，它把 `IDataTable` 容器委托给 `IConfigManager`；`ConfigManager` 用 `ConcurrentDictionary<string, IDataTable>` 存储配置项，`ConfigComponent` 再叠一层类型 → 名称映射，让 `GetConfig<T>()` 可以按类型快速定位。资产读取部分由项目的 `AssetComponent` 负责，与本组件解耦。
