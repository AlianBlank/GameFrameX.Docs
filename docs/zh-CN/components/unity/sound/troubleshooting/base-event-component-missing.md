# Base component / Event component is invalid 怎么办

当 `SoundComponent` 在游戏启动阶段无法从 `GameEntry` 中取到 `BaseComponent` 或 `EventComponent` 时,会在控制台抛出 `Base component is invalid.` 或 `Event component is invalid.` 致命日志,音效系统直接停止初始化,后续播放、事件回调全部失效。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台输出 `Base component is invalid.` | 场景中缺少 `BaseComponent`,或它的初始化顺序晚于 `SoundComponent` | 见 [BaseComponent 缺失](#修复步骤) |
| 控制台输出 `Event component is invalid.` | 场景中缺少 `EventComponent`,或它同样晚于 `SoundComponent` 被加载 | 见 [EventComponent 缺失](#修复步骤) |
| 两条致命日志接连出现,声音功能完全不可用 | `BaseComponent` / `EventComponent` 都没有挂载到启动场景 | 同时挂载两者并调整 Script Execution Order |

日志原文与触发位置来自 `SoundComponent.Start()`:

```csharp
BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
if (baseComponent == null)
{
    Log.Fatal("Base component is invalid.");
    return;
}

m_EventComponent = GameEntry.GetComponent<EventComponent>();
if (m_EventComponent == null)
{
    Log.Fatal("Event component is invalid.");
    return;
}
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L202-L221)

## 修复步骤

### BaseComponent 缺失

1. 打开启动场景(通常是 `GameFramework` 引导场景)。
2. 在 Hierarchy 中新建空物体,命名为 `Base`,挂上 `BaseComponent` 脚本。
3. 确认该物体处于激活状态,且 `BaseComponent.Awake()` 会在 `SoundComponent.Start()` 之前执行。
4. 重新运行游戏,检查日志是否还有 `Base component is invalid.`。

### EventComponent 缺失

1. 在启动场景再新建一个空物体(可与 `BaseComponent` 同物体),命名为 `Event`,挂上 `EventComponent`。
2. 确认 `EventComponent` 已被 `GameEntry` 注册(`GameEntry.RegisterComponent` 或 Inspector 拖拽均可)。
3. 重新运行,确认 `Event component is invalid.` 不再出现。

### 调整组件初始化顺序

如果两个组件都已挂载但仍报错,通常是脚本执行顺序问题:

1. 选中挂载 `SoundComponent` 的物体,在 Inspector 中点击 `Script Execution Order`。
2. 把 `BaseComponent` 和 `EventComponent` 的执行顺序调到比 `SoundComponent` 更早(`Order in Script` 数值更小)。
3. 保存设置后重启 Unity,再运行一次。

## 验证

- 控制台不再出现 `Base component is invalid.` / `Event component is invalid.`。
- `SoundComponent.Start()` 走到下一行,会看到 `Sound Helper` 子物体被创建并打印后续 `[Sound] Load sound group` 类日志。
- 调用 `SoundComponent.PlaySound(...)` 时,`m_EventComponent.Fire(this, PlaySoundSuccessEventArgs...)` 与 `PlaySoundFailureEventArgs...` 能被订阅者正常收到。
