# 如何切换语言：系统语言检测、默认语言回退与偏好持久化

本页说明在 GameFrameX Unity Localization 包中完成一次语言切换的完整流程：读取系统语言、在不支持时回退到默认语言、把用户选择持久化，并在下次启动时优先恢复用户偏好。

## 前置条件

- Unity 项目已安装 `com.gameframex.unity.localization` 包。
- 已为至少一种目标语言准备好本地化资源（语言表/语言包），并确保其中包含默认语言。
- 已能进入运行时并访问本包对外暴露的本地化管理入口（具体类型请查阅包的入口脚本）。

## 操作步骤

1. **确认语言资源就绪**：启动时先确认所有候选语言的本地化数据已加载，否则切换后取不到文本。
2. **读取持久化的用户偏好**：启动时优先读取上次保存的语言偏好（通常是 `PlayerPrefs` 或包内自己的持久化封装）。
   - 若存在有效偏好且该语言可用，直接应用，跳过第 3、4 步。
   - 若无偏好，继续第 3 步。
3. **检测系统语言**：通过 Unity 引擎提供的系统语言信息（引擎层面为 `Application.systemLanguage`，包内通常有对应封装）获取当前设备语言。
4. **匹配与回退**：将系统语言映射到包内支持的语言：
   - 命中支持列表 → 应用该语言；
   - 未命中（例如系统语言无对应语言包）→ 回退到默认语言，保证界面始终有文案可显示。
5. **执行切换**：调用本包的切换语言入口，触发文本刷新（UI 上的本地化组件应随语言变化重新取值）。
6. **持久化偏好**：用户主动选择语言后，立即写入偏好存储，确保下次启动按第 2 步恢复。
7. **验证**：切换后检查界面上已显示的本地化文本是否更新为新语言；重启应用后确认语言仍是用户上次的选择。

## 常见错误

| 现象 | 可能原因 | 规避方法 |
|------|----------|----------|
| 切换语言后界面文本未更新 | 本地化组件未订阅语言变化事件，或切换时新语言数据尚未加载完成 | 确认先加载语言数据再切换；检查组件是否监听语言变更 |
| 每次启动都回到系统语言 | 切换后未写入偏好，或启动时先检测系统语言再读偏好 | 保证"读偏好优先于检测系统语言"的顺序，且用户选择后立即持久化 |
| 界面出现空白/Key 原文 | 系统语言不在支持列表且未正确回退，或当前语言缺少对应词条 | 确认默认语言回退逻辑生效，并补齐缺失词条 |
| 偏好保存的语言在换包/清档后失效 | 偏好存储随应用数据被清除，未做容错 | 读取偏好时校验语言是否仍受支持，不支持则走回退链路 |

## 背景

这一套"偏好优先 → 系统语言 → 默认语言"的三级顺序是本地化包的通用设计：默认语言兜底保证任何情况下界面都有文案；系统语言让首次启动自动贴合用户环境；持久化偏好则尊重用户的主动选择，避免每次启动被系统语言覆盖。具体的检测、匹配与持久化实现（包括是否使用 `PlayerPrefs`、支持语言列表在哪里定义、默认语言如何配置）请直接查阅仓库源码。
