# 生成に失敗した/エラーが出た場合の対処法

`gen-*.bat` / `gen-*.sh` を実行した後に Luban が例外を投げたり、出力ファイルが生成されない場合は、このページの診断表に従って項目ごとに確認してください。問題は主にスクリプトパス、設定プレースホルダー、Excel テーブル構造の3種類に集中しています。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `Could not find a part of the path ... Tools/Luban.dll` | ツールディレクトリが存在しないか、パスの記述が誤っている | リポジトリルートに `Tools/` を作成して `Luban.dll` を配置するか、`luban.conf` の `toolPath` を修正する |
| `luban.conf not found` / `conf not loaded` | カレントディレクトリが正しくなく、スクリプトがリポジトリルートに移動していない | `Tools/` と同じ階層のディレクトリでスクリプトを実行するか、スクリプトで設定ファイルのあるディレクトリに `cd` する |
| プレースホルダー `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` が展開されない | `luban.conf` 内の2つのキーが空文字列になっている | `luban.conf` 内の `UNITY_ASSETS_PATH` と `SERVER_PATH` を絶対パスに置き換える |
| `Excel ... __tables__.xlsx` の解析失敗が報告される | テンプレートのヘッダーが壊れている、列が欠落している、または複数テーブルのマージエラー | `Excels/__tables__.xlsx`、`__beans__.xlsx`、`__enums__.xlsx` を元に戻し、手動で列を削除しない |
| `Localization.xlsx not found` が報告される | クライアント生成時にローカライズファイルがリネームされている/欠落している | コマンド内の `localizationFileName` のデフォルトは `Localization.xlsx` なので、必要に応じてリポジトリの実際のファイル名に変更する |
| コマンドが一瞬で終わり、エラーが見えない | 末尾に `pause` がない(Windows) | `gen-*.bat` の最終行が `pause` になっているか確認する(既存のスクリプトを参考) |
| コードのみ生成され、データが生成されない | `dataTarget` と `codeTarget` が一致していない、または `outputDataDir` のパスが無効 | `--dataTarget` と `--codeTarget` を同時に設定し、`outputDataDir` が書き込み可能か確認する |
| `validation failed` が報告される | `--validationFailAsError true` が設定されており、データが検証を通過していない | 一時的に `--validationFailAsError true` を外して具体的な警告を確認し、データを修正してから再有効化する |

## 修正手順

### 1. Luban.dll が見つからない

`luban.conf` を開き、`toolPath` フィールドを確認します:

```json
"toolPath": "/../Config/Tools/Luban.dll",
```

スクリプトは実際には次のように呼び出しています:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf
```

Source: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L2)

両者は一致している必要があります:スクリプトに `./Tools/Luban.dll` と書かれているなら、リポジトリに `Tools/Luban.dll` が存在しなければなりません。プロジェクトでツールを `Config/Tools/` に置いている場合は、`toolPath` とスクリプトのパスを同期して変更してください。

### 2. プレースホルダーが展開されない

`luban.conf` ではデフォルトで空文字列が設定されています:

```json
"UNITY_ASSETS_PATH": "",
"SERVER_PATH": "",
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L62-L65)

`commands` 内のコマンドはこの2つの変数を参照します。例えば:

```json
"command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config"
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L78)

スクリプトを直接実行すると、これらの `%XXX%` は展開されず、ファイルシステム層で「パスが存在しない」というエラーが出ます。お使いのマシン上の絶対パスに置き換えてから生成してください。

### 3. Excel テンプレートが壊れている

`luban.conf` は `schemaFiles` を通じて4つのメタデータテーブルを宣言しています:

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

エラーメッセージにこれら4つのファイルのいずれかが含まれる場合は、まずリポジトリからそれらを復元し、次に `Excels/Tables/` と `Excels/Local/` 配下の業務テーブルの列名が `__tables__.xlsx` のフィールドと一対一で対応しているか確認してください。

### 4. クライアント生成時にローカライズテーブルが見つからない

クライアントのコマンドには独立した `localizationFileName` が付いており、デフォルトでは `Localization.xlsx` というファイル名を期待しています:

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L72-L77)

ローカライズテーブルの名前を変更した場合(例：リポジトリに `L-Localization-UI.xlsx`、`L-Localization-成就.xlsx`、`L-Localization-文本.xlsx` しかない場合)は、`localizationFileName` を実際のファイル名に変更するか、テーブル名を `Localization.xlsx` に戻してください。

### 5. スクリプトが一瞬で終わりエラーが見えない

Windows の `gen-*.bat` はすべて末尾に `pause` を追加すべきです:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf

pause
```

Source: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L3)

スクリプトから `pause` を外していると、エラーメッセージが閉じられたウィンドウとともに消えてしまい、原因がわかりません。`pause` を追加してから再実行してください。

### 6. サーバー側バイナリ生成の失敗

リポジトリが提供するサーバー側 bin 生成スクリプトは次の通りです:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
pause
```

Source: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L2)

注意点として、ここでは `gen-server-bin.sh` と書かれていますが、内容は Windows スタイルの `dotnet ... && pause` であり、さらに相対パス `../Server/GameFrameX.Config/` に依存しています。パス関連のエラーが出た場合は、以下を確認してください:
- `Server/GameFrameX.Config/Json` と `Server/GameFrameX.Config/Config` の2つのディレクトリが存在するか書き込み可能であること;
- 他のディレクトリから `sh ./gen-server-bin.sh` を実行したのではなく、リポジトリのルートディレクトリでスクリプトを実行したこと。

## 検証

上記の修正が完了したら、最小構成のコマンドを実行して経路が通じているか確認します:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json \
  --xargs outputDataDir=./out/Json \
  --xargs outputCodeDir=./out/Config \
  --conf ./Luban.conf
```

成功した場合:
- `./out/Config/` 配下に `TablesComponent.cs` などの生成コードがあること;
- `./out/Json/` 配下に `Tb*.json` データファイルがあること;
- ターミナルに例外のスタックトレースがないこと。

その後、対応するプラットフォームのスクリプト(`gen-server-json.bat` / `gen-client-json.sh` など)をもう一度実行して、業務がエンドツーエンドで利用可能であることを確認してください。
