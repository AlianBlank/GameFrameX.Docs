# 如何注册网络协议消息处理器

通过给继承 `IMessageHandler` 的管理器类贴上 `[MessageHandler]` 特性,并在初始化时调用 `ProtoMessageHandler.Add(this)`,即可让 GameFrameX 在收到对应协议时自动派发到目标方法,无需手动 `switch` 派发。

## 前置条件

- 已有一个从 `GameFrameX.Network.Runtime` 引入的协议消息类(由 Proto 生成,例如 `NotifyBagInfoChanged`)。
- 管理器类继承 `GameFrameworkSingleton<T>` 并实现 `IMessageHandler` 接口。

## 操作步骤

1. **让管理器实现 `IMessageHandler` 并继承单例基类**。整个类只需要一个实例,网络层只会派发到这一个对象。

   ```csharp
   using GameFrameX.Network.Runtime;
   using GameFrameX.Runtime;

   namespace Hotfix.Manager
   {
       public sealed class BagManager : GameFrameworkSingleton<BagManager>, IMessageHandler
       {
           // ...
       }
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L16)

2. **在处理方法上贴 `[MessageHandler(typeof(消息类), nameof(消息类))]` 特性**。特性第一个参数指定协议消息类型,第二个参数是日志/调试用的描述名,与方法签名一一对应。

   ```csharp
   /// <summary>
   /// 监听道具变化通知
   /// </summary>
   /// <param name="msg"></param>
   [MessageHandler(typeof(NotifyBagInfoChanged), nameof(NotifyBagInfoChanged))]
   private void NotifyBagInfoChanged(NotifyBagInfoChanged msg)
   {
       // 处理消息体
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L29-L30)

3. **实现 `Register()` 并在其中调用 `ProtoMessageHandler.Add(this)`**。把当前管理器注册到协议分发器,框架反射扫描时会读取该实例上所有带 `[MessageHandler]` 特性的方法。

   ```csharp
   /// <summary>
   /// 注册消息。请勿多次调用
   /// </summary>
   public void Register()
   {
       ProtoMessageHandler.Add(this);
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L126-L129)

4. **在合适的时机调用一次 `Register()`**。一般在 `Awake` 或首次 `GetInstance()` 时触发,例如:

   ```csharp
   private void Awake()
   {
       Register();
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L120)

## 常见变体

- **同一管理器处理多种协议**:每个方法分别贴一个 `[MessageHandler(typeof(不同消息), nameof(不同消息))]`,`ProtoMessageHandler.Add(this)` 只需调用一次即可注册全部方法。`PlayerAttributeManager` 同时处理 `NotifyPlayerAttributeSync` 和 `NotifyPlayerAttributeChanged` 就是这种用法。([PlayerAttributeManager.cs#L79](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L79)、[PlayerAttributeManager.cs#L109](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L109))

- **不同管理器处理不同协议**:每个管理器各自实现 `IMessageHandler`、各自 `Register()`,互不影响。例如 `RoomDataManager` 处理 `NotifyRoomChanged`、`RockPaperScissorsDataManager` 处理猜拳相关协议。([RoomDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RoomDataManager.cs#L16)、[RockPaperScissorsDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RockPaperScissorsDataManager.cs#L16))

## 常见错误

- **忘记在 `Register()` 里调用 `ProtoMessageHandler.Add(this)`**:特性只是元数据,不会自动生效,会导致消息到达但没有任何方法被调用。
- **重复调用 `Register()`**:注释明确写了"请勿多次调用",同一实例多次注册会重复派发。
- **方法签名与特性里的消息类型不匹配**:`[MessageHandler(typeof(X), ...)]` 的 `X` 必须与方法参数类型完全一致,否则反射绑定失败。
- **把 `Register()` 放在构造函数里**:`GameFrameworkSingleton` 在构造时其他子系统未必初始化完成,建议放在 `Awake` 或显式 `GetInstance().Register()` 时机调用。

## 背景(可选)

`[MessageHandler]` 是基于反射的协议路由标记,框架在收到协议包后通过 `ProtoMessageHandler.Add(this)` 注册进来的实例集合查表派发,所以每个处理器只需要一个实例,这也是它继承 `GameFrameworkSingleton` 的原因。
