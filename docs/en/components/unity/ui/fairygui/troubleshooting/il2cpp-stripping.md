# What to Do If UI Code Is Stripped After an IL2CPP Build

When Unity builds with IL2CPP, it performs Managed Code Stripping, removing types and methods that "appear to have no static references". This package's FairyGUI helpers (such as `FairyGUIFormHelper` and `FairyGUILoadAsyncResourceHelper`) are mainly invoked indirectly at runtime by the GameFrameX UI framework, making them prime targets for accidental stripping — everything works fine in the editor, but on device the UI fails to open or exceptions are thrown when the helpers are instantiated. This package already provides full stripping protection via the `[UnityEngine.Scripting.Preserve]` attribute. If problems still occur, it is usually because the stripping level is set too high or your project's own UI code lacks protection.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Works fine in the editor, but after an IL2CPP device build, opening UI fails or errors occur when instantiating the form helper or async resource helper | `Managed Stripping Level` is set too high; helper types invoked indirectly by the framework get stripped | See [Step 1](#1-verify-the-package-version-and-preserve-attributes) and [Step 2](#2-lower-the-managed-stripping-level) below |
| Types/members inside the package are stripped, but you are using an older version of the package | Older versions may not cover `[UnityEngine.Scripting.Preserve]` annotations on all members | Upgrade this package (see [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/package.json#L6) for the current version); see Step 1 |
| Project-custom FairyGUI extension components (your own classes inheriting `GComponent`/`GObject`) go missing on device | Project-owned code has no stripping protection; unrelated to this package | Add `[UnityEngine.Scripting.Preserve]` to your own classes or a project-level `link.xml`; see Step 3 |

## Fix Steps

### 1. Verify the Package Version and Preserve Attributes

This package annotates everything at the class, field, property, and method levels with `[UnityEngine.Scripting.Preserve]`. The official description states: "**IL2CPP safe** — the Preserve attribute prevents code stripping during IL2CPP builds" (see [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L38)).

The actual class-level and member-level annotations look like this; you can compare them against the files in your local copy of the package:

```csharp

{
    [UnityEngine.Scripting.Preserve]
    private readonly Dictionary<string, UIPackageData> m_UIPackages = new Dictionary<string, UIPackageData>(32);
```

### 2. Lower the Managed Stripping Level

`[Preserve]` only protects "the annotated members"; when the project-wide stripping level is too high, edge cases can still get stripped. Adjust in the following order:

1. Open `Edit → Project Settings → Player → Other Settings`.
2. Change `Managed Stripping Level` (under IL2CPP) from `High`/`Medium` down to `Low` or `Minimal`.
3. Rebuild a device package with IL2CPP and verify.

If you must keep a high stripping level for package-size reasons, follow Step 3 to preserve whole assemblies with a `link.xml`.

### 3. Add Stripping Protection for Project-Owned Code (or Whole-Assembly link.xml)

This repository does **not** include a `link.xml` (stripping protection relies entirely on `[UnityEngine.Scripting.Preserve]`), so project-owned code needs its own protection. Choose either of the two approaches:

- **Attribute approach (recommended, consistent with this package's practice)**: Annotate each custom FairyGUI extension component and each form logic class invoked via reflection individually:

```csharp
[UnityEngine.Scripting.Preserve]
public class MyCustomPanel : GComponent
{
}
```

- **link.xml approach**: Preserve an entire assembly by placing it anywhere under `Assets` (e.g., `Assets/link.xml`). Note that this is a project file you must create yourself; there is no ready-made one in this package:

```xml
<linker>
  <assembly fullname="Your.GameAssembly" preserve="all"/>
</linker>
```

### 4. Troubleshoot the FairyGUI Extender Reflection Registration Chain

This package obtains the UI helper implementations inside the assembly via reflection, and this chain is the easiest to break after stripping. Confirm that the following classes exist in the build output (check the build log or the symbol files inside `{Project}_BackUpThisFolder_ButDontShipItWithYourGame`):

- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIUIGroupHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUILoadAsyncResourceHelper` (an internal class, invoked indirectly through the `IAsyncResource` interface, and the most likely to be stripped)

## Verification

1. Build a device package with IL2CPP (Android/iOS both work); do not re-test using Mono mode.
2. On the device, open in turn the UIs that depend on different UI groups, and confirm: UIs are created normally (the `UIPackage.CreateObject` path), asynchronously loaded UI packages (the YooAsset path) call back `LoadResource` correctly, and there are no helper instantiation exceptions such as `TypeLoadException`/`NullReferenceException`.
3. Optional: Search the build log for `Stripping`-related warnings and confirm that the `GameFrameX.UI.FairyGUI.Runtime` assembly does not appear in stripping reports.

## Background

This package's helpers are not directly instantiated with new by business code; instead, the GameFrameX UI framework instantiates them at runtime via interfaces and reflection. Static analysis cannot see those references, so IL2CPP may consider them "unused" and strip them. `[UnityEngine.Scripting.Preserve]` tells the stripper "preserve this member and everything it references", and this package applies it comprehensively from classes and fields to methods (see [FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L47) and [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L53)). Therefore, under normal circumstances you do not need to write any additional stripping protection configuration for this package.
