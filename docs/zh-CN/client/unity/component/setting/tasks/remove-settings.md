# 删除与清空配置

通过 `ISettingManager` 接口可以在运行时删除单个配置项或一次性清空全部配置,常用于玩家重置设置、清缓存或切换账号。

## 前置条件

- 已完成 [快速开始](../../overview/quick-start) 中的初始化流程,`SettingManager` 已被 `SettingComponent` 创建并持有。
- 配置辅助器 `ISettingHelper` 已通过 `SetSettingHelper` 设置,否则删除/清空接口会抛出 `GameFrameworkException("Setting helper is invalid.")`。
- 需要拿到 `ISettingManager` 实例,可参考下方"获取管理器"小节。

## 操作步骤

1. 获取配置管理器实例。

   ```csharp
   var settingManager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>();
   if (settingManager == null)
   {
       // 通常是 SettingComponent 未挂载或初始化失败
       return;
   }
   ```

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

2. 按名称删除单个配置项。删除前可先用 `HasSetting` 判定是否存在。

   ```csharp
   const string key = "Player.MusicVolume";
   if (settingManager.HasSetting(key))
   {
       bool removed = settingManager.RemoveSetting(key);
       if (removed)
       {
           settingManager.Save();
       }
   }
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L210-L234)

3. 一次性清空全部配置项(慎用,会移除所有键)。

   ```csharp
   settingManager.RemoveAllSettings();
   settingManager.Save(); // 视实际实现决定是否需要手动 Save
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L244-L249)

4. 验证结果。再次枚举配置项,确认数量符合预期。

   ```csharp
   int remaining = settingManager.Count; // 应为 0(全部清空)或比删除前少 1
   string[] names = settingManager.GetAllSettingNames();
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L84-L92)

## 接口速查

| 方法 | 签名 | 行为 |
|------|------|------|
| `HasSetting` | `bool HasSetting(string settingName)` | 配置名为空时抛 `GameFrameworkException("Setting name is invalid.")`;否则查询是否存在。 |
| `RemoveSetting` | `bool RemoveSetting(string settingName)` | 返回 `bool`,指示是否成功移除。配置名为空抛异常。 |
| `RemoveAllSettings` | `void RemoveAllSettings()` | 清空所有项;无返回值,无参数校验以外的错误。 |

Source: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L104-L133)

## 常见变体

- 仅删除不保存:某些后端(如 `PlayerPrefs`)需要显式 `Save` 才会落盘,删除后若进程崩溃可能丢失更改;视具体 `ISettingHelper` 实现决定。
- 删除只读/默认配置:若配置来自序列化文件,`RemoveSetting` 通常只影响运行时内存缓存中的条目,不会回写源文件。

## 常见错误

- **"Setting helper is invalid."**:未设置 `ISettingHelper`,确认 `SettingComponent` 已正确初始化并赋值了辅助器。
- **"Setting name is invalid."**:`settingName` 为 `null` 或空字符串,删除前必须传入合法名称。
- **删除后旧值仍能读到**:后端没有自动持久化,记得调用 `Save()`;或下一次 `Load()` 又从持久层把同名项加载回来。
- **没有预期的清理效果**:`RemoveAllSettings` 不会重置后端底层(如 `PlayerPrefs` 中其它无关键),只清空当前管理器持有的条目。

## 背景(可选)

`SettingManager` 是薄壳,所有删除/清空动作直接转发给 `ISettingHelper` 实现([`SettingHelperBase`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs) 定义抽象方法)。`DefaultSettingHelper`、`PlayerPrefsSettingHelper` 等具体实现各自决定是改内存、还是同步到底层存储。关闭模块时会自动 `Save()`,见 [`Shutdown`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L112-L115)。
