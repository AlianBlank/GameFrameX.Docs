# 如何銷毀 FSM

呼叫 `FsmManager` 的 `DestroyFsm` 多載即可銷毀有限狀態機。銷毀後，該 FSM 會從管理器中移除並標記為已銷毀(`IsDestroyed == true`),在下一輪 Update 中將不再被驅動。

## 前置條件

- 專案中已透過 `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IFsmManager>()` 取得 `IFsmManager` 執行個體(或透過 `FsmComponent` 取得)。
- 已透過 `CreateFsm` 建立目標 FSM,並記住擁有者型別 `T` 與名稱(`null` 表示匿名)。

## 操作步驟

1. **依擁有者型別銷毀(匿名 FSM)**

   ```csharp
   IFsmManager fsmMgr = GameFrameX.Runtime.GameFrameworkEntry.GetModule<GameFrameX.Fsm.Runtime.IFsmManager>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>();
   ```

2. **以擁有者型別 + 名稱銷毀**

   ```csharp
   bool ok = fsmMgr.DestroyFsm<MyOwner>("BattleFsm");
   ```

3. **直接傳入 FSM 參考以銷毀**

   若仍持有 `IFsm<T>` 或 `FsmBase` 控制代碼，可直接傳入，無需重新撰寫泛型與名稱：

   ```csharp
   IFsm<MyOwner> fsm = fsmMgr.GetFsm<MyOwner>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>(fsm);   // 泛型多載
   bool ok2 = fsmMgr.DestroyFsm(fsm as FsmBase); // 非泛型多載
   ```

`DestroyFsm` 的回傳值為 `bool`,表示銷毀是否成功。若 FSM 不存在，則回傳 `false`。

## 常見變化

- **從 `FsmComponent` 銷毀**:`FsmComponent` 內部封裝了 `IFsmManager`,因此可直接使用 `GameEntry.GetComponent<FsmComponent>().DestroyFsm<MyOwner>(name)` 的形式。
- **批次清理**：管理器在 `Shutdown` 時會走訪所有 FSM 並呼叫 `Shutdown()`,因此無需手動逐一銷毀([FsmManager.cs#L138-L147](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L138-L147))。
- **存在驗證**：可在銷毀前呼叫 `HasFsm<T>(name)`,以避免因重複銷毀而回傳 `false`。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `DestroyFsm` 回傳 `false` | 傳入的擁有者型別或名稱與建立時不一致，或 FSM 已被銷毀 | 先以 `HasFsm` 驗證再銷毀，或直接傳入 `FsmBase` 控制代碼 |
| 銷毀後仍收到 Update 回呼 | 銷毀會延遲生效，且本影格的 Update 已被派發 | 於下一影格再次觀察；管理器的 Update 會略過 `IsDestroyed == true` 的 FSM |
| `DestroyFsm(typeof(T))` 擲出 `GameFrameworkException("Owner type is invalid.")` | 傳入了 `null` | 使用泛型多載，或自行進行 null 檢查 |

## 驗證

銷毀後可使用下列任一方式驗證：

```csharp
Assert.IsFalse(fsmMgr.HasFsm<MyOwner>()); // 不存在即為成功
Assert.AreEqual(0, fsmMgr.Count);          // 計數應為 0
```

## 背景(選用)

`FsmManager` 內部以 `Dictionary<TypeNamePair, FsmBase>` 儲存 FSM,Update 迴圈會先複製到暫存清單後再走訪。走訪時會略過 `IsDestroyed == true` 的項目，因此即使中途銷毀也不會影響本次迭代。銷毀會透過 `Shutdown()` 釋放狀態資源並從字典中移除。
