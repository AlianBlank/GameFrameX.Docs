# 미니게임 플랫폼 매크로 정의 오류 해결 방법

`ApplicationHelper.IsWebGLWeChatMiniGame`(또는 기타 `IsWebGLXxxMiniGame` 시리즈 속성)을 호출했을 때, 실제로 특정 미니게임 플랫폼에서 실행 중인지 여부와 관계없이 항상 `false`를 반환한다면, 이는 보통 해당 매크로 정의가 올바르게 적용되지 않았음을 의미합니다. 본 문서에서는 일반적인 오류 증상, 원인 및 해결 단계를 안내합니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| 실기에서 `IsWebGLWeChatMiniGame` 등의 속성이 항상 `false`임 | **Project Settings → Player → Other Settings → Scripting Define Symbols**에 해당 `ENABLE_*_MINI_GAME` 매크로를 추가하지 않음 | 플랫폼 매크로 이름 표에 따라 해당 매크로를 Scripting Define Symbols에 추가 |
| 매크로를 추가했는데도 속성이 여전히 `false`(WebGL 플랫폼) | WebGL 플랫폼으로 전환하지 않음; 매크로는 `UNITY_WEBGL`에서만 적용됨 | File → Build Settings → Switch Platform → WebGL |
| 컴파일 오류: `The type or namespace name 'EnableWebglMiniGame' could not be found` | `#define ENABLE_WEBGL_MINI_GAME`을 직접 작성했지만, 매크로는 Scripting Define Symbols를 통해 설정해야 함 | Project Settings 구성을 사용하고 소스 코드에 `#define`을 쓰지 말 것 |
| 컴파일 경고 또는 코드가 잘못 제거됨 (IL2CPP / AOT) | `#if`로 매크로를 직접 판단했지만 `[UnityEngine.Scripting.Preserve]` 표시를 빠뜨림 | 호출 측이 보존되어 있는지 확인하고, `ApplicationHelper.MiniGame.cs`의 속성 작성법을 참고 |
| 플랫폼 전환 후 매크로가 적용되지 않음 | Unity에서 스크립트 재컴파일을 트리거해야 하고, IDE 캐시가 갱신되지 않음 | IDE를 닫고 다시 열기 / `Assets → Reimport All` |

## 해결 단계

### 1. Scripting Define Symbols 설정 열기

`Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`로 이동합니다. 대상 플랫폼을 선택한 후 텍스트 상자에 필요한 매크로를 추가합니다. 여러 매크로는 세미콜론(;)으로 구분합니다. 예시:

```text
ENABLE_WEBGL_MINI_GAME;ENABLE_WECHAT_MINI_GAME
```

출처: [ApplicationHelper.MiniGame.cs#L17-L23](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L17-L23)에서 사용된 `ENABLE_WEBGL_MINI_GAME` 매크로를 참조하세요.

### 2. 플랫폼이 WebGL로 전환되었는지 확인

모든 `IsWebGL*MiniGame` 속성은 `#if UNITY_WEBGL && ENABLE_<PLATFORM>_MINI_GAME`으로 판단되므로, 현재 Active Build Target이 WebGL이 아니면 전처리 분기가 바로 `false`를 반환합니다.

`File → Build Settings`를 열고 왼쪽 플랫폼 목록에서 **WebGL**을 선택한 후 **Switch Platform**을 클릭합니다. 완료되면 Unity가 전체 재컴파일을 트리거합니다.

### 3. 플랫폼별로 올바른 매크로 이름 선택

프레임워크에서 지원하는 모든 미니게임 매크로 이름은 다음과 같습니다(모두 `UNITY_WEBGL`과 함께 사용해야 함):

### 4. 코드에서 해당 속성 호출

`#if`를 중첩하여 매크로를 직접 판단하지 마세요 — 누락되기 쉽습니다. `ApplicationHelper`의 속성을 직접 호출하세요:

```csharp
using GameFrameX.Runtime;

if (ApplicationHelper.IsWebGLWeChatMiniGame)
{
    // WeChat 미니게임 전용 로직
}
else if (ApplicationHelper.IsWebGLDouYinMiniGame)
{
    // Douyin 미니게임 전용 로직
}
```

소스 코드 예시(WeChat 미니게임 분기):

```csharp
[UnityEngine.Scripting.Preserve]
public static bool IsWebGLWeChatMiniGame
{
    get
    {
#if UNITY_WEBGL && ENABLE_WECHAT_MINI_GAME
        return true;
#else
        return false;
#endif
    }
}
```

## 검증

1. `Awake()` 또는 디버그 버튼에 `Debug.Log($"WeChat={ApplicationHelper.IsWebGLWeChatMiniGame}")`을 한 줄 추가하고, 실행 후 Console을 확인합니다.
2. WebGL과 비WebGL 플랫폼에서 각각 Log를 출력합니다. 비WebGL에서는 모두 `false`일 것으로 예상되며, WebGL에서는 현재 설정된 매크로 플랫폼만 `true`여야 합니다.
3. 여전히 `false`라면 진단 표로 돌아가 다음 항목을 하나씩 확인합니다: 플랫폼이 WebGL인지, 매크로 이름의 철자가 맞는지, 재컴파일이 트리거되었는지.

## 배경

프레임워크는 각 미니게임 플랫폼에 대해 정적 속성(모두 `GameFrameX.Runtime.ApplicationHelper`에 위치)을 노출하며, `UNITY_WEBGL`과 각 플랫폼 매크로의 조합을 통해 컴파일 시점에 `true`/`false` 반환 여부를 결정합니다. 이를 통해 IL2CPP / AOT 스트립 시에도 올바르게 적용됩니다. 속성의 실제 소스 파일은 [ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs)를 참조하세요.
