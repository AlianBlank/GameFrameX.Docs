# IL2CPP 게시 후 타입 누락 또는 오류 발생 시 대처법

IL2CPP는 빌드 시 관리 코드 스트리핑(Managed Code Stripping)을 수행하며, LitJson은 리플렉션을 통해 reader/writer를 생성하므로 잘려나가면 IL2CPP 런타임에서 `MissingMethodException`, `InvalidCastException`이 발생하거나 역직렬화 결과가 빈 객체로 반환됩니다. 이 페이지에서는 빠른 진단 및 수정 단계를 제공합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `MissingMethodException: ... LitJson ...` | IL2CPP 링커가 LitJson 내부 메서드를 잘라냄 | `link.xml`을 추가하고 `LitJsonCroppingHelper`를 부착 |
| 역직렬화 결과 필드가 모두 `null`/기본값 | `JsonData`/`JsonMapper`의 익스포터가 잘림 | `link.xml` 추가 |
| `JsonMapper.ToObject<T>`는 객체를 반환하지만 속성이 누락됨 | 사용자 정의 T의 필드/속성이 잘림 | `link.xml`에서 해당 T의 타입을 어셈블리별로 보존 |
| `Type.GetType("...")`이 `null` 반환 | IL2CPP는 문자열 이름으로 보존되지 않은 타입 조회를 지원하지 않음 | 제네릭 `ToObject<T>()` 사용 또는 `link.xml`에서 해당 타입 보존 |
| 사용자 정의 Importer/Exporter 등록 시 `InvalidCastException` | 델리게이트 대상 메서드가 잘림 | `link.xml`에서 본인의 어셈블리 보존 |

## 수정 단계

### 1. link.xml 선언적 보존 추가

Unity 프로젝트의 임의의 `Assets` 하위 디렉터리에 `link.xml`을 생성합니다(보통 `Assets/link.xml`에 위치). 내용은 다음과 같으며, LitJson 어셈블리를 명시적으로 보존하는 역할을 합니다:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
</linker>
```

빌드 시 이 파일을 기반으로 LitJson 관련 타입의 스트리핑이 건너뛰어지며, 이것이 첫 번째 방어선입니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/README.zh-CN.md#L40-L50)

### 2. LitJsonCroppingHelper 런타임 스트리핑 방지 부착

저장소에는 `LitJsonCroppingHelper`가 포함되어 있으며, 이 컴포넌트는 `Start()`에서 `typeof(...)`를 통해 모든 공용 LitJson 타입을 명시적으로 참조하여 두 번째 보험 역할을 합니다:

```csharp
[Preserve]
public class LitJsonCroppingHelper : UnityEngine.MonoBehaviour
{
    [Preserve]
    public void Start()
    {
        _ = typeof(ArrayMetadata);
        _ = typeof(Condition);
        _ = typeof(ExporterFunc);
        _ = typeof(ExporterFunc<>);
        _ = typeof(JsonIgnoreAttribute);
        _ = typeof(JsonPropertyAttribute);
        _ = typeof(FsmContext);
        _ = typeof(IJsonWrapper);
        _ = typeof(ImporterFunc);
        _ = typeof(ImporterFunc<,>);
        _ = typeof(JsonData);
        _ = typeof(JsonException);
        _ = typeof(JsonMapper);
        _ = typeof(JsonMockWrapper);
        _ = typeof(JsonReader);
        _ = typeof(JsonToken);
        _ = typeof(JsonType);
        _ = typeof(JsonWriter);
        _ = typeof(Lexer);
        _ = typeof(ObjectMetadata);
        _ = typeof(OrderedDictionaryEnumerator);
        _ = typeof(ParserToken);
        _ = typeof(PropertyMetadata);
        _ = typeof(UnityTypeBindings);
        _ = typeof(WrapperFactory);
        _ = typeof(WriterContext);
    }
}
```

이 컴포넌트를 씬에서 **가장 먼저 시작되는** GameObject(예: `Bootstrap`)에 부착하여, `Start()`가 모든 `JsonMapper` 호출보다 먼저 실행되도록 보장하세요.

Source: [LitJsonCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/LitJsonCroppingHelper.cs#L12-L52)

### 3. 사용자 정의 데이터 타입 보존

`JsonMapper.ToObject<MyData>("...")`를 사용하여 사용자 정의 클래스를 역직렬화하고, `MyData`가 다른 어셈블리에 위치하는 경우, `link.xml`에 보존 항목을 추가해야 합니다:

```xml
<linker>
  <assembly fullname="GameFrameX.LitJSON.Runtime" preserve="all"/>
  <assembly fullname="MyGame.Models" preserve="all"/>
</linker>
```

또는 패키지 크기를 줄이기 위해 특정 타입만 보존할 수도 있습니다:

```xml
<linker>
  <assembly fullname="MyGame.Models">
    <type fullname="MyGame.Models.PlayerData" preserve="all"/>
    <type fullname="MyGame.Models.InventoryItem" preserve="all"/>
  </assembly>
</linker>
```

### 4. 문자열 이름으로 타입 로드에 의존하지 않기

`Type.GetType("MyGame.Models.PlayerData, MyGame.Models")`는 IL2CPP에서 해당 타입이 `link.xml`로 보존되지 않은 경우 `null`을 반환합니다. 권장 사항:

- 제네릭 `JsonMapper.ToObject<PlayerData>(json)` 사용;
- 또는 `link.xml`에서 해당 타입을 명시적으로 보존;
- 또는 `JsonMapper.RegisterImporter<string, Type>(s => Type.GetType(s))`를 호출하여 사용자 정의 임포터를 등록할 때 대상 타입이 보존되어 있는지 확인.

Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L47)

### 5. Unity 빌드 설정 확인

1. `Player Settings > Managed Stripping Level`: IL2CPP에서는 `Low` 이하로 유지; `High`/사용자 정의 규칙을 사용하는 경우 반드시 `link.xml`과 함께 사용.
2. `Player Settings > Strip Engine Code`: 체크 해제하거나 `link.xml` 예외에 포함.
3. Library/ScriptAssemblies를 정리한 후 다시 패키징하여 캐시로 인한 설정 변경 마스킹 방지.

## 검증

1. IL2CPP로 패키징한 후, 게임을 실행하여 `JsonMapper.ToJson`과 `JsonMapper.ToObject` 양방향 흐름을 한 번 완전하게 트리거하여 `MissingMethodException`이 없는지 확인.
2. Xcode/Android 로그에서 `LitJson`, `MissingMethod` 키워드를 검색하여 오류가 없는지 확인.
3. 역직렬화 결과 객체의 필드 값이 원본 JSON과 일치하는지 확인(null/기본값 없음).
4. 임시로 `Managed Stripping Level`을 `High`로 조정한 후 재테스트하여, 가장 엄격한 스트리핑 조건에서도 `link.xml`과 `LitJsonCroppingHelper`가 여전히生效하는지 확인.
