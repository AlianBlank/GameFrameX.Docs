# ダウンロード失敗時の対処法:エラーコードとコールバックの切り分け

`DownloadComponent` が `DownloadFailureEventArgs` または `DownloadAgentHelperErrorEventArgs` をスローした場合、タスクは失敗状態にあります。このページでは、エラーコールバック内のフィールドに基づいて根本原因を迅速に特定し、修正する方法を説明します。

## クイック診断

| 症状(コールバックフィールドの値)| 根本原因 | 簡易修正方法 |
|---|---|---|
| `ErrorMessage` が `"... 416 ..."` であり、かつ `DeleteDownloading == true`(UnityWebRequest)または `"416"` で始まる(WWW)| HTTP 416 Range Not Satisfiable — リモートがリクエストされたバイト範囲をサポートしていない | 下記の「416 Range エラー」修正手順を参照 |
| `ErrorMessage` が空ではないが、416 を含まない | ネットワーク層の異常(タイムアウト、DNS 失敗、接続切断、プロトコルエラーなど)| 下記の「ネットワーク層エラー」修正手順を参照 |
| `DeleteDownloading == true` かつ `ErrorMessage` が空ではない | タスクが書き込んだファイルを削除する必要があり、残留を防ぐ必要がある | 下記の「失敗残留のクリーンアップ」修正手順を参照 |
| 長時間コールバックがない、`WorkingAgentCount == TotalAgentCount` | すべての Agent が占有されており、新しいタスクが待機中 | 下記の「タスクのスタック」修正手順を参照 |

> フィールドの定義は [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L38-L88) と [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L38-L116) を参照してください。

## 修正手順

### 1. 失敗コールバックを購読し、まず元の情報を取得する

`DownloadComponent.Awake` 後のイベント購読箇所には、すでに `DownloadFailure` が登録されています。処理関数を実装し、イベントバスまたは `IDownloadManager.DownloadFailure` を介して `DownloadFailureEventArgs` を取得するだけです:

```csharp
using GameFrameX.Download.Runtime;
using GameFrameX.Event.Runtime;

// イベントバス経由で購読(推奨、コンポーネントとの結合を解消)
GameEntry.GetComponent<EventComponent>().Subscribe(
    DownloadFailureEventArgs.EventId,
    OnDownloadFailure
);

private void OnDownloadFailure(object sender, GameEventArgs e)
{
    var args = (DownloadFailureEventArgs)e;
    Debug.LogError($"[Download] FAIL serial={args.SerialId} path={args.DownloadPath} uri={args.DownloadUri} err={args.ErrorMessage} userData={args.UserData}");
}
```

Source: [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L80-L97)

### 2. 416 Range Not Satisfiable

これはフレームワークが「リモートがレジューム用バイト範囲を拒否した」と識別したシグナルです。フレームワークの判定方法は以下の通りです:

- UnityWebRequest 実装:`responseCode == 416` の場合、`DeleteDownloading = true`。
- WWW 実装:`error` 文字列が `"416"` で始まる場合、`DeleteDownloading = true`。

Source: [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs#L44-L44) ; [UnityWebRequestDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/UnityWebRequestDownloadAgentHelper.cs#L240-L240) ; [WWWDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/WWWDownloadAgentHelper.cs#L248-L248)

修正操作：

1. `DeleteDownloading == true` の失敗コールバックを受信した後、ローカルに残留している断片ファイルを削除します。
2. `DownloadComponent.AddDownload(url, tag, priority, userData)` を再度呼び出すと、フレームワークは 0 から再ダウンロードします。
3. CDN/OSS が `Range` リクエストをサポートしていない場合は、レジュームを無効化するか、アドレス層でこのファイル種別を除外します。

### 3. ネットワーク層エラー(タイムアウト / DNS / 接続リセット)

`DownloadAgentHelperErrorEventArgs.ErrorMessage` は Unity ネイティブのエラー文字列をそのまま透過します。例：`"Cannot resolve destination host"`、`"Request timeout"`、`"Connection failure"`。

修正操作：

1. `DownloadComponent.Timeout`(デフォルト 30 秒)を必要に応じて大きくします。例えば、インターネット上のファイルの場合は 60 秒に変更します:[DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60-L62) を参照。
2. アドレスに HTTPS が必要か、プロキシにブロックされていないかを確認します。
3. リトライを実装します:`DownloadFailure` コールバック内で同じ URL のダウンロードタスクを再度キューに入れます(再試行回数を区別できるよう `UserData` を置き換えることに注意)。

### 4. 失敗残留のクリーンアップ

`DownloadAgentHelperErrorEventArgs.DeleteDownloading == true` の場合、フレームワークはローカルの断片ファイルをクリーンアップすることを推奨しています:

```csharp
private void OnAgentError(object sender, GameEventArgs e)
{
    var args = (DownloadAgentHelperErrorEventArgs)e;
    if (args.DeleteDownloading && !string.IsNullOrEmpty(localPath) && File.Exists(localPath))
    {
        File.Delete(localPath);
    }
}
```

Source: [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L67-L73)

### 5. タスクのスタック(キューの滞留)

長時間 `DownloadSuccess` を取得できず、`DownloadFailure` も発生しない場合、通常は Agent が満杯です。以下のプロパティを監視して判断します:

| プロパティ | 意味 |
|---|---|
| `DownloadComponent.TotalAgentCount` | 総 Agent 数、デフォルト 3 |
| `DownloadComponent.WorkingAgentCount` | ダウンロード中の Agent |
| `DownloadComponent.WaitingTaskCount` | 待機中のタスク |
| `DownloadComponent.Paused` | 全体的に一時停止されているかどうか |

Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L78-L105)

修正：

1. Inspector で `Download Agent Helper Count` を大きくします。
2. `DownloadComponent.Paused = true` にした後、復元を忘れていないか確認します。
3. `DownloadComponent.GetDownloadInfo(serialId)` / `GetDownloadInfos(tag)` を使用して現在のタスク状態を取得します。

## 検証

以下の順序で問題が解決されたことを検証します:

1. 失敗することがわかっているダウンロードを 1 回実行し(例：間違ったアドレスを入力、または意図的にネットワークを切断)、`DownloadFailure` コールバックを受信でき、`ErrorMessage` が期待どおりであることを確認します。
2. 416 のシナリオでは、コールバック後にローカルに残留ファイルがなく、`AddDownload` を再度呼び出すことで完全なファイルのダウンロードに成功することを確認します。
3. ネットワークタイムアウトのシナリオでは、`Timeout` を小さくして一度再現し、その後新しいタイムアウト値で成功まで再現します。
4. 一括ダウンロードを一通り実行し、`WaitingTaskCount` が合理的な時間内に 0 になり、`FreeAgentCount` が `TotalAgentCount` に戻ることを確認します。
