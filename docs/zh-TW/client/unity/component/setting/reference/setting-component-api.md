# SettingComponent API 速查

`SettingComponent` 是 GameFrameX 設定模組對外公開的 Unity 元件進入點。將其附加到場景後，框架會自動初始化並載入設定，業務端可透過此元件讀寫鍵值對設定。下表彙整了所有公開 API 及對應的簽章。這些全部會直接轉發至 `ISettingManager` 的實作。

## 元件屬性與序列化欄位

| 成員 | 型別 | 預設值 | 說明 |
|------|------|--------|------|
| `Count` | `int` (get) | — | 目目前已載入的設定項目數 |
| `m_SettingHelperTypeName` | `string` (SerializeField) | `"GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper"` | 透過反射產生之內建輔助器的完整型別名稱 |
| `m_CustomSettingHelper` | `SettingHelperBase` (SerializeField) | `null` | 自訂輔助器實例。若不為 null 則優先使用 |

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L48-L54)

## 生命週期

| 階段 | 行為 |
|------|------|
| `Awake()` | 解析 `componentType`、`InterfaceComponentType = typeof(ISettingManager)`,並透過 `GameFrameworkEntry.GetModule<ISettingManager>()` 取得管理器。以反射方式產生 `m_SettingHelperTypeName`,或直接附加 `m_CustomSettingHelper`,掛載到自身的 `Transform` 後呼叫 `SetSettingHelper`。 |
| `Start()` | 呼叫 `m_SettingManager.Load()`,若失敗則記錄 `Log.Error("Load settings failure.")`。 |

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L75-L108)

## 最小呼叫範例

```csharp
using GameFrameX.Setting.Runtime;
using UnityEngine;

public class GameSettingExample : MonoBehaviour
{
    private SettingComponent _setting;

    private void Awake()
    {
        _setting = GetComponent<SettingComponent>();
        // 寫入後立即持久化
        _setting.SetBool("MusicOn", true);
        _setting.Save();
    }

    private void Start()
    {
        // 指定預設值讀取。若 "Score" 不存在則回傳 0
        int score = _setting.GetInt("Score", 0);
        bool musicOn = _setting.GetBool("MusicOn", false);
        Debug.Log($"score={score}, music={musicOn}");
    }
}
```

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `Log.Fatal("Setting manager is invalid.")` | 在 `Awake` 階段未能取得 `ISettingManager` 實例 | 確認專案已正確整合 `GameFrameX` 框架的進入點，並已載入至 `GameFrameworkEntry` |
| `Log.Error("Can not create setting helper.")` | `m_SettingHelperTypeName` 所指的型別不存在，或未附加 `m_CustomSettingHelper` | 確認在 Inspector 中輸入的完整型別名稱，或確認自訂輔助器繼承自 `SettingHelperBase` |
| `Log.Error("Load settings failure.")` | 在 `Start` 中 `m_SettingManager.Load()` 回傳 `false` | 確認所選平台是否有對應可用的 `ISettingStorageBackend`(請參閱 `Storage/SettingStorageBackendFactory`) |
