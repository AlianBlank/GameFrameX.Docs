# GET 요청 보내는 방법(쿼리 파라미터와 요청 헤더)

`IWebManager`의 `GetToString` / `GetToBytes` 시리즈 메서드로 GET 요청을 보낼 수 있습니다: 쿼리 파라미터는 `Dictionary<string, string>`으로 전달하고(프레임워크가 자동으로 URL에 연결), 요청 헤더는 별도의 `Dictionary<string, string>`으로 전달하며, `await`할 수 있도록 `Task<WebStringResult>` 또는 `Task<WebBufferResult>`를 반환합니다.

## 사전 조건

- 프로젝트에 이 패키지의 Web 런타임(`Runtime/Web`, 진입 컴포넌트는 [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs))이 이미 도입되어 있어야 합니다.
- `IWebManager` 인스턴스를 확보합니다([WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs)에서 구현된 `partial` 클래스).

## GET 메서드 빠른 참조

아래 시그니처는 [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L18-L67)에서 발췌한 것입니다:

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| 가장 간단한 GET(텍스트) | `Task<WebStringResult> GetToString(string url, object userData = null)` | 파라미터 없음, 커스텀 헤더 없음 |
| 가장 간단한 GET(바이트) | `Task<WebBufferResult> GetToBytes(string url, object userData = null)` | 바이너리 다운로드에 적합 |
| 쿼리 파라미터 포함(텍스트) | `Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, object userData = null)` | 파라미터가 자동으로 URL에 추가됨 |
| 쿼리 파라미터 포함(바이트) | `Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, object userData = null)` | 위와 동일, 바이트 반환 |
| 파라미터와 요청 헤더 포함(텍스트) | `Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | 파라미터가 뒤에, 요청 헤더가 앞에 |
| 파라미터와 요청 헤더 포함(바이트) | `Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | 위와 동일, 바이트 반환 |

모든 오버로드는 선택 사항인 `userData`를 지원하며, 이 값은 결과 객체에 그대로 담겨 반환됩니다(아래 "배경" 참조).

## 작업 단계

1. `GetToString` / `GetToBytes`의 원하는 오버로드를 호출하며 `url`을 전달합니다. 쿼리 파라미터나 요청 헤더가 필요하면 해당 딕셔너리를 추가로 전달합니다.
2. 반환된 `Task`를 `await`하여 `WebStringResult`(응답 텍스트) 또는 `WebBufferResult`(바이트 배열)를 얻습니다.
3. 실패 시 태스크에서 예외가 발생하므로(네트워크/HTTP 오류 또는 `TimeoutException`), `await`를 `try/catch`로 감싸면 됩니다.

가장 간단한 형태의 실제 구현(파라미터 없는 오버로드는 "파라미터 + 헤더" 오버로드를 바로 호출):

```csharp
public Task<WebStringResult> GetToString(string url, object userData = null)
{
    return GetToString(url, null, null, userData);
}
```

출처: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L133-L136)

쿼리 파라미터와 요청 헤더를 포함한 전체 오버로드(프레임워크 내부에서 파라미터 병합, URL 연결, 큐잉을 수행):

```csharp
public Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)
{
    var uniTaskCompletionSource = new TaskCompletionSource<WebStringResult>();
    queryString = MergeQueryString(queryString);
    header = MergeHeader(header);
    url = UrlHandler(url, queryString);

    WebJsonData webJsonData = WebJsonData.Create(url, header, true, uniTaskCompletionSource, userData);
    m_WaitingNormalQueue.Enqueue(webJsonData);
    return uniTaskCompletionSource.Task;
}
```

출처: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L184-L195)

위 시그니처를 기반으로 한 일반적인 호출 방식(반환된 Task를 `await`로 소비):

```csharp
// 1) 가장 간단한 GET
WebStringResult r1 = await webManager.GetToString("https://example.com/api/info");

// 2) 쿼리 파라미터 포함
var query = new Dictionary<string, string> { { "page", "1" }, { "size", "20" } };
WebStringResult r2 = await webManager.GetToString("https://example.com/api/list", query);

// 3) 쿼리 파라미터 + 요청 헤더
var header = new Dictionary<string, string> { { "Authorization", "Bearer <token>" } };
WebStringResult r3 = await webManager.GetToString("https://example.com/api/user", query, header);
```

출처: [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L18-L67)

## 일반적인 변형

- **바이트 배열 반환(파일, 이미지 다운로드)**: `GetToBytes`를 대신 사용하면 `WebBufferResult`를 반환합니다. 시그니처는 [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L26-L67) 참조.
- **쿼리 파라미터 순서가 맞지 않나요?** 오버로드 파라미터 순서는 `(url, queryString, header, userData)`로 고정되어 있어, 요청 헤더만 전달할 때도 `queryString` 자리에 `null`을 넣어야 합니다.
- **쿼리 파라미터만 전달하고 헤더는 불필요**: 두 파라미터 오버로드를 직접 호출하면 되며, URL을 수동으로 조합할 필요가 없습니다.

## 자주 발생하는 오류

| 현상 | 원인 | 처리 |
|------|------|------|
| `await`에서 `TimeoutException` 발생 | 요청 시간 초과, [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L300)의 `WebExceptionStatus.Timeout` 분기에서 변환됨 | 타임아웃 시간을 늘리거나 네트워크를 점검하고, `catch (TimeoutException)`으로 별도 처리 |
| 태스크에서 일반 `Exception` 발생(내용은 오류 텍스트) | WebGL이 아닌 플랫폼은 `HttpWebRequest`를 사용하며, 네트워크/HTTP 오류 시 바로 `SetException` 호출(참조: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L305)) | URL, 파라미터, 서버 상태 코드 확인 |
| WebGL에서 `unityWebRequest.error` 발생 | WebGL 분기에서 `isNetworkError / isHttpError / error`를 감지한 뒤 `TrySetException` 호출(참조: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L239-L247)) | WebGL 플랫폼에서 접근 가능한 크로스 도메인 정책과 서버 설정 확인 |
| 요청 헤더가 적용되지 않음 | 전달한 `header` 딕셔너리가 비어 있거나 전역 기본 헤더 덮어쓰기 로직의 영향 | 키와 값이 비어 있지 않은지 확인. 헤더는 `SetRequestHeader`/`request.Headers[key] = value`로 항목별로 기록됨(참조: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L227-L233), [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L273-L279)) |

## 배경(선택)

GET 요청의 데이터 운반체는 내부의 `WebJsonData`입니다(참조: [WebManager.WebJsonData.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.WebJsonData.cs#L12-L98)). 이 객체는 URL, `Header` 딕셔너리, 결과 `TaskCompletionSource`를 보관합니다. 요청은 먼저 `m_WaitingNormalQueue`에 들어가 대기한 뒤, 전송 흐름에 따라 WebGL에서는 `UnityWebRequest.Get`으로, 그 외 플랫폼에서는 `HttpWebRequest`(`WebRequestMethods.Http.Get`)로 발송됩니다. 쿼리 파라미터는 `UrlHandler(url, queryString)`를 통해 URL에 연결되고, 커스텀 헤더는 요청에 항목별로 기록됩니다. `userData`는 결과 객체와 함께 반환되어 동시 요청을 구분하는 데 유용합니다.
