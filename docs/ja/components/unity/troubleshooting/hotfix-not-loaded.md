# ホットアップデートが効かない / DLL が読み込まれない場合の対処

GameFrameX をエディターまたは実機で起動した際、ホットアップデート用 DLL が読み込まれない、ホットアップデートのエントリーメソッドが呼び出されない、あるいは新しいパッケージを出力しても業務ロジックに何の変化もない場合は、本ページのステップに従って原因を特定してください。

## クイック診断

| 症状 | 原因 | 修復方法 |
|------|------|------|
| コンソールに `开始加载AOT DLL` / `开始加载程序集Hotfix` のログが一切表示されない | HybridCLR マクロが有効化されておらず、`RunNative` 分岐に進んでいる | Player Settings → Scripting Define Symbols に `ENABLE_GAME_FRAME_X_HYBRID_CLR` を追加し、`DISABLE_HYBRIDCLR` を削除する |
| 起動時、エディターは `Unity.Hotfix` アセンブリの読み込みを行うが、実機では DLL が効かない | 実機は AOT + ホットアップデート DLL 経路で動作しており、`AOTGenericReferences.PatchedAOTAssemblyList` が空である | HybridCLR Settings → `AOT Generic References` でジェネリック参照をチェックし、`HybridCLR/Compile DLL` を実行して再生成する |
| ログが `开始加载XXX.dll` で止まり、例外（リソースが見つからない）が発生する | DLL が AB パッケージに含まれていない、またはフレームワーク既定のディレクトリに配置されていない | `HybridCLR/Build DLL` とフレームワークのビルドパイプラインでパッケージを出力し、`Utility.Asset.Path.GetCodePath` が返すパスでリソースがヒットすることを確認する |
| ログの `EntryType=>method` が null で、アセンブリは読み込まれたがエントリーメソッドが実行されない | `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` が実際の DLL と一致していない | `StartupOptions` で正しい名称を明示的に指定するか、`HotfixHelper` のデフォルト値（既定では `Unity.Hotfix` / `Hotfix.HotfixLauncher` / `Main`）を変更する |
| 実機でホットアップデート DLL を読み込んでも旧ロジックが動作する | リソースサーバーが古い `AssetBundle` / ホットアップデート DLL を返している | CDN キャッシュを消去し、最新のパッケージを強制的に再取得する |

## 修復手順

### 1. コンパイルマクロとエントリ一名の確認

ホットアップデートロジックは `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR` で括られており、この 2 つのマクロ定義が満たされたときにのみ AOT DLL とホットアップデート DLL が実際に読み込まれます。

[HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L5-L9) の重要なコード:

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR
using System.Reflection;
using System.Linq;
using HybridCLR;
#endif
```

エントリーメソッドのデフォルト値（`StartupOptions` を渡さない場合に使用される）は [HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70) で定義されています:

```csharp
var assemblyName = options == null || string.IsNullOrEmpty(options.HotfixAssemblyName)
    ? "Unity.Hotfix"
    : options.HotfixAssemblyName;
var entryTypeName = options == null || string.IsNullOrEmpty(options.HotfixEntryTypeName)
    ? "Hotfix.HotfixLauncher"
    : options.HotfixEntryTypeName;
var entryMethodName = options == null || string.IsNullOrEmpty(options.HotfixEntryMethodName)
    ? "Main"
    : options.HotfixEntryMethodName;
```

ホットアップデート DLL のアセンブリ名、エントリ型、エントリメソッドがこれらのデフォルト値と完全に一致していることを確認してください。

### 2. エディターとランタイムで進む分岐の確認

[HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L72-L110) では、エディターは読み込まれたアセンブリを直接 `Run` し、実機でのみ AOT DLL + ホットアップデート DLL の読み込みを行います:

```csharp
if (ApplicationHelper.IsEditor)
{
    var assemblies = Utility.Assembly.GetAssemblies();
    foreach (var assembly in assemblies)
    {
        if (assembly.GetName().Name.Equals(assemblyName, StringComparison.OrdinalIgnoreCase))
        {
            Run(assembly, entryTypeName, entryMethodName);
            break;
        }
    }
    return;
}
```

つまり、エディターで「コードを変更するとすぐに反映される」のは正常な動作です。ホットアップデート DLL が実際に読み込まれているかを検証するには、実機でのテストが必要です。

### 3. AOT ジェネリック参照が生成されていることの確認

実機分岐では `AOTGenericReferences.PatchedAOTAssemblyList` に基づいて AOT メタデータが読み込まれます:

```csharp
var aotDlls = AOTGenericReferences.PatchedAOTAssemblyList.ToArray();
foreach (var aotDll in aotDlls)
{
    var assetHandle = await GameApp.Asset.LoadAssetAsync<UnityEngine.Object>(
        Utility.Asset.Path.GetAOTCodePath(aotDll));
    var aotBytes = assetHandle.GetAssetObject<UnityEngine.TextAsset>().bytes;
    RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet);
}
```

リストが空の場合、AOT メタデータの読み込みはスキップされ、その後の `Assembly.Load(hotfixDll)` 呼び出しがメタデータ欠如により失敗します。修復方法: HybridCLR パネルで `Compile DLL` をクリックし、`AOTGenericReferences.PatchedAOTAssemblyList` を再生成してください。

### 4. ホットアップデート DLL リソースがヒットできることの確認

ホットアップデート DLL は `Utility.Asset.Path.GetCodePath` でパスを組み立て、リソースシステム経由で読み込まれます:

```csharp
var assetHotfixDllPath = Utility.Asset.Path.GetCodePath(assemblyName + Utility.Const.FileNameSuffix.DLL);
var assetHotfixDllOperationHandle = await GameApp.Asset.LoadAssetAsync<UnityEngine.Object>(assetHotfixDllPath);
var assemblyDataHotfixDll = assetHotfixDllOperationHandle.GetAssetObject<UnityEngine.TextAsset>().bytes;
var hotfixAssembly = Assembly.Load(assemblyDataHotfixDll, null);
```

パスに対応するリソースが AB パッケージ内に存在しない場合、読み込み時に例外が発生し、`HotfixHelper.StartHotfixAsync` でキャッチされて `HotfixLaunchResult.Fail(e.Message)` として返されます:

```csharp
catch (Exception e)
{
    Log.Error(e);
    return HotfixLaunchResult.Fail(e.Message);
}
```

修復方法: ビルドパイプラインが `Unity.Hotfix.dll` および AOT DLL を対応する AB に実際に含めているかを確認し、ローカルキャッシュ / CDN キャッシュを消去してください。

### 5. `StartupOptions` で明示的にエントリを指定する

ホットアップデートのアセンブリ名やエントリクラス名を変更した場合は、`StartupOptions` で明示的に渡すことで、デフォルト値の不一致を避けてください:

```csharp
var options = new StartupOptions
{
    HotfixAssemblyName = "Unity.Hotfix",
    HotfixEntryTypeName = "Hotfix.HotfixLauncher",
    HotfixEntryMethodName = "Main",
};
await HotfixHelper.StartHotfixAsync(options);
```

アプリケーション層のエントリは [ApplicationHotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs#L22-L25) で `IHotfixLauncher` に適合されます:

```csharp
public UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    return HotfixHelper.StartHotfixAsync(options);
}
```

## 検証

1. パッケージを再出力し、ローカルの `AssetBundle` キャッシュディレクトリを空にする。
2. ゲームを起動し、ログに `开始加载AOT DLL`、`开始加载XXX.dll`、`加载程序集Hotfix 结束 Assembly ...`、`加载程序集Hotfix 结束 EntryType=>method` が順番に表示されることを確認する。
3. `Hotfix.HotfixLauncher.Main` のロジックを変更した後、ホットアップデート DLL のみを再ビルドし、実機で新しいロジックが有効になるかを検証する。

## 背景（任意）

- エディター分岐は `Assembly.GetName().Name.Equals(...)` のマッチングのみを行うため、プロジェクト内に `Unity.Hotfix` アセンブリが存在すれば必ず読み込まれる。
- 実機分岐は `Utility.Asset.Path.GetCodePath` / `GetAOTCodePath` の実装に依存しており、これら 2 つのユーティリティメソッドが DLL の実際のリソースパスを決定する。具体的な設定についてはフレームワークのビルドパイプラインドキュメントを参照。
- 読み込み時の例外は `try/catch` で吸収され、`HotfixLaunchResult.Fail` を通じて呼び出し元に公開される。そのため、起動失敗はプロセスをクラッシュさせないが、ホットアップデートロジックも実行されない。
