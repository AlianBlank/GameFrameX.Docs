# 回呼擲出例外怎麼辦

當計時器回呼內部擲出例外(如空參考、`InvalidOperationException`)時,預設行為是例外直接向上擲出，可能中斷 `Update` 中後續回呼的執行；將 `TimerManager.CatchCallbackExceptions` 設為 `true` 可讓管理器攔截例外並降級為警告日誌，不影響其餘計時器繼續執行。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 回呼擲出例外後主控台直接出現紅色錯誤訊息，後續計時器回呼不執行 | `TimerManager.CatchCallbackExceptions` 保持預設值 `false`,例外原樣向上傳播 | 按下文步驟設為 `true`,再排查回呼自身邏輯 |
| 主控台出現 `Timer callback error > {例外訊息}` 警告 | `CatchCallbackExceptions = true` 時被攔截的例外，以 `Debug.LogWarning` 輸出 | 警告內容即回呼內真實例外，據此定位回呼程式碼 |
| 測試中例外以 `TargetInvocationException` 形式擲出 | 透過反射呼叫 `Update` 時，未攔截的例外會被包成 `TargetInvocationException` | 屬正常傳播行為，非計時器缺陷；開啟攔截或修復回呼即可 |

## 修復步驟

### 1. 開啟回呼例外攔截

在遊戲初始化階段(設定回呼之前)把靜態開關打開:

```csharp
TimerManager.CatchCallbackExceptions = true;
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L204-L206)

該開關的預設值為 `false`:

```csharp
/// <summary>
/// 是否觸發回呼例外
/// </summary>
public static bool CatchCallbackExceptions = false;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L53-L56)

### 2. 了解攔截後的行為

開啟後，管理器在執行回呼時用 `try/catch` 包裹呼叫，攔截到例外只輸出警告，不中斷迴圈:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L190)

注意：所有回呼都在鎖外統一執行，單一回呼例外被吞掉後，**同一幀內其餘待執行回呼仍會正常觸發**。

### 3. 用測試重現兩種模式的行為

儲存庫的單元測試展示了開關兩種狀態下的差異，可直接作為排查參照:

```csharp
[Test]
public void CatchCallbackExceptions_On_DoesNotThrow_OnException()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = true;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.DoesNotThrow(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Should catch exception silently");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}

[Test]
public void CatchCallbackExceptions_Off_ThrowsToCaller()
{
    var original = TimerManager.CatchCallbackExceptions;
    TimerManager.CatchCallbackExceptions = false;
    try
    {
        _timerManager.AddOnce(1f, _ => throw new InvalidOperationException("expected test error"));
        Assert.Throws<TargetInvocationException>(() => InvokeUpdate(_timerManager, 0f, 1.5f),
            "Exception should propagate through reflection as TargetInvocationException");
    }
    finally
    {
        TimerManager.CatchCallbackExceptions = original;
    }
}
```

## 驗證

- 開啟開關後，建立一個會擲出例外的回呼(如 `_ => throw new InvalidOperationException("test")`)並註冊計時器;
- 驅動 `Update` 推進時間，確認不再擲出未處理例外，主控台僅出現 `Timer callback error > test` 形式的黃色警告；
- 確認同一幀註冊的其他計時器回呼仍按預期執行；
- 生產環境建議始終關閉例外攔截並**修復回呼本身**，開關只用於隔離故障、避免單一回呼拖垮整幀。

## 背景

回呼統一在鎖外的 `_pendingCallbacks` 佇列中執行，這樣做是為了避免業務回呼長時間佔用鎖、阻塞其他執行緒。正因為所有回呼循序執行，任何一個未攔截的例外都會終止整批回呼，所以框架提供了這個全域開關作為容錯保護。
