# 租戶/組織隔離實體基底類別的使用方法

繼承 `EntityTenantOrganizationBase`（或其泛型版本），可讓實體同時具備多租戶隔離與組織隔離的能力。`TenantId` 與 `CreateOrganizationId` 欄位會自動附加，並實作 `ITenantIdFilter` 與 `IOrganizationIdFilter` 介面。結合 ORM 篩選器，即可依租戶/組織自動過濾資料。

## 前置條件

- 已安裝 NuGet 套件：`GameFrameX.Foundation.Orm.Entity`
- ORM 框架已設定租戶上下文（目前的 `TenantId`）與組織上下文（目前的 `CreateOrganizationId`），且篩選器可自動注入
- 資料庫資料表中存在 `TenantId`、`CreateOrganizationId` 欄位（`long?` 可為 Null）

## 操作步驟

1. **讓實體類別繼承 `EntityTenantOrganizationBase<TKey>`**。指定主鍵型別（一般為 `long` 或 `Guid`）後，實體會自動取得 `TenantId`、`CreateOrganizationId` 兩個可為 Null 的 `long?` 屬性。

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L44-L55)

2. **（選用）為實體加上 `[TenantTable]` 屬性**。ORM 會依據此屬性啟用租戶隔離功能：自動注入租戶篩選器、強制寫入租戶識別碼、防止跨租戶存取。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
}
```

Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L63-L72)

3. **使用非泛型版本（主鍵由基底類別決定的情況）**。若 `EntityBase` 已提供預設的主鍵型別，可直接繼承 `EntityTenantOrganizationBase`，無需指定 `TKey`。

```csharp
public class GameArea : EntityTenantOrganizationBase
{
    public string AreaName { get; set; }
    public bool IsActive { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L64-L76)

4. **視需要寫入租戶與組織欄位**。ORM 攔截器會在新增/查詢時以目前上下文自動覆寫 `TenantId` 與 `CreateOrganizationId`。若需手動控制，可在業務程式碼中賦值。

```csharp
var order = new GameOrder
{
    OrderNo      = "O-20260101-0001",
    Amount       = 99.5m,
    CreatedTime  = DateTime.UtcNow,
    // TenantId 與 CreateOrganizationId 會由上下文自動設定
};
```

## 常見變化

| 情境 | 基底類別的選擇 | 說明 |
|------|----------|------|
| 僅需租戶隔離，不需區分組織 | `EntityTenantBase<TKey>` | 繼承 `ITenantIdFilter`，無 `CreateOrganizationId` 欄位 |
| 僅需組織隔離 | 於自訂實體實作 `IOrganizationIdFilter` | 僅公開 `CreateOrganizationId` |
| 同時需要租戶 + 組織隔離 | `EntityTenantOrganizationBase<TKey>` | 本頁所介紹 |
| 主鍵型別由框架預設決定 | `EntityTenantOrganizationBase`（非泛型） | 不明確傳入 `TKey` |

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| 查詢結果包含其他租戶/組織的資料 | 篩選器未啟用，或上下文未注入 `TenantId`/`CreateOrganizationId` | 檢查 ORM 的全域篩選器註冊；確認每個請求都有設定租戶/組織上下文 |
| 寫入時 `TenantId` 恆為 `null` | 實體類別同時被標記為全域資料表，或攔截器順序問題 | 租戶實體不要同時加上 `[SystemTable]`；僅加上 `[TenantTable]` |
| 繼承後找不到 `CreateOrganizationId` 欄位 | 誤繼承了 `EntityTenantBase`（僅租戶） | 使用 `EntityTenantOrganizationBase` 或其泛型版本 |
| 欄位名稱不一致 | 資料表結構缺少 `TenantId` 或 `CreateOrganizationId` 欄位 | 透過資料庫移轉新增對應的可為 Null 的 `bigint` 欄位 |

## 背景（選用）

`EntityTenantOrganizationBase` 繼承自 `EntityTenantBase`（提供 `TenantId` + `ITenantIdFilter`），並實作 `IOrganizationIdFilter`（提供 `CreateOrganizationId`）。這兩個篩選器介面會在 ORM 層被識別，對查詢自動附加 `WHERE TenantId = ? AND CreateOrganizationId = ?` 條件，對新增自動補上兩個欄位。`[TenantTable]` 是資料表層級的開關，用來通知 ORM 在此資料表啟用租戶隔離。它與 `[SystemTable]`（全域共享）互斥。

關於多租戶隔離的整體設計，請參閱《租戶隔離實體基底類別的使用方法》。
