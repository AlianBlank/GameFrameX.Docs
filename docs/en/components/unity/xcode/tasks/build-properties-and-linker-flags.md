# Setting Build Properties and Linker Flags

Fill in `properties` (Build Settings) and `otherLinkerFlag` (linker flags, such as `OTHER_LDFLAGS`) under the `unityMain` / `unityFramework` sections of `XCodeConfig.json`. After Unity exports the iOS project, the post-build processing automatically writes them into the generated Xcode project — there is no need to open Xcode and modify Build Settings manually.

## Prerequisites

- Unity has been switched to the iOS platform.
- A configuration file named `XCodeConfig.json` exists in the project (the file name must match exactly, as the post-processing scans by that file name); you can copy the repository's bundled [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) or [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json), rename it, and use it.

## Steps

1. Create `XCodeConfig.json` in the project (for content, refer to the templates and examples bundled in the repository).
2. Determine the target: the main executable Unity-iPhone goes in the `unityMain` section, dynamic libraries go in the `unityFramework` section, and the two sections have exactly the same structure.
3. Use the `properties` field to modify Build Settings; three operators are supported:

| Operator | PBXProject API Actually Called | Purpose |
|--------|---------------------------|------|
| `=` | `SetBuildProperty(targetGuid, key, value)` | Directly overwrites the value of a Build Setting |
| `+` | `UpdateBuildProperty(targetGuid, key, list, null)` | Appends values to a list-type Build Setting |
| `-` | `UpdateBuildProperty(targetGuid, key, null, list)` | Removes values from a list-type Build Setting |

   Parsing logic for the three operators (excerpted from `SetBuildProperties`):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}

Hashtable addTable = table.Get<Hashtable>("+");
// ... ArrayList-to-List<string> conversion omitted ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), list, null);

Hashtable removeTable = table.Get<Hashtable>("-");
// ... ArrayList-to-List<string> conversion omitted ...
proj.UpdateBuildProperty(targetGuid, i.Key.ToString(), null, list);
```

Source: [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L58)

4. Write the JSON following the table structure above (the key-value pairs under the `=`/`+`/`-` keys are the Build Setting names and values; values for `+`/`-` must be arrays):

```json
{
  "unityFramework": {
    "properties": {
      "=": { "ENABLE_BITCODE": "NO" },
      "+": { "OTHER_LDFLAGS": ["-lxml2"] },
      "-": { "OTHER_LDFLAGS": ["-ObjC"] }
    }
  }
}
```

5. Use the `otherLinkerFlag` field to add linker flags; it sits at the same level as `properties`. The actual form as written in the example file:

```json
"otherLinkerFlag": {
  "OTHER_LDFLAGS": ["-ObjC"]
}
```

Source: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L152-L154)

   Each flag is appended one by one to the corresponding Build Setting (calling `AddBuildProperty` once per entry):

```csharp
foreach (DictionaryEntry kv in table)
{
    var keyStr = kv.Key.ToString().Trim();
    if (kv.Value is ArrayList list)
    {
        // Array: call AddBuildProperty for each entry
        foreach (var part in parts)
        {
            proj.AddBuildProperty(targetGuid, keyStr, part);
        }
    }
    else
    {
        // String: call AddBuildProperty directly
        proj.AddBuildProperty(targetGuid, keyStr, kv.Value.ToString().Trim());
    }
}
```

Source: [PostProcessBuildHelper.OtherLinkFlag.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.OtherLinkFlag.cs#L15-L47)

6. Trigger the iOS build. The `[PostProcessBuild(888)]` `OnPostProcessBuild` reads all `XCodeConfig.json` files, merges them into one configuration, applies it in turn to `GetUnityMainTargetGuid()` and `GetUnityFrameworkTargetGuid()`, and finally writes back to `Unity-iPhone.xcodeproj/project.pbxproj`.

```csharp
Run(project, project.GetUnityMainTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityMain"), path);
Run(project, project.GetUnityFrameworkTargetGuid(), project.GetUnityMainTargetGuid(),
    finalConfig.Get<Hashtable>("unityFramework"), path);
```

## Common Variants

- **Array or single string both work**: if the value of `otherLinkerFlag` is written as an array (e.g., `["-ObjC", "-lxml2"]`), entries are appended one by one; if written as a single string, it is added once as a whole. The source code has handling branches for both forms.
- **Merging multiple configurations**: all scanned `XCodeConfig.json` files are merged in order, with later merges overriding earlier ones; if a channel is enabled (`SettingLoader.GetChannel()`), `XCodeConfig.{channel}.json` is merged last and has the highest priority.
- **Other fields in the same section**: the `unityMain` / `unityFramework` sections can also contain fields such as `frameworks`, `libs`, `files`, `folders`, `filesCompileFlag`, and `runPathSearchPaths`, all applied in sequence by the same `Run` call.

## Common Errors

| Symptom / Original Log | Cause | Fix |
|-----------------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | The file name is not `XCodeConfig.json`, or its location cannot be scanned | Rename it to the correct file name and place it in a scannable location |
| `{jsonPath} 解析失败, 跳过合并` | JSON syntax error | Fix it with a JSON validation tool and build again |
| `合并后的配置为空，跳过设置` | All files failed to parse | Check the syntax of each configuration file |
| Modified `properties` / `otherLinkerFlag` but no effect in Xcode | The fields were written at the top level of the JSON | These two fields must be written inside the `unityMain` or `unityFramework` sections; `Run` reads only from these two sections |
| `+` / `-` operations have no effect | The value was written as a string | The source code reads it with `i.Value as ArrayList`; a string yields an empty list, so it must be written as an array |

## Background

`properties` ultimately maps to `SetBuildProperty` / `UpdateBuildProperty`, and `otherLinkerFlag` maps to `AddBuildProperty` — all standard interfaces of Unity's built-in `UnityEditor.iOS.Xcode.PBXProject`. The difference is that the former supports overwriting as well as adding/removing, while the latter only appends. The whole flow is hooked on the `[PostProcessBuild(888)]` callback and runs only when `target == BuildTarget.iOS`.
