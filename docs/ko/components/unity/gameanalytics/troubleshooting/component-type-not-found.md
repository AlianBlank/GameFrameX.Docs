# 초기화 시 "Can not find component type" 오류 발생 시 대처 방법

이 오류는 `GameAnalyticsComponent.Init()`에서 발생합니다: Inspector에 구성된 특정 분석 컴포넌트의 `ComponentType` 문자열이 런타임에 `Utility.Assembly.GetType()`으로 실제 타입으로 해석되지 않으면 해당 Provider는 바로 건너뛰어지고(`continue`), 대응하는 통계 채널의 데이터가 전혀 업로드되지 않습니다. 해결의 핵심은 `ComponentType`을 실제로 존재하며 `IGameAnalyticsManager`를 구현한 클래스의 전체 타입 이름(네임스페이스 포함)과 일치시키는 것입니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Can not find component type 'XXX'` 오류가 발생하고 해당 채널에 업로드가 전혀 없음 | `ComponentType` 문자열이 실제 클래스 이름/네임스페이스와 일치하지 않음(텍스트를 직접 수정했거나 클래스 이름이 변경됨) | Inspector 드롭다운에서 올바른 타입을 다시 선택. 아래 단계 1 참조 |
| 에디터에서는 정상, 실기기 빌드 후 오류 발생 | 구현 클래스가 있는 어셈블리/코드가 스트리핑되었거나 빌드에 포함되지 않음 | 구현 클래스의 어셈블리가 빌드에 포함되고 코드 스트리핑으로 제거되지 않았는지 확인 |
| 구성에 있는 클래스가 실제로 존재하지만 여전히 오류 발생 | 타입 이름에 전체 네임스페이스가 포함되지 않아 `Utility.Assembly.GetType`에서 찾을 수 없음 | `GameFrameX.GameAnalytics.Runtime.XXXManager`와 같은 전체 타입 이름 사용 |
| 드롭다운 목록에 원하는 타입이 아예 없음 | 해당 클래스가 `IGameAnalyticsManager` 인터페이스를 구현하지 않아 Inspector에 나열되지 않음 | 클래스가 `IGameAnalyticsManager`를 구현하도록 함(일반적으로 `BaseGameAnalyticsManager` 상속) |

오류 발생 판정 로직(주의: 타입을 찾을 수 있어도 `IGameAnalyticsManager`를 구현하지 않으면 조용히 적용되지 않을 뿐 오류는 발생하지 않음):

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)

        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
```

## 해결 단계

### 1. Inspector 드롭다운으로 타입을 다시 선택하고, 문자열을 직접 입력하지 마세요

씬에서 GameAnalytics 컴포넌트(`AddComponentMenu("Game Framework/GameAnalytics")`)를 선택하고, Inspector의 "게임 데이터 분석 컴포넌트 목록, 순서대로 업로드" 목록에서 오류가 발생한 항목의 ComponentType을 다시 선택합니다.

드롭다운의 후보 목록은 `GameAnalyticsComponentInspector.RefreshTypeNames()`가 생성합니다: `IGameAnalyticsManager`를 구현한 모든 런타임 타입을 스캔하고, 추가로 `NoneOptionName` 빈 옵션 하나를 포함합니다.

```csharp
protected override void RefreshTypeNames()
{
    List<string> managerTypeNameList = new List<string>
    {
        NoneOptionName
    };
    managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
    m_ManagerTypeNames = managerTypeNameList.ToArray();
}
```

Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

드롭다운에서 목표 타입이 보이면 그것을 선택하면 됩니다. Inspector가 기록하는 것은 런타임 해석과 일치하는 타입 이름이므로, 직접 작성한 철자/네임스페이스 오류를 근본적으로 해결할 수 있습니다.

### 2. 드롭다운에 목표 타입이 없을 때, 클래스 정의를 확인하세요

구현 클래스는 `IGameAnalyticsManager`의 구현이어야 하며, 가장 간단한 방법은 프레임워크가 제공하는 추상 기반 클래스 `BaseGameAnalyticsManager`를 상속하고 그 추상 멤버를 구현하는 것입니다:

```csharp
public abstract class BaseGameAnalyticsManager : GameFrameworkModule, IGameAnalyticsManager
{
    public abstract void Init(Dictionary<string, string> args);
    public abstract void ManualInit(Dictionary<string, string> args);
    public abstract bool IsManualInit();
    ...
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L10-L36)

### 3. 구성 데이터 자체가 유효한지 확인하세요

`ComponentType`은 직렬화 클래스 `GameAnalyticsComponentProvider`(`Runtime/GameAnalytics/GameAnalyticsComponent.cs`의 362번째 줄 부근에 정의됨)에 저장되며, 씬/프리팹과 함께 직렬화됩니다. 다음 상황에서 "무효한 타입 이름이 잔존"하게 됩니다:

- 구현 클래스가 삭제되거나 이름이 변경된 후, 이전 씬/프리팹의 직렬화된 문자열이 동기화 업데이트되지 않음;
- 다른 사람의 씬 또는 프리팹을 복사했지만, 그것이 의존하는 분석 SDK 패키지가 현재 프로젝트에 임포트되지 않음.

처리 방법: 해당 씬/프리팹을 열고, 오류가 발생한 Provider 항목을 유효한 타입으로 변경하거나 해당 항목을 직접 삭제합니다.

## 검증

1. Play 모드에 다시 진입하거나(또는 컴포넌트를 다시 활성화하여 `OnEnable` → `Init()` 트리거), Console에 더 이상 `Can not find component type '...'`이 나타나지 않는지 확인합니다.
2. 공개 API를 한 번 호출하여(예: `GameAnalyticsComponent.SetPlayerId("test")`) 예외가 없고 데이터가 해당 채널에 도달하는지 확인합니다; `Init()`은 성공적으로 생성된 모든 `IGameAnalyticsManager`를 순회하며 그 `Init(args)`를 호출합니다.

```csharp
var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
{
    Dictionary<string, string> args = new Dictionary<string, string>();
    foreach (var param in gameAnalyticsComponentProvider.Setting)
    {
        args[param.Key] = param.Value;
    }

    gameAnalyticsManager.Init(args);
    m_GameAnalyticsManager.Add(gameAnalyticsManager);
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L65-L75)

`Init()`에는 `m_IsInit` 재진입 방지 보호가 있어 중복 호출 시 타입을 다시 해석하지 않습니다; 검증 시에는 완전히 새로운 초기화(Play 다시 시작 또는 컴포넌트 다시 활성화)에서 관찰해야 합니다.

## 배경

`GameAnalyticsComponent`는 `Awake`에서 Provider 목록을 구성하고, `OnEnable` 시 `Init()`을 호출하며, 리플렉션 `Utility.Assembly.GetType` + `Activator.CreateInstance`를 통해 문자열로 각 분석 채널 관리자를 인스턴스화하고, Inspector에서 해당 항목의 `Setting` 딕셔너리를 `Init(Dictionary<string, string> args)`에 그대로 전달합니다. 이러한 "문자열 + 리플렉션" 설계 덕분에 컴포넌트 구성이 컴파일 시점 의존성에서 벗어날 수 있지만, 그 대가로 타입 이름이 무효화되었을 때는 런타임에만 발견할 수 있으며, 이 페이지의 오류로 나타납니다.
