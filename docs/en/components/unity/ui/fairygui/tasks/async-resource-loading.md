# Switching Async Resource Loading Methods (YooAsset / Resources)

In this framework, whether a FairyGUI UI goes through YooAsset async loading or Resources sync loading is **automatically determined by whether the resource path passed in when opening the UI contains the Bundles directory name** (the check is based on `Utility.Asset.Path.BundlesDirectoryName`); no loader code changes are required. You only need to place the UI package in the correct directory and pass in the correct `uiFormAssetPath` to complete the switch.

## Prerequisites

- YooAsset mode: The project has the GameFrameX Asset component configured (obtained in code via `GameEntry.GetComponent<AssetComponent>()`), and the UI package build output is located under the Bundles directory.
- Resources mode: The UI package is placed directly under the `Resources` directory.
- The FairyGUI runtime library has been imported (`using FairyGUI;`).

## Steps

1. **Confirm the UI package storage location**:
   - For YooAsset async loading: place the package in the Bundles directory (the path contains `Utility.Asset.Path.BundlesDirectoryName`).
   - For Resources sync loading: place the package in the `Resources` directory, with no Bundles directory name in the path.

2. **Call the UI opening API and pass in the corresponding path**. The framework automatically routes based on the path in `UIManager.InnerLoadUIFormAsync`, with the branching logic as follows:

```csharp
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);

var lastIndexOfStart = uiFormAssetPath.LastIndexOf("/", StringComparison.OrdinalIgnoreCase);
// If there is no / in the path, the entire path is used as the package name (suitable for simple paths under the Resources directory)
var packageName = lastIndexOfStart >= 0 ? uiFormAssetPath.Substring(lastIndexOfStart + 1) : uiFormAssetPath;
// Check whether the UI package has already been loaded
var hasUIPackage = FairyGuiPackage.Has(packageName);
...
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Load from Resources
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

3. **The YooAsset branch first loads the UI package asynchronously, then loads the UI asset**. If the package has already been loaded, the UI is created directly; otherwise `AddPackageAsync` loads the package, and then the UI description asset is loaded asynchronously from `路径 + "_fui"`:

```csharp
if (hasUIPackage)
{
    // If the UI package exists, create the UI
    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 1, openUIFormInfo);
}

if (packageName == uiFormAssetName)
{
    // If the UI asset name matches the package name, load it directly
    await FairyGuiPackage.AddPackageAsync(assetPath);
}
else
{
    // If they don't match, recombine the path
    string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
    await FairyGuiPackage.AddPackageAsync(newPackagePath);
}

string newAssetPackagePath = assetPath;
if (packageName != uiFormAssetName)
{
    newAssetPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
}

newAssetPackagePath += "_fui";
// Load from the package
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);

if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    // Loaded successfully
    openUIFormInfo.SetAssetHandle(assetHandle);
    return LoadAssetSuccessCallback(assetPath, uiFormAssetName, openUIFormInfoData, assetHandle.Progress, openUIFormInfo);
}

// UI package does not exist
return LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo);
```

4. **Async loading of sub-assets within the package (atlases, sounds, fonts, etc.) is handled by `FairyGUILoadAsyncResourceHelper`**. It implements the `IAsyncResource` interface and uniformly goes through `AssetComponent`'s async APIs:

```csharp

            action.Invoke(false, assetName, null);
```

6. **Unload by package name when releasing resources**. `ReleasePackage` / `ReleaseAllPackage` also calls `AssetComponent.UnloadAsset` to unload both the description file and the assets:

```csharp
public void ReleasePackage(string uiPackageName)
{
    if (m_UIPackages.TryGetValue(uiPackageName, out var uiPackageData))
    {
        AssetComponent.UnloadAsset(uiPackageData.DescAssetPath);
        if (uiPackageData.ResourceAssetPath != null)
        {
            AssetComponent.UnloadAsset(uiPackageData.ResourceAssetPath);
        }

        uiPackageData.Dispose();
        m_UIPackages.Remove(uiPackageName);
    }
}
```

## Common Variants

| Variant | Approach |
|------|------|
| Package name differs from the UI name | Pass the path with the directory serving as the package name: the code takes the last segment of `uiFormAssetPath` as `packageName`; if it differs from the UI name, the path is recombined with `PathHelper.Combine(uiFormAssetPath, packageName)` before loading |
| Simple Resources path (no `/`) | The entire path is used directly as the package name, going through the `FairyGuiPackage.AddPackageSync` sync loading branch |
| Package already loaded | When `FairyGuiPackage.Has(packageName)` is true, loading is skipped and the flow goes straight to UI creation |
| Preload and wait for completion | Call `FairyGuiPackage.AddPackageAsync(descFilePath)`, which returns a `Task<UIPackage>`; it internally uses the `m_UIPackageLoading` dictionary + `TaskCompletionSource` to prevent duplicate loading |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Opening a UI returns synchronously without going through async loading | `assetPath` does not contain the Bundles directory name, so it is routed to the Resources sync branch | Make sure the path contains `Utility.Asset.Path.BundlesDirectoryName` in YooAsset mode |
| `LoadAssetFailureCallback` is invoked | `assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed` is false; the YooAsset handle failed | Inspect the returned `assetHandle.LastError` and confirm that the `路径 + "_fui"` asset has been packed into Bundles |
| `加载资源失败 Unknown file type: ...` log | `PackageItemType` falls into the default branch of `FairyGUILoadAsyncResourceHelper` (or the `FAIRYGUI_DRAGONBONES` macro is not enabled) | Confirm the asset type is supported; DragonBones requires the `FAIRYGUI_DRAGONBONES` macro to be defined |
| Console reports a missing Asset ending in `!a` | "Separate alpha channel" was not checked when exporting from FairyGUI, so the `!a` asset cannot be loaded | Source code comments explicitly state that this error **does not affect runtime**; to eliminate it, enable separate alpha channel when exporting |
| UI assets still occupy memory after being unloaded | `ReleasePackage` was not called, so the description file and asset handles were not unloaded | Call `FairyGUILoadAsyncResourceHelper.ReleasePackage(uiPackageName)` or `ReleaseAllPackage()` |

## Verification

- YooAsset mode: Watch AssetComponent's loading logs before and after opening a UI; confirm that the `xxx_fui` description asset and atlases/textures are loaded asynchronously and that the successful load goes through the `LoadAssetSuccessCallback` callback.
- Resources mode: Use breakpoints or logs to confirm that execution enters the `FairyGuiPackage.AddPackageSync(assetPath)` branch and that the UI displays correctly.
- Release verification: After calling `ReleasePackage`, open the same UI again; it should reload successfully with no handle leak errors.

## Background

Both loading methods share the same UI opening flow and only diverge by path at `InnerLoadUIFormAsync`; sub-assets within the package are uniformly handed over to `FairyGUILoadAsyncResourceHelper`, which implements `IAsyncResource`, and are loaded via `AssetComponent.LoadAssetAsync` / `LoadAllAssetsAsync`. Therefore, switching the loading method does not require replacing any helper code.
