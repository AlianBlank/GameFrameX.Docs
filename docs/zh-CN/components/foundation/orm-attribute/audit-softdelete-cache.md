# 如何为实体打审计/软删除/缓存特性

通过 `AuditTableAttribute`、`SoftDeleteAttribute`、`CacheTableAttribute` 三个特性，可以在实体类上一行声明启用 ORM 的审计跟踪、软删除和查询缓存能力，无需改动业务代码即可被 ORM 框架识别。

## 前置条件

- 项目引用 `GameFrameX.Foundation.Orm.Attribute` 程序集（包含三个特性类），以及 `GameFrameX.Foundation.Orm.Entity`（包含 `IAuditableEntity` 接口）。
- 实体类使用 `GameFrameX.Foundation.Orm.Attribute` 命名空间下的特性，文件中 `using GameFrameX.Foundation.Orm.Attribute;`。
- 若要获得自动填充的"创建/更新时间/操作人"字段，让实体实现 `IAuditableEntity` 接口（在 `GameFrameX.Foundation.Orm.Entity` 命名空间下）。

## 操作步骤

### 1. 启用审计跟踪

把 `[AuditTable]` 打在实体类上即可。默认 `Enabled = true`、`AuditLevel = ChangesOnly`、`IncludeUserInfo = true`，会记录 INSERT/UPDATE/DELETE 的变更历史。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[AuditTable(AuditLevel = AuditLevel.Full, IncludeUserInfo = true, IncludeIpAddress = true)]
public class UserAccount
{
    public int Id { get; set; }
    public string Username { get; set; }
    public decimal Balance { get; set; }
    public DateTime LastLoginTime { get; set; }
}
```

Source: [AuditTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/AuditTableAttribute.cs#L74-L143)

如需自定义审计表名，把 `AuditTableName` 设为具体表名；如需关闭审计，把 `Enabled` 设为 `false`。

### 2. 启用软删除

构造器至少传入"软删除标记字段"，并按需传入"删除时间字段"和"删除用户字段"。默认 `AutoFilter = true`，查询时会自动排除已删除记录。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[SoftDelete("IsDeleted", "DeletedTime", "DeletedBy")]
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }
    public string? DeletedBy { get; set; }
}
```

Source: [SoftDeleteAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SoftDeleteAttribute.cs#L74-L175)

如果标记字段不是 `bool`，可在属性中自定义 `DeletedValue` 与 `NotDeletedValue`，例如用字符串 `"DELETED"` / `"ACTIVE"` 标识状态。

### 3. 启用查询缓存

把 `[CacheTable]` 打在实体类上，ORM 框架会按 `CacheType` + `ExpireMinutes` 启用对应的缓存策略。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[CacheTable(CacheType = "Redis", ExpireMinutes = 30, KeyPrefix = "ProductInfo:")]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public DateTime LastModified { get; set; }
}
```

Source: [CacheTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/CacheTableAttribute.cs#L74-L137)

### 4. 组合使用：审计 + 软删除 + 可审计字段

让实体同时实现 `IAuditableEntity`，ORM 在写入时会自动维护 `CreateTime`、`UpdateTime`、`CreateUserId/Name`、`UpdateUserId/Name` 字段，与 `[AuditTable]` 配合形成完整的审计闭环。

```csharp
using GameFrameX.Foundation.Orm.Attribute;
using GameFrameX.Foundation.Orm.Entity;

[AuditTable(AuditLevel = AuditLevel.ChangesOnly)]
[SoftDelete("IsDeleted", "DeletedTime")]
[CacheTable(CacheType = "Memory", ExpireMinutes = 10)]
public class OrderInfo : IAuditableEntity
{
    public int Id { get; set; }
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }

    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }

    public DateTime? CreateTime { get; set; }
    public DateTime? UpdateTime { get; set; }
    public long? CreateUserId { get; set; }
    public string? CreateUserName { get; set; }
    public long? UpdateUserId { get; set; }
    public string? UpdateUserName { get; set; }
}
```

## 常见变体

- **仅审计字段、不记录用户**：将 `IncludeUserInfo` 置为 `false`，避免在不需要追溯到人的场景下存储冗余字段。
- **关闭查询自动过滤**：软删除场景下需要看到全部数据（含已删除）时，把 `AutoFilter` 设为 `false`，由调用方自行加 `WHERE`。
- **字符串状态字段做软删除**：把 `DeletedValue` / `NotDeletedValue` 改成 `"DELETED"` / `"ACTIVE"`，适配状态机式字段。
- **多缓存后端并存**：不同实体选用不同 `CacheType`（如热数据用 `Memory`，跨进程共享用 `Redis`），通过 `KeyPrefix` 防止键冲突。
- **运行时临时关闭**：在单元测试或迁移脚本中，把对应特性的 `Enabled` 设为 `false`，即可禁用当前实体的审计/缓存。

## 常见错误

- **漏写 `DeletedField` 构造参数**：三个 `SoftDeleteAttribute` 构造器都把 `deletedField` 标记为必填，传 `null` 会直接抛出 `ArgumentNullException`。务必传入一个有效的列名。
- **标记字段类型与 `DeletedValue` 不一致**：默认 `DeletedValue = true`、`NotDeletedValue = false`，如果标记字段是 `string` 或 `int`，必须显式指定字符串/整型值，否则 ORM 生成的 SQL 会报类型转换错误。
- **多个特性重复叠加在同一类上**：三个特性都设置了 `AllowMultiple = false`，对同一个实体重复打标会触发编译错误；如需不同行为，请用属性参数区分。
- **缓存键冲突**：未设置 `KeyPrefix` 时，多个实体共用默认前缀会导致键碰撞，命中率下降。建议按实体名设置 `"{EntityName}:"` 前缀。
- **把审计当成备份**：审计只记录变更历史，不会保存删除前的完整快照；如需"还原任意时刻数据"的能力，请同时配合软删除或自定义快照机制。

## 背景（可选）

三个特性都通过 `AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = true)` 标注，意味着只能贴在类上、每个类只能打一个，且会被派生类继承。ORM 在实体注册阶段通过反射读取这些特性，决定是否生成审计拦截器、是否在 `WHERE` 中追加软删除条件、是否走缓存通道；`IAuditableEntity` 接口里的字段则用于让 ORM 自动写入审计所需的上下文信息。
