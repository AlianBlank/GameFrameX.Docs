# 快速入門

使用 GameFrameX Setting,只需幾分鐘即可為 Unity 專案導入帶型別的鍵值儲存區。安裝後，將 `SettingComponent` 放置到場景中，呼叫 `SetXxx` / `GetXxx` 即可讀寫 `bool` / `int` / `float` / `string` 以及可序列化物件。

## 前置條件

- Unity 2019.4 或更新版本。
- 相依套件 `com.gameframex.unity` 1.1.1。會隨套件自動解析。
- 場景中必須存在 `GameFramework` 入口(執行階段會透過 `GameFrameworkEntry.GetModule<ISettingManager>()` 取得管理器)。

## 安裝

請選擇以下任一方式安裝到 Unity 專案：

1. 編輯 `Packages/manifest.json`,加入 scopedRegistries:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.setting": "1.5.2"
     }
   }
   ```

2. 直接在 `manifest.json` 的 `dependencies` 中加入 Git 相依性：

   ```json
   {
     "com.gameframex.unity.setting": "https://github.com/gameframex/com.gameframex.unity.setting.git"
   }
   ```

3. 在 Unity 的 `Package Manager` 中使用 **Add package from git URL**,貼上上述 Git 位址。
4. 將儲存庫直接放入 Unity 專案的 `Packages` 目錄，Unity 會自動辨識。

## 操作步驟

### 1. 在場景中加入 SettingComponent

建立一個空的 GameObject,並加入元件 **GameFrameX/Setting**(`SettingComponent`)。元件會在 `Awake` 中自動建立 `SettingManager`,並載入持久化資料。

元件預設附帶 `GameFrameXSettingCroppingHelper`,並由 `[RequireComponent]` 使其成為必要元件。

來源： [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L43-L99)

### 2. 選擇儲存後端

`SettingComponent` 的兩個欄位決定儲存後端：

| Inspector 欄位 | 用途 | 預設值 |
|------|------|--------|
| `Setting Helper Type Name` | 透過反射以型別完整名稱建立 `ISettingHelper` | `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` |
| `Custom Setting Helper` | 將 `SettingHelperBase` 的子類別直接拖曳至場景 | `null` |

可用的內建後端：

- `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`(預設)— Unity PlayerPrefs。支援抖音、微信、快手、支付寶小遊戲 SDK。
- `GameFrameX.Setting.Runtime.DefaultSettingHelper` — 基於 `Application.persistentDataPath` 的二進位檔案儲存。

切換方式：在 Inspector 中變更 `Setting Helper Type Name` 欄位，或在 `Custom Setting Helper` 指定您自己的實作。

來源： [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L54)

### 3. 寫入與讀取設定

透過 `SettingComponent` 提供的帶型別 API 操作設定。當索引鍵不存在或資料損毀時，`GetXxx` 會回傳傳入的預設值並輸出警告(不會拋出例外)。

```csharp
using GameFrameX.Setting.Runtime;

SettingComponent setting = /* 從 GetComponent 或 GameFramework 入口取得 */;

// 寫入設定
setting.SetBool("FullScreen", true);
setting.SetInt("ResolutionWidth", 1920);
setting.SetFloat("Volume", 0.8f);
setting.SetString("PlayerName", "PlayerOne");

// 讀取設定(含回退至預設值)
float volume = setting.GetFloat("Volume", 0.5f);

// 確認索引鍵是否存在
if (setting.HasSetting("PlayerName"))
{
    string name = setting.GetString("PlayerName");
}
```

來源： [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs) · [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L43-L73)

### 4. 持久化與刪除

變更預設僅在記憶體中生效，呼叫 `Save()` 之後才會寫入磁碟。刪除操作同時支援單一索引鍵與全部清除。

```csharp
// 持久化到儲存區
setting.Save();

// 刪除單一索引鍵
setting.RemoveSetting("PlayerName");

// 清除所有設定
setting.RemoveAllSettings();
```

來源： [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

## 常見變化用法

- **儲存可序列化物件** — `SetObject<T>(string, T)` / `GetObject<T>(string)` 內部使用 JSON 序列化，最適合存檔資料與設定結構。
- **手動載入** — 在應用程式啟動後呼叫 `setting.Load()`,從儲存位置重新載入所有設定。
- **取得所有索引鍵名稱** — `setting.GetAllSettingNames()` 會回傳目前記憶體中所有設定索引鍵的字串陣列(注意：PlayerPrefs 後端不支援此功能)。
- **小遊戲平台** — 在抖音、微信、快手、支付寶小遊戲的建置中，PlayerPrefs 後端會自動路由至平台 SDK 的儲存區。`DefaultSettingHelper` 則持續使用 `Application.persistentDataPath` 的檔案 I/O,在所有平台上保持一致。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|----------|
| 啟動後的日誌輸出 `Setting manager is invalid.` | 場景中沒有 `GameFramework` 入口，或入口未在 `SettingComponent` 之前完成初始化 | 在 `GameFramework` 初始化完成後，再啟用包含 `SettingComponent` 的場景 |
| `Log.Fatal` 之後設定無法運作 | 在 `Awake` 階段取得 `ISettingManager` 失敗 | 確認 `GameFramework` 的元件鏈是否完整 |
| 修改後重新啟動遊戲時資料遺失 | 寫入記憶體後未呼叫 `Save()` | 在應用程式結束前或關鍵時機明確呼叫 `setting.Save()` |
| 自訂 Helper 無法運作 | `Setting Helper Type Name` 與實際型別完整名稱不一致，或同時設定了 `Custom Setting Helper` | 優先順序:`Custom Setting Helper` > `Setting Helper Type Name`。請僅選擇其中之一 |
| 在不同語言環境中浮點數讀取值異常 | `SetFloat` 以 `CultureInfo.InvariantCulture` 寫入，但讀取端已在地化 | 一律使用 `GetFloat`,不要自行反序列化底層字串 |

## 背景(可選)

`SettingComponent` 是 `GameFrameworkComponent` 的子類別，會在 `Awake` 階段使用 `GameFrameworkEntry.GetModule<ISettingManager>()` 取得 `SettingManager`,並以反射或自訂欄位建立 `ISettingHelper` 並注入。`SettingManager` 會對所有 `SetXxx` / `GetXxx` 呼叫進行索引鍵名稱驗證，對空索引鍵會拋出 `GameFrameworkException("Setting name is invalid.")`。當資料損毀時，會使用 `TryParse` 回退至預設值並輸出 `Log.Warning`,確保執行不會中斷。
