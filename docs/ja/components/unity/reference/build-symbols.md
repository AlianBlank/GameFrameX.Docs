# ビルドマクロと条件コンパイルシンボルの説明

このページでは、GameFrameX フレームワークがソースコード、Assembly Definition、Unity Player Settings で実際に使用している**ビルドマクロ / 条件コンパイルシンボル**を集約し、各シンボルの有効プラットフォーム、定義位置、プロジェクトでの有効化または検出方法について説明します。

> `UNITY_` プレフィックスを持つシンボルは Unity エンジンによって自動的に注入されます。フレームワーク独自のシンボル(例: `ENABLE_GAME_FRAME_X_HYBRID_CLR`)は `asmdef` の `versionDefines` を通じて自動的に注入されます。

## シンボル早見表

| シンボル | スコープ | 定義元 | 用途 |
|------|--------|----------|------|
| `UNITY_EDITOR` | Editor アセンブリ | Unity 自動注入 | エディタでのみ有効なコードブロック |
| `UNITY_ANDROID` | Android プラットフォーム | Unity 自動注入 | Android プラットフォーム特化ロジック |
| `UNITY_IOS` | iOS プラットフォーム | Unity 自動注入 | iOS プラットフォーム特化ロジック |
| `UNITY_STANDALONE` | スタンドアロンプラットフォーム(Win/Mac/Linux) | Unity 自動注入 | デスクトップ特化ロジック |
| `UNITY_2018_1_OR_NEWER` | バージョン検出 | Unity 自動注入 | バージョン互換分岐 |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` | HybridCLR ホットアップデートを有効化するアセンブリ | `versionDefines`(`com.code-philosophy.hybridclr` パッケージを検出) | HybridCLR 統合に関連するコードパスの制御 |

> Unity の完全なプラットフォーム/バージョンマクロ一覧については、Unity 公式ドキュメントを参照してください(ランタイムシンボルはソースコードには現れませんが、コンパイラによって自動的に認識されます)。

## フレームワーク独自シンボル:ENABLE_GAME_FRAME_X_HYBRID_CLR

このシンボルは、フレームワークレベルで現在**唯一**、`asmdef` の `versionDefines` を介して注入されるカスタムマクロです。プロジェクトに `com.code-philosophy.hybridclr` パッケージがインストールされている場合、Unity は自動的に `GameFrameX.Startup.Application` アセンブリにこのマクロを注入し、HybridCLR ホットアップデートに関連するコードパスを有効化します。

```json
{
    "name": "GameFrameX.Startup.Application",
    "references": [
        "GameFrameX.Runtime",
        "HybridCLR.Runtime",
        "HybridCLRData"
    ],
    "versionDefines": [
        {
            "name": "com.code-philosophy.hybridclr",
            "expression": "",
            "define": "ENABLE_GAME_FRAME_X_HYBRID_CLR"
        }
    ]
}
```

Source: [Unity.Startup.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Unity.Startup.asmdef#L33-L39)

### 使用例

```csharp
using UnityEngine;

namespace GameFrameX
{
    public static class HotUpdateGate
    {
        public static bool IsHotUpdateSupported
        {
            get
            {
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
                return true;
#else
                return false;
#endif
            }
        }
    }
}
```

### マクロが有効かどうかの検証

Unity でメニュー **Window → General → Test Runner** を実行するか、任意のスクリプトでリフレクションを使用して読み取ります:

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
    Debug.Log("HybridCLR は有効です。ホットアップデートコードはホットアップデートアセンブリに入ります。");
#else
    Debug.LogWarning("HybridCLR は有効ではありません。Startup は AOT 方式で実行されます。");
#endif
```

*HybridCLR は有効です* というメッセージが出力されれば、`ENABLE_GAME_FRAME_X_HYBRID_CLR` が正常に注入されたことを意味します。

## プラットフォームマクロの実際の使用方法

### Android プラットフォーム特化設定

`ProjectSettingEditor.cs` は Android プラットフォームでセーフエリア制限を無効化し、チーム ID のプレースホルダーを書き込みます。Android 以外のプラットフォームでは、この分岐はコンパイラによって除外されます。

```csharp
public override void OnInspectorGUI()
{
    base.OnInspectorGUI();
    PlayerSettings.assemblyVersionValidation = false;
#if UNITY_ANDROID
    PlayerSettings.Android.renderOutsideSafeArea = true;
#endif
#if UNITY_IOS
    PlayerSettings.iOS.appleDeveloperTeamID = "XXXXXX";
#endif
}
```

Source: [ProjectSettingEditor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/ProjectSettingEditor/ProjectSettingEditor.cs#L28-L52)

### バージョン互換分岐

`AutoCopySymbolsPostprocessor.cs` は `UNITY_2018_1_OR_NEWER` を使用して 32 ビット x86 アーキテクチャ処理ロジックを遮蔽します(Unity 2018.1 以降、Android x86 ビルドはサポートされていません)。

```csharp
#if UNITY_2018_1_OR_NEWER

#else
    if ((PlayerSettings.Android.targetArchitectures & AndroidArchitecture.X86) > 0)
    {
        var dir = CopySymbols(symbolsDir, abi_x86);
        GenerateAllSymbols(dir);
    }
#endif
```

Source: [AutoCopySymbolsPostprocessor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/AutoCopySymbolsPostprocessor.cs#L46-L54)

## プラットフォームレベルアセンブリ分離

`includePlatforms` / `excludePlatforms` は、対応するプラットフォームビルドにアセンブリ が参加するかどうかを制御するもので、**追加のマクロは必要ありません**。

| アセンブリ | includePlatforms | 効果 |
|--------|------------------|------|
| `Unity.Editor` | `["Editor"]` | エディタビルドのみ。プレイヤーパッケージには含まれない |
| `Unity.Startup` / `Unity.HotFix` / `HybridCLRData` | `[]`(すべて) | すべてのプラットフォームビルドに参加 |

Source: [Unity.Editor.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/Unity.Editor.asmdef#L11-L13)

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| Android デバイスで x86 lib ファイルが残っている | 時代遅れの `UNITY_2018_1_OR_NEWER` 以前のパスが有効になっている | Unity を 2018.1 以上にアップグレードし、マクロが x86 処理を正しく除外するようにする |
| HotFix アセンブリ がビルドに参加していない | `UNITY_HOTFIX` などの古いマクロが誤って使用されている | 最新の HybridCLR が注入する `ENABLE_GAME_FRAME_X_HYBRID_CLR` または `includePlatforms` 設定を使用する |
| プレイヤーパッケージに Editor ツールコードが含まれている | `Unity.Editor` アセンブリ の `includePlatforms` が `Editor` に設定されていない | `.asmdef` で明示的に `"includePlatforms": ["Editor"]` を宣言する |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` が常に未定義 | HybridCLR パッケージがインストールされていない、またはパッケージ名が間違っている | Package Manager で `com.code-philosophy.hybridclr` がインストールされていることを確認し、`asmdef` の `versionDefines.name` のスペルが一致しているか確認する |

## カスタムビルド宏の追加

1. 対応する `.asmdef` を開き、ルートレベルに `defineConstraints` または `versionDefines` を追加します(パッケージマネージャ管理用)。
2. グローバルに有効にする必要がある場合(パッケージマネージャ管理外)は、**Edit → Project Settings → Player → Other Settings → Scripting Define Symbols** を使用します。
3. C# コードでは、標準の `#if SYMBOL_NAME ... #endif` 構文を使用して参照します。Unity はビルド時に現在のターゲットプラットフォームに従って一致しない分岐を自動的に除外します。
