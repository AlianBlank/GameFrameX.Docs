# Managing Download Tasks in Groups with Tags

By passing a `tag` string to `AddDownload`, you can group download tasks of the same kind together, then use `GetDownloadInfos(tag)` to retrieve the status of all tasks in that group at once. This page explains how to tag tasks, how to query by tag, and common errors.

## Prerequisites

- The `com.gameframex.unity.download` package is installed, and a `DownloadComponent` has been added to the scene.
- You have obtained a `DownloadComponent` reference, e.g. `GameEntry.GetComponent<DownloadComponent>()`.
- You are familiar with the basic usage of `AddDownload` (see the `AddDownload(string, string)` overload in the component).

## Steps

### 1. Tag a Download Task

Call the `AddDownload` overload that takes a `tag` parameter. A tag is just an ordinary string; you define its semantics yourself, for example `"asset-bundle"`, `"lua-3.2.0"`, `"res-avatar"`.

```csharp
// Specify only the tag, using default priority and null userData
int id1 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/a.png",
    downloadUri:  "https://example.com/a.png",
    tag:          "asset-bundle");

// Specify tag + priority
int id2 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/b.png",
    downloadUri:  "https://example.com/b.png",
    tag:          "asset-bundle",
    priority:     10);

// Specify tag + priority + userData (full version)
int id3 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/c.png",
    downloadUri:  "https://example.com/c.png",
    tag:          "asset-bundle",
    priority:     10,
    userData:     myCallback);
```

### 2. Query All Tasks in a Group by Tag at Once

Use `GetDownloadInfos(string tag)` to get the `TaskInfo[]` for that group, or use `GetDownloadInfos(string tag, List<TaskInfo> results)` to reuse an existing list and avoid GC.

```csharp
// Returns TaskInfo[]
TaskInfo[] infos = downloadComponent.GetDownloadInfos("asset-bundle");
foreach (var info in infos)
{
    Debug.Log($"tag={info.Tag} status={info.Status} progress={info.Progress}");
}

// Reuse the List to avoid allocating a new array every frame
var buffer = new List<TaskInfo>();
downloadComponent.GetDownloadInfos("asset-bundle", buffer);
```

### 3. Aggregate Progress by Tag

Treat the tag as a "batch" dimension and display overall batch progress in the UI:

```csharp
void Update()
{
    var infos = downloadComponent.GetDownloadInfos("asset-bundle");
    if (infos.Length == 0) return;

    long downloaded = 0, total = 0;
    foreach (var info in infos)
    {
        downloaded += info.DownloadedLength;
        total      += info.TotalLength;
    }
    progressBar.value = total > 0 ? (float)downloaded / total : 0f;
}
```

> The fields of `TaskInfo` (`Status`, `Progress`, `DownloadedLength`, `TotalLength`, `Tag`, `SerialId`, etc.) are updated by `DownloadManager` over the task's lifecycle.

### 4. View Tags in the Editor Inspector

Open the Inspector for `DownloadComponent`; in the "Download Infos" list you can directly see the `Tag` column, which you can use to verify that tasks have been assigned to the expected group.

## Common Variants

| Scenario | Usage |
|------|------|
| Same batch of assets with different priorities | Use the same `tag` with different `priority` values; they can be queried together and scheduled separately |
| Asset version number as the Tag | For example, `tag = "v1.2.3"` makes it easy to upgrade whole batches by version |
| Cancel an entire batch of tasks | Extract the `SerialId` from the `TaskInfo[]` and call `RemoveDownload(serialId)` one by one |
| Carry callback context | Use the `userData` parameter to attach a callback to the task, while the Tag still categorizes by business logic |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GetDownloadInfos(tag)` always returns empty | The Tag was not passed when adding the task, or the Tag string is inconsistent (case, whitespace) | Make sure `AddDownload` uses the overload with `tag`, and store the Tag as a constant |
| The same file is downloaded repeatedly under multiple Tags | Different Tags are independent tasks; the framework does not deduplicate automatically | Use a global dictionary to deduplicate by `downloadUri`, or consistently use a single Tag |
| Calling `AddDownload` throws `Download path is invalid.` / `Download uri is invalid.` | `downloadPath` or `downloadUri` is an empty string or null | Check for null/empty before calling; the Tag does not affect the validation of these two parameters |

## Background (Optional)

Internally, `DownloadTask` stores the tag as `TaskBase.Tag` (a string field); `m_TaskPool` maintains task collections by tag, and `GetDownloadInfos(tag)` actually delegates to `m_TaskPool.GetTaskInfos(tag)`. The tag is used only for "grouping + querying" and does not affect download priority, concurrency, or retry-on-failure strategy — those behaviors are determined by `priority` and the global parameters of `DownloadComponent`.
