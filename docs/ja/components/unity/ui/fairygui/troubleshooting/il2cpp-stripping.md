# IL2CPP ビルド後に UI コードがストリッピングされた場合の対処方法

Unity は IL2CPP でビルドを行う際に Managed Code Stripping（マネージコードのストリッピング）を実行し、「静的に参照されていないように見える」型やメソッドを削除します。本パッケージの FairyGUI ヘルパー（`FairyGUIFormHelper`、`FairyGUILoadAsyncResourceHelper` など）は、主に GameFrameX UI フレームワークから実行時に間接的に呼び出されるため、まさに誤ってストリッピングされやすい対象です——エディターではすべて正常に動作するのに、実機では UI が開けない、またはヘルパーのインスタンス化時に例外がスローされるといった事態が発生します。本パッケージは `[UnityEngine.Scripting.Preserve]` 属性による全面的なストリッピング防止措置をすでに講じており、それでも問題が発生する場合は、通常、ストリッピングレベルの設定が高すぎるか、プロジェクト独自の UI コードに保護がないことが原因です。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| エディターでは正常だが、IL2CPP 実機ビルド後に UI を開けない、UI フォームヘルパーまたは非同期リソースヘルパーのインスタンス化でエラーが発生する | `Managed Stripping Level` の設定が高すぎて、フレームワークが間接的に呼び出すヘルパー型がストリッピングされた | 下記の[ステップ 1](#1-确认本包版本与-preserve-标注) と[ステップ 2](#2-降低-managed-stripping-level) を参照 |
| パッケージ内の型/メンバーがストリッピングされているが、旧バージョンのパッケージを使用している | 旧バージョンでは全メンバーへの `[UnityEngine.Scripting.Preserve]` 属性の付与が不完全な可能性がある | 本パッケージをアップグレードする（現在のバージョンは [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/package.json#L6) を参照）。ステップ 1 を参照 |
| プロジェクトで独自に定義した FairyGUI 拡張コンポーネント（`GComponent`/`GObject` を継承した独自クラス）が実機で失われる | プロジェクト独自のコードがストリッピング対策を行っておらず、本パッケージとは無関係 | 独自クラスに `[UnityEngine.Scripting.Preserve]` を付与するか、プロジェクトレベルの `link.xml` を追加する。ステップ 3 を参照 |

## 修正手順

### 1. 本パッケージのバージョンと Preserve 属性の確認

本パッケージでは、クラス、フィールド、プロパティ、メソッドのすべてのレベルに `[UnityEngine.Scripting.Preserve]` 属性が付与されています。公式の説明は「**IL2CPP セーフ** — Preserve 属性は IL2CPP ビルド時のコードストリッピングを防止します」（[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L38) を参照）。

クラスレベルとメンバーレベルの属性の実際の記述は以下の通りです。ローカルのパッケージ内のファイルと照合して確認できます：

```csharp
[UnityEngine.Scripting.Preserve]
internal sealed class FairyGUILoadAsyncResourceHelper : IAsyncResource
{
    [UnityEngine.Scripting.Preserve]
    private readonly Dictionary<string, UIPackageData> m_UIPackages = new Dictionary<string, UIPackageData>(32);
```

パッケージ内のファイルにこれらの属性が不足している場合は、まず Package Manager で本パッケージをアップグレードしてから再ビルドしてください。

### 2. Managed Stripping Level を下げる

`[Preserve]` が保護できるのは「属性が付与されたメンバー」だけです。プロジェクト全体のストリッピングレベルが高すぎる場合、エッジケースでストリッピングが発生する可能性が依然としてあります。以下の順序で調整してください：

1. `Edit → Project Settings → Player → Other Settings` を開きます。
2. `Managed Stripping Level`（IL2CPP の場合）を `High`/`Medium` から `Low` または `Minimal` に下げます。
3. IL2CPP で実機パッケージを再ビルドして検証します。

パッケージサイズの都合上、高いストリッピングレベルを維持する必要がある場合は、ステップ 3 を実行して `link.xml` でアセンブリ全体を保持してください。

### 3. プロジェクト独自コードへのストリッピング防止策の追加（またはアセンブリ全体用の link.xml）

本リポジトリには `link.xml` は**含まれていません**（ストリッピング防止は完全に `[UnityEngine.Scripting.Preserve]` に依存しています）。そのため、プロジェクト独自のコードは自前で保護する必要があります。以下の 2 つの方法のいずれかを選択してください：

- **属性方式（推奨、本パッケージの手法と同じ）**：カスタマイズした FairyGUI 拡張コンポーネントや、リフレクションで呼び出されるフォームロジッククラスに 1 つずつ属性を付与します：

```csharp
[UnityEngine.Scripting.Preserve]
public class MyCustomPanel : GComponent
{
}
```

- **link.xml 方式**：`Assets` 配下の任意の場所（例：`Assets/link.xml`）でアセンブリ全体を保持します。これは自分で作成する必要があるプロジェクトファイルであり、本パッケージには既製のものは含まれていない点に注意してください：

```xml
<linker>
  <assembly fullname="Your.GameAssembly" preserve="all"/>
</linker>
```

### 4. FairyGUI エクステンダーのリフレクション登録チェーンの確認

本パッケージはリフレクションによってアセンブリ内の UI ヘルパー実装を取得しており、このチェーンはストリッピング後に最も切れやすくなります。以下のクラスがビルド成果物に存在することを確認してください（ビルドログまたは `{プロジェクト}_BackUpThisFolder_ButDontShipItWithYourGame` 内のシンボルファイル）：

- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUIUIGroupHelper`
- `GameFrameX.UI.FairyGUI.Runtime.FairyGUILoadAsyncResourceHelper`（internal クラス。インターフェース `IAsyncResource` を介して間接的に呼び出されるため、最もストリッピングされやすい）

## 検証

1. IL2CPP で実機パッケージをビルドします（Android/iOS のどちらでも可）。Mono モードでは再検証しないでください。
2. 実機で、異なる UI グループに依存する画面を順番に開き、以下を確認します：画面が正常に作成されること（`UIPackage.CreateObject` パス）、非同期読み込みされる UI パッケージ（YooAsset パス）が正常に `LoadResource` をコールバックできること、`TypeLoadException`/`NullReferenceException` などのヘルパーインスタンス化関連の例外が発生しないこと。
3. 任意：ビルドログで `Stripping` 関連の警告を検索し、`GameFrameX.UI.FairyGUI.Runtime` アセンブリがストリッピング対象として報告されていないことを確認します。

## 背景

本パッケージのヘルパーはビジネスコードから直接 new されるものではなく、GameFrameX UI フレームワークによって実行時にインターフェースとリフレクションを介してインスタンス化されます。静的解析では参照が見えないため、IL2CPP がそれを「未使用」と判定してストリッピングする可能性があります。`[UnityEngine.Scripting.Preserve]` はストリッパーに対して「このメンバーとその参照先を保持する」ことを宣言します。本パッケージはクラス、フィールドからメソッドに至るまで完全にカバーしており（[FairyGUILoadAsyncResourceHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUILoadAsyncResourceHelper.cs#L47) と [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L53) を参照）、そのため通常、本パッケージのために追加のストリッピング防止設定を記述する必要はありません。
