# Implementing Account Login (Account / Login Flow)

This page walks you through wiring up the client-initiated account login message, completing the minimal loop from `ReqPlayerLogin` to persisting character data. Once complete, the client will receive `RespPlayerLogin` and enter the game business logic.

## Prerequisites

- The `GameFrameX.Server` gateway and central server are deployed, and the Actor type `ActorTypeServer` is available.
- The `PlayerState` table exists in the database, with `Id` as the primary key field (the login message looks up by `Id`).
- The client can send the `ReqPlayerLogin` message and receive `RespPlayerLogin`.
- The following namespaces are referenced: `GameFrameX.Apps.Account.Login.Component`, `GameFrameX.Apps.Account.Login.Entity`, `GameFrameX.Apps.Player.Player.Entity`, `GameFrameX.Monitor.Player`.

   {
       MetricsPlayerHelper.LoginCounterOptions.Inc();
       return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
   }

3. **Write the Agent to complete binding and forwarding**. `LoginComponentAgent.OnPlayerLogin` is responsible for: calling the component to look up the player, writing the player's `Id` into the `NetWorkChannel` (key name `GlobalConst.ActorIdKey`), then obtaining the `PlayerComponentAgent` on the player's Actor via `ActorManager`, and handing the login off to the actual player component.

   ```csharp
   public async Task OnPlayerLogin(INetWorkChannel workChannel, ReqPlayerLogin reqLogin, RespPlayerLogin response)
   {
       var playerState = await OwnerComponent.OnPlayerLogin(reqLogin);
       if (playerState == null)
       {
           // Character not found?
           return;
       }

       // Bind player ID
       workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id);
       var playerComponentAgent = await ActorManager.GetComponentAgent<PlayerComponentAgent>(playerState.Id);
       await playerComponentAgent.OnPlayerLogin(workChannel, playerState, response);
   }
   ```

   internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
   {

- **Disabled sample code**: `GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs` is currently commented out entirely with `/* … */` and serves as a reference for the legacy `ReqLogin` implementation; use the `ReqPlayerLogin` chain for actual integration.

## Common Errors

- **Returning directly when `playerState == null`**: In this case, `response` is never assigned, and the client will keep waiting or time out. Make sure to write an error code into `response` in the Agent according to your business protocol, or throw an explicit exception.
- **Forgetting `workChannel.SetData(GlobalConst.ActorIdKey, playerState.Id)`**: Subsequent messages cannot be routed to the player's Actor, and the player will not receive business pushes.
- **`IsCreateDefaultState = false` combined with a missing `PlayerState`**: When a player logs in for the first time and there is no record in the database, you need to create the `PlayerState` in `OnPlayerLogin` first; otherwise it will always return `null`.

## Background (Optional)

- `LoginComponent` is marked with `ActorTypeServer`, indicating that the login logic runs on the central server Actor and is not coupled to any specific player Actor.
- `LoginComponentAgent` is a state component agent, responsible for converging cross-Actor messages into `LoginComponent`, then dispatching them to the corresponding `PlayerComponentAgent` by player ID.
