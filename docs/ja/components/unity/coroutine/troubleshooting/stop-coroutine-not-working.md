# `StopCoroutine` を呼び出したのにコルーチンが止まらない場合の対処法

`CoroutineComponent.StopCoroutine(...)` を呼び出しても、コルーチンが動き続けてしまい、シーンが閉じるか `StopAllCoroutines` が呼ばれるまでクリアされません。これは通常、渡した `IEnumerator` インスタンスが起動時に使ったものと異なる参照であるため、コンポーネント内部の追跡テーブルにヒットしないことが原因です。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `StopCoroutine(ienumerator)` 呼び出し後もコルーチンが動き続ける | 渡したものが起動時と同じ `IEnumerator` インスタンスでないため辞書で見つからず、`base.StopCoroutine` にフォールバックされるが、`base` パスはこのコルーチンを実際には追跡していない | `StartCoroutine` に渡した元の `IEnumerator` 参照を保持し、停止時に同じ変数を渡す |
| `StartCoroutine` が返した `UnityEngine.Coroutine` で停止しても無効 | ベースクラスの `MonoBehaviour.StopCoroutine` パスを呼び出しており、追跡テーブルから該当コルーチンが削除されない | `CoroutineComponent` インスタンスの `StopCoroutine(UnityEngine.Coroutine)` オーバーロードを呼ぶように変更 |
| `WaitForEndOfFrameFinish` のコールバックが停止後も発火する | `yield return WaitForEndOfFrame` が次のフレームに到達する前に停止しても、そのフレーム終了時にコールバックが実行される | コルーチンを停止する前に `callback` を null にするか、条件判定を使う |

## 修正手順

### ケース 1:`StopCoroutine(IEnumerator)` が効かない

`CoroutineComponent` は `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` で起動したすべてのコルーチンを追跡しており、key は `IEnumerator` 参照です。辞書がヒットしない場合、ソースコードは `base.StopCoroutine(enumerator)` 分岐にフォールバックします:

```csharp
public new void StopCoroutine(IEnumerator enumerator)
{
    if (m_CoroutineMap.TryGetValue(enumerator, out var coroutine))
    {
        base.StopCoroutine(coroutine);
        m_CoroutineMap.TryRemove(enumerator, out _);
    }
    else
    {
        base.StopCoroutine(enumerator);
    }
}
```

出典: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

解決方法:起動時に渡した `IEnumerator` をフィールドに保存し、停止時に同じ参照を渡します。

```csharp
private IEnumerator _runningRoutine;

void Start()
{
    _runningRoutine = MyRoutine();
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StartCoroutine(_runningRoutine);
}

void StopMyRoutine()
{
    // 同じインスタンスを返す。_runningRoutine が辞書の key になる
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StopCoroutine(_runningRoutine);
}

IEnumerator MyRoutine()
{
    while (true) { yield return null; }
}
```

### ケース 2:`UnityEngine.Coroutine` オーバーロードでの停止が無効

`StartCoroutine` が返した `UnityEngine.Coroutine` を取得した場合は、必ず 2 つ目のオーバーロードを使う必要があります。ソースコードは辞書を走査して対応するエントリを見つけて削除します:

```csharp
public new void StopCoroutine(UnityEngine.Coroutine coroutine)
{
    base.StopCoroutine(coroutine);
    foreach (var item in m_CoroutineMap)
    {
        if (item.Value == coroutine)
        {
            m_CoroutineMap.TryRemove(item.Key, out _);
            break;
        }
    }
}
```

出典: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L56-L67)

よくある間違い:`Coroutine` 参照を最初のオーバーロード `StopCoroutine(IEnumerator)` に渡してしまうと、辞書で見つからず `else` 分岐に落ちてしまいます。

### ケース 3:すべてのコルーチンを一括クリア

すべてまとめて止めたい場合は、`StopAllCoroutines` オーバーロードを直接使ってください。コルーチンを 1 つずつ停止して辞書をクリアします:

```csharp
GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
    .StopAllCoroutines();
```

ソースコードはまず辞書を走査して 1 つずつ停止し、その後 `base.StopAllCoroutines()` を呼び出して追跡されていないコルーチンを処理します:

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

出典: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

## 検証

1. コルーチン内部に `Debug.Log` を仕掛けて周期的に出力し、`StopCoroutine` 呼び出し後 1 秒以内に新しいログが出ないことを確認する。
2. Unity Profiler の Memory パネルで `Coroutine` を確認し、バックグラウンドタスクが増加していないか確認する。
3. コルーチン内に `yield return new WaitForSeconds(...)` が含まれる場合、停止後にその `WaitForSeconds` のコールバックが完了しないことを確認する。
