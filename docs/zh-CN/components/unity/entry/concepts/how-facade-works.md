# 工作原理:门面层、条件编译与延迟加载

`GameApp` 是一个静态门面类,通过 C# `partial` 关键字把每个组件的访问入口拆分到独立的源文件中,再借助 `#if` 条件编译按需启用,最后用字段缓存实现延迟加载。

## 三种机制一览

| 机制 | 作用 | 实现位置 |
|------|------|----------|
| `partial class GameApp` | 把所有组件访问入口合并到同一个 `GameApp` 类 | [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53) |
| `#if ENABLE_GAME_FRAME_X_*` | 未启用某个模块时,对应的字段、属性、using 全部不进入编译 | [Runtime/GameApp.Advertisement.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Advertisement.cs#L32-L56) |
| 字段缓存 + `GetComponent<T>()` | 第一次访问时从 `GameEntry` 取组件,后续直接返回缓存字段 | [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L39-L52) |

## 三步理解门面层

1. **入口统一**。所有模块都通过 `GameApp.<模块名>` 这个静态属性访问,业务代码不需要持有 `GameEntry` 引用,也无需关心组件生命周期。
2. **编译期裁剪**。每个模块(广告、登录、热更新、网络等)对应一个独立的 `GameApp.<模块名>.cs` 文件,文件首尾用 `#if ENABLE_GAME_FRAME_X_<MODULE>` / `#endif` 包起来。未定义宏时,整个文件不参与编译,既不占体积,也不会引入对模块包的依赖。
3. **运行期懒加载**。静态属性内部的 `if (_xxx == null)` 判断保证 `GameEntry.GetComponent<T>()` 只在第一次访问时执行,之后直接返回缓存字段,避免重复查找。

## 典型代码片段

`GameApp.Base` 是门面层的最小可用示例,只暴露属性和私有缓存字段:

```csharp
public static partial class GameApp
{
    /// <summary>
    /// 获取游戏基础组件。
    /// </summary>
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }

            return _base;
        }
    }

    private static BaseComponent _base;
}
```

Source: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

需要条件编译的模块(如广告)在外层加上 `#if` 守卫:

```csharp
#if ENABLE_GAME_FRAME_X_ADVERTISEMENT
using GameFrameX.Runtime;
using GameFrameX.Advertisement.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// 获取广告组件。
    /// </summary>
    public static AdvertisementComponent Advertisement
    {
        get
        {
            if (_advertisement == null)
            {
                _advertisement = GameEntry.GetComponent<AdvertisementComponent>();
            }

            return _advertisement;
        }
    }

    private static AdvertisementComponent _advertisement;
}
#endif
```

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 访问 `GameApp.Advertisement` 报“找不到类型” | 没在 Player Settings / asmdef 中定义 `ENABLE_GAME_FRAME_X_ADVERTISEMENT` | 启用对应模块包并定义宏,或在 `scriptingDefineSymbols` 中加入 |
| 启用宏后仍报缺失 using | 模块包未安装 | 通过 NuGet/UPM 安装对应模块(如 `GameFrameX.Advertisement`) |
| `GetComponent<T>()` 返回 `null` | `GameEntry` 上未挂载目标组件 | 在 `GameEntry` 预制体上挂载对应 `Component` 子类,见《如何挂载与初始化组件》 |

## 背景(可选)

把每个模块的访问入口放进独立的 `partial` 文件,等价于“按模块拆分源代码、按宏控制是否进入编译、按需懒加载实例”。这种写法让框架本体足够精简,业务侧引哪个模块就启用哪个宏,不引用的模块既不会被编译也不会被打包,运行时只多一个静态属性 getter 的开销。
