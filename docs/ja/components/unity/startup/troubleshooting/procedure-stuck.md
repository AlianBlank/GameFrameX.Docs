# 起動フローが ProcedureLauncherState で止まる場合の対処法

`StartupRunner.RunAsync` がすでに起動チェーンを `ProcedureLauncherState` まで進めているにもかかわらず、UI が表示されず、フローが `ProcedureGetGlobalInfoState` に切り替わらない(起動全体の Promise が永遠に `Pending` のまま)場合、問題はほぼすべて FSM ブラックボードデータ、UI リソース、または `WebComponent` の初期化に起因します。このページでは、迅速な診断と対応する修正手順を示します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 起動後に画面が真っ暗になり、ログには `ProcedureLauncherState` に入ったことしか確認されず、`ChangeState<ProcedureGetGlobalInfoState>` が実行されない | `BlackBoardKeys.StartupOptions` または `BlackBoardKeys.StartupUIHandler` が null のため、`OnEnter` が早期に `return` する | 下記の「修正 1:FSM ブラックボードデータの欠落」を参照 |
| 起動 UI が一瞬だけ表示されて消える、またはまったく表示されず、起動ページで止まる | `IStartupUIHandler.StartAsync` が例外をスローまたはハングする | 下記の「修正 2:UI Handler の起動失敗」を参照 |
| 起動が Launcher 段階に達した時点でコンソールに `WebComponent` 関連の null 参照エラーが出る | `GameEntry.GetComponent<WebComponent>()` が `null` を返す。Web モジュールが未登録 | 下記の「修正 3:WebComponent が未登録」を参照 |
| フローが止まり、`OnEnter` に一度も入らない | `procedureManager.StartProcedure<ProcedureLauncherState>()` の前に FSM にデータが正しく注入されていない、または `StartupOptions.LauncherUIResName` のパスが誤っている | 下記の「修正 4:LauncherUIResName のリソースパス誤り」を参照 |
| 起動チェーンが Launcher までしか進まず、`UniTaskCompletionSource` が SetResult されない | 後続の Procedure が Launcher の後に `SetResult` を担当しており、Launcher 自身は状態を切り替えるだけ | 下記の「修正 5:後続 Procedure の完了を待つ」を参照 |

## 修正手順

### 修正 1:FSM ブラックボードデータの欠落

`ProcedureLauncherState.OnEnter` は FSM ブラックボードから `StartupOptions` と `IStartupUIHandler` を読み取りますが、どちらか一方でも `null` であればメソッドはそのまま `return` し、状態も切り替わらずエラーも出ません:

```csharp
// 出典: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var options = optionsBox.Value as StartupOptions;
var uiHandler = uiHandlerBox.Value as IStartupUIHandler;

if (options == null || uiHandler == null)
{
    return; // そのまま抜け、フローが止まり、例外は発生しない
}
```

`StartupRunner.RunAsync` が `StartProcedure<ProcedureLauncherState>` を呼び出す前に、確かに null でない `options` と `uiHandler` を渡していることを確認してください:

```csharp
// 出典: Runtime/Startup/StartupRunner.cs
procedureFsm.SetData(BlackBoardKeys.StartupOptions, optionsBox);
procedureFsm.SetData(BlackBoardKeys.StartupUIHandler, uiHandlerBox);
```

自分で起動チェーンを組み立てている場合(`StartupRunner` を使用していない場合)は、`StartProcedure<ProcedureLauncherState>()` を呼び出す前に同じ key でデータを注入する必要があります。[BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs) を参照してください。

### 修正 2:UI Handler の起動失敗

`OnEnter` は `await uiHandler.StartAsync(options.LauncherUIResName)` の箇所で実際に UI のロード完了を待機します。`IStartupUIHandler` の実装内で例外がスローされると、例外は `async void` に飲み込まれてフローが固まります。また、ハングした場合(例：Addressables リソースが準備できていない場合)も同様に次の状態へ切り替わりません。

切り分け手順:

1. カスタムの `IStartupUIHandler.StartAsync` の入口に `try/catch` を追加し、少なくとも例外をログに出力して、実際にスローされているか確認します。
2. Editor 上で一時的に `LauncherUIResName` を存在が確認済みの Prefab/Asset に向け、リソースパスの誤りを排除します。
3. `UniTaskCompletionSource` を使用している場合は、`StartAsync` 内部で `TrySetResult` されていること、および `await` を忘れていないことを確認します。

### 修正 3:WebComponent が未登録

`ProcedureLauncherState` は状態を切り替える前に `WebComponent` から Header を読み書きする必要があります。モジュールが登録されていない場合、`GameEntry.GetComponent<WebComponent>()` が `null` を返し、次の行の `webComponent.RemoveBaseHeader(...)` で即座に NRE が発生します:

```csharp
// 出典: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var webComponent = GameEntry.GetComponent<WebComponent>();
webComponent.RemoveBaseHeader(StartupProcedureUtility.GameFrameXApiKeyHeader);
// ...
```

`GameEntry` のモジュール登録フローにおいて `WebComponent` がコンポーネントテーブルに追加されていること、および実行時の呼び出し順序が `StartupRunner.RunAsync` の開始より前であることを確認してください。

### 修正 4:LauncherUIResName のリソースパス誤り

`options.LauncherUIResName` は有効な UI プレハブまたはリソースアドレスを指している必要があります。リソースが存在しない場合、大半の `IStartupUIHandler` 実装は「リソースのロード待ち」の無限ループに入り、自ら失敗することはありません。検証方法：

1. `StartupOptions` の構築時に `LauncherUIResName` をログに出力し、Addressables Groups / Resources ディレクトリ内の実際のキーと照合します。
2. まず `EPlayMode.EditorSimulateMode` + 存在が確認済みのリソースで起動フローを一通り実行し、ビルド/グルーピングの問題を排除します。

### 修正 5:後続 Procedure の完了を待つ

`ProcedureLauncherState` 自身の責務は「起動 UI をロード → 次の状態へ切り替え」だけであり、`UniTaskCompletionSource.SetResult` は呼び出しません。観測している「固まる」現象が、実際には `StartupRunner.RunAsync` が返す `UniTask<StartupResult>` がずっと `Pending` のままであることを指す場合は、`ProcedureGetGlobalInfoState` および後続の Procedure が最終的な成功/失敗時に `StartupProcedureUtility.GetCompletionSource(fsm).TrySetResult(...)` を実行しているか確認してください。

[StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs) の `GetCompletionSource` の実装を参照し、取得しているのが `StartupRunner` が `BlackBoardKeys.StartupCompletionSource` に注入した `UniTaskCompletionSource` と同一であることを確認してください。

## 検証

修正後、以下の順序でチェーンが正常につながっていることを確認します:

1. 起動後のログで `ProcedureLauncherState.OnEnter` に入ったことが確認でき、続いて `ProcedureGetGlobalInfoState.OnEnter` にも入ることが確認できること(前者しか表示されない状態ではないこと)。
2. `StartupRunner.RunAsync` が返す `UniTask<StartupResult>` が妥当な時間内(通常は数秒)で完了すること。ずっと `Pending` のままにならないこと。
3. コンソールに `WebComponent` の null 参照や UI リソースのロード失敗エラーが表示されなくなること。
4. カスタムの `IStartupUIHandler` を使用している場合は、ブレークポイントで `StartAsync` が `LauncherUIResName` に対応するリソースの準備完了後に戻ること、および復帰後の呼び出しスタックが `ProcedureLauncherState` の `ChangeState<ProcedureGetGlobalInfoState>` に戻ることを確認します。
