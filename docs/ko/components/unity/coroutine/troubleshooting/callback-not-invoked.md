# 프레임 종료 콜백이 실행되지 않을 때怎么办

`CoroutineComponent.WaitForEndOfFrameFinish`이 주입하는 콜백은 내부 코루틴이 `yield return new WaitForEndOfFrame()`까지 실행된 다음에야 트리거됩니다; 코루틴이 프레임 종료 전에 정지되거나 덮어쓰기되거나 아예 실행되지 않으면 콜백도 실행되지 않습니다. 이 페이지에서는 일반적인 시나리오의 진단 및 수정 방법을 제공합니다.

코루틴 컴포넌트에 대한 전체 설명은 《코루틴 컴포넌트》를 참조하세요.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 등록된 콜백이 한 번도 트리거되지 않고 로그에 예외가 없음 | 코루틴이 `StopCoroutine` / `StopAllCoroutines`로 조기 종료되어 프레임 종료를 기다리는 `WaitForEndOfFrame`이 실행될 기회가 없음 | 콜백이 트리거되어야 하는 동일한 프레임에서 코루틴을 정지하지 마세요. 또는 다른 동기화 지점을 사용하세요 |

| 씬 전환 / Play 모드 종료 후 콜백이 더 이상 트리거되지 않음 | 컴포넌트가 GameObject와 함께 파괴되어 내부 `m_CoroutineMap`이 비워짐 | 프레임 종료 콜백을 파괴될 객체에 걸지 마시고, 상주하는 `CoroutineComponent`에 두세요 |

## 수정 단계

### 1. `StopCoroutine`으로 조기 종료되었는지 확인

`WaitForEndOfFrameFinish`의 구현은 일회성 코루틴입니다:

```csharp
private readonly WaitForEndOfFrame _waitForEndOfFrame = new WaitForEndOfFrame();

private IEnumerator WaitForEndOfFrameFinishInternal(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke();
}

public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(WaitForEndOfFrameFinishInternal(callback));
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

`yield return _waitForEndOfFrame`은 현재 프레임의 렌더링이 끝날 때까지 대기해야 하므로, 그 사이에 `StopCoroutine` / `StopAllCoroutines`이 호출되면 `callback?.Invoke()` 줄은 영원히 실행되지 않습니다.

수정:

1. `StopCoroutine` / `StopAllCoroutines` 호출 전에, 콜백에서 수행해야 할 부작용을 `WaitForEndOfFrameFinish`에 의존하지 말고 `Time.timeScale`, `Application.targetFrameRate` 또는 이벤트 능동적发布로 변경하세요.
2. 반드시 취소해야 한다면, 먼저 비즈니스 코드에서 콜백을 수동으로 한 번 실행한 다음 코루틴을 정지하세요:

```csharp
GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()
    .StopCoroutine(coroutineEnumerator); // 그 후에 자체 정리 처리
```

### 2. `CoroutineComponent`의 `StartCoroutine`을 호출하는지 확인

`StartCoroutine`은 `new`로 재정의되어 `m_CoroutineMap`을 유지 관리하며, 부모 클래스 `MonoBehaviour` 호출은 추적을 우회합니다. `StopCoroutine`이 key를 가져올 수 없으면 정지할 코루틴을 찾을 수 없어 "시작되지 않은 것처럼" 보입니다:

```csharp
public new UnityEngine.Coroutine StartCoroutine(IEnumerator enumerator)
{
    var ret = base.StartCoroutine(enumerator);
    m_CoroutineMap[enumerator] = ret;
    return ret;
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

수정: 모든 호출은 `GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()`로 얻은 인스턴스를 통해 통일하여发起하고, `MonoBehaviour`로 암묵적 변환하지 마세요.

### 3. `StopAllCoroutines`의误清 방지

`StopAllCoroutines`은 `m_CoroutineMap`을 비우고 추적된 모든 코루틴을 정지시키며, 프레임 종료를 기다리는 콜백도 함께 버려집니다:

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

수정:

1. `StopAllCoroutines`을 호출하기 전에 아직 정산되지 않은 `WaitForEndOfFrameFinish` 콜백이 없는지 확인하세요.
2. 프레임 종료 수준의 동기화는 `WaitForEndOfFrame` 대신 `Update` / `LateUpdate` 또는 사용자 정의 이벤트를 사용하세요.

### 4. 객체 생명 주기 확인

`CoroutineComponent`는 `MonoBehaviour`로 GameObject와 함께 파괴됩니다; 객체가 `Destroy`되거나所在 씬이 언로드되면 프레임 종료를 기다리던 코루틴도 중단되어 콜백이 더 이상 트리거되지 않습니다.

수정:

1. 프레임 종료 콜백은 상주하는 전역 `CoroutineComponent`(`GameFrameX` 프레임워크에서 자동 생성됨)에서 실행하도록 하세요.
2. 자신의 스크립트에 걸어야 한다면, 콜백이 `OnDestroy` 전에 이미 트리거 완료되었는지 확인하거나, 자체적으로 폴백 로직을 처리하세요.

## 검증

1. `WaitForEndOfFrameFinish`의 콜백에 `Debug.Log` 한 줄을 추가하고, Play 모드에서 매 프레임 한 번씩 출력되는지 확인하거나, 콜백에서 실행되어야 할 로직을 한 번 트리거하여 효과를 관찰하세요.
2. 코루틴 실행 중에 능동적으로 `StopAllCoroutines`을 호출하고 로그를 관찰하세요: 콜백이 더 이상 출력되지 않으면 문제가 1단계에 있음을 의미합니다; 정상적으로 출력되면 콜백 로직 자체가失效한 것입니다.
3. 씬을 전환하거나 Play를 종료하고, `CoroutineComponent` 인스턴스가 여전히 존재하는지 (`GameFrameXEntry`가 해제되었는지) 확인하여 4단계의 객체 생명 주기 문제인지 판단하세요.
