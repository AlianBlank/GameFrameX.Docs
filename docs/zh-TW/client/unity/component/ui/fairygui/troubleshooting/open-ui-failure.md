# 介面開啟失敗怎麼辦

呼叫 `UIManager` 開啟 FairyGUI 介面後沒有出現介面，或拋出例外 / 觸發 `OpenUIFormFailure` 事件。失敗點幾乎都在三處：資源路徑或包名拼接不對、UI 包未正確載入、介面腳本類型與元件不匹配。先對照下方診斷表定位，再按對應修復步驟處理。

## 快速診斷

| 症狀（日誌/現象原文） | 原因 | 修復 |
|------|------|------|
| `GameFrameworkException: Load UI form failure, asset name 'XXX', error message '...'` 且未註冊失敗事件處理器時拋出 | UI 包資源載入失敗：路徑錯誤、包未打進 Bundles、YooAsset 報錯 | 見下方「修復步驟 1：核對資源路徑與包名規則」 |
| 觸發了 `OpenUIFormFailure` 事件但程式碼不會崩潰 | 載入失敗但你註冊了 `OpenUIFormFailureEventHandler`，錯誤被轉為事件回呼 | 見「修復步驟 2：註冊失敗事件拿到真實錯誤」 |
| `Can not create UI form in UI form helper.` | `IUIFormHelper.CreateUIForm` 回傳 null：介面腳本類型（`uiFormType`）與元件資源不匹配或未註冊 | 見「修復步驟 3：檢查介面類型與元件名」 |
| `Open UI form info is invalid.` | `OpenUIFormInfo` 參考被提前釋放/複用池異常，通常是外部混用了內部流程 | 檢查是否繞過 `UIManager` 公開 API 直接呼叫了內部方法 |
| `Log.Error("加载资源失败 Unknown file type: " + assetName + " extension: " + extension)` | FairyGUI 相依資源副檔名不被識別（非 `_fui`/貼圖等已知類型） | 檢查發佈出的資源檔案是否完整、副檔名是否被改動 |
| 介面「開啟」了但拿到的實例不重新整理、事件不回應 | 單例模式下命中了已開啟的同名實例，直接複用回傳 | 見「修復步驟 4：理解單例開啟行為」 |

## 修復步驟

### 修復步驟 1：核對資源路徑與包名規則

開啟介面時，框架按以下規則從 `uiFormAssetPath` 與介面類型名推導所有位址（見 `UIManager.InnerLoadUIFormAsync`）：

- `uiFormAssetName` = 介面類型名 `uiFormType.Name`（**必須與 FairyGUI 編輯器中匯出的元件名一致**）；
- `assetPath` = `uiFormAssetPath/uiFormAssetName`；
- `packageName` = `uiFormAssetPath` 中最後一個 `/` 之後的部分；若路徑中沒有 `/`，則整個路徑就是包名；
- 走 Bundles 載入時，實際載入的資源是 `uiFormAssetPath/packageName_fui`。

```csharp
var uiFormAssetName = uiFormType.Name;
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);

var lastIndexOfStart = uiFormAssetPath.LastIndexOf("/", StringComparison.OrdinalIgnoreCase);
// 如果路徑中沒有 /，則整個路徑作為包名（適用於 Resources 目錄下的簡單路徑）
var packageName = lastIndexOfStart >= 0 ? uiFormAssetPath.Substring(lastIndexOfStart + 1) : uiFormAssetPath;
// 檢查UI包是否已經載入過
var hasUIPackage = FairyGuiPackage.Has(packageName);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L127-L136)

排查要點：

1. 確認 `uiFormAssetPath` 末段目錄名與 FairyGUI 發佈的包名一致（例如路徑 `Assets/Bundles/UI/MainUI` 推出包名 `MainUI`）。
2. 確認介面類別名（`uiFormType.Name`）與元件名完全一致，區分大小寫。
3. 走 Bundles 時確認存在 `<uiFormAssetPath>/<packageName>_fui` 資源；當包名與介面名不同，框架會用 `uiFormAssetPath/packageName` 重新拼接路徑再附加 `_fui`：

```csharp
// 不一致則重新拼接路徑
string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
await FairyGuiPackage.AddPackageAsync(newPackagePath);
...
newAssetPackagePath += "_fui";
// 從包中載入
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L163-L178)

4. 如果 `assetPath` 中不包含 `Utility.Asset.Path.BundlesDirectoryName`（預設 Bundles 目錄名），框架會按 **Resources 模式**同步加包，此時確認該路徑在 Resources 下真實存在：

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // 從 Resources 中載入
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

### 修復步驟 2：註冊失敗事件拿到真實錯誤

載入失敗最終進入 `LoadAssetFailureCallback`。錯誤訊息格式固定為：

```text
Load UI form failure, asset name '{0}', error message '{1}'.
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L358-L368)

關鍵行為分兩種情況：

- 已訂閱 `OpenUIFormFailureEventHandler`：錯誤包裝為 `OpenUIFormFailureEventArgs` 觸發事件，方法回傳 null，不拋出例外；
- 未訂閱：直接 `throw new GameFrameworkException(appendErrorMessage)`，例外冒泡到你的呼叫處。

排查時建議先訂閱失敗事件，把 `errorMessage` 輸出到日誌裡，其中的 YooAsset/資源錯誤訊息就是根因。

### 修復步驟 3：檢查介面類型與元件名

`InternalOpenUIForm` 中，若 `IUIFormHelper.CreateUIForm` 回傳 null 會拋出：

```csharp
IUIForm uiForm = m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData);
if (uiForm == null)
{
    throw new GameFrameworkException("Can not create UI form in UI form helper.");
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L211-L217)

該例外同樣會觸發 `OpenUIFormFailure` 事件（攜帶 `exception.ToString()`）後重新拋出。檢查：

1. 傳入的 `uiFormType` 是否是已註冊/可建立的 `FUI` 子類別；
2. 元件在包內是否存在同名匯出；
3. 若在 `OnOpen`/`BindEvent`/`LoadData` 階段拋出例外，同樣走失敗事件 + rethrow 路徑（見 [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L264-L273)）。

### 修復步驟 4：理解單例開啟行為

單例模式開啟的介面，命中已開啟實例時直接複用並聚焦，不會重新載入：

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L84)

若「開啟」後表現異常，先用 `GetUIForm(uiFormAssetName)` 檢查是否是舊實例；正在載入中的同名介面會複用同一個載入 Task，不會重複載入。執行中 UI 元素路徑查不到時另見 `FairyGUIPathFinderHelper` 的報錯：`error uiPath : can not found ui by this path :{path}` 與 `Invalid UI path: child not found`（[Runtime/FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L141-L191)）。

## 驗證

1. 重新呼叫開啟 API，確認回傳的 `IUIForm` 不為 null 且 `SerialId > 0`；
2. 觀察是否觸發 `OpenUIFormSuccess` 事件（[Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L255-L260)），同時不再出現 `Load UI form failure` 日誌；
3. 失敗事件回呼不再被觸發，主控台無 `GameFrameworkException`。
