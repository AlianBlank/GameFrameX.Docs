# 機密欄位的標註與自訂正規化結果

在實體屬性上加入 `[SensitiveField]` 屬性後，該欄位在序列化、匯出、日誌輸出時，會依照內建政策或自訂規則自動進行遮罩。在類別或方法上加入 `[CustomUnifyResult]` 後，框架會對該目標套用指定名稱的正規化（結果統一）處理器。本頁面將展示這兩個屬性的最小使用範例與常見變化。

## 前置條件

- 參考 NuGet 套件 `GameFrameX.Foundation.Orm.Attribute`（命名空間 `GameFrameX.Foundation.Orm.Attribute`）。
- 在 .NET 專案中使用支援 `System.Attribute` 屬性語法的 C# 語言版本。

## 操作步驟

### 1. 標註機密欄位

對需要遮罩的實體屬性使用 `[SensitiveField]`，並以 `MaskingStrategy` 指定遮罩政策：

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }

    [SensitiveField(MaskingStrategy.Email)]
    public string Email { get; set; }

    [SensitiveField(MaskingStrategy.BankCard)]
    public string BankCard { get; set; }
}
```

來源：[SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

### 2. 選擇內建遮罩政策

`MaskingStrategy` 列舉提供 7 種內建政策（不含 `None`），涵蓋常見的機密資料類型：

| 政策 | 行為 |
|------|------|
| `None` | 不遮罩（預設值） |
| `Phone` | 保留前 3 碼與後 4 碼 |
| `IdCard` | 保留前 6 碼與後 4 碼 |
| `Email` | 保留首字與網域名稱 |
| `BankCard` | 保留後 4 碼 |
| `Name` | 保留姓氏 |
| `Address` | 保留省市區，詳細地址予以遮罩 |
| `Custom` | 自訂規則（與 `KeepPrefix`/`KeepSuffix`/`CustomPattern` 搭配使用） |

來源：[SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L132-L196)

### 3. 標註自訂正規化結果

在類別或方法上加入 `[CustomUnifyResult("處理器名稱")]` 後，框架會套用與該名稱對應的正規化政策（資料格式轉換、結果包裝、例外處理等）：

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[CustomUnifyResult("ApiResponse")]
public class UserController
{
    public User GetUser(int id) => userService.GetById(id);
}

[CustomUnifyResult("DatabaseResult")]
public class UserRepository
{
    public List<User> GetUsers() => database.Query<User>();
}
```

來源：[CustomUnifyResultAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/CustomUnifyResultAttribute.cs#L45-L58)

## 常見變化

### 自訂字首與字尾遮罩

當政策為 `MaskingStrategy.Custom` 時，可與 `KeepPrefix`（字首保留字元數）和 `KeepSuffix`（字尾保留字元數）搭配使用：

```csharp
[SensitiveField(MaskingStrategy.Custom, KeepPrefix = 1, KeepSuffix = 1)]
public string Nickname { get; set; }
```

來源：[SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L59-L60)

### 使用自訂正規表示式進行遮罩

若需要更複雜的遮罩規則，可在 `CustomPattern` 中設定自訂正規表示式（僅在 `Custom` 政策下有效）：

```csharp
[SensitiveField(MaskingStrategy.Custom, CustomPattern = "\\d{4}")]
public string CustomField { get; set; }
```

來源：[SensitiveFieldAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L95-L101)

### 對多個目標標註正規化結果

`[CustomUnifyResult]` 支援 `AttributeTargets.All`，並允許對同一目標多次標註（`AllowMultiple = true`）：

```csharp
[CustomUnifyResult("ApiResponse")]
[CustomUnifyResult("Audit")]
public class OrderController
{
    public Order GetOrder(int id) => orderService.GetById(id);
}
```

來源：[CustomUnifyResultAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/CustomUnifyResultAttribute.cs#L60)

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `ArgumentNullException`：`name` 不可為 null | 建構 `[CustomUnifyResult]` 時傳入了 `null` 名稱 | 使用非空字串作為處理器名稱 |
| 欄位未遮罩 | 標註時未傳入 `MaskingStrategy`，因此成為預設的 `None` | 明確指定政策（例如：`[SensitiveField(MaskingStrategy.Phone)]`） |
| 自訂規則無效 | `KeepPrefix`/`KeepSuffix`/`CustomPattern` 在 `Custom` 以外的政策下會被忽略 | 將 `Strategy` 設定為 `MaskingStrategy.Custom` |
| 欄位標註無效 | 將 `[SensitiveField]` 標註於類別或欄位以外的目標上 | 此屬性僅允許 `AttributeTargets.Property`，只能用於屬性 |

## 背景（選讀）

`SensitiveFieldAttribute` 僅能標註於屬性，且不允許多次標註。其目的在於「程式庫內為明文、對外輸出時遮罩」——即資料儲存至資料庫時保留原始值，在對外輸出（序列化、匯出、日誌）時依政策進行遮罩。`CustomUnifyResultAttribute` 則是標記型屬性，由框架端依名稱查找並套用對應的正規化處理器。兩者皆為宣告式中繼資料，其行為由執行框架解釋。
