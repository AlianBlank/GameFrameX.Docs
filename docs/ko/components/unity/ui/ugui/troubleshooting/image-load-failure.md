# 비동기 이미지 로드 예외 처리 방법

`UIImage.icon` 또는 `Image.SetIconAsync(...)` 호출 후 이미지가 표시되지 않거나, 콘솔에 `Failed to load icon '<path>': ...` 오류가 발생하거나, 이미지가 편집기에서는 정상 작동하지만 패키징 후 사라지는 경우 이 페이지의 단계를 따라 문제를 해결하세요.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 콘솔에 `Failed to load icon 'xxx': ...` 출력 | `AssetComponent.LoadAssetAsync` 예외 발생 또는 리소스 없음 | 「리소스 경로 오류」 참고 |
| `icon` 할당 후 이미지가 여전히 비어 있음 | 자산이 YooAsset 패키징 매니페스트에 포함되지 않음 | 「리소스가 YooAsset 매니페스트에 포함되지 않음」 참고 |
| 편집기는 정상, 실행 후 이미지 손실 | 런타임에서 편집기 전용 리소스 사용(예: `AssetDatabase`) | 「편집기 / 런타임 리소스 분리」 참고 |
| 아이콘은 표시되지만 늘어남/잘림 발생 | `SetIconAsync`가 `Rect(0,0,w,h)`로 Sprite를 재생성하여 원본 보더 무시 | 「Sprite 보더와 9-slice 손실」 참고 |
| `icon` 전환 후 이전 텍스처가 메모리에 잔류 | `SetIconAsync` 내 `using`이 핸들은 해제했지만 이전 Sprite를 명시적으로 파괴하지 않음 | 「메모리 누수와 핸들 해제」 참고 |

## 해결 단계

### 리소스 경로 오류

`SetIconAsync` 내부에서 `AssetComponent.LoadAssetAsync<Texture2D>(icon)`을 사용하며, 경로는 YooAsset 매니페스트의 `Location`과 완전히 일치해야 합니다(대소문자 구분, 파일 확장자 제외).

```csharp
[UnityEngine.Scripting.Preserve]
public static async Task SetIconAsync(this UnityEngine.UI.Image self, string icon)
{
    try
    {
        var assetComponent = GameEntry.GetComponent<AssetComponent>();
        using (var valueHandle = await assetComponent.LoadAssetAsync<Texture2D>(icon))
        {
            if (valueHandle.IsDone && valueHandle.Status == EOperationStatus.Succeed)
            {
                var texture2D = valueHandle.GetAssetObject<Texture2D>();
                self.sprite = Sprite.Create(texture2D, new Rect(0, 0, texture2D.width, texture2D.height), new Vector2(0.5f, 0.5f));
            }
        }
    }
    catch (System.Exception e)
    {
        Log.Error($"Failed to load icon '{icon}': {e.Message}");
    }
}
```

Source: [UGUIImageExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIImageExtension.cs#L56-L74)

수정 작업:

1. YooAsset 리소스 관리 창(예: `Asset Bundle Collector`)에서 해당 `icon` 문자열을 검색하여 `Texture2D` 타입의 Location으로 존재하는지 확인합니다.
2. 확장자를 제거합니다(예: `.png` 대신 `Assets/UI/Icons/coin`으로 작성).
3. `AssetComponent.LoadAssetAsync<Texture2D>`에 동일한 문자열을 전달하여 직접 디버깅을 시도하여 예외가 여전히 발생하는지 확인합니다.

### 리소스가 YooAsset 매니페스트에 포함되지 않음

`UIImage.icon` setter는 `SetIconAsync`를 통해 런타임 리소스 로드를 수행합니다:

```csharp
[UnityEngine.Scripting.Preserve]
public string icon
{
    get { return m_icon; }
    set
    {
        if (m_icon != value)
        {
            m_icon = value;
            _ = this.SetIconAsync(m_icon);
        }
    }
}
```

Source: [UIImage.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIImage.cs#L60-L71)

수정 작업:

1. YooAsset 수집기를 열고 아이콘이 있는 디렉터리가 특정 수집 규칙에 포함되어 있는지 확인합니다.
2. 리소스 패키지를 재구축하고 대상 플랫폼에 핫 업데이트한 후 게임을 시작합니다.

런타임에서 직접 `Resources.Load`로 편집기 경로를 가져오면 실패합니다. 수정 작업: 모든 아이콘이 YooAsset의 런타임 매니페스트에서 제공되도록 하고, `Resources/` 또는 편집기 내장 자산을 혼용하지 마세요.

### Sprite 보더와 9-slice 손실

`SetIconAsync`는 `Sprite.Create(texture2D, new Rect(0,0,w,h), ...)`를 사용하여 직접 Sprite를 생성하며, 원본 Sprite의 `border`를 읽지 않습니다. 수정 작업: 원본 이미지가 9-slice인 경우 `AssetBundle`에서 `Sprite` 타입 프리팹을 사용하고, `icon` 문자열을 통한 런타임 생성을 피하세요.

### 메모리 누수와 핸들 해제

`SetIconAsync` 내부에서 이미 `using (var valueHandle = ...)`가 사용되어 핸들은 자동으로 반환되지만, `icon`을 여러 번 전환하면 이전 `Sprite`가 여전히 새로운 `Texture2D`에 연결되어 있어 참조가 남아 있을 수 있습니다. 수정 작업: 전환 전에 수동으로 `self.sprite = null`을 설정하여 이전 Sprite가 참조되지 않은 상태로 `Texture2D`와 함께 GC되도록 합니다.

## 검증

1. `UIImage.icon`을 다시 할당하여 콘솔에 더 이상 `Failed to load icon`이 출력되지 않는지 확인합니다.
2. YooAsset 리소스 브라우저에서 동일한 `Location`을 `UIImage.icon`으로 드래그하여 `Sprite Renderer` 패널에 이미지가 표시되는지 확인합니다.
3. Profiler → Memory → Texture에서 전환 후 이전 텍스처의 참조 카운트가 0이 되는지 확인합니다.
4. 대상 플랫폼에 패키징한 후 실제 기기에서 동일한流程을 다시 실행합니다.

## 배경(선택 사항)

`UIImage`는 `UnityEngine.UI.Image`에 `icon` 속성만 추가하며, 실제 로드 로직은 모두 `UGUIImageExtension.SetIconAsync`를 통해 `GameEntry.GetComponent<AssetComponent>()`로 YooAsset 비동기 인터페이스를 호출합니다. 실패 시 예외를 던지지 않고 로그만 기록합니다.
