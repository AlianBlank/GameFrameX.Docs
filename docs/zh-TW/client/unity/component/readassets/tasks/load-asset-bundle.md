# 載入 AssetBundle(同步與非同步)

`BlankReadAssets` 提供了兩個靜態方法 `LoadAssetBundle` 與 `LoadAssetBundleAsync`,用於從 StreamingAssets 載入 Unity AssetBundle,並在各平台(Editor / Android APK / 散裝檔案)間統一處理路徑。

## API 概覽

| 方法 | 簽章 | 回傳值 | 用途 |
|------|------|--------|------|
| 同步載入 | `LoadAssetBundle(string path, uint crc = 0)` | `AssetBundle` | 立即阻塞式載入，適合啟動階段或小型 bundle |
| 非同步載入 | `LoadAssetBundleAsync(string path, uint crc = 0)` | `AssetBundleCreateRequest` | 非阻塞，可監控載入進度 |

## 前置條件

- AssetBundle 檔案已放置於專案的 `StreamingAssets/` 目錄中，或其相對路徑可由 `BlankReadAssets` 解析。
- `path` 為**相對路徑**(相對於 StreamingAssets 根目錄)；請勿傳入 `Application.streamingAssetsPath` 前綴。
- `Initialize` 會在首次呼叫任何 API 時自動執行，無需手動初始化。

## 操作步驟

### 1. 同步載入 AssetBundle

```csharp
using GameFrameX.ReadAssets.Runtime;

// path 為相對於 StreamingAssets 根目錄的路徑
var bundle = BlankReadAssets.LoadAssetBundle("AssetBundles/ui.bundle");
if (bundle == null)
{
    Debug.LogError("載入失敗");
    return;
}

var prefab = bundle.LoadAsset<GameObject>("LoginPanel");
Instantiate(prefab);
```

來源:[BlankReadAssets.cs#L125-L130](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L125-L130)

### 2. 非同步載入 AssetBundle

```csharp
using GameFrameX.ReadAssets.Runtime;

var request = BlankReadAssets.LoadAssetBundleAsync("AssetBundles/ui.bundle");
yield return request;

var bundle = request.assetBundle;
if (bundle == null)
{
    Debug.LogError("載入失敗");
    yield break;
}

var assetRequest = bundle.LoadAssetAsync<GameObject>("LoginPanel");
yield return assetRequest;

Instantiate(assetRequest.asset as GameObject);
```

來源:[BlankReadAssets.cs#L118-L123](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L118-L123)

### 3. 載入時的 CRC 驗證

若 AssetBundle 在建置時有記錄 CRC,可以在載入時傳入驗證值；若不相符，Unity 將回傳 `null`。

```csharp
// crc 必須與建置時 AssetBundle 的資訊清單一致,否則保持為 0
var bundle = BlankReadAssets.LoadAssetBundle("AssetBundles/ui.bundle", crc: 0xA1B2C3D4u);
```

## 常見變化

### 帶進度的非同步載入(進度條)

```csharp
var req = BlankReadAssets.LoadAssetBundleAsync("AssetBundles/big.bundle");
while (!req.isDone)
{
    UpdateProgressBar(req.progress); // 0~0.9,LoadFromFileAsync 階段
    yield return null;
}
var bundle = req.assetBundle;
```

### 同一檔案僅載入一次(參考計數)

```csharp
private static readonly Dictionary<string, AssetBundle> s_cache = new();

public static AssetBundle LoadCached(string path)
{
    if (!s_cache.TryGetValue(path, out var bundle))
    {
        bundle = BlankReadAssets.LoadAssetBundle(path);
        s_cache[path] = bundle;
    }
    return bundle;
}
```

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 擲出 `FileNotFoundException: File not found` | `path` 不在 StreamingAssets 之下或有拼寫錯誤 | 先使用 `BlankReadAssets.FileExists(path)` 檢查，確認相對路徑是否正確 |
| 回傳 `null` | 傳入的 CRC 與建置資訊清單不符，或該檔案不是有效的 AssetBundle | 驗證 CRC 是否正確，或嘗試 `crc = 0` 略過驗證，以確認是否為打包問題 |
| 在 Android 上載入到空 / 損壞的 bundle | 檔案在 APK 內受到壓縮，Unity 無法直接映射 | 監聽 `CompressedStreamingAssetFound` 事件，改用 `OpenRead` + 自行解壓縮流程，或在建置時停用 StreamingAssets 壓縮 |
| 非同步請求的 `progress` 一直為 0 | `LoadFromFileAsync` 階段的進度映射為 0~0.9,資源讀取發生在 `LoadAssetAsync` | 一併驅動 `assetRequest.progress` |

## 背景說明(選讀)

在內部，`LoadAssetBundle` / `LoadAssetBundleAsync` 會使用 `GetInfoOrThrow` 取得平台對應的 `readPath` 與 `offset`,再分別呼叫 `AssetBundle.LoadFromFile` 與 `AssetBundle.LoadFromFileAsync`。如此一來，Android APK 內的 AssetBundle 就能像散裝檔案一樣透過偏移量讀取。

有關 CRC 驗證、APK 壓縮資源處理等詳細資訊，請參閱「BlankReadAssets 總覽」。
