# 非同期リソースロード方式の切り替え（YooAsset / Resources）

本フレームワークでは、FairyGUI の UI フォームが YooAsset による非同期ロードと Resources による同期ロードのどちらを使用するかは、**UI フォームを開く際に渡されるリソースパスに Bundles ディレクトリ名が含まれるかどうかによって自動的に決定されます**（判定基準は `Utility.Asset.Path.BundlesDirectoryName`）。ローダーのコードを変更する必要はありません。UI パッケージを正しいディレクトリに配置し、正しい `uiFormAssetPath` を渡すだけで切り替えが完了します。

## 前提条件

- YooAsset モード：プロジェクトに GameFrameX の Asset コンポーネントが設定済みであること（コード内では `GameEntry.GetComponent<AssetComponent>()` で取得）。UI パッケージの成果物が Bundles ディレクトリ配下に存在すること。
- Resources モード：UI パッケージが `Resources` ディレクトリ直下に配置されていること。
- FairyGUI ランタイムライブラリが導入済みであること（`using FairyGUI;`）。

## 操作手順

1. **UI パッケージの配置場所を確認する**：
   - YooAsset 非同期ロードを使用する場合：パッケージを Bundles ディレクトリに配置する（パスに `Utility.Asset.Path.BundlesDirectoryName` が含まれる）。
   - Resources 同期ロードを使用する場合：パッケージを `Resources` ディレクトリに配置する。パスに Bundles ディレクトリ名は含めない。

2. **UI フォームを開く API を呼び出し、対応するパスを渡します**。フレームワークは `UIManager.InnerLoadUIFormAsync` 内でパスに基づいて自動的に振り分けを行います。判定ロジックは以下の通りです：

```csharp
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);

var lastIndexOfStart = uiFormAssetPath.LastIndexOf("/", StringComparison.OrdinalIgnoreCase);
// パスに / が含まれない場合、パス全体がパッケージ名として扱われる（Resources ディレクトリ配下の単純なパスに対応）
var packageName = lastIndexOfStart >= 0 ? uiFormAssetPath.Substring(lastIndexOfStart + 1) : uiFormAssetPath;
// UIパッケージが既にロード済みかどうかを確認
var hasUIPackage = FairyGuiPackage.Has(packageName);
...
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Resources からロードする
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L130-L149)

3. **YooAsset 分岐では、まず UI パッケージを非同期にロードし、その後フォームリソースをロードします**。パッケージが既にロード済みであれば直接フォームを生成します。そうでない場合は `AddPackageAsync` でパッケージをロードし、続けて `パス + "_fui"` からフォームの記述リソースを非同期にロードします：

```csharp
if (hasUIPackage)
{
    // UIパッケージが存在する場合はフォームを生成
    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 1, openUIFormInfo);
}

if (packageName == uiFormAssetName)
{
    // UIリソース名とパッケージ名が一致する場合はそのままロード
    await FairyGuiPackage.AddPackageAsync(assetPath);
}
else
{
    // 一致しない場合はパスを再結合する
    string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
    await FairyGuiPackage.AddPackageAsync(newPackagePath);
}

string newAssetPackagePath = assetPath;
if (packageName != uiFormAssetName)
{
    newAssetPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
}

newAssetPackagePath += "_fui";
// パッケージからロードする
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);

if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    // ロード成功
    openUIFormInfo.SetAssetHandle(assetHandle);
    return LoadAssetSuccessCallback(assetPath, uiFormAssetName, openUIFormInfoData, assetHandle.Progress, openUIFormInfo);
}

// UIパッケージが存在しない
return LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo);
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L151-L189)

4. **パッケージ内のサブリソース（アトラス、サウンド、フォントなど）の非同期ロードは `FairyGUILoadAsyncResourceHelper` が担当します**。このクラスは `IAsyncResource` インターフェースを実装しており、`AssetComponent` の非同期 API を統一的に使用します：

```csharp
internal sealed class FairyGUILoadAsyncResourceHelper : IAsyncResource
{
    public async void LoadResource(string assetName, string uiPackageName, string extension, PackageItemType type, Action<bool, string, object> action)
    {
        ...
        assetHandle = await AssetComponent.LoadAssetAsync<UnityEngine.Object>(assetName);
        ...
        var allAssetsHandle = await AssetComponent.LoadAllAssetsAsync<UnityEngine.Object>(assetName);
        if (!(allAssetsHandle.IsDone && allAssetsHandle.Status == EOperationStatus.Succeed))
        {
            action.Invoke(false, assetName, null);
            return;
        }
        ...
    }
}
```

6. **リソースを解放する際はパッケージ名単位でアンロードします**。`ReleasePackage` / `ReleaseAllPackage` は `AssetComponent.UnloadAsset` を呼び出して、記述ファイルとリソースの両方をアンロードします：

```csharp
public void ReleasePackage(string uiPackageName)
{
    if (m_UIPackages.TryGetValue(uiPackageName, out var uiPackageData))
    {
        AssetComponent.UnloadAsset(uiPackageData.DescAssetPath);
        if (uiPackageData.ResourceAssetPath != null)
        {
            AssetComponent.UnloadAsset(uiPackageData.ResourceAssetPath);
        }

        uiPackageData.Dispose();
        m_UIPackages.Remove(uiPackageName);
    }
}
```

## よくあるバリエーション

| バリエーション | 手法 |
|------|------|
| パッケージ名とフォーム名が異なる | パスを渡す際、ディレクトリをパッケージ名として扱う：コードは `uiFormAssetPath` の最後のセグメントを `packageName` として取り出し、フォーム名と一致しない場合は `PathHelper.Combine(uiFormAssetPath, packageName)` で再結合してロードする |
| Resources の単純なパス（`/` を含まない） | パス全体がそのままパッケージ名となり、`FairyGuiPackage.AddPackageSync` の同期ロード分岐に入る |
| パッケージがロード済み | `FairyGuiPackage.Has(packageName)` が true の場合はロードをスキップし、直接フォーム生成フローに入る |
| プリロードして完了を待つ | `FairyGuiPackage.AddPackageAsync(descFilePath)` が返す `Task<UIPackage>` を使用する。内部では `m_UIPackageLoading` ディクショナリ + `TaskCompletionSource` で重複ロードを防止する |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| UI フォームを開くと即座に同期で返り、非同期が実行されない | `assetPath` に Bundles ディレクトリ名が含まれておらず、Resources の同期分岐に振り分けられている | YooAsset モードではパスに `Utility.Asset.Path.BundlesDirectoryName` が含まれていることを確認する |
| `LoadAssetFailureCallback` が呼び出される | `assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed` が false で、YooAsset のハンドルが失敗している | 返された `assetHandle.LastError` を確認し、`パス + "_fui"` のリソースが Bundles にパックされていることを確認する |
| `加载资源失败 Unknown file type: ...` のログ | `PackageItemType` が `FairyGUILoadAsyncResourceHelper` の default 分岐に入っている（または `FAIRYGUI_DRAGONBONES` マクロが有効化されていない） | リソースタイプがサポートされていることを確認する。DragonBones を使用するには `FAIRYGUI_DRAGONBONES` マクロの定義が必要 |
| コンソールに `!a` で終わる Asset が見つからないというエラーが出る | FairyGUI のエクスポート時に「アルファチャンネルの分離」がチェックされておらず、`!a` リソースがロードできない | ソースコードのコメントには、このエラーは**実行に影響しない**と明記されている。解消したい場合は、エクスポート時にアルファチャンネルの分離を有効にする |
| アンロード後も UI リソースがメモリを占有している | `ReleasePackage` が呼び出されておらず、記述ファイルとリソースハンドルが Unload されていない | `FairyGUILoadAsyncResourceHelper.ReleasePackage(uiPackageName)` または `ReleaseAllPackage()` を呼び出す |

default 分岐と DragonBones 分岐の元のログは以下の通りです：

```csharp
default:
{
    Log.Error("加载资源失败 Unknown file type: " + assetName + " extension: " + extension);
    action.Invoke(false, assetName, null);
    break;
}
```

## 検証

- YooAsset モード：UI フォームを開く前後で AssetComponent のロードログを観察し、`xxx_fui` 記述リソースとアトラス/テクスチャに対する非同期ロードが行われ、ロード成功時のコールバックが `LoadAssetSuccessCallback` を経由していることを確認します。
- Resources モード：ブレークポイントまたはログで `FairyGuiPackage.AddPackageSync(assetPath)` 分岐に入り、フォームが正常に表示されることを確認します。
- 解放の検証：`ReleasePackage` を呼び出した後、同じフォームを再度開き、正常に再ロードでき、ハンドルリークのエラーが発生しないことを確認します。

## 背景

2 つのロード方式は同一のフォームを開くフローを共有しており、`InnerLoadUIFormAsync` の箇所でのみパスによって振り分けが行われます。パッケージ内のサブリソースは `IAsyncResource` を実装した `FairyGUILoadAsyncResourceHelper` に統一的に委ねられ、`AssetComponent.LoadAssetAsync` / `LoadAllAssetsAsync` によってロードが完結するため、ロード方式を切り替える際にヘルパーコードを置き換える必要は一切ありません。
