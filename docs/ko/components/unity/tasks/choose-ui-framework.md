# FairyGUI와 UGUI 사이에서 선택하고 전환하는 방법

GameFrameX는 두 개의 독립된 UI 어댑터 패키지를 통해 FairyGUI와 UGUI를 동시에 지원합니다. 비즈니스 코드는 생성 단계에서 어댑터 계층을 선택하면 되며, 런타임에는 스크립트 매크로(`ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI`)로 결과물을 격리하여 동일 프로젝트에서 공존하거나 전환할 수 있습니다.

## 사전 조건

프로젝트에서 Unity Package Manager를 통해 다음 패키지를 도입했습니다([Packages/manifest.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Packages/manifest.json#L36-L38) 참조):

| 패키지 이름 | 버전 | 역할 |
|------|------|------|
| `com.gameframex.unity.ui` | 2.11.0 | UI 기본 프레임워크(열기/닫기/이벤트) |
| `com.gameframex.unity.ui.fairygui` | 3.4.2 | FairyGUI 어댑터 계층 |
| `com.gameframex.unity.ui.ugui` | 2.6.0 | UGUI 어댑터 계층 |
| `com.gameframex.unity.fairygui.unity` | 5.3.4 | FairyGUI 에디터 런타임 |
| `com.unity.ugui` | 1.0.0 | Unity 내장 UGUI |

> FairyGUI 의존성 패키지인 `FairyGUI`는 `com.gameframex.unity.fairygui.unity`에서 제공하므로 별도로 설치할 필요가 없습니다.

## 선택 제안

| 시나리오 | 추천 방안 | 이유 |
|------|----------|------|
| 아트가 이미 FairyGUI 에디터로 다수의 `.fui` 자산을 생성한 경우 | FairyGUI | 기존 패키지를 바로 재사용, 필드 타입이 `GComponent` / `GTextField` 등 |
| 팀이 Unity 네이티브 워크플로에 익숙하고 Prefab + Canvas를 사용하는 경우 | UGUI | 필드 타입이 `UnityEngine.UI.Text` / `InputField`로 Unity 직관에 부합 |
| 두 세트의 인터페이스 공존이 필요한 경우(예: 메인 인터페이스는 UGUI, 이벤트 팝업은 FairyGUI) | 동시 활성화 | 서로 다른 디렉터리의 생성 코드를 격리하면 됨 |
| 처음부터 시작하며 최대한 빠르게 익히고 싶은 경우 | UGUI | FairyGUI 에디터에 의존하지 않고 Prefab을 직접 드래그 |

## 작업 단계: 컴파일 결과물에서 방안 선택하기

1. `Project Settings` → `Player` → `Scripting Define Symbols`에서 해당 매크로를 추가(또는 제거)합니다:

   ```
   ENABLE_UI_FAIRYGUI   // FairyGUI 어댑터 활성화
   ENABLE_UI_UGUI       // UGUI 어댑터 활성화
   ```

2. FairyGUI 생성 코드 예시 —— 클래스가 `FUI`를 상속하고 `UIPackage.CreateObject`로 생성:

   ```csharp
   // 출처:Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs
   #if ENABLE_UI_FAIRYGUI
   public sealed partial class UIAnnouncement : FUI
   {
       public const string UIPackageName = "UILogin";
       public const string UIResName     = "UIAnnouncement";
       public const string URL           = "ui://f011l0h9aneks9g";

       public GComponent self { get; private set; }
       public GTextField  m_TextTitle { get; private set; }
   }
   #endif
   ```

   Source: [UIAnnouncement.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/FairyGUI/UILogin/Components/UIAnnouncement.cs#L3-L29)

3. UGUI 생성 코드 예시 —— 클래스가 `UGUI`를 상속하고 `[SerializeField] [UGUIElementProperty]`로 노드를 노출:

   ```csharp
   // 출처:Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs
   #if ENABLE_UI_UGUI
   [OptionUIConfig(null, "Assets/Bundles/UI/UILogin")]
   public sealed partial class UILogin : UGUI
   {
       [SerializeField] [UGUIElementProperty("UserName")]
       private UnityEngine.UI.InputField UserName;
       public UnityEngine.UI.InputField m_UserName => UserName;
   }
   #endif
   ```

   Source: [UILogin.UI.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/UGUI/UILogin/UILogin.UI.cs#L3-L46)

4. UI Launcher를 실행하면 프레임워크가 현재 활성화된 매크로에 따라 해당 생성 클래스(`FUI` 또는 `UGUI`)를 자동으로 찾아 패널을 엽니다. 비즈니스 계층에서 하드코딩할 필요가 없습니다.

## 일반적인 변형

- **두 세트의 UI 공존**: 두 매크로를 동시에 정의하고, FairyGUI 결과물을 `Assets/Hotfix/UI/FairyGUI/`에, UGUI 결과물을 `Assets/Hotfix/UI/UGUI/`에 두면 프레임워크가 클래스 이름으로 매칭합니다.
- **런타임 동적 전환**: 동일한 빌드 패키지 내에서 매크로로 전환하는 것은 권장하지 않습니다. A/B 테스트가 필요한 경우 두 개의 빌드를 각각 생성하고 각 빌드에서 하나의 매크로만 활성화하도록 변경하세요.
- **하나만 유지**: 다른 디렉터리의 생성 코드를 삭제하고 해당 매크로를 제거하면 됩니다.

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| UI 열 때 `TypeInitializationException`이 발생하고 클래스를 찾을 수 없음 | `Scripting Define Symbols`에 해당 매크로를 추가하지 않아 생성 코드가 `#if`로 전체 제외됨 | `ENABLE_UI_FAIRYGUI` 또는 `ENABLE_UI_UGUI`를 추가 |
| FairyGUI 패키지 로드 실패, 자원이 분홍색으로 표시됨 | `com.gameframex.unity.fairygui.unity`가 설치되지 않았거나 FairyGUI 에디터에서 내보내지 않음 | 패키지를 다시 가져오고 `.fui` 패키지 주소 `ui://...`가 `UIPackageName`과 일치하는지 확인 |
| UGUI 노드가 모두 `null` | Prefab 경로와 `[OptionUIConfig]`의 `Assets/Bundles/UI/...`가 일치하지 않음 | UI 코드를 다시 생성하거나 `OptionUIConfig`에서 경로 수정 |

## 검증

1. 프로젝트를 컴파일하고 Console에 `TypeLoadException` / `MissingMethodException`이 발생하지 않아야 합니다.
2. 시작 후 임의의 샘플 패널(예: `UILogin`)을 열어 해당 방안의 컨트롤을 확인할 수 있어야 합니다.
3. 매크로를 전환한 후 다시 컴파일하여 패널 타입이 `FUI` 서브클래스에서 `UGUI` 서브클래스로(또는 그 반대로) 변경되는지 확인합니다.

## 배경(선택)

두 어댑터 패키지는 동일한 의미의 `Open` / `Close` / `Show` 흐름을 제공하며, 차이는 노드 바인딩 방식에만 있습니다: FairyGUI는 `GObject`로 패키지 내 컴포넌트를 리플렉션하고, UGUI는 `UGUIElementProperty` 특성으로 Prefab 위의 `GameObject`를 리플렉션합니다. 비즈니스 코드는 기본 클래스 `FUI` / `UGUI`만 향해 프로그래밍하며 필드 타입에 직접 의존하지 않습니다.
