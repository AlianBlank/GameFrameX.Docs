# 如何設定自訂額外資料

在廣告載入之前，呼叫 `IAdvertisementManager.SetExtraData(string key, string value)` 寫入鍵值對擴充資料。廣告載入時，這些鍵值對會被打包成 JSON 並透傳至伺服器端的獎勵驗證回呼，用於使用者識別、獎勵發放比對等業務邏輯。

## 前置條件

- 已安裝 `com.gameframex.unity.advertisement` 套件，並已在場景中掛載 `AdvertisementComponent`。
- 廣告管理器已透過 `Initialize(AdvertisementConfig)` 完成初始化，且擴充資料必須在 **呼叫 Load 之前** 設定；否則將不會被打包進請求中。

## 步驟

1. **取得廣告管理器實例**

   透過 `AdvertisementComponent` 取得目前平台的 `IAdvertisementManager`。後續所有 API 呼叫都經由該介面進行。

2. **在 Load 之前呼叫 SetExtraData**

   `SetExtraData` 接受一個字串 key 和一個字串 value,內部維護一個 `Dictionary<string, string>` 容器；重複設定相同的 key 會覆寫舊值，傳入 `null` 值則會移除該 key。

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   var mgr = GameFrameworkEntry.GetModule<IAdvertisementManager>();

   // 寫入使用者識別碼;伺服器可據此比對獎勵歸屬
   mgr.SetExtraData("user_id", "10086");

   // 寫入業務標籤
   mgr.SetExtraData("scene", "level_clear");

   // 傳入 null 會移除該 key
   mgr.SetExtraData("user_id", null);
   ```

   來源:[BaseAdvertisementManager.cs#L165-L189](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L165-L189)

3. **按平台載入廣告**

   Load 呼叫之後，管理器會呼叫受保護的 `SerializeExtraData()`,將整個字典序列化為 JSON,並隨 Load 請求一併傳送至伺服器。沒有額外資料時會回傳 `null`。

   ```csharp
   // Load 之後,SetExtraData 的任何變更將不再被透傳
   mgr.Load(option);
   ```

   `SerializeExtraData()` 的實作如下：

   ```csharp
   protected string SerializeExtraData()
   {
       if (ExtraData.Count == 0)
       {
           return null;
       }
       return Utility.Json.ToJson(ExtraData);
   }
   ```

   來源:[BaseAdvertisementManager.cs#L273-L282](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L273-L282)

4. **(可選)載入後回讀**

   若子類別需要在驗證後回讀鍵值對，可以使用受保護的 `GetExtraDataValue(string key)`,當 key 不存在時會回傳 `null`。

   ```csharp
   // 僅在繼承 BaseAdvertisementManager 的子類別中可用
   var uid = GetExtraDataValue("user_id");
   ```

   來源:[BaseAdvertisementManager.cs#L292-L297](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L292-L297)

## 常見變體

- **播放時攜帶單一自訂資料段**:`AdvertisementPlayOption.customData` 欄位用於在廣告播放時透傳自訂資訊，與 `extraData` 欄位(僅在 Load 階段生效)是相互獨立的通道。

  ```csharp
  var option = new AdvertisementPlayOption
  {
      OnSuccess = extra => { /* 獎勵發放 */ },
      customData = "level_id=42"
  };
  ```

  來源:[AdvertisementPlayOption.cs#L78-L84](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L78-L84)

- **批次鍵值預設**：在遊戲啟動時或登入成功後一次性寫入一批擴充資料，後續的 Load 呼叫會自動攜帶它們。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 伺服器收到的 `extraData` 為 `null` | `SetExtraData` 在 Load 呼叫之後才被呼叫；序列化發生在 Load 內部，因此後續寫入不會進入請求 | 將所有 `SetExtraData` 呼叫放在 `Load` 之前 |
| 伺服器收到的 JSON 是空物件 `{}` | 未呼叫過 `SetExtraData`,或所有 key 已被 `null` 值移除 | 至少設定一組鍵值對；字典為空時 `SerializeExtraData()` 會回傳 `null` |
| 設定的 key 未生效 | 傳入的 `key` 為 `null` 或空字串；`SetExtraData` 會直接返回 | 確保 `key` 非空 |
| 想刪除某個 key,但下一次 Load 仍會攜帶它 | 使用了 `SetExtraData(key, "")` 寫入空字串，只會被保留為空值 | 使用 `SetExtraData(key, null)` 明確移除 |

## 背景(可選)

擴充資料儲存於 `BaseAdvertisementManager.ExtraData`(受保護的 `Dictionary<string, string>`),會在 Load 時由框架統一序列化為 JSON,並透傳至廣告 SDK 的伺服器端獎勵驗證回呼；`AdvertisementPlayOption.extraData` 是同名但用途不同的欄位——後者僅在 Load 階段被讀取，載入後的寫入無效。
