# Xcode プロジェクトへのファイルとフォルダーのコピー

本ページでは、Xcode ビルド後処理の設定において、ローカルファイルやフォルダー全体を生成された Xcode プロジェクトにコピーし、Build リストや検索パスに自動的に追加する方法を説明します。Xcode 設定ファイル(JSON)の `files` と `folders` フィールドに「コピー元パス → コピー先パス」のマッピングを記述するだけで、ビルド時にコピーが自動的に実行されます。

## 前提条件

- Unity プロジェクトが iOS プラットフォームに切り替え済みであること(実装はすべて `#if UNITY_IOS` の下にあります)。
- Xcode ビルド後処理の基本連携が完了していること:`PostProcessBuildHelper` がビルドコールバック内でマージ後の設定を読み込み、`Run` を呼び出します。

## 操作手順

1. Xcode ビルド後処理の設定ファイルを開き、対象ターゲットの設定ノード(`unityMain` / `unityFramework` に対応するハッシュテーブルなど)を見つけます。
2. このノードの下に `files` フィールドを追加します。Key はコピー元ファイルのパス(Unity プロジェクトのルートディレクトリ、すなわち `Environment.CurrentDirectory` からの相対パス)、Value はコピー先パス(生成された Xcode プロジェクトディレクトリからの相対パス)です:

```json
{
  "files": {
    "Assets/Plugins/iOS/NativeCode.mm": "Libraries/NativeCode.mm",
    "Assets/Plugins/iOS/MySDK.framework": "Frameworks/MySDK.framework"
  }
}
```

3. フォルダー全体をコピーする必要がある場合は、`folders` フィールドを追加します。同じく「コピー元パス → コピー先パス」のマッピングです:

```json
{
  "folders": {
    "Assets/Plugins/iOS/NativeFolder": "Libraries/NativeFolder"
  }
}
```

4. iOS ビルドを一度実行します。ビルド終了後、`Run` が順番にコピーを実行します:まず `RunCopyFiles` が `files` を処理し、その後 `CopyFolders` が `folders` を処理します:

```csharp
// ファイルをコピー
RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
// フォルダーをコピー
CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L173-L176)

5. Xcode プロジェクトで確認します:ファイルが対応するコピー先パスに出現し、`AddFileToBuild` によって対象ターゲットの Build リストに追加されていること。コンソールには `copy file {src} -> {des}` のログが出力されます。

## コピー動作の詳細

コピーは単純なファイル複製ではなく、以下の動作はソースコードの実装に由来するものであり、設定時に把握しておく必要があります:

| 動作 | 説明 |
|------|------|
| コピー先ディレクトリの自動作成 | `CopyFolder` は既存の同名ディレクトリ/ファイルを先に削除し、`Directory.CreateDirectory` で再作成してから再帰的にコピーします |
| 既存ファイルの上書き | 単一ファイルのコピーには `File.Copy(src, des, true)` が使用され、同名のファイルは上書きされます |
| 隠しファイル・不要ファイルの無視 | `.` で始まるファイル名、`.gitkeep`、`.DS_Store` はスキップされ、コピーも Build への追加も行われません |
| Build への自動追加 | ファイルは `proj.AddFile` + `proj.AddFileToBuild` によってプロジェクトに追加されます |
| 検索パスの自動追加 | `.framework` / `.xcframework` をコピーすると `FRAMEWORK_SEARCH_PATHS` が、`.h` には `HEADER_SEARCH_PATHS` が、`.a` には `LIBRARY_SEARCH_PATHS` が自動的に追加されます。プレフィックスは `$PROJECT_DIR` です |
| bundle のメインターゲットへの同時追加 | `folders` 内の `.bundle` で終わる項目は、対象ターゲットに加えて `AddFileToBuild(mainTargetGuid, fileGuid)` によって Unity メインターゲットにも追加されます |
| フォルダー全体をフレームワークとして扱う | `folders` のコピー先パスが `.framework` / `.xcframework` / `.bundle` / `.a` で終わる場合、ディレクトリ全体が単一のライブラリファイルとしてビルドに追加され、再帰的に展開されません |

ファイルコピーの中核となる実装:

```csharp
private static void CopyFile(PBXProject proj, string targetGuid, string xcodePath, string src, string des)
{
    bool needCopy = IsNeedCopy(src);
    if (needCopy)
    {
        File.Copy(src, des, true);
        proj.AddFileToBuild(targetGuid, proj.AddFile(des, des.Replace(xcodePath + "/", ""), PBXSourceTree.Absolute));
        AutoAddSearchPath(proj, xcodePath, targetGuid, des);
        Debug.Log("copy file " + src + " -> " + des);
    }
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L42-L52)

フォルダー再帰コピーの中核となる実装(先にコピー先を空にしてから再作成):

```csharp
private static void CopyFolder(string srcPath, string dstPath)
{
    if (Directory.Exists(dstPath))
    {
        Directory.Delete(dstPath, true);
    }

    if (File.Exists(dstPath))
    {
        File.Delete(dstPath);
    }

    Directory.CreateDirectory(dstPath);

    foreach (var file in Directory.GetFiles(srcPath))
    {
        if (IsNeedCopy(Path.GetFileName(file)))
        {
            File.Copy(file, Path.Combine(dstPath, Path.GetFileName(file)));
        }
    }

    foreach (var dir in Directory.GetDirectories(srcPath))
    {
        CopyFolder(dir, Path.Combine(dstPath, Path.GetFileName(dir)));
    }
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L172-L198)

## よくあるバリエーション

- **SDK / スタティックライブラリのコピー**:`.framework`、`.xcframework`、`.a` を `folders` に配置し、コピー先パスは `Frameworks/xxx.framework` と直接記述します。フレームワークは Link Binary With Libraries に追加され、検索パスも自動的に補完されます(`AddFrameworkToProject(targetGuid, root, false)`)。`.a` スタティックライブラリはリンクフェーズのみに追加されます。
- **リソース bundle のコピー**:`folders` 内の `.bundle` で終わるディレクトリは、Unity メインターゲットと UnityFramework ターゲットの両方に追加され、パッケージと一緒に配布する必要があるリソースに適しています。
- **ファイルをプロジェクトに入れるだけでコンパイルには参加させない細かい調整**：コピー完了後、同階層の `filesCompileFlag` 設定でコンパイルフラグを設定できます。このステップはコピーの後に実行されます(`SetFilesCompileFlag`)。

## よくあるエラー

| 問題 | 原因 | 回避策 |
|------|------|------|
| コピー後に Xcode でファイルが見つからない | コピー元パスが絶対パスになっていた、または相対階層が誤っている | `files`/`folders` の Key は Unity プロジェクトのルートディレクトリからの相対パスで、実行時には `Path.Combine(Environment.CurrentDirectory, key)` が使用されます |
| 一部のファイルがいつまでもコピーされない | `IsNeedCopy` の除外ルールに該当している | `.` で始まるファイル名、`.gitkeep`、`.DS_Store` は直接スキップされるため、名前を変更するか移動してください |
| ビルドのたびにコピー先ディレクトリの内容が「失われる」 | `CopyFolder` が先に `Directory.Delete(dstPath, true)` でコピー先ディレクトリを空にする | `folders` 設定のコピー先ディレクトリに他の内容を手動で入れないでください |
| 単一ファイルのコピーで「コピー先が既に存在する」例外が発生して反映されない | 実際には発生しません。単一ファイルのコピーには `overwrite: true` が付いています | それでも失敗する場合は、コピー先に同名のフォルダーが存在していないか確認してください(ディレクトリとして扱われます) |
| フレームワークのリンクで見つからないというエラー | 自動検索パスのロジックが適用されていない | `.framework` / `.xcframework` / `.a` で終わることを確認してください。`AutoAddSearchPath` はこの3種類の拡張子にのみ有効です |

## 背景

コピーは Xcode プロジェクトの生成後に行われます:`PostProcessBuildHelper` は PBXProject とマージ後の設定を読み込み、`Run` が properties、frameworks、libs、files、folders 等を順番に処理します。`CopyFolders` が追加で `mainTargetGuid` を受け取るのは、`.bundle` を Unity メインターゲットにも同時に登録できるようにするためです。ファイルパスはすべて `PBXSourceTree` に基づいており、フレームワーク/スタティックライブラリには `Source`、単一ファイルには `Absolute` が使用されます。
