# リスナーの正しい解除方法

リスナーを正しく解除することで、MonoBehaviour が破棄された後もフレームワークからコールバックされ続けることを防ぎ、`NullReferenceException`、メモリリーク、重複実行を回避できます。このページでは、GameFrameX Mono モジュールが提供する解除 API と使用ルールについて説明します。

## 前提条件

- `GameFrameX.Mono.Runtime.MonoComponent` または `MonoManager` を通じてリスナーを登録済みであること
- C# の `Action` / `Action<T>` デリゲートの参照セマンティクスを理解していること(解除には登録時と同じインスタンスを渡す必要がある)

## 操作手順

### 1. 対応する解除 API を選択する

GameFrameX Mono モジュールは [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L120-L238) で、各ライフサイクルイベントに対して登録/解除メソッドのペアを提供しています。

| ライフサイクル | 登録メソッド | 解除メソッド |
|---------|---------|---------|
| Update | `AddUpdateListener` | `RemoveUpdateListener` |
| FixedUpdate | `AddFixedUpdateListener` | `RemoveFixedUpdateListener` |
| LateUpdate | `AddLateUpdateListener` | `RemoveLateUpdateListener` |
| OnDestroy | `AddDestroyListener` | `RemoveDestroyListener` |
| OnApplicationPause | `AddOnApplicationPauseListener` | `RemoveOnApplicationPauseListener` |
| OnApplicationFocus | `AddOnApplicationFocusListener` | `RemoveOnApplicationFocusListener` |

### 2. MonoBehaviour の OnDestroy / OnDisable で解除する

推奨される解除の場所は `OnDestroy`(オブジェクトが破棄される時)または `OnDisable`(オブジェクトが無効化される時、破棄前の統一的なタイミング)です。解除処理を `OnDestroy` 内に記述することで、GameObject のライフサイクル終了時にリスナーが確実にクリーンアップされます。

```csharp
using System;
using GameFrameX.Mono.Runtime;
using UnityEngine;

public class PlayerController : MonoBehaviour
{
    private Action<float, float> _onUpdate;
    private Action<float, float> _onLateUpdate;
    private Action _onDestroyCallback;

    private void OnEnable()
    {
        var monoComponent = MonoComponent.Instance;
        if (monoComponent == null) return;

        _onUpdate = HandleUpdate;
        _onLateUpdate = HandleLateUpdate;
        _onDestroyCallback = HandleDestroy;

        monoComponent.AddUpdateListener(_onUpdate);
        monoComponent.AddLateUpdateListener(_onLateUpdate);
        monoComponent.AddDestroyListener(_onDestroyCallback);
    }

    private void OnDestroy()
    {
        var monoComponent = MonoComponent.Instance;
        if (monoComponent == null) return;

        monoComponent.RemoveUpdateListener(_onUpdate);
        monoComponent.RemoveLateUpdateListener(_onLateUpdate);
        monoComponent.RemoveDestroyListener(_onDestroyCallback);
    }

    private void HandleUpdate(float elapse, float realElapse) { /* ... */ }
    private void HandleLateUpdate(float elapse, float realElapse) { /* ... */ }
    private void HandleDestroy() { /* ... */ }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs) · [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L125-L136)

### 3. 解除時に渡すデリゲートは登録時と同じインスタンスであること

`MonoManager` の解除実装は `LinkedList<T>.Remove(action)` の参照比較に基づいているため、`null`、匿名ラムダ、新しいメソッドを渡すと失敗します。

```csharp
// ✅ 正しい：フィールドに保存した同じデリゲートインスタンスを使用する
monoComponent.RemoveUpdateListener(_onUpdate);

// ❌ 間違い：新しく作成したラムダは、論理的に同じでもマッチしない
monoComponent.RemoveUpdateListener((e, r) => HandleUpdate(e, r));

// ❌ 間違い：null を渡すと例外が発生する
monoComponent.RemoveUpdateListener(null);
```

解除メソッドは `null` が渡された場合、`ArgumentNullException(nameof(action))` をスローします。詳細は [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L127-L131) を参照してください。

## よくあるバリエーション

### OnDisable で必要に応じてクリーンアップする

オブジェクトが頻繁に Enable / Disable される場合(プールされたオブジェクトなど)、`OnDisable` で解除することで、無効化された時点で直ちにコールバックを停止できます。

```csharp
private void OnDisable()
{
    if (_onUpdate != null)
    {
        MonoComponent.Instance?.RemoveUpdateListener(_onUpdate);
    }
}
```

### MonoManager を直接使用する(MonoComponent を使用しない場合)

`MonoComponent` を使用しない場合は、`GameFrameworkEntry.GetModule<IMonoManager>()` を通じて直接マネージャーを取得して解除できます。

```csharp
var mono = GameFrameworkEntry.GetModule<IMonoManager>();
mono.RemoveUpdateListener(_onUpdate);
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs)

## よくあるエラー

- **リスナーを解除しなかったことによる NullReferenceException**:オブジェクトが破棄された後も Update キューに残り、コールバック実行時に破棄済みオブジェクトのフィールドにアクセスすると例外がスローされます。`OnDestroy` / `OnDisable` で必ず解除してください。
- **解除時に異なるデリゲートインスタンスを渡す**:`LinkedList<T>.Remove` は参照で比較されるため、新しいラムダやメソッドグループの変換は異なるインスタンスとなり、解除に失敗します。
- **同一コールバックを複数回登録する**:`AddUpdateListener` は重複を除去しないため、同じフィールドを繰り返し追加するとコールバックが複数回実行されます。取り消す際も対応する回数の `RemoveUpdateListener` を呼び出す必要があります。
- **解除メソッドに `null` を渡す**:`MonoManager` のすべての Remove メソッドは `ArgumentNullException` をスローするため、解除前にデリゲートフィールドが null でないことを確認する必要があります。

## 背景(オプション)

`MonoManager` は内部的に `LinkedList<Action>` を使用して各種コールバックを保存しており、登録時には `AddLast`、解除時には `Remove(action)` が呼び出されます。これらの操作はスレッド安全性を保証するため `lock (Lock)` 内で実行されます。解除が失敗する根本原因は `LinkedList<T>.Remove` が参照の同一性に依存しているためであり、これがインラインのラムダではなくデリゲートフィールドを保存しなければならない理由です。
