# AssemblyResourceProvider를 구성하여 리소스를 제공하는 방법

`AssemblyResourceProvider`는 GameFrameX 로컬라이제이션 프레임워크의 어셈블리 수준 리소스 공급자이며, .NET 어셈블리에 포함된 `.resources` 파일에서 로컬라이제이션 문자열을 로드하고 처음 액세스할 때 지연 로드합니다. 로드가 완료되면 내장 리소스처럼 `LocalizationService.GetString(...)`을 통해 문자열을 가져올 수 있습니다. 이 페이지에서는 사용자 지정 어셈블리에서 리소스 파일을 준비하고, 해당 공급자를 생성하며, `ResourceManager`에 연결하는 방법을 설명합니다.

## 사전 조건

- `GameFrameX.Foundation.Localization` NuGet 패키지가 설치되어 있어야 합니다.
- 대상 프로젝트는 .NET 어셈블리이며, `.resx`는 `EmbeddedResource`로 어셈블리 매니페스트에 포함되어야 합니다(그렇지 않으면 `GetManifestResourceNames()`가 이러한 항목을 반환하지 않으며 공급자가 아무것도 스캔할 수 없습니다).

## 작업 단계

1. 프로젝트에서 규약에 따라 `.resx` 파일을 생성합니다. 기본 규약은 `Localization/Messages/` 디렉터리에 배치하며, 파일 이름은 문화권별로 구분합니다(특정 명명 규칙은 아래 참조).

   ```text
   {AssemblyName}/
   └── Localization/
       └── Messages/
           ├── Resources.resx         # 기본/영어 폴백
           ├── Resources.zh-CN.resx   #简体中文
           └── Resources.en-US.resx   # 미식 영어
   ```

   출처: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L216-L223)

2. `.csproj`에서 명시적으로 `.resx`를 `EmbeddedResource`로 표시하고, 필요에 따라 기본 암시적 포함을 비활성화하여 컴파일러의 자동 동작에 의존하지 않도록 합니다:

   ```xml
   <PropertyGroup>
     <EnableDefaultEmbeddedResourceItems>false</EnableDefaultEmbeddedResourceItems>
   </PropertyGroup>

   <ItemGroup>
     <EmbeddedResource Include="Localization\Messages\*.resx" />
   </ItemGroup>
   ```

   출처: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L110-L118)

3. 명명 규약에 따라 리소스 파일의 이름을 지정하여 공급자가 `baseName`을 올바르게 구문 분석할 수 있도록 합니다. 프레임워크가 인식하는 매니페스트 리소스 이름 규칙은 다음과 같습니다(`TryGetBaseName`에서 가져옴):

   | 매니페스트 리소스 이름 예시 | 구문 분석된 baseName | 용도 |
   |---|---|---|
   | `MyApp.Localization.Messages.Resources.resources` | `MyApp.Localization.Messages.Resources` | 기본 문화권 |
   | `MyApp.Localization.Messages.Resources.zh-CN.resources` | `MyApp.Localization.Messages.Resources` | 특정 문화권 `zh-CN` |
   | `MyApp.CustomPath.Resources.resources` | `MyApp.CustomPath.Resources` | 사용자 지정 경로 기본 문화권 |
   | `MyApp.CustomPath.Resources.en.resources` | `MyApp.CustomPath.Resources` | 사용자 지정 경로 중립 문화권 |
   | `MyApp.Category.resources` | `MyApp.Category` | 이전 버전과의 호환을 위한 3단 형식 |

   규칙 요점: `.resources`로 끝나며, 마지막에서 두 번째 세그먼트가 `Resources`이거나 합법적인 문화권 이름(`-`를 포함하거나 `CultureInfo.GetCultureInfo`로 인식 가능)이어야 합니다. 인식되려면 세그먼트 수가 ≥ 3이어야 합니다.

   출처: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L282-L330)

4. 코드에서 공급자를 생성하고 로드를 트리거합니다. `AssemblyResourceProvider`는 `IDisposable`이므로 사용 후 해제해야 합니다.

   ```csharp
   using System.Reflection;
   using GameFrameX.Foundation.Localization.Providers;

   var assembly = Assembly.GetExecutingAssembly();
   using var provider = new AssemblyResourceProvider(assembly);

   // 선택 사항: 지연 로드를 미리 트리거하여 첫 번째 액세스 지연 방지
   provider.EnsureLoaded();

   string message = provider.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   출처: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L104-L138)

5. `ResourceManager`에 연결하여 통합 해석 체인에 포함시킵니다. `ResourceManager`는 "사용자 지정 → 어셈블리 → 기본" 순서로 검색하며, 프레임워크가 모든 어셈블리 공급자를 자동으로 검색하도록 하거나, 초기화 후 지정된 어셈블리를 수동으로 등록할 수 있습니다:

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // 방법 1: ResourceManager가 현재 로드된 어셈블리를 자동으로 검색하도록 함
   LocalizationService.EnsureLoaded();

   // 방법 2: 지정된 어셈블리를 수동으로 추가
   LocalizationService.AddAssembly(Assembly.GetExecutingAssembly());

   var msg = LocalizationService.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   출처: [ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L370-L450)

## 일반적인 변형

- **중립 문화권 이름**(예: `zh`, `fr`): 마지막에서 두 번째 세그먼트가 중립 문화권 이름일 때, `IsCultureSegment`는 `CultureInfo.GetCultureInfo`를 통해 유효성을 검사하여 `MyApp`과 같은 카테고리 이름을 문화권 이름으로 잘못 판단하지 않도록 합니다.

  출처: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L332-L360)

- **사용자 지정 경로**(`Localization/Messages/`가 아닌 경우): `{AssemblyName}.{임의 경로}.Resources[.{culture}].resources`의 세그먼트 구조를 충족하기만 하면 인식됩니다. 예를 들어 `MyApp.LangPack.Resources.zh-CN.resx` → baseName `MyApp.LangPack.Resources`.

  출처: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L256-L268)

- **키를 찾을 수 없을 때의 폴백**: 모든 `GetString` 호출이 모든 `ResourceManager`에서 일치하는 항목을 찾지 못하면, 예외를 발생시키지 않고 직접 입력된 `key` 문자열을 반환합니다.

  출처: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L146-L178)

## 일반적인 오류

- **리소스가 적용되지 않음**: 가장 일반적인 원인은 `.resx`가 `EmbeddedResource`로 포함되지 않았거나, 파일 이름이 위의 명명 규칙을 충족하지 않는 것입니다. `assembly.GetManifestResourceNames()`를 실행하여 매니페스트에 예상 이름이 포함되어 있는지 확인합니다.
- **동일한 어셈블리에 동일한 이름의 baseName이 여러 개 있음**: `LoadResources`는 `BaseName`을 기준으로 중복을 제거하며, 일치하는 첫 번째 `ResourceManager`만 유지하고 후속 동일한 이름의 항목은 무시됩니다.
- **`GetString`이 `MissingManifestResourceException`을 발생시킴**: 코드는 이를 포착하고 다른 `ResourceManager`를 계속 검색하므로 일반적으로 전파되지 않습니다. 로그에 `Failed to load resource '{key}'`이 표시되면 모든 일치 항목이 실패한 것이며, 폴백으로 `key`를 반환합니다.
- **어셈블리 검색 실패**: 전체 검색은 `try/catch`로 감싸여 `Debug.WriteLine`에 기록되며 예외를 발생시키지 않습니다. 그러나 `_isInitialized`는 반복적인 재시도를 방지하기 위해 `true`로 표시되므로, 근본 원인을 찾으려면 디버그 출력을 확인해야 합니다.

  출처: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L204-L279)

## 배경(선택 사항)

`AssemblyResourceProvider`는 `ILazyResourceProvider`, `ICultureResourceProvider`, `IDisposable`를 구현합니다. 생성 시 리소스를 즉시 로드하지 않으며, `EnsureLoaded()` 또는 `GetString()`을 처음 호출할 때 어셈블리 매니페스트를 스캔하고 `baseName`을 기준으로 중복을 제거하여 `ResourceManager`를 생성합니다. `ResourceManager`는 `assembly.FullName`을 키로 사용하는 `ConcurrentDictionary<string, AssemblyResourceProvider>`를 유지 관리하며, 외부에는 "사용자 지정 공급자 > 어셈블리 공급자 > 기본 공급자"의 우선순위 체인을 제공합니다. 전체 리소스 해석 체인 및 통계 인터페이스에 대해서는 [ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs)를 참조하십시오.
