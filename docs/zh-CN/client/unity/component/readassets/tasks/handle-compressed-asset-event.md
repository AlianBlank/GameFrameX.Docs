# 处理 Android 压缩 StreamingAsset 事件

当 APK 构建（特别是 App Bundle）中 `StreamingAssets` 目录下的文件被 APK 压缩存储时,Unity 无法直接通过文件偏移读取。本框架会在初始化时扫描 APK 的 Central Directory,发现此类文件后触发 `CompressedStreamingAssetFound` 事件,允许你在运行时拦截并处理。

## 前置条件

- 仅在 `UNITY_ANDROID` 或 `UNITY_EDITOR`(使用 `InitializeWithExternalApk`)平台下,事件签名才会真实存在;其它平台 `add`/`remove` 为空操作。
- 项目已通过 `BlankReadAssets.Initialize()` 或 `BlankReadAssets.Root` 完成初始化(首次访问任意 API 时会自动触发)。

## 操作步骤

1. **订阅事件**。事件签名是 `Func<string, bool>`,接收 APK 中的文件全名(如 `"assets/config/data.json"`),返回 `true` 表示你已处理,框架不再报警告:

```csharp
using GameFrameX.ReadAssets.Runtime;

BlankReadAssets.CompressedStreamingAssetFound += fileName =>
{
    // fileName 形如 "assets/xxx.bin"
    if (fileName.EndsWith(".json"))
    {
        // 你的兜底逻辑:从远端下载 / 从 persistentDataPath 拷贝 / 内置默认值等
        Debug.Log($"处理被压缩的 StreamingAsset: {fileName}");
        return true;
    }
    return false;
};
```

2. **在初始化之前订阅**。事件是在 `ApkImpl.Initialize` → `GetStreamingAssetsInfoFromJar` 扫描 APK 时触发的,所以订阅必须早于首次读取,推荐放在 `RuntimeInitializeOnLoadMethod` 中:

```csharp
using UnityEngine;
using GameFrameX.ReadAssets.Runtime;

public static class Bootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSplashScreen)]
    private static void Init()
    {
        BlankReadAssets.CompressedStreamingAssetFound += OnCompressed;
    }

    private static bool OnCompressed(string fileName)
    {
        // 返回 true 表示"已处理",框架会静默
        return false;
    }
}
```

3. **(可选)在 Editor 中验证**。通过 `InitializeWithExternalApk` 加载一个真实 APK 即可在编辑器里触发同一条事件,方便联调:

```csharp
BlankReadAssets.InitializeWithExternalApk(@"C:\builds\game.apk");
```

事件与 `InitializeWithExternalApk` 共用同一份 `ApkImpl` 扫描逻辑([BlankReadAssets.ApkImpl.cs#L294-L354](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L294-L354))。

## 常见变体

- **不想订阅,只想静默**。实现分部方法 `AndroidIsCompressedFileStreamingAsset`,返回 `false` 让框架直接忽略该文件,不进入事件分发,也不打日志:

```csharp
using GameFrameX.ReadAssets.Runtime;
using UnityEngine;

public partial class BlankReadAssets
{
    static partial void AndroidIsCompressedFileStreamingAsset(string fileName, ref bool isStreamingAsset)
    {
        // 比如屏蔽某类资源
        if (fileName.StartsWith("assets/internal/")) isStreamingAsset = false;
    }
}
```

分部方法的声明位置见 [BlankReadAssets.ApkImpl.cs#L334](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L334)。

- **App Bundle 场景**。如果项目本身就是 App Bundle(`*.aab`)上传 Google Play 后展开为多 `.apk` 拆分件,框架在 `dataPath` 不是 `base.apk` 时会自动回退到同目录下的 `base.apk` 重新扫描([BlankReadAssets.ApkImpl.cs#L43-L51](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L43-L51));此分支仍然会触发同一事件,订阅代码无需修改。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `Debug.LogAssertionFormat` 持续报 `BlankReadAssets: file ... is where Streaming Assets are put, but is compressed.` | 没人订阅事件,也没实现分部方法过滤 | 订阅 `CompressedStreamingAssetFound` 或实现 `AndroidIsCompressedFileStreamingAsset` |
| iOS / Standalone 下写 `BlankReadAssets.CompressedStreamingAssetFound += ...` 直接报编译错误 | 该事件只在 `UNITY_EDITOR || UNITY_ANDROID` 下有真实签名 | 用 `#if UNITY_ANDROID || UNITY_EDITOR` 包住订阅代码;或忽略(其它平台为 no-op) |
| 订阅时机太晚,启动后立刻就触发了一次 | 事件在 `Initialize` 内部同步触发 | 用 `[RuntimeInitializeOnLoadMethod(BeforeSplashScreen)]` 或更早的 bootstrap 订阅 |
| 误以为返回 `false` 会抛出异常 | 返回 `false` 仅表示"未处理",框架会按无订阅路径继续处理(可能打断言) | 真正处理了就返回 `true` |

## 背景(可选)

Unity 在打包 Android 时默认会对 APK 中超过阈值的 `assets/` 文件做整体压缩;但 `BlankReadAssets` 通过 ZIP Central Directory 直接定位 `StreamingAssets` 内文件的偏移 + 未压缩大小,只有当 APK 内该文件被压缩(`CompressedSize != UncompressedSize`)时,这种"按偏移读原字节"的策略会失败。事件机制因此被设计出来:让业务侧决定对被压缩的资产如何兜底([BlankReadAssets.cs#L70-L78](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L70-L78))。
