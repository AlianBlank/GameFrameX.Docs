# 常見問題

本文件收集了使用 CoroutineComponent 協程組件時常見的問題及解決方案。

## 概述

CoroutineComponent 是 GameFrameX 框架的協程管理組件，擴充套件了 Unity 內建的協程功能，提供更好的協程生命週期管理和記憶體安全控制。該組件使用 `ConcurrentDictionary` 執行緒安全字典來跟蹤所有執行的協程，確保可以隨時管理和停止協程。

> 詳細使用說明請參考 [使用指南](./3-getting-started.index) 和 [API 參考](./4-api-reference.coroutine-component)。

## 常見問題列表

### Q1: 為什麼在同一 GameObject 上無法新增多個 CoroutineComponent？

**問題描述：**
在同一個 GameObject 上嘗試新增第二個 CoroutineComponent 時，Unity 編輯器報錯或無法新增。

**原因：**
CoroutineComponent 使用了 `[DisallowMultipleComponent]` 屬性，該屬性禁止在同一 GameObject 上新增多個相同型別的組件。

**解決方案：**
- 確保每個 GameObject 只有一個 CoroutineComponent 例項
- 如果需要管理多個協程，請在同一個 CoroutineComponent 例項上啟動多個協程
- 使用 `StopAllCoroutines()` 方法停止所有協程

```csharp
// 正確用法：在同一個組件上管理多個協程
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(CoroutineA());
coroutineComponent.StartCoroutine(CoroutineB());
coroutineComponent.StopAllCoroutines(); // 停止所有協程
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L10-L11)

### Q2: StartCoroutine 傳入 null 列舉器會怎樣？

**問題描述：**
向 `StartCoroutine` 方法傳入 `null` 值的 IEnumerator 時會發生什麼？

**原因：**
如果向 `StartCoroutine` 傳入 null 列舉器，Unity 底層會丟擲空引用異常。

**解決方案：**
- 在啟動協程前始終檢查列舉器是否為 null
- 新增空值保護邏輯

```csharp
IEnumerator myCoroutine = GetSomeCoroutine(); // 可能是 null

if (myCoroutine != null)
{
    coroutineComponent.StartCoroutine(myCoroutine);
}
```

### Q3: 如何正確停止一個正在執行的協程？

**問題描述：**
呼叫 `StopCoroutine` 後協程似乎仍在執行，或者無法停止協程。

**原因：**
- 傳入的 IEnumerator 與啟動時的列舉器不是同一個引用
- 協程已經執行完畢
- 協程在 StopCoroutine 呼叫前已經結束

**解決方案：**
- 儲存啟動協程時返回的 IEnumerator 引用
- 使用 `StopAllCoroutines()` 停止所有協程
- 確保在協程執行過程中及時停止

```csharp
// 儲存協程引用
IEnumerator myCoroutine = coroutineComponent.StartCoroutine(MyLongRunningTask());

// 在適當的時機停止
coroutineComponent.StopCoroutine(myCoroutine);

// 或者停止所有協程
coroutineComponent.StopAllCoroutines();
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L32-L45)

### Q4: 組件掛載的 GameObject 被銷燬後會發生什麼？

**問題描述：**
當包含 CoroutineComponent 的 GameObject 被銷燬時，正在執行的協程會怎樣？

**原因：**
當 GameObject 被銷燬時，Unity 會自動停止該 GameObject 上的所有協程。CoroutineComponent 繼承自 MonoBehaviour，因此也會遵循這一行為。

**建議：**
- 在場景切換或物件銷燬前，手動呼叫 `StopAllCoroutines()` 確保協程乾淨停止
- 使用 OnDestroy 生命週期鉤子進行清理

```csharp
private void OnDestroy()
{
    // 確保在物件銷燬前停止所有協程
    if (coroutineComponent != null)
    {
        coroutineComponent.StopAllCoroutines();
    }
}
```

### Q5: WaitForEndOfFrameFinish 的回呼傳入 null 會崩潰嗎？

**問題描述：**
向 `WaitForEndOfFrameFinish` 方法傳入 null 回呼會發生什麼？

**原因：**
CoroutineComponent 使用了空值合併運算子 `callback?.Invoke()`，因此傳入 null 回呼不會導致崩潰，呼叫會被安全地忽略。

**原始碼驗證：**
```csharp
public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(_WaitForEndOfFrameFinish(callback));
}

private IEnumerator _WaitForEndOfFrameFinish(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke(); // 使用 ?. 運算子安全呼叫
}
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L97)

### Q6: 如何在幀渲染結束後執行邏輯？

**問題描述：**
需要在 Unity 每幀渲染結束後執行某些操作，應該如何使用？

**解決方案：**
使用 `WaitForEndOfFrameFinish` 方法，該方法會在當前幀的渲染完成後執行回呼。

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    // 這個回呼會在幀渲染結束後執行
    Debug.Log("幀渲染結束，執行邏輯");
});
```

**適用場景：**
- 在 UI 渲染後獲取螢幕截圖
- 在物理計算完成後執行某些操作
- 需要在幀末尾進行狀態同步

### Q7: CoroutineComponent 是執行緒安全的嗎？

**問題描述：**
CoroutineComponent 可以在多執行緒環境中使用嗎？

**原因：**
是的，CoroutineComponent 使用了 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 來儲存協程對映，該資料結構是執行緒安全的。

**注意事項：**
- 雖然內部儲存是執行緒安全的，但協程本身在 Unity 主執行緒上執行
- 多執行緒訪問時，主要需要考慮的是 IEnumerator 引用的正確傳遞

### Q8: 協程未正確停止導致記憶體洩漏如何處理？

**問題描述：**
協程未正確停止可能導致記憶體洩漏，如何預防？

**原因：**
如果不正確停止協程，特別是包含無限迴圈或長時間等待的協程，可能會導致記憶體洩漏。CoroutineComponent 透過維護協程對映表來幫助管理這個問題。

**解決方案：**
- 使用 `StopAllCoroutines()` 清理所有協程
- 在組件銷燬時確保呼叫 `StopAllCoroutines()`
- 使用具有明確結束條件的協程

```csharp
private void OnDestroy()
{
    // 重要：確保停止所有協程防止記憶體洩漏
    StopAllCoroutines();
}
```

### Q10: CoroutineComponent 需要手動新增到 GameObject 嗎？

**問題描述：**
為什麼組件沒有自動新增到場景中？

**原因：**
CoroutineComponent 在 `Awake` 方法中設定了 `IsAutoRegister = false`，這意味著組件不會自動註冊到框架的自動註冊系統中。

**解決方案：**
需要手動將 CoroutineComponent 新增到 GameObject 上：

```csharp
// 手動新增組件
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();

// 或者在 Unity 編輯器中手動新增
// 1. 選擇 GameObject
// 2. 點選 Add Component
// 3. 搜尋 "Game Framework/Coroutine"
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L99-L103)

### Q11: 如何在 Unity 編輯器中找到 CoroutineComponent？

**問題描述：**
在 Unity 編輯器中如何新增 CoroutineComponent？

**解決方案：**
由於組件使用了 `[AddComponentMenu("Game Framework/Coroutine")]` 屬性，您可以透過以下方式新增：

1. 在 Unity 編輯器中選擇 GameObject
2. 右鍵點選 Inspector 面板 → Add Component
3. 在搜尋框中輸入 "Coroutine" 或 "Game Framework/Coroutine"
4. 選擇 CoroutineComponent

> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12)

## 診斷步驟

如果遇到無法解決的問題，請按以下步驟進行診斷：

1. **檢查 GameObject 狀態**：確認 GameObject 和組件是否已啟用
2. **檢查協程引用**：確認用於停止協程的 IEnumerator 引用是否正確
3. **檢視 Unity 控制檯**：檢查是否有錯誤或警告資訊
4. **使用 StopAllCoroutines**：作為除錯手段，先停止所有協程排查問題
5. **檢查場景切換**：確認場景切換時協程是否被正確清理
