# How to Enable Request Logging and Use the Inspector

In the Unity menu bar under `GameFrameX/Scripting Define Symbols`, check "Enable Web Send/Receive Log Printing" and wait for the scripts to recompile. After that, every HTTP request sent by `WebManager` and every response received will be printed to the Console via `Log.Debug`; when a GameObject with `WebComponent` attached is selected, the Inspector additionally provides a 0–120 second `Timeout` slider for adjusting the request timeout.

## Prerequisites

- The project has the `com.gameframex.unity.web` package installed and the Web components initialized.
- The Console panel's log level must allow Debug logs to be displayed; otherwise, no output will be visible even after enabling the macros.

## Steps: Enable Request Logging

1. Open the Unity top menu `GameFrameX/Scripting Define Symbols`.
2. Click the following menu items as needed (clicking takes effect immediately; the macro is written into the Scripting Define Symbols of the current Build Target):

| Menu Item | Purpose | Macro Written |
|------|------|---------|
| `Enable Web Send Logs(开启Web发送日志打印)` | Prints the URL, Header, and Form of each request | `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` |
| `Disable Web Send Logs(关闭Web发送日志打印)` | Removes the send log macro | — |
| `Enable Web Receive Logs(开启Web接收日志打印)` | Prints the URL, Header, Form, and Content of each response | `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` |
| `Disable Web Receive Logs(关闭Web接收日志打印)` | Removes the receive log macro | — |

3. Wait for Unity to recompile the scripts (wait until the spinner in the bottom-right corner finishes).
4. Make any Web request (e.g., via `WebManager`'s Get/Post interfaces), and Debug logs such as `Web Request: ...` and `Web Response: ...` will appear in the Console.

The implementation behind these menu items is simply adding and removing macro definitions:

```csharp
public static class WebLogScriptingDefineSymbols
{
    public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG";
    public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_SEND_LOG";

    [MenuItem("GameFrameX/Scripting Define Symbols/Enable Web Send Logs(开启Web发送日志打印)", false, 451)]
    public static void EnableNetworkSendLogs()
    {
        ScriptingDefineSymbols.AddScriptingDefineSymbol(EnableNetworkSendLogScriptingDefineSymbol);
    }
}
```

## Steps: Use the WebComponent Inspector

1. In the Hierarchy, select the GameObject with the `WebComponent` component attached.
2. A `Timeout` slider appears at the bottom of the Inspector panel, with a value range of 0–120.
3. Drag the slider:
   - **In Play Mode**: writes directly to the runtime object `t.Timeout`, taking effect immediately for subsequent requests.
   - **Outside Play Mode**: writes to the serialized property `m_Timeout`, which is saved with the scene/prefab.

```csharp
[CustomEditor(typeof(WebComponent))]
internal sealed class WebComponentInspector : ComponentTypeComponentInspector
{
    public override void OnInspectorGUI()
    {
        base.OnInspectorGUI();
        serializedObject.Update();

        WebComponent t = (WebComponent)target;
        float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
        if (timeout != m_Timeout.floatValue)
        {
            if (EditorApplication.isPlaying)
            {
                t.Timeout = timeout;
            }
            else
            {
                m_Timeout.floatValue = timeout;
            }
        }

        serializedObject.ApplyModifiedProperties();
    }
}
```

Source: [Editor/Inspector/WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/Inspector/WebComponentInspector.cs#L7-L37)

> `WebComponentInspector` inherits from `ComponentTypeComponentInspector`, so the Inspector also retains the dropdown for selecting the `IWebManager` implementation type on the component (`RefreshComponentTypeNames(typeof(IWebManager))`).

## Common Variants

- **View requests only, without responses**: click only `Enable Web Send Logs`; the two macros are independent of each other and can be combined freely.
- **Manage macros manually**: you can also directly enter `ENABLE_GAMEFRAMEX_WEB_SEND_LOG;ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` in `Project Settings → Player → Scripting Define Symbols`, which has the same effect as using the menu.
- **Timeout behavior**: the value written by the `Timeout` slider is applied to requests in seconds (WebGL) or milliseconds (non-WebGL) in `WebManager`; see `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;` and `request.Timeout = (int)RequestTimeout.TotalMilliseconds;` in `Runtime/Web/WebManager.cs`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| No `Web Request/Web Response` logs in the Console after clicking the menu | The Console panel is filtering out Debug-level logs | Check Debug/Info in the filter at the top-right corner of the Console |
| Logs only appear on some platforms | Macros take effect per Build Target; they must be re-enabled after switching platforms | Re-run the menu items after switching platforms |
| Requests still use the old timeout after changing the slider | Outside Play Mode, changes only write to `m_Timeout`; you need to re-enter Play or save the scene | Adjust in Play Mode, or save the scene and re-enter Play |
| Log content does not include `Form`/`Header` | The request itself carries no form or headers | Check the header/form parameters passed by the caller |

## Verification

1. After `GameFrameX/Scripting Define Symbols → Enable Web Send Logs`, make any GET request.
2. If `Web Request: {URL} \n Header: ... \n Form: ...` appears in the Console, the send log is in effect; if `Web Response: ... \n Content: ...` appears after a response is received, the receive log is in effect.
3. In Play Mode, drag the Inspector's `Timeout` slider and make a request; observe whether the request duration or timeout exceptions in the logs change accordingly.

## Background

Request logging wraps `Log.Debug` calls with the conditional compilation macros `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`. When the macros are disabled, the code is completely excluded from the compiled output, so no performance overhead is left in release builds; this is also why the menu toggle needs to trigger a script recompilation. On the Inspector side, the `Timeout` slider uses `EditorGUILayout.Slider` to distinguish between the Play and non-Play write paths, ensuring that runtime hot-adjustment and scene serialization do not interfere with each other.
