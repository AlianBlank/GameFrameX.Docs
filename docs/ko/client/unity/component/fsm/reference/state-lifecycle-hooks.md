# 상태 생명주기 훅 레퍼런스

이 페이지에는 `FsmState<T>`에서 제공하는 모든 생명주기 콜백 메서드가收录되어 있으며, 시그니처, 트리거 시점, 일반적인 용도를 포함합니다. 모든 훅은 `Runtime/Fsm/FsmState.cs`에 정의되어 있으며, 기본값은 빈 메서드이므로 필요에 따라 재정의하면 됩니다.

## 훅 빠른 참조 표

| 훅 | 시그니처 | 트리거 시점 | 일반적인 용도 |
|------|------|----------|----------|
| `OnInit` | `protected internal virtual void OnInit(IFsm<T> fsm)` | 상태가 상태기에 처음 추가될 때 한 번 호출됨 | 일회성 리소스 준비, 데이터 캐싱, 이벤트 구독 |
| `OnEnter` | `protected internal virtual void OnEnter(IFsm<T> fsm)` | 해당 상태로 진입할 때 호출됨 | 진입 애니메이션 재생, 타이머 리셋, 로그 기록 |
| `OnUpdate` | `protected internal virtual void OnUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | 상태기 폴링 시 호출됨(매 프레임) | 전환 조건 검사, 시간 누적 |
| `OnFixedUpdate` | `protected internal virtual void OnFixedUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | 상태기 고정 폴링 시 호출됨 | 물리 관련 로직 |
| `OnLeave` | `protected internal virtual void OnLeave(IFsm<T> fsm, bool isShutdown)` | 해당 상태를 떠날 때 호출됨, 종료 시 `isShutdown`은 `true` | 임시 상태 정리, 전역 설정 복원 |
| `OnDestroy` | `protected internal virtual void OnDestroy(IFsm<T> fsm)` | 상태가 상태기에서 제거되거나 상태기가 파괴될 때 호출됨 | `OnInit`에서 보유한 리소스 해제 |

## 트리거 순서

정상 전환流程의 호출 순서는 `OnLeave(舊 상태, false)` → `OnEnter(新 상태)`입니다. 상태를 처음 추가할 때 `OnInit`이 한 번 더 트리거됩니다. 상태기가 파괴되거나 상태가 제거될 때는 `OnLeave(..., true)` → `OnDestroy` 순서로 트리거됩니다.

```csharp
// 소스 코드 발췌:Runtime/Fsm/Fsm.cs의 상태 전환의 전형적인 흐름
m_CurrentState.OnLeave(this, false);   // 舊 상태 이탈
m_CurrentState = state;
m_CurrentState.OnEnter(this);          // 新 상태 진입
```

## 시간 파라미터

`OnUpdate`과 `OnFixedUpdate`은 두 개의 시간 값을 받습니다.

| 파라미터 | 타입 | 의미 |
|------|------|------|
| `elapseSeconds` | `float` | 논리 경과 시간(초 단위), 시간 스케일의 영향을 받음 |
| `realElapseSeconds` | `float` | 실제 경과 시간(초 단위), 시간 스케일의 영향을 받지 않음 |

일시 정지/슬로우 모션 중에도 실제 시간에 맞춰 진행되어야 하는 로직(예: UI 카운트다운)은 `realElapseSeconds`을 사용해야 합니다.

## 상태 전환

훅 내부에서 다음 메서드를 통해 다른 상태로 전환을 요청할 수 있습니다.

```csharp
// 제네릭 버전:런타임 타입 안전
public void ChangeToState<TState>(IFsm<T> fsm) where TState : FsmState<T>

// 타입 버전:stateType은 반드시 FsmState<T>를 상속해야 함
protected void ChangeState(IFsm<T> fsm, Type stateType)
```

`ChangeState` 호출 시 `fsm`이 이미 무효화된 경우 `GameFrameworkException("FSM is invalid.")`을 던지고, `stateType`이 `null`인 경우 `"State type is invalid."`을 던지며, 타입이 일치하지 않는 경우 `"State type '{0}' is invalid."`을 던집니다.

Source: [Runtime/Fsm/FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L163)

## 최소 예제

```csharp
using GameFrameX.Fsm.Runtime;

public sealed class IdleState : FsmState<Player>
{
    protected internal override void OnEnter(IFsm<Player> fsm)
    {
        // 대기 상태 진입:애니메이션 재생, 타이머 리셋
        fsm.SetData<float>("StateEnterTime", Time.time);
    }

    protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // 전환 조건 검사
        if (fsm.Owner.MoveInput.sqrMagnitude > 0.01f)
        {
            ChangeToState<MoveState>(fsm);
        }
    }

    protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
    {
        // 정상 전환 시에만 정리;종료 시에는 전역 데이터를 리셋하지 않음
        if (!isShutdown)
        {
            fsm.RemoveData("StateEnterTime");
        }
    }
}
```

## 훅 내부의 제한 사항

모든 훅은 `protected internal`로 표시되어 있어 파생 클래스 또는 동일 어셈블리 내에서만 재정의할 수 있습니다. `OnEnter`에서 다시 `ChangeState`을 호출한 직후 다른 부작용을 즉시 트리거하지 마십시오. 상태기는 전환 지점에서 동기적으로 `OnLeave`/`OnEnter`을 실행하므로 실행 순서에 따른 부작용에 주의하십시오.

상태기가 어떻게 구동되는지(폴링 진입점)에 대한 자세한 내용은 [Runtime/Fsm/FsmBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs)을 참조하십시오.
