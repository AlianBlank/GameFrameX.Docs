# What to Do When the Startup Flow Gets Stuck at ProcedureLauncherState

When `StartupRunner.RunAsync` has already advanced the startup chain to `ProcedureLauncherState`, but the UI does not appear and the flow does not switch to `ProcedureGetGlobalInfoState` (the entire startup Promise stays `Pending` forever), the problem almost always lies in the FSM blackboard data, UI resources, or `WebComponent` initialization. This page provides quick diagnostics and the corresponding fix steps.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Black screen after startup; logs only show entering `ProcedureLauncherState`, and `ChangeState<ProcedureGetGlobalInfoState>` is never executed | `BlackBoardKeys.StartupOptions` or `BlackBoardKeys.StartupUIHandler` is null, causing `OnEnter` to `return` early | See "Fix 1: Missing FSM Blackboard Data" below |
| The startup screen flashes by or never appears at all, stuck on the splash screen | `IStartupUIHandler.StartAsync` throws an exception or hangs | See "Fix 2: UI Handler Startup Failure" below |
| The console reports `WebComponent`-related null references when startup reaches the Launcher stage | `GameEntry.GetComponent<WebComponent>()` returns `null`; the Web module is not registered | See "Fix 3: WebComponent Not Registered" below |
| The flow gets stuck and never enters `OnEnter` | The FSM did not have data correctly injected before `procedureManager.StartProcedure<ProcedureLauncherState>()`, or the `StartupOptions.LauncherUIResName` path is wrong | See "Fix 4: LauncherUIResName Resource Path Error" below |
| The startup chain only reaches Launcher, but `UniTaskCompletionSource` is never SetResult | Subsequent Procedures are responsible for `SetResult` after Launcher; Launcher itself only switches states | See "Fix 5: Waiting for Subsequent Procedures to Complete" below |

## Fix Steps

### Fix 1: Missing FSM Blackboard Data

`ProcedureLauncherState.OnEnter` reads `StartupOptions` and `IStartupUIHandler` from the FSM blackboard; if either is `null`, the method returns immediately, neither switching states nor raising an error:

```csharp
// Source: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var options = optionsBox.Value as StartupOptions;
var uiHandler = uiHandlerBox.Value as IStartupUIHandler;

if (options == null || uiHandler == null)
{
    return; // Exits immediately; the flow gets stuck with no exception
}
```

Confirm that `StartupRunner.RunAsync` actually passes non-null `options` and `uiHandler` before calling `StartProcedure<ProcedureLauncherState>`:

```csharp
// Source: Runtime/Startup/StartupRunner.cs
procedureFsm.SetData(BlackBoardKeys.StartupOptions, optionsBox);
procedureFsm.SetData(BlackBoardKeys.StartupUIHandler, uiHandlerBox);
```

If you are assembling the startup chain yourself (not going through `StartupRunner`), you need to inject the data with the same keys before calling `StartProcedure<ProcedureLauncherState>()`; see [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs).

### Fix 2: UI Handler Startup Failure

`OnEnter` actually waits for the UI to finish loading at `await uiHandler.StartAsync(options.LauncherUIResName)`. If the `IStartupUIHandler` implementation throws an exception, the exception is swallowed by `async void` and the flow gets stuck; if it hangs (for example, Addressables resources are not ready), it likewise never switches to the next state.

Troubleshooting order:

1. Add a `try/catch` at the entry of your custom `IStartupUIHandler.StartAsync` and at least log the exception to confirm whether one is actually thrown.
2. In the Editor, temporarily point `LauncherUIResName` to a Prefab/Asset that is confirmed to exist, to rule out resource path errors.
3. If you use a `UniTaskCompletionSource`, confirm that it is completed with `TrySetResult` inside `StartAsync`, rather than forgetting to `await`.

### Fix 3: WebComponent Not Registered

Before switching states, `ProcedureLauncherState` needs to read/write Headers via `WebComponent`. If the module is not registered, `GameEntry.GetComponent<WebComponent>()` returns `null`, and the next line, `webComponent.RemoveBaseHeader(...)`, immediately throws an NRE:

```csharp
// Source: Runtime/Procedures/Startup/ProcedureLauncherState.cs
var webComponent = GameEntry.GetComponent<WebComponent>();
webComponent.RemoveBaseHeader(StartupProcedureUtility.GameFrameXApiKeyHeader);
// ...
```

In the `GameEntry` module registration flow, confirm that `WebComponent` has been added to the component table and that at runtime it is registered before `StartupRunner.RunAsync` is initiated.

### Fix 4: LauncherUIResName Resource Path Error

`options.LauncherUIResName` must point to a valid UI prefab or resource address. When the resource does not exist, most `IStartupUIHandler` implementations fall into an "waiting for the resource to load" infinite loop instead of failing actively. Verification methods:

1. Print `LauncherUIResName` when constructing `StartupOptions` and compare it against the actual keys in the Addressables Groups / Resources directories.
2. First run the startup flow once with `EPlayMode.EditorSimulateMode` + a resource known to exist, to rule out packaging/grouping issues.

### Fix 5: Waiting for Subsequent Procedures to Complete

`ProcedureLauncherState`'s own responsibility is only "load the startup UI → switch to the next state"; it does not call `UniTaskCompletionSource.SetResult`. If the "stuck" behavior you observe is actually the `UniTask<StartupResult>` returned by `StartupRunner.RunAsync` staying `Pending` forever, check whether `ProcedureGetGlobalInfoState` and subsequent Procedures execute `StartupProcedureUtility.GetCompletionSource(fsm).TrySetResult(...)` upon final success/failure.

See the `GetCompletionSource` implementation in [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs) to confirm that the retrieved `UniTaskCompletionSource` is exactly the one `StartupRunner` injected into `BlackBoardKeys.StartupCompletionSource`.

## Verification

After fixing, confirm the chain works end to end in the following order:

1. After startup, the logs show `ProcedureLauncherState.OnEnter` being entered, immediately followed by `ProcedureGetGlobalInfoState.OnEnter` also being entered, rather than only the former.
2. The `UniTask<StartupResult>` returned by `StartupRunner.RunAsync` completes within a reasonable time (usually a few seconds), instead of staying `Pending` forever.
3. The console no longer shows `WebComponent` null reference errors or UI resource load failure errors.
4. If you use a custom `IStartupUIHandler`, set a breakpoint to confirm that `StartAsync` returns after the resource corresponding to `LauncherUIResName` is ready, and that after returning, the call stack reaches `ChangeState<ProcedureGetGlobalInfoState>` in `ProcedureLauncherState`.
