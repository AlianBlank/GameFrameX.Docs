# What to Do When a Request Fails or Times Out

When a request fails or times out, `WebManager` throws the exception back to the `await` call site: timeouts manifest as `TimeoutException`, while other failures manifest as `WebException` or `IOException`. The most common causes are an overly short timeout (only 5 seconds by default), concurrent requests exceeding the limit and queuing up, and server/network issues themselves.

## Quick Diagnosis

| Symptom (Exception/Behavior) | Cause | Fix |
|------|------|------|
| `TimeoutException`, with a message originating from `WebException` | Request took longer than `Timeout` (5 seconds by default) | [Increase the timeout](#1-increase-the-timeout) |
| Requests are slow to be sent, everything feels slower overall | Concurrent requests exceed `MaxConnectionPerServer` (8 by default); excess requests queue up in `m_WaitingNormalQueue` | [Raise the concurrency limit](#2-raise-the-concurrency-limit) |
| `WebException` (Status is not Timeout) | HTTP protocol errors (404/500), DNS resolution failure, connection refused | Verify the URL and server status; enable logging to inspect responses |
| `IOException` | Connection dropped while reading the response stream (network fluctuation, server closing early) | Check the network and retry |
| No request/response content visible in the console | Logging compile defines not enabled | [Enable send/receive logs](#3-enable-sendreceive-logs-to-locate-the-problem) |
| HTTPS certificate errors | Certificate validation failed | The WebGL/`UnityWebRequest` path is already bypassed by `DefaultBypassCertificate`; on non-WebGL platforms, check the system time and certificate chain |

## Fix Steps

### 1. Increase the timeout

By default, `WebManager` is constructed with `Timeout = 5f` (seconds) and a concurrency limit of 8. If your API responds slowly (e.g., uploading large files, weak network conditions), increase the timeout first:

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// Gets or sets the timeout in seconds
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L43-L60)

Set it in your own code (the two approaches are equivalent; `Timeout` synchronously updates `RequestTimeout`):

```csharp
webManager.Timeout = 30f;
// or
webManager.RequestTimeout = TimeSpan.FromSeconds(60);
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L236-L237)

Once set, it takes effect on both underlying request paths: WebGL uses `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds` ([WebManager.cs L218](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L218), [WebManager.Binary.cs L97](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L97)), while non-WebGL uses `request.Timeout = (int)RequestTimeout.TotalMilliseconds` ([WebManager.cs L259](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L259), [WebManager.Binary.cs L131](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L131)).

### 2. Raise the concurrency limit

Each frame, `WebManager.Update` dequeues a waiting request only when the sending list is smaller than `MaxConnectionPerServer`; requests that exceed the concurrency limit keep sitting in `m_WaitingNormalQueue`, which appears as "stuck and never sent":

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    lock (m_StringBuilder)
    {
        if (m_SendingNormalList.Count < MaxConnectionPerServer)
        {
            if (m_WaitingNormalQueue.Count > 0)
            {
                var webJsonData = m_WaitingNormalQueue.Dequeue();

                if (webJsonData.UniTaskCompletionStringSource != null)
                {
                    MakeJsonStringRequest(webJsonData);
                }
                else
                {
                    MakeJsonBytesRequest(webJsonData);
                }

                m_SendingNormalList.Add(webJsonData);
            }
        }

        UpdateBinary(elapseSeconds, realElapseSeconds);
    }
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L75-L101)

When higher concurrency is needed, set:

```csharp
webManager.MaxConnectionPerServer = 16;
```

The property definition can be found at [WebManager.cs L65](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L65).

### 3. Enable send/receive logs to locate the problem

Send and response logging is controlled by compile defines, and the package provides `WebLogScriptingDefineSymbols` for toggling them. Once enabled, you can see the actual request URL, Header, Form, and the response content (or exception messages):

```csharp
#if ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
    Log.Debug($"Web Response: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)} \n Content: {content}");
#endif
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L286-L288)

Available compile defines: `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` (send), `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` (receive). See [WebLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/WebLogScriptingDefineSymbols.cs) for the related script.

### 4. Correctly catch exceptions on the caller side

Timeouts are uniformly converted and thrown as `TimeoutException`, while other failures preserve the original `WebException` / `IOException`. Catch them in the following order to distinguish timeouts from other errors:

```csharp
try
{
    WebStringResult result = await webManager.GetToString(url);
}
catch (TimeoutException)
{
    // Timeout: increase Timeout / RequestTimeout and retry
}
catch (WebException e)
{
    // HTTP/network error: check the URL, DNS, and server status
    Debug.LogError(e.Message);
}
catch (IOException e)
{
    // Response stream interrupted: usually caused by network fluctuation; you can retry
    Debug.LogError(e.Message);
}
```

Timeout conversion and exception dispatch logic (non-WebGL path; the Binary path outside WebGL handles it the same way in [WebManager.Binary.cs L164](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L164)):

```csharp
catch (WebException e)
{
    // Catch timeout exceptions
    if (e.Status == WebExceptionStatus.Timeout)
    {
        webJsonData.UniTaskCompletionStringSource.SetException(new TimeoutException(e.Message));
        return;
    }
    webJsonData.UniTaskCompletionStringSource.SetException(e);
}
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L305)

The caller example (the recommended pattern in the README) also handles timeouts via the `WebExceptionStatus.Timeout` branch; see [README.md L145-L148](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L145-L148).

## Common Mistakes

- **Assuming the default timeout is 30 seconds**: The README's configuration example labels it "Default: 30 seconds", but the `WebManager` constructor actually hardcodes `Timeout = 5f`; see [WebManager.cs L46](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L46). Any API response that takes longer than 5 seconds is treated as a timeout.
- **Only catching `Exception`**: This loses the distinction between "timeout" and other errors; catch `TimeoutException` first, then `WebException`/`IOException`.
- **Suspecting lost requests after firing off many requests at once**: Requests that exceed the `MaxConnectionPerServer` concurrency are not lost; they simply remain in the queue, with at most one dequeued per frame. Just wait, or raise the limit.
- **Debugging `HttpWebRequest` behavior on the WebGL platform**: WebGL only takes the `UnityWebRequest` branch, where the timeout unit is seconds (`TotalSeconds`), unlike the native platform's milliseconds (`TotalMilliseconds`) path; see [WebManager.cs L217-L218](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L217-L218) and [WebManager.cs L258-L259](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L258-L259).

## Verification

- Increase `Timeout` to a sufficiently large value (e.g., 30 seconds) and resend the same request. If it still fails with a `WebException`, a timeout can essentially be ruled out; turn to checking the URL and the server.
- Enable `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`, and confirm in the logs that the request was actually sent and that the URL/Header/Form match expectations.
- In concurrency scenarios, compare `m_SendingNormalList` with `MaxConnectionPerServer`: if requests no longer linger in the queue for long after raising the limit, you can confirm the issue was caused by concurrency queuing.

## Background

Each frame, `WebManager` takes requests from the waiting queue and selects the implementation based on the platform: WebGL uses `UnityWebRequest` (certificates are passed through directly by `DefaultBypassCertificate`; see [DefaultBypassCertificate.cs L39-L45](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/DefaultBypassCertificate.cs#L39-L45)), while other platforms use `HttpWebRequest`. Both paths read the same `RequestTimeout` value, only with different units (seconds vs. milliseconds). After a request completes or fails, it is removed from the sending list and returned to the reference pool, so no queue leakage occurs.
