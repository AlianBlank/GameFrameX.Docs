# AOT 程式碼列表 JSON 解析失敗怎麼辦

執行階段為 `GlobalConfigComponent.AOTCodeList` 指派值時，如果字串不是合法的 JSON 陣列格式，`GlobalConfigComponent` 會透過 `Utility.Json.ToObject<List<string>>(value)` 反序列化失敗並呼叫 `Log.Error(e)` 記錄例外狀況，導致 `AOTCodeLists` 保持為空，AOT 中繼資料補充失效。本頁說明常見原因與修復方法。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 主控台輸出 `Log.Error`,內容為 JSON 解析例外狀況，但 `AOTCodeList` 字串已寫入 | 字串不是合法 JSON 陣列 | 用 `[ "A", "B" ]` 格式重寫，見下方「修正 JSON 格式」 |
| `AOTCodeLists` 始終為空列表，但無報錯 | 空字串或未觸發 setter | 給欄位指派一個非空 JSON 陣列字串 |
| IL2CPP/iOS 下出現 `MissingMethodException` 或 `TypeLoadException` | `AOTCodeLists` 沒解析出型別/組件名稱，補充中繼資料未產生 | 在 Inspector 的「補充組件列表」填寫完整 JSON,並確認 HybridCLR/IL2CPP 生效 |
| 含中文逗號 `,` 或單引號 `'…'` | JSON 要求雙引號 + 半形逗號 | 把字串改為標準 JSON |
| 多行、註解、結尾逗號 | JSON 不支援註解與結尾逗號 | 改為單行、嚴格合法的字串陣列 |

## 修復步驟

### 1. 確認目標格式

原始碼中 setter 直接反序列化為 `List<string>`,因此欄位必須是**字串陣列**的 JSON 表示。合法範例：

```json
["GameFrameX.Runtime","GameFrameX.GlobalConfig.Runtime"]
```

原始碼位置：

```csharp
public string AOTCodeList
{
    get { return m_aotCodeList; }
    set
    {
        m_aotCodeList = value;
        try
        {
            m_aotCodeLists = Utility.Json.ToObject<List<string>>(value);
        }
        catch (Exception e)
        {
            Log.Error(e);
        }
    }
}
```

來源： [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L64-L79)

### 2. 修正 JSON 格式

在 Inspector 上選取掛有 `GlobalConfigComponent` 的 GameObject,找到 **「補充組件列表」** 欄位(`m_aotCodeList`),把內容改為嚴格的 JSON 陣列：

- 必須是 `[` 開始、`]` 結束
- 元素必須用**雙引號**包裹，不能使用單引號
- 元素之間用**半形逗號**加一個空格
- 不要寫註解、不要留結尾逗號、不要在結尾加 `;`

Inspector 中欄位名稱與序列化屬性的對應關係如下：

| Inspector 顯示名稱 | 序列化欄位 | 型別 |
|------------------|-----------|------|
| 補充組件列表 | `m_aotCodeList` | `string`(JSON 原文) |
| 補充中繼資料列表 | `m_aotCodeLists` | `List<string>`(解析後，執行階段唯讀) |

來源： [GlobalConfigComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Editor/Inspector/GlobalConfigComponentInspector.cs#L13-L14)

### 3. 透過程式碼設定時保證格式

如果將從遠端推送的設定指派給 `AOTCodeList`,請在寫入前用 `Utility.Json.ToObject<List<string>>` 先做一次驗證，避免把後端髒資料塞進 setter:

```csharp
var raw = "[\"GameFrameX.Runtime\",\"GameFrameX.GlobalConfig.Runtime\"]";
globalConfig.AOTCodeList = raw; // 內部 try/catch,失敗會 Log.Error
```

原始碼中 setter 已對解析例外狀況做了 `try/catch` 並 `Log.Error`,因此**不會向上拋出**——但例外狀況會被記入日誌，`AOTCodeLists` 保持原值不變，這是排查「解析失敗」的關鍵觀察點。

來源： [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L70-L78)

### 4. 確認 AOT 補充中繼資料鏈路

`AOTCodeLists` 列表裡的字串需要與專案裡 HybridCLR(或同類 AOT 工具)要求補充的組件名稱一一對應。如果列表能解析成功但執行階段仍出現 `MissingMethodException`,代表問題出在 AOT 工具鏈本身，而非 JSON 解析環節。

## 驗證

1. 在 Inspector 修改 **「補充組件列表」** 後，確認 **「補充中繼資料列表」** 立即出現與 JSON 等長的條目數。
2. 在 Editor 主控台搜尋 `Log.Error` 或 `Json` 關鍵字，確認無解析例外狀況輸出。
3. 打包 IL2CPP/AOT 目標平台(iOS、WebGL 等)後啟動，檢查原先的 `MissingMethodException` 是否消失。

## 背景(可選)

`AOTCodeList` 與 `AOTCodeLists` 是「來源 JSON 字串 + 解析後快取列表」的雙欄位設計，setter 把解析例外狀況吞掉只記日誌，是為了避免髒設定打斷業務初始化——代價是失敗容易被忽略，需透過日誌與「補充中繼資料列表」是否填入來反向確認。
