# Using AOT Preserve Configuration and Validation

Use the Unity menu `GameFrameX/HybridCLR Generate AOT Preserve` to one-click generate `link.xml`, reference summary code, and per-type split reference code files, and use the validation runner in CI to ensure generated files are always consistent with the latest configuration, avoiding missing AOT metadata during HybridCLR hot updates.

## Prerequisites

- The project has HybridCLR installed (runtime dependency for hot-update AOT metadata).
- A custom implementation has been provided for `IAotPreserveSettingsProvider`, or the configuration entry has been placed under the default implementation (the default implementation is located at [IAotPreserveSettingsProvider.cs](/Editor/AotPreserve/IAotPreserveSettingsProvider.cs)).
- The Unity editor has the project open and has write permissions for the `Assets/Generated/` directory.

## Operation Steps

1. **Trigger Generation**. Select `GameFrameX > HybridCLR Generate AOT Preserve` from the top menu of the Unity editor. This will invoke `AotPreserveGenerator.GenerateAndWrite()` and output the logs to the console.

   See the menu entry implementation at [AotPreserveMenu.cs#L20-L25](/Editor/AotPreserve/AotPreserveMenu.cs#L20-L25):

   ```csharp
   [MenuItem(AotPreserveConstants.MenuPath)]
   public static void Generate()
   {
       AotPreserveGenerator.GenerateAndWrite();
       Debug.Log("Hotfix AOT preserve files generated under " + AotPreserveConstants.GeneratedDirectory);
   }
   ```

2. **View Generation Path**. The default generation root directory is `Assets/Generated/AotPreserve`. The core artifact paths are managed uniformly by constants. See [AotPreserveConstants.cs#L17-L65](/Editor/AotPreserve/AotPreserveConstants.cs#L17-L65):

   | Artifact | Path Constant | Actual Path |
   |------|----------|----------|
   | `link.xml` (managed code stripping preserve) | `LinkXmlPath` | `Assets/Generated/AotPreserve/link.xml` |
   | Reference summary code | `ReferencesPath` | `Assets/Generated/AotPreserveReferences.cs` |
   | Per-type split reference file name prefix | `ReferenceTypeFilePrefix` | `AotPreserveReference_<TypeName>.cs` |
   | Generated code asmdef | `GeneratedAsmdefPath` | `Assets/Generated/AotPreserve.Generated.asmdef` |
   | Generation report Markdown | `ReportPath` | `Assets/Generated/AotPreserve/aot_preserve_report.md` |

3. **Invoke Validation in CI**. CI or unit tests can directly call `AotPreserveValidationRunner.ValidateGeneratedFiles()`. When files are missing or outdated, it throws an `InvalidOperationException`, and the exception message aggregates all errors. See [AotPreserveValidationRunner.cs#L20-L27](/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27):

   ```csharp
   public static void ValidateGeneratedFiles()
   {
       var errors = AotPreserveGenerator.ValidateGeneratedFiles();
       if (errors.Length > 0)
       {
           throw new InvalidOperationException(string.Join("\n", errors));
       }
   }
   ```

4. **Error Handling**. When an error occurs during generation (e.g., invalid configuration, write failure), `GenerateAndWrite()` will throw an `InvalidOperationException`, with a prompt starting with `"Hotfix AOT preserve generation failed:\n"` listing errors line by line. See [AotPreserveGenerator.cs#L72-L78](/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L78); when writing to disk fails, `IOException` or `UnauthorizedAccessException` will also be thrown.

## Common Variants

- **Programmatic Triggering**: When menu clicks are not needed, you can directly call `AotPreserveGenerator.GenerateAndWrite()` in an editor script.
- **Pure Build (No Disk Write)**: In a custom pipeline where you only want to preview artifacts, use `AotPreserveGenerator.Build()` to get `AotPreserveBuildResult` (including `LinkXml`, `ReferencesCode`, `GeneratedAsmdef`, `Report`, `ReferenceFiles`, `Errors`). See [AotPreserveGenerator.cs#L29-L61](/Editor/AotPreserve/AotPreserveGenerator.cs#L29-L61).
- **Custom Configuration Provider**: Implement `IAotPreserveSettingsProvider` and inject it via `AotPreserveSettingsProviderResolver` to override the source of the default configuration.

## Common Errors

- **`Hotfix AOT preserve generation failed: ...` reported in the console after clicking the menu**: This indicates that the `Errors` of `AotPreserveBuildResult` returned by `Build()` is non-empty, usually because the `IAotPreserveSettingsProvider` configuration is invalid or the analysis phase failed; fix them one by one according to the exception messages and regenerate.
- **`InvalidOperationException` thrown in CI listing multiple errors**: Indicates that `link.xml`, reference code, or `asmdef` are inconsistent with the current analysis result; run the menu generation once to refresh.
- **`UnauthorizedAccessException`**: Check the write permissions of the `Assets/Generated/AotPreserve/` directory, and whether `Assets/Generated/AotPreserve.Generated.asmdef` is locked by another process.
- **Missing generated files**: Manually deleting `Assets/Generated/AotPreserve` without re-triggering the menu—run the menu generation once to rebuild the entire set of artifacts.

## Background (Optional)

The generation entry `AotPreserveGenerator.GenerateAndWrite()` first calls `AotPreserveAnalyzer.Analyze()` to aggregate the types that need to be preserved, then produces `link.xml` (for assembly-level preservation during managed stripping), aggregated and per-type split reference code (used to explicitly trigger AOT metadata loading at runtime), and an `aot_preserve_report.md` report for auditing; `ValidateGeneratedFiles()` detects whether files are outdated by comparing against the latest analysis results.
