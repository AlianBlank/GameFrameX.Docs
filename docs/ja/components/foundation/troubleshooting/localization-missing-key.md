# ローカリゼーションのキー欠落・フォーマットエラーが発生した場合の対処

`LocalizationService.GetString` / `GetString(key, args)` がキー名そのもの（例：`"Some.Unknown.Key"`）を返す、あるいは返される文字列に `"{0}"`、`{n:xxxxx}` などのプレースホルダーが置換されずに残っている場合、ローカリゼーションの「キー欠落」または「フォーマットエラー」分岐がトリガーされています。本ページでは、原因の特定と修正方法を説明します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GetString("X.Y")` が `"X.Y"` をそのまま返す | リソースキーが存在しない（未登録、アセンブリと一緒にロードされていない、キー名のスペルミス） | `EnsureLoaded()` で強制ロードし、`MissingKey` イベントを購読してキーを確認。[キー欠落](#修正-1-キー欠落) を参照 |
| テンプレートに置換されていない `{0}`、`{1}`、`{name}` が表示される | プレースホルダーのインデックス/名前が `args` と一致せず、`string.Format` が `FormatException` をスローする | テンプレートのプレースホルダー数と型を確認。`FormatErrorBehavior` を切り替え。[フォーマットエラー](#修正-2-フォーマットエラー) を参照 |
| `FormatException: Input string was not in a correct format` がスローされる | `FormatErrorBehavior` が `Throw` に設定されている | 一時的に `ReturnTemplate` に戻して問題を特定するか、テンプレートと引数を修正。[フォーマットエラー](#修正-2-フォーマットエラー) を参照 |
| 返される文字列が現在の `CultureInfo` と一致しない（常に英語/常に特定の言語） | その `CultureInfo` 用のリソースが登録されていない、またはデフォルトカルチャにフォールバックしている | [カルチャとフォールバック動作](#修正-3-カルチャとフォールバック動作) を参照 |

`FormatErrorBehavior` の 3 種類の値の意味については [`LocalizationFormatErrorBehavior`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/LocalizationFormatErrorBehavior.cs#L6-L22) を参照してください。デフォルト値は `ReturnTemplate` です。

## 修正手順

### 修正 1: キー欠落

1. キー名のスペルが正しいか確認する（大文字小文字とドットを含む）。キー名は文字列で厳密に一致するため、`"Utility.Exceptions.TimestampOutOfRange"` と `"utility.exceptions.timestampoutofrange"` は異なるキーとして扱われます。
2. [`LocalizationService.EnsureLoaded()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L207-L210) を呼び出してすべてのプロバイダーのロードを強制し、遅延ロードによる問題の隠蔽を避けます。
3. [`MissingKey`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L79-L89) イベントを購読し、ログに実際に欠落しているキーを出力します:

   ```csharp
   LocalizationService.MissingKey += (sender, args) =>
   {
       // args.Key / args.Culture から欠落している具体的なキーとカルチャを取得できる
       Console.WriteLine($"Missing localization key: {args.Key} ({args.Culture})");
   };
   ```

4. それでもキー名が返される場合は、アセンブリのリソースがメインアセンブリと一緒に公開されているか確認し（`*.resources.dll` が出力ディレクトリにコピーされているか）、カスタムリソースプロバイダーが `LocalizationService.RegisterProvider(...)` で登録されているかを確認してください。

### 修正 2: フォーマットエラー

フォーマット処理の失敗は [`ResourceManager.FormatString`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L234-L252) の内部で `FormatException` をキャッチし、`FormatErrorBehavior` に応じて処理されます:

```csharp
public LocalizationFormatErrorBehavior FormatErrorBehavior { get; set; }
    = LocalizationFormatErrorBehavior.ReturnTemplate;
```

以下の順序で調査してください:

1. **プレースホルダー数の確認**: テンプレートの `{0}` / `{1}` の数は `args` に渡される数と一致している必要があります。プレースホルダーが多いと直接 `FormatException` がスローされます。
2. **型の確認**: テンプレートで `{0:d}`、`{0:N2}` などのフォーマット指定子を使用する場合、`args` の対応する位置はそのフォーマットが要求する数値/日付型に変換できる必要があります。`string` を `{0:d}` に渡すと失敗します。
3. **特定のために一時的に動作を切り替える**: `FormatErrorBehavior` を `Throw` に変更して、例外のスタックトレースから呼び出し元を直接特定します:

   ```csharp
   LocalizationService.Instance.FormatErrorBehavior
       = LocalizationFormatErrorBehavior.Throw;
   ```

   3 種類の値の意味:

   | 値 | 動作 |
   |------|------|
   | `ReturnTemplate` (デフォルト) | フォーマットされていないローカリゼーションテンプレート（`{0}` などを含む）を返す |
   | `ReturnKey` | リソースのキー名を返す |
   | `Throw` | `FormatException` を再スローし、開発環境での特定を容易にする |

4. 修正が完了したら `ReturnTemplate` に戻し、本番環境で未処理の例外がスローされないようにしてください。

### 修正 3: カルチャとフォールバック動作

1. `CultureInfo.CurrentUICulture` を通じて検索するカルチャを制御します。カルチャを明示的に指定するには [`LocalizationService.GetString(key, culture)`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L130-L138) を使用します。
2. 特定のカルチャで常に英語が返される（または常にキーが返される）場合、そのカルチャ用のリソースが存在せず、デフォルトカルチャまたはキー名にフォールバックしています。リソースファイルに対応する `.resx` を追加してください。
3. [`LocalizationService.GetStatistics()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L234-L237) を呼び出してプロバイダーがロードされているか確認します:

   ```csharp
   var stats = LocalizationService.GetStatistics();
   Console.WriteLine($"Providers loaded: {stats.ProvidersLoaded}");
   ```

## 検証

1. 元の呼び出しパスを再トリガーし、戻り値が渡されたキー名と等しくないこと、および置換されていない `{0}` / `{1}` プレースホルダーが表示されないことを確認します。
2. 一時的に `FormatErrorBehavior` を `Throw` に設定してテスト/スモークテストを実行し、`FormatException` がスローされないことを確認します。
3. 異なる `CultureInfo` でそれぞれ `GetString(key)` を呼び出し、戻り値が選択したカルチャと一致することを確認します。欠落している場合は、ログで `MissingKey` イベントがトリガーされているか確認してください。
