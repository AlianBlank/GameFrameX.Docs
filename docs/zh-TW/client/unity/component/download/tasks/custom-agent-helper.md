# 自訂下載代理協助程式

透過實作 `IDownloadAgentHelper` 介面，可以取代或擴充預設的下載後端（代理取得、檔案寫入磁碟、串流讀取等行為）。

## 前置條件

- 已將 `Microsoft.Kiota.Authentication.Azure` 或相關 Kiota 驗證套件加入專案。
- 目標專案使用 C# / .NET，並瞭解相依性插入與 `IHttpClient` 生命週期。
- 已有可用的 `IAuthenticationProvider` 執行個體作為下游呼叫來源。

## 操作步驟

1. 建立新類別以實作 `IDownloadAgentHelper` 介面的三個成員（具體簽章以原始碼為準）。
2. 在建構函式中插入所需的相依性（如 `IHttpClient`、`IAuthenticationProvider`、`ILogger` 等）。
3. 將實作的執行個體以單一或具範圍的方式註冊到 `IServiceCollection` 中。
4. 在要求執行前，將該協助程式傳遞給需要它的呼叫端（例如 `KiotaClientFactory` 的相關多載）。
5. 發起一次最小化的下載要求，驗證自訂邏輯（記錄、中斷點、檔案路徑）是否生效。

## 常見變體

- **記錄包裝**：在原有實作外再套一層，僅新增記錄/遙測，其餘轉送。
- **路徑重寫**：根據租用戶或使用者內容將暫存檔案放到隔離目錄。
- **串流分塊**：自訂分塊大小與並行程度，覆寫預設的 `BufferSize` 行為。

## 常見錯誤

| 現象 | 可能原因 | 處理 |
|------|---------|------|
| 註冊後未生效 | 未取代預設註冊或範圍不一致 | 檢查 `services.AddSingleton<>` / `AddScoped<>` 的選擇 |
| 下載失敗且無錯誤訊息 | 未攔截並轉送 `HttpRequestException` | 在 `DownloadAsync` 中包裝 `try/catch` 並記錄 |
| 檔案被佔用 | 未釋放資料流 | `await using` 或明確呼叫 `Dispose()` |
| 驗證標頭遺失 | 未在 `GetAuthenticationProvider` 中呼叫下游 provider | 轉送而非取代 |

## 背景（選用）

`IDownloadAgentHelper` 是 Kiota 抽象的下載能力擴充點：預設實作走 `HttpClient`，自訂實作可以接入驗證、重試、寫入磁碟策略等橫切關注點。本頁僅描述如何掛載，驗證提供者的整體設計不在此處展開。
