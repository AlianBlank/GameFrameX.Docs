# 요청 및 응답 메시지 타입 정의 방법

GameFrameX Web ProtoBuff에서 요청 메시지는 `GameFrameX.Network.Runtime.MessageObject`를 상속하고 protobuf-net 규칙에 따라 `[ProtoContract]`/`[ProtoMember]`를 지정하기만 하면 되고, 응답 메시지는 여기에 더해 `GameFrameX.Network.Runtime.IResponseMessage` 인터페이스를 구현해야 `WebComponent.Post<T>`의 제네릭 매개변수로 역직렬화되어 반환될 수 있습니다. 타입 제약은 모두 API 시그니처에 의해 컴파일 시점에 강제되므로, 올바르게 정의하면 `await`로 바로 강타입 응답을 얻을 수 있습니다.

## 사전 조건

- `com.gameframex.unity.web.protobuff` 패키지가 설치되어 있어야 합니다([README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L43-L74) 참조).
- Unity의 **Player Settings → Scripting Define Symbols**에 매크로 `ENABLE_GAME_FRAME_X_WEB_PROTOBF_NETWORK`를 추가해야 합니다(README에는 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`로 표기되어 있음). 이 매크로가 없으면 컴포넌트의 관련 `Post<T>` 메서드가 컴파일에 포함되지 않습니다(구현 전체가 `#if ... #endif` 조건부 컴파일로 감싸져 있음).
- 프로젝트에 protobuf-net이 이미 도입되어 있어야 합니다(`using ProtoBuf;`), 메시지 클래스는 이를 통해 생성하거나 직접 작성합니다.

## 작업 단계

### 1. 컴파일 시점 타입 제약 확인

먼저 API가 양쪽 메시지 타입에 각각 어떤 요구 사항을 가지는지 확인한 후 정의를 시작하세요:

| 역할 | 반드시 충족해야 할 조건 | 출처 |
|------|----------------|------|
| 요청 메시지(`message` 매개변수) | `MessageObject` 상속 | [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108) |
| 응답 메시지(제네릭 `T`) | `MessageObject` 상속 **및** `IResponseMessage` 구현 | [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108) |

컴포넌트가 외부에 노출하는 실제 시그니처(`where` 절이 전체 하드 요구 사항임):

```csharp
public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message)
    where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
{
    return m_WebProtoBuffManager.Post<T>(url, message);
}
```

출처: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108)

하위 관리자의 시그니처도 동일하며, `using`으로 네임스페이스를 간략화했을 뿐입니다:

```csharp
public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
```

출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L182)

### 2. 요청 메시지 정의

요청 메시지는 `MessageObject`를 상속하고 protobuf-net 규칙에 따라 계약과 필드 번호를 지정합니다. 다음은 위 제약에 따라 작성한 새 타입 템플릿입니다(직접 생성하는 것으로, 저장소에 포함된 파일이 아님):

```csharp
using GameFrameX.Network.Runtime;
using ProtoBuf;

[ProtoContract]
public class LoginRequest : MessageObject
{
    [ProtoMember(1)] public string UserName { get; set; }
    [ProtoMember(2)] public string Password { get; set; }
}
```

### 3. 응답 메시지 정의

응답 메시지는 요청보다 한 단계가 더 필요합니다: `IResponseMessage` 구현. 다음은 마찬가지로 제약에 따라 작성한 템플릿입니다:

```csharp
using GameFrameX.Network.Runtime;
using ProtoBuf;

[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)] public int Code { get; set; }
    [ProtoMember(2)] public string Token { get; set; }
}
```

### 4. 강타입 응답 전송 및 수신

정의가 완료되면 README의 공식 사용법에 따라 호출하면 되며, `T`에는 정의한 응답 타입을 넣습니다:

```csharp
using GameFrameX.Web.ProtoBuff.Runtime;

// 요청을 전송하고 결과를 기다립니다
LoginResponse response = await WebComponent.Post<LoginResponse>(url, request);
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L108-L113)

## 일반적인 변형

- **WebGL 플랫폼**: 동일한 메시지 정의를 변경 없이 사용할 수 있습니다. WebGL에서는 `UnityWebRequest` 경로를 사용하며, 컴포넌트가 자동으로 `Content-Type: application/x-protobuf`를 설정하고 `MessageObject`를 직렬화한 바이트를 원본 body로 업로드합니다([WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L83-L97) 참조); WebGL이 아닌 플랫폼은 다른 분기를 거칩니다.
- **타임아웃 시간**: 관리자의 `RequestTimeout`(`TimeSpan`)으로 제어되며, 초 단위 값으로 설정하면 자동으로 변환됩니다(`RequestTimeout = TimeSpan.FromSeconds(value)`), [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L41-L54) 참조.
- **`.proto` 파일로 생성**: 마찬가지로 적용 가능하며, 생성된 C# 클래스가 "`MessageObject` 상속(+ 응답은 `IResponseMessage` 구현)"을 충족하고 `[ProtoContract]`/`[ProtoMember]` 지정이 유지되기만 하면 됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Post<T>`가 존재하지 않음 / 메서드를 찾을 수 없음 | 매크로 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`가 정의되지 않아 조건부 컴파일에서 메서드가 제외됨 | Player Settings → Scripting Define Symbols에 매크로를 추가하고 다시 컴파일 |
| 제네릭 매개변수 컴파일 오류 "IResponseMessage 누락" | 응답 타입이 `MessageObject`만 상속하고 `IResponseMessage`를 구현하지 않음 | 응답 클래스에 `, IResponseMessage` 추가 |
| 요청 매개변수 컴파일 오류 | 요청 클래스가 `MessageObject`를 상속하지 않음(예: `[ProtoContract]`만 지정됨) | 요청 클래스가 `MessageObject`를 상속하도록 변경 |
| 응답 필드가 모두 기본값 | 필드에 `[ProtoMember(n)]`가 지정되지 않았거나 번호가 서버 측과 불일치 | 필드 번호 보완/정렬 |
| 서버에서 body 파싱 실패 | Content-Type 또는 직렬화 방식 불일치 | 서버가 `application/x-protobuf`로 protobuf 바이너리를 파싱하는지 확인 |

## 검증

- 컴파일 통과: `WebComponent.Post<LoginResponse>(url, request)`가 메서드로 해석되면 매크로, 상속 관계, 인터페이스 구현이 모두 충족된 것입니다.
- 런타임: `await`가 반환한 `LoginResponse` 인스턴스의 필드가 서버에서 전달된 실제 값이면(Inspector 또는 로그에서 출력하여 확인 가능) 정의가 올바른 것입니다.

## 배경

요청 측은 "protobuf-net으로 직렬화 가능한 `MessageObject`"만 요구하며, 전송 전에 일괄적으로 바이너리로 직렬화됩니다. 응답 측은 바이트를 수신한 후 구체적 타입으로 복원해야 하므로, `IResponseMessage` 인터페이스를 통해 타입 시스템에서 "역직렬화 가능한 응답 메시지"임을 구분합니다. 전체 송수신은 `WebProtoBuffManager`의 대기 큐/전송 목록으로 스케줄링되며, 메시지 정의와 결합되어 있지 않으므로 메시지를 정의할 때 신경 쓸 필요가 없습니다.
