# 如何使用 DSA 签名验签

`DsaHelper` 提供 DSA 数字签名算法的签名与验签能力,使用 SHA256 作为摘要算法,密钥以 XML 字符串形式存取。本页演示从生成密钥对、单条字符串签名验签,到 `DsaHelper` 实例复用的完整步骤。

## 前置条件

- 项目引用 `GameFrameX.Foundation.Encryption` 包。
- 目标框架为 .NET(支持 `System.Security.Cryptography.DSA`);`DsaHelper` 内部使用 `DSA.Create()`,跨 Windows / Linux / macOS 均可运行。
- 使用命名空间 `using GameFrameX.Foundation.Encryption;`。

## 操作步骤

### 1. 生成 DSA 密钥对

调用 `DsaHelper.Make()` 一次性获得私钥与公钥的 XML 字符串,分别用键名 `privatekey`、`publickey` 取出:

```csharp
using GameFrameX.Foundation.Encryption;

var keys = DsaHelper.Make();
string privateKey = keys["privatekey"]; // XML 私钥
string publicKey  = keys["publickey"];  // XML 公钥
```

Source: [DsaHelper.cs#L127-L140](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L127-L140)

### 2. 对字符串数据签名(静态方法)

将待签名字符串与私钥传入 `SignData(string, string)`,返回 Base64 编码的签名值。私钥格式错误时会抛出 `CryptographicException`,提示 `"Invalid DSA private key."`。

```csharp
using GameFrameX.Foundation.Encryption;

string data = "hello world";
string signature = DsaHelper.SignData(data, privateKey); // 返回 Base64 字符串
```

签名实际流程:`Encoding.UTF8.GetBytes` → `DSA.SignData(..., HashAlgorithmName.SHA256)` → `Convert.ToBase64String`。

Source: [DsaHelper.cs#L189-L200](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L189-L200)

### 3. 验证字符串签名(静态方法)

将原文、Base64 签名、公钥传入 `VerifyData(string, string, string)`,返回 `true` 表示签名有效;公钥格式错误或签名无效时返回 `false`(不会抛异常):

```csharp
using GameFrameX.Foundation.Encryption;

bool ok = DsaHelper.VerifyData(data, signature, publicKey);
```

底层调用 `DSA.VerifyData(..., HashAlgorithmName.SHA256)`,捕获 `CryptographicException` 与 `XmlException` 后返回 `false`。

Source: [DsaHelper.cs#L282-L287](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L282-L287)

### 4. 直接对字节数组签名验签(可选)

若要避免字符串/Base64 编解码,也可使用 `byte[]` 重载。签名时 `CryptographicException` 或 `XmlException` 会被吞掉并返回 `null`,需自行处理:

```csharp
using GameFrameX.Foundation.Encryption;

byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello world");
byte[] signedBytes = DsaHelper.SignData(payload, privateKey);     // 失败返回 null
bool valid = DsaHelper.VerifyData(payload, signedBytes, publicKey); // 失败返回 false
```

Source: [DsaHelper.cs#L153-L176](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L153-L176), [DsaHelper.cs#L246-L270](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L246-L270)

### 5. 复用 `DsaHelper` 实例(可选)

如果同一进程内要反复签名/验签,推荐用 `using` 创建 `DsaHelper` 实例持有公钥或私钥,避免每次 `FromXmlString` 的开销。实例方法走的是 `_dsa.SignData` / `_dsa.VerifyData`,异常直接向上抛:

```csharp
using GameFrameX.Foundation.Encryption;

using (var signer = new DsaHelper(privateKey))
{
    string signature = signer.SignData("hello world"); // Base64
}

using (var verifier = new DsaHelper(publicKey))
{
    bool ok = verifier.VerifyData("hello world", signature);
}
```

构造时支持两种重载:传入 `DSA` 实例或 XML 密钥字符串;传入 null / 空字符串会分别抛 `ArgumentNullException` / `ArgumentException`,XML 非法时抛 `CryptographicException`。

Source: [DsaHelper.cs#L70-L102](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L70-L102), [DsaHelper.cs#L212-L232](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L212-L232), [DsaHelper.cs#L299-L320](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/DsaHelper.cs#L299-L320)

## 常见变体

- **使用实例签名但配以静态验签(跨进程传输场景)**:发送方用 `new DsaHelper(privateKey).SignData(原文)` 拿到 Base64 签名随消息发出,接收方用 `DsaHelper.VerifyData(原文, 签名, 公钥)` 验签。
- **签名原始字节流**:数据本身就是字节(例如已经序列化好的 protobuf)时,直接调用 `byte[]` 重载,跳过 UTF-8 / Base64 编解码。
- **密钥来自配置文件**:把 `Make()` 输出的 XML 字符串存到配置中心,启动时读出,直接喂给构造器或静态方法。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `SignData(string, string)` 抛 `CryptographicException: Invalid DSA private key.` | 私钥字符串不是合法的 DSA XML,或公钥被误当作私钥传入 | 确认传入的是 `Make()["privatekey"]`;XML 损坏时重新生成 |
| `SignData(byte[], string)` 返回 `null` | 私钥格式异常(`CryptographicException` 或 `XmlException` 被内部吞掉) | 检查密钥 XML;改用字符串重载可拿到明确的异常信息 |
| `VerifyData` 始终返回 `false` | 公钥/原文/签名三者任一不匹配(编码、截断、用了不同密钥对) | 确保原文用 UTF-8 一致编码、签名未被二次 Base64、签签双方使用配套密钥对 |
| `new DsaHelper(null)` 抛 `ArgumentNullException` | 传入了 null 的 `DSA` 实例或密钥字符串 | 先校验输入再构造;XML 密钥应 `ArgumentException.ThrowIfNullOrEmpty` 之后再传入 |
| macOS 上指定 2048 位密钥失败 | 平台 DSA 实现对非默认密钥大小支持有限 | 直接用 `DsaHelper.Make()` 生成的默认大小密钥对 |

## 背景(可选)

`DsaHelper` 内部统一使用 `DSA.Create()` 取代已弃用的 `DSACryptoServiceProvider`,签名摘要显式指定为 `HashAlgorithmName.SHA256`,规避了 DSA 默认 SHA-1 的弱点;类实现了 `IDisposable`,长期持有实例时务必用 `using` 释放底层非托管资源。DSA 仅用于签名验签,不能做加解密。
