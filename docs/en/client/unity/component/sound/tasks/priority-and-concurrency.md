# How to Control Playback Requests with Priority and Concurrency

By using `PlaySoundParams.Priority` and the sound group's `AvoidBeingReplacedBySamePriority` switch, you can control the preemption behavior among multiple concurrent playback requests within the same sound group: the larger the priority number, the higher the priority; when preemption is triggered, the sound can still be replaced by a new request.

## Prerequisites

- Sound groups have been registered via `GameFrameX.Sound.Runtime`, and at least one sound agent (`SoundAgent`) has been assigned to the sound group.
- The caller can access an `ISoundManager` instance (usually via `GameEntry.Sound`).

## Steps

1. Before playing, create the parameter object through the reference pool, set the priority, and pass it to the `PlaySound` overload:

```csharp
using GameFrameX.Sound.Runtime;

var p = PlaySoundParams.Create(isLoop: false);
p.Priority = 100; // The larger the value, the higher the priority
p.FadeInSeconds = 0.1f;

int serialId = GameEntry.Sound.PlaySound("sfx/click", "SoundEffect", p);
```

Source: [PlaySoundParams.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundParams.cs#L105-L239)

2. Configure whether the sound group allows preemption among sounds with the same priority. By default, a new request replaces the currently playing sound only if its priority is **strictly greater**; if you want same-priority sounds to also be replaceable by new sounds, flip the switch:

```csharp
ISoundGroup group = GameEntry.Sound.GetSoundGroup("SoundEffect");
group.AvoidBeingReplacedBySamePriority = false; // Same-priority sounds will also be preempted
```

Source: [ISoundGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Interface/ISoundGroup.cs#L50-L53)

3. Listen for the playback failure event to capture requests that were "ignored due to priority", for analytics tracking or fallback logic:

```csharp
GameEntry.Sound.PlaySoundFailure += (sender, args) =>
{
    if (args.ErrorCode == PlaySoundErrorCode.IgnoredDueToLowPriority)
    {
        // All agents in the current group are occupied, and the priority is not high enough to preempt, so the request is discarded
    }
};
```

Source: [PlaySoundErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundErrorCode.cs#L60-L64)

## Common Variants

- **Critical voice lines are never interrupted**: When playing dialogue/story voice lines, set `Priority` to a value far higher than regular sound effects (e.g., 1000), and keep the group's `AvoidBeingReplacedBySamePriority` as `true`, so that same-priority BGM will not replace it.
- **High concurrency with multiple agents in the same group**: Assign multiple `SoundAgent`s to the `SoundEffect` group (e.g., 8–16), so that most short sound effects can play in parallel; priority arbitration only kicks in when a new request cannot even secure an agent.
- **Concurrency cap only**: If you don't differentiate by priority and just want to limit the number of simultaneous plays within the same group, simply have all requests use the default priority (`Constant.DefaultPriority`) and keep `AvoidBeingReplacedBySamePriority = true`; the earliest sound added will be replaced by new requests.

## Common Mistakes

- **Treating priority as volume or pitch**: `Priority` is an integer used only for preemption arbitration; it has nothing to do with `VolumeInSoundGroup` or `Pitch`.
- **Expecting same-priority replacement without changing the switch**: By default, `AvoidBeingReplacedBySamePriority = true`; a new sound's priority must be strictly higher than the currently playing sound's to preempt it, otherwise `IgnoredDueToLowPriority` is returned.
- **Forgetting to return the parameter object**: `PlaySoundParams` comes from the reference pool; call `ReferencePool.Release(p)` promptly after use to avoid long-term retention causing state pollution.
- **Triggering playback when no agent is available in the group**: Playback also fails when the group has no assigned agents; first make sure `SoundGroup.SoundAgentCount > 0`.

## Background (Optional)

Both `ISoundAgent` and `ISoundAgentHelper` sync `Priority` to the underlying `AudioSource` frame by frame, and the manager arbitrates preemption based on the "agent + priority" model; priority values are a relative concept — business code only needs to ensure that critical sound sources have higher values than ordinary ones.
