# ProcedureComponent の設定方法

`ProcedureComponent` は GameFrameX フローシステムのエントリコンポーネントであり、`IProcedureManager` の登録、利用可能なフロー（プロシージャ）クラスの収集、起動時に指定されたエントリフローへの遷移を担当します。このページでは Unity 上でこれを設定し、ゲームが想定どおりにエントリフローから起動する方法を説明します。

## 前提条件

- `GameFrameX.Procedure` アセンブリがプロジェクトに追加されていること。
- [ProcedureBase](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L80) を継承したフロークラスが用意済みであること（エントリフロー `ProcedureLaunch` など）。
- シーン内に `GameFramework` プレハブ（`GameFrameXEntry` / `GameFrameworkEntry` を含む）が存在し、`GameFrameworkComponent` 派生コンポーネントを保持していること。

## 操作手順

1. シーンに `GameFramework` プレハブを配置し、**Add Component → GameFrameX → Procedure** から `ProcedureComponent` を追加します。

   コンポーネントの属性は `ProcedureComponentInspector` によって Inspector 上で視覚的に表示されます：

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Procedure")]
   [GameFrameXAutoComponent(-1000)]
   public sealed class ProcedureComponent : GameFrameworkComponent
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L43-L46)

2. Inspector の **Available Procedures** 領域で、有効化するすべてのフロークラス（`ProcedureBase` を継承している必要があります）にチェックを入れます。Inspector はリフレクション `typeof(ProcedureBase)` で候補の型を自動収集します：

   ```csharp
   m_ProcedureTypeNames = TypeHelper.GetRuntimeTypeNames(typeof(ProcedureBase));
   ```

   Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L162-L165)

3. **Entrance Procedure** のドロップダウンからエントリフローを選択します。この値はシリアル化されたフィールド `m_EntranceProcedureTypeName` に書き込まれ、起動時に型マッチングでエントリのインスタンスが特定されます：

   ```csharp
   if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
   {
       m_EntranceProcedure = procedures[i];
   }
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L152-L155)

4. Play モードに入ると、コンポーネントは `Start` コルーチン内で `Initialize` と `StartProcedure` を呼び出します：

   ```csharp
   m_ProcedureManager.Initialize(GameFrameworkEntry.GetModule<IFsmManager>(), procedures);
   yield return new WaitForEndOfFrame();
   m_ProcedureManager.StartProcedure(m_EntranceProcedure.GetType());
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L164-L168)

5. 実行後、Inspector 上部の **Current Procedure** フィールドで現在のフローを確認できます：

   ```csharp
   EditorGUILayout.LabelField("Current Procedure", currentProcedureName);
   ```

   Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L83)

## よくあるバリエーション

- **StartupRunner に起動を委譲する**：Inspector の **Use Startup Runner** にチェックを入れます。このモードでは `Awake` で `IProcedureManager` の登録のみを行い、`Initialize` と `StartProcedure` は呼び出しません。`ApplicationStartupEntry` が `StartupRunner.Run` により起動を一元的に引き継ぎます：

  ```csharp
  if (m_UseStartupRunner)
  {
      // 由 ApplicationStartupEntry + StartupRunner.Run 接管 Initialize 和 StartProcedure，
      // 本组件仅承担 Awake 注册 IProcedureManager 的职责，避免与新入口重复 Initialize 报 Already exist FSM。
      yield break;
  }
  ```

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L122-L127)

  チェックを入れた状態では Inspector にメッセージが表示され、下の **Available Procedures** と **Entrance Procedure** の設定は無視されます：

  ```csharp
  EditorGUILayout.HelpBox("流程启动已委托给 StartupRunner.Run。Available Procedures 与 Entrance Procedure 配置将被忽略。", MessageType.Info);
  ```

  Source: [ProcedureComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Editor/Inspector/ProcedureComponentInspector.cs#L59)

- **実行時にフローを再構築する**：`ReinitializeProcedures` を呼び出して既存の状態マシンを破棄し、新しいフロー配列で再初期化します。ホットアップデートや独自の起動順序のカスタマイズによく用いられます：

  ```csharp
  [Preserve]
  public void ReinitializeProcedures(ProcedureBase[] procedures, ProcedureBase entranceProcedure)
  {
      m_ProcedureManager.ReinitializeProcedures(procedures);
      m_EntranceProcedure = entranceProcedure;
  }
  ```

  Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

## よくあるエラー

| 現象 | ログ原文 | 原因と対処 |
|------|----------|-----------|
| フローが起動しない | `Available procedure type names is empty. Procedure auto start skipped.` | Inspector の **Available Procedures** が空です。少なくとも 1 つのフロークラスにチェックを入れてから実行してください。 |
| インスタンスを作成できない | `Can not find procedure type '{0}'.` | 型名がランタイムアセンブリ内に存在しません。フロークラスがコンパイル済みで、名前空間が完全であることを確認してください。 |
| 作成に失敗する | `Can not create procedure instance '{0}'.` | フロークラスに引数なしのコンストラクタがないか、`ProcedureBase` を継承していません。 |
| エントリがない | `Entrance procedure is invalid.` | **Entrance Procedure** が選択されていないか、選択した項目が **Available Procedures** の一覧に含まれていません。 |
| 起動時に FSM 重複エラー | StartupRunner を有効化したのに旧経路の `Initialize` がトリガされる | 2 つのエントリ（`ApplicationStartupEntry` と旧 `ProcedureComponent.Start`）が同時に存在していないか確認し、いずれか一方だけを残してください。 |

## 背景（任意）

`ProcedureComponent` は `Awake` 内で `GameFrameworkEntry.GetModule<IProcedureManager>()` を呼び出してフロー管理モジュールを取得します。`IsRuntimeComponentReady` が真の場合のみ処理が継続されるため、Editor モードにおける誤った初期化を防ぎます。`m_UseStartupRunner` が `false`（既定値）の場合、`Start` コルーチンはリフレクションの型名配列から `ProcedureBase` のインスタンスを生成し、マッチしたエントリフローから起動します。`true` の場合はモジュールの登録のみを行い、初期化と起動はすべて `StartupRunner.Run` に委ね、`Initialize` の重複による `Already exist FSM` エラーを回避します。
