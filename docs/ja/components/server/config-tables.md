# 企画設定表(Tables)の読み書き方法

このページを読み終えると、GameFrameX のすべての企画設定表(`TbAchievementConfig`、`TbItemConfig`、`TbSoundsConfig`、`TbLocalization`)の統一エントリポイントである `TablesComponent`、および設定表からの読み取り、主キーによる検索、列挙、条件検索、参照解析の完全な書き方を習得できます。

## 前提条件

- プロジェクトに `GameFrameX.Config` アセンブリを参照し、対応する企画設定表ファイルを生成済みであること。
- `TablesComponent.Init` の引数として、`ConfigComponent` を構築済みであること。
- `Func<string, Task<JsonElement>>` 型のローダーを用意していること(一般的な実装はローカルファイルやリモートから JSON データをダウンロードし、`JsonElement` として解析する)。

## 操作手順

### 1. すべての設定表を初期化し非同期で読み込む

`TablesComponent` は各表を並列に読み込み、読み込み完了後に自動的に `Refresh()` を呼び出し、内部で `PostInit()` と `ResolveRef()`(テーブル間の参照解析用)をトリガーします。

```csharp
using GameFrameX.Config;
using System.Text.Json;
using System.Threading.Tasks;

// 呼び出し側が実装する、例えばリソース名に基づいて JSON 内容を返す
async Task<JsonElement> Loader(string name)
{
    var bytes = await File.ReadAllBytesAsync($"Configs/{name}.json");
    return JsonDocument.Parse(bytes).RootElement.Clone();
}

var configComponent = new ConfigComponent();
var tables = new TablesComponent();
tables.Init(configComponent);
await tables.LoadAsync(Loader);
```

読み込み完了後、`tables.TbAchievementConfig`、`tables.TbItemConfig`、`tables.TbSoundsConfig`、`tables.TbLocalization` を通じて各表にアクセスできます。

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L56)

### 2. 主キーで単一データを読み取る

すべての表は `BaseDataTable<T>` に基づいており、整数主キーと文字列主キーの 2 種類のインデックス方法をサポートしています。読み取りに失敗した場合のデフォルト戻り値は `null` です。

```csharp
// 整型主キーで読み取り
var item = tables.TbItemConfig[1001];
if (item != null)
{
    Console.WriteLine(item.Name);
}

// 長整型主キーで読み取り(主キーが long として定義されている場合)
var ach = tables.TbAchievementConfig[100001L];

// 文字列主キーで読み取り(ローカライズ表によく使用される)
var loc = tables.TbLocalization["ui.btn.confirm"];
```

`this[id]` の内部は `TryGet(id, out var v) ? v : null` であり、見つからない場合は例外をスローしません。

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L110-L180)

### 3. TryGet を使って安全に取得し「未ヒット」を区別する

`null` を取得したくないが、設定の欠落なのか業務ロジックなのかを区別したい場合は、`TryGet` を使って `bool` の戻り値を取得できます:

```csharp
if (tables.TbSoundsConfig.TryGet(2005, out var sound))
{
    // sound は有効なデータ
}
else
{
    // 設定欠落、企画に表の補充を促す
}
```

文字列キーにも `TryGet(string id, out T value)` のオーバーロードがあり、署名は `IDataTable<T>` インターフェイスを参照してください。

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L138-L141)

### 4. 列挙、統計、条件クエリ

`BaseDataTable<T>` は LINQ スタイルの一般的な操作を提供し、内部で `DataList` に基づいています:

| 操作 | メソッドシグネチャ | 用途 |
|------|---------|------|
| 数量を取得 | `int Count { get; }` | キャッシュをヒットし、複数回呼び出しても重複計算しない |
| 最初を取得 | `T FirstOrDefault { get; }` | ソート後の最初の 1 件を取得 |
| 最後を取得 | `T LastOrDefault { get; }` | ソート後の最後の 1 件を取得 |
| 全配列 | `T[] All { get; }` / `T[] ToArray()` / `List<T> ToList()` | コピーを取得 |
| 条件で 1 件検索 | `T Find(Func<T, bool> func)` | 見つからない場合は `null` を返す |
| 条件で複数検索 | `T[] FindListArray(Func<T, bool> func)` / `List<T> FindList(...)` | 配列またはリストを取得 |
| 列挙して実行 | `void ForEach(Action<T> func)` | 列挙しながら処理 |
| 最大/最小を射影 | `Tk Max<Tk>(Func<T, Tk>)` / `Tk Min<Tk>(...)` | あるフィールドの極値を取得 |

以下に典型的な「タイプでアイテムを検索する」例を示します:

```csharp
// すべての Type == 2 (仮 consumes を表す) のアイテムを検索
var consumables = tables.TbItemConfig.FindListArray(x => x.Type == 2);
Console.WriteLine($"消耗品数量:{consumables.Length}");

// すべての報酬設定の Id の最大値を累計
var maxRewardId = tables.TbAchievementConfig.Max(x => x.Id);
```

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L189-L329)

### 5. 表を再更新する(ホットリロード)

企画表をリロードする必要がある場合は、再度 `LoadAsync` を呼び出します:

```csharp
await tables.LoadAsync(Loader); // 各表を並列で再ロードし Refresh() をトリガーする
```

`Refresh()` は順番に `PostInit()` と `ResolveRef()` を実行し、テーブル間の参照を再構築します。

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L73)

## よくあるバリエーション

### ローカライズ多言語読み取り

`TbLocalization` は `GameFrameX.Config.Local` 名前空間に属し、文字列キーでインデックスされます。使い方は他の表とまったく同じです:

```csharp
var key = "ui.title.home";
if (tables.TbLocalization.TryGet(key, out var loc))
{
    Console.WriteLine(loc.Content);
}
```

### ローダーの再初期化

`Init` はまず `configComponent.RemoveAllConfigs()` を呼び出して古い登録をクリアするため、データソースを一式交換する場合は、`Init` を再呼び出ししてから `LoadAsync` を実行するだけです。

```csharp
tables.Init(newConfigComponent);
await tables.LoadAsync(newLoader);
```

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

## よくあるエラー

- **`LoadAsync` の完了を待たずに読み取る**:`TbAchievementConfig` などのプロパティは `LoadAsync` の前はデフォルト参照であり、デフォルト値から取得すると `null` または空集合が得られます。必ず `await tables.LoadAsync(Loader);` を実行してください。
- **整型と長整型の主キーを混同する**:主キーが `long` として定義されている場合、`int` のオーバーロードで渡すと暗黙の変換がトリガーされますがオーバーフローする可能性があります。主キーが `int` の場合に `long` のオーバーロードを使わないでください、意味が一致しません。
- **テーブル間の参照が更新されていない**:`PostInit()` / `ResolveRef()` は `Refresh()` によってトリガーされるため、カスタムシナリオで `LoadAsync` をバイパスすると、参照フィールドが `null` になる可能性があります。
- **文字列キーにインデックスでアクセスする際のスペルミス**:`this[string id]` で見つからない場合は静かに `null` を返すため、まず `TryGet` で一度チェックする方が安全です。
- **`BaseDataTable` が公開する `LongDataMaps` / `StringDataMaps` を直接変更する**:これらは `protected` ですが、リフレクションで書き換えると以降のホットリロードの冪等性が破壊されるため、再 `LoadAsync` の経路を経るべきです。

## 背景(オプション)

`TablesComponent` は設定表ジェネレーターによって自動生成され(`<auto-generated>` ヘッダー)、各 `Tb*` 表を `ConfigComponent` に登録し、読み込み完了後に `Refresh()` で参照解析を完了します。`BaseDataTable<T>` は検索、列挙、条件クエリ、集約などの共通機能を基底クラスに抽出し、具体的な各表は自身の JSON 解析と主キーマッピングのみを担当します。

`ConfigComponent` の全体的な組み立てについては、`GameFrameX.Config` 名前空間の関連ソースコードを参照してください。各 `Tb*` 表のフィールド定義は、企画設定表ジェネレーターによって Excel/JSON データから自動生成されます。
