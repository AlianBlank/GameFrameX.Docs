# 고성능 해시(MurmurHash3/xxHash 등) 사용 방법

`GameFrameX.Foundation.Hash`는 MurmurHash3와 xxHash 두 가지 비암호화형 고성능 해시 알고리즘의 즉시 사용 가능한 API를 제공하며, 정적 메서드를 직접 호출하여 문자열, 바이트 배열, Type에 대해 32/64/128 비트 해시 값을 계산할 수 있습니다. 주로 해시 테이블 키, 블룸 필터, 로드 밸런싱 샤딩 등 비보안 시나리오에 사용됩니다.

## 사전 조건

- 프로젝트 대상 프레임워크가 .NET이어야 합니다(코드는 `uint`/`ulong`/`ArgumentNullException.ThrowIfNull` 등 BCL API 사용).
- 프로젝트에서 `GameFrameX.Foundation.Hash` 어셈블리를 참조해야 합니다. xxHash 구현은 NuGet 패키지 `Standart.Hash.xxHash`에 의존합니다.

## 작업 단계

### 1. 문자열/Byte 배열의 MurmurHash3 계산

`MurmurHash3Helper`는 두 가지 오버로드를 제공하며, 기본 시드는 `27`입니다:

```csharp
using GameFrameX.Foundation.Hash;

// 문자열 버전: UTF-8 인코딩 후 해시, seed 생략 가능(기본값 27)
uint hash1 = MurmurHash3Helper.Hash("hello");
uint hash2 = MurmurHash3Helper.Hash("hello", seed: 1234u);

// 바이트 배열 버전: length와 seed를 명시적으로 지정
byte[] data = System.Text.Encoding.UTF8.GetBytes("hello");
uint hash3 = MurmurHash3Helper.Hash(data, (uint)data.Length, seed: 27u);
```

Source: [MurmurHash3Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/MurmurHash3Helper.cs#L62-L68)

### 2. xxHash 32/64/128 비트 해시 계산

`XxHashHelper`는 `byte[]`, `string`, `Type` 및 제네릭 오버로드를 모두 제공하며, 반환 타입은 각각 `uint`, `ulong`, `uint128`입니다:

```csharp
using GameFrameX.Foundation.Hash;
using Standart.Hash.xxHash;

// 32비트
uint h32 = XxHashHelper.Hash32("hello");
uint h32Type = XxHashHelper.Hash32<MyClass>();

// 64비트
ulong h64 = XxHashHelper.Hash64("hello");

// 128비트(uint128 반환, high64 / low64 포함)
uint128 h128 = XxHashHelper.Hash128("hello");
bool zero = XxHashHelper.IsDefault(h128); // high64와 low64가 모두 0일 때 true 반환
```

> ⚠️ 명명 규칙 주의: `Hash32(byte[])`는 `ulong`을 반환하고, `Hash32(string)`은 `uint`를 반환합니다. 이는 SDK의 실제 시그니처이며 오기가 아닙니다.

Source: [XxHashHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/XxHashHelper.cs#L62-L100)

### 3. 샤딩 키/해시 테이블 키에서 사용

사용자 ID, 요청 ID, 플레이어 ID 등을 샤딩 또는 해시 테이블 키로 사용할 때는 먼저 바이트로 변환할 필요 없이 문자열을 직접 전달하면 됩니다:

```csharp
// 사용자 ID로 샤드 선택
int shardIndex = (int)(MurmurHash3Helper.Hash(userId) % shardCount);

// 64비트 해시를 해시 버킷에 넣기
ulong bucketKey = XxHashHelper.Hash64($"player:{playerId}");
```

## 일반적인 변형

| 시나리오 | 권장 API | 반환 타입 |
|------|---------|----------|
| 소규모 데이터, 재현 가능한 시드 필요 | `MurmurHash3Helper.Hash(str, seed)` | `uint` |
| 고吞吐量, 바이트 배열, 언어 간 호환성 | `XxHashHelper.Hash32/64/128(buffer)` | `uint`/`ulong`/`uint128` |
| 타입 메타데이터에 대한 안정적 해시(디스패치 테이블) | `XxHashHelper.Hash64<T>()` | `ulong` |
| 부분 길이 해시(스트리밍/샤딩 데이터) | `XxHashHelper.Hash128(buffer, length)` | `uint128` |

## 일반적인 오류

- **MurmurHash3를 암호화 해시로 사용**: MurmurHash3는 비암호화 해시로, 충돌/프리이미지 공격에 저항할 수 없으므로 비밀번호, 토큰, 서명에 사용하지 마세요.
- **시드 일관성 무시**: 동일한 데이터를 서로 다른 `seed`로 해시하면 완전히 다른 결과가 나옵니다. 업스트림과 다운스트림 간 일관성이 필요하면 동일한 시드(기본값 `27`)를 사용해야 합니다.
- **`Hash32(byte[])`와 `Hash32(string)`의 반환 타입 혼동**: 전자는 `ulong`을 반환하고, 후자는 `uint`을 반환하며, 이는 SDK의 실제 시그니처 차이입니다.
- **`null` 전달**: 모든 오버로드는 `ArgumentNullException`을 던지므로, 먼저 `??`로 방어하거나 사전 검증하세요.
- **MD5/SHA-1을 보안 시나리오에 사용**: `HashAlgorithmKind` 열거형의 `Md5`, `Sha1`은 호환성 및 비보안 검증에만 적합하며, 비밀번호 시나리오에서는 `PasswordHashHelper`를 사용해야 합니다.

## 배경(선택)

MurmurHash3는 본 SDK에서 순수 관리형(managed) 방식으로 구현되었으며, 핵심은 4바이트 블록 루프 + 테일 병합 + `Fmix32` 마무리 믹스입니다. 일반적인 용도는 해시 테이블 키, 캐시 샤딩입니다. xxHash는 NuGet 패키지 `Standart.Hash.xxHash`를 통해 네이티브 구현을 호출하며, 32/64비트는 대부분의 하드웨어에서 MD5/SHA 계열보다 처리량이 현저히 높습니다. 둘 다 암호화 알고리즘이 아니므로, "변조 방지" 용도로는 SHA-2/3 또는 HMAC이 필요합니다.
