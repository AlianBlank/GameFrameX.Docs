# 工作原理：Hotfix 入口与启动流程

Hotfix 启动由框架内的 [`HotfixHelper`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs) 负责：它在运行时加载 AOT DLL 与热更 DLL，定位约定的入口类型与方法，并通过反射触发热更代码的初始化。应用层通过 [`ApplicationHotfixLauncher`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs) 将这套逻辑适配到启动管线的 `IHotfixLauncher` 接口上。

## 启动入口一览

| 入口 | 类型 | 作用 |
|------|------|------|
| `HotfixHelper.StartHotfix()` | `async void` | 默认选项触发，丢弃返回结果 |
| `HotfixHelper.StartHotfixAsync(StartupOptions)` | `async UniTask<HotfixLaunchResult>` | 异步加载并返回启动结果 |
| `ApplicationHotfixLauncher.StartAsync(StartupOptions)` | `UniTask<HotfixLaunchResult>` | `IHotfixLauncher` 适配器，转发到 `HotfixHelper.StartHotfixAsync` |

默认参数（`options == null` 或字段为空时生效）：

| 字段 | 默认值 |
|------|--------|
| `HotfixAssemblyName` | `Unity.Hotfix` |
| `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` |
| `HotfixEntryMethodName` | `Main` |

## 启动步骤

1. 调用 `HotfixHelper.StartHotfixAsync(options)`，方法会进入 `try/catch` 包裹的内部实现 `StartHotfixInternalAsync`。
2. 解析最终的 `assemblyName` / `entryTypeName` / `entryMethodName`，缺省值分别为 `Unity.Hotfix`、`Hotfix.HotfixLauncher`、`Main`。
3. 根据宏 `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR` 选择加载路径：
   - **启用 HybridCLR（且非 Editor）**：先迭代 `AOTGenericReferences.PatchedAOTAssemblyList`，对每个 AOT DLL 通过 `GameApp.Asset.LoadAssetAsync<UnityEngine.Object>` 加载并调用 `RuntimeApi.LoadMetadataForAOTAssembly`；再加载 `Unity.Hotfix.dll` 并 `Assembly.Load`。
   - **Editor 或未启用 HybridCLR**：直接进入 `RunNative`，通过 `Utility.Assembly.GetType` 反射调用入口。
4. 反射命中目标类型与方法后 `method.Invoke(null, null)`，热更层拿到控制权。
5. 成功时返回 `HotfixLaunchResult.Succeed()`；抛出异常时通过 `Log.Error` 记录并返回 `HotfixLaunchResult.Fail(e.Message)`。

public static async UniTask<HotfixLaunchResult> StartHotfixAsync(StartupOptions options)
{
    try
    {
        await StartHotfixInternalAsync(options);
        return HotfixLaunchResult.Succeed();
    }
    catch (Exception e)
    {
        Log.Error(e);
        return HotfixLaunchResult.Fail(e.Message);
    }
}

## 关键加载路径

| 阶段 | 调用 | 说明 |
|------|------|------|
| AOT 元数据加载 | `RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet)` | HybridCLR 模式下必须先加载所有 AOT DLL，否则热更代码中泛型共享会失败 |
| 热更 DLL 加载 | `Assembly.Load(assemblyDataHotfixDll, null)` | 把字节数组加载为运行时程序集 |
| 入口反射 | `assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | 通过反射调用无参静态入口 |
| 原生回退 | `Utility.Assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | 非 HybridCLR 模式从已加载 AppDomain 中查找入口类型 |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `entryType` 为 `null`，反射 `NullReferenceException` | 传入的 `HotfixEntryTypeName` 与 DLL 内类型不匹配，或 `Unity.Hotfix.dll` 未打包进资源 | 确认 `options.HotfixEntryTypeName` 与 DLL 中命名空间/类名完全一致；检查 `Utility.Asset.Path.GetCodePath("Unity.Hotfix.dll")` 是否能解析到资源 |
| 泛型方法调用报 `MissingMethodException` 或 `TypeLoadException` | HybridCLR 模式下未加载 `AOTGenericReferences.PatchedAOTAssemblyList` 中的 AOT DLL | 检查 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 宏是否启用，确认 `AOTGenericReferences` 已生成并随包发布 |
| Editor 下加载不到 `Unity.Hotfix` 程序集 | `StartHotfixInternalAsync` 在 Editor 走 `Utility.Assembly.GetAssemblies()` 遍历，未命中大小写敏感的名称 | 在 `StartupOptions.HotfixAssemblyName` 中显式传入正确名称，或确认程序集名 `Unity.Hotfix` 与 DLL 一致 |
| `StartHotfix()` 抛出后没有错误回调 | `StartHotfix` 是 `async void`，异常仅写日志 | 改用 `StartHotfixAsync(options)` 接收 `HotfixLaunchResult`，检查 `Succeed` / `Fail` 字段 |
