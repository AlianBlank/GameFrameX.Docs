# 如何使用 Bot 客户端做联调与压测

`GameFrameX.Client` 是一个独立的 .NET 控制台程序，用来模拟一批机器人玩家同时连接游戏服，自动完成"账号登录 → 角色列表 → 创建/登录角色"的完整链路，配合 `EnableDisconnectLoop` 还能循环重连，常用于联调验证和压力测试。

## 前置条件

- 一台可登录的游戏服（默认假设监听 `127.0.0.1:49100` 的 TCP 网关）。
- 启用了 HTTP 登录网关（默认 `http://127.0.0.1:48080/game/api/`，由 `BotRunOptions.LoginUrl` 指定）。
- 已安装 .NET SDK 10（脚本调用 `dotnet run --framework net10.0`）。
- 账号口令使用测试夹具默认口令 `12312`（常量 `DefaultBotLoginSecret`），所有机器人共享，可通过 `--login-password` 覆盖。

## 操作步骤

1. **进入仓库根目录**（脚本通过相对路径定位工程文件）：

   ```bash
   cd GameFrameX.Server.Source
   ```

2. **直接运行多 Bot 脚本**（推荐压测入口，自动设置默认值并打印运行参数）：

   ```bash
   bash scripts/multi/run-bots-rpc.sh
   ```

   脚本内部最终会调用 `dotnet run`，并把环境变量透传为命令行参数。

   Source: [scripts/multi/run-bots-rpc.sh](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/scripts/multi/run-bots-rpc.sh#L1-L37)

3. **手动用 `dotnet run` 启动**（联调时更灵活）：

   ```bash
   dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
     --bot-count=50 \
     --tcp-host=127.0.0.1 \
     --tcp-port=49100 \
     --login-url=http://127.0.0.1:48080/game/api/ \
     --scenario=login
   ```

   `--scenario` 接受逗号分隔的多个场景名（如 `login,friend`），由 `BotRunOptions.HasScenario` 判断是否启用。

   Source: [GameFrameX.Client/Bot/BotRunOptions.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotRunOptions.cs#L31-L70)

4. **观察输出日志**：每个 Bot 跑通登录流程后会输出一行 `[METRICS] connect=… auth=… list=… create=… login=… total=…`（毫秒），用于评估各阶段耗时。

   Source: [GameFrameX.Client/Bot/BotClient.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotClient.cs#L184-L187)

## 命令行参数速查

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--bot-count` | int | 50 | 同时启动的机器人数量 |
| `--bot-prefix` | string | `BotClient` | 机器人名前缀，编号从 `_1` 起递增 |
| `--tcp-host` | string | `127.0.0.1` | 游戏服 TCP 网关地址 |
| `--tcp-port` | int | 49100 | 游戏服 TCP 网关端口 |
| `--login-url` | string | `http://127.0.0.1:48080/game/api/` | HTTP 登录网关基址，自动补齐末尾 `/` |
| `--login-password` | string | `12312` | 所有机器人共享的登录口令 |
| `--connect-stagger-ms` | int | 20 | 每个 Bot 启动间隔，避免瞬时打满连接 |
| `--disconnect-loop` | bool | true | 登录完成后是否自动断线循环 |
| `--disconnect-after-login-seconds` | int | 15 | 登录成功后多少秒断线 |
| `--run-seconds` | int | 0 | 总运行时间，0 表示持续运行直到手动停止 |
| `--scenario` | string | `login` | 启用的场景，逗号分隔 |

Source: [GameFrameX.Client/Bot/BotRunOptions.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotRunOptions.cs#L14-L70)

## 常见变体

- **小规模联调（验证业务流程）**：降到 5~10 个 Bot，`--run-seconds=60`，关闭断线循环 `--disconnect-loop=false`，便于人眼观察日志。

  ```bash
  dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
    --bot-count=5 --run-seconds=60 --disconnect-loop=false
  ```

- **连接型压测（打满网关）**：保留默认断线循环，缩短 stagger 间隔到 5~10ms，让 Bot 持续重连以验证网关稳定性：

  ```bash
  bash scripts/multi/run-bots-rpc.sh
  # 默认 BOT_COUNT=100、CONNECT_STAGGER_MS=10、RUN_SECONDS=180
  ```

- **自定义环境压测**：通过环境变量覆盖脚本默认参数，例如连到测试服并跑 300 秒：

  ```bash
  BOT_COUNT=200 RUN_SECONDS=300 TCP_HOST=10.0.0.5 TCP_PORT=49100 \
    bash scripts/multi/run-bots-rpc.sh
  ```

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| Bot 启动后立即报 `EntryAsync Error: …` | TCP 网关不可达或端口被占用 | 检查 `TcpHost`/`TcpPort`，确认游戏服已启动并监听 |
| 日志反复出现 `账号登录失败，错误码:非0` | 登录网关未启用或口令不一致 | 检查 `LoginUrl` 是否能访问、`--login-password` 是否与服务端校验一致 |
| `[METRICS]` 始终缺字段（如 `list=-1`） | 该阶段未进入（账号或前置流程失败） | 顺着前面 ERROR 日志定位上游失败原因 |
| 服务器侧连接数迅速打满 | stagger 间隔过小或 Bot 数过大 | 调大 `--connect-stagger-ms` 或降低 `--bot-count` |

## 背景（可选）

`BotClient` 内部用 `BotTcpClient` 维护一条到游戏服 TCP 网关的长连接；连接建立后立即发 `ReqLogin`，服务端返回 `RespLogin` 触发角色列表请求，再按需 `ReqPlayerCreate` / `ReqPlayerLogin`，登录成功后会在 `EnableDisconnectLoop=true` 时调度一次断开重连。所有 Bot 共享同一个 `BotRunOptions`（连接地址、端口、口令、场景开关等），并通过 `BotRunOptions.Parse` 从命令行读取覆盖值。指标通过 `LogHelper.Info` 以 `[METRICS]` 前缀输出，便于脚本聚合。
