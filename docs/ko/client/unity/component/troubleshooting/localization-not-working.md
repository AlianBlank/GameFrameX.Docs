# 로컬라이제이션 텍스트가 적용되지 않을 때 해결 방법

`GameApp.Localization.GetString(key)`를 호출하거나 FairyGUI/UI 컴포넌트를 통해 다국어 텍스트를 조회할 때, 여전히 이전 언어 문자열, Key 자체 또는 빈 값이 반환된다면 로컬라이제이션 데이터가 현재 `GameApp.Localization.Language`에 맞게 채워지지 않은 것입니다. 이 페이지에서는 일반적인 원인과 그에 맞는 진단 방법 및 수정 단계를 안내합니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GetString(key)` 호출 시 Key 문자열 자체가 반환됨 | 설정 테이블의 `Key` 필드가 비어 있거나 생성되지 않음 | `local_tblocalization.json`에서 `key` 열이 채워져 있는지 확인하고, 설정 코드를 다시 생성 |
| `Language`를 전환해도 텍스트가 바뀌지 않음 | `TranslateText()`가 호출되지 않았거나 호출 순서가 잘못됨 | 시작 흐름에서 먼저 `Config.GetConfig<TbLocalization>()`를 호출한 뒤, `TranslateText()`를 호출 |

## 수정 단계

### 1. 시작 흐름에서 `TranslateText` 호출 확인

`TranslateText()`는 `TbLocalization` 테이블의 다국어 필드를 현재 언어에 맞춰 내부 딕셔너리에 쓰는 역할을 합니다. 이 단계를 건너뛰면 어떤 값도 가져올 수 없습니다.

```csharp
// 1. 원본 데이터 삭제
GameApp.Localization.RemoveAllRawStrings();
// 2. 설정 테이블에서 데이터 로드
var tbLocalization = GameApp.Config.GetConfig<TbLocalization>();
// 3. 데이터 채우기
tbLocalization.ForEach(localization =>
{
    if (localization.Key.IsNullOrWhiteSpace())
    {
        return;
    }
    // ... switch GameApp.Localization.Language ...
    GameApp.Localization.AddRawString(localization.Key, value);
});
```

Source: [HotfixLauncher.cs#L66-L164](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L66-L164)

주의: Key가 빈 행은 바로 `return`되어 딕셔너리에 쓰여지지 않습니다. 설정 테이블로 돌아가서 Key를 채워주세요.

### 2. switch 분기에서 현재 언어 확인

생성된 `Localization` 엔티티에는 총 15개의 언어 필드가 있으며, 런처는 `LocalizationCode` 열거형을 하나씩 매칭합니다. 매칭되지 않은 언어는 `default`로 떨어지며, `DefaultLanguage == English`일 때만 영어 값을 받고, 그 외에는 `string.Empty` 상태로 유지됩니다.

```csharp
case LocalizationCode.ChineseSimplified:
    value = localization.ChineseSimplified;
    break;
case LocalizationCode.English:
    value = localization.English;
    break;
// ... ChineseTraditionalTW / HK / French / German / Italian / Japanese /
//     Korean / Portuguese* / Spanish* / Thai / Vietnamese / Russian / Indonesian
default:
{
    if (GameApp.Localization.DefaultLanguage == LocalizationCode.English)
    {
        value = localization.English;
    }
}
    break;
```

Source: [HotfixLauncher.cs#L82-L161](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L82-L161)

만약 대상 언어가 위 분기에 없다면(예: 아랍어를 새로 추가한 경우) 다음 작업이 필요합니다.

1. LuBan 테이블 `local_tblocalization.json`에 해당 열을 새로 추가합니다.
2. `Localization.cs`를 다시 생성하여 새 필드가 생성자와 JSON 파서에 포함되도록 합니다.
3. `HotfixLauncher.TranslateText`의 switch에 새로운 `case`를 추가해 필드를 `value`에 매핑합니다.

### 3. 설정 테이블과 생성 코드의 동기화 여부 확인

생성된 `Localization` 생성자는 각 필드에 대해 문자열 여부를 검사하며, 필드가 누락되면 역직렬화 시 `SerializationException`이 발생하여 테이블 전체의 로드가 실패합니다.

```csharp
public Localization(JSONNode _buf)
{
    { if(!_buf["key"].IsString) { throw new SerializationException(); }  Key = _buf["key"]; }
    { if(!_buf["ChineseSimplified"].IsString) { throw new SerializationException(); }  ChineseSimplified = _buf["ChineseSimplified"]; }
    { if(!_buf["English"].IsString) { throw new SerializationException(); }  English = _buf["English"]; }
    // ... 나머지 12개 언어에 대해서도 동일한 구조의 검증
}
```

Source: [Localization.cs#L38-L59](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Local/Localization.cs#L38-L59)

수정 방법: LuBan 에디터에서 `local_tblocalization.json`을 열고, 15개 언어 필드명(ChineseSimplified, ChineseTraditional, English, Japanese, Korean, Thai, Indonesian, French, German, Russian, Italian, PortuguesePortugal, Spanish, Vietnamese)과 `key` 열이 모두 존재하며 문자열 타입인지 확인한 뒤, 코드를 다시 생성합니다.

### 4. 언어 전환 후 UI 강제 새로 고침

단순히 `GameApp.Localization.Language`를 변경하는 것만으로는 설정이 다시 읽히지 않으며, 딕셔너리의 기존 값을 덮어쓰려면 `TranslateText()`를 다시 실행해야 합니다. 일반적인 방법은 언어 전환 이벤트에서 이 메서드를 호출한 뒤, UI 레이어로 `OnLanguageChanged`를 브로드캐스트하는 것입니다.

## 검증

다음 순서대로 문제가 해결되었는지 확인하세요.

1. 게임을 실행하고, 콘솔에서 `tbLocalization`의 행 수가 0보다 크며 `SerializationException`이 발생하지 않았는지 확인합니다.
2. 스크립트에서 임시로 `GameApp.Localization.GetString("설정 테이블에 있는 특정 Key")`를 호출하고, 반환값이 Key 자체가 아닌 현재 `Language`에 해당하는 문자열인지 브레이크포인트로 확인합니다.
3. FairyGUI/UGUI의 로컬라이제이션 컴포넌트로 Key를 사용하는 텍스트 노드를 열고, 실행 시 표시되는 값을 확인합니다.
4. `GameApp.Localization.Language = LocalizationCode.English`(또는 다른 언어)로 전환하고, `TranslateText()`를 다시 호출한 뒤, UI 텍스트가 전환에 따라 업데이트되는지 다시 확인합니다.

## 일반적인 오류

- `local_tblocalization.json`을 직접 수정한 뒤 LuBan의 "코드 생성" 버튼을 누르는 것을 잊어, 실행 시 코드의 필드명이 맞지 않아 역직렬화가 조용히 실패하는 경우.
- `TranslateText()`를 `Awake`에서 호출하도록 작성했지만, 이때 `GameApp.Config`가 아직 초기화되지 않아 `GetConfig<TbLocalization>()`가 null을 반환하는 경우.
- 테이블의 Key가 중국어 또는 공백이 포함된 문자열로 작성되어, 호출 측에서 Key를 전달할 때 오타가 나기 쉬운 경우. 영문 숫자 + 언더스코어를 사용하는 통일하는 것을 권장합니다.
- `default` 분기에서 영어 폴백에 의존하지만 `DefaultLanguage`가 `English`가 아닌 경우, 일부 언어가 빈 문자열로 표시되는 문제.
