# What to Do When Ad Loading or Playback Fails

When `Play(...)` or `Load(...)` triggers a failure callback, it is usually caused by missing configuration, an unfilled ad unit ID, an uninitialized SDK, or unbound callbacks. Below, match the symptoms to the causes, locate the issue, and then follow the steps to fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Play` goes straight into `OnFail`, no ad events in logs | `Initialize` was not called or `m_config` is null | Inject `AdvertisementConfig` into `AdvertisementComponent` before `Start`, or assign the config asset in the Inspector |
| `Log.Fatal("Advertisement manager is invalid.")` | The framework did not register an advertisement manager implementation | Register a subclass of `BaseAdvertisementManager` via `AdvertisementConfigAttribute` and place it in the scene startup chain |
| No callbacks at all from load/play | `AdvertisementPlayOption.OnSuccess/OnFail/OnShowResult` not assigned | Assign all three Actions on `AdvertisementPlayOption` before calling `Play` |
| iOS/Android/mini-game loads empty config | The ad unit ID field for the current platform is empty | Fill in `m_adUnitIdAndroid`, `m_adUnitIdiOS`, or one of the three mini-game fields (`WeChat` / `DouYin` / `KuaiShou`) |
| `Play` reports an error but `OnShowResult` returns false | The display flow succeeded but the SDK marked it as not fully played | Check the ad unit review status and whether the creative was rejected; see the "Ad Unit Review Rejected" section |
| `Load` deprecation warning | Using the old API | Switch to `Play(AdvertisementPlayOption)`; do not use `Load(success, fail)` |

## Fix Steps

### 1. Confirm the advertisement manager is registered

`AdvertisementComponent.Awake()` uses reflection to obtain an `IAdvertisementManager` implementation; if it cannot find one, it will directly call `Log.Fatal`. Check the following:

- Your custom manager class has `[AdvertisementConfigAttribute]` and inherits from `BaseAdvertisementManager`
- The class is actually compiled into the runtime assembly in the project
- `AdvertisementComponent` exists in the scene, and the `componentType` field points to your custom manager

Reference implementation location: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L87-L118)

### 2. Inject AdvertisementConfig

`Start()` only calls `_advertisementManager.Initialize(m_config)` when `m_config != null`. Remember to drag the advertisement config asset onto the `m_config` field in the Inspector, or initialize it explicitly in code:

```csharp
var component = GameEntry.GetComponent<AdvertisementComponent>();
component.Initialize(myAdvertisementConfig);
```

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L140)

### 3. Fill in the ad unit ID for the current platform

`AdUnitId` is selected based on platform compile directives; if any branch is empty, the SDK will not receive a valid ID. Common omissions:

- Only the iOS ID is filled in for the Android channel
- A generic ID is selected for WebGL, but the `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` macros are enabled and the mini-game-specific unit is not filled in

Confirm that at least one of `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` has a value in the Inspector.

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57)

### 4. Complete the playback callbacks

If any of the three Actions on `AdvertisementPlayOption` is not assigned, the corresponding callback will not fire:

```csharp
var option = new AdvertisementPlayOption
{
    OnSuccess = json => Debug.Log($"Reward granted successfully: {json}"),
    OnFail    = err  => Debug.LogError($"Playback failed: {err}"),
    OnShowResult = shown => Debug.Log($"Fully displayed: {shown}"),
    customData = "level=1",
};
component.Play(option);
```

`extraData` is only serialized and passed through to the server during the Load phase; changing it after loading completes has no effect.

Source: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L84)

### 5. Do not use the deprecated Load

`BaseAdvertisementManager.Load(Action<string>, Action<string>, string)` is marked as `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`. Continuing to use it only triggers a warning and does not automatically bridge to the new flow. Consistently use `Play(AdvertisementPlayOption)` instead.

Source: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L236-L238)

### 6. Debug mode troubleshooting

Enable `m_debug = true` (or pass `true` as the second argument to `Initialize`) so the SDK outputs more detailed request logs, helping identify whether the issue is with the network, signature, or an error code returned by the ad unit.

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L59)

## Verification

After fixing, confirm each of the following:

1. The fatal log `Advertisement manager is invalid.` no longer appears in the startup logs.
2. When calling `Play`, at least one of `OnSuccess` or `OnFail` is triggered, rather than being "completely silent".
3. When switching between compilation targets such as Android / iOS / WeChat Mini Game / Douyin / Kuaishou Mini Game, `AdUnitId` is not empty.
4. Confirm in the ad platform backend that the ad unit status is "Approved" and that no frequency-capping policy has been triggered.
