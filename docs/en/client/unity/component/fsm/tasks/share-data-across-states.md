# How to Share Data Between States (Variable)

Use the built-in `SetData` / `GetData` methods of `Fsm<T>` to store and retrieve `Variable` instances with a string as the key, allowing runtime data to be safely passed between any two `FsmState<T>` instances.

## Prerequisites

- A finite state machine has been created via `FsmComponent.CreateFsm<T>`, with at least two states registered.
- The state class inherits from `FsmState<T>` and can access the FSM through the `fsm` parameter in `OnEnter` / `OnUpdate` / `OnExit`.
- The shared data type must inherit from `Variable` (either built-in or custom).

## Steps

1. **Confirm the shared data type**: The framework requires that the data derive from `Variable`. This is because the FSM reuses `Variable` instances through the object pool (`ReferencePool`) to avoid GC.

   ```csharp
   // Share an integer progress (0~100)
   public sealed class ProgressVar : Variable
   {
       private int m_Value;
       public int Value
       {
           get => m_Value;
           set => m_Value = value;
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L46)

2. **Write data in state A**: Call `SetData<TData>(name, data)`. When data with the same name is written again, the old instance is automatically recycled back to `ReferencePool`.

   ```csharp
   public class LoadingState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = new ProgressVar { Value = 0 };
           fsm.SetData("Progress", progress);
       }

       protected override void OnUpdate(IFsm<MyOwner> fsm, float elapseSeconds, float realElapseSeconds)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress != null)
           {
               progress.Value += 1; // Directly modify Value, no need to Set again
           }
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L497-L500)

3. **Read data in state B**: Use the strongly-typed `GetData<TData>(name)` to directly obtain the derived class instance; if the key does not exist or the type does not match, `null` is returned.

   ```csharp
   public class PlayState : FsmState<MyOwner>
   {
       protected override void OnEnter(IFsm<MyOwner> fsm)
       {
           var progress = fsm.GetData<ProgressVar>("Progress");
           if (progress == null)
           {
               // The state machine does not carry this data, fall back as needed
               return;
           }
           fsm.Owner.Ui.ShowProgress(progress.Value);
       }
   }
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

4. **Clean up data when no longer needed**: Call `RemoveData(name)`, and the data object will be recycled back to the object pool.

   ```csharp
   fsm.RemoveData("Progress");
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L535)

## Common Variations

| Scenario | Usage | Notes |
|------|------|------|
| Don't know the exact type, only care whether it exists | `fsm.GetData("Progress")` returns `Variable` base class | See [Fsm.cs#L469](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488) |
| Multiple states repeatedly overwrite the same key | Simply call `SetData` again | The old instance will automatically call `ReferencePool.Release` ([Fsm.cs#L521-L524](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L521-L524)) |
| Shared data does not require GC reuse | Any `Variable` subclass can be passed | The framework only enforces that the base class be `Variable`; fields are free |

## Common Errors

| Error Symptom | Cause | Fix |
|----------|------|------|
| Passing an empty string as `name` throws `GameFrameworkException("Data name is invalid.")` | The API requires `name` to be non-empty | Use constants or enums as keys |
| `GetData<TData>` returns `null`, causing NRE | The key was never written, or the type does not match | Read after `SetData` on the writing side, or use `GetData(name)` to check existence first |
| Repeated `new` of same-named data causes memory growth | `Variable` objects are not being reused | Reuse the same instance and only modify its internal fields; only `SetData` to overwrite when necessary |
| Accessing `GetData` after FSM is destroyed | The FSM has been destroyed | Clean up references within `OnExit`, do not cache the `IFsm<T>` handle |

## Background (Optional)

`m_Datas` is a `Dictionary<string, Variable>`, created on demand by `Fsm<T>` on the first `SetData` call ([Fsm.cs#L515-L518](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L515-L518)). When overwriting a same-named key, `ReferencePool.Release` is called to return it to the pool, so `Variable` must implement the reference pool protocol (inheriting from `Variable` already provides this).
