# UIフォームの依存リソース読み込み異常時の対処方法

UIフォームを開く際(`OpenUIFormAsync`)に依存リソースの読み込み失敗に遭遇した場合――依存アセットが存在しない、読み込みコールバックがトリガーされない、依存カウントが長時間変化しない、またはオープンフローが中断されるなど――本ページの診断表で根本原因を特定し、修復できます。

## クイック診断

| 症状 | 原因 | 修復方法 |
|------|------|------|
| `OpenUIFormFailure` イベントがトリガーされ、`ErrorMessage` にリソースが存在しない旨が表示される | 渡された `uiFormAssetPath` が実際のアセットパスと一致しない、またはアセットが AssetBundle / Addressables に含まれていない | パス文字列と `UIFormAssetName` を照合し、依存リストを再構築する |
| `LoadedCount` が常に 0 のままで、`TotalCount` が 0 より大きい | 依存リソースの読み込みコールバックが正しく登録されていない、または同時実行のオープンリクエストに割り込まれている | 同一リソースのオープンを直列化し、`OpenUIFormDependencyAssetEventArgs` のリスニング経路を確認する |
| `DependencyAssetName` が `null` | UIフォーム自体に依存アセットが宣言されていない、または依存メタデータが生成されていない | UI設定を再生成し、依存アセットリストが空でないことを確認する |
| `Task` が長時間 `IUIForm` を返さない | 依存読み込みチェーンが完了しておらず、非同期フローが `await` でブロックされている | `OpenUIFormAsync` の呼び出し元で `await` の漏れがないか確認し、リソースマネージャーが初期化済みであることを確認する |
| `UIFormAssetPath` / `UIFormAssetName` が `null` | 上位の呼び出しで有効なパスが渡されていない | `OpenUIFormAsync` を呼び出す前にパラメータを検証し、`GameFrameworkGuard.NotNull` を使用する |

イベントオブジェクトの主要なフィールド定義は以下の通りです。ログと照合して確認できます:

## 修復手順

### 1. リソースパスまたは名前の不一致

`OpenUIFormAsync` は 2 つの重要なパラメータを受け取ります:リソースパス `uiFormAssetPath` とリソース名 `uiFormAssetName`(読み込みオブジェクト内)です。いずれかがプロジェクト内に実在するアセットに対応していない場合、読み込みは即座に失敗し、`OpenUIFormFailure` を通じてスローされます。

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class UIFormLoadingObject : IReference
{
    public string UIFormAssetPath { get; private set; }
    public string UIFormAssetName { get; private set; }
    public Type UIFormType { get; private set; }
    public Task<IUIForm> Task { get; private set; }

    public static UIFormLoadingObject Create(string uiFormAssetPath, string uiFormAssetName, Type uiFormType, Task<IUIForm> task)
    {
        var uiFormLoadingObject = ReferencePool.Acquire<UIFormLoadingObject>();
        uiFormLoadingObject.UIFormAssetPath = uiFormAssetPath;
        uiFormLoadingObject.UIFormAssetName = uiFormAssetName;
        uiFormLoadingObject.UIFormType = uiFormType;
        uiFormLoadingObject.Task = task;
        return uiFormLoadingObject;
    }
}
```

Source: [BaseUIManager.UIFormLoadingObject.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.UIFormLoadingObject.cs#L43-L86)

操作手順:

1. Unity で該当する UI プレハブを特定し、その `Addressables` アドレスまたは AssetBundle パスをコピーします。
2. `OpenUIFormAsync` を呼び出す際、完全に同一の文字列を使用します(大文字・小文字は区別されます)。
3. `OpenUIFormFailure` コールバック内で `UIFormAssetName` と `ErrorMessage` を出力し、一文字ずつ照合します。

### 2. 非同期フローが待機されていない

`OpenUIFormAsync` は `Task<IUIForm>` を返し、内部実装の `InnerOpenUIFormAsync` は抽象メソッドであり、依存の読み込みはサブクラスによって完了されます。

```csharp
[UnityEngine.Scripting.Preserve]
public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}

[UnityEngine.Scripting.Preserve]
protected abstract Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false);
```

Source: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L114-L130)

呼び出し元で `await` が漏れていると、`Task` は未完了の状態のまま黙って破棄され、後続の処理で `uiForm` を読み取った際に `null` が得られます。修復方法：

1. 呼び出し箇所では統一的に `await uiManager.OpenUIFormAsync<MyForm>(path, true, userData);` を使用します。
2. コルーチンやコールバックスタイルのコードでは、コンテキストを同期するために `.ContinueWith(...)` または `await` を使用します。
3. `OpenUIFormSuccess` / `OpenUIFormFailure` イベントと組み合わせて、フローが終了したことを確認します。

### 3. 依存カウントが変化しない / コールバックがトリガーされない

`OpenUIFormDependencyAssetEventArgs` は現在 `BaseUIManager` 内でコメント形式で保持されています(`m_OpenUIFormDependencyAssetEventHandler` はコメントアウト済み)。プロジェクトでこのイベントを購読していた場合は、再度有効化し、サブクラスが依存の読み込みプロセス中に `EventId` を呼び出して配信する必要があります。`LoadedCount` / `TotalCount` が長時間変化しない場合、通常は依存読み込みコールバックが駆動されていないか、`TotalCount` が初期化前に 0 として読み取られていることが原因です。

カスタムの `BaseUIManager` サブクラス内で以下を行うことを推奨します:

1. `InnerOpenUIFormAsync` 内で依存アセットのリストを取得し、`totalCount` を得ます。
2. 依存の読み込みが 1 つ完了するたびに、`OpenUIFormDependencyAssetEventArgs.Create(...)` を呼び出し、イベントバスを通じてブロードキャストします。
3. リスナー側で `LoadedCount` / `TotalCount` を読み取り、プログレスバーを駆動します。

### 4. 失敗イベントが未登録

`OpenUIFormFailure` イベントは例外のキャプチャに使用されます。シグネチャは以下の通りです:

```csharp
[UnityEngine.Scripting.Preserve]
public event EventHandler<OpenUIFormFailureEventArgs> OpenUIFormFailure
{
    add { m_OpenUIFormFailureEventHandler += value; }
    remove { m_OpenUIFormFailureEventHandler -= value; }
}
```

Source: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L63-L68)

アプリケーションがこのイベントを購読していない場合、例外は `Task` からスローされるのみで、上位層で黙って飲み込まれる可能性があります。修復方法：UI フレームワークの起動直後に `OpenUIFormFailure` と `OpenUIFormSuccess` を登録し、エラーログを一元的にファイルへ書き出すか、報告します。

## 検証

1. 正常なオープンフローを一度トリガーし、`OpenUIFormSuccess` がトリガーされ、`SerialId` がリクエストと一致することを確認します。
2. 意図的に誤ったパスを指定したオープンリクエストを一度トリガーし、`OpenUIFormFailure.ErrorMessage` に読み取り可能な情報が含まれていることを確認します。
3. 依存アセットを持つUIフォームを一度トリガーし、`LoadedCount` が最終的に `TotalCount` と等しくなることを確認します。
4. デバッガーで `UIFormLoadingObject.Task.Status` を観察し、`WaitingForActivation` から `RanToCompletion` または `Faulted` に遷移することを確認します。
