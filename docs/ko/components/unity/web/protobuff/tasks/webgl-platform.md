# WebGL 및 크로스 플랫폼 사용 가이드

이 페이지에서는 WebGL과 기타 플랫폼(에디터, Windows, 모바일 등)에서 Web ProtoBuff 컴포넌트를 사용하여 ProtoBuf HTTP 요청을 보내는 방법을 설명합니다: 호출자는 동일한 `Post<T>` API를 사용하고, 컴포넌트 내부에서 `#if UNITY_WEBGL`을 통해 `UnityWebRequest`와 `HttpWebRequest`를 자동으로 전환하므로, 플랫폼별로 코드를 두 벌 작성할 필요가 없습니다.

## 사전 조건

- `com.gameframex.unity.web.protobuff` 패키지 및 해당 의존성(GameFrameX, `GameFrameX.Network`, ProtoBuf 런타임)이 설치되어 있어야 합니다.
- 요청 및 응답 메시지 클래스는 `MessageObject`를 상속하며, 응답 클래스는 추가로 `IResponseMessage`를 구현해야 합니다.
- WebGL 빌드는 IL2CPP를 사용합니다; 패키지에 포함된 [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs)가 빌드 크로핑 처리에 참여합니다.

## 작업 단계

1. **대상 플랫폼의 매크로가 활성화되었는지 확인**. 컴포넌트는 `UNITY_WEBGL` 매크로가 정의되어 있을 때만 UnityWebRequest 경로를 사용하며, WebGL 플랫폼으로 전환(File → Build Settings → Switch Platform)하면 매크로가 자동으로 활성화됩니다.

   ```csharp
   using System;
   using System.Collections.Generic;
   using System.Text;
   using GameFrameX.Runtime;
   #if UNITY_WEBGL
   using UnityEngine.Networking;
   #endif
   ```

   출처: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L1-L7)

2. **플랫폼별 필요에 따라 타임아웃과 동시 연결 상한을 조정**. 생성 시 기본값은 `Timeout = 5`(초), `MaxConnectionPerServer = 8`이며, `Timeout`을 수정하면 `RequestTimeout`도 동기적으로 갱신됩니다.

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public WebProtoBuffManager()
   {
       MaxConnectionPerServer = 8;
       Timeout = 5f;
   }

   public float Timeout
   {
       get { return m_Timeout; }
       set
       {
           m_Timeout = value;
           RequestTimeout = TimeSpan.FromSeconds(value);
       }
   }

   public int MaxConnectionPerServer { get; set; }

   public TimeSpan RequestTimeout { get; set; }
   ```

   출처: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L27-L54)

3. **직접 `Post<T>`를 호출하여 요청을 전송**. 이것은 크로스 플랫폼 통합 진입점이며, 응답 본문은 메시지 Id로 타입을 검증한 후 `T`로 역직렬화됩니다.

   ```csharp
   public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
   {
       DebugSendLog(message);
       var webBufferResult = await PostInner(url, message);
       if (webBufferResult.IsNotNull())
       {
           var messageObjectHttp = SerializerHelper.Deserialize<MessageHttpObject>(webBufferResult.Result);
           if (messageObjectHttp.IsNotNull() && messageObjectHttp.Id != default)
           {
               var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
               if (messageType != typeof(T))
               {
                   Log.Error($"Response message type is invalid. Expected '{typeof(T).FullName}', actual '{messageType.FullName}'.");
                   return default;
               }

               var messageObject = SerializerHelper.Deserialize<T>(messageObjectHttp.Body);
               DebugReceiveLog(messageObject);
               return messageObject;
           }
       }

       return default;
   }
   ```

   출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L182-L205)

   사용자 지정 예제(식별자는 소스 코드와 동일하게 유지):

   ```csharp
   // message는 요청 메시지 객체입니다; LoginResponse : MessageObject, IResponseMessage
   var response = await webProtoBuffManager.Post<LoginResponse>(url, message);
   ```

4. **WebGL 차이에 대한 추가 처리가 불필요**. 요청이 큐에 들어간 후 `UpdateProtoBuf`가 매 프레임 동시 연결 상한 이내에서 디큐하여 `MakeProtoBufBytesRequest`를 호출하며, 이 메서드는 내부에서 플랫폼별로 컴파일됩니다:

   ```csharp
   void UpdateProtoBuf(float elapseSeconds, float realElapseSeconds)
   {
       lock (m_StringBuilder)
       {
           if (m_SendingProtoBufList.Count < MaxConnectionPerServer)
           {
               if (m_WaitingProtoBufQueue.Count > 0)
               {
                   var webProtoBufData = m_WaitingProtoBufQueue.Dequeue();

                   MakeProtoBufBytesRequest(webProtoBufData);

                   m_SendingProtoBufList.Add(webProtoBufData);
               }
           }
       }
   }
   ```

   출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L39-L55)

## 일반적인 변형

- **WebGL 플랫폼**: `UnityEngine.Networking.UnityWebRequest`를 사용하여 요청을 보내며, `Content-Type`은 `application/x-protobuf`, 타임아웃은 `RequestTimeout.TotalSeconds`(초) 값을 사용하고 `completed` 콜백으로 결과를 처리합니다; `timeout` 속성은 `int`이므로 잘림을 방지하려면 `Timeout`을 정수 초로 설정하는 것이 좋습니다.

  ```csharp
  #if UNITY_WEBGL
              UnityEngine.Networking.UnityWebRequest unityWebRequest;
              if (webData.IsGet)
              {
                  unityWebRequest = UnityEngine.Networking.UnityWebRequest.Get(webData.URL);
              }
              else
              {
                  unityWebRequest = UnityEngine.Networking.UnityWebRequest.Post(webData.URL, string.Empty);
              }

              unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;
              unityWebRequest.SetRequestHeader("Content-Type", ProtoBufContentType);
              byte[] postData = webData.SendData;
              unityWebRequest.uploadHandler = new UnityEngine.Networking.UploadHandlerRaw(postData);

              var asyncOperation = unityWebRequest.SendWebRequest();
              asyncOperation.completed += (asyncOperation2) =>
              {
                  try
                  {
                      m_SendingProtoBufList.Remove(webData);
                      if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)
                      {
                          webData.Task.TrySetException(new Exception(unityWebRequest.error));
                          return;
                      }

                      webData.Task.SetResult(new WebBufferResult(webData.UserData, unityWebRequest.downloadHandler.data));
                  }
                  finally
                  {
                      unityWebRequest.Dispose();
                      ReferencePool.Release(webData);
                  }
              };
  #else
  ```

  출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L83-L119)

- **비 WebGL 플랫폼**(에디터, 데스크톱, 모바일): `HttpWebRequest` 비동기 스트리밍 구현을 사용하며, 타임아웃 단위는 밀리초(`RequestTimeout.TotalMilliseconds`)이고, `WebExceptionStatus.Timeout`을 `TimeoutException`으로 변환하여 상위 계층에 던집니다:

  ```csharp
                  HttpWebRequest request = WebRequest.CreateHttp(webData.URL);
                  request.Method = webData.IsGet ? WebRequestMethods.Http.Get : WebRequestMethods.Http.Post;
                  request.Timeout = (int)RequestTimeout.TotalMilliseconds; // 요청 타임아웃 설정
                  request.ContentType = ProtoBufContentType;
  ```

  ```csharp
              catch (WebException e)
              {
                  // 타임아웃 예외 캡처
                  if (e.Status == WebExceptionStatus.Timeout)
                  {
                      webData.Task.SetException(new TimeoutException(e.Message));
                      return;
                  }

                  webData.Task.SetException(e);
              }
  ```

  출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L120-L155)

- **요청 본문 캡슐화**: 외부에서는 `MessageObject`만 전달하면 됩니다; `PostInner`가 자동으로 `MessageHttpObject`(Id, UniqueId, Body)로 한 겹 감싸고 이진 형식으로 직렬화한 후 큐에 넣습니다:

  ```csharp
           var id = ProtoMessageIdHandler.GetReqMessageIdByType(message.GetType());
           MessageHttpObject messageHttpObject = new MessageHttpObject
           {
               Id = id,
               UniqueId = message.UniqueId,
               Body = SerializerHelper.Serialize(message),
           };
           var sendData = SerializerHelper.Serialize(messageHttpObject);
           var webData = WebProtoBufData.Create(url, sendData, uniTaskCompletionSource, userData);
           m_WaitingProtoBufQueue.Enqueue(webData);
  ```

  출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L214-L229)

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Response message type is invalid. Expected '...', actual '...'` 로그 출력 및 `default` 반환 | 서버가 반환한 메시지 Id에 해당하는 응답 타입이 호출자가 전달한 `T`와 일치하지 않음 | `ProtoMessageIdHandler`에 등록된 요청/응답 매핑과 `Post<T>`의 제네릭 매개변수를 확인 |
| WebGL에서 요청이 무응답 | 대상 `Timeout`에 소수점이 포함되어 `(int)RequestTimeout.TotalSeconds`에 의해 지나치게 작은 값으로 잘림(예: `0.5` → `0`) | `Timeout`을 정수 초로 설정 |
| 요청이 계속 대기 상태로 중단됨 | 동시 연결 수가 `MaxConnectionPerServer`(기본값 8)에 도달하여 이후 요청이 `m_WaitingProtoBufQueue`에 머무름 | `MaxConnectionPerServer`를 높이거나 컴포넌트의 `Update`가 지속적으로 구동되도록 보장 |
| WebGL 콘솔에 `Unknown error` / CORS 관련 네트워크 오류 발생 | `unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null` 분기가 트리거되며, 예외 텍스트는 `unityWebRequest.error`임 | 서버의 CORS 설정과 URL 접근 가능성 확인 |
| 비 WebGL 플랫폼에서 `TimeoutException` 발생 | 서버가 `RequestTimeout`(밀리초 정밀도) 이내에 응답하지 않음 | `Timeout`을 늘리거나 서버 측 소요 시간 점검 |

## 검증

- WebGL과 에디터 두 플랫폼에서 각각 동일한 `Post<T>` 요청을 보내, 양쪽 모두 역직렬화된 `T` 인스턴스가 반환되고 `UniqueId`가 일치하는지 확인합니다.
- `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 매크로를 활성화하면 `接收消息 ID:[...] 消息内容:...` 디버그 로그를 확인할 수 있습니다(출처: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L231-L237)).
- 의도적으로 `T`를 잘못된 타입으로 바꾸어 `Response message type is invalid...` 오류가 발생하는지 확인하여 타입 검증이 작동함을 증명합니다.

## 배경

컴포넌트는 플랫폼별 조건부 컴파일로 이중 구현되어 있습니다: WebGL은 런타임 제한으로 인해 `HttpWebRequest`를 사용할 수 없어 `UnityWebRequest`의 `completed` 콜백 방식으로 통일되었으며, 나머지 플랫폼은 `Task` 기반의 스트리밍 `HttpWebRequest` 구현을 유지합니다. 두 방식 모두 결과를 동일한 `TaskCompletionSource<WebBufferResult>`에 기록하므로 상위 계층의 `Post<T>`는 차이를 인식하지 못합니다. URL 쿼리 매개변수, 재사용되는 `StringBuilder`와 동시 연결 상한은 [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs)에 정의되어 있습니다.
