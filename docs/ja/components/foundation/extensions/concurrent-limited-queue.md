# 並行制限付きキューの使用方法

`ConcurrentLimitedQueue<T>` はスレッドセーフな固定長キューです。要素数が容量上限に達した場合、指定された戦略に従って自動的に要素を破棄し、破棄時にコールバックを通じて呼び出し元に通知することができます。

## 前提条件

- `GameFrameX.Foundation.Extensions` 名前空間を導入。
- .NET 環境で使用可能（`System.Collections.Concurrent` に依存）。

## 操作手順

### 1. 指定した容量のキューを作成する

最大長さを渡し、デフォルトは `DropOldest` 戦略です（満杯時に最も古い要素を削除し、新しい要素を追加）。

```csharp
using GameFrameX.Foundation.Extensions;

var queue = new ConcurrentLimitedQueue<int>(limit: 3);
queue.Enqueue(1);
queue.Enqueue(2);
queue.Enqueue(3);
queue.Enqueue(4); // このとき 1 が自動的に削除され、キューには [2, 3, 4] が残る
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L91-L110)

### 2. オーバーフロー戦略を選択する

`LimitedQueueOverflowStrategy` を通じて、キューが満杯のときの振る舞いを選択します：

| 戦略 | 振る舞い |
|------|------|
| `DropOldest` | 最も古い要素を削除し、新しい要素を追加（デフォルト） |
| `DropNewest` | 新しい要素を破棄し、キューは変更されない |
| `RejectNewItem` | 新しい要素を拒否し、破棄通知を発生させない |
| `Throw` | `InvalidOperationException` をスロー |

```csharp
var queue = new ConcurrentLimitedQueue<string>(limit: 2, LimitedQueueOverflowStrategy.DropNewest);
queue.Enqueue("a");
queue.Enqueue("b");
queue.Enqueue("c"); // "c" は破棄され、キューは ["a", "b"] のまま
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L245-L266)

### 3. 破棄イベントを購読する

`ItemDiscarded` コールバックを通じて破棄された要素を監視し、メトリクス記録、ログ記録、または補償処理に使用できます。

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 2, LimitedQueueOverflowStrategy.DropOldest)
{
    ItemDiscarded = item =>
    {
        Console.WriteLine($"要素 {item.Item} を破棄しました、理由 {item.Reason}");
    }
};
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L138-L140)

### 4. 容量上限を調整する

`Limit` プロパティへの代入または `SetLimit` メソッドを通じて動的に容量を調整できます。縮小時に削除された要素は、`LimitReduced` を理由としてコールバックを通じて通知されます。

```csharp
var queue = new ConcurrentLimitedQueue<int>(limit: 5);
for (var i = 0; i < 5; i++) queue.Enqueue(i);

queue.SetLimit(2); // 余分な要素を削除し、コールバック内の Reason は LimitReduced になる
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L276-L296)

### 5. デキューと確認

標準的な並行キューのセマンティクスを使用：`TryDequeue` / `TryPeek` / `ToArray` / `Clear` のいずれも使用できます。

```csharp
if (queue.TryPeek(out var head))
{
    Console.WriteLine($"先頭: {head}");
}

if (queue.TryDequeue(out var first))
{
    Console.WriteLine($"デキュー: {first}");
}
```

Source: [ConcurrentLimitedQueue.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ConcurrentLimitedQueue.cs#L306-L328)

## 一般的なバリエーション

- **既存のコレクションから初期化**：`new ConcurrentLimitedQueue<int>(new List<int> { 1, 2, 3 })` または暗黙的な変換 `ConcurrentLimitedQueue<int> q = new List<int> { 1, 2, 3 };` で、容量は自動的にコレクションのサイズに設定されます。
- **`IProducerConsumerCollection<T>` として使用**：`TryAdd` / `TryTake` を直接呼び出すことができ、内部的には `TryEnqueue` / `TryDequeue` を使用します。
- **コールバック内で同じキューを操作しないようにする**：`ItemDiscarded` は内部ロック外で発生するため、コールバック内でのエンキュー/デキューは安全ですが、長時間のブロックは避けてください。

## よくあるエラー

| エラー | 説明 |
|------|------|
| `limit <= 0` で構築時に `ArgumentOutOfRangeException` をスロー | 容量は 0 より大きくなければならない |
| 空のコレクションを渡して構築すると `ArgumentOutOfRangeException` をスロー | コレクションの要素数は 0 より大きくなければならない |
| `OverflowStrategy.Throw` で満杯のキューにエンキューすると `InvalidOperationException("The limited queue has reached its capacity.")` をスロー | 呼び出し側は例外をキャッチするか、他の戦略を使用する必要がある |
| `DropOldest` が `ItemDiscarded` で発生することを期待していたが、`RejectNewItem` を使用していた | `RejectNewItem` は破棄通知を発生させない |

## 背景（オプション）

`ConcurrentLimitedQueue<T>` は内部的に `ConcurrentQueue<T>` をカプセル化し、独立した `_syncRoot` を使用して容量カウントとエンキューのオーバーフロー処理を保護しています。これにより、容量調整とエンキュー戦略の判定が同一のクリティカルセクション内でアトミックに完了します。基盤となる `ConcurrentQueue` 自身がスレッドセーフな要素アクセスを保証しています。
