# "Event manager is invalid." 致命的エラーの対処法

この `Log.Fatal("Event manager is invalid.")` は `EventComponent.Awake()` から出力されます。`GameFrameworkEntry.GetModule<IEventManager>()` が `null` を返した時点で出力され、その後コンポーネントはそのまま `return` するため、`m_EventManager` は空のままになり、以降のイベント購読/ディスパッチの呼び出しではすべて NullReferenceException がスローされます。根本的な原因は、**`IEventManager` の実装型がフレームワークから見つからず、登録されていない**ことです（実装型名の設定ミス、名称変更/名前空間の移動、またはコードストリッピングによる除去）。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| Play 開始/シーン起動時にすぐ `Fatal: Event manager is invalid.` が出力され、その後 `Subscribe`/`Fire` の呼び出しで `NullReferenceException` がスローされる | `GetModule<IEventManager>()` が null を返し、実装型が登録されていない | [修正手順 1](#1-eventcomponent-の実装型設定を確認する) を参照 |
| パッケージのバージョンアップや名前空間の変更後に発生し始める | `EventComponent` に保存された `componentType` 文字列が古い型名を指したままで、`Utility.Assembly.GetType(componentType)` で見つからない | Inspector で `EventManager` 実装を選択し直してシーンを保存する。[修正手順 1](#1-eventcomponent-の実装型設定を確認する) を参照 |
| エディターでは正常だが、ビルド（IL2CPP / マネージドストリッピング）後に発生する | 実装型 `EventManager` がストリッピングにより除去され、リフレクションで見つからない | `[Preserve]` 属性とストリッピング保護設定を維持する。[修正手順 2](#2-eventmanager-実装型がストリッピングされていないことを確認する) を参照 |
| コンポーネントが手作業で組み立てたプレハブや他のプロジェクトからコピーしたもの | プレハブの `componentType` シリアライズ値が空、または現在のプロジェクトに属していない | 削除して `GameFrameX/Event` メニューから追加し直す。[修正手順 3](#3-gameframex-event-コンポーネントを再作成する) を参照 |

エラーがスローされる箇所（実際のソースコード）：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

## 修正手順

### 1. EventComponent の実装型設定を確認する

`EventComponent` は `Awake()` 内でリフレクション `Utility.Assembly.GetType(componentType)` によって実装型を解決し、その後 `GameFrameworkEntry.GetModule<IEventManager>()` でモジュールを取得します。`componentType` は Inspector 上でシリアライズされて保存される文字列で、エディター側では `EventComponentInspector` が候補リストを設定します：

```csharp
[CustomEditor(typeof(EventComponent))]
internal sealed class EventComponentInspector : ComponentTypeComponentInspector
{
    // ...
    RefreshComponentTypeNames(typeof(IEventManager));
}
```

Source: [EventComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Editor/Inspector/EventComponentInspector.cs#L36-L63)

手順：

1. `EventComponent` がアタッチされた GameObject を選択します（デフォルトは GameFrameX のルートオブジェクトで、コンポーネントメニューは `GameFrameX/Event` です）。
2. Inspector のコンポーネントタイプのドロップダウンを確認し、`GameFrameX.Event.Runtime.EventManager`（本パッケージ内の唯一の実装）が選択されていることを確認します。
3. 空表示、または赤色/欠落（Missing）になっている場合は、`EventManager` を選択し直してシーンと関連プレハブを保存します。
4. 再度 Play モードに入って検証します。

### 2. EventManager 実装型がストリッピングされていないことを確認する

本パッケージの実装クラスには `[UnityEngine.Scripting.Preserve]` による保護も付与されています：

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class EventManager : GameFrameworkModule, IEventManager
{
    private readonly EventPool<GameEventArgs> m_EventPool;

    public EventManager()
    {
        m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L38-L49)

手順：

1. Player Settings で `Managed Stripping Level` を有効にしている、または IL2CPP を使用している場合は、パッケージ内の `Preserve` 属性が除去されていないことを確認してください（アセンブリのストリッピング免除設定を変更しないでください）。本パッケージでは、ストリッピング環境下での補助処理として [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs) も提供しています。
2. `Runtime` アセンブリ（`GameFrameX.Event.Runtime` 名前空間）が実際にビルドに含まれていることを確認してください（asmdef のプラットフォーム設定のチェック、Build から手動で除外されていないこと）。

### 3. GameFrameX/Event コンポーネントを再作成する

コンポーネントがコピーしたプレハブに由来し、シリアライズデータが無効になっている場合：

1. GameObject から現在の `EventComponent` を削除します（コンポーネントには `[DisallowMultipleComponent]` が付与されており、同一オブジェクトへの重複アタッチは不可です）。
2. `Add Component → GameFrameX → Event` から再度追加します。コンポーネントの定義は以下のとおりです：

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Event")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-7000)]
public sealed class EventComponent : GameFrameworkComponent
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)

3. `GameFrameworkEntry` が存在する GameFrameX の基礎ランタイムパッケージがインストールされ、参照されていることを確認します（`GetModule<T>` はそれに依存してモジュール登録スキャンを実行します）。
4. シーンを保存した後、再度 Play モードに入ります。

## 検証

- 起動時に Console に `Fatal: Event manager is invalid.` が表示されなくなります。
- 任意のスクリプトからイベントコンポーネントの読み取り専用プロパティにアクセスしても NullReferenceException がスローされなくなります。例：`EventCount` / `EventHandlerCount`（内部でそのまま `m_EventManager` に転送されます。詳細は [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L50-L61) を参照）。
- `Check(id, handler)` または `Subscribe(id, handler)` を一度呼び出し、正常に結果が返る/登録され、`Count(id)` のカウントが期待どおりであることを確認します。
