# 如何控制 JSON 輸出格式（美化/緊湊）

在 GameFrameX.LitJson 中，您可以透過 `JsonMapper.ToJson` 的 `prettyPrint` 參數在美化輸出與緊湊輸出之間切換。如果需要自訂縮排或實現更細粒度的控制，可以使用底層的 `JsonWriter`。

## 步驟

### 1. 產生美化格式的 JSON（含縮排與換行）

呼叫 `JsonMapper.ToJson` 時將 `prettyPrint` 設為 `true`：

```csharp
using GameFrameX.LitJSON.Runtime;

var player = new PlayerData { Id = 42, Name = "Blank", Hp = 100.5f };
string json = JsonMapper.ToJson(player, prettyPrint: true);
```

來源：[JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs#L1196-L1213)

輸出範例（4 空格縮排）：

```json
{
    "Id": 42,
    "Name": "Blank",
    "Hp": 100.5
}
```

### 2. 產生緊湊格式的 JSON（單行、無空白）

將 `prettyPrint` 設為 `false`（這也是 `ToJson` 方法的預設值）：

```csharp
string json = JsonMapper.ToJson(player, prettyPrint: false);
// 等同於：JsonMapper.ToJson(player)
```

輸出範例：

```json
{"Id":42,"Name":"Blank","Hp":100.5}
```

來源：[JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs#L1196-L1213)

### 3. 使用 JsonWriter 自訂縮排與格式

當預設縮排不符合您的需求時，可以直接使用 `JsonWriter` 來設定 `PrettyPrint` 與 `IndentValue`：

```csharp
using System.IO;
using System.Text;
using GameFrameX.LitJSON.Runtime;

var sb = new StringBuilder();
using var sw = new JsonWriter(new StringWriter(sb))
{
    PrettyPrint = true,    // 啟用美化輸出（自動換行 + 縮排）
    IndentValue = 2        // 每一層縮排 2 個空格
};

sw.WriteObjectStart();
sw.WritePropertyName("Id");   sw.Write(42);
sw.WritePropertyName("Name"); sw.Write("Blank");
sw.WriteObjectEnd();

string json = sb.ToString();
```

來源：[JsonWriter.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonWriter.cs#L80-L103)

`JsonWriter` 提供三種建構函式，以適用於不同的寫入目標：

| 建構函式 | 用途 |
|----------|------|
| `JsonWriter()` | 寫入內部的 `StringBuilder`；讀取 `TextWriter` 以取得結果 |
| `JsonWriter(StringBuilder sb)` | 直接寫入指定的 `StringBuilder` |
| `JsonWriter(TextWriter writer)` | 寫入任何 `TextWriter`（例如檔案串流、網路串流） |

來源：[JsonWriter.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonWriter.cs#L166-L198)

## 常見變化

| 情境 | 建議做法 |
|------|----------|
| 偵錯記錄、目視檢查 | `JsonMapper.ToJson(obj, prettyPrint: true)` |
| 網路傳輸、儲存至磁碟 | `JsonMapper.ToJson(obj)` 或 `prettyPrint: false`（節省頻寬/大小） |
| 自訂縮排寬度 | 使用 `JsonWriter` + `PrettyPrint=true` + `IndentValue=N` |
| 串流輸出至檔案/網路 | `new JsonWriter(TextWriter)`，搭配 `PrettyPrint` 控制格式 |

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 呼叫 `JsonMapper.ToJson(obj)` 後，輸出仍然是單行 | `prettyPrint` 的預設值為 `false`，即緊湊輸出 | 明確傳入 `prettyPrint: true` |
| 修改 `JsonWriter.IndentValue` 後沒有產生預期的縮排 | 未同時將 `PrettyPrint` 設為 `true`；未啟用美化輸出 | 先設定 `PrettyPrint = true`，再調整 `IndentValue` |
| `JsonWriter` 擲回「Invalid token」之類的例外 | 呼叫順序不正確（例如在 `WriteObjectStart` 之前呼叫 `WritePropertyName`） | 依照 `ObjectStart → PropertyName → value → ObjectEnd` 的順序成對呼叫 |

## 背景說明（選讀）

`ToJson` 內部會重複使用一個靜態的 `JsonWriter`（`static_writer`），並在呼叫前將 `pretty_print` 與 `indent_value` 重設為該方法的預設值，因此 `JsonMapper.ToJson(obj, true)` 只會影響本次呼叫的格式，不會污染後續的呼叫。`JsonWriter.IndentValue` 的 setter 也會按比例重新計算已累積的縮排（`indentation / indent_value * value`），因此中途切換縮排寬度不會破壞現有的輸出。
