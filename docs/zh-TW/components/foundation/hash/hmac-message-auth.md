# HMAC-SHA256/HMAC-SHA512 的使用方法

透過呼叫 `HmacSha256Helper` 或 `HmacSha512Helper` 的靜態方法，只需幾行程式碼即可取得金鑰訊息認證碼（Base64 字串），並可使用 `Verify` 系列方法以固定時間比較安全地驗證簽章。兩者皆提供字串、位元組陣列、串流（同步／非同步）三組多載。

## 前置條件

- 專案的目標框架需支援 `System.Security.Cryptography` 內的 `HMACSHA256` / `HMACSHA512`（.NET 6+ 建議使用 `HMACSHA256.HashData`）。
- 參考命名空間 `GameFrameX.Foundation.Hash`。
- 準備 UTF-8 編碼的金鑰字串（為配合 SHA-256 的區塊大小，建議長度 ≥ 32 位元組）。

## 操作步驟

### 1. 對字串計算 HMAC-SHA256

```csharp
using GameFrameX.Foundation.Hash;

string message = "hello world";
string key = "my-secret-key";
string signature = HmacSha256Helper.Hash(message, key);
// signature 是 Base64 字串，長度固定為 44 個字元（32 位元組）
```

來源：[HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L60-L66)

### 2. 對位元組陣列計算 HMAC-SHA512

```csharp
using System.Text;
using GameFrameX.Foundation.Hash;

byte[] message = Encoding.UTF8.GetBytes("payload");
byte[] key = Encoding.UTF8.GetBytes("another-secret-key");
string signature = HmacSha512Helper.Hash(message, key);
// signature 是 Base64 字串，長度固定為 88 個字元（64 位元組）
```

來源：[HmacSha512Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha512Helper.cs#L24-L29)

### 3. 對串流非同步計算 HMAC-SHA256

```csharp
using GameFrameX.Foundation.Hash;

using FileStream fs = File.OpenRead("data.bin");
byte[] key = Encoding.UTF8.GetBytes("my-secret-key");
string signature = await HmacSha256Helper.HashAsync(fs, key, cancellationToken);
```

來源：[HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L94-L103)

### 4. 使用固定時間比較驗證簽章

為防止時序攻擊，驗證時請務必使用 `Verify`，切勿使用 `==` 直接比較 Base64 字串。

```csharp
using GameFrameX.Foundation.Hash;

bool ok = HmacSha256Helper.Verify("hello world", "my-secret-key", signature);
```

來源：[HmacSha256Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/HmacSha256Helper.cs#L119-L125)

## 常見變化情境

| 情境 | 建議方法 |
|------|---------|
| 簡短訊息（JSON、URL 參數） | `Hash(string, string)` |
| 已知位元組緩衝區（如通訊協定封包） | `Hash(byte[], byte[])` |
| 大型檔案或網路串流 | `Hash(Stream, byte[])` 同步；非同步情境使用 `HashAsync` |
| API 簽章驗證 | 使用對應的 `Verify(...)` 系列，避免時序攻擊 |
| 需要更高安全性時 | 選擇 `HmacSha512Helper`，輸出為 64 位元組 |

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| `ArgumentNullException: message` | 傳入 `null` 字串 | 事先進行 null 檢查，或使用空字串作為佔位符 |
| 用戶端與伺服器簽章不一致 | 編碼不一致（其中一方使用 GBK/ASCII） | 全程統一使用 UTF-8 |
| `Verify` 一律回傳 `false` | 使用 `==` 直接比較 Base64 字串且長度存在差異 | 使用 `Verify(...)` 進行固定時間比較 |
| 效能瓶頸 | 對大型檔案重複將 `HMACSHA256` 實例化 | 重複使用金鑰，實例僅建立一次 |

## 補充（選用）

- 輸出一律為 Base64，適合在 HTTP 標頭、URL、JSON 中傳輸。如需十六進位，請先以 `Convert.FromBase64String` 解碼後再使用 `BitConverter`。
- `Verify` 內部使用 `HashHelper.FixedTimeEqualsBase64`，與直接比較字串相等性不同，可降低側通道攻擊的風險。
- `HashData` 是 .NET 6+ 的單次呼叫靜態 API。串流版本仍使用 `HMACSHA256/512` 實例，以支援 `ComputeHash(Stream)` 與 `ComputeHashAsync`。
