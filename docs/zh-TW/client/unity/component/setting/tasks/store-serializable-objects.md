# 可序列化物件設定的存取

使用 `SettingComponent` 的 `GetObject<T>` 與 `SetObject<T>` 介面，以單一字串鍵值將帶有 `[Serializable]` 標記的任意物件讀寫至遊戲設定儲存空間。

## 前置條件

- 專案中必須已附加 `GameFrameXSettingCroppingHelper` 與 `SettingComponent`(後者會透過 `[RequireComponent]` 自動要求前者)。
- 要儲存的型別必須標記 `[System.Serializable]`。欄位會由 `UnityEngine.JsonUtility` 進行序列化。
- 請以 `GameFrameworkEntry.GetModule<ISettingManager>()` 取得管理器實例，或在 `SettingComponent.Awake()` 完成後再呼叫儲存 API。

## 操作步驟

1. **定義可序列化的設定類別**。型別須加上 `[Serializable]`,欄位必須為 `public` 或帶有 `[SerializeField]`:

   ```csharp
   using System;
   using UnityEngine;

   [Serializable]
   public class PlayerProfile
   {
       public string playerId;
       public int level;
       public bool vip;
       public Vector3 lastPosition;
   }
   ```

2. **取得設定管理器**。元件初始化完成後，可直接從元件實例存取：

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingComponent = UnityEngine.Object.FindObjectOfType<SettingComponent>();
   ISettingManager settingManager = settingComponent.GetComponent<SettingComponent>() != null
       ? GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>()
       : null;
   ```

   也可以將元件的參照快取起來，並在需要時直接讀取 `settingComponent` 上的 `ISettingManager` 模組。

3. **寫入物件**。呼叫 `SetObject<T>(string settingName, T value)` 時，框架內部會以 `JsonUtility.ToJson` 轉換為字串，並寫入底層儲存空間：

   ```csharp
   var profile = new PlayerProfile
   {
       playerId = "p-1001",
       level = 12,
       vip = true,
       lastPosition = new Vector3(1.5f, 0f, -3.2f),
   };

   settingManager.SetObject("profile.current", profile);
   settingManager.Save();
   ```

   Source: [SettingManager.cs#L300-L320](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L300-L320)

4. **讀取物件**。使用 `GetObject<T>(string settingName)` 取得。若鍵值不存在則回傳 `null`(帶有預設值的多載 `GetObject<T>(string settingName, T defaultValue)` 會在鍵值缺少時回傳預設值)：

   ```csharp
   if (settingManager.HasSetting("profile.current"))
   {
       PlayerProfile loaded = settingManager.GetObject<PlayerProfile>("profile.current");
       Debug.Log($"おかえりなさい,{loaded.playerId},レベル {loaded.level}");
   }
   ```

5. **刪除與清除**。物件與基本型別共用相同的儲存空間：

   ```csharp
   settingManager.RemoveSetting("profile.current");  // 刪除單一鍵值
   settingManager.RemoveAllSettings();                // 清除全部
   ```

## 常見變化情境

| 情境 | 用法 | 說明 |
|------|------|------|
| 以預設值回退 | `GetObject<PlayerProfile>("profile.current", defaultProfile)` | 當鍵值不存在時，回傳傳入的預設值物件 |
| 列舉所有鍵值 | `string[] keys = settingManager.GetAllSettingNames();` | 除錯時可快速找出已儲存的物件名稱 |
| 跨小遊戲平台 | 使用 `WeChatMiniGameSettingStorage` 等平台實作 | 透過 `SettingStorageBackendFactory` 切換後端，API 保持一致 |
| 複雜巢狀結構 | `[Serializable] class Wrapper { public PlayerProfile profile; public Settings settings; }` | `JsonUtility` 支援巢狀的 `[Serializable]` 型別，但不支援字典/介面 |

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | 在 `SettingComponent.Awake()` 之前呼叫了 `GetObject`/`SetObject` | 等待元件初始化完成，或將讀寫邏輯放在業務模組的 `Start`/`Awake` 階段 |
| `GameFrameworkException: Setting name is invalid.` | 傳入的 `settingName` 為 `null` 或空字串 | 呼叫前先執行 `string.IsNullOrEmpty` 檢查 |
| 讀取出的欄位全部變成預設值 | 欄位為 `private` 且未加上 `[SerializeField]` | 在欄位加上 `[SerializeField]`,或改為 `public` |
| 字典/介面成員遺失 | `JsonUtility` 不支援 `Dictionary`、介面、屬性 | 使用 `List<T>` 或自訂的可序列化包裝類別 |
| 變更未儲存至磁碟 | 寫入後忘記呼叫 `Save()` | 寫入完成後呼叫 `settingManager.Save()`;框架會在 `Shutdown` 時自動 `Save` |

## 背景(選讀)

`SettingManager` 會將物件與基本型別統一對應到底層的 `ISettingHelper`,後者會先以 `JsonUtility.ToJson` 序列化為字串，再將持久化委派給 `ISettingStorageBackend`(預設為 `UnityPlayerPrefsSettingStorage`)。讀取時則以相反順序透過 `JsonUtility.FromJson<T>` 還原，因此僅能存取 `JsonUtility` 可處理的物件。關於底層儲存後端的切換，請參閱《自訂設定儲存後端》。
