# ホットアップデートが停止する、ダウンロードが失敗する、バージョンが一致しない場合の対処法

ホットアップデートフロー(YooAsset ベースの HostPlayMode)において「フローが特定状態で停止する」、「パッチダウンロードでエラーが発生する」、「クライアントバージョンとリモートマニフェストが一致しない」といった問題が発生した場合は、本ページの表と手順に従って原因を特定し、修正してください。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| フローが `UpdateStaticVersion` で停止する(リモート `PackageVersion` の取得に失敗) | `hostServerURL` にアクセスできない、またはリモートに `PackageVersion` ファイルが発行されていない | [修正手順 §1](#修正手順) を参照 |
| フローが `UpdateManifest` で停止する(マニフェスト取得に失敗) | `fallbackHostServerURL` が未設定、マニフェストパスが誤っている、または `AppVersion` がリモートと一致しない | [修正手順 §2](#修正手順) を参照 |
| `CreateDownloader` が空 / ダウンロード対象ファイルがない | ローカルキャッシュが現在の `PackageVersion` を既にカバーしている、または `AppVersion` 不一致でマニフェストにダウンロード対象がない | [修正手順 §3](#修正手順) を参照 |
| `DownloadWebFiles` が途中で失敗する、一部ファイルでエラー | 単一ファイルのダウンロード失敗。`FailedTryAgain` と `VerifyLevel` の影響を受ける | [修正手順 §4](#修正手順) を参照 |
| 起動時に「リモートバージョンとローカルに互換性なし」エラー | クライアント `AppVersion` < リモートの最低サポートバージョン | [修正手順 §5](#修正手順) を参照 |

`EPatchStates` 列挙型の定義は以下の通りで、ログとの照合に使用します。

Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L32)

```csharp
public enum EPatchStates
{
    UpdateStaticVersion,
    UpdateManifest,
    CreateDownloader,
    DownloadWebFiles,
    PatchDone,
}
```

## 修正手順

### §1 UpdateStaticVersion で停止する

1. 渡された `hostServerURL` を確認し、ブラウザで直接開いてテキスト `PackageVersion` が返されることを確認する(YooAsset のデフォルト構成)。
2. ビルドマシンが当該リソースパッケージを発行済みであることを確認する。リモートディレクトリには少なくとも `PackageVersion.txt` / `GameVersion.txt` が含まれている必要がある。
3. CDN を有効化している場合は、CDN のオリジン戻り先が実際のリソースサーバーを指していることを確認する。

### §2 UpdateManifest で停止する

1. `fallbackHostServerURL`(予備アドレス)を必ず同時に指定する。`HostPlayMode` の初期化時に `RemoteServices` を通じて両方を YooAsset に渡している。

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L148-L164)

```csharp
private InitializationOperation InitializeYooAssetHostPlayMode(
    ResourcePackage resourcePackage,
    string hostServerURL,
    string fallbackHostServerURL)
{
    var remoteServices = new RemoteServices(hostServerURL, fallbackHostServerURL);
    var createParameters = new HostPlayModeParameters
    {
        BuildinFileSystemParameters = FileSystemParameters.CreateDefaultBuildinFileSystemParameters(),
        CacheFileSystemParameters   = FileSystemParameters.CreateDefaultCacheFileSystemParameters(remoteServices),
    };
    return resourcePackage.InitializeAsync(createParameters);
}
```

2. クライアントの `AppVersion` がリモートの `GameVersion.txt` よりも高くないことを確認する(YooAsset は AppVersion でマニフェストをフィルタリングする)。
3. ログ内の YooAsset が返すマニフェスト URL を確認し、ブラウザで手動で開いて `PackageManifest_{AppVersion}_{PackageVersion}.hash` と `.bytes` がダウンロードできることを確認する。

### §3 CreateDownloader が空

1. キャッシュをクリアした直後や初回インストールの場合、これは想定動作であるためダウンロードをスキップしてゲームに直接進入すればよい。
2. 空になるべきでない場合(実際に新規リソースがある場合)、通常は `AppVersion` の選択誤りによりマニフェスト内容が誤っているため、§2 に戻ってバージョン番号を確認する。

### §4 DownloadWebFiles が失敗する

`IAssetManager` の以下の 2 つのパラメータでダウンロード動作を調整できる。

Source: [IAssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L13-L41)

```csharp
/// 同時ダウンロードの最大数。
int DownloadingMaxNum { get; set; }

/// 失敗リトライの最大回数。
int FailedTryAgain { get; set; }

/// ダウンロードファイルの検証レベルを取得または設定する。
EFileVerifyLevel VerifyLevel { get; }
```

1. `DownloadingMaxNum` を適切に増やす(デフォルトは小さめの値であり、高帯域幅環境では 10〜20 に設定可能)。
2. `FailedTryAgain` を適切に増やし、ネットワークの瞬間的な揺らぎで即座に失敗と判定されないようにする。
3. CDN ファイルが大量に 404 になる場合は、まずビルド成果物ディレクトリでファイル名を照合する。YooAsset のリモート構成はビルド時と一致している必要がある。
4. ファイルが改ざんや破損の疑いがある場合は、`VerifyLevel` をより高いレベルに引き上げる(`EFileVerifyLevel` 列挙型によって決定される)。YooAsset はファイルハッシュを検証する。

### §5 リモートバージョンとローカルが非互換

YooAsset は `UpdateManifest` 段階で `AppVersion` を検証し、リモート要件未満のバージョンは拒否される。対処方法は以下の通り。

1. クライアントの `Player Settings.bundleVersion`、または `InitPackageAsync` 呼び出し時に渡すバージョン番号を `>=` リモート `GameVersion.txt` に引き上げる。
2. パッケージを再ビルドしてリリースする。旧クライアントで回避しようとしないこと。

## 検証

1. 進捗コールバックが `UpdateStaticVersion → UpdateManifest → CreateDownloader → DownloadWebFiles → PatchDone` をスキップや停止なく完全に経過することを確認する。
2. YooAsset キャッシュディレクトリ(例: `Application.persistentDataPath/yooasset/{packageName}/`)内に、当該バージョンに対応する `.bytes` / `.hash` のキャッシュファイルが生成されていることを確認する。
3. ゲーム進入後、すべてのホットアップデートリソースが正常に読み込まれ、内蔵パッケージへフォールバックしないことを確認する。
