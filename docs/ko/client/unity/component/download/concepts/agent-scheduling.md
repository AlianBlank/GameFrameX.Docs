# 멀티 에이전트 스케줄링 및 태스크 라이프사이클

다운로드 관리자는 `TaskPool<DownloadTask>`를 통해 여러 다운로드 에이전트(`DownloadAgent`)를 동시에 관리하며, 제출된 모든 태스크는 우선순위에 따라 대기열에 들어가고, 유휴 상태의 에이전트가 가져가며, 통합된 폴링 루프에서 진행됩니다. 이 페이지에서는 에이전트가 어떻게 생성되고 스케줄되는지, 그리고 태스크가 라이프사이클 동안 거치는 각 상태와 이벤트를 설명합니다.

## 빠른 시작

1. 컴포넌트 시작 시 `DownloadComponent`를 통해 여러 다운로드 에이전트 헬퍼를 등록합니다(각 헬퍼는 하나의 독립적인 에이전트에 대응하며, 병렬 다운로드가 가능합니다):

```csharp
// AddDownloadAgentHelper는 new DownloadAgent(helper)를 수행하고 m_TaskPool.AddAgent(agent)를 호출합니다
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
downloadComponent.AddDownloadAgentHelper(new UnityWebRequestDownloadAgentHelper());
```

소스: [DownloadManager.cs#L204-L213](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L204-L213)

2. `AddDownload(...)`를 호출하여 태스크를 제출하면, 태스크는 `TaskPool`의 대기열에 들어가 유휴 에이전트가 가져가기를 기다립니다:

```csharp
int serialId = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/pkg.zip",
    downloadUri:  "https://example.com/pkg.zip",
    tag:         "asset",
    priority:    0);
```

소스: [DownloadManager.cs#L269-L296](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L269-L296)

3. 프레임워크 모듈은 매 프레임 `DownloadManager.Update`를 호출하며, 내부적으로 업데이트를 태스크 풀에 전달합니다. 에이전트가 태스크를 가져간 후 `IDownloadAgentHelper.Download`를 호출하여 전송을 시작하고, 진행 과정에서 `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` 이벤트를 트리거합니다.

```csharp
// DownloadManager.Update -> m_TaskPool.Update(elapseSeconds, realElapseSeconds)
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_TaskPool.Update(elapseSeconds, realElapseSeconds);
    m_DownloadCounter.Update(elapseSeconds, realElapseSeconds);
}
```

소스: [DownloadManager.cs#L185-L189](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L185-L189)

## 에이전트 스케줄링

다운로드 관리자는 `AddDownloadAgentHelper` 시 각 헬퍼마다 독립적인 `DownloadAgent`를 생성하고, `TaskPool<DownloadTask>.AddAgent`를 통해 등록합니다. `TaskPool`은 에이전트 집합과 대기열을 관리하며, 유휴 상태인 에이전트에만 태스크를 할당합니다.

에이전트 집합의 주요 통계량과 대기열 상태는 모두 `DownloadManager`를 통해 노출되며, UI나 디버그 패널에서 직접 읽을 수 있습니다:

| 이름 | 소스 속성 | 의미 |
|------|----------|------|
| 총 에이전트 수 | `TotalAgentCount` | 등록된 다운로드 에이전트 총 수 |
| 유휴 에이전트 수 | `FreeAgentCount` | 현재 태스크를 담당하지 않은 에이전트 수 |
| 작업 중 에이전트 수 | `WorkingAgentCount` | 다운로드 진행 중인 에이전트 수 |
| 대기 태스크 수 | `WaitingTaskCount` | 대기열에 들어갔지만 아직 가져가지지 않은 태스크 수 |
| 현재 속도 | `CurrentSpeed` | `DownloadCounter`가 계산한 순간 속도(MB/s) |
| 일시정지 플래그 | `Paused` | 일시정지 시 에이전트가 새 태스크를 가져가는 것이 중단됩니다 |

소스: [DownloadManager.cs#L86-L142](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L86-L142)

스케줄링 흐름 개요:

1. 에이전트 등록: `AddDownloadAgentHelper` → `new DownloadAgent(helper)` → `m_TaskPool.AddAgent(agent)`.
2. 태스크 제출: `AddDownload` → `DownloadTask.Create` 구성 → 태스크 풀 대기열에 기록.
3. 태스크 가져오기: 매 프레임 `TaskPool.Update`가 대기열에서 우선순위가 가장 높은 태스크를 유휴 에이전트에 전달하고, 에이전트는 이후 `IDownloadAgentHelper.Download(downloadUri, userData)`를 호출합니다.
4. 에이전트 해제: 에이전트가 완료(성공 또는 실패)되면 자체적으로 유휴 상태로 표시되며, 태스크 풀은 다음 라운드에서 다른 대기 태스크를 계속 배분할 수 있습니다.

> `TaskPool<T>` 내부의 우선순위 비교 및 대기열 구현에 대해서는 GameFrameX 런타임 소스 코드를 참조하십시오. 본 컴포넌트는 `DownloadTask`와 `DownloadAgent` 구현만 제공합니다.

## 태스크 라이프사이클

각 다운로드 태스크는 `DownloadManager.DownloadTask`이며, `TaskBase`를 상속하고, `ReferencePool.Acquire<DownloadTask>()`를 통해 생성되며, `Clear()` 시 객체 풀에 반환됩니다. 태스크에는 다음 상태가 있습니다:

| 상태 열거형 값 | 값 | 설명 |
|------------|------|------|
| `DownloadTaskStatus.Todo` | 0 | 대기열에 들어가 에이전트가 가져가기를 기다리는 상태 |
| `DownloadTaskStatus.Doing` | 1 | 에이전트가 가져가어 전송 중 |
| `DownloadTaskStatus.Done` | 2 | 다운로드 완료, 파일 디스크 기록 |
| `DownloadTaskStatus.Error` | 3 | 다운로드 실패(타임아웃, 네트워크 오류 등) |

소스: [DownloadManager.DownloadTaskStatus.cs#L39-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTaskStatus.cs#L39-L60)

`DownloadTask`가 가진 주요 필드:

| 필드 | 타입 | 의미 |
|------|------|------|
| `SerialId` | `int` | `s_Serial` 자동 증가로 할당되며, 매 `Create` 시 `++s_Serial` 실행 |
| `DownloadPath` | `string` | 다운로드 완료 후 파일 저장 경로 |
| `DownloadUri` | `string` | 원본 다운로드 주소 |
| `FlushSize` | `int` | 버퍼를 디스크에 기록하는 임계 크기(관리자 기본값으로 덮어씀) |
| `Timeout` | `float` | 다운로드 타임아웃 초 단위(관리자 기본값으로 덮어씀) |
| `Priority` | `int` | 태스크 우선순위, 값이 클수록 앞에 배치됨 |
| `Tag` | `string` | 태스크 태그, 태그별로 `TaskInfo` 일괄 조회 가능 |
| `UserData` | `object` | `IDownloadAgentHelper.Download`에 전달되는 사용자 정의 데이터 |

소스: [DownloadManager.DownloadTask.cs#L39-L130](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs#L39-L130)

### 라이프사이클 단계

1. **대기열 진입**: `AddDownload` 오버로드를 호출하여 전체 매개변수 버전으로 진입하면, `DownloadTask.Create(downloadPath, downloadUri, tag, priority, flushSize, timeout, userData)`로 태스크가 생성되고, 초기 상태는 `Todo`이며 즉시 `TaskPool`의 대기열에 들어갑니다.
2. **배분**: `TaskPool.Update`가 태스크를 유휴 `DownloadAgent`에 전달하면, 에이전트는 `OnDownloadAgentStart` 콜백에서 태스크 상태를 `Doing`으로 전환하고 로컬 `FileStream`을 엽니다.
3. **진행 중**: 에이전트는 `IDownloadAgentHelper`의 `DownloadAgentHelperUpdateBytesEventArgs` / `UpdateLength`를 지속적으로 수신하여 `m_DownloadedLength`와 `m_SavedLength`를 누적하고, `m_WaitFlushSize`가 `FlushSize`에 도달하면 디스크에 기록하며, 동시에 주기적으로 `m_WaitTime`을 갱신하여 타임아웃 판정에 사용합니다.
4. **완료 / 실패**: 성공 시 `DownloadAgentSuccess`가 트리거되고, 실패(타임아웃 포함) 시 `DownloadAgentFailure`가 트리거됩니다. 에이전트는 스트림을 닫고 상태를 정리하며, 태스크 상태는 `Done` 또는 `Error`로 설정되고 `TaskPool`이 자동으로 객체 풀에 반환하기를 기다립니다.
5. **리소스 회수**: `Clear()`가 태스크 필드를 `Todo`/빈 값으로 재설정한 후 `ReferencePool.Release`에 의해 풀로 반환되어 다음 `Create`에서 재사용되기를 기다립니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 모든 태스크가 계속 `WaitingTaskCount > 0`, `WorkingAgentCount = 0` 상태에 머무름 | `AddDownloadAgentHelper`를 호출하지 않아 태스크 풀에 에이전트가 없음 | 컴포넌트 시작 단계에서 필요에 따라 최소 하나의 `IDownloadAgentHelper`(UnityWebRequest / WWW 구현)를 추가 |
| 컴포넌트 시작 시 즉시 `Download agent helper is invalid.` 발생 | `null`을 전달했거나 객체가 조기에 해제됨 | 유효한 인스턴스를 전달하고, 외부에서 조기에 `Dispose`되지 않도록 보장 |
| 태스크가 오랫동안 `Doing` 상태에 있다가 실패로 표시됨 | `Timeout`이 너무 짧게 설정되었거나, 약한 네트워크 환경에서 `FlushSize`가 너무 커서 버퍼가 디스크에 기록되지 않음 | `DownloadManager.Timeout` / `DownloadManager.FlushSize`로 조정하거나, `AddDownload` 오버로드를 사용하여 태스크별로 덮어씀 |
| 여러 헬퍼를 등록했지만 동시성이 여전히 1 | 동일한 헬퍼 인스턴스를 중복 등록하여 에이전트가 기본 연결을 공유함 | 각 `UnityWebRequestDownloadAgentHelper`/`WWWDownloadAgentHelper` 인스턴스당 `AddDownloadAgentHelper`를 한 번만 호출 |

## 배경(선택 사항)

다운로드 관리자는 `GameFrameworkModule`(`Priority = 5`)이며, `Update`에서 스케줄링 권한을 완전히 `TaskPool<DownloadTask>`에 위임합니다. 본 클래스는 다음만 담당합니다:

- 다운로드 에이전트 목록 유지(`AddDownloadAgentHelper`를 통해 주입).
- 매 `AddDownload`를 `DownloadTask.Create(...)`로 변환하여 태스크 풀에 전달.
- 에이전트의 네 가지 이벤트(`Start/Update/Success/Failure`)를 수신하고 통합된 이벤트 콜백으로 외부에 노출.
- `DownloadCounter`를 활용하여 모든 에이전트의 바이트 증가분을 통합된 순간 다운로드 속도로 환산.

태스크 객체(`DownloadTask`) 자체는 `ReferencePool`에서 관리되며, 에이전트(`DownloadAgent`)는 `ITaskAgent<DownloadTask>`와 `IDisposable`을 구현합니다. 이 두 추상화는 `TaskPool`과의 연결 계약이자, GameFrameX 런타임 태스크 스케줄링 하위 시스템과 일치하는 부분입니다.
