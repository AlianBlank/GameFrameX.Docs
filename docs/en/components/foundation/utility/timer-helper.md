# How to Use TimerHelper to Handle Time Zones/Timestamps

`TimerHelper` is a static time utility class that provides time retrieval based on UTC or the currently configured time zone, as well as Unix timestamp conversion and elapsed time calculation. The default time zone is UTC, and you can switch to any system time zone via `SetTimeZone`.

## Prerequisites

- The `GameFrameX.Foundation.Utility` namespace has been referenced.
- When specifying an IANA time zone ID on Linux/macOS, verify that the ID is registered in the current runtime (Windows uses names such as "China Standard Time").

```csharp
using GameFrameX.Foundation.Utility;
```

## Steps

### 1. Select and Set the Time Zone

The default time zone of `TimerHelper` is `TimeZoneInfo.Utc`. The naming conventions are as follows:

| Suffix | Meaning |
|--------|---------|
| No suffix | Base method, usually returns UTC time |
| `WithUtc` | Calculated based on UTC time |
| `WithTimeZone` | Calculated based on `CurrentTimeZone` |
| `WithTimeZoneOffset` | UTC timestamp + time zone offset |

Switch the time zone via `SetTimeZone`. Passing `null` or an invalid ID falls back to UTC.

```csharp
// Using a TimeZoneInfo object
TimerHelper.SetTimeZone(TimeZoneInfo.FindSystemTimeZoneById("Asia/Shanghai"));

// Using a time zone ID string (automatically falls back to UTC on failure)
bool ok = TimerHelper.SetTimeZone("China Standard Time");
if (!ok) { /* Fallback to UTC */ }
```

### 2. Get the Current Time (DateTime)

```csharp
DateTime utcNow = TimerHelper.GetNowWithUtc();
DateTime localNow = TimerHelper.GetNowWithTimeZone();   // Already converted to the current time zone
Console.WriteLine($"UTC: {utcNow:o}");
Console.WriteLine($"Local(TZ): {localNow:o}");
```

### 3. Get and Generate Unix Timestamps

| Method | Returns | Description |
|--------|---------|-------------|
| `UnixTimeSeconds()` | `long` | UTC timestamp in seconds |
| `UnixTimeMilliseconds()` | `long` | UTC timestamp in milliseconds |
| `UnixTimeSecondsWithTimeZoneOffset()` | `long` | Standard UTC timestamp + current time zone offset + `TimeOffsetSeconds` |
| `UnixTimeMillisecondsWithTimeZoneOffset()` | `long` | Standard UTC timestamp + current time zone offset + `TimeOffsetMilliseconds` |
| `DateTimeToSecondsWithTimeZone(DateTime)` | `long` | Treats any `DateTime` as current time zone time and generates a second-level timestamp |
| `DateTimeToMillisecondsWithTimeZone(DateTime)` | `long` | Same as above, in milliseconds |

```csharp
long sec  = TimerHelper.UnixTimeSeconds();
long msec = TimerHelper.UnixTimeMilliseconds();

// With offset: under UTC+8, this will be 28800 seconds larger than the standard UTC timestamp
long secOffset  = TimerHelper.UnixTimeSecondsWithTimeZoneOffset();
long msecOffset = TimerHelper.UnixTimeMillisecondsWithTimeZoneOffset();

// DateTime -> timestamp (Unspecified is interpreted as CurrentTimeZone by default)
DateTime t = new DateTime(2024, 1, 1, 0, 0, 0, DateTimeKind.Unspecified);
long tsZ = TimerHelper.DateTimeToSecondsWithTimeZone(t);
```

## Common Variants

- **Cross-platform time zone IDs**: Use "China Standard Time" on Windows, and "Asia/Shanghai" on Linux/macOS. `SetTimeZone(string)` catches exceptions and returns `false` when the ID is invalid.
- **Epoch constants**: `EpochUtc = 1970-01-01T00:00:00Z (Utc)`, `EpochLocal = 1970-01-01T00:00:00 (Local)`. `EpochLocal` always uses the system local time zone and does not change with `CurrentTimeZone`.

## Common Errors

| Error | Cause | How to Avoid |
|-------|-------|--------------|
| `SetTimeZone("Asia/Shanghai")` returns `false` on Windows | Linux/macOS uses IANA IDs, while Windows uses Microsoft time zone names | Use `TimeZoneInfo.FindSystemTimeZoneById` to check at the OS level, or call `SetTimeZone(TimeZoneInfo)` to pass it in explicitly |
| The "time zone" time obtained by passing in a `DateTime` with `Kind=Unspecified` is incorrect | `ConvertToUtc` treats `Unspecified` as `CurrentTimeZone` time | Explicitly set `DateTimeKind.Utc` or `DateTimeKind.Local` before passing it in |
| `CurrentTimeZone` reads inconsistent values under multithreading | The static field is written with `volatile`, which does not guarantee atomicity of compound operations | Sufficient for read-only configuration scenarios; add your own locking if switching frequently at runtime |
