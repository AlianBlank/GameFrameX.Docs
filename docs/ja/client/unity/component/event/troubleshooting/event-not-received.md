# イベントが受信されない・発火しない場合の対処法

イベントを購読しているのにコールバックが受信されない場合、その原因は通常、**購読側と発行側のイベント id の不一致**、**Fire の「次フレーム配信」というセマンティクスの誤解**、または**シーンに `EventComponent` がないこと**です。以下の診断表で該当する項目を確認し、対応する修正手順に進めば原因を特定できます。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| コールバックが一切実行されない | 購読した `id` と `Fire` に渡されたイベント番号が同じ文字列ではない（スペル、大文字・小文字、片方は `typeof(X).FullName` を使いもう片方は手書きリテラル） | 定数または `typeof(X).FullName` に統一する。[修正手順 1](#1-イベント-id-が完全に一致するか確認) を参照 |
| コールバックが一切実行されないが、id は一致している | 購読が `Fire` の後に行われたため、`EventPoolMode.AllowNoHandler` ではイベントがサイレントに破棄される | 先に `Subscribe` してから `Fire` する。[修正手順 2](#2-先に購読してから発行し購読の成否を自己チェックする) を参照 |
| イベントが Fire したフレームでは受信されず、次フレームに届く | `Fire` はスレッドセーフだが、次フレームまで配信が遅延される。設計上の動作 | 即時コールバックが必要な場合は `FireNow` を使う。[修正手順 3](#3-fire-の次フレーム配信セマンティクスを理解する) を参照 |
| まれにイベントが失われる | イベント発行後に同フレームでオブジェクトを破棄 / ゲームの一時停止により `EventManager.Update` が再実行されず、キュー内のイベントが配信されない | 発行直後に購読者を破棄しない。または `FireNow` を使う |
| コンソールに `Event manager is invalid.` と出力され、すべてのイベントが無効になる | シーンに `EventComponent` がなく、`Awake` で `IEventManager` モジュールを取得できない | シーンに GameFrameX/Event コンポーネントを追加する。[修正手順 4](#4-シーンに-eventcomponent-が存在するか確認) を参照 |
| `Fire(sender, "")` を呼び出したり null のイベント番号を渡したりすると直接例外がスローされる | `GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId))` のパラメーター検証 | 空でないイベント番号文字列を渡す |
| 購読者のいないイベントをログに出力して調査したい | デフォルトハンドラーが未設定 | `SetDefaultHandler` を呼び出してフォールバックさせる。[修正手順 5](#5-デフォルトハンドラーによるフォールバックで購読者のいないイベントを調査) を参照 |
| 購読解除時に handler が存在しないというエラーが出る | `Unsubscribe` に未購読の handler を渡した | `CheckUnsubscribe` を使う |

## 修正手順

### 1. イベント id が完全に一致するか確認

`Subscribe` と `Fire` のマッチングの唯一の根拠は `string` 型のイベント番号です。両側が一致しない場合、イベントプールはエラーを報告しません（`EventManager` は `EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler` モードで作成されます）。イベントはサイレントに破棄されます：

```csharp
m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L46-L49)

推奨される方法：イベント番号を単一の定数または `typeof(X).FullName` に集約し、購読側と発行側が同じソースを参照するようにします。引数なしのイベントを使用する場合、`Fire(sender, eventId)` は内部で `EmptyEventArgs` を作成し、その番号を書き込みます：

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L157-L161)

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L33-L38)

なお、`EmptyEventArgs` はリサイクル時に番号が `typeof(EmptyEventArgs).FullName` にリセットされるため、配信後もイベント引数オブジェクトがカスタム番号を保持していることに依存しないでください。

### 2. 先に購読してから発行し、購読の成否を自己チェックする

イベントは必ず購読してから発行する必要があります。購読の経路に問題があると疑われる場合は、`Count(id)` / `Check(id, handler)` でイベントプールの現在の状態を直接確認できます：

```csharp
public int Count(string id)
{
    return m_EventManager.Count(id);
}

public bool Check(string id, EventHandler<GameEventArgs> handler)
{
    return m_EventManager.Check(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L98)

初期化を繰り返すと、同一の handler が複数回購読されやすくなります（`AllowMultiHandler` は重複購読を許可するため、コールバックが重複して呼び出されます）。フレームワークには重複防止版が用意されています：

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

対称に、存在しない handler を購読解除する場合は `CheckUnsubscribe` を使います。handler が存在しない場合はそのままスキップされます：

```csharp
public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L128-L131)

### 3. Fire の「次フレーム」配信セマンティクスを理解する

`Fire` はスレッドセーフですが、イベントはキューに入った後、`EventManager.Update` によって次フレームで配信されます。`FireNow` は即時に配信しますが、スレッドセーフではありません：

```csharp
/// イベントを発行します。この操作はスレッドセーフで、メインスレッド以外から発行した場合でもイベント処理関数はメインスレッドでコールバックされることが保証されますが、イベントは発行後の次フレームに配信されます。
public void Fire(object sender, GameEventArgs e)
{
    m_EventPool.Fire(sender, e);
}

/// イベントを即時発行するモードです。この操作はスレッドセーフではなく、イベントは直ちに配信されます。
public void FireNow(object sender, GameEventArgs e)
{
    m_EventPool.FireNow(sender, e);
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L158-L175)

キュー内のイベントは、毎フレームのポーリングによって消費されます：

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    m_EventPool.Update(elapseSeconds, realElapseSeconds);
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L81-L84)

ここから、次の 2 つの調査ポイントが導かれます：
1. `Fire` の後、同じフレーム内でコールバックが実行済みと断定すると失敗します――次フレームを待つか、`FireNow` を使ってください。
2. イベント発行の直後に購読オブジェクトを破棄した場合、またはゲームの一時停止により `Update` が停止した場合、キュー内のイベントが配信されないままになる可能性があります。

### 4. シーンに EventComponent が存在するか確認

`EventComponent` は `Awake` 内で `GameFrameworkEntry.GetModule<IEventManager>()` によってモジュールを取得します。失敗すると `Log.Fatal` を出力して即座に返り、以降すべてのイベント API が使用できなくなります：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

修正：シーンに `GameFrameX/Event` コンポーネントを追加し（`[AddComponentMenu("GameFrameX/Event")]`）、初期化順序がモジュールの優先度を満たしていることを確認してください（`EventManager.Priority` は 7 です）。

### 5. デフォルトハンドラーによるフォールバックで購読者のいないイベントを調査

デフォルトハンドラーを設定すると、購読者のいないすべてのイベントがこのコールバックに到達します。調査段階で「イベントが発行されたのに誰も処理していない」ことをログ出力するのに適しています：

```csharp
public void SetDefaultHandler(EventHandler<GameEventArgs> handler)
{
    m_EventManager.SetDefaultHandler(handler);
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L137-L140)

## 検証

1. ログを出力するだけの handler を購読し、`Count(eventId)` を記録します。期待される戻り値は ≥ 1 です。
2. `Fire(sender, eventId)` の後、次フレームまで待つ（または直接 `FireNow` を使う）して、ログ出力を確認します。
3. `Check(eventId, handler)` は `true` を返すはずです。`CheckUnsubscribe` を実行した後は `Count(eventId)` が 0 に戻り、再度 `Fire` するとイベントはデフォルトハンドラーに入ります（設定している場合）。
4. エディターで `EventComponent` をアタッチしたオブジェクトを選択すると、Inspector でイベント数とハンドラー数を確認できます（`EventHandlerCount` / `EventCount`）。
