# 請求失敟或逾時時的應對方法

當請求失敗或發生逾時時，`WebManager` 會將例外重新拋回至 `await` 呼叫處：逾時以 `TimeoutException` 呈現，其餘則以 `WebException` 或 `IOException` 呈現。最常見的原因是逾時時間過短（預設僅 5 秒）、並行請求數超過上限而在佇列中等待，以及伺服器/網路本身的問題。

## 快速診斷

| 症狀（例外/現象） | 原因 | 解決方法 |
|------|------|------|
| `TimeoutException`，訊息源自 `WebException` | 請求耗時超過 `Timeout`（預設 5 秒） | [調大逾時時間](#1-调大超时时间) |
| 請求遲遲未送出，整體變慢 | 並行中的請求數超過 `MaxConnectionPerServer`（預設 8），超出的請求在 `m_WaitingNormalQueue` 中等待 | [提高並行連線上限](#2-提高并发上限) |
| `WebException`（Status 不為 Timeout） | HTTP 協定錯誤（404/500）、DNS 解析失敗、連線被拒 | 檢查 URL 與伺服器狀態，並開啟日誌確認回應 |
| `IOException` | 讀取回應資料流時連線中斷（網路不穩、伺服器提前終止連線） | 檢查網路後重試 |
| 主控台看不到請求/回應內容 | 未啟用日誌編譯巨集 | [開啟收發日誌](#3-开启收发日志定位问题) |
| 發生 HTTPS 憑證錯誤 | 憑證驗證失敗 | WebGL/`UnityWebRequest` 路徑已透過 `DefaultBypassCertificate` 略過；非 WebGL 平台請檢查系統時間與憑證鏈 |

## 解決步驟

### 1. 調大逾時時間

`WebManager` 建構時的預設值為 `Timeout = 5f`（秒），並行連線上限預設為 8。若所使用介面的回應較慢（例如：上傳大型檔案、網路環境不佳），請先調大逾時時間：

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// 取得或設定以秒為單位的逾時時間
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}
```

來源：[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L43-L60)

在自己的程式碼中設定（兩種方式等效，`Timeout` 會同步更新 `RequestTimeout`）：

```csharp
webManager.Timeout = 30f;
// 或
webManager.RequestTimeout = TimeSpan.FromSeconds(60);
```

來源：[README.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L236-L237)

設定後會套用至底層的兩條請求路徑：WebGL 使用 `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds`（[WebManager.cs L218](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L218)、[WebManager.Binary.cs L97](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L97)），非 WebGL 則使用 `request.Timeout = (int)RequestTimeout.TotalMilliseconds`（[WebManager.cs L259](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L259)、[WebManager.Binary.cs L131](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L131)）。

### 2. 提高並行連線上限

`WebManager.Update` 每個影格只在傳送清單小於 `MaxConnectionPerServer` 時，才從佇列取出一個等待中的請求；超過並行連線數的請求會持續留在 `m_WaitingNormalQueue` 中，看起來就像「卡住不動、遲遲未送出」：

```csharp
protected override void Update(float elapseSeconds, float realElapseSeconds)
{
    lock (m_StringBuilder)
    {
        if (m_SendingNormalList.Count < MaxConnectionPerServer)
        {
            if (m_WaitingNormalQueue.Count > 0)
            {
                var webJsonData = m_WaitingNormalQueue.Dequeue();

                if (webJsonData.UniTaskCompletionStringSource != null)
                {
                    MakeJsonStringRequest(webJsonData);
                }
                else
                {
                    MakeJsonBytesRequest(webJsonData);
                }

                m_SendingNormalList.Add(webJsonData);
            }
        }

        UpdateBinary(elapseSeconds, realElapseSeconds);
    }
}
```

來源：[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L75-L101)

需要更高並行度時進行設定：

```csharp
webManager.MaxConnectionPerServer = 16;
```

屬性定義請參考 [WebManager.cs L65](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L65)。

### 3. 開啟收發日誌以定位問題

傳送與回應日誌由編譯巨集控制，套件提供了用於切換的 `WebLogScriptingDefineSymbols`。開啟後即可查看實際請求的 URL、Header、Form 以及回應內容（或例外訊息）：

```csharp
#if ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
    Log.Debug($"Web Response: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)} \n Content: {content}");
#endif
```

來源：[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L286-L288)

可用的編譯巨集：`ENABLE_GAMEFRAMEX_WEB_SEND_LOG`（傳送）、`ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`（接收）；相關腳本請參考 [WebLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/WebLogScriptingDefineSymbols.cs)。

### 4. 在呼叫端正確捕捉例外

逾時會統一轉換為 `TimeoutException` 後拋出，其他失敗則保留原始的 `WebException` / `IOException`。依照下方順序 catch，即可區分逾時與其他錯誤：

```csharp
try
{
    WebStringResult result = await webManager.GetToString(url);
}
catch (TimeoutException)
{
    // 逾時：調大 Timeout / RequestTimeout 值後重試
}
catch (WebException e)
{
    // HTTP/網路錯誤：檢查 URL、DNS、伺服器狀態
    Debug.LogError(e.Message);
}
catch (IOException e)
{
    // 回應資料流中斷：多為網路不穩，可重試
    Debug.LogError(e.Message);
}
```

逾時轉換與例外分支邏輯（非 WebGL 路徑；WebGL 以外的 Binary 路徑在 [WebManager.Binary.cs L164](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L164) 中以相同方式處理）：

```csharp
catch (WebException e)
{
    // 捕捉逾時例外
    if (e.Status == WebExceptionStatus.Timeout)
    {
        webJsonData.UniTaskCompletionStringSource.SetException(new TimeoutException(e.Message));
        return;
    }
    webJsonData.UniTaskCompletionStringSource.SetException(e);
}
```

來源：[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L305)

呼叫端範例（README 的建議寫法）同樣以 `WebExceptionStatus.Timeout` 分支處理逾時。請參考 [README.md L145-L148](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L145-L148)。

## 常見錯誤

- **誤以為預設逾時為 30 秒**：README 的設定範例標示為「預設：30 秒」，但 `WebManager` 建構函式中實際硬編碼為 `Timeout = 5f`。請參考 [WebManager.cs L46](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L46)。介面回應超過 5 秒即會判定為逾時。
- **只 catch `Exception`**：這樣會失去「逾時」與其他錯誤的區分能力。請先 catch `TimeoutException`，再 catch `WebException`/`IOException`。
- **一次送出大量請求後懷疑請求遺失**：超過 `MaxConnectionPerServer` 的並行請求並不會遺失，只是留在佇列中，每個影格最多取出一個。等待或提高上限即可。
- **在 WebGL 平台檢查 `HttpWebRequest` 的行為**：WebGL 僅使用 `UnityWebRequest` 分支，逾時單位為秒（`TotalSeconds`），與原生平台以毫秒（`TotalMilliseconds`）處理的路徑不同。請參考 [WebManager.cs L217-L218](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L217-L218) 與 [WebManager.cs L258-L259](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L258-L259)。

## 驗證

- 將 `Timeout` 調大到足夠大（例如 30 秒）後重新傳送相同請求；若仍然失敗且例外為 `WebException`，幾乎可排除逾時的可能性，請轉為檢查 URL 與伺服器。
- 開啟 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`，從日誌確認請求是否確實送出，以及 URL/Header/Form 是否與預期一致。
- 在並行情境下比較 `m_SendingNormalList` 與 `MaxConnectionPerServer`：若提高上限後請求不再長時間停留在佇列中，即可確認原因為並行等待。

## 背景

`WebManager` 每個影格會從等待佇列取出請求，並依平台選擇實作：WebGL 使用 `UnityWebRequest`（憑證由 `DefaultBypassCertificate` 直接放行，請參考 [DefaultBypassCertificate.cs L39-L45](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/DefaultBypassCertificate.cs#L39-L45)），其他平台使用 `HttpWebRequest`。兩條路徑讀取的都是相同的 `RequestTimeout` 值，僅單位不同（秒 vs 毫秒）。請求完成或失敗後會從傳送清單中移除並歸還至參考集區，因此不會發生佇列洩漏。
