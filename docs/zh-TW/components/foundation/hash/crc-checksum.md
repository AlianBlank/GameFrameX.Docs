# 使用 CRC32/CRC64 的資料驗證方法

`GameFrameX.Foundation.Hash.CrcHelper` 提供 CRC32 與 CRC64 兩種循環冗餘檢查演算法。支援對位元組陣列、`Stream` 串流(同步與非同步)直接計算校驗和，並可將 CRC32 整數轉換為大端序位元組陣列，供儲存或傳輸使用。

## 前置條件

- 參考命名空間 `GameFrameX.Foundation.Hash`,類別名稱為 `CrcHelper`(靜態部分類別)。
- 目標架構： .NET Standard 2.x 以上，支援 `Stream`、`Task`、`CancellationToken`。

## 操作步驟

### 1. 計算位元組陣列的 CRC32

最簡單的呼叫方式，只要傳入完整的位元組陣列，即可取得 `int` 型別的 CRC32 校驗和值。

```csharp
using GameFrameX.Foundation.Hash;
using System.Text;

byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data);   // 回傳 int
```

來源： [CrcHelper.cs#L121-L126](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L121-L126)

### 2. 計算位元組陣列指定範圍的 CRC32

傳入 `offset` 與 `length`,僅對位元組陣列的切片部分計算 CRC32。若超出範圍或為負數，會擲回 `ArgumentException`。

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data, offset: 2, length: 5);
```

來源： [CrcHelper.cs#L140-L152](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L140-L152)

### 3. 計算串流的 CRC32(同步)

以每 4 KB(`CachedBytesLength = 0x1000`)區塊讀取並計算，因此適合用於大型檔案的驗證。

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = CrcHelper.GetCrc32(stream);
```

來源： [CrcHelper.cs#L163-L183](https://github.com/GameFrameX/GameFrameX/FFoundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L163-L183)

### 4. 非同步計算串流的 CRC32

非同步版本使用 `Stream.ReadAsync`,支援透過 `CancellationToken` 進行取消。

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = await CrcHelper.GetCrc32Async(stream, cancellationToken);
```

來源： [CrcHelper.cs#L188-L202](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L188-L202)

### 5. 計算位元組陣列 / 串流的 CRC64

CRC64 有 3 個公開多載:`GetCrc64(byte[])`、`GetCrc64(Stream)`、`GetCrc64Async(Stream, CancellationToken)`。回傳值為 `ulong`。

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
ulong crc64 = CrcHelper.GetCrc64(data);                 // 位元組陣列

using var stream = File.OpenRead("big.bin");
ulong crc64FromStream = CrcHelper.GetCrc64(stream);    // 同步串流

ulong crc64Async = await CrcHelper.GetCrc64Async(stream); // 非同步串流
```

來源： [CrcHelper.cs#L66-L110](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L66-L110)

### 6. 將 CRC32 整數轉換為大端序位元組陣列

CRC32 的結果經常需要儲存，`GetCrc32Bytes` 提供兩種使用方式：

```csharp
int crc32 = CrcHelper.GetCrc32(data);

// 方法 1: 回傳新的 4 位元組陣列(大端序)
// 以大端序排列的 4 位元組陣列
byte[] bytes = CrcHelper.GetCrc32Bytes(crc32);

// 方法 2: 寫入既有陣列的指定位置
byte[] buffer = new byte[64];
CrcHelper.GetCrc32Bytes(crc32, buffer, offset: 0);
```

來源： [CrcHelper.cs#L212-L257](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L212-L257)

## 常見變化

- **CRC32 與位元組碼循環 XOR 的組合**： `CrcHelper.GetCrc32(stream, code, length)` 是 internal 多載，會先將 `code` 位元組陣列與資料串流進行循環 XOR,再計算 CRC。適用於帶金鑰的輕量驗證情境。
- **不同資料長度的一致性**： CRC 演算法對相同輸入始終回傳相同結果，因此可用於網路封包驗證、檔案指紋、存檔資料完整性驗證。
- **大型檔案的串流計算**： `Stream` 多載(同步/非同步)以 4 KB 為單位進行區塊處理，因此記憶體使用量穩定。

## 常見錯誤

| 錯誤現象 | 原因 | 修正方法 |
|----------|------|------|
| `ArgumentNullException`("bytes") | 傳入的 `byte[]` 為 null | 呼叫前先檢查，或使用 `Array.Empty<byte>()` |
| `ArgumentException`(InvalidDataLength) | `GetCrc32(bytes, offset, length)` 的 `offset` 超出範圍，或 `length` 為負數 | 確保 `offset >= 0`、`length >= 0`,且 `offset + length <= bytes.Length` |
| `ArgumentException`(InvalidDataLength) | `GetCrc32Bytes` 的 `offset` 超出範圍，或目標陣列剩餘容量不足 4 位元組 | 確保 `offset >= 0`,且 `offset + 4 <= bytes.Length` |
| `ArgumentNullException`("stream") | 串流為 null | 驗證串流是否已正常開啟、檔案路徑是否正確 |
| 計算結果不一致 | 字串編碼不一致(UTF-8 / GBK / UTF-16) | 雙方使用相同的 `Encoding`(例： 兩者皆使用 `Encoding.UTF8.GetBytes`) |

## 背景(選用)

CRC32 的預設多項式為 `0xedb88320`,種子為 `0xffffffff`(與 IEEE 802.3 / zlib 相同)，CRC64 內部會委派給 `Crc64` 類別的 `Append` + `GetCurrentHashAsUInt64`。校驗和值適用於非加密的完整性檢查，無法取代 HMAC 等帶金鑰的驗證演算法。
