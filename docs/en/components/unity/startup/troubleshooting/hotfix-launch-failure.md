# What to Do When Hotfix Startup Returns Failure

This page covers the cases where the `HotfixLaunchResult` returned by `IHotfixLauncher.StartAsync` is marked as failed, or the startup procedure triggers `StartupFailedEventArgs` in `ProcedureGameLauncherState`.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `HotfixLaunchResult.IsSuccess == false`, logs indicate the assembly cannot be found | `StartupOptions.HotfixAssemblyName` does not match the actual compiled output | Verify the Inspector field value and ensure it matches the dll output by the build script |
| `HotfixLaunchResult.IsSuccess == false`, logs indicate the entry type cannot be found | `HotfixEntryTypeName` spelling or namespace error | Check the fully qualified type name (including namespace) and verify against the decompiled dll |
| Listening to `StartupFailedEventArgs`, `FailedProcedureName == "ProcedureGameLauncherState"` | Hotfix launcher threw an exception or returned failure | Add try/catch in the `IHotfixLauncher` implementation, populate `ErrorMessage`, then return a failure result |
| Procedure stuck in `ProcedureGameLauncherState` with no progress | `IHotfixLauncher` was not injected into the BlackBoard | Call `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, ...)` before the `Startup Runner` call |
| Received `StartupFailedEventArgs` but `ErrorMessage` is an empty string | Business implementation did not populate `ErrorMessage` as required | Explicitly assign `HotfixLaunchResult.ErrorMessage` when the launcher fails |

See the reference table below for the field definitions of `HotfixLaunchResult` and `StartupFailedEventArgs`.

## Fix Steps

### 1. Verify the StartupOptions Configuration

The hotfix entry trio (assembly name / fully qualified entry type name / entry method name) is injected via `StartupOptions`. If any item does not match, `StartAsync` will return failure:

```csharp
// Default values from StartupOptions.cs
public string HotfixAssemblyName = "Unity.Hotfix";
public string HotfixEntryTypeName = "Hotfix.HotfixLauncher";
public string HotfixEntryMethodName = "Run"; // See the field declaration in StartupOptions.cs
```

Confirm that these three values in the `StartupOptions` asset match the hotfix project's compiled output and the IL2CPP/HybridCLR loading list. Source: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L33-L40)

### 2. Listen for StartupFailedEventArgs

Subscribe to the startup failure event and display the failure message thrown by `ProcedureGameLauncherState` to the player:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(StartupFailedEventArgs.EventId, e =>
{
    var args = (StartupFailedEventArgs)e;
    // args.FailedProcedureName / args.FailedUrl / args.ErrorMessage
});
```

The event firing location is centrally invoked by `StartupProcedureUtility.NotifyFailure`, which fires `StartupFailedEventArgs` once more in addition to the UI hint text. Source: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L160-L170),[StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L40-L60)

### 3. Make the IHotfixLauncher Implementation Return Structured Failure

The `IHotfixLauncher` contract requires that **both success and failure return a `HotfixLaunchResult`, without throwing exceptions**. In your implementation, always catch all exceptions and put them into `ErrorMessage`:

```csharp
public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    try
    {
        // Load + invoke the entry method via reflection
        return HotfixLaunchResult.Success();
    }
    catch (Exception ex)
    {
        return HotfixLaunchResult.Failure(ex.Message);
    }
}
```

Source: [IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L8-L16),[HotfixLaunchResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/HotfixLaunchResult.cs#L1-L40)

### 4. Confirm IHotfixLauncher Is Injected into the BlackBoard

`ProcedureGameLauncherState` reads `IHotfixLauncher` from the FSM BlackBoard. If the injection is missing, the procedure will get stuck at this Procedure. The injection convention is as follows:

```csharp
// Constant defined in BlackBoardKeys
public const string StartupHotfixLauncher = "__startup_hotfix_launcher__";
```

When creating the FSM, the launcher must call `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, hotfixLauncher)`. Source: [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs#L19-L23),[StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L80-L100)

## Verification

After completing the fixes above, confirm each item:

1. `HotfixLaunchResult.IsSuccess == true`, and `ErrorMessage` is empty.
2. `StartupFailedEventArgs` is no longer triggered (or `FailedProcedureName` has switched to another failure point, no longer `ProcedureGameLauncherState`).
3. The subsequent procedure advances to the game's main scene, and `StartupCompletedEventArgs` fires normally.
