# Command Line Arguments Configuration Guide

Use Unity command line arguments to invoke GameFrameX Builder for APK / asset bundle builds, uploads, version updates, and WeCom notifications. This page provides the argument list, value passing methods, and typical invocation commands.

## Prerequisites

- Unity Editor (supports `Environment.GetCommandLineArgs()`, typically used in batch mode `Unity -batchmode`).
- The GameFrameX Builder package is installed and can execute methods under the `GameFrameX.Builder.Editor.Builder` namespace within the editor.
- The build machine or CI must be able to invoke the Unity executable and pass arguments.

## Steps

1. **Determine the entry method**: After `-executeMethod`, pass the fully qualified name of a method in `GameFrameX.Builder.Editor.Builder` (choose `BuildApk`, `BuildAsset`, etc. as needed).

2. **Pass required arguments**: `-executeMethod` and `-BUILD_NUMBER` must be provided, otherwise the builder will throw an exception.

3. **Append optional arguments per task**: Upload, object storage, WeCom notification, and other arguments are only passed when the corresponding flow is needed.

4. **Execute the command in batch mode**: Launch with `-batchmode -quit` from the command line so Unity exits after execution completes.

### Required Arguments

| Argument | Type | Description |
|------|------|------|
| `-executeMethod` | string | Fully qualified method name, e.g. `GameFrameX.Builder.Editor.Builder.BuildApk` |
| `-BUILD_NUMBER` | string | Build number, build flow identifier, must be unique |

Argument parsing and validation logic is as follows:

```csharp
// Editor/Builder.BuildParamsParse.cs
var commandLineArgs = Environment.GetCommandLineArgs();
_builderOptions = new BuilderOptions();
for (var index = 0; index < commandLineArgs.Length; index++)
{
    var commandLineArg = commandLineArgs[index];
    if (commandLineArg == "-executeMethod")
    {
        if (index + 1 < commandLineArgs.Length)
        {
            _builderOptions.ExecuteMethod = commandLineArgs[index + 1].Trim();
        }
    }
    else if (commandLineArg == "-BUILD_NUMBER")
    {
        if (index + 1 < commandLineArgs.Length)
        {
            _builderOptions.BuildNumber = commandLineArgs[index + 1];
        }
    }
    // ... other argument branches
}

if (_builderOptions.ExecuteMethod.IsNullOrWhiteSpace())
{
    throw new Exception("executeMethod is null");
}

if (_builderOptions.BuildNumber.IsNullOrWhiteSpace())
{
    throw new Exception("build number is null");
}
```

### General Arguments

| Argument | Type | Default | Description |
|------|------|--------|------|
| `-logFile` | string | `../Logs/{last segment of executeMethod}_{BUILD_NUMBER}.log` | Log file path; auto-generated by rule when omitted. Replaces `/Unity/` with `/`. |
| `-JOB_NAME` | string | empty | Job name, easy to search in CI |
| `-BundleId` | string | Inherit project settings | Application bundle ID; writes back to `PlayerSettings.applicationIdentifier` when non-empty |
| `-AppVersion` | string | Inherit project settings | Application version; writes back to `PlayerSettings.bundleVersion` when non-empty |
| `-ChannelName` | string | `default` | Channel name |
| `-Language` | string | `default` | Language |

`BundleId` and `AppVersion` writeback implementation:

```csharp
// Editor/Builder.BuildParamsParse.cs
if (!_builderOptions.BundleId.IsNullOrWhiteSpace())
{
    PlayerSettings.applicationIdentifier = _builderOptions.BundleId.Trim();
}

if (!_builderOptions.AppVersion.IsNullOrWhiteSpace())
{
    PlayerSettings.bundleVersion = _builderOptions.AppVersion.Trim();
}
```

## Common Invocation Examples

### Build APK and Upload to Object Storage

```bash
Unity -batchmode -quit \
  -projectPath /path/to/project \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
  -BUILD_NUMBER 20240101120000 \
  -logFile /path/to/logs/build.log \
  -AppVersion 1.0.0 \
  -BundleId com.example.game \
  -ChannelName googleplay \
  -IsUploadApk true \
  -ObjectStorageKey YOUR_KEY \
  -ObjectStorageSecret YOUR_SECRET \
  -ObjectStorageBucketName your-bucket \
  -ObjectStorageEndPoint https://oss-cn-hangzhou.aliyuncs.com
```

### Incrementally Build Asset Package and Notify WeCom Bot

```bash
Unity -batchmode -quit \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
  -BUILD_NUMBER 20240101120000 \
  -PackageName MainAssets \
  -PackageVersion 1.0.1 \
  -BuildPipeline ScriptableBuildPipeline \
  -IsIncrementalBuildPackage \
  -IsUploadAsset true \
  -WeChatBotKey xxx-yyy-zzz
```

## Common Errors

- **Throws `executeMethod is null`**: `-executeMethod` was not passed or its value is a whitespace string.
- **Throws `build number is null`**: `-BUILD_NUMBER` was not passed; this also triggers if the CI variable is not injected.
- **Log file not generated**: When `-logFile` is not passed, it will be auto-generated as `../Logs/{last segment of executeMethod}_{BUILD_NUMBER}.log`; if the working directory is abnormal, pass it explicitly.
- **Bundle ID / version not applied**: Passing a whitespace string to `-BundleId` or `-AppVersion` will fall through to the default branch — ensure they are non-empty.
- **Invalid enum value**: `-BuildPipeline` and `-BuildinFileCopyOption` values must strictly match the case in the table above, otherwise conversion exceptions will occur downstream.

## Background (Optional)

The argument parsing entry point is `Builder.BuildParamsParse()`, which is called by `Builder` at the start of the build. It scans `Environment.GetCommandLineArgs()` item by item and writes the values into `BuilderOptions`. Finally, it outputs via `Debug.Log` and writes back to `PlayerSettings` as needed.

For the default values and downstream consumption locations of each field in `BuilderOptions`, see the "BuilderOptions Reference".
