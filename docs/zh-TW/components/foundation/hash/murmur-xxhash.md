# 高效能雜湊（MurmurHash3 / xxHash 等）的使用方法

`GameFrameX.Foundation.Hash` 提供了 MurmurHash3 與 xxHash 兩種非加密型高效能雜湊演算法的開箱即用 API，直接呼叫靜態方法即可計算字串、位元組陣列與 `Type` 的 32 / 64 / 128 位元雜湊值。廣泛應用於雜湊表鍵值、布隆過濾器、負載平衡分片等非安全性用途。

## 前置條件

- 專案的目標框架為 .NET（程式碼中使用了 `uint` / `ulong` / `ArgumentNullException.ThrowIfNull` 等 BCL API）。
- 專案已參考 `GameFrameX.Foundation.Hash` 組件。xxHash 的實作相依於 NuGet 套件 `Standart.Hash.xxHash`。

## 操作步驟

### 1. 計算字串 / 位元組陣列的 MurmurHash3

`MurmurHash3Helper` 提供了 2 個多載，預設種子值為 `27`。

```csharp
using GameFrameX.Foundation.Hash;

// 字串版：先以 UTF-8 編碼再計算雜湊。seed 可省略（預設 27）
uint hash1 = MurmurHash3Helper.Hash("hello");
uint hash2 = MurmurHash3Helper.Hash("hello", seed: 1234u);

// 位元組陣列版：需明確指定 length 與 seed
byte[] data = System.Text.Encoding.UTF8.GetBytes("hello");
uint hash3 = MurmurHash3Helper.Hash(data, (uint)data.Length, seed: 27u);
```

來源：[MurmurHash3Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/MurmurHash3Helper.cs#L62-L68)

### 2. 計算 xxHash 的 32 / 64 / 128 位元雜湊

`XxHashHelper` 提供 `byte[]` / `string` / `Type` 以及泛型版本，回傳值型別分別為 `uint` / `ulong` / `uint128`。

```csharp
using GameFrameX.Foundation.Hash;
using Standart.Hash.xxHash;

// 32 位元
uint h32 = XxHashHelper.Hash32("hello");
uint h32Type = XxHashHelper.Hash32<MyClass>();

// 64 位元
ulong h64 = XxHashHelper.Hash64("hello");

// 128 位元（回傳值為 uint128，包含 high64 / low64）
uint128 h128 = XxHashHelper.Hash128("hello");
bool zero = XxHashHelper.IsDefault(h128); // 當 high64 與 low64 皆為 0 時回傳 true
```

> ⚠️ 請注意名稱：`Hash32(byte[])` 回傳 `ulong`，而 `Hash32(string)` 回傳 `uint`。這是 SDK 的實際簽章，並非筆誤。

來源：[XxHashHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/XxHashHelper.cs#L62-L100)

### 3. 作為分片鍵 / 雜湊表鍵值使用

要將使用者 ID、請求 ID、玩家 ID 等作為分片鍵或雜湊表鍵值使用時，直接傳入字串即可，無需事先轉換為位元組陣列。

```csharp
// 根據使用者 ID 選擇分片
int shardIndex = (int)(MurmurHash3Helper.Hash(userId) % shardCount);

// 以 64 位元雜湊作為雜湊桶的鍵值
ulong bucketKey = XxHashHelper.Hash64($"player:{playerId}");
```

## 常見變化

| 情境 | 建議 API | 回傳值型別 |
|------|---------|----------|
| 少量資料、需要可重現的種子 | `MurmurHash3Helper.Hash(str, seed)` | `uint` |
| 高吞吐量、位元組陣列、需要跨語言相容性 | `XxHashHelper.Hash32/64/128(buffer)` | `uint` / `ulong` / `uint128` |
| 需要對型別中繼資料取得穩定雜湊（分派表） | `XxHashHelper.Hash64<T>()` | `ulong` |
| 部分長度的雜湊（串流 / 分片資料） | `XxHashHelper.Hash128(buffer, length)` | `uint128` |

## 常見錯誤

- **將 MurmurHash3 當作加密雜湊使用**：MurmurHash3 是非加密雜湊，無法抵禦碰撞攻擊與原像攻擊，請勿用於密碼、權杖、簽章。
- **忽略種子值的一致性**：即使資料相同，只要 `seed` 不同就會得到完全不同的雜湊值。若需要上下游一致，請務必使用相同的種子值（預設 `27`）。
- **混淆 `Hash32(byte[])` 與 `Hash32(string)` 的回傳值型別**：前者回傳 `ulong`，後者回傳 `uint`。這是 SDK 實際簽章上的差異。
- **傳入 `null`**：所有多載都會擲出 `ArgumentNullException`。請以 `??` 進行後備處理，或事先驗證。
- **將 MD5 / SHA-1 用於安全性用途**：`HashAlgorithmKind` 列舉型別中的 `Md5` / `Sha1` 僅供相容性與非安全性驗證使用，密碼用途請使用 `PasswordHashHelper`。

## 背景（可選）

MurmurHash3 在本 SDK 中以純受管理程式碼實作，核心部分由 4 位元組區塊的迴圈 + 尾端合併 + `Fmix32` 的最終混合所組成。典型用途為雜湊表鍵值與快取分片。xxHash 透過 NuGet 套件 `Standart.Hash.xxHash` 呼叫原生實作，其 32 / 64 位元版本在許多硬體上的吞吐量遠高於 MD5 / SHA 系列。由於兩者皆非加密演算法，以「防篡改」為目的的用途需要使用 SHA-2 / 3 或 HMAC。
