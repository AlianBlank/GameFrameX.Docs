# 调度异步任务

`TaskPool<T>` 通过「任务代理 + 优先级队列」的方式管理异步任务:你把若干 `ITaskAgent<T>` 注册到池中,提交 `TaskBase` 派生任务,池会在每帧 `Update` 时按优先级把任务分发给空闲代理执行。本页说明如何接入并调度异步任务。

## 前置条件

- 已引入 `GameFrameX.Runtime` 程序集(任务池位于 [Runtime/Base/TaskPool](/Runtime/Base/TaskPool/TaskPool.cs#L44-L64) 命名空间 `GameFrameX.Runtime`)。
- 自定义任务继承 `TaskBase`,自定义代理实现 `ITaskAgent<T>`。
- 任务对象建议通过 `ReferencePool.Acquire<T>()` 获取,池释放后自动回收([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L11-L21))。

## 操作步骤

1. **定义任务类型**。继承 `TaskBase`,至少重写 `Description` 属性,任务用 `Initialize(serializeId, tag, priority, userData)` 配置优先级与自定义数据。

   ```csharp
   using GameFrameX.Runtime;

   public class LoadAssetTask : TaskBase
   {
       public string AssetName { get; private set; }

       public override string Description => $"LoadAsset:{AssetName}";

       public void Init(string assetName)
       {
           AssetName = assetName;
           Initialize(0, assetName, 0, null);
       }
   }
   ```

   Source: [Runtime/Base/TaskPool/TaskBase.cs](/Runtime/Base/TaskPool/TaskBase.cs)

2. **实现任务代理**。实现 `ITaskAgent<T>` 的 `Initialize / Update / Shutdown / Start / Reset`,在 `Start` 中返回 `StartTaskStatus.CanResume / CanNotResume`,通过 `Task.Done = true` 标记完成([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L23-L62))。

   ```csharp
   public class LoadAssetAgent : ITaskAgent<LoadAssetTask>
   {
       public LoadAssetTask Task { get; private set; }
       public bool IsInitialized { get; private set; }
       public bool IsShutdown { get; private set; }

       public void Initialize() { IsInitialized = true; }
       public void Update(float e, float re) { /* 真实加载完成后置 Task.Done = true */ }
       public void Shutdown() { IsShutdown = true; }

       public StartTaskStatus Start(LoadAssetTask task)
       {
           Task = task;
           return StartTaskStatus.CanResume; // 同步完成请返回 CanNotResume
       }

       public void Reset() { Task = null; }
   }
   ```

   Source: [Runtime/Base/TaskPool/ITaskAgent.cs](/Runtime/Base/TaskPool/ITaskAgent.cs)

3. **创建任务池并注册代理**。实例化 `TaskPool<T>`,调用 `AddAgent` 注册一个或多个代理;代理数量即为最大并发任务数。

   ```csharp
   var taskPool = new TaskPool<LoadAssetTask>();
   taskPool.AddAgent(new LoadAssetAgent());
   taskPool.AddAgent(new LoadAssetAgent()); // 并发 2
   ```

   Source: [Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L58-L64)

4. **提交任务**。通过 `ReferencePool.Acquire` 拿到任务对象,`Initialize` 后调用 `AddTask`。任务会按 `priority` 倒序排列:数值越大越先执行([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L127-L145))。

   ```csharp
   var task = ReferencePool.Acquire<LoadAssetTask>();
   task.Init("Config/battle.json");
   taskPool.AddTask(task);

   var urgent = ReferencePool.Acquire<LoadAssetTask>();
   urgent.Initialize(1, "Player/Avatar", 10, null); // priority=10 先执行
   taskPool.AddTask(urgent);
   ```

5. **每帧驱动 Update**。在游戏主循环中调用 `taskPool.Update(elapseSeconds, realElapseSeconds)`,池会自动:① 推进所有 `WorkingAgent`;② 把等待队列中优先级最高的任务分发给空闲代理([Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L136-L145))。

   ```csharp
   void Update()
   {
       taskPool.Update(Time.deltaTime, Time.unscaledDeltaTime);
   }
   ```

6. **暂停与清理**。需要冻结调度时设置 `taskPool.Paused = true`,`Update` 将直接 return,不会触发任何任务处理([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L185-L196))。不再使用时调用 `RemoveAllTasks()` + `Shutdown()`,并 `ReferencePool.ClearAll()` 释放任务对象。

## 常见变体

| 场景 | 做法 |
|------|------|
| 异步耗时任务(资源加载、网络) | `Start` 返回 `CanResume`,在 `Update` 中轮询进度,完成时置 `Task.Done = true` |
| 同步即可完成的任务 | `Start` 返回 `CanNotResume`,池会在下一帧把代理标记为可继续派发 |
| 控制并发上限 | 仅注册 N 个 `ITaskAgent<T>`,多余任务会留在 `WaitingTasks` 队列 |
| 查询任务状态 | 通过 `GetAllTaskInfos()` 获取 `TaskInfo[]`(含 `Priority`、`Status`、`Description`) |
| 取消指定任务 | `RemoveTask(serializeId, tag)` 命中后归还对象到 `ReferencePool` |

## 常见错误

| 错误 | 说明 | 规避 |
|------|------|------|
| `AddAgent(null)` | 抛出 `GameFrameworkException`([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L99-L101)) | 注册前做空值检查 |
| 代理数量过少 | 等待队列堆积,`WaitingTaskCount` 持续大于 0 | 按预期并发量注册代理 |
| 忘记调用 `Update` | 任务永远不会开始执行 | 把 `taskPool.Update` 接入 MonoBehaviour 主循环或框架的 `GameFramework` 派发 |
| 代理 `Start` 永远不返回 `CanNotResume`、也不置 `Task.Done` | 代理永久占用,空闲代理数不增长 | 在异步回调或 `Update` 中明确置 `Done = true` |
| 直接 `new T()` 创建任务 | 任务未走引用池,无法被回收复用 | 使用 `ReferencePool.Acquire<T>()` |

## 背景(可选)

任务池是「任务 = 数据 / 代理 = 执行者」分离模式:池本身只负责派发和回收,具体怎么执行交给 `ITaskAgent<T>`。优先级由 `m_WaitingTasks` 链表按 `priority` 倒序维护,保证每次出队都是当前优先级最高的任务。`Paused` 用于游戏暂停、切场景等需要冻结后台任务的场景。

关于任务池与其他子系统的协作,见《ReferencePool 参考》。
