# How to Run the Generation Scripts (Client/Server)

Run the `gen-*.bat` or `gen-*.sh` scripts in the repository root to automatically convert the Excel tables under `Excels/` into code and data files that the client (Unity) or the server (.NET) can use directly. This page covers the differences among the four scripts, the minimal steps to run them, and fixes for common errors.

## Overview of the Four Generation Scripts

The repository ships with 4 generation entry points, formed by combining the **target** (`client` / `server`) and the **output format** (`bin` / `json`):

| Script | Target | Data Format | Code Format | Output Location (Data / Code) |
|------|--------|----------|----------|------------------------|
| `gen-client-bin.sh` / `.bat` | Client | Binary (`bin`) | C# binary serialization (`cs-bin`) | `../Unity/Assets//Bundles/Config` / `../Unity/Assets//Hotfix/Config/Generate` |
| `gen-client-json.sh` / `.bat` | Client | JSON | C# | `Unity/Assets/Bundles/Config` / `Unity/Assets/Hotfix/Config/Generate` |
| `gen-server-bin.sh` / `.bat` | Server | Binary (`bin`) | C# .NET binary serialization (`cs-dotnet-bin`) | `../Server/GameFrameX.Config/Json` / `../Server/GameFrameX.Config/Config` |
| `gen-server-json.sh` / `.bat` | Server | JSON | C# | `Server/GameFrameX.Config/Json` / `Server/GameFrameX.Config/Config` |

> `c` = client, `s` = server, `bin` = binary, `json` = text. For the same target, `bin` is smaller in size and faster to load; `json` is human-readable and convenient for troubleshooting data.

## Prerequisites

- The **.NET SDK** is installed (the scripts launch `./Tools/Luban.dll` via `dotnet`).
- `Tools/Luban.dll`, `luban.conf`, `Defines/builtin.xml`, and `Excels/__tables__.xlsx` (plus `__beans__` and `__enums__`) in the repository must remain in their original locations — do not move them.
- The tables are filled in according to the rules (table names in `Excels/Tables/` follow the format `字母-英文名-中文名.xlsx`, i.e., Letter-EnglishName-ChineseName, and the English name must not contain Chinese characters).

## Steps

1. Open a terminal / command line and **`cd` to the repository root** (the level where you can see `gen-*.sh` and `gen-*.bat`). All relative paths in the scripts are based on this directory; do not run them from a subdirectory.

2. Choose your target and output format, then run the corresponding script:

   - **Generate JSON for the client (the most common beginner command):**

     ```bash
     sh gen-client-json.sh
     ```

     On Windows, the equivalent is double-clicking `gen-client-json.bat`.

   - **Generate binary for the client:**

     ```bash
     sh gen-client-bin.sh
     ```

     The core invocation of [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1) is:

     ```bash
     dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin \
       --xargs outputDataDir=../Unity/Assets//Bundles/Config \
       --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
       --xargs tableImporter.name=gameframex \
       -x l10n.provider=gameframex \
       -x l10n.textFile.keyFieldName=key \
       -x l10n.textFile.path=./Excels/Local/ \
       --conf ./Luban.conf
     ```

     Source: [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1)

   - **Generate binary for the server:**

     ```bash
     sh gen-server-bin.sh
     ```

     See [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1) for the actual invocation:

     ```bash
     dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin \
       --xargs outputDataDir=../Server/GameFrameX.Config/Json \
       --xargs tableImporter.name=gameframex \
       --xargs outputCodeDir=../Server/GameFrameX.Config/Config \
       --conf ./Luban.conf
     ```

     Source: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1)

   - **Generate JSON for the server:** Run `sh gen-server-json.sh` (or the corresponding `.bat`).

3. Wait for the script to finish. If it ends at `pause` (Windows `.bat`) or there are no errors in red, it succeeded.

4. Verify the output:
   - Client: `Unity/Assets/Hotfix/Config/Generate/` should contain auto-generated C# classes (e.g., `TbAchievementConfig.cs`), and `Unity/Assets/Bundles/Config/` should contain the data files.
   - Server: `Server/GameFrameX.Config/Config/` contains the C# classes, and `Server/GameFrameX.Config/Json/` contains the data files.

## Common Variants

- **Generate for only one side:** Simply add a group tag to the table name — no need to switch scripts. For example, `D-ItemConfig-道具表.xlsx` (an item table) generates for both client and server; `D-ItemConfig-c-道具表.xlsx` generates only for the client; `D-ItemConfig-s-道具表.xlsx` generates only for the server. See [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md) for details.
- **Changed localization texts (Excels/Local/):** Just re-run the same script; no need to restart anything.
- **Changed table headers (field names/types):** Re-run the script → regenerate the code → compile the calling code against the new field names.
- **Switching between bin and json:** For the same target, simply swap `gen-client-bin.sh` for `gen-client-json.sh` and run it again. If you switch formats at client runtime, remember to update the loading code accordingly.

## Common Errors

- **`'dotnet' is not recognized` / `dotnet: command not found`**: The .NET SDK is not installed, or the terminal cannot find it in PATH. Install the .NET 6+ SDK first, then reopen the terminal.
- **`Could not find ./Tools/Luban.dll`**: The current directory is wrong. `cd` to the repository root that contains `Tools/` and run again.
- **`不支持中文表名` ("Chinese table names not supported") / class names turning into garbled characters**: The English segment of the file name contains Chinese. Rename it to `字母-英文名-中文名.xlsx` (letter-EnglishName-ChineseName), keeping only letters, digits, and underscores in the English name.
- **Stale files remain in the output directory referencing deleted fields**: Simply delete the entire directory pointed to by `outputCodeDir` (e.g., `Unity/Assets/Hotfix/Config/Generate/`), then re-run the script.
- **`failed: conf file` / configuration errors**: `luban.conf` was modified, causing a parsing failure. Restore the file from Git and retry; do not arbitrarily change top-level fields.
- **A localization key read from the `text` field still returns the key itself**: Make sure you are running `gen-client-bin.sh`, or a command with the `-x l10n.provider=gameframex -x l10n.textFile.path=./Excels/Local/` set of arguments, rather than a command using only `--conf ./Luban.conf`.

## Background (Optional)

All four scripts essentially invoke `dotnet ./Tools/Luban.dll`, differing only in three switches: `--target` (determines whether client or server code templates and data type mappings are used), `--dataTarget` (determines the on-disk data format, `bin` or `json`), and `--codeTarget` (determines the generated C# serialization style, e.g., `cs-bin`, `cs-dotnet-bin`). `outputDataDir` and `outputCodeDir` control where the output is written, and `--conf ./Luban.conf` points to the project-level configuration. `gen-client-bin.sh` includes a few extra `-x l10n.*` arguments compared to `gen-server-bin.sh`, because the Unity side needs to resolve the localization keys in the `text` field directly into strings for the current language; therefore, the script explicitly injects a localization provider.
