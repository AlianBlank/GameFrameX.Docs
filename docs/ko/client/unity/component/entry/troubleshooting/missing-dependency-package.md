# 의존 서브패키지 미설치로 인해 컴파일이 실패하는 경우 어떻게 해야 하나요

`com.gameframex.unity.entry`가 특정 서브패키지(예: Network, UI, FairyGUI, Asset, Procedure 등)를 참조하는데 해당 서브패키지가 설치되지 않았거나 버전이 일치하지 않으면, Unity 콘솔에 `Assembly 'GameFrameX.Entry.Runtime' references assembly 'GameFrameX.Xxx.Runtime' which is not in the project` 또는 `The type or namespace name 'X' could not be found` 오류가 표시되어 컴파일이 중단됩니다. 이 페이지에서는 오류를 기반으로 누락된 서브패키지를 찾아내고 컴파일을 복구하는 단계를 안내합니다.

### 2. 누락된 서브패키지 설치

Unity에서 `Window` → `Package Manager`를 열고, 왼쪽 상단의 `+` → `Add package by name...`을 클릭한 후, 위 표의 `name`과 `version`을 입력하여 설치합니다. 예를 들어 Network를 보완하려면:

1. Package Manager를 엽니다.
2. `Add package by name`을 선택합니다.
3. 이름: `com.gameframex.unity.network`, 버전: `2.6.10`.
4. `Add`를 클릭하고 Unity가 확인 및 다운로드를 완료할 때까지 기다립니다.

설치가 완료되면 Package Manager가 자동으로 `Packages/manifest.json`에 기록하고 해당 `versionDefines` 매크로를 주입합니다.

### 3. 버전이 일치하지 않을 때의 처리

`package.json`에 고정된 의존성 버전은 테스트를 통해 호환성이 확인된 조합입니다. 더 낮은/높은 버전을 수동으로 고정한 경우 `asmdef`가 참조하는 어셈블리를 찾지 못할 수 있습니다.

- `Packages/manifest.json` 또는 `Packages/packages-lock.json`에서 해당 패키지의 버전을 확인합니다.
- `package.json`의 `dependencies` 필드와 비교하여 대상 버전으로 통일합니다.
- Git URL 참조인 경우(예: `com.gameframex.unity.network`), URL 뒤에 `#2.6.10`을 추가하여 태그를 고정합니다.

### 4. 해당 하위 시스템이 필요 없을 때의 간소화 방법

특정 선택적 하위 시스템이 필요 없다면 설치를 피하는 동시에 `GameFrameX.Entry.Runtime`이 해당 어셈블리를 참조하지 않도록 할 수 있습니다. 구체적인 방법은 자신의 asmdef에서 더 이상 `GameFrameX.Entry`를 통해 해당 경로를 트리거하지 않도록 하거나, 해당 하위 시스템에 대한 코드 참조를 삭제하는 것입니다. `GameFrameX.Entry.Runtime.asmdef`는 해당 서브패키지의 존재 여부에 따라 `versionDefines`를 통해 코드 분기를 자동으로 활성화/비활성화합니다.

```text
예시: Procedure + UI + Network만 사용하는 경우 다음만 설치하면 됩니다
  com.gameframex.unity.procedure@1.4.0
  com.gameframex.unity.ui@2.11.0
  com.gameframex.unity.network@2.6.10
기타 선택적 서브패키지(광고, 로그인, 통계, XLua 등)는 설치할 필요가 없으며, 코드는 매크로를 통해 자동으로 제거됩니다.
```

### 5. 설치 후에도 오류가 발생하는 경우 정리 단계

1. Unity를 종료합니다.
2. 프로젝트 루트 디렉터리의 `Library/ScriptAssemblies/`와 `Library/PlayerScriptAssemblies/`를 삭제합니다.
3. `Library/PackageCache/` 아래에서 누락된 서브패키지와 관련된 잔여 캐시를 삭제합니다.
4. Unity를 다시 열고 최초 임포트가 완료될 때까지 기다립니다.

완료되면 콘솔에 누락된 어셈블리 관련 알림이 더 이상 표시되지 않아야 합니다.

## 검증

- Unity Console에서 `Assembly ... references ... which is not in the project` 유형의 오류가 더 이상 발생하지 않습니다.
- `Window` → `Package Manager`에서 `dependencies`에 선언된 모든 서브패키지가 `Installed` 상태인 것을 확인할 수 있습니다.
- 임의의 스크립트에서 `using GameFrameX.Entry.Runtime;`이 성공적으로 적용되고 `GameApp.Procedure`, `GameApp.Network` 등의 정적 접근자에 접근할 수 있습니다.

## 배경(선택 사항)

엔트리 패키지 `com.gameframex.unity.entry`는 `GameFrameX.Entry.Runtime.asmdef`를 통해 모든 하위 시스템 어셈블리에 대한 참조를 중앙에서 선언하고, `versionDefines`에서 서브패키지의 존재 여부에 따라 `ENABLE_GAME_FRAME_X_*` 매크로를 주입하여, 설치되지 않은 서브패키지의 코드 구간이 `#if`로 제외되도록 함으로써 필요에 따른 컴파일을 구현합니다. `package.json`의 `dependencies` 필드는 버전 정렬의 유일한 진실 공급원입니다. 컴파일 시 "어셈블리를 찾을 수 없다"는 오류가 발생하면 asmdef를 수동으로 수정하기 전에 먼저 이곳의 버전을 확인하십시오.
