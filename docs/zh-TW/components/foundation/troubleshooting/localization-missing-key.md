# 當地語系化發生索引鍵缺失或格式錯誤時的處理方式

當 `LocalizationService.GetString` / `GetString(key, args)` 回傳索引鍵名稱本身（例如：`"Some.Unknown.Key"`），或回傳的字串中殘留未替換的 `"{0}"`、`{n:xxxxx}` 等佔位符時，表示已觸發當地語系化的「索引鍵缺失」或「格式錯誤」分支。本頁面將說明如何定位原因與修正方法。

## 快速診斷

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `GetString("X.Y")` 直接回傳 `"X.Y"` | 資源索引鍵不存在（未註冊、未隨組件一同載入、索引鍵名稱拼寫錯誤） | 以 `EnsureLoaded()` 強制載入，並訂閱 `MissingKey` 事件確認索引鍵。請參閱[索引鍵缺失](#修正-1-索引鍵缺失) |
| 範本中顯示未替換的 `{0}`、`{1}`、`{name}` | 佔位符的索引/名稱與 `args` 不一致，導致 `string.Format` 擲回 `FormatException` | 確認範本的佔位符數量與型別。切換 `FormatErrorBehavior`。請參閱[格式錯誤](#修正-2-格式錯誤) |
| 擲回 `FormatException: Input string was not in a correct format` | `FormatErrorBehavior` 設定為 `Throw` | 暫時切換回 `ReturnTemplate` 以定位問題，或修正範本與引數。請參閱[格式錯誤](#修正-2-格式錯誤) |
| 回傳的字串與目前的 `CultureInfo` 不符（永遠是英文/永遠是特定語言） | 未註冊該 `CultureInfo` 用的資源，或回退至預設文化特性 | 請參閱[文化特性與回退行為](#修正-3-文化特性與回退行為) |

關於 `FormatErrorBehavior` 三種值的意義，請參閱 [`LocalizationFormatErrorBehavior`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/LocalizationFormatErrorBehavior.cs#L6-L22)。預設值為 `ReturnTemplate`。

## 修正步驟

### 修正 1: 索引鍵缺失

1. 確認索引鍵名稱的拼寫是否正確（包含大小寫與句點）。索引鍵名稱以字串嚴格比對，因此 `"Utility.Exceptions.TimestampOutOfRange"` 與 `"utility.exceptions.timestampoutofrange"` 會被視為不同的索引鍵。
2. 呼叫 [`LocalizationService.EnsureLoaded()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L207-L210) 強制載入所有提供者，避免因延遲載入而掩蓋問題。
3. 訂閱 [`MissingKey`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L79-L89) 事件，將實際缺失的索引鍵輸出至日誌：

   ```csharp
   LocalizationService.MissingKey += (sender, args) =>
   {
       // 可從 args.Key / args.Culture 取得具體缺失的索引鍵與文化特性
       Console.WriteLine($"Missing localization key: {args.Key} ({args.Culture})");
   };
   ```

4. 若仍然回傳索引鍵名稱，請確認組件的資源是否已隨主組件一同發佈（`*.resources.dll` 是否已複製到輸出目錄），以及自訂資源提供者是否已透過 `LocalizationService.RegisterProvider(...)` 註冊。

### 修正 2: 格式錯誤

格式處理失敗時，[`ResourceManager.FormatString`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L234-L252) 內部會攔截 `FormatException`，並依據 `FormatErrorBehavior` 進行處理：

```csharp
public LocalizationFormatErrorBehavior FormatErrorBehavior { get; set; }
    = LocalizationFormatErrorBehavior.ReturnTemplate;
```

請依照以下順序進行排查：

1. **確認佔位符數量**：範本中 `{0}` / `{1}` 的數量必須與傳入 `args` 的數量一致。佔位符過多時會直接擲回 `FormatException`。
2. **確認型別**：若範本使用 `{0:d}`、`{0:N2}` 等格式規範，`args` 對應位置的值必須能轉換為該格式要求的數值/日期型別。將 `string` 傳入 `{0:d}` 會導致失敗。
3. **暫時切換行為以利定位**：將 `FormatErrorBehavior` 變更為 `Throw`，即可從例外狀況的堆疊追蹤直接定位呼叫端：

   ```csharp
   LocalizationService.Instance.FormatErrorBehavior
       = LocalizationFormatErrorBehavior.Throw;
   ```

   三種值的意義：

   | 值 | 行為 |
   |------|------|
   | `ReturnTemplate`（預設） | 回傳未經格式化的當地語系化範本（含 `{0}` 等） |
   | `ReturnKey` | 回傳資源的索引鍵名稱 |
   | `Throw` | 重新擲回 `FormatException`，便於在開發環境中定位問題 |

4. 修正完成後，請切換回 `ReturnTemplate`，以避免在正式環境中擲回未處理的例外狀況。

### 修正 3: 文化特性與回退行為

1. 透過 `CultureInfo.CurrentUICulture` 控制用於查找的文化特性。若要明確指定文化特性，請使用 [`LocalizationService.GetString(key, culture)`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L130-L138)。
2. 若特定文化特性永遠回傳英文（或永遠回傳索引鍵），表示該文化特性沒有對應的資源，因而回退至預設文化特性或索引鍵名稱。請在資源檔案中加入對應的 `.resx`。
3. 呼叫 [`LocalizationService.GetStatistics()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L234-L237) 確認提供者是否已載入：

   ```csharp
   var stats = LocalizationService.GetStatistics();
   Console.WriteLine($"Providers loaded: {stats.ProvidersLoaded}");
   ```

## 驗證

1. 重新觸發原始呼叫路徑，確認回傳值不等於傳入的索引鍵名稱，且不會顯示未替換的 `{0}` / `{1}` 佔位符。
2. 暫時將 `FormatErrorBehavior` 設定為 `Throw` 並執行測試/煙霧測試，確認不會擲回 `FormatException`。
3. 分別以不同的 `CultureInfo` 呼叫 `GetString(key)`，確認回傳值與所選的文化特性一致。若有缺失，請確認日誌中是否觸發了 `MissingKey` 事件。
