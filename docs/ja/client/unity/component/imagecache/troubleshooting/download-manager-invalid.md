# Download manager is invalid エラーの対処法

非 WebGL プラットフォームで ImageCache コンポーネントを起動した際、ログに `Log.Fatal("Download manager is invalid.")` が出力される場合は、`GameFrameworkEntry.GetModule<IDownloadManager>()` が null を返しているために、`ImageCacheComponent` が `ImageCacheManager` に Download Manager を注入できていないことを意味します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動シーンで `Download manager is invalid.` が発生し、画像読み込みが全て無効になる | `IDownloadManager` モジュールが登録されていない | 起動フローに `GameFrameworkEntry.GetModule<IDownloadManager>()` が利用可能な Download コンポーネントを追加する |
| WebGL プラットフォームでは本エラーは発生しないが、他の平台では発生する | 非 WebGL 分岐でのみ Download Manager を検証している | ビルドターゲットが非 WebGL であること、および Download コンポーネントがアタッチされていることを確認する |
| `LoadImageAsync` が null を返し、コンソールに他のエラーが出ない | Download Manager は存在するが、`Awake` 後に登録されている | モジュールの初期化順序を調整し、Download コンポーネントが ImageCache コンポーネントの Awake よりも先に初期化されるようにする |

## 修正手順

### 1. Download コンポーネントのアタッチ

本エラーは [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55-L64) 内の `Awake` 検証から発生しています:

```csharp
#if !UNITY_WEBGL
            var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
            if (downloadManager == null)
            {
                Log.Fatal("Download manager is invalid.");
                return;
            }

            ((ImageCacheManager)_imageCacheManager).SetDownloadManager(downloadManager);
#endif
```

`IDownloadManager` が登録されていない場合、ここで即座に `Log.Fatal` が出力され `return` されるため、後続の `SetDownloadManager` は実行されず、すべての `LoadImageAsync` 呼び出しが失敗します。

操作手順:

1. 起動シーン（通常は `Bootstrap` / `Launch` シーン）を開きます。
2. 同じ `GameFramework` エントリオブジェクト（またはその子オブジェクト）に Download コンポーネント（`GameFrameX.Download` パッケージで提供）を追加します。
3. シーンを実行し、コンソールに `Download manager is invalid.` が出力されないことを確認します。

### 2. モジュール登録順序の保証

`ImageCacheComponent.Awake` は `GameFrameworkEntry` から能動的にモジュールを取得します:

```csharp
_imageCacheManager = GameFrameworkEntry.GetModule<IImageCacheManager>();
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
```

Download コンポーネントが ImageCache コンポーネントよりも後に Awake された場合、後者からはモジュール一覧に `IDownloadManager` がまだ存在しないため、検証は失敗します。

操作手順:

1. Inspector でコンポーネントの順序を調整し、Download コンポーネントが ImageCache コンポーネントよりも前に並ぶようにします（Unity はコンポーネントの追加順に `Awake` を実行します）。
2. あるいは、コードで初期化を制御する方法もあります。`Start` / 独自の初期化段階で Download モジュールを先にインスタンス化し、その後で ImageCache をアクティブ化します。

### 3. ビルドプラットフォームの確認

エラーブロックは `#if !UNITY_WEBGL` で囲まれており（[ImageCacheComponent.cs#L55](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55)）、WebGL プラットフォームでは Download Manager 分岐を処理しないため、WebGL ではこのエラーは表示されません。WebGL 上で同じ文字列を確認した場合は、マクロの記述ミスや非 WebGL 用リソースの取り込みミスの可能性を確認してください。

## 検証

- 起動シーン起動後、コンソールに `Download manager is invalid.` が表示されないこと。
- `ImageCacheComponent.LoadImageAsync(url)` を呼び出し、画像が正常に `Texture2D` を返すこと（またはキャッシュヒットすること）。
- ImageCache コンポーネントの参照をブレークポイントで確認すると、`ImageCacheManager._downloadManager` が null ではないことが確認できます（[ImageCacheManager.cs#L56-L61](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L56-L61) を参照）。
