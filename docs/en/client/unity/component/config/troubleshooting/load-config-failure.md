# What to Do When Configuration Loading Fails

When registering or reading global configuration through `ConfigComponent`, if a `LoadConfigFailureEventArgs` (with the full class name `LoadConfigFailureEventArgs`, event ID) is thrown, or `GetConfig<T>()` returns `default`/`null`, it usually means the underlying `ConfigManager` did not obtain the configuration data. This page helps you quickly locate the cause and fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|---------|-------|-----|
| Log prints `Config manager is invalid.` | `IConfigManager` implementation was not retrieved during `ConfigComponent.Awake` | See [ConfigManager Not Injected](#configmanager-not-injected) |
| `GetConfig<T>()` returns `null` / `default(T)` | Resource loaded successfully but not registered to the manager via `Add`, or the resource name does not match the type name | See [Not Registered to ConfigComponent](#not-registered-to-configcomponent) |
| Received `LoadConfigFailureEventArgs`, `ErrorMessage` contains `IOException` / parsing failure | Configuration binary / JSON resource not generated or out of sync with code | See [Configuration Resource Missing or Corrupted](#configuration-resource-missing-or-corrupted) |
| `HasConfig<T>()` always returns `false` | The name lookup key uses case-sensitive comparison (`StringComparer.Ordinal`) | See [Configuration Name Case Mismatch](#configuration-name-case-mismatch) |

## Fix Steps

### ConfigManager Not Injected

`ConfigComponent.Awake` retrieves the manager implementation through `GameFrameworkEntry.GetModule<IConfigManager>()`. If the framework has not registered `ConfigManager`, a fatal log is immediately recorded and the method returns directly, making all subsequent read/write operations invalid.

In [ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85):

```csharp
protected override void Awake()
{
    m_ConfigNameTypeMap.Clear();
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IConfigManager);
    base.Awake();
    m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
    if (m_ConfigManager == null)
    {
        Log.Fatal("Config manager is invalid.");
        return;
    }
}
```

Make sure the project contains the `GameFrameX.Config.Runtime.ConfigManager` assembly, and that framework initialization is triggered before business code during the bootstrap phase (the framework's `[GameFrameXAutoComponent(-5000)]` attribute ensures it is registered earlier than normal business components).

### Not Registered to ConfigComponent

`ConfigComponent` itself is only responsible for "storing by name", and is **not** responsible for loading resources. Before reading configuration, the parsed `IDataTable` must be explicitly placed into the manager:

```csharp
ConfigComponent.Instance.Add(typeof(MyConfig).Name, myDataTableInstance);
var cfg = ConfigComponent.Instance.GetConfig<MyConfig>();
```

In [ConfigComponent.cs#L182-L185](/Runtime/Config/ConfigComponent.cs#L182-L185):

```csharp
public void Add(string configName, IDataTable dataTable)
{
    m_ConfigManager.AddConfig(configName, dataTable);
}
```

If you skip `Add` and call `GetConfig<T>()` directly, the key will not exist in `ConfigManager`'s internal dictionary, returning `default`, and triggering `LoadConfigFailureEventArgs`.

### Configuration Resource Missing or Corrupted

When you asynchronously load binary/JSON through the resource system and deserialize it into `IDataTable`, if the file does not exist, the version does not match, or deserialization throws an exception, the resource layer will callback the failure event `LoadConfigFailureEventArgs`. Its fields have the following meanings:

In [LoadConfigFailureEventArgs.cs#L43-L65](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L43-L65):

```csharp
public sealed class LoadConfigFailureEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(LoadConfigFailureEventArgs).FullName;

    public LoadConfigFailureEventArgs()
    {
        ConfigAssetName = null;
        ErrorMessage = null;
        UserData = null;
    }

    public override string Id { get { return EventId; } }
    public string ConfigAssetName { get; private set; }
    public string ErrorMessage    { get; private set; }
    public object UserData        { get; private set; }
}
```

Troubleshooting checklist:

1. When subscribing to the event, print `e.ConfigAssetName` and `e.ErrorMessage` to locate which resource failed;
2. Re-export/regenerate configuration (ensure Excel/Lua/JSON has been re-exported, and the binary has been re-packed into StreamingAssets or Addressables);
3. If the configuration struct fields have changed, confirm that the code and data table have been regenerated; old binaries cannot be deserialized.

### Configuration Name Case Mismatch

`ConfigManager` uses `StringComparer.Ordinal` when constructing the dictionary, which is **strictly case-sensitive** and culture-independent:

In [ConfigManager.cs#L58-L61](/Runtime/Config/ConfigManager.cs#L58-L61):

```csharp
public ConfigManager()
{
    m_ConfigDatas = new ConcurrentDictionary<string, IDataTable>(StringComparer.Ordinal);
}
```

`ConfigComponent.GetTypeName<T>()` uses `typeof(T).Name`, and if the `configName` you pass differs in case, it will be treated as a different key. Make sure the strings are exactly identical during registration and lookup.

## Verification

After fixing, confirm the issue has been resolved by:

1. `Log.Fatal("Config manager is invalid.")` no longer appears;
2. `HasConfig<T>()` returns `true` for the target type;
3. `GetConfig<T>()` returns a non-null instance, with field values consistent with the source data;
4. Subscribe to `LoadConfigFailureEventArgs.EventId` and confirm no failure events are received.

```csharp
GameFrameworkEvent.Get().Subscribe(LoadConfigFailureEventArgs.EventId, (sender, e) =>
{
    var args = (LoadConfigFailureEventArgs)e;
    Log.Error($"Configuration loading failed: {args.ConfigAssetName} - {args.ErrorMessage}");
});
```
