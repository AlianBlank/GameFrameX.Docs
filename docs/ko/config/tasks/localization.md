# 현지화 다국어 구성 방법(text 필드)

Excel 구성 테이블에서 필드 타입을 `text`로 선언하면 해당 열을 `TbLocalization` 다국어 테이블에 연결할 수 있으며, 런타임에 key를 기준으로 현재 언어의 실제 문구를 가져와 동일한 구성 하나로 다국어 전환을 구현합니다.

## 사전 조건

- .NET SDK(Luban 도구의 실행 종속성)가 설치되어 있어야 합니다.
- 저장소 루트 디렉터리에 `L-` 접두사 다국어 파일을 두는 `Excels/Local/` 디렉터리가 존재해야 합니다.
- 생성 스크립트(`gen-client-json.sh` / `gen-server-json.sh` 등)를 실행할 수 있어야 하며, 생성 후 `Hotfix/Config/Generate` 또는 `Server.Config/Config`에 `TbLocalization` 클래스가 만들어집니다.

## 작업 단계

1. **필드 타입을 `text`로 선언합니다**. 임의의 비즈니스 테이블(예: 업적 테이블, 아이템 테이블)의 `##type` 행에서 필드 타입을 `string`이 아니라 `text`로 작성합니다. `text`는 해당 열에 key를 채우고 런타임에 다국어 테이블에서 실제 문구를 조회한다는 의미이고, `string`은 원문 그대로 직접 사용되며 번역되지 않습니다.

   예시: 업적 테이블의 `name`과 `achievement_content` 필드 모두 `text` 타입을 사용하고 key만 채웁니다:

   | ##var | id | image | name | achievement_content |
   |-------|----|-------|------|---------------------|
   | ##type | int | int | text | text |
   | ##group | | | | |
   | ## | ID | 아이콘 id | 업적 Key | 업적 내용 Key |
   | | 900001 | 101 | achievement_001 | achievement_001_desc |

   출처: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L227-L232)

2. **`text`와 `string`의 차이를 이해합니다**. `text`는 현지화 대상인 다국어 문구(key를 채움)이고, `string`은 번역되지 않는 일반 텍스트(내용을 직접 작성)입니다. 번역이 필요한 필드를 실수로 `string`으로 작성하면 런타임에 원본 문자열을 받게 되어 번역이 적용되지 않습니다.

   출처: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L223)

3. **다국어 Excel 파일을 준비합니다**. 저장소에는 `Excels/Local/` 아래에 세 개의 예시가 이미 제공되어 있으며, 모두 동일한 `TbLocalization` 테이블로 병합됩니다:

   | 다국어 분류 | 파일 | 내용 |
   |------------|------|------|
   | 다국어-업적 | `Excels/Local/L-Localization-成就.xlsx` | 업적 문구 |
   | 다국어-텍스트 | `Excels/Local/L-Localization-文本.xlsx` | 공통 문구 |
   | 다국어-UI | `Excels/Local/L-Localization-UI.xlsx` | UI 문구 |

   여러 `L-Localization-*.xlsx`는 영어 부분(`Localization`)만 일치하면 자동으로 병합됩니다:

   ```
   L-Localization-成就.xlsx    ┐
   L-Localization-文本.xlsx    ├→ 하나의 TbLocalization으로 병합
   L-Localization-UI.xlsx      ┘
   ```

   출처: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L199), [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L250-L254)

4. **모듈별로 다국어 테이블을 분할합니다(선택 사항)**. 문구량이 많을 때는 업적, UI, 텍스트 등 모듈별로 여러 `L-Localization-XXX.xlsx`로 나누면 되며, 영어 이름 접두사만 `L-Localization`으로 유지하면 되고 중국어 부분은 자유롭게 명명할 수 있습니다(도구가 파싱하지 않음).

   출처: [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L256)

5. **생성 명령에 `localizationFileName`가 켜져 있는지 확인합니다**. `luban.conf`에서 클라이언트의 `client` target 명령에 `"localizationFileName": "Localization.xlsx"`가 포함되어 있어야 하며, 이 항목이 없으면 `TbLocalization`이 생성되지 않습니다.

   ```json
   {
     "localizationFileName": "Localization.xlsx",
     "command": "--target client --dataTarget json --codeTarget cs-simple-json ...",
     "target": "client",
     "active": true
   }
   ```

   출처: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

6. **생성 스크립트를 실행합니다**. Windows에서는 `gen-client-json.bat`를 더블클릭하고, Mac/Linux에서는 `sh gen-client-json.sh`를 실행합니다. 생성이 완료되면 비즈니스 테이블의 `text` 필드가 `TbLocalization`에 매핑되며, 런타임에 key로 현재 언어의 문구를 가져올 수 있습니다.

## 일반적인 변형

- **클라이언트/서버별 그룹화**: 다국어 파일의 영어 이름 뒤에 `c-` 또는 `s-`를 추가하면(예: `L-Localization-c-UI.xlsx`) 해당 측에서만 가져가도록 할 수 있습니다.
- **사용자 지정 다국어 파일 추가**: `Excels/Local/` 아래에 두고 영어 이름 접두사가 `L-Localization`이면 자동으로 `TbLocalization`에 병합됩니다.
- **항목 수 기준으로 대형 테이블 분할**: 일반 테이블과 마찬가지로 동일한 영어 이름 + 다른 중국어 이름(예: `L-Localization-UI-1.xlsx`, `L-Localization-UI-2.xlsx`)을 사용하면 도구가 자동으로 병합합니다.

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| 런타임에 가져온 문구가 key 리터럴임 | `##type`을 `text`가 아닌 `string`으로 작성함 | 필드 타입을 `text`로 변경 |
| 생성된 `TbLocalization`을 찾을 수 없음 | `luban.conf`의 `client` target 명령에 `localizationFileName`가 없음 | 위의 5단계에 따라 명령 JSON에 추가 |
| 테이블 영어 이름에 중국어가 포함됨 | 도구 요구 사항상 영어 이름에 중국어가 있으면 안 되며, 있으면 바로 오류 발생 | `L-本地化-成就.xlsx`를 `L-Localization-成就.xlsx` 형식으로 변경 |
| 문구가 적용되지 않고 key만 보임 | `L-Localization-*.xlsx`가 `Excels/Local/` 디렉터리에 없음 | 파일을 `Excels/Local/`로 이동한 후 생성 스크립트 다시 실행 |

## 배경(선택 사항)

`text` 필드는 본질적으로 `TbLocalization`의 key를 참조하며, 모든 `L-Localization-*.xlsx`는 동일한 다국어 테이블로 병합됩니다. `string`은 번역을 건너뛰고 원본 문자열로 직접 사용됩니다. `luban.conf`의 `localizationFileName`는 클라이언트 다국어 생성을 켜는 스위치입니다.
