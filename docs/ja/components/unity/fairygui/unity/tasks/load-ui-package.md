# UI パッケージのロードとアンロード

FairyGUI Unity ランタイムでは、UI パッケージのロードとは、`UIPackage.AddPackage` シリーズの静的メソッドを呼び出して、パブリッシュされた `_fui` 記述ファイルとそのリソースをグローバルのパッケージリストに登録することを指し、その後 `UIPackage.CreateObject` でコンポーネントを作成できるようになります。アンロードは `UIPackage.RemovePackage` / `RemoveAllPackages` を呼び出して、パッケージ内のすべてのリソースを解放します。すべての API は [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L311) に集約されています。

## 前提条件

- FairyGUI エディターで UI パッケージをパブリッシュ済みであり、`包名_fui.bytes` 記述ファイルおよびリソースファイルを取得していること。
- 記述ファイルを Unity の `Resources` ディレクトリに配置していること(または AssetBundle / カスタムローダー経由で提供)。

## 操作手順

1. **パブリッシュ成果物をプロジェクトに配置する**:`包名_fui.bytes`(および画像、サウンドなどのリソース)を `Resources` ディレクトリ配下のサブディレクトリ、例えば `Assets/Resources/UI/Basics` に配置します。記述ファイル名は必ず `_fui` で終わる必要があり、ランタイムは `assetPath + "_fui"` と `".bytes"` を自動的に連結してロードします([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L324-L325) 参照)。

2. **パッケージをロードする**:Resources からの相対パスで `AddPackage(string descFilePath)` を呼び出します。パスに `_fui` サフィックスは付けません。例:

```csharp
// パスは Resources ディレクトリ基準の相対パスで、_fui サフィックスは付けない
UIPackage.AddPackage("UI/Basics");
```

   このオーバーロードの完全な実装:パスが `Assets/` で始まる場合は Editor 下でのみ使用可能(`_loadFromAssetsPath` を経由)で、それ以外の場合は Resources の相対パスとしてロードされます([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L298-L311) 参照)。

3. **(任意)先に重複チェックをしてからロードする**:`AddPackage` を重複して呼び出すと複数のパッケージインスタンスが登録されるため、先にロード済みかどうかを判定します。リポジトリ内の `UIPainter` がまさにこのようにしています:

```csharp
if (!string.IsNullOrEmpty(packagePath) && UIPackage.GetByName(packageName) == null)
    UIPackage.AddPackage(packagePath);
```

出典: [UIPainter.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPainter.cs#L64-L66)

4. **コンポーネントを作成してロード成功を検証する**:

```csharp
public static GObject CreateObject(string pkgName, string resName)
{
    UIPackage pkg = GetByName(pkgName);
    if (pkg != null)
        return pkg.CreateObject(resName);
    else
        return null;
}
```

出典: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L512-L519)

   呼び出しは `UIPackage.CreateObject("Basics", "MainMenu")` のような形です。`CreateObjectFromURL("ui://Basics/MainMenu")` を使うこともできます([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L542-L547) 参照)。

5. **パッケージをアンロードする**:画面が閉じられ、リソースが不要になったときに、パッケージ名またはパッケージ id でアンロードします:

```csharp
public static void RemovePackage(string packageIdOrName)
{
    UIPackage pkg = null;
    if (!_packageInstById.TryGetValue(packageIdOrName, out pkg))
    {
        if (!_packageInstByName.TryGetValue(packageIdOrName, out pkg))
            throw new Exception("FairyGUI: '" + packageIdOrName + "' is not a valid package id or name.");
    }

    pkg.Dispose();
    _packageInstById.Remove(pkg.id);
    ...
}
```

出典: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L458-L475)

   渡すのはパッケージ id **または** パッケージ名で、一致しない場合は `FairyGUI: '...' is not a valid package id or name.` が直接スローされます。すべてのパッケージを一括で消去するには `RemoveAllPackages()` を使います([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L480-L495) 参照)。

## AddPackage オーバーロード早見表

| オーバーロード | シグネチャ | 適用場面 |
|------|------|----------|
| AssetBundle 単一 bundle | `AddPackage(AssetBundle bundle)` | 記述とリソースが同じ bundle 内にある | 
| AssetBundle 2 つの bundle | `AddPackage(AssetBundle desc, AssetBundle res)` | 記述とリソースを分離してパッキング |
| AssetBundle + メインアセット名 | `AddPackage(AssetBundle desc, AssetBundle res, string mainAssetName)` | 記述ファイルのアセット名を指定、例： `Basics_fui` |
| Resources パス | `AddPackage(string descFilePath)` | 記述ファイルが Resources 配下にある |
| カスタムロード関数 | `AddPackage(string assetPath, LoadResource loadFunc)` | 独自のリソース管理システムへの接続;同一パスでの重複呼び出しはロード済みパッケージを直接返す |
| バイト配列 | `AddPackage(byte[] descData, string assetNamePrefix, LoadResource loadFunc)` | 記述データが既にメモリ上にある |
| 非同期 | `AddPackageAsync(string assetPath, Action<UIPackage> callback)` | 非同期ロード、事前に `SetAsyncLoadResource` が必要 |

以上のシグネチャはすべて [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L381) によるものです。

関連するクエリインターフェース:`GetByName(string name)`、`GetById(string id)`、`GetPackages()`([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L190-L211) 参照)。

## よくあるバリエーション

**AssetBundle からロード**(記述とリソースが同一 bundle):

```csharp
public static UIPackage AddPackage(AssetBundle bundle)
{
    return AddPackage(bundle, bundle, null);
}
```

出典: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L221)

bundle 内に `_fui` 記述ファイルが見つからない場合は `FairyGUI: no package found in this bundle.` がスローされます。`desc` と `res` が異なる 2 つの bundle であり、`UIPackage.unloadBundleByFGUI` が `true`(デフォルト値)の場合、記述ファイルのロード完了後に即座に `desc.Unload(true)` が実行されます([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L269-L273) 参照)。

**カスタムロード関数**(プロジェクトのリソースフレームワークへの接続)、Editor ツールでの実際の使用例：

```csharp
UIPackage.AddPackage(assetPath,
    (string name, string extension, System.Type type, out DestroyMethod destroyMethod) =>
    {
        // ロードした asset を返し、out destroyMethod でアンロード方法を指定する
        ...
    });
```

出典: [EditorToolSet.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/EditorToolSet.cs#L118-L119)

`LoadResource` デリゲートのシグネチャは [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L319-L325) を参照してください:`assetPath + "_fui"`、`".bytes"`、`typeof(TextAsset)` で記述ファイルを要求し、実装側が `out DestroyMethod` を通じてリソースの破棄方法を決定します。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `FairyGUI: Cannot load ui package in '...'` がスローされる | `loadFunc` が null を返した、記述ファイルのパスが誤っている、またはパッケージに含まれていない | パスに `_fui` サフィックスが付いていないことを確認;`Resources` 配下に `路径_fui.bytes` が存在することを確認;ランタイム(`Application.isPlaying`)では例外が直接スローされ、Editor の非再生モードでは警告のみ([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L326-L332) 参照) |
| `FairyGUI: no package found in this bundle.` がスローされる | bundle 内に `_fui` の名前を持つ TextAsset がない | 再パブリッシュして bundle に `包名_fui` 記述ファイルが含まれていることを確認するか、`mainAssetName` を明示的に渡す([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L252-L270) 参照) |
| `FairyGUI: '...' is not a valid package id or name.` がスローされる | `RemovePackage` に渡された値がパッケージ id でもパッケージ名でもない、またはパッケージが既にアンロードされている | `UIPackage.GetByName` でパッケージの存在を確認してからアンロードする([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L460-L465) 参照) |
| Editor / 実機で `Assets/` パスのロードが失敗し警告が出る | `AddPackage(string)` は `Assets/` で始まるパスに対して `UNITY_EDITOR` 下でのみ有効 | 実機では Resources 相対パス、AssetBundle、またはカスタムロード関数に変更する([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L300-L308) 参照) |
| アンロード後に画面がピンクになる/テクスチャが失われる | パッケージは `Dispose` 済みだが、パッケージ内リソースを使用中のコンポーネントがまだ存在する | そのパッケージを使用するすべての UI を先に破棄してから、`RemovePackage` を呼び出す |

## 検証

- ロード後、`UIPackage.GetByName("Basics")` を呼び出すと null 以外が返り、かつ `UIPackage.CreateObject("Basics", "组件名")` で null 以外の `GObject` が取得できること。
- アンロード後、`UIPackage.GetByName("Basics")` が null を返し、`GetPackages()` のリストにそのパッケージが含まれなくなること。

## 背景

`AddPackage` のすべてのオーバーロードは、最終的に `包名_fui` 記述ファイルを `byte[]` として読み込み、`ByteBuffer` を構築した後、`LoadPackage` がリソースリストを解析し、パッケージ id・パッケージ名(および assetPath)をキーとして `_packageInstById` / `_packageInstByName` / `_packageList` の 3 つの静的コレクションに登録します。`RemovePackage` は先に `Dispose` を行い、その後これら 3 つのコレクションから削除します([UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L334-L346) と [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L466-L475) を参照)。これが「パスに `_fui` を付けない」「重複ロードは自分でチェックする必要がある」といった規約の背後にある仕組みです。
