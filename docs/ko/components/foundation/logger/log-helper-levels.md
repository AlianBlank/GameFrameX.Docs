# LogHelper로 수준별 로그 출력하기

`LogHelper`는 `GameFrameX.Foundation.Logger` 네임스페이스 아래의 정적 클래스로, Serilog을 기반으로 Debug / Verbose / Info / Warning / Error / Fatal 총 6개 수준의 로그 출력 메서드를 제공합니다. 구조화된 템플릿, 콘솔 출력 및 예외 기록을 지원합니다. 이 페이지를 읽고 나면 자체 코드에서 수준에 따라 규약에 맞는 로그를 작성할 수 있습니다.

## 사전 조건

- .NET 프로젝트에서 `GameFrameX.Foundation.Logger` 어셈블리를 참조해야 합니다(Serilog은 전이 의존성으로 포함됨).
- 애플리케이션 시작 초기에 `LogHelper.SetLogger(...)`를 통해 설정된 `Serilog.ILogger`를 주입해야 합니다. 그렇지 않으면 `LogHelper`가 내장된 `InternalTempLogger`를 사용해 로그를 임시 저장하고, 정식 로거가 준비된 후 이를 플러시합니다.

## 작업 단계

### 1. 로거 초기화

```csharp
using GameFrameX.Foundation.Logger;
using Serilog;

var logger = new LoggerConfiguration()
    .MinimumLevel.Verbose()      // Verbose를 포함한 가장 낮은 수준의 로그 출력 허용
    .WriteTo.Console()
    .CreateLogger();

LogHelper.SetLogger(logger);
```

Source: [LogHelper.cs#L101-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.cs#L101-L112)

### 2. 수준에 맞는 메서드 호출

여섯 수준에 대한 진입 메서드의 이름은 수준 이름과 직접 대응하며, 시그니처는 일관됩니다: `(string messageTemplate, ...)` 또는 `(object message)`. 내부적으로 하위 `ILogger`의 동일한 이름 메서드에 위임합니다.

```csharp
using GameFrameX.Foundation.Logger;

// 디버그 / 상세 정보
LogHelper.Verbose("시작 단계:구성 로드 {ConfigName}", configName);
LogHelper.Debug("사용자 {Id}가 캐시를 적중함", userId);

// 일반 정보
LogHelper.Info("로그인 성공 user={Id} ip={Ip}", userId, ip);
LogHelper.Info(loginResult);

// 경고
LogHelper.Warning("API {Api} 응답 시간 {Ms}ms가 임계값 초과", apiName, elapsed);

// 오류
LogHelper.Error("주문 실패 orderId={Id}", orderId);

// 치명적 오류
LogHelper.Fatal("데이터베이스 연결 중단 {Conn}", connectionString);
```

### 3. 예외를 포함한 오류/치명적 오류 로그 기록

`Error` / `Fatal` 오버로드는 `Exception` 매개변수를 지원하며, 예외 객체를 로그 이벤트에 기록합니다:

```csharp
try
{
    DoWork();
}
catch (Exception ex)
{
    LogHelper.Error(ex, "실행 실패 task={Name}", taskName);
    // 또는 Fatal 수준
    LogHelper.Fatal(ex, "치명적 오류 task={Name}", taskName);
}
```

### 4. 콘솔에만 출력

파일에 기록하거나 Serilog을 거치지 않는 경우 `LogHelper.Console`을 사용합니다. 이 메서드는 밀리초 단위의 타임스탬프를 포함해 `System.Console`에 직접 기록합니다:

```csharp
LogHelper.Console("서버 시작 중...");
LogHelper.Console("리소스 {Count}개 로드, 소요 시간 {Ms}ms", count, ms);
```

### 5. 애플리케이션 종료 전 버퍼 플러시

프로그램을 종료하기 전에 `FlushAndSave()` 또는 `CloseAndFlushAsync()`를 호출해 버퍼의 로그를 파일에 기록합니다:

```csharp
LogHelper.FlushAndSave();
// 또는
await LogHelper.CloseAndFlushAsync();
```

## 6개 수준 빠른 참조표

| 수준 | 메서드 | 일반적인 용도 | Serilog 대응 메서드 |
|------|------|----------|------------------|
| Verbose | `LogHelper.Verbose(...)` | 가장 세밀한 추적 정보, 루프 내부 세부 정보 | `ILogger.Verbose` |
| Debug | `LogHelper.Debug(...)` | 디버깅 단계 진단 정보, 일반적으로 릴리스 버전에서는 비활성화 | `ILogger.Debug` |
| Info | `LogHelper.Info(...)` | 비즈니스 흐름의 핵심 지점(로그인, 주문, 종료) | `ILogger.Information` |
| Warning | `LogHelper.Warning(...)` | 복구 가능한 예외, 임계값 경고, 성능 저하 | `ILogger.Warning` |
| Error | `LogHelper.Error(...)` / `Error(Exception, ...)` | 비즈니스 실패, 포착된 예외 | `ILogger.Error` |
| Fatal | `LogHelper.Fatal(...)` / `Fatal(Exception, ...)` | 프로세스 수준의 치명적 오류, 복구 불가능 | `ILogger.Fatal` |

## 일반적인 변형

- **구조화된 속성 템플릿**: 각 수준에는 1~8개의 제네릭 오버로드가 있어 객체를 속성에 직접 바인딩합니다(문자열을 이어 붙이지 않음). 따라서 하위 Sink에서 필드별로 검색할 수 있습니다:
  ```csharp
  LogHelper.Info<Player>("현재 플레이어 {Current}", player);
  LogHelper.Info<Player, int>("플레이어 {Current}가 {Kills}명을 처치", player, kills);
  ```
  Source: [LogHelper.Info.cs#L87-L216](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L87-L216)

- **객체 매개변수**: `object`를 전달하면 `Info`가 `ToString()`을 호출하며, `null`인 경우 문자열 `"null object"`를 기록합니다:
  ```csharp
  LogHelper.Info(someObject); // someObject가 null이면 "null object" 출력
  ```
  Source: [LogHelper.Info.cs#L48-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHelper.Info.cs#L48-L51)

- **매개변수 없는 템플릿**: 메시지 템플릿만 제공하고 서식 값을 전달하지 않는 경우, 문자열을 직접 출력하는 것과 동일합니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `LogHelper.Info(...)`가 아무 내용도 출력하지 않음 | `LogHelper.SetLogger(...)`를 호출하지 않았고, `MinimumLevel`도 해당 수준을 허용하도록 설정하지 않음 | 시작 시 로거를 주입하고, 디버깅할 수 있도록 `MinimumLevel.Verbose()` 설정 |
| 프로세스 종료 시 로그 손실 | `FlushAndSave()` / `CloseAndFlushAsync()`를 호출하지 않음 | `OnExit` / `Main` 끝에서 위 메서드 중 하나를 호출 |
| 템플릿의 `{Name}`이 값으로 대체되지 않음 | 문자열에 불필요한 자리표시자를 사용했거나 매개변수 수가 일치하지 않음 | Serilog 표준 템플릿 구문 `{Property}`를 사용하고, 매개변수 수를 자리표시자와 일치시킴 |
| 파일 기록 위치를 확인하고 싶음 | 현재 메서드에서 경로를 직접 노출하지 않으므로 Serilog Sink를 직접 구성해야 함 | `LoggerConfiguration().WriteTo.File(...)`를 통해 직접 지정 |
| `null` 객체 기록 시 충돌 발생 | `Info(object)`만 `ToString()` 대체 처리를 수행하며, 다른 수준의 `null` 처리는 Serilog에 따라 달라짐 | 문자열 템플릿 버전을 사용하거나 직접 null 여부를 확인 |

## 배경 지식(선택 사항)

`LogHelper`는 `public static partial class`이며, 각 수준의 메서드는 `LogHelper.Debug.cs`와 같은 개별 파일에 분산되어 있습니다. 모든 메서드는 `GetLogger()`를 통해 현재 `Serilog.ILogger`를 가져옵니다. 아직 `SetLogger`가 호출되지 않은 경우 내부 `InternalTempLogger`를 사용해 로그를 임시 저장하고, 정식 로거가 주입될 때 `FlushTo`를 통해 전달하므로 **첫 로그 호출보다 초기화 순서를 엄격하게 먼저 둘 필요가 없습니다**. Level이 낮을수록 더 상세하며, 운영 환경에서는 일반적으로 `MinimumLevel`을 `Information`으로 설정하고 디버깅할 때 `Debug` 또는 `Verbose`로 낮춥니다. Serilog 전체 통합에 관한 내용은 《LogHandler로 로그 시스템을 초기화하는 방법》을 참조하십시오.
