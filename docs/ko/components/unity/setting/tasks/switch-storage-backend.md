# 스토리지 백엔드 변경

Setting 모듈의 키-값 스토리지를 기본 `UnityPlayerPrefsSettingStorage`에서 미니게임 플랫폼 SDK가 제공하는 스토리지 백엔드로 전환하여 설정 데이터가 미니게임 플랫폼 자체의 저장소에 기록되도록 합니다.

## 사전 조건

- `com.gameframex.unity.setting` 패키지와 의존성 GameFrameX Runtime이 설치되어 있어야 합니다.
- 대상 플랫폼이 미니게임(위챗/도우인/支付宝/快手 등)이고 해당 플랫폼의 adapter 어셈블리(`RegisterMiniGameBackend` 호출 포함)가 도입되어 있어야 합니다.
- Unity Editor에서 실행할 때는 미니게임 팩토리 분기를 거치지 않고 여전히 `UnityPlayerPrefsSettingStorage`를 사용하므로, 스토리지 로직을 검증하려면 대상 플랫폼으로 패키징하여 실행해야 합니다.

## 작업 단계

1. 커스텀 백엔드를 구현합니다. 미니게임 SDK는 일반적으로 `setStorageSync`/`getStorageSync` 인터페이스를 비동기로 제공하므로, 이를 `ISettingStorageBackend`로 감싸야 합니다. 최소 계약에는 `Save`, `HasKey`, `DeleteKey`, `DeleteAll`, `GetInt/SetInt`, `GetFloat/SetFloat`, `GetString/SetString`이 포함됩니다.

   Source: [ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs#L1-L30)

2. 팩토리 델리게이트를 구성하고 `SettingStorageBackendFactory`에 등록합니다. 게임 시작 단계(GameFrameX 프레임워크 초기화 이후, 첫 `SettingComponent.Save`/`Load` 이전)에 호출합니다:

   ```csharp
   using GameFrameX.Setting.Runtime;

   SettingStorageBackendFactory.RegisterMiniGameBackend(() => new WeChatMiniGameSettingStorage());
   ```

   등록 메서드는 `null`이 전달되면 `GameFrameworkException("Storage backend factory is invalid.")`을 던집니다.

   Source: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

3. 팩토리가 런타임에 백엔드를 선택합니다. `Create()`의 분기 로직은 다음과 같습니다:

   | 빌드 조건 | 사용 백엔드 |
   |----------|----------|
   | `UNITY_EDITOR` | `UnityPlayerPrefsSettingStorage` (고정) |
   | 플레이어 빌드이고 `s_MiniGameBackendFactory`가 등록됨 | 등록된 팩토리 반환값 |
   | 플레이어 빌드이지만 미등록 | `UnityPlayerPrefsSettingStorage`로 폴백 (오류 던지지 않음) |

   Source: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L32-L39)

4. `SettingHelperBase`의 구체적 구현이 해당 백엔드를 사용하도록 합니다. 패키지의 기본 `PlayerPrefsSettingHelper`는 이미 `UnityEngine.PlayerPrefs`를 직접 호출하고 있으므로, 크로스 플랫폼 환경에서는 `SettingStorageBackendFactory.Create()`가 반환한 객체에 위임하도록 다시 작성해야 합니다. 이렇게 하면 `PlayerPrefs`를 지원하지 않는 플랫폼(일부 미니게임 런타임)에서 API가 누락되는 문제를 피할 수 있습니다.

   Source: [UnityPlayerPrefsSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/UnityPlayerPrefsSettingStorage.cs#L9-L67)

## 일반적인 변형

- **공식 미니프로그램 SDK adapter**: `Runtime/MiniGame/` 디렉터리에 이미 위챗, 두우인, 支付宝, 快手 네 가지 adapter(`WeChatMiniGameSettingStorage.cs` 등)가 있으며, 각각 플랫폼 SDK 시작 시 `SettingStorageBackendFactory.RegisterMiniGameBackend`를 호출하여 자신의 구현을 등록합니다. 해당 adapter 어셈블리를 직접 도입하면 `ISettingStorageBackend`를 직접 구현할 필요가 없습니다.
- **암호화된 스토리지**: 커스텀 백엔드에서 `SetString` 시 AES로 암호화하고 `GetString` 시 복호화한 뒤 해당 백엔드를 등록합니다.
- **메모리/디버그 백엔드**: 단위 테스트나 디버그 시나리오에서는 메모리 딕셔너리에만 저장하는 구현을 등록할 수 있으며, 프로세스를 재시작할 때마다 자동으로 비워집니다.

## 일반적인 오류

- **`UNITY_EDITOR`에서 커스텀 백엔드가 적용되지 않는 현상**: `Create()`는 Editor에서 항상 `UnityPlayerPrefsSettingStorage`를 반환하므로 등록 로직이 실행되더라도 적용되지 않습니다. 대상 플랫폼 미니프로그램으로 패키징하여 실행해야 합니다.
- **등록 시점이 너무 늦음**: `SettingComponent.Save()` 또는 첫 `Load()` 이후에 `RegisterMiniGameBackend`를 호출하면 이미 캐시된 PlayerPrefs 백엔드가 교체되지 않습니다. `SettingManager`의 첫 디스크 쓰기보다 먼저 등록해야 합니다.
- **`null` 팩토리 등록**: 즉시 `GameFrameworkException("Storage backend factory is invalid.")`을 던지며 시작 프로세스가 중단됩니다. 전달 전에 null 검사를 수행하세요.
- **`PlayerPrefsSettingHelper` 미교체**: 비즈니스 로직이 동시에 `PlayerPrefsSettingHelper`를 사용하는 경우 이는 `UnityEngine.PlayerPrefs`를 직접 호출하므로, PlayerPrefs를 지원하지 않는 미니게임 런타임에서 컴파일/실행 오류가 발생합니다. 커스텀 Helper로 교체하거나 통합된 스토리지 접근 계층을 래핑해야 합니다.

## 배경 (선택 사항)

스토리지 백엔드 설계의 목적은 "어디에 저장할지"를 `SettingHelperBase` 파생 클래스에서 분리하는 것입니다. 플랫폼 SDK 통합 측이 `RegisterMiniGameBackend`를 통해 팩토리를 주입하면, `SettingStorageBackendFactory.Create()`가 런타임에 플랫폼별로 선택합니다. Editor는 디버깅 편의를 위해 항상 `UnityPlayerPrefsSettingStorage`로 폴백하며, 미등록 시에도 안전하게 폴백됩니다.
