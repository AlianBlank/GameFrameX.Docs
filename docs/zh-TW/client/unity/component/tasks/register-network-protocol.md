# 如何註冊網路協定訊息處理器

透過為繼承 `IMessageHandler` 的管理器類別套用 `[MessageHandler]` 特性，並在初始化時呼叫 `ProtoMessageHandler.Add(this)`,即可讓 GameFrameX 在收到對應協定時自動派發到目標方法，無須手動 `switch` 派發。

## 前置條件

- 已有一個從 `GameFrameX.Network.Runtime` 引入的協定訊息類別(由 Proto 產生，例如 `NotifyBagInfoChanged`)。
- 管理器類別繼承 `GameFrameworkSingleton<T>` 並實作 `IMessageHandler` 介面。

## 操作步驟

1. **讓管理器實作 `IMessageHandler` 並繼承單例基底類別**。整個類別只需要一個實例，網路層只會派發到這一個物件。

   ```csharp
   using GameFrameX.Network.Runtime;
   using GameFrameX.Runtime;

   namespace Hotfix.Manager
   {
       public sealed class BagManager : GameFrameworkSingleton<BagManager>, IMessageHandler
       {
           // ...
       }
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L16)

2. **在處理方法上套用 `[MessageHandler(typeof(消息类), nameof(消息类))]` 特性**。特性第一個參數指定協定訊息類型，第二個參數是日誌/偵錯用的描述名稱，與方法簽章一一對應。

   ```csharp
   /// <summary>
   /// 監聽道具變化通知
   /// </summary>
   /// <param name="msg"></param>
   [MessageHandler(typeof(NotifyBagInfoChanged), nameof(NotifyBagInfoChanged))]
   private void NotifyBagInfoChanged(NotifyBagInfoChanged msg)
   {
       // 處理訊息內容
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L29-L30)

3. **實作 `Register()` 並在其中呼叫 `ProtoMessageHandler.Add(this)`**。將目前管理器註冊到協定分發器，框架反射掃描時會讀取該實例上所有帶有 `[MessageHandler]` 特性的方法。

   ```csharp
   /// <summary>
   /// 註冊訊息。請勿多次呼叫
   /// </summary>
   public void Register()
   {
       ProtoMessageHandler.Add(this);
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L126-L129)

4. **在合適的時機呼叫一次 `Register()`**。一般在 `Awake` 或首次 `GetInstance()` 時觸發，例如：

   ```csharp
   private void Awake()
   {
       Register();
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L120)

## 常見變體

- **同一管理器處理多種協定**：每個方法分別套用一個 `[MessageHandler(typeof(不同消息), nameof(不同消息))]`,`ProtoMessageHandler.Add(this)` 只需呼叫一次即可註冊全部方法。`PlayerAttributeManager` 同時處理 `NotifyPlayerAttributeSync` 和 `NotifyPlayerAttributeChanged` 就是這種用法。([PlayerAttributeManager.cs#L79](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L79)、[PlayerAttributeManager.cs#L109](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L109))

- **不同管理器處理不同協定**：每個管理器各自實作 `IMessageHandler`、各自 `Register()`,互不影響。例如 `RoomDataManager` 處理 `NotifyRoomChanged`、`RockPaperScissorsDataManager` 處理猜拳相關協定。([RoomDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RoomDataManager.cs#L16)、[RockPaperScissorsDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RockPaperScissorsDataManager.cs#L16))

## 常見錯誤

- **忘記在 `Register()` 裡呼叫 `ProtoMessageHandler.Add(this)`**:特性只是中繼資料，不會自動生效，會導致訊息到達但沒有任何方法被呼叫。
- **重複呼叫 `Register()`**:註解明確寫了「請勿多次呼叫」，同一實例多次註冊會重複派發。
- **方法簽章與特性裡的訊息類型不相符**:`[MessageHandler(typeof(X), ...)]` 的 `X` 必須與方法參數類型完全一致，否則反射繫結失敗。
- **把 `Register()` 放在建構函式裡**:`GameFrameworkSingleton` 在建構時其他子系統未必初始化完成，建議放在 `Awake` 或明確 `GetInstance().Register()` 的時機呼叫。

## 背景(選擇性)

`[MessageHandler]` 是基於反射的協定路由標記，框架在收到協定封包後，會從透過 `ProtoMessageHandler.Add(this)` 註冊進來的實例集合查表派發，所以每個處理器只需要一個實例，這也是它繼承 `GameFrameworkSingleton` 的原因。
