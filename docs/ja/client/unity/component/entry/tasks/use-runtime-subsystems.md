# エンティティ、コルーチン、サウンド、シーン、Mono 管理の使用方法

`GameFrameX` は `GameApp` スタティックファサードを通じて、エンティティ、コルーチン、サウンド、シーン、Mono などの各ランタイムサブシステムコンポーネントを遅延読み込み方式で公開しています。各サブシステムは `GameEntry.GetComponent<T>()` で取得されるコンポーネントインスタンスに対応しており、使用時はコード内で `GameApp.{サブシステム名}` にアクセスするだけで済みます。本ページではこれらのサブシステムの組み込み方法と典型的な使い方を説明します。

## 前提条件

1. `com.gameframex.unity.entry` パッケージがインストール済みであり、シーンに `GameEntry` ランチャーがアタッチされていること。
2. Package Manager を通じて各サブシステムに対応するランタイムパッケージがインストール済みであること:
   - `com.gameframex.unity.entity`(エンティティ)
   - `com.gameframex.unity.coroutine`(コルーチン)
   - `com.gameframex.unity.sound`(サウンド)
   - `com.gameframex.unity.scene`(シーン)
   - 組み込みの Mono マネージャーは entry パッケージに同梱されています
3. プロジェクトで対応する有効化マクロが定義済みであること:`ENABLE_GAME_FRAME_X_ENTITY`、`ENABLE_GAME_FRAME_X_COROUTINE` など(各コンポーネントのソースコードは `#if` でガードされており、マクロがない場合は関連フィールドがコンパイルされません。下記の「よくあるエラー」を参照)。

## 操作手順

### 1. GameApp を通じてサブシステムにアクセスする

すべてのサブシステムは `GameApp` クラス内で `public static {コンポーネントクラス} {サブシステム名}` の形式で公開され、初回アクセス時に `GameEntry.GetComponent<T>()` を通じて作成・キャッシュされます。手動での `new` や登録は不要です。

```csharp
using GameFrameX.Runtime;

public static partial class GameApp
{
    public static EntityComponent Entity
    {
        get
        {
            if (_entity == null)
            {
                _entity = GameEntry.GetComponent<EntityComponent>();
            }
            return _entity;
        }
    }

    private static EntityComponent _entity;
}
```

Source: [Runtime/GameApp.Entity.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Entity.cs#L36-L55)

コルーチンコンポーネントもまったく同じパターンを採用しています:

```csharp
using GameFrameX.Runtime;
using GameFrameX.Coroutine.Runtime;

public static partial class GameApp
{
    public static CoroutineComponent Coroutine
    {
        get
        {
            if (_coroutine == null)
            {
                _coroutine = GameEntry.GetComponent<CoroutineComponent>();
            }
            return _coroutine;
        }
    }

    private static CoroutineComponent _coroutine;
}
```

```csharp
// エンティティ
var entityComponent = GameApp.Entity;

// コルーチン
var coroutineComponent = GameApp.Coroutine;
```

### 2. エンティティ(Entity)の使用ポイント

`GameApp.Entity` を通じて `EntityComponent` を取得した後、フレームワークが提供するエンティティの作成、検索、破棄のインターフェースを使用できます。エンティティのライフサイクルは `EntityComponent` によって統一的に管理され、通常は `Entity` 基底クラスおよび `EntityLogic` ロジックスクリプトと併用されます。詳細なインターフェースのシグネチャは `EntityComponent` のソースコードを基準としてください。本リポジトリはその実装を直接保持していないため、`com.gameframex.unity.entity` パッケージ内のドキュメントを参照する必要があります。

### 3. コルーチン(Coroutine)の使用ポイント

`GameApp.Coroutine` を通じて `CoroutineComponent` を取得し、任意の非 MonoBehaviour コンテキストでコルーチンタスクを開始できます。コルーチンコンポーネントは内部的に Unity の `Coroutine` 機構をラップしており、非 Mono クラスでも安全に遅延処理やフレーム分割処理を開始できます。呼び出しエントリは通常以下の形になります:

```csharp
GameApp.Coroutine.StartCoroutine(MyRoutine());

GameApp.Coroutine.StopCoroutine(handle);
```

具体的なオーバーロードは `CoroutineComponent` のソースファイルを基準としてください。

### 4. サウンド(Sound)の使用ポイント

サウンドサブシステムも同様のスタティックファサードエントリを使用します。リポジトリ内の `Runtime/GameApp.Sound.cs` は `#if` ガードを通じて `GameApp.Sound` を提供し、`SoundComponent` インスタンスを返します。よく使う操作には BGM の再生、効果音の再生、一時停止/再開、音量設定などがあります。具体的な API は `SoundComponent` の実装を基準としてください。

```csharp
// あくまで例です:実際のシグネチャは SoundComponent を参照
GameApp.Sound.PlayMusic(musicId);
GameApp.Sound.PlaySound(soundId);
```

### 5. シーン(Scene)の使用ポイント

`Runtime/GameApp.Scene.cs` も同様に `GameApp.Scene` として `SceneComponent` を公開しています。このコンポーネントを通じてシーンの読み込み・アンロード、および現在読み込み済みのシーンリソース情報の取得が可能です。典型的なフロー:シーンリソース名を渡す → 非同期読み込みをトリガー → 読み込み完了後にアタッチしてアクティブシーンを切り替える。

```csharp
// あくまで例です
GameApp.Scene.LoadScene("MainCity", onComplete: () => { /* シーン遷移完了 */ });
```

### 6. Mono 管理の使用ポイント

`Mono` マネージャーは、非 MonoBehaviour クラスで `Mono` と同様の機能(ポーリング、コルーチン、タイマーなど)を獲得するために使用され、`GameApp.Coroutine` と連携して動作します。`GameApp` 上の Mono 関連プロパティを通じて直接取得でき、その後 `Update`/`OnDestroy` などのライフサイクルフックを `MonoBehaviour` を継承せずに呼び出せます。

## よくあるバリエーション

- **クロスプラットフォームでのトリミング**:各 `GameApp.*.cs` は `#if ENABLE_GAME_FRAME_X_{NAME}` 条件コンパイルを使用しており、プロジェクトの `csc.rsp` または `Player Settings` で必要に応じてサブシステムを有効/無効にできます。無効にすると対応する `GameApp.{Name}` フィールドは消えます。
- **依存性注入への拡張**：スタティックファサードを使用したくない場合は、`GameEntry.GetComponent<EntityComponent>()` などを直接呼び出して元のコンポーネント参照を取得できます。両者は等価です。
- **一部サブシステムの命名差異**：一部のバージョンでは `MonoManager` ではなく `Mono` という名前が使用されている場合があります。現在のランタイムパッケージのバージョンのソースコードを基準としてください。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GameApp.Entity` / `GameApp.Coroutine` などのプロパティが存在しない | 対応するサブシステムパッケージがインストールされていない、または `ENABLE_GAME_FRAME_X_ENTITY` / `ENABLE_GAME_FRAME_X_COROUTINE` などのマクロが定義されていない | Package Manager で対応するパッケージをインストールし、プロジェクトの `csc.rsp` または `Scripting Define Symbols` にマクロ定義を追加する |
| 呼び出し時に `null` が返される、または null 参照例外がスローされる | シーンに `GameEntry` がアタッチされていない、またはサブシステムが `GameEntry` 上にコンポーネントとして登録されていない | 起動シーンに `GameEntry` プレハブを追加し、Inspector で対象コンポーネントにチェックが入っていることを確認する |
| コルーチンが実行されない | `StartCoroutine` 呼び出し時に渡したメソッドが `IEnumerator` を返していない、または `Mono` コンテキストが破棄された後に呼び出している | メソッドのシグネチャを確認し、既に破棄されたオブジェクト上でコルーチンを開始しないようにする |
| サウンド/シーンのインターフェースが見つからない | サブシステムパッケージが現在の entry パッケージと一致するバージョンにアップグレードされていない | 対応するランタイムパッケージをアップグレードするか、対象バージョンの `SoundComponent` / `SceneComponent` の実際のシグネチャを参照する |

## 背景(任意)

`GameApp` は `partial class` であり、各サブシステムは `Runtime/GameApp.{Name}.cs` ファイルに対応し、それぞれ `#if` でガードされ、互いに結合していません。その目的は必要に応じてパッケージサイズをトリミングすることです。すべてのコンポーネントは `GameEntry.GetComponent<T>()` の遅延読み込みパターンを通じて取得され、初回アクセス時に `GameEntry` によってインスタンス化され、`GameApp` のプライベート静的フィールドにキャッシュされます。以降の呼び出しではキャッシュが直接返されるため、グローバルな一意性を保証すると同時に、モジュールの読み込み順序の問題も回避できます。
