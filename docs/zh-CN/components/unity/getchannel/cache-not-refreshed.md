# 修改渠道配置后读到的还是旧值怎么办

当你修改了 `application_config.txt`、AndroidManifest 的 meta-data 或 iOS 的 Info.plist,但 `BlankGetChannel.GetChannelName()` 仍返回旧值时,几乎都是两类原因:进程内的静态缓存 `ChannelCache` 命中后不再重新读取,或配置已在构建时被打进包里、改磁盘文件对已构建的应用无效。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| Editor/PC/WebGL 下改了 `application_config.txt`,`GetChannelName()` 仍返回旧值 | 静态字典 `ChannelCache` 命中后直接返回,不再读文件 | 退出 Play Mode 重新进入(触发脚本域重载),见下文「清空进程内缓存」 |
| Editor 中改了文件、重启 Play Mode 后仍旧值 | Unity 尚未重新导入该 TextAsset,`Resources.Load` 拿到的还是旧资源 | 切回 Editor 窗口等待重新导入,或右键该文件 `Reimport`,再进入 Play Mode |
| 打包(Standalone/WebGL)后修改了配置文件,App 内渠道不变 | `Resources/application_config.txt` 在构建时已固化进包 | 修改 `Assets/Resources/application_config.txt` 后重新构建并覆盖安装 |
| Android 上改了 AndroidManifest 的 meta-data 没生效 | meta-data 已编译进 APK,且首次读取结果已入缓存 | 修改 manifest 后重新出包安装;运行期内无法刷新 |
| iOS 重新构建后渠道还是 `default` 或旧值 | `PostProcessBuildHandler` 只在 Info.plist 中**不存在** `channel` 键时才写入,已有值会跳过 | 在 Xcode 中删除或修改 Info.plist 的 `channel` 键后重新构建,见下文 |
| iOS 上未配置键时返回 `unknown` 而不是 C# 侧的 `default` | 原生 `getChannelName` 找不到键时固定返回 `unknown` | 在 Info.plist 中补上对应键 |
| 配置值里含 `=`,读出来的值被截断 | 解析按 `=` 分段后只取第二段 | 值中避免使用 `=`,见下文「值被截断」 |

## 修复步骤

### 清空进程内缓存(最常见的根因)

`GetChannelName` 的第一件事就是查静态缓存,命中即返回,后面的读取逻辑完全跳过:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
{
    if (ChannelCache.TryGetValue(channelKey, out var value))
    {
        return value;
    }

    string channelName = defaultValue;
    ...
    ChannelCache[channelKey] = channelName;
    return channelName;
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98-L141)

缓存字典是 `private static readonly`,仓库中没有提供任何清空缓存的公开 API,所以**运行期内无法刷新**,只能让静态字段随域/进程一起重建:

1. Editor 中:退出 Play Mode → 等待编译/域重载完成 → 重新进入 Play Mode 再读取。
2. 真机/独立版:退出应用进程后重新启动(仅解决缓存问题;若配置本身在包内,还需按下面的小节重新出包)。

另注意一个副作用:在 Editor/PC 分支下,首次读取会把 `application_config.txt` 里**所有** `key=value` 一次性写入缓存(见 [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L107-L121))。因此改完文件后,哪怕换一个 channelKey 查询,拿到的仍是首次加载时的旧内容。

### Editor/PC/WebGL:让 Resources 重新加载

这些平台读取的是 `Resources.Load<TextAsset>("application_config")`,即 `Assets/Resources/application_config.txt`:

1. 确认文件路径为 `Assets/Resources/application_config.txt`(无扩展名也能加载,内容按行 `key=value`)。
2. 修改保存后,点击 Unity 窗口触发重新导入(或右键文件 → `Reimport`)。
3. 按「清空进程内缓存」重启 Play Mode。
4. 已构建的包:磁盘上改文件无效,必须改 `Assets/Resources/application_config.txt` 后重新构建。

### Android:修改 meta-data 后重新出包

Android 渠道来自原生类的静态调用,首次结果同样进入缓存:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

修改 AndroidManifest.xml 中对应 meta-data 后,需要重新构建 APK/AAB 并覆盖安装;进程内不会自动刷新。

### iOS:处理 PostProcessBuild 的「跳过设置」

iOS 构建后处理只在 Info.plist 缺少 `channel` 键时写入 `default`,已有值则直接跳过:

```csharp
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

想换渠道值时:在 Xcode 工程的 Info.plist 中直接修改或删除 `channel` 键(删除后由该处理逻辑重新写入),再重新构建到真机。同时注意原生层缺省返回值是 `unknown`:

```objc
char * getChannelName(char * channel_name) {
    NSString* channel_name_String=  [NSString stringWithUTF8String:channel_name];
    NSString* File = [[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"];
    NSMutableDictionary* dict = [[NSMutableDictionary alloc] initWithContentsOfFile:File];
    NSString * channel_value =  [dict objectForKey:channel_name_String];
    if (channel_value != nil) {
        return StringToCharArray(channel_value);
    }
    channel_value = @"unknown";
    return StringToCharArray(channel_value);
}
```

Source: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

### 值被截断:检查配置行格式

解析逻辑对每行按 `=` 切分后只取第二段并 `Trim()`:

```csharp
var split = line.Split(new string[] { "=" }, StringSplitOptions.RemoveEmptyEntries);
if (split.Length > 1)
{
    var key = split[0].Trim();
    var channelValue = split[1].Trim();
    ChannelCache[key] = channelValue;
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120)

`channel=a=b` 会被解析成 `a`。把值里的 `=` 去掉(或改用其他分隔字符的编码方式)后,按「清空进程内缓存」重启再验证。

## 验证

1. 在修改配置并重启 Play Mode / 重新出包后,调用:

```csharp
string channel = BlankGetChannel.GetChannelName();
string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

2. 确认返回值与配置文件中新值一致;iOS 上键缺失时应观察到 `unknown`(而非 C# 默认参数 `default`)。
3. 若仍旧值,优先怀疑缓存未清(重启 Play Mode / 进程),其次怀疑读的不是你以为的那份配置(Editor 看 `Assets/Resources/application_config.txt`,Android 看 manifest meta-data,iOS 看 Info.plist)。
