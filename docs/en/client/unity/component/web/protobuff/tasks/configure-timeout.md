# Timeout and Connection Count Configuration Guide

This page explains how to configure the **request timeout** and **maximum connections per server** for the Web ProtoBuff network module. The timeout defaults to `5f` seconds and can be adjusted either with a slider in the Inspector (0–120 seconds) or modified at runtime via code; `MaxConnectionPerServer` defaults to `8`, has no Inspector field, and can only be set in code through the manager.

## Prerequisites

- The `com.gameframex.unity.web.protobuff` package is installed;
- A GameObject with the **Web ProtoBuff** component (`AddComponentMenu("GameFrameX/Web ProtoBuff")`) exists in the scene.

## Configuration Quick Reference

| Option | Type / Default Value | How to Configure |
|--------|--------------|----------|
| `Timeout` | `float`, in seconds, default `5f` | Inspector slider (0–120), component property, manager property |
| `RequestTimeout` | `TimeSpan`, automatically synced from `Timeout` (`TimeSpan.FromSeconds(value)`) | Manager property, can be assigned directly |
| `MaxConnectionPerServer` | `int`, default `8` (set in the constructor) | Code only, set via `IWebProtoBuffManager` |

## Steps

### Method 1: Set the Timeout in the Inspector

1. In the scene, select the GameObject with the **Web ProtoBuff** component;
2. In the component's custom Inspector, drag the `Timeout` slider; the valid range is `0f`–`120f` seconds;
3. The value is written to the serialized field `m_Timeout` and applied to the manager by `Awake` when the game starts.

The editor slider implementation:

```csharp
float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
```

Source: [WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Editor/Inspector/WebComponentInspector.cs#L23)

The corresponding serialized field on the component side:

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;

public float Timeout
{
    get { return m_WebProtoBuffManager.Timeout; }
    set { m_WebProtoBuffManager.Timeout = m_Timeout = value; }
}
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L60-L71)

### Method 2: Modify at Runtime via Code

Modify the timeout via the component property (writes back to both the serialized field and the manager):

```csharp
var component = GetComponent<GameFrameX.Web.ProtoBuff.Runtime.WebProtoBuffComponent>();
component.Timeout = 15f;
```

### Method 3: Set the Maximum Connection Count

`MaxConnectionPerServer` is not exposed as a serialized field on the component; it must be set in code through the module interface:

```csharp
var manager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<GameFrameX.Web.ProtoBuff.Runtime.IWebProtoBuffManager>();
manager.MaxConnectionPerServer = 16;
manager.Timeout = 10f;
```

`GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` is exactly how the component obtains the manager instance in `Awake`:

```csharp
m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
if (m_WebProtoBuffManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebProtoBuffManager.Timeout = m_Timeout;
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L82-L90)

## Common Variants

- **Need sub-second or TimeSpan-precision timeouts**: Set the manager's `RequestTimeout` (type `TimeSpan`) directly. Note that setting `Timeout` (float seconds) automatically overwrites `RequestTimeout`:

```csharp
// Timeout duration (seconds)
private float m_Timeout = 5f;

/// <summary>Get or set the timeout duration (seconds)</summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>Get or set the maximum connections per server</summary>
public int MaxConnectionPerServer { get; set; }

/// <summary>Get or set the request timeout</summary>
public TimeSpan RequestTimeout { get; set; }
```

Source: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L20-L54)

- **Restore factory defaults**: The manager's constructor sets `MaxConnectionPerServer = 8; Timeout = 5f;` by default; simply change the two properties back to these values.

Source: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L27-L31)

## Common Mistakes

| Symptom | Cause | Fix |
|------|------|------|
| The `Timeout` set in code "doesn't take effect" after startup | Another script's initialization runs first, then the component's `Awake` executes `m_WebProtoBuffManager.Timeout = m_Timeout`, overwriting the code-set value with the serialized Inspector value | Modify it after the component's `Awake`, or change the value directly in the Inspector |
| `MaxConnectionPerServer` can't be found in the Inspector | It is not a serialized field of the component; it only exists on the manager | Set it in code with `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` |
| Want to set a timeout longer than 120 seconds, but the slider won't go further | The editor slider's range is hardcoded to `0f`–`120f` | Use code instead: `component.Timeout = 150f;` |
| Changed `RequestTimeout` directly, but it is quickly overridden | Any subsequent assignment to `Timeout` overwrites `RequestTimeout` with `TimeSpan.FromSeconds(value)` | Adjust only through `Timeout`, or set `RequestTimeout` last |

## Verification

- After modifying, read `component.Timeout` / `manager.Timeout` to confirm the new value is returned;
- After `manager.Timeout = x`, read `manager.RequestTimeout`; it should equal `TimeSpan.FromSeconds(x)`.

## Background

`Timeout` is the unified external "seconds"-based configuration entry point: setting it also generates the `TimeSpan`-form `RequestTimeout` used by the request side; `MaxConnectionPerServer` represents the maximum number of connections per server, defaulting to 8. For the module's overall structure, see the overview page.
