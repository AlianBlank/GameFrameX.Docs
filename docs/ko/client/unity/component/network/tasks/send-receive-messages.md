# 네트워크 메시지 송수신(메시지 정의 및 핸들러 등록)

GameFrameX Network에서 메시지를 송수신하려면 세 단계만 거치면 됩니다: `MessageObject`를 상속하는 메시지 클래스를 정의하고, 해당 `IPacket*Handler` 인터페이스를 구현하는 핸들러 클래스를 작성하고, `INetworkChannel.Send(...)`를 통해 전송합니다. 핸들러는 **수동으로 등록할 필요가 없습니다** — `DefaultNetworkChannelHelper.Initialize`가 리플렉션으로 어셈블리를 스캔하여 자동으로 `RegisterHandler`를 호출해 등록을 완료합니다.

## 사전 조건

- 네트워크 채널이 생성되어 연결된 상태여야 합니다(`NetworkManager` 준비 완료).
- 메시지 기본 클래스 `MessageObject`는 프레임워크 기반 라이브러리에서 제공되며, 본 패키지의 직렬화 제약은 `where T : MessageObject`입니다.
- 핸들러 클래스는 **비추상 class**여야 하고, 마커 인터페이스 `IPacketHandler`를 구현해야 하며, public 매개변수 없는 생성자를 제공해야 합니다(리플렉션에서 `Activator.CreateInstance`로 인스턴스화).

## 작업 단계

1. **메시지 클래스 정의**: 메시지가 `MessageObject`를 상속받게 합니다. 채널 내부에서 관리하는 송신 큐가 바로 `GameFrameworkLinkedList<MessageObject>`이며, 직렬화 진입점의 제네릭 제약도 `MessageObject`입니다:

   ```csharp
   public bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject
   ```

   > 본 저장소에는 네트워크 컴포넌트 자체만 포함되어 있으며, 구체적인 게임 측 메시지 정의(예: protobuf 메시지 클래스)는 포함되어 있지 않으므로 게임 프로젝트에서 직접 정의해야 합니다.

2. **핸들러 구현**: 송수신 단계에 따라 구현할 인터페이스를 선택합니다. 모든 핸들러는 마커 인터페이스 `IPacketHandler`를 구현해야 합니다([IPacketHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketHandler.cs#L4)에 정의되어 있으며, 주석은 "네트워크 메시지 패킷 핸들러를 식별하기 위한 마커 인터페이스"라고 명시):

   | 인터페이스 | 등록 API(리플렉션으로 자동 호출) | 담당 작업 |
   |------|---------------------------|------|
   | `IPacketReceiveHeaderHandler` | `RegisterHandler(IPacketReceiveHeaderHandler)` | 수신 패킷 헤더 파싱 |
   | `IPacketReceiveBodyHandler` | `RegisterHandler(IPacketReceiveBodyHandler)` | 패킷 본문을 `MessageObject`로 역직렬화 |
   | `IPacketSendHeaderHandler` | `RegisterHandler(IPacketSendHeaderHandler)` | 패킷 헤더 직렬화 |
   | `IPacketSendBodyHandler` | `RegisterHandler(IPacketSendBodyHandler)` | 패킷 본문 직렬화 |
   | `IPacketHeartBeatHandler` | `RegisterHeartBeatHandler(IPacketHeartBeatHandler)` | 하트비트 패킷 생성/검증 |
   | `IMessageCompressHandler` / `IMessageDecompressHandler` | `RegisterMessageCompressHandler` / `RegisterMessageDecompressHandler` | 패킷 본문 압축/해제 |

   패키지 내에 기본 구현이 이미 제공되므로 직접 상속하거나 교체할 수 있습니다: [DefaultPacketReceiveHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveHeaderHandler.cs#L9), [DefaultPacketReceiveBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveBodyHandler.cs#L7), [DefaultPacketSendHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendHeaderHandler.cs#L10), [DefaultPacketSendBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendBodyHandler.cs#L9), [BasePacketHeartBeatHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/BasePacketHeartBeatHandler.cs#L7).

3. **자동 등록 확인**: 채널 초기화 시 `DefaultNetworkChannelHelper.Initialize`가 모든 어셈블리 타입을 스캔하며, `IPacketHandler`를 구현한 비추상 클래스는 모두 인스턴스화되어 채널에 등록됩니다:

   ```csharp
   var types = Utility.Assembly.GetTypes();
   foreach (var type in types)
   {
       if (!type.IsClass || type.IsAbstract)
       {
           continue;
       }

       if (!type.IsImplWithInterface(packetHandlerBaseType))
       {
           continue;
       }

       if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
       {
           var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       else if (type.IsImplWithInterface(packetReceiveBodyHandlerBaseType))
       {
           var handler = (IPacketReceiveBodyHandler)Activator.CreateInstance(type);
           InjectChannelSerializer(handler, type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       // ...이후 SendHeader / SendBody / HeartBeat / Compress / Decompress 순으로 매칭
   }
   ```

   출처: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L73-L107)

4. **메시지 전송**: 채널의 `Send` 메서드를 호출합니다. 패키지 내 하트비트의 전송 방식이 바로 표준 사용법입니다:

   ```csharp
   public bool SendHeartBeat()
   {
       if (m_NetworkChannel == null)
       {
           return false;
       }

       var message = m_NetworkChannel.PacketHeartBeatHandler.Handler();
       m_NetworkChannel.Send(message);
       return true;
   }
   ```

   출처: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L146-L156)

5. **메시지 수신**: 패킷 수신 후 수신 핸들러 체인이 파싱을 완료하며, 수신 패킷 본문은 `messageId`에 따라 구체적인 `MessageObject`로 역직렬화되어 복원됩니다:

   ```csharp
   public bool DeserializePacketHeader(byte[] source)
   public bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)
   ```

   출처: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L179-L189)

6. **(선택) 네트워크 이벤트 수신 대기**: 연결, 종료, 하트비트 유실 및 오류 이벤트는 Helper가 이미 통합 구독하고 있으며(`NetworkConnectedEventArgs`, `NetworkClosedEventArgs`, `NetworkMissHeartBeatEventArgs`, `NetworkErrorEventArgs`), 게임 측에서 이벤트 컴포넌트를 통해 구독하면 됩니다. [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128) 참조.

## 일반적인 변형

## 일반적인 변형

- **커스텀 하트비트**: `BasePacketHeartBeatHandler`를 상속하고(`IPacketHeartBeatHandler`와 `IPacketHandler`를 동시에 구현), `Handler()`가 하트비트 메시지 객체를 반환하도록 구현하면 됩니다. 하트비트 전송 시 `m_NetworkChannel.Send(message)`가 호출되며, 일반 메시지와 동일합니다.
- **커스텀 압축**: `IMessageCompressHandler` / `IMessageDecompressHandler`를 각각 구현하고 `IPacketHandler` 마커를 추가하면, 등록 후 `SerializePacketHeader` / `DeserializePacketBody` 흐름에서 자동으로 호출됩니다. 기본 구현은 [DefaultMessageCompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageCompressHandler.cs#L10)와 [DefaultMessageDecompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageDecompressHandler.cs#L10)를 참조하세요.
- **수동 핸들러 등록**: `INetworkChannel`은 각 `RegisterHandler` 오버로드도 노출합니다(`[Obsolete("Use RegisterHeartBeatHandler instead")]`로 표시된 하트비트 오버로드 포함). [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L150-L181) 참조.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 핸들러가 전혀 호출되지 않음 | 클래스가 추상 클래스이거나 `IPacketHandler` 마커 인터페이스를 구현하지 않아 리플렉션 스캔에서 `continue`로 건너뜀 | 클래스를 비추상으로 선언하고 `IPacketHandler`를 추가 |
| 런타임에 핸들러 인스턴스화 시 예외 발생 | 리플렉션이 `Activator.CreateInstance(type)`를 사용하는데 public 매개변수 없는 생성자가 없음 | 핸들러에 public 매개변수 없는 생성자 추가 |
| 하나의 클래스가 잘못된 등록 분기에 매칭됨 | 등록은 `ReceiveHeader → ReceiveBody → SendHeader → SendBody → HeartBeat → Compress → Decompress` 순서의 `if / else if`에서 **첫 번째 매칭**을 사용함 | 각 클래스가 하나의 처리 인터페이스만 구현하도록 여러 클래스로 분할 |
| 송신/수신 패킷 헤더·본문 파싱 동작이 예상과 다름 | 직렬화기 주입 누락(`ReceiveBody`, `SendHeader` 분기에서만 `InjectChannelSerializer(handler, type)` 호출됨) | 해당 핸들러에 채널 직렬화기를 구성하거나 패키지 내 기본 핸들러를 직접 사용 |
| 직렬화 호출에서 인수 null 예외 발생 | `SerializePacketHeader` / `SerializePacketBody` 내부에서 `m_NetworkChannel`, `PacketSendHeaderHandler`, `PacketSendBodyHandler`, `messageObject`, `destination`에 대해 `GameFrameworkGuard.NotNull` 검증 수행 | 핸들러 등록을 먼저 완료한 후 전송하고, 메시지와 대상 스트림이 null이 아닌지 확인 |

## 검증

- 송신 측: 채널 통계 속성 `SendPacketCount` / `SentPacketCount`(송신 큐 수량 / 이미 전송된 수량)를 관찰합니다. Unity Inspector 패널에는 "Send Packet"으로 표시됩니다. [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L108) 참조.
- 수신 측: `IPacketReceiveBodyHandler` 구현에 중단점을 설정하고, `DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)`가 콜백되며 `messageObject`가 성공적으로 복원되는지 확인합니다.

## 배경

설계상 패킷 송수신 처리는 "헤더 / 본문" 두 단계로 분리되어 있으며, 송수신 방향도 각각 독립적인 인터페이스로 구성됩니다. 전송 시 `SerializePacketHeader`가 헤더를 쓰고 패킷 본문 버퍼를 생성한 뒤, `SerializePacketBody`가 본문을 기록합니다. 수신은 반대로 `DeserializePacketHeader` → `DeserializePacketBody` 순으로 실행됩니다. 마커 인터페이스 `IPacketHandler`는 어셈블리 리플렉션과 결합하여, 새로 추가되는 메시지와 핸들러가 프레임워크 코드 수정 없이 자동으로 연결되도록 합니다([DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L60-L71) 참조). 채널 계층의 송신 큐 및 핸들러 등록 구현은 [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L525-L572)에 위치합니다.
