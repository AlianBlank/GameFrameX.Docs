# How to Determine Whether an Image Has Been Cached

Use `IsCached(string url)` to check whether the image at the specified URL has already been downloaded to the local cache. A cache hit avoids redundant network requests. The WebGL platform always returns `false`; on other platforms, the MD5 hash of the URL is used as the file name to check whether the cache file exists.

## Prerequisites

- `ImageCacheComponent` has been attached to the game framework's component manager (or you hold an `IImageCacheManager` instance).
- The current build platform is **not WebGL** (caching is meaningless under WebGL, and the method always returns `false`).

## Steps

1. Obtain the cache component instance:

```csharp
var cache = GameEntry.GetComponent<ImageCacheComponent>();
```

2. Call `IsCached` and pass in the remote image address:

```csharp
string url = "https://example.com/avatar.png";
bool cached = cache.IsCached(url);
if (cached)
{
    // Cache hit, proceed with local loading logic or skip the download prompt
}
else
{
    // Go through the download process, e.g. cache.LoadImageAsync(url)
}
```

3. The same method is exposed on `IImageCacheManager`, and can be called directly through the interface:

```csharp
IImageCacheManager manager = cache;
bool cached = manager.IsCached(url);
```

See the interface signature in `IImageCacheManager.cs` line 34, the implementation in `ImageCacheManager.cs` line 180, and the component wrapper in `ImageCacheComponent.cs` line 83.

## Common Variations

- **Passing an empty URL**: `IsCached(string url)` returns `false` directly when `url` is `null` or an empty string, and does not throw an exception.
- **WebGL platform**: Controlled by the `#if UNITY_WEBGL` compile branch, it returns `false` regardless of whether the file has been downloaded — do not use this to judge "not cached".
- **Combined with async loading**: You can call `IsCached` before `LoadImageAsync` to provide UI placeholders or progress hints, avoiding blank flickering.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `IsCached` always returns `false` under WebGL | WebGL does not support local file caching; the source code fixedly returns `false` | Skip this check under WebGL or treat it as the "not cached" path |
| Different determination results for the same URL with different size/crop parameters | The cache uses the MD5 of the **original URL** as the key; URLs with query strings are treated as different resources | Keep the URL string consistent with what was used during download |
| Old files become invalid after modifying the `CachePath` configuration | The path has changed, and old cache files are not in the new path | Clean up the old directory or migrate before checking |

## Background (Optional)

The implementation lives in `ImageCacheManager.cs`. At its core, `Utility.Hash.MD5.Hash(url)` is combined with `Utility.Const.FileNameSuffix.PNG` to compose the cache path, and then `FileHelper.IsExists` is used to check file existence. The check is synchronous, pure local I/O, with very low overhead — suitable for being called up front in UI logic.
