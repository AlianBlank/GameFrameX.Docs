# 생성 후 TbXxx 클래스를 찾을 수 없는 경우

`gen-client-json.bat` / `gen-client-json.sh`를 실행한 후 Unity 또는 .NET 프로젝트에서 `TbMyItem`, `TbAchievement` 같은 클래스를 찾을 수 없다면—대개는 도구가 고장 난 것이 아니라 파일명, 생성 스크립트 또는 출력 디렉터리가 맞지 않는 경우입니다. 이 페이지에서는 오류 증상별로 진단표와 복구 단계를 안내합니다.

## 빠른 진단

| 증상 | 원인 | 복구 |
|------|------|------|
| `TbXxx` 클래스를 전혀 찾을 수 없고, 출력 디렉터리에도 해당 `.cs` 파일이 없음 | Excel 파일명이 `字母-英文名-中文名.xlsx` 규칙에 맞지 않아 도구가 인식하지 못함 | 「복구 단계 1」 참조 |
| `不支持中文表名` 또는 `table name invalid` 오류 발생 | 파일명의 「영문명」 부분에 중국어를 작성함 | 「복구 단계 2」 참조 |
| `TbClient`에는 `TbXxx`가 있고 `TbServer`에는 없음(또는 그 반대) | 파일명에 그룹 표시 `c` / `s`가 붙어 테이블이 한쪽에서만 쓰이도록 제한됨 | 「복구 단계 3」 참조 |

## 복구 단계

### 1. Excel 파일명이 명명 규칙에 맞는지 확인

도구는 `字母-英文名-中文名.xlsx` 형식에 엄격하게 부합하는 파일만 인식하며, 파일명이 틀리면 코드가 전혀 생성되지 않습니다.

`Config/Excels/Tables/` 폴더를 열고 파일명이 다음과 같은 형태인지 확인하세요:

```
D-ItemConfig-道具表.xlsx
```

세 부분의 의미:

| 부분 | 역할 | 규칙 |
|----|------|------|
| 문자 | 정렬용 단일 문자 | 임의의 문자 또는 숫자 |
| 영문명 | **코드 클래스명 `Tb英文名`이 됨** | 반드시 순수 영문이어야 하며, **중국어를 쓰면 안 됨** |
| 중문명 | 기획자/동료가 보는 용도 | 임의, `-` 포함 가능 |

출처:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L164-L190)

예시 대조표:

| 파일명 | 생성되는 클래스 |
|--------|----------|
| `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
| `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
| `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |

### 2. 영문명 부분에 중국어가 포함되면 안 됨

`不支持中文表名` 또는 `table name invalid` 오류가 발생하면 「영문명」 부분에 중국어를 썼다는 뜻입니다(예: `D-道具-我的道具表.xlsx`). 가운데 부분을 순수 영문으로 바꾸면 됩니다:

```
오류:D-道具-我的道具表.xlsx
올바름:D-Item-我的道具表.xlsx     → TbItem 생성
```

### 3. 파일명의 그룹 표시 확인

클라이언트 전용 또는 서버 전용으로만 쓰고 싶다면 영문명과 중문명 사이에 그룹 표시를 추가해야 합니다. **표시를 추가했다는 사실을 인식하지 못하면 클래스가 「사라졌다」고 착각하게 됩니다.**

| 파일명 | 효과 |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | 클라이언트, 서버 모두 사용 |
| `D-ItemConfig-c-道具表.xlsx` | **클라이언트에만** `TbItemConfig`가 있음 |
| `D-ItemConfig-s-道具表.xlsx` | **서버에만** `TbItemConfig`가 있음 |

원하는 대상 프로젝트가 클라이언트인지 서버인지 확인한 뒤 해당하는 파일명을 선택하거나, `-c-` / `-s-`를 제거하여 양쪽 모두 생성되도록 하세요.

출처:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

### 4. 올바른 생성 스크립트를 실행했는지 확인

`Config/` 루트 디렉터리에는 보통 여러 개의 생성 스크립트가 있으며, **잘못된 스크립트를 실행하는 것이 클래스를 찾지 못하는 가장 흔한 원인입니다**:

| 스크립트 | 생성되는 항목 |
|------|----------|
| `gen-client-json.bat` / `gen-client-json.sh` | JSON 데이터 + C# 클래스, 클라이언트용 |
| `gen-server-bin.bat` / `gen-server-bin.sh` | 바이너리 데이터 + C# 클래스, 서버용 |

- Windows: `Config/` 디렉터리에서 해당 `.bat` 파일을 더블 클릭
- Mac / Linux: 터미널에서 `cd Config` 후 `sh gen-*.sh` 실행

실행 후 출력 디렉터리에 새로 생성된 `.cs` 파일이 있는지 확인하세요—있으면 성공한 것이며, 단지 다른 프로젝트에 있을 뿐일 수 있습니다.

출처:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L134-L148)

### 5. Config 루트 디렉터리에서 스크립트 실행

`gen-*.bat` / `gen-*.sh`는 같은 디렉터리에 있는 `luban.conf`와 `Tools/` 디렉터리에 의존합니다. 다른 디렉터리에서 실행하면 설정이나 도구 디렉터리를 찾을 수 없다는 오류가 발생하고, 생성이 조용히 실패합니다.

```bash
# 올바름
cd Config
sh gen-client-json.sh

# 잘못됨(상위 디렉터리에서 실행)
sh Config/gen-client-json.sh   # luban.conf를 찾지 못할 수 있음
```

### 6. 테이블을 여러 개로 나눌 때 영문명은 완전히 일치해야 함

테이블이 너무 크면 여러 개로 나눌 수 있으며, 도구는 「영문명」을 기준으로 병합합니다. **영문명 철자가 일치하지 않으면 두 개의 테이블로 나뉘어 두 개의 클래스가 생성됩니다**:

```
올바름(모두 TbItemConfig로 병합됨):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemConfig-道具表-1001-2000.xlsx

잘못됨(영문명이 일치하지 않아 TbItemConfig와 TbItemConfig2가 생성됨):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemCongfig-道具表-1001-2000.xlsx   ← ItemCongfig의 철자가 틀렸다는 점에 주의
```

영문명을 통일한 뒤 생성 스크립트를 다시 실행하세요.

출처:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L234-L248)

## 검증

위 단계대로 고친 후 다음 방법으로 확인하세요:

1. **생성 스크립트를 다시 실행**하여 스크립트가 **오류 없이** 끝까지 실행되는지 확인하세요(오류 스택이 아니라 `pause` 또는 `Press any key`가 보여야 함).
2. **생성 출력 디렉터리를 열어** 그 안에 `TbXxx.cs`와 해당 데이터 파일(JSON 또는 bin)이 있는지 확인하세요.
3. **Unity / .NET 프로젝트에서 마우스 오른쪽 클릭 → 다시 빌드/프로젝트 새로 고침**을 하여 IDE가 새로 추가된 `.cs` 파일을 인식하게 하세요.
4. **최소 호출로 검증**:

```csharp
// 테이블명이 ItemConfig이고, id 열에 10001이 입력되어 있다고 가정
var item = tables.TbItemConfig.Get(10001);
UnityEngine.Debug.Log(item.Name);
```

정상적으로 출력되면 클래스가 올바르게 로드된 것입니다. 여전히 `TbItemConfig`가 존재하지 않는다는 오류가 발생하면 진단표로 돌아가 계속 원인을 확인하세요.
