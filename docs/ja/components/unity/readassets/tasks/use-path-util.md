# PathUtil を使ったパス処理（正規化／連結／ワイルドカード）

`PathUtil` は静的ユーティリティクラスで、読み書きリソースで扱う相対パスの処理に特化しています。混在した区切り文字や `.`、`..` を含むパスを正規化し、2 つのパスを安全に `/` 区切りの文字列として連結し、`*`/`?` のワイルドカードを直接マッチングに使える正規表現に変換します。

## 前提条件

- プロジェクトに `com.gameframex.unity.readassets` パッケージが導入済みであること。
- コードに `using GameFrameX.ReadAssets.Runtime;` が記述されていること。

## 主なメソッド一覧

| メソッド | 役割 |
|------|------|
| `IsDirectorySeparator(char c)` | 文字が `/` または `\` かどうかを判定する |
| `FixTrailingDirectorySeparators(string path)` | 末尾の連続した区切り文字を 1 つにまとめる |
| `CombineSlash(string a, string b)` | `/` で 2 つのパスを連結し、重複や欠落した区切り文字を回避する |
| `NormalizeRelativePath(string relative, bool forceTrailingSlash = false)` | 相対パスを `/a/b/c` 形式に正規化し、`.`、`..`、混在区切り文字を処理する |
| `IsValidCharacter(char c)` | 文字がパスとして許可された文字かどうかを判定する |
| `WildcardToRegex(string pattern)` | `*`/`?` のワイルドカードを大小文字を区別しない正規表現に変換する |

## 手順

### 1. 2 つのパスを連結する

```csharp
using GameFrameX.ReadAssets.Runtime;

string full = PathUtil.CombineSlash("assets/config", "settings.json");
// 結果："assets/config/settings.json"

string root = PathUtil.CombineSlash("assets/config/", "sub/file.json");
// 結果："assets/config/sub/file.json"、スラッシュが重複しない

string abs = PathUtil.CombineSlash("assets/config", "/absolute/file.json");
// b が '/' で始まる場合、b をそのまま返す："absolute/file.json"
```

### 2. 相対パスを正規化する

`NormalizeRelativePath` は `\` をすべて `/` に変換し、`.` を折りたたみ、`..` を解決し、不正な文字を検証します。デフォルトでは末尾のスラッシュは保持されず、`forceTrailingSlash: true` を渡すと強制的に保持できます。

```csharp
using GameFrameX.ReadAssets.Runtime;

// 混在した区切り文字 → / に統一
string p1 = PathUtil.NormalizeRelativePath("a\\b\\c");
// 結果："a/b/c"

// . と .. を解決
string p2 = PathUtil.NormalizeRelativePath("a/./b/../c");
// 結果："a/c"

// 末尾のスラッシュを強制的に保持
string p3 = PathUtil.NormalizeRelativePath("a/b/c", forceTrailingSlash: true);
// 結果："a/b/c/"

// 両端が引用符で囲まれた文字列は除去される
string p4 = PathUtil.NormalizeRelativePath("\"a/b\"");
// 結果："a/b"
```

Source: [Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L170)

### 3. ワイルドカードでマッチングする

`WildcardToRegex` はワイルドカードを正規表現に変換し、`*` は任意の文字シーケンス、`?` は 1 文字に対応し、マッチング時は大小文字を区別しません。

```csharp
using System.Text.RegularExpressions;
using GameFrameX.ReadAssets.Runtime;

Regex rx = PathUtil.WildcardToRegex("assets/configs/*.json");
bool match1 = rx.IsMatch("assets/configs/settings.json"); // true
bool match2 = rx.IsMatch("assets/configs/data.json");    // true
bool match3 = rx.IsMatch("assets/configs/sub/a.json");   // false（* は / をまたがない）

Regex rx2 = PathUtil.WildcardToRegex("file_?.txt");
bool match4 = rx2.IsMatch("file_1.txt"); // true
bool match5 = rx2.IsMatch("file_12.txt"); // false
```

Source: [Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L183-L186)

### 4. 末尾の余分なスラッシュを修正する

using GameFrameX.ReadAssets.Runtime;

string p1 = PathUtil.FixTrailingDirectorySeparators("assets//");

string p2 = PathUtil.FixTrailingDirectorySeparators("a\\b\\");

## よくあるバリエーション

- **引用符をそのまま保持**：パスがダブルクォーテーションで囲まれた文字列全体ではない場合（先頭または末尾にのみ `"` がある場合）、`NormalizeRelativePath` は引用符を除去しません。引用符は不正な文字でもあり、`Invalid characters` がスローされます。
- **文字が合法かどうかを判定する**：`IsValidCharacter` は `"`、`<`、`>`、`|`、`*`、`?`、`:` および制御文字（ASCII < 32）を拒否するため、カスタム検証で再利用できます。
- **絶対パスを連結する**：`CombineSlash` で `b` が `/` で始まる場合、`b`（先頭の `/` を除去したもの）をそのまま返します。これは「渡されたパスでプレフィックスを上書きする」シナリオに使用されます。

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| `ArgumentException: Empty or null` | `NormalizeRelativePath` に `null` または空文字列が渡された | あらかじめ null チェックを行う |
| `IOException: Invalid path: double dot error` | `..` が多すぎて現在のディレクトリを超える（すでにルートまで遡った） | パスが本当にルートより上になっていないか確認する |
| `IOException: Invalid characters` | パスに `"`、`<`、`>`、`|`、`*`、`?`、`:` または制御文字が含まれている | `IsValidCharacter` でフィルタリングするか入力を修正する |
| `ArgumentNullException: a / b` | `CombineSlash` の引数のいずれかが `null` | 呼び出し前に null チェックを行う |

## 背景（任意）

`PathUtil` はリソース読み込みフローにおいて最もハマりやすい 3 つのポイント——区切り文字、`./..`、ワイルドカード——を 1 つの静的クラスに集約しています：`NormalizeRelativePath` は状態機械でパスのセグメントを解析し、出力が `/` で始まり冗長な部分を含まないことを保証します；`WildcardToRegex` は `Regex.Escape` で安全にした後に `*`/`?` を置換するため、パス中のドットが正規表現のメタ文字として扱われるのを防ぎます。
