# 設定の削除とクリア

`ISettingManager` インターフェースを使用すると、実行時に単一の項目を削除したり、すべての設定を一度にクリアしたりできます。プレイヤーの設定リセット、キャッシュクリア、アカウント切り替えによく使われます。

## 前提条件

- [クイックスタート](../../overview/quick-start) の初期化フローが完了しており、`SettingManager` が `SettingComponent` によって作成・保持されていること。
- 設定ヘルパー `ISettingHelper` が `SetSettingHelper` 経由で設定されていること。設定されていない場合、削除/クリアインターフェースは `GameFrameworkException("Setting helper is invalid.")` をスローします。
- `ISettingManager` インスタンスを取得していること。下記の「マネージャーの取得」セクションを参照してください。

## 操作手順

1. 設定マネージャーのインスタンスを取得します。

   ```csharp
   var settingManager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>();
   if (settingManager == null)
   {
       // 通常は SettingComponent がアタッチされていないか、初期化に失敗しています
       return;
   }
   ```

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

2. 名前を指定して単一の項目を削除します。削除前に `HasSetting` で存在を確認できます。

   ```csharp
   const string key = "Player.MusicVolume";
   if (settingManager.HasSetting(key))
   {
       bool removed = settingManager.RemoveSetting(key);
       if (removed)
       {
           settingManager.Save();
       }
   }
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L210-L234)

3. すべての項目を一度にクリアします(注意して使用してください、すべてのキーが削除されます)。

   ```csharp
   settingManager.RemoveAllSettings();
   settingManager.Save(); // 手動で Save が必要かどうかは実装に応じて決まります
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L244-L249)

4. 結果を検証します。設定項目を再度列挙し、数量が期待どおりであることを確認します。

   ```csharp
   int remaining = settingManager.Count; // 0 になるはず(全クリア)、または削除前より 1 少ない
   string[] names = settingManager.GetAllSettingNames();
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L84-L92)

## インターフェース早見表

| メソッド | シグネチャ | 動作 |
|------|------|------|
| `HasSetting` | `bool HasSetting(string settingName)` | 設定名が空の場合、`GameFrameworkException("Setting name is invalid.")` をスローします。それ以外は存在を照会します。 |
| `RemoveSetting` | `bool RemoveSetting(string settingName)` | 削除が成功したかを示す `bool` を返します。設定名が空の場合は例外をスローします。 |
| `RemoveAllSettings` | `void RemoveAllSettings()` | すべての項目をクリアします。戻り値はなく、パラメータ検証以外のエラーはありません。 |

Source: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L104-L133)

## よくあるバリエーション

- 削除のみで保存しない:特定のバックエンド(例: `PlayerPrefs`)では明示的に `Save` を呼び出さないとディスクに書き込まれず、削除後にプロセスがクラッシュすると変更が失われる可能性があります。具体的な `ISettingHelper` の実装に応じて判断してください。
- 読み取り専用/デフォルト設定の削除:設定がシリアル化ファイルから読み込まれたものである場合、`RemoveSetting` は通常、実行時のメモリキャッシュ内のエントリにのみ影響し、ソースファイルには書き戻されません。

## よくあるエラー

- **"Setting helper is invalid."**:`ISettingHelper` が設定されていません。`SettingComponent` が正しく初期化され、ヘルパーが割り当てられていることを確認してください。
- **"Setting name is invalid."**:`settingName` が `null` または空文字列です。削除前に有効な名前を渡す必要があります。
- **削除後も古い値が読み取れる**:バックエンドが自動で永続化しないため、`Save()` を呼び出すことを忘れないでください。または、次回の `Load()` で永続層から同名の項目が再度読み込まれる可能性があります。
- **期待したクリーンアップ効果がない**:`RemoveAllSettings` はバックエンドの基盤(例: `PlayerPrefs` 内の他の無関係なキー)をリセットせず、現在のマネージャーが保持するエントリのみをクリアします。

## 背景(オプション)

`SettingManager` は薄いラッパーであり、すべての削除/クリア操作は `ISettingHelper` 実装に直接転送されます([`SettingHelperBase`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs) に抽象メソッドが定義されています)。`DefaultSettingHelper`、`PlayerPrefsSettingHelper` などの具体的な実装は、それぞれメモリを変更するのか、基盤ストレージに同期するのかを決定します。モジュールをシャットダウンする際には自動的に `Save()` が呼ばれます。詳細は [`Shutdown`](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L112-L115) を参照してください。
