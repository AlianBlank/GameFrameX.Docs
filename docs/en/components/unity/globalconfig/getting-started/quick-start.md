# Quick Start

`GlobalConfig` is the global configuration component of GameFrameX, used to centrally manage the application version check URL, resource version check URL, host server URL, and a piece of customizable additional content. This section will walk you through the entire process of installation, mounting the component, and reading the configuration.

## Prerequisites

- Unity 2019.4 or later.
- The two dependency packages `com.gameframex.unity` and `com.gameframex.unity.web` are installed (see [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/README.zh-CN.md#L76-L80) for the latest stable versions).
- A GameFrameX framework entry scene (containing the `GameFramework` component) already exists, because `GlobalConfigComponent` inherits from `GameFrameworkComponent`.

## Installation

Choose one of the following to complete the installation:

1. **Modify `Packages/manifest.json` (recommended)**, and add the GameFrameX scoped registry:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.globalconfig": "1.3.2"
     }
   }
   ```

2. **Add directly via Git URL**, write the following under `dependencies` in `manifest.json`:

   ```json
   {
     "dependencies": {
       "com.gameframex.unity.globalconfig": "https://github.com/gameframex/com.gameframex.unity.globalconfig.git"
     }
   }
   ```

3. **Unity Package Manager → Add package from git URL**, enter `https://github.com/gameframex/com.gameframex.unity.globalconfig.git`.

4. **Local source installation**: Copy the repository directory to the project's `Packages/`, and Unity will automatically recognize it.

## Operation Steps

1. **Mount the component to the framework entry**. On the entry GameObject, click `Add Component → GameFrameX → Global Config` to add `GlobalConfigComponent`. The component itself disables auto-registration (`IsAutoRegister = false`) in `Awake`, so you need to manually call it at an appropriate time:

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   using UnityEngine;

   public class GlobalConfigBootstrap : MonoBehaviour
   {
       [SerializeField] private GlobalConfigComponent m_GlobalConfig;

       private void Start()
       {
           // Called by your startup process to register the component with the GameFrameX framework
           GameFrameX.Runtime.GameFrameworkEntry.RegisterComponent(m_GlobalConfig);
       }
   }
   ```

   The `Awake` and component attribute definitions are available at [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L11-L13).

2. **Fill in the basic fields**. In the Inspector, fill in at least one of `Check App Version Url` or `Check Resource Version Url`, and set `Host Server Url`, `Content`, and `AOT Code List` as needed. All fields are exposed as `[SerializeField]` string fields in the component. See the definitions at [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L18-L98).

3. **Fetch and inject the configuration from the server**. Use any HTTP client to request your global info endpoint, deserialize the JSON into `ResponseGlobalInfo`, then call `SetGlobalConfig`:

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   using GameFrameX.Runtime;

   var component = GameFrameworkEntry.GetComponent<GlobalConfigComponent>();
   var rawJson = "<JSON returned by the server>";
   var info = Utility.Json.ToObject<ResponseGlobalInfo>(rawJson);
   component.SetGlobalConfig(info);
   ```

   The field definitions of `ResponseGlobalInfo` are available at [ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L6-L27). `SetGlobalConfig` performs null validation and throws `ArgumentNullException`. See the signature at [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L160-L168).

4. **Read it in game logic**. Get the instance via `GameFrameworkEntry.GetComponent<GlobalConfigComponent>()`, and then access the corresponding properties:

   ```csharp
   var globalConfig = GameFrameworkEntry.GetComponent<GlobalConfigComponent>();
   string appVersionUrl = globalConfig.CheckAppVersionUrl;
   string resourceUrl   = globalConfig.CheckResourceVersionUrl;
   string hostUrl       = globalConfig.HostServerUrl;
   string extra         = globalConfig.Content;

   ResponseGlobalInfo info = globalConfig.GlobalInfo;
   string serverAotJson    = info?.AOTCodeList;
   ```

   `AOTCodeList` is a JSON string that is automatically parsed into the `AOTCodeLists` list upon assignment. If parsing fails, an error log is output, but no exception is thrown ([GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L46-L79)).

## Common Variants

- **Just want to store a raw JSON string**: Call `SetOriginalData(json)` to save it directly, and parse it externally. See the signature at [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L126-L134).
- **Edit the AOT list in the Inspector**: Since 1.3.2, `AOTCodeLists` has been changed to read-only. The list can only be assigned through the `AOTCodeList` JSON field and automatically parsed. See [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L51-L79) and the version notes for details.
- **Switch server URLs at runtime**: Simply assign values to `CheckAppVersionUrl`, `CheckResourceVersionUrl`, and `HostServerUrl`. All these properties have setters.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GetComponent<GlobalConfigComponent>()` returns `null` | The component was not manually registered (`IsAutoRegister = false`) | Call `GameFrameworkEntry.RegisterComponent(m_GlobalConfig)` in the startup script |
| `SetGlobalConfig(null)` throws `ArgumentNullException` | The argument is null | Check for non-null before calling to ensure the server returned a valid object |
| `AOTCodeLists` is always empty | `AOTCodeList` is not a valid JSON string | Confirm that the JSON issued by the server is in the form `["a.dll","b.dll"]`; if it fails, `Log.Error` will appear in the console |
| `GlobalInfo` is `null` after the server response | `SetGlobalConfig` or `SetOriginalData` has not been called yet | Call `SetGlobalConfig` in the success callback of the request |

## Background (Optional)

`GlobalConfigComponent` is a `sealed` `GameFrameworkComponent`. Its `Awake` disables auto-registration, so its lifecycle must be controlled by the business side. It only holds the configuration and does not proactively initiate network requests. `RequestBase` and the various `Request*` / `Response*` types are merely accompanying request/response data carriers; the logic is determined by the caller.
