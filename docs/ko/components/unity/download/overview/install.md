# 설치 및 연동

이 페이지에서는 GameFrameX Download 컴포넌트를 Unity 프로젝트에 연동하고 첫 다운로드를 완료하는 방법을 소개합니다. 컴포넌트는 Unity Package 형태로 배포되며, Scoped Registry, Git URL 또는 로컬 파일 세 가지 방식으로 설치합니다. 연동 방법은 `DownloadComponent`를 `GameEntry`에 부착한 뒤 `EventComponent`를 통해 이벤트를 구독하거나 `AddDownload` / `Download`를 직접 호출하는 것입니다.

## 사전 조건

| 조건 | 요구 사항 |
|------|------|
| Unity 버전 | 2019.4 이상([package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L6-L8)) |
| 실행 환경 | `com.gameframex.unity` >= 2.5.1 |
| 이벤트 컴포넌트 | `com.gameframex.unity.event` >= 1.3.0 |
| 진입 스크립트 | `GameFrameX.Runtime.GameEntry`와 `EventComponent`가 이미 부착되어 있어야 함(이벤트 구독용) |

의존 관계는 [package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L25-L28)에 명시되어 있습니다:

```json
"dependencies": {
  "com.gameframex.unity.event": "1.3.0",
  "com.gameframex.unity": "2.5.1"
}
```

## 설치 단계

아래 방법 중 하나를 선택하세요.

### 방법 1: Scoped Registry(권장)

Unity 프로젝트의 `Packages/manifest.json`을 편집하여 scoped registry와 의존성을 추가합니다:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.download": "1.2.1"
  }
}
```

여기서 `scopes: ["com.gameframex"]`는 `com.gameframex`로 시작하는 패키지만 이 레지스트리를 통해 해석되도록 제어하며, 다른 의존성에는 영향을 주지 않습니다.

### 방법 2: Git URL

`manifest.json`의 `dependencies`에 Git 저장소 주소를 직접 작성합니다:

```json
"com.gameframex.unity.download": "https://github.com/GameFrameX/com.gameframex.unity.download.git"
```

Unity Package Manager를 열고 `Add package from git URL`을 클릭한 후 `https://github.com/GameFrameX/com.gameframex.unity.download.git`를 붙여넣어도 됩니다.

### 방법 3: 로컬 배치

저장소를 Unity 프로젝트의 `Packages/` 디렉터리 아래에 직접 클론하거나 복사하면(예: `Packages/com.gameframex.unity.download`), Unity가 시작될 때 `package.json`을 자동으로 인식하여 로드합니다.

## 컴포넌트 연동

다운로드 컴포넌트의 핵심 진입점은 `GameFrameX.Download.Runtime.DownloadComponent`입니다([Editor/Inspector/DownloadComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Editor/Inspector/DownloadComponentInspector.cs#L41-L48)):

```csharp
[CustomEditor(typeof(DownloadComponent))]
internal sealed class DownloadComponentInspector : ComponentTypeComponentInspector
```

프로젝트에 연동하는 방식은 두 가지가 있습니다.

### 방식 A: 자동 생성(권장)

메뉴 `GameFrameX/xxx`를 통해 프리팹을 생성하면 `DownloadComponent`와 기본 `UnityWebRequestDownloadAgentHelper`가 자동으로 부착됩니다.

### 방식 B: 수동 부착

`DownloadComponent`를 `GameEntry`가 참조하는 컴포넌트 프리팹에 드래그하면 Inspector에서 4개의 핵심 필드를 설정할 수 있습니다:

| Inspector 필드 | 의미 | 값 범위 / 기본값 |
|----------------|------|------------------|
| `Instance Root` | 런타임 부모 노드 Transform | 씬의 기존 노드 |
| `Download Agent Helper Count` | 다운로드 에이전트 풀 크기 | `IntSlider`, 범위 `1 - 16` |
| `Timeout` | 단일 다운로드 타임아웃(초) | `Slider`, 범위 `0 - 120` |
| `Flush Size` | 디스크 플러시 임계값(바이트) | `DelayedIntField`, 기본 약 1 MB |

`Download Agent` 드롭다운은 `IDownloadAgentHelper` 구현을 전환하는 데 사용합니다([DownloadComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Editor/Inspector/DownloadComponentInspector.cs#L48-L49)):

```csharp
private HelperInfo<DownloadAgentHelperBase> m_DownloadAgentHelperInfo = new HelperInfo<DownloadAgentHelperBase>("DownloadAgent");
```

## 첫 다운로드

설치가 올바르게 되었는지 확인하는 가장 간단한 방법은 한 줄의 `Download(...)`를 작성하여 결과를 얻을 수 있는지 확인하는 것입니다. 두 가지 호출 방식은 다음과 같습니다.

### 비동기 사용법

```csharp
var downloadComponent = GameEntry.GetComponent<DownloadComponent>();

bool success = await downloadComponent.Download(
    "/로컬 저장 경로/file.zip",          // downloadPath: 로컬 전체 경로
    "https://example.com/file.zip"    // downloadUri: 원격 주소
);

if (success)
{
    // 다운로드 완료
}
```

### 이벤트 기반 사용법

```csharp
var downloadComponent = GameEntry.GetComponent<DownloadComponent>();

// 이벤트 구독
var eventComponent = GameEntry.GetComponent<EventComponent>();
eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);

// 작업 디스패치
int serialId = downloadComponent.AddDownload(
    "/로컬 저장 경로/file.zip",
    "https://example.com/file.zip"
);

void OnDownloadSuccess(object sender, GameEventArgs e)
{
    var args = (DownloadSuccessEventArgs)e;
    if (args.SerialId == serialId) { /* 완료 */ }
}

void OnDownloadFailure(object sender, GameEventArgs e)
{
    var args = (DownloadFailureEventArgs)e;
    Debug.LogError($"다운로드 실패:{args.ErrorMessage}");
}
```

실행 후 Inspector의 `Paused`, `Total/Free/Working Agent Count`, `Waiting Agent Count`, `Current Speed` 그리고 작업 목록이 실시간으로 갱신됩니다([DownloadComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Editor/Inspector/DownloadComponentInspector.cs#L93-L142)). 작업 목록은 `Export CSV Data` 버튼으로 한 번에 내보낼 수 있습니다.

## 일반적인 변형

**태그 및 우선순위 지정**: `AddDownload`의 선택 매개변수 `tag`는 그룹화에 사용되며, `priority` 값이 클수록 먼저 디스패치됩니다.

```csharp
int serialId = downloadComponent.AddDownload(
    downloadPath, downloadUri,
    tag: "assets",
    priority: 10
);

// 태그로 조회
TaskInfo[] infos = downloadComponent.GetDownloadInfos("assets");

// 해당 태그 그룹의 모든 작업 제거
downloadComponent.RemoveDownloads("assets");
```

**전체 일시정지 / 재개**:

```csharp
downloadComponent.Paused = true;   // 모든 다운로드 일시정지
downloadComponent.Paused = false;  // 다운로드 재개
```

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Package Manager에서 패키지를 찾을 수 없음 | scoped registry가 구성되지 않았거나 `scopes`가 잘못 작성됨 | `manifest.json`에 `scopedRegistries`를 추가하고, `scopes`에 반드시 `com.gameframex` 포함 |
| 컴파일 시 `EventComponent` 누락 오류 발생 | 이벤트 하위 패키지가 임포트되지 않음 | `com.gameframex.unity.event`가 `manifest.json`의 `dependencies`에 있는지 확인 |
| `Download Component Inspector` 필드가 회색으로 표시됨 | Play 모드에서는 에이전트 수와 Instance Root 수정이 금지됨 | Play 모드를 종료한 후 편집 |
| `Timeout` / `Flush Size`를 조정해도 적용되지 않음 | Play 모드가 아닌 상태에서 SerializedProperty를 변경함 | Play 모드에서 `t.Timeout = ...`과 `t.FlushSize = ...`로 직접 값 할당([DownloadComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Editor/Inspector/DownloadComponentInspector.cs#L67-L91)) |

## 배경(선택 사항)

`DownloadComponent`는 `GameFrameX` 프레임워크의 표준 모듈 컴포넌트로, 프레임워크의 `Component` 기본 클래스를 상속하며 `GameEntry.GetComponent<T>()` 싱글톤으로 접근합니다. 다운로드 에이전트(agent)는 풀링된 객체이며 수량은 `Download Agent Helper Count`로 제어되고, 작업은 우선순위순으로 정렬된 뒤 유휴 상태의 agent에 디스패치되므로 에이전트 수를 늘리면 동시 처리량을 높일 수 있습니다. 이벤트 콜백은 `EventComponent`를 통해 디스패치되며, 다운로드 모듈과 비즈니스 모듈을 분리할 수 있습니다.
