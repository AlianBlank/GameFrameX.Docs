# 實作自訂支付渠道

繼承 `BasePaymentManager` 並實作其全部抽象成員，再將你的實作類別完整型別名稱填入 `PaymentComponent` 上對應平台的序列化欄位中，遊戲啟動時元件會自動透過反射載入並切換到你的渠道實作，業務層呼叫程式碼無須改動。

## 前置條件

- 已安裝 `com.gameframex.unity.payment` 套件，場景中掛有 `GameFrameX/Payment` 元件(`PaymentComponent`,它透過 `RequireComponent` 強制附帶 `GameFrameXPaymentCroppingHelper`)。
- 你的實作類別所在組件需參與 Unity 編譯(即能被 `Utility.Assembly.GetType` 解析到)。

## 操作步驟

### 1. 建立渠道管理器類別

新增類別繼承 `GameFrameX.Payment.Runtime.BasePaymentManager`(它已實作 `GameFrameworkModule` 與 `IPaymentManager` 的事件定義，並預留了事件拋出方法)：

```csharp
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;
    // ...
}
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L14-L34)

子類別形如 `public class MyPaymentManager : BasePaymentManager`(類別名稱與命名空間自定，後續步驟會用到完整型別名稱)。

需要 `override` 的抽象成員(全部來自真實原始碼簽章)：

| 成員 | 真實簽章 | 說明 |
|------|----------|------|
| `Init` | `void Init(bool isDebug = false, bool isClientVerify = false)` | 初始化渠道 SDK;`isDebug` 沙盒模式，`isClientVerify` 是否做用戶端驗單 |
| `IsReady` | `bool IsReady()` | 渠道是否就緒 |
| `SetPredefinedProductIds` | `void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds)` | 預載入預先定義的商品 ID,必須在 `Init` 之前呼叫 |
| `QueryPurchases` | `void QueryPurchases(PaymentProductType productType)` | 查詢購買記錄，結果經 `OnQueryPurchasesResult` 回呼 |
| `ConsumePurchase` | `void ConsumePurchase(string purchaseToken)` | 消耗購買，結果經 `OnConsumePurchaseResult` 回呼 |
| `BuyInApp` | `void BuyInApp(string productId, string orderId, string offerToken = "", string customData = "")` | 舊介面，已標記 `[Obsolete]`,仍需 override |
| `BuySubs` | `void BuySubs(string productId, string orderId, string offerToken = "", string customData = "")` | 舊介面，已標記 `[Obsolete]`,仍需 override |
| `Buy` | `void Buy(string productId, PaymentProductType productType, string orderId, string offerToken = "", string customData = "")` | 舊介面，已標記 `[Obsolete]`,仍需 override |
| `Buy` | `void Buy(PurchaseParams purchaseParams)` | 建議入口，購買參數可傳入渠道子類別 |

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L42-L112)

### 2. 在實作中拋出事件

渠道 SDK 回呼後，呼叫基底類別提供的受保護方法通知業務層，不要直接存取事件欄位：

```csharp
protected void RaisePurchaseSuccess(PaymentEventArgs e)
{
    OnPurchaseSuccess?.Invoke(this, e);
}

protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}

protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
{
    OnQueryPurchasesResult?.Invoke(this, e);
}

protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
{
    OnConsumePurchaseResult?.Invoke(this, e);
}
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L41-L59)

### 3. (可選)擴充渠道專屬購買參數

`Buy(PurchaseParams)` 的參數是抽象基底類別，官方註解明確指出「各渠道可繼承並擴充自有欄位」：

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

為你的渠道派生一個子類別，將渠道特有參數(如渠道側 token、渠道使用者 ID)作為屬性加上去；在 `MyPaymentManager.Buy(PurchaseParams)` 中向下轉型讀取。

### 4. 將實作類別接入 PaymentComponent

`PaymentComponent` 按平台以序列化欄位決定載入哪個實作類別，在 Inspector 中將對應平台欄位替換為你自己的完整型別名稱即可。框架預設值如下：

```csharp
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L24-L28)

平台對應規則(來自 `PaymentComponent.Awake` 的條件編譯)：

| 編譯巨集 | 使用的欄位 | 預設實作 |
|--------|-----------|----------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `WebGLPaymentManager` |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `m_componentPCType` | `PCPaymentManager` |
| `UNITY_STANDALONE_OSX` | `m_componentMacType` | `ApplePaymentManager` |
| 其他平台 | — | `DefaultPaymentManager` |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

載入流程：元件在 `Awake` 中呼叫 `Utility.Assembly.GetType(componentType)` 解析型別，再由 `GameFrameworkEntry.GetModule<IPaymentManager>()` 取得實例；解析失敗或模組無效時會 `Log.Fatal("Pay Manager is invalid.")`。

### 5. 驗證接入

在業務層照常呼叫，無須感知具體渠道：

```csharp
// 訂閱事件(PaymentComponent 已把事件轉發到底層管理器)
paymentComponent.OnPurchaseSuccess += (sender, e) => { /* 出貨 */ };
paymentComponent.Init(isDebug: true, isClientVerify: false);
paymentComponent.Buy(myChannelPurchaseParams);
```

`PaymentComponent.Init` 的簽章為 `public void Init(bool isDebug = false, bool isClientVerify = true)`,內部直接轉發到 `IPaymentManager.Init`。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

## 常見變體

- **只替換某個平台**：僅修改對應平台欄位，其餘平台保留官方渠道套件，實現各平台混用。
- **測試樁渠道**：為所有平台欄位填入同一個空的/模擬的 `BasePaymentManager` 子類別，即可在 Editor 或不支援的平台上使用(否則非列出的平台會落到 `DefaultPaymentManager`)。
- **渠道需要購買額外參數**：為渠道實作 `PurchaseParams` 子類別，業務層只依賴該子類別的建構參數。

## 常見錯誤

| 症狀/現象 | 原因 | 修復 |
|-----------|------|------|
| 啟動即 `Log.Fatal("Pay Manager is invalid.")` | 型別名稱寫錯、命名空間不符或類別未被編譯進組件，`Utility.Assembly.GetType` 解析失敗 | 核對 Inspector 中填寫的是「命名空間.類別名稱」完整形式，且腳本無編譯錯誤 |
| `Buy` 無任何反應且無錯誤 | `PaymentComponent` 對空參數做了前置驗證，例如 `"Product ID is null or empty."`、`"Order ID is null or empty."`、`"Purchase token is null or empty."` | 檢查 `ProductId`/`OrderId`/`purchaseToken` 非空；對照 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L230) 的驗證邏輯 |
| `SetPredefinedProductIds` 不生效 | 介面註解明確要求「此方法必須在 Initialize() 之前呼叫」 | 在呼叫 `Init` 之前先設定預先定義的商品 ID |
| 編譯報 `Obsolete` 警告 | 使用了 `BuyInApp`/`BuySubs`/舊 `Buy` 多載，均已標記 `[Obsolete("请使用 Buy(PurchaseParams) 替代")]` | 改為建構 `PurchaseParams` 子類別並呼叫 `Buy(PurchaseParams)` |
| 事件從未觸發 | 在渠道實作裡直接給事件賦值/未呼叫基底類別 `Raise*` 方法 | 統一透過 `RaisePurchaseSuccess` 等受保護方法拋出事件 |

## 背景

框架透過「元件 + 反射」解耦渠道:`PaymentComponent` 只依賴 `IPaymentManager` 介面，執行階段按平台巨集選擇實作類別名稱字串並用 `Utility.Assembly.GetType` 反射實例化，業務程式碼與具體渠道(官方 `GameFrameX.Payment.Google` 等渠道套件同理)完全隔離。關於支付模組的整體結構，見《支付模組簡介》。
