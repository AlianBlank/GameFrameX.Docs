# 코루틴 로직 테스트 작성 방법

코루틴 로직은 Unity 런타임(`MonoBehaviour`, `StartCoroutine`)에 의존하므로, 순수 NUnit 에디터 단위 테스트에서는 직접 구동할 수 없습니다. 이 페이지에서는 `GameFrameX.Coroutine.Tests`의 규약과 Unity PlayMode 테스트에서 코루틴 동작을 검증하는 방법을 설명합니다.

## 사전 조건

- `com.gameframex.unity.coroutine`과 호환되는 버전의 Unity가 설치되어 있어야 합니다.
- Package Manager를 통해 본 패키지가 설치되어 있어야 하며, Tests 어셈블리인 `GameFrameX.Coroutine.Tests`도 함께 임포트됩니다.
- PlayMode 테스트를 사용할 경우, 프로젝트 내에 `UnityEngine.TestRunner`와 `UnityEditor.TestRunner` 어셈블리가 필요합니다(Unity에 기본 제공).

## Tests 어셈블리 규약

`Tests/GameFrameX.Coroutine.Tests.asmdef`는 Editor 플랫폼에서만 적용되며, `references`를 통해 `GameFrameX.Coroutine.Runtime`을 명시적으로 참조하여 런타임 빌드를 오염시키지 않습니다.

```json
{
    "name": "GameFrameX.Coroutine.Tests",
    "references": [
        "GameFrameX.Coroutine.Runtime"
    ],
    "rootNamespace": "GameFrameX.Coroutine.Tests",
    "includePlatforms": [
        "Editor"
    ]
}
```

Source: [GameFrameX.Coroutine.Tests.asmdef](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/GameFrameX.Coroutine.Tests.asmdef#L1-L18)

## 작업 단계

### 1. Editor 어셈블리에 플레이스홀더 단위 테스트 배치

`Tests/UnitTests.cs`는 코루틴 모듈이 순수 NUnit 환경에서 실행될 수 없음을 명시적으로 설명하며, "테스트 커버리지가 없다 = 테스트되지 않음"으로 오해하지 않도록 플레이스홀더 케이스를 유지합니다.

```csharp
using NUnit.Framework;

namespace GameFrameX.Coroutine.Tests
{
    internal class UnitTests
    {
        [Test]
        public void TestPlaceholder()
        {
            // 코루틴 모듈은 Unity 런타임(MonoBehaviour, StartCoroutine)에 의존하므로,
            // 순수 NUnit 환경에서는 코루틴 로직을 직접 테스트할 수 없습니다.
            // 코루틴 관련 통합 테스트는 Unity PlayMode 테스트에서 작성해야 합니다.
            Assert.Pass("Coroutine module requires Unity runtime for testing.");
        }
    }
}
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/UnitTests.cs#L1-L16)

### 2. 실제 코루틴을 커버하는 PlayMode 테스트 작성

새로운 PlayMode 테스트 어셈블리(네임스페이스는 자유롭게 지정, 예: `GameFrameX.Coroutine.PlayModeTests`)를 만들고, `asmdef`에서 `includePlatforms`를 비워두고 `references`에 `GameFrameX.Coroutine.Runtime`과 `nunit.framework`를 추가합니다. 테스트 케이스에서는 `GameFrameX.Entry.GetComponent<CoroutineComponent>()`로 컴포넌트를 가져온 뒤, `new` 키워드로 숨겨진 `StartCoroutine` / `StopCoroutine`을 호출하여 동작을 검증합니다.

```csharp
using System.Collections;
using GameFrameX.Coroutine.Runtime;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

namespace GameFrameX.Coroutine.PlayModeTests
{
    public class CoroutineComponentTests
    {
        [UnityTest]
        public IEnumerator StartAndStop_TracksEnumerator()
        {
            var component = GameFrameX.Entry.GetComponent<CoroutineComponent>();
            Assert.IsNotNull(component);

            var routine = component.StartCoroutine(Sample());
            yield return null;

            // 동일한 IEnumerator 인스턴스는 StopCoroutine을 통해 올바르게 종료되고 추적 테이블에서 제거되어야 합니다.
            component.StopCoroutine(routine);
            yield return null;
        }

        private static IEnumerator Sample()
        {
            yield return null;
        }
    }
}
```

> 참고: `CoroutineComponent.StartCoroutine` / `StopCoroutine`은 `new` 키워드로 베이스 클래스 메서드를 숨기므로, 반드시 `CoroutineComponent` 타입의 참조를 통해 호출해야 컴포넌트가 코루틴을 추적 테이블에 등록합니다. 자세한 내용은 [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L50)를 참조하세요.

### 3. 테스트 실행

- Unity Editor에서 **Window → General → Test Runner**을 엽니다.
- **PlayMode** 탭으로 이동하여 방금 작성한 PlayMode 어셈블리를 선택하고 **Run All**을 클릭합니다.
- 플레이스홀더 Editor 테스트는 **EditMode** 탭에서 실행되며, 예상 결과는 `Passed`입니다.

## 일반적인 변형

- **EditMode 검증만 수행**: `UnitTests.TestPlaceholder` 플레이스홀더만 유지하여 CI의 EditMode 스위트가 본 모듈 누락으로 인해 오류를 발생시키지 않도록 합니다.
- **커스텀 이벤트/타이밍 로직 결합**: 비즈니스 코루틴을 `IEnumerator`를 반환하는 순수 메서드로 캡슐화하고, PlayMode 테스트에서 여러 번 `yield return`한 후 최종 상태를 검증합니다.
- **예외/로그 검증**: `LogAssert.Expect`를 사용하여 컴포넌트가 예외 코루틴에서 출력하는 로그를 캡처하고, 테스트가 잘못 실패로 보고되지 않도록 합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| PlayMode 테스트에서 `CoroutineComponent`가 `null`임 | `GameFrameX` 시작 절차가 완료되기 전에 값을 가져옴 | `yield return null` 이후에 가져오거나, `[SetUp]`에서 `Entry` 초기화 완료를 대기 |
| `StopCoroutine`이 코루틴을 찾을 수 없음 | `MonoBehaviour` 베이스 클래스 참조로 호출하여 `new` 숨김 메서드를 우회함 | 항상 `CoroutineComponent` 타입 참조를 통해 `StartCoroutine` / `StopCoroutine` 호출 |
| EditMode 테스트 실행 시 "Type or namespace not found" 오류 발생 | 테스트 어셈블리가 `GameFrameX.Coroutine.Runtime`을 참조하지 않음 | `asmdef`의 `references`에 `GameFrameX.Coroutine.Runtime`을 추가 |
| PlayMode 테스트가 무시됨 | PlayMode 어셈블리의 `includePlatforms`에 `Editor`가 잘못 입력됨 | `includePlatforms`를 비워두어 모든 플랫폼에서 컴파일되도록 함 |

## 배경(선택 사항)

`CoroutineComponent`는 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>`를 사용하여 코루틴을 추적하므로, `StopCoroutine`에는 `StartCoroutine`에 전달한 것과 동일한 `IEnumerator` 인스턴스를 전달해야 합니다. 이러한 제약 조건으로 인해 테스트에서는 동일한 메서드 호출 내에서 열거자 참조를 유지해야 합니다.
