# 決済システムの初期化

Unity シーンに `PaymentComponent` をアタッチして `Init` を呼び出すだけで、決済システムの初期化が完了します：コンポーネントは `Awake` 内で現在のプラットフォームに応じて対応する決済マネージャー実装（Google / Apple / WebGL / PC）を自動的に選択します。商品 ID を設定し、サンドボックスと検証のスイッチを渡すだけで、購入インターフェースを使用開始できます。

## 前提条件

- Unity プロジェクトに本パッケージがインストールされていること。以下のいずれかの方法を選択してください（詳細は [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/README.zh-CN.md#L40-L67) を参照）：
  - `Packages/manifest.json` の `dependencies` に `"com.gameframex.unity.payment": "https://github.com/gameframex/com.gameframex.unity.payment.git"` を追加する。
  - または Unity の `Package Manager` の `Git URL` 方式で追加する。
  - またはリポジトリを `Packages` ディレクトリ直下に置き、自動認識させる。
- 依存パッケージ `com.gameframex.unity`（バージョン 1.1.1 以上）がインストールされていること。
- ターゲットプラットフォームが Android（Google Play）または iOS（App Store）であること。Editor およびその他のプラットフォームではプレースホルダー実装にフォールバックします（下記の「よくあるエラー」を参照）。

## 操作手順

1. 起動シーンに GameObject を作成し、メニュー `GameFrameX/Payment` から `PaymentComponent` を追加します。コンポーネントは依存関係とエントリーメニューを次のように宣言しています：

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
```

出典：[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

コンポーネントを追加する際、`GameFrameXPaymentCroppingHelper` は `RequireComponent` によって自動的に付加されるため、手動で追加する必要はありません。同一オブジェクトへの重複アタッチは許可されません。

2. （任意）プラットフォーム実装タイプを確認します。コンポーネントは `Awake` 内でコンパイルマクロに基づき、実装クラスの完全名を自動的に選択します：

```csharp
#if UNITY_ANDROID
    componentType = m_componentAndroidType;
#elif UNITY_IOS
    componentType = m_componentIOSType;
#elif UNITY_WEBGL
    componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
    componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
    componentType = m_componentMacType;
#else
    componentType = typeof(DefaultPaymentManager).FullName;
#endif
```

出典：[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L83)

各プラットフォームのデフォルトタイプ名（Inspector のシリアライズフィールドで変更可能）：

| フィールド | デフォルト値 | 有効プラットフォーム |
|------|--------|----------|
| `m_componentAndroidType` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` | Android |
| `m_componentIOSType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | iOS |
| `m_componentWebGLType` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` | WebGL |
| `m_componentPCType` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` | Windows / Linux |
| `m_componentMacType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | macOS |

3. `Init` を呼び出す前に、商品キャッシュをプリロードする必要がある場合は、先に `SetPredefinedProductIds` を呼び出します（このメソッドは初期化より前に呼び出す必要があります）：

```csharp
/// <summary>
/// プリロード用の事前定義商品IDを設定します。キャッシュのプリロードに使用します。注意：このメソッドはInitialize()より前に呼び出す必要があります
/// </summary>
/// <param name="inAppProductIds">アプリ内課金商品IDのリスト</param>
/// <param name="subsProductIds">サブスクリプション商品IDのリスト</param>
[UnityEngine.Scripting.Preserve]
public void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds)
{
    _paymentManager.SetPredefinedProductIds(inAppProductIds, subsProductIds);
}
```

出典：[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L117-L126)

4. `Init` を呼び出して初期化を完了します。コンポーネント上のシグネチャとデフォルト値は以下の通りです：

```csharp
/// <summary>
/// 初期化
/// </summary>
/// <param name="isDebug">サンドボックス購入かどうか</param>
/// <param name="isClientVerify">クライアント側で購入検証を行うかどうか</param>
[UnityEngine.Scripting.Preserve]
public void Init(bool isDebug = false, bool isClientVerify = true)
{
    _paymentManager.Init(isDebug, isClientVerify);
}
```

出典：[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L96-L105)

パラメータの説明：

| パラメータ | 型 | デフォルト値 | 説明 |
|------|------|--------|------|
| `isDebug` | `bool` | `false` | サンドボックス購入モードを使用するかどうか |
| `isClientVerify` | `bool` | `true`（コンポーネント層）/ `false`（インターフェース層） | クライアント側で購入検証を行うかどうか。強ネットワーク接続でサーバー検証を行う場合は `false` を渡す必要があります |

インターフェース層の定義とコメント（サーバー検証を優先する場合は `false` を渡す）：

```csharp
/// <param name="isClientVerify">クライアント側で購入成功を検証するかどうか。強ネットワーク接続による検証の場合は有効にする必要はなく、false に設定してサーバー検証を行います</param>
[UnityEngine.Scripting.Preserve]
void Init(bool isDebug = false,bool isClientVerify = false);
```

出典：[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L37-L43)

5. `IsReady()` で決済システムの準備ができているかをポーリング／確認し、準備が整ってから購入を開始します：

```csharp
/// <summary>
/// 決済システムの準備ができているかどうか
/// </summary>
/// <returns>準備ができている場合はtrue、それ以外の場合はfalseを返します</returns>
[UnityEngine.Scripting.Preserve]
public bool IsReady()
{
    return _paymentManager.IsReady();
}
```

出典：[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L107-L115)

6. （任意）購入結果イベントを購読します。イベントはコンポーネント上で `IPaymentManager` から直接パススルーされます：`OnPurchaseSuccess`、`OnPurchaseFailed`、`OnQueryPurchasesResult`、`OnConsumePurchaseResult`、パラメータ型はすべて `EventHandler<PaymentEventArgs>` です。

出典：[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64)

## よくあるバリエーション

- **自社開発／その他チャネル実装への切り替え**：コードを修正せずに、Inspector で対応プラットフォームのシリアライズフィールド（例：`m_componentAndroidType`）を自分の実装クラスの完全名に変更します。該当クラスは `IPaymentManager` を実装している必要があります（通常は `BasePaymentManager` を継承）。コンポーネントは `Utility.Assembly.GetType(componentType)` でリフレクションによりタイプを読み込みます。
出典：[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L84-L85)
- **サンドボックス／テスト環境**：`Init(true)` を呼び出して `isDebug` を `true` に設定し、チャネルのサンドボックス購入フローを実行します。
- **サーバー側検証**：`Init(isDebug: false, isClientVerify: false)` を呼び出します。購入成功後はサーバーがレシートを検証し、クライアント側ではローカル検証を行いません。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| ログに `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).` が出力され、`IsReady()` が常に `false` のまま | 現在のプラットフォーム（Editor など）がプレースホルダー実装 `DefaultPaymentManager` にフォールバックしている | ターゲットプラットフォームが Android/iOS であること、対応するチャネルパッケージがインストールされていることを確認する。またはカスタム実装クラスを組み込む |
| ログに `Pay Manager is invalid.` が出力され、処理が中断される | `GameFrameworkEntry.GetModule<IPaymentManager>()` が null を返す。モジュールが未登録 | GameFrameX 基礎パッケージ（`com.gameframex.unity`）がインストールされているか、バージョンが一致しているかを確認する |
| 事前定義商品が有効にならない | `SetPredefinedProductIds` が `Init` の後に呼び出されている | この呼び出しを `Init` の前に移動する |
| プラットフォーム実装タイプが正しくない | Inspector のシリアライズフィールドが誤って変更されている、またはプラットフォーム切替後にマクロが有効になっていない | 上記のプラットフォームマッピング表に従ってフィールド値を確認する。プラットフォーム切替後に再コンパイルする |

プレースホルダー実装の関連ソースコード（ログとの照合用）：

```csharp
private const string NotImplWarning = "You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).";

public override void Init(bool isDebug = false, bool isClientVerify = false)
{
    Log.Warning(NotImplWarning);
}

public override bool IsReady()
{
    return false;
}
```

出典：[DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L36)

## 検証

- 初期化後に `PaymentComponent.IsReady()` を呼び出します：`true` が返されればチャネル実装の準備が整っています。Editor やチャネル未対応のプラットフォームで `false` が返されるのは想定内の動作です。
- Console に `DefaultPaymentManager which is a stub` 警告が表示されなくなれば、現在のプラットフォームで実際のチャネル実装が読み込まれていることを示します。

## 背景

`PaymentComponent` は GameFrameworkComponent です。`Awake` 内でコンパイルマクロに基づいて実装クラスの完全名を決定し、`Utility.Assembly.GetType` で `ImplementationComponentType` として解決します。インターフェース型は `IPaymentManager` に固定されており、その後 `GameFrameworkEntry.GetModule<IPaymentManager>()` によってモジュールインスタンスを取得します。コンポーネント上の `Init`、`IsReady`、`Buy` などのメソッドは、すべてこのインスタンスへの転送です。チャネル実装（Google、Apple など）のソースコードは本リポジトリには含まれておらず、対応するチャネルパッケージを別途インストールする必要があります。
