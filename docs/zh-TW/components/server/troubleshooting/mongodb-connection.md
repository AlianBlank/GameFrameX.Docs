# MongoDB 連線失敗或實體序列化出錯怎麼辦

啟動服務時遇到 `MongoDB connection failed`、`数据库服务启动失败`、`No serializer found for ...`、`An error occurred while deserializing ...` 等錯誤時，按本頁診斷表定位原因，再依對應小節修復。

## 快速診斷

| 症狀（主控台/日誌原文） | 根本原因 | 修復 |
|---|---|---|
| `数据库服务启动失败` / `MongoDB connection failed` / `TimeoutException` | `DataBaseUrl` 無法連上、帳號密碼錯誤、authSource 不相符、單機直連未開啟 `directConnection` | 見「連線組態錯誤」 |
| `MongoCommandException: Authentication failed` | 使用者名稱/密碼錯誤或目標資料庫沒有建立帳號 | 見「認證失敗」 |
| `No serializer found for type X` / `An error occurred while deserializing the X bson element ...` | 實體類別沒有註冊 BsonClassMap，或基底類別帶有 `BaseCacheState` 的欄位未忽略 | 見「實體序列化失敗」 |
| 啟動時卡住或首次 `Insert`/`Find` 拋出 `MongoConnectionException` | Docker 容器未啟動、連接埠被佔用、或服務先於 mongo 啟動 | 見「服務相依與連接埠」 |
| 寫入後欄位全是 `_t` discriminator，但讀出來是 `null` | 多個組件使用了同一完整類別名稱且未設定 `Discriminator`，或子類別未註冊 | 見「實體序列化失敗 → Discriminator 衝突」 |

## 修復步驟

### 連線組態錯誤

1. 確認組態鍵 `DataBaseUrl` 的寫法。預設透過 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L61-L65) 中的 `Setting.DataBaseUrl` 傳給 `GameDb.Init<MongoDbService>`，連線字串格式必須符合 MongoDB Driver 的要求。

2. 本機 Docker 啟動時，使用 [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L2-L13) 內建的容器組態：

   ```yaml
   mongodb:
     image: mongo
     container_name: mongodb
     ports:
       - "27017:27017"
     volumes:
       - ./running/database:/data/db
     environment:
       - MONGO_INITDB_ROOT_USERNAME=admin
       - MONGO_INITDB_ROOT_PASSWORD=admin
   ```

   對應的連線字串範例（與 compose 中的環境變數一致）：

   ```bash
   DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
   ```

   Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L60-L72)

3. 使用 [MongoDB Atlas](https://www.mongodb.com/atlas) 等雲端服務時，保持 `mongodb+srv://` 形式，並附帶 `retryWrites=true&w=majority`：

   ```csharp
   DataBaseUrl = "mongodb+srv://gameframex:***@gameframex.8taphic.mongodb.net/?retryWrites=true&w=majority",
   DataBaseName = "gameframex",
   ```

   Source: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L112-L113)

4. 本機直連 `127.0.0.1` 時若遇到 `No routing to host`，加上 `directConnection=true`：

   ```text
   mongodb://admin:admin@127.0.0.1:27017/?authSource=admin&directConnection=true
   ```

### 認證失敗

1. 檢查 `MONGO_INITDB_ROOT_USERNAME`/`MONGO_INITDB_ROOT_PASSWORD` 與連線字串中的帳號是否一致。
2. 當帳號建立在 `admin` 而目標資料庫是 `gameframex` 時，連線字串必須帶 `?authSource=admin`，否則驅動程式會用預設資料庫驗證而拋出 `Authentication failed`。
3. 自建帳號後只對單一資料庫授權：`authSource` 必須等於該資料庫名稱。

### 服務相依與連接埠

1. `docker compose up mongodb -d` 後先確認容器健康：

   ```bash
   docker ps --filter name=mongodb
   docker logs mongodb --tail 50
   ```

2. 容器與遊戲行程必須在同一個 `gameframex` 網路下；單獨執行遊戲行程時，把 `DataBaseUrl` 的主機名稱換成 `localhost` 或對應 IP。
3. 主機連接埠 `27017` 被佔用時，修改 compose 的連接埠對應（如 `"27018:27017"`），連線字串同步改成 `27018`。

### 實體序列化失敗

1. 啟動時會掃描組件內所有繼承 `BaseCacheState`/`CacheState` 的實體並註冊 BsonClassMap。註冊入口見 [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)：

   ```csharp
   var assembly = typeof(AppsHandler).Assembly;
   BsonClassMapHelper.SetConvention();
   foreach (var type in assembly.GetTypes())
   {
       if (!typeof(BaseCacheState).IsAssignableFrom(type)) continue;
       HashMap.TryAdd(XxHashHelper.Hash32(type.ToString()), type);
       BsonClassMapHelper.RegisterClass(type);
   }
   ```

   Source: [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L20-L33)

2. `BsonClassMapHelper` 會自動對應並忽略多餘欄位，參考實作 [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)：

   ```csharp
   var bsonClassMap = new BsonClassMap(t);
   bsonClassMap.AutoMap();
   bsonClassMap.SetIgnoreExtraElements(true);
   bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
   BsonClassMap.RegisterClassMap(bsonClassMap);
   ```

   Source: [BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

3. 出現 `No serializer found for type X` 時的常見原因與處理：
   - 實體類別未繼承 `BaseCacheState`，被註冊流程跳過 — 讓實體繼承 `BaseCacheState`，或在呼叫前手動 `BsonClassMap.RegisterClassMap<T>()`。
   - 實體定義在另一個組件（如 `GameFrameX.Hotfix`）中，但 `CacheStateTypeManager` 只掃描了 `AppsHandler` 組件 — 在熱更新入口同步呼叫一次註冊，或擴充掃描器以涵蓋 Hotfix 組件。
   - 實體使用了未具體化的泛型參數 — 在註冊前補齊泛型實質引數。

4. **Discriminator 衝突**：不同子型別同名、跨組件使用相同完整類別名稱，都會讓反序列化拿到 `null`。在實體類別上明確指定：

   ```csharp
   [BsonDiscriminator("player_attr_v1")]
   public sealed class PlayerAttributeState : BaseCacheState { /* ... */ }
   ```

5. **基底類別欄位污染**：若不想把 `BaseCacheState` 內建的字典/版本號欄位寫入 MongoDB，請在欄位上加 `[BsonIgnore]`；已經 `SetIgnoreExtraElements(true)` 只會忽略讀取方向，寫入仍需明確忽略。

6. 啟動順序由 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67) 保證：`GameDb.Init` → `ComponentRegister.Init` → `HotfixManager.LoadHotfixModule`。熱更新中直接讀取 Mongo 的程式碼必須放在最後一步之後，否則序列化器尚未註冊就會拋出 `No serializer found`。

## 驗證

1. 重新啟動服務，觀察啟動日誌依序出現：`开始启动数据库服务...` → `启动数据库服务 结束...` → `注册组件开始/结束` → `加载热更新模块结束`。
2. 在 Mongo Shell 或 Compass 中執行 `db.runCommand({ ping: 1 })`，應回傳 `{ ok: 1 }`。
3. 用任意實體類別的 `Insert`/`Find` 走一遍讀寫流程，斷言讀出的欄位與寫入一致。
4. 故意把 `DataBaseUrl` 改成錯誤位址再次啟動，應立即拋出 `数据库服务启动失败` 並印出根本原因堆疊 — 用來確認例外透傳鏈路是通的。
