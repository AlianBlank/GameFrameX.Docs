# How to Switch Between States

In any state class that inherits from `FsmState<T>`, call `ChangeState<TState>(fsm)` to immediately switch the active state of the current FSM. The framework will trigger the current state's `OnLeave` and the new state's `OnEnter` in order.

## Prerequisites

- The target FSM has been created via `FsmComponent.CreateFsm(...)` or `GameApp.Fsm.CreateFsm(...)`, and the target state has been passed in as a parameter.
- The target state type must inherit from `FsmState<T>`, where `T` matches the FSM's generic parameter.

## Steps

1. **Trigger switching inside the state class**: Call the protected `ChangeState<TState>(IFsm<T> fsm)` from within a class derived from `FsmState<T>`.

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

2. **When triggering from outside the state**: Use the public method `ChangeToState<TState>(IFsm<T> fsm)` on `FsmState<T>`, which internally forwards to `ChangeState<TState>(fsm)`.

   ```csharp
   fsm.CurrentState.ChangeToState<MoveState>(fsm);
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L119)

3. **When only the target state type is known**: Use the `Type` overload, passing the runtime type of the state class.

   ```csharp
   ChangeState(fsm, typeof(MoveState));
   ```

   This overload validates that the passed `Type` is assignable to `FsmState<T>`, otherwise it throws `GameFrameworkException("State type '{0}' is invalid.")`.  
   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

4. **Internal execution flow**: When `Fsm<T>.ChangeState(Type)` is called, the framework first calls the old state's `OnLeave(this, false)`, resets `m_CurrentStateTime`, replaces `m_CurrentState`, and then calls the new state's `OnEnter(this)`.

   ```csharp
   m_CurrentState.OnLeave(this, false);
   m_CurrentStateTime = 0f;
   m_CurrentState = state;
   m_CurrentState.OnEnter(this);
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L726-L729)

## Common Variants

- **Switching by string name**: First locate the state using a named API such as `FsmComponent.HasState<T>(name)`, then use the `Type` overload to switch. The public generic overload in this repository does not provide a direct name-based switching entry.
- **Chained multiple switches**: Call `ChangeState<NextState>(fsm)` immediately inside `OnEnter` to cascade switches within a single frame; however, be careful to avoid infinite recursion.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GameFrameworkException: Current state is invalid.` | `ChangeState` was called before `Start<T>()` or after the FSM was `Shutdown` | First call `fsm.Start<IdleState>()` to start the FSM |
| `FSM '...' can not change state to '...' which is not exist.` | The target state class was not passed into the `states` array of `CreateFsm` | Add the target state instance to `CreateFsm(owner, new IdleState(), new MoveState())` |
| `State type '...' is invalid.` | The type passed via the `Type` overload is not a derived class of `FsmState<T>` | Confirm the target type inherits from `FsmState<T>`, and that `T` matches the FSM |
| `OnLeave` does not receive notification after switching | The switch was written after `OnLeave` or the FSM has been destroyed | Ensure the call is made within a state lifecycle method, and the FSM is still alive |

## Background (Optional)

`ChangeState<TState>` only performs a single method forwarding internally. The actual switching logic is centralized in `Fsm<T>.ChangeState(Type)`, ensuring that all overloads go through the same `OnLeave → reset timer → replace → OnEnter` flow to avoid missed branches.
