# 全局信息接口拉取失败怎么办

启动流程进入 `ProcedureGetGlobalInfoState` 后,所有 `GlobalInfoUrls` 都无法成功返回配置(且没有可用本地缓存),会触发 `StartupFailedEventArgs` 并以 `ProcedureGetGlobalInfoState` 作为失败流程名结束启动。本文说明常见原因、定位方法与对应修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动立刻抛出 `ArgumentException`: `StartupOptions.GlobalInfoUrls must contain at least one URL.` | `StartupOptions.GlobalInfoUrls` 为 `null` 或空数组 | 见"修复步骤 1" |
| 流程跳过全局信息请求,直接进入 `ProcedurePatchInit` | `SkipRemoteStartupRequests = true`,或 `GamePlayMode` 为 `EditorSimulateMode` / `OfflinePlayMode` | 见"修复步骤 2" |
| 失败事件 `StartupFailedEventArgs` 中 `procedureName = "ProcedureGetGlobalInfoState"`,UI 提示 `Loading... (n/total)` 卡住 | URL 故障转移全部失败(网络/超时/HTTP 错误/服务端返回非成功码) | 见"修复步骤 3" |
| 第一次失败后启动仍然成功,UI 显示 `Using cached startup config...` | 上次成功的结果已通过 `StartupNetworkCacheUtility` 写入缓存,本次走兜底逻辑 | 见"修复步骤 4" |
| WebGL/单机环境无法访问后端,启动卡死在网络阶段 | 不应启用远程启动请求 | 见"修复步骤 2" 中 `SkipRemoteStartupRequests` 用法 |

`procedureName`、`failedUrl`、`errorMessage` 三个字段由 [`StartupProcedureUtility.CompleteFailure`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L162-L167) 写入 `StartupFailedEventArgs`,可用于精确定位。

## 修复步骤

### 修复步骤 1:配置了空的 `GlobalInfoUrls`

`StartupRunner.Run` 会在进入 async 状态机之前同步校验:

```csharp
// Runtime/Startup/StartupRunner.cs
if (options.GlobalInfoUrls == null || options.GlobalInfoUrls.Length == 0)
{
    throw new ArgumentException(
        "StartupOptions.GlobalInfoUrls must contain at least one URL.",
        nameof(StartupOptions.GlobalInfoUrls));
}
```

Source: [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L63-L68)

在 `StartupOptions` 资产里填入至少一个 URL:

```csharp
// Runtime/Startup/StartupOptions.cs
[Header("Network")] [Tooltip("全局信息接口 URL 主备列表，按顺序尝试。空数组视为配置错误。")]
public string[] GlobalInfoUrls = new string[0];
```

Source: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### 修复步骤 2:运行环境不应发起远程请求

`ProcedureGetGlobalInfoState.OnEnter` 里有三条早退分支,任意一条命中都会跳过全局信息接口:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode)
{
    Debug.Log("Editor simulate mode, skip global info request.");
    ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
    return;
}

if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}

if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L28-L48)

对应处理:

| 场景 | 应设置 | 备注 |
|------|--------|------|
| 编辑器模拟模式 | `GamePlayMode = EPlayMode.EditorSimulateMode` | 只在编辑器生效,非编辑器下 `StartupRunner.NormalizeAssetPlayMode` 会改写为 `HostPlayMode` |
| 离线模式 | `GamePlayMode = EPlayMode.OfflinePlayMode` | 直接进入 `ProcedurePatchInit`,不再尝试远程 |
| WebGL 单机 / 无后端 | `SkipRemoteStartupRequests = true` | 字段说明见 [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31) |

### 修复步骤 3:URL 故障转移全部失败

`GetGlobalInfoAsync` 通过 [`UrlFailoverRunner.ExecuteAsync`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L67-L92) 按顺序尝试 `GlobalInfoUrls`,每个 URL 内部最多 `MaxAttemptsPerUrl` 次,每次间隔 `RetryDelayMs` 毫秒。任意一次 HTTP 异常或 `responseGlobalInfo.IsSuccess == false` 都视为该次失败:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var json = await GameEntry.GetComponent<WebComponent>().PostToString(url, jsonParams);
var responseGlobalInfo = json.Result.ToHttpJsonResultData<ResponseGlobalInfo>();
if (!responseGlobalInfo.IsSuccess)
{
    return UrlAttemptResult.Fail("Global info server returned code " + responseGlobalInfo.Code);
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L75-L84)

按下列顺序排查:

1. 在 `StartupOptions` 中确认至少填入一个可访问的 URL,并按"主→备"顺序排列。
2. 在浏览器/Postman 直接 `POST` 该 URL,使用同样的 `jsonParams`(通过 `StartupProcedureUtility.CreateHttpParams` 生成),确认服务端返回 `IsSuccess == true`。
3. 检查 `MaxAttemptsPerUrl`(默认 3)与 `RetryDelayMs`(默认 3000)是否过小,导致弱网下过早耗尽尝试次数:

   ```csharp
   // Runtime/Startup/StartupOptions.cs
   public int MaxAttemptsPerUrl = 3;
   public int RetryDelayMs = 3000;
   ```
   Source: [Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L26-L28)

4. 在 `IStartupHttpParamsProvider` 中确认 `PackageName` / `Channel` / `SubChannel` 等公共参数被服务端正确识别,缺失或错误也可能让服务端返回非成功码。

### 修复步骤 4:启用本地缓存兜底

当所有 URL 都失败时,`GetGlobalInfoAsync` 会尝试读取上次成功写入的缓存;命中即继续启动:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (!result.Success)
{
    if (StartupNetworkCacheUtility.TryApplyCachedGlobalInfo())
    {
        uiHandler?.SetTipText("Using cached startup config...");
        ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
        return;
    }

    StartupProcedureUtility.CompleteFailure(
        procedureOwner,
        nameof(ProcedureGetGlobalInfoState),
        result.FailedUrl,
        result.ErrorMessage);
    return;
}
```

Source: [Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L94-L109)

- 缓存键为 `GameFrameX.Startup.NetworkCache.GlobalInfo`,由 [`StartupNetworkCacheUtility`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupNetworkCacheUtility.cs#L23) 维护。
- 如果希望弱网下也能继续启动,先让程序在良好网络环境跑一次完整流程以写入缓存,然后保留兜底逻辑。
- 如果希望"网络失败立即报错"而不是走缓存,在调用方拿到 `StartupResult` 时显式判断 `ProcedureName == "ProcedureGetGlobalInfoState"` 并提示用户检查网络。

## 验证

1. 重新启动应用,确认启动流程不再因全局信息接口失败而中断。
2. 在启动失败时检查 `StartupFailedEventArgs`:`procedureName` 应不再是 `ProcedureGetGlobalInfoState`,或者启动走 `Using cached startup config...` 路径完成。
3. 在 `StartupOptions` Inspector(由 [`StartupOptionsInspector`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Editor/StartupOptionsInspector.cs#L24-L66) 提供可拖拽排序 UI)中确认 `GlobalInfoUrls` 顺序正确,无空字符串。
