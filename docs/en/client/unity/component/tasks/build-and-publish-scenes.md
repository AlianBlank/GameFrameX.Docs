# How to Build and Publish the Launcher / LauncherAuto Scenes

This page explains the key points for building and publishing the two launch scenes in GameFrameX.Unity, `Assets/Scenes/Launcher.unity` and `Assets/Scenes/LauncherAuto.unity`, including their index positions in Build Settings, the UI components they host, and common handling when publishing to standalone platforms.

## Prerequisites

- Unity Editor is installed (matching the version declared in the repository's `ProjectSettings/`).
- The project has been opened via Unity Hub, and the directory contains the two scene files `Assets/Scenes/Launcher.unity` and `Assets/Scenes/LauncherAuto.unity`.
- The GameFrameX framework runtime is installed, and the `UILauncher` component script preset in the scenes is available.

## Steps

### 1. Open File → Build Settings

In the Unity menu bar, select `File` → `Build Settings`. In the `Scenes In Build` list, confirm that `Launcher` and `LauncherAuto` have been added, and that `Launcher` is typically the first launch scene at index 0.

### 2. Verify the Scene Files Exist

Confirm that the following two files exist in the project; this is a prerequisite for the subsequent build artifacts to include the launch scenes:

- [Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity)
- [Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity)

### 3. Check the UILauncher Component in the Launcher Scene

`Launcher.unity` has the `UILauncher` script component attached, which is responsible for the launcher UI and version detection logic. The file retains the component reference:

```yaml
propertyPath: m_Name
value: UILauncher
```

Reference source: [Assets/Scenes/Launcher.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/Launcher.unity#L1158)

After opening the scene, you should see the `UILauncher` component on the GameObject at the top of the Hierarchy, with fields including version number, hot update URL, server list, etc. If the fields are empty, configure them in the Inspector before publishing.

### 4. Handle the Build Settings of the LauncherAuto Scene

`LauncherAuto.unity` internally declares its own `m_BuildSettings` section in YAML form (serialized version 3). Unity uses this section to record whether the scene participates in the build as well as the lighting/Lightmap settings. Opening the file directly shows:

```yaml
m_BuildSettings:
  serializedVersion: 3
```

Reference source: [Assets/Scenes/LauncherAuto.unity](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scenes/LauncherAuto.unity#L105-L107)

If you need to disable this scene in Build Settings, you can adjust the `m_Scenes` reference under `m_BuildSettings` or simply uncheck it in the Unity editor.

### 5. Select the Target Platform and Build

In Build Settings, select the target platform (Windows, Android, iOS, macOS, etc.), then click `Build` or `Build And Run`. Unity will package both `Launcher` and `LauncherAuto` into the Player binary, following the order in `Scenes In Build`.

### 6. Verify the Artifacts

After the build completes, check the output directory for:

- The executable launches normally and enters the `Launcher` scene;
- `LauncherAuto` is loaded when configured to automatically skip the UI;
- The version number and hot update URL on the launcher interface are displayed correctly.

## Common Variants

- **LauncherAuto auto scene skipping**: If you want to enter the business scene directly after launch instead of showing the UI launcher, you can enable `LauncherAuto` in Player Settings → Other Settings. This scene is typically used for UI-less automated launch flows.
- **Trimming scenes by platform**: For weaker platforms such as WebGL, you can remove `LauncherAuto` from Build Settings and keep only `Launcher`; conversely, for standalone clients, both can be checked together.
- **Replacing UILauncher fields**: Different publishing channels use different hot update URLs; simply switch the configuration on the `UILauncher` script temporarily before building.

## Common Errors

- **Black screen on launch after build**: Usually caused by unconfigured `UILauncher` component fields (empty version number or hot update URL), resulting in launcher initialization failure.
- **Missing scene in Scenes In Build**: When manually adding new scenes, removing `Launcher` or `LauncherAuto` from the list will cause the launcher to be skipped at runtime and throw an error directly.
- **Scene GUID conflicts**: When copying .unity files directly, keeping the original `m_SceneGUID` will cause Build Settings references to become corrupted. Always let Unity re-import and generate a new GUID.

## Background (Optional)

`Launcher` and `LauncherAuto` form GameFrameX's dual launch scene combination: `Launcher` provides a UI-based launcher responsible for version checking, hot updates, and server selection; `LauncherAuto` is a background or automated launch scene that skips the UI and loads business logic directly. `m_BuildSettings` is the metadata section in Unity scene files describing build participation status, read by both the Editor and the Player.
