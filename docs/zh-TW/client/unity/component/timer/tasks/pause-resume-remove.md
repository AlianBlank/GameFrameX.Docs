# 暫停、恢復與移除定時器

對已經建立的定時器，`TimerManager` 提供按 ID 的 `Pause` / `Resume` / `Remove`、按標籤的 `PauseByTag` / `ResumeByTag` / `RemoveByTag`，以及配套查詢（`IsPaused`、`Exists`、`HasTag`、`GetRemaining` 等）。全部 API 定義在 `ITimerManager` 介面上，直接在取得的 `ITimerManager` 實例上呼叫即可。

## 前置條件

- 專案已接入 GameFrameX Timer 元件，並持有 `ITimerManager` 實例（元件入口見 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs)）。
- 已透過 `Add` / `AddOnce` / `AddUpdate` 建立定時器，並儲存了回傳的 `int` 型別定時器 ID；或建立時指定了 `tag` 標籤。

## 操作步驟

### 1. 暫停與恢復單一定時器

```csharp
ITimerManager timer; // 由 GameFrameX 元件取得

// interval=1 秒，repeat=0 表示無限重複
int id = timer.Add(1f, 0, obj => { /* 週期邏輯 */ });

timer.Pause(id);              // 暫停期間不累積時間
bool paused = timer.IsPaused(id);  // true

timer.Resume(id);             // 從暫停處繼續累積時間，已累積的時間不會遺失
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L74-L91)

### 2. 移除單一定時器

```csharp
timer.Remove(id);                        // 按 ID 移除
timer.Remove(new Action<object>(OnTick)); // 按回呼移除

bool alive = timer.Exists(id);           // 移除後回傳 false
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L48-L72)

`Remove(int id)` 內部先把 ID 對應到回呼，再執行與 `Remove(Action<object>)` 相同的移除路徑，因此兩種移除方式效果一致：

```csharp
public void Remove(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return;
        }

        Remove(callback);
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L376-L387)

### 3. 按標籤批次暫停、恢復與移除

建立定時器時傳入 `tag`，之後可以整組操作，適合「場景切換時暫停戰鬥相關定時器」這類需求：

```csharp
int id = timer.Add(5f, 0, obj => { /* ... */ }, null, "battle");

timer.PauseByTag("battle");   // 暫停該標籤下所有定時器
timer.ResumeByTag("battle");  // 恢復該標籤下所有定時器
timer.RemoveByTag("battle");  // 移除該標籤下所有定時器

bool anyLeft = timer.HasTag("battle"); // 標籤下還有活躍定時器時為 true
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L93-L118)

`RemoveByTag` 內部會複製標籤下的 ID 清單後逐一呼叫 `Remove(id)`，避免迭代中被修改：

```csharp
public void RemoveByTag(string tag)
{
    lock (Locker)
    {
        if (_tags.TryGetValue(tag, out var ids))
        {
            // Copy to avoid modification during iteration
            var idsCopy = new List<int>(ids);
            foreach (var id in idsCopy)
            {
                Remove(id);
            }
        }
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)

### 4. 驗證狀態

| API | 回傳值 | 說明 |
|------|--------|------|
| `IsPaused(int id)` | `bool` | 暫停中回傳 `true`；ID 不存在回傳 `false` |
| `Exists(int id)` / `Exists(Action<object> callback)` | `bool` | 定時器存在且未刪除回傳 `true` |
| `HasTag(string tag)` | `bool` | 標籤下至少存在一個定時器回傳 `true` |
| `GetRemaining(int id)` | `float` | 剩餘秒數；ID 不存在或尚未生效回傳 `-1`；`interval <= 0` 或無限循環回傳 `0` |
| `GetElapsed(int id)` | `float` | 已累積秒數；ID 不存在回傳 `-1` |
| `GetRepeatLeft(int id)` | `int` | 剩餘重複次數（`0` 表示無限）；ID 不存在回傳 `-1` |

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L120-L142)

## 常見變體

**非同步等待的取消。** 若使用 `WaitForSecondsAsync` 等擴充方法，「移除」透過 `CancellationToken` 完成：權杖取消時 `TaskCompletionSource` 會被設定為取消狀態，等待方收到取消的 Task。

```csharp
var tcs = new TaskCompletionSource<bool>();
var registration = cancellationToken.Register(() => tcs.TrySetCanceled(cancellationToken));
```

Source: [TimerAsyncExtensions.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerAsyncExtensions.cs#L26-L34)

## 常見錯誤

- **對不存在或已移除的 ID 呼叫 `Pause` / `Resume` / `Remove`**：實作內部直接 `return`，不會拋出例外，但也不會有任何效果；操作後用 `Exists(id)` 複核。
- **剛 Add 就立即 `Pause(id)` 可能不生效**：若定時器還停留在待加入佇列（`_toAdd`）中，`Pause` 會在設定旗標前直接回傳，屬於 no-op；待其進入活躍清單後再暫停即可。

  ```csharp
  // Timer in _toAdd (pending): also pausable
  if (_toAdd.ContainsKey(callback))
  {
      return;
  }
  ```

  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L404-L413)
- **`GetRemaining(id)` 回傳 `-1` 不一定是異常**：ID 不存在、已被移除，或定時器尚未進入活躍清單時都回傳 `-1`（見 `GetRemaining` 實作的回傳路徑）。
- **移除會觸發 `onComplete`**：`Add(..., Action onComplete = null)` 的介面註解標明該回呼在「定時器完成/移除時」觸發，主動 `Remove` 時需預期它會被呼叫。
- **暫停 ≠ 移除**：暫停的定時器仍保留在管理器條目清單中，只是跳過時間累積，不釋放；確定不再使用時應呼叫 `Remove`。

## 背景

`TimerManager` 內部為每個定時器維護一個條目（`Deleted`、`IsPaused`、`PausedElapsed` 等欄位），更新迴圈中遇到 `IsPaused == true` 的條目會跳過已用時間累積但保留其在 `_items` 中，因此恢復後能從暫停處繼續。所有暫停/恢復/移除操作均在 `lock (Locker)` 保護下執行，可在非主執行緒安全呼叫。
