# 國密 SM2/SM3/SM4 的使用方法

`GameFrameX.Foundation.Encryption` 提供了國密三大演算法的一站式入口：`Sm2Helper`（非對稱加密 / 解密 / 金鑰配對產生）、`Sm4Helper`（對稱加密 / 解密，支援 CBC / ECB），以及基於 BouncyCastle 的 `SM3Util.Hash`（SM3 摘要）。本頁面說明三種演算法的最小使用程式碼範例，以及常見的陷阱。

## 前置條件

- 參考命名空間：`GameFrameX.Foundation.Encryption`、`GameFrameX.Foundation.Encryption.Sm`。
- 專案需參考 BouncyCastle（`Org.BouncyCastle.*`）。框架已預設包含。
- SM2 的公鑰 / 私鑰為十六進位字串。SM4 的金鑰在非 hex 模式下需為 16 位元組，在 hex 模式下需為 32 個十六進位字元。

## 操作步驟

### 1. SM3 雜湊

SM3 是雜湊演算法，而非加密演算法。`SM3Util.Hash` 接收字串，回傳固定長度（256 位元）的十六進位摘要。內部使用 UTF-8 編碼，以確保跨平台的一致性。

```csharp
using GameFrameX.Foundation.Encryption.Sm;

string hash = SM3Util.Hash("hello world");
// 對同一輸入多次呼叫的結果一致，可用於完整性驗證
```

來源: [SM3Util.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm/SM3Util.cs#L47-L69)

### 2. SM2 非對稱加密

`Sm2Helper` 提供字串與位元組陣列兩套多載，亦支援產生金鑰配對。內部基於 BouncyCastle 實作。

```csharp
using GameFrameX.Foundation.Encryption;

// 產生金鑰配對
Sm2Helper.GenerateKeyPair(out string publicKey, out string privateKey);

// 使用公鑰加密
string cipher = Sm2Helper.Encrypt(publicKey, "secret message");

// 使用私鑰解密
string plain = Sm2Helper.Decrypt(privateKey, cipher);
```

位元組陣列多載（適用於二進位資料 / 網路協定）：

```csharp
byte[] pubKeyBytes = Convert.FromHexString(publicKey);
byte[] data = System.Text.Encoding.UTF8.GetBytes("payload");
string cipherHex = Sm2Helper.Encrypt(pubKeyBytes, data);
byte[] plainBytes = Sm2Helper.Decrypt(Convert.FromHexString(privateKey), Convert.FromHexString(cipherHex));
```

來源: [Sm2Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm2Helper.cs#L62-L174)

### 3. SM4 對稱加密

`Sm4Helper` 預設採用 CBC 模式。金鑰長度規則：非 hex 模式為 16 位元組，hex 模式為 32 個字元。若未傳入 `iv`，hex 模式下預設填入全 0（`00000000000000000000000000000000`）。

CBC 加密 / 解密：

```csharp
using GameFrameX.Foundation.Encryption;

string key = "0123456789abcdef";        // 16 位元組
string cipher = Sm4Helper.EncryptCbc(key, "明文內容");
string plain  = Sm4Helper.DecryptCbc(key, cipher);
```

ECB 模式（無需 IV）：

```csharp
string cipher = Sm4Helper.EncryptEcb(key, "明文內容");
string plain  = Sm4Helper.DecryptEcb(key, cipher);
```

JavaScript 相容模式（用於與前端 sm-crypto 等程式庫互通的填充行為）：

```csharp
string cipher = Sm4Helper.EncryptCbc(key, "明文", forJavascript: true);
string plain  = Sm4Helper.DecryptCbc(key, cipher, forJavascript: true);
```

hex 金鑰模式：

```csharp
string hexKey = "0123456789ABCDEF0123456789ABCDEF"; // 32 個十六進位字元
string cipher = Sm4Helper.EncryptCbc(hexKey, "明文", hexString: true);
```

來源: [Sm4Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm4Helper.cs#L64-L105)
來源: [Sm4Helper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/Sm4Helper.cs#L163-L195)

## 常見變化情境

| 情境 | 建議做法 |
|------|----------|
| 與前端 / Node 互通 | SM4 使用 `forJavascript: true`，前端則使用 sm-crypto 的相同模式 |
| 長訊息的簽章驗證 | 先以 `SM3Util.Hash` 取得摘要，與業務欄位一併送出後比對 |
| 高頻率的二進位流加密 / 解密 | 使用 SM2 / SM4 的位元組陣列多載，避免字串編碼 / 解碼的額外開銷 |
| SM2 金鑰的持久化 | 直接儲存 `GenerateKeyPair` 輸出的十六進位字串，不要自行處理 Base64 |

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `ArgumentException: KeyMustBe16Characters` | 非 hex 模式下的 SM4 金鑰不是 16 位元組 | 調整字串長度，或改用 `hexString: true` 搭配 32 字元的 hex |
| `ArgumentException: KeyMustBe32Characters` | hex 模式的金鑰長度不是 32 | 確認 hex 字串沒有被截斷，也沒有多餘的字元 |
| SM2 解密擲回 `CryptographicException(Sm2InvalidDataFormat)` | 公鑰 / 私鑰不匹配，或密文被誤做二次編碼 | 確認加密 / 解密兩側的十六進位大小寫一致，且未進行不必要的 Base64 轉換 |
| SM3 雜湊在不同平台結果不同 | 輸入被以 `Encoding.Default` 重新編碼 | 務必以 UTF-8 編碼傳入。`SM3Util.Hash` 內部已統一使用 UTF-8 |
| `ArgumentException(PublicKeyStringCannotBeEmpty)` | SM2 公鑰字串為空 | 確認 `GenerateKeyPair` 的輸出未被截斷 |

## 背景（可選）

`Sm2Helper` / `Sm4Helper` 是面向業務的薄封裝層，所有底層邏輯（橢圓曲線點運算、SM4 輪金鑰擴展等）皆由 BouncyCastle 處理。`SM3Util` 則直接重複使用 BouncyCastle 的 `Sm3Digest`。三種例外會在 `Sm*Helper` 層被捕捉，並統一包裝為 `CryptographicException`，因此上層可用單一型別一併捕捉。
