# MVVM バインディングとイベントの自動クリーンアップ

FairyGUI の UI で `BindableProperty<T>` を使ってデータバインディングを行う際、拡張メソッド `ClearWithGObjectDestroyed` を呼び出すだけで、イベントのクリーンアップを `GObject` の `onRemovedFromStage` に紐付けることができます。GObject が表示リストから離脱したとき(破棄を含む)に `bindableProperty.Clear` が自動的に実行されるため、登録解除ロジックを手書きする必要がなく、イベントの残留やメモリリークを防げます。

## 前提条件

- `com.gameframex.unity.fairygui` パッケージがインストール済みであること(README の依存関係表を参照:`com.gameframex.unity` 1.1.1、`com.gameframex.unity.ui` 1.0.0 など)。
- `BindableProperty<T>` は GameFrameX コアパッケージに属し、名前空間は `GameFrameX.Runtime` です。拡張メソッド自体は `GameFrameX.UI.FairyGUI.Runtime` にあります。
- UI クラスが `FUI` を継承していること(`FUI` は `GObject` プロパティを公開しています。[FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L43-L53) を参照)。

## 操作手順

1. UI/ロジッククラスでバインディングプロパティ(例:`BindableProperty<int>`、`BindableProperty<string>` など)を作成し、そのイベントを購読してデータバインディングを完了します。

2. この UI とライフサイクルが一致する `GObject` を取得した後、拡張メソッドを呼び出して自動クリーンアップを登録します:

```csharp
// GObject 破棄時に自動的にイベントを解除
myProperty.ClearWithGObjectDestroyed(gObject);
```

出典: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L123-L128)

3. その後は通常どおり UI を閉じる/破棄するだけでよく、バインディングプロパティのイベントを手動で解除する必要はありません。

拡張メソッドの完全な実装は以下の通りです(仕組み全体は登録 1 行だけです):

```csharp
[UnityEngine.Scripting.Preserve]
public static void ClearWithGObjectDestroyed<T>(this BindableProperty<T> bindableProperty, GObject gObject)
{
    gObject.onRemovedFromStage.Add(bindableProperty.Clear);
}
```

出典: [BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L52-L56)

## よくあるバリエーション

- **FUI サブクラスでのバインディング**:`FUI` を継承した UI は、自身の `GObject` をそのままライフサイクルのアンカーとして使用できます。例えば、バインディングの初期化箇所で `myProperty.ClearWithGObjectDestroyed(GObject);` を呼び出せば、UI 破棄時にイベントも一緒にクリアされます。
- **任意のジェネリック型に対応**：このメソッドはジェネリック拡張のため、`BindableProperty<int>`、`BindableProperty<string>` など任意の `T` で直接呼び出せます。型ごとにクリーンアップコードを書く必要はありません。

## よくあるエラー

| 症状 | 原因 | 回避方法 |
|------|------|----------|
| UI 破棄後もバインディングイベントが発生し続け、オブジェクトが回収されない | `ClearWithGObjectDestroyed` の呼び出しを忘れ、購読がバインディングプロパティに残ったままになる | バインディングプロパティのイベントを購読するたびに、直ちに同じ GObject でこの拡張メソッドを一度呼び出す |
| `NullReferenceException` | 渡した `gObject` が null(UI がまだ GObject を生成していないうちに呼び出した)| GObject の初期化が完了してから呼び出すこと。`FUI.Visible` の実装からも `GObject` が null になりうることがわかります([FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L135-L149)) |
| イベントが「まだ破棄されていないように見える」タイミングでクリアされる | 発火のフックは `onRemovedFromStage`(表示リストからの離脱)であり、破棄だけではない。オブジェクトを表示リストから外す操作はすべて `Clear` を発火する | GObject を動的に表示リストから外して再利用する場合は、表示リストに再追加した後で再バインドし、このメソッドを再度呼び出すこと |

## 検証

- UI を閉じた後にバインディングプロパティの値を変更し、UI コールバックが一切発生しないことを確認します。
- `Clear` が効く前後でメモリプロファイラ(Unity Memory Profiler など)を使って比較し、UI 関連のオブジェクトが回収可能であることを確認します。

## 背景

この仕組みは意図的に極めてシンプルに作られています。FairyGUI の `GObject.onRemovedFromStage` イベントを利用し、`BindableProperty.Clear` をコールバックとして登録します([BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L55))。バインディングプロパティ自体は GameFrameX コアパッケージ(`GameFrameX.Runtime` 名前空間)に属し、UI 層はそれと GObject のライフサイクルの間に「破棄したら即クリーンアップ」という関連付けを構築するだけです。メソッドには `[UnityEngine.Scripting.Preserve]` が付与されており、コードストリッピングによる削除を防いでいます。
