# 생성 스크립트 실행 방법(클라이언트/서버)

저장소 루트 디렉터리의 `gen-*.bat` 또는 `gen-*.sh` 스크립트를 실행하면 `Excels/`의 Excel 표를 클라이언트(Unity) 또는 서버(.NET)에서 바로 사용할 수 있는 코드와 데이터 파일로 자동 변환할 수 있습니다. 이 페이지에서는 네 가지 스크립트의 차이점, 최소 실행 단계, 그리고 자주 발생하는 오류의 해결 방법을 설명합니다.

## 네 가지 생성 스크립트 개요

저장소에는 4개의 생성 진입점이 포함되어 있으며, **대상 엔드**(`client` / `server`)와 **출력 형식**(`bin` / `json`)의 조합으로 구성됩니다:

| 스크립트 | 대상 엔드 | 데이터 형식 | 코드 형식 | 출력 위치(데이터 / 코드) |
|------|--------|----------|----------|------------------------|
| `gen-client-bin.sh` / `.bat` | 클라이언트 | 바이너리(`bin`) | C# 바이너리 직렬화(`cs-bin`) | `../Unity/Assets//Bundles/Config` / `../Unity/Assets//Hotfix/Config/Generate` |
| `gen-client-json.sh` / `.bat` | 클라이언트 | JSON | C# | `Unity/Assets/Bundles/Config` / `Unity/Assets/Hotfix/Config/Generate` |
| `gen-server-bin.sh` / `.bat` | 서버 | 바이너리(`bin`) | C# .NET 바이너리 직렬화(`cs-dotnet-bin`) | `../Server/GameFrameX.Config/Json` / `../Server/GameFrameX.Config/Config` |
| `gen-server-json.sh` / `.bat` | 서버 | JSON | C# | `Server/GameFrameX.Config/Json` / `Server/GameFrameX.Config/Config` |

> `c` = 클라이언트(client), `s` = 서버(server), `bin` = 바이너리, `json` = 텍스트. 동일한 엔드에서 `bin`은 크기가 더 작고 로드가 더 빠르며, `json`은 가독성이 좋아 데이터를 점검하기 편리합니다.

## 사전 조건

- **.NET SDK**가 설치되어 있어야 합니다(스크립트가 `dotnet`을 통해 `./Tools/Luban.dll`을 실행하기 때문입니다).
- 저장소의 `Tools/Luban.dll`, `luban.conf`, `Defines/builtin.xml`, `Excels/__tables__.xlsx`(및 `__beans__`, `__enums__`)는 반드시 원래 위치에 있어야 하며, 이동하지 마세요.
- 표가 규칙에 따라 작성되어 있어야 합니다(`Excels/Tables/`의 표 이름 형식은 `字母-英文名-中文名.xlsx`이며, 영문명에는 중국어를 포함할 수 없습니다).

## 작업 단계

1. 터미널 / 명령줄을 열고, **저장소 루트 디렉터리로 `cd`**하세요(`gen-*.sh`, `gen-*.bat`가 보이는 계층). 스크립트 내의 상대 경로는 모두 이 디렉터리를 기준으로 하므로, 하위 디렉터리에서 실행하지 마세요.

2. 대상 엔드와 출력 형식을 선택하고, 해당 스크립트를 실행하세요:

   - **클라이언트 JSON 생성(가장 많이 사용되는 입문 명령):**

     ```bash
     sh gen-client-json.sh
     ```

     해당하는 Windows 명령은 `gen-client-json.bat`를 더블클릭하는 것입니다.

   - **클라이언트 바이너리 생성:**

     ```bash
     sh gen-client-bin.sh
     ```

     [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1)의 핵심 호출은 다음과 같습니다:

     ```bash
     dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin \
       --xargs outputDataDir=../Unity/Assets//Bundles/Config \
       --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
       --xargs tableImporter.name=gameframex \
       -x l10n.provider=gameframex \
       -x l10n.textFile.keyFieldName=key \
       -x l10n.textFile.path=./Excels/Local/ \
       --conf ./Luban.conf
     ```

     Source: [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1)

   - **서버 바이너리 생성:**

     ```bash
     sh gen-server-bin.sh
     ```

     실제 호출은 [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1)를 참고하세요:

     ```bash
     dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin \
       --xargs outputDataDir=../Server/GameFrameX.Config/Json \
       --xargs tableImporter.name=gameframex \
       --xargs outputCodeDir=../Server/GameFrameX.Config/Config \
       --conf ./Luban.conf
     ```

     Source: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1)

   - **서버 JSON 생성:** `sh gen-server-json.sh`를 실행하세요(해당 `.bat` 있음).

3. 스크립트가 완료될 때까지 기다립니다. 마지막에 `pause`(Windows `.bat`)에서 멈추거나 빨간색 오류가 없으면 성공입니다.

4. 결과물 확인:
   - 클라이언트: `Unity/Assets/Hotfix/Config/Generate/` 아래에 자동 생성된 C# 클래스(예: `TbAchievementConfig.cs`)가 있어야 하고, `Unity/Assets/Bundles/Config/` 아래에 데이터 파일이 있어야 합니다.
   - 서버: `Server/GameFrameX.Config/Config/` 아래는 C# 클래스, `Server/GameFrameX.Config/Json/` 아래는 데이터 파일입니다.

## 일반적인 변형

- **한쪽 엔드에만 생성하고 싶은 경우:** 표 이름에 그룹 표시를 추가하면 되며, 스크립트를 바꿀 필요가 없습니다. 예를 들어 `D-ItemConfig-道具表.xlsx`는 클라이언트와 서버 모두 생성하고, `D-ItemConfig-c-道具表.xlsx`는 클라이언트에만, `D-ItemConfig-s-道具表.xlsx`는 서버에만 생성합니다. 자세한 내용은 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md)를 참고하세요.
- **다국어 텍스트(Excels/Local/)를 수정한 경우:** 같은 스크립트를 다시 실행하면 되며, 어떤 것도 재시작할 필요가 없습니다.
- **표 헤더(필드명/타입)를 수정한 경우:** 스크립트 재실행 → 코드 재생성 → 호출 측에서 새 필드명에 맞춰 컴파일.
- **bin과 json 전환:** 동일한 대상 엔드에서 `gen-client-bin.sh`를 `gen-client-json.sh`로 바꾸어 다시 실행하면 됩니다. 클라이언트 런타임에서 형식을 전환하는 경우, 로드 코드도 함께 업데이트하는 것을 잊지 마세요.

## 자주 발생하는 오류

- **`'dotnet' is not recognized` / `dotnet: command not found`**: .NET SDK가 설치되지 않았거나, 터미널의 PATH에서 찾지 못한 것입니다. 먼저 .NET 6+ SDK를 설치한 후 터미널을 다시 여세요.
- **`Could not find ./Tools/Luban.dll`**: 현재 디렉터리가 잘못되었습니다. `Tools/`가 포함된 저장소 루트 디렉터리로 `cd`한 후 다시 실행하세요.
- **`不支持中文表名` / 클래스명이 이상한 문자가 되는 경우**: 파일명의 영문 부분에 중국어를 썼기 때문입니다. `字母-英文名-中文名.xlsx` 형식으로 바꾸고, 영문명에는 알파벳, 숫자, 언더스코어만 남기세요.
- **출력 디렉터리에 오래된 파일이 남아 있어 삭제된 필드를 참조하는 경우**: `outputCodeDir`가 가리키는 디렉터리(예: `Unity/Assets/Hotfix/Config/Generate/`)를 통째로 삭제한 후 스크립트를 다시 실행하세요.
- **`failed: conf file` / 설정 오류**: `luban.conf`를 수정하여 파싱에 실패한 것입니다. Git에서 해당 파일을 복원한 후 재시도하고, 최상위 필드를 함부로 수정하지 마세요.
- **다국어 key를 `text` 필드에서 읽었는데 여전히 key 자체로 나오는 경우**: 실행한 것이 `gen-client-bin.sh` 또는 `-x l10n.provider=gameframex -x l10n.textFile.path=./Excels/Local/` 매개변수 세트가 포함된 명령인지, `--conf ./Luban.conf`만 사용한 명령은 아닌지 확인하세요.

## 배경(선택 사항)

네 가지 스크립트는 본질적으로 모두 `dotnet ./Tools/Luban.dll`을 호출하며, 차이는 세 가지 스위치에만 있습니다: `--target`(client 또는 server 중 어느 쪽의 코드 템플릿과 데이터 타입 매핑을 사용할지 결정), `--dataTarget`(데이터 저장 형식 `bin` 또는 `json` 결정), `--codeTarget`(생성되는 C# 직렬화 방식 결정, 예: `cs-bin`, `cs-dotnet-bin`). `outputDataDir`와 `outputCodeDir`는 산출물의 저장 위치를 제어하며, `--conf ./Luban.conf`는 프로젝트 수준의 설정을 가리킵니다. `gen-client-bin.sh`가 `gen-server-bin.sh`보다 몇 개의 `-x l10n.*` 매개변수를 더 가지는 이유는, Unity 엔드에서 `text` 필드의 다국어 key를 현재 언어의 문자열로 직접 파싱해야 하기 때문에 스크립트에 로컬라이제이션 제공자를 명시적으로 주입했기 때문입니다.
