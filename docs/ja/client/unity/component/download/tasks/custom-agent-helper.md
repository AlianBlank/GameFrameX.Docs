# カスタムダウンロードエージェントヘルパー

`IDownloadAgentHelper` インターフェイスを実装することで、デフォルトのダウンロードバックエンド（プロキシの取得、ファイルのディスク書き込み、ストリーム読み取りなどの動作）を置き換えたり拡張したりできます。

## 前提条件

- `Microsoft.Kiota.Authentication.Azure` または関連する Kiota 認証パッケージがプロジェクトに追加済みであること。
- 対象プロジェクトが C# / .NET を使用しており、依存性の注入と `IHttpClient` のライフサイクルを理解していること。
- ダウンストリーム呼び出し元として使用可能な `IAuthenticationProvider` インスタンスが既にあること。

## 操作手順

1. 新しいクラスを作成し、`IDownloadAgentHelper` インターフェイスの 3 つのメンバーを実装します（具体的なシグネチャはソースコードを参照）。
2. コンストラクターで必要な依存関係（`IHttpClient`、`IAuthenticationProvider`、`ILogger` など）を注入します。
3. 実装のインスタンスをシングルトンまたはスコープ付きで `IServiceCollection` に登録します。
4. リクエスト実行前に、このヘルパーを必要とする呼び出し元（例： `KiotaClientFactory` の関連オーバーロード）に渡します。
5. 最小構成のダウンロードリクエストを発行し、カスタムロジック（ログ、ブレークポイント、ファイルパス）が有効になっているかを確認します。

## 一般的なバリエーション

- **ログラッパー**： 元の実装の外側にレイヤーを追加し、ログ/テレメトリのみを追加し、残りは転送します。
- **パスの書き換え**： テナントまたはユーザーコンテキストに基づいて、一時ファイルを分離ディレクトリに保存します。
- **ストリーミングチャンク**： チャンクサイズと並行度をカスタマイズし、デフォルトの `BufferSize` の動作をオーバーライドします。

## よくあるエラー

| 症状 | 考えられる原因 | 対処 |
|------|---------|------|
| 登録後に有効にならない | デフォルトの登録が置き換えられていない、またはスコープが一致していない | `services.AddSingleton<>` / `AddScoped<>` の選択を確認 |
| ダウンロード失敗時にエラー情報がない | `HttpRequestException` がキャッチ・転送されていない | `DownloadAsync` 内で `try/catch` をラップして記録する |
| ファイルが使用中 | ストリームが解放されていない | `await using` または明示的な `Dispose()` |
| 認証ヘッダーが欠落 | `GetAuthenticationProvider` 内でダウンストリームプロバイダーが呼び出されていない | 置き換えずに転送する |

## 背景（任意）

`IDownloadAgentHelper` は、Kiota が抽象化したダウンロード機能の拡張ポイントです。デフォルトの実装は `HttpClient` を使用し、カスタム実装では認証、リトライ、ディスク書き込みポリシーなどの横断的な関心事を組み込むことができます。このページでは組み込み方法のみを説明し、認証プロバイダーの全体設計についてはここでは扱いません。
