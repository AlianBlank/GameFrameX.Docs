# AES 暗号化/復号化の使用方法

`AesHelper` は AES-GCM ベースの認証付き暗号化/復号化機能を提供します。平文と鍵を渡すだけで Base64 暗号文が取得でき、同じ鍵で復号化すれば元の平文に戻せます。暗号化ごとに Salt と Nonce がランダム生成されるため、呼び出し側で管理する必要はありません。

## 前提条件

- プロジェクトで NuGet パッケージ `GameFrameX.Foundation.Encryption` を参照する。
- ターゲットフレームワークが `System.Security.Cryptography.AesGcm` をサポートしている（.NET 5+ / .NET Standard 2.1 プラットフォーム実装）。
- `using GameFrameX.Foundation.Encryption;` と `using System.Text;`。

## 操作手順

### 1. 文字列の暗号化/復号化（Base64 出力）

```csharp
using GameFrameX.Foundation.Encryption;

string plain = "Hello, World! 这是一个测试字符串。";
string key = "MySecretKey123456";

string cipher = AesHelper.Encrypt(plain, key);
string back = AesHelper.Decrypt(cipher, key);
// back == plain
```

Source: [AesHelper.cs#L111-L124](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/AesHelper.cs#L111-L124)

### 2. バイト配列の暗号化/復号化（バイナリデータ用）

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

byte[] data = Encoding.UTF8.GetBytes("任意二进制数据");
byte[] cipherBytes = AesHelper.Encrypt(data, "MySecretKey123456");
byte[] plainBytes = AesHelper.Decrypt(cipherBytes, "MySecretKey123456");
```

Source: [AesHelper.cs#L140-L178](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/AesHelper.cs#L140-L178)

### 3. 暗号化/復号化後にディスク保存や転送を行う

`cipher`（Base64 文字列）または `cipherBytes`（バイナリ）をデータベース、設定ファイルに保存したり、ネットワーク経由で送信します。受信側は同じ鍵で `Decrypt` を呼び出すことで元のデータに戻せます。

```csharp
// 疑似コード：暗号文をファイルに保存
File.WriteAllText("secret.bin", cipher);

// 疑似コード：読み取って復号化
string read = File.ReadAllText("secret.bin");
string original = AesHelper.Decrypt(read, key);
```

## よくあるバリエーション

- **異なる長さの鍵**：ソースコードでは PBKDF2(SHA256, 600,000 回) を使用して任意の文字列鍵を 32 バイトの鍵に派生するため、`"ShortKey"` から `"VeryLongKeyThatExceedsNormalLength123456789"` まで、すべて正しく暗号化/復号化できます。
- **Unicode/Emoji を含む平文**：平文は UTF-8 でエンコードされた後に暗号化されるため、`"🚀🌟💻🎮🔥"` などの 4 バイト文字も正常に往復できます。
- **同じ平文 + 同じ鍵で 2 回暗号化**：Salt/Nonce がランダムなため 2 回の結果は異なりますが、両方の結果から元の平文に復号化できます — これは AES-GCM の意味論的セキュリティ特性です。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|----------|
| `ArgumentException: Plain text cannot be null or empty` | 平文が `null` または `""` | 暗号化前に文字列が空でないことを確認する |
| `ArgumentException: Encryption key cannot be null or empty` | 鍵が空 | 長さ ≥ 1 の空でない文字列鍵を提供する |
| `ArgumentException: Cipher text byte array is too short to be valid.` | 暗号文の長さが 45 バイト未満（1+16+12+16 ヘッダー） | `Encrypt` の完全な出力を渡していることを確認する |
| `CryptographicException: Unsupported AES payload format version.` | 暗号文ヘッダーのバージョン Byte が `2` でない | 現在のバージョンのライブラリにアップグレードするか、旧バージョンで復号化する |
| `CryptographicException`（復号化時） | 鍵が暗号化時と異なる、またはデータが改ざんされている | 暗号化と復号化で同じ鍵を使用していることを確認し、転送の完全性を検証する |

> 暗号化/復号化の呼び出しで、いずれかのパラメータが `null` / 空文字列の場合、即座に `ArgumentException` がスローされます。呼び出し前にアサーションするか、外側の `try/catch` で処理できます。

## 背景（オプション）

実装は AES-GCM 認証付き暗号化を採用しています：毎回ランダムに生成された 16 バイトの Salt と 12 バイトの Nonce に、PBKDF2(SHA256, 600k 回) で派生した 32 バイトのセッション鍵を組み合わせて使用します。出力形式は `Version(1) | Salt(16) | Nonce(12) | Tag(16) | 暗号文` で、Tag は完全性検証に使用されます。改ざんや鍵の誤りは復号化段階で `CryptographicException` としてスローされます。
