# ビルド失敗とコマンドライン引数エラーが発生した場合の対処法

コマンドラインからビルド処理を呼び出す際、ビルド失敗はほぼ常に「パラメータの欠落 / スペルミス / 不正な値」または「前提ステップの未完了」が原因です。本ページではエラーメッセージ原文に基づいて、対応する根本原因と修正方法を説明します。

## クイック診断

| 症状(エラー原文/キーワード) | 根本原因 | 修正方法 |
|---|---|---|
| `executeMethod is null` | `-ExecuteMethod` でエントリーメソッド名が渡されていない | コマンドラインに `-ExecuteMethod <名前空間.クラス.メソッド>` を追加 |
| `build number is null` | `-BuildNumber` でビルド番号が渡されていない | コマンドラインに `-BuildNumber <バージョン番号>` を追加 |
| `無効の构建管线类型: <xxx>，可选値: BuiltinBuildPipeline, ScriptableBuildPipeline, RawFileBuildPipeline` | `-BuildPipeline` の値が有効な enum 名ではない | 値を `BuiltinBuildPipeline`、`ScriptableBuildPipeline`、`RawFileBuildPipeline` のいずれかに変更 |
| `無効の内置文件拷贝选项: <xxx>，可选値: None, ClearAndCopyAll, ClearAndCopyByTags, OnlyCopyNew` | `-BuildinFileCopyOption` の値が不正 | 値を `None`、`ClearAndCopyAll`、`ClearAndCopyByTags`、`OnlyCopyNew` のいずれかに変更。未指定の場合はデフォルトで `ClearAndCopyAll` |
| ログに本ツールの出力が全くないが、Unity が終了した | `LogFilePath` が指す場所が書き込み不可、またはビルド番号が空のためパス導出に失敗 | `-LogFilePath` のディレクトリ権限を確認、または明示的に `-BuildNumber` を指定 |
| `-BuildPipeline`/`-PackageVersion` などの値付きパラメータが効かない | 値をパラメータに続けて `-BuildPipelineBuiltinBuildPipeline` のように記述している | パラメータと値の間には**必ずスペース**を入れて `-BuildPipeline BuiltinBuildPipeline` と記述 |
| BuildAsset は正常だが BuildPlayer(パッケージ出力)段階で赤エラー | 前段の `BuildAsset` が実行されていない、またはホットアップデート/AOT コードディレクトリが空 | まず `BuildAsset` を実行し、`Assets/.../Hotfix/`、`AOT/` ディレクトリに内容があることを確認してからパッケージ出力 |

エラーログ原文の出所:[Editor/Builder.BuildParamsParse.cs#L175-L183](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L175-L183)、[Editor/Builder.BuildAsset.cs#L40-L44](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L44)、[Editor/Builder.BuildAsset.cs#L76-L80](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L76-L80)。

## 修正手順

### 1. 必須 3 つのパラメータを補完する

パーサーは `-ExecuteMethod`、`-BuildNumber`、`-LogFilePath` を必須としています(後者は未指定の場合、前 2 つから自動導出されますが、明示的に指定することを推奨)。コマンド例:

```bash
Unity \
  -batchmode -nographics -quit \
  -projectPath /path/to/project \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
  -BuildNumber 1.0.0.1 \
  -LogFilePath ../Logs/BuildAsset_1.0.0.1.log \
  -ChannelName default \
  -PackageName DefaultPackage
```

いずれかが欠落すると `Exception` がスローされ、プロセスが直接終了します。出所:[Editor/Builder.BuildParamsParse.cs#L175-L189](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L175-L189)。

### 2. `-BuildPipeline` と `-BuildinFileCopyOption` の値を修正する

これら 2 つのパラメータは `Enum.TryParse` で検証されます。大文字小文字は区別されませんが、**enum 名でなければならず**、数字やスペルミスも不可です:

- `-BuildPipeline`:`BuiltinBuildPipeline`(デフォルト)、`ScriptableBuildPipeline`、`RawFileBuildPipeline` から選択
- `-BuildinFileCopyOption`:`None`、`ClearAndCopyAll`(デフォルト)、`ClearAndCopyByTags`、`OnlyCopyNew` から選択

```bash
  -BuildPipeline BuiltinBuildPipeline \
  -BuildinFileCopyOption ClearAndCopyAll \
```

検証ロジック:[Editor/Builder.BuildAsset.cs#L40-L84](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L84)。

### 3. `-xxx <値>` の間はスペース区切りにする

パーサーは `commandLineArgs` を 1 つずつ走査し、各スイッチの値は `index + 1` で次の要素を取得します。そのため、パラメータと値の間は必ずスペースで区切る必要があります(`=` や連結は不可)。出所:[Editor/Builder.BuildParamsParse.cs#L152-L172](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L152-L172)。

正しい記述:`-PackageVersion 20240101120000`
誤った記述:`-PackageVersion=20240101120000`、`-PackageVersion20240101120000`

### 4. 先に `BuildAsset` を実行してから `BuildPlayer`

`BuildAsset` 内部ではホットアップデートと AOT アセンブリのコピー、AssetDatabase の更新が行われ、その後 YooAsset によるパッケージングが実行されます。パッケージ出力コマンドを直接実行して、ホットアップデートコードの欠落、「アセンブリが見つからない」エラー、または空のリソースパッケージングが発生した場合、通常はリソースパッケージングステップがスキップされています。修正:パイプラインを 2 段階に分け、まず `BuildAsset` を実行し、その後 `BuildPlayerAndroid`/`BuildPlayerIOS` を実行します。出所:[Editor/Builder.BuildAsset.cs#L15-L27](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L15-L27)、[Editor/Builder.cs#L60-L66](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L60-L66)。

### 5. `-BundleId` / `-AppVersion` を実際に有効化する

これら 2 つのパラメータは、空でない文字列が渡された場合にのみ `PlayerSettings` を上書きします。コマンドラインで指定したのに `PlayerSettings` が変化しない場合は、両端に余分なスペースや改行がないか確認してください(コードは `Trim` を実行します)。出所:[Editor/Builder.BuildParamsParse.cs#L194-L202](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L194-L202)。

## 検証

1. コマンドラインの最初の行に `executeMethod is null` / `build number is null` が表示されなくなれば、必須パラメータが補完されたことを示します。
2. Edit/Console で `-----------构建参数开始-----------` という行の直後に `_builderOptions` の JSON 出力があれば、すべてのパラメータが正しく解析されたことを確認できます。出所:[Editor/Builder.BuildParamsParse.cs#L191-L193](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L191-L193)。
3. `BuildAsset` 完了後のログに `BuildAsset End` が含まれていれば、その後 `BuildPlayer*` を起動してもリソース不足による失敗は発生しません。出所:[Editor/Builder.BuildAsset.cs#L99-L100](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L99-L100)。

## 背景(オプション)

ツールは `Builder.BuildParamsParse` でコマンドラインを解析 → `BuilderOptions` に書き込む → `BuildAsset` / `BuildPlayer*` に配信、という流れで動作します。検証は解析段階(`Exception` のスロー)と `BuildAsset` 開始時点の enum `TryParse` に集中しているため、「ビルド失敗」のほとんどはこの 2 つのレイヤーで捕捉されます。YooAsset / Unity パッケージ出力自体の調査に戻る必要があるのはむしろ少数です。
