# What to Do When Event Types Are Strpped After Packaging

It works fine in the Editor, but after building with IL2CPP (especially with Managed Stripping Level set to Medium/High), subscribed callbacks don't fire, or reflecting by type name fails to find the event type — this is almost always caused by managed code stripping deleting event types that are "only referenced by strings/reflection". The module's core types are already protected by `GameFrameXEventCroppingHelper` and `[Preserve]`; your own custom `EventArgs` types need the protections described below.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Subscribed callbacks don't execute after `Fire`, but work fine in the Editor | Custom event `EventArgs` type was stripped, `Type.FullName` cannot be resolved | Step 1: Add `[Preserve]` to your custom event classes |
| `Utility.Assembly.GetType(componentType)` can't resolve the implementation type, component initialization fails | The implementation type is only referenced by string and was stripped by the linker | Step 2: Confirm the stripping protection Helper exists in the scene/assembly |
| All event types in the base build/hot-update assemblies stop working entirely | The whole assembly was stripped | Step 3: Use `link.xml` to fully preserve the assembly |
| Don't want to troubleshoot one by one | Just want to restore functionality quickly | Step 4: Lower the Managed Stripping Level |

## Fix Steps

### 1. Add `[Preserve]` to Custom Event Classes (Recommended)

The module's event base class is itself protected this way; follow its example and add the attribute to each of your custom event classes:

```csharp
namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// Base class for game logic events.
    /// </summary>
    [UnityEngine.Scripting.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

Event IDs depend on the type's full-name string (for example, `EmptyEventArgs` internally uses `typeof(EmptyEventArgs).FullName` as `_eventId`); once a type is stripped, the subscription and trigger IDs no longer match, so you must ensure the type isn't removed. See [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L15-L21).

### 2. Confirm the Module's Built-in Stripping Protection Helper Is in Effect

The module ships with a reference-protection component; as long as this assembly participates in compilation at build time, the core types will not be stripped:

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Event.Runtime
{
    [Preserve]
    public class GameFrameXEventCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(EventManager);
            _ = typeof(EventComponent);
            _ = typeof(GameEventArgs);
            _ = typeof(IEventManager);
        }
    }
}
```

Source: [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs#L1-L18)

When troubleshooting, confirm two things:

1. The `GameFrameX.Event.Runtime` assembly hasn't been stripped entirely (see the fallback in step 3).
2. Your own newly added types are not in the reference list above, so they still need individual `[Preserve]` attributes as described in step 1.

Additionally, `EventComponent` resolves the implementation type by string using `Utility.Assembly.GetType(componentType)` during initialization; this step is the most sensitive to stripping. See [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L67-L69).

### 3. Use `link.xml` to Fully Preserve Assemblies (Fallback)

Create a `link.xml` anywhere under `Assets` (e.g., in a regular directory outside `Assets/StreamingAssets`), preserve the runtime assembly as a whole, and also add the assembly that contains your custom events:

```xml
<linker>
  <assembly fullname="GameFrameX.Event.Runtime" preserve="all"/>
  <!-- The assembly containing your custom event types; fill in the asmdef name -->
  <assembly fullname="YourGame.Logic" preserve="all"/>
</linker>
```

Assembly names should follow the asmdefs in the repository: the runtime assembly file is `Runtime/GameFrameX.Event.Runtime.asmdef`, and the editor assembly is `Editor/GameFrameX.Event.Editor.asmdef`.

### 4. Lower the Managed Stripping Level

Set `Project Settings → Player → Other Settings → Optimization → Managed Stripping Level` to `Minimal` or `Low`; with reduced stripping, most "string-referenced types removed" problems disappear. The tradeoff is a larger package size, so this is recommended only for quickly verifying whether stripping is the root cause.

## Verification

1. Build for the target device again (the Editor does not trigger stripping; you must verify with an actual build).
2. Subscribe to an event in the scene and `Fire` it, then confirm the callback executes.
3. You can also verify programmatically via the event-counting API: `EventManager` provides the `EventHandlerCount` and `EventCount` properties and the `Count(string id)` method; after a successful subscription, the handler count for the corresponding ID should be greater than 0. See [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L54-L65) and [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L98-L102).

## Background

Events in this module use the "type full-name string" as their ID; subscription, triggering, and component implementation resolution all go through string/reflection paths. IL2CPP's managed linker only tracks statically visible references and cannot see these dynamic references, so it deems the related types "unused" and removes them. The `[Preserve]` attribute and `link.xml` are the standard means of telling the linker "this type must be kept"; the explicit `typeof(...)` references in `GameFrameXEventCroppingHelper.Start` work the same way.
