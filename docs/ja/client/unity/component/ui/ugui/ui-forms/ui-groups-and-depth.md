# UI グループ（UIGroup）を使用して Canvas の階層と深度を制御する方法

`UIGroup`（UI グループ）を使用すると、開いた UI フォームを業務ごとにグループ分けして異なる `RectTransform` ノードにアタッチできます。グループ内で 1 層追加されるたびに、1000 をステップとして `Z` 軸の深度を後ろへ押し進めることで、描画順序とクリックのヒット順序が決まります。本ページでは、最も一般的な 2 つの使い方を紹介します。UI フォームに対して属性でグループを宣言する方法と、実行時に手動でグループへ追加する方法です。

## 前提条件

- プロジェクトに GameFrameX と `com.gameframex.unity.ui.ugui` が導入済みであり、UI フレームワークがシーン内で `UIComponent` を通じて初期化済みであること（シーン内に `UGUICanvas`、`UGUICamera`、`EventSystem` などのノードが存在します。これらは `UGUIUIGroupHelper.EnsureRuntimeRoot` によって、初めて UI フォームを開くときに必要に応じて作成されます）。
- 開こうとする UI フォームのクラスが `IUIForm` を実装している（または `UIForm` もしくはフレームのコードジェネレーターが生成した基底クラスを継承している）ことを既に把握していること。

## 操作手順

### 方法 1：`OptionUIGroupAttribute` で UI フォームをグループにバインドする

UI フォームの型に `OptionUIGroup` 属性を宣言すると、`UGUIFormHelper` が自動的に `UIComponent` から同名のグループを取得し、`uiForm.UIGroup` に代入します。

```csharp
using GameFrameX.UI.Runtime;

[OptionUIGroup("HUD")]
public sealed class HUDForm : UIForm
{
    // ...
}
```

`UGUIFormHelper` はまず `uiForm.UIGroup` を読み取り、それが空であれば属性の `GroupName` に基づいて `m_UIComponent.GetUIGroup(...)` を呼び出します：

```csharp
// 出典：UGUIFormHelper.cs
var uiGroup = uiForm.UIGroup;
if (uiGroup == null)
{
    var attribute = uiFormType.GetCustomAttribute(typeof(OptionUIGroupAttribute));
    if (attribute is OptionUIGroupAttribute optionUIGroup)
    {
        uiGroup = m_UIComponent.GetUIGroup(optionUIGroup.GroupName);
    }

    uiForm.UIGroup = uiGroup;
}
```

出典：[UGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L112-L122)

### 方法 2：実行時に手動でグループを指定する

`UIComponent.OpenUIForm` を呼び出す（または `UIManager.OpenUIForm` を介して間接的に呼び出す）前に、自分で `UIComponent` から対象の `IUIGroup` を取得し、`uiForm.UIGroup` に書き込みます。

```csharp
var group = GameEntry.UI.GetUIGroup("Popup"); // 例えば "Popup" という名前のグループを取得
// UI フォームを開いた後にグループを書き込む
uiForm.UIGroup = group;
```

書き込みが完了すると、`UIManager.Open` の中でグループがパラメーターとして `uiForm.Init(...)` に渡され、以降のオープン/クローズ/フォーカスはすべてそのグループ単位で管理されます：

```csharp
// 出典：UIManager.Open.cs
var uiGroup = uiForm.UIGroup;
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, null,
    pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);
```

出典：[UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L200-L201)

### 深度はどのように算出されるのか

`UGUIUIGroupHelper` によって作成される各グループは 1 つの `RectTransform` を持ち、グループ配下の子ノードは `localPosition.z` によって距離を確保します：

```csharp
// 出典：UGUIUIGroupHelper.cs
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

出典：[UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

ポイント：

- `Depth` は、全グループの中でそのグループが持つインデックスです（通常は `UIComponent` が作成順に割り当てます）。
- 同じグループ内の複数の UI フォームは、1000 を単位としてオープン順に後ろへ重なっていくため、`ScreenSpaceCamera` の `Canvas`（`planeDistance = 100f`、`sortingOrder = 0`）では描画順序が確定します。
- 特定の UI フォームを別の UI フォームの上に重ねたい場合は、より大きなインデックスのグループへ配置するか、同じグループ内で後から開いたものが先に開いたものを覆うようにします。

### グループの実行時構造

`Handler(...)` を呼び出すと、以下が実行されます：

1. `SetDepth(depth)` を呼び出して、現在のノードの `z` を `depth * 1000` に設定します。
2. `EnsureRuntimeRoot` を通じて、ルート配下に `UGUICamera`、`UGUICanvas`、`EventSystem` が存在することを保証します。
3. `root` 配下に `groupName` という名前の `GameObject` を作成し、`RectTransform` をアタッチして画面全体に広げます。
4. ノード全体とその子ノードのレイヤーを `UI` に設定します。
5. `Helper.CreateHelper` を呼び出して、そのノードに `UGUIUIGroupHelper` のインスタンス（または自分で渡したカスタムヘルパー）をアタッチします：

```csharp
// 出典：UGUIUIGroupHelper.cs
GameObject component = new GameObject(groupName);
component.transform.SetParent(root, false);
var uiLayer = LayerMask.NameToLayer("UI");
component.SetLayerRecursively(uiLayer);

RectTransform rectTransform = component.GetOrAddComponent<RectTransform>();
rectTransform.MakeFullScreen();
var uiGroupHelper = Helper.CreateHelper(component, uiGroupHelperTypeName,
    (UIGroupHelperBase)customUIGroupHelper, 0);
return uiGroupHelper;
```

出典：[UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L86-L113)

最終的なシーンの階層は概ね次のようになります：

```
UIComponent
└── UGUICanvas (Canvas, CanvasScaler, GraphicRaycaster)
    ├── Default (グループ 0)
    │   ├── FormA
    │   └── FormB
    ├── HUD (グループ 1)
    │   └── HUDForm
    └── Popup (グループ 2)
        └── PopupForm
```

## よくあるバリエーション

- **複数グループの階層化**：`HUD`、`Popup`、`Dialog`、`Loading` など用途の異なる UI フォームを別々のグループに振り分けると、グループ間は `depth * 1000` によって自然に階層化されます。
- **デフォルトヘルパーの置き換え**：`IUIGroupHelper` を実装（`UIGroupHelperBase` を継承）し、`UIComponent` でグループを追加するときに `customUIGroupHelper` パラメーターで渡すことで、デフォルトの `UGUIUIGroupHelper` の動作を上書きできます（例：カスタムの深度アルゴリズムや追加コンポーネント）。
- **エディターでのカスタマイズ**：Inspector で `UGUIComponentInspector` などのエディター用スクリプトを使用して、グループと深度を確認/調整できます。

## よくある間違い

- **`OptionUIGroup` を宣言しておらず手動での代入もしていない**：`UGUIFormHelper` の処理に入った時点で `uiGroup` が `null` のままとなり、最終的にログ `UI group is invalid.` が出力されて `null` が返却され、UI フォームのオープンに失敗します。
- **グループ名のスペルミス**：`OptionUIGroup("Popuo")` を使用したが `UIComponent` では実際には `"Popup"` という名前である場合、`GetUIGroup` が `null` を返し、同様に `UI group is invalid.` が発生します。統一した定数を取り決めてスペルミスを防ぎましょう。
- **`Canvas.sortingOrder` で階層を変えようとする**：この実装ではグループレベルの `Canvas.sortingOrder` は `0` に固定されており、グループ内/グループ間の順序は `localPosition.z = depth * 1000` によって確保されます。Inspector で直接 `sortingOrder` を変更しても、次回の `Handler(...)` で上書きされます。
- **`UGUICanvas` 配下に手動でノードを追加し、`UI` レイヤーの設定を忘れる**：`UGUIUIGroupHelper` が作成するノードには `SetLayerRecursively(uiLayer)` が適用されますが、自分でアタッチした補助 UI の子ノードも `UI` レイヤーを維持する必要があります。そうしないと、`UGUICamera` の `cullingMask` によってカリングされます。

## 背景（任意）

`UIGroup` の考え方は、古典的な GameFrameX フレームワークの UI フォームのグループ化に由来しています。すべての UI フォームが 1 つの `UGUICanvas` を共有し、`Z` 軸オフセットによって複数の Canvas が互いに覆い合うのを回避し、`GraphicRaycaster` を利用してクリックの振り分けを行います。`SetDepth` が `depth` をそのまま 1000 倍に拡大するのは、同じグループ内で何度も「最前面へ移動」を行うための十分なスロットを確保するためです。`Depth` と同じ桁位置にさらに小さなステップのオフセットを重ねるだけで、他のグループに影響を与えることなく、特定の UI フォームをグループ内の最上位へ安定して移動させることができます。
