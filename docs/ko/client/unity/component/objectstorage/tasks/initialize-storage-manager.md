# 객체 스토리지 매니저를 초기화하는 방법

`ObjectStorageUploadFactory.Create<T>` 를 통해 객체 스토리지 업로드 매니저 인스턴스를 생성하고 초기화합니다. 완료되면 `UploadFile` / `UploadDirectory` 등의 인터페이스를 호출하여 파일을 업로드할 수 있습니다.

## 사전 조건

- `com.gameframex.unity.objectstorage` 패키지가 설치되어 있어야 합니다.
- `IObjectStorageUploadManager` 를 구현하는 구체적인 타입이 도입되어 있어야 합니다(이 패키지는 추상 기본 클래스 `BaseObjectStorageUploadManager` 만 제공하며, 특정 클라우드 공급업체 구현은 별도로 도입해야 합니다).
- 네 가지 매개변수가 준비되어 있어야 합니다: `accessKey`, `secretKey`, `bucketName`, 그리고 선택 사항인 `endpoint`.

## 작업 단계

1. 코드에 네임스페이스 참조를 추가합니다:

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13)

2. 정적 메서드 `ObjectStorageUploadFactory.Create<T>` 를 호출하여 제네릭 매개변수(구현 클래스)와 네 가지 자격 증명을 전달합니다. 팩토리 내부에서 `Activator.CreateInstance<T>()` 를 호출하고 자동으로 `Init` 을 실행하므로 수동으로 초기화할 필요가 없습니다:

   ```csharp
   // 假设已引入某个具体实现,例如 MyCloudUploader : IObjectStorageUploadManager
   IObjectStorageUploadManager manager = ObjectStorageUploadFactory.Create<MyCloudUploader>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: "https://oss-cn-hangzhou.aliyuncs.com" // 选填,部分对象存储无需该值
   );
   ```

   Source: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. 원격 저장 경로를 사용자 정의하려면 `SetSavePath` 를 호출합니다(디렉터리 구분 기호로 끝나지 않는 경로를 전달해야 하며, 기본 클래스가 자동으로 끝의 슬래시를 제거합니다):

   ```csharp
   manager.SetSavePath("uploads/build/v1");
   ```

   Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

4. 위 단계를 완료하면 매니저는 "초기화됨" 상태가 되며, 바로 `UploadFile` 또는 `UploadDirectory` 를 호출하여 업로드를 수행할 수 있습니다.

## 일반적인 변형

- 팩토리를 사용하지 않고 직접 구현 클래스를 `new` 로 생성한 후 수동으로 `Init` 을 호출합니다:

  ```csharp
  var manager = new MyCloudUploader();
  manager.Init("ak", "sk", "bucket", "endpoint");
  ```

  `Init` 의 시그니처는 인터페이스 `IObjectStorageManager` 에서 가져온, `endpoint` 는 nullable 매개변수이며 기본값은 `null` 입니다.

  Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L13)

- `BaseObjectStorageUploadManager` 를 직접 상속하여 사용자 정의 업로드 로직을 구현합니다. `Init` , `UploadDirectoryInternal` , `UploadFileInternal` 의 세 가지 `protected` / `public abstract` 메서드만 재정의하면 됩니다.

  Source: [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L10-L34)

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Create<T>` 컴파일 오류, `T` 가 제약 조건을 충족하지 않음 | 제네릭 `T` 가 `IObjectStorageUploadManager` 를 구현하지 않음 | 구체적인 업로드 매니저 클래스(`BaseObjectStorageUploadManager` 를 상속받거나 인터페이스를 직접 구현) 전달 |
| `SetSavePath` 호출 후 경로가 잘림 | 전달된 경로가 디렉터리 구분 기호로 끝남 | 기본 클래스가 자동으로 끝의 `Path.DirectorySeparatorChar` 를 제거하므로 수동으로 처리할 필요 없지만, 유효한 디렉터리 이름을 전달해야 함 |
| 업로드 시 여전히 기본 경로를 따름 | 인스턴스 생성 후 `SetSavePath` 호출을 잊음 | 업로드 전에 명시적으로 `BucketSavePath` 설정 |

## 배경(선택 사항)

`ObjectStorageUploadFactory.Create<T>` 는 내부적으로 `new` 와 `Init` 호출을 한 번에 처리하여 호출자가 초기화 단계를 누락하는 것을 방지하는 것이 목적입니다. `endpoint` 는 클라우드 공급업체마다 의미가 다르므로, 인터페이스는 선택적 매개변수 형태로 호환됩니다.
