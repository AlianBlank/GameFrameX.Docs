# What to Do When Module Lookup Fails

When calling `GameFrameX.Runtime.GameFrameworkEntry.GetModule<T>()` to look up a module, the framework locates the implementation class via reflection based on the interface name; the lookup process may throw a `GameFrameworkException` due to interface constraints, naming conventions, failed auto-registration, and other reasons. This page lists the root causes and fix steps by exception message.

## Quick Diagnosis

| Symptom (Original Exception Message) | Root Cause | Fix |
|---|---|---|
| `You must get module by interface, but 'X' is not.` | The generic `T` is not an interface; the framework mandates using an interface to obtain the module | [Pass an interface type instead](#fix-1-must-use-interface-to-get-module) |
| `You must get a Game Framework module, but 'X' is not.` | The passed interface does not start with the `GameFrameX.` namespace | [Fix the namespace](#fix-2-namespace-must-start-with-gameframex) |
| `Can not find Game Framework module type 'X.Y.Z'.` | The implementation class cannot be found automatically by naming convention; explicit registration is required | [Call RegisterModule or add the implementation class](#fix-3-implementation-class-not-found) |
| `You must register module by interface, but 'X' is not.` | The first argument of `RegisterModule` is passed a class | [Pass an interface type](#fix-4-first-argument-of-registermodule-must-be-an-interface) |
| `You must register module by Class and not Interface and Abstract, but 'X' is not.` | The second argument is not a concrete class (interface, abstract class, or non-class type) | [Pass a concrete implementation class](#fix-5-second-argument-of-registermodule-must-be-a-concrete-class) |
| `Can not create module 'X'.` | The implementation class lacks a parameterless constructor, or `Activator.CreateInstance` fails | [Add a parameterless constructor](#fix-6-implementation-class-lacks-a-parameterless-constructor) |

## Fix Steps

### Fix 1: Must Use Interface to Get Module

The very first thing `GetModule<T>` does is check `typeof(T).IsInterface`; non-interfaces throw immediately.

```csharp
// Wrong: passing the implementation class
var foo = GameFrameworkEntry.GetModule<FooImpl>();

// Correct: passing the interface
var foo = GameFrameworkEntry.GetModule<IFoo>();
```

Source: [GameFrameworkEntry.cs#L95-L120](/src/Runtime/Base/GameFrameworkEntry.cs#L95-L120)

### Fix 2: Namespace Must Start with `GameFrameX.`

The framework requires the interface's `FullName` to begin with `GameFrameX.`; otherwise, the second exception is thrown.

```csharp
// Wrong: namespace is not under GameFrameX
namespace MyGame { public interface IBar {} }

// Correct
namespace GameFrameX.Runtime { public interface IBar {} }
```

Source: [GameFrameworkEntry.cs#L104-L107](/src/Runtime/Base/GameFrameworkEntry.cs#L104-L107)

### Fix 3: Implementation Class Not Found

When looking up the implementation class, the framework follows the convention of stripping the `I` prefix from the interface name and reflecting in the same namespace (e.g., `GameFrameX.Runtime.IFoo` → `GameFrameX.Runtime.Foo`). If this fails, explicit `RegisterModule` is required.

```csharp
// Convention-based lookup (the Foo class must exist in the same namespace)
public class Foo : GameFrameworkModule, IFoo { /* ... */ }

// Or explicit registration: the second Type passed in can come from any namespace
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(MyGame.Modules.FooImpl));
```

The call entry point is in the `Type.GetType(moduleName)` logic within `GetModule<T>`, see [GameFrameworkEntry.cs#L109-L119](/src/Runtime/Base/GameFrameworkEntry.cs#L109-L119); the registration logic is at [GameFrameworkEntry.cs#L153-L169](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L169).

### Fix 4: First Argument of RegisterModule Must Be an Interface

The very first line of `RegisterModule` validates `interfaceType.IsInterface`.

```csharp
GameFrameworkEntry.RegisterModule(typeof(IFoo), typeof(Foo));   // Correct
GameFrameworkEntry.RegisterModule(typeof(Foo), typeof(Foo));     // Throws
```

Source: [GameFrameworkEntry.cs#L153-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L153-L163)

### Fix 5: Second Argument of RegisterModule Must Be a Concrete Class

It requires `implType.IsClass && !implType.IsInterface && !implType.IsAbstract`.

- Interface → throws `by Class and not Interface ... is not.`
- Abstract class → throws the same
- Register with a concrete class

Source: [GameFrameworkEntry.cs#L160-L163](/src/Runtime/Base/GameFrameworkEntry.cs#L160-L163)

### Fix 6: Implementation Class Lacks a Parameterless Constructor

`CreateModule` uses `Activator.CreateInstance(moduleType)` for instantiation. If no parameterless constructor is found or the constructor throws, you'll get `Can not create module 'X'.`.

```csharp
public class Foo : GameFrameworkModule
{
    public Foo() { }  // An accessible parameterless constructor must be kept
    protected internal override int Priority => 0;
    protected internal override void Update(float a, float b) { }
    protected internal override void Shutdown() { }
}
```

Source: [GameFrameworkEntry.cs#L179-L208](/src/Runtime/Base/GameFrameworkEntry.cs#L179-L208)

## Verification

- Catch `GameFrameworkException` in `Awake` or `Start`:
  ```csharp
  try
  {
      var ui = GameFrameworkEntry.GetModule<IFooModule>();
  }
  catch (GameFrameworkException ex)
  {
      Debug.LogError(ex.Message);
  }
  ```
  If it no longer throws, both registration and namespace are correct.
- When `Can not find Game Framework module type` no longer appears in the console, the automatic convention-based lookup is successful; if lookup still fails, confirm that the assembly has been compiled into the Player Settings and that the interface and implementation class share the same namespace.
