# 构建失败与热更异常怎么办

本页面针对使用 GameFrameX 的 `BuildProduct`（构建产品）和 `BuildHotfix`（构建热更新）菜单时常见的问题，按症状对照排查，并给出与源码一致的修复方式。

## 快速诊断

| 症状（日志原文） | 原因 | 修复 |
|------|------|------|
| `当前构建目标不是 Windows` | 菜单要求当前 `BuildTarget` 与菜单目标一致，但你切换到了其他平台 | 打开 `File → Build Settings`，将平台切到对应目标后再触发菜单 |
| `当前构建目标不是 Mac Os` | 同上，针对 macOS 打包入口 | 切到 `StandaloneOSX` 后重试 |
| `当前构建目标不是 WebGL` | 同上，针对 WebGL 打包入口 | 切到 `WebGL` 后重试 |
| `当前构建目标不是 Android` | 同上，针对 Android 打包入口 | 切到 `Android` 后重试 |
| `输出路径异常,取消打包AAB` | 构建输出目录为空或不可写 | 见下文修复步骤 4 |
| `未找到HybridCLR数据目录:{path}` | 还没跑过 HybridCLR 的生成流程，`HybridCLRData/AssembliesPostIl2CppStrip/<Target>` 不存在 | 先做一次 `HybridCLR → Generate` 再复制 AOT |
| `复制Hotfix DLL到Assets/Bundles/Code完成` 之后运行仍找不到热更代码 | 没有把 `Unity.HotFix.dll` 拷到 `Library/ScriptAssemblies` | 触发 `GameFrameX → Build → Copy HotFix Code` |
| `Build Output Path:...` 但构建报红 | 输出目录权限或磁盘空间不足 | 换一个可写目录并清理旧产物 |

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L101-L110), [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L80-L100)

## 修复步骤

### 1. 平台不匹配（"当前构建目标不是 XXX"）

`BuildProductHelper` 在每个平台入口都先校验 `EditorUserBuildSettings.activeBuildTarget`，不匹配直接 `Debug.LogError` 后 `return`：

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    Debug.Log(EditorUserBuildSettings.activeBuildTarget);
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("当前构建目标不是 Windows");
        return;
    }
    ...
}
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L101-L110)

**操作：**

1. Unity 菜单 `File → Build Settings…`
2. 切换到与入口对应的 `Target Platform`（Windows64 / macOS / WebGL / Android）
3. 点击 `Switch Platform` 等待转平台完成
4. 重新执行 `GameFrameX → Build → <对应平台>`

### 2. 复制 AOT 元数据失败（"未找到HybridCLR数据目录"）

`CopyAOTCode` 会从 `<Project>/HybridCLRData/AssembliesPostIl2CppStrip/<activeBuildTarget>` 拷贝 `*.dll` 到 `Assets/Bundles/AOTCode/`。若该目录不存在会报错并 return：

```csharp
DirectoryInfo aotCodeDir = new DirectoryInfo(path);
if (!aotCodeDir.Exists)
{
    Debug.LogError($"未找到HybridCLR数据目录:{path}");
    return;
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L84-L92)

**操作：**

1. 在 Unity 中打开 `HybridCLR → Generate`（或对应项目的 `HybridCLR/Generate` 流程）生成 Strip 后的 AOT DLL
2. 确认 `HybridCLRData/AssembliesPostIl2CppStrip/<Target>` 下出现 `*.dll`
3. 再执行 `GameFrameX → Build → Copy AOT Code`

### 3. 找不到 `Unity.HotFix.dll`

`BuildHotfixHelper.CopyHotfixCode()` 默认从 `Library/ScriptAssemblies/Unity.HotFix.dll` 拷贝到 `Assets/Bundles/Code/Unity.HotFix.dll.bytes`：

```csharp
private const string HotFixAssembliesDir = "Library/ScriptAssemblies";
private static readonly string[] HotfixDlls = new string[] { "Unity.HotFix.dll" };
private const string CodeDir = "Assets/Bundles/Code/";

foreach (var hotfix in HotfixDlls)
{
    var srcPath = Path.Combine(HotFixAssembliesDir, hotfix);
    if (!File.Exists(srcPath))
    {
        continue;
    }
    File.Copy(srcPath, Path.Combine(CodeDir, hotfix + Utility.Const.FileNameSuffix.Binary), true);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L21-L65)

如果 `Library/ScriptAssemblies` 下没有该 DLL，代码会静默 `continue`，最终 `Assets/Bundles/Code/` 为空。**操作：**

1. 确认工程中存在 `Unity.HotFix` 的 `asmdef`（热更程序集），命名必须严格是 `Unity.HotFix.dll`
2. 切换到对应构建目标后让 Unity 重新编译，看到 `Library/ScriptAssemblies/Unity.HotFix.dll` 生成
3. 再执行 `GameFrameX → Build → Copy HotFix Code(复制热更新代码到Assets>Bundles>Code)`
4. 在 `Assets/Bundles/Code/` 下确认 `Unity.HotFix.dll.bytes` 已生成

### 4. AAB 输出路径异常

Android AAB 入口在校验输出目录时会打印：

```csharp
Debug.LogError("输出路径异常,取消打包AAB");
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L421)

**操作：**

1. 在 `GameFrameX/Build` 菜单触发前，先设置好构建输出目录，确保路径存在且当前用户可写
2. 清理上一次构建残留（同名旧 AAB 占用、只读文件）
3. 重新触发对应 Android AAB 入口

### 5. 想临时关掉 HybridCLR

源码提供了宏开关 `DISABLE_HYBRIDCLR`，菜单可一键切换：

```csharp
public const string HybridCLRScriptingDefineSymbol = "DISABLE_HYBRIDCLR";

[MenuItem("GameFrameX/Scripting Define Symbols/Disable HybridCLR(关闭HybridCLR适配)", false, 5000)]
public static void DisableHybridCLR()
{
    ScriptingDefineSymbols.AddScriptingDefineSymbol(HybridCLRScriptingDefineSymbol);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L107-L116)

当热更链路导致打包流程整体失败、又必须先出一版产物时，可临时走 `GameFrameX → Scripting Define Symbols → Disable HybridCLR`，跳过热更相关步骤定位问题，之后再用 `Enable HybridCLR` 恢复。

## 验证

构建/热更问题修复后，按下面顺序自检：

1. `BuildProductHelper` 入口不再打印 `当前构建目标不是 XXX` 类的 LogError，并且构建报告 `BuildResult.Succeeded`
2. `Assets/Bundles/Code/Unity.HotFix.dll.bytes` 与 `Assets/Bundles/AOTCode/` 下存在本次目标的 AOT DLL
3. 运行构建产物，HybridCLR 热更入口能正常加载热更程序集
