# 常見問題

本文件收集了使用 GameFrameX Advertisement 模組時常見的問題及其解決方案。

## 概述

GameFrameX Advertisement 模組為 Unity 專案提供了統一的廣告整合抽象層。由於廣告功能涉及多個平臺（Android、iOS、WebGL）以及多個廣告網路 SDK（AdMob、Unity Ads、IronSource 等），在實際使用過程中可能遇到各種配置和執行時問題。本文件旨在幫助開發者快速定位和解決這些常見問題。

> **提示**：在排查問題時，請首先確認您已正確安裝並配置了廣告模組。如需基礎使用說明，請參閱 [快速開始](../3-getting-started) 和 [核心概念](../4-core-concepts) 文件。

## 核心架構

在深入排查問題之前，瞭解模組的核心架構有助於更好地理解問題根源：

```mermaid
flowchart TD
    subgraph Unity["Unity 場景層"]
        GameObj[GameObject + AdvertisementComponent]
    end

    subgraph Framework["GameFrameX 框架層"]
        GFX[GameFrameworkEntry]
        AdComp[AdvertisementComponent]
    end

    subgraph Interface["介面抽象層"]
        IAM[IAdvertisementManager]
        BAM[BaseAdvertisementManager]
    end

    subgraph Impl["具體實現層"]
        ADM[廣告管理器實現<br/>AdMob/IronSource/UnityAds...]
    end

    GameObj --> AdComp
    AdComp --> GFX
    GFX -->|GetModule| IAM
    IAM <|.. BAM
    BAM <|-- ADM
```

**工作流程：**
1. 開發者將 `AdvertisementComponent` 新增到場景中的 GameObject
2. `AdvertisementComponent` 在 `Awake()` 中透過 `GameFrameworkEntry.GetModule<IAdvertisementManager>()` 獲取廣告管理器
3. 在 `Start()` 時呼叫 `Initialize()` 初始化廣告管理器
4. 透過 `Load()`、`Show()`、`Play()` 方法與廣告系統互動

## 常見問題與解決方案

### 問題一：廣告管理器初始化失敗

#### 症狀

執行遊戲時，控制檯顯示以下錯誤：
```
Log.Fatal: Advertisement manager is invalid.
```

#### 原因分析

此錯誤表示 `GameFrameworkEntry.GetModule<IAdvertisementManager>()` 返回了 `null`，即框架未能找到 `IAdvertisementManager` 介面的實現。

可能的根本原因：
1. **未註冊廣告管理器實現**：框架中沒有任何模組實現 `IAdvertisementManager` 介面
2. **程式集剝離問題**：Unity 的 IL2CPP 或程式碼剝離導致廣告管理器實現類被移除
3. **模組載入順序問題**：廣告模組在其他依賴模組之前被載入

#### 解決方案

**步驟 1：確認已實現廣告管理器**

確保您的專案中存在 `IAdvertisementManager` 介面的具體實現類。例如：

```csharp
using GameFrameX.Advertisement.Runtime;
using GameFrameX.Runtime;
using UnityEngine;
using UnityEngine.Scripting;

[Preserve]
public class MyAdsManager : BaseAdvertisementManager
{
    public override void Initialize(string adUnitId, bool debug = false)
    {
        // 實現廣告 SDK 的初始化邏輯
    }

    public override void Play(System.Action<bool> playResult, string customData = null)
    {
        // 實現廣告播放邏輯
    }

    public override void Show(System.Action<string> success, System.Action<string> fail, 
        System.Action<bool> onShowResult, string customData = null)
    {
        // 實現廣告展示邏輯
    }

    public override void Load(System.Action<string> success, System.Action<string> fail, 
        string customData = null)
    {
        // 實現廣告載入邏輯
    }
}
```

> Source: [BaseAdvertisementManager.cs]({{file_base_url}}/Runtime/Advertisement/BaseAdvertisementManager.cs#L11-L88)

**步驟 2：解決程式集剝離問題**

如果使用了 IL2CPP 或程式碼裁剪，確保新增 `[Preserve]` 屬性（Unity 會保留帶有此屬性的類）：

```csharp
[Preserve]
public class MyAdsManager : BaseAdvertisementManager
{
    // ...
}
```

同時在 `link.xml`（位於 `Assets/Plugins/` 目錄下）中新增保留規則：

```xml
<linker>
    <assembly fullname="YourAssemblyName" preserve="all">
        <type fullname="YourNamespace.MyAdsManager" preserve="all"/>
    </assembly>
</linker>
```

**步驟 3：檢查模組註冊**

確保在遊戲啟動時正確註冊了廣告管理器。具體方式取決於您的 GameFrameX 框架配置方式。

### 問題二：廣告位 ID 為空

#### 症狀

控制檯輸出警告或錯誤，表明廣告位 ID 未設定：
```
AdvertisementComponent: AdUnitId is empty!
```

#### 原因分析

此問題發生在 `AdvertisementComponent` 嘗試根據當前平臺選擇廣告位 ID 時，未能找到對應的配置。

檢查程式碼邏輯（見 `AdvertisementComponent.cs` 第 69-87 行）：

```csharp
AdUnitId =
#if UNITY_WEBGL
#if ENABLE_WECHAT_MINI_GAME
        m_adUnitIdWebGLWeChat
#elif ENABLE_DOUYIN_MINI_GAME
        m_adUnitIdWebGLDouYin
#elif ENABLE_KUAISHOU_MINI_GAME
        m_adUnitIdWebGLKuaiShou
#else
        m_adUnitIdWebGL
#endif
#elif UNITY_ANDROID
        m_adUnitIdAndroid
#elif UNITY_IOS
        m_adUnitIdiOS
#else
        string.Empty
#endif
        ;
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L69-L87)

#### 解決方案

**步驟 1：在 Inspector 中配置廣告位 ID**

1. 在 Unity 場景中選擇新增了 `AdvertisementComponent` 的 GameObject
2. 在 Inspector 面板中，根據目標平臺填寫對應的廣告位 ID：
   - **Android 廣告位ID**：填寫 Google AdMob 或其他 Android 廣告網路的 ID
   - **IOS 廣告位ID**：填寫 iOS 廣告網路的 ID
   - **WebGL 廣告位ID**：填寫 Web 平臺廣告 ID
   - **WebGL 微信/抖音/快手 廣告位ID**：填寫對應小程式平臺的廣告 ID

> Source: [AdvertisementComponentInspector.cs]({{file_base_url}}/Editor/Inspector/AdvertisementComponentInspector.cs#L41-L47)

**步驟 2：驗證平臺宏定義**

如果廣告位 ID 仍然為空，請檢查專案的編譯宏定義：
- 開啟 `Edit > Project Settings > Player`
- 在 **Other Settings** 中檢查 **Scripting Define Symbols**
- 確保為 WebGL 平臺定義了正確的宏：`ENABLE_WECHAT_MINI_GAME`、`ENABLE_DOUYIN_MINI_GAME` 或 `ENABLE_KUAISHOU_MINI_GAME`

**步驟 3：使用程式碼動態設定**

如果需要在執行時動態設定廣告位 ID：

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;

public class AdInitializer : MonoBehaviour
{
    public AdvertisementComponent adComponent;
    
    void Start()
    {
        // 動態設定廣告位ID
        string customAdUnitId = "your_ad_unit_id_here";
        adComponent.Initialize(customAdUnitId, isDebug: true);
    }
}
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L100-L105)

### 問題三：廣告載入失敗

#### 症狀

呼叫 `Load()` 方法後，`fail` 回呼被觸發，收到類似以下錯誤資訊：
```
廣告載入失敗: No ad available
廣告載入失敗: Network error
```

#### 原因分析

廣告載入失敗可能有多種原因：

1. **廣告 SDK 未正確初始化**：未在 `Initialize()` 中正確配置廣告 SDK
2. **網路問題**：裝置網路連線異常
3. **廣告位配置錯誤**：廣告單元 ID 在廣告平臺後臺未正確配置
4. **廣告庫存為空**：當前廣告平臺沒有可用的廣告
5. **SDK 版本問題**：使用的廣告 SDK 版本過舊或不相容

#### 解決方案

**步驟 1：檢查初始化程式碼**

確保在展示廣告前正確初始化了廣告 SDK：

```csharp
void Start()
{
    var adComponent = GetComponent<AdvertisementComponent>();
    // AdvertisementComponent 會在 Start 時自動呼叫 Initialize
    // 如果需要手動初始化：
    // adComponent.Initialize("your_ad_unit_id", isDebug: true);
    
    // 建議提前載入廣告
    adComponent.Load(
        (message) => Debug.Log("廣告載入成功: " + message),
        (error) => Debug.LogError("廣告載入失敗: " + error)
    );
}
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L163-L167)

**步驟 2：使用測試模式**

在開發階段，啟用除錯模式以便獲取測試廣告：

```csharp
// 在 Inspector 中勾選"是否是測試模式"
// 或者透過程式碼：
adComponent.Initialize("your_ad_unit_id", isDebug: true);
```

**步驟 3：檢查網路連線**

確保裝置具有有效的網路連線。對於移動裝置，注意：
- 蜂窩資料可能被廣告 SDK 限制
- 需要在 `AndroidManifest.xml`（Android）或 `Info.plist`（iOS）中宣告網路許可權

**步驟 4：驗證廣告位配置**

登入廣告平臺開發者後臺，確認：
- 廣告位已建立並啟用
- 廣告位 ID 與程式碼中配置的一致
- 廣告位型別（激勵影片/插屏/橫幅）匹配您的請求

### 問題四：廣告展示失敗

#### 症狀

呼叫 `Show()` 方法後，`fail` 回呼被觸發，錯誤資訊例如：
```
廣告展示失敗: Ad not ready
廣告展示失敗: Show() called before Load()
```

#### 原因分析

1. **廣告未預先載入**：在呼叫 `Show()` 前未呼叫 `Load()` 載入廣告
2. **載入的廣告已過期**：廣告載入後長時間未展示，快取已失效
3. **廣告被跳過**：廣告 SDK 內部錯誤

#### 解決方案

**正確的廣告展示流程：**

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;

public class AdCaller : MonoBehaviour
{
    private AdvertisementComponent adComponent;

    void Start()
    {
        adComponent = GetComponent<AdvertisementComponent>();
        
        // 第一步：載入廣告
        LoadAd();
    }

    public void LoadAd()
    {
        adComponent.Load(
            (message) => 
            { 
                Debug.Log("廣告載入成功，可以呼叫 Show"); 
                // 廣告載入成功後可以展示
                ShowAd();
            },
            (error) => { Debug.LogError("廣告載入失敗: " + error); }
        );
    }

    public void ShowAd()
    {
        adComponent.Show(
            (message) => Debug.Log("廣告展示成功: " + message),
            (error) => Debug.LogError("廣告展示失敗: " + error),
            (reward) => 
            {
                if (reward)
                {
                    Debug.Log("✅ 使用者完整觀看廣告，發放獎勵");
                    // 在此處新增獎勵發放邏輯
                }
                else
                {
                    Debug.Log("❌ 使用者跳過廣告，不發放獎勵");
                }
            }
        );
    }

    // 使用 Play 方法的簡化版本
    public void PlayAd()
    {
        adComponent.Play(
            (reward) => 
            {
                if (reward)
                {
                    Debug.Log("✅ 廣告播放完成，發放獎勵");
                }
            },
            "custom_data_for_ad"
        );
    }
}
```

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L121-L151)

**關鍵點：**
- 必須先呼叫 `Load()` 載入廣告，等待 `success` 回呼後再呼叫 `Show()`
- 廣告載入成功後有有效期限制，應儘快展示
- 推薦在遊戲啟動時預載入廣告

### 問題五：平臺特定問題

#### 5.1 WebGL 平臺問題

**問題：WebGL 構建後廣告不顯示**

可能原因與解決方案：

1. **瀏覽器廣告攔截**：某些瀏覽器或廣告攔截外掛會阻止廣告請求
   - 測試時使用隱私/無痕模式

2. **跨域問題**：廣告 SDK 需要正確的 CORS 配置
   - 確保伺服器響應頭包含正確的 `Access-Control-Allow-Origin`

3. **小遊戲平臺宏定義**：微信/抖音/快手小遊戲需要定義對應宏
   - 在 Player Settings 中新增：`ENABLE_WECHAT_MINI_GAME` 或 `ENABLE_DOUYIN_MINI_GAME` 或 `ENABLE_KUAISHOU_MINI_GAME`

#### 5.2 Android 平臺問題

**問題：Android 構建後應用崩潰**

可能原因與解決方案：

1. **許可權缺失**：確保 `AndroidManifest.xml` 包含必要許可權：
   ```xml
   <uses-permission android:name="android.permission.INTERNET"/>
   <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>
   ```

2. **SDK 版本衝突**：檢查是否有多個廣告 SDK 版本衝突
   - 使用 Gradle 依賴解決工具檢視並排除衝突

3. **ProGuard/R8 規則**：如果啟用了程式碼混淆，可能需要新增保留規則：
   ```properties
   -keep class com.your.ad.provider.** { *; }
   -dontwarn com.your.ad.provider.**
   ```

#### 5.3 iOS 平臺問題

**問題：iOS 構建後廣告不顯示**

可能原因與解決方案：

1. **廣告識別符號 (IDFA)**：iOS 14+ 需要請求使用者授權跟蹤
   - 在 `Info.plist` 中新增 `NSUserTrackingUsageDescription`

2. **App Transport Security (ATS)**：確保允許廣告域名的 HTTP 連線
   - 在 `Info.plist` 中配置 `NSAppTransportSecurity`

3. **Swift 版本相容**：某些廣告 SDK 需要特定 Swift 版本
   - 在 Xcode 專案設定中檢查 Swift 版本

### 問題六：獎勵發放時機問題

#### 症狀

使用者觀看完激勵影片後，獎勵未正確發放；或者使用者在廣告播放一半時退出了，獎勵仍然被髮放。

#### 原因分析

激勵影片廣告的獎勵發放邏輯需要根據 `onShowResult` 回呼的布林值來決定：

- `true`：使用者完整觀看廣告，應發放獎勵
- `false`：使用者跳過廣告或中斷播放，不應發放獎勵

> Source: [AdvertisementComponent.cs]({{file_base_url}}/Runtime/Advertisement/AdvertisementComponent.cs#L126-L127)

#### 解決方案

確保在 `onShowResult` 回呼中正確處理獎勵發放：

```csharp
public void ShowRewardAd()
{
    adComponent.Show(
        // success 回呼：廣告開始展示
        (message) => Debug.Log("廣告開始展示: " + message),
        
        // fail 回呼：廣告展示失敗
        (error) => 
        {
            Debug.LogError("廣告展示失敗: " + error);
            // 不要發放獎勵
        },
        
        // onShowResult 回呼：廣告關閉
        (shouldReward) => 
        {
            if (shouldReward)
            {
                // ✅ 使用者完整觀看廣告，發放獎勵
                Debug.Log("發放獎勵：金幣 + 100");
                AddCoins(100);
            }
            else
            {
                // ❌ 使用者未完整觀看，不發放獎勵
                Debug.Log("使用者跳過廣告，不發放獎勵");
            }
        }
    );
}
```

**安全獎勵發放建議：**

1. **在伺服器端驗證**：對於高價值獎勵，建議在伺服器端驗證獎勵發放
2. **使用廣告平臺伺服器回呼**：多數廣告平臺提供伺服器到伺服器的獎勵回呼
3. **防止重複發放**：使用標誌位防止同一廣告多次發放獎勵

### 問題七：Editor 模式下組件不工作

#### 症狀

在 Unity Editor 中執行時，廣告功能無法正常工作。

#### 原因分析

1. **Editor 不支援某些廣告 SDK**：大多數廣告 SDK 僅支援真機或特定構建平臺
2. **模組未在 Editor 模式下初始化**

#### 解決方案

**建立 Editor 專用的模擬廣告管理器：**

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;
using System;

[CreateAssetMenu(menuName = "GameFrameX/Editor Mock Ads Manager")]
public class EditorMockAdsManager : BaseAdvertisementManager
{
    [SerializeField] private bool simulateSuccess = true;
    [SerializeField] private float simulatedDelay = 1.0f;

    public override void Initialize(string adUnitId, bool debug = false)
    {
        Debug.Log($"[Editor] Mock Ads Manager 初始化: {adUnitId}");
    }

    public override void Play(Action<bool> playResult, string customData = null)
    {
        Debug.Log($"[Editor] Mock Play 被呼叫, customData: {customData}");
        playResult?.Invoke(simulateSuccess);
    }

    public override void Show(Action<string> success, Action<string> fail, 
        Action<bool> onShowResult, string customData = null)
    {
        Debug.Log($"[Editor] Mock Show 被呼叫, customData: {customData}");
        
        if (simulateSuccess)
        {
            success?.Invoke("Mock ad shown successfully");
            onShowResult?.Invoke(true);
        }
        else
        {
            fail?.Invoke("Mock ad failed");
        }
    }

    public override void Load(Action<string> success, Action<string> fail, 
        string customData = null)
    {
        Debug.Log($"[Editor] Mock Load 被呼叫");
        
        if (simulateSuccess)
        {
            success?.Invoke("Mock ad loaded successfully");
        }
        else
        {
            fail?.Invoke("Mock ad failed to load");
        }
    }
}
```

**在 Inspector 中選擇 Editor 模擬實現：**

1. 選擇場景中的 AdvertisementComponent 物件
2. 在 Inspector 中找到廣告管理器實現型別選擇器
3. 選擇 Editor 模擬管理器

## 診斷工具與日誌

### 啟用除錯模式

除錯模式會輸出詳細的廣告操作日誌，幫助排查問題：

```csharp
// 方法1：在 Inspector 中勾選"是否是測試模式"

// 方法2：透過程式碼設定
adComponent.Initialize("your_ad_unit_id", isDebug: true);
```

### 關鍵日誌標籤

在控制檯中過濾以下標籤可以幫助定位問題：

| 日誌標籤 | 含義 |
|---------|------|
| `Advertisement manager is invalid` | 廣告管理器未註冊 |
| `廣告載入成功/失敗` | 載入操作結果 |
| `廣告展示成功/失敗` | 展示操作結果 |
| `發放獎勵` | 獎勵發放邏輯 |

## 常見錯誤程式碼參考

| 錯誤程式碼 | 含義 | 解決方案 |
|---------|------|---------|
| `No ad available` | 當前無廣告庫存 | 等待一段時間後重試，或聯絡廣告平臺 |
| `Network error` | 網路連線問題 | 檢查網路連線 |
| `Ad not ready` | 廣告未載入 | 先呼叫 Load() 方法 |
| `Show() called before Load()` | 展示順序錯誤 | 確保先 Load 再 Show |
| `Invalid ad unit ID` | 廣告位 ID 無效 | 檢查廣告位 ID 配置 |
| `SDK not initialized` | SDK 未初始化 | 檢查 Initialize() 呼叫 |
