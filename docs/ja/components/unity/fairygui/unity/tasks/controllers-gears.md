# コントローラーとギアの連動

コントローラー(Controller)は複数の「ページ」間の切り替えを担当し、ギア(Gear)はコンポーネントのプロパティをコントローラーのページにバインドします。ページが変わるとプロパティも自動的に追従して変化します。このページでは、ランタイムコードでコントローラーを取得する方法、ページを切り替える方法、変化をリッスンする方法、およびギアのイージング動作を調整する方法について説明します。

## 前提条件

コントローラーとギアは、まず FairyGUI エディターで作成および設定しておく必要があります。ソースコードのコメントには「コントローラーの作成と設計はエディターで行う必要があり、コードでの作成は推奨されません」と明記されています([Controller.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Controller.cs#L7-L11) を参照)。ギアのデータは、UI パッケージのロード時に `GearBase.Setup(ByteBuffer)` によって逆シリアル化され、所属コンポーネントのコントローラーと自動的に関連付けられます。ランタイムコードは取得と切り替えのみを担当します。

## 操作手順

1. **コンポーネント上のコントローラーインスタンスを取得します**。コントローラーは特定の `GComponent` に属しており、ギアは逆シリアル化時にコンポーネントを介してインデックスでコントローラーを取得しています:

```csharp
_controller = _owner.parent.GetControllerAt(buffer.ReadShort());
```

出典： [GearBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Gears/GearBase.cs#L61-L64)

あなたのコードでも同様にコンポーネント経由でアクセスします。例：`Controller c = com.GetControllerAt(0);`。`c.name`、`c.pageCount`、`c.GetPageName(index)`、`c.GetPageId(index)` でコントローラーの情報を確認できます(いずれも `Controller` の公開メンバーです)。

エディターで選択可能なギアのタイプと本リポジトリでの対応する実装：

| ギア | ソースファイル | 説明 |
|------|--------|------|
| `GearXY` | Runtime/UI/Gears/GearXY.cs | 位置の連動(パーセント位置をサポート) |
| `GearSize` | Runtime/UI/Gears/GearSize.cs | サイズの連動 |
| `GearLook` | Runtime/UI/Gears/GearLook.cs | 外観の連動(不透明度、可視性など) |
| `GearColor` | Runtime/UI/Gears/GearColor.cs | 色の連動 |
| `GearAnimation` | Runtime/UI/Gears/GearAnimation.cs | アニメーション再生の連動 |
| `GearText` | Runtime/UI/Gears/GearText.cs | テキストの連動 |
| `GearIcon` | Runtime/UI/Gears/GearIcon.cs | アイコンの連動 |
| `GearFontSize` | Runtime/UI/Gears/GearFontSize.cs | フォントサイズの連動 |
| `GearDisplay` | Runtime/UI/Gears/GearDisplay.cs | 表示/非表示の連動(ページリストによる) |
| `GearDisplay2` | Runtime/UI/Gears/GearDisplay2.cs | 高度な表示連動(condition 条件付き) |

2. **アクティブページを切り替えます**。4 つの方法があり、インデックス指定か名前指定か、`onChanged` イベントをトリガーするかどうかが異なります:

```csharp
c.selectedIndex = 2;        // インデックスで切り替え、onChanged をトリガー
c.selectedPage = "page2";   // 名前で切り替え、onChanged をトリガー
c.SetSelectedIndex(2);      // インデックスでサイレントに切り替え、onChanged をトリガーしない
c.SetSelectedPage("page2"); // 名前でサイレントに切り替え、onChanged をトリガーしない
```

`selectedIndex` への代入の実際の実装(範囲外では `IndexOutOfRangeException` をスロー、先に適用してからイベントをディスパッチ):

```csharp
set
{
    if (_selectedIndex != value)
    {
        if (value > _pageIds.Count - 1)
            throw new IndexOutOfRangeException("" + value);

        changing = true;

        _previousIndex = _selectedIndex;
        _selectedIndex = value;
        parent.ApplyController(this);

        DispatchEvent(EventName.onChanged, null);

        changing = false;
    }
}
```

出典： [Controller.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Controller.cs#L67-L84)

3. **ページの変化をリッスンします**。`Controller` は `onChanged` イベントリスナーを公開しており、ページが変更されるとトリガーされます。コールバック内では `selectedPage`/`selectedIndex` で現在のページを、`previousPage`/`previousIndex` で前回のページを読み取ることができます:

```csharp
/// コントローラーのアクティブページが変更されたときに、このイベントがトリガーされます。
public EventListener onChanged
{
    get { return _onChanged ?? (_onChanged = new EventListener(this, EventName.onChanged)); }
}
```

出典： [Controller.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Controller.cs#L48-L55)

4. **ギアのイージングを調整します**(任意)。エディターでギアに設定されたイージングは `GearTweenConfig` に逆シリアル化されます:

```csharp
if (buffer.ReadBool())
{
    _tweenConfig = new GearTweenConfig();
    _tweenConfig.easeType = (EaseType)buffer.ReadByte();
    _tweenConfig.duration = buffer.ReadFloat();
    _tweenConfig.delay = buffer.ReadFloat();
}
```

出典： [GearBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Gears/GearBase.cs#L90-L96)

ランタイムでは、すべてのギアのトゥイーンを一括で無効化できます(例：初期化時のちらつきを回避):`GearBase.disableAllTweenEffect = true;`(静的フィールド、デフォルトは `false`、[GearBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Gears/GearBase.cs#L10) を参照)。

## 一般的なバリエーション

**ボタンによるコントローラー駆動(単一選択グループ)**:`GButton` の Radio/Check モードは、クリック時に関連コントローラーを指定ページへ切り替えるため、切り替えコードを手書きする必要はありません:

```csharp
_relatedController.selectedPageId = _relatedPageId;
```

出典： [GButton.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GButton.cs#L249-L256)

同じコントローラーが変更された際、ボタンは現在のページに応じて選択状態を同期します:

```csharp
if (_relatedController == c)
    this.selected = _relatedPageId == c.selectedPageId;
```

出典： [GButton.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GButton.cs#L438-L441)

**一部のページのみ表示を連動させる**:`GearDisplay`/`GearDisplay2` はページごとの状態を保存せず、ページ配列 `pages` を保持し、コントローラーが配列内のページにあるときのみ表示されます。`GearDisplay2` はさらに `condition` バイトで条件方式を制御します。対応する逆シリアル化の分岐は [GearBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Gears/GearBase.cs#L66-L74) と [GearBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Gears/GearBase.cs#L118-L119) を参照してください。

**パーセント位置による連動**:`GearXY` は `positionsInPercent` をサポートしており、データバージョン ≥ 2 の場合に拡張状態 `AddExtStatus` を読み取ります。[GearBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Gears/GearBase.cs#L100-L116) を参照してください。

## よくあるエラー

- **`IndexOutOfRangeException`**:`selectedIndex`/`SetSelectedIndex` に渡した値が `pageCount - 1` を超えるとスローされます。設定前に `c.pageCount` を確認してください。
- **`selectedPage` を代入しても「効いていない」のに第 0 ページへジャンプする**:`selectedPage` の setter は `IndexOf` で検索し、名前が見つからない場合はサイレントにインデックス 0 へフォールバックします([Controller.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/Controller.cs#L133-L139) を参照)。ページ名のスペルミスは、知らないうちに間違ったページへ切り替えてしまう原因になります。
- **コールバック内でさらにページを変更してしまう**:プロパティ setter の内部では先に `parent.ApplyController(this)` を実行してから `onChanged` をディスパッチするため、イベントコールバック内で再び `selectedIndex` を変更するとネストした変更となり、状態のジッターを引き起こしやすくなります。どうしても連動が必要な場合は次フレームでの実行にしてください。
- **サイレント切り替えの誤用**:`SetSelectedIndex`/`SetSelectedPage` と `selectedIndex`/`selectedPage` の違いは「`onChanged` をトリガーしない」点のみで、ギアの連動(`parent.ApplyController`)はどちらも実行されます。サイレント設定が UI に影響しないと思い込まないでください。

## 検証

- 切り替え後に `c.selectedPage`、`c.selectedIndex` を読み取り、設定値と一致していることを確認します。`c.previousPage`/`c.previousIndex` は切り替え前の値になっているはずです。
- `onChanged` に一時的にコールバックを取り付け、プロパティ代入では受信でき、`SetSelectedIndex` では受信できないことを確認します。
- 目視確認：ギアが設定されたターゲットコンポーネント(位置/サイズ/色/表示など)がページの切り替えに追従し、`tweenConfig` に従ってイージングすることを確認します。

## 背景

ギアの本質は「オブジェクトとコントローラー間の接続」です。各ギアは `_owner`(ターゲットコンポーネント)と `_controller`(関連コントローラー)を保持し、コントローラーの `selectedIndex` が変更されると `parent.ApplyController(this)` が呼び出され、コンポーネントが新しいページを各ギア(例:`GearLook.OnControllerChanged` のようなコールバック)へ配布して対応する状態を適用します。トゥイーンは `GearTweenConfig`(easeType/duration/delay)によって駆動され、`GearBase.disableAllTweenEffect` がグローバルスイッチを提供します。
