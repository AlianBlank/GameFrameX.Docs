# How to Start and Stop Coroutines

Use `CoroutineComponent` to start and stop individual coroutines, as well as stop all coroutines in batch.

## Prerequisites

- The `com.gameframex.unity.coroutine` package has been installed, and the `CoroutineComponent` component has been attached to a scene (the framework automatically registers this component).
- The caller must be able to obtain a `CoroutineComponent` instance (typically via `GameEntry.GetComponent<CoroutineComponent>()` or by holding a reference in a custom component).

## Steps

### 1. Get the Coroutine Component

```csharp
var coroutineComponent = GameEntry.GetComponent<CoroutineComponent>();
```

### 2. Start a Coroutine

Pass an iterator method to `StartCoroutine`. The component internally tracks the coroutine using a `ConcurrentDictionary`, allowing it to be stopped later via the same iterator instance.

```csharp
IEnumerator MyTask()
{
    yield return new WaitForSeconds(1f);
    Debug.Log("Executed after 1 second");
}

IEnumerator enumerator = MyTask();
coroutineComponent.StartCoroutine(enumerator);
```

> Note: Since `IEnumerator` is used as a dictionary key based on reference equality, `StopCoroutine` must be passed the **same** `IEnumerator` instance as the one used in `StartCoroutine`.

Source: [CoroutineComponent.cs#L28-L33](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

### 3. Stop a Single Coroutine

You can stop a coroutine either by its iterator or by its `UnityEngine.Coroutine` object. The component will remove it from both the Unity engine and the internal tracking dictionary.

```csharp
// Method A: Stop by iterator (must pass the same instance used at startup)
coroutineComponent.StopCoroutine(enumerator);

// Method B: Stop by UnityEngine.Coroutine object
coroutineComponent.StopCoroutine(handle);
```

Source: [CoroutineComponent.cs#L39-L67](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L67)

### 4. Stop All Coroutines

After clearing the tracked coroutines, the base class method is called to thoroughly clean up all running coroutines. This is suitable for scene transitions or exit logic.

```csharp
coroutineComponent.StopAllCoroutines();
```

Source: [CoroutineComponent.cs#L72-L82](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

## Common Variants

### End-of-Frame Callback

When you need to execute a piece of logic after the current frame finishes rendering, you can use the convenient `WaitForEndOfFrameFinish` interface without writing an iterator yourself.

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    Debug.Log("Current frame rendering completed");
});
```

Source: [CoroutineComponent.cs#L101-L104](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L101-L104)

> If the coroutine is stopped via `StopCoroutine` or `StopAllCoroutines` before the callback fires, the callback will not be executed.

## Common Errors

| Symptom | Cause | Workaround |
|------|------|---------|
| `StopCoroutine` does not take effect | The passed `IEnumerator` is not the same instance used at startup (e.g., the iterator method was called again) | Save the `IEnumerator` reference returned or passed at startup, and reuse it when stopping |
| Coroutine object holding causes memory leak | Coroutine was not stopped before the object was destroyed | Call `StopAllCoroutines` in `OnDestroy`, or explicitly call `StopCoroutine` |
| Calling `StartCoroutine` through a subclass reference does not enter the tracking dictionary | The base class method is hidden by `new`, and only references of type `CoroutineComponent` are recorded | Always use a reference of type `CoroutineComponent` to call `StartCoroutine` |

## Background (Optional)

`CoroutineComponent` inherits from `GameFrameworkComponent` and overrides the same-named methods of `MonoBehaviour` using the `new` keyword. Internally, it uses a `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` to store both the startup parameters and the coroutine handle returned by Unity, making it easy to stop by either iterator or handle in both directions, while ensuring thread-safe access.
