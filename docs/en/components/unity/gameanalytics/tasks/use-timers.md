# How to Use Timers to Track Duration (Start / Pause / Resume / Stop)

Calling the four timer interfaces on `GameAnalyticsComponent` (or the underlying `IGameAnalyticsManager`) completes a full duration tracking flow: `StartTimer` to start, `PauseTimer` to pause, `ResumeTimer` to resume, and `StopTimer` to stop and produce the duration data for that event. All four interfaces take a single parameter `eventName` (the event name), and the component forwards it to all initialized analytics backends.

## Prerequisites

- `GameAnalyticsComponent` is mounted in the scene and initialized (`Init` / `ManualInit`). If not initialized, timer calls are silently ignored and may output a `GameAnalyticsManager is not init.` warning.
- For details on the initialization flow, refer to the component's documentation.

## Steps

1. Confirm the component is initialized (`IsInit()` returns `true`).
2. Call `StartTimer` where the gameplay begins, passing in the event name to track:

```csharp
public void StartTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StartTimer(eventName);
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/README.md#L80-L86)

3. (Optional) When switching to the background or when the player leaves the gameplay, call `PauseTimer` to pause accumulation:

```csharp
_gameAnalyticsComponent.PauseTimer("level_1_playtime");
```

4. (Optional) When the player returns, call `ResumeTimer` to continue accumulating:

```csharp
_gameAnalyticsComponent.ResumeTimer("level_1_playtime");
```

5. When the gameplay ends, call `StopTimer` to stop the timer; the duration data is reported along with the event name:

```csharp
public void StopTimer(string eventName)
{
    if (!_isInit) return;
    _gameAnalyticsManager.StopTimer(eventName);
}
```

### Interface Overview

| Name | Signature | Description |
|------|------|------|
| Start timer | `void StartTimer(string eventName)` | Starts the timer for the specified event name |
| Pause timer | `void PauseTimer(string eventName)` | Pauses duration accumulation for that event name |
| Resume timer | `void ResumeTimer(string eventName)` | Resumes accumulation from where it was paused |
| Stop timer | `void StopTimer(string eventName)` | Stops the timer and produces the duration data for that event |

All four signatures are defined in `IGameAnalyticsManager` (`StartTimer` L52, `PauseTimer` L58, `ResumeTimer` L64, `StopTimer` L70).

### Complete Ready-to-Use Wrapper

```csharp
private const string LevelTimerName = "level_1_playtime";

public void OnLevelStart()
{
    GameAnalyticsComponent.Instance.StartTimer(LevelTimerName);
}

public void OnApplicationPause(bool pauseStatus)
{
    if (pauseStatus)
    {
        GameAnalyticsComponent.Instance.PauseTimer(LevelTimerName);
    }
    else
    {
        GameAnalyticsComponent.Instance.ResumeTimer(LevelTimerName);
    }
}

public void OnLevelFinish()
{
    GameAnalyticsComponent.Instance.StopTimer(LevelTimerName);
}
```

Note: The exact way to obtain `GameAnalyticsComponent.Instance` depends on how components are registered in your project; the four method names and signatures above come from the actual repository interfaces.

## Common Variants

- **Short duration tracking without pausing**: Just call `StartTimer` and `StopTimer`; `PauseTimer` / `ResumeTimer` can be omitted (the official example in the README only contains these two calls).
- **Tracking multiple events in parallel**: Call `StartTimer` with different `eventName` values respectively; each timer operates independently. The behavior of starting the same event name repeatedly is determined by the underlying analytics backend; it is recommended to use the same event name serially.
- **Interfacing directly with the underlying Manager**: If you hold an `IGameAnalyticsManager` implementation instead of going through the component, you can call the same-named interfaces directly, bypassing the component loop; `BaseGameAnalyticsManager` declares the four timer methods as abstract methods, implemented by concrete backends.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Timer calls produce no reported data | Component not initialized; the method directly `return`s when `m_IsInit == false` | Call `Init` / `ManualInit` first before starting the timer |
| Log shows `GameAnalyticsManager is not init.` | While iterating, `StartTimer` / `StopTimer` found a backend whose `IsInit()` is `false` | Confirm all analytics backends have finished initializing |
| Passing an empty event name throws an exception | `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))` intercepts empty/`null` | Ensure `eventName` is non-empty |
| Duration continues to be counted after pausing | Only methods other than `PauseTimer` were called, or the event names are inconsistent | Pausing and resuming must use the same `eventName` used at start |

Taking `StartTimer` as an example, the component's internal checks on parameters and initialization state are as follows (`StopTimer` has identical logic):

```csharp
public void StartTimer(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.StartTimer(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179)

## Verification

- After calling `StopTimer`, check the corresponding analytics platform (the GameAnalytics dashboard) to see whether the duration data for that `eventName` appears with reasonable values.
- If there is no data, check the Console for a `GameAnalyticsManager is not init.` warning, and confirm that `eventName` is non-empty and that the same name is used for both start and stop.

## Background

`GameAnalyticsComponent` acts as a facade for the four timer interfaces: it first performs parameter guarding and initialization checks, then broadcasts the call to all initialized `IGameAnalyticsManager` implementations in the `m_GameAnalyticsManager` list (the broadcasts of `PauseTimer` / `ResumeTimer` do not perform a secondary `IsInit()` check, but they are still blocked by the component-level `m_IsInit`). The actual timing logic is implemented by each analytics backend via the abstract methods in `BaseGameAnalyticsManager`.
