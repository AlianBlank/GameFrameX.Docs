# 日誌報 "Mono manager is invalid." 怎麼辦

當 `MonoComponent.Awake()` 透過 `GameFrameworkEntry.GetModule<IMonoManager>()` 取不到已註冊的 `IMonoManager` 實作時，會立即呼叫 `Log.Fatal("Mono manager is invalid.")` 並中止後續初始化，所有 Update/FixedUpdate/LateUpdate 都不會再執行。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 主控台日誌:`Mono manager is invalid.` | `MonoManager` 模組尚未註冊到 `GameFrameworkEntry` | 在 `GameEntry`/啟動流程中先於 `MonoComponent` 呼叫 `GameFrameworkEntry.RegisterModule(new MonoManager())` |
| 同上，場景中只掛了 `MonoComponent` 但沒有 `GameFrameworkEntry` 引導 | 啟動順序錯誤:`MonoComponent` 在 `GameFrameworkEntry` 初始化之前就 `Awake` 了 | 調整腳本執行順序，確保 `GameFrameworkEntry` 先完成註冊 |
| 同上，報 "Event manager is invalid." 緊跟其後 | `EventComponent` 也未掛載 | 在 `GameEntry` 上新增 `EventComponent`,見 [`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76) |

## 修復步驟

### 1. 在啟動時註冊 `MonoManager` 模組

`MonoComponent` 只負責「呼叫已經存在的管理器」，真正建立並註冊模組的職責在啟動流程。框架入口需明確呼叫：

```csharp
using GameFrameX.Mono.Runtime;
using GameFrameX.Runtime;

// 在 GameFrameworkEntry 初始化階段(早於任何 MonoComponent.Awake)
GameFrameworkEntry.RegisterModule(new MonoManager());
```

註冊邏輯只接受 `IMonoManager` 實作，而 `MonoManager` 是框架內建的預設實作([`MonoManager.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L42-L43))。

### 2. 確保 `MonoComponent` 的 Awake 晚於 `GameFrameworkEntry`

`MonoComponent` 在 `Awake` 中透過 `GameFrameworkEntry.GetModule<IMonoManager>()` 取得模組([`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L57-L62))。如果 `MonoComponent` 掛在比 `GameFrameworkEntry` 引導腳本更早的 GameObject 上,`GetModule` 會回傳 `null`。

修復方法：
1. 把 `MonoComponent` 掛到一個獨立的 GameObject,確保 `GameFrameworkEntry` 的入口元件先於它 `Awake`。
2. 在 Unity 的 `Project Settings → Script Execution Order` 中，把 `MonoComponent` 排在啟動元件之後。

### 3. 不要停用或重新命名 `MonoComponent`

- 類別上標註了 `[DisallowMultipleComponent]` 與 `[AddComponentMenu("GameFrameX/Mono")]`([`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L42-L43)),重複掛載或重新命名繼承鏈會讓基底類別 `Awake` 行為異常，導致模組取得失敗。

## 驗證

1. 啟動遊戲，確認主控台不再出現 `Mono manager is invalid.`,而是看到正常的 Mono 事件流程。
2. 呼叫 `IMonoManager.AddUpdate(...)` 註冊的回呼應能在每幀觸發：

```csharp
var mono = GameFrameworkEntry.GetModule<IMonoManager>();
mono.AddUpdate((dt, udt) => { /* 每幀執行 */ });
```

3. 若 `MonoComponent.Start()` 仍報 `Event manager is invalid.`,表示 `EventComponent` 未掛載，按 `MonoComponent.Start` 的檢查路徑補齊即可([`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76))。
