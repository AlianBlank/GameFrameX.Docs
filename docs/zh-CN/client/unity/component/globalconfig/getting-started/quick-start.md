# 快速上手

`GlobalConfig` 是 GameFrameX 的全局配置组件，用于集中管理应用版本检测地址、资源版本检测地址、主机服务地址以及一段可自定义的附加内容；本节将带你完成安装、挂载组件并读取配置的全流程。

## 前置条件

- Unity 2019.4 或更高版本。
- 已安装 `com.gameframex.unity` 与 `com.gameframex.unity.web` 两个依赖包（最新稳定版本见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/README.zh-CN.md#L76-L80)）。
- 已有一个 GameFrameX 框架入口场景（包含 `GameFramework` 组件），因为 `GlobalConfigComponent` 继承自 `GameFrameworkComponent`。

## 安装

任选其一完成安装：

1. **修改 `Packages/manifest.json`（推荐）**，加入 GameFrameX scoped registry：

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.globalconfig": "1.3.2"
     }
   }
   ```

2. **直接以 Git URL 添加**，在 `manifest.json` 的 `dependencies` 下写入：

   ```json
   {
     "dependencies": {
       "com.gameframex.unity.globalconfig": "https://github.com/gameframex/com.gameframex.unity.globalconfig.git"
     }
   }
   ```

3. **Unity Package Manager → Add package from git URL**，填入 `https://github.com/gameframex/com.gameframex.unity.globalconfig.git`。

4. **本地源码安装**：把仓库目录拷到工程的 `Packages/` 下，Unity 会自动识别。

## 操作步骤

1. **挂载组件到框架入口**。在入口 GameObject 上点击 `Add Component → GameFrameX → Global Config`，添加 `GlobalConfigComponent`。组件自身在 `Awake` 中会关闭自动注册（`IsAutoRegister = false`），需要你在合适的时机手动调用：

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   using UnityEngine;

   public class GlobalConfigBootstrap : MonoBehaviour
   {
       [SerializeField] private GlobalConfigComponent m_GlobalConfig;

       private void Start()
       {
           // 由你的启动流程调用，把组件注册到 GameFrameX 框架
           GameFrameX.Runtime.GameFrameworkEntry.RegisterComponent(m_GlobalConfig);
       }
   }
   ```

   `Awake` 与组件特性的定义见 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L11-L13)。

2. **填写基础字段**。在 Inspector 中至少填一项 `Check App Version Url` 或 `Check Resource Version Url`，并按需设置 `Host Server Url`、`Content`、`AOT Code List`。所有字段在组件中都是 `[SerializeField]` 暴露的字符串字段，定义见 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L18-L98)。

3. **从服务器拉取并注入配置**。用任意 HTTP 客户端请求你的全局信息接口，把 JSON 反序列化成 `ResponseGlobalInfo` 后调用 `SetGlobalConfig`：

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;
   using GameFrameX.Runtime;

   var component = GameFrameworkEntry.GetComponent<GlobalConfigComponent>();
   var rawJson = "<服务器返回的 JSON>";
   var info = Utility.Json.ToObject<ResponseGlobalInfo>(rawJson);
   component.SetGlobalConfig(info);
   ```

   `ResponseGlobalInfo` 的字段定义见 [ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L6-L27)，`SetGlobalConfig` 会做空值校验并抛 `ArgumentNullException`，签名见 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L160-L168)。

4. **在游戏逻辑中读取**。通过 `GameFrameworkEntry.GetComponent<GlobalConfigComponent>()` 获取实例，然后访问对应属性：

   ```csharp
   var globalConfig = GameFrameworkEntry.GetComponent<GlobalConfigComponent>();
   string appVersionUrl = globalConfig.CheckAppVersionUrl;
   string resourceUrl   = globalConfig.CheckResourceVersionUrl;
   string hostUrl       = globalConfig.HostServerUrl;
   string extra         = globalConfig.Content;

   ResponseGlobalInfo info = globalConfig.GlobalInfo;
   string serverAotJson    = info?.AOTCodeList;
   ```

   `AOTCodeList` 是 JSON 字符串，赋值时会自动解析成 `AOTCodeLists` 列表；解析失败会输出错误日志，但不会抛出异常（[GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L46-L79)）。

## 常见变体

- **只想存一个原始 JSON 字符串**：调用 `SetOriginalData(json)` 直接保存，外部解析即可，签名见 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L126-L134)。
- **在 Inspector 编辑 AOT 列表**：1.3.2 起 `AOTCodeLists` 已改为只读，列表只能通过 `AOTCodeList` JSON 字段赋值后自动解析，详见 [GlobalConfigComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/GlobalConfigComponent.cs#L51-L79) 和版本说明。
- **运行时切换服务器地址**：直接给 `CheckAppVersionUrl`、`CheckResourceVersionUrl`、`HostServerUrl` 赋值即可，属性都是带 setter 的。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GetComponent<GlobalConfigComponent>()` 返回 `null` | 组件未手动注册（`IsAutoRegister = false`） | 在启动脚本中调用 `GameFrameworkEntry.RegisterComponent(m_GlobalConfig)` |
| `SetGlobalConfig(null)` 抛 `ArgumentNullException` | 入参为空 | 在调用前判断非空，确保服务器返回了有效对象 |
| `AOTCodeLists` 一直是空 | `AOTCodeList` 不是合法 JSON 字符串 | 确认服务器下发的 JSON 形如 `["a.dll","b.dll"]`；失败时控制台会有 `Log.Error` |
| 服务器下发后 `GlobalInfo` 为 `null` | 还没调用 `SetGlobalConfig` 或 `SetOriginalData` | 在请求成功的回调里调用 `SetGlobalConfig` |

## 背景（可选）

`GlobalConfigComponent` 是一个 `sealed` 的 `GameFrameworkComponent`，由 `Awake` 关闭自动注册，因此必须由业务侧控制生命周期；它只持有配置，不主动发起网络请求，`RequestBase` 与各 `Request*` / `Response*` 类型只是配套的请求/响应数据载体，逻辑由调用方决定。
