# 發生無效字元例外時的處理方式

當呼叫 `JsonMapper.ToObject` / `JsonReader` 解析輸入時，如果拋出了訊息類似 `Invalid character '{0}' in input string` 的 `JsonException`，表示詞法分析器在輸入字串中遇到了不在 JSON 詞法表中的字元。本頁面可協助您快速找出原因並修復問題。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| `Invalid character 'x' in input string`（x 為字母） | 輸入不是有效的 JSON，例如第一個字元是未加引號的 `xyz`、未加引號的 `true`，或是非 JSON 文字（例如 XML / YAML / 註解） | 使用線上 JSON 驗證工具確認格式；確保文字以 `{`、`[`、數字、字串或 `true`/`false`/`null` 其中之一開頭 |
| 例外訊息包含數字 / 控制字元（例如 `Invalid character '\0'`） | 字串結尾有 BOM（`\uFEFF`）、結尾的 `\r`，或殘留的二進位位元組 | 解析前先執行 `Trim` / `Trim('\uFEFF')`；讀取串流時使用預設 UTF-8 的 `StreamReader` 以去除 BOM |
| 例外訊息包含反斜線 `\` 後面接著非法字元 | 字串中的逸出序列無效（例如長度不足的 `"\x"`、`"\u00"`、`"\u12"`） | 僅允許以下逸出序列：`\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX`（4 個十六進位數字） |
| 例外訊息包含 `'`（單引號）或 `,` 後面有換行 | JSON 混入了 JavaScript / Python 風格的語法（單引號字串、註解、結尾逗號） | 移除單引號，改用雙引號；移除 `//`、`/* */` 註解，以及物件 / 陣列結尾多餘的逗號 |
| 例外訊息包含中文字元 | 將 `null` / `undefined` / C# 預設的 `ToString()` 輸出等內容直接傳給了解析器 | 先檢查回應主體是否真的是 JSON（`Content-Type` / 第一個字元）；如果不是，請勿呼叫 `JsonMapper.ToObject` |

例外訊息的原始範本來自 `JsonException(int c)` 建構函式：

```csharp
internal JsonException(int c) :
    base(string.Format(
             "Invalid character '{0}' in input string", (char)c))
{
}
```

來源：[Runtime/JsonException.cs#L77-L83](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonException.cs#L77-L83)

## 修復步驟

### 1. 先輸出原始輸入內容

不要只在日誌中貼上 `e.Message`，而要輸出實際傳給解析器的字串。例外訊息中的字元就是該位置上的問題字元。

```csharp
try
{
    var obj = GameFrameX.LitJSON.Runtime.JsonMapper.ToObject<Dictionary<string, object>>(rawText);
}
catch (GameFrameX.LitJSON.Runtime.JsonException ex)
{
    Debug.LogError($"LitJSON parse failed: {ex.Message} | raw input length={rawText?.Length} | first 64 chars=[{rawText?.Substring(0, System.Math.Min(64, rawText?.Length ?? 0))}]");
}
```

### 2. 處理 BOM 與隱藏字元

如果伺服器回傳的是帶有 BOM 的 UTF-8，或檔案是由 Windows 記事本儲存的，字串開頭就會殘留一個 `\uFEFF`，詞法分析器會將其當作「無效的首字元」拋出例外。

```csharp
using GameFrameX.LitJSON.Runtime;

string rawText = File.ReadAllText(path);
// 去除開頭的 BOM
if (!string.IsNullOrEmpty(rawText) && rawText[0] == '\uFEFF')
    rawText = rawText.Substring(1);

var data = JsonMapper.ToObject<MyData>(rawText);
```

參考資料：[Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs) 中的狀態機在遇到不在表中的字碼點（codepoint）時會拋出 `JsonException(c)`。

### 3. 修正逸出序列

JSON 字串僅支援以下逸出序列；其他如 `\'`、`\x`、`\v`、`\u{}`，或不滿 4 個十六進位數字的 `\u`，都會觸發 `Invalid character` 例外（發生在 `\` 後面的字元上）。

| 有效逸出序列 | 說明 |
|----------|------|
| `\"` | 雙引號 |
| `\\` | 反斜線 |
| `\/` | 正斜線 |
| `\b` `\f` `\n` `\r` `\t` | 控制字元 |
| `\uXXXX` | 必須是 4 個十六進位數字（例如 `\u4E2D`） |

### 4. 修正非法的 JSON 語法

LitJSON 是嚴格的 JSON 解析器，**不**支援 JavaScript / JSON5 風格的擴充語法：

- 字串必須使用雙引號，不得使用單引號 `'…'`。
- 不允許 `//`、`/* */` 註解。
- 物件 / 陣列的最後一個元素後面不得有多餘的 `,` 逗號。
- 數字不得有前導零或十六進位字面值（`0x1A`）。

```csharp
// 錯誤 — 不是 JSON
var bad = "{ name: 'Tom', age: 18, }";

// 修正後
var good = "{\"name\":\"Tom\",\"age\":18}";
var obj = JsonMapper.ToObject<Dictionary<string, object>>(good);
```

### 5. 確認呼叫進入點

`JsonMapper.ToObject` 的進入點簽章請見 [Runtime/JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs)；`JsonReader` 串流進入點則位於 [Runtime/JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs)。無論經由哪個進入點，詞法錯誤都會被包裝為同樣的 `JsonException`。

## 驗證

請依照以下順序確認問題已解決：

1. 將觸發例外的輸入內容複製到任一線上 JSON 驗證工具（例如 jsonlint），確認格式有效後，再回到程式碼。
2. 重新執行程式，確認不再拋出 `JsonException`，且 `JsonMapper.ToObject<T>` 能正常回傳結果。
3. 如果資料來自網路回應，還要驗證回應標頭 `Content-Type: application/json` 以及回應主體的第一個字元，以避免將 HTML 錯誤頁面或空回應送進解析器。

## 背景說明（選讀）

LitJSON 的詞法分析基於有限狀態機（[Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs)）；解析表 `parse_table` 不接受任何非 JSON 字元。一旦讀取到這類字元，就會透過 `JsonException(int c)` 拋出 `Invalid character '{0}' in input string`。例外訊息中的字元即為問題字元本身，因此診斷時應優先關注這個字元，而非字串內容。
