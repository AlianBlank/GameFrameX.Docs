# How to Configure Show/Hide Animations and Lifecycle for UI Forms

Enable show/hide animations for UGUI forms, and handle initialization, show, hide, and recycle logic via lifecycle callbacks. This page provides an executable minimal path: from toggling animations with Attributes, to inheriting from `UGUI` and implementing lifecycle methods.

## Prerequisites

- The workflow for opening forms via the GameFrameX UI framework is in place, and UI assets have logic scripts inheriting from `UGUI` attached.
- You understand that in the framework, `OptionUIShowAnimationAttribute` / `OptionUIHideAnimationAttribute` are used to enable animations per class declaration, and the actual animation playback is implemented by `IUIFormShowHandler` / `IUIFormHideHandler`.

## Steps

### 1. Declare the Show Animation Attribute on the Form Class

Add `[OptionUIShowAnimation]` to a script class inheriting from `UGUI`; the framework reads it when creating the form and writes the values into `EnableShowAnimation` / `ShowAnimationName`:

```csharp
using GameFrameX.UI.Runtime;
using GameFrameX.UI.UGUI.Runtime;

[OptionUIShowAnimation(Enable = true, AnimationName = "Show")]
public sealed class MainMenuForm : UGUI
{
    // ...
}
```

### 2. Declare the Hide Animation Attribute

Similarly, use `[OptionUIHideAnimation]` to control the hide animation:

```csharp
[OptionUIHideAnimation(Enable = true, AnimationName = "Hide")]
public sealed class MainMenuForm : UGUI
{
    // ...
}
```

Source: [UGUIFormHelper.cs#L135-L144](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L135-L144)

> When no attribute is declared, the framework falls back to the global switches `IsEnableUIShowAnimation` / `IsEnableUIHideAnimation` on `UIComponent`; you can disable animations globally at the project level to speed up debugging.

### 3. Implement Lifecycle Callbacks

After inheriting from `UGUI`, override the lifecycle methods. The framework triggers them in the following order:

| Phase | Method | When Triggered |
|------|------|----------|
| Awake | `OnAwake()` | When the form instance is first created; called once by `UGUIFormHelper.CreateUIForm` |
| Initialize | `OnInit()` | Each time the form is opened; first-time data initialization |
| Before Show | `OnShow()` | Before the `Show` flow invokes the show animation |
| Show | (callback after animation completes) | Subsequent business logic triggered by `complete` of `IUIFormShowHandler` |
| Hide | `OnHide()` | Before the `Hide` flow invokes the hide animation |
| Recycle | `OnRecycle()` | When the form is closed and recycled; see [UIManager.Close.cs#L54](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Close.cs#L54) |

```csharp
public sealed class MainMenuForm : UGUI
{
    protected override void OnInit(object userData)
    {
        // Bind data, refresh lists, subscribe to events
    }

    protected override void OnShow()
    {
        // Logic executed on every Show (can be distinguished from OnInit)
    }

    protected override void OnHide()
    {
        // Pause animations, stop coroutines, save temporary state
    }

    protected override void OnRecycle()
    {
        // Fully release: clean up events, release objects
    }
}
```

### 4. Call Show/Hide to Trigger Animations

`UGUI.Show` and `UGUI.Hide` internally pass `EnableShowAnimation` / `EnableHideAnimation` to the registered `IUIFormShowHandler` / `IUIFormHideHandler`:

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(Handle, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}

public override void Hide(IUIFormHideHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(Handle, EnableHideAnimation, HideAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

Source: [UGUI.cs#L56-L88](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUI.cs#L56-L88)

As long as the implementations of `IUIFormShowHandler` / `IUIFormHideHandler` read these parameters to play animations, they will be wired up to the `Enable` / `AnimationName` declared in the form script.

## Common Variants

- **Disable global animations**: Skip the attributes and directly turn off `UIComponent.IsEnableUIShowAnimation` / `IsEnableUIHideAnimation`; all forms without attributes will skip animations, which is ideal for faster iteration during debugging.
- **Disable animations for a single form**: Set `Enable = false` in the attribute to override the global switch.
- **Synchronous show**: When no `IUIFormShowHandler` is registered, `Show` immediately invokes the `complete` callback, which is equivalent to showing the form directly without animation.

## Common Errors

- **Attribute not taking effect**: The attribute must be applied to a concrete type inheriting from `UGUI`, and `UGUIFormHelper.CreateUIForm` must be able to read that type; at runtime it is read via `GetCustomAttribute`, which only reflects the class declaration and does not read scripts outside the inheritance chain.
- **`OnShow` not running**: This means you overrode old hooks such as `OnShowBeforeAction`, which are commented-out placeholders (see the comment block at [UGUI.cs#L141-L161](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUI.cs#L141-L161)); you should use the `OnShow` / `OnHide` virtual methods instead.
- **Animation not playing but the form opens**: Check whether `IUIFormShowHandler` is registered when the UI framework starts; when `handler` is null, `Show` directly invokes `complete`, skipping the animation branch.

## Background (Optional)

After instantiating a form, `UGUIFormHelper.CreateUIForm` writes the animation flags according to the priority "attribute → global switch"; `UGGUI.Show` / `Hide` then pass these flags through to the handler, and the actual animation playback happens inside the handler (usually provided out of the box by the upper-level UI framework). The lifecycle method `OnAwake` is triggered only once on first creation, `OnInit` / `OnShow` are triggered on each open, and `OnRecycle` is triggered on destruction and recycling — just implement them as needed.
