# 自訂訊息序列化與壓縮

透過實作 `IMessageSerializer` 並以 `MessageSerializerRegistry.RegisterGlobal()` 註冊，您可以使用自己的解決方案（Protobuf、JSON、MemoryPack 等）取代網路層的訊息編碼／解碼；壓縮與解壓縮則是透過實作 `IMessageCompressHandler` / `IMessageDecompressHandler` 介面來替換。當未註冊任何序列化器時，框架會拋出明確的例外。

## 前置條件

- 已安裝 `com.gameframex.unity.network` 套件並完成網路元件設定。
- 自訂訊息類型必須繼承自 `MessageObject`（由序列化方法上的泛型條件約束所要求）。

## 核心介面總覽

| 名稱 | 實際簽章 | 說明 |
|------|----------|------|
| `IMessageSerializer.Serialize<T>` | `byte[] Serialize<T>(T message) where T : MessageObject` | 序列化訊息物件 |
| `IMessageSerializer.Deserialize` | `object Deserialize(byte[] data, Type targetType)` | 反序列化為目標訊息類型 |
| `IMessageCompressHandler.Handler` | `byte[] Handler(byte[] message)` | 壓縮訊息資料 |
| `MessageSerializerRegistry.RegisterGlobal` | `void RegisterGlobal(IMessageSerializer serializer)` | 註冊全域序列化器 |
| `MessageSerializerRegistry.Global` | `IMessageSerializer Global { get; }` | 取得全域序列化器；未註冊任何序列化器時回傳備援實作 |
| `MessageSerializerRegistry.Reset` | `void Reset()` | 重設為預設的備援實作 |

壓縮介面的完整定義如下；解壓縮介面 `IMessageDecompressHandler` 則是與其對應的存在：

```csharp
namespace GameFrameX.Network.Runtime
{
    /// <summary>
    /// 訊息壓縮器介面定義，用於壓縮訊息資料
    /// </summary>
    public interface IMessageCompressHandler
    {
        /// <summary>
        /// 壓縮處理
        /// </summary>
        /// <param name="message">未壓縮的訊息內容</param>
        /// <returns></returns>
        byte[] Handler(byte[] message);
    }
}
```

2. **註冊為全域序列化器**：在遊戲初始化階段（建立網路通道之前），呼叫登錄器並傳入您的實作實例：

```csharp
public static void RegisterGlobal(IMessageSerializer serializer)
{
    if (serializer == null)
    {
        throw new ArgumentNullException(nameof(serializer));
    }
    _global = serializer;
}
```

來源：[MessageSerializerRegistry.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/MessageSerializerRegistry.cs#L35-L42)

換句話說，業務端只需一行程式碼 —— `MessageSerializerRegistry.RegisterGlobal(new MyProtobufSerializer());` —— 即可完成整合。

3. **實作壓縮與解壓縮處理器**：分別實作 `IMessageCompressHandler` 與 `IMessageDecompressHandler`，在 `Handler(byte[] message)` 中回傳壓縮／解壓縮後的位元組陣列。框架隨附預設實作 `DefaultMessageCompressHandler` 與 `DefaultMessageDecompressHandler`（位於 `Runtime/Network/Helper/`），可作為自訂時的參考。在本次原始碼驗證範圍內，未找到壓縮器的獨立註冊進入點；請參考上述預設實作的呼叫位置，以確認替換方式。

4. **驗證**：傳送一個自訂訊息，並在對端列印接收到的欄位，以確認序列化與壓縮管線正常運作。

## 常見錯誤

| 症狀／錯誤訊息 | 原因 | 修正方式 |
|------|------|------|
| `InvalidOperationException: No IMessageSerializer registered. Call MessageSerializerRegistry.RegisterGlobal() or provide a channel-level serializer.` | 尚未註冊任何序列化器；全域會備援至 `DefaultMessageSerializer`，其方法一律拋出此例外 | 在初始化期間呼叫 `MessageSerializerRegistry.RegisterGlobal(...)`，或為該通道提供通道層級的序列化器 |
| `ArgumentNullException`（參數名稱為 `serializer`） | 向 `RegisterGlobal` 傳入了 `null` | 傳入非 null 的實作實例 |
| 註冊後仍執行舊邏輯 | 註冊發生在第一次訊息收發之後 | 將註冊動作移至建立網路通道之前；必要時先呼叫 `MessageSerializerRegistry.Reset()` 再重新註冊 |

## 背景

`MessageSerializerRegistry` 內部以 `volatile` 欄位保存全域實例；當未註冊任何序列化器時，`Global` 屬性會回傳 `DefaultMessageSerializer.Instance` 作為備援。這個備援實作的方法主體只有一個 throw 陳述式，是特意設計用來提示使用者註冊真正的序列化器——因此「忘記註冊」會在第一次訊息收發時以明確的錯誤呈現，而非無聲地失敗。
