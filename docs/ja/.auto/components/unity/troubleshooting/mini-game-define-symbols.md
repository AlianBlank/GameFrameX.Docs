# 小ゲームプラットフォームマクロ定義エラーが発生した場合の対処法

`ApplicationHelper.IsWebGLWeChatMiniGame`（またはその他の `IsWebGLXxxMiniGame` 系のプロパティ）を呼び出した際、現在実際に小游戏プラットフォームで動作しているかどうかに関わらず、常に `false` が返される場合、対応するマクロ定義が正しく有効化されていないことを意味します。本稿では、一般的なエラーの症状、根本原因、修正手順について説明します。

## 迅速な診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 実機環境で `IsWebGLWeChatMiniGame` などのプロパティが常に `false` になる | **Project Settings → Player → Other Settings → Scripting Define Symbols** に対応する `ENABLE_*_MINI_GAME` マクロが追加されていない | プラットフォームマクロ名一覧表に従い、対応するマクロを Scripting Define Symbols に追加する |
| マクロを追加したにもかかわらず、WebGL プラットフォームでプロパティが `false` のまま | WebGL プラットフォームに切り替えていない。`UNITY_WEBGL` 下でのみマクロが有効になる | File → Build Settings → Switch Platform → WebGL |
| コンパイルエラー：`The type or namespace name 'EnableWebglMiniGame' could not be found` | `#define ENABLE_WEBGL_MINI_GAME` を直接記述しているが、マクロは Scripting Define Symbols で設定する必要がある | Project Settings 経由で設定し、ソースコード内で `#define` を記述しない |
| コンパイル警告やコードの誤った削除（IL2CPP / AOT） | `#if` でマクロを直接判定しているが、`[UnityEngine.Scripting.Preserve]` の設定を忘れている | 呼び出し側が保持されているか確認し、`ApplicationHelper.MiniGame.cs` のプロパティ記述方法を参考にする |
| プラットフォーム切り替え後にマクロが反映されない | Unity がスクリプトの再コンパイルを必要とし、IDE のキャッシュが更新されていない | IDE を閉じて再起動する / `Assets → Reimport All` |

## 修正手順

### 1. Scripting Define Symbols の設定を開く

`Edit → Project Settings → Player → Other Settings → Scripting Define Symbols` を開きます。対象プラットフォームを選択後、テキストボックスに必要なマクロを追加してください。複数のマクロはセミコロン（;）で区切ります：

```text
ENABLE_WEBGL_MINI_GAME;ENABLE_WECHAT_MINI_GAME
```

参考：[ApplicationHelper.MiniGame.cs#L17-L23](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L17-L23) で使用されているマクロ `ENABLE_WEBGL_MINI_GAME`。

### 2. WebGL プラットフォームへの切り替えを確認する

すべての `IsWebGL*MiniGame` プロパティの判定は `#if UNITY_WEBGL && ENABLE_<PLATFORM>_MINI_GAME` となっており、現在の Active Build Target が WebGL でない場合、プリプロセッサの分岐が直接 `false` を返します。

`File → Build Settings` を開き、左側のプラットフォーム一覧から **WebGL** を選択し、**Switch Platform** をクリックしてください。完了後、Unity がフル再コンパイルを実行します。

### 3. プラットフォームごとに正しいマクロ名を選択する

フレームワークがサポートしているすべての小游戏マクロ名は以下の通りです（すべて `UNITY_WEBGL` と併用する必要があります）：

| プラットフォーム | マクロ名 | 対応するプロパティ |
|------|--------|----------|
| WebGL 小游戏（汎用） | `ENABLE_WEBGL_MINI_GAME` | `IsWebGLMiniGame` |
| WeChat 小游戏 | `ENABLE_WECHAT_MINI_GAME` | `IsWebGLWeChatMiniGame` |
| Alipay 小游戏 | `ENABLE_ALIPAY_MINI_GAME` | `IsWebGLAlipayMiniGame` |
| Douyin 小游戏 | `ENABLE_DOUYIN_MINI_GAME` | `IsWebGLDouYinMiniGame` |
| Kuaishou 小游戏 | `ENABLE_KUAISHOU_MINI_GAME` | `IsWebGLKuaiShouMiniGame` |
| Baidu 小游戏 | `ENABLE_BAIDU_MINI_GAME` | `IsWebGLBaiduMiniGame` |
| JD 小游戏 | `ENABLE_JINGDONG_MINI_GAME` | `IsWebGLJingDongMiniGame` |
| Taobao 小程序 | `ENABLE_TAOBAO_MINI_GAME` | `IsWebGLTaobaoMiniGame` |
| Meituan 小游戏 | `ENABLE_MEITUAN_MINI_GAME` | `IsWebGLMeituanMiniGame` |
| Bilibili 小游戏 | `ENABLE_BILIBILI_MINI_GAME` | `IsWebGLBilibiliMiniGame` |
| Discord 小游戏 | `ENABLE_DISCORD_MINI_GAME` | `IsWebGLDiscordMiniGame` |
| YouTube 小游戏 | `ENABLE_YOUTUBE_MINI_GAME` | `IsWebGLYouTubeMiniGame` |
| Facebook 小游戏 | `ENABLE_FACEBOOK_MINI_GAME` | `IsWebGLFacebookMiniGame` |
| Google Play 小游戏 | `ENABLE_GOOGLE_PLAY_MINI_GAME` | `IsWebGLGooglePlayMiniGame` |

参考：[ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs) 内の各プロパティにおける `#if UNITY_WEBGL && ENABLE_*_MINI_GAME` の定義。

### 4. コード内で対応するプロパティを呼び出す

独自に `#if` を入れ子にしてマクロを判定しないでください。判定漏れが発生しやすくなります。`ApplicationHelper` のプロパティを直接呼び出してください：

```csharp
using GameFrameX.Runtime;

if (ApplicationHelper.IsWebGLWeChatMiniGame)
{
    // WeChat 小游戏専用のロジック
}
else if (ApplicationHelper.IsWebGLDouYinMiniGame)
{
    // Douyin 小游戏専用のロジック
}
```

ソースコード例（WeChat 小游戏ブランチ）：

```csharp
[UnityEngine.Scripting.Preserve]
public static bool IsWebGLWeChatMiniGame
{
    get
    {
#if UNITY_WEBGL && ENABLE_WECHAT_MINI_GAME
        return true;
#else
        return false;
#endif
    }
}
```

参考：[ApplicationHelper.MiniGame.cs#L33-L43](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L33-L43)

## 検証

1. `Awake()` またはデバッグボタンに `Debug.Log($"WeChat={ApplicationHelper.IsWebGLWeChatMiniGame}")` を追加し、実行後に Console を確認します。
2. WebGL と WebGL 以外のプラットフォームでそれぞれ Log を出力します。WebGL 以外ではすべて `false` になることが期待されます。WebGL では現在設定されているマクロのプラットフォームのみ `true` になります。
3. それでも `false` のままの場合は、診断表に戻って一つずつ確認してください：プラットフォームが WebGL であるか、マクロ名のスペルが正しいか、再コンパイルが発生したか。

## 背景

フレームワークは、各小游戏プラットフォームに対して、`UNITY_WEBGL` と各プラットフォームマクロの組み合わせによってコンパイル時に `true`/`false` を決定する静的プロパティ（すべて `GameFrameX.Runtime.ApplicationHelper` に統一）を公開しており、これにより IL2CPP / AOT によるコード削除時にも正しく機能します。プロパティの実装ファイルについては [ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs) を参照してください。
