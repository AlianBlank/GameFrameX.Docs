# 非同步可釋放字典的使用方式

`AsyncDisposableDictionary<TKey, TValue>` 是一個要求值實作 `IAsyncDisposable` 的字典容器，並繼承自 `NullableDictionary<TKey, TValue>`。當字典本身透過 `DisposeAsync()` 釋放時，會自動以非同步方式釋放所有非 null 值。適合用於管理資料庫連線、網路工作階段、長時間連線的用戶端等需要非同步清理的資源集合。

## 前置條件

- `TValue` 必須實作 `IAsyncDisposable`。
- 請參考命名空間 `GameFrameX.Foundation.Extensions`。
- 目標 .NET 版本必須支援 `IAsyncDisposable`(.NET Standard 2.1+ / .NET 5+)。

## 操作步驟

1. **建立字典實例並寫入值**

   使用集合初始設定式或索引子，直接寫入資源物件：

   ```csharp
   using GameFrameX.Foundation.Extensions;

   var dictionary = new AsyncDisposableDictionary<string, MyAsyncResource>
   {
       ["conn-1"] = new MyAsyncResource(),
       ["conn-2"] = new MyAsyncResource()
   };
   ```

   來源： [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L6-L37)

2. **(選用)設定釋放錯誤處理常式**

   當某個值的 `DisposeAsync()` 擲回例外時，字典會呼叫 `DisposalErrorHandler`。記錄或備援處理的方式由呼叫端決定：

   ```csharp
   dictionary.DisposalErrorHandler = (value, ex) =>
   {
       Console.WriteLine($"释放 {value} 失败: {ex.Message}");
   };
   ```

   處理常式本身擲回的例外會被吸收，並保證其餘值的釋放會繼續進行。  
   來源： [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L92-L102)

3. **呼叫 `DisposeAsync()` 以非同步方式釋放所有值**

   ```csharp
   await dictionary.DisposeAsync();
   ```

   釋放處理具有冪等性。即使重複呼叫 `DisposeAsync()`,值也不會被重複釋放。可以使用 `dictionary.IsDisposed` 確認狀態。  
   來源： [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L71-L90)

4. **釋放後請勿進行寫入或修改**

   釋放後若呼叫索引子的 `set`、`Add`、`Remove`,將會擲回 `ObjectDisposedException`。讀取(get)繼承自基底類別的字典，因此仍可繼續使用。

## 常見變化情境

- **並行情境**：在多執行緒環境中需要並行讀寫時，請使用執行緒安全版本的 `AsyncDisposableConcurrentDictionary<TKey, TValue>`。使用方式與本頁相同。
- **空字典的釋放**：即使字典中沒有值，直接呼叫 `await dictionary.DisposeAsync()` 也是安全的，會直接返回。
- **部分值釋放失敗**：即使某個值釋放失敗，其他值的釋放也不會中斷，所有 `IAsyncDisposable` 都會逐一嘗試釋放。

## 常見錯誤

| 現象 | 原因 | 修正 |
|------|------|------|
| `ObjectDisposedException` | 在 `DisposeAsync()` 之後呼叫了 `Add`、`Remove` 或索引子的 `set` | 釋放後請停止寫入，僅允許唯讀存取 |
| 值未被釋放 | 儲存了 `null` 值 | `DisposeAsync` 會跳過 `null`。請確認已寫入實際的資源實例 |
| 釋放遭到中斷，後續資源未被釋放 | 舊有程式碼手動擲回未處理的例外 | 一律透過 `DisposalErrorHandler` 進行備援處理，並依賴字典內部的 try/catch 繼續迭代 |
| 型別編譯錯誤 | `TValue` 未實作 `IAsyncDisposable` | 請確認資源型別已實作 `IAsyncDisposable`(例如： `DbConnection`、`HttpClient` 的自訂包裝器)|

## 驗證

- 呼叫 `await dictionary.DisposeAsync()` 之後，`dictionary.IsDisposed` 會變為 `true`。
- 所有非 null 值的 `DisposeAsync()` 只會被呼叫一次(已在測試案例中驗證)。  
  來源： [AsyncDisposableDictionaryTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Tests/Extensions/AsyncDisposableDictionaryTests.cs#L28-L45)
- 釋放後再次呼叫 `DisposeAsync()` 也不會擲回例外，值更不會被重複釋放。

## 背景(選用)

`AsyncDisposableDictionary` 會在將 `_isDisposed` 設為 `true` 後迭代 `Values`,因此即使在迭代過程中某個 `DisposeAsync` 遭到封鎖或擲回錯誤，也能保證後續的值會繼續被釋放。錯誤處理會透過回呼委派公開給呼叫端，因此框架不會強制依賴日誌系統。
