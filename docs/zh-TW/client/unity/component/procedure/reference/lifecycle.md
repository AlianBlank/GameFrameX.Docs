# 生命週期回呼

`ProcedureBase` 繼承自 `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`。按照有限狀態機（FSM）的慣例，每個流程在建立、進入、輪詢、離開與銷毀階段都會觸發一個虛擬方法。這些就是流程的**生命週期回呼**。子類可以覆寫它們來掛入業務邏輯。

## 回呼快速參考

| 回呼 | 簽章 | 觸發時機 |
|------|------|----------|
| `OnInit` | `protected override void OnInit(IFsm<IProcedureManager> procedureOwner)` | 當狀態機初始化時（每個流程實例一次） |
| `OnEnter` | `protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)` | 當切換到該流程時 |
| `OnUpdate` | `protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 每幀輪詢（邏輯經過時間／實際經過時間） |
| `OnFixedUpdate` | `protected override void OnFixedUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)` | 以固定步長輪詢 |
| `OnLeave` | `protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)` | 當離開該流程時；`isShutdown=true` 表示該次離開是由狀態機關閉所觸發 |
| `OnDestroy` | `protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)` | 當狀態機被銷毀時（每個流程實例一次） |

所有方法的預設實作都只是 `base.Xxx(...)`，可以覆寫，但**應保留 `base` 呼叫**以維持基類行為。

來源：[ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

## 參數說明

| 參數 | 說明 |
|------|------|
| `procedureOwner` | 持有該流程的狀態機物件，型別為 `IFsm<IProcedureManager>`。透過它可以存取流程管理器（`procedureOwner.Owner`）、切換流程等。 |
| `elapseSeconds` | 受時間縮放影響的邏輯經過時間（秒）。 |
| `realElapseSeconds` | 不受時間縮放影響的實際經過時間（秒）。 |
| `isShutdown` | 在 `OnLeave` 中為 `true` 時，表示此次離開是由狀態機關閉所導致，而非正常的流程切換。 |

## 觸發時機（對應管理器 API）

| 管理器操作 | 觸發的回呼（於該流程實例上） |
|------------|----------------------------|
| `Initialize(fsmManager, procedures...)` | 每個傳入的流程會依序呼叫 `OnInit` |
| `StartProcedure<T>()` / `StartProcedure(Type)` | 目標流程呼叫 `OnEnter`；若目前存在流程，則舊流程會先呼叫 `OnLeave(isShutdown=false)` |
| 狀態機心跳（每幀） | 目前流程呼叫 `OnUpdate` 與 `OnFixedUpdate` |
| `DestroyProcedures()` | 目前流程呼叫 `OnLeave(isShutdown=true)`，接著所有已註冊的流程依序呼叫 `OnDestroy` |
| `ReinitializeProcedures(procedures...)` | 等同於先呼叫 `DestroyProcedures()`，再以新的流程陣列重新 `Initialize` |

來源：[IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L39-L119)

## 最小使用範例

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

public class MyProcedure : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // 初始化該流程所需的資源、快取等
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 進入該流程時開啟 UI、註冊事件等
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner,
        float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        // 每幀的業務邏輯（條件滿足時透過 procedureOwner 切換流程）
    }

    protected override void OnLeave(IFsm<IProcedureManager> procedureOwner, bool isShutdown)
    {
        base.OnLeave(procedureOwner, isShutdown);
        // 清理 UI、取消註冊事件
        // isShutdown == true 表示狀態機正在整體關閉
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // 釋放該流程持有的資源
    }
}
```

來源：[ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L38-L98)

## 常見錯誤

| 現象 | 原因 | 修復方式 |
|------|------|------|
| 覆寫後忘記呼叫 `base.OnXxx(...)`，導致狀態機內部狀態異常 | 基類可能維護著狀態統計、計時器等隱式行為 | 覆寫時務必在最後呼叫 `base.OnXxx(...)` |
| 在 `OnInit` 中呼叫 `StartProcedure` 切換流程 | `Initialize` 階段流程尚未呼叫 `OnEnter`；過早切換會使狀態機處於不一致狀態 | 改為在 `OnEnter` 或後續的 `OnUpdate` 中切換 |
| 在 `OnDestroy` 中透過 `procedureOwner` 存取其他流程 | 銷毀階段狀態機內部狀態正被回收 | 在 `OnEnter` 中快取跨流程引用，並在 `OnLeave` 中清理 |
| 使用 `OnUpdate` 進行一次性初始化 | `OnUpdate` 每幀都會被呼叫，會重複觸發 | 將一次性邏輯放在 `OnInit` 或 `OnEnter` 中 |
| 期望每次 `Initialize` 都會呼叫 `OnEnter` | 初始化期間只會呼叫 `OnInit`；`OnEnter` 僅在狀態切換時呼叫 | 將啟動邏輯放在 `OnEnter`，資料準備放在 `OnInit` |
