# 모든 설정 항목 열거

`SettingManager`가 제공하는 메서드를 통해 현재 로드된 모든 설정 항목 이름을 한 번에 가져와서, 설정 디버깅, 내보내기, 일괄 검증 또는 일괄 삭제 전 미리보기에 사용합니다.

## 사전 조건

- `SettingComponent.SetSettingHelper`를 통해 구현체(예: `DefaultSettingHelper` 또는 `PlayerPrefsSettingHelper`)를 주입하고, 성공적으로 `Load()`를 호출하여 설정을 로드한 상태여야 합니다.
- `SettingManager` 인스턴스를 획득할 수 있어야 하며, 일반적인 방법은 `GameEntry` / `SettingComponent.SetSettingManager` 속성에서 읽어오는 것입니다.

## 작업 단계

1. `SettingManager` 인스턴스를 가져옵니다. 일반적인 진입점은 `GameEntry.GetComponent<SettingComponent>().SettingManager`이며, 또는 `SettingComponent`에서 노출하는 `GetSettingManager` 파생 메서드를 직접 사용할 수도 있습니다.

2. `GetAllSettingNames()`를 호출하여 설정 항목 이름 배열을 직접 가져옵니다.

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingManager = GameEntry.GetComponent<SettingComponent>().SettingManager;
   string[] names = settingManager.GetAllSettingNames();

   foreach (var name in names)
   {
       UnityEngine.Debug.Log(name);
   }
   ```

   Source: [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L140-L260),[ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs#L85-L95)

3. 기존 리스트를 재사용하려면(GC 방지) `List<string>` 매개변수를 가진 오버로드를 사용합니다:

   ```csharp
   var results = new System.Collections.Generic.List<string>(settingManager.Count);
   settingManager.GetAllSettingNames(results);
   ```

   Source: [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L81-L92)

4. `HasSetting`과 `RemoveSetting`을 결합하면 일괄 검증 또는 정리가 가능합니다:

   ```csharp
   foreach (var name in settingManager.GetAllSettingNames())
   {
       if (name.StartsWith("tmp_") && settingManager.HasSetting(name))
       {
           settingManager.RemoveSetting(name);
       }
   }
   settingManager.Save();
   ```

   Source: [ISettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingManager.cs)

## 일반적인 변형

- **`List<string>` 오버로드 사용**: 루프에서 열거를 반복적으로 호출하거나 다른 문자열 컬렉션과 결합할 때, 리스트를 받는 오버로드를 사용하면 반복 할당을 피할 수 있습니다.
- **접두사로 필터링**: LINQ 또는 `StartsWith`와 함께 화이트리스트/블랙리스트 필터링을 수행합니다. 예를 들어 `ui_*`로 시작하는 키만 내보낼 수 있습니다.
- **런타임 열거자 지원**: `DefaultSetting`과 `PlayerPrefsSettingHelper` 자체도 `GetAllSettingNames()` 구현을 제공합니다. 관리자를 우회하고 기본 설정 인스턴스를 직접 읽는 경우, 인터페이스 시그니처는 동일합니다.

## 일반적인 오류

| 현상 | 원인 | 해결 |
|------|------|------|
| 호출 시 `Setting helper is invalid.` 예외 발생 | `SetSettingHelper`를 호출하지 않았거나 관리자가 아직 초기화되지 않음 | 시작 시 `DefaultSettingHelper`/`PlayerPrefsSettingHelper` 주입 |
| 호출 시 `Setting name is invalid.` 예외 발생 | 빈 문자열 또는 `null`을 전달함 | 열거에서 반환된 항목에 대해서만 다시 접근하고, 빈 이름을 수동으로 작성하지 않음 |
| 가져온 배열이 비어 있음 | `Load()`를 호출하지 않았거나 로드 실패 | 먼저 `Load()`를 호출하고 반환값을 확인한 후 열거 |
| 수정 후 적용되지 않음 | `Save()`를 호출하지 않음 | 제거/쓰기 후 `settingManager.Save()` 호출 |

## 배경 (선택 사항)

`GetAllSettingNames`는 인터페이스 계층에서 `string[]`과 `List<string>` 두 가지 오버로드로 정의되며, 구체적인 저장은 `ISettingHelper` 구현체에 의해 결정됩니다(`DefaultSettingHelper`는 `DefaultSetting` 메모리 사전을 사용하고, `PlayerPrefsSettingHelper`는 PlayerPrefs를 사용). 관리자는 주입된 helper로 호출을 전달하기만 하므로, 열거 범위는 `Load()` 시 로드된 데이터와 완전히 일치합니다.
