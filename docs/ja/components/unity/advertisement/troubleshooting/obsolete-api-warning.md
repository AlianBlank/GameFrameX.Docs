# 旧 API のコンパイル警告の対処方法

コード内で `[Obsolete]` 属性付きのインターフェースを呼び出すと、Unity のコンパイラがコンソールに `CS0618` 警告を出力し、代替 API を提示します。このページでは、これらの呼び出しをすばやく特定し、新しい API に切り替える方法を説明します。

## クイック診断

| 警告原文 | トリガーされる旧 API | 推奨される代替 API |
|---|---|---|
| `Use Initialize(AdvertisementConfig) instead.` | `AdvertisementComponent.Initialize(string adUnitId, bool isDebug)`、`IAdvertisementManager.Initialize(...)`、`BaseAdvertisementManager.Initialize(...)` | `Initialize(AdvertisementConfig config)` |
| `Use Play(AdvertisementPlayOption) instead.` | `AdvertisementComponent.Show(Action<string>, Action<string>, Action<bool>)`、`AdvertisementComponent.Play(Action<bool>, string)` および `IAdvertisementManager` / `BaseAdvertisementManager` 内の対応する複数の `Play` オーバーロード | `Play(AdvertisementPlayOption option)` |

`[Obsolete]` 属性の実際の位置については、[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L150-L191)、[IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L62-L122)、[BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L144-L236) を参照してください。

## 修正手順

### 1. `Initialize(string, bool)` を `Initialize(AdvertisementConfig)` に置き換える

旧シグネチャは広告ユニット ID とデバッグフラグのみを受け取ります。新しいシグネチャは `AdvertisementConfig` 派生の設定オブジェクトを受け取り、より多くのパラメータを保持できます（サブクラスは具体的な広告 SDK の実装から提供されます。例えば `PangleAdvertisementConfig` など）。

```csharp
// 旧写法 —— 会触发 CS0618
[Obsolete("Use Initialize(AdvertisementConfig) instead.")]
adComponent.Initialize("ad-unit-id-xxx", isDebug: true);

// 新写法
var config = new MyAdSdkConfig // 具体子类由使用的广告 SDK 提供
{
    adUnitId = "ad-unit-id-xxx",
    isDebug = true,
};
adComponent.Initialize(config);
```

`AdvertisementConfig` 基底クラスの定義は [AdvertisementConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L41-L53) を参照してください。

### 2. `Show` / 複数パラメータの `Play` を `Play(AdvertisementPlayOption)` に置き換える

旧 `Show(success, fail, onShowResult)` および `Play(onShowResult, customData)` は分散したパラメータを使用していましたが、新しいインターフェースはすべてのコールバックと拡張データを `AdvertisementPlayOption` オブジェクトに集約します。

```csharp
// 旧写法 —— 会触发 CS0618
[Obsolete("Use Play(AdvertisementPlayOption) instead.")]
adComponent.Show(
    success: info => Debug.Log($"成功:{info}"),
    fail: err => Debug.LogError($"失败:{err}"),
    onShowResult: shown => Debug.Log($"展示:{shown}"));

// 新写法
var option = new AdvertisementPlayOption
{
    OnSuccess = info => Debug.Log($"成功:{info}"),
    OnFail = err => Debug.LogError($"失败:{err}"),
    OnShowResult = shown => Debug.Log($"展示:{shown}"),
    customData = "reward-key-001",
};
adComponent.Play(option);
```

`AdvertisementPlayOption` のフィールド定義は [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L80) を参照してください。

### 3. 一時的に旧呼び出しを保持する必要がある場合、局所的に CS0618 を抑制する

フレームワーク内部で旧呼び出しを転送する際にも、以下の方法が使用されています。

```csharp
#pragma warning disable CS0618
_advertisementManager.Initialize(AdUnitId, isDebug);
#pragma warning restore CS0618
```

移行期間中、すぐには置き換えられない少数の外部依存ポイントに対してのみ `#pragma warning disable CS0618` を使用し、新しいバージョンで速やかに削除してください。

## 検証

1. Unity でコンソールを `Clear` し、広告の初期化と再生を 1 回トリガーします。
2. コンソールに `CS0618` に関する `Use Initialize(AdvertisementConfig) instead.` または `Use Play(AdvertisementPlayOption) instead.` の警告が表示されないことを確認します。
3. 「初期化 → 再生 → コールバック」の完全なフローを実行し、`OnSuccess` / `OnFail` / `OnShowResult` がすべて正常にトリガーされることを確認します。
