# 安裝與首次執行

GameFrameX Xcode 設定是一個 Unity Package，安裝後無需撰寫任何 C# 程式碼，只需在專案裡放置一個 `XCodeConfig.json`，iOS 建置結束時會自動完成 Info.plist、簽署、Capabilities、CocoaPods 等 Xcode 專案修改。本頁帶你從安裝套件到第一次跑通完整流程。

## 快速開始

### 1. 安裝套件

任選以下一種方式（建議使用 scopedRegistries，便於統一管理版本）：

**方式一：Scoped Registry（可指定版本）** — 編輯 `Packages/manifest.json`：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.xcode": "1.11.1"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L47-L63)

`scopes` 控制哪些套件會透過此註冊表解析：只有以 `com.gameframex` 開頭的套件才會從這個註冊表取得。

**方式二：Git URL** — 在 `manifest.json` 的 `dependencies` 節點下新增：

```json
{
   "com.gameframex.unity.xcode": "https://github.com/gameframex/com.gameframex.unity.xcode.git"
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L67-L72)

**方式三：Package Manager** — 在 Unity 的 `Package Manager` 中使用 `Git URL` 方式新增，位址同上。

**方式四：直接下載儲存庫** 放置到 Unity 專案的 `Packages` 目錄下，會自動載入識別。

環境需求：Unity 2019.4 及以上。

### 2. 建立設定檔

設定檔**必須命名為 `XCodeConfig.json`**，可放在專案任意位置；支援多個檔案並存，建置時自動深度合併（適合多模組協作）。若需按渠道區分，可再建立 `XCodeConfig.{渠道名}.json`，渠道設定最後合併、優先順序最高。

頂層結構如下：

```json
{
  "swiftBridging": true,
  "signing": {},
  "plist": {},
  "environmentVariables": {},
  "launcherArgs": [],
  "podSource": [],
  "podfile": "",
  "podInstall": true,
  "localizations": [],
  "capabilities": {},
  "unityFramework": {},
  "unityMain": {}
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L79-L96)

最小可用範例（關閉 Bitcode + 寫一條 plist + 新增一個系統框架）：

```json
{
  "plist": { "NSCameraUsageDescription": "用于拍摄头像" },
  "unityMain": {
    "properties": { "=": { "ENABLE_BITCODE": "NO" } },
    "frameworks": { "+": [ "WebKit.framework" ], "-": [] }
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L145-L173)

常用頂層欄位速覽：

| 欄位 | 型別 | 說明 |
| :--- | :--- | :--- |
| `swiftBridging` | bool | 自動產生 Swift 橋接標頭檔（預設 `true`） |
| `signing` | object | 程式碼簽署設定（Team ID、Bundle Identifier 等） |
| `plist` | object | Info.plist 鍵值對，值支援任意型別 |
| `capabilities` | object | iOS 應用程式能力（內購、推播、iCloud 等） |
| `podfile` / `podInstall` | string / bool | 自訂 Podfile 路徑 / 是否自動執行 `pod install`（預設 `true`） |
| `unityMain` / `unityFramework` | object | 分別對應 Unity-iPhone 與 UnityFramework target 設定 |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L98-L111)

### 3. 建置 iOS 並驗證

1. 在 Unity 中將平台切換到 iOS，執行建置（File → Build Settings → Build）。
2. 建置結束後，工具會自動在 [PostProcessBuild(888)] 回呼中執行——晚於大多數其他後處理腳本，且僅在 `BuildTarget.iOS` 下生效：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        //讀取設定檔
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 如果沒有找到任何符合的檔案，直接傳回
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L32)

3. 檢查 Unity Console 日誌。看到下面這些輸出即表示安裝成功、流程已跑通：
   - `[MergeConfig] 正在合并配置: <你的 XCodeConfig.json 路径>`
   - `[PBXProject] 正在应用最终合并配置...`
   - `[OtherSettings] 正在应用最终合并配置...`
4. 開啟產生的 Xcode 專案確認效果：Info.plist 中出現你設定的鍵、Build Settings 中 `ENABLE_BITCODE` 已變為 `NO` 等。

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L38-L107)

如果日誌出現 `未找到任何 XCodeConfig 相关配置文件, 跳过设置`，表示檔案名稱不是 `XCodeConfig.json`（區分大小寫）或不在專案目錄內，改名/移動後重新建置即可。

## 常見變體

- **多模組多設定**：不同模組各自放一份 `XCodeConfig.json`，建置時按檔案順序深度合併；同鍵以「後合併者覆寫」。
- **渠道差異化**：透過 `SettingLoader.GetChannel()` 偵測渠道，讀取 `XCodeConfig.{channel}.json` 並最後合併覆寫。相關邏輯請見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)。
- **略過 pod install**：設定 `"podInstall": false` 可略過自動執行 `pod install`；有自訂 Podfile 時透過 `"podfile": "<路徑>"` 指定（優先順序高於 `pods` 欄位）。見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156)。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| Console 報 `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 檔案名稱不是 `XCodeConfig.json`，或不在專案目錄內 | 嚴格按 `XCodeConfig.json` 命名（區分大小寫）後重新建置 |
| Console 報 `<路径> 解析失败, 跳过合并` | JSON 語法錯誤 | 用 JSON 驗證工具檢查後修正並重新建置 |
| Console 報 `合并后的配置为空，跳过设置` | 檔案存在但內容為空物件 | 至少寫入一個有效欄位 |
| 建置後 Xcode 專案無變化 | 建置目標不是 iOS，或回呼拋出例外被吞掉 | 確認 BuildTarget 為 iOS；檢查 Console 是否有 `Debug.LogException` 輸出的例外堆疊 |

以上錯誤訊息均來自 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83) 的真實日誌原文。

## 驗證

1. Console 出現 `[MergeConfig]` → `[PBXProject]` → `[OtherSettings]` 三段日誌，無紅色 Error。
2. 用 Xcode 開啟建置輸出目錄，確認：Info.plist 已寫入 `plist` 設定項；Build Settings 符合 `properties` 設定；若已設定 `podfile`/`pods`，專案目錄下 Podfile 已產生且相依套件已安裝。

## 背景

工具分兩階段寫入：第一階段把建置屬性、框架、程式庫、檔案複製、編譯旗標等套用到 `Unity-iPhone` 與 `UnityFramework` 兩個 target 並儲存 `project.pbxproj`；第二階段處理 Plist、環境變數、啟動參數、Capabilities、本地化與 CocoaPods，並在 Capabilities 獨立寫入磁碟後重新讀取專案檔案以保留其修改。Swift 橋接預設開啟，只在主專案上設定簽署與 Capabilities。完整實作請見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)。
