# 实现玩家邮件(Mail)模块

通过本页面,你能在 GameFrameX.Server 中启用并扩展玩家邮件子系统:它由 `MailComponent` 承载玩家邮箱(`MailBoxState`)、以 Campaign 形式批量发送、并支持领取附件、撤回作废、过期清理等完整生命周期。

## 前置条件

- 已基于 GameFrameX.Server 模板创建工程,玩家 Actor 能正常登录并落库。
- 已熟悉 [Component / StateComponent 的基本用法](https://github.com/GameFrameX/GameFrameX.Server/blob/main/src/Example.cs),以及 Admin 后台 HTTP Handler 的注册方式。
- 邮件奖励道具需已在物品/奖励模块中实现,`MailAttachmentInstance.ItemId` 引用对应物品表。

## 操作步骤

1. **挂载玩家邮件组件**。组件以玩家 Actor 为粒度,直接继承 `StateComponent<MailBoxState>`,通过 `[ComponentType(GlobalConst.ActorTypePlayer)]` 自动绑定。

   ```csharp
   using GameFrameX.Apps.Player.Mail.Entity;

   namespace GameFrameX.Apps.Player.Mail.Component;

   /// <summary>
   /// 玩家邮件组件,挂载玩家粒度的邮件箱 <see cref="MailBoxState"/>。
   /// </summary>
   [ComponentType(GlobalConst.ActorTypePlayer)]
   public sealed class MailComponent : StateComponent<MailBoxState>
   {
   }
   ```

   Source: [MailComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/Component/MailComponent.cs#L34-L44)

2. **选择邮件类型**。枚举编号发布后不可变,新增类型只能追加、不能复用旧值。

   ```csharp
   public enum MailType
   {
       System = 0,         // 系统邮件(如维护补偿)
       Operation = 1,      // 运营邮件(Admin 发布,按过滤条件懒创建)
       Compensation = 2,   // 补偿邮件(定向补偿,复用 Campaign 落库)
   }
   ```

   Source: [MailType.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/MailType.cs#L37-L53)

3. **理解邮件状态机**。`MailStatus` 决定一封玩家邮件实例的流转:`Unread → Read → Claimed → Deleted`,或在撤回/过期时进入 `Revoked` / `Expired` 终态。

   ```csharp
   public enum MailStatus
   {
       Unread = 0,
       Read = 1,
       PartialClaimed = 2,
       Claimed = 3,
       Deleted = 4,    // 终态
       Revoked = 5,    // 终态
       Expired = 6,    // 终态
   }
   ```

   删除仅在“无附件”或“附件全部已领”时被允许;撤回不会回滚已领附件。  
   Source: [MailEnums.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/MailEnums.cs#L43-L65)

4. **配套维度枚举**。`ReadStatus`(派生自 `ReadTime`)、`AttachmentStatus`(列表展示用,源数据为 `MailStatus` + 各附件 `ClaimStatus`)、`ClaimStatus`(单附件: `Claimable` / `Claimed` / `Discarded`)。

   ```csharp
   public enum ClaimStatus
   {
       Claimable = 0,
       Claimed = 1,      // 终态,撤回不回滚
       Discarded = 2,    // 撤回/过期作废未领附件
   }
   ```

   Source: [MailEnums.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Mail/MailEnums.cs#L100-L109)

5. **使用 Admin HTTP Handler 发布/撤回 Campaign**。仓库已提供四类管理接口,可直接挂到 Admin 后台:

   - `PreviewMailCampaignHttpHandler`:预演命中玩家数与道具估算。
   - `PublishMailCampaignHttpHandler`:正式发布,落地 `MailCampaignState`。
   - `QueryMailCampaignHttpHandler`:查询 Campaign 状态(草稿/已发布/已撤回)。
   - `RevokeMailCampaignHttpHandler`:撤回 Campaign,已发邮件按 `MailStatus.Revoked` 处理。

   实际接入时按现有 Handler 注册方式挂到 Admin 路由即可,典型位置:
   - [PreviewMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/PreviewMailCampaignHttpHandler.cs)
   - [PublishMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/PublishMailCampaignHttpHandler.cs)
   - [QueryMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/QueryMailCampaignHttpHandler.cs)
   - [RevokeMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/RevokeMailCampaignHttpHandler.cs)

6. **实现客户端读取与领取入口**。在玩家侧 `MailAttachmentClaim` 之类的请求 Handler 中完成三件事:
   - 读信:`Unread → Read`(`ReadStatus.Read`,幂等)。
   - 领取附件:逐个 `MailAttachmentInstance` 更新 `ClaimStatus` 至 `Claimed`,全部领取后整体进入 `MailStatus.Claimed`。
   - 删除:仅当 `MailStatus == Claimed` 且无未领附件时允许置 `Deleted`。

   参考已有领取测试用例确认边界: [MailAttachmentClaimTests.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix.Tests/MailAttachmentClaimTests.cs)、注册相关: [MailCampaignRegistryTests.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix.Tests/MailCampaignRegistryTests.cs)。

## 常见变体

- **系统补偿**:走 `MailType.System`,无需 Campaign,直接在游戏代码里向玩家 `MailComponent` 写入 `MailState` 即可。
- **运营全服推送**:走 `MailType.Operation` + `PublishMailCampaignHttpHandler`,按 `MailCampaignFilter` 命中懒创建到玩家邮箱。
- **定向补偿**:走 `MailType.Compensation`,复用 Campaign 落库但绕过全服过滤,直接指定目标玩家 ID。

## 常见错误

- **枚举复用**:把 `System = 0` 改号或删号,会导致线上玩家存档中的 `MailType` 含义漂移。务必只追加、不复用。
- **撤回误用**:对已领玩家附件做回滚。`Claimed` 附件在撤回时不可回退(`Discarded` 只针对未领附件)。
- **删除未领附件**:未校验 `ClaimStatus` 就将邮件置 `Deleted`,会导致玩家凭空损失道具。
- **Component 未挂载**:忘记给玩家 Actor 装配 `MailComponent`,会出现 `MailComponentAgent` 调用 null 异常。

## 背景(可选)

`MailComponent` 仅作为状态容器,真正的过滤命中、懒创建、过期清理等逻辑集中在 `MailComponentAgent` 与 `MailCampaignState`;Campaign 是“一份定义 + N 份玩家实例”的二段式落库,既便于运营审稿,也便于按 Campaign 维度做撤回。玩家侧的“状态机 + 维度派生”(`MailStatus` / `ReadStatus` / `AttachmentStatus` / `ClaimStatus`)用于在不改源数据的前提下提供列表展示与领取入口的稳定契约。
