# What to Do About the "Event manager is invalid." Fatal Error

This `Log.Fatal("Event manager is invalid.")` comes from `EventComponent.Awake()`: it is printed when `GameFrameworkEntry.GetModule<IEventManager>()` returns `null`, after which the component does an early `return`, leaving `m_EventManager` empty. Any subsequent event subscription/dispatch call will then throw a NullReferenceException. The root cause is that **the implementation type of `IEventManager` was not found and registered by the framework** (the implementation type name is misconfigured, was renamed/moved to a different namespace, or was stripped out by code stripping).

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Entering Play mode / loading the scene immediately prints `Fatal: Event manager is invalid.`, and subsequent `Subscribe`/`Fire` calls throw `NullReferenceException` | `GetModule<IEventManager>()` returns null; the implementation type was not registered | See [Fix Step 1](#1-check-the-implementation-type-configuration-on-eventcomponent) |
| Starts occurring after upgrading the package version or changing namespaces | The `componentType` string saved on `EventComponent` still points to the old type name, so `Utility.Assembly.GetType(componentType)` cannot find it | Re-select the `EventManager` implementation in the Inspector and save the scene; see [Fix Step 1](#1-check-the-implementation-type-configuration-on-eventcomponent) |
| Works fine in the editor but appears after building (IL2CPP / managed stripping) | The implementation type `EventManager` was stripped out and cannot be found via reflection | Keep the `[Preserve]` attribute and the stripping protection configuration; see [Fix Step 2](#2-confirm-the-eventmanager-implementation-type-is-not-stripped) |
| The component is on a hand-assembled prefab or was copied from another project | The serialized `componentType` value on the prefab is empty or does not belong to the current project | Remove it and re-add it via the `GameFrameX/Event` menu; see [Fix Step 3](#3-rebuild-the-gameframex-event-component) |

Where the error is thrown (actual source code):

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

## Fix Steps

### 1. Check the implementation type configuration on EventComponent

In `Awake()`, `EventComponent` uses reflection via `Utility.Assembly.GetType(componentType)` to resolve the implementation type, and then retrieves the module through `GameFrameworkEntry.GetModule<IEventManager>()`. `componentType` is a string serialized and saved in the Inspector; on the editor side, `EventComponentInspector` populates the candidate list:

```csharp
[CustomEditor(typeof(EventComponent))]
internal sealed class EventComponentInspector : ComponentTypeComponentInspector
{
    // ...
    RefreshComponentTypeNames(typeof(IEventManager));
}
```

Source: [EventComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Editor/Inspector/EventComponentInspector.cs#L36-L63)

Steps:

1. Select the GameObject that has `EventComponent` attached (by default the GameFrameX root object; the component menu is `GameFrameX/Event`).
2. In the Inspector, check the component type dropdown and confirm that `GameFrameX.Event.Runtime.EventManager` is selected (the only implementation in this package).
3. If it appears empty or red/missing (Missing), re-select `EventManager` and save the scene and the related prefabs.
4. Enter Play mode again to verify.

### 2. Confirm the EventManager implementation type is not stripped

The implementation class in this package also carries the `[UnityEngine.Scripting.Preserve]` protection:

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class EventManager : GameFrameworkModule, IEventManager
{
    private readonly EventPool<GameEventArgs> m_EventPool;

    public EventManager()
    {
        m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L38-L49)

Steps:

1. If you have enabled `Managed Stripping Level` in Player Settings or are using IL2CPP, make sure the `Preserve` attributes in the package have not been removed (do not change the assembly's stripping exemption configuration); this package also provides [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs) as an aid for stripping scenarios.
2. Confirm that the `Runtime` assembly (namespace `GameFrameX.Event.Runtime`) is actually included in the build (the asmdef platform checkboxes are enabled and it has not been manually excluded from the Build).

### 3. Rebuild the GameFrameX/Event component

If the component came from a copied prefab and its serialized data is no longer valid:

1. Remove the current `EventComponent` from the GameObject (the component is marked `[DisallowMultipleComponent]`; duplicates are not allowed on the same object).
2. Re-add it via `Add Component → GameFrameX → Event`; the component definition is:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Event")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-7000)]
public sealed class EventComponent : GameFrameworkComponent
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)

3. Confirm that the GameFrameX base runtime package containing `GameFrameworkEntry` is installed and referenced (`GetModule<T>` depends on it to complete the module registration scan).
4. Save the scene and enter Play mode again.

## Verification

- The Console no longer shows `Fatal: Event manager is invalid.` at startup.
- Accessing the event component's read-only properties from any script no longer throws a null reference, e.g. `EventCount` / `EventHandlerCount` (they forward directly to `m_EventManager` internally; see [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L50-L61)).
- Call `Check(id, handler)` or `Subscribe(id, handler)` once; it should return/register normally, and the `Count(id)` count should match expectations.
