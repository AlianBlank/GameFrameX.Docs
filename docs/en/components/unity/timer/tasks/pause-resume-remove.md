# Pausing, Resuming, and Removing Timers

For timers that have already been created, `TimerManager` provides `Pause` / `Resume` / `Remove` by ID, `PauseByTag` / `ResumeByTag` / `RemoveByTag` by tag, along with companion queries (`IsPaused`, `Exists`, `HasTag`, `GetRemaining`, etc.). All APIs are defined on the `ITimerManager` interface; simply call them on the `ITimerManager` instance you obtain.

## Prerequisites

- The project has integrated the GameFrameX Timer component and holds an `ITimerManager` instance (see [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs) for the component entry point).
- Timers have been created via `Add` / `AddOnce` / `AddUpdate`, and the returned `int` timer ID has been saved; or a `tag` was specified at creation time.

## Steps

### 1. Pausing and Resuming a Single Timer

```csharp
ITimerManager timer; // Obtained from the GameFrameX component

// interval=1 second, repeat=0 means infinite repetition
int id = timer.Add(1f, 0, obj => { /* periodic logic */ });

timer.Pause(id);              // No time accumulates while paused
bool paused = timer.IsPaused(id);  // true

timer.Resume(id);             // Resumes accumulating time from the pause point; accumulated time is not lost
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L74-L91)

### 2. Removing a Single Timer

```csharp
timer.Remove(id);                        // Remove by ID
timer.Remove(new Action<object>(OnTick)); // Remove by callback

bool alive = timer.Exists(id);           // Returns false after removal
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L48-L72)

`Remove(int id)` internally maps the ID to a callback first, then executes the same removal path as `Remove(Action<object>)`, so both removal approaches behave identically:

```csharp
public void Remove(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return;
        }

        Remove(callback);
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L376-L387)

### 3. Batch Pausing, Resuming, and Removing by Tag

Pass in a `tag` when creating timers, and you can then operate on the whole group at once — ideal for needs such as "pausing battle-related timers when switching scenes":

```csharp
int id = timer.Add(5f, 0, obj => { /* ... */ }, null, "battle");

timer.PauseByTag("battle");   // Pauses all timers under this tag
timer.ResumeByTag("battle");  // Resumes all timers under this tag
timer.RemoveByTag("battle");  // Removes all timers under this tag

bool anyLeft = timer.HasTag("battle"); // true when there are still active timers under this tag
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L93-L118)

`RemoveByTag` internally copies the list of IDs under the tag and then calls `Remove(id)` on each one, avoiding modification during iteration:

```csharp
public void RemoveByTag(string tag)
{
    lock (Locker)
    {
        if (_tags.TryGetValue(tag, out var ids))
        {
            // Copy to avoid modification during iteration
            var idsCopy = new List<int>(ids);
            foreach (var id in idsCopy)
            {
                Remove(id);
            }
        }
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)

### 4. Verifying State

| API | Return Value | Description |
|------|--------|------|
| `IsPaused(int id)` | `bool` | Returns `true` while paused; returns `false` if the ID does not exist |
| `Exists(int id)` / `Exists(Action<object> callback)` | `bool` | Returns `true` if the timer exists and has not been deleted |
| `HasTag(string tag)` | `bool` | Returns `true` if at least one timer exists under the tag |
| `GetRemaining(int id)` | `float` | Remaining seconds; returns `-1` if the ID does not exist or has not yet taken effect; returns `0` if `interval <= 0` or infinite looping |
| `GetElapsed(int id)` | `float` | Accumulated seconds; returns `-1` if the ID does not exist |
| `GetRepeatLeft(int id)` | `int` | Remaining repeat count (`0` means infinite); returns `-1` if the ID does not exist |

## Common Variants

**Cancelling asynchronous waits.** If you use extension methods such as `WaitForSecondsAsync`, "removal" is accomplished via a `CancellationToken`: when the token is cancelled, the `TaskCompletionSource` is set to the cancelled state, and the awaiting party receives a cancelled Task.

```csharp
var tcs = new TaskCompletionSource<bool>();
var registration = cancellationToken.Register(() => tcs.TrySetCanceled(cancellationToken));
```

## Common Mistakes

- **Calling `Pause` / `Resume` / `Remove` on a nonexistent or already-removed ID**: The implementation simply `return`s internally, throwing no exception but also having no effect; verify afterwards with `Exists(id)`.
- **Calling `Pause(id)` immediately after Add may not take effect**: If the timer is still sitting in the pending-add queue (`_toAdd`), `Pause` returns directly before setting the flag, making it a no-op; wait until it enters the active list before pausing.

  ```csharp
  // Timer in _toAdd (pending): also pausable
  if (_toAdd.ContainsKey(callback))
  {
      return;
  }
  ```

  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L404-L413)
- **`GetRemaining(id)` returning `-1` is not necessarily an error**: `-1` is returned when the ID does not exist, has been removed, or the timer has not yet entered the active list (see the return paths in the `GetRemaining` implementation).
- **Removal triggers `onComplete`**: The interface comment for `Add(..., Action onComplete = null)` states that this callback fires "when the timer completes/is removed"; when calling `Remove` manually, expect it to be invoked.
- **Paused ≠ removed**: A paused timer is still kept in the manager's entry list; it simply skips time accumulation and is not released; once you are sure it is no longer needed, call `Remove`.

## Background

`TimerManager` internally maintains an entry for each timer (with fields such as `Deleted`, `IsPaused`, `PausedElapsed`). When the update loop encounters an entry with `IsPaused == true`, it skips elapsed-time accumulation but keeps the entry in `_items`, so the timer can continue from the pause point after resuming. All pause/resume/remove operations are executed under `lock (Locker)` protection and can be safely called from non-main threads.
