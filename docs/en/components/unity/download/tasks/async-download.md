# Using await to Asynchronously Wait for a Download to Complete

`DownloadComponent` provides a `Download` method that returns `Task<bool>`, which can be used directly in coroutines or async methods with `await` to wait for a file download to complete, without needing to subscribe to event callbacks.

## Prerequisites

- The `DownloadComponent` component is attached in the scene (automatically registered via `[GameFrameXAutoComponent(-4000)]`).
- Your business code can obtain the `DownloadComponent` instance, typically retrieved via `GameEntry.GetComponent<DownloadComponent>()`.

## Steps

1. Call `DownloadComponent.Download(downloadPath, downloadUri)` to obtain a `Task<bool>`.
2. `await` this task inside an `async` method; a value of `true` indicates a successful download, while `false` indicates failure or that the download never started.
3. Decide the follow-up logic based on the return value (load resources, show an error, etc.).

Minimal working example:

```csharp
using System.Threading.Tasks;
using GameFrameX.Download.Runtime;

public async Task LoadRemoteConfigAsync()
{
    var download = GameEntry.GetComponent<DownloadComponent>();
    bool ok = await download.Download(
        downloadPath: Application.persistentDataPath + "/config.json",
        downloadUri:  "https://example.com/config.json");

    if (ok)
    {
        // Read the local file and continue with subsequent logic
    }
    else
    {
        // Fallback handling when the download fails
    }
}
```

## Common Variants

- Versions with tags or priorities still go through the original `AddDownload` flow; the `Download` method currently only exposes the most commonly used `(path, uri)` overload. If you need custom tags or priorities, you can continue using the `AddDownload` + events approach.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| `await` never returns, and the value is always `false` | The download task has not yet entered the download manager; `m_Downloads.TryGetValue` fails, and a task that has already had `TrySetResult(false)` called on it is returned directly | Verify that the path and URI are valid, and ensure that `DownloadComponent` has been `Start`ed (it depends on `EventComponent` and `m_DownloadManager`) |
| A `NullReferenceException` occurs at the call site | The business-side `DownloadComponent` is not present in the scene or has not yet been Awoken | Retrieve it via `GameEntry.GetComponent<DownloadComponent>()` and check for null first |
| With multiple concurrent tasks, the returned `Task`s overwrite one another | The `Download` method looks up the corresponding `TaskCompletionSource<bool>` in an internal dictionary based on `serialId` | Use separate `await` variables to receive each download, avoiding mixing up return values |

## Background (Optional)

Internally, a `ConcurrentDictionary<int, DownloadData>` is used to maintain the mapping from `serialId` to `TaskCompletionSource<bool>`; `DownloadSuccess` / `DownloadFailure` events are subscribed in `Awake`, and `TrySetResult(true/false)` is called in the callbacks, thereby converting the event-based API into a `Task` API.
