# 实体显示失败怎么办

调用 `ShowEntity` / `ShowEntityAsync` 后实体没有出现在场景中,或者日志提示 `ShowEntityFailure` 事件触发时,通常是实体组、资源或辅助组件配置不正确导致的。本页按常见原因给出快速诊断与修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `ShowEntityFailure` 事件立即触发,日志包含 `Entity group name is invalid.` | 传入的 `entityGroupName` 为 `null` / 空字符串,或该实体组未注册 | 在 `EntityComponent` 的 `m_EntityGroups` 中预先添加同名实体组 |
| 提示 `Entity group is invalid.` | 实体组存在,但其内部 `EntityGroup` 实例未初始化或被销毁 | 通过 `HasEntityGroup` 先确认组存在,再调用 `ShowEntity` |
| 提示 `Can not create entity helper.` | `EntityComponent.Awake`/`Start` 中未能根据 `m_EntityHelperTypeName` 反射出 `EntityHelperBase` | 检查 `m_EntityHelperTypeName` 是否为 `GameFrameX.Entity.Runtime.DefaultEntityHelper` 或自定义助手类的完整类型名;自定义助手需挂到 `m_CustomEntityHelper` 字段 |
| `ShowEntityFailure` 事件持续触发,资源加载失败 | `m_AssetManager` 未设置,或资源地址 (`entityAssetName`) 不在 YooAsset 资源清单中 | 确认 `EntityComponent.Start` 已调用 `SetResourceManager`;在 YooAsset 中正确配置实体 Prefab 的标签与地址 |
| 实体创建成功但 GameObject 不显示 | `m_InstanceRoot` 未挂到可见场景根下,或 Prefab 自身的 Layer/可见性被关闭 | 在场景中为 `EntityComponent` 指定可见的 `m_InstanceRoot`;检查 Prefab 的 `MeshRenderer` 状态 |
| 异步接口 `ShowEntityAsync` 一直不返回 | 资源加载卡住,或 `m_EntitiesBeingLoaded` 同一实体重复请求 | 避免在同一帧对同一 `EntityId` 发起多次 Show;确认资源管理器未被外部阻塞 |

## 修复步骤

### 1. 确认实体组已注册

`EntityManager` 会在实体组名为空时直接抛 `GameFrameworkException("Entity group name is invalid.")`。所有 `ShowEntity` 调用前必须先通过 `EntityComponent.AddEntityGroup` 添加组。

```csharp
// Source: Runtime/Entity/Entity/EntityManager.Get.cs#L53-L61
public bool HasEntityGroup(string entityGroupName)
{
    if (string.IsNullOrEmpty(entityGroupName))
    {
        throw new GameFrameworkException("Entity group name is invalid.");
    }
    return m_EntityGroups.ContainsKey(entityGroupName);
}
```

操作:

1. 打开挂有 `EntityComponent` 的场景对象 Inspector。
2. 在 `Entity Groups` 列表里添加要使用的组(填入 `Name`、`InstanceAutoReleaseInterval`、`InstanceCapacity`、`InstanceExpireTime`、`InstancePriority`)。
3. 在代码中使用组名前先调用 `HasEntityGroup` 校验。

### 2. 确认实体助手可用

`EntityComponent.Start` 中会调用 `Helper.CreateHelper` 创建实体助手;若返回 `null` 会输出 `Log.Error("Can not create entity helper.")` 并中止初始化。

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L171-L183
EntityHelperBase entityHelper = Helper.CreateHelper(m_EntityHelperTypeName, m_CustomEntityHelper);
if (entityHelper == null)
{
    Log.Error("Can not create entity helper.");
    return;
}
entityHelper.name = "Entity Helper";
Transform transform = entityHelper.transform;
transform.SetParent(this.transform);
transform.localScale = Vector3.one;
m_EntityManager.SetEntityHelper(entityHelper);
```

操作:

1. 确认 `Entity Helper Type Name` 字段指向的类存在(默认 `GameFrameX.Entity.Runtime.DefaultEntityHelper`)。
2. 自定义助手必须继承 `EntityHelperBase` 并实现实体实例化逻辑;将实例拖到 `Entity Component` 上的 `Custom Entity Helper` 字段。
3. 若助手类位于独立程序集,确认该程序集已被构建包含,反射可解析。

### 3. 确认资源管理器已注入

`EntityManager` 加载实体 Prefab 时依赖 `IAssetManager`(通过 `SetResourceManager` 注入);未注入会导致 `ShowEntityFailure` 在加载阶段失败。

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L167-L169
m_EntityManager.SetResourceManager(GameFrameworkEntry.GetModule<IAssetManager>());
m_EntityManager.SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>());
```

操作:

1. 确认场景中 `Asset Component`、`Object Pool Component` 已挂载且 Awake 顺序早于 `EntityComponent`。
2. 确认 YooAsset 已正确初始化,并在资源清单中存在传入的 `entityAssetName`(路径或标签)。
3. 必要时开启 `Enable Show Entity Dependency Asset Event`,通过事件观察依赖资源是否下载完成。

### 4. 监听失败事件定位根因

`EntityComponent` 在 Awake 中已默认订阅 `ShowEntityFailure`。在调试阶段可在自己的脚本里额外订阅,获取 `EntityId`、`EntityAssetName`、`EntityGroupName`、`ErrorMessage` 等信息。

```csharp
// Source: Runtime/Entity/Entity/EntityManager.cs#L118-L122
public event EventHandler<ShowEntityFailureEventArgs> ShowEntityFailure
{
    add { m_ShowEntityFailureEventHandler += value; }
    remove { m_ShowEntityFailureEventHandler -= value; }
}
```

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L130-L131
m_EntityManager.ShowEntitySuccess += OnShowEntitySuccess;
m_EntityManager.ShowEntityFailure += OnShowEntityFailure;
```

操作:在失败回调里打印 `EventArgs.ErrorMessage` 与 `EventArgs.EntityId`,根据消息回查上述 1~3 项。

### 5. 检查运行时实例根节点

实体助手会创建 `GameObject("Entity Instances")` 作为 `m_InstanceRoot`,若该根节点被禁用或不在场景中,实体虽然创建成功但视觉上不可见。

```csharp
// Source: Runtime/Entity/EntityComponent.cs#L185-L190
if (m_InstanceRoot == null)
{
    m_InstanceRoot = new GameObject("Entity Instances").transform;
    m_InstanceRoot.SetParent(gameObject.transform);
    m_InstanceRoot.localScale = Vector3.one;
}
```

操作:

1. 在 Hierarchy 中定位 `Entity Instances` 节点,确认它处于激活状态。
2. 若自定义了 `m_InstanceRoot`,确认其父节点与自身均激活,且未被相机剔除(如 `Layer` 设置、`Culling Mask` 等)。

## 验证

1. 在测试场景中调用 `ShowEntity<MyEntityLogic>(entityId, "Default", "MyPrefab", userData)`。
2. 观察 Console:应出现 `ShowEntitySuccess` 事件,`OnShowEntitySuccess` 被调用一次。
3. 在 Hierarchy 中确认以实体 `EntityId` 命名的 GameObject 出现在 `Entity Instances` 下,且位置/缩放/可见性符合预期。
4. 调用 `HideEntity(entityId)` 后,确认对象被回收回对象池,`HideEntityComplete` 事件正常触发。

## 背景(可选)

`EntityManager` 内部维护 `m_EntityInfos`、`m_EntityGroups`、`m_EntitiesBeingLoaded` 等字典与队列,资源加载通过 `IAssetManager` 异步完成,完成后调用 `IEntityHelper` 实例化实体并发出 `ShowEntitySuccess`;任何一步抛错都会走 `ShowEntityFailure` 路径并复用 `ShowEntityInfo` 引用对象([ShowEntityInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.ShowEntityInfo.cs#L38-L106))。
