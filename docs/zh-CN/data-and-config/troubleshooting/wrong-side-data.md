# 客户端/服务端数据没分开怎么办

如果你遇到这种情况：明明只想给客户端用的表，结果服务端也生成了；或者只想给服务端用的表，客户端也拿到了；又或者改了文件名前缀但两边的代码/数据没分开——这都是「客户端/服务端数据分组没生效」的典型表现。本页帮你快速定位并修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 服务端生成了只想给客户端用的表（反之亦然） | Excel 文件名没有带分组标记，默认两组都生成 | 在文件名里加 `-c-`（仅客户端）或 `-s-`（仅服务端）分组段 |
| 加了分组标记但还是两边都生成 | `luban.conf` 里 `groups` 配置把 `c`、`s` 都标成了 `default: true`，文件名没解析到分组 | 文件名段必须是 `<字母>-<英文名>-<分组>-<中文名>.xlsx`，且分组只能是 `c` 或 `s` |
| 改了分组后，旧的生成代码还在 | 只改了文件名，没重跑生成脚本 | 重跑 `gen-client-*` 和 `gen-server-*` 脚本 |
| 客户端/服务端都跑通了，但只想让一端用的字段在另一边也出现 | 字段没有按端分组（Excel 里没标记），工具默认全端输出 | 在 `__tables__.xlsx` 或对应 Bean 里给字段加端分组 |

## 修复步骤

### 1. 给文件名加分组标记

文件名格式：`字母-英文名-分组-中文名.xlsx`。分组段只能是 `c`（仅客户端）或 `s`（仅服务端）；不加分组就表示两端都要。

| 文件名 | 效果 |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | 客户端、服务端都用（默认） |
| `D-ItemConfig-c-道具表.xlsx` | 只有客户端用 |
| `D-ItemConfig-s-道具表.xlsx` | 只有服务端用 |

示例文件路径：[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

> `c` = client，`s` = server。不要写中文分组、不要写 `cs`/`sc` 之类两字母组合，工具只识别 `c` 和 `s`。

### 2. 检查 luban.conf 的 groups 配置

`luban.conf` 里的 `groups` 节点定义了两个分组 `c` 和 `s`，两者都设了 `default: true`，所以**没标记分组**的文件会被两端都生成：

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

`targets` 节点里 `server` 只取 `s` 组、`client` 只取 `c` 组、`all` 取两组并集：

```json
"targets": [
    { "name": "server", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "groups": ["c","s"], "topModule": "cfg" }
]
```

完整配置见 [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L61)。

这意味着：**仅靠文件名分组还不够，你还必须分别跑对应的生成脚本**，才会真正落到对应端。

### 3. 分别跑生成脚本

- 客户端：双击 `gen-client-json.bat`（Mac/Linux：`sh gen-client-json.sh`）
- 服务端：双击 `gen-server-json.bat`（Mac/Linux：`sh gen-server-json.sh`）

脚本说明见 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L265-L285)。

### 4. 字段级别的端分组（进阶）

如果同一张表里某些字段只想给某一端用（例如价格只让服务端有、UI 提示只让客户端有），需要在 `__tables__.xlsx` / `__beans__.xlsx` 里给该字段加 `c` 或 `s` 的端分组标记。普通 `int`、`string` 字段默认两端都有，工具会按配置自动裁剪。

## 验证

完成上面 1-3 步后，按下面方法确认分组生效：

1. 看输出目录：
   - 客户端代码/数据：`Unity/Assets/Bundles/Config`（数据）、`Unity/Assets/Hotfix/Config/Generate`（代码）
   - 服务端代码/数据：`Server/GameFrameX.Config/Json`（数据）、`Server/GameFrameX.Config/Config`（代码）
2. 在不该出现的那一端目录里**搜索表名**（例如 `TbItemConfig`），搜不到就说明分组生效。
3. 在代码里访问：客户端用 `tables.TbXxx.Get(id)`，服务端同样调用但代码命名空间不同（`Hotfix.Config` vs `GameFrameX.Config`），命名空间不一致即代表分组正确。
