# 打开、关闭与回收界面

本页讲解 FairyGUI 版 `UIManager` 的界面生命周期用法:如何触发打开(含单例去重与实例池复用)、关闭后如何回收,以及回收不等于销毁时该注意什么。对外打开/关闭入口继承自 GameFrameX.UI 包的 `BaseUIManager`,本仓库(插件)通过重写 `InnerOpenUIFormAsync` 与 `RecycleUIForm` 完成 FairyGUI 的具体实现。

## 前置条件

- 场景中已存在 `FairyGUIPackageComponent` 组件。`UIManager.SetResourceManager` 在设置资源管理器时会执行 `GameEntry.GetComponent<FairyGUIPackageComponent>()`,并用 `GameFrameworkGuard.NotNull` 校验,缺失会直接抛错:

```csharp
public override void SetResourceManager(IAssetManager assetManager)
{
    base.SetResourceManager(assetManager);
    FairyGuiPackage = GameEntry.GetComponent<FairyGUIPackageComponent>();
    GameFrameworkGuard.NotNull(FairyGuiPackage, nameof(FairyGuiPackage));
}
```

Source: [UIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs#L87-L92)

- 回收间隔有下限:构造函数中 `m_RecycleInterval` 小于 10 时强制置为 10(秒),即界面实例在池中最少保留 10 秒后才可能被真正释放。
- 界面逻辑类继承自 `FUI`(它继承自 `UIForm`),通过 `GObject` 属性访问 FairyGUI 对象。

## 操作步骤:打开界面

1. 以异步方式请求打开界面,`InnerOpenUIFormAsync` 是所有打开请求的汇聚点,签名为:

```csharp
protected override async Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L64-L64)

2. 若该界面类型启用了单例打开模式(`UseSingletonOpenMode(uiFormType)`),已打开则直接复用并重新聚焦,正在加载中则等待同一个任务,不会重复实例化:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }

    foreach (var value in m_LoadingUIForms)
    {
        if (value.UIFormAssetPath == uiFormAssetPath && value.UIFormAssetName == uiFormAssetName && value.UIFormType == uiFormType)
        {
            return await value.Task;
        }
    }
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L85)

3. 未命中单例分支时,先尝试从实例池取回(`m_InstancePool.Spawn(uiFormAssetName)`),命中则直接以新序列号 `InternalOpenUIForm` 完成打开,完全不经过资源加载:

```csharp
var uiFormInstanceObject = m_InstancePool.Spawn(uiFormAssetName);

if (uiFormInstanceObject != null)
{
    // 池复用也分配新的请求序列号，确保每次打开请求可观测。
    int serialId = ++m_Serial;
    return InternalOpenUIForm(serialId, uiFormAssetPath, uiFormAssetName, uiFormType, uiFormInstanceObject.Target, pauseCoveredUIForm, false, 0f, userData, isFullScreen);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L87-L94)

4. 池中也没有时进入 `InnerLoadUIFormAsync`:从资源路径截取包名,若 FairyGUI 包尚未加载则按来源加载——`Resources` 目录用 `FairyGuiPackage.AddPackageSync(assetPath)` 同步加载;Bundle 路径用 `FairyGuiPackage.AddPackageAsync` 异步加载,再加载带 `_fui` 后缀的界面资源:

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // 从Resources 中加载
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

5. 加载成功后回调 `LoadAssetSuccessCallback` 创建界面实例;加载失败则走 `LoadAssetFailureCallback(assetPath, uiFormAssetName, assetHandle.LastError, openUIFormInfo)`,错误信息来自 `assetHandle.LastError`。

## 操作步骤:关闭与回收

关闭界面最终会调用本仓库重写的 `RecycleUIForm`,其完整逻辑是:触发 `uiForm.OnRecycle()`,再从 `Handle` 对应的 GameObject 上取 `DisplayObjectInfo`,拿到 `GComponent` 后归还实例池;仅当 `isDispose == true` 时才额外 `ReleaseObject` 真正销毁:

```csharp
protected override void RecycleUIForm(IUIForm uiForm, bool isDispose = false)
{
    uiForm.OnRecycle();
    var formHandle = uiForm.Handle as GameObject;
    if (!formHandle)
    {
        return;
    }

    var displayObjectInfo = formHandle.GetComponent<DisplayObjectInfo>();
    if (!displayObjectInfo)
    {
        return;
    }

    var component = displayObjectInfo.displayObject.gOwner as GComponent;
    if (component == null)
    {
        return;
    }

    m_InstancePool.Unspawn(component);
    if (isDispose)
    {
        m_InstancePool.ReleaseObject(component);
    }
}
```

Source: [UIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Close.cs#L53-L79)

要点:

| 参数 | 行为 |
|------|------|
| `isDispose = false`(默认) | `Unspawn` 归还实例池,对象保留,下次打开直接复用 |
| `isDispose = true` | 归还后再 `ReleaseObject` 销毁释放 |
| `Handle` 不是 GameObject / 缺 `DisplayObjectInfo` / `gOwner` 不是 `GComponent` | 仅调用 `OnRecycle()` 后提前返回,不入池 |

## 常见变体:显示与隐藏动画

界面类 `FUI` 重写了 `Show` / `Hide`,把 FairyGUI 对象交给处理器播放动画;是否播动画由 `EnableShowAnimation` / `EnableHideAnimation` 与动画名 `ShowAnimationName` / `HideAnimationName` 控制,处理器为 null 时直接回调完成:

```csharp
public override void Show(IUIFormShowHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableShowAnimation, ShowAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}

public override void Hide(IUIFormHideHandler handler, Action complete)
{
    if (handler != null)
    {
        handler.Handler(GObject, EnableHideAnimation, HideAnimationName, complete);
    }
    else
    {
        complete?.Invoke();
    }
}
```

Source: [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L74-L105)

另一个常见变体是包名与界面资源名不一致:此时会重拼包路径 `PathHelper.Combine(uiFormAssetPath, packageName)` 后再 `AddPackageAsync`,并在其后拼接 `_fui` 加载界面资源,详见 [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L158-L178)。

## 常见错误

- **打开界面时抛出 `FairyGuiPackage` 为 null 的守卫异常**:`FairyGUIPackageComponent` 未挂载或未初始化,先在场景/入口补齐该组件再调用 `SetResourceManager`。
- **打开失败但没看到细节**:Bundle 模式下失败原因取自 `assetHandle.LastError`,并以 `LoadAssetFailureCallback` 收尾;排查时确认路径中包含 `BundlesDirectoryName` 指示的 Bundle 目录名,且包名能从资源路径正确截取。
- **关闭后内存未下降**:默认 `isDispose = false` 只归还实例池,实例在池中最少保留 `m_RecycleInterval`(下限 10 秒),这是预期行为;确需销毁时以 `isDispose: true` 回收。
- **频繁开关同一界面出现重复实例**:确认该界面类型启用了 `UseSingletonOpenMode`;未启用时每次打开都会走池/加载流程,允许同时存在多份。
## 验证

- 打开后通过返回的 `IUIForm` 检查 `GObject` 是否已挂到 `FUI.GObject`,单例界面二次打开应返回同一实例并触发 `RefocusUIForm`。
- 关闭后确认界面实例可从池中再次 `Spawn` 复用(默认路径),或以 `isDispose: true` 后不可再复用(销毁路径)。
- 动画路径验证:`Show`/`Hide` 完成回调 `complete` 必须被调用,否则上层流程不会继续。

## 背景

打开流程分三级短路:单例去重 → 实例池复用 → 异步加载。`m_LoadingUIForms` 列表记录进行中的加载任务以合并并发请求,每次打开(包括池复用)都会分配新的 `m_Serial` 序列号用于观测。回收路径上,`FUI.InternalSetVisible` 只改可见性不发事件,真正的实例归还/销毁都集中在 `RecycleUIForm` 中基于 `GComponent` 与 `m_InstancePool` 完成。
