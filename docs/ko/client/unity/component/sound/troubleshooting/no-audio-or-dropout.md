# 재생 시 소리가 나지 않거나 소리가 끊기는 경우 해결 방법

`ISoundManager.PlaySound` 호출 후 소리가 들리지 않거나, 소리가 잘리거나, 콘솔/로그에서 `PlaySoundFailure` 이벤트가 보일 때, 이 페이지의 절차에 따라 원인을 파악하고 수정하세요.

## 빠른 진단

| 증상 / 로그 키워드 | 원인(해당 `PlaySoundErrorCode`) | 수정 요점 |
|------|------|------|
| `Sound group 'X' is not exist.` | `SoundGroupNotExist` | `ISoundManager`에 X라는 이름의 사운드 그룹 등록 |
| `Sound group 'X' is have no sound agent.` | `SoundGroupHasNoAgent` | 해당 사운드 그룹에 최소 하나의 `ISoundAgent`(채널) 추가 |
| 에셋 경로 오류 / Addressables 에셋 로드 콜백 실패 | `LoadAssetFailure` | `soundAssetName`이 Addressables에 등록되어 있는지, `.wav`/`.mp3`가 Addressable로 표시되어 있는지 확인 |
| `AudioSource.clip`이 비어 있음 / 에이전트 컴포넌트가 AudioClip을 가져오지 못함 | `SetSoundAssetFailure` | 에이전트 GameObject가 씬에 있는지, AudioSource가 활성화되어 있는지 확인 |
| 배경 음악이 갑자기 멈추고 로그에 무시되었다고 표시됨 | `IgnoredDueToLowPriority` | 낮은 우선순위 재생 요청의 `Priority`를 높이거나, 동시 재생 수 줄이기 |
| 오류가 전혀 없지만 소리가 들리지 않음 | 볼륨이 변경됨 / 음소거 / 거리 감쇠 | `Volume`, `Mute`, 오디오 리스너, 3D 거리 파라미터 확인 |
| 소리가 버벅이거나 재생 중 갑자기 사라짐 | 동시 재생이 SoundAgent 수를 초과함 / 에셋이 미리 로드되지 않음 | 그룹 에이전트 수 늘리기, 미리 `PlaySound`를 호출하여 에셋 워밍업 |

오류 코드와 그 의미는 다음 열거형 정의에서 확인할 수 있습니다:

```csharp
public enum PlaySoundErrorCode : byte
{
    Unknown = 0,
    SoundGroupNotExist,
    SoundGroupHasNoAgent,
    LoadAssetFailure,
    IgnoredDueToLowPriority,
    SetSoundAssetFailure
}
```

Source: [PlaySoundErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/PlaySoundErrorCode.cs#L38-L69)

## 수정 단계

### 1. 실패 이벤트를 구독하여 먼저 상황 파악

시스템 시작 시점에 `PlaySoundFailure`를 구독하여 어떤 오류 코드인지 특정합니다:

```csharp
GameFrameXSound.Sound.PlaySoundFailure += OnPlaySoundFailure;

void OnPlaySoundFailure(object sender, PlaySoundFailureEventArgs e)
{
    Debug.LogError($"播放失败:[{e.ErrorCode}] {e.ErrorMessage} asset={e.SoundAssetName} group={e.SoundGroupName}");
}
```

이벤트 본체와 필드 의미(SerialId, SoundAssetName, SoundGroupName, ErrorCode, ErrorMessage, UserData)는 다음 파일에 정의되어 있습니다:

Source: [PlaySoundFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/EventArgs/PlaySoundFailureEventArgs.cs#L41-L91)
Source: [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L99-L101)

구독 트리거 지점에서는 실패 원인을 `ErrorMessage`에 기록합니다. 예를 들어:

- `Sound group 'X' is not exist.` → 2단계로 이동
- `Sound group 'X' is have no sound agent.` → 3단계로 이동
- `... play sound 'X' failure.`와 함께 `LoadAssetFailure` / `SetSoundAssetFailure` 발생 → 4단계로 이동

### 2. `SoundGroupNotExist` —— 사운드 그룹이 등록되지 않음

사운드 그룹 이름이 일치하지 않으면(대소문자, 공백) 이 오류가 발생합니다. 먼저 호출부에서 전달한 `soundGroupName`이 `ISoundManager.AddSoundGroup`로 등록한 이름과 완전히 일치하는지 확인하세요.

### 3. `SoundGroupHasNoAgent` —— 그룹에 에이전트가 없음

각 사운드 그룹에는 최소 하나의 `ISoundAgent`(하나의 `AudioSource`에 해당)가 필요합니다. 동시 재생 수가 에이전트 수보다 많으면 이후 요청은 버려지거나 중단됩니다. `ISoundGroup.AgentCount`를 확인하거나, `PlaySoundParams`에서 우선순위를 낮추거나 / `Priority`를 높여 낮은 우선순위 요청이 현재 오디오 트랙을 덮어쓰는 대신 무시되도록 하세요.

### 4. `LoadAssetFailure` / `SetSoundAssetFailure`

- **에셋 등록 여부**: `soundAssetName`은 Addressables(또는 커스텀 `ISoundHelper`)에서 `AudioClip`로 해석될 수 있어야 합니다.
- **에이전트 준비 여부**: `DefaultSoundAgentHelper`는 재생 전에 `AudioSource`를 얻어 `clip`을 설정해야 하며, 어느 단계에서든 실패하면 `SetSoundAssetFailure`가 발생합니다. 흔한 원인은 에이전트 GameObject가 파괴되었거나, 씬 전환 후 사운드 그룹이 다시 생성되지 않은 경우입니다.

Source: [DefaultSoundAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/DefaultSoundAgentHelper.cs)

### 5. 오류가 전혀 없는데 소리가 들리지 않음 —— 볼륨 / 공간 파라미터

`ISoundAgent.Volume`과 `ISoundGroup.Volume`은 기본적으로 모두 `Constant.DefaultVolume = 1f`로 계산되며, 비즈니스 로직에 의해 0으로 변경되거나 `Mute=true`로 덮어씌워지면 "재생은 성공했지만 소리가 없음" 현상이 발생합니다. `PlaySoundParams`의 주요 기본값은 다음과 같으며, 어느 하나라도 잘못 0으로 변경되면 영향을 받습니다:

| 파라미터 | 기본값 | 의미 |
|------|--------|------|
| `Volume` | `1f` | 단일 재생 볼륨 |
| `Mute` | `false` | 음소거 여부 |
| `Loop` | `false` | 반복 여부 |
| `Priority` | `0` | 재생 우선순위, 0이 기본 최저 |
| `FadeInSeconds` / `FadeOutSeconds` | `0f` | 페이드 인/아웃 시간(초) |
| `Pitch` | `1f` | 음조(피치) |
| `PanStereo` | `0f` | 스테레오 팬 |
| `SpatialBlend` | `0f` | 2D/3D 혼합, 1f는 순수 3D |
| `MaxDistance` | `100f` | 3D 최대 청취 거리 |
| `DopplerLevel` | `1f` | 도플러 레벨 |

Source: [Constant.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/Constant.cs#L43-L99)

추가로 확인할 사항:

- 씬에 `AudioListener`가 있는지(Unity에서 소리를 들으려면 반드시 하나가 존재해야 합니다).
- 3D 사운드의 `SpatialBlend`가 1에 가깝고, 발음체가 `AudioListener`로부터 `MaxDistance`보다 멀리 있으면 감쇠되어 들리지 않게 됩니다.
- 에디터의 "Mute Audio" 버튼이 실수로 켜져 있지 않은지 확인합니다.

### 6. 소리 끊김 / 프레임 드롭

- **동시 재생이 에이전트 수를 초과**: `PlaySoundParams.Priority`가 낮을수록 새로운 높은 우선순위 요청에 밀려나기 쉽습니다. 중요한 BGM/대사에는 더 높은 `Priority`를 사용하고 `Loop`를 `true`로 설정하세요.
- **에셋이 미리 로드되지 않음**: 처음 비동기로 에셋을 로드할 때 오디오 트랙이 아직 로드 완료되지 않은 상태에서 `PlaySound`가 다시 트리거됩니다. `PreloadSound`(또는 유사한 워밍업 API)를 사용하여 자주 사용하는 에셋을 미리 로드하세요.

## 검증

수정 후 아래 세 가지 작업을 수행하여 문제가 해결되었는지 확인합니다:

1. `OnPlaySoundFailure` 콜백에서 해당 `ErrorCode` 출력이 더 이상 발생하지 않는지 관찰합니다.
2. 콘솔에서 `GameFrameXSound.Sound.IsPlaying(serialId)`(또는 캐시해 둔 반환값)를 입력하여 재생 중인 핸들이 종료 시 정상적으로 회수되는지 확인합니다.
3. Player 실제 기기(에디터 음소거 아님)에서 BGM + 대사 + SFX를 포함한 전체 흐름을 한 번 실행하여 프레임 드롭이나 갑작스러운 끊김이 없는지 확인합니다.

## 관련 링크

- 인터페이스 및 이벤트 구독에 관해서는 《사운드 재생 이벤트(PlaySoundSuccess / PlaySoundFailure)》를 참고하세요.
- 사운드 그룹 및 에이전트 등록에 관해서는 《사운드 그룹과 SoundAgent 구성》을 참고하세요.
- `PlaySoundParams` 필드 의미에 관해서는 《PlaySoundParams 필드 레퍼런스》를 참고하세요.
