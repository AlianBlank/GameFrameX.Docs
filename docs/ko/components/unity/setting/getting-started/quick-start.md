# 빠른 시작

GameFrameX Setting을 사용하여 몇 분 내에 Unity 프로젝트의 타입화된 키-값 저장소를 통합하세요: 설치를 완료하고, `SettingComponent`를 씬에 추가한 후, `SetXxx` / `GetXxx`를 호출하면 `bool` / `int` / `float` / `string` 및 직렬화 가능한 객체를 읽고 쓸 수 있습니다.

## 사전 요구 사항

- Unity 2019.4 이상.
- 의존성 패키지 `com.gameframex.unity` 1.1.1, 패키지와 함께 자동으로 해석됩니다.
- 씬에 `GameFramework` 진입점이 존재해야 합니다 (런타임 시 `GameFrameworkEntry.GetModule<ISettingManager>()`를 통해 관리자를 가져옵니다).

## 설치

다음 방법 중 하나를 선택하여 Unity 프로젝트에 설치하세요:

1. `Packages/manifest.json`을 편집하여 scopedRegistries를 추가합니다:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.setting": "1.5.2"
     }
   }
   ```

2. `manifest.json`의 `dependencies`에 Git 의존성을 직접 추가합니다:

   ```json
   {
     "com.gameframex.unity.setting": "https://github.com/gameframex/com.gameframex.unity.setting.git"
   }
   ```

3. Unity `Package Manager`에서 **Add package from git URL**을 사용하여 위의 Git 주소를 붙여넣습니다.
4. 저장소를 Unity 프로젝트의 `Packages` 디렉터리에 직접 배치하면 Unity가 자동으로 인식합니다.

## 작업 단계

### 1. 씬에 SettingComponent 추가

빈 GameObject를 새로 만들고, 컴포넌트 **GameFrameX/Setting**(`SettingComponent`)을 추가합니다. 컴포넌트는 `Awake`에서 자동으로 `SettingManager`를 생성하고 영구 데이터를 로드합니다.

컴포넌트에는 기본적으로 `GameFrameXSettingCroppingHelper`가 함께 제공되며, `[RequireComponent]`에 의해 강제 요구됩니다.

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L43-L99)

### 2. 저장 백엔드 선택

`SettingComponent`의 두 필드가 저장 백엔드를 결정합니다:

| Inspector 필드 | 역할 | 기본값 |
|------|------|--------|
| `Setting Helper Type Name` | 리플렉션을 통해 `ISettingHelper`의 타입 전체 이름 생성 | `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` |
| `Custom Setting Helper` | `SettingHelperBase` 서브클래스를 씬에 직접 드래그 | `null` |

선택 가능한 내장 백엔드:

- `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`(기본값) — Unity PlayerPrefs,抖音, 微信, 快手, 支付宝 미니게임 SDK에 적응.
- `GameFrameX.Setting.Runtime.DefaultSettingHelper` — `Application.persistentDataPath` 기반의 바이너리 파일 저장.

전환 방법: Inspector에서 `Setting Helper Type Name` 필드를 수정하거나, `Custom Setting Helper`에 자체 구현을 지정합니다.

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L54)

### 3. 설정 쓰기 및 읽기

`SettingComponent`에서 제공하는 타입화된 API를 통해 설정을 조작합니다. 키가 존재하지 않거나 데이터가 손상된 경우, `GetXxx`는 전달된 기본값을 반환하고 경고를 출력하며 예외를 발생시키지 않습니다.

```csharp
using GameFrameX.Setting.Runtime;

SettingComponent setting = /* GetComponent 또는 GameFramework 진입점에서 가져오기 */;

// 설정 쓰기
setting.SetBool("FullScreen", true);
setting.SetInt("ResolutionWidth", 1920);
setting.SetFloat("Volume", 0.8f);
setting.SetString("PlayerName", "PlayerOne");

// 설정 읽기 (기본값 폴백 포함)
float volume = setting.GetFloat("Volume", 0.5f);

// 키 존재 여부 확인
if (setting.HasSetting("PlayerName"))
{
    string name = setting.GetString("PlayerName");
}
```

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs) · [SettingManager.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L43-L73)

### 4. 영구 저장 및 삭제

수정은 기본적으로 메모리에서만生效되며, `Save()`를 호출한 후에야 디스크에 기록됩니다. 삭제 작업도 단일 키와 전체 삭제를 지원합니다.

```csharp
// 저장소에 영구 저장
setting.Save();

// 단일 키 삭제
setting.RemoveSetting("PlayerName");

// 모든 설정 삭제
setting.RemoveAllSettings();
```

Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)

## 일반적인 변형

- **직렬화 가능한 객체 저장** — `SetObject<T>(string, T)` / `GetObject<T>(string)`은 내부적으로 JSON 직렬화를 사용하며, 저장 파일 및 구조체 설정에 적합합니다.
- **수동 로드** — 앱 시작 후 `setting.Load()`를 호출하여 저장소에서 모든 설정을 다시 로드합니다.
- **모든 키 이름 열거** — `setting.GetAllSettingNames()`는 현재 메모리에 있는 모든 설정 키의 문자열 배열을 반환합니다 (참고: PlayerPrefs 백엔드는 이 기능을 지원하지 않음).
- **미니게임 플랫폼** — 抖音, 微信, 快手, 支付宝 미니게임 빌드에서 PlayerPrefs 백엔드는 자동으로 플랫폼 SDK 저장소로 라우팅됩니다. `DefaultSettingHelper`는 여전히 `Application.persistentDataPath` 파일 I/O를 사용하며, 모든 플랫폼에서 일관됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|----------|
| 시작 후 로그 오류 `Setting manager is invalid.` | 씬에 `GameFramework` 진입점이 없거나, 진입점이 `SettingComponent`보다 먼저 초기화되지 않음 | `GameFramework` 초기화가 완료된 후 `SettingComponent`가 포함된 씬 활성화 |
| `Log.Fatal` 후 설정이 적용되지 않음 | `Awake` 단계에서 `ISettingManager` 가져오기 실패 | `GameFramework` 컴포넌트 체인이 완전한지 확인 |
| 수정 후 게임 재시작 시 데이터 손실 | 메모리 쓰기에서 `Save()` 미호출 | 앱 종료 전 또는 주요 시점에 명시적으로 `setting.Save()` 호출 |
| 사용자 정의 Helper가 적용되지 않음 | `Setting Helper Type Name`이 실제 타입 전체 이름과 일치하지 않거나, `Custom Setting Helper`도 함께 설정됨 | 우선순위: `Custom Setting Helper` > `Setting Helper Type Name`; 둘 중 하나만 선택 |
| 부동 소수점 숫자가 다른 언어 환경에서 잘못 읽힘 | `SetFloat`은 `CultureInfo.InvariantCulture`를 사용하여 쓰지만, 읽기 측이 로컬화됨 | 항상 `GetFloat`을 사용하고, 기본 문자열을 직접 역직렬화하지 말 것 |

## 배경 (선택 사항)

`SettingComponent`는 `GameFrameworkComponent`의 서브클래스로, `Awake` 단계에서 `GameFrameworkEntry.GetModule<ISettingManager>()`를 통해 `SettingManager`를 가져온 다음, 리플렉션 또는 사용자 정의 필드를 사용하여 `ISettingHelper`를 생성 및 주입합니다. `SettingManager`는 모든 `SetXxx` / `GetXxx` 호출에 대해 키 이름 검증을 수행하며, 빈 키는 `GameFrameworkException("Setting name is invalid.")`을 발생시킵니다. 데이터가 손상된 경우 `TryParse`를 사용하여 기본값으로 폴백하고 `Log.Warning`을 출력하여 실행이 중단되지 않도록 합니다.
