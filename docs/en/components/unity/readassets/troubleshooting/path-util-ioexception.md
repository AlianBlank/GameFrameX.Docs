# PathUtil Throws IOException: Invalid path: double dot error / Invalid characters

When calling `PathUtil.NormalizeRelativePath`, if the relative path passed in contains out-of-bounds `..` segments or illegal characters, a `System.IO.IOException` will be thrown. Common messages include two: `Invalid path: double dot error (before N)` and `Invalid characters`.

## Quick Diagnosis

| Symptom (original exception message) | Root Cause | Fix |
|---|---|---|
| `Invalid path: double dot error (before <N>)` | After reaching the "virtual root `/`", still trying to go up one more level using `..` | Remove the extra `../` and ensure the path does not go beyond the entry root directory |
| `Invalid characters` | The path contains characters rejected by `IsValidCharacter` (`\"`, `<`, `>`, `\|`, control characters `<32`, `:`, `*`, `?`) | Remove or replace the illegal characters |

Both exceptions come from `NormalizeRelativePath` in `Runtime/PathUtil.cs`.

## Fix Steps

### 1. Handling `Invalid path: double dot error`

Trigger condition: during parsing, `..` attempts to go beyond the already-normalized "root `output`". Source code snippet:

```csharp
// Runtime/PathUtil.cs#L107-L112
else if ( state == NormalizeState.PrevDoubleDot )
{
    if ( output.Length == 1 )
    {
        throw new System.IO.IOException("Invalid path: double dot error (before " + i + ")");
    }
    ...
}
```

That is, when a `..` appears while the currently accumulated output only has the leading root slash, an exception is thrown directly.

Fix method:

1. Print the passed-in relative path to locate the "last" problematic `..`.
2. Calculate the actual number of levels you can go up (equal to the number of non-`..` segments in the path prefix), and remove the extra `../`.
3. If the caller uses `Path.Combine` to concatenate an absolute path with a relative path containing `../`, switch to `PathUtil.CombineSlash`, or call `NormalizeRelativePath` first before concatenating.

```csharp
// Before using NormalizeRelativePath, first reduce ../ to a reasonable range
var safe = relative.Replace("..\\", "").Replace("../", "");
var normalized = PathUtil.NormalizeRelativePath(safe);
```

`NormalizeRelativePath` also supports being wrapped in double quotes at the beginning and end: in the source code, if it detects that both the start and end are `"`, it automatically strips them before parsing (`Runtime/PathUtil.cs#L93-L97`). Do not treat this as an "escape hatch" to bypass illegal characters—the following type of exception will still be thrown.

### 2. Handling `Invalid characters`

Trigger condition: the path contains characters not allowed by `IsValidCharacter`:

```csharp
// Runtime/PathUtil.cs#L173-L180
public static bool IsValidCharacter(char c)
{
    if (c == '\"' || c == '<' || c == '>' || c == '|' || c < 32 || c == ':' || c == '*' || c == '?')
    {
        return false;
    }
    return true;
}
```

Where the exception is thrown in the source code:

```csharp
// Runtime/PathUtil.cs#L159-L162
if (!IsValidCharacter(relative[i]))
{
    throw new System.IO.IOException("Invalid characters");
}
```

Fix method:

1. Before calling `NormalizeRelativePath`, filter or replace the 8 categories of characters listed above. You can directly reuse the existing check:

```csharp
// Caller performs a self-check first to avoid hitting IOException directly
foreach (var ch in relative)
{
    if (!PathUtil.IsValidCharacter(ch))
    {
        // Report error or replace
        throw new ArgumentException($"Illegal character: {ch}");
    }
}
```

2. Windows-style drive letters (`C:`, colon) will be treated as illegal characters. If the path comes from user input or external resource names, it is recommended to perform a whitelist validation first.
3. If this is a wildcard scenario, use `PathUtil.WildcardToRegex` instead (see `Runtime/PathUtil.cs#L183-L186`); it only accepts `*` and `?` as metacharacters. Other illegal characters will be escaped by `Regex.Escape` and will not trigger the IOException here.

## Background (Optional)

`NormalizeRelativePath` internally treats the path as a relative virtual root starting with `/`, scans character by character, and maintains four states: `PrevSlash / PrevDot / PrevDoubleDot / NothingSpecial` (`Runtime/PathUtil.cs#L11-L17`); `..` is implemented by rolling back already-written segments, and once it rolls back to only the root slash left, it is considered out of bounds. Illegal characters are checked against a whitelist before being written (`Append`)—this is when both exceptions are triggered.
