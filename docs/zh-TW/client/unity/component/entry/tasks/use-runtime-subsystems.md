# 如何使用 Entity、Coroutine、Sound、Scene 與 Mono 管理

`GameFrameX` 以延遲載入的方式，透過 `GameApp` 靜態外觀（Facade）公開其執行階段子系統元件——包括 Entity、Coroutine、Sound、Scene 與 Mono。每個子系統都對應一個透過 `GameEntry.GetComponent<T>()` 取得的元件實例；若要使用某個子系統，只需在程式碼中存取 `GameApp.{SubsystemName}` 即可。本頁說明如何整合這些子系統及其典型用法。

## 前置條件

1. 已安裝 `com.gameframex.unity.entry` 套件，且 `GameEntry` 啟動器已掛載到場景中。
2. 已透過 Package Manager 安裝各子系統對應的執行階段套件：
   - `com.gameframex.unity.entity`（Entity）
   - `com.gameframex.unity.coroutine`（Coroutine）
   - `com.gameframex.unity.sound`（Sound）
   - `com.gameframex.unity.scene`（Scene）
   - 內建的 Mono 管理器隨入口套件一併提供
3. 專案已定義對應的啟用巨集：`ENABLE_GAME_FRAME_X_ENTITY`、`ENABLE_GAME_FRAME_X_COROUTINE` 等（每個元件的原始碼都由 `#if` 保護；若未定義巨集，相關欄位將無法編譯——詳見下方「常見錯誤」）。

## 操作說明

### 1. 透過 GameApp 存取子系統

所有子系統都以 `public static {ComponentClass} {SubsystemName}` 的形式公開於 `GameApp` 類別中，並在首次存取時透過 `GameEntry.GetComponent<T>()` 建立並快取。無需手動 `new` 或註冊。

```csharp
using GameFrameX.Runtime;

public static partial class GameApp
{
    public static EntityComponent Entity
    {
        get
        {
            if (_entity == null)
            {
                _entity = GameEntry.GetComponent<EntityComponent>();
            }
            return _entity;
        }
    }

    private static EntityComponent _entity;
}
```

原始碼：[Runtime/GameApp.Entity.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Entity.cs#L36-L55)

Coroutine 元件遵循完全相同的模式：

```csharp
using GameFrameX.Runtime;
using GameFrameX.Coroutine.Runtime;

public static partial class GameApp
{
    public static CoroutineComponent Coroutine
    {
        get
        {
            if (_coroutine == null)
            {
                _coroutine = GameEntry.GetComponent<CoroutineComponent>();
            }
            return _coroutine;
        }
    }

    private static CoroutineComponent _coroutine;
}
```

原始碼：[Runtime/GameApp.Coroutine.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Coroutine.cs#L36-L55)

使用範例：

```csharp
// Entity
var entityComponent = GameApp.Entity;

// Coroutine
var coroutineComponent = GameApp.Coroutine;
```

### 2. 使用 Entity 的要點

透過 `GameApp.Entity` 取得 `EntityComponent` 後，即可使用框架提供的實體建立、查詢與銷毀介面。實體生命週期由 `EntityComponent` 統一管理，通常與 `Entity` 基底類別及 `EntityLogic` 邏輯腳本搭配使用。詳細的介面簽章請參考 `EntityComponent` 原始碼；本儲存庫並未直接包含其實作——請查閱 `com.gameframex.unity.entity` 套件內的文件。

### 3. 使用 Coroutine 的要點

透過 `GameApp.Coroutine` 取得 `CoroutineComponent`，即可在任何非 MonoBehaviour 的環境中啟動協程任務。協程元件在底層封裝了 Unity 的 `Coroutine` 機制，讓你能夠在非 Mono 類別中安全地啟動延遲與逐幀操作。呼叫入口通常如下：

```csharp
GameApp.Coroutine.StartCoroutine(MyRoutine());

GameApp.Coroutine.StopCoroutine(handle);
```

確切的多載形式請參考 `CoroutineComponent` 原始碼檔案。

### 4. 使用 Sound 的要點

Sound 子系統使用相同的靜態外觀入口。在本儲存庫中，`Runtime/GameApp.Sound.cs` 提供了由 `#if` 保護的 `GameApp.Sound`，會回傳 `SoundComponent` 實例。常見操作包括播放 BGM、播放音效、暫停／恢復以及設定音量；確切的 API 請參考 `SoundComponent` 的實作。

```csharp
// 僅供示意：實際簽章請參閱 SoundComponent
GameApp.Sound.PlayMusic(musicId);
GameApp.Sound.PlaySound(soundId);
```

### 5. 使用 Scene 的要點

`Runtime/GameApp.Scene.cs` 同樣將 `SceneComponent` 公開為 `GameApp.Scene`。你可以使用此元件載入與卸載場景，以及取得目前已載入場景資產的相關資訊。典型流程：傳入場景資產名稱 → 觸發非同步載入 → 載入完成後附加並切換作用中場景。

```csharp
// 僅供示意
GameApp.Scene.LoadScene("MainCity", onComplete: () => { /* 場景進入完成 */ });
```

### 6. 使用 Mono 管理器的要點

`Mono` 管理器用於在非 MonoBehaviour 類別中取得類似 `Mono` 的能力（輪詢、協程、計時器等），並與 `GameApp.Coroutine` 協同運作。它可以直接透過 `GameApp` 上的 Mono 相關屬性取得；後續呼叫 `Update`/`OnDestroy` 等生命週期鉤子時，無需繼承 `MonoBehaviour`。

## 常見變體

- **跨平台裁剪**：每個 `GameApp.*.cs` 都使用 `#if ENABLE_GAME_FRAME_X_{NAME}` 條件編譯，因此可以在專案的 `csc.rsp` 或 `Player Settings` 中依需求啟用／停用子系統。一旦停用，對應的 `GameApp.{Name}` 欄位就會消失。
- **依賴注入替代方案**：如果你不想使用靜態外觀，可以直接呼叫 `GameEntry.GetComponent<EntityComponent>()` 等方式取得原始元件參考；兩種做法是等價的。
- **子系統命名差異**：例如，某些版本使用 `Mono` 而不是 `MonoManager` 作為名稱；請參考目前執行階段套件版本的原始碼。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `GameApp.Entity` / `GameApp.Coroutine` 等屬性不存在 | 未安裝對應的子系統套件，或未定義 `ENABLE_GAME_FRAME_X_ENTITY` / `ENABLE_GAME_FRAME_X_COROUTINE` 等巨集 | 在 Package Manager 中安裝對應套件，並在專案的 `csc.rsp` 或 `Scripting Define Symbols` 中加入巨集定義 |
| 呼叫時回傳 `null` 或擲回 Null 參考例外 | `GameEntry` 未掛載到場景中，或該子系統未註冊為 `GameEntry` 上的元件 | 將 `GameEntry` 預製物件加入啟動場景，並確認 Inspector 中已勾選目標元件 |
| 協程不執行 | 傳遞給 `StartCoroutine` 的方法未回傳 `IEnumerator`，或呼叫發生在 `Mono` 環境被銷毀之後 | 驗證方法簽章，並避免在已銷毀的物件上啟動協程 |
| 找不到 Sound/Scene 介面 | 子系統套件尚未升級至與目前入口套件相符的版本 | 升級對應的執行階段套件，或參考目標版本 `SoundComponent` / `SceneComponent` 的實際簽章 |

## 背景說明（可選）

`GameApp` 是一個 `partial class`；每個子系統對應一個 `Runtime/GameApp.{Name}.cs` 檔案，各自由 `#if` 保護並彼此解耦，以便按需裁剪套件。所有元件都透過 `GameEntry.GetComponent<T>()` 的延遲載入模式取得；首次存取時，`GameEntry` 會將其實例化並快取到 `GameApp` 的私用靜態欄位中，後續呼叫則直接回傳快取的實例——在確保全域唯一性的同時，也避免了模組載入順序的問題。
