# UI Form Helper をカスタマイズする方法

`UIFormHelperBase` を継承して `IUIFormHelper` の3つのメソッドを実装することで、UI リソースのインスタンス化、`IUIForm` ビジネスオブジェクトの作成、および UI の解放フローを引き継ぐことができます。その後、`UIComponent` にクラス名文字列またはプレハブ参照であなたの実装を使用させるだけで有効になります。

## 前提条件

- GameFrameX UI サブシステムの基本的なフローをすでに理解していること(全体のアーキテクチャについては、関連ドキュメントを参照)。
- プロジェクトに `com.gameframex.unity.ui` パッケージがインストールされており、シーンに `UIComponent` がアタッチされていること。

## 操作手順

1. **`IUIFormHelper` インターフェースを実装する、または `UIFormHelperBase` を継承します。**

   `UIFormHelperBase` はすでに `MonoBehaviour` ライフサイクルと `Scripting.Preserve]` 属性の処理を済ませているため、これを継承して3つの抽象メソッドを実装するだけで済みます。

   インターフェースの定義は [IUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIFormHelper.cs#L40-L76) に、抽象基底クラスは [UIFormHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81) にあります。

   ```csharp
   using System;
   using GameFrameX.UI.Runtime;
   using UnityEngine;

   public class MyUIFormHelper : UIFormHelperBase
   {
       public override object InstantiateUIForm(object uiFormAsset)
       {
           // 使用している UI ソリューション(FairyGUI / UGUI / その他)に応じて UI リソースをインスタンス化
           var prefab = uiFormAsset as GameObject;
           if (prefab == null) return null;
           return Instantiate(prefab);
       }

       public override IUIForm CreateUIForm(object uiFormInstance, Type uiFormType, object userData)
       {
           // uiFormInstance を uiFormType に対応するビジネスロジックスクリプトにバインドし、IUIForm を返す
           var go = uiFormInstance as GameObject;
           var form = go.GetComponent(uiFormType) as IUIForm;
           if (form != null)
           {
               (form as Component).gameObject.SetActive(true);
           }
           return form;
       }

       public override void ReleaseUIForm(object uiFormAsset, object uiFormInstance, object assetHandle,
                                          string uiFormAssetPath, string uiFormAssetName)
       {
           // インスタンスを破棄し、必要に応じてリソースハンドルを返却する
           var go = uiFormInstance as GameObject;
           if (go != null) Destroy(go);
       }
   }
   ```
   Source: [Runtime/UIFormHelperBase.cs#L42-L81](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)

2. **`UIComponent` にあなたの Helper を使用させます。**

   `UIComponent` は「型名リフレクションによる生成」と「カスタム Helper プレハブの直接ドラッグ&ドロップ」の2つの方法をサポートしています。いずれか一方を選択してください:

   - **方法 A —— 型名による指定**:`UIComponent` の Inspector 上の `UI Form Helper Type Name` を、あなたのクラスの完全名(名前空間を含む)に変更します。デフォルト値は `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper` です。
   - **方法 B —— プレハブによる指定**:あなたの `MyUIFormHelper` を GameObject にアタッチしてプレハブ化し、`UIComponent` の `Custom UI Form Helper` フィールドにドラッグします。実行時には `Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper)` がこの参照を優先的に使用します。

   ```csharp
   // Runtime/UIComponent.cs でカスタム Helper を読み込むロジック
   UIFormHelperBase uiFormHelper = Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper);
   if (uiFormHelper == null)
   {
       Log.Error("Can not create UI form helper.");
       return;
   }
   uiFormHelper.name = "UIFormHelper";
   transform = uiFormHelper.transform;
   transform.SetParent(this.transform);
   transform.localScale = Vector3.one;
   m_UIManager.SetUIFormHelper(uiFormHelper);
   ```
   Source: [Runtime/UIComponent.cs#L526-L538](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L526-L538)

3. **型名の名前空間が ComponentType と一致することを保証します。**

   起動時に `UIComponent` は次の検証を行います:`m_UIFormHelperTypeName` は現在の UI システムに対応する名前空間で始まっている必要があります。そうでない場合、コンソールに `UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.` というエラーが出力され、該当コンポーネントが無効化されます。

   ```csharp
   if (!m_UIFormHelperTypeName.StartsWithFast(namespaceName))
   {
       Debug.LogError("UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.");
       enabled = false;
       return;
   }
   ```
   Source: [Runtime/UIComponent.cs#L437-L442](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L437-L442)

4. **実行時に Helper を手動で置き換える(任意)。**

   ゲーム実行中に Helper を切り替えたい場合は、`BaseUIManager.SetUIFormHelper(IUIFormHelper)` を直接呼び出します:

   ```csharp
   m_UIManager.SetUIFormHelper(new MyUIFormHelper());
   ```

## よくあるバリエーション

| シナリオ | 方法 |
|------|------|
| FairyGUI の導入 | Helper 内部で `uiFormAsset` を FairyGUI コンポーネントとして解析して `GComponent` を返し、`CreateUIForm` ではその `GComponent` をラップした `IUIForm` 実装を返します。 |
| UGUI の導入 | `GameObject` をそのまま汎用のキャリアとして使用し、`InstantiateUIForm` 内で `Object.Instantiate` を呼び出し、`CreateUIForm` 内で `GetComponent(uiFormType)` によってロジックスクリプトをバインドします。 |
| 実行時のホットスワップ | `BaseUIManager.SetUIFormHelper` で新しい Helper インスタンスに置き換えますが、古いインスタンスの破棄は自分で管理する必要があります。 |

## よくあるエラー

| エラー | 原因 | 修正方法 |
|------|------|------|
| 起動後にコンソールで `UI组件的 UI Form Helper 设置错误。` とエラーが表示される | `UI Form Helper Type Name` の名前空間が現在の `ComponentType` と一致していない。 | 名前空間を選択した UI システムに一致するように変更する(例：FairyGUI は `GameFrameX.UI.FairyGUI.Runtime`、`UGUI` は `GameFrameX.UI.UGUI.Runtime`)か、正しいプレハブをドラッグします。 |
| 画面を開く際に `Can not create UI form helper.` と表示される | 型名のスペルミス、またはカスタムプレハブにスクリプトがアタッチされていない。 | `m_UIFormHelperTypeName` の完全クラス名を確認するか、`m_CustomUIFormHelper` プレハブに `UIFormHelperBase` のサブクラスがアタッチされていることを確認します。 |
| `SetUIFormHelper(null)` で例外がスローされる | `BaseUIManager` 内部で引数に対する非 null チェックが行われている。 | 常に null 以外のインスタンスを渡し、クリアしたい場合はデフォルト実装に置き換えます。 |

## 背景(任意)

`IUIFormHelper` は「リソースをどのように GameObject / GComponent に変換するか」と「それをどのようにロジックスクリプトにバインドするか」という2つの責務を UI マネージャーから切り離し、同一の `BaseUIManager` で異なる UI ソリューションに対応できるようにします。`UIComponent` は `Start` 内で「型名 → カスタムプレハブ」の優先順位で Helper を生成し、その後 `BaseUIManager.SetUIFormHelper` を呼び出してフレームワークに登録します。
