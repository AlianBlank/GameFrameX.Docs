# How to Handle Payment Result Events

Subscribe to the 4 payment events on `PaymentComponent` (purchase success, purchase failure, query purchases result, consume purchase result), dispatch handling in the callbacks based on `PaymentEventArgs.ResultCode`, and use `PurchaseToken` to complete consumption. All APIs are defined in [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L64) and [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66).

## Prerequisites

- The scene already contains a GameFrameX root object with `PaymentComponent` attached (menu `GameFrameX/Payment`; the component requires `GameFrameXPaymentCroppingHelper` to also be present).
- `Init()` has been called to initialize the payment manager, and purchases should only be initiated after `IsReady()` returns `true`:

```csharp
// Signature: public void Init(bool isDebug = false, bool isClientVerify = true)
// Signature: public bool IsReady()
paymentComponent.Init(isDebug: false, isClientVerify: true);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115)

## Steps

1. Get a reference to `PaymentComponent` (e.g., via the GameFrameX module entry point).
2. Subscribe to the events during game startup and unsubscribe symmetrically during teardown (`PaymentComponent` forwards directly to the internal `IPaymentManager`):

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseSuccess += OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed += OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult += OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult += OnConsumePurchaseResult;

// On exit/destroy
paymentComponent.OnPurchaseSuccess -= OnPurchaseSuccess;
paymentComponent.OnPurchaseFailed -= OnPurchaseFailed;
paymentComponent.OnQueryPurchasesResult -= OnQueryPurchasesResult;
paymentComponent.OnConsumePurchaseResult -= OnConsumePurchaseResult;
```

The actual declarations of the events on the component are as follows (`add`/`remove` forward directly to the manager):

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}

public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L64)

3. In the callbacks, branch on `ResultCode` and retrieve data via the fields of `PaymentEventArgs`:

```csharp
private void OnPurchaseSuccess(object sender, PaymentEventArgs e)
{
    // e.ProductId / e.OrderId / e.PurchaseToken / e.PurchaseData / e.CustomData
}

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    switch (e.ResultCode)
    {
        case PaymentResultCode.Cancelled:
            // User actively cancelled; usually handled silently
            break;
        case PaymentResultCode.NetworkError:
        case PaymentResultCode.ServiceUnavailable:
            // Prompt to retry later
            break;
        case PaymentResultCode.ItemAlreadyOwned:
        case PaymentResultCode.VerifyFailed:
        default:
            // Display or report using e.ErrorMessage
            break;
    }
}
```

4. After successfully delivering a consumable product, call `ConsumePurchase` with the `PurchaseToken` from the callback to consume the purchase; its result is likewise returned via the `OnConsumePurchaseResult` event:

```csharp
// Signature: public void ConsumePurchase(string purchaseToken)
paymentComponent.ConsumePurchase(e.PurchaseToken);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L133-L152)

## Common Variants

- **Order recovery / restore purchases**: Call `QueryPurchases(PaymentProductType)` and listen for `OnQueryPurchasesResult`, then deliver historical orders with `ResultCode == PaymentResultCode.Success` one by one and call `ConsumePurchase(e.PurchaseToken)`.
- **Only care about the result code**: Both `OnPurchaseSuccess` and `OnPurchaseFailed` carry the same `PaymentEventArgs` structure; failure scenarios additionally rely on `ErrorMessage`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Log shows `You are using DefaultPaymentManager which is a stub...` | Editor/non-mobile platforms fall back to the stub implementation, so events never fire | Integrate a channel implementation (e.g., Google/Apple), or verify on a real device |
| Log shows `Pay Manager is invalid.` | The manager module was not loaded correctly | Check that `PaymentComponent` and the cropping helper component are both present |
| Log shows `Purchase token is null or empty.` | `ConsumePurchase` was called with an empty token | Use the `e.PurchaseToken` returned by the callback |

The original warning/error messages above come from [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L19-L48) and [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L152).

## Verification

- After subscribing, initiate a `Buy(new PurchaseParams(...))` and confirm that `OnPurchaseSuccess` or `OnPurchaseFailed` fires at least once, and that `e.ProductId` and `e.OrderId` match the initiating parameters.
- After calling `ConsumePurchase`, confirm that `OnConsumePurchaseResult` returns with `ResultCode == PaymentResultCode.Success`.

## Background

`PaymentComponent` is a thin wrapper: the 4 events are forwarded directly to platform implementations via `add`/`remove` accessors (Android uses `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`, iOS/macOS uses `Apple.Runtime.ApplePaymentManager`, WebGL/PC each have their own implementations, and all other platforms fall back to the `DefaultPaymentManager` stub). Therefore, the event handling logic is platform-independent; simply subscribe at the component layer.
