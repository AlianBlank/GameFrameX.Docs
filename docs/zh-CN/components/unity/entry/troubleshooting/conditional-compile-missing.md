# 条件编译导致某子系统不可用怎么办

当 `GameApp` 上某个子系统(如 `Network`、`GUI`、`Entity`、`Download`)的属性访问不到、报"`GameApp` 不包含 XXX 的定义",或调用时直接报空引用,通常是缺少对应的条件编译宏,导致整个 `GameApp.XXX.cs` 文件在编译时被 `#if … #endif` 整体排除,而不是真的没有这个 API。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameApp.Network`、`GameApp.GUI`、`GameApp.Entity` 等属性找不到,IDE 标红 | 对应的 `ENABLE_GAME_FRAME_X_XXX` 宏未定义,整个 `GameApp.XXX.cs` 被 `#if … #endif` 排除 | 在 *Project Settings → Player → Scripting Define Symbols* 中添加缺失的宏,或安装对应子模块包 |
| 调用 `GameApp.XXX` 时返回的组件为 `null`、调用方法报 `NullReferenceException` | 宏已定义、属性存在,但底层组件未注册到 `GameEntry` | 检查 `GameEntry.RegisterComponent` 流程,确认对应的 Runtime 包已安装并启动 |
| 切换平台(如 iOS/Android/Editor)后某个子系统突然不可用 | 部分宏同时包在平台编译里,或宏只针对特定平台定义 | 检查宏是否随 `UNITY_IOS`、`UNITY_ANDROID` 等平台宏一起变化 |

## 修复步骤

### 1. 确认你用到了哪个子系统

每个子系统都对应一个 `Runtime/GameApp.<Name>.cs` 文件,文件首尾被同一个宏包住。下面是仓库里目前存在的子系统与对应宏:

| 子系统 | 文件 | 条件编译宏 |
|--------|------|------------|
| 网络 Network | `Runtime/GameApp.Network.cs` | `ENABLE_GAME_FRAME_X_NETWORK` |
| GUI(UGUI) | `Runtime/GameApp.GUI.cs` | `ENABLE_GAME_FRAME_X_L_UGUI` |
| 实体 Entity | `Runtime/GameApp.Entity.cs` | `ENABLE_GAME_FRAME_X_ENTITY` |
| 下载 Download | `Runtime/GameApp.Download.cs` | `ENABLE_GAME_FRAME_X_DOWNLOAD` |
| 全局配置 GlobalConfig | `Runtime/GameApp.GlobalConfig.cs` | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` |
| 广告 Advertisement | `Runtime/GameApp.Advertisement.cs` | `ENABLE_GAME_FRAME_X_ADVERTISEMENT` |
| 苹果登录 AppleLogin | `Runtime/GameApp.AppleLogin.cs` | `ENABLE_GAME_FRAME_X_APPLE_LOGIN` |
| Facebook 登录 | `Runtime/GameApp.FaceBookLogin.cs` | `ENABLE_GAME_FRAME_X_FACEBOOK_LOGIN` |
| Google 登录 | `Runtime/GameApp.GoogleLogin.cs` | `ENABLE_GAME_FRAME_X_GOOGLE_LOGIN` |
| QQ 登录 | `Runtime/GameApp.QQLogin.cs` | `ENABLE_GAME_FRAME_X_QQ_LOGIN` |
| 微信登录 | `Runtime/GameApp.WeChatLogin.cs` | `ENABLE_GAME_FRAME_X_WECHAT_LOGIN` |
| 内购支付 | `Runtime/GameApp.Payment.cs` | `ENABLE_GAME_FRAME_X_PAYMENT` |
| Mono 行为 | `Runtime/GameApp.Mono.cs` | `ENABLE_GAME_FRAME_X_MONO` |
| Web ProtoBuf | `Runtime/GameApp.Web.ProtoBuff.cs` | `ENABLE_GAME_FRAME_X_WEB_PROTO_BUFF` |

> 命名上有一个特例:GUI 子系统的宏是 `ENABLE_GAME_FRAME_X_L_UGUI`(带 `L_` 前缀),而不是 `ENABLE_GAME_FRAME_X_GUI`,按表中的宏名原样添加即可。

### 2. 在 Scripting Define Symbols 里添加缺失的宏

打开 `Edit → Project Settings → Player`,在 *Other Settings → Configuration → Scripting Define Symbols* 中,把上一步查到的宏加进去。多个宏之间用分号 `;` 分隔。

```text
ENABLE_GAME_FRAME_X_NETWORK;ENABLE_GAME_FRAME_X_L_UGUI;ENABLE_GAME_FRAME_X_ENTITY
```

添加后回到 IDE 触发一次脚本重新编译(`Assets → Reimport` 或重启 Editor),IDE 标红会消失。

### 3. 确认对应的 Runtime 包已经装好

宏只是开关,真正的类型(如 `NetworkComponent`、`UGUIComponent`)来自各子模块的 Runtime 程序集。下面这段就是宏开启后才参与编译的 `GameApp.Network.cs`,可见它依赖 `GameFrameX.Network.Runtime`:

```csharp
#if ENABLE_GAME_FRAME_X_NETWORK
using GameFrameX.Network.Runtime;
using GameFrameX.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// 获取网络组件。
    /// </summary>
    public static NetworkComponent Network
    {
        get
        {
            if (_network == null)
            {
                _network = GameEntry.GetComponent<NetworkComponent>();
            }

            return _network;
        }
    }

    private static NetworkComponent _network;
}
#endif
```

Source: [Runtime/GameApp.Network.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Network.cs#L32-L56)

GUI 子系统同理:

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
using GameFrameX.Runtime;
using GameFrameX.LUGUI.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// 获取UI组件。
    /// </summary>
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }

            return _gui;
        }
    }

    private static UGUIComponent _gui;
}
#endif
```

Source: [Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

如果加了宏仍提示找不到 `NetworkComponent` / `UGUIComponent` 等类型,说明对应的子模块包没有通过 UPM/Package Manager 安装,打开 `Window → Package Manager` 把对应包装上即可。

### 4. 启动时确认组件已注册到 `GameEntry`

`GameApp.XXX` 内部都是 `GameEntry.GetComponent<XXXComponent>()`,所以还需要在启动流程里注册过这个组件。如果 `GetComponent` 返回 `null`,在 `GameEntry` 的 `RegisterComponent` 调用链中补上对应组件即可。

## 验证

1. IDE 中 `GameApp.Network`、`GameApp.GUI` 等属性不再标红。
2. 运行时调用 `GameApp.Network` 不再返回 `null`,方法调用不再抛 `NullReferenceException`。
3. 在不同目标平台(Editor、iOS、Android)之间切换编译,所用子系统在每个平台都可用。
