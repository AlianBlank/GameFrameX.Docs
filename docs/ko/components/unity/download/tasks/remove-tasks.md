# 단일 또는 일괄 다운로드 작업 제거

`DownloadComponent`에서 제공하는 세 가지 제거 인터페이스를 통해 일련 번호로 단일 작업을 제거하거나, 태그를 기준으로 일괄 제거하거나, 모든 작업을 한 번에 비울 수 있습니다.

## 사전 조건

- `GameFrameX` 프레임워크가 초기화되어 있고, `GameEntry.GetComponent<DownloadComponent>()`를 통해 컴포넌트를 가져온 상태여야 합니다.
- 최소 하나 이상의 다운로드 작업이 존재해야 합니다(`AddDownload`가 `serialId`를 반환한 상태).

## 작업 단계

### 1. 일련 번호로 단일 작업 제거

`AddDownload`가 반환한 `serialId`를 전달하면, 작업이 존재할 경우 `true`를, 그렇지 않으면 `false`를 반환합니다. 컴포넌트 계층에서는 동시에 해당 대기 핸들(`TCS`)도 취소합니다.

```csharp
using GameFrameX.Download.Runtime;

DownloadComponent downloadComponent = GameEntry.GetComponent<DownloadComponent>();
int serialId = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/file.bin",
    downloadUri: "https://example.com/file.bin",
    tag: "update"
);

bool removed = downloadComponent.RemoveDownload(serialId);
```

출처: [DownloadComponent.cs#L387-L400](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L387-L400)

### 2. 태그로 작업 일괄 제거

`tag`를 전달하면 해당 태그와 일치하는 모든 작업이 제거되며, 제거된 작업 수를 반환합니다.

```csharp
int removedCount = downloadComponent.RemoveDownloads("update");
```

구현 내부에서는 먼저 컴포넌트 딕셔너리에서 태그에 해당하는 `serialId`를 수집하고, 각각의 `TCS`를 취소한 뒤, 하위 `DownloadManager`에 제거를 위임합니다.

출처: [DownloadComponent.cs#L402-L427](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L402-L427)

### 3. 모든 작업 제거

컴포넌트 딕셔너리에 저장된 전체 작업을 비우고, `DownloadManager` 작업 풀의 모든 작업을 제거하며, 제거된 수량을 반환합니다.

```csharp
int total = downloadComponent.RemoveAllDownloads();
```

출처: [DownloadComponent.cs#L429-L442](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L429-L442)

하위 계층은 최종적으로 모두 `DownloadManager`에 위임되며, 해당 구현은 다음과 같습니다:

```csharp
public bool RemoveDownload(int serialId) { return m_TaskPool.RemoveTask(serialId); }
public int RemoveDownloads(string tag)   { return m_TaskPool.RemoveTasks(tag); }
public int RemoveAllDownloads()          { return m_TaskPool.RemoveAllTasks(); }
```

출처: [DownloadManager.cs#L380-L407](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L380-L407)

인터페이스 시그니처 정의:

## 일반적인 변형

| 시나리오 | 권장 API | 반환 값 |
|------|---------|--------|
| 특정 다운로드 하나 취소 | `RemoveDownload(serialId)` | `bool`, 존재 여부 |
| 특정 유형의 다운로드 취소(동일 tag) | `RemoveDownloads(tag)` | 제거 수량 |
| 사용자 로그아웃 또는 씬 전환 시 큐 비우기 | `RemoveAllDownloads()` | 제거 수량 |

## 흔한 실수

- **`serialId` 저장 누락**: `AddDownload`는 비동기 진입점이므로 반드시 반환 값을 보관해야 합니다. 그렇지 않으면 tag를 통한 일괄 제거만 가능합니다.
- **존재하지 않는 `serialId`로 `RemoveDownload` 호출**: `false`를 반환하며 예외가 발생하지 않으므로, 이를 통해 작업이 아직 큐에 남아 있는지 판단할 수 있습니다.
- **다운로드 진행 중 작업 제거**: 작업은 취소되어 풀에서 삭제되지만, 이미 디스크에 기록된 일부 바이트는 자동으로 롤백되지 않습니다. 원자성을 보장해야 하는 경우 `DownloadSuccess` 이벤트 콜백에서 검증을 완료한 후 정리하십시오.
