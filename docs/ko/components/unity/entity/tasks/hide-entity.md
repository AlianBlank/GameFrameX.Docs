# 엔티티 숨기기 및 회수 방법

`EntityManager`의 숨기기 인터페이스를 호출하면 엔티티가 "숨김" 상태로 전환되며, 프레임워크가 자동으로 인스턴스 객체를 회수하고 엔티티 그룹의 점유를 해제하며, 숨기기 완료 후 `HideEntityCompleteEventArgs` 이벤트를 트리거합니다. 숨기기는 구성 데이터를 파괴하지 않으므로 언제든지 `ShowEntity`를 통해 다시 표시할 수 있습니다.

## 전제 조건

- `EntityComponent`를 통해 엔티티 관리자를 초기화하고 엔티티 그룹 등록을 완료했습니다.
- 숨길 엔티티 번호(`int entityId`) 또는 `IEntity` 참조를 보유하고 있습니다.

## 작업 단계

1. 엔티티 컴포넌트를 통해 `IEntityManager`를 가져옵니다:

```csharp
IEntityManager entityManager = GameEntry.GetComponent<EntityComponent>().EntityManager;
```

2. 엔티티 번호로 숨기기(가장 일반적으로 사용됨):

```csharp
// userData를 전달하지 않음
entityManager.HideEntity(entityId);

// 비즈니스 컨텍스트 전달
entityManager.HideEntity(entityId, userData);
```

구현은 먼저 해당 엔티티가 여전히 로드 대기열에 있는지 판단합니다. 여전히 로드 중(`IsLoadingEntity`가 참)이라면, 엔티티를 `m_EntitiesToReleaseOnLoad`에 추가하고 로드 콜백에서 회수합니다. 그렇지 않으면 `m_EntityInfos`에서 `EntityInfo`를 가져와 `InternalHideEntity`를 호출하여 숨기기를 완료합니다.

Source: [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L46-L72)

3. `IEntity` 참조를 직접 전달할 수도 있습니다:

```csharp
entityManager.HideEntity(entity);
entityManager.HideEntity(entity, userData);
```

참조가 `null`이면 `GameFrameworkException("Entity is invalid.")`이 발생합니다.

Source: [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L78-L96)

4. 일괄 숨기기(장면 전환 및 레벨 종료 시 일반적으로 사용됨):

```csharp
// 로드된 모든 엔티티 숨기기
entityManager.HideAllLoadedEntities(userData);

// 로드 중인 모든 엔티티 숨기기(완료되지 않은 로드 취소)
entityManager.HideAllLoadingEntities();
```

`HideAllLoadedEntities`는 현재 `m_EntityInfos`의 키를 복사한 다음 하나씩 `InternalHideEntity`를 호출하여 컬렉션을 순회 중 수정하는 것을 방지합니다. `HideAllLoadingEntities`는 여전히 로드 중인 모든 엔티티 번호를 회수 대기 컬렉션에 추가하고 로드 대기열을 비웁니다.

Source: [EntityManager.Hide.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Hide.cs#L101-L135)

5. 숨기기 완료 이벤트를 수신 대기하여 콜백에서 사용자 지정 리소스를 회수합니다(선택 사항):

```csharp
EventComponent.Subscribe(HideEntityCompleteEventArgs.EventId, (sender, args) =>
{
    var e = (HideEntityCompleteEventArgs)args;
    // e.EntityId / e.EntityAssetName 사용 가능
    // 여기에서 해당 엔티티 전용 텍스처, AudioClip 등을 해제
});
```

`HideEntityCompleteEventArgs`는 `GameFrameXEntityCroppingHelper`에서 참조되는 런타임 타입이며, 프레임워크는 `InternalHideEntity` 끝부분에서 이를 게시합니다.

Source: [GameFrameXEntityCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/GameFrameXEntityCroppingHelper.cs#L1-L20)

## 일반적인 변형

- **숨기면서 부모-자식 관계 해제**: 먼저 `DetachEntity(childEntityId, userData)` 또는 `DetachChildEntities(parentEntityId, userData)`를 호출한 다음 `HideEntity`를 호출합니다. `DetachEntity`는 부모 엔티티에서 `OnDetached`를 호출하고, 자식 엔티티에서 `OnDetachFrom`을 호출한 다음에만 숨기기 프로세스를 진행합니다.
- **사용자 데이터 포함**: 모든 `HideEntity` / `HideAllLoadedEntities` / `DetachEntity`에는 `object userData` 오버로드가 있어 비즈니스 컨텍스트를 `IEntity.OnHide` 및 이벤트 매개변수로 투명하게 전달하는 데 사용됩니다.
- **숨긴 후 다시 표시**: `HideEntity`는 엔티티를 숨김 상태로 설정하고 인스턴스만 회수하며, `EntityInfo`는 여전히 유지됩니다. 다시 `ShowEntity(entityId, ...)`를 호출하면 재사용할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 수정 |
|------|------|------|
| `Log.Error("Can not find entity '{0}'.")` | `entityId`가 등록되지 않았거나 이미 숨겨졌습니다 | 호출 전에 엔티티가 `WillShow` / `Show` 상태인지 확인 |
| `GameFrameworkException: Entity is invalid.` | `null`인 `IEntity`를 전달했습니다 | `HideEntity(entityId, ...)`를 사용하거나 먼저 null 참조 검사를 수행 |
| 숨긴 후에도 엔티티가 여전히 장면에 있습니다 | `HideEntity`만 호출하고 `HideEntityCompleteEventArgs`를 수신 대기하지 않아 사용자 지정 로직이 트리거되지 않았습니다 | 이벤트 콜백에서 자체 보유한 리소스 해제를 실행하거나 `EntityGroupHelper.ReleaseEntity`가 자동으로 회수했는지 확인 |

## 관련 링크

- `ShowEntity` 및 엔티티 라이프사이클에 대해서는 《엔티티 표시 및 생성 방법》을 참조하세요.
- 엔티티 그룹 및 `IEntityGroup`에 대해서는 《엔티티 그룹 및 엔티티 그룹화 관리》를 참조하세요.
- 엔티티 이벤트 구독의 일반적인 프로세스에 대해서는 《이벤트 시스템 사용 안내》를 참조하세요.

## 배경(선택 사항)

`HideEntity`의 회수는 두 부분으로 구성됩니다: 프레임워크 계층은 `InternalHideEntity`에서 `EntityInfo.Status`를 숨김 상태로 전환하고, `EntityGroupHelper.ReleaseEntity`를 호출하여 객체 풀을 반환하며, `HideEntityCompleteEventArgs`를 게시합니다. 비즈니스 계층은 이벤트 콜백에서 전용 리소스를 해제합니다. 이 두 부분이 함께 작동하면 구성을 파괴하지 않고도 엔티티 인스턴스를 회수할 수 있습니다.
