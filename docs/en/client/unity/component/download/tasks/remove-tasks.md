# Removing Download Tasks Individually or in Batch

Through the three removal interfaces provided by `DownloadComponent`, you can remove a single task by serial ID, remove tasks in batch by tag, or clear all tasks at once.

## Prerequisites

- The `GameFrameX` framework has been initialized, and the component has been obtained via `GameEntry.GetComponent<DownloadComponent>()`.
- At least one download task already exists (`AddDownload` has returned a `serialId`).

## Steps

### 1. Remove a Single Task by Serial ID

Pass in the `serialId` returned by `AddDownload`; it returns `true` if the task exists, otherwise `false`. The component layer also cancels the corresponding await handle (`TCS`).

```csharp
using GameFrameX.Download.Runtime;

DownloadComponent downloadComponent = GameEntry.GetComponent<DownloadComponent>();
int serialId = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/file.bin",
    downloadUri: "https://example.com/file.bin",
    tag: "update"
);

bool removed = downloadComponent.RemoveDownload(serialId);
```

Source: [DownloadComponent.cs#L387-L400](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L387-L400)

### 2. Batch Remove Tasks by Tag

Pass in a `tag`; all tasks matching the tag will be removed, and the number of removed tasks is returned.

```csharp
int removedCount = downloadComponent.RemoveDownloads("update");
```

The implementation first collects the `serialId`s by tag from the component dictionary, cancels each `TCS` one by one, and then hands them off to the underlying `DownloadManager` for removal.

Source: [DownloadComponent.cs#L402-L427](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L402-L427)

### 3. Remove All Tasks

Clears all tasks stored in the component dictionary and removes all tasks in the `DownloadManager` task pool, returning the number of removed tasks.

```csharp
int total = downloadComponent.RemoveAllDownloads();
```

Source: [DownloadComponent.cs#L429-L442](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L429-L442)

At the lower level, all of these are ultimately delegated to `DownloadManager`, with the corresponding implementation:

```csharp
public bool RemoveDownload(int serialId) { return m_TaskPool.RemoveTask(serialId); }
public int RemoveDownloads(string tag)   { return m_TaskPool.RemoveTasks(tag); }
public int RemoveAllDownloads()          { return m_TaskPool.RemoveAllTasks(); }
```

## Common Variants

| Scenario | Recommended API | Return Value |
|------|---------|--------|
| Cancel a specific download | `RemoveDownload(serialId)` | `bool`, whether the task exists |
| Cancel a category of downloads (same tag) | `RemoveDownloads(tag)` | Number of removed tasks |
| Clear the queue when the user logs out or switches scenes | `RemoveAllDownloads()` | Number of removed tasks |

## Common Errors

- **Forgetting to save the `serialId`**: `AddDownload` is an async entry point; be sure to keep the return value, otherwise you can only remove tasks in batch by tag.
- **Calling `RemoveDownload` with a non-existent `serialId`**: It returns `false` without throwing an exception; you can use this to check whether the task is still in the queue.
- **Removing a task while it is downloading**: The task will be canceled and removed from the pool, but the bytes already written to disk will not be automatically rolled back. If atomicity is required, clean up after verification is completed in the `DownloadSuccess` event callback.
