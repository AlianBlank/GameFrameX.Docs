# SetActiveScene 抛 ArgumentException 怎么办

调用 `SetActiveScene` 时如果传入的 `Scene` 还未真正被 Unity 加载完成，Unity 会抛出 `ArgumentException`。本框架已经在内部捕获并降级处理（仅记一条 `Warning`），但订阅者或自定义代码仍可能踩到同样的根因。下面给出定位和修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志出现 `SetActiveScene failed (will be retried by Unity internally): Scene ... is not loaded.` | `Scene.isLoaded` 仍为 `false` 时调用了 `SetActiveScene`（典型场景：YooAsset 的 `await` 完成时机早于 Unity 真正加载完） | 等场景真正 `isLoaded == true` 再激活，见下方「等待 isLoaded」 |
| 激活的是缓存的 `m_GameFrameworkScene` 句柄，但该场景已被 Unity 卸载 | 第一次 Single 加载后框架场景被卸载，缓存句柄 `IsValid()` 为 `false` | 重新 `GetSceneByName` 取句柄再激活，见下方「句柄失效」 |
| 控制台抛 `ArgumentException: SceneManager.SetActiveScene ... is not loaded` | 自定义代码直接在 `SceneManager` 上调用，绕过了框架的 try/catch | 用框架入口或自己加防御，见下方「绕过框架直接调用」 |
| 连续切换场景时新旧协程互相争抢 `SetActiveScene` | 上一次刷新协程未停掉，新的又启动 | 启动新协程前先 `StopCoroutine`，见下方「协程冲突」 |

## 修复步骤

### 等待 isLoaded

框架在 `SceneComponent.SetActiveScene` 处已经 try/catch 住了 `ArgumentException`，但你自己监听 `LoadSceneSuccess` 事件后的回调里仍可能遇到。确认目标场景 `isLoaded` 后再设置：

```csharp
var scene = UnityEngine.SceneManagement.SceneManager.GetSceneByName(sceneName);
if (scene.IsValid() && scene.isLoaded)
{
    UnityEngine.SceneManagement.SceneManager.SetActiveScene(scene);
}
```

如果当前帧还没 `isLoaded`，用协程延迟到下一帧再试，直到超时回退到框架场景——参考 [SceneComponent.cs#L480-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L480-L509) 的 `RefreshSceneOrderWhenLoadedCo` 实现。

### 句柄失效

缓存的 `Scene` 句柄在 `Single` 模式下会随旧场景一起被 Unity 卸载。框架在 [SceneComponent.cs#L449-L457](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L449-L457) 用 `IsValid()` 防御：

```csharp
if (!activeScene.IsValid())
{
    // 句柄过期时跳过设置，Unity 自己会在新 Single 场景加载完成后激活它
    RefreshMainCamera();
    return;
}
```

自己的代码里要复用 `Scene` 句柄时，调用前同样校验 `IsValid()`，否则就需要重新 `GetSceneByName`。

### 绕过框架直接调用

不要在订阅者回调里直接调 `UnityEngine.SceneManagement.SceneManager.SetActiveScene`，绕过了框架的异常吞咽逻辑。优先用框架入口 `GameSceneComponent.SetActiveScene` 之类的方法；如果一定要在事件回调里切激活场景，自己包一层 try/catch 并按上面「等待 isLoaded」的判断走。

### 协程冲突

多次连续切换场景时，如果不先停掉上一轮刷新协程，新旧协程会在同一帧里争抢 `SetActiveScene`，触发 `ArgumentException`。框架的修复模式见 [SceneComponent.cs#L430-L435](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L430-L435)：

```csharp
if (m_RefreshSceneOrderCo != null)
{
    StopCoroutine(m_RefreshSceneOrderCo);
    m_RefreshSceneOrderCo = null;
}
m_RefreshSceneOrderCo = StartCoroutine(RefreshSceneOrderWhenLoadedCo(maxSceneName));
```

`finally` 块里记得把句柄置 `null`（见 [SceneComponent.cs#L505-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L505-L509)），避免下次 `RefreshSceneOrder` 误判旧协程还在运行。

## 验证

- 日志里不再出现 `ArgumentException: SceneManager.SetActiveScene ... is not loaded`。
- `SceneManager.GetActiveScene()` 在加载回调返回时等于目标场景。
- 连续触发两次切换场景，控制台没有 `SetActiveScene failed` 警告。
