# How to Define Custom Event Arguments

To define custom event arguments, simply create a new class inheriting from `GameEventArgs`, override `Id` and `Clear()`, and provide a static `Create` factory method that creates instances via `ReferencePool.Acquire<T>()`. You can then subscribe to and fire the event through `EventComponent`.

## Prerequisites

- The GameFrameX Event package is installed in the project, and an `EventComponent` component exists in the scene (menu `GameFrameX/Event`, automatically attached when the framework starts).
- Reference the namespaces `GameFrameX.Event.Runtime` and `GameFrameX.Runtime`.

## Steps

1. Create a new event argument class inheriting from `GameEventArgs` (it is an abstract subclass of `BaseEventArgs` and carries the `Preserve` attribute to prevent code stripping):

```csharp
using GameFrameX.Runtime;

namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// Base class for game logic events.
    /// </summary>
    [UnityEngine.Scriptivity.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L30-L41)

2. Implement your event arguments following the pattern of the framework's built-in `EmptyEventArgs`: override `Id` to return the event ID, override `Clear()` to reset fields, and provide a static `Create` method that acquires an object from the reference pool. The `PlayerLevelUpEventArgs` below is a custom example written in the same pattern:

```csharp
using GameFrameX.Runtime;

namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// Player level-up event arguments
    /// </summary>
    public sealed class PlayerLevelUpEventArgs : GameEventArgs
    {
        public int OldLevel { get; private set; }
        public int NewLevel { get; private set; }

        /// <summary>
        /// Event ID; defaults to the full type name. Use the same string when subscribing and firing
        /// </summary>
        public override string Id
        {
            get { return typeof(PlayerLevelUpEventArgs).FullName; }
        }

        /// <summary>
        /// Called when the reference pool recycles the instance; all fields must be restored to their default values
        /// </summary>
        public override void Clear()
        {
            OldLevel = 0;
            NewLevel = 0;
        }

        /// <summary>
        /// Creates the event arguments, acquiring an instance from the reference pool
        /// </summary>
        public static PlayerLevelUpEventArgs Create(int oldLevel, int newLevel)
        {
            var eventArgs = ReferencePool.Acquire<PlayerLevelUpEventArgs>();
            eventArgs.OldLevel = oldLevel;
            eventArgs.NewLevel = newLevel;
            return eventArgs;
        }
    }
}
```

The original framework implementation referenced above is as follows; the `Id`, `Clear()`, and `Create` trio and the usage of `ReferencePool.Acquire<T>()` should all follow it:

```csharp
public sealed class EmptyEventArgs : GameEventArgs
{
    private string _eventId = typeof(EmptyEventArgs).FullName;

    public override void Clear()
    {
        _eventId = typeof(EmptyEventArgs).FullName;
    }

    public override string Id
    {
        get { return _eventId; }
    }

    public static EmptyEventArgs Create(string eventId)
    {
        var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
        eventArgs.SetEventId(eventId);
        return eventArgs;
    }

    private void SetEventId(string eventId)
    {
        _eventId = eventId;
    }
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L7-L49)

3. Subscribe to the event. `EventComponent`'s public subscription entry point is `CheckSubscribe` (only subscribes if not already subscribed, avoiding duplicate subscriptions):

```csharp
// Signature: public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
EventComponent.CheckSubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);

private void OnPlayerLevelUp(object sender, GameEventArgs e)
{
    var args = (PlayerLevelUpEventArgs)e;
    Debug.Log($"Level up: {args.OldLevel} -> {args.NewLevel}");
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L100-L111)

4. Fire the event. `Fire` is thread-safe and dispatches on the next frame; `FireNow` dispatches immediately but is not thread-safe:

```csharp
// Signature: public void Fire(object sender, GameEventArgs e)
EventComponent.Fire(this, PlayerLevelUpEventArgs.Create(10, 11));

// Signature: public void FireNow(object sender, GameEventArgs e)
EventComponent.FireNow(this, PlayerLevelUpEventArgs.Create(10, 11));
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L171)

5. Unsubscribe when it is no longer needed; the event ID must exactly match the one used when subscribing:

```csharp
// Signature: public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
EventComponent.Unsubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);

// Use the safe version when the handler may not be subscribed; it does nothing if the subscription does not exist
EventComponent.CheckUnsubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L113-L131)

## Common Variants

- **Events without data**: No need to create a new class; just use the framework's built-in `EmptyEventArgs`. `EventComponent` provides a convenient overload `Fire(object sender, string eventId)` that internally calls `EmptyEventArgs.Create(eventId)` automatically; passing `null` or an empty string as `eventId` triggers argument validation:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

- **Custom event ID strings**: If you don't want to use `typeof(X).FullName`, you can store the ID in a private field `_eventId` like `EmptyEventArgs` does, passed in via `Create(eventId)`, allowing a single class to carry multiple logical events.

## Common Mistakes

| Symptom | Cause | Fix |
|---------|-------|-----|
| No callbacks at all after firing the event | The `Id` string used for subscribing differs from the one used for firing | Use `typeof(PlayerLevelUpEventArgs).FullName` consistently in both places |
| Event callback reads stale data | `Clear()` did not reset all fields, leaving old values behind after the instance was reused by the reference pool | Reset all fields in `Clear()` |
| Duplicate callbacks executed multiple times in the same frame | The same handler was subscribed multiple times via `Subscribe` | Use `CheckSubscribe` instead, which checks first and then subscribes |
| Callbacks still fire after the object is destroyed, throwing null references | Forgot to call `Unsubscribe` | Call `Unsubscribe` or `CheckUnsubscribe` in `OnDestroy` |
| Custom argument class gets stripped by code stripping | The class is not preserved | Add `[UnityEngine.Scripting.Preserve]`, consistent with `GameEventArgs` |

## Background

Event argument instances come from the `ReferencePool` reference pool (`ReferencePool.Acquire<T>()`) and are recycled for reuse after being fired and dispatched, which is why `Clear()` must restore fields to their default values; this is also why all event arguments are created through the static `Create` method rather than with `new`. Event dispatching and threading semantics are managed by `IEventManager`; `Fire` guarantees that callbacks occur on the main thread.
