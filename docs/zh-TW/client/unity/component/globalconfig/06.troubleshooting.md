# 常見問題

本文件彙總了使用 GlobalConfig 組件過程中可能遇到的常見問題及解決方案。

## 概述

GlobalConfigComponent 是 GameFrameX 框架中的全域性配置管理組件，主要用於管理遊戲應用的全域性配置資訊，包括應用版本檢查地址、資源版本檢查地址、伺服器地址等。該組件採用 Unity 組件的形式實現，可以靈活地配置和使用。

> 組件的詳細功能說明請參考 [GlobalConfig 組件簡介](./1-overview.1-introduction)。
> 組件的完整 API 請參考 [GlobalConfigComponent](./4-core-component.1-global-config-component)。

## 安裝與設定

### Q1: 如何安裝 GlobalConfig 組件？

GlobalConfig 組件可以透過以下方式安裝：

1. **透過 manifest.json 安裝**：在專案的 `manifest.json` 檔案中新增依賴：
   ```json
   {"com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git"}
   ```

2. **透過 Unity Package Manager**：在 Unity 中選擇 `Window > Package Manager`，然後點選 `+` 號新增 Git URL：
   ```
   https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git
   ```

3. **手動安裝**：直接下載倉庫並放置到 Unity 專案的 `Packages` 目錄下。

> 詳細的安裝步驟請參考 [安裝方式](./2-installation.1-install-methods)。

### Q2: 安裝後報 "Assembly has reference to missing assembly" 錯誤？

這是因為 GlobalConfig 組件依賴以下包：
- `com.gameframex.unity` (版本 1.1.1)
- `com.gameframex.unity.web` (版本 1.1.2)

**解決方案**：確保這些依賴包已正確安裝。可以在 `manifest.json` 中新增完整依賴：

```json
{
  "dependencies": {
    "com.gameframex.unity": "1.1.1",
    "com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git",
    "com.gameframex.unity.web": "1.1.2"
  }
}
```

### Q3: Unity 版本相容性如何？

根據 package.json，組件支援的最低 Unity 版本為 **2017.1**。如果使用更低版本的 Unity，可能會出現相容性問題。

## 組件使用

### Q4: 如何將 GlobalConfigComponent 新增到場景？

1. 在 Unity 編輯器中，建立或選擇一個 GameObject
2. 在 Inspector 面板中，點選 **Add Component** 按鈕
3. 搜尋並選擇 **Game Framework > Global Config**
4. 組件將新增到選定的 GameObject 上

> 詳細的新增步驟請參考 [新增到場景](./3-getting-started.1-add-to-scene)。

### Q5: 可以在場景中新增多個 GlobalConfigComponent 嗎？

**不建議**。組件使用了 `[DisallowMultipleComponent]` 特性，這限制了同一 GameObject 上只能新增一個例項。雖然技術上可以將組件新增到不同的 GameObject，但框架設計為單例模式，建議只在場景中保留一個全域性配置組件。

### Q6: 如何在程式碼中訪問 GlobalConfigComponent？

由於組件使用了 `IsAutoRegister = false`，組件不會自動註冊。典型的訪問方式是在場景中查詢或透過引用訪問：

```csharp
// 透過 FindObjectOfType 查詢
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
if (globalConfig != null)
{
    string appVersionUrl = globalConfig.CheckAppVersionUrl;
    string resourceVersionUrl = globalConfig.CheckResourceVersionUrl;
}
```

> 詳細的程式碼訪問方式請參考 [程式碼訪問](./3-getting-started.3-code-access)。

### Q7: 如何透過程式碼動態設定配置？

可以在執行時透過程式碼設定各個屬性：

```csharp
var globalConfig = FindObjectOfType<GlobalConfigComponent>();

// 設定各種 URL
globalConfig.CheckAppVersionUrl = "https://example.com/check-app-version";
globalConfig.CheckResourceVersionUrl = "https://example.com/check-resource-version";
globalConfig.HostServerUrl = "https://example.com/server";

// 設定附加內容
globalConfig.Content = "{\"key\": \"value\"}";

// 設定全域性配置資訊
ResponseGlobalInfo globalInfo = new ResponseGlobalInfo
{
    // 配置屬性
};
globalConfig.SetGlobalConfig(globalInfo);
```

## 屬性配置

### Q8: 各個屬性有什麼作用？

| 屬性 | 說明 |
|------|------|
| **主機服務地址 (HostServerUrl)** | 後端伺服器的地址，用於連線遊戲伺服器 |
| **檢測App版本地址介面 (CheckAppVersionUrl)** | 檢查應用程式新版本的 URL 地址 |
| **檢測資源版本地址介面 (CheckResourceVersionUrl)** | 檢查遊戲資源更新的 URL 地址 |
| **補充程式集列表 (AOTCodeList)** | AOT 編譯時需要補充的程式集列表（JSON 格式） |
| **附加內容 (Content)** | 其他附加的配置內容 |
| **補充後設資料列表 (AOTCodeLists)** | AOT 補充後設資料列表 |

> 詳細的屬性配置說明請參考 [配置屬性](./3-getting-started.2-configure-properties)。

### Q9: AOTCodeList 和 AOTCodeLists 有什麼區別？

- **AOTCodeList** (字串型別)：用於在 Inspector 中以 JSON 字串格式輸入 AOT 程式碼列表
- **AOTCodeLists** (列表型別)：解析後的 AOT 程式碼列表，供執行時使用

設定 AOTCodeList 時，系統會自動解析 JSON 並填充到 AOTCodeLists：

```csharp
// 設定 JSON 格式的 AOT 程式碼列表
globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\", \"Assembly3\"]";

// 自動解析，可以在 AOTCodeLists 中獲取解析結果
List<string> aotCodeLists = globalConfig.AOTCodeLists;
```

## AOT 配置相關

### Q10: 什麼是 AOT 程式碼列表？為什麼要配置它？

AOT (Ahead-of-Time) 編譯是 .NET 的一種編譯模式，主要用於 IL2CPP 等平臺。某些泛型型別和反射程式碼在 AOT 編譯時可能無法正確生成，需要透過 AOT 程式碼列表來指定需要額外處理的程式集。

> 詳細的 AOT 配置說明請參考 [AOT 程式碼列表配置](./7-aot-configuration.1-aot-code-list)。

### Q11: 設定 AOTCodeList 時出現 JSON 解析錯誤？

如果在設定 AOTCodeList 時遇到解析錯誤，可能的原因和解決方案：

1. **JSON 格式錯誤**：確保 JSON 格式正確
   ```csharp
   // 錯誤示例
   globalConfig.AOTCodeList = "Assembly1, Assembly2"; // 錯誤的格式

   // 正確示例
   globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\"]"; // 正確的 JSON 陣列格式
   ```

2. **特殊字元轉義**：如果字串中包含特殊字元，確保正確轉義

### Q12: AOT 程式碼列表為空會導致什麼問題？

如果 AOT 程式碼列表為空，某些使用泛型或反射的功能可能在 IL2CPP 平臺上無法正常工作。具體表現包括：
- 泛型型別序列化失敗
- 反射獲取型別失敗
- 某些動態程式碼執行異常

## 編輯器相關

### Q13: 在 Play 模式下無法編輯屬性？

這是正常行為。Inspector 中的屬性在 **Play 模式**下是隻讀的，這是為了保護執行時配置不被意外修改。

```csharp
// GlobalConfigComponentInspector.cs 中的實現
EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode & Application.isPlaying);
{
    // 屬性編輯區域
}
EditorGUI.EndDisabledGroup();
```

### Q14: 原始資料 (OriginalData) 是隻讀的？

是的，原始資料屬性在 Inspector 中是隻讀的。該屬性用於儲存從伺服器獲取的原始配置資料，通常在執行時透過程式碼設定：

```csharp
// 設定原始資料
globalConfig.SetOriginalData(jsonString);

// 讀取原始資料
string originalData = globalConfig.OriginalData;
```

## 執行時相關

### Q15: 組件的 Awake 方法有什麼特殊處理？

組件重寫了 `Awake` 方法，並將 `IsAutoRegister` 設定為 `false`：

```csharp
protected override void Awake()
{
    IsAutoRegister = false;
    base.Awake();
}
```

這意味著組件不會自動註冊到框架的組件管理系統中，需要開發者手動管理或透過其他方式訪問。

### Q16: 如何從伺服器獲取並設定全域性配置？

典型的工作流程如下：

1. 使用配置的 URL 向伺服器傳送請求
2. 伺服器返回配置資料（JSON 格式）
3. 解析響應資料到 ResponseGlobalInfo 物件
4. 呼叫 SetGlobalConfig 設定全域性配置

```csharp
// 虛擬碼示例
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
string url = globalConfig.HostServerUrl;

// 傳送網路請求獲取配置
// ...
ResponseGlobalInfo response = ParseServerResponse(data);
globalConfig.SetGlobalConfig(response);

// 訪問配置資訊
ResponseGlobalInfo info = globalConfig.GlobalInfo;
```

## 故障排查

### Q19: 常見問題排查步驟

1. **檢查依賴**：確認所有依賴包已正確安裝
2. **檢查 Unity 版本**：確保使用 Unity 2017.1 或更高版本
3. **檢查組件新增**：確認 GlobalConfigComponent 已正確新增到場景
4. **檢查屬性配置**：確認必要的 URL 屬性已配置
5. **檢視日誌**：檢查 Unity 控制檯是否有錯誤或警告資訊

### Q20: 執行時找不到 GlobalConfigComponent？

如果 `FindObjectOfType<GlobalConfigComponent>()` 返回 null，可能原因：
1. 組件未新增到任何 GameObject
2. 組件新增到了未啟用的 GameObject
3. 場景未正確載入

**解決方案**：
- 確認組件已新增到場景中的活動 GameObject
- 確保 GlobalConfig 所在的場景已被載入

## 配置檔案為空或未載入

**原因**：未在 Inspector 中配置 GlobalConfigComponent 或配置檔案路徑不正確。

**解決方案**：在 Unity 編輯器中選中掛載 GlobalConfigComponent 的 GameObject，在 Inspector 面板中檢查配置項是否已正確填寫。

## 版本檢查 URL 無法訪問

**原因**：伺服器地址配置錯誤或網路不可達。

**解決方案**：檢查 `AppVersionCheckUrl` 和 `ResourceVersionCheckUrl` 是否為有效的 HTTP/HTTPS 地址，確保裝置網路連通。
