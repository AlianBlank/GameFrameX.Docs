# 設定の読み込みが失敗した場合の対処法

`SettingComponent.Start()` の中で `m_SettingManager.Load()` が `false` を返したとき、コンソールに `Load settings failure.` が出力されます。これは設定読み込みフローの失敗を意味します。このページでは、失敗の原因をすばやく特定して修正する方法を説明します。

## クイック診断

| 症状（原文ログ） | 原因 | 修正 |
|------|------|------|
| `Setting manager is invalid.` | `ISettingManager` モジュールが登録されていない、または GameFramework が起動していない | [モジュール未登録](#モジュール未登録-setting-manager-is-invalid) を参照 |
| `Can not create setting helper.` | `SettingHelper` の型名設定ミス、アセンブリがランタイムに含まれていない、またはカスタム Helper クラスが見つからない | [Helper 作成失敗](#helper-作成失敗-can-not-create-setting-helper) を参照 |
| `Load settings failure.` | `ISettingHelper.Load()` の実装が `false` を返した（読み込み / デシリアライズ失敗） | [Load 実装が false を返す](#load-実装が-false-を返す-load-settings-failure) を参照 |
| `Setting helper is invalid.` 例外 | `Load()` / `Save()` を呼び出す前に `SetSettingHelper()` を呼び出していない | [Helper 未設定で例外発生](#helper-未設定で例外発生-setting-helper-is-invalid) を参照 |
| プラットフォームのミニゲーム用ストレージにデータがない | PlayerPrefs / ミニゲームのストレージバックエンドが空で、読み込む内容がない | [ストレージバックエンドが空](#ストレージバックエンドが空) を参照 |

## モジュール未登録（Setting manager is invalid）

`SettingComponent.Awake()` は `GameFrameworkEntry.GetModule<ISettingManager>()` でマネージャーを取得します。`null` が返った場合、`Setting manager is invalid.` が出力されて即時 return し、その後の `Start()` では Load は実行されません。

修正手順：

1. シーン内に `GameFrameX.Runtime.GameFrameworkEntry`（または同等の起動コンポーネント）が存在することを確認してください。フレームワークのエントリポイントは `SettingComponent` よりも先に起動している必要があります。
2. `SettingManager` モジュールがフレームワークのアセンブリリストに含まれていること（`Runtime/Setting/Setting/SettingManager.cs` にあり、名前空間は `GameFrameX.Setting.Runtime`）、パッケージ外に除外されていないことを確認してください。
3. カスタム GameFramework の起動フローを使用している場合、`SettingManager` を起動モジュールリストに追加する必要があります。

## Helper 作成失敗（Can not create setting helper）

`SettingComponent.Awake()` は `Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper)` を呼び出します。`null` が返ると `Can not create setting helper.` が出力されます。

```csharp
// 出典：Runtime/Setting/SettingComponent.cs#L87-L92
SettingHelperBase settingHelper = Helper.CreateHelper(m_SettingHelperTypeName, m_CustomSettingHelper);
if (settingHelper == null)
{
    Log.Error("Can not create setting helper.");
    return;
}
```

修正手順：

1. Inspector で `SettingComponent` の `Setting Helper Type Name` を確認してください。デフォルト値は `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` です。
2. カスタム Helper を使用している場合、カスタムクラスが `SettingHelperBase`（`Runtime/Setting/SettingHelperBase.cs#L43`）を継承していること、および完全修飾型名（名前空間を含む）のスペルが正しいことを確認してください。
3. カスタム Helper が存在するアセンブリが、Player / ミニゲームのランタイムビルドに含まれており、削除されていないことを確認してください。
4. `m_CustomSettingHelper` フィールドをインジェクトする場合は、Inspector にドラッグし、シーン内に `SettingComponent` が一つしかないことを確認してください。

## Load 実装が false を返す（Load settings failure）

Helper の作成は成功したが、`Load()` 内部が失敗した場合に `SettingComponent.Start()` が `Load settings failure.` を出力します：

```csharp
// 出典：Runtime/Setting/SettingComponent.cs#L102-L108
private void Start()
{
    if (!m_SettingManager.Load())
    {
        Log.Error("Load settings failure.");
    }
}
```

`SettingManager.Load()` は内部で現在の Helper に処理を委譲するだけです：

```csharp
// 出典：Runtime/Setting/Setting/SettingManager.cs#L145-L150
public bool Load()
{
    EnsureSettingHelper();
    return m_SettingHelper.Load();
}
```

Helper の種類ごとにそれぞれ対応してください：

- **PlayerPrefsSettingHelper**：`Load()` は常に `true` を返します（[出典](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L86-L89)）。もしこのエラーが表示される場合、まず実際に有効になっている Helper クラスがカスタム実装ではないことを確認してください。
- **カスタム Helper**：`Load()` 内でファイルの存在、読み込み権限、デシリアライズ例外を一つずつ確認してください。詳細なログを追加して失敗箇所を特定することをおすすめします。
- **ミニゲームプラットフォーム Helper**（WeChat / DouYin / KuaiShou / Alipay）：`SettingStorageBackendFactory.Create()` で `ISettingStorageBackend` を取得し、対応するプラットフォームマクロが定義されていること、および SDK が正しく組み込まれていることを確認してください。

## Helper 未設定で例外発生（Setting helper is invalid）

`SettingManager` で `SetSettingHelper()` を呼び出さずに `Load()` / `Save()` / `GetAllSettingNames()` を呼び出すと、`GameFrameworkException("Setting helper is invalid.")` が発生します：

```csharp
// 出典：Runtime/Setting/Setting/SettingManager.cs#L130
throw new GameFrameworkException("Setting helper is invalid.");
```

これは `SettingComponent` を介さずに直接 `SettingManager` を new した場合にのみ発生する可能性があります。修正方法：まず `SetSettingHelper(yourHelper)` を呼び出してから `Load()` を呼び出してください。あるいは `SettingComponent` を直接使用すれば、`Awake()` で自動的にインジェクトされます。

## ストレージバックエンドが空

`PlayerPrefsSettingHelper` は `SettingStorageBackendFactory.Create()` で `ISettingStorageBackend` を遅延読み込みします。ファクトリが `null` を返すか、プラットフォーム SDK が初期化されていない場合、`GetString` / `SetString` などの呼び出しで例外が発生し、それが `Load()` / `Save()` から `false` として透過されます。

修正手順：

1. 対応するプラットフォームマクロが有効になっているか確認してください（`UNITY_WEBGL`、ミニゲームプラットフォームのマクロなど）。
2. プラットフォーム SDK が `Awake()` / `Start()` よりも前に初期化されていることを確認してください。
3. `PlayerPrefsSettingHelper` の前にテスト用の `ISettingStorageBackend` をインジェクトしてください。`SetStorageBackendForTests(...)` の使い方を参照してください。

## 検証

修正が完了したら、以下の順序で確認してください：

1. ゲームを起動し、コンソールに `Load settings failure.` や上記で挙げたエラーログが表示されないこと。
2. `SettingComponent.GetAllSettingNames()` が正常に返ること（PlayerPrefs の実装は常に空配列を返しますが、これは想定動作です）。
3. `SettingComponent.Save()` を呼び出した後、ゲームを再起動し、`HasSetting(name)` / `GetString(name)` で以前書き込んだ値を読み戻せること。
4. それでも例外が発生する場合は、完全なスタック情報を残し、問題が `SettingHelperBase` から派生した具体的なクラス側にないことを確認してください。
