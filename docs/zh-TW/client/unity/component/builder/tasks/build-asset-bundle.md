# Asset Bundle 資源的打包方法

按照本頁的步驟，讓 GameFrameX 的建置器基於 [YooAsset](https://github.com/tuyoogame/YooAsset) 將專案資源打包為 Asset Bundle，並可依照設定控制是否啟用增量建置、上傳至物件儲存、版本通知與企業微信通知。

## 前置條件

- Unity 編輯器中已開啟目標專案，且已安裝本儲存庫的 `com.gameframex.unity.builder` 套件。
- 已安裝 `YooAsset` 與 `GameFrameX.Editor`（本套件的相依套件），且可從 `Builder.BuildAsset()` 呼叫 `EBuildPipeline`、`AssetBundleCollectorSettingData`、`AssetBundleBuilderSetting` 等型別。
- YooAsset 資源收集器（`AssetBundleCollectorSettingData`）已設定要收集的資源包（若未設定，迴圈將無法取得 `Packages`）。
- 透過 [Builder.BuildParamsParse](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs) 傳入 `_builderOptions`，或在呼叫 `Builder.BuildAsset()` 之前自行賦值。

## 操作步驟

1. 從編輯器選單或 CI 腳本呼叫 `Builder.BuildAsset()`。框架會先複製熱更新 DLL 與 AOT 程式碼，並將所有收集包的 `LocationToLower` 強制設定為 `true`，使檔名不區分大小寫：

   ```csharp
   Debug.Log("BuildAsset Start Copy Hotfix Code");
   BuildHotfixHelper.CopyHotfixCode();
   AssetDatabase.Refresh();
   BuildHotfixHelper.CopyAOTCode();
   AssetDatabase.Refresh();

   foreach (var assetBundleCollectorPackage in AssetBundleCollectorSettingData.Setting.Packages)
   {
       assetBundleCollectorPackage.LocationToLower = true;
   }
   AssetBundleCollectorSettingData.SaveFile();
   ```

   出處： [Builder.BuildAsset.cs#L17-L37](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L17-L37)

2. 選擇建置管線。可選值為 `ScriptableBuildPipeline`、`RawFileBuildPipeline`（不符合時會回退為 `BuiltinBuildPipeline`），透過 `_builderOptions.BuildPipeline` 傳入：

   ```csharp
   if (!Enum.TryParse(typeof(EBuildPipeline), _builderOptions.BuildPipeline, true, out var buildPipelineObj))
   {
       Debug.LogError($"無効なビルドパイプラインタイプ: {_builderOptions.BuildPipeline}、選択可能な値: {string.Join(", ", Enum.GetNames(typeof(EBuildPipeline)))}");
       return;
   }
   ```

   出處： [Builder.BuildAsset.cs#L40-L64](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L64)

3. 準備 `BuildParameters`。此步驟會一次設定建置模式（BuildMode / ForceRebuild）、目標平台、版本號、檔名樣式、輸出根目錄、內建複製目錄、是否啟用共享打包規則等：

   ```csharp
   buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage ? EBuildMode.IncrementalBuild : EBuildMode.ForceRebuild;
   buildParameters.BuildTarget = EditorUserBuildSettings.activeBuildTarget;
   buildParameters.PackageVersion = string.IsNullOrWhiteSpace(_builderOptions.PackageVersion)
       ? DateTime.Now.ToString("yyyyMMddHHmmss")
       : _builderOptions.PackageVersion;
   buildParameters.VerifyBuildingResult = true;
   buildParameters.FileNameStyle = EFileNameStyle.HashName;
   buildParameters.BuildOutputRoot = AssetBundleBuilderHelper.GetDefaultBuildOutputRoot();
   buildParameters.BuildinFileRoot = AssetBundleBuilderHelper.GetStreamingAssetsRoot();
   buildParameters.PackageName = _builderOptions.PackageName;
   buildParameters.EnableSharePackRule = true;
   buildParameters.EncryptionServices = new EncryptionNone();
   ```

   出處： [Builder.BuildAsset.cs#L65-L94](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L65-L94)

4. 執行建置並捕捉例外。若失敗，會以 `Environment.Exit(1)` 立即讓 CI 程序失敗：

   ```csharp
   bool isSuccess = false;
   try
   {
       pipeline.Run(buildParameters, true);
       isSuccess = true;
   }
   catch (Exception e)
   {
       Debug.LogException(e);
       Environment.Exit(1);
   }
   ```

   出處： [Builder.BuildAsset.cs#L95-L107](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L95-L107)

5. 建置成功後，依據 `_builderOptions` 的開關決定是否上傳資源包、更新版本號、傳送企業微信通知。完整的 `finally` 分支如下：

   ```csharp
   if (isSuccess && _builderOptions.IsUploadAsset)
   {
       string savePath = $"Bundles/{PlayerSettings.applicationIdentifier}/{EditorUserBuildSettings.activeBuildTarget}/{Application.version}/{_builderOptions.ChannelName}/{_builderOptions.PackageName}/{buildParameters.PackageVersion}";
       string uploadPath = $"{buildParameters.BuildOutputRoot}/{buildParameters.BuildTarget}/{Application.version}/{buildParameters.PackageName}/{buildParameters.PackageVersion}";
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.SetSavePath(savePath);
       ObjectStorageUploadManager.UploadDirectory(uploadPath);
   #endif
   }
   if (_builderOptions.IsUpdateAssetPackageVersion)
   {
       BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
   }
   ```

## 常見變化

- **切換建置管線**：修改 `_builderOptions.BuildPipeline`。可選 `ScriptableBuildPipeline` / `RawFileBuildPipeline`，其他值會變為 `BuiltinBuildPipeline`。
- **強制完整建置**：將 `IsIncrementalBuildPackage` 設為 `false`，建置模式即為 `EBuildMode.ForceRebuild`。
- **控制內建包複製策略**：若 `_builderOptions.BuildinFileCopyOption` 保持為空，會以 `ClearAndCopyAll` 處理；否則會解析為 `EBuildinFileCopyOption` 列舉型別。無效值會直接 `return`。
- **將日誌/資源上傳至物件儲存**：以編譯符號事先啟用 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 及對應的子模組（七牛/騰訊/Alibaba Cloud）。詳情請參閱 [Builder.cs#L27-L48](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L27-L48)。
- **使用自訂包名/版本**：直接設定 `_builderOptions.PackageName` 與 `_builderOptions.PackageVersion`。版本號留空時會自動以 `yyyyMMddHHmmss` 填入。

## 常見錯誤

| 症狀（原始碼錯誤原文） | 原因 | 修正方式 |
|---|---|---|
| `無効なビルドパイプラインタイプ: {xxx}` | `_builderOptions.BuildPipeline` 的字串無法解析為 `EBuildPipeline` | 以列舉名稱傳值：`BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` |
| `無効な内蔵ファイルコピーオプション: {xxx}` | `_builderOptions.BuildinFileCopyOption` 不是 `EBuildinFileCopyOption` 的列舉值 | 使用有效的列舉名稱，或保持為空以使用預設的 `ClearAndCopyAll` |
| 建置後程序立即以結束代碼 `1` 結束，並在主控台拋出例外 | `pipeline.Run` 拋出例外，catch 後呼叫 `Environment.Exit(1)` | 檢查 `Debug.LogException(e)` 的堆疊追蹤，修正 YooAsset 設定或收集器後重新執行 |
| `Builder.BuildAsset()` 開始時 `Packages` 清單為空 | YooAsset 資源收集器（`AssetBundleCollectorSettingData`）未設定 | 先在 YooAsset 工具列新增收集包，再執行建置 |

## 背景（可選）

`Builder.BuildAsset()` 在 YooAsset 之上做三件事：① 複製熱更新 DLL 與 AOT 程式碼；② 將收集包的路徑強制轉為小寫，避免在 Linux/Android 上因大小寫差異導致打包失敗；③ 呼叫對應的 `IBuildPipeline`（如 `BuiltinBuildPipeline`）產生資訊清單，並依據 `_builderOptions` 判斷是否執行上傳與版本通知。`EnableSharePackRule = true` 可讓資源以共享包方式打包，降低初始包的容量。加密介面預設為 `EncryptionNone`，但可在呼叫前自行替換 `buildParameters.EncryptionServices`。
