# 절차 목록 재설정 방법

런타임에 현재 절차 상태 머신을 파괴하고 새로운 절차 배열로 재초기화하여 한 번의 호출로 "비우기 + 재구성"을 완료합니다. 이 문서에서는 `ReinitializeProcedures`의 두 가지 진입점과 올바른 사용법을 소개합니다.

## 사전 조건

- `GameEntry.GetComponent<ProcedureComponent>()`를 통해 절차 컴포넌트 인스턴스를 가져왔습니다
- `ProcedureBase`를 상속하는 절차 클래스를 하나 이상 정의했습니다
- 프레임워크 초기화가 완료되었습니다(`m_ProcedureFsm`이 존재하거나 존재하지 않아도 됨)

## 작업 단계

1. **새 절차 배열 구성**: 새 상태 머신에 등록할 모든 절차 객체를 인스턴스화합니다.

   ```csharp
   var procedures = new ProcedureBase[]
   {
       new LaunchProcedure(),
       new LoginProcedure(),
       new GameProcedure(),
   };
   ```

2. **진입 절차 지정**: 동일한 절차 그룹에서 진입 절차로 사용할 하나를 선택합니다.

   ```csharp
   var entrance = procedures[1]; // LoginProcedure
   ```

3. **재설정 메서드 호출**: 절차 컴포넌트를 통해 재설정을 실행하면, 프레임워크는 먼저 이전 상태 머신을 파괴한 다음 새 배열로 재구성합니다.

   ```csharp
   ProcedureComponent procedureComponent = GameEntry.GetComponent<ProcedureComponent>();
   procedureComponent.ReinitializeProcedures(procedures, entrance);
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

4. **(선택 사항) 진입 절차 시작**: 즉시 절차로 진입하려면 `StartProcedure`를 호출합니다.

   ```csharp
   procedureComponent.StartProcedure(entrance.GetType());
   ```

## 일반적인 변형

### 절차 관리자 직접 사용

`ProcedureComponent` 래퍼를 거치지 않고 관리자 계층에서 직접 `ReinitializeProcedures(params ProcedureBase[] procedures)`를 호출할 수 있습니다. 시그니처는 절차 배열만 받고, 진입 절차 진입 설정을 포함하지 않습니다.

```csharp
m_ProcedureManager.ReinitializeProcedures(new ProcedureBase[]
{
    new LaunchProcedure(),
    new LoginProcedure(),
});
```

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L260-L271)

### 파괴만 수행 (비우기와 재구성 없음)

기존 절차를 비우고 재구성하지 않으려면 `DestroyProcedures()`를 사용합니다:

```csharp
procedureComponent.DestroyProcedures();
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L107-L111)

## 일반적인 오류

| 현상 | 원인 | 수정 |
|------|------|------|
| `GameFrameworkException("Procedures is invalid.")` 예외 발생 | 전달된 `procedures` 배열의 길이가 0임 | 최소 하나 이상의 `ProcedureBase` 인스턴스 전달 |
| 재설정 후 이전 절차의 `OnDestroy`가 트리거되지 않음 | 이전 절차 참조가 외부에서 여전히 유지되어 상태 머신 파괴 콜백이 실행되지 않음 | 외부에서 `ProcedureBase` 인스턴스를 장기적으로 캐시하지 말 것 |
| 호출 후 `CurrentProcedure`에서 예외 발생 | 재구성 후 `StartProcedure`를 호출하지 않음 | 재설정 후 `StartProcedure`를 호출하여 진입 절차 지정 |
| `NullReferenceException` | `ProcedureComponent`가 프레임워크에 등록되지 않음 | 장면에 `ProcedureComponent`가 마운트되고 활성화되어 있는지 확인 |

## 배경 (선택 사항)

`ReinitializeProcedures` 내부 순서는 다음과 같습니다: 먼저 `DestroyProcedures()`를 호출하여 이전 상태 머신을 파괴하고, 새 배열이 비어 있지 않은지 확인한 다음, 마지막으로 `m_FsmManager.CreateFsm(this, procedures)`로 FSM을 재구성합니다. `ProcedureComponent` 래퍼 계층은 이를 기반으로 추가로 `m_EntranceProcedure`를 저장하여 이후 `StartProcedure`에서 사용합니다.
