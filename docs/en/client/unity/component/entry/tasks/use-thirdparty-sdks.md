# How to Integrate Login, Ads, and Third-Party SDKs (Apple/Facebook/Google/AppsFlyer/AdJust/GameAnalytics)

By following the steps on this page to enable the corresponding script macros, you can invoke login, ads, and third-party SDK components via `GameApp.XXX`, without directly depending on the implementation details of each native SDK.

## Prerequisites

- The project has `com.gameframex.unity.entry` (this repository) installed, along with the corresponding sub-packages, such as `com.gameframex.unity.login.apple`, `com.gameframex.unity.login.facebook`, `com.gameframex.unity.login.google`, `com.gameframex.unity.appsflyer`, `com.gameframex.unity.adjust`, `com.gameframex.unity.gameanalytics`, etc.
- The framework declares the corresponding script macros in Player Settings / `csc.rsp` / `asmdef` based on the sub-packages, for example:
  - `ENABLE_GAME_FRAME_X_APPLE_LOGIN`
  - `ENABLE_GAME_FRAME_X_FACEBOOK_LOGIN`
  - `ENABLE_GAME_FRAME_X_GOOGLE_LOGIN`
  - `ENABLE_GAME_FRAME_X_ADS`
  - `ENABLE_GAME_FRAME_X_ADJUST`
  - `ENABLE_GAME_FRAME_X_APPSFLYER`
  - `ENABLE_GAME_FRAME_X_GAMEANALYTICS`

  When a macro is missing, the corresponding files will not be compiled, and the `GameApp.XXX` properties will not be available.

## Steps

### 1. Register components in the framework

At startup, `GameEntry` automatically discovers and registers each SDK component object; you only need to call `GameApp.XXX` before use. Below are the unified access entry points for each SDK within the framework (all located in `Runtime/GameApp.*.cs` in this repository):

```csharp
// Apple Login
AppleLoginComponent apple = GameApp.AppleLogin;

// Facebook Login
FaceBookLoginComponent fb = GameApp.FaceBookLogin;

// Google Login
GoogleLoginComponent google = GameApp.GoogleLogin;

// Ads
var ads = GameApp.Advertisement;

// AdJust
AdJustComponent adjust = GameApp.AdJust;

// AppsFlyer
var appsFlyer = GameApp.AppsFlyer;

// GameAnalytics
var ga = GameApp.GameAnalytics;
```

> These properties are lazily loaded via `GameEntry.GetComponent<>()` on first access and cached in static fields.

### 2. Invoke the login component

Taking Apple login as an example, get the component and call the corresponding method to trigger the native login flow:

```csharp
var apple = GameApp.AppleLogin;
if (apple != null)
{
    apple.Login();
}
```

Facebook and Google login are invoked the same way:

```csharp
GameApp.FaceBookLogin?.Login();
GameApp.GoogleLogin?.Login();
```

Each `LoginComponent` subclass is provided by the corresponding sub-package; refer to the sub-package API for specific method names (Login / Logout / callback registration, etc.).

Source: [Runtime/GameApp.AppleLogin.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.AppleLogin.cs#L36-L55)

### 3. Invoke the ads and attribution / analytics components

Ads, AdJust, AppsFlyer, and GameAnalytics are also accessed through the same entry points. A common pattern is: after the game starts or enters the main scene, call the initialization/tracking API once, and afterwards trigger displays or events as needed by your business logic.

```csharp
// Example: trigger an ad display (refer to AdvertisementComponent for the specific method)
GameApp.Advertisement?.Show();

// Example: AdJust track event
GameApp.AdJust?.TrackEvent("login_success");

// Example: AppsFlyer track event
GameApp.AppsFlyer?.TrackEvent("af_login");

// Example: GameAnalytics track event
GameApp.GameAnalytics?.TrackEvent("login_success");
```

The specific initialization parameters for each component (App ID, Dev Key, callbacks, etc.) are defined in the `*Component.cs` files within their sub-packages; refer to the corresponding sub-package documentation.

## Common Variants

- **Platform-specific conditional compilation**: When enabling the Apple login macro only on iOS, you can wrap the call with `#if UNITY_IOS && ENABLE_GAME_FRAME_X_APPLE_LOGIN`, so the Apple SDK is not included on Android.
- **Optional enabling**: For SDKs you do not integrate, simply do not install the corresponding sub-package; the corresponding macro will not appear, and the `GameApp.XXX` properties will not be compiled into the assembly.
- **Multiple login methods coexisting**: You can enable Apple, Facebook, and Google login simultaneously, and dynamically select the entry point based on platform or region:

```csharp
ILogin login = Application.platform == RuntimePlatform.IPhonePlayer
    ? (ILogin)GameApp.AppleLogin
    : GameApp.GoogleLogin;
login?.Login();
```

## Common Errors

- **Symptom**: `GameApp.AppleLogin` fails to compile with "GameApp does not contain a definition for AppleLogin".  
  **Cause**: The Apple login sub-package is not installed, or the `ENABLE_GAME_FRAME_X_APPLE_LOGIN` macro is not declared.  
  **Fix**: Install the corresponding sub-package, let the framework write the script macros, and recompile.

- **Symptom**: `GameApp.AdJust` returns `null` or throws an NRE at runtime.  
  **Cause**: `GameEntry` did not attach this component to the startup flow, or the `AdJustComponent` sub-package is not imported.  
  **Fix**: Confirm that the sub-package exists and that `AdJustComponent` is included in the `GameEntry` initialization chain.

- **Symptom**: Facebook / Google login does not respond when clicked.  
  **Cause**: Native SDK credentials are not configured, or the callback Activity / URL Scheme is missing.  
  **Fix**: Complete the OAuth credentials in the Facebook / Google consoles and app configuration, and configure Info.plist / AndroidManifest according to each sub-package's instructions.

## Background (Optional)

`GameApp` is a `static partial class`, with one `GameApp.XXX.cs` file per SDK, all uniformly lazily loaded via `GameEntry.GetComponent<>()`. `#if ENABLE_GAME_FRAME_X_*` ensures that disabled SDKs are completely excluded from compilation, which both avoids dependency pollution and ensures that the final build only contains the SDK implementations actually used.
