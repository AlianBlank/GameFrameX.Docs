# 如何理解命名慣例與縮寫對應（Component / FUI / GUI）

`GameApp` 是 Game Frame X 的靜態 Facade 類別，將 `GameApp.{Name}` 對應到 `GameEntry.GetComponent<{Name}Component>()`。理解命名規則後，您可以直接透過 `GameApp.XXX` 存取任何內建元件，而無需查閱文件。

## 命名對應規則

絕大多數元件都遵循「移除 `Component` 後綴」的簡單規則；只有 `FUI` 和 `GUI` 是縮寫例外。

| GameApp 屬性 | 等效呼叫 | 類型 |
|---|---|---|
| `GameApp.Event` | `GameEntry.GetComponent<EventComponent>()` | 一般對應 |
| `GameApp.UI` | `GameEntry.GetComponent<UIComponent>()` | 一般對應 |
| `GameApp.Asset` | `GameEntry.GetComponent<AssetComponent>()` | 一般對應 |
| `GameApp.FUI` | `GameEntry.GetComponent<FairyGUIComponent>()` | 縮寫例外（FUI=FairyGUI） |
| `GameApp.GUI` | `GameEntry.GetComponent<UGUIComponent>()` | 縮寫例外（GUI=uGUI） |

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L30-L38)

## 縮寫例外說明

`FUI` 和 `GUI` 是兩個 UI 子系統的歷史縮寫。它們保留了與「移除 `Component` 後綴」規則不一致的精簡大寫形式，因此使用時請特別注意：

- **FUI** → `FairyGUIComponent`（基於 FairyGUI 解決方案的 UI 元件；根據 [CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6)，fairygui 相依套件已被移除）
- **GUI** → `UGUIComponent`（基於 Unity 原生 UGUI 的 UI 元件，定義於 `GameApp.GUI.cs`，並由編譯巨集 `ENABLE_GAME_FRAME_X_L_UGUI` 控制）

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
public static partial class GameApp
{
    public static UGUIComponent GUI
    {
        get
        {
            if (_gui == null)
            {
                _gui = GameEntry.GetComponent<UGUIComponent>();
            }
            return _gui;
        }
    }
}
#endif
```

來源：[Runtime/GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

## 使用方式

請按照以下步驟在您自己的腳本中使用此對應：

1. **確認名稱**：先在 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/README.zh-CN.md#L32-L38) 的對應表中查詢 `GameApp.{Name}`，找到對應的 `*Component` 類型。
2. **一般元件**：直接撰寫 `GameApp.Event`、`GameApp.UI`、`GameApp.Asset` 等。
3. **UI 元件**：UI 子系統有兩種變體；請根據引擎解決方案選擇 `GameApp.FUI`（FairyGUI）或 `GameApp.GUI`（UGUI）。
4. **視需要啟用巨集**：`GameApp.GUI` 僅在啟用 `ENABLE_GAME_FRAME_X_L_UGUI` 編譯巨集時才存在；`GameApp.FUI` 相依於 FairyGUI 套件，一旦移除該相依性，屬性就會失效。

```csharp
// 一般對應範例
var evt = GameApp.Event;
var asset = GameApp.Asset;

// UI 子系統：根據引擎解決方案擇一使用
var fairygui = GameApp.FUI;   // FairyGUIComponent（需要 FairyGUI 套件）
var ugui = GameApp.GUI;       // UGUIComponent（需要 ENABLE_GAME_FRAME_X_L_UGUI 巨集）
```

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|---|---|---|
| `GameApp.FUI` 編譯失敗顯示「未定義」或回傳 null | fairygui 相依套件已被移除（[CHANGELOG b9d469b](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/CHANGELOG.md#L6)） | 改用 `GameApp.GUI` 或安裝 FairyGUI 套件 |
| `GameApp.GUI` 無法存取 | 缺少編譯巨集 `ENABLE_GAME_FRAME_X_L_UGUI` | 在 Player Settings 的 Scripting Define Symbols 中加入該巨集 |
| 誤將 `GameApp.FUI` 當作 `UIComponent` | `FUI` 是 `FairyGUIComponent`；`UI` 才是真正的 `UIComponent` | 區分兩個 UI 子系統：一般用途 UI 使用 `GameApp.UI`，引擎特定 UI 使用 `GameApp.FUI`/`GameApp.GUI` |
| 誤用 `GameApp.GameApp` 之類的名稱 | 屬性名稱是移除 `Component` 後的元件名稱，而非原始元件名稱 | 遵循「XxxComponent → Xxx」規則，例如 `AssetComponent → Asset` |

## 背景

`GameApp` 以 C# `partial class`（部分類別）的形式分散於多個檔案中組織，每個元件對應一個 `GameApp.{Name}.cs` 檔案。在內部，延遲載入的靜態欄位會快取第一次呼叫的結果，後續存取會直接回傳快取值，以避免重複查找。保留 `FUI` 和 `GUI` 縮寫是為了與舊有程式碼相容並縮短 UI 呼叫路徑。如果新程式碼不需要區分引擎解決方案，建議優先使用一般用途的 `GameApp.UI`（`UIComponent`）。
