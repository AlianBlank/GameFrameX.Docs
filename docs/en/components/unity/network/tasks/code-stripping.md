# Handling Code Stripping During Builds

When you enable **Managed Stripping Level** in Player Settings (especially High/Medium) or build with IL2CPP, issues such as `NetworkComponent` or network event classes going missing, or `CreateNetworkChannel` throwing `MissingMethodException` / `TypeLoadException`, are usually caused by Unity's managed code stripping removing types/methods that are not statically referenced. This package already annotates key types with `[UnityEngine.Scripting.Preserve]`, so in most cases no extra handling is needed; what does get stripped is usually the parts of your own project registered via reflection/strings—just follow the steps below to add the protection.

## Prerequisites

- Unity version 2019.4 or higher (the minimum version declared in this package's `package.json`).
- `com.gameframex.unity.network` (current version 2.6.10) installed along with its dependencies `com.gameframex.unity`, `com.gameframex.unity.event`, and `com.gameframex.unity.litjson`.
- The build target platform uses IL2CPP, or Managed Stripping Level (Low/Medium/High) is enabled in Player Settings.

## Steps

1. First, confirm whether the protection built into this package is in effect. This package annotates every entry component and public API with `[UnityEngine.Scripting.Preserve]`; for example, the `NetworkComponent` class itself:

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Network")]
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkComponent : GameFrameworkComponent
   ```
   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L42-L45)

   Its public methods (such as `CreateNetworkChannel`, `GetNetworkChannel`) also carry `[Preserve]`:

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   ```
   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L176)

   The network event argument classes are all annotated with `[Preserve]` as well (these classes are often dispatched by type through the event system, making them easy targets for stripping):

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkConnectedEventArgs : GameEventArgs
   ```
   Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L40-L41)

   The same treatment is applied to `NetworkClosedEventArgs`, `NetworkErrorEventArgs`, `NetworkMissHeartBeatEventArgs`, as well as the parameterless constructor of `NetworkManager.HeartBeatState` (the framework internally creates state objects via reflection):
   Source: [NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L43-L45)

2. Open **Edit → Project Settings → Player → Other Settings → Optimization → Managed Stripping Level** and check the current stripping level. If only sporadic types are missing, you can first lower the level to **Low (or Minimal)** and do a test build to confirm the problem is indeed caused by stripping.

3. Check the types in **your own project** that get stripped. Common cases that this package cannot protect for you:
   - Your `INetworkChannelHelper` derived classes (packet header and packet body handlers for sending/receiving);
   - Message handlers you register through `NetworkComponent` but that are only referenced by string/reflection;
   - Data models used for serialization (e.g., LitJSON-related DTOs).

4. For the types you own above, prefer adding `[UnityEngine.Scripting.Preserve]` to the classes and public members (consistent with the package's approach):

   ```csharp
   // Example usage in your project: the attribute usage is the same as NetworkComponent in the package
   [UnityEngine.Scripting.Preserve]
   public sealed class MyNetworkChannelHelper : INetworkChannelHelper
   {
       ...
   }
   ```

5. If many types are stripped and adding attributes one by one is impractical, create a `link.xml` under the project's `Assets/` folder to preserve entire assemblies (this is Unity's official mechanism; **this repository does not include a link.xml**, you need to create it yourself in the consuming project):

   ```xml
   <linker>
     <!-- Preserve the entire network assembly -->
     <assembly fullname="GameFrameX.Network.Runtime" preserve="all"/>
     <!-- Preserve your own business/protocol assemblies -->
     <assembly fullname="YourAssemblyName" preserve="all"/>
   </linker>
   ```

6. Rebuild, confirm in the build log that there are no `MissingMethodException`/`TypeLoadException`, and perform a real-device connection test following the "Verification" section below.

## Verification

- After the build, the `NetworkComponent` attached in the scene (menu path GameFrameX/Network) is created normally;
- The channel returned by `CreateNetworkChannel` can complete a connection, and the `NetworkConnectedEventArgs` event is received;
- Heartbeat logic works correctly (indicating `HeartBeatState` is not stripped), and `NetworkMissHeartBeatEventArgs`/`NetworkErrorEventArgs` are received when the network disconnects.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Build reports `TypeLoadException`/`MissingMethodException`; works fine in the editor | Managed Stripping removed types that are only referenced via reflection | Lower the Managed Stripping Level, or add `[UnityEngine.Scripting.Preserve]` to the affected types |
| Heartbeat state object creation fails | The `HeartBeatState` parameterless constructor was stripped (the framework creates it internally via reflection) | The package already adds `[Preserve]`; if you forked/modified this file, make sure the attribute is kept |
| Not receiving `NetworkConnectedEventArgs` and other network events | Event argument classes were stripped, so the event system fails to deserialize them | The package already adds `[Preserve]`; check whether a fork overrides them or your own EventArgs are missing the annotation |
| Methods of your own `INetworkChannelHelper` derived class go missing | The types in your project are not statically referenced | Add `[Preserve]` to your Helper class or write a link.xml |
| Still stripped after adding link.xml | The file is not under `Assets/`, or the XML format is incorrect | Verify the path and the `assembly fullname` spelling (see the assembly name in the asmdef) |

## Background

When building with IL2CPP/High Stripping, Unity removes types and members that are not statically reachable from managed code entry points. The network framework makes heavy use of the "interface + reflection + event dispatch" pattern—for example, locating implementations via the `INetworkManager` interface and dispatching argument classes such as `NetworkConnectedEventArgs` by type through the event system—these references are invisible to the stripper. Therefore, this package annotates each of these key locations with `[UnityEngine.Scripting.Preserve]` (see the source code referenced in Step 1 above). It covers all public types in the package, but it cannot cover types registered via reflection on your project side; those must be protected by you in the same way.
