# 服务器提示 ServerFullyLoaded(超过最大在线人数)怎么办

当客户端连接服务器或进入房间时,如果收到 `ServerFullyLoaded` (枚举值 `14`) 错误或 `NotifyServerFullyLoaded` 通知,说明已达上限,服务器拒绝了连接或加入请求。该错误来自两个独立的限流点:服务器全局最大在线数 `MaxClientCount` 与单个房间的 `MaxPlayerCount`。

## 快速诊断

| 症状 | 触发位置 | 根因 | 修复 |
|------|----------|------|------|
| 客户端一连上就被踢出,收到 `NotifyServerFullyLoaded` 通知 | `OnConnected` 全局入口 | 当前会话数 `count > Setting.MaxClientCount` | 调大 `MaxClientCount` 或扩容/排队,见 [服务器侧修复](#服务器侧修复) |
| 进入特定房间失败,响应中 `ErrorCode = 14` | `RoomComponentAgent` 加入房间逻辑 | `room.PlayerIds.Count >= room.MaxPlayerCount` | 调大房间 `MaxPlayerCount`、拆房间或引导进其他房间,见 [房间侧修复](#房间侧修复) |

错误码定义在 `OperationStatusCode.ServerFullyLoaded = 14`,描述为「通知客户端服务器人数已达上限」:


## 服务器侧修复

触发点:客户端刚建立连接时,服务端比对当前会话数与全局上限。

```csharp
// Source: GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L79-L90
protected override async ValueTask OnConnected(IAppSession appSession)
{
    LogHelper.Info("有外部客户端网络连接成功！。链接信息：SessionID:" + appSession.SessionID + " RemoteEndPoint:" + appSession.RemoteEndPoint);
    var netChannel = new DefaultNetWorkChannel(appSession, Setting);
    var count = SessionManager.Count();
    if (count > Setting.MaxClientCount)
    {
        // 达到最大在线人数限制
        await netChannel.WriteAsync(new NotifyServerFullyLoaded(), (int)OperationStatusCode.ServerFullyLoaded);
        netChannel.Close();
        return;
    }
    // ...
}
```

注意比较运算符是严格大于(`>`),即 `count` 达到 `MaxClientCount` 本身仍允许连接;超过才拒绝。

按以下顺序处理:

1. **确认配置项来源**:`MaxClientCount` 读取自 `Setting`(由启动配置初始化)。找到部署目录下 `setting.json`(或对应环境配置)中 `MaxClientCount`,核对当前值与预期承载量。
2. **提高上限**:在配置文件中把 `MaxClientCount` 调高,例如从 `5000` 改到 `8000`,然后重启服务使新值生效。
3. **横向扩容**:如果单机已到承载瓶颈,在网关后挂接更多 GameFrameX 节点(部署多进程/多机),通过网关层负载均衡分担会话。
4. **加入排队**:客户端在收到 `NotifyServerFullyLoaded` 后不要立即重试,显示「服务器繁忙,请稍候」并按退避策略(例如 5s、10s、30s 递增)排队重连。
5. **排查会话泄漏**:确认 `OnDisconnected` 中 `SessionManager.Remove(appSession.SessionID)` 正确执行([AppStartUpHotfixGameByMain.cs#L71](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L71)),否则异常断开的会话会一直占位。

## 房间侧修复

触发点:玩家加入房间时,目标房间已满。

```csharp
// Source: GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L181-L186
if (room.PlayerIds.Count >= room.MaxPlayerCount)
{
    response.ErrorCode = (int)OperationStatusCode.ServerFullyLoaded;
    response.Room = await ToMessageAsync(room);
    return;
}
```

处理步骤:

1. **调高 `MaxPlayerCount`**:在房间配置(创建房间时使用的参数)中,把目标房间类型的 `MaxPlayerCount` 调大,重启或重发配置让房间组件读到新值。
2. **拆分成多房间**:把同一类玩法的房间模板切成多份(例如房间号段、匹配池分桶),让玩家分散到不同房间。
3. **客户端侧引导**:收到 `ErrorCode = 14` 时,客户端不要原地死循环重试,应重新走匹配/换房流程;后端可在响应里附带可用房间列表(本仓库当前实现只回 `room` 本身,若需要多房推荐需扩展响应结构)。
4. **检查房间配置**:确认 `MaxPlayerCount` 与 `MinPlayerCount`、`Status` 转换逻辑一致([RoomComponentAgent.cs#L189](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L189)),避免配错造成一直停在 `Waiting` 或 `Ready` 误判。

## 验证

1. **服务器侧**:重启后,连接数临近 `MaxClientCount` 时仍可加入;再多一个连接仍应收到 `NotifyServerFullyLoaded`,关闭连接。
2. **房间侧**:使用测试客户端把房间塞到 `MaxPlayerCount`,再尝试加入应得到 `ErrorCode = 14` 且 `Room` 字段返回当前房间信息(可用于客户端展示「房间已满 XX/XX」)。
3. **日志核验**:服务端 `LogHelper.Info` 会记录「有外部客户端网络连接成功」;在触发踢人时,客户端应观察到 `ServerFullyLoaded = 14` 后连接关闭,无需服务端再写额外日志。

## 背景(可选)

`ServerFullyLoaded` 在仓库里是双重含义:既是 `OperationStatusCode` 的返回码,也是断连时主动推送的 `NotifyServerFullyLoaded` 通知。两类场景共用同一个枚举值,所以客户端只需用 14 这一个值判断「人满」即可,但根因排查需要分清是连接层还是房间层拒绝。
