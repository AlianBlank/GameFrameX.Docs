# 如何發起購買（內購與訂閱）

呼叫 `PaymentComponent.Buy(PurchaseParams)` 並監聽 `OnPurchaseSuccess` / `OnPurchaseFailed` 事件，即可完成一次性內購與訂閱商品的購買；伺服器驗證通過後再呼叫 `ConsumePurchase` 消耗訂單。舊的 `BuyInApp` / `BuySubs` 介面已標記 `[Obsolete]`，建議統一改用 `Buy(PurchaseParams)`。

## 前置條件

- 場景中已掛載 `PaymentComponent`（元件選單路徑 `GameFrameX/Payment`），它會自動附帶 `GameFrameXPaymentCroppingHelper`：

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
public class PaymentComponent : GameFrameworkComponent
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

- 已按目標平台引入對應的通路實作套件。`PaymentComponent.Awake()` 會依編譯巨集自動選擇實作類別（Android → `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`，iOS → `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`，其餘平台則退回至 `DefaultPaymentManager`）。

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 操作步驟

1. **設定預先定義商品 ID**（可選但建議）。用於預先載入商品快取，**必須在 `Init()` 之前呼叫**：

```csharp
payment.SetPredefinedProductIds(
    new List<string> { "gem_100", "gem_500" },      // 內購商品ID列表
    new List<string> { "vip_monthly" });             // 訂閱商品ID列表
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

2. **初始化支付系統**：

```csharp
// isDebug：是否沙箱模式；isClientVerify：是否執行用戶端購買驗證
payment.Init(isDebug: false, isClientVerify: false);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

| 參數 | 類型 | 預設值（元件層） | 說明 |
|------|------|------------------|------|
| `isDebug` | `bool` | `false` | 是否使用沙箱購買 |
| `isClientVerify` | `bool` | `true`（`PaymentComponent`）；`false`（`IPaymentManager`） | 是否由用戶端驗證購買；採用伺服器驗證時應設為 `false` |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L102-L102)、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

3. **訂閱購買結果事件**（建議在初始化前後一次性掛好）：

```csharp
payment.OnPurchaseSuccess += (sender, e) =>
{
    Debug.Log($"購買成功: {e.ProductId}, OrderId={e.OrderId}");
    // 伺服器驗證通過後消耗訂單：
    // payment.ConsumePurchase(e.PurchaseToken);
};
payment.OnPurchaseFailed += (sender, e) =>
    Debug.Log($"購買失敗: {e.ResultCode}, {e.ErrorMessage}");
```

事件簽章來源：[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L18-L26)，元件層同名轉送見 [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L46)

4. **確認支付系統就緒後再發起購買**：呼叫 `payment.IsReady()`，傳回 `false` 時不要繼續呼叫 `Buy`。

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L45-L49)

5. **建構 `PurchaseParams` 並呼叫 `Buy`**。`PurchaseParams` 是抽象基底類別（建構函式為 `protected`），不能直接 `new`；各通路使用其子類別傳入通路特有的參數（如訂閱所需的 `offerToken`）。若通路套件未提供子類別，可自行繼承：

```csharp
public sealed class MyPurchaseParams : PurchaseParams
{
    public MyPurchaseParams(string productId, string orderId, PaymentProductType productType)
        : base(productId, orderId, productType) { }
}

// 發起購買（productType 取內購/訂閱對應的列舉值，定義見 Runtime/PaymentProductType.cs）
payment.Buy(new MyPurchaseParams("gem_100", "order_20240101_001", productType));
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35)（基底類別定義）、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112)（建議入口）

6. **伺服器驗證通過後消耗購買**。一次性商品必須消耗後才能再次購買：

```csharp
payment.ConsumePurchase(e.PurchaseToken);   // PurchaseToken 來自 OnPurchaseSuccess 的 PaymentEventArgs
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L140-L152)

`PaymentEventArgs` 攜帶的欄位（用於回傳伺服器驗證）：

| 欄位 | 類型 | 說明 |
|------|------|------|
| `ProductId` | `string` | 產品 ID |
| `OrderId` | `string` | 訂單 ID |
| `PurchaseToken` | `string` | 購買權杖（消耗訂單用） |
| `ResultCode` | `PaymentResultCode` | 支付結果代碼 |
| `ErrorMessage` | `string` | 錯誤訊息 |
| `PurchaseData` | `string` | 原始購買資料（JSON 格式） |
| `CustomData` | `string` | 自訂資料 |

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

## 常見變體

- **查詢歷史訂單 / 恢復購買**：呼叫 `payment.QueryPurchases(PaymentProductType.列舉值)`，結果透過 `OnQueryPurchasesResult` 事件回傳，事件參數同樣是 `PaymentEventArgs`。
  Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L51-L56)、[IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L28-L31)
- **舊介面（已棄用）**：`BuyInApp(productId, orderId, offerToken = "", customData = "")` 與 `BuySubs(productId, orderId, offerToken = "", customData = "")` 分別對應一次性商品與訂閱商品，兩者均標記 `[Obsolete("請使用 Buy(PurchaseParams) 替代")]`，新程式碼請勿使用。
  Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L72-L93)
- **自訂資料傳遞**：舊介面透過 `customData` 參數傳遞，事件回呼中用 `PaymentEventArgs.CustomData` 讀回；新 `Buy(PurchaseParams)` 入口由各通路子類別擴充對應欄位。

## 常見錯誤

| 症狀 / 日誌 | 原因 | 修正 |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` 傳回空 | 檢查平台實作類別名稱設定（`PaymentComponent` Inspector 中的 `m_componentXxxType`）與通路套件是否已引入 |
| `Log.Warning("Product ID is null or empty.")` | 呼叫舊 `Buy*` 介面時 `productId` 為空 | 傳入非空商品 ID |
| `Log.Warning("Order ID is null or empty.")` | 呼叫舊 `Buy*` 介面時 `orderId` 為空 | 傳入非空訂單 ID |
| `Log.Warning("Purchase token is null or empty.")` | `ConsumePurchase` 傳入空 token | 使用 `OnPurchaseSuccess` 事件中的 `e.PurchaseToken` |
| `SetPredefinedProductIds` 未生效 | 在 `Init()` 之後才呼叫 | 移到 `Init()` 之前 |
| 一次性商品重複購買失敗（`ItemAlreadyOwned`） | 上一次購買未消耗 | 伺服器驗證通過後呼叫 `ConsumePurchase`；`ItemNotOwned`、`VerifyFailed`、`NetworkError` 等結果碼見 `PaymentResultCode` 列舉 |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93)、[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L117-L152)、[PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L14-L25)

## 背景

`PaymentComponent` 是外觀（Facade）層，只做參數驗證與事件轉送，實際邏輯由按平台解析出的 `IPaymentManager` 實作完成（Google / Apple / WebGL / PC / Default）。購買結果統一透過 `PaymentEventArgs` 拋出，`PaymentResultCode` 區分成功、取消、網路錯誤、已擁有等情形，便於各端重複使用同一套上層處理程式碼。
