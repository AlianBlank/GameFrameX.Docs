# フレーム終了コールバックが実行されない場合の対処法

`CoroutineComponent.WaitForEndOfFrameFinish` が注入するコールバックは、内部のコルーチンが `yield return new WaitForEndOfFrame()` に到達した後でないと発火しません。コルーチンがフレーム終了前に停止、上書き、あるいはそもそも起動しなかった場合、コールバックは実行されません。このページでは、代表的なシナリオの診断と修正方法を説明します。

コルーチンコンポーネント全般の説明は、『Coroutine Component』を参照してください。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 登録したコールバックが一度も発火せず、ログにも例外が出ない | コルーチンが `StopCoroutine` / `StopAllCoroutines` で早期終了され、`WaitForEndOfFrame` を待つところまで到達していない | コールバックが発火すべきフレームと同じフレームでコルーチンを停止しない、または別の同期点を使う |
| 同じコールバックを複数回登録したのに一度しか発火しない | `WaitForEndOfFrameFinishInternal` は `IEnumerator` イテレータメソッドであり、`System.Action` を渡すと**新しい**イテレータインスタンスが返されるため、フレームワークの参照同値性キーにより古い追跡エントリが上書きされる | 同じ `WaitForEndOfFrameFinish` 呼び出しを一度きりの使用と見なすか、業務層側でコールバックをキューイング・マージする |
| Play に入ったあとコルーチンがそもそも起動していない | 呼び出し側が親クラス `MonoBehaviour` の参照を取得しており、そのコンポーネントでは `StartCoroutine` が `new` キーワードでオーバーライドされ追跡されているが、親クラスからの呼び出しはこの追跡をすり抜ける。さらに GameObject が既に `Destroy` されている場合も起動できない | `CoroutineComponent` 型経由の参照で呼び出し、コンポーネントオブジェクトがまだアクティブであることを確認する |
| シーン切り替え / Play モード終了後、コールバックが二度と発火しない | コンポーネントが GameObject とともに破棄され、内部の `m_CoroutineMap` がクリアされる | フレーム終了コールバックを破棄されるオブジェクトに付けず、常駐の `CoroutineComponent` に付ける |

## 修正手順

### 1. `StopCoroutine` で早期終了されていないか確認する

`WaitForEndOfFrameFinish` の実装はワンショット コルーチンです:

```csharp
private readonly WaitForEndOfFrame _waitForEndOfFrame = new WaitForEndOfFrame();

private IEnumerator WaitForEndOfFrameFinishInternal(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke();
}

public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(WaitForEndOfFrameFinishInternal(callback));
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

`yield return _waitForEndOfFrame` は、現在のフレームのレンダリング終了まで戻りません。この間に `StopCoroutine` / `StopAllCoroutines` が呼ばれると、`callback?.Invoke()` の行は永遠に到達しません。

修正:

1. `StopCoroutine` / `StopAllCoroutines` を呼ぶ前に、コールバックで行う副作用を `Time.timeScale`、`Application.targetFrameRate`、あるいはイベント能動的発行に切り替え、`WaitForEndOfFrameFinish` に依存しないようにする。
2. どうしてもキャンセルする必要がある場合は、業務コード内で手動でコールバックを一度実行してから、コルーチンを停止する:

```csharp
GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()
    .StopCoroutine(coroutineEnumerator); // その後、自分でクリーンアップを行う
```

### 2. 呼び出しが `CoroutineComponent` の `StartCoroutine` 経由であることを確認する

`StartCoroutine` は `new` でオーバーライドされ `m_CoroutineMap` を維持しているため、親クラス `MonoBehaviour` からの呼び出しは追跡をすり抜けます。`StopCoroutine` がキーを取得できないと停止対象のコルーチンが見つからず、「起動しなかったように」見えます:

```csharp
public new UnityEngine.Coroutine StartCoroutine(IEnumerator enumerator)
{
    var ret = base.StartCoroutine(enumerator);
    m_CoroutineMap[enumerator] = ret;
    return ret;
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

修正: すべての呼び出しを `GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()` で取得したインスタンス経由に統一し、暗黙的に `MonoBehaviour` にキャストしない。

### 3. `StopAllCoroutines` の巻き添えクリアを避ける

`StopAllCoroutines` は `m_CoroutineMap` をクリアして追跡中のすべてのコルーチンを停止するため、フレーム終了を待っているコールバックもまとめて破棄されます:

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

修正:

1. `StopAllCoroutines` を呼ぶ前に、未精算の `WaitForEndOfFrameFinish` コールバックが残っていないことを確認する。
2. フレーム終了レベルの同期は `Update` / `LateUpdate` または独自イベントで行い、`WaitForEndOfFrame` に頼らない。

### 4. オブジェクトのライフサイクルを確認する

`CoroutineComponent` は `MonoBehaviour` であり、GameObject と一緒に破棄されます。オブジェクトが `Destroy` されたり、属するシーンがアンロードされたりすると、フレーム終了を待っていたコルーチンも中断され、コールバックは二度と発火しません。

修正:

1. フレーム終了コールバックは、常駐のグローバル `CoroutineComponent`(`GameFrameX` フレームワークが自動生成)に委譲して実行する。
2. 自分のスクリプトに付ける必要がある場合は、コールバックが `OnDestroy` までに確実に発火済みであること、または自前でフォールバック処理を行うこと。

## 検証

1. `WaitForEndOfFrameFinish` のコールバック内に `Debug.Log` を 1 行追加し、Play モードで毎フレーム 1 回出力されることを確認する。あるいはコールバック内で本来実行されるはずのロジックを 1 回発火させて効果を観察する。
2. コルーチン実行中に `StopAllCoroutines` を能動的に呼び、ログを観察する: コールバックが出力されなくなれば問題は手順 1 にある。正常に出力されればコールバックロジック自体の不具合。
3. シーンを切り替えるか Play を終了し、`CoroutineComponent` インスタンスがまだ存在するか(`GameFrameXEntry` が解放されていないか)を確認する。これにより手順 4 のオブジェクトライフサイクル問題かどうかを判断する。
