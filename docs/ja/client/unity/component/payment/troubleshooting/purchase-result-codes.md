# 購入失敗と結果コード早見表

購入コールバック `OnPurchaseFailed`（または `OnQueryPurchasesResult` / `OnConsumePurchaseResult`）がトリガーされると、`PaymentEventArgs.ResultCode` が `PaymentResultCode` 列挙値を返し、失敗原因の特定に使用されます。本ページでは、すべての結果コード、対応する対処方法、およびこれらの情報を取得するためのコールバックの正しい購読方法をまとめています。

## クイック診断

| 症状（ResultCode / 現象） | 原因 | 修正 |
|------|------|------|
| `Success` | 購入成功 | `OnPurchaseSuccess` 内でアイテムを付与。消耗型アイテムは必ず `ConsumePurchase` を呼び出す |
| `Failed` | チャネル共通の失敗。詳細は `ErrorMessage` を参照 | `ErrorMessage` と `PurchaseData` を出力し、チャネルのエラーコードに基づいて調査 |
| `Cancelled` | ユーザーが決済画面で自らキャンセルした | エラー表示をせず、サイレントに処理すればよい |
| `NetworkError` | デバイスのネットワークが利用不可 | 再試行を促し、ネットワーク回復後に再度 `Buy` を実行 |
| `ServiceUnavailable` | チャネルの決済サービスが利用不可（ストア未準備など） | まず `IsReady()` で決済システムの準備を確認し、時間をおいて再試行 |
| `ItemAlreadyOwned` | アイテムを既に所持しており未消耗（消耗型アイテムの重複購入） | `QueryPurchases` で `PurchaseToken` を取得した後、`ConsumePurchase` を実行してから再度購入 |
| `ItemNotOwned` | 未所持のアイテムを消耗しようとした | 先に購入を完了させる。存在しない `PurchaseToken` に対して `ConsumePurchase` を呼び出さない |
| `VerifyFailed` | 購入検証の失敗（`Init` の `isClientVerify` に関連） | サーバー検証方式では `isClientVerify` を `false` に設定。サーバー側の署名検証ロジックを確認 |
| `Unknown` | チャネルが未マッピングの結果を返した | `ErrorMessage` と `PurchaseData`（生の JSON）を頼りに手動で分析 |

結果コードは以下の通り定義されており、全部で 9 個です：

```csharp
public enum PaymentResultCode
{
    Success,
    Failed,
    Cancelled,
    NetworkError,
    ServiceUnavailable,
    ItemAlreadyOwned,
    ItemNotOwned,
    VerifyFailed,
    Unknown,
}
```

## 完全なエラー情報を取得

コールバックの引数 `PaymentEventArgs` には以下のフィールドが含まれます。トラブルシューティング時にはすべて出力してください：

| フィールド | 型 | 説明 |
|------|------|------|
| `ProductId` | `string` | 製品 ID |
| `OrderId` | `string` | 注文 ID |
| `PurchaseToken` | `string` | 購入トークン（消耗・照会時に使用） |
| `ResultCode` | `PaymentResultCode` | 決済結果コード |
| `ErrorMessage` | `string` | エラーメッセージ |
| `PurchaseData` | `string` | 生の購入データ（JSON 形式） |
| `CustomData` | `string` | 購入時に渡されたカスタムデータ |

## 修正手順

### 購入失敗コールバックを購読する

3 つの結果イベント（`OnPurchaseSuccess` / `OnPurchaseFailed` / `OnQueryPurchasesResult` / `OnConsumePurchaseResult`）は `IPaymentManager` 上で宣言されており、`PaymentComponent` はイベントラッパーの形式で内部の `_paymentManager` へ転送します：

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

出典： [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L42-L46)

ビジネス層での購読例：

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseFailed += OnPurchaseFailed;

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    UnityEngine.Debug.LogError(
        $"[Payment] 失败 ProductId={e.ProductId} ResultCode={e.ResultCode} " +
        $"ErrorMessage={e.ErrorMessage} PurchaseData={e.PurchaseData}");
}
```

出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L19-L36)

### `ItemAlreadyOwned`：消耗後に再試行

消耗型アイテム（`PaymentProductType` の消耗型）は、付与後に消耗されていないと、次回の購入でこの結果コードが返されます：

1. `QueryPurchases(PaymentProductType)` を呼び出して購入履歴を照会します。
2. `OnQueryPurchasesResult` コールバック内で `PurchaseToken` を取り出します。
3. `ConsumePurchase(e.PurchaseToken)` を呼び出して消耗を完了します。
4. `Buy(purchaseParams)` を再度実行します。

関連シグネチャ（`IPaymentManager` で定義され、`BasePaymentManager` で抽象実装）：

```csharp
void QueryPurchases(PaymentProductType productType);
void ConsumePurchase(string purchaseToken);
```

出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L52-L63)

### `VerifyFailed`：検証モードを確認

`Init` の第 2 引数が検証方式を決定します：

```csharp
/// <param name="isClientVerify">購入成功時にクライアント側で検証を実行するかどうか。強ネットワーク検証の場合は有効にする必要はありません。false に設定してサーバー検証を行ってください</param>
void Init(bool isDebug = false, bool isClientVerify = false);
```

出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

サーバー検証を採用する場合は `false` を渡し、サーバー側で署名検証を行います。これにより、クライアント検証の失敗による `VerifyFailed` の誤検知を回避できます。

### `ServiceUnavailable`：準備状態を確認

購入前にまず `bool IsReady()` を呼び出します。未準備の場合、チャネル側の初期化が完了しておらず、`ServiceUnavailable` に該当します。また、`SetPredefinedProductIds` は初期化より前に呼び出す必要があります。そうしないと、プリロードキャッシュが有効になりません：

```csharp
void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds);
```

出典： [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

## 検証

- 購入キャンセルを 1 回トリガーし（サンドボックス環境でキャンセルを選択）、コールバックが `Cancelled` を受信し、例外ログが出力されないことを確認します。
- 既に所持しており未消耗のアイテムを再度購入し、`ItemAlreadyOwned` が返されること、`ConsumePurchase` 実行後に正常に再購入できることを確認します。
- `OnPurchaseFailed` 内で出力された `ErrorMessage` / `PurchaseData` の内容が完全であり、チャネルの管理コンソールと照合できることを確認します。

## 背景

各チャネル実装は `BasePaymentManager` を継承しており、`RaisePurchaseFailed` などの 4 つの protected メソッドを通じて統一的に結果イベントをトリガーするため、すべてのチャネルのコールバックにおける `PaymentEventArgs` の構造は一貫しています：

```csharp
protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}
```
