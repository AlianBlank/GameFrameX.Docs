# プレイヤー ID と共通プロパティの設定方法

`IGameAnalyticsManager` インターフェースの `SetPlayerId(string playerId)` と `SetPublicProperties(string key, object value)` の 2 つの呼び出しにより、ゲーム実行中以降のすべての送信イベントにプレイヤー識別子と共通プロパティを付加できます。フレームワークは初期化時に一連のデバイス共通プロパティを自動的に書き込んでいるため、業務フィールドを追加するだけで済みます。

## 前提条件

- プロジェクトに `com.gameframex.unity.gameanalytics` パッケージがインストールされ、`GameAnalyticsComponent` コンポーネントがアタッチ済みであること。
- `Init` / `ManualInit` を呼び出して初期化が完了していること(`IsInit()` で確認できます)。

## 操作手順

1. マネージャーインスタンスを取得します(`GameAnalyticsComponent` が公開するマネージャーインターフェースを通じて)。
2. プレイヤーのログイン成功後にプレイヤー ID を設定します:

```csharp
// プレイヤーのログイン成功後、プレイヤー ID をバインドします(以降のすべてのイベントにこの ID が付加されます)
GameAnalyticsComponent.Instance.SetPlayerId("123456789");
```

`SetPlayerId` のインターフェースシグネチャは `void SetPlayerId(string playerId)` で、`IGameAnalyticsManager` で定義されており、基底クラス `BaseGameAnalyticsManager` では抽象メソッドとして宣言され、各プラットフォームのサブクラスで実装されます:

```csharp
/// <summary>
/// プレイヤーIDを設定する
/// </summary>
/// <param name="playerId">プレイヤーID</param>
void SetPlayerId(string playerId);
```

出典： [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L100-L104)

3. 業務用の共通プロパティを追加します。1 回の呼び出しで 1 つのキーと値のペアを設定します:

```csharp
// 呼び出しごとに 1 つの Key を書き込みます。同じ Key を重複して設定すると古い値が上書きされます
GameAnalyticsComponent.Instance.SetPublicProperties("server_id", "s1001");
GameAnalyticsComponent.Instance.SetPublicProperties("vip_level", 5);
```

基底クラスの実装は空の Key を無視し、内部ディクショナリ `m_PublicProperties` に書き込みます:

```csharp
public virtual void SetPublicProperties(string key, object value)
{
    if (string.IsNullOrEmpty(key))
    {
        return;
    }

    m_PublicProperties[key] = value;
}
```

出典： [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L53-L65)

4. (任意)共通プロパティの読み取りまたはクリア:

```csharp
// 読み取り:内部ディクショナリのコピーを返します。コピーを変更しても実際の共通プロパティには影響しません
Dictionary<string, object> props = GameAnalyticsComponent.Instance.GetPublicProperties();

// 業務プロパティをクリアします。その後、デバイス情報の共通プロパティが自動的に再書き込みされます
GameAnalyticsComponent.Instance.ClearPublicProperties();
```

出典： [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L67-L83)

## 組み込みのデバイス共通プロパティ

初期化段階で、フレームワークは `AddDeviceInfoToPublicProperties()` を通じて以下の共通プロパティを自動的に書き込みます。手動で設定する必要はなく、`ClearPublicProperties()` 実行後も自動的に復元されます:

| 分類 | プロパティ Key |
|------|----------|
| デバイス | `device_id`、`device_model`、`device_type` |
| OS | `os` |
| アプリ | `app_version`、`unity_version`、`platform` |
| ハードウェア | `processor_type`、`processor_count`、`processor_frequency`、`system_memory_size` |
| グラフィックス | `graphics_device_name`、`graphics_device_type`、`graphics_memory_size`、`graphics_device_version`、`graphics_shader_level` |
| 画面 | `screen_width`、`screen_height`、`screen_dpi`、`screen_refresh_rate` |
| ローカライズ | `system_language`、`current_culture` |
| ネットワーク | `network_type`(値は `No Network` / `Mobile Data` / `WiFi` / `Unknown`) |

出典： [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L86-L144)

## よくあるバリエーション

- **アカウント切り替え**:まず `ClearPublicProperties()` で旧アカウントの業務フィールドをクリアしてから、`SetPlayerId` と `SetPublicProperties` を設定し直します。クリア後はデバイス情報のプロパティが自動的に復元されます。
- **組み込みプロパティの上書き**:カスタム Key が上の表と同じ場合、組み込み値が直接上書きされます(同一ディクショナリへの書き込み)。デバイスディメンションの情報が失われるのを避けるため、通常は避けることをお勧めします。

## よくある間違い

- **空の Key はサイレントに無視される**:`SetPublicProperties` は `string.IsNullOrEmpty(key)` の場合に直接 `return` するため、例外もスローされず書き込みも行われません。設定が反映されない場合は、まず Key が空でないか確認してください。
- **`ClearPublicProperties` はプレイヤー ID をクリアしない**:このメソッドは共通プロパティのディクショナリのみをクリアしてデバイスプロパティを再構築します。プレイヤー ID は別途 `SetPlayerId` で再設定する必要があります。
- **`GetPublicProperties` の戻り値はコピー**:`return new Dictionary<string, object>(m_PublicProperties);` であり、戻り値を直接変更しても実際に送信される共通プロパティには影響しません。

## 背景

共通プロパティは基底クラスの `m_PublicProperties` ディクショナリに格納され、イベント送信時にすべてのイベントとともに付加されます。比較的安定したディメンションフィールド(チャネル、サーバー、会員レベルなど)の格納に適しています。頻繁に変化する数値は、イベントのカスタムフィールド `Event(string eventName, Dictionary<string, object> customF)` で送信する方が適しています。
