# UI のオープンに失敗した場合の対処方法

`UIManager` を呼び出して FairyGUI の UI を開いたにもかかわらず UI が表示されない、または例外がスローされる / `OpenUIFormFailure` イベントが発生する。失敗箇所はほぼ次の 3 つです：リソースパスまたはパッケージ名の連結が正しくない、UI パッケージが正しくロードされていない、UI スクリプトタイプとコンポーネントが一致しない。まず下記の診断表で原因を特定し、対応する修正手順に従って処理してください。

## クイック診断

| 症状（ログ/現象の原文） | 原因 | 修正 |
|------|------|------|
| `GameFrameworkException: Load UI form failure, asset name 'XXX', error message '...'` が出力され、失敗イベントハンドラーが未登録の場合にスローされる | UI パッケージリソースのロード失敗：パスの誤り、パッケージが Bundles に含まれていない、YooAsset のエラー | 下記の「修正手順 1：リソースパスとパッケージ名ルールの確認」を参照 |
| `OpenUIFormFailure` イベントが発生するがコードはクラッシュしない | ロードには失敗したが `OpenUIFormFailureEventHandler` を登録しているため、エラーがイベントコールバックに変換されている | 「修正手順 2：失敗イベントを登録して実際のエラーを取得」を参照 |
| `Can not create UI form in UI form helper.` | `IUIFormHelper.CreateUIForm` が null を返す：UI スクリプトタイプ（`uiFormType`）とコンポーネントリソースが一致しない、または未登録 | 「修正手順 3：UI タイプとコンポーネント名の確認」を参照 |
| `Open UI form info is invalid.` | `OpenUIFormInfo` の参照が早期に解放された / 再利用プールの異常。通常は外部から内部処理を混用していることが原因 | `UIManager` の公開 API を迂回して内部メソッドを直接呼び出していないか確認 |
| `Log.Error("加载资源失败 Unknown file type: " + assetName + " extension: " + extension)` | FairyGUI の依存リソースの拡張子が認識されない（`_fui`/テクスチャなどの既知の型ではない） | 公開されたリソースファイルが完全であるか、拡張子が変更されていないかを確認 |
| UI が「開かれた」ように見えるが、取得したインスタンスが更新されない、イベントに応答しない | シングルトンモードで既に開かれている同名インスタンスにヒットし、そのまま再利用して返されている | 「修正手順 4：シングルトンのオープン動作を理解する」を参照 |

## 修正手順

### 修正手順 1：リソースパスとパッケージ名ルールの確認

UI を開く際、フレームワークは以下のルールに従い、`uiFormAssetPath` と UI タイプ名からすべてのアドレスを導出します（`UIManager.InnerLoadUIFormAsync` を参照）：

- `uiFormAssetName` = UI タイプ名 `uiFormType.Name`（**FairyGUI エディターでエクスポートされたコンポーネント名と一致している必要があります**）。
- `assetPath` = `uiFormAssetPath/uiFormAssetName`。
- `packageName` = `uiFormAssetPath` の最後の `/` 以降の部分。パスに `/` が含まれない場合、パス全体がパッケージ名になります。
- Bundles からロードする場合、実際にロードされるリソースは `uiFormAssetPath/packageName_fui` です。

```csharp
var uiFormAssetName = uiFormType.Name;
string assetPath = PathHelper.Combine(uiFormAssetPath, uiFormAssetName);

var lastIndexOfStart = uiFormAssetPath.LastIndexOf("/", StringComparison.OrdinalIgnoreCase);
// パスに / が含まれない場合、パス全体をパッケージ名として使用（Resources ディレクトリ下の単純なパスに適用）
var packageName = lastIndexOfStart >= 0 ? uiFormAssetPath.Substring(lastIndexOfStart + 1) : uiFormAssetPath;
// UIパッケージが既にロード済みか確認
var hasUIPackage = FairyGuiPackage.Has(packageName);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L127-L136)

調査ポイント：

1. `uiFormAssetPath` の末尾のディレクトリ名が FairyGUI で公開されたパッケージ名と一致していることを確認してください（例：パス `Assets/Bundles/UI/MainUI` からパッケージ名 `MainUI` が導出されます）。
2. UI クラス名（`uiFormType.Name`）とコンポーネント名が完全に一致していることを確認してください。大文字・小文字は区別されます。
3. Bundles 経由でロードする場合は `<uiFormAssetPath>/<packageName>_fui` リソースが存在することを確認してください。パッケージ名と UI 名が異なる場合、フレームワークは `uiFormAssetPath/packageName` でパスを再構築し、`_fui` を追記します：

```csharp
// 不一致の場合はパスを再構築
string newPackagePath = PathHelper.Combine(uiFormAssetPath, packageName);
await FairyGuiPackage.AddPackageAsync(newPackagePath);
...
newAssetPackagePath += "_fui";
// パッケージからロード
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(newAssetPackagePath);
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L163-L178)

4. `assetPath` に `Utility.Asset.Path.BundlesDirectoryName`（デフォルトの Bundles ディレクトリ名）が含まれない場合、フレームワークは **Resources モード** でパッケージを同期ロードします。この場合、該当パスが Resources 下に実際に存在することを確認してください：

```csharp
if (assetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    // Resources からロード
    if (!hasUIPackage)
    {
        FairyGuiPackage.AddPackageSync(assetPath);
    }

    return LoadAssetSuccessCallback(uiFormAssetPath, uiFormAssetName, openUIFormInfoData, 0, openUIFormInfo);
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L140-L149)

### 修正手順 2：失敗イベントを登録して実際のエラーを取得

ロード失敗は最終的に `LoadAssetFailureCallback` に到達します。エラーメッセージの形式は次の通り固定されています：

```text
Load UI form failure, asset name '{0}', error message '{1}'.
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L358-L368)

重要な動作は 2 つの場合に分かれます：

- `OpenUIFormFailureEventHandler` を購読している場合：エラーは `OpenUIFormFailureEventArgs` にラップされてイベントが発生し、メソッドは null を返し、例外はスローされません。
- 未購読の場合：`throw new GameFrameworkException(appendErrorMessage)` が直接実行され、例外は呼び出し元へ伝播します。

調査時は、まず失敗イベントを購読して `errorMessage` をログに出力することをお勧めします。そこに含まれる YooAsset/リソースのエラー情報が根本原因です。

### 修正手順 3：UI タイプとコンポーネント名の確認

`InternalOpenUIForm` 内で `IUIFormHelper.CreateUIForm` が null を返した場合、以下の例外がスローされます：

```csharp
IUIForm uiForm = m_UIFormHelper.CreateUIForm(uiFormInstance, uiFormType, userData);
if (uiForm == null)
{
    throw new GameFrameworkException("Can not create UI form in UI form helper.");
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L211-L217)

この例外も同様に `OpenUIFormFailure` イベントを（`exception.ToString()` を伴って）発生させた後、再スローされます。以下を確認してください：

1. 渡された `uiFormType` が登録済み/生成可能な `FUI` のサブクラスであるかどうか。
2. パッケージ内に同名のエクスポートされたコンポーネントが存在するかどうか。
3. `OnOpen`/`BindEvent`/`LoadData` の段階で例外がスローされた場合も、同様に失敗イベント + 再スローのパスを通ります（[Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L264-L273) を参照）。

### 修正手順 4：シングルトンのオープン動作を理解する

シングルトンモードで開かれた UI は、既に開かれているインスタンスにヒットした場合、再ロードせずにそのまま再利用してフォーカスします：

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    // Singleton behavior: if already opened, return the existing instance.
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L68-L84)

「開いた」後に動作が異常な場合は、まず `GetUIForm(uiFormAssetName)` で既存のインスタンスでないかを確認してください。ロード中の同名 UI は同じロード Task を再利用するため、重複ロードは行われません。実行時に UI 要素のパスが見つからない場合は、`FairyGUIPathFinderHelper` のエラーも参照してください：`error uiPath : can not found ui by this path :{path}` および `Invalid UI path: child not found`（[Runtime/FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L141-L191)）。

## 検証

1. オープン API を再度呼び出し、返される `IUIForm` が null でなく、かつ `SerialId > 0` であることを確認します。
2. `OpenUIFormSuccess` イベントが発生するか（[Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L255-L260)）、また `Load UI form failure` のログが表示されなくなったことを確認します。
3. 失敗イベントのコールバックが発生せず、コンソールに `GameFrameworkException` が出力されないことを確認します。
