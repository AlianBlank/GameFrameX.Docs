# 타이머 일시정지, 재개 및 제거

이미 생성된 타이머에 대해 `TimerManager`는 ID 기반의 `Pause` / `Resume` / `Remove`, 태그 기반의 `PauseByTag` / `ResumeByTag` / `RemoveByTag`, 그리고 관련 조회 기능(`IsPaused`, `Exists`, `HasTag`, `GetRemaining` 등)을 제공합니다. 모든 API는 `ITimerManager` 인터페이스에 정의되어 있으며, 가져온 `ITimerManager` 인스턴스에서 직접 호출하면 됩니다.

## 사전 조건

- 프로젝트에 GameFrameX Timer 컴포넌트가 연동되어 있고, `ITimerManager` 인스턴스를 보유하고 있어야 합니다(컴포넌트 진입점은 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs) 참조).
- `Add` / `AddOnce` / `AddUpdate`를 통해 타이머를 생성하고, 반환된 `int` 타입의 타이머 ID를 저장했거나, 생성 시 `tag` 태그를 지정했어야 합니다.

## 작업 단계

### 1. 단일 타이머 일시정지 및 재개

```csharp
ITimerManager timer; // GameFrameX 컴포넌트에서 가져옴

// interval=1초, repeat=0은 무한 반복을 의미
int id = timer.Add(1f, 0, obj => { /* 주기 로직 */ });

timer.Pause(id);              // 일시정지 중에는 시간이 누적되지 않음
bool paused = timer.IsPaused(id);  // true

timer.Resume(id);             // 일시정지 지점부터 시간 누적을 계속하며, 이미 누적된 시간은 손실되지 않음
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L74-L91)

### 2. 단일 타이머 제거

```csharp
timer.Remove(id);                        // ID로 제거
timer.Remove(new Action<object>(OnTick)); // 콜백으로 제거

bool alive = timer.Exists(id);           // 제거 후 false 반환
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L48-L72)

`Remove(int id)`는 내부적으로 먼저 ID를 콜백에 매핑한 다음, `Remove(Action<object>)`와 동일한 제거 경로를 실행하므로 두 가지 제거 방식의 효과는 동일합니다:

```csharp
public void Remove(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return;
        }

        Remove(callback);
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L376-L387)

### 3. 태그별 일괄 일시정지, 재개 및 제거

타이머 생성 시 `tag`를 전달하면 이후 그룹 단위로 작업할 수 있으며, "씬 전환 시 전투 관련 타이머를 일시정지"하는 것과 같은 요구 사항에 적합합니다:

```csharp
int id = timer.Add(5f, 0, obj => { /* ... */ }, null, "battle");

timer.PauseByTag("battle");   // 해당 태그의 모든 타이머를 일시정지
timer.ResumeByTag("battle");  // 해당 태그의 모든 타이머를 재개
timer.RemoveByTag("battle");  // 해당 태그의 모든 타이머를 제거

bool anyLeft = timer.HasTag("battle"); // 태그에 활성 타이머가 남아 있으면 true
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L93-L118)

`RemoveByTag`는 내부적으로 태그에 속한 ID 목록을 복사한 후 하나씩 `Remove(id)`를 호출하여, 반복 중 수정되는 것을 방지합니다:

```csharp
public void RemoveByTag(string tag)
{
    lock (Locker)
    {
        if (_tags.TryGetValue(tag, out var ids))
        {
            // Copy to avoid modification during iteration
            var idsCopy = new List<int>(ids);
            foreach (var id in idsCopy)
            {
                Remove(id);
            }
        }
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)

### 4. 상태 확인

| API | 반환값 | 설명 |
|------|--------|------|
| `IsPaused(int id)` | `bool` | 일시정지 중이면 `true` 반환; ID가 존재하지 않으면 `false` 반환 |
| `Exists(int id)` / `Exists(Action<object> callback)` | `bool` | 타이머가 존재하고 삭제되지 않았으면 `true` 반환 |
| `HasTag(string tag)` | `bool` | 태그에 최소 하나의 타이머가 존재하면 `true` 반환 |
| `GetRemaining(int id)` | `float` | 남은 초; ID가 존재하지 않거나 아직 활성화되지 않았으면 `-1` 반환; `interval <= 0` 또는 무한 반복이면 `0` 반환 |
| `GetElapsed(int id)` | `float` | 누적된 초; ID가 존재하지 않으면 `-1` 반환 |
| `GetRepeatLeft(int id)` | `int` | 남은 반복 횟수(`0`은 무한을 의미); ID가 존재하지 않으면 `-1` 반환 |

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L120-L142)

## 일반적인 변형

**비동기 대기 취소.** `WaitForSecondsAsync` 등의 확장 메서드를 사용하는 경우, "제거"는 `CancellationToken`을 통해 수행됩니다: 토큰이 취소되면 `TaskCompletionSource`가 취소 상태로 설정되고, 대기 중인 쪽은 취소된 Task를 받게 됩니다.

```csharp
var tcs = new TaskCompletionSource<bool>();
var registration = cancellationToken.Register(() => tcs.TrySetCanceled(cancellationToken));
```

## 일반적인 오류

- **존재하지 않거나 이미 제거된 ID에 대해 `Pause` / `Resume` / `Remove` 호출**: 구현 내부에서 바로 `return`하며 예외를 던지지 않지만, 아무 효과도 없습니다; 작업 후 `Exists(id)`로 다시 확인하세요.
- **Add 직후 바로 `Pause(id)`하면 적용되지 않을 수 있음**: 타이머가 아직 추가 대기 큐(`_toAdd`)에 남아 있는 경우, `Pause`는 플래그를 설정하기 전에 바로 반환되어 no-op이 됩니다; 활성 목록에 들어간 후 일시정지하면 됩니다.

  ```csharp
  // Timer in _toAdd (pending): also pausable
  if (_toAdd.ContainsKey(callback))
  {
      return;
  }
  ```

  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L404-L413)
- **`GetRemaining(id)`이 `-1`을 반환하는 것이 반드시 오류는 아님**: ID가 존재하지 않거나, 이미 제거되었거나, 타이머가 아직 활성 목록에 들어가지 않은 경우 모두 `-1`을 반환합니다(`GetRemaining` 구현의 반환 경로 참조).
- **제거 시 `onComplete`가 트리거됨**: `Add(..., Action onComplete = null)`의 인터페이스 주석에 해당 콜백이 "타이머 완료/제거 시" 트리거된다고 명시되어 있으므로, 직접 `Remove`할 때 호출될 것을 예상해야 합니다.
- **일시정지 ≠ 제거**: 일시정지된 타이머는 여전히 관리자의 항목 목록에 유지되며, 시간 누적만 건너뛸 뿐 해제되지 않습니다; 더 이상 사용하지 않는 것이 확실하면 `Remove`를 호출해야 합니다.

## 배경

`TimerManager`는 내부적으로 각 타이머에 대해 하나의 항목(`Deleted`, `IsPaused`, `PausedElapsed` 등 필드)을 유지하며, 업데이트 루프에서 `IsPaused == true`인 항목을 만나면 경과 시간 누적을 건너뛰지만 `_items`에는 유지하므로, 재개 후 일시정지 지점부터 계속할 수 있습니다. 모든 일시정지/재개/제거 작업은 `lock (Locker)` 보호하에 실행되므로, 메인 스레드가 아닌 곳에서도 안전하게 호출할 수 있습니다.
