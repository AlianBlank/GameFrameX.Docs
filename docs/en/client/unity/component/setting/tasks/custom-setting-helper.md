# Implementing a Custom Storage Helper

Inherit from [SettingHelperBase](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44) and implement all members of `ISettingHelper`, then route reads and writes to your own storage medium (database, encrypted file, remote API, etc.). The framework will call your Helper via `SettingComponent` during startup to perform loading and saving.

## Prerequisites

- The `com.gameframex.unity.setting` package is installed and `SettingComponent` is visible in the Inspector.
- Familiarity with C# abstract classes and the `MonoBehaviour` lifecycle—the Helper must be attached to a GameObject in the scene.
- Your own storage medium (e.g., SQLite, local encrypted file, remote key-value service, etc.).

## Steps

1. **Create the Helper class that inherits from the base class**.
   Create a new script `Assets/Scripts/MySettingHelper.cs` that inherits from `GameFrameX.Setting.Runtime.SettingHelperBase`. The base class is itself an abstract `MonoBehaviour`, and the framework uses it to obtain all `ISettingHelper` members.

   ```csharp
   using GameFrameX.Setting.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
   }
   ```

   Source: [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44)

2. **Implement the required abstract members**. The reference table for the abstract members declared by the base class is shown below; all must be implemented using `override`:

   | Member | Signature | Suggested Behavior |
   |------|------|---------|
   | `Count` | `int Count { get; }` | Return `-1` if not supported (refer to the approach in `PlayerPrefsSettingHelper`) |
   | `Load()` | `bool Load()` | If no preloading is needed, simply return `true` |
   | `Save()` | `bool Save()` | Return only after actually persisting |
   | `GetAllSettingNames()` | `string[] GetAllSettingNames()` | If not supported, log a warning via `Log.Warning` and return `null` |
   | `GetAllSettingNames(List<string>)` | `void GetAllSettingNames(List<string> results)` | Throw `GameFrameworkException("Results is invalid.")` when `results == null`; otherwise call `results.Clear()` |
   | `HasSetting` / `RemoveSetting` / `RemoveAllSettings` | See the interface | Delegate to your own storage |
   | `GetBool/Int/Float/String`, `SetBool/Int/Float/String` | See the interface | Delegate to your own storage; return the agreed default value when the key does not exist |

   For full signatures, see [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L42-L42) and [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L43-L43).

3. **Delegate reads and writes to the concrete storage**. Minimal example: simulate storage with an in-memory dictionary.

   ```csharp
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
       private readonly Dictionary<string, string> _store = new Dictionary<string, string>();

       public override int Count => _store.Count;

       public override bool Load() { return true; }

       public override bool Save() { /* Write back to file/database */ return true; }

       public override bool HasSetting(string settingName) => _store.ContainsKey(settingName);

       public override bool RemoveSetting(string settingName) => _store.Remove(settingName);

       public override void RemoveAllSettings() => _store.Clear();

       public override void SetString(string settingName, string value) => _store[settingName] = value;

       public override string GetString(string settingName, string defaultValue)
           => _store.TryGetValue(settingName, out var v) ? v : defaultValue;

       // Bool/Int/Float follow the same pattern; bool can be stored as 0/1 via SetInt/GetInt, refer to PlayerPrefsSettingHelper.
   }
   ```

   Source: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L42-L42) (the standard implementation example for the base class, demonstrating how to delegate `GetBool`/`SetBool` to the underlying `StorageBackend.GetInt/SetInt`)

4. **Attach the script to a GameObject in the scene**. `SettingHelperBase` inherits from `MonoBehaviour` and must be attached to a GameObject so that `SettingComponent` can discover and instantiate it.

5. **Select `Custom Setting Helper` in `SettingComponent`'s Inspector**. Set `Setting Helper Type` to your `MySettingHelper`; the framework will reflectively create this Helper during startup.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs) (`SettingComponent` is responsible for creating and holding the `ISettingHelper` instance)

## Common Variants

- **Don't modify the Helper, just switch the underlying storage backend**: If you want to keep using `PlayerPrefsSettingHelper` but route the storage through SQLite or the WeChat Mini Game SDK, simply implement an `ISettingStorageBackend` and register it at startup via `SettingStorageBackendFactory.RegisterMiniGameBackend`. `PlayerPrefsSettingHelper` lazily loads that backend internally via the `StorageBackend` property.

  ```csharp
  // At platform startup (only takes effect outside UNITY_EDITOR)
  SettingStorageBackendFactory.RegisterMiniGameBackend(() => new MySqliteBackend());
  ```

  Source: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

- **Mini Game platform implementation reference**: `WeChatMiniGameSettingStorage`, `AlipayMiniGameSettingStorage`, etc. already wrap the platform-native APIs according to the `ISettingStorageBackend` interface and can be used as a minimal viable implementation example.

  Source: [WeChatMiniGameSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/MiniGame/WeChat/WeChatMiniGameSettingStorage.cs), [Storage/ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs)

## Common Mistakes

- **Not inheriting from `SettingHelperBase`**: You can directly implement `ISettingHelper`, but `SettingComponent` typically scans for `SettingHelperBase` derivatives; maintaining the inheritance relationship is safer.
- **Helper not attached to a scene object**: `SettingHelperBase` is a `MonoBehaviour`; when it is not attached, the framework cannot instantiate it, and at runtime you will either get the default implementation or an exception will be thrown.
- **Missing the `results == null` check in `GetAllSettingNames(List<string>)`**: The base class expects a `GameFrameworkException("Results is invalid.")` to be thrown; other framework modules depend on this contract.
- **Accessing Unity runtime APIs such as `UnityEngine.PlayerPrefs` in the Helper's constructor**: Do not access Unity APIs during static construction or field initialization—do it in `Load()` or on first access.
- **Save logic swallows exceptions**: A write failure should return `false` so that `SettingComponent` can detect the failure and notify the user; do not silently `try/catch` and return `true`.

## Background (Optional)

`PlayerPrefsSettingHelper` delegates all reads and writes to `ISettingStorageBackend`, which is created by `SettingStorageBackendFactory`—using `UnityPlayerPrefsSettingStorage` under `UNITY_EDITOR`, and using factories registered by each platform's adapter on real-device Mini Game platforms. This is a quick path to "switch the underlying storage without rewriting the Helper". You only need to implement a custom `SettingHelperBase` derivative following the steps on this page when your business truly requires a brand-new Helper behavior (e.g., remote fetching, encryption, cross-process synchronization).
