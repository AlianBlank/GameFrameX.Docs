# 객체 스토리지 업로드 실패 시 대처법

빌드 프로세스에서 `-IsUploadLogFile` 또는 `-IsUploadAsset`이 트리거되었지만 로그/리소스가 객체 스토리지 버킷에 나타나지 않는 경우, 이 페이지의 진단표를 따라 항목별로 점검하세요.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| 로그에 `The type or namespace name 'ObjectStorageUploadManager' could not be found` 표시됨 | 프로젝트에서 객체 스토리지 모듈이 활성화되지 않음 | `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 매크로에 해당하는 Package Manager에서 객체 스토리지 컴포넌트를 설치 및 활성화 |
| 명령줄에 자격 증명이 전달되지 않아 실행 후 업로드 동작이 전혀 없음 | `-IsUploadLogFile` 누락, 또는 해당 매크로가 활성화되지 않음 | 아래 "스위치가 켜져 있지 않음" 섹션 참조 |
| 업로드 호출에서 403 / SignatureDoesNotMatch 발생 | 자격 증명 불일치 또는 읽기/쓰기 권한 부족 | 아래 "자격 증명 또는 권한 오류" 섹션 참조 |
| `NoSuchBucket` / `InvalidBucketName` 발생 | 버킷명 오타 또는 지정된 리전에 버킷이 생성되지 않음 | 아래 "버킷명 또는 Endpoint 오류" 섹션 참조 |
| 업로드 완료되었으나 버킷에서 파일이 보이지 않음 | Endpoint 리전 불일치로 파일이 다른 리전에 업로드됨 | 아래 "리전 불일치" 섹션 참조 |
| 빌드 프로세스가 `BuildReady` 단계에서 중단됨 | `UploadFile` 호출 시 잡히지 않은 예외 발생 | 아래 "예외가 무시됨" 섹션 참조 |

## 해결 단계

### 1. 스위치가 켜져 있지 않음 (가장 흔함)

빌드 스크립트는 두 조건이 동시에 충족될 때만 업로드를 호출합니다: [`Builder.BuildReady.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L44-L49)의 `if (_builderOptions.IsUploadLogFile)`가 `#if ENABLE_GAME_FRAME_X_OBJECT_STORAGE`로 감싸여 있습니다. 즉, `-IsUploadLogFile`을 전달했더라도 프로젝트에서 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 매크로가 정의되지 않았다면 코드가 컴파일러에 의해 완전히 제거되어 실행 시 아무 출력도 나타나지 않습니다.

확인 방법:

1. 명령줄에 `-IsUploadLogFile`이 포함되어 있는지 확인 (값 불필요, [`Builder.BuildParamsParse.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L94-L96) 참조).
2. `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`가 프로젝트의 `Scripting Define Symbols`에 정의되어 있는지 확인.
3. `GameFrameX.ObjectStorage` 패키지가 Package Manager를 통해 설치되어 있는지 확인, 그렇지 않으면 `ObjectStorageUploadManager` 타입을 찾을 수 없음.

```text
-ExecuteMethod GameFrameX.Builder.Editor.Builder.BuildReady \
-IsUploadLogFile \
-ObjectStorageKey <your-key> \
-ObjectStorageSecret <your-secret> \
-ObjectStorageBucketName <your-bucket> \
-ObjectStorageEndPoint <your-endpoint>
```

매개변수 정의는 [`BuilderOptions.cs`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40) 참조. 네 개의 객체 스토리지 필드는 모두 기본값이 빈 문자열이므로, 하나라도 누락되면 SDK가 요청 시 직접 예외를 던집니다.

### 2. 자격 증명 또는 권한 오류

`ObjectStorageUploadManager.UploadFile`은 내부적으로 전달받은 Key/Secret을 사용해 서명을 생성합니다. 키를 복사할 때 문자가 누락되거나 공백이 추가되었거나, 서브 계정에 해당 버킷의 `PutObject` 권한이 없으면 `403 SignatureDoesNotMatch` 또는 `AccessDenied`가 직접 발생합니다.

1. 객체 스토리지 콘솔에서 Key와 Secret을 다시 복사하여 수동 입력을 피하세요.
2. 해당 서브 계정에 버킷의 읽기/쓰기 권한을 부여하세요 (Aliyun OSS / Tencent Cloud COS / MinIO 모두 동일한 개념).
3. 임시 STS 자격 증명을 사용하는 경우, `ObjectStorageKey/Secret`이 STS 3요소 정보의 `AccessKeyId/SecretAccessKey`이며 `SessionToken`이 아닌지 확인하세요.

### 3. 버킷명 또는 Endpoint 오류

`ObjectStorageBucketName`은 콘솔에 표시되는 버킷의 정식 이름이어야 하고, `ObjectStorageEndPoint`는 해당 버킷이 있는 리전의 외부/내부 네트워크 도메인이어야 합니다. 두 값이 일치하지 않으면 `NoSuchBucket` 또는 `InvalidBucketName`이 발생합니다.

1. 객체 스토리지 콘솔에 로그인하여 버킷 이름과 리전을 확인하세요.
2. `ObjectStorageEndPoint`를 해당 리전 공식 문서의 Endpoint로 변경하세요 (예: Aliyun 화동 1: `oss-cn-hangzhou.aliyuncs.com`).
3. 빌드를 다시 트리거하여 콘솔의 `Object Storage → 파일 관리`에서 업로드된 로그 파일을 확인할 수 있는지 확인하세요.

### 4. 리전 불일치

요청은 성공했고 콘솔에서 200을 반환했지만 버킷에서 파일이 보이지 않는 경우 — 보통 Endpoint가 다른 리전을 가리키고 있어 파일이 "올바른" 버킷의 다른 리전 동일명 버킷에 업로드된 경우입니다 (프라이빗 클라우드/리전 간 복제 시나리오에서 흔함).

1. `ObjectStorageEndPoint`와 버킷이 속한 Region이 완전히 일치하는지 확인하세요.
2. 콘솔의 "버킷 목록"에서 리전별로 필터링하여 대상 버킷이 해당 리전에 존재하는지 확인하세요.

### 5. 예외가 무시됨

`BuildReady`에서 `UploadFile`을 호출할 때 예외가 발생하면 기본적으로 빌드 프로세스가 중단되며, 로그에서 `ObjectStorageUploadManager`가 던진 원본 예외 스택트레이스를 확인할 수 있습니다. 스택트레이스의 첫 줄 키워드를 진단표의 해당 행에 붙여넣고 위 1~4단계에 따라 처리하세요.

예외가 외부 Jenkins/CI 스크립트에 의해 무시되어 스택트레이스가 보이지 않는 경우, `BuildReady` 뒤에 임시로 `Debug.Log($"Upload finished: {_builderOptions.LogFilePath}")` 한 줄을 추가하여 코드가 실제로 업로드 분기에 진입하는지 검증할 수 있습니다.

## 검증

1. 명령줄에 `-IsUploadLogFile`과 네 개의 객체 스토리지 매개변수가 모두 포함된 상태로 빌드를 다시 실행하세요.
2. 객체 스토리지 콘솔의 해당 버킷에서 업로드 시간을 기준으로 정렬하여 로그 파일이 나타나는지 확인하세요.
3. 해당 로그 파일을 다운로드하여 이번 빌드의 `BuildReady Start` / `BuildReady End` 라인이 포함되어 있는지 확인하고, 로컬 Unity 콘솔 출력과 일치하는지 검증하세요.

## 배경 (선택)

업로드 호출은 모두 외부 `GameFrameX.ObjectStorage` 패키지의 `ObjectStorageUploadManager.UploadFile`에 위임됩니다. 본 저장소는 [`BuilderOptions`](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L23-L40)로 네 개의 명령줄 매개변수를 그대로 전달할 뿐이며, 어떤 SDK도 직접 조작하지 않습니다.
