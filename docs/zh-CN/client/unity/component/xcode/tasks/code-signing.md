# 配置代码签名

在 `XCodeConfig.json` 配置文件的 `signing` 节点填入 Team ID、包名、签名身份等字段,Unity 导出 iOS 工程后,构建后处理会自动把这些值写入 Xcode 主 Target(Unity-iPhone)的构建设置,无需手动在 Xcode 里改签名。

## 前置条件

- Unity iOS 平台已可正常出包(PostProcessBuildPlayer 阶段会执行本组件)。
- 已在工程中放置 `XCodeConfig.json` 配置文件;没有的话可参考仓库中的 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) 或 [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json) 创建。
- 手动签名(Manual)模式需要事先在 Apple Developer 后台创建好 Provisioning Profile,并在本机安装对应证书。

## 操作步骤

1. 打开(或新建)工程中的 `XCodeConfig.json`,在顶层加入 `signing` 节点。仓库自带 Demo 的写法如下:

```json
{
  "swiftBridging": true,
  "signing": {
    "teamId": "XXXXXXXXXX",
    "codeSignStyle": "Automatic",
    "provisioningProfileSpecifier": ""
  }
}
```

Source: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L2-L9)

2. 按下表填写 `signing` 内的字段。全部字段都是可选的,留空或缺失时该构建设置保持 Unity 导出时的默认值;`signing` 节点只在主项目(Unity-iPhone Target)上生效。

| 字段 | 对应构建设置 | 说明 |
|------|--------------|------|
| `teamId` | `DEVELOPMENT_TEAM` | Apple Developer Team ID |
| `bundleId` | `PRODUCT_BUNDLE_IDENTIFIER` | 应用包名 |
| `codeSignIdentity` | `CODE_SIGN_IDENTITY` | 签名证书身份 |
| `codeSignStyle` | `CODE_SIGN_STYLE` | 签名方式,`Automatic` 或 `Manual` |
| `provisioningProfileSpecifier` | `PROVISIONING_PROFILE_SPECIFIER` | 描述文件名称(仅 Manual 模式需要) |

字段含义与映射关系均来自模板文件中的注释与 `SetSigning` 的实现:

```csharp
private static void SetSigning(PBXProject proj, string targetGuid, Hashtable signing)
{
    if (signing == null) return;

    var teamId = signing.Get<string>("teamId");
    if (!string.IsNullOrEmpty(teamId))
    {
        proj.SetBuildProperty(targetGuid, "DEVELOPMENT_TEAM", teamId);
    }

    var bundleId = signing.Get<string>("bundleId");
    if (!string.IsNullOrEmpty(bundleId))
    {
        proj.SetBuildProperty(targetGuid, "PRODUCT_BUNDLE_IDENTIFIER", bundleId);
    }
    // codeSignIdentity / codeSignStyle / provisioningProfileSpecifier 同样按非空才写入
}
```

Source: [PostProcessBuildHelper.Signing.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Signing.cs#L15-L48)

3. 使用自动签名时,只需 `teamId` + `codeSignStyle: "Automatic"`,Xcode 会自动管理证书和描述文件。

4. 使用手动签名时,补全证书与描述文件信息:

```json
{
  "signing": {
    "teamId": "你的TeamID",
    "bundleId": "com.yourcompany.yourapp",
    "codeSignStyle": "Manual",
    "provisioningProfileSpecifier": "你的描述文件名称"
  }
}
```

描述文件名称需与 Apple Developer 后台创建的 Profile 名称一致,模板注释明确标注该字段"仅 Manual 模式需要"(见 [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json#L14-L15))。

5. 导出 iOS 工程(或执行构建)。后处理读取所有 `XCodeConfig.json` 并合并,随后在主 Target 上调用签名设置:

```csharp
// 设置签名配置（只在主项目上设置）
SetSigning(project, project.GetUnityMainTargetGuid(), finalConfig.Get<Hashtable>("signing"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L96-L97)

6. 验证:打开生成的 Xcode 工程,选中 Unity-iPhone Target → Signing & Capabilities,确认 Team、Bundle Identifier、Provisioning Profile 与配置一致;或直接在终端执行 `xcodebuild -showBuildSettings | grep -E "DEVELOPMENT_TEAM|CODE_SIGN"` 查看。

## 常见变体

**按渠道覆盖签名配置。** 后处理会先合并所有通用的 `XCodeConfig.json`,再合并渠道专属配置 `XCodeConfig.{channel}.json`,渠道配置优先级最高、最后合并覆盖。因此可以为不同渠道(如不同包名的马甲包)各放一个渠道文件,只写 `signing` 里的差异字段:

```json
{
  "signing": {
    "bundleId": "com.yourcompany.app.channelA"
  }
}
```

渠道文件命名格式与合并顺序见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L76) 与 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L80-L83)。

**通过 ScriptableObject 配置。** 仓库还提供 `XcodeConfig` ScriptableObject(菜单 `XcodeConfig/Create Settings`),可用于在 Inspector 中维护环境变量、Plist、Capabilities 等配置,见 [XcodeConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XcodeConfig.cs#L10-L31)。签名相关的 JSON 字段仍以 `signing` 节点为准。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台输出 `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 工程内没有可被扫描到的 `XCodeConfig.json` | 按模板放置配置文件后再导出 |
| 控制台输出 `合并后的配置为空，跳过设置` | 配置文件存在但 JSON 解析结果为空 | 检查 JSON 语法是否正确 |
| `未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json`(仅 Log) | 设置了渠道但没有对应渠道文件 | 属提示信息;需要差异配置时补建 `XCodeConfig.{channel}.json` |
| 导出后 Xcode 中 Team 仍为空 | `teamId` 留空或写错字段名(字段非空才会写入) | 核对字段名拼写与大小写:`teamId`、`bundleId`、`codeSignIdentity`、`codeSignStyle`、`provisioningProfileSpecifier` |
| 手动签名时报描述文件不匹配 | `provisioningProfileSpecifier` 与实际 Profile 名称不一致,或本机未安装对应证书 | 核对 Profile 名称并安装证书 |

上表中的日志原文来自配置加载与合并流程,见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83)。

## 背景

签名设置发生在 Unity 的 PostProcessBuild 阶段:组件读取工程内所有 `XCodeConfig.json` 合并成最终配置,解析生成的 `Unity-iPhone.xcodeproj/project.pbxproj`,仅在主 Target(UnityMainTarget)上写入签名相关构建设置,然后把工程写回磁盘。所有签名字段都遵循"非空才写入"的原则,因此可以只配置需要的字段。另外,`signing.bundleId` 还会被传给 Capabilities 处理,用于配合 entitlements 的设置(见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L116-L119))。
