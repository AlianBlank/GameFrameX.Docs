# How to Configure Cache Path and Capacity

Through `ImageCacheConfig`, you can set the disk cache path, maximum capacity, and expiration days. When the component `Awake`s, it syncs the Inspector configuration to `IImageCacheManager.Config`. When no path is specified, it defaults to `cache/images/` under `Application.persistentDataPath`.

## Prerequisites

- `ImageCacheComponent` has been attached to the scene entry GameObject.
- `ImageCacheManager` has been registered in `GameFrameworkEntry` (the component's `Awake` internally creates it via reflection using `componentType`).

## Steps

1. Select the GameObject with `ImageCacheComponent` attached in the scene. The Inspector will display the **Image Cache Config** section, containing three fields: `Cache Path`, `Max Disk Size (Bytes)`, and `Expire Days`.

2. Set the cache directory path `Cache Path`. When left empty, `PathHelper.AppHotfixResPath + "/cache/images/"` is used as the default directory. If a custom path is used, ensure the process has read/write permissions on the directory. The manager will automatically create the directory as needed if it does not exist.

```csharp
[SerializeField]
private string m_CachePath;
public string CachePath { get; set; }
```

Source: [ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L12-L44)

3. Set the maximum disk capacity `MaxDiskSize` (in bytes). `0` means no limit.

```csharp
[SerializeField]
private long m_MaxDiskSize;
public long MaxDiskSize { get; set; }
```

Source: [ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L18-L53)

4. Set the expiration days `ExpireDays`. `0` means never expires.

```csharp
[SerializeField]

public int ExpireDays { get; set; }
```

Source: [ImageCacheConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheConfig.cs#L24-L62)

5. Runtime configuration sync: the component's `Awake` syncs the serialized fields to the manager, no manual call is required.

```csharp
_imageCacheManager.Config.CachePath = string.IsNullOrEmpty(m_Config.CachePath)
    ? PathHelper.AppHotfixResPath + "/cache/images/"
    : m_Config.CachePath;
_imageCacheManager.Config.MaxDiskSize = m_Config.MaxDiskSize;
_imageCacheManager.Config.ExpireDays = m_Config.ExpireDays;
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L49-L53)

## Common Variants

- **Modifying configuration at runtime**: Obtain the configuration object via `ImageCacheComponent.Config`, and directly assign values to `CachePath`, `MaxDiskSize`, and `ExpireDays`. Subsequent `LoadImageAsync` calls will use the new values.
- **WebGL platform**: Cache is managed by the browser; `CachePath`/`MaxDiskSize`/`ExpireDays` have no effect. `IsCached` always returns `false`, and calls to `RemoveCache` and `ClearCache` will output the warning `ImageCache: ... is not supported on WebGL.`.
- **Non-WebGL platforms**: Cache files use the MD5 of the URL as the filename with a `.png` extension; the path format is `CachePath/<md5>.png`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Startup log `ImageCache manager is invalid.` | `IImageCacheManager` implementation not registered or `componentType` is misconfigured | Check `Component Type` in the Inspector, ensuring it resolves to `ImageCacheManager` |
| Startup log `Download manager is invalid. (non-WebGL)` | `IDownloadManager` not registered | Confirm that the download module has been loaded in `GameFrameworkEntry` |
| Calling `RemoveCache` / `ClearCache` outputs the warning `not supported on WebGL.` | WebGL does not use disk cache | Use browser cache or call `UnityWebRequest` to handle it yourself |
| Permission error after customizing `CachePath` | Path is not writable | Use a subdirectory of `Application.persistentDataPath` or ensure the directory is writable |

## Background (Optional)

`ImageCacheConfig` is a `[Serializable]` class, serialized by `ImageCacheComponent.m_Config`, and exposed in the Inspector via `ComponentTypeComponentInspector`. `MaxDiskSize` and `ExpireDays` are only retained as configuration items; the current `ImageCacheManager` does not perform cleanup based on these two during the loading process, so cleanup must be initiated by the business side by calling `ClearCache`.
