# 多言語アプリ名の設定

ビルド設定 JSON の `localizations` 配列で各言語に対して `languageCode` と `validMap`（`CFBundleDisplayName` キーを含む）を宣言すると、ビルド後処理によって Xcode プロジェクトディレクトリ配下に `{languageCode}.lproj/InfoPlist.strings` が自動生成され、ファイルがメイン target の Resources に追加され、`Info.plist` に `LSHasLocalizedDisplayName = true` が書き込まれ、iOS のホーム画面アイコンの下に対応言語の名称が表示されるようになります。

## 前提条件

- Unity が iOS プラットフォームに切り替えられており、本パッケージ（`com.gameframex.unity.xcode`）がインストール済みであること。
- プロジェクトが `PostProcessBuildHelper` のビルド後処理フローに接続済みであること——ローカライズロジックはこのフローから一元的にトリガーされます（[PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126) を参照。マージ後の設定から `localizations` フィールドを読み取ります）。

## 操作手順

1. iOS ビルド設定 JSON に `localizations` 配列を追加します（`podInstall`、`capabilities` などのフィールドと同階層）：

   ```json
   "localizations": [
     {
       "languageCode": "en",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "My Game" }
       ]
     },
     {
       "languageCode": "zh-Hans",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "我的游戏" }
       ]
     }
   ]
   ```

   フィールドの意味：

   | フィールド | 型 | 説明 |
   |------|------|------|
   | `localizations` | array | ローカライズ設定のリスト。各項目が 1 つの言語に対応します |
   | `languageCode` | string | 言語コード。`{languageCode}.lproj` ディレクトリ名として使用されます（例：`en.lproj`、`zh-Hans.lproj`）。空または欠落している場合、そのエントリはスキップされます |
   | `validMap` | array | キーと値のペアのリスト。各項目には `key` と `value` が含まれます。空または欠落している場合、そのエントリはスキップされます |
   | `key` | string | Info.plist のキー名。アプリ名のローカライズには固定で `CFBundleDisplayName` を使用します |
   | `value` | string | 該当言語での表示テキスト |

   設定例の構造は [README.zh-TW.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-TW.md#L323-L346) の `localizations` セクションの書き方と一致しています。`languageCode` / `validMap` のフィールド名は [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L52) の実際の読み取りロジックに準拠します。

2. iOS ビルドを実行します。後処理が以下の動作を自動的に完了します（手動での介入は不要です）：

   ```csharp
   foreach (Hashtable loc in localizations)
   {
       ...
       // Create .lproj directory
       string lprojName = langCode + ".lproj";
       string lprojPath = Path.Combine(path, lprojName);
       if (!Directory.Exists(lprojPath))
       {
           Directory.CreateDirectory(lprojPath);
       }

       // Prepare InfoPlist.strings content
       StringBuilder sb = new StringBuilder();
       foreach (Hashtable map in validMap)
       {
           if (map.ContainsKey("key") && map.ContainsKey("value"))
           {
               string key = map["key"].ToString();
               string value = map["value"].ToString();
               sb.Append($"\"{key}\" = \"{value}\";\n");

               // CFBundleDisplayName が含まれているか確認
               if (key == "CFBundleDisplayName")
               {
                   hasLocalizedDisplayName = true;
               }
           }
       }
       ...
   }
   ```

   Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L91)

3. 生成結果を確認します。生成された `en.lproj/InfoPlist.strings` の内容は以下のようになります：

   ```text
   "CFBundleDisplayName" = "My Game";
   ```

   生成フォーマットは `sb.Append($"\"{key}\" = \"{value}\";\n")` によって決定されます。[PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L62-L90) を参照してください。

## よくあるバリエーション

- **他の Info.plist キーも同時にローカライズする**：`validMap` には権限の説明などのキーと値のペアをさらに追加できます。それらは同じ `InfoPlist.strings` に書き込まれます：

  ```json
  "validMap": [
    { "key": "CFBundleDisplayName", "value": "我的游戏" },
    { "key": "NSCameraUsageDescription", "value": "需要访问相机用于扫描二维码" }
  ]
  ```

- **さらに多くの言語**：`localizations` 配列にエントリを追加するだけで、各言語ごとに 1 つの `.lproj` ディレクトリと 1 つの `InfoPlist.strings` が生成されます。

- **ローカライズを無効にする**：`localizations` を空の配列 `[]` にするか、このフィールドを設定しなければ、後処理は即座にリターンし、いかなる変更も行いません（[PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L20-L23) を参照）。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| ビルド後に `.lproj` ディレクトリが生成されない | `localizations` が空/未設定、またはエントリに `languageCode`、`validMap` が欠けている | 設定がマージ後の最終設定に反映されていること、および各エントリに空でない `languageCode` と空でない `validMap` が付いていることを確認してください（欠落したエントリは `continue` でスキップされます） |
| 権限の説明だけがローカライズされ、ホーム画面の名称が英語のまま | `validMap` に `CFBundleDisplayName` がない | アプリ名のローカライズにはキー名 `CFBundleDisplayName` を使用する必要があります。これは同時に `LSHasLocalizedDisplayName` をトリガーする唯一の条件でもあります |
| `InfoPlist.strings` が Xcode プロジェクトに入っていない（表示言語がデフォルトにフォールバックする） | ファイルが Resources ビルドフェーズに追加されていない | 後処理は `project.AddFile(...)` + `project.AddFileToBuild(mainTargetGuid, fileGuid)` で注入します。下記を参照してください。プロジェクトファイルを手動で削除したことがある場合は、再ビルドしてください |
| ビルドログに `InfoPlist.strings not found at: ...` が出る | `.lproj` ディレクトリ下のファイルが外部スクリプトによって削除された、または生成されなかった | ローカライズより前に他の後処理スクリプトがディレクトリをクリアしていないか確認し、再ビルドしてください |

## 背景

トリガーチェーン：`PostProcessBuildHelper` は設定をマージした後、`RunLocalization(project, project.ProjectGuid(), path, finalConfig.Get("localizations") as ArrayList)` を呼び出します（[PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126) を参照）。`RunLocalization` はファイル生成後、`CFBundleDisplayName` を検出すると `Info.plist` の `LSHasLocalizedDisplayName` を `true` に設定し（[PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L97-L108)）、その後 `AddLocalizationToProject` によって各 `InfoPlist.strings` がメイン target の Resources に追加され、`project.pbxproj` に書き戻されます：

```csharp
// PBXProject API を使用してファイルをプロジェクトに追加
string fileGuid = project.AddFile(infoPlistStringsPath, infoPlistStringsPath, PBXSourceTree.Source);

// ファイルをメイン target の Resources ビルドフェーズに追加
project.AddFileToBuild(mainTargetGuid, fileGuid);

LogHelper.Log($"Added localization file to project: {infoPlistStringsPath}");
```

Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L194-L205)

iOS ビルド後処理全体のフローとその他の設定項目については、『iOS ビルド後処理設定リファレンス』を参照してください。
