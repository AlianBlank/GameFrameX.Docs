# 配置 App 能力（Capabilities）

在构建后处理的 JSON 配置文件中填写 `capabilities` 字段，Unity 导出 Xcode 工程时会自动生成 `gameframex.entitlements` 并把 In-App Purchase、Game Center、推送、iCloud、App Groups 等 13 种能力写进 `Unity-iPhone` 工程，无需手动打开 Xcode 勾选。

## 前置条件

- Unity 项目已安装本包（`com.gameframex.unity.xcode`），`Editor/GameFrameX.Xcode.Editor.asmdef` 存在。
- 已有一个供构建后处理读取的 JSON 配置（顶层包含 `capabilities` 对象，参见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L279-L303)）。
- 目标平台为 iOS（能力设置代码位于 `#if UNITY_IOS` 块内）。

## 操作步骤

1. 打开构建后处理使用的 JSON 配置文件，找到顶层的 `capabilities` 字段（没有则添加一个空对象 `"capabilities": {}`）。
2. 按需要开启能力。以下为完整示例，包含全部 13 项：

```json
{
  "capabilities": {
    "inAppPurchase": true,
    "gameCenter": false,
    "pushNotifications": false,
    "signInWithApple": false,
    "backgroundModes": ["audio", "remote-notification"],
    "iCloud": {
      "keyValueStorage": false,
      "iCloudDocument": false,
      "customContainers": []
    },
    "appGroups": [],
    "associatedDomains": [],
    "keychainSharing": false,
    "healthKit": false,
    "siri": false,
    "personalVPN": false,
    "dataProtection": false
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L281-L303)

3. 重新执行 iOS 构建。构建后处理会调用 `SetCapabilities` 创建 `ProjectCapabilityManager`，随后逐项写入能力并保存：

```csharp
var projectCapabilityManager = new ProjectCapabilityManager(path + "/Unity-iPhone.xcodeproj/project.pbxproj", "gameframex.entitlements", null, targetGuid);

// In-App Purchase
if (hashtable.ContainsKey("inAppPurchase") && hashtable["inAppPurchase"] is bool inAppPurchase && inAppPurchase)
{
    projectCapabilityManager.AddInAppPurchase();
    Debug.Log("已添加 In-App Purchase Capability");
}

// ... 其余能力按配置逐项写入 ...

projectCapabilityManager.WriteToFile();
```

Source: [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L29-L35)

4. 构建完成后在 Unity Console 检查日志。每成功添加一项能力都会输出一条 `已添加 XXX Capability` 日志（例如 `已添加 Push Notifications Capability`），最后由 `projectCapabilityManager.WriteToFile()` 落盘（见 [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L231-L231)）。

## 字段速查

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `inAppPurchase` | bool | 内购 |
| `gameCenter` | bool | Game Center |
| `pushNotifications` | bool | 推送通知 |
| `signInWithApple` | bool | Sign In with Apple |
| `backgroundModes` | string[] | 后台模式，可选值：`audio`、`location`、`voip`、`newsstand`、`external`、`bluetooth`、`bluetooth-peripheral`、`fetch`、`remote-notification` |

| `siri` | bool | Siri 语音助手集成 |

## 常见变体

### 只开内购 + 远程推送

```json
{
  "capabilities": {
    "inAppPurchase": true,
    "pushNotifications": true
  }
}
```

推送通知通过 `AddPushNotifications(false)` 写入，第二个参数为 `false`（不启用 Push Notifications 环境 capability 的 development 变体），见 [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L45-L50)。

### 开启后台音频与远程通知

```json
{
  "capabilities": {
    "backgroundModes": ["audio", "remote-notification"]
  }
}
```

`backgroundModes` 数组中的字符串会被转为小写并映射到 Unity 的 `BackgroundModesOptions` 标志位后一次性写入，见 [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L60-L108)。映射关系：`audio`→`AudioAirplayPiP`、`location`→`LocationUpdates`、`voip`→`VoiceOverIP`、`newsstand`→`NewsstandDownloads`、`external`→`ExternalAccessoryCommunication`、`bluetooth`→`UsesBluetoothLEAccessory`、`bluetooth-peripheral`→`ActsAsABluetoothLEAccessory`、`fetch`→`BackgroundFetch`、`remote-notification`→`RemoteNotifications`。

### 配置 iCloud 容器

```json
{
  "capabilities": {
    "iCloud": {
      "keyValueStorage": true,
      "iCloudDocument": true,
      "customContainers": ["iCloud.com.example.mygame"]
    }
  }
}
```

三个子项分别对应 `AddiCloud(enableKeyValueStorage, enableiCloudDocument, containers)` 的三个参数，见 [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L111-L134)。

### Keychain Sharing 的三种写法

```json
{
  "capabilities": {
    "keychainSharing": true,
    "keychainSharing_custom": { "accessGroups": ["group.com.example.shared"] }
  }
}
```

- `false`：不写入 Keychain Sharing。
- `true`：自动生成分组 `$(AppIdentifierPrefix)` + 包名（`bundleId`），见 [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L159-L165)。
- `{"accessGroups": [...]}`：显式指定分组，见 [PostProcessBuildHelper.Capabilities.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Capabilities.cs#L166-L183)。实际配置中二选一，上面的示例仅为展示两种形式。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| Console 没有任何 `已添加 XXX Capability` 日志 | `capabilities` 配置为 `null`，`SetCapabilities` 直接 `return` | 确认 JSON 顶层存在 `"capabilities"` 对象且键名拼写正确（区分大小写） |
| 某项能力始终没生效 | 布尔项写成了字符串（如 `"true"`），`is bool` 检查不通过 | 全部布尔项用 JSON 的 `true` / `false` 字面量 |
| `backgroundModes` 全部失效 | 数组内元素为空或大小写不符 | 代码会 `ToLower()` 后匹配，写小写即可；空元素会被跳过 |
| Keychain Sharing 没写入 | `keychainSharing: true` 但 `bundleId` 为空，分组数组为 null | 确认配置中同时填写了 `bundleId`，或改用 `accessGroups` 显式指定 |
| `appGroups` / `associatedDomains` 为空数组时不写入 | 代码要求数组非空才调用对应 Add 方法 | 至少填入一个分组或域名 |

## 验证

1. 重新构建 iOS 工程，Console 中应出现 `开始设置Capabilities` 以及对应每项能力的 `已添加 XXX Capability` 日志。
2. 打开导出的 Xcode 工程，选中 `Unity-iPhone` target → **Signing & Capabilities**，确认目标能力已出现，且工程内生成 `gameframex.entitlements` 文件。
3. 真机运行相关功能（如内购、推送）确认 Apple 后台的 App ID 已勾选对应能力；本包只负责写工程文件，Apple Developer 后台的 App ID 配置仍需手动开启。

## 背景

能力统一由 `PostProcessBuildHelper` 的分部类 `SetCapabilities` 方法处理：它读取配置中的 `Hashtable`，针对每个键调用 `UnityEditor.iOS.Xcode.ProjectCapabilityManager` 的对应方法（`AddInAppPurchase`、`AddGameCenter`、`AddPushNotifications`、`AddSignInWithApple`、`AddBackgroundModes`、`AddiCloud`、`AddAppGroups`、`AddKeychainSharing`、`AddAssociatedDomains`、`AddHealthKit`、`AddSiri`、`AddPersonalVPN`、`AddDataProtection`），最后 `WriteToFile()` 一次性写入。整个方法包在 `try/catch` 中，任何异常通过 `Debug.LogError` 输出，不会中断构建。关于包的整体结构与配置入口，见《概述》。
