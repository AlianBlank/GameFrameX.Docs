# Invalid character 例外が発生した場合の対処方法

`JsonMapper.ToObject` / `JsonReader` で入力を解析する際に `JsonException` がスローされ、そのメッセージが `Invalid character '{0}' in input string` という形式である場合、字句解析器が入力文字列の中で JSON 字句テーブルに含まれない文字に遭遇したことを意味します。このページは、原因をすばやく特定して修正するのに役立ちます。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `Invalid character 'x' in input string`(x が英字)| 入力が正当な JSON ではない。例えば、先頭がいきなり裸の `xyz`、裸の `true`、あるいは XML / YAML / コメントなどの非 JSON テキストになっている | JSON オンライン検証ツールでフォーマットを確認する。テキストが `{`、`[`、数字、文字列、`true`/`false`/`null` のいずれかで始まることを確認する |
| 例外メッセージに数字 / 制御文字が出る(例:`Invalid character '\0'`)| 文字列末尾の BOM(`\uFEFF`)、行末の `\r`、残留したバイナリバイト | 解析前に `Trim` / `Trim('\uFEFF')` を実行する。ストリームを読み取る際は `StreamReader` のデフォルト UTF-8 で BOM を除去する |
| 例外メッセージにバックスラッシュ `\` の後に不正な文字が続く | 文字列内のエスケープシーケンスが不正(例:`"\x"`、`"\u00"`、`"\u12"` の桁数不足)| エスケープシーケンスとして許可されるのは `\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX`(4 桁の十六進数)のみ |
| 例外メッセージに `'`(シングルクォート)や `,` の後の改行が出る | JSON に JavaScript / Python 風の構文が混入している(シングルクォート文字列、コメント、末尾カンマ)| シングルクォートを削除してダブルクォートに置き換える。`//`、`/* */` コメントとオブジェクト/配列末尾の余分なカンマを削除する |
| 例外メッセージに中国語の文字が出る | `null` / `undefined` / C# のデフォルト `ToString()` などがそのままパーサーに渡された | まずレスポンス本文が本当に JSON かどうかを判定する(`Content-Type` / 先頭文字)。JSON でなければ `JsonMapper.ToObject` を呼び出さない |

例外メッセージの元となるテンプレートは `JsonException(int c)` コンストラクターに由来します:

```csharp
internal JsonException(int c) :
    base(string.Format(
             "Invalid character '{0}' in input string", (char)c))
{
}
```

出典： [Runtime/JsonException.cs#L77-L83](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonException.cs#L77-L83)

## 修正手順

### 1. まず元の入力を出力する

ログに `e.Message` だけを貼り付けるのではなく、実際にパーサーへ渡された文字列を出力してください。例外メッセージ内の文字こそが問題の文字(その位置)です。

```csharp
try
{
    var obj = GameFrameX.LitJSON.Runtime.JsonMapper.ToObject<Dictionary<string, object>>(rawText);
}
catch (GameFrameX.LitJSON.Runtime.JsonException ex)
{
    Debug.LogError($"LitJSON 解析失敗: {ex.Message} | 元の入力長={rawText?.Length} | 先頭 64 文字=[{rawText?.Substring(0, System.Math.Min(64, rawText?.Length ?? 0))}]");
}
```

### 2. BOM と不可視文字の処理

サーバーが UTF-8 with BOM を返す場合や、ファイルが Windows のメモ帳で保存された場合、文字列の先頭に `\uFEFF` が残り、字句解析器はそれを「不正な先頭文字」とみなして例外をスローします。

```csharp
using GameFrameX.LitJSON.Runtime;

string rawText = File.ReadAllText(path);
// 先頭の BOM を除去する
if (!string.IsNullOrEmpty(rawText) && rawText[0] == '\uFEFF')
    rawText = rawText.Substring(1);

var data = JsonMapper.ToObject<MyData>(rawText);
```

参考情報：[Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs) のステートマシンは、テーブル外のコードポイントに遭遇した時点で即座に `JsonException(c)` をスローします。

### 3. エスケープシーケンスの修正

JSON 文字列がサポートするエスケープは以下のみです。それ以外の `\'`、`\x`、`\v`、`\u{}`、4 桁が揃っていない `\u` などは、すべて `Invalid character` 例外を引き起こします(発生箇所は `\` の後の文字です)。

| 有効なエスケープ | 説明 |
|----------|------|
| `\"` | ダブルクォート |
| `\\` | バックスラッシュ |
| `\/` | スラッシュ |
| `\b` `\f` `\n` `\r` `\t` | 制御文字 |
| `\uXXXX` | 4 桁の十六進数である必要があります(例:`\u4E2D`) |

### 4. 不正な JSON 構文の修正

LitJSON は厳密な JSON パーサーであり、JavaScript / JSON5 流の拡張は**サポートしていません**:

- 文字列にはダブルクォートのみ使用でき、シングルクォート `'…'` は使用できません。
- `//`、`/* */` コメントは許可されません。
- オブジェクト / 配列の最後の要素の後に末尾カンマ `,` を付けることはできません。
- 数字の先頭ゼロや十六進数リテラル(`0x1A`)は許可されません。

```csharp
// 誤った書き方 —— JSON ではない
var bad = "{ name: 'Tom', age: 18, }";

// 修正後
var good = "{\"name\":\"Tom\",\"age\":18}";
var obj = JsonMapper.ToObject<Dictionary<string, object>>(good);
```

### 5. 呼び出しエントリポイントの確認

`JsonMapper.ToObject` のエントリポイントのシグネチャは [Runtime/JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs)、`JsonReader` のストリーミングエントリポイントは [Runtime/JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs) を参照してください。どちらの入口でも、字句エラーは同じ種類の `JsonException` としてラップされます。

## 検証

以下の順序で問題が解決したことを確認します:

1. 例外を引き起こした入力を任意のオンライン JSON 検証ツール(jsonlint など)にコピーし、フォーマットが正当であることを確認してからコードに戻ってください。
2. プログラムを再実行し、`JsonException` がスローされず、`JsonMapper.ToObject<T>` が正常に結果を返すことを確認します。
3. データがネットワークレスポンスに由来する場合は、あわせてレスポンスヘッダーの `Content-Type: application/json` とレスポンス本文の先頭文字を検証し、HTML のエラーページや空のレスポンスをパーサーに渡さないようにしてください。

## 背景(任意)

LitJSON の字句解析は有限ステートマシンに基づいています([Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs))。解析テーブル `parse_table` は JSON 以外の文字を一切受け付けず、読み込んだ時点で `JsonException(int c)` によって `Invalid character '{0}' in input string` をスローします。例外メッセージ内の文字が問題の文字そのものであるため、診断時には文字列の内容よりもこの文字を優先的に確認してください。
