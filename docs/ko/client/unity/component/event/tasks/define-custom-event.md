# 사용자 정의 이벤트 인수를 정의하는 방법

사용자 정의 이벤트 인수를 정의하려면 `GameEventArgs`를 상속하는 새 클래스를 만들고, `Id`와 `Clear()`를 재정의한 다음, `ReferencePool.Acquire<T>()`로 인스턴스를 생성하는 정적 `Create` 팩토리 메서드를 제공하기만 하면 됩니다. 이후 `EventComponent`를 통해 해당 이벤트를 구독하고 발생시킬 수 있습니다.

## 사전 조건

- 프로젝트에 GameFrameX Event 패키지가 설치되어 있고, 씬에 `EventComponent` 컴포넌트가 존재해야 합니다(메뉴 `GameFrameX/Event`, 프레임워크 시작 시 자동으로 부착됨).
- 네임스페이스 `GameFrameX.Event.Runtime`와 `GameFrameX.Runtime`를 참조합니다.

## 작업 단계

1. 새 이벤트 인수 클래스를 만들어 `GameEventArgs`를 상속합니다(`BaseEventArgs`의 추상 하위 클래스이며, 코드 스트리핑을 방지하는 `Preserve` 특성이 표시되어 있음):

```csharp
using GameFrameX.Runtime;

namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// 게임 로직 이벤트 기본 클래스입니다.
    /// </summary>
    [UnityEngine.Scripting.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L30-L41)

2. 프레임워크에 내장된 `EmptyEventArgs`의 작성 방식에 따라 이벤트 인수를 구현합니다: `Id`를 재정의하여 이벤트 ID를 반환하고, `Clear()`를 재정의하여 필드를 복원하며, 정적 `Create` 메서드를 제공하여 참조 풀에서 객체를 가져옵니다. 아래의 `PlayerLevelUpEventArgs`는 동일한 패턴으로 작성된 사용자 정의 예제입니다:

```csharp
using GameFrameX.Runtime;

namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// 플레이어 레벨업 이벤트 인수
    /// </summary>
    public sealed class PlayerLevelUpEventArgs : GameEventArgs
    {
        public int OldLevel { get; private set; }
        public int NewLevel { get; private set; }

        /// <summary>
        /// 이벤트 ID, 기본적으로 타입 전체 이름을 사용하며 구독과 발생 시 동일한 문자열을 사용합니다
        /// </summary>
        public override string Id
        {
            get { return typeof(PlayerLevelUpEventArgs).FullName; }
        }

        /// <summary>
        /// 참조 풀에서 회수될 때 호출되며, 모든 필드를 기본값으로 되돌려야 합니다
        /// </summary>
        public override void Clear()
        {
            OldLevel = 0;
            NewLevel = 0;
        }

        /// <summary>
        /// 이벤트 인수를 생성하며, 참조 풀에서 인스턴스를 가져옵니다
        /// </summary>
        public static PlayerLevelUpEventArgs Create(int oldLevel, int newLevel)
        {
            var eventArgs = ReferencePool.Acquire<PlayerLevelUpEventArgs>();
            eventArgs.OldLevel = oldLevel;
            eventArgs.NewLevel = newLevel;
            return eventArgs;
        }
    }
}
```

위에서 참조한 프레임워크의 원본 구현은 다음과 같으며, `Id`, `Clear()`, `Create` 3종 세트와 `ReferencePool.Acquire<T>()`의 사용법은 모두 이것을 기준으로 합니다:

```csharp
public sealed class EmptyEventArgs : GameEventArgs
{
    private string _eventId = typeof(EmptyEventArgs).FullName;

    public override void Clear()
    {
        _eventId = typeof(EmptyEventArgs).FullName;
    }

    public override string Id
    {
        get { return _eventId; }
    }

    public static EmptyEventArgs Create(string eventId)
    {
        var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
        eventArgs.SetEventId(eventId);
        return eventArgs;
    }

    private void SetEventId(string eventId)
    {
        _eventId = eventId;
    }
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L7-L49)

3. 이벤트를 구독합니다. `EventComponent`의 외부 구독 진입점은 `CheckSubscribe`입니다(존재하지 않을 때만 구독하여 중복 구독을 방지함):

```csharp
// 시그니처: public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
EventComponent.CheckSubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);

private void OnPlayerLevelUp(object sender, GameEventArgs e)
{
    var args = (PlayerLevelUpEventArgs)e;
    Debug.Log($"레벨업: {args.OldLevel} -> {args.NewLevel}");
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L100-L111)

4. 이벤트를 발생시킵니다. `Fire`는 스레드 안전하며 다음 프레임에 디스패치되고, `FireNow`는 즉시 디스패치되지만 스레드 안전하지 않습니다:

```csharp
// 시그니처: public void Fire(object sender, GameEventArgs e)
EventComponent.Fire(this, PlayerLevelUpEventArgs.Create(10, 11));

// 시그니처: public void FireNow(object sender, GameEventArgs e)
EventComponent.FireNow(this, PlayerLevelUpEventArgs.Create(10, 11));
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L171)

5. 더 이상 필요하지 않을 때 구독을 해제합니다. 이벤트 ID는 구독할 때와 완전히 동일해야 합니다:

```csharp
// 시그니처: public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
EventComponent.Unsubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);

// handler가 구독되지 않았을 수 있는 경우 안전 버전을 사용하며, 존재하지 않으면 아무 작업도 수행하지 않습니다
EventComponent.CheckUnsubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L113-L131)

## 일반적인 변형

- **데이터가 없는 이벤트**: 새 클래스를 만들 필요 없이 프레임워크에 내장된 `EmptyEventArgs`를 직접 사용합니다. `EventComponent`는 편리한 오버로드 `Fire(object sender, string eventId)`를 제공하며, 내부에서 자동으로 `EmptyEventArgs.Create(eventId)`를 호출합니다. `eventId`에 `null` 또는 빈 문자열을 전달하면 매개변수 유효성 검사가 트리거됩니다:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

- **사용자 정의 이벤트 ID 문자열**: `typeof(X).FullName`을 사용하고 싶지 않다면, `EmptyEventArgs`처럼 ID를 private 필드 `_eventId`로 저장하고 `Create(eventId)`로 전달할 수 있으며, 하나의 클래스로 여러 논리 이벤트를 처리할 수 있습니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 이벤트를 발생시킨 후 콜백이 전혀 없음 | 구독과 발생에 사용된 `Id` 문자열이 일치하지 않음 | 양쪽 모두 `typeof(PlayerLevelUpEventArgs).FullName`을 사용하도록 통일 |
| 이벤트 콜백에서 읽은 데이터가 더티 값임 | `Clear()`가 모든 필드를 복원하지 않아 인스턴스가 참조 풀에서 재사용된 후 이전 값이 남음 | `Clear()`에서 모든 필드를 재설정 |
| 동일한 프레임에서 콜백이 여러 번 실행됨 | 동일한 handler를 여러 번 `Subscribe`함 | `CheckSubscribe`로 변경하여 먼저 `Check`한 후 구독 |
| 객체가 파괴된 후에도 콜백이 트리거되며 null 참조 예외 발생 | `Unsubscribe`를 잊음 | `OnDestroy`에서 `Unsubscribe` 또는 `CheckUnsubscribe` 호출 |
| 사용자 정의 인수 클래스가 코드 스트리핑으로 제거됨 | 클래스가 보존되지 않음 | `GameEventArgs`와 동일하게 `[UnityEngine.Scripting.Preserve]` 추가 |

## 배경

이벤트 인수 인스턴스는 `ReferencePool` 참조 풀(`ReferencePool.Acquire<T>()`)에서 가져오며, 발생 및 디스패치 후 회수되어 재사용됩니다. 따라서 `Clear()`는 필드를 기본값으로 되돌려야 하며, 이것이 모든 이벤트 인수가 `new`가 아닌 정적 `Create`를 통해 생성되는 이유입니다. 이벤트 디스패치와 스레드 의미론은 `IEventManager`가 관리하며, `Fire`는 콜백이 메인 스레드에서 발생하는 것을 보장합니다.
