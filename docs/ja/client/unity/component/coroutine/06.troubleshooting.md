# よくある問題

このドキュメント收集了使用 CoroutineComponent 协程コンポーネント时常见的問題及解決策。

## 概要

CoroutineComponent 是 GameFrameX フレームワーク的协程管理コンポーネント，拡張了 Unity 内置的协程機能，提供更好的协程ライフサイクル管理和内存安全控制。该コンポーネント使用 `ConcurrentDictionary` 线程安全字典来跟踪所有运行的协程，確認してください〜できます随时管理和停止协程。

> 詳細使用説明请リファレンス [使用ガイド](./3-getting-started.index) 和 [API リファレンス](./4-api-reference.coroutine-component)。

## よくある問題列表

### Q1: 为什么在同一 GameObject 上无法追加多个 CoroutineComponent？

**問題説明：**
在同一个 GameObject 上尝试追加第2个 CoroutineComponent 时，Unity エディタ报错或无法追加。

**原因：**
CoroutineComponent 使用了 `[DisallowMultipleComponent]` プロパティ，该プロパティ禁止在同一 GameObject 上追加多个相同タイプ的コンポーネント。

**解決策：**
- 確認してください每个 GameObject 只有一个 CoroutineComponent インスタンス
- もし〜する必要があります管理多个协程，请在同一个 CoroutineComponent インスタンス上启动多个协程
- 使用 `StopAllCoroutines()` メソッド停止所有协程

```csharp
// 正确用法：在同一个组件上管理多个协程
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(CoroutineA());
coroutineComponent.StartCoroutine(CoroutineB());
coroutineComponent.StopAllCoroutines(); // 停止所有协程
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L10-L11)

### Q2: StartCoroutine 传入 null 列挙型器会怎样？

**問題説明：**
向 `StartCoroutine` メソッド传入 `null` 值的 IEnumerator 时会发生什么？

**原因：**
もし向 `StartCoroutine` 传入 null 列挙型器，Unity 底层会抛出空参照例外。

**解決策：**
- 在启动协程前始终確認列挙型器是否为 null
- 追加空值保护逻辑

```csharp
IEnumerator myCoroutine = GetSomeCoroutine(); // 可能是 null

if (myCoroutine != null)
{
    coroutineComponent.StartCoroutine(myCoroutine);
}
```

### Q3: 如何正确停止一个〜中运行的协程？

**問題説明：**
呼び出し `StopCoroutine` 后协程似乎仍在运行，または无法停止协程。

**原因：**
- 传入的 IEnumerator 与启动时的列挙型器不是同一个参照
- 协程すでに执行完毕
- 协程在 StopCoroutine 呼び出し前すでに结束

**解決策：**
- 保存启动协程时返す的 IEnumerator 参照
- 使用 `StopAllCoroutines()` 停止所有协程
- 確認してください在协程执行过程中及时停止

```csharp
// 保存协程引用
IEnumerator myCoroutine = coroutineComponent.StartCoroutine(MyLongRunningTask());

// 在适当的时机停止
coroutineComponent.StopCoroutine(myCoroutine);

// 或者停止所有协程
coroutineComponent.StopAllCoroutines();
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L32-L45)

### Q4: コンポーネント挂载的 GameObject 被破棄后会发生什么？

**問題説明：**
当パッケージ含 CoroutineComponent 的 GameObject 被破棄时，〜中运行的协程会怎样？

**原因：**
当 GameObject 被破棄时，Unity 会自动停止该 GameObject 上的所有协程。CoroutineComponent 継承自 MonoBehaviour，因此也会遵循这一行为。

**お勧め：**
- 在シーン切换或对象破棄前，手动呼び出し `StopAllCoroutines()` 確認してください协程干净停止
- 使用 OnDestroy ライフサイクル钩子进行清理

```csharp
private void OnDestroy()
{
    // 确保在对象销毁前停止所有协程
    if (coroutineComponent != null)
    {
        coroutineComponent.StopAllCoroutines();
    }
}
```

### Q5: WaitForEndOfFrameFinish 的コールバック传入 null 会崩溃吗？

**問題説明：**
向 `WaitForEndOfFrameFinish` メソッド传入 null コールバック会发生什么？

**原因：**
CoroutineComponent 使用了空值合并运算符 `callback?.Invoke()`，因此传入 null コールバック不会导致崩溃，呼び出し会被安全地忽略。

**ソースコード検証：**
```csharp
public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(_WaitForEndOfFrameFinish(callback));
}

private IEnumerator _WaitForEndOfFrameFinish(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke(); // 使用 ?. 操作符安全调用
}
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L97)

### Q6: 如何在帧渲染结束后执行逻辑？

**問題説明：**
〜する必要があります在 Unity 每帧渲染结束后执行某些操作，〜すべき如何使用？

**解決策：**
使用 `WaitForEndOfFrameFinish` メソッド，该メソッド会在当前帧的渲染完成后执行コールバック。

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    // 这个回调会在帧渲染结束后执行
    Debug.Log("帧渲染结束，执行逻辑");
});
```

**适用シーン：**
- 在 UI 渲染后取得屏幕截图
- 在物理计算完成后执行某些操作
- 〜する必要があります在帧末尾进行ステータス同步

### Q7: CoroutineComponent 是线程安全的吗？

**問題説明：**
CoroutineComponent 〜できます在多线程環境中使用吗？

**原因：**
是的，CoroutineComponent 使用了 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 来存储协程映射，该数据结构是线程安全的。

**注意事项：**
- 虽然内部存储是线程安全的，但协程本身在 Unity 主线程上执行
- 多线程访问时，主な〜する必要があります考虑的是 IEnumerator 参照的正确传递

### Q8: 协程未正确停止导致内存泄漏如何処理？

**問題説明：**
协程未正确停止〜の可能性があります导致内存泄漏，如何预防？

**原因：**
もし不正确停止协程，特别是パッケージ含无限循环或长时间等待的协程，〜の可能性があります会导致内存泄漏。CoroutineComponent 通过维护协程映射表来帮助管理这个問題。

**解決策：**
- 使用 `StopAllCoroutines()` 清理所有协程
- 在コンポーネント破棄时確認してください呼び出し `StopAllCoroutines()`
- 使用具有明确结束条件的协程

```csharp
private void OnDestroy()
{
    // 重要：确保停止所有协程防止内存泄漏
    StopAllCoroutines();
}
```

### Q10: CoroutineComponent 〜する必要があります手动追加到 GameObject 吗？

**問題説明：**
为什么コンポーネント没有自动追加到シーン中？

**原因：**
CoroutineComponent 在 `Awake` メソッド中設定了 `IsAutoRegister = false`，这意味着コンポーネント不会自动登録到フレームワーク的自动登録系统中。

**解決策：**
〜する必要があります手动将 CoroutineComponent 追加到 GameObject 上：

```csharp
// 手动添加组件
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();

// 或者在 Unity 编辑器中手动添加
// 1. 选择 GameObject
// 2. 点击 Add Component
// 3. 搜索 "Game Framework/Coroutine"
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L99-L103)

## 診断ステップ

もし遇到无法解决的問題，请按以下ステップ进行診断：

1. **確認 GameObject ステータス**：確認 GameObject 和コンポーネント是否已激活
2. **確認协程参照**：確認用于停止协程的 IEnumerator 参照是否正确
3. **確認 Unity 控制台**：確認是否有エラー或警告情報
4. **使用 StopAllCoroutines**：作为デバッグ手段，先停止所有协程排查問題
5. **確認シーン切换**：確認シーン切换时协程是否被正确清理
