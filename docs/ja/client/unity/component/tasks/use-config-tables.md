# 設定表(設定センター)の読み込みと使用方法

このページでは、GameFrameX.Unity で LuBan ツールによって生成され、`Hotfix.Config` アセンブリ配下に配置された設定表データの読み込みと使用方法を解説します。設定表は `TbXxxConfig` 形式で提供され、`TablesComponent` によって初期化された後、`Id` または文字列キーでエントリを検索できます。

## 前提条件

- LuBan エディタ拡張によって設定表コードが生成済みであること(デフォルト出力先 `Assets/Hotfix/Config/Generate/`)。
- プロジェクトに `GameFrameX.Config.Runtime` と `SimpleJSON` のランタイム依存関係が導入済みであること。
- 業務側で設定表のリソース読み込み方式(ローカル StreamingAssets / リモート CDN)を決定し、`Func<Task<JSONNode>>` を `TbXxxConfig` のコンストラクタに渡すこと。

## 操作手順

1. 設定表のエンティティクラスとテーブルクラスが生成されていることを確認します。各テーブルは2つのファイルに対応します:エンティティクラス `XxxConfig`(フィールド + コンストラクタ + `Deserialize`)と、テーブルクラス `TbXxxConfig`(`BaseDataTable<XxxConfig>` を継承)。

   例:`AchievementConfig` エンティティクラスは [AchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L16-L50) で定義され、テーブルコンテナは [TbAchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L60) にあります。`TbAchievementConfig` は `BaseDataTable<Tables.AchievementConfig>` を継承し、コンストラクタで `_loadFunc` を注入します。

   ```csharp
   // Source: Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L38
   public partial class TbAchievementConfig : BaseDataTable<Tables.AchievementConfig>
   {
       private readonly System.Func<System.Threading.Tasks.Task<JSONNode>> _loadFunc;
       public TbAchievementConfig(System.Func<System.Threading.Tasks.Task<JSONNode>> loadFunc)
       {
           _loadFunc = loadFunc;
       }
       public override async System.Threading.Tasks.Task LoadAsync()
       {
           var jsonNode = await _loadFunc();
           StringDataMaps.Clear();
           DataList.Clear();
           foreach(var _ele in jsonNode.Children)
           {
               Tables.AchievementConfig _v;
               { if(!_ele.IsObject) { throw new SerializationException(); }
                 _v = Tables.AchievementConfig.DeserializeAchievementConfig(_ele); }
               DataList.Add(_v);
               LongDataMaps.Add(_v.Id, _v);
               StringDataMaps.Add(_v.Id.ToString(), _v);
           }
           PostInit();
       }
   }
   ```

2. 各テーブルに対して `loadFunc` を提供し、内部でローカル/リモートリソースから JSON を読み込み、`JSONNode` にデシリアライズします。

   ```csharp
   // loadFunc の例:StreamingAssets から非同期で JSON を読み込みパースする
   Func<Task<JSONNode>> loadAchievement = async () =>
   {
       var text = await File.ReadAllTextAsync(
           Path.Combine(Application.streamingAssetsPath, "AchievementConfig.json"));
       return JSON.Parse(text);
   };

   var tbAchievement = new TbAchievementConfig(loadAchievement);
   await tbAchievement.LoadAsync();
   ```

3. すべての `TbXxxConfig` を `TablesComponent` に登録し、読み込み、テーブル間参照解決(`ResolveRef`)、多言語キーの翻訳(`TranslateText`)を一括管理させます。

   ```csharp
   // テーブルインスタンスを TablesComponent に追加して初期化を実行
   var tables = new TablesComponent();
   tables.Add(tbAchievement);   // 他の TbXxxConfig も同様
   await tables.InitAsync();    // 内部で依存順に各テーブル LoadAsync + ResolveRef を呼び出す
   ```

4. 業務コードで `Id` またはキーに従ってデータを検索します。`BaseDataTable<T>` は `LongDataMaps`、`StringDataMaps`、`DataList` の3つのコレクションを提供しており、キーで直接読み取ることができます。

   ```csharp
   // エンティティクラスが露出するフィールドの例(読み取り専用プロパティ)
   // Source: Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L51-L80
   var row = tables.Achievement.Get(1001);   // LongDataMaps["1001"]
   var nameKey = row.Name;                   // 多言語 Key
   var conditions = row.AchievementUnlockCondition;  // List<int>
   ```

5. テーブル間参照と多言語を処理します:すべてのテーブルの `LoadAsync` 完了後、`ResolveRef(tables)` を呼び出してエントリが他のテーブルへの参照を解析し、その後 `TranslateText(translator)` を呼び出して `xxx_Localization_Key` のローカライズを完了します。

   ```csharp
   // Source: TbAchievementConfig.cs#L40-L54
   tbAchievement.ResolveRef(tables);
   tbAchievement.TranslateText((key, defaultText) => Localization.Get(key) ?? defaultText);
   ```

## よくあるバリエーション

- **ローカルリソース vs リモートリソース**:`loadFunc` 内で `Application.streamingAssetsPath` からの読み込み、または `UnityWebRequest.Get` によるダウンロードをそれぞれ実装できます。最終的に `JSONNode` を返すことができれば問題ありません。
- **多言語キー**:`AchievementConfig` はコンストラクタで多言語フィールドを `Name_Localization_Key`、`AchievementContent_Localization_Key`、`LockText_Localization_Key` にコピーし、`TranslateText` コールバックで置換します。
- **拡張型マッピング**:列挙型や外部型は [ExternalTypeUtil.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Extension/ExternalTypeUtil.cs) で登録でき、LuBan のデシリアライズ時に参照されます。

## よくあるエラー

- **JSON フィールドの型不一致**:`Deserialize` は型が一致しない場合、`SerializationException`(`AchievementConfig.cs` の31〜36行のアサーション) をスローします。Excel/JSON エクスポートスクリプトとエンティティクラスのフィールド型が一致しているか確認してください。
- **`ResolveRef` の呼び忘れ**:テーブル間参照フィールドがデフォルト/空値のままになります。必ずすべてのテーブルの `LoadAsync` 完了後に呼び出してください。
- **`LoadAsync` の重複呼び出し**:事前に `Clear()` しないと `LongDataMaps`/`StringDataMaps` にキーが重複します。生成コードの先頭で `Clear()` が呼ばれていますが、`loadFunc` を手動で再利用する場合は注意してください。
- **生成ファイルの直接編集**:`XxxConfig.cs` と `TbXxxConfig.cs` の上部には `<auto-generated>` マーカーがあり、変更は次回生成時に上書きされます。カスタムロジックは `partial` の別ファイル側に配置してください。

## 背景(任意)

LuBan は GameFrameX と連携する Excel→JSON→C# コード生成ツールです:Excel でテーブル構造を定義し、ツールが JSON データファイルと上記のような `BeanBase` / `BaseDataTable<T>` 形式のエンティティ+コンテナコードを出力します。`TablesComponent` は設定センターとして機能し、起動時に読み込みと参照解決を一元的に行い、必要に応じてローカライズをトリガーすることで、業務側が強く型付けされたオブジェクトのみを扱えるようにします。
