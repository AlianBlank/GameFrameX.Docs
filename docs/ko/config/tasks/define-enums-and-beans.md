# 열거형, 구조체, 복잡한 필드 정의 방법

한 열의 필드가 "고정된 몇 개의 값"(예: 아이템 유형)만 가질 수 있게 하거나, 여러 필드를 하나의 복합 필드(예: 좌표, 가격 범위)로 묶어야 할 때는 `__enums__.xlsx`와 `__beans__.xlsx`라는 두 장의 「고급 정의표」를 사용해야 합니다. 이 문서에서는 열거형 하나와 구조체 하나를 처음부터 정의하고, 데이터 테이블에서 이를 참조하는 과정을 안내합니다.

## 사전 조건

- 《구성 테이블을 새로 만드는 방법》의 절차에 따라 `Excels/Tables/` 아래에 최소 한 장의 일반 데이터 테이블을 만들어 본 경험이 있습니다(앞 4행 헤더의 의미를 이해할 것).
- 로컬에 Excel, WPS 또는 `.xlsx` 파일을 편집할 수 있는 도구가 설치되어 있습니다.
- `Excels/` 디렉터리의 `__enums__.xlsx`와 `__beans__.xlsx`를 열어본 적이 있습니다(비어 있더라도 한 번은 열어야 합니다).

> 이 두 표를 한 번 정의해 두면, 모든 데이터 테이블의 `##type` 행에 열거형 이름이나 구조체 이름을 필드 타입으로 직접 쓸 수 있습니다.

## 작업 단계

### 1단계: 「열거형 정의표」 열기

`Excels/__enums__.xlsx`를 엽니다. 이 표의 용도는 단 하나입니다: 모든 "열거형"을 여기에 모아 정의하는 것입니다.

이 표의 헤더 역시 고정된 4행입니다:

| 행 | 마커 | 입력할 내용 |
|----|------|--------|
| 1 | `##var` | 열거형에 속한 각 값의 영문 이름 |
| 2 | `##type` | 모두 `int`라고 작성 |
| 3 | `##group` | 비워 둠 |
| 4 | `##` | 중국어 설명 |

> 도구는 **영문 열 이름(`##var` 행)**으로 열거형을 식별합니다. 명명 규칙: `EnumName.Member`, 예: `ItemType.Consumable`.

### 2단계: 열거형 정의하기

예를 들어 "아이템 유형"에 대한 열거형 `ItemType`를 만들고, 소모품·장비·재료 세 가지를 포함시키고 싶다면 `__enums__.xlsx`에 다음과 같이 입력합니다:

| ##var | ItemType.Consumable | ItemType.Equipment | ItemType.Material |
|-------|---------------------|--------------------|-------------------|
| ##type | int | int | int |
| ##group | | | |
| ## | 소모품 | 장비 | 재료 |

**명명 요점:**

| 작성법 | 의미 |
|------|------|
| `ItemType.Consumable` | 열거형 이름 = `ItemType`, 멤버 = `Consumable` |
| `Color.R` / `Color.G` / `Color.B` | 같은 표에 여러 열거형을 둘 수 있으며, 열 이름으로 구분합니다 |

정의가 완료되면 모든 데이터 테이블의 `##type` 행에 `ItemType`라고 쓰기만 하면 이 열거형을 참조할 수 있습니다.

### 3단계: 데이터 테이블에서 열거형 사용하기

아이템 테이블을 새로 만들어(또는 열어서) "유형" 열의 타입을 열거형 이름으로 작성하면 됩니다:

| ##var | id | name | type |
|-------|----|------|------|
| ##type | int | text | ItemType |
| ##group | | | |
| ## | 아이템ID | 아이템 이름 | 유형 |
| | 10001 | diamond | ItemType.Consumable |
| | 10002 | sword | ItemType.Equipment |

도구가 검증합니다: 셀에는 반드시 `ItemType.`로 시작하는 멤버 이름을 입력해야 하며, 그렇지 않으면 생성 시 "정의되지 않은 열거형 값" 오류가 발생합니다.

### 4단계: 「구조체 정의표」 열기

`Excels/__beans__.xlsx`를 엽니다. 이 표의 용도: 여러 필드를 하나의 재사용 가능한 복합 타입(예: `vec3` 좌표, `Reward` 보상 패키지)으로 묶는 것입니다.

헤더 역시 4행의 고정 마커이며, 의미는 일반 표와 동일합니다:

| 행 | 마커 | 입력할 내용 |
|----|------|--------|
| 1 | `##var` | 필드 이름(영문) |
| 2 | `##type` | 필드 타입(`int`, `string`, 열거형 이름, 심지어 다른 구조체 이름도 가능) |
| 3 | `##group` | 비워 둠 |
| 4 | `##` | 중국어 설명 |

> 구조체는 `##var` 행의 **열 이름(`.` 포함)**으로 식별됩니다. 예를 들어 `Reward.ItemId`, `Reward.Count`는 같은 구조체 `Reward`의 두 필드를 나타냅니다.

### 5단계: 구조체 정의하기

예를 들어 아이템 ID와 수량을 포함하는 보상 패키지 `Reward`를 정의합니다:

| ##var | Reward.ItemId | Reward.Count |
|-------|---------------|--------------|
| ##type | int | int |
| ##group | | | |
| ## | 아이템ID | 수량 |

이렇게 하면 `ItemId`(int)와 `Count`(int) 두 필드를 가진 `Reward`라는 이름의 구조체가 선언됩니다.

**복합 필드에 구조체나 열거형을 중첩할 수도 있습니다:**

| ##var | Reward.ItemId | Reward.ItemType | Reward.Pos.x | Reward.Pos.y |
|-------|---------------|------------------|--------------|--------------|
| ##type | int | ItemType | float | float |
| ##group | | | | |
| ## | 아이템ID | 아이템 유형 | X좌표 | Y좌표 |

위 예제는 두 개의 구조체를 정의합니다: `Reward`(`ItemId`, `ItemType`, `Pos` 포함)와 `Pos`(`x`, `y` 포함).

### 6단계: 데이터 테이블에서 구조체 사용하기

구조체 이름을 `##type` 행에 직접 쓰면 되고, 셀에는 필드 순서대로 값을 입력합니다(구분자 `,` 또는 `;` 사용, 도구는 선언 순서대로 읽습니다):

| ##var | id | first_reward |
|-------|----|--------------|
| ##type | int | Reward |
| ##group | | | |
| ## | 업적ID | 첫 클리어 보상 |
| | 900001 | 10001,1 |
| | 900002 | 10002,5 |

> 행 내 구분자는 도구의 실제 설정을 따릅니다(기본값은 쉼표 `,`); 필드 순서는 `__beans__.xlsx`의 `##var` 순서와 반드시 일치해야 합니다.

## 일반적인 변형

| 시나리오 | 작성법 |
|------|------|
| 리스트형 필드(같은 구조체 여러 개) | 타입에 `list,Reward`라고 쓰고, 셀에서는 `;`로 각 Reward를 구분 |
| 딕셔너리형 필드 | 타입에 `map,int,Reward`라고 씀(키 타입이 앞, 값 타입이 뒤) |
| 다국어 필드를 구조체에 포함 | 필드 타입을 `text`로 쓰면 됨 |
| 내장 좌표 타입 재사용 | `##type`에 직접 `vec2` / `vec3` / `vec4`라고 씀([Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml)에 기본 내장) |

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 생성 시 *정의되지 않은 열거형* 오류 | `__enums__.xlsx`에 해당 열거형 이름이 없음 | `__enums__.xlsx`에 `EnumName.Member` 형식으로 추가 |
| 생성 시 *지원되지 않는 중국어 표 이름* 오류 | 열 이름/열거형 이름에 중국어를 사용함 | 열거형 이름, 멤버 이름, 필드 이름은 반드시 영문이어야 함 |
| 구조체 필드가 맞지 않음 | 셀에 입력한 값의 순서가 `__beans__.xlsx` 필드 순서와 불일치 | `##var` 행 순서를 엄격히 따라 입력 |
| 데이터 열을 전혀 읽지 못함 | `__var` / `##type` / `##group` / `##` 마커를 잘못 씀 | 이 4개 마커는 고정 문자열이므로 그대로 정확히 써야 함 |
| 같은 열거형 충돌 | `__enums__.xlsx`의 같은 열에 접두사가 다른 멤버를 씀 | 열거형마다 별도의 열을 사용하고 섞어 쓰지 말 것 |

## 배경(선택)

`__enums__.xlsx`와 `__beans__.xlsx`는 본질적으로 "코드에 `enum` / `class`를 작성하는" 작업을 Excel로 옮겨온 것입니다: 기획자가 헤더를 입력하면 도구가 그에 대응하는 C# 열거형과 클래스를 생성하고, 클라이언트(Unity)와 서버(.NET)는 각자 타입이 서로 일치하는 코드를 받게 됩니다. 내장 타입(예: 좌표)은 [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml)에서 제공되며, 플랫폼 간 각자의 좌표 구현에 자동으로 맞춰집니다.
