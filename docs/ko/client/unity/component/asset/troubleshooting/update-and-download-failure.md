# 핫업데이트 멈춤, 다운로드 실패 또는 버전 불일치가 발생했을 때

핫업데이트 프로세스(YooAsset 기반 HostPlayMode)에서 "프로세스가 특정 상태에서 더 이상 진행되지 않음", "패치 다운로드 오류" 또는 "클라이언트 버전과 원격 매니페스트가 일치하지 않음"이 발생할 경우, 이 페이지의 표와 단계에 따라 문제를 진단하고 해결하세요.

`EPatchStates` 열거형 값은 다음과 같이 정의되며, 로그 확인 용도로 사용됩니다:

## 해결 단계

### §1 UpdateStaticVersion에서 멈춤

1. 전달된 `hostServerURL`을 확인하여 브라우저에서 직접 열 때 텍스트 `PackageVersion`(YooAsset 기본 레이아웃)을 반환하는지 확인하세요.
2. 패키지 빌드 시스템에서 해당 리소스 패키지가 게시되었는지 확인하세요. 원격 디렉터리에는 최소한 `PackageVersion.txt` / `GameVersion.txt`가 포함되어야 합니다.
3. CDN을 활성화한 경우 CDN 원본 서버 주소가 실제 리소스 서버를 가리키는지 확인하세요.

### §2 UpdateManifest에서 멈춤

1. `fallbackHostServerURL`(대체 주소)도 반드시 제공해야 합니다. `HostPlayMode` 초기화 시 `RemoteServices`를 통해 두 주소가 모두 YooAsset에 전달됩니다.

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L148-L164)

```csharp
private InitializationOperation InitializeYooAssetHostPlayMode(
    ResourcePackage resourcePackage,
    string hostServerURL,
    string fallbackHostServerURL)
{
    var remoteServices = new RemoteServices(hostServerURL, fallbackHostServerURL);
    var createParameters = new HostPlayModeParameters
    {
        BuildinFileSystemParameters = FileSystemParameters.CreateDefaultBuildinFileSystemParameters(),
        CacheFileSystemParameters   = FileSystemParameters.CreateDefaultCacheFileSystemParameters(remoteServices),
    };
    return resourcePackage.InitializeAsync(createParameters);
}
```

2. 클라이언트 `AppVersion`이 원격 `GameVersion.txt`보다 높지 않은지 확인하세요(YooAsset는 AppVersion으로 매니페스트를 필터링합니다).
3. 로그에서 YooAsset가 반환한 매니페스트 URL을 확인하고, 브라우저에서 수동으로 열었을 때 `PackageManifest_{AppVersion}_{PackageVersion}.hash`와 `.bytes`를 다운로드할 수 있어야 합니다.

### §3 CreateDownloader가 비어 있음

1. 방금 캐시를 지웠거나 처음 설치한 경우 이는 정상 동작이므로 다운로드를 건너뛰고 게임에 바로 진입하면 됩니다.
2. 비어 있는 것이 비정상이라면(실제로 새로운 리소스가 있는 경우), 보통 `AppVersion`이 잘못 선택되어 매니페스트 내용이 잘못된 경우이므로 §2로 돌아가 버전 번호를 확인하세요.

### §4 DownloadWebFiles 실패

`IAssetManager`의 다음 두 매개변수를 통해 다운로드 동작을 조정할 수 있습니다:

Source: [IAssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L13-L41)

```csharp
/// 동시에 다운로드할 최대 개수。
int DownloadingMaxNum { get; set; }

/// 실패 시 재시도 최대 횟수。
int FailedTryAgain { get; set; }

/// 다운로드 파일 검증 수준을 가져오거나 설정합니다.
EFileVerifyLevel VerifyLevel { get; }
```

1. `DownloadingMaxNum`을 적절히 높이세요(기본값은 작으므로, 대역폭이 충분하면 10~20으로 조정 가능).
2. 네트워크 일시 장애로 인해 바로 실패 처리되지 않도록 `FailedTryAgain`을 적절히 높이세요.
3. 다수의 CDN 파일에서 404가 발생하면 먼저 빌드 산출물 디렉터리에서 파일명을 확인하세요. YooAsset 원격 레이아웃은 빌드 시점과 일치해야 합니다.
4. 파일이 변조되었거나 손상되었을 가능성이 있다면 `VerifyLevel`을 더 높은 수준으로(열거형 `EFileVerifyLevel`에 의해 결정됨) 설정하세요. YooAsset가 파일 해시를 검증합니다.

### §5 원격 버전과 로컬 호환 불가

YooAsset는 `UpdateManifest` 단계에서 `AppVersion`을 검증하며, 원격이 요구하는 버전보다 낮으면 거부됩니다. 처리 방법:

1. 클라이언트의 `Player Settings.bundleVersion` 또는 `InitPackageAsync` 호출 시 전달되는 버전 번호를 원격 `GameVersion.txt` `>=` 값으로 상향하세요.
2. 패키지를 다시 빌드하여 배포하세요. 기존 클라이언트에서 우회하려고 하지 마세요.

## 검증

1. 진행률 콜백이 `UpdateStaticVersion → UpdateManifest → CreateDownloader → DownloadWebFiles → PatchDone`을 빠짐없이 통과하며, 건너뛰거나 멈추지 않는지 확인하세요.
2. YooAsset 캐시 디렉터리(예: `Application.persistentDataPath/yooasset/{packageName}/`)에서 이번 버전에 해당하는 `.bytes` / `.hash` 캐시 파일을 확인할 수 있어야 합니다.
3. 게임에 진입한 후 모든 핫업데이트 리소스가 정상적으로 로드되며 더 이상 내장 패키지로 폴백되지 않아야 합니다.
