# 이미지 캐시 여부 판단 방법

`IsCached(string url)` 을 통해 지정된 URL 의 이미지가 로컬 캐시에 이미 다운로드되었는지 판단할 수 있으며, 캐시 히트 시 중복 네트워크 요청을 피할 수 있습니다. WebGL 플랫폼은 항상 `false` 를 반환하며, 나머지 플랫폼은 URL 의 MD5 값을 파일명으로 사용하여 캐시 파일의 존재 여부를 확인합니다.

## 사전 조건

- `ImageCacheComponent` 를 게임 프레임워크의 컴포넌트 매니저에挂(등록)해 두어야 합니다(또는 `IImageCacheManager` 인스턴스를 보유하고 있어야 합니다).
- 현재 빌드 플랫폼이 **WebGL 이 아님**(WebGL 에서는 캐시가 무의미하므로 인터페이스는 항상 `false` 입니다).

## 操作 단계

1. 캐시 컴포넌트 인스턴스 가져오기:

```csharp
var cache = GameEntry.GetComponent<ImageCacheComponent>();
```

2. `IsCached` 를 호출하여 원격 이미지 주소 전달:

```csharp
string url = "https://example.com/avatar.png";
bool cached = cache.IsCached(url);
if (cached)
{
    // 이미 캐시 히트, 직접 로컬 로드 로직을 타거나 다운로드 알림을 건너뛸 수 있음
}
else
{
    // 다운로드 절차 진행, 예: cache.LoadImageAsync(url)
}
```

3. `IImageCacheManager` 에서도 동일 메서드가 제공되므로 인터페이스를 통해 직접 호출 가능:

```csharp
IImageCacheManager manager = cache;
bool cached = manager.IsCached(url);
```

인터페이스 시그니처는 `IImageCacheManager.cs` 34 번째 줄, 구현은 `ImageCacheManager.cs` 180 번째 줄, 컴포넌트 래핑은 `ImageCacheComponent.cs` 83 번째 줄을 참조하세요.

## 일반적인 변형

- **빈 URL 전달**: `IsCached(string url)` 은 `url` 이 `null` 또는 빈 문자열일 때 즉시 `false` 를 반환하며, 예외를 던지지 않습니다.
- **WebGL 플랫폼**: `#if UNITY_WEBGL` 컴파일 분기로 제어되며, 다운로드 여부와 관계없이 항상 `false` 를 반환하므로 "캐시되지 않음" 의 판단 기준으로 사용하면 안 됩니다.
- **비동기 로드와 결합**: `LoadImageAsync` 호출 전에 먼저 `IsCached` 로 UI 플레이스홀더/진행률 알림을 처리하여 빈 화면 깜빡임을 방지할 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| WebGL 에서 `IsCached` 가 항상 `false` 반환 | WebGL 은 로컬 파일 캐시를 지원하지 않으므로, 소스 코드에서 고정적으로 `false` 반환 | WebGL 에서는 해당 검사를 건너뛰거나 "캐시되지 않음" 절차로 처리 |
| 동일한 URL 이지만 크기/자르기 파라미터가 다를 때 결과가 다름 | 캐시는 **원본 URL** 의 MD5 를 키로 사용하므로, query string 이 포함된 URL 은 다른 리소스로 간주됨 | URL 문자열을 다운로드 시와 동일하게 유지 |
| `CachePath` 설정을 수정한 후 기존 파일이 무효화됨 | 경로가 변경되어 기존 캐시 파일이 새 경로에 없음 | 기존 디렉터리 정리 또는 마이그레이션 후 다시 판단 |

## 배경 (선택)

구현은 `ImageCacheManager.cs` 에 있으며, 핵심은 `Utility.Hash.MD5.Hash(url)` 에 `Utility.Const.FileNameSuffix.PNG` 를 연결하여 캐시 경로를 만들고, `FileHelper.IsExists` 로 파일 존재 여부를 판단하는 것입니다. 전체 판정은 동기식이며 순수 로컬 IO 이므로 오버헤드가 매우 낮아, UI 로직 사전 호출에 적합합니다.
