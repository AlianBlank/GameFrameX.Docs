# How to Enable UI Show/Hide Animations

By adding the `OptionUIShowAnimationAttribute` and `OptionUIHideAnimationAttribute` attributes to a UI form class, the UI can automatically play the specified animations when opening and closing, without manually calling any API.

## Prerequisites

- The `GameFrameX.UI` package has been integrated into the project following the "Quick Start" guide.
- The UI prefab has an `Animator` (or a custom animation component) attached, with Animation Clips / Triggers available by name.

## Steps

1. Add the show animation attribute to the UI form class:

   ```csharp
   using GameFrameX.UI.Runtime;

   [OptionUIShowAnimation("Show", true)]
   public sealed class MyMainForm : UIForm
   {
       // ...
   }
   ```

   The first parameter is the animation name, and the second parameter is whether to enable it (default `true`).

   Source: [OptionUIShowAnimationAttribute.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/Attribute/OptionUIShowAnimationAttribute.cs#L75-L79)

2. Add the hide animation attribute to the same class:

   ```csharp
   [OptionUIShowAnimation("Show", true)]
   [OptionUIHideAnimation("Hide", true)]
   public sealed class MyMainForm : UIForm
   {
       // ...
   }
   ```

   The `OptionUIHideAnimation` signature is fully symmetrical to the show version.

   Source: [OptionUIHideAnimationAttribute.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/Attribute/OptionUIHideAnimationAttribute.cs#L75-L79)

3. When overriding `OnOpen` and `OnClose`, call the base class implementations; the framework will trigger `PlayOpenAnimation()` / `PlayHideAnimation()` at the appropriate time:

   ```csharp
   protected override void OnOpen(object userData)
   {
       base.OnOpen(userData);
       // Custom logic
   }

   protected override void OnClose(bool isShutdown, object userData)
   {
       // Custom logic
       base.OnClose(isShutdown, userData);
   }
   ```

4. When opening the form via `BaseUIManager.OpenUIForm(...)`, the framework automatically plays the animation based on the attributes; when closing via `CloseUIForm(...)`, the close animation is played.

## Key Field Quick Reference

`UIForm` also exposes the corresponding serialized fields in the Inspector, so you can check/fill them directly on the Prefab without using attributes:

| Field | Type | Description |
|------|------|------|
| `m_EnableShowAnimation` | `bool` | Whether to enable the show animation |
| `m_ShowAnimationName` | `string` | Show animation name (corresponds to the state/Trigger name in the `Animator`) |
| `m_EnableHideAnimation` | `bool` | Whether to enable the hide animation |
| `m_HideAnimationName` | `string` | Hide animation name |

The corresponding public properties are `EnableShowAnimation` / `ShowAnimationName` / `EnableHideAnimation` / `HideAnimationName`.

Source: [UIForm.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIForm.cs#L76-L82)

## Common Variants

- **Only toggling on/off, without specifying an animation name**: Use the single-parameter constructor; `AnimationName` defaults to an empty string.

  ```csharp
  [OptionUIShowAnimation(false)]   // Disable the show animation
  [OptionUIHideAnimation(true)]    // Enable the hide animation, name follows the default Trigger on the Animator
  ```

  Source: [OptionUIShowAnimationAttribute.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/Attribute/OptionUIShowAnimationAttribute.cs#L89-L93)

- **Runtime modification**: Assign values directly to properties such as `UIForm.EnableShowAnimation` / `ShowAnimationName`.

  Source: [UIForm.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIForm.cs#L197-L200)

## Common Mistakes

- **Misspelled animation name**: `ShowAnimationName` / `HideAnimationName` must exactly match the state or Trigger on the `Animator`, otherwise playback will not be triggered.
- **Forgetting `base.OnOpen` / `base.OnClose`**: If overridden in a subclass without calling the base class method, the framework will not play animations.
- **No `Animator` on the prefab**: Attribute declarations alone are ineffective; the animation component must exist on the instantiated GameObject.

## Background

Show/hide animations are driven by the four serialized fields maintained by `UIForm`: `m_EnableShowAnimation` / `m_ShowAnimationName` / `m_EnableHideAnimation` / `m_HideAnimationName`; attributes are a more convenient configuration entry point, and ultimately all values are written back to these fields and playback is triggered within the `OnOpen` / `OnClose` lifecycle.

For the UI lifecycle and open/close flow, see "UI Form Lifecycle".
