# 運算式樹/路徑連結擴充的使用方式

`ExpressionExtension` 提供一組針對 `Expression<Func<T, bool>>` 的鏈式連結方法，可將多個獨立的述詞運算式安全地組合成新的運算式。無需手寫 `Expression.AndAlso` / `ParameterExpression` 等樣板程式碼，常用於查詢條件動態連結、篩選管線等場景。

## 前置條件

- 於專案中參考 `GameFrameX.Foundation.Extensions`。
- 於檔案開頭撰寫 `using System.Linq.Expressions;` 與 `using GameFrameX.Foundation.Extensions;`。
- 目標框架需支援 `Expression<Func<T, bool>>`(標準 .NET 即可)。

## 操作步驟

### 1. 使用 `And` 連結兩個條件

當左右兩側的運算式都必須成立時，請使用 `And`(內部使用 `Expression.AndAlso`,因此支援短路求值)。

```csharp
using System.Linq.Expressions;
using GameFrameX.Foundation.Extensions;

Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.And(expr2);

bool ok1 = combined.Compile()("testing"); // true
bool ok2 = combined.Compile()("test");    // false
```

Source: [ExpressionExtension.cs#L57-L67](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L57-L67)

### 2. 使用 `Or` 連結兩個條件

當任一運算式成立即可時，請使用 `Or`(內部使用 `Expression.OrElse`,因此支援短路求值)。

```csharp
Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.Or(expr2);
bool ok = combined.Compile()("test"); // true:命中 StartsWith("test")
```

Source: [ExpressionExtension.cs#L114-L125](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L114-L125)

### 3. 使用 `AndIf` / `OrIf` 依開關進行條件式連結

若想以布林值開關判斷是否實際參與連結，請使用條件式版本。當條件為 `false` 時，會直接回傳左側運算式，不會經過存取器或改寫邏輯。

```csharp
Expression<Func<string, bool>> left  = s => s.Length > 5;
Expression<Func<string, bool>> right = s => s.StartsWith("test");

bool enableFilter = true;
var withFilter = left.AndIf(() => enableFilter, right);

enableFilter = false;
var withoutFilter = left.AndIf(() => enableFilter, right); // 與 left 等同
```

Source: [ExpressionExtension.cs#L83-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L83-L100)

### 4. 使用 `Not` 進行否定

```csharp
Expression<Func<int, bool>> expr = x => x > 5;
var neg = expr.Not(); // x => !(x > 5),即等同於 x <= 5
```

Source: [ExpressionExtension.cs#L171-L178](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L171-L178)

### 5. 多條件鏈式連結

由於回傳值同樣是 `Expression<Func<T, bool>>`,因此可以連續呼叫。

```csharp
Expression<Func<string, bool>> baseExpr = s => s != null;
var query = baseExpr
    .And(s => s.Length > 0)
    .And(s => s.Contains("foo"))
    .OrIf(() => AllowShort, s => s.Length <= 2);
```

## 常見變化

- **述詞字串 + LINQ 提供者**：連結完成後呼叫 `Compile()` 取得 `Func<T, bool>`,直接進行篩選。若與 EF Core 等 ORM 搭配使用，直接將 `combined` 傳入 `Where(...)` 即可轉換為 SQL。
- **空集合的短路處理**：先在外層使用 `IEnumerable.Any()` 等方式判斷是否為空，再呼叫 `And` / `Or`。
- **多參數 Lambda**:`CustomExpressionVisitor` 針對多參數 Lambda 只會替換第一個參數，其餘保持原樣。

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| `ArgumentNullException`(參數名 `leftExpression` / `rightExpression` / `condition` / `expr`) | 某個運算式或條件委派為 `null` | 呼叫前對運算式進行 null 檢查，或在外層提供一律回傳 `true` 的條件委派 |
| 連結後編譯失敗，並回報「參數不符」 | 左右運算式的型別不同(例如:`Func<string,bool>` 與 `Func<int,bool>`) | 確認兩個運算式使用相同的泛型參數 `T` |
| 連結結果沒有短路行為 | 誤以為本擴充使用 `And`/`Or` | 本擴充的 `And`/`Or` 內部使用 `AndAlso`/`OrElse`,因此天生就具備短路求值，無需額外處理 |
| 多參數 Lambda 連結後運作異常 | 僅替換第一個參數，其餘保持原樣 | 將述詞撰寫為只接收單一參數的 Lambda,或自行改寫運算式 |

## 背景(選讀)

`And` / `Or` / `AndIf` / `OrIf` 皆透過內部類別 `CustomExpressionVisitor`(繼承自 `ExpressionVisitor`),將左右兩個運算式各自的 `ParameterExpression` 替換為新建的統一參數，再以 `Expression.Lambda` 重新組裝。如此可在保留左右子樹原始結構的同時，確保新的運算式僅擁有單一參數，使鏈式連結與跨 ORM 轉譯更為容易。
