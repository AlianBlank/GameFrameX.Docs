# よくある問題

このドキュメント汇总了使用 GlobalConfig コンポーネント过程中〜の可能性があります遇到的常见問題及解決策。

## 概要

GlobalConfigComponent 是 GameFrameX フレームワーク中的全局設定管理コンポーネント，主な用于管理游戏应用的全局設定情報，含みます应用バージョン確認地址、リソースバージョン確認地址、服务器地址等。该コンポーネント采用 Unity コンポーネント的形式実装，〜できます柔軟地設定和使用。

> コンポーネント的詳細機能説明请リファレンス [GlobalConfig コンポーネント紹介](./1-overview.1-introduction)。
> コンポーネント的完全な API 请リファレンス [GlobalConfigComponent](./4-core-component.1-global-config-component)。

## インストール与設定

### Q1: 如何インストール GlobalConfig コンポーネント？

GlobalConfig コンポーネント〜できます通过以下方法インストール：

1. **通过 manifest.json インストール**：在プロジェクト的 `manifest.json` ファイル中追加依赖：
   ```json
   {"com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git"}
   ```

2. **通过 Unity Package Manager**：在 Unity 中选择 `Window > Package Manager`，次に点击 `+` 号追加 Git URL：
   ```
   https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git
   ```

3. **手动インストール**：直接下载リポジトリ并放置到 Unity プロジェクト的 `Packages` ディレクトリ下。

> 詳細的インストールステップ请リファレンス [インストール方法](./2-installation.1-install-methods)。

### Q2: インストール后报 "Assembly has reference to missing assembly" エラー？

这是因为 GlobalConfig コンポーネント依赖以下パッケージ：
- `com.gameframex.unity` (バージョン 1.1.1)
- `com.gameframex.unity.web` (バージョン 1.1.2)

**解決策**：確認してください这些依赖パッケージ已正确インストール。〜できます在 `manifest.json` 中追加完全な依赖：

```json
{
  "dependencies": {
    "com.gameframex.unity": "1.1.1",
    "com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git",
    "com.gameframex.unity.web": "1.1.2"
  }
}
```

### Q3: Unity バージョン兼容性如何？

根据 package.json，コンポーネントサポート的最低 Unity バージョン为 **2017.1**。もし使用更低バージョン的 Unity，〜の可能性があります会出现兼容性問題。

## コンポーネント使用

### Q4: 如何将 GlobalConfigComponent 追加到シーン？

1. 在 Unity エディタ中，作成或选择一个 GameObject
2. 在 Inspector パネル中，点击 **Add Component** ボタン
3. 検索并选择 **Game Framework > Global Config**
4. コンポーネント将追加到选定的 GameObject 上

> 詳細的追加ステップ请リファレンス [追加到シーン](./3-getting-started.1-add-to-scene)。

### Q5: 〜できます在シーン中追加多个 GlobalConfigComponent 吗？

**不お勧め**。コンポーネント使用了 `[DisallowMultipleComponent]` 特性，这限制了同一 GameObject 上只能追加一个インスタンス。虽然技术上〜できます将コンポーネント追加到不同的 GameObject，但フレームワーク設計为单例モード，お勧め只在シーン中保留一个全局設定コンポーネント。

### Q6: 如何在コード中访问 GlobalConfigComponent？

由于コンポーネント使用了 `IsAutoRegister = false`，コンポーネント不会自动登録。典型的访问方法是在シーン中查找或通过参照访问：

```csharp
// 通过 FindObjectOfType 查找
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
if (globalConfig != null)
{
    string appVersionUrl = globalConfig.CheckAppVersionUrl;
    string resourceVersionUrl = globalConfig.CheckResourceVersionUrl;
}
```

> 詳細的コード访问方法请リファレンス [コード访问](./3-getting-started.3-code-access)。

### Q7: 如何通过コード动态設定設定？

〜できます在ランタイム通过コード設定各个プロパティ：

```csharp
var globalConfig = FindObjectOfType<GlobalConfigComponent>();

// 设置各种 URL
globalConfig.CheckAppVersionUrl = "https://example.com/check-app-version";
globalConfig.CheckResourceVersionUrl = "https://example.com/check-resource-version";
globalConfig.HostServerUrl = "https://example.com/server";

// 设置附加内容
globalConfig.Content = "{\"key\": \"value\"}";

// 设置全局配置信息
ResponseGlobalInfo globalInfo = new ResponseGlobalInfo
{
    // 配置属性
};
globalConfig.SetGlobalConfig(globalInfo);
```

## プロパティ設定

### Q8: 各个プロパティ有什么作用？

| プロパティ | 説明 |
|------|------|
| **主机服务地址 (HostServerUrl)** | 后端服务器的地址，用于连接游戏服务器 |
| **检测Appバージョン地址インターフェース (CheckAppVersionUrl)** | 確認应用程序新バージョン的 URL 地址 |
| **检测リソースバージョン地址インターフェース (CheckResourceVersionUrl)** | 確認游戏リソースアップデート的 URL 地址 |
| **补充アセンブリ列表 (AOTCodeList)** | AOT コンパイル时〜する必要があります补充的アセンブリ列表（JSON フォーマット） |
| **附加内容 (Content)** | 其他附加的設定内容 |
| **补充元数据列表 (AOTCodeLists)** | AOT 补充元数据列表 |

> 詳細的プロパティ設定説明请リファレンス [設定プロパティ](./3-getting-started.2-configure-properties)。

### Q9: AOTCodeList 和 AOTCodeLists 有什么区别？

- **AOTCodeList** (字符串タイプ)：用于在 Inspector 中以 JSON 字符串フォーマット输入 AOT コード列表
- **AOTCodeLists** (列表タイプ)：解析后的 AOT コード列表，供ランタイム使用

設定 AOTCodeList 时，系统会自动解析 JSON 并填充到 AOTCodeLists：

```csharp
// 设置 JSON 格式的 AOT 代码列表
globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\", \"Assembly3\"]";

// 自动解析，可以在 AOTCodeLists 中获取解析结果
List<string> aotCodeLists = globalConfig.AOTCodeLists;
```

## AOT 設定相关

### Q10: 什么是 AOT コード列表？为什么要設定它？

AOT (Ahead-of-Time) コンパイル是 .NET 的一种コンパイルモード，主な用于 IL2CPP 等プラットフォーム。某些ジェネリックタイプ和反射コード在 AOT コンパイル时〜の可能性があります无法正确生成，〜する必要があります通过 AOT コード列表来指定〜する必要があります额外処理的アセンブリ。

> 詳細的 AOT 設定説明请リファレンス [AOT コード列表設定](./7-aot-configuration.1-aot-code-list)。

### Q11: 設定 AOTCodeList 时出现 JSON 解析エラー？

もし在設定 AOTCodeList 时遇到解析エラー，〜の可能性があります的原因和解決策：

1. **JSON フォーマットエラー**：確認してください JSON フォーマット正确
   ```csharp
   // 错误示例
   globalConfig.AOTCodeList = "Assembly1, Assembly2"; // 错误的格式

   // 正确示例
   globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\"]"; // 正确的 JSON 数组格式
   ```

2. **特殊字符转义**：もし字符串中パッケージ含特殊字符，確認してください正确转义

### Q12: AOT コード列表为空会导致什么問題？

もし AOT コード列表为空，某些使用ジェネリック或反射的機能〜の可能性があります在 IL2CPP プラットフォーム上无法正常工作。具体表现含みます：
- ジェネリックタイプシリアライズ失敗
- 反射取得タイプ失敗
- 某些动态コード执行例外

## エディタ相关

### Q13: 在 Play モード下无法编辑プロパティ？

这是正常行为。Inspector 中的プロパティ在 **Play モード**下是只读的，这是为了保护ランタイム設定不被意外変更。

```csharp
// GlobalConfigComponentInspector.cs 中的实现
EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode & Application.isPlaying);
{
    // 属性编辑区域
}
EditorGUI.EndDisabledGroup();
```

### Q14: 原始数据 (OriginalData) 是只读的？

是的，原始数据プロパティ在 Inspector 中是只读的。该プロパティ用于存储从服务器取得的原始設定数据，通常在ランタイム通过コード設定：

```csharp
// 设置原始数据
globalConfig.SetOriginalData(jsonString);

// 读取原始数据
string originalData = globalConfig.OriginalData;
```

## ランタイム相关

### Q15: コンポーネント的 Awake メソッド有什么特殊処理？

コンポーネントオーバーライド了 `Awake` メソッド，并将 `IsAutoRegister` 設定为 `false`：

```csharp
protected override void Awake()
{
    IsAutoRegister = false;
    base.Awake();
}
```

这意味着コンポーネント不会自动登録到フレームワーク的コンポーネント管理系统中，〜する必要があります開発者手动管理或通过其他方法访问。

### Q16: 如何从服务器取得并設定全局設定？

典型的工作フロー如下：

1. 使用設定的 URL 向服务器发送请求
2. 服务器返す設定数据（JSON フォーマット）
3. 解析响应数据到 ResponseGlobalInfo 对象
4. 呼び出し SetGlobalConfig 設定全局設定

```csharp
// 伪代码示例
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
string url = globalConfig.HostServerUrl;

// 发送网络请求获取配置
// ...
ResponseGlobalInfo response = ParseServerResponse(data);
globalConfig.SetGlobalConfig(response);

// 访问配置信息
ResponseGlobalInfo info = globalConfig.GlobalInfo;
```

## 故障排查

### Q19: 常见問題排查ステップ

1. **確認依赖**：確認所有依赖パッケージ已正确インストール
2. **確認 Unity バージョン**：確認してください使用 Unity 2017.1 或更高バージョン
3. **確認コンポーネント追加**：確認 GlobalConfigComponent 已正确追加到シーン
4. **確認プロパティ設定**：確認必要的 URL プロパティ已設定
5. **確認ログ**：確認 Unity 控制台是否有エラー或警告情報

### Q20: ランタイム找不到 GlobalConfigComponent？

もし `FindObjectOfType<GlobalConfigComponent>()` 返す null，〜の可能性があります原因：
1. コンポーネント未追加到任何 GameObject
2. コンポーネント追加到了未激活的 GameObject
3. シーン未正确ロード

**解決策**：
- 確認コンポーネント已追加到シーン中的活动 GameObject
- 確認してください GlobalConfig 所在的シーン已被ロード

## 設定ファイル为空或未ロード

**原因**：未在 Inspector 中設定 GlobalConfigComponent 或設定ファイル路径不正确。

**解決策**：在 Unity エディタ中选中挂载 GlobalConfigComponent 的 GameObject，在 Inspector パネル中確認設定项是否已正确填写。

## バージョン確認 URL 无法访问

**原因**：服务器地址設定エラー或网络不可达。

**解決策**：確認 `AppVersionCheckUrl` 和 `ResourceVersionCheckUrl` 是否为有效的 HTTP/HTTPS 地址，確認してください设备网络连通。
