# How to Define Enums, Structs, and Complex Fields

When you need a field column to accept only "a fixed set of values" (e.g., item types), or want to bundle multiple fields into a composite field (e.g., coordinates, price ranges), you need the two "advanced definition tables": `__enums__.xlsx` and `__beans__.xlsx`. This article walks you through defining an enum and a struct from scratch, and referencing them in data tables.

## Prerequisites

- You have already created at least one regular data table under `Excels/Tables/` by following "How to Create a New Configuration Table" (and understand the meaning of the first 4 header rows).
- Excel, WPS, or a tool capable of editing `.xlsx` files is installed locally.
- You have opened `__enums__.xlsx` and `__beans__.xlsx` under the `Excels/` directory (even if they are empty).

> Once these two tables are defined, you can write enum names or struct names directly in the `##type` row of any data table as field types.

## Steps

### Step 1: Open the "Enum Definition Table"

Open `Excels/__enums__.xlsx`. This table has a single purpose: to define all "enums" centrally here.

Its header likewise consists of 4 fixed rows:

| Row | Marker | What to Fill In |
|-----|--------|-----------------|
| 1 | `##var` | English name of each value in the enum |
| 2 | `##type` | Write `int` for all |
| 3 | `##group` | Leave empty |
| 4 | `##` | Chinese description |

> The tool identifies an enum by its **English column name (the `##var` row)**. Naming rule: `EnumName.Member`, e.g., `ItemType.Consumable`.

### Step 2: Define an Enum

For example, suppose you want to create an enum `ItemType` for "item types" containing three kinds: consumables, equipment, and materials. Fill in `__enums__.xlsx` as follows:

| ##var | ItemType.Consumable | ItemType.Equipment | ItemType.Material |
|-------|---------------------|--------------------|-------------------|
| ##type | int | int | int |
| ##group | | | |
| ## | Consumable | Equipment | Material |

**Naming key points:**

| Notation | Meaning |
|----------|---------|
| `ItemType.Consumable` | Enum name = `ItemType`, member = `Consumable` |
| `Color.R` / `Color.G` / `Color.B` | Multiple enums can coexist in the same table, distinguished by column name |

Once defined, writing `ItemType` in the `##type` row of any data table references this enum.

### Step 3: Use the Enum in a Data Table

Create (or open) an item table and simply write the enum name as the type of the "type" column:

| ##var | id | name | type |
|-------|----|------|------|
| ##type | int | text | ItemType |
| ##group | | | |
| ## | Item ID | Item Name | Type |
| | 10001 | diamond | ItemType.Consumable |
| | 10002 | sword | ItemType.Equipment |

The tool validates that cells must contain a member name starting with `ItemType.`; otherwise, it reports an "undefined enum value" error at generation time.

### Step 4: Open the "Struct Definition Table"

Open `Excels/__beans__.xlsx`. The purpose of this table: to bundle several fields into a reusable composite type (e.g., `vec3` coordinates, a `Reward` reward pack).

The header likewise consists of 4 fixed marker rows, with the same meaning as regular tables:

| Row | Marker | What to Fill In |
|-----|--------|-----------------|
| 1 | `##var` | Field name (English) |
| 2 | `##type` | Field type (can be `int`, `string`, an enum name, or even another struct name) |
| 3 | `##group` | Leave empty |
| 4 | `##` | Chinese description |

> Structs are identified by the **column names (containing `.`)** in the `##var` row; for example, `Reward.ItemId` and `Reward.Count` represent two fields of the same struct `Reward`.

### Step 5: Define a Struct

For example, define a reward pack `Reward` that contains an item ID and a quantity:

| ##var | Reward.ItemId | Reward.Count |
|-------|---------------|--------------|
| ##type | int | int |
| ##group | | | |
| ## | Item ID | Quantity |

This declares a struct named `Reward` with two fields: `ItemId` (int) and `Count` (int).

**Composite fields can also nest structs or enums:**

| ##var | Reward.ItemId | Reward.ItemType | Reward.Pos.x | Reward.Pos.y |
|-------|---------------|------------------|--------------|--------------|
| ##type | int | ItemType | float | float |
| ##group | | | | |
| ## | Item ID | Item Type | X Coordinate | Y Coordinate |

The example above defines two structs: `Reward` (containing `ItemId`, `ItemType`, `Pos`) and `Pos` (containing `x`, `y`).

### Step 6: Use a Struct in a Data Table

Simply write the struct name directly in the `##type` row, and fill the cell with values in field order (using the separators `,` or `;`; the tool reads them in declaration order):

| ##var | id | first_reward |
|-------|----|--------------|
| ##type | int | Reward |
| ##group | | | |
| ## | Achievement ID | First-Clear Reward |
| | 900001 | 10001,1 |
| | 900002 | 10002,5 |

> The in-cell separator depends on the tool's actual configuration (comma `,` by default); the field order must match the `##var` order in `__beans__.xlsx`.

## Common Variants

| Scenario | Notation |
|----------|----------|
| List-type fields (multiple instances of the same struct) | Write the type as `list,Reward`; separate each Reward in the cell with `;` |
| Dictionary-type fields | Write the type as `map,int,Reward` (key type first, value type after) |
| Multi-language fields embedded in a struct | Just write the field type as `text` |
| Reuse built-in coordinate types | Write `vec2` / `vec3` / `vec4` directly in `##type` (provided by [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml)) |

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| *Undefined enum* reported at generation | The enum name is not defined in `__enums__.xlsx` | Add it in `__enums__.xlsx` using the `EnumName.Member` form |
| *Unsupported Chinese table name* reported at generation | Column names/enum names use Chinese | Enum names, member names, and field names must be in English |
| Struct fields do not match | Cell value order differs from the field order in `__beans__.xlsx` | Fill in values strictly following the `##var` row order |
| All data columns fail to be read | The `__var` / `##type` / `##group` / `##` markers are written incorrectly | These 4 markers are fixed strings and must be copied exactly |
| Same-enum conflict | Members with different prefixes are written in the same column of `__enums__.xlsx` | Use a separate column for each enum; do not mix them |

## Background (Optional)

`__enums__.xlsx` and `__beans__.xlsx` essentially move the work of "writing `enum` / `class` in code" into Excel: designers fill in the headers, the tool generates the corresponding C# enums and classes, and the client (Unity) and server (.NET) each receive a copy of type-matching code. Built-in types (such as coordinates) are provided by [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml), automatically adapting to each platform's coordinate implementation.
