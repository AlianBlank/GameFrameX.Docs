# One-Click Switch for Domestic Mini Game Platforms

Through the commands under the Unity editor menu `GameFrameX/Scripting Define Symbols/Domestic Mini Games`, you can enable or disable the adaptation macro definitions for a specific domestic mini game platform with one click, and automatically mask the mutually exclusive macros from other domestic mini game platforms.

## Prerequisites

- The editor Build Target has been switched to `WebGL` (the menu items and implementation of `MiniGameDefineSymbolHelper` are wrapped under `#if UNITY_WEBGL`; otherwise the menu will not appear).
- The project has imported the GameFrameX editor extension assembly (the scripts under `Editor/MiniGame/` in this directory).
- Understand that the macro definitions corresponding to each platform will be written to `Project Settings → Player → Scripting Define Symbols` (WebGL platform).

## Operation Steps

1. In the Unity top menu, click **GameFrameX → Scripting Define Symbols → Domestic Mini Games**, and expand the submenu.
2. Select the **Enable xxx Mini Game** item under the target platform.
3. After the switch is complete, the Console will print `xxx Mini Game macro definition [ENABLE_XXX_MINI_GAME] has been enabled` for each entry.
4. When switching to another platform, select the corresponding Enable item again; the macros from the old platform will be automatically cleaned up.

For example, enabling the WeChat Mini Game:

```csharp
// Editor/MiniGame/DomesticMiniGames/MiniGameDefineSymbolHelper.WeChat.cs
public static readonly string[] EnableWeChatMiniGameScriptingDefineSymbol =
    new[] { "ENABLE_WECHAT_MINI_GAME", "WEIXINMINIGAME" };

#if UNITY_WEBGL
[MenuItem("GameFrameX/Scripting Define Symbols/Domestic Mini Games(国内小游戏)/Enable WeChat Mini Game(开启[微信小游戏]适配)", false, 2000)]
#endif
public static void EnableWeChatMiniGame()
{
#if UNITY_WEBGL
    DisableOtherMiniGameScriptingDefineSymbols(EnableWeChatMiniGameScriptingDefineSymbol);
    foreach (var define in EnableWeChatMiniGameScriptingDefineSymbol)
    {
        if (!ScriptingDefineSymbols.HasScriptingDefineSymbol(BuildTargetGroup.WebGL, define))
        {
            ScriptingDefineSymbols.AddScriptingDefineSymbol(define);
        }
        Debug.Log($"微信小游戏宏定义 [{define}] 已经打开");
    }
    EnableUnifiedMiniGameScriptingDefineSymbol();
#endif
}
```

## Common Variants

- **Disable a platform's macro**: Select `Disable xxx Mini Game`, which will remove the macros corresponding to that platform from `Scripting Define Symbols` and print `xxx Mini Game macro definition [xxx] has been disabled`.
- **Only remove the current platform's macros, without affecting other domestic mini game platform macros**: When disabling, `DisableOtherMiniGameScriptingDefineSymbols` will not be called; only the unified mini game macros will be refreshed.
- **Enabling multiple platforms simultaneously**: Mutually exclusive by default. Each time you Enable a platform, `DisableOtherMiniGameScriptingDefineSymbols` will first clear the macros of other domestic mini game platforms.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The `Domestic Mini Games` submenu is not visible in the menu | The current Build Target is not WebGL | Switch to WebGL and then open the menu |
| Compilation error after Enable: `The type or namespace xxx could not be found` | The third-party mini game SDK's project has not been imported | First install the Unity adaptation package for the corresponding platform, then Enable the macro |
| After switching to a new platform, the old platform's code still participates in compilation | Manual merging of `Scripting Define Symbols` caused the cleanup to fail | Clear the WebGL macros in Player Settings, then use the Enable menu to reset |

## Background

The Enable process follows a fixed three-step workflow: first call `DisableOtherMiniGameScriptingDefineSymbols` to clean up macros from other domestic mini game platforms → iterate through this platform's macro set, calling `AddScriptingDefineSymbol` as needed → call `EnableUnifiedMiniGameScriptingDefineSymbol()` to refresh the unified mini game macros; the Disable process removes this platform's macros and calls `RefreshUnifiedMiniGameScriptingDefineSymbol()`. This "clear first, then add" approach avoids type conflicts caused by the same code referencing different platform SDKs when macros from multiple domestic mini game platforms exist simultaneously.
