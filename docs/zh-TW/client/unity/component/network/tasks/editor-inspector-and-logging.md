# 啟用網路日誌與使用 Inspector 面板

透過 Unity 選單 `GameFrameX/Scripting Define Symbols` 啟用傳送/接收日誌巨集後，網路元件會將每一條傳送/接收訊息的 ID、型別與 JSON 內容列印到主控台；此外，在播放模式中，選取掛載了 `NetworkComponent` 的 GameObject,即可在 Inspector 面板中即時檢視各網路通道的連線狀態、已傳送/已接收封包數量與心跳進度，並支援一鍵斷線。

## 前置條件

- 專案中已安裝 GameFrameX Network 套件，且場景中已掛載 `NetworkComponent`。
- 日誌透過 `Log.Debug` 輸出；請確認已啟用 GameFrameX 日誌元件的 Debug 層級日誌，否則主控台不會顯示任何內容。

## 步驟

### 1. 啟用/停用網路日誌

1. 在 Unity 頂端的選單列中找到 `GameFrameX/Scripting Define Symbols` 群組。
2. 視需要點選以下選單項目(點選後會將對應巨集寫入 Player Settings 中的 Scripting Define Symbols,Unity 會自動重新編譯)：

| 選單項目 | 用途 | 對應巨集 |
|------|------|--------|
| `Enable Network Send Logs(开启网络发送日志打印)` | 列印傳送的訊息 | `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Disable Network Send Logs(关闭网络发送日志打印)` | 關閉傳送日誌 | 移除 `ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG` |
| `Enable Network Receive Logs(开启网络接收日志打印)` | 列印接收的訊息 | `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |
| `Disable Network Receive Logs(关闭网络接收日志打印)` | 關閉接收日誌 | 移除 `ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG` |

選單實作來自 [NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L67-L98),巨集常數定義如下：

```csharp
public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG";
public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG";
public const string ForceEnableNetworkSendLogScriptingDefineSymbol = "FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET";
```

來源:[NetworkLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/NetworkLogScriptingDefineSymbols.cs#L40-L44)

3. 啟用後執行遊戲，主控台會輸出如 `发送消息 ID:[10001,0,xxxReq] 消息内容:{...}` 與 `收到消息 ID:[...] 消息内容:{...}` 的日誌。實際的列印邏輯如下：

```csharp
protected void DebugSendLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_SEND_LOG
    var messageId = ProtoMessageIdHandler.GetReqMessageIdByType(messageObject.GetType());
    if (!IgnoreSendIds.Contains(messageId))
    {
        Log.Debug($"发送消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}

protected void DebugReceiveLog(MessageObject messageObject)
{
#if ENABLE_GAMEFRAMEX_NETWORK_RECEIVE_LOG
    var messageId = ProtoMessageIdHandler.GetRespMessageIdByType(messageObject.GetType());
    if (!IgnoreReceiveIds.Contains(messageId))
    {
        Log.Debug($"收到消息 ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] 消息内容:{Utility.Json.ToJson(messageObject)}");
    }
#endif
}
```

來源:[NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L949-L969)

### 2. 設定日誌中要忽略的訊息 ID

高頻訊息(如心跳)可能會灌爆主控台；您可以在 Inspector 中將其從日誌中排除：

1. 在場景中選取掛載了 `NetworkComponent` 的 GameObject。
2. 在 Inspector 面板中找到下列兩個欄位(**僅可在播放模式外編輯**)：
   - `Ignore Log Printing For Sent Message IDs`:傳送端忽略的訊息 ID 清單。
   - `Ignore Log Printing Of Received Message IDs`:接收端忽略的訊息 ID 清單。
3. 填入您不想列印的訊息 ID;變更會在進入播放模式時生效。符合清單的訊息將不會執行上方的 `Log.Debug`。

若需要在程式碼中動態設定，通道基底類別提供了公開方法：

```csharp
public void SetIgnoreLogNetworkIds(List<int> sendIds, List<int> receiveIds)
{
    IgnoreSendIds = sendIds;
    IgnoreReceiveIds = receiveIds;
}
```

來源:[NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L977-L982)

### 3. 在 Inspector 面板中檢視執行階段狀態

1. 進入播放模式，並在 Hierarchy 中選取場景的 `NetworkComponent` GameObject。
2. Inspector 頂部會顯示 `Network Channel Count`,其後為每個網路通道各一組，內容包含：

| 面板欄位 | 意義 |
|------|------|
| 通道名稱 + `Connected`/`Disconnected` | 通道名稱與連線狀態 |
| `Address Family` | 位址家族(IPv4/IPv6 等)|
| `Local Address` / `Remote Address` | 本機/遠端 Socket 位址；未連線時顯示 `Unavailable` |
| `Send Packet` | `sent packet count / pending packet count` |
| `Miss Heart Beat Count` | 遺失的心跳次數 |
| `Heart Beat` | `elapsed time / heartbeat interval`(秒，保留兩位小數)|
| `Disconnect` 按鈕 | 斷開該通道的連線 |

核心的面板繪製程式碼如下;`Disconnect` 按鈕內部會呼叫 `Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError)`:

```csharp
EditorGUILayout.LabelField(networkChannel.Name, networkChannel.Connected ? "Connected" : "Disconnected");
EditorGUILayout.LabelField("Address Family", networkChannel.AddressFamily.ToString());
EditorGUILayout.LabelField("Send Packet", Utility.Text.Format("{0} / {1}", networkChannel.SendPacketCount, networkChannel.SentPacketCount));
EditorGUILayout.LabelField("Miss Heart Beat Count", networkChannel.MissHeartBeatCount.ToString());
EditorGUILayout.LabelField("Heart Beat", Utility.Text.Format("{0:F2} / {1:F2}", networkChannel.HeartBeatElapseSeconds, networkChannel.HeartBeatInterval));
EditorGUI.BeginDisabledGroup(!networkChannel.Connected);
{
    if (GUILayout.Button("Disconnect"))
    {
        networkChannel.Close(NetworkCloseReason.ConnectClose, (ushort)NetworkErrorCode.DisposeError);
    }
}
```

來源:[NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L95-L123)

此外，在播放模式外，Inspector 可讓您編輯兩個執行階段設定:`RPC Timeout Time In Milliseconds`(滑桿範圍 3000–50000 毫秒)與 `Focus Send Heartbeat`。在播放模式外，面板僅顯示設定區段以及提示 `Available during runtime only.`;執行階段狀態區段不會被渲染。

## 常見變體

- **強制 WebSocket 通道**：同一個選單群組還包含 `Enable Force WebSocket(开启强制使用WebSocket网络)` / `Disable Force WebSocket(关闭强制使用WebSocket网络)`,用於控制巨集 `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET`,強制網路走 WebSocket。
- **僅檢視單向流量**：只啟用 `Enable Network Receive Logs` 並關閉傳送日誌，再搭配接收忽略清單過濾掉心跳，如此就只會看到來自伺服器的下行訊息。

## 常見問題

- **啟用巨集後完全沒有日誌**：日誌層級為 `Log.Debug`;若 GameFrameX 日誌元件抑制了 Debug 層級的日誌，或訊息 ID 命中忽略清單(`IgnoreSendIds`/`IgnoreReceiveIds`),就不會列印任何內容。
- **無法在 Inspector 中修改欄位**:`RPC Timeout`、`Focus Heartbeat` 與兩個忽略清單在播放模式中是停用狀態(`EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode)`);請先離開播放模式再進行變更。
- **面板中看不到通道狀態**：執行階段狀態僅在播放模式且 GameObject 位於場景 Hierarchy 中時才會繪製；在播放模式外或選取 Prefab 資產時，僅會顯示提示訊息。
- **巨集未生效/編譯錯誤**：Unity 會在巨集寫入後觸發重新編譯。若日誌仍未列印，請檢查 `Project Settings > Player > Scripting Define Symbols` 中巨集是否確實存在(選單僅會新增或移除該巨集)。

## 背景

日誌開關採用條件編譯(`#if`)而非執行階段的布林開關，以確保停用時記錄日誌完全不產生額外開銷——整個 `Log.Debug` 呼叫與 JSON 序列化都不會進入建置輸出。Inspector 由標記了 `[CustomEditor(typeof(NetworkComponent))]` 的 `NetworkComponentInspector` 提供，它會每幀呼叫 `Repaint()` 重新整理執行階段資料，因此在播放模式中資料會持續更新。
