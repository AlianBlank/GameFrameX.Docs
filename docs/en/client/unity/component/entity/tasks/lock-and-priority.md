# How to Lock Entities and Control Recycle Priority

The entity framework reuses entity instances through object pools. You can lock an entity instance to prevent it from being automatically recycled, and set the object pool priority when creating an entity group to influence the recycle order. This page explains how to invoke these two capabilities and how they take effect.

## Prerequisites

- An `EntityComponent` has been attached to the scene, and entity groups have been added via the Inspector or code.
- Lock/unlock operations on entities within a group can only be performed after the entity group exists.

## Steps

### 1. Lock or Unlock an Entity Instance

Set via `EntityComponent.SetEntityInstanceLocked(Entity entity, bool locked)`. Once locked, the underlying object pool will not recycle the instance during automatic release; once unlocked, it becomes recyclable again.

```csharp
using GameFrameX.Entity.Runtime;
using UnityEngine;

public class MyBehaviour : MonoBehaviour
{
    [SerializeField] private EntityComponent entityComponent;

    // Lock the entity to prevent automatic recycling (e.g., while an important cutscene is playing)
    public void LockEntity(Entity entity)
    {
        entityComponent.SetEntityInstanceLocked(entity, true);
    }

    // Unlock after the cutscene ends, allowing the object pool to recycle normally
    public void UnlockEntity(Entity entity)
    {
        entityComponent.SetEntityInstanceLocked(entity, false);
    }
}
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L1140-L1170)

### 2. Set the Object Pool Priority When Adding an Entity Group

The full overload of `AddEntityGroup` accepts an `instancePriority` parameter. The larger the value, the later the instance gets recycled when the underlying object pool performs automatic release. `0` is the default value, corresponding to the constant `DefaultPriority`.

```csharp
using GameFrameX.Entity.Runtime;

public class MyBootstrap
{
    public void Setup(EntityComponent entityComponent)
    {
        // Capacity 32, expire time 60 seconds, priority 10 (higher than the default 0, recycled later)
        entityComponent.AddEntityGroup(
            entityGroupName: "Boss",
            instanceAutoReleaseInterval: 60f,
            instanceCapacity: 32,
            instanceExpireTime: 60f,
            instancePriority: 10);

        // Simplified overload using the default priority (0)
        entityComponent.AddEntityGroup("Bullet", 30f);
    }
}
```

Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L246-L290)

### 3. Configure the Priority in the Inspector

The `EntityGroup` serialized class of `EntityComponent` exposes the `InstancePriority` field, which can be adjusted directly in the Inspector. At runtime, the priority is registered to the underlying object pool along with `AddEntityGroup`.

```csharp
[SerializeField] private int m_InstancePriority = 0; // Default 0

public int InstancePriority
{
    get { return m_InstancePriority; }
}
```

| API | Location | Description |

## Common Variants

- Simplified `AddEntityGroup(string, float)`: only specifies the group name and automatic release interval; capacity, expiration, and priority all use default values.
- Serialized configuration: after adding an entity group in the `EntityComponent` Inspector, `m_InstancePriority` is passed into `AddEntityGroup` as a parameter, with no code involvement required.
- Direct invocation via `IEntityGroup`: in custom entity group helpers or manager extensions, you can also obtain an `IEntityGroup` and then call `SetEntityInstanceLocked`.

## Common Mistakes

- Locking a `null` entity: `SetEntityInstanceLocked` accesses `entity.gameObject`, so passing `null` throws a null reference; first obtain a valid entity via `GetEntity(entityId)`.
- Assuming a locked entity won't be recycled by `HideEntity`: locking only affects the object pool's automatic recycling; `HideEntity` will still immediately return the entity to the pool, so combine it with your business logic accordingly.
- Assuming a larger priority value is "better": here "high priority" = recycled later, not higher quality; before setting it, confirm it matches the expectation that "critical assets are recycled last".
- Forgetting to unlock: locked entity instances remain resident in the object pool indefinitely; a large number of locks that are never unlocked will exhaust the object pool capacity and affect subsequent `ShowEntity` calls.

## Background (Optional)

Locking is ultimately forwarded to the underlying `IObjectPool<EntityInstanceObject>.SetLocked`, where the object pool skips locked objects when `AutoReleaseInterval` triggers; priority is passed into `CreateSingleSpawnObjectPool` when the `EntityGroup` is constructed, serving as the basis for the object pool itself to choose recycle targets among multiple groups.
