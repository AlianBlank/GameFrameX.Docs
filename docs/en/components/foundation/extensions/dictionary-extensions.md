# How to Use Dictionary Extensions (Bidirectional Dictionary, Disposable Dictionary)

This page introduces how to use the three kinds of dictionary containers and extension methods under the `GameFrameX.Foundation.Extensions` namespace: `BidirectionalDictionary<TKey, TValue>` (key↔value bidirectional mapping), `DisposableDictionary<TKey, TValue>` / `DisposableConcurrentDictionary<TKey, TValue>` (automatic value disposal), and the `AddOrUpdate` / `TryAdd` extensions in `IDictionaryExtensions`. After reading, you will be able to apply bidirectional mapping and managed resource disposal to your own types with minimal changes.

## Prerequisites

- The .NET project references the `GameFrameX.Foundation.Extensions` assembly.
- Source code location: `GameFrameX.Foundation.Extensions/`. The namespace is `GameFrameX.Foundation.Extensions`.
- The `TValue` of all disposable dictionaries must implement `System.IDisposable`.

## Steps

### 1. Use `BidirectionalDictionary` for bidirectional key↔value mapping

The bidirectional dictionary maintains both the forward and reverse mappings simultaneously with two internal `Dictionary` instances, so lookups from either side are O(1). It requires that **both keys and values are unique**.

```csharp
using GameFrameX.Foundation.Extensions;

var map = new BidirectionalDictionary<int, string>(initialCapacity: 16);

map.TryAdd(1, "Alice");
map.TryAdd(2, "Bob");

// Forward: key -> value
if (map.TryGetValue(1, out var name))
{
    Console.WriteLine(name); // Alice
}

// Reverse: value -> key
if (map.TryGetKey("Bob", out var id))
{
    Console.WriteLine(id); // 2
}
```

You can customize key/value comparers and update existing mappings in both directions:

```csharp
var map = new BidirectionalDictionary<string, int>(
    initialCapacity: 8,
    keyComparer: StringComparer.OrdinalIgnoreCase,
    valueComparer: null);

// Update the value by key (the reverse mapping is kept in sync)
map.TryUpdateByKey("score", 99);

// Update the key by value (the forward mapping is kept in sync)
map.TryUpdateByValue(99, "Score");
```

Source: [BidirectionalDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/BidirectionalDictionary.cs#L47-L204)

Common APIs:

| Method | Purpose |
|------|------|
| `TryAdd(key, value)` | Adds only if neither the key nor the value already exists; returns `false` on failure |
| `TryGetValue(key, out value)` | Forward lookup |
| `TryGetKey(value, out key)` | Reverse lookup |
| `TryUpdateByKey(key, newValue)` | Changes the value via the key, with reverse synchronization |
| `TryUpdateByValue(value, newKey)` | Changes the key via the value, with forward synchronization |
| `ContainsKey` / `ContainsValue` | Checks for existence |
| `Clear()` | Clears the bidirectional mapping |

### 2. Use `DisposableDictionary` to dispose values along with the container

`DisposableDictionary<TKey, TValue>` inherits from `NullableDictionary<TKey, TValue>` with the constraint `TValue : IDisposable`. On `Dispose()`, it calls `Dispose()` on every non-null value one by one and forwards exceptions to `DisposalErrorHandler`, so that a single value's disposal failure will not block subsequent values.

```csharp
using GameFrameX.Foundation.Extensions;

public sealed class MyHandle : IDisposable
{
    public void Dispose() { /* dispose underlying resources */ }
}

// When the using block ends, all values will be disposed
using var cache = new DisposableDictionary<string, MyHandle>
{
    DisposalErrorHandler = (value, ex) =>
        Console.WriteLine($"释放失败:{ex.Message}")
};

cache.Add("session-1", new MyHandle());
cache["session-2"] = new MyHandle();

// Afterwards, any Add/Remove/assignment/enumeration on the disposed dictionary will throw ObjectDisposedException
```

Source: [DisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DisposableDictionary.cs#L11-L219)

For thread-safe scenarios, use `DisposableConcurrentDictionary<TKey, TValue>` instead; the API usage is identical.

### 3. Use `AddOrUpdate` from `IDictionaryExtensions`

The extension methods provide overloads for `IDictionary<TKey, TValue>`, `NullableDictionary<TKey, TValue>`, and `NullableConcurrentDictionary<TKey, TValue>`.

```csharp
using GameFrameX.Foundation.Extensions;

var dict = new Dictionary<int, string>();
dict.AddOrUpdate(new Dictionary<int, string>
{
    [1] = "one",
    [2] = "two",
});

// Single AddOrUpdate: adds if the key does not exist, otherwise uses the factory function to return the new value
var current = dict.AddOrUpdate(
    key: 3,
    addValue: "three",
    updateValueFactory: (k, old) => old + "!");

// Overload without a factory: directly overwrites with a fixed value when the key exists
dict.AddOrUpdate(key: 1, addValue: "ONE", updateValue: "uno");
```

## Common Variants

| Scenario | Recommended Type | Reason |
|------|----------|------|
| Need to look up keys by value | `BidirectionalDictionary<TKey, TValue>` | O(1) reverse lookup |
| Values are managed resources that need centralized disposal | `DisposableDictionary<TKey, TValue>` | `Dispose` automatically disposes all values |
| Used in multi-threaded scenarios where values need disposal | `DisposableConcurrentDictionary<TKey, TValue>` | Concurrency-safe with automatic disposal |
| Allow null keys or need a fallback default value | `NullableDictionary<TKey, TValue>` | Supports null keys and `FallbackValue` |
| Want upsert semantics on a regular Dictionary | `IDictionary.AddOrUpdate` | No need to replace it with a new collection |

## Common Mistakes

| Symptom | Cause | Fix |
|------|------|------|
| `BidirectionalDictionary.TryAdd` always returns `false` | The key or value already exists in the other side of the mapping | `Remove` first and then `TryAdd`, or switch to `TryUpdateByKey` / `TryUpdateByValue` |
| `DisposableDictionary` throws `ObjectDisposedException` after `Dispose` | `Add` / `Remove` / indexer set / `GetEnumerator` was called after disposal | Ensure there is no access after `Dispose`; or extend the lifetime until access is no longer needed |
| Ambiguous `NullableDictionary(int)` call | When `TValue` is `int`, the compiler cannot distinguish between `capacity` and `fallbackValue` | Use `NullableDictionary<int, int>.WithCapacity(n)` |
| `AddOrUpdate` throws `ArgumentNullException` | `self`, `key`, or `updateValueFactory` is null | Explicitly pass non-null arguments |

## Background (Optional)

`BidirectionalDictionary` uses two `Dictionary` instances that mirror each other to achieve O(1) bidirectional lookup, at the cost of double writes during insertion and rollback on failure; `DisposableDictionary` binds the disposal semantics of `IDisposable` to dictionary semantics, and uses `DisposalErrorHandler` to turn a single value's disposal failure into a callback instead of interrupting the flow, so that even if some resources fail, the remaining resources will still be disposed.
