# DefaultPaymentManager のスタブ警告が表示された場合の対処方法

Unity Console に `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).` という警告が表示された場合、現在の `PaymentComponent` がいずれのチャネル（Google / Apple / WebGL / PC）のペイメントマネージャーも解決できず、スタブ実装である `DefaultPaymentManager` にフォールバックしていることを示します。これはエラーではなく、スタブ実装は警告を出力して「未実装」を返すだけですが、すべての決済呼び出しは実際には機能しません。解決方法は、実行プラットフォームが対応するチャネル実装タイプにヒットするようにすることです。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| Console に `You are using DefaultPaymentManager which is a stub. ...` と出力される | `PaymentComponent.Awake()` 内でプラットフォームマクロがいずれの分岐にもヒットせず、`componentType` が `typeof(DefaultPaymentManager).FullName` にフォールバックしている | 現在の実行プラットフォームのマクロと `m_component*Type` フィールドの設定を確認してください。下記の[修正手順](#修正手順)を参照 |
| `Init(...)`、`Buy(...)`、`QueryPurchases(...)`、`ConsumePurchase(...)` などの任意の呼び出しでも同じ警告が出力される | `DefaultPaymentManager` のすべてのメソッドは空の実装であり、`Log.Warning(NotImplWarning)` を行うのみ | チャネルパッケージを統合した後で再度呼び出してください。[修正手順](#修正手順)を参照 |
| `IsReady()` が常に `false` を返し、購入を一切開始できない | `DefaultPaymentManager.IsReady()` はハードコードで `false` を返す | スタブ実装の想定動作であり、チャネル実装を統合すれば自然に回復します |
| Editor で実行するとこの警告が表示される | Editor / 非モバイルプラットフォームは `#else` 分岐に入り、`DefaultPaymentManager` が固定で使用される | 想定動作です。Editor でテストする必要がある場合は[よくあるパターン](#よくあるパターン)を参照 |
| 実機（Android / iOS）でもこの警告が表示される | チャネル実装のアセンブリがインストールされておらず、`Utility.Assembly.GetType(componentType)` が null を返す、またはタイプが見つからない | 対応するチャネルパッケージ（Google / Apple / WebGL / PC）をインストールするか、Inspector 内のタイプ名を手動で修正してください |

## 修正手順

### 1. 現在ヒットしているプラットフォーム分岐を確認する

`PaymentComponent.Awake()` はコンパイルマクロに基づいて実装タイプを選択しており、すべてのマクロにヒットしなかった場合にのみ `DefaultPaymentManager` にフォールバックします：

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
            if (_paymentManager == null)
            {
                Log.Fatal("Pay Manager is invalid.");
                return;
            }
```

出典: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L94)

上の表と照らし合わせてください：実機の Android であれば `UNITY_ANDROID` に、iOS であれば `UNITY_IOS` にヒットするはずです。チャネル分岐にヒットしているにもかかわらず警告が表示される場合は、チャネルタイプ自体が不足しています（手順 3 を参照）。

### 2. チャネルタイプ名の設定を確認する

`PaymentComponent` 上のチャネルタイプ名はシリアライズフィールドであり、デフォルト値は以下の通りです：

```csharp
private IPaymentManager _paymentManager;
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

出典: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L23-L28)

Inspector で `PaymentComponent` がアタッチされたオブジェクト（コンポーネントのメニューパスは `GameFrameX/Payment`）を選択し、対応プラットフォームのフィールドが無効な値に変更されていないか確認してください。手動で変更した覚えがあり不確かな場合は、上記のデフォルトの完全名に戻してください。

### 3. 対応するチャネル決済パッケージをインストールする

デフォルトのタイプ名が指しているのは独立したチャネルパッケージ内のクラスであり、このパッケージ自体はインターフェースとスタブ実装のみを提供します：

| プラットフォームマクロ | 期待される実装タイプ | 必要なチャネルパッケージ |
|--------|----------------|------------|
| `UNITY_ANDROID` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` | Google 決済パッケージ |
| `UNITY_IOS` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple 決済パッケージ |
| `UNITY_WEBGL` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` | WebGL 決済パッケージ |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` | PC 決済パッケージ |
| `UNITY_STANDALONE_OSX` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` | Apple 決済パッケージ |
| その他（Editor を含む） | `GameFrameX.Payment.Runtime.DefaultPaymentManager` | 本パッケージに同梱 |

チャネルパッケージがインストールされていない場合、`Utility.Assembly.GetType(componentType)` でタイプを取得できず、実行時にはスタブ実装のみが得られてこの警告が発生します。チャネルパッケージをインストールした後、Play モードに入り直す、または再ビルドするだけで解決します。

### 4. ログの動作でスタブ実装を確認する

スタブ実装のすべてのメソッドの動作は以下の通りです（問題が確かにスタブ実装に起因していることを逆方向から確認するためのものです）：

```csharp
public sealed class DefaultPaymentManager : BasePaymentManager
{
    private const string NotImplWarning = "You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).";

    public override void Init(bool isDebug = false, bool isClientVerify = false)
    {
        Log.Warning(NotImplWarning);
    }

    public override bool IsReady()
    {
        return false;
    }
```

出典: [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L17-L36)

残りのメソッド（`QueryPurchases`、`ConsumePurchase`、`BuyInApp`、`BuySubs`、`Buy`、`SetPredefinedProductIds`）も `Init` と同様に `Log.Warning(NotImplWarning)` を出力するだけです。詳細は [DefaultPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/DefaultPaymentManager.cs#L38-L81) を参照してください。

## よくあるパターン

- **単に Editor でログが流れるのを防ぎたい場合**：Editor のプラットフォームマクロは `#else` 分岐に入るため、必然的に `DefaultPaymentManager` が使用され、設定でこの警告を消すことはできません。ログフィルターでこの警告テキストを除外するか、決済インターフェースを呼び出す前に `IsReady()` でガードを入れる（スタブ実装は常に `false` を返します）ことで対処できます。
- **独自のサーバー/チャネルを接続する場合**：`BasePaymentManager` を継承して `IPaymentManager` の抽象メンバー（`Init`、`IsReady`、`SetPredefinedProductIds`、`QueryPurchases`、`ConsumePurchase`、`Buy` シリーズ。抽象シグネチャは [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L61-L96) を参照）を実装し、その後 Inspector の対応プラットフォームの `m_component*Type` フィールドを自分の実装クラスの完全名に変更すれば、スタブ実装を置き換えられます。

## 検証

1. Play モードに入り直すか再ビルドして実行すると、Console に `You are using DefaultPaymentManager which is a stub. ...` 警告が表示されなくなります。
2. `PaymentComponent.Init(...)` を呼び出した後に `IsReady()` を呼び出します（コンポーネントはそのままマネージャーへ委譲します。詳細は [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L115) を参照）：スタブ実装では常に `false` ですが、チャネル実装では初期化完了後、準備が整えば `true` を返すはずです。
3. テスト購入を一度実行すると、`OnPurchaseSuccess` / `OnPurchaseFailed` イベントのコールバックが届くはずです。スタブ実装ではこれらのイベントは決してトリガーされません（`Raise*` の呼び出しが一切ありません）。

## 背景

`DefaultPaymentManager` は、フレームワークが Editor と未識別プラットフォームのために用意したフォールバック実装であり、チャネルパッケージを一切統合していなくてもゲームがコンパイル・起動できることを保証します。また、決済インターフェースを誤って使用するたびに、警告の形で開発者にチャネル実装の統合を促します（CHANGELOG にも「すべてのメソッドに未実装警告ログを追加」「`IsReady()` は `false` を返す」という 2 つの動作が明確に記録されています）。実装の選択は完全にコンパイルマクロとシリアライズされたタイプ名によって決まり、実行時環境には依存しないため、設定の修正やパッケージのインストールだけで解決でき、フレームワークコードを変更する必要はありません。
