# 5분 만에 시작 프로세스 연동

이 페이지의 단계를 따라 하면, 패키지 설치부터 `StartupRunner.Run(...)` 호출 한 번을 성공적으로 실행하는 데 약 5분이 걸립니다: `StartupOptions` 에셋 하나를 생성하고, 두 개의 인터페이스를 구현한 뒤, 부트스트랩 스크립트 하나를 붙여 시작하면 됩니다.

## 사전 조건

- Unity 2019.4+
- GameFrameX 프레임워크 및 해당 의존성 설치됨:`com.gameframex.unity` / `com.gameframex.unity.procedure` / `com.gameframex.unity.fsm` / `com.gameframex.unity.event` / `com.gameframex.unity.cysharp.unitask`
- YooAsset(핫픽스 패치 프로세스를 활성화하는 경우)

## 작업 단계

### 1. 패키지 설치

`Packages/manifest.json`에 `com.gameframex.unity.startup` 의존성을 추가하고 GameFrameX scoped registry를 구성합니다:

```json
{
  "dependencies": {
    "com.gameframex.unity.startup": "1.1.0"
  },
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ]
}
```

`scopes`는 `com.gameframex` 접두사를 가진 패키지만 이 레지스트리에서 해석되도록 제어합니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L20-L39)

### 2. 설정 에셋 생성

Unity 메뉴: `Create > GameFrameX > Startup Options`를 선택하면 `StartupOptions` ScriptableObject 에셋이 생성됩니다. 자주 사용하는 항목:
- `GlobalInfoUrls`: 전역 정보 인터페이스의 기본/보조 URL 목록
- `GamePlayMode`: 리소스 실행 모드, 시작 전 Asset 컴포넌트에 동기화됨
- `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`: 핫픽스 진입점
- `PackageName` / `Channel` / `SubChannel`: HTTP 공용 파라미터
- `LauncherUIResName`: 시작 UI 리소스 경로(기본값 `UI/UILauncher`)
- `SkipRemoteStartupRequests`: 모든 원격 시작 요청 건너뛰기(WebGL 단독 실행 또는 백엔드가 없을 때 활성화)

### 3. UI 핸들러 구현

`IStartupUIHandler`를 구현하면, 프레임워크가 이 인터페이스를 통해 UI 상태를 콜백합니다:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class GameStartupUIHandler : IStartupUIHandler
{
    public UniTask StartAsync(string uiResName) { /* UI 로드 */ return UniTask.CompletedTask; }
    public void SetTipText(string text) { /* 팁 텍스트 업데이트 */ }
    public void SetProgress(float progress, string sizeInfo) { /* 진행 바 업데이트 */ }
    public void SetProgressUpdateFinish() { /* 완료 표시 */ }
    public void Dispose() { /* UI 닫기, 구독 해제 */ }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L54-L66)

### 4. 핫픽스 런처 구현(선택 사항)

핫픽스를 활성화해야 하는 경우 `IHotfixLauncher`를 구현합니다:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class HybridClrHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        // options.HotfixAssemblyName에 따라 핫픽스 어셈블리 로드
        // options.HotfixEntryTypeName의 options.HotfixEntryMethodName 호출
        return HotfixLaunchResult.Succeed();
    }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L67-L79)

### 5. 시작

아무 GameObject에 부트스트랩 스크립트를 하나 붙이고, 씬 로드 후 `StartupRunner.Run`을 호출합니다:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;
using UnityEngine;

public class GameBootstrap : MonoBehaviour
{
    [SerializeField] private StartupOptions _options;

    private async void Start()
    {
        var uiHandler = new GameStartupUIHandler();
        var hotfixLauncher = new HybridClrHotfixLauncher();

        var result = await StartupRunner.Run(_options, uiHandler, hotfixLauncher);

        if (result.Success)
        {
            // 시작 완료, 게임 준비됨
        }
        else
        {
            Debug.LogError($"启动失败 at {result.FailedProcedureName}: {result.ErrorMessage}");
        }
    }
}
```

`StartupResult`는 `Success` / `FailedProcedureName` / `FailedUrl` / `ErrorMessage` 필드를 포함합니다.

## 일반적인 변형

### 이벤트 구독으로 알림 디커플링

직접 `await`하는 대신, 완료/실패 이벤트를 구독합니다:

```csharp
GameApp.Event.Subscribe(StartupCompletedEventArgs.EventId, OnStartupCompleted);
GameApp.Event.Subscribe(StartupFailedEventArgs.EventId, OnStartupFailed);
```

`StartupCompletedEventArgs`와 `StartupFailedEventArgs`는 `GameApp.Event.Fire`를 통해 트리거되며, await 경로와 이벤트 경로 모두 알림을 받게 됩니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L107-L112)

### WebGL / 단독 배포

`StartupOptions.SkipRemoteStartupRequests`를 true로 체크하면 모든 원격 시작 요청(전역 정보 / App 버전 / 리소스 패키지 버전)을 건너뛰고 로컬 YooAsset 초기화만 실행합니다.

### URL 기본/보조 failover

`StartupOptions.GlobalInfoUrls`에 여러 URL을 구성하면 프레임워크가 순서대로 시도하며, 단일 URL에 대한 유한 재시도는 `MaxAttemptsPerUrl`로 제어됩니다.

## 자주 발생하는 오류

- **`Start`에 `async void`가 없음**: `StartupRunner.Run`은 `UniTask<StartupResult>`를 반환하므로 부트스트랩 메서드는 반드시 `async void Start()`여야 합니다. 그렇지 않으면 UniTask가 구동되지 않습니다.
- **메뉴에서 `Create > GameFrameX > Startup Options`를 찾을 수 없음**: 패키지가 올바르게 임포트되지 않은 것입니다. `Packages/manifest.json`의 `scopedRegistries`와 `dependencies`를 확인하세요.
- **핫픽스 진입점이 호출되지 않음**: `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` 중 하나라도 잘못 입력하면 시작 시 procedure FSM에서 `FailedProcedureName`이 보고됩니다. 로그 `result.ErrorMessage`를 확인하세요.
- **중복 시작**: 같은 씬에서 반복 호출하면 procedure FSM이 재구축됩니다. `StartupRunner.Run`은 일회성 진입점이므로 `OnEnable`에서 호출하지 마세요.

## 배경(선택 사항)

`StartupRunner.Run(options, uiHandler, hotfixLauncher)`는 내부적으로 procedure FSM을 구성하고, `options` / `uiHandler` / `hotfixLauncher` 세 인스턴스를 고정된 BlackBoard key(`__startup_options__` / `__startup_ui_handler__` / `__startup_hotfix_launcher__`)에 기록합니다. 모든 procedure 상태는 `IFsm<IProcedureManager>.GetData<VarObject>(key)`로 읽으며, 완료 결과는 `__startup_completion_source__`를 통해 `UniTask<StartupResult>`로 노출됩니다. 전체 블랙보드 상수는 `BlackBoardKeys.cs`를 참고하세요.
