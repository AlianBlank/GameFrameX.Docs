# 변수와 바인딩 가능 속성을 사용한 데이터 주도 개발

GameFrameX에서 `Variable<T>`는 참조 카운팅이 있는 강타입 데이터 컨테이너(서브시스템 간 약타입 값 전달용)이며, `BindableProperty<T>`는 값 변경 콜백이 있는 반응형 속성(UI와 로직의 데이터 바인딩용)입니다. 이 페이지에서는 두 가지를 데이터 주도 시나리오에서 사용하는 전형적인 방법을 보여줍니다.

## 사전 조건

- `GameFrameX.Runtime` 네임스페이스를 이미 가져왔습니다.
- GameFrameX의 참조 풀 / `IReference` 개념을 이해하고 있습니다(`Variable<T>`에만 필요).

## 작업 단계

### 1. `Variable<T>`로 모듈 간 데이터 전달

`Variable<T>`를 상속하여 구체적인 타입을 구현하면, 이벤트와 매개변수 테이블에서 약타입 `object`로 전달하면서 인스턴스를 받을 때에는 강타입으로 값을 가져올 수 있습니다.

```csharp
using GameFrameX.Runtime;

public class IntVariable : Variable<int>
{
    public IntVariable() { }
    public IntVariable(int value) { SetValue(value); }
}
```

사용 방식:

```csharp
var v = ReferencePool.Acquire<IntVariable>();
v.SetValue(42);
int actual = v.Value;                // 강타입 값 가져오기
object boxed = v.GetValue();         // 약타입 박싱(이벤트 매개변수용)
ReferencePool.Release(v);            // 참조 풀에 반환, Clear()가 콜백됨
```

설정 타입이 일치하지 않을 때, `SetValue(object)`는 `GameFrameworkException`을 발생시키며, 원본 메시지는 다음과 같습니다:

```
Cannot set value of type '{0}' to variable of type '{1}'.
```

> 참조 풀과 `IReference`의 전체 워크플로우는 《IReference와 참조 풀》을 참조하세요.

### 2. `BindableProperty<T>`로 값 변경 통지

`BindableProperty<T>`는 값을 할당할 때 새 값과 기존 값이 서로 다르면 자동으로 등록된 콜백을 호출하며, 주로 UI 새로 고침을 구동하는 데 사용됩니다.

```csharp
using System;
using GameFrameX.Runtime;

public sealed class PlayerStats
{
    public readonly BindableProperty<int> Hp = new BindableProperty<int>(100);
    public readonly BindableProperty<string> Name = new BindableProperty<string>("Hero");
}
```

구독과 구독 해제:

```csharp
var stats = new PlayerStats();

Action<int> onHp = newHp => Debug.Log($"HP -> {newHp}");
stats.Hp.Add(onHp);                       // 콜백 등록
stats.Hp.Value = 80;                       // 콜백 트리거, 로그 출력 "HP -> 80"
stats.Hp.Value = 80;                       // 같은 값은 트리거되지 않음
stats.Hp.Remove(onHp);                     // 콜백 제거
stats.Hp.Clear();                          // 모든 콜백 비우기
```

### 3. 즉시 현재 값이 필요할 때 `RegisterWithInitValue` 사용

구독 시 콜백이 즉시 한 번 호출되기를 원한다면(현재 값 전달), `RegisterWithInitValue`를 사용합니다:

```csharp
stats.Hp.RegisterWithInitValue(newHp => UpdateHpBar(newHp));
```

## 일반적인 변형

| 시나리오 | 선택 | 핵심 API |
|------|------|----------|
| 이벤트 / 작업의 약타입 매개변수 | `Variable<T>` 서브클래스 | `SetValue(object)` / `GetValue()` |
| UI 바인딩 / 다중 옵저버 동기화 | `BindableProperty<T>` | `Add` / `Remove` / `RegisterWithInitValue` |
| 중복 트리거를 피하고 싶을 때 | `BindableProperty<T>` | 내부에서 이미 `Equals` 비교 사용, 같은 값은 트리거되지 않음 |
| 변수를 풀링하여 재사용하고 싶을 때 | `Variable<T>` | `ReferencePool.Acquire / Release` |

## 일반적인 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| `Cannot set value of type 'X' to variable of type 'Y'.` | `Variable<T>`의 `SetValue(object)`에 `T` 타입이 아닌 값을 전달 | 호출 지점에서 타입 변환을 수행하거나, 일치하는 서브클래스로 변경 |
| 값을 할당했는데 콜백이 실행되지 않음 | 새 값과 기존 값이 같아서 `BindableProperty` 내부에서 `Equals` 비교 후 건너뜀 | 이것은 예상된 동작입니다. 강제로 통지해야 한다면 `Equals`가 false를 반환하는 새 인스턴스를 사용 |
| `Add(null)` 예외 발생 | `BindableProperty.Add`에서 `GameFrameworkGuard.NotNull`로 검증함 | 구체적인 `Action<T>` 메서드 또는 람다를 전달 |
| 참조 풀에 반환한 후에도 콜백이 계속 트리거됨 | `Variable<T>`가 이미 풀에서回收되었지만 외부에서 여전히 참조를 보유 | 보유자 자체의 `Clear()` 또는 해제 시 참조를 동시에 비움 |

## 배경(선택 사항)

- `Variable`은 `IReference`를 구현하며, `ReferencePool`을 통해 획득 / 해제할 수 있습니다. `Clear()`는 값을 `default(T)`로 재설정하므로 이벤트, 작업 매개변수 같은 "쓰고 버리는" 시나리오에서 GC를 줄이는 데 적합합니다.
- `BindableProperty<T>`는 내부적으로 `Equals`로 새 값과 기존 값을 비교하여 실제로 변경된 경우에만 콜백합니다. `Add`는 체이닝하여 자기 자신을 반환하는 것을 지원하며, `Remove`은 올바르게 바인딩을 해제하려면 반드시 동일한 대리자 참조를 전달해야 합니다.
