# JSON 回應解析方法

在 GameFrameX.Web 中，JSON 回應解析的核心在於對回應字串呼叫擴充方法 `ToHttpJsonResultData<T>()`:此方法會將伺服器統一的結構(`code`/`message`/`data`)反序列化為 `HttpJsonResultData<T>`,並根據 `code` 自動設定 `IsSuccess`。框架內部使用 LitJSON(`GameFrameX.LitJSON.Runtime.JsonMapper`)來執行反序列化。

## 前置條件

- 專案必須已包含 `GameFrameX.Web` 與 `GameFrameX.LitJSON` 執行階段模組。
- 伺服器回傳統一的 JSON 結構，欄位為小寫的 `code`、`message`、`data`:

```json
{
  "code": 0,
  "message": "ok",
  "data": "{\"id\":1,\"name\":\"Player\"}"
}
```

其中 `code == 0` 代表成功，而 `data` 是巢狀的 JSON 字串(會再被反序列化為 `T`)。

## 操作步驟

1. 定義業務資料模型 `T`:必須是 `class`,且須包含無參數建構函式(因為擴充方法簽章的條件約束為 `where T : class, new()`)。當欄位名稱與 JSON 不一致時，以 `[JsonProperty("...")]` 標記。

```csharp
using GameFrameX.LitJSON.Runtime;

public sealed class PlayerInfo
{
    [JsonProperty("id")]
    public int Id { get; set; }

    [JsonProperty("name")]
    public string Name { get; set; }
}
```

2. 收到回應字串後，呼叫擴充方法以取得結果物件：

```csharp
using GameFrameX.Web.Runtime;

HttpJsonResultData<PlayerInfo> result = responseText.ToHttpJsonResultData<PlayerInfo>();
```

3. 根據 `IsSuccess` / `Code` 處理結果：

```csharp
if (result.IsSuccess)
{
    PlayerInfo player = result.Data;
    Debug.Log($"玩家:{player.Id} {player.Name}");
}
else
{
    // Code 不為 0 表示伺服器錯誤碼;若 Code 為 0 且 IsSuccess 為 false,則表示反序列化過程中發生了例外
    Log.Error($"请求失败,Code={result.Code}");
}
```

`ToHttpJsonResultData<T>` 的完整邏輯(先解析外殼，再解析 `data`)如下：

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // 將 JSON 字串反序列化為 HttpJsonResult 物件
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // 檢查回應代碼是否表示成功
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // 回傳預設的失敗結果
        }

        resultData.IsSuccess = true; // 設定成功旗標
        // 反序列化資料部分;若資料為空,則回傳型別 T 的預設實例
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // 攔截並輸出例外資訊
        Log.Error(e);
    }

    return resultData; // 回傳結果資料
}
```

來源： [HttpJsonResultHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultHelper.cs#L20-L48)

## 常見變體

- **只需要外殼結構、不需要強型別 Data 的情況**：直接使用 `JsonMapper.ToObject<HttpJsonResult>(json)` 來取得 `Code` / `Message` / `Data` 三個欄位(此時 `Data` 為原始字串)。

```csharp
var shell = JsonMapper.ToObject<HttpJsonResult>(responseText);
Debug.Log($"code={shell.Code}, message={shell.Message}");
```

來源： [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L9-L33)

- **在請求階段取得字串回應**：`WebManager` 內部透過 `WebJsonData`(私有的請求描述類別)串接 `TaskCompletionSource<WebStringResult>` / `TaskCompletionSource<WebBufferResult>`,分別對應字串結果與位元組陣列結果。字串結果可直接原樣傳遞給 `ToHttpJsonResultData<T>`。傳送 Web 請求的方式請參考《如何傳送 HTTP 請求》。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `IsSuccess == false` 且 `Code != 0` | 伺服器回傳了非 0 的回應代碼，導致 `Data` 保持為 `null` | 根據 `Code` 進行業務錯誤處理;`Code` 值的意義依伺服器端約定而定 |
| `IsSuccess == false` 且 `Code == 0` | 反序列化過程中發生例外，由 `catch (Exception e)` 處理並以 `Log.Error(e)` 輸出 | 檢查主控台錯誤日誌；檢查 JSON 格式與欄位名稱對應 |
| 發生編譯錯誤：缺少 `new()` 條件約束 | `T` 是結構，或沒有無參數建構函式 | 將模型改為具有無參數建構函式的 `class` |
| `Data` 的欄位全為預設值 | 欄位名稱與 JSON 鍵不一致，且未標記 `[JsonProperty]` | 以 `[JsonProperty("原始鍵名")]` 進行明確對應 |
| `Data` 為預設實例，但 `IsSuccess == true` | 伺服器回傳的 `data` 為空字串，因此此時回傳 `new T()` | 伺服器應在成功時包含有效的 `data`,或由用戶端視需要檢查空值 |
| 沒有任何欄位被解析 | 外殼欄位名稱不是小寫的 `code`/`message`/`data` | 應與伺服器約定統一的外殼結構，參見 [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L14-L27) |

## 驗證

- 建立字串 `{"code":0,"message":"ok","data":"{\"id\":1,\"name\":\"a\"}"}` 並呼叫 `ToHttpJsonResultData<PlayerInfo>()`,應得到 `IsSuccess == true` 且 `Data.Id == 1`。
- 將 `code` 改為非 0 的值(例如 `1001`),應得到 `IsSuccess == false`、`Code == 1001`、`Data == null`。
- 將字串改為無效的 JSON,應得到 `IsSuccess == false`、`Code == 0`,且日誌中應顯示例外輸出。

## 背景

`HttpJsonResultData<T>` 只是「統一外殼 + 業務資料」的一層薄包裝:`IsSuccess`(預設值 `false`)、`Code`(int,0 為成功)、`Data`(`T`,失敗時為 `null`)。擴充方法內部會先反序列化為 `HttpJsonResult` 以檢查 `code`,成功後再將 `data` 反序列化一次。整個過程中例外都會被攔截而不會向外擲回，因此呼叫端只需關注 `IsSuccess` 與 `Code` 這兩個旗標。
