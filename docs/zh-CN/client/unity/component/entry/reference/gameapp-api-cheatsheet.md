# GameApp 门面层全量 API 速查

`GameApp` 是 GameFrameX 在 Unity 入口包中暴露的静态门面,把所有子系统组件(例如 `Base`、`Event`、`Asset` 等)统一收敛到一个全局静态类下,业务侧无需直接引用 `GameEntry.GetComponent<...>()` 即可拿到对应组件。

源码采用 C# `partial class` 拆分:每个子模块单独一个 `GameApp.<Module>.cs` 文件,统一对外暴露同名静态属性,因此查表时按"模块名 = 属性名 = 文件名"理解即可。

## 通用签名

每个分片都遵循同一模板:静态属性 + 懒加载 + `GameEntry.GetComponent<T>()` 拉取实例。

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }
    private static BaseComponent _base;
}
```

Source: [GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L36-L52)

带编译开关的模块示例(`Event`、`Asset` 等):


## 调用示例

```csharp
// 触发一个全局事件

GameApp.Asset.LoadAssetAsync<GameObject>("Assets/Prefabs/UI/LoginPanel.prefab", callback);
```

## 注意事项

- `GameApp` 是 `public static partial class`,各分片文件必须同处于全局命名空间(无 `namespace`),否则 C# 不会将它们合并为同一类型。
- 带 `#if` 宏的模块(如 `Event`、`Asset`)若在工程里未启用对应编译开关,则对应属性不存在,直接访问会编译报错——属于按需裁剪,不是 Bug。
- 首次访问某个属性时才会从 `GameEntry` 拉取组件,因此业务侧无须关心注册顺序,但要保证 `GameEntry` 已被初始化(由框架启动流程负责)。
