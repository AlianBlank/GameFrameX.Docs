# How to Use RSA Encryption/Decryption and Signing

`RsaHelper` wraps RSA asymmetric encryption into static methods, supporting encryption/decryption and signing/verification with Base64 keys, as well as key pair generation and instance-based encryption/decryption with XML keys. This page walks you through the complete workflow from generating keys to encryption/decryption and signature verification.

## Prerequisites

- The project references the `GameFrameX.Foundation.Encryption` assembly and includes `using GameFrameX.Foundation.Encryption;`.
- The .NET runtime supports `System.Security.Cryptography.RSA` (.NET 6+ is sufficient).
- Prepare a pair of RSA keys in Base64 format (PKCS#8/PKCS#1) or keys in XML format; if you don't have any, generate them on the fly with `RsaHelper.Make()`.

## Steps

### 1. Generate an RSA Key Pair (XML Format)

```csharp
using GameFrameX.Foundation.Encryption;

var keyPair = RsaHelper.Make(); // Returns a dictionary containing "privateKey" and "publicKey"
string privateKeyXml = keyPair["privateKey"];
string publicKeyXml  = keyPair["publicKey"];
```

The two keys in the dictionary are the private key in XML format (containing `Modulus`, `Exponent`, private parameters, etc.) and the public key, which can be saved directly or converted to Base64.

### 2. Encrypt with the Public Key, Decrypt with the Private Key (XML Keys)

`Encrypt(string, string)` and `Decrypt(string, string)` accept XML-format keys and return Base64 strings.

```csharp
using GameFrameX.Foundation.Encryption;
using System.Text;

string plain = "Hello, RSA!";

// Encrypt: public key XML + plaintext → Base64 ciphertext
string cipher = RsaHelper.Encrypt(publicKeyXml, plain);

// Decrypt: private key XML + Base64 ciphertext → plaintext
string back = RsaHelper.Decrypt(privateKeyXml, cipher);
```

If you want to work with byte arrays directly, use `RsaHelper.Encrypt(string publicKey, byte[] content)` on the encryption side and `RsaHelper.Decrypt(string privateKey, byte[] content)` on the decryption side.

### 3. Encrypt with the Public Key, Decrypt with the Private Key (Base64 Keys)

`EncryptBase64` and `DecryptBase64` accept Base64-encoded keys and automatically detect PKCS#8 / PKCS#1 internally:

```csharp
string cipher64 = RsaHelper.EncryptBase64(publicKeyBase64, plain);
string plain64 = RsaHelper.DecryptBase64(privateKeyBase64, cipher64);
```

Encryption uses **OAEP-SHA256** padding; when the plaintext exceeds the single-block limit, it is automatically encrypted in blocks, making it suitable for data of any length.

### 4. Sign with the Private Key, Verify with the Public Key

Signing and verification always use SHA256 + PKCS#1 padding, and keys support both PKCS#8 and PKCS#1:

```csharp
string signature = RsaHelper.Sign(privateKeyBase64, plain);
bool ok = RsaHelper.Verify(publicKeyBase64, plain, signature);
```

`Verify` returns `true` if the signature is valid; tampering with the public key, data, or signature will result in `false`.

### 5. Reuse the Same Key Pair with an Instance

Suitable for scenarios requiring repeated encryption/decryption (the instance holds an `RSA` resource at construction time; remember to `Dispose` it):

```csharp
using (var helper = new RsaHelper(privateKeyXml))
{
    string cipher = helper.Encrypt(plain);             // Instance public key encryption (the XML private key also contains public key parameters)
    string back   = helper.Decrypt(cipher);            // Instance private key decryption
}
```

Or pass in a `System.Security.Cryptography.RSA` instance directly: `new RsaHelper(rsaInstance)`.

## Common Variants

| Scenario | Recommended API | Key Format |
|------|---------|----------|
| Interoperability with Java/Go etc., where the key is the Base64 segment inside a PEM | `EncryptBase64` / `DecryptBase64` / `Sign` / `Verify` | PKCS#8 or PKCS#1 Base64 |
| Internal .NET ecosystem, storing keys long-term in configuration files | `Make()` + `Encrypt` / `Decrypt` | XML |
| Chunked encryption of large files | `EncryptBase64` / `DecryptBase64` | Base64 (automatic chunking) |
| Multiple calls with the same key, avoiding repeated imports | Instantiate `new RsaHelper(key)` | XML or `RSA` object |

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| `CryptographicException` "Bad Data" | The Base64 string is not a valid PKCS#8/PKCS#1 key | Make sure the PEM has `-----BEGIN/END-----` and line breaks removed before Base64 encoding |
| `Encrypt` throws "Key not valid for use in specified state" | The XML string is a private key rather than a public key | Only the `publicKey` returned by `Make()` can be used for encryption |
| `Verify` always returns `false` | The signed data was modified, the key pair doesn't match, or a different hash was used for signing | Ensure the original UTF-8 text used for signing matches verification; both sides use SHA256 |
| Garbled encryption/decryption results | Inconsistent padding between the two sides | `EncryptBase64`/`DecryptBase64` must be used in pairs; both use OAEP-SHA256 |

## Background (Optional)

- Encryption padding: Since the C-05 fix, encryption/decryption uniformly uses `RSAEncryptionPadding.OaepSHA256`, avoiding the Bleichenbacher attack risk of PKCS#1 v1.5.
- Signature padding: Signing/verification is fixed to `RSASignaturePadding.Pkcs1` + `HashAlgorithmName.SHA256`, consistent with the defaults of most external systems.
- Resource management: Instance methods hold unmanaged RSA resources; after using `new RsaHelper(...)`, you must call `Dispose()` or use `using`.
