# JSON 또는 BIN 출력 형식을 선택하는 방법

Luban은 **JSON**과 **BIN** 두 가지 데이터 출력 형식을 동시에 지원하며, 각 형식에 맞는 서로 다른 코드 템플릿을 함께 제공합니다. 이 페이지는 클라이언트/서버, 런타임 성능, 가독성 등의 요구 사항에 따라 둘 중에서 빠르게 선택할 수 있도록 돕고, 해당하는 생성 스크립트와 설정 항목으로 전환하는 방법을 안내합니다.

## 한 줄 결론

- 서버(C# / .NET): 기본값은 `JSON`, 극한의 로딩 속도를 추구할 때 `BIN`으로 전환합니다.
- 클라이언트(Unity): 개발/디버깅에는 `JSON`, 릴리스 버전에는 `BIN`을 강력히 권장합니다.
- 출력 형식과 코드 템플릿은 일대일로 대응되므로, 형식을 변경할 때 `--dataTarget`과 `--codeTarget`을 함께 변경해야 합니다.

## 두 형식 비교표

| 항목 | JSON | BIN |
|------|------|-----|
| 데이터 파일 가독성 | 순수 텍스트, 편집기/git으로 직접 확인 가능 | 바이너리, 도구 또는 런타임을 통해서만 읽을 수 있음 |
| 파일 크기 | 상대적으로 큼(따옴표, 들여쓰기, 필드명 포함) | 컴팩트함(필드를 컴팩트하게 직렬화, 필드명 없음) |
| 로딩/파싱 속도 | 상대적으로 느림(런타임에서 문자열 파싱) | 빠름(`MemoryStream`으로 직접 읽기) |
| Git diff/병합 | 친화적, 충돌 처리 용이 | 비친화적, 충돌 시 사실상 파일 전체 교체만 가능 |
| 함께 사용되는 코드 템플릿 | `cs-dotnet-json`(서버), `cs-simple-json`(클라이언트) | `cs-bin`(서버와 클라이언트 공용) |
| 검증 엄격도 | 기본값 | `--validationFailAsError true` 활성화 |
| 적합한 시나리오 | 개발 기간, 서버, 디버깅, 핫업데이트 그레이스케일 배포 | 클라이언트 정식 버전, 시작/메모리에 민감한 시나리오 |

소스 설정은 [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)의 `commands` 섹션을 참고하세요.

## 작업 단계: 출력 형식 선택 및 전환

### 1. 현재 활성화된 형식 확인

`luban.conf`를 열고, `commands` 배열에서 생성하려는 대상(server 또는 client)을 찾은 후 `active` 필드를 확인하세요:

- `active: true` → 현재 적용 중인 명령입니다.
- `active: false` → 백업 명령으로, 수동으로 활성화해야 합니다.

저장소에서 기본적으로 활성화되어 있는 것은 JSON입니다:

```json
{
  "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

출처: [luban.conf#L66-L94](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

### 2. 생성 스크립트를 통한 빠른 전환

저장소 루트 디렉터리에 이미 네 쌍의 생성 스크립트가 제공되므로, `luban.conf`를 수정할 필요 없이 바로 실행하면 됩니다:

| 대상 | JSON | BIN |
|------|------|-----|
| Server | `gen-server-json.bat` / `gen-server-json.sh` | `gen-server-bin.bat` / `gen-server-bin.sh` |
| Client | `gen-client-json.bat` / `gen-client-json.sh` | `gen-client-bin.bat` / `gen-client-bin.sh` |

예를 들어 **서버 BIN**으로 전환하려면:

```bat
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

출처: [gen-server-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.bat#L1)

**클라이언트 BIN**으로 전환하려면:

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

출처: [gen-client-bin.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.bat#L1)

### 3. luban.conf를 수정하여 대상 명령을 active로 설정

IDE/플러그인 수준에서 기본적으로 BIN이 생성되기를 원하는 경우(예: 정식 릴리스 파이프라인), 해당 `BIN` 명령의 `active`를 `true`로 변경하고, `JSON` 명령의 `active`를 `false`로 변경하세요:

```json
{
  "command": "--target server --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

출처: [luban.conf#L78-L87](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L78-L87)

참고: `--validationFailAsError true`를 설정하면 BIN 형식은 검증 실패 시 경고 대신 바로 오류가 발생하므로, 프로덕션 환경에서는 유지할 것을 권장합니다.

## 일반적인 변형

### 변형 A: 서버 JSON(기본값)

로컬 개발과 서버 핫업데이트에 적합합니다. 생성 결과물은 직접 `git diff`가 가능하고 텍스트 검색도 할 수 있습니다.

```bat
dotnet.exe ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
```

출처: [gen-server-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-json.bat#L1)

### 변형 B: 클라이언트 JSON(기본값)

Unity 클라이언트 디버깅 단계에 적합하며, `*.json`을 `Assets/Bundles/Config`로 내보내고 코드 템플릿은 `cs-simple-json`입니다.

```bat
dotnet.exe ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=../Unity/Assets//Bundles/Config  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate --xargs tableImporter.name=gameframex -x l10n.provider=gameframex -x l10n.textFile.keyFieldName=key  -x l10n.textFile.path=./Excels/Local/ --conf ./Luban.conf
```

출처: [gen-client-json.bat#L1](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1)

### 변형 C: 클라이언트 BIN(릴리스 권장)

코드 템플릿은 `cs-bin`으로 통일되고, 데이터는 컴팩트한 바이너리이며, Unity 환경에서 로딩 시 메모리와 IO를 더 절약할 수 있습니다.

```sh
dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin --validationFailAsError true --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate
```

출처: [luban.conf#L83-L87](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L83-L87)

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 실행 시 `dataTarget/codeTarget 不匹配` 오류 발생 | `--dataTarget`만 변경하고 `--codeTarget`을 변경하지 않음 | 두 값은 반드시 짝을 이뤄야 함(json↔cs-dotnet-json/cs-simple-json, bin↔cs-bin/cs-dotnet-bin/cs-dotnet-bin) |
| BIN 파일을 직접 열어 내용을 볼 수 없음 | bin을 선택했지만 json처럼 확인할 수 있기를 기대함 | 함께 제공되는 `cs-bin` 템플릿으로 읽어야 하며, 텍스트 파싱을 시도하지 마세요 |
| luban.conf를 수정했는데 적용되지 않음 | 여전히 이전 스크립트를 실행 중 | `gen-*-bin.*` 스크립트를 직접 실행하거나, `commands`에서 대상 명령의 `active`를 `true`로 변경 |
| 클라이언트 릴리스 후 시작 속도가 느려짐 | 클라이언트가 여전히 JSON을 사용 중 | `gen-client-bin.*`으로 전환하고, BIN 명령의 `active`를 `true`로 설정 |
| 서버에서 설정 핫업데이트 후 오류 원인 파악이 어려움 | 서버가 BIN을 사용하지만 검증이 비활성화됨 | BIN 명령에 `--validationFailAsError true` 추가 |

## 배경(선택 사항)

JSON과 BIN의 차이는 본질적으로 **가독성 / 크기 / 파싱 속도**의 삼각 트레이드오프입니다. Luban은 데이터 직렬화(`--dataTarget`)와 코드 생성 템플릿(`--codeTarget`)을 분리하여, 동일한 데이터를 서로 다른 런타임 표현으로 담을 수 있게 합니다. 개발 기간에는 JSON을 유지하고 정식 단계에는 BIN으로 전환하는 것이 GameFrameX가 권장하는 점진적 방식입니다.
