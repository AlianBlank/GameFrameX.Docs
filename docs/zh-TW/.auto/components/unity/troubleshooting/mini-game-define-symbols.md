# 小遊戲平台巨集定義錯誤怎麼辦

當你呼叫 `ApplicationHelper.IsWebGLWeChatMiniGame`（或其它 `IsWebGLXxxMiniGame` 系列屬性）時，無論當前是否真的在某個小遊戲平台下執行，都回傳 `false`——這通常意味著對應的巨集定義沒有正確生效。本文給出常見的報錯症狀、根因與修復步驟。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `IsWebGLWeChatMiniGame` 等屬性在真機裡始終為 `false` | 沒有在 **Project Settings → Player → Other Settings → Scripting Define Symbols** 加入對應的 `ENABLE_*_MINI_GAME` 巨集 | 按平台巨集名稱表把對應巨集加入 Scripting Define Symbols |
| 加了巨集，但屬性仍為 `false`（WebGL 平台） | 沒有切到 WebGL 平台；巨集僅在 `UNITY_WEBGL` 下生效 | File → Build Settings → Switch Platform → WebGL |
| 編譯報錯：`The type or namespace name 'EnableWebglMiniGame' could not be found` | 直接寫成了 `#define ENABLE_WEBGL_MINI_GAME`，但巨集應通過 Scripting Define Symbols 設定 | 改用 Project Settings 設定，不要在原始碼裡 `#define` |
| 編譯警告或程式碼被錯誤地剝離（IL2CPP / AOT） | 用 `#if` 直接判斷巨集卻忘了同步標記 `[UnityEngine.Scripting.Preserve]` | 確認呼叫方已被保留，參考 `ApplicationHelper.MiniGame.cs` 的屬性寫法 |
| 切換平台後巨集未生效 | Unity 需要觸發一次腳本重編譯，IDE 快取未刷新 | 關閉並重開 IDE / `Assets → Reimport All` |

## 修復步驟

### 1. 開啟 Scripting Define Symbols 設定

`Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`。選擇目標平台後，在文字框裡加入需要的巨集；多個巨集用英文分號分隔，例如：

```text
ENABLE_WEBGL_MINI_GAME;ENABLE_WECHAT_MINI_GAME
```

來源：見 [ApplicationHelper.MiniGame.cs#L17-L23](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L17-L23) 中使用的巨集 `ENABLE_WEBGL_MINI_GAME`。

### 2. 確認平台已切到 WebGL

所有 `IsWebGL*MiniGame` 屬性的判斷都是 `#if UNITY_WEBGL && ENABLE_<PLATFORM>_MINI_GAME`，若當前 Active Build Target 不是 WebGL，前處理器分支會直接回傳 `false`。

開啟 `File → Build Settings`，在左側平台列表中選擇 **WebGL**，然後點擊 **Switch Platform**。完成後 Unity 會觸發一次全量重編譯。

### 3. 按平台選擇正確的巨集名稱

框架支援的所有小遊戲巨集名稱如下（均需搭配 `UNITY_WEBGL`）：

| 平台 | 巨集名稱 | 對應屬性 |
|------|--------|----------|
| WebGL 小遊戲（通用） | `ENABLE_WEBGL_MINI_GAME` | `IsWebGLMiniGame` |
| 微信小遊戲 | `ENABLE_WECHAT_MINI_GAME` | `IsWebGLWeChatMiniGame` |
| 支付寶小遊戲 | `ENABLE_ALIPAY_MINI_GAME` | `IsWebGLAlipayMiniGame` |
| 抖音小遊戲 | `ENABLE_DOUYIN_MINI_GAME` | `IsWebGLDouYinMiniGame` |
| 快手小遊戲 | `ENABLE_KUAISHOU_MINI_GAME` | `IsWebGLKuaiShouMiniGame` |
| 百度小遊戲 | `ENABLE_BAIDU_MINI_GAME` | `IsWebGLBaiduMiniGame` |
| 京東小遊戲 | `ENABLE_JINGDONG_MINI_GAME` | `IsWebGLJingDongMiniGame` |
| 淘寶小程式 | `ENABLE_TAOBAO_MINI_GAME` | `IsWebGLTaobaoMiniGame` |
| 美團小遊戲 | `ENABLE_MEITUAN_MINI_GAME` | `IsWebGLMeituanMiniGame` |
| Bilibili 小遊戲 | `ENABLE_BILIBILI_MINI_GAME` | `IsWebGLBilibiliMiniGame` |
| Discord 小遊戲 | `ENABLE_DISCORD_MINI_GAME` | `IsWebGLDiscordMiniGame` |
| YouTube 小遊戲 | `ENABLE_YOUTUBE_MINI_GAME` | `IsWebGLYouTubeMiniGame` |
| Facebook 小遊戲 | `ENABLE_FACEBOOK_MINI_GAME` | `IsWebGLFacebookMiniGame` |
| Google Play 小遊戲 | `ENABLE_GOOGLE_PLAY_MINI_GAME` | `IsWebGLGooglePlayMiniGame` |

來源：[ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs) 中各屬性的 `#if UNITY_WEBGL && ENABLE_*_MINI_GAME` 定義。

### 4. 在程式碼中呼叫對應屬性

不要自己再用 `#if` 巢狀判斷巨集——這樣容易遺漏。直接呼叫 `ApplicationHelper` 上的屬性即可：

```csharp
using GameFrameX.Runtime;

if (ApplicationHelper.IsWebGLWeChatMiniGame)
{
    // 微信小遊戲專用邏輯
}
else if (ApplicationHelper.IsWebGLDouYinMiniGame)
{
    // 抖音小遊戲專用邏輯
}
```

原始碼範例（微信小遊戲分支）：

```csharp
[UnityEngine.Scripting.Preserve]
public static bool IsWebGLWeChatMiniGame
{
    get
    {
#if UNITY_WEBGL && ENABLE_WECHAT_MINI_GAME
        return true;
#else
        return false;
#endif
    }
}
```

Source: [ApplicationHelper.MiniGame.cs#L33-L43](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L33-L43)

## 驗證

1. 在 `Awake()` 或除錯按鈕裡加一行 `Debug.Log($"WeChat={ApplicationHelper.IsWebGLWeChatMiniGame}")`，執行後查看 Console。
2. 切換 WebGL 與非 WebGL 平台分別打 Log，預期非 WebGL 下全部為 `false`；WebGL 下應僅當前設定巨集的平台為 `true`。
3. 仍為 `false` 時回到診斷表逐項核對：平台是否 WebGL、巨集名稱是否拼字正確、是否觸發重編譯。

## 背景

框架為每個小遊戲平台暴露一個靜態屬性（統一位於 `GameFrameX.Runtime.ApplicationHelper`），透過 `UNITY_WEBGL` 與各平台巨集的組合在編譯期決定回傳 `true`/`false`，從而在 IL2CPP / AOT 裁剪時也能正確生效。屬性的真實原始檔可參考 [ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs)。
