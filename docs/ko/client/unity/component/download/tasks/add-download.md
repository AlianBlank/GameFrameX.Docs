# 다운로드 추가 및 실행

`DownloadComponent.AddDownload(...)`를 통해 원격 파일을 다운로드 큐에 추가하면, 프레임워크가 자동으로 다운로드 에이전트를 스케줄링하여 다운로드를 완료하고, 이벤트 콜백을 통해 진행률, 성공, 실패 결과를 반환합니다.

## 사전 조건

- 씬에 `DownloadComponent`가 마운트되어 있어야 합니다(컴포넌트 메뉴 `GameFrameX/Download`), 그리고 `GameFramework`와 함께 시작이 완료되어야 합니다.
- 씬에 `EventComponent`가 마운트되어 있어야 합니다. 그렇지 않으면 다운로드 성공 / 실패 이벤트를 디스패치할 수 없습니다.
- `DownloadComponent`의 `Download Agent Helper Count`가 0보다 커야 합니다. 기본값은 3입니다.
- `downloadPath`가 위치한 디렉터리에 쓰기 권한이 있어야 합니다.

## 작업 단계

1. `DownloadComponent` 인스턴스를 가져옵니다:

```csharp
var download = GameEntry.GetComponent<DownloadComponent>();
```

출처: [DownloadComponent.cs#L46-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L60)

2. `AddDownload`를 호출하여 다운로드 작업을 큐에 추가하면, 작업의 일련 번호 `serialId`가 반환됩니다:

```csharp
int serialId = download.AddDownload(
    downloadPath: Application.persistentDataPath + "/files/bundle.zip",
    downloadUri:   "https://example.com/bundle.zip",
    tag:           "Bundle",
    priority:      0,
    userData:      null);
```

출처: [DownloadComponent.cs#L379-L385](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L379-L385)

3. `EventComponent`의 다운로드 이벤트를 구독하여 콜백을 받습니다. 이벤트 ID 정의는 `Constant.cs`를 참조하세요:

```csharp
var eventComp = GameEntry.GetComponent<EventComponent>();
eventComp.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComp.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComp.Subscribe(DownloadUpdateEventArgs.EventId,   OnDownloadUpdate);
```

콜백에서 `e.SerialId`로 추가 시 반환된 `serialId`와 매칭할 수 있습니다.

4. 다운로드 결과를 처리합니다. `DownloadSuccessEventArgs` / `DownloadFailureEventArgs` 모두 `SerialId`를 제공하므로, 이를 통해 어떤 작업이 종료되었는지 판단할 수 있습니다.

## 일반적인 변형

- **`Task<bool>`만 필요한 경우**: `download.Download(downloadPath, downloadUri)`를 사용하세요. 내부적으로 `AddDownload` + `TaskCompletionSource`를 캡슐화하며, 완료 시 `Task`가 `SetResult(true)`를, 실패 / 취소 시 `SetResult(false)` / `TrySetCanceled()`를 호출합니다.
  출처: [DownloadComponent.cs#L306-L317](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L317)

- **tag / priority를 전달하지 않는 경우**: 두 개의 매개변수를 가진 `AddDownload(string downloadPath, string downloadUri)`를 직접 사용하면, 기본값으로 `tag = null`, `priority = 0`이 적용됩니다.
  출처: [DownloadComponent.cs#L271-L274](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L274)

- **tag로 일괄 관리**: `GetDownloadInfos(tag)`로 조회하고, `RemoveDownloads(tag)`로 일괄 취소합니다.

## 일반적인 오류

- **`Log.Fatal("Download manager is invalid.")`**: 씬에 `DownloadComponent`가 마운트되지 않았거나 제대로 Awake되지 않은 경우입니다. GameFramework 시작 순서를 확인하세요.
- **`Log.Fatal("Event component is invalid.")`**: `EventComponent`가 없어서 다운로드 이벤트를 디스패치할 수 없는 경우입니다.
- **다운로드 디렉터리에 쓰기 권한이 없음**: `Application.persistentDataPath`와 같이 Unity에서 제공하는 쓰기 가능한 경로를 사용하고, `StreamingAssets`나 `jar:file://` 등 읽기 전용 위치에는 쓰지 마세요.
- **에이전트가 모두 사용 중일 때 새 작업이 계속 대기**: 작업은 빈 에이전트가 생길 때까지 대기 큐에 들어갑니다. `FreeAgentCount` / `WaitingTaskCount`로 모니터링할 수 있습니다.
  출처: [DownloadComponent.cs#L82-L105](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L82-L105)

## 배경

`DownloadComponent`는 `Start` 단계에서 `Download Agent Helper Count`에 따라 해당 수량만큼의 `UnityWebRequestDownloadAgentHelper`를 생성합니다(Inspector에서 커스텀 구현으로 전환 가능). 모든 동시 다운로드는 이 Helper들에서 순환 처리됩니다. `AddDownload`는 큐에 추가만 하며, 실제 HTTP 요청 발생 및 디스크 쓰기는 `DownloadManager`가 다음 프레임에 스케줄링합니다.
