# 빠른 시작: 처음부터 GameFrameX 서버 시작하기

이 페이지에서는 최소한의 단계로 GameFrameX Server를 실행하는 방법을 안내합니다: .NET 10과 MongoDB를 준비하고, 시작 방식(Docker / 명령줄 / Rider / Visual Studio) 중 하나를 선택한 후, 헬스 체크와 테스트 인터페이스가 정상적으로 응답하면 시작 성공으로 간주합니다.

## 사전 조건

| 항목 | 버전 요구 사항 |
| :--- | :--- |
| [.NET SDK](https://dotnet.microsoft.com/download) | 10.0+ |
| [MongoDB](https://www.mongodb.com/try/download/community) | 4.x+ |
| IDE(선택) | Visual Studio 2022 / JetBrains Rider / VS Code |
| Docker(선택) | 원클릭 시작 또는 로컬 MongoDB 실행용 |

소스 코드 루트 디렉터리는 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L1-L150)를 참조하세요.

## 작업 단계

### 방식 1: Docker 원클릭 시작

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
docker compose up -d --build
```

로컬에 .NET 10 SDK를 설치하고 싶지 않은 사용자에게 적합합니다; Compose가 MongoDB와 서버 컨테이너를 동시에 실행합니다.

### 방식 2: 명령줄 로컬 시작

1. MongoDB를 단독으로 실행합니다:

```bash
docker compose up -d mongodb
```

2. 빌드 후 출력 디렉터리에서 Launcher를 실행합니다:

```bash
git clone https://github.com/GameFrameX/Server_main.git
cd Server_main
dotnet restore
dotnet build Server.sln
cd bin/app_debug
dotnet GameFrameX.Launcher.dll
```

`GameFrameX.Launcher.dll`은 프레임워크의 진입점 어셈블리이며, 해당 프로젝트 파일은 [GameFrameX.Launcher.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/GameFrameX.Launcher.csproj#L1-L41)를 참조하세요. `Debug` 구성의 `OutputPath`는 `bin\app_debug`, `Release`는 `bin\app`입니다.

### 방식 3: JetBrains Rider 디버깅

1. `Server.slnx`를 엽니다; Rider 버전이 `.slnx`를 지원하지 않으면 `Server.sln`을 엽니다.
2. MongoDB를 실행합니다: `docker compose up -d mongodb`.
3. `GameFrameX.Launcher`에 대한 `.NET Project` 실행 구성을 생성하거나 편집합니다.
4. `Working directory`를 `$SolutionDir$/bin/app_debug`로 설정합니다.
5. `Program arguments`는 비워 둡니다(기본 구성은 [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs) 참조).
6. Debug를 클릭합니다. `bin/app_debug`가 없으면 먼저 `dotnet build Server.sln`을 한 번 실행하세요.

### 방식 4: Visual Studio 디버깅

1. `Server.slnx`를 엽니다; Visual Studio 버전이 `.slnx`를 지원하지 않으면 `Server.sln`을 엽니다.
2. `GameFrameX.Launcher`를 시작 프로젝트로 설정합니다.
3. MongoDB를 실행합니다: `docker compose up -d mongodb`.
4. `Working directory`를 솔루션 디렉터리의 `bin\app_debug`로 설정합니다.
5. `Command line arguments`는 비워 둡니다.
6. F5를 눌러 디버깅을 시작합니다. 첫 디버깅 전에 출력 디렉터리가 없으면 먼저 Build Solution을 실행하세요.

## 일반적인 변형

기본 구성(포트, 데이터베이스 연결 등)을 재정의해야 할 때는 명령줄에 시작 매개변수를 추가합니다:

```bash
dotnet GameFrameX.Launcher.dll \
    --ServerId=1000 \
    --ServerType=Game \
    --IsEnableTcp=true \
    --InnerPort=29100 \
    --MetricsPort=29090 \
    --IsEnableHttp=true \
    --HttpPort=28080 \
    --IsEnableWebSocket=true \
    --WsPort=29110 \
    --HttpIsDevelopment=true \
    --MinModuleId=10 \
    --MaxModuleId=9999 \
    --TagName=GameFrameX \
    --DataBaseUrl="mongodb://localhost:27017" \
    --DataBaseName=gameframex
```

| 매개변수 | 의미 |
| :--- | :--- |
| `--ServerId` `--ServerType` | 서버 고유 번호와 타입(예: Game) |
| `--IsEnableTcp` `--InnerPort` | TCP 내부 네트워크 포트 활성화 여부 |
| `--IsEnableHttp` `--HttpPort` `--HttpIsDevelopment` | HTTP 리스닝 및 개발 모드 여부 |
| `--IsEnableWebSocket` `--WsPort` | WebSocket 리스닝 활성화 여부 |
| `--MetricsPort` | Prometheus 메트릭 및 헬스 체크 포트 |
| `--MinModuleId` `--MaxModuleId` | 비즈니스 모듈 ID 범위 |
| `--TagName` | 시작 태그, `AppStartUpGame` 등의 런처로 라우팅하는 데 사용 |
| `--DataBaseUrl` `--DataBaseName` | MongoDB 연결 문자열과 데이터베이스 이름 |

로컬 디버깅 시 **매개변수를 비워 두면** 됩니다. 기본값은 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`에 있습니다.

## 배포 검증

시작에 성공한 후 아래 엔드포인트로 서비스가 정상인지 확인합니다:

| 엔드포인트 | 주소 | 설명 |
| :--- | :--- | :--- |
| 헬스 체크 | `http://localhost:29090/health` | 서비스 상태 |
| 메트릭 모니터링 | `http://localhost:29090/metrics` | Prometheus 메트릭 |
| 테스트 인터페이스 | `http://localhost:28080/game/api/test` | HTTP 연결 테스트 |

세 가지 중 하나라도 정상적으로 응답하면 프레임워크가 올바르게 실행된 것입니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
| :--- | :--- | :--- |
| 시작 시 MongoDB 연결 실패 오류 발생 | MongoDB가 실행되지 않았거나 연결 문자열 또는 데이터베이스 이름이 잘못됨 | 먼저 `docker compose up -d mongodb` 실행, 또는 `--DataBaseUrl` `--DataBaseName` 조정 |
| Rider / VS 디버깅 시 `bin/app_debug`를 찾을 수 없음 | 최초 빌드가 실행되지 않음 | 먼저 `dotnet build Server.sln` 실행 후 디버깅 시작 |
| `Server.slnx`를 열 수 없음 | IDE 버전이 너무 오래됨 | `Server.sln` 사용 |
| 포트가 점유됨 | 기본 28080 / 29090 / 29100 / 29110이 이미 사용 중 | "일반적인 변형" 섹션을 참조하여 매개변수로 재정의 |
| HTTP 테스트 인터페이스 404 | 프레임워크가 HTTP를 활성화하지 않았거나 포트 구성 충돌 | `--IsEnableHttp=true --HttpPort=28080`이 런처와 일치하는지 확인 |

## 배경(선택)

GameFrameX Server는 Actor 모델과 상태/로직 분리를 채택하고 있습니다: 영속화 데이터는 `GameFrameX.Apps`에, 비즈니스 로직은 `GameFrameX.Hotfix`에 있으며, 서비스를 중단하지 않고 핫 교체할 수 있습니다. 런처 `AppStartUpGame`은 `[StartUpTag(GameServerConst.Game.Name)]`와 `--TagName` 매개변수를 매칭하여 네트워크 프로토콜, 컴포넌트 프록시, 설정 테이블의 조립을 완료합니다. 소스 코드 구성에 대한 자세한 내용은 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server/blob/main/README.zh-CN.md#L180-L260)를 참조하세요.
