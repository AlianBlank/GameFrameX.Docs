# 言語切り替えが反映されない・保存されない：システム言語フォールバックと Setting 永続化のチェック

`Language` がまだセンチネル値 `"zxx"`（`UnknownLocalization`）のままである場合、フレームワークは実行時に**システム言語へ自動的にフォールバック**します。また、`LocalizationComponent` を通して言語を設定するたびに、フレームワークは Setting に書き込み、`Save()` によって永続化します。言語が「反映されない／保存されない」ケースのほとんどは、`LocalizationManager.Language` を直接変更した（Setting への書き込みをバイパスした）、エディターモードにより `m_IsEnableEditorMode` + `EditorLanguage` で上書きされた、あるいは `"zxx"` を渡して拒否された、のいずれかが原因です。以下、症状別に 1 つずつ切り分けていきます。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 言語を設定したのに、再起動してもシステム言語のまま表示される | 直接変更したのは `LocalizationManager.Language` であり、`SettingComponent` による永続化を経由していない | `LocalizationComponent.Language` のみを通して代入する。[修正 1](#修正-1localizationcomponentlanguage-で切り替えて永続化する) を参照 |
| エディター内でどれだけ言語を切り替えても、Play 後に `zh_CN` などの固定値で上書きされる | コンポーネントで `m_IsEnableEditorMode` がチェックされており、`Start()` 内で `EditorLanguage` により上書きされる | チェックを外すか、Inspector の Editor Language を変更する。[修正 2](#修正-2エディターで言語が-editorlanguage-に上書きされる) を参照 |
| `GameFrameworkException: Language is invalid.` がスローされる | `Language` に `UnknownLocalization`（`"zxx"`）を代入したため、setter が直接例外をスローする | `"zxx"` を渡さないこと。空の値の場合は明示的にデフォルト言語を代入する。[修正 3](#修正-3zxx-を渡して-language-is-invalid-が発生する) を参照 |
| `GameFrameworkException: default Language is invalid.` がスローされる | `DefaultLanguage` に `"zxx"` を代入した | 有効な言語コード（`"zh_CN"`、`"en_US"` など）を代入する。[修正 3](#修正-3zxx-を渡して-language-is-invalid-が発生する) を参照 |
| 起動ログに `Can not create localization helper.` が出た後、言語関連機能がすべて動作しなくなる | `m_LocalizationHelperTypeName` が誤った型名に変更されており、Helper の作成に失敗している | デフォルトの完全名 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` に戻す。[修正 4](#修正-4helper-作成失敗で-systemlanguage-が使用不可になる) を参照 |
| ログに `Setting component is invalid.` と出て、言語設定の読み書きがすべて機能しなくなる | シーンに `SettingComponent` がなく、`Start()` が即座に Fatal で return する | Setting コンポーネントを取り付ける。[修正 4](#修正-4helper-作成失敗で-systemlanguage-が使用不可になる) を参照 |
| 言語を切り替えたのに UI のテキストが変わらない | 言語イベントは発行されたが、辞書が再読み込みされていない、または UI が更新されていない | `LocalizationLanguageChangeAfterEventArgs` をリッスンした後に辞書を再読み込み／UI を更新する。[修正 5](#修正-5言語切替後にテキストが更新されない) を参照 |
| UI に `<NoKey>xxx` が表示される | 現在の言語の辞書にその Key がない | 該当言語の辞書エントリを補完する。[検証](#検証) を参照 |

## 修正手順

### 修正 1：`LocalizationComponent.Language` で切り替えて永続化する

永続化が行われるのは `LocalizationComponent` というレイヤーの setter 内だけです。Setting キー `LocalizationComponent.Language` に書き込んで即座に `Save()` を実行し、その後 Before / Change / After の 3 つの言語イベントを順に発火します。`LocalizationManager.Language` を直接変更しても Setting には書き込まれず、再起動すると失われます。

```csharp
// 正しい：コンポーネント層を経由した代入 —— Setting への書き込み + Save + 3 つの言語イベントの発火
GameEntry.GetComponent<LocalizationComponent>().Language = "en_US";

// 誤り：コンポーネント層をバイパスするため、再起動後に失われる（Setting に書き込まず、イベントも発火しない）
// GameFrameXEntry.GetModule<ILocalizationManager>().Language = "en_US";
```

出典: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L140-L171)

対応する Setting キーと読み取り順序（getter はまず Setting を調べ、それでも不明な場合にのみフォールバックします）：

```csharp
get
{
    if (m_LocalizationManager.Language == UnknownLocalization)
    {
        var value = m_SettingComponent.GetString(nameof(LocalizationComponent) + "." + nameof(Language));
        if (value.IsNotNullOrWhiteSpace())
        {
            m_LocalizationManager.Language = value;
        }
    }

    return m_LocalizationManager.Language;
}
```

出典: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L143-L153)

`DefaultLanguage` の動作もまったく同じで、キー名が `LocalizationComponent.DefaultLanguage` に変わるだけです：[LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L104-L128)

### 修正 2：エディターで言語が `EditorLanguage` に上書きされる

`Start()` ではエディターモードによって 2 つのパスに分かれます。`m_IsEnableEditorMode` がチェックされている場合、エディター内の言語は `EditorLanguage` に強制設定されます。ビルド環境（または未チェック）では、`Language == UnknownLocalization` の場合にのみシステム言語へフォールバックします。

```csharp
#if UNITY_EDITOR
            if (m_IsEnableEditorMode)
            {
                Language = EditorLanguage != UnknownLocalization ? EditorLanguage : m_LocalizationManager.SystemLanguage;
            }
#else
            if (Language == UnknownLocalization)
            {
                Language = m_LocalizationManager.SystemLanguage;
```

出典: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L270)

操作方法：

1. シーン内の Localization コンポーネントを選択し、**Is Enable Editor Mode** がチェックされているかどうかを確認します。
2. チェックされている場合、Inspector の **Editor Language**（デフォルト `zh_CN`）が Play のたびに以前保存された言語を上書きします——チェックを外すか、検証したい言語に変更してください。
3. デフォルトのシリアライズ値の参考（`m_EditorLanguage`／`m_DefaultLanguage` はいずれも `"zh_CN"`、エディターモードはデフォルトでオフ）：

```csharp
        [SerializeField] private string m_EditorLanguage = "zh_CN";

        [SerializeField] private string m_DefaultLanguage = "zh_CN";

        [SerializeField] private bool m_EnableLoadDictionaryUpdateEvent = false;
        [SerializeField] private bool m_IsEnableEditorMode = false;
```

出典: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L71)

### 修正 3：`zxx` を渡して `Language is invalid.` が発生する

`"zxx"` は「未知のローカライゼーション」を表すセンチネル値であり、両方の setter がこれを拒否します：

```csharp
            set
            {
                if (value == UnknownLocalization)
                {
                    throw new GameFrameworkException("Language is invalid.");
                }

                _language = value;
            }
```

出典: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L100-L108)

| プロパティ | 例外メッセージ原文 | トリガー値 |
|------|--------------|--------|
| `LocalizationManager.Language` | `Language is invalid.` | `"zxx"` |
| `LocalizationManager.DefaultLanguage` | `default Language is invalid.` | `"zxx"` |

`default Language is invalid.` の出所は [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L71-L83) を参照してください。代入時に実際の言語コードを使えば解決します。

### 修正 4：Helper 作成失敗で `SystemLanguage` が使用不可になる

`Start()` は `BaseComponent`、`EventComponent`、`SettingComponent` の順に依存しており、いずれかが欠けていると `Log.Fatal` の後 `return` し、言語の読み書きはすべて機能しなくなります。続いて `m_LocalizationHelperTypeName` に基づいて Helper を作成し、失敗するとログに `Can not create localization helper.` を出力します。また、`SystemLanguage` の内部には非 null ガードがあり、Helper が null の場合に直接例外をスローします：

```csharp
        public string SystemLanguage
        {
            get
            {
                GameFrameworkGuard.NotNull(_localizationHelper, nameof(_localizationHelper));
                return _localizationHelper.SystemLanguage;
            }
        }
```

出典: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L115-L122)

操作方法：

1. シーンに Setting／Event コンポーネントが存在することを確認します（ログに `Setting component is invalid.` / `Event component is invalid.` が出ていれば欠落しています）。出所は [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227-L246)。
2. Inspector の **Localization Helper Type Name** がデフォルトの完全名のままであるかを確認します：

```csharp
        [SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

出典: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

3. デフォルト Helper のシステム言語は `CultureInfo.CurrentCulture` に由来し、`-` を `_` に置き換えます（例：`zh-CN` → `zh_CN`）。デバイスの地域形式が辞書の命名と一致しない場合、それが「フォールバック言語が永遠に一致しない」根本原因です：

```csharp
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
```

出典: [DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L52-L55)

`LocalizationHelperBase` を継承して `SystemLanguage` をオーバーライドし（抽象定義は [LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L47) を参照）、その後 **Custom Localization Helper** スロットを通じてデフォルト実装を置き換えることができます。

### 修正 5：言語切替後にテキストが更新されない

`LocalizationComponent.Language` の setter は、保存後に 3 つのイベントを順に発火します：`LocalizationLanguageChangeBeforeEventArgs`、`LocalizationLanguageChangeEventargs`（Change）、`LocalizationLanguageChangeAfterEventArgs`。いずれも `oldLanguage` と新しい言語を保持しています。辞書の再読み込みと UI の更新は、これらのイベントを購読して行うべきであり、典型的なタイミングは After です：

```csharp
var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventargs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
```

出典: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L163-L168)

イベント引数の定義は [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41) を参照してください。

## 検証

1. **言語値**：Inspector で Localization コンポーネントを選択すると、パネルに `Language`、`System Language` の 2 つの読み取り専用フィールドが直接表示されます（[LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L70-L72)）。言語を切り替えた後、`Language` が新しい値、`System Language` がデバイスの地域値になっていることを確認します。
2. **永続化**：言語を設定 → Play を停止 → 再度 Play。`Language` は新しい値を保持しているはずです（getter は Setting キー `LocalizationComponent.Language` から読み戻します）。
3. **フォールバックロジック**：ローカルの Setting をクリアしてから Play すると、`Language` は `SystemLanguage` と等しくなるはずです——`LocalizationManager.Language` は未設定時にシステム言語を返すためです：

```csharp
            get
            {
                if (_language == UnknownLocalization)
                {
                    return SystemLanguage;
                }

                return _language;
            }
```

出典: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L91-L99)

4. **辞書**：値の取得が正常になると、`<NoKey>{key}` プレースホルダーは出力されなくなります（[LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L168-L177)）。それでも出力される場合は、現在の言語の辞書が未ロードか Key が不足しているため、該当言語の辞書を補完してください。

## 背景

`Language` はセンチネル値 `"zxx"`（`LocalizationManager.UnknownLocalization` 定数、[LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L53) を参照）で「未設定」を表します。3 か所のフォールバックチェーンは次の通りです：コンポーネント層 getter → Setting の永続値、マネージャー getter → `SystemLanguage`、`Start()` → システム言語による最終的な代入。言語コードは RFC 5646 スタイルに従い（コンポーネントの `[HelpURL]` がこの仕様を指しています）、内部では `-` の代わりに `_` を統一して使用します。
