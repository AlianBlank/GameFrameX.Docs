# 핫픽스 런처(Hotfix Launcher) 연동 방법(IHotfixLauncher)

`IHotfixLauncher` 인터페이스를 구현하면 시작 프로세스가 리소스 패치 완료 후 사용자의 핫픽스 솔루션(HybridCLR, ILRuntime, 자체 개발 솔루션 등)을 호출하며, 어셈블리를 로드하고 핫픽스 진입점으로 이동하는 방법은 애플리케이션 계층에서 결정합니다.

## 사전 조건

- 시작 프로세스가 올바르게 초기화되어 있어야 합니다(시작 프로세스 연동 문서 참조).
- `StartupOptions` 설정 에셋을 준비하고 `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`을 입력했어야 합니다.
- `GameFrameX.Startup.Runtime` 네임스페이스와 `Cysharp.Threading.Tasks`를 임포트했어야 합니다.

## 인터페이스 계약

`IHotfixLauncher`는 하나의 비동기 메서드만 노출하며, 성공 또는 실패와 관계없이 반드시 `HotfixLaunchResult`를 반환해야 하고, 예외를 직접 던지지 않아야 합니다.

```csharp
using Cysharp.Threading.Tasks;

namespace GameFrameX.Startup.Runtime
{
    /// <summary>
    /// 핫픽스 시작 인터페이스로, 애플리케이션 계층에서 구현합니다. 패키지는 구체적인 핫픽스 솔루션(HybridCLR / 기타)에 바인딩되지 않습니다.
    /// </summary>
    public interface IHotfixLauncher
    {
        UniTask<HotfixLaunchResult> StartAsync(StartupOptions options);
    }
}
```

## 작업 단계

1. 애플리케이션 프로젝트 아래에 새 클래스(예: `MyHotfixLauncher`)를 만들고 `IHotfixLauncher`를 구현합니다.
2. `StartAsync` 내에서 `options`에 따라 핫픽스 DLL/어셈블리를 읽고, 리플렉션을 통해 진입 메서드를 호출합니다(`HotfixLaunchResult.Succeed()` 또는 `HotfixLaunchResult.Fail(message)`를 생성하여 반환).
3. `StartAsync` 내에서 예외를 던지지 마세요 — 실패 시 `HotfixLaunchResult.Fail("에러 메시지")`를 생성하여 반환하면, 시작 프레임워크가 이를 기반으로 실패 분기로 진행하고 `StartupFailedEventArgs`를 발행합니다.
4. `MyHotfixLauncher` 인스턴스를 시작 관리자에 주입합니다(일반적으로 `StartupManager`의 주입 인터페이스 또는 `GameObject` 드래그 설정을 통해). 이를 통해 프레임워크의 기본 Launcher를 덮어씁니다.
5. 시작 프로세스를 실행합니다. Patch 단계가 모두 완료되면 프레임워크가 자동으로 `StartAsync`를 호출합니다.

## 최소 구현 예제

다음은 계약 테스트 기반의 최소 사용 가능한 구현으로, 템플릿으로 바로 활용할 수 있습니다:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public sealed class MyHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        try
        {
            // 1) 핫픽스 어셈블리 로드(예: HybridCLR / YooAsset / 자체 개발 loader 사용)
            //    var assembly = LoadAssembly(options.HotfixAssemblyName);

            // 2) 리플렉션을 통해 핫픽스 진입점으로 이동
            //    var entryType = assembly.GetType(options.HotfixEntryTypeName);
            //    var entryMethod = entryType.GetMethod(options.HotfixEntryMethodName);
            //    entryMethod.Invoke(null, null);

            await UniTask.Yield();
            return HotfixLaunchResult.Succeed();
        }
        catch (System.Exception ex)
        {
            return HotfixLaunchResult.Fail(ex.Message);
        }
    }
}
```

## 일반적인 변형

- **HybridCLR 솔루션**: `StartAsync`에서 `HybridCLR.RuntimeApi.LoadDllFromMemory`를 통해 DLL을 로드한 후, `System.Reflection.Assembly` 리플렉션으로 진입 메서드를 호출합니다.
- **순수 리소스 핫픽스(DLL 없음)**: `Resources.Load<GameObject>`로 프리팹을 직접 로드한 후 `Instantiate`하며, 진입 로직에서 리플렉션 단계를 건너뛸 수 있습니다.
- **초기화 단계가 있는 솔루션**: 핫픽스 프레임워크에 비동기 초기화(예: 다운로드, 검증)가 필요한 경우, `StartAsync` 내에서 `await` 완료 후 `Succeed`를 반환합니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 시작 시 크래시 또는 검은 화면 | `StartAsync`에서 처리되지 않은 예외가 발생함 | 캐처한 후 `HotfixLaunchResult.Fail(message)`를 반환하도록 변경 |
| `Success=true`가 반환되지만 게임이 메인 씬에 진입하지 않음 | 진입 메서드 이름/타입 이름 오타 | `StartupOptions`의 `HotfixEntryTypeName` / `HotfixEntryMethodName`이 DLL과 완전히 일치하는지 확인 |
| 계속 Patch 단계에 머물러 있음 | 커스텀 `IHotfixLauncher`가 주입되지 않아 프레임워크가 기본 빈 구현을 사용함 | 시작 관리자에서 자체 구현 클래스로 교체 |

## 검증

- 시작 프로세스를 실행하여 Patch 완료 후 핫픽스 진입점에 진입하는지 확인합니다.
- 단위 테스트는 `IHotfixLauncherContractTests`를 참고할 수 있으며, 성공 구현은 `result.Success == true`이고 `ErrorMessage`가 빈 문자열임을, 실패 구현은 `result.Success == false`이고 `ErrorMessage`가 전달된 예외 메시지와 같음을 단언합니다.

## 배경(선택)

`IHotfixLauncher`는 패키지가 의도적으로 노출한 확장 포인트입니다. 패키지 내에서는 「Patch 완료 → Launcher 호출 → 결과 획득」이라는 프로토콜만 규정하며, 구체적인 핫픽스 솔루션에 바인딩하지 않아 HybridCLR 등 서드파티 패키지와의 강한 결합을 피합니다.
