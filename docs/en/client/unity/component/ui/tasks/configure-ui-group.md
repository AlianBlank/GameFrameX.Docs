# How to Configure UI Groups (UIGroup)

In GameFrameX UI, UI Groups (UIGroup) are used to organize multiple UI forms into layers and control rendering order. After completing the configuration on this page, you will be able to define UI groups, set depths, and have the UI framework display forms correctly according to depth order.

## Prerequisites

- The `com.gameframex.unity.ui` package is installed and enabled.
- A basic understanding of Unity UGUI / UCanvas hierarchy concepts (Sibling Index, SortingOrder).

## Core Concepts of UI Groups

A UI group consists of three parts:

| Component | Purpose |
|------|------|
| `UIGroupDefine` | UI group definition, containing two read-only fields: `Depth` and `Name` |
| `IUIGroupHelper` | UI group helper that actually modifies the RectTransform's Sibling Index / Canvas hierarchy |
| `UIGroup` | Runtime instance that manages a set of UI forms (add/remove, pause, depth switching) |

### UIGroupDefine Definition

`UIGroupDefine` is a lightweight value object that holds only the `Depth` and `Name` fields:

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class UIGroupDefine
{
    public readonly int Depth;
    public readonly string Name;

    public UIGroupDefine(int depth, string name)
    {
        Depth = depth;
        Name = name;
    }
}
```

The framework provides 19 commonly used UI groups in `UIGroupConstants`, arranged from highest to lowest depth. The greater the depth, the later it is rendered (displayed on a higher layer).

### Step 2: Create a Custom UI Group (Optional)

If the built-in constants are not sufficient, you can create your own `UIGroupDefine`. It is recommended to keep depths within the existing range (e.g., -50 to 50) to avoid overriding system layers:

```csharp
using GameFrameX.UI.Runtime;

// Custom "Main" group with depth 5 (between Normal and Fixed)
var mainGroup = new UIGroupDefine(5, "Main");

// Custom "BattleText" (floating battle text) group with depth 28 (between Hud and Battle)
var battleText = new UIGroupDefine(28, "BattleText");
```

Source: [UIGroupDefine.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIGroupDefine.cs#L70-L74)

### Step 3: Implement a UI Group Helper (Optional, Advanced Usage)

`UIGroupHelperBase` is an abstract MonoBehaviour. You need to implement the `Depth`, `SetDepth(int)`, and `Handler(...)` methods, which actually change the Transform's Sibling Index or the Canvas's SortingOrder.

```csharp
using UnityEngine;
using GameFrameX.UI.Runtime;

public sealed class MyUIGroupHelper : UIGroupHelperBase
{
    private int m_Depth;
    public override int Depth { get => m_Depth; protected set => m_Depth = value; }

    public override void SetDepth(int depth)
    {
        m_Depth = depth;
        transform.SetSiblingIndex(depth);
    }

    public override IUIGroupHelper Handler(
        Transform root, string groupName,
        string uiGroupHelperTypeName,
        IUIGroupHelper customUIGroupHelper, int depth = 0)
    {
        // Create a child node under root as this group's container, attach the Helper component, and return it
        var go = new GameObject(groupName);
        go.transform.SetParent(root, false);
        var helper = go.AddComponent<MyUIGroupHelper>();
        helper.SetDepth(depth);
        return helper;
    }
}
```

Source: [UIGroupHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIGroupHelperBase.cs#L41-L77)

### Step 4: Mark the UI Group of Each Form in the UI Table

In the UI table (Excel / SO configuration), select the UI group each UI form belongs to. The framework will automatically create the corresponding `UIGroup` instance based on this field and attach the form to the matching hierarchy level. The UIGroup runtime class manages the form list within the group, pause states, and depth synchronization:

```csharp
// The runtime UIGroup holds a linked list of UI forms; you can read properties such as depth/pause/count
var group = uiManager.GetUIGroup(UIGroupConstants.Tip.Name);
group.Depth  // Current depth; assigning a value automatically calls Helper.SetDepth and refreshes the forms
group.Pause  // Whether OnUpdate is paused for all forms in the group
group.UIFormCount
group.CurrentUIForm
```

## Common Variations

### Choosing Between Multiple Constants

- **Background layer**: `Background` (35) holds scene background images.
- **Floating battle text**: `Battle` (25) or a custom higher depth, to ensure numbers float above characters.
- **Dialogue**: `Dialogue` (-23) always sits above regular windows.
- **Global Loading**: `Loading` (-25) covers the vast majority of UI, but still sits below `Notify`/`System`.

### Custom Depth Ranges

If your project requires frequently inserting new layers, you can divide sub-ranges at intervals of 5 (e.g., `12`, `8`, `3`, etc.) to avoid frequent changes to existing depths later.

## Common Mistakes

| Error | Symptom | Fix |
|------|------|------|
| Depth values spread too far apart | Later-inserted forms cannot find a suitable position between two layers | Use a reasonable range (e.g., -50 to 50) with intervals of 5 |
| Creating a UIGroup with a duplicate Name | The framework throws an exception when a duplicate name is detected | Reuse the same `UIGroupDefine` constant; do not build names by string concatenation |
| Custom Helper not attached to a GameObject | `SetDepth` calls have no effect | Call `go.AddComponent<MyHelper>()` inside `Handler` |
| Form displayed on the wrong layer | Check whether the UIGroup name spelling matches the table configuration | Use `UIGroupConstants.*` constants to avoid typos |

## Background (Optional)

UIGroup is designed to centrally manage "display layering". Depth is applied to Unity's Sibling Index via `IUIGroupHelper.SetDepth`, and during `Refresh()` the UI framework updates visibility/pause states according to the UI order within each group, avoiding the confusion caused by every UI maintaining its own layering. The 19 preset constants cover the layering needs of the vast majority of 2D/3D games.
