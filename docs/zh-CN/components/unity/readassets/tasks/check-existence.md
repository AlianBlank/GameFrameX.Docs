# 查询文件与目录是否存在

`BlankReadAssets` 提供 `FileExists` 与 `DirectoryExists` 两个静态方法,用于在运行时判断 `StreamingAssets` 下的文件或目录是否存在。它们在 Android(直接读取 APK)、编辑器、其他平台(松散文件)下都能正确工作,首次调用会自动调用 `Initialize`。

## 前置条件

- 已安装 `com.gameframex.unity.readassets` 包。
- `StreamingAssets` 目录在工程中存在(运行时无需手动初始化,首次调用 API 会自动完成)。

## 操作步骤

1. 判断文件是否存在,传入相对于 `StreamingAssets` 的路径:

```csharp
using GameFrameX.ReadAssets.Runtime;

bool exists = BlankReadAssets.FileExists("configs/level1.json");
if (exists)
{
    // 安全地继续 OpenRead / LoadAssetBundle 等
}
```

2. 判断目录是否存在,同样使用相对路径(以 `/` 开头或结尾均可,内部会规范化):

```csharp
using GameFrameX.ReadAssets.Runtime;

bool dirExists = BlankReadAssets.DirectoryExists("configs/");
```

## API 速查

| 方法 | 签名 | 说明 |
|------|------|------|
| `FileExists` | `static bool FileExists(string path)` | 检查相对 `StreamingAssets` 的文件是否存在 |
| `DirectoryExists` | `static bool DirectoryExists(string path)` | 检查相对 `StreamingAssets` 的目录是否存在 |

两个方法都标记了 `[Preserve]`,均通过 `EnsureInitialized()` 自动初始化后委托给平台实现(`EditorImpl` / `ApkImpl` / `LooseFilesImpl`)。

## 常见变体

- 在编辑器中想检查一个外部 APK 内 `StreamingAssets` 的存在性,需要先调用 `InitializeWithExternalApk(apkPath)`,之后再用同样的 `FileExists` / `DirectoryExists`。
- 在 Android 上,APK 内的路径判断会扫描 APK 的目录树(`ApkImpl.DirectoryExists` 内部使用 `GetDirectoryIndex`),因此无需担心大小写与压缩状态。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 始终返回 `false`,但文件确实存在 | 路径传成了绝对路径或包含 `Application.streamingAssetsPath` 前缀 | 只传相对于 `StreamingAssets` 的路径,如 `"config.json"` 而不是 `Application.streamingAssetsPath + "/config.json"` |
| 路径带反斜杠或多余 `/` 导致误判 | 平台路径分隔符差异 | 直接传入 `/` 分隔的相对路径,工具内部通过 `PathUtil.NormalizeRelativePath` 规范化 |
| 在 Android 上返回 `true` 但后续 `OpenRead` 抛异常 | 文件在 APK 内被 Unity 标记为压缩 | 监听 `BlankReadAssets.CompressedStreamingAssetFound` 事件,改用 `UnityWebRequest` 读取 |

## 背景(可选)

平台分发由 `BlankReadAssets.cs` 顶部的条件编译选择:`UNITY_EDITOR` 走 `EditorImpl`(支持 APK 模式/外部目录),`UNITY_ANDROID` 走 `ApkImpl`(从 APK 内部二进制搜索定位),其他平台走 `LooseFilesImpl`(直接走文件系统)。`DirectoryExists` 在 APK 内通过构建好的路径索引 `GetDirectoryIndex` 判断,因此不会触发实际解压。
