# 네트워크 프로토콜 메시지 핸들러 등록 방법

`IMessageHandler`를 상속한 매니저 클래스에 `[MessageHandler]` 특성을 붙이고, 초기화 시 `ProtoMessageHandler.Add(this)`를 호출하면, GameFrameX가 해당 프로토콜을 수신했을 때 수동 `switch` 디스패치 없이 자동으로 대상 메서드로 라우팅합니다.

## 사전 조건

- `GameFrameX.Network.Runtime`에서 가져온 프로토콜 메시지 클래스가 이미 있어야 합니다 (Proto로 생성됨, 예: `NotifyBagInfoChanged`).
- 매니저 클래스가 `GameFrameworkSingleton<T>`를 상속하고 `IMessageHandler` 인터페이스를 구현해야 합니다.

## 작업 단계

1. **매니저가 `IMessageHandler`를 구현하고 싱글톤 베이스 클래스를 상속하도록 합니다**. 전체 클래스에는 하나의 인스턴스만 필요하며, 네트워크 레이어는 이 하나의 객체로만 디스패치합니다.

   ```csharp
   using GameFrameX.Network.Runtime;
   using GameFrameX.Runtime;

   namespace Hotfix.Manager
   {
       public sealed class BagManager : GameFrameworkSingleton<BagManager>, IMessageHandler
       {
           // ...
       }
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L16)

2. **처리 메서드에 `[MessageHandler(typeof(메시지 클래스), nameof(메시지 클래스))]` 특성을 붙입니다**. 첫 번째 매개변수는 프로토콜 메시지 타입을 지정하고, 두 번째 매개변수는 로그/디버그용 설명 이름이며, 메서드 시그니처와 일대일 대응됩니다.

   ```csharp
   /// <summary>
   /// 监听道具变化通知
   /// </summary>
   /// <param name="msg"></param>
   [MessageHandler(typeof(NotifyBagInfoChanged), nameof(NotifyBagInfoChanged))]
   private void NotifyBagInfoChanged(NotifyBagInfoChanged msg)
   {
       // 처리 메시지 본문
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L29-L30)

3. **`Register()`를 구현하고 그 안에서 `ProtoMessageHandler.Add(this)`를 호출합니다**. 현재 매니저를 프로토콜 디스패처에 등록하면, 프레임워크가 리플렉션 스캔 시 해당 인스턴스의 모든 `[MessageHandler]` 특성이 붙은 메서드를 읽어들입니다.

   ```csharp
   /// <summary>
   /// 注册消息。请勿多次调用
   /// </summary>
   public void Register()
   {
       ProtoMessageHandler.Add(this);
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L126-L129)

4. **적절한 시점에 `Register()`를 한 번 호출합니다**. 일반적으로 `Awake` 또는 첫 `GetInstance()` 시점에 트리거되며, 예를 들어:

   ```csharp
   private void Awake()
   {
       Register();
   }
   ```

   Source: [BagManager.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/BagManager.cs#L120)

## 일반적인 변형

- **동일한 매니저가 여러 프로토콜을 처리**: 각 메서드에 각각 `[MessageHandler(typeof(다른 메시지), nameof(다른 메시지))]`를 붙이고, `ProtoMessageHandler.Add(this)`를 한 번만 호출하면 모든 메서드가 등록됩니다. `PlayerAttributeManager`가 동시에 `NotifyPlayerAttributeSync`와 `NotifyPlayerAttributeChanged`를 처리하는 것이 바로 이 용례입니다. ([PlayerAttributeManager.cs#L79](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L79), [PlayerAttributeManager.cs#L109](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/PlayerAttributeManager.cs#L109))

- **다른 매니저가 다른 프로토콜을 처리**: 각 매니저가 각각 `IMessageHandler`를 구현하고 각각 `Register()`를 호출하며, 서로 영향을 주지 않습니다. 예를 들어 `RoomDataManager`는 `NotifyRoomChanged`를, `RockPaperScissorsDataManager`는 가위바위보 관련 프로토콜을 처리합니다. ([RoomDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RoomDataManager.cs#L16), [RockPaperScissorsDataManager.cs#L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Manager/RockPaperScissorsDataManager.cs#L16))

## 일반적인 오류

- **`Register()` 안에서 `ProtoMessageHandler.Add(this)` 호출을 잊음**: 특성은 단지 메타데이터일 뿐 자동으로 적용되지 않으므로, 메시지는 도착했지만 어떤 메서드도 호출되지 않습니다.
- **`Register()`를 중복 호출**: 주석에 "请勿多次调用"(여러 번 호출하지 마세요)라고 명시되어 있으며, 동일한 인스턴스를 여러 번 등록하면 디스패치가 중복됩니다.
- **메서드 시그니처와 특성의 메시지 타입 불일치**: `[MessageHandler(typeof(X), ...)]`의 `X`는 메서드 매개변수 타입과 완전히 일치해야 하며, 그렇지 않으면 리플렉션 바인딩이 실패합니다.
- **`Register()`를 생성자에 배치**: `GameFrameworkSingleton`은 생성 시점에 다른 서브시스템이 아직 초기화되지 않았을 수 있으므로, `Awake` 또는 명시적인 `GetInstance().Register()` 시점에 호출하는 것을 권장합니다.

## 배경(선택 사항)

`[MessageHandler]`는 리플렉션 기반의 프로토콜 라우팅 마커입니다. 프레임워크는 프로토콜 패킷을 수신한 후 `ProtoMessageHandler.Add(this)`를 통해 등록된 인스턴스 집합을 조회하여 디스패치하므로, 각 핸들러는 하나의 인스턴스만 필요하며, 이것이 바로 `GameFrameworkSingleton`을 상속하는 이유입니다.
