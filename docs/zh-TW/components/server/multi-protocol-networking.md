# 如何使用 TCP/WebSocket/KCP/HTTP 客戶端連線

透過 `GameFrameX.NetWork` 的 `INetWorkChannel` 與 `NetWorkSenderFactory`,業務端可以透明地收發 TCP、WebSocket、KCP 與 HTTP 客戶端訊息，而無需關心底層的協定差異。

## 前置條件

- 必須安裝 `GameFrameX.NetWork.Abstractions` 與 `GameFrameX.NetWork` 套件；KCP 客戶端需額外參考 `GameFrameX.NetWork.Kcp`,HTTP 客戶端則需要 `GameFrameX.NetWork.HTTP`。
- 必須整合 `GameFrameX.SuperSocket.Server.Abstractions.Session.IGameAppSession`(SuperSocket 工作階段)。
- 必須設定對應協定(TCP / WebSocket / KCP / HTTP)的監聽器。

## 步驟

### 1. 取得網路通道

在業務處理器中，透過工作階段取得 `INetWorkChannel`。後續的傳送與接收操作都經由通道進行，不會直接接觸協定。

```csharp
using GameFrameX.NetWork;
using GameFrameX.NetWork.Abstractions;
using GameFrameX.SuperSocket.Server.Abstractions.Session;

// 在 SuperSocket 訊息處理上下文中
IGameAppSession session = /* 來自連線事件或訊息處理器 */;
INetWorkChannel channel = NetWorkSenderFactory.Create(session);
// NetWorkSenderFactory 會依據實際的工作階段型別自動選擇 WebSocket 或 TCP 傳送器
```

來源:[GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L12-L17)

### 2. 向客戶端傳送訊息

建構 `INetworkMessage` 並呼叫 `WriteAsync` 以非同步方式傳送;`errorCode` 預設為 `0`,業務端在發生錯誤時可回傳錯誤碼。

```csharp
using GameFrameX.NetWork.Abstractions;

await channel.WriteAsync(message, errorCode: 0);
```

`INetWorkChannel.WriteAsync` 在網路通道已關閉時會拋出例外狀況。可以在呼叫前先檢查 `IsClosed()`。

來源:[GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L96-L108)

### 3. 關閉連線

```csharp
channel.Close();
```

來源:[GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L110-L116)

### 4. 在通道上儲存與讀取自訂資料

`SetData` / `GetData<T>` / `RemoveData` / `ClearData` 用於將使用者模式的資料(例如玩家物件、登入狀態)附加到通道的生命週期上，無需額外的 Map。

```csharp
channel.SetData("playerId", 10001);
var pid = channel.GetData<long>("playerId");
channel.RemoveData("playerId");
// channel.ClearData(); // 斷線或需要重設時
```

來源:[GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L118-L155)

## 常見變體

### TCP / WebSocket

`NetWorkSenderFactory.BuildProviders()` 內建 `WebSocketNetWorkSenderProvider` 與 `SessionNetWorkSenderProvider`,分別涵蓋 WebSocket 與 TCP(以及像 KCP 這樣共用 `IGameAppSession` 的協定)的工作階段型別——無需額外註冊；它會依據 `session.GetType()` 自動比對。

來源:[GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L19-L36)

### KCP

KCP 工作階段同樣實作 `IGameAppSession`,並重複使用 `SessionNetWorkSenderProvider` 的傳送路徑；若需要自訂編解碼，請在 KCP 監聽端接上。

### HTTP

HTTP 使用來自 `GameFrameX.NetWork.HTTP` 的獨立通道。請求處理完成後呼叫 `Close()`;可使用 `GetData`/`SetData` 在請求處理鏈中傳遞上下文。

## 常見錯誤

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `WriteAsync` 拋出例外狀況 | 通道已關閉(`IsClosed()` 回傳 `true`) | 傳送前加上 `if (!channel.IsClosed())` 的防護判斷 |
| `GetData<T>` 拋出例外狀況 | 索引鍵不存在或型別不符 | 寫入時使用統一的型別；讀取前先以 `ContainsKey` 之類的方式檢查，或捕捉例外狀況 |
| WebSocket 訊息傳送失敗 | 未經過 `NetWorkSenderFactory`,直接使用了 TCP 傳送器 | 一律透過 `NetWorkSenderFactory.Create(session)` 取得通道，工廠會依據工作階段型別分派 |
| KCP 封包已送達但業務端未收到 | KCP 監聽端未接上 `INetWorkChannel` 管線 | 確認 KCP 工作階段有包裝 `IGameAppSession`,且通道由工廠建立 |

## 背景說明(選擇性)

`NetWorkSenderFactory` 透過 `SenderProviders` 字典將各協定的工作階段型別對應到 `INetWorkSenderProvider`。`ResolveProvider` 會優先採用完全相符的比對，再退回可指派關係，因此新增協定時只需新增一組 `Provider` + `Sender` 實作並註冊即可——業務端的 `WriteAsync` 呼叫不需修改。`INetWorkChannel` 將位元組/封包計數、心跳時間、自訂資料以及關閉等能力整合到單一介面，讓業務程式碼只看到與協定無關的通道檢視。
