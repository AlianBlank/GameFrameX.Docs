# 如何使用异步可回收字典

`AsyncDisposableDictionary<TKey, TValue>` 是一个要求值实现 `IAsyncDisposable` 的字典容器,继承自 `NullableDictionary<TKey, TValue>`。当字典本身被 `DisposeAsync()` 时,它会自动遍历并异步释放所有非空值,适合管理一组需要异步清理的资源(如数据库连接、网络会话、长连接客户端等)。

## 前置条件

- `TValue` 必须实现 `IAsyncDisposable`。
- 引入命名空间 `GameFrameX.Foundation.Extensions`。
- 适用 .NET 版本支持 `IAsyncDisposable`(.NET Standard 2.1+ / .NET 5+)。

## 操作步骤

1. **创建字典实例并写入值**

   直接通过集合初始化器或索引器写入资源对象即可:

   ```csharp
   using GameFrameX.Foundation.Extensions;

   var dictionary = new AsyncDisposableDictionary<string, MyAsyncResource>
   {
       ["conn-1"] = new MyAsyncResource(),
       ["conn-2"] = new MyAsyncResource()
   };
   ```

   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L6-L37)

2. **(可选)设置释放错误处理器**

   当某个值的 `DisposeAsync()` 抛出异常时,字典会调用 `DisposalErrorHandler`,由你决定如何记录或兜底:

   ```csharp
   dictionary.DisposalErrorHandler = (value, ex) =>
   {
       Console.WriteLine($"释放 {value} 失败: {ex.Message}");
   };
   ```

   处理器自身抛出的异常会被吞掉,以保证剩余值仍能被释放。  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L92-L102)

3. **调用 `DisposeAsync()` 异步释放所有值**

   ```csharp
   await dictionary.DisposeAsync();
   ```

   释放过程是幂等的:重复调用 `DisposeAsync()` 不会重复释放值。可用 `dictionary.IsDisposed` 查询状态。  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L71-L90)

4. **释放后不要再写入或修改**

   释放后调用索引器 `set`、`Add`、`Remove` 会抛出 `ObjectDisposedException`。读取(get)仍然可用,因为它继承自基类字典。

## 常见变体

- **并发场景**:若需在多线程环境下并发读写,使用线程安全版本 `AsyncDisposableConcurrentDictionary<TKey, TValue>`,用法与本页一致。
- **空字典释放**:即便字典中没有值,直接 `await dictionary.DisposeAsync()` 也是安全的,会直接返回。
- **部分值释放失败**:某个值释放失败不会阻断其他值的释放,所有 `IAsyncDisposable` 都会被尝试一次。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `ObjectDisposedException` | 在 `DisposeAsync()` 之后又调用了 `Add`、`Remove` 或索引器 `set` | 释放后停止写入,仅允许只读访问 |
| 值未被释放 | 存入 `null` 值 | `DisposeAsync` 会跳过 `null`;请确保真实资源实例已写入 |
| 释放中断、后续资源未清理 | 旧代码手动抛出了未处理异常 | 始终使用 `DisposalErrorHandler` 兜底,并依赖字典内部的 try/catch 继续迭代 |
| 类型编译报错 | `TValue` 未实现 `IAsyncDisposable` | 确认资源类型实现 `IAsyncDisposable`,例如 `DbConnection`、`HttpClient` 的自定义包装 |

## 验证

- 调用 `await dictionary.DisposeAsync()` 后,`dictionary.IsDisposed` 为 `true`。
- 所有非空值的 `DisposeAsync()` 仅被调用一次(测试用例验证了这一点)。  
  Source: [AsyncDisposableDictionaryTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Tests/Extensions/AsyncDisposableDictionaryTests.cs#L28-L45)
- 释放后再次 `DisposeAsync()` 不抛异常,值也不会被二次释放。

## 背景(可选)

`AsyncDisposableDictionary` 通过把 `_isDisposed` 标记为 `true` 后再遍历 `Values` 来保证:即使在迭代过程中 `DisposeAsync` 被某个值阻塞或抛错,后续值仍可继续被释放。错误处理通过回调委托暴露给调用方,使框架不强制依赖日志系统。
