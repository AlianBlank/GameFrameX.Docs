# ローカライズ Helper をカスタマイズする方法（システム言語検出のオーバーライド）

ローカライズ Helper のカスタマイズは 2 ステップだけです：`LocalizationHelperBase` を継承したクラスを作成して `SystemLanguage` プロパティをオーバーライドし、その後 `LocalizationComponent` パネルで Helper を自分の型に置き換えます。デフォルト実装は `CultureInfo.CurrentCulture` でシステム言語を検出しますが、このプロパティをオーバーライドすれば任意の検出戦略（セーブデータの読み取り、アカウント設定の読み取り、固定言語など）に差し替えられます。

## 前提条件

- `com.gameframex.unity.localization` パッケージがインストール済みであること。
- シーンに `LocalizationComponent` がアタッチされたオブジェクトが既に存在すること。

## 操作手順

### 1. カスタム Helper クラスを作成する

まず基底クラスの定義を見てみましょう——Helper は `MonoBehaviour` であり、実装が必要なのは読み取り専用プロパティ `SystemLanguage` だけです：

```csharp
namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// ローカライズヘルパーの基底クラス。
    /// </summary>
    [Preserve]
    public abstract class LocalizationHelperBase : MonoBehaviour, ILocalizationHelper
    {
        /// <summary>
        /// システム言語を取得する。
        /// </summary>
        [Preserve]
        public abstract string SystemLanguage { get; }
    }
}
```

出典：[LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L37-L48)

デフォルト実装 `DefaultLocalizationHelper` は以下のように記述されており、現在のカルチャ名を取得して `-` を `_` に置き換えます（例：`zh-CN` → `zh_CN`）：

```csharp
using System.Globalization;
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    /// <summary>
    /// デフォルトのローカライズヘルパー。
    /// </summary>
    [Preserve]
    public class DefaultLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public DefaultLocalizationHelper()
        {
        }

        /// <summary>
        /// システム言語を取得する。
        /// </summary>
        [Preserve]
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
    }
}
```

出典：[DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L32-L57)

デフォルト実装の骨格を参考に、独自のクラスを作成します。以下の例ではシステム言語を `zh_CN` に固定しています（構造は `DefaultLocalizationHelper` に倣って書き換えたもので、戻り値は独自の検出ロジックに置き換えられます。`xx_XX` のアンダースコア形式を維持してください）：

```csharp
using UnityEngine.Scripting;

namespace GameFrameX.Localization.Runtime
{
    [Preserve]
    public class MyLocalizationHelper : LocalizationHelperBase
    {
        [Preserve]
        public override string SystemLanguage
        {
            get { return "zh_CN"; } // ここに独自の言語検出を実装する
        }
    }
}
```

### 2. LocalizationComponent にカスタム Helper を設定する

`LocalizationComponent` は Helper を選択するための 2 つのシリアライズフィールドを公開しています：

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";

[SerializeField] private LocalizationHelperBase m_CustomLocalizationHelper = null;
```

出典：[LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

- Inspector の **Localization Helper** ドロップダウンでカスタム型を選択します（パネル内部では `HelperInfo<LocalizationHelperBase>` によって選択可能な Helper が一覧表示されます。詳細は [LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L46) を参照）。
- `m_LocalizationHelperTypeName` は**完全な型名**（名前空間を含む）である必要があります。デフォルト値 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` の書き方を参考にしてください。

### 3. 実行時に Helper が有効になっていることを確認する

コンポーネントは初期化時に `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)` で Helper インスタンスを生成します（[LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L250) を参照）。実行後、`LocalizationComponent` のシステム言語/言語関連プロパティを確認すると、戻り値はオーバーライドしたロジックによるものになっているはずです。

## よくあるバリエーション

- **Unity のシステム言語に基づくマッピング**：`SystemLanguage` の getter 内で、Unity の `Application.systemLanguage` に基づいてプロジェクトで使用する言語コード（例：`zh_CN`、`en_US`）へマッピングします。
- **セーブデータやアカウント設定からの読み取り**：getter 内でプロジェクト独自のセーブデータ/クラウド設定を読み取り、ユーザーが前回選択した言語を返すことで、「初回はシステムに追従、以降はユーザー設定に追従」を実現します。
- **デフォルト値へのフォールバック**：`LocalizationComponent` の `m_DefaultLanguage` はデフォルトで `zh_CN` になっており、ローカライズの読み込みに失敗した場合はデフォルト言語でフォールバックします（[LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L68) を参照）。カスタム Helper と組み合わせることで、未対応の言語でもコンテンツを表示できるようになります。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| Inspector に自分の Helper 型が見つからない | クラスが `LocalizationHelperBase` を継承していない、またはコンパイル範囲に含まれていない | クラスが `public class Xxx : LocalizationHelperBase` と宣言されており、保存してコンパイルが通っていることを確認する |
| 実行時に Helper が null になる | `m_LocalizationHelperTypeName` の記述が誤っている（名前空間の欠落、スペルミス） | 型名は完全名（名前空間を含む）である必要がある。デフォルト値 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper` を参考にする |
| 返された言語が反映されない/辞書にマッチしない | 返される言語コードの形式が正しくない | `xx_XX` のアンダースコア形式を維持する（デフォルト実装は `-` を `_` に置き換える）。`zh-CN`、`Chinese` などの形式を返さない |
| カスタム Helper クラスがストリッピングされる（IL2CPP/リンカーによる除去） | 保持属性が付与されていない | クラスとプロパティに `[Preserve]` を付与する（デフォルト実装での使い方を参考にする） |
| 言語切り替え後に UI が更新されない | Helper の戻り値を直接変更してもイベントが発火しない | `LocalizationComponent.Language` の setter で言語を設定すると、言語変更イベント（Before/Change/After）が発火する |

## 背景

`LocalizationComponent` は初期化時に `Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper)` によって「型名 + オプションのカスタムインスタンス」という 2 つの方法で Helper を生成します。そのため、カスタム Helper は Inspector パネルから選択する（型名文字列を書き込む）ことも、参照を直接ドラッグすることもできます。言語の取得は `SystemLanguage` プロパティを経由し、言語の設定と永続化はコンポーネントの `Language` / `DefaultLanguage` プロパティが担います（`SettingComponent` と連携して保存）。切り替え時には `LocalizationLanguageChangeBeforeEventArgs`、`LocalizationLanguageChangeEventArgs`、`LocalizationLanguageChangeAfterEventArgs` の 3 つのイベントが順に発火します。

ローカライズコンポーネント全体の使用方法については、本パッケージの『LocalizationComponent』関連ドキュメントを参照してください。
