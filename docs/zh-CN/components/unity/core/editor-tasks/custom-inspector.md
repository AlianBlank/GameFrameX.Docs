# 使用自定义 Inspector 监控池

在 Unity 编辑器运行模式下，通过 `ObjectPoolComponentInspector` 与 `ReferencePoolComponentInspector` 两个自定义 Inspector 面板，实时查看对象池与引用池的容量、占用、命中率等指标，并能把数据导出为 CSV 文件。

## 前置条件

1. 场景中已挂载 `ObjectPoolComponent` 或 `ReferencePoolComponent`（一般在 `GameFramework` 预制体上）。
2. Unity 必须处于 **Play Mode**，否则 Inspector 仅显示空信息提示 `Available during runtime only.`。
3. 组件必须挂在层级（Hierarchy）中的实例上，预制体资产上不会显示池数据。

## 操作步骤

### 1. 打开对象池（ObjectPool）监控面板

在 Hierarchy 中选中带有 `ObjectPoolComponent` 的 GameObject，Inspector 会展开以下内容：

- `Object Pool Count`：当前已注册的对象池数量。
- 每个对象池以折叠项（`Foldout`）展示，标题是 `objectPool.FullName`。

展开后可以看到该池的实时属性：

| 字段 | 含义 |
|------|------|
| `Name` | 池名称 |
| `Type` | 池内对象类型全名 |
| `Auto Release Interval` | 自动释放间隔 |
| `Capacity` | 容量上限 |
| `Used Count` | 已使用对象数 |
| `Can Release Count` | 可立即释放的对象数 |
| `Expire Time` | 过期时间 |
| `Priority` | 优先级 |

随后是对象实例列表（`GetAllObjectInfos()`），每行显示 `Name / Locked / Count 或 InUse / CustomCanReleaseFlag / Priority / LastUseTime`。当 `AllowMultiSpawn` 为 true 时，`In Use` 列被替换为 `Count`。

底部提供三个动作按钮：

- `Release`：调用 `objectPool.Release()`，立刻释放所有可释放对象。
- `Release All Unused`：调用 `objectPool.ReleaseAllUnused()`。
- `Export CSV Data`：把当前池对象写入 CSV，文件默认名 `Object Pool Data - {Name}.csv`。

```csharp
ObjectPoolComponent t = (ObjectPoolComponent)target;
ObjectPoolBase[] objectPools = t.GetAllObjectPools(true);
foreach (ObjectPoolBase objectPool in objectPools)
{
    DrawObjectPool(objectPool);
}
```

### 2. 打开引用池（ReferencePool）监控面板

选中带有 `ReferencePoolComponent` 的 GameObject，运行时会展示：

- `Enable Strict Check` 开关：可即时切换严格检查模式。
- `Reference Pool Count`：由 `ReferencePool.Count` 提供。
- `Show Full Class Name` 开关：切换列表按 `FullName` 还是 `Name` 排序。

池条目按程序集（`Assembly.GetName().Name`）分组，每组一个折叠项；展开后表格列依次为 `Unused / Using / Acquire / Release / Add / Remove`。

```csharp
ReferencePoolInfo[] referencePoolInfos = ReferencePool.GetAllReferencePoolInfos();
foreach (ReferencePoolInfo info in referencePoolInfos)
{
    string assemblyName = info.Type.Assembly.GetName().Name;
    // 按程序集分组后展示
}
```

### 3. 导出 CSV 并验证

1. 在 Inspector 中点击 `Export CSV Data`。
2. 弹出 `EditorUtility.SaveFilePanel`，选择保存路径。
3. 写入成功后 Console 输出 `Export object pool CSV data to '{0}' success.`；失败时输出 `Export ... failure, exception is '{1}'.`，并以 `Debug.LogError` 形式记录。

```csharp
File.WriteAllLines(exportFileName, data, Encoding.UTF8);
Debug.Log(Utility.Text.Format("Export object pool CSV data to '{0}' success.", exportFileName));
```

## 常见变体

- **多实例对象池（`AllowMultiSpawn = true`）**：行表头切换为 `Locked\tCount\tFlag\tPriority\tLast Use Time`；CSV 中 `IsInUse` 列被 `SpawnCount` 取代。
- **空池状态**：当 `GetAllObjectInfos().Length == 0`，Inspector 显示 `Object Pool is Empty ...`，不会出现 `Release / Export` 按钮。
- **非运行态**：对象池 Inspector 直接返回 `Available during runtime only.`；引用池 Inspector 仅显示 `Enable Strict Check` 序列化字段。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| Inspector 只显示 `Available during runtime only.` | 未进入 Play Mode | 点击 Unity 的 `Play` 按钮进入运行模式 |
| 选择预制体资产看不到池数据 | `IsPrefabInHierarchy` 检查失败 | 把组件放到 Hierarchy 中的实例上 |
| 点击 `Export CSV Data` 报 `failure, exception is ...` | 路径无写权限或被占用 | 换一个有写权限的目录后重试 |
| 引用池面板只显示 `m_EnableStrictCheck` 字段 | 不在运行态 | 进入 Play Mode 后会自动展开 |

## 背景（可选）

两个 Inspector 都继承自 `GameFrameworkInspector` / `ComponentTypeComponentInspector`，通过 `[CustomEditor(typeof(...))]` 绑定到对应的 `BaseComponent`。`OnInspectorGUI` 末尾统一调用 `Repaint()`，保证池数据在运行时持续刷新。
