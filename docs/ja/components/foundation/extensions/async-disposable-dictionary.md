# 非同期破棄可能辞書の使用方法

`AsyncDisposableDictionary<TKey, TValue>` は、値に `IAsyncDisposable` の実装を要求する辞書コンテナであり、`NullableDictionary<TKey, TValue>` を継承しています。辞書自体が `DisposeAsync()` で破棄されると、自動的にすべての非 null 値を非同期で解放します。データベース接続、ネットワークセッション、長時間接続クライアントなど、非同期クリーンアップが必要なリソース群の管理に適しています。

## 前提条件

- `TValue` は `IAsyncDisposable` を実装している必要があります。
- 名前空間 `GameFrameX.Foundation.Extensions` を参照してください。
- 対象 .NET バージョンは `IAsyncDisposable` をサポートしている必要があります(.NET Standard 2.1+ / .NET 5+)。

## 操作手順

1. **辞書インスタンスの作成と値の書き込み**

   コレクション初期化子またはインデクサーを使用して、リソースオブジェクトを直接書き込みます:

   ```csharp
   using GameFrameX.Foundation.Extensions;

   var dictionary = new AsyncDisposableDictionary<string, MyAsyncResource>
   {
       ["conn-1"] = new MyAsyncResource(),
       ["conn-2"] = new MyAsyncResource()
   };
   ```

   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L6-L37)

2. **(オプション)破棄エラーハンドラーの設定**

   ある値の `DisposeAsync()` が例外をスローした場合、辞書は `DisposalErrorHandler` を呼び出します。記録やフォールバックの処理は呼び出し側で決定します:

   ```csharp
   dictionary.DisposalErrorHandler = (value, ex) =>
   {
       Console.WriteLine($"释放 {value} 失败: {ex.Message}");
   };
   ```

   ハンドラー自体がスローした例外は吸収され、残りの値の解放が継続することが保証されます。  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L92-L102)

3. **`DisposeAsync()` を呼び出してすべての値を非同期解放**

   ```csharp
   await dictionary.DisposeAsync();
   ```

   解放処理は冪等です。`DisposeAsync()` を繰り返し呼び出しても、値は再解放されません。状態の確認には `dictionary.IsDisposed` を使用できます。  
   Source: [AsyncDisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Extensions/AsyncDisposableDictionary.cs#L71-L90)

4. **解放後は書き込みや変更を行わない**

   解放後にインデクサーの `set`、`Add`、`Remove` を呼び出すと `ObjectDisposedException` がスローされます。読み取り(get)は基底クラスの辞書から継承しているため、引き続き使用可能です。

## よくあるバリエーション

- **並行シナリオ**:マルチスレッド環境で並行読み書きが必要な場合は、スレッドセーフ版の `AsyncDisposableConcurrentDictionary<TKey, TValue>` を使用してください。使用法は本ページと同じです。
- **空の辞書の解放**:辞書に値がなくても、`await dictionary.DisposeAsync()` を直接呼び出すのは安全で、そのまま戻ります。
- **一部の値の解放が失敗**:ある値の解放が失敗しても他の値の解放は中断されず、すべての `IAsyncDisposable` が一度ずつ解放を試みられます。

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| `ObjectDisposedException` | `DisposeAsync()` の後に `Add`、`Remove`、またはインデクサーの `set` を呼び出した | 解放後は書き込みを停止し、読み取り専用アクセスのみ許可する |
| 値が解放されていない | `null` 値が格納されている | `DisposeAsync` は `null` をスキップします。実際の リソースインスタンスが書き込まれていることを確認してください |
| 解放が中断され、後続のリソースが解放されていない | 旧コードが処理されていない例外を手動でスローしている | 常に `DisposalErrorHandler` でフォールバックし、辞書内部の try/catch に依存して反復を継続する |
| 型のコンパイルエラー | `TValue` が `IAsyncDisposable` を実装していない | リソース型が `IAsyncDisposable` を実装していることを確認してください(例: `DbConnection`、`HttpClient` のカスタムラッパー) |

## 検証

- `await dictionary.DisposeAsync()` を呼び出した後、`dictionary.IsDisposed` は `true` になります。
- すべての非 null 値の `DisposeAsync()` は一度だけ呼び出されます(テストケースで検証済み)。  
  Source: [AsyncDisposableDictionaryTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Tests/Extensions/AsyncDisposableDictionaryTests.cs#L28-L45)
- 解放後に再度 `DisposeAsync()` を呼び出しても例外はスローされず、値も再解放されません。

## 背景(オプション)

`AsyncDisposableDictionary` は、`_isDisposed` を `true` に設定した後に `Values` を反復することで、反復処理中にいずれかの `DisposeAsync` がブロックされたりエラーをスローしたりしても、後続の値の解放を続行できることが保証されています。エラー処理はコールバックデリゲートを通じて呼び出し側に公開されるため、フレームワークはログシステムへの依存を強制しません。
