# How to Use the Event System for Module Decoupling

Through the event system, modules do not need to reference each other directly. Simply define events, publish events, and have independent listeners handle them to achieve loose coupling. This page describes how to define events, write listeners, and dispatch events.

## Prerequisites

- Familiarity with C# generics and asynchronous programming (`async`/`await`).
- The project references `GameFrameX.Core.Abstractions.Events` and `GameFrameX.Core.Events`.
- Understanding of the basic concepts of Actor and component agents (see the Actor module documentation).

## Core Concepts Quick Reference

| Name | Type | Purpose |
|------|----------|------|
| `GameEventArgs` | `GameFrameX.Core.Abstractions.Events.GameEventArgs` | Base class for event arguments; all custom event arguments must inherit from it |
| `IEventListener` | `GameFrameX.Core.Abstractions.Events.IEventListener` | Listener interface that defines the `HandleEvent` method |
| `EventListener<T>` | `GameFrameX.Core.Events.EventListener<T>` | Abstract listener base class that can handle events for a specific component agent (`T : IComponentAgent`) |
| `EventDispatcher.Dispatch` | `GameFrameX.Core.Events.EventDispatcher` | Static entry point used to publish events to a specified Actor or global listeners |

## Operation Steps

### 1. Define Event Arguments

Create a class that inherits from `GameEventArgs` to carry event data. `GameEventArgs` itself only inherits `System.EventArgs` and contains no fields.

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class PlayerLoginEventArgs : GameEventArgs
{
    public long PlayerId { get; }
    public DateTime LoginTime { get; }

    public PlayerLoginEventArgs(long playerId)
    {
        PlayerId = playerId;
        LoginTime = DateTime.UtcNow;
    }
}
```

### 2. Implement the Listener

There are two ways: directly implement `IEventListener`, or inherit the generic base class `EventListener<T>(T : IComponentAgent)`.

**Approach A: Inherit `EventListener<T>` (recommended, when component agent access is needed)**

```csharp
using GameFrameX.Core.Events;

public sealed class PlayerLoginListener : EventListener<PlayerComponentAgent>
{
    protected override async Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        if (gameEventArgs is not PlayerLoginEventArgs args) return;
        // Access component state through the component agent
        var player = agent.GetPlayer();
        await player.OnLogin(args.LoginTime);
    }
}
```

`EventListener<T>` automatically converts the incoming `IComponentAgent` to the generic `T`, and internally invokes your implemented `HandleEvent(T agent, GameEventArgs)`.

**Approach B: Directly implement `IEventListener` (when component agent access is not needed)**

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class GlobalStartupListener : IEventListener
{
    public Type AgentType => null;
    public Task HandleEvent(IComponentAgent agent, GameEventArgs gameEventArgs)
        => HandleEvent(gameEventArgs);

    public Task HandleEvent(GameEventArgs gameEventArgs)
    {
        // Global event handling logic
        return Task.CompletedTask;
    }
}
```

Listeners are managed by the framework as **singletons**, and implementations must be thread-safe.

### 3. Register the Listener

Listeners are automatically registered by the framework through scanning the `GameFrameX.Hotfix` assembly. They are typically placed under the `GameFrameX.Hotfix` project to be auto-discovered. Naming must follow the project architecture rules (using `EventListener` as the suffix; specific constraints are enforced by `GameFrameX.Architecture.Analyzers`).

### 4. Dispatch the Event

Call the static class `EventDispatcher.Dispatch`, passing in the target ActorId, event ID, and event arguments. If the Actor corresponding to actorId does not exist, the event is automatically dispatched to **global listeners**.

```csharp
using GameFrameX.Core.Events;

// Dispatch the event in the context of the Actor corresponding to actorId
EventDispatcher.Dispatch(playerActorId, EventId.PlayerLogin, new PlayerLoginEventArgs(playerId));
```

Event IDs use `int` constants, typically defined centrally in `GameFrameX.Apps/Common/Event/EventId.cs`.

## Common Variants

| Scenario | Approach |
|------|------|
| Player-level events (need to access player components) | Inherit `EventListener<PlayerComponentAgent>`, override `HandleEvent(T, GameEventArgs)` |
| Global/server-level events | Implement `IEventListener`, use the agent-less version `HandleEvent(GameEventArgs)` |
| Listen to events without arguments | Event arguments inherit `GameEventArgs`, but carry no fields |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `NoListenersFound` warning is shown | No listeners are registered for this event ID | Confirm that the listener class is in the `GameFrameX.Hotfix` assembly and the naming complies with analyzer rules |
| `HandleEvent` receives event arguments of another type | The event was incorrectly dispatched to another event ID | Use centrally defined `EventId` constants; avoid hardcoded magic numbers |
| Concurrent issues caused by shared state across multiple listener instances | The listener is a singleton but its internal state is not thread-safe | Change mutable state to local variables or add locking; avoid storing request-level data in listeners |

## Background (Optional)

Event dispatch within the Actor context is executed **serially** (`foreach` + `await`), ensuring that events under the same Actor will not execute concurrently; when the Actor does not exist, global listeners are dispatched on a new thread. Each listener exception is caught and logged by `LogHelper.Error`, and will not interrupt the handling of other listeners. See [EventDispatcher.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Events/EventDispatcher.cs#L50-L135) for details.
