# 如何自訂 UI Form Helper

透過繼承 `UIFormHelperBase` 並實作 `IUIFormHelper` 的三個方法，你可以接管介面資源的實例化、`IUIForm` 業務物件的建立以及介面釋放流程；再讓 `UIComponent` 透過類別名稱字串或預製物件參考使用你的實作即可生效。

## 前置條件

- 已熟悉 GameFrameX UI 子系統的基本流程(關於整體架構，見相關說明)。
- 專案已安裝 `com.gameframex.unity.ui` 套件，且場景中掛有 `UIComponent`。

## 操作步驟

1. **實作 `IUIFormHelper` 介面或繼承 `UIFormHelperBase`。**

   `UIFormHelperBase` 已經幫你處理了 `MonoBehaviour` 生命週期與 `Scripting.Preserve]` 標記，你只需要繼承它並實作三個抽象方法。

   介面定義位於 [IUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIFormHelper.cs#L40-L76),抽象基底類別位於 [UIFormHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)。

   ```csharp
   using System;
   using GameFrameX.UI.Runtime;
   using UnityEngine;

   public class MyUIFormHelper : UIFormHelperBase
   {
       public override object InstantiateUIForm(object uiFormAsset)
       {
           // 根據你使用的 UI 方案(FairyGUI / UGUI / 其他)實例化介面資源
           var prefab = uiFormAsset as GameObject;
           if (prefab == null) return null;
           return Instantiate(prefab);
       }

       public override IUIForm CreateUIForm(object uiFormInstance, Type uiFormType, object userData)
       {
           // 將 uiFormInstance 綁定到 uiFormType 對應的業務邏輯腳本,回傳 IUIForm
           var go = uiFormInstance as GameObject;
           var form = go.GetComponent(uiFormType) as IUIForm;
           if (form != null)
           {
               (form as Component).gameObject.SetActive(true);
           }
           return form;
       }

       public override void ReleaseUIForm(object uiFormAsset, object uiFormInstance, object assetHandle,
                                          string uiFormAssetPath, string uiFormAssetName)
       {
           // 銷毀實例並視需要歸還資源控制代碼
           var go = uiFormInstance as GameObject;
           if (go != null) Destroy(go);
       }
   }
   ```
   Source: [Runtime/UIFormHelperBase.cs#L42-L81](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIFormHelperBase.cs#L42-L81)

2. **讓 `UIComponent` 使用你的 Helper。**

   `UIComponent` 同時支援「類型名稱反射建立」和「直接拖入自訂 Helper 預製物件」兩種方式。選擇其中一種：

   - **方式 A —— 透過類型名稱**：把 `UIComponent` Inspector 上的 `UI Form Helper Type Name` 改為你的完整類別名稱(含命名空間)。預設值為 `GameFrameX.UI.FairyGUI.Runtime.FairyGUIFormHelper`。
   - **方式 B —— 透過預製物件**：將你的 `MyUIFormHelper` 掛到一個 GameObject 上做成預製物件，拖曳到 `UIComponent` 的 `Custom UI Form Helper` 欄位。執行時 `Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper)` 會優先使用該參考。

   ```csharp
   // Runtime/UIComponent.cs 中讀取自訂 Helper 的邏輯
   UIFormHelperBase uiFormHelper = Helper.CreateHelper(m_UIFormHelperTypeName, m_CustomUIFormHelper);
   if (uiFormHelper == null)
   {
       Log.Error("Can not create UI form helper.");
       return;
   }
   uiFormHelper.name = "UIFormHelper";
   transform = uiFormHelper.transform;
   transform.SetParent(this.transform);
   transform.localScale = Vector3.one;
   m_UIManager.SetUIFormHelper(uiFormHelper);
   ```
   Source: [Runtime/UIComponent.cs#L526-L538](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L526-L538)

3. **確保類型名稱的命名空間與 ComponentType 一致。**

   啟動時 `UIComponent` 會進行驗證:`m_UIFormHelperTypeName` 必須以目前 UI 系統對應的命名空間開頭，否則會在主控台報錯 `UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.` 並停用該元件。

   ```csharp
   if (!m_UIFormHelperTypeName.StartsWithFast(namespaceName))
   {
       Debug.LogError("UI组件的 UI Form Helper 设置错误。请设置和 ComponentType 类型 一致.");
       enabled = false;
       return;
   }
   ```
   Source: [Runtime/UIComponent.cs#L437-L442](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L437-L442)

4. **執行時手動替換 Helper(可選)。**

   如果你想在遊戲執行中切換 Helper,直接呼叫 `BaseUIManager.SetUIFormHelper(IUIFormHelper)`:

   ```csharp
   m_UIManager.SetUIFormHelper(new MyUIFormHelper());
   ```
   Source: [Runtime/BaseUIManager.cs#L313-L320](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L313-L320)

## 常見變體

| 場景 | 做法 |
|------|------|
| 接入 FairyGUI | 讓 Helper 內部將 `uiFormAsset` 解析為 FairyGUI 元件並回傳 `GComponent`,`CreateUIForm` 中回傳包裝該 `GComponent` 的 `IUIForm` 實作。 |
| 接入 UGUI | 直接以 `GameObject` 作為通用載體，在 `InstantiateUIForm` 內呼叫 `Object.Instantiate`,`CreateUIForm` 內透過 `GetComponent(uiFormType)` 綁定邏輯腳本。 |
| 在執行時熱替換 | 透過 `BaseUIManager.SetUIFormHelper` 替換為新的 Helper 實例，但需自行管理舊實例的銷毀。 |

## 常見錯誤

| 錯誤 | 原因 | 修復 |
|------|------|------|
| 啟動後主控台報錯 `UI组件的 UI Form Helper 设置错误。` | `UI Form Helper Type Name` 的命名空間與目前 `ComponentType` 不相符。 | 將命名空間改為與所選 UI 系統一致(如 FairyGUI 用 `GameFrameX.UI.FairyGUI.Runtime`、`UGUI` 用 `GameFrameX.UI.UGUI.Runtime`)或拖入正確的預製物件。 |
| 開啟介面時報 `Can not create UI form helper.` | 類型名稱拼字錯誤或自訂預製物件未掛腳本。 | 檢查 `m_UIFormHelperTypeName` 的完整類別名稱，或確認 `m_CustomUIFormHelper` 預製物件上掛的是 `UIFormHelperBase` 子類別。 |
| `SetUIFormHelper(null)` 擲出例外 | `BaseUIManager` 內部對傳入參數做了非空驗證。 | 一律傳入非空實例，需清空時改為預設實作。 |

## 背景(可選)

`IUIFormHelper` 把「資源怎麼變成 GameObject / GComponent」和「怎麼把它與邏輯腳本綁定」這兩件事從 UI 管理器中抽離出來，使同一套 `BaseUIManager` 能適配不同 UI 方案。`UIComponent` 在 `Start` 中按「類型名稱 → 自訂預製物件」的優先順序建立 Helper,再呼叫 `BaseUIManager.SetUIFormHelper` 寫入框架。
