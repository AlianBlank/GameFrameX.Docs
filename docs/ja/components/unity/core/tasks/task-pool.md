# 非同期タスクのスケジューリング

`TaskPool<T>` は「タスクエージェント + 優先度キュー」によって非同期タスクを管理します。複数の `ITaskAgent<T>` をプールに登録し、`TaskBase` 派生タスクを投入すると、プールは毎フレームの `Update` で優先度に従ってタスクを空いているエージェントにディスパッチして実行します。このページでは、非同期タスクの組み込みとスケジューリング方法を説明します。

## 前提条件

- `GameFrameX.Runtime` アセンブリを参照していること(タスクプールは [Runtime/Base/TaskPool](/Runtime/Base/TaskPool/TaskPool.cs#L44-L64) 名前空間 `GameFrameX.Runtime` にあります)。
- カスタムタスクは `TaskBase` を継承し、カスタムエージェントは `ITaskAgent<T>` を実装します。
- タスクオブジェクトは `ReferencePool.Acquire<T>()` で取得することを推奨します。プール解放後に自動回収されます([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L11-L21))。

## 操作手順

1. **タスク型を定義する**。`TaskBase` を継承し、最低限 `Description` プロパティをオーバーライドします。タスクは `Initialize(serializeId, tag, priority, userData)` で優先度とカスタムデータを設定します。

   ```csharp
   using GameFrameX.Runtime;

   public class LoadAssetTask : TaskBase
   {
       public string AssetName { get; private set; }

       public override string Description => $"LoadAsset:{AssetName}";

       public void Init(string assetName)
       {
           AssetName = assetName;
           Initialize(0, assetName, 0, null);
       }
   }
   ```

   Source: [Runtime/Base/TaskPool/TaskBase.cs](/Runtime/Base/TaskPool/TaskBase.cs)

2. **タスクエージェントを実装する**。`ITaskAgent<T>` の `Initialize / Update / Shutdown / Start / Reset` を実装し、`Start` で `StartTaskStatus.CanResume / CanNotResume` を返します。完了は `Task.Done = true` でマークします([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L23-L62))。

   ```csharp
   public class LoadAssetAgent : ITaskAgent<LoadAssetTask>
   {
       public LoadAssetTask Task { get; private set; }
       public bool IsInitialized { get; private set; }
       public bool IsShutdown { get; private set; }

       public void Initialize() { IsInitialized = true; }
       public void Update(float e, float re) { /* 実際のロード完了後に Task.Done = true を設定 */ }
       public void Shutdown() { IsShutdown = true; }

       public StartTaskStatus Start(LoadAssetTask task)
       {
           Task = task;
           return StartTaskStatus.CanResume; // 同期完了の場合は CanNotResume を返す
       }

       public void Reset() { Task = null; }
   }
   ```

   Source: [Runtime/Base/TaskPool/ITaskAgent.cs](/Runtime/Base/TaskPool/ITaskAgent.cs)

3. **タスクプールを作成しエージェントを登録する**。`TaskPool<T>` をインスタンス化し、`AddAgent` を呼び出して 1 つ以上のエージェントを登録します。エージェント数がそのまま最大並行タスク数になります。

   ```csharp
   var taskPool = new TaskPool<LoadAssetTask>();
   taskPool.AddAgent(new LoadAssetAgent());
   taskPool.AddAgent(new LoadAssetAgent()); // 並行数 2
   ```

   Source: [Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L58-L64)

4. **タスクを投入する**。`ReferencePool.Acquire` でタスクオブジェクトを取得し、`Initialize` 後に `AddTask` を呼び出します。タスクは `priority` の降順で並べられます:値が大きいほど先に実行されます([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L127-L145))。

   ```csharp
   var task = ReferencePool.Acquire<LoadAssetTask>();
   task.Init("Config/battle.json");
   taskPool.AddTask(task);

   var urgent = ReferencePool.Acquire<LoadAssetTask>();
   urgent.Initialize(1, "Player/Avatar", 10, null); // priority=10 先に実行
   taskPool.AddTask(urgent);
   ```

5. **毎フレーム `Update` を駆動する**。ゲームのメインループで `taskPool.Update(elapseSeconds, realElapseSeconds)` を呼び出します。プールは自動的に:① すべての `WorkingAgent` を進行させ、② 待機キューから最も優先度の高いタスクを空いているエージェントにディスパッチします([Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L136-L145))。

   ```csharp
   void Update()
   {
       taskPool.Update(Time.deltaTime, Time.unscaledDeltaTime);
   }
   ```

6. **一時停止とクリーンアップ**。スケジューリングを凍結する場合は `taskPool.Paused = true` を設定します。`Update` は即座に return し、いかなるタスク処理もトリガーしません([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L185-L196))。不要になったら `RemoveAllTasks()` + `Shutdown()` を呼び出し、`ReferencePool.ClearAll()` でタスクオブジェクトを解放します。

## よくあるバリエーション

| シナリオ | 方法 |
|------|------|
| 非同期で時間のかかるタスク(アセットロード、ネットワーク) | `Start` で `CanResume` を返し、`Update` で進捗をポーリング、完了時に `Task.Done = true` を設定 |
| 同期で完了できるタスク | `Start` で `CanNotResume` を返す。プールは次のフレームでエージェントを再ディスパッチ可能としてマークします |
| 並行上限を制御する | `ITaskAgent<T>` を N 個だけ登録する。超過したタスクは `WaitingTasks` キューに残ります |
| タスク状態を照会する | `GetAllTaskInfos()` で `TaskInfo[]` を取得する(`Priority`、`Status`、`Description` を含む) |
| 指定タスクをキャンセルする | `RemoveTask(serializeId, tag)` でヒットした場合、オブジェクトを `ReferencePool` に返却します |

## よくあるエラー

| エラー | 説明 | 回避策 |
|------|------|------|
| `AddAgent(null)` | `GameFrameworkException` がスローされます([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L99-L101)) | 登録前に null チェックを行う |
| エージェント数が少なすぎる | 待機キューが積み上がり、`WaitingTaskCount` が 0 より大きいままになる | 想定並行数に応じてエージェントを登録する |
| `Update` の呼び出し忘れ | タスクが永遠に開始されない | `taskPool.Update` を MonoBehaviour のメインループまたはフレームワークの `GameFramework` ディスパッチに接続する |
| エージェントの `Start` が `CanNotResume` を返さず、`Task.Done` も設定しない | エージェントが永久占有され、空きエージェント数が増えない | 非同期コールバックまたは `Update` で明示的に `Done = true` を設定する |
| `new T()` でタスクを直接生成する | タスクが参照プールを通らず、回収・再利用できない | `ReferencePool.Acquire<T>()` を使用する |

## 背景(任意)

タスクプールは「タスク = データ / エージェント = 実行者」を分離したパターンです。プール自体はディスパッチと回収のみ担当し、具体的な実行は `ITaskAgent<T>` に委ねます。優先度は `m_WaitingTasks` リンクリストによって `priority` の降順で維持され、デバッグ時には現在の最高優先度のタスクが確実に取り出されます。`Paused` はゲームの一時停止やシーン切り替えなど、バックグラウンドタスクを凍結する必要があるシナリオで使用されます。

タスクプールと他のサブシステムの連携については、《ReferencePool リファレンス》を参照してください。
