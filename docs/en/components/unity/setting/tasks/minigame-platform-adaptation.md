# Mini Game Platform Adaptation Configuration

`GameFrameX.Setting` adapts to Douyin, WeChat, Kuaishou, and Alipay mini games through `PlayerPrefsSettingHelper` + platform-specific `ISettingStorageBackend`. No manual switching is required — the corresponding SDK is automatically selected by platform at runtime.

## Prerequisites

| Platform | Required SDK Package | Backend Implementation |
|------|-------------|---------|
| Douyin Mini Game | `TTSDK`(TTStorage) | `DouYinMiniGameSettingStorage` |
| WeChat Mini Game | `WeChatWASM`(WXSDKManagerHandler) | `WeChatMiniGameSettingStorage` |
| Kuaishou Mini Game | KS SDK | `KuaiShouMiniGameSettingStorage` |
| Alipay Mini Game | Alipay SDK | `AlipayMiniGameSettingStorage` |

Each platform's SDK needs to be obtained from the corresponding mini game developer tools / Unity conversion plugin and placed in the project's `Assets/` directory. Otherwise, compilation will fail with errors indicating that types such as `WeChatWASM.WXSDKManagerHandler` and `TTSDK.TTStorage` cannot be found.

## Operation Steps

1. Install the `com.gameframex.unity.setting` package in Unity (version ≥ 1.5.2).

   Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/package.json#L1-L20)

2. Attach a `SettingComponent` to a `GameObject` in the scene. Keep the `Setting Helper Type Name` field as the default `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`.

3. Install the target mini game platform SDK (using WeChat Mini Game as an example):

   ```text
   Publish the project as a WeChat Mini Game project through the Unity WeChat Mini Game conversion plugin,
   ensuring that the WeChatWASM assembly under Assets/WX-WASM-SDK/ is available.
   ```

4. Build and publish to the target platform. The framework automatically registers the platform backend during the `SubsystemRegistration` phase, no adaptation code is required:

   ```csharp
   [UnityEngine.RuntimeInitializeOnLoadMethod(UnityEngine.RuntimeInitializeLoadType.SubsystemRegistration)]
   private static void Register()
   {
       SettingStorageBackendFactory.RegisterMiniGameBackend(() => new WeChatMiniGameSettingStorage());
   }
   ```

   Source: [WeChatMiniGameSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/MiniGame/WeChat/WeChatMiniGameSettingStorage.cs#L5-L9)

5. Read and write settings just like a regular Unity project — the data will be written to the corresponding platform's native storage:

   ```csharp
   SettingComponent setting = ...;
   setting.SetString("PlayerName", "PlayerOne");
   setting.SetFloat("Volume", 0.8f);
   setting.Save();
   ```

## Platform Storage Mapping

| Backend | Standard Unity | Douyin | WeChat | Kuaishou | Alipay |
|------|:-:|:-:|:-:|:-:|:-:|
| PlayerPrefsSettingHelper(Default) | PlayerPrefs | TTStorage | WX SDK | KS SDK | Alipay SDK |
| DefaultSettingHelper(Optional) | File I/O | File I/O | File I/O | File I/O | File I/O |

In the mini game environment, `PlayerPrefsSettingHelper` automatically bridges to that platform's native KV storage. If `DefaultSettingHelper` is used instead, all platforms will use `Application.persistentDataPath` file storage.

### Forcing File Storage

If the mini game platform SDK does not take effect on certain sub-platforms (such as the PC Mini Game debugger), you can change `Setting Helper Type Name` to `GameFrameX.Setting.Runtime.DefaultSettingHelper`, and all reads and writes will go through file I/O.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Compilation reports `WeChatWASM.WXSDKManagerHandler` does not exist | WeChat Mini Game SDK is not installed | Integrate the SDK through the Unity WeChat Mini Game conversion plugin |
| Compilation reports `TTSDK.TTStorage` does not exist | Douyin SDK is not installed | Install the Douyin Mini Game Unity conversion plugin |
| Data loss or unable to read after restart | `DefaultSettingHelper` is used, and the mini game platform file system has been cleaned up | Switch back to `PlayerPrefsSettingHelper` so that data is written to the platform's native KV |
| `setting.Save()` returns false | Platform storage write failed (quota full, missing permissions) | Check the mini game backend storage quota and user authorization |

## Verification

1. Run `setting.SetString("MiniGameTest", "ok"); setting.Save();` in the editor or the target platform build artifact.
2. Exit and restart, then call `setting.GetString("MiniGameTest", "miss")` — it should return `"ok"`.
3. The corresponding key can be seen in the "Local Storage" panel of the mini game developer tools, indicating that the backend is in effect.

## Background (Optional)

`PlayerPrefsSettingHelper` obtains the current platform's `ISettingStorageBackend` through `SettingStorageBackendFactory`. Each platform backend registers itself during the `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` phase, and an instance is selected based on platform macros / compile symbols on the first call. By design, "reading/writing KV" is decoupled from "platform SDK calls". Adding a new platform only requires implementing `ISettingStorageBackend` and registering it.
