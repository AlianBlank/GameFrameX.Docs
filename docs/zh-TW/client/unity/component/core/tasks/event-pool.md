# 訂閱與分發事件

透過事件池 `EventPool<T>` 可以讓任意模組以「字串 ID + 事件參數」的形式訂閱和分發事件,既能在主執行緒排隊觸發(`Fire`),也支援立即同步觸發(`FireNow`)。

## 前置條件

- 自訂事件參數必須繼承 `BaseEventArgs`,並實作唯一的字串 `Id`(用於區分事件類型)。
- 透過 `EventPool` 模組取得或建立一個 `EventPool<T>` 實例,本教學假設你已經能拿到 `EventPool<MyEventArgs>`。
- 呼叫方需保證在遊戲迴圈中觸發 `EventPool<T>.Update(elapseSeconds, realElapseSeconds)`,否則 `Fire` 佇列裡的事件不會分發。

## 操作步驟

1. 定義事件參數類別,繼承 `BaseEventArgs` 並給出唯一的 `Id`。

   ```csharp
   public class PlayerHpChangedEventArgs : BaseEventArgs
   {
       public string PlayerId { get; set; }
       public int NewHp { get; set; }

       public override string Id => "PlayerHpChanged";
   }
   ```

   Source: [BaseEventArgs.cs](/Runtime/Base/EventPool/BaseEventArgs.cs#L43-L54)

2. 訂閱事件。在模組初始化時呼叫 `Subscribe`,把字串事件 ID 和 `EventHandler<T>` 回呼註冊到事件池中。

   ```csharp
   eventPool.Subscribe("PlayerHpChanged", OnPlayerHpChanged);

   void OnPlayerHpChanged(object sender, PlayerHpChangedEventArgs e)
   {
       Debug.Log($"{e.PlayerId} HP -> {e.NewHp}");
   }
   ```

   `EventHandler<T>` 的簽章來自 `EventPool<T>` 的型別參數。

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

3. 分發事件。在主執行緒呼叫 `Fire` 即可把事件加入佇列,事件會在下次 `Update` 時回呼到所有訂閱者,跨執行緒 `Fire` 也安全。

   ```csharp
   var args = ReferencePool.Acquire<PlayerHpChangedEventArgs>();
   args.PlayerId = "p_001";
   args.NewHp = 80;
   eventPool.Fire(this, args);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L304-L314)

4. 驅動事件池。每幀驅動 `Update` 才會消費 `Fire` 排隊的節點;節點處理完會透過 `ReferencePool.Release` 歸還。

   ```csharp
   void Update()
   {
       eventPool.Update(0f, Time.deltaTime);
   }
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L113-L121)

5. 在合適的時機取消訂閱,防止物件已銷毀仍被事件池持有回呼。

   ```csharp
   eventPool.Unsubscribe("PlayerHpChanged", OnPlayerHpChanged);
   ```

   Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L245-L281)

## 常見變體

- **立即同步分發**:在主執行緒且不需要排隊時,可呼叫 `FireNow`,事件會在當前呼叫堆疊立刻派發到所有訂閱者,但不是執行緒安全的。

  ```csharp
  eventPool.FireNow(this, args);
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L325-L336)

- **設定預設處理器**:透過 `SetDefaultHandler` 註冊兜底回呼,當某事件 ID 沒有訂閱者時會被呼叫。

  ```csharp
  eventPool.SetDefaultHandler((sender, e) => Debug.Log($"未處理事件:{e.Id}"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L290-L293)

- **依事件池模式控制訂閱規則**:`EventPool<T>` 建構時傳入 `EventPoolMode`,決定是否允許多個或重複的訂閱者。

  | 模式 | 行為 |
  |------|------|
  | `EventPoolMode.Default` (0) | 必須存在且只能有一個訂閱者 |
  | `EventPoolMode.AllowNoHandler` (1) | 允許事件沒有訂閱者 |
  | `EventPoolMode.AllowMultiHandler` (2) | 允許同一事件 ID 註冊多個訂閱者 |
  | `EventPoolMode.AllowDuplicateHandler` (4) | 允許註冊重複的同一個回呼(需搭配 `AllowMultiHandler`) |

  多個旗標可按位元組合,例如 `EventPoolMode.AllowMultiHandler | EventPoolMode.AllowDuplicateHandler`。

  Source: [EventPoolMode.cs](/Runtime/Base/EventPool/EventPoolMode.cs#L43-L77), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L208-L234)

- **查詢訂閱數量**:透過 `EventHandlerCount` 或 `Count(id)` 讀取訂閱者數量,用於除錯或 UI 顯示。

  ```csharp
  Debug.Log(eventPool.EventHandlerCount);
  Debug.Log(eventPool.Count("PlayerHpChanged"));
  ```

  Source: [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L82-L91), [EventPool.cs](/Runtime/Base/EventPool/EventPool.cs#L164-L175)

## 常見錯誤

| 錯誤 | 現象 | 處理 |
|------|------|------|
| `handler` 為 `null` 呼叫 `Subscribe`/`Unsubscribe`/`Check` | 拋出 `GameFrameworkException("Event handler is invalid.")` | 註冊前確保回呼是實例方法或靜態委派,不要傳 `null` |
| `Fire` 事件後沒有任何訂閱者且模式未開啟 `AllowNoHandler` | 拋出 "not allow multi handler." 或由預設處理器兜底 | 建構函式中依需求加入 `EventPoolMode.AllowNoHandler` |
| 不呼叫 `Update` 消費佇列 | 事件看起來「消失」了 | 確保遊戲迴圈每幀驅動 `eventPool.Update(...)` |
| 物件銷毀後未 `Unsubscribe` | 事件觸發時回呼到已銷毀物件導致空參考 | 在 `OnDestroy`/`OnDisable` 中呼叫 `Unsubscribe` |

## 背景(選用)

`EventPool<T>` 內部用 `ConcurrentQueue<EventNode>` 暫存 `Fire` 來的事件,在 `Update` 中取出並透過 `GameFrameworkMultiDictionary<string, EventHandler<T>>` 派發;`_cachedNodes` 用於支援「事件處理過程中安全地取消訂閱」。`Fire` 是執行緒安全的(會在下一幀主執行緒派發),`FireNow` 則是立即同步派發,適合對延遲敏感但能保證呼叫端執行緒安全的場景。
