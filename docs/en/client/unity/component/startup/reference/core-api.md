# Core API Quick Reference

This page summarizes the core APIs exposed by the GameFrameX Startup framework, including startup entry points, procedure nodes, event arguments, HTTP parameter interfaces, and failover result types. All signatures come from the source code under the Runtime directory.

## Startup Entry Points

| Type | Location | Description |
|------|------|------|
| `GameFrameXStartup` | `Runtime/` | Main framework launcher class, responsible for procedure scheduling and lifecycle management |
| `IHotfixLauncher` | `Runtime/Hotfix/IHotfixLauncher.cs` | Hotfix launcher interface, used to launch the hotfix DLL after the Patch completes |
| `StartupOptions` | `Editor/StartupOptionsInspector.cs` | Editor-side startup configuration (used together with the Inspector) |

## Procedure Nodes (Procedures)

The startup flow consists of several `Procedure*` states, executed in sequence at runtime:

| Procedure Class | Responsibility |
|--------|------|
| `ProcedureGameLauncherState` | Final state before launching the main game logic |
| `ProcedureGetAppVersionInfoState` | Fetches remote App version information |
| `ProcedurePatchInit` | Patch flow initialization |
| `ProcedureUpdateStaticVersion` | Updates the static version number |
| `ProcedureUpdateManifest` | Updates the asset manifest |
| `ProcedureCreateDownloader` | Creates the downloader |
| `ProcedureDownloadWebFiles` | Downloads Web resource files |
| `ProcedurePatchDone` | Patch flow completion |

## Event Arguments

| Type | Location | Purpose |
|------|------|------|
| `StartupCompletedEventArgs` | `Runtime/Events/StartupCompletedEventArgs.cs` | Context carried when the startup flow completes successfully |
| `StartupFailedEventArgs` | `Runtime/Events/StartupFailedEventArgs.cs` | Error information when startup fails |

## Blackboard Key Constants

| Type | Location | Description |
|------|------|------|
| `BlackBoardKeys` | `Runtime/Constants/BlackBoardKeys.cs` | Collection of key name constants for data shared between procedure nodes |

## HTTP Parameter Interfaces

During the Patch phase, the launcher communicates with the remote server via HTTP; the following interfaces allow replacing the default implementations:

| Interface / Class | Location | Description |
|-----------|------|------|
| `IStartupHttpParamsProvider` | `Runtime/Http/IStartupHttpParamsProvider.cs` | HTTP parameter provider interface |
| `IStartupHttpParams` | `Runtime/Http/IStartupHttpParams.cs` | HTTP parameter object interface |
| `StartupHttpParams` | `Runtime/Http/StartupHttpParams.cs` | Default HTTP parameter implementation |
| `DefaultStartupHttpParamsProvider` | `Runtime/Http/DefaultStartupHttpParamsProvider.cs` | Default HTTP parameter provider implementation |

## Failover (Url Failover)

| Type | Location | Description |
|------|------|------|
| `UrlAttemptResult` | `Runtime/Failover/UrlAttemptResult.cs` | Result of a single URL attempt |
| `UrlFailoverResult` | `Runtime/Failover/UrlFailoverResult.cs` | Final result of multi-URL failover |
| `UrlFailoverRunner` | `Runtime/Failover/UrlFailoverRunner.cs` | URL failover executor |
