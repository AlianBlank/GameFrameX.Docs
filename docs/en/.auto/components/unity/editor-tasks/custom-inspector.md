# Monitoring Pools with Custom Inspectors

In Unity Editor's Play Mode, use the two custom Inspector panels—`ObjectPoolComponentInspector` and `ReferencePoolComponentInspector`—to view real-time metrics such as capacity, usage, and hit rate for object pools and reference pools, and to export the data as CSV files.

## Prerequisites

1. An `ObjectPoolComponent` or `ReferencePoolComponent` is attached in the scene (typically on the `GameFramework` prefab).
2. Unity must be in **Play Mode**; otherwise, the Inspector will only display the empty information prompt `Available during runtime only.`.
3. The component must be attached to an instance in the Hierarchy; pool data will not display on prefab assets.

## Steps

### 1. Open the Object Pool (ObjectPool) Monitoring Panel

Select the GameObject with the `ObjectPoolComponent` attached in the Hierarchy. The Inspector will expand the following content:

- `Object Pool Count`: The number of currently registered object pools.
- Each object pool is shown as a foldout item with the title `objectPool.FullName`.

After expanding, you can see the real-time properties of that pool:

| Field | Description |
|------|------|
| `Name` | Pool name |
| `Type` | Full name of the type of object in the pool |
| `Auto Release Interval` | Auto release interval |
| `Capacity` | Capacity upper limit |
| `Used Count` | Number of objects in use |
| `Can Release Count` | Number of objects that can be released immediately |
| `Expire Time` | Expiration time |
| `Priority` | Priority |

Next is the list of object instances (`GetAllObjectInfos()`), with each row showing `Name / Locked / Count or InUse / CustomCanReleaseFlag / Priority / LastUseTime`. When `AllowMultiSpawn` is true, the `In Use` column is replaced by `Count`.

Three action buttons are provided at the bottom:

- `Release`: Calls `objectPool.Release()` to immediately release all releasable objects.
- `Release All Unused`: Calls `objectPool.ReleaseAllUnused()`.
- `Export CSV Data`: Writes the current pool objects to CSV with the default file name `Object Pool Data - {Name}.csv`.

```csharp
ObjectPoolComponent t = (ObjectPoolComponent)target;
ObjectPoolBase[] objectPools = t.GetAllObjectPools(true);
foreach (ObjectPoolBase objectPool in objectPools)
{
    DrawObjectPool(objectPool);
}
```

### 2. Open the Reference Pool (ReferencePool) Monitoring Panel

Select the GameObject with the `ReferencePoolComponent` attached. At runtime, it will display:

- `Enable Strict Check` toggle: Switches strict check mode on the fly.
- `Reference Pool Count`: Provided by `ReferencePool.Count`.
- `Show Full Class Name` toggle: Switches the list sorting between `FullName` and `Name`.

Pool entries are grouped by assembly (`Assembly.GetName().Name`), with each group as a foldout item; after expanding, the table columns are `Unused / Using / Acquire / Release / Add / Remove`.

```csharp
ReferencePoolInfo[] referencePoolInfos = ReferencePool.GetAllReferencePoolInfos();
foreach (ReferencePoolInfo info in referencePoolInfos)
{
    string assemblyName = info.Type.Assembly.GetName().Name;
    // Group by assembly and display
}
```

### 3. Export CSV and Verify

1. Click `Export CSV Data` in the Inspector.
2. The `EditorUtility.SaveFilePanel` dialog will pop up for selecting the save path.
3. On successful write, the Console outputs `Export object pool CSV data to '{0}' success.`; on failure, it outputs `Export ... failure, exception is '{1}'.`, recorded as `Debug.LogError`.

```csharp
File.WriteAllLines(exportFileName, data, Encoding.UTF8);
Debug.Log(Utility.Text.Format("Export object pool CSV data to '{0}' success.", exportFileName));
```

## Common Variations

- **Multi-instance object pool (`AllowMultiSpawn = true`)**: Row header switches to `Locked\tCount\tFlag\tPriority\tLast Use Time`; the `IsInUse` column in CSV is replaced by `SpawnCount`.
- **Empty pool state**: When `GetAllObjectInfos().Length == 0`, the Inspector displays `Object Pool is Empty ...` and the `Release / Export` buttons will not appear.
- **Non-runtime state**: The object pool Inspector directly returns `Available during runtime only.`; the reference pool Inspector only displays the `Enable Strict Check` serialized field.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Inspector only displays `Available during runtime only.` | Not in Play Mode | Click Unity's `Play` button to enter runtime mode |
| Selecting a prefab asset shows no pool data | `IsPrefabInHierarchy` check fails | Place the component on an instance in the Hierarchy |
| Clicking `Export CSV Data` reports `failure, exception is ...` | Path has no write permission or is in use | Switch to a directory with write permission and retry |
| Reference pool panel only shows the `m_EnableStrictCheck` field | Not in runtime state | It will auto-expand after entering Play Mode |

## Background (Optional)

Both Inspectors inherit from `GameFrameworkInspector` / `ComponentTypeComponentInspector`, and are bound to the corresponding `BaseComponent` via `[CustomEditor(typeof(...))]`. At the end of `OnInspectorGUI`, `Repaint()` is uniformly called to ensure pool data continuously refreshes at runtime.
