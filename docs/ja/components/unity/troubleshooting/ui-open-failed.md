# UI オープン失敗・白画面の対処法

`GameApp.UI.OpenAsync<T>()` を呼び出した後、UI が表示されない・白画面になる・画面全体に反応がない、といった現象が起きるのは、通常 FairyGUI のリソースパッケージが先に読み込まれていない、UI パスが間違っている、または UI コンポーネントがシーンのルートノードにアタッチされていないことが原因です。本ページでは症状ごとに切り分け方法を説明します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GameApp.UI.OpenAsync<UILogin>()` 呼び出し後にエラーは出ないが何も表示されない | 対象 UI が含まれる FairyGUI パッケージの `AddPackageAsync` が呼ばれていない | UI を開く前に `GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.XXX))` を呼び出す |
| "パッケージが見つからない"、またはリソース読み込みエラーが出る | `FUIPackage` 列挙体の記述が誤っている / パッケージ名とビルド成果物が一致していない | `FUIPackage` の列挙値と FairyGUI エディターで実際にビルドされたパッケージ名を照合する |
| UI は開くが画面全体が白画面になる | 全画面用のインターフェース以外を使用しており、対象 UI が `OpenFullScreen` タイプのため、階層に隠されている | `OpenFullScreenAsync<T>(path, group)` に切り替え、対応する `UIGroupConstants` を渡す |
| "UI パスが見つからない"エラーが出る | `GetUIPath(nameof(X))` の `nameof(X)` クラス名と実際のクラスが一致していない | クラス名を FairyGUI リソース内の `Package_XXX` から生成される `X.cs` と一致させる |
| Hotfix 内で `GameApp.UI` を呼び出すと null になる | `LoadUI()` の実行が完了する前にアクセスしている | 上の読み込みを `await` するか、後続の処理を `OpenAsync` の継続中に記述する |
| UI は表示されるがすぐに消える | `CloseUIForm` を await していない、または上位で即座に `OpenUIForm` が上書きしている | 呼び出し順序を確認し、`CloseUIForm<T>` が `await OpenAsync` の後に呼ばれるようにする |

## 修正手順

### 1. UI が一切表示されない — FairyGUI パッケージの読み込みを追加

フレームワークでは、任意の UI を開く前に、対応する FairyGUI リソースパッケージを先に読み込む必要があります。`HotfixLauncher.LoadUI` が標準的な実装例を示しています:

```csharp
#if ENABLE_UI_FAIRYGUI
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommon));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UICommonAvatar));
GameApp.FUIPackage.AddPackageAsync(Utility.Asset.Path.GetUIPackagePath(FUIPackage.UIRoom));
#endif
await GameApp.UI.OpenAsync<UILogin>();
```

`FUIPackage.XXX` の列挙値は FairyGUI エディターから書き出されたパッケージ名と完全に一致させる必要があります(例: `UIRoom`、`UICommon`)。いずれかの登録が漏れていると、そのパッケージ内のすべての UI が開けません。

Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L46)

### 2. 白画面・隠蔽される — 適切なオープンインターフェースを使用

「全画面タイプの UI」(ログイン、キャラクター一覧、メイン画面)を開くには、必ず `OpenFullScreenAsync` を使用し、UI グループを指定します:

```csharp
await GameApp.UI.OpenFullScreenAsync<UIPlayerList>(
    Utility.Asset.Path.GetUIPath(nameof(UILogin)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

通常の `OpenAsync<T>()` は、ポップアップ・通知ボックスのような全画面以外のコンポーネント向けです。対象 UI が実際には全画面レイアウトであるにもかかわらず `OpenAsync` を使うと、「開いているように見えて実際には隠されている／描画されていない」白画面が発生します。

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 3. 閉じてから再度開くときは await する

`CloseUIForm` は、必ず `await OpenAsync/OpenFullScreenAsync` の後に実行してください。そうしないと、上位の UI が先に現在の画面を上書きしてしまいます:

```csharp
await GameApp.UI.OpenFullScreenAsync<UIMain>(
    Utility.Asset.Path.GetUIPath(nameof(UIMain)),
    UIGroupConstants.Floor);
GameApp.UI.CloseUIForm(this);
```

Source: [UIPlayerList.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UILogin/UIPlayerList.cs#L95-L97)

### 4. クラス名を FairyGUI 生成コードと一致させる

`GetUIPath(nameof(X))` に渡す `X` は、FairyGUI の書き出しツールが生成する `Package_X.cs` のクラス名と完全に一致している必要があります。クラス名を変更したのに同期し忘れると、パスが見つからない・白画面・一つ前の古い画面が開かれる、といった現象が発生します。

### 5. ポップアップ型 UI のクローズ例

汎用的な確認／キャンセルポップアップを閉じる場合は、以下を直接呼び出します:

```csharp
GameApp.UI.CloseUIForm<UIDialogMessageBox>();
data.OnEnter?.Invoke();
```

Source: [UIDialogMessageBox.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/UI/Logic/UICommon/UIDialogMessageBox.cs#L22-L29)

### 6. Launcher 段階での UI クローズ

`LauncherUIHandler` は初期化完了時に起動画面を閉じます:

```csharp
GameApp.UI.CloseUIForm<UILauncher>();
_ui = null;
```

Source: [LauncherUIHandler.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/LauncherUIHandler.cs#L66-L67)

## 検証

- `LoadUI()` 内で UI が使用するすべての `FUIPackage` 列挙値を登録し、起動ログに対応するパッケージの読み込み行が出力されることを確認する。
- `await OpenAsync<T>()` から戻った後、Hierarchy 上で `T` のインスタンスが FairyGUI の Stage 下にアタッチされていることを確認する(Root 外で止まっていないこと)。
- 全画面 UI 切り替え時、遷移中は白画面が一瞬表示されるのではなく、旧画面が新画面に覆われることを確認する。
- 閉じた後に再度 `OpenAsync<T>()` を呼び、新しい画面が正常に表示されることを確認する(リソースが一括回収されていないこと、あるいは破棄処理で適切に解放されていること)。

## 背景(任意)

`HotfixLauncher.LoadUI` では、まず `UICommon`、`UICommonAvatar`、`UIRoom` といった基本パッケージをプリロードしてから `await OpenAsync<UILogin>` を呼び出します。続く `UIPlayerList → UIMain` のチェーン遷移はいずれも「await で開く → 自分自身を CloseUIForm」というパターンに従っており、これが白画面や階層の混乱を避けるための重要な取り決めです。
