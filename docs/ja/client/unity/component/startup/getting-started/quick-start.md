# 5分で起動フローを組み込む

このページの手順に従えば、パッケージのインストールから `StartupRunner.Run(...)` の呼び出しを一度成功させるまで、およそ5分で完了します:`StartupOptions` アセットを1つ作成し、2つのインターフェースを実装し、ブートストラップスクリプトを1つアタッチして起動するだけです。

## 前提条件

- Unity 2019.4+
- GameFrameX フレームワークとその依存関係がインストール済みであること:`com.gameframex.unity` / `com.gameframex.unity.procedure` / `com.gameframex.unity.fsm` / `com.gameframex.unity.event` / `com.gameframex.unity.cysharp.unitask`
- YooAsset(ホットアップデートパッチフローを有効にする場合)

## 操作手順

### 1. パッケージのインストール

`Packages/manifest.json` に `com.gameframex.unity.startup` の依存関係を追加し、GameFrameX の scoped registry を設定します:

```json
{
  "dependencies": {
    "com.gameframex.unity.startup": "1.1.0"
  },
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ]
}
```

`scopes` により、`com.gameframex` プレフィックスを持つパッケージのみがこのレジストリから解決されるよう制御されます。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L20-L39)

### 2. 設定アセットの作成

Unity メニュー:`Create > GameFrameX > Startup Options` を選択すると、`StartupOptions` の ScriptableObject アセットが生成されます。主な項目：
- `GlobalInfoUrls`:グローバル情報インターフェースのプライマリ/バックアップ URL リスト
- `GamePlayMode`:リソースの実行モード。起動前に Asset コンポーネントへ同期されます
- `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`:ホットアップデートエントリ
- `PackageName` / `Channel` / `SubChannel`:HTTP 共通パラメータ
- `LauncherUIResName`:起動 UI のリソースパス(デフォルトは `UI/UILauncher`)
- `SkipRemoteStartupRequests`:すべてのリモート起動リクエストをスキップ(WebGL スタンドアロンまたはバックエンドがない場合に有効化)

### 3. UI ハンドラーの実装

`IStartupUIHandler` を実装すると、フレームワークはこのインターフェースを通じて UI 状態をコールバックします:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class GameStartupUIHandler : IStartupUIHandler
{
    public UniTask StartAsync(string uiResName) { /* UI をロード */ return UniTask.CompletedTask; }
    public void SetTipText(string text) { /* ヒントテキストを更新 */ }
    public void SetProgress(float progress, string sizeInfo) { /* プログレスバーを更新 */ }
    public void SetProgressUpdateFinish() { /* 完了をマーク */ }
    public void Dispose() { /* UI を閉じる、サブスクリプションを解放 */ }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L54-L66)

### 4. ホットアップデートランチャーの実装(オプション)

ホットアップデートを有効にする必要がある場合は、`IHotfixLauncher` を実装します:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class HybridClrHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        // options.HotfixAssemblyName に従いホットアップデートアセンブリをロード
        // options.HotfixEntryTypeName.options.HotfixEntryMethodName を呼び出し
        return HotfixLaunchResult.Succeed();
    }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L67-L79)

### 5. 起動

任意の GameObject にブートストラップスクリプトをアタッチし、シーンのロード後に `StartupRunner.Run` を呼び出します:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;
using UnityEngine;

public class GameBootstrap : MonoBehaviour
{
    [SerializeField] private StartupOptions _options;

    private async void Start()
    {
        var uiHandler = new GameStartupUIHandler();
        var hotfixLauncher = new HybridClrHotfixLauncher();

        var result = await StartupRunner.Run(_options, uiHandler, hotfixLauncher);

        if (result.Success)
        {
            // 起動完了、ゲーム準備完了
        }
        else
        {
            Debug.LogError($"启动失败 at {result.FailedProcedureName}: {result.ErrorMessage}");
        }
    }
}
```

`StartupResult` には `Success` / `FailedProcedureName` / `FailedUrl` / `ErrorMessage` の各フィールドが含まれます。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L81-L105)

## よくあるバリエーション

### イベント購読による通知の疎結合化

直接 `await` するのではなく、完了/失敗イベントを購読します:

```csharp
GameApp.Event.Subscribe(StartupCompletedEventArgs.EventId, OnStartupCompleted);
GameApp.Event.Subscribe(StartupFailedEventArgs.EventId, OnStartupFailed);
```

`StartupCompletedEventArgs` と `StartupFailedEventArgs` は `GameApp.Event.Fire` によって発火され、await パスとイベントパスの両方で通知を受け取ります。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L107-L112)

### WebGL / スタンドアロンデプロイ

`StartupOptions.SkipRemoteStartupRequests` を true にチェックすると、すべてのリモート起動リクエスト(グローバル情報 / App バージョン / リソースパックバージョン)をスキップし、ローカルの YooAsset 初期化のみを実行します。

### URL プライマリ/バックアップフェイルオーバー

`StartupOptions.GlobalInfoUrls` に複数の URL を設定すると、フレームワークは順番に試行します。単一 URL ごとのリトライ回数の上限は `MaxAttemptsPerUrl` で制御されます。

## よくあるエラー

- **`Start` に `async void` がない**:`StartupRunner.Run` は `UniTask<StartupResult>` を返すため、ブートストラップメソッドは `async void Start()` でなければなりません。そうしないと UniTask が駆動されません。
- **メニューに `Create > GameFrameX > Startup Options` が見つからない**:パッケージが正しくインポートされていません。`Packages/manifest.json` の `scopedRegistries` と `dependencies` を確認してください。
- **ホットアップデートエントリが呼び出せない**:`HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` のいずれかにスペルミスがあると、起動時に procedure FSM 内で `FailedProcedureName` が報告されます。ログの `result.ErrorMessage` を確認してください。
- **重複起動**：同一シーンで繰り返し呼び出すと procedure FSM が再構築されます。`StartupRunner.Run` は一度きりのエントリであるため、`OnEnable` 内で呼び出さないでください。

## 背景(オプション)

`StartupRunner.Run(options, uiHandler, hotfixLauncher)` は内部で procedure FSM を構築し、`options` / `uiHandler` / `hotfixLauncher` の3つのインスタンスを固定の BlackBoard キー(`__startup_options__` / `__startup_ui_handler__` / `__startup_hotfix_launcher__`)に書き込みます。すべての procedure 状態は `IFsm<IProcedureManager>.GetData<VarObject>(key)` を通じて読み取られます。完了結果は `__startup_completion_source__` によって `UniTask<StartupResult>` として公開されます。BlackBoard 定数の全容は `BlackBoardKeys.cs` を参照してください。
