# 如何播放獎勵式影片廣告

按照本頁的步驟呼叫 GameFrameX 廣告元件來播放獎勵式影片廣告，並在使用者完整觀看廣告後，透過 `AdvertisementPlayOption.OnShowResult` 接收獎勵發放回呼，以發放金幣、復活次數等遊戲內道具。

## 前置條件

1. 專案中已整合 `com.gameframex.unity.advertisement` 套件，且底層廣告 SDK（如 Pangle、騰訊廣告以及各種 WebGL 小遊戲廣告聚合）已完成整合與初始化。
2. 場景中已建立掛載了 [AdvertisementComponent](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L45-L46) 的 GameObject，並已在 Inspector 中填入對應平台（Android/iOS/WebGL/微信/抖音/快手）的廣告位 ID。
3. 若要透過腳本呼叫，需先取得元件參考：

```csharp
using GameFrameX.Advertisement.Runtime;
using UnityEngine;

public class RewardAdCaller : MonoBehaviour
{
    private AdvertisementComponent _adComponent;

    private void Awake()
    {
        _adComponent = GetComponent<AdvertisementComponent>();
    }
}
```

## 步驟

1. 在 Inspector 中為各平台填入獎勵式影片廣告位 ID。元件會根據目前的建置平台自動選擇對應的 ID（參見 [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)）。

2. （可選）在 `Start` 之前，設定獎勵廣告伺服器端回呼所需的額外欄位，例如使用者 ID、訂單號等：

```csharp
_adComponent.SetExtraData("userId", "10001");
_adComponent.SetExtraData("orderId", "20240101001");
```

`SetExtraData` 的實作請見 [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L173-L189)。當 `value` 為 `null` 時，會移除對應的鍵。

3. 當玩家點擊「觀看廣告領取獎勵」按鈕時，建構一個 [AdvertisementPlayOption](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L85) 實例並填入三個回呼：

```csharp
public void OnClickWatchAd()
{
    var option = new AdvertisementPlayOption
    {
        OnSuccess = msg => Debug.Log($"Rewarded video success: {msg}"),
        OnFail    = err => Debug.LogWarning($"Rewarded video failure: {err}"),
        OnShowResult = watched =>
        {
            // watched == true 表示使用者已完整觀看，可以發放獎勵
            if (watched)
            {
                GrantReward();
            }
        },
        extraData  = "{\"orderId\":\"20240101001\"}", // 僅在 Load 階段透傳給伺服器
        customData = "reward_coins_100"               // 播放時透傳給回呼
    };

    _adComponent.Play(option);
}
```

4. 呼叫 `Play(AdvertisementPlayOption)` 來播放廣告。該方法的定義請見 [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L216-L219)：

```csharp
_adComponent.Play(option);
```

5. 在 `OnShowResult` 回呼中，根據 `watched` 判斷是否發放獎勵（例如 +100 金幣）。只有完整觀看後的回呼才算有效曝光。

## 常見變體

- **舊版 API（標記為 `[Obsolete]`）**：直接接收三個 `Action` 參數的舊 `Show`/`Load` 方法仍可使用，但編譯器會發出 `CS0618` 警告。建議盡快遷移至 `Play(AdvertisementPlayOption)`。定義請見 [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L85-L124)。
- **透過管理器直接呼叫**：若不想經過 `AdvertisementComponent`，也可以呼叫 `GameFrameworkEntry.GetModule<IAdvertisementManager>()` 後直接呼叫 `Play(AdvertisementPlayOption)`。方法簽章請見 [IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L97-L97)。
- **WebGL 多平台分支**：以 WebGL 為目標平台時，獎勵式影片廣告位 ID 分別由 `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 編譯巨集決定。需為每個小遊戲分別申請並填入對應 ID。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `Log.Fatal("Advertisement manager is invalid.")` | 未註冊任何 `IAdvertisementManager` 實作 | 整合對應平台的廣告 SDK 套件，或確保 `GameFrameworkEntry` 已在 `Awake` 之前完成初始化 |
| `ArgumentNullException: config` | 傳遞給 `Initialize` 的 `AdvertisementConfig` 為 null | 先 `new` 一個設定物件，或在 Inspector 中為 `m_config` 指派值並讓 `Start` 自動初始化 |
| 廣告有顯示但 `OnShowResult` 恆為 `false` | 使用者中途關閉，或底層 SDK 回報錯誤 | 在 `OnFail` 中列印錯誤資訊以進行排查，並確認 `extraData`/`customData` 未導致伺服器端驗證失敗 |
| WebGL 建置失敗，提示找不到廣告位 | 未啟用編譯巨集，或未填入對應小遊戲的 ID | 檢查 Player Settings 中的 Scripting Define Symbols，並為該小遊戲填入 `m_adUnitIdWebGLWeChat` 等欄位 |

## 背景說明（選讀）

`AdvertisementPlayOption` 同時攜帶成功/失敗/顯示結果回呼，以及 `extraData` 與 `customData` 兩個額外欄位：`extraData` 僅在 `Load` 階段被序列化為 JSON 並透傳給伺服器進行獎勵驗證，載入完成後即失效；`customData` 則在播放時透傳給底層 SDK 回呼。`BaseAdvertisementManager` 使用 `_delegating` 互斥鎖來防止新舊 `Initialize` 呼叫之間的相互遞迴。詳細內容請參閱 [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L111-L163)。
