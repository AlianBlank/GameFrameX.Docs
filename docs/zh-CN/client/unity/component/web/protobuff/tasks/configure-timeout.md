# 超时时间与连接数配置指南

本页说明如何为 Web ProtoBuff 网络模块配置**请求超时时间**与**每服务器最大连接数**。超时时间默认 `5f` 秒,既可在 Inspector 中用滑块调整(0–120 秒),也可在运行时通过代码修改;`MaxConnectionPerServer` 默认为 `8`,没有 Inspector 字段,只能通过管理器在代码中设置。

## 前置条件

- 已安装 `com.gameframex.unity.web.protobuff` 包;
- 场景中存在挂有 **Web ProtoBuff** 组件(`AddComponentMenu("GameFrameX/Web ProtoBuff")`)的 GameObject。

## 配置项速查

| 配置项 | 类型 / 默认值 | 配置方式 |
|--------|--------------|----------|
| `Timeout` | `float`,单位秒,默认 `5f` | Inspector 滑块(0–120)、组件属性、管理器属性 |
| `RequestTimeout` | `TimeSpan`,由 `Timeout` 自动同步(`TimeSpan.FromSeconds(value)`) | 管理器属性,可直接赋值 |
| `MaxConnectionPerServer` | `int`,默认 `8`(构造函数中设置) | 仅代码,通过 `IWebProtoBuffManager` 设置 |

## 操作步骤

### 方式一:在 Inspector 中设置超时时间

1. 在场景中选中挂有 **Web ProtoBuff** 组件的 GameObject;
2. 在组件的自定义 Inspector 中拖动 `Timeout` 滑块,取值范围 `0f`–`120f` 秒;
3. 该值写入序列化字段 `m_Timeout`,游戏启动时由 `Awake` 应用到管理器。

编辑器滑块的实现:

```csharp
float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
```

Source: [WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Editor/Inspector/WebComponentInspector.cs#L23)

组件侧对应的序列化字段:

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;

public float Timeout
{
    get { return m_WebProtoBuffManager.Timeout; }
    set { m_WebProtoBuffManager.Timeout = m_Timeout = value; }
}
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L60-L71)

### 方式二:运行时通过代码修改

通过组件属性修改超时(同时写回序列化字段与管理器):

```csharp
var component = GetComponent<GameFrameX.Web.ProtoBuff.Runtime.WebProtoBuffComponent>();
component.Timeout = 15f;
```

### 方式三:设置最大连接数

`MaxConnectionPerServer` 未在组件上暴露序列化字段,需要通过模块接口在代码中设置:

```csharp
var manager = GameFrameX.Runtime.GameFrameworkEntry.GetModule<GameFrameX.Web.ProtoBuff.Runtime.IWebProtoBuffManager>();
manager.MaxConnectionPerServer = 16;
manager.Timeout = 10f;
```

`GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` 正是组件 `Awake` 中获取管理器实例的方式:

```csharp
m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
if (m_WebProtoBuffManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebProtoBuffManager.Timeout = m_Timeout;
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L82-L90)

## 常见变体

- **需要亚秒级或 TimeSpan 精度的超时**:直接设置管理器的 `RequestTimeout`(类型 `TimeSpan`)。注意设置 `Timeout`(float 秒)会自动覆盖 `RequestTimeout`:

```csharp
// 超时时间(秒)
private float m_Timeout = 5f;

/// <summary>获取或设置超时时间(秒)</summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>获取或设置每个服务器的最大连接数</summary>
public int MaxConnectionPerServer { get; set; }

/// <summary>获取或设置请求超时时间</summary>
public TimeSpan RequestTimeout { get; set; }
```

Source: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L20-L54)

- **恢复出厂默认**:管理器构造函数中默认 `MaxConnectionPerServer = 8; Timeout = 5f;`,把两个属性改回这两个值即可。

Source: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L27-L31)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 代码里设置的 `Timeout` 启动后"不生效" | 另一脚本的初始化先执行,之后组件 `Awake` 又执行 `m_WebProtoBuffManager.Timeout = m_Timeout`,用 Inspector 序列化值覆盖了代码设置 | 在组件 `Awake` 之后再修改,或直接改 Inspector 中的值 |
| Inspector 里找不到 `MaxConnectionPerServer` | 该项不是组件的序列化字段,只在管理器上 | 用 `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` 在代码中设置 |
| 想设超过 120 秒的超时,滑块拖不动 | 编辑器滑块硬编码范围为 `0f`–`120f` | 改用代码 `component.Timeout = 150f;` |
| 直接改了 `RequestTimeout` 但很快失效 | 之后任何一次对 `Timeout` 的赋值都会用 `TimeSpan.FromSeconds(value)` 覆盖 `RequestTimeout` | 只通过 `Timeout` 调整,或最后再设置 `RequestTimeout` |

## 验证

- 修改后读取 `component.Timeout` / `manager.Timeout`,确认返回新值;
- `manager.Timeout = x` 之后读取 `manager.RequestTimeout`,应等于 `TimeSpan.FromSeconds(x)`。

## 背景

`Timeout` 是对外统一的"秒"配置入口:设置它会同步生成 `TimeSpan` 形式的 `RequestTimeout`,供请求侧使用;`MaxConnectionPerServer` 表示每个服务器的最大连接数,默认 8。关于模块整体结构,见概述页。
