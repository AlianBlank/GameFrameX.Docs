# UI、GUI、FairyGUI 三大 UI エントリの使い方

GameFrameX のエントリパッケージは、3つの静的プロパティ `GameApp.UI`、`GameApp.GUI`、`GameApp.FUIPackage` を通じて、UI、UGUI、FairyGUI の三大 UI コンポーネントをそれぞれ公開しています。対応するモジュールをコンパイルマクロで有効化するだけで、任意のビジネスコードからこれらのコンポーネントを直接利用して、UI を開いたり/管理したりすることができます。

## 前提条件

- プロジェクトに GameFrameX のエントリパッケージ [com.gameframex.unity.entry](https://github.com/GameFrameX/com.gameframex.unity.entry) が導入済みであること。
- プロジェクトの `Assembly Definition` またはプロジェクト設定で、以下の対応するコンパイルマクロを有効化すること(いずれか一つ、または組み合わせ):
  - `ENABLE_GAME_FRAME_X_UI`:`GameApp.UI`(UI サブシステム)を有効化します。
  - `ENABLE_GAME_FRAME_X_L_UGUI`:`GameApp.GUI`(UGUI サブシステム)を有効化します。
  - `ENABLE_GAME_FRAME_X_UI_FAIRYGUI`:`GameApp.FUIPackage`(FairyGUI パッケージ管理)を有効化します。
- `GameEntry` を通じて、対応するランタイムコンポーネント(`UIComponent`、`UGUIComponent`、`FairyGUIPackageComponent`)が登録済みであること。

## 三大エントリの一覧

| エントリ | コンパイルマクロ | 戻り値のコンポーネント | 典型的な用途 |
|------|--------|----------|----------|
| `GameApp.UI` | `ENABLE_GAME_FRAME_X_UI` | `UIComponent` | GameFrameX 独自の UI サブシステムの統一エントリ |
| `GameApp.GUI` | `ENABLE_GAME_FRAME_X_L_UGUI` | `UGUIComponent` | UGUI ベースの従来型 UI コンポーネントのエントリ |
| `GameApp.FUIPackage` | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` | `FairyGUIPackageComponent` | FairyGUI リソースパッケージ/UI 管理のエントリ |

## 操作手順

### 1. UI サブシステムを有効化する(`GameApp.UI`)

プロジェクトレベルでマクロ `ENABLE_GAME_FRAME_X_UI` を有効化すると、任意のコードから `GameApp.UI` を通じて `UIComponent` インスタンスを取得できます:

```csharp
#if ENABLE_GAME_FRAME_X_UI
var ui = GameApp.UI;   // 初回アクセス時に GameEntry.GetComponent<UIComponent>() で遅延ロードされる
ui.SomeApi();
#endif
```

ソース: [GameApp.UI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.UI.cs#L32-L55)

### 2. UGUI サブシステムを有効化する(`GameApp.GUI`)

プロジェクトレベルでマクロ `ENABLE_GAME_FRAME_X_L_UGUI` を有効化すると、`GameApp.GUI` を通じて `UGUIComponent` インスタンスを取得できます:

```csharp
#if ENABLE_GAME_FRAME_X_L_UGUI
var gui = GameApp.GUI; // GameEntry.GetComponent<UGUIComponent>() で遅延ロードされる
gui.SomeApi();
#endif
```

ソース: [GameApp.GUI.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GUI.cs#L1-L25)

### 3. FairyGUI パッケージ管理を有効化する(`GameApp.FUIPackage`)

プロジェクトレベルでマクロ `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` を有効化すると、`GameApp.FUIPackage` を通じて `FairyGUIPackageComponent` を取得できます:

```csharp
#if ENABLE_GAME_FRAME_X_UI_FAIRYGUI
var fUIPackage = GameApp.FUIPackage; // GameEntry.GetComponent<FairyGUIPackageComponent>() で遅延ロードされる
fUIPackage.SomeApi();
#endif
```

ソース: [GameApp.FairyGUIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.FairyGUIPackage.cs#L32-L55)

### 4. ビジネスコードで安全にアクセスする

3つのエントリはいずれも遅延ロード方式を採用しています。初回アクセス時に `GameEntry.GetComponent<T>()` を呼び出してコンポーネントを取得してキャッシュし、以降は静的フィールドをそのまま再利用します。プロパティ内部では `if (_xxx == null)` による null チェックが行われているため、マルチスレッドのコンテキストで静的フィールドをリセットしてしまうのを避けるためにも、ビジネスシステムでは読み取り専用として使用することを推奨します。

```csharp
var ui = GameApp.UI;
var gui = GameApp.GUI;
var pkg = GameApp.FUIPackage;
```

## よくあるバリエーション

- 複数の UI 体系を同時に有効化する:同一プロジェクト内で `ENABLE_GAME_FRAME_X_UI`、`ENABLE_GAME_FRAME_X_L_UGUI`、`ENABLE_GAME_FRAME_X_UI_FAIRYGUI` を同時に有効化できます。`GameApp` クラスは `partial` 形式で3つの拡張をマージするため、相互に影響を与えません。
- FairyGUI のみを有効化する:プロジェクトで FairyGUI だけを使用する場合は、`ENABLE_GAME_FRAME_X_UI_FAIRYGUI` だけをチェックすればよく、コード生成によって他の2つのプロパティは取り除かれます。
- UGUI + FairyGUI の併用:`ENABLE_GAME_FRAME_X_L_UGUI` と `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` を同時に有効化し、`GameApp.GUI` で UGUI のフローを処理し、`GameApp.FUIPackage` で FairyGUI リソースパッケージを管理します。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| コンパイルエラー `GameApp 不包含 UI 的定义` | コンパイルマクロ `ENABLE_GAME_FRAME_X_UI` が有効化されていない | プロジェクトまたは asmdef の Scripting Define Symbols に `ENABLE_GAME_FRAME_X_UI` を追加する |
| コンパイルエラー `GameApp 不包含 GUI 的定义` | `ENABLE_GAME_FRAME_X_L_UGUI` が有効化されていない | `ENABLE_GAME_FRAME_X_L_UGUI` を追加する |
| コンパイルエラー `GameApp 不包含 FUIPackage 的定义` | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` が有効化されていない | `ENABLE_GAME_FRAME_X_UI_FAIRYGUI` を追加する |
| 実行時に `GameApp.UI` が返すコンポーネントが `null` になる | `GameEntry` に `UIComponent` が登録されていない | 起動フロー内で `GameEntry.RegisterComponent` を通じて `UIComponent` インスタンスを登録する |

## 背景(任意)

エントリパッケージは `partial class GameApp` の方式によって、異なるサブシステムへのアクセスエントリを独立したファイルに分割し、コンパイルマクロで囲むことで必要に応じたコンパイルを実現し、未有効の UI 体系へのハードな依存を回避しています。3つのプロパティの内部はいずれも `if (_x == null) _x = GameEntry.GetComponent<T>()` というシングルトンの遅延ロードパターンを採用しており、`GameEntry` のコンポーネント登録機構と一貫性を保っています。
