# フォルダコピーでエラーが発生した場合の対処方法

Unity iOS ビルドのポストプロセス段階において、`folders` 設定で宣言されたフォルダは Xcode プロジェクトにコピーされ、自動的にコンパイルに追加されます。Unity Console に `DirectoryNotFoundException` や `IOException` などの例外が表示された場合、またはコピー後にファイル/フレームワークが欠落している場合は、下記の診断表で原因を特定し、修正してください。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `DirectoryNotFoundException: Could not find a part of the path ...` | `folders` の Key のソースパスが存在しない:Key は Unity プロジェクトのルートディレクトリ(`Assets` と同階層)からの相対パスであり、`Assets` からの相対パスではない | 修正手順 1 を参照 |
| `IOException` / `UnauthorizedAccessException` がターゲットディレクトリの削除時にスローされる | ターゲットディレクトリが Xcode などのプログラムに占有されている、または読み取り専用ファイルが含まれている | 占有しているプログラムを終了するか、ターゲットディレクトリを手動で削除してから再ビルドする。修正手順 2 を参照 |
| コピーは成功するが一部のファイルが欠落する | ファイル名が `.` で始まる、または `.gitkeep` / `.DS_Store` であるため、意図的にフィルタリングされる | 仕様通りの動作。修正手順 3 を参照 |
| `.framework` / `.bundle` / `.a` のコピー後にリンクエラー(シンボルが見つからない)が発生 | 過去バージョンに存在したフォルダコピーのリンクバグ、または拡張子が正しくないため認識されない | 最新バージョンにアップグレードする。修正手順 4 を参照 |

## 修正手順

### 1. ソースパスが存在しない(DirectoryNotFoundException)

コピー時にソースパスは以下の方式で連結されます。`Environment.CurrentDirectory` は Unity プロジェクトのルートディレクトリであり、`Assets` と同階層です:

```csharp
string src = Path.Combine(Environment.CurrentDirectory, map.Key.ToString().Trim());
string des = Path.Combine(xcodePath, map.Value.ToString().Trim());
CopyFolder(src, des);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L29-L31)

JSON 設定を確認して修正してください(パスの前後の空白は `Trim()` で除去されます):

```json
{
  "folders": {
    "XC": "Classes/XC"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L191-L197)

- Key:Unity プロジェクトのルートディレクトリ内のフォルダのパス。誤って `Assets/` 始まりで書かないように注意
- Value:Xcode プロジェクト内にコピーされる相対パス

### 2. ターゲットディレクトリの削除に失敗(IOException)

`CopyFolder` はコピー前に、既に存在するターゲットディレクトリと同名のファイルを先に削除してから、ディレクトリを再作成します:

```csharp
if (Directory.Exists(dstPath))
{
    Directory.Delete(dstPath, true);
}

if (File.Exists(dstPath))
{
    File.Delete(dstPath);
}

Directory.CreateDirectory(dstPath);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L174-L184)

`Directory.Delete(dstPath, true)` は再帰的に削除します。ターゲット内に占有されているファイルや読み取り専用のファイルがある場合、例外がスローされます:

1. この Xcode プロジェクト(またはこのディレクトリを占有しているプログラム)を開いているプログラムを終了する
2. Xcode プロジェクト内のターゲットディレクトリを手動で削除する
3. Unity iOS ビルドを再実行する

### 3. 一部のファイルがコピーされない

コピーとコンパイルへの追加は、いずれも `IsNeedCopy` によるフィルタリングを経由します:

```csharp
private static bool IsNeedCopy(string file)
{
    string fileName = Path.GetFileNameWithoutExtension(file);
    if (fileName.StartsWith(".") || file.EndsWith(".gitkeep") || file.EndsWith(".DS_Store"))
    {
        return false;
    }

    return true;
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L112-L121)

ファイル名(拡張子を除く)が `.` で始まるもの、`.gitkeep`、`.DS_Store` はすべてスキップされます。空ディレクトリのプレースホルダファイルを保持する必要がある場合は、ドット以外のプレフィックスで命名してください。

### 4. framework / bundle / 静的ライブラリのリンクエラー

`AddFolderBuild` は拡張子によって処理方法を区別します。ターゲットパス(すなわち `folders` の Value)の拡張子が正しいことを確認してください:

| Value の末尾 | 処理方法 |
|------------|----------|
| `.framework` | `AddFile` + `AddFileToBuild` + `AddFrameworkToProject` |
| `.bundle` | UnityFramework ターゲットとメインターゲットの両方に追加 |
| `.xcframework` / `.a` | `AddFile` + `AddFileToBuild` |
| 通常のディレクトリ | サブディレクトリとファイルを再帰的に展開し、フレームワーク/静的ライブラリに対して検索パスを自動追加(`AutoAddSearchPath`) |

```csharp
if (root.EndsWith(".framework") || root.EndsWith(".bundle"))
{
    Debug.LogFormat("add framework/bundle to build:{0}->{1}", currDir, root);
    string fileGuid = proj.AddFile(currDir, root, PBXSourceTree.Source);
    proj.AddFileToBuild(targetGuid, fileGuid);
    if (root.EndsWith(".bundle"))
    {
        proj.AddFileToBuild(mainTargetGuid, fileGuid);
    }
    // linked framework として追加
    proj.AddFrameworkToProject(targetGuid, root, false);
    return;
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L47-L59)

## 検証

1. Unity iOS ビルドを再実行し、Console に `DirectoryNotFoundException` / `IOException` の例外がなく、`add framework/bundle to build:...`、`add file to build:...` のログが表示されること
2. 生成された Xcode プロジェクトを開き、`folders` の Value が指すディレクトリが存在し、内容が揃っていること
3. `.framework` / `.bundle` が **General → Frameworks, Libraries, and Embedded Content** または **Build Phases → Link Binary With Libraries** に表示され、コンパイルが通ること
