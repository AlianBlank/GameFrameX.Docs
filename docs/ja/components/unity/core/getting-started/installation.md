# インストールとプロジェクト統合

このガイドでは、GameFrameX Unity コアパッケージを Unity プロジェクトに統合し、シーンスクリプトでフレームワークコンポーネントを取得する方法を説明します。完了すると、`GameEntry.GetComponent<T>()` を通じて `GameManager` からオブジェクトプール、参照プールなどのコンポーネントを取得し、拡張メソッドを直接使用できます。

## 前提条件

| 項目 | 要件 |
|------|------|
| Unity バージョン | 2019.4 以降([package.json](/package.json#L7)) |
| .NET バージョン | .NET Standard 2.0+ |
| プラットフォーム | Windows / macOS / Linux / iOS / Android / WebGL |
| プロジェクトタイプ | Unity 標準プロジェクト（`Packages/manifest.json` が生成済み） |

## 操作手順

### 方法一：Unity Package Manager グラフィカルインターフェース（推奨）

1. Unity エディターを開き、対象のプロジェクトを開きます。
2. トップメニューから `Window` → `Package Manager` を選択します。
3. 左上隅の `+` ボタンをクリックし、`Add package from git URL...` を選択します。
4. 入力欄に `https://github.com/GameFrameX/com.gameframex.unity.git` を貼り付けます。
5. `Add` をクリックし、Unity がダウンロードとインポートを完了するまで待ちます。

Source: [README.zh-CN.md](/README.zh-CN.md#L353-L359)

### 方法二：手動で Release パッケージをダウンロード

1. [Releases ページ](https://github.com/GameFrameX/com.gameframex.unity/releases) を開き、最新の `.zip` または `.tar.gz` をダウンロードします。
2. Unity プロジェクトのルートディレクトリにある `Packages/` フォルダに圧縮ファイルを解凍します。
3. Unity エディターに戻ると、Unity が自動的に認識してインポートします。

Source: [README.zh-CN.md](/README.zh-CN.md#L361-L364)

### 方法三：scopedRegistries 経由で導入（UPM）

プロジェクトのルートディレクトリにある `Packages/manifest.json` を編集し、scoped registry 設定を追加し、`dependencies` でバージョンを宣言します：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity": "1.10.1"
  }
}
```

`scopes` はこのレジストリから解決される名前空間を制御します：`com.gameframex` で始まるパッケージのみが GameFrameX レジストリから取得され、その他の依存関係は引き続き Unity のデフォルトレジストリが使用されます。

Source: [README.zh-CN.md](/README.zh-CN.md#L366-L387)

### インストールの検証

任意の `MonoBehaviour` の `Start()` でコンポーネント取得を一度呼び出し、正常に返されれば統合成功です：

```csharp
using GameFrameX.Runtime;

public class GameManager : MonoBehaviour
{
    void Start()
    {
        var objectPool = GameEntry.GetComponent<ObjectPoolComponent>();
        var referencePool = GameEntry.GetComponent<ReferencePoolComponent>();

        transform.SetPositionX(10f);
        gameObject.SetActiveOptimized(true);
    }
}
```

## よくあるバリエーション

| シナリオ | 調整方法 |
|------|---------|
| 特定のバージョンに固定する | `manifest.json` の `dependencies` で `"com.gameframex.unity"` を正確なバージョン番号（例：`"1.10.1"`）に記述し、Git URL の HEAD に追従しないようにします。 |
| 国内/海外ミニゲームプラットフォームへの統合 | Editor モジュールの MiniGame ツールと `BuildProduct` パイプラインを保持し、iOS/Android 以外のプラットフォームでこれらを除外しないでください。 |
| イントラネット/オフライン環境 | 方法二を優先し、Release パッケージをイントラネットにコピーしてから `Packages/` に解凍します。 |
| LiteJSON が必要 | 追加のインストールは不要です。フレームワークは `dependencies` で `com.gameframex.unity.litjson: 1.2.0` を推移的依存として宣言済みです。 |

Source: [package.json](/package.json#L21-L30)

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| UPM で Git URL を追加した後 `Unable to find package` と表示される | URL の誤記、または GitHub へアクセスできないネットワーク環境 | URL が `https://github.com/GameFrameX/com.gameframex.unity.git` であることを確認するか、`scopedRegistries` 方式で `scopes` を `com.gameframex` に設定してください |
| UPM で対応するバージョンが解決できない | `scopedRegistries` が追加されていない、または `scopes` の記述ミス | 方法三に従って `scopedRegistries` を補完し、`scopes` が `["com.gameframex"]` であることを確認してください |
| `GameEntry.GetComponent<...>()` で null 参照エラーが発生する | シーンにフレームワークエントリのプレハブがマウントされていない、またはエントリコンポーネントが有効化されていない | シーンにフレームワーク起動コンポーネントを追加してから呼び出してください。詳細は「クイックスタート」を参照 |
| コンパイル時に LitJSON が見つからない | 依存関係の削除またはバージョンの競合 | フレームワークを再導入するか、`com.gameframex.unity.litjson: 1.2.0` を個別に復元してください |
| Unity バージョンが 2019.4 未満 | フレームワークの最低サポートバージョン未達 | Unity を 2019.4 以降にアップグレードしてください([package.json](/package.json#L7)) |

## 背景（オプション）

`com.gameframex.unity` は GameFrameX フレームワークのコアパッケージであり、UPM を通じてランタイム依存関係（`com.gameframex.unity.litjson`）といくつかの Unity 内蔵モジュール（`assetbundle`、`audio`、`jsonserialize`、`unitywebrequest`、`androidjni`、`animation`、`imgui`）を同時に宣言しています。Unity 2019.4+ は `package.json` で明示的に要求されている最低バージョンであり、これを満たさない場合 UPM は依存関係の解決を拒否します。
