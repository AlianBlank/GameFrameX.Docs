# 작동 원리: 플랫폼 라우팅과 컴포넌트 조립

`PaymentComponent`는 `Awake()`에서 현재 컴파일 플랫폼의 Unity 매크로에 따라 결제 관리자 구현 클래스의 전체 이름 문자열을 선택한 뒤, 리플렉션을 통해 이를 `IPaymentManager` 모듈로 조립합니다. 각 플랫폼의 구체적인 구현(구글, 애플, WebGL, PC)은 독립 패키지에서 제공되며, 이 저장소에는 라우팅 프레임워크, 인터페이스, 기본 구현만 포함됩니다.

## 플랫폼 라우팅 결정 테이블

`PaymentComponent`의 5개 `[SerializeField]` 필드는 각 플랫폼의 구현 클래스 전체 이름을 저장하며, Inspector에서 덮어쓸 수 있습니다:

```csharp
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L24-L28)

런타임에는 컴파일 매크로에 따라 다음 중 하나로 라우팅됩니다:

| 컴파일 매크로 | 사용 필드 | 기본 구현 클래스 전체 이름 |
|------|------|------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager` |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `m_componentPCType` | `GameFrameX.Payment.PC.Runtime.PCPaymentManager` |
| `UNITY_STANDALONE_OSX` | `m_componentMacType` | `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager` |
| 기타 플랫폼 | 없음 | `typeof(DefaultPaymentManager).FullName` |

```csharp
protected override void Awake()
{
#if UNITY_ANDROID
    componentType = m_componentAndroidType;
#elif UNITY_IOS
    componentType = m_componentIOSType;
#elif UNITY_WEBGL
    componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
    componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
    componentType = m_componentMacType;
#else
    componentType = typeof(DefaultPaymentManager).FullName;
#endif
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IPaymentManager);
    base.Awake();

    _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
    if (_paymentManager == null)
    {
        Log.Fatal("Pay Manager is invalid.");
        return;
    }
}
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## 컴포넌트 조립 흐름

시작 시 조립은 다음 순서대로 발생하며, 각 단계는 위의 소스 코드에서 찾아볼 수 있습니다:

1. `PaymentComponent`는 씬 오브젝트에 부착되는 Unity 컴포넌트로, `[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]`가 지정되어 있으며 `GameFrameworkComponent`를 상속합니다.
2. `Awake()`가 컴파일 매크로에 따라 구현 클래스 전체 이름 하나를 선택해 기본 클래스 필드 `componentType`에 기록합니다.
3. `Utility.Assembly.GetType(componentType)`가 리플렉션으로 구현 클래스의 `Type`을 解析하여 `ImplementationComponentType`에 할당합니다; `InterfaceComponentType`은 `typeof(IPaymentManager)`로 고정됩니다.
4. `base.Awake()`(GameFrameworkComponent의 로직)가 이 두 `Type`에 따라 모듈 인스턴스를 생성/등록합니다.
5. `GameFrameworkEntry.GetModule<IPaymentManager>()`가 조립된 모듈을 가져와 `_paymentManager`에 저장합니다; 가져오지 못하면 `Log.Fatal("Pay Manager is invalid.")`가 호출됩니다.
6. 이후 `PaymentComponent`의 모든 공개 메서드(`Init`, `IsReady`, `Buy`, `QueryPurchases`, `ConsumePurchase` 등)는 매개변수 검증 후 `_paymentManager`로 전달하기만 합니다.

예를 들어 `Buy`의 전달과 검증은 다음과 같습니다:

```csharp
[UnityEngine.Scripting.Preserve]
public void Buy(PurchaseParams purchaseParams)
{
    if (purchaseParams == null)
    {
        Log.Warning("Purchase params is null.");
        return;
    }

    if (string.IsNullOrEmpty(purchaseParams.ProductId))
    {
        Log.Warning("Product ID is null or empty.");
        return;
    }

    if (string.IsNullOrEmpty(purchaseParams.OrderId))
    {
        Log.Warning("Order ID is null or empty.");
        return;
    }

    _paymentManager.Buy(purchaseParams);
}
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L238-L259)

## 구현 측의 계약: BasePaymentManager

각 플랫폼 패키지(구글, 애플 등)의 관리자는 `BasePaymentManager : GameFrameworkModule, IPaymentManager`를 상속합니다. 이 클래스는 네 개의 이벤트(`OnPurchaseSuccess`, `OnPurchaseFailed`, `OnQueryPurchasesResult`, `OnConsumePurchaseResult`)를 한곳에 선언하고, 하위 클래스가 이벤트를 발생시킬 수 있도록 `RaiseXxx(e)` protected 메서드를 제공하며, 동시에 `Init`, `IsReady` 등을 추상 멤버로 선언합니다:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    [UnityEngine.Scripting.Preserve]
    protected BasePaymentManager()
    {
    }

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);

    [UnityEngine.Scripting.Preserve]
    public abstract bool IsReady();
```

출처: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L74)

`PaymentComponent`의 동명 이벤트는 `_paymentManager`의 이벤트(add/remove 접근자)로 직접 연결되므로, 상위 계층의 구독과 구현 측의 트리거가 동일한 이벤트 소스를 공유합니다:

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseSuccess
{
    add { _paymentManager.OnPurchaseSuccess += value; }
    remove { _paymentManager.OnPurchaseSuccess -= value; }
}
```

출처: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L33-L37)

## 스트리핑 방지: GameFrameXPaymentCroppingHelper

`PaymentComponent`는 `GameFrameXPaymentCroppingHelper`와 반드시 같은 오브젝트에 공존해야 합니다(`[RequireComponent]`). 이 Helper의 `Start()`는 `_ = typeof(...)`를 사용해 인터페이스, 기본 구현, 매개변수/이벤트 타입을 강하게 참조함으로써, 코드 스트리핑이나 IL2CPP 패키징 시 이 타입들이 잘려나가지 않도록 보장합니다:

```csharp
[Preserve]
public class GameFrameXPaymentCroppingHelper : MonoBehaviour
{
    [Preserve]
    void Start()
    {
        _ = typeof(PaymentComponent);
        _ = typeof(BasePaymentManager);
        _ = typeof(IPaymentManager);
        _ = typeof(DefaultPaymentManager);
        _ = typeof(PurchaseParams);
        _ = typeof(PaymentEventArgs);
        _ = typeof(PaymentProductType);
        _ = typeof(PaymentResultCode);
    }
}
```

출처: [GameFrameXPaymentCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/GameFrameXPaymentCroppingHelper.cs#L12-L27)

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 로그에 `Pay Manager is invalid.`(Fatal) 발생 | `GameFrameworkEntry.GetModule<IPaymentManager>()`가 null을 반환함. 주로 라우팅 문자열에 해당하는 구현 패키지가 설치되지 않았거나 클래스 이름이 변경된 경우 | 해당 플랫폼의 결제 구현 패키지를 설치하거나, Inspector에서 해당 플랫폼의 `Type` 필드를 올바른 클래스 전체 이름으로 되돌리기 |
| 기본 구현으로 실행되어 실제 결제가 동작하지 않음 | 현재 플랫폼이 다섯 개의 매크로 분기에 해당하지 않음(예: 에디터 또는 기타 플랫폼)으로 `DefaultPaymentManager`로 라우팅됨 | 예상된 동작임; 실기기에서 해당 플랫폼으로 빌드해야 구체적인 구현으로 라우팅됨 |
| 스트리핑/IL2CPP 패키징 후 타입 손실 | 리플렉션으로 로드되는 타입이 잘려나감 | `GameFrameXPaymentCroppingHelper`의 강한 참조로 이미 방지됨; 해당 컴포넌트를 제거하지 말 것 |
| `Buy` 호출 시 아무 반응 없이 Warning 로그만 출력됨 | `purchaseParams`가 null이거나 `ProductId`/`OrderId`가 비어 있어 매개변수 검증에서 바로 return됨 | `PurchaseParams`의 필수 필드를 확인한 뒤 호출할 것 |

## 배경

직접 `typeof(...)`를 쓰지 않고 "문자열 전체 이름 + 리플렉션"을 사용하는 이유는 다음과 같습니다: 각 플랫폼 구현은 독립 패키지(예: `com.gameframex.unity.payment.google`)에 위치하며, 이 저장소는 컴파일 시점에 이들을 참조하지 않습니다. 타입을 하드코딩하면 컴파일 의존성이 발생합니다. 반면 문자열은 대상 플랫폼으로 패키징할 때만 해석됩니다. 이렇게 하면 이 패키지를 단독으로 배포할 수 있고, 플랫폼 패키지는 필요에 따라 도입할 수 있으며, Inspector의 직렬화 필드를 통해 프로젝트가 코드를 수정하지 않고도 구현을 교체할 수 있습니다.
