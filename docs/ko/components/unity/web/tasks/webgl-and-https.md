# WebGL 플랫폼 사용 가이드 및 HTTPS 인증서 처리

이 페이지에서는 WebGL 플랫폼에서 GameFrameX Web으로 HTTP(S) 요청을 보내는 방법과, 자체 서명/신뢰할 수 없는 인증서를 만났을 때의 처리 방법을 설명합니다. 이 라이브러리는 C# Task 비동기 패턴을 기반으로 하며 WebGL, PC, 모바일을 크로스 플랫폼으로 지원하고, WebGL에서의 요청은 최종적으로 브라우저 네트워크 스택에 의해 실행됩니다.

## 사전 조건

- Unity 2019.4 이상.
- 빌드 대상을 **WebGL**로 전환 완료(File → Build Settings → WebGL → Switch Platform).
- `com.gameframex.unity.web` 패키지 설치 완료(아래 단계 1 참조).

## 작업 단계

1. 패키지를 설치합니다. `Packages/manifest.json`에 scoped registry를 추가합니다(또는 Git URL을 직접 사용):

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.web": "1.3.5"
  }
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L43-L59)

   Package Manager에서 Git URL(`https://github.com/gameframex/com.gameframex.unity.web.git`)을 사용해도 되고, 저장소를 `Packages` 디렉터리에 클론하면 자동으로 로드됩니다.

2. 플랫폼을 WebGL로 전환한 후 `GameFrameworkEntry.GetModule<IWebManager>()`를 통해 네트워크 모듈을 가져옵니다.

3. `async/await`로 요청을 보냅니다. 다음은 바이너리 업로드의 전체 예제입니다(WebGL에도 동일하게 적용):

```csharp
public async Task UploadBinaryDataAsync(byte[] fileData, string fileName)
{
    var webManager = GameFrameworkEntry.GetModule<IWebManager>();

    var queryParams = new Dictionary<string, string>
    {
        { "fileName", fileName }
    };

    var headers = new Dictionary<string, string>
    {
        { "Content-Type", "application/octet-stream" },
        { "Authorization", "Bearer your-token" }
    };

    WebBufferResult result = await webManager.PostToBytes(
        "https://api.example.com/upload",
        fileData,
        queryParams,
        headers
    );

    if (result.IsSuccess)
    {
        Debug.Log("Upload successful!");
        byte[] responseData = result.Data;
    }
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/README.md#L75-L104)

4. 브라우저 콘솔에서 요청을 점검해야 할 때는 로그 매크로 스위치를 켭니다(컴파일 시점에 적용):

```csharp
public static class WebLogScriptingDefineSymbols
{

    public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_SEND_LOG";

    [MenuItem("GameFrameX/Scripting Define Symbols/Enable Web Receive Logs(开启Web接收日志打印)", false, 461)]
    public static void EnableNetworkReceiveLogs()
    {
        ScriptingDefineSymbols.AddScriptingDefineSymbol(EnableNetworkReceiveLogScriptingDefineSymbol);
    }

    [MenuItem("GameFrameX/Scripting Define Symbols/Enable Web Send Logs(开启Web发送日志打印)", false, 451)]
    public static void EnableNetworkSendLogs()
    {
        ScriptingDefineSymbols.AddScriptingDefineSymbol(EnableNetworkSendLogScriptingDefineSymbol);
    }
}
```

Source: [WebLogScriptingDefineSymbols.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/WebLogScriptingDefineSymbols.cs#L40-L79)

   전체 네 개의 메뉴 항목은 `GameFrameX/Scripting Define Symbols/` 아래에 있습니다: Enable/Disable Web Receive Logs(461/460)와 Enable/Disable Web Send Logs(451/450). WebGL 빌드 전에 켜면 브라우저 콘솔에서 송수신 로그를 확인할 수 있습니다.

## HTTPS 인증서 처리

- 저장소에는 인증서 검증 실패 시나리오를 우회하기 위한 인증서 바이패스 컴포넌트 [DefaultBypassCertificate.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/DefaultBypassCertificate.cs)가 내장되어 있으며, 자체 `IWebManager` 구현 또는 커스텀 검증 로직 작성 시 참고할 수 있습니다.
- 저장소 소스 코드에서 `UNITY_WEBGL`을 검색해도 결과가 없습니다: 이 패키지에는 WebGL 전용 코드 분기가 없으며, WebGL 빌드에서의 TLS 핸드셰이크와 인증서 검증은 브라우저 네트워크 스택이 담당하므로 에디터/네이티브 플랫폼의 바이패스 콜백은 WebGL 페이지에 적용되지 않습니다.
- 따라서 WebGL 배포의 권장 방법은 **사이트와 API 도메인에 신뢰할 수 있는 유효한 인증서를 설정하는 것**입니다(예: Let's Encrypt). 자체 서명 인증서는 리버스 프록시/게이트웨이 측에서 TLS를 종결하고, 클라이언트 우회에 의존하지 마세요.
- 페이지와 API의 프로토콜은 반드시 일치해야 합니다: HTTPS 페이지에서 HTTP API를 요청하면 브라우저가 "혼합 콘텐츠(Mixed Content)"로 차단하므로, WebGL 페이지에서는 `https://` API 주소로 통일하세요.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 브라우저 콘솔에 혼합 콘텐츠/Mixed Content 차단 오류 표시 | HTTPS 페이지에서 HTTP API 요청 | API URL을 `https://`로 통일 |
| WebGL 요청이 거부되고 인증서를 신뢰할 수 없다는 메시지 표시 | 사이트 또는 API에서 자체 서명/만료된 인증서 사용 | 도메인에 신뢰할 수 있는 인증서 발급 또는 게이트웨이 측에서 TLS 종결 |
| 에디터에서는 인증서 바이패스가 유효, WebGL 빌드 후에는 무효 | WebGL의 TLS 검증은 브라우저가 수행하며 클라이언트 콜백은 관여하지 않음 | 클라이언트 우회에 의존하지 말고 서버 인증서를 수정 |
| 요청 시간 초과 | 네트워크에 도달할 수 없거나 서버가 응답하지 않음 | README의 예외 처리 패턴에 따라 `WebExceptionStatus.Timeout` 캡처 |
| WebGL에서 요청 로그가 보이지 않음 | 송수신 로그 매크로 미활성화 | GameFrameX/Scripting Define Symbols 메뉴에서 해당 매크로를 켠 후 다시 빌드 |

시간 초과 등의 예외는 아래 패턴으로 캡처합니다(README 공식 예제):

```csharp
public async Task<string> SafeWebRequestAsync(string url)
{
    try
    {
        return await webManager.GetToString(url);
    }
    catch (WebException ex) when (ex.Status == WebExceptionStatus.Timeout)
    {
        Debug.LogError("Request timeout: " + ex.Message);
        return null;
    }
    catch (IOException ex)
    {
        Debug.LogError("Network IO error: " + ex.Message);
        return null;
    }
}
```

## 자주 사용하는 API 빠른 참조

핵심 인터페이스는 [IWebManager](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs)이며, 자주 사용하는 시그니처(README API Reference에서 발췌):

| 메서드 | 시그니처 | 설명 |
|------|------|------|
| GetToString | `Task<string> GetToString(string url)` | GET 요청, 문자열 반환 |
| GetToBytes | `Task<byte[]> GetToBytes(string url, Dictionary<string, string> queryString, Dictionary<string, string> header)` | GET 요청, 바이트 배열 반환 |
| PostToString | `Task<string> PostToString(string url, Dictionary<string, string> formData = null)` | POST 폼, 문자열 반환 |
| PostToBytes | `Task<WebBufferResult> PostToBytes(string url, byte[] binaryData, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | POST 바이너리 업로드 |
| GetProtoBuf | `Task<T> GetProtoBuf<T>(string url) where T : class, IExtensible` | Protocol Buffers GET |
| PostProtoBuf | `Task<T> PostProtoBuf<T>(string url, IExtensible requestData) where T : class, IExtensible` | Protocol Buffers POST |

## 배경

GameFrameX Web은 크로스 플랫폼 HTTP 네트워크 라이브러리로, 문자열, JSON, 바이너리 및 Protocol Buffers를 지원하며 연결 풀 재사용과 최대 동시 연결 제어 기능을 제공합니다(README Features 목록 참조). WebGL 빌드 시 Unity는 `HttpClient`/`HttpWebRequest` 요청을 브라우저의 Fetch/XHR로 변환하므로, TLS, CORS, 혼합 콘텐츠 등의 정책은 모두 브라우저가 결정합니다 — 이것이 인증서 문제를 반드시 서버 측에서 해결해야 하는 이유입니다. 네트워크 라이브러리의 전체 기능에 대해서는 공식 문서 https://gameframex.doc.alianblank.com 을 참조하세요.
