# AssemblyResourceProvider によるリソース提供の設定方法

`AssemblyResourceProvider` は GameFrameX ローカリゼーションフレームワークのアセンブリレベルリソースプロバイダであり、.NET アセンブリに埋め込まれた `.resources` ファイルからローカライズ文字列を読み込む役割を担います。初回アクセス時に遅延読み込みが行われ、完了後は内蔵リソースと同様に `LocalizationService.GetString(...)` で文字列を取得できます。このページでは、カスタムアセンブリでのリソースファイルの準備方法、このプロバイダの構築方法、および `ResourceManager` への組み込み方法について説明します。

## 前提条件

- `GameFrameX.Foundation.Localization` NuGet パッケージがインストールされていること。
- 対象プロジェクトが .NET アセンブリであり、`.resx` が `EmbeddedResource` としてアセンブリマニフェストに埋め込まれていること(埋め込まれていないと `GetManifestResourceNames()` がこれらのエントリを返さず、プロバイダが何もスキャンできません)。

## 操作手順

1. プロジェクト内の規約に従ったパスに `.resx` ファイルを作成します。デフォルト規約では `Localization/Messages/` ディレクトリ以下に配置し、ファイル名はカルチャごとに分割します(具体的な命名規則は後述)。

   ```text
   {AssemblyName}/
   └── Localization/
       └── Messages/
           ├── Resources.resx         # デフォルト/英語のフォールバック
           ├── Resources.zh-CN.resx   # 簡体字中国語
           └── Resources.en-US.resx   # アメリカ英語
   ```

   Source: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L216-L223)

2. `.csproj` で `.resx` を明示的に `EmbeddedResource` としてマークし、必要に応じてデフォルトの暗黙的埋め込みをオフにして、コンパイラの自動動作に依存しないようにします:

   ```xml
   <PropertyGroup>
     <EnableDefaultEmbeddedResourceItems>false</EnableDefaultEmbeddedResourceItems>
   </PropertyGroup>

   <ItemGroup>
     <EmbeddedResource Include="Localization\Messages\*.resx" />
   </ItemGroup>
   ```

   Source: [GameFrameX.Foundation.Localization/README.md](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/README.md#L110-L118)

3. リソースファイルを命名規則に従って命名し、プロバイダが `baseName` を正しく解析できるようにします。フレームワークが認識するマニフェストリソース名の規則は以下の通りです(`TryGetBaseName` から取得):

   | マニフェストリソース名の例 | 解析後の baseName | 用途 |
   |---|---|---|
   | `MyApp.Localization.Messages.Resources.resources` | `MyApp.Localization.Messages.Resources` | デフォルトカルチャ |
   | `MyApp.Localization.Messages.Resources.zh-CN.resources` | `MyApp.Localization.Messages.Resources` | 特定カルチャ `zh-CN` |
   | `MyApp.CustomPath.Resources.resources` | `MyApp.CustomPath.Resources` | カスタムパスのデフォルトカルチャ |
   | `MyApp.CustomPath.Resources.en.resources` | `MyApp.CustomPath.Resources` | カスタムパスのニュートラルカルチャ |
   | `MyApp.Category.resources` | `MyApp.Category` | 後方互換性のための 3 セグメント形式 |

   規則の要点:`.resources` で終わり、後ろから 2 番目のセグメントが `Resources` または有効なカルチャ名(`-` を含む、または `CultureInfo.GetCultureInfo` で識別可能)であること。セグメント数が 3 以上でないと認識されません。

   Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L282-L330)

4. コード内でプロバイダを構築し、読み込みをトリガーします。`AssemblyResourceProvider` は `IDisposable` なので、使用後は解放するべきです。

   ```csharp
   using System.Reflection;
   using GameFrameX.Foundation.Localization.Providers;

   var assembly = Assembly.GetExecutingAssembly();
   using var provider = new AssemblyResourceProvider(assembly);

   // オプション: 初回アクセス時の遅延を回避するため、先行して遅延読み込みをトリガーする
   provider.EnsureLoaded();

   string message = provider.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L104-L138)

5. `ResourceManager` に組み込んで統一された解決チェーンに含めます。`ResourceManager` は「カスタム → アセンブリ → デフォルト」の順序で検索します。フレームワークにすべてのアセンブリプロバイダを自動検出させるか、初期化後に指定したアセンブリを手動で登録することができます:

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // 方法 1: ResourceManager に現在ロード済みのアセンブリを自動スキャンさせる
   LocalizationService.EnsureLoaded();

   // 方法 2: 指定したアセンブリを手動で追加する
   LocalizationService.AddAssembly(Assembly.GetExecutingAssembly());

   var msg = LocalizationService.GetString("MyApp.Exceptions.InvalidArgument");
   ```

   Source: [ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L370-L450)

## よくあるバリエーション

- **ニュートラルカルチャ名**(例: `zh`、`fr`):後ろから 2 番目のセグメントがニュートラルカルチャ名の場合、`IsCultureSegment` が `CultureInfo.GetCultureInfo` でその有効性を検証し、`MyApp` のようなカテゴリ名をカルチャ名と誤判定するのを防ぎます。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L332-L360)

- **カスタムパス**(`Localization/Messages/` 以外):`{AssemblyName}.{任意のパス}.Resources[.{culture}].resources` のセグメント構造を満たしていれば認識されます。例えば `MyApp.LangPack.Resources.zh-CN.resx` → baseName `MyApp.LangPack.Resources`。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L256-L268)

- **キーが見つからない場合のフォールバック**:すべての `ResourceManager` で `GetString` 呼び出しにマッチするものがない場合、渡された `key` 文字列がそのまま返され、例外はスローされません。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L146-L178)

## よくあるエラー

- **リソースが効かない**:最も一般的な原因は、`.resx` が `EmbeddedResource` として埋め込まれていないこと、またはファイル名が上記の命名規則に従っていないことです。`assembly.GetManifestResourceNames()` を実行して、マニフェストに期待される名前が含まれているか確認してください。
- **同一アセンブリ内に同じ baseName の重複**:`LoadResources` は `BaseName` で重複排除を行い、最初にマッチした `ResourceManager` のみを保持し、後続の同名エントリは無視されます。
- **`GetString` が `MissingManifestResourceException` をスローする**:コードはこれをキャッチして他の `ResourceManager` の検索を続行するため、通常は伝播しません。ログに `Failed to load resource '{key}'` と表示されている場合は、すべてのマッチが失敗したことを意味し、フォールバックとして `key` が返されます。
- **アセンブリスキャンの失敗**:スキャン全体が `try/catch` でラップされ `Debug.WriteLine` に書き込まれますが、例外はスローされません。ただし、繰り返し試行を防ぐために `_isInitialized` が `true` にマークされるため、デバッグ出力を確認して根本原因を特定する必要があります。

  Source: [AssemblyResourceProvider.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Providers/AssemblyResourceProvider.cs#L204-L279)

## 背景(オプション)

`AssemblyResourceProvider` は `ILazyResourceProvider`、`ICultureResourceProvider`、`IDisposable` を実装しています。構築時にはリソースを即座にロードせず、`EnsureLoaded()` または `GetString()` の初回呼び出し時にアセンブリマニフェストをスキャンし、`baseName` で重複排除して `ResourceManager` を作成します。`ResourceManager` は `assembly.FullName` をキーとする `ConcurrentDictionary<string, AssemblyResourceProvider>` を維持し、外部には「カスタムプロバイダ > アセンブリプロバイダ > デフォルトプロバイダ」の優先度チェーンを提供します。リソース解決チェーン全体と統計インターフェースについては、[ResourceManager.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs) を参照してください。
