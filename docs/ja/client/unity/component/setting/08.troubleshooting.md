# よくある問題

このドキュメント汇总了使用 GameFrameX Setting 設定コンポーネント时〜の可能性があります遇到的常见問題、エラー情報及其解決策。

## 概要

GameFrameX Setting 設定コンポーネント是游戏フレームワーク的コアコンポーネント，负责管理游戏的設定情報。在使用过程中，開発者〜の可能性があります遇到初期化失敗、数据无法保存、プラットフォーム兼容性等問題。このドキュメント提供詳細的問題診断和解決策，帮助開発者快速定位和解决問題。

## 初期化問題

### 問題 1：Setting manager is invalid

**エラー情報：**
```
Log.Fatal("Setting manager is invalid.");
```

**原因分析：**
此エラー表示 `SettingComponent` 在 `Awake()` フェーズ无法从 `GameFrameworkEntry` 取得 `ISettingManager` モジュール。这通常是因为 GameFramework コアコンポーネント未正确初期化。

**解決策：**

1. 確認してくださいシーン中存在 GameFrameX コア入口コンポーネント
2. 確認 `GameFrameworkEntry` 是否已正确初期化
3. 確認してください SettingComponent 挂载在正确的 GameObject 上

```csharp
// 正确的初始化顺序
// 1. 先初始化 GameFrameworkEntry
GameFrameworkEntry.Initialize();

// 2. 然后 SettingComponent 会自动通过 Awake 获取管理器
var settingComponent = gameObject.AddComponent<SettingComponent>();
```

### 問題 2：Can not create setting helper

**エラー情報：**
```
Log.Error("Can not create setting helper.");
```

**原因分析：**
此エラー表示无法根据設定的タイプ名称作成設定辅助器インスタンス。〜の可能性があります原因：
- 設定的 Helper タイプ名称不正确
- 指定的 Helper 类不存在或未正确参照
- Helper タイプ没有无参コンストラクタ

**解決策：**

1. 確認 `SettingComponent` Inspector パネル上的 `Setting Helper Type Name` 設定
2. 確認してくださいタイプ名称完全な且正确（含みます名前空間）

```csharp
// 默认配置
// Setting Helper Type Name: GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper
// 或
// Setting Helper Type Name: GameFrameX.Setting.Runtime.DefaultSettingHelper
```

3. 可用的 Helper タイプ：
   - `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` - 基于 Unity PlayerPrefs
   - `GameFrameX.Setting.Runtime.DefaultSettingHelper` - 基于本地ファイル存储

### 問題 3：缺少必需的依赖コンポーネント

**エラー情報：**
Unity ランタイムエラー或コンポーネント无法正常工作

**原因分析：**
`SettingComponent` 使用了 `[RequireComponent(typeof(GameFrameXSettingCroppingHelper))]`，〜しなければなりません配合 `GameFrameXSettingCroppingHelper` コンポーネント使用。

**解決策：**

1. SettingComponent 会自动追加 GameFrameXSettingCroppingHelper 依赖コンポーネント
2. もし出现依赖問題，手动追加 GameFrameXSettingCroppingHelper 到同一 GameObject

## 数据操作問題

### 問題 4：Load settings failure

**エラー情報：**
```
Log.Error("Load settings failure.");
```

**原因分析：**
ロード設定失敗，〜の可能性があります原因：
- 設定ファイル损坏
- 存储介质不可用
- ファイル路径不存在
- シリアライズ/反シリアライズエラー

**解決策：**

1. **对于 DefaultSettingHelper：**
```csharp
// 检查文件是否存在
var helper = settingComponent.GetComponent<DefaultSettingHelper>();
string filePath = helper.FilePath;
Debug.Log($"Settings file path: {filePath}");
```

2. **例外処理：**
```csharp
try
{
    settingComponent.Save();
}
catch (Exception ex)
{
    Debug.LogError($"Save failed: {ex.Message}");
}
```

3. **確認ファイル权限：**
   - 確認してください Application.persistentDataPath 可写
   - 確認磁盘空间是否充足

### 問題 5：設定值未正確認してください存

**問題説明：**
呼び出し `Save()` メソッド后，設定值在重新ロード时丢失

**〜の可能性があります原因：**

1. **未呼び出し Save()**：設定值只在内存中変更，未持久化
2. **PlayerPrefs 未同步**：在某些プラットフォーム上 PlayerPrefs.Save() 〜する必要があります手动呼び出し
3. **WebGL プラットフォーム限制**：小程序プラットフォーム有特殊的存储机制

**解決策：**

```csharp
// 1. 修改设置后必须调用 Save()
settingComponent.SetString("PlayerName", "NewName");
settingComponent.Save();  // 必须调用

// 2. 使用 DefaultSettingHelper 确保数据持久化
// 其会自动保存到 Application.persistentDataPath/GameFrameworkSetting.dat
```

### 問題 6：GetAllSettingNames 返す null 或不サポート

**エラー情報：**
```
Log.Warning("GetAllSettingNames is not supported.");
```

**原因分析：**
`PlayerPrefsSettingHelper` 不サポート取得所有設定项名称的機能，因为 Unity PlayerPrefs 本身不提供列挙型所有键的 API。

> Source: [PlayerPrefsSettingHelper.cs#L96-L100](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L96-L100)

**解決策：**

1. **使用 DefaultSettingHelper 替代**：该 Helper サポート完全な的列挙型機能

```csharp
// 在 SettingComponent Inspector 中将 Helper 类型改为：
// GameFrameX.Setting.Runtime.DefaultSettingHelper
```

2. **自行维护設定键列表**：もし〜しなければなりません使用 PlayerPrefs，〜する必要があります自行记录所有設定的键名

### 問題 7：Count プロパティ返す -1

**問題説明：**
呼び出し `settingComponent.Count` 返す -1

**原因分析：**
`PlayerPrefsSettingHelper` 的 Count プロパティ始终返す -1，因为 Unity PlayerPrefs 不提供取得設定项数量的インターフェース。

> Source: [PlayerPrefsSettingHelper.cs#L52-L55](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L52-L55)

```csharp
public override int Count
{
    get { return -1; }  // PlayerPrefs 不支持获取数量
}
```

**解決策：**

1. 使用 `DefaultSettingHelper` 〜できます取得准确的設定项数量
2. または自行维护计数变量

## プラットフォーム兼容性問題

### 問題 8：WebGL 小程序プラットフォーム存储問題

**問題説明：**
在抖音、微信、快手等小程序プラットフォーム上，設定无法正常保存或读取

**原因分析：**
小程序プラットフォーム有各自的存储 API，不サポート Unity 原生 PlayerPrefs。フレームワーク针对这些プラットフォーム做了适配：

> Source: [PlayerPrefsSettingHelper.cs#L80-L86](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L80-L86)

```csharp
public override bool Save()
{
#if UNITY_WEBGL && (ENABLE_DOUYIN_MINI_GAME || ENABLE_WECHAT_MINI_GAME || ENABLE_KUAISHOU_MINI_GAME)
    return true;  // 小程序平台无需手动保存
#else
    UnityEngine.PlayerPrefs.Save();
    return true;
#endif
}
```

**解決策：**

1. 確認してください定義了正确的プラットフォーム宏：
   - `ENABLE_DOUYIN_MINI_GAME` - DouYinミニゲーム
   - `ENABLE_WECHAT_MINI_GAME` - WeChatミニゲーム
   - `ENABLE_KUAISHOU_MINI_GAME` - KuaiShouミニゲーム

2. 在 Unity Build Settings 中正确設定リリースプラットフォーム

### 問題 9：对象シリアライズ失敗

**問題説明：**
使用 `SetObject()` 或 `GetObject()` 时，对象数据无法正確認してください存或读取

**〜の可能性があります原因：**

1. 对象タイプ不サポート JSON シリアライズ
2. 对象パッケージ含不可シリアライズ的成员（如 delegate、EventHandler）
3. 循环参照导致シリアライズ失敗

**解決策：**

1. 確認してください对象类标记为 `[Serializable]`
2. 使用可シリアライズ的数据结构
3. 処理循环参照

```csharp
[Serializable]
public class PlayerData
{
    public string Name;
    public int Level;
    public List<Item> Items;
}

[Serializable]
public class Item
{
    public int Id;
    public int Count;
}

// 使用示例
var playerData = new PlayerData
{
    Name = "Player1",
    Level = 10,
    Items = new List<Item>()
};

settingComponent.SetObject("PlayerData", playerData);
settingComponent.Save();

// 读取数据
var loadedData = settingComponent.GetObject<PlayerData>("PlayerData");
```

## API 使用問題

### 問題 10：Setting name is invalid

**エラー情報：**
抛出 `GameFrameworkException("Setting name is invalid.")`

**原因分析：**
所有設定 API 都会確認設定名称是否为空。もし传入 null 或空字符串，将抛出例外。

> Source: [SettingManager.cs#L215-L218](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L215-L218)

```csharp
if (string.IsNullOrEmpty(settingName))
{
    throw new GameFrameworkException("Setting name is invalid.");
}
```

**解決策：**

```csharp
// 错误用法
settingComponent.SetBool("", true);  // 抛出异常

// 正确用法
settingComponent.SetBool("IsFullScreen", true);
```

### 問題 11：空值返す問題

**問題説明：**
使用无デフォルト值的メソッド取得不存在的設定时，返す意外的值

**原因分析：**
不同的数据タイプ在没有デフォルト值パラメータ时的デフォルト戻り値不同：

| 数据タイプ | 无デフォルト值メソッド戻り値 |
|----------|-------------------|
| bool | false |
| int | 0 |
| float | 0f |
| string | null |

**解決策：**

1. **始终使用带デフォルト值的メソッド**：
```csharp
// 不推荐
bool isFullScreen = settingComponent.GetBool("IsFullScreen");

// 推荐
bool isFullScreen = settingComponent.GetBool("IsFullScreen", false);
```

2. **先確認設定是否存在**：
```csharp
if (settingComponent.HasSetting("PlayerName"))
{
    string name = settingComponent.GetString("PlayerName");
}
else
{
    // 处理不存在的情况
}
```

## デバッグ技巧

### デバッグログ

启用詳細ログ来診断問題：

```csharp
// 在代码中添加调试信息
Debug.Log($"Settings Count: {settingComponent.Count}");
Debug.Log($"Has PlayerName: {settingComponent.HasSetting("PlayerName")}");

// 获取所有设置名称（仅 DefaultSettingHelper 支持）
string[] allNames = settingComponent.GetAllSettingNames();
foreach (var name in allNames)
{
    Debug.Log($"Setting: {name}");
}
```

### 確認 Helper 設定

```csharp
// 获取当前使用的 Helper 信息
var helper = settingComponent.GetComponent<SettingHelperBase>();
Debug.Log($"Helper Type: {helper.GetType().Name}");
Debug.Log($"Helper FilePath: {(helper is DefaultSettingHelper dh ? dh.FilePath : "N/A")}");
```

## 常见エラー对照表

| エラー情報 | 原因 | 解決策 |
|----------|------|----------|
| Setting manager is invalid | GameFramework 未初期化 | 確認してください GameFrameworkEntry 已初期化 |
| Can not create setting helper | Helper タイプ名称エラー | 確認 Inspector 設定 |
| Load settings failure | 設定ファイル损坏或路径エラー | 確認ファイル路径和权限 |
| Save settings failure | 存储介质不可用 | 確認磁盘空间和权限 |
| GetAllSettingNames is not supported | 使用了 PlayerPrefsHelper | 改用 DefaultSettingHelper |
| Setting name is invalid | 設定名称为空 | 使用非空字符串作为键名 |
| Count returns -1 | PlayerPrefs 不サポート计数 | 使用 DefaultSettingHelper |
