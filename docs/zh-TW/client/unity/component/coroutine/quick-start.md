# 快速上手:安裝並啟動第一個協程

本指南帶你把 GameFrameX 協程套件接入 Unity 專案，並跑通「啟動→停止→幀尾回呼」三個最常用的介面。本元件是對 Unity 原生協程的薄封裝，會在內部以 `ConcurrentDictionary` 追蹤所有啟動過的協程，避免漏停導致的懸掛參考。

## 前置條件

- Unity 2017.1 或更高版本(測試目標為 Unity 2019.4)
- 一個能正常開啟的 Unity 專案
- 專案裡已安裝 `com.gameframex.unity.runtime`(本元件繼承自其 `GameFrameworkComponent`)

## 安裝

選擇以下任一方式把套件加入專案：

1. **透過 Scoped Registry(推薦)** —— 編輯 `Packages/manifest.json`,在 `scopedRegistries` 中加入 GameFrameX 註冊表，並宣告相依性：

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.coroutine": "1.0.3"
     }
   }
   ```

2. **透過 Git URL** —— 在 `dependencies` 下直接寫：

   ```json
   "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
   ```

3. **透過 Package Manager** —— 使用 `Add package from Git URL`,填入上面的儲存庫位址。

4. **手動放置** —— 把整個儲存庫複製到專案的 `Packages/` 目錄下，Unity 會自動識別。

## 操作步驟

1. **取得 CoroutineComponent 實例。** 由於該元件帶有 `[DisallowMultipleComponent]` 與 `[GameFrameXAutoComponent(-6500)]` 特性，通常由 GameFrameX 框架自動註冊到一個掛載了 `GameFrameworkEntry` 的 GameObject 上。手動方式如下：

   ```csharp
   var coroutineComponent = gameObject.AddComponent<GameFrameX.Coroutine.Runtime.CoroutineComponent>();
   ```

   來源： [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L21)

2. **撰寫協程方法。** 協程簽章必須傳回 `IEnumerator`,內部用 `yield return` 控制節奏：

   ```csharp
   IEnumerator HelloCoroutine()
   {
       Debug.Log("Hello");
       yield return null;            // 等一幀
       Debug.Log("Next frame");
   }
   ```

3. **啟動協程。** 呼叫 `StartCoroutine` 並儲存傳回的迭代器實例，以便後續停止：

   ```csharp
   IEnumerator routine = HelloCoroutine();
   coroutineComponent.StartCoroutine(routine);
   ```

   注意：必須透過 `CoroutineComponent` 型別參考呼叫 `StartCoroutine`,因為它用 `new` 關鍵字隱藏了基底類別方法，以保證寫入追蹤字典。

   來源： [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

4. **停停單一協程(可選)。** 把啟動時儲存的同一個 `IEnumerator` 實例傳回去：

   ```csharp
   coroutineComponent.StopCoroutine(routine);
   ```

   該多載會先在字典裡查表找到對應的 `UnityEngine.Coroutine`,停止後再從字典移除；若找不到則回退到 `base.StopCoroutine(enumerator)`。

   來源： [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

5. **停止全部協程(可選)。** 在切換場景或重置邏輯時呼叫：

   ```csharp
   coroutineComponent.StopAllCoroutines();
   ```

   實作會先逐個停止字典裡追蹤的協程、清空字典，再呼叫 `base.StopAllCoroutines()`,對未被追蹤的協程做最後清理。

   來源： [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

6. **幀尾回呼(可選)。** 當你需要在目前幀所有渲染完成後做點事情(例如截圖、上報)，使用：

   ```csharp
   coroutineComponent.WaitForEndOfFrameFinish(() =>
   {
       Debug.Log("End of frame");
   });
   ```

   內部會重複使用同一個 `WaitForEndOfFrame` 一次性物件，避免每次呼叫產生 GC 配置。

   來源： [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

## 常見變體

- **透過 `UnityEngine.Coroutine` 多載停止**：當只持有 Unity 傳回的協程控制代碼時，使用 `StopCoroutine(UnityEngine.Coroutine coroutine)` 多載，內部會反向遍歷字典找到對應迭代器並清理。
- **不要在 `WaitForEndOfFrameFinish` 回呼裡拋出例外**：若在幀結束前透過 `StopCoroutine` 停止了該協程，回呼將不會執行，無需再做防禦性的空值判斷。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `StartCoroutine` 後字典裡查不到 | 呼叫到了 `MonoBehaviour.StartCoroutine` 而不是 `CoroutineComponent.StartCoroutine` | 一律透過 `CoroutineComponent` 型別的參考呼叫，確保走的是 `new` 隱藏版本 |
| `StopCoroutine` 無效 | 傳入了一個**重新建構**的 `IEnumerator`(例如再次呼叫 `HelloCoroutine()`)| 重複使用啟動時儲存的同一個 `IEnumerator` 實例，因為字典以參考相等性為 key |
| `StopAllCoroutines` 後仍有協程在跑 | 呼叫的是一般 `MonoBehaviour.StopAllCoroutines()` | 呼叫 `CoroutineComponent.StopAllCoroutines()`,確保追蹤字典一併清空 |
| 幀尾回呼沒觸發 | 在回呼應執行前呼叫了 `StopCoroutine`/`StopAllCoroutines` | 把回呼裡要做的邏輯放到下一幀，或等待 `yield return new WaitForEndOfFrame()` 後再判斷 |
