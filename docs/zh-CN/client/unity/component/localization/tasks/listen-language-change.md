# 如何监听语言变化事件并刷新界面文本

给 `LocalizationComponent.Language` 赋新语言时,组件会依次广播三个语言变化事件;在界面脚本中订阅其中之一(推荐 `LocalizationLanguageChangeAfterEventArgs`),即可在回调里拿到新旧语言并刷新界面文本。

## 前置条件

- 项目已启用 GameFrameX 的 Localization 与 Event 组件。
- 场景中存在 `LocalizationComponent`:切换语言时会通过它依赖的 `SettingComponent` 持久化语言设置,并通过 `EventComponent` 派发事件。

## 操作步骤

三个事件都携带相同的数据(`Language` 新语言、`OldLanguage` 旧语言),按需选一个订阅即可:

| 事件参数类 | 派发顺序 | 适用场景 |
|------|------|------|
| `LocalizationLanguageChangeBeforeEventArgs` | 1 | 切换流程最先收到通知,适合做切换前的记录/准备 |
| `LocalizationLanguageChangeEventArgs` | 2 | 通用语言变化事件 |
| `LocalizationLanguageChangeAfterEventArgs` | 3 | 切换完成通知,推荐在这里刷新界面文本 |

三个事件在 `Language` 赋值器中同步、连续派发:

```csharp
set
{
    if (m_LocalizationManager.Language != value)
    {
        var oldLanguage = m_LocalizationManager.Language;
        m_LocalizationManager.Language = value;
        m_SettingComponent.SetString(nameof(LocalizationComponent) + "." + nameof(Language), value);
        m_SettingComponent.Save();
        var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
        var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
        var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
    }
}
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L155-L171)

### 1. 编写事件处理方法

回调参数直接使用对应事件参数类,从中读取新语言与旧语言:

```csharp
private void OnLanguageChanged(object sender, LocalizationLanguageChangeAfterEventArgs e)
{
    Debug.Log($"语言由 {e.OldLanguage} 切换为 {e.Language}");
    // 在这里按 e.Language 重新取文案,刷新本界面的所有文本控件
}
```

事件参数类的 `Language` / `OldLanguage` 定义与 `EventId` 如下,`EventId` 即类型完整名:

```csharp
[Preserve] public static readonly string EventId = typeof(LocalizationLanguageChangeAfterEventArgs).FullName;

[Preserve]
public string Language { get; private set; }   // 当前(新)语言

[Preserve]
public string OldLanguage { get; private set; } // 旧语言
```

Source: [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41-L67)

### 2. 注册与取消监听

事件通过 GameFrameX 的 Event 组件派发(`m_EventComponent.Fire(...)`)。用 `EventId` 常量注册监听,并在界面销毁/禁用时退订,典型写法:

```csharp
private void OnEnable()
{
    GameEntry.Event.AddListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}

private void OnDisable()
{
    GameEntry.Event.RemoveListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}
```

> 说明:`AddListener` / `RemoveListener` 的确切签名以 com.gameframex.unity.event 包为准;本仓库的本地化组件只负责用 `EventId`(类型完整名,即 `GameFrameX.Localization.Runtime.LocalizationLanguageChangeAfterEventArgs`)派发事件。

### 3. 切换语言触发事件

给 `Language` 赋一个与当前不同的语言值即可触发全部三个事件:

```csharp
GameEntry.GetComponent<LocalizationComponent>().Language = "ChineseSimplified";
```

赋值的同时会自动把语言写入设置(键名 `LocalizationComponent.Language`)并保存,下次启动可读回。

### 4. 在回调中刷新文本

在步骤 1 的回调里,按 `e.Language`(或组件当前 `Language`)重新加载对应语言文案并更新各文本控件;也可以只刷新语言相关的控件,无需重建界面。

## 验证

- 切换语言后,步骤 1 回调中的日志应打印旧语言与新语言;
- 把语言设置为与当前相同的值,回调**不会**被触发(赋值器有 `!=` 判断,见上文 Source 第 157 行)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 切换语言后回调没执行 | 监听时使用的 ID 与事件实际 ID 不一致 | 统一使用事件类自带的常量 `LocalizationLanguageChangeAfterEventArgs.EventId`,不要手写字符串 |
| 回调里读到的语言是 `UnknownLocalization` | 未正确处理事件参数的引用池重用 | 回调内即取即用 `e.Language` / `e.OldLanguage`,不要缓存事件参数对象本身 |
| 反复切换语言后收到重复事件 | 退订时机不对或重复注册 | 在 `OnEnable` 注册、`OnDisable` 退订,保证成对出现 |
| 设置相同语言后想刷新文本但没反应 | 赋值器对相同值短路,不派发事件 | 需要强制刷新时,在调用处自行触发刷新逻辑,或先设置为目标语言以外的值再切回 |

## 背景

三个事件参数类均继承 `GameEventArgs`,实例通过 `ReferencePool.Acquire<T>()` 获取(引用池复用),因此不要长期持有事件参数对象。语言变化由 `LocalizationComponent.Language` 的 setter 统一驱动:先更新管理器语言并持久化设置,再以"Before → Change → After"顺序同步派发三个事件,监听方无需区分时序差异,任选其一即可。
