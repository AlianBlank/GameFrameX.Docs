# EventComponent / IEventManager API クイックリファレンス

このページでは、GameFrameX.Event イベントモジュールの外部向け公開 API をすべて収録しています：シーンコンポーネント `EventComponent` とその背後にあるインターフェース `IEventManager` で、実際のシグネチャ、イベント引数の基底クラス、スレッドセーフティに関する説明を含み、表のまま直接参照して利用できます。

## コンポーネントの取得

`EventComponent` はシーンにアタッチする Unity コンポーネントです（メニューパス `GameFrameX/Event`、`[DisallowMultipleComponent]`、コンポーネント優先度 -7000）。`Awake` 内で `GameFrameworkEntry.GetModule<IEventManager>()` を通じてイベントマネージャーを取得し、その後すべての公開メソッドはそのマネージャーに直接転送されます。日常のビジネスコードでは `EventComponent` を使用するだけでよく、自分で `IEventManager` の実装を作成する必要はありません。

## EventComponent 公開 API

| 名称 | シグネチャ | 説明 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | イベントハンドラー関数の総数を取得 |
| EventCount | `int EventCount { get; }` | イベント数を取得 |
| Count | `int Count(string id)` | 指定したイベント ID のイベントハンドラー関数の数を取得 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 指定したイベントがこのハンドラー関数を既に購読しているかを確認 |
| CheckSubscribe | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 存在しない場合のみ購読し、重複購読を回避 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | イベントハンドラー関数の購読を解除 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 確認して購読解除；handler が存在しない場合は何も実行しない |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | デフォルトのイベントハンドラー関数を設定（購読者がいない場合のフォールバック） |
| Fire | `void Fire(object sender, GameEventArgs e)` | イベントを発火；スレッドセーフ、メインスレッドでコールバック、次のフレームで配信 |
| Fire（オーバーロード） | `void Fire(object sender, string eventId)` | `eventId` で `EmptyEventArgs` を作成して発火；内部で `GameFrameworkGuard.NotNullOrEmpty` を呼び出して非空を検証 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | イベントを即時モードで発火；非スレッドセーフ、即時に配信 |

Source: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L171)

なお `CheckSubscribe` は `EventComponent` 固有の便利メソッドです（インターフェースには存在しません）：まず `Check` を呼び出し、未購読の場合のみ基盤の `Subscribe` を呼び出します。

```csharp
if (!Check(id, handler))
{
    m_EventManager.Subscribe(id, handler);
}
```

## IEventManager インターフェースメンバー

`EventComponent` は `Subscribe` の転送メソッドを公開しておらず、基盤の購読は統一的にインターフェースを通じて行われます（コンポーネント層では代わりに `CheckSubscribe` を提供）。インターフェースの定義は以下の通りです：

| 名称 | シグネチャ | 説明 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | イベントハンドラー関数の数を取得 |
| EventCount | `int EventCount { get; }` | イベント数を取得 |
| Count | `int Count(string id)` | 指定したイベント ID のイベントハンドラー関数の数を取得 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | イベントハンドラー関数が存在するかを確認 |
| Subscribe | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | イベントハンドラー関数を購読 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | イベントハンドラー関数の購読を解除 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 確認して購読解除；handler が存在しない場合は何も実行しない |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | デフォルトのイベントハンドラー関数を設定 |
| Fire | `void Fire(object sender, GameEventArgs e)` | イベントを発火；スレッドセーフ、メインスレッドでコールバック、イベントは発火後の次のフレームで配信 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | イベントを即時モードで発火；スレッドセーフではなく、イベントは即時に配信される |

Source: [Runtime/Event/IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L38-L105)

`EventComponent` との違いの一覧：

- `EventComponent.CheckSubscribe(id, handler)` は `IEventManager.Subscribe(id, handler)` の「確認後に購読」版に相当します。
- `EventComponent.Fire(object sender, string eventId)` はコンポーネント固有の文字列オーバーロードで、`Fire(sender, EmptyEventArgs.Create(eventId))` と等価です。
- 初期化に失敗した場合、コンポーネントは `Log.Fatal("Event manager is invalid.")` を出力します。

## イベント引数の型

| 型 | 定義 | 説明 |
|------|------|------|
| `GameEventArgs` | `public abstract class GameEventArgs : BaseEventArgs` | すべてのゲームロジックイベントの抽象基底クラス。カスタムイベントはこれを継承します |
| `EmptyEventArgs` | `public static EmptyEventArgs Create(string eventId)` | ペイロードなしのイベント；`ReferencePool.Acquire<EmptyEventArgs>()` から取得してイベント ID を設定し、`EventComponent.Fire(sender, eventId)` と組み合わせて使用します |

```csharp
public static EmptyEventArgs Create(string eventId)
{
    var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
    eventArgs.SetEventId(eventId);
    return eventArgs;
}
```

## Fire と FireNow の使い分け

| シナリオ | 使用方法 | 理由 |
|------|------|------|
| サブスレッド / 非同期タスク内でイベントを発火 | `Fire(sender, e)` | スレッドセーフで、コールバックはメインスレッドで実行されることが保証されるが、次のフレームまで配信が遅延する |
| メインスレッド内でコールバックを同期的に実行する必要がある | `FireNow(sender, e)` | 即時に配信；非スレッドセーフのため、サブスレッドから呼び出さないでください |
| シグナルのトリガーのみが必要で、追加データがない | `Fire(sender, eventId)` | コンポーネントのオーバーロードが自動的に `EmptyEventArgs` を作成（内部で参照プールを経由） |

以上のスレッドセマンティクスは、ソースコード内の 2 か所のコメントによるものです：`Fire`「この操作はスレッドセーフであり、メインスレッド以外で発火しても、イベントハンドラー関数がメインスレッドでコールバックされることが保証されますが、イベントは発火後の次のフレームで配信されます」；`FireNow`「この操作はスレッドセーフではなく、イベントは即時に配信されます」。
