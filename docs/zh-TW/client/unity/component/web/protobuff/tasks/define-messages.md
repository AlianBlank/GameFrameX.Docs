# 如何定義請求與回應訊息型別

在 GameFrameX Web ProtoBuff 中,請求訊息只需繼承 `GameFrameX.Network.Runtime.MessageObject` 並按 protobuf-net 規則標註 `[ProtoContract]`/`[ProtoMember]`;回應訊息在此基礎上還要實作 `GameFrameX.Network.Runtime.IResponseMessage` 介面,才能作為 `WebComponent.Post<T>` 的泛型參數被反序列化回傳。型別約束全部由 API 簽章在編譯期強制，定義對了就能直接 `await` 取得強型別回應。

## 前置條件

- 已安裝 `com.gameframex.unity.web.protobuff` 套件(參見 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.zh-CN.md#L43-L74))。
- 在 Unity 的 **Player Settings → Scripting Define Symbols** 中新增巨集 `ENABLE_GAME_FRAME_X_WEB_PROTOBF_NETWORK`(README 中寫為 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`)。沒有該巨集，元件中相關的 `Post<T>` 方法不會參與編譯(整個實作包在 `#if ... #endif` 條件編譯內)。
- 專案中已引入 protobuf-net(`using ProtoBuf;`),訊息類別用它產生或手寫。

## 操作步驟

### 1. 確認編譯期型別約束

先看清 API 對兩邊的訊息型別各有什麼要求，再動手定義：

| 角色 | 必須滿足的條件 | 出處 |
|------|----------------|------|
| 請求訊息(`message` 參數) | 繼承 `MessageObject` | [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108) |
| 回應訊息(泛型 `T`) | 繼承 `MessageObject` **且** 實作 `IResponseMessage` | [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108) |

元件對外暴露的真實簽章(`where` 子句即全部硬性要求)：

```csharp
public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message)
    where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
{
    return m_WebProtoBuffManager.Post<T>(url, message);
}
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L105-L108)

底層管理器簽章一致，只是用 `using` 簡化了命名空間：

```csharp
public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
```

Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L182)

### 2. 定義請求訊息

請求訊息繼承 `MessageObject`,並按 protobuf-net 規則標註契約與欄位編號。以下為按上述約束撰寫的新型別範本(自行建立，非儲存庫內建檔案)：

```csharp
using GameFrameX.Network.Runtime;
using ProtoBuf;

[ProtoContract]
public class LoginRequest : MessageObject
{
    [ProtoMember(1)] public string UserName { get; set; }
    [ProtoMember(2)] public string Password { get; set; }
}
```

### 3. 定義回應訊息

回應訊息比請求多一步：實作 `IResponseMessage`。以下同為按約束撰寫的範本：

```csharp
using GameFrameX.Network.Runtime;
using ProtoBuf;

[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)] public int Code { get; set; }
    [ProtoMember(2)] public string Token { get; set; }
}
```

### 4. 傳送並接收強型別回應

定義完成後，按 README 官方用法呼叫即可，`T` 填入你定義的回應型別：

```csharp
using GameFrameX.Web.ProtoBuff.Runtime;

// 傳送請求並等待結果
LoginResponse response = await WebComponent.Post<LoginResponse>(url, request);
```

## 常見變體

- **WebGL 平台**：同一套訊息定義無需改動。WebGL 下走 `UnityWebRequest` 路徑，由元件自動設定 `Content-Type: application/x-protobuf` 並把 `MessageObject` 序列化後的位元組作為原始 body 上傳(見 [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L83-L97));非 WebGL 平台走另一條分支。
- **逾時時間**：由管理器的 `RequestTimeout`(`TimeSpan`)控制，設定秒數時會自動換算(`RequestTimeout = TimeSpan.FromSeconds(value)`),見 [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L41-L54)。
- **用 `.proto` 檔案產生**：同樣適用，只要產生的 C# 類別滿足「繼承 `MessageObject`(+ 回應實作 `IResponseMessage`)」並保留 `[ProtoContract]`/`[ProtoMember]` 標註即可。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| `Post<T>` 不存在 / 找不到方法 | 未定義巨集 `ENABLE_GAME_FRAME_X_WEB_PROTOBF_NETWORK`,條件編譯把方法裁掉了 | 在 Player Settings → Scripting Define Symbols 新增巨集並重新編譯 |
| 泛型參數編譯報錯「缺少 IResponseMessage」 | 回應型別只繼承了 `MessageObject`,沒實作 `IResponseMessage` | 給回應類別加上 `, IResponseMessage` |
| 請求參數編譯報錯 | 請求類別沒有繼承 `MessageObject`(例如只標了 `[ProtoContract]`) | 讓請求類別繼承 `MessageObject` |
| 回應欄位全為預設值 | 欄位沒標 `[ProtoMember(n)]` 或編號與伺服器端不一致 | 補齊/對齊欄位編號 |
| 伺服器端解析 body 失敗 | Content-Type 或序列化方式不符 | 確認伺服器端按 `application/x-protobuf` 解析 protobuf 二進位 |

## 驗證

- 編譯通過:`WebComponent.Post<LoginResponse>(url, request)` 能解析到方法，說明巨集、繼承關係、介面實作全部滿足。
- 執行時:`await` 回傳的 `LoginResponse` 實例中欄位為伺服器端下發的真實值(可在 Inspector 或日誌中輸出確認)，即定義正確。

## 背景

請求側只要求「可被 protobuf-net 序列化的 `MessageObject`」,傳送前會被統一序列化為二進位；回應側因為要在收到位元組後還原成具體型別，所以透過 `IResponseMessage` 介面在型別系統上區分「這是可反序列化的回應訊息」。整個收發由 `WebProtoBuffManager` 的等待佇列/傳送列表調度，與訊息定義無耦合，定義訊息時無需關心。
