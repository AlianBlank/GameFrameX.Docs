# 保存路径设置与路径分隔符问题

当调用 `SetSavePath` 后对象在桶里的存储路径不符合预期(多出或缺少分隔符、出现平台错误的斜杠)时,通常源于传入路径的格式与 `Path.DirectorySeparatorChar` 处理逻辑不一致。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 保存路径末尾被多切掉一个字符(如 `mybucket/folder` 变成 `mybucket/folde`) | 传入路径以反斜杠 `\` 结尾,而当前平台分隔符是正斜杠 `/`(常见于 Windows 路径写入 Linux/Mac 目标) | 在调用前把 `\` 替换为平台分隔符,或使用 `Path.Combine`/`Path.DirectorySeparatorChar` 组装 |
| 保存路径末尾仍带分隔符(如 `mybucket/folder/`),后续拼接生成 `mybucket/folder//file` | 调用方传入的是不带分隔符结尾的字符串,但实际上一次调用前已被手动截断过;或传入时无分隔符但拼到了已有的带分隔符路径上 | 改为每次调用前重新传入完整路径,避免叠加截断 |
| 路径中的 `/` 与 `\` 混用,远端对象路径出现 `mybucket/folder\file` | 直接拼接了 Windows 风格路径或字符串硬编码的 `/` | 统一使用 `Path.DirectorySeparatorChar`,不要在远端路径里混用两种斜杠 |

## 修复步骤

### 1. 让 `SetSavePath` 只处理一次

`SetSavePath` 的逻辑是:仅当传入字符串以 `Path.DirectorySeparatorChar` 结尾时,才去掉最后一个字符。

```csharp
public void SetSavePath(string savePath)
{
    if (savePath.EndsWith(Path.DirectorySeparatorChar.ToString()))
    {
        savePath = savePath.Substring(0, savePath.Length - 1);
    }

    BucketSavePath = savePath;
}
```

Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

因此,如果传入路径的尾字符不是当前平台的 `Path.DirectorySeparatorChar`(例如在 Windows 下传入以 `\` 结尾的路径,而运行时实际目标平台是 macOS/Linux),末尾分隔符不会被去除,后续拼接就会得到带多余分隔符的远端路径。

### 2. 使用平台相关的分隔符

将硬编码的 `/` 或 `\` 替换为 `Path.DirectorySeparatorChar`,或在 Windows 上传入路径时统一改成 `\` 结尾。例如:

```csharp
string remote = $"mybucket{Path.DirectorySeparatorChar}folder";
manager.SetSavePath(remote);
```

### 3. 避免重复调用

每次 `SetSavePath` 都基于传入值整体重写 `BucketSavePath`,所以不要先调用一次再去手动拼接;直接把最终路径一次性传入。

```csharp
manager.SetSavePath("mybucket/folder");
```

## 验证

1. 在上传完成后,登录对象存储控制台或调用 List 接口,确认对象 Key 与期望路径一致,没有多余的 `/` 或 `\`。
2. 用一个已知文件做单文件上传 (`UploadFile`),对比远端 Key 是否等于 `BucketSavePath` + 本地相对路径。
3. 在切换平台(Editor 平台切换到 macOS/Linux 再次运行)后重新设置路径,确认分隔符处理仍正确。
