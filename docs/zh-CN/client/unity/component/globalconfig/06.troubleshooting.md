# 常见问题

本文档汇总了使用 GlobalConfig 组件过程中可能遇到的常见问题及解决方案。

## 概述

GlobalConfigComponent 是 GameFrameX 框架中的全局配置管理组件，主要用于管理游戏应用的全局配置信息，包括应用版本检查地址、资源版本检查地址、服务器地址等。该组件采用 Unity 组件的形式实现，可以灵活地配置和使用。

> 组件的详细功能说明请参考 [GlobalConfig 组件简介](./1-overview.1-introduction)。
> 组件的完整 API 请参考 [GlobalConfigComponent](./4-core-component.1-global-config-component)。

## 安装与设置

### Q1: 如何安装 GlobalConfig 组件？

GlobalConfig 组件可以通过以下方式安装：

1. **通过 manifest.json 安装**：在项目的 `manifest.json` 文件中添加依赖：
   ```json
   {"com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git"}
   ```

2. **通过 Unity Package Manager**：在 Unity 中选择 `Window > Package Manager`，然后点击 `+` 号添加 Git URL：
   ```
   https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git
   ```

3. **手动安装**：直接下载仓库并放置到 Unity 项目的 `Packages` 目录下。

> 详细的安装步骤请参考 [安装方式](./2-installation.1-install-methods)。

### Q2: 安装后报 "Assembly has reference to missing assembly" 错误？

这是因为 GlobalConfig 组件依赖以下包：
- `com.gameframex.unity` (版本 1.1.1)
- `com.gameframex.unity.web` (版本 1.1.2)

**解决方案**：确保这些依赖包已正确安装。可以在 `manifest.json` 中添加完整依赖：

```json
{
  "dependencies": {
    "com.gameframex.unity": "1.1.1",
    "com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git",
    "com.gameframex.unity.web": "1.1.2"
  }
}
```

### Q3: Unity 版本兼容性如何？

根据 package.json，组件支持的最低 Unity 版本为 **2017.1**。如果使用更低版本的 Unity，可能会出现兼容性问题。

## 组件使用

### Q4: 如何将 GlobalConfigComponent 添加到场景？

1. 在 Unity 编辑器中，创建或选择一个 GameObject
2. 在 Inspector 面板中，点击 **Add Component** 按钮
3. 搜索并选择 **Game Framework > Global Config**
4. 组件将添加到选定的 GameObject 上

> 详细的添加步骤请参考 [添加到场景](./3-getting-started.1-add-to-scene)。

### Q5: 可以在场景中添加多个 GlobalConfigComponent 吗？

**不建议**。组件使用了 `[DisallowMultipleComponent]` 特性，这限制了同一 GameObject 上只能添加一个实例。虽然技术上可以将组件添加到不同的 GameObject，但框架设计为单例模式，建议只在场景中保留一个全局配置组件。

### Q6: 如何在代码中访问 GlobalConfigComponent？

由于组件使用了 `IsAutoRegister = false`，组件不会自动注册。典型的访问方式是在场景中查找或通过引用访问：

```csharp
// 通过 FindObjectOfType 查找
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
if (globalConfig != null)
{
    string appVersionUrl = globalConfig.CheckAppVersionUrl;
    string resourceVersionUrl = globalConfig.CheckResourceVersionUrl;
}
```

> 详细的代码访问方式请参考 [代码访问](./3-getting-started.3-code-access)。

### Q7: 如何通过代码动态设置配置？

可以在运行时通过代码设置各个属性：

```csharp
var globalConfig = FindObjectOfType<GlobalConfigComponent>();

// 设置各种 URL
globalConfig.CheckAppVersionUrl = "https://example.com/check-app-version";
globalConfig.CheckResourceVersionUrl = "https://example.com/check-resource-version";
globalConfig.HostServerUrl = "https://example.com/server";

// 设置附加内容
globalConfig.Content = "{\"key\": \"value\"}";

// 设置全局配置信息
ResponseGlobalInfo globalInfo = new ResponseGlobalInfo
{
    // 配置属性
};
globalConfig.SetGlobalConfig(globalInfo);
```

## 属性配置

### Q8: 各个属性有什么作用？

| 属性 | 说明 |
|------|------|
| **主机服务地址 (HostServerUrl)** | 后端服务器的地址，用于连接游戏服务器 |
| **检测App版本地址接口 (CheckAppVersionUrl)** | 检查应用程序新版本的 URL 地址 |
| **检测资源版本地址接口 (CheckResourceVersionUrl)** | 检查游戏资源更新的 URL 地址 |
| **补充程序集列表 (AOTCodeList)** | AOT 编译时需要补充的程序集列表（JSON 格式） |
| **附加内容 (Content)** | 其他附加的配置内容 |
| **补充元数据列表 (AOTCodeLists)** | AOT 补充元数据列表 |

> 详细的属性配置说明请参考 [配置属性](./3-getting-started.2-configure-properties)。

### Q9: AOTCodeList 和 AOTCodeLists 有什么区别？

- **AOTCodeList** (字符串类型)：用于在 Inspector 中以 JSON 字符串格式输入 AOT 代码列表
- **AOTCodeLists** (列表类型)：解析后的 AOT 代码列表，供运行时使用

设置 AOTCodeList 时，系统会自动解析 JSON 并填充到 AOTCodeLists：

```csharp
// 设置 JSON 格式的 AOT 代码列表
globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\", \"Assembly3\"]";

// 自动解析，可以在 AOTCodeLists 中获取解析结果
List<string> aotCodeLists = globalConfig.AOTCodeLists;
```

## AOT 配置相关

### Q10: 什么是 AOT 代码列表？为什么要配置它？

AOT (Ahead-of-Time) 编译是 .NET 的一种编译模式，主要用于 IL2CPP 等平台。某些泛型类型和反射代码在 AOT 编译时可能无法正确生成，需要通过 AOT 代码列表来指定需要额外处理的程序集。

> 详细的 AOT 配置说明请参考 [AOT 代码列表配置](./7-aot-configuration.1-aot-code-list)。

### Q11: 设置 AOTCodeList 时出现 JSON 解析错误？

如果在设置 AOTCodeList 时遇到解析错误，可能的原因和解决方案：

1. **JSON 格式错误**：确保 JSON 格式正确
   ```csharp
   // 错误示例
   globalConfig.AOTCodeList = "Assembly1, Assembly2"; // 错误的格式

   // 正确示例
   globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\"]"; // 正确的 JSON 数组格式
   ```

2. **特殊字符转义**：如果字符串中包含特殊字符，确保正确转义

### Q12: AOT 代码列表为空会导致什么问题？

如果 AOT 代码列表为空，某些使用泛型或反射的功能可能在 IL2CPP 平台上无法正常工作。具体表现包括：
- 泛型类型序列化失败
- 反射获取类型失败
- 某些动态代码执行异常

## 编辑器相关

### Q13: 在 Play 模式下无法编辑属性？

这是正常行为。Inspector 中的属性在 **Play 模式**下是只读的，这是为了保护运行时配置不被意外修改。

```csharp
// GlobalConfigComponentInspector.cs 中的实现
EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode & Application.isPlaying);
{
    // 属性编辑区域
}
EditorGUI.EndDisabledGroup();
```

### Q14: 原始数据 (OriginalData) 是只读的？

是的，原始数据属性在 Inspector 中是只读的。该属性用于存储从服务器获取的原始配置数据，通常在运行时通过代码设置：

```csharp
// 设置原始数据
globalConfig.SetOriginalData(jsonString);

// 读取原始数据
string originalData = globalConfig.OriginalData;
```

## 运行时相关

### Q15: 组件的 Awake 方法有什么特殊处理？

组件重写了 `Awake` 方法，并将 `IsAutoRegister` 设置为 `false`：

```csharp
protected override void Awake()
{
    IsAutoRegister = false;
    base.Awake();
}
```

这意味着组件不会自动注册到框架的组件管理系统中，需要开发者手动管理或通过其他方式访问。

### Q16: 如何从服务器获取并设置全局配置？

典型的工作流程如下：

1. 使用配置的 URL 向服务器发送请求
2. 服务器返回配置数据（JSON 格式）
3. 解析响应数据到 ResponseGlobalInfo 对象
4. 调用 SetGlobalConfig 设置全局配置

```csharp
// 伪代码示例
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
string url = globalConfig.HostServerUrl;

// 发送网络请求获取配置
// ...
ResponseGlobalInfo response = ParseServerResponse(data);
globalConfig.SetGlobalConfig(response);

// 访问配置信息
ResponseGlobalInfo info = globalConfig.GlobalInfo;
```

## 故障排查

### Q19: 常见问题排查步骤

1. **检查依赖**：确认所有依赖包已正确安装
2. **检查 Unity 版本**：确保使用 Unity 2017.1 或更高版本
3. **检查组件添加**：确认 GlobalConfigComponent 已正确添加到场景
4. **检查属性配置**：确认必要的 URL 属性已配置
5. **查看日志**：检查 Unity 控制台是否有错误或警告信息

### Q20: 运行时找不到 GlobalConfigComponent？

如果 `FindObjectOfType<GlobalConfigComponent>()` 返回 null，可能原因：
1. 组件未添加到任何 GameObject
2. 组件添加到了未激活的 GameObject
3. 场景未正确加载

**解决方案**：
- 确认组件已添加到场景中的活动 GameObject
- 确保 GlobalConfig 所在的场景已被加载

## 配置文件为空或未加载

**原因**：未在 Inspector 中配置 GlobalConfigComponent 或配置文件路径不正确。

**解决方案**：在 Unity 编辑器中选中挂载 GlobalConfigComponent 的 GameObject，在 Inspector 面板中检查配置项是否已正确填写。

## 版本检查 URL 无法访问

**原因**：服务器地址配置错误或网络不可达。

**解决方案**：检查 `AppVersionCheckUrl` 和 `ResourceVersionCheckUrl` 是否为有效的 HTTP/HTTPS 地址，确保设备网络连通。
