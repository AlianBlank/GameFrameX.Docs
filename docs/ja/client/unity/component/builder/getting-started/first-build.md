# 最初のビルドを実行する

このページのステップに従うことで、Unity のコマンドラインから GameFrameX Builder の自動ビルドをトリガーし、最初の APK / アセットバンドルを生成できます。

## 前提条件

- Unity 2019.4 以上
- `Packages/manifest.json` から `com.gameframex.unity.builder` をインストール済み（2.0.3 以上を推奨）
- Player Settings（パッケージ名、バージョン番号、アイコンなど）が設定済みの Unity プロジェクト

`manifest.json` に scoped registry と依存関係を追加する最小構成：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.builder": "2.0.3"
  }
}
```

ソース: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L36-L72)

## 操作手順

1. **Unity プロジェクトを開き、パッケージのインポートが完了するまで待つ**。`Packages` の下に `com.gameframex.unity.builder` があれば OK です。

2. **`-executeMethod` の対象メソッドが利用可能か確認する**。ビルドのエントリポイントは `GameFrameX.Builder.Editor.Builder` にあり、最もよく使われる 2 つのメソッドは次のとおりです：

   | メソッド | 役割 |
   |------|------|
   | `GameFrameX.Builder.Editor.Builder.BuildApk` | APK をパッケージ化し、`-IsUploadApk` が有効な場合はオブジェクトストレージにアップロードする |
   | `GameFrameX.Builder.Editor.Builder.BuildAsset` | YooAsset のアセットバンドルをビルドする |

   ソース: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L51-L78)

3. **コマンドラインからビルドをトリガーする**。最もシンプルなコマンドラインの形式（BuildApk を例に）：

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath /path/to/your/project \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
         -BUILD_NUMBER 1 \
         -logFile /path/to/build.log
   ```

   `-BUILD_NUMBER` は必須項目です。`-logFile` を省略した場合、Builder は自動的にログファイルのパスを生成します。

4. **ビルド結果を確認する**。`-BUILD_NUMBER`、`-AppVersion`、`-BundleId` などのパラメータは `Builder.BuildParamsParse` によって `BuilderOptions` に解析され、ビルドパイプライン全体を駆動します。ログファイルのパスは `-logFile` で指定し、APK の出力先は Unity の `BuildPlayerAndroid` によって決定されます。

   ソース: [Builder.BuildParamsParse.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs)

## よくあるバリエーション

### アセットバンドルのみビルド（APK は作成しない）

`-executeMethod` を `GameFrameX.Builder.Editor.Builder.BuildAsset` に置き換え、アセットビルド用パラメータを指定します：

```bash
Unity -batchmode -nographics -quit \
      -projectPath /path/to/your/project \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
      -BUILD_NUMBER 1 \
      -PackageName DefaultPackage \
      -BuildPipeline BuiltinBuildPipeline \
      -IsIncrementalBuildPackage false
```

アセットビルド用パラメータ（抜粋）：

| パラメータ | デフォルト値 | 説明 |
|------|--------|------|
| `-PackageName` | `DefaultPackage` | アセットバンドル名 |
| `-PackageVersion` | タイムスタンプ | 空欄の場合、自動的にタイムスタンプを使用 |
| `-BuildPipeline` | `BuiltinBuildPipeline` | `BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` から選択可能 |
| `-BuildinFileCopyOption` | `ClearAndCopyAll` | 内蔵ファイルのコピーオプション |
| `-IsIncrementalBuildPackage` | `false` | 増分ビルドを行うかどうか |

ソース: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L97-L106)

### CI でログとアップロードを追加する

ビルド時に以下のフラグを追加すると、パッケージング完了後にログ / APK / アセットバンドルをオブジェクトストレージにアップロードできます：

```bash
-IsUploadLogFile \
-IsUploadApk \
-IsUploadAsset \
-ObjectStorageKey <key> \
-ObjectStorageSecret <secret> \
-ObjectStorageBucketName <bucket> \
-ObjectStorageEndPoint <endpoint>
```

ソース: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L107-L127)

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `executeMethod` で対象メソッドが見つからない | パッケージが正しくインポートされていない、または名前空間が間違っている | `Packages` の下に `com.gameframex.unity.builder` が存在することを確認し、メソッドの完全名は `GameFrameX.Builder.Editor.Builder.BuildApk` にします |
| `-BUILD_NUMBER` が不足しているというエラー | 必須パラメータが渡されていない | コマンドラインに `-BUILD_NUMBER <n>` を追加する |
| オブジェクトストレージへのアップロードが失敗する | オブジェクトストレージのマクロが有効になっていない | プロジェクトに対応するオブジェクトストレージのサブパッケージがインストールされ、`ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 系のマクロが有効になっていることを確認する |

## 背景（オプション）

Builder は静的コンストラクション段階で `BuildParamsParse` を呼び出し、コマンドライン引数を `BuilderOptions` に解析し、その後 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_*` マクロに従ってオブジェクトストレージの実装を選択します。`BuildApk` は Unity によるパッケージ出力を起動し、必要に応じてアップロードを行うだけです。リソースビルドは独立した `BuildAsset` パスを通ります。Builder 全体のパラメータ一覧については、『コマンドライン引数リファレンス』を参照してください。
