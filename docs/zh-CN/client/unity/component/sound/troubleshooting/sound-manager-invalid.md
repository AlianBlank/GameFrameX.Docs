# Sound manager is invalid 怎么办

运行游戏后日志中打印 `Fatal: Sound manager is invalid.`,声音组件无法播放任何音效。该错误来自 `SoundComponent.Awake()` 在向 `GameFrameworkEntry` 询问 `ISoundManager` 模块时返回了 `null`,导致后续初始化直接 return。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动后日志出现 `Fatal: Sound manager is invalid.`,PlaySound 无效 | 没有把 `SoundManager` 实现类注册到框架模块表 | 在 `SoundComponent` Inspector 上设置正确的 `Component Type`(参见下文步骤 1) |
| 启动后日志出现 `Fatal: Sound manager is invalid.`,但 `Component Type` 已配置 | 配置的类名拼写错误,或该类被代码剥离/未编译进运行时程序集 | 按类名 `GameFrameX.Sound.SoundManager` 在工程中搜索,确认类存在且未被 Stripping 移除 |
| 编辑器下正常、发布包后报错 | IL2CPP/Managed Stripping 把 `SoundManager` 类型剥离 | 在 `link.xml` 中保留 `GameFrameX.Sound.SoundManager`,或关闭 Stripping |

## 修复步骤

### 1. 在 SoundComponent Inspector 上指定实现类

打开挂载 `SoundComponent` 的场景对象,在 Inspector 中找到 `Component Type` 字段,填入实现类的完整类型名称。`SoundComponent.Awake()` 会按该名字反射加载并注册到 `GameFrameworkEntry`:

```csharp
// Runtime/Sound/SoundComponent.cs#L102-L118
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ISoundManager);
    base.Awake();
    EnsureAudioMixer();
    if (!IsRuntimeComponentReady)
    {
        return;
    }

    m_SoundManager = GameFrameworkEntry.GetModule<ISoundManager>();
    if (m_SoundManager == null)
    {
        Log.Fatal("Sound manager is invalid.");
        return;
    }
    ...
}
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L102-L132)

`Component Type` 的典型值:`GameFrameX.Sound.SoundManager`(命名空间 + 类名,可在 `Runtime/Sound/Sound/SoundManager.cs` 中核对)。

### 2. 校验实现类本身存在

在 Project 视图搜索 `SoundManager.cs`,确认仓库自带的实现类还在工程里:

```
Runtime/Sound/Sound/SoundManager.cs
```

Source: [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs)

该文件如果被误删或改名,反射 `GetType(componentType)` 就会返回 `null`,模块表里就没有 `ISoundManager`,触发本错误。

### 3. 处理 IL2CPP 代码剥离(发布包场景)

`Utility.Assembly.GetType(componentType)` 依赖运行时能够通过名字找到类型。IL2CPP + Managed Code Stripping 可能在出包时把没有直接引用的 `SoundManager` 优化掉,导致 `GetType` 返回 `null`。在 `Assets/link.xml` 中追加:

```xml
<linker>
  <assembly fullname="GameFrameX.Sound" preserve="all"/>
</linker>
```

或者把 `Stripping Level` 调整为 `Low`,重新出包验证。

## 验证

1. 启动场景,确认 Console 中不再出现 `Fatal: Sound manager is invalid.`。
2. 调用 `GameEntry.GetComponent<SoundComponent>().PlaySound(...)`,能听到音效且没有 `PlaySoundFailure` 事件。
3. 检查 `m_SoundManager` 是否已被赋值:在 `SoundComponent.Awake` 之后的代码路径(`Start`)里 `m_SoundManager != null`,后续 `SetResourceManager` / `SetSoundHelper` 才能正常执行。
