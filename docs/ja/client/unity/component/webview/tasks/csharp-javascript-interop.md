# C# と JavaScript の相互運用とイベントリッスンの実装方法

このページの手順に従うことで、GameFrameX WebView でページを読み込み、C# からページ内の JavaScript コードを呼び出し、Web ページから返されるメッセージとクローズイベントをリッスンできます。C# → JS は `IWebViewManager.ExecuteJavaScript` を経由し、JS → C# は `WebViewReceivedMessageEventArgs` などのイベント引数によって伝達されます。

## 前提条件

- Unity プロジェクトに `com.gameframex.unity.webview` パッケージがインストール済みであること(ルートディレクトリの [package.json](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/package.json) を参照)。
- シーンに [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs) がアタッチ済みであること(エディターパネルは [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L13-L19) を参照。これは当該コンポーネントを `IWebViewManager` の実装型に関連付けるものです)。

## 操作手順

1. コンポーネントを通じて `IWebViewManager` のインスタンスを取得します。インタラクションのエントリーポイントはこのインターフェースに集約されており、実際のシグネチャは以下の通りです:

   ```csharp
   public interface IWebViewManager
   {
       void Initialize();                    // 初期化
       void Show(string url);                // WebView を表示し url を読み込む
       void MakeFullScreen();                // フルスクリーン
       void ExecuteJavaScript(string javaScript); // JavaScript を実行
       void Hide();                          // 非表示
   }
   ```

   Source: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L12-L40)

2. 初期化して対象ページを読み込みます。`ExecuteJavaScript` は現在読み込み済みのページに作用するため、必ず `Initialize()` を行ってから `Show(url)` を実行する必要があります:

   ```csharp
   using GameFrameX.WebView.Runtime;

   webViewManager.Initialize();
   webViewManager.Show("https://example.com/index.html");
   webViewManager.MakeFullScreen(); // オプション:フルスクリーンが必要な場合に呼び出す
   ```

3. C# から JavaScript を実行します。完全な JS 文字列を渡すだけでよく、メソッドに戻り値はありません(実行結果は返されません):

   ```csharp
   // ページタイトルを変更
   webViewManager.ExecuteJavaScript("document.title = 'Hello from Unity';");

   // ページ内で定義されたカスタム関数を呼び出す
   webViewManager.ExecuteJavaScript("window.onUnityReady && window.onUnityReady();");
   ```

   Source: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L30-L35)

4. Web ページから返されるイベントをリッスンします。リポジトリの `Runtime/EventArgs/` 以下には 2 つのイベント引数型が用意されており、それぞれ「メッセージ受信」と「クローズ」に対応します:
   - [WebViewReceivedMessageEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/EventArgs/WebViewReceivedMessageEventArgs.cs) — Web ページが C# へメッセージを送信した際のイベントデータ。
   - [WebViewCloseEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/EventArgs/WebViewCloseEventArgs.cs) — WebView がクローズされた際のイベントデータ。

   イベントのディスパッチとサブスクリプションのエントリーポイントは [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs) と [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs) にあります。ソースコードからは(今回の取得が制限されていたため)これら 2 つのイベント引数の完全なフィールドシグネチャは確認できていません。上記ファイル内の実際の定義を正として扱い、ドキュメント内の推測によるフィールドに依存しないでください。

5. 使用しなくなったら `webViewManager.Hide()` を呼び出して WebView を非表示にします。

Source: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L39)

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `ExecuteJavaScript` が何の効果もない | ページの読み込みが完了する前に呼び出されている | 先に `Initialize()` + `Show(url)` を行い、ページの読み込みを確認してから JS を実行する |
| `ExecuteJavaScript` の呼び出しで NullReferenceException が発生する | シーンに `WebViewComponent` がアタッチされていない、または Inspector で `IWebViewManager` の実装型が選択されていない | コンポーネントをアタッチし、Inspector([WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L16-L19) が提供)でリフレッシュして実装型を選択する |
| JS 側のデータが受信できない | `ExecuteJavaScript` を同期で値を取得するメソッドとして使用している | このメソッドには戻り値がなく、値の取得は `WebViewReceivedMessageEventArgs` のメッセージイベントによる返却で行う必要がある |

## 背景

`ExecuteJavaScript` の設計意図は一方向の呼び出しです。インターフェースのシグネチャ `void ExecuteJavaScript(string javaScript)` はスクリプトの送信のみを担い、結果は返さないため、双方向のインタラクションには「送信 + イベントによる返却」という組み合わせが採用されています。イベント引数は独立した `WebViewReceivedMessageEventArgs` と `WebViewCloseEventArgs` に分割されており、`BaseWebViewManager` がライフサイクルを一元管理します。WebView コンポーネントの全体構造については、概要ページを参照してください。
