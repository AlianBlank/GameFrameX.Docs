# コルーチンロジックのテストを記述する方法

コルーチンロジックは Unity ランタイム（`MonoBehaviour`、`StartCoroutine`）に依存しているため、純粋な NUnit エディタ単体テストでは直接実行できません。このページでは `GameFrameX.Coroutine.Tests` の規約と、Unity PlayMode テストでコルーチンの動作を検証する方法を説明します。

## 前提条件

- Unity がインストールされていること（`com.gameframex.unity.coroutine` と互換性のあるバージョン）。
- Package Manager 経由で本パッケージがインストールされていること。Tests アセンブリ `GameFrameX.Coroutine.Tests` も一緒にインポートされます。
- PlayMode テストを使用する場合、プロジェクトには `UnityEngine.TestRunner` と `UnityEditor.TestRunner` アセンブリも必要となります（これらは Unity に標準で付属しています）。

## Tests アセンブリの規約

`Tests/GameFrameX.Coroutine.Tests.asmdef` は Editor プラットフォームでのみ有効であり、`references` で明示的に `GameFrameX.Coroutine.Runtime` に依存することで、ランタイムビルドを汚染しないようにしています。

```json
{
    "name": "GameFrameX.Coroutine.Tests",
    "references": [
        "GameFrameX.Coroutine.Runtime"
    ],
    "rootNamespace": "GameFrameX.Coroutine.Tests",
    "includePlatforms": [
        "Editor"
    ]
}
```

出典: [GameFrameX.Coroutine.Tests.asmdef](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/GameFrameX.Coroutine.Tests.asmdef#L1-L18)

## 操作手順

### 1. Editor アセンブリにプレースホルダ単体テストを配置する

`Tests/UnitTests.cs` で明示されている通り、コルーチンモジュールは純粋な NUnit 環境では実行できないため、プレースホルダ用のテストケースを残しておき、「テストカバレッジがない＝未テスト」と誤解されないようにします。

```csharp
using NUnit.Framework;

namespace GameFrameX.Coroutine.Tests
{
    internal class UnitTests
    {
        [Test]
        public void TestPlaceholder()
        {
            // Coroutine モジュールは Unity ランタイム（MonoBehaviour、StartCoroutine）に依存しているため、
            // 純粋な NUnit 環境ではコルーチンロジックを直接テストできません。
            // コルーチン関連の統合テストは Unity PlayMode テストで記述する必要があります。
            Assert.Pass("Coroutine module requires Unity runtime for testing.");
        }
    }
}
```

出典: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/UnitTests.cs#L1-L16)

### 2. PlayMode テストを記述して実際のコルーチンをカバーする

新しい PlayMode テストアセンブリ（名前空間は任意。例えば `GameFrameX.Coroutine.PlayModeTests`）を作成し、`asmdef` では `includePlatforms` を空に、`references` に `GameFrameX.Coroutine.Runtime` と `nunit.framework` を追加します。テストケース内で `GameFrameX.Entry.GetComponent<CoroutineComponent>()` からコンポーネントを取得し、`new` キーワード付きの `StartCoroutine` / `StopCoroutine` を呼び出して動作を検証します。

```csharp
using System.Collections;
using GameFrameX.Coroutine.Runtime;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

namespace GameFrameX.Coroutine.PlayModeTests
{
    public class CoroutineComponentTests
    {
        [UnityTest]
        public IEnumerator StartAndStop_TracksEnumerator()
        {
            var component = GameFrameX.Entry.GetComponent<CoroutineComponent>();
            Assert.IsNotNull(component);

            var routine = component.StartCoroutine(Sample());
            yield return null;

            // 同じ IEnumerator インスタンスは StopCoroutine で正しく終了し、追跡テーブルから削除される必要があります。
            component.StopCoroutine(routine);
            yield return null;
        }

        private static IEnumerator Sample()
        {
            yield return null;
        }
    }
}
```

> 注意: `CoroutineComponent.StartCoroutine` / `StopCoroutine` は `new` で基底クラスのメソッドを隠しているため、`CoroutineComponent` 型の参照から呼び出さなければ、コンポーネントはコルーチンを追跡テーブルに追加しません。詳細は [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L50) を参照してください。

### 3. テストを実行する

- Unity Editor で **Window → General → Test Runner** を開きます。
- **PlayMode** タブに切り替え、作成した PlayMode アセンブリを選択して **Run All** をクリックします。
- プレースホルダ Editor 用ケースは **EditMode** タブで実行され、想定結果は `Passed` です。

## よくあるバリエーション

- **EditMode 検証のみ**: `UnitTests.TestPlaceholder` のプレースホルダを残しておくだけで十分です。CI 上の EditMode スイートが本モジュールの不在によってエラーにならないようにできます。
- **カスタムイベント/タイマー処理との組み合わせ**: ビジネスロジックのコルーチンを `IEnumerator` を返す純粋メソッドとしてカプセル化し、PlayMode 用ケース内で複数回 `yield return` してから最終状態をアサートします。
- **例外/ログのアサート**: `LogAssert.Expect` を使用して、例外コルーチン内でコンポーネントが出力するログを捕捉し、テストが誤って失敗しないようにします。

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| PlayMode テストで `CoroutineComponent` が `null` になる | `GameFrameX` の起動フローが完了する前に値を取得している | `yield return null` の後に取得するか、`[SetUp]` 内で `Entry` の初期化完了を待つ |
| `StopCoroutine` でコルーチンが見つからない | `MonoBehaviour` 基底クラスの参照から呼び出したため、`new` で隠蔽されたメソッドをバイパスしている | 常に `CoroutineComponent` 型の参照から `StartCoroutine` / `StopCoroutine` を呼び出す |
| EditMode 用ケース実行時に "Type or namespace not found" が発生 | テストアセンブリが `GameFrameX.Coroutine.Runtime` を参照していない | `asmdef` の `references` に `GameFrameX.Coroutine.Runtime` を追加する |
| PlayMode 用ケースが無視される | PlayMode アセンブリの `includePlatforms` に誤って `Editor` を設定している | `includePlatforms` を空にして、すべてのプラットフォームでアセンブリがコンパイルされるようにする |

## 背景（任意）

`CoroutineComponent` は `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` でコルーチンを追跡しているため、`StopCoroutine` には `StartCoroutine` と同じ `IEnumerator` インスタンスを渡す必要があります。この制約により、テストでは同一メソッド呼び出し内で列挙子の参照を保持しておく必要があります。
