# How to Integrate the Hotfix Launcher (IHotfixLauncher)

By implementing the `IHotfixLauncher` interface, you can have the startup flow invoke your hotfix solution (HybridCLR, ILRuntime, custom solutions, etc.) after resource patching is complete, with you deciding at the application layer how to load assemblies and jump to the hotfix entry point.

## Prerequisites

- The startup flow has been properly initialized (refer to the startup flow integration documentation).
- A `StartupOptions` configuration asset has been prepared, with `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` filled in.
- The `GameFrameX.Startup.Runtime` namespace and `Cysharp.Threading.Tasks` have been imported.

## Interface Contract

`IHotfixLauncher` exposes only a single asynchronous method that must return a `HotfixLaunchResult` regardless of success or failure—do not throw exceptions directly.

```csharp
using Cysharp.Threading.Tasks;

namespace GameFrameX.Startup.Runtime
{
    /// <summary>
    /// Hotfix launch interface, implemented by the application layer. The package does not bind to any specific hotfix solution (HybridCLR / others).
    /// </summary>
    public interface IHotfixLauncher
    {
        UniTask<HotfixLaunchResult> StartAsync(StartupOptions options);
    }
}
```

Source: [IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L1-L17)

## Steps

1. Create a new class in your application project (e.g., `MyHotfixLauncher`) that implements `IHotfixLauncher`.
2. Inside `StartAsync`, read the hotfix DLL/assembly based on `options`, and invoke the entry method via reflection (return by constructing `HotfixLaunchResult.Succeed()` or `HotfixLaunchResult.Fail(message)`).
3. Do not throw exceptions inside `StartAsync`—on failure, construct `HotfixLaunchResult.Fail("error message")` and return it; the startup framework will follow the failure branch based on this and publish `StartupFailedEventArgs`.
4. Inject the `MyHotfixLauncher` instance into the startup manager (usually via `StartupManager`'s injection interface or by drag-and-drop configuration on a `GameObject`), overriding the framework's default Launcher.
5. Run the startup flow; once all Patch stages are complete, the framework will automatically call your `StartAsync`.

## Minimal Implementation Example

Below is a minimal working implementation based on the contract tests, which you can adapt directly as a template:

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public sealed class MyHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        try
        {
            // 1) Load the hotfix assembly (example: using HybridCLR / YooAsset / a custom loader)
            //    var assembly = LoadAssembly(options.HotfixAssemblyName);

            // 2) Jump to the hotfix entry via reflection
            //    var entryType = assembly.GetType(options.HotfixEntryTypeName);
            //    var entryMethod = entryType.GetMethod(options.HotfixEntryMethodName);
            //    entryMethod.Invoke(null, null);

            await UniTask.Yield();
            return HotfixLaunchResult.Succeed();
        }
        catch (System.Exception ex)
        {
            return HotfixLaunchResult.Fail(ex.Message);
        }
    }
}
```

## Common Variants

- **HybridCLR solution**: Load the DLL in `StartAsync` via `HybridCLR.RuntimeApi.LoadDllFromMemory`, then invoke the entry method via reflection using `System.Reflection.Assembly`.
- **Pure asset hotfix (no DLL)**: Load the prefab directly with `Resources.Load<GameObject>` and then `Instantiate`; the entry logic can skip the reflection step.
- **Solutions with an initialization phase**: If your hotfix framework requires asynchronous initialization (e.g., downloading, verification), `await` it inside `StartAsync` before returning `Succeed`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Startup crash or black screen | `StartAsync` threw an uncaught exception | Catch the exception instead and return `HotfixLaunchResult.Fail(message)` |
| Returns `Success=true` but the game does not enter the main scene | Entry method name/type name is misspelled | Verify that `HotfixEntryTypeName` / `HotfixEntryMethodName` in `StartupOptions` exactly match those in the DLL |
| Stuck at the Patch stage indefinitely | No custom `IHotfixLauncher` was injected; the framework is using the default empty implementation | Replace it with your own implementation class in the startup manager |

## Verification

- Run the startup flow and observe whether it enters the hotfix entry after Patching completes.
- For unit tests, refer to `IHotfixLauncherContractTests`: assert that a successful implementation returns `result.Success == true` with `ErrorMessage` being an empty string; a failing implementation returns `result.Success == false` with `ErrorMessage` equal to the passed-in exception message.

## Background (Optional)

`IHotfixLauncher` is an extension point deliberately exposed by the package: the package only defines the "Patch complete → call Launcher → get result" protocol without binding to any specific hotfix solution, in order to avoid strong coupling with third-party packages such as HybridCLR.
