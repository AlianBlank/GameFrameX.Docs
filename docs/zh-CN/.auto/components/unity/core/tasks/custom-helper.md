# 接入自定义 Helper 替换默认实现

通过 GameFrameX 提供的 `Helper.CreateHelper<T>` 入口,你可以在框架启动时用自定义 Helper 替换默认实现(如日志、压缩、版本、JSON、文本辅助器等),用于对接项目内部的工具链或第三方 SDK。

## 前置条件

- 已按快速开始文档初始化 `GameFrameX` 框架,并能在 `Awake/Start` 中拿到 `GameFrameXComponent`。
- 自定义 Helper 类已实现对应的接口(例如 `GameFrameworkLog.ILogHelper`、`Utility.Compression.ICompressionHelper`、`Utility.Json.IJsonHelper`、`Utility.Text.ITextHelper`、`GameVersion.IVersionHelper`),且在 Unity 程序集能被反射找到。
- 自定义 Helper 为 `MonoBehaviour` 派生类(框架通过 `GameObject.AddComponent` 创建)。

## 操作步骤

### 1. 实现自定义 Helper

新建一个类,实现框架内置接口。下面以替换默认日志辅助器为例:

```csharp
using UnityEngine;
using GameFrameX;

namespace GameFrameX.Runtime
{
    [UnityEngine.Scripting.Preserve]
    public class MyLogHelper : GameFrameworkLog.ILogHelper
    {
        public void Log(GameFrameworkLogLevel level, object message)
        {
            // 接入项目自有日志 SDK,例如上传到服务器或写入本地文件
            MyLogger.Write(level, message);
        }
    }
}
```

Source: [Runtime/Helper/DefaultLogHelper.cs](/Runtime/Helper/DefaultLogHelper.cs#L42-L83)

### 2. 通过字符串类型名注册

把自定义 Helper 的完整类名(含命名空间)传给 `Helper.CreateHelper<T>`。框架会用反射查找该类型并 `AddComponent` 到一个新 `GameObject` 上:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: "GameFrameX.Runtime.MyLogHelper",
    customHelper: null);
```

字符串方式的好处是不需要在场景里预先放好组件,适合纯代码工程。

### 3. 通过预制组件注册

把自定义 Helper 做成 `MonoBehaviour` 脚本挂到一个预制体上,然后直接传给 `customHelper` 参数。框架会判断组件是否已在场景中,决定直接复用还是 `Instantiate` 复制:

```csharp
// myLogHelperPrefab 是预制体上的 MyLogHelper 组件引用
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: string.Empty,
    customHelper: myLogHelperPrefab);
```

`helperTypeName` 留空、`customHelper` 非空时,优先使用 `customHelper`;反之则按字符串查类型;两者都为空时框架会输出警告并返回 `null`。

### 4. 在框架入口挂接

在 `GameFrameXComponent.Awake` 或初始化流程里,把创建好的 Helper 注入到对应子系统。以 `Log` 模块为例:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    "GameFrameX.Runtime.MyLogHelper", null);
GameFrameworkLog.SetLogHelper(logHelper);
```

源码注册入口参见 [Runtime/Helper/Helper.cs](/Runtime/Helper/Helper.cs#L57-L106)。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 警告 `Can not find helper type 'XXX'.` | 字符串类名拼错、命名空间缺失,或程序集未启用反射 | 用 `Type.FullName` 核对;确认类所在程序集未被 IL2CPP 裁剪 |
| 警告 `Type 'A' is not assignable from 'B'.` | 自定义类没实现目标接口 | 让自定义类 `implements` 对应的 `IXxxHelper` |
| 警告 `You must set custom helper with '...' type first.` | `helperTypeName` 留空且 `customHelper` 也为 `null` | 二选一填一个,或先 `AddComponent` 再传入 |
| 自定义逻辑没生效 | 没有调用对应子系统的 `SetXxxHelper` 注入 | 在框架初始化早期完成 `CreateHelper` + `SetHelper` 注入 |

## 背景(可选)

`Helper.CreateHelper<T>` 内部通过 `Utility.Assembly.GetType` 按字符串查找类型,找到后用 `new GameObject().AddComponent` 实例化;当传入 `customHelper` 时,按组件是否已在场景决定复用或 `Instantiate`。两个参数互为兜底,让配置驱动的工程和无配置工程都能接入。
