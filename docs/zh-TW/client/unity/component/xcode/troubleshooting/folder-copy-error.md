# 資料夾複製發生錯誤怎麼辦

在 Unity iOS 打包的後處理階段，`folders` 設定所宣告的資料夾會被複製到 Xcode 專案並自動加入編譯；當 Unity Console 擲出 `DirectoryNotFoundException`、`IOException` 等例外，或複製後檔案/框架遺失時，請按下方診斷表定位原因並修復。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `DirectoryNotFoundException: Could not find a part of the path ...` | `folders` 的 Key 來源路徑不存在：Key 是相對 Unity 專案根目錄(與 `Assets` 同層)，不是相對 `Assets` 的路徑 | 見修復步驟 1 |
| `IOException` / `UnauthorizedAccessException`,於刪除目標目錄時擲出 | 目標目錄被 Xcode 等程式佔用，或其中含有唯讀檔案 | 關閉佔用的程式或手動刪除目標目錄後重新打包，見修復步驟 2 |
| 複製成功但個別檔案遺失 | 檔名以 `.` 開頭、或為 `.gitkeep` / `.DS_Store`,會被主動過濾 | 屬預期行為，見修復步驟 3 |
| `.framework` / `.bundle` / `.a` 複製後連結錯誤(找不到符號) | 歷史版本的資料夾複製連結 bug,或副檔名不正確未被識別 | 升級至最新版本，見修復步驟 4 |

## 修復步驟

### 1. 來源路徑不存在(DirectoryNotFoundException)

複製時來源路徑按以下方式串接，`Environment.CurrentDirectory` 即 Unity 專案根目錄，與 `Assets` 同層：

```csharp
string src = Path.Combine(Environment.CurrentDirectory, map.Key.ToString().Trim());
string des = Path.Combine(xcodePath, map.Value.ToString().Trim());
CopyFolder(src, des);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L29-L31)

檢查並修正 JSON 設定(路徑前後的空白會被 `Trim()` 去除)：

```json
{
  "folders": {
    "XC": "Classes/XC"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L191-L197)

- Key:資料夾在 Unity 專案根目錄下的路徑，不要誤寫成 `Assets/` 開頭
- Value:複製到 Xcode 專案內的相對路徑

### 2. 刪除目標目錄失敗(IOException)

`CopyFolder` 在複製前會先刪除已存在的目標目錄與同名檔案，再重建目錄：

```csharp
if (Directory.Exists(dstPath))
{
    Directory.Delete(dstPath, true);
}

if (File.Exists(dstPath))
{
    File.Delete(dstPath);
}

Directory.CreateDirectory(dstPath);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L174-L184)

`Directory.Delete(dstPath, true)` 採遞迴刪除，當目標內有檔案被佔用或為唯讀時會擲出例外：

1. 關閉正在開啟該 Xcode 專案(或佔用該目錄)的程式
2. 手動刪除 Xcode 專案內的目標目錄
3. 重新執行 Unity iOS 建置

### 3. 個別檔案沒有被複製

複製與加入編譯都會經過 `IsNeedCopy` 過濾：

```csharp
private static bool IsNeedCopy(string file)
{
    string fileName = Path.GetFileNameWithoutExtension(file);
    if (fileName.StartsWith(".") || file.EndsWith(".gitkeep") || file.EndsWith(".DS_Store"))
    {
        return false;
    }

    return true;
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L112-L121)

檔名(不含副檔名)以 `.` 開頭、`.gitkeep`、`.DS_Store` 一律跳過。若需要保留空目錄佔位檔案，請改用非點前綴命名。

### 4. framework / bundle / 靜態庫連結錯誤

`AddFolderBuild` 依副檔名區分處理方式，請確認目標路徑(即 `folders` 的 Value)副檔名正確：

| Value 結尾 | 處理方式 |
|------------|----------|
| `.framework` | `AddFile` + `AddFileToBuild` + `AddFrameworkToProject` |
| `.bundle` | 同時加入 UnityFramework target 與主 target |
| `.xcframework` / `.a` | `AddFile` + `AddFileToBuild` |
| 一般目錄 | 遞迴展開子目錄與檔案，並對框架/靜態庫自動補上搜尋路徑(`AutoAddSearchPath`) |

```csharp
if (root.EndsWith(".framework") || root.EndsWith(".bundle"))
{
    Debug.LogFormat("add framework/bundle to build:{0}->{1}", currDir, root);
    string fileGuid = proj.AddFile(currDir, root, PBXSourceTree.Source);
    proj.AddFileToBuild(targetGuid, fileGuid);
    if (root.EndsWith(".bundle"))
    {
        proj.AddFileToBuild(mainTargetGuid, fileGuid);
    }
    // 新增為 linked framework
    proj.AddFrameworkToProject(targetGuid, root, false);
    return;
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L47-L59)

## 驗證

1. 重新執行 Unity iOS 建置，Console 無 `DirectoryNotFoundException` / `IOException` 例外，且能看到 `add framework/bundle to build:...`、`add file to build:...` 日誌
2. 開啟產生的 Xcode 專案，`folders` 中 Value 指向的目錄已存在且內容齊全
3. `.framework` / `.bundle` 出現在 **General → Frameworks, Libraries, and Embedded Content** 或 **Build Phases → Link Binary With Libraries** 中，編譯通過
