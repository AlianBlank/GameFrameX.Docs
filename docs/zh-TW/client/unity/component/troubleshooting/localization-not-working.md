# 本地化文字不生效怎麼辦

當你呼叫 `GameApp.Localization.GetString(key)` 或透過 FairyGUI/UI 元件尋找多語言文字時，得到的仍是舊語言字串、Key 本身、或空值，表示本地化資料沒有按當前 `GameApp.Localization.Language` 裝填。本頁提供常見原因、對應的診斷方法與修復步驟。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 呼叫 `GetString(key)` 回傳 Key 字串本身 | 設定表 `Key` 欄位為空或未產生 | 檢查 `local_tblocalization.json` 中 `key` 欄是否填寫，並重新產生設定程式碼 |
| 切換 `Language` 後文字沒變化 | 沒有呼叫 `TranslateText()` 或呼叫順序不對 | 在啟動流程中，先 `Config.GetConfig<TbLocalization>()`,再呼叫 `TranslateText()` |
| `AddRawString` 時拋出 `SerializationException` | 設定表 JSON 與產生的 `Localization` 欄位不匹配 | 用 LuBan 重新匯出 `local_tblocalization.json`,確認所有 15 個語言欄位齊全 |
| 某些語言(例如泰語、印尼語)始終為空 | 該語言分支沒有在 `switch` 中處理或表中欄位為空 | 在 `local_tblocalization.json` 中補齊對應語言欄，或在 `Localization.cs` 產生器中加分支 |
| 執行後所有本地化字串都是英文 | `DefaultLanguage == English` 且 `Language` 不在 switch 分支中 | 確認 `GameApp.Localization.Language` 命中上方分支，或擴充 default 分支的回退邏輯 |

## 修復步驟

### 1. 確認啟動流程呼叫了 `TranslateText`

`TranslateText()` 負責把 `TbLocalization` 表裡的多語言欄位按當前語言寫入底層字典，跳過它將拿不到任何值。

```csharp
// 1. 刪除來源資料
GameApp.Localization.RemoveAllRawStrings();
// 2. 從設定表中載入資料
var tbLocalization = GameApp.Config.GetConfig<TbLocalization>();
// 3. 裝填資料訊息
tbLocalization.ForEach(localization =>
{
    if (localization.Key.IsNullOrWhiteSpace())
    {
        return;
    }
    // ... switch GameApp.Localization.Language ...
    GameApp.Localization.AddRawString(localization.Key, value);
});
```

Source: [HotfixLauncher.cs#L66-L164](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L66-L164)

注意：Key 為空白的行會直接 `return`,不會寫入字典。請回到設定表裡把 Key 補齊。

### 2. 核對當前語言在 switch 分支中

產生的 `Localization` 實體共 15 個語言欄位，啟動器按 `LocalizationCode` 列舉逐一匹配。漏匹配的語言會落到 `default`,只會在 `DefaultLanguage == English` 時拿到英文，其他情況保持 `string.Empty`。

```csharp
case LocalizationCode.ChineseSimplified:
    value = localization.ChineseSimplified;
    break;
case LocalizationCode.English:
    value = localization.English;
    break;
// ... ChineseTraditionalTW / HK / French / German / Italian / Japanese /
//     Korean / Portuguese* / Spanish* / Thai / Vietnamese / Russian / Indonesian
default:
{
    if (GameApp.Localization.DefaultLanguage == LocalizationCode.English)
    {
        value = localization.English;
    }
}
    break;
```

Source: [HotfixLauncher.cs#L82-L161](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L82-L161)

如果你的目標語言不在上面這些分支(例如新增了阿拉伯語)，需要：

1. 在 LuBan 表 `local_tblocalization.json` 新增對應欄。
2. 重新產生 `Localization.cs`,讓新欄位進入建構函式和 JSON 解析。
3. 在 `HotfixLauncher.TranslateText` 的 switch 裡追加一個 `case`,把欄位映射到 `value`。

### 3. 檢查設定表與產生程式碼是否同步

產生的 `Localization` 建構函式對每個欄位都做了非字串校驗，缺少欄位會讓反序列化拋出 `SerializationException`,導致整張表載入失敗。

```csharp
public Localization(JSONNode _buf)
{
    { if(!_buf["key"].IsString) { throw new SerializationException(); }  Key = _buf["key"]; }
    { if(!_buf["ChineseSimplified"].IsString) { throw new SerializationException(); }  ChineseSimplified = _buf["ChineseSimplified"]; }
    { if(!_buf["English"].IsString) { throw new SerializationException(); }  English = _buf["English"]; }
    // ... 其他 12 種語言同構校驗
}
```

Source: [Localization.cs#L38-L59](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Local/Localization.cs#L38-L59)

修復方式：用 LuBan 編輯器開啟 `local_tblocalization.json`,確認 15 個語言欄位名稱(ChineseSimplified、ChineseTraditional、English、Japanese、Korean、Thai、Indonesian、French、German、Russian、Italian、PortuguesePortugal、Spanish、Vietnamese)以及 `key` 欄都存在且為字串，然後重新產生程式碼。

### 4. 切換語言後強制重新整理介面

單純修改 `GameApp.Localization.Language` 不會重新讀取設定，需要重新執行一次 `TranslateText()` 才會把字典裡的舊值覆蓋。常見做法是在切語言事件裡呼叫該方法，然後向 UI 層廣播 `OnLanguageChanged`。

## 驗證

按以下順序確認問題已解決：

1. 執行遊戲，在主控台確認 `tbLocalization` 行數大於 0,且沒有 `SerializationException`。
2. 在腳本裡臨時呼叫一次 `GameApp.Localization.GetString("你設定表裡的某個 Key")`,以中斷點確認回傳的是當前 `Language` 對應的字串，而不是 Key 本身。
3. 透過 FairyGUI/UGUI 的本地化元件開啟一個用了 Key 的文字節點，執行時檢查顯示值。
4. 切換 `GameApp.Localization.Language = LocalizationCode.English`(或其他語言)，重新呼叫 `TranslateText()`,再次確認 UI 文字隨切換更新。

## 常見錯誤

- 直接改了 `local_tblocalization.json` 後忘了點 LuBan 的「產生程式碼」，導致執行時程式碼裡的欄位名稱對不上，反序列化時靜默失敗。
- `TranslateText()` 寫成在 `Awake` 呼叫，但此時 `GameApp.Config` 還沒初始化完成，導致 `GetConfig<TbLocalization>()` 回傳 null。
- 表裡 Key 寫了中文/帶空格的字串，雖然合法但呼叫方傳 Key 時容易寫錯，建議統一用英數 + 底線。
- 在 `default` 分支依賴英文作為後備，但 `DefaultLanguage` 不是 `English`,會讓部分語言顯示為空字串。
