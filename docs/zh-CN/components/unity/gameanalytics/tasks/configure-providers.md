# 如何添加与配置统计 Provider

在 `GameAnalyticsComponent` 组件的 Inspector 中,把实现了 `IGameAnalyticsManager` 的类型加入「游戏数据分析组件列表,按序上报」,并为每个条目填写 `Setting` 键值对;运行时组件会自动反射实例化所有 Provider 并调用其 `Init`,后续所有上报接口会按列表顺序转发给每一个 Provider。

## 前置条件

- 已安装本包 `com.gameframex.unity.gameanalytics`。
- 场景中已存在 `GameAnalyticsComponent`(可通过 `Add Component → Game Framework → GameAnalytics` 添加)。
- 场景中至少有一个实现了 `IGameAnalyticsManager` 接口的统计实现类(通常由各个第三方 SDK 适配包提供),否则 Inspector 的下拉列表里只有 None。

## 操作步骤

1. 选中挂有 `GameAnalyticsComponent` 的 GameObject,Inspector 会由 `GameAnalyticsComponentInspector` 绘制一个可排序列表,标题为「游戏数据分析组件列表,按序上报」。

2. 点击列表右下角的 `+` 新增一个条目。每个条目对应一个 `GameAnalyticsComponentProvider`,其序列化字段如下:

| 字段 | 类型 | 说明 |
|------|------|------|
| `ComponentType` | `string` | 实现 `IGameAnalyticsManager` 的类型完整名,由下拉框自动写入 |
| `ComponentTypeNameIndex` | `int` | 编辑器下拉框当前索引,运行时不使用 |
| `Setting` | `List<GameAnalyticsComponentParamKV>` | 传给该 Provider 的初始化参数,每项为一对 `Key`/`Value` 字符串 |

```csharp
[Serializable]
public class GameAnalyticsComponentProvider
{
    /// <summary>
    /// 实现组件类型
    /// </summary>
    public string ComponentType;

    /// <summary>
    /// 这个是给编辑器用的
    /// </summary>
    public int ComponentTypeNameIndex = 0;

    /// <summary>
    /// 参数
    /// </summary>
    public List<GameAnalyticsComponentParamKV> Setting = new List<GameAnalyticsComponentParamKV>();
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L361-L378)

3. 在 `ComponentType` 下拉框中选择目标实现类。下拉项由 Inspector 通过反射收集所有 `IGameAnalyticsManager` 的运行时类型生成,选中后会把类型名写入 `ComponentType` 字符串:

```csharp
managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

4. 在 `Setting` 中填写该 Provider 需要的初始化参数(如 AppKey、Channel 等由具体 SDK 实现定义的键)。如果实现程序集中存在继承自 `BaseGameAnalyticsSetting` 的类,Inspector 会按其公共字段自动补齐 Setting 条目,只需填 Value:

```csharp
var types = type.Assembly.GetTypes();
foreach (var typeImpl in types)
{
    if (typeImpl.BaseType != typeof(BaseGameAnalyticsSetting))
    {
        continue;
    }

    var fieldInfos = typeImpl.GetFields();
    ...
}
```
Source: [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L148-L158)

5. 进入 Play 模式。组件在 `OnEnable` 中调用 `Init()`,对每个条目反射创建实例并把 `Setting` 转成字典传入:

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }

        if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
        {
            Dictionary<string, string> args = new Dictionary<string, string>();
            foreach (var param in gameAnalyticsComponentProvider.Setting)
            {
                args[param.Key] = param.Value;
            }

            gameAnalyticsManager.Init(args);
            m_GameAnalyticsManager.Add(gameAnalyticsManager);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L79)

6. 利用列表的拖拽手柄调整顺序。顺序只影响转发顺序,不影响功能;`Init` 与后续所有上报调用都按列表顺序执行。

## 常见变体

- **需要登录后补充初始化的 SDK**:部分 Provider 实现了 `IsManualInit()`,在拿到用户信息后调用组件的 `ManualInit(Dictionary<string, string> extraArgs)`,组件会把 `extraArgs` 转发给所有需要手动初始化的 Provider:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```
Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

- **设置玩家 ID / 公共属性**:调用 `SetPlayerId(string playerId)`、`SetPublicProperties(string key, object value)`、`ClearPublicProperties()` 会同步转发给列表中的所有 Provider,无需逐个调用。
- **自定义 Provider**:新建类实现 `IGameAnalyticsManager`(接口定义见 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8)),必须提供无参构造函数(组件用 `Activator.CreateInstance` 实例化);如希望 Inspector 自动生成 Setting 键,再在同一程序集定义一个继承 `BaseGameAnalyticsSetting` 的类并用公共字段声明各配置项。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 日志 `Can not find component type 'XXX'.`,该条目被跳过 | `ComponentType` 类型名无法通过 `Utility.Assembly.GetType` 解析:实现类所在程序集未参与构建,或手改了序列化值 | 确认实现包已引入并在 Inspector 下拉框中重新选择类型 |
| 日志 `GameAnalyticsManager is not init.` | 组件尚未 `Init` 就调用了上报接口(如组件被禁用导致 `OnEnable` 未执行) | 确保 `GameAnalyticsComponent` 处于启用状态;必要时手动调用 `Init()` |
| 某个条目被静默忽略,无任何报错 | `ComponentType` 留空,`Init` 中 `IsNotNullOrWhiteSpace` 检查未通过直接跳过 | 为该条目在下拉框选择实现类型 |
| `ManualInit` 调用没有效果 | `m_IsInit` 为 false 时 `ManualInit` 直接 return;或该 Provider 的 `IsManualInit()` 返回 false | 先确认 Play 后已触发 `Init`,再检查实现的 `IsManualInit` 逻辑 |
| 修改 Inspector 配置后运行仍用旧配置 | `Init` 由 `m_IsInit` 保护,只在首次调用时生效 | 重启 Play 模式;不要期望运行中重复调用 `Init` 生效 |

## 验证

- Play 后 Console 无 `Can not find component type` 报错,说明所有条目的类型解析成功。
- 调用 `SetPlayerId` 等转发接口时无 `GameAnalyticsManager is not init.` 警告,说明 Provider 列表已初始化完成。
- 在各 Provider 实现的 `Init(Dictionary<string, string>)` 内打断点或加日志,确认 `Setting` 中的键值已按配置传入。

## 背景

组件不直接依赖任何具体 SDK:它在 `Init` 时用反射按 `ComponentType` 创建实例、把 `Setting` 列表转成 `Dictionary<string, string>` 传给 `Init(args)`,之后所有公共接口(set/上报等)都遍历 `m_GameAnalyticsManager` 逐个转发,从而实现多套统计 SDK 同时按序上报。
