# 取消進行中圖片載入的方法

透過 `CancellationToken` 取消載入任務，`LoadImageAsync` 會在適當的時機中斷後續處理並回傳 `null`。取消機制僅在 WebGL 以外的平台上有效，且不會在下載處理進行中立即阻斷網路請求。

## 前置條件

- 已透過 `GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>()` 取得圖片快取元件。
- 目標建置平台不是 WebGL（在 WebGL 上 `cancellationToken` 會被忽略。詳情請參閱後述的「常見錯誤」）。

## 操作步驟

1. **建立可取消的權杖來源**。使用 `CancellationTokenSource` 產生權杖，並透過 `Token` 屬性傳遞給載入介面。

   ```csharp
   using System.Threading;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   var component = GameFrameX.Runtime.Entry.GetComponent<ImageCacheComponent>();
   var cts = new CancellationTokenSource();
   ```

2. **開始載入並傳遞權杖**。呼叫 `LoadImageAsync(url, cts.Token)` 以取得 `Task<Texture2D>`。

   ```csharp
   var task = component.LoadImageAsync("https://example.com/foo.png", cts.Token);
   ```

3. **在適當的時機呼叫 `Cancel()`**。在頁面關閉、清單項目回收等情況發生時觸發取消。

   ```csharp
   cts.Cancel();
   ```

4. **處理回傳值**。已取消的任務會回傳 `null`（不會拋出例外）。請將其視為失敗時的分支來處理。

   ```csharp
   var tex = await task; // 若已取消則回傳 null
   if (tex == null) return;
   ```

   來源： [ImageCacheManager.cs#L70-L89](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## 常見變化

- **與 `MonoBehaviour` 生命週期連動的自動取消**：將 `CancellationTokenSource` 綁定到 GameObject 的生命週期（例如：在自訂 `MonoBehaviour` 的 `OnDestroy` 中呼叫 `cts.Cancel()`）。如此一來，場景切換時就無需手動管理。
- **逾時取消**：使用 `cts.CancelAfter(TimeSpan.FromSeconds(5))` 設定逾時並自動取消。
- **依條件取消多個任務**：讓多個 `LoadImageAsync` 呼叫共用同一個 `CancellationTokenSource`，只需呼叫一次 `Cancel()` 即可全部中止。

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| 在 WebGL 平台上呼叫 `Cancel()` 後任務仍會完成 | `LoadImageAsync` 在 `#if UNITY_WEBGL` 分支中不接收 `cancellationToken`。請參閱 [ImageCacheManager.cs#L84-L85](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L85) | 在 WebGL 上需由業務層以旗標等方式自行銷毀回傳的 Texture2D |
| 取消後下載仍會在背景繼續執行，並在磁碟上產生快取檔案 | 目前的實作僅在下載**成功完成後**才會確認權杖，因此進行中的下載不會被中斷。請參閱 [ImageCacheManager.cs#L139-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L139-L149) | 若想完全停止請求，請在取消前主動從 `_downloadManager` 移除任務，或在業務層忽略下載結果 |
| 呼叫 `Cancel()` 後，await 的任務拋出 `OperationCanceledException` | 本介面不使用 `ThrowIfCancellationRequested`，因此取消時一律回傳 `null`。請參閱 [ImageCacheManager.cs#L146-L149](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L146-L149) | 請以 `if (tex == null)` 判斷是否取消，不要去捕捉 `OperationCanceledException` |

## 驗證

取消成功時，若滿足以下兩點即屬正常。

- `await LoadImageAsync(...)` 回傳 `null`。
- 不會拋出 `OperationCanceledException`，且後續的圖片解碼日誌也不會輸出（因為偵測到取消後會直接 `return null`）。

## 背景（選讀）

WebGL 以外分支的 `LoadImageDiskCacheAsync` 僅在「下載完成 → 準備讀取本機檔案」之間確認一次 `IsCancellationRequested`。因此取消的實際意義是「下載結束後捨棄本次結果」，而非中斷網路請求。WebGL 平台是以 `UnityWebRequestTexture` + 瀏覽器快取實作，因此方法的簽章中並未公開權杖，呼叫端只能在取得結果後自行判斷是否可用。
