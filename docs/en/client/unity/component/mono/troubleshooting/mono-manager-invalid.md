# What to Do When You See the Log "Mono manager is invalid."

When `MonoComponent.Awake()` fails to retrieve a registered `IMonoManager` implementation via `GameFrameworkEntry.GetModule<IMonoManager>()`, it immediately calls `Log.Fatal("Mono manager is invalid.")` and aborts the subsequent initialization. As a result, none of `Update` / `FixedUpdate` / `LateUpdate` will be executed.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Console log: `Mono manager is invalid.` | The `MonoManager` module has not been registered with `GameFrameworkEntry` | Call `GameFrameworkEntry.RegisterModule(new MonoManager())` in `GameEntry` / the startup flow before `MonoComponent` |
| Same as above, with only `MonoComponent` in the scene but no `GameFrameworkEntry` bootstrap | Incorrect startup order: `MonoComponent`'s `Awake` runs before `GameFrameworkEntry` is initialized | Adjust the script execution order to ensure `GameFrameworkEntry` completes registration first |
| Same as above, followed by "Event manager is invalid." | `EventComponent` is also missing | Add an `EventComponent` to `GameEntry`; see [`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76) |

## Fix Steps

### 1. Register the `MonoManager` Module at Startup

`MonoComponent` is only responsible for "invoking an already-existing manager"; the responsibility of actually creating and registering the module lies with the startup flow. The framework entry must explicitly call:

```csharp
using GameFrameX.Mono.Runtime;
using GameFrameX.Runtime;

// In the GameFrameworkEntry initialization phase (earlier than any MonoComponent.Awake)
GameFrameworkEntry.RegisterModule(new MonoManager());
```

The registration logic only accepts `IMonoManager` implementations, and `MonoManager` is the default implementation shipped with the framework ([`MonoManager.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L42-L43)).

### 2. Ensure `MonoComponent`'s `Awake` Runs After `GameFrameworkEntry`

`MonoComponent` retrieves the module in `Awake` via `GameFrameworkEntry.GetModule<IMonoManager>()` ([`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L57-L62)). If `MonoComponent` is attached to a GameObject that runs `Awake` earlier than the `GameFrameworkEntry` bootstrap script, `GetModule` will return `null`.

How to fix:
1. Attach `MonoComponent` to a separate GameObject to ensure the `GameFrameworkEntry` entry component's `Awake` runs before it.
2. In Unity's `Project Settings → Script Execution Order`, place `MonoComponent` after the startup component.

### 3. Do Not Disable or Rename `MonoComponent`

- The class is annotated with `[DisallowMultipleComponent]` and `[AddComponentMenu("GameFrameX/Mono")]` ([`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L42-L43)). Duplicate attachments or renaming the inheritance chain will cause the base class's `Awake` behavior to become abnormal, leading to module retrieval failures.

## Verification

1. Launch the game and confirm that `Mono manager is invalid.` no longer appears in the console, but that the normal Mono event flow is visible instead.
2. Callbacks registered via `IMonoManager.AddUpdate(...)` should be triggered every frame:

```csharp
var mono = GameFrameworkEntry.GetModule<IMonoManager>();
mono.AddUpdate((dt, udt) => { /* Executed every frame */ });
```

3. If `MonoComponent.Start()` still reports `Event manager is invalid.`, it means `EventComponent` is not attached. Follow the check path in `MonoComponent.Start` to address this ([`MonoComponent.cs`](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L68-L76)).
