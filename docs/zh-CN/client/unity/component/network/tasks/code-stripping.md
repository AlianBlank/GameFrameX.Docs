# 处理打包时代码裁剪

当你在 Player Settings 中开启了 **Managed Stripping Level**(尤其是 High/Medium)或使用 IL2CPP 打包后,若出现 `NetworkComponent`、网络事件类丢失、`CreateNetworkChannel` 报 `MissingMethodException` / `TypeLoadException` 之类的问题,通常是 Unity 的托管代码裁剪把未被静态引用的类型/方法裁掉了。本包已在关键类型上标注 `[UnityEngine.Scripting.Preserve]`,大部分情况无需额外处理;被裁掉的通常是你自己项目里通过反射/字符串注册的部分,按下面步骤补齐保护即可。

## 前置条件

- Unity 版本不低于 2019.4(本包 `package.json` 声明的最低版本)。
- 已安装 `com.gameframex.unity.network`(当前版本 2.6.10)及其依赖 `com.gameframex.unity`、`com.gameframex.unity.event`、`com.gameframex.unity.litjson`。
- 打包目标平台使用 IL2CPP 或在 Player Settings 中开启了 Managed Stripping Level(Low/Medium/High)。

## 操作步骤

1. 先确认包内自带的保护是否已生效。本包对入口组件与公开 API 逐个标注了 `[UnityEngine.Scripting.Preserve]`,例如 `NetworkComponent` 类本身:

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/Network")]
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkComponent : GameFrameworkComponent
   ```
   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L42-L45)

   其公开方法(如 `CreateNetworkChannel`、`GetNetworkChannel`)同样带 `[Preserve]`:

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   ```
   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L175-L176)

   网络事件参数类也全部带 `[Preserve]`(这些类常通过事件系统按类型派发,容易被裁剪):

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public sealed class NetworkConnectedEventArgs : GameEventArgs
   ```
   Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L40-L41)

   同样处理的还有 `NetworkClosedEventArgs`、`NetworkErrorEventArgs`、`NetworkMissHeartBeatEventArgs`,以及 `NetworkManager.HeartBeatState` 的无参构造(框架内部会反射创建状态对象):
   Source: [NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L43-L45)

2. 打开 **Edit → Project Settings → Player → Other Settings → Optimization → Managed Stripping Level**,确认当前裁剪级别。若仅出现零星类型丢失,可先把级别降到 **Low(或 Minimal)** 打包验证,确认问题确实来自裁剪。

3. 检查你**自己项目**中被裁剪的类型。常见会被裁掉、而本包无法替你保护的:
   - 你实现的 `INetworkChannelHelper` 派生类(发包/收包头部与包体处理器);
   - 你通过 `NetworkComponent` 注册、但只被字符串/反射引用的消息处理器;
   - 序列化用的数据模型(如 LitJSON 相关 DTO)。

4. 对上述自有类型,优先在类与公开成员上加 `[UnityEngine.Scripting.Preserve]`(与包内做法一致):

   ```csharp
   // 你项目中的写法示例:属性用法与包内 NetworkComponent 相同
   [UnityEngine.Scripting.Preserve]
   public sealed class MyNetworkChannelHelper : INetworkChannelHelper
   {
       ...
   }
   ```

5. 若被裁类型数量多、逐个加特性不现实,在工程 `Assets/` 下新建 `link.xml`,按程序集整体保留(这是 Unity 官方机制;**本仓库内没有自带 link.xml**,需要你在使用方工程自行创建):

   ```xml
   <linker>
     <!-- 保留整个网络程序集 -->
     <assembly fullname="GameFrameX.Network.Runtime" preserve="all"/>
     <!-- 保留你自己的业务/协议程序集 -->
     <assembly fullname="YourAssemblyName" preserve="all"/>
   </linker>
   ```

6. 重新打包,在构建日志中确认无 `MissingMethodException`/`TypeLoadException`,并按下面"验证"小节做一次真机连接测试。

## 验证

- 打包后运行,场景中挂载的 `NetworkComponent`(菜单路径 GameFrameX/Network)能正常创建;
- 调用 `CreateNetworkChannel` 返回的频道可完成连接,能收到 `NetworkConnectedEventArgs` 事件;
- 心跳逻辑正常(说明 `HeartBeatState` 未被裁剪),断网时能收到 `NetworkMissHeartBeatEventArgs`/`NetworkErrorEventArgs`。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 打包后报 `TypeLoadException`/`MissingMethodException`,编辑器下正常 | Managed Stripping 裁掉了仅被反射引用的类型 | 降级 Managed Stripping Level,或给对应类型加 `[UnityEngine.Scripting.Preserve]` |
| 心跳状态对象创建失败 | `HeartBeatState` 无参构造被裁(框架内部反射创建) | 包内已加 `[Preserve]`;若你 fork/改动了此文件,确保保留该特性 |
| 收不到 `NetworkConnectedEventArgs` 等网络事件 | 事件参数类被裁,事件系统反序列化失败 | 包内已加 `[Preserve]`;检查是否有 fork 覆盖或自己的 EventArgs 漏标 |
| 自己的 `INetworkChannelHelper` 派生类方法丢失 | 你项目中的类型未被静态引用 | 给你的 Helper 类加 `[Preserve]` 或写 link.xml |
| 加了 link.xml 仍被裁 | 文件不在 `Assets/` 内或 XML 格式错误 | 确认路径与 `assembly fullname` 拼写(见 asmdef 中的程序集名) |

## 背景

Unity 在 IL2CPP/High Stripping 打包时会删除从托管代码入口静态不可达的类型与成员。网络框架大量使用"接口 + 反射 + 事件派发"模式——例如通过 `INetworkManager` 接口定位实现、通过事件系统按类型分发 `NetworkConnectedEventArgs` 等参数类——这些引用对裁剪器不可见,因此本包在这些关键位置逐个标注了 `[UnityEngine.Scripting.Preserve]`(见上文步骤 1 引用的源码)。它能覆盖包内所有公开类型,但无法覆盖你项目侧通过反射注册的类型,这类需要你按同样方式自行保护。
