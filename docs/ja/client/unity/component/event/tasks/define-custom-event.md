# カスタムイベント引数の定義方法

カスタムイベント引数を定義するには、`GameEventArgs` を継承する新しいクラスを作成し、`Id` と `Clear()` をオーバーライドし、`ReferencePool.Acquire<T>()` でインスタンスを作成する静的な `Create` ファクトリメソッドを提供するだけです。その後、`EventComponent` を通じてそのイベントを購読・発火できます。

## 前提条件

- プロジェクトに GameFrameX Event パッケージがインストールされており、シーンに `EventComponent` コンポーネントが存在すること（メニュー `GameFrameX/Event`。フレームワーク起動時に自動的にアタッチされます）。
- 名前空間 `GameFrameX.Event.Runtime` と `GameFrameX.Runtime` を参照すること。

## 操作手順

1. イベント引数クラスを新規作成し、`GameEventArgs` を継承します（これは `BaseEventArgs` の抽象サブクラスであり、コードストリッピングを防ぐ `Preserve` 属性が付けられています）：

```csharp
using GameFrameX.Runtime;

namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// ゲームロジックイベントの基底クラス。
    /// </summary>
    [UnityEngine.Scripting.Preserve]
    public abstract class GameEventArgs : BaseEventArgs
    {
    }
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L30-L41)

2. フレームワーク組み込みの `EmptyEventArgs` の書き方に従ってイベント引数を実装します：`Id` をオーバーライドしてイベント ID を返し、`Clear()` をオーバーライドしてフィールドを元に戻し、静的な `Create` メソッドで参照プールからオブジェクトを取得します。以下の `PlayerLevelUpEventArgs` は同じパターンで書かれたカスタムのサンプルです：

```csharp
using GameFrameX.Runtime;

namespace GameFrameX.Event.Runtime
{
    /// <summary>
    /// プレイヤーレベルアップイベント引数
    /// </summary>
    public sealed class PlayerLevelUpEventArgs : GameEventArgs
    {
        public int OldLevel { get; private set; }
        public int NewLevel { get; private set; }

        /// <summary>
        /// イベント ID。デフォルトでは型のフルネームを使用し、購読時と発火時には同じ文字列を使用する
        /// </summary>
        public override string Id
        {
            get { return typeof(PlayerLevelUpEventArgs).FullName; }
        }

        /// <summary>
        /// 参照プールに回収される際に呼び出される。すべてのフィールドをデフォルト値に戻す必要がある
        /// </summary>
        public override void Clear()
        {
            OldLevel = 0;
            NewLevel = 0;
        }

        /// <summary>
        /// イベント引数を作成し、参照プールからインスタンスを取得する
        /// </summary>
        public static PlayerLevelUpEventArgs Create(int oldLevel, int newLevel)
        {
            var eventArgs = ReferencePool.Acquire<PlayerLevelUpEventArgs>();
            eventArgs.OldLevel = oldLevel;
            eventArgs.NewLevel = newLevel;
            return eventArgs;
        }
    }
}
```

上記で参考にしたフレームワークの元の実装は以下の通りです。`Id`、`Clear()`、`Create` の三点セットと `ReferencePool.Acquire<T>()` の使い方はこれを基準にします：

```csharp
public sealed class EmptyEventArgs : GameEventArgs
{
    private string _eventId = typeof(EmptyEventArgs).FullName;

    public override void Clear()
    {
        _eventId = typeof(EmptyEventArgs).FullName;
    }

    public override string Id
    {
        get { return _eventId; }
    }

    public static EmptyEventArgs Create(string eventId)
    {
        var eventArgs = ReferencePool.Acquire<EmptyEventArgs>();
        eventArgs.SetEventId(eventId);
        return eventArgs;
    }

    private void SetEventId(string eventId)
    {
        _eventId = eventId;
    }
}
```

Source: [EmptyEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/EmptyEventArgs.cs#L7-L49)

3. イベントを購読します。`EventComponent` の外部向けの購読エントリは `CheckSubscribe` です（存在しない場合にのみ購読し、重複購読を防ぎます）：

```csharp
// シグネチャ：public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
EventComponent.CheckSubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);

private void OnPlayerLevelUp(object sender, GameEventArgs e)
{
    var args = (PlayerLevelUpEventArgs)e;
    Debug.Log($"レベルアップ：{args.OldLevel} -> {args.NewLevel}");
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L100-L111)

4. イベントを発火します。`Fire` はスレッドセーフで次のフレームにディスパッチされ、`FireNow` は即時にディスパッチされますがスレッドセーフではありません：

```csharp
// シグネチャ：public void Fire(object sender, GameEventArgs e)
EventComponent.Fire(this, PlayerLevelUpEventArgs.Create(10, 11));

// シグネチャ：public void FireNow(object sender, GameEventArgs e)
EventComponent.FireNow(this, PlayerLevelUpEventArgs.Create(10, 11));
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L171)

5. 不要になったら購読を解除します。イベント ID は購読時のものと完全に一致している必要があります：

```csharp
// シグネチャ：public void Unsubscribe(string id, EventHandler<GameEventArgs> handler)
EventComponent.Unsubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);

// handler が未購読の可能性がある場合は安全版を使用。存在しない場合は何も実行されない
EventComponent.CheckUnsubscribe(typeof(PlayerLevelUpEventArgs).FullName, OnPlayerLevelUp);
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L113-L131)

## よくあるバリエーション

- **データを持たないイベント**：新しいクラスを作る必要はなく、フレームワーク組み込みの `EmptyEventArgs` をそのまま使用します。`EventComponent` には便利なオーバーロード `Fire(object sender, string eventId)` が用意されており、内部で自動的に `EmptyEventArgs.Create(eventId)` が呼ばれます。`eventId` に `null` や空文字列を渡すと引数の検証がトリガーされます：

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

- **カスタムのイベント ID 文字列**：`typeof(X).FullName` を使いたくない場合は、`EmptyEventArgs` のように ID をプライベートフィールド `_eventId` として保持し、`Create(eventId)` で渡すことで、一つのクラスで複数のロジックイベントを扱えます。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| イベントを発火してもコールバックが一切呼ばれない | 購読と発火で使用する `Id` 文字列が一致していない | 両方とも `typeof(PlayerLevelUpEventArgs).FullName` に統一する |
| イベントコールバックで読み取ったデータが汚れた値になっている | `Clear()` ですべてのフィールドが元に戻されておらず、インスタンスが参照プールで再利用された後も古い値が残っている | `Clear()` ですべてのフィールドをリセットする |
| 同じコールバックが同一フレームで複数回実行される | 同一 handler を複数回 `Subscribe` している | `CheckSubscribe` に変更し、先に `Check` してから購読する |
| オブジェクト破棄後もコールバックが発生し、NullReferenceException がスローされる | `Unsubscribe` を忘れている | `OnDestroy` で `Unsubscribe` または `CheckUnsubscribe` を呼び出す |
| カスタム引数クラスがコードストリッピングで削除される | クラスが保持されていない | `GameEventArgs` と同様に `[UnityEngine.Scripting.Preserve]` を追加する |

## 背景

イベント引数のインスタンスは `ReferencePool` 参照プール（`ReferencePool.Acquire<T>()`）から取得され、発火・ディスパッチされた後は回収されて再利用されます。そのため、`Clear()` ではフィールドをデフォルト値に戻す必要があります。すべてのイベント引数が `new` ではなく静的な `Create` を通じて作成されるのはこのためです。イベントのディスパッチとスレッドセマンティクスは `IEventManager` によって管理され、`Fire` はコールバックがメインスレッドで発生することを保証します。
