# 收发网络消息(定义消息与注册处理器)

在 GameFrameX Network 中收发消息只需要三步:定义继承自 `MessageObject` 的消息类、编写实现对应 `IPacket*Handler` 接口的处理器类、通过 `INetworkChannel.Send(...)` 发送。处理器**不需要手动注册**——`DefaultNetworkChannelHelper.Initialize` 会反射扫描程序集并自动调用 `RegisterHandler` 完成注册。

## 前置条件

- 已创建并连接网络通道(`NetworkManager` 已就绪)。
- 消息基类 `MessageObject` 来自框架基础库;本包的序列化约束为 `where T : MessageObject`。
- 处理器类必须是**非抽象 class**、实现标记接口 `IPacketHandler`、并提供公共无参构造函数(反射用 `Activator.CreateInstance` 实例化)。

## 操作步骤

1. **定义消息类**:让消息继承 `MessageObject`。通道内部维护的发送队列即为 `GameFrameworkLinkedList<MessageObject>`,序列化入口的泛型约束也是 `MessageObject`:

   ```csharp
   public bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject
   ```

   > 本仓库只包含网络组件本身,不含具体游戏侧消息定义(如 protobuf 消息类),需要在游戏工程中自行定义。

2. **实现处理器**:按收发阶段选择接口实现。所有处理器都必须实现标记接口 `IPacketHandler`(定义于 [IPacketHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/IPacketHandler.cs#L4),注释为"标记接口,用于标识网络消息包处理器"):

   | 接口 | 注册 API(由反射自动调用) | 职责 |
   |------|---------------------------|------|
   | `IPacketReceiveHeaderHandler` | `RegisterHandler(IPacketReceiveHeaderHandler)` | 解析收包包头 |
   | `IPacketReceiveBodyHandler` | `RegisterHandler(IPacketReceiveBodyHandler)` | 反序列化包体为 `MessageObject` |
   | `IPacketSendHeaderHandler` | `RegisterHandler(IPacketSendHeaderHandler)` | 序列化包头 |
   | `IPacketSendBodyHandler` | `RegisterHandler(IPacketSendBodyHandler)` | 序列化包体 |
   | `IPacketHeartBeatHandler` | `RegisterHeartBeatHandler(IPacketHeartBeatHandler)` | 生成/校验心跳包 |
   | `IMessageCompressHandler` / `IMessageDecompressHandler` | `RegisterMessageCompressHandler` / `RegisterMessageDecompressHandler` | 包体压缩/解压 |

   包内已提供默认实现,可直接继承或替换:[DefaultPacketReceiveHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveHeaderHandler.cs#L9)、[DefaultPacketReceiveBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketReceiveBodyHandler.cs#L7)、[DefaultPacketSendHeaderHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendHeaderHandler.cs#L10)、[DefaultPacketSendBodyHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultPacketSendBodyHandler.cs#L9)、[BasePacketHeartBeatHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/BasePacketHeartBeatHandler.cs#L7)。

3. **确认自动注册**:通道初始化时 `DefaultNetworkChannelHelper.Initialize` 会扫描全部程序集类型,凡实现 `IPacketHandler` 的非抽象类都会被实例化并注册到通道:

   ```csharp
   var types = Utility.Assembly.GetTypes();
   foreach (var type in types)
   {
       if (!type.IsClass || type.IsAbstract)
       {
           continue;
       }

       if (!type.IsImplWithInterface(packetHandlerBaseType))
       {
           continue;
       }

       if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
       {
           var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       else if (type.IsImplWithInterface(packetReceiveBodyHandlerBaseType))
       {
           var handler = (IPacketReceiveBodyHandler)Activator.CreateInstance(type);
           InjectChannelSerializer(handler, type);
           m_NetworkChannel.RegisterHandler(handler);
       }
       // ...后续依次匹配 SendHeader / SendBody / HeartBeat / Compress / Decompress
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L73-L107)

4. **发送消息**:调用通道的 `Send` 方法。包内心跳的发送方式即为标准用法:

   ```csharp
   public bool SendHeartBeat()
   {
       if (m_NetworkChannel == null)
       {
           return false;
       }

       var message = m_NetworkChannel.PacketHeartBeatHandler.Handler();
       m_NetworkChannel.Send(message);
       return true;
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L146-L156)

5. **接收消息**:收包后由接收处理器链完成解析,收包体反序列化按 `messageId` 还原为具体 `MessageObject`:

   ```csharp
   public bool DeserializePacketHeader(byte[] source)
   public bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L179-L189)

6. **(可选)监听网络事件**:连接、关闭、心跳丢失与错误事件已由 Helper 统一订阅(`NetworkConnectedEventArgs`、`NetworkClosedEventArgs`、`NetworkMissHeartBeatEventArgs`、`NetworkErrorEventArgs`),在游戏侧通过事件组件订阅即可,见 [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128)。

## 常见变体

- **自定义心跳**:继承 `BasePacketHeartBeatHandler`(同时实现 `IPacketHeartBeatHandler` 与 `IPacketHandler`),实现 `Handler()` 返回心跳消息对象即可;心跳发送时会调用 `m_NetworkChannel.Send(message)`,与普通消息一致。
- **自定义压缩**:分别实现 `IMessageCompressHandler` / `IMessageDecompressHandler` 并加上 `IPacketHandler` 标记,注册后由 `SerializePacketHeader` / `DeserializePacketBody` 流程自动调用;默认实现见 [DefaultMessageCompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageCompressHandler.cs#L10) 与 [DefaultMessageDecompressHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultMessageDecompressHandler.cs#L10)。
- **手动注册处理器**:`INetworkChannel` 同时暴露了各 `RegisterHandler` 重载(含已标记 `[Obsolete("Use RegisterHeartBeatHandler instead")]` 的心跳重载),见 [INetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Interface/INetworkChannel.cs#L150-L181)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 处理器从未被调用 | 类是抽象类、或未实现 `IPacketHandler` 标记接口,反射扫描直接 `continue` 跳过 | 类声明为非抽象并补上 `IPacketHandler` |
| 运行时实例化处理器抛异常 | 反射使用 `Activator.CreateInstance(type)`,缺少公共无参构造函数 | 为处理器添加公共无参构造函数 |
| 一个类匹配到错误的注册分支 | 注册按 `ReceiveHeader → ReceiveBody → SendHeader → SendBody → HeartBeat → Compress → Decompress` 的 `if / else if` 顺序取**第一个匹配** | 每个类只实现一个处理接口,拆分为多个类 |
| 发送/接收包头体解析行为不符预期 | 缺少序列化器注入(仅 `ReceiveBody`、`SendHeader` 分支会调用 `InjectChannelSerializer(handler, type)`) | 为对应处理器配置通道序列化器,或直接使用包内默认处理器 |
| 序列化调用抛参数空异常 | `SerializePacketHeader` / `SerializePacketBody` 内部对 `m_NetworkChannel`、`PacketSendHeaderHandler`、`PacketSendBodyHandler`、`messageObject`、`destination` 做了 `GameFrameworkGuard.NotNull` 校验 | 先完成处理器注册再发送,并确保消息与目标流非空 |

## 验证

- 发送侧:观察通道统计属性 `SendPacketCount` / `SentPacketCount`(发送队列数量 / 已发出数量),Unity Inspector 面板中显示为 "Send Packet",见 [NetworkComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Editor/Inspector/NetworkComponentInspector.cs#L108)。
- 接收侧:在 `IPacketReceiveBodyHandler` 实现中打断点,确认 `DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` 被回调且 `messageObject` 还原成功。

## 背景

设计上收发包处理被拆分为"包头 / 包体"两段、且收发方向各自独立成接口,发送时由 `SerializePacketHeader` 写包头并产出包体缓冲,再由 `SerializePacketBody` 写入包体;接收则反向执行 `DeserializePacketHeader` → `DeserializePacketBody`。标记接口 `IPacketHandler` 配合程序集反射,使新增消息与处理器无需修改框架代码即可被自动接入(见 [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L60-L71))。通道层的发送队列、处理器注册实现位于 [NetworkManager.NetworkChannelBase.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.NetworkChannelBase.cs#L525-L572)。
