# 빠른 시작

이 섹션에서는 GameFrameX.ImageCache를 Unity 프로젝트에 통합하고 "비동기 원격 이미지 로드 → 캐시 적중 → 능동적 정리"의 최소 폐쇄 루프를 실행하는 방법을 설명합니다.

## 사전 조건

- Unity **2019.4 이상 버전**(패키지의 `package.json`에 선언된 최소 버전).
- GameFrameX 프레임워크 기본 패키지 `com.gameframex.unity`(1.1.1 이상)가 설치되어 있어야 합니다.
- WebGL이 아닌 플랫폼의 경우 `IDownloadManager`를 제공하기 위해 `com.gameframex.unity.download`가 추가로 필요합니다.

## 작업 단계

### 1. scopedRegistries 추가

프로젝트 루트 디렉터리의 `Packages/manifest.json`을 편집하여 최상위에 `GameFrameX` 레지스트리를 추가합니다:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ]
}
```

`scopes`는 `com.gameframex`로 시작하는 패키지만 해당 레지스트리에서 해석되도록 제한하여, 다른 패키지의 출처가 오염되는 것을 방지합니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L48-L62)

### 2. 의존성 추가

동일한 `manifest.json`의 `dependencies` 노드에 ImageCache를 추가합니다:

```json
{
  "dependencies": {
    "com.gameframex.unity.imagecache": "0.0.1"
  }
}
```

저장하면 Unity Package Manager가 자동으로 패키지를 해석하고 설치하며, 동시에 `com.gameframex.unity`와 `com.gameframex.unity.download` 두 개의 전이 의존성도 함께 가져옵니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L64-L72)

### 3. 설치 확인

Unity Editor로 돌아가 **Window → Package Manager**를 열고 목록에 **Game Frame X Image Cache**(`com.gameframex.unity.imagecache`)가 표시되는지 확인합니다.

패키지 메타데이터에 등록된 런타임 의존성은 다음과 같으며, 하나라도 누락되면 컴파일이 실패합니다:

| 패키지명 | 버전 | 역할 |
|------|------|------|
| `com.gameframex.unity` | 1.1.1 | 프레임워크 기본 컴포넌트(`GameEntry.GetComponent<T>`) |
| `com.gameframex.unity.download` | 1.1.1 | `IDownloadManager` 제공(WebGL이 아닌 다운로드) |

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/package.json#L24-L27)

### 4. 이미지 하나 로드하기

임의의 스크립트에서 `GameEntry`를 통해 이미지 캐시 컴포넌트를 가져온 후, 원격 이미지를 비동기로 로드할 수 있습니다:

```csharp
// 이미지 캐시 컴포넌트 가져오기
var imageCache = GameEntry.GetComponent<ImageCacheComponent>();

// 원격 이미지 비동기 로드
Texture2D texture = await imageCache.LoadImageAsync("https://example.com/image.png");
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L78-L83)

### 5. 캐시 확인 및 정리

```csharp
// 이미지가 캐시되었는지 확인
bool cached = imageCache.IsCached("https://example.com/image.png");

// 지정된 캐시 제거
imageCache.RemoveCache("https://example.com/image.png");

// 모든 캐시 비우기
imageCache.ClearCache();
```

## 일반적인 변형

### WebGL 플랫폼

WebGL에는 쓰기 가능한 로컬 디스크가 없으므로, 컴포넌트는 `UnityWebRequestTexture`를 사용하며 캐시는 브라우저 자체가 관리합니다. 사전 판단이나 정리를 위해 `IsCached` / `ClearCache`에 의존해서는 **안 됩니다**.

| 플랫폼 | 로드 방식 | 캐시 소유 |
|------|---------|----------|
| iOS / Android / Windows / macOS | `IDownloadManager` + 디스크 | 본 컴포넌트 |
| WebGL | `UnityWebRequestTexture` | 브라우저 |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L97-L100)

## 일반적인 오류

- **`ImageCacheComponent` 타입을 찾을 수 없음**: `GameFrameX` 기본 패키지가 적용되지 않았다는 의미이므로, 먼저 `com.gameframex.unity`가 설치되어 프레임워크에 등록되었는지 확인하세요.
- **WebGL이 아닌 플랫폼 컴파일 시 `IDownloadManager`를 찾을 수 없음**: `com.gameframex.unity.download` 의존성이 누락된 것이므로, 해당 패키지를 다시 설치하면 됩니다.
- **WebGL 플랫폼에서 `ClearCache`가 작동하지 않음**: 예상된 동작입니다. WebGL 캐시는 브라우저가 보유하고 있으므로, 브라우저 자체 또는 HTTP 캐시 헤더를 통해 제어해야 합니다.

## 배경 지식(선택 사항)

ImageCache는 `IDownloadManager`를 통해 원격 이미지를 로컬로 다운로드하며, 파일명은 URL의 MD5를 기반으로 하므로 자연스럽게 중복 제거됩니다. `Texture2D` 인스턴스는 호출자가 보유하고, 컴포넌트는 바이트 저장과 적중 여부만 관리하므로 비즈니스 로직 측은 동시 다운로드에 신경 쓸 필요가 없습니다.
