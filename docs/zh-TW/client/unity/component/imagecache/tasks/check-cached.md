# 如何判斷圖片是否已快取

使用 `IsCached(string url)` 可以判斷指定 URL 的圖片是否已下載至本機快取。快取命中時可避免重複的網路請求。在 WebGL 平台上始終回傳 `false`,在其他平台上則以 URL 的 MD5 值作為檔案名稱來檢查快取檔案是否存在。

## 前置條件

- 已將 `ImageCacheComponent` 附加至遊戲框架的元件管理器(或已持有 `IImageCacheManager` 實例)。
- 目前的建置平台**不是 WebGL**(在 WebGL 上快取沒有意義，介面始終回傳 `false`)。

## 操作步驟

1. 取得快取元件的實例：

```csharp
var cache = GameEntry.GetComponent<ImageCacheComponent>();
```

2. 呼叫 `IsCached`,並傳入遠端圖片的位址：

```csharp
string url = "https://example.com/avatar.png";
bool cached = cache.IsCached(url);
if (cached)
{
    // 已快取命中，可直接進入本機載入流程，或跳過下載提示
}
else
{
    // 進入下載流程(例如:cache.LoadImageAsync(url))
}
```

3. `IImageCacheManager` 也公開了相同的方法，因此可以直接透過介面呼叫：

```csharp
IImageCacheManager manager = cache;
bool cached = manager.IsCached(url);
```

介面簽章請參閱 `IImageCacheManager.cs` 的第 34 行，實作請參閱 `ImageCacheManager.cs` 的第 180 行，元件的包裝請參閱 `ImageCacheComponent.cs` 的第 83 行。

## 常見變化

- **傳入空 URL**:`IsCached(string url)` 在 `url` 為 `null` 或空字串時會直接回傳 `false`,不會拋出例外。
- **WebGL 平台**：由 `#if UNITY_WEBGL` 編譯分支控制，無論是否已下載都會回傳 `false`,請勿據此判斷為「未快取」。
- **與非同步載入搭配使用**：在 `LoadImageAsync` 之前呼叫 `IsCached`,可用於 UI 的佔位符/進度提示，避免出現空白閃爍。

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| 在 WebGL 上 `IsCached` 始終回傳 `false` | WebGL 不支援本機檔案快取，因此原始碼中固定回傳 `false` | 在 WebGL 上略過此檢查，或將其視為「未快取」流程處理 |
| 即使是相同 URL,只要尺寸/裁切參數不同，判定結果就會不同 | 快取鍵值為**原始 URL 的 MD5**,帶有 query string 的 URL 會被視為不同資源 | 保持 URL 字串與下載時一致 |
| 變更 `CachePath` 設定後，舊檔案會失效 | 由於路徑變更，舊的快取檔案不存在於新路徑之下 | 清理舊目錄，或於移轉後再進行判定 |

## 背景(選讀)

實作位於 `ImageCacheManager.cs`,核心處理是將 `Utility.Hash.MD5.Hash(url)` 與 `Utility.Const.FileNameSuffix.PNG` 串接以產生快取路徑，再以 `FileHelper.IsExists` 判斷檔案是否存在。此判斷處理為同步的純本機 IO,額外開銷極低，適合在 UI 邏輯的前段呼叫。
