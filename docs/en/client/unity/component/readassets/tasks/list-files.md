# Enumerate Files in a Directory (Wildcards and Recursion)

Use `BlankReadAssets.GetFiles` to enumerate files under StreamingAssets, with support for wildcards (`searchPattern`) and recursion (`SearchOption.AllDirectories`), automatically adapting across editor, Android APK, and release builds.

## Prerequisites

- Initialization has been completed via `BlankReadAssets.Initialize()` (the first call to any API will also trigger this automatically).
- `path` is a relative path relative to the StreamingAssets root directory, separated by `/`, recommended to start with `/`.

## Steps

1. Enumerate using the top-level directory (only direct child files):

```csharp
using GameFrameX.ReadAssets.Runtime;

string[] files = BlankReadAssets.GetFiles("config/");
// Or explicitly specify: BlankReadAssets.GetFiles("config/", "*", SearchOption.TopDirectoryOnly);
foreach (var f in files)
{
    Debug.Log(f); // Looks like "config/a.json"
}
```

2. Use wildcards to filter specific extensions (only enumerate the current layer):

```csharp
string[] pngs = BlankReadAssets.GetFiles("ui/", "*.png");
foreach (var p in pngs)
{
    Debug.Log(p); // Looks like "ui/icon.png"
}
```

3. Recursively enumerate all files in subdirectories:

```csharp
string[] all = BlankReadAssets.GetFiles("audio/", "*", SearchOption.AllDirectories);
foreach (var a in all)
{
    Debug.Log(a); // Looks like "audio/bgm/menu.ogg"
}
```

4. Combine recursion with wildcards:

```csharp
string[] oggs = BlankReadAssets.GetFiles("audio/", "*.ogg", SearchOption.AllDirectories);
foreach (var a in oggs)
{
    Debug.Log(a);
}
```

### Public API

| Method | Signature | Default Behavior |
|------|------|----------|
| Single parameter | `string[] GetFiles(string path)` | `searchPattern = null` → `"*"`, current layer only |
| Wildcard | `string[] GetFiles(string path, string searchPattern)` | Current layer only (`TopDirectoryOnly`) |
| Full | `string[] GetFiles(string path, string searchPattern, SearchOption searchOption)` | `TopDirectoryOnly` or `AllDirectories` |

The return value is an array of paths relative to the StreamingAssets root directory, uniformly separated by `/`.

## Common Variants

- In the editor, `LooseFilesImpl.GetFiles` automatically removes entries ending with `.meta`.
- On the Android platform, files are actually `jar:file://...!/assets/` resources inside the APK, implemented via `ApkImpl`. The signature is consistent, but the underlying implementation no longer goes through `Directory.GetFiles`.
- When you need to determine whether a directory exists, use `BlankReadAssets.DirectoryExists(path)` together to avoid misjudging an empty collection.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Returns empty array | `path` does not exist or the root directory has not been generated | First call `BlankReadAssets.DirectoryExists(path)` to validate |
| No results when `searchPattern` contains `/` | `searchPattern` only matches single-layer filenames | Move subdirectories into `path`, or switch to `AllDirectories` |
| Extra `.meta` files in the editor | Legacy implementation did not filter | Upgrade to the current version, or filter `EndsWith(".meta")` yourself |

## Background (Optional)

`BlankReadAssets` selects its implementation at compile time via `#if UNITY_EDITOR / UNITY_ANDROID`. In the editor, it also forwards calls to `ApkImpl` or `LooseFilesImpl` at runtime depending on whether an APK is attached (`EditorImpl.cs` lines 75-90). All `GetFiles` overloads eventually flow into the underlying `Directory.GetFiles`, so `searchPattern` follows .NET wildcard semantics (`*`, `?`), and `SearchOption` controls recursion depth.
