# Embedding Models, Particles, and Skeletal Animations in the UI

Use FairyGUI's `GoWrapper` to wrap any `GameObject` (3D models, particle systems, skeletal animations, etc.) into a display object, then attach it to an empty graph component in the UI, allowing it to participate in FairyGUI's layering, occlusion, and sorting—no extra camera or RenderTexture required.

## Prerequisites

- The project has imported this FairyGUI package (the assembly containing `Runtime/Core/GoWrapper.cs`).
- Prepare an **empty graph (Graph)** component in the UI as a placeholder; alternatively, draw a transparent rectangle as a placeholder in code first. FairyGUI itself does exactly this in `GWindow`:

```csharp
GGraph graph = _dragArea as GGraph;
if (graph != null && graph.shape.isEmpty)
    graph.DrawRect(_dragArea.width, _dragArea.height, 0, Color.clear, Color.clear);
```

Source: [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L159-L161)

## Steps

1. Instantiate the `GameObject` you want to display (model, particle prefab, skeletal animation host, etc.).
2. Construct a `GoWrapper` to complete the wrapping, then set the wrapped result onto the empty graph component:

```csharp
GameObject model = Instantiate(modelPrefab);
GoWrapper wrapper = new GoWrapper(model);   // wrapping is completed upon construction
holder.SetNativeObject(wrapper);            // holder is the empty graph GGraph in the UI
```

The actual signature of `GoWrapper(GameObject go)` is as follows; by default, materials are **not** copied during construction:

```csharp
public GoWrapper(GameObject go) : this()
{
    SetWrapTarget(go, false);
}
```

Source: [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L47-L54)

3. If the material is shared with other objects, or if you need to apply UI-specific processing to the material, set the wrap target in material-cloning mode instead:

```csharp
/// Sets the wrap target. Note: if a wrapped object already exists, after setting a new wrap target,
/// the old wrapped object will only have its reference removed, but will not be destroyed.
/// None of the materials contained by the object will be copied; if the materials are already shared, this may affect other objects. If you want automatic copying, use SetWrapTarget(target, true) instead.
public GameObject wrapTarget
{
    get { return _wrapTarget; }
    set { SetWrapTarget(value, false); }
}

public void SetWrapTarget(GameObject target, bool cloneMaterial)
```

Source: [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L56-L77)

4. The internal wrapping implementation parents the target object under itself and caches its renderers; non-Canvas objects have their size set to 0, with display determined by the renderers themselves:

```csharp
if (_wrapTarget != null)
{
    _wrapTarget.transform.SetParent(this.cachedTransform, false);
    _canvas = _wrapTarget.GetComponent<Canvas>();
    if (_canvas != null)
    {
        _canvas.renderMode = RenderMode.WorldSpace;
        _canvas.worldCamera = StageCamera.main;
        _canvas.overrideSorting = true;

        RectTransform rt = _canvas.GetComponent<RectTransform>();
        rt.pivot = new Vector2(0, 1);
        rt.position = new Vector3(0, 0, 0);
        this.SetSize(rt.rect.width, rt.rect.height);
    }
    else
    {
        CacheRenderers();
        this.SetSize(0, 0);
    }

    SetGoLayers(this.layer);
}
```

Source: [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L92-L114)

5. When extra processing must follow the wrapped object every frame, subscribe to `onUpdate`; when you need to fully take over the material replacement logic, provide the `customCloneMaterials` / `customRecoverMaterials` delegates:

```csharp
public event Action<UpdateContext> onUpdate;
public Action<Dictionary<Material, Material>> customCloneMaterials;
public Action customRecoverMaterials;
```

## Common Variants

- **Embedding a UGUI Canvas**: when `SetWrapTarget` detects that the target has a `Canvas`, it automatically switches to `RenderMode.WorldSpace`, assigns `StageCamera.main`, and calls `SetSize` based on the RectTransform dimensions, so you can embed a UGUI panel directly into FairyGUI.
- **3D objects requiring hit testing**: the repository provides several hit test implementations to be used with the hit area of `GoWrapper` (which inherits from `DisplayObject`) as needed: [ColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/ColliderHitTest.cs), [MeshColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/MeshColliderHitTest.cs), [PixelHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/PixelHitTest.cs).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Other objects sharing the material get unexpectedly recolored | Wrapping directly uses `sharedMaterial` | Use `SetWrapTarget(target, true)` to clone materials instead |
| The old model still shows after switching the wrap target | `SetWrapTarget` only removes the reference and does **not** destroy the old object | `Destroy` the old object yourself before switching targets |
| Layer-based effects such as blur behave incorrectly on the wrapped object | The wrapped object and its children must be on the same Layer as the UI | `GoWrapper` already sets the Layer recursively in `_SetLayerDirect`; verify it has not been changed back by external code |
| Skeletal animation/particles don't update or are partially missing | The internal renderer cache is stale | Re-set the wrap target or trigger `CacheRenderers()` to re-cache (see the call site at lines 92–114 above) |

The recursive Layer handling in `_SetLayerDirect` (the source comment explains this is to enable blur effects inside `GoWrapper`):

```csharp
override internal void _SetLayerDirect(int value)
{
    gameObject.layer = value;
    if (_wrapTarget != null)//this if exists to support blur effects inside GoWrapper
    {
        _wrapTarget.layer = value;
        foreach (Transform tf in _wrapTarget.GetComponentsInChildren<Transform>(true))
        {
            tf.gameObject.layer = value;
        }
    }
}
```

## Background

`GoWrapper` inherits from `DisplayObject` (declaration at [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L8-L12)); it creates a host `GameObject` named `GoWrapper`, parents the wrap target via `SetParent` under its `cachedTransform`, and caches all `Renderer`s on the target (the `RendererInfo` struct contains `renderer`, `materials`, `sortingOrder`; see [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L27-L32)), thereby bringing ordinary 3D content into FairyGUI's display list and batching/sorting system. The old `supportStencil` flag has been marked `[Obsolete]`; stencil buffer handling is now done automatically and requires no manual setup.
