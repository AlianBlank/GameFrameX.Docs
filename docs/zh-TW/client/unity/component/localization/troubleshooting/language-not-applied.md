# 語言切換不生效或不儲存：系統語言回退與 Setting 持久化檢查

當 `Language` 仍為哨兵值 `"zxx"`（`UnknownLocalization`）時，框架會在執行階段**自動回退到系統語言**；而每次透過 `LocalizationComponent` 設定語言時，框架會寫入 Setting 並 `Save()` 持久化。語言「不生效/不儲存」絕大多數是因為：直接改了 `LocalizationManager.Language`（繞過了 Setting 寫入）、編輯器模式被 `m_IsEnableEditorMode` + `EditorLanguage` 覆蓋、或傳入 `"zxx"` 被拒絕。下面按症狀逐條排查。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 設定了語言，重新啟動後仍顯示系統語言 | 直接改的是 `LocalizationManager.Language`，沒經過 `SettingComponent` 持久化 | 只透過 `LocalizationComponent.Language` 賦值，見 [修復 1](#修復-1用-localizationcomponentlanguage-切換並持久化) |
| 編輯器裡怎麼切語言，Play 後都被覆蓋為 `zh_CN` 等固定值 | 元件勾選了 `m_IsEnableEditorMode`，`Start()` 中用 `EditorLanguage` 覆蓋 | 取消勾選或修改 Inspector 上的 Editor Language，見 [修復 2](#修復-2編輯器下語言被-editorlanguage-覆蓋) |
| 拋出 `GameFrameworkException: Language is invalid.` | 給 `Language` 賦了 `UnknownLocalization`（`"zxx"`），setter 直接拋出例外 | 不要傳 `"zxx"`；空值請顯式賦預設語言，見 [修復 3](#修復-3傳入-zxx-導致-language-is-invalid) |
| 拋出 `GameFrameworkException: default Language is invalid.` | 給 `DefaultLanguage` 賦了 `"zxx"` | 賦合法語言碼（如 `"zh_CN"`、`"en_US"`），見 [修復 3](#修復-3傳入-zxx-導致-language-is-invalid) |
| 啟動日誌出現 `Can not create localization helper.` 後語言相關功能全掛 | `m_LocalizationHelperTypeName` 被改成錯誤類型名，Helper 建立失敗 | 還原為預設全名 `GameFrameX.Localization.Runtime.DefaultLocalizationHelper`，見 [修復 4](#修復-4helper-建立失敗導致-systemlanguage-不可用) |
| 日誌 `Setting component is invalid.`，語言設定讀寫全失效 | 場景缺少 `SettingComponent`，`Start()` 直接 Fatal 傳回 | 掛上 Setting 元件，見 [修復 4](#修復-4helper-建立失敗導致-systemlanguage-不可用) |
| 切了語言但介面文字沒變 | 語言事件發出去了，但字典未重新載入或 UI 未重新整理 | 監聽 `LocalizationLanguageChangeAfterEventArgs` 後重新載入字典/重新整理 UI，見 [修復 5](#修復-5切語言後文字未重新整理) |
| 介面出現 `<NoKey>xxx` | 目前語言字典裡沒有該 Key | 補齊對應語言字典條目，見 [驗證](#驗證) |

## 修復步驟

### 修復 1：用 `LocalizationComponent.Language` 切換並持久化

持久化只發生在 `LocalizationComponent` 這一層的 setter 中：寫入 Setting 鍵 `LocalizationComponent.Language` 並立即 `Save()`，隨後依序拋出 Before / Change / After 三個語言事件。直接改 `LocalizationManager.Language` 不會寫 Setting，重新啟動即遺失。

```csharp
// 正確：經元件層賦值 —— 寫入 Setting + Save + 觸發三個語言事件
GameEntry.GetComponent<LocalizationComponent>().Language = "en_US";

// 錯誤：繞過元件層，重新啟動後遺失（不寫 Setting，不發事件）
// GameFrameXEntry.GetModule<ILocalizationManager>().Language = "en_US";
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L140-L171)

對應的 Setting 鍵與讀取順序（getter 先查 Setting，仍未知才回退）：

```csharp
get
{
    if (m_LocalizationManager.Language == UnknownLocalization)
    {
        var value = m_SettingComponent.GetString(nameof(LocalizationComponent) + "." + nameof(Language));
        if (value.IsNotNullOrWhiteSpace())
        {
            m_LocalizationManager.Language = value;
        }
    }

    return m_LocalizationManager.Language;
}
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L143-L153)

`DefaultLanguage` 的行為完全一致，僅鍵名換為 `LocalizationComponent.DefaultLanguage`：[LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L104-L128)

### 修復 2：編輯器下語言被 `EditorLanguage` 覆蓋

`Start()` 中按編輯器模式分兩條路徑：勾選了 `m_IsEnableEditorMode` 時，編輯器內語言被強制設為 `EditorLanguage`；打包環境（或未勾選）時，僅當 `Language == UnknownLocalization` 才回退到系統語言。

```csharp
#if UNITY_EDITOR
            if (m_IsEnableEditorMode)
            {
                Language = EditorLanguage != UnknownLocalization ? EditorLanguage : m_LocalizationManager.SystemLanguage;
            }
#else
            if (Language == UnknownLocalization)
            {
                Language = m_LocalizationManager.SystemLanguage;
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L270)

操作方法：

1. 選取場景中的 Localization 元件，檢查 **Is Enable Editor Mode** 是否勾選。
2. 已勾選時，Inspector 上的 **Editor Language**（預設 `zh_CN`）會在每次 Play 時覆蓋之前儲存的語言——要嘛取消勾選，要嘛把它改成你要驗證的語言。
3. 預設序列化值參考（`m_EditorLanguage`/`m_DefaultLanguage` 均為 `"zh_CN"`，編輯器模式預設關閉）：

```csharp
        [SerializeField] private string m_EditorLanguage = "zh_CN";

        [SerializeField] private string m_DefaultLanguage = "zh_CN";

        [SerializeField] private bool m_EnableLoadDictionaryUpdateEvent = false;
        [SerializeField] private bool m_IsEnableEditorMode = false;
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L66-L71)

### 修復 3：傳入 `zxx` 導致 `Language is invalid.`

`"zxx"` 是「未知本地化」哨兵值，兩個 setter 都會拒絕它：

```csharp
            set
            {
                if (value == UnknownLocalization)
                {
                    throw new GameFrameworkException("Language is invalid.");
                }

                _language = value;
            }
```

Source: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L100-L108)

| 屬性 | 例外訊息原文 | 觸發值 |
|------|--------------|--------|
| `LocalizationManager.Language` | `Language is invalid.` | `"zxx"` |
| `LocalizationManager.DefaultLanguage` | `default Language is invalid.` | `"zxx"` |

`default Language is invalid.` 的出處見 [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L71-L83)。賦值時改用真實語言碼即可。

### 修復 4：Helper 建立失敗導致 `SystemLanguage` 不可用

`Start()` 依序依賴 `BaseComponent`、`EventComponent`、`SettingComponent`，任一缺失都會 `Log.Fatal` 後 `return`，語言讀寫全部癱瘓；隨後按 `m_LocalizationHelperTypeName` 建立 Helper，失敗則日誌 `Can not create localization helper.`。而 `SystemLanguage` 內部有非空守衛，Helper 為空時直接拋出：

```csharp
        public string SystemLanguage
        {
            get
            {
                GameFrameworkGuard.NotNull(_localizationHelper, nameof(_localizationHelper));
                return _localizationHelper.SystemLanguage;
            }
        }
```

Source: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L115-L122)

操作方法：

1. 確認場景中存在 Setting/Event 元件（日誌出現 `Setting component is invalid.` / `Event component is invalid.` 即為缺失），出處 [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227-L246)。
2. 檢查 Inspector 上 **Localization Helper Type Name** 是否仍為預設全名：

```csharp
        [SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73-L75)

3. 預設 Helper 的系統語言來自 `CultureInfo.CurrentCulture`，並把 `-` 換成 `_`（如 `zh-CN` → `zh_CN`）。若裝置區域格式與你的字典命名不一致，就是「回退語言永遠對不上」的根因：

```csharp
        public override string SystemLanguage
        {
            get { return CultureInfo.CurrentCulture.Name.Replace("-", "_"); }
        }
```

Source: [DefaultLocalizationHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/DefaultLocalizationHelper.cs#L52-L55)

可繼承 `LocalizationHelperBase` 覆寫 `SystemLanguage`（抽象定義見 [LocalizationHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationHelperBase.cs#L47)），再透過 **Custom Localization Helper** 槽位替換預設實作。

### 修復 5：切語言後文字未重新整理

`LocalizationComponent.Language` 的 setter 在儲存後依序觸發三個事件：`LocalizationLanguageChangeBeforeEventArgs`、`LocalizationLanguageChangeEventargs`（Change）、`LocalizationLanguageChangeAfterEventArgs`，均攜帶 `oldLanguage` 與新語言。字典重新載入與 UI 重新整理應訂閱這些事件完成，典型時機是 After：

```csharp
var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventargs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
```

Source: [LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L163-L168)

事件參數定義見 [LocalizationLanguageChangeAfterEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LocalizationLanguageChangeAfterEventArgs.cs#L41)。

## 驗證

1. **語言值**：Inspector 選取 Localization 元件後，面板會直接顯示 `Language`、`System Language` 兩個唯讀欄位（[LocalizationComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Editor/Inspector/LocalizationComponentInspector.cs#L70-L72)）。切換語言後確認 `Language` 為新值、`System Language` 為裝置區域值。
2. **持久化**：設定語言 → 停止 Play → 再次 Play，`Language` 應保持新值（getter 會從 Setting 鍵 `LocalizationComponent.Language` 讀回）。
3. **回退邏輯**：清掉本地 Setting 後再 Play，`Language` 應等於 `SystemLanguage`——因為 `LocalizationManager.Language` 在未設定時傳回系統語言：

```csharp
            get
            {
                if (_language == UnknownLocalization)
                {
                    return SystemLanguage;
                }

                return _language;
            }
```

Source: [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L91-L99)

4. **字典**：取值正常時不再輸出 `<NoKey>{key}` 佔位（[LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L168-L177)）；若仍出現，說明目前語言的字典未載入或缺 Key，請為對應語言補齊字典。

## 背景

`Language` 採用哨兵值 `"zxx"`（`LocalizationManager.UnknownLocalization` 常數，見 [LocalizationManager.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/Localization/LocalizationManager.cs#L53)）表示「未設定」，三處回退鏈為：元件層 getter → Setting 持久值；管理器 getter → `SystemLanguage`；`Start()` → 系統語言保底賦值。語言碼遵循 RFC 5646 風格（元件上的 `[HelpURL]` 即指向該規範），內部統一用 `_` 替代 `-`。
