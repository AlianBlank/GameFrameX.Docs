# 인터페이스 열기 실패 시 대처 방법

`UIManager.OpenUIForm` / `OpenUIFormAsync` 호출 후 인터페이스가 표시되지 않거나, 예외가 발생하거나, 실패 콜백만 트리거되는 경우, 이 페이지에 따라 근본 원인을 빠르게 파악하고 수정하세요.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `OpenUIFormFailureEventArgs` 콜백의 오류 메시지가 `Resources.Load failed for path: <path>` | 리소스 경로가 `BundlesDirectoryName` 아래에 있지 않아 Resources 로드를 시도했지만 경로가 존재하지 않음 | 「Resources 경로 리소스 로드 실패」 참조 |
| `OpenUIFormFailureEventArgs`에 `assetHandle.LastError` 포함 | 패키지 내 로드를 시도했지만 `LoadAssetAsync`가 `Failed` 상태를 반환 | 「패키지 내 리소스 로드 실패」 참조 |
| 예외 `GameFrameworkException: Can not create UI form in UI form helper.` | `UGUIFormHelper.CreateUIForm`이 `null`을 반환 | 「로직 스크립트 타입 불일치 / 스크립트 미부착」 참조 |
| 예외 `GameFrameworkException: Open UI form info is invalid.` | `LoadAssetSuccess/FailureCallback`에서 `openUIFormInfo`가 비어 있음 | 「핸들과 콜백 생명주기 예외」 참조 |
| 예외 `ArgumentNullException`(`GameFrameworkGuard.NotNull`에서 발생) | 전달된 `m_AssetManager` / `m_UIFormHelper` / `uiFormType`이 null | 「핵심 매개변수가 null」 참조 |
| 콘솔에 `UI form instance type Xxx is invalid.` 출력되지만 예외는 없음 | 프리팹에 `IUIForm`을 상속한 로직 스크립트가 부착되지 않음 | 「로직 스크립트 타입 불일치 / 스크립트 미부착」 참조 |
| 리소스 풀 재사용 분기에서 여러 번의 열기 요청이 발생했지만 1개만 표시됨 | 싱글톤 열기 모드(`UseSingletonOpenMode`)에 해당하여 이후 요청이 병합됨 | 「싱글톤 열기가 병합됨」 참조 |

## 해결 단계

### Resources 경로 리소스 로드 실패

`InnerLoadUIFormAsync`는 경로에 `BundlesDirectoryName`이 포함되어 있지 않을 때 `Resources.Load`를 사용하며, 찾지 못하면 실패 메시지를 구성하여 반환합니다:

```csharp
if (uiFormAssetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    var original = (GameObject)Resources.Load(assetPath);
    if (original == null)
    {
        return LoadAssetFailureCallback(assetPath, $"Resources.Load failed for path: {assetPath}", openUIFormInfo);
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L144-L155](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L144-L155)

해결:

1. `uiFormAssetPath + uiFormType.Name`이 실제로 임의의 `Resources/` 디렉토리 아래에 존재하는지 확인하세요(대소문자 구분).
2. 리소스가 AssetBundle에 있는 경우, 경로를 `BundlesDirectoryName`(기본값 `Assets/AssetBundle/` 또는 게임에서 사용자 정의한 하위 디렉토리 이름)을 포함하도록 변경하여 패키지 내 로드 분기를 타도록 하세요.
3. 구체적인 경로를 얻기 위해 실패 콜백을 등록하세요:

```csharp
m_UIManager.OpenUIFormFailureEvent += (sender, args) =>
{
    Debug.LogError($"OpenFail [{args.UIFormAssetName}] {args.ErrorMessage}");
};
```

### 패키지 내 리소스 로드 실패

패키지 내 분기는 `AssetManager.LoadAssetAsync`를 거치며, 상태가 `Succeed`가 아니면 실패로 간주합니다:

```csharp
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(assetPath);
if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    ...
    return LoadAssetSuccessCallback(assetPath, gameObject, assetHandle.Progress, openUIFormInfo);
}
return LoadAssetFailureCallback(assetPath, assetHandle.LastError, openUIFormInfo);
```

Source: [Runtime/UIManager.Open.cs#L158-L169](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L158-L169)

해결:

1. `assetHandle.LastError`를 확인하세요. 일반적인 원인: AssetBundle 매니페스트에 해당 인터페이스가 포함되지 않음, 패키징 경로와 로드 경로 불일치, 의존 패키지 로드 완료 전에 Open 호출.
2. `m_AssetManager`가 초기화되었는지 확인하세요(「핵심 매개변수가 null」 참조).
3. 시작流程에서 AssetBundle 매니페스트 파싱이 완료된 후 열기 요청을 시작하세요.

### 로직 스크립트 타입 불일치 / 스크립트 미부착

`UGUIFormHelper.CreateUIForm`은 인스턴스가 `GameObject`가 아니거나 `IUIForm` 스크립트가 부착되지 않은 경우 `null`을 반환하며, 이후 `InternalOpenUIForm`이 `Can not create UI form in UI form helper.`를 던집니다:

```csharp
var componentType = uiGameObject.GetOrAddComponent(uiFormType);
if (!(componentType is IUIForm uiForm))
{
    Log.Error($"UI form instance type {uiFormType} is invalid.");
    return null;
}
```

Source: [Runtime/UGUIFormHelper.cs#L91-L105](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L91-L105)

해결:

1. 열기 실패 시 Preload 동작: Preload는 여전히 인터페이스를 생성하고 OnAwake를 호출하므로, 로직 스크립트가 초기화되지 않은 데이터에 의존하지 않도록 보장해야 합니다.
2. Preload 리소스 경로와 열기 경로가 완전히 동일한지 확인하세요. 그렇지 않으면 두 풀이 서로 다른 프리팹을 가리킵니다.

### 핸들과 콜백 생명주기 예외

`LoadAssetSuccessCallback` / `LoadAssetFailureCallback`이 받는 `openUIFormInfo`가 비어 있으면 `Open UI form info is invalid.`를 던집니다. 이 정보는 `InnerOpenUIFormAsync`에서 `UIFormLoadingObject.Create`로 생성됩니다:

```csharp
UIFormLoadingObject uiFormLoadingObject = UIFormLoadingObject.Create(uiFormAssetPath, uiFormAssetName, uiFormType, uiForm);
m_LoadingUIForms.Add(uiFormLoadingObject);
```

Source: [Runtime/UIManager.Open.cs#L108-L110](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L108-L110)

이러한 예외는 일반적으로 사용자 정의 `UIFormHelper`가 규약대로 `OpenUIFormInfo`를 구성하지 않을 때 발생합니다. 필요한 경우가 아니면 리소스 로드 콜백을 재정의하지 마세요.

### 핵심 매개변수가 null

`InnerOpenUIFormAsync` 진입 지점에서 핵심 필드에 대해 `GameFrameworkGuard.NotNull` 검증을 수행하며, 어느 하나라도 비어 있으면 즉시 `ArgumentNullException`을 던집니다:

```csharp
GameFrameworkGuard.NotNull(m_AssetManager, nameof(m_AssetManager));
GameFrameworkGuard.NotNull(m_UIFormHelper, nameof(m_UIFormHelper));
GameFrameworkGuard.NotNull(uiFormType, nameof(uiFormType));
```

Source: [Runtime/UIManager.Open.cs#L72-L74](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L72-L74)

해결:

1. `OpenUIForm` 호출 전에 `UIManager`가 초기화를 완료했는지 확인하세요(프레임워크의 `GameFramework` 시작 흐름).
2. 호출자가 전달한 `Type`은 null이 아니며 `IUIForm`을 구현해야 합니다.
3. `UIFormHelper`를 교체한 경우, `UIManager`에 등록되었는지 확인하세요.

## 검증

수정 후 최소한의 사용 사례를 통해 검증하세요:

```csharp
var form = await m_UIManager.OpenUIFormAsync<MyUIFomLogic>("Assets/AssetBundle/UI/");
if (form == null)
{
    Debug.LogError("Open failed, see OpenUIFormFailureEvent for details.");
}
```

확인 사항:

- `OpenUIFormSuccessEvent`가 트리거되고 콜백에서 `duration > 0`.
- 실패 이벤트가 더 이상 발생하지 않으며, 대상 인터페이스가 UI 카메라에 표시됨.
- `IsLoadingUIForm(assetName)`이 `false`를 반환하고, `GetUIForm(assetName)`이 null이 아닌 인스턴스를 반환.## 싱글톤 열기가 병합됨

인터페이스 클래스가 `[OptionUIGroup]`을 통하거나 프레임워크가 싱글톤 열기 모드(`UseSingletonOpenMode`)로 판정한 경우, 동일한 리소스 이름으로 반복하여 열면 기존 인스턴스를 반환하고 `RefocusUIForm`을 트리거하며, 새 인스턴스를 생성하지 않습니다:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L77-L97](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L77-L97)

해결:

1. 매번 새 인스턴스를 생성하기를 기대하는 경우, 해당 모드의 싱글톤 표시를 비활성화하거나(또는 비즈니스 계층에서 자체적으로 인스턴스 생명주기를 관리).
2. 동시 열기 요청은 동일한 로드 Task로 병합되어 동일한 로드 결과를 기다립니다:

```csharp
foreach (var loadingUIForm in m_LoadingUIForms)
{
    if (loadingUIForm.UIFormAssetPath == uiFormAssetPath &&
        loadingUIForm.UIFormAssetName == uiFormAssetName &&
        loadingUIForm.UIFormType == uiFormType)
    {
        return await loadingUIForm.Task;
    }
}
```

Source: [Runtime/UIManager.Open.cs#L88-L96](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L88-L96)

동시의 두 번째 열기는 새로운 실패 콜백을 트리거하지 않으며, 첫 번째 요청의 실패/성공 이벤트만 트리거됩니다.
