# How to Implement C# and JavaScript Interaction and Event Listening

By following the steps on this page, you can load pages in GameFrameX WebView, call JavaScript code in the page from C#, and listen to messages and close events sent back from the web page. C# → JS goes through `IWebViewManager.ExecuteJavaScript`, and JS → C# is carried by event arguments such as `WebViewReceivedMessageEventArgs`.

## Prerequisites

- The Unity project has the `com.gameframex.unity.webview` package installed (see [package.json](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/package.json) in the root directory).
- [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs) is attached in the scene (for the editor panel, see [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L13-L19), which associates the component with an `IWebViewManager` implementation type).

## Steps

1. Get the `IWebViewManager` instance through the component. The interaction entry points are all concentrated on this interface; the actual signature is as follows:

   ```csharp
   public interface IWebViewManager
   {
       void Initialize();                    // Initialize
       void Show(string url);                // Show the WebView and load url
       void MakeFullScreen();                // Full screen
       void ExecuteJavaScript(string javaScript); // Execute JavaScript
       void Hide();                          // Hide
   }
   ```

   Source: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L12-L40)

2. Initialize and load the target page. `ExecuteJavaScript` acts on the currently loaded page, so you must call `Initialize()` first, then `Show(url)`:

   ```csharp
   using GameFrameX.WebView.Runtime;

   webViewManager.Initialize();
   webViewManager.Show("https://example.com/index.html");
   webViewManager.MakeFullScreen(); // Optional: call when full screen is needed
   ```

3. Execute JavaScript from C#. Just pass in a complete JS string; the method has no return value (the execution result is not sent back):

   ```csharp
   // Change the page title
   webViewManager.ExecuteJavaScript("document.title = 'Hello from Unity';");

   // Call a custom function defined in the page
   webViewManager.ExecuteJavaScript("window.onUnityReady && window.onUnityReady();");
   ```

   Source: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L30-L35)

4. Listen to events sent back from the web page. The repository provides two event argument types under `Runtime/EventArgs/`, corresponding to "message received" and "closed":
   - [WebViewReceivedMessageEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/EventArgs/WebViewReceivedMessageEventArgs.cs) — Event data for when the web page sends a message to C#;
   - [WebViewCloseEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/EventArgs/WebViewCloseEventArgs.cs) — Event data for when the WebView is closed.

   The dispatch and subscription entry points for the events are located in [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs) and [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs). The complete field signatures of these two event argument types could not be read from the source code (this fetch was limited); refer to the actual definitions in the files above and do not rely on any guessed fields in this documentation.

5. Call `webViewManager.Hide()` to hide the WebView when it is no longer needed.

Source: [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L39)

## Common Issues

| Symptom | Cause | Fix |
|------|------|------|
| `ExecuteJavaScript` has no effect | It is called before the page has finished loading | Call `Initialize()` + `Show(url)` first, and execute JS only after confirming the page has loaded |
| Calling `ExecuteJavaScript` throws a null reference | `WebViewComponent` is not attached in the scene, or no `IWebViewManager` implementation type is selected in the Inspector | Attach the component and refresh and select the implementation type in the Inspector (provided by [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L16-L19)) |
| Data from the JS side is not received | Using `ExecuteJavaScript` as a synchronous value-retrieval method | The method has no return value; to retrieve values, use the message event callback via `WebViewReceivedMessageEventArgs` |

## Background

`ExecuteJavaScript` is designed as a one-way call: the interface signature `void ExecuteJavaScript(string javaScript)` is only responsible for dispatching scripts, and results are not sent back. Therefore, two-way interaction uses a combination of "dispatch + event callback". The event arguments are split into separate `WebViewReceivedMessageEventArgs` and `WebViewCloseEventArgs`, whose lifecycle is managed uniformly by `BaseWebViewManager`. For the overall structure of the WebView component, see the overview page.
