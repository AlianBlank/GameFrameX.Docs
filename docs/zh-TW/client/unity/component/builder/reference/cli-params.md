# 命令列參數速查表

本頁彙整了 `GameFrameX.Builder` 所識別的所有命令列參數、對應的 `BuilderOptions` 欄位以及預設值。在以 CI 管線或本機批次模式驅動建置流程時使用。

## 必要參數

| 參數 | 對應欄位 | 類型 | 預設值 | 說明 |
|------|----------|------|--------|------|
| `-executeMethod` | `ExecuteMethod` | string | `""` | 要執行的進入點方法。未指定時會發生 `executeMethod is null` |
| `-BUILD_NUMBER` | `BuildNumber` | string | `""` | 建置編號。未指定時會發生 `build number is null` |

若未設定 `-logFile`,系統會自動產生日誌路徑:`../Logs/{ExecuteMethod の最後のセグメント}_{BuildNumber}.log`(詳情請參閱 [Builder.BuildParamsParse.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L185-L189))。

## 呼叫範例

最小可運作的資源包建置命令列(macOS / Linux 範例)：

```bash
Unity -batchmode -nographics -quit \
  -projectPath /path/to/project \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
  -BUILD_NUMBER 100 \
  -ChannelName googleplay \
  -IsUploadAsset \
  -ObjectStorageKey AKIAxxxxxxxx \
  -ObjectStorageSecret xxxxxxxx \
  -ObjectStorageBucketName my-bucket \
  -ObjectStorageEndPoint oss-cn-hangzhou.aliyuncs.com
```

## 解析後的副作用

`BuildParamsParse` 在解析完所有參數後，會立即依據 `BundleId` 與 `AppVersion` 覆寫並儲存 PlayerSettings:

{
    PlayerSettings.applicationIdentifier = _builderOptions.BundleId.Trim();

if (!_builderOptions.AppVersion.IsNullOrWhiteSpace())
{
    PlayerSettings.bundleVersion = _builderOptions.AppVersion.Trim();

## 常見錯誤

| 現象 | 原因 | 修正方式 |
|------|------|------|
| `executeMethod is null` | 未指定 `-executeMethod` | 補上指定 `-executeMethod <Type.Method>` |
| `build number is null` | 未指定 `-BUILD_NUMBER` | 補上指定 `-BUILD_NUMBER <number>` |
| 資源包名稱始終為 `DefaultPackage` | 未指定 `-PackageName` | 明確指定 `-PackageName <name>` |
| 上傳開關無效 | 漏列了開關參數(無值參數必須明確指定) | 在命令列中明確加上 `-IsUploadAsset` 等參數 |
| 渠道始終為 `default` | 未指定 `-ChannelName` | 明確指定 `-ChannelName <channel>` |

## 背景

參數解析會在 `Builder.BuildParamsParse` 內按照 `Environment.GetCommandLineArgs()` 的順序進行掃描，逐一比對字串索引鍵。布林開關型參數只要存在於陣列中即會被設為 `true`,而無值參數若未明確列舉則不會啟用。`BuilderOptions` 會透過 `JsonConvert.SerializeObject` 輸出，因此可在建置日誌中確認實際生效的值。
