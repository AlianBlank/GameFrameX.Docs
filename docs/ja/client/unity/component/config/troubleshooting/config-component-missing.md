# GetComponent<ConfigComponent> が null を返す場合の対処法

`GetComponent<ConfigComponent>()` が `null` を返すのは、通常はシーンに `ConfigComponent` がアタッチされていないか、Game Framework のエントリーモジュールがまだ初期化されていないことが原因です。このページでは、優先度順の迅速な診断と修復手順を説明します。

## 迅速な診断

| 症状 | 原因 | 修復方法 |
|------|------|----------|
| `GetComponent<ConfigComponent>()` が `null` を返す | シーン内の GameObject に `ConfigComponent` がアタッチされていない | 下記の「ConfigComponent をアタッチする」手順に従って追加する |
| コンポーネントはアタッチ済みだが、まだ `null` を返す | 検索対象のオブジェクトが `GameFrameworkEntry` を含む GameObject ではない | `GameFrameworkEntry` を含むオブジェクトから取得する |
| 起動ログに `Config manager is invalid.` が出力される | `IConfigManager` モジュールが登録されていない | `GameFrameX.Config` パッケージがインストールされているか、自動登録が有効かを確認する |
| エディタでは取得できるが、ビルド後に `null` を返す | パッケージのストリッピングによって `ConfigComponent` が削除されている | `GameFrameXConfigCroppingHelper` を導入する（後述） |

## 修復手順

### 1. シーンに ConfigComponent がアタッチされていることを確認する

`ConfigComponent` は `GameFrameworkEntry` を含む GameObject にアタッチされている必要があります。これは `[GameFrameXAutoComponent(-5000)]` 属性を持ち、ほとんどの GameFrameX プロジェクトのテンプレートではエントリーポイントと共に自動的に作成されます。

```csharp
using GameFrameX.Config.Runtime;
using UnityEngine;

var configComponent = GameObject.FindObjectOfType<ConfigComponent>();
if (configComponent == null)
{
    Debug.LogError("シーンに ConfigComponent が見つかりません。GameFrameworkEntry を含む GameObject にアタッチしてください");
    return;
}
```

Source: [ConfigComponent.cs](/Runtime/Config/ConfigComponent.cs#L46-L50)

### 2. 正しいオブジェクトからコンポーネントを取得する

`ConfigComponent` は `GameFrameworkComponent` のサブクラスであり、Game Framework エントリーポイントの GameObject にのみアタッチできます。スクリプトが別の GameObject にアタッチされている場合は、`GameFrameworkEntry` を含むオブジェクトから取得してください。

```csharp
using GameFrameX.Config.Runtime;
using GameFrameX.Runtime;
using UnityEngine;

// Game Framework エントリーポイントの GameObject を取得
var entryGo = GameObject.Find("GameFrameworkEntry");
var configComponent = entryGo.GetComponent<ConfigComponent>();
```

エントリーポイントのオブジェクト名が異なる場合は、Hierarchy 内で `GameFrameworkEntry` スクリプトを持つ GameObject を検索してください。

### 3. 実行時ログを確認する

`ConfigComponent.Awake()` は `IConfigManager` が利用できない場合に致命的なログを出力します。

```csharp
m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
if (m_ConfigManager == null)
{
    Log.Fatal("Config manager is invalid.");
    return;
}
```

Source: [ConfigComponent.cs](/Runtime/Config/ConfigComponent.cs#L79-L84)

`Config manager is invalid.` が表示された場合は、`IConfigManager` が `GameFrameworkEntry` に登録されていないことを意味します。`GameFrameX.Config` パッケージが導入されているか、また関連モジュールがストリッピングされていないかを確認してください。

### 4. IL2CPP / ビルド後のストリッピングを防ぐ

本コンポーネントは自動登録を使用しているため、ランタイムコードで明示的に `ConfigComponent` を参照していない場合、リリースビルドでストリッピングされる可能性があります。リポジトリにはストリッピング防止用のヘルパーが用意されています。

```csharp
_ = typeof(ConfigComponent);
```

Source: [GameFrameXConfigCroppingHelper.cs](/Runtime/GameFrameXConfigCroppingHelper.cs#L21)

シーンの初期化時またはいずれかの `RuntimeInitializeOnLoadMethod` 内でこのヘルパーを呼び出すことで、`ConfigComponent` 型がストリッピングされなくなります。ビルド後、実機上で再度 `GetComponent<ConfigComponent>()` を実行して確認してください。

## 検証

1. エディタで実行し、Hierarchy で `GameFrameworkEntry` を含む GameObject を選択すると、Inspector に `Config Component` フィールドが表示されます。
2. 上記の `GetComponent` の方法で null でないインスタンスを取得し、`configComponent.Count` を呼び出しても例外が発生しません。
3. Android/iOS にビルドし、最初のシーン実行時のログに `Config manager is invalid.` が出力されていないことを確認します。

## よくあるバリエーション

- **ランタイムでの動的作成**: `new GameObject().AddComponent<ConfigComponent>()` は使用しないでください。`ConfigComponent` は `GameFrameworkEntry` の GameObject 上に存在し、`GameFrameworkEntry` のモジュールシステムと連携する必要があります。
- **複数シーンの切り替え**: 各独立したシーンで `GameFrameworkEntry` を保持する必要があります。保持しないと、シーン切り替え後にコンポーネントが失われます。
