# How to Use TCP/WebSocket/KCP/HTTP Client Connections

Through `GameFrameX.NetWork`'s `INetWorkChannel` and `NetWorkSenderFactory`, the business side can transparently send and receive TCP, WebSocket, KCP, and HTTP client messages without needing to care about the underlying protocol differences.

## Prerequisites

- The `GameFrameX.NetWork.Abstractions` and `GameFrameX.NetWork` packages must be installed; KCP clients additionally require a reference to `GameFrameX.NetWork.Kcp`, and HTTP clients require `GameFrameX.NetWork.HTTP`.
- `GameFrameX.SuperSocket.Server.Abstractions.Session.IGameAppSession` (SuperSocket session) must be integrated.
- Listeners for the corresponding protocols (TCP / WebSocket / KCP / HTTP) must be configured.

## Steps

### 1. Get the Network Channel

In the business handler, obtain `INetWorkChannel` through the session. Subsequent send and receive operations go through the channel without directly touching the protocol.

```csharp
using GameFrameX.NetWork;
using GameFrameX.NetWork.Abstractions;
using GameFrameX.SuperSocket.Server.Abstractions.Session;

// In the SuperSocket message handling context
IGameAppSession session = /* from connection event or message handler */;
INetWorkChannel channel = NetWorkSenderFactory.Create(session);
// NetWorkSenderFactory will automatically select the WebSocket or TCP sender based on the actual session type
```

Source: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L12-L17)

### 2. Send Messages to the Client

Construct an `INetworkMessage` and call `WriteAsync` to send asynchronously; `errorCode` defaults to `0`, and the business side can return an error code when something goes wrong.

```csharp
using GameFrameX.NetWork.Abstractions;

await channel.WriteAsync(message, errorCode: 0);
```

`INetWorkChannel.WriteAsync` will throw an exception when the network channel is closed. You can check `IsClosed()` before calling.

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L96-L108)

### 3. Close the Connection

```csharp
channel.Close();
```

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L110-L116)

### 4. Store and Retrieve Custom Data on the Channel

`SetData` / `GetData<T>` / `RemoveData` / `ClearData` are used to attach user-mode data (such as player objects, login state) to the channel's lifecycle without requiring an extra Map.

```csharp
channel.SetData("playerId", 10001);
var pid = channel.GetData<long>("playerId");
channel.RemoveData("playerId");
// channel.ClearData(); // when disconnecting or needing to reset
```

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L118-L155)

## Common Variants

### TCP / WebSocket

`NetWorkSenderFactory.BuildProviders()` has built-in `WebSocketNetWorkSenderProvider` and `SessionNetWorkSenderProvider`, which respectively cover WebSocket and TCP (as well as protocols like KCP that share `IGameAppSession`) session types—no extra registration needed; it automatically matches based on `session.GetType()`.

Source: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L19-L36)

### KCP

KCP sessions also implement `IGameAppSession` and reuse the `SessionNetWorkSenderProvider` send path; if custom encoding/decoding is needed, connect it on the KCP listener side.

### HTTP

HTTP uses the standalone channel from `GameFrameX.NetWork.HTTP`. After processing the request, call `Close()`; `GetData`/`SetData` can be used to pass context through the request processing chain.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `WriteAsync` throws an exception | The channel is closed (`IsClosed()` returns `true`) | Add a `if (!channel.IsClosed())` guard before sending |
| `GetData<T>` throws an exception | Key does not exist or type mismatch | Use a unified type when writing; use a `ContainsKey`-style check before reading, or catch the exception |
| WebSocket message send fails | Did not go through `NetWorkSenderFactory`, used the TCP sender directly | Always obtain the channel through `NetWorkSenderFactory.Create(session)`, and the factory will dispatch based on the session type |
| KCP packets arrive but the business doesn't receive them | The `INetWorkChannel` pipeline is not connected on the KCP listener side | Confirm that the KCP session wraps `IGameAppSession` and that the channel is created by the factory |

## Background (Optional)

`NetWorkSenderFactory` maps protocol session types to `INetWorkSenderProvider` through the `SenderProviders` dictionary. `ResolveProvider` prefers an exact match first and then falls back to an assignable relationship, so that adding a new protocol only requires adding a pair of `Provider` + `Sender` implementations and registering them—the business side's `WriteAsync` calls don't need to change. `INetWorkChannel` consolidates capabilities such as byte/packet counting, heartbeat time, custom data, and closing into a single interface, so business code only sees a protocol-agnostic channel view.
