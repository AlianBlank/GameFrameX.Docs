# 排程非同步任務

`TaskPool<T>` 透過「任務代理 + 優先級佇列」的方式管理非同步任務:你把若干 `ITaskAgent<T>` 註冊到池中,提交 `TaskBase` 衍生任務,池會在每幀 `Update` 時按優先級把任務分發給閒置代理執行。本頁說明如何接入並排程非同步任務。

## 前置條件

- 已引入 `GameFrameX.Runtime` 組件(任務池位於 [Runtime/Base/TaskPool](/Runtime/Base/TaskPool/TaskPool.cs#L44-L64) 命名空間 `GameFrameX.Runtime`)。
- 自訂任務繼承 `TaskBase`,自訂代理實作 `ITaskAgent<T>`。
- 任務物件建議透過 `ReferencePool.Acquire<T>()` 取得,池釋放後自動回收([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L11-L21))。

## 操作步驟

1. **定義任務型別**。繼承 `TaskBase`,至少覆寫 `Description` 屬性,任務用 `Initialize(serializeId, tag, priority, userData)` 設定優先級與自訂資料。

   ```csharp
   using GameFrameX.Runtime;

   public class LoadAssetTask : TaskBase
   {
       public string AssetName { get; private set; }

       public override string Description => $"LoadAsset:{AssetName}";

       public void Init(string assetName)
       {
           AssetName = assetName;
           Initialize(0, assetName, 0, null);
       }
   }
   ```

   Source: [Runtime/Base/TaskPool/TaskBase.cs](/Runtime/Base/TaskPool/TaskBase.cs)

2. **實作任務代理**。實作 `ITaskAgent<T>` 的 `Initialize / Update / Shutdown / Start / Reset`,在 `Start` 中返回 `StartTaskStatus.CanResume / CanNotResume`,透過 `Task.Done = true` 標記完成([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L23-L62))。

   ```csharp
   public class LoadAssetAgent : ITaskAgent<LoadAssetTask>
   {
       public LoadAssetTask Task { get; private set; }
       public bool IsInitialized { get; private set; }
       public bool IsShutdown { get; private set; }

       public void Initialize() { IsInitialized = true; }
       public void Update(float e, float re) { /* 真實載入完成後設定 Task.Done = true */ }
       public void Shutdown() { IsShutdown = true; }

       public StartTaskStatus Start(LoadAssetTask task)
       {
           Task = task;
           return StartTaskStatus.CanResume; // 同步完成請返回 CanNotResume
       }

       public void Reset() { Task = null; }
   }
   ```

   Source: [Runtime/Base/TaskPool/ITaskAgent.cs](/Runtime/Base/TaskPool/ITaskAgent.cs)

3. **建立任務池並註冊代理**。實例化 `TaskPool<T>`,呼叫 `AddAgent` 註冊一個或多個代理;代理數量即為最大並行任務數。

   ```csharp
   var taskPool = new TaskPool<LoadAssetTask>();
   taskPool.AddAgent(new LoadAssetAgent());
   taskPool.AddAgent(new LoadAssetAgent()); // 並行 2
   ```

   Source: [Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L58-L64)

4. **提交任務**。透過 `ReferencePool.Acquire` 取得任務物件,`Initialize` 後呼叫 `AddTask`。任務會按 `priority` 倒序排列:數值越大越先執行([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L127-L145))。

   ```csharp
   var task = ReferencePool.Acquire<LoadAssetTask>();
   task.Init("Config/battle.json");
   taskPool.AddTask(task);

   var urgent = ReferencePool.Acquire<LoadAssetTask>();
   urgent.Initialize(1, "Player/Avatar", 10, null); // priority=10 先執行
   taskPool.AddTask(urgent);
   ```

5. **每幀驅動 Update**。在遊戲主迴圈中呼叫 `taskPool.Update(elapseSeconds, realElapseSeconds)`,池會自動:① 推進所有 `WorkingAgent`;② 把等待佇列中優先級最高的任務分發給閒置代理([Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L136-L145))。

   ```csharp
   void Update()
   {
       taskPool.Update(Time.deltaTime, Time.unscaledDeltaTime);
   }
   ```

6. **暫停與清理**。需要凍結排程時設定 `taskPool.Paused = true`,`Update` 將直接 return,不會觸發任何任務處理([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L185-L196))。不再使用時呼叫 `RemoveAllTasks()` + `Shutdown()`,並 `ReferencePool.ClearAll()` 釋放任務物件。

## 常見變體

| 場景 | 做法 |
|------|------|
| 非同步耗時任務(資源載入、網路) | `Start` 返回 `CanResume`,在 `Update` 中輪詢進度,完成時設定 `Task.Done = true` |
| 同步即可完成的任務 | `Start` 返回 `CanNotResume`,池會在下一幀把代理標記為可繼續派發 |
| 控制並行上限 | 僅註冊 N 個 `ITaskAgent<T>`,多餘任務會留在 `WaitingTasks` 佇列 |
| 查詢任務狀態 | 透過 `GetAllTaskInfos()` 取得 `TaskInfo[]`(含 `Priority`、`Status`、`Description`) |
| 取消指定任務 | `RemoveTask(serializeId, tag)` 命中後歸還物件到 `ReferencePool` |

## 常見錯誤

| 錯誤 | 說明 | 規避 |
|------|------|------|
| `AddAgent(null)` | 拋出 `GameFrameworkException`([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L99-L101)) | 註冊前做空值檢查 |
| 代理數量過少 | 等待佇列堆積,`WaitingTaskCount` 持續大於 0 | 按預期並行量註冊代理 |
| 忘記呼叫 `Update` | 任務永遠不會開始執行 | 把 `taskPool.Update` 接入 MonoBehaviour 主迴圈或框架的 `GameFramework` 派發 |
| 代理 `Start` 永遠不返回 `CanNotResume`、也不設定 `Task.Done` | 代理永久佔用,閒置代理數不增長 | 在非同步回呼或 `Update` 中明確設定 `Done = true` |
| 直接 `new T()` 建立任務 | 任務未走引用池,無法被回收復用 | 使用 `ReferencePool.Acquire<T>()` |

## 背景(可選)

任務池是「任務 = 資料 / 代理 = 執行者」分離模式:池本身只負責派發和回收,具體怎麼執行交給 `ITaskAgent<T>`。優先級由 `m_WaitingTasks` 鏈表按 `priority` 倒序維護,保證每次出隊都是當前優先級最高的任務。`Paused` 用於遊戲暫停、切場景等需要凍結背景任務的場景。

關於任務池與其他子系統的協作,見《ReferencePool 參考》。
