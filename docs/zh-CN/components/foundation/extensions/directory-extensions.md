# 如何使用目录/路径扩展

`DirectoryExtensions.CreateAsDirectory` 是 `GameFrameX.Foundation.Extensions` 命名空间下 `string` 的扩展方法，用来安全地创建目录（必要时递归创建父目录），并支持直接把文件路径当作入参来自动创建文件所在目录。

## 前置条件

- 引用 `GameFrameX.Foundation.Extensions` 命名空间。
- 运行环境为 .NET，且对目标路径具有文件系统写权限。

```csharp
using GameFrameX.Foundation.Extensions;
```

## 操作步骤

1. **创建普通目录**：直接对一个目录路径调用 `CreateAsDirectory()`。若目录已存在则不会抛出异常；若中间层级不存在，会递归创建所有父目录。

```csharp
using GameFrameX.Foundation.Extensions;

string dir = @"C:\temp\gfx\level1\level2\level3";
dir.CreateAsDirectory();
```

Source: [DirectoryExtensions.cs#L57-L75](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DirectoryExtensions.cs#L57-L75)

2. **为即将写入的文件提前创建所在目录**：把文件路径传进去并设置 `isFile: true`，扩展方法会自动取文件所在目录并创建它，不会把文件本身当成目录去创建。

```csharp
using GameFrameX.Foundation.Extensions;

string filePath = @"C:\temp\gfx\subdir\testfile.txt";
filePath.CreateAsDirectory(isFile: true);
// 此时 C:\temp\gfx\subdir 已存在，testfile.txt 尚未创建
```

Source: [DirectoryExtensions.cs#L57-L75](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DirectoryExtensions.cs#L57-L75)

3. **写入文件前配合 `File.WriteAllText`**：典型用法是在写日志、写配置前先调用一次扩展方法，确保目录存在再写入。

```csharp
using GameFrameX.Foundation.Extensions;
using System.IO;

string logFile = Path.Combine(AppContext.BaseDirectory, "logs", "app.log");
logFile.CreateAsDirectory(isFile: true);
File.AppendAllText(logFile, $"[{DateTime.Now}] started\n");
```

4. **校验结果**：方法本身不返回值，使用 `Directory.Exists` 或 `File.Exists` 确认创建是否符合预期。

```csharp
Assert.True(Directory.Exists(@"C:\temp\gfx\level1\level2\level3"));
Assert.True(Directory.Exists(@"C:\temp\gfx\subdir"));
```

## 常见变体

- **相对路径**：传入相对路径同样会按 `Directory.CreateDirectory` 的语义创建，例如 `"logs/output".CreateAsDirectory()` 会在当前工作目录下创建。
- **Linux/macOS 路径**：使用 `Path.Combine` 或正斜杠拼接，例如 `"/var/log/gfx/sub".CreateAsDirectory(isFile: true)`，方法本身不区分平台。
- **幂等重复调用**：对同一路径多次调用不会抛异常，便于在启动流程或写入循环里放心重复执行。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| 传入 `null` 抛 `ArgumentNullException` | 方法在入口处显式校验 `path` | 调用前判断非空，或用 `??` 提供默认值 |
| 期望 `isFile: true` 创建出文件 | 该模式只创建目录，不会创建文件 | 创建目录后另行使用 `File.Create` / `File.WriteAllText` 等 |
| 传入仅含文件名的字符串（如 `"plainfile.txt"`）且 `isFile: true` 时未报错但也未创建 | `Path.GetDirectoryName` 返回空，方法直接 return | 传入完整路径，确保至少包含目录段 |

## 背景（可选）

`CreateAsDirectory` 是 `Directory.CreateDirectory` 的薄封装：底层 `.NET API` 已具备递归创建和“目录已存在则跳过”的语义，扩展方法在此基础上额外做了两件事——把“文件路径自动转目录路径”内联到调用点，以及在入口处统一抛出 `ArgumentNullException`。完整的契约与单元测试覆盖见 [DirectoryExtensionsTests.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Extensions/DirectoryExtensionsTests.cs#L21-L169)。
