# Troubleshooting

This document collects common issues and their solutions that may be encountered when using the GameFrameX Web ProtoBuff component.

## Overview

The Web ProtoBuff component is the network module of the GameFrameX framework, specifically designed for handling Protocol Buffer format HTTP requests. During usage, developers may encounter compilation errors, runtime exceptions, message serialization issues, etc. This document aims to help developers quickly locate and resolve these issues.

---

## Compilation Issues

### 1. Post Method Not Visible

**Problem Description:**
Cannot call `WebProtoBuffComponent.Post<T>()` method in code, IDE prompts method does not exist.

**Cause Analysis:**
The `Post<T>` method is wrapped in compile define `#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`. If this define is not defined, the method will not be available.

**Solution:**
In Unity Editor, open **Edit > Project Settings > Player**, add the following define in **Scripting Define Symbols**:

```
ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
```

> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

### 2. Component Initialization Failed

**Problem Description:**
"Web manager is invalid." error appears in console when running game.

**Cause Analysis:**
In `WebProtoBuffComponent.Awake()` method, the manager instance is obtained through `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()`. If it returns null, a fatal error is logged. This usually happens because:

1. GameFrameX core framework not correctly initialized
2. `WebProtoBuffManager` module not registered
3. Assembly stripping removed necessary types

**Solution:**
1. Ensure GameFrameX core framework is correctly installed and initialized
2. Check if `GameFrameXWebProtoBuffCroppingHelper` component is added to GameObject
3. If using IL2CPP or assembly stripping, ensure necessary Preserve attributes are added

```csharp
// Component already has Preserve attribute
[UnityEngine.Scripting.Preserve]
[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]
public sealed class WebProtoBuffComponent : GameFrameworkComponent
```

> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L46-L90)

## Runtime Errors

### 3. Request Timeout

**Problem Description:**
Network request has no response for a long time, eventually throws timeout exception.

**Cause Analysis:**
Component default timeout is 5 seconds. If server response time exceeds this value, timeout error is triggered.

WebGL platform uses `UnityWebRequest.timeout`:
```csharp
unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;
```

Other platforms use `HttpWebRequest.Timeout`:
```csharp
request.Timeout = (int)RequestTimeout.TotalMilliseconds;
```

**Solution:**
1. Adjust timeout via Inspector (range 0-120 seconds)
2. Dynamically set timeout in code:

```csharp
// Get component reference and set timeout
var webComponent = GetComponent<WebProtoBuffComponent>();
webComponent.Timeout = 30f; // Set to 30 seconds
```

> Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L60-L71)

---

### 4. Network Error

**Problem Description:**
Request failed, network error information appears in console.

**Cause Analysis:**
WebGL platform detects errors through `UnityWebRequest.isNetworkError` and `UnityWebRequest.isHttpError`:

```csharp
if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)
{
    webData.Task.TrySetException(new Exception(unityWebRequest.error));
    return;
}
```

Other platforms catch `WebException`:

```csharp
catch (WebException e)
{
    if (e.Status == WebExceptionStatus.Timeout)
    {
        webData.Task.SetException(new TimeoutException(e.Message));
        return;
    }
    webData.Task.SetException(e);
}
```

**Solution:**
1. Check if network connection is normal
2. Confirm server address URL is correct
3. Check firewall or proxy settings
4. Check error message to determine specific cause

---

### 5. Response Message Type Mismatch

**Problem Description:**
Request succeeded but returns null or log shows "Response message type is invalid".

**Cause Analysis:**
Component validates whether response message type matches request type:

```csharp
var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
if (messageType != typeof(T))
{
    Log.Error($"Response message type is invalid. Expected '{typeof(T).FullName}', actual '{messageType.FullName}'.");
    return default;
}
```

This usually happens because:
1. Server returned message ID does not match expectation
2. `ProtoMessageIdHandler` not correctly registered message type mapping

**Solution:**
1. Ensure server returned message ID matches request/response type mapping
2. Check if `ProtoMessageIdHandler` correctly initializes message types

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L185-L197)

## Message Definition Issues

### 6. Message Serialization Failed

**Problem Description:**
Serialization exception occurs when sending request or server cannot parse request data.

**Cause Analysis:**
Component uses `SerializerHelper.Serialize()` to serialize messages, request body is wrapped as `MessageHttpObject`:

```csharp
MessageHttpObject messageHttpObject = new MessageHttpObject
{
    Id = id,
    UniqueId = message.UniqueId,
    Body = SerializerHelper.Serialize(message),
};
var sendData = SerializerHelper.Serialize(messageHttpObject);
```

Message type must meet the following conditions:
1. Mark `[ProtoContract]` attribute
2. Inherit `MessageObject` base class
3. All properties marked `[ProtoMember]`

**Solution:**
Correctly declare message type:

```csharp
using ProtoBuf;
using GameFrameX.Network.Runtime;

[ProtoContract]
public class LoginRequest : MessageObject
{
    [ProtoMember(1)]
    public string Username { get; set; }

    [ProtoMember(2)]
    public string Password { get; set; }
}

[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)]
    public bool Success { get; set; }

    [ProtoMember(2)]
    public string Token { get; set; }
}
```

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L210-L225)

### 7. Response Message Interface Not Implemented

**Problem Description:**
Compilation error or runtime exception, prompt response type needs to implement specific interface.

**Cause Analysis:**
`Post<T>` method's generic constraint requires type to inherit `MessageObject` and implement `IResponseMessage` interface:

```csharp
public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message)
    where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
```

**Solution:**
Ensure response class inherits both types:

```csharp
[ProtoContract]
public class LoginResponse : MessageObject, IResponseMessage
{
    [ProtoMember(1)]
    public bool Success { get; set; }
}
```

> Source: [IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L22-L24)

## Platform-related Issues

### 8. WebGL Platform Request Failed

**Problem Description:**
Network requests not working after WebGL platform build.

**Cause Analysis:**
WebGL platform uses `UnityWebRequest` instead of `HttpWebRequest`, there are differences in API and behavior:

```csharp
#if UNITY_WEBGL
        UnityEngine.Networking.UnityWebRequest unityWebRequest;
        if (webData.IsGet)
        {
            unityWebRequest = UnityEngine.Networking.UnityWebRequest.Get(webData.URL);
        }
        else
        {
            unityWebRequest = UnityEngine.Networking.UnityWebRequest.Post(webData.URL, string.Empty);
        }

        unityWebRequest.SetRequestHeader("Content-Type", ProtoBufContentType);
        byte[] postData = webData.SendData;
        unityWebRequest.uploadHandler = new UnityEngine.Networking.UploadHandlerRaw(postData);
#else
        // Use HttpWebRequest
#endif
```

**Solution:**
1. Ensure Unity version supports WebGL requests
2. Check browser console for cross-origin errors
3. Server needs to configure correct CORS headers
4. Confirm Content-Type is set to `application/x-protobuf`

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L85-L117)

### 9. Assembly Stripping Issue

**Problem Description:**
Component not working after IL2CPP packaging.

**Cause Analysis:**
Unity's assembly stripping may remove types considered "unused", causing necessary classes not found at runtime.

**Solution:**
Component has already added `UnityEngine.Scripting.Preserve` attribute to prevent stripping:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Web ProtoBuff")]
[UnityEngine.Scripting.Preserve]
[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]
public sealed class WebProtoBuffComponent : GameFrameworkComponent
```

If problems still occur, you can manually add linker configuration or use the following code to force preserve types:

```csharp
// Call at startup to ensure types are not stripped
void PreserveTypes()
{
    _ = typeof(WebProtoBuffComponent);
    _ = typeof(IWebProtoBuffManager);
    _ = typeof(WebProtoBuffManager);
}
```

> Source: [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs#L6-L17)

## Debug and Logging

### 10. Enable Debug Logging

**Problem Description:**
Need to view request and response details for debugging.

**Cause Analysis:**
Component provides debug logging functionality, but it's off by default. Can be enabled with the following defines:

- `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` - Send logging
- `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` - Receive logging

**Solution:**
Add one or all of the above defines in Player Settings:

```
ENABLE_GAMEFRAMEX_WEB_SEND_LOG;ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
```

Log output example:

```csharp
// Send log
Log.Debug($"Sending message ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] Content:{...}");

// Receive log
Log.Debug($"Receiving message ID:[{messageId},{messageObject.UniqueId},{messageObject.GetType().Name}] Content:{...}");
```

> Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L227-L241)
