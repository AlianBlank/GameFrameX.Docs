# ログに "fun is invalid." が出力される、または ArgumentNullException が発生した場合の対処法

`MonoComponent` の `AddXxxListener` / `RemoveXxxListener` 系のメソッドを呼び出した際に、ログに `fun is invalid.` というメッセージが表示されたり、テストコードで `ArgumentNullException` が捕捉されたりした場合は、いずれも **null のコールバックが渡された** ことを意味します。このページでは、迅速な特定方法と修正方法を説明します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 実行ログに `fun is invalid.` が出力される | `AddXxxListener` / `RemoveXxxListener` に渡された `Action` が `null` であり、内部で `Log.Fatal` を呼び出した後に即座に `return` するため、リスナーが登録されない | コールバック変数に実際のメソッドまたは `lambda` を代入し、`?.` でチェックしたうえで渡す |
| ユニットテストで `ArgumentNullException` がスローされる | 同じインターフェース群の内部にある `_monoManager` が `null` に対して例外をスローするため、「null を渡すと必ず失敗する」ことが検証されている | 上記と同じ原因のため、null 以外のコールバックを渡す |
| 起動時に `Mono manager is invalid.` が出力される | `MonoComponent.Awake` 内で `_monoManager == null` となっており、フレームワークのモジュールが登録されていない | 後述の「修正手順 2」を参照 |
| 起動時に `Event manager is invalid.` が出力される | `MonoComponent.Start` 内で `m_EventComponent == null` となっており、イベントコンポーネントがアタッチされていない | 後述の「修正手順 2」を参照 |

## 修正手順

### 1. コールバックが null の場合は、渡すごとに null チェックを行う

`MonoComponent` はすべての `Add*Listener` / `Remove*Listener` に対して `if (fun == null)` の検証を行っており、これに該当した場合には `Fatal` ログを記録するだけで、購読/購読解除の処理は一切実行されず、例外も自動的にスローされません — ただし、登録の動作は発生しません。

ソース: [MonoComponent.cs#L147-L171](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L147-L171)

```csharp
public void AddLateUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddLateUpdateListener(fun);
}
```

修正方法: 渡す前に null チェックを行うか、空合体演算子 (null 合体演算子) を使って空の実装を既定値として指定します。例:

```csharp
Action<float, float> onLate = null;
if (onLate != null)
{
    GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener(onLate);
}

// または lambda をプレースホルダーとして使用する
GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener((dt, fdt) => { /* あなたのロジック */ });
```

### 2. 起動時に "Mono manager is invalid." または "Event manager is invalid." が出力される

これら 2 つのログは `MonoComponent` 自体の初期化段階で出力されるものであり、コールバックが null であることは原因ではありません。フレームワークのモジュール/コンポーネントが未準備であることが原因です。

```csharp
protected override void Awake()
{
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}

private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

ソース: [MonoComponent.cs#L52-L76](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76)

修正方法:

1. シーンに `IMonoManager` を実装したモジュールのエントリポイント用コンポーネントがアタッチされているか、対応するアセンブリが Player Settings の `Scripting Define Symbols` またはアセンブリ定義に含まれているかを確認します。
2. GameFramework の `GameEntry` プレハブに `EventComponent` をアタッチし、その実行順序が `MonoComponent` よりも早いことを確認します。

### 3. 対象となるすべてのリスナーメソッド

`MonoComponent.cs` 内の以下のメソッドは、いずれも「null を渡すと → `fun is invalid.` ログ → return」という同一のパターンに従っているため、原因調査時にはまとめて確認してください:

`AddUpdateListener` / `RemoveUpdateListener`、`AddFixedUpdateListener` / `RemoveFixedUpdateListener`、`AddLateUpdateListener` / `RemoveLateUpdateListener`、`AddDestroyListener` / `RemoveDestroyListener`、`AddOnApplicationFocusListener` / `RemoveOnApplicationFocusListener`、`AddOnApplicationPauseListener` / `RemoveOnApplicationPauseListener`、`AddOnApplicationQuitListener` / `RemoveOnApplicationQuitListener`、`AddDrawGizmosListener` / `RemoveDrawGizmosListener`。

ソース: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs)

## 検証

修正後、以下の方法で問題が解決したことを確認します:

1. **実行時**: ゲームを再度実行し、ログに `fun is invalid.`、`Mono manager is invalid.`、`Event manager is invalid.` がもう表示されないことを確認します。
2. **コールバックの発火**: コールバック内で `Debug.Log` を 1 行記述し、対応するライフサイクル (例: `Update`、`LateUpdate`) に進んだ際にログが出力されることを確認します。これにより、サブスクリプションが成功したことがわかります。
3. **ユニットテスト**: リポジトリの `Tests/UnitTests.cs` 内の `Assert.Throws<ArgumentNullException>(() => _manager.AddUpdateListener(null))` などのテストケースは、「null を渡すと必ず失敗する」という契約の検証に使用されます。ビジネスコード側では実際のデリゲートを渡すようにしてください。
