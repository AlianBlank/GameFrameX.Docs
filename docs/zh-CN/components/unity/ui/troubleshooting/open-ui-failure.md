# 打开界面失败怎么办

调用 `OpenUIForm` / `OpenUIFormAsync` 没有出现界面,或收到 `OpenUIFormFailureEventArgs` 事件时,可以按本页给出的诊断表定位原因并修复。常见的失败原因集中在**资源未注册、界面组不存在、序列化脚本宏缺失、脚本未挂载**几类。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `OpenUIForm` 返回的实例为 `null`,或 `OpenUIFormFailureEventArgs.ErrorMessage` 提示找不到资源 | `uiFormAssetName` 未在 UI 组件中注册(配置缺失或拼写错误) | 在 UIForm 配置中补全资源名,确认 `UIFormAssetName` 与调用方传入完全一致 |
| 报错提示找不到 UI 组 / UIGroup | 传入的 `uiGroupName` 不存在 | 先调用 `AddUIGroup` 添加组,或传入已注册的组名 |
| 整个 `UIComponent` 报错或无法调用 `OpenUIForm` | 项目未启用 `GameFrameX.UI` 脚本宏 | 编辑器中通过 `UISystemScriptingDefineCheckHandler` 补齐脚本宏,或在 Player Settings 中添加 `GameFrameX.UI` |
| 资源存在但界面打开后逻辑不触发 | UIForm 预制体上没有挂载对应的逻辑脚本 | 给 `UIForm` 预制体挂上正确的逻辑类组件 |
| `OpenUIFormFailureEventArgs` 始终不触发,但界面也没显示 | 没有订阅事件,失败被静默吞掉 | 订阅 `OpenUIFormSuccessEventArgs` / `OpenUIFormFailureEventArgs` 后再调用 |
| `uiFormAssetPath` 与 `uiFormAssetName` 混淆,导致异步加载失败 | 调用时把"路径"和"资源名"互换 | 区分:配置里填的是 `UIFormAssetName`(逻辑名),`uiFormAssetPath` 是资源地址 |

## 修复步骤

### 1. 资源未注册 / 名字拼错

打开 UI 配置,确认对应 UIForm 的 `UIFormAssetName` 字段已填写,且名称与 `OpenUIForm` 调用一致。

```csharp
// 调用方:名称必须与 UIFormInspector 中 m_UIFormAssetName 一致
UIComponent.OpenUIForm("ShopUI", "Normal");
```

`UIForm` 预制体的可用字段见 [UIFormInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UIFormInspector.cs#L92-L110)。

### 2. UI 组不存在

`uiGroupName` 必须是已通过 `AddUIGroup` 注册过的组名。常见场景:复制别人的代码但忘了注册 `Window`、`Popup` 等自定义组。

### 3. 脚本宏未启用

`UIComponent` 的全部接口依赖脚本宏 `GameFrameX.UI`。如果从未启用,调用会直接报错。运行时通过 [UISystemScriptingDefineCheckHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UISystemScriptingDefineCheckHandler.cs) 在编辑器里自动检查并补齐。

### 4. 订阅失败事件,定位真实错误

不要只判断返回值。订阅 `OpenUIFormFailureEventArgs` 可以拿到完整错误堆栈,比盲猜更快。

```csharp
// 来自 README.md 示例
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnUIFormOpenFailure);
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnUIFormOpenSuccess);

private void OnUIFormOpenFailure(object sender, GameEventArgs e)
{
    var args = (OpenUIFormFailureEventArgs)e;
    Debug.LogError($"打开 {args.UIFormAssetName} 失败: {args.ErrorMessage}");
}
```

`ErrorMessage`、`UIFormAssetName`、`SerialId`、`UserData` 的字段定义见 [OpenUIFormFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormFailureEventArgs.cs#L88-L131)。

### 5. UIForm 预制体没挂逻辑脚本

如果界面"打开"了但是逻辑(`OnInit`、`OnOpen`、`OnUpdate`)不执行,通常是预制体上缺少 `IUIForm` 逻辑组件。打开对应预制体,把继承 `UIForm` 的脚本挂到根节点上。

## 验证

按下列顺序逐项确认:

1. 在 Console 中看到 `OpenUIFormSuccessEventArgs` 触发,说明打开成功。
2. 在 `OnUIFormOpenFailure` 中 `Debug.LogError` 出 `ErrorMessage`,按消息关键字(例如 "not found"、"has not been")回到上方诊断表。
3. 关闭并重新进入界面,确认场景切换不会导致 UI 状态丢失。
4. 在 Editor 中检查 `UIForm` 组件的 Inspector(`UIFormAssetName`、`FullName`、`SerialId`)显示正常。
