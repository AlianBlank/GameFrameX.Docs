# Sound manager is invalid 解決方法

執行遊戲時，日誌中會輸出 `Fatal: Sound manager is invalid.`,且音效元件無法播放任何音效。此錯誤的原因是 `SoundComponent.Awake()` 向 `GameFrameworkEntry` 請求 `ISoundManager` 模組時返回了 `null`,導致後續初始化直接 return。

## 快速診斷

| 症狀 | 原因 | 解決方案 |
|------|------|------|
| 啟動後日誌中出現 `Fatal: Sound manager is invalid.` 且 PlaySound 不作用 | 未將 `SoundManager` 實作類別註冊至框架模組表 | 在 `SoundComponent` Inspector 中設定正確的 `Component Type`(參閱下方步驟 1) |
| 啟動後日誌中出現 `Fatal: Sound manager is invalid.` 但 `Component Type` 已設定 | 所設定的類別名稱拼字錯誤、該類別被程式碼剝離，或未被編譯進執行階段組件 | 在專案中以類別名稱 `GameFrameX.Sound.SoundManager` 搜尋，確認類別存在且未被 Stripping 移除 |
| 在編輯器中正常，但建置打包後發生錯誤 | IL2CPP/Managed Stripping 將 `SoundManager` 型別剝離 | 在 `link.xml` 中保留 `GameFrameX.Sound.SoundManager`,或停用 Stripping |

## 解決步驟

### 1. 在 SoundComponent Inspector 中指定實作類別

開啟掛載了 `SoundComponent` 的場景物件，在 Inspector 中找到 `Component Type` 欄位，輸入實作類別的完整型別名稱。`SoundComponent.Awake()` 會以該名稱透過反射載入並註冊至 `GameFrameworkEntry`:

```csharp
// Runtime/Sound/SoundComponent.cs#L102-L118
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ISoundManager);
    base.Awake();
    EnsureAudioMixer();
    if (!IsRuntimeComponentReady)
    {
        return;
    }

    m_SoundManager = GameFrameworkEntry.GetModule<ISoundManager>();
    if (m_SoundManager == null)
    {
        Log.Fatal("Sound manager is invalid.");
        return;
    }
    ...
}
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L102-L132)

`Component Type` 的常見值:`GameFrameX.Sound.SoundManager`(命名空間 + 類別名稱，可在 `Runtime/Sound/Sound/SoundManager.cs` 中確認)。

### 2. 確認實作類別本身是否存在

在 Project 視窗中搜尋 `SoundManager.cs`,確認儲存庫中包含的實作類別是否仍存在於專案中：

```
Runtime/Sound/Sound/SoundManager.cs
```

Source: [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs)

若此檔案被意外刪除或重新命名，反射 `GetType(componentType)` 會返回 `null`,使模組表中沒有 `ISoundManager`,進而引發此錯誤。

### 3. 處理 IL2CPP 程式碼剝離(建置打包情境)

`Utility.Assembly.GetType(componentType)` 需要執行階段能依名稱找到型別才能運作。IL2CPP + Managed Code Stripping 可能在建置時移除未被直接參考的 `SoundManager`,使 `GetType` 返回 `null`。請在 `Assets/link.xml` 中加入以下內容：

```xml
<linker>
  <assembly fullname="GameFrameX.Sound" preserve="all"/>
</linker>
```

或將 `Stripping Level` 調整為 `Low` 後重新建置以進行驗證。

## 驗證

1. 啟動場景，確認 Console 中不再出現 `Fatal: Sound manager is invalid.`。
2. 呼叫 `GameEntry.GetComponent<SoundComponent>().PlaySound(...)`,確認能聽到音效且未觸發 `PlaySoundFailure` 事件。
3. 確認 `m_SoundManager` 已被指派：在 `SoundComponent.Awake` 之後的程式碼路徑(`Start`)中必須滿足 `m_SoundManager != null`,後續的 `SetResourceManager` / `SetSoundHelper` 才能正常執行。
