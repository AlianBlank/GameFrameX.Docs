# EventComponent / IEventManager API 速查

本页收录 GameFrameX.Event 事件模块对外的全部公开 API：场景组件 `EventComponent` 与其背后的接口 `IEventManager`，包含真实签名、事件参数基类与线程安全说明，可直接按表查用。

## 获取组件

`EventComponent` 是挂在场景中的 Unity 组件（菜单路径 `GameFrameX/Event`，`[DisallowMultipleComponent]`，组件优先级 -7000），它在 `Awake` 中通过 `GameFrameworkEntry.GetModule<IEventManager>()` 拿到事件管理器，随后所有公开方法都直接转发给该管理器。日常业务代码只需使用 `EventComponent`，无需自己创建 `IEventManager` 实现。

## EventComponent 公开 API

| 名称 | 签名 | 说明 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | 获取事件处理函数的总数量 |
| EventCount | `int EventCount { get; }` | 获取事件数量 |
| Count | `int Count(string id)` | 获取指定事件编号的事件处理函数数量 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 检查指定事件是否已订阅该处理函数 |
| CheckSubscribe | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 不存在时才订阅，避免重复订阅 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 取消订阅事件处理函数 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 检查并取消订阅；handler 不存在时不执行任何操作 |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | 设置默认事件处理函数（无订阅者时兜底） |
| Fire | `void Fire(object sender, GameEventArgs e)` | 抛出事件；线程安全，主线程回调，下一帧分发 |
| Fire（重载） | `void Fire(object sender, string eventId)` | 用 `eventId` 创建 `EmptyEventArgs` 并抛出；内部调用 `GameFrameworkGuard.NotNullOrEmpty` 校验非空 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | 抛出事件立即模式；非线程安全，立刻分发 |

Source: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L171)

注意 `CheckSubscribe` 是 `EventComponent` 独有的便捷方法（接口上没有）：它先调用 `Check`，未订阅才调用底层 `Subscribe`。

```csharp
if (!Check(id, handler))
{
    m_EventManager.Subscribe(id, handler);
}
```

## IEventManager 接口成员

`EventComponent` 未公开 `Subscribe` 的转发方法，底层订阅统一通过接口完成（组件层提供 `CheckSubscribe` 代替）。接口定义如下：

| 名称 | 签名 | 说明 |
|------|------|------|
| EventHandlerCount | `int EventHandlerCount { get; }` | 获取事件处理函数的数量 |
| EventCount | `int EventCount { get; }` | 获取事件数量 |
| Count | `int Count(string id)` | 获取指定事件编号的事件处理函数数量 |
| Check | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 检查是否存在事件处理函数 |
| Subscribe | `void Subscribe(string id, EventHandler<GameEventArgs> handler)` | 订阅事件处理函数 |
| Unsubscribe | `void Unsubscribe(string id, EventHandler<GameEventArgs> handler)` | 取消订阅事件处理函数 |
| CheckUnsubscribe | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 检查并取消订阅；handler 不存在时不执行任何操作 |
| SetDefaultHandler | `void SetDefaultHandler(EventHandler<GameEventArgs> handler)` | 设置默认事件处理函数 |
| Fire | `void Fire(object sender, GameEventArgs e)` | 抛出事件；线程安全，主线程回调，事件在抛出后的下一帧分发 |
| FireNow | `void FireNow(object sender, GameEventArgs e)` | 抛出事件立即模式；不是线程安全的，事件会立刻分发 |

Source: [Runtime/Event/IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L38-L105)

与 `EventComponent` 的差异一览：

- `EventComponent.CheckSubscribe(id, handler)` 对应 `IEventManager.Subscribe(id, handler)` 的"检查后订阅"版本。
- `EventComponent.Fire(object sender, string eventId)` 是组件独有的字符串重载，等价于 `Fire(sender, EmptyEventArgs.Create(eventId))`。
- 初始化失败时组件会打出 `Log.Fatal("Event manager is invalid.")`。

Source: [Runtime/EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

## Fire 与 FireNow 选型

| 场景 | 用法 | 原因 |
|------|------|------|
| 子线程 / 异步任务中抛事件 | `Fire(sender, e)` | 线程安全，回调保证在主线程执行，但会推迟到下一帧分发 |
| 主线程内需要同步执行回调 | `FireNow(sender, e)` | 立刻分发；非线程安全，不要在子线程调用 |
| 只需要触发信号、无附加数据 | `Fire(sender, eventId)` | 组件重载会自动创建 `EmptyEventArgs`（内部经引用池） |

以上线程语义来自源码中两处的注释说明：`Fire` "这个操作是线程安全的，即使不在主线程中抛出，也可保证在主线程中回调事件处理函数，但事件会在抛出后的下一帧分发"；`FireNow` "这个操作不是线程安全的，事件会立刻分发"。
