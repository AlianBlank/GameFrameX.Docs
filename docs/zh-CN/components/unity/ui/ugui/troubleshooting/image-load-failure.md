# 异步图片加载异常怎么办

当调用 `UIImage.icon` 或 `Image.SetIconAsync(...)` 后图片未显示、控制台出现 `Failed to load icon '<path>': ...` 报错，或者图片只在编辑器生效打包后丢失时，按本页步骤排查。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台输出 `Failed to load icon 'xxx': ...` | `AssetComponent.LoadAssetAsync` 抛异常或资源不存在 | 见「资源路径错误」 |
| `icon` 赋值后图片仍是空白 | 资产未被打进 YooAsset 打包清单 | 见「资源未打入 YooAsset 清单」 |
| 编辑器正常,运行后图片丢失 | 运行时使用了编辑器专属资源(如 `AssetDatabase`) | 见「编辑器 / 运行时资源分离」 |
| 图标显示但拉伸/裁剪异常 | `SetIconAsync` 用 `Rect(0,0,w,h)` 重建 Sprite,忽略原图边框 | 见「Sprite 边框与九宫格丢失」 |
| 切换 `icon` 后旧纹理仍驻留内存 | `SetIconAsync` 内 `using` 已释放句柄,但旧 Sprite 未显式销毁 | 见「内存泄漏与句柄释放」 |

## 修复步骤

### 资源路径错误

`SetIconAsync` 内部使用 `AssetComponent.LoadAssetAsync<Texture2D>(icon)`,路径必须与 YooAsset 清单中的 `Location` 完全一致(大小写敏感,且不要带文件扩展名)。

```csharp
[UnityEngine.Scripting.Preserve]
public static async Task SetIconAsync(this UnityEngine.UI.Image self, string icon)
{
    try
    {
        var assetComponent = GameEntry.GetComponent<AssetComponent>();
        using (var valueHandle = await assetComponent.LoadAssetAsync<Texture2D>(icon))
        {
            if (valueHandle.IsDone && valueHandle.Status == EOperationStatus.Succeed)
            {
                var texture2D = valueHandle.GetAssetObject<Texture2D>();
                self.sprite = Sprite.Create(texture2D, new Rect(0, 0, texture2D.width, texture2D.height), new Vector2(0.5f, 0.5f));
            }
        }
    }
    catch (System.Exception e)
    {
        Log.Error($"Failed to load icon '{icon}': {e.Message}");
    }
}
```

Source: [UGUIImageExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIImageExtension.cs#L56-L74)

修复动作:

1. 在 YooAsset 资源管理窗口(例如 `Asset Bundle Collector`)里搜索该 `icon` 字符串,确认其作为 `Texture2D` 类型的 Location 存在。
2. 移除扩展名(如写 `Assets/UI/Icons/coin` 而不是 `.png`)。
3. 用 `AssetComponent.LoadAssetAsync<Texture2D>` 直接传同一个字符串调试一次,看是否还抛异常。

### 资源未打入 YooAsset 清单

`UIImage.icon` setter 通过 `SetIconAsync` 走运行时资源加载:

```csharp
[UnityEngine.Scripting.Preserve]
public string icon
{
    get { return m_icon; }
    set
    {
        if (m_icon != value)
        {
            m_icon = value;
            _ = this.SetIconAsync(m_icon);
        }
    }
}
```

Source: [UIImage.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIImage.cs#L60-L71)

修复动作:

1. 打开 YooAsset 收集器,确认图标所在目录被某个收集规则覆盖。
2. 重新构建资源包并热更到目标平台,再启动游戏。

### 编辑器 / 运行时资源分离

`UIImage` 是继承自 `UnityEngine.UI.Image` 的脚本组件,只在编辑器内通过菜单替换为它:

```csharp
[CustomEditor(typeof(UnityEngine.UI.Image))]
public class UIImageReplaceHandler : UnityEditor.Editor
{
    [MenuItem("CONTEXT/Image/Replace To UIImage(替换为UIImage)", false, 10)]

    {
        ...
    }
}
```

Source: [UIImageReplaceHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UIImageReplaceHandler.cs#L39-L76)

如果运行时直接走 `Resources.Load` 取编辑器路径,会失败。修复动作:确保所有图标都来自 YooAsset 的运行时清单,不要混用 `Resources/` 或编辑器内置资产。

### Sprite 边框与九宫格丢失

`SetIconAsync` 用 `Sprite.Create(texture2D, new Rect(0,0,w,h), ...)` 直接构造 Sprite,不读取原 Sprite 的 `border`。修复动作:如果原图是九宫格,改用 `AssetBundle` 中带 `Sprite` 类型预制,不要通过 `icon` 字符串走运行时创建。

### 内存泄漏与句柄释放

`SetIconAsync` 内已经 `using (var valueHandle = ...)`,句柄会自动归还;但若你多次切换 `icon`,旧 `Sprite` 仍挂在新 `Texture2D` 上,可能被认为仍有引用。修复动作:在切换前手动把 `self.sprite = null`,让旧 Sprite 没有引用后随 `Texture2D` 一起被 GC。

## 验证

1. 重新给 `UIImage.icon` 赋值,观察控制台不再输出 `Failed to load icon`。
2. 在 YooAsset 资源浏览器里把同一个 `Location` 拖到 `UIImage.icon` 上,看 `Sprite Renderer` 面板里有图。
3. Profiler → Memory → Texture,确认切换后旧纹理引用计数归零。
4. 打包到目标平台后,在真机再跑一次同样流程。

## 背景(可选)

`UIImage` 仅为 `UnityEngine.UI.Image` 增加 `icon` 属性,实际加载逻辑全部走 `UGUIImageExtension.SetIconAsync`,通过 `GameEntry.GetComponent<AssetComponent>()` 调用 YooAsset 异步接口,失败时仅记录日志而不抛出。
