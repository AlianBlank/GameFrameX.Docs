# 使用 UI 群組（UIGroup）控制 Canvas 圖層與深度的方法

透過 `UIGroup`（UI 群組），可將開啟的 UI 依業務別分組，並掛載到不同的 `RectTransform` 節點上；群組內每新增一層，`Z` 軸深度便會以 1000 單位向後推移，據此決定繪製順序與點擊命中順序。本頁面提供兩種最常見的用法：在 UI 中以特性（Attribute）宣告群組的方式，以及在執行階段手動加入群組的方式。

## 前置條件

- 專案已引入 GameFrameX 與 `com.gameframex.unity.ui.ugui`，且 UI 框架必須已透過場景中的 `UIComponent` 完成初始化（場景中需存在 `UGUICanvas`、`UGUICamera`、`EventSystem` 等節點，這些節點會由 `UGUIUIGroupHelper.EnsureRuntimeRoot` 在首次開啟 UI 時視需要建立）。
- 瞭解要開啟的 UI 類別必須實作 `IUIForm`（或繼承 `UIForm`／框架程式碼產生器所產生的基底類別）。

## 操作步驟

### 方法 1：使用 `OptionUIGroupAttribute` 將 UI 綁定至群組

只要在 UI 型別上宣告 `OptionUIGroup` 特性，`UGUIFormHelper` 就會自動從 `UIComponent` 取得同名群組，並指派給 `uiForm.UIGroup`。

```csharp
using GameFrameX.UI.Runtime;

[OptionUIGroup("HUD")]
public sealed class HUDForm : UIForm
{
    // ...
}
```

`UGUIFormHelper` 會先讀取 `uiForm.UIGroup`，若為空，則依據特性中的 `GroupName` 呼叫 `m_UIComponent.GetUIGroup(...)`：

```csharp
// 來源: UGUIFormHelper.cs
var uiGroup = uiForm.UIGroup;
if (uiGroup == null)
{
    var attribute = uiFormType.GetCustomAttribute(typeof(OptionUIGroupAttribute));
    if (attribute is OptionUIGroupAttribute optionUIGroup)
    {
        uiGroup = m_UIComponent.GetUIGroup(optionUIGroup.GroupName);
    }

    uiForm.UIGroup = uiGroup;
}
```

來源：[UGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L112-L122)

### 方法 2：在執行階段手動指定群組

在呼叫 `UIComponent.OpenUIForm`（或透過 `UIManager.OpenUIForm` 的間接呼叫）之前，先從 `UIComponent` 取得目標 `IUIGroup`，並直接寫入 `uiForm.UIGroup`。

```csharp
var group = GameEntry.UI.GetUIGroup("Popup"); // 範例: 取得名為 "Popup" 的群組
// 開啟 UI 後寫入群組
uiForm.UIGroup = group;
```

寫入完成後，`UIManager.Open` 會將群組作為參數傳入 `uiForm.Init(...)`，之後的開啟／關閉／焦點操作都會以該群組為基準進行管理：

```csharp
// 來源: UIManager.Open.cs
var uiGroup = uiForm.UIGroup;
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, null,
    pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);
```

來源：[UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L200-L201)

### 深度如何計算

每個群組在透過 `UGUIUIGroupHelper` 建立時會取得 `RectTransform`，群組下的子節點會以 `localPosition.z` 拉開距離：

```csharp
// 來源: UGUIUIGroupHelper.cs
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

來源：[UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

重點事項：

- `Depth` 是該群組在所有群組中的索引（通常由 `UIComponent` 依建立順序指派）。
- 同一群組內的多個 UI 會以 1000 單位依開啟順序向後堆疊，因此在 `ScreenSpaceCamera` 的 `Canvas`（`planeDistance = 100f`、`sortingOrder = 0`）上決定繪製順序。
- 若要讓特定 UI 顯示在其他 UI 之上，應將其放入索引較大的群組，或讓同一群組內較晚開啟的 UI 蓋住較早開啟的 UI。

### 群組的執行階段結構

呼叫 `Handler(...)` 時會執行下列操作：

1. 呼叫 `SetDepth(depth)`，將目前節點的 `z` 設定為 `depth * 1000`；
2. 透過 `EnsureRuntimeRoot` 確認根節點下是否存在 `UGUICamera`、`UGUICanvas`、`EventSystem`；
3. 在 `root` 之下建立名為 `groupName` 的 `GameObject`，並掛上 `RectTransform` 使其填滿整個畫面；
4. 將該節點與所有子節點的圖層設定為 `UI`；
5. 呼叫 `Helper.CreateHelper`，在該節點上附加 `UGUIUIGroupHelper` 實例（或使用者傳入的自訂 Helper）：

```csharp
// 來源: UGUIUIGroupHelper.cs
GameObject component = new GameObject(groupName);
component.transform.SetParent(root, false);
var uiLayer = LayerMask.NameToLayer("UI");
component.SetLayerRecursively(uiLayer);

RectTransform rectTransform = component.GetOrAddComponent<RectTransform>();
rectTransform.MakeFullScreen();
var uiGroupHelper = Helper.CreateHelper(component, uiGroupHelperTypeName,
    (UIGroupHelperBase)customUIGroupHelper, 0);
return uiGroupHelper;
```

來源：[UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L86-L113)

最終的場景階層結構大致如下：

```
UIComponent
└── UGUICanvas (Canvas, CanvasScaler, GraphicRaycaster)
    ├── Default (群組 0)
    │   ├── FormA
    │   └── FormB
    ├── HUD (群組 1)
    │   └── HUDForm
    └── Popup (群組 2)
        └── PopupForm
```

## 常見變化

- **多群組分層**：將 `HUD`、`Popup`、`Dialog`、`Loading` 等不同用途的 UI 劃分至不同群組，群組之間便會以 `depth * 1000` 自然分層。
- **取代預設 Helper**：實作 `IUIGroupHelper`（繼承 `UIGroupHelperBase`）後，在 `UIComponent` 新增群組時透過 `customUIGroupHelper` 參數傳入，即可覆寫預設 `UGUIUIGroupHelper` 的行為（例如：自訂深度演算法或額外元件）。
- **編輯器自訂**：可在 Inspector 中透過 `UGUIComponentInspector` 等編輯器指令碼檢視／調整群組與深度。

## 常見錯誤

- **既未宣告 `OptionUIGroup` 也未手動指派的情況**：進入 `UGUIFormHelper` 後 `uiGroup` 會是 `null`，最終觸發日誌 `UI group is invalid.` 並回傳 `null`，導致 UI 開啟失敗。
- **群組名稱拼字錯誤**：使用了 `OptionUIGroup("Popuo")`，但 `UIComponent` 中實際的群組名稱為 `"Popup"` 時，`GetUIGroup` 會回傳 `null`，同樣觸發 `UI group is invalid.`。建議以統一的常數約定，避免拼字錯誤。
- **想以 `Canvas.sortingOrder` 變更層級的情況**：在此實作中，群組層級的 `Canvas.sortingOrder` 為固定值 `0`，群組內／群組之間是以 `localPosition.z = depth * 1000` 區隔。即使在 Inspector 中直接修改 `sortingOrder`，下一次呼叫 `Handler(...)` 時也會被覆寫。
- **手動將節點放入 `UGUICanvas` 之下卻忘記設定 `UI` 圖層的情況**：`UGUIUIGroupHelper` 建立的節點會執行 `SetLayerRecursively(uiLayer)`，但使用者自行新增的輔助 UI 子節點仍須維持 `UI` 圖層，否則會被 `UGUICamera` 的 `cullingMask` 剔除。

## 背景（可選）

`UIGroup` 的設計思維源自經典 GameFrameX 框架的 UI 群組化：所有 UI 共用同一個 `UGUICanvas`，透過 `Z` 軸偏移避免多個 Canvas 相互重疊，並透過 `GraphicRaycaster` 進行點擊分發。`SetDepth` 之所以將 `depth` 放大 1000 倍，是為了在同一群組內保留足夠的空間，供多次「移至最上層」操作之用——只要在與 `Depth` 相同的位置再疊加小單位偏移，就能在不影響其他群組的情況下，穩定地將特定 UI 提升至該群組內的最上層。
