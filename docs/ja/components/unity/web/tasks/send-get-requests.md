# GETリクエストの送信方法(クエリパラメータとリクエストヘッダー)

`IWebManager` の `GetToString` / `GetToBytes` シリーズのメソッドで GET リクエストを送信できます:クエリパラメータは `Dictionary<string, string>` で渡し(フレームワークが自動的に URL に結合します)、リクエストヘッダーはもう一つの `Dictionary<string, string>` で渡します。`Task<WebStringResult>` または `Task<WebBufferResult>` が返され、`await` で待機できます。

## 前提条件

- プロジェクトに本パッケージの Web ランタイムが既に導入されていること(`Runtime/Web`、エントリコンポーネントは [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs))。
- `IWebManager` のインスタンスを取得していること([WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs) で実装された `partial` クラス)。

## GET メソッド早見表

以下のシグネチャは [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L18-L67) から抜粋したものです:

| メソッド | シグネチャ | 説明 |
|------|------|------|
| 最もシンプルな GET(テキスト) | `Task<WebStringResult> GetToString(string url, object userData = null)` | パラメータなし、カスタムヘッダーなし |
| 最もシンプルな GET(バイト) | `Task<WebBufferResult> GetToBytes(string url, object userData = null)` | バイナリのダウンロードに適する |
| クエリパラメータ付き(テキスト) | `Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, object userData = null)` | パラメータは自動的に URL に結合される |
| クエリパラメータ付き(バイト) | `Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, object userData = null)` | 同上、バイトを返す |
| パラメータとリクエストヘッダー付き(テキスト) | `Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | パラメータは後、リクエストヘッダーは前 |
| パラメータとリクエストヘッダー付き(バイト) | `Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)` | 同上、バイトを返す |

すべてのオーバーロードはオプションの `userData` をサポートしており、結果オブジェクトにそのまま格納されて返されます(下記の「背景」を参照)。

## 操作手順

1. `GetToString` / `GetToBytes` の目的のオーバーロードを呼び出して `url` を渡します。クエリパラメータやリクエストヘッダーが必要な場合は、対応するディクショナリも渡します。
2. 返された `Task` を `await` し、`WebStringResult`(レスポンステキスト)または `WebBufferResult`(バイト配列)を取得します。
3. 失敗するとタスクが例外をスローします(ネットワーク/HTTP エラーまたは `TimeoutException`)。`await` を `try/catch` で囲むだけで対応できます。

最もシンプルな形式の実際の実装(引数なしのオーバーロードは「パラメータ + ヘッダー」オーバーロードに直接委譲します):

```csharp
public Task<WebStringResult> GetToString(string url, object userData = null)
{
    return GetToString(url, null, null, userData);
}
```

出典: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L133-L136)

クエリパラメータとリクエストヘッダーを含む完全なオーバーロード(フレームワーク内部でパラメータのマージ、URL の結合、キューイングを行います):

```csharp
public Task<WebStringResult> GetToString(string url, Dictionary<string, string> queryString, Dictionary<string, string> header, object userData = null)
{
    var uniTaskCompletionSource = new TaskCompletionSource<WebStringResult>();
    queryString = MergeQueryString(queryString);
    header = MergeHeader(header);
    url = UrlHandler(url, queryString);

    WebJsonData webJsonData = WebJsonData.Create(url, header, true, uniTaskCompletionSource, userData);
    m_WaitingNormalQueue.Enqueue(webJsonData);
    return uniTaskCompletionSource.Task;
}
```

出典: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L184-L195)

上記のシグネチャに基づく典型的な呼び出し方(返された Task を `await` で消費します):

```csharp
// 1) 最もシンプルな GET
WebStringResult r1 = await webManager.GetToString("https://example.com/api/info");

// 2) クエリパラメータ付き
var query = new Dictionary<string, string> { { "page", "1" }, { "size", "20" } };
WebStringResult r2 = await webManager.GetToString("https://example.com/api/list", query);

// 3) クエリパラメータ + リクエストヘッダー付き
var header = new Dictionary<string, string> { { "Authorization", "Bearer <token>" } };
WebStringResult r3 = await webManager.GetToString("https://example.com/api/user", query, header);
```

出典： [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L18-L67)

## よくあるバリエーション

- **バイト配列を返す(ファイルや画像のダウンロード)**:`GetToBytes` に切り替えると、`WebBufferResult` が返されます。シグネチャは [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L26-L67) を参照。
- **クエリパラメータの順序が正しくない?** オーバーロードの引数の順序は `(url, queryString, header, userData)` で固定されており、リクエストヘッダーのみを渡す場合も `queryString` を `null` で埋める必要があります。
- **クエリパラメータのみ渡す場合(ヘッダー不要)**：2 引数のオーバーロードを直接呼び出せば、URL を手動で組み立てる必要はありません。

## よくあるエラー

| 症状 | 原因 | 対処 |
|------|------|------|
| `await` が `TimeoutException` をスローする | リクエストのタイムアウト。[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L300) の `WebExceptionStatus.Timeout` 分岐で変換されたもの | タイムアウト時間を延ばすか、ネットワークを確認。`catch (TimeoutException)` で個別に処理 |
| タスクが一般的な `Exception` をスローする(内容はエラーテキスト) | 非 WebGL プラットフォームでは `HttpWebRequest` を使用し、ネットワーク/HTTP エラーは直接 `SetException`([WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L293-L305) を参照) | URL、パラメータ、サーバーのステータスコードを確認 |
| WebGL で `unityRequest.error` が発生 | WebGL 分岐で `isNetworkError / isHttpError / error` を検出した後に `TrySetException`([WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L239-L247) を参照) | WebGL プラットフォームからアクセス可能なクロスオリジンポリシーとサーバー設定を確認 |
| リクエストヘッダーが反映されない | 渡された `header` ディクショナリが空、またはグローバルのデフォルトヘッダーによる上書きロジックの影響 | キーと値が空でないことを確認。ヘッダーは `SetRequestHeader`/`request.Headers[key] = value` で 1 つずつ書き込まれます([WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L227-L233)、[WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L273-L279) を参照) |

## 背景(任意)

GET リクエストのデータの運び役は内部の `WebJsonData` です([WebManager.WebJsonData.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.WebJsonData.cs#L12-L98) を参照)。これは URL、`Header` ディクショナリ、結果の `TaskCompletionSource` を保持します。リクエストはまず `m_WaitingNormalQueue` に入って並び、送信フローによって WebGL では `UnityWebRequest.Get`、その他のプラットフォームでは `HttpWebRequest`(`WebRequestMethods.Http.Get`)で送信されます。クエリパラメータは `UrlHandler(url, queryString)` によって URL に結合され、カスタムヘッダーは 1 つずつリクエストに書き込まれます。`userData` は結果オブジェクトとともに返されるため、並行リクエストの区別に役立ちます。
