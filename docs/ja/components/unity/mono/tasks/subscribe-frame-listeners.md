# Update / FixedUpdate / LateUpdate のリスニング方法

`IMonoManager` の `AddUpdateListener` / `AddFixedUpdateListener` / `AddLateUpdateListener` の 3 つのメソッドを使用することで、独自に作成したコールバックを GameFrameX フレームワークが統合管理する Mono フレームループに登録でき、シーン内に別途 `MonoBehaviour` サブクラスを配置する必要がありません。

## 前提条件

- フレームワークの `MonoManager` モジュールが初期化されていること(フレームワークstarterによって読み込まれるため、通常は手動での対応は不要です)。
- プロジェクトが `GameFrameX.Mono.Runtime` アセンブリを参照していること。
- `using GameFrameX.Mono.Runtime;` を記述した後、フレームワークの `GameFrameworkEntry.GetModule<IMonoManager>()` を使用してマネージャーインスタンスを取得すること。

## 操作手順

1. Mono マネージャーインスタンスを取得します。

```csharp
using GameFrameX.Mono.Runtime;

IMonoManager mono = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IMonoManager>();
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L39-L51)

2. Update リスナーを登録します。コールバックのシグネチャは `Action<float, float>` で、最初のパラメータは経過時間 `elapseSeconds`、2 番目のパラメータは実経過時間 `realElapseSeconds` です。

```csharp
mono.AddUpdateListener((elapseSeconds, realElapseSeconds) =>
{
    // 毎フレームのロジック
});
```

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L142-L156)

3. FixedUpdate リスナーを登録します。渡される 2 つの float パラメータは `Time.fixedDeltaTime` と `Time.fixedUnscaledDeltaTime` です。

```csharp
mono.AddFixedUpdateListener((fixedDeltaTime, fixedUnscaledDeltaTime) =>
{
    // 固定ステップのロジック(物理関連でよく使用される)
});
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L87-L97)

4. LateUpdate リスナーを登録します。このコールバックはすべての `Update` の後に実行されるため、カメラ追従など最終ステップの処理が必要なロジックに適しています。

```csharp
mono.AddLateUpdateListener((deltaTime, unscaledDeltaTime) =>
{
    // すべての Update の後に実行される
});
```

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L75-L85)

5. 不要になった場合は、対応する `RemoveXxxListener` を使用してリスナーを削除します。渡されるデリゲートは登録時と同じインスタンスである必要があります。

```csharp
Action<float, float> handler = (a, b) => { /* ... */ };
mono.AddUpdateListener(handler);
// その後:
mono.RemoveUpdateListener(handler);
```

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L157-L180)

## よくあるバリエーション

- **Lambda 内でローカル変数をキャプチャ**:シンプルなロジックに適していますが、リスナーを削除する際に同じデリゲートインスタンスを取得できないため、オブジェクト破棄時にまとめて処理しない限り使用できません。
- **フィールドとしてキャッシュ**:`Action<float, float>` をメンバーフィールドに保存することで、後から `Remove` を繰り返せ、重复登録を回避できます。

```csharp
private Action<float, float> _tick;

private void OnEnable()
{
    var mono = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IMonoManager>();
    _tick = (a, b) => DoWork(a, b);
    mono.AddUpdateListener(_tick);
}

private void OnDisable()
{
    var mono = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IMonoManager>();
    if (_tick != null) mono.RemoveUpdateListener(_tick);
}
```

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `ArgumentNullException: action` | `AddXxxListener` に `null` を渡した | `null` を渡さず、必要に応じて先に null チェックを行う |
| リスナーが呼び出されない | モジュールが初期化されていない、または誤ったインスタンスを取得した | `GameFrameworkEntry.GetModule<IMonoManager>()` を使用してマネージャーを取得する |
| コールバックが毎フレーム複数回実行される | 同じデリゲートを重複して `Add` した | `OnEnable` で登録し `OnDisable` で削除するか、フィールドキャッシュを使用する |
| 削除後も実行される | 削除時に新しい lambda を渡し、参照が等しくない | 登録時のデリゲートインスタンスをキャッシュしてから `Remove` する |

Source: [MonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L142-L156)

## 背景(オプション)

`MonoManager` は内部で 3 種類のフレームループごとに `LinkedList<Action<float, float>>` を維持しており、`Update` / `FixedUpdate` / `LateUpdate` が発生した際に順次巡回し、対応する時間パラメータ(それぞれ `Time.deltaTime`、`Time.fixedDeltaTime` など)を渡します。リスナーの登録と削除は `lock` によって保護されているため、マルチスレッド環境でも安全に呼び出せます。
