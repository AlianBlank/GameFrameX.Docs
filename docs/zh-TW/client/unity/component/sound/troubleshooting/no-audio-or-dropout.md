# 播放時沒有聲音或聲音中斷的解決方法

呼叫 `ISoundManager.PlaySound` 後聽不到聲音、聲音被切斷，或在主控台/日誌中看到 `PlaySoundFailure` 事件時，請依照本頁的步驟找出原因並修正。

## 快速診斷

| 症狀 / 日誌關鍵字 | 原因(對應的 `PlaySoundErrorCode`) | 修正要點 |
|------|------|------|
| `Sound group 'X' is not exist.` | `SoundGroupNotExist` | 在 `ISoundManager` 註冊名為 X 的聲音群組 |
| `Sound group 'X' is have no sound agent.` | `SoundGroupHasNoAgent` | 在該聲音群組中加入至少一個 `ISoundAgent`(聲道) |
| 資產路徑錯誤 / Addressables 資產載入回呼失敗 | `LoadAssetFailure` | 確認 `soundAssetName` 是否已註冊至 Addressables、`.wav`/`.mp3` 是否已標記為 Addressable |
| `AudioSource.clip` 為空 / 代理器元件無法取得 AudioClip | `SetSoundAssetFailure` | 確認代理器 GameObject 是否位於場景中、AudioSource 是否已啟用 |
| 背景音樂突然停止，且日誌顯示被忽略 | `IgnoredDueToLowPriority` | 提高低優先順序播放請求的 `Priority`,或減少同時播放數量 |
| 完全沒有錯誤但聽不到聲音 | 音量被變更 / 靜音 / 距離衰減 | 確認 `Volume`、`Mute`、音訊監聽器、3D 距離參數 |
| 聲音斷斷續續或播放中突然消失 | 同時播放數超過 SoundAgent 數量 / 資產未預先載入 | 增加群組代理器數量，預先呼叫 `PlaySound` 為資產暖機 |

錯誤碼及其含義可在下列列舉定義中確認：

```csharp
public enum PlaySoundErrorCode : byte
{
    Unknown = 0,
    SoundGroupNotExist,
    SoundGroupHasNoAgent,
    LoadAssetFailure,
    IgnoredDueToLowPriority,
    SetSoundAssetFailure
}
```

## 修正步驟

### 1. 先訂閱失敗事件以掌握狀況

在系統啟動時訂閱 `PlaySoundFailure`,以確定具體是哪個錯誤碼：

```csharp
GameFrameXSound.Sound.PlaySoundFailure += OnPlaySoundFailure;

void OnPlaySoundFailure(object sender, PlaySoundFailureEventArgs e)
{
    Debug.LogError($"播放失败:[{e.ErrorCode}] {e.ErrorMessage} asset={e.SoundAssetName} group={e.SoundGroupName}");
}
```

在訂閱觸發點，失敗原因會記錄在 `ErrorMessage` 中，例如：

- `Sound group 'X' is not exist.` → 前往步驟 2
- `Sound group 'X' is have no sound agent.` → 前往步驟 3
- 出現 `... play sound 'X' failure.` 並伴隨 `LoadAssetFailure` / `SetSoundAssetFailure` → 前往步驟 4

### 2. `SoundGroupNotExist` —— 聲音群組未註冊

若聲音群組名稱不一致(大小寫、空格)，就會發生此錯誤。請先確認呼叫端傳入的 `soundGroupName` 是否與以 `ISoundManager.AddSoundGroup` 註冊的名稱完全一致。

### 3. `SoundGroupHasNoAgent` —— 群組中沒有代理器

每個聲音群組至少需要一個 `ISoundAgent`(對應一個 `AudioSource`)。若同時播放數量超過代理器數量，後續的請求會被丟棄或中斷。請檢查 `ISoundGroup.AgentCount`,或在 `PlaySoundParams` 中降低優先順序 / 提高 `Priority`,讓低優先順序的請求被忽略，而不是覆寫目前的音訊軌。

### 4. `LoadAssetFailure` / `SetSoundAssetFailure`

- **資產是否已註冊**:`soundAssetName` 必須能在 Addressables(或自訂的 `ISoundHelper`)中被解析為 `AudioClip`。
- **代理器是否就緒**:`DefaultSoundAgentHelper` 必須在播放前取得 `AudioSource` 並設定 `clip`,任一步驟失敗都會觸發 `SetSoundAssetFailure`。常見原因是代理器 GameObject 已被銷毀，或場景切換後聲音群組未重新建立。

Source: [DefaultSoundAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/DefaultSoundAgentHelper.cs)

### 5. 完全沒有錯誤卻聽不到聲音 —— 音量 / 空間參數

`ISoundAgent.Volume` 與 `ISoundGroup.Volume` 預設皆以 `Constant.DefaultVolume = 1f` 計算，若被業務邏輯改為 0 或被 `Mute=true` 覆寫，就會出現「播放成功但沒有聲音」的現象。`PlaySoundParams` 的主要預設值如下，任何一項被錯誤地改為 0 都會受到影響：

| 參數 | 預設值 | 含義 |
|------|--------|------|
| `Volume` | `1f` | 單次播放音量 |
| `Mute` | `false` | 是否靜音 |
| `Loop` | `false` | 是否循環播放 |
| `Priority` | `0` | 播放優先順序，0 為預設最低值 |
| `FadeInSeconds` / `FadeOutSeconds` | `0f` | 淡入/淡出時間(秒) |
| `Pitch` | `1f` | 音調(Pitch) |
| `PanStereo` | `0f` | 立體聲相位 |
| `SpatialBlend` | `0f` | 2D/3D 混合，1f 為純 3D |
| `MaxDistance` | `100f` | 3D 最大可聽距離 |
| `DopplerLevel` | `1f` | 都卜勒等級 |

Source: [Constant.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/Constant.cs#L43-L99)

另外需確認的事項：

- 場景中是否有 `AudioListener`(在 Unity 中要聽到聲音，必須存在一個)。
- 若 3D 聲音的 `SpatialBlend` 接近 1,且發聲體距離 `AudioListener` 超過 `MaxDistance`,聲音會衰減至聽不見。
- 確認編輯器的「Mute Audio」按鈕沒有被意外開啟。

### 6. 聲音中斷 / 掉幀

- **同時播放超過代理器數量**:`PlaySoundParams.Priority` 越低，越容易被新的高優先順序請求擠掉。重要的 BGM/語音請使用較高的 `Priority`,並將 `Loop` 設為 `true`。
- **資產未預先載入**：首次非同步載入資產時，音訊軌尚未載入完成，`PlaySound` 就再次被觸發。請使用 `PreloadSound`(或類似的暖機 API)預先載入常用資產。

## 驗證

修正後，請執行以下三項操作，確認問題是否已解決：

1. 觀察 `OnPlaySoundFailure` 回呼中，對應的 `ErrorCode` 輸出是否不再出現。
2. 在主控台中輸入 `GameFrameXSound.Sound.IsPlaying(serialId)`(或事先快取的回傳值)，確認播放中的控制代碼在結束時有被正常回收。
3. 在 Player 實機(非編輯器靜音)上完整執行一次包含 BGM + 語音 + SFX 的流程，確認沒有掉幀或突然中斷的情形。
