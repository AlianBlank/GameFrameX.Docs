# 如何使用 TCP/WebSocket/KCP/HTTP 接入客户端

通过 `GameFrameX.NetWork` 的 `INetWorkChannel` 与 `NetWorkSenderFactory`,可以让业务侧透明地收发 TCP、WebSocket、KCP、HTTP 客户端消息,无需关心底层协议差异。

## 前置条件

- 已安装 `GameFrameX.NetWork.Abstractions`、`GameFrameX.NetWork` 包;KCP 客户端需额外引用 `GameFrameX.NetWork.Kcp`,HTTP 客户端需引用 `GameFrameX.NetWork.HTTP`。
- 已接入 `GameFrameX.SuperSocket.Server.Abstractions.Session.IGameAppSession`(SuperSocket 会话)。
- 已配置对应协议的监听器(TCP / WebSocket / KCP / HTTP)。

## 操作步骤

### 1. 获取网络通道

业务处理器中通过会话获取 `INetWorkChannel`,后续收发都走通道,不直接接触协议。

```csharp
using GameFrameX.NetWork;
using GameFrameX.NetWork.Abstractions;
using GameFrameX.SuperSocket.Server.Abstractions.Session;

// 在 SuperSocket 消息处理上下文中
IGameAppSession session = /* 来自连接事件或消息处理 */;
INetWorkChannel channel = NetWorkSenderFactory.Create(session);
// NetWorkSenderFactory 会根据 session 实际类型自动选择 WebSocket 或 TCP 发送器
```

Source: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L12-L17)

### 2. 发送消息给客户端

构造 `INetworkMessage`,调用 `WriteAsync` 异步发送;`errorCode` 默认 `0`,业务侧可在出错时回传错误码。

```csharp
using GameFrameX.NetWork.Abstractions;

await channel.WriteAsync(message, errorCode: 0);
```

`INetWorkChannel.WriteAsync` 会在网络通道已关闭时抛出异常,调用前可用 `IsClosed()` 判一下。

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L96-L108)

### 3. 关闭连接

```csharp
channel.Close();
```

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L110-L116)

### 4. 在通道上存取自定义数据

`SetData` / `GetData<T>` / `RemoveData` / `ClearData` 用来在通道生命周期内挂载用户态数据(例如玩家对象、登录态),无需额外 Map。

```csharp
channel.SetData("playerId", 10001);
var pid = channel.GetData<long>("playerId");
channel.RemoveData("playerId");
// channel.ClearData(); // 断开或需要重置时
```

Source: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L118-L155)

## 常见变体

### TCP / WebSocket

`NetWorkSenderFactory.BuildProviders()` 内置了 `WebSocketNetWorkSenderProvider` 和 `SessionNetWorkSenderProvider`,分别覆盖 WebSocket 与 TCP(及 KCP 这类共享 `IGameAppSession` 的协议)会话类型——无需额外注册,按 `session.GetType()` 自动匹配。

Source: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L19-L36)

### KCP

KCP 会话同样实现 `IGameAppSession`,复用 `SessionNetWorkSenderProvider` 的发送路径;如需自定义编解码,在 KCP 监听器侧接入。

### HTTP

HTTP 走 `GameFrameX.NetWork.HTTP` 独立通道,处理完请求后 `Close()` 即可;`GetData`/`SetData` 可用于在请求处理链中传递上下文。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `WriteAsync` 抛异常 | 通道已关闭(`IsClosed()` 返回 `true`) | 发送前先 `if (!channel.IsClosed())` 守卫 |
| `GetData<T>` 抛异常 | Key 不存在或类型不匹配 | 写入时统一类型;读取前用 `ContainsKey` 风格的判断,或捕获异常 |
| WebSocket 消息发送失败 | 未走 `NetWorkSenderFactory`,直接用了 TCP 发送器 | 始终通过 `NetWorkSenderFactory.Create(session)` 获取通道,工厂会按会话类型分发 |
| KCP 包到达但业务收不到 | 未在 KCP 监听器侧接入 `INetWorkChannel` 管线 | 确认 KCP 会话包装了 `IGameAppSession`,并由工厂创建通道 |

## 背景(可选)

`NetWorkSenderFactory` 通过 `SenderProviders` 字典把协议会话类型映射到 `INetWorkSenderProvider`,`ResolveProvider` 优先精确匹配再回退到可赋值关系,使新增协议只需新增一对 `Provider` + `Sender` 实现并注册,业务侧 `WriteAsync` 调用无需改动。`INetWorkChannel` 把字节/包计数、心跳时间、自定义数据、关闭等能力都收敛到同一接口,业务代码因此只看到一个协议无关的通道视图。
