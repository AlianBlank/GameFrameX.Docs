# 다운로드 우선순위 및 동시 에이전트 수 설정

이 작업 페이지에서는 다운로드 작업에 **우선순위**를 설정하는 방법과, 컴포넌트의 **다운로드 에이전트(동시 코루틴) 수**를 조정하여 동시에 다운로드되는 작업 수의 상한을 제어하는 방법을 설명합니다.

## 사전 조건

- `GameFrameX.Download.Runtime`을 임포트하고 씬에 `DownloadComponent`가 추가되어 있습니다(메뉴: GameFrameX / Download).
- 대상 다운로드 작업의 로컬 저장 경로(`downloadPath`)와 원격 주소(`downloadUri`)를 알고 있습니다.

## 작업 단계

### 1. 단일 작업의 우선순위 설정

`DownloadComponent.AddDownload`는 `priority` 매개변수(`int`, 값이 클수록 우선순위가 높음, 기본값 `0`)를 받는 여러 오버로드를 제공합니다. 가장 자주 사용되는 두 가지는 다음과 같습니다:

```csharp
using GameFrameX.Download.Runtime;

// 우선순위만 지정
int serialId = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, priority: 100);

// tag와 우선순위를 동시에 지정
int serialId2 = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, tag: "asset-bundle", priority: 100);
```

소스 코드:

```csharp
// Runtime/Download/DownloadComponent.cs
private const int DefaultPriority = 0;
...
public int AddDownload(string downloadPath, string downloadUri, int priority)
{
    return AddDownload(downloadPath, downloadUri, null, priority, null);
}

public int AddDownload(string downloadPath, string downloadUri, string tag, int priority)
{
    return AddDownload(downloadPath, downloadUri, tag, priority, null);
}
```

### 2. 동시 에이전트 수 구성

동시 다운로드 능력은 `DownloadComponent.m_DownloadAgentHelperCount`에 의해 결정되며, 기본값은 `3`입니다. 이는 동시에 최대 3개의 다운로드 코루틴이 작동함을 의미합니다. Inspector에서 조정하거나, 코드를 통해 런타임에 확장할 수 있습니다:

- **Inspector**: 컴포넌트를 추가한 후 Inspector에서 `Download Agent Helper Count` 필드(`m_DownloadAgentHelperCount`에 해당)를 직접 수정합니다. 컴포넌트가 `Start()`될 때 이 값에 따라 에이전트가 한 번에 생성됩니다.
- **런타임 시 추가**: 동적으로 늘려야 하는 경우, 컴포넌트의 내부 진입점을 계속 호출하거나 `DownloadAgentHelperBase` 기반의 확장을 직접 구현할 수 있습니다([DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs) 참조).

소스 코드(에이전트 생성):

```csharp
// Runtime/Download/DownloadComponent.cs
[SerializeField] private int m_DownloadAgentHelperCount = 3;
...
private void Start()
{
    ...
    for (int i = 0; i < m_DownloadAgentHelperCount; i++)
    {
        AddDownloadAgentHelper(i);
    }
}
```

출처: [DownloadComponent.cs#L60-L215](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60-L215)

### 3. 런타임 중 에이전트 사용 현황 확인

컴포넌트는 다음과 같은 읽기 전용 속성을 제공하며, 디버그 HUD에서 실시간으로 표시할 수 있습니다:

| 속성 | 의미 |
|------|------|
| `TotalAgentCount` | 생성된 다운로드 에이전트 총 개수 |
| `FreeAgentCount` | 현재 유휴 상태인 다운로드 에이전트 수 |
| `WorkingAgentCount` | 작업 중인 다운로드 에이전트 수 |
| `WaitingTaskCount` | 에이전트가 유휴 상태가 되기를 기다리는 작업 수 |

소스 코드:

```csharp
// Runtime/Download/DownloadComponent.cs
public int TotalAgentCount   { get { return m_DownloadManager.TotalAgentCount; } }
public int FreeAgentCount    { get { return m_DownloadManager.FreeAgentCount; } }
public int WorkingAgentCount { get { return m_DownloadManager.WorkingAgentCount; } }
public int WaitingTaskCount  { get { return m_DownloadManager.WaitingTaskCount; } }
```

출처: [DownloadComponent.cs#L78-L105](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L78-L105)

## 일반적인 변형

- **핵심 리소스 우선**: 첫 화면 리소스에는 높은 `priority`(예: `100`)를 사용하고, 백그라운드 사전 다운로드에는 `0` 또는 음수를 사용합니다.
- **일시 중지 및 재개**: `DownloadComponent.Paused = true/false`를 통해 새 작업 배포를 일시적으로 중단할 수 있으며, 에이전트는 중단되지 않습니다.
- **`m_DownloadAgentHelperCount` 수정의 즉시 적용**: 값이 커지는 경우에만 컴포넌트 시작 시 모든 에이전트가 미리 생성되며, 실행 중 값을 줄여도 기존 에이전트는 파괴되지 않으므로 커스텀 로직과 결합하여 회수해야 합니다.

## 일반적인 오류

- **"동시 코루틴"과 "동시 스레드"의 혼동**: 다운로드 에이전트는 `UnityWebRequest` 코루틴으로, 이 값은 동시에 수행되는 HTTP 요청 수만 제어하며 스레드와는 무관합니다. WebGL 등 제한이 있는 플랫폼에서는 너무 크게 설정하지 마세요.
- **작업이 시작되지 않고 막힘**: `WaitingTaskCount`가 계속 증가하는데 `FreeAgentCount`가 계속 0이면 동시 처리 수가 너무 적거나 작업의 네트워크가 느리다는 뜻입니다. `m_DownloadAgentHelperCount`를 적절히 높이세요.
- **우선순위 미지정 시 높은 우선순위라고 간주함**: `DefaultPriority = 0`이므로, 다른 작업에 음수 값을 지정하면 "기본" 작업이 오히려 뒤로 밀리게 됩니다.

## 배경(선택 사항)

다운로드 관리자는 내부적으로 `TaskPool<DownloadTask>`를 사용하여 작업을 스케줄링합니다(`[DownloadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs)`). 우선순위가 높은 작업이 유휴 에이전트를 먼저 할당받아 네트워크 대역폭의 점유 순서를 제어합니다.
