# Subscribe to Download Events (Start/Progress/Success/Failure)

By subscribing to the four events `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` via `EventComponent`, you can receive callbacks at any stage of a download task's lifecycle, driving UI progress bars, notification messages, and failure retry logic.

## Prerequisites

- The `com.gameframex.unity.download` package is installed, and the `DownloadComponent` is attached to `GameEntry`.
- GameFrameX's `EventComponent` is enabled in the project (`DownloadComponent` dispatches all download events through it).
- A valid local save path and remote download URL are available.

## Steps

1. Get the `DownloadComponent` and `EventComponent` instances:

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   var eventComponent    = GameEntry.GetComponent<EventComponent>();
   ```

2. Subscribe to the four events via `EventComponent.Subscribe`; the callback signature is fixed as `void Handler(object sender, GameEventArgs e)`:

   ```csharp
   eventComponent.Subscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Subscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

3. Add a download task and record the returned `serialId`, which is used in the callbacks to distinguish which download it is:

   ```csharp
   int serialId = downloadComponent.AddDownload(
       "/本地保存路径/file.zip",      // downloadPath
       "https://example.com/file.zip" // downloadUri
   );
   ```

4. In the four callbacks, cast `GameEventArgs` to the corresponding type and read the fields:

   ```csharp
   void OnDownloadStart(object sender, GameEventArgs e)
   {
       var args = (DownloadStartEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadUpdate(object sender, GameEventArgs e)
   {
       var args = (DownloadUpdateEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadSuccess(object sender, GameEventArgs e)
   {
       var args = (DownloadSuccessEventArgs)e;
       if (args.SerialId == serialId)
       {
           // Download complete: args.DownloadPath / args.DownloadUri / args.CurrentLength / args.UserData
       }
   }

   void OnDownloadFailure(object sender, GameEventArgs e)
   {
       var args = (DownloadFailureEventArgs)e;
       Debug.LogError($"下载失败：{args.ErrorMessage}");
   }
   ```

5. Remember to `Unsubscribe` when you are done, to avoid memory leaks and accidental triggering:

   ```csharp
   eventComponent.Unsubscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Unsubscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Unsubscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

## Common Variants

- **Filter by SerialId**: A single `DownloadComponent` may run multiple tasks concurrently; use `args.SerialId == serialId` in the callback to distinguish which download it is.
- **Tasks with UserData**: An overload of `AddDownload` lets you attach `userData`, and all four event args pass it back unchanged, making it easy to carry business context into the callbacks.
- **Only need the final result**: If you don't want to write four callbacks, you can use `await downloadComponent.Download(...)` instead; see the "Asynchronous Usage" section of the README.

## Common Mistakes

- **Wrong EventId**: You must use the `XxxEventArgs.EventId` constants rather than assembling the string yourself. In the source code, all four `EventId`s are `typeof(XxxEventArgs).FullName`; getting this wrong means the subscription will not receive the events.
- **Callback fires but the SerialId doesn't match**: When downloading concurrently, you failed to filter by `args.SerialId` in the callback and mistook another task's result for your own.
- **Forgetting to `Unsubscribe`**: If you don't unsubscribe after a script is destroyed or a scene is switched, the callbacks are still held by the old instance, which can easily cause memory leaks or duplicate triggers.
- **Getting the legacy event chain when using `WWWDownloadAgentHelper`**: The four `DownloadXxxEventArgs` are the unified events at the `DownloadComponent` layer and differ from the events of the underlying `DownloadAgentHelper`; for UI progress, subscribe to the former and do not subscribe directly to Helper-layer events.

## Background (Optional)

All four `DownloadXxxEventArgs` inherit from `GameFrameX.Event.Runtime.GameEventArgs` and are dispatched by `DownloadComponent` via `EventComponent.Fire(this, ...)` as its internal state machine transitions: Start is dispatched after `AddDownload`, Update is dispatched during the download process, and finally Success or Failure is dispatched. The event mechanism allows callers to receive asynchronous notifications without holding a returned object from `DownloadComponent`.
