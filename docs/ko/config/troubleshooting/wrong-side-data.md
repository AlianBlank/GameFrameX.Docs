# 클라이언트/서버 데이터가 분리되지 않을 때 어떻게 해야 하나요

다음과 같은 상황에 해당한다면: 분명히 클라이언트용으로만 만들려던 테이블이 서버에서도 생성되었거나, 서버용으로만 만들려던 테이블을 클라이언트도 받았거나, 파일명 접두사를 변경했는데도 양쪽의 코드/데이터가 분리되지 않는 경우 — 이는 모두 「클라이언트/서버 데이터 그룹화가 적용되지 않은」 전형적인 증상입니다. 이 페이지에서 빠르게 원인을 파악하고 수정할 수 있습니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 클라이언트용으로만 만들려던 테이블이 서버에서도 생성됨(반대의 경우도 마찬가지) | Excel 파일명에 그룹 표시가 없어 기본적으로 두 그룹 모두 생성됨 | 파일명에 `-c-`(클라이언트 전용) 또는 `-s-`(서버 전용) 그룹 세그먼트 추가 |
| 그룹 표시를 추가했는데도 여전히 양쪽 모두 생성됨 | `luban.conf`의 `groups` 설정에서 `c`, `s` 모두 `default: true`로 표시되어 있고, 파일명에서 그룹이 파싱되지 않음 | 파일명 세그먼트는 반드시 `<字母>-<英文名>-<分组>-<中文名>.xlsx` 형식이어야 하며, 그룹은 `c` 또는 `s`만 가능 |
| 그룹을 변경한 후에도 이전 생성 코드가 남아 있음 | 파일명만 변경하고 생성 스크립트를 다시 실행하지 않음 | `gen-client-*` 및 `gen-server-*` 스크립트 재실행 |
| 클라이언트/서버 모두 실행되지만 한쪽 엔드에서만 사용하려는 필드가 다른 쪽에도 나타남 | 필드가 엔드별로 그룹화되지 않음(Excel에 표시 없음), 도구는 기본적으로 모든 엔드에 출력 | `__tables__.xlsx` 또는 해당 Bean에서 필드에 엔드 그룹화 추가 |

## 수정 단계

### 1. 파일명에 그룹 표시 추가

파일명 형식: `字母-英文名-分组-中文名.xlsx`. 그룹 세그먼트는 `c`(클라이언트 전용) 또는 `s`(서버 전용)만 가능하며, 그룹을 추가하지 않으면 양쪽 엔드 모두에 적용됨을 의미합니다.

| 파일명 | 효과 |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | 클라이언트, 서버 모두 사용(기본값) |
| `D-ItemConfig-c-道具表.xlsx` | 클라이언트만 사용 |
| `D-ItemConfig-s-道具表.xlsx` | 서버만 사용 |

예시 파일 경로: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

> `c` = client, `s` = server. 그룹명을 중국어로 쓰거나 `cs`/`sc` 같은 두 글자 조합을 쓰지 마세요. 도구는 `c`와 `s`만 인식합니다.

### 2. luban.conf의 groups 설정 확인

`luban.conf`의 `groups` 노드는 두 개의 그룹 `c`와 `s`를 정의하며, 둘 다 `default: true`로 설정되어 있어 **그룹이 표시되지 않은** 파일은 양쪽 엔드 모두에서 생성됩니다:

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

`targets` 노드에서 `server`는 `s` 그룹만, `client`는 `c` 그룹만, `all`은 두 그룹의 합집합을 사용합니다:

```json
"targets": [
    { "name": "server", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "groups": ["c","s"], "topModule": "cfg" }
]
```

전체 설정은 [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L61)를 참고하세요.

즉, **파일명 그룹화만으로는 부족하며, 해당하는 생성 스크립트를 각각 실행해야만** 비로소 해당 엔드에 실제로 반영됩니다.

### 3. 생성 스크립트 각각 실행

- 클라이언트: `gen-client-json.bat` 더블 클릭(Mac/Linux: `sh gen-client-json.sh`)
- 서버: `gen-server-json.bat` 더블 클릭(Mac/Linux: `sh gen-server-json.sh`)

스크립트 설명은 [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L265-L285)를 참고하세요.

### 4. 필드 수준의 엔드별 그룹화(고급)

같은 테이블에서 특정 필드를 한쪽 엔드에서만 사용하려면(예: 가격은 서버에만, UI 안내는 클라이언트에만 포함), `__tables__.xlsx` / `__beans__.xlsx`에서 해당 필드에 `c` 또는 `s` 엔드 그룹 표시를 추가해야 합니다. 일반 `int`, `string` 필드는 기본적으로 양쪽 엔드 모두에 포함되며, 도구가 설정에 따라 자동으로 잘라냅니다.

## 검증

위의 1~3 단계를 완료한 후, 아래 방법으로 그룹화가 적용되었는지 확인하세요:

1. 출력 디렉터리 확인:
   - 클라이언트 코드/데이터: `Unity/Assets/Bundles/Config`(데이터), `Unity/Assets/Hotfix/Config/Generate`(코드)
   - 서버 코드/데이터: `Server/GameFrameX.Config/Json`(데이터), `Server/GameFrameX.Config/Config`(코드)
2. 나타나지 않아야 할 엔드의 디렉터리에서 **테이블 이름을 검색**하세요(예: `TbItemConfig`). 검색되지 않으면 그룹화가 적용된 것입니다.
3. 코드에서 접근: 클라이언트는 `tables.TbXxx.Get(id)`를 사용하고, 서버에서도 동일하게 호출하지만 코드 네임스페이스가 다릅니다(`Hotfix.Config` vs `GameFrameX.Config`). 네임스페이스가 서로 다르면 그룹화가 올바르게 적용된 것입니다.
