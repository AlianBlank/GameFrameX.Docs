# 在 Android 上無法讀取 StreamingAssets 時怎麼辦（檔名 / 壓縮 / 字元）

在 Android 裝置上，此函式庫並不會把 APK 內的 `assets/` 當成一般資料夾來讀取，而是讀取 APK 的 ZIP End-of-Central-Directory 與 Central Directory，並透過 `offset/size` 直接開啟 `FileStream` 切片。因此「無法讀取」幾乎都源自：**路徑不相符**、**APK 項目被壓縮**、**檔名含特殊字元**，或**被封裝成分割 APK / 修補包而未命中 `base.apk`**。本文提供快速診斷表與對應的修復步驟。

## 快速診斷

| 症狀 | 直接原因 | 修復入口 |
|------|----------|----------|
| `TryGetInfo` 回傳 `false` / `OpenRead` 擲出 `FileNotFoundException` | 傳入的相對路徑與 APK 內 `assets/` 下的項目不相符（大小寫、空格、`/` 或 `\` 格式） | [修正路徑大小寫與分隔符號](#fix-path-case-and-separator) |
| `Debug.Assert` 觸發：`CompressedSize != UncompressedSize` | 建置 APK 時啟用了壓縮，或某個外掛/Gradle 重新壓縮了 `assets` | [強制 APK assets 不壓縮](#force-apk-assets-to-be-uncompressed) |
| `paths duplicate! <file>` 執行時期例外 | 同時建置了主 APK 與分割/修補包，且兩者的 `assets` 下存在同名項目 | [處理分割 APK / OBB 修補包](#handle-split-apk--obb-patch) |
| 中文/日文檔名無法開啟，或找不到大小寫異常的資源 | ZIP 標準要求檔名只能是 ASCII，或須設定 UTF-8 旗標；APK 預設不會設定 UTF-8 旗標 | [統一檔案命名規範](#unify-file-naming-conventions) |
| 安裝 64 位元外掛或升級 Mono 後，在 `stream.CanSeek == false` 處崩潰，或 APK 路徑無效 | `dataPath` 未正確解析為 `base.apk`（例如位於分割子包中） | [確認 APK 主包路徑](#confirm-apk-main-package-path) |

## 修復步驟

### 修正路徑大小寫與分隔符號

在 `BlankReadAssets.ApkImpl.TryGetInfo` 內部會呼叫 `PathUtil.NormalizeRelativePath`，並以 `StringComparer.OrdinalIgnoreCase` 對 `s_paths` 執行二分搜尋。因此路徑必須與打包進 APK 的實際檔名完全一致，且必須使用正斜線 `/`。

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L58-L84
public static bool TryGetInfo(string path, out ReadInfo info)
{
    path = PathUtil.NormalizeRelativePath(path);
    info = new ReadInfo();

    var index = Array.BinarySearch(s_paths, path, StringComparer.OrdinalIgnoreCase);
    if ( index < 0 )
    {
        return false;
    }
    ...
}
```

來源：[Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L58-L84)

操作：

1. 取得實際打包出來的 APK（位於 `Library/` 或 `Build/` 目錄），使用 `unzip -l your.apk | head` 檢查 `assets/` 下各項目的確切大小寫。
2. 程式碼中統一使用 `/`；不要混用 `\`，也不要包含 `StreamingAssets` 前綴或 `jar:file://...`。
3. 資源名稱應只使用 `A–Z`、`a–z`、`0–9`、`_`、`-`、`.` 與單層 `/`。

### 強制 APK assets 不壓縮

此函式庫在定位項目時會進行如下斷言（開發期間會警告）：

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L325-L340（節選）
while ( ZipCentralDirectoryFileHeader.TryReadBlock(reader, out header) )
{
    if ( header.CompressedSize != header.UncompressedSize )
    {
#if UNITY_ASSERTIONS
        // 未壓縮 -> 切片讀取才正確
#endif
        continue;
    }
    ...
}
```

來源：[Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L325-L340)

後果：被壓縮的項目會被跳過，表現出來就像「無法讀取」。修復方式：

1. Unity：Player Settings → Publishing Settings → 不應勾選 **Build APK(s) without compression**，但要確保 Gradle/AAPT 不會再次壓縮。
2. 若使用自訂 Gradle（主模板 `unityLibrary` 的 `build.gradle`），請在 `android` 節點下加入以下內容，讓 `assets/**/*.bundle` 與 `StreamingAssets/**` 等熱更新目錄保持未壓縮：

```groovy
android {
    aaptOptions {
        noCompress 'bundle','unitydefaultresources','StreamingAssets','bin','config.json'
    }
}
```

3. 重新打包後，使用 `unzip -lv your.apk | grep -E "Method|---"` 確認熱更新檔案的 `Method` 欄位為 `Stored`（而非 `Defl:N`）。

### 處理分割 APK / OBB 修補包

Initialize 會檢查 `dataPath` 的結尾，以決定要走修補目錄還是回退到 `base.apk`：

```csharp
// Runtime/BlankReadAssets.ApkImpl.cs#L27-L56
public static void Initialize(string dataPath, string streamingAssetsPath)
{
    s_root = dataPath;
    if (dataPath.EndsWith("pram-shadow-files"))
    {
        Debug.Assert(streamingAssetsPath.EndsWith("pram-shadow-files/assets"));
        GetStreamingAssetsFromPatch(dataPath, paths, parts);
    }
    else
    {
        GetStreamingAssetsInfoFromJar(s_root, paths, parts);
        if (paths.Count == 0 && !Application.isEditor && Path.GetFileName(dataPath) != "base.apk")
        {
            var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
            if (File.Exists(newDataPath))
            {
                s_root = newDataPath;
                GetStreamingAssetsInfoFromJar(newDataPath, paths, parts);
            }
        }
    }
}
```

來源：[Runtime/BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

如果您的應用程式部署了多個分割包，您需要：

1. 將實際的 `assets` 集中到 `base.apk`，避免分割包中殘留 `assets/` 子目錄。
2. 若使用 Play Asset Delivery / 自訂修補目錄，請確保呼叫端傳入的 `dataPath` 為 `.../pram-shadow-files`（此時邏輯分支會走 `GetStreamingAssetsFromPatch`）。

### 統一檔案命名規範

ZIP Central Directory 中的檔名長度受 `[ushort]` 限制，而 Unicode 編碼的處理取決於 General Purpose Bit Flag 的第 11 位元（UTF-8）。有些 Android 工具鏈不會設定此旗標，導致含多位元組字元的檔名解析失敗。操作：

1. 資源名稱只使用 ASCII：`game_config`、`map_01.bin`、`lang_zh.json`。
2. 禁用 `+`、`%`、空格與表情符號。
3. 若必須支援多語言資源，請改用目錄區分（`assets/i18n/zh/...`），而不要把語言寫進檔名。

### 確認 APK 主包路徑

在分割情境下，Unity 給出的 `Application.streamingAssetsPath` 並不會指向 `base.apk`。Initialize 會自動回退：

```csharp
var newDataPath = Path.GetDirectoryName(dataPath) + "/base.apk";
if (File.Exists(newDataPath)) { s_root = newDataPath; }
```

（來源同上）但如果專案做了 App Bundle 合併或自訂 aapt，把 `assets` 導向非 `base.apk` 的檔案，回退就會失效。修復方式：

1. 在裝置上使用 `adb shell pm path <your.package>` 找出當前套件 `base.apk` 的實際路徑。
2. 與 `Application.streamingAssetsPath` 比對。若不一致，檢查 Gradle/AGP 是否啟用了 `--split-by-abi` / `--split-resources`，並避免連 `assets` 也被分割。

## 驗證

1. **離線檢查清單**：對產生的 APK 執行 `unzip -l`，列出 `assets/` 下的前 50 個項目；與程式碼中傳入的相對路徑逐一比對（大小寫、分隔符號、`.bin` 後綴）。
2. **Editor 與裝置同源**：`BlankReadAssets.LooseFilesImpl`（非 Android）與 `BlankReadAssets.ApkImpl`（Android）都遵循同一套 `PathUtil`，因此先讓 `OpenRead` 在 Editor 中正常運作，再到裝置上驗證。
3. **開啟讀取煙霧測試**：

```csharp
using (var s = BlankReadAssets.OpenRead("config/game_config.json"))
{
    Debug.Assert(s.Length > 0, "size == 0, indicates APK content was compressed or path is wrong");
}
```

4. **實機日誌**：把上面的 `Debug.Assert` 換成 `Debug.LogError` 以查看完整堆疊追蹤；如果出現 `Method != Stored`，請回到[強制 APK assets 不壓縮](#force-apk-assets-to-be-uncompressed)。

## 背景（選讀）

在 Android 上，Unity 會將整個 `Assets/StreamingAssets/` 打包進 APK 的 `assets/` 區段；索引位於 ZIP 容器結尾，因此不需要像 iOS/Jar 那樣使用 `UnityWebRequest` 去請求 `jar:file://...`。此函式庫直接使用 `File.OpenRead(apkPath)` + `SubReadOnlyStream`，走零複製切片路徑，因此「是否壓縮」與「路徑是否正確」將直接決定是讀不到還是讀錯。
