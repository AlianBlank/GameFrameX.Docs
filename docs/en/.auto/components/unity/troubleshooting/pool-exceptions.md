# What to Do When Object Pool and Reference Pool Exceptions Occur

When using `ObjectPool` / `ReferencePool`, if you encounter `GameFrameworkException` or object state exceptions, follow the diagnostic table on this page to troubleshoot one by one.

## Quick Diagnosis

| Exception Message (Original) | Trigger Location | Common Cause | One-Line Fix |
|---|---|---|---|
| `Object pool manager is invalid.` | [ObjectPoolComponent.Awake](/Runtime/ObjectPool/ObjectPoolComponent.cs#L61-L72) | No `ObjectPoolComponent` attached in the scene, or the component `componentType` is misconfigured | Add `ObjectPoolComponent` to the scene, check the `componentType` field |
| `Object type is invalid.` | [ObjectPoolManager.cs#L132](/Runtime/ObjectPool/ObjectPoolManager.cs#L132-L137)、[#L166](/Runtime/ObjectPool/ObjectPoolManager.cs#L166-L171) | The passed `Type` is `null` or not a subclass of `ObjectBase` | Pass a non-null type that actually inherits `ObjectBase` |
| `Object type '{0}' is invalid.` | [ObjectPoolManager.cs#L137](/Runtime/ObjectPool/ObjectPoolManager.cs#L132-L137) | The generic `T` does not inherit `ObjectBase`, or the type is an abstract class/interface | Make `T : ObjectBase` and a concrete class |
| `Condition is invalid.` | [ObjectPoolManager.cs#L187](/Runtime/ObjectPool/ObjectPoolManager.cs#L185-L189) | `Predicate<ObjectPoolBase>` was passed `null` | Do not pass a `null` condition; pass an empty predicate that always returns `false` |
| `Object is not initialized.` | [ObjectPoolManager.Object.cs#L68](/Runtime/ObjectPool/ObjectPoolManager.Object.cs#L66-L70)、[#L84](/Runtime/ObjectPool/ObjectPoolManager.Object.cs#L82-L86)、[#L92](/Runtime/ObjectPool/ObjectPoolManager.Object.cs#L90-L94) | Object was Released multiple times, or Acquired again after Release but not returned | Strictly ensure `Acquire` / `Release` correspond one-to-one |
| `Reference is invalid.` | [ReferencePool.cs#L161](/Runtime/Base/ReferencePool/ReferencePool.cs#L157-L167) | `Release(null)` or a reference that has already been Disposed | Caller should null-check before Release |
| `Reference type '{0}' is invalid.` | [ReferencePool.cs](/Runtime/Base/ReferencePool/ReferencePool.cs) `InternalCheckReferenceType` | The type does not implement `IReference` or lacks a parameterless constructor | Make the type implement `IReference` and keep the `new()` constraint |
| Type mismatch on reference return / duplicate recycling | [ReferencePool.ReferenceCollection.cs](/Runtime/Base/ReferencePool/ReferencePool.ReferenceCollection.cs) Release path | In strict check mode, a type `A` object was returned to the type `B` pool | Set `ReferencePool.EnableStrictCheck = true` to immediately locate the problem object |

## Repair Steps

### 1. Startup Error `Object pool manager is invalid.`

This exception is thrown at scene startup, indicating that the `IObjectPoolManager` module is not registered.

1. Confirm that there is a unique `ObjectPoolComponent` component in the scene (menu `Add Component → GameFrameX → Object Pool`).
2. In the Inspector, confirm that the `Component Type` field points to the default implementation `GameFrameX.ObjectPool.ObjectPoolManager` (generally no need to modify).
3. Re-enter play mode and confirm that `m_ObjectPoolManager` is no longer `null`.

### 2. Calling `CreateObjectPool` / `GetObjectPool` Throws `Object type is invalid.`

This indicates that the passed `Type` is not accepted by the framework.

1. Check the code: `objectType` should not be `null`, and must be a non-abstract subclass of `ObjectBase`.
2. Prefer using the generic overload `GetObjectPool<T>()`, which lets the compiler guarantee `T : ObjectBase`.
3. If reflecting by string at runtime, first call `Type.GetType("MyNamespace.MyObj")`, and validate `typeof(ObjectBase).IsAssignableFrom(t)`.

### 3. Business Throws `Object is not initialized.`

`ObjectPoolManager.Object.cs` throws this exception in the strict check path if an object is repeatedly Acquired/Released.

1. Search all `Release` calls for the same variable in the code to ensure an object is Released only once after being taken from the pool.
2. Investigate coroutines / async callbacks: if Release is called after `await` / `yield return`, confirm the object was not Released early.
3. Keep strict checks in development builds; you can reduce check overhead in release builds.

### 4. Reference Pool `Reference is invalid.`

[ReferencePool.Release](/Runtime/Base/ReferencePool/ReferencePool.cs#L157-L167) immediately throws when passed `null`.

1. Null-check before calling Release: `if (obj != null) ReferencePool.Release(obj);`
2. For objects that may have been Disposed, uniformly call `ReferencePool.Release(this)` in `Dispose` first to avoid dangling references.

### 5. Reference Type Validation Failure / Duplicate Recycling

`ReferencePool.Acquire(Type)` and `Release(IReference)` internally call `InternalCheckReferenceType` to validate that the type implements `IReference` and has an accessible constructor.

1. Make the data class `class MyData : IReference`, implement `void Clear()`, and keep a public parameterless constructor.
2. If you suspect that a type `A` object was incorrectly returned to the type `B` pool somewhere, set the `m_EnableStrictCheck` of [ReferencePoolComponent](/Runtime/ReferencePool/ReferencePoolComponent.cs) to `AlwaysEnable` (or `OnlyEnableWhenDevelopment`). The framework will immediately throw an exception on out-of-bounds, making it easy to locate.
3. After troubleshooting, switch back to `OnlyEnableInEditor` or `Disable` to avoid release build performance loss.

### 6. `Condition is invalid.`

A `null` predicate was passed when using `HasObjectPool(Predicate<…>)` or `GetObjectPools(Predicate<…>)`.

1. Do not pass `null`; if you want to get all, use `GetAllObjectPools()` instead.
2. If you want "no match", pass `_ => false`.

## Verification

- The startup scene no longer throws `GameFrameworkException`, and `Log.Fatal` / `Log.Error` in the Console is empty.
- Open `ObjectPoolComponent` / `ReferencePoolComponent` in the Inspector and confirm that the runtime `Count` matches expectations, with no object leak continuously growing.
- Run a complete object lifecycle (Create → Acquire → Use → Release → Pool Recycle) without any `Object is not initialized.` or `Reference is invalid.` being thrown.
- After disabling `EnableStrictCheck`, package the release build again and run a stress test to confirm that GC allocation is significantly lower than when the object pool is not enabled.
