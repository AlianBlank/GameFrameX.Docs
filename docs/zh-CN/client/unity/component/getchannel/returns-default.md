# 获取渠道总是返回 default 怎么办

当 `BlankGetChannel.GetChannelName()` 在目标平台上读不到渠道配置时,会返回参数 `defaultValue` 的默认值 `"default"`。这个现象几乎都源于:当前平台的配置源里没有 `channel` 键、键名不匹配,或首次读取的结果被静态缓存住了。API 签名如下:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L97-L98)

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| Editor / PC / WebGL / 主机上返回 `default` | `Assets/Resources/application_config.txt` 不存在,或没有 `channel=` 行 | 在 `Assets/Resources/` 下创建 `application_config.txt` 并写入 `channel=xxx` |
| 新建/修改了 `application_config.txt`,仍返回 `default` | 静态缓存 `ChannelCache` 已把 `default` 缓存,本会话内不再重读 | 退出 Play 模式触发 Domain Reload,或重启 Unity 后再测 |
| Android 真机返回 `default` | `<meta-data android:name="channel" .../>` 没写在主启动 Activity 内,或键名不是 `channel` | 把 `meta-data` 移到 AndroidManifest.xml 的主启动 `<activity>` 标签内部 |
| iOS 真机返回 `default` | 打包后处理脚本在 Info.plist 缺少 `channel` 键时自动写入了 `"default"` | 在打包前/更高优先级的后处理中预先写入 `channel` 键 |
| iOS 上返回 `unknown` 而不是 `default` | Info.plist 中没有该键,iOS 原生实现返回 `"unknown"` | 在 Info.plist 中补上 `channel` 键 |
| 取 `sub_channel` 等自定义键返回 `default` | 传入的 `channelKey` 与配置文件里的键名不一致 | 核对键名后按正确键写入配置 |

## 修复步骤

### 1. Editor / PC / WebGL:检查 application_config.txt

这些平台通过 `Resources.Load<TextAsset>("application_config")` 读取,文件必须位于 `Assets/Resources/application_config.txt`,每行一个 `键=值`:

```text
channel=editor_cn_test
sub_channel=test
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L106-L121)

注意解析规则(来自源码 `L110-L119`):

- 按 `\n` / `\r` / `\r\n` 换行,空行被忽略;
- 每行按 `=` 分割且**必须多于 1 段**,形如 `channel`(没有 `=`)的行会被整行丢弃;
- 键与值两端的空白会被 `Trim()`,写成 `channel = abc` 也能读到 `abc`。

### 2. 排除静态缓存的干扰

结果会被写入静态字典 `ChannelCache`,同一会话内第二次调用直接走缓存。尤其注意:`textAsset == null`(文件不存在)时会把 `default` 写入缓存,之后即使补上文件也不会重读:

```csharp
if (ChannelCache.TryGetValue(channelKey, out var value))
{
    return value;
}
// ...
var textAsset = Resources.Load<TextAsset>("application_config");
if (textAsset != null)
{
    // 解析并填充 ChannelCache
}
else
{
    ChannelCache[channelKey] = defaultValue;  // 找不到文件时缓存 default
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L100-L125)

在 Editor 里验证配置是否生效前,先退出 Play 模式(触发 Domain Reload)或重启 Unity,再进入 Play 测试。Android / iOS 侧同理:修改清单或 plist 后需要重新打包,进程内不会自动刷新。

### 3. Android:把 meta-data 放进主启动 Activity

Android 通过 JNI 调用 `com.alianhome.getchannel.MainActivity` 的静态方法 `GetChannel` 读取,键名默认为 `channel`:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

在 `AndroidManifest.xml` 的**主启动 Activity 标签内部**(而不是 `<application>` 下)添加:

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

检查点:

- 键名必须是 `android:name="channel"`,与 C# 侧传入的 `channelKey` 一致;要取其他键,调用时传 `GetChannelName("你的键名")`。
- 自定义清单方式(自定义 `Assets/Plugins/Android/AndroidManifest.xml`)要与 Unity 当前使用的模板匹配,确认打进 APK 后仍在主 Activity 内。

### 4. iOS / tvOS / visionOS:检查 Info.plist

iOS 侧通过 `DllImport("__Internal")` 调用原生 `getChannelName`,从 Info.plist 读取 `channel` 键:

```csharp
[DllImport("__Internal")]
private static extern string getChannelName(string channelKey);
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L47-L48)

原生实现找不到键时返回 `"unknown"`(而不是 C# 侧的 `default`):

```objc
NSString * channel_value =  [dict objectForKey:channel_name_String];
if (channel_value != nil) {
    return StringToCharArray(channel_value);
}
channel_value = @"unknown";
return StringToCharArray(channel_value);
```

Source: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

包内 `channel` 键由 `PostProcessBuild(99)` 的打包后处理自动写入。它**只在该键不存在时**才写入,且写入的值固定为 `"default"`,所以直接用本包默认流程打的 iOS 包会得到 `default`,这是设计使然:

```csharp
const string channelKey = "channel";
const string channelValue = "default";

string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

要拿到真实渠道,任选其一:

1. 写一个 `callbackOrder` 小于 `99` 的 `PostProcessBuild` 处理器,先在 Info.plist 写入真实渠道,本包检测到已存在即跳过(日志输出 `已有渠道,跳过设置=>`);
2. 或在打包产物上直接改 Info.plist 再签名。

Info.plist 中应为 String 类型:

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)
