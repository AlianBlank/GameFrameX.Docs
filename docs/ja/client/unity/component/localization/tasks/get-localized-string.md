# ローカライズ文字列を取得する方法（1～16 個の引数によるフォーマットを含む）

`LocalizationComponent.GetString` シリーズのオーバーロードを使用すると、辞書の主キーでローカライズ文字列を取得できます。フォーマットが必要な場合は、辞書値に標準 .NET プレースホルダー（`{0}`、`{1}` …）を記述し、対応するオーバーロードに 1～16 個の引数を渡します。key が存在しない場合は `<NoKey>{key}` が返され、プレースホルダーと引数が一致しない場合、結果は `<Error>` で始まります。

## 前提条件

- プロジェクトに `com.gameframex.unity.localization` パッケージがインストール済みであり、シーン内の `LocalizationComponent` の初期化（辞書の読み込み）が完了していること。
- スクリプトで名前空間 `GameFrameX.Localization.Runtime` を using し、`GameEntry` を通じてコンポーネントを取得します：

```csharp
using GameFrameX.Localization.Runtime;

// 標準的な方法：GameEntry を通じて取得
var localization = GameEntry.GetComponent<LocalizationComponent>();
```

## 操作手順

1. **コンポーネント参照を取得**（上記のコードのように、通常は `Start` 内でキャッシュします）。
2. **単純な取得**：key のみを渡すと、その key に対応する元の翻訳文が返ります：

```csharp
// 単純な key の照会
// key が見つからない場合、"<NoKey>{key}" を返す
string okText = localization.GetString("UI.Button.OK");
string cancelText = localization.GetString("UI.Button.Cancel");

// 取得前に key が存在するか確認
if (localization.HasRawString("UI.Button.Confirm"))
{
    string confirmText = localization.GetString("UI.Button.Confirm");
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L133-L144)

3. **引数付きフォーマット**：辞書値に `{0}`、`{1}` などのプレースホルダーを使用し、呼び出し時に引数を順番に渡します。

```csharp
// 辞書に以下が含まれていると仮定：
// "UI.Message.Welcome" = "Welcome, {0}!"
// "UI.Info.Score"     = "Player {0} scored {1} points at level {2}!"
// "UI.Shop.Buy"       = "Buy {0} x {1} for {2} coins, discount {3:P}, total {4:C}"

// params object[] オーバーロードを使用
string welcome = localization.GetString("UI.Message.Welcome", playerName);

// 型指定されたジェネリックオーバーロードを使用（推奨 —— 値型のボックス化を回避できる）
string info = localization.GetString<string, int, int>("UI.Info.Score", playerName, score, level);

// 型指定された引数は最大 16 個までサポート
string shopMsg = localization.GetString<string, int, int, float, decimal>(
    "UI.Shop.Buy", itemName, quantity, unitPrice, discount, total);
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L150-L165)

4. **任意：元の翻訳文を直接読み取る**。フォーマットを実行したくない場合は `GetRawString` を使用します（key が存在しない場合は `null` を返します）：

```csharp
string rawText = localization.GetRawString("UI.Button.NewButton");
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L173-L192)

コンポーネント上の `GetString` は、`m_LocalizationManager` の同名メソッドへの直接転送であり、実際のシグネチャは以下の通りです：

| オーバーロード | 説明 |
|------|------|
| `public string GetString(string key)` | 引数なしでの取得 |
| `public string GetString(string key, params object[] args)` | 任意個数の引数（object 配列） |
| `public string GetString<T>(string key, T arg)` | 1 個の型指定された引数 |
| `public string GetString<T1, T2>(string key, T1 arg1, T2 arg2)` | 2 個の型指定された引数 |
| `public string GetString<T1, …, T16>(string key, T1 arg1, …, T16 arg16)` | 以降同様に 16 個の型指定された引数まで対応 |

```csharp
[Preserve]
public string GetString(string key)
{
    return m_LocalizationManager.GetString(key);
}

[Preserve]
public string GetString(string key, params object[] args)
{
    return m_LocalizationManager.GetString(key, args);
}

[Preserve]
public string GetString<T>(string key, T arg)
{
    return m_LocalizationManager.GetString(key, arg);
}

[Preserve]
public string GetString<T1, T2>(string key, T1 arg1, T2 arg2)
{
    return m_LocalizationManager.GetString(key, arg1, arg2);
}
```

## よくあるバリエーション

- **言語切り替え後のテキスト更新**：`localization.Language` を切り替えると言語変更イベントがブロードキャストされるため、イベントコールバック内で `GetString` を再度呼び出して UI テキストを更新します。言語切り替えとイベントリスニングの完全な手順については、『実行時の言語を切り替える方法』を参照してください。
- **実行時のエントリ追加/削除**：`AddRawString` で追加（key が既に存在する場合や空の場合は `false` を返す）、`RemoveRawString` で 1 件削除、`RemoveAllRawStrings` で全件クリア、`HasRawString` で存在確認を行います。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 結果が `<NoKey>{key}` 形式になる | 辞書に該当する key が存在しない | まず `HasRawString` で確認する。辞書が読み込まれていること、key のスペルが正しいことを確認する |
| 結果が `<Error>` で始まり診断情報が付随する | フォーマット文字列のプレースホルダーと渡された引数が一致しない | 辞書値の `{0}`、`{1}` … と引数の個数・順序が一致しているか確認する |
| `GetRawString` が `null` を返す | key が存在しない | `<NoKey>` と同様に、key と辞書の読み込み状態を確認する |
| UI に古い言語が表示されたままになる | 言語切り替え後に再取得していない | 言語変更イベントのコールバック内で `GetString` を再度呼び出す |

## 検証

- 引数なしの呼び出し：既知の key（例：`UI.Button.OK`）に対して `GetString` を呼び出すと、戻り値は `<NoKey>...` ではなく、現在の言語の辞書の翻訳文と等しくなるはずです。
- 引数付きの呼び出し：プレースホルダーを含む key（例：`UI.Info.Score` = `"Player {0} scored {1} points at level {2}!"`）に対して `GetString<string, int, int>("UI.Info.Score", playerName, score, level)` を呼び出すと、戻り値はプレースホルダーの置換が完了しており、`<Error>` で始まらないはずです。

## 背景

コンポーネントの `GetString` の各オーバーロードは、内部の `m_LocalizationManager` の同名メソッドへの転送を行うだけです。ジェネリックオーバーロードの意義は、値型の引数（`int`、`float` など）で `object` へのボックス化のオーバーヘッドを回避できることにあり、引数の個数が 16 を超える場合や型が事前に分からない場合は `params object[]` オーバーロードで対応します。フォーマットは標準 .NET の複合フォーマット規則（`{0}`、`{3:P}`、`{4:C}` など）に従うため、複合フォーマット文字列の書き方をそのまま流用できます。
