# 如何使用 AES 加解密

`AesHelper` 提供了基于 AES-GCM 的认证加解密能力：传入明文和密钥即可得到 Base64 密文，再用同一密钥解密即可还原原文。每次加密都会随机生成 Salt 和 Nonce，无需调用方管理。

## 前置条件

- 项目引用 NuGet 包 `GameFrameX.Foundation.Encryption`。
- 目标框架支持 `System.Security.Cryptography.AesGcm`（.NET 5+ / .NET Standard 2.1 平台实现）。
- `using GameFrameX.Foundation.Encryption;` 与 `using System.Text;`。

## 操作步骤

### 1. 字符串加解密（Base64 输出）

```csharp
using GameFrameX.Foundation.Encryption;

string plain = "Hello, World! 这是一个测试字符串。";
string key = "MySecretKey123456";

string cipher = AesHelper.Encrypt(plain, key);
string back = AesHelper.Decrypt(cipher, key);
// back == plain
```

Source: [AesHelper.cs#L111-L124](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/AesHelper.cs#L111-L124)

### 2. 字节数组加解密（用于二进制数据）

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

byte[] data = Encoding.UTF8.GetBytes("任意二进制数据");
byte[] cipherBytes = AesHelper.Encrypt(data, "MySecretKey123456");
byte[] plainBytes = AesHelper.Decrypt(cipherBytes, "MySecretKey123456");
```

Source: [AesHelper.cs#L140-L178](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/AesHelper.cs#L140-L178)

### 3. 加解密后落盘或传输

把 `cipher`（Base64 字符串）或 `cipherBytes`（二进制）存入数据库、配置文件或通过网络发送，接收方用同一密钥调用 `Decrypt` 即可还原。

```csharp
// 伪代码：将密文保存到文件
File.WriteAllText("secret.bin", cipher);

// 伪代码：读取并解密
string read = File.ReadAllText("secret.bin");
string original = AesHelper.Decrypt(read, key);
```

## 常见变体

- **不同长度密钥**：源码使用 PBKDF2(SHA256, 600,000 次) 把任意字符串密钥派生为 32 字节密钥，传入 `"ShortKey"` 到 `"VeryLongKeyThatExceedsNormalLength123456789"` 都能正确加解密。
- **包含 Unicode/Emoji 的明文**：明文按 UTF-8 编码后参与加密，`"🚀🌟💻🎮🔥"` 等 4 字节字符可正常往返。
- **同一明文 + 同一密钥加密两次**：两次结果不同（因为 Salt/Nonce 随机），但两次结果都能解密回原文——这是 AES-GCM 的语义安全特性。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `ArgumentException: Plain text cannot be null or empty` | 明文为 `null` 或 `""` | 加密前检查字符串非空 |
| `ArgumentException: Encryption key cannot be null or empty` | 密钥为空 | 提供长度 ≥ 1 的非空字符串密钥 |
| `ArgumentException: Cipher text byte array is too short to be valid.` | 密文长度小于 45 字节（1+16+12+16 头部） | 确认传入的是 `Encrypt` 的完整输出 |
| `CryptographicException: Unsupported AES payload format version.` | 密文头部版本字节不是 `2` | 升级到当前版本的库，或用旧版本解密 |
| `CryptographicException`（解密时） | 密钥与加密时不一致，或数据被篡改 | 确认加解密使用同一密钥，并校验传输完整性 |

> 加解密调用任一参数为 `null` / 空字符串都会立刻抛出 `ArgumentException`，可在调用前断言或在外层 `try/catch` 中处理。

## 背景（可选）

实现采用 AES-GCM 认证加密：每次随机生成 16 字节 Salt 和 12 字节 Nonce，配合 PBKDF2(SHA256, 600k 次) 把字符串密钥派生为 32 字节会话密钥。输出格式 `Version(1) | Salt(16) | Nonce(12) | Tag(16) | 密文`，Tag 用于完整性校验，篡改或密钥错误会在解密阶段抛出 `CryptographicException`。
