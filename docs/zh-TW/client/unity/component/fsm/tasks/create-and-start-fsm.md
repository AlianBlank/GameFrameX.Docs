# FSM 建立與啟動方式

透過 `FsmComponent` 建立由指定 Owner 持有的有限狀態機，傳入狀態實例後呼叫 `Start<TState>()` 開始輪詢，即可在遊戲中驅動實體行為。本頁面提供從狀態定義到開始執行的完整最小路徑。

## 前置條件

- 必須安裝 `com.gameframex.unity.fsm` 套件。
- 場景中必須存在附加了 `FsmComponent` 的 GameObject(元件帶有 `[GameFrameXAutoComponent(-6000)]`,會在框架啟動時自動註冊)。
- 必須至少定義一個繼承 `FsmState<T>` 的狀態類別(關於狀態定義，請參閱《FsmState 定義方式》)。

## 作業步驟

1. 取得 `FsmComponent` 實例。

   ```csharp
   var fsmComponent = GameEntry.GetComponent<FsmComponent>();
   ```

2. 呼叫 `CreateFsm<T>` 建立狀態機，並傳入 Owner 與所有初始狀態實例。

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
   ```

   `FsmComponent.CreateFsm<T>(T owner, params FsmState<T>[] states)` 的原始碼定義位於 [FsmComponent.cs#L197-L208](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L197-L208),內部會轉發至 `IFsmManager.CreateFsm`。
   針對同一個 Owner,也可以使用帶有 `name` 的多載來建立多個共存的實例：

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm<Player>("Combat", player, new IdleState(), new AttackState());
   ```

3. 呼叫 `Start<TState>()` 讓 FSM 進入第一個狀態。

   ```csharp
   fsm.Start<IdleState>();
   ```

   `Start<TState>()` 會觸發目標狀態的 `OnEnter`,並從下一幀開始每幀呼叫 `OnUpdate`。
   `Start` 介面定義請參閱 [IFsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsm.cs)。

4. 在任意狀態內部透過 `ChangeState<TState>(fsm)` 切換狀態。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

## 常見變化

| 情境 | 呼叫方式 |
|------|----------|
| 同一個 Owner 需要多個獨立的 FSM 時 | 使用 `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` 並以 `name` 區分 |
| 在執行階段新增狀態 | `fsm.AddState(new JumpState())` |
| 在執行階段移除狀態(不可為目前狀態) | `fsm.RemoveState<IdleState>()` |
| 結束目前狀態並重置資料後重新啟動 | `fsm.Reset(); fsm.Start<IdleState>();` |
| 透過 `GameApp` 快速存取(需要 `com.gameframex.unity.entry`) | `IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());` |

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `Log.Fatal("FSM manager is invalid.")` | 在 `Awake` 階段未能取得 `IFsmManager` 實作，通常是框架初始化順序問題 | 確認 `FsmComponent` 已附加到框架根 GameObject,並確保 GameFrameX 框架元件比業務腳本更早初始化 |
| `Start<TState>()` 出現「狀態不存在」錯誤 | 呼叫 `CreateFsm` 時未傳入該狀態，或之後呼叫了 `RemoveState` | 將其加入 `CreateFsm` 的 `params FsmState<T>[] states`,或在 `Start` 之前呼叫 `AddState` |
| FSM 未運作 / `OnUpdate` 未被觸發 | `FsmComponent` 的 `FixedUpdate` 依賴於 `m_FsmManager` 不為空；若元件未附加或已停用，Update 將不會執行 | 確認場景中存在已啟用的 `FsmComponent` |
| `CreateFsm` 對同一個 Owner 回傳已存在的實例 | 當 Owner 與 name 皆相同時，會重複使用現有的 FSM | 使用不同的 `name` 區分，或先呼叫 `DestroyFsm` 再建立 |

## 驗證

- 在 `IdleState.OnEnter` 中輸出日誌，可看到場景執行時立即輸出一次。
- 在 `IdleState.OnUpdate` 中輸出日誌，場景執行時每幀都會輸出，這表示 `FsmComponent.FixedUpdate` 正在驅動輪詢。
- 呼叫 `fsm.IsRunning` 應為 `true`;呼叫 `fsm.CurrentState` 應回傳剛才 `Start` 的狀態類型。
