# 통합 JSON 응답 형식 사용 방법

`GameFrameX.Foundation.Http.Normalization`은 HTTP 인터페이스의 통합 JSON 응답 래퍼로 `HttpJsonResultData<T>`를 제공합니다. 모든 성공 및 실패 응답은 동일한 필드 규약(`code` / `message` / `data` / `trackId` / `errorCode` / `type` / `time` / `extras`)을 사용하며, 프런트엔드는 필드 이름만으로 파싱하여 일관된 구조를 얻을 수 있습니다.

## 사전 조건

- .NET 프로젝트에서 `GameFrameX.Foundation.Http.Normalization`을 참조 (네임스페이스 `GameFrameX.Foundation.Http.Normalization`).
- 직렬화는 저장소에 내장된 `GameFrameX.Foundation.Json.JsonHelper`를 사용하여 중국어와 이모지가 이스케이프되지 않도록 자동 보존됩니다.

## 작업 단계

### 1. 성공 응답 반환 (데이터 포함)

제네릭 팩토리 메서드 `HttpJsonResultData<T>.Success(data)`를 호출하여 컨트롤러 / 핸들러를 통해 직접 반환합니다.

```csharp
using GameFrameX.Foundation.Http.Normalization;

[HttpGet("{id}")]
public HttpJsonResultData<UserInfo> GetUser(int id)
{
    var user = _repository.Find(id);
    return HttpJsonResultData<UserInfo>.Success(user);
}
```

직렬화 후 대략 다음과 같습니다:

```json
{
  "code": 0,
  "message": "",
  "data": { "id": 1, "name": "Alice" },
  "trackId": "",
  "time": 1714000000
}
```

> `code == 0`이면 성공으로 간주합니다; `IsSuccess` 속성은 이 규칙에 따라 자동으로 계산됩니다 (직렬화에는 참여하지 않음).

Source: [HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L213-L220)

### 2. 실패 응답 반환 (오류 메시지 포함)

`Fail(message)` / `Fail(code, message)` 팩토리 메서드를 사용하거나, 의미에 따라 `ParamError`, `Unauthorized`, `NotFound`, `ServerError` 등의 사전 정의된 오류 팩토리를 선택합니다.

```csharp
[HttpGet("{id}")]
public HttpJsonResultData<UserInfo> GetUser(int id)
{
    if (id <= 0)
    {
        return HttpJsonResultData<UserInfo>.ParamError("id는 0보다 커야 합니다");
    }

    var user = _repository.Find(id);
    if (user == null)
    {
        return HttpJsonResultData<UserInfo>.NotFound();
    }
    return HttpJsonResultData<UserInfo>.Success(user);
}
```

실패 응답 예시:

```json
{
  "code": 403,
  "message": "id는 0보다 커야 합니다",
  "trackId": "",
  "errorCode": "PARAM.ERROR",
  "type": "error",
  "time": 1714000000
}
```

Source: [HttpJsonResultConstants.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultConstants.cs#L31-L115)

### 3. 링크 추적 ID와 비즈니스 오류 코드 전달

`TrackId`는 응답, 로그, 다운스트림 호출을 연관시키는 데 사용됩니다; `ErrorCode`는 안정적인 비즈니스 오류 코드 문자열입니다 (`Code`와 의미적으로 직교). 두 값 모두 생성 후 할당할 수 있습니다.

```csharp
var result = HttpJsonResultData<OrderDto>.Fail(HttpJsonResultConstants.ValidationErrorCode, "주문이 닫혔습니다");
result.TrackId = Activity.Current?.TraceId.ToString();
result.ErrorCode = "ORDER.CLOSED";
result.Type = "error";
result.Extras = new { orderId = 42, closedAt = DateTime.UtcNow };
return result;
```

> `extras`는 null이 아닐 때만 직렬화에 참여합니다; `errorCode` / `type`도 마찬가지입니다.

Source: [HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L128-L186)

### 4. JSON 문자열 직접 얻기

인터페이스가 JSON 텍스트를 직접 출력해야 하는 경우 (미들웨어 / 레거시 프레임워크)에는 `SuccessString()` / `FailString()`을 사용하거나, 먼저 생성한 다음 `.ToString()`을 호출할 수 있으며, 내부적으로 `JsonHelper.Serialize`를 거칩니다.

```csharp
return HttpJsonResultData<UserInfo>.SuccessString();
// 또는
return HttpJsonResultData<UserInfo>.Fail("서비스를 일시적으로 사용할 수 없습니다").ToString();
```

## 일반적인 변형

| 시나리오 | 권장 사용법 | 설명 |
|------|----------|------|
| 성공/실패 부울만 신경 쓰는 경우 | `IsSuccess` 속성 | `JsonIgnore`, 서버 측 단락 판단에만 사용 |
| 래핑할 임의의 타입이 이미 있는 경우 | `HttpJsonResultData<T>.Success(obj)` | 제네릭 `T`에 제약이 없으며, 임의의 참조/값 타입 전달 가능 |
| 타사 인터페이스 응답을 통합 구조로 변환 | `IHttpJsonResult` 인터페이스 | `Data`가 직렬화된 JSON 문자열을 반환하여 타입 간 소비가 용이함 |
| 실패했지만 일부 데이터를 보존해야 하는 경우 | `Fail(code, message, data)` 오버로드 | `data` 필드는 여전히 프런트엔드에 반환됨 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `IsSuccess`가 항상 `false`임 | `Code`를 비즈니스 오류 코드 문자열이나 0이 아닌 정수로 잘못 설정함 | 성공은 `0`만 사용하고, 다른 값은 실패로 간주 |
| 중국어가 `\uXXXX`로 이스케이프됨 | `JsonHelper.Serialize`를 사용하지 않음 | 항상 `.ToString()` 또는 팩토리 메서드를 통해 반환하며, 내부에서 통합 직렬화를 수행 |
| 클라이언트가 `extras`를 받지 못함 | 필드가 `null`임 | 명시적으로 null이 아닌 객체를 할당; null일 때 직렬화에 참여하지 않는 것이 예상 동작 |
| `code`와 `errorCode` 혼동 | HTTP 상태 코드를 `ErrorCode`에 작성함 | `Code`는 HTTP/상태 의미를 사용 (숫자), `ErrorCode`는 안정적인 비즈니스 문자열을 사용 |

## 검증

1. 인터페이스를 시작한 후 `curl`로 호출하여 반환되는 JSON에 `code`, `message`, `data` 세 가지 핵심 필드가 모두 포함되어 있는지 확인합니다.
2. 실패 분기를 트리거하여 `code`가 0이 아니고, `message`에 사람이 읽을 수 있는 설명이 있으며, 서버 측 단락 판단에서 `IsSuccess`가 `false`를 반환하는지 확인합니다.
3. `TrackId`를 활성화한 경우, 응답, 로그, 호출 체인에 동일한 `trackId` 값이 나타나는지 확인합니다.

## 배경

- `IHttpJsonResult`는 `HttpJsonResultData<T>`의 `Data`를 JSON 문자열로 직렬화하여 제네릭 차이를 숨기므로, 비제네릭 컨텍스트 (예: 미들웨어, 로그 인터셉터)에서 통합 처리가 용이합니다.
- `HttpJsonResultConstants`는 `SuccessCode=0`, `FailCode=-1`, `ValidationErrorCode=400`, `UnauthorizedCode=401`, `ParamErrorCode=403`, `NotFoundCode=404`, `ServerErrorCode=500` 등의 숫자와 기본 메시지 상수를 집중적으로 관리하여 비즈니스 측에 매직 넘버가 흩어지는 것을 방지합니다.
- `IsSuccess`는 읽기 전용 속성으로 변경된 후 `Code`에서 자동으로 계산되므로, 생성 시 성공 플래그를 수동으로 유지할 필요가 없습니다.
