# 生成スクリプトの実行方法(クライアント/サーバー)

リポジトリのルートディレクトリにある `gen-*.bat` または `gen-*.sh` スクリプトを実行するだけで、`Excels/` 配下の Excel テーブルを、クライアント(Unity)またはサーバー(.NET)で直接使用できるコードとデータファイルに自動変換できます。このページでは、4 種類のスクリプトの違い、最小限の実行手順、およびよくあるエラーの修正方法を紹介します。

## 4 つの生成スクリプト一覧

リポジトリには 4 つの生成エントリが用意されており、**ターゲット側**(`client` / `server`)と**出力形式**(`bin` / `json`)の組み合わせで構成されています:

| スクリプト | ターゲット側 | データ形式 | コード形式 | 出力先(データ / コード) |
|------|--------|----------|----------|------------------------|
| `gen-client-bin.sh` / `.bat` | クライアント | バイナリ(`bin`) | C# バイナリシリアライズ(`cs-bin`) | `../Unity/Assets//Bundles/Config` / `../Unity/Assets//Hotfix/Config/Generate` |
| `gen-client-json.sh` / `.bat` | クライアント | JSON | C# | `Unity/Assets/Bundles/Config` / `Unity/Assets/Hotfix/Config/Generate` |
| `gen-server-bin.sh` / `.bat` | サーバー | バイナリ(`bin`) | C# .NET バイナリシリアライズ(`cs-dotnet-bin`) | `../Server/GameFrameX.Config/Json` / `../Server/GameFrameX.Config/Config` |
| `gen-server-json.sh` / `.bat` | サーバー | JSON | C# | `Server/GameFrameX.Config/Json` / `Server/GameFrameX.Config/Config` |

> `c` = クライアント(client)、`s` = サーバー(server)、`bin` = バイナリ、`json` = テキスト。同じターゲット側では、`bin` はサイズが小さくロードが高速です。`json` は可読性が高く、データの調査に便利です。

## 前提条件

- **.NET SDK** がインストール済みであること(スクリプトは `dotnet` を介して `./Tools/Luban.dll` を起動するため)。
- リポジトリ内の `Tools/Luban.dll`、`luban.conf`、`Defines/builtin.xml`、`Excels/__tables__.xlsx`(`__beans__`、`__enums__` を含む)は必ず元の場所に置いてください。移動しないでください。
- テーブルがルールに従って記入済みであること(`Excels/Tables/` 内のテーブル名の形式は `字母-英文名-中文名.xlsx` で、英語名に中国語を含めてはいけません)。

## 操作手順

1. ターミナル / コマンドラインを開き、**リポジトリのルートディレクトリに `cd` します**(`gen-*.sh`、`gen-*.bat` が見える階層)。スクリプト内の相対パスはすべてこのディレクトリ基準のため、サブディレクトリでは実行しないでください。

2. ターゲット側と出力形式を選び、対応するスクリプトを実行します:

   - **クライアント向け JSON 生成(最もよく使う入門コマンド):**

     ```bash
     sh gen-client-json.sh
     ```

     Windows での対応操作は `gen-client-json.bat` をダブルクリックすることです。

   - **クライアント向けバイナリ生成:**

     ```bash
     sh gen-client-bin.sh
     ```

     [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1) の中心的な呼び出しは以下の通りです:

     ```bash
     dotnet ./Tools/Luban.dll --target client --dataTarget bin --codeTarget cs-bin \
       --xargs outputDataDir=../Unity/Assets//Bundles/Config \
       --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
       --xargs tableImporter.name=gameframex \
       -x l10n.provider=gameframex \
       -x l10n.textFile.keyFieldName=key \
       -x l10n.textFile.path=./Excels/Local/ \
       --conf ./Luban.conf
     ```

     Source: [gen-client-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-bin.sh#L1-L1)

   - **サーバー向けバイナリ生成:**

     ```bash
     sh gen-server-bin.sh
     ```

     実際の呼び出しは [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1) を参照してください:

     ```bash
     dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin \
       --xargs outputDataDir=../Server/GameFrameX.Config/Json \
       --xargs tableImporter.name=gameframex \
       --xargs outputCodeDir=../Server/GameFrameX.Config/Config \
       --conf ./Luban.conf
     ```

     Source: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L1)

   - **サーバー向け JSON 生成:** `sh gen-server-json.sh` を実行します(対応する `.bat`)。

3. スクリプトの完了を待ちます。最後に `pause`(Windows `.bat`)で停止する、または赤色のエラーが表示されなければ成功です。

4. 成果物を確認します:
   - クライアント:`Unity/Assets/Hotfix/Config/Generate/` 配下に自動生成された C# クラス(例:`TbAchievementConfig.cs`)があり、`Unity/Assets/Bundles/Config/` 配下にデータファイルがあるはずです。
   - サーバー:`Server/GameFrameX.Config/Config/` 配下は C# クラス、`Server/GameFrameX.Config/Json/` 配下はデータファイルです。

## よくあるバリエーション

- **特定のターゲット側だけに生成したい場合：** テーブル名にグループマークを追加するだけでよく、スクリプトを切り替える必要はありません。例えば、`D-ItemConfig-道具表.xlsx` はクライアントとサーバーの両方に生成され、`D-ItemConfig-c-道具表.xlsx` はクライアントのみ、`D-ItemConfig-s-道具表.xlsx` はサーバーのみに生成されます。詳細は [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md) を参照してください。
- **多言語テキスト(Excels/Local/)を変更した場合：** 同じスクリプトをそのまま再実行するだけでよく、何も再起動する必要はありません。
- **テーブルヘッダー(フィールド名/型)を変更した場合：** スクリプトを再実行 → コードを再生成 → 呼び出し側で新しいフィールド名に合わせてコンパイルします。
- **bin と json の切り替え:** 同じターゲット側で、`gen-client-bin.sh` を `gen-client-json.sh` に置き換えて再実行するだけです。クライアントの実行時に形式を切り替えた場合は、ロードコードも忘れずに更新してください。

## よくあるエラー

- **`'dotnet' is not recognized` / `dotnet: command not found`**:.NET SDK が未インストール、またはターミナルが PATH 内で見つけられないことが原因です。まず .NET 6+ SDK をインストールし、ターミナルを開き直してください。
- **`Could not find ./Tools/Luban.dll`**:カレントディレクトリが正しくありません。`Tools/` を含むリポジトリのルートディレクトリに `cd` してから再実行してください。
- **`不支持中文表名` / クラス名が文字化けする**:ファイル名の英語部分に中国語が書かれています。`字母-英文名-中文名.xlsx` の形式に変更し、英語名には英数字とアンダースコアのみを使用してください。
- **出力ディレクトリに古いファイルが残存し、削除済みフィールドを参照している**:`outputCodeDir` が指すディレクトリ(例:`Unity/Assets/Hotfix/Config/Generate/`)を丸ごと削除してから、スクリプトを再実行してください。
- **`failed: conf file` / 設定エラー**:`luban.conf` を変更したことで解析に失敗しています。Git からこのファイルを復元してから再試行してください。トップレベルのフィールドをむやみに変更しないでください。
- **多言語キーを `text` フィールドから読み込んでもキー自身のまま**:`gen-client-bin.sh` または `-x l10n.provider=gameframex -x l10n.textFile.path=./Excels/Local/` 付きの一連のパラメータを実行しているか、`--conf ./Luban.conf` のみを使用したコマンドではないことを確認してください。

## 背景(任意)

4 つのスクリプトは本質的にすべて `dotnet ./Tools/Luban.dll` を呼び出しており、違いは 3 つのスイッチだけです:`--target`(client か server のどちらのコードテンプレートとデータ型マッピングを使用するかを決定)、`--dataTarget`(データの保存形式 `bin` または `json` を決定)、`--codeTarget`(生成される C# のシリアライズ方式(例:`cs-bin`、`cs-dotnet-bin`)を決定)。`outputDataDir` と `outputCodeDir` は成果物の保存先を制御し、`--conf ./Luban.conf` はプロジェクトレベルの設定を指します。`gen-client-bin.sh` に `-x l10n.*` パラメータが `gen-server-bin.sh` よりいくつか多いのは、Unity 側で `text` フィールドの多言語キーを現在の言語の文字列へ直接解決する必要があるため、スクリプト内で明示的にローカライズプロバイダーを注入しているからです。
