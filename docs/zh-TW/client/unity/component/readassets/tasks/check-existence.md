# 查詢檔案與目錄是否存在

`BlankReadAssets` 提供了兩個靜態方法 `FileExists` 和 `DirectoryExists`，用於在執行階段判斷 `StreamingAssets` 下的檔案或目錄是否存在。它們在 Android（直接讀取 APK）、編輯器以及其他平台（鬆散檔案）上都能正確運作。首次呼叫時會自動執行 `Initialize`。

## 前置條件

- 已安裝 `com.gameframex.unity.readassets` 套件。
- 專案中存在 `StreamingAssets` 目錄（執行階段無需手動初始化；首次呼叫 API 時會自動完成）。

## 步驟

1. 若要檢查檔案是否存在，請傳入相對於 `StreamingAssets` 的路徑：

```csharp
using GameFrameX.ReadAssets.Runtime;

bool exists = BlankReadAssets.FileExists("configs/level1.json");
if (exists)
{
    // 安全地繼續執行 OpenRead / LoadAssetBundle 等操作
}
```

2. 若要檢查目錄是否存在，同樣使用相對路徑（開頭或結尾帶有 `/` 皆可；系統會在內部進行正規化處理）：

```csharp
using GameFrameX.ReadAssets.Runtime;

bool dirExists = BlankReadAssets.DirectoryExists("configs/");
```

## API 快速參考

| 方法 | 簽章 | 說明 |
|------|------|------|
| `FileExists` | `static bool FileExists(string path)` | 檢查相對於 `StreamingAssets` 的檔案是否存在 |
| `DirectoryExists` | `static bool DirectoryExists(string path)` | 檢查相對於 `StreamingAssets` 的目錄是否存在 |

這兩個方法都標記了 `[Preserve]`，並在透過 `EnsureInitialized()` 自動初始化後，委派給各平台實作（`EditorImpl` / `ApkImpl` / `LooseFilesImpl`）。

## 常見變化

- 在編輯器中，若要檢查外部 APK 內 `StreamingAssets` 的存在性，需要先呼叫 `InitializeWithExternalApk(apkPath)`，再使用相同的 `FileExists` / `DirectoryExists`。
- 在 Android 上，APK 內的路徑檢查會掃描 APK 的目錄樹（`ApkImpl.DirectoryExists` 內部使用 `GetDirectoryIndex`），因此無需擔心大小寫或壓縮狀態的問題。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| 一律回傳 `false`，但檔案確實存在 | 路徑以絕對路徑方式傳入，或包含 `Application.streamingAssetsPath` 前綴 | 僅傳入相對於 `StreamingAssets` 的路徑，例如使用 `"config.json"` 而非 `Application.streamingAssetsPath + "/config.json"` |
| 含有反斜線或多餘 `/` 的路徑導致誤判 | 各平台路徑分隔符號的差異 | 直接傳入以 `/` 分隔的相對路徑；工具內部會透過 `PathUtil.NormalizeRelativePath` 進行正規化 |
| 在 Android 上回傳 `true`，但後續的 `OpenRead` 擲出例外 | 檔案在 APK 內被 Unity 標記為壓縮 | 監聽 `BlankReadAssets.CompressedStreamingAssetFound` 事件，改用 `UnityWebRequest` 讀取 |

## 背景說明（選讀）

平台分派由 `BlankReadAssets.cs` 頂部的條件編譯決定：`UNITY_EDITOR` 走 `EditorImpl`（支援 APK 模式 / 外部目錄），`UNITY_ANDROID` 走 `ApkImpl`（在 APK 內透過二分搜尋定位），其他平台則走 `LooseFilesImpl`（直接存取檔案系統）。`DirectoryExists` 在 APK 內部使用預先建立的路徑索引 `GetDirectoryIndex` 來判斷，因此不會觸發實際的解壓縮。
