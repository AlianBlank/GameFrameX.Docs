# Configuring iOS / tvOS / visionOS Channels

On iOS, tvOS, and visionOS platforms, channel information is stored in the Xcode project's `Info.plist`. This package automatically checks `Info.plist` at build time: if there is no `channel` key, the default value `default` is written automatically; you then change this value to the actual channel name in Xcode, and read it at runtime using `BlankGetChannel.GetChannelName()`.

## Prerequisites

- The Unity project has this package `com.gameframex.unity.getchannel` installed (Unity 2019.4+).
- Switched to the iOS build target (`File > Build Settings > iOS > Switch Platform`). Note: the post-build processing script is compiled with `#if UNITY_IOS` and only takes effect for `BuildTarget.iOS`.

## Steps

1. Perform an iOS build in Unity (`Build` or `Build And Run`) to generate the Xcode project. After the build completes, the script automatically processes the generated `Info.plist`:

   ```csharp
   private static void Run(string path)
   {
       const string channelKey = "channel";
       const string channelValue = "default";

       string plistPath = path + "/Info.plist";
       PlistDocument plist = new PlistDocument();
       plist.ReadFromString(File.ReadAllText(plistPath));
       if (!plist.root.values.TryGetValue(channelKey, out var value))
       {
           plist.root.SetString(channelKey, channelValue);
           plist.WriteToFile(plistPath);
           Debug.Log("配置渠道成功=>" + channelValue);
       }
       else
       {
           Debug.Log("已有渠道,跳过设置=>" + value);
       }
   }
   ```

   Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

   This callback is attached via `[PostProcessBuild(99)]` and only takes effect for `BuildTarget.iOS`; processing exceptions are caught and output via `Debug.LogException`, without interrupting the build.

2. Open the generated Xcode project and change the value of `channel` in `Info.plist` to the actual channel name; you can also add other keys as needed (e.g., `sub_channel`):

   ```xml
   <key>channel</key>
   <string>ios_cn_taptap</string>

   <key>sub_channel</key>
   <string>beta</string>
   ```

   Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L133-L141)

3. Read the channel in C# code:

   ```csharp
   using UnityEngine;

   public class MyGameScript : MonoBehaviour
   {
       void Start()
       {
           // Get default channel (key name is "channel")
           string channel = BlankGetChannel.GetChannelName();
           Debug.Log("Current channel: " + channel);

           // Get channel with a specific key
           string customChannel = BlankGetChannel.GetChannelName("channelName");
           Debug.Log("Custom channel: " + customChannel);

           // Get channel with a default fallback value
           string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
           Debug.Log("Sub channel: " + subChannel);
       }
   }
   ```

   Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/README.md#L103-L123)

4. Run on a device/simulator and confirm that the channel value output in the Console matches the one in `Info.plist`.

## Common Variants

- **Custom key name**: You don't have to use the default key `channel`; you can define any key in `Info.plist` (e.g., `channelName`) and then call `BlankGetChannel.GetChannelName("channelName")`; the key must actually exist in `Info.plist`.
- **Multi-level channels**: Maintain both `channel` and `sub_channel` keys, reading the main channel and sub-channel separately.
- **Reading with a fallback value**: The full API signature is

  ```csharp
  public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
  ```

  Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98)

  The second parameter specifies the default value returned when reading fails at the C# layer; if omitted, it is `default`.

## Common Errors

- **Console outputs `unknown`**: The native layer returns the string `unknown` when it cannot find the corresponding key while reading `Info.plist`. Check whether the key actually exists in the Xcode project's `Info.plist`, and whether its spelling exactly matches the `channelKey` used in the C# call. See the related implementation at [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36).
- **The channel name was changed but overwritten back to `default` after rebuilding**: The script only writes the value when the key does not exist. If you changed `channel` in the Xcode project and then rebuilt in Unity, overwriting the entire Xcode project directory, you need to modify it again; if it is only an incremental build and the key already exists, the script skips it and outputs `已有渠道,跳过设置=>...`.
- **`Info.plist` not written after a tvOS / visionOS build**: The post-processing script checks against `BuildTarget.iOS`; make sure the corresponding platform is switched to the iOS build pipeline to generate the project for it to take effect; if the key is not written, you can manually add the `channel` key in Xcode.

## Verification

- The Unity Console shows `配置渠道成功=>default` (first time) or `已有渠道,跳过设置=>xxx` (already exists), indicating the post-processing script has run. See [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L43-L48).
- Open `Info.plist` in Xcode and verify that you can see the `channel` key and its current value.
- Run the app; the value returned by `BlankGetChannel.GetChannelName()` matches the one in `Info.plist`; when the key does not exist, it returns `unknown`.

## Background

The native plugin on iOS reads the main bundle's `Info.plist` dictionary from `[[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"]`, looks up the value by the passed-in key name, converts it to a C string, and returns it to the C# layer; it returns `unknown` when the value cannot be retrieved. This is why the channel value must be configured in `Info.plist`, and the key name must match the call parameter. See the implementation at [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36).

For Android channel configuration, see "Configuring Android Channels"; platforms such as Editor/PC/WebGL use `Resources/application_config.txt` — see the README for details.
