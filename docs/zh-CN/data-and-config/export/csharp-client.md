# 如何导出 C# 客户端代码

把仓库内的 `.proto` 文件批量编译为 C# 客户端代码,生成可放进 Unity `Assets/Hotfix/Proto` 目录的命名空间 `Hotfix.Proto`,包含所有消息体和错误码枚举。

## 前置条件

- 本机已安装 .NET SDK(导出工具基于 .NET 10)。
- 已构建 `GameFrameX.Tools.ProtoExport`,产物 `Tools/ProtoExport.dll` 放在本仓库根目录的 `Tools/` 下(脚本里写死 `./Tools/ProtoExport.dll`)。
- 客户端工程是 Unity 项目,目标输出目录为 `../Unity/Assets/Hotfix/Proto`(相对于本仓库根)。

## 操作步骤

### 1. 使用本地脚本(Linux/macOS)

仓库自带脚本 [Proto2CsExport_Client.sh](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Client.sh),直接执行即可:

```bash
./Proto2CsExport_Client.sh
```

脚本内容等价于:

```bash
dotnet ./Tools/ProtoExport.dll \
  --mode csharp \
  --usingStatements "using System|using ProtoBuf|using System.Collections.Generic|using GameFrameX.Network.Runtime" \
  --inputPath ./ \
  --outputPath ../Unity/Assets/Hotfix/Proto \
  --namespaceName Hotfix.Proto \
  --isGenerateErrorCode true
```

Source: [Proto2CsExport_Client.sh](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Client.sh#L1-L3)

### 2. 使用本地脚本(Windows)

在 Windows 上用对应的 bat 脚本 [Proto2CsExport_Client.bat](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Client.bat),逻辑与上面一致,把 `dotnet ./Tools/ProtoExport.dll` 换成 Windows 路径写法即可。

### 3. 使用 Docker(无需本地 .NET 工具链)

```bash
docker run --rm -v "$(pwd)":/proto -v "$(pwd)/../Unity/Assets/Hotfix/Proto":/out \
  gameframex/gameframex-tools:latest \
  --mode csharp \
  --usingStatements "using System|using ProtoBuf|using System.Collections.Generic|using GameFrameX.Network.Runtime" \
  --inputPath /proto \
  --outputPath /out \
  --namespaceName Hotfix.Proto \
  --isGenerateErrorCode true
```

挂载本仓库为 `/proto`,客户端输出目录挂载到容器内 `/out`。

### 4. 使用 CI Release(零配置)

每次 `push` 触发 GitHub Actions 工作流 [proto-export.yml](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/.github/workflows/proto-export.yml),所有语言产物会自动发布到滚动更新的 [`latest` Release](https://github.com/GameFrameX/GameFrameX.Protobuf/releases/latest),直接下载 `csharp-client.zip` 解压到 `Unity/Assets/Hotfix/Proto` 即可。

## 常用参数速查

| 参数 | 含义 | 本脚本取值 |
|------|------|-----------|
| `--mode` | 目标语言 | `csharp` |
| `--inputPath` | `.proto` 所在根目录 | `./`(仓库根) |
| `--outputPath` | 生成代码输出目录 | `../Unity/Assets/Hotfix/Proto` |
| `--namespaceName` | 生成的 C# 命名空间 | `Hotfix.Proto` |
| `--usingStatements` | 注入到生成文件头部的 `using`,用 `|` 分隔 | `using System\|using ProtoBuf\|using System.Collections.Generic\|using GameFrameX.Network.Runtime` |
| `--isGenerateErrorCode` | 是否生成错误码枚举 | `true` |

## 常见变体

- **同时导出服务端**:使用 [Proto2CsExport_Server.sh](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Server.sh) 即可,命名空间与输出目录不同。
- **一次性导出全部 C# 目标(客户端+服务端)**:运行 [Proto2CsExport_All.bat](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_All.bat)。
- **只想拿非内部协议**:内部文件以 `_-` 开头(如 `_-0120_Inner_Social.proto`),客户端模式天然不打包它们;若仍出现在输出里,检查脚本的 `--inputPath` 是否只指向对外目录。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `Could not load Tools/ProtoExport.dll` | 工具未构建或路径错 | 先到 `GameFrameX.Tools` 仓库 build,产物复制到本仓库根 `Tools/ProtoExport.dll` |
| `dotnet: command not found` | 未装 .NET SDK | 安装 .NET 10 SDK,或改用 Docker / CI Release |
| 输出目录里没有 `Hotfix.Proto` 命名空间 | `--namespaceName` 拼错 | 确认传值严格为 `Hotfix.Proto`,大小写敏感 |
| 找不到 `using GameFrameX.Network.Runtime` 报红 | Unity 工程缺 `GameFrameX.Network` 包 | 在 Unity 中通过 Package Manager 安装 `GameFrameX.Network` |
| 错误码枚举缺失 | 没启用错误码生成 | 确认 `--isGenerateErrorCode true` |

## 验证

1. 检查输出目录确实存在 C# 文件,且每个 `.proto` 都生成对应 `.cs`。
2. 打开 Unity,确认无编译错误,且能在脚本里 `using Hotfix.Proto;` 引用到消息类型。
3. 校验错误码:对 `_0020_Common.proto` 中的 `OperationStatusCode` 与各模块的业务错误码(如 `MailErrorCode`)在生成代码里都能找到对应枚举值。

## 背景(可选)

- 工具入口 `ProtoExport` 由 [GameFrameX.Tools](https://github.com/GameFrameX/GameFrameX.Tools) 仓库维护;本仓库只负责协议源与薄脚本封装。
- 文件名以 `_<ModuleID:0000>_<Domain>.proto` 命名,模块号同时作为客户端路由号;内部协议以负数 ID + `Inner` 前缀标识,客户端导出不会包含它们。
