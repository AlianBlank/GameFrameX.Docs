# 設定多語系應用程式名稱

在建置設定 JSON 的 `localizations` 陣列中為每種語言宣告 `languageCode` 和 `validMap`（包含 `CFBundleDisplayName` 鍵），打包後處理會在 Xcode 專案目錄下自動產生 `{languageCode}.lproj/InfoPlist.strings`、把檔案加入主 target 的 Resources，並在 `Info.plist` 中寫入 `LSHasLocalizedDisplayName = true`，讓 iOS 主畫面圖示下方顯示對應語言的名稱。

## 前置條件

- Unity 切換到 iOS 平台，且本套件（`com.gameframex.unity.xcode`）已安裝。
- 專案已整合 `PostProcessBuildHelper` 的建置後處理流程——本地化邏輯由該流程統一觸發（見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126)，從合併後的設定讀取 `localizations` 欄位）。

## 操作步驟

1. 在 iOS 建置設定 JSON 中新增 `localizations` 陣列（與 `podInstall`、`capabilities` 等欄位同層）：

   ```json
   "localizations": [
     {
       "languageCode": "en",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "My Game" }
       ]
     },
     {
       "languageCode": "zh-Hans",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "我的遊戲" }
       ]
     }
   ]
   ```

   欄位說明：

   | 欄位 | 類型 | 說明 |
   |------|------|------|
   | `localizations` | array | 本地化設定清單，每項對應一種語言 |
   | `languageCode` | string | 語言代碼，會作為 `{languageCode}.lproj` 目錄名（如 `en.lproj`、`zh-Hans.lproj`）；為空或缺少時該條目會被跳過 |
   | `validMap` | array | 鍵值對清單，每項包含 `key` 和 `value`；為空或缺少時該條目會被跳過 |
   | `key` | string | Info.plist 鍵名；應用程式名稱本地化固定使用 `CFBundleDisplayName` |
   | `value` | string | 該語言下的顯示文字 |

   設定範例結構與 [README.zh-TW.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-TW.md#L323-L346) 中 `localizations` 一節的寫法一致；`languageCode` / `validMap` 的欄位名以 [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L52) 中的實際讀取邏輯為準。

2. 執行 iOS 建置。後處理會自動完成以下動作（無須手動介入）：

   ```csharp
   foreach (Hashtable loc in localizations)
   {
       ...
       // Create .lproj directory
       string lprojName = langCode + ".lproj";
       string lprojPath = Path.Combine(path, lprojName);
       if (!Directory.Exists(lprojPath))
       {
           Directory.CreateDirectory(lprojPath);
       }

       // Prepare InfoPlist.strings content
       StringBuilder sb = new StringBuilder();
       foreach (Hashtable map in validMap)
       {
           if (map.ContainsKey("key") && map.ContainsKey("value"))
           {
               string key = map["key"].ToString();
               string value = map["value"].ToString();
               sb.Append($"\"{key}\" = \"{value}\";\n");

               // 檢查是否包含 CFBundleDisplayName
               if (key == "CFBundleDisplayName")
               {
                   hasLocalizedDisplayName = true;
               }
           }
       }
       ...
   }
   ```

   Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L91)

3. 檢查產生結果。產生的 `en.lproj/InfoPlist.strings` 內容形如：

   ```text
   "CFBundleDisplayName" = "My Game";
   ```

   產生格式由 `sb.Append($"\"{key}\" = \"{value}\";\n")` 決定，見 [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L62-L90)。

## 常見變體

- **同時本地化其他 Info.plist 鍵**：`validMap` 中可繼續新增如權限描述等鍵值對，它們會寫進同一個 `InfoPlist.strings`：

  ```json
  "validMap": [
    { "key": "CFBundleDisplayName", "value": "我的遊戲" },
    { "key": "NSCameraUsageDescription", "value": "需要存取相機以掃描 QR Code" }
  ]
  ```

- **更多語言**：在 `localizations` 陣列中追加條目即可，每種語言各產生一個 `.lproj` 目錄和一份 `InfoPlist.strings`。

- **關閉本地化**：把 `localizations` 設為空陣列 `[]` 或不設定該欄位，後處理會直接傳回，不做任何修改（見 [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L20-L23)）。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 打包後沒有產生 `.lproj` 目錄 | `localizations` 為空/未設定，或條目缺少 `languageCode`、`validMap` | 確認設定已進入合併後的最終設定，且每個條目都帶非空 `languageCode` 與非空 `validMap`（缺失的條目會被 `continue` 跳過） |
| 只本地化了權限描述、主畫面名稱仍是英文 | `validMap` 中沒有 `CFBundleDisplayName` | 應用程式名稱本地化必須使用鍵名 `CFBundleDisplayName`，它同時是觸發 `LSHasLocalizedDisplayName` 的唯一條件 |
| `InfoPlist.strings` 未加入 Xcode 專案（顯示語言 fallback 到預設） | 檔案未被加入 Resources 建置階段 | 後處理會用 `project.AddFile(...)` + `project.AddFileToBuild(mainTargetGuid, fileGuid)` 注入，見下文；若曾手動刪除過專案檔案，重新打包一次 |
| 建置日誌出現 `InfoPlist.strings not found at: ...` | `.lproj` 目錄下檔案被外部腳本刪除或未產生 | 檢查是否有其他後處理腳本在本地化之前清理目錄，重新打包 |

## 背景

觸發鏈路：`PostProcessBuildHelper` 在合併設定後呼叫 `RunLocalization(project, project.ProjectGuid(), path, finalConfig.Get("localizations") as ArrayList)`（見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126)）。`RunLocalization` 產生檔案後，當偵測到 `CFBundleDisplayName` 時會把 `Info.plist` 的 `LSHasLocalizedDisplayName` 設為 `true`（[PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L97-L108)），隨後由 `AddLocalizationToProject` 把每份 `InfoPlist.strings` 新增至主 target 的 Resources 並寫回 `project.pbxproj`：

```csharp
// 使用 PBXProject API 將檔案新增至專案
string fileGuid = project.AddFile(infoPlistStringsPath, infoPlistStringsPath, PBXSourceTree.Source);

// 將檔案新增到主 target 的 Resources 建置階段
project.AddFileToBuild(mainTargetGuid, fileGuid);

LogHelper.Log($"Added localization file to project: {infoPlistStringsPath}");
```

Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L194-L205)
