# 新增 HTTP 介面(Bag / Mail / Player 等)

本頁教你如何在 `GameFrameX.Hotfix` 組件中新增一個 HTTP 介面，用於對外提供 Bag、Mail、Player 等業務能力。完成後框架會自動把這個介面註冊到內建 HTTP 服務，你用 URL 直接呼叫即可。

## 前置條件

- 已熟悉方案中的 `GameFrameX.Hotfix` 專案結構，知道業務程式碼放在 `GameFrameX.Hotfix/Logic/Http/<模块>/`。
- 已經在協定專案(`GameFrameX.Proto`)中定義好了 `HttpMessageRequestBase` / `HttpMessageResponseBase` 的請求 / 回應類型，以及 `ErrorCode` 列舉。
- 了解框架的 HTTP 啟動入口:[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L40-L52) 透過 `HotfixManager.GetListHttpHandler()` 自動掃描所有繼承 `BaseHttpHandler` 的類別。

## 操作步驟

1. **建立 Handler 類別**：在 `GameFrameX.Hotfix/Logic/Http/<模块>/` 下新增一個 `sealed class`,繼承 `BaseHttpHandler`。類別必須位於 `GameFrameX.Hotfix` 組件，否則會被架構分析器 `GFX0003` 拒絕編譯([HttpHandlerAssemblyAnalyzer.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Architecture.Analyzers/Analyzers/Architecture/HttpHandlerAssemblyAnalyzer.cs#L10-L20))。

2. **標上三個特性**：類別上必須同時標註 `HttpMessageMapping`(路由)、`HttpMessageRequest`(請求類型),`HttpMessageResponse`(回應類型，可省略但強烈建議加上)。Mail 系列還要求使用強型別 `HttpMessageRequestBase` 多載：

```csharp
namespace GameFrameX.Hotfix.Logic.Http.Mail;

[HttpMessageMapping(typeof(QueryMailCampaignHttpHandler))]
[HttpMessageRequest(typeof(QueryMailCampaignRequest))]
[HttpMessageResponse(typeof(QueryMailCampaignResponse))]
[Description("Admin 查询运营邮件 Campaign 发布状态")]
public sealed class QueryMailCampaignHttpHandler : BaseHttpHandler
{
    public override async Task<string> Action(string ip, string url, HttpMessageRequestBase requestBase)
    {
        var request = (QueryMailCampaignRequest)requestBase;
        var response = new QueryMailCampaignResponse { Code = MailCampaignErrorCode.Ok };
        // ...業務邏輯...
        return HttpJsonResult.SuccessString(response);
    }
}
```

Source: [QueryMailCampaignHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Mail/QueryMailCampaignHttpHandler.cs#L44-L70)

3. **覆寫 `Action` 方法**：根據是否需要反序列化請求主體，選擇兩種簽章之一：
   - 簡單介面(`ReloadHttpHandler`、`TestHttpHandler`):接收 `Dictionary<string, object> parameters`,自行解析查詢參數。
   - 強型別介面(Mail、Bag):接收 `HttpMessageRequestBase requestBase`,框架已替你反序列化。

   傳回值必須是 `string`,統一透過 `HttpJsonResult` 工具方法序列化(`SuccessString` / `ParamErrorString` 等):

```csharp
public override Task<string> Action(string ip, string url, Dictionary<string, object> parameters)
{
    if (parameters.TryGetValue("version", out var version))
    {
        await HotfixManager.LoadHotfixModule(null, version.ToString());
        return Task.FromResult(HttpJsonResult.SuccessString(null));
    }
    return Task.FromResult(HttpJsonResult.ParamErrorString());
}
```

Source: [ReloadHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/ReloadHttpHandler.cs#L40-L60)

4. **建置並啟動**：在儲存庫根目錄執行建置，框架會自動掃描所有 `BaseHttpHandler` 子類別並向 `HttpServer.Start(Setting.HttpPort, Setting.HttpsPort, HotfixManager.GetListHttpHandler(), HotfixManager.GetHttpHandler, null, Setting.HttpUrl)` 註冊([AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L49-L51))。啟動後即可用註解裡標註的 URL 偵錯。

## 常見變體

- **無請求 / 無回應主體**(`TestHttpHandler`):只標 `HttpMessageMapping`,需要傳回資料時手寫一個繼承 `HttpMessageResponseBase` 的類別即可。
- **需要事件分發**(Bag 道具發放)：在 Handler 內呼叫 `EventDispatcher.Dispatch(...)`,非同步等待 `BagComponentAgent` 完成，最後用 `HttpJsonResult.SuccessString` 傳回彙總結果([ReqPlayerSendItemHttpHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Http/Bag/ReqPlayerSendItemHttpHandler.cs#L45-L80))。
- **GM 類唯讀介面**(Player 線上清單)：同樣走 `Dictionary<string, object> parameters`,Handler 內部去查 SessionManager,範本可直接參考 `GetOnlinePlayerListHttpHandler`。
- **營運郵件四件套**:`PreviewMailCampaignHttpHandler` / `PublishMailCampaignHttpHandler` / `QueryMailCampaignHttpHandler` / `RevokeMailCampaignHttpHandler` 示範了同一模組下多介面的標準寫法。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| 編譯出現 `GFX0003` | `BaseHttpHandler` 子類別沒有放在 `GameFrameX.Hotfix` 組件 | 把 Handler 類別移到 `GameFrameX.Hotfix/Logic/Http/...` 下 |
| 啟動後存取出現 404 | 沒有標 `[HttpMessageMapping]`,或類別自身未作為泛型引數傳入特性 | 確認特性參數是 `typeof(YourHandler)` 本身 |
| 取不到請求參數 | 用了 `Dictionary<string, object>` 簽章但前端傳的是 JSON Body | 改用 `HttpMessageRequestBase` 多載並加上 `[HttpMessageRequest]` |
| 傳回 `null` 序列化失敗 | 直接傳回物件而不是字串 | 用 `HttpJsonResult.SuccessString(response)` 包一層 |
| 路由無法被 GM 後台識別 | `[Description]` 為空，工具無法歸類 | 加上語意化中文 `Description("...")` |

## 背景(選用)

`BaseHttpHandler` 是 `GameFrameX.NetWork.HTTP` 提供的事件式基底類別；啟動時 `HotfixManager.GetListHttpHandler()` 會反射出所有非抽象子類別，交給 `HttpServer` 完成路由註冊。Mail / Bag / Player 模組依目錄切分子命名空間，便於 GM 後台和自動化掃描按模組歸類。
