# 新增並發起一次下載

透過 `DownloadComponent.AddDownload(...)` 把遠端檔案加入下載佇列,框架會自動排程下載代理程式完成下載,並透過事件回呼把進度、成功、失敗結果回傳給你。

## 前置條件

- 場景中已掛載 `DownloadComponent`(元件選單 `GameFrameX/Download`),並隨 `GameFramework` 啟動完成。
- 場景中已掛載 `EventComponent`,否則下載成功 / 失敗事件無法分發。
- `DownloadComponent` 上的 `Download Agent Helper Count` 大於 0,預設值為 3。
- `downloadPath` 所在目錄有寫入權限。

## 操作步驟

1. 取得 `DownloadComponent` 實例：

```csharp
var download = GameEntry.GetComponent<DownloadComponent>();
```

Source: [DownloadComponent.cs#L46-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L60)

2. 呼叫 `AddDownload` 把下載任務加入佇列，回傳任務的序號 `serialId`:

```csharp
int serialId = download.AddDownload(
    downloadPath: Application.persistentDataPath + "/files/bundle.zip",
    downloadUri:   "https://example.com/bundle.zip",
    tag:           "Bundle",
    priority:      0,
    userData:      null);
```

Source: [DownloadComponent.cs#L379-L385](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L379-L385)

3. 訂閱 `EventComponent` 中的下載事件以取得回呼，事件 ID 定義請見 `Constant.cs`:

```csharp
var eventComp = GameEntry.GetComponent<EventComponent>();
eventComp.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComp.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComp.Subscribe(DownloadUpdateEventArgs.EventId,   OnDownloadUpdate);
```

回呼中透過 `e.SerialId` 與加入時回傳的 `serialId` 對應。

4. 處理下載結果。`DownloadSuccessEventArgs` / `DownloadFailureEventArgs` 皆提供 `SerialId`,根據它即可判斷是哪個任務結束。

## 常見變體

- **只想取得 `Task<bool>`**:使用 `download.Download(downloadPath, downloadUri)`,內部封裝了 `AddDownload` + `TaskCompletionSource`,完成時 `Task` 會 `SetResult(true)`,失敗 / 取消時 `SetResult(false)` / `TrySetCanceled()`。
  Source: [DownloadComponent.cs#L306-L317](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L317)

- **不傳 tag / priority**:直接使用兩個參數的 `AddDownload(string downloadPath, string downloadUri)`,預設 `tag = null`,`priority = 0`。
  Source: [DownloadComponent.cs#L271-L274](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L274)

- **依 tag 批次管理**：用 `GetDownloadInfos(tag)` 查詢，用 `RemoveDownloads(tag)` 批次取消。

## 常見錯誤

- **`Log.Fatal("Download manager is invalid.")`**:場景中沒有掛載 `DownloadComponent` 或它沒有正確 Awake。檢查 GameFramework 啟動順序。
- **`Log.Fatal("Event component is invalid.")`**:缺少 `EventComponent`,下載事件無法分發。
- **下載目錄無寫入權限**：請使用 `Application.persistentDataPath` 這類 Unity 提供的可寫入路徑，不要寫到 `StreamingAssets` 或 `jar:file://` 等唯讀位置。
- **代理程式全部忙碌時新任務持續等待**：任務會進入等待佇列，直到有閒置的代理程式。可用 `FreeAgentCount` / `WaitingTaskCount` 監控。
  Source: [DownloadComponent.cs#L82-L105](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L82-L105)

## 背景

`DownloadComponent` 在 `Start` 階段會依 `Download Agent Helper Count` 建立對應數量的 `UnityWebRequestDownloadAgentHelper`(可在 Inspector 切換為自訂實作)，所有並行下載都會在這些 Helper 上輪流進行。`AddDownload` 僅將任務加入佇列，真正發起 HTTP 請求與寫入磁碟由 `DownloadManager` 在下一幀排程。
