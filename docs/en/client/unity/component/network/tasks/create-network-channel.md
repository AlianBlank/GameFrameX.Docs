# Connecting to a Server: Creating a Channel and Implementing a Channel Helper (TCP/WebSocket)

Creating a network channel only requires calling `NetworkComponent.CreateNetworkChannel(channelName, networkChannelHelper)` and passing in a channel helper that implements `INetworkChannelHelper`; the framework automatically selects the underlying implementation based on compilation defines — `WebSocketNetworkChannel` is used when the WebGL/WebSocket define is enabled, otherwise `SystemTcpNetworkChannel` is used.

## Prerequisites

- The `NetworkComponent` is attached in the scene (namespace `GameFrameX.Network.Runtime`).
- The transport method has been determined: system TCP by default; when WebSocket is required, the define `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` or `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` must be enabled.
- A channel helper class is ready (you can directly use the framework's built-in `DefaultNetworkChannelHelper`, or implement your own according to its interface).

## Steps

1. Prepare the channel helper. The framework's built-in [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L13) implements all members of `INetworkChannelHelper` and can be reused directly or used as a template for a custom helper:

   | Member | Signature (from DefaultNetworkChannelHelper) | Description |
   |------|------|------|
   | `SetChannelSerializer` | `void SetChannelSerializer(IMessageSerializer serializer)` | Sets the channel-level message serializer; must be called before `Initialize` |
   | `Initialize` | `void Initialize(INetworkChannel netChannel)` | Saves the channel reference, registers handlers via reflection, and subscribes to network events |
   | `PrepareForConnecting` | `void PrepareForConnecting()` | Sets the Socket send/receive buffers to `1024 * 64 - 1` before connecting |
   | `SendHeartBeat` | `bool SendHeartBeat()` | Builds and sends a heartbeat packet using `PacketHeartBeatHandler` |
   | `SerializePacketHeader<T>` | `bool SerializePacketHeader<T>(T messageObject, MemoryStream destination, out byte[] messageBodyBuffer) where T : MessageObject` | Delegates to the channel's `PacketSendHeaderHandler` |
   | `SerializePacketBody` | `bool SerializePacketBody(byte[] messageBodyBuffer, MemoryStream destination)` | Delegates to the channel's `PacketSendBodyHandler` |
   | `DeserializePacketHeader` | `bool DeserializePacketHeader(byte[] source)` | Delegates to the channel's `PacketReceiveHeaderHandler` |
   | `DeserializePacketBody` | `bool DeserializePacketBody(byte[] source, int messageId, out MessageObject messageObject)` | Delegates to the channel's `PacketReceiveBodyHandler` |
   | `Clear` | `void Clear()` | Closes the channel (`NetworkCloseReason.Dispose` / `NetworkErrorCode.DisposeError`) and cleans up references |

2. (Optional) Set a channel-level serializer for the helper. Note that it must be called before channel initialization (`Initialize`), otherwise an exception is thrown:

   ```csharp
   public void SetChannelSerializer(IMessageSerializer serializer)
   {
       if (m_NetworkChannel != null)
       {
           throw new InvalidOperationException(
               "SetChannelSerializer must be called before Initialize().");
       }
       m_ChannelSerializer = serializer;
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L32-L40)

3. Call `NetworkComponent.CreateNetworkChannel` to create the channel. `channelName` must not be empty, the timeout is taken from the component's `m_rpcTimeout`, and the message ID lists for ignored logs are applied automatically:

   ```csharp
   public INetworkChannel CreateNetworkChannel(string channelName, INetworkChannelHelper networkChannelHelper)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
       networkChannel.SetIgnoreLogNetworkIds(m_IgnoredSendNetworkIds, m_IgnoredReceiveNetworkIds);
       return networkChannel;
   }
   ```

   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L176-L182)

4. TCP / WebSocket is selected automatically by compilation defines and cannot be switched at runtime. The selection logic is located in `NetworkManager.CreateNetworkChannel`:

   ```csharp
   #if (ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL) || FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET
       NetworkChannelBase networkChannel = new WebSocketNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #else
       NetworkChannelBase networkChannel = new SystemTcpNetworkChannel(channelName, networkChannelHelper, rpcTimeout);
   #endif
   ```

   Source: [NetworkManager.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.cs#L220-L224)

   Both underlying implementations are sealed subclasses of `NetworkChannelBase : INetworkChannel, IDisposable`, located in [NetworkManager.SystemTcpNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/SystemSocket/NetworkManager.SystemTcpNetworkChannel.cs#L45) and [NetworkManager.WebSocketNetworkChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/WebSocket/NetworkManager.WebSocketNetworkChannel.cs#L48) respectively.

5. During channel initialization, the helper reflection-scans assemblies and automatically registers handlers that implement the corresponding interfaces with the channel (receive header, receive body, send header, send body, heartbeat, compression, decompression). Therefore, custom handlers only need to implement the corresponding interfaces:

   ```csharp
   if (type.IsImplWithInterface(packetReceiveHeaderHandlerBaseType))
   {
       var handler = (IPacketReceiveHeaderHandler)Activator.CreateInstance(type);
       m_NetworkChannel.RegisterHandler(handler);
   }
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L86-L90)

6. Use the returned `INetworkChannel` to connect to the target server, and subscribe to the four event types — connect/close/heartbeat miss/error — in the event component. The helper has already subscribed in `Initialize`, and `NetworkComponent` forwards them as global events:

   ```csharp
   Event.CheckSubscribe(NetworkConnectedEventArgs.EventId, OnNetworkConnectedEventArgs);
   Event.CheckSubscribe(NetworkClosedEventArgs.EventId, OnNetworkClosedEventArgs);
   Event.CheckSubscribe(NetworkMissHeartBeatEventArgs.EventId, OnNetworkMissHeartBeatEventArgs);
   Event.CheckSubscribe(NetworkErrorEventArgs.EventId, OnNetworkErrorEventArgs);
   ```

   Source: [DefaultNetworkChannelHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Helper/DefaultNetworkChannelHelper.cs#L125-L128)

7. Destroy the channel when it is no longer needed:

   ```csharp
   public bool DestroyNetworkChannel(string channelName)
   {
       GameFrameworkGuard.NotNullOrEmpty(channelName, nameof(channelName));
       return m_NetworkManager.DestroyNetworkChannel(channelName);
   }
   ```

   Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L190-L194)

## Common Variants

- **Reuse the default helper directly**: Most projects can simply call `CreateNetworkChannel("main", new DefaultNetworkChannelHelper())` together with handler classes implementing `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler` / `IPacketSendHeaderHandler` / `IPacketSendBodyHandler` / `IPacketHeartBeatHandler` / `IMessageCompressHandler` / `IMessageDecompressHandler`; registration is done automatically via reflection.
- **Switch to WebSocket**: Add the define `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` in Player Settings (forces WebSocket on non-WebGL platforms), or use `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` (for the WebGL platform).
- **Multiple coexisting channels**: Create multiple channels for different servers/gateways, each with its own uniquely named `channelName` and helper instance; `NetworkComponent.GetAllNetworkChannels()` can retrieve all channels (see [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L154-L157)).

## Common Errors

| Symptom/Error | Cause | How to Avoid |
|------|------|------|
| `SetChannelSerializer must be called before Initialize().` | `SetChannelSerializer` was called after channel initialization (`Initialize` has already assigned the channel to the helper) | Call `SetChannelSerializer` first, then perform creation/initialization |
| Creating a channel throws a parameter validation exception | `channelName` is empty or null | Pass a non-empty channel name (`GameFrameworkGuard.NotNullOrEmpty`) |
| Wanted WebSocket but TCP is used | The current defines do not hit the WebSocket branch | Confirm that the define `ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL` or `FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET` is in effect |
| `GameFrameworkGuard.NotNull` thrown during serialization | The channel has not registered `PacketSendHeaderHandler` / `PacketSendBodyHandler` yet | Confirm that the corresponding handler classes exist and implement the relevant interfaces so they can be registered via reflection |

## Verification

- If `CreateNetworkChannel` returns a non-null `INetworkChannel` instance, the channel was created successfully.
- Use a breakpoint or logs in `Initialize` to confirm that `IPacketReceiveHeaderHandler`, `IPacketSendBodyHandler`, etc. have been registered via `RegisterHandler`.
- Receiving the `NetworkConnectedEventArgs` event indicates a successful connection; `NetworkErrorEventArgs` and `NetworkClosedEventArgs` can be used to check failure reasons.

## Background

The channel helper (`INetworkChannelHelper`) is the adaptation layer between the channel and the concrete packet format: when sending, messages are handed to `IPacketSendHeaderHandler` / `IPacketSendBodyHandler` to build packets; when receiving, they are unpacked into `MessageObject` via `IPacketReceiveHeaderHandler` / `IPacketReceiveBodyHandler`; heartbeat, compression, and decompression are also handled through the registered handlers. The transport layer (TCP or WebSocket) is determined by compilation defines inside `NetworkManager.CreateNetworkChannel` and is transparent to business code.
