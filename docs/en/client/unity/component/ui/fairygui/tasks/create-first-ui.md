# How to Create Your First FairyGUI UI

This page walks you through building a FairyGUI UI from scratch that can be opened by GameFrameX: export a package in the FairyGUI editor → attach `FairyGUIPackageComponent` in the Unity scene → write a UI logic class implementing `IUIForm` → open it via the UI manager. This package (`com.gameframex.unity.ui.fairygui`) is responsible for connecting FairyGUI packages to GameFrameX's UI framework.

## Prerequisites

| Dependency | Description |
|------|------|
| GameFrameX Framework | This package's code references the `GameFrameX.Asset.Runtime`, `GameFrameX.Runtime`, and `GameFrameX.UI.Runtime` namespaces; the corresponding Asset / UI base packages must be installed first |
| FairyGUI Editor | Create and export UI packages in the FairyGUI editor (this repository only provides the Unity runtime hosting) |
| `FairyGUIPackageComponent` | This component must exist in the scene, otherwise initialization fails with an assertion immediately (see step 2 below) |

## Steps

1. **Create a component in the FairyGUI editor**. Create a component (e.g., `MainPanel`), then publish and export it to the Unity project.
2. **Make sure the scene has `FairyGUIPackageComponent` attached**. This package's `UIManager` forcibly retrieves this component when setting the asset manager; if it cannot be retrieved, an assertion is thrown immediately:

```csharp
public override void SetResourceManager(IAssetManager assetManager)
{
    base.SetResourceManager(assetManager);
    FairyGuiPackage = GameEntry.GetComponent<FairyGUIPackageComponent>();
    GameFrameworkGuard.NotNull(FairyGuiPackage, nameof(FairyGuiPackage));
}
```
Source: [Runtime/UIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs#L87-L92)

This component is responsible for loading and managing FairyGUI packages; the editor side provides a companion Inspector ([Editor/Inspector/FairyGUIPackageComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Editor/Inspector/FairyGUIPackageComponentInspector.cs)).

3. **Write the UI logic class and annotate the UI group**. The class must implement `IUIForm` (the base class is defined in the GameFrameX.UI base package). `FairyGUIFormHelper` attaches the logic component to the FairyGUI component's `displayObject.gameObject`, then reads the `OptionUIGroupAttribute` on the class to determine its UI group:

```csharp
GComponent component = uiFormInstance as GComponent;
if (component == null)
{
    Log.Error("UI form instance is invalid.");
    return null;
}

var componentType = component.displayObject.gameObject.GetOrAddComponent(uiFormType);
var uiForm = componentType as IUIForm;
if (uiForm == null)
{
    Log.Error("UI form instance is invalid.");
    return null;
}

if (uiForm.IsAwake == false)
{
    uiForm.OnAwake();
}

var uiGroup = uiForm.UIGroup;

if (uiGroup == null)
{
    var attribute = uiFormType.GetCustomAttribute(typeof(OptionUIGroupAttribute));
    if (attribute is OptionUIGroupAttribute optionUIGroup)
    {
        uiGroup = m_UIComponent.GetUIGroup(optionUIGroup.GroupName);
    }

    uiForm.UIGroup = uiGroup;
}
```
Source: [Runtime/FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L84-L115)

Key points: logic classes that do not implement `IUIForm` are rejected and print `UI form instance is invalid.`; the UI group name comes from the `GroupName` property of `OptionUIGroupAttribute`.

4. **Open the UI via the UI manager**. The public open entry point is defined in `BaseUIManager` of the GameFrameX.UI base package (the `UIManager` in this package is an `internal` implementation class and is not directly exposed). This package completes FairyGUI loading and instantiation by overriding the following entry point:

```csharp
protected override async Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
```
Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L64)

The one that actually creates the FairyGUI object is `FairyGUIFormHelper.InstantiateUIForm`, which calls `UIPackage.CreateObject` with the package name + component name:

```csharp
public override object InstantiateUIForm(object uiFormAsset)
{
    var openUIFormInfoData = (OpenUIFormInfoData)uiFormAsset;
    GameFrameworkGuard.NotNull(openUIFormInfoData, nameof(uiFormAsset));

    return UIPackage.CreateObject(openUIFormInfoData.PackageName, openUIFormInfoData.UIName);
}
```
Source: [Runtime/FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L63-L69)

Therefore, the asset path must resolve to the correct `PackageName` and `UIName`; both must match what was exported from the FairyGUI editor.

5. **Listen for the open result** (optional). After a successful open, `UIManager` fires a success event; on failure, the failure callback is invoked instead:

```csharp
if (m_OpenUIFormSuccessEventHandler != null)
{
    OpenUIFormSuccessEventArgs openUIFormSuccessEventArgs = OpenUIFormSuccessEventArgs.Create(uiForm, duration, userData);
    m_OpenUIFormSuccessEventHandler(this, openUIFormSuccessEventArgs);
}
```
Source: [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L255-L258)

## Common Variants

- **Asynchronous opening**: `InnerOpenUIFormAsync` is the asynchronous entry point. If the package has not been loaded yet, `UIManager.Open` first records the context via `OpenUIFormInfoData.Create(serialId, packageName, uiFormAssetName, uiFormType, pauseCoveredUIForm, userData)` and loads the asset asynchronously; once loading completes, instantiation is done via `LoadAssetSuccessCallback`; if the package does not exist, it goes through `LoadAssetFailureCallback` (see [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L137-L188)).
- **Full-screen UI**: The `isFullScreen` parameter of `InnerOpenUIFormAsync` (default `false`) specifies full-screen behavior and is passed all the way to `InternalOpenUIForm` (see [Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L209)).
- **Show animation control**: `FairyGUIFormHelper.CreateUIForm` also reads the `OptionUIShowAnimationAttribute` on the logic class to write to `uiForm.EnableShowAnimation` ([Runtime/FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L117-L120)).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Assertion failure during initialization (`FairyGuiPackage` is null) | The scene is missing `FairyGUIPackageComponent` | Add this component to the scene's GameEntry before running ([Runtime/UIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs#L90-L91)) |
| Log reports `UI form instance is invalid.` | The passed-in logic type does not implement `IUIForm` | The UI logic class must implement the `IUIForm` interface |
| UI instantiation returns null | The package name/component name of `UIPackage.CreateObject` does not match the FairyGUI export | Verify the package name and component name exported from FairyGUI |
| Open failure goes through the failure callback | The UI package asset failed to load | Follow the `LoadAssetFailureCallback` path and check the asset path and loading configuration ([Runtime/UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.Open.cs#L186-L188)) |

## Verification

- If the `IUIForm` returned by `InnerOpenUIFormAsync` is non-null and `m_OpenUIFormSuccessEventHandler` receives `OpenUIFormSuccessEventArgs`, it means the UI has been successfully created and attached.
- In the Unity hierarchy, you should see your logic component added to the FairyGUI component's `displayObject.gameObject`.

## Background (Optional)

This package's implementation has a three-layer structure: `FairyGUIPackageComponent` handles FairyGUI package loading, `UIManager` (`internal sealed partial class UIManager : BaseUIManager`) handles the open/close workflow and lifecycle, and `FairyGUIFormHelper` (`public class FairyGUIFormHelper : UIFormHelperBase`) handles the actual instantiation and attaching the logic class to `GComponent`. The runtime source code is located in the [Runtime](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/UIManager.cs) directory (`UIManager.cs`, `UIManager.Open.cs`, `UIManager.Close.cs`, `FairyGUIFormHelper.cs`, `FairyGUIPackageComponent.cs`, etc.).
