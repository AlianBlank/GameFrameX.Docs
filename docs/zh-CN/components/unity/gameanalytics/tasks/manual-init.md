# 如何手动初始化（ManualInit 使用场景）

在 GameAnalytics 组件自动初始化完成之后,调用 `GameAnalyticsComponent.ManualInit(extraArgs)` 可把登录后的玩家 ID、渠道号等**运行时才能拿到的参数**补充传给支持手动初始化的数据分析管理器。典型场景:SDK 需要等玩家登录拿到账号后才能真正上报,这时在登录成功回调里调一次 `ManualInit` 即可。

## 前置条件

- 场景中已有 `GameAnalyticsComponent`(菜单 `Game Framework/GameAnalytics`),并在 Inspector 的「游戏数据分析组件列表,按序上报」中配置了至少一个 `ComponentType` 与其 `Setting` 键值对。
- 目标管理器实现了 `IsManualInit()` 并在需要手动初始化时返回 `true`——只有这类管理器才会接收 `ManualInit` 传入的参数。

## 操作步骤

1. **保持组件自动初始化可用。** 组件在 `OnEnable()` 里自动执行一次 `Init()`,按 Inspector 配置反射创建各管理器并调用其 `Init(args)`(参数来自 `Setting` 键值对),随后把内部标记 `m_IsInit` 置为 `true`:

    ```csharp
    private void OnEnable()
    {
        Init();
    }
    ```

    Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L27-L30)

2. **确认自动初始化已生效。** 检查 Console 没有出现 `Can not find component type '...'` 报错;该报错表示 Inspector 里的 `ComponentType` 填错,对应管理器不会被创建,后续 `ManualInit` 也轮不到它。

3. **在合适时机调用 `ManualInit`,传入运行时参数。** 例如玩家登录成功、拿到账号 ID/渠道信息之后,通过场景中的 `GameAnalyticsComponent` 实例调用一次:

    ```csharp
    Dictionary<string, string> extraArgs = new Dictionary<string, string>();
    // 填入运行时才能确定的数据,例如账号、渠道等
    gameAnalyticsComponent.ManualInit(extraArgs);
    ```

    组件层的真实实现如下——注意它先检查 `m_IsInit`,再只对 `IsManualInit()` 为 `true` 的管理器转发参数:

    ```csharp
    public void ManualInit(Dictionary<string, string> extraArgs)
    {
        if (!m_IsInit)
        {
            return;
        }

        foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
        {
            if (gameAnalyticsManager.IsManualInit())
            {
                gameAnalyticsManager.ManualInit(extraArgs);
            }
        }
    }
    ```

    Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L82-L100)

4. **(可选)在手动初始化后再补玩家 ID 等通用信息。** `ManualInit` 只是透传参数,不负责后续属性;登录后可继续调用 `SetPlayerId(playerId)` / `SetPublicProperties(key, value)`,这些方法同样要求 `m_IsInit == true`。

## 常见变体

- **无额外参数、仅触发各 SDK 的"就绪"回调**:传入空字典调用 `gameAnalyticsComponent.ManualInit(new Dictionary<string, string>());` 即可,管理器侧自行决定如何处理。
- **自定义管理器接入手动初始化**:继承 `BaseGameAnalyticsManager` 并实现两个抽象方法,把 `IsManualInit()` 返回 `true` 即可让组件把 `extraArgs` 转发给你:

    ```csharp
    public abstract void Init(Dictionary<string, string> args);
    public abstract void ManualInit(Dictionary<string, string> args);
    ...
    public abstract bool IsManualInit();
    ```

    Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L28-L50)

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 调了 `ManualInit` 没有任何反应 | 组件的 `Init()` 尚未执行,`m_IsInit` 为 `false`,方法第一行直接 `return` | 等组件 `OnEnable()` 完成自动初始化后再调用(登录回调等时机通常已满足) |
| 某个管理器收不到 `extraArgs` | 该管理器的 `IsManualInit()` 返回 `false` | 在管理器实现中让 `IsManualInit()` 返回 `true` |
| Console 输出 `Can not find component type '...'` | Inspector 中 `ComponentType` 类型名填写错误或程序集未编译 | 修正 `ComponentType`,确保类型实现 `IGameAnalyticsManager` |
| SDK 参数仍是 Inspector 里 `Setting` 的旧值 | `ManualInit` 传入的是补充参数,不会替换 `Init` 时由 `Setting` 提供的基础参数 | 基础配置仍放在 Inspector 的 `Setting`;运行时数据走 `ManualInit` |

## 背景

GameAnalytics 采用"两层初始化":`Init(args)` 在组件 `OnEnable()` 时用 Inspector `Setting` 的静态配置自动执行,负责创建管理器;`ManualInit(extraArgs)` 面向需要运行时数据(如登录后的账号)的 SDK,由业务在明确时机显式触发,且只作用于声明了 `IsManualInit() == true` 的管理器。完整接口定义见 [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L28)。
