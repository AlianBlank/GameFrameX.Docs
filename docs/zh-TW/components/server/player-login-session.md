# 如何處理玩家登入與會話（Session）

本頁面幫助您完成兩件事：讓玩家透過客戶端訊息完成登入，以及在帳號頂替/斷線時正確管理玩家的網路會話。完成後，玩家可以進入遊戲邏輯，伺服器也能正確清理離線玩家。

## 前置條件

- 客戶端使用框架網路層（KCP/HTTP）發起請求，登入訊息使用 Protobuf 協定編號 `ReqPlayerLogin` / `RespPlayerLogin`。
- 伺服器已啟動 `GameApp` 並註冊 `SessionManager`（框架啟動時自動載入）。
- 帳號服務 `LoginComponent` 存在（位於 [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs)），並且可以透過帳號 Token 取得 `roleId`。

## 操作步驟

### 1. 實作登入請求處理器

新建一個 `ReqPlayerLoginHandler`，繼承自 `GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>`。框架會根據 `[MessageMapping]` 自動路由訊息。

```csharp
using GameFrameX.Hotfix.Logic.Player.Login;
using GameFrameX.Apps.Player.Login.Component;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[MessageMapping(typeof(ReqPlayerLogin))]
internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
{
    protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
    {
        await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
    }
}
```

來源：[ReqPlayerLoginHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L30-L38)

### 2. 在 LoginComponentAgent 中完成綁定

`OnPlayerLogin` 內部依序執行四件事：驗證帳號/簽名 → 取得 `roleId` → 將 `roleId` 與 `sign` 寫入當前 `Session` → 呼叫 `SessionManager.UpdateSession` 完成綁定並觸發帳號頂替邏輯。

```csharp
// 虛擬碼，展示呼叫順序，實際簽名請參見 LoginComponentAgent
var loginResult = await LoginComponent.LoginByToken(request.AccountToken); // 回傳 roleId / sign
NetWorkChannel.Session.SetPlayerId(loginResult.RoleId);
NetWorkChannel.Session.SetSign(loginResult.Sign);
await SessionManager.UpdateSession(NetWorkChannel.Session.SessionId, loginResult.RoleId, loginResult.Sign);
```

實際的函式簽名由 `LoginComponentAgent.OnPlayerLogin(NetWorkChannel, request, response)` 提供，詳見 [LoginComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs)。

### 3. 監聽會話移除事件以完成離線清理

實作 `SessionRemoveEventListener`。當會話被移除（主動 `Remove` 或被頂替時清除）時，框架會派發 `EventId.SessionRemove` 事件，觸發玩家離線邏輯。

```csharp
using GameFrameX.Apps.Common.Event;
using GameFrameX.Core.Abstractions.Events;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

來源：[SessionRemoveEventListener.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L30-L42)

### 4. 帳號頂替與會話替換（由框架實作）

`SessionManager.UpdateSession` 內部先呼叫 `GetByRoleId(roleId)` 查找舊會話，然後透過 `WriteAsync` 向舊連線發送一條 `Type=5` 提示訊息（`Apps.SessionManager.AccountAlreadyLoggedIn` 本地化文字），接著執行 `ClearData()` + `Close()`，最後 `Remove(oldSession.SessionId)`。業務端無需重新實作帳號頂替，只需確保呼叫 `UpdateSession` 即可。

```csharp
// 摘錄自 SessionManager.UpdateSession
var oldSession = GetByRoleId(roleId);
if (oldSession != null)
{
    var msg = new RespPrompt { Type = 5,
        Content = LocalizationService.GetString(Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn) };
    await oldSession.WriteAsync(msg);
    oldSession.WorkChannel.ClearData();
    oldSession.WorkChannel.Close();
    Remove(oldSession.SessionId);
}
```

來源：[SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L216-L240)

## 常見變體

| 場景 | 做法 |
|------|------|
| 同一玩家在同一裝置上重複登入 | `Session.Sign` 相同，直接走 `UpdateSession` 替換綁定，不會踢掉舊連線 |
| 同一玩家在不同裝置上登入 | `Sign` 不同，舊會話被關閉並收到 `Type=5` 提示訊息 |
| 透過 HTTP 登入 | 由 [ReqLoginHttpHandler](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs) 處理，業務端取得 `roleId` 後，再走客戶端 `ReqPlayerLogin` 完成綁定 |
| GM 強制踢人 | 呼叫 `SessionManager.KickOffLineByUserId(roleId)`，將自動派發 `SessionRemove` 事件 |

## 常見錯誤

- **忘記呼叫 `UpdateSession`**：登入驗證通過但 `roleId` 未綁定，後續透過 `PlayerId` 查詢找不到會話，所有玩家邏輯失效。
- **未監聽 `SessionRemove`**：斷線後玩家物件未被清理，導致資源洩漏與重連時出現髒資料。
- **帳號頂替文字未本地化**：使用寫死的字串，直接繞過 `LocalizationService.GetString`，會導致多語言環境下提示錯誤。
- **手動 `Remove` 會話後又手動 `Close`**：框架已在 `UpdateSession` 內部處理舊連線的關閉，業務端再次呼叫會重複觸發 `SessionRemove`。

## 背景（選讀）

- `Session` 是連線層級的物件，內部持有 `INetWorkChannel`，並透過 `SetData(GlobalConst.SessionIdKey, ...)` 與網路通道互相綁定。
- `SessionManager` 使用 `ConcurrentDictionary<string, Session>` 儲存會話，並維護 `PlayerRouteMap` 用於跨伺服器路由；帳號頂替時採用先 `Remove` 再等待 `Disconnected` 回呼的方式，避免清理延遲。
- 帳號頂替提示訊息 `Type=5` 由 `RespPrompt` 協定承載，文字來自 `Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn`。
