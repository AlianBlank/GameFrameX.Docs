# ホットアップデート方法:バージョン確認、マニフェスト更新、パッチダウンロード

ホットアップデートは `EPatchStates` 列挙型で定義された 5 つの状態によって駆動されます:`UpdateStaticVersion`(静的リソースバージョン更新)→ `UpdateManifest`(パッチマニフェスト更新)→ `CreateDownloader`(ダウンローダー作成)→ `DownloadWebFiles`(リモートファイルダウンロード)→ `PatchDone`(パッチフロー完了)。本タスクでは「パッチ起動 → 状態変更の購読 → 失敗時のロールバック → メインフローへの遷移」を通し、ビジネスコード内で完全なホットアップデートチェーンを動作させます。

## 前提条件

- `GameFrameX.Runtime` の `GameEntry` を介して `AssetComponent` インスタンスを取得済みであること(フレームワークのエントリーポイントについては『クイックスタート』を参照)。
- リモートサーバーが YooAsset のディレクトリ構造に従ってデプロイ済みであること:ルートディレクトリ配下の `{platform}/{version}/{packageName}` には `GameVersion.txt`、`{packageName}_PatchManifest_{version}.bytes`、`{packageName}_StaticVersion_{version}.bytes` などのファイルが含まれている必要があります。
- プロジェクト内の `AssetPatchStatesChangeEventArgs` などのイベント型を保持しておく必要があります(コードには既に `[UnityEngine.Scripting.Preserve]` が付与されており、削除されないようにしています)。

## 操作手順

### 1. パッチ状態変更イベントを購読する

`GameFrameX` のイベントバスを介して `AssetPatchStatesChangeEventArgs` を購読します。次の状態に進むたびにコールバックを受信し、進捗バー UI の更新に利用できます。

```csharp
GameEntry.Event.Subscribe(AssetPatchStatesChangeEventArgs.EventId, OnPatchStatesChange);

private void OnPatchStatesChange(object sender, GameEventArgs e)
{
    var args = (AssetPatchStatesChangeEventArgs)e;
    // args.PackageName: 現在更新中のリソースパッケージ名
    // args.CurrentStates: EPatchStates 列挙型(下表参照)
    Debug.Log($"[{args.PackageName}] 段階進入:{args.CurrentStates}");
}
```

Source: [AssetPatchStatesChangeEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchStatesChangeEventArgs.cs#L18-L46)

### 2.「更新対象ファイル検出」と「ダウンロード進捗」イベントを購読する(任意だが推奨)

この 2 つのイベントは UI 上で「ダウンロード対象のファイル総数」「現在何個目をダウンロード中か / 合計サイズ」を表示するために使用します。

| イベント EventId | イベント引数 | 発火タイミング | キーフィールド |
|---|---|---|---|
| `AssetFoundUpdateFilesEventArgs.EventId` | `AssetFoundUpdateFilesEventArgs` | CreateDownloader の後、DownloadWebFiles の前 | ダウンロード対象ファイル総数、合計サイズ |
| `AssetDownloadProgressUpdateEventArgs.EventId` | `AssetDownloadProgressUpdateEventArgs` | 各ファイルのダウンロード中 | 現在の進捗、ダウンロード済み / 合計サイズ、残りサイズ |

### 3. 失敗イベントを購読し、ロールバックを処理する

ホットアップデート中のいずれかのステップが失敗すると、対応するイベント引数が発行されるため、購読箇所でリトライやフォールバック処理を行う必要があります:

```csharp
GameEntry.Event.Subscribe(AssetStaticVersionUpdateFailedEventArgs.EventId, OnStaticVersionFailed);
GameEntry.Event.Subscribe(AssetPatchManifestUpdateFailedEventArgs.EventId, OnManifestFailed);
GameEntry.Event.Subscribe(AssetWebFileDownloadFailedEventArgs.EventId, OnFileDownloadFailed);
```

### 4. ホットアップデートフローを起動する

`AssetComponent` が提供する更新エントリを呼び出します(実際のシグネチャは現在のリポジトリ `Runtime/Asset/AssetComponent.cs` を参照してください)。1 回のパッチセッションは順に以下の 5 つの状態に進みます:

```csharp
// Boot 段階(GameEntry 起動後)に一度だけ呼び出す
var assetComponent = GameEntry.GetComponent<AssetComponent>();
assetComponent.UpdatePackages(); // バージョン番号取得 → マニフェスト比較 → ダウンローダー作成 → ダウンロード → PatchDone コールバック
```

トリガー後、イベントバスは順にブロードキャストします:
1. `EPatchStates.UpdateStaticVersion` —— リモートの `GameVersion.txt` とローカルキャッシュのバージョンを比較。
2. `EPatchStates.UpdateManifest` —— `{packageName}_PatchManifest_{version}.bytes` を取得し、ローカルのマニフェストと差分検出。
3. `EPatchStates.CreateDownloader` —— `AssetDownloadProgressUpdateEventArgs` などで利用するダウンローダーを構築。
4. `EPatchStates.DownloadWebFiles` —— 実際に差分ファイルをダウンロード。各ファイルごとに `AssetDownloadProgressUpdateEventArgs` を一度コールバック。
5. `EPatchStates.PatchDone` —— フロー完了。安全にメインシーンへ遷移可能。

## よくあるバリエーション

| シナリオ | 対応方法 |
|---|---|
| チェックをスキップしてローカルリソースを直接使用 | `AssetComponent` の「ローカルのみ」初期化オーバーロードを呼び出し、`UpdatePackages` にはそもそも進まない |
| 単一のリソースパッケージのみを更新 | `UpdatePackages` の前に `SetForceUpdateAllPackageVersions(true)` のようなスイッチで対象範囲を制御 |
| レジュームダウンロード | イベント `AssetDownloadProgressUpdateEventArgs` にダウンロード済みバイト数が保持されているため、`UpdatePackages` を再呼び出しすると未完了ファイルを自動でレジューム |

## よくあるエラー

| 症状 | 考えられる原因 | 回避方法 |
|---|---|---|
| `EPatchStates.PatchDone` がいつまで経っても発火しない | イベントが購読されていない、または購読した EventId のスペルミス | EventId は手書き文字列ではなく `typeof(AssetPatchStatesChangeEventArgs).FullName` を使用 |
| ダウンロード途中で無反応になる | `AssetDownloadProgressUpdateEventArgs` を購読しておらず、ダウンローダーがメインスレッドで待機している可能性がある | ダウンローダーは別個の非同期コンテキストで実行し、UI に進捗を表示 |
| リモートマニフェストが 404 | サーバーに `{packageName}_PatchManifest_{version}.bytes` がデプロイされていない | フレームワーク付属のアップロードツール(YooAsset 公式 Builder を参照)で再アップロード。`AssetPatchManifestUpdateFailedEventArgs` にエラー情報が含まれる |
| 静的バージョンファイルのダウンロード失敗 | サーバーに `{platform}/GameVersion.txt` が無い、またはキャッシュディレクトリが読み取り専用 | `Application.persistentDataPath` の書き込み権限を確認。`AssetStaticVersionUpdateFailedEventArgs` を監視 |

## 背景(任意)

`EPatchStates` は YooAsset の一連のパッチライフサイクルを 5 つの列挙値として抽象化しています。フレームワーク層は状態遷移時に `AssetPatchStatesChangeEventArgs` を `GameFrameX` のイベントバスに投げる役割のみで、ビジネス側は EventId を購読することで疎結合化されます。これにより UI、ネットワークリトライ、フォールバック戦略を無侵襲で差し替え可能となり、パッチのメインフローは安定して保たれます。
