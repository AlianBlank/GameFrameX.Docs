# Android 압축 StreamingAsset 이벤트 처리

APK 빌드(특히 App Bundle)에서 `StreamingAssets` 디렉토리 아래의 파일이 APK로 압축 저장되면, Unity는 파일 오프셋을 통해 직접 읽을 수 없습니다. 본 프레임워크는 초기화 시 APK의 Central Directory를 스캔하여, 이러한 파일을 발견하면 `CompressedStreamingAssetFound` 이벤트를 트리거하여 런타임에 이를 가로채고 처리할 수 있게 합니다.

## 사전 조건

- `UNITY_ANDROID` 또는 `UNITY_EDITOR`(`InitializeWithExternalApk` 사용) 플랫폼에서만 이벤트 시그니처가 실제로 존재합니다; 다른 플랫폼에서는 `add`/`remove`가 빈 연산(no-op)입니다.
- 프로젝트가 `BlankReadAssets.Initialize()` 또는 `BlankReadAssets.Root`를 통해 초기화되었는지 확인하세요(임의의 API에 처음 접근할 때 자동으로 트리거됨).

## 작업 단계

1. **이벤트 구독**. 이벤트 시그니처는 `Func<string, bool>`이며, APK 내 파일의 전체 이름을 수신하여(예: `"assets/config/data.json"`) `true`를 반환하면 처리되었음을 의미하며 프레임워크는 더 이상 경고를 출력하지 않습니다:

```csharp
using GameFrameX.ReadAssets.Runtime;

BlankReadAssets.CompressedStreamingAssetFound += fileName =>
{
    // fileName은 "assets/xxx.bin"과 같은 형태
    if (fileName.EndsWith(".json"))
    {
        // 폴백 로직: 원격에서 다운로드 / persistentDataPath에서 복사 / 내장된 기본값 등
        Debug.Log($"처리된 압축 StreamingAsset: {fileName}");
        return true;
    }
    return false;
};
```

2. **초기화 전에 구독**. 이벤트는 `ApkImpl.Initialize` → `GetStreamingAssetsInfoFromJar`가 APK를 스캔할 때 트리거되므로, 구독은 첫 번째 읽기보다 먼저 이루어져야 하며, `RuntimeInitializeOnLoadMethod`에 배치하는 것을 권장합니다:

```csharp
using UnityEngine;
using GameFrameX.ReadAssets.Runtime;

public static class Bootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSplashScreen)]
    private static void Init()
    {
        BlankReadAssets.CompressedStreamingAssetFound += OnCompressed;
    }

    private static bool OnCompressed(string fileName)
    {
        // true를 반환하면 "처리됨"을 의미하며, 프레임워크는 조용히 처리함
        return false;
    }
}
```

3. **(선택 사항) Editor에서 검증**. `InitializeWithExternalApk`를 통해 실제 APK를 로드하면 에디터에서도 동일한 이벤트를 트리거할 수 있어 디버깅에 편리합니다:

```csharp
BlankReadAssets.InitializeWithExternalApk(@"C:\builds\game.apk");
```

이벤트는 `InitializeWithExternalApk`과 동일한 `ApkImpl` 스캔 로직을 공유합니다([BlankReadAssets.ApkImpl.cs#L294-L354](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L294-L354)).

## 일반적인 변형

- **구독하지 않고 조용히 처리**. 분할 메서드 `AndroidIsCompressedFileStreamingAsset`를 구현하여 `false`를 반환하면 프레임워크가 해당 파일을 직접 무시하고, 이벤트 디스패치도 로그 출력도 하지 않습니다:

```csharp
using GameFrameX.ReadAssets.Runtime;
using UnityEngine;

public partial class BlankReadAssets
{
    static partial void AndroidIsCompressedFileStreamingAsset(string fileName, ref bool isStreamingAsset)
    {
        // 예: 특정 유형의 리소스 차단
        if (fileName.StartsWith("assets/internal/")) isStreamingAsset = false;
    }
}
```

분할 메서드 선언 위치는 [BlankReadAssets.ApkImpl.cs#L334](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L334)를 참조하세요.

- **App Bundle 시나리오**. 프로젝트 자체가 App Bundle(`*.aab`)이고 Google Play에 업로드 후 여러 `.apk`로 분할되는 경우, 프레임워크는 `dataPath`가 `base.apk`가 아닐 때 자동으로 동일 디렉토리의 `base.apk`로 폴백하여 다시 스캔합니다([BlankReadAssets.ApkImpl.cs#L43-L51](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L43-L51)); 이 분기에서도 동일한 이벤트가 트리거되므로 구독 코드를 수정할 필요가 없습니다.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `Debug.LogAssertionFormat`에서 지속적으로 `BlankReadAssets: file ... is where Streaming Assets are put, but is compressed.`를 보고함 | 이벤트를 구독하지 않았고 분할 메서드 필터도 구현하지 않음 | `CompressedStreamingAssetFound`를 구독하거나 `AndroidIsCompressedFileStreamingAsset`를 구현 |
| iOS / Standalone에서 `BlankReadAssets.CompressedStreamingAssetFound += ...` 작성 시 컴파일 오류 발생 | 해당 이벤트는 `UNITY_EDITOR || UNITY_ANDROID`에서만 실제 시그니처가 존재함 | 구독 코드를 `#if UNITY_ANDROID || UNITY_EDITOR`로 감싸기; 또는 무시(다른 플랫폼에서는 no-op) |
| 구독 시점이 너무 늦어 시작 직후 즉시 한 번 트리거됨 | 이벤트가 `Initialize` 내부에서 동기적으로 트리거됨 | `[RuntimeInitializeOnLoadMethod(BeforeSplashScreen)]` 또는 그보다 더 이른 bootstrap에서 구독 |
| `false`를 반환하면 예외가 발생한다고 잘못 생각함 | `false` 반환은 "처리되지 않음"을 의미할 뿐이며, 프레임워크는 구독이 없는 경로로 계속 진행(어설션이 트리거될 수 있음) | 실제로 처리했으면 `true`를 반환 |

## 배경(선택 사항)

Unity는 Android 패키징 시 기본적으로 임계값을 초과하는 APK의 `assets/` 파일을 전체적으로 압축합니다; 하지만 `BlankReadAssets`는 ZIP Central Directory를 통해 직접 `StreamingAssets` 내 파일의 오프셋 + 압축되지 않은 크기를 찾으므로, APK 내 해당 파일이 압축된 경우(`CompressedSize != UncompressedSize`) "오프셋으로 원본 바이트 읽기" 전략이 실패합니다. 따라서 이벤트 메커니즘이 설계되었습니다: 압축된 자산에 대해 어떻게 폴백할지 비즈니스 측에서 결정할 수 있게 합니다([BlankReadAssets.cs#L70-L78](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L70-L78)).
