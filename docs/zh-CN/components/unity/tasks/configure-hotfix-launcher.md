# 如何接入热更新入口(HotfixLauncher)

完成本页配置后,框架启动时会自动加载 AOT DLL 与 Hotfix DLL,并通过反射调用你指定的入口方法,把热更程序集拉起来。

## 前置条件

- 已创建热更程序集 `Unity.Hotfix`(默认 Assembly Definition)。
- 已存在一个静态入口类与无参静态方法(如 `Hotfix.HotfixLauncher.Main`)。
- 已在 `Assets/Resources/StartupOptions.asset` 看到以下三项配置(框架默认已写好):
  - `HotfixAssemblyName: Unity.Hotfix`
  - `HotfixEntryTypeName: Hotfix.HotfixLauncher`
  - `HotfixEntryMethodName: Main`

## 操作步骤

1. **创建入口类**。在 `Assets/Hotfix/` 目录下新建 `HotfixLauncher.cs`,使用默认命名空间 `Hotfix`,并提供一个静态 `Main()` 方法作为热更入口。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX;
   using GameFrameX.UI.Runtime;
   using Hotfix.Config;
   using Hotfix.Config.Local;
   using Hotfix.Config.Tables;
   using Hotfix.UI;

   namespace Hotfix
   {
       public static class HotfixLauncher
       {
           public static void Main()
           {
               Log.Info("Hello World HybridCLR");
               LoadConfig();
               LoadUI();
           }
       }
   }
   ```

   Source: [HotfixLauncher.cs#L26-L34](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L26-L34)

2. **在入口里加载配置与 UI**。框架只会调用你的入口方法,后续的资源、配置、UI 初始化都由此方法驱动。模板项目使用 `TablesComponent` 加载 JSON/二进制配置表,并以 `await` 方式打开登录 UI。

   ```csharp
   private static async void LoadUI()
   {
       await GameApp.UI.OpenAsync<UILogin>();
   }

   static async void LoadConfig()
   {
       _tablesComponent = new TablesComponent();
       _tablesComponent.Init(GameApp.Config);
       await _tablesComponent.LoadAsync(ConfigLoader);
       TranslateText();
   }

   static TablesComponent _tablesComponent;
   ```

   Source: [HotfixLauncher.cs#L36-L61](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L61)

3. **确认 `StartupOptions.asset` 三项键值匹配你的入口**。框架启动器 `HotfixHelper.StartHotfixInternalAsync` 会读取这三个字段去反射调用方法,缺省值见下表;若你改了命名空间或类名,必须同步修改这里。

   | 键 | 默认值 | 作用 |
   |---|---|---|
   | `HotfixAssemblyName` | `Unity.Hotfix` | 待加载的 DLL 名(不含 `.dll`) |
   | `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` | 入口类的完整类型名(命名空间 + 类名) |
   | `HotfixEntryMethodName` | `Main` | 入口方法名,需为 `public static` 无参方法 |

   Source: [HotfixHelper.cs#L62-L70](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70)、[StartupOptions.asset#L24-L26](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Resources/StartupOptions.asset#L24-L26)

4. **确保启动流程已挂上 `ApplicationHotfixLauncher`**。框架入口 `ApplicationStartupEntry` 通过它把启动 UI 处理器与热更启动器接入 `StartupRunner.Run`,无需改动,只要保证引用存在即可。

   ```csharp
   var result = await StartupRunner.Run(startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   Source: [ApplicationStartupEntry.cs#L43](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L43)、[ApplicationHotfixLauncher.cs#L12](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs#L12)

## 常见变体

- **二进制配置表**:在 `HotfixLauncher.LoadConfig` 中把 `LoadAsync(ConfigLoader)` 换成 `LoadAsync(ConfigBufferLoader)`,并在编译选项里打开 `ENABLE_BINARY_CONFIG`(模板已使用 `#if ENABLE_BINARY_CONFIG` 条件编译)。
- **关闭 HybridCLR**(原生 IL2CPP 路径):当 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 或 `DISABLE_HYBRIDCLR` 生效时,`HotfixHelper.StartHotfixInternalAsync` 走 `RunNative` 分支,直接用 `Utility.Assembly.GetType` 反射调用入口,不需要 AOT DLL 加载流程。
- **自定义入口类名**:例如把 `HotfixLauncher` 改成 `MyGame.EntryBoot`,同步把 `StartupOptions.asset` 的 `HotfixEntryTypeName` 改为 `MyGame.EntryBoot`、`HotfixEntryMethodName` 改为 `Boot`。

## 常见错误

- **入口类/方法签名不对**:必须是 `public static`,且无参数;否则 `entryType.GetMethod(entryMethodName)` 会返回 `null`,日志出现 `EntryType=>method ` 后面为空。
- **命名空间或类名拼错**:`HotfixEntryTypeName` 必须使用 `命名空间.类名` 的完整形式,且与 DLL 内的真实命名空间一致,否则 `Run` 中 `entryType.FullName` 抛 `NullReferenceException`。
- **修改了入口但未重启 `StartupOptions.asset`**:改动在运行时不会生效,需要在 Editor 重新选择该 ScriptableObject 或重启 Player。
- **`#if ENABLE_UI_FAIRYGUI` 分支误删**:模板里 FairyGUI 包的加载包裹在条件编译里,如果你使用 FairyGUI 但没有定义该宏,会导致 `LoadUI` 加载 UI 包失败。

## 背景(可选)

`HotfixHelper.StartHotfixInternalAsync` 在编辑器内直接遍历已加载程序集找到 DLL,出包后则按 `AOTGenericReferences.PatchedAOTAssemblyList` 顺序加载 AOT 元数据,再用 `Assembly.Load` 加载 Hotfix DLL,最后通过反射调用入口方法。`ApplicationHotfixLauncher` 只是把 `HotfixHelper` 适配成 `IHotfixLauncher` 接口,以便在 `StartupRunner` 中复用同一套启动流程。
