# 시작 관련 문제 해결 방법

이 페이지에서는 `ProcedureComponent` 시작 단계에서 가장 흔히 발생하는 오류와 예외 상황을 정리하고, [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs) 및 [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs)의 실제 동작을 기반으로 해결 방법을 안내합니다.

## 빠른 진단

| 증상(콘솔 원문) | 원인 | 해결 방법 |
|------|------|------|
| `Procedure manager is invalid.` | 프레임워크가 `GameFrameworkEntry`에서 `IProcedureManager`를 가져오지 못했습니다. 보통 `ProcedureComponent`가 마운트되지 않았거나 컴포넌트의 `Awake`가 실행되지 않은 경우입니다. | [수정 1](#수정-1procedure-manager-is-invalid) 참조 |
| `Available procedure type names is empty. Procedure auto start skipped.` | Inspector의 `Available Procedure Type Names` 배열이 비어 있습니다. | [수정 2](#수정-2available-procedure-type-names-is-empty) 참조 |
| `Can not find procedure type '{0}'.` | `Available Procedure Type Names`의 타입 이름 문자열이 현재 어셈블리에서 해당 `Type`을 찾을 수 없습니다. | [수정 3](#수정-3can-not-find-procedure-type) 참조 |
| `Can not create procedure instance '{0}'.` | 타입 이름은 찾을 수 있지만, `Activator.CreateInstance`로 인스턴스를 생성할 수 없습니다(추상 클래스 / public 생성자 없음). | [수정 4](#수정-4can-not-create-procedure-instance) 참조 |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name`이 `Available Procedure Type Names`에 포함되어 있지 않습니다. | [수정 5](#수정-5entrance-procedure-is-invalid) 참조 |
| `You must initialize procedure first.` | `Initialize` 호출 전에 `StartProcedure` / `HasProcedure` / `GetProcedure` / `CurrentProcedure` / `CurrentProcedureTime`을 호출했습니다. | [수정 6](#수정-6you-must-initialize-procedure-first) 참조 |
| `Procedures is invalid.` | 직접 `m_ProcedureManager.Initialize(..., procedures)`를 호출할 때 빈 배열을 전달했습니다. | [수정 7](#수정-7procedures-is-invalid) 참조 |
| `Already exist FSM.` 시작 후 다시 씬에 진입 | `Use Startup Runner`를 활성화했지만 `ProcedureComponent`가 기존 로직을 계속 실행하여 `ApplicationStartupEntry`에 의해 중복 초기화되었습니다. | [수정 8](#수정-8already-exist-fsm) 참조 |

## 수정 단계

### 수정 1:Procedure manager is invalid

`ProcedureComponent.Awake`에서 다음을 실행합니다:

```csharp
m_ProcedureManager = GameFrameworkEntry.GetModule<IProcedureManager>();
if (m_ProcedureManager == null)
{
    Log.Fatal("Procedure manager is invalid.");
    return;
}
```

확인 방향:

1. `ProcedureComponent`가 마운트된 GameObject가 씬에 존재하는지 확인합니다. 컴포넌트 메뉴 경로는 `GameFrameX/Procedure`입니다.
2. `GameFrameworkEntry`가 정상적으로 초기화되었는지 확인합니다(다른 `GameFrameworkComponent`도 마운트되어 `Awake`가 실행되어야 합니다).
3. 다른 컴포넌트가 `IProcedureManager` 구현체를 등록하여 인터페이스가 점유되고 있는지 확인합니다. 동일한 인터페이스에는 하나의 구현체만 등록할 수 있습니다.
4. IL2CPP / 코드 스트리핑 처리 시, `[Preserve]` 특성이 이미 매니저 클래스에 선언되어 있습니다. 그래도 손실된다면 자체 `link.xml`이 `GameFrameX.Procedure.Runtime`을 포함하는지 확인합니다.

### 수정 2:Available procedure type names is empty

`ProcedureComponent.Start`의 검사:

```csharp
if (m_AvailableProcedureTypeNames == null || m_AvailableProcedureTypeNames.Length <= 0)
{
    Log.Warning("Available procedure type names is empty. Procedure auto start skipped.");
    yield break;
}
```

해결 방법: Inspector의 `Available Procedure Type Names` 배열에 프로시저 클래스의 전체 이름(네임스페이스 + 클래스명)을 최소 한 개 이상 입력합니다.

### 수정 3:Can not find procedure type

해당 코드:

```csharp
Type procedureType = Utility.Assembly.GetType(m_AvailableProcedureTypeNames[i]);
if (procedureType == null)
{
    Log.Error("Can not find procedure type '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

해결 방법:

1. 문자열은 반드시 `Type.FullName`과 정확히 일치해야 합니다. 예: `GameFrameX.Procedure.Runtime.ProcedureLaunch`.
2. 프로시저 클래스를 사용자 정의 어셈블리에 둔 경우, 해당 어셈블리가 로드되었는지 확인합니다(빌드 설정 → Player Settings → "Disable Domain Reload" 체크 해제 시에도 코드가 프로젝트에 컴파일되어 있어야 함).
3. 이름 변경 / 네임스페이스 이동 후 Inspector 동기화를 잊어버린 경우가 가장 흔합니다. 클래스명을 수정한 후에는 반드시 Inspector의 문자열도 함께 수정해야 합니다.

### 수정 4:Can not create procedure instance

해당 코드:

```csharp
procedures[i] = (ProcedureBase) Activator.CreateInstance(procedureType);
if (procedures[i] == null)
{
    Log.Error("Can not create procedure instance '{0}'.", m_AvailableProcedureTypeNames[i]);
    yield break;
}
```

해결 방법: 프로시저 클래스가 `public`이고, public 매개변수 없는 생성자를 가지며, 추상 클래스나 인터페이스가 아니어야 합니다. `ProcedureBase`의 표준 작성법:

```csharp
public sealed class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
    }
}
```

### 수정 5:Entrance procedure is invalid

`Start`에서 진입 프로시저를 매칭합니다:

```csharp
if (m_EntranceProcedureTypeName == m_AvailableProcedureTypeNames[i])
{
    m_EntranceProcedure = procedures[i];
}
```

반복문이 끝날 때까지 `m_EntranceProcedure`가 여전히 `null`이면 `Entrance procedure is invalid.`가 출력됩니다. 해결 방법: `Entrance Procedure Type Name` 필드를 `Available Procedure Type Names` 중 **정확히 동일한** 항목 하나로 설정합니다.

### 수정 6:You must initialize procedure first

`ProcedureManager`의 여러 멤버가 `m_ProcedureFsm == null`일 때 이 예외를 발생시킵니다. 예:

```csharp
public ProcedureBase CurrentProcedure
{
    get
    {
        if (m_ProcedureFsm == null)
        {
            throw new GameFrameworkException("You must initialize procedure first.");
        }
        return (ProcedureBase)m_ProcedureFsm.CurrentState;
    }
}
```

발생 조건: `CurrentProcedure` / `CurrentProcedureTime` / `StartProcedure` / `HasProcedure` / `GetProcedure` 중 어느 하나라도 `Initialize` 호출 전에 접근합니다.

해결 방법:

1. 기본적으로 `ProcedureComponent.Start`가 자동으로 `Initialize` + `StartProcedure`를 수행하므로 직접 호출할 필요가 없습니다.
2. `IProcedureManager`를 직접 보유하고 먼저 접근하는 경우, 다른 멤버에 접근하기 전에 먼저 `Initialize(IFsmManager fsmManager, params ProcedureBase[] procedures)`를 호출합니다.
3. `Use Startup Runner`를 활성화하면 컴포넌트의 `Start`는 자동으로 프로시저를 시작하지 않습니다. 이 경우 `ApplicationStartupEntry` / `StartupRunner.Run`이 초기화를 담당하므로 반드시 실행되도록 해야 합니다.

### 수정 7:Procedures is invalid

`ProcedureManager.Initialize`의 사전 검사:

```csharp
if (procedures.Length <= 0)
{
    throw new GameFrameworkException("Procedures is invalid.");
}
```

해결 방법: `Initialize`에 빈 배열을 전달하지 말고, 최소 하나의 `ProcedureBase` 인스턴스를 전달합니다.

### 수정 8:Already exist FSM

`Use Startup Runner = true`일 때 `ProcedureComponent.Start`는 즉시 종료됩니다:

```csharp
if (m_UseStartupRunner)
{
    yield break;
}
```

이 분기가 존재하는 이유는 `ApplicationStartupEntry` + `StartupRunner.Run`과 중복으로 `Initialize`가 호출되어 `Already exist FSM`(동일한 `IProcedureManager` 보유자가 반복적으로 `CreateFsm`을 호출)이 발생하는 것을 방지하기 위함입니다.

해결 방법: 둘 중 하나만 선택하여 혼용하지 않습니다.

- 기존 모드: `Use Startup Runner = false`, Inspector 배열을 통한 자동 시작에 의존합니다.
- 신규 모드: `Use Startup Runner = true`, `ApplicationStartupEntry`가 `StartupRunner.Run`을 통해 시작 흐름을 인계받습니다.

## 검증

위 수정 사항을 적용한 후, 다음 방법으로 문제가 해결되었는지 확인할 수 있습니다:

1. Play Mode에 다시 진입하여 콘솔에 해당 오류가 더 이상 출력되지 않고, `ProcedureComponent.CurrentProcedure`가 `null`이 아닌지 확인합니다.
2. 첫 번째 프로시저(예: `ProcedureLaunch`)의 `OnEnter`에 로그를 추가하여 로그가 나타나는지 확인합니다. 이는 `StartProcedure`가 실제로生效했다는 의미입니다.
3. 두 번째 프로시저에서 `ChangeState<ProcedureXxx>()`를 호출하여 상태 전환이预期的대로 동작하는지 관찰하여 전체 FSM이 올바르게 초기화되었는지 검증합니다.
4. `Use Startup Runner`를 활성화한 경우, `ApplicationStartupEntry`에서 실제로 `StartupRunner.Run`을 호출하고 진입 프로시저 타입을 전달했는지 확인합니다. 그렇지 않으면 프로시저가 절대 시작되지 않습니다(`Awake`에서 매니저만 등록됨).
