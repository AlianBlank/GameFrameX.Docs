# ホットフィックス起動が失敗を返す場合の対処方法

`IHotfixLauncher.StartAsync` が返す `HotfixLaunchResult` が失敗としてマークされている場合、または起動フローが `ProcedureGameLauncherState` 内で `StartupFailedEventArgs` をトリガーした場合が、このページで扱う状況です。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `HotfixLaunchResult.IsSuccess == false`、ログにアセンブリが見つからないと表示される | `StartupOptions.HotfixAssemblyName` が実際のコンパイル成果物と一致していない | Inspector のフィールド値を確認し、パッケージ化スクリプトが出力する dll と一致させる |
| `HotfixLaunchResult.IsSuccess == false`、ログにエントリタイプが見つからないと表示される | `HotfixEntryTypeName` のスペルミスまたは名前空間の誤り | 型の完全名(名前空間を含む)を確認し、dll の逆コンパイル結果と照合する |
| `StartupFailedEventArgs` をリッスンすると `FailedProcedureName == "ProcedureGameLauncherState"` | ホットフィックスの launcher が例外をスローした、または失敗を返した | `IHotfixLauncher` の実装内で try/catch し、`ErrorMessage` を設定してから失敗結果を返す |
| フローが `ProcedureGameLauncherState` で止まって先に進まない | `IHotfixLauncher` が BlackBoard に注入されていない | `Startup Runner` の呼び出し前に `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, ...)` を実行する |
| `StartupFailedEventArgs` を受け取ったが `ErrorMessage` が空文字列 | ビジネス実装が取り決めに従って `ErrorMessage` を設定していない | launcher の失敗時に明示的に `HotfixLaunchResult.ErrorMessage` に代入する |

`HotfixLaunchResult` と `StartupFailedEventArgs` のフィールド定義は、下記の参考表を参照してください。

## 修正手順

### 1. StartupOptions 設定の確認

ホットフィックスエントリの 3 点セット(アセンブリ名 / エントリタイプの完全名 / エントリメソッド名)は `StartupOptions` によって注入されます。いずれか 1 項目でも一致しない場合、`StartAsync` は失敗を返します:

```csharp
// StartupOptions.cs のデフォルト値より
public string HotfixAssemblyName = "Unity.Hotfix";
public string HotfixEntryTypeName = "Hotfix.HotfixLauncher";
public string HotfixEntryMethodName = "Run"; // StartupOptions.cs のフィールド宣言を参照
```

`StartupOptions` アセット内のこの 3 項目の値が、ホットフィックスプロジェクトのコンパイル出力、および IL2CPP/HybridCLR の読み込みリストと一致していることを確認してください。Source: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L33-L40)

### 2. StartupFailedEventArgs をリッスンする

起動失敗イベントを購読し、`ProcedureGameLauncherState` がスローした失敗メッセージをプレイヤーに表示します:

```csharp
GameEntry.GetComponent<EventComponent>().Subscribe(StartupFailedEventArgs.EventId, e =>
{
    var args = (StartupFailedEventArgs)e;
    // args.FailedProcedureName / args.FailedUrl / args.ErrorMessage
});
```

イベントのトリガー箇所は `StartupProcedureUtility.NotifyFailure` によって一元的に呼び出され、UI のヒントテキストとは別に `StartupFailedEventArgs` をもう一度 fire します。Source: [StartupProcedureUtility.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L160-L170),[StartupFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Events/StartupFailedEventArgs.cs#L40-L60)

### 3. IHotfixLauncher 実装が構造化された失敗を返すようにする

`IHotfixLauncher` の契約では、**成功・失敗のいずれの場合も `HotfixLaunchResult` を返し、例外をスローしない**ことが定められています。実装側では必ずすべての例外を catch して `ErrorMessage` に入れてください:

```csharp
public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    try
    {
        // ロード + リフレクションによるエントリメソッドの呼び出し
        return HotfixLaunchResult.Success();
    }
    catch (Exception ex)
    {
        return HotfixLaunchResult.Failure(ex.Message);
    }
}
```

Source: [IHotfixLauncher.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Hotfix/IHotfixLauncher.cs#L8-L16),[HotfixLaunchResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/HotfixLaunchResult.cs#L1-L40)

### 4. IHotfixLauncher が BlackBoard に注入済みであることを確認する

`ProcedureGameLauncherState` は FSM BlackBoard を通じて `IHotfixLauncher` を読み取ります。注入が欠けている場合、フローはこの Procedure で止まります。注入の取り決めは以下の通りです:

```csharp
// BlackBoardKeys で定義されている定数
public const string StartupHotfixLauncher = "__startup_hotfix_launcher__";
```

起動器は FSM 作成時に必ず `fsm.SetData(BlackBoardKeys.StartupHotfixLauncher, hotfixLauncher)` を実行する必要があります。Source: [BlackBoardKeys.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Constants/BlackBoardKeys.cs#L19-L23),[StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L80-L100)

## 検証

上記の修正が完了したら、各項目を順に確認してください:

1. `HotfixLaunchResult.IsSuccess == true` であり、`ErrorMessage` が空であること。
2. `StartupFailedEventArgs` がトリガーされなくなる(または `FailedProcedureName` が他の障害点に変わり、`ProcedureGameLauncherState` ではなくなる)こと。
3. それ以降のフローがゲームのメインシーンまで進み、`StartupCompletedEventArgs` が正常に fire されること。
