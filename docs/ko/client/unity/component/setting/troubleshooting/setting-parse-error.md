# 설정 항목 파싱 예외 처리 방법

`GameFrameX.Setting`이 설정을 로드하거나 읽는 동안 예외를 던지거나, 기본값을 반환하거나, `Load()`가 `false`를 반환하는 경우, 이는 보통 기본 저장 파일이 손상되었거나, 헬퍼가 설정되지 않았거나, 키 이름이 유효하지 않음을 나타냅니다. 이 페이지에서는 예외 현상에 따른 빠른 진단 및 수정 방법을 제공합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | `SettingManager`에 `ISettingHelper`가 설정되지 않았거나 `null`이 전달됨 | 먼저 구체적인 Helper(기본 `DefaultSettingHelper` 또는 `PlayerPrefsSettingHelper`)를 인스턴스화한 후 `SetSettingHelper` 호출 |
| `GameFrameworkException: Setting name is invalid.` | `settingName`이 `null`이거나 빈 문자열임 | `HasSetting / GetBool / GetInt / GetFloat / GetString` 등의 메서드를 호출하기 전에 `settingName`이 비어 있지 않은지 확인 |
| 시작 로그에 `Load settings failure with exception '{0}'.`가 표시됨 | 설정 파일 `GameFrameworkSetting.dat`이 없거나 손상되었거나 권한이 부족함 | 손상된 파일을 삭제하거나 권한을 복구한 후 다시 초기화, 아래 "수정 단계" 참조 |
| 시작 로그에 `Save settings failure with exception '{0}'.`가 표시됨 | 설정 디렉터리가 읽기 전용이거나 디스크가 가득 찼거나 경로가 유효하지 않음 | `FilePath`가 가리키는 곳의 쓰기 가능 여부를 확인하고 `Application.persistentDataPath`로 다시 지정 |
| 읽은 값이 항상 타입 기본값(`false / 0 / 0f / null`)임 | 키 이름의 철자가 틀렸거나 새 버전에서 해당 키를 쓰지 않음 | `GetAllSettingNames()`로 모든 키를 나열하여 확인하거나, 먼저 `defaultValue`를 사용하는 오버로드를 호출 |

## 수정 단계

### 1. 헬퍼 미설정으로 인한 `Setting helper is invalid`

`SettingManager`는 매번 읽기/쓰기 전에 `EnsureSettingHelper()`를 호출하며, `m_SettingHelper`가 `null`이면 해당 예외를 던집니다.

Source: [SettingManager.cs#L47-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L47-L61)

```csharp
private void EnsureSettingHelper()
{
    if (m_SettingHelper == null)
    {
        throw new GameFrameworkException("Setting helper is invalid.");
    }
}
```

수정 방법:

1. `SettingHelperBase`를 상속받은 Helper 인스턴스를 생성합니다(프레임워크에 내장된 `DefaultSettingHelper`, `PlayerPrefsSettingHelper`).
2. `GameFrameworkEntry.GetModule<ISettingManager>().SetSettingHelper(helper)`를 통해 주입합니다.
3. `SetSettingHelper(null)` 자체도 동일한 예외를 던지므로, null이 아닌 값을 전달해야 합니다.

Source: [SettingManager.cs#L126-L134](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L126-L134)

### 2. 설정 파일 파싱 실패(`Load settings failure`)

`DefaultSettingHelper.Load()`는 try/catch로 역직렬화 과정을 감싸며, 모든 예외는 로그로 변환되어 `false`를 반환합니다. 예외를 던지지 않지만 설정 항목은 빈 집합으로 돌아갑니다.

Source: [DefaultSettingHelper.cs#L126-L146](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L126-L146)

```csharp
public override bool Load()
{
    try
    {
        if (!File.Exists(m_FilePath))
        {
            return true;
        }

        using (FileStream fileStream = new FileStream(m_FilePath, FileMode.Open, FileAccess.Read))
        {
            m_Serializer.Deserialize(fileStream);
            return true;
        }
    }
    catch (Exception exception)
    {
        Log.Warning("Load settings failure with exception '{0}'.", exception);
        return false;
    }
}
```

수정 방법:

1. **파일이 존재하지 않음**: 첫 시작 시에는 정상이며 처리할 필요 없음; 비즈니스 로직에서 기본값을 미리 설정해야 하는 경우, `Load()`가 `false`를 반환한 후 `SetBool/SetInt/...`을 호출하여 채워 넣습니다.
2. **파일 헤더 불일치**: `DefaultSettingSerializer`의 `Header`는 `{'G','F','S'}`이며, 파일이 다른 프로그램에 의해 수정되면 파싱에 실패합니다. 해당 `GameFrameworkSetting.dat`을 삭제한 후 다시 시작합니다.

Source: [DefaultSettingSerializer.cs#L41-L67](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingSerializer.cs#L41-L67)
3. **디스크/권한 문제**: `FilePath`(`Application.persistentDataPath` 등에서 파생됨)가 있는 디렉터리가 읽기/쓰기 가능한지 확인; Windows / macOS에서 백신 소프트웨어에 의해 격리되었는지 확인합니다.

### 3. 키 이름이 비어 있어 발생하는 `Setting name is invalid`

`HasSetting / RemoveSetting`은 `EnsureSettingName`에서 검증합니다.

Source: [SettingManager.cs#L55-L61](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L55-L61)

```csharp
private void EnsureSettingName(string settingName)
{
    if (string.IsNullOrEmpty(settingName))
    {
        throw new GameFrameworkException("Setting name is invalid.");
    }
}
```

수정 방법: 설정 센터에서 키 이름을 가져올 때 `string.IsNullOrEmpty` 검증을 수행하거나, `GetString(name, defaultValue)` / `GetInt(name, defaultValue)` 등 기본값을 가진 오버로드를 사용하여 빈 키 예외를 피합니다.

### 4. 저장 실패(`Save settings failure`)

`Save()`도 마찬가지로 try/catch로 감싸여 있으며, 예외 발생 시 `false`를 반환하고 `Save settings failure with exception '{0}'.`를 출력합니다.

Source: [DefaultSettingHelper.cs#L156-L170](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/DefaultSettingHelper.cs#L156-L170)

수정 방법:

1. `FilePath`가 초기화되었는지 확인합니다(Helper는 `SetFilePath`를 통하거나 초기화 시 값을 할당받음).
2. 대상 디렉터리의 쓰기 권한을 확인합니다; `FileMode.Create`는 쓰기 가능해야 합니다.
3. `Log.Warning` 출력에 포함된 `IOException`, `UnauthorizedAccessException` 등 구체적인 예외를 캡처하여 그에 따라 처리합니다.

## 검증

다음 순서에 따라 문제가 해결되었는지 확인합니다:

1. `GameFrameworkEntry.GetModule<ISettingManager>().Load()`가 `true`를 반환하고, 시작 로그에 더 이상 `Load settings failure` / `Save settings failure`가 나타나지 않음.
2. `GetAllSettingNames()`가 반환하는 배열에 예상한 모든 키가 포함되어 있는지 확인; `HasSetting("your.key")`로 특정 키의 존재 여부를 확인.
3. 설정을 한 번 씁니다(`SetInt("score", 100)` → `Save()`), 종료 후 다시 시작해도 `GetInt("score")`이 여전히 100을 읽을 수 있는지 확인.
4. `SetSettingHelper(null)`, 빈 키 이름 전달 등의 케이스를 사용하여 예외 경로가 예상대로 `GameFrameworkException`을 던지는지, 삼켜지지 않는지 확인.
