# GameFrameX FSM 套件安裝方法

本指南說明如何將 `com.gameframex.unity.fsm`(GameFrameX FSM 有限狀態機套件)整合到 Unity 專案中。完成後，即可在程式碼中使用 `FsmComponent`、`IFsm<T>`、`FsmState<T>` 等型別。

## 前置需求

| 項目 | 需求 |
|------|------|
| Unity 版本 | 2019.4 或以上([package.json](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/package.json#L7)) |
| 套件相依性 | 無(`dependencies` 為空,[package.json](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/package.json#L22)) |
| 套件名稱 | `com.gameframex.unity.fsm` |
| 最新版本 | 1.2.0([package.json](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/package.json#L6)) |

## 操作步驟

只需選擇以下四種方法之一即可。

### 方法 1:UPM 註冊表(建議)

編輯 Unity 專案根目錄中的 `Packages/manifest.json`,新增 `scopedRegistries` 區段，並在 `dependencies` 中明確指定版本：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.fsm": "1.2.0"
  }
}
```

> `scopes` 會限制僅讓以 `com.gameframex` 開頭的套件從此註冊表解析，因此不會污染其他套件來源。

來源:[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L46-L61)

### 方法 2:Git URL(直接連結 GitHub)

直接在 `manifest.json` 的 `dependencies` 節點中加入 Git 儲存庫位址：

```json
{
  "dependencies": {
    "com.gameframex.unity.fsm": "https://github.com/gameframex/com.gameframex.unity.fsm.git"
  }
}
```

來源:[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L65-L70)

### 方法 3:Unity Package Manager Git URL

1. 開啟 Unity 編輯器，並從選單中選擇 `Window` → `Package Manager`。
2. 點擊左上角的 `+` → `Add package from git URL...`。
3. 輸入:`https://github.com/gameframex/com.gameframex.unity.fsm.git`
4. 點擊 `Add`,等待 Unity 解析並匯入完成。

來源:[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L71)

### 方法 4:直接下載至 Packages 目錄

1. 從 [Releases](https://github.com/GameFrameX/com.gameframex.unity.fsm/releases) 頁面下載原始碼 zip,或複製(clone)儲存庫。
3. 將整個 `com.gameframex.unity.fsm` 資料夾放入 Unity 專案的 `Packages/` 目錄。
3. Unity 會自動將其識別為本地內嵌套件(embedded package)並完成載入。

來源:[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L72)

## 驗證安裝

安裝完成後，請在 Unity 中確認以下事項：

1. 在 `Window` → `Package Manager` 中確認 `Packages: In Project` 有顯示 `Game Frame X FSM`。
2. 確認在任何腳本中都能成功執行 `using GameFrameX.Fsm;`,且可使用 `FsmComponent`、`IFsm<T>`、`FsmState<T>` 等型別。
3. 建立並啟動一個簡單的 FSM,確認沒有編譯錯誤：

```csharp
using GameFrameX.Fsm;
using UnityEngine;

public class BootCheck : MonoBehaviour
{
    class TestState : { }

    void Start()
    {
        var fsmComponent = GameEntry.GetComponent<FsmComponent>();
        // 僅供連線測試;實際用法請參閱《使用範例》頁面。
    }
}
```

## 常見變化

| 情境 | 選擇 |
|------|------|
| 已在使用 GameFrameX 生態系統(`com.gameframex.unity.entry`) | 使用方法 1,之後可透過 `GameApp.Fsm` 快速存取 |
| 需固定於特定版本(團隊協作) | 使用方法 1,指定如 `1.2.0` 的固定版本號 |
| 想跟隨 main 分支最新版本時 | 使用方法 2 或方法 3 |
| 因網路限制無法存取 GitHub/UPM | 使用方法 4,將 zip 內嵌至專案 |

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 在 Package Manager 中找不到 `com.gameframex.unity.fsm` | 未設定 `scopedRegistries`,或 `scopes` 不相符 | 確認 `scopes` 包含 `com.gameframex`,且 `url` 為 `https://gameframex.upm.alianblank.uk` |
| 出現 `Package 'com.gameframex.unity.fsm' has no version` 等版本錯誤 | 在 `dependencies` 中寫入 Git URL 時又額外加入了版本號 | 兩者擇一:`"1.2.0"` 或 Git URL,請勿混用 |
| 修改內嵌套件後 Unity 無法識別 | 直接解壓縮檔案時可能遺漏 `.meta` 檔案 | 使用 `git clone` 取得原始碼，或解壓縮 zip 時保留 `.meta` 檔案 |
