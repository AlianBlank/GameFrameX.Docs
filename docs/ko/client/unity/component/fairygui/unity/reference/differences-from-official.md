# 공식 FairyGUI와의 차이점

본 패키지는 공식 [FairyGUI-unity](https://github.com/fairygui/FairyGUI-unity)의 GameFrameX 배포판입니다(UPM 패키지명 `com.gameframex.unity.fairygui.unity`). 공식 코드를 기반으로 픽셀화 렌더링 컴파일 매크로 `ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED`와 몇 가지 GList/에디터 수정 사항을 추가하고, UPM 규격에 따라 패키지 설명 정보를 보완했습니다. 코드 네임스페이스는 여전히 `FairyGUI`이므로 기존 `using FairyGUI` 참조는 수정할 필요가 없습니다.

## 컴파일 매크로 차이: ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED

공식 FairyGUI-unity에는 이 컴파일 매크로가 존재하지 않습니다. 본 패키지에서 이를 정의하면 FairyGUI의 머티리얼 시스템에 `Pixelated` 머티리얼 변형 플래그가 하나 추가됩니다:

| 영향받는 위치 | 공식 동작 | 본 패키지(매크로 정의 후) |
|------------|----------|------------------|
| `MaterialFlags` 열거형 | `ColorFilter = 32`까지 | `Pixelated = 64` 추가 |
| `MaterialManager.internalKeywords` | 6개의 내장 키워드 | 7개, `"PIXELATED"` 추가 |
| `MaterialManager.GetMaterial` | 호출부에서 전달된 flags에 따라 머티리얼 생성 | 무조건 `flags |= Pixelated`, 즉 픽셀화 효과가 기본 활성화 |

열거형 정의 부분의 차이 코드:

```csharp
namespace FairyGUI
{
    [Flags]
    public enum MaterialFlags
    {
        Clipped = 1,
        SoftClipped = 2,
        StencilTest = 4,
        AlphaMask = 8,
        Grayed = 16,
        ColorFilter = 32,
#if ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED
        Pixelated = 64
#endif
    }
```

출처: [MaterialManager.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/MaterialManager.cs#L6-L20)

머티리얼 키워드 테이블과 기본 활성화 로직:

```csharp
#if ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED
        const int internalKeywordsCount = 7;
        static string[] internalKeywords = new[] { "CLIPPED", "SOFT_CLIPPED", null, "ALPHA_MASK", "GRAYED", "COLOR_FILTER", "PIXELATED" };
#else
        const int internalKeywordsCount = 6;
        static string[] internalKeywords = new[] { "CLIPPED", "SOFT_CLIPPED", null, "ALPHA_MASK", "GRAYED", "COLOR_FILTER" };
#endif
```

```csharp
        public Material GetMaterial(int flags, BlendMode blendMode, uint group)
        {
            if (blendMode != BlendMode.Normal && BlendModeUtils.Factors[(int)blendMode].pma)
                flags |= (int)MaterialFlags.ColorFilter;

#if ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED
            // 매크로가 정의된 경우 픽셀화 효과를 기본으로 활성화
            flags |= (int)MaterialFlags.Pixelated;
#endif
```

출처: [MaterialManager.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/MaterialManager.cs#L45-L51), [MaterialManager.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/MaterialManager.cs#L101-L109)

사용 방법: Unity의 **Player Settings → Scripting Define Symbols**(또는 어셈블리 defines)에 `ENABLE_GAMEFRAMEX_FAIRYGUI_PIXELATED`를 추가하면 활성화됩니다. 이 매크로를 정의하지 않으면 위의 세 가지 차이점은 모두 공식과 동일한 동작으로 되돌아갑니다. 활성화하면 모든 FairyGUI 머티리얼의 변형 키워드 목록에 `PIXELATED`가 포함된다는 점에 유의하세요.

## 입력 시스템 차이: FAIRYGUI_INPUT_SYSTEM

본 패키지는 [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L891-L902)에 두 가지 터치 읽기 경로를 모두 유지하고 있습니다: `FAIRYGUI_INPUT_SYSTEM`을 정의하면 새 버전 Input System의 `Touch.activeTouches` / `Touch.screenPosition`을 사용하고, 정의하지 않으면 구버전 `Input.GetTouch`로 폴백됩니다. 프로젝트에서 새 Input System을 사용하는 경우 이 매크로를 정의해야 하며, 그렇지 않으면 터치(멀티 터치) 이벤트가 디스패치되지 않습니다. 이는 CHANGELOG의 issue [#1 "uTouch 호환성 문제"](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/issues/1)와 관련된 변경 방향이기도 합니다.

```csharp
#if FAIRYGUI_INPUT_SYSTEM
                foreach (Touch uTouch in Touch.activeTouches)
                {
                    Vector2 pos = uTouch.screenPosition;
                    int touchId = uTouch.touchId;
                ...
#else
                    Touch uTouch = Input.GetTouch(i);
```

출처: [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L891-L902)
