# Running Your First Build

Follow the steps on this page to trigger an automated build of GameFrameX Builder from the command line in Unity and produce your first APK / asset bundle.

## Prerequisites

- Unity 2019.4 or higher
- `com.gameframex.unity.builder` installed via `Packages/manifest.json` (version 2.0.3 or higher is recommended)
- A Unity project with Player Settings configured (package name, version number, icon, etc.)

The minimal usable configuration for adding a scoped registry and dependency in `manifest.json`:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.builder": "2.0.3"
  }
}
```

## Steps

1. **Open the Unity project and wait for packages to finish importing**. You should see `com.gameframex.unity.builder` under `Packages`.

2. **Confirm the `-executeMethod` target method is available**. The build entry point is located at `GameFrameX.Builder.Editor.Builder`. The two most commonly used methods are:

   | Method | Description |
   |------|------|
   | `GameFrameX.Builder.Editor.Builder.BuildApk` | Packages an APK, and uploads it to object storage when `-IsUploadApk` is enabled |
   | `GameFrameX.Builder.Editor.Builder.BuildAsset` | Builds a YooAsset asset bundle |

   Source: [Builder.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L51-L78)

3. **Trigger the build from the command line**. The simplest command line form (using BuildApk as an example):

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath /path/to/your/project \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildApk \
         -BUILD_NUMBER 1 \
         -logFile /path/to/build.log
   ```

   `-BUILD_NUMBER` is required; when `-logFile` is omitted, Builder will automatically generate a log path.

4. **Check the build result**. Parameters such as `-BUILD_NUMBER`, `-AppVersion`, and `-BundleId` will be parsed into `BuilderOptions` by `Builder.BuildParamsParse`, which drives the entire build pipeline. The log file path is specified by `-logFile`, and the APK output location is determined by Unity's BuildPlayerAndroid.

   Source: [Builder.BuildParamsParse.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs)

## Common Variants

### Build Asset Bundles Only (Without APK)

Change `-executeMethod` to `GameFrameX.Builder.Editor.Builder.BuildAsset`, and specify the asset build parameters:

```bash
Unity -batchmode -nographics -quit \
      -projectPath /path/to/your/project \
      -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
      -BUILD_NUMBER 1 \
      -PackageName DefaultPackage \
      -BuildPipeline BuiltinBuildPipeline \
      -IsIncrementalBuildPackage false
```

Asset build parameters (excerpt):

| Parameter | Default | Description |
|------|--------|------|
| `-PackageName` | `DefaultPackage` | Asset bundle name |
| `-PackageVersion` | Timestamp | Automatically uses a timestamp when left empty |
| `-BuildPipeline` | `BuiltinBuildPipeline` | Optional: `BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` |
| `-BuildinFileCopyOption` | `ClearAndCopyAll` | Built-in file copy option |
| `-IsIncrementalBuildPackage` | `false` | Whether to perform an incremental build |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L97-L106)

### Add Logging and Upload in CI

Add the following flags during the build to upload logs/APK/asset bundles to object storage after packaging:

```bash
-IsUploadLogFile \
-IsUploadApk \
-IsUploadAsset \
-ObjectStorageKey <key> \
-ObjectStorageSecret <secret> \
-ObjectStorageBucketName <bucket> \
-ObjectStorageEndPoint <endpoint>
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `executeMethod` cannot find the target method | Package not imported correctly, or namespace is misspelled | Confirm that `com.gameframex.unity.builder` exists under `Packages`; the full method name should be `GameFrameX.Builder.Editor.Builder.BuildApk` |
| Reports missing `-BUILD_NUMBER` | Required parameter not passed | Add `-BUILD_NUMBER <n>` to the command line |
| Object storage upload failure | Object storage macro not enabled | Confirm that the project has installed the corresponding object storage sub-package and enabled the `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` family of macros |

## Background (Optional)

During the static construction phase, Builder calls `BuildParamsParse` to parse command line arguments into `BuilderOptions`, then selects the object storage implementation based on the `ENABLE_GAME_FRAME_X_OBJECT_STORAGE_*` macros. `BuildApk` is only responsible for invoking Unity to produce the package and uploading it as needed; asset building goes through the independent `BuildAsset` path. For the complete parameter list of Builder, see 《Command Line Parameter Reference》.
