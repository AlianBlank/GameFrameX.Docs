# キャッシュの清理とリソースパッケージのライフサイクル管理

本ページでは `GameFrameX.Asset` におけるキャッシュファイルの清理、リソースのアンロード、YooAssets リソースパッケージのライフサイクル管理(破棄、デフォルトパッケージの切り替え)について解説します。

## 前提条件

- `AssetComponent` を介して YooAssets が初期化済みで、少なくとも 1 つの `ResourcePackage` が存在すること。
- 業務側で `GameFramework.GetComponent<AssetComponent>()` のインスタンスを取得済みであること。
- [デフォルトパッケージ名の定数](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L170-L183) とパッケージ名のパラメータルールを理解していること。

## 操作手順

### 1. 単一リソースのアンロード(参照カウントを 1 減らす)

デフォルトパッケージを使用:

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAsset("Assets/Prefabs/Hero.prefab");
```

パッケージ名を指定:

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAsset("pkg_battle", "Assets/Prefabs/Hero.prefab");
```

内部的には `package.TryUnloadUnusedAsset(assetPath)` を呼び出します。出典: [AssetManager.cs#L100-L124](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L100-L124)

### 2. 未使用リソースの非同期アンロード(GC フレンドリー)

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadUnusedAssetsAsync();                // デフォルトパッケージ
GameFramework.GetComponent<AssetComponent>()
    .UnloadUnusedAssetsAsync("pkg_battle");    // パッケージ指定
```

参照カウントが 0 のリソースのみを回収するため、シーン切り替え時の呼び出しに適しています。出典: [AssetManager.cs#L150-L163](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L150-L163)

### 3. パッケージ内全リソースの非同期強制回収

```csharp
GameFramework.GetComponent<AssetComponent>()
    .UnloadAllAssetsAsync();
```

参照カウントを無視して、そのパッケージがロードしたすべてのリソースを強制的に解放します。出典: [AssetManager.cs#L127-L144](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L127-L144)

### 4. 不要な Bundle キャッシュファイルの清理

```csharp
GameFramework.GetComponent<AssetComponent>()
    .ClearUnusedBundleFilesAsync();
```

どのリソースからも参照されていない Bundle ファイルのみを削除し、ロード済みのリソースはアンロードしません。出典: [AssetManager.cs#L189-L201](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L189-L201)

### 5. パッケージ内すべての Bundle キャッシュをクリア

```csharp
GameFramework.GetComponent<AssetComponent>()
    .ClearAllBundleFilesAsync();
```

`UnloadAllAssetsAsync` を実行してから `ClearUnusedBundleFilesAsync` を実行し、完全に解放します。出典: [AssetManager.cs#L165-L183](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L165-L183)

### 6. デフォルトリソースパッケージの切り替え

```csharp
var pkg = YooAssets.GetPackage("pkg_main");
GameFramework.GetComponent<AssetComponent>()
    .SetDefaultAssetsPackage(pkg);
```

以後 `packageName` を指定しないロード/アンロードは、すべて新しいデフォルトパッケージに対して実行されます。出典: [IAssetManager.cs#L443-L444](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/IAssetManager.cs#L443-L444)

## よくあるバリエーション

| シーン | 推奨 API | 説明 |
|------|----------|------|
| シーン切り替え時に前シーンのリソースを解放 | `UnloadUnusedAssetsAsync` | 参照されていないリソースのみを回収し、誤って解放するのを防ぐ |
| ダンジョン退出時にパッケージ全体を解放 | `UnloadAllAssetsAsync` + `ClearUnusedBundleFilesAsync` | メモリとキャッシュの両方を解放 |
| パッケージ再インストール前に徹底的に清理 | `ClearAllBundleFilesAsync` | リソースとキャッシュの清理を 1 行で完了 |
| 必要に応じて単一リソースを解放 | `UnloadAsset(path)` | 参照カウントを 1 減らす |

## よくあるエラー

- **`packageName` が null だがパッケージが作成されていない**:アンロード/清理を呼び出す前に、必ず `CreatePackage` と `Initialize` を実行してください。さもないと `YooAssets.GetPackage` は `null` を返し、メソッド内部で `null` チェックがあるため例外は発生しませんが、操作は静かに失敗します。
- **`UnloadAsset` の参照カウントがゼロにならない**:同じリソースを繰り返しロードするとカウントが増加するため、対応する回数の `UnloadAsset` を呼び出さなければ実際に解放されません。
- **「リソースのアンロード」と「キャッシュの清理」を混同する**: `UnloadUnusedAssetsAsync` はメモリのみをクリアします。ディスク上の Bundle ファイルは `ClearUnusedBundleFilesAsync` または `ClearAllBundleFilesAsync` を使用する必要があります。
- **強制回収直後にリソースにアクセスする**: `UnloadAllAssetsAsync` は非同期操作であるため、`yield return` またはコールバック完了後に該当アセットを操作してください。さもないと破棄済みのオブジェクトを取得してしまいます。

## 背景(オプション)

`AssetManager` のすべてのクリーンアップ API は YooAssets の `ResourcePackage` オブジェクトに転送されます。`UnloadAsset` は `TryUnloadUnusedAsset`(参照カウント)を経由し、`UnloadUnusedAssetsAsync` と `UnloadAllAssetsAsync` はメモリを解放し、`ClearUnusedBundleFilesAsync` はディスクを削除します。`ClearAllBundleFilesAsync` は複合操作であり、メモリとキャッシュを同時にクリアします。
