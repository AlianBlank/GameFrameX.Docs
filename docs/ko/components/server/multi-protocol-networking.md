# TCP/WebSocket/KCP/HTTP 클라이언트 연결 방법

`GameFrameX.NetWork`의 `INetWorkChannel`과 `NetWorkSenderFactory`를 통해 비즈니스 측에서는 하위 프로토콜 차이를 신경 쓰지 않고 투명하게 TCP, WebSocket, KCP, HTTP 클라이언트 메시지를 송수신할 수 있습니다.

## 사전 조건

- `GameFrameX.NetWork.Abstractions`, `GameFrameX.NetWork` 패키지가 설치되어 있어야 합니다. KCP 클라이언트는 `GameFrameX.NetWork.Kcp`를 추가로 참조해야 하고, HTTP 클라이언트는 `GameFrameX.NetWork.HTTP`를 참조해야 합니다.
- `GameFrameX.SuperSocket.Server.Abstractions.Session.IGameAppSession`(SuperSocket 세션)이 연동되어 있어야 합니다.
- 해당 프로토콜의 리스너(TCP / WebSocket / KCP / HTTP)가 구성되어 있어야 합니다.

## 작업 단계

### 1. 네트워크 채널 가져오기

비즈니스 프로세서에서 세션을 통해 `INetWorkChannel`을 가져오며, 이후의 송수신은 모두 채널을 통해 이루어지고 프로토콜에 직접 접근하지 않습니다.

```csharp
using GameFrameX.NetWork;
using GameFrameX.NetWork.Abstractions;
using GameFrameX.SuperSocket.Server.Abstractions.Session;

// SuperSocket 메시지 처리 컨텍스트에서
IGameAppSession session = /* 연결 이벤트 또는 메시지 처리에서 가져옴 */;
INetWorkChannel channel = NetWorkSenderFactory.Create(session);
// NetWorkSenderFactory는 session의 실제 타입에 따라 WebSocket 또는 TCP 송신자를 자동으로 선택합니다
```

출처: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L12-L17)

### 2. 클라이언트로 메시지 보내기

`INetworkMessage`를 생성하고 `WriteAsync`를 호출하여 비동기로 전송합니다. `errorCode`의 기본값은 `0`이며, 비즈니스 측에서 오류 발생 시 오류 코드를 반환할 수 있습니다.

```csharp
using GameFrameX.NetWork.Abstractions;

await channel.WriteAsync(message, errorCode: 0);
```

`INetWorkChannel.WriteAsync`는 네트워크 채널이 이미 닫혀 있을 때 예외를 발생시키므로, 호출 전에 `IsClosed()`로 확인할 수 있습니다.

출처: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L96-L108)

### 3. 연결 닫기

```csharp
channel.Close();
```

출처: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L110-L116)

### 4. 채널에서 사용자 정의 데이터 저장 및 조회

`SetData` / `GetData<T>` / `RemoveData` / `ClearData`는 채널 생명주기 동안 사용자 데이터(예: 플레이어 객체, 로그인 상태)를 첨부하는 데 사용되며, 별도의 Map이 필요 없습니다.

```csharp
channel.SetData("playerId", 10001);
var pid = channel.GetData<long>("playerId");
channel.RemoveData("playerId");
// channel.ClearData(); // 연결이 끊어지거나 초기화가 필요할 때
```

출처: [GameFrameX.NetWork.Abstractions/INetWorkChannel.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/INetWorkChannel.cs#L118-L155)

## 일반적인 변형

### TCP / WebSocket

`NetWorkSenderFactory.BuildProviders()`에는 `WebSocketNetWorkSenderProvider`와 `SessionNetWorkSenderProvider`가 내장되어 있으며, 각각 WebSocket과 TCP(`IGameAppSession`을 공유하는 KCP 같은 프로토콜 포함) 세션 타입을 다룹니다. 별도의 등록 없이 `session.GetType()`에 따라 자동으로 매칭됩니다.

출처: [GameFrameX.NetWork/NetWorkSenderFactory.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork/NetWorkSenderFactory.cs#L19-L36)

### KCP

KCP 세션 역시 `IGameAppSession`을 구현하며, `SessionNetWorkSenderProvider`의 전송 경로를 재사용합니다. 사용자 정의 인코딩/디코딩이 필요한 경우 KCP 리스너 측에서 연동합니다.

### HTTP

HTTP는 `GameFrameX.NetWork.HTTP` 독립 채널을 사용하며, 요청 처리 후 `Close()`만 호출하면 됩니다. `GetData`/`SetData`는 요청 처리 체인에서 컨텍스트를 전달하는 데 사용할 수 있습니다.

## 자주 발생하는 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `WriteAsync` 예외 발생 | 채널이 이미 닫힘(`IsClosed()`가 `true` 반환) | 전송 전에 `if (!channel.IsClosed())` 가드 추가 |
| `GetData<T>` 예외 발생 | Key가 존재하지 않거나 타입 불일치 | 쓰기 시 타입을 통일; 읽기 전에 `ContainsKey` 스타일의 확인 또는 예외 캡처 |
| WebSocket 메시지 전송 실패 | `NetWorkSenderFactory`를 거치지 않고 TCP 송신자를 직접 사용함 | 항상 `NetWorkSenderFactory.Create(session)`를 통해 채널을 가져오면 팩토리가 세션 타입에 따라 분배함 |
| KCP 패킷은 도착하지만 비즈니스에서 수신 불가 | KCP 리스너 측에서 `INetWorkChannel` 파이프라인이 연동되지 않음 | KCP 세션이 `IGameAppSession`을 래핑하는지 확인하고, 팩토리가 채널을 생성하도록 함 |

## 배경(선택 사항)

`NetWorkSenderFactory`는 `SenderProviders` 딕셔너리를 통해 프로토콜 세션 타입을 `INetWorkSenderProvider`에 매핑하며, `ResolveProvider`는 정확한 매칭을 우선으로 하고 할당 가능한 관계로 폴백합니다. 따라서 새 프로토콜 추가 시 `Provider` + `Sender` 구현 한 쌍을 추가하고 등록하기만 하면 되고, 비즈니스 측의 `WriteAsync` 호출은 변경할 필요가 없습니다. `INetWorkChannel`은 바이트/패킷 카운트, 하트비트 시간, 사용자 정의 데이터, 닫기 등의 기능을 동일한 인터페이스로 통합하여, 비즈니스 코드는 프로토콜과 무관한 채널 뷰만 보게 됩니다.
