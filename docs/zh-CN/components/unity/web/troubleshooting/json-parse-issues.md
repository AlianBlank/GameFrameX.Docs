# JSON 解析结果不正确怎么办

当 `WebManager` 返回的 JSON 字符串经 `ToHttpJsonResultData<T>()` 解析后出现 `IsSuccess == false`、`Data == null`、`Code` 恒为 0 或字段丢失时，通常是响应结构不符合 `{"code":0,"message":"...","data":"..."}` 约定、`data` 是嵌套对象、或 `T` 类型缺少无参构造/字段名不匹配造成的。按下方诊断表逐条排查即可定位。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `IsSuccess == false` 且 `Code` 为非 0 值 | 服务端返回的业务错误码，`data` 未被解析（源码中 `Code != 0` 时直接返回失败结果） | 打开日志查看 `message`，按业务错误处理；见下方"Code 非 0" |
| `IsSuccess == false`、`Code == 0`、`Data == null` | 解析过程抛异常被 `catch` 吞掉，仅输出 `Log.Error(e)`，返回默认失败结果 | 查看 Console 中 `Log.Error` 输出的异常堆栈；检查 JSON 结构与 `T` 的匹配 |
| `Data` 是 `new T()` 全默认值的实例 | 服务端返回的 `data` 为空字符串，源码在 `data` 为空时直接 `new T()` | 确认接口是否真的返回空 `data`；如非预期，检查响应原文 |
| `Data` 里的字段全是默认值，但没报错 | `data` 是对象却按 `string` 处理失败，或 `T` 的属性名与 JSON 字段名不一致 | 给 `T` 的属性加 `[JsonProperty("字段名")]`，见下方修复步骤 |
| 日志里根本看不到响应原文 | 宏 `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 未定义 | 在 Player Settings / 脚本宏中添加 `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 后重编译 |
| 反序列化直接抛 `JsonMapper` 异常 | `T` 不满足 `class, new()` 约束场景下的字段类型错误（如日期格式、嵌套字典） | 简化 `T` 为最小可复现模型，逐字段加回排查 |

## 修复步骤

### 1. 先打开响应日志，拿到原始 JSON

`WebManager` 在收到响应时会把原始内容打到日志里，但需要宏开关：

- 请求日志：`ENABLE_GAMEFRAMEX_WEB_SEND_LOG`
- 响应日志：`ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`

源码中的响应日志实现（`unityWebRequest.downloadHandler.text` 即原始响应体）：

```csharp
#if ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG
                    Log.Debug($"Web Response: {webJsonData.URL} \n Header: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Header)} \n  Form: {GameFrameX.Runtime.Utility.Json.ToJson(webJsonData.Form)} \n Content: {unityWebRequest.downloadHandler.text}");
#endif
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L248-L250)

拿到原始 JSON 后，与统一响应结构对比，这一步能解决大部分"解析不正确"问题。

### 2. 确认响应符合统一结构 `{"code", "message", "data"}`

解析器强依赖这三个字段名，通过 `JsonProperty` 绑定：

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class HttpJsonResult
{
    /// <summary>
    /// 响应码0 为成功
    /// </summary>
    [JsonProperty("code")]
    public int Code { get; set; }

    /// <summary>
    /// 响应消息
    /// </summary>
    [JsonProperty("message")]
    public string Message { get; set; }

    /// <summary>
    /// 响应数据.
    /// </summary>
    [JsonProperty("data")]
    public string Data { get; set; }
}
```

Source: [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L8-L27)

核对要点：

| 核对项 | 预期 | 不符时的表现 |
|--------|------|--------------|
| 字段名 | 必须是 `code` / `message` / `data` | 字段丢失或恒为默认值 |
| `code` | 0 表示成功 | 非 0 时 `IsSuccess` 恒为 `false` |
| `data` | 期望是字符串（嵌套 JSON 的字符串形式） | 若是直接的对象字面量，`Data` 可能解析异常 |

如果服务端返回的顶层字段名不同（例如 `status`/`msg`/`result`），需要先让服务端按此约定返回，或自行反序列化为自定义结构，不能直接用 `ToHttpJsonResultData<T>()`。

### 3. 让 `T` 满足约束并正确映射字段

`ToHttpJsonResultData<T>` 的扩展方法签名与内部解析逻辑：

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // 反序列化JSON字符串为HttpJsonResult对象
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // 检查响应码是否表示成功
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // 返回默认的失败结果
        }

        resultData.IsSuccess = true; // 设置成功标志
        // 反序列化数据部分，如果数据为空则返回类型T的默认实例
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // 捕获并输出异常信息
        Log.Error(e);
    }

    return resultData; // 返回结果数据
}
```

Source: [HttpJsonResultHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultHelper.cs#L20-L48)

排查 `T` 时的检查清单：

1. `T` 必须是 `class` 且有无参构造函数（`where T : class, new()`），结构体、抽象类都不行。
2. `T` 的属性名需与 `data` 内的 JSON 字段名一致，不一致时加 `[JsonProperty("字段名")]`（LitJSON 提供的 `GameFrameX.LitJSON.Runtime.JsonProperty`）。
3. `data` 为空字符串时得到的是 `new T()`，不要把"全默认值"误判成解析失败——这其实是源码的既定行为。
4. 解析异常被 `catch` 后仅 `Log.Error(e)`，`IsSuccess` 保持 `false`、`Code` 保持 0。看到这种组合时优先查 Console 的异常日志。

### 4. `Code 非 0` 时按业务错误处理

`HttpJsonResultData<T>` 返回给调用方的字段含义：

| 字段 | 类型 | 说明 |
|------|------|------|
| `IsSuccess` | `bool` | 是否成功，默认 `false` |
| `Code` | `int` | 响应码，0 为成功，非 0 为服务端业务错误码 |
| `Data` | `T` | 成功时为反序列化后的数据；失败时为默认值或 `null` |

Source: [HttpJsonResultData.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResultData.cs#L8-L28)

若 `Code` 非 0，说明是服务端返回的业务错误，`Data` 不会被解析，需要根据 `Code` 与 `message`（可从原始响应日志查看）做对应提示或重试。

## 验证

1. 定义 `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 宏重新发起请求，确认日志中的响应原文符合 `{"code":0,"message":"...","data":"..."}` 结构。
2. 对响应原文调用 `.ToHttpJsonResultData<T>()`，断言 `IsSuccess == true`。
3. 逐字段检查 `Data` 的属性值与 `data` 字段内容一致（含嵌套对象）。
4. 请求/响应宏同时打开时，`WebManager` 会输出完整请求头与表单，可进一步排除"请求参数错误导致服务端返回错误结构"的可能。
