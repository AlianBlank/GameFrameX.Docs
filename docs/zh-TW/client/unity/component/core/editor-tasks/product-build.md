# 配置產品建構流程

透過 Unity 頂部選單 `GameFrameX/Build/*` 一鍵匯出不同平台的可發佈版本,並在建構前後透過 Hook 注入自訂步驟(如複製設定、注入熱更新工程、清理暫存目錄)。

## 前置條件

- 已安裝 Unity 編輯器,工程已透過 Unity Hub 開啟。
- 在 `File → Build Settings` 中預先勾選要打包的場景,否則 `EditorBuildSettings.scenes` 為空,產物不會包含任何場景。
- 需要打 Android 平台時,確保已安裝對應 Build Support 模組並設定好 JDK / Android SDK。
- 如需熱修復流程,確認已安裝 `GameFrameX` 相關的 HotFix 編輯器擴充功能(命令 `HotFixEditorCompilerHelper.AddEditor()` 會自動呼叫)。
- 輸出目錄所在磁碟有寫入權限;Windows 平台預設產物路徑見下文。

## 操作步驟

### 1. 切換建構平台

在 Unity 頂部選單點擊 `File → Build Settings`,在 `Platform` 列表中選擇目標平台並點擊 `Switch Platform`。選單項目會校驗當前活動建構目標,平台不符會輸出 `當前建構目標不是 XXX` 並直接返回。

### 2. 選擇選單觸發建構

按目標平台,在 Unity 頂部選單依序點擊 `GameFrameX → Build → <平台名稱>`,每個選單項目對應 `BuildProductHelper` 中的一個靜態方法。

| 選單項目 | 對應方法 | BuildTarget | 輸出位置 |
|--------|----------|-------------|----------|
| `GameFrameX/Build/Windows X64` | `BuildPlayerToWindows64BuildTarget` | `StandaloneWindows64` | `_buildPath/PlayerSettings.productName.exe` |
| `GameFrameX/Build/Windows X32` | `BuildPlayerToWindows32BuildTarget` | `StandaloneWindows` | 同上(目錄名不同) |
| `GameFrameX/Build/Mac Os` | `BuildPlayerToMacBuildTarget` | `StandaloneOSX` | 同上 |
| `GameFrameX/Build/WebGL` | `BuildPlayerToWebGLBuildTarget` | `WebGL` | 由 `BuildOutputPath()` 決定 |
| `GameFrameX/Build/Android(APK)` | `BuildPlayerToAndroid` | `Android` | `apkPath`(APK) |
| `GameFrameX/Build/Android(AAB)` | `BuildPlayerToAndroidAAB` | `Android` | `aabFilePath`(AAB) |
| `GameFrameX/Build/Android Studio Project` | `BuildPlayerToAndroidStudio` | `Android` | `_buildPath`(Gradle 工程目錄) |
| `GameFrameX/Build/Android(Development)` | `BuildPlayerToAndroidDevelopment` | `Android` | 含 `AllowDebugging \| Development \| ConnectWithProfiler` |
| `GameFrameX/Build/iOS` | `BuildPlayerToIOS` | `iOS` | Xcode 工程目錄 |

呼叫入口摘錄:

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("當前建構目標不是 Windows");
        return;
    }
    try
    {
        HotFixEditorCompilerHelper.AddEditor();
        PlayerSettings.fullScreenMode = FullScreenMode.Windowed;
        PlayerSettings.defaultScreenHeight = 720;
        PlayerSettings.defaultScreenWidth = 1280;
        EditorUserBuildSettings.selectedStandaloneTarget = BuildTarget.StandaloneWindows64;
        UpdateBuildTime();
        AssetDatabase.SaveAssets();
        _buildPath = BuildOutputPath();
        var resultDirectory = _buildPath + Path.DirectorySeparatorChar;
        RunPreHookBuild();
        var buildReport = BuildPipeline.BuildPlayer(EditorBuildSettings.scenes, resultDirectory + PlayerSettings.productName + ".exe", EditorUserBuildSettings.activeBuildTarget, BuildOptions.None);
        // ...
    }
    finally
    {
        HotFixEditorCompilerHelper.RemoveEditor();
        RunPostHookBuild();
    }
}
```

Source: [BuildProductHelper.cs](/src/Editor/BuildProduct/BuildProductHelper.cs#L101-L152)

### 3. 等待建構並查看輸出

建構過程中 `BuildPipeline.BuildPlayer` 會回傳 `BuildReport`,只有當 `summary.result == BuildResult.Succeeded` 時才會繼續後續清理與複製步驟;否則方法會提前返回。主控台會輸出 `Build Output Path:` 後接最終產物路徑。Android 平台還會自動呼叫 `EditorUserBuildSettings.selectedStandaloneTarget` / 對應 API 設定簽章相關參數(請參閱原始檔 [BuildProductHelper.cs](/src/Editor/BuildProduct/BuildProductHelper.cs#L360-L450))。

### 4. 接入建構前後 Hook(選用)

如需在每次建構前後自動執行步驟,實作 `IBuilderPreHookHandler` 或 `IBuilderPostHookHandler` 即可,框架會在建構產物前後呼叫所有實作類別,並按 `Priority` 升序執行。

```csharp
using UnityEditor;
using GameFrameX.Editor;

public sealed class CopyExtraConfigsPreHook : IBuilderPreHookHandler
{
    // 數值越大,執行順序越靠後
    public int Priority => 100;

    public void Run(BuildTarget target, string path)
    {
        // target: 當前 BuildPipeline.BuildPlayer 的目標平台
        // path:   框架準備好的輸出路徑(含可執行檔名稱或目錄)
        // 這裡寫複製資源、改 PlayerSettings 等自訂邏輯
    }
}
```

Source: [IBuilderPreHookHandler.cs](/src/Editor/BuildProduct/IBuilderPreHookHandler.cs#L36-L52)

## 常見變體

- 自訂輸出路徑:每個方法都先把 `_buildPath = BuildOutputPath()`(類別內靜態欄位)再傳入 `BuildPipeline.BuildPlayer`,如需改名或換目錄,在呼叫選單前修改 `PlayerSettings.productName` 或擴充 `BuildOutputPath()`。
- 嵌入熱修復流程:`HotFixEditorCompilerHelper.AddEditor()` 已在每個平台入口的 `try` 起手呼叫,`finally` 中呼叫 `HotFixEditorCompilerHelper.RemoveEditor()` 還原工程檔案,無熱修需求可忽略。
- 自訂後處理:Steamworks 設定檔會透過 `CopySteamWorksConfig` 自動複製到產物目錄;新增同類工具可直接複製該呼叫或註冊 `IBuilderPostHookHandler`。
- 除錯版建構:Android 平台提供專門的 `BuildPlayerToAndroidDevelopment` 入口,產出帶 `AllowDebugging | Development | ConnectWithProfiler` 的 APK,用於 Profiler 除錯。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| 選單點擊後立刻輸出 `當前建構目標不是 XXX` 並退出 | 當前活動平台與選單項目對應的 `BuildTarget` 不一致 | 先在 `Build Settings` 切到對應平台再觸發選單 |
| 建構產物只有 `*_Data` 目錄,缺可執行檔 | `EditorBuildSettings.scenes` 為空,只勾選一部分場景 | 在 `Build Settings → Scenes In Build` 勾全需要打包的場景 |
| 最終目錄裡多出 `BackUpThisFolder_ButDontShipItWithYourGame` | 框架已主動刪除該目錄,但部分檔案可能因佔用而殘留 | 關閉佔用處理程序後重試;若需保留可在自訂 Hook 中跳過對應清理邏輯 |
| Hook 沒有按預期順序執行 | 未設定 `Priority`,或多個實作使用相同數值 | 給每個實作明確賦值,數值越大排序越靠後 |
| 建構後 Unity 仍殘留編輯巨集或編輯器工程檔 | `HotFixEditorCompilerHelper.RemoveEditor()` 未觸發 | 不要手動跳過選單的 `try/finally`,應透過選單而非複製方式觸發 |

## 背景(選用)

`BuildProductHelper` 在 `BuildPipeline.BuildPlayer` 之前呼叫 `RunPreHookBuild()`,在 `finally` 中呼叫 `RunPostHookBuild()`,兩者內部都透過反射掃描所有 `Utility.Assembly.GetTypes()` 中實作了對應介面的具體類型,然後按 `Priority` 升序實例化並呼叫 `Run(BuildTarget, string)`。這項機制讓使用者業務無需修改框架原始碼即可注入建構前後邏輯。
