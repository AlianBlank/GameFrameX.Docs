# 如何使用 GameApp 调用各子系统(门面层指南)

`GameApp` 是 GameFrameX 提供的静态门面类(Facade),把分散在各组件中的子系统(Asset、Config、Event、Fsm、UI、Entity、Localization 等)统一汇聚为静态属性,业务代码无需再通过 `GameEntry.GetComponent<T>()` 反复查找,直接 `GameApp.Asset.xxx` 即可调用。

## 前置条件

- 已安装并初始化 GameFrameX 的 `GameEntry`,框架会在启动时按 `Enable` 列表创建各 `Component`。
- 用到哪个子系统,就要确保该子系统对应的 `ENABLE_GAME_FRAME_X_*` 宏已启用(各 `GameApp.*.cs` 文件用宏包裹整个 partial 块),否则属性不会编译出来。
- 业务代码不要持有 `Component` 引用,统一通过 `GameApp.xxx` 访问。

## 操作步骤

### 1. 通过静态属性获取子系统

每个 `GameApp.*.cs` 文件都遵循同一个模式:内部持有一个静态私有字段,公开一个只读静态属性,首次访问时从 `GameEntry` 取出对应 `Component` 并缓存。

```csharp
// 取出基础组件
var baseComp = GameApp.Base;

// 取出资产组件(需启用 ENABLE_GAME_FRAME_X_ASSET 宏)
var asset = GameApp.Asset;

// 取出配置组件(需启用 ENABLE_GAME_FRAME_X_CONFIG 宏)
var cfg = GameApp.Config;

// 取出事件组件(需启用 ENABLE_GAME_FRAME_X_EVENT 宏)
var evt = GameApp.Event;
```

### 2. 在业务代码里调用子系统方法

拿到属性后,直接调用对应 `Component` 的方法即可。例如下面这段演示加载资源、读取配置、订阅事件,全部经过 `GameApp`:

```csharp
// 加载资产
GameApp.Asset.LoadAsset<GameObject>("Assets/Prefabs/Hero.prefab", prefab =>
{
    // 使用 prefab ...
});

// 读取配置
var heroHp = GameApp.Config.GetInt("Hero_HP", 100);

// 订阅事件
GameApp.Event.Subscribe("OnPlayerLevelUp", payload =>
{
    // 处理升级事件
});
```

> 以上 API 名称(LoadAsset / GetInt / Subscribe)来自各自组件的常用公开方法,具体签名以 [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs)、[GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs)、[GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) 对应的 `Component` 实现为准。

### 3. 通过宏开关裁剪不需要的子系统

`GameApp` 中每个子系统都包裹在 `ENABLE_GAME_FRAME_X_<NAME>` 编译宏里。如果项目不需要某个子系统,关闭对应宏后,该属性就不会被编译进来,可有效减少包体和依赖。

| 宏(示例) | 影响的属性 | 文件 |
|---|---|---|
| `ENABLE_GAME_FRAME_X_ASSET` | `GameApp.Asset` | [GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs) |
| `ENABLE_GAME_FRAME_X_CONFIG` | `GameApp.Config` | [GameApp.Config.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs) |
| `ENABLE_GAME_FRAME_X_EVENT` | `GameApp.Event` | [GameApp.Event.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Event.cs) |

所有子系统均采用同一宏命名规则,具体宏名见各 [Runtime/GameApp.*.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs) 文件首部的 `#if` 指令。

## 常见变体

### 使用其它已暴露子系统

仓库 `Runtime/` 目录下每个 `GameApp.*.cs` 文件对应一个子系统,常用入口包括:

- `GameApp.AdJust`、`GameApp.Advertisement` —— 推广与广告。
- `GameApp.AppleLogin`、`GameApp.FaceBookLogin`、`GameApp.GoogleLogin` —— 三方登录。
- `GameApp.AppsFlyer`、`GameApp.GameAnalytics` —— 数据埋点。
- `GameApp.Asset` —— 资产加载。
- `GameApp.Config` —— 配置读取。
- `GameApp.Coroutine` —— 协程。
- `GameApp.Download` —— 下载。
- `GameApp.Entity` —— 实体。
- `GameApp.Event` —— 事件。
- `GameApp.FairyGUIPackage` —— FairyGUI 资源包。
- `GameApp.Fsm` —— 状态机。
- `GameApp.GlobalConfig` —— 全局配置。
- `GameApp.GUI` —— UI。
- `GameApp.Guide` —— 新手引导。
- `GameApp.Localization` —— 本地化。

调用方式一致:确认宏已启用后,使用 `GameApp.<Name>` 即可拿到对应 `Component`。

## 常见错误

- **找不到属性 / 编译报错 `GameApp` 不包含 `xxx` 的定义**:多半是没有启用对应的 `ENABLE_GAME_FRAME_X_*` 宏,或者对应 `GameApp.*.cs` 没被编译进项目。先在 `Scripting Define Symbols` 或 `asmdef` 中打开宏。
- **`GameEntry` 未启动就访问属性**:`GameApp` 通过 `GameEntry.GetComponent<T>()` 取组件,若框架初始化尚未完成会拿到 `null`,后续调用即抛空引用。确保在 `GameEntry` 启动完成之后再访问 `GameApp.xxx`。
- **手动 `new` 一个 `Component` 替代门面调用**:`GameApp` 的静态字段是缓存,只在使用 `GameEntry.GetComponent<T>()` 拿到的实例之间保持一致;自己 `new` 出来的实例不会通过门面拿到,会导致两份状态不同步。
- **跨场景持有静态字段**:目前 `GameApp` 中的字段是进程级静态缓存,设计上随进程生命周期使用,不要尝试在场景切换时手动重置。

## 背景(可选)

`GameApp` 由多个 `partial class` 组成(`Runtime/GameApp.*.cs` 各自实现一个子系统属性),统一通过懒加载 + `GameEntry.GetComponent<T>()` 的方式获取组件实例,既保留单例组件的全局访问能力,又避免业务层散落 `GameEntry.GetComponent<T>()` 的样板代码,这是框架中典型的 Facade 模式应用。

关于框架整体启动流程与 `GameEntry` 的角色,见《概述》页。
