# 辞書の読み込みに失敗した（LoadDictionaryFailureEventArgs）場合の対処方法

ローカライズ辞書リソースの読み込みに失敗すると、フレームワークは `LoadDictionaryFailureEventArgs` イベントを送出します。このイベントは3つのフィールドを保持します――`DictionaryAssetName`（読み込みに失敗した辞書リソース名）、`ErrorMessage`（エラーメッセージ）、`UserData`（読み込み開始時に渡されたカスタムデータ）――トラブルシューティングではまずこの3つのフィールドを読めば、「リソース名の設定ミス」なのか「リソースの欠落/読み込み異常」なのかを切り分けられます。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `ErrorMessage` にリソースが存在しない/見つからない旨が表示される | 辞書リソースが未生成、またはリソースパッケージに含まれていない | 下記の【修正手順 1】でリソースが読み込み可能か確認する |
| `DictionaryAssetName` が空、または想定と一致しない | 読み込み呼び出し時に誤ったリソース名が渡された | 下記の【修正手順 2】で呼び出し箇所で渡されたリソース名を確認する |
| `UserData` が空で、どの読み込みが失敗したか区別できない | 読み込み開始時にカスタムデータを渡していない | 下記の【修正手順 3】で読み込み呼び出し箇所から識別用オブジェクトを渡す |
| イベントが一度も発火せず、成功イベントも発生しない | イベントが未購読、または読み込みフローが開始されていない | 下記の【修正手順 4】で購読と読み込み呼び出しを確認する |

フィールド説明（イベントクラスの実際の定義から抜粋）：

| プロパティ | 型 | 生成時のデフォルト値 | 説明 |
|------|------|--------------|------|
| `DictionaryAssetName` | `string` | `null` | 読み込みに失敗した辞書リソース名 |
| `ErrorMessage` | `string` | `null` | エラーメッセージ（具体的なテキストは基盤の読み込みチェーンから返される） |
| `UserData` | `object` | `null` | ユーザーカスタムデータ |

出典： [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L69-L85)

イベントID定数には型の完全修飾名が使用されており、イベントの購読/購読解除時の識別子として利用できます：

```csharp
[Preserve] public static readonly string EventId = typeof(LoadDictionaryFailureEventArgs).FullName;

[Preserve]
public override string Id
{
    get { return EventId; }
}
```

## 修正手順

### 1. ErrorMessage でリソースが読み込み可能かを確認する

イベントコールバック内で3つのフィールドを出力し、まず `ErrorMessage` の具体的な内容を確認します。リソースが存在しない旨のメッセージであれば、`DictionaryAssetName` に対応する辞書リソースが生成されていない、またはパッケージに同梱されてビルドされていないことを意味します。コードを変更するのではなく、当該リソースの生成/パッケージング設定を確認してください。

```csharp
private void OnLoadDictionaryFailure(object sender, GameEventArgs e)
{
    var args = (LoadDictionaryFailureEventArgs)e;
    UnityEngine.Debug.LogError(
        $"字典加载失败: {args.DictionaryAssetName}, 错误: {args.ErrorMessage}");
}
```

出典： [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L36-L58)

説明：購読/購読解除のインターフェースは GameFrameX のイベントコンポーネントが提供し、購読時には `LoadDictionaryFailureEventArgs.EventId` をイベント識別子として使用します。コールバックの引数型は `GameEventArgs` であり、本イベント型にキャストしてからフィールドを読み取ります（イベント基底クラスと `using GameFrameX.Event.Runtime;` は、いずれもこのイベントクラスのファイル内の実際の参照です）。

### 2. DictionaryAssetName の由来を確認する

`DictionaryAssetName` の値は、読み込み開始時に渡された `dataAssetName` と同一です（下記の `Create` ファクトリメソッドを参照）。したがって「名前が正しくない」場合は、読み込みを呼び出している該当コード行に戻り、渡されているリソース名の文字列を確認してください（大文字/小文字、パスのプレフィックスとサフィックスに注意）。

```csharp
public static LoadDictionaryFailureEventArgs Create(string dataAssetName, string errorMessage, object userData)
{
    LoadDictionaryFailureEventArgs loadDictionaryFailureEventArgs = ReferencePool.Acquire<LoadDictionaryFailureEventArgs>();
    loadDictionaryFailureEventArgs.DictionaryAssetName = dataAssetName;
    loadDictionaryFailureEventArgs.ErrorMessage = errorMessage;
    loadDictionaryFailureEventArgs.UserData = userData;
    return loadDictionaryFailureEventArgs;
}
```

出典： [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L87-L102)

### 3. UserData で複数回の読み込みを区別する

同一フレーム内で複数の辞書を読み込んでいる場合、`DictionaryAssetName` だけでは呼び出し箇所を特定できないことがあります。読み込みを開始するたびに識別可能な `userData`（呼び出し元オブジェクトや列挙型マーカーなど）を渡すと、失敗イベントにそのまま返されるため、どの呼び出しが失敗したのかを特定できます。

### 4. イベントが確実に購読されていること、読み込みが確実に開始されていることを確認する

失敗イベントも成功イベント（`LoadDictionarySuccessEventArgs`）も発生しない場合は、まず以下を確認してください：

1. イベントリスナーが購読済みであること（`LoadDictionaryFailureEventArgs.EventId` を識別子として使用）。
2. 辞書読み込みの呼び出しが実際に実行されていること（呼び出しの前後にログを追加して確認できます）。
3. 使用しているアセンブリがストリッピングされていないこと――本コンポーネントは `GameFrameXLocalizationCroppingHelper` によって型を明示的に保持しています。ストリッピング設定をカスタマイズしている場合は、`LoadDictionaryFailureEventArgs` が除外されないようにしてください：

```csharp
_ = typeof(ILocalizationManager);
_ = typeof(LoadDictionaryFailureEventArgs);
_ = typeof(LoadDictionarySuccessEventArgs);
```

出典： [GameFrameXLocalizationCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/GameFrameXLocalizationCroppingHelper.cs#L44-L46)

## 検証

- 辞書の読み込みを再実行した後、失敗コールバックが呼ばれなくなり、コンソールに出力していた失敗ログも出力されなくなる。
- 該当する辞書リソースで `LoadDictionarySuccessEventArgs`（成功イベント、フィールドは `DictionaryAssetName`、`Duration`、`UserData`）が発生し、読み込みチェーンが復旧したことが確認できる。
- `LocalizationComponent` 上のローカライズテキストを再度読み取ると、辞書内のエントリを取得できる。

読み込み成功/進捗イベントおよびローカライズコンポーネント全体の使い方については、リポジトリの中国語版ドキュメント [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.zh-CN.md#L311-L313) を参照してください。

## 背景

このイベントは `GameEventArgs` を継承しており、インスタンスは `ReferencePool` 参照プールから取得され（`ReferencePool.Acquire<LoadDictionaryFailureEventArgs>()`）、`Clear()` 内で3つのフィールドを `null` にリセットしたうえでプールに返却されます。そのため、コールバック内でイベントオブジェクト自体をキャッシュせず、フィールドの値のみを読み取りまたはコピーしてください。イベント配信後、オブジェクトは再利用されます。
