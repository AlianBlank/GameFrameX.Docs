# 경로로 GObject 찾기

`FairyGUIPathFinderHelper.GetUIFromPath(path)`를 사용하면 런타임에 계층 경로(예: `GRoot/Group/MyButton`)로 직접 `GObject`를 가져올 수 있어, 계층마다 `GetChild`를 호출할 필요가 없습니다. 반대로 `gObject.GetUIPath()`를 사용하면 임의의 객체의 전체 경로를 얻을 수 있습니다.

## 사전 조건

- 네임스페이스 `FairyGUI`와 `GameFrameX.UI.FairyGUI.Runtime`을 참조하세요(이 Helper는 `GameFrameX.UI.FairyGUI.Runtime` 어셈블리에 포함되어 있습니다).
- 검색은 `GRoot.inst`에서 시작하며, 대상 객체는 현재 표시 목록(GRoot 아래)에 이미 연결되어 있어야 합니다. 열려 있지 않거나/이미 파괴된 화면 내의 객체는 찾을 수 없습니다.

## 작업 단계

1. (선택 사항) 먼저 전체 경로를 가져옵니다. 계층 이름이 확실하지 않다면, 임의의 `GObject`에 대해 확장 메서드 `GetUIPath()`를 호출하여 경로를 출력합니다:

```csharp
using FairyGUI;
using GameFrameX.UI.FairyGUI.Runtime;

// GObject의 계층 경로를 가져옵니다. 예: "GRoot/UISynthesisScene/ContentBox/ListSelect/1990197248/icon"
string path = gObject.GetUIPath();
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L43-L57)

2. 경로 문자열로 객체를 파싱하고, 반환값에 대해 null 검사를 수행합니다(찾지 못했을 때 메서드 내부에서 이미 오류 로그를 기록하고 `null`을 반환합니다):

```csharp
// 경로를 통해 GObject를 파싱합니다
GObject obj = FairyGUIPathFinderHelper.GetUIFromPath("GRoot/Group/MyButton");
if (obj == null)
{
    // 경로가 유효하지 않음: Log에 "error uiPath : can not found ui by this path : ..."가 출력됩니다
    return;
}
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L117-L145)

경로 형식 규칙(`GetUIFromPath`의 파싱 로직에 의해 결정됨):

| 작성법 | 규칙 |
|------|------|
| 구분자 | 각 레벨 이름을 `/`로 구분 |
| `GRoot` 세그먼트 | 자동으로 건너뛰며, 경로에 `GRoot` 접두사를 쓰든 안 쓰든 결과는 동일 |
| 일반 세그먼트 | `GComponent.GetChild(name)`를 호출하여 이름으로 찾으며, 에디터에서 설정한 객체 이름과 일치해야 함 |
| `$숫자` 세그먼트 | 먼저 전체 이름으로 `GetChild`를 시도하고, 찾지 못하면 `$` 뒤의 숫자를 하위 인덱스로 간주하여 `GetChildAt(index)`로 가져옴 |
| 빈 큐 | 빈 경로를 전달하면 루트 객체 `GRoot.inst`를 바로 반환 |

## 일반적인 변형

- **인덱스로 이름 없는 하위 객체 찾기**: 경로 세그먼트를 `$인덱스`로 작성합니다. 예를 들어 `"GRoot/MyList/$3"`는 `MyList`의 4번째 하위 객체를 의미합니다. 인덱스가 범위를 벗어나거나 컴포넌트가 아닌 노드에 매칭되면 예외를 던지고 `null`을 반환합니다:

```csharp
// 먼저 이름 "$3"으로 찾고, 실패하면 인덱스로 GetChildAt(3)을 호출하여 찾습니다
GObject item = FairyGUIPathFinderHelper.GetUIFromPath("GRoot/MyList/$3");
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L166-L187)

- **객체가 특정 경로 아래에 있는지 판단**: `SearchPathInclude`를 사용합니다. 경로를 `all`(대소문자 무시)로 작성하면 어떤 객체와도 매칭되지 않음을 의미합니다(`false` 반환):

```csharp
// gObject가 "GRoot/Group/Panel" 경로 아래에 있는지 판단합니다($인덱스 세그먼트 지원)
bool inside = FairyGUIPathFinderHelper.SearchPathInclude("GRoot/Group/Panel", gObject);
```

Source: [FairyGUIPathFinderHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPathFinderHelper.cs#L218-L276)

## 일반적인 오류

| 증상(Log.Error / 예외 원문) | 근본 원인 | 회피 방법 |
|------|------|------|
| `error uiPath : can not found ui by this path :{path}, error : ...` | 경로의 세그먼트 중 하나가 파싱에 실패하여, 메서드가 예외를 캐치한 후 `null`을 반환함 | 먼저 `GetUIPath()`로 실제 경로를 출력한 후 복사 |
| `Invalid UI path: child not found` | 특정 세그먼트 이름이 실제 하위 객체 이름과 일치하지 않음(대소문자, 이름 변경) | 에디터에서 객체 이름을 확인 |
| `Invalid UI path: index out of range` | `$인덱스`가 `numChildren` 범위를 벗어남 | 하위 객체 개수를 확인 |
| `Invalid UI path: not a GComponent` | 경로의 중간 노드가 일반 `GObject`(예: 이미지, 텍스트)로 하위 항목이 없음 | 중간 세그먼트는 반드시 컴포넌트 노드여야 함 |
| `null`이 반환되지만 경로 오류가 없음 | 대상 객체가 GRoot 아래에 표시되지 않음 | 화면이 열려 있고 닫히지 않았는지 확인 |

예외 발생 및 캐치 위치의 소스 코드 대조:

```csharp
if (index < 0 || index >= o.numChildren)
{
    throw new Exception("Invalid UI path: index out of range");
}
...
if (child == null)
{
    throw new Exception("Invalid UI path: child not found");
}
...
throw new Exception("Invalid UI path: not a GComponent");
```

## 배경

`GetUIPath`는 `SearchParent`를 통해 대상 객체에서 위로 단계별로 `name`을 수집한 뒤, 뒤집어서 `/`로 연결하므로 출력된 경로를 `GetUIFromPath`에 그대로 다시 전달하여 동일한 객체를 복원할 수 있습니다. `GetUIFromPath`는 경로를 큐로 분해한 후 `GRoot`를 건너뛰고 `GRoot.inst`부터 세그먼트별로 재귀적으로 `SearchChild`를 수행하며, 전체 과정에서 캐싱을 하지 않고 매 호출마다 현재 표시 트리를 실시간으로 순회합니다.
