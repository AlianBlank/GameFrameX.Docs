# 使用 Actor / ComponentAgent 调度并发任务

Actor 把"玩家/场景/全局"等业务实体包装成单线程串行执行的调度单元；ComponentAgent 是 Actor 上的可复用业务组件,所有跨实体调用都通过 `ActorManager` 获取,从而避免锁并保证数据一致。本页演示如何获取并调用 ComponentAgent 来调度并发任务。

## 前置条件

- 已接入 GameFrameX Actor 框架,`ActorManager` 在运行环境内可访问。
- 已存在一个继承 `ComponentAgent<TComponent>` 或 `StateComponentAgent<TComponent, TState>` 的组件 Agent。
- 业务实体已具备 `ActorId`(`long` 类型),无 `ActorId` 的全局 Agent 调用使用 `GetComponentAgent<T>()`。

## 操作步骤

1. 在任意可访问 Actor 的位置,通过 `ActorManager` 获取目标组件 Agent。

```csharp
// 全局共享组件(无 ActorId 维度)
var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
await serverComp.RemoveOnlineRole(ActorId);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L46-L53)

2. 需要操作某个玩家的组件时,把玩家 `ActorId` 作为第二个参数传入,框架会路由到对应 Actor 的串行队列。

```csharp
var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
await attributeComponentAgent.InitializeDefaultsSilent();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L77-L78)

3. 对同一 Actor 下的多个 Agent 串行调度时,按业务顺序 `await` 调用即可,框架保证同一 Actor 内调用串行执行。

```csharp
// 全部落在同一个玩家 ActorId 上,按顺序串行执行
var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
await mailAgent.SyncAsync();

var bagAgent = await ActorManager.GetComponentAgent<BagComponentAgent>(playerState.Id);
await bagAgent.SomeBusiness();
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L91-L92)

4. 当 Agent 的工作完成后,在持有 Actor 引用处设置自动回收,避免常驻。

```csharp
// 下线后会被自动回收
SetAutoRecycle(true);
QuartzTimer.Remove(ScheduleIdSet);
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L50-L52)

## 常见变体

| 场景 | 写法 | 说明 |
|------|------|------|
| 全局单例组件 | `await ActorManager.GetComponentAgent<T>()` | 不传 `ActorId`,获取进程级共享 Agent |
| 玩家私有组件 | `await ActorManager.GetComponentAgent<T>(actorId)` | 框架按 `actorId` 路由到对应玩家 Actor |
| 房间/场景组件 | `await ActorManager.GetComponentAgent<RoomComponentAgent>()` | 通常为全局 Agent,内部再按房间 Key 索引 |

## 常见错误

- 直接 `new T()` 创建 Agent:Agent 必须由 `ActorManager` 创建并托管,手动实例化会绕过串行队列与回收机制。
- 在不持有 `ActorId` 的地方调用玩家私有 Agent:会因找不到 Actor 而抛错;全局组件请使用无参 `GetComponentAgent<T>()`。
- 忘记在玩家下线时调用 `SetAutoRecycle(true)`:Agent 会持续驻留,占用队列与计时器资源(参考 [PlayerComponentAgent.OnLogout](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L45-L53))。

## 背景(可选)

Actor 模型将"对同一玩家/场景的并发访问"转化为串行消息队列,ComponentAgent 则是挂在 Actor 上的业务单元;`ActorManager` 同时承担组件生命周期与跨 Actor 路由,这也是登录流程里所有初始化操作都能在单 `await` 链中完成而无需锁的原因。
