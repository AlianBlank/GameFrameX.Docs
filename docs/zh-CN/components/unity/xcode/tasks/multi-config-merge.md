# 多模块配置文件合并

把每个模块各自的 iOS 构建配置写成一份 `XCodeConfig.json`，框架在 Xcode 工程导出后会自动扫描、合并所有同名配置文件（含渠道专属配置），再把合并结果一次性写入 Xcode 工程。你不需要手工汇总一份大配置，只要把文件放在能被扫描到的位置即可。

## 前置条件

- Unity 项目已引入本包（Editor 程序集 `GameFrameX.Xcode.Editor`）。
- 构建目标为 iOS：整个合并流程位于 `#if UNITY_IOS` 内，其他平台直接返回。

## 操作步骤

1. 为每个模块创建一份 `XCodeConfig.json`，只写本模块关心的字段。框架通过 `SettingLoader.LoadSettingsData("XCodeConfig.json")` 扫描出全部匹配文件的路径列表（见 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58)）。
2. 执行 iOS 构建。构建完成后 Unity 回调自动执行，开始读取并合并配置：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        //读取配置文件
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 如果没有找到任何匹配的文件，直接返回
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }

        // 合并所有配置文件的内容
        Hashtable finalConfig = new Hashtable();
        foreach (var jsonPath in jsonPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
            string json = File.ReadAllText(jsonPath);
            Hashtable table = json.HashtableFromJson();
            if (table == null)
            {
                LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
                continue;
            }

            // 使用扩展方法合并 Hashtable
            finalConfig.Merge(table);
        }
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L49)

3. （可选）提供渠道专属配置。框架通过 `SettingLoader.GetChannel()` 取得当前渠道，再加载 `XCodeConfig.{channel}.json` 并在最后合并，因此渠道配置优先级最高、会覆盖普通配置中的同名字段：

```csharp
// 合并渠道专属配置（优先级最高，最后合并覆盖）
string channel = SettingLoader.GetChannel();
if (!string.IsNullOrEmpty(channel))
{
    var channelPaths = SettingLoader.LoadChannelSettingsData("XCodeConfig.json", channel);
    if (channelPaths.Count > 0)
    {
        LogHelper.Log($"[MergeConfig] 检测到渠道: {channel}，正在合并渠道配置...");
        foreach (var channelPath in channelPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并渠道配置: {channelPath}");
            string channelJson = File.ReadAllText(channelPath);
            Hashtable channelTable = channelJson.HashtableFromJson();
            if (channelTable == null)
            {
                LogHelper.Error($"{channelPath} 解析失败, 跳过合并");
                continue;
            }

            finalConfig.Merge(channelTable);
        }
    }
    else
    {
        LogHelper.Log($"[MergeConfig] 未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json");
    }
}
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)

4. 检查 Console 输出。每份被合并的文件都会打印 `[MergeConfig] 正在合并配置: <路径>`（渠道配置为 `[MergeConfig] 正在合并渠道配置: <路径>`），据此确认哪些文件参与了合并。

## 可合并的顶层配置字段

合并结果按下列键应用（键名来自 `finalConfig.Get<...>(...)` 的真实取值，任何模块都只需提供自己用到的键）：

| 键 | 类型 | 应用动作 |
|----|------|----------|
| `unityMain` | Hashtable | 应用到 Unity 主 Target：`properties`、`frameworks`、`libs`、`files`、`folders`、`filesCompileFlag`、`otherLinkerFlag`、`runPathSearchPaths`（及旧式 `pods`） |
| `unityFramework` | Hashtable | 同上，应用到 UnityFramework Target |
| `signing` | Hashtable | 签名配置，仅在主 Target 上设置；其 `bundleId` 供 Capabilities 使用 |
| `swiftBridging` | bool | Swift 桥接开关，缺省视为开启 |
| `plist` | Hashtable | 写入 Info.Plist |
| `environmentVariables` | Hashtable | 启动环境变量 |
| `launcherArgs` | ArrayList | 运行启动参数 |
| `capabilities` | Hashtable | Capability 设置，仅在主 Target 上设置 |
| `localizations` | ArrayList | 本地化资源 |
| `podSource` | ArrayList | Podfile 的 source 源 |
| `podfile` | string | 完整 Podfile 的配置路径，复制成功后走新路径 |
| `podInstall` | bool | 是否在 Podfile 处理后执行 `pod install`，缺省视为开启 |

## 常见变体

- **某模块 JSON 解析失败仍要完成构建**：单份文件解析失败只会打 `Error` 日志并 `continue`，不会中断整体流程；其余文件继续合并。
- **不想执行 `pod install`**：在（任一参与合并的）配置中写 `"podInstall": false`，见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L151-L156)。
- **关闭 Swift 桥接**：写 `"swiftBridging": false`；不写该键时默认开启，见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101)。

## 常见错误

| 症状（日志原文） | 原因 | 修复 |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 扫描结果为空，没有任何模块提供配置 | 确认至少存在一份可被 `LoadSettingsData` 扫描到的 `XCodeConfig.json` |
| `<路径> 解析失败, 跳过合并` | 该文件内容不是合法 JSON，`HashtableFromJson()` 返回 null | 修正该文件的 JSON 语法；该文件被跳过，其余文件正常合并 |
| `合并后的配置为空，跳过设置` | 所有文件都解析失败或内容为空 | 逐份检查 JSON；从 `[MergeConfig] 正在合并配置:` 日志核对参与合并的文件清单 |
| `[MergeConfig] 未找到渠道 [...] 的专属配置文件 XCodeConfig.[...].json` | 渠道已设置但缺少渠道专属文件 | 按需补建 `XCodeConfig.{渠道}.json`；不补也不影响普通配置生效 |

## 验证

- Console 中出现 `[MergeConfig] 正在合并配置: ...` 列出全部参与的文件；设置渠道时出现 `[MergeConfig] 检测到渠道: <渠道>` 与对应的渠道合并日志。
- 随后出现 `[PBXProject] 正在应用最终合并配置...` 与 `[OtherSettings] 正在应用最终合并配置...`，表示合并结果已写入工程。
- 打开导出的 Xcode 工程，核对 Target 的构建属性、框架/库、Info.Plist、Podfile 等是否与合并后预期一致。

## 背景

合并基于 `Hashtable.Merge()` 扩展方法逐份叠加，后合并的覆盖先合并的，因此加载顺序就是优先级顺序；渠道配置最后合并，优先级最高。整个流程对 `Get<Hashtable>(...)` 的取值做了 null 容错，所以每个模块只写自己需要的键即可，不必提供完整结构。
