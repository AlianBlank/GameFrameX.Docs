# 入口別ホットアップデート読み込み（Main / Entry / GateWay / Heart）

GameFrameX.Server は「入口別ホットアップデート読み込み」を4つのpartialクラスファイルに分割し、統一的に`AppStartUpBase`を継承し、`AppStartUpHotfixGame`をpartialコンテナとしています：`Main`は業務サーバーのネットワーク層とメッセージ配信を担当し、`Entry`は初回起動/リロードとグローバルコンポーネントの有効化を担当し、`GateWay`はゲートウェイ接続とハートビートを担当し、`Heart`はクライアントハートビート応答を担当します。

## 入口ファイル一覧

| 入口 partial | ファイル | トリガーシナリオ |
|---|---|---|
| Main | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs` | `AppStartUpHotfixGame.StartAsync()`、`RunServer()`、`OnConnected`/`OnDisconnected`/`PackageHandler`、`StopAsync` |
| Entry | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs` | `OnLoadSuccess(setting, reload)`（初回起動とリロード）、`Stop(message)` |
| GateWay | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByGateWay.cs` | ゲートウェイサーバーとのTCP接続確立、切断再接続、ハートビート維持、メッセージ上行 |
| Heart | `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByHeart.cs` | クライアントハートビートメッセージ`ReqHeartBeat`の解析と`NotifyHeartBeat`応答 |

4つのファイルはC#の`partial class`メカニズムにより同じ`AppStartUpHotfixGame`に合成され、追加登録は不要です。

## 起動順序（コードで直接参照可能）

1. `Entry.OnLoadSuccess(AppSetting setting, bool reload)` —— `AppSetting`を取得し、ホットリロードかどうかを判定する。
   - `reload == true`：`ActorManager.ClearAgent()`後に直接戻る。
   - `reload == false`：完全な初回起動フローを実行する。
2. `Entry.Init(setting.ServerType, setting)` —— フレームワーク基盤を初期化する。
3. `Entry.RunServer()` → `Main.StartAsync()` —— SuperSocketサーバーを起動し、圧縮/解凍、HTTPプロセッサとすべてのTcpHandlerを組み立てる。
4. `Entry`は`QuartzTimer.Start()`、`GlobalTimer.Start()`と`ComponentRegister.ActiveGlobalComponents()`を起動する。
5. `Main.PackageHandler`がクライアントメッセージを受信した時：ハートビートメッセージは`Heart.ReplyHeartBeat`に転送され、業務メッセージは`HotfixManager.GetTcpHandler`により配信される。

出典：[AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L37-L60) と [AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L43-L65)。

## 各入口の責務

### Main — ネットワーク層とメッセージ配信

`StartAsync()`はネットワークサービスを開始し、HTTPプロセッサを読み込みます：

```csharp
public override async Task StartAsync()
{
    await StartServerAsync<DefaultMessageDecoderHandler, DefaultMessageEncoderHandler>(
        new DefaultMessageCompressHandler(),
        new DefaultMessageDecompressHandler(),
        HotfixManager.GetListHttpHandler(),
        HotfixManager.GetHttpHandler);
}
```

出典：[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L45-L52)

`RunServer(bool reload = false)`は毎回`ConfigComponent.Instance.LoadConfig()`を実行します；`reload`時はActorをクリアした後に直接戻り、そうでなければ`StartAsync()`に入ります。

`PackageHandler`ではまず`NetworkMessagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat`のメッセージを`ReplyHeartBeat`に分流し、その他は`MessageId`で配信します：

```csharp
if (messagePackage.Header.OperationType == (byte)MessageOperationType.HeartBeat)
{
    ReplyHeartBeat(netWorkChannel, (MessageObject)messagePackage.DeserializeMessageObject());
    return;
}
var handler = HotfixManager.GetTcpHandler(messagePackage.Header.MessageId);
```

出典：[AppStartUpHotfixGameByMain.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L113-L135)

`OnConnected`では`SessionManager.Count()`と`Setting.MaxClientCount`により最大オンライン人数を制御します；`OnDisconnected`は`RoomComponentAgent.MarkPlayerDisconnected`に通知します。

### Entry — 初回起動 / リロード

`OnLoadSuccess`はホットアップデートフレームワークから呼び出される入口で、「ホットリロード」と「初回起動」を区別する役割を担います：

```csharp
public async Task<bool> OnLoadSuccess(AppSetting setting, bool reload)
{
    if (reload)
    {
        ActorManager.ClearAgent();
        return true;
    }

    Init(setting.ServerType, setting);
    await RunServer();
    await QuartzTimer.Start();
    GlobalTimer.Start();
    await ComponentRegister.ActiveGlobalComponents();
    return true;
}
```

出典：[AppStartUpHotfixGameByEntry.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs#L39-L54)

`Stop(message)`は直接`Main.StopAsync(message)`に転送され、ホットアップデートフレームワークの停止コールバックとなります。

### GateWay — ゲートウェイとの通信

ファイルには`AsyncTcpSession _gatewayClient`、`_gateWayReconnectionTimer`と`_gateWayHeartBeatTimer`が含まれており、切断時は`_gateWayReconnectionTimer`により再接続がトリガーされ、メッセージの配信に成功するたびに`_gateWayHeartBeatTimer.Reset()`でハートビートタイマーがリセットされます。

`SendToGatewayMessage`はゲートウェイへの上行の統一チャネルです：接続が確立されている場合は`_gatewayClient.TrySend(span)`を呼び出してメッセージを配信します。

### Heart — クライアントハートビート応答

`PackageHandler`はハートビートを`ReplyHeartBeat`に渡し、partialファイル内で`NotifyHeartBeat`を構築してチャネルに書き戻します：

```csharp
if (messageObject is ReqHeartBeat req)
{
    netWorkChannel.UpdateReceiveMessageTime();
    NotifyHeartBeat notifyHeartBeat = MessageObjectPoolHelper.Get<NotifyHeartBeat>();
    notifyHeartBeat.Timestamp = TimerHelper.UnixTimeMilliseconds();
    notifyHeartBeat.UniqueId = req.UniqueId;
    await netWorkChannel.WriteAsync(notifyHeartBeat);
}
```

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| ホットリロード後も古い業務ロジックが実行され続ける | `OnLoadSuccess`の`reload == true`分岐で`ActorManager.ClearAgent()`の呼び出しを忘れている | 既存の`ClearAgent()`呼び出しを維持し、古いActorキャッシュが確実にクリアされるようにする |
| クライアントが切断され続け、`NotifyServerFullyLoaded`後にキックされる | `Setting.MaxClientCount`制限が有効で、新しい接続が上限を超えている | `appsettings.json`で`MaxClientCount`を引き上げるか、異常接続を調査する |
| `[xxx][yyy]に対応するhandlerが見つかりません`ログ | `messagePackage.Header.MessageId`が`HotfixManager`に登録されていない | 対応するホットアップデートモジュールのHandler登録表に`MessageId`を補完する |

## 背景（オプション）

4つのファイルを「段階」ではなく「責務」で分割しているのは、Mainのネットワーク層とEntryのライフサイクルがそれぞれpartialを占有し、GateWay / Heartのような横断的な関心事も独立したファイルとなるようにするためです；すべてのpartialが同じ`AppStartUpHotfixGame`にマージされた後、基底クラス`AppStartUpBase`と`IHotfixBridge`はコンパイル時に単一の型入口のみを必要とし、ホットアップデートフレームワークの結合面が削減されます。
