# 如何配置主机服务器地址

在 `GlobalConfigComponent` 上设置 `HostServerUrl`,客户端即可在启动时拿到后端根地址,用于拼接版本检测、资源更新等接口。

## 前置条件

- 已将 `GameFrameX.GlobalConfig` 组件挂载到游戏入口场景,组件类型为 `GlobalConfigComponent`。
- 准备一个可用的 HTTP/HTTPS 主机地址(以 `http://` 或 `https://` 开头,末尾不需要再加 `/`)。

## 操作步骤

1. 在场景中找到挂有 `GlobalConfigComponent` 的 GameObject,选中后在 Inspector 中可以看到 "主机服务地址" 字段。该字段对应序列化字段 `m_hostServerUrl`。

   ```csharp
   // Runtime/GlobalConfig/GlobalConfigComponent.cs:L98-L112
   /// <summary>
   /// 主机服务地址
   /// </summary>
   [SerializeField] private string m_hostServerUrl = string.Empty;

   /// <summary>
   /// 主机服务地址
   /// </summary>
   public string HostServerUrl
   {
       get { return m_hostServerUrl; }
       set { m_hostServerUrl = value; }
   }
   ```

2. 在 Inspector 的 "主机服务地址" 输入框中填入完整 URL,例如 `https://api.example.com`。

3. 如果需要在运行时(例如读档、热更新中心下发后)修改地址,通过 `GlobalConfigComponent` 实例的属性赋值即可:

   ```csharp
   var globalConfig = GameEntry.GetComponent<GlobalConfigComponent>();
   globalConfig.HostServerUrl = "https://api.example.com";
   ```

4. 验证:启动游戏后,在 Inspector 的 "原始数据"(对应 `OriginalData`)或控制台日志中可以观察到该字段已生效;后续所有依赖该地址拼接的下游接口(版本检查、资源版本检查)都会自动使用新值。

## 常见变体

- 与 `CheckAppVersionUrl` / `CheckResourceVersionUrl` 配合使用:当 "主机服务地址" 仅作根域名,而版本检查走独立 CDN 时,可分别填入对应字段,避免被主机地址覆盖。
- 通过 `OriginalData` 批量下发:服务器返回的整段 JSON 会被反序列化并写回 `m_originalData`,业务可读取该原始串再分发到各子系统。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 设置后接口仍走旧地址 | 字段赋值发生在场景已激活但下游已缓存旧值之后 | 在 `GameEntry` 启动流程最早期、或下游读取之前赋值 |
| 地址末尾多了 `/` 导致请求路径变成 `//api/...` | 习惯性在域名后追加斜杠 | 去掉末尾的 `/`,由调用方按需拼接 |
| Inspector 中字段灰显无法编辑 | 当前处于 Play 模式,Inspector 会禁用编辑以避免运行时改动丢失 | 退出 Play 模式后再修改,或使用属性赋值 |
