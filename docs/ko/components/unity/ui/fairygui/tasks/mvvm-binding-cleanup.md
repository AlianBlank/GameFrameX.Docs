# MVVM 바인딩과 이벤트 자동 정리

FairyGUI UI에서 `BindableProperty<T>`로 데이터 바인딩을 수행할 때, 확장 메서드 `ClearWithGObjectDestroyed`를 호출하기만 하면 이벤트 정리를 `GObject`의 `onRemovedFromStage`에 연결할 수 있습니다. GObject가 디스플레이 리스트를 벗어날 때(파괴 포함) `bindableProperty.Clear`가 자동으로 실행되므로, 더 이상 구독 해제 로직을 직접 작성할 필요가 없으며 이벤트 잔존과 메모리 누수를 방지할 수 있습니다.

## 사전 조건

- `com.gameframex.unity.fairygui` 패키지가 설치되어 있어야 합니다(README 의존성 표 참조: `com.gameframex.unity` 1.1.1, `com.gameframex.unity.ui` 1.0.0 등).
- `BindableProperty<T>`는 GameFrameX 코어 패키지에 속하며 네임스페이스는 `GameFrameX.Runtime`입니다. 확장 메서드 자체는 `GameFrameX.UI.FairyGUI.Runtime`에 위치합니다.
- UI 클래스는 `FUI`를 상속합니다(`FUI`는 `GObject` 속성을 노출합니다. [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L43-L53) 참조).

## 작업 단계

1. UI/로직 클래스에서 바인딩 속성을 생성합니다. 예를 들어 `BindableProperty<int>`, `BindableProperty<string>` 등이 있으며, 해당 이벤트를 구독하여 데이터 바인딩을 완료합니다.

2. 해당 UI의 라이프사이클과 일치하는 `GObject`를 가져온 후, 확장 메서드를 호출하여 자동 정리를 등록합니다:

```csharp
// GObject가 파괴될 때 이벤트 자동 구독 해제
myProperty.ClearWithGObjectDestroyed(gObject);
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L123-L128)

3. 이후에는 평소처럼 UI를 닫거나 파괴하기만 하면 되며, 바인딩 속성 이벤트를 수동으로 구독 해제할 필요가 없습니다.

확장 메서드의 전체 구현은 다음과 같습니다(전체 메커니즘은 단 한 줄의 등록입니다):

```csharp
[UnityEngine.Scripting.Preserve]
public static void ClearWithGObjectDestroyed<T>(this BindableProperty<T> bindableProperty, GObject gObject)
{
    gObject.onRemovedFromStage.Add(bindableProperty.Clear);
}
```

출처: [BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L52-L56)

## 일반적인 변형

- **FUI 하위 클래스에서 바인딩**: `FUI`를 상속한 UI는 자체 `GObject`를 라이프사이클 앵커로 직접 사용할 수 있습니다. 예를 들어 바인딩 초기화 지점에서 `myProperty.ClearWithGObjectDestroyed(GObject);`를 호출하면, UI가 파괴될 때 이벤트도 함께 정리됩니다.
- **모든 제네릭 타입 지원**: 이 메서드는 제네릭 확장이므로 `BindableProperty<int>`, `BindableProperty<string>` 등 모든 `T`에 대해 직접 호출할 수 있으며, 타입별로 별도의 정리 코드를 작성할 필요가 없습니다.

## 일반적인 오류

| 증상 | 원인 | 회피 방법 |
|------|------|----------|
| UI 파괴 후에도 바인딩 이벤트가 계속 트리거되고 객체가 회수되지 않음 | `ClearWithGObjectDestroyed` 호출을 잊어서 구독이 바인딩 속성에 남아 있음 | 바인딩 속성 이벤트를 구독할 때마다 즉시 동일한 GObject로 이 확장 메서드를 한 번 호출 |
| `NullReferenceException` | 전달한 `gObject`가 null임(UI가 아직 GObject를 생성하지 않은 상태에서 호출) | GObject 초기화가 완료된 후에 호출하도록 하세요. `FUI.Visible`의 구현 역시 `GObject`가 null일 수 있음을 보여줍니다([FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L135-L149)) |
| 이벤트가 "아직 파괴되지 않은 것처럼 보이는" 시점에 정리됨 | 트리거 훅은 `onRemovedFromStage`(디스플레이 리스트에서 벗어남)이며 단순한 파괴가 아닙니다. 객체를 디스플레이 리스트에서 제거하는 모든 작업이 `Clear`를 트리거합니다 | GObject를 디스플레이 리스트에서 동적으로 제거했다가 재사용하는 경우, 디스플레이 리스트에 다시 추가한 후 다시 바인딩하고 이 메서드를 다시 호출하세요 |

## 검증

- UI를 닫은 후 바인딩 속성의 값을 변경하여 더 이상 UI 콜백이 트리거되지 않는지 확인합니다.
- `Clear` 적용 전후로 메모리 프로파일러(예: Unity Memory Profiler)로 비교하여 UI 관련 객체가 회수될 수 있는지 확인합니다.

## 배경

이 메커니즘은 의도적으로 극도로 간단하게 만들어졌습니다: FairyGUI의 `GObject.onRemovedFromStage` 이벤트를 활용하여 `BindableProperty.Clear`를 콜백으로 등록합니다([BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L55)). 바인딩 속성 자체는 GameFrameX 코어 패키지(`GameFrameX.Runtime` 네임스페이스)에 속하며, UI 계층은 이것과 GObject의 라이프사이클 사이에 "파괴 즉시 정리"라는 연관을 구축하는 역할만 담당합니다. 코드 스트리핑으로 인해 제거되는 것을 방지하기 위해 메서드에 `[UnityEngine.Scripting.Preserve]`가 표시되어 있습니다.
