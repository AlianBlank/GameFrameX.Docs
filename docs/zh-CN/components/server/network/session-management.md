# 管理客户端会话(Session / 连接断开)

GameFrameX 通过 `Session` 与 `SessionManager` 维护每个网络连接的会话状态,包括登录后的角色绑定、顶号踢人、连接断开清理等行为。读完本页你可以在登录、踢人、掉线等场景中正确地读写 Session,并接住 `EventId.SessionRemove` 事件做下线收尾。

## 前置条件

- 已引入 `GameFrameX.Apps.Common.Session` 命名空间(代码位于 [Session.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs) 与 [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs))。
- 已使用框架的 `AppStartUp` 接入协议,并通过 `IAppSession` 拿到连接信息。
- 玩家 Actor 已通过 `ActorManager` 注册(否则 `GetByRoleId` 会返回空)。

## 操作步骤

### 1. 在握手/登录成功后创建并登记 Session

登录成功时由 `AppStartUp` 调用 `SessionManager.Add` 把当前连接登记到全局字典。底层会把 `SessionId` 写入通道数据,便于协议层回调时按 ID 反查。

```csharp
using GameFrameX.Apps.Common.Session;

// netWorkChannel 来源于协议层的 INetWorkChannel
var session = new Session(sessionId, netWorkChannel);
SessionManager.Add(session);
```

Source: [SessionManager.cs#L186-L191](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L186-L191)

### 2. 登录成功后绑定角色 ID 与签名

通过 `UpdateSession` 把 `roleId` 与 `sign` 写入当前连接;如果该 `roleId` 已在另一台设备登录,框架会向旧会话下发"账号已在其他设备登陆"提示并踢下线。

```csharp
SessionManager.UpdateSession(sessionId, roleId, sign);
```

底层行为(摘自源码):

1. 用 `GetByRoleId(roleId)` 找出旧会话。
2. 构造 `RespPrompt { Type = 5, Content = "你的账号已在其他设备上登陆" }` 通过 `oldSession.WriteAsync` 下发。
3. 调用 `oldSession.WorkChannel.ClearData()` + `Close()`,并 `Remove(oldSession.SessionId)`。
4. 给当前会话调用 `SetPlayerId(roleId)` / `SetSign(sign)`。

Source: [SessionManager.cs#L200-L229](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L200-L229)

### 3. 通过 Session 给客户端回消息

`Session.WriteAsync` 委托给底层网络通道发送,可附带错误码。

```csharp
var session = SessionManager.Get(sessionId);
if (session != null)
{
    await session.WriteAsync(messageObject, errorCode: 0);
}
```

Source: [Session.cs#L99-L105](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs#L99-L105)

### 4. 监听连接断开(主动踢人 / 网络掉线)

连接断开由 `AppStartUp` 钩子统一处理,源码示例(节选):

```csharp
protected override async ValueTask OnDisconnected(IAppSession appSession, CloseEventArgs disconnectEventArgs)
{
    var session = SessionManager.Get(appSession.Id);
    if (session != null)
    {
        var roomAgent = await ActorManager.GetComponentAgent<RoomComponentAgent>();
        await roomAgent.MarkPlayerDisconnected(session.PlayerId);
    }
}
```

`RoomComponentAgent` 中预留了 120 秒掉线宽限(`DisconnectedPlayerAutoLeaveSeconds`),超时才会真正踢出房间。

Source: [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76)、[RoomComponentAgent.cs#L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L45)

### 5. 响应 SessionRemove 事件做下线收尾

`SessionManager` 在三种情况下会派发 `EventId.SessionRemove`(值=1000):

- `Remove(sessionId)`
- `KickOffLineByUserId(roleId)`
- `RemoveAll()`
- `UpdateSession` 顶号时移除旧会话

框架用 `[Event(EventId.SessionRemove)]` 特性把监听器绑定到玩家 Agent,默认实现会调用 `agent.OnLogout()`。你可以按业务扩展:

```csharp
[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

Source: [SessionRemoveEventListener.cs#L39-L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L39-L45)、[EventId.cs#L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Event/EventId.cs#L41)

## 常见变体

### 按角色 ID 主动踢人

```csharp
SessionManager.KickOffLineByUserId(roleId);
```

会在内部派发 `SessionRemove`,触发 `OnLogout`。来源:[SessionManager.cs#L79-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L79-L89)。

### 关闭时清空所有会话

```csharp
await SessionManager.RemoveAll();
```

会逐个派发 `SessionRemove` 后 `Clear()` 字典。来源:[SessionManager.cs#L158-L170](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L158-L170)。

### 分页查询在线玩家

`GetPageList(pageSize, pageIndex)` 会过滤掉 `ActorManager` 中已不存在的 Actor,只返回真正在线的玩家。来源:[SessionManager.cs#L65-L73](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L65-L73)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GetByRoleId(roleId)` 始终返回 null | 玩家 Actor 未注册,或 `SessionMap` 已被异步清理 | 确保登录流程中 `ActorManager` 已注册玩家,且调用方在 Session 生命周期内访问 |
| 顶号提示发出后旧连接没立即关闭 | 仅 `WriteAsync` 没调用 `WorkChannel.Close()` | 使用框架自带的 `SessionManager.UpdateSession` 流程,不要自己手动管理旧会话 |
| 掉线玩家没自动离房 | 没在 `OnDisconnected` 调用 `MarkPlayerDisconnected` | 参考 [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76) 模板,把断连转发到房间 Agent |

## 背景(可选)

`SessionManager` 使用 `ConcurrentDictionary<string, Session>` 作为全局存储,每个连接一个 `SessionId`;`Session` 内部持有 `INetWorkChannel` 用于收发数据。`UpdateSession` 的"先移除再等 Disconnected"注释([L217](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L217))说明顶号时若只靠断连回调清理会产生延迟,因此同步 `Remove` 旧条目以保证状态一致。
