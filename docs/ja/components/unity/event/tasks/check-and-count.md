# サブスクリプション状態の確認とハンドラー数の集計方法

`EventComponent` の `Check`（特定の処理関数が既にサブスクライブされているかを確認）、`Count`（指定したイベント ID の処理関数の数を集計）、`EventHandlerCount` / `EventCount`（グローバル統計）を使用することで、サブスクリプション状態の確認と数量の集計が行えます。また、Unity Inspector で実行時に統計値を直接確認することもできます。

## 前提条件

- シーンに Event コンポーネント（`EventComponent`、メニューパス `GameFrameX/Event`）が既に存在すること。
- コード内で名前空間 `GameFrameX.Event.Runtime` をインポートしていること。

## API 概要

| 名称 | シグネチャ | 説明 |
|------|------|------|
| `Check` | `bool Check(string id, EventHandler<GameEventArgs> handler)` | 指定されたイベント処理関数が存在するかを確認します |
| `Count` | `int Count(string id)` | 指定したイベント ID のイベント処理関数の数を取得します |
| `EventHandlerCount` | `int { get; }` | イベント処理関数の総数を取得します |
| `EventCount` | `int { get; }` | イベント数を取得します |
| `CheckSubscribe` | `void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)` | 存在しない場合にのみ自動的にサブスクライブします（`EventComponent` のみで提供） |
| `CheckUnsubscribe` | `void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)` | 存在する場合にのみサブスクリプションを解除し、存在しない場合は何も実行しません |

上記のシグネチャはインターフェース定義とコンポーネントのラッパー層から抜粋したものです：

```csharp
int EventHandlerCount { get; }

int EventCount { get; }

int Count(string id);

bool Check(string id, EventHandler<GameEventArgs> handler);

void Subscribe(string id, EventHandler<GameEventArgs> handler);

void Unsubscribe(string id, EventHandler<GameEventArgs> handler);

void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler);
```

出典：[IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L38-L106)

`EventComponent` 上の対応するラッパーと冪等サブスクリプションの実装：

```csharp
public int Count(string id)
{
    return m_EventManager.Count(id);
}

public bool Check(string id, EventHandler<GameEventArgs> handler)
{
    return m_EventManager.Check(id, handler);
}

public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}

public void CheckUnsubscribe(string id, EventHandler<GameEventArgs> handler)
{
    m_EventManager.CheckUnsubscribe(id, handler);
}
```

出典：[EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L84-L131)

## 操作手順

1. `EventComponent` の参照を取得します（例：コンポーネント参照や既存の取得方法による）。
2. サブスクリプション状態の確認：`Check(id, handler)` を呼び出し、`true` が返された場合、その `handler` は `id` に対応するイベントを既にサブスクライブしています。
3. 単一イベントの集計：`Count(id)` を呼び出すと、そのイベント ID に登録済みの処理関数の数が返されます。
4. グローバル統計：`EventHandlerCount`（処理関数の総数）と `EventCount`（イベント数）を読み取ります。
5. 冪等な操作が必要な場合は、`Subscribe` / `Unsubscribe` の代わりに `CheckSubscribe` / `CheckUnsubscribe` を使用します。

呼び出し例（上表で確認済みの実際のシグネチャを使用）：

```csharp
using System;
using GameFrameX.Event.Runtime;

// 特定の処理関数が既にサブスクライブされているか確認
bool subscribed = eventComponent.Check("MyEventId", OnMyEvent);

// 特定のイベント ID の処理関数の数を集計
int handlerCount = eventComponent.Count("MyEventId");

// グローバル統計
int totalHandlers = eventComponent.EventHandlerCount;
int eventCount = eventComponent.EventCount;

// 冪等サブスクリプション：存在しない場合にのみサブスクライブ
eventComponent.CheckSubscribe("MyEventId", OnMyEvent);

// 冪等サブスクリプション解除：存在しない場合は何も実行しない
eventComponent.CheckUnsubscribe("MyEventId", OnMyEvent);

void OnMyEvent(object sender, GameEventArgs e)
{
    // イベント処理ロジック
}
```

## 一般的なバリエーション

**Inspector で統計を確認する**：シーン内の Event コンポーネントを選択すると、Inspector に `Event Handler Count` と `Event Count` が読み取り専用フィールドとして表示されます。実行時にのみ確認できます：

```csharp
if (!EditorApplication.isPlaying)
{
    EditorGUILayout.HelpBox("Available during runtime only.", MessageType.Info);
    return;
}

EventComponent t = (EventComponent)target;

if (IsPrefabInHierarchy(t.gameObject))
{
    EditorGUILayout.LabelField("Event Handler Count", t.EventHandlerCount.ToString());
    EditorGUILayout.LabelField("Event Count", t.EventCount.ToString());
}
```

出典：[EventComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Editor/Inspector/EventComponentInspector.cs#L43-L55)

**インターフェースのみに依存したプログラミング**：`IEventManager` も同様に `Check` / `Count` / `EventHandlerCount` / `EventCount` / `CheckUnsubscribe` を公開しており、モジュールのインターフェースを通じて直接呼び出せます。ただし、`CheckSubscribe` は `EventComponent` のみで提供されており、インターフェース層には存在しない点に注意してください。

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| Inspector に統計値が表示されず "Available during runtime only." と表示される | 統計は Play モードでのみ利用可能 | 実行モードに入ってから確認する |
| 同じ `handler` を重複してサブスクライブする | `Check` が `true` を返しても再度 `Subscribe` を呼び出している | サブスクライブ前に `Check` を行うか、直接 `CheckSubscribe` を使用する |
| 未登録の `handler` のサブスクリプションを解除する | `Unsubscribe` を直接呼び出している | `CheckUnsubscribe` を使用する（存在しない場合は何も実行しない） |
| 統計値が期待と一致しない | `Count(id)`（単一イベント ID）と `EventHandlerCount`（全処理関数の総数）を混同している | 必要に応じて対応する API を選択する |

## 背景

`EventManager` は内部で `EventPool<GameEventArgs>` に基づいて実装されており、すべてのクエリは最終的にイベントプールへ転送されます。また、`EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler` モードで作成されるため、処理関数を持たないイベントが許可され、同じイベントに複数の処理関数を登録することもできます：

```csharp
public EventManager()
{
    m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
}
```

出典：[EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L46-L49)

`Check` / `Count` も `EventManager` 内で同様にイベントプールへ直接転送されます：

```csharp
public int Count(string id)
{
    return m_EventPool.Count(id);
}

public bool Check(string id, EventHandler<GameEventArgs> handler)
{
    return m_EventPool.Check(id, handler);
}
```
