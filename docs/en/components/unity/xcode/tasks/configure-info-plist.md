# Configure Info.plist Permissions and URL Schemes

Add key-value pairs to the top-level `plist` field in the Xcode build configuration (JSON). After the build, `PostProcessBuildHelper` will automatically write them into the generated `Info.plist`. Permission description texts, URL Schemes, scheme whitelists, and so on are all handled through this single configuration, with no need to manually modify the Xcode project.

## Prerequisites

- The Unity project has the `com.gameframex.unity.xcode` package installed.
- Building for the iOS platform (Xcode-related code is compiled under `#if UNITY_IOS`).
- You already have an Xcode build configuration file containing a top-level `plist` object (it can be empty):

```json
"plist": {},
```

Source: [README.ja.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.ja.md#L84-L86)

## Steps

1. Open the Xcode build configuration file and locate the top-level `plist` field (create a new empty object if there isn't one).
2. Add string key-value pairs such as permission descriptions, for example usage descriptions for the camera and photo library.
3. If third-party login / launch callbacks are needed, add `CFBundleURLTypes` to register URL Schemes.
4. If you need to detect whether other Apps are installed (mandatory on iOS 9+), add the `LSApplicationQueriesSchemes` whitelist.
5. Run the iOS build. When the console shows the `设置项目[Info.plist]开始` and `设置项目[Info.plist]结束` logs, the write has succeeded:

```csharp
LogHelper.Log("设置项目[Info.plist]开始");
//plist
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
SetPlist(project, plist.root, hashtable);
// Write
plist.WriteToFile(plistPath);
LogHelper.Log("设置项目[Info.plist]结束");
```

Source: [Editor/PostProcessBuildHelper.Plist.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Plist.cs#L11-L22)

6. Open the generated Xcode project and confirm that the corresponding keys appear in the Target → Info tab.

Below is a copy-ready `plist` configuration example (key names are standard iOS Info.plist keys; value types are determined by the types supported by the framework — see the mapping table in "Background" below):

```json
"plist": {
    "NSCameraUsageDescription": "扫描二维码需要使用相机",
    "NSPhotoLibraryUsageDescription": "保存截图需要访问相册",
    "LSApplicationQueriesSchemes": [
        "weixin",
        "weixinULAPI"
    ],
    "CFBundleURLTypes": [
        {
            "CFBundleURLName": "com.yourcompany.yourgame",
            "CFBundleURLSchemes": ["yourgame"]
        }
    ]
}
```

The `plist` value in the configuration is read at build time via `finalConfig.Get<Hashtable>("plist")` and passed into the processing flow:

```csharp
// Set Info.Plist
RunPlist(project, path, finalConfig.Get<Hashtable>("plist"));
```

## Common Variants

- **Multiple sets of URL Schemes**: Simply append multiple dictionary objects to the `CFBundleURLTypes` array, each containing `CFBundleURLName` and `CFBundleURLSchemes`.
- **Background modes**: Also written under `plist`, for example `"UIBackgroundModes": ["audio"]` (a string array).
- **Localized permission texts**: Use the framework's localization configuration instead, which automatically generates `.lproj/InfoPlist.strings` and sets `LSHasLocalizedDisplayName` to `true`; do not hardcode multilingual texts into `plist` key-value pairs:

```csharp
plistPath = Path.Combine(path, "Info.plist");
if (File.Exists(plistPath))
{
    ...
    plist.WriteToFile(plistPath);
    LogHelper.Log("Updated Info.plist: Set LSHasLocalizedDisplayName to true");
}
```

## Common Mistakes

- **Numbers are only written as integers**: The write logic uniformly executes `SetInteger(key, Convert.ToInt32(...))` for numeric types; decimals get truncated, so do not use it to write floating-point values.
- **Booleans written as strings**: Only genuine JSON booleans (`true`/`false`) will invoke `SetBoolean`; writing `"YES"` / `"true"` will be written as strings, resulting in a wrong type in Info.plist.
- **No warning for misspelled key names**: The processing is a plain item-by-item overwrite of "write whatever is present"; misspelled keys (e.g. `NSCameraUsageDesciption`) will not raise errors and can only be verified manually in Xcode's Info tab.
- **Incorrect nesting levels**: `CFBundleURLTypes` must be nested as "array → dict → array"; missing one level will cause it to appear as a plain string in Xcode instead of URL Types.

## Background

`SetPlist` writes recursively based on the runtime type of the configuration value, with the following mapping (also applies to array elements):

| Config value type | Info.plist written type | Call |
|------|------|------|
| String | string | `SetString` |
| Boolean | boolean | `SetBoolean` |
| Number (double) | integer | `SetInteger` (`Convert.ToInt32`) |
| Array (ArrayList) | array | `CreateArray` / `AddArray` |
| Object (Hashtable) | dict | `CreateDict` / `AddDict` |

```csharp
if (vType == typeof(string))
{
    node.SetString(key, (string)val);
}
else if (vType == typeof(bool))
{
    node.SetBoolean(key, (bool)val);
}
else if (vType == typeof(double))
{
    node.SetInteger(key, Convert.ToInt32((double)val));
}
else if (vType == typeof(ArrayList))
{
    var t = node.CreateArray(key);
    var array = val as ArrayList;
    SetPlist(proj, t, array);
}
else if (vType == typeof(Hashtable))
{
    var t = node.CreateDict(key);
    var table = val as Hashtable;
    SetPlist(proj, t, table);
}
```
