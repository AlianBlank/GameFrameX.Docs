# How to Preserve Coroutine Components During Build Stripping

Attach `GameFrameXCoroutineCroppingHelper` to a GameObject in a Unity scene to prevent `CoroutineComponent` from being stripped away when IL2CPP / Managed Stripping is enabled in the build environment, ensuring the coroutine API can still be called normally.

## Prerequisites

- This coroutine package (`com.gameframex.unity.coroutine`) is installed
- The target platform has managed code stripping enabled (Managed Stripping or IL2CPP), or the project uses link.xml / Preserve mechanisms
- A persistent scene already exists (GameObject will not be destroyed after build)

## Step-by-Step Instructions

1. Create a new GameObject in any persistent scene (e.g., the launch scene), for example, named `GameFrameXCoroutineCroppingHelper`.
2. Add the `GameFrameXCoroutineCroppingHelper` component to the GameObject.

   ```csharp
   using GameFrameX.Coroutine.Runtime;
   ```
   Source: [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

3. No need to attach `DontDestroyOnLoad` — the component's `Start` only needs to execute once in any scene to make the stripper preserve the type reference of `CoroutineComponent`.
4. Re-build the project. After running the game, you can use `GameEntry.GetComponent<CoroutineComponent>().StartCoroutine(...)` as usual.

## Common Variants

- **Without using CroppingHelper**: Add a `link.xml` to the project to preserve the entire `GameFrameX.Coroutine.Runtime` namespace.
- **Avoiding any extra GameObject**: Add the following code to the `Start` method of any existing component script: `private void Start() { _ = typeof(GameFrameX.Coroutine.Runtime.CoroutineComponent); }`, and mark the class with `[Preserve]`. This achieves the same effect.
- **AOT platforms (IL2CPP + iOS/Android)**: It is strongly recommended to attach the CroppingHelper; otherwise, the `new` overrides of `StartCoroutine` / `StopCoroutine` may fail to find the corresponding methods under certain stripping levels.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `MissingMethodException` is thrown when calling `StartCoroutine` after build | The `new` overload methods of `CoroutineComponent` were removed by the stripper | Attach `GameFrameXCoroutineCroppingHelper`, or add `link.xml` to preserve the namespace |
| `GameFrameXCoroutineCroppingHelper` type cannot be found at runtime | The script itself was stripped out under AOT | Do not accidentally exclude `GameFrameX.Coroutine.Runtime.*` in link.xml; CroppingHelper itself is already marked with `[Preserve]` |
| An empty object appears in the scene after adding the component | It only exists to trigger the `Start` reference, with no visual or logical side effects | Hide its `MeshRenderer`, or merge it into an existing persistent singleton object |

## Background (Optional)

`GameFrameXCoroutineCroppingHelper` internally only contains a `Start` method that references `typeof(CoroutineComponent)`. Since both the class and the method are marked with `[Preserve]` (from `UnityEngine.Scripting`), Unity's Stripping phase will preserve this reference chain, thereby protecting `CoroutineComponent` and its `new`-hidden methods.
