# 广告加载或播放失败怎么办

当 `Play(...)` 或 `Load(...)` 触发失败回调时,通常是配置缺失、广告位 ID 未填、SDK 未初始化或回调未被绑定造成的。下面按症状对照原因,定位后再按步骤修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `Play` 直接进入 `OnFail`,日志无广告事件 | 未调用 `Initialize` 或 `m_config` 为 null | 在 `Start` 前给 `AdvertisementComponent` 注入 `AdvertisementConfig`,或在 Inspector 勾选配置资产 |
| `Log.Fatal("Advertisement manager is invalid.")` | 框架未注册广告管理器实现 | 在 `BaseAdvertisementManager` 子类中按 `AdvertisementConfigAttribute` 注册,并放到场景启动链中 |
| 加载/播放无任何回调 | `AdvertisementPlayOption.OnSuccess/OnFail/OnShowResult` 未赋值 | 在调用 `Play` 前给 `AdvertisementPlayOption` 三个 Action 都赋值 |
| iOS/Android/小游戏加载空配置 | 当前平台对应的广告位 ID 字段为空 | 填写 `m_adUnitIdAndroid`、`m_adUnitIdiOS`、小游戏三选一(`WeChat` / `DouYin` / `KuaiShou`)对应字段 |
| `Play` 报错但 `OnShowResult` 返回 false | 展示流程成功但 SDK 标记为未完整播放 | 检查广告位审核状态与素材是否被拒,见"广告位审核被拒"小节 |
| `Load` 已废弃警告 | 使用了旧 API | 改用 `Play(AdvertisementPlayOption)`,不要用 `Load(success, fail)` |

## 修复步骤

### 1. 确认广告管理器已注册

`AdvertisementComponent.Awake()` 会通过反射拿到 `IAdvertisementManager` 实现,如果拿不到会直接 `Log.Fatal`。检查:

- 自定义管理器类带 `[AdvertisementConfigAttribute]` 并继承 `BaseAdvertisementManager`
- 该类在项目里实际被编译进运行时程序集
- 场景中存在 `AdvertisementComponent`,且 `componentType` 字段指向你自定义管理器

参考实现位置:[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L87-L118)

### 2. 注入 AdvertisementConfig

`Start()` 只在 `m_config != null` 时调用 `_advertisementManager.Initialize(m_config)`。Inspector 上记得把广告配置资产拖到 `m_config` 字段,或代码里显式初始化:

```csharp
var component = GameEntry.GetComponent<AdvertisementComponent>();
component.Initialize(myAdvertisementConfig);
```

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L140)

### 3. 给当前平台填写广告位 ID

`AdUnitId` 按平台编译指令取值,任意一个分支为空都会让后续 SDK 拿不到有效 ID。常见遗漏:

- Android 渠道只填了 iOS 的 ID
- WebGL 选了通用 ID,但启用了 `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 宏,小程序专用位未填

确认 Inspector 上 `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` 至少有一条有值。

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57)

### 4. 补齐播放回调

`AdvertisementPlayOption` 上三个 Action 任意一个未赋值,对应回调就不会触发:

```csharp
var option = new AdvertisementPlayOption
{
    OnSuccess = json => Debug.Log($"奖励发放成功: {json}"),
    OnFail    = err  => Debug.LogError($"播放失败: {err}"),
    OnShowResult = shown => Debug.Log($"完整展示: {shown}"),
    customData = "level=1",
};
component.Play(option);
```

`extraData` 只在 Load 阶段会被序列化透传到服务端,加载完成后再改不生效。

Source: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L84)

### 5. 不要使用已废弃的 Load

`BaseAdvertisementManager.Load(Action<string>, Action<string>, string)` 标注为 `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`,继续使用只会触发警告且不会自动桥接新流程,统一改用 `Play(AdvertisementPlayOption)`。

Source: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L236-L238)

### 6. 调试模式排错

打开 `m_debug = true`(或 `Initialize` 时第二个参数传 `true`),让 SDK 输出更详细的请求日志,定位是网络、签名还是广告位返回的错误码。

Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L59)

## 验证

修复后,逐项确认:

1. 启动日志中不再出现 `Advertisement manager is invalid.` 致命日志。
2. 调用 `Play`,`OnSuccess` 或 `OnFail` 中至少一个被触发,而不是"完全静默"。
3. 切换 Android / iOS / 微信小游戏 / 抖音 / 快手小游戏等编译目标,`AdUnitId` 不为空。
4. 在广告平台后台确认广告位状态为"已通过",且没有触发限频策略。
