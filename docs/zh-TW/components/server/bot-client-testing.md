# 如何使用 Bot 客戶端進行整合測試與壓力測試

`GameFrameX.Client` 是一個獨立的 .NET 主控台應用程式，用於模擬一批 Bot 玩家同時連線至遊戲伺服器，自動完成「帳號登入 → 角色列表 → 建立/登入角色」的完整流程。結合 `EnableDisconnectLoop`，還可以循環重新連線，常用於整合測試驗證與壓力測試。

## 前置條件

- 可登入的遊戲伺服器（預設假設：TCP 閘道監聽於 `127.0.0.1:49100`）。
- 已啟用 HTTP 登入閘道（預設為 `http://127.0.0.1:48080/game/api/`，由 `BotRunOptions.LoginUrl` 指定）。
- 已安裝 .NET SDK 10（腳本會呼叫 `dotnet run --framework net10.0`）。
- 帳號密碼使用測試夾具的預設密碼 `12312`（常數 `DefaultBotLoginSecret`），所有 Bot 共用，可透過 `--login-password` 覆寫。

## 操作步驟

1. **進入儲存庫根目錄**（腳本透過相對路徑定位專案檔案）：

   ```bash
   cd GameFrameX.Server.Source
   ```

2. **直接執行多 Bot 腳本**（壓力測試的建議入口，會自動設定預設值並列印執行時參數）：

   ```bash
   bash scripts/multi/run-bots-rpc.sh
   ```

   腳本內部會呼叫 `dotnet run`，並將環境變數以命令列參數的形式傳遞。

   來源：[scripts/multi/run-bots-rpc.sh](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/scripts/multi/run-bots-rpc.sh#L1-L37)

3. **使用 `dotnet run` 手動啟動**（整合測試時更為靈活）：

   ```bash
   dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
     --bot-count=50 \
     --tcp-host=127.0.0.1 \
     --tcp-port=49100 \
     --login-url=http://127.0.0.1:48080/game/api/ \
     --scenario=login
   ```

   `--scenario` 接受以逗號分隔的多個情境名稱（例如 `login,friend`），由 `BotRunOptions.HasScenario` 判斷是否啟用。

   來源：[GameFrameX.Client/Bot/BotRunOptions.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotRunOptions.cs#L31-L70)

4. **觀察輸出日誌**：每個 Bot 完成登入流程後，會輸出一行 `[METRICS] connect=… auth=… list=… create=… login=… total=…`（單位為毫秒），用於評估各階段所耗費的時間。

   來源：[GameFrameX.Client/Bot/BotClient.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Client/Bot/BotClient.cs#L184-L187)

## 命令列參數速查表

| 參數 | 類型 | 預設值 | 說明 |
|------|------|--------|------|
| `--bot-count` | int | 50 | 同時啟動的 Bot 數量 |
| `--bot-prefix` | string | `BotClient` | Bot 名稱前綴，編號從 `_1` 開始遞增 |
| `--tcp-host` | string | `127.0.0.1` | 遊戲伺服器 TCP 閘道位址 |

| `--login-password` | string | `12312` | 所有 Bot 共用的登入密碼 |
| `--connect-stagger-ms` | int | 20 | 每個 Bot 的啟動間隔，避免瞬間灌爆連線 |
| `--disconnect-loop` | bool | true | 登入完成後是否自動斷線並循環 |
| `--disconnect-after-login-seconds` | int | 15 | 登入成功後多少秒斷線 |
| `--run-seconds` | int | 0 | 總執行時間，0 表示持續執行直到手動停止 |
| `--scenario` | string | `login` | 啟用的情境，以逗號分隔 |

## 常見變體

- **小規模整合測試（驗證業務流程）**：減少至 5~10 個 Bot，`--run-seconds=60`，停用斷線循環 `--disconnect-loop=false`，方便目視檢查日誌。

  ```bash
  dotnet run --framework net10.0 --project GameFrameX.Client/GameFrameX.Client.csproj -- \
    --bot-count=5 --run-seconds=60 --disconnect-loop=false
  ```

- **連線型壓力測試（灌爆閘道）**：保留預設的斷線循環，將交錯間隔縮短至 5~10ms，讓 Bot 持續重新連線以驗證閘道穩定性：

  ```bash
  bash scripts/multi/run-bots-rpc.sh
  # 預設 BOT_COUNT=100、CONNECT_STAGGER_MS=10、RUN_SECONDS=180
  ```

- **自訂環境壓力測試**：透過環境變數覆寫腳本預設參數，例如連線至測試伺服器並執行 300 秒：

  ```bash
  BOT_COUNT=200 RUN_SECONDS=300 TCP_HOST=10.0.0.5 TCP_PORT=49100 \
    bash scripts/multi/run-bots-rpc.sh
  ```

## 常見錯誤

| 症狀 | 原因 | 解決方案 |
|------|------|------|
| Bot 啟動後立即回報 `EntryAsync Error: …` | TCP 閘道無法連上或連接埠被佔用 | 檢查 `TcpHost`/`TcpPort`，確認遊戲伺服器已啟動並在監聽 |
| 日誌反覆出現 `账号登录失败，错误码:非0` | 登入閘道未啟用或密碼不一致 | 檢查 `LoginUrl` 是否可存取，以及 `--login-password` 是否與伺服器端驗證一致 |
| `[METRICS]` 持續缺少欄位（例如 `list=-1`） | 未進入該階段（帳號或前序流程失敗） | 沿著前面的 ERROR 日誌追溯上游失敗原因 |
| 伺服器端連線數迅速飽和 | 交錯間隔太小或 Bot 數量太多 | 增大 `--connect-stagger-ms` 或減少 `--bot-count` |

## 背景說明（選讀）

`BotClient` 內部使用 `BotTcpClient` 來維護與遊戲伺服器 TCP 閘道的長連線；連線建立後會立即傳送 `ReqLogin`，伺服器回傳 `RespLogin` 以觸發角色列表請求，接著視需要傳送 `ReqPlayerCreate` / `ReqPlayerLogin`。登入成功後，當 `EnableDisconnectLoop=true` 時會排程斷線重連。所有 Bot 共用同一個 `BotRunOptions`（連線位址、連接埠、密碼、情境開關等），並透過 `BotRunOptions.Parse` 從命令列讀取覆寫值。指標資料以 `[METRICS]` 前綴透過 `LogHelper.Info` 輸出，方便腳本彙整。
