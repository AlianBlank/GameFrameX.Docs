# Integrating Platform Channels

Configure the implementation type string for each platform on `PaymentComponent`; the framework automatically instantiates the corresponding channel `PaymentManager` (Google / Apple / WebGL / PC) at startup based on the platform, and business code only programs against `IPaymentManager`. To integrate your own channel, inherit from `BasePaymentManager` and fill the type name into the Inspector.

## Prerequisites

- The payment core package (`GameFrameX.Payment.Runtime`) is installed.
- `PaymentComponent` is attached in the scene; it automatically brings `GameFrameXPaymentCroppingHelper` along via `RequireComponent`.
- The channel implementation package for the target platform is installed (see the "Channel Type Reference Table" below; each channel implementation is distributed in a separate package under its corresponding namespace).

## Steps

1. Add the component to a scene object: the menu path is `GameFrameX/Payment` (from `AddComponentMenu`):

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
{
    private IPaymentManager _paymentManager;
    [SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
    [SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
    [SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
    [SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
    [SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L28)

2. Install the channel implementation package for the target platform (the package name matches the namespace in the table below; for example, the Google channel is located at `GameFrameX.Payment.Google.Runtime`).

3. Confirm that the channel type name matches the actually installed implementation; if you need to replace it with your own implementation, directly modify the type string for the corresponding platform in the Inspector.

4. At startup, the framework automatically selects the implementation based on platform macros:

```csharp
#if UNITY_ANDROID
            componentType = m_componentAndroidType;
#elif UNITY_IOS
            componentType = m_componentIOSType;
#elif UNITY_WEBGL
            componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
            componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
            componentType = m_componentMacType;
#else
            componentType = typeof(DefaultPaymentManager).FullName;
#endif
            ImplementationComponentType = Utility.Assembly.GetType(componentType);
            InterfaceComponentType = typeof(IPaymentManager);
            base.Awake();

            _paymentManager = GameFrameworkEntry.GetModule<IPaymentManager>();
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

| Platform Macro | Inspector Field | Default Implementation Type |

## Integrating Your Own Channel

1. Inherit from `BasePaymentManager` (it already implements `GameFrameworkModule, IPaymentManager` and includes built-in `Raise*` trigger methods for the four events), and implement the abstract members:

```csharp
[UnityEngine.Scripting.Preserve]
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    /// <summary>
    /// Purchase success event
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;

    /// <summary>
    /// Purchase failure event
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;

    /// <summary>
    /// Query purchases result event
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

    /// <summary>
    /// Consume purchase result event
    /// </summary>
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

    protected void RaisePurchaseSuccess(PaymentEventArgs e)
    {
        OnPurchaseSuccess?.Invoke(this, e);
    }

    protected void RaisePurchaseFailed(PaymentEventArgs e)
    {
        OnPurchaseFailed?.Invoke(this, e);
    }

    protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
    {
        OnQueryPurchasesResult?.Invoke(this, e);
    }

    protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
    {
        OnConsumePurchaseResult?.Invoke(this, e);
    }

    [UnityEngine.Scripting.Preserve]
    public abstract void Init(bool isDebug = false, bool isClientVerify = false);
}
```

Source: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L13-L67)

The remaining abstract members `IsReady()`, `SetPredefinedProductIds(List<string>, List<string>)`, `QueryPurchases(PaymentProductType)`, `ConsumePurchase(string)`, `BuyInApp`/`BuySubs`/`Buy` (marked with `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`) and the recommended `Buy(PurchaseParams)` must all be implemented in subclasses; see [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L69-L137) for complete signatures.

2. If the channel requires additional purchase parameters, inherit from `PurchaseParams` to extend fields (source comment: "Each channel can inherit and extend its own fields"):

```csharp
/// <summary>
/// Purchase parameter base class; each channel can inherit and extend its own fields
/// </summary>
public abstract class PurchaseParams
{
    /// <summary>Product ID or SKU</summary>
    public string ProductId { get; set; }

    /// <summary>Order ID</summary>
    public string OrderId { get; set; }

    /// <summary>Product type</summary>
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

3. Fill the full name of your implementation class (including namespace) into the Inspector field of `PaymentComponent` for the corresponding platform, and after running, use `IsReady()` to verify whether the channel initialized successfully.

## Common Variants

- **Replace the Android channel with your own SDK**: Keep the `m_componentAndroidType` field unchanged and change its value to the full name of your implementation class (including namespace), then rebuild the package—no modification to `PaymentComponent` code is required.
- **Mac and iOS share the Apple channel**: The default configuration already does this—both `m_componentIOSType` and `m_componentMacType` point to `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`.
- **Editor/unsupported platforms**: When the `#else` branch is hit, the built-in `DefaultPaymentManager` of this package is used as a fallback, making it easy to run through business flows in the editor.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` returns null, usually because the channel implementation class name is misspelled or the corresponding assembly was not compiled | Verify that the platform type string in the Inspector matches the actual full class name and namespace, and confirm the channel implementation package is installed |
| `Utility.Assembly.GetType(componentType)` cannot find the type | The type name does not match the full name in the assembly (spelling/namespace error) | Confirm the `namespace` and class name in the channel implementation package, then fill in the complete full name such as `GameFrameX.Payment.Google.Runtime.GooglePaymentManager` |
| Calling purchase in the editor gets no response | The `#else` branch is hit, using the `DefaultPaymentManager` fallback implementation | Switch to a device/target platform build to verify, or integrate a custom channel implementation |
| `Log.Warning("Product ID is null or empty.")` / `"Order ID is null or empty."` | The legacy `BuyInApp`/`BuySubs`/`Buy(productId, ...)` passed an empty `productId` or `orderId` | Pass valid values, or switch to the recommended `Buy(PurchaseParams)` overload |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L88-L93) (Fatal log location); see [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L163-L204) for the remaining warning messages

> Note: `BuyInApp`, `BuySubs`, `Buy(productId, productType, orderId, ...)` are all marked with `[Obsolete("请使用 Buy(PurchaseParams) 替代")]`; for new integrations, use `Buy(PurchaseParams)` directly ([IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112)).

## Background

In `Awake`, `PaymentComponent` determines `componentType` based on compile macros, then obtains `ImplementationComponentType` via reflection through `Utility.Assembly.GetType`, registers it with `GameFrameworkEntry` using `IPaymentManager` as the interface type, and subsequently retrieves the instance via `GameFrameworkEntry.GetModule<IPaymentManager>()`. In this way, the business layer depends only on the interface, while channel implementations are injected at runtime via Inspector strings, achieving a "one set of business code, multiple platform channels" switching approach. For the overall architecture and complete API of the payment component, see the framework overview page and API reference page.
