# UI 열기에 실패하면 어떻게 해야 하나요

`OpenUIForm` / `OpenUIFormAsync`를 호출했는데 UI가 나타나지 않거나 `OpenUIFormFailureEventArgs` 이벤트를 수신했을 때, 이 페이지에서 제공하는 진단 표를 따라 원인을 파악하고 수정할 수 있습니다. 흔한 실패 원인은 **리소스 미등록, UI 그룹 부재, 직렬화 스크립팅 디파인 심볼 누락, 스크립트 미부착** 등 몇 가지 유형에 집중되어 있습니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `OpenUIForm`이 반환한 인스턴스가 `null`이거나, `OpenUIFormFailureEventArgs.ErrorMessage`에 리소스를 찾을 수 없다고 표시됨 | `uiFormAssetName`이 UI 컴포넌트에 등록되지 않음(설정 누락 또는 철자 오류) | UIForm 설정에서 리소스 이름을 채워 넣고, `UIFormAssetName`이 호출부에서 전달한 값과 완전히 일치하는지 확인 |
| 오류 메시지에 UI 그룹 / UIGroup을 찾을 수 없다고 표시됨 | 전달한 `uiGroupName`이 존재하지 않음 | 먼저 `AddUIGroup`을 호출해 그룹을 추가하거나, 이미 등록된 그룹 이름을 전달 |
| `UIComponent` 전체에서 오류가 발생하거나 `OpenUIForm`을 호출할 수 없음 | 프로젝트에서 `GameFrameX.UI` 스크립팅 디파인 심볼이 활성화되지 않음 | 에디터에서 `UISystemScriptingDefineCheckHandler`를 통해 스크립팅 디파인 심볼을 보완하거나, Player Settings에서 `GameFrameX.UI`를 추가 |
| 리소스는 존재하지만 UI가 열린 후 로직이 실행되지 않음 | UIForm 프리팹에 해당 로직 스크립트가 부착되어 있지 않음 | `UIForm` 프리팹에 올바른 로직 클래스 컴포넌트를 부착 |
| `OpenUIFormFailureEventArgs`가 전혀 트리거되지 않는데 UI도 표시되지 않음 | 이벤트를 구독하지 않아 실패가 조용히 무시됨 | `OpenUIFormSuccessEventArgs` / `OpenUIFormFailureEventArgs`를 구독한 후 호출 |
| `uiFormAssetPath`와 `uiFormAssetName`을 혼동하여 비동기 로드가 실패함 | 호출 시 "경로"와 "리소스 이름"을 서로 바꿔 전달함 | 구분: 설정에 입력하는 것은 `UIFormAssetName`(논리 이름)이고, `uiFormAssetPath`는 리소스 주소 |

## 수정 단계

### 1. 리소스 미등록 / 이름 철자 오류

UI 설정을 열어 해당 UIForm의 `UIFormAssetName` 필드가 입력되어 있고, 이름이 `OpenUIForm` 호출과 일치하는지 확인합니다.

```csharp
// 호출부: 이름은 UIFormInspector의 m_UIFormAssetName과 일치해야 합니다
UIComponent.OpenUIForm("ShopUI", "Normal");
```

`UIForm` 프리팹에서 사용할 수 있는 필드는 [UIFormInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UIFormInspector.cs#L92-L110)를 참고하세요.

### 2. UI 그룹이 존재하지 않음

`uiGroupName`은 반드시 `AddUIGroup`으로 등록된 그룹 이름이어야 합니다. 흔한 상황: 다른 사람의 코드를 복사했지만 `Window`, `Popup` 같은 커스텀 그룹 등록을 잊은 경우입니다.

### 3. 스크립팅 디파인 심볼이 활성화되지 않음

`UIComponent`의 모든 인터페이스는 스크립팅 디파인 심볼 `GameFrameX.UI`에 의존합니다. 한 번도 활성화한 적이 없다면 호출 시 바로 오류가 발생합니다. 런타임에 [UISystemScriptingDefineCheckHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UISystemScriptingDefineCheckHandler.cs)를 통해 에디터에서 자동으로 검사하고 보완합니다.

### 4. 실패 이벤트를 구독하여 실제 오류 파악

반환값만으로 판단하지 마세요. `OpenUIFormFailureEventArgs`를 구독하면 전체 오류 스택을 얻을 수 있어, 막연히 추측하는 것보다 빠릅니다.

```csharp
// README.md 예제에서 발췌
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnUIFormOpenFailure);
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnUIFormOpenSuccess);

private void OnUIFormOpenFailure(object sender, GameEventArgs e)
{
    var args = (OpenUIFormFailureEventArgs)e;
    Debug.LogError($"打开 {args.UIFormAssetName} 失败: {args.ErrorMessage}");
}
```

`ErrorMessage`, `UIFormAssetName`, `SerialId`, `UserData`의 필드 정의는 [OpenUIFormFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormFailureEventArgs.cs#L88-L131)를 참고하세요.

### 5. UIForm 프리팹에 로직 스크립트가 부착되지 않음

UI가 "열린" 것처럼 보이지만 로직(`OnInit`, `OnOpen`, `OnUpdate`)이 실행되지 않는다면, 보통 프리팹에 `IUIForm` 로직 컴포넌트가 없는 경우입니다. 해당 프리팹을 열고 `UIForm`을 상속하는 스크립트를 루트 노드에 부착하세요.

## 확인

다음 순서대로 항목별로 확인하세요:

1. Console에서 `OpenUIFormSuccessEventArgs`가 트리거되면 열기에 성공한 것입니다.
2. `OnUIFormOpenFailure`에서 `ErrorMessage`를 `Debug.LogError`로 출력하고, 메시지 키워드(예: "not found", "has not been")를 근거로 위의 진단 표로 돌아갑니다.
3. UI를 닫았다가 다시 들어가, 씬 전환 시 UI 상태가 손실되지 않는지 확인합니다.
4. 에디터에서 `UIForm` 컴포넌트의 Inspector(`UIFormAssetName`, `FullName`, `SerialId`)가 정상적으로 표시되는지 확인합니다.
