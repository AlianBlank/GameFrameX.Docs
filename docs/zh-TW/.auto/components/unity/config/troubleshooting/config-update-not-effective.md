# 配置表更新未生效怎麼辦

當你在執行階段重新載入、重新讀取或重新 `Add` 一個配置表，卻發現資料沒有變化時，問題多出現在「已存在的 key 被新值跳過」「讀到了快取的舊參考」或「鍵名與型別不一致」三個環節。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 呼叫 `Add` 後 `GetConfig` 仍然回傳舊值 | `AddConfig` 內部使用 `TryAdd`，鍵已存在時**不會覆蓋** | 改為先 `RemoveConfig` 再 `AddConfig`，或使用 `HasConfig` 先判斷 |
| 修改了配置檔案後，執行中的資料未更新 | 資料表實例被持有為舊參考，只更新了 dict 裡的物件而未替換 | 重新建構 `IDataTable` 後，先移除舊 key 再 `Add` |
| `HasConfig<T>()` 回傳 false，但配置明明已載入 | `GetTypeName<T>()` 使用 `typeof(T).Name` 作為鍵，泛型實參型別不一致 | 確認 `T` 是同一個具體類別（例如 `PlayerConfig`，而不是 `BaseDataTable`） |
| `RemoveAllConfigs()` 後再 `GetConfig` 仍能拿到值 | `ConfigComponent` 內部有 `m_ConfigNameTypeMap` 快取，清空後未重新 `Add` | 清空後重新執行載入流程，不要單獨依賴快取 |
| 重新載入配置時事件沒觸發 | 沒有訂閱 `LoadConfigUpdateEventArgs` / `LoadConfigSuccessEventArgs` | 在 `ConfigComponent.Awake` 後訂閱相關事件，見下方程式碼 |

## 修復步驟

### 1. 重複 Add 不生效 — 先 Remove 再 Add

`ConfigManager.AddConfig` 內部呼叫的是 `m_ConfigDatas.TryAdd(configName, configValue)`，在 `ConcurrentDictionary` 中，**鍵已存在時不會覆蓋**。要更新值必須先移除舊條目。

```csharp
var component = GameFrameX.Runtime.GameEntry.GetComponent<ConfigComponent>();

// 錯誤寫法:不會覆蓋
component.Add("PlayerConfig", newDataTable);

// 正確寫法:先移除再添加
if (component.HasConfig<PlayerConfig>())
{
    component.RemoveConfig<PlayerConfig>();
}
component.Add("PlayerConfig", newDataTable);
```

### 2. 鍵名與型別不一致 — 保持 typeof(T).Name 一致

`ConfigComponent.GetTypeName<T>()` 用 `typeof(T).Name` 當作 dict 的 key。所以 `HasConfig<PlayerConfig>()` 和 `HasConfig<BaseDataTable>()` 拿到的是**不同的 key**；父類別參考不會命中子類別條目。確保 `T` 是載入時使用的同一個具體類別。

```csharp
// 一致:用具體類別
var data = component.GetConfig<PlayerConfig>();

// 不一致:用介面或父類別會查不到
var data = component.GetConfig<IDataTable>();
```

### 3. 重新載入後參考仍是舊物件 — 替換整張表

`GetConfig` 回傳的是 `IDataTable` 介面，**dict 裡持有的是參考**。如果你只是修改了底層集合，而不重新 `Add` 一張新表，某些序列化器／快取層不會感知到變化。安全做法是建構新的 `IDataTable` 實例並替換 dict 條目。

```csharp
var newTable = LoadFromBytes(bytes); // 你的反序列化邏輯
if (component.HasConfig<PlayerConfig>())
{
    component.RemoveConfig<PlayerConfig>();
}
component.Add(nameof(PlayerConfig), newTable);
```

### 4. 重新載入事件沒回呼 — 訂閱對應 EventArgs

倉庫在 `Runtime/EventArgs/` 下提供了 `LoadConfigUpdateEventArgs`、`LoadConfigSuccessEventArgs`、`LoadConfigFailureEventArgs` 三個事件參數類別。如果你改寫了載入流程，記得透過 `GameFrameX.Runtime.GameEntry.GetComponent<ConfigComponent>()` 拿到實例後，再按框架事件機制訂閱，否則完成回呼不會觸發，看起來就像「沒生效」。

```csharp
// 範例:在自訂載入器裡 fire，使用框架事件機制
GameFrameX.Runtime.GameEntry.GetComponent<ConfigComponent>()
    .SendEvent(nameof(LoadConfigSuccessEventArgs), new LoadConfigSuccessEventArgs { ... });
```

## 驗證

1. 在 `Add` 之前呼叫 `HasConfig<T>()`，確認回傳值為 `true` 時先 `RemoveConfig<T>()`。
2. 呼叫 `GetConfig<T>()` 後，在除錯器裡查看 `m_ConfigDatas`(反射可見)中的參考與新表是否為同一物件。
3. 如果修改了 `IDataTable` 的內部集合，**重新建構新實例**而不是原地修改，確保參考被替換。
4. 關鍵路徑加上日誌：列印 `typeof(T).Name`、`HasConfig` 回傳值，以及載入完成事件是否觸發。
