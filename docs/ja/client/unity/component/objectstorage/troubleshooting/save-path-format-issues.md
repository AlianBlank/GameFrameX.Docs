# 保存パスの設定とパス区切り文字の問題

`SetSavePath` を呼び出した後、オブジェクトのバケット内の保存パスが想定と異なる場合(区切り文字が多かったり少なかったり、プラットフォームに誤ったスラッシュが入ったり)は、通常、渡されたパスの形式と `Path.DirectorySeparatorChar` の処理ロジックが一致していないことが原因です。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 保存パスの末尾から文字が一つ多く切り取られる(例: `mybucket/folder` が `mybucket/folde` になる) | 渡されたパスがバックスラッシュ `\` で終わっているが、現在のプラットフォームの区切り文字はスラッシュ `/`(Windows のパスを Linux/Mac ターゲットに書き込む場合によくある) | 呼び出し前に `\` をプラットフォームの区切り文字に置き換えるか、`Path.Combine` / `Path.DirectorySeparatorChar` を使用して組み立てる |
| 保存パスの末尾に区切り文字がついたままになる(例: `mybucket/folder/`)、その後の連結で `mybucket/folder//file` が生成される | 呼び出し側が区切り文字で終わらない文字列を渡しているが、実際には呼び出し前に手動で切り詰められていた。または区切り文字なしで渡したが、すでに区切り文字付きのパスに連結された | 毎回呼び出し前に完全なパスを再渡し、切り詰めの積み重ねを避ける |
| パス内の `/` と `\` が混在し、リモートオブジェクトのパスに `mybucket/folder\file` が現れる | Windows 形式のパスを直接連結した、または文字列に `/` をハードコードした | `Path.DirectorySeparatorChar` を統一して使用し、リモートパス内で2種類のスラッシュを混在させない |

## 修正手順

### 1. `SetSavePath` の処理を一回だけにする

`SetSavePath` のロジックは次のとおりです:渡された文字列が `Path.DirectorySeparatorChar` で終わる場合のみ、最後の文字を削除します。

```csharp
public void SetSavePath(string savePath)
{
    if (savePath.EndsWith(Path.DirectorySeparatorChar.ToString()))
    {
        savePath = savePath.Substring(0, savePath.Length - 1);
    }

    BucketSavePath = savePath;
}
```

出典: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

したがって、渡されたパスの末尾の文字が現在のプラットフォームの `Path.DirectorySeparatorChar` でない場合(たとえば、Windows で `\` で終わるパスを渡したが、実際のランタイムのターゲットプラットフォームが macOS/Linux の場合)、末尾の区切り文字は削除されず、その後の連結で余分な区切り文字を含むリモートパスが生成されます。

### 2. プラットフォーム固有の区切り文字を使用する

ハードコードされた `/` や `\` を `Path.DirectorySeparatorChar` に置き換えるか、Windows でパスを渡すときは `\` で終わるように統一します。例えば:

```csharp
string remote = $"mybucket{Path.DirectorySeparatorChar}folder";
manager.SetSavePath(remote);
```

### 3. 重複呼び出しを避ける

`SetSavePath` は毎回渡された値に基づいて `BucketSavePath` を完全に書き換えるため、一度呼び出してから手動で連結するのは避けてください。最終的なパスを一度に渡してください。

```csharp
manager.SetSavePath("mybucket/folder");
```

## 検証

1. アップロード完了後、オブジェクトストレージのコンソールにログインするか List インターフェースを呼び出し、オブジェクトの Key が想定パスと一致し、余分な `/` や `\` がないことを確認します。
2. 既知のファイルを使用して単一ファイルのアップロード(`UploadFile`)を行い、リモートの Key が `BucketSavePath` + ローカル相対パスと等しいかを比較します。
3. プラットフォームを切り替えた後(Editor プラットフォームを macOS/Linux に切り替えて再度実行)、パスを再設定し、区切り文字の処理が依然として正しいことを確認します。
