# 設定下載優先順序與並行代理數

本任務頁面講解如何為下載任務設定**優先順序**，以及如何調整元件的**下載代理(並行協程)數量**，從而控制同時下載的任務上限。

## 前置條件

- 已引入 `GameFrameX.Download.Runtime` 並在場景掛載 `DownloadComponent`(選單：GameFrameX / Download)。
- 知道目標下載任務的本機儲存路徑(`downloadPath`)與遠端位址(`downloadUri`)。

## 操作步驟

### 1. 設定單一任務的優先順序

`DownloadComponent.AddDownload` 提供多個多載，接受 `priority` 參數(`int`,數值越大優先順序越高，預設 `0`)。最常用的兩個：

```csharp
using GameFrameX.Download.Runtime;

// 僅指定優先順序
int serialId = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, priority: 100);

// 同時指定 tag 與優先順序
int serialId2 = GameEntry.GetComponent<DownloadComponent>()
    .AddDownload(downloadPath, downloadUri, tag: "asset-bundle", priority: 100);
```

原始碼：

```csharp
// Runtime/Download/DownloadComponent.cs
private const int DefaultPriority = 0;
...
public int AddDownload(string downloadPath, string downloadUri, int priority)
{
    return AddDownload(downloadPath, downloadUri, null, priority, null);
}

public int AddDownload(string downloadPath, string downloadUri, string tag, int priority)
{
    return AddDownload(downloadPath, downloadUri, tag, priority, null);
}
```

### 2. 設定並行代理數

並行下載能力由 `DownloadComponent.m_DownloadAgentHelperCount` 決定，預設 `3`,表示同時最多有 3 個下載協程在工作。需要在 Inspector 中調整，或者透過程式碼在執行階段擴充：

- **Inspector**:掛載元件後，直接在 Inspector 中修改 `Download Agent Helper Count` 欄位(對應 `m_DownloadAgentHelperCount`)。元件 `Start()` 時會依該數值一次性建立代理。
- **執行階段追加**：如需動態增加，可繼續呼叫元件的內部入口或自訂基於 `DownloadAgentHelperBase` 的擴充(參考 [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs))。

原始碼(建立代理):

```csharp
// Runtime/Download/DownloadComponent.cs
[SerializeField] private int m_DownloadAgentHelperCount = 3;
...
private void Start()
{
    ...
    for (int i = 0; i < m_DownloadAgentHelperCount; i++)
    {
        AddDownloadAgentHelper(i);
    }
}
```

### 3. 執行期間查看代理使用情況

元件提供以下唯讀屬性，可在偵錯 HUD 中即時顯示：

| 屬性 | 意義 |
|------|------|
| `TotalAgentCount` | 已建立的下載代理總數 |
| `FreeAgentCount` | 目前閒置的下載代理數 |
| `WorkingAgentCount` | 正在工作中的下載代理數 |
| `WaitingTaskCount` | 等待代理閒置的任務數 |

原始碼：

public int WaitingTaskCount  { get { return m_DownloadManager.WaitingTaskCount; } }

## 常見變體

- **關鍵資源優先**：首屏資源用較高 `priority`(如 `100`),背景預先下載用 `0` 或負數。
- **暫停與恢復**：透過 `DownloadComponent.Paused = true/false` 暫時停止新任務的派發，代理不會被中斷。
- **修改 `m_DownloadAgentHelperCount` 立即生效**：僅當數值變大時，元件啟動時就會預先建立全部代理；執行中減小不會銷毀已存在的代理，需結合自訂邏輯回收。

## 常見錯誤

- **混淆「並行協程」與「並行執行緒」**：下載代理是 `UnityWebRequest` 協程，數值只控制同時進行的 HTTP 請求數，與執行緒無關；在 WebGL 等受限平台上不要設定過大。
- **任務被卡住不開始**:`WaitingTaskCount` 持續增加而 `FreeAgentCount` 恆為 0 時，表示並行數過小或任務網路較慢——可適當調高 `m_DownloadAgentHelperCount`。
- **未指定優先順序就以為是高優先**:`DefaultPriority = 0`,若其他任務給了負值，你的「預設」任務反而會被排在後面。

## 背景(選用)

下載管理器內部使用 `TaskPool<DownloadTask>` 排程任務(`[DownloadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs)`)。優先順序高的任務會優先獲得閒置代理，從而控制網路出口的佔用順序。
