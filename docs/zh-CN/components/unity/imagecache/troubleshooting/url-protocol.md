# URL 协议校验失败怎么办

当你调用 `LoadImageAsync` 时,如果传入的 URL 不是以 `http://` 或 `https://` 开头,组件会直接拒绝加载并在控制台输出警告,本次调用返回 `null`,不会触发下载或缓存流程。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台出现 `ImageCache: url must start with http:// or https://. url: ...`,且 `LoadImageAsync` 返回 `null` | URL 缺少协议前缀或协议不是 http/https(例如 `ftp://`、`file://`、`data:`、相对路径、`www.example.com/x.png` 等) | 在 URL 字符串前补全 `http://` 或 `https://` |
| URL 看似正确却仍校验失败 | URL 前后带有多余空白、换行或不可见字符 | 调用前用 `Trim()` 去除首尾空白 |
| URL 通过校验后加载仍然失败 | URL 协议已合法但资源不可用、网络不通或服务器返回错误 | 见下文"校验通过仍加载失败"一节 |

## 修复步骤

### 1. URL 缺少协议前缀

校验逻辑只接受 `http://` 和 `https://` 两种前缀,其他协议或裸域名都会被拒绝。

```csharp
// 不合法 —— 裸域名会被拒绝
string bad1 = "www.example.com/img.png";
string bad2 = "example.com/img.png";

// 合法
string good1 = "http://www.example.com/img.png";
string good2 = "https://www.example.com/img.png";
```

Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L78-L82)

### 2. URL 首尾有多余空白

`StartsWith` 校验区分大小写且不做裁剪,任何前置空白都会让前缀比对失败。建议在调用前显式 `Trim`。

```csharp
string rawUrl = "  https://example.com/img.png  ";
string url = rawUrl.Trim();

var tex = await ImageCacheComponent.Instance.LoadImageAsync(url);
```

### 3. URL 通过校验后仍然加载失败

校验只检查协议前缀,不验证资源是否真的可下载。如果日志里没有出现 "url must start with ..." 提示,请按顺序排查:

- 控制台出现 `ImageCache: url is null or empty.` —— 传入的字符串为 `null` 或空串,补上有效 URL。
- 控制台出现下载失败事件(`DownloadFailure`)—— 服务端返回 404/403、网络超时或跨域限制,需检查服务器状态与 HTTPS 证书。
- WebGL 平台:校验通过后会调用 `LoadImageWebGLAsync`,由浏览器负责缓存;若浏览器报 CORS 错误,需服务端返回正确的跨域头。

Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

## 验证

1. 调用前打印或断点确认 URL 以 `http://` 或 `https://` 开头,且首尾无空白。
2. 发起 `LoadImageAsync` 后,若返回非空 `Texture2D` 且控制台无 "url must start with" 警告,即校验通过且加载成功。
3. 若仍返回 `null`,对照上方诊断表检查日志关键字,定位到具体失败阶段。
