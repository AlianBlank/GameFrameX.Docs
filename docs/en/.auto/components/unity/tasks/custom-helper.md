# Integrating Custom Helpers to Replace Default Implementations

Through the `Helper.CreateHelper<T>` entry point provided by GameFrameX, you can replace the default implementations (such as logging, compression, version, JSON, text helpers, etc.) with custom Helpers when the framework starts up. This is useful for integrating with your project's internal toolchain or third-party SDKs.

## Prerequisites

- The `GameFrameX` framework has been initialized according to the Quick Start documentation, and you can obtain `GameFrameXComponent` in `Awake/Start`.
- Your custom Helper class has implemented the corresponding interface (for example, `GameFrameworkLog.ILogHelper`, `Utility.Compression.ICompressionHelper`, `Utility.Json.IJsonHelper`, `Utility.Text.ITextHelper`, `GameVersion.IVersionHelper`), and can be found via reflection in the Unity assembly.
- The custom Helper is a `MonoBehaviour`-derived class (the framework creates it via `GameObject.AddComponent`).

## Steps

### 1. Implement a Custom Helper

Create a new class that implements the framework's built-in interface. The following example shows how to replace the default log helper:

```csharp
using UnityEngine;
using GameFrameX;

namespace GameFrameX.Runtime
{
    [UnityEngine.Scripting.Preserve]
    public class MyLogHelper : GameFrameworkLog.ILogHelper
    {
        public void Log(GameFrameworkLogLevel level, object message)
        {
            // Integrate with your project's own logging SDK, e.g., upload to a server or write to a local file
            MyLogger.Write(level, message);
        }
    }
}
```

Source: [Runtime/Helper/DefaultLogHelper.cs](/Runtime/Helper/DefaultLogHelper.cs#L42-L83)

### 2. Register via Type Name String

Pass the complete class name of the custom Helper (including namespace) to `Helper.CreateHelper<T>`. The framework will use reflection to find the type and `AddComponent` it to a new `GameObject`:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: "GameFrameX.Runtime.MyLogHelper",
    customHelper: null);
```

The advantage of the string approach is that you don't need to pre-place the component in the scene, making it suitable for pure code projects.

### 3. Register via Pre-placed Component

Make the custom Helper a `MonoBehaviour` script attached to a prefab, then pass it directly to the `customHelper` parameter. The framework checks whether the component is already in the scene and decides whether to reuse it directly or `Instantiate` a copy:

```csharp
// myLogHelperPrefab is a reference to the MyLogHelper component on a prefab
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: string.Empty,
    customHelper: myLogHelperPrefab);
```

When `helperTypeName` is empty and `customHelper` is not null, `customHelper` takes precedence; otherwise, the type is looked up by string; when both are empty, the framework outputs a warning and returns `null`.

### 4. Hook into the Framework Entry Point

In `GameFrameXComponent.Awake` or the initialization flow, inject the created Helper into the corresponding subsystem. Taking the `Log` module as an example:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    "GameFrameX.Runtime.MyLogHelper", null);
GameFrameworkLog.SetLogHelper(logHelper);
```

See the registration entry point in the source code: [Runtime/Helper/Helper.cs](/Runtime/Helper/Helper.cs#L57-L106).

```csharp
var helper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    target: myRoot,
    helperTypeName: "GameFrameX.Runtime.MyLogHelper",
    customHelper: null,
    index: 0);
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Warning `Can not find helper type 'XXX'.` | The string class name is mistyped, the namespace is missing, or reflection is not enabled for the assembly | Verify with `Type.FullName`; confirm the class's assembly is not stripped by IL2CPP |
| Warning `Type 'A' is not assignable from 'B'.` | The custom class does not implement the target interface | Make the custom class `implements` the corresponding `IXxxHelper` |
| Warning `You must set custom helper with '...' type first.` | `helperTypeName` is empty and `customHelper` is also `null` | Fill in one of the two, or `AddComponent` first and then pass it in |
| Custom logic does not take effect | The corresponding subsystem's `SetXxxHelper` injection was not called | Complete the `CreateHelper` + `SetHelper` injection early in framework initialization |

## Background (Optional)

Internally, `Helper.CreateHelper<T>` uses `Utility.Assembly.GetType` to look up the type by string, then instantiates it with `new GameObject().AddComponent`; when `customHelper` is passed in, it decides between reusing or `Instantiate` based on whether the component is already in the scene. The two parameters serve as fallbacks for each other, allowing both configuration-driven and non-configuration-driven projects to integrate.
