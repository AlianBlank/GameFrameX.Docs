# 初期化エラー "Can not find component type" が発生した場合の対処法

このエラーは `GameAnalyticsComponent.Init()` によってスローされます。Inspector で設定された分析コンポーネントの `ComponentType` 文字列が、実行時に `Utility.Assembly.GetType()` で実際の型として解決できない場合、該当する Provider は直接スキップされ(`continue`)、対応する統計チャネルからはデータが一切送信されません。修正の要点は、`ComponentType` を、実際に存在し `IGameAnalyticsManager` を実装しているクラスの完全な型名(名前空間を含む)と一致させることです。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `Can not find component type 'XXX'` が発生し、該当チャネルからデータが一切送信されない | `ComponentType` 文字列が実際のクラス名/名前空間と一致していない(テキストを手動で編集した、クラスがリネームされた) | Inspector のドロップダウンで正しい型を選択し直す。下記の手順 1 を参照 |
| エディターでは正常だが、実機ビルド後にエラーが発生する | 実装クラスが含まれるアセンブリ/コードがストリッピングされた、またはビルドに含まれていない | 実装クラスのアセンブリがビルドに含まれていること、コードストリッピングで削除されていないことを確認する |
| 設定内のクラスは確かに存在するのにエラーが出る | 型名に完全な名前空間が含まれておらず、`Utility.Assembly.GetType` で見つからない | `GameFrameX.GameAnalytics.Runtime.XXXManager` のような完全な型名を使用する |
| ドロップダウンリストにそもそも目的の型が表示されない | そのクラスが `IGameAnalyticsManager` インターフェースを実装していないため、Inspector に列挙されない | クラスに `IGameAnalyticsManager` を実装させる(通常は `BaseGameAnalyticsManager` を継承) |

エラーの発生箇所を判定するロジック(注意：型が見つかっても `IGameAnalyticsManager` を実装していない場合は、エラーにならずサイレントに無効になるだけです):

```csharp
foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
{
    if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
    {
        var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
        if (gameAnalyticsComponentType == null)
        {
            Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
            continue;
        }
```

出典： [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L54-L63)

## 修正手順

### 1. Inspector のドロップダウンで型を選択し直す(文字列の手入力はしない)

シーン内の GameAnalytics コンポーネント(`AddComponentMenu("Game Framework/GameAnalytics")`)を選択し、Inspector の「ゲームデータ分析コンポーネントリスト、順次レポート」リストで、エラーが発生しているエントリの ComponentType を選択し直します。

ドロップダウンの候補リストは `GameAnalyticsComponentInspector.RefreshTypeNames()` によって生成されます。このメソッドは `IGameAnalyticsManager` を実装したすべてのランタイム型をスキャンし、さらに `NoneOptionName` の空オプションを追加します。

```csharp
protected override void RefreshTypeNames()
{
    List<string> managerTypeNameList = new List<string>
    {
        NoneOptionName
    };
    managerTypeNameList.AddRange(Type.GetRuntimeTypeNames(typeof(IGameAnalyticsManager)));
    m_ManagerTypeNames = managerTypeNameList.ToArray();
}
```

出典： [GameAnalyticsComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Editor/Inspector/GameAnalyticsComponentInspector.cs#L42-L50)

ドロップダウンに目的の型が表示されていれば、それを選択するだけで問題ありません。Inspector が書き込むのはランタイムの解決と一致する型名であるため、手入力によるスペルミス/名前空間の誤りを根本的に解消できます。

### 2. ドロップダウンに目的の型がない場合、クラス定義を確認する

実装クラスは `IGameAnalyticsManager` の実装でなければなりません。最も簡単な方法は、フレームワークが提供する抽象基底クラス `BaseGameAnalyticsManager` を継承し、その抽象メンバーを実装することです:

```csharp
public abstract class BaseGameAnalyticsManager : GameFrameworkModule, IGameAnalyticsManager
{
    public abstract void Init(Dictionary<string, string> args);
    public abstract void ManualInit(Dictionary<string, string> args);
    public abstract bool IsManualInit();
    ...
}
```

出典： [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L10-L36)

### 3. 設定データ自体が有効であることを確認する

`ComponentType` はシリアライズクラス `GameAnalyticsComponentProvider`(`Runtime/GameAnalytics/GameAnalyticsComponent.cs` の 362 行目付近で定義)に格納されており、シーン/プレハブと一緒にシリアライズされます。以下の場合、「残留した無効な型名」が発生します:

- 実装クラスが削除またはリネームされた後、古いシーン/プレハブ内のシリアライズされた文字列が同期的に更新されていない;
- 他人のシーンやプレハブをコピーしたが、その依存する分析 SDK パッケージが現在のプロジェクトにインポートされていない。

対処方法：該当するシーン/プレハブを開き、エラーが発生している Provider エントリを有効な型に変更するか、そのエントリを直接削除してください。

## 検証

1. Play モードに再突入する(またはコンポーネントを再度有効化して `OnEnable` → `Init()` をトリガーする)と、Console に `Can not find component type '...'` が表示されなくなります。
2. 公開 API(例:`GameAnalyticsComponent.SetPlayerId("test")`)を一度呼び出し、例外がなくデータが該当チャネルに到達することを確認します。`Init()` は、正常に作成されたすべての `IGameAnalyticsManager` を走査してその `Init(args)` を呼び出します。

```csharp
var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
{
    Dictionary<string, string> args = new Dictionary<string, string>();
    foreach (var param in gameAnalyticsComponentProvider.Setting)
    {
        args[param.Key] = param.Value;
    }

    gameAnalyticsManager.Init(args);
    m_GameAnalyticsManager.Add(gameAnalyticsManager);
}
```

出典： [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L65-L75)

なお、`Init()` には `m_IsInit` による再入防止の保護があり、重複して呼び出しても型は再解析されません。検証時は、新規の初期化(Play のやり直しまたはコンポーネントの再有効化)の中で確認する必要があります。

## 背景

`GameAnalyticsComponent` は `Awake` で Provider リストを構築し、`OnEnable` 時に `Init()` を呼び出します。リフレクション `Utility.Assembly.GetType` + `Activator.CreateInstance` によって、文字列に基づいて各分析チャネルのマネージャーをインスタンス化し、Inspector 内の該当エントリの `Setting` ディクショナリをそのまま `Init(Dictionary<string, string> args)` に渡します。この「文字列 + リフレクション」の設計により、コンポーネントの設定はコンパイル時の依存から切り離されますが、その代償として、型名が無効になった場合には実行時にしか発見できず、本ページのエラーとして現れます。
