# 狀態間轉換方法

在繼承 `FsmState<T>` 的任意狀態類別中呼叫 `ChangeState<TState>(fsm)` 時，目前 FSM 的作用中狀態會立即轉換，框架會依序觸發目前狀態的 `OnLeave` 與新狀態的 `OnEnter`。

## 前置條件

- 已透過 `FsmComponent.CreateFsm(...)` 或 `GameApp.Fsm.CreateFsm(...)` 建立目標 FSM，且要轉換的目標狀態已作為參數傳入。
- 目標狀態型別必須繼承 `FsmState<T>`，其中 `T` 必須與 FSM 的泛型參數一致。

## 操作步驟

1. **在狀態類別內部觸發轉換**：在 `FsmState<T>` 衍生類別內部呼叫以 protected 宣告的 `ChangeState<TState>(IFsm<T> fsm)`。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

   來源：[FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

2. **需要從狀態外部觸發時**：使用 `FsmState<T>` 的 public 方法 `ChangeToState<TState>(IFsm<T> fsm)`，其內部會將呼叫轉送至 `ChangeState<TState>(fsm)`。

   ```csharp
   fsm.CurrentState.ChangeToState<MoveState>(fsm);
   ```

   來源：[FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L119)

3. **只知道目標狀態型別時**：使用 `Type` 多載傳入狀態類別的執行階段型別。

   ```csharp
   ChangeState(fsm, typeof(MoveState));
   ```

   此多載會驗證傳入的 `Type` 是否可指派給 `FsmState<T>`，若否則會擲回 `GameFrameworkException("State type '{0}' is invalid.")`。  
   來源：[FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

4. **內部執行流程**：呼叫 `Fsm<T>.ChangeState(Type)` 時，框架會先呼叫前一個狀態的 `OnLeave(this, false)`，重設 `m_CurrentStateTime`，替換 `m_CurrentState`，然後呼叫新狀態的 `OnEnter(this)`。

   ```csharp
   m_CurrentState.OnLeave(this, false);
   m_CurrentStateTime = 0f;
   m_CurrentState = state;
   m_CurrentState.OnEnter(this);
   ```

   來源：[Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L726-L729)

## 常見變化

- **以字串名稱轉換**：先透過 `FsmComponent.HasState<T>(name)` 等以名稱為基礎的 API 尋找狀態，再使用 `Type` 多載進行轉換。本儲存庫未提供以名稱直接轉換的 public 泛型多載。
- **鏈式多次轉換**：在 `OnEnter` 中立即呼叫 `ChangeState<NextState>(fsm)` 即可在單一影格內進行連鎖轉換。但需避免無限遞迴。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| `GameFrameworkException: Current state is invalid.` | 尚未呼叫 `Start<T>()`，或是在 FSM 已 `Shutdown` 的狀態下呼叫 `ChangeState` | 先呼叫 `fsm.Start<IdleState>()` 以啟動 FSM |
| `FSM '...' can not change state to '...' which is not exist.` | 目標狀態類別未傳入 `CreateFsm` 的 `states` 陣列 | 將目標狀態執行個體加入 `CreateFsm(owner, new IdleState(), new MoveState())` |
| `State type '...' is invalid.` | 透過 `Type` 多載傳入的型別並非 `FsmState<T>` 的衍生類別 | 確認目標型別繼承 `FsmState<T>`，且 `T` 與 FSM 一致 |
| 轉換後未收到 `OnLeave` 通知 | 轉換程式碼寫在 `OnLeave` 之後，或 FSM 已被銷毀 | 在狀態生命週期方法內呼叫，並確認 FSM 仍存活 |

## 背景（選擇性）

`ChangeState<TState>` 內部僅單純轉送方法呼叫，實際的轉換邏輯集中在 `Fsm<T>.ChangeState(Type)`，確保所有多載皆遵循相同的 `OnLeave → 重設計時器 → 替換 → OnEnter` 流程，以避免分支遺漏。
