# WebGL and Cross-Platform Usage Guide

This page explains how to use the Web ProtoBuff component to send ProtoBuf HTTP requests on WebGL and other platforms (Editor, Windows, mobile, etc.): the caller uses the same `Post<T>` API, and the component internally switches between `UnityWebRequest` and `HttpWebRequest` via `#if UNITY_WEBGL`, so you don't need to write separate code for different platforms.

## Prerequisites

- The `com.gameframex.unity.web.protobuff` package and its dependencies (GameFrameX, `GameFrameX.Network`, ProtoBuf runtime) are installed.
- Request and response message classes inherit from `MessageObject`, and response classes additionally implement `IResponseMessage`.
- WebGL builds use IL2CPP; the package includes [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs) to participate in build stripping processing.

## Steps

1. **Confirm the target platform macro is active**. The component only takes the UnityWebRequest path when the `UNITY_WEBGL` macro is defined; the macro takes effect automatically after switching to the WebGL platform (File → Build Settings → Switch Platform).

   ```csharp
   using System;
   using System.Collections.Generic;
   using System.Text;
   using GameFrameX.Runtime;
   #if UNITY_WEBGL
   using UnityEngine.Networking;
   #endif
   ```

   Source: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L1-L7)

2. **Adjust timeout and concurrency limits as needed per platform**. Defaults at construction are `Timeout = 5` (seconds) and `MaxConnectionPerServer = 8`; modifying `Timeout` also refreshes `RequestTimeout` in sync.

   ```csharp
   [UnityEngine.Scripting.Preserve]
   public WebProtoBuffManager()
   {
       MaxConnectionPerServer = 8;
       Timeout = 5f;
   }

   public float Timeout
   {
       get { return m_Timeout; }
       set
       {
           m_Timeout = value;
           RequestTimeout = TimeSpan.FromSeconds(value);
       }
   }

   public int MaxConnectionPerServer { get; set; }

   public TimeSpan RequestTimeout { get; set; }
   ```

   Source: [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs#L27-L54)

3. **Call `Post<T>` directly to send the request**. This is the unified cross-platform entry point; the response body is deserialized into `T` after the type is validated against the message Id.

   ```csharp
   public async Task<T> Post<T>(string url, MessageObject message) where T : MessageObject, IResponseMessage
   {
       DebugSendLog(message);
       var webBufferResult = await PostInner(url, message);
       if (webBufferResult.IsNotNull())
       {
           var messageObjectHttp = SerializerHelper.Deserialize<MessageHttpObject>(webBufferResult.Result);
           if (messageObjectHttp.IsNotNull() && messageObjectHttp.Id != default)
           {
               var messageType = ProtoMessageIdHandler.GetRespTypeById(messageObjectHttp.Id);
               if (messageType != typeof(T))
               {
                   Log.Error($"Response message type is invalid. Expected '{typeof(T).FullName}', actual '{messageType.FullName}'.");
                   return default;
               }

               var messageObject = SerializerHelper.Deserialize<T>(messageObjectHttp.Body);
               DebugReceiveLog(messageObject);
               return messageObject;
           }
       }

       return default;
   }
   ```

   Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L182-L205)

   Custom example (keeping identifiers consistent with the source code):

   ```csharp
   // message is the request message object; LoginResponse : MessageObject, IResponseMessage
   var response = await webProtoBuffManager.Post<LoginResponse>(url, message);
   ```

4. **No extra handling is needed for WebGL differences**. Once a request enters the queue, `UpdateProtoBuf` dequeues it every frame within the concurrency limit and calls `MakeProtoBufBytesRequest`, which is compiled per platform internally:

   ```csharp
   void UpdateProtoBuf(float elapseSeconds, float realElapseSeconds)
   {
       lock (m_StringBuilder)
       {
           if (m_SendingProtoBufList.Count < MaxConnectionPerServer)
           {
               if (m_WaitingProtoBufQueue.Count > 0)
               {
                   var webProtoBufData = m_WaitingProtoBufQueue.Dequeue();

                   MakeProtoBufBytesRequest(webProtoBufData);

                   m_SendingProtoBufList.Add(webProtoBufData);
               }
           }
       }
   }
   ```

   Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L39-L55)

## Common Variants

- **WebGL platform**: Uses `UnityEngine.Networking.UnityWebRequest` to send requests, with `Content-Type` set to `application/x-protobuf`; the timeout is taken from `RequestTimeout.TotalSeconds` (seconds), and results are driven via the `completed` callback; note that the `timeout` property is an `int`, so `Timeout` should be set to whole seconds to avoid truncation.

  ```csharp
  #if UNITY_WEBGL
              UnityEngine.Networking.UnityWebRequest unityWebRequest;
              if (webData.IsGet)
              {
                  unityWebRequest = UnityEngine.Networking.UnityWebRequest.Get(webData.URL);
              }
              else
              {
                  unityWebRequest = UnityEngine.Networking.UnityWebRequest.Post(webData.URL, string.Empty);
              }

              unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;
              unityWebRequest.SetRequestHeader("Content-Type", ProtoBufContentType);
              byte[] postData = webData.SendData;
              unityWebRequest.uploadHandler = new UnityEngine.Networking.UploadHandlerRaw(postData);

              var asyncOperation = unityWebRequest.SendWebRequest();
              asyncOperation.completed += (asyncOperation2) =>
              {
                  try
                  {
                      m_SendingProtoBufList.Remove(webData);
                      if (unityWebRequest.isNetworkError || unityWebRequest.isHttpError || unityWebRequest.error != null)
                      {
                          webData.Task.TrySetException(new Exception(unityWebRequest.error));
                          return;
                      }

                      webData.Task.SetResult(new WebBufferResult(webData.UserData, unityWebRequest.downloadHandler.data));
                  }
                  finally
                  {
                      unityWebRequest.Dispose();
                      ReferencePool.Release(webData);
                  }
              };
  #else
  ```

  Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L83-L119)

- **Non-WebGL platforms** (Editor, desktop, mobile): Use the `HttpWebRequest` asynchronous streaming implementation, with the timeout in milliseconds (`RequestTimeout.TotalMilliseconds`); `WebExceptionStatus.Timeout` is converted into a `TimeoutException` thrown to upper layers:

  ```csharp
                  HttpWebRequest request = WebRequest.CreateHttp(webData.URL);
                  request.Method = webData.IsGet ? WebRequestMethods.Http.Get : WebRequestMethods.Http.Post;
                  request.Timeout = (int)RequestTimeout.TotalMilliseconds; // Set the request timeout
                  request.ContentType = ProtoBufContentType;
  ```

  ```csharp
              catch (WebException e)
              {
                  // Catch the timeout exception
                  if (e.Status == WebExceptionStatus.Timeout)
                  {
                      webData.Task.SetException(new TimeoutException(e.Message));
                      return;
                  }

                  webData.Task.SetException(e);
              }
  ```

  Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L120-L155)

- **Request body wrapping**: Externally, only a `MessageObject` is passed in; `PostInner` automatically wraps it in a `MessageHttpObject` (Id, UniqueId, Body) and serializes it to binary before enqueueing it:

  ```csharp

           MessageHttpObject messageHttpObject = new MessageHttpObject
           {
               Id = id,
               UniqueId = message.UniqueId,
               Body = SerializerHelper.Serialize(message),
           };
           var sendData = SerializerHelper.Serialize(messageHttpObject);
           var webData = WebProtoBufData.Create(url, sendData, uniTaskCompletionSource, userData);
           m_WaitingProtoBufQueue.Enqueue(webData);
  ```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Response message type is invalid. Expected '...', actual '...'` log and `default` returned | The response type mapped to the message Id returned by the server does not match the `T` passed in by the caller | Verify the request/response mapping registered in `ProtoMessageIdHandler` and the generic parameter of `Post<T>` |
| No response to requests under WebGL | The target `Timeout` contains a decimal and is truncated to an overly small value by `(int)RequestTimeout.TotalSeconds` (e.g., `0.5` → `0`) | Set `Timeout` to whole seconds |
| Requests hang indefinitely | Concurrency has reached `MaxConnectionPerServer` (default 8), leaving subsequent requests stuck in `m_WaitingProtoBufQueue` | Increase `MaxConnectionPerServer`, or make sure the component's `Update` keeps being driven |
| WebGL console reports `Unknown error` / CORS-type network errors | The `unityWebRequest.isNetworkError \|\| unityWebRequest.isHttpError \|\| unityWebRequest.error != null` branch is triggered; the exception text is exactly `unityWebRequest.error` | Check the server's CORS configuration and URL reachability |
| Non-WebGL platforms throw `TimeoutException` | The server did not respond within `RequestTimeout` (millisecond precision) | Increase `Timeout` or investigate server-side latency |

## Verification

- Send the same `Post<T>` request on both WebGL and Editor, and confirm that both return a deserialized `T` instance with a matching `UniqueId`.
- After enabling the `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` macro, you can see the `接收消息 ID:[...] 消息内容:...` debug log (Source: [WebProtoBuffManager.ProtoBuf.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.ProtoBuf.cs#L231-L237)).
- Deliberately replace `T` with the wrong type and confirm that the `Response message type is invalid...` error appears, proving the type validation works.

## Background

The component is conditionally compiled into dual implementations per platform: WebGL cannot use `HttpWebRequest` due to runtime limitations, so it uniformly uses the `completed` callback of `UnityWebRequest`; all other platforms keep the `Task`-based streaming `HttpWebRequest` implementation. Both write results back to the same `TaskCompletionSource<WebBufferResult>`, so the upper-level `Post<T>` is unaware of any difference. URL query parameters, the reused `StringBuilder`, and the concurrency limit are defined in [WebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffManager.cs).
