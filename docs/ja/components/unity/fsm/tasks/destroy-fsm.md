# FSM を破棄する方法

`FsmManager` の `DestroyFsm` オーバーロードを呼び出すことで、有限状態マシンを破棄できます。破棄後、その FSM はマネージャーから削除され、破棄済みとしてマークされ(`IsDestroyed == true`)、次の Update 時には駆動されなくなります。

## 前提条件

- プロジェクト内で `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IFsmManager>()` を通じて `IFsmManager` インスタンスを取得済みであること(または `FsmComponent` から取得していること)。
- `CreateFsm` で対象の FSM を作成済みであり、その所有者型 `T` と名前(`null` は匿名を表す)を把握していること。

## 操作手順

1. **所有者型で破棄(匿名 FSM)**

   ```csharp
   IFsmManager fsmMgr = GameFrameX.Runtime.GameFrameworkEntry.GetModule<GameFrameX.Fsm.Runtime.IFsmManager>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>();
   ```

2. **所有者型 + 名前で破棄**

   ```csharp
   bool ok = fsmMgr.DestroyFsm<MyOwner>("BattleFsm");
   ```

3. **FSM 参照を直接渡して破棄**

   `IFsm<T>` または `FsmBase` のハンドルを保持している場合、ジェネリック型と名前を再度指定することなく、直接渡すことができます:

   ```csharp
   IFsm<MyOwner> fsm = fsmMgr.GetFsm<MyOwner>();
   bool ok = fsmMgr.DestroyFsm<MyOwner>(fsm);   // ジェネリック版オーバーロード
   bool ok2 = fsmMgr.DestroyFsm(fsm as FsmBase); // 非ジェネリック版オーバーロード
   ```

`DestroyFsm` の戻り値は `bool` で、破棄が成功したかどうかを表します。存在しない FSM の場合は `false` が返されます。

## よくあるバリエーション

- **`FsmComponent` から破棄**:`FsmComponent` は内部に `IFsmManager` をカプセル化しているため、`GameEntry.GetComponent<FsmComponent>().DestroyFsm<MyOwner>(name)` の形式で直接使用できます。
- **一括クリーンアップ**:マネージャーの `Shutdown` 時にはすべての FSM を順次 `Shutdown()` 呼び出すため、手動で一つずつ破棄する必要はありません([FsmManager.cs#L138-L147](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs#L138-L147))。
- **存在チェック**:破棄前に `HasFsm<T>(name)` を呼び出すことで、重複した破棄による `false` の返却を回避できます。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `DestroyFsm` が `false` を返す | 渡された所有者型または名前が作成時と一致しないか、FSM がすでに破棄済みである | `HasFsm` でチェックしてから破棄するか、`FsmBase` ハンドルを直接渡す |
| 破棄後も Update コールバックを受信する | 破棄は遅延生效であり、本フレームの Update はすでにディスパッチ済みである | 次のフレームで再度確認する。マネージャーの Update 内では `IsDestroyed == true` の FSM はスキップされる |
| `DestroyFsm(typeof(T))` が `GameFrameworkException("Owner type is invalid.")` をスローする | `null` が渡されている | ジェネリック版オーバーロードを使用するか、自身で null チェックを行う |

## 検証

破棄後は以下のいずれかの方法で確認できます:

```csharp
Assert.IsFalse(fsmMgr.HasFsm<MyOwner>()); // 存在しない場合は成功
Assert.AreEqual(0, fsmMgr.Count);          // カウントは 0 になるはず
```

## 背景(オプション)

`FsmManager` は内部的に `Dictionary<TypeNamePair, FsmBase>` で FSM を保持しており、Update ループではまず一時リストをコピーしてから反復処理を行い、反復中に `IsDestroyed == true` のエントリはスキップされます。そのため、反復途中で破棄が発生しても今回の反復には影響しません。破棄時には `Shutdown()` を通じて状態リソースが解放され、辞書から削除されます。
