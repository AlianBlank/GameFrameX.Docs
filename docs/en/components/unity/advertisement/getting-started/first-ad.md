# First Ad: From Attaching the Component to Playback Complete

Follow this page and you will get a usable `AdvertisementComponent` in the scene, play an ad once through `Play(AdvertisementPlayOption)`, and receive three results in the callback: "playback succeeded / failed / fully watched".

## Prerequisites

| Item | Description |
|---|---|
| GameFrameX Runtime | The component inherits from `GameFrameworkComponent` and retrieves the module via `GameFrameworkEntry.GetModule<IAdvertisementManager>()`, so the GameFrameX framework entry must already exist in the scene |
| A specific ad implementation | This package only provides the abstraction layer (`IAdvertisementManager` / `AdvertisementConfig`); the actual channel SDK implementation needs to be integrated separately |
| Platform ad unit IDs | Prepare according to your target platform (Android / iOS / WebGL / WeChat / Douyin / Kuaishou) |

## Steps

### 1. Attach the Advertisement Component

Select the GameObject where the GameFrameX framework is located in the scene, and add the component via the menu **GameFrameX → Advertisement**. The component has `[DisallowMultipleComponent]`, so only one can be attached to a single object.

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Advertisement")]
public class AdvertisementComponent : GameFrameworkComponent
{
    [SerializeField] private string m_adUnitIdAndroid = string.Empty;
    [SerializeField] private string m_adUnitIdiOS = string.Empty;
    [SerializeField] private string m_adUnitIdWebGL = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLWeChat = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLDouYin = string.Empty;
    [SerializeField] private string m_adUnitIdWebGLKuaiShou = string.Empty;
    [SerializeField] private bool m_debug = false;
    [SerializeReference, SerializeField] private AdvertisementConfig m_config = null;
}
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L43-L61)

### 2. Fill in the Ad Unit IDs for Each Platform in the Inspector

The six ID fields in the Inspector each correspond to a platform. In `Awake`, the component automatically selects one based on the current compilation platform and mini-game macros, and assigns it to the read-only property `AdUnitId`:

```csharp
AdUnitId =
#if UNITY_WEBGL
#if ENABLE_WECHAT_MINI_GAME
        m_adUnitIdWebGLWeChat
#elif ENABLE_DOUYIN_MINI_GAME
        m_adUnitIdWebGLDouYin
#elif ENABLE_KUAISHOU_MINI_GAME
        m_adUnitIdWebGLKuaiShou
#else
        m_adUnitIdWebGL
#endif
#elif UNITY_ANDROID
        m_adUnitIdAndroid
#elif UNITY_IOS
        m_adUnitIdiOS
#else
        string.Empty
#endif
        ;
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)

In other words, in the editor (when not targeting Android / iOS / WebGL) `AdUnitId` will be an empty string. This is expected behavior, not a configuration error.

### 3. Provide a Configuration and Complete Initialization

`AdvertisementConfig` is an abstract base class with only one generic field `isDebug`; channel-specific parameters are extended by your implementation class:

```csharp
[Preserve]
[Serializable]
public abstract class AdvertisementConfig
{
    /// <summary>
    /// Whether to enable debug mode.
    /// </summary>
    [Preserve]
    public bool isDebug;
}
```

> Source: [AdvertisementConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L41-L53)

There are two ways to initialize, choose either one:

- **Method A (Recommended, Zero Code)**: The field `m_config` is marked with `[SerializeReference]`, so you can directly select your configuration subclass in the Inspector and fill in the parameters. The component's `Start()` will automatically call `Initialize` when `m_config != null`:

```csharp
private void Start()
{
    if (m_config != null)
    {
        _advertisementManager.Initialize(m_config);
    }
}
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126)

- **Method B (Code)**: Create your own configuration object and pass it in, which will also overwrite the component's `Config`:

```csharp
[Preserve]
public void Initialize(AdvertisementConfig config)
{
    m_config = config;
    _advertisementManager.Initialize(config);
}
```

> Source: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L135-L140)

### 4. Play the Ad and Handle the Result

Playback uniformly goes through `Play(AdvertisementPlayOption option)`, putting the callbacks into the option object:

```csharp
using GameFrameX.Advertisement.Runtime;
using GameFrameX.Runtime;
using UnityEngine;

public class RewardButton : MonoBehaviour
{
    public void OnClickWatchAd()
    {
        var component = GameEntry.GetComponent<AdvertisementComponent>();

        component.Play(new AdvertisementPlayOption
        {
            extraData  = "level_10_double_reward", // Only passed through to the server-side reward verification during the Load phase
            customData = "from_main_ui",
            OnSuccess = data => Log.Info($"Ad played successfully, extra data: {data}"),
            OnFail    = error => Log.Error($"Ad playback failed: {error}"),
            OnShowResult = isShown => Log.Info($"Whether the ad was successfully shown: {isShown}"),
        });
    }
}
```

> Sources: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L42-L85), [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L215-L219)

Semantics of the three callbacks (from source code comments):

| Callback | Signature | Trigger Timing |
|---|---|---|
| `OnSuccess` | `Action<string>` | Ad playback succeeded (e.g., reward verification passed), the parameter is the extra data |
| `OnFail` | `Action<string>` | Ad playback failed, the parameter is the error message |
| `OnShowResult` | `Action<bool>` | Ad display result, the parameter indicates whether it was successfully shown |

> Source: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L46-L68)

### 5. Add Extra Data When Needed

Before playback, you can append key-value pairs via `SetExtraData(key, value)`, which will be forwarded directly to the manager:

```csharp
[Preserve]
public void SetExtraData(string key, string value)
{
    Debug.Log($"[AdComponent] SetExtraData: key={key}, value={value ?? "(null)"}, managerType={_advertisementManager?.GetType().FullName ?? "(null)"}");
    _advertisementManager.SetExtraData(key, value);
}
```

## Common Variants

### Use the Manager Interface Directly, Bypassing the Component

The component is just a thin wrapper over `IAdvertisementManager`. When you need to play ads in non-MonoBehaviour code, you can directly get the module:

```csharp
var manager = GameFrameworkEntry.GetModule<IAdvertisementManager>();
manager.Play(new AdvertisementPlayOption
{
    OnSuccess    = data => { /* Issue reward */ },
    OnFail       = error => { /* Notify */ },
    OnShowResult = isShown => { /* Analytics */ },
});
```

### Legacy API (Still Compilable, but Marked Obsolete)

The following members are all marked with `[Obsolete]` and are only recommended for short-term use when migrating old projects:

| Obsolete Member | Obsolete Message | Replacement |
|---|---|---|
| `Initialize(string adUnitId, bool isDebug = false)` | `Use Initialize(AdvertisementConfig) instead.` | `Initialize(AdvertisementConfig)` |
| `Show(Action<string>, Action<string>, Action<bool>)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |
| `Play(Action<bool> onShowResult, string customData = null)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |
| `Load(Action<string> success, Action<string> fail)` | `Use Play(AdvertisementPlayOption) instead.` | `Play(AdvertisementPlayOption)` |

## Common Errors

| Symptom | Cause | Solution |
|---|---|---|
| Console outputs `Advertisement manager is invalid.` (`Log.Fatal`) | `GameFrameworkEntry.GetModule<IAdvertisementManager>()` returns null—no available advertisement manager implementation is registered | Confirm that a specific channel implementation has been integrated, and that the component's `componentType` can be resolved by `Utility.Assembly.GetType` |
| `AdUnitId` is an empty string | The current platform is not in the `UNITY_WEBGL` / `UNITY_ANDROID` / `UNITY_IOS` branches, so the source code falls back to `string.Empty` | Switch to the target platform (or a real device) for testing; being empty in the editor is normal |
| The mini-game platform gets the regular WebGL ID | The `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` macros are not defined | Add the corresponding macros in Player Settings' Scripting Define Symbols |
| `NullReferenceException` thrown during playback | Called `Play` without initialization: when `m_config` is null, `Start()` will not automatically call `Initialize` | Specify `Config` in the Inspector, or manually call `Initialize(AdvertisementConfig)` before playback |
| `extraData` is set but not received by server-side verification | This field "is only passed through to the server-side reward verification callback during the ad loading (Load) phase; setting it after loading is ineffective" | Fill in `extraData` all at once before triggering load/playback, do not change it during playback |
| Adding a second advertisement component fails | The class has `[DisallowMultipleComponent]` | Keep only one `AdvertisementComponent` on a single GameObject |

## Background (Optional)

In `Awake`, the component sets `InterfaceComponentType` to `typeof(IAdvertisementManager)`, and the implementation type is resolved via reflection from `componentType`. Therefore, when switching channel SDKs, the business code does not need to change—only replace the implementation and configuration subclass.
