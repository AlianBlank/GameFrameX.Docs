# What to Do When "Web View manager is invalid" Is Reported at Startup

This error comes from `WebViewComponent.Awake()`: `GameFrameworkEntry.GetModule<IWebViewManager>()` returned `null`, which means no concrete module implementing `IWebViewManager` has been registered/loaded in the framework. When this occurs, the WebView component will not call `Initialize()`, and subsequent calls such as `Show` / `Hide` will result in null references.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Log.Fatal("Web View manager is invalid.")` is output immediately at startup | `GameFrameworkEntry.GetModule<IWebViewManager>()` returns `null`; the concrete implementation module is not loaded | Confirm that a concrete implementation module of `BaseWebViewManager` exists in the project; see [Fix Step 1](#fix-steps) |
| A later call to `Show(url)` throws `NullReferenceException` | After the previous step failed, `_webViewManager` remains `null` and the component skips initialization entirely | Resolve the Fatal error above first; see [Verification](#verification) |
| The component's implementation type dropdown in the Inspector is empty | The implementation type is not selected, or the corresponding assembly was not compiled into the project | See [Fix Step 2](#fix-steps) |

Source code where the error is triggered:

```csharp
_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

## Fix Steps

### 1. Confirm that the project contains a concrete implementation of `IWebViewManager`

This repository only provides the abstraction layer: `BaseWebViewManager` is an abstract class and contains no platform implementations (the directory only contains `BaseWebViewManager`, `IWebViewManager`, `WebViewComponent`, etc.). Concrete implementations must be provided by the companion runtime module:

```csharp
public abstract partial class BaseWebViewManager : GameFrameworkModule, IWebViewManager
{
    public abstract void Initialize();
    public abstract void Show(string url);
    public abstract void MakeFullScreen();
    public abstract void ExecuteJavaScript(string javaScript);
    public abstract void Hide();
}
```

Source: [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39)

Troubleshooting: search the project globally for `: BaseWebViewManager` and confirm that at least one non-abstract derived class exists; if none exists, install/import the corresponding runtime implementation package and retry.

### 2. Check that the implementation type on the component is selected

`WebViewComponent` resolves the implementation type via reflection in `Awake()`, then retrieves the interface module:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IWebViewManager);
base.Awake();
if (!IsRuntimeComponentReady)
{
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L30)

The value of `componentType` is provided by the Inspector; the editor script populates the dropdown with all types that implement `IWebViewManager`:

```csharp
internal sealed class WebViewComponentInspector : ComponentTypeComponentInspector
{
    ...
    RefreshComponentTypeNames(typeof(IWebViewManager));
}
```

Source: [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L14-L19)

Action: select the GameObject with the `WebView` component attached and confirm in the Inspector that the implementation type is not empty; an empty value indicates that the corresponding assembly was not compiled into the current build target (common when a platform implementation package only supports specific platforms). Save the scene after fixing and run again.

### 3. Confirm that the runtime assemblies participate in compilation

This package's assemblies are defined as `Runtime/GameFrameX.WebView.Runtime.asmdef` and `Editor/GameFrameX.WebView.Editor.asmdef`. Check the Unity Console for compilation errors related to these two assemblies (or to the implementation module assembly); a compilation failure prevents `GetModule` from obtaining the implementation, which manifests as the same Fatal error.

## Verification

1. Re-enter Play mode; the Console no longer shows the Fatal log `Web View manager is invalid.`.
2. Execute the full call chain once; the page should open normally:

```csharp
var webView = GameObject.FindObjectOfType<GameFrameX.WebView.Runtime.WebViewComponent>();
webView.Show("https://example.com");
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L51-L58)

## Background

`WebViewComponent` is a `GameFrameworkComponent`; it does not implement any WebView logic itself and is only responsible for retrieving the `IWebViewManager` module from `GameFrameworkEntry` in `Awake()` and forwarding calls (`Show`, `MakeFullScreen`, `ExecuteJavaScript`, `Hide`). The separation of abstraction and implementation means the interface layer and each platform implementation can be packaged independently; when the implementation module is missing, the module retrieval step fails and outputs the Fatal log shown on this page.
