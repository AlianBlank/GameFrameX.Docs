# TCP / WebSocket / HTTP 다중 프로토콜 리스닝 활성화

GameFrameX.Server 시작 진입점에서 필요에 따라 TCP, WebSocket, HTTP 세 가지 네트워크 리스닝을 활성화하여, 동일한 비즈니스 코드가 서로 다른 프로토콜 엔드포인트를 동시에 외부에 제공하도록 합니다. 주로 멀티 플랫폼 통합(네이티브 TCP, 웹/H5, 미니 프로그램, 외부 HTTP API)에 사용됩니다.

## 사전 조건

- [GameFrameX.Server](https://github.com/GameFrameX/GameFrameX.Server)의 로컬 빌드 및 기본 설정이 완료되어 있어야 합니다.
- 외부 포트가 사용 중이 아닌지 확인하고, 방화벽에서 해당 TCP 포트가 허용되어 있는지 확인합니다(프레임워크 기본 리스닝 포트는 아래 표 참조).
- `GameFrameX.StartUp` 네임스페이스의 `AppStartUpGame` 등 시작 클래스의 호출 순서를 숙지하고 있어야 합니다.

## 작업 단계

1. 시작 진입 파일 `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`를 엽니다. 프레임워크의 프로토콜 등록 및 시작 흐름이 이곳에 집중되어 있습니다.

2. 비즈니스 필요에 따라 `AppStartUpGame`에서 `UseServer` 또는 해당 확장 메서드를 호출하면서 `tcpOptions`, `wsOptions`, `httpOptions` 세 개의 설정 노드를 전달합니다. 노드 중 하나라도 생략하면 해당 프로토콜이 비활성화됩니다.

3. 설정 파일(기본 `App.Config.json` 또는 환경 변수로 덮어쓰기)에 다음 구조를 작성하면, 프레임워크가 시작 시 `Enable*` 스위치에 따라 해당 프로토콜의 리스닝 여부를 자동으로 결정합니다:

```json
{
  "Server": {
    "Tcp":    { "Enable": true,  "Host": "0.0.0.0", "Port": 30100 },
    "WebSocket": { "Enable": true, "Host": "0.0.0.0", "Port": 30101, "Path": "/" },
    "Http":   { "Enable": true,  "Host": "0.0.0.0", "Port": 30102 }
  }
}
```

4. `GameFrameX.Launcher`를 시작하면 실행 로그에 `Tcp Server Started`, `WebSocket Server Started`, `Http Server Started`와 같은 메시지가 나타나며, 세 개의 링크가 병렬로 리스닝 중임을 나타냅니다.

5. 임의의 비즈니스 코드에서 `INetSession` 또는 `HttpContext`를 통해 메시지를 처리하면, 프레임워크가 연결이 진입한 포트/경로에 따라 해당 프로토콜 채널로 자동 디스패치하므로 비즈니스 계층에서 프로토콜을 구분할 필요가 없습니다.

```csharp
// 메시지 핸들러 등록(TCP / WebSocket 공통)
[MessageHandler(MessageId.C2S_Login)]
public class C2S_LoginHandler : IMessageHandler
{
    public async Task HandleAsync(INetSession session, C2S_Login request)
    {
        // 비즈니스 로직
    }
}
```

## 일반적인 변형

- **TCP만 활성화**: `Tcp.Enable`을 `true`로 설정하고 나머지 두 항목을 `false`로 설정합니다. 주로 순수 게이트웨이 서버에 사용됩니다.
- **WebSocket + HTTP 공존**: H5 페이지는 WebSocket을 사용하고, 관리자 백오피스나 콜백 알림은 HTTP를 사용하며, 둘 다 동일한 프로세스와 동일한 Actor 세트를 공유합니다.
- **단일 프로토콜 비활성화**: 해당 노드의 `Enable`을 `false`로 설정하기만 하면 되며, 코드를 수정할 필요가 없습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 시작 시 `Address already in use` 오류 발생 | 여러 프로토콜이 동일한 포트를 사용하거나 다른 프로세스가 점유 중 | 각 프로토콜에 서로 다른 `Port`를 사용하고 OS 포트가 비어 있는지 확인 |
| WebSocket 클라이언트가 연결 후 즉시 끊김 | `Path` 또는 하위 프로토콜 불일치 | `Path`를 클라이언트 URL과 일치시킴(예: `ws://host:port/` ) |
| HTTP 인터페이스 404 | `Enable*` 설정이 주입되지 않았거나 컨트롤러 누락 | `Http.Enable=true`를 확인하고 컨트롤러가 등록되었는지 확인 |
| TCP는 연결되지만 메시지를 수신하지 못함 | 시작 순서 문제로 비즈니스 Actor가 등록되지 않음 | `AppStartUpHotfixGameByEntry` 등이 `AppStartUpGame`에 의해 순서대로 호출되는지 확인 |

## 배경(선택 사항)

`AppStartUpGame`은 `GameFrameX.StartUp`이 제공하는 통합 진입점을 통해 애플리케이션 서버 프로토콜 스택을 초기화하며, 동일한 메시지 라우팅과 세션( `INetSession` ) 추상화를 사용하여 세 가지 프로토콜을 처리합니다. 따라서 비즈니스 처리 계층(`Component/ServerComponent.cs` 참조)은 메시지 상호작용만 다루면 되고 기반 전송 방식은 신경 쓸 필요가 없습니다.

전체 시작 흐름과 `ServerComponent`에 대한 자세한 내용은 《Server 컴포넌트》를 참조하십시오.
