# プロシージャの書き方

本章では、カスタムの Procedure(プロシージャ)を記述し、`ProcedureComponent` に組み込んでフレームワーク起動後に自動的にそのプロシージャへ進入する方法を説明します。各 Procedure は `ProcedureBase` を継承し、有限状態機械(FSM)によって `ProcedureManager` がスケジューリングして実行します。

## 前提条件

- `com.gameframex.unity.procedure` パッケージがインストール済みで、シーンに `ProcedureComponent` が存在する(`GameFramework` 起動オブジェクトにアタッチされ、`[GameFrameXAutoComponent(-1000)]` で自動登録される)。
- `GameFrameX.Procedure.Runtime` と `GameFrameX.Fsm.Runtime` 名前空間が参照されている。
- `ProcedureBase` を継承する具象型が少なくとも 1 つ存在する。フレームワークは `Activator.CreateInstance` でリフレクションによりインスタンスを生成するため、プロシージャクラスには引数なしのコンストラクタが必要(省略可能なものも可)。

## 操作手順

### 1. プロシージャクラスを作成して ProcedureBase を継承する

`ProcedureBase` は `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>` を継承しており、`OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy` という 6 つのライフサイクルコールバックを公開しています。既定の実装はすべて空のため、必要に応じてオーバーライドしてください。

Source: [ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L30-L98)

最小限の使用例(ユニットテストの実装例を参考にしてください):

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

internal class ProcedurePreload : ProcedureBase { }

internal class ProcedureLogin : ProcedureBase { }

internal class ProcedureMain : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // アセット、設定、ホットアップデートなどの初期化
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // メインシーンのロジックへ進入
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // リソースの解放
    }
}
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L13-L40)

### 2. Inspector でプロシージャを登録する

シーン内の `ProcedureComponent` がアタッチされたオブジェクトを選択し、Inspector で以下を設定します:

- `Available Procedure Type Names`:利用可能なすべてのプロシージャ型の完全名(名前空間を含む)を入力します。例: `GameFrameX.Procedure.ProcedurePreload`、`GameFrameX.Procedure.ProcedureLogin`、`GameFrameX.Procedure.ProcedureMain`。
- `Entrance Procedure Type Name`:起動時のエントリープロシージャの型完全名を入力します。上記配列のいずれかと完全に一致している必要があります。一致しない場合、`Start()` コルーチンは `m_EntranceProcedure == null` のため直ちにリターンし、`Entrance procedure is invalid.` を出力します。

`ProcedureComponent.Start()` は上記設定に従ってリフレクションでプロシージャインスタンスを生成し、`ProcedureManager.Initialize(...)` と `StartProcedure(...)` を呼び出します。

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L51-L169)

### 3. プロシージャ内から次のプロシージャへ切り替える

各プロシージャ内では `procedureOwner` から所属の `IProcedureManager` を取得し、`procedureOwner.StartProcedure<T>()`(または `StartProcedure(typeof(T))`)を呼び出して次の状態へ切り替えます。例えば、`ProcedureLogin` のログイン完了後に `ProcedureMain` へ遷移する場合:

```csharp
protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
{
    base.OnEnter(procedureOwner);
    // ...ログイン成功ロジック...
    procedureOwner.StartProcedure<ProcedureMain>();
}
```

コンポーネント経由でもアクセスできます:

```csharp
GameEntry.GetComponent<ProcedureComponent>().StartProcedure(typeof(ProcedureMain));
```

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L202-L240)

### 4. StartupRunner で起動フローを引き継ぐ(任意)

プロジェクトが `ApplicationStartupEntry` + `StartupRunner.Run` という新しい起動方式を使用している場合、`ProcedureComponent` の `Use Startup Runner` を `true` にチェックする必要があります。この場合、`ProcedureComponent` は `Awake` 内で `IProcedureManager` を登録するのみとなり、`Initialize` と `StartProcedure` は呼び出しません。プロシージャのアセンブリおよびエントリープロシージャの起動は StartupRunner が担当し、`Initialize` の重複呼び出しによる `Already exist FSM` を回避します。

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L55-L127)

## よくあるバリエーション

| シーン | 実装方法 |
|------|------|
| コンポーネントを使用せず、`ProcedureManager` の API のみ利用 | `new ProcedureManager().Initialize(fsmManager, procs)` を呼び出してから `StartProcedure<T>()` を呼び出す |
| ポーリング(`OnUpdate`)が必要 | 対応するプロシージャクラスで `OnUpdate(IFsm<IProcedureManager>, float, float)` をオーバーライドする。フレームワークが毎フレームポーリングする |
| 固定間隔でのポーリングが必要 | `OnFixedUpdate(IFsm<IProcedureManager>, float, float)` をオーバーライドする |
| プロシージャ退出前にクリーンアップ | `OnLeave(IFsm<IProcedureManager>, bool isShutdown)` をオーバーライドし、`isShutdown` に応じて通常の切り替えか状態機械のシャットダウンかを区別する |
| 登録済みプロシージャインスタンスの確認/取得 | `HasProcedure<T>()` / `GetProcedure<T>()` を使用する |

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L41-L273)

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `You must initialize procedure first.` | `Initialize` 呼び出し前に `CurrentProcedure` / `StartProcedure` / `HasProcedure` / `GetProcedure` にアクセスした | まず `ProcedureManager.Initialize(fsmManager, procedures)` を呼び出してから上記の API にアクセスする |
| `ArgumentNullException`(引数が `fsmManager`) | `Initialize` に `null` を渡した | 有効な `IFsmManager`(例: `GameFrameworkEntry.GetModule<IFsmManager>()`)を渡す |
| `Procedures is invalid.` | `procedures` 配列が空 | 少なくとも 1 つのプロシージャインスタンスを渡す |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` が `Available Procedure Type Names` のどの項目とも一致しない | エントリープロシージャの型完全名が配列のいずれかの項目と厳密に一致するようにする |
| `Can not find procedure type '{0}'.` | 型完全名のスペルミス、または対応するアセンブリが読み込まれていない | 名前空間とアセンブリ参照を確認する |
| `Already exist FSM` | `ProcedureComponent` と `StartupRunner` の両方の起動フローが有効になっている | `ProcedureComponent` の `Use Startup Runner` を `true` に設定するか、StartupRunner で再度 `Initialize` を呼び出さないようにする |

## 背景(任意)

`ProcedureBase` は `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>` の薄いラッパーで、`ProcedureManager` は内部的に `IFsm<IProcedureManager>` としてこれらの状態を保持します。`ProcedureComponent` は既定で `Start()` コルーチン内でプロシージャインスタンスをリフレクションで生成し、`Initialize` を呼び出してからエントリープロシージャへ遷移します。`Use Startup Runner` が `true` の場合は `IProcedureManager` の登録のみを行い、初期化と起動は `ApplicationStartupEntry` が引き継ぎます。これはホットアップデートやリソース分包のシナリオに適しています。
