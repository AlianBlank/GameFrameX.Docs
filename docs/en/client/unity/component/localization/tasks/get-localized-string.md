# How to Get Localized Strings (with Formatting for 1–16 Arguments)

Use the `LocalizationComponent.GetString` series of overloads to retrieve localized strings by dictionary key; when formatting is needed, write standard .NET placeholders (`{0}`, `{1}`, …) in the dictionary value, then pass 1 to 16 arguments to the corresponding overload. If the key does not exist, `<NoKey>{key}` is returned; if the placeholders do not match the arguments, the result begins with `<Error>`.

## Prerequisites

- The `com.gameframex.unity.localization` package is installed in the project, and the `LocalizationComponent` in the scene has been initialized (dictionaries are loaded).
- The script imports the namespace `GameFrameX.Localization.Runtime` and obtains the component via `GameEntry`:

```csharp
using GameFrameX.Localization.Runtime;

// Standard approach: via GameEntry
var localization = GameEntry.GetComponent<LocalizationComponent>();
```

## Steps

1. **Get the component reference** (as in the code above, usually cached in `Start`).
2. **Simple retrieval**: pass only the key to get the raw translation for that key:

```csharp
// Simple key lookup
// If the key is not found, returns "<NoKey>{key}"
string okText = localization.GetString("UI.Button.OK");
string cancelText = localization.GetString("UI.Button.Cancel");

// Check whether the key exists before retrieval
if (localization.HasRawString("UI.Button.Confirm"))
{
    string confirmText = localization.GetString("UI.Button.Confirm");
}
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L133-L144)

3. **Formatted retrieval with arguments**: the dictionary value uses placeholders such as `{0}` and `{1}`; pass the arguments in order when calling.

```csharp
// Assume the dictionary contains:
// "UI.Message.Welcome" = "Welcome, {0}!"
// "UI.Info.Score"     = "Player {0} scored {1} points at level {2}!"
// "UI.Shop.Buy"       = "Buy {0} x {1} for {2} coins, discount {3:P}, total {4:C}"

// Using the params object[] overload
string welcome = localization.GetString("UI.Message.Welcome", playerName);

// Using the typed generic overload (recommended — value types avoid boxing)
string info = localization.GetString<string, int, int>("UI.Info.Score", playerName, score, level);

// Supports up to 16 typed arguments
string shopMsg = localization.GetString<string, int, int, float, decimal>(
    "UI.Shop.Buy", itemName, quantity, unitPrice, discount, total);
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L150-L165)

4. **Optional: read the raw translation directly**. Use `GetRawString` when you don't want to trigger formatting (returns `null` if the key does not exist):

```csharp
string rawText = localization.GetRawString("UI.Button.NewButton");
```

Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.md#L173-L192)

The component's `GetString` methods simply forward to the same-named methods on `m_LocalizationManager`; the actual signatures are as follows:

| Overload | Description |
|------|------|
| `public string GetString(string key)` | Retrieval without arguments |
| `public string GetString(string key, params object[] args)` | Any number of arguments (object array) |
| `public string GetString<T>(string key, T arg)` | 1 typed argument |
| `public string GetString<T1, T2>(string key, T1 arg1, T2 arg2)` | 2 typed arguments |
| `public string GetString<T1, …, T16>(string key, T1 arg1, …, T16 arg16)` | And so on, up to 16 typed arguments |

```csharp
[Preserve]
public string GetString(string key)
{
    return m_LocalizationManager.GetString(key);
}

[Preserve]
public string GetString(string key, params object[] args)
{
    return m_LocalizationManager.GetString(key, args);
}

[Preserve]
public string GetString<T>(string key, T arg)
{
    return m_LocalizationManager.GetString(key, arg);
}

[Preserve]
public string GetString<T1, T2>(string key, T1 arg1, T2 arg2)
{
    return m_LocalizationManager.GetString(key, arg1, arg2);
}
```

## Common Variants

- **Refresh text after a language switch**: switching `localization.Language` broadcasts a language-changed event; re-invoke `GetString` in the event callback to update UI text. For the complete approach to language switching and event listening, see "How to Switch the Runtime Language".
- **Add/remove entries at runtime**: `AddRawString` adds an entry (returns `false` if the key already exists or is empty), `RemoveRawString` deletes a single entry, `RemoveAllRawStrings` clears all entries, and `HasRawString` checks existence.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Result is in the `<NoKey>{key}` form | The key does not exist in the dictionary | Check with `HasRawString` first; confirm the dictionary is loaded and the key is spelled correctly |
| Result starts with `<Error>` and includes diagnostic information | Format-string placeholders do not match the passed arguments | Verify that `{0}`, `{1}`, … in the dictionary value match the number and order of the arguments |
| `GetRawString` returns `null` | The key does not exist | Same as `<NoKey>`; check the key and the dictionary loading status |
| The UI still shows the old language | Strings were not re-fetched after the language switch | Re-invoke `GetString` in the language-changed event callback |

## Verification

- No-argument call: call `GetString` on a known key (e.g., `UI.Button.OK`); the return value should equal the translation in the current language's dictionary, not `<NoKey>...`.
- Argument call: call `GetString<string, int, int>("UI.Info.Score", playerName, score, level)` on a key containing placeholders (e.g., `UI.Info.Score` = `"Player {0} scored {1} points at level {2}!"`); the return value should have the placeholders substituted and should not start with `<Error>`.

## Background

Each `GetString` overload on the component merely forwards to the same-named method on the internal `m_LocalizationManager`; the point of the generic overloads is to spare value-type arguments (`int`, `float`, etc.) from `object` boxing overhead, while the `params object[]` overload serves as a fallback when there are more than 16 arguments or the types cannot be known in advance. Formatting follows standard .NET composite format rules (`{0}`, `{3:P}`, `{4:C}`, etc.), so existing composite format strings can be used as-is.
