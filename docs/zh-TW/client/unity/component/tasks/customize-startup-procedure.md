# 如何在 Startup 流程中接入自訂 Procedure

在 `ApplicationStartupEntry` 呼叫 `StartupRunner.Run` 時，框架會按 `startupOptions.ProcedureSettings` 中設定的順序依序執行每一個 Procedure。本頁示範如何新增一個自訂 Procedure 並接入這條啟動鏈路。

## 前置條件

- 已存在 `Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs` 啟動入口。
- 專案中已引入 `GameFrameX.Startup.Runtime`(提供 `StartupRunner`、`ProcedureBase`、`IStartupUIHandler`)。
- `startupOptions` 資產已掛到 `ApplicationStartupEntry` 的檢視面板。

## 操作步驟

1. **建立自訂 Procedure 類別**，繼承 `ProcedureBase`,並實作 `OnEnter` / `OnLeave`(視情況覆寫 `OnUpdate`)。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   namespace GameFrameX.Startup.Application
   {
       /// <summary>
       /// 自訂啟動流程:登入遠端帳號服務,載入玩家基礎資料。
       /// </summary>
       public sealed class ProcedureLogin : ProcedureBase
       {
           protected override async UniTask OnEnter(ProcedureContext context)
           {
               // 進入流程:這裡寫你希望在啟動時執行的邏輯
               await LoginRemoteServiceAsync();
           }

           protected override UniTask OnLeave(ProcedureContext context)
           {
               // 離開流程:清理資源或狀態
               return UniTask.CompletedTask;
           }

           private UniTask LoginRemoteServiceAsync()
           {
               // 由業務端實作
               return UniTask.CompletedTask;
           }
       }
   }
   ```

   Source: [ApplicationStartupUIHandler.cs](Assets/Scripts/Framework/Procedure/ApplicationStartupUIHandler.cs#L1-L87)

2. **把 Procedure 註冊到 `StartupOptions`**。在 `startupOptions.ProcedureSettings` 清單中按執行順序加入 `ProcedureLogin`(類別名稱或類型識別碼需與框架約定一致，通常直接是 `Type` 或資源鍵)。

3. **(可選)自訂啟動 UI**。如果需要在啟動過程中更新 UI 提示，實作 `IStartupUIHandler` 並在入口處傳入：

   ```csharp
   var result = await StartupRunner.Run(
       startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   `IStartupUIHandler` 必須實作的成員:`StartAsync(uiResName)`、`SetTipText(text)`、`SetProgress(progress, sizeInfo)`、`SetProgressUpdateFinish()`、`ShowUpgradeAsync(upgradeInfo)`、`Dispose()`。

   Source: [ApplicationStartupEntry.cs](Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L14-L55)

4. **處理失敗回執**。`StartupRunner.Run` 回傳 `StartupResult`,透過 `Success`、`FailedProcedureName`、`FailedUrl`、`ErrorMessage` 欄位判斷哪個 Procedure 失敗並寫入日誌：

   ```csharp
   if (!result.Success)
   {
       Log.Error($"Startup failed. Procedure: {result.FailedProcedureName}, Url: {result.FailedUrl}, Error: {result.ErrorMessage}");
   }
   ```

   Source: [ApplicationStartupEntry.cs](Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L45-L48)

## 常見變體

| 場景 | 做法 |
|------|------|
| 只想加日誌或埋點 | 覆寫 `OnEnter` / `OnLeave`,內部只呼叫 `Log.Info`,不做 IO。 |
| 需要非同步等待網路結果 | 在 `OnEnter` 回傳 `UniTask`,內部 `await` 你的網路/資源載入方法。 |
| 啟動 UI 使用 FairyGUI / UGUI | 框架已透過 `ENABLE_UI_FAIRYGUI` / `ENABLE_UI_UGUI` 自動切換 `LauncherUIResName`,無需在 Procedure 裡處理。 |

## 常見錯誤

- **`startupOptions` 未指派**：啟動入口會在 `Log.Error("StartupOptions is not assigned.")` 後直接返回，Procedure 全部不會執行。
- **忘記實作 `OnLeave`**:若 `OnEnter` 進入了某種「啟動中」狀態，後續流程可能拿不到正確的上下文；至少回傳 `UniTask.CompletedTask`。
- **Procedure 順序錯亂**：把登入/資源校驗放到熱更新之前，會導致熱更新失敗時拿不到玩家上下文；按「初始化 → 熱更新 → 業務校驗 → 進入主場景」的順序排列。

## 背景(可選)

`StartupRunner.Run` 是框架啟動鏈路的統一入口，接收 `StartupOptions`、UI 處理器、熱修復啟動器三部分;`startupOptions.ProcedureSettings` 決定了 Procedure 鏈的拓撲與執行順序，所以接入工作實際上是宣告式設定，而不是改 `StartupRunner` 內部程式碼。
