# 集成 CocoaPods 依赖

在 Unity 导出 iOS 工程后,本包会根据 JSON 配置自动生成(或复制)Podfile、注入 `pod` 依赖,并在构建输出目录直接执行 `pod install`,全程无需手动打开终端。声明依赖有两种方式:在 `unityMain` / `unityFramework` 内写 `pods` 字段(推荐,逐条注入),或用 `podfile` 指定一份完整 Podfile 文件(设置后忽略 `pods`)。

## 前置条件

- 构建机为 macOS 且已安装 CocoaPods:`sudo gem install cocoapods`。未安装时会在日志中看到 `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)`。
- 工程已引入本包,并准备好 Xcode 配置 JSON(模板与示例随包提供:`Editor/XCodeConfigTemplate.json`、`Editor/XCodeConfigDemo.json`)。

## 操作步骤

1. 在配置 JSON 的 `unityMain`(主工程 target)或 `unityFramework`(UnityFramework target)块内添加 `pods` 字段。`key` 为 pod 名称,`value` 为版本约束,空字符串表示不约束:

   ```json
   "podSource": [
       "https://mirrors.tuna.tsinghua.edu.cn/git/CocoaPods/Specs.git"
   ],
   "podfile": "",
   "podInstall": true,
   ```

   顶层字段如上(Demo 中的真实取值);`pods` 则写在目标块内部,Demo 示例值如下:

   ```json
   "pods": {
       "Ads-CN-Beta": ", :subspecs => ['CSJMediation']"
   }
   ```

2. (可选)配置 `podSource` 使用国内镜像源加速 `pod install`;不配置时自动生成的 Podfile 会写入默认源 `https://github.com/CocoaPods/Specs.git`。

3. 触发 iOS 构建。构建后处理会按以下顺序落地 CocoaPods 配置:

   - `CopyPodfile`:若配置了 `podfile` 路径,直接把该文件复制到构建输出目录,之后仅重写其中的 `source` 行;
   - 否则走注入路径:`EnsurePodfileExists` 先保证 Podfile 存在(不存在则按当前 `PlayerSettings.iOS.targetOSVersionString` 生成骨架,为空时回退 `12.0`),再由 `AddPodsForTarget` 分别向 `Unity-iPhone` 和 `UnityFramework` 两个 target 注入 `pod` 行(自动跳过已存在的同名 pod);
   - 最后 `RunPodInstall` 在构建输出目录执行 `pod install`(可用 `"podInstall": false` 跳过)。

   ```csharp
   // PodFile
   var podSourceList = finalConfig.Get("podSource") as ArrayList;
   string podfileConfigPath = finalConfig.Get("podfile") as string;
   bool podfileCopied = CopyPodfile(path, podfileConfigPath);

   if (podfileCopied)
   {
       // 新路径：已复制完整 Podfile，仅需重写 source URL
       RunPodfile(path, podSourceList);
   }
   else
   {
       // 旧路径（向后兼容）：从 JSON 配置的 pods 字段逐行注入
       var mainPods = finalConfig.Get<Hashtable>("unityMain")?.Get<Hashtable>("pods");
       var frameworkPods = finalConfig.Get<Hashtable>("unityFramework")?.Get<Hashtable>("pods");
       if ((mainPods != null && mainPods.Count > 0) || (frameworkPods != null && frameworkPods.Count > 0))
       {
           EnsurePodfileExists(path, podSourceList);
           AddPodsForTarget(path, "Unity-iPhone", mainPods);
           AddPodsForTarget(path, "UnityFramework", frameworkPods);
       }
   }
   ```

4. 验证结果:查看 Unity Console 中的 `[Pods]` 与 `[PodInstall]` 前缀日志(如 `[Pods] 已为 Unity-iPhone 添加 N 个 pod 依赖`、`[PodInstall] pod install 完成`),并确认构建输出目录下生成了 `Podfile` 与 `Pods` 目录、`.xcworkspace` 可正常打开。

## 配置项速查

| 配置项 | 类型 / 默认值 | 说明 |
|------|------|------|
| `podSource` | `string[]` / 未配置时用 `https://github.com/CocoaPods/Specs.git` | 写入 Podfile 顶部的 `source` 源列表,可填国内镜像 |
| `podfile` | `string` / `""` | 完整 Podfile 文件路径,支持相对路径(基于 Unity 工程根目录,即 Assets 的上一级)与绝对路径;设置后忽略 `pods` |
| `podInstall` | `bool` / `true` | 是否在构建后自动执行 `pod install`,设为 `false` 可跳过 |
| `unityMain.pods` / `unityFramework.pods` | `object` / `{}` | key 为 pod 名称,value 为版本约束;空字符串表示无约束 |

## 版本约束写法

`pods` 的 value 按以下规则拼成 Podfile 中的 `pod` 行:

```csharp
// 构建 pod 行
foreach (DictionaryEntry kv in pods)
{
    var podName = kv.Key.ToString().Trim();
    if (existingPods.Contains(podName)) continue;

    var version = kv.Value?.ToString()?.Trim();
    if (string.IsNullOrEmpty(version))
    {
        podLines.Add($"  pod '{podName}'");
    }
    else if (version.Contains("=>") || version.StartsWith(":"))
    {
        podLines.Add($"  pod '{podName}', {version}");
    }
    else
    {
        podLines.Add($"  pod '{podName}', '{version}'");
    }
}
```

对应关系:`""` → `pod 'Name'`;含 `=>` 或以 `:` 开头(如 `:subspecs => [...]`、`:git => '...'`)→ 原样拼在逗号后不加引号;其余(如 `~> 1.0`)→ 自动补单引号变为 `pod 'Name', '~> 1.0'`。

## 常见变体

- **使用完整 Podfile**:依赖复杂时,把维护好的 Podfile 放到工程内,配置 `"podfile": "MyPodfile"`(相对 Unity 工程根目录)或绝对路径。复制成功后仅会重写其中的 `source` 行,其余内容原样保留;文件不存在时日志会给出 `[Pods] 配置指定的 Podfile 不存在: {src}` 并回退到 `pods` 注入路径。
- **跳过自动 pod install**:CI 需要自行控制安装时机时设置 `"podInstall": false`,构建后处理只生成/注入 Podfile,由流水线后续步骤执行 `pod install`。
- **私有源 / 多源**:`podSource` 是数组,可同时写入多个 `source` 行,例如同时保留官方 Specs 与私有仓库。

## 常见错误

| 现象(日志原文) | 原因 | 修复 |
|------|------|------|
| `[PodInstall] 未找到 pod 命令，请确认已安装 CocoaPods (sudo gem install cocoapods)` | 构建机未安装 CocoaPods,或 pod 不在常见路径(`.gem/ruby/bin`、Homebrew、`/usr/local/bin`、`/usr/bin`)且 `which pod` 解析失败 | 安装 CocoaPods;或将 pod 软链到 `/usr/local/bin/pod` 等可被探测的路径 |
| `[Pods] 配置指定的 Podfile 不存在: {src}` | `podfile` 路径写错或文件被移动 | 改为正确路径;相对路径基于 Unity 工程根目录(Assets 上一级) |
| `[Pods] 未找到 target '{targetName}' do, 跳过设置` | 自定义 Podfile 中 target 行格式不匹配(必须形如 `target 'Unity-iPhone' do`) | 修正 target 行写法,或直接用 `pods` 注入方式 |
| `[PodInstall] pod install 失败 (退出码: {code}): {error}` | pod 版本约束冲突、源不可达、Gem/Ruby 环境问题等 | 按 error 输出排查;可先用镜像源、必要时设置 `"podInstall": false` 手动执行 `pod install` 复现问题 |
| `当前不是Pod 项目结构,跳过设置` | 构建输出目录缺少 `Podfile` | 使用 `pods` 注入方式让其自动创建,或提供 `podfile` 配置 |

## 验证

- Unity Console 中依次出现 `修改PodFile 文件的源, 开始/结束`、`[Pods] ...`、`[PodInstall] 开始执行 pod install...` 与 `[PodInstall] pod install 完成`。
- 构建输出目录存在 `Podfile`(内容含配置的 `source` 行与各 target 的 `pod` 行)、`Pods/` 目录及 `Podfile.lock`。
- 打开生成的 `.xcworkspace`(而非 `.xcodeproj`),依赖库出现在 Pods 工程中且能编译通过。

## 背景

CocoaPods 相关逻辑集中在构建后处理的第二阶段,实现在 `PostProcessBuildHelper` 的分部类文件中:[PostProcessBuildHelper.PodFile.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.PodFile.cs#L19) 提供 `RunPodfile`(重写 source 行)、`EnsurePodfileExists`(生成骨架)、`CopyPodfile`(复制自定义 Podfile)、`AddPodsForTarget`(按 target 注入并去重)、`RunPodInstall` 与 `GetPodFullPath`;主流程在 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156) 中串联。执行 `pod install` 时会显式设置 `LANG` / `LC_ALL` 为 `en_US.UTF-8`(CocoaPods 对编码有要求),并解析 pod 的绝对路径(Unity 子进程不继承 shell PATH),这是常见"终端可用但构建时找不到 pod"问题的根因。关于 iOS 构建后处理的整体流程,见《iOS 构建后处理》。
