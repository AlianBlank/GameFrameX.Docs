# 如何分配模块 ID 与文件名

完成本页后,你可以为新的 Proto 模块正确分配唯一 ID、命名 .proto 文件,并在文件顶部声明 `option module = N;`,确保生成代码时多模块之间不会冲突。

## 前置条件

- 已安装 protobuf 编译器(`protoc`)或配套的代码生成脚本(仓库根目录下的 `Proto2CsExport_*.bat` / `Proto2CsExport_*.sh`、`Proto2GoExport.bat`、`Proto2CppExport.bat` / `Proto2CppExport.sh`)。
- 了解当前仓库已存在的模块前缀,避免重复。已存在的模块见下方"现有模块清单"。

## 命名规则(同时满足两个)

本仓库用**文件名**与 **`option module` 值**双重锁定模块 ID,二者必须一致:

1. **文件名**采用 `_<4 位数字>_<模块名>.proto`,例如 `_0010_Basic.proto`。
2. **文件首行 `option module = <数字>;`** 必须与文件名前缀数字相同(允许去掉前导 0)。

```protobuf
// 文件:_0010_Basic.proto
syntax = "proto3";
package Basic;
option module = 10;
```

Source: [_0010_Basic.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0010_Basic.proto#L1-L3)

```protobuf
// 文件:_0020_Common.proto
syntax = "proto3";
package Common;
option module = 20;
```

Source: [_0020_Common.proto](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/_0020_Common.proto#L1-L3)

## 操作步骤

1. **挑选未占用的模块 ID**。仓库按 10 为步长预留号段,每 100 段划给一个业务域。常用区间:
   - `0010–0099`:基础(Basic / Common / Bag / Social 等)
   - `0100–0199`:社交与公共
   - `0200–0299`:通用扩展
   - `0300–0399`:用户与属性
   - `0400–0499`:房间 / 玩法
   - `0500–0599`:邮件 / 系统功能

   同一号段内,新模块以 10 为步长递增(如已有 `_0010_Basic`、`_0020_Common`,下一个选 `_0030_xxx`)。

2. **按规则命名文件**。文件名前缀必须与所选 ID 数字一致(保留 4 位,前导补 0):

   ```
   _0030_<模块名>.proto
   ```

   `package` 字段使用 PascalCase 的模块名,与文件名主体保持一致。

3. **在文件第二行声明 package、第三行声明 module**。顺序固定为 `syntax` → `package` → `option module = N;`,N 与文件名前缀去掉前导 0 后相同:

   ```protobuf
   syntax = "proto3";
   package <ModuleName>;
   option module = 30;
   ```

4. **运行导出脚本验证**。根目录下选择对应语言的脚本(以 C# 客户端为例):

   ```bash
   ./Proto2CsExport_Client.sh
   ```

   生成无报错即代表模块 ID 与文件名已正确登记。

> 表中同一 `option module` 下允许多个文件并存(如 `_0120_Social.proto` 与 `_0120_Inner_Social.proto` 共用 120),用文件名后缀区分内部 / 外部消息。

## 常见变体

- **同号段多文件**:一个 `option module` 值可以对应多个 `.proto` 文件,文件名后追加 `_Inner_`、`_Client_`、`_Server_` 等以区分用途,但**前缀数字必须保持一致**。
- **跨语言导出**:`Proto2GoExport.bat`、`Proto2CppExport.bat`、`Proto2CsExport_Client.bat`、`Proto2CsExport_Server.bat` 分别面向不同输出场景,模块 ID 在所有脚本中通用。

## 常见错误

| 症状 | 原因 | 修复 |
|---|---|---|
| 生成时提示 `module ID 已存在` 或重复定义 | 文件名数字前缀与 `option module` 不一致 | 让二者数字部分相同(去掉前导 0 后) |
| 多个模块被合并到同一命名空间 | 不同文件复用了同一个 `option module` 但属于不同业务 | 检查前缀是否重复,或拆分子包后缀(如 `_Inner_`) |
| 客户端 / 服务端只生成一半消息 | 没有运行对应导出脚本 | `Proto2CsExport_Client.bat` 与 `Proto2CsExport_Server.bat` 各跑一次 |

## 背景(可选)

仓库用 10 的倍数分配模块 ID,使各业务域号段整齐划一;`_0120_Inner_Social.proto` 与 `_0120_Social.proto` 共用同一 module,只是借助文件名后缀区分消息边界,这与导出脚本解析目录的方式直接相关。
