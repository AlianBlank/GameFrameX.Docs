# SetActiveScene이 ArgumentException을 던지면 어떻게 해야 하나요

`SetActiveScene`을 호출할 때 전달된 `Scene`이 아직 Unity에서 실제로 로드가 완료되지 않았다면 Unity는 `ArgumentException`을 던집니다. 본 프레임워크는 이미 내부적으로 이를 캡처하여 완화 처리하지만(`Warning` 한 줄만 기록), 구독자나 커스텀 코드에서도 여전히 동일한 근본 원인에 부딪힐 수 있습니다. 아래에 원인 파악 및 수정 단계를 제시합니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| 로그에 `SetActiveScene failed (will be retried by Unity internally): Scene ... is not loaded.`가 나타남 | `Scene.isLoaded`가 여전히 `false`인 상태에서 `SetActiveScene`을 호출함(전형적인 상황: YooAsset의 `await` 완료 시점이 Unity의 실제 로드 완료보다 빠름) | 씬이 실제로 `isLoaded == true`가 된 후에 활성화할 것, 아래「isLoaded 대기」 참조 |
| 활성화하려는 것이 캐시된 `m_GameFrameworkScene` 핸들이지만 해당 씬이 이미 Unity에 의해 언로드됨 | 첫 번째 Single 로드 후 프레임워크 씬이 언로드되어 캐시된 핸들의 `IsValid()`가 `false`임 | 다시 `GetSceneByName`으로 핸들을 가져와 활성화할 것, 아래「핸들 무효화」 참조 |
| 콘솔에서 `ArgumentException: SceneManager.SetActiveScene ... is not loaded` 발생 | 커스텀 코드가 `SceneManager`에서 직접 호출하여 프레임워크의 try/catch를 우회함 | 프레임워크 진입점을 사용하거나 직접 방어 코드를 추가할 것, 아래「프레임워크를 우회한 직접 호출」 참조 |
| 연속으로 씬을 전환할 때 이전 코루틴과 새 코루틴이 `SetActiveScene`을 서로 차지하려 다툼 | 이전 갱신 코루틴이 중지되지 않은 채 새 코루틴이 다시 시작됨 | 새 코루틴 시작 전에 먼저 `StopCoroutine`할 것, 아래「코루틴 충돌」 참조 |

## 수정 단계

### isLoaded 대기

프레임워크는 `SceneComponent.SetActiveScene`에서 이미 `ArgumentException`을 try/catch로 처리하지만, 직접 `LoadSceneSuccess` 이벤트를 구독한 콜백에서는 여전히 마주칠 수 있습니다. 대상 씬이 `isLoaded`인지 확인한 후 설정하세요:

```csharp
var scene = UnityEngine.SceneManagement.SceneManager.GetSceneByName(sceneName);
if (scene.IsValid() && scene.isLoaded)
{
    UnityEngine.SceneManagement.SceneManager.SetActiveScene(scene);
}
```

현재 프레임에서 아직 `isLoaded`가 아니라면, 코루틴으로 다음 프레임으로 지연한 뒤 다시 시도하고, 타임아웃 시 프레임워크 씬으로 폴백하세요 —— [SceneComponent.cs#L480-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L480-L509)의 `RefreshSceneOrderWhenLoadedCo` 구현을 참고하세요.

### 핸들 무효화

캐시된 `Scene` 핸들은 `Single` 모드에서 이전 씬과 함께 Unity에 의해 언로드됩니다. 프레임워크는 [SceneComponent.cs#L449-L457](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L449-L457)에서 `IsValid()`로 방어합니다:

```csharp
if (!activeScene.IsValid())
{
    // 핸들이 만료된 경우 설정을 건너뛰며, Unity는 새 Single 씬 로드 완료 후 자체적으로 활성화함
    RefreshMainCamera();
    return;
}
```

자신의 코드에서 `Scene` 핸들을 재사용할 때는 호출 전에 동일하게 `IsValid()`를 검증해야 하며, 그렇지 않으면 다시 `GetSceneByName`을 호출해야 합니다.

### 프레임워크를 우회한 직접 호출

구독자 콜백에서 `UnityEngine.SceneManagement.SceneManager.SetActiveScene`을 직접 호출하지 마세요. 프레임워크의 예외 처리 로직을 우회하게 됩니다. 프레임워크 진입점인 `GameSceneComponent.SetActiveScene` 같은 메서드를 우선 사용하세요. 반드시 이벤트 콜백에서 활성 씬을 전환해야 한다면 직접 try/catch로 감싸고 위의「isLoaded 대기」판단에 따라 진행하세요.

### 코루틴 충돌

씬을 연속으로 여러 번 전환할 때 이전 갱신 코루틴을 먼저 중지하지 않으면, 이전 코루틴과 새 코루틴이 같은 프레임에서 `SetActiveScene`을 두고 다투어 `ArgumentException`이 발생합니다. 프레임워크의 수정 패턴은 [SceneComponent.cs#L430-L435](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L430-L435)을 참고하세요:

```csharp
if (m_RefreshSceneOrderCo != null)
{
    StopCoroutine(m_RefreshSceneOrderCo);
    m_RefreshSceneOrderCo = null;
}
m_RefreshSceneOrderCo = StartCoroutine(RefreshSceneOrderWhenLoadedCo(maxSceneName));
```

`finally` 블록에서 핸들을 `null`로 설정하는 것을 잊지 마세요([SceneComponent.cs#L505-L509](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L505-L509) 참조). 다음 번 `RefreshSceneOrder`가 이전 코루틴이 아직 실행 중이라고 잘못 판단하는 것을 방지하기 위함입니다.

## 검증

- 로그에 더 이상 `ArgumentException: SceneManager.SetActiveScene ... is not loaded`가 나타나지 않습니다.
- 로드 콜백이 반환될 때 `SceneManager.GetActiveScene()`이 대상 씬과 일치합니다.
- 씬 전환을 연속으로 두 번 트리거해도 콘솔에 `SetActiveScene failed` 경고가 없습니다.
