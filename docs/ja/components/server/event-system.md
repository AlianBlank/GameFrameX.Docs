# イベントシステムを使用したモジュール間の疎結合化

イベントシステムを使用することで、モジュール間が直接互いを参照する必要がなくなり、イベントの定義、イベントの発行、独立したリスナーによる処理を行うだけで、疎結合を実現できます。このページでは、イベントの定義方法、リスナーの作成方法、イベントのディスパッチ方法について説明します。

## 前提条件

- C# のジェネリックと非同期プログラミング(`async`/`await`)を理解していること。
- プロジェクトが `GameFrameX.Core.Abstractions.Events` と `GameFrameX.Core.Events` を参照していること。
- Actor とコンポーネントプロキシの基本概念を理解していること(Actor モジュールのドキュメントを参照)。

## コアコンセプト早見表

| 名前 | 型 | 役割 |
|------|----------|------|
| `GameEventArgs` | `GameFrameX.Core.Abstractions.Events.GameEventArgs` | イベント引数の基底クラス。すべてのカスタムイベント引数はこれを継承する必要があります |
| `IEventListener` | `GameFrameX.Core.Abstractions.Events.IEventListener` | リスナーインターフェース。`HandleEvent` メソッドを定義します |
| `EventListener<T>` | `GameFrameX.Core.Events.EventListener<T>` | リスナーの抽象基底クラス。特定のコンポーネントプロキシ(`T : IComponentAgent`)に対してイベントを処理できます |
| `EventDispatcher.Dispatch` | `GameFrameX.Core.Events.EventDispatcher` | 静的エントリポイント。指定した Actor またはグローバルリスナーにイベントを発行します |

## 操作手順

### 1. イベント引数の定義

`GameEventArgs` を継承するクラスを作成し、イベントデータを保持します。`GameEventArgs` 自体は `System.EventArgs` を継承しているだけで、フィールドは含まれていません。

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class PlayerLoginEventArgs : GameEventArgs
{
    public long PlayerId { get; }
    public DateTime LoginTime { get; }

    public PlayerLoginEventArgs(long playerId)
    {
        PlayerId = playerId;
        LoginTime = DateTime.UtcNow;
    }
}
```

### 2. リスナーの実装

実装方法は2つあります:`IEventListener` を直接実装するか、ジェネリック基底クラス `EventListener<T>(T : IComponentAgent)` を継承します。

**書き方 A:`EventListener<T>` を継承(推奨、コンポーネントプロキシにアクセスする必要がある場合)**

```csharp
using GameFrameX.Core.Events;

public sealed class PlayerLoginListener : EventListener<PlayerComponentAgent>
{
    protected override async Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        if (gameEventArgs is not PlayerLoginEventArgs args) return;
        // コンポーネントプロキシを通じてコンポーネント状態にアクセス
        var player = agent.GetPlayer();
        await player.OnLogin(args.LoginTime);
    }
}
```

`EventListener<T>` は、渡された `IComponentAgent` を自動的にジェネリック `T` に変換し、内部で実装された `HandleEvent(T agent, GameEventArgs)` を呼び出します。

**書き方 B:`IEventListener` を直接実装(コンポーネントプロキシにアクセスする必要がない場合)**

```csharp
using GameFrameX.Core.Abstractions.Events;

public sealed class GlobalStartupListener : IEventListener
{
    public Type AgentType => null;
    public Task HandleEvent(IComponentAgent agent, GameEventArgs gameEventArgs)
        => HandleEvent(gameEventArgs);

    public Task HandleEvent(GameEventArgs gameEventArgs)
    {
        // グローバルイベントの処理ロジック
        return Task.CompletedTask;
    }
}
```

リスナーはフレームワークにより**シングルトン**として管理されるため、実装はスレッドセーフを保証する必要があります。

### 3. リスナーの登録

リスナーは、フレームワークが `GameFrameX.Hotfix` アセンブリをスキャンすることで自動登録されます。通常、`GameFrameX.Hotfix` プロジェクト配下に配置すれば自動的に検出されます。命名はプロジェクトアーキテクチャのルールに従う必要があります(`EventListener` を接尾辞とし、具体的な制約は `GameFrameX.Architecture.Analyzers` によって強制チェックされます)。

### 4. イベントの発行

静的クラス `EventDispatcher.Dispatch` を呼び出し、対象の ActorId、イベント ID、イベント引数を渡します。actorId に対応する Actor が存在しない場合、イベントは自動的に**グローバルリスナー**に配信されます。

```csharp
using GameFrameX.Core.Events;

// actorId に対応する Actor コンテキスト内でイベントを発行
EventDispatcher.Dispatch(playerActorId, EventId.PlayerLogin, new PlayerLoginEventArgs(playerId));
```

イベント ID は `int` 型の定数を使用し、通常 `GameFrameX.Apps/Common/Event/EventId.cs` に集約して定義します。

## よくあるバリエーション

| シナリオ | 書き方 |
|------|------|
| プレイヤーレベルのイベント(プレイヤークリップへのアクセスが必要) | `EventListener<PlayerComponentAgent>` を継承し、`HandleEvent(T, GameEventArgs)` をオーバーライド |
| グローバル/サーバーレベルのイベント | `IEventListener` を実装し、プロキシなしバージョン `HandleEvent(GameEventArgs)` を使用 |
| 引数なしイベントの監視 | イベント引数は `GameEventArgs` を継承するが、フィールドは一切持たない |

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `NoListenersFound` 警告が表示される | そのイベント ID に登録されたリスナーがない | リスナークラスが `GameFrameX.Hotfix` アセンブリにあり、命名がアナライザーのルールに準拠していることを確認 |
| `HandleEvent` が受け取るイベント引数が別の型になっている | イベントが誤って別のイベント ID にディスパッチされている | 集約定義された `EventId` 定数を使用し、ハードコードされたマジックナンバーを避ける |
| リスナーの複数インスタンスで状態が共有され並行性問題が発生する | リスナーはシングルトンだが、内部状態がスレッドセーフに保護されていない | 可変状態をローカル変数に変更するかロックし、リスナーにリクエストレベルのデータを保持しない |

## 背景(オプション)

イベントディスパッチは Actor コンテキスト内では**シリアル**に実行され(`foreach` + `await`)、同一 Actor 内のイベントが並行実行されないことを保証します。Actor が存在しない場合は、新しいスレッドでグローバルリスナーにディスパッチされます。各リスナーの例外は `LogHelper.Error` で捕捉・記録され、他のリスナーの処理が中断されることはありません。詳細は [EventDispatcher.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Events/EventDispatcher.cs#L50-L135) を参照してください。
