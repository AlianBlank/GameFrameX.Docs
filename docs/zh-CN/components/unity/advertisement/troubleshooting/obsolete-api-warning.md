# 旧 API 编译警告怎么办

代码里调用了带 `[Obsolete]` 标记的接口时,Unity 编译器会在控制台输出 `CS0618` 警告,并提示替代 API。本页告诉你怎样快速定位这些调用、并切换到新 API。

## 快速诊断

| 警告原文 | 触发的旧 API | 推荐替代 |
|---|---|---|
| `Use Initialize(AdvertisementConfig) instead.` | `AdvertisementComponent.Initialize(string adUnitId, bool isDebug)`、`IAdvertisementManager.Initialize(...)`、`BaseAdvertisementManager.Initialize(...)` | `Initialize(AdvertisementConfig config)` |
| `Use Play(AdvertisementPlayOption) instead.` | `AdvertisementComponent.Show(Action<string>, Action<string>, Action<bool>)`、`AdvertisementComponent.Play(Action<bool>, string)` 及 `IAdvertisementManager` / `BaseAdvertisementManager` 中对应的多个 `Play` 重载 | `Play(AdvertisementPlayOption option)` |

`[Obsolete]` 标记的真实位置见 [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L150-L191)、[IAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/IAdvertisementManager.cs#L62-L122)、[BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L144-L236)。

## 修复步骤

### 1. 把 `Initialize(string, bool)` 替换为 `Initialize(AdvertisementConfig)`

旧签名只接收广告位 ID 和调试开关;新签名接收一个 `AdvertisementConfig` 派生配置对象,可承载更多参数(子类由具体广告 SDK 实现提供,如 `PangleAdvertisementConfig` 等)。

```csharp
// 旧写法 —— 会触发 CS0618
[Obsolete("Use Initialize(AdvertisementConfig) instead.")]
adComponent.Initialize("ad-unit-id-xxx", isDebug: true);

// 新写法
var config = new MyAdSdkConfig // 具体子类由使用的广告 SDK 提供
{
    adUnitId = "ad-unit-id-xxx",
    isDebug = true,
};
adComponent.Initialize(config);
```

`AdvertisementConfig` 基类定义见 [AdvertisementConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementConfig.cs#L41-L53)。

### 2. 把 `Show` / 多参数 `Play` 替换为 `Play(AdvertisementPlayOption)`

旧的 `Show(success, fail, onShowResult)` 和 `Play(onShowResult, customData)` 都用分散参数;新接口把所有回调和扩展数据集中到 `AdvertisementPlayOption` 对象里。

```csharp
// 旧写法 —— 会触发 CS0618
[Obsolete("Use Play(AdvertisementPlayOption) instead.")]
adComponent.Show(
    success: info => Debug.Log($"成功:{info}"),
    fail: err => Debug.LogError($"失败:{err}"),
    onShowResult: shown => Debug.Log($"展示:{shown}"));

// 新写法
var option = new AdvertisementPlayOption
{
    OnSuccess = info => Debug.Log($"成功:{info}"),
    OnFail = err => Debug.LogError($"失败:{err}"),
    OnShowResult = shown => Debug.Log($"展示:{shown}"),
    customData = "reward-key-001",
};
adComponent.Play(option);
```

`AdvertisementPlayOption` 字段定义见 [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L80)。

### 3. 临时必须保留旧调用时,局部抑制 CS0618

框架内部在转发旧调用时已经这么做了:

```csharp
#pragma warning disable CS0618
_advertisementManager.Initialize(AdUnitId, isDebug);
#pragma warning restore CS0618
```

仅在迁移期、对极少数无法立刻替换的外部依赖点使用 `#pragma warning disable CS0618`,并尽快在新版本中移除。

## 验证

1. 在 Unity 中 `Clear` 控制台,触发一次广告初始化与播放。
2. 确认控制台不再出现 `CS0618` 关于 `Use Initialize(AdvertisementConfig) instead.` 或 `Use Play(AdvertisementPlayOption) instead.` 的告警。
3. 跑一次完整的「初始化 → 播放 → 回调」流程,确认 `OnSuccess` / `OnFail` / `OnShowResult` 都被正常触发。
