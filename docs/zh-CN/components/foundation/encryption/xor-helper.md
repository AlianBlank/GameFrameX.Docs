# 如何使用 XOR 简单加解密

`XorHelper` 提供基于异或运算的轻量级加解密工具,使用相同密钥对数据做两次 XOR 即可还原原文,适合做配置文件、内存中临时字节流的简单混淆。注意:它不是密码学安全方案,不能用于需要保密性的场景。

## 前置条件

- 引用 NuGet 包 `GameFrameX.Foundation.Encryption`(或直接引用 `GameFrameX.Foundation.Encryption/XorHelper.cs`)。
- 使用 `using GameFrameX.Foundation.Encryption;` 引入命名空间。

## 操作步骤

### 1. 最简加密与解密

调用 `XorHelper.GetXorBytes(byte[], byte[])` 完成一次 XOR,再用同一密钥调用一次即可解密。两次调用完全对称,无加密 / 解密方法之分。

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

var keyBytes = Encoding.UTF8.GetBytes("MySecretKey123");
var dataBytes = Encoding.UTF8.GetBytes("Hello, World! 这是一个测试字符串。");

// 加密
var encrypted = XorHelper.GetXorBytes(dataBytes, keyBytes);
// 解密(用同一密钥再调用一次)
var decrypted = XorHelper.GetXorBytes(encrypted, keyBytes);

Console.WriteLine(Encoding.UTF8.GetString(decrypted)); // 输出原文
```

Source: [XorHelper.cs#L133-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L133-L144)

### 2. 选择"原地修改"版本节省内存

如果输入数组后续不再需要保留原文,使用 `GetSelfXorBytes` 直接改写输入数组,不会额外分配一份新字节流。

```csharp
var dataBytes = Encoding.UTF8.GetBytes("payload");
var keyBytes = Encoding.UTF8.GetBytes("key");

// 直接在 dataBytes 上做 XOR,不返回新数组
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
// 再调用一次还原
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
```

Source: [XorHelper.cs#L158-L169](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L158-L169)

### 3. 只加密数据的前 220 字节(快速模式)

需要在大字节流(如协议包头)上做轻量混淆,但不想遍历整个数组时,使用 `GetQuickXorBytes` / `GetQuickSelfXorBytes`。两者都只对前 `QuickEncryptLength`(默认 220)字节做 XOR,超出部分保持原值不变。

```csharp
var buffer = new byte[1024];           // 协议头 + 后续负载
var key = Encoding.UTF8.GetBytes("k");

// 只混淆前 220 字节,后续字节原样保留
var encrypted = XorHelper.GetQuickXorBytes(buffer, key);
// 还原时同样只处理前 220 字节
var restored = XorHelper.GetQuickXorBytes(encrypted, key);
```

Source: [XorHelper.cs#L76-L90](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L76-L90), [XorHelper.cs#L104-L118](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L104-L118)

### 4. 只加密数组中的某一段

使用带 `startIndex` 和 `length` 参数的重载,可以只对指定范围做 XOR,适用于"只混淆头部 / 中间某段"等场景。

```csharp
var data = new byte[] { 1, 2, 3, 4, 5, 6, 7, 8 };
var key  = Encoding.UTF8.GetBytes("MySecretKey123");

// 只加密索引 2 开始的 4 个字节
var result = XorHelper.GetXorBytes(data, 2, 4, key);
// data[0..2] 与 data[6..8] 保持不变
```

## 常用方法速查

| 方法 | 是否分配新数组 | 加密范围 | 适用场景 |
|------|----------------|----------|----------|
| `GetXorBytes(bytes, code)` | 是 | 整个数组 | 常规加解密,需要保留原文 |
| `GetSelfXorBytes(bytes, code)` | 否(原地修改) | 整个数组 | 不再需要原文,省一次分配 |
| `GetQuickXorBytes(bytes, code)` | 是 | 前 220 字节 | 大包头快速混淆 |
| `GetQuickSelfXorBytes(bytes, code)` | 否 | 前 220 字节 | 大包头原地快速混淆 |
| `GetXorBytes(bytes, startIndex, length, code)` | 是 | 指定区间 | 仅混淆头部/中间段 |
| `GetSelfXorBytes(bytes, startIndex, length, code)` | 否 | 指定区间 | 仅混淆头部/中间段,原地 |

## 常见变体

### 密钥比数据长 / 比数据短 / 单字符密钥

XOR 算法对密钥长度没有限制,长短均能正确加解密。测试覆盖了单字符、3 字节、14 字节、34 字节等不同密钥,只要密钥非空即可往返还原。

Source: [XorHelperTests.cs#L82-L116](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Encryption/XorHelperTests.cs#L82-L116)

### 字符串往返

直接把字符串 `Encoding.UTF8.GetBytes` 后传入,再把结果 `Encoding.UTF8.GetString` 回来,适用于配置文件中的敏感字段。

## 常见错误

| 错误做法 | 现象 | 正确做法 |
|----------|------|----------|
| 把 `GetXorBytes` 返回结果当作新数组再次修改 | 混淆范围错位 | 用 `GetXorBytes` 返回值,或显式 `Array.Copy` 后再传 `GetSelfXorBytes` |
| 给 `code` 传 `Array.Empty<byte>()` | 抛 `ArgumentException("KeyArrayCannotBeEmpty")` | 使用至少 1 字节的密钥 |
| 用 `GetQuickXorBytes` 处理 220 字节内的完整数据时,以为超出部分也被加密 | 数据后半段原样保留 | 需要整体加密请用 `GetXorBytes` |
| `startIndex + length` 超过数组长度 | 抛 `ArgumentOutOfRangeException` | 先校验 `startIndex + length <= bytes.Length` |
| 用作账号密码 / 传输密钥 | 已知明文攻击可轻易破解 | 仅用于防意外读取的混淆;保密场景请用真正的对称加密算法 |

## 背景(可选)

XOR 运算天然满足 `(A ^ K) ^ K == A`,因此同一接口既可加密也可解密。`QuickEncryptLength = 220` 是为协议头场景设置的经验值,在安全性和性能间取的折中。所有公开方法都先做 `ArgumentNullException.ThrowIfNull` 与 `code.Length == 0` 校验,带 offset/length 的重载还校验 `startIndex + length <= bytes.Length`。
