# ローカライズテキストが反映されない場合の対処法

`GameApp.Localization.GetString(key)` を呼び出した場合や、FairyGUI/UI コンポーネントから多言語テキストを検索した際に、依然として古い言語文字列や Key 自身、あるいは空の値が返ってくる場合は、ローカライズデータが現在の `GameApp.Localization.Language` に応じてロードされていないことを意味します。本ページでは、よくある原因、対応する診断方法、修正手順について説明します。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GetString(key)` を呼び出すと Key 文字列自体が返される | 設定テーブルの `Key` フィールドが空、または未生成 | `local_tblocalization.json` の `key` 列が記入されているか確認し、設定コードを再生成する |
| `Language` を切り替えてもテキストが変化しない | `TranslateText()` が呼ばれていない、または呼び出し順序が正しくない | 起動フロー内で、まず `Config.GetConfig<TbLocalization>()` を呼び、その後 `TranslateText()` を呼び出す |
| `AddRawString` 呼び出し時に `SerializationException` が発生 | 設定テーブル JSON と生成された `Localization` フィールドが一致していない | LuBan で `local_tblocalization.json` を再エクスポートし、15 個すべての言語フィールドが揃っていることを確認する |
| 一部の言語(タイ語、インドネシア語など)が常に空 | その言語分岐が `switch` で処理されていない、またはテーブルのフィールドが空 | `local_tblocalization.json` に対応する言語列を補完するか、`Localization.cs` ジェネレーターに分岐を追加する |
| 実行後にすべてのローカライズ文字列が英語になる | `DefaultLanguage == English` かつ `Language` が switch 分岐にない | `GameApp.Localization.Language` が上の分岐にヒットしていることを確認するか、default 分岐のフォールバック処理を拡充する |

## 修正手順

### 1. 起動フローで `TranslateText` が呼ばれているか確認する

`TranslateText()` は `TbLocalization` テーブルの多言語フィールドを現在の言語に従って基底の辞書に書き込む役割を担います。これをスキップすると何も値を取得できません。

```csharp
// 1. ソースデータを削除
GameApp.Localization.RemoveAllRawStrings();
// 2. 設定テーブルからデータをロード
var tbLocalization = GameApp.Config.GetConfig<TbLocalization>();
// 3. データ情報をロード
tbLocalization.ForEach(localization =>
{
    if (localization.Key.IsNullOrWhiteSpace())
    {
        return;
    }
    // ... switch GameApp.Localization.Language ...
    GameApp.Localization.AddRawString(localization.Key, value);
});
```

Source: [HotfixLauncher.cs#L66-L164](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L66-L164)

注意:Key が空白の行は直接 `return` され、辞書には書き込まれません。設定テーブルに戻って Key を補完してください。

### 2. 現在の言語が switch 分岐に含まれているか確認する

生成された `Localization` エンティティには 15 個の言語フィールドがあり、ローダーは `LocalizationCode` 列挙型を一つずつ照合します。照合されなかった言語は `default` に落ち、`DefaultLanguage == English` の場合にのみ英語を取得し、その他の場合は `string.Empty` のままとなります。

```csharp
case LocalizationCode.ChineseSimplified:
    value = localization.ChineseSimplified;
    break;
case LocalizationCode.English:
    value = localization.English;
    break;
// ... ChineseTraditionalTW / HK / French / German / Italian / Japanese /
//     Korean / Portuguese* / Spanish* / Thai / Vietnamese / Russian / Indonesian
default:
{
    if (GameApp.Localization.DefaultLanguage == LocalizationCode.English)
    {
        value = localization.English;
    }
}
    break;
```

Source: [HotfixLauncher.cs#L82-L161](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L82-L161)

ターゲット言語が上記分岐のいずれにも含まれていない場合(例えば新たにアラビア語を追加した場合)は、以下の対応が必要です:

1. LuBan テーブル `local_tblocalization.json` に対応する列を追加する。
2. `Localization.cs` を再生成し、新しいフィールドをコンストラクタと JSON 解析に含める。
3. `HotfixLauncher.TranslateText` の switch に `case` を追加し、フィールドを `value` にマッピングする。

### 3. 設定テーブルと生成コードが同期しているか確認する

生成された `Localization` コンストラクタは各フィールドに対して非文字列の検証を行います。フィールドが欠けていると逆シリアル化で `SerializationException` がスローされ、テーブル全体のロードが失敗します。

```csharp
public Localization(JSONNode _buf)
{
    { if(!_buf["key"].IsString) { throw new SerializationException(); }  Key = _buf["key"]; }
    { if(!_buf["ChineseSimplified"].IsString) { throw new SerializationException(); }  ChineseSimplified = _buf["ChineseSimplified"]; }
    { if(!_buf["English"].IsString) { throw new SerializationException(); }  English = _buf["English"]; }
    // ... 他の 12 言語も同様の検証
}
```

Source: [Localization.cs#L38-L59](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Local/Localization.cs#L38-L59)

修正方法:LuBan エディターで `local_tblocalization.json` を開き、15 個の言語フィールド名(ChineseSimplified、ChineseTraditional、English、Japanese、Korean、Thai、Indonesian、French、German、Russian、Italian、PortuguesePortugal、Spanish、Vietnamese)および `key` 列がすべて存在し、かつ文字列型であることを確認してから、コードを再生成してください。

### 4. 言語切り替え後に強制的に UI を再描画する

単に `GameApp.Localization.Language` を変更するだけでは設定は再読み込みされません。辞書の古い値を上書きするには、`TranslateText()` を再度実行する必要があります。一般的な方法としては、言語切り替えイベントでこのメソッドを呼び出し、続いて UI レイヤーに `OnLanguageChanged` をブロードキャストします。

## 検証

以下の順序で確認し、問題が解決されたことを確認してください:

1. ゲームを実行し、コンソールで `tbLocalization` の行数が 0 より大きく、`SerializationException` が発生していないことを確認する。
2. スクリプト内で一時的に `GameApp.Localization.GetString("あなたの設定テーブル内の Key")` を呼び、ブレークポイントで Key 自体ではなく現在の `Language` に対応する文字列が返されることを確認する。
3. FairyGUI/UGUI のローカライズコンポーネントを通じて、Key を使ったテキストノードを開き、実行時に表示される値を確認する。
4. `GameApp.Localization.Language = LocalizationCode.English`(または他の言語)に切り替え、再び `TranslateText()` を呼び出し、UI テキストが切り替えに応じて更新されることを再度確認する。

## よくあるエラー

- `local_tblocalization.json` を直接編集した後、LuBan の「コード生成」ボタンをクリックするのを忘れ、実行時にコード内のフィールド名が一致せず、逆シリアル化時に静かに失敗する。
- `TranslateText()` が `Awake` 内で呼び出されるように書かれているが、この時点では `GameApp.Config` がまだ初期化されておらず、`GetConfig<TbLocalization>()` が null を返す。
- テーブル内に Key を中国語/空白を含む文字列で記述しており、合法ではあるものの呼び出し側で Key を渡す際に記述ミスをしやすいため、統一して英数字 + アンダースコアの使用を推奨。
- `default` 分岐で英語のフォールバックに依存しているが、`DefaultLanguage` が `English` ではないため、一部の言語が空文字列として表示される。
