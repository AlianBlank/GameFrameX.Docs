# 如何在状态之间切换

在任意继承 `FsmState<T>` 的状态类中调用 `ChangeState<TState>(fsm)` 即可立刻切换当前 FSM 的活动状态，框架会按顺序触发当前状态的 `OnLeave` 与新状态的 `OnEnter`。

## 前置条件

- 已通过 `FsmComponent.CreateFsm(...)` 或 `GameApp.Fsm.CreateFsm(...)` 创建好目标 FSM，且要切换的目标状态已作为参数传入。
- 目标状态类型必须继承 `FsmState<T>`，其中 `T` 与 FSM 的泛型参数一致。

## 操作步骤

1. **在状态类内部触发切换**：从 `FsmState<T>` 派生类内部调用受保护的 `ChangeState<TState>(IFsm<T> fsm)`。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

2. **需要从状态外部触发时**：可使用 `FsmState<T>` 上的公开方法 `ChangeToState<TState>(IFsm<T> fsm)`，它内部转发到 `ChangeState<TState>(fsm)`。

   ```csharp
   fsm.CurrentState.ChangeToState<MoveState>(fsm);
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L119)

3. **只知道目标状态类型时**：使用按 `Type` 重载，传入状态类的运行时类型。

   ```csharp
   ChangeState(fsm, typeof(MoveState));
   ```

   该重载会校验传入的 `Type` 是否可赋值给 `FsmState<T>`，否则抛出 `GameFrameworkException("State type '{0}' is invalid.")`。  
   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

4. **内部执行流程**：调用 `Fsm<T>.ChangeState(Type)` 时，框架先调用旧状态的 `OnLeave(this, false)`、重置 `m_CurrentStateTime`、替换 `m_CurrentState`，再调用新状态的 `OnEnter(this)`。

   ```csharp
   m_CurrentState.OnLeave(this, false);
   m_CurrentStateTime = 0f;
   m_CurrentState = state;
   m_CurrentState.OnEnter(this);
   ```

   Source: [Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L726-L729)

## 常见变体

- **按字符串名称切换**：先通过 `FsmComponent.HasState<T>(name)` 等命名 API 找到状态，再使用 `Type` 重载切换；本仓库公开泛型重载未提供名称直接切换入口。
- **链式多次切换**：在 `OnEnter` 里立刻调用 `ChangeState<NextState>(fsm)`，可在一帧内级联切换；但要注意避免无限递归。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GameFrameworkException: Current state is invalid.` | 在尚未 `Start<T>()` 或 FSM 已 `Shutdown` 时调用 `ChangeState` | 先调用 `fsm.Start<IdleState>()` 启动 FSM |
| `FSM '...' can not change state to '...' which is not exist.` | 目标状态类未传入 `CreateFsm` 的 `states` 数组 | 把目标状态实例加到 `CreateFsm(owner, new IdleState(), new MoveState())` |
| `State type '...' is invalid.` | 通过 `Type` 重载传入的类型不是 `FsmState<T>` 的派生类 | 确认目标类型继承自 `FsmState<T>`，且 `T` 与 FSM 一致 |
| 切换后 `OnLeave` 收不到通知 | 把切换写在 `OnLeave` 之后或 FSM 已销毁 | 确保在状态生命周期方法内调用，且 FSM 仍存活 |

## 背景（可选）

`ChangeState<TState>` 内部仅做一次方法转发，真正的切换逻辑集中在 `Fsm<T>.ChangeState(Type)` 中，保证所有重载走同一份 `OnLeave → 重置计时 → 替换 → OnEnter` 流程，避免分支遗漏。
