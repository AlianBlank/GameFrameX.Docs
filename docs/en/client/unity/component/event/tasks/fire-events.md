# How to Fire Events: Fire, FireNow, and Parameterless Events

In GameFrameX.Event, firing an event is as simple as calling one of the three methods on `EventComponent`: `Fire` (thread-safe, main-thread callback on the next frame), `FireNow` (immediate synchronous dispatch), or `Fire(sender, eventId)` (a shortcut that doesn't require a custom event argument). This article provides the complete steps for all three usages, applicable scenarios, and common pitfalls.

## Prerequisites

- The GameFrameX entry point already exists in the scene, and `EventComponent` is attached automatically along with the framework (the component menu is `GameFrameX/Event`, see [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)).
- Someone has already subscribed to the corresponding event ID; otherwise, no one will receive it after it is fired (you can use a default handler as a fallback, see "Common Variants" below).

## Steps

1. Get a reference to the event component (attach it to your MonoBehaviour or obtain it from the framework entry point):

   ```csharp
   using GameFrameX.Event.Runtime;

   private EventComponent eventComponent;
   // In Awake/Start:
   // eventComponent = GameEntry.GetComponent<EventComponent>();
   ```

2. Prepare the event argument class (inherit from `GameEventArgs`, provide a `Create` factory and `Clear`/recycling convention):

   ```csharp
   public class LevelUpEventArgs : GameEventArgs
   {
       public int Level { get; private set; }
       public static LevelUpEventArgs Create(int level) { /* ... */ }
   }
   ```

3. Fire in deferred mode (default recommendation, thread-safe) — the event is invoked on the main thread in the next frame after being fired:

   ```csharp
   eventComponent.Fire(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L124-L128)

   The corresponding component API signature:

   ```csharp
   // Fire an event. This operation is thread-safe. Even if it is fired off the main thread,
   // the event handler function is still guaranteed to be invoked on the main thread, but the event will be dispatched in the next frame after being fired.
   public void Fire(object sender, GameEventArgs e)
   {
       m_EventManager.Fire(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L150)

4. Fire in immediate mode (use only on the main thread) — the event is dispatched synchronously and immediately; handlers have finished executing before the call returns:

   ```csharp
   eventComponent.FireNow(this, LevelUpEventArgs.Create(5));
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L130-L134)

   ```csharp
   // Fire an event in immediate mode. This operation is not thread-safe; the event is dispatched immediately.
   public void FireNow(object sender, GameEventArgs e)
   {
       m_EventManager.FireNow(sender, e);
   }
   ```

   Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

5. After firing, you can observe the dispatch results. A comparison of the three approaches:

   | API | Dispatch Timing | Thread Safety | Typical Use |
   |-----|---------|---------|---------|
   | `Fire(object, GameEventArgs)` | Next frame, main thread | Yes | Default choice; firing events from worker threads/async tasks |
   | `FireNow(object, GameEventArgs)` | Immediate, synchronous | No | Immediate main-thread responses such as UI clicks, or when subsequent state must reflect "event handling completed" |
   | `Fire(object, string)` | Next frame, main thread | Yes | Parameterless notifications (internally wrapped with `EmptyEventArgs`) |

## Common Variants

**Parameterless events (shortcut)**: When you don't want to define an argument class for a one-off notification, just pass a string ID; internally, the component wraps it with `EmptyEventArgs.Create(eventId)` before going through `Fire`, after first validating that `eventId` is not null or empty:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

```csharp
eventComponent.Fire(this, "level_up");
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L136-L140)

**Firing from a worker thread**: When firing events from a thread pool, Task, or network callback, you must use `Fire`, which guarantees the callback occurs on the main thread (next frame), so you can access Unity APIs directly inside the callback.

**Fallback when there are no subscribers**: Firing an ID that has no subscribers will not throw an error, but you can set a default handler to troubleshoot "events fired but no one received them":

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"Unhandled event: {e.Id}");
}
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Cannot read the handling result in the same frame after `Fire` | `Fire` uses deferred dispatch; the callback only occurs on the next frame | Use `FireNow` when you need the result in the same frame |
| Callback behaves abnormally after calling `FireNow` from a worker thread | `FireNow` is not thread-safe | Always use `Fire` from worker threads |
| The data received inside the handler after firing is incorrect/empty | The argument object was recycled and reused, or was not properly `Create`d | Call the argument class's `Create(...)` on every fire; do not cache old instances |
| Nothing happens after the event is fired | No one is subscribed to the target ID | Troubleshoot with `eventComponent.Check(id, handler)` or `Count(id)`; set a default handler to observe if necessary |
| `Fire(sender, eventId)` throws an argument validation exception | `eventId` is null or an empty string | Make sure to pass a non-empty string ID (validated by `GameFrameworkGuard.NotNullOrEmpty`) |

## Verification

- Log inside the handler to confirm the event is received: `Debug.Log($"Leveled up to {args.Level}")` (see the example in [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L102-L106)).
- Cross-check with the statistics properties: `eventComponent.EventHandlerCount` / `eventComponent.EventCount` / `eventComponent.Count("level_up")` (see [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) and [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L153-L159)).

## Background

`EventComponent` is merely a thin wrapper; the actual logic lives in `IEventManager` (`EventManager`); `Fire` leverages the event pool's queue to dispatch uniformly on the main thread in the next frame, which is why it is thread-safe; `FireNow` skips the queue and invokes handlers synchronously and directly. For event subscription and unsubscription, see "How to Subscribe to and Unsubscribe from Events".
