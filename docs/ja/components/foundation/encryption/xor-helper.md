# XOR による簡易暗号化・復号化の使い方

`XorHelper` は、排他的論理和（XOR）演算に基づく軽量な暗号化・復号化ツールを提供します。同じ鍵でデータを 2 回 XOR することで元のデータに戻せるため、設定ファイルやメモリ内の一時バイトストリームの簡易的な難読化に適しています。注意：これは暗号学的に安全な方式ではないため、機密性が求められるシナリオには使用しないでください。

## 前提条件

- NuGet パッケージ `GameFrameX.Foundation.Encryption` を参照する（または `GameFrameX.Foundation.Encryption/XorHelper.cs` を直接参照する）。
- `using GameFrameX.Foundation.Encryption;` で名前空間を導入する。

## 操作手順

### 1. 最も簡単な暗号化と復号化

`XorHelper.GetXorBytes(byte[], byte[])` を呼び出して 1 回 XOR を行い、同じ鍵で再度呼び出すと復号化されます。2 回の呼び出しは完全に対称的で、暗号化 / 復号化メソッドの区別はありません。

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

var keyBytes = Encoding.UTF8.GetBytes("MySecretKey123");
var dataBytes = Encoding.UTF8.GetBytes("Hello, World! 这是一个测试字符串。");

// 暗号化
var encrypted = XorHelper.GetXorBytes(dataBytes, keyBytes);
// 復号化（同じ鍵で再度呼び出す）
var decrypted = XorHelper.GetXorBytes(encrypted, keyBytes);

Console.WriteLine(Encoding.UTF8.GetString(decrypted)); // 原文を出力
```

Source: [XorHelper.cs#L133-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L133-L144)

### 2.「インプレース変更」版を選択してメモリを節約する

入力配列を後続で元のまま保持する必要がない場合は、`GetSelfXorBytes` を使用して入力配列を直接書き換えると、新しいバイトストリームを別途確保する必要がありません。

```csharp
var dataBytes = Encoding.UTF8.GetBytes("payload");
var keyBytes = Encoding.UTF8.GetBytes("key");

// dataBytes 上で直接 XOR を実行し、新しい配列を返さない
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
// 再度呼び出して復元
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
```

Source: [XorHelper.cs#L158-L169](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L158-L169)

### 3. データの先頭 220 バイトのみを暗号化する（高速モード）

大きなバイトストリーム（プロトコルパケットヘッダなど）に対して軽量な難読化を行いたいが、配列全体を走査したくない場合は、`GetQuickXorBytes` / `GetQuickSelfXorBytes` を使用します。これらは先頭から `QuickEncryptLength`（デフォルト 220）バイトのみを XOR し、それ以降は元の値のまま保持されます。

```csharp
var buffer = new byte[1024];           // プロトコルヘッダ + 後続のペイロード
var key = Encoding.UTF8.GetBytes("k");

// 先頭 220 バイトのみを難読化し、後続のバイトはそのまま
var encrypted = XorHelper.GetQuickXorBytes(buffer, key);
// 復元時も先頭 220 バイトのみを処理
var restored = XorHelper.GetQuickXorBytes(encrypted, key);
```

Source: [XorHelper.cs#L76-L90](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L76-L90), [XorHelper.cs#L104-L118](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L104-L118)

### 4. 配列内の一部の範囲のみを暗号化する

`startIndex` と `length` パラメータを持つオーバーロードを使用すると、指定した範囲のみを XOR できます。「先頭部 / 中央の一部のみを難読化する」といったシナリオに適しています。

```csharp
var data = new byte[] { 1, 2, 3, 4, 5, 6, 7, 8 };
var key  = Encoding.UTF8.GetBytes("MySecretKey123");

// インデックス 2 から始まる 4 バイトのみを暗号化
var result = XorHelper.GetXorBytes(data, 2, 4, key);
// data[0..2] と data[6..8] は変更されない
```

## よく使うメソッド早見表

| メソッド | 新規配列の確保 | 暗号化範囲 | 適用シナリオ |
|------|----------------|----------|----------|
| `GetXorBytes(bytes, code)` | あり | 配列全体 | 通常の暗号化・復号化、原文の保持が必要 |
| `GetSelfXorBytes(bytes, code)` | なし（インプレース変更） | 配列全体 | 原文が不要、割り当てを 1 回節約 |
| `GetQuickXorBytes(bytes, code)` | あり | 先頭 220 バイト | 大きなヘッダの高速難読化 |
| `GetQuickSelfXorBytes(bytes, code)` | なし | 先頭 220 バイト | 大きなヘッダのインプレース高速難読化 |
| `GetXorBytes(bytes, startIndex, length, code)` | あり | 指定範囲 | 先頭部 / 中央部分のみを難読化 |
| `GetSelfXorBytes(bytes, startIndex, length, code)` | なし | 指定範囲 | 先頭部 / 中央部分のみをインプレースで難読化 |

## よくあるバリエーション

### 鍵がデータより長い / 短い / 単一文字の鍵

XOR アルゴリズムは鍵長に制限がなく、長短いずれでも正しく暗号化・復号化できます。テストでは単一文字、3 バイト、14 バイト、34 バイトなど、さまざまな鍵がカバーされており、鍵が空でなければ往復で復元できます。

Source: [XorHelperTests.cs#L82-L116](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Encryption/XorHelperTests.cs#L82-L116)

### 文字列のラウンドトリップ

文字列を直接 `Encoding.UTF8.GetBytes` して渡し、結果を `Encoding.UTF8.GetString` で戻すだけで、設定ファイル内の機密フィールドに適しています。

## よくある間違い

| 誤った方法 | 現象 | 正しい方法 |
|----------|------|----------|
| `GetXorBytes` の戻り値を新しい配列として再変更する | 難読化範囲がずれる | `GetXorBytes` の戻り値を使うか、明示的に `Array.Copy` してから `GetSelfXorBytes` に渡す |
| `code` に `Array.Empty<byte>()` を渡す | `ArgumentException("KeyArrayCannotBeEmpty")` が発生 | 少なくとも 1 バイト以上の鍵を使用する |
| 220 バイト以内の完全なデータを `GetQuickXorBytes` で処理する際、それ以降も暗号化されると思う | データ後半は元のまま残る | 全体を暗号化する必要がある場合は `GetXorBytes` を使用する |
| `startIndex + length` が配列長を超える | `ArgumentOutOfRangeException` が発生 | 先に `startIndex + length <= bytes.Length` を検証する |
| アカウントパスワード / 伝送鍵として使用する | 既知平文攻撃で簡単に解読される | 偶発的な読み取りを防ぐための難読化にのみ使用し、機密が必要なシナリオでは本格的な対称暗号化アルゴリズムを使用する |

## 背景（任意）

XOR 演算は本質的に `(A ^ K) ^ K == A` を満たすため、同じインターフェースで暗号化にも復号化にも使用できます。`QuickEncryptLength = 220` はプロトコルヘッダのシナリオに合わせて設定された経験値で、セキュリティとパフォーマンスの間の折衷案です。すべての公開メソッドは最初に `ArgumentNullException.ThrowIfNull` と `code.Length == 0` の検証を行い、offset / length 付きのオーバーロードは `startIndex + length <= bytes.Length` も検証します。
