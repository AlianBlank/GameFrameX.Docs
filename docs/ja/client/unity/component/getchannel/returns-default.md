# チャネル取得が常に default を返す場合の対処法

`BlankGetChannel.GetChannelName()` がターゲットプラットフォームでチャネル設定を読み取れない場合、パラメータ `defaultValue` のデフォルト値 `"default"` が返されます。この現象の原因はほとんどの場合、現在のプラットフォームの設定ソースに `channel` キーが存在しない、キー名が一致しない、または初回の読み取り結果が静的キャッシュされていることです。API シグネチャは以下の通りです:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L97-L98)

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| Editor / PC / WebGL / コンソール機で `default` が返される | `Assets/Resources/application_config.txt` が存在しない、または `channel=` 行がない | `Assets/Resources/` 配下に `application_config.txt` を作成し、`channel=xxx` を書き込む |
| `application_config.txt` を新規作成/変更したのに、依然として `default` が返される | 静的キャッシュ `ChannelCache` に `default` がキャッシュ済みで、このセッション内では再読み込みされない | Play モードを終了して Domain Reload をトリガーするか、Unity を再起動してから再テストする |
| Android 実機で `default` が返される | `<meta-data android:name="channel" .../>` がメイン起動 Activity 内に書かれていない、またはキー名が `channel` ではない | `meta-data` を AndroidManifest.xml のメイン起動 `<activity>` タグ内部に移動する |
| iOS 実機で `default` が返される | ビルド後処理スクリプトが Info.plist に `channel` キーがない場合、自動的に `"default"` を書き込んだ | ビルド前、またはより優先度の高い後処理であらかじめ `channel` キーを書き込む |
| iOS で `default` ではなく `unknown` が返される | Info.plist に該当キーがなく、iOS ネイティブ実装が `"unknown"` を返す | Info.plist に `channel` キーを追加する |
| `sub_channel` などのカスタムキーを取得すると `default` が返される | 渡した `channelKey` が設定ファイル内のキー名と一致していない | キー名を確認した上で、正しいキーで設定に書き込む |

## 修正手順

### 1. Editor / PC / WebGL:application_config.txt を確認する

これらのプラットフォームでは `Resources.Load<TextAsset>("application_config")` で読み込まれるため、ファイルは `Assets/Resources/application_config.txt` に配置する必要があります。1 行につき 1 つの `キー=値` です:

```text
channel=editor_cn_test
sub_channel=test
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L106-L121)

解析ルールの注意点(ソースコード `L110-L119` より):

- `\n` / `\r` / `\r\n` で改行され、空行は無視されます;
- 各行は `=` で分割され、**分割結果は 1 段より多い必要があります**。`channel` の形式(`=` がない)の行は行全体が破棄されます;
- キーと値の両端の空白は `Trim()` されるため、`channel = abc` と書いても `abc` が読み取れます。

### 2. 静的キャッシュの干渉を排除する

結果は静的ディクショナリ `ChannelCache` に書き込まれ、同一セッション内での 2 回目以降の呼び出しはキャッシュがそのまま使われます。特に注意すべきは、`textAsset == null`(ファイルが存在しない)の場合、`default` がキャッシュに書き込まれ、その後ファイルを追加しても再読み込みされないことです:

```csharp
if (ChannelCache.TryGetValue(channelKey, out var value))
{
    return value;
}
// ...
var textAsset = Resources.Load<TextAsset>("application_config");
if (textAsset != null)
{
    // ChannelCache を解析して格納
}
else
{
    ChannelCache[channelKey] = defaultValue;  // ファイルが見つからない場合、default をキャッシュ
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L100-L125)

Editor で設定が有効かどうかを確認する前に、まず Play モードを終了する(Domain Reload をトリガーする)か Unity を再起動してから、Play に入ってテストしてください。Android / iOS 側も同様です。マニフェストや plist を変更した後は再ビルドが必要で、プロセス内で自動的に更新されることはありません。

### 3. Android:meta-data をメイン起動 Activity 内に配置する

Android では JNI を通じて `com.alianhome.getchannel.MainActivity` の静的メソッド `GetChannel` を呼び出して読み取りが行われ、キー名はデフォルトで `channel` です:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

`AndroidManifest.xml` の**メイン起動 Activity タグの内部**(`<application>` 配下ではなく)に追加します:

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

確認ポイント:

- キー名は `android:name="channel"` でなければならず、C# 側で渡す `channelKey` と一致させてください。他のキーを取得するには、呼び出し時に `GetChannelName("你的键名")` を渡します。
- カスタムマニフェスト方式(独自の `Assets/Plugins/Android/AndroidManifest.xml` を使用する場合)は、Unity が現在使用しているテンプレートと一致させ、APK に組み込んだ後もメイン Activity 内にあることを確認してください。

### 4. iOS / tvOS / visionOS:Info.plist を確認する

iOS 側では `DllImport("__Internal")` によってネイティブの `getChannelName` を呼び出し、Info.plist から `channel` キーを読み取ります:

```csharp
[DllImport("__Internal")]
private static extern string getChannelName(string channelKey);
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L47-L48)

ネイティブ実装はキーが見つからない場合 `"unknown"` を返します(C# 側の `default` ではありません):

```objc
NSString * channel_value =  [dict objectForKey:channel_name_String];
if (channel_value != nil) {
    return StringToCharArray(channel_value);
}
channel_value = @"unknown";
return StringToCharArray(channel_value);
```

Source: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

パッケージ内では、`channel` キーは `PostProcessBuild(99)` のビルド後処理によって自動的に書き込まれます。この処理は**そのキーが存在しない場合にのみ**書き込みを行い、書き込まれる値は `"default"` に固定されています。そのため、本パッケージのデフォルトのフローでビルドした iOS パッケージは `default` になります。これは仕様どおりの動作です:

```csharp
const string channelKey = "channel";
const string channelValue = "default";

string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

実際のチャネルを取得するには、いずれかを選択してください:

1. `callbackOrder` が `99` より小さい `PostProcessBuild` ハンドラを記述し、先に Info.plist に実際のチャネルを書き込みます。本パッケージはキーの存在を検出するとスキップします(ログに `已有渠道,跳过设置=>` と出力されます);
2. または、ビルド成果物の Info.plist を直接編集してから再署名します。

Info.plist では String 型にする必要があります:

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)

## 検証

1. 上記の手順で設定を整えた後、アプリを再起動します(または Unity を再起動して Play に入ります);
2. 起動の早い段階(チャネルの読み取りが行われる前)に呼び出してログを出力します:

```csharp
string channel = BlankGetChannel.GetChannelName();
Debug.Log("channel = " + channel);
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

3. Android では `adb logcat | grep channel` で出力を確認します。iOS では Xcode のコンソールで確認します。iOS のビルド時に後処理が実行されていれば、ビルドログに `配置渠道成功=>` または `已有渠道,跳过设置=>` という文字列が出力されます;
4. 出力が設定に書き込んだ値であれば修正完了です。依然として `default` の場合は、「クイック診断」の表に戻り、プラットフォームごとに設定ソースとキャッシュを一つずつ確認してください。
