# How to Handle UI Lifecycle Events

`UIForm` calls a set of virtual methods at key moments such as opening, closing, being covered, and being paused. Override these methods in subclasses to hook in custom business logic; alternatively, listen to framework-level dispatched events via `UIEventSubscriber`.

## Prerequisites

- The project has imported the `GameFrameX.UI` module, and UI forms are opened/closed via `GameFrameX.UI.UIComponent`.
- Business UI form scripts inherit from `UIForm` (or implement `IUIForm`).
- To listen for open/close events, you need a `GameFrameX.UI.UIComponent` instance (the framework entry point).

## Steps

### 1. Override `UIForm` lifecycle virtual methods

`UIForm` exposes all lifecycle hooks as `virtual` methods with empty default implementations. Subclasses can override them as needed without worrying about the call order.

```csharp
using GameFrameX.UI.Runtime;
using UnityEngine;

public class MyMainForm : UIForm
{
    public override void OnInit()
    {
        // Executed on first instantiation: find child widgets, bind components
        base.OnInit();
    }

    public override void OnOpen(object userData)
    {
        // Triggered every time the form opens: receive data passed in from outside
        base.OnOpen(userData);
    }

    public override void OnClose(bool isShutdown, object userData)
    {
        // Cleanup on close
        base.OnClose(isShutdown, userData);
    }

    public override void OnPause()
    {
        // Covered by a new form and paused
        base.OnPause();
    }

    public override void OnResume()
    {
        // Resume from being covered
        base.OnResume();
    }

    public override void OnCover()
    {
        // Covered (not necessarily paused)
    }

    public override void OnReveal()
    {
        // Recovered from being covered
    }

    public override void OnRefocus(object userData)
    {
        // Refocused (the same form shown multiple times)
    }

    public override void OnUpdate(float elapseSeconds, float realElapseSeconds)
    {
        // Polled every frame
    }

    public override void OnDepthChanged(int uiGroupDepth, int depthInUIGroup)
    {
        // Depth changed (layering within the group)
    }

    public override void OnRecycle()
    {
        // The form is recycled
    }
}
```

Source: [UIForm.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIForm.cs#L600-L900)

### 2. Inject an initialization delegate before opening (optional)

`UIForm.Init` accepts an `Action<IUIForm>` delegate that is called before `OnInit`, which is well suited for parameter injection or dynamic initialization:

```csharp
var form = uiComponent.OpenUIForm("Assets/UI/MyMainForm.prefab", "MyMainForm",
    uiGroup: UIGroupNameConstants.Default,
    pauseCoveredUIForm: true,
    userData: myPayload,
    onInitAction: form =>
    {
        // Executed before OnInit
        ((MyMainForm)form).Initialize(myPayload);
    });
```

Source: [UIForm.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIForm.cs#L548-L600)

### 3. Listen to framework-dispatched open/close events

If you do not want to inherit from `UIForm`, you can also subscribe to the event arguments on `GameFrameX.Event`:

```csharp
using GameFrameX.UI.Runtime;
using GameFrameX.Event.Runtime;

// Subscribe to the open-success event
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnOpenSuccess);
GameEntry.Event.Subscribe(CloseUIFormCompleteEventArgs.EventId, OnCloseComplete);
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnOpenFailure);

private void OnOpenSuccess(object sender, GameEventArgs e)
{
    var args = (OpenUIFormSuccessEventArgs)e;
    // args.UIForm / args.Duration
}

private void OnCloseComplete(object sender, GameEventArgs e)
{
    var args = (CloseUIFormCompleteEventArgs)e;
    // args.SerialId / args.UIFormAssetName
}
```

The available event types are listed in the table below.

| Event Type | Trigger Timing | Key Fields |
|---|---|---|
| `OpenUIFormSuccessEventArgs` | UI form opened successfully | `UIForm`, `Duration` |
| `OpenUIFormFailureEventArgs` | UI form failed to open | `ErrorMessage`, `UIFormAssetName` |
| `OpenUIFormDependencyAssetEventArgs` | While loading dependency assets | `DependencyAssetName`, `LoadedCount`, `TotalCount` |
| `CloseUIFormCompleteEventArgs` | UI form close completed | `SerialId`, `UIFormAssetName` |

Sources: [OpenUIFormSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormSuccessEventArgs.cs), [CloseUIFormCompleteEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/CloseUIFormCompleteEventArgs.cs)

## Common Variants

- **Decoupling with `UIEventSubscriber`**: see [UIEventSubscriber.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIEventSubscriber.cs). You can centrally manage subscriptions via `Subscribe/Unsubscribe` in `Awake`/`OnDestroy`, avoiding scattered lambdas.
- **Overriding `Show` and `Hide`**: these two methods are `abstract`; subclasses must implement custom show/hide animations (`IUIFormShowHandler` / `IUIFormHideHandler`).
- **Binding common events**: you can override `BindEvent()` to centrally register button clicks and similar handlers, combined with `LoadData()` and `UpdateLocalization()` for phased processing.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Overriding `OnInit` has no effect | `base.OnInit()` is not called, so base class initialization is skipped | Call `base.OnInit()` on the first line of the override |
| Logic still runs after closing | `OnClose` is not overridden, relying solely on Unity destruction | Stop coroutines, timers, and network requests in `OnClose` |
| Form still responds to input after being covered | Forgot to override `OnPause` / `OnCover` to disable interactive components | Override these two methods and disable buttons or set `interactable = false` |
| Data not refreshed when reopening the same form | `OnInit` is only called the first time | Put the actual refresh logic in `OnOpen`, fetching the latest data from `userData` |

## Background (Optional)

`UIForm` is uniformly managed by `BaseUIManager`, and lifecycle methods are called by the manager during state transitions: `Open` → `OnInit` → `OnOpen`; when a new form opens and covers an old one, `OnCover`/`OnPause` are triggered; the reverse triggers `OnReveal`/`OnResume`. The framework does not force overriding any methods; business logic chooses hook-in points as needed, with empty implementations provided by the base class.
