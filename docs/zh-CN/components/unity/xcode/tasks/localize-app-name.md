# 配置多语言应用名称

在构建配置 JSON 的 `localizations` 数组中为每种语言声明 `languageCode` 和 `validMap`（包含 `CFBundleDisplayName` 键），打包后处理会在 Xcode 工程目录下自动生成 `{languageCode}.lproj/InfoPlist.strings`、把文件加入主 target 的 Resources，并在 `Info.plist` 中写入 `LSHasLocalizedDisplayName = true`，让 iOS 桌面图标下显示对应语言的名称。

## 前置条件

- Unity 切换到 iOS 平台，且本包（`com.gameframex.unity.xcode`）已安装。
- 项目已接入 `PostProcessBuildHelper` 的构建后处理流程——本地化逻辑由该流程统一触发（见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126)，从合并后的配置读取 `localizations` 字段）。

## 操作步骤

1. 在 iOS 构建配置 JSON 中添加 `localizations` 数组（与 `podInstall`、`capabilities` 等字段同级）：

   ```json
   "localizations": [
     {
       "languageCode": "en",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "My Game" }
       ]
     },
     {
       "languageCode": "zh-Hans",
       "validMap": [
         { "key": "CFBundleDisplayName", "value": "我的游戏" }
       ]
     }
   ]
   ```

   字段含义：

   | 字段 | 类型 | 说明 |
   |------|------|------|
   | `localizations` | array | 本地化配置列表，每项对应一种语言 |
   | `languageCode` | string | 语言代码，会作为 `{languageCode}.lproj` 目录名（如 `en.lproj`、`zh-Hans.lproj`）；为空或缺失时该条目被跳过 |
   | `validMap` | array | 键值对列表，每项包含 `key` 和 `value`；为空或缺失时该条目被跳过 |
   | `key` | string | Info.plist 键名；应用名本地化固定用 `CFBundleDisplayName` |
   | `value` | string | 该语言下的显示文本 |

   配置示例结构与 [README.zh-TW.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-TW.md#L323-L346) 中 `localizations` 一节的写法一致；`languageCode` / `validMap` 的字段名以 [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L52) 中的实际读取逻辑为准。

2. 执行 iOS 构建。后处理自动完成以下动作（无需手动干预）：

   ```csharp
   foreach (Hashtable loc in localizations)
   {
       ...
       // Create .lproj directory
       string lprojName = langCode + ".lproj";
       string lprojPath = Path.Combine(path, lprojName);
       if (!Directory.Exists(lprojPath))
       {
           Directory.CreateDirectory(lprojPath);
       }

       // Prepare InfoPlist.strings content
       StringBuilder sb = new StringBuilder();
       foreach (Hashtable map in validMap)
       {
           if (map.ContainsKey("key") && map.ContainsKey("value"))
           {
               string key = map["key"].ToString();
               string value = map["value"].ToString();
               sb.Append($"\"{key}\" = \"{value}\";\n");

               // 检查是否包含 CFBundleDisplayName
               if (key == "CFBundleDisplayName")
               {
                   hasLocalizedDisplayName = true;
               }
           }
       }
       ...
   }
   ```

   Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L35-L91)

3. 检查生成结果。生成的 `en.lproj/InfoPlist.strings` 内容形如：

   ```text
   "CFBundleDisplayName" = "My Game";
   ```

   生成格式由 `sb.Append($"\"{key}\" = \"{value}\";\n")` 决定，见 [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L62-L90)。

## 常见变体

- **同时本地化其它 Info.plist 键**：`validMap` 中可继续添加如权限描述等键值对，它们会写进同一个 `InfoPlist.strings`：

  ```json
  "validMap": [
    { "key": "CFBundleDisplayName", "value": "我的游戏" },
    { "key": "NSCameraUsageDescription", "value": "需要访问相机用于扫描二维码" }
  ]
  ```

- **更多语言**：在 `localizations` 数组中追加条目即可，每种语言各生成一个 `.lproj` 目录和一份 `InfoPlist.strings`。

- **关闭本地化**：把 `localizations` 置为空数组 `[]` 或不配置该字段，后处理直接返回，不做任何改动（见 [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L20-L23)）。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 打包后没有生成 `.lproj` 目录 | `localizations` 为空/未配置，或条目缺 `languageCode`、`validMap` | 确认配置已进入合并后的最终配置，且每个条目都带非空 `languageCode` 与非空 `validMap`（缺失的条目会被 `continue` 跳过） |
| 只本地化了权限描述、桌面名称仍是英文 | `validMap` 中没有 `CFBundleDisplayName` | 应用名本地化必须使用键名 `CFBundleDisplayName`，它同时是触发 `LSHasLocalizedDisplayName` 的唯一条件 |
| `InfoPlist.strings` 没进 Xcode 工程（显示语言 fallback 到默认） | 文件未被加入 Resources 构建阶段 | 后处理会用 `project.AddFile(...)` + `project.AddFileToBuild(mainTargetGuid, fileGuid)` 注入，见下文；若手动删过工程文件，重新打包一次 |
| 构建日志出现 `InfoPlist.strings not found at: ...` | `.lproj` 目录下文件被外部脚本删除或未生成 | 检查是否有其它后处理脚本在本地化之前清理目录，重新打包 |

## 背景

触发链路：`PostProcessBuildHelper` 在合并配置后调用 `RunLocalization(project, project.ProjectGuid(), path, finalConfig.Get("localizations") as ArrayList)`（见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L126)）。`RunLocalization` 生成文件后，当检测到 `CFBundleDisplayName` 时会把 `Info.plist` 的 `LSHasLocalizedDisplayName` 设为 `true`（[PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L97-L108)），随后由 `AddLocalizationToProject` 把每份 `InfoPlist.strings` 添加进主 target 的 Resources 并写回 `project.pbxproj`：

```csharp
// 使用 PBXProject API 添加文件到项目
string fileGuid = project.AddFile(infoPlistStringsPath, infoPlistStringsPath, PBXSourceTree.Source);

// 将文件添加到主 target 的 Resources 构建阶段
project.AddFileToBuild(mainTargetGuid, fileGuid);

LogHelper.Log($"Added localization file to project: {infoPlistStringsPath}");
```

Source: [PostProcessBuildHelper.Localization.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Localization.cs#L194-L205)
