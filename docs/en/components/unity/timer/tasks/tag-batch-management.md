# Batch Managing Timers by Tag

Pass a `tag` string when creating a timer with `Add()`. You can then use the four methods `PauseByTag` / `ResumeByTag` / `RemoveByTag` / `HasTag` to operate on all timers sharing the same tag at once, without having to hold each timer ID individually.

## Prerequisites

- The `TimerComponent` component already exists in the scene (menu path `GameFrameX/Timer`). It obtains the manager in `Awake` via `GameFrameworkEntry.GetModule<ITimerManager>()`.

## Steps

1. Create timers with `Add()`, passing the group name to the 5th parameter, `tag`. `tag` defaults to `null`; only timers with an explicitly passed tag will enter that tag group:

```csharp
using System;
using GameFrameX.Timer.Runtime;
using UnityEngine;

public class BattleScene : MonoBehaviour
{
    TimerComponent _timer;

    void Start()
    {
        // Add(interval, repeat, callback, callbackParam, tag, ...)
        _timer.Add(1f, 0, OnEnemyTick, null, "Battle");    // Refreshes every second, repeats indefinitely
        _timer.Add(5f, 10, OnBuffRefresh, null, "Battle"); // Once every 5 seconds, 10 times in total
        _timer.Add(30f, 1, OnBossRoar, null, "Battle");    // Triggers once after 30 seconds
    }

    void OnEnemyTick(object param) { /* ... */ }
    void OnBuffRefresh(object param) { /* ... */ }
    void OnBossRoar(object param) { /* ... */ }
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

2. Call `PauseByTag` when the entire group needs to be paused; time does not accumulate while paused:

```csharp
_timer.PauseByTag("Battle"); // e.g., when opening the pause menu
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L152-L155)

3. Call `ResumeByTag` to resume; accumulation continues from where it was paused:

```csharp
_timer.ResumeByTag("Battle"); // e.g., when closing the pause menu
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L161-L164)

4. Call `RemoveByTag` when the group ends to remove all members at once:

```csharp
_timer.RemoveByTag("Battle"); // e.g., unified cleanup when the battle ends
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L170-L173)

5. Use `HasTag` to check whether there are still active timers under the tag, then proceed with subsequent logic:

```csharp
if (_timer.HasTag("Battle"))
{
    Debug.Log("Battle timers are still running");
}
```

Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L180-L183)

Overview of tag-related methods:

| Method | Signature | Description |
|------|------|------|
| `PauseByTag` | `void PauseByTag(string tag)` | Pauses all non-deleted timers under this tag |
| `ResumeByTag` | `void ResumeByTag(string tag)` | Resumes all timers under this tag |
| `RemoveByTag` | `void RemoveByTag(string tag)` | Removes all timers under this tag |
| `HasTag` | `bool HasTag(string tag)` | Returns `true` when at least one timer exists under this tag |

These methods are defined on both the `ITimerManager` interface and `TimerComponent`, and their behavior is identical.

## Common Variants

- **One-shot tasks that also need grouping**: `AddOnce` and `AddUpdate` do not provide a `tag` parameter; if tag-based management is needed, use `Add(interval, 1, callback, param, tag)` instead for an equivalent single-trigger implementation.
- **Precisely operating on a single member by ID**: The return value of `Add()` is the timer ID. You can combine it with `Pause(int id)` / `Resume(int id)` / `Remove(int id)` / `IsPaused(int id)` to control an individual item within the group. See [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L105-L146).

## Common Mistakes

- **The tag is passed as `null` or an empty string**: The `tag` parameter of `Add` defaults to `null`. If omitted, the timer will not enter any group, and subsequent calls such as `PauseByTag` will have no effect on it—but no error will be raised; calling a tag that has no members is a safe no-op.
- **Assuming `RemoveByTag` triggers `onComplete`**: Tag operations go through the same removal path as `Remove(id)` ([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L516-L530)) and only perform removal. Do not rely on the completion callback for critical logic such as scene switching.
- **Calling `RemoveByTag` on the current tag directly inside a callback**: The implementation first copies the ID set to a temporary list and then removes items one by one to avoid modifying the collection during iteration, so it is safe to call within a callback. However, it is still recommended to defer removal until after the callback returns to keep the logic clear.

## Background

Internally, `TimerManager` uses `_tags` (`tag -> ID set`) to record groups, and `TimerItem` stores the `Tag` string; all tag operations are performed inside `lock (Locker)` to ensure thread safety. `PauseByTag` only takes effect on non-deleted items and sets `IsPaused = true`; `ResumeByTag` unconditionally clears the pause flag; and `HasTag` returns `true` as long as `ids.Count > 0`. For the overall structure of the timer module, see *Timer Component Overview*.
