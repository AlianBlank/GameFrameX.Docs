# 订阅下载事件（开始/进度/成功/失败）

通过 `EventComponent` 订阅 `DownloadStart` / `DownloadUpdate` / `DownloadSuccess` / `DownloadFailure` 四个事件，你可以在下载任务的生命周期任意阶段收到回调，从而驱动 UI 进度条、提示信息和失败重试逻辑。

## 前置条件

- 已安装 `com.gameframex.unity.download` 包，并在 `GameEntry` 上挂载了 `DownloadComponent`。
- 工程内已启用 GameFrameX 的 `EventComponent`（`DownloadComponent` 通过它派发所有下载事件）。
- 已有合法的本地保存路径与远端下载地址。

## 操作步骤

1. 获取 `DownloadComponent` 与 `EventComponent` 实例：

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   var eventComponent    = GameEntry.GetComponent<EventComponent>();
   ```

2. 通过 `EventComponent.Subscribe` 订阅四个事件，回调签名固定为 `void Handler(object sender, GameEventArgs e)`：

   ```csharp
   eventComponent.Subscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Subscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

3. 添加下载任务，记录返回的 `serialId`，用于在回调里区分是哪一次下载：

   ```csharp
   int serialId = downloadComponent.AddDownload(
       "/本地保存路径/file.zip",      // downloadPath
       "https://example.com/file.zip" // downloadUri
   );
   ```

4. 在四个回调里把 `GameEventArgs` 强制转换为对应类型，读取字段：

   ```csharp
   void OnDownloadStart(object sender, GameEventArgs e)
   {
       var args = (DownloadStartEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadUpdate(object sender, GameEventArgs e)
   {
       var args = (DownloadUpdateEventArgs)e;
       // args.SerialId, args.DownloadPath, args.DownloadUri, args.CurrentLength, args.UserData
   }

   void OnDownloadSuccess(object sender, GameEventArgs e)
   {
       var args = (DownloadSuccessEventArgs)e;
       if (args.SerialId == serialId)
       {
           // 下载完成：args.DownloadPath / args.DownloadUri / args.CurrentLength / args.UserData
       }
   }

   void OnDownloadFailure(object sender, GameEventArgs e)
   {
       var args = (DownloadFailureEventArgs)e;
       Debug.LogError($"下载失败：{args.ErrorMessage}");
   }
   ```

5. 用完记得 `Unsubscribe`，避免内存泄漏与误触发：

   ```csharp
   eventComponent.Unsubscribe(DownloadStartEventArgs.EventId,   OnDownloadStart);
   eventComponent.Unsubscribe(DownloadUpdateEventArgs.EventId,  OnDownloadUpdate);
   eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Unsubscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
   ```

## 常见变体

- **按 SerialId 过滤**：同一个 `DownloadComponent` 可能并发多个任务，回调里用 `args.SerialId == serialId` 区分是哪一次下载。
- **带 UserData 的任务**：调用 `AddDownload` 的重载可附带 `userData`，四个事件参数都会原样回传，便于把业务上下文一起带到回调里。
- **只想拿到完成结果**：不想写四个回调时，可改用 `await downloadComponent.Download(...)`，详见 README 的"异步用法"小节。

## 常见错误

- **EventId 写错**：必须使用 `XxxEventArgs.EventId` 常量，不要自己拼字符串。源码中四个 `EventId` 均为 `typeof(XxxEventArgs).FullName`，写错会导致订阅不到事件。
- **回调收到但 SerialId 对不上**：并发下载时未在回调里过滤 `args.SerialId`，把别人的结果当成自己的。
- **忘了 `Unsubscribe`**：脚本销毁或场景切换后未取消订阅，回调仍会被旧实例持有，容易引起内存泄漏或重复触发。
- **使用 `WWWDownloadAgentHelper` 时拿到的是旧版事件链**：四个 `DownloadXxxEventArgs` 是 `DownloadComponent` 层的统一事件，与底层 `DownloadAgentHelper` 的事件不同；UI 进度请订阅前者，不要直接订阅 Helper 层事件。

## 背景（可选）

四个 `DownloadXxxEventArgs` 均继承 `GameFrameX.Event.Runtime.GameEventArgs`，由 `DownloadComponent` 在内部状态机切换时通过 `EventComponent.Fire(this, ...)` 派发：`AddDownload` 后派发 Start，下载过程中派发 Update，最终派发 Success 或 Failure。事件机制让调用方无需持有 `DownloadComponent` 的返回对象即可收到异步通知。
