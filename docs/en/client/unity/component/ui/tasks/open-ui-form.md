# How to Open a UI Form

Using the asynchronous methods `OpenUIFormAsync` / `OpenUIAsync` provided by `UIComponent`, you can load and display a UI form by prefab path or form name, and obtain the form instance via the return value or an event callback once loading completes.

## Prerequisites

- The `GameFrameX/UI` component (`UIComponent`) has been attached to the project and initialized (it is called automatically during the framework startup process).
- A prefab has been created for the form, and the UI groups (`UIGroup`) and the asset helper have been configured in the `UIComponent` Inspector.
- The UI logic class implements the `IUIForm` interface, and show/hide animations are declared via attributes such as `OptionUIConfigAttribute` (optional).

## Steps

1. Get the UI component through the framework component entry point, for example:

```csharp
using GameFrameX.UI.Runtime;

var uiComponent = GameFrameX.Runtime.GameEntry.GetComponent<UIComponent>();
```

2. Open a form by its "form logic type", passing in the prefab asset path (relative to the Resources or Assets path, depending on project conventions). `pauseCoveredUIForm` indicates whether to pause lower-level forms that are covered, and `userData` is used to pass parameters to the form:

```csharp
using System.Threading.Tasks;
using GameFrameX.UI.Runtime;

public class MyMain : MonoBehaviour
{
    public async Task OpenLoginAsync()
    {
        var ui = GameEntry.GetComponent<UIComponent>();
        var form = await ui.OpenUIFormAsync<LoginUIForm>(
            "Assets/Game/UI/Forms/LoginUIForm",
            pauseCoveredUIForm: true,
            userData: null,
            isFullScreen: false);
        // form is the LoginUIForm instance and can be cast to a subclass for use
    }
}
```

`OpenUIFormAsync<T>(string uiFormAssetPath, bool pauseCoveredUIForm, object userData, bool isFullScreen)` internally calls `InnerOpenUIFormAsync`, returns the `IUIForm` instance once loading completes, and triggers the `OpenUIFormSuccess` event.

Source: [Runtime/BaseUIManager.Open.cs#L92-L130](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L92-L130)

3. If you only have a `Type`, you can use the non-generic overload:

```csharp
IUIForm form = await uiComponent.OpenUIFormAsync(
    uiFormAssetPath: "Assets/Game/UI/Forms/LoginUIForm",
    uiFormType: typeof(LoginUIForm),
    pauseCoveredUIForm: true,
    userData: null);
```

Source: [Runtime/BaseUIManager.Open.cs#L105-L118](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L105-L118)

4. If the UI asset name has already been registered via `OptionUIConfigAttribute` (which `Utility.Asset.Path.GetUIPath` resolves into the full path), you can use the more concise overload that only requires the type and parameters:

```csharp
T form = await uiComponent.OpenUIFormAsync<T>(
    pauseCoveredUIForm: false,
    userData: null,
    isFullScreen: false);
```

This overload internally obtains the path automatically via `Utility.Asset.Path.GetUIPath(uiFormAssetName)` and then calls the generic overload above.

Source: [Runtime/UIComponent.Open.cs#L116-L122](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.Open.cs#L116-L122)

5. Listen for the result events (optional, enabled by default):

```csharp
uiComponent.OpenUIFormSuccess += (sender, e) =>
{
    // e.UIFormType / e.UIFormAssetPath / e.Duration
};
uiComponent.OpenUIFormFailure += (sender, e) =>
{
    // e.UIFormType / e.ErrorMessage
};
```

The events are exposed by `BaseUIManager`, and their triggering can be controlled via `m_EnableOpenUIFormSuccessEvent` and `m_EnableOpenUIFormFailureEvent` (both default to `true`).

Source: [Runtime/UIComponent.cs#L61-L66](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L61-L66)

## Common Variants

| Scenario | Recommended Overload | Key Parameters |
|------|----------|----------|
| Open by asset path and get the specific subclass at runtime | `OpenUIFormAsync<T>(path, pause, userData, fullScreen)` | `path` is the prefab path, `T : class, IUIForm` |
| General scenario where only a `Type` is available | `OpenUIFormAsync(path, type, pause, userData, fullScreen)` | Pass in `typeof(...)` |
| UI asset name known (resolved via path parsing) | `OpenUIFormAsync<T>(pause, userData, fullScreen)` | Resolved by `Utility.Asset.Path.GetUIPath` |
| Using reflection or dynamic types, without caring about the concrete return type | `OpenUIAsync(path, type, pause, userData, fullScreen)` | Returns `IUIForm` |

## Common Errors

- Confusion about the meaning of `pauseCoveredUIForm`: this parameter controls whether to "pause the covered forms", not to "pause itself". Set it to `false` when opening a persistent main form, and `true` when opening a modal popup.
- The `T` in `OpenUIFormAsync<T>` must be a logic class that implements `IUIForm`, and the class must be associated with the prefab via `OptionUIConfigAttribute`; otherwise, after opening, the instance type will not match and `as T` will return `null`.
- `OpenUIFormSuccess` / `OpenUIFormFailure` are enabled by default (`m_EnableOpenUIFormSuccessEvent = true`); if disabled in the Inspector, they will not fire even if subscribed to.
- If the asset path is empty or the prefab does not have the UI logic script attached, a failure event is raised via `OpenUIFormFailure`; you can subscribe to this event to log it.

## Background

`OpenUIFormAsync` is ultimately implemented through the abstract method `BaseUIManager.InnerOpenUIFormAsync`. The UI manager handles focus, pausing of covered forms, and object pool reuse according to the `UIGroup` the prefab belongs to. Show/hide animations are controlled by `m_IsEnableUIShowAnimation` and `m_IsEnableUIHideAnimation` (both default to `false`) respectively; enable them in the `UIComponent` Inspector when needed.
