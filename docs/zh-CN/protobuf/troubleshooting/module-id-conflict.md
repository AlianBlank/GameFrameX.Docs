# 模块 ID 冲突怎么办

当你新增或重命名 `.proto` 文件后，CI 导出失败或生成代码里出现重复路由号时，多半是模块 ID 冲突了。本页告诉你怎么快速定位、修复并验证。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 两个 `.proto` 文件的文件名前缀相同（如都叫 `_0100_*.proto`） | 同一个模块号被分配给了两个文件 | 给其中一个文件改名，让模块号唯一 |
| `option module = N;` 与文件名里的 `0100` 不一致 | 文件名和声明的路由号对不上 | 二选一统一：改文件名或改 `option module` |
| 负数模块 ID 没保留负号（文件名用了 `_0120_Inner_Social.proto`） | 内部协议 `_-0120_…` 写成了对外协议的 `_0120_…` | 恢复 `_-` 前缀，与 `option module = -120;` 一致 |
| `ProtoExport` 报错提示 `duplicate module` | 上面的任一种情况导致冲突 | 按上三条之一修复后重新跑导出 |

## 修复步骤

### 1. 用文件名快速排查冲突

模块 ID 写在文件名里（`_<ModuleID:0000>_<Domain>.proto`），所以一眼就能看出谁占了同一个号。在仓库根目录执行：

```bash
ls _*.proto | awk -F_ '{print "_" $2}' | sort | uniq -d
```

- 没有任何输出 → 文件名层面没有冲突。
- 输出形如 `_0100` → 这个号被多个文件占用，继续到步骤 2。

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.zh-CN.md#L64-L82)

### 2. 检查 `option module` 与文件名是否一致

每个 `.proto` 文件头部都必须用 `option module = N;` 声明路由号，且必须和文件名里的数字一致。例：

```protobuf
// 文件名：_0100_Bag.proto
syntax = "proto3";
package Bag;
option module = 100; // 必须和文件名里的 0100 对上
```

如果文件名叫 `_0100_Bag.proto` 但写的是 `option module = 101;`，CI 导出时会判定为冲突。修法：

1. 打开冲突文件，对照文件名里的 4 位数字。
2. 把 `option module = N;` 改成相同的值（或反过来重命名文件）。
3. 保存后回到步骤 1 再跑一次 `uniq -d` 复核。

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.zh-CN.md#L66-L77)

### 3. 区分内部协议与对外协议

负数模块 ID 是内部协议（服务端之间），命名上必须保留负号前缀 `_-`：

```text
_-0120_Inner_Social.proto   ← module = -120（内部）
_0120_Social.proto          ← module = 120（对外）
```

如果内部文件被误命名为 `_0120_Inner_Social.proto`（少了负号），就会和对外协议撞号。改成 `_-0120_Inner_Social.proto` 并确认 `option module = -120;` 即可。

Source: [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.zh-CN.md#L82-L85)

### 4. 重新跑导出工具

修复后任选一种方式触发导出，确认冲突消失：

- **CI（零配置）**：把改动 `push` 到远程，`.github/workflows/proto-export.yml` 会自动跑并把产物发布到 [`latest` Release](https://github.com/GameFrameX/GameFrameX.Protobuf/releases/latest)。
- **Docker**：`docker run gameframex/gameframex-tools:latest ...`（无需本地工具链）。
- **本地脚本**：自行构建 `Tools/ProtoExport`（.NET 10），然后运行 `Proto2*Export.sh/.bat`。

## 验证

1. `ls _*.proto | awk -F_ '{print "_" $2}' | sort | uniq -d` 输出为空。
2. 每个文件的 `option module = N;` 与文件名中的 4 位数字（带符号）严格相等。
3. CI / Docker / 本地脚本的导出日志里不再出现 `duplicate module` 或类似冲突字样。
4. 下载最新 Release 产物，在客户端代码里搜索旧号应已替换为新号（或保留旧号、删除重复文件的那一方）。

## 背景

模块 ID 同时充当消息路由键和错误码生成的业务前缀——和文件名耦合是为了让"两个文件悄悄占用同一个号"这种事不可能发生，只要遵守 `_<ModuleID:0000>_<Domain>.proto` 这一约定，并在文件顶部用 `option module = N;` 把号锁死，冲突在编辑器里就能被肉眼发现，而不必等到运行时。
