# WeChat 通知未送達時的處理方法

建置完成後若未收到企業微信機器人通知，通常是因為 `WeChatBotKey` 未傳入、機器人未啟用，或是建置流程未抵達 `IsUpdateAssetPackageVersion` 的成功分支。修正前請先將以下診斷表與實際現象進行對照。

## 快速診斷

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 主控台中顯示 `System.Net.Http.HttpRequestException` 或逾時例外 | 無法存取 `qyapi.weixin.qq.com`，或被代理伺服器阻擋 | 檢查建置機器的網路/代理設定，確認是否能存取 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send` |
| WeChat 群組完全未收到任何訊息 | 命令列未傳入 `-WeChatBotKey`，導致 `BuilderOptions.WeChatBotKey` 為空字串 | 在建置命令中加入 `-WeChatBotKey <機器人Key>`（請注意大小寫）|
| 收到 `{"errcode":40001,...}` 或 `errcode":40014` | 機器人 Key 錯誤或已失效 | 重新複製企業微信群組機器人的 Webhook Key |
| 收到 `{"errcode":45009,...}` | 訊息頻率超過企業微信機器人的限制（20 則/分） | 降低建置頻率，或分散至多個機器人 |
| 通知從未被呼叫，且日誌中也沒有 `Debug.Log(response)` | `IsUpdateAssetPackageVersion` 為 false，或資源版本更新失敗 | 同時傳入 `-IsUpdateAssetPackageVersion true`，並確保 `BuilderUpdateAssetPackageVersionHelper.Run` 回傳 `true` |
| Unity Console 僅輸出 `Debug.LogException(e)`，沒有回應內容 | 例外被 `catch (Exception e)` 吞掉 | 請參閱後述的「修正步驟 - 檢查被吞掉的例外」 |

## 修正步驟

### 1. 確認命令列是否已傳入 `-WeChatBotKey`

`BuilderOptions.WeChatBotKey` 的預設值為空字串，只有在命令列指定 `-WeChatBotKey` 時才會被賦值。

```csharp
else if (commandLineArg == "-WeChatBotKey")
{
    if (index + 1 < commandLineArgs.Length)
    {
        _builderOptions.WeChatBotKey = commandLineArgs[index + 1];
    }
}
```

建置命令範例（Unity 命令列）:

```bash
-gameframex.builder -WeChatBotKey xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx -IsUpdateAssetPackageVersion true
```

參數說明請參閱 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md#L117)。

### 2. 確認建置是否已抵達通知分支

通知只會在「資源版本更新成功」後送出，因此只傳入 `WeChatBotKey` 並沒有意義。

```csharp
if (_builderOptions.IsUpdateAssetPackageVersion)
{
    var result = BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
    if (result)
    {
        WeChatNotifyWorkHelper.Run(buildParameters, _builderOptions);
    }
}
```

請同時指定兩個開關：

```bash
-IsUpdateAssetPackageVersion true -WeChatBotKey <key>
```

若 `BuilderUpdateAssetPackageVersionHelper.Run` 回傳 false，通知將不會被觸發，因此請先調查版本更新失敗的原因。

### 3. 驗證 Webhook Key 是否有效

若 Key 錯誤，企業微信會回傳 `errcode:40001`（secret 錯誤）或 `40014`（無效的 Key）。可以使用 `curl` 直接測試：

```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<你的Key>' \
  -H 'Content-Type: application/json' \
  -d '{"msgtype":"text","text":{"content":"hello"}}'
```

若回傳 `errcode: 0` 即為正常。若為其他值，請在企業微信群組中重新新增機器人並取得新的 Key。

### 4. 檢查被吞掉的例外

`WeChatNotifyWorkHelper.Run` 會捕捉所有例外並以 `Debug.LogException` 記錄。若只顯示例外堆疊，表示 HTTP 呼叫本身已失敗（網路/DNS/逾時）。

```csharp
try
{
    var httpResponseMessage = httpClient.PostAsync(url, stringContent).GetAwaiter().GetResult();
    var response = httpResponseMessage.Content.ReadAsStringAsync().GetAwaiter().GetResult();
    Debug.Log(response);
}
catch (Exception e)
{
    Debug.LogException(e);
}
```

因應方式：`httpClient.Timeout` 為 30 秒，在內部網路環境中請適當調長。HTTPS 憑證由系統的信任鏈處理，但若建置機器使用自我簽署的代理伺服器，則需要額外設定 `HttpClientHandler`。

### 5. 確認 Newtonsoft.Json 參考是否存在

CHANGELOG 中特別記載了 `WeChatNotifyWorkHelper` 缺少 `Newtonsoft.Json` 參考的問題。若編譯時出現 `The type or namespace name 'Newtonsoft' could not be found`，請在 `Editor/GameFrameX.Builder.Editor.asmdef`（或對應的組件定義）中加入 `Newtonsoft.Json` 的參考。

```text
* **builder:** 加入 WeChatNotifyWorkHelper 所缺少的 Newtonsoft.Json 參考
```

## 驗證

1. 重新執行建置，確認 Unity Console 同時輸出 `Debug.Log(response)` 與正常的 JSON 回應內容（包含 `errcode: 0`）。
2. 確認企業微信群組顯示 `### 游戏资源版本更新` 的 markdown 通知，且內容包含時間、資源版本、遊戲版本等欄位。
