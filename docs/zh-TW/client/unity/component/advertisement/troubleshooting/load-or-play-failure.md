# 廣告載入或播放失敗時的處理方式

當 `Play(...)` 或 `Load(...)` 觸發失敗回呼時，通常是因為設定缺失、廣告單元 ID 未填寫、SDK 未初始化或回呼未綁定所導致。請將下方症狀與原因進行比對，定位問題所在，然後依照步驟進行修復。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| `Play` 直接進入 `OnFail`,日誌中沒有任何廣告事件 | 未呼叫 `Initialize` 或 `m_config` 為 null | 在 `Start` 之前將 `AdvertisementConfig` 注入 `AdvertisementComponent`,或在 Inspector 中指定設定資產 |
| `Log.Fatal("Advertisement manager is invalid.")` | 框架未註冊廣告管理器實作 | 透過 `AdvertisementConfigAttribute` 註冊 `BaseAdvertisementManager` 的子類別，並將其放入場景啟動鏈中 |
| 載入/播放完全沒有任何回呼 | `AdvertisementPlayOption.OnSuccess/OnFail/OnShowResult` 未指派 | 在呼叫 `Play` 之前，為 `AdvertisementPlayOption` 指派全部三個 Action |
| iOS/Android/小遊戲載入了空設定 | 當前平台的廣告單元 ID 欄位為空 | 填寫 `m_adUnitIdAndroid`、`m_adUnitIdiOS`,或三個小遊戲欄位之一(`WeChat` / `DouYin` / `KuaiShou`) |
| `Play` 回報錯誤但 `OnShowResult` 回傳 false | 展示流程已成功，但 SDK 將其標記為未完整播放 | 檢查廣告單元的審核狀態以及素材是否被拒；詳見「廣告單元審核被拒」一節 |
| `Load` 過時警告 | 使用了舊版 API | 改用 `Play(AdvertisementPlayOption)`;不要使用 `Load(success, fail)` |

## 修復步驟

### 1. 確認廣告管理器已註冊

`AdvertisementComponent.Awake()` 會使用反射取得 `IAdvertisementManager` 的實作；如果找不到，將直接呼叫 `Log.Fatal`。請檢查以下幾點：

- 您的自訂管理器類別具有 `[AdvertisementConfigAttribute]`,並繼承自 `BaseAdvertisementManager`
- 該類別確實已編譯進專案的執行階段組件中
- 場景中存在 `AdvertisementComponent`,且 `componentType` 欄位指向您的自訂管理器

參考實作位置:[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L87-L118)

### 2. 注入 AdvertisementConfig

`Start()` 僅在 `m_config != null` 時才會呼叫 `_advertisementManager.Initialize(m_config)`。請記得將廣告設定資產拖曳到 Inspector 中的 `m_config` 欄位，或在程式碼中明確初始化：

```csharp
var component = GameEntry.GetComponent<AdvertisementComponent>();
component.Initialize(myAdvertisementConfig);
```

來源:[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L140)

### 3. 填寫當前平台的廣告單元 ID

`AdUnitId` 會依據平台編譯指示詞進行選擇；如果任一分支為空，SDK 將收不到有效的 ID。常見遺漏情況：

- Android 版本只填寫了 iOS ID
- WebGL 選擇了通用 ID,但已啟用 `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 巨集，且未填寫小遊戲專屬的單元 ID

請確認在 Inspector 中，`m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` 至少有一項已填入值。

來源:[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57)

### 4. 補齊播放回呼

如果 `AdvertisementPlayOption` 的三個 Action 中有任何一個未指派，對應的回呼將不會觸發：

```csharp
var option = new AdvertisementPlayOption
{
    OnSuccess = json => Debug.Log($"Reward granted successfully: {json}"),
    OnFail    = err  => Debug.LogError($"Playback failed: {err}"),
    OnShowResult = shown => Debug.Log($"Fully displayed: {shown}"),
    customData = "level=1",
};
component.Play(option);
```

`extraData` 僅會在 Load 階段被序列化並傳遞給伺服器；載入完成後再修改不會產生任何效果。

來源:[AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L84)

### 5. 不要使用已棄用的 Load

`BaseAdvertisementManager.Load(Action<string>, Action<string>, string)` 已被標記為 `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`。繼續使用它只會觸發警告，並不會自動銜接到新流程。請一律改用 `Play(AdvertisementPlayOption)`。

來源:[BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L236-L238)

### 6. Debug 模式疑難排解

啟用 `m_debug = true`(或將 `true` 作為第二個參數傳入 `Initialize`),讓 SDK 輸出更詳細的請求日誌，協助判斷問題出在網路、簽名，還是廣告單元回傳的錯誤碼。

來源:[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L59)

## 驗證

修復完成後，請確認以下各項：

1. 啟動日誌中不再出現致命日誌 `Advertisement manager is invalid.`。
2. 呼叫 `Play` 時，`OnSuccess` 或 `OnFail` 至少會觸發其中一個，而不是「完全沒有任何回應」。
3. 在 Android / iOS / 微信小遊戲 / 抖音 / 快手小遊戲等編譯目標之間切換時，`AdUnitId` 不為空。
4. 在廣告平台後台確認廣告單元狀態為「已審核通過」，且未觸發頻次上限策略。
