# ImageCacheConfig 설정 참조

`ImageCacheConfig`는 `ImageCacheComponent`가 Inspector에서 노출하는 이미지 캐시 설정 컨테이너로, 캐시 경로, 디스크 용량 상한, 만료일 수 세 가지 필드를 포함하며, 컴포넌트 초기화 시 기본 `IImageCacheManager.Config`를 어떻게 초기화할지 제어합니다.

## 설정 필드 빠른 참조

| 필드명 | 타입 | 기본값 | 의미 |
|--------|------|--------|------|
| `CachePath` | `string` | `string.Empty` | 캐시 파일 저장 경로. 비어 있을 경우 컴포넌트는 `PathHelper.AppHotfixResPath + "/cache/images/"`로 대체합니다. |
| `MaxDiskSize` | `long`（바이트） | `0` | 디스크 캐시 최대 용량. `0`은 제한 없음을 의미합니다. |
| `ExpireDays` | `int`（일） | `0` | 캐시 만료일 수. `0`은 만료되지 않음을 의미합니다. |

## 필드 의미 상세 설명

### CachePath

캐시 파일의 디스크 디렉터리. 컴포넌트 `Awake` 단계에서 다음을 실행합니다:

```csharp
_imageCacheManager.Config.CachePath = string.IsNullOrEmpty(m_Config.CachePath)
    ? PathHelper.AppHotfixResPath + "/cache/images/"
    : m_Config.CachePath;
```

즉, `CachePath`가 `null` 또는 빈 문자열일 때는 프레임워크 내장 핫업 리소스 디렉터리의 `cache/images/` 하위 디렉터리를 사용하고, 그렇지 않으면 사용자가 입력한 경로에 기록됩니다. 절대 경로 또는 `Application.persistentDataPath` 기반의 상대 경로를 입력할 것을 권장하며, 플랫폼별로 디렉터리를 찾지 못하는 상황을 피할 수 있습니다.

### MaxDiskSize

디스크 캐시 상한 (단위: 바이트). `0`은 용량을 제한하지 않음을 의미하며, `ExpireDays`가 정리를 트리거하거나 수동으로 `ClearCache()`를 호출할 때까지 컴포넌트는 계속해서 기록합니다. 0이 아닌 값은 기본 계층에서 캐시淘汰를 제어하여 점유 공간이 해당 임계값을 초과하지 않도록 보장합니다.

### ExpireDays

캐시 만료일 수 (단위: 일). `0`은 만료되지 않음을 의미하며, 캐시 파일은 용량 초과 또는主动 정리 시에만 제거됩니다. 0이 아닌 값은 지정된 일 수를 초과한 캐시 파일이 새 캐시写入 시 만료로 판정되어 정리되도록 합니다.

## 설정 적용 시점

`ImageCacheConfig`는 Inspector에서 `ImageCacheComponent.m_Config` 필드에 직렬화된 데이터 컨테이너이며, 컴포넌트 `Awake()` 시 세 필드를 한 번에 `IImageCacheManager.Config`로 동기화합니다:

```csharp
[SerializeField]
private ImageCacheConfig m_Config = new ImageCacheConfig();

public ImageCacheConfig Config
{
    get { return m_Config; }
}
```

```csharp
protected override void Awake()
{
    // ...
    _imageCacheManager.Config.CachePath = string.IsNullOrEmpty(m_Config.CachePath)
        ? PathHelper.AppHotfixResPath + "/cache/images/"
        : m_Config.CachePath;
    _imageCacheManager.Config.MaxDiskSize = m_Config.MaxDiskSize;
    _imageCacheManager.Config.ExpireDays = m_Config.ExpireDays;
    // ...
}
```

런타임에 `ImageCacheComponent.Config`를 통해서는 직렬화된 값만 읽을 수 있습니다. 게임 실행 중 캐시 동작을 수정하려면 `ImageCacheComponent.LoadImageAsync` / `ClearCache` 등의 메서드를 직접 호출하거나, 컴포넌트 초기화流程을 다시 거쳐야 합니다.

## 코드 예제: 직렬화 필드를 통해 수동으로 구성 생성

```csharp
using GameFrameX.ImageCache.Runtime;

var config = new ImageCacheConfig
{
    CachePath   = UnityEngine.Application.persistentDataPath + "/image-cache/",
    MaxDiskSize = 50L * 1024 * 1024, // 50 MB
    ExpireDays  = 7
};
```

> `ImageCacheConfig`의 세 가지 속성은 모두 공개 setter를 가지므로, 런타임에 `component.Config.CachePath = ...` 방식으로 값을 할당할 수 있지만, 컴포넌트 `Awake` 이후 수정은 읽기에만 영향을 미치며 직렬화 필드로 역방향 기록되지 않는 점에 유의하십시오.

## 일반적인 값 권장

| 시나리오 | CachePath | MaxDiskSize | ExpireDays |
|------|-----------|-------------|------------|
| 로컬 개발, 디버깅 | 비워두고 기본 `AppHotfixResPath/cache/images/` 사용 | `0` | `0` |
| 정식 출시, 제한된 공간 | `Application.persistentDataPath + "/images/"` | `50 * 1024 * 1024`（50 MB） | `7` |
| 리소스 장기 재사용 | 사용자 정의 경로 | `0`（제한 없음） | `0`（만료되지 않음） |
