# 如何从子线程安全派发事件

在子线程（如网络线程、Task、异步回调）中调用 `Fire`（而不是 `FireNow`）即可安全派发事件：该操作是线程安全的，事件会被排队，保证在主线程的下一帧回调事件处理函数，处理函数里可以放心访问 Unity API。

## 前置条件

- 场景中已存在挂载 `EventComponent` 的对象（或已通过模块系统获取到 `EventManager`）。
- 在主线程上先完成事件订阅（`Subscribe` / `CheckSubscribe`），子线程只负责 `Fire`。

## 操作步骤

1. 在主线程（如 `Awake`/`Start`）通过场景中 `EventComponent` 的引用订阅事件。`Fire` 派发的事件没有处理函数也不会报错（事件池以 `AllowNoHandler | AllowMultiHandler` 模式创建）：

```csharp
private void Start()
{
    // CheckSubscribe：不存在时才订阅，避免重复注册
    eventComponent.CheckSubscribe(DownloadFinishedEventArgs.EventId, OnDownloadFinished);
}

private void OnDownloadFinished(object sender, GameEventArgs e)
{
    // Fire 派发的事件保证在主线程回调，可以直接操作 Unity 对象
    Debug.Log("下载完成");
}
```

`CheckSubscribe` 的真实实现（不存在时才订阅）：

```csharp
public void CheckSubscribe(string id, EventHandler<GameEventArgs> handler)
{
    if (!Check(id, handler))
    {
        m_EventManager.Subscribe(id, handler);
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L105-L111)

2. 在子线程中调用线程安全的 `Fire` 派发事件（下面是调用方式示意，`EventComponent` 的真实接口见步骤末尾的源码摘录）。事件会在抛出后的**下一帧**于主线程分发：

```csharp
// 子线程代码（例如 Task.Run / 网络库回调），eventComponent 为场景中 EventComponent 的引用
Task.Run(() =>
{
    byte[] data = DownloadFromNetwork(); // 耗时操作
    eventComponent.Fire(this, EmptyEventArgs.Create(DownloadFinishedEventArgs.EventId));
});
```

`EventComponent.Fire` 提供了两个重载，其中按事件编号派发的重载内部使用 `EmptyEventArgs.Create(eventId)` 并对编号做非空校验：

```csharp
public void Fire(object sender, GameEventArgs e)
{
    m_EventManager.Fire(sender, e);
}

public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L147-L161)

3. 需要携带自定义数据时，自定义一个继承 `GameEventArgs` 的参数类型并在子线程填好数据后随 `Fire` 抛出（下面是调用方式示意，`EmptyEventArgs` 是仓库内置的无参事件，自定义参数类按同样思路实现）：

```csharp
public class DownloadFinishedEventArgs : GameEventArgs
{
    public const string EventId = "Download.Finished";
    public byte[] Data { get; set; }
}

// 子线程派发：
eventComponent.Fire(this, new DownloadFinishedEventArgs { Data = data });

// 主线程处理函数中读取：
private void OnDownloadFinished(object sender, GameEventArgs e)
{
    var args = (DownloadFinishedEventArgs)e;
    UseBytes(args.Data);
}
```

`GameEventArgs` 是一个开放继承的抽象基类，位于 `GameFrameX.Event.Runtime` 命名空间：

```csharp
public abstract class GameEventArgs : BaseEventArgs
{
}
```

Source: [GameEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventArgs/GameEventArgs.cs#L34-L40)

## 常见变体

| 场景 | 做法 |
|------|------|
| 只需通知、无数据 | `Fire(sender, eventId)` 字符串重载，内部用 `EmptyEventArgs.Create(eventId)` 构造空参数 |
| 直接持有 `IEventManager` | `IEventManager.Fire(object sender, GameEventArgs e)`，与组件封装行为一致 |
| 事件仅在主线程、需要同帧生效 | 用 `FireNow`，但**绝不能在子线程调用**（见下） |

## 常见错误

| 错误 | 后果与规避 |
|------|-----------|
| 在子线程调用 `FireNow` | `FireNow` **不是线程安全的**，会立刻在调用线程上分发，处理函数会在子线程执行并可能崩溃 Unity；子线程一律用 `Fire`。源码注释明确标注：[EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L167-L175) |
| 期望 `Fire` 同帧生效 | `Fire` 派发的事件在抛出后的下一帧才分发，依赖同帧时序的逻辑（如立即读状态）需要改为在处理函数回调后执行 |
| 在子线程里 `Subscribe`/`Unsubscribe` | 订阅表操作没有线程安全保证，请只在主线程增删处理函数 |
| 事件编号传空串 | `Fire(sender, eventId)` 内部 `GameFrameworkGuard.NotNullOrEmpty` 会直接抛出校验异常 |

## 背景

`EventManager` 是一个 `GameFrameworkModule`（优先级 7）。`Fire` 把事件放入内部 `EventPool<GameEventArgs>` 队列；模块每帧在主线程 `Update` 中调用 `m_EventPool.Update(elapseSeconds, realElapseSeconds)` 排空队列并回调处理函数，这就是"子线程抛出、主线程回调、下一帧分发"的由来。相关实现见 [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L76-L92) 与 [IEventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/IEventManager.cs#L93-L104)。
