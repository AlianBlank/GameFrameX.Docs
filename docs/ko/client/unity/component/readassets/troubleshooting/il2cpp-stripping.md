# IL2CPP 빌드 후 API가 잘려나갈 때 어떻게 해야 하나

IL2CPP 백엔드는 관리되는 바이트코드 링커(Unity Linker / IL2CPP stripping)를 통해 "직접 코드에서 참조되지 않는" 타입과 멤버를 잘라냅니다. IL2CPP 패키징 후 본 라이브러리의 API 호출 시 `MissingMethodException`, `NullReferenceException` 또는 "Editor에서는 분명히 동작하는데 패키징 후에는 동작하지 않는" 현상이 발생한다면 잘림이 원인입니다. 본 페이지에서는 빠른 진단 및 수정 방법을 안내합니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| Editor / Mono 빌드는 정상, IL2CPP 빌드 후 `MissingMethodException: void BlankReadAssets::xxx` 오류 발생 | 링커가 리플렉션 / 동적 호출되는 진입점을 잘라냄 | 의존 패키지에 포함된 `Runtime/link.xml`이 패키지에 포함되었는지 확인; 또는 사용자 정의 호출 지점에 `[Preserve]` 추가 |
| `BlankReadAssets.OpenRead` 등 API 호출 시 `null` 반환 또는 null 참조 예외 발생, 단 링커는 오류 없음 | 네임스페이스 / 내부 클래스가 잘려 구현 분기가 빈 껍데기로 변함 | `link.xml`이 `GameFrameX.ReadAssets.Runtime` 및 `GameFrameX.ReadAssets.Runtime.ZipArchive` 네임스페이스를 포함하는지 다시 확인 |
| 패키징 후 모든 platform에서 정상 동작, 단 Android IL2CPP StreamingAssets 읽기가 비어 있음 반환 | `ApkImpl` / `LooseFilesImpl` 구현 클래스가 잘려 platform 분기가 구현 없는 fallback으로 빠짐 | Managed Stripping이 활성화되어 있는지 확인하고, 필요 시 Player Settings에서 Strip Engine Code를 끄거나 link.xml 추가 |

## 수정 단계

### 1. 의존 패키지의 `link.xml`이 존재하고 패키지에 포함되어 있는지 확인

본 저장소는 `Runtime/link.xml`에서 보존해야 할 어셈블리와 네임스페이스를 명시적으로 선언하며, Unity Linker는 패키징 시 자동으로 이를 인식합니다:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<linker>
    <assembly fullname="BlankReadAssets.Runtime" preserve="all">
        <namespace fullname="GameFrameX.ReadAssets.Runtime" preserve="all"/>
        <namespace fullname="GameFrameX.ReadAssets.Runtime.ZipArchive" preserve="all"/>
    </assembly>
</linker>
```

Source: [Runtime/link.xml](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/link.xml#L1-L7)

확인 방법: `.apk` / `.ipa` / 빌드 산출물의 압축을 해제하여 `*_Data/Managed`와 같은 위치 또는 `Assets/` 아래에 `link.xml`이 있고 그 내용에 `BlankReadAssets.Runtime`이 포함되어 있는지 확인합니다. UPM 패키지는 `package.json`의 `samples` 또는 직접 파일 방식을 통해 이 파일을 포함합니다.

### 2. Player Settings의 Strip 레벨 확인

`Project Settings → Player → Other Settings → Managed Stripping`:

| 레벨 | 위험도 | 권장 사항 |
|------|------|------|
| Disabled | 잘리지 않음, 단 패키지 크기 증가 | 임시 검증용 |
| Low | 명백히 사용되지 않는 코드만 잘라냄 | 일반적으로 충분 |
| Medium / High | 리플렉션, 동적 로드 코드가 잘릴 수 있음 | 반드시 `link.xml`과 함께 사용 |

만약 프로젝트의 Managed Stripping이 High로 설정되어 있다면 3단계에 따라 리플렉션 지점에 `[Preserve]`를 추가합니다.

### 3. 공개 API에는 `[Preserve]`가 이미 적용되어 있으며, 새로 추가하는 코드도 동일하게 표시 가능

본 라이브러리의 모든 공개 API에는 이미 `[Preserve]`가 표시되어 있으며, 예시는 다음과 같습니다:

```csharp
[Preserve]
public static string Root
{
    get
    {
        EnsureInitialized();
        return BlankReadAssetsImpl.s_root;
    }
}

[Preserve]
public static void Initialize()
{
    BlankReadAssetsImpl.Initialize(Application.dataPath, Application.streamingAssetsPath);
    s_initialized = true;
}
```

Source: [Runtime/BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L37-L68)

비즈니스 레이어가 리플렉션(예: `Type.GetMethod("OpenRead")`)을 통해 본 라이브러리를 호출할 때 Unity Linker는 호출 관계를 인식하지 못합니다. 진입점 또는 래퍼 메서드에 `[Preserve]`를 추가하여 보존할 수 있습니다:

```csharp
using UnityEngine.Scripting;

[Preserve]
public static Stream OpenAsset(string file)
{
    return BlankReadAssets.OpenRead(file);
}
```

### 4. 사용자 정의 link.xml으로 fallback 처리 (단독 수단으로는 권장하지 않음)

프로젝트의 `Assets/link.xml`에 다음 내용을 추가하여 간접적으로 사용하는 네임스페이스도 함께 보존합니다:

```xml
<linker>
    <assembly fullname="YourGame" preserve="all"/>
</linker>
```

이는 "특정 어셈블리 전체를 보존"하는 것과 동일하며, 최후의 수단으로만 사용하고 장기적으로 의존하지 마십시오.

## 검증

수정을 완료한 후 다음 순서로 검증합니다:

1. **로컬에서 IL2CPP 빌드 재수행**: `File → Build Settings → Player Settings → Other Settings → Configuration → Scripting Backend = IL2CPP`로 설정한 뒤 Build And Run(또는 `Build`)을 다시 실행합니다.
2. **Release 빌드로 재현**: Editor IL2CPP 백엔드는 패키징 후에만 링커를 실행하므로, Editor에서는 잘림 문제를 재현할 수 없습니다.
3. **패키징 산출물의 잔여 심볼 확인**: `il2cppdumper` / `ilspycmd`를 사용하여 `il2cpp.so` 또는 `*_Data/Managed`의 metadata를 역분석하여 `BlankReadAssets` 타입과 호출 진입점이 여전히 존재하는지 확인합니다.
4. **로그 펜스 추가**: 호출 전후에 `Debug.Log`를 한 줄 작성한 뒤 실행 후 logcat / Player.log에서 진입점에 도달했는지 확인합니다. 진입점에 도달했는데도 오류가 발생한다면 문제는 잘림이 아니라 런타임 로직에 있습니다.

## 배경 (선택 사항)

Unity Linker는 기본적으로 "코드의 직접 참조"에 따라 잘라내며, 어셈블리 간 리플렉션, `Activator.CreateInstance`, 문자열 이름으로 타입을 찾는 호출 그래프는 모두 손실됩니다. 본 라이브러리의 `Runtime/link.xml`은 패키징 단계에서 `BlankReadAssets.Runtime` 어셈블리와 `ZipArchive` 네임스페이스를 명시적으로 보존하며, 공개 API의 `[Preserve]`와 함께 이중 안전장치를 구성합니다. 이 두 가지가 모두 적용되는 한 IL2CPP 패키징 후 API는 잘리지 않습니다.
