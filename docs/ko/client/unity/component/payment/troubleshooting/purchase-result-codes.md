# 구매 실패 및 결과 코드 빠른 참조

구매 콜백 `OnPurchaseFailed`(또는 `OnQueryPurchasesResult` / `OnConsumePurchaseResult`)이 트리거되면 `PaymentEventArgs.ResultCode`가 실패 원인을 파악하기 위한 `PaymentResultCode` 열거형 값을 제공합니다. 이 페이지에서는 전체 결과 코드, 각 결과에 대한 처리 권장 사항, 그리고 이 정보를 받기 위해 콜백을 올바르게 구독하는 방법을 정리합니다.

## 빠른 진단

| 증상(ResultCode / 현상) | 원인 | 수정 |
|------|------|------|
| `Success` | 구매 성공 | `OnPurchaseSuccess`에서 상품 지급; 일회성 상품은 반드시 `ConsumePurchase` 호출 |
| `Failed` | 채널 공통 실패, 자세한 내용은 `ErrorMessage` 확인 | `ErrorMessage`와 `PurchaseData`를 출력하고, 채널 오류 코드에 따라 원인 파악 |
| `Cancelled` | 사용자가 결제 화면에서 직접 취소 | 오류 알림을 띄우지 말고 조용히 처리하면 됩니다 |
| `NetworkError` | 기기 네트워크를 사용할 수 없음 | 재시도 안내, 네트워크 복구 후 다시 `Buy` |
| `ServiceUnavailable` | 채널 결제 서비스 사용 불가(예: 스토어 미준비) | 먼저 `IsReady()`로 결제 시스템 준비 여부를 확인하고, 잠시 후 재시도 |
| `ItemAlreadyOwned` | 상품을 이미 보유 중이고 소비되지 않음(일회성 상품 중복 구매) | `QueryPurchases`로 `PurchaseToken`을 조회한 후 `ConsumePurchase` 실행, 이후 재구매 |
| `ItemNotOwned` | 상품을 보유하지 않은 상태에서 소비 시도 | 먼저 구매를 완료하고, 존재하지 않는 `PurchaseToken`에 대해 `ConsumePurchase`를 호출하지 마세요 |
| `VerifyFailed` | 구매 검증 실패(`Init`의 `isClientVerify`와 관련) | 서버 검증 방식에서는 `isClientVerify`를 `false`로 설정; 서버 측 서명 검증 로직 확인 |
| `Unknown` | 채널이 매핑되지 않은 결과를 반환함 | `ErrorMessage`와 `PurchaseData`(원본 JSON)를 통해 수동 분석 |

결과 코드 정의는 다음과 같으며, 총 9개입니다:

```csharp
public enum PaymentResultCode
{
    Success,
    Failed,
    Cancelled,
    NetworkError,
    ServiceUnavailable,
    ItemAlreadyOwned,
    ItemNotOwned,
    VerifyFailed,
    Unknown,
}
```

## 전체 오류 정보 얻기

콜백 매개변수 `PaymentEventArgs`는 다음 필드를 포함하고 있으며, 문제 해결 시 모두 출력하세요:

| 필드 | 타입 | 설명 |

## 수정 단계

### 구매 실패 콜백 구독

세 개의 결과 이벤트(`OnPurchaseSuccess` / `OnPurchaseFailed` / `OnQueryPurchasesResult` / `OnConsumePurchaseResult`)는 `IPaymentManager`에 선언되어 있으며, `PaymentComponent`는 이벤트 래퍼 형태로 내부의 `_paymentManager`에 전달합니다:

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L42-L46)

비즈니스 레이어 구독 예시:

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseFailed += OnPurchaseFailed;

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    UnityEngine.Debug.LogError(
        $"[Payment] 失败 ProductId={e.ProductId} ResultCode={e.ResultCode} " +
        $"ErrorMessage={e.ErrorMessage} PurchaseData={e.PurchaseData}");
}
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L19-L36)

### `ItemAlreadyOwned`: 소비 후 재시도

일회성 상품(`PaymentProductType`의 소비형)은 지급 후 소비하지 않으면, 다음 구매 시 이 결과 코드를 받게 됩니다:

1. `QueryPurchases(PaymentProductType)`를 호출하여 구매 기록을 조회합니다;
2. `OnQueryPurchasesResult` 콜백에서 `PurchaseToken`을 꺼냅니다;
3. `ConsumePurchase(e.PurchaseToken)`를 호출하여 소비를 완료합니다;
4. 다시 `Buy(purchaseParams)`를 실행합니다.

관련 시그니처(`IPaymentManager`에 정의되고, `BasePaymentManager`에서 추상 구현):

```csharp
void QueryPurchases(PaymentProductType productType);
void ConsumePurchase(string purchaseToken);
```

Sources: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L52-L63)

### `VerifyFailed`: 검증 모드 확인

`Init`의 두 번째 매개변수가 검증 방식을 결정합니다:

```csharp
/// <param name="isClientVerify">구매 성공에 대해 클라이언트 검증을 수행할지 여부. 강력한 온라인 검증인 경우. 활성화할 필요가 없으면 false로 설정하여 서버 검증을 수행합니다</param>
void Init(bool isDebug = false, bool isClientVerify = false);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

서버 검증을 사용하는 경우 `false`를 전달하여 서버 측에서 서명을 검증하도록 하고, 클라이언트 검증 실패로 인한 `VerifyFailed` 오탐을 방지합니다.

### `ServiceUnavailable`: 준비 상태 확인

구매 전에 먼저 `bool IsReady()`를 호출하세요. 준비되지 않은 상태라면 채널 측 초기화가 완료되지 않은 것이며, `ServiceUnavailable`에 해당합니다. 또한 `SetPredefinedProductIds`는 반드시 초기화 전에 호출해야 하며, 그렇지 않으면 사전 로드 캐시가 적용되지 않습니다:

```csharp
void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

## 검증

- 구매 취소를 한 번 트리거하여(샌드박스 환경에서 취소 선택) 콜백이 `Cancelled`를 받았으며 예외 로그가 없는지 확인합니다;
- 이미 보유하고 있으며 소비되지 않은 상품을 다시 구매할 때 `ItemAlreadyOwned`를 받는지 확인하고, `ConsumePurchase` 실행 후 정상적으로 재구매 가능한지 확인합니다;
- `OnPurchaseFailed`에서 출력한 `ErrorMessage` / `PurchaseData` 내용이 완전하여 채널 백오피스와 대조할 수 있는지 확인합니다.

## 배경

각 채널 구현은 `BasePaymentManager`를 상속하며, `RaisePurchaseFailed` 등 네 개의 protected 메서드를 통해 통일된 방식으로 결과 이벤트를 트리거하므로, 모든 채널 콜백의 `PaymentEventArgs` 구조는 동일합니다:

```csharp
protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}
```
