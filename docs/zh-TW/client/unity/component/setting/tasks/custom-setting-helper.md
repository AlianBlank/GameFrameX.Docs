# 實作自訂儲存 Helper

繼承 [SettingHelperBase](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44)，實作 `ISettingHelper` 的所有成員，將讀寫連接到實際的儲存媒體（資料庫、加密檔案、遠端介面等）。框架會在啟動時透過 `SettingComponent` 呼叫 Helper，進行載入與儲存。

## 前置條件

- 已安裝 `com.gameframex.unity.setting` 套件，並可在 Inspector 中確認 `SettingComponent`。
- 了解 C# 抽象類別與 `MonoBehaviour` 的生命週期。Helper 必須附加到場景中的 GameObject 上。
- 自有的儲存媒體（SQLite、本機加密檔案、遠端 Key-Value 服務等）。

## 操作步驟

1. **建立 Helper 類別並繼承基底類別**。
   建立新腳本 `Assets/Scripts/MySettingHelper.cs`，繼承 `GameFrameX.Setting.Runtime.SettingHelperBase`。基底類別本身就是一個抽象 `MonoBehaviour`，框架會透過它取得所有 `ISettingHelper` 成員。

   ```csharp
   using GameFrameX.Setting.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
   }
   ```

   出處： [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44)

2. **實作必須覆寫的抽象成員**。基底類別中宣告的抽象成員對照表如下。請全部以 `override` 實作：

   | 成員 | 簽章 | 建議行為 |
   |------|------|---------|
   | `Count` | `int Count { get; }` | 不支援時回傳 `-1`（參考 `PlayerPrefsSettingHelper` 的實作） |
   | `Load()` | `bool Load()` | 若不需預先載入，直接回傳 `true` |
   | `Save()` | `bool Save()` | 在實際執行持久化後回傳 |
   | `GetAllSettingNames()` | `string[] GetAllSettingNames()` | 不支援時在 `Log.Warning` 後回傳 `null` |
   | `GetAllSettingNames(List<string>)` | `void GetAllSettingNames(List<string> results)` | 若 `results == null` 則拋出 `GameFrameworkException("Results is invalid.")`，否則執行 `results.Clear()` |
   | `HasSetting` / `RemoveSetting` / `RemoveAllSettings` | 介面參考 | 委派給自有的儲存 |
   | `GetBool/Int/Float/String`、`SetBool/Int/Float/String` | 介面參考 | 委派給自有的儲存。不存在時回傳規定的預設值 |

   完整簽章請參閱 [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L42-L42) 與 [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L43-L43)。

3. **將讀寫委派給具體的儲存**。最小範例：以記憶體字典模擬儲存。

   ```csharp
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
       private readonly Dictionary<string, string> _store = new Dictionary<string, string>();

       public override int Count => _store.Count;

       public override bool Load() { return true; }

       public override bool Save() { /* 寫回檔案/資料庫 */ return true; }

       public override bool HasSetting(string settingName) => _store.ContainsKey(settingName);

       public override bool RemoveSetting(string settingName) => _store.Remove(settingName);

       public override void RemoveAllSettings() => _store.Clear();

       public override void SetString(string settingName, string value) => _store[settingName] = value;

       public override string GetString(string settingName, string defaultValue)
           => _store.TryGetValue(settingName, out var v) ? v : defaultValue;

       // Bool/Int/Float 同理。Bool 可透過 SetInt/GetInt 以 0/1 形式儲存（參考 PlayerPrefsSettingHelper）。
   }
   ```

   出處： [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L42-L42)（基底類別的標準實作範例。示範如何將 `GetBool`/`SetBool` 委派給底層的 `StorageBackend.GetInt/SetInt`）

4. **將腳本附加到場景中的 GameObject**。`SettingHelperBase` 繼承自 `MonoBehaviour`，因此必須附加到 GameObject 上，才能被 `SettingComponent` 偵測並實例化。

5. **在 `SettingComponent` 的 Inspector 中選擇 `Custom Setting Helper`**。將 `Setting Helper Type` 設定為你的 `MySettingHelper` 後，框架啟動時會以反射方式產生 Helper。

   出處： [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)（`SettingComponent` 負責 `ISettingHelper` 實例的產生與持有）

## 常見變化

- **不修改 Helper，僅切換底層儲存後端**：若想繼續使用 `PlayerPrefsSettingHelper`，但希望底層改用 SQLite/WeChat 小遊戲 SDK 等，請實作 `ISettingStorageBackend`，並在啟動時透過 `SettingStorageBackendFactory.RegisterMiniGameBackend` 註冊。在 `PlayerPrefsSettingHelper` 內部，此後端會透過 `StorageBackend` 屬性延遲載入。

  ```csharp
  // 平台啟動時（僅在 UNITY_EDITOR 下生效）
  SettingStorageBackendFactory.RegisterMiniGameBackend(() => new MySqliteBackend());
  ```

  出處： [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

- **小遊戲平台的實作參考**：`WeChatMiniGameSettingStorage`、`AlipayMiniGameSettingStorage` 等已依照 `ISettingStorageBackend` 介面封裝平台原生 API，可作為最小實作範例參考。

  出處： [WeChatMiniGameSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/MiniGame/WeChat/WeChatMiniGameSettingStorage.cs)、[Storage/ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs)

## 常見錯誤

- **未繼承 `SettingHelperBase`**：也可以直接實作 `ISettingHelper`，但 `SettingComponent` 通常會以 `SettingHelperBase` 衍生類別進行掃描。維持繼承關係較為安全。
- **Helper 未附加到場景物件**：`SettingHelperBase` 是 `MonoBehaviour`，若未附加，框架將無法實例化，執行時會取得預設實作或拋出例外。
- **`GetAllSettingNames(List<string>)` 遺漏 `results == null` 檢查**：基底類別預期拋出 `GameFrameworkException("Results is invalid.")`，框架的其他模組依賴此規約。
- **在 Helper 的建構函式中存取 `UnityEngine.PlayerPrefs` 等執行時 API**：請勿在靜態建構函式或欄位初始化階段存取 Unity API。請在 `Load()` 內或首次存取時執行。
- **在儲存邏輯中吞掉例外**：寫入失敗時應回傳 `false`，讓 `SettingComponent` 能夠偵測失敗並發出通知。不得以 `try/catch` 靜默處理後回傳 `true`。

## 背景（可選）

`PlayerPrefsSettingHelper` 將所有讀寫委派給 `ISettingStorageBackend`，`SettingStorageBackendFactory` 在 `UNITY_EDITOR` 下使用 `UnityPlayerPrefsSettingStorage`，在實機小遊戲平台下則使用各平台轉接器所註冊的工廠。這是「無需重新實作 Helper 即可切換底層儲存」的快速路徑。只有在業務邏輯確實需要新 Helper 行為（遠端取得、加密、跨處理程序同步等）時，才依照本頁步驟實作自訂的 `SettingHelperBase` 衍生類別。
