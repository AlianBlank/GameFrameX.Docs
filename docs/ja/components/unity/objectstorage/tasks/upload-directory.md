# ディレクトリ全体をアップロードする方法

`IObjectStorageUploadManager.UploadDirectory(localDirectory)` を呼び出すことで、ローカルディレクトリ(およびその下にあるすべてのファイル)をオブジェクトストレージバケットにアップロードできます。ルートパスは `SetSavePath` で指定します。

## 前提条件

- `BaseObjectStorageUploadManager` を継承したアップロードマネージャーの実装がすでに存在していること(たとえば、具体的なクラウドサービス SDK に基づく実装)。
- `Init(accessKey, secretKey, bucketName, endpoint)` を呼び出して、認証情報とバケットの初期化が完了していること。
- `SetSavePath(savePath)` を呼び出してバケット内の保存ディレクトリを設定していること(末尾に区切り文字があるかどうかは問わず、実装内部で自動的に末尾の区切り文字が除去されます)。

## 操作手順

1. **アップロードマネージャーを初期化する**。`ObjectStorageUploadFactory` を通じて具体的な実装を取得し、認証情報とバケット名の設定を完了します。

```csharp
IObjectStorageUploadManager uploader = ObjectStorageUploadFactory.Create();
// 内部で具体的な実装の Init(accessKey, secretKey, bucketName, endpoint) を呼び出します
uploader.Init("your-access-key", "your-secret-key", "your-bucket-name");
```

2. **バケット内の保存パスを設定する**。`savePath` はバケット内でのファイルのルートディレクトリプレフィックスです。

```csharp
uploader.SetSavePath("/assets/Resources");
```

3. **`UploadDirectory` を呼び出してディレクトリ全体をアップロードする**。ローカルの絶対パスまたは相対パスを渡すと、ディレクトリ下のすべてのファイルが相対パスに従って `savePath` の下にアップロードされます。

```csharp
uploader.UploadDirectory("Assets/StreamingAssets/configs");
```

`UploadDirectory` の内部では、渡されたパスを `UploadRootPath` として記録し、その後抽象メソッド `UploadDirectoryInternal(localDirectory)` に処理を委譲します:

```csharp
public void UploadDirectory(string localDirectory)
{
    UploadRootPath = localDirectory;
    UploadDirectoryInternal(localDirectory);
}
```

## よくあるバリエーション

- **単一のファイルのみをアップロードする**: `uploader.UploadFile("Assets/StreamingAssets/configs/a.json")` を使用するように変更し、指定したファイルのみを `savePath` に格納します。
- **元のディレクトリ階層を保持する**: `UploadDirectoryInternal` を実装する際、`UploadRootPath` を基準にしてサブディレクトリのパスでオブジェクトキーを生成すれば、ローカルの構造を保持できます。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `Init` の前に `UploadDirectory` を呼び出すと NRE または認証エラーが発生する | 認証情報が注入されていない | 必ず `Init` → `SetSavePath` → `UploadDirectory` の順に呼び出す |
| アップロード後、バケット内のファイルがすべてルートディレクトリにまとまり、階層がない | `UploadDirectoryInternal` がサブディレクトリに基づいてオブジェクトキーを生成していない | `UploadRootPath` を基準に相対パスを計算し、オブジェクトキーのサフィックスとして使用する |
| `savePath` の末尾に区切り文字があるため、パスの連結で `//` が発生する | `SetSavePath` による正規化が行われていない | 必ず `SetSavePath` を通じて目標パスを設定し、実装が末尾の区切り文字を除去するようにする |

## 背景(任意)

`UploadDirectory` はルートディレクトリの記録と抽象メソッドのトリガーのみを担当し、実際の走査とアップロードのロジックは具体的な実装(`BaseObjectStorageUploadManager` を継承したもの)が `UploadDirectoryInternal` の中で完了します。通常はローカルファイルを再帰的に読み取り、`UploadRootPath` を除いた相対パスをオブジェクトキーの一部として使用します。
