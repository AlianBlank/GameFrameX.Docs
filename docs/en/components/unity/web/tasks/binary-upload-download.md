# How to Upload and Download Binary Data

Use the `GetToBytes` / `PostToBytes` series of methods of `WebComponent` to send or receive `byte[]` binary data. They all return `Task<WebBufferResult>`, so you can directly obtain the byte array result via `async/await`.

## Prerequisites

- The `WebComponent` component has been added to the scene (the entry point of the GameFrameX Web module).
- The method using `await` must be marked as `async` and have imported the `GameFrameX.Web.Runtime` namespace.
- The server must support the `application/octet-stream` content type — the framework always uses this Content-Type when sending binary requests.

## Steps

1. Get a `WebComponent` instance (e.g., via the GameEntry module manager).

2. Download binary: call `GetToBytes` and retrieve the byte array from the returned `WebBufferResult.Result`.

```csharp
WebBufferResult result = await GameEntry.Web.GetToBytes("https://example.com/assets/avatar.png");
byte[] bytes = result.Result; // Raw binary content returned by the server
```

The actual signature of `GetToBytes` in the `IWebManager` interface:

```csharp
Task<WebBufferResult> GetToBytes(string url, object userData = null);
Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, object userData = null);
```

Source: [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L26-L45)

3. Upload binary: call `PostToBytes` and pass in `byte[]` form data.

```csharp
byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello");
WebBufferResult result = await GameEntry.Web.PostToBytes(
    "https://example.com/api/upload",
    payload,
    null,   // queryString, can be null
    null,   // header, can be null
    "myTag" // userData, passed back as-is on callback
);
```

Source: [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L199-L209)

4. Read the result. `WebBufferResult` contains only two properties:

| Property | Type | Description |
|------|------|------|
| `Result` | `byte[]` | Raw byte array returned by the server |
| `UserData` | `object` | Custom data passed in with the request, returned as-is |

Source: [WebBufferResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebBufferResult.cs#L11-L19)

## Common Variants

**With query parameters and request headers**: the two dictionaries are merged into the URL and HTTP headers.

```csharp
var queryString = new Dictionary<string, string> { { "id", "1001" } };
var header = new Dictionary<string, string> { { "Authorization", "Bearer token" } };
WebBufferResult result = await GameEntry.Web.GetToBytes("https://example.com/file", queryString);
```

**Post object form**: in addition to the `byte[]` overload, `PostToBytes` also supports a `Dictionary<string, object>` form (serialized internally by the framework before sending):

```csharp
Task<WebBufferResult> PostToBytes(string url, Dictionary<string, object> from, object userData = null);
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L506-L508)

**WebGL platform**: the same set of APIs automatically switches to `UnityWebRequest` under WebGL and attaches the `DefaultBypassCertificate` certificate handler, with no need to modify the calling code.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Throws `TimeoutException` | Request timed out on non-WebGL platforms (`WebExceptionStatus.Timeout` is converted to `TimeoutException`) | Check network and server availability, or increase the manager's `RequestTimeout` setting |
| Throws `Exception` (with the original `unityRequest.error` text) | Under WebGL, `isNetworkError` / `isHttpError` is true | Diagnose based on the error text: 404 — check the URL; `crossdomain` — check cross-origin configuration |
| Throws `WebException` / `IOException` | Response stream read failure or connection interrupted on non-WebGL platforms | Add try/catch and retry; confirm the server returns a binary stream |
| Server receives garbled data | Server does not parse according to `application/octet-stream` | The framework always sends this Content-Type; the server must read the request body as raw bytes |

Source code for the timeout and exception conversion logic:

```csharp
// Catch timeout exceptions
if (e.Status == WebExceptionStatus.Timeout)
{
    webData.TaskSource.SetException(new TimeoutException(e.Message));
    return;
}
```

## Background

Binary requests are handled by the partial implementation `WebManager.Binary.cs` of `WebManager`: requests first enter the `m_WaitingBinaryQueue` waiting queue and are taken out one by one for execution by `UpdateBinary` under the `MaxConnectionPerServer` concurrency limit; non-WebGL platforms use `HttpWebRequest` + memory stream copying, while WebGL uses `UnityWebRequest`. `WebBinaryData` objects are reused via the reference pool and are automatically released when finished. For the overall structure of the Web module, see "Web Module Introduction".
