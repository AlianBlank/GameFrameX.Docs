# What to Do When Mini Game Platform Macro Definitions Don't Work

When you call `ApplicationHelper.IsWebGLWeChatMiniGame` (or other `IsWebGLXxxMiniGame` properties), it returns `false` regardless of whether you are actually running on a mini game platform—this usually means the corresponding macro definition has not taken effect properly. This article describes common error symptoms, root causes, and the steps to fix them.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Properties like `IsWebGLWeChatMiniGame` always return `false` on a real device | The corresponding `ENABLE_*_MINI_GAME` macro has not been added in **Project Settings → Player → Other Settings → Scripting Define Symbols** | Add the corresponding macro to Scripting Define Symbols according to the platform macro name table |
| Macros added but properties still return `false` (WebGL platform) | WebGL platform not selected; macros only take effect under `UNITY_WEBGL` | File → Build Settings → Switch Platform → WebGL |
| Compilation error: `The type or namespace name 'EnableWebglMiniGame' could not be found` | Wrote `#define ENABLE_WEBGL_MINI_GAME` directly, but the macro should be configured via Scripting Define Symbols | Use Project Settings instead of `#define` in source code |
| Compilation warnings or code stripped incorrectly (IL2CPP / AOT) | Used `#if` to check macros directly but forgot to also mark `[UnityEngine.Scripting.Preserve]` | Make sure the caller is preserved; refer to the property pattern in `ApplicationHelper.MiniGame.cs` |
| Macros don't take effect after switching platforms | Unity needs to trigger a script recompile and the IDE cache must be refreshed | Close and reopen the IDE / `Assets → Reimport All` |

## Fix Steps

### 1. Open Scripting Define Symbols Configuration

`Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`. Select the target platform, then add the required macros in the text box; separate multiple macros with semicolons, for example:

```text
ENABLE_WEBGL_MINI_GAME;ENABLE_WECHAT_MINI_GAME
```

Source: see the macro `ENABLE_WEBGL_MINI_GAME` used in [ApplicationHelper.MiniGame.cs#L17-L23](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L17-L23).

### 2. Confirm the Platform Has Been Switched to WebGL

All `IsWebGL*MiniGame` property checks use the pattern `#if UNITY_WEBGL && ENABLE_<PLATFORM>_MINI_GAME`. If the current Active Build Target is not WebGL, the preprocessor branch will return `false` directly.

Open `File → Build Settings`, select **WebGL** from the platform list on the left, then click **Switch Platform**. Once completed, Unity will trigger a full recompile.

### 4. Call the Corresponding Property in Code

Don't nest your own `#if` checks for macros—this is error-prone. Just call the properties on `ApplicationHelper` directly:

```csharp
using GameFrameX.Runtime;

if (ApplicationHelper.IsWebGLWeChatMiniGame)
{
    // WeChat Mini Game specific logic
}
else if (ApplicationHelper.IsWebGLDouYinMiniGame)
{
    // Douyin Mini Game specific logic
}
```

Source example (WeChat Mini Game branch):

```csharp
[UnityEngine.Scripting.Preserve]
public static bool IsWebGLWeChatMiniGame
{
    get
    {
#if UNITY_WEBGL && ENABLE_WECHAT_MINI_GAME
        return true;
#else
        return false;
#endif
    }
}
```

Source: [ApplicationHelper.MiniGame.cs#L33-L43](/Runtime/Helper/ApplicationHelper.MiniGame.cs#L33-L43)

## Verification

1. Add a line `Debug.Log($"WeChat={ApplicationHelper.IsWebGLWeChatMiniGame}")` in `Awake()` or in a debug button, then check the Console after running.
2. Switch between WebGL and non-WebGL platforms and log on each. The expected result is that all return `false` on non-WebGL, and only the platform whose macro is currently configured returns `true` on WebGL.
3. If it still returns `false`, go back to the diagnosis table and check item by item: is the platform WebGL, is the macro name spelled correctly, and has a recompile been triggered.

## Background

The framework exposes a static property for each mini game platform (all located in `GameFrameX.Runtime.ApplicationHelper`). The return value of `true`/`false` is decided at compile time through the combination of `UNITY_WEBGL` and each platform's macro, so it also works correctly during IL2CPP / AOT stripping. The actual source file for these properties can be found in [ApplicationHelper.MiniGame.cs](/Runtime/Helper/ApplicationHelper.MiniGame.cs).
