# How to Create and Start an FSM

Use `FsmComponent` to create a finite state machine that holds the specified Owner, pass in state instances, and call `Start<TState>()` to start polling—this drives entity behavior in the game. This page provides the complete minimum path from defining states to starting execution.

## Prerequisites

- The `com.gameframex.unity.fsm` package is installed.
- A GameObject with `FsmComponent` exists in the scene (the component carries `[GameFrameXAutoComponent(-6000)]` and is automatically registered when the framework starts).
- At least one state class inheriting from `FsmState<T>` is defined (see "How to Define an FsmState" for details).

## Steps

1. Get the `FsmComponent` instance.

   ```csharp
   var fsmComponent = GameEntry.GetComponent<FsmComponent>();
   ```

2. Call `CreateFsm<T>` to create the state machine, passing in the Owner and all initial state instances.

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
   ```

   The source definition of `FsmComponent.CreateFsm<T>(T owner, params FsmState<T>[] states)` is at [FsmComponent.cs#L197-L208](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L197-L208), internally forwarded to `IFsmManager.CreateFsm`.
   For the same Owner, you can also use the overload with `name` to create multiple coexisting instances:

   ```csharp
   IFsm<Player> fsm = fsmComponent.CreateFsm<Player>("Combat", player, new IdleState(), new AttackState());
   ```

3. Call `Start<TState>()` to make the FSM enter its first state.

   ```csharp
   fsm.Start<IdleState>();
   ```

   `Start<TState>()` triggers the target state's `OnEnter` and calls `OnUpdate` every frame starting from the next frame.
   See [IFsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/IFsm.cs) for the `Start` interface definition.

4. Switch states from within any state using `ChangeState<TState>(fsm)`.

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }
   }
   ```

## Common Variations

| Scenario | Invocation |
|------|----------|
| Multiple independent FSMs on the same Owner | Use `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` and distinguish by `name` |
| Add a new state at runtime | `fsm.AddState(new JumpState())` |
| Remove a state at runtime (cannot be the current state) | `fsm.RemoveState<IdleState>()` |
| Exit the current state, clear data, and restart | `fsm.Reset(); fsm.Start<IdleState>();` |
| Quick access via `GameApp` (requires `com.gameframex.unity.entry`) | `IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());` |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Log.Fatal("FSM manager is invalid.")` | The `IFsmManager` implementation was not obtained during the `Awake` phase, usually due to framework initialization order issues | Ensure `FsmComponent` is mounted on the framework root GameObject, and the GameFrameX framework components initialize before business scripts |
| `Start<TState>()` reports "state does not exist" | The state was not passed in during `CreateFsm`, or `RemoveState` was called subsequently | Add it to the `params FsmState<T>[] states` of `CreateFsm`, or call `AddState` before `Start` |
| FSM is not driven / `OnUpdate` does not trigger | `FsmComponent`'s `FixedUpdate` depends on `m_FsmManager` being non-null; if the component is not mounted or is disabled, Update will not execute | Confirm that an active `FsmComponent` exists in the scene |
| `CreateFsm` returns an existing instance for the same Owner | The old FSM is reused when the Owner and name are the same | Distinguish with a different `name`, or call `DestroyFsm` first and then create |

## Verification

- Add a log in `IdleState.OnEnter`; running the scene should immediately show one output.
- Add a log in `IdleState.OnUpdate`; running the scene should show output every frame, indicating that `FsmComponent.FixedUpdate` is driving the polling.
- Calling `fsm.IsRunning` should be `true`; calling `fsm.CurrentState` should return the type of the state just `Start`ed.
