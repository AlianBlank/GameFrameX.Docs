# 啟用 Objective-C/Swift 混編橋接

在 `XCodeConfig.json` 中把 `swiftBridging` 設為 `true`（或保持預設——該設定**預設開啟**），建置 iOS 專案後 GameFrameX 會自動產生 Swift 橋接檔案與橋接標頭檔案，並設定 `SWIFT_VERSION=5.0` 與 `SWIFT_OBJC_BRIDGING_HEADER`，全程無 Xcode 彈出視窗，可直接用於 CI。

## 前置條件

- 已在專案中引入 GameFrameX Xcode Config 套件，並按《XCodeConfig.json 設定總覽》完成基礎設定（本套件在 iOS 建置時自動執行後處理，無需手動呼叫任何 API）。
- 建置目標為 iOS 平台（相關程式碼位於 `#if UNITY_IOS` 區塊內）。

## 操作步驟

1. 開啟專案根目錄（或模組目錄）下的 `XCodeConfig.json`，將 `swiftBridging` 設為 `true`：

   ```json
   {
     "swiftBridging": true
   }
   ```

   > 該鍵可省略——省略時視為 `true`（預設開啟）。判定邏輯見下方原始碼：

   ```csharp
   // 設定 Swift 橋接（預設開啟）
   bool swiftBridging = !finalConfig.ContainsKey("swiftBridging") || finalConfig.Get<bool>("swiftBridging");
   SetupSwiftBridging(project, project.GetUnityMainTargetGuid(), project.GetUnityFrameworkTargetGuid(), path, swiftBridging);
   ```

   Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101)

2. 在 Unity 中執行 iOS 建置（File → Build Settings → Build），後處理階段會自動完成：

   - 在產生的 Xcode 專案根目錄建立 `gameframex_swift_bridging.swift`（不存在時寫入，內容為 `import Foundation`，檔案開頭標註 `DO NOT EDIT`）；
   - 建立 `Unity-iPhone-Bridging-Header.h` 橋接標頭檔案；
   - 將 `.swift` 檔案加入 UnityFramework target 編譯，將橋接標頭檔案加入專案；
   - 為主 target 與 UnityFramework target 設定 `SWIFT_VERSION = 5.0`，並為主 target 設定 `SWIFT_OBJC_BRIDGING_HEADER = Unity-iPhone-Bridging-Header.h`。

   核心實作：

   ```csharp
   proj.AddFileToBuild(frameworkTargetGuid, proj.AddFile(swiftFile, SwiftBridgingFileName, PBXSourceTree.Source));
   proj.AddFile(bridgingHeaderFile, SwiftBridgingHeaderName, PBXSourceTree.Source);

   proj.SetBuildProperty(mainTargetGuid, "SWIFT_VERSION", "5.0");
   proj.SetBuildProperty(mainTargetGuid, "SWIFT_OBJC_BRIDGING_HEADER", SwiftBridgingHeaderName);

   proj.SetBuildProperty(frameworkTargetGuid, "SWIFT_VERSION", "5.0");

   LogHelper.Log("[SwiftBridging] Swift bridging header configured");
   ```

   Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L37-L45)

3. 驗證結果：開啟產生的 `.xcodeproj`，選取 **Unity-iPhone** target → Build Settings：
   - `SWIFT_VERSION` 顯示 `5.0`；
   - `SWIFT_OBJC_BRIDGING_HEADER` 顯示 `Unity-iPhone-Bridging-Header.h`；
   - Unity Console 輸出 `[SwiftBridging] Swift bridging header configured`。

## 常見變體

- **關閉混編橋接**：明確寫入 `"swiftBridging": false`。`SetupSwiftBridging` 開頭有 `if (!enabled) return;`，關閉後不會建立任何檔案、不設定任何 Swift 建置屬性。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L12-L14)
- **在橋接標頭中公開 Objective-C 標頭**：橋接標頭檔案只在不存在的情況下產生、之後不會被覆寫（`File.Exists` 判斷），你可以直接在產生的 `Unity-iPhone-Bridging-Header.h` 中加入 `#import`，重複建置不會遺失你的修改。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L27-L35)
- **多模組協作**：多個 `XCodeConfig.json` 會被深度遞迴合併，最終以合併後的 `swiftBridging` 值生效；未在任何一份設定檔中寫明時預設為 `true`。
  Source: [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L100)

## 常見錯誤

- **Xcode 中未看到 Swift 檔案 / `SWIFT_OBJC_BRIDGING_HEADER` 為空**：多半是設定合併後 `swiftBridging` 被某份 `XCodeConfig.json` 明確設為 `false`。檢查所有參與合併的設定檔。
- **改了橋接標頭檔案內容又「消失」了**：檢查是否重新產生了 Xcode 專案目錄（Unity 覆寫匯出會重建目錄）。橋接標頭只在檔案不存在時寫入，建議把自訂 `#import` 放到不會被覆寫的穩定位置或由你自己的腳本注入。
- **Swift 語法錯誤 / 版本不符**：本套件固定寫入 `SWIFT_VERSION = 5.0`，不要手動在專案裡改回舊版本值，重複建置會被再次覆寫為 5.0。
  Source: [Editor/PostProcessBuildHelper.SwiftBridging.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.SwiftBridging.cs#L40-L43)

## 背景

該功能僅作用於 **Unity-iPhone（主）target 與 UnityFramework target**：Swift 檔案被加入 UnityFramework target 編譯，`SWIFT_OBJC_BRIDGING_HEADER` 只設定在主 target 上。與在 Xcode 中手動新增 Swift 檔案時彈出的「是否建立橋接標頭」對話框不同，此流程完全由後處理腳本完成，因此在 CI 環境下無人值守建置也不會被彈出視窗阻塞。
