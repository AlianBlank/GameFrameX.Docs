# Listening to Network Events (Connect/Disconnect/Error/Heartbeat Loss)

This page explains how to subscribe to and handle the four types of events raised by the network module: `NetworkConnectedEventArgs` (connection success), `NetworkClosedEventArgs` (connection closed), `NetworkErrorEventArgs` (network error), and `NetworkMissHeartBeatEventArgs` (heartbeat loss). All of these events inherit from `GameFrameX.Event.Runtime.GameEventArgs`, register subscriptions via each type's static field `EventId` (whose value equals the type's full name), and in the handling callback you can directly read the fields carried by the event.

## Prerequisites

- The GameFrameX network component has been imported (namespace `GameFrameX.Network.Runtime`).
- The event subscription entry point is provided by the **GameFrameX.Event component** (the `GameEventArgs` base class is located in `GameFrameX.Event.Runtime`; this component is not in this repository). Please confirm that the event component is enabled in your project before subscribing to the event Ids listed on this page.

## Steps

1. Confirm the events you want to listen to and the fields they carry (all located in the `GameFrameX.Network.Runtime` namespace):

| Event Class | Triggered When | Carried Fields | EventId Value |
|--------|----------|----------|------------|
| `NetworkConnectedEventArgs` | Network connection succeeds | `NetworkChannel` (`INetworkChannel`), `UserData` (`object`, custom data passed in when connecting) | `GameFrameX.Network.Runtime.NetworkConnectedEventArgs` |
| `NetworkClosedEventArgs` | Network connection closed | `NetworkChannel` (see source file for the full set of fields) | `GameFrameX.Network.Runtime.NetworkClosedEventArgs` |
| `NetworkErrorEventArgs` | Network error | `NetworkChannel`, `ErrorCode` (`NetworkErrorCode`), `SocketErrorCode` (`System.Net.Sockets.SocketError`), `ErrorMessage` (`string`) | `GameFrameX.Network.Runtime.NetworkErrorEventArgs` |
| `NetworkMissHeartBeatEventArgs` | Heartbeat packet lost | `NetworkChannel`, `MissCount` (`int`, number of losses so far) | `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs` |

2. Register callbacks with the event component using each event class's **static field** `EventId`; do not hand-write strings — the definition of `EventId` is simply the type's full name:

```csharp
/// <summary>
/// The event Id for the network connection success event.
/// </summary>
public static readonly string EventId = typeof(NetworkConnectedEventArgs).FullName;

/// <summary>
/// Gets the event Id for the network connection success event.
/// </summary>
public override string Id
{
    get { return EventId; }
}
```

Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L44-L54)

3. In the callback, read the fields according to the event type. Taking the error event as an example, you can obtain the framework-level error code, the Socket-level error code, and the error message at the same time:

```csharp
/// <summary>
/// Gets the network channel.
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// Gets the error code.
/// </summary>
public NetworkErrorCode ErrorCode { get; private set; }

/// <summary>
/// Gets the Socket error code.
/// </summary>
public SocketError SocketErrorCode { get; private set; }

/// <summary>
/// Gets the error message.
/// </summary>
public string ErrorMessage { get; private set; }
```

Source: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L68-L86)

4. When a heartbeat is lost, use `MissCount` to gauge the severity (this count increments with consecutive losses), combined with `NetworkChannel` to identify which channel it is:

```csharp
/// <summary>
/// Gets the network channel.
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// Gets the number of heartbeat packets lost so far.
/// </summary>
public int MissCount { get; private set; }
```

Source: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L65-L73)

5. **Do not cache the event object** after the callback returns. Event instances come from the reference pool (created via `ReferencePool.Acquire`, fields reset by `Clear()`), and the fields are cleared after the event is dispatched:

```csharp
public static NetworkConnectedEventArgs Create(INetworkChannel networkChannel, object userData)
{
    NetworkConnectedEventArgs networkConnectedEventArgs = ReferencePool.Acquire<NetworkConnectedEventArgs>();
    networkConnectedEventArgs.NetworkChannel = networkChannel;
    networkConnectedEventArgs.UserData = userData;
    return networkConnectedEventArgs;
}

/// <summary>
/// Clears the network connection success event.
/// </summary>
public override void Clear()
{
    NetworkChannel = null;
    UserData = null;
}
```

Source: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L77-L96)

## Common Variants

- **Reconnection after disconnection**: In the `NetworkMissHeartBeatEventArgs` (`MissCount` exceeding a threshold) or `NetworkClosedEventArgs` callback, record the channel information (address, etc., obtained from `NetworkChannel`), then re-initiate the connection after a delay; the connection result is then confirmed by `NetworkConnectedEventArgs`.
- **Distinguishing multiple channels**: When maintaining multiple connections simultaneously, compare `NetworkChannel` first (e.g., the channel name) in all callbacks before processing, to avoid mistaking channel A's error for channel B's.
- **Tiered error display**: Use `ErrorCode` for business logic branching, and `SocketErrorCode`/`ErrorMessage` for logging and user-facing message text.

## Common Errors

| Symptom | Cause | How to Avoid |
|------|------|----------|
| Events not received after hand-writing the subscription string | The string does not match the actual `EventId` (note the full namespace prefix `GameFrameX.Network.Runtime.`) | Always subscribe using static fields such as `NetworkConnectedEventArgs.EventId` |
| Fields read in the callback are `null` / `0` | The event object comes from the reference pool; `Clear()` has already reset the fields after dispatch | Read and copy the needed values immediately within the callback; do not cache the event instance |
| `SocketErrorCode` / `ErrorMessage` cannot be referenced | The `System.Net.Sockets` namespace is not imported | Add `using System.Net.Sockets;` at the top of the subscribing class file (this is how the error event source file imports it) |
| Compilation reports `GameEventArgs` not found | The event base class is in the GameFrameX.Event component, not in this repository | Install/enable the event component first |

## Background

All four event argument classes are `sealed class ... : GameEventArgs` and are marked with `[UnityEngine.Scripting.Preserve]` to prevent being stripped by code trimming; instances are obtained from the reference pool via the static `Create(...)`, and fields are reset before returning via `Clear()`. This is the framework's unified "reference pool event" pattern, which is also why data must be consumed immediately within the callback. The event class source code is located in the `Runtime/EventArgs/` directory ([NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs), [NetworkClosedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkClosedEventArgs.cs), [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs), [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs)); the error code enum can be found at `Runtime/Network/Base/NetworkErrorCode.cs`, and the heartbeat-handling related base classes can be found at `Runtime/Network/Helper/BasePacketHeartBeatHandler.cs` and `Runtime/Network/Base/IHeartBeatMessage.cs`. The event dispatch and subscription APIs belong to the GameFrameX.Event component; for overall usage of the event component, see its corresponding documentation.
