# 이벤트가 수신되지 않거나 콜백이 트리거되지 않음

`EventComponent.Subscribe(DownloadXxxEventArgs.EventId, ...)`로 구독한 후, 다운로드 시작·업데이트·성공·실패 네 가지 콜백이 한 번도 트리거되지 않거나 일부만 트리거되는 경우, 이 페이지의 진단 표에 따라 점검하세요.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 네 가지 이벤트가 모두 트리거되지 않음 | `EventComponent`가 `DownloadComponent`에 주입되지 않았거나, `DownloadComponent`가 마운트되지 않음 | 아래 "EventComponent와 DownloadComponent 확인" 참조 |
| `EventId`를 잘못 작성함 / 문자열 리터럴을 사용함 | 서로 다른 `*EventArgs` 클래스의 `EventId`는 `typeof(...).FullName`으로 생성되므로, 철자가 틀리면 매칭되지 않음 | 아래 "문자열 대신 EventId 상수 사용" 참조 |
| 구독은 성공했지만 실제 다운로드가 발생하지 않음 | `AddDownload` 인수의 `downloadPath` / `downloadUri`가 비어 있거나, `Paused = true`로 멈춰 있음 | 아래 "작업이 실제로 다운로드 큐에 진입했는지 확인" 참조 |
| Start만 수신되고 Success / Failure는 수신되지 않음 | `DownloadAgentHelperCount`가 0으로 설정되었거나, `m_CustomDownloadAgentHelper`가 할당되지 않음 | 아래 "에이전트 풀이 시작되지 않음" 참조 |
| `OnDownloadSuccess` 수신 후 `args.SerialId`가 일치하지 않음 | 콜백에서 모든 다운로드 작업을 동일한 작업으로 처리하거나, 구독 시점에 serialId를 아직 저장하지 않음 | 아래 "SerialId로 작업 구분" 참조 |
| 코루틴 종료 / 씬 전환 후 콜백 유실 | 구독이 바인딩된 객체가 파괴되었지만 `Unsubscribe`하지 않았거나, 새 씬에서 `Subscribe`를 여러 번 반복 실행함 | 아래 "구독 수명 주기 관리" 참조 |

## 해결 단계

### EventComponent와 DownloadComponent 확인

이벤트 체인은 두 컴포넌트가 동시에 존재해야 동작합니다. `DownloadComponent`는 내부에 하나의 `EventComponent` 참조만 가지며, 시작 시점에 주입되므로 누락되면 이벤트가 절대 디스패치되지 않습니다.

```csharp
var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
var eventComponent = GameEntry.GetComponent<EventComponent>();
if (downloadComponent == null || eventComponent == null)
{
    Debug.LogError("DownloadComponent와 EventComponent가 모두 GameEntry에 마운트되어 있는지 확인하세요");
}
```
[Runtime/Download/DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L62)에서 `DownloadComponent`는 `[GameFrameXAutoComponent(-4000)]` 자동 등록 컴포넌트이며, `EventComponent`는 `com.gameframex.unity.event` 의존성 패키지에서 제공됩니다([package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json) 참조).

### 문자열 대신 EventId 상수 사용

모든 `*EventArgs`의 `EventId`는 `typeof(...).FullName`으로 생성되므로, 정적 필드를 직접 사용하는 것이 가장 안전합니다:

```csharp
eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComponent.Subscribe(DownloadStartEventArgs.EventId, OnDownloadStart);
eventComponent.Subscribe(DownloadUpdateEventArgs.EventId, OnDownloadUpdate);
```
네 가지 이벤트 인수 클래스의 소스 코드:
- [DownloadSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadSuccessEventArgs.cs#L39-L42)
- [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L40-L42)

`"GameFrameX.Download.Runtime.DownloadSuccessEventArgs"` 같은 문자열을 직접 작성하지 마세요. 네임스페이스나 클래스 이름이 변경되는 순간 매칭에 실패합니다.

### 작업이 실제로 다운로드 큐에 진입했는지 확인

`AddDownload`는 `int serialId`를 반환하며, 작업이 실제로 에이전트에 발송되어야 Start가 트리거되고, 완료되어야 Success/Failure가 트리거됩니다. 먼저 serialId를 출력하고 상태를 폴링하여 확인하세요:

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);
Debug.Log($"serialId={serialId}");

TaskInfo info = downloadComponent.GetDownloadInfo(serialId);
Debug.Log($"status={info?.Status}, currentLength={info?.CurrentLength}");
```
`info == null`이거나 `Status`가 계속 `Waiting`이라면, 먼저 `downloadComponent.Paused`가 `true`인지 확인하세요.

### 에이전트 풀이 시작되지 않음

에이전트 수가 0이거나, 커스텀 Helper가 비어 있는데 `m_DownloadAgentHelperTypeName`이 존재하지 않는 타입을 가리키는 경우, 작업이 대기 큐에 쌓여 콜백이 절대 발생하지 않습니다:

- Inspector에서 `Download Agent Helper Count` ≥ 1인지 확인하세요(기본값 3, [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60) 참조).
- 커스텀 Helper를 사용할 때는 `m_CustomDownloadAgentHelper`를 입력하거나, `m_DownloadAgentHelperTypeName`이 유효한 타입 이름이 되도록 하세요. 둘 다 동시에 비어 있으면 안 됩니다.

### SerialId로 작업 구분

콜백은 모듈 전체에 브로드캐스트되며 작업을 구분하지 않습니다. 반드시 `args.SerialId`를 자신이 저장해 둔 serialId와 비교하세요:

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);

void OnDownloadSuccess(object sender, GameEventArgs e)
{
    var args = (DownloadSuccessEventArgs)e;
    if (args.SerialId == serialId)
    {
        // 내가 이번에 시작한 작업임
    }
}
```
소스 코드 예제는 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/README.zh-CN.md#L113-L126)를 참조하세요.

### 구독 수명 주기 관리

`EventComponent.Subscribe`는 강한 참조 콜백을 등록하며 `this`를 유지합니다. 구독한 객체가 파괴된 후에도 이벤트 큐에는 댕글링 참조가 남아 있고, 새 씬에서 `Subscribe`를 여러 번 실행하면 중복으로 트리거됩니다. 권장 방법:

1. `OnDestroy` / `OnDisable`에서 `eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess)`를 호출하세요.
2. 전역에서 한 번만 구독하고, 상주하는 매니저에 배치하세요. 매번 `Start()`가 실행될 때마다 수행되는 스크립트에 넣지 마세요.

## 검증

위 단계를 모두 완료한 후 작은 파일 다운로드를 한 번 실행하고, 모든 콜백에 `Debug.Log`를 추가하세요:

```csharp
void OnDownloadStart(object sender, GameEventArgs e) =>
    Debug.Log($"Start serialId={(e as DownloadStartEventArgs).SerialId}");

void OnDownloadUpdate(object sender, GameEventArgs e) =>
    Debug.Log($"Update {((DownloadUpdateEventArgs)e).CurrentLength}");

void OnDownloadSuccess(object sender, GameEventArgs e) =>
    Debug.Log($"Success {(e as DownloadSuccessEventArgs).DownloadPath}");

void OnDownloadFailure(object sender, GameEventArgs e) =>
    Debug.LogError($"Failure {(e as DownloadFailureEventArgs).ErrorMessage}");
```

정상적인 경우 Start → 몇 차례의 Update → Success 순으로 네 가지 이벤트가 각각 한 번씩 출력되며, Failure는 오류 발생 시에만 출력됩니다.
