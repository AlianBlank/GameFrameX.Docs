# 如何设置场景优先级与切换活跃场景

通过 `SceneComponent.SetSceneOrder` 为已加载 / 正在加载的场景分配一个数值,框架会在每次调整后自动把数值最大的场景设为 Unity 的活跃场景(`SceneManager.SetActiveScene`),并发出 `ActiveSceneChangedEventArgs` 事件。常用于 Additive 模式下多场景共存时,精确控制哪个场景作为逻辑主场景。

## 前置条件

- 项目已接入 GameFrameX 场景组件(`[AddComponentMenu("GameFrameX/Scene")]` 的 `SceneComponent`)和 YooAsset 资源管理。
- 场景资源路径必须以 `Assets/` 开头、以 `.unity` 结尾(框架会校验,否则打印 `Scene asset name '{0}' is invalid.`)。
- 调用 `SetSceneOrder` 之前,该场景必须已经处于「加载中」或「已加载」状态,否则框架打印 `Scene '{0}' is not loaded or loading.` 并忽略本次设置。
- 若需要监听切换结果,需注册 `ActiveSceneChangedEventArgs` 事件(参见《如何加载与卸载场景》)。

## 操作步骤

1. **获取场景组件**。在任意可访问 `GameEntry` 的脚本里:

```csharp
using GameFrameX.Scene.Runtime;

var sceneComponent = GameEntry.GetComponent<SceneComponent>();
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L49-L50)

2. **以 Additive 模式加载场景**。活跃场景切换依赖多个已加载场景并存,通常用 `LoadSceneMode.Additive`:

```csharp
await sceneComponent.LoadScene(
    "Assets/Scenes/Battle.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L294-L322)

3. **为场景分配优先级**。数值越大,优先级越高;相同数值时按 `m_SceneOrder`(`SortedDictionary<string,int>`)的枚举顺序决定胜负:

```csharp
// 把 Battle 设为最高优先级,它会被切换为活跃场景
sceneComponent.SetSceneOrder("Assets/Scenes/Battle.unity", 100);

// 再加载一个 HUD 场景,优先级低一些
await sceneComponent.LoadScene(
    "Assets/Scenes/HUD.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
sceneComponent.SetSceneOrder("Assets/Scenes/HUD.unity", 10);
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L352-L381)

4. **订阅活跃场景切换事件**(可选,用于在切换后刷新 UI、相机或重新派发主相机引用):

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Scene.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    ActiveSceneChangedEventArgs.EventId,
    (sender, args) =>
    {
        var e = (ActiveSceneChangedEventArgs)args;
        UnityEngine.Debug.Log($"Active: {e.ActiveSceneName} (prev: {e.LastActiveSceneName})");
        sceneComponent.RefreshMainCamera(); // 重新拿 Camera.main
    });
```

Source: [ActiveSceneChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/ActiveSceneChangedEventArgs.cs)

## 常见变体

**调整顺序立即生效**:`SetSceneOrder` 会调用内部的 `RefreshSceneOrder()`,把优先级最高且已加载的场景设为活跃;若新场景仍在 `isLoaded==false` 异步窗口期,框架会启动 `RefreshSceneOrderWhenLoadedCo` 协程等下一帧再激活。

**没有活跃候选时**:当 `m_SceneOrder` 为空,或所有登记的场景都仍在加载中,框架会把活跃场景回退到 GameFramework 自身场景(`m_GameFrameworkScene`)。

**多场景平级**:若两个场景优先级相同,枚举顺序靠后的胜出(因为 `RefreshSceneOrder` 用 `>` 比较后覆盖)。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| 调用 `SetSceneOrder` 后没生效,日志 `Scene '{0}' is not loaded or loading.` | 场景既不在「加载中」也不在「已加载」状态 | 先 `await LoadScene(...)` 再设置顺序 |
| 路径写错,日志 `Scene asset name '{0}' is invalid.` | 资源名不以 `Assets/` 开头或 `.unity` 结尾 | 使用完整的项目相对资产路径 |
| 抛出 `ArgumentException: sceneHandle.IsValid` 一类异常 | YooAsset `await` 完成时机早于 Unity 场景 `isLoaded==true` | 框架已在 `RefreshSceneOrder` 内部用协程延迟到下一帧,无需自行重试 |
| 重复连续调用 `SetSceneOrder` 导致旧协程仍在运行 | 框架已 `StopCoroutine` 旧协程后再启新的 | 无需手动管理;若自定义逻辑中混用其它激活方式,需避免与框架争抢 |
| 活跃场景切换后 `Camera.main` 仍指向旧相机 | 切换只换 Scene,不主动找新相机 | 调用 `sceneComponent.RefreshMainCamera()`,或订阅 `ActiveSceneChangedEventArgs` 后刷新 |

## 背景(可选)

`m_SceneOrder` 是一个 `SortedDictionary<string, int>`,以 `Ordinal` 比较键;`RefreshSceneOrder` 遍历它挑出最大值,然后调用私有 `SetActiveScene(...)` 把场景交给 Unity `SceneManager.SetActiveScene`,并通过 `m_EventComponent.Fire(this, ActiveSceneChangedEventArgs.Create(...))` 派发事件。Single 模式下 YooAsset/Unity 会自行管理活跃场景,框架检测到目标 Scene 句柄失效时直接跳过此次设置,以免在异步窗口期抛出 `ArgumentException`。
