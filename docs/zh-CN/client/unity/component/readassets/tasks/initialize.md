# 初始化与根路径获取

本页说明 `BlankReadAssets` 如何初始化,以及在不同平台上如何读取 `Root` 根路径。首次调用任意 API 时框架会自动完成初始化,大多数情况下你不需要手动调用,只有在你需要在其他 API 之前就拿到根路径时,才需要显式初始化。

## 前置条件

- 已通过 Unity Package Manager 引入 `com.gameframex.unity.readassets`。
- 项目中存在 `Assets/StreamingAssets/` 目录,且其中已放置待读取的资源。
- 已 `using GameFrameX.ReadAssets.Runtime;`。

## 操作步骤

1. **直接读取根路径(自动初始化)**。框架内部使用 `EnsureInitialized()` 守护懒加载,首次访问 `Root` 时自动调用 `Initialize()`。在 Android 平台,实现会切换到 `ApkImpl`;在 Editor、Standalone、iOS、WebGL 等平台,使用 `LooseFilesImpl`。

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    string root = BlankReadAssets.Root;
    UnityEngine.Debug.Log("StreamingAssets Root = " + root);
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L46-L54)

2. **手动调用无参初始化**。该重载使用 `Application.dataPath` 和 `Application.streamingAssetsPath` 作为初始化参数。

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    BlankReadAssets.Initialize();
    string root = BlankReadAssets.Root;
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L56-L61)

3. **使用自定义路径初始化**。在测试或外部资源目录场景下,传入任意 `dataPath` 与 `streamingAssetsPath`。

    ```csharp
    BlankReadAssets.Initialize(
        dataPath: "/path/to/your/project",
        streamingAssetsPath: "/path/to/your/project/Assets/StreamingAssets");
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L63-L68)

4. **非 Android 平台下,`Root` 取自 `streamingAssetsPath`**。LooseFilesImpl 会把传入的 `streamingAssetsPath` 转为绝对路径、替换反斜杠、去掉末尾斜杠后赋给 `s_root`。

    ```csharp
    // LooseFilesImpl.Initialize 中的实现
    s_root = Path.GetFullPath(streamingAssetsPath).Replace('\\', '/').TrimEnd('/');
    ```

    Source: [BlankReadAssets.LooseFilesImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L17-L20)

5. **Android 平台下,`Root` 为 APK 路径**。ApkImpl 会把 `dataPath` 赋给 `s_root`,并在找不到内容时回退到 `base.apk`;patch overlay 场景下,`s_root` 为 `pram-shadow-files` 目录。

    ```csharp
    // ApkImpl.Initialize 中的实现
    s_root = dataPath;
    ```

    Source: [BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

## 常见变体

- **Editor 中指定外部 APK 文件进行读取**。仅在 `UNITY_EDITOR` 下可用,允许在编辑器里模拟 Android 的压缩 APK 路径访问。

    ```csharp
    BlankReadAssets.InitializeWithExternalApk("/path/to/your.apk");
    string root = BlankReadAssets.Root;
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

- **Editor 中使用外部 StreamingAssets 目录**。与 InitializeWithExternalApk 配对,关闭 ApkMode 后仍以目录方式读取。

    ```csharp
    BlankReadAssets.InitializeWithExternalDirectories(
        dataPath: "/path/to/project",
        streamingAssetsPath: "/path/to/project/Assets/StreamingAssets");
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

- **关闭懒加载、提前完成初始化**。某些场景(例如应用启动后立即检查文件存在)希望在调用其他 API 之前就完成初始化,可显式调用无参 `Initialize()`。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| `Root` 为空字符串或异常路径 | 在 Android 上没有等到 APK 路径就读取,而 ApkImpl 的 `s_root` 依赖 `dataPath` | 使用 `BlankReadAssets.Initialize()` 让框架用 `Application.dataPath` 完成初始化,或先访问任意一个 API 触发 `EnsureInitialized` |
| Editor 下把 APK 当作目录遍历 | 没有调用 `InitializeWithExternalApk` | 显式调用 `InitializeWithExternalApk(apkPath)` 切换到 ApkImpl |
| 自定义路径时报 `ArgumentNullException` | `dataPath` 或 `streamingAssetsPath` 传了 null | 检查上游配置,避免空值传入 `Initialize(string, string)` |

## 背景(可选)

平台实现通过 `using BlankReadAssetsImpl = ...` 静态别名按编译期条件切换,确保不同目标平台调用不同的 `Initialize`。`EnsureInitialized()` 与 `s_initialized` 静态标志共同保证初始化只发生一次,后续所有读取 API 都会复用第一次的结果,这也是为何 `Root` 可被任意位置安全访问。
