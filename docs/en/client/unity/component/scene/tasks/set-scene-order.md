# How to Set Scene Priority and Switch the Active Scene

Use `SceneComponent.SetSceneOrder` to assign a numeric value to a loaded or loading scene. The framework will automatically set the scene with the largest value as Unity's active scene (`SceneManager.SetActiveScene`) after each adjustment, and emit the `ActiveSceneChangedEventArgs` event. This is commonly used to precisely control which scene serves as the logical main scene when multiple scenes coexist in Additive mode.

## Prerequisites

- The project has integrated the GameFrameX scene component (`SceneComponent` with `[AddComponentMenu("GameFrameX/Scene")]`) and YooAsset resource management.
- The scene asset path must start with `Assets/` and end with `.unity` (the framework validates this; otherwise it prints `Scene asset name '{0}' is invalid.`).
- Before calling `SetSceneOrder`, the scene must already be in a "loading" or "loaded" state; otherwise the framework prints `Scene '{0}' is not loaded or loading.` and ignores this assignment.
- To listen for switch results, subscribe to the `ActiveSceneChangedEventArgs` event (see "How to Load and Unload Scenes").

## Steps

1. **Get the scene component**. In any script that can access `GameEntry`:

```csharp
using GameFrameX.Scene.Runtime;

var sceneComponent = GameEntry.GetComponent<SceneComponent>();
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L49-L50)

2. **Load scenes in Additive mode**. Active scene switching relies on multiple loaded scenes coexisting, typically using `LoadSceneMode.Additive`:

```csharp
await sceneComponent.LoadScene(
    "Assets/Scenes/Battle.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L294-L322)

3. **Assign priority to scenes**. The larger the value, the higher the priority; when values are equal, the enumeration order of `m_SceneOrder` (`SortedDictionary<string,int>`) decides the winner:

```csharp
// Set Battle as the highest priority; it will be switched to the active scene
sceneComponent.SetSceneOrder("Assets/Scenes/Battle.unity", 100);

// Load another HUD scene with a lower priority
await sceneComponent.LoadScene(
    "Assets/Scenes/HUD.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
sceneComponent.SetSceneOrder("Assets/Scenes/HUD.unity", 10);
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L352-L381)

4. **Subscribe to the active scene switched event** (optional, used to refresh UI, cameras, or re-dispatch the main camera reference after switching):

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Scene.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    ActiveSceneChangedEventArgs.EventId,
    (sender, args) =>
    {
        var e = (ActiveSceneChangedEventArgs)args;
        UnityEngine.Debug.Log($"Active: {e.ActiveSceneName} (prev: {e.LastActiveSceneName})");
        sceneComponent.RefreshMainCamera(); // Re-acquire Camera.main
    });
```

Source: [ActiveSceneChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/ActiveSceneChangedEventArgs.cs)

## Common Variations

**Adjustments take effect immediately**: `SetSceneOrder` calls the internal `RefreshSceneOrder()` to set the scene with the highest priority that is already loaded as the active scene; if the new scene is still in the `isLoaded==false` async window, the framework starts the `RefreshSceneOrderWhenLoadedCo` coroutine to wait until the next frame before activation.

**No active candidates**: When `m_SceneOrder` is empty, or all registered scenes are still loading, the framework falls back to the GameFramework's own scene (`m_GameFrameworkScene`) as the active scene.

**Equal-priority scenes**: If two scenes have the same priority, the one enumerated later wins (because `RefreshSceneOrder` uses `>` for comparison before overwriting).

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| `SetSceneOrder` has no effect, log shows `Scene '{0}' is not loaded or loading.` | Scene is neither in "loading" nor "loaded" state | Call `await LoadScene(...)` first, then set the order |
| Incorrect path, log shows `Scene asset name '{0}' is invalid.` | Asset name does not start with `Assets/` or end with `.unity` | Use the full project-relative asset path |
| Throws `ArgumentException: sceneHandle.IsValid` or similar exception | YooAsset `await` completion timing is earlier than Unity scene `isLoaded==true` | The framework already uses a coroutine inside `RefreshSceneOrder` to delay to the next frame; no manual retry needed |
| Repeated consecutive `SetSceneOrder` calls leave old coroutines still running | The framework already calls `StopCoroutine` on old coroutines before starting new ones | No manual management needed; if mixing other activation methods in custom logic, avoid competing with the framework |
| After active scene switches, `Camera.main` still points to the old camera | Switching only changes the Scene, not actively finding a new camera | Call `sceneComponent.RefreshMainCamera()`, or subscribe to `ActiveSceneChangedEventArgs` and refresh |

## Background (Optional)

`m_SceneOrder` is a `SortedDictionary<string, int>` that compares keys using `Ordinal`; `RefreshSceneOrder` iterates through it to pick the maximum value, then calls the private `SetActiveScene(...)` to hand the scene off to Unity's `SceneManager.SetActiveScene`, and dispatches the event via `m_EventComponent.Fire(this, ActiveSceneChangedEventArgs.Create(...))`. In Single mode, YooAsset/Unity manage the active scene themselves; the framework detects when the target Scene handle becomes invalid and skips this assignment directly, avoiding throwing `ArgumentException` during the async window.
