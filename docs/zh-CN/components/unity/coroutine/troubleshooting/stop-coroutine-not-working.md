# 调用了 StopCoroutine 但协程没停怎么办

你调用了 `CoroutineComponent.StopCoroutine(...)`,但协程依然在跑,直到场景关闭或 `StopAllCoroutines` 才被清掉。这通常是因为传入的 `IEnumerator` 实例与启动时使用的不是同一个引用,导致组件内部跟踪表无法命中。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `StopCoroutine(ienumerator)` 调用后协程仍在跑 | 传入的不是启动时的同一个 `IEnumerator` 实例,字典查不到,只能回退到 `base.StopCoroutine`,但 `base` 路径并没有真正跟踪到这个协程 | 保存 `StartCoroutine` 时传入的原始 `IEnumerator` 引用,停止时传同一个变量 |
| 用 `StartCoroutine` 返回的 `UnityEngine.Coroutine` 停止无效 | 调用的是基类 `MonoBehaviour.StopCoroutine` 路径,而没有从跟踪表中移除该协程 | 改为调用 `CoroutineComponent` 实例上的 `StopCoroutine(UnityEngine.Coroutine)` 重载 |
| `WaitForEndOfFrameFinish` 的回调在停止后仍触发了 | 在 `yield return WaitForEndOfFrame` 还未到下一帧时停止,该帧结束后回调依然会跑 | 在停止协程前先把 `callback` 置空,或改用条件判断 |

## 修复步骤

### 场景 1:`StopCoroutine(IEnumerator)` 没生效

`CoroutineComponent` 用 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 跟踪所有启动过的协程,key 是 `IEnumerator` 引用。字典未命中时,源码会走 `base.StopCoroutine(enumerator)` 分支:

```csharp
public new void StopCoroutine(IEnumerator enumerator)
{
    if (m_CoroutineMap.TryGetValue(enumerator, out var coroutine))
    {
        base.StopCoroutine(coroutine);
        m_CoroutineMap.TryRemove(enumerator, out _);
    }
    else
    {
        base.StopCoroutine(enumerator);
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

解决方法:把启动时传入的 `IEnumerator` 保存到字段里,停止时传同一个引用。

```csharp
private IEnumerator _runningRoutine;

void Start()
{
    _runningRoutine = MyRoutine();
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StartCoroutine(_runningRoutine);
}

void StopMyRoutine()
{
    // 传回同一个实例,_runningRoutine 是字典的 key
    GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
        .StopCoroutine(_runningRoutine);
}

IEnumerator MyRoutine()
{
    while (true) { yield return null; }
}
```

### 场景 2:用 `UnityEngine.Coroutine` 重载停止无效

如果拿到的是 `StartCoroutine` 返回的 `UnityEngine.Coroutine`,必须用第二个重载,源码会遍历字典找到对应条目并移除:

```csharp
public new void StopCoroutine(UnityEngine.Coroutine coroutine)
{
    base.StopCoroutine(coroutine);
    foreach (var item in m_CoroutineMap)
    {
        if (item.Value == coroutine)
        {
            m_CoroutineMap.TryRemove(item.Key, out _);
            break;
        }
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L56-L67)

常见错误:把 `Coroutine` 引用丢给第一个重载 `StopCoroutine(IEnumerator)`,字典查不到,落进 `else` 分支。

### 场景 3:一次性清掉所有协程

如果只想干脆全部停下,直接用 `StopAllCoroutines` 重载,它会逐个停止并清空字典:

```csharp
GameFrameX.Runtime.GameFrameXEntry.GetComponent<CoroutineComponent>()
    .StopAllCoroutines();
```

源码先遍历字典逐一停止、再调用 `base.StopAllCoroutines()` 处理未跟踪的协程:

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

## 验证

1. 在协程内部加 `Debug.Log` 周期性输出,调用 `StopCoroutine` 后 1 秒内不再有新日志。
2. 在 Unity Profiler 的 Memory 面板查看 `Coroutine`,看后台任务是否还在增长。
3. 若协程内嵌 `yield return new WaitForSeconds(...)`,停止后该 `WaitForSeconds` 不应再完成回调。
