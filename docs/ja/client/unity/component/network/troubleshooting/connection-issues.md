# 接続失敗または接続中断が発生した場合の対処方法

接続失敗や接続中断が発生した際、GameFrameX Network は `NetworkErrorEventArgs`（`ErrorCode`、`SocketErrorCode`、`ErrorMessage` を含む）および `NetworkConnectedEventArgs` / `NetworkClosedEventArgs` という接続状態イベントを通じて、エラーコードと `NetworkCloseReason` の切断理由を上位層に渡します。まずこれらのイベントを購読してエラーコードを取得し、下表のエラーコード/切断理由と照らし合わせて問題を特定・修正してください。

## クイック診断

| 症状（エラーコード / 切断理由） | 根本原因 | 修正方法 |
|------|------|------|
| 切断理由が `ConnectAddressError` | サーバーアドレスまたはポートの形式エラー（URL にスキームがない、ポート番号が範囲外など） | 接続アドレスを確認。下記の「アドレスとポートの確認」を参照 |
| 切断理由が `ConnectAddressExceptionError` | アドレス解析時に例外が発生（不正な IP 文字列、DNS 失敗など） | 有効なアドレスに変更して解析を検証。下記の「アドレスとポートの確認」を参照 |
| エラーコード `AddressFamilyError` | 設定された `AddressFamily` がアドレスの実際のファミリーと不一致（IPv4/IPv6 の不整合） | チャンネルの AddressFamily をサーバーアドレスと一致させる。下記の「AddressFamily の確認」を参照 |
| エラーコード `ConnectError`、`SocketErrorCode` が `ConnectionRefused` / `TimedOut` | サーバーがリッスンしていない、ファイアウォールによる遮断、またはネットワーク到達不可 | サーバーが起動済みでポートが開放されていることを確認 |
| エラーコード `SocketError` / `SendError` / `ReceiveError` | 下位層の Socket が送受信段階でエラーを発生 | `SocketErrorCode` で特定。よくあるのは接続が相手側で切断された後に送受信を継続したケース |
| 切断理由が `MissHeartBeat`、エラーコード `MissHeartBeatError` | ハートビートタイムアウトにより切断と判定 | ハートビート間隔を調整し、「フォーカス制御ハートビート」設定を確認。下記の「ハートビート切断の調査」を参照 |
| 切断理由が `Timeout`（WebSocket） | WebSocket の接続確立タイムアウトにより保護的な切断が発動 | ws/wss アドレスとサーバー側のハンドシェイク所要時間を確認し、必要に応じて接続タイムアウト保護を含むバージョンへアップグレード（CHANGELOG を参照） |

上記のエラーコードと切断理由はいずれもソースコード内の実際の定義であり、完全な値は [NetworkErrorCode.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkErrorCode.cs#L38-L136) を参照してください：

## 修正手順

### ステップ 1：エラー・切断イベントを購読して実際のエラーコードを取得する

`NetworkComponent` の初期化時に、チャンネルイベントはすでに `m_NetworkManager` の `NetworkConnected` / `NetworkClosed` などのイベントへブリッジされています：

```csharp
m_NetworkManager.NetworkConnected += OnNetworkConnected;
m_NetworkManager.NetworkClosed += OnNetworkClosed;
```

Source: [NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L108-L110)

エラーイベントは 3 つの診断フィールドを保持しており、`SocketErrorCode` は `System.Net.Sockets.SocketError` の生の値です：

```csharp
public INetworkChannel NetworkChannel { get; private set; }
public NetworkErrorCode ErrorCode { get; private set; }
public SocketError SocketErrorCode { get; private set; }
public string ErrorMessage { get; private set; }

public static NetworkErrorEventArgs Create(INetworkChannel networkChannel, NetworkErrorCode errorCode, SocketError socketErrorCode, string errorMessage)
```

Source: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L71-L104)

エラーコールバック内で `ErrorCode`、`SocketErrorCode`、`ErrorMessage` の 3 つの値をログ出力し、上の診断表と照らし合わせてください。

### アドレスとポートの確認

1. 切断理由に `ConnectAddressError` または `ConnectAddressExceptionError` が含まれる場合、まずアドレス文字列自体が有効か確認してください：TCP では `IP:端口`、WebSocket では `ws://host:port` または `wss://host:port` を使用します。
2. Unity と同一ネットワーク上のマシンから、`telnet host port`（TCP）またはブラウザでの直接アクセス（WebSocket）によってサーバーへの到達性を検証してください。接続できない場合は、まずサーバーのリッスンまたはファイアウォールの問題を解決してください。
3. 同一アドレスを使用する複数のチャンネルインスタンスを同時に起動し、サーバー側から能動的に拒否されているケースがないか確認してください。

### AddressFamily の確認

`AddressFamilyError` は、設定されたアドレスファミリーが実際のアドレスと一致しないことを示します。サーバーアドレスが IPv6（またはドメイン名が IPv6 に解決される）であるにもかかわらず、チャンネルが IPv4（`InterNetwork`）で接続しようとするケースでよく発生します。チャンネル初期化時に使用する `NetworkAddressFamily` をサーバーアドレスの実際のファミリーと一致させれば、このエラーは解消されます。選択可能なファミリーの定義は [NetworkAddressFamily.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Base/NetworkAddressFamily.cs) を参照してください。

### ハートビート切断の調査

1. `MissHeartBeat` / `MissHeartBeatError` が発生した場合、チャンネルが予期した時間内にハートビート応答を受信できず、コンポーネントが「ハートビート喪失」として接続を切断したことを示します。
2. 本パッケージは「フォーカス制御ハートビート」（アプリのバックグラウンド移行時にハートビートを一時停止、フォアグラウンド復帰時に再開）をサポートしています。バックグラウンド移行/フォアグラウンド復帰のロジックがサーバーのタイムアウトしきい値と整合しているか確認してください：バックグラウンド滞在時間が長すぎるとサーバー側でタイムアウトと判定されます。
3. ハートビート間隔の上限値またはサーバー側のタイムアウト時間を適切に引き上げてから、再テストを行ってください。

## 検証

- 再接続後、`NetworkConnected` イベントが正常に発火し、一定期間 `NetworkErrorEventArgs` や `NetworkClosedEventArgs`（切断理由が `Normal` 以外）を受信しなくなること。
- WebSocket チャンネルでは、長時間のサスペンド（バックグラウンド移行後にフォアグラウンドへ復帰）でも `Timeout` による切断が発生しなくなること。
- ハートビートのシナリオで `NetworkMissHeartBeatEventArgs` イベントが発生しなくなること（[NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs) を参照）。

## 背景

エラーと切断は 2 本のイベントチェーンに分離されています：瞬間的なエラーは `NetworkErrorEventArgs`（細粒度のエラーコード + 生の `SocketError`）、接続ライフサイクルは `NetworkConnectedEventArgs` / `NetworkClosedEventArgs`（`NetworkCloseReason` を含む）で処理されます。WebSocket の接続タイムアウト保護、接続イベントの順序、`SystemTcpNetworkChannel` の受信失敗処理などの問題は CHANGELOG で修正済みです。不可解な切断に遭遇した場合は、まずパッケージのバージョンが最新であることを確認してください。詳細は [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/CHANGELOG.md) を参照してください。
