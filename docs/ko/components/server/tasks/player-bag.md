# 플레이어 가방(Bag) 모듈 구현

이 작업을 완료하면 사용 가능한 플레이어 가방 컴포넌트를 얻게 됩니다: 아이템 추가, 제거, 사용 및 가방 전체 데이터 조회를 지원하며, 데이터는 Actor 상태를 통해 자동으로 영속화되고, 아이템 변경 시 클라이언트에 능동적으로 푸시됩니다.

## 사전 조건

- 프레임워크의 Actor/Component 체계 구축이 완료되었고, `StateComponent`, `StateComponentAgent`의 기본 사용법을 이해하고 있어야 합니다.
- 아이템 설정 테이블 `TbItemConfig`가 `ConfigComponent`를 통해 등록되어 있어야 합니다(코드에서 `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(itemId, out _)`로 아이템 존재 여부를 검증).
- 클라이언트/서버가 ProtoBuf 프로토콜 기반의 `Proto/_0100_Bag.cs`에서 `ReqBagInfo`, `RespBagInfo`, `ReqAddItem`, `RespAddItem`, `ReqRemoveItem`, `RespRemoveItem`, `ReqUseItem`, `RespUseItem`, `NotifyBagInfoChanged`, `NotifyBagItem` 등의 메시지 타입을 생성했습니다.

### 3. Hotfix 계층에서 BagComponentAgent 구현

`GameFrameX.Hotfix/Logic/Player/Bag/BagComponentAgent.cs`에서 `StateComponentAgent<BagComponent, BagState>`를 상속받아 「추가 / 제거 / 사용 / 조회」 네 가지 핵심 메서드를 구현합니다. 모든 메서드는 먼저 `ConfigComponent`를 통해 아이템 존재 여부를 검증한 후, 상태를 수정하고 `OwnerComponent.WriteStateAsync()`를 통해 영속화합니다.

```csharp
using GameFrameX.Apps.Player.Bag.Component;
using GameFrameX.Apps.Player.Bag.Entity;
using GameFrameX.Config;
using GameFrameX.Config.Tables;

namespace GameFrameX.Hotfix.Logic.Player.Bag;

public class BagComponentAgent : StateComponentAgent<BagComponent, BagState>
{
    public async Task<BagState> UpdateChanged(INetWorkChannel netWorkChannel, Dictionary<int, long> itemDic)
    {
        var bagState = OwnerComponent.State;
        var notifyBagInfoChanged = new NotifyBagInfoChanged();
        foreach (var item in itemDic)
        {
            var notifyBagItem = new NotifyBagItem() { ItemId = item.Key };
            if (bagState.List.TryGetValue(item.Key, out var value))
            {
                value.Count += item.Value;
                notifyBagItem.Count = value.Count;
                notifyBagItem.Value = item.Value;
            }
            else
            {
                bagState.List[item.Key] = new BagItemState() { Count = item.Value, ItemId = item.Key };
                notifyBagItem.Count = item.Value;
                notifyBagItem.Value = item.Value;
            }

            notifyBagInfoChanged.ItemDic[item.Key] = notifyBagItem;
        }

        // netWorkChannel가 null이면 오프라인 지급을 의미합니다: 가방만 영속화하고 클라이언트에 알림을 푸시하지 않습니다
        if (netWorkChannel != null)
        {
            await netWorkChannel.WriteAsync(notifyBagInfoChanged);
        }

        await OwnerComponent.WriteStateAsync();
        return bagState;
    }
}
```

```csharp
public async Task OnAddBagItem(INetWorkChannel netWorkChannel, ReqAddItem message, RespAddItem response)
{
    foreach (var item in message.ItemDic)
    {
        if (!ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(item.Key, out var itemConfigState))
        {
            response.ErrorCode = (int)OperationStatusCode.NotFound;
            return;
        }
    }

    var result = await UpdateChanged(netWorkChannel, message.ItemDic);
    if (result.IsNull())
    {
        response.ErrorCode = (int)OperationStatusCode.Unprocessable;
    }
}
```

### 4. RPC 핸들러 노출

`GameFrameX.Hotfix/Logic/Player/Bag/ReqBagInfoHandler.cs`에서 `MessageMapping` 특성을 사용해 `ReqBagInfo` 메시지를 `BagComponentAgent`로 라우팅하여, 클라이언트가 가방을 조회하는 진입점으로 사용합니다. 다른 메시지(`ReqAddItem` / `ReqRemoveItem` / `ReqUseItem`)도 같은 방식으로 Handler를 작성하면 됩니다.

```csharp
[MessageMapping(typeof(ReqBagInfo))]
internal sealed class ReqBagInfoHandler : PlayerRpcComponentHandler<BagComponentAgent, ReqBagInfo, RespBagInfo>
{
    protected override async Task ActionAsync(ReqBagInfo request, RespBagInfo response)
    {
        try
        {
            await ComponentAgent.OnReqBagInfoAsync(NetWorkChannel, request, response);
        }
        catch (Exception e)
        {
            LogHelper.Fatal(e);
            response.ErrorCode = (int)OperationStatusCode.InternalServerError;
        }
    }
}
```

### 5. 조회 로직 구현

`OnReqBagInfoAsync`는 상태의 아이템 목록을 응답 메시지의 `Dictionary<int, long>(ItemId -> Count)`로 변환하여, 클라이언트가 한 번에 전체 가방을 가져올 수 있게 합니다.

```csharp
public async Task OnReqBagInfoAsync(INetWorkChannel netWorkChannel, ReqBagInfo message, RespBagInfo response)
{
    var bagState = OwnerComponent.State;
    if (bagState.IsNotNull())
    {
        response.ItemDic = bagState.List.ToDictionary(x => x.Key, x => x.Value.Count);
    }

    await Task.CompletedTask;
}
```

## 일반적인 변형

- **오프라인 보상 지급**: `UpdateChanged(netWorkChannel: null, itemDic)`를 호출합니다. `netWorkChannel`이 `null`이면 클라이언트 푸시를 건너뛰고 영속화만 수행하며, 우편 첨부물, 로그인 보상 등 통합 보상 지급 인터페이스에 적합합니다.
- **아이템 사용 소모**: `OnUseBagItem`에서 수량이 0이 되면 해당 아이템을 `bagState.List`에서 직접 제거하고 `value.Count`를 0으로 초기화합니다. 동시에 `NotifyBagInfoChanged`를 통해 클라이언트에 푸시합니다.
- **제거 검증**: `OnRemoveBagItem`은 아이템 수량이 부족하면 `OperationStatusCode.Unprocessable`를 바로 반환하고, 아이템이 존재하지 않으면 `OperationStatusCode.NotFound`를 반환합니다.

## 일반적인 오류

- **컴포넌트 미등록**: `BagComponent`는 반드시 `[ComponentType(GlobalConst.ActorTypePlayer)]`로 표시해야 합니다. 그렇지 않으면 플레이어 Actor에 해당 컴포넌트가 마운트되지 않아 `OwnerComponent.State`에서 데이터를 가져올 수 없습니다.
- **설정 테이블 미구성**: `OnAddBagItem` / `OnRemoveBagItem` / `OnUseBagItem` 모두 `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)`로 아이템을 검증하며, 아이템이 구성되지 않은 경우 `NotFound`를 바로 반환하고 상태를 작성하지 않습니다.
- **오프라인 보상 지급 시 네트워크 채널 전달**: 온라인에서 변경을 봐서는 안 되는 클라이언트가 푸시를 받게 되어 데이터 동기화에 이상이 생길 수 있습니다. 오프라인 시나리오에서는 `null`을 전달해야 합니다.
- **차감 후 영속화 누락**: `bagState.List`를 수정하는 모든 분기는 반드시 `await OwnerComponent.WriteStateAsync();`를 호출해야 합니다. 그렇지 않으면 상태가 메모리에만 존재하게 되어 프로세스 재시작 후 손실됩니다.

## 배경(선택)

- `BagComponent`는 `StateComponent<BagState>`이며, Actor 프레임워크가 직렬화와 영속화를 담당합니다. Hotfix 계층의 `BagComponentAgent`는 `OwnerComponent`를 통해 `BagState` 인스턴스를 얻어 그 자리에서 수정합니다.
- 아이템 추가 / 사용 후, 서버가 능동적으로 `WriteAsync(notifyBagInfoChanged)`를 호출하여 변경 증분을 클라이언트에 푸시함으로써 클라이언트의 폴링을 방지합니다.
