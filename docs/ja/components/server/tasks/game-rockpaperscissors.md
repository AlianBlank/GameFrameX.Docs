# じゃんけん(RockPaperScissors)玩法の実装

このページでは、GameFrameX.Server において既存のじゃんけん玩法コードを基に、複数プレイヤーが拳を出し、サーバーが同期的に勝敗を判定してゲーム状態をリアルタイムにクライアントへ返す一連のルーム内玩法を接続する方法を紹介します。完了すると、以下の完全なフローを実現できます：プレイヤーが拳を提出し、サーバーがルールに従って勝敗を判定し、ゲーム状態をリアルタイムにプレイヤーへフィードバックする。

## 前提条件

- GameFrameX.Server メインプロジェクトをコンパイル・実行済みで、フレームワークの Actor/Component/MessageHandler 機構が利用可能である。
- すでに `RoomHandlerHelper.GetCurrentRoleId(netWorkChannel)` があり、ネットワークチャネルから現在のプレイヤー ID を取得できる。じゃんけん玩法はこの同じ認証パスを再利用する。
- クライアントが下記3種類のメッセージに対応するリクエスト/レスポンス処理を実装済みである。

## 玩法メッセージ一覧

メッセージ番号は Proto 内で `(MainId << 16) + SubId` で割り当てられ、じゃんけんメインモジュール ID は `410`。

| メッセージ名 | メッセージ番号 | 方向 | 主なフィールド |
|--------|--------|------|----------|
| `ReqRockPaperScissorsGameInfo` | `(410 << 16) + 10` | C→S | `RoomId` |
| `RespRockPaperScissorsGameInfo` | `(410 << 16) + 11` | S→C | `GameInfo`、`ErrorCode` |
| `ReqSubmitRockPaperScissorsGesture` | `(410 << 16) + 12` | C→S | `RoomId`、`Gesture` |
| `RespSubmitRockPaperScissorsGesture` | `(410 << 16) + 13` | S→C | `GameInfo`、`ErrorCode` |
| `ReqRestartRockPaperScissorsGame` | `(410 << 16) + 14` | C→S | `RoomId` |
| `RespRestartRockPaperScissorsGame` | `(410 << 16) + 15` | S→C | `GameInfo`、`ErrorCode` |

`RockPaperScissorsGesture` 列挙の値：`None = 0`、`Rock = 1`、`Scissors = 2`、`Paper = 3`。クライアントは勝敗確定前に見るすべてのプレイヤーの `Gesture` は一律 `None` となり、確定後にのみ実際の出した拳を読み取ることができる。

## サーバー側データ構造

サーバー側は `RockPaperScissorsGameListState` をグローバルキャッシュとして使用し、`RoomId` をキーとして各ルームのじゃんけん1局分のデータ `RockPaperScissorsGameState` を保存します。そのうち `GestureMap` は各プレイヤーの本局での出した拳を記録します。

```csharp
public sealed class RockPaperScissorsGameListState : CacheState
{
    // Key: 部屋ID、Value: じゃんけんの玩法データ。
    public Dictionary<long, RockPaperScissorsGameState> Games { get; set; }
        = new Dictionary<long, RockPaperScissorsGameState>();
}

public sealed class RockPaperScissorsGameState
{
    public long RoomId { get; set; }
    public int Round { get; set; } = 1;
    // プレイヤーの出した拳の記録。Key: プレイヤーID, Value: 出した拳。
    public Dictionary<long, RockPaperScissorsGesture> GestureMap { get; set; }
        = new Dictionary<long, RockPaperScissorsGesture>();
    // 勝利したプレイヤーID。引き分けの場合は0。
    public long WinnerRoleId { get; set; }
}
```

Source: [RockPaperScissorsGameComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Game/RockPaperScissors/Component/RockPaperScissorsGameComponent.cs#L36-L38)

2. **現在のプレイヤー ID の解析**。すべての Handler は統一されたヘルパークラスを通じて `INetWorkChannel` から `RoleId` を読み取ります。Handler 内で直接パースしないでください：

```csharp
internal static class RockPaperScissorsHandlerHelper
{
    public static long GetCurrentRoleId(INetWorkChannel netWorkChannel)
    {
        return RoomHandlerHelper.GetCurrentRoleId(netWorkChannel);
    }
}
```

Source: [RockPaperScissorsHandlerHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/RockPaperScissors/RockPaperScissorsHandlerHelper.cs#L36-L41)

3. **3つのメッセージハンドラの実装**。`GameFrameX.Hotfix/Logic/Game/RockPaperScissors/` 配下にそれぞれ配置します：
   - `ReqRockPaperScissorsGameInfoHandler`：ルームの現在局情報を読み取って返す。
   - `ReqSubmitRockPaperScissorsGestureHandler`：プレイヤーの出した拳を記録し、全員が出した後に勝敗を確定して `WinnerRoleId` を書き込む。`GameInfo` を返送する（`Gesture` フィールドは確定前は外部に対して `None` を維持）。
   - `ReqRestartRockPaperScissorsGameHandler`：`GestureMap` をリセットし、`Round` をインクリメントし、前局の `WinnerRoleId` をクリアして次局で再出拳できるようにする。

4. **クライアントプロトコルの整合性確保**。クライアントは上表「メッセージ番号」に従ってリクエスト構造体を構築し、送信前に `Clear()` を呼び出し、レスポンス受信後に `ErrorCode` と `GameInfo.Players` を読み取り、`HasGesture` でプレイヤーが出拳済みかどうかを判定する。

## よくあるバリエーション

- **2人プレイヤーシーン**：`GestureMap` のレコード数がちょうど2件になった時点で勝敗を確定し、勝者を `WinnerRoleId` に書き込む。2つの拳が同じ場合は `0` のまま引き分けとする。
- **多人数プレイヤーシーン**：「任意の2人の出した拳が同じ場合、他のプレイヤーは継続する」といったルールに拡張可能で、ロジックは `ReqSubmitRockPaperScissorsGestureHandler` 内部に記述し、Proto の変更は不要。
- **1局のリプレイ**：クライアントは確定結果を受信後、`ReqRestartRockPaperScissorsGame`（`(410 << 16) + 14`）を呼び出して `Round` をインクリメントし `GestureMap` をクリアする。プレイヤーは再出拳可能となる。

## よくあるエラー

- **対戦相手の出した拳を直接読み取る**：サーバーは確定前に `Gesture` を `None` に設定するため、クライアントが確定を待たずに読み取ると、常に `None` しか表示されない。
- **`Clear()` を呼び忘れる**：Proto メッセージオブジェクトを再利用する場合、残ったフィールドにより古い `RoomId` / `Gesture` が新しいリクエストに伝播するため、必ず `Send` 前に `req.Clear()` を呼び出す。
- **権限を超えるアクセス**：Handler 内で独自に `RoleId` をパースせず、必ず `RockPaperScissorsHandlerHelper.GetCurrentRoleId(netWorkChannel)` を経由して、なりすましを防ぐ。
- **ルームを横断したデータの混線**：すべての読み書きは `RoomId` を辞書キーとして `RockPaperScissorsGameListState.Games` にアクセスし、静的フィールドでルーム状態を保存してはならない。
