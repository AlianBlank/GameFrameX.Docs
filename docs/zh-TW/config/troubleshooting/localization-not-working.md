# 本地化文字未生效時的處理方法

儘管已在 `Excels/Local/` 中新增或修改多語言條目，但執行時卻未顯示新文字時，通常是 **Luban 未能掃描到對應的本地化表格**，或 **在程式碼生成時未指定本地化參數** 所導致。本頁面將介紹常見症狀與快速的修正步驟。

## 快速診斷

| 症狀 | 原因 | 修正 |
|------|------|------|
| 啟動後僅顯示 Key(例:`Text_001`)而非翻譯文字 | 本地化檔案未被 LuBan 載入 | 確認生成命令中包含 `-x l10n.textFile.path=./Excels/Local/` |
| 新增的 `L-Localization-*.xlsx` 未生效 | 檔案名稱不符合 `L-Localization-` 前綴，或未放置於 `Excels/Local/` | 重新命名為 `L-Localization-<分類>.xlsx` 並放置於 `Excels/Local/` 目錄 |
| 生成 `Localization.xlsx` 後仍發生欄位不足的錯誤 | `luban.conf` 的 `localizationFileName` 未設定或拼字錯誤 | 在對應 target 的 command 中加入 `"localizationFileName": "Localization.xlsx"` |
| 切換語言後仍顯示來源語言的文字 | 執行階段程式碼未重新載入本地化表格 / 未觸發重新生成 | 刪除舊的生成產物，重新執行 `gen-client-json.sh`(或對應的 .bat) |
| 打包用戶端後，遠端文字變為空字串 | JSON 資料目錄(例:`Bundles/Config`)未更新 | 重新執行 `gen-client-bin.sh`,以生成的 JSON 覆寫 `outputDataDir` |

## 修正步驟

### 1. 確認本地化檔案的位置與命名

本地化檔案必須放置於 `Excels/Local/` 目錄，且須以 `L-Localization-` 開頭。儲存庫的範例中已包含 3 個本地化檔案：

- `Excels/Local/L-Localization-UI.xlsx`
- `Excels/Local/L-Localization-成就.xlsx`
- `Excels/Local/L-Localization-文本.xlsx`

新增的本地化檔案也請遵循相同的命名規則。

### 2. 在生成命令中啟用本地化

儲存庫隨附的 `gen-client-json.sh` 已明確傳入本地化相關參數：

```bash
dotnet ./Tools/Luban.dll --target client --dataTarget json --codeTarget cs-simple-json \
  --xargs outputDataDir=../Unity/Assets//Bundles/Config \
  --xargs outputCodeDir=../Unity/Assets//Hotfix/Config/Generate \
  --xargs tableImporter.name=gameframex \
  -x l10n.provider=gameframex \
  -x l10n.textFile.keyFieldName=key \
  -x l10n.textFile.path=./Excels/Local/ \
  --conf ./Luban.conf
```

出處:[gen-client-json.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.sh#L1-L1)

若命令中未包含 `-x l10n.textFile.path=./Excels/Local/` 或 `-x l10n.provider=gameframex`,請新增後重新生成。

### 3. 在 `luban.conf` 中宣告 `localizationFileName`

在 `luban.conf` 中，必須為生成本地化資料的 target 加入 `localizationFileName` 欄位(預設名稱 `Localization.xlsx`):

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

出處:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

### 4. 重新生成並覆寫生成產物

- 用戶端 JSON:`gen-client-json.sh`(或 `gen-client-json.bat`)。生成產物會輸出至 `%UNITY_ASSETS_PATH%/Bundles/Config`。
- 用戶端二進位檔:`gen-client-bin.sh`。生成位置同樣為 `Bundles/Config`,但輸出格式為 `cs-bin`。
- 伺服器：伺服器目前不需要本地化(`server` target 沒有 `localizationFileName`)。若需要在伺服器端啟用多語言，請參考 `client` 的寫法加入 `localizationFileName` 欄位。

### 5. 確認表格標頭與 `keyFieldName`

`-x l10n.textFile.keyFieldName=key` 表示本地化表格中必須有名為 `key` 的欄。若表格標頭的欄位名稱不是 `key`(例如寫成 `Key` 或 `ID`),載入將會失敗。處理方式：在 Excel 中將首欄名稱改為 `key`,或將生成命令中的 `keyFieldName` 改為表格實際的欄位名稱。

## 驗證

1. 重新執行對應的生成腳本，確認 `active: true` 的設定未被停用。
2. 確認生成目錄(例:`Bundles/Config` 或 `%SERVER_PATH%/Server.Config/Json`)中已生成並更新 `Localization.xlsx` 及其衍生資料。
3. 在執行階段程式碼中以 `key` 取得本地化文字，確認切換語言後回傳的是對應的翻譯文字，而非空字串或來源語言。
4. 若仍只顯示 `key` 本身，表示本地化資料未被載入。請確認步驟 2 的命令中是否包含 `-x l10n.textFile.path`,以及 `Excels/Local/` 下是否確實存在 `L-Localization-*.xlsx`。
