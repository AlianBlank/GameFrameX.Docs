# 시작 실패/데이터베이스 연결 오류 시 대처 방법

서비스가 시작 단계에서 크래시하거나 로그에 Mongo 연결 오류가 나타날 때, 일반적으로 `--DataBaseUrl` / `--DataBaseName` 설정 오류, Mongo 컨테이너 미준비, 또는 네트워크/인증 실패가 원인입니다. 이 페이지는 신속하게 원인을 파악하고 복구하는 데 도움을 드립니다.

## 빠른 진단

| 증상 | 원인 | 복구 |
|------|------|------|
| 시작 로그에 `connection refused` / `No connection could be made` 포함 | Mongo 포트에 도달할 수 없거나 주소 오기 | `--DataBaseUrl`의 호스트와 포트 확인 |
| 시작 로그에 `Authentication failed` / `authSource` 오류 포함 | 인증 소스 또는 계정/비밀번호 불일치 | 연결 문자열 `?authSource=...`와 자격 증명 수정 |
| 시작 로그에 `Database name cannot be empty` 또는 데이터베이스 누락 알림 포함 | `--DataBaseName` 미전달 또는 데이터베이스 이름 오타 | `--DataBaseName=xxx` 추가 |
| 컨테이너 시작 순서 이상: Game이 Mongo보다 먼저 시작됨 | `depends_on`이 healthcheck 통과를 대기하지 않음 | `condition: service_healthy`를 사용하여 Mongo 대기 |
| 로컬에서 docker 내 Mongo 연결 실패 | 포트가 외부에 노출되지 않았거나 노출 포트 오기 | `docker-compose.yml`의 `ports` 매핑과 대조 |

## 복구 단계

### 1. `--DataBaseUrl`과 `--DataBaseName` 확인

시작 파라미터에는 데이터베이스 연결 문자열과 데이터베이스 이름을 명시적으로 전달해야 합니다. `docker-compose.yml`의 기본값은 다음과 같습니다:

```yaml
command:
  - "--DataBaseUrl=mongodb://mongo:27017/?authSource=admin"
  - "--DataBaseName=gameframex"
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L36-L37)

로컬에서 docker 내 Mongo에 직접 연결하려면 `mongodb://localhost:37017/?authSource=admin`을 사용하십시오(compose 파일의 `37017:27017` 포트 매핑에 해당). 멀티 서버 버전은 `localhost:47017`과 `gameframex_multi`를 사용합니다.

```yaml
ports:
  - "37017:27017"
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L7-L7)

```yaml
ports:
  - "47017:27017"
```

Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L23-L23)

### 2. Mongo 헬스 체크 통과 대기

Game과 Social 서비스는 반드시 Mongo `healthcheck`가 통과된 후 시작되어야 합니다. compose에서 이미 `condition: service_healthy` 제약이 적용되어 있으므로 `service_started`로 변경하지 마십시오.

```yaml
depends_on:
  mongo:
    condition: service_healthy
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L21-L23)

헬스 체크 명령은 `ping`을 사용하여 도달 가능성을 검증합니다:

```yaml
healthcheck:
  test: [ "CMD", "mongosh", "--quiet", "--eval", "db.runCommand({ ping: 1 }).ok" ]
  interval: 5s
  timeout: 3s
  retries: 20
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L9-L12)

Mongo 상태를 수동으로 검증:

```bash
docker exec -it gfx-mongo mongosh --quiet --eval "db.runCommand({ ping: 1 }).ok"
# 예상 출력: 1
```

### 3. 데이터 볼륨과 영속성 확인

멀티 서버 버전은 Mongo 데이터를 `./running-multi/mongo:/data/db`에 마운트하며, 호스트 디렉터리 권한이 부족하거나 디스크가 가득 차면 Mongo가 반복적으로 재시작되어 Game 연결이 불안정해집니다.

```yaml
volumes:
  - "./running-multi/mongo:/data/db"
```

Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L30-L31)

디렉터리가 쓰기 가능하고 충분한 공간이 있는지 확인하십시오:

```bash
ls -ld ./running-multi/mongo
df -h ./running-multi/mongo
```

### 4. 인증 소스 수정

기본적으로 계정/비밀번호가 비활성화되어 있으며, `?authSource=admin`은 관리 데이터베이스 식별 용도로만 사용됩니다. Mongo에서 `mongod --auth`를 활성화한 경우 URL에 자격 증명을 추가하고 `authSource`를 실제 인증 데이터베이스로 변경해야 합니다(일반적으로 `admin`).

```bash
# 인증 활성화 시 연결 문자열 예시
--DataBaseUrl=mongodb://user:password@mongo:27017/?authSource=admin
```

## 검증

복구 완료 후, 다음 순서로 확인하십시오:

1. Mongo 헬스 상태 확인: `docker ps`로 `STATUS` 열에 `(healthy)`가 포함되어 있는지 확인합니다.
2. Game 서비스 재시작: `docker compose up -d --force-recreate game`, 로그에 Mongo 오류가 더 이상 나타나지 않는지 관찰합니다.
3. Mongo 컨테이너 진입하여 데이터베이스 생성 확인: `docker exec -it gfx-mongo mongosh --quiet --eval "show dbs"`, `gameframex` 또는 `gameframex_multi`가 보여야 합니다.
4. 여전히 실패하면 시작 로그(`docker logs gfx-game | tail -200`)를 수집하여 진단 표와 대조하며 계속 원인을 파악하십시오.

## 일반적인 오류

- **컨테이너 내부 호스트명으로 로컬 데이터베이스에 접근**. 호스트 머신에서 직접 클라이언트를 실행할 때, `--DataBaseUrl`의 `mongo` 호스트를 해석할 수 없으므로 `localhost` 또는 호스트 머신 IP로 변경해야 합니다.
- **포트 매핑 변경 후 URL 동기화 누락**. `ports` 수정 후 `--DataBaseUrl`의 포트도 동기화해야 하며, 그렇지 않으면 Game이 여전히 이전 포트로 연결을 시도합니다.
- **`depends_on`에 `service_started`만 작성**. 이는 컨테이너 프로세스 시작만 대기할 뿐 Mongo 초기화 완료를 기다리지 않아, 일시적인 연결 실패가 반복해서 발생합니다.
- **Mongo 재시작 후 Game이 자동으로 재연결되지 않음**. 기본값은 `restart: unless-stopped`이며, Game이 다시 연결되려면 수동으로 `docker compose restart game`을 실행해야 합니다.
