# "Localization manager is invalid / Base component is invalid" 怎麼辦

這兩條 Fatal 日誌分別來自 `LocalizationComponent` 的 `Awake()` 與 `Start()`:`Awake()` 裡透過 `GameFrameworkEntry.GetModule<ILocalizationManager>()` 取不到本地化管理器模組,或 `Start()` 裡透過 `GameEntry.GetComponent<BaseComponent>()` 找不到 Base 元件時輸出,隨後元件直接 `return`,本地化功能無法運作。絕大多數情況是「本地化實作組件未隨套件編譯/被裁剪」或「場景裡缺少 GameFrameX 基礎元件」，依下方診斷表逐條排查即可恢復。

## 修復步驟

### 步驟 1:確認實作組件存在

`LocalizationComponent.Awake()` 中以介面型別取得模組：

```csharp
m_LocalizationManager = GameFrameworkEntry.GetModule<ILocalizationManager>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L216)

`GetModule` 傳回 null 意味著 `ILocalizationManager` 的具體實作類別(`LocalizationManager`)沒有被註冊到 `GameFrameworkEntry`,通常是它所在的實作組件沒有參與編譯。依序檢查：

1. 開啟 Unity Console,先清除所有 **編譯錯誤(Compiler Error)**——存在編譯錯誤時 Unity 會跳過部分組件編譯，模組註冊隨之遺失，這是最常見的誘因。
2. 確認本套件 `Runtime` 目錄下的執行階段 asmdef(`GameFrameX.Localization`)已匯入且未被移除；本套件元件宣告為 `[RequireComponent(typeof(GameFrameXLocalizationCroppingHelper))]`,若 Inspector 裡出現 Missing Script,表示執行階段組件缺失或未編譯成功。
3. 若專案啟用了 GameFrameX 的元件裁剪/模組移除機制，確認本地化模組沒有被剔除。

### 步驟 2:補齊 BaseComponent

`Base component is invalid.` 的判定依據是 `Start()` 中的尋找：

```csharp
BaseComponent baseComponent = GameEntry.GetComponent<BaseComponent>();
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L227)

1. 在場景中掛載 `LocalizationComponent` 的同一 GameFrameX 根物件上，確認存在 `BaseComponent`(以及 `EventComponent`、`SettingComponent`,`Start()` 同樣依賴它們)。
2. 若 Inspector 中顯示 "Missing (Mono Script)",表示對應腳本未編譯或組件缺失——回到步驟 1 清除編譯錯誤。
3. 不要手工在多個物件上分散掛載這些元件；`GameEntry.GetComponent<T>()` 期望它們在框架入口上。

### 步驟 3:核對本地化 Helper

`Start()` 裡隨後會按序列化欄位建立 Helper,失敗時輸出 `Can not create localization helper.`:

```csharp
LocalizationHelperBase localizationHelper = Helper.CreateHelper(m_LocalizationHelperTypeName, m_CustomLocalizationHelper);
if (localizationHelper == null)
{
    Log.Fatal("Can not create localization helper.");
    return;
}
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L249-L254)

在 `LocalizationComponent` 的 Inspector 中核對 `m_LocalizationHelperTypeName`,預設值為完整型別名稱：

```csharp
[SerializeField] private string m_LocalizationHelperTypeName = "GameFrameX.Localization.Runtime.DefaultLocalizationHelper";
```

Source: [Runtime/Localization/LocalizationComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L73)

如果改用了自訂 Helper,要麼在 `m_CustomLocalizationHelper` 欄位拖入參考，要麼保證 `m_LocalizationHelperTypeName` 是「命名空間.類別名稱， 組件名稱」形式的完整可解析型別名稱。

## 驗證

1. 重新進入 Play 模式，Console 中不再出現 `Localization manager is invalid.`、`Base component is invalid.` 等上述 Fatal 日誌。
2. `Start()` 正常執行完畢後會初始化語言：非編輯器模式下當 `Language == UnknownLocalization` 時自動採用 `SystemLanguage`,並最終設定 `DefaultLanguage`(來源見 [LocalizationComponent.cs 第 261-272 行](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/Localization/LocalizationComponent.cs#L261-L272))。可用 `LocalizationComponent.Language`、`DefaultLanguage`、`DictionaryCount` 斷言元件已可用。
3. 呼叫一次取詞介面(如 `GetLocalizedString`/`GetRawString` 系列)能傳回字串而非空，即確認整條鏈路初始化成功。
