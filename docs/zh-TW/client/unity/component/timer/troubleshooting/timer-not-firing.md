# 計時器不觸發或查詢回傳 -1 怎麼辦

計時器不回呼，或 `GetRemaining` / `GetElapsed` / `GetRepeatLeft` 回傳 `-1`,通常屬於以下幾類：回呼為 null 導致 `Add` 直接失敗並回傳 0、計時器剛 `Add` 完還沒被 `Update` 刷入 `_items`、重複次數已耗盡或已被 `Remove`、被 `Pause` 後未 `Resume`、`Scaled` 模式下 `Time.timeScale` 為 0。本頁按症狀提供診斷表與對應修復步驟(以下範例假定你已持有 `TimerManager` / `ITimerManager` 實例，Unity 側經 `TimerComponent` 轉發同名方法)。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `Add` 回傳 0,主控台輸出 `timer callback is null, {interval},{repeat}` | `callback` 參數為 null,註冊被拒絕 | 檢查回呼非空再註冊，見[修復 1](#1-add-回傳-0-回呼為-null) |
| 剛 `Add` 完立即查詢 `GetRemaining`/`GetElapsed`/`GetRepeatLeft` 回傳 -1 | 計時器還在 `_toAdd` 佇列，要等下一次 `Update` 結尾才刷入 `_items` | 等一幀再查，或先用 `Exists(id)` 判斷，見[修復 2](#2-剛-add-完查詢回傳--1計時器尚未被-update-刷新) |
| `AddOnce` 觸發一次後再查詢回傳 -1 | `repeat` 減到 0 後計時器被刪除並從 `_ids` 移除，屬正常行為 | 需要再次觸發就重新 `Add`,見[修復 3](#3-重複次數耗盡或已被-remove) |
| `Exists(id)` 為 true 但一直不觸發 | 曾呼叫 `Pause(id)` 未 `Resume`;或 `Scaled` 模式且 `Time.timeScale = 0` | 呼叫 `Resume(id)`;或改用預設 `Unscaled`,見[修復 4](#4-被-pause-後未恢復)、[修復 5](#5-scaled-模式且-timetimescale-為-0) |
| 同一回呼註冊第二個計時器後，第一個計時「歸零重來」 | 回呼委派是字典鍵，重複 `Add` 會原地重置(`Elapsed = 0`) | 每個計時器用獨立回呼/lambda,見[修復 6](#6-同一回呼重複註冊導致計時被重置) |
| 某個回呼拋出例外後，後續回呼都不執行 | `TimerManager.CatchCallbackExceptions` 預設 `false`,例外直接拋出中斷本輪分發 | 設為 `true` 定位問題回呼，見[修復 7](#7-回呼拋例外吞掉後續回呼) |

## 修復步驟

### 1. `Add` 回傳 0:回呼為 null

`Add` 的完整簽名與失敗分支如下，`callback == null` 時只輸出警告並回傳 0,該 ID 永遠不會觸發：

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
{
    lock (Locker)
    {
        if (callback == null)
        {
            Debug.LogWarning("timer callback is null, " + interval + "," + repeat);
            return 0;
        }
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217-L225)

註冊後先檢查回傳值：

```csharp
int id = timerManager.Add(1f, 0, OnTick);
if (id == 0)
{
    // 回呼為 null,註冊失敗,這裡不應繼續持有該 id
}
```

### 2. 剛 `Add` 完查詢回傳 -1:計時器尚未被 `Update` 刷新

新計時器先進入 `_toAdd`,在 `Update` 結尾才被刷入 `_items`;而查詢方法只有在 `_items` 中找到未刪除的條目才回傳有效值，否則回傳 -1:

```csharp
public float GetRemaining(int id)
{
    lock (Locker)
    {
        if (!_ids.TryGetValue(id, out var callback))
        {
            return -1f;
        }

        if (_items.TryGetValue(callback, out var t) && !t.Deleted)
        {
            // ...回傳剩餘時間
        }

        // Timer is in _toAdd (not yet flushed)
        return -1f;
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L552-L575)

刷入發生在 `Update` 的最後一步，所以「本幀註冊、本幀查詢」必然得到 -1:

```csharp
if (_toAdd.Count > 0)
{
    var enumerator = _toAdd.GetEnumerator();
    while (enumerator.MoveNext())
    {
        _items.Add(enumerator.Current.Key, enumerator.Current.Value);
    }

    enumerator.Dispose();
    _toAdd.Clear();
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L153-L163)

**修復方式**：把查詢挪到下一幀(協程 `yield return null`、或放到另一個每幀回呼裡)，或先判斷 `Exists(id)`——它同時檢查 `_toAdd` 與 `_items`,對「尚未刷新」的計時器回傳 true。

### 3. 重複次數耗盡或已被 `Remove`

`repeat > 0` 的計時器每次觸發遞減，減到 0 即被標記刪除；刪除時會把 ID 從 `_ids` 移除，之後所有按 ID 的查詢都回傳 -1。`AddOnce` 內部就是 `repeat = 1`,觸發一次即銷毀;`repeat = 0` 表示無限迴圈。

```csharp
if (timerItem.Repeat > 0)
{
    timerItem.Repeat--;
    if (timerItem.Repeat == 0)
    {
        timerItem.Deleted = true;
        _toRemove.Add(timerItem);
    }
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L114-L122)

**修復方式**：這是設計行為，不是 bug。需要週期性觸發就傳 `repeat = 0`;一次性任務結束後的 -1 屬正常，不要沿用舊 ID,重新 `Add` 取得新 ID 即可。

### 4. 被 `Pause` 後未恢復

`Pause(id)` 置 `IsPaused = true`,此後 `Update` 直接 `continue`,不累積時間、不觸發回呼，但計時器仍留在 `_items` 中(`Exists(id)` 仍為 true)。`Resume(id)` 會把 `IsPaused` 置回 false 並繼續計時：

```csharp
if (timerItem.IsPaused)
{
    continue;
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L75-L78)

**修復方式**：呼叫 `Resume(id)`;確認沒有程式碼路徑只 `Pause` 不 `Resume`。可用 Inspector 或日誌檢查目前是否存在被暫停的計時器。

### 5. `Scaled` 模式且 `Time.timeScale` 為 0

時間源按 `TimeScaleMode` 選擇，預設是 `Unscaled`(不受 `timeScale` 影響)；若註冊時傳了 `TimerTimeScale.Scaled`,暫停遊戲(`Time.timeScale = 0`)時 delta 為 0,計時器將永遠不會到達觸發條件：

```csharp
// Select time source based on TimeScaleMode
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L80-L81)

**修復方式**：UI、斷線重連等暫停期間也要執行的邏輯，保持預設 `Unscaled` 不傳 `timeScale` 參數；確認需要隨遊戲暫停的才傳 `TimerTimeScale.Scaled`。

### 6. 同一回呼重複註冊導致計時被重置

內部以回呼委派作為字典鍵。對已存在的回呼再次 `Add` 不會建立新計時器，而是原地重置(`Elapsed = 0`)並沿用舊 ID——表現通常是「第一個計時器莫名其妙從頭計時」：

```csharp
// Re-add existing callback: update in-place
if (_items.TryGetValue(callback, out var t))
{
    UpdateTagIndex(t, tag);
    t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete);
    t.Elapsed = 0;
    t.Deleted = false;
    t.IsPaused = false;
    return t.Id;
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L236)

**修復方式**：同一物件上的多個計時器各自使用獨立的方法或 lambda(每個 lambda 是不同委派實例)；需要更新參數時，可有意利用這個「重新註冊即重置」行為。

### 7. 回呼拋出例外吞掉後續回呼

回呼在鎖外集中分發。`TimerManager.CatchCallbackExceptions` 預設為 `false`,某個回呼拋出的例外會中斷本輪 for 迴圈，同幀排在後面的回呼全部不執行。把它設為 `true` 可捕捉並只輸出 `Timer callback error > {message}`:

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        callback(param);
    }
    catch (Exception e)
    {
        Debug.LogWarning("Timer callback error > " + e.Message);
    }
}
else
{
    callback(param);
}
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L172-L186)

**修復方式**：除錯期間設 `TimerManager.CatchCallbackExceptions = true` 並觀察警告以定位拋出例外的回呼；根因修復後建議恢復預設，避免吞掉例外。

## 驗證

按上述修復操作後，逐條確認：

1. `Add` 回傳非 0 的 ID,且 `Exists(id)` 為 true(註冊成功，包括「尚未刷新」階段)。
2. 等待一幀後再查 `GetRemaining(id)` / `GetElapsed(id)`,不再回傳 -1 且數值隨時間推進。
3. 到達 `interval` 後回呼被呼叫;`GetRepeatLeft(id)` 回傳 0 表示無限迴圈，其餘正數為剩餘次數。
4. `Pause(id)` 後 `GetElapsed(id)` 不再增長，`Resume(id)` 後恢復增長。
5. 設 `TimerManager.CatchCallbackExceptions = true` 後無 `Timer callback error >` 警告，表示沒有回呼在拋出例外。
