# How to Verify Data with CRC32/CRC64

`GameFrameX.Foundation.Hash.CrcHelper` provides two cyclic redundancy check algorithms, CRC32 and CRC64, supporting direct checksum computation on byte arrays and `Stream` objects (both synchronous and asynchronous), and can split a CRC32 integer into a big-endian byte array for storage or transmission.

## Prerequisites

- Reference the namespace `GameFrameX.Foundation.Hash`; the class name is `CrcHelper` (a static partial class).
- Target framework: .NET Standard 2.x and above, supporting `Stream`, `Task`, and `CancellationToken`.

## Steps

### 1. Compute the CRC32 of a Byte Array

The simplest call: pass in the complete byte array to get the CRC32 checksum as an `int`.

```csharp
using GameFrameX.Foundation.Hash;
using System.Text;

byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data);   // returns int
```

Source: [CrcHelper.cs#L121-L126](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L121-L126)

### 2. Compute the CRC32 of a Specified Range in a Byte Array

Pass in `offset` and `length` to compute the CRC32 for only a slice of the byte array; out-of-range or negative values throw `ArgumentException`.

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data, offset: 2, length: 5);
```

Source: [CrcHelper.cs#L140-L152](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L140-L152)

### 3. Compute the CRC32 of a Stream (Synchronous)

Reads and computes in 4 KB chunks (`CachedBytesLength = 0x1000`), suitable for verifying large files.

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = CrcHelper.GetCrc32(stream);
```

Source: [CrcHelper.cs#L163-L183](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L163-L183)

### 4. Compute the CRC32 of a Stream Asynchronously

The asynchronous version uses `Stream.ReadAsync` and supports cancellation via `CancellationToken`.

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = await CrcHelper.GetCrc32Async(stream, cancellationToken);
```

Source: [CrcHelper.cs#L188-L202](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L188-L202)

### 5. Compute the CRC64 of a Byte Array / Stream

CRC64 has three public overloads: `GetCrc64(byte[])`, `GetCrc64(Stream)`, and `GetCrc64Async(Stream, CancellationToken)`, returning `ulong`.

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
ulong crc64 = CrcHelper.GetCrc64(data);                 // byte array

using var stream = File.OpenRead("big.bin");
ulong crc64FromStream = CrcHelper.GetCrc64(stream);    // synchronous stream

ulong crc64Async = await CrcHelper.GetCrc64Async(stream); // asynchronous stream
```

Source: [CrcHelper.cs#L66-L110](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L66-L110)

### 6. Convert a CRC32 Integer to a Big-Endian Byte Array

CRC32 results often need to be persisted; `GetCrc32Bytes` provides two usage patterns:

```csharp
int crc32 = CrcHelper.GetCrc32(data);

// Option 1: returns a new 4-byte array (big-endian)
byte[] bytes = CrcHelper.GetCrc32Bytes(crc32);

// Option 2: writes to a specified position in an existing array
byte[] buffer = new byte[64];
CrcHelper.GetCrc32Bytes(crc32, buffer, offset: 0);
```

## Common Variants

- **CRC32 combined with byte-code circular XOR**: `CrcHelper.GetCrc32(stream, code, length)` is an internal overload that first circularly XORs the `code` byte array onto the data stream, then computes the CRC; suitable for lightweight keyed verification scenarios.
- **Consistency across different data lengths**: The CRC algorithm always returns the same result for the same input, so it can be used for network packet verification, file fingerprinting, and save file integrity checks.
- **Streaming computation for large files**: Processed in 4 KB chunks via the `Stream` overloads (synchronous/asynchronous), with stable memory usage.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| `ArgumentNullException`("bytes") | The passed-in `byte[]` is null | Check before calling or use `Array.Empty<byte>()` |
| `ArgumentException`(InvalidDataLength) | The `offset` of `GetCrc32(bytes, offset, length)` is out of range or `length` is negative | Ensure `offset >= 0`, `length >= 0`, and `offset + length <= bytes.Length` |
| `ArgumentException`(InvalidDataLength) | The `offset` of `GetCrc32Bytes` is out of range or the remaining space in the target array is less than 4 bytes | Ensure `offset >= 0` and `offset + 4 <= bytes.Length` |
| `ArgumentNullException`("stream") | The stream is null | Verify the stream was opened successfully and the file path is correct |
| Inconsistent computation results | Inconsistent string encodings (UTF-8 / GBK / UTF-16) | Both sides should use the same `Encoding`, e.g., both use `Encoding.UTF8.GetBytes` |

## Background (Optional)

CRC32 uses the default polynomial `0xedb88320` and seed `0xffffffff` (same as IEEE 802.3 / zlib); CRC64 internally delegates to the `Crc64` class's `Append` + `GetCurrentHashAsUInt64`. Checksums are suitable for non-cryptographic integrity checks and cannot replace keyed authentication algorithms such as HMAC.
