# How to Subscribe to Scene Events (Success / Failure / Progress / Active Scene Changed)

Subscribe to the event IDs via `m_EventComponent` of `SceneComponent` to receive callbacks when a scene finishes loading/unloading, when the progress changes, or when the active scene changes. All event arguments derive from `GameFrameX.Event.Runtime.GameEventArgs`. The subscription approach is consistent with other global events in the framework.

## Prerequisites

- `SceneComponent` has been attached to the scene entry point (the framework will automatically `Awake` and connect the manager).
- `SceneComponent.m_EnableLoadSceneUpdateEvent` defaults to `true`; only then will load progress events be forwarded. If you explicitly set it to `false`, subscribing to `LoadSceneUpdateEventArgs` will not trigger.
- You know the `EventId` corresponding to the target event, e.g., `typeof(LoadSceneSuccessEventArgs).FullName`.

## Steps

### 1. Get the Event Component

`SceneComponent` caches `EventComponent` in `Start()`, which can be obtained directly via `GameEntry.GetComponent<EventComponent>()`.

```csharp
var eventComponent = GameFrameX.Runtime.GameEntry.GetComponent<GameFrameX.Event.Runtime.EventComponent>();
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L115-L139)

### 2. Subscribe by Event ID

All scene events expose the `EventId` static field. When subscribing, pass the `EventId` and the handler function. Events are reused through `ReferencePool`, so there is no need to manually release them after reading the fields in the callback.

```csharp
// Load success
eventComponent.Subscribe(
    GameFrameX.Scene.Runtime.LoadSceneSuccessEventArgs.EventId,
    OnLoadSceneSuccess);

// Load failure
eventComponent.Subscribe(
    GameFrameX.Scene.Runtime.LoadSceneFailureEventArgs.EventId,
    OnLoadSceneFailure);

// Load progress
eventComponent.Subscribe(
    GameFrameX.Scene.Runtime.LoadSceneUpdateEventArgs.EventId,
    OnLoadSceneUpdate);

// Unload success
eventComponent.Subscribe(
    GameFrameX.Scene.Runtime.UnloadSceneSuccessEventArgs.EventId,
    OnUnloadSceneSuccess);

// Unload failure
eventComponent.Subscribe(
    GameFrameX.Scene.Runtime.UnloadSceneFailureEventArgs.EventId,
    OnUnloadSceneFailure);

// Active scene changed
eventComponent.Subscribe(
    GameFrameX.Scene.Runtime.ActiveSceneChangedEventArgs.EventId,
    OnActiveSceneChanged);
```

Source: [LoadSceneSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneSuccessEventArgs.cs#L41-L66), [ActiveSceneChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/ActiveSceneChangedEventArgs.cs#L41-L66)

### 3. Write the Callback Handlers

The callback signature looks like `void OnXxx(object sender, GameEventArgs e)`. Cast the received `e` to the appropriate type before reading its fields:

```csharp
private void OnLoadSceneSuccess(object sender, GameFrameX.Runtime.GameEventArgs e)
{
    var args = (GameFrameX.Scene.Runtime.LoadSceneSuccessEventArgs)e;
    Debug.Log($"Load completed: {args.SceneAssetName}, took {args.Duration:F2}s");
}

private void OnLoadSceneUpdate(object sender, GameFrameX.Runtime.GameEventArgs e)
{
    var args = (GameFrameX.Scene.Runtime.LoadSceneUpdateEventArgs)e;
    Debug.Log($"Progress: {args.Progress:P0}");
}

private void OnActiveSceneChanged(object sender, GameFrameX.Runtime.GameEventArgs e)
{
    var args = (GameFrameX.Scene.Runtime.ActiveSceneChangedEventArgs)e;
    Debug.Log($"Active scene: {args.LastActiveScene.name} -> {args.ActiveScene.name}");
}
```

Source: [LoadSceneSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneSuccessEventArgs.cs#L67-L100), [ActiveSceneChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/ActiveSceneChangedEventArgs.cs#L67-L100)

### 4. Unsubscribe

Call `Unsubscribe` when no longer needed; otherwise, `EventComponent` will keep holding the delegate.

```csharp
eventComponent.Unsubscribe(LoadSceneSuccessEventArgs.EventId, OnLoadSceneSuccess);
```

## Common Variants

- **Disable progress events**: Uncheck `Enable Load Scene Update Event` on the node where `SceneComponent` is attached. The framework will then not forward `LoadSceneUpdate` as a global event — this can reduce subscription frequency but you will lose progress updates.
- **Dispatch by business logic**: Subscribe to the same `EventId` twice and use `args.UserData` inside the callback to distinguish different businesses, avoiding the need to remember the order when calling `LoadScene`.

## Common Errors

- **Callback not triggered**: Check `SceneComponent.m_EnableLoadSceneUpdateEvent`. If it is `false`, `LoadSceneUpdateEventArgs` will not be emitted; other events are not affected by this switch.
- **Forgot to `Unsubscribe`**: Long-lived objects (singletons/MonoBehaviours that are not destroyed) will keep their subscriptions. Be sure to unregister when closing a UI or switching modules.
- **Cast error**: The callback signature is `object sender, GameEventArgs e`. You must cast `e` to the corresponding `EventArgs` to access its fields; reading it directly will throw `InvalidCastException`.

## Background (Optional)

`SceneComponent.Awake()` connects `GameSceneManager`'s `LoadSceneSuccess/Failure/Update` and `UnloadSceneSuccess/Failure` to its own event handlers, which are then dispatched to subscribers by `EventComponent`. `ActiveSceneChanged` comes from Unity's built-in `SceneManager.activeSceneChanged`, and the framework also exposes it as a `GameEventArgs` for unified dispatch.
