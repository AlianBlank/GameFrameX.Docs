# IL2CPP/AOT 建置：防止類型被裁剪

本套件針對 IL2CPP/AOT 建置的受管理程式碼剝離(Managed Stripping)內建了雙重防護：核心類型(`TimerComponent`、`TimerManager`、`ITimerManager`)全部標註 `[UnityEngine.Scripting.Preserve]`,並額外提供一個 `GameFrameXTimerCroppingHelper` 裁剪輔助類別來明確參考這些類型。正常引入本套件後無需任何額外設定，類型即不會被剝離。

## 前置條件

- 專案已安裝本套件(`com.gameframex.unity.timer`)。
- 目標平台在 Player Settings 中使用 IL2CPP 腳本後端(本機制對 Mono 後端無副作用，可保留)。

### 2. 確認裁剪輔助類別隨套件建置

套件內 `Runtime/GameFrameXTimerCroppingHelper.cs` 是防剝離的第二道防線，類別與方法均帶有 `[Preserve]`,並在 `Start()` 中使用 `typeof` 明確參考全部核心類型，為剝離器留下靜態參考根：

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Timer.Runtime
{
    [Preserve]
    public class GameFrameXTimerCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(TimerComponent);
            _ = typeof(ITimerManager);
            _ = typeof(TimerManager);
        }
    }
}
```

Source: [GameFrameXTimerCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/GameFrameXTimerCroppingHelper.cs#L1-L17)

該檔案位於套件的 `Runtime` 目錄，會隨套件自動參與建置，不需要手動掛到場景上。

### 3. 建置並驗證

1. 切換至 IL2CPP 後端並執行一次真實平台建置(僅進入 Play 模式無法驗證剝離問題)。
2. 在建置產物中確認類型保留，任選其一：
   - 在建置報告/剝離日誌中搜尋 `GameFrameX.Timer`,確認無 "stripped" 相關移除記錄；
   - 執行建置包，確認計時器元件能正常初始化並執行 `AddTimer` 之類的呼叫。

## 常見變體

- **專案中還有依賴反射的其他類型被剝離**：可在你自己的專案程式碼中複製上述輔助類別模式——新增一個帶有 `[Preserve]` 的 `MonoBehaviour`,在 `Start()` 中使用 `typeof` 參考需要保留的類型。這是 Unity 通用的防裁剪手法，本套件的 `GameFrameXTimerCroppingHelper` 就是該模式的現成範例。
- **提升剝離等級後建置失敗**：若專案設定了 High/Medium 剝離等級，`[Preserve]` 與 `typeof` 參考根仍然有效，無需為計時器類型單獨做任何調整。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| IL2CPP 建置包中計時器初始化失敗、介面/元件解析不到 | 剝離器移除了未被靜態參考的類型(例如手動刪除了 `[Preserve]` 特性或裁剪輔助類別) | 按上文步驟 1、2 還原標記與輔助類別後重新建置 |
| 編輯器正常、真機包異常 | 編輯器不執行受管理剝離，問題只在 AOT 建置時暴露 | 以真機/模擬器建置為準，按步驟 3 驗證 |
| 只在 Play 模式驗證，誤以為已涵蓋 | Play 模式不經過 IL2CPP 編譯與剝離 | 必須執行真實平台建置驗證 |

## 背景

IL2CPP 的受管理程式碼剝離會移除靜態分析中「無人參考」的類型。本套件的類型常透過框架反射與自動元件機制載入，靜態參考鏈不完整，容易被誤判為可移除。`[Preserve]` 特性直接告知剝離器保留目標，裁剪輔助類別再用 `typeof` 提供編譯期可見的參考根，兩者疊加保證任何剝離等級下類型均被保留。README 中將其列為「IL2CPP 安全——裁剪輔助類別防止 AOT 建置中的類型剝離」(見 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L35))。
