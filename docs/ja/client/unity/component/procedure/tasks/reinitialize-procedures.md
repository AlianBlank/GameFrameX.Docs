# 流程リストのリセット方法

ランタイムで現在の流程ステートマシンを破棄し、新しい流程配列で再初期化することで、1回の呼び出しで「クリア + 再構築」を実現します。本ドキュメントでは `ReinitializeProcedures` の2つのエントリポイントと正しい使用方法を紹介します。

## 前提条件

- `GameEntry.GetComponent<ProcedureComponent>()` で流程コンポーネントインスタンスを取得済み
- `ProcedureBase` を継承した流程クラスを少なくとも1つ定義済み
- フレームワークの初期化が完了している（`m_ProcedureFsm` の有無は問わない）

## 操作手順

1. **新しい流程配列を構築する**:新しいステートマシンに登録するすべての流程オブジェクトをインスタンス化します。

   ```csharp
   var procedures = new ProcedureBase[]
   {
       new LaunchProcedure(),
       new LoginProcedure(),
       new GameProcedure(),
   };
   ```

2. **エントリ流程を指定する**:同じ流程グループから1つをエントリ流程として選択します。

   ```csharp
   var entrance = procedures[1]; // LoginProcedure
   ```

3. **リセットメソッドを呼び出す**:流程コンポーネントを通じてリセットを実行すると、フレームワークはまず古いステートマシンを破棄し、次に新しい配列で再構築します。

   ```csharp
   ProcedureComponent procedureComponent = GameEntry.GetComponent<ProcedureComponent>();
   procedureComponent.ReinitializeProcedures(procedures, entrance);
   ```

   Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L230-L234)

4. **（オプション）エントリ流程を起動する**:すぐに流程に入る場合は `StartProcedure` を呼び出します。

   ```csharp
   procedureComponent.StartProcedure(entrance.GetType());
   ```

## よくあるバリエーション

### 流程マネージャーを直接使用する

`ProcedureComponent` のラッパーを経由しない場合は、マネージャーレイヤーで直接 `ReinitializeProcedures(params ProcedureBase[] procedures)` を呼び出すことができます。このシグネチャは流程配列のみを受け取り、エントリ流程の設定は含まれません。

```csharp
m_ProcedureManager.ReinitializeProcedures(new ProcedureBase[]
{
    new LaunchProcedure(),
    new LoginProcedure(),
});
```

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L260-L271)

### 破棄のみ（クリアして再構築しない）

既存の流程をクリアするだけで再構築しない場合は、`DestroyProcedures()` を使用します:

```csharp
procedureComponent.DestroyProcedures();
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L107-L111)

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| `GameFrameworkException("Procedures is invalid.")` がスローされる | 渡された `procedures` 配列の長さが0 | 少なくとも1つの `ProcedureBase` インスタンスを渡す |
| リセット後、古い流程の `OnDestroy` がトリガーされない | 古い流程の参照が外部に保持されており、ステートマシン破棄のコールバックが実行されていない | 外部で `ProcedureBase` インスタンスを長期間キャッシュしない |
| 呼び出し後 `CurrentProcedure` が例外をスローする | 再構築後に `StartProcedure` を呼び出していない | リセット後に `StartProcedure` を呼び出してエントリを指定する |
| `NullReferenceException` | `ProcedureComponent` がフレームワークに登録されていない | シーンに `ProcedureComponent` がマウントされ有効化されていることを確認する |

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L264-L270)

## 背景（オプション）

`ReinitializeProcedures` の内部順序は次のとおりです: まず `DestroyProcedures()` を呼び出して古いステートマシンを破棄し、新しい配列が空でないことを検証し、最後に `m_FsmManager.CreateFsm(this, procedures)` でFSMを再構築します。`ProcedureComponent` のラッパーレイヤーではこれに加えて `m_EntranceProcedure` を保存し、後続の `StartProcedure` で使用します。
