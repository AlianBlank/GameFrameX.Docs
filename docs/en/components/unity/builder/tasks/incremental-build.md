# How to Enable Incremental Builds

When calling `BuildAsset` to build a resource package, set `IsIncrementalBuildPackage` to `true`. The builder switches YooAsset's build mode to `EBuildMode.IncrementalBuild`, which only repackages changed resources and skips unchanged parts, significantly shortening build time.

## Prerequisites

- The `GameFrameX.Builder.Editor` assembly has been integrated following the "Quick Start" guide.
- The current build pipeline is `BuiltinBuildPipeline` or `RawFileBuildPipeline` (both support the `BuildMode` field in their `BuildParameters`).
- This build targets a resource package directory that has previously been packaged. The first build has no reusable cache, and the effect is equivalent to a full rebuild.

## Steps

1. **Enable in code**

   Assign `true` to `BuilderOptions.IsIncrementalBuildPackage` and then call the build:

   ```csharp
   var options = new GameFrameX.Builder.Editor.BuilderOptions
   {
       PackageName = "DefaultPackage",
       IsIncrementalBuildPackage = true,
   };
   GameFrameX.Builder.Editor.Builder.BuildAsset(options);
   ```

   Source: [Editor/BuilderOptions.cs#L72-L75](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L72-L75)

2. **Enable via command-line argument**

   Add the `-IsIncrementalBuildPackage` flag in CI / batch scripts. `Builder.BuildParamsParse` will parse it as `true` (note that the command-line method does not require a value—simply including the flag is treated as enabled):

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
         -PackageName DefaultPackage \
         -IsIncrementalBuildPackage
   ```

   Source: [Editor/Builder.BuildParamsParse.cs#L90-L93](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L90-L93)

3. **Verify it's in effect**

   After the build starts, `Builder.BuildAsset` will execute the following assignment to switch YooAsset's build mode to incremental:

   ```csharp
   buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage
       ? EBuildMode.IncrementalBuild
       : EBuildMode.ForceRebuild;
   ```

   Source: [Editor/Builder.BuildAsset.cs#L65](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L65)

   If `IsIncrementalBuildPackage` is `false` (the default value) or `-IsIncrementalBuildPackage` is not passed, the build mode will be `EBuildMode.ForceRebuild`.

## Common Variants

- **Upload assets and perform incremental build simultaneously**: Simply include both `-IsUploadAsset` and `-IsIncrementalBuildPackage`. The two flags are parsed independently and do not affect each other.
- **Fall back to a full build**: Before releasing a major version, it is recommended to remove this parameter or explicitly pass `false` (not passing any flag defaults to `false`) to force `EBuildMode.ForceRebuild`.

## Common Errors

- **First build still runs incrementally, mistakenly assumed to be ineffective**: Incremental builds depend on the output cache from the previous run. The first package has no cache to reuse, so it is normal for the output to be identical to a full build.
- **Forgot the hyphen prefix in the command line**: `-IsIncrementalBuildPackage` must include the `-`. Writing it as `IsIncrementalBuildPackage` without the prefix will not be parsed and will be treated as the default value `false`.
- **Misspelled `PackageName`**: The incremental build's cache is isolated by package name directory. If `PackageName` is changed to a new name, the cache will not match, and it will appear "as slow as a full build". When reusing the old cache, be sure to keep `PackageName` consistent.

## Background (Optional)

`IsIncrementalBuildPackage` is just a regular boolean field in `BuilderOptions`. The actual point of effect is where `Builder.BuildAsset` maps its value to YooAsset's `EBuildMode` (incremental vs. force rebuild). Both the command-line and code entry points ultimately converge on the same field, so both approaches behave identically.
