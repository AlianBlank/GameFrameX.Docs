# UI 管理器(IUIManager)工作原理

`IUIManager` 是 GameFrameX UI 模組的總入口，負責統一管理介面組(`IUIGroup`)、介面實例池、載入/關閉流程與對外事件。本頁說明它內部如何運作——從開啟一個介面到回收它，呼叫鏈上發生了什麼，以及各設定項的意義。

## 介面一覽

`IUIManager` 定義在 [Runtime/UI/IUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIManager.cs) 中，其核心成員按職責分組如下。

| 分類 | 成員 | 作用 |
|------|------|------|
| 實例池設定 | `InstanceAutoReleaseInterval`、`InstanceCapacity`、`InstanceExpireTime`、`RecycleInterval` | 控制 UI 實例物件池的容量、過期時間、自動釋放與回收節奏 |
| 動畫開關 | `IsEnableUIShowAnimation`、`IsEnableUIHideAnimation` | 是否啟用介面顯示/隱藏動畫 |
| 組管理 | `AddUIGroup`、`HasUIGroup`、`GetUIGroup`、`GetAllUIGroups` | 增/查 UI 組 |
| 介面查詢 | `HasUIForm`、`GetUIForm(s)`、`GetAllLoadedUIForms`、`IsLoadingUIForm`、`IsValidUIForm` | 依序號或資源名稱查詢介面 |
| 開啟/關閉 | `OpenUIFormAsync`、`CloseUIForm`、`CloseAllLoadedUIForms`、`CloseAllLoadingUIForms` | 非同步開啟、關閉、批次關閉 |
| 事件 | `OpenUIFormSuccess`、`OpenUIFormFailure`、`CloseUIFormComplete` | 非同步操作完成時的回呼 |
| 依賴注入 | `SetObjectPoolManager`、`SetResourceManager`、`SetUIFormHelper` | 注入底層物件池、資產、輔助器 |

抽象基底類別 `BaseUIManager : GameFrameworkModule, IUIManager`（[Runtime/BaseUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L36-L39)）負責儲存這些狀態並實作通用邏輯。

## 關鍵內部欄位

`BaseUIManager` 使用以下欄位追蹤狀態（[BaseUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L48-L114)）：

| 欄位 | 用途 |
|------|------|
| `m_UIFormsBeingLoaded` | 載入中的介面（序號 → 資源路徑） |
| `m_UIFormsToReleaseOnLoad` | 載入完畢後需要立即釋放的介面 |
| `m_RecycleQueue` | 待回收的介面佇列 |
| `m_RecycleInterval`、`m_RecycleTime` | 回收節奏控制（預設 60 秒） |
| `m_Serial` | 自動遞增序號產生器 |
| `m_AssetManager`、`m_ObjectPoolManager`、`m_UIFormHelper` | 透過 setter 注入的依賴 |

## 開啟一個介面的流程

`OpenUIFormAsync` 入口在 [Runtime/BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118)。兩個多載最終都委派給內部 `InnerOpenUIFormAsync`：

```csharp
public Task<IUIForm> OpenUIFormAsync<T>(string uiFormAssetPath, bool pauseCoveredUIForm, object userData, bool isFullScreen = false) where T : class, IUIForm
{
    return InnerOpenUIFormAsync(uiFormAssetPath, typeof(T), pauseCoveredUIForm, userData, isFullScreen);
}

public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}
```

Source: [Runtime/BaseUIManager.Open.cs#L100-L118](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118)

開啟過程中，管理器依以下順序運作：

1. 取得自動遞增的 `serialId`，將 `{serialId, assetPath}` 寫入 `m_UIFormsBeingLoaded`。
2. 透過 `m_AssetManager` 非同步載入 Prefab，載入完成事件中實例化 `IUIForm`。
3. 將實例放入所屬 `IUIGroup`，根據 `pauseCoveredUIForm` 決定是否觸發目標組內被覆蓋介面的 `OnCover`/`OnReveal`。
4. 觸發 `OpenUIFormSuccess` 事件，將 `IUIForm` 透過 `Task` 傳回給呼叫端。
5. 任何階段發生例外都會觸發 `OpenUIFormFailure` 並從 `m_UIFormsBeingLoaded` 移除項目。

## 關閉一個介面的流程

`CloseUIForm` 提供依序號、依實例、依泛型、依 `userData` 的多載，統一在 [Runtime/BaseUIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs) 中實作。流程要點：

1. 驗證 `IsValidUIForm`，通過則從 `IUIGroup` 移除。
2. 根據 `IsEnableUIHideAnimation` 決定是否播放隱藏動畫。
3. 預設進入回收佇列延遲回收；傳入 `isNowRecycle: true` 時立即回收到物件池。
4. 回收完成後觸發 `CloseUIFormComplete`。

回收佇列由 `RecycleInterval`（預設 60 秒）控制節奏，時間到時批次回收到 `m_ObjectPoolManager` 中的 `m_InstancePool`。

## 實例物件池

`m_InstancePool` 是 `IObjectPoolManager` 下的一個物件池，對應 UI 實例的可重複使用快取。`InstanceCapacity`、`InstanceExpireTime`、`InstanceAutoReleaseInterval` 三個屬性直接轉發到該池的對應欄位（[BaseUIManager.cs#L122-L182](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L122-L182)）。

| 屬性 | 轉發目標 |
|------|---------|
| `InstanceAutoReleaseInterval` | `m_InstancePool.AutoReleaseInterval` |
| `InstanceCapacity` | `m_InstancePool.Capacity` |
| `InstanceExpireTime` | `m_InstancePool.ExpireTime` |

含義：池滿了會依過期時間淘汰最久未使用的實例，避免頻繁實例化 Prefab。

## 事件回呼

三個事件在 [BaseUIManager.Open.cs#L42-L68](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L42-L68) 透過明確的 `add`/`remove` 維護，便於在 IL2CPP 下保留：

- `OpenUIFormSuccess(OpenUIFormSuccessEventArgs)` — 載入並初始化成功後觸發。
- `OpenUIFormFailure(OpenUIFormFailureEventArgs)` — 資源載入失敗、類型不相符、輔助器未注入等情況下觸發。
- `CloseUIFormComplete(CloseUIFormCompleteEventArgs)` — 關閉流程（動畫、回收）全部完成時觸發。

## 依賴注入順序

`BaseUIManager` 不會自行建立 `IAssetManager`、`IObjectPoolManager`、`IUIFormHelper`，必須由呼叫端在呼叫 `Open/Close` 前透過對應 setter 注入。這三者在 `OpenUIFormAsync` 路徑上必須就緒，否則 `OpenUIFormFailure` 會被立即觸發。
