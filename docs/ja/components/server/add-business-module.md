# 新しい業務モジュール（Apps レイヤー）の追加方法

`GameFrameX.Apps` プロジェクトに、`Component` + `Entity` + `State` のディレクトリ規則に従って新しい業務サブモジュールを追加し、ホットアップデート（Hotfix）レイヤーから呼び出すことで、最小限の業務モジュールを接続できます。

## 前提条件

- `GameFrameX.Server.Source` リポジトリをクローン済みでコンパイルでき、`.NET 8+` SDK が利用可能であること。
- `GameFrameX.Apps` プロジェクトの場所（`GameFrameX.Apps/`）を把握していること。
- `GameFrameX.Hotfix` が `<ProjectReference>` によって `GameFrameX.Apps` を参照していることを確認済みであること（[GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj#L18) を参照）。

## 操作手順

以下では、新しい `Player/Mail` モジュールを例に、ディレクトリ、コンポーネント、状態を作成し、Hotfix から呼び出すまでの完全な手順を示します。

1. **ディレクトリ規則に従ってサブモジュール用フォルダを作成します**。
   `GameFrameX.Apps/` 配下にサブディレクトリを作成します。推奨する 3 層構造は `{ドメイン}/{モジュール}/{Component|Entity}` です。
   たとえば、メールモジュールを追加する場合は次のとおりです。
   ```text
   GameFrameX.Apps/Player/Mail/Component/MailComponent.cs
   GameFrameX.Apps/Player/Mail/Entity/MailState.cs
   ```
   既存の例として、`Account/Login` と `Player/Bag` のディレクトリ構造を参照できます（[LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L30-L46)、[BagComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Player/Bag/Component/BagComponent.cs)）。

2. **エンティティ状態クラス（Entity/State）を作成します**。
   フレームワークが提供する `CacheState` を継承し、業務フィールドのみを配置し、動作メソッドは配置しません。たとえば、`LoginState` は次のように記述します。
   ```csharp
   namespace GameFrameX.Apps.Account.Login.Entity;

   public class LoginState : CacheState
   {
       public string NickName { get; set; }
       public string UserName { get; set; }
       public uint Level { get; set; }
       // ... その他の業務フィールド
   }
   ```
   出典: [LoginState.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Entity/LoginState.cs#L30-L72)

3. **コンポーネントクラス（Component）を作成し、状態と Actor タイプをバインドします**。
   `StateComponent<TState>` を継承し、`[ComponentType]` 属性を使用して所属する Actor を宣言します。たとえば、`LoginComponent` は `ActorTypeServer` にバインドします。
   ```csharp
   using GameFrameX.Apps.Account.Login.Entity;

   namespace GameFrameX.Apps.Account.Login.Component;

   [ComponentType(GlobalConst.ActorTypeServer)]
   public sealed class LoginComponent : StateComponent<LoginState>
   {
       protected override bool IsCreateDefaultState { get; set; } = false;

       public async Task<PlayerState> OnPlayerLogin(ReqPlayerLogin reqLogin)
       {
           MetricsPlayerHelper.LoginCounterOptions.Inc();
           return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
       }
   }
   ```
   出典: [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L30-L46)

4. **名前空間とディレクトリを一致させます**。
   コンポーネントの名前空間は `GameFrameX.Apps.{ドメイン}.{モジュール}.Component`、状態の名前空間は `GameFrameX.Apps.{ドメイン}.{モジュール}.Entity` とし、`global using` と整合させます（[GlobalUsings.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/GlobalUsings.cs) を参照）。

5. **`GameFrameX.Hotfix` から新しいコンポーネントを呼び出します**。
   Hotfix レイヤーは `Component` フレームワークインターフェースを通じて新しいモジュールにアクセスします。たとえば、`LoginComponent.OnPlayerLogin` は Hotfix のログインメッセージ処理エントリーポイントから呼び出されます。`AppsHandler.cs` に追加で登録する必要はありません（現時点で `AppsHandler` は空のクラスです。[AppsHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/AppsHandler.cs#L31-L34) を参照）。

6. **コンパイルして検証します**。
   リポジトリのルートディレクトリで次のコマンドを実行します。
   ```bash
   dotnet build GameFrameX.Apps/GameFrameX.Apps.csproj
   ```
   コンパイルが成功すれば、新しいモジュールが正常に接続されたことを示します。

## 一般的なバリエーション

- **別の Actor タイプにバインドする**: `[ComponentType(GlobalConst.ActorTypeServer)]` の定数を、業務に必要な Actor に置き換えます（[LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L36) を参照）。
- **状態をデフォルトで作成するかどうか**: Actor の作成時にデフォルトの `State` を自動初期化する場合は、`IsCreateDefaultState` を `true` に設定します。初めてデータベースに保存するときにのみ作成する場合は、`false` のままにします（[LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L39) を参照）。

## 一般的なエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `dotnet build` で `CacheState` / `StateComponent<T>` / `GlobalConst` が見つからない | 該当する `global using` が導入されていない、またはプロジェクト参照が不足している | `GameFrameX.Hotfix.csproj` が `GameFrameX.Apps.csproj` を参照していることを確認します（[GameFrameX.Hotfix.csproj#L18](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj#L18) を参照） |
| Hotfix でコンポーネントメソッドが見つからない | 名前空間がディレクトリと一致していない、またはクラスに `public` が付いていない | `GameFrameX.Apps.{ドメイン}.{モジュール}.Component` という名前にし、クラスの宣言を `public sealed` にします |
| `ComponentType` 属性でエラーが発生する | 誤った Actor 定数を使用している | `GlobalConst.ActorTypeServer` など、定義済みの定数を使用します |
