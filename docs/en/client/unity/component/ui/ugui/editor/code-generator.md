# How to Use the UGUI Code Generator to Automatically Generate UI Scripts

The UGUI Code Generator is a built-in editor extension of the `GameFrameX.UI.UGUI` package. It scans the node tree of a UGUI prefab and automatically generates a partial class inheriting from `UGUI`, containing strongly-typed properties for all child nodes, `Create` / `GetFromPool` factory methods, and `InitView` initialization logic. After the class is attached to the prefab, control references can be automatically bound via `UGUIElementProperty`.

## Prerequisites

1. `com.gameframex.unity.ui.ugui` has been imported into the Unity project (as a dependency or a local Package).
2. `ENABLE_UI_UGUI` has been defined in Project Settings → Player → Scripting Define Symbols; otherwise the generated code will be entirely excluded due to `#if ENABLE_UI_UGUI`.
3. The GameFrameX runtime is installed in the project (the `GameFrameX.Runtime`, `GameFrameX.Entity.Runtime`, `GameFrameX.UI.Runtime`, `GameFrameX.UI.UGUI.Runtime`, and `Cysharp.Threading.Tasks` namespaces can be resolved in the generated code).
4. The target asset must be a UGUI prefab already saved to disk (with a `RectTransform` on the root node); it cannot be a temporary scene node in the Hierarchy.

## Steps

1. **Select the root node of the UI prefab**. Click the `.prefab` file in the Project window and make sure the Selection contains only one root GameObject and that it is the prefab's root (`transform.parent == null`).

2. **Execute the generate command**. Right-click the prefab and select `GameObject/UI/Generate UGUI Code(生成UGUI代码)` in turn, or find the item with the same name in the top menu. The command entry point in the source code is as follows:

   ```csharp
   [MenuItem("GameObject/UI/Generate UGUI Code(生成UGUI代码)", false, 1)]
   static void Code()
   {
       if (Selection.activeObject is GameObject selectedObject)
       {
           Generate(selectedObject);
           return;
       }

       Debug.LogError("请选择一个有效的UGUI预制体进行操作");
   }
   ```

   Source: [UGUICodeGenerator.cs#L56-L66](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UGUICodeGenerator.cs#L56-L66)

3. **The generator automatically traverses and writes out the script**. `Generate` validates the prefab, resolves control types sorted by the `Priority` of `IUGUIGeneratorCodeConvertTypeHandler`, and then calls `GenerateCode` to write out the `.UI.cs` file:

   ```csharp
   // Prefabs under the Resources directory are generated into Assets/Scripts/Game/UGUI/<ClassName>
   // Prefabs in other locations are generated into Assets/Hotfix/UI/UGUI/<ClassName>
   if (assetPath.Contains(nameof(Resources)))
   {
       savePath = System.IO.Path.Combine(Application.dataPath, "Scripts", "Game", "UGUI", className);
   }
   else
   {
       savePath = System.IO.Path.Combine(Application.dataPath, "Hotfix", "UI", "UGUI", className);
   }
   ```

   Source: [UGUICodeGenerator.cs#L128-L138](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UGUICodeGenerator.cs#L128-L138)

4. **Attach the script back to the prefab and rebind**. After the script is generated, the Console outputs the messages `生成UI代码完成 文件路径:…` and `现在请将生成的代码挂载到当前的UGUI预制体上,然后点击重新绑定列表`. Add this partial class component to the original prefab's root node, and the editor will automatically bind the references found via `Transform.FindChildName` according to the `[UGUIElementProperty("path")]` attribute on each property.

## Generated Script Structure

The generated code is located at `Assets/Scripts/Game/UGUI/<Name>/<Name>.UI.cs` or `Assets/Hotfix/UI/UGUI/<Name>/<Name>.UI.cs`, with the core skeleton as follows (taken from the actual generator):

```csharp
/** This is an automatically generated class by UGUI. Please do not modify it. **/

#if ENABLE_UI_UGUI
using Cysharp.Threading.Tasks;
using GameFrameX.Entity.Runtime;
using GameFrameX.UI.Runtime;
using GameFrameX.Runtime;
using GameFrameX.UI.UGUI.Runtime;
using UnityEngine;

namespace Hotfix.UI
{
    /// <summary>
    /// Code-generated UI code <ClassName>
    /// </summary>
    [DisallowMultipleComponent]
    [OptionUIConfig(null, "<资源所在目录>")]
    public sealed partial class <ClassName> : UGUI
    {
        public GameObject self { get; private set; }

        #region Properties
        [UGUIElementProperty("Panel/Button_Confirm")]
        private Button Button_Confirm;

        public Button m_Button_Confirm
        {
            get { return Button_Confirm; }
        }
        #endregion

        public static <ClassName> Create(GameObject go)
        {
            var ui = go.GetOrAddComponent<<ClassName>>();
            ui?.InitView();
            return ui;
        }

        public static <ClassName> GetFromPool(GameObject go) { /* Same as above, sets IsFromPool = true */ }

        protected override void InitView()
        {
            if (_isInitView) return;
            _isInitView = true;
            this.self = this.gameObject;
            Button_Confirm = gameObject.transform.FindChildName("Panel/Button_Confirm").GetComponent<Button>();
        }
    }
}
#endif
```

Source: [UGUICodeGenerator.cs#L169-L264](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UGUICodeGenerator.cs#L169-L264)

The generator processes controls internally in the following order:

| Step | Behavior |
|------|------|
| Reflection discovery | `Utility.Assembly.GetTypes()` finds all `IUGUIGeneratorCodeConvertTypeHandler` implementation classes |
| Sorting | Sorted ascending by `handler.Priority`; smaller values match first |
| Recursion | `PropertyHandler` performs a DFS of child nodes from the root node and stops immediately upon encountering a child branch that already has a `UGUI` component attached |
| Naming | Concatenates the parent node prefix and removes ` ` (space), `(`, `)` to derive the property name, e.g., `Panel/Button (1)` → `Panel_Button1` |
| Output | `PropertyCodeHandler` generates properties + public getters, `PropertyInitCodeHandler` generates the assignments inside `InitView` |

## Common Variants

- **Prefabs under Resources**: When `assetPath` contains `Resources`, code is generated into `Assets/Scripts/Game/UGUI/<Name>/`, with the namespace `Unity.Startup` and marked with `[OptionUIConfig(true)]` (resident loading at generation time). Source: [UGUICodeGenerator.cs#L181-L208](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UGUICodeGenerator.cs#L181-L208)
- **Hotfix prefabs**: When located under `Assets/Hotfix/UI/UGUI/...` or other directories, code is generated into `Assets/Hotfix/UI/UGUI/<Name>/`, with the namespace `Hotfix.UI`; `[OptionUIConfig(null, "<资源目录>")]` is used for on-demand loading.
- **UI with object pooling**: Use the generator-output `GetFromPool(GameObject go)`, which does not destroy the GameObject on `Dispose`; you need to wire up object pool recycling yourself. Source: [UGUICodeGenerator.cs#L230-L243](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Editor/UGUICodeGenerator.cs#L230-L243)

## Common Errors

| Console Error | Trigger Condition | Fix |
|--------------|---------|------|
| `请选择一个有效的UGUI预制体进行操作` | The current Selection is not a GameObject, or `PrefabAssetType` is `NotAPrefab`, or the root node has no `RectTransform` | Select the `.prefab` file in the Project window, confirm the root node has a `RectTransform`, and make sure the root node itself is selected rather than a child node |
| `请选择包含RectTransform组件的UI根节点预制体进行操作` | The selected object is not a UI element | Select a UI root node under a Canvas (must contain a `RectTransform`) |
| `请选择UI对象根节点进行操作,不能选择子节点` | The selected node has a parent | Expand the prefab in the Hierarchy and select the root node without a parent |
| Class not found after generation | The script was not attached back to the prefab | After the generated `<ClassName>.UI.cs` compiles successfully, add the component with the same name to the prefab's root node, then click rebind |
| File excluded due to undefined `ENABLE_UI_UGUI` | The macro was not configured in Player Settings | Add `ENABLE_UI_UGUI` in Project Settings → Player → Scripting Define Symbols |

## Background (Optional)

The generator's resolution of each control type is implemented via `IUGUIGeneratorCodeConvertTypeHandler`; the priority of the built-in default implementations affects the final generated property type — for example, TMP controls are usually matched by more specialized handlers instead of the fallback `Graphic`. You can extend custom UI controls by implementing this interface; after setting an appropriate `Priority`, the generator will use it in the next code generation.
