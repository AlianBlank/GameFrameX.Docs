# 常见问题

本文档收集了使用 CoroutineComponent 协程组件时常见的问题及解决方案。

## 概述

CoroutineComponent 是 GameFrameX 框架的协程管理组件，扩展了 Unity 内置的协程功能，提供更好的协程生命周期管理和内存安全控制。该组件使用 `ConcurrentDictionary` 线程安全字典来跟踪所有运行的协程，确保可以随时管理和停止协程。

> 详细使用说明请参考 [使用指南](./3-getting-started.index) 和 [API 参考](./4-api-reference.coroutine-component)。

## 常见问题列表

### Q1: 为什么在同一 GameObject 上无法添加多个 CoroutineComponent？

**问题描述：**
在同一个 GameObject 上尝试添加第二个 CoroutineComponent 时，Unity 编辑器报错或无法添加。

**原因：**
CoroutineComponent 使用了 `[DisallowMultipleComponent]` 属性，该属性禁止在同一 GameObject 上添加多个相同类型的组件。

**解决方案：**
- 确保每个 GameObject 只有一个 CoroutineComponent 实例
- 如果需要管理多个协程，请在同一个 CoroutineComponent 实例上启动多个协程
- 使用 `StopAllCoroutines()` 方法停止所有协程

```csharp
// 正确用法：在同一个组件上管理多个协程
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(CoroutineA());
coroutineComponent.StartCoroutine(CoroutineB());
coroutineComponent.StopAllCoroutines(); // 停止所有协程
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L10-L11)

### Q2: StartCoroutine 传入 null 枚举器会怎样？

**问题描述：**
向 `StartCoroutine` 方法传入 `null` 值的 IEnumerator 时会发生什么？

**原因：**
如果向 `StartCoroutine` 传入 null 枚举器，Unity 底层会抛出空引用异常。

**解决方案：**
- 在启动协程前始终检查枚举器是否为 null
- 添加空值保护逻辑

```csharp
IEnumerator myCoroutine = GetSomeCoroutine(); // 可能是 null

if (myCoroutine != null)
{
    coroutineComponent.StartCoroutine(myCoroutine);
}
```

### Q3: 如何正确停止一个正在运行的协程？

**问题描述：**
调用 `StopCoroutine` 后协程似乎仍在运行，或者无法停止协程。

**原因：**
- 传入的 IEnumerator 与启动时的枚举器不是同一个引用
- 协程已经执行完毕
- 协程在 StopCoroutine 调用前已经结束

**解决方案：**
- 保存启动协程时返回的 IEnumerator 引用
- 使用 `StopAllCoroutines()` 停止所有协程
- 确保在协程执行过程中及时停止

```csharp
// 保存协程引用
IEnumerator myCoroutine = coroutineComponent.StartCoroutine(MyLongRunningTask());

// 在适当的时机停止
coroutineComponent.StopCoroutine(myCoroutine);

// 或者停止所有协程
coroutineComponent.StopAllCoroutines();
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L32-L45)

### Q4: 组件挂载的 GameObject 被销毁后会发生什么？

**问题描述：**
当包含 CoroutineComponent 的 GameObject 被销毁时，正在运行的协程会怎样？

**原因：**
当 GameObject 被销毁时，Unity 会自动停止该 GameObject 上的所有协程。CoroutineComponent 继承自 MonoBehaviour，因此也会遵循这一行为。

**建议：**
- 在场景切换或对象销毁前，手动调用 `StopAllCoroutines()` 确保协程干净停止
- 使用 OnDestroy 生命周期钩子进行清理

```csharp
private void OnDestroy()
{
    // 确保在对象销毁前停止所有协程
    if (coroutineComponent != null)
    {
        coroutineComponent.StopAllCoroutines();
    }
}
```

### Q5: WaitForEndOfFrameFinish 的回调传入 null 会崩溃吗？

**问题描述：**
向 `WaitForEndOfFrameFinish` 方法传入 null 回调会发生什么？

**原因：**
CoroutineComponent 使用了空值合并运算符 `callback?.Invoke()`，因此传入 null 回调不会导致崩溃，调用会被安全地忽略。

**源码验证：**
```csharp
public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(_WaitForEndOfFrameFinish(callback));
}

private IEnumerator _WaitForEndOfFrameFinish(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke(); // 使用 ?. 操作符安全调用
}
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L97)

### Q6: 如何在帧渲染结束后执行逻辑？

**问题描述：**
需要在 Unity 每帧渲染结束后执行某些操作，应该如何使用？

**解决方案：**
使用 `WaitForEndOfFrameFinish` 方法，该方法会在当前帧的渲染完成后执行回调。

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    // 这个回调会在帧渲染结束后执行
    Debug.Log("帧渲染结束，执行逻辑");
});
```

**适用场景：**
- 在 UI 渲染后获取屏幕截图
- 在物理计算完成后执行某些操作
- 需要在帧末尾进行状态同步

### Q7: CoroutineComponent 是线程安全的吗？

**问题描述：**
CoroutineComponent 可以在多线程环境中使用吗？

**原因：**
是的，CoroutineComponent 使用了 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 来存储协程映射，该数据结构是线程安全的。

**注意事项：**
- 虽然内部存储是线程安全的，但协程本身在 Unity 主线程上执行
- 多线程访问时，主要需要考虑的是 IEnumerator 引用的正确传递

---

### Q8: 协程未正确停止导致内存泄漏如何处理？

**问题描述：**
协程未正确停止可能导致内存泄漏，如何预防？

**原因：**
如果不正确停止协程，特别是包含无限循环或长时间等待的协程，可能会导致内存泄漏。CoroutineComponent 通过维护协程映射表来帮助管理这个问题。

**解决方案：**
- 使用 `StopAllCoroutines()` 清理所有协程
- 在组件销毁时确保调用 `StopAllCoroutines()`
- 使用具有明确结束条件的协程

```csharp
private void OnDestroy()
{
    // 重要：确保停止所有协程防止内存泄漏
    StopAllCoroutines();
}
```

### Q10: CoroutineComponent 需要手动添加到 GameObject 吗？

**问题描述：**
为什么组件没有自动添加到场景中？

**原因：**
CoroutineComponent 在 `Awake` 方法中设置了 `IsAutoRegister = false`，这意味着组件不会自动注册到框架的自动注册系统中。

**解决方案：**
需要手动将 CoroutineComponent 添加到 GameObject 上：

```csharp
// 手动添加组件
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();

// 或者在 Unity 编辑器中手动添加
// 1. 选择 GameObject
// 2. 点击 Add Component
// 3. 搜索 "Game Framework/Coroutine"
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L99-L103)

### Q11: 如何在 Unity 编辑器中找到 CoroutineComponent？

**问题描述：**
在 Unity 编辑器中如何添加 CoroutineComponent？

**解决方案：**
由于组件使用了 `[AddComponentMenu("Game Framework/Coroutine")]` 属性，您可以通过以下方式添加：

1. 在 Unity 编辑器中选择 GameObject
2. 右键点击 Inspector 面板 → Add Component
3. 在搜索框中输入 "Coroutine" 或 "Game Framework/Coroutine"
4. 选择 CoroutineComponent

## 诊断步骤

如果遇到无法解决的问题，请按以下步骤进行诊断：

1. **检查 GameObject 状态**：确认 GameObject 和组件是否已激活
2. **检查协程引用**：确认用于停止协程的 IEnumerator 引用是否正确
3. **查看 Unity 控制台**：检查是否有错误或警告信息
4. **使用 StopAllCoroutines**：作为调试手段，先停止所有协程排查问题
5. **检查场景切换**：确认场景切换时协程是否被正确清理
