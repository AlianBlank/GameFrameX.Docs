# 起動時に「Web View manager is invalid」と表示される場合の対処方法

このエラーは `WebViewComponent.Awake()` から発生します:`GameFrameworkEntry.GetModule<IWebViewManager>()` が `null` を返した場合、フレームワーク内に `IWebViewManager` を実装した具象モジュールが登録/ロードされていないことを意味します。このエラーが発生すると、WebView コンポーネントは `Initialize()` を呼び出さず、以降の `Show` / `Hide` などの呼び出しはすべて null 参照になります。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 起動直後に `Log.Fatal("Web View manager is invalid.")` が出力される | `GameFrameworkEntry.GetModule<IWebViewManager>()` が `null` を返し、具象実装モジュールがロードされていない | プロジェクト内に `BaseWebViewManager` の具象実装モジュールが存在することを確認、[修正手順 1](#修正手順) を参照 |
| その後 `Show(url)` を呼び出すと `NullReferenceException` がスローされる | 前のステップが失敗した後、`_webViewManager` が `null` のまま保持され、コンポーネントが初期化をスキップする | まず上記の Fatal を解決してください、[検証](#検証) を参照 |
| Inspector 内のコンポーネントの実装タイプのドロップダウンが空 | 実装タイプが未選択、または対応するアセンブリがプロジェクトにコンパイルされていない | [修正手順 2](#修正手順) を参照 |

エラー発生箇所のソースコード:

```csharp
_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

## 修正手順

### 1. プロジェクト内に `IWebViewManager` の具象実装が存在することを確認

本リポジトリが提供するのは抽象層のみです:`BaseWebViewManager` は抽象クラスであり、プラットフォーム実装を一切含みません(ディレクトリ内には `BaseWebViewManager`、`IWebViewManager`、`WebViewComponent` などしかありません)。具象実装は対応するランタイムモジュールによって提供される必要があります:

```csharp
public abstract partial class BaseWebViewManager : GameFrameworkModule, IWebViewManager
{
    public abstract void Initialize();
    public abstract void Show(string url);
    public abstract void MakeFullScreen();
    public abstract void ExecuteJavaScript(string javaScript);
    public abstract void Hide();
}
```

Source: [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39)

調査方法：プロジェクト内で `: BaseWebViewManager` をグローバル検索し、少なくとも 1 つの非抽象派生クラスが存在することを確認してください。存在しない場合は、対応するランタイム実装パッケージをインストール/導入してから再試行してください。

### 2. コンポーネント上の実装タイプが選択されているかを確認

`WebViewComponent` は `Awake()` 内でリフレクションによって実装タイプを解決し、その後インターフェースモジュールを取得します:

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IWebViewManager);
base.Awake();
if (!IsRuntimeComponentReady)
{
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L30)

`componentType` の値は Inspector から提供され、エディタスクリプトは `IWebViewManager` を実装するすべての型をドロップダウンリストに反映します:

```csharp
internal sealed class WebViewComponentInspector : ComponentTypeComponentInspector
{
    ...
    RefreshComponentTypeNames(typeof(IWebViewManager));
}
```

Source: [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L14-L19)

操作手順:`WebView` コンポーネントがアタッチされたゲームオブジェクトを選択し、Inspector で実装タイプが空でないことを確認してください。空の場合は、対応するアセンブリが現在のビルドターゲットにコンパイルされていないことを意味します(プラットフォーム実装パッケージが特定のプラットフォームのみをサポートしているケースでよく発生します)。修正後、シーンを保存してから再実行してください。

### 3. ランタイムアセンブリがコンパイルに含まれていることを確認

本パッケージのアセンブリ定義は `Runtime/GameFrameX.WebView.Runtime.asmdef` と `Editor/GameFrameX.WebView.Editor.asmdef` です。Unity Console にこれら 2 つのアセンブリ(または実装モジュールのアセンブリ)に関するコンパイルエラーがないか確認してください。コンパイルに失敗すると `GetModule` が実装を取得できず、同様の Fatal として現れます。

## 検証

1. Play モードに再度入り、Console に `Web View manager is invalid.` の Fatal ログが表示されなくなることを確認します。
2. 完全な呼び出しチェーンを 1 回実行し、ページが正常に開くことを確認します:

```csharp
var webView = GameObject.FindObjectOfType<GameFrameX.WebView.Runtime.WebViewComponent>();
webView.Show("https://example.com");
```

## 背景

`WebViewComponent` は `GameFrameworkComponent` であり、自身では WebView ロジックを一切実装せず、`Awake()` 内で `GameFrameworkEntry` から `IWebViewManager` モジュールを取得して呼び出しを転送すること(`Show`、`MakeFullScreen`、`ExecuteJavaScript`、`Hide`)だけを担当します。抽象と実装の分離により、インターフェース層と各プラットフォームの実装を独立してパッケージ化できます。実装モジュールが欠落している場合、モジュールの取得ステップが失敗し、このページの Fatal ログが出力されます。
