# 如何為協程邏輯編寫測試

協程邏輯依賴 Unity 執行階段（`MonoBehaviour`、`StartCoroutine`），無法在純 NUnit 編輯器單元測試中直接驅動。本頁說明 `GameFrameX.Coroutine.Tests` 的慣例，以及在 Unity PlayMode 測試中驗證協程行為的做法。

## 前置條件

- 已安裝 Unity（與 `com.gameframex.unity.coroutine` 相容的版本）。
- 已透過 Package Manager 安裝本套件，Tests 組件 `GameFrameX.Coroutine.Tests` 會被一併匯入。
- 用於 PlayMode 測試時，專案內還需要 `UnityEngine.TestRunner` 與 `UnityEditor.TestRunner` 組件（預設隨 Unity 附帶）。

## Tests 組件慣例

`Tests/GameFrameX.Coroutine.Tests.asmdef` 僅在 Editor 平台生效，並透過 `references` 明確依賴 `GameFrameX.Coroutine.Runtime`，避免污染執行階段建置。

```json
{
    "name": "GameFrameX.Coroutine.Tests",
    "references": [
        "GameFrameX.Coroutine.Runtime"
    ],
    "rootNamespace": "GameFrameX.Coroutine.Tests",
    "includePlatforms": [
        "Editor"
    ]
}
```

Source: [GameFrameX.Coroutine.Tests.asmdef](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/GameFrameX.Coroutine.Tests.asmdef#L1-L18)

## 操作步驟

### 1. 在 Editor 組件下放置佔位單元測試

`Tests/UnitTests.cs` 明確說明：協程模組無法在純 NUnit 環境中執行，因此保留一個佔位測試案例，避免誤以為「沒有測試覆蓋 = 未測試」。

```csharp
using NUnit.Framework;

namespace GameFrameX.Coroutine.Tests
{
    internal class UnitTests
    {
        [Test]
        public void TestPlaceholder()
        {
            // Coroutine 模組依賴 Unity 執行階段（MonoBehaviour、StartCoroutine），
            // 無法在純 NUnit 環境中直接測試協程邏輯。
            // 協程相關的整合測試應在 Unity PlayMode 測試中編寫。
            Assert.Pass("Coroutine module requires Unity runtime for testing.");
        }
    }
}
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/UnitTests.cs#L1-L16)

### 2. 編寫 PlayMode 測試覆蓋真實協程

新建一個 PlayMode 測試組件（命名空間自訂，例如 `GameFrameX.Coroutine.PlayModeTests`），在 `asmdef` 中 `includePlatforms` 留空、`references` 加入 `GameFrameX.Coroutine.Runtime` 與 `nunit.framework`。測試案例中透過 `GameFrameX.Entry.GetComponent<CoroutineComponent>()` 取得元件，再呼叫其帶 `new` 關鍵字的 `StartCoroutine` / `StopCoroutine` 來驗證行為。

```csharp
using System.Collections;
using GameFrameX.Coroutine.Runtime;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

namespace GameFrameX.Coroutine.PlayModeTests
{
    public class CoroutineComponentTests
    {
        [UnityTest]
        public IEnumerator StartAndStop_TracksEnumerator()
        {
            var component = GameFrameX.Entry.GetComponent<CoroutineComponent>();
            Assert.IsNotNull(component);

            var routine = component.StartCoroutine(Sample());
            yield return null;

            // 同一個 IEnumerator 實例應能被 StopCoroutine 正確終止並移出追蹤表。
            component.StopCoroutine(routine);
            yield return null;
        }

        private static IEnumerator Sample()
        {
            yield return null;
        }
    }
}
```

> 注意：`CoroutineComponent.StartCoroutine` / `StopCoroutine` 使用 `new` 隱藏基底類別方法，必須透過 `CoroutineComponent` 型別的參考呼叫，元件才會把協程加入追蹤表。詳見 [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L50)。

### 3. 執行測試

- 在 Unity Editor 中開啟 **Window → General → Test Runner**。
- 切換到 **PlayMode** 分頁，選取剛編寫的 PlayMode 組件，點擊 **Run All**。
- 佔位 Editor 測試案例在 **EditMode** 分頁執行，預期結果為 `Passed`。

## 常見變體

- **僅做 EditMode 驗證**：保留 `UnitTests.TestPlaceholder` 佔位即可，確保 CI 上的 EditMode 套件不會因本模組缺失而報錯。
- **結合自訂事件/計時邏輯**：把業務協程封裝成回傳 `IEnumerator` 的純方法，在 PlayMode 測試案例中 `yield return` 多次再斷言最終狀態。
- **斷言例外/日誌**：使用 `LogAssert.Expect` 擷取元件在例外協程中輸出的日誌，避免測試誤報失敗。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| PlayMode 測試 `CoroutineComponent` 為 `null` | 還未走完 `GameFrameX` 啟動流程就取值 | 在 `yield return null` 之後再取得，或在 `[SetUp]` 中等待 `Entry` 初始化完成 |
| `StopCoroutine` 找不到協程 | 透過 `MonoBehaviour` 基底類別參考呼叫，繞過了 `new` 隱藏方法 | 始終用 `CoroutineComponent` 型別參考呼叫 `StartCoroutine` / `StopCoroutine` |
| EditMode 測試案例執行時報「Type or namespace not found」 | 測試組件未參考 `GameFrameX.Coroutine.Runtime` | 在 `asmdef` 的 `references` 中加上 `GameFrameX.Coroutine.Runtime` |
| PlayMode 測試案例被忽略 | PlayMode 組件 `includePlatforms` 誤填了 `Editor` | 將 `includePlatforms` 留空，讓組件在所有平台編譯 |

## 背景(可選)

`CoroutineComponent` 用 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>` 追蹤協程，因此 `StopCoroutine` 必須傳入與 `StartCoroutine` 相同的 `IEnumerator` 實例；該約束要求測試在同一次方法呼叫中持有列舉器參考。
