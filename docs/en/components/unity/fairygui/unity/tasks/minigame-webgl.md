# WeChat/Douyin Mini Game and WebGL Adaptation

In the WebGL environment of WeChat Mini Games or Douyin Mini Games, FairyGUI's input field cannot bring up the keyboard by default; this package solves the problem through macro definitions + dedicated keyboard adapters. You only need to enable the corresponding macro (`ENABLE_WECHAT_MINI_GAME` or `ENABLE_DOUYIN_MINI_GAME`) and integrate the corresponding platform's SDK, and `GTextInput` will automatically bring up the native keyboard when it gains focus.

## Prerequisites

- Unity has been switched to the **WebGL** platform (the adaptation code is wrapped entirely in `UNITY_WEBGL` and will not be compiled on other platforms).
- The corresponding platform's Mini Game SDK has been integrated; the SDK injects the platform macro and provides the keyboard API:

| Platform | Macro Provided by SDK | Keyboard API Namespace Used |
|------|--------------|--------------------------|
| WeChat Mini Game | `WECHAT_MINI_GAME` | `WeChatWASM` (`WX.ShowKeyboard`, etc.) |
| Douyin Mini Game | `DOUYIN_MINI_GAME` | `StarkSDKSpace` (`StarkSDK.API.GetStarkKeyboard()`) |

- The FairyGUI runtime module already ships with references and version constraints for both SDKs, so regular WebGL builds are unaffected:

```json
"references": [
    ...
    "StarkWebGL",
    ...
],
"versionDefines": [
    ...
    {
      "name": "com.qq.weixin.minigame",
      "expression": "",
      ...
    }
]
```

Source: [Runtime/Fairygui.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Fairygui.Runtime.asmdef#L5-L23)

The adaptation only takes effect when both the "platform macro + switch macro" are satisfied:

| Macro | Source | Purpose |
|----|------|------|
| `UNITY_WEBGL` | Unity | WebGL platform, outer layer of conditional compilation |
| `WECHAT_MINI_GAME` | WeChat WASM SDK | Identifies the WeChat Mini Game environment |
| `ENABLE_WECHAT_MINI_GAME` | This package (must be enabled manually) | Enables the WeChat keyboard adaptation |
| `DOUYIN_MINI_GAME` | Douyin Stark SDK | Identifies the Douyin Mini Game environment |
| `ENABLE_DOUYIN_MINI_GAME` | This package (must be enabled manually) | Enables the Douyin keyboard adaptation |

Source: [Runtime/UI/GTextInput.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInput.cs#L21-L28)

## Steps

1. **Enable the adaptation macro (menu recommended)**: In the editor menu `Tools` > `FairyGUI`, select the menu item for WeChat or Douyin to quickly write/remove the `ENABLE_WECHAT_MINI_GAME` or `ENABLE_DOUYIN_MINI_GAME` script macro definitions (the quick toggles described in the README). You can also add them manually in `Edit > Project Settings > Player > Scripting Define Symbols`.
2. **Enable only one of them**: The WeChat and Douyin switch macros must **not be enabled at the same time**, otherwise both adapters will be compiled into the package. The original text warns: `Note: do not enable together with Douyin` / `Note: do not enable together with WeChat`.
   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/README.zh-CN.md#L34-L37)
3. **Confirm the SDK macro has been injected**: `WECHAT_MINI_GAME` after a WeChat build and `DOUYIN_MINI_GAME` after a Douyin build are defined automatically by their respective SDKs; if they are missing, the `#if` conditions are not met and the adaptation code is stripped out entirely.
4. **Verify**: Build to the Mini Game environment and run it; when `GTextInput` is clicked and gains focus, the keyboard is automatically brought up, and the input content is written back to `GTextInput.text` in real time.

Once the macro is enabled, `GTextInput` automatically creates the adapter for the corresponding platform at construction time and releases it in `Dispose`:

```csharp
#if UNITY_WEBGL
#if WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME
        private GTextInputWeChat weChatTextInput;
#endif
#if DOUYIN_MINI_GAME && ENABLE_DOUYIN_MINI_GAME
        private GTextInputDouYin douYinTextInput;
#endif
#endif

        public GTextInput()
        {
            _textField.autoSize = AutoSizeType.None;
            _textField.wordWrap = false;
#if UNITY_WEBGL
#if WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME
            weChatTextInput = new GTextInputWeChat(this);
#endif
#if DOUYIN_MINI_GAME && ENABLE_DOUYIN_MINI_GAME
            douYinTextInput = new GTextInputDouYin(this);
#endif
#endif
        }
```

## Common Variants

**WeChat Mini Game**: The adapter listens to `onFocusIn`/`onFocusOut`, uses `WX.ShowKeyboard` to bring up the keyboard and binds three callbacks; `multiple` is determined by whether the input field is single-line, and `confirmHold = true` means the keyboard does not collapse automatically after the confirm key is tapped:

```csharp
private void ShowKeyboard()
{
    if (!_isShowKeyboard)
    {
        WX.ShowKeyboard(new ShowKeyboardOption()
        {
            multiple = _isMultiline,
            confirmHold = true,
            defaultValue = _textInput.text,
            maxLength = _textInput.maxLength,
            confirmType = "done"
        });

        // Bind callbacks
        WX.OnKeyboardConfirm(OnConfirm);
        WX.OnKeyboardComplete(OnComplete);
        WX.OnKeyboardInput(OnInput);
        _isShowKeyboard = true;
    }
}
```

Source: [Runtime/UI/GTextInputWeChat.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputWeChat.cs#L62-L81)

**Douyin Mini Game**: The keyboard is brought up via the Stark SDK's `GetStarkKeyboard()`, and events are registered as C# events (`+=`/`-=`):

```csharp
private void ShowKeyboard()
{
    if (!_isShowKeyboard)
    {
        StarkSDK.API.GetStarkKeyboard().ShowKeyboard(new StarkKeyboard.ShowKeyboardOptions()
        {
            defaultValue = _textInput.text,
            maxLength = _textInput.maxLength,
            multiple = isMultiLine,
            confirmType = "done"
        });

        RegisterKeyboardEvents();
        _isShowKeyboard = true;
    }
}
```

Source: [Runtime/UI/GTextInputDouYin.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputDouYin.cs#L83-L98)

**Regular WebGL (browser)**: No macros are needed. The package's `Plugins/WebGL/WebGLTextInput.jslib` overlays a DOM input layer on top of the canvas (`WebGLTextInputSetText` / `WebGLTextInputShow` / `WebGLTextInputHide`), which is called directly by Unity's WebGL build.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Tapping the input field brings up no keyboard | `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` not enabled | Enable the corresponding macro via the `Tools > FairyGUI` menu or the Player settings |
| Compilation reports duplicate definitions or both keyboards pop up at the same time | The WeChat and Douyin switch macros are enabled at the same time | Keep only one platform macro; the two are mutually exclusive |
| The macro is enabled but still has no effect at runtime | The SDK did not inject the platform macros (`WECHAT_MINI_GAME` / `DOUYIN_MINI_GAME` missing) | Confirm that the WeChat WASM SDK or the Douyin Stark SDK is installed and configured correctly, then rebuild |
| The on-screen text does not update after input | Write-back only happens in the `focused` state (`if (_textInput.focused)`) | Check whether the input field has lost focus; tap it again to give it focus if necessary |

## Verification

- Build to the corresponding Mini Game environment and run it, then tap `GTextInput`:
  - WeChat: after the keyboard pops up, every input triggers `OnInput`, the content is written back to `_textInput.text` in real time and the cursor is moved to the end; tapping "Done" triggers `OnConfirm` and then the keyboard collapses.
    Source: [Runtime/UI/GTextInputWeChat.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputWeChat.cs#L29-L50)
  - Douyin: input triggers `OnKeyboardInput`, and `OnKeyboardComplete` also writes the text back.
    Source: [Runtime/UI/GTextInputDouYin.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputDouYin.cs#L47-L67)
- When focus is lost (`onFocusOut`), the keyboard hides automatically and all event listeners are unbound; you can further confirm in `Dispose` that the listeners have been removed.

## Background

The adapter hooks `onFocusIn`/`onFocusOut` when `GTextInput` is constructed, bridging FairyGUI's focus events to the platform keyboard API; the input callbacks uniformly write the platform keyboard's value back to `_textInput.text` and call `SetSelection` to move the cursor; the whole chain only participates in compilation when `UNITY_WEBGL` + platform macro + switch macro are all satisfied at the same time, so it has zero impact on non-Mini-Game targets.
