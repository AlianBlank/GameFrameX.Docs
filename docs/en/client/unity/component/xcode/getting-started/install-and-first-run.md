# Installation and First Run

The GameFrameX Xcode Config is a Unity Package. After installation, you don't need to write any C# code—simply place a `XCodeConfig.json` in your project, and when the iOS build finishes, Xcode project modifications such as Info.plist, signing, Capabilities, and CocoaPods are applied automatically. This page walks you through the complete process, from installing the package to your first successful run.

## Quick Start

### 1. Install the Package

Choose any one of the following methods (scopedRegistries is recommended, for easier unified version management):

**Method 1: Scoped Registry (allows specifying a version)** — Edit `Packages/manifest.json`:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.xcode": "1.11.1"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L47-L63)

`scopes` controls which packages are resolved through this registry: only packages whose names start with `com.gameframex` will be fetched from it.

**Method 2: Git URL** — Add it under the `dependencies` node in `manifest.json`:

```json
{
   "com.gameframex.unity.xcode": "https://github.com/gameframex/com.gameframex.unity.xcode.git"
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L67-L72)

**Method 3: Package Manager** — In Unity's `Package Manager`, add it using the `Git URL` method, with the same URL as above.

**Method 4: Download the repository directly** and place it in the Unity project's `Packages` directory; it will be loaded and recognized automatically.

Environment requirements: Unity 2019.4 or later.

### 2. Create the Configuration File

The configuration file **must be named `XCodeConfig.json`** and can be placed anywhere in the project; multiple files can coexist and are automatically deep-merged at build time (ideal for multi-module collaboration). If you need to differentiate by channel, you can also create `XCodeConfig.{channel}.json`; the channel configuration is merged last and has the highest priority.

The top-level structure is as follows:

```json
{
  "swiftBridging": true,
  "signing": {},
  "plist": {},
  "environmentVariables": {},
  "launcherArgs": [],
  "podSource": [],
  "podfile": "",
  "podInstall": true,
  "localizations": [],
  "capabilities": {},
  "unityFramework": {},
  "unityMain": {}
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L79-L96)

Minimal working example (disable Bitcode + write one plist entry + add one system framework):

```json
{
  "plist": { "NSCameraUsageDescription": "用于拍摄头像" },
  "unityMain": {
    "properties": { "=": { "ENABLE_BITCODE": "NO" } },
    "frameworks": { "+": [ "WebKit.framework" ], "-": [] }
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L145-L173)

Quick overview of common top-level fields:

| Field | Type | Description |
| :--- | :--- | :--- |
| `swiftBridging` | bool | Automatically generates the Swift bridging header file (default `true`) |
| `signing` | object | Code signing configuration (Team ID, Bundle Identifier, etc.) |
| `plist` | object | Info.plist key-value pairs; values can be of any type |
| `capabilities` | object | iOS app capabilities (in-app purchase, push notifications, iCloud, etc.) |
| `podfile` / `podInstall` | string / bool | Custom Podfile path / whether to automatically run `pod install` (default `true`) |
| `unityMain` / `unityFramework` | object | Configurations for the Unity-iPhone and UnityFramework targets, respectively |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L98-L111)

### 3. Build for iOS and Verify

1. In Unity, switch the platform to iOS and perform the build (File → Build Settings → Build).
2. After the build finishes, the tool runs automatically in the `[PostProcessBuild(888)]` callback—later than most other post-processing scripts, and it only takes effect when the target is `BuildTarget.iOS`:

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        // Read the configuration files
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // If no matching files are found, return directly
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L32)

3. Check the Unity Console logs. Seeing the following output means the installation was successful and the whole workflow has completed:
   - `[MergeConfig] 正在合并配置: <your XCodeConfig.json path>`
   - `[PBXProject] 正在应用最终合并配置...`
   - `[OtherSettings] 正在应用最终合并配置...`
4. Open the generated Xcode project to confirm the results: your configured keys appear in Info.plist, `ENABLE_BITCODE` in Build Settings has changed to `NO`, and so on.

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L38-L107)

If the log shows `未找到任何 XCodeConfig 相关配置文件, 跳过设置`, it means the file name is not `XCodeConfig.json` (case-sensitive) or the file is not inside the project directory; rename or move it and rebuild.

## Common Variants

- **Multiple modules with multiple configs**: Different modules each place their own `XCodeConfig.json`; at build time they are deep-merged in file order; for the same key, "the one merged later overwrites the earlier one."
- **Channel differentiation**: The channel is detected via `SettingLoader.GetChannel()`, then `XCodeConfig.{channel}.json` is read and merged last as an override. See [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77) for the relevant logic.
- **Skip pod install**: Set `"podInstall": false` to skip the automatic `pod install`; if you have a custom Podfile, specify it via `"podfile": "<path>"` (this takes priority over the `pods` field). See [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Console reports `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | The file name is not `XCodeConfig.json`, or the file is not in the project directory | Name the file exactly `XCodeConfig.json` (case-sensitive) and rebuild |
| Console reports `<path> 解析失败, 跳过合并` | JSON syntax error | Check it with a JSON validation tool, fix it, and rebuild |
| Console reports `合并后的配置为空，跳过设置` | The file exists but its content is an empty object | Write at least one valid field |
| No changes in the Xcode project after the build | The build target is not iOS, or an exception thrown in the callback was swallowed | Confirm that BuildTarget is iOS; check the Console for exception stack traces output by `Debug.LogException` |

All of the above error messages are quoted verbatim from the actual logs in [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83).

## Verification

1. The Console shows the three log sections `[MergeConfig]` → `[PBXProject]` → `[OtherSettings]`, with no red Errors.
2. Open the build output directory in Xcode and confirm: the `plist` entries have been written into Info.plist; Build Settings match the `properties` settings; if `podfile`/`pods` was configured, a Podfile has been generated in the project directory and the dependencies are installed.

## Background

The tool writes in two phases: the first phase applies build properties, frameworks, libraries, file copying, compile flags, etc. to the two targets `Unity-iPhone` and `UnityFramework` and saves `project.pbxproj`; the second phase handles Plist, environment variables, launcher arguments, Capabilities, localizations, and CocoaPods, and re-reads the project file after Capabilities is written to disk separately in order to preserve those modifications. Swift bridging is enabled by default, and signing and Capabilities are set only on the main project. See [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156) for the complete implementation.
