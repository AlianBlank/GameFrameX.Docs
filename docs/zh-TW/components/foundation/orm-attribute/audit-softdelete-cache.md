# 如何為實體附加稽核/軟刪除/快取功能

只要在實體類別上使用 `AuditTableAttribute`、`SoftDeleteAttribute`、`CacheTableAttribute` 三個特性，即可僅以一行宣告 ORM 的稽核追蹤、軟刪除與查詢快取功能，無需修改業務程式碼便能讓 ORM 框架加以識別。

## 前置條件

- 專案必須參考 `GameFrameX.Foundation.Orm.Attribute` 組件（包含 3 個特性類別）以及 `GameFrameX.Foundation.Orm.Entity`（包含 `IAuditableEntity` 介面）。
- 實體類別必須使用 `GameFrameX.Foundation.Orm.Attribute` 命名空間下的特性，並在檔案中撰寫 `using GameFrameX.Foundation.Orm.Attribute;`。
- 若要取得自動填入的「建立/更新時間/操作者」欄位，必須讓實體實作 `IAuditableEntity` 介面（位於 `GameFrameX.Foundation.Orm.Entity` 命名空間下）。

## 操作步驟

### 1. 啟用稽核追蹤

將 `[AuditTable]` 套用至實體類別。預設為 `Enabled = true`、`AuditLevel = ChangesOnly`、`IncludeUserInfo = true`，會記錄 INSERT/UPDATE/DELETE 的變更歷程。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[AuditTable(AuditLevel = AuditLevel.Full, IncludeUserInfo = true, IncludeIpAddress = true)]
public class UserAccount
{
    public int Id { get; set; }
    public string Username { get; set; }
    public decimal Balance { get; set; }
    public DateTime LastLoginTime { get; set; }
}
```

來源：[AuditTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/AuditTableAttribute.cs#L74-L143)

若要自訂稽核資料表名稱，請在 `AuditTableName` 中設定具體的資料表名稱。若要停用稽核，請將 `Enabled` 設定為 `false`。

### 2. 啟用軟刪除

建構函式至少必須傳入「軟刪除旗標欄位」，並可視需要傳入「刪除時間欄位」與「刪除使用者欄位」。預設為 `AutoFilter = true`，查詢時會自動排除已刪除的記錄。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[SoftDelete("IsDeleted", "DeletedTime", "DeletedBy")]
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }
    public string? DeletedBy { get; set; }
}
```

來源：[SoftDeleteAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SoftDeleteAttribute.cs#L74-L175)

若旗標欄位不是 `bool` 型別，可透過屬性自訂 `DeletedValue` 與 `NotDeletedValue`，例如以字串 `"DELETED"` / `"ACTIVE"` 識別狀態的情況。

### 3. 啟用查詢快取

將 `[CacheTable]` 套用至實體類別後，ORM 框架會依據 `CacheType` + `ExpireMinutes` 啟用對應的快取策略。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[CacheTable(CacheType = "Redis", ExpireMinutes = 30, KeyPrefix = "ProductInfo:")]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public DateTime LastModified { get; set; }
}
```

來源：[CacheTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/CacheTableAttribute.cs#L74-L137)

### 4. 組合使用：稽核 + 軟刪除 + 可稽核欄位

若同時讓實體實作 `IAuditableEntity`，寫入時 ORM 會自動維護 `CreateTime`、`UpdateTime`、`CreateUserId/Name`、`UpdateUserId/Name` 欄位，並與 `[AuditTable]` 結合，形成完整的稽核閉環。

```csharp
using GameFrameX.Foundation.Orm.Attribute;
using GameFrameX.Foundation.Orm.Entity;

[AuditTable(AuditLevel = AuditLevel.ChangesOnly)]
[SoftDelete("IsDeleted", "DeletedTime")]
[CacheTable(CacheType = "Memory", ExpireMinutes = 10)]
public class OrderInfo : IAuditableEntity
{
    public int Id { get; set; }
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }

    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }

    public DateTime? CreateTime { get; set; }
    public DateTime? UpdateTime { get; set; }
    public long? CreateUserId { get; set; }
    public string? CreateUserName { get; set; }
    public long? UpdateUserId { get; set; }
    public string? UpdateUserName { get; set; }
}
```

## 常見變化

- **只稽核欄位、不記錄使用者**：將 `IncludeUserInfo` 設定為 `false`，避免在無需追蹤到人的情境下儲存冗餘欄位。
- **停用查詢自動過濾**：在軟刪除情境下若需查看全部資料（含已刪除），可將 `AutoFilter` 設定為 `false`，由呼叫端自行附加 `WHERE` 條件。
- **以字串狀態欄位進行軟刪除**：將 `DeletedValue` / `NotDeletedValue` 改為 `"DELETED"` / `"ACTIVE"`，以適應狀態機型別的欄位。
- **多種快取後端共存**：為每個實體選擇不同的 `CacheType`（例如：熱門資料使用 `Memory`、跨處理序共用使用 `Redis`），並以 `KeyPrefix` 避免索引鍵衝突。
- **執行階段暫時停用**：在單元測試或移轉指令碼中，可將對應特性的 `Enabled` 設定為 `false`，以停用目前實體的稽核/快取。

## 常見錯誤

- **忘記填寫 `DeletedField` 建構函式參數**：三個 `SoftDeleteAttribute` 建構函式皆將 `deletedField` 標記為必要參數，傳入 `null` 會立即擲回 `ArgumentNullException`。請務必傳入有效的資料行名稱。
- **旗標欄位型別與 `DeletedValue` 不相符**：預設為 `DeletedValue = true`、`NotDeletedValue = false`，但若旗標欄位為 `string` 或 `int`，則必須明確指定字串/整數值，否則 ORM 產生的 SQL 會發生型別轉換錯誤。
- **將多個特性重複套用至同一類別**：三個特性皆設定為 `AllowMultiple = false`，對同一實體重複套用會導致編譯錯誤。若需要不同行為，請以特性參數加以區分。
- **快取索引鍵衝突**：若未設定 `KeyPrefix`，多個實體會共用預設前置詞而導致索引鍵衝突，降低快取命中率。建議設定以實體名稱為基礎的 `"{EntityName}:"` 前置詞。
- **將稽核與備份混為一談**：稽核僅記錄變更歷程，不會儲存刪除前的完整快照。若需要「還原任意時間點資料」的功能，請與軟刪除或自訂快照機制併用。

## 背景（選讀）

三個特性皆以 `AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = true)` 標註，這表示：只能套用於類別、每個類別僅能套用一次、且會由衍生類別繼承。ORM 會在實體註冊階段透過反射讀取這些特性，以決定要產生稽核攔截器、在 `WHERE` 中附加軟刪除條件，還是使用快取通道。`IAuditableEntity` 介面的欄位則供 ORM 自動寫入稽核所需的內容資訊。
