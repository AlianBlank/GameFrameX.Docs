# 如何在 WebGL 平台使用

在 WebGL 平台下使用 `ImageCacheComponent` 加载远程图片时，组件会自动切换到浏览器托管的 `UnityWebRequestTexture` 通道，本地磁盘缓存相关 API 会变成空操作，无需为 WebGL 编写额外分支代码。

## 前置条件

- 已将 `GameFrameXImageCacheCroppingHelper` 与 `ImageCacheComponent` 加入场景或运行时入口。
- WebGL 构建里允许跨域加载远程图片（服务器返回 CORS 头，或在 Player Settings 中配置 `Allow downloads over HTTP` / `Use default CORS`）。
- 远程图片 URL 必须以 `http://` 或 `https://` 开头，组件会校验前缀。

## 操作步骤

1. 在场景中挂载 `ImageCacheComponent` 后，正常调用 `LoadImageAsync`。WebGL 下组件会调用 `LoadImageWebGLAsync` 走 `UnityWebRequestTexture`，由浏览器自身的 HTTP 缓存托管。

   ```csharp
   using System.Threading;
   using System.Threading.Tasks;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   public class WebGLSample : MonoBehaviour
   {
       public ImageCacheComponent imageCache;

       public async Task<Sprite> LoadRemoteIcon(string url, CancellationToken ct = default)
       {
           Texture2D tex = await imageCache.LoadImageAsync(url, ct);
           if (tex == null)
           {
               Debug.LogWarning($"加载失败：{url}");
               return null;
           }
           return Sprite.Create(tex, new Rect(0, 0, tex.width, tex.height), Vector2.one * 0.5f);
       }
   }
   ```

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L115)

2. WebGL 下 `IsCached`、`RemoveCache`、`ClearCache` 始终不可用：前者在 WebGL 上始终返回 `false`，后两者直接不支持磁盘缓存。请在调用前判平台，避免业务出现误导日志。

   ```csharp
   if (Application.platform != RuntimePlatform.WebGLPlayer)
   {
       bool hit = imageCache.IsCached(url);
       // …非 WebGL 才走磁盘缓存判断
   }
   ```

   Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L28-L47)

3. 处理跨域与混合内容：浏览器默认禁止跨域纹理。远程服务器需返回 `Access-Control-Allow-Origin`，或在同一域下托管图片；HTTPS 站点请使用 HTTPS 图片 URL，否则浏览器会拦截请求。

4. 释放纹理：`UnityWebRequestTexture.GetContent` 返回的 `Texture2D` 不会被框架自动销毁，组件卸载或切场景时记得 `Object.Destroy(texture)`，避免显存泄漏。

5. 取消令牌仅在非 WebGL 平台生效。WebGL 下 `CancellationToken` 传入会被忽略，请在 UI 层（例如关闭面板）直接丢弃返回的 `Task` 即可。

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L66-L89)

## 常见变体

- **编辑器中模拟 WebGL**：在 Editor 下运行仍是磁盘缓存逻辑；想验证 WebGL 行为请通过 `File → Build Settings → WebGL → Build And Run` 发布后调试。
- **使用 UnityWebRequest 直接调用**：若业务需要额外处理进度或自定义 header，可以在 WebGL 分支单独走 `UnityWebRequestTexture.GetTexture`，不必经过 `ImageCacheComponent`。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `url must start with http:// or https://.` 警告 | URL 缺少协议头或使用相对路径 | 补全 `https://` 前缀 |
| 浏览器报 CORS / Mixed Content 错误 | 远程服务器未返回 CORS 头或协议不一致 | 服务端加 `Access-Control-Allow-Origin`，或同域 / 同协议托管资源 |
| 调用 `RemoveCache` / `ClearCache` 没生效 | WebGL 下无磁盘缓存 | 业务层隐藏这两个入口；改用浏览器自身的缓存清理策略 |
| `IsCached` 一直返回 `false` | WebGL 下不感知浏览器缓存 | 直接走 `LoadImageAsync`，由浏览器决定命中 |
| 反复切场景后显存增长 | WebGL 返回的 `Texture2D` 未释放 | 在场景卸载 / 替换图片前 `Object.Destroy(texture)` |

## 背景（可选）

非 WebGL 平台下，`ImageCacheComponent.Awake` 会通过 `IDownloadManager` 拉取文件并以 URL 的 MD5 作为文件名落盘；WebGL 下 `#if !UNITY_WEBGL` 的整段代码被剔除，因此 `IDownloadManager` 在 WebGL 中既不会被引用也不会被注入。WebGL 平台仅依赖 `UnityEngine.Networking.UnityWebRequestTexture`，浏览器接管所有缓存逻辑，组件因此在 WebGL 上无需也无法干预磁盘。

相关组件的整体流程见 [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L1-L100)。
