# 如何做熱更新:版本檢查、清單更新與補丁下載

熱更新由 `EPatchStates` 列舉定義的 5 個狀態驅動:`UpdateStaticVersion`(更新靜態資源版本)→ `UpdateManifest`(更新補丁清單)→ `CreateDownloader`(建立下載器)→ `DownloadWebFiles`(下載遠端檔案)→ `PatchDone`(補丁流程完畢)。本任務把「啟動補丁 → 訂閱狀態變更 → 失敗回滾 → 進入主流程」打通，讓你在業務程式碼裡跑通完整的熱更鏈路。

## 前置條件

- 已透過 `GameFrameX.Runtime` 的 `GameEntry` 取得 `AssetComponent` 實例(框架入口相關參見《快速開始》)。
- 遠端伺服器已經按 YooAsset 的目錄結構部署好：根目錄下的 `{platform}/{version}/{packageName}` 必須包含 `GameVersion.txt`、`{packageName}_PatchManifest_{version}.bytes`、`{packageName}_StaticVersion_{version}.bytes` 等檔案。
- 專案裡 `AssetPatchStatesChangeEventArgs` 等事件類型需要保留(程式碼裡已帶 `[UnityEngine.Scripting.Preserve]`,避免被裁剪)。

## 操作步驟

### 1. 訂閱補丁狀態變更事件

透過 `GameFrameX` 事件匯流排訂閱 `AssetPatchStatesChangeEventArgs`,每進入下一個狀態會收到回呼，即可用來重新整理進度條 UI。

```csharp
GameEntry.Event.Subscribe(AssetPatchStatesChangeEventArgs.EventId, OnPatchStatesChange);

private void OnPatchStatesChange(object sender, GameEventArgs e)
{
    var args = (AssetPatchStatesChangeEventArgs)e;
    // args.PackageName: 目前正在更新的資源包名
    // args.CurrentStates: EPatchStates 列舉(見下表)
    Debug.Log($"[{args.PackageName}] 進入階段:{args.CurrentStates}");
}
```

Source: [AssetPatchStatesChangeEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchStatesChangeEventArgs.cs#L18-L46)

### 2. 訂閱「發現待更新檔案」與「下載進度」事件(可選但推薦)

這兩個事件用來在 UI 上展示「共多少檔案需要下載」「目前下載到第幾個/總共多大」。

| 事件 EventId | 事件參數 | 觸發時機 | 關鍵欄位 |
|---|---|---|---|
| `AssetFoundUpdateFilesEventArgs.EventId` | `AssetFoundUpdateFilesEventArgs` | CreateDownloader 之後、DownloadWebFiles 之前 | 待下載檔案總數、總大小 |
| `AssetDownloadProgressUpdateEventArgs.EventId` | `AssetDownloadProgressUpdateEventArgs` | 每個檔案下載過程中 | 目前進度、已下載/總大小、剩餘大小 |

### 3. 訂閱失敗事件並處理回滾

熱更過程中任何一步失敗都會拋出對應的事件參數，需要在訂閱處做重試或降級處理：

```csharp
GameEntry.Event.Subscribe(AssetStaticVersionUpdateFailedEventArgs.EventId, OnStaticVersionFailed);
GameEntry.Event.Subscribe(AssetPatchManifestUpdateFailedEventArgs.EventId, OnManifestFailed);
GameEntry.Event.Subscribe(AssetWebFileDownloadFailedEventArgs.EventId, OnFileDownloadFailed);
```

Source: [AssetStaticVersionUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetStaticVersionUpdateFailedEventArgs.cs) · [AssetPatchManifestUpdateFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetPatchManifestUpdateFailedEventArgs.cs#L10-L25) · [AssetWebFileDownloadFailedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EventArgs/AssetWebFileDownloadFailedEventArgs.cs)

### 4. 啟動熱更新流程

呼叫 `AssetComponent` 提供的更新入口(實際簽章請以目前儲存庫 `Runtime/Asset/AssetComponent.cs` 為準)。一次完整的補丁工作階段會按順序進入下面五個狀態：

```csharp
// 在 Boot 階段(GameEntry 啟動後)呼叫一次即可
var assetComponent = GameEntry.GetComponent<AssetComponent>();
assetComponent.UpdatePackages(); // 拉取版本號 → 比對清單 → 建立下載器 → 下載 → 回呼 PatchDone
```

觸發後，事件匯流排會按順序廣播：
1. `EPatchStates.UpdateStaticVersion` —— 對比遠端 `GameVersion.txt` 與本機快取版本。
2. `EPatchStates.UpdateManifest` —— 拉取 `{packageName}_PatchManifest_{version}.bytes` 與本機清單做差分。
3. `EPatchStates.CreateDownloader` —— 建構 `AssetDownloadProgressUpdateEventArgs` 等所需的下載器。
4. `EPatchStates.DownloadWebFiles` —— 真正下載差分檔案；每個檔案回呼一次 `AssetDownloadProgressUpdateEventArgs`。
5. `EPatchStates.PatchDone` —— 流程結束，可以安全進入主場景。

Source: [EPatchStates.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Update/EPatchStates.cs#L6-L32)

## 常見變體

| 場景 | 做法 |
|---|---|
| 跳過檢查直接用本機資源 | 呼叫 `AssetComponent` 的「僅本機」初始化多載，根本不進入 `UpdatePackages` |
| 只更新單一資源包 | 在 `UpdatePackages` 之前透過 `SetForceUpdateAllPackageVersions(true)` 之類開關控制範圍 |
| 斷點續傳 | 事件 `AssetDownloadProgressUpdateEventArgs` 中保留已下載位元組數，再次呼叫 `UpdatePackages` 時框架會自動續傳未完成的檔案 |

## 常見錯誤

| 症狀 | 可能原因 | 規避 |
|---|---|---|
| `EPatchStates.PatchDone` 始終沒觸發 | 事件沒訂閱或訂閱的 EventId 拼寫錯 | 用 `typeof(AssetPatchStatesChangeEventArgs).FullName` 作為 EventId,不要手寫字串 |
| 下載到一半無回應 | 沒訂閱 `AssetDownloadProgressUpdateEventArgs`,下載器可能被主執行緒等待 | 給下載器單獨開非同步上下文;UI 上顯示進度 |
| 遠端清單 404 | 伺服器沒部署 `{packageName}_PatchManifest_{version}.bytes` | 用框架內建上傳工具(參見 YooAsset 官方 Builder)重新上傳；事件 `AssetPatchManifestUpdateFailedEventArgs` 會帶錯誤訊息 |
| 靜態版本檔案下載失敗 | 伺服器缺 `{platform}/GameVersion.txt` 或快取目錄唯讀 | 檢查 `Application.persistentDataPath` 寫入權限；監聽 `AssetStaticVersionUpdateFailedEventArgs` |

## 背景(可選)

`EPatchStates` 把 YooAsset 的整套補丁生命週期抽象為 5 個列舉值，框架層只負責在狀態切換時把 `AssetPatchStatesChangeEventArgs` 拋到 `GameFrameX` 事件匯流排，業務側透過訂閱 EventId 解耦。這樣 UI、網路重試、降級策略都可以無侵入地替換，而補丁主流程保持穩定。
