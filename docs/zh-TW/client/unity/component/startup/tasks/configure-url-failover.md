# URL 主要-備援 failover 策略設定方法

使用 `UrlFailoverRunner.ExecuteAsync` 可讓 URL 群組依序執行主要-備援切換，並可針對每個 URL 最多重試 N 次。本頁介紹可直接複製執行的最小用法、參數意義，以及常見的陷阱。

## 前置條件

- 專案中必須已安裝 `com.gameframex.unity.startup` 套件，並參考 `GameFrameX.Startup.Runtime` 命名空間。
- 業務端必須實作 `Func<string, UniTask<UrlAttemptResult>>` 委派，對單一 URL 傳送實際請求(GET/POST 等)，並依回應傳回 `UrlAttemptResult.Succeed()` 或 `UrlAttemptResult.Fail(errorMessage)`。
- 必須引入 `Cysharp.Threading.Tasks` 與 `UniTask` 非同步機制(`using Cysharp.Threading.Tasks;`)。

## 操作步驟

1. **準備 URL 清單**。將候選 URL 依「主要—備援—備援…」順序放入 `IReadOnlyList<string>`,執行階段會依陣列索引順序嘗試。

2. **實作單一 URL 嘗試委派**。對每個 URL 傳送一次請求，並依 HTTP 狀態碼或業務碼傳回成功或失敗的結果。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;
   using UnityEngine.Networking;

   UniTask<UrlAttemptResult> TryFetchAsync(string url)
   {
       return UniTask.RunOnThreadPool(async () =>
       {
           using var req = UnityWebRequest.Get(url);
           await req.SendWebRequest();
           if (req.result == UnityWebRequest.Result.Success)
           {
               return UrlAttemptResult.Succeed();
           }
           return UrlAttemptResult.Fail(req.error ?? "unknown error");
       });
   }
   ```

   出處： [UrlAttemptResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlAttemptResult.cs#L6-L27)

3. **呼叫 `UrlFailoverRunner.ExecuteAsync`**。傳入 URL 清單、每個 URL 的最大嘗試次數、重試間隔(毫秒)，以及前一步驟的委派。

   ```csharp
   using System.Collections.Generic;
   using System.Threading;
   using Cysharp.Threading.Tasks;
   using GameFrameX.Startup.Runtime;

   public async UniTask<UrlFailoverResult> RunAsync(CancellationToken ct = default)
   {
       var urls = new[] { "https://api-primary.example.com", "https://api-backup.example.com" };

       return await UrlFailoverRunner.ExecuteAsync(
           urls,
           maxAttemptsPerUrl: 3,
           retryDelayMs: 500,
           attempt: TryFetchAsync,
           onProgress: (url, attempt, total) =>
               UnityEngine.Debug.Log($"try {attempt}/{total} -> {url}"),
           cancellationToken: ct);
   }
   ```

   出處： [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L14-L43)

4. **處理傳回的 `UrlFailoverResult`**。成功時使用業務資料；失敗時則依據 `FailedUrl` 與 `ErrorMessage` 決定要執行後備(fallback)邏輯，還是回報追蹤事件。

   ```csharp
   var result = await RunAsync(this.GetCancellationTokenOnDestroy());
   if (!result.Success)
   {
       UnityEngine.Debug.LogError($"all URLs failed. last={result.FailedUrl}, err={result.ErrorMessage}");
       return;
   }
   ```

   出處： [UrlFailoverResult.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverResult.cs#L6-L30)

## 常見變化

- **同步寫法(常見於單元測試)**。將委派寫成立即傳回 `UniTask.FromResult(...)`,因此無需等待。

  ```csharp
  var result = await UrlFailoverRunner.ExecuteAsync(
      new[] { "http://a", "http://b" },
      maxAttemptsPerUrl: 2,
      retryDelayMs: 0,
      attempt: url => UniTask.FromResult(
          url == "http://b" ? UrlAttemptResult.Succeed() : UrlAttemptResult.Fail("down")));
  ```

  出處： [UrlFailoverRunnerTests.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Tests/Runtime/UrlFailoverRunnerTests.cs#L63-L85)

- **只進行主要-備援切換、不做重試**。將 `maxAttemptsPerUrl` 設為 `1`、`retryDelayMs` 設為 `0`,即為「失敗一次就立即切換到下一個 URL」,而且沒有延遲。

  ```csharp
  await UrlFailoverRunner.ExecuteAsync(urls, maxAttemptsPerUrl: 1, retryDelayMs: 0, attempt: TryFetchAsync);
  ```

  出處： [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L68-L71)

- **使用進度回呼**。`onProgress(url, attempt, total)` 會在每次嘗試前觸發，且 `attempt` 從 `1` 開始計數，因此適合用來驅動 UI 進度條。

  出處： [UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L57-L57)

## 常見錯誤

| 現象 | 原因 | 解決方法 |
|------|------|------|
| 同步擲回 `ArgumentNullException`,參數名稱為 `urls` | 對 URL 清單傳入 `null` | 應傳入非 `new string[0]` 的清單；空陣列會擲回 `ArgumentException` |
| 同步擲回 `ArgumentException`,訊息為 "URL list must contain at least one URL." | 傳入空陣列 `new string[0]` | 必須至少包含 1 個 URL |
| 同步擲回 `ArgumentException`,訊息為 "Max attempts per URL must be greater than zero." | `maxAttemptsPerUrl < 1` | 將每個 URL 的嘗試次數設為 ≥ 1 |
| 同步擲回 `ArgumentException`,訊息為 "Retry delay must be zero or greater." | `retryDelayMs < 0` | 設為 `0` 或正整數 |
| 同步擲回 `ArgumentNullException`,參數名稱為 `attempt` | 對嘗試委派傳入 `null` | 傳入有效的 `Func<string, UniTask<UrlAttemptResult>>` 給 `attempt` |
| 所有 URL 失敗時，業務端收到 `result.Success == false`,但 `FailedUrl` 為空字串 | 從未在任何 URL 上呼叫過失敗路徑(幾乎不會發生)，或所有失敗都被忽略 | 確認委派內是否一律傳回 `UrlFailoverResult.Fail(...)` |

驗證這些參數條件約束的實作位於 `UrlFailoverRunner.ExecuteAsync` 的進入點。

## 背景(選用)

`UrlFailoverRunner` 是以「URL 順序 × 每個 URL 嘗試次數」雙層迴圈執行的靜態工具類別。外層迴圈走訪 `urls`,內層迴圈則對單一 URL 重複呼叫傳入的 `attempt` 委派，直到成功或 `maxAttemptsPerUrl` 用盡為止。一旦某個 URL 成功，便立即傳回 `UrlFailoverResult.Succeed()`,不再嘗試後續的 URL。只有當所有 URL 的所有重試都失敗時，才會傳回包含最後失敗的 URL 與錯誤資訊的 `UrlFailoverResult.Fail(...)`。若 `retryDelayMs > 0`,會在同一 URL 的兩次嘗試之間以 `UniTask.Delay` 等待；若 `maxAttemptsPerUrl == 1`,則既不等待也不重試。
