# How to Create a New Configuration Table

Create a new Excel file that follows the naming convention in `Excels/Tables/`, define the fields using the 4 fixed header rows and fill in the data, then run the generation script. The tool will automatically produce the corresponding C# classes and data files, which can be read directly in the game via `tables.TbXxx.Get(id)`.

## Prerequisites

- The repository root has been cloned locally (including `Excels/`, `Tools/`, `luban.conf`, `gen-*.bat/.sh`).
- A tool capable of editing `.xlsx` files is installed (e.g., Microsoft Excel, WPS, Numbers).
- `UNITY_ASSETS_PATH` and `SERVER_PATH` in `luban.conf` have been configured; otherwise the generation script cannot find the target directories (both values are left empty by default in the repository).

## Steps

### 1. Create a New Excel File in the Tables Directory

Go to `Excels/Tables/` and create a new Excel file. The filename follows the `letter - English name - Chinese name.xlsx` rule:

```
D-MyItem-我的道具表.xlsx
```

Meaning of each segment:

| Segment | Purpose | Example |
|---------|---------|---------|
| Letter | Used for file sorting; a single letter is enough | `D` |
| English name | **Becomes the code class name** (a `Tb` prefix is added automatically); must be entirely in English | `MyItem` → `TbMyItem` |
| Chinese name | Human-readable description; can be anything | `我的道具表` |

Chinese characters must not appear in the English name; otherwise Luban will throw a "Chinese table names are not supported" error. For existing naming examples, see `Excels/Tables/C-AchievementConfig-成就表.xlsx`, `D-ItemConfig-道具表-道具-1001.xlsx`, and `S-SoundsConfig-声音表.xlsx`.

### 2. Fill in the First 4 Fixed Header Rows

Open the newly created Excel file. The first 4 rows are the field definitions; fill them in according to the following rules:

| Row | Fixed Marker in Column 1 | Meaning |
|-----|--------------------------|---------|
| Row 1 | `##var` | Field name (English) |
| Row 2 | `##type` | Field type |
| Row 3 | `##group` | Field group (usually left empty) |
| Row 4 | `##` | Chinese description |

Example (using `D-MyItem-我的道具表.xlsx`):

| ##var | id | name | price |
|-------|----|------|-------|
| ##type | int | text | int |
| ##group | | | |
| ## | Item ID | Item Name | Price |

These four markers — `##var`/`##type`/`##group`/`##` — must be written exactly as shown; they cannot be omitted or renamed.

### 3. Fill in Data

Actual data starts from row 5, one record per row:

| ##var | id | name | price |
|-------|----|------|-------|
| ##type | int | text | int |
| ##group | | | |
| ## | Item ID | Item Name | Price |
| | 10001 | diamond | 10 |
| | 10002 | coin | 1 |

Common field types:

| Type | Meaning | Example |
|------|---------|---------|
| `int` | Integer | `10001` |
| `string` | Plain text (not localized) | `icon_diamond` |
| `text` | Localization key (must be translated in `Excels/Local/`) | `diamond` |
| `bool` | Yes/No | `true` / `false` |
| `float` | Decimal number | `1.5` |

### 4. Run the Generation Script

Go back to the repository root and run the corresponding script:

- **Windows**: Double-click `gen-client-json.bat` (generates client JSON + C# classes).
- **Mac / Linux**: Run `sh gen-client-json.sh` in a terminal.
- Server-side generation: Double-click `gen-server-json.bat` or run `sh gen-server-json.sh`.
- Generate binary versions (smaller, faster to load): `gen-client-bin.bat` / `gen-server-bin.bat`.

These scripts invoke the Luban toolchain specified by `toolPath` in `luban.conf` and run generation over all Excel files.

`Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L62-L94)`, `Source: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L10)`

### 5. Read Data in Code

The tool automatically generates the `TbMyItem` class and the data files. In code, simply fetch values by `id`:

```csharp
// Get the item with id 10001
var item = tables.TbMyItem.Get(10001);

// Localized fields automatically return text in the current language
Debug.Log(item.Name); // Displays "钻石" (Diamond) in a Chinese environment
Debug.Log(item.Price); // 10
```

## Common Variants

### Defining Separately for Client/Server

Adding a group marker between the English name and the Chinese name restricts the table's generation to the specified side:

| Filename | Effect |
|----------|--------|
| `D-ItemConfig-道具表.xlsx` | Used by both client and server |
| `D-ItemConfig-c-道具表.xlsx` | Client only |
| `D-ItemConfig-s-道具表.xlsx` | Server only |

`c` = client, `s` = server, corresponding to the `targets[*].groups` definitions in `luban.conf`.

### Splitting One Table into Multiple Files

When the data volume is large, you can split it into multiple xlsx files following the rule that the English name must be identical while the Chinese name can be arbitrary; the tool will automatically merge them into a single table. For example:

```
D-ItemConfig-道具表-道具-1001.xlsx
D-ItemConfig-道具表-道具-2001.xlsx
```

Both will be merged into `TbItemConfig`.

### Using Enum or Struct Fields

Complex field types must first be defined in `Excels/__enums__.xlsx` (enums) and `Excels/__beans__.xlsx` (structs), then referenced by name in the `##type` header row. Existing definition files: `Excels/__tables__.xlsx`, `Excels/__beans__.xlsx`, `Excels/__enums__.xlsx`.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| Error "Chinese table names are not supported" | The "English name" segment of the filename contains Chinese characters | Change it to pure English, e.g. `MyItem` |
| Generated class name is empty or `TbXxx` cannot be found | The filename does not follow the three-segment `letter-English name-Chinese name` format | Check that the filename follows the rule |
| All fields are 0/empty | Forgot to write `##var` in the first column of the field name row (row 1) | Add `##var` |
| A `text` field shows the key instead of the translated text in game | No translation for this key in `Excels/Local/` | Add an entry in `Excels/Local/L-Localization-*.xlsx` |
| Running `.bat/.sh` reports that Luban cannot be found | The `toolPath` in `luban.conf` is incorrect | Adjust `toolPath` to point to the local `Tools/Luban.dll` |
| Generated output is written to an empty directory | `UNITY_ASSETS_PATH` / `SERVER_PATH` not configured | Fill in the absolute paths in `luban.conf` |

## Background (Optional)

Under the hood, the tool is based on the open-source [Luban](https://github.com/GameFrameX/luban): it treats Excel as a "game data dictionary" and automatically converts it into code and data files that the client (Unity C#) and the server (.NET) can read directly. Designers only fill in the tables, programmers only call `tables.TbXxx.Get(id)`, and the steps in between are handled by Luban invoked through the `gen-*.bat/.sh` scripts.
