# 如何处理玩家登录与会话(Session)

本页帮助你完成两件事:让玩家通过客户端消息完成登录,以及在顶号/断线时正确管理玩家的网络会话。完成后玩家就能进入游戏逻辑,服务器也能正确清理离线玩家。

## 前置条件

- 客户端使用框架网络层(KCP/HTTP)发起请求,登录消息使用 Protobuf 协议号 `ReqPlayerLogin` / `RespPlayerLogin`。
- 服务端已启动 `GameApp`,并注册了 `SessionManager`(框架启动时自动加载)。
- 已存在账号服务 `LoginComponent`(位于 [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs)),并能通过账号 Token 获取到 `roleId`。

## 操作步骤

### 1. 实现登录请求处理器

新建 `ReqPlayerLoginHandler`,继承 `GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>`,框架会根据 `[MessageMapping]` 自动路由消息。

```csharp
using GameFrameX.Hotfix.Logic.Player.Login;
using GameFrameX.Apps.Player.Login.Component;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[MessageMapping(typeof(ReqPlayerLogin))]
internal sealed class ReqPlayerLoginHandler : GlobalRpcComponentHandler<LoginComponentAgent, ReqPlayerLogin, RespPlayerLogin>
{
    protected override async Task ActionAsync(ReqPlayerLogin request, RespPlayerLogin response)
    {
        await ComponentAgent.OnPlayerLogin(NetWorkChannel, request, response);
    }
}
```

Source: [ReqPlayerLoginHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/ReqPlayerLoginHandler.cs#L30-L38)

### 2. 在 LoginComponentAgent 中完成绑定

`OnPlayerLogin` 内部依次做四件事:校验账号/签名 → 拿到 `roleId` → 把 `roleId` 与 `sign` 写入当前 `Session` → 调用 `SessionManager.UpdateSession` 完成绑定并触发顶号逻辑。

```csharp
// 伪代码,展示调用顺序,真实签名见 LoginComponentAgent
var loginResult = await LoginComponent.LoginByToken(request.AccountToken); // 返回 roleId / sign
NetWorkChannel.Session.SetPlayerId(loginResult.RoleId);
NetWorkChannel.Session.SetSign(loginResult.Sign);
await SessionManager.UpdateSession(NetWorkChannel.Session.SessionId, loginResult.RoleId, loginResult.Sign);
```

实际签名由 `LoginComponentAgent.OnPlayerLogin(NetWorkChannel, request, response)` 提供,见 [LoginComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/LoginComponentAgent.cs)。

### 3. 监听 Session 移除事件完成下线收尾

实现 `SessionRemoveEventListener`,框架在会话被移除(主动 `Remove` 或顶号时清旧会话)时,会派发 `EventId.SessionRemove` 事件,触发玩家下线逻辑。

```csharp
using GameFrameX.Apps.Common.Event;
using GameFrameX.Core.Abstractions.Events;

namespace GameFrameX.Hotfix.Logic.Player.Login;

[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

Source: [SessionRemoveEventListener.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L30-L42)

### 4. 顶号与会话替换(框架已实现)

`SessionManager.UpdateSession` 内部会先调用 `GetByRoleId(roleId)` 找到旧会话,通过 `WriteAsync` 给旧连接下发 `Type=5` 的提示消息(`Apps.SessionManager.AccountAlreadyLoggedIn` 本地化文案),再 `ClearData()` + `Close()`,最后 `Remove(oldSession.SessionId)`。无需业务侧重复实现顶号,只需确保调用了 `UpdateSession`。

```csharp
// 摘录自 SessionManager.UpdateSession
var oldSession = GetByRoleId(roleId);
if (oldSession != null)
{
    var msg = new RespPrompt { Type = 5,
        Content = LocalizationService.GetString(Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn) };
    await oldSession.WriteAsync(msg);
    oldSession.WorkChannel.ClearData();
    oldSession.WorkChannel.Close();
    Remove(oldSession.SessionId);
}
```

Source: [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L216-L240)

## 常见变体

| 场景 | 做法 |
|------|------|
| 同一玩家在同一设备重复登录 | `Session.Sign` 相同,直接走 `UpdateSession` 替换绑定,不踢旧连接 |
| 同一玩家在不同设备登录 | `Sign` 不同,旧会话被关闭并收到 `Type=5` 提示消息 |
| 通过 HTTP 登录 | 由 [ReqLoginHttpHandler](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/Logic/Http/Player/ReqLoginHttpHandler.cs) 处理账号 Token,业务侧拿到 `roleId` 后再走客户端 `ReqPlayerLogin` 完成绑定 |
| GM 强制踢人 | 调用 `SessionManager.KickOffLineByUserId(roleId)`,会自动派发 `SessionRemove` 事件 |

## 常见错误

- **忘记调用 `UpdateSession`**:登录校验通过但未绑定 `roleId`,后续按 `PlayerId` 查不到会话,所有玩家逻辑全部失效。
- **没有监听 `SessionRemove`**:玩家断线后没有清理内存对象,资源泄漏且重连后会拿到陈旧数据。
- **顶号文案未做本地化**:使用硬编码字符串,直接绕过 `LocalizationService.GetString`,会导致多语言环境提示不正确。
- **手动 `Remove` 会话后又手动 `Close`**:框架在 `UpdateSession` 内部已经处理了旧连接的关闭,业务侧再调用一次会重复触发 `SessionRemove`。

## 背景(可选)

- `Session` 是连接级对象,内部持有 `INetWorkChannel`,通过 `SetData(GlobalConst.SessionIdKey, ...)` 与网络通道互绑。
- `SessionManager` 使用 `ConcurrentDictionary<string, Session>` 存储会话,并维护 `PlayerRouteMap` 用于跨服路由;顶号时通过先 `Remove` 再等待 `Disconnected` 回调来避免清理时延。
- 顶号提示消息 `Type=5` 由 `RespPrompt` 协议承载,文案来自 `Localization.Keys.Apps.SessionManager.AccountAlreadyLoggedIn`。
