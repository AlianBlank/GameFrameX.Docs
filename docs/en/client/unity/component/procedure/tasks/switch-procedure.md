# How to Switch Between Procedures

Switching procedures is done through `IProcedureManager.StartProcedure`. Anywhere in the game (inside procedure classes, external systems, UI button callbacks), as long as you have `ProcedureComponent.Procedure`, you can call it. This page provides the minimal runnable steps from obtaining the manager to completing a switch.

## Prerequisites

- Multiple procedure classes inherited from `ProcedureBase` have been created (such as `ProcedureLogin`, `ProcedureMain`).
- `ProcedureComponent` has been mounted in the scene, and the procedure type names have been filled in `Available Procedure Type Names` in the Inspector.
- The overall architecture is understood, see "Overview".

## Steps

### 1. Obtain the Procedure Manager

Get `IProcedureManager` through the `Procedure` property of `ProcedureComponent`:

```csharp
using GameFrameX.Procedure.Runtime;
using UnityEngine;

ProcedureComponent procedureComponent = GameFrameX.Runtime.GameFrameworkEntry.GetComponent<ProcedureComponent>();
IProcedureManager procedureManager = procedureComponent.Procedure;
```

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L70-L74)

### 2. Initiate a Switch in the Current Procedure's `OnUpdate`

The most common way to switch: detect that conditions are met during a procedure's polling and call `StartProcedure`. The manager will trigger the current procedure's `OnLeave` and the target procedure's `OnEnter`.

```csharp
using GameFrameX.Procedure.Runtime;

public class ProcedureLogin : ProcedureBase
{
    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);

        if (登录完成的条件满足)
        {
            procedureOwner.Owner.StartProcedure<ProcedureMain>();
        }
    }
}
```

The two overload definitions of `IProcedureManager.StartProcedure` are available at [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L64-L73). Under the hood, it invokes the state machine's state transition.

### 3. Switch in External Code

Switching does not have to happen inside a procedure. Anywhere in the game that holds an `IProcedureManager` reference can call:

```csharp
using GameFrameX.Procedure.Runtime;

procedureManager.StartProcedure(typeof(ProcedureMain));
// or the generic version
procedureManager.StartProcedure<ProcedureMain>();
```

Generic version source signature:

```csharp
public interface IProcedureManager
{
    void StartProcedure<T>() where T : ProcedureBase;
    void StartProcedure(Type procedureType);
}
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L60-L73)

### 4. Verify the Switch Succeeded

After switching, read `CurrentProcedure` and `CurrentProcedureTime` to confirm that the new procedure is in effect and the timer has been reset to 0. The approach in unit tests can serve as a reference:

```csharp
m_ProcedureManager.Initialize(m_FsmManager, new ProcedurePreload(), new ProcedureMain());
m_ProcedureManager.StartProcedure<ProcedurePreload>();

Assert.IsNotNull(m_ProcedureManager.CurrentProcedure);
Assert.IsInstanceOf<ProcedurePreload>(m_ProcedureManager.CurrentProcedure);
Assert.AreEqual(0f, m_ProcedureManager.CurrentProcedureTime);
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L153-L173)

## Common Variations

### Query Only, No Switch

Before switching, you can use `HasProcedure` to confirm that the target is registered, avoiding exceptions inside the state machine:

```csharp
if (procedureManager.HasProcedure<ProcedureMain>())
{
    procedureManager.StartProcedure<ProcedureMain>();
}
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L78-L89)

### Obtain the Registered Instance Without Switching

Sometimes you just want to read the current procedure instance for conditional checks, without switching:

```csharp
ProcedureBase main = procedureManager.GetProcedure<ProcedureMain>();
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L94-L105)

## Common Errors

- **Calling too early**: Calling any method before the procedure manager's `Initialize` will throw an exception. The unit tests `CurrentProcedure_BeforeInitialize_Throws` and `HasProcedure_BeforeInitialize_Throws` validate this, see [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L96-L128). Ensure `Initialize` is completed before `StartProcedure`.
- **Target procedure not registered**: `StartProcedure` requires the procedure to have been registered through `Initialize(..., params ProcedureBase[] procedures)` or `ReinitializeProcedures`. You can use `HasProcedure<T>()` to check in advance.
- **Switching inside `OnEnter` / `OnInit`**: Calling `StartProcedure` during the state machine initialization phase may conflict with its own lifecycle. It is recommended to place it in `OnUpdate` or use external driving.

## Background (Optional)

`ProcedureComponent` holds `m_ProcedureManager`. At startup, it reflects the procedure instances based on the `m_AvailableProcedureTypeNames` configured in the Inspector and calls `StartProcedure` in order. After that, `m_EntranceProcedure` becomes the initial procedure. During switching, the underlying state machine executes `OnLeave`/`OnEnter` transitions. When `m_UseStartupRunner = true`, the component itself no longer calls `Initialize`; instead, it is taken over by `ApplicationStartupEntry` + `StartupRunner.Run` to avoid duplicate `Initialize`.
