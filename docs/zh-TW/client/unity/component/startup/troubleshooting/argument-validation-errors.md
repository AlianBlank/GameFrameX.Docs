# 啟動同步參數驗證例外發生時的處理方法

呼叫 `StartupRunner.Run(...)` 時，若傳入的參數不符合要求（例如：`options` 為 null、`GlobalInfoUrls` 為空陣列等），系統不會在進入非同步狀態機前回傳失敗結果，而是**同步**擲回 `ArgumentNullException` 或 `ArgumentException`。這類例外屬於「開發階段設定錯誤」，因此應讓它在驗證階段立即顯現，以避免汙染後續的協程流程。

## 快速診斷

| 例外類型 | 代表訊息原文 | 發生位置 | 修正方向 |
|----------|--------------|----------|----------|
| `ArgumentNullException` | （無訊息，`ParamName`=`options`） | `StartupRunner.Run` 進入點 | 傳入有效的 `StartupOptions` 實例 |
| `ArgumentNullException` | （無訊息，`ParamName`=`uiHandler`） | `StartupRunner.Run` 進入點 | 實作 `IStartupUIHandler` 並傳入 |
| `ArgumentNullException` | （無訊息，`ParamName`=`hotfixLauncher`） | `StartupRunner.Run` 進入點 | 實作 `IHotfixLauncher` 並傳入 |
| `ArgumentException` | 訊息中包含 `"GlobalInfoUrls"` | `StartupRunner.Run` 進入點 | 在 `StartupOptions` 中輸入至少一個全域資訊介面 URL |
| `ArgumentNullException` | （無訊息，`ParamName`=`urls`） | `UrlFailoverRunner` 建構 | 確認 URL 陣列物件本身不為 null |
| `ArgumentException` | `"URL list must contain at least one URL."` | `UrlFailoverRunner` 建構 | URL 陣列包含至少一個元素 |
| `ArgumentException` | `"Max attempts per URL must be greater than zero."` | `UrlFailoverRunner` 建構 | 將 `maxAttemptsPerUrl` 變更為 `>= 1` |
| `ArgumentException` | `"Retry delay must be zero or greater."` | `UrlFailoverRunner` 建構 | 將 `retryDelayMs` 變更為 `>= 0` |
| `ArgumentNullException` | （無訊息，`ParamName`=`options`） | `StartupHttpParams.FromOptions` | 傳入非 null 的 `StartupOptions` |

例外訊息原文與參數名稱皆直接取自原始碼，詳情請參閱 [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L34-L60) 與 [Runtime/Failover/UrlFailoverRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L40)。

## 修正步驟

### 1. 修正 `ArgumentNullException`（options/uiHandler/hotfixLauncher）

`StartupRunner.Run` 在進入協程之前，會同步檢查三個輸入參數是否為 null：

```csharp
public static UniTask<StartupResult> Run(
    StartupOptions options,
    IStartupUIHandler uiHandler,
    IHotfixLauncher hotfixLauncher)
```

對應實作（[Runtime/Startup/StartupRunner.cs#L45-L60](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L45-L60)）：

```csharp
if (options == null)        throw new ArgumentNullException(nameof(options));
if (uiHandler == null)      throw new ArgumentNullException(nameof(uiHandler));
if (hotfixLauncher == null) throw new ArgumentNullException(nameof(hotfixLauncher));
```

修正方法：在呼叫進入點之前逐項檢查，或確認已透過 Inspector / DI 容器注入非 null 的實例。例如：

```csharp
if (StartupOptions.Instance == null)
{
    Debug.LogError("StartupOptions 尚未設定");
    return;
}
if (uiHandler == null || hotfixLauncher == null)
{
    Debug.LogError("尚未註冊 UI/Hotfix 啟動器");
    return;
}
await StartupRunner.Run(StartupOptions.Instance, uiHandler, hotfixLauncher);
```

### 2. 修正 `ArgumentException`（`GlobalInfoUrls` 為空）

通過三項 null 檢查後，`Run` 還會驗證 `options.GlobalInfoUrls`（對應實作請參閱 [Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L37-L60)）。若此欄位為 null 或長度為 0，將同步擲回訊息中包含 `"GlobalInfoUrls"` 的 `ArgumentException`。

修正方法：在 Unity 中透過 `Create > GameFrameX > Startup Options` 建立資產後，於 Inspector 的 `GlobalInfoUrls` 欄位輸入至少一個可存取的全域資訊介面位址（預設/備援 URL 以陣列元素區分）。

### 3. 修正 `UrlFailoverRunner` 擲回的驗證例外

`UrlFailoverRunner` 在建構時會對 URL 清單與重試參數執行完整驗證（[Runtime/Failover/UrlFailoverRunner.cs#L19-L34](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L19-L34)）：

```csharp
if (urls == null)
    throw new ArgumentNullException(nameof(urls));
if (urls.Length == 0)
    throw new ArgumentException("URL list must contain at least one URL.", nameof(urls));
if (maxAttemptsPerUrl <= 0)
    throw new ArgumentException("Max attempts per URL must be greater than zero.", nameof(maxAttemptsPerUrl));
if (retryDelayMs < 0)
    throw new ArgumentException("Retry delay must be zero or greater.", nameof(retryDelayMs));
```

修正方法：

- 確保傳遞給 `UrlFailoverRunner` 建構函式的陣列參考不為 null，且至少包含一個 URL。
- `maxAttemptsPerUrl` 必須 ≥ 1。
- `retryDelayMs` 必須 ≥ 0（0 表示無重試延遲，為有效值）。

### 4. 修正 `StartupHttpParams.FromOptions` 擲回的 null 例外

`FromOptions` 會在 `options` 為 null 時擲回 `ArgumentNullException`（[Runtime/Http/StartupHttpParams.cs#L94-L99](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Http/StartupHttpParams.cs#L94-L99)）。若已覆寫 `IStartupHttpParamsProvider`，請在呼叫 `FromOptions` 之前自行檢查其是否為 null。

## 驗證

- 以 `try/catch (ArgumentException)` / `try/catch (ArgumentNullException)` 包裹 `StartupRunner.Run` 的呼叫處以擷取例外，並確認例外類型與 `ParamName`/`Message` 是否與上表一致。
- 修改 `StartupOptions` 資產後，於 Editor 中重新進入 PlayMode，啟動流程應能正常進入 `ProcedureGetAppVersionInfoState` 等後續節點，且不再於第一幀同步擲回例外。
- 若直接建立並使用 `UrlFailoverRunner`，請在單元測試中傳入空陣列、負數重試參數等邊界值，確認上表的例外訊息可重現後再進行修正。

## 背景（選讀）

`StartupRunner.Run` 將同步驗證與非同步流程分離。所有「明顯撰寫錯誤」的輸入參數都會在驗證階段同步擲回，使無效狀態無法進入 `UniTask` 狀態機。實際上，只有網路、補丁、遠端服務中發生的問題，才會透過 `StartupResult` / `StartupFailedEventArgs` 以非同步方式回報。此慣例亦明確記錄於 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/CHANGELOG.md#L103)：「Synchronous validation throws `ArgumentException` for empty `GlobalInfoUrls` before entering async state machine.」
