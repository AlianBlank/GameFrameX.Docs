# 资源加载不到、加载为空或路径错误怎么办

当 `AssetComponent.LoadAssetAsync`、`LoadAssetSync`、各类型的扩展方法(如 `LoadPrefabAsync`/`LoadAudioAsync`)以及 `AssetManager` 中的接口返回的 `AssetHandle` 拿不到有效对象时，按本页步骤定位问题。

## 快速诊断

| 症状 | 可能原因 | 修复 |
|------|----------|------|
| `AssetHandle.AssetObject` 为 `null` 或 `GetAssetObject<T>()` 返回 `null` | 资源路径错误 / 资源未打包 / 未初始化资源包 | 见「资源包未初始化」「路径错误」修复步骤 |
| 报 `Asset manager is invalid.` 致命日志 | `_assetManager` 未获取到（模块缺失或类型未注册） | 见「资源管理器未就绪」 |
| WebGL 平台加载失败 | `EPlayMode` 未切换为 `WebPlayMode` | 见「运行模式不匹配」 |
| 编辑器下能加载，发布后加载失败 | 运行模式不匹配（如仍为 `EditorSimulateMode`） | 见「运行模式不匹配」 |
| 异步加载完成回调里 `handle.Status` 不等于 `Succeed` | 资源不存在 / 类型不匹配 / 网络下载失败 | 见「路径错误」「类型不匹配」 |
| 返回了对象但是空材质/丢失贴图 | 资源依赖未打进包，或子资源未用 `LoadSubAssetsAsync` | 见「依赖与子资源」 |

## 修复步骤

### 资源包未初始化

`AssetComponent.Awake` 仅设置运行模式，真正初始化由 `Start` 调用 `_assetManager.Initialize()`；而具体资源包需要显式调用 `InitPackageAsync` 才会进入可用状态。未初始化的包加载资源会拿到空句柄。

```csharp
// 资源组件首次启动时，对每个要使用的资源包执行一次初始化
bool ok = await GameEntry.GetComponent<AssetComponent>()
    .InitPackageAsync("DefaultPackage", hostServer, fallbackHostServer, isDefaultPackage: true);
if (!ok)
{
    // 初始化失败，检查 host/fallbackHostServer 配置是否正确
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L100-L120)

### 路径错误

路径必须使用 YooAssets 收集阶段记录的定位地址（一般是 `assets/...` 全小写），并且要带上文件后缀。扩展方法如 `LoadPrefabAsync` 内部其实调用的是 `LoadAssetAsync<GameObject>(path)`，路径写错就拿不到 GameObject。

```csharp
// 正确：使用打包时收集到的资源定位地址
var handle = await assetComponent.LoadPrefabAsync("assets/game/prefabs/player.prefab");
var go = handle.GetAssetObject<GameObject>();

// 错误：写成了 Unity 资产路径 / 漏后缀 / 大小写不一致
var bad = await assetComponent.LoadPrefabAsync("Assets/Prefabs/Player"); // ❌
```

Source: [AssetComponent.Prefab.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Prefab.cs#L26-L29)

### 运行模式不匹配

`AssetComponent.Awake` 里在非编辑器以及 WebGL 下会强制覆盖 `GamePlayMode`，把 `EditorSimulateMode` 改为 `HostPlayMode`，WebGL 一律 `WebPlayMode`。编辑器里能看到资源、发布后拿不到，99% 是模式没切对。

```csharp
// Inspector 或代码里显式指定运行模式
assetComponent.GamePlayMode = EPlayMode.HostPlayMode;
// WebGL 平台无需手动设置，Awake 会强制设置为 WebPlayMode
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L62-L85)

### 类型不匹配

泛型版本 `LoadAssetAsync<T>` 会按 `T` 类型过滤资源；如果实际资源是 `Texture2D`，却用 `LoadAssetAsync<Sprite>(path)`，会拿到空对象。可改用非泛型重载拿到原始对象后用 `GetAssetObject<T>()` 取出正确类型。

```csharp
// 通过非泛型接口拿到 AssetInfo 后加载，避免类型猜错
var assetInfo = YooAssets.GetAssetInfo("assets/ui/icon.png");
var handle = assetComponent.LoadAssetAsync(assetInfo);
var sprite = handle.GetAssetObject<Sprite>();
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L357-L361)

### 资源管理器未就绪

`AssetComponent.Awake` 中如果 `GameFrameworkEntry.GetModule<IAssetManager>()` 返回 `null`，会写致命日志 `Asset manager is invalid.` 并直接 return。这种情况下后续 `LoadAssetAsync` 都会拿到无效句柄——通常是 `AssetComponent` 的 `componentType` 没解析出对应的实现类。

```csharp
// Awake 内的判定
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L83)

### 依赖与子资源

SpriteAtlas、图集里的子图、Material 引用的贴图都属于依赖或子资源。主资源加载出来后再去取依赖对象是取不到的。需要：

- 主资源 + 依赖一起加载：用 `LoadSubAssetsAsync<T>(path)` 或把依赖打成同一包由 YooAssets 自动收集。
- 取图集子图：用 `LoadSubAssetsAsync<Sprite>(atlasPath)`，再从 `SubAssetsHandle` 中按名字取。

```csharp
var subHandle = await assetComponent.LoadSubAssetsAsync<Sprite>("assets/ui/atlas/mainAtlas.png");
foreach (var sprite in subHandle.AllAssetObjects)
{
    // 每个 sub asset 都是 Sprite
}
```

## 验证

按以下顺序验证问题是否解决：

1. 在 `LoadAssetAsync` 返回的 `AssetHandle.AssetObject` 上打印类型和名字，确认是否为预期对象。
2. 检查 `handle.Status` 是否为 `Succeed`；如果不是，`handle.LastError` 会给出 YooAssets 的错误原文。
3. 确认 `AssetComponent.GamePlayMode` 在目标平台上的值（编辑器下模拟模式、WebGL 下应为 `WebPlayMode`）。
4. 在 YooAssets 资源收集器(AssetBundle Collector)里搜索该路径，确认它属于已初始化的资源包并已构建到当前版本。
