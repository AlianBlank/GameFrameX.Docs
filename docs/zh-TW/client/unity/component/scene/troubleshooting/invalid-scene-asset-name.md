# 場景資源名稱無效時的處理方式

呼叫 `LoadScene(string sceneAssetName, ...)` 時，若傳入的資源名稱（路徑）在 YooAsset 清單中找不到，場景載入將直接失敗。常見症狀包括 `LoadSceneFailure` 事件被觸發、`await` 回傳的 `Task` 擲出例外狀況，或編輯器日誌輸出「资源不存在 / asset not found」。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| `LoadSceneFailure` 事件被觸發，`SceneAssetName` 即為您傳入的字串 | YooAsset 清單中不包含此 `sceneAssetName` | 使用正確的「資源名稱 / 資源路徑」重試，並確認其已註冊於建置輸出中 |
| 錯誤回報 `sceneAssetName` 為空或 null | 呼叫前路徑未正確串接，或從設定表讀取到空字串 | 呼叫前先進行 null/空值驗證，並使用設定表中完整的 `Assets/...` 路徑 |
| 非同步 `Task` 擲出 `OperationCanceledException` 或永不回傳 | 相同的資源名稱已存在於 `m_LoadingSceneAssetNames` 中，重複載入被忽略 | 先呼叫 `UnloadScene` 或等待前一個載入完成，避免同時重複載入 |
| 在編輯器中正常運作，但建置後找不到場景 | 場景未被打包進 YooAsset Bundle，或 Bundle 名稱與載入路徑不符 | 將場景檔案加入 YooAsset 收集器並重新建置 Bundle |

## 修復步驟

### 1. 驗證資源名稱非空且與清單相符

`LoadScene` 內部以 `sceneAssetName` 作為 YooAsset 場景查詢的索引鍵，因此該字串必須與 YooAsset 收集器所產生的資源路徑完全一致（通常為 `Assets/Scenes/xxx.unity`）。

```csharp
// 建議：呼叫前先驗證
if (string.IsNullOrWhiteSpace(sceneAssetName))
{
    GameFrameworkLog.Error("[Scene] sceneAssetName cannot be empty");
    return;
}
var handle = await GameEntry.Scene.LoadScene(sceneAssetName,
    UnityEngine.SceneManagement.LoadSceneMode.Single);
```

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L337-L348) 提供了四個 `LoadScene` 多載，簽章分別為 `(string)`、`(string, LoadSceneMode)`、`(string, object)` 與 `(string, LoadSceneMode, object)`。所有多載皆需要有效的 `sceneAssetName`。

### 2. 監聽失敗事件以識別實際的資源名稱

訂閱 `LoadSceneFailure` 事件，即可從事件參數中取得執行階段實際嘗試載入的 `SceneAssetName`：

```csharp
GameEntry.Scene.LoadSceneFailure += (sender, e) =>
{
    Debug.LogError($"Scene load failed: {e.SceneAssetName}, Error: {e.ErrorMessage}");
};
```

事件來源位於 [LoadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/LoadSceneFailureEventArgs.cs)。請將日誌中列印的 `SceneAssetName` 與 YooAsset 清單（`AssetBundle` / `AssetPackage` 清單）進行比對——這通常能立即找出拼字或大小寫錯誤。

### 3. 確認 YooAsset 已收集並建置該場景

場景要能夠載入，必須滿足兩個條件：

1. `.unity` 檔案已包含於 YooAsset 收集器規則中；
2. YooAsset 建置流程（build/本機建置）已重新執行，且在 Run Mode 中使用最新的 Bundle 輸出。

如果只在 Unity 編輯器中正常運作，建置後卻失敗，問題幾乎都出在這一步。

### 4. 避免以相同資源名稱同時載入

`GameSceneManager` 內部使用 `m_LoadingSceneAssetNames` 追蹤正在載入中的資源。以相同 `sceneAssetName` 重複呼叫 `LoadScene` 不會取得新的 `Task`，看起來就像是「無效」。解決方式是讓每個載入邏輯獨佔使用一個資源名稱，或等待前一個 `LoadScene` 回傳的 `Task` 完成後，再發起下一次載入。

[GameSceneManager.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/Scene/GameSceneManager.cs#L371) 中的完整實作位於四參數多載內，您可以看到它會將 `SceneHandle` 與 `UserData` 儲存於 `m_LoadingSceneAssetNames`，並僅在成功或失敗回呼時才將其移除。

## 驗證

與一個可正常載入的場景進行對照測試：

1. 以已知存在的場景（例如 `Assets/Scenes/Init.unity`）呼叫 `LoadScene`，並確認 `LoadSceneSuccess` 事件被觸發；
2. 故意將 `sceneAssetName` 改為不存在的字串，確認 `LoadSceneFailure` 被觸發且日誌輸出實際嘗試的資源名稱；
3. 將不存在的字串改回正確路徑，再次呼叫 `LoadScene`，並確認成功。

若步驟 1 與步驟 3 皆成功，且中間步驟的失敗事件也如預期被觸發，即表示「場景資源名稱無效」的問題已被確認為字串/路徑問題，而非框架 API 的呼叫方式問題。
