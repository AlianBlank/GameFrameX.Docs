# 設定 Info.plist 權限與 URL Schemes

在 Xcode 建置設定(JSON)頂層的 `plist` 欄位中加入鍵值對，建置後 `PostProcessBuildHelper` 會自動將它們寫入產生的 `Info.plist`,權限描述文案、URL Schemes、scheme 白名單等都透過這一處設定完成，無需手動修改 Xcode 專案。

## 前置條件

- Unity 專案已安裝 `com.gameframex.unity.xcode` 套件。
- 使用 iOS 平台建置(Xcode 相關程式碼在 `#if UNITY_IOS` 下編譯)。
- 已有一份 Xcode 建置設定檔，其中包含頂層 `plist` 物件(為空也可)：

```json
"plist": {},
```

Source: [README.ja.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.ja.md#L84-L86)

## 操作步驟

1. 開啟 Xcode 建置設定檔，定位到頂層 `plist` 欄位(沒有就新增一個空物件)。
2. 加入權限描述等字串鍵值，例如相機、相簿的使用說明。
3. 如需第三方登入/喚起回呼，加入 `CFBundleURLTypes` 註冊 URL Schemes。
4. 如需偵測其他 App 是否安裝(iOS 9+ 強制要求)，加入 `LSApplicationQueriesSchemes` 白名單。
5. 執行 iOS 建置。控制台出現 `设置项目[Info.plist]开始` 與 `设置项目[Info.plist]结束` 日誌即表示寫入成功：

```csharp
LogHelper.Log("设置项目[Info.plist]开始");
//plist
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
SetPlist(project, plist.root, hashtable);
//寫入
plist.WriteToFile(plistPath);
LogHelper.Log("设置项目[Info.plist]结束");
```

Source: [Editor/PostProcessBuildHelper.Plist.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Plist.cs#L11-L22)

6. 開啟產生的 Xcode 專案，在 Target → Info 頁籤確認對應鍵已出現。

以下是一份可直接複製的 `plist` 設定範例(鍵名為 iOS 標準 Info.plist 鍵，值類型由框架支援的類型決定，見下文「背景」中的對應表)：

```json
"plist": {
    "NSCameraUsageDescription": "扫描二维码需要使用相机",
    "NSPhotoLibraryUsageDescription": "保存截图需要访问相册",
    "LSApplicationQueriesSchemes": [
        "weixin",
        "weixinULAPI"
    ],
    "CFBundleURLTypes": [
        {
            "CFBundleURLName": "com.yourcompany.yourgame",
            "CFBundleURLSchemes": ["yourgame"]
        }
    ]
}
```

設定中 `plist` 的取值在建置時透過 `finalConfig.Get<Hashtable>("plist")` 讀出並傳入處理流程：

```csharp
// 設定Info.Plist
RunPlist(project, path, finalConfig.Get<Hashtable>("plist"));
```

## 常見變體

- **多組 URL Schemes**:在 `CFBundleURLTypes` 陣列中追加多個字典物件即可，每個物件含 `CFBundleURLName` 與 `CFBundleURLSchemes`。
- **背景模式**：同樣寫在 `plist` 下，例如 `"UIBackgroundModes": ["audio"]`(字串陣列)。
- **在地化權限文案**：改用框架的在地化設定，自動產生 `.lproj/InfoPlist.strings` 並將 `LSHasLocalizedDisplayName` 設為 `true`,不要把多語言文案硬編碼在 `plist` 鍵值裡：

```csharp
plistPath = Path.Combine(path, "Info.plist");
if (File.Exists(plistPath))
{
    ...
    plist.WriteToFile(plistPath);
    LogHelper.Log("Updated Info.plist: Set LSHasLocalizedDisplayName to true");
}
```

## 常見錯誤

- **數字只會寫成整數**：寫入邏輯對數字類型統一執行 `SetInteger(key, Convert.ToInt32(...))`,小數會被截斷，不要用它寫浮點值。
- **布林值寫成字串**：只有真正的 JSON 布林(`true`/`false`)才會呼叫 `SetBoolean`;寫成 `"YES"` / `"true"` 會按字串寫入，Info.plist 中類型錯誤。
- **鍵名拼寫錯誤無提示**：處理是「有什麼寫什麼」的逐項覆蓋，拼錯的鍵(如 `NSCameraUsageDesciption`)不會報錯，只能到 Xcode 的 Info 頁籤人工核對。
- **巢狀結構層級不對**:`CFBundleURLTypes` 必須是「陣列 → 字典 → 陣列」的巢狀，少一層會導致 Xcode 中顯示為普通字串而非 URL Types。

## 背景

`SetPlist` 按設定值的執行時類型遞迴寫入，對應關係如下(陣列元素同樣適用)：

| 設定值類型 | Info.plist 寫入類型 | 呼叫 |
|------|------|------|
| 字串 | string | `SetString` |
| 布林 | boolean | `SetBoolean` |
| 數字(double) | integer | `SetInteger`(`Convert.ToInt32`) |
| 陣列(ArrayList) | array | `CreateArray` / `AddArray` |
| 物件(Hashtable) | dict | `CreateDict` / `AddDict` |

```csharp
if (vType == typeof(string))
{
    node.SetString(key, (string)val);
}
else if (vType == typeof(bool))
{
    node.SetBoolean(key, (bool)val);
}
else if (vType == typeof(double))
{
    node.SetInteger(key, Convert.ToInt32((double)val));
}
else if (vType == typeof(ArrayList))
{
    var t = node.CreateArray(key);
    var array = val as ArrayList;
    SetPlist(proj, t, array);
}
else if (vType == typeof(Hashtable))
{
    var t = node.CreateDict(key);
    var table = val as Hashtable;
    SetPlist(proj, t, table);
}
```
