# 配置 Info.plist 权限与 URL Schemes

在 Xcode 构建配置(JSON)顶层的 `plist` 字段中添加键值对,构建后 `PostProcessBuildHelper` 会自动把它们写入生成的 `Info.plist`,权限描述文案、URL Schemes、scheme 白名单等都通过这一处配置完成,无需手工改 Xcode 工程。

## 前置条件

- Unity 项目已安装 `com.gameframex.unity.xcode` 包。
- 使用 iOS 平台构建(Xcode 相关代码在 `#if UNITY_IOS` 下编译)。
- 已有一份 Xcode 构建配置文件,其中包含顶层 `plist` 对象(为空也可):

```json
"plist": {},
```

Source: [README.ja.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.ja.md#L84-L86)

## 操作步骤

1. 打开 Xcode 构建配置文件,定位到顶层 `plist` 字段(没有就新建一个空对象)。
2. 添加权限描述等字符串键值,例如相机、相册的使用说明。
3. 如需第三方登录/唤起回调,添加 `CFBundleURLTypes` 注册 URL Schemes。
4. 如需检测其他 App 是否安装(iOS 9+ 强制要求),添加 `LSApplicationQueriesSchemes` 白名单。
5. 执行 iOS 构建。控制台出现 `设置项目[Info.plist]开始` 与 `设置项目[Info.plist]结束` 日志即表示写入成功:

```csharp
LogHelper.Log("设置项目[Info.plist]开始");
//plist
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
SetPlist(project, plist.root, hashtable);
//写入
plist.WriteToFile(plistPath);
LogHelper.Log("设置项目[Info.plist]结束");
```

Source: [Editor/PostProcessBuildHelper.Plist.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Plist.cs#L11-L22)

6. 打开生成的 Xcode 工程,在 Target → Info 页签确认对应键已出现。

下面是一份可直接复制的 `plist` 配置示例(键名为 iOS 标准 Info.plist 键,值类型由框架支持的类型决定,见下文"背景"中的映射表):

```json
"plist": {
    "NSCameraUsageDescription": "扫描二维码需要使用相机",
    "NSPhotoLibraryUsageDescription": "保存截图需要访问相册",
    "LSApplicationQueriesSchemes": [
        "weixin",
        "weixinULAPI"
    ],
    "CFBundleURLTypes": [
        {
            "CFBundleURLName": "com.yourcompany.yourgame",
            "CFBundleURLSchemes": ["yourgame"]
        }
    ]
}
```

配置中 `plist` 的取值在构建时通过 `finalConfig.Get<Hashtable>("plist")` 读出并传入处理流程:

```csharp
// 设置Info.Plist
RunPlist(project, path, finalConfig.Get<Hashtable>("plist"));
```

## 常见变体

- **多套 URL Schemes**:在 `CFBundleURLTypes` 数组中追加多个字典对象即可,每个对象含 `CFBundleURLName` 与 `CFBundleURLSchemes`。
- **后台模式**:同样写在 `plist` 下,例如 `"UIBackgroundModes": ["audio"]`(字符串数组)。
- **本地化权限文案**:改用框架的本地化配置,自动生成 `.lproj/InfoPlist.strings` 并把 `LSHasLocalizedDisplayName` 置为 `true`,不要把多语言文案硬编码在 `plist` 键值里:

```csharp
plistPath = Path.Combine(path, "Info.plist");
if (File.Exists(plistPath))
{
    ...
    plist.WriteToFile(plistPath);
    LogHelper.Log("Updated Info.plist: Set LSHasLocalizedDisplayName to true");
}
```

## 常见错误

- **数字只会写成整数**:写入逻辑对数字类型统一执行 `SetInteger(key, Convert.ToInt32(...))`,小数会被截断,不要用它写浮点值。
- **布尔值写成字符串**:只有真正的 JSON 布尔(`true`/`false`)才会调用 `SetBoolean`;写成 `"YES"` / `"true"` 会按字符串写入,Info.plist 中类型错误。
- **键名拼写错误无提示**:处理是"有什么写什么"的逐项覆盖,拼错的键(如 `NSCameraUsageDesciption`)不会报错,只能到 Xcode 的 Info 页签人工核对。
- **嵌套结构层级不对**:`CFBundleURLTypes` 必须是"数组 → 字典 → 数组"的嵌套,少一层会导致 Xcode 中显示为普通字符串而非 URL Types。

## 背景

`SetPlist` 按配置值的运行时类型递归写入,映射关系如下(数组元素同样适用):

| 配置值类型 | Info.plist 写入类型 | 调用 |
|------|------|------|
| 字符串 | string | `SetString` |
| 布尔 | boolean | `SetBoolean` |
| 数字(double) | integer | `SetInteger`(`Convert.ToInt32`) |
| 数组(ArrayList) | array | `CreateArray` / `AddArray` |
| 对象(Hashtable) | dict | `CreateDict` / `AddDict` |

```csharp
if (vType == typeof(string))
{
    node.SetString(key, (string)val);
}
else if (vType == typeof(bool))
{
    node.SetBoolean(key, (bool)val);
}
else if (vType == typeof(double))
{
    node.SetInteger(key, Convert.ToInt32((double)val));
}
else if (vType == typeof(ArrayList))
{
    var t = node.CreateArray(key);
    var array = val as ArrayList;
    SetPlist(proj, t, array);
}
else if (vType == typeof(Hashtable))
{
    var t = node.CreateDict(key);
    var table = val as Hashtable;
    SetPlist(proj, t, table);
}
```
