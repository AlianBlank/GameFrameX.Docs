# 常见问题

本文档汇总了使用 GameFrameX Setting 配置コンポーネント时可能遇到的常见问题、错误信息及其解決策。

## 概要

GameFrameX Setting 配置コンポーネント是ゲームフレームワーク的コアコンポーネント，负责管理ゲーム的配置信息。在使用过程中，開発者可能遇到初期化失败、数据无法保存、平台兼容性等问题。本文档提供详细的问题诊断和解決策，帮助開発者快速定位和解决问题。

## 初期化问题

### 问题 1：Setting manager is invalid

**错误信息：**
```
Log.Fatal("Setting manager is invalid.");
```

**原因分析：**
此错误表示 `SettingComponent` 在 `Awake()` 阶段无法从 `GameFrameworkEntry` 取得 `ISettingManager` 模块。这通常是因为 GameFramework コアコンポーネント未正确初期化。

**解決策：**

1. 确保シーン中存在 GameFrameX コアエントリーポイントコンポーネント
2. 检查 `GameFrameworkEntry` 是否已正确初期化
3. 确保 SettingComponent 挂载在正确的 GameObject 上

```csharp
// 正确的初期化顺序
// 1. 先初期化 GameFrameworkEntry
GameFrameworkEntry.Initialize();

// 2. 然后 SettingComponent 会自动を通じて Awake 取得管理器
var settingComponent = gameObject.AddComponent<SettingComponent>();
```

### 问题 2：Can not create setting helper

**错误信息：**
```
Log.Error("Can not create setting helper.");
```

**原因分析：**
此错误表示无法に基づいて配置的クラス型名称作成設定辅助器インスタンス。可能原因：
- 配置的 Helper クラス型名称不正确
- 指定的 Helper クラス不存在或未正确引用
- Helper クラス型没有无参构造函数

**解決策：**

1. 检查 `SettingComponent` Inspector 面板上的 `Setting Helper Type Name` 配置
2. 确保クラス型名称完整且正确（包括名前空間）

```csharp
// 默认配置
// Setting Helper Type Name: GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper
// 或
// Setting Helper Type Name: GameFrameX.Setting.Runtime.DefaultSettingHelper
```

3. 可用的 Helper クラス型：
   - `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` - 基づく Unity PlayerPrefs
   - `GameFrameX.Setting.Runtime.DefaultSettingHelper` - 基づく本地ファイル存储

### 问题 3：缺少必須的依赖コンポーネント

**错误信息：**
Unity 运行时错误或コンポーネント无法正常工作

**原因分析：**
`SettingComponent` 使用了 `[RequireComponent(typeof(GameFrameXSettingCroppingHelper))]`，必須配合 `GameFrameXSettingCroppingHelper` コンポーネント使用。

**解決策：**

1. SettingComponent 会自动添加 GameFrameXSettingCroppingHelper 依赖コンポーネント
2. 如果出现依赖问题，手动添加 GameFrameXSettingCroppingHelper 到同一 GameObject

## 数据操作问题

### 问题 4：Load settings failure

**错误信息：**
```
Log.Error("Load settings failure.");
```

**原因分析：**
加载設定失败，可能原因：
- 配置ファイル损坏
- 存储介质不可用
- ファイル路径不存在
- 序列化/反序列化错误

**解決策：**

1. **对于 DefaultSettingHelper：**
```csharp
// 检查ファイル是否存在
var helper = settingComponent.GetComponent<DefaultSettingHelper>();
string filePath = helper.FilePath;
Debug.Log($"Settings file path: {filePath}");
```

2. **異常处理：**
```csharp
try
{
    settingComponent.Save();
}
catch (Exception ex)
{
    Debug.LogError($"Save failed: {ex.Message}");
}
```

3. **检查ファイル权限：**
   - 确保 Application.persistentDataPath 可写
   - 检查磁盘空间是否充足

### 问题 5：設定值未正确保存

**问题説明：**
呼び出し `Save()` メソッド后，設定值在重新加载时丢失

**可能原因：**

1. **未呼び出し Save()**：設定值只在内存中修改，未持久化
2. **PlayerPrefs 未同步**：在某些平台上 PlayerPrefs.Save() 必要手动呼び出し
3. **WebGL 平台限制**：小程序平台有特殊的存储机制

**解決策：**

```csharp
// 1. 修改設定后必須呼び出し Save()
settingComponent.SetString("PlayerName", "NewName");
settingComponent.Save();  // 必須呼び出し

// 2. 使用 DefaultSettingHelper 确保数据持久化
// 其会自动保存到 Application.persistentDataPath/GameFrameworkSetting.dat
```

### 问题 6：GetAllSettingNames 返回 null 或不サポート

**错误信息：**
```
Log.Warning("GetAllSettingNames is not supported.");
```

**原因分析：**
`PlayerPrefsSettingHelper` 不サポート取得所有設定项名称的機能，因为 Unity PlayerPrefs 本身不提供枚举所有键的 API。

> Source: [PlayerPrefsSettingHelper.cs#L96-L100](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L96-L100)

**解決策：**

1. **使用 DefaultSettingHelper 替代**：该 Helper サポート完整的枚举機能

```csharp
// 在 SettingComponent Inspector 中将 Helper クラス型改为：
// GameFrameX.Setting.Runtime.DefaultSettingHelper
```

2. **自行维护設定键列表**：如果必須使用 PlayerPrefs，必要自行记录所有設定的键名

### 问题 7：Count プロパティ返回 -1

**问题説明：**
呼び出し `settingComponent.Count` 返回 -1

**原因分析：**
`PlayerPrefsSettingHelper` 的 Count プロパティ始终返回 -1，因为 Unity PlayerPrefs 不提供取得設定项数量的インターフェース。

> Source: [PlayerPrefsSettingHelper.cs#L52-L55](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L52-L55)

```csharp
public override int Count
{
    get { return -1; }  // PlayerPrefs 不サポート取得数量
}
```

**解決策：**

1. 使用 `DefaultSettingHelper` 可能取得准确的設定项数量
2. 或者自行维护计数变量

## 平台兼容性问题

### 问题 8：WebGL 小程序平台存储问题

**问题説明：**
在抖音、微信、快手等小程序平台上，設定无法正常保存或读取

**原因分析：**
小程序平台有各自的存储 API，不サポート Unity 原生 PlayerPrefs。フレームワーク针对这些平台做了适配：

> Source: [PlayerPrefsSettingHelper.cs#L80-L86](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L80-L86)

```csharp
public override bool Save()
{
#if UNITY_WEBGL && (ENABLE_DOUYIN_MINI_GAME || ENABLE_WECHAT_MINI_GAME || ENABLE_KUAISHOU_MINI_GAME)
    return true;  // 小程序平台无需手动保存
#else
    UnityEngine.PlayerPrefs.Save();
    return true;
#endif
}
```

**解決策：**

1. 确保定义了正确的平台宏：
   - `ENABLE_DOUYIN_MINI_GAME` - 抖音小程序
   - `ENABLE_WECHAT_MINI_GAME` - 微信小程序
   - `ENABLE_KUAISHOU_MINI_GAME` - 快手小程序

2. 在 Unity Build Settings 中正确配置发布平台

### 问题 9：对象序列化失败

**问题説明：**
使用 `SetObject()` 或 `GetObject()` 时，对象数据无法正确保存或读取

**可能原因：**

1. 对象クラス型不サポート JSON 序列化
2. 对象包含不可序列化的成员（如 delegate、EventHandler）
3. 循环引用导致序列化失败

**解決策：**

1. 确保对象クラス标记为 `[Serializable]`
2. 使用可序列化的数据结构
3. 处理循环引用

```csharp
[Serializable]
public class PlayerData
{
    public string Name;
    public int Level;
    public List<Item> Items;
}

[Serializable]
public class Item
{
    public int Id;
    public int Count;
}

// 使用示例
var playerData = new PlayerData
{
    Name = "Player1",
    Level = 10,
    Items = new List<Item>()
};

settingComponent.SetObject("PlayerData", playerData);
settingComponent.Save();

// 读取数据
var loadedData = settingComponent.GetObject<PlayerData>("PlayerData");
```

## API 使用问题

### 问题 10：Setting name is invalid

**错误信息：**
抛出 `GameFrameworkException("Setting name is invalid.")`

**原因分析：**
所有設定 API 都会检查設定名称是否为空。如果传入 null 或空字符串，将抛出異常。

> Source: [SettingManager.cs#L215-L218](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L215-L218)

```csharp
if (string.IsNullOrEmpty(settingName))
{
    throw new GameFrameworkException("Setting name is invalid.");
}
```

**解決策：**

```csharp
// 错误用法
settingComponent.SetBool("", true);  // 抛出異常

// 正确用法
settingComponent.SetBool("IsFullScreen", true);
```

### 问题 11：空值返回问题

**问题説明：**
使用无默认值的メソッド取得不存在的設定时，返回意外的值

**原因分析：**
不同的数据クラス型在没有默认值参数时的默认返回值不同：

| 数据クラス型 | 无默认值メソッド返回值 |
|----------|-------------------|
| bool | false |
| int | 0 |
| float | 0f |
| string | null |

**解決策：**

1. **始终使用带默认值的メソッド**：
```csharp
// 不推荐
bool isFullScreen = settingComponent.GetBool("IsFullScreen");

// 推荐
bool isFullScreen = settingComponent.GetBool("IsFullScreen", false);
```

2. **先检查設定是否存在**：
```csharp
if (settingComponent.HasSetting("PlayerName"))
{
    string name = settingComponent.GetString("PlayerName");
}
else
{
    // 处理不存在的情况
}
```

## 调试技巧

### 调试日志

启用详细日志来诊断问题：

```csharp
// 在代码中添加调试信息
Debug.Log($"Settings Count: {settingComponent.Count}");
Debug.Log($"Has PlayerName: {settingComponent.HasSetting("PlayerName")}");

// 取得所有設定名称（仅 DefaultSettingHelper サポート）
string[] allNames = settingComponent.GetAllSettingNames();
foreach (var name in allNames)
{
    Debug.Log($"Setting: {name}");
}
```

### 检查 Helper 配置

```csharp
// 取得当前使用的 Helper 信息
var helper = settingComponent.GetComponent<SettingHelperBase>();
Debug.Log($"Helper Type: {helper.GetType().Name}");
Debug.Log($"Helper FilePath: {(helper is DefaultSettingHelper dh ? dh.FilePath : "N/A")}");
```

## 常见错误对照表

| 错误信息 | 原因 | 解決策 |
|----------|------|----------|
| Setting manager is invalid | GameFramework 未初期化 | 确保 GameFrameworkEntry 已初期化 |
| Can not create setting helper | Helper クラス型名称错误 | 检查 Inspector 配置 |
| Load settings failure | 配置ファイル损坏或路径错误 | 检查ファイル路径和权限 |
| Save settings failure | 存储介质不可用 | 检查磁盘空间和权限 |
| GetAllSettingNames is not supported | 使用了 PlayerPrefsHelper | 改用 DefaultSettingHelper |
| Setting name is invalid | 設定名称为空 | 使用非空字符串作为键名 |
| Count returns -1 | PlayerPrefs 不サポート计数 | 使用 DefaultSettingHelper |
