# How to Initiate a Purchase (In-App Purchases and Subscriptions)

Call `PaymentComponent.Buy(PurchaseParams)` and listen to the `OnPurchaseSuccess` / `OnPurchaseFailed` events to complete purchases of one-time in-app products and subscription products; after server verification passes, call `ConsumePurchase` to consume the order. The old `BuyInApp` / `BuySubs` APIs have been marked `[Obsolete]`; it is recommended to uniformly use `Buy(PurchaseParams)`.

## Prerequisites

- `PaymentComponent` is attached to the scene (component menu path `GameFrameX/Payment`), and it automatically comes with `GameFrameXPaymentCroppingHelper`:

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
public class PaymentComponent : GameFrameworkComponent
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

- The corresponding channel implementation package for the target platform has been imported. `PaymentComponent.Awake()` automatically selects the implementation class based on compilation defines (Android → `GameFrameX.Payment.Google.Runtime.GooglePaymentManager`, iOS → `GameFrameX.Payment.Apple.Runtime.ApplePaymentManager`, other platforms fall back to `DefaultPaymentManager`).

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L69-L94)

## Steps

1. **Set predefined product IDs** (optional but recommended). Used to preload the product cache; **must be called before `Init()`**:

```csharp
payment.SetPredefinedProductIds(
    new List<string> { "gem_100", "gem_500" },      // List of in-app product IDs
    new List<string> { "vip_monthly" });             // List of subscription product IDs
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

2. **Initialize the payment system**:

```csharp
// isDebug: whether sandbox mode is enabled; isClientVerify: whether client-side purchase verification is performed
payment.Init(isDebug: false, isClientVerify: false);
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

| Parameter | Type | Default (component level) | Description |
|------|------|------------------|------|
| `isDebug` | `bool` | `false` | Whether to use sandbox purchases |
| `isClientVerify` | `bool` | `true` (`PaymentComponent`); `false` (`IPaymentManager`) | Whether to verify purchases on the client; set to `false` when using server-side verification |

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L102-L102), [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

3. **Subscribe to purchase result events** (recommended to subscribe once, before or after initialization):

```csharp
payment.OnPurchaseSuccess += (sender, e) =>
{
    Debug.Log($"购买成功: {e.ProductId}, OrderId={e.OrderId}");
    // Consume the order after server verification passes:
    // payment.ConsumePurchase(e.PurchaseToken);
};
payment.OnPurchaseFailed += (sender, e) =>
    Debug.Log($"购买失败: {e.ResultCode}, {e.ErrorMessage}");
```

Event signature source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L18-L26); for the same-named forwarding at the component level, see [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L30-L46)

4. **Confirm the payment system is ready before initiating a purchase**: Call `payment.IsReady()`; do not proceed to call `Buy` if it returns `false`.

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L45-L49)

5. **Construct `PurchaseParams` and call `Buy`**. `PurchaseParams` is an abstract base class (its constructor is `protected`) and cannot be instantiated directly with `new`; each channel uses its subclasses to pass in channel-specific parameters (such as the `offerToken` required for subscriptions). If the channel package does not provide a subclass, you can inherit one yourself:

```csharp
public sealed class MyPurchaseParams : PurchaseParams
{
    public MyPurchaseParams(string productId, string orderId, PaymentProductType productType)
        : base(productId, orderId, productType) { }
}

// Initiate a purchase (productType takes the enum value corresponding to in-app/subscription; see Runtime/PaymentProductType.cs for the definition)
payment.Buy(new MyPurchaseParams("gem_100", "order_20240101_001", productType));
```

Source: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L12-L35) (base class definition), [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L107-L112) (recommended entry point)

6. **Consume the purchase after server verification passes**. One-time products must be consumed before they can be purchased again:

```csharp
payment.ConsumePurchase(e.PurchaseToken);   // PurchaseToken comes from the PaymentEventArgs of OnPurchaseSuccess
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L140-L152)

Fields carried by `PaymentEventArgs` (used to send back for server verification):

| Field | Type | Description |
|------|------|------|
| `ProductId` | `string` | Product ID |
| `OrderId` | `string` | Order ID |
| `PurchaseToken` | `string` | Purchase token (used to consume the order) |
| `ResultCode` | `PaymentResultCode` | Payment result code |
| `ErrorMessage` | `string` | Error message |
| `PurchaseData` | `string` | Raw purchase data (JSON format) |

## Common Variants

- **Query historical orders / restore purchases**: Call `payment.QueryPurchases(PaymentProductType.<enum value>)`; the result is returned via the `OnQueryPurchasesResult` event, whose event arguments are also `PaymentEventArgs`.
  Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L51-L56), [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L28-L31)
- **Legacy APIs (deprecated)**: `BuyInApp(productId, orderId, offerToken = "", customData = "")` and `BuySubs(productId, orderId, offerToken = "", customData = "")` correspond to one-time products and subscription products respectively; both are marked `[Obsolete("请使用 Buy(PurchaseParams) 替代")]` and should not be used in new code.
  Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L72-L93)
- **Custom data pass-through**: With the legacy APIs, data is passed through the `customData` parameter and read back in event callbacks via `PaymentEventArgs.CustomData`; with the new `Buy(PurchaseParams)` entry point, channel subclasses extend the corresponding fields.

## Common Errors

| Symptom / Log | Cause | Fix |
|------|------|------|
| `Log.Fatal("Pay Manager is invalid.")` | `GameFrameworkEntry.GetModule<IPaymentManager>()` returns null | Check the platform implementation class name configuration (`m_componentXxxType` in the `PaymentComponent` Inspector) and whether the channel package has been imported |
| `Log.Warning("Product ID is null or empty.")` | `productId` is empty when calling the legacy `Buy*` APIs | Pass in a non-empty product ID |
| `Log.Warning("Order ID is null or empty.")` | `orderId` is empty when calling the legacy `Buy*` APIs | Pass in a non-empty order ID |
| `Log.Warning("Purchase token is null or empty.")` | An empty token is passed to `ConsumePurchase` | Use `e.PurchaseToken` from the `OnPurchaseSuccess` event |
| `SetPredefinedProductIds` has no effect | It is called only after `Init()` | Move the call before `Init()` |
| Repeated purchase of a one-time product fails (`ItemAlreadyOwned`) | The previous purchase was not consumed | Call `ConsumePurchase` after server verification passes; for result codes such as `ItemNotOwned`, `VerifyFailed`, and `NetworkError`, see the `PaymentResultCode` enum |

## Background

`PaymentComponent` is a facade that only performs parameter validation and event forwarding; the actual logic is completed by the `IPaymentManager` implementation resolved for each platform (Google / Apple / WebGL / PC / Default). Purchase results are raised uniformly through `PaymentEventArgs`, and `PaymentResultCode` distinguishes cases such as success, cancellation, network error, and already owned, making it easy to reuse the same high-level handling code across all platforms.
