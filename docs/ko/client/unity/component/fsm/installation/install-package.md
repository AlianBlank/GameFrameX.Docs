# GameFrameX FSM 패키지 설치 방법

이 가이드는 `com.gameframex.unity.fsm`(GameFrameX FSM 유한 상태 머신 패키지)을 Unity 프로젝트에 통합하는 방법을 설명합니다. 완료되면 코드에서 `FsmComponent`, `IFsm<T>`, `FsmState<T>` 등의 타입을 사용할 수 있습니다.

## 사전 요구 사항

| 항목 | 요구 사항 |
|------|------|
| Unity 버전 | 2019.4 이상([package.json](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/package.json#L7)) |
| 패키지 의존성 | 없음(`dependencies` 비어있음, [package.json](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/package.json#L22)) |
| 패키지 이름 | `com.gameframex.unity.fsm` |
| 최신 버전 | 1.2.0([package.json](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/package.json#L6)) |

## 작업 단계

아래 네 가지 방법 중 하나를 선택하면 됩니다.

### 방법 1: UPM 레지스트리(권장)

Unity 프로젝트 루트 디렉토리의 `Packages/manifest.json`을 편집하여 `scopedRegistries` 섹션을 추가하고, `dependencies`에 버전을 명시합니다:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.fsm": "1.2.0"
  }
}
```

> `scopes`는 `com.gameframex`로 시작하는 패키지만 이 레지스트리에서 해석하도록 제한하므로 다른 패키지 소스를 오염시키지 않습니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L46-L61)

### 방법 2: Git URL(GitHub 직접 연결)

`manifest.json`의 `dependencies` 노드에 Git 저장소 주소를 직접 추가합니다:

```json
{
  "dependencies": {
    "com.gameframex.unity.fsm": "https://github.com/gameframex/com.gameframex.unity.fsm.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L65-L70)

### 방법 3: Unity Package Manager Git URL

1. Unity 에디터를 열고 메뉴에서 `Window` → `Package Manager`를 선택합니다.
2. 왼쪽 상단의 `+` → `Add package from git URL...`을 클릭합니다.
3. 입력: `https://github.com/gameframex/com.gameframex.unity.fsm.git`
4. `Add`를 클릭하고 Unity가 해석하고 가져올 때까지 기다립니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L71)

### 방법 4: Packages 디렉토리에 직접 다운로드

1. [Releases](https://github.com/GameFrameX/com.gameframex.unity.fsm/releases) 페이지에서 소스 코드 zip을 다운로드하거나 저장소를 클론합니다.
3. 전체 `com.gameframex.unity.fsm` 폴더를 Unity 프로젝트의 `Packages/` 디렉토리에 넣습니다.
3. Unity가 자동으로 로컬 임베디드 패키지(embedded package)로 인식하고 로드를 완료합니다.

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L72)

## 설치 확인

설치가 완료되면 Unity에서 다음 사항을 확인합니다:

1. `Window` → `Package Manager`에서 `Packages: In Project`에 `Game Frame X FSM`이 표시되는지 확인합니다.
2. 임의의 스크립트에서 `using GameFrameX.Fsm;`이 성공하고 `FsmComponent`, `IFsm<T>`, `FsmState<T>` 등의 타입을 사용할 수 있는지 확인합니다.
3. 간단한 FSM을 생성하고 시작하여 컴파일 오류가 없는지 확인합니다:

```csharp
using GameFrameX.Fsm;
using UnityEngine;

public class BootCheck : MonoBehaviour
{
    class TestState : { }

    void Start()
    {
        var fsmComponent = GameEntry.GetComponent<FsmComponent>();
        // 연결 테스트 전용; 실제 사용법은 《사용 예제》 페이지를 참조하세요.
    }
}
```

## 일반적인 변형

| 시나리오 | 선택 |
|------|------|
| 이미 GameFrameX 생태계 사용 중(`com.gameframex.unity.entry`) | 방법 1 사용, 이후 `GameApp.Fsm`으로 빠른 접근 가능 |
| 특정 버전에 고정(팀 협업) | 방법 1 사용, `1.2.0`과 같은 고정 버전 번호 지정 |
| main 브랜치 최신 버전을跟随하고 싶은 경우 | 방법 2 또는 방법 3 사용 |
| 네트워크 제한으로 GitHub/UpM에 접근 불가 | 방법 4 사용, zip을 프로젝트에 임베드 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Package Manager에서 `com.gameframex.unity.fsm`을 찾을 수 없음 | `scopedRegistries`가 설정되지 않았거나 `scopes`가 일치하지 않음 | `scopes`에 `com.gameframex`가 포함되어 있는지, `url`이 `https://gameframex.upm.alianblank.uk`인지 확인 |
| `Package 'com.gameframex.unity.fsm' has no version` 등의 버전 오류 발생 | `dependencies`에 Git URL을 작성하면서 버전 번호도 추가한 경우 | 둘 중 하나만 선택: `"1.2.0"` 또는 Git URL, 혼용하지 마세요 |
| 임베디드 패키지를 수정한 후 Unity가 인식하지 못함 | 압축 파일을 직접 풀어 놓은 경우 `.meta` 파일이 누락될 수 있음 | `git clone`으로 소스를 가져오거나, zip 압축 해제 시 `.meta` 파일을 유지하세요 |

## 배경(선택 사항)

`com.gameframex.unity.fsm`은 의존성이 없는 패키지로, `package.json`에 Unity 2019.4의 최소 버전 요구 사항만 명시되어 있으므로 GameFrameX 메인 프레임워크를 추가로 도입하지 않고도 단독으로 설치하여 사용할 수 있습니다.
