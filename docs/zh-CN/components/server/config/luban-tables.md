# 使用 Luban 配置表与 TablesComponent 加载

`TablesComponent` 是 GameFrameX.Config 中由 Luban 工具自动生成的配置表容器,负责在运行时把所有 `.json` 配置表加载进 `ConfigComponent`,并解析表间的引用关系。读完本页你能在服务端或客户端启动时一次性加载所有 Luban 表,并按需访问具体条目。

## 前置条件

- 已通过 Luban 工具生成 `GameFrameX.Config` 项目,产物中包含 `TablesComponent.cs` 与 `Tables/*.cs`、`Local/*.cs`。
- 项目已引用 `GameFrameX.Core.Abstractions`(提供 `ConfigComponent` 与 `BeanBase`)。
- 准备好 Luban 导出的 JSON 文件(`tables_tbxxx`、`local_tblocalization` 等命名约定),部署到可被 `loader` 回调读取的位置(本地文件、AssetBundle、远端下载均可)。

## 操作步骤

1. **实例化配置管理器**。`ConfigComponent` 内部已经创建好 `TablesComponent`,直接用即可:

   ```csharp
   var configComponent = new ConfigComponent();
   var tables = configComponent.Tables; // 私有属性,需要经下方 Init 注入
   ```

   Source: [ConfigComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/ConfigComponent.cs#L14-L19)

2. **调用 `Init` 注入 `ConfigComponent`**。这一步把表注册入口交给 `ConfigComponent`,后续 `Add` 时把表写入统一容器:

   ```csharp
   tables.Init(configComponent);
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

3. **提供 `loader` 回调并异步加载**。`loader` 接收表名,返回该表 JSON 的 `JsonElement`。所有表并行加载,完成后自动 `Refresh` 解析引用:

   ```csharp
   await tables.LoadAsync(async tableName =>
   {
       var json = await File.ReadAllTextAsync($"Configs/{tableName}.json");
       return JsonDocument.Parse(json).RootElement.Clone();
   });
   ```

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L56)

4. **读取具体表与条目**。加载完成后,通过 `TablesComponent` 的强类型属性拿到具体表对象。例如:

   ```csharp
   var itemConfig = tables.TbItemConfig;
   var oneItem = itemConfig.Get(1001); // 由 Luban 生成的索引/查询方法
   ```

   `TablesComponent` 当前暴露的表属性:`TbLocalization`、`TbAchievementConfig`、`TbItemConfig`、`TbSoundsConfig`。

   Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L18-L21)

5. **(可选)在热更新场景重新加载**。再次调用 `LoadAsync` 前不需要 `Init`;`loader` 会再次读取每个表的最新 JSON,`Refresh()` 会重跑 `PostInit` 与 `ResolveRef`,覆盖之前的引用关系。

## 常见变体

- **远端下载 + 本地缓存**:把 `loader` 实现成「先查本地缓存,未命中走 HTTP,下载后落盘并解析 JSON」,即可让 Luban 表支持 CDN 热更。
- **从 AssetBundle 读取**:在客户端把 `loader` 替换为 `Resources.LoadAsync<TextAsset>(tableName).Result.text`,保持函数签名一致即可,无需改动 `TablesComponent`。
- **部分表懒加载**:把不需要启动时加载的表从 `LoadAsync` 中注释掉(注释代码已保留在生成文件中),改由业务侧按需 `new TbXxx(...)` 加载。

## 常见错误

- **找不到表 JSON**:`loader` 抛异常会让 `Task.WhenAll` 失败,整个 `LoadAsync` 抛出;确保文件命名严格遵循 `tables_xxx` / `local_xxx` 前缀。
- **引用解析失败**:`Refresh()` 内部会调用每个表的 `ResolveRef(this)`;若 `PostInit` 或 `ResolveRef` 中访问尚未加载的表会触发空引用,需保证所有相关表都通过 `LoadAsync` 走一遍。
- **重复 `Init`**:再次调用 `Init` 会再次执行 `RemoveAllConfigs()`,会清空已加载的表引用,通常只在重置场景使用。
- **修改生成文件**:`TablesComponent.cs` 与 `Tables/*.cs` 顶部都标记了 `// <auto-generated>`,任何手写改动会在下次 Luban 重新生成时被覆盖。

## 背景(可选)

`TablesComponent` 是 Luban `gen_cs_server_json` / `gen_cs_client_json` 模板的产物:每张表对应一个 `BeanBase` 子类(如 [`ItemConfig`](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Config/Config/Tables/ItemConfig.cs#L15-L76)),构造函数从 `JsonElement` 反序列化字段,`ResolveRef` 用于在表间把 `xxx_ref` 字段连接回具体行对象。
