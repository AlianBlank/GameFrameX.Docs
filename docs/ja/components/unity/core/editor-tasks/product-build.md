# 製品ビルドフローの設定

Unity の上部メニュー `GameFrameX/Build/*` からワンクリックで各プラットフォームの公開可能バージョンをエクスポートし、ビルド前後にフックを通じてカスタムステップ(設定ファイルのコピー、ホット更新プロジェクトの注入、一時ディレクトリのクリーンアップなど)を注入します。

## 前提条件

- Unity エディタがインストールされており、プロジェクトが Unity Hub を通じて開かれていること。
- `File → Build Settings` でパッケージ化するシーンを事前にチェックしておくこと。チェックされていないと `EditorBuildSettings.scenes` が空になり、成果物にシーンが含まれません。
- Android プラットフォームをビルドする場合は、対応する Build Support モジュールがインストールされ、JDK / Android SDK が設定されていることを確認してください。
- ホットフィックスフローが必要な場合は、`GameFrameX` 関連の HotFix エディタ拡張がインストールされていることを確認してください(コマンド `HotFixEditorCompilerHelper.AddEditor()` が自動的に呼び出されます)。
- 出力ディレクトリのあるディスクに書き込み権限があること。Windows プラットフォームのデフォルトの成果物パスは以下を参照してください。

## 操作手順

### 1. ビルドプラットフォームの切り替え

Unity の上部メニューから `File → Build Settings` をクリックし、`Platform` リストからターゲットプラットフォームを選択して `Switch Platform` をクリックします。メニュー項目は現在のアクティブなビルドターゲットを検証し、プラットフォームが一致しない場合は `現在のビルドターゲットは XXX ではありません` を出力して直接戻ります。

### 2. メニューを選択してビルドをトリガーする

ターゲットプラットフォームに応じて、Unity の上部メニューから `GameFrameX → Build → <プラットフォーム名>` を順にクリックします。各メニュー項目は `BuildProductHelper` 内の静的メソッドに対応しています。

| メニュー項目 | 対応メソッド | BuildTarget | 出力場所 |
|--------|----------|-------------|----------|
| `GameFrameX/Build/Windows X64` | `BuildPlayerToWindows64BuildTarget` | `StandaloneWindows64` | `_buildPath/PlayerSettings.productName.exe` |
| `GameFrameX/Build/Windows X32` | `BuildPlayerToWindows32BuildTarget` | `StandaloneWindows` | 同上(ディレクトリ名が異なる) |
| `GameFrameX/Build/Mac Os` | `BuildPlayerToMacBuildTarget` | `StandaloneOSX` | 同上 |
| `GameFrameX/Build/WebGL` | `BuildPlayerToWebGLBuildTarget` | `WebGL` | `BuildOutputPath()` によって決定 |
| `GameFrameX/Build/Android(APK)` | `BuildPlayerToAndroid` | `Android` | `apkPath`(APK) |
| `GameFrameX/Build/Android(AAB)` | `BuildPlayerToAndroidAAB` | `Android` | `aabFilePath`(AAB) |
| `GameFrameX/Build/Android Studio Project` | `BuildPlayerToAndroidStudio` | `Android` | `_buildPath`(Gradle プロジェクトディレクトリ) |
| `GameFrameX/Build/Android(Development)` | `BuildPlayerToAndroidDevelopment` | `Android` | `AllowDebugging \| Development \| ConnectWithProfiler` を含む |
| `GameFrameX/Build/iOS` | `BuildPlayerToIOS` | `iOS` | Xcode プロジェクトディレクトリ |

呼び出しエントリの抜粋:

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("現在のビルドターゲットは Windows ではありません");
        return;
    }
    try
    {
        HotFixEditorCompilerHelper.AddEditor();
        PlayerSettings.fullScreenMode = FullScreenMode.Windowed;
        PlayerSettings.defaultScreenHeight = 720;
        PlayerSettings.defaultScreenWidth = 1280;
        EditorUserBuildSettings.selectedStandaloneTarget = BuildTarget.StandaloneWindows64;
        UpdateBuildTime();
        AssetDatabase.SaveAssets();
        _buildPath = BuildOutputPath();
        var resultDirectory = _buildPath + Path.DirectorySeparatorChar;
        RunPreHookBuild();
        var buildReport = BuildPipeline.BuildPlayer(EditorBuildSettings.scenes, resultDirectory + PlayerSettings.productName + ".exe", EditorUserBuildSettings.activeBuildTarget, BuildOptions.None);
        // ...
    }
    finally
    {
        HotFixEditorCompilerHelper.RemoveEditor();
        RunPostHookBuild();
    }
}
```

### 3. ビルドを待ち、出力を確認する

ビルドプロセス中、`BuildPipeline.BuildPlayer` は `BuildReport` を返します。`summary.result == BuildResult.Succeeded` の場合のみ後続のクリーンアップとコピー処理が続行されます。それ以外の場合はメソッドが早期に返されます。コンソールには `Build Output Path:` とそれに続く最終成果物パスが表示されます。Android プラットフォームでは、`EditorUserBuildSettings.selectedStandaloneTarget` / 対応する API を通じて署名関連のパラメータも自動的に設定されます(ソースファイル [BuildProductHelper.cs](/src/Editor/BuildProduct/BuildProductHelper.cs#L360-L450) を参照)。

### 4. ビルド前後のフックを組み込む(オプション)

ビルドの前後で自動的にステップを実行する必要がある場合は、`IBuilderPreHookHandler` または `IBuilderPostHookHandler` を実装してください。フレームワークは成果物の構築前後にすべての実装クラスを呼び出し、`Priority` の昇順で実行します。

```csharp
using UnityEditor;
using GameFrameX.Editor;

public sealed class CopyExtraConfigsPreHook : IBuilderPreHookHandler
{
    // 値が大きいほど、実行順序が後になります
    public int Priority => 100;

    public void Run(BuildTarget target, string path)
    {
        // target: 現在の BuildPipeline.BuildPlayer のターゲットプラットフォーム
        // path:   フレームワークが準備した出力パス(実行可能ファイル名またはディレクトリを含む)
        // ここにリソースのコピー、PlayerSettings の変更などのカスタムロジックを記述します
    }
}
```

## よくあるバリエーション

- カスタム出力パス:各メソッドはまず `_buildPath = BuildOutputPath()`(クラス内静的フィールド)を設定し、それを `BuildPipeline.BuildPlayer` に渡します。名前の変更やディレクトリの変更が必要な場合は、メニューを呼び出す前に `PlayerSettings.productName` を変更するか、`BuildOutputPath()` を拡張してください。
- ホットフィックスフローの組み込み:`HotFixEditorCompilerHelper.AddEditor()` は各プラットフォームエントリの `try` の先頭ですでに呼び出されており、`finally` で `HotFixEditorCompilerHelper.RemoveEditor()` を呼び出してプロジェクトファイルを復元します。ホットフィックスの必要がない場合は無視しても構いません。
- カスタム後処理:Steamworks 設定ファイルは `CopySteamWorksConfig` を通じて自動的に成果物ディレクトリにコピーされます。同様のツールを追加する場合は、その呼び出しを直接コピーするか、`IBuilderPostHookHandler` を登録してください。
- デバッグ版ビルド:Android プラットフォームには専用の `BuildPlayerToAndroidDevelopment` エントリがあり、`AllowDebugging | Development | ConnectWithProfiler` を含む APK を出力します。Profiler デバッグに使用します。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|----------|
| メニューをクリックするとすぐに `現在のビルドターゲットは XXX ではありません` が出力されて終了する | 現在のアクティブプラットフォームがメニュー項目に対応する `BuildTarget` と一致していない | まず `Build Settings` で対応するプラットフォームに切り替え、その後メニューをトリガーする |
| ビルド成果物に `*_Data` ディレクトリしかなく、実行可能ファイルがない | `EditorBuildSettings.scenes` が空であるか、一部のシーンしかチェックされていない | `Build Settings → Scenes In Build` でパッケージ化するすべてのシーンをチェックする |
| 最終ディレクトリに `BackUpThisFolder_ButDontShipItWithYourGame` が余計に存在する | フレームワークはすでにそのディレクトリを能動的に削除しているが、一部のファイルは占有されているため残留している可能性がある | 占有プロセスを閉じてから再試行する。保持が必要な場合はカスタムフックで対応するクリーンアップロジックをスキップする |
| フックが期待通りの順序で実行されない | `Priority` が設定されていないか、複数の実装で同じ値が使用されている | 各実装に明示的に値を割り当てる。値が大きいほど後方にソートされる |
| ビルド後も Unity に編集マクロやエディタプロジェクトファイルが残る | `HotFixEditorCompilerHelper.RemoveEditor()` がトリガーされていない | メニューの `try/finally` を手動でスキップしないこと。コピー方式ではなくメニューを通じてトリガーする必要がある |

## 背景(オプション)

`BuildProductHelper` は `BuildPipeline.BuildPlayer` の前に `RunPreHookBuild()` を呼び出し、`finally` で `RunPostHookBuild()` を呼び出します。どちらも内部で `Utility.Assembly.GetTypes()` を介してリフレクションで対応するインターフェースを実装する具象型をすべてスキャンし、`Priority` の昇順でインスタンス化して `Run(BuildTarget, string)` を呼び出します。この仕組みにより、ユーザの業務はフレームワークのソースコードを変更することなく、ビルド前後のロジックを注入できます。
