# 伺服器提示 ServerFullyLoaded(超過最大線上人數)怎麼辦

當用戶端連線伺服器或進入房間時，如果收到 `ServerFullyLoaded` (列舉值 `14`) 錯誤或 `NotifyServerFullyLoaded` 通知，表示已達上限，伺服器拒絕了連線或加入請求。該錯誤來自兩個獨立的限流點：伺服器全域最大線上數 `MaxClientCount` 與單一房間的 `MaxPlayerCount`。

## 快速診斷

| 症狀 | 觸發位置 | 根本原因 | 修復 |
|------|----------|------|------|
| 用戶端一連上就被踢出，收到 `NotifyServerFullyLoaded` 通知 | `OnConnected` 全域進入點 | 目前工作階段數 `count > Setting.MaxClientCount` | 調大 `MaxClientCount` 或擴充/排隊，見 [伺服器側修復](#伺服器側修復) |
| 進入特定房間失敗，回應中 `ErrorCode = 14` | `RoomComponentAgent` 加入房間邏輯 | `room.PlayerIds.Count >= room.MaxPlayerCount` | 調大房間 `MaxPlayerCount`、拆分房間或引導進其他房間，見 [房間側修復](#房間側修復) |

錯誤碼定義在 `OperationStatusCode.ServerFullyLoaded = 14`,描述為「通知用戶端伺服器人數已達上限」:

```csharp
// Source: GameFrameX.Proto/Proto/_0020_Common.cs#L148-L153
/// <summary>
/// 通知用戶端伺服器人數已達上限
/// </summary>
[System.ComponentModel.Description("通知客户端服务器人数已达上限")]
ServerFullyLoaded = 14,
```

通知訊息定義：

## 伺服器側修復

觸發點：用戶端剛建立連線時，伺服器端比對目前工作階段數與全域上限。

```csharp
// Source: GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L79-L90
protected override async ValueTask OnConnected(IAppSession appSession)
{
    LogHelper.Info("有外部客户端网络连接成功！。链接信息：SessionID:" + appSession.SessionID + " RemoteEndPoint:" + appSession.RemoteEndPoint);
    var netChannel = new DefaultNetWorkChannel(appSession, Setting);
    var count = SessionManager.Count();
    if (count > Setting.MaxClientCount)
    {
        // 達到最大線上人數限制
        await netChannel.WriteAsync(new NotifyServerFullyLoaded(), (int)OperationStatusCode.ServerFullyLoaded);
        netChannel.Close();
        return;
    }
    // ...
}
```

注意比較運算子是嚴格大於(`>`),即 `count` 達到 `MaxClientCount` 本身仍允許連線；超過才拒絕。

按以下順序處理：

1. **確認設定項來源**:`MaxClientCount` 讀取自 `Setting`(由啟動設定初始化)。找到部署目錄下 `setting.json`(或對應環境設定)中 `MaxClientCount`,核對目前值與預期承載量。
2. **提高上限**：在設定檔中把 `MaxClientCount` 調高，例如從 `5000` 改到 `8000`,然後重新啟動服務使新值生效。
3. **橫向擴充**：如果單機已到承載瓶頸，在閘道後掛接更多 GameFrameX 節點(部署多程序/多機)，透過閘道層負載平衡分擔工作階段。
4. **加入排隊**：用戶端在收到 `NotifyServerFullyLoaded` 後不要立即重試，顯示「伺服器繁忙，請稍候」並按退避策略(例如 5s、10s、30s 遞增)排隊重新連線。
5. **排查工作階段洩漏**：確認 `OnDisconnected` 中 `SessionManager.Remove(appSession.SessionID)` 正確執行([AppStartUpHotfixGameByMain.cs#L71](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L71)),否則異常斷線的工作階段會一直佔位。

## 房間側修復

觸發點：玩家加入房間時，目標房間已滿。

```csharp
// Source: GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L181-L186
if (room.PlayerIds.Count >= room.MaxPlayerCount)
{
    response.ErrorCode = (int)OperationStatusCode.ServerFullyLoaded;
    response.Room = await ToMessageAsync(room);
    return;
}
```

處理步驟：

1. **調高 `MaxPlayerCount`**:在房間設定(建立房間時使用的參數)中，把目標房間類型的 `MaxPlayerCount` 調大，重新啟動或重新發送設定讓房間元件讀到新值。
2. **拆分成多房間**：把同一類玩法的房間範本切成多份(例如房間編號區段、配對池分桶)，讓玩家分散到不同房間。
3. **用戶端側引導**：收到 `ErrorCode = 14` 時，用戶端不要原地無限迴圈重試，應重新走配對/換房流程；後端可在回應裡附帶可用房間清單(本儲存庫目前實作只回 `room` 本身，若需要多房推薦需擴充回應結構)。
4. **檢查房間設定**：確認 `MaxPlayerCount` 與 `MinPlayerCount`、`Status` 轉換邏輯一致([RoomComponentAgent.cs#L189](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L189)),避免設定錯誤造成一直停在 `Waiting` 或 `Ready` 誤判。

## 驗證

1. **伺服器側**：重新啟動後，連線數接近 `MaxClientCount` 時仍可加入；再多一個連線仍應收到 `NotifyServerFullyLoaded`,關閉連線。
2. **房間側**：使用測試用戶端把房間塞到 `MaxPlayerCount`,再嘗試加入應得到 `ErrorCode = 14` 且 `Room` 欄位回傳目前房間資訊(可用於用戶端顯示「房間已滿 XX/XX」)。
3. **日誌核驗**：伺服器端 `LogHelper.Info` 會記錄「有外部用戶端網路連線成功」；在觸發踢人時，用戶端應觀察到 `ServerFullyLoaded = 14` 後連線關閉，無需伺服器端再寫額外日誌。

## 背景(可選)

`ServerFullyLoaded` 在儲存庫裡有雙重意義：既是 `OperationStatusCode` 的回傳碼，也是斷線時主動推送的 `NotifyServerFullyLoaded` 通知。兩類場景共用同一個列舉值，所以用戶端只需用 14 這一個值判斷「人滿」即可，但根本原因排查需要分清是連線層還是房間層拒絕。
