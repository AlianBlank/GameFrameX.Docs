# 常見問題

本文件彙總了使用 Timer 計時器組件時可能遇到的常見問題及其解決方案。

## 概述

Timer 組件是 GameFrameX 框架提供的計時器功能模組，為 Unity 專案提供定時任務、延遲執行和幀更新等功能支援。在使用過程中，使用者可能會遇到一些問題，本文件將提供詳細的診斷和解決方案。

## 常見問題與解決方案

### 1. 定時器不執行

#### 症狀
新增定時任務後，回呼函式從未被執行。

#### 可能原因
- Timer 組件未正確新增到場景中的 GameObject
- GameFramework 框架未正確初始化
- TimerManager 模組未註冊

#### 解決方案

**檢查組件是否新增：**

```csharp
// 確保場景中有 TimerComponent
var timerComponent = FindObjectOfType<TimerComponent>();
if (timerComponent == null)
{
    Debug.LogError("TimerComponent 未找到，請先新增組件");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

**檢查框架初始化：**
確保在遊戲啟動時正確初始化了 GameFramework 框架。TimerComponent 會在 Awake 時從 GameFrameworkEntry 獲取 ITimerManager 例項：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(ITimerManager);
    base.Awake();
    _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
    if (_timerManager == null)
    {
        Log.Fatal("Timer manager is invalid.");  // 計時器管理器無效
        return;
    }
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L17-L28)

### 2. 回呼函式引數傳遞問題

#### 症狀
傳遞給回呼函式的引數為 null，或者無法正確獲取引數。

#### 可能原因
- 未正確傳遞 callbackParam 引數
- 誤用了 AddOnce 的單引數過載

#### 解決方案

Timer 組件的回呼函式簽名為 `Action<object>`，引數透過 callbackParam 傳遞：

```csharp
// 正確傳遞引數的方式
timerComponent.Add(1.0f, 1, OnTimerComplete, "這是傳遞的資料");

// 回呼函式接收引數
private void OnTimerComplete(object param)
{
    Debug.Log($"定時器完成，引數: {param}");  // 輸出: 定時器完成，引數: 這是傳遞的資料
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

---

### 3. 間隔時間單位混淆

#### 症狀
定時器執行間隔與預期不符，例如設定 1000 毫秒卻每秒執行多次。

#### 可能原因
**重要：Timer 組件的 interval 引數單位是秒（seconds），而不是毫秒！**

README 文件中存在錯誤描述，實際程式碼中 interval 是以秒為單位的浮點數：

```csharp
// interval 引數單位為秒 (seconds)
public void Add(float interval, int repeat, Action<object> callback, object callbackParam = null)
{
    _timerManager.Add(interval, repeat, callback, callbackParam);
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L37-L40)

#### 解決方案

```csharp
// ❌ 錯誤：將 1000 理解為毫秒
timerComponent.Add(1000f, 1, callback);  // 實際上會以 1000 秒的間隔執行

// ✅ 正確：將 interval 視為秒
timerComponent.Add(1.0f, 1, callback);  // 1 秒後執行一次
timerComponent.Add(0.5f, 5, callback); // 每 0.5 秒執行一次，共 5 次

// 轉換為毫秒的正確寫法
float intervalInSeconds = 1000f / 1000f;  // 1000 毫秒 = 1 秒
timerComponent.AddOnce(intervalInSeconds, callback);
```

### 4. 定時任務重複新增

#### 症狀
使用相同回呼函式多次呼叫 Add 方法後，定時器行為異常。

#### 可能原因
TimerManager 使用回呼函式作為字典鍵，當新增相同回呼的定時器時，會更新現有定時器而非建立新定時器：

```csharp
// 程式碼實現：如果回呼已存在，會更新現有定時器
if (_items.TryGetValue(callback, out var t))
{
    t.Set(interval, repeat, callback, callbackParam);
    t.Elapsed = 0;
    t.Deleted = false;
    return;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L167-L173)

#### 解決方案

在新增新定時器前檢查是否已存在：

```csharp
// 檢查定時器是否已存在
if (!timerComponent.Exists(MyCallback))
{
    timerComponent.Add(1.0f, 5, MyCallback);
}
else
{
    Debug.LogWarning("定時器已存在，請先移除後再新增");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 5. 回呼函式異常導致定時器崩潰

#### 症狀
定時器回呼中發生異常後，整個定時器系統停止工作。

#### 可能原因
預設情況下，回呼函式中的異常會中斷定時器的執行。

#### 解決方案

TimerManager 提供了 `CatchCallbackExceptions` 靜態屬性來控制異常處理行為：

```csharp
// 啟用異常捕獲，防止回呼異常導致定時器崩潰
TimerManager.CatchCallbackExceptions = true;

// 新增定時任務
timerComponent.Add(1.0f, 0, OnTimerTick);

// 回呼函式中即使發生異常也不會終止定時器
private void OnTimerTick(object param)
{
    // 可能丟擲異常的程式碼
    throw new Exception("模擬異常");
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L41-L43)

啟用異常捕獲後，異常會被捕獲並記錄警告日誌，同時標記該定時器為已刪除：

```csharp
if (CatchCallbackExceptions)
{
    try
    {
        timerItem.Callback(timerItem.Param);
    }
    catch (Exception e)
    {
        timerItem.Deleted = true;
        Debug.LogWarning("Timer: timer(internal=" + timerItem.Interval + ", repeat=" + timerItem.Repeat + ") callback error > " + e.Message);
    }
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L86-L97)

### 6. 定時器記憶體洩漏

#### 症狀
長時間執行後，記憶體佔用持續增長。

#### 可能原因
- 定時任務完成後未正確移除
- 使用 AddUpdate 新增的幀更新任務未手動移除

#### 解決方案

**對於重複次數有限的定時器：**
Repeat = 0 表示無限重複，Repeat > 0 會在執行指定次數後自動移除：

```csharp
// ✅ Repeat = 0 會無限重複，需要手動移除
timerComponent.Add(1.0f, 0, repeatingCallback);

// 在適當時候手動移除
timerComponent.Remove(repeatingCallback);

// ✅ Repeat > 0 會在執行完指定次數後自動移除
timerComponent.Add(1.0f, 5, limitedCallback);  // 執行 5 次後自動移除
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L73-L81)

**對於幀更新任務（AddUpdate）：**
AddUpdate 本質上使用極小間隔（0.001秒）的重複定時器，必須手動移除：

```csharp
// 新增幀更新任務
timerComponent.AddUpdate(OnUpdate);

// 在物件銷燬或不需要時移除
timerComponent.Remove(OnUpdate);
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L206-L219)

### 7. 定時器精度問題

#### 症狀
定時器執行時間不精確，存在較大誤差。

#### 可能原因
- 使用了過小的間隔時間
- 遊戲幀率不穩定
- 切換到後臺時 Unity 的時間系統會發生變化

#### 解決方案

TimerManager 使用 `realElapseSeconds`（實際經過的時間）來計算定時器：

```csharp
// 內部使用 realElapseSeconds 計算經過時間
timerItem.Elapsed += realElapseSeconds;
if (timerItem.Elapsed < timerItem.Interval)
{
    continue;
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L63-L71)

**最佳化建議：**

```csharp
// ❌ 避免使用過小的間隔
timerComponent.Add(0.0001f, 0, callback);  // 可能導致效能問題

// ✅ 推薦：最小間隔不低於 0.01 秒（10 毫秒）
timerComponent.Add(0.01f, 0, callback);

// 對於需要更高精度的場景，考慮使用 Unity 的 Update 或 Coroutine
```

### 8. 在協程中使用定時器

#### 症狀
在協程中建立的定時器行為異常。

#### 解決方案

Timer 組件可以在協程中使用，但需要注意生命週期管理：

```csharp
IEnumerator StartTimerInCoroutine()
{
    // 在協程中使用定時器
    timerComponent.AddOnce(2.0f, OnDelayComplete, "協程資料");
    
    yield return new WaitForSeconds(2.0f);
    // 協程結束，但定時器任務可能仍在執行
}

private void OnDelayComplete(object param)
{
    Debug.Log($"延遲完成: {param}");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L48-L51)

## 診斷工具

### 檢查定時器狀態

使用 Exists 方法檢查定時器是否存在：

```csharp
// 檢查特定回呼的定時器是否存在
bool isRunning = timerComponent.Exists(MyCallback);

if (isRunning)
{
    Debug.Log("定時器正在執行");
}
else
{
    Debug.Log("定時器未執行或已完成");
}
```
> Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L77-L80)

### 列出所有活動定時器

由於 TimerManager 使用字典儲存定時器，可以透過擴充套件來獲取活動定時器列表：

```csharp
// 注意：TimerManager 的 _items 欄位是私有的
// 如需除錯，可以啟用日誌輸出
Debug.Log($"當前活動定時器數量: {活動數量}");
```

## 效能注意事項

### 1. 回呼函式委託建立

每次新增定時器時，不要使用匿名Lambda表示式作為回呼，因為這會建立新的委託例項，導致無法正確移除定時器：

```csharp
// ❌ 錯誤：匿名方法無法移除
timerComponent.Add(1.0f, 1, (param) => Debug.Log("test"));

// ✅ 正確：使用具名方法
timerComponent.Add(1.0f, 1, OnTimerTick);

// 之後可以正確移除
timerComponent.Remove(OnTimerTick);

private void OnTimerTick(object param)
{
    Debug.Log("Timer tick");
}
```

### 2. 大量定時器

TimerManager 使用字典和鎖實現，對於數千個同時存在的定時器可能會有效能影響。考慮合併多個定時任務或使用其他方式管理。
