# 如何在打包裁剪中保住協程元件

把 `GameFrameXCoroutineCroppingHelper` 掛到 Unity 場景裡的 GameObject 上,即可讓 `CoroutineComponent` 在 IL2CPP / Managed Stripping 開啟的打包環境下不被裁剪掉,協程 API 仍可正常呼叫。

## 前置條件

- 已安裝本協程套件(`com.gameframex.unity.coroutine`)
- 目標平台啟用受管理程式碼裁剪(Managed Stripping 或 IL2CPP),或使用了 link.xml / Preserve 機制的專案
- 已有一個常駐場景(GameObject 在打包後不會銷毀)

## 操作步驟

1. 在任意一個常駐場景(例如啟動場景)裡新增一個 GameObject,例如命名為 `GameFrameXCoroutineCroppingHelper`。
2. 為該 GameObject 新增 `GameFrameXCoroutineCroppingHelper` 元件。

   ```csharp
   using GameFrameX.Coroutine.Runtime;
   ```
   Source: [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

3. 不用掛載到 `DontDestroyOnLoad` —— 該元件的 `Start` 在任意場景裡執行一次,都足以讓裁剪器保留 `CoroutineComponent` 的型別參考。
4. 重新打包,執行遊戲後即可照常使用 `GameEntry.GetComponent<CoroutineComponent>().StartCoroutine(...)`。

## 常見變體

- **不使用 CroppingHelper**:可以在專案中加一個 `link.xml`,把 `GameFrameX.Coroutine.Runtime` 命名空間整體保留。
- **避免任何額外 GameObject**:在任意已有元件的腳本裡寫 `private void Start() { _ = typeof(GameFrameX.Coroutine.Runtime.CoroutineComponent); }`,並給該類別加上 `[Preserve]`,效果等同。
- **AOT 平台(IL2CPP + iOS/Android)**:強烈建議掛上 CroppingHelper,否則 `StartCoroutine` / `StopCoroutine` 的 `new` 覆寫在某些裁剪層級下會找不到對應方法。

## 常見錯誤

| 現象 | 原因 | 修正 |
|------|------|------|
| 打包後呼叫 `StartCoroutine` 擲回 `MissingMethodException` | `CoroutineComponent` 的 `new` 多載方法被裁剪器移除 | 掛上 `GameFrameXCoroutineCroppingHelper`,或補上 `link.xml` 保留命名空間 |
| 執行階段找不到 `GameFrameXCoroutineCroppingHelper` 型別 | 該腳本在 AOT 下被一併裁掉了 | 不要在 link.xml 中誤把 `GameFrameX.Coroutine.Runtime.*` 排除;CroppingHelper 自身已帶 `[Preserve]` |
| 新增元件後場景裡多了一個空物件 | 僅用於觸發 `Start` 參考,沒有視覺/邏輯副作用 | 可隱藏 `MeshRenderer`,或把它合併到已有的常駐單例物件上 |

## 背景(選用)

`GameFrameXCoroutineCroppingHelper` 內部僅有一段 `Start`,參考了 `typeof(CoroutineComponent)`。由於類別與方法都標記了 `[Preserve]`(來自 `UnityEngine.Scripting`),Unity 的 Stripping 階段會保留這條參考鏈,從而保住 `CoroutineComponent` 及其 `new` 隱藏的方法。
