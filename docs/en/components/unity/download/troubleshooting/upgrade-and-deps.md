# Version Upgrades and Dependency Compatibility Issues

When upgrading `com.gameframex.unity.download` or updating upstream dependencies (Unity main framework, event module), if you encounter compilation errors, missing namespaces, or `Package Manager` resolution failures, you can troubleshoot them on this page.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Package Manager` reports `An error occurred while resolving packages: Project depends on 'com.gameframex.unity'` | Missing main framework dependency, or the version does not meet the requirements of `com.gameframex.unity.download` | Add or upgrade [com.gameframex.unity](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L25-L28) to the specified version in `manifest.json` |
| Compilation reports `The type or namespace name 'GameFrameX' could not be found` | `com.gameframex.unity.event` is missing or the version is too low | Add the event package dependency [com.gameframex.unity.event 1.3.0](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L25-L28) |
| After upgrading, `WWWDownloadAgentHelper` related symbols cannot be found | Namespace/spelling errors before 1.1.2; the old API has been changed | Upgrade to [1.1.2+](https://github.com/gameframex/com.gameframex.unity.download/blob/main/CHANGELOG.md#L15-L21) and reference using the corrected namespace |
| Old version remnants appear in `Library/PackageCache`, causing behavior inconsistent with the new version | Unity cached the old version without cleaning it up | Delete `Library/PackageCache/com.gameframex.unity.download*` and re-resolve the packages |
| Package incompatibility reported when opening the project with Unity below 2019.4 | The package declares a minimum Unity version of 2019.4 | Upgrade Unity Editor to [2019.4 or higher](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L7) |

## Fix Steps

### 1. Verify Package Dependency Declarations

The dependencies declared by `com.gameframex.unity.download` itself are as follows (versions may be updated at any time; refer to the repository as the source of truth):

```json
"dependencies": {
  "com.gameframex.unity.event": "1.3.0",
  "com.gameframex.unity": "2.5.1"
}
```

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json#L25-L28)

If these two dependencies are missing in the project's `Packages/manifest.json`, have versions that are too low, or are explicitly pinned to different versions, you need to align them with the versions above and then let Unity re-resolve.

### 2. Upgrade the Package in the Unity Project

Following the order of operations below can avoid most caching issues:

1. Close Unity Editor.
2. Edit `Packages/manifest.json` and change `com.gameframex.unity.download` to the target version (e.g., `1.2.1`).
3. Delete the old caches of the three directories: `Library/PackageCache/com.gameframex.unity.download*`, `Library/PackageCache/com.gameframex.unity*`, and `Library/PackageCache/com.gameframex.unity.event*`.
4. Reopen Unity and let `Package Manager` re-resolve the dependencies.

### 3. Handle the Framework Auto-Registration Change in 1.2.0

Starting from 1.2.0, the module adapted to the GameFrameX framework's auto-registration mechanism ([CHANGELOG 1.2.0](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L8-L13)). When upgrading to 1.2.0 or above, make sure to also upgrade the main framework `com.gameframex.unity` to 2.5.1+, otherwise the entry types required for auto-registration may not be found.

### 4. Handle the Namespace Fix in 1.1.2

1.1.2 fixed the namespace and spelling errors of `WWWDownloadAgentHelper` ([CHANGELOG 1.1.2](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L15-L21)). When upgrading from 1.1.1 or earlier, if the project contains `using` statements or code referencing the old name of this helper class, they must be adjusted to the new namespace; otherwise, compilation will fail.

### 5. Handle the Dependency Completion in 1.1.1

Versions before 1.1.1 may be missing key dependencies in `package.json` ([CHANGELOG 1.1.1](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L23-L29)). If upgrading from an even older version, it is recommended to upgrade directly to [1.2.1](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/CHANGELOG.md#L1-L6), skipping the intermediate manual dependency fixes.

### 6. Handle Assembly Definition Changes

This package maintains separate `.asmdef` metadata in three directories:

- [Runtime/GameFrameX.Download.Runtime.asmdef.meta](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/GameFrameX.Download.Runtime.asmdef.meta)
- [Editor/GameFrameX.Download.Editor.asmdef.meta](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Editor/GameFrameX.Download.Editor.asmdef.meta)
- [Tests/GameFrameX.Download.Tests.asmdef.meta](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Tests/GameFrameX.Download.Tests.asmdef.meta)

If the project uses custom `.asmdef` files and you encounter "type not found / cannot access" errors after upgrading, check whether the custom assemblies correctly reference these three assemblies, or allow the dependency package assemblies in the `overrideReferences` of the custom asmdef.

## Verification

1. Open Unity Editor and confirm that `com.gameframex.unity.download` displays the target version in `Window > Package Manager`, and that the `Dependencies` section shows `com.gameframex.unity` and `com.gameframex.unity.event` as resolved.
2. No red compilation errors in the Console, especially errors related to the `GameFrameX` namespace or `WWWDownloadAgentHelper`.
3. After launching the project, invoke a download entry point once (e.g., the `DownloadManager` registration process) to confirm there are no runtime `MissingMethodException` or `TypeLoadException`.
4. If step 3 fails, go back to `Library/PackageCache` and check whether the actually cached version number matches `package.json`.
