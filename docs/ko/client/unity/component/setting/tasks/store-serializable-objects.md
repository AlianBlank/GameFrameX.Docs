# 직렬화 가능한 객체 설정 저장/로드

`SettingComponent`의 `GetObject<T>` 및 `SetObject<T>` 인터페이스를 사용하여 임의의 `[Serializable]`로 표시된 객체를 단일 문자열 키로 게임 설정 저장소에 읽고 쓸 수 있습니다.

## 사전 조건

- 프로젝트에 `GameFrameXSettingCroppingHelper`와 `SettingComponent`가 부착되어 있어야 합니다(후자는 `[RequireComponent]`를 통해 자동으로 전자를 요구함).
- 저장할 타입은 반드시 `[System.Serializable]`로 표시되어야 하며, 필드는 `UnityEngine.JsonUtility`에 의해 직렬화됩니다.
- `GameFrameworkEntry.GetModule<ISettingManager>()`를 통해 매니저 인스턴스를 가져오거나, `SettingComponent.Awake()` 완료 후에 저장 API를 호출합니다.

## 작업 단계

1. **직렬화 가능한 설정 클래스 정의**. 타입은 반드시 `[Serializable]`로 표시되어야 하며, 필드는 `public`이거나 `[SerializeField]`를 가져야 합니다:

   ```csharp
   using System;
   using UnityEngine;

   [Serializable]
   public class PlayerProfile
   {
       public string playerId;
       public int level;
       public bool vip;
       public Vector3 lastPosition;
   }
   ```

2. **설정 매니저 가져오기**. 컴포넌트 초기화가 완료되면 컴포넌트 인스턴스를 통해 직접 접근합니다:

   ```csharp
   using GameFrameX.Setting.Runtime;

   var settingComponent = UnityEngine.Object.FindObjectOfType<SettingComponent>();
   ISettingManager settingManager = settingComponent.GetComponent<SettingComponent>() != null
       ? GameFrameX.Runtime.GameFrameworkEntry.GetModule<ISettingManager>()
       : null;
   ```

   컴포넌트의 참조를 캐시한 후 필요할 때 직접 `settingComponent`의 `ISettingManager` 모듈을 읽을 수도 있습니다.

3. **객체 쓰기**. `SetObject<T>(string settingName, T value)`를 호출하면, 프레임워크 내부에서 `JsonUtility.ToJson`을 사용하여 문자열로 변환한 후 기본 저장소에 기록합니다:

   ```csharp
   var profile = new PlayerProfile
   {
       playerId = "p-1001",
       level = 12,
       vip = true,
       lastPosition = new Vector3(1.5f, 0f, -3.2f),
   };

   settingManager.SetObject("profile.current", profile);
   settingManager.Save();
   ```

   출처: [SettingManager.cs#L300-L320](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L300-L320)

4. **객체 읽기**. `GetObject<T>(string settingName)`을 통해 가져옵니다. 키가 없으면 `null`을 반환합니다(기본값을 가진 오버로드 `GetObject<T>(string settingName, T defaultValue)`은 없을 때 기본값을 반환함):

   ```csharp
   if (settingManager.HasSetting("profile.current"))
   {
       PlayerProfile loaded = settingManager.GetObject<PlayerProfile>("profile.current");
       Debug.Log($"다시 오신 것을 환영합니다,{loaded.playerId},레벨 {loaded.level}");
   }
   ```

5. **삭제 및 비우기**. 객체와 기본 타입은 동일한 저장소를 공유합니다:

   ```csharp
   settingManager.RemoveSetting("profile.current");  // 단일 키 제거
   settingManager.RemoveAllSettings();                // 전체 비우기
   ```

## 일반적인 변형

| 시나리오 | 사용법 | 설명 |
|------|------|------|
| 기본값 폴백 | `GetObject<PlayerProfile>("profile.current", defaultProfile)` | 키가 없을 때 전달된 기본값 객체를 반환 |
| 모든 키 나열 | `string[] keys = settingManager.GetAllSettingNames();` | 디버그 시 저장된 객체 이름을 빠르게 찾는 용도 |
| 크로스 미니게임 플랫폼 | `WeChatMiniGameSettingStorage` 등의 플랫폼 구현 사용 | `SettingStorageBackendFactory`를 통해 기본 저장소를 전환하며, API는 동일하게 유지됨 |
| 복잡한 중첩 구조 | `[Serializable] class Wrapper { public PlayerProfile profile; public Settings settings; }` | `JsonUtility`는 중첩된 `[Serializable]` 타입을 지원하지만, 딕셔너리/인터페이스는 지원하지 않음 |

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GameFrameworkException: Setting helper is invalid.` | `SettingComponent.Awake()`가 호출되기 전에 `GetObject`/`SetObject` 호출됨 | 컴포넌트 초기화가 완료될 때까지 기다리거나, 읽기/쓰기 로직을 비즈니스 모듈의 `Start`/`Awake` 단계에 배치 |
| `GameFrameworkException: Setting name is invalid.` | 전달된 `settingName`이 `null`이거나 빈 문자열임 | 호출 전에 `string.IsNullOrEmpty` 검증 수행 |
| 읽어온 필드가 모두 기본값임 | 필드가 `private`로 선언되었고 `[SerializeField]`가 추가되지 않음 | 필드에 `[SerializeField]`를 추가하거나 `public`으로 변경 |
| 딕셔너리/인터페이스 멤버가 사라짐 | `JsonUtility`는 `Dictionary`, 인터페이스, 속성을 지원하지 않음 | `List<T>` 또는 사용자 정의 직렬화 가능한 래퍼 클래스로 변경 |
| 수정 사항이 디스크에 저장되지 않음 | 쓰기 후 `Save()` 호출을 잊음 | 쓰기 완료 후 `settingManager.Save()` 호출; 프레임워크는 `Shutdown` 시 자동으로 `Save`를 수행함 |

## 배경 설명(선택)

`SettingManager`는 객체와 기본 타입을 모두 기본 `ISettingHelper`에 매핑하며, 후자는 `JsonUtility.ToJson`을 통해 문자열을 직렬화한 다음 `ISettingStorageBackend`(기본값은 `UnityPlayerPrefsSettingStorage`)에 위임하여 영구 저장합니다. 읽을 때는 역방향으로 `JsonUtility.FromJson<T>`를 사용하여 복원하므로, `JsonUtility`가 처리할 수 있는 객체만 저장 및 로드할 수 있습니다. 기본 저장소 백엔드 전환에 대한 자세한 내용은《사용자 정의 설정 저장소 백엔드》를 참조하세요.
