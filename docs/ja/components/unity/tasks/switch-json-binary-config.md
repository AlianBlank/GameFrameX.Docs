# JSON とバイナリ設定を切り替える方法

GameFrameX では、`Hotfix/Config/Generate/Tables/` 配下のテーブルデータクラス（LuBan ツールによって生成）は、デシリアライズの入口として `SimpleJSON.JSONNode` を使用します。実行時は `TablesComponent` が各テーブルを `ConfigComponent` に登録します。このページでは、「JSON 設定」と「バイナリ設定」という 2 つのソースを切り替える方法について説明します。

## 前提条件

- `Packages/manifest.json` で、GameFrameX scoped registry を介して `com.gameframex.unity.json.simplejson` を導入済みである（[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/README.zh-CN.md#L40-L80) を参照）。
- プロジェクトに `Assets/Hotfix/Config/Generate/Tables/TablesComponent.cs` が存在し、LuBan ツールによって `ItemConfig`、`AchievementConfig`、`SoundsConfig` などのテーブルクラスが生成済みである（[ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86) を参照）。
- `ConfigComponent` と `BaseDataTable<T>` を提供するランタイムフレームワークパッケージ `com.gameframex.unity.config` がインストール済みである（[link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28) を参照）。

## 操作手順

1. テーブルクラスのデシリアライズ用コンストラクターのシグネチャを確認します。ジェネレーターが生成するすべてのテーブルクラスには、JSON をテーブルオブジェクトにデシリアライズするために、`SimpleJSON.JSONNode` を受け取るコンストラクターが用意されています。

```csharp
// 出典:LuBan 生成コード
public ItemConfig(JSONNode _buf)
{
    { if(!_buf["id"].IsNumber) { throw new SerializationException(); }  Id = _buf["id"]; }
    { if(!_buf["Name"].IsString) { throw new SerializationException(); }  Name = _buf["Name"]; }
    // ... 残りのフィールドを省略
    PostInit();
}

public static ItemConfig DeserializeItemConfig(JSONNode _buf)
{
    return new Tables.ItemConfig(_buf);
}
```

出典: [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86)

2. `TablesComponent` で各テーブルを `ConfigComponent` に登録します。既定の実装では、すべてのテーブルを `TbXxxConfig.LoadAsync()` で非同期に読み込み、テーブル名をキーとして登録します（[TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L52-L70) を参照）。

```csharp
m_ConfigComponent.RemoveAllConfigs();
var loadTasks = new System.Collections.Generic.List<System.Threading.Tasks.Task>();
loadTasks.Add(TbItemConfig.LoadAsync());
m_ConfigComponent.Add(nameof(Tables.TbItemConfig), TbItemConfig);
```

3. JSON 設定ソースに切り替えます（既定の方式）。既存の生成コードを変更する必要はなく、データを JSON ファイルとしてエクスポートし、LuBan に読み込ませるだけです。ジェネレーターが生成する `DeserializeXxxConfig(JSONNode)` は JSON テキストを直接受け取るため、実行時に追加の変換は不要です。

4. バイナリ設定ソースに切り替えます（パフォーマンス優先の方式）。ホットアップデートパッケージまたは初期パッケージ内にバイナリデータしかない場合、まず読み込みの入口でバイナリストリームを `JSONNode` にデコードし、同じ `DeserializeXxxConfig` パスを経由します。これにより、下流のテーブルクラスを一切変更せずに済みます。例:

```csharp
using SimpleJSON;
using System.Text;

// bytes は YooAsset から取得したバイナリ設定パッケージを想定
JSONNode node = JSON.Parse(Encoding.UTF8.GetString(bytes));
var item = Tables.ItemConfig.DeserializeItemConfig(node);
```

重要な点:デシリアライズの入口は引き続き `DeserializeXxxConfig(JSONNode)` です。したがって、JSON とバイナリの切り替えは、「読み込み段階でデータ形式を `JSONNode` に正規化する」ことと等価です。テーブルクラス自体を再生成する必要はありません。

5. 実行時に `ConfigComponent.GetConfig<T>()` で設定を取得します。基盤となるデータが JSON であろうとバイナリであろうと、`TablesComponent.Add` 実行時にテーブル名が登録されていれば、 비즈니스 レイヤーの呼び出し方法は変わりません。

```csharp
var itemConfig = GameFrameX.Config.Runtime.ConfigComponent.Instance
    .GetConfig<Tables.ItemConfig>();
```

## 一般的なバリエーション

- **ホットアップデート段階でプラットフォーム別に切り替え**:Android プラットフォームの初期パッケージではパッケージサイズを小さくするためバイナリ圧縮パッケージを使用し、iOS プラットフォームまたは開発期間中は問題を調査しやすい JSON を使用します。`TablesComponent.Init` の前にプラットフォームに応じて読み込みソースを選択し、得られた `JSONNode` を `DeserializeXxxConfig` に渡すだけです。
- **ローカライズ設定**:生成済みのテーブル（例: `TbLocalization`）もまったく同じ登録フローを使用します。[TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L70) にある `m_ConfigComponent.Add(nameof(Local.TbLocalization), TbLocalization)` を参照してください。

## 一般的なエラー

- **生成されたテーブルクラスを直接変更する**:ジェネレーターは `Assets/Hotfix/Config/Generate/Tables/*.cs` を上書きします。カスタマイズロジックはすべて `partial` パーシャルクラスまたはビジネスレイヤーに配置してください。
- **フィールド名を変更した後に再生成していない**:`_buf["xxx"]` のフィールド名は大文字と小文字を区別します（`id` は小文字、`Name` は大文字、`description` は小文字に注意してください）。フィールドが一致しない場合、`SerializationException` が発生します（[ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L74) を参照）。
- **`m_ConfigComponent.Add` の呼び出しを忘れる**:`LoadAsync()` だけを呼び出してテーブル名を登録していない場合、`GetConfig<T>()` は null を返します。登録フローについては [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L69) を参照してください。
- **HybridCLR AOT によるトリミングの問題**:非ジェネリックの反射対象を追加した場合、`ConfigComponent`/`BaseDataTable<T>` が link.xml に保持されていることを確認してください（[link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28) を参照）。

## 背景（任意）

LuBan テーブルジェネレーターの生成物は、デシリアライズの入口として統一して `SimpleJSON.JSONNode` を使用します。この段階で、「データが JSON から来たものかバイナリから来たものか」という差異を読み込みレイヤーに集約します。`TablesComponent` は各テーブルを `ConfigComponent` に登録し、ビジネスレイヤーは `ConfigComponent.GetConfig<T>()` を通じてデータを統一的に取得します。そのため、データを切り替えるために利用側を変更する必要はありません。LuBan ジェネレーターと設定パイプライン全体の位置については、プロジェクト内の `Assets/Hotfix/Config/Generate/` を参照してください。
