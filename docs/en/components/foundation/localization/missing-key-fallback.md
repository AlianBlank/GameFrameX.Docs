# How to Handle Missing Keys and Culture Fallback

When `GetString` fails to find a key across all providers and the entire fallback chain, the framework returns the key itself, increments the missing-key count, and raises the `MissingKey` event. This page explains how to subscribe to the event to observe missing keys, adjust the fallback chain and default culture, and control the behavior when formatting fails.

## Prerequisites

- You have obtained the `ResourceManager` singleton via `LocalizationService`, or created your own with `new ResourceManager()`.
- You have referenced the namespaces `GameFrameX.Foundation.Localization` and `GameFrameX.Foundation.Localization.Core`.

## Steps

### 1. Subscribe to the `MissingKey` Event to Observe Missing Keys

```csharp
using GameFrameX.Foundation.Localization;
using GameFrameX.Foundation.Localization.Core;

LocalizationService.Manager.MissingKey += (sender, args) =>
{
    Console.WriteLine($"[Missing] key={args.Key}");
    Console.WriteLine($"  culture={args.Culture.Name}");
    Console.WriteLine($"  fallback={string.Join(" -> ", args.FallbackChain.Select(c => c.Name))}");
    Console.WriteLine($"  providers={string.Join(", ", args.ProviderNames)}");
};
```

The event argument comes from `MissingResourceEventArgs`, which contains the key, the requested culture, the fallback chain, and the assembly names of the providers that were queried. For where the event is defined and raised, see [`ResourceManager.cs`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L95-L97) (definition) and [`ResourceManager.cs#L281-L294`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L281-L294) (raise site).

Source: [GameFrameX.Foundation.Localization/Core/MissingResourceEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/MissingResourceEventArgs.cs#L8-L40)

### 2. Read the Missing-Key Count

```csharp
var manager = LocalizationService.Manager;
var stats = manager.GetStatistics(); // Contains MissingKeyCount, FormatFailureCount, per-key hit counts, etc.
```

### 3. Adjust the Fallback Chain and Default Culture

`ResourceManager` provides two related switches:

| Property | Default Value | Purpose |
|------|--------|------|
| `DefaultCulture` | `CultureInfo.InvariantCulture` | The final fallback culture, appended to the end of the fallback chain |
| `CultureFallbackEnabled` | `true` | When disabled, only the single culture specified by `CurrentUICulture` is queried |

Example of disabling fallback:

```csharp
LocalizationService.Manager.CultureFallbackEnabled = false;
```

The fallback chain generation logic is in [`ResourceManager.cs#L191-L221`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L191-L221): starting from the requested culture, it walks up the `Parent` chain, then appends `DefaultCulture` and `InvariantCulture` at the end.

### 4. Control the Behavior on Formatting Failure

When calling `FormatString(key, args)`, if the template does not match the arguments (e.g., a placeholder `{0}` is missing its argument), the behavior is determined by `FormatErrorBehavior`:

```csharp
using GameFrameX.Foundation.Localization.Core;

LocalizationService.Manager.FormatErrorBehavior = LocalizationFormatErrorBehavior.ReturnKey;
// LocalizationFormatErrorBehavior.Throw  — throws a FormatException
// LocalizationFormatErrorBehavior.ReturnTemplate — returns the unsubstituted template (default)
```

The enum is defined in [`LocalizationFormatErrorBehavior.cs`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/LocalizationFormatErrorBehavior.cs#L6-L22); the branching implementation is in [`ResourceManager.cs#L242-L259`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L242-L259).

## Common Variants

- **On-demand discovery of late-loaded GameFrameX assemblies**: To avoid missing localization resources for assemblies that are only JIT-loaded at runtime, the `ResourceManager` constructor already subscribes to `AppDomain.CurrentDomain.AssemblyLoad`. No manual action is required.
- **Only want the missing rate, no event callbacks**: Simply call `GetStatistics()` to read `MissingKeyCount`; there is no need to subscribe to the event.
- **Want an exception thrown when a match fails, for easier self-testing**: Set `FormatErrorBehavior` to `Throw` so that unit tests can assert that the "template + argument mismatch" path is actually hit.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The UI shows English key names (e.g., `Utility.Exceptions.TimestampOutOfRange`) | No match was found for the current UI culture + all parent cultures + `DefaultCulture` + `InvariantCulture`; and no `MissingKey` event subscription exists | Check that the resource DLLs are published with the package and confirm that `Localization.*.resources` are embedded; or set `DefaultCulture` explicitly |
| Still falls back to `en-US` after changing `DefaultCulture` | The assembly resources contain `en-US` entries, which take priority over `DefaultCulture` | This is expected behavior; to force `DefaultCulture`, disable `CultureFallbackEnabled` or remove the corresponding resources |
| A flood of `FormatException` logs reported temporarily | The number of placeholders does not match the number of arguments; by default the behavior is just `ReturnTemplate` without throwing | Set `FormatErrorBehavior` to `Throw` only while debugging, and restore `ReturnTemplate` in production |

## Background (Optional)

The fallback order is in [`ResourceManager.cs#L162-L184`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L162-L184): for each culture in the fallback chain, providers are queried in order; the first hit is returned. Provider exceptions are swallowed and printed to `Debug` to prevent a single bad resource from breaking the entire lookup. When no path yields a result, `RecordMissingKey` is called: it increments the count, aggregates by key, and then raises the event; ultimately the key name itself is returned to the caller as a fallback, ensuring the UI always receives a non-empty string.
