# Environment Preparation and Local Build

This section guides you through preparing the environment and tools needed to run the GameFrameX server locally, and completing the first build until you can see the server startup logs in the console.

## Prerequisites

| Tool/Component | Requirement | Notes |
|----------|------|------|
| .NET SDK | Only supports .NET 10.0 SDK | Not compatible with .NET 8/9 |
| Database | MongoDB 4.x and above | Can be installed locally or started via Docker |
| IDE | Visual Studio 2022 or JetBrains Rider | Any editor that recognizes .NET 10 will work |
| Optional | Docker | Used to quickly spin up MongoDB containers |
| Optional | Git | Clone the repository |

> The above version requirements come from the "Environment Requirements" section of the project README ([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L168-L172)). The badges also explicitly indicate `.NET-10.0` ([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L8)).

## Operation Steps

1. **Clone the repository and enter the server directory**

   ```bash
   git clone https://github.com/GameFrameX/GameFrameX.git
   cd GameFrameX/Server
   ```

2. **Restore NuGet dependencies**

   ```bash
   dotnet restore
   ```

   This will pull NuGet packages such as `Aspire.Hosting.*` in projects like `GameFrameX.AppHost` ([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L9-L12)).

3. **Build the solution**

   ```bash
   dotnet build
   ```

   The first build will compile all modules (including the hotfix layer `Hotfix` and persistence layer `Apps`), and the build output will be written to the `bin/` directory of each project.

4. **Start MongoDB**

   Choose one of the following methods:

   ```bash
   # Method 1: Local mongod
   mongod --dbpath /path/to/data

   # Method 2: Docker
   docker run -d -p 27017:27017 --name mongo mongo:8.2
   ```

   After a successful startup, MongoDB listens on `127.0.0.1:27017` by default.

5. **Run Launcher to start the server**

   Use command-line arguments to specify the service type and port (see the "Startup Parameters" reference page for details):

   ```bash
   dotnet run --project GameFrameX.Launcher -- \
       --ServerType=Game \
       --ServerId=1000 \
       --OuterPort=29100 \
       --HttpPort=28080 \
       --DataBaseUrl=mongodb://127.0.0.1:27017 \
       --DataBaseName=gameframex
   ```

   The above command corresponds to the "Minimal Startup" path provided in the README ([README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/README.zh-CN.md#L203-L210)).

6. **Verify startup**

   - Access `http://localhost:28080/game/api/health` via a browser or curl, and expect a healthy status to be returned.
   - Check the logs in the Launcher console to confirm that the Actor and network listener are ready.

## Common Variants

### One-Click Orchestration with Aspire AppHost

The repository root provides the `GameFrameX.AppHost` project, which uses the `.NET Aspire` SDK and references the MongoDB component ([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19)). Simply press F5 to run AppHost, and the Aspire Dashboard will automatically spin up MongoDB and Launcher:

```bash
dotnet run --project GameFrameX.AppHost
```

### Debugging in the IDE

In Rider/VS, set `GameFrameX.Launcher` as the startup project, paste the above command-line arguments into "Run Configuration → Program arguments", and you can debug the startup process with breakpoints.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `dotnet restore` reports `NETSDK1045` indicating .NET 10 is not installed | .NET 8/9 is installed but not .NET 10 | Install [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) and set it as the default SDK |
| Build reports `NU1605` / package conflict | Subprojects have pinned incompatible transitive dependencies | Delete `bin/` and `obj/`, then run `dotnet restore` again |
| Startup reports `MongoDB connection refused` | MongoDB is not started or the port is occupied | Confirm that `mongod` is running, or adjust `--DataBaseUrl` |
| Health check 404 / port unresponsive | `--HttpPort` is occupied or `--OuterPort` conflicts with an existing process | Change the port and restart |

## Background (Optional)

The project is based on .NET 10 SDK + .NET Aspire 13.4.6 for orchestrating local dependencies ([GameFrameX.AppHost.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.AppHost/GameFrameX.AppHost.csproj#L1-L19)). Launcher (`GameFrameX.Launcher`) is the process entry point that actually hosts the Actor and network listener, responsible for mapping command-line arguments to `StartupOptions`, and then driving `GameFrameX.StartUp` to start the host.

For the complete list of runtime configuration items, see "Startup Parameter Reference".
