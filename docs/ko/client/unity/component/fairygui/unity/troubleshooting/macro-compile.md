# 매크로 스위치가 적용되지 않거나 충돌할 때 어떻게 해야 하나요

이 패키지의 기능 매크로(`FAIRYGUI_TMPRO`, `FAIRYGUI_SPINE`, `FAIRYGUI_INPUT_SYSTEM`, `WECHAT_MINI_GAME`, `DOUYIN_MINI_GAME`)는 **Player Settings의 Scripting Define Symbols에서 수동으로 정의하는 것이 아니라**, `Fairygui.Runtime.asmdef`의 `versionDefines`가 해당 패키지의 설치 여부에 따라 자동으로 켜고 끕니다. 매크로가 "적용되지 않는" 경우 대부분은 해당 패키지가 설치되지 않았거나 패키지 이름이 일치하지 않거나, 전역 심볼에 수동으로 매크로를 추가했지만 의존성이 없어 충돌 오류가 발생하는 경우입니다.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| Input System 패키지를 사용하는데 터치/클릭이 반응하지 않음 | `FAIRYGUI_INPUT_SYSTEM`이 정의되지 않음(패키지 이름이 versionDefines와 일치하지 않거나 설치되지 않음), `Stage`가 이전 입력 분기를 사용함 | `com.unity.inputsystem`이 설치되어 있는지 확인, 아래 단계 1 참조 |
| TMP 관련 코드(밑줄, faceDilate 등)가 적용되지 않음 | `FAIRYGUI_TMPRO`가 정의되지 않음, `com.unity.textmeshpro`가 프로젝트에 없음 | TextMeshPro 패키지를 설치하고 재컴파일 트리거 |
| `GLoader3D`의 Spine 리소스 로드가 작동하지 않음 / `case PackageItemType.Spine` 분기가 컴파일에서 제거됨 | `FAIRYGUI_SPINE`이 정의되지 않음, 두 spine 패키지 이름 모두 일치하지 않음 | spine 패키지 설치(둘 중 하나만 일치하면 됨), 단계 1의 패키지 이름 목록 참조 |
| Player Settings에 수동으로 `FAIRYGUI_SPINE`을 추가한 후 컴파일 시 CS0246 오류 발생(`Spine.Unity.SkeletonDataAsset` 등을 찾을 수 없음) | 매크로가 강제로 켜졌지만 spine 의존성이 프로젝트에 없어 `UIPackage`/`GLoader3D`의 Spine 코드를 컴파일할 수 없음 | 수동으로 추가한 전역 매크로를 삭제하고, 해당 패키지를 설치하여 versionDefines가 자동으로 켜지도록 함 |
| 위챗/더우인 미니게임의 `GTextInputWeChat` / `GTextInputDouYin` 파일 전체가 컴파일되지 않음 | 조건은 `UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME`(더우인도 동일), 세 가지 조건이 모두 필요함 | WebGL 플랫폼으로 전환 + 해당 SDK 패키지 설치 + Wx/StarkWebGL 측에서 `ENABLE_*` 매크로 활성화 |
| Editor 어셈블리에서 `#if`가 항상 false임 | `Fairygui.Editor.asmdef`의 `versionDefines`가 비어 있어 에디터 어셈블리가 이 매크로들을 인식하지 못함 | Editor 코드에서 이 매크로에 의존하지 말 것; Runtime 어셈블리에서만 사용 |

## 매크로와 패키지 이름 대조표

매크로의 실제 출처는 [Fairygui.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Fairygui.Runtime.asmdef#L20-L51)의 `versionDefines`입니다:

| 매크로 | 트리거하는 패키지 | 소스 코드에서 제어하는 내용 |
|----|--------------|----------------|
| `FAIRYGUI_INPUT_SYSTEM` | `com.unity.inputsystem` | `Stage`의 입력 읽기(새/이전 입력 시스템 전환) |
| `FAIRYGUI_TMPRO` | `com.unity.textmeshpro` | `GTextField`의 TMP 렌더링 및 속성 직렬화 |
| `FAIRYGUI_SPINE` | `com.gameframex.unity.esotericsoftware.spine.spine-unity` 또는 `com.esotericsoftware.spine.spine-csharp`(둘 중 하나) | `GLoader3D`의 Spine 로드/업데이트/해제, `UIPackage`의 Spine 리소스 바인딩 |
| `WECHAT_MINI_GAME` | `com.qq.weixin.minigame` | `UNITY_WEBGL`, `ENABLE_WECHAT_MINI_GAME`과 함께 위챗 미니게임 입력창 활성화 |
| `DOUYIN_MINI_GAME` | `com.bytedance.starksdk` | `UNITY_WEBGL`, `ENABLE_DOUYIN_MINI_GAME`과 함께 더우인 미니게임 입력창 활성화 |

핵심 소스 코드 조각(매크로가 실제로 적용되는 위치):

```csharp
#if FAIRYGUI_INPUT_SYSTEM
using UnityEngine.InputSystem;
#endif
```

출처: [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L12)

```csharp
#if UNITY_WEBGL && WECHAT_MINI_GAME && ENABLE_WECHAT_MINI_GAME
using UnityEngine;
```

출처: [GTextInputWeChat.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputWeChat.cs#L1-L2)

```csharp
#if UNITY_WEBGL && DOUYIN_MINI_GAME && ENABLE_DOUYIN_MINI_GAME
```

출처: [GTextInputDouYin.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextInputDouYin.cs#L1-L1)

## 수정 단계

1. **먼저 패키지가 실제로 설치되어 있는지 확인하세요.** `Packages/manifest.json` 또는 Package Manager를 열고, 아래 목록의 패키지 이름이 **완전히 일치**하는지 확인하세요(versionDefines는 패키지 이름 기준으로 정확히 매칭되며 대소문자를 구분합니다):
   - `FAIRYGUI_SPINE` → `com.gameframex.unity.esotericsoftware.spine.spine-unity` **또는** `com.esotericsoftware.spine.spine-csharp`
   - `FAIRYGUI_TMPRO` → `com.unity.textmeshpro`
   - `FAIRYGUI_INPUT_SYSTEM` → `com.unity.inputsystem`
   - `WECHAT_MINI_GAME` → `com.qq.weixin.minigame`
   - `DOUYIN_MINI_GAME` → `com.bytedance.starksdk`
   참고: `Runtime/Fairygui.Runtime.asmdef`의 `references`에는 `spine-unity.Runtime`, `spine-unity`, `spine-csharp` 등이 동시에 참조되어 있어, 이 중 하나의 spine 패키지만 존재하면 매크로가 켜집니다. 모두 없다면 `FAIRYGUI_SPINE`도 함께 꺼 두는 것을 권장합니다(즉, 수동으로 매크로를 추가하지 마세요).
2. **수동으로 추가한 전역 매크로를 제거하세요.** *Edit → Project Settings → Player → Scripting Define Symbols*를 열고, 직접 작성한 `FAIRYGUI_*`, `WECHAT_MINI_GAME`, `DOUYIN_MINI_GAME`이 **없는지** 확인하세요. 이 매크로들은 asmdef 버전 제약으로 관리되며, 수동으로 하드코딩하면 패키지를 제거한 후에도 관련 코드가 계속 강제로 컴파일되어 CS0246 같은 타입을 찾을 수 없는 오류가 발생합니다.
3. **재컴파일을 트리거하세요.** 패키지를 설치/제거하면 Unity가 자동으로 새로 고칩니다. 그렇지 않으면 프로젝트 창에서 마우스 오른쪽 버튼으로 *Reimport All*을 실행하거나 Unity를 재시작하세요. versionDefines는 도메인 리로드 시 다시 평가됩니다.
4. **미니게임 플랫폼은 세 가지 조건을 확인하세요.** 위챗/더우인 입력창 클래스는 `UNITY_WEBGL && <平台宏> && ENABLE_*`가 동시에 성립할 때만 컴파일됩니다:
   - WebGL 빌드 플랫폼으로 전환(이때만 `UNITY_WEBGL`이 참이 됨);
   - 해당 플랫폼 매크로는 SDK 패키지에 의해 자동 정의됨(위 표 참조);
   - `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME`은 Wx / StarkWebGL 관련 패키지에서 제공합니다. 사용 중인 SDK 버전이 이 매크로를 제공하지 않는다면 해당 파일이 꺼져 있는 것이 정상이므로 수동으로 작성해 추가하지 마세요.
5. **Editor 코드에서 이 매크로에 의존하지 마세요.** [Fairygui.Editor.asmdef](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/Fairygui.Editor.asmdef#L15-L15)의 `versionDefines`는 빈 배열이므로, 에디터 어셈블리에서는 위 매크로들이 전혀 보이지 않습니다. 매크로로 분기해야 하는 코드는 반드시 `Runtime` 어셈블리에 넣어야 합니다.

## 검증

- 아무 Runtime 스크립트에 임시로 컴파일 시점 자가 점검 코드를 추가하세요(확인 후 삭제):

```csharp
#if FAIRYGUI_INPUT_SYSTEM
        Debug.Log("FAIRYGUI_INPUT_SYSTEM on");
#endif
#if FAIRYGUI_SPINE
        Debug.Log("FAIRYGUI_SPINE on");
#endif
```

- [Stage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/Stage.cs#L10-L11) 또는 [GTextField.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GTextField.cs#L45-L46)를 열어, IDE에서 `#if` 내부의 코드가 더 이상 회색으로 표시되지 않으면(비활성화 시 회색으로 표시됨) 매크로가 적용된 것입니다.
- 이전에 수동으로 작성한 매크로 때문에 발생한 CS0246 / CS0103 컴파일 오류가 전역 매크로를 삭제한 후 사라지고, 콘솔에 새로운 오류가 없는지 확인하세요.
