# Configuring Code Signing

Fill in fields such as Team ID, bundle ID, and signing identity in the `signing` node of the `XCodeConfig.json` configuration file. After Unity exports the iOS project, the post-build processing will automatically write these values into the build settings of the main Xcode Target (Unity-iPhone), so there is no need to manually change signing in Xcode.

## Prerequisites

- The Unity iOS platform can already produce builds normally (this component is executed during the PostProcessBuildPlayer stage).
- A `XCodeConfig.json` configuration file has been placed in the project; if not, you can create one with reference to [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json) or [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json) in the repository.
- Manual signing mode requires a Provisioning Profile to be created in advance in the Apple Developer portal, with the corresponding certificate installed on the local machine.

## Steps

1. Open (or create) the `XCodeConfig.json` in the project and add a `signing` node at the top level. The repository's built-in Demo looks like this:

```json
{
  "swiftBridging": true,
  "signing": {
    "teamId": "XXXXXXXXXX",
    "codeSignStyle": "Automatic",
    "provisioningProfileSpecifier": ""
  }
}
```

Source: [XCodeConfigDemo.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigDemo.json#L2-L9)

2. Fill in the fields inside `signing` according to the table below. All fields are optional; when left empty or missing, that build setting keeps the default value from the Unity export. The `signing` node only takes effect on the main project (Unity-iPhone Target).

| Field | Corresponding Build Setting | Description |
|------|--------------|------|
| `teamId` | `DEVELOPMENT_TEAM` | Apple Developer Team ID |
| `bundleId` | `PRODUCT_BUNDLE_IDENTIFIER` | App bundle ID |
| `codeSignIdentity` | `CODE_SIGN_IDENTITY` | Signing certificate identity |
| `codeSignStyle` | `CODE_SIGN_STYLE` | Signing style, `Automatic` or `Manual` |
| `provisioningProfileSpecifier` | `PROVISIONING_PROFILE_SPECIFIER` | Provisioning profile name (only required for Manual mode) |

The field meanings and mapping relationships come from the comments in the template file and the implementation of `SetSigning`:

```csharp
private static void SetSigning(PBXProject proj, string targetGuid, Hashtable signing)
{
    if (signing == null) return;

    var teamId = signing.Get<string>("teamId");
    if (!string.IsNullOrEmpty(teamId))
    {
        proj.SetBuildProperty(targetGuid, "DEVELOPMENT_TEAM", teamId);
    }

    var bundleId = signing.Get<string>("bundleId");
    if (!string.IsNullOrEmpty(bundleId))
    {
        proj.SetBuildProperty(targetGuid, "PRODUCT_BUNDLE_IDENTIFIER", bundleId);
    }
    // codeSignIdentity / codeSignStyle / provisioningProfileSpecifier are likewise only written when non-empty
}
```

Source: [PostProcessBuildHelper.Signing.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Signing.cs#L15-L48)

3. When using automatic signing, only `teamId` + `codeSignStyle: "Automatic"` is needed; Xcode will automatically manage certificates and provisioning profiles.

4. When using manual signing, complete the certificate and provisioning profile information:

```json
{
  "signing": {
    "teamId": "YourTeamID",
    "bundleId": "com.yourcompany.yourapp",
    "codeSignStyle": "Manual",
    "provisioningProfileSpecifier": "YourProfileName"
  }
}
```

The provisioning profile name must match the Profile name created in the Apple Developer portal. The template comments explicitly mark this field as "only required for Manual mode" (see [XCodeConfigTemplate.json](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XCodeConfigTemplate.json#L14-L15)).

5. Export the iOS project (or run a build). The post-processing reads and merges all `XCodeConfig.json` files, then calls the signing setup on the main Target:

```csharp
// Set the signing configuration (only set on the main project)
SetSigning(project, project.GetUnityMainTargetGuid(), finalConfig.Get<Hashtable>("signing"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L96-L97)

6. Verify: open the generated Xcode project, select the Unity-iPhone Target → Signing & Capabilities, and confirm that the Team, Bundle Identifier, and Provisioning Profile match the configuration; or run `xcodebuild -showBuildSettings | grep -E "DEVELOPMENT_TEAM|CODE_SIGN"` directly in a terminal to check.

## Common Variants

**Overriding signing configuration per channel.** The post-processing first merges all the common `XCodeConfig.json` files, then merges the channel-specific configuration `XCodeConfig.{channel}.json`; channel configurations have the highest priority and are merged last to override. Therefore, you can place one channel file for each channel (e.g., repackaged apps with different bundle IDs), containing only the differing fields inside `signing`:

```json
{
  "signing": {
    "bundleId": "com.yourcompany.app.channelA"
  }
}
```

For the channel file naming format and merge order, see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L76) and [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L80-L83).

**Configuring via ScriptableObject.** The repository also provides a `XcodeConfig` ScriptableObject (menu `XcodeConfig/Create Settings`), which can be used to maintain environment variables, Plist, Capabilities, and other configurations in the Inspector; see [XcodeConfig.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/XcodeConfig.cs#L10-L31). For signing-related JSON fields, the `signing` node still takes precedence.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Console outputs `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | No scannable `XCodeConfig.json` exists in the project | Place the configuration file according to the template, then export again |
| Console outputs `合并后的配置为空，跳过设置` | The configuration file exists but the JSON parsing result is empty | Check whether the JSON syntax is correct |
| `未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json` (Log only) | A channel is set but there is no corresponding channel file | This is informational; create the missing `XCodeConfig.{channel}.json` when differentiated configuration is needed |
| Team is still empty in Xcode after export | `teamId` is left empty or the field name is misspelled (fields are only written when non-empty) | Check the spelling and capitalization of the field names: `teamId`, `bundleId`, `codeSignIdentity`, `codeSignStyle`, `provisioningProfileSpecifier` |
| Manual signing reports a provisioning profile mismatch | `provisioningProfileSpecifier` does not match the actual Profile name, or the corresponding certificate is not installed on the local machine | Verify the Profile name and install the certificate |

The log messages quoted in the table above come from the configuration loading and merging flow; see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83).

## Background

Signing setup happens during Unity's PostProcessBuild stage: the component reads all `XCodeConfig.json` files in the project and merges them into a final configuration, parses the generated `Unity-iPhone.xcodeproj/project.pbxproj`, writes the signing-related build settings only on the main Target (UnityMainTarget), and then writes the project back to disk. All signing fields follow the "write only when non-empty" principle, so you can configure only the fields you need. In addition, `signing.bundleId` is also passed to the Capabilities handling to coordinate with entitlements settings (see [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L116-L119)).
