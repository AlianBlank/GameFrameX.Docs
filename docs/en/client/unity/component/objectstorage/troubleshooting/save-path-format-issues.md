# Save Path Settings and Path Separator Issues

When the object's storage path in the bucket does not match expectations after calling `SetSavePath` (extra or missing separators, incorrect platform slashes), the cause is usually an inconsistency between the format of the passed-in path and the `Path.DirectorySeparatorChar` handling logic.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| The last character of the save path is trimmed off unexpectedly (e.g., `mybucket/folder` becomes `mybucket/folde`) | The passed-in path ends with a backslash `\`, while the current platform separator is a forward slash `/` (common when writing Windows-style paths to Linux/Mac targets) | Replace `\` with the platform separator before calling, or assemble the path using `Path.Combine`/`Path.DirectorySeparatorChar` |
| The save path still ends with a separator (e.g., `mybucket/folder/`), and subsequent concatenation produces `mybucket/folder//file` | The caller passes a string without a trailing separator, but it was actually manually truncated before a previous call; or it was passed without a separator but concatenated onto an existing path that already had one | Re-pass the complete path each time before calling, to avoid accumulated truncation |
| Mixed use of `/` and `\` in the path, resulting in remote object paths like `mybucket/folder\file` | Directly concatenated Windows-style paths or hard-coded `/` in strings | Use `Path.DirectorySeparatorChar` consistently, and do not mix both slashes in remote paths |

## Fix Steps

### 1. Let `SetSavePath` Only Process Once

The logic of `SetSavePath` is: only when the passed-in string ends with `Path.DirectorySeparatorChar`, the last character is removed.

```csharp
public void SetSavePath(string savePath)
{
    if (savePath.EndsWith(Path.DirectorySeparatorChar.ToString()))
    {
        savePath = savePath.Substring(0, savePath.Length - 1);
    }

    BucketSavePath = savePath;
}
```

Source: [BaseObjectStorageUploadManager.cs#L12-L20](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs#L12-L20)

Therefore, if the trailing character of the passed-in path is not the current platform's `Path.DirectorySeparatorChar` (for example, on Windows passing a path ending with `\` while the actual runtime target platform is macOS/Linux), the trailing separator will not be removed, and subsequent concatenation will produce a remote path with extra separators.

### 2. Use Platform-Relative Separators

Replace hard-coded `/` or `\` with `Path.DirectorySeparatorChar`, or when passing paths on Windows, consistently end them with `\`. For example:

```csharp
string remote = $"mybucket{Path.DirectorySeparatorChar}folder";
manager.SetSavePath(remote);
```

### 3. Avoid Repeated Calls

Each `SetSavePath` overwrites `BucketSavePath` based on the entire passed-in value, so do not call it once and then manually concatenate; instead, pass the final path in a single call.

```csharp
manager.SetSavePath("mybucket/folder");
```

## Verification

1. After upload completes, log into the object storage console or call the List API to confirm that the object Key matches the expected path, without any extra `/` or `\`.
2. Use a known file to perform a single-file upload (`UploadFile`), and verify whether the remote Key equals `BucketSavePath` + the local relative path.
3. After switching platforms (switching the Editor platform to macOS/Linux and running again), re-set the path and confirm that separator handling is still correct.
