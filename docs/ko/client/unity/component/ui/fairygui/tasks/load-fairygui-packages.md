# FairyGUI 패키지 로드 및 언로드

`FairyGUIPackageComponent`가 제공하는 `AddPackageSync` / `AddPackageAsync`로 FairyGUI 패키지를 로드하고, `RemovePackage`로 패키지 이름 기준으로 언로드합니다. 화면을 열 때 `UIManager`가 자동으로 해당 패키지를 확인하고 로드하므로, 일반적으로 수동 개입이 필요 없습니다.

## 사전 조건

- 프로젝트에 `com.gameframex.unity.ui.fairygui`가 설치되어 있고, FairyGUI 에디터에서 패키지 설명 파일이 이미 게시되어 있어야 합니다(리소스 모드에서는 `{包名}_fui` 리소스, Resources 모드에서는 설명 파일 경로).
- GameFrameX의 `UIManager`를 통해 화면이 열려 있어야 합니다(자동 로드 흐름이 이에 의존합니다).

## 작업 단계

먼저 세 가지 진입 메서드를 살펴봅니다:

| 방법 | 시그니처 | 설명 |
|------|------|------|
| 동기 로드 | `void AddPackageSync(string descFilePath, bool isLoadAsset = true)` | 내부적으로 `UIPackage.AddPackage`를 호출하며, Resources 디렉터리에 있는 패키지에 적합 |
| 비동기 로드 | `Task<UIPackage> AddPackageAsync(string descFilePath, bool isLoadAsset = true)` | `await` 가능한 Task를 반환하며, Bundle 로드에 적합 |
| 언로드 | `void RemovePackage(string packageName)` | 패키지 이름(Name)으로 이미 로드된 딕셔너리에서 찾아 제거 |

1. **동기 로드가 필요한 경우**(예: 패키지가 Resources 디렉터리에 있고 Bundle을 거치지 않는 경우): `AddPackageSync`를 호출하고 설명 파일 경로를 전달합니다. `isLoadAsset`의 기본값은 `true`이며, 패키지 등록 후 `LoadAllAssets()`를 호출하여 전체 리소스를 미리 로드합니다.

```csharp
public void AddPackageSync(string descFilePath, bool isLoadAsset = true)
{
    if (!m_UILoadedPackages.TryGetValue(descFilePath, out var packageData))
    {
        var package = UIPackage.AddPackage(descFilePath);
        packageData = new UIPackageData(descFilePath, package.name, isLoadAsset);
        packageData.SetPackage(package);
        m_UILoadedPackages[descFilePath] = packageData;
        if (isLoadAsset)
        {
            packageData.Package.LoadAllAssets();
        }
    }
}
```

2. **비동기 로드가 필요한 경우**(패키지가 AssetBundle에 있는 경우): `await AddPackageAsync(descFilePath)`를 사용합니다. 동일한 `descFilePath`에 대한 중복 요청은 같은 `TaskCompletionSource`를 재사용하므로 이중으로 로드되지 않습니다.

```csharp

void Complete(UIPackage uiPackage)
{

    packageData = new UIPackageData(descFilePath, uiPackage.name, isLoadAsset);
    packageData.SetPackage(uiPackage);
    if (isLoadAsset)
    {
        packageData.Package.LoadAllAssets();
    }

    m_UILoadedPackages[descFilePath] = packageData;
    tcs.TrySetResult(packageData.Package);
}

m_UIPackageLoading[descFilePath] = tcs;
UIPackage.AddPackageAsync(descFilePath, Complete);
return tcs.Task;
```

## 일반적인 변형

- **패키지만 등록하고 전체 리소스를 즉시 로드하지 않기**: `AddPackageSync` / `AddPackageAsync`에 `isLoadAsset: false`를 전달하면 `LoadAllAssets()`를 건너뛰고, 리소스는 컴포넌트 인스턴스화 시점에 필요에 따라 로드됩니다. 동일한 패키지의 리소스 용량이 크고 이번에 일부 화면만 사용하는 시나리오에 적합합니다.
- **동일한 패키지 반복 로드**: `AddPackageAsync`는 내부적으로 `m_UIPackageLoading`으로 중복을 제거합니다. 동일한 `descFilePath`가 로드 중이면 이미 존재하는 `tcs.Task`를 바로 반환하고, 로드가 완료된 경우에는 `m_UILoadedPackages`를 통해 `Task.FromResult(packageData.Package)`를 반환합니다. 따라서 동일한 패키지를 여러 번 호출해도 안전하며, 중복 인스턴스화가 발생하지 않습니다.

## 자주 발생하는 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 화면 열기에 실패하고 콜백이 `LoadAssetFailureCallback`로 진행됨 | Bundle 분기에서 `{包名}_fui` 리소스 로드 실패(리소스가 Bundle에 포함되지 않았거나 경로 불일치) | FairyGUI 게시 산출물이 임포트되었는지, 그리고 `uiFormAssetPath`의 마지막 세그먼트가 패키지 이름과 일치하는지 확인하거나, 둘이 일치하지 않을 경우 디렉터리 아래에 `包名/包名_fui`가 존재하는지 확인 |
| `RemovePackage` 호출 후에도 패키지가 여전히 유효함 | 패키지 이름이 아니라 설명 파일 경로를 전달함 | `UIPackage.name`(즉, 로드 시 기록된 `Name`)으로 `RemovePackage` 호출 |
| Resources 디렉터리의 패키지가 계속 비동기로 로드되지 않음 | `assetPath`에 Bundle 디렉터리 이름(`Utility.Asset.Path.BundlesDirectoryName`)이 없으면 동기 분기가 강제 적용됨 | Resources 모드에서는 `AddPackageSync` 사용; 비동기가 필요하면 패키지를 Bundle 디렉터리로 이동 |
| 동일한 패키지가 여러 인스턴스로 로드됨 | `FairyGUIPackageComponent`를 우회하여 `UIPackage.AddPackage`를 직접 호출함 | `AddPackageSync` / `AddPackageAsync`로 통일하여 컴포넌트 내부 딕셔너리가 중복을 제거하도록 함 |

## 배경(선택 사항)

`FairyGUIPackageComponent`는 두 개의 딕셔너리로 패키지 상태를 유지합니다: `m_UIPackageLoading`(로드 중, `descFilePath → TaskCompletionSource`)과 `m_UILoadedPackages`(로드 완료, `descFilePath → UIPackageData`). 로드가 완료되면 후자에 기록하고 전자를 제거하며, 언로드 시에는 `Name`으로 `descFilePath`를 역조회한 뒤 FairyGUI의 `UIPackage` 레지스트리에서 제거합니다. GameFrameX 전체 UI 아키텍처와 각 컴포넌트의 역할 분담에 대해서는 《개요》 페이지를 참고하세요.
