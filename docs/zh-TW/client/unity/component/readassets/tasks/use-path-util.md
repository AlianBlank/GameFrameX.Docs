# 使用 PathUtil 進行路徑處理（正規化／串接／萬用字元）

`PathUtil` 是一個靜態工具類別，專門用於處理資源讀寫時所涉及的相對路徑：將帶有混合分隔符號、`.` 與 `..` 的路徑正規化、安全地將兩段路徑串接為以 `/` 分隔的字串，並將 `*`／`?` 萬用字元轉換為可直接用於比對的正規表示式。

## 前置條件

- 專案已引入 `com.gameframex.unity.readassets` 套件。
- 程式碼中已加入 `using GameFrameX.ReadAssets.Runtime;`。

## 常用方法總覽

| 方法 | 用途 |
|------|------|
| `IsDirectorySeparator(char c)` | 判斷字元是否為 `/` 或 `\` |
| `FixTrailingDirectorySeparators(string path)` | 將結尾連續出現的分隔符號合併為一個 |
| `CombineSlash(string a, string b)` | 使用 `/` 串接兩段路徑，避免分隔符號重複或遺漏 |
| `NormalizeRelativePath(string relative, bool forceTrailingSlash = false)` | 將相對路徑正規化為 `/a/b/c` 形式，處理 `.`、`..` 與混合分隔符號 |
| `IsValidCharacter(char c)` | 判斷字元是否為路徑中允許的字元 |
| `WildcardToRegex(string pattern)` | 將 `*`／`?` 萬用字元轉換為不區分大小寫的正規表示式 |

## 操作步驟

### 1. 串接兩段路徑

```csharp
using GameFrameX.ReadAssets.Runtime;

string full = PathUtil.CombineSlash("assets/config", "settings.json");
// 結果："assets/config/settings.json"

string root = PathUtil.CombineSlash("assets/config/", "sub/file.json");
// 結果："assets/config/sub/file.json"，不會出現重複的分隔符號

string abs = PathUtil.CombineSlash("assets/config", "/absolute/file.json");
// 當 b 以 '/' 開頭時，會直接回傳 b："absolute/file.json"
```

原始碼：[Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75)

### 2. 正規化相對路徑

`NormalizeRelativePath` 會將所有 `\` 轉換為 `/`、消除多餘的 `.`、解析 `..`，並驗證非法字元。預設不會保留結尾斜線；傳入 `forceTrailingSlash: true` 可強制保留。

```csharp
using GameFrameX.ReadAssets.Runtime;

// 混合分隔符號 → 統一為 /
string p1 = PathUtil.NormalizeRelativePath("a\\b\\c");
// 結果："a/b/c"

// 解析 . 與 ..
string p2 = PathUtil.NormalizeRelativePath("a/./b/../c");
// 結果："a/c"

// 強制保留結尾斜線
string p3 = PathUtil.NormalizeRelativePath("a/b/c", forceTrailingSlash: true);
// 結果："a/b/c/"

// 兩側皆以引號包裹的字串會被去除
string p4 = PathUtil.NormalizeRelativePath("\"a/b\"");
// 結果："a/b"
```

原始碼：[Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L170)

### 3. 使用萬用字元進行比對

`WildcardToRegex` 會將萬用字元轉換為正規表示式：`*` 對應任意字元序列、`?` 對應單一字元，且比對時不區分大小寫。

```csharp
using System.Text.RegularExpressions;
using GameFrameX.ReadAssets.Runtime;

Regex rx = PathUtil.WildcardToRegex("assets/configs/*.json");
bool match1 = rx.IsMatch("assets/configs/settings.json"); // true
bool match2 = rx.IsMatch("assets/configs/data.json");    // true
bool match3 = rx.IsMatch("assets/configs/sub/a.json");   // false（* 不會跨越 /）

Regex rx2 = PathUtil.WildcardToRegex("file_?.txt");
bool match4 = rx2.IsMatch("file_1.txt"); // true
bool match5 = rx2.IsMatch("file_12.txt"); // false
```

原始碼：[Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L183-L186)

### 4. 修正多餘的結尾斜線

```csharp
using GameFrameX.ReadAssets.Runtime;

string p1 = PathUtil.FixTrailingDirectorySeparators("assets//");
// 結果："assets/"：結尾兩個分隔符號會合併為一個

string p2 = PathUtil.FixTrailingDirectorySeparators("a\\b\\");
// 結果："a/b/"：保留最後一個分隔符號的類型
```

## 常見變化

- **保留引號原樣**：若路徑並非整段以雙引號包裹的字串（亦即僅開頭或結尾有 `"`），`NormalizeRelativePath` 便不會去除引號；引號同時也會被視為非法字元，將拋出 `Invalid characters`。
- **判斷字元是否有效**：`IsValidCharacter` 會拒絕 `"`、`<`、`>`、`|`、`*`、`?`、`:` 以及控制字元（ASCII < 32），可在自訂驗證邏輯中重複使用。
- **串接絕對路徑**：在 `CombineSlash` 中，若 `b` 以 `/` 開頭，會直接回傳 `b`（並移除開頭的 `/`），適用於「傳入路徑覆蓋前綴」的情境。

## 常見錯誤

| 症狀 | 原因 | 處理方式 |
|------|------|------|
| `ArgumentException: Empty or null` | `NormalizeRelativePath` 傳入了 `null` 或空字串 | 事先進行空值檢查 |
| `IOException: Invalid path: double dot error` | `..` 超出目前目錄（已位於根目錄） | 檢查路徑是否確實超出了根目錄 |
| `IOException: Invalid characters` | 路徑包含 `"`、`<`、`>`、`|`、`*`、`?`、`:` 或控制字元 | 使用 `IsValidCharacter` 過濾或修正輸入內容 |
| `ArgumentNullException: a / b` | `CombineSlash` 的任一參數為 `null` | 呼叫前先進行空值檢查 |

## 背景（選讀）

`PathUtil` 將資源讀取流程中最容易出錯的三個環節——分隔符號、`./..` 與萬用字元——整合進單一靜態類別：`NormalizeRelativePath` 使用狀態機解析路徑區段，確保輸出統一以 `/` 分隔且不含冗餘內容；`WildcardToRegex` 在替換 `*`／`?` 之前會先使用 `Regex.Escape` 做為防護進行逸出，避免路徑中的點被當作正規表示式的中繼字元。
