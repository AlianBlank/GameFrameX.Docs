# YooAsset パッチフローが失敗した場合の対処方法

YooAsset パッチフローが `ProcedurePatchInit` → `ProcedureUpdateStaticVersion` → `ProcedureUpdateManifest` → `ProcedureCreateDownloader` → `ProcedureDownloadWebFiles` → `ProcedurePatchDone` という一連のチェーンのうち任意のステップで異常を起こした場合、起動フローが止まったり、上流のフローへ戻されたりします。本ドキュメントでは、現象ごとに原因特定と修正方法を示します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `ProcedurePatchInit` で止まり、リソースパッケージの初期化に失敗する | `packageUrl` が空、または CDN に到達できない | `procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName)` が正しく書き込まれているか確認する。CDN にアクセスできることを確認する |
| `ProcedureUpdateStaticVersion` で止まり、バージョン不一致が表示される | リモートの静的バージョン番号がローカルと一致しない | 再ビルドしてリモートの静的バージョンファイルを再公開し、`StaticVersion.txt` がアップロード済みであることを確認する |
| `ProcedureUpdateManifest` がマニフェストエラーを報告する | リモートのマニフェストファイルが未公開、または署名エラー | リソースマニフェスト(`PackageManifest_{ver}.hash` / `.bytes`)を再公開し、YooAsset の暗号化キーを照合する |
| `ProcedureDownloadWebFiles` に入った後、進捗が動かない | ダウンローダーが空、または HTTP のレート制限 | `ProcedureCreateDownloader` の成果物に `VarObject` キー `"Downloader"` が含まれているか確認する。プロキシ/帯域を確認する |
| ダウンロード途中で `ProcedureCreateDownloader` に戻る | 単一ファイルのダウンロードに失敗し、`OnDownloadErrorCallback` が発火する | `AssetWebFileDownloadFailedEventArgs` の `FileName` と `ErrorInfo` を確認し、リモートに欠けているファイルを特定する |
| `ProcedureDownloadWebFiles` 完了後に `ProcedurePatchDone` に入らない | `downloader.Status != EOperationStatus.Succeed` | 直前の `OnDownloadError` ログを確認し、欠けているリソースを補完してから再度起動する |

## 修正手順

### 1. リソースパッケージの初期化失敗

`ProcedurePatchInit` は `GamePlayMode` に基づいて初期化ブランチを選択します。EditorSimulate/Offline は空の URL を使用し、その他のモードは `BuildInPackageName` から取得したパッケージアドレスを使用します。

```csharp
// ProcedurePatchInit.InitPatchAsync (Runtime/Procedures/Patch/ProcedurePatchInit.cs)
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode || assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, string.Empty, string.Empty, true);
    ChangeState<ProcedureUpdateStaticVersion>(procedureOwner);
    return;
}

var packageUrl = procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName);
await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, packageUrl.Value, packageUrl.Value, true);
```

ソース: [ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L33-L48)

修正操作：

1. デバッグモード(EditorSimulate)で再現し、CDN のネットワーク問題を切り分ける。
2. `ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState` で `packageUrl` が BlackBoard に書き込まれていることを確認する。
3. 実機モードで `StartupOptions.PlayMode` が `NormalizeAssetPlayMode` によって書き換えられていないか確認する(WebGL では `WebPlayMode` が強制され、非エディター環境では `EditorSimulateMode` が `HostPlayMode` に強制書き換えされる)。

### 2. 静的バージョン/マニフェスト更新の失敗

`ProcedureUpdateStaticVersion` と `ProcedureUpdateManifest` は YooAsset の組み込みフローによって駆動されます。よくある失敗原因：

- リモートに `StaticVersion.txt` だけがアップロードされ、`PackageManifest_*.bytes` がアップロードされていない。
- YooAsset の暗号化キーがエディターと一致せず、マニフェストの解析に失敗する。

修正操作：

1. ビルドツール(Builtin Build Pipeline)で再ビルドし、`ServerData/{Platform}` 一式をすべてアップロードする。`StaticVersion.txt` を忘れないこと。
2. エディター内の `YooAsset > AssetBundle Builder` でビルドした後、ローカルで HTTP サーバーを起動し、まず同じ `PlayMode` で一通り検証する。
3. マニフェストの暗号化をオフにするか、キーが一致していることを確認する。

### 3. ダウンローダーが空、またはダウンロードが中断する

`ProcedureDownloadWebFiles` は、`ProcedureCreateDownloader` が書き込んだ `VarObject` キー `"Downloader"`(`ResourceDownloaderOperation`)を直接消費し、コールバックを通じてエラーを監視します:

```csharp
// ProcedureDownloadWebFiles.BeginDownload (Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs)
var downloader = (ResourceDownloaderOperation)procedureOwner.GetData<VarObject>("Downloader").GetValue();

downloader.OnDownloadErrorCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetWebFileDownloadFailedEventArgs.Create(data.PackageName, data.FileName, data.ErrorInfo));
    ChangeState<ProcedureCreateDownloader>(procedureOwner);
};
downloader.OnDownloadProgressCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetDownloadProgressUpdateEventArgs.Create(
        data.PackageName, data.TotalDownloadCount, data.CurrentDownloadCount,
        data.TotalDownloadBytes, data.CurrentDownloadBytes));
    StartupProcedureUtility.SetDownloadProgress(
        StartupProcedureUtility.GetUIHandler(procedureOwner),
        data.CurrentDownloadBytes, data.TotalDownloadBytes);
};

downloader.BeginDownload();
yield return downloader;

if (downloader.Status == EOperationStatus.Succeed)
{
    ChangeState<ProcedurePatchDone>(procedureOwner);
}
```

ソース: [ProcedureDownloadWebFiles.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs#L36-L61)

修正操作：

1. `AssetWebFileDownloadFailedEventArgs` を購読して `FileName` と `ErrorInfo` を取得し、そのファイルが CDN 上に存在し、匿名でダウンロードできることを確認する。
2. HTTPS 証明書が信頼されていない場合、YooAsset は `ErrorInfo` に SSL エラーを報告します。YooAsset の設定で HostPlayMode に証明書を設定するか、HTTP にフォールバックしてください。
3. 単一ファイルの失敗は `ChangeState<ProcedureCreateDownloader>` によるリトライを引き起こすため、手動での介入は不要です。連続して失敗する場合は、`ClearCacheWhenDownloadFailure` のような YooAsset のスイッチでローカルキャッシュをクリアしてから、もう一度起動してください。

### 4. 起動後 `ProcedureGameLauncherState` の手前で止まる

`ProcedurePatchDone` はパッチ完了の最後のステップです。フローがここで止まる場合は:

- `ProcedureDownloadWebFiles` が `ChangeState<ProcedurePatchDone>` を正常に発火させたか確認する(`downloader.Status == EOperationStatus.Succeed` のときのみ遷移します)。
- `AssetPatchStatesChangeEventArgs` を購読しているカスタム Procedure がフローを止めていないか確認する。

## 検証

1. ゲームに再び入り、`ProcedureGetGlobalInfoState` → `ProcedurePatchDone` の間に `EPatchStates.DownloadWebFiles` イベントが報告されているか確認する。
2. エディターで `EditorSimulateMode` を使用し、`StartupOptions.GlobalInfoUrls` をローカルに向けて、パッチチェーンが正常に通ることを確認する。
3. 実機モードでは、YooAsset のサンドボックスディレクトリ(`Application.persistentDataPath/yoo/{PackageName}`)を開き、`PackageManifest_*.bytes` とリソースファイルがすべて配置済みであることを確認する。
4. 以上がすべて正常でもまだ止まる場合は、YooAsset のサンドボックスをクリアしてもう一度起動し、汚れたキャッシュによるマニフェスト検証失敗の可能性を排除する。
