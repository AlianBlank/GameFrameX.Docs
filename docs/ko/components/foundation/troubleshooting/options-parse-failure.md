# 명령줄 인수 파싱 실패 시 대처 방법

`OptionsBuilder` 또는 `CommandLineArgumentConverter`로 명령줄 인수를 파싱할 때 `ArgumentException`, `ArgumentAlreadyException`, 필수 옵션 검증 실패 또는 속성 값 타입이 맞지 않는 경우, 이 페이지의 진단 표를 통해 원인을 파악하고 수정하세요.

## 수정 단계

### 수정 1: args에서 null 요소 제거

`ConvertToStandardFormat`은 `arg == null`을 감지하면 즉시 `ArgumentException`을 던집니다:

```csharp
// CommandLineArgumentConverter.ConvertToStandardFormat
if (arg == null)
{
    throw new ArgumentException(LocalizationService.GetString(LocalizationKeys.Exceptions.ArgsCannotContainNull), nameof(args));
}
```

수정 방법: 호출 전에 필터링합니다:

```csharp
using GameFrameX.Foundation.Options;

var cleanArgs = (args ?? Array.Empty<string>())
    .Where(a => a != null)
    .ToArray();

var options = OptionsBuilder.Create<MyOptions>(cleanArgs);
```

> 출처: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L188-L194)

### 수정 2: 인수 처리 시 내부 예외 조사

`ConvertToStandardFormat`의 외부 `catch`는 임의의 비-`ArgumentException` 예외를 래핑하여 다시 던집니다:

```csharp
catch (Exception ex)
{
    throw new ArgumentException(
        LocalizationService.GetString(LocalizationKeys.Exceptions.ProcessingError, ex.Message),
        ex);
}
```

조사 단계:

1. 외부 `ArgumentException`을 잡고 `ex.InnerException`을 읽어 실제 스택 트레이스를 가져옵니다.
2. `InnerException`이 `ArgumentAlreadyException`이면 [수정 4](#수정-4매개변수-중복-또는-환경-변수와-명령줄-충돌-해결)로 이동합니다.
3. `InnerException`이 리플렉션/타입 변환 관련 (예: `InvalidCastException`, `FormatException`)인 경우, 일반적으로 명령줄 값의 문자열을 대상 속성 타입으로 변환할 수 없기 때문입니다—`MyOptions`의 해당 필드 타입과 전달된 값을 확인하세요.

> 출처: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L219-L227)

### 수정 3: 필수 매개변수 보완 또는 검증 건너뛰기

`OptionsBuilder.Create<TOptions>(args, skipValidation)`의 두 번째 매개변수는 필수 옵션 검증을 건너뛸지 여부를 제어합니다. 개발/디버그 단계 또는 프로세스를 종료하고 싶지 않은 시나리오에서는 다음과 같이 할 수 있습니다:

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.Create<MyOptions>(args, skipValidation: true);
```

비즈니스 로직상 건너뛸 수 없는 경우, "필수"로 표시된 모든 옵션이 전달되었는지 확인해야 합니다:

- `OptionsDebugger.PrintParsedOptions(opts)`를 사용하여 파싱 결과를 출력하고 속성이 예상 값인지 확인합니다.
- 환경 변수가 "암시적 소스"로 필드를 채우기 때문에 "명령줄이 전달되지 않은 것처럼 보여도" 실제로는 환경 변수가 적용 중일 수 있습니다.

> 출처: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L67)

### 수정 4: 매개변수 중복 또는 환경 변수와 명령줄 충돌 해결

동일한 이름의 키가 중복되면 `ArgumentAlreadyException`이 트리거됩니다:

```csharp
// ArgumentAlreadyException.Throw
public static void Throw(string message)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(message, nameof(message));
    throw new ArgumentAlreadyException(message);
}
```

수정 방법:

- 명령줄 측면: 중복 옵션을 병합하여 동일한 논리 키가 한 번만 나타나도록 합니다.
- 명령줄 vs 환경 변수: `OptionsBuilder.CreateFromArgsOnly<TOptions>(args)`를 사용하여 환경 변수를 명시적으로 비활성화하고 동일 이름 키가 덮어쓸 때 발생하는 논리적 혼란을 방지합니다:

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);
```

> 출처: [ArgumentAlreadyException.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ArgumentAlreadyException.cs#L69-L73), [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L103-L107)

### 수정 5: 불리언 매개변수 파싱 이상

`BoolArgumentFormat.Flag` (기본값) 모드에서는 `AttachValueIfPresent`가 불리언 리터럴로 인식된 다음 토큰을 건너뛰어 `--verbose true`와 같은 작성법에서 `true`가 `--verbose`의 값으로 잘못 처리되지 않도록 합니다:

```csharp
if (BoolFormat == BoolArgumentFormat.Flag && BooleanParser.IsBooleanValue(nextArg))
{
    return currentIndex + 1;
}
```

불리언 값을 실제로 문자열/컬렉션 타입 필드에 할당하려면 키-값 쌍 작성법을 사용하세요:

```bash
# 이렇게 하지 마세요 (불리언이 건너뜁니다)
myapp --mode true

# 이렇게 작성하세요
myapp --mode=true
```

> 출처: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L336-L344)

### 수정 6: 음수와 공백이 포함된 값 파싱 이상

`IsOptionToken`은 이미 음수에 대해 예외 처리를 합니다:

```csharp
private static bool IsOptionToken(string value)
{
    if (string.IsNullOrEmpty(value)) return false;
    if (!value.StartsWith("-")) return false;
    return !IsNegativeNumber(value);
}
```

하지만 `EnsurePrefixedKeys=true`일 때 "옵션이 아닌"으로 잘못 인식된 음수 토큰은 `NormalizeKey`에 의해 `--` 접두사가 추가됩니다:

```csharp
return EnsurePrefixedKeys ? "--" + arg : arg;
```

따라서 음수를 전달할 때는 명시적으로 접두사를 붙이거나 키-값 쌍을 사용하는 것이 좋습니다:

```bash
# 권장: 키-값 쌍은 변경되지 않습니다
myapp --offset=-3

# 비권장: -- -3으로 변경되거나 옵션으로 잘못 인식될 수 있음
myapp offset -3
```

공백이 포함된 문자열 값은 `AppendTokenWithQuotingIfNeeded`에 의해 자동으로 큰따옴표가 추가됩니다. `string[]`에서 파싱할 때는 이미 공백으로 분할되어 있으므로 추가 처리가 필요 없습니다. 단일 문자열에서 명령줄을 재구성할 때 (`ToCommandLineString`)는 자동으로 따옴표가 추가됩니다.

> 출처: [CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L347-L365)

## 검증

다음 순서로 문제가 해결되었는지 확인하세요:

1. `OptionsBuilder.CreateWithDebug<TOptions>(args)`를 사용하여 파싱 결과를 출력하고 각 속성의 최종 값을 확인합니다.
2. `OptionsBuilder.TryCreate<TOptions>(args, out var result, out var error)`로 실패 경로를 래핑합니다: 실패 시 기본 인스턴스를 반환하고 `error`를 통해 메시지를 받아 프로세스가 충돌하지 않습니다.
3. 디버거에서 `ex.InnerException`을 관찰하여 근본 원인이 식별되었는지 확인합니다 (특히 `ArgumentAlreadyException` 및 `FormatException`과 같은 하위 예외).

> 출처: [OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L149-L184)
