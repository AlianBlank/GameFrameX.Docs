# テナント/データ権限/ツリーエンティティの宣言方法

3つの専用属性 `[TenantTable]`、`[DataScope]`、`[TreeEntity]` を使用して「テナント分離、行レベルのデータ権限、ツリー構造」のメタデータをエンティティクラスに宣言することで、ORM層が自動的に認識し対応する機能を有効化します。リポジトリごとにフィルタ条件を手書きする必要はありません。

## 前提条件

- `GameFrameX.Foundation.Orm.Attribute` 名前空間を参照していること。
- エンティティフィールドは公開プロパティを使用すること（属性が読み取るのはプロパティ名）、フィールド名は属性パラメータと一致させること。

## 操作手順

### 1. テナント分離テーブルの宣言

クラスに `[TenantTable]` を追加し、エンティティに `TenantId` フィールドを含めます。ORMは現在のテナントコンテキストに従って自動的にフィルタと代入を注入します。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder
{
    public long Id { get; set; }
    public long TenantId { get; set; }   // 租户标识
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L83-L94)

### 2. 行レベルデータ権限の宣言

クラスに `[DataScope("锚点字段")]` を追加し、必要に応じて `DefaultScope` と `DepartmentField` を設定します。コンストラクタパラメータ `scopeField` は必須で、nullの場合は `ArgumentNullException` がスローされます。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[DataScope("CreatedUserId", DefaultScope = DataScope.Self)]
public class GameOrder
{
    public long Id { get; set; }
    public long CreatedUserId { get; set; }  // 数据范围锚点
    public string OrderNo { get; set; }
}

[DataScope("CreatedUserId",
    DefaultScope = DataScope.Department,
    DepartmentField = "CreatedDeptId")]
public class GamePlayer
{
    public long Id { get; set; }
    public long CreatedUserId { get; set; }
    public long CreatedDeptId { get; set; }
}
```

`DataScope` 列挙型は `All`、`Department`、`DepartmentAndChild`、`Self`、`Custom` をサポートします。Source: [DataScopeAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L111-L114) および列挙型定義 [DataScopeAttribute.cs#L123-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L123-L164)

### 3. ツリー構造エンティティの宣言

自己参照型のツリーエンティティに `[TreeEntity("ParentId")]` を追加し、オプションのプロパティで materialized path、階層、並べ替え、子ノードコレクションを記述します。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TreeEntity(
    ParentIdField = "ParentId",
    PathField = "Path",
    LevelField = "Level",
    SortField = "Sort",
    ChildrenField = "Children")]
public class SysDept
{
    public long Id { get; set; }
    public long? ParentId { get; set; }   // 父节点
    public string Path { get; set; }      // 物化路径，如 "1.5.12"
    public int Level { get; set; }        // 层级（根为 1）
    public int Sort { get; set; }         // 同级排序
    public string Name { get; set; }
    public List<SysDept> Children { get; set; }
}
```

コンストラクタパラメータ `parentIdField` は必須で、`null` を渡すと `ArgumentNullException` がスローされます。Source: [TreeEntityAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TreeEntityAttribute.cs#L124-L127)

## よくあるバリエーション

- **3つの属性の組み合わせ**：同一エンティティに複数の属性を同時に付与できます。例えばテナント業務テーブル + データ権限 + 部門ツリー構造のように、分離、権限、ツリークエリをそれぞれ制御します。
- **サブツリーフィールドのみマーク**：子コレクションの遅延ロードのみが必要な場合は、`ChildrenField` を単独で設定すればよく、その他の `PathField`/`LevelField`/`SortField` は `null` で構いません。
- **部門および下位部門**：`DepartmentField` を `DefaultScope = DataScope.DepartmentAndChild` と組み合わせて使用し、多層組織のデータ閲覧に適しています。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `[DataScope]` または `[TreeEntity]` が `ArgumentNullException` をスロー | コンストラクタパラメータに `null` 文字列を渡している | パラメータが `null` でないことを確認する（例：`[DataScope("CreatedUserId")]`） |
| データ範囲フィルタが有効にならない | アンカーフィールド名とエンティティプロパティ名が一致していない | `ScopeField` とプロパティ名を厳密に一致させる（大文字小文字を区別） |
| ツリークエリがテーブル全体を返す | `ParentIdField` が設定されていない、または `[TreeEntity]` の宣言が漏れている | `[TreeEntity("ParentId")]` で明示的に宣言する |
| `[TenantTable]` をシステムレベルテーブルに誤用 | テナントテーブルをグローバル共有テーブルとして記述している | テナント分離には `[TenantTable]` を使用。グローバル共有テーブルはシステムテーブル属性を参照（本ドキュメントの範囲外） |

## 背景

`[TenantTable]` は「各行が特定のテナントに属する」ことを示し、クエリ/挿入は自動的にテナント条件を含みます。`[DataScope]` はテナントベースに「ロール可視範囲」を重ね合わせます。`[TreeEntity]` はエンティティ内部の親子構造を記述し、再帰と materialized path 検索を容易にします。3つは直交して存在し、ビジネスの必要に応じて単独または組み合わせて使用できます。Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L36-L82)、[DataScopeAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/DataScopeAttribute.cs#L36-L82)、[TreeEntityAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TreeEntityAttribute.cs#L36-L58)
