# IL2CPP/AOT 빌드: 타입 스트리핑 방지

이 패키지는 IL2CPP/AOT 빌드 시 관리 코드 스트리핑(Managed Stripping)에 대비한 이중 방어 메커니즘을 내장하고 있습니다: 핵심 타입(`TimerComponent`, `TimerManager`, `ITimerManager`) 모두에 `[UnityEngine.Scripting.Preserve]`가 표시되어 있으며, 추가로 `GameFrameXTimerCroppingHelper` 스트리핑 헬퍼 클래스를 제공하여 해당 타입들을 명시적으로 참조합니다. 이 패키지를 정상적으로 추가한 후에는 별도의 추가 설정 없이도 타입이 스트리핑되지 않습니다.

## 사전 조건

- 프로젝트에 이 패키지(`com.gameframex.unity.timer`)가 설치되어 있어야 합니다.
- 대상 플랫폼이 Player Settings에서 IL2CPP 스크립팅 백엔드를 사용해야 합니다(이 메커니즘은 Mono 백엔드에 부작용이 없으므로 유지해도 됩니다).

## 작업 단계

### 1. 핵심 타입의 [Preserve] 표시가 온전한지 확인

패키지 내의 다음 세 파일을 열어 어트리뷰트가 제거되지 않았는지 확인합니다. 세 곳의 표시는 각각 인터페이스, 컴포넌트, 매니저 구현을 보호합니다:

```csharp
[UnityEngine.Scripting.Preserve]
public interface ITimerManager
```

출처: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L7-L9)

```csharp
[AddComponentMenu("GameFrameX/Timer")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-5000)]
```

출처: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L13-L15)

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class TimerManager : GameFrameworkModule, ITimerManager
```

출처: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L10-L12)

### 2. 스트리핑 헬퍼 클래스가 패키지와 함께 빌드되는지 확인

패키지 내의 `Runtime/GameFrameXTimerCroppingHelper.cs`는 스트리핑 방지의 2차 방어선입니다. 클래스와 메서드 모두 `[Preserve]`가 붙어 있으며, `Start()`에서 `typeof`로 모든 핵심 타입을 명시적으로 참조하여 스트리퍼에 정적 참조 루트를 남깁니다:

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Timer.Runtime
{
    [Preserve]
    public class GameFrameXTimerCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(TimerComponent);
            _ = typeof(ITimerManager);
            _ = typeof(TimerManager);
        }
    }
}
```

출처: [GameFrameXTimerCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/GameFrameXTimerCroppingHelper.cs#L1-L17)

이 파일은 패키지의 `Runtime` 디렉터리에 위치하며 패키지와 함께 자동으로 빌드에 포함되므로, 씬에 수동으로 부착할 필요가 없습니다.

### 3. 빌드 및 검증

1. IL2CPP 백엔드로 전환한 뒤 실제 플랫폼 빌드를 한 번 실행합니다(Play 모드 진입만으로는 스트리핑 문제를 검증할 수 없습니다).
2. 빌드 산출물에서 타입이 보존되었는지 확인합니다. 아래 방법 중 하나를 선택하세요:
   - 빌드 리포트/스트리핑 로그에서 `GameFrameX.Timer`를 검색하여 "stripped" 관련 제거 기록이 없는지 확인합니다;
   - 빌드된 패키지를 실행하여 타이머 컴포넌트가 정상적으로 초기화되고 `AddTimer`와 같은 호출을 수행하는지 확인합니다.

## 일반적인 변형 사례

- **프로젝트 내 리플렉션에 의존하는 다른 타입도 스트리핑되는 경우**: 위의 헬퍼 클래스 패턴을 자신의 프로젝트 코드에 그대로 복사하면 됩니다 — `[Preserve]`가 붙은 `MonoBehaviour`를 새로 만들고 `Start()`에서 `typeof`로 보존할 타입을 참조하십시오. 이는 Unity에서 일반적으로 통용되는 스트리핑 방지 기법이며, 이 패키지의 `GameFrameXTimerCroppingHelper`가 바로 해당 패턴의 바로 사용 가능한 예시입니다.
- **스트리핑 레벨을 높인 후 빌드가 실패하는 경우**: 프로젝트에서 High/Medium 스트리핑 레벨을 설정했더라도 `[Preserve]`와 `typeof` 참조 루트는 여전히 유효하므로, 타이머 타입을 위해 별도로 조정할 필요가 없습니다.

## 배경

IL2CPP의 관리 코드 스트리핑은 정적 분석상 "아무도 참조하지 않는" 타입을 제거합니다. 이 패키지의 타입은 주로 프레임워크 리플렉션과 자동 컴포넌트 메커니즘을 통해 로드되기 때문에 정적 참조 체인이 완전하지 않아 제거 가능한 타입으로 잘못 판단되기 쉽습니다. `[Preserve]` 어트리뷰트는 스트리퍼에게 보존 대상을 직접 알려주고, 스트리핑 헬퍼 클래스는 `typeof`를 통해 컴파일 시점에 확인 가능한 참조 루트를 제공합니다. 이 둘이 결합되어 어떠한 스트리핑 레벨에서도 타입이 보존되도록 보장합니다. README에서는 이를 "IL2CPP 안전 — 스트리핑 헬퍼 클래스가 AOT 빌드에서의 타입 스트리핑을 방지"로 분류하고 있습니다(참조: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L35)).
