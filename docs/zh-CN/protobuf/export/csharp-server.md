# 如何导出 C# 服务器代码

把仓库根目录下的 `.proto` 文件导出为可在服务器工程中直接使用的 C# 类（命名空间 `GameFrameX.Proto.Proto`），包含服务端专用消息（带 `-s` / `_s` 后缀的内部协议）、错误码与字段描述。

## 前置条件

- `.NET 10` 运行时（用于执行 `ProtoExport.dll`），或已安装 Docker。
- 已克隆本仓库到本地，仓库根目录即为 `--inputPath` 起点。
- 已准备好输出目录 `../Server/GameFrameX.Proto/Proto`，或自行修改为目标路径。

## 操作步骤

### 步骤 1：准备 ProtoExport 工具

任选一种获取方式：

- **CI 制品**：直接到仓库的 [latest Release](https://github.com/GameFrameX/GameFrameX.Protobuf/releases/latest) 下载预编译包，跳过构建。
- **Docker**：直接使用 `gameframex/gameframex-tools:latest` 镜像，无需本地工具链。
- **本地构建**：在 [GameFrameX.Tools](https://github.com/GameFrameX/GameFrameX.Tools) 仓库克隆并构建 `ProtoExport`（.NET 10），把产物放到本仓库的 `Tools/` 目录下。

### 步骤 2：运行导出脚本

仓库根目录已提供 `Proto2CsExport_Server.bat`（Windows）与 `Proto2CsExport_Server.sh`（Linux/macOS）。根据操作系统任选其一执行：

```bash
# Linux / macOS
./Proto2CsExport_Server.sh
```

```bat
:: Windows
Proto2CsExport_Server.bat
```

Source: [Proto2CsExport_Server.sh](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Server.sh#L1-L3)

两条脚本都调用同一条 `dotnet` 命令，参数含义如下：

| 参数 | 值 | 作用 |
|------|----|----|
| `--mode` | `csharp` | 指定目标语言为 C# |
| `--isServer` | `true` | 包含 `-s` / `_s` 后缀的服务端专用文件 |
| `--usingStatements` | `using System\|using ProtoBuf\|using System.Collections.Generic\|using GameFrameX.NetWork.Abstractions\|using GameFrameX.NetWork.Messages` | 注入生成文件的命名空间引用 |
| `--isGenerateDescription` | `true` | 把 `.proto` 中的字段注释写入 XML 文档 |
| `--inputPath` | `./` | 从当前目录读取所有 `.proto` 文件 |
| `--outputPath` | `../Server/GameFrameX.Proto/Proto` | 生成文件的输出根目录 |
| `--namespaceName` | `GameFrameX.Proto.Proto` | 生成类所属命名空间 |
| `--isGenerateErrorCode` | `true` | 根据 `option module` 同时生成错误码类 |

Source: [Proto2CsExport_Server.bat](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/Proto2CsExport_Server.bat#L1-L1)

### 步骤 3：使用 Docker 方式（可选）

如果不想本地装 .NET，可以挂载仓库目录运行镜像，把结果写回到挂载点：

```bash
docker run --rm \
  -v $(pwd):/protos \
  gameframex/gameframex-tools:latest \
  --mode csharp --isServer true \
  --usingStatements "using System|using ProtoBuf|using System.Collections.Generic|using GameFrameX.NetWork.Abstractions|using GameFrameX.NetWork.Messages" \
  --isGenerateDescription true \
  --inputPath /protos \
  --outputPath /protos/../Server/GameFrameX.Proto/Proto \
  --namespaceName GameFrameX.Proto.Proto \
  --isGenerateErrorCode true
```

Source: [README.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.md#L326-L339)

### 步骤 4：把生成代码接入服务器工程

1. 在 Visual Studio / Rider 中打开 `../Server/GameFrameX.Proto/Proto` 目录对应的工程。
2. 确认工程已引用 `ProtoBuf`、`GameFrameX.NetWork.Abstractions`、`GameFrameX.NetWork.Messages` 三个 NuGet 包，与脚本里的 `usingStatements` 对齐。
3. 编译工程，确保生成的所有 `*.cs` 文件无报错。

## 常见变体

- **只想导出客户端共用消息**：把 `--isServer` 改为 `false`，内部协议（`-s` / `_s` 文件）会被跳过，避免泄露到客户端。
- **修改输出位置**：调整 `--outputPath` 为服务器工程下的任意目录，并相应修改 `.csproj` 的 `Compile Include` 范围。
- **只想导 C++ 或 Go**：直接使用仓库提供的 `Proto2CppExport.sh/.bat`、`Proto2GoExport.bat` 等脚本。

## 常见错误

- **找不到 `Tools/ProtoExport.dll`**：尚未构建或下载 ProtoExport 工具。需要按步骤 1 选择 CI 制品、Docker 或本地构建其中一种补齐。
- **生成代码缺命名空间引用**：服务器工程未安装对应的 NuGet 包（`ProtoBuf`、`GameFrameX.NetWork.*`），在 `.csproj` 中补充后重新编译。
- **内部协议意外出现在客户端**：导出时 `--isServer` 误设为 `false` 或 `true`，以及 `.proto` 文件名后缀与 `--isServer` 不一致都会导致漏导或误导。
- **`option module` 与文件名编号不一致**：导出工具会校验 `_<四位数模块ID>_<域>.proto` 与 `option module = N;` 是否匹配，不一致会被拒绝。

## 背景（可选）

- 文件名以 `_` 前缀加 4 位模块号（`_<ModuleID:0000>_<Domain>.proto`）是路由键；负数表示内部协议，例如 `_-0120_Inner_Social.proto`。
- 服务端专用文件以 `-s` 或 `_s` 后缀区分，仅当 `--isServer true` 时被纳入，机制见 [README.md](https://github.com/GameFrameX/GameFrameX.Protobuf/blob/main/README.md#L303-L303)。
- 所有强约束（命名、字段编号、Reorder/Reuse 限制）的权威说明在 [GameFrameX.Tools README](https://github.com/GameFrameX/GameFrameX.Tools#readme)。
