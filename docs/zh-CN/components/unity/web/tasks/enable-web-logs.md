# 如何开启请求日志与使用 Inspector

在 Unity 菜单栏 `GameFrameX/Scripting Define Symbols` 下勾选「开启Web发送/接收日志打印」并等待脚本重编译后，`WebManager` 发出的每个 HTTP 请求与收到的响应都会以 `Log.Debug` 打印到 Console；选中挂载 `WebComponent` 的 GameObject 时，Inspector 会额外提供一个 0–120 秒的 `Timeout` 滑块用于调整请求超时。

## 前置条件

- 项目已安装 `com.gameframex.unity.web` 包并完成 Web 组件初始化。
- Console 面板的日志级别需允许显示 Debug 日志，否则开启宏后也不会看到输出。

## 操作步骤：开启请求日志

1. 打开 Unity 顶部菜单 `GameFrameX/Scripting Define Symbols`。
2. 根据需要点击以下菜单项（点击即生效，宏会写入当前 Build Target 的 Scripting Define Symbols）：

| 菜单项 | 作用 | 写入的宏 |
|------|------|---------|
| `Enable Web Send Logs(开启Web发送日志打印)` | 打印每个请求的 URL、Header、Form | `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` |
| `Disable Web Send Logs(关闭Web发送日志打印)` | 移除发送日志宏 | — |
| `Enable Web Receive Logs(开启Web接收日志打印)` | 打印每个响应的 URL、Header、Form、Content | `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` |
| `Disable Web Receive Logs(关闭Web接收日志打印)` | 移除接收日志宏 | — |

3. 等待 Unity 重新编译脚本（右下角转圈结束）。
4. 发起任意一次 Web 请求（如 `WebManager` 的 Get/Post 接口），Console 中即可看到形如 `Web Request: ...` 与 `Web Response: ...` 的 Debug 日志。

菜单项背后的实现就是对宏定义的增删：

```csharp
public static class WebLogScriptingDefineSymbols
{
    public const string EnableNetworkReceiveLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG";
    public const string EnableNetworkSendLogScriptingDefineSymbol = "ENABLE_GAMEFRAMEX_WEB_SEND_LOG";

    [MenuItem("GameFrameX/Scripting Define Symbols/Enable Web Send Logs(开启Web发送日志打印)", false, 451)]
    public static void EnableNetworkSendLogs()
    {
        ScriptingDefineSymbols.AddScriptingDefineSymbol(EnableNetworkSendLogScriptingDefineSymbol);
    }
}
```

## 操作步骤：使用 WebComponent Inspector

1. 在 Hierarchy 中选中挂载了 `WebComponent` 组件的 GameObject。
2. Inspector 面板底部会出现 `Timeout` 滑块，取值范围 0–120。
3. 拖动滑块：
   - **运行模式下（Play Mode）**：直接写入运行时对象 `t.Timeout`，立即对后续请求生效。
   - **非运行模式**：写入序列化属性 `m_Timeout`，随场景/ prefab 保存。

```csharp
[CustomEditor(typeof(WebComponent))]
internal sealed class WebComponentInspector : ComponentTypeComponentInspector
{
    public override void OnInspectorGUI()
    {
        base.OnInspectorGUI();
        serializedObject.Update();

        WebComponent t = (WebComponent)target;
        float timeout = EditorGUILayout.Slider("Timeout", m_Timeout.floatValue, 0f, 120f);
        if (timeout != m_Timeout.floatValue)
        {
            if (EditorApplication.isPlaying)
            {
                t.Timeout = timeout;
            }
            else
            {
                m_Timeout.floatValue = timeout;
            }
        }

        serializedObject.ApplyModifiedProperties();
    }
}
```

Source: [Editor/Inspector/WebComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Editor/Inspector/WebComponentInspector.cs#L7-L37)

> `WebComponentInspector` 继承自 `ComponentTypeComponentInspector`，因此 Inspector 同时保留了组件上 `IWebManager` 实现类型的下拉选择（`RefreshComponentTypeNames(typeof(IWebManager))`）。

## 常见变体

- **只看请求不看响应**：只点击 `Enable Web Send Logs`，两个宏相互独立，可任意组合。
- **手动管理宏**：也可以在 `Project Settings → Player → Scripting Define Symbols` 中直接填入 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG;ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG`，与菜单操作效果相同。
- **超时行为**：`Timeout` 滑块写入的值在 `WebManager` 中按秒（WebGL）或毫秒（非 WebGL）应用到请求上，见 `Runtime/Web/WebManager.cs` 中的 `unityWebRequest.timeout = (int)RequestTimeout.TotalSeconds;` 与 `request.Timeout = (int)RequestTimeout.TotalMilliseconds;`。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 点击菜单后 Console 仍无 `Web Request/Web Response` 日志 | Console 面板过滤掉了 Debug 级别日志 | 在 Console 右上角过滤器中勾选 Debug/Info |
| 日志只在部分平台出现 | 宏按 Build Target 分别生效，切换平台后需重新勾选 | 切换平台后重新执行菜单项 |
| 滑块改动后仍按旧超时发出请求 | 非 Play 模式下改动只写入 `m_Timeout`，需重新进入 Play 或保存场景 | 在 Play 模式下调整，或保存场景后重进 Play |
| 日志内容不含 `Form`/`Header` | 该请求本身未携带表单或请求头 | 检查调用方传入的 header/form 参数 |

## 验证

1. `GameFrameX/Scripting Define Symbols → Enable Web Send Logs` 后发起任意 GET 请求。
2. Console 出现 `Web Request: {URL} \n Header: ... \n Form: ...` 即说明发送日志已生效；收到响应后出现 `Web Response: ... \n Content: ...` 即说明接收日志已生效。
3. Play 模式下拖动 Inspector 的 `Timeout` 滑块并发起请求，观察日志中的请求耗时或超时异常是否随之变化。

## 背景

请求日志通过条件编译宏 `ENABLE_GAMEFRAMEX_WEB_SEND_LOG` / `ENABLE_GAMEFRAMEX_WEB_RECEIVE_LOG` 包裹 `Log.Debug` 调用，关闭宏时代码完全不进入编译产物，因此不会在正式包里留下性能开销；这也是菜单开关需要触发一次脚本重编译的原因。Inspector 侧的 `Timeout` 滑块则通过 `EditorGUILayout.Slider` 区分 Play 与非 Play 两种写入路径，保证运行时热调与场景序列化互不干扰。
