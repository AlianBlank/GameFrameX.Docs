# 日誌出現「fun is invalid.」或 ArgumentNullException 時怎麼辦

當你在呼叫 `MonoComponent` 的 `AddXxxListener` / `RemoveXxxListener` 系列方法時，在日誌中看到 `fun is invalid.` 字樣，或在測試程式碼中攔截到 `ArgumentNullException`,都表示**傳入了 `null` 回呼**。本頁提供快速定位與修復方法。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 執行日誌出現 `fun is invalid.` | 傳給 `AddXxxListener` / `RemoveXxxListener` 的 `Action` 為 `null`,內部 `Log.Fatal` 後直接 `return`,監聽未生效 | 給回呼變數指派一個真實方法或 `lambda`,再用 `?.` 判斷後再傳入 |
| 單元測試擲回 `ArgumentNullException` | 同一組介面的底層 `_monoManager` 會對 `null` 擲回例外，驗證了「傳 null 必然失敗」 | 與上一條同因，改為傳入非 null 回呼 |
| 啟動時出現 `Mono manager is invalid.` | `MonoComponent.Awake` 中 `_monoManager == null`,框架模組未註冊 | 見下方「修復步驟 2」 |
| 啟動時出現 `Event manager is invalid.` | `MonoComponent.Start` 中 `m_EventComponent == null`,事件元件未掛載 | 見下方「修復步驟 2」 |

## 修復步驟

### 1. 回呼為 null 時，先做空值檢查再傳入

`MonoComponent` 對每個 `Add*Listener` / `Remove*Listener` 都做了 `if (fun == null)` 校驗，觸發後只記錄 `Fatal` 日誌，不做任何訂閱/取消訂閱動作，也不會自動擲回例外 — 但該行為不會發生。

Source: [MonoComponent.cs#L147-L171](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L147-L171)

```csharp
public void AddLateUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddLateUpdateListener(fun);
}
```

修復方式：在傳入前先做 null 檢查，或使用 null 合併運算子提供一個預設空實作，例如：

```csharp
Action<float, float> onLate = null;
if (onLate != null)
{
    GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener(onLate);
}

// 或使用 lambda 佔位
GameEntry.GetComponent<MonoComponent>().AddLateUpdateListener((dt, fdt) => { /* 你的邏輯 */ });
```

### 2. 啟動階段出現「Mono manager is invalid.」或「Event manager is invalid.」

這兩條日誌來自 `MonoComponent` 自身的初始化階段，不是回呼為 null 所引起，而是框架模組/元件未就緒。

```csharp
protected override void Awake()
{
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}

private void Start()
{
    m_EventComponent = GameEntry.GetComponent<EventComponent>();
    if (m_EventComponent == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs#L52-L76](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L76)

修復方式：

1. 檢查場景中是否掛有實作 `IMonoManager` 的模組入口元件，或對應的組件是否已加入 Player Settings 的 `Scripting Define Symbols` / 組件定義中。
2. 在 GameFramework 的 `GameEntry` 預製物件上掛上 `EventComponent`,並確認其執行順序早於 `MonoComponent`。

### 3. 涉及的全部監聽器方法

以下方法在 `MonoComponent.cs` 中都遵循「傳 null → `fun is invalid.` 日誌 → return」的相同模式，排查時可一併檢查：

`AddUpdateListener` / `RemoveUpdateListener`、`AddFixedUpdateListener` / `RemoveFixedUpdateListener`、`AddLateUpdateListener` / `RemoveLateUpdateListener`、`AddDestroyListener` / `RemoveDestroyListener`、`AddOnApplicationFocusListener` / `RemoveOnApplicationFocusListener`、`AddOnApplicationPauseListener` / `RemoveOnApplicationPauseListener`、`AddOnApplicationQuitListener` / `RemoveOnApplicationQuitListener`、`AddDrawGizmosListener` / `RemoveDrawGizmosListener`。

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs)

## 驗證

修復後可用以下方式確認問題已解決：

1. **執行階段**：重新執行遊戲，觀察日誌不再出現 `fun is invalid.`、`Mono manager is invalid.`、`Event manager is invalid.`。
2. **回呼觸發**：在回呼內加上一條 `Debug.Log`,進入對應生命週期(如 `Update`、`LateUpdate`)後能看到日誌，表示訂閱成功。
3. **單元測試**：儲存庫 `Tests/UnitTests.cs` 中的 `Assert.Throws<ArgumentNullException>(() => _manager.AddUpdateListener(null))` 等測試案例用於驗證**傳 null 必然失敗**這項契約；業務程式碼中應傳入真實委派。
