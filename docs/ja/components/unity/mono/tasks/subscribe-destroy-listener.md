# OnDestroy をリッスンする方法

`MonoComponent.AddDestroyListener(Action)` でコールバックを登録すると、`MonoComponent` がアタッチされた `GameObject` が破棄されたときに通知を受け取ることができます。`MonoBehaviour` を継承して `OnDestroy()` をオーバーライドする必要はありません。

## 前提条件

- シーン内に `MonoComponent` がアタッチされた `GameObject` が存在する(コンポーネントメニュー:`GameFrameX/Mono`)。
- フレームワークが `IMonoManager` と `EventComponent` を初期化済みである(これらは `MonoComponent.Awake()` / `Start()` で自動的に取得されます)。

## 操作手順

1. 破棄をリッスンするスクリプト内で `MonoComponent` の参照を保持します(`GetComponent` または `FindObjectOfType` を使用)。
2. `AddDestroyListener` を呼び出し、引数なしの `Action` デリゲートを渡します。
3. コンポーネントを保持する `GameObject` が破棄されると、`MonoComponent.OnDestroy()` が `_monoManager.OnDestroy()` を呼び出し、登録したコールバックがトリガーされます。

```csharp
using System;
using GameFrameX.Mono.Runtime;
using UnityEngine;

public class DestroyWatcher : MonoBehaviour
{
    private MonoComponent _monoComponent;

    private void Awake()
    {
        _monoComponent = GetComponent<MonoComponent>();
    }

    private void OnEnable()
    {
        if (_monoComponent != null)
        {
            _monoComponent.AddDestroyListener(OnMonoDestroyed);
        }
    }

    private void OnDisable()
    {
        if (_monoComponent != null)
        {
            _monoComponent.RemoveDestroyListener(OnMonoDestroyed);
        }
    }

    private void OnMonoDestroyed()
    {
        Debug.Log("MonoComponent が破棄されました");
    }
}
```

Source: [MonoComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L97-L105)

リスナーを解除する対応するメソッド:

```csharp
public void RemoveDestroyListener(Action fun)
```

追加時と**同じデリゲートインスタンス**を渡せばバインドを解除できます。`null` を渡すと `fun is invalid.` の致命的ログが記録され、直接 return します。

Source: [IMonoManager.cs](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/IMonoManager.cs#L111-L121)

## よくあるバリエーション

- **手動で `Destroy(gameObject)` を呼び出す**:`MonoComponent` を保持する `GameObject` が破棄されればコールバックがトリガーされます。`Destroy` の呼び出しかシーンのアンロードかは区別されません。
- **シーン切り替えによるアンロード**:シーン切り替えによって `MonoComponent` が破棄された場合も同様にトリガーされ、シーンをまたぐキャッシュのクリーンアップに使用できます。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 登録時に `fun is invalid.` が出力される | 渡された `Action` が `null` である | メソッドグループまたはラムダ式を渡して null でないことを確認する |
| 破棄時にコールバックがトリガーされない | `_monoManager` が `null` である(コンポーネントの `Awake` がマネージャー初期化より早い) | `MonoComponent` が正常なフローで初期化されており、`Awake` が無効化されていないことを確認する |
| 同じコールバックが複数回トリガーされる | 同じデリゲートを複数回 `AddDestroyListener` で登録している | `OnEnable`/`OnDisable` のペアでライフサイクルを管理するか、重複登録の前に先に削除する |

## 背景(オプション)

`MonoComponent.OnDestroy()` は Unity のネイティブのライフサイクルフックであり、フレームワークはここで破棄イベントを `IMonoManager` に委譲します。そのため、業務側は各クラスが個別に `MonoBehaviour` を継承するのではなく、通常のイベントを購読するのと同じように破棄イベントを購読できます。
