# Initialization and Root Path Retrieval

This page explains how `BlankReadAssets` initializes and how it reads the `Root` path on different platforms. The framework automatically completes initialization on the first call to any API. In most cases, you do not need to call it manually. You only need to explicitly initialize when you need to obtain the root path before calling other APIs.

## Prerequisites

- `com.gameframex.unity.readassets` has been imported via Unity Package Manager.
- The `Assets/StreamingAssets/` directory exists in the project and the resources to be read have been placed in it.
- `using GameFrameX.ReadAssets.Runtime;` has been added.

## Steps

1. **Read the root path directly (auto-initialization)**. The framework internally uses `EnsureInitialized()` to guard lazy loading, automatically calling `Initialize()` on the first access of `Root`. On the Android platform, the implementation switches to `ApkImpl`; on Editor, Standalone, iOS, WebGL, and other platforms, `LooseFilesImpl` is used.

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    string root = BlankReadAssets.Root;
    UnityEngine.Debug.Log("StreamingAssets Root = " + root);
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L46-L54)

2. **Manually call parameterless initialization**. This overload uses `Application.dataPath` and `Application.streamingAssetsPath` as initialization parameters.

    ```csharp
    using GameFrameX.ReadAssets.Runtime;

    BlankReadAssets.Initialize();
    string root = BlankReadAssets.Root;
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L56-L61)

3. **Initialize with custom paths**. In testing or external resource directory scenarios, pass any `dataPath` and `streamingAssetsPath`.

    ```csharp
    BlankReadAssets.Initialize(
        dataPath: "/path/to/your/project",
        streamingAssetsPath: "/path/to/your/project/Assets/StreamingAssets");
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L63-L68)

4. **On non-Android platforms, `Root` is taken from `streamingAssetsPath`**. LooseFilesImpl converts the passed `streamingAssetsPath` to an absolute path, replaces backslashes, removes trailing slashes, and assigns it to `s_root`.

    ```csharp
    // Implementation in LooseFilesImpl.Initialize
    s_root = Path.GetFullPath(streamingAssetsPath).Replace('\\', '/').TrimEnd('/');
    ```

    Source: [BlankReadAssets.LooseFilesImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L17-L20)

5. **On the Android platform, `Root` is the APK path**. ApkImpl assigns `dataPath` to `s_root`, and falls back to `base.apk` when the content is not found; in the patch overlay scenario, `s_root` is the `pram-shadow-files` directory.

    ```csharp
    // Implementation in ApkImpl.Initialize
    s_root = dataPath;
    ```

    Source: [BlankReadAssets.ApkImpl.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L27-L56)

## Common Variations

- **Specify an external APK file for reading in Editor**. Only available under `UNITY_EDITOR`, it allows simulating the Android compressed APK path access in the editor.

    ```csharp
    BlankReadAssets.InitializeWithExternalApk("/path/to/your.apk");
    string root = BlankReadAssets.Root;
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

- **Use an external StreamingAssets directory in Editor**. Pairs with InitializeWithExternalApk; after disabling ApkMode, it still reads as a directory.

    ```csharp
    BlankReadAssets.InitializeWithExternalDirectories(
        dataPath: "/path/to/project",
        streamingAssetsPath: "/path/to/project/Assets/StreamingAssets");
    ```

    Source: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

- **Disable lazy loading and complete initialization early**. In some scenarios (such as checking file existence immediately after application startup), you may want to complete initialization before calling other APIs. You can explicitly call the parameterless `Initialize()`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Root` is an empty string or an abnormal path | On Android, reading was performed before waiting for the APK path, while ApkImpl's `s_root` depends on `dataPath` | Use `BlankReadAssets.Initialize()` to let the framework complete initialization with `Application.dataPath`, or first access any API to trigger `EnsureInitialized` |
| Traverse APK as a directory in Editor | `InitializeWithExternalApk` was not called | Explicitly call `InitializeWithExternalApk(apkPath)` to switch to ApkImpl |
| `ArgumentNullException` when using custom paths | `dataPath` or `streamingAssetsPath` was passed as null | Check the upstream configuration to avoid passing null values to `Initialize(string, string)` |

## Background (Optional)

The platform implementation switches at compile time via the `using BlankReadAssetsImpl = ...` static alias, ensuring that different target platforms call different `Initialize`. `EnsureInitialized()` and the `s_initialized` static flag together ensure that initialization occurs only once, and all subsequent read APIs will reuse the result from the first call. This is why `Root` can be safely accessed from anywhere.
