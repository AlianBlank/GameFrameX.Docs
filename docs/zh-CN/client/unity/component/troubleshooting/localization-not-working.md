# 本地化文本不生效怎么办

当你调用 `GameApp.Localization.GetString(key)` 或通过 FairyGUI/UI 组件查找多语言文本时,得到的仍是旧语言字符串、Key 本身、或空值,说明本地化数据没有按当前 `GameApp.Localization.Language` 装填。本页给出常见原因、对应的诊断方法和修复步骤。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 调用 `GetString(key)` 返回 Key 字符串本身 | 配置表 `Key` 字段为空或未生成 | 检查 `local_tblocalization.json` 中 `key` 列是否填写,并重新生成配置代码 |
| 切换 `Language` 后文本没变化 | 没有调用 `TranslateText()` 或调用顺序不对 | 在启动流程中,先 `Config.GetConfig<TbLocalization>()`,再调用 `TranslateText()` |
| `AddRawString` 时抛 `SerializationException` | 配置表 JSON 与生成的 `Localization` 字段不匹配 | 用 LuBan 重新导出 `local_tblocalization.json`,确认所有 15 个语言字段齐全 |
| 某些语言(例如泰语、印尼语)始终为空 | 该语言分支没有在 `switch` 中处理或表中字段为空 | 在 `local_tblocalization.json` 中补齐对应语言列,或在 `Localization.cs` 生成器中加分支 |
| 运行后所有本地化字符串都是英文 | `DefaultLanguage == English` 且 `Language` 不在 switch 分支中 | 确认 `GameApp.Localization.Language` 命中上方分支,或扩充 default 分支的回退逻辑 |

## 修复步骤

### 1. 确认启动流程调用了 `TranslateText`

`TranslateText()` 负责把 `TbLocalization` 表里的多语言字段按当前语言写入底层字典,跳过它将拿不到任何值。

```csharp
// 1. 删除源数据
GameApp.Localization.RemoveAllRawStrings();
// 2. 从配置表中加载数据
var tbLocalization = GameApp.Config.GetConfig<TbLocalization>();
// 3. 装填数据信息
tbLocalization.ForEach(localization =>
{
    if (localization.Key.IsNullOrWhiteSpace())
    {
        return;
    }
    // ... switch GameApp.Localization.Language ...
    GameApp.Localization.AddRawString(localization.Key, value);
});
```

注意:Key 为空白的行会直接 `return`,不会写入字典。请回到配置表里把 Key 补齐。

### 2. 核对当前语言在 switch 分支中

生成的 `Localization` 实体共 15 个语言字段,启动器按 `LocalizationCode` 枚举逐一匹配。漏匹配的语言会落到 `default`,只会在 `DefaultLanguage == English` 时拿到英文,其他情况保持 `string.Empty`。

```csharp
case LocalizationCode.ChineseSimplified:
    value = localization.ChineseSimplified;
    break;
case LocalizationCode.English:
    value = localization.English;
    break;
// ... ChineseTraditionalTW / HK / French / German / Italian / Japanese /
//     Korean / Portuguese* / Spanish* / Thai / Vietnamese / Russian / Indonesian
default:
{
    if (GameApp.Localization.DefaultLanguage == LocalizationCode.English)
    {
        value = localization.English;
    }
}
    break;
```

Source: [HotfixLauncher.cs#L82-L161](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L82-L161)

如果你的目标语言不在上面这些分支(例如新增了阿拉伯语),需要:

1. 在 LuBan 表 `local_tblocalization.json` 新增对应列。
2. 重新生成 `Localization.cs`,让新字段进入构造函数和 JSON 解析。
3. 在 `HotfixLauncher.TranslateText` 的 switch 里追加一个 `case`,把字段映射到 `value`。

### 3. 检查配置表与生成代码是否同步

生成的 `Localization` 构造函数对每个字段都做了非字符串校验,缺字段会让反序列化抛 `SerializationException`,导致整张表加载失败。

```csharp
public Localization(JSONNode _buf)
{
    { if(!_buf["key"].IsString) { throw new SerializationException(); }  Key = _buf["key"]; }
    { if(!_buf["ChineseSimplified"].IsString) { throw new SerializationException(); }  ChineseSimplified = _buf["ChineseSimplified"]; }
    { if(!_buf["English"].IsString) { throw new SerializationException(); }  English = _buf["English"]; }
    // ... 其他 12 种语言同构校验
}
```

Source: [Localization.cs#L38-L59](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Local/Localization.cs#L38-L59)

修复方式:用 LuBan 编辑器打开 `local_tblocalization.json`,确认 15 个语言字段名(ChineseSimplified、ChineseTraditional、English、Japanese、Korean、Thai、Indonesian、French、German、Russian、Italian、PortuguesePortugal、Spanish、Vietnamese)以及 `key` 列都存在且为字符串,然后重新生成代码。

### 4. 切换语言后强制刷新界面

单纯修改 `GameApp.Localization.Language` 不会重新读取配置,需要重新执行一次 `TranslateText()` 才会把字典里的旧值覆盖。常见做法是在切语言事件里调用该方法,然后向 UI 层广播 `OnLanguageChanged`。

## 验证

按以下顺序确认问题已解决:

1. 运行游戏,在控制台确认 `tbLocalization` 行数大于 0,且没有 `SerializationException`。
2. 在脚本里临时调用一次 `GameApp.Localization.GetString("你配置表里的某个 Key")`,断点确认返回的是当前 `Language` 对应的字符串,而不是 Key 本身。
3. 通过 FairyGUI/UGUI 的本地化组件打开一个用了 Key 的文本节点,运行时检查显示值。
4. 切换 `GameApp.Localization.Language = LocalizationCode.English`(或其他语言),重新调用 `TranslateText()`,再次确认 UI 文本随切换更新。

## 常见错误

- 直接改了 `local_tblocalization.json` 后忘了点 LuBan 的"生成代码",导致运行时代码里的字段名对不上,反序列化时静默失败。
- `TranslateText()` 写成在 `Awake` 调用,但此时 `GameApp.Config` 还没初始化完成,导致 `GetConfig<TbLocalization>()` 返回 null。
- 表里 Key 写了中文/带空格的字符串,虽然合法但调用方传 Key 时容易写错,建议统一用英文数字 + 下划线。
- 在 `default` 分支依赖英文兜底,但 `DefaultLanguage` 不是 `English`,会让部分语言显示为空字符串。
