# What to Do If UI Form Opening Fails

When the UI form does not display, throws an exception, or only triggers the failure callback after calling `UIManager.OpenUIForm` / `OpenUIFormAsync`, use this page to quickly locate the root cause and fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Error message in the `OpenUIFormFailureEventArgs` callback is `Resources.Load failed for path: <path>` | The asset path is not under `BundlesDirectoryName`, so Resources loading was used, but the path does not exist | See "Resources Path Asset Loading Failure" |
| `OpenUIFormFailureEventArgs` carries `assetHandle.LastError` | Bundle loading was used, but `LoadAssetAsync` returned a `Failed` status | See "Bundle Asset Loading Failure" |
| Exception `GameFrameworkException: Can not create UI form in UI form helper.` | `UGUIFormHelper.CreateUIForm` returned `null` | See "Logic Script Type Mismatch / Script Not Attached" |
| Exception `GameFrameworkException: Open UI form info is invalid.` | `openUIFormInfo` in `LoadAssetSuccess/FailureCallback` is null | See "Handle and Callback Lifecycle Exception" |
| Exception `ArgumentNullException` (thrown by `GameFrameworkGuard.NotNull`) | The passed-in `m_AssetManager` / `m_UIFormHelper` / `uiFormType` is null | See "Key Parameters Are null" |
| Console outputs `UI form instance type Xxx is invalid.` but no exception | The prefab does not have a logic script inheriting `IUIForm` attached | See "Logic Script Type Mismatch / Script Not Attached" |
| Multiple open requests appear in the asset pool reuse branch but only 1 is displayed | Singleton open mode (`UseSingletonOpenMode`) was hit, and subsequent requests were merged | See "Singleton Open Requests Merged" |

## Fix Steps

### Resources Path Asset Loading Failure

`InnerLoadUIFormAsync` uses `Resources.Load` when the path does not contain `BundlesDirectoryName`; if the asset cannot be found, it constructs a failure message and returns:

```csharp
if (uiFormAssetPath.IndexOf(Utility.Asset.Path.BundlesDirectoryName, StringComparison.OrdinalIgnoreCase) < 0)
{
    var original = (GameObject)Resources.Load(assetPath);
    if (original == null)
    {
        return LoadAssetFailureCallback(assetPath, $"Resources.Load failed for path: {assetPath}", openUIFormInfo);
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L144-L155](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L144-L155)

Fix:

1. Confirm that `uiFormAssetPath + uiFormType.Name` actually exists under any `Resources/` directory (case-sensitive).
2. If the asset is in an AssetBundle, change the path to include `BundlesDirectoryName` (default `Assets/AssetBundle/` or the game's custom subdirectory name) so that it goes through the bundle loading branch.
3. Register the failure callback to get the specific path:

```csharp
m_UIManager.OpenUIFormFailureEvent += (sender, args) =>
{
    Debug.LogError($"OpenFail [{args.UIFormAssetName}] {args.ErrorMessage}");
};
```

### Bundle Asset Loading Failure

The bundle branch goes through `AssetManager.LoadAssetAsync`; any status other than `Succeed` is treated as failure:

```csharp
var assetHandle = await m_AssetManager.LoadAssetAsync<UnityEngine.Object>(assetPath);
if (assetHandle.IsDone && assetHandle.Status == EOperationStatus.Succeed)
{
    ...
    return LoadAssetSuccessCallback(assetPath, gameObject, assetHandle.Progress, openUIFormInfo);
}
return LoadAssetFailureCallback(assetPath, assetHandle.LastError, openUIFormInfo);
```

Source: [Runtime/UIManager.Open.cs#L158-L169](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L158-L169)

Fix:

1. Check `assetHandle.LastError`; common causes: the AssetBundle manifest does not include this UI form, the build path and loading path are inconsistent, or Open is called before dependency bundles finish loading.
2. Confirm that `m_AssetManager` is initialized (see "Key Parameters Are null").
3. Wait until the startup process has finished parsing the AssetBundle manifest before issuing open requests.

### Logic Script Type Mismatch / Script Not Attached

`UGUIFormHelper.CreateUIForm` returns `null` when the instance is not a `GameObject` or does not have an `IUIForm` script attached, and the subsequent `InternalOpenUIForm` throws `Can not create UI form in UI form helper.`:

```csharp
var componentType = uiGameObject.GetOrAddComponent(uiFormType);
if (!(componentType is IUIForm uiForm))
{
    Log.Error($"UI form instance type {uiFormType} is invalid.");
    return null;
}
```

Source: [Runtime/UGUIFormHelper.cs#L91-L105](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L91-L105)

Fix:

1. Preload behavior when opening fails: Preload still creates the UI form and calls OnAwake, so make sure the logic script does not depend on uninitialized data.
2. Confirm that the Preload asset path is exactly the same as the open path; otherwise the two pools will point to different prefabs.

### Handle and Callback Lifecycle Exception

`LoadAssetSuccessCallback` / `LoadAssetFailureCallback` throw `Open UI form info is invalid.` when the received `openUIFormInfo` is null. This info is created by `UIFormLoadingObject.Create` in `InnerOpenUIFormAsync`:

```csharp
UIFormLoadingObject uiFormLoadingObject = UIFormLoadingObject.Create(uiFormAssetPath, uiFormAssetName, uiFormType, uiForm);
m_LoadingUIForms.Add(uiFormLoadingObject);
```

Source: [Runtime/UIManager.Open.cs#L108-L110](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L108-L110)

This exception usually occurs when a custom `UIFormHelper` does not construct `OpenUIFormInfo` as expected. Unless necessary, do not override the asset loading callbacks.

### Key Parameters Are null

`InnerOpenUIFormAsync` validates key fields with `GameFrameworkGuard.NotNull` at the entry point; if any of them is null, `ArgumentNullException` is thrown immediately:

```csharp
GameFrameworkGuard.NotNull(m_AssetManager, nameof(m_AssetManager));
GameFrameworkGuard.NotNull(m_UIFormHelper, nameof(m_UIFormHelper));
GameFrameworkGuard.NotNull(uiFormType, nameof(uiFormType));
```

Source: [Runtime/UIManager.Open.cs#L72-L74](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L72-L74)

Fix:

1. Before calling `OpenUIForm`, confirm that `UIManager` has completed initialization (the framework's `GameFramework` startup process).
2. The `Type` passed in by the caller must be non-null and implement `IUIForm`.
3. If `UIFormHelper` has been replaced, confirm that it has been registered with `UIManager`.

## Verification

After fixing, verify with a minimal test case:

```csharp
var form = await m_UIManager.OpenUIFormAsync<MyUIFomLogic>("Assets/AssetBundle/UI/");
if (form == null)
{
    Debug.LogError("Open failed, see OpenUIFormFailureEvent for details.");
}
```

Confirm:

- `OpenUIFormSuccessEvent` is triggered and `duration > 0` in the callback.
- The failure event no longer occurs, and the target UI form is visible in the UI camera.
- `IsLoadingUIForm(assetName)` returns `false`, and `GetUIForm(assetName)` returns a non-null instance.## Singleton Open Requests Merged

If the UI form class is marked as singleton open mode via `[OptionUIGroup]` or is determined by the framework to be in singleton open mode (`UseSingletonOpenMode`), repeated opens with the same asset name will return the existing instance and trigger `RefocusUIForm`, without creating a new instance:

```csharp
if (UseSingletonOpenMode(uiFormType))
{
    var openedUIForm = GetUIForm(uiFormAssetName);
    if (openedUIForm != null)
    {
        RefocusUIForm(openedUIForm, userData);
        return openedUIForm;
    }
    ...
}
```

Source: [Runtime/UIManager.Open.cs#L77-L97](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L77-L97)

Fix:

1. If you expect a new instance every time, disable the singleton flag for this mode (or manage the instance lifecycle yourself at the business layer).
2. Concurrent open requests are merged into the same loading Task, waiting for the same loading result:

```csharp
foreach (var loadingUIForm in m_LoadingUIForms)
{
    if (loadingUIForm.UIFormAssetPath == uiFormAssetPath &&
        loadingUIForm.UIFormAssetName == uiFormAssetName &&
        loadingUIForm.UIFormType == uiFormType)
    {
        return await loadingUIForm.Task;
    }
}
```

Source: [Runtime/UIManager.Open.cs#L88-L96](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L88-L96)

A concurrent second open will not trigger a new failure callback; only the first request's failure/success events will be triggered.
