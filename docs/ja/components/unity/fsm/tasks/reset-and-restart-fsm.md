# FSM のリセットと再起動方法

`Start<TState>()` で現在の状態をリセットし、指定された状態から FSM に再入場します。完全に破棄する必要がある場合は `Clear()` を使用します。フレームワークには `Reset` という名前のメソッドはありません。所谓"リセット"は再 `Start` によって実現し、"再起動"は破棄後に再構築することによって実現します。

## 前提条件

- `FsmManager` 経由で `IFsm<T>` を作成済みであり、現在の FSM 参照を取得できること。
- 状態集合 `FsmStateCount > 0` であり、ターゲットの状態类型が FSM に登録済みであること(`HasState<TState>()` で検証)。

## 操作手順

### 1. 初期状態にリセットする(一般的)

`Fsm<T>.Start` は `IsRunning == true` のとき `GameFrameworkException("FSM is running, can not start again.")` をスローするため([Fsm.cs#L272-L277](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L277))、"リセット"做法はまずプレースホルダー状態に遷移してから `Start` で初期状態を呼び出すことです。最もシンプルなプレースホルダー状態は同じ状態に再度遷移し、`OnLeave` をトリガーし、`CurrentStateTime` をゼロにし、それから `Start` を呼び出します。

```csharp
// owner は現在の所有者参照
void ResetToInitial(IFsm<MyOwner> fsm, MyOwner owner)
{
    if (fsm == null || fsm.IsDestroyed) return;

    // 等価状態に入って OnLeave をトリガーし、タイマーをゼロにする
    if (fsm.HasState<IdleState>())
    {
        fsm.Start<IdleState>();
        fsm.Start<IdleState>();
    }
}
```

参考: [Fsm.cs#L272-L288](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L272-L288)

### 2. 再起動(完全な破棄 + 再構築)

完全にリセットするには `Clear()` を呼び出してすべての状態、所有者、データをクリアし([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265))、その後 `FsmManager.CreateFsm` で再構築し `Start` します。

```csharp
// manager と owner を取得
var fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());

fsm.Start<IdleState>();
// ... その後、整体重置を行いたい場合:
GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>().DestroyFsm(fsm);
fsm = GameFrameX.Runtime.GameFrameX.GetModule<IFsmManager>()
    .CreateFsm<MyOwner>("BattleFsm", owner,
        new IdleState(),
        new MoveState(),
        new AttackState());
fsm.Start<IdleState>();
```

`Clear()` は内部でまず `m_CurrentState.OnLeave(this, true)` を呼び、次にすべての状態を遍历して `OnDestroy` を呼び、`m_CurrentState` を `null` に、`m_CurrentStateTime` を `0` に、`m_IsDestroyed` を `true` に設定します([Fsm.cs#L230-L265](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L230-L265))。

## よくあるバリエーション

- **任意の状態にリセットする**:ステップ 1 の `IdleState` をターゲットの `TState` に置き換えます。前提は `HasState<TState>()` が `true` を返すことです。
- **データのみリセットし、状態は変えない**:ユーザーデータ辞書をクリアし、現在の状態を維持して実行を続けます([Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs) の `m_Datas` のクリア方法を参照)。
- **Editor で状態を観察する**:Inspector は `fsm.CurrentStateName` と `CurrentStateTime` を表示します。状態名が `null` の場合は未実行を意味します([FsmComponentInspector.cs#L72](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Editor/Inspector/FsmComponentInspector.cs#L72))。

## よくあるエラー

| 現象 | 原因 | 修正 |
|------|------|------|
| `FSM is running, can not start again.` がスローされる | `IsRunning == true` のときに直接 `Start` を呼び出した | まず `IsRunning` を `false` にする(他の状態に切り替えてから戻す、または先に `Clear` してから `CreateFsm`) |
| `FSM 'X' can not start state 'Y' which is not exist.` がスローされる | `TState` が FSM に登録されていない | 呼び出し前に `fsm.HasState<TState>()` で検証し、欠落している場合は FSM を再構築する |
| `State type 'X' is invalid.` がスローされる | `FsmState<T>` 派生クラスでない `Type` を渡した | `stateType` が現在の FSM に対応する `FsmState<T>` を継承していることを確認する |
| `Start` 後に状態が変化しない | 同じ状態を重複して `Start` した際、"既に実行中" と判定される前の `Start` は既に有効になっている | 前述の「まず等価状態に切り替えてから戻す」方法で回避するか、新しい FSM を作成する |

## 背景(オプション)

`Start` は `m_CurrentState` を直接上書きして `OnEnter` を呼び出すため、"自身にリセット" は一見無効に見えますが、実際に有効なのは `OnLeave(..., true)` と `m_CurrentStateTime = 0f` の副作用です。完全な破棄は参照プール `ReferencePool` を使用し、`Fsm<T>.Clear` の実装を参照してください。
