# ログイン・広告・サードパーティ SDK(Apple/Facebook/Google/AppsFlyer/AdJust/GameAnalytics)の導入方法

このページの手順に従って対応するスクリプトマクロを有効にすると、`GameApp.XXX` を通じてログイン・広告・サードパーティ SDK コンポーネントを呼び出すことができ、各社ネイティブ SDK の実装詳細に直接依存する必要はありません。

## 前提条件

- プロジェクトに `com.gameframex.unity.entry`(本リポジトリ)および対応するサブパッケージがインストールされていること。例:`com.gameframex.unity.login.apple`、`com.gameframex.unity.login.facebook`、`com.gameframex.unity.login.google`、`com.gameframex.unity.appsflyer`、`com.gameframex.unity.adjust`、`com.gameframex.unity.gameanalytics` など。
- フレームワークはサブパッケージに応じて、Player Settings / `csc.rsp` / `asmdef` 内に対応するスクリプトマクロを宣言します。例:
  - `ENABLE_GAME_FRAME_X_APPLE_LOGIN`
  - `ENABLE_GAME_FRAME_X_FACEBOOK_LOGIN`
  - `ENABLE_GAME_FRAME_X_GOOGLE_LOGIN`
  - `ENABLE_GAME_FRAME_X_ADS`
  - `ENABLE_GAME_FRAME_X_ADJUST`
  - `ENABLE_GAME_FRAME_X_APPSFLYER`
  - `ENABLE_GAME_FRAME_X_GAMEANALYTICS`

  あるマクロが欠けている場合、対応するファイルはコンパイルに含まれず、`GameApp.XXX` プロパティも使用できません。

## 操作手順

### 1. フレームワークにコンポーネントを登録する

起動時に `GameEntry` が各 SDK コンポーネントオブジェクトを自動的に検出して登録するため、使用前に `GameApp.XXX` を呼び出すだけで済みます。以下は各 SDK のフレームワーク内における統一されたアクセス入口です(いずれも本リポジトリの `Runtime/GameApp.*.cs` にあります):

```csharp
// Apple ログイン
AppleLoginComponent apple = GameApp.AppleLogin;

// Facebook ログイン
FaceBookLoginComponent fb = GameApp.FaceBookLogin;

// Google ログイン
GoogleLoginComponent google = GameApp.GoogleLogin;

// 広告
var ads = GameApp.Advertisement;

// AdJust
AdJustComponent adjust = GameApp.AdJust;

// AppsFlyer
var appsFlyer = GameApp.AppsFlyer;

// GameAnalytics
var ga = GameApp.GameAnalytics;
```

> これらのプロパティは、初回アクセス時に `GameEntry.GetComponent<>()` によって遅延ロードされ、静的フィールドにキャッシュされます。

### 2. ログインコンポーネントを呼び出す

Apple ログインを例にすると、コンポーネントを取得した後、対応するメソッドを呼び出すだけでネイティブのログインフローを開始できます:

```csharp
var apple = GameApp.AppleLogin;
if (apple != null)
{
    apple.Login();
}
```

Facebook と Google のログインも呼び出し方法は同じです:

```csharp
GameApp.FaceBookLogin?.Login();
GameApp.GoogleLogin?.Login();
```

各 `LoginComponent` サブクラスは対応するサブパッケージによって提供されます。具体的なメソッド名(Login / Logout / コールバック登録など)はサブパッケージの API に従ってください。

Source: [Runtime/GameApp.AppleLogin.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.AppleLogin.cs#L36-L55)

### 3. 広告・アトリビューション / 分析コンポーネントを呼び出す

広告、AdJust、AppsFlyer、GameAnalytics も同じ入口からアクセスします。一般的なパターンは、ゲームの起動時またはメインシーンへの遷移後に初期化 / 送信インターフェースを一度呼び出し、その後はビジネス要件に応じて表示やイベントをトリガーするというものです。

```csharp
// 例:広告表示のトリガー(具体的なメソッドは AdvertisementComponent に準拠)
GameApp.Advertisement?.Show();

// 例:AdJust のイベント送信
GameApp.AdJust?.TrackEvent("login_success");

// 例:AppsFlyer のイベント送信
GameApp.AppsFlyer?.TrackEvent("af_login");

// 例:GameAnalytics のイベント送信
GameApp.GameAnalytics?.TrackEvent("login_success");
```

各コンポーネントの具体的な初期化パラメータ(App ID、Dev Key、コールバックなど)は、サブパッケージ内の `*Component.cs` で定義されています。対応するサブパッケージのドキュメントを参照してください。

## よくあるバリエーション

- **プラットフォーム別の条件コンパイル**:Apple ログインのマクロを iOS プラットフォームでのみ有効にする場合、`#if UNITY_IOS && ENABLE_GAME_FRAME_X_APPLE_LOGIN` で呼び出しを囲むことで、Android 側に Apple SDK が組み込まれなくなります。
- **選択的な有効化**:統合しない SDK は対応するサブパッケージをインストールしなければ、対応するマクロは定義されず、`GameApp.XXX` プロパティもアセンブリにコンパイルされません。
- **複数ログイン方式の共存**:Apple、Facebook、Google の3種類のログインを同時に有効にでき、プラットフォームや地域に応じて入口を動的に選択できます:

```csharp
ILogin login = Application.platform == RuntimePlatform.IPhonePlayer
    ? (ILogin)GameApp.AppleLogin
    : GameApp.GoogleLogin;
login?.Login();
```

## よくあるエラー

- **症状**:`GameApp.AppleLogin` のコンパイル時に「GameApp に AppleLogin の定義が含まれていない」というエラーが発生する。  
  **原因**:Apple ログインのサブパッケージがインストールされていない、または `ENABLE_GAME_FRAME_X_APPLE_LOGIN` マクロが宣言されていない。  
  **修正**:対応するサブパッケージをインストールし、フレームワークがスクリプトマクロを書き込んだ後、再コンパイルしてください。

- **症状**:`GameApp.AdJust` が `null` を返す、または実行時に NRE が発生する。  
  **原因**:`GameEntry` がこのコンポーネントを起動フローに組み込んでいない、または `AdJustComponent` サブパッケージがインポートされていない。  
  **修正**:サブパッケージが存在することを確認し、`GameEntry` の初期化チェーンに `AdJustComponent` を含めてください。

- **症状**:Facebook / Google ログインをタップしても反応がない。  
  **原因**:ネイティブ SDK の認証情報が未設定、またはコールバック Activity / URL Scheme が欠落している。  
  **修正**:Facebook / Google のコンソールとアプリ設定で OAuth 認証情報を整え、各サブパッケージの説明に従って Info.plist / AndroidManifest を設定してください。

## 背景(任意)

`GameApp` は `static partial class` であり、各 SDK に対応する `GameApp.XXX.cs` ファイルが1つずつ存在し、すべて `GameEntry.GetComponent<>()` の形式で遅延ロードされます。`#if ENABLE_GAME_FRAME_X_*` により、有効化されていない SDK はコンパイルにまったく含まれなくなり、依存関係の汚染を避けられると同時に、最終的なパッケージには実際に使用される SDK の実装のみが含まれるようになります。
