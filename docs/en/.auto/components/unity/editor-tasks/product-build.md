# Configuring the Product Build Process

Use the Unity top menu `GameFrameX/Build/*` to one-click export publishable versions for different platforms, and inject custom steps via hooks before and after the build (such as copying configurations, injecting the hot-update project, and cleaning up temporary directories).

## Prerequisites

- Unity Editor is installed, and the project has been opened through Unity Hub.
- Pre-select the scenes to package in `File → Build Settings`; otherwise `EditorBuildSettings.scenes` will be empty, and the output will not contain any scenes.
- When building for the Android platform, make sure the corresponding Build Support module is installed and that JDK / Android SDK are properly configured.
- If the hotfix process is needed, confirm that the `GameFrameX`-related HotFix editor extension is installed (the `HotFixEditorCompilerHelper.AddEditor()` command will be invoked automatically).
- The disk where the output directory resides must have write permission; the default output path for the Windows platform is shown below.

## Steps

### 1. Switch the Build Platform

Click `File → Build Settings` in the Unity top menu, select the target platform in the `Platform` list, and click `Switch Platform`. The menu item validates the current active build target; if the platform does not match, it will output `当前构建目标不是 XXX` (Current build target is not XXX) and return directly.

### 2. Select the Menu to Trigger the Build

Depending on the target platform, sequentially click `GameFrameX → Build → <Platform Name>` in the Unity top menu. Each menu item corresponds to a static method in `BuildProductHelper`.

| Menu Item | Corresponding Method | BuildTarget | Output Location |
|-----------|----------------------|-------------|-----------------|
| `GameFrameX/Build/Windows X64` | `BuildPlayerToWindows64BuildTarget` | `StandaloneWindows64` | `_buildPath/PlayerSettings.productName.exe` |
| `GameFrameX/Build/Windows X32` | `BuildPlayerToWindows32BuildTarget` | `StandaloneWindows` | Same as above (different directory name) |
| `GameFrameX/Build/Mac Os` | `BuildPlayerToMacBuildTarget` | `StandaloneOSX` | Same as above |
| `GameFrameX/Build/WebGL` | `BuildPlayerToWebGLBuildTarget` | `WebGL` | Determined by `BuildOutputPath()` |
| `GameFrameX/Build/Android(APK)` | `BuildPlayerToAndroid` | `Android` | `apkPath` (APK) |
| `GameFrameX/Build/Android(AAB)` | `BuildPlayerToAndroidAAB` | `Android` | `aabFilePath` (AAB) |
| `GameFrameX/Build/Android Studio Project` | `BuildPlayerToAndroidStudio` | `Android` | `_buildPath` (Gradle project directory) |
| `GameFrameX/Build/Android(Development)` | `BuildPlayerToAndroidDevelopment` | `Android` | Includes `AllowDebugging \| Development \| ConnectWithProfiler` |
| `GameFrameX/Build/iOS` | `BuildPlayerToIOS` | `iOS` | Xcode project directory |

Excerpt of the invocation entry:

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("当前构建目标不是 Windows");
        return;
    }
    try
    {
        HotFixEditorCompilerHelper.AddEditor();
        PlayerSettings.fullScreenMode = FullScreenMode.Windowed;
        PlayerSettings.defaultScreenHeight = 720;
        PlayerSettings.defaultScreenWidth = 1280;
        EditorUserBuildSettings.selectedStandaloneTarget = BuildTarget.StandaloneWindows64;
        UpdateBuildTime();
        AssetDatabase.SaveAssets();
        _buildPath = BuildOutputPath();
        var resultDirectory = _buildPath + Path.DirectorySeparatorChar;
        RunPreHookBuild();
        var buildReport = BuildPipeline.BuildPlayer(EditorBuildSettings.scenes, resultDirectory + PlayerSettings.productName + ".exe", EditorUserBuildSettings.activeBuildTarget, BuildOptions.None);
        // ...
    }
    finally
    {
        HotFixEditorCompilerHelper.RemoveEditor();
        RunPostHookBuild();
    }
}
```

### 3. Wait for the Build and View the Output

During the build process, `BuildPipeline.BuildPlayer` returns a `BuildReport`. The subsequent cleanup and copy steps only proceed when `summary.result == BuildResult.Succeeded`; otherwise, the method returns early. The console will print `Build Output Path:` followed by the final output path. The Android platform also automatically invokes `EditorUserBuildSettings.selectedStandaloneTarget` / the corresponding API to set signature-related parameters (see the source file [BuildProductHelper.cs](/src/Editor/BuildProduct/BuildProductHelper.cs#L360-L450)).

### 4. Integrate Pre/Post-Build Hooks (Optional)

If you need to automatically execute steps before and after each build, implement `IBuilderPreHookHandler` or `IBuilderPostHookHandler`. The framework will call all implementing classes before and after constructing the output, executing them in ascending order of `Priority`.

```csharp
using UnityEditor;
using GameFrameX.Editor;

public sealed class CopyExtraConfigsPreHook : IBuilderPreHookHandler
{
    // 数值越大,执行顺序越靠后
    public int Priority => 100;

    public void Run(BuildTarget target, string path)
    {
        // target: 当前 BuildPipeline.BuildPlayer 的目标平台
        // path:   框架准备好的输出路径(含可执行文件名或目录)
        // 这里写拷贝资源、改 PlayerSettings 等自定义逻辑
    }
}
```

## Common Variations

- **Custom output path**: Each method first assigns `_buildPath = BuildOutputPath()` (a static field in the class) before passing it to `BuildPipeline.BuildPlayer`. To rename or change the directory, modify `PlayerSettings.productName` or extend `BuildOutputPath()` before invoking the menu.
- **Embedding the hotfix process**: `HotFixEditorCompilerHelper.AddEditor()` is already called at the start of the `try` block in each platform entry, and `HotFixEditorCompilerHelper.RemoveEditor()` is called in `finally` to restore project files. If hotfix is not needed, this can be ignored.
- **Custom post-processing**: The Steamworks configuration file is automatically copied to the output directory through `CopySteamWorksConfig`; for new tools of the same kind, you can directly copy that call or register an `IBuilderPostHookHandler`.
- **Debug build**: The Android platform provides a dedicated `BuildPlayerToAndroidDevelopment` entry that produces an APK with `AllowDebugging | Development | ConnectWithProfiler` enabled, used for Profiler debugging.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| The menu prints `当前构建目标不是 XXX` and exits immediately after clicking | The current active platform does not match the `BuildTarget` corresponding to the menu item | First switch to the corresponding platform in `Build Settings`, then trigger the menu |
| The build output only contains the `*_Data` directory and is missing the executable | `EditorBuildSettings.scenes` is empty, or only some scenes are selected | Select all scenes to be packaged in `Build Settings → Scenes In Build` |
| The final directory contains an extra `BackUpThisFolder_ButDontShipItWithYourGame` folder | The framework proactively deletes this directory, but some files may remain due to being in use | Close the occupying process and retry; if you need to retain it, skip the corresponding cleanup logic in a custom hook |
| Hooks are not executed in the expected order | `Priority` is not set, or multiple implementations use the same value | Explicitly assign a value to each implementation; the larger the value, the later it is sorted |
| Unity still has leftover editor macros or editor project files after the build | `HotFixEditorCompilerHelper.RemoveEditor()` was not triggered | Do not manually skip the menu's `try/finally`; trigger via the menu rather than by copy |

## Background (Optional)

`BuildProductHelper` calls `RunPreHookBuild()` before `BuildPipeline.BuildPlayer`, and calls `RunPostHookBuild()` in `finally`. Both internally use reflection to scan all concrete types implementing the corresponding interface in `Utility.Assembly.GetTypes()`, then instantiate and invoke `Run(BuildTarget, string)` in ascending order of `Priority`. This mechanism allows user code to inject pre- and post-build logic without modifying the framework source.
