# 메인/백업 URL이 모두 소진되면 어떻게 해야 하나요

시작 프로세스가 글로벌 정보 인터페이스를 요청할 때 프레임워크는 `StartupOptions.GlobalInfoUrls` 메인/백업 URL 목록을 순서대로 순회하며, 각 URL 내부에서 `MaxAttemptsPerUrl`번 재시도합니다. 모든 URL이 실패하면 `UrlFailoverRunner`가 `UrlFailoverResult.Fail(...)`을 반환하고, 시작 프로세스는 `StartupResult.Fail`로 종료되며 `StartupFailedEventArgs`가 발생합니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 시작이 "글로벌 정보" 단계에서 멈추고 로그에 `URL list must contain at least one URL.`가 출력됨 | `GlobalInfoUrls`가 빈 배열임 | `StartupOptions` 에셋에 최소 1개의 URL을 입력 |
| 시작이 "글로벌 정보" 단계에서 멈추고 UI에 "모든 URL 소진됨 / All URLs exhausted" 안내가 표시됨 | 메인/백업 URL이 모두 접근 불가하지만 설정 자체는 유효함 | URL, 파라미터, 재시도 상한을 순서대로 점검(아래 해결 단계 참조) |
| 로그에 `ArgumentException: Max attempts per URL must be greater than zero.` 발생 | `MaxAttemptsPerUrl`이 0 또는 음수로 설정됨 | `MaxAttemptsPerUrl`을 ≥1로 변경 |
| 로그에 `ArgumentException: Retry delay must be zero or greater.` 발생 | `RetryDelayMs`가 음수로 설정됨 | `RetryDelayMs`를 ≥0으로 변경 |
| 단일 URL이 첫 시도에서 바로 200을 반환하는데도 실패로 잘못 판정됨 | `attempt` 델리게이트가 `UrlAttemptResult.Success`를 올바르게 구현하지 않음 | `IStartupHttpParamsProvider`가 반환하는 HTTP 상태 코드 판단 로직 확인 |

## 해결 단계

### 1. `GlobalInfoUrls`에 최소 1개 이상의 설정이 있는지 확인

`UrlFailoverRunner.ExecuteAsync`는 빈 목록에 대해 즉시 `ArgumentException("URL list must contain at least one URL.", nameof(urls))`를 던집니다. 프로젝트의 `StartupOptions.asset`를 열고 `Network → Global Info URLs`에 메인/백업 URL을 입력합니다(메인이 앞, 백업이 뒤):

```csharp
public string[] GlobalInfoUrls = new string[0]; // 시작 전 최소 1개 항목이 반드시 필요
```

출처: [StartupOptions.cs#L22-L23](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### 2. 각 URL 자체가 접근 가능한지 확인

`GlobalInfoUrls`의 주소를 순서대로 하나씩 접근하여 2xx 응답이 반환되는지 확인합니다:

1. 브라우저 또는 `curl`로 URL이 JSON을 반환하는지 테스트합니다.
2. 프로토콜(https / http), 포트, 경로의 철자가 정확한지 확인합니다.
3. 서버가 배포되어 있으며 CDN, 방화벽, 교차 출처(CORS) 및 인증 헤더가 허용되어 있는지 확인합니다.
4. `IStartupHttpParamsProvider`를 사용해 공통 파라미터를 주입하는 경우, Provider가 401/403을 반환하지 않는지 확인합니다.

### 3. 단일 URL의 재시도 상한 높이기

각 URL은 내부에서 기본 3회(초기 시도 포함) 재시도하며, 순간적인 지터를 허용하도록 `StartupOptions` 에셋에서 값을 늘릴 수 있습니다:

```csharp
[Tooltip("每个 URL 内部的总尝试次数上限（含初次）。")]
public int MaxAttemptsPerUrl = 3;
```

상한은 반드시 ≥1이어야 하며, 그렇지 않으면 파라미터 검증 예외가 트리거됩니다:

```csharp
if (maxAttemptsPerUrl < 1)
{
    throw new ArgumentException(
        "Max attempts per URL must be greater than zero.",
        nameof(maxAttemptsPerUrl));
}
```

출처: [UrlFailoverRunner.cs#L27-L30](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L27-L30)

### 4. 재시도 간격 조정

`RetryDelayMs`는 두 번의 재시도 사이의 대기 시간(밀리초)을 제어하며 기본값은 3000ms입니다. 순간적인 장애에는 적절히 늘리고, 긴 경로나 불안정한 네트워크 환경에서는 총 소요 시간을 줄이기 위해 줄일 수 있습니다. 값은 반드시 ≥0이어야 합니다:

```csharp
if (retryDelayMs < 0)
{
    throw new ArgumentException(
        "Retry delay must be zero or greater.",
        nameof(retryDelayMs));
}
```

출처: [UrlFailoverRunner.cs#L32-L35](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L32-L35)

### 5. UI가 사용자의 재시도를 유도하도록 하기

`UrlFailoverRunner`는 `onProgress(url, attempt, max)` 콜백을 통해 상위 계층에 현재 진행 상황을 알립니다. 연동 측에서는 일반적으로 이 진행 정보를 시작 UI의 "재시도" 버튼으로 전달합니다. 사용자는 프로세스를 종료하지 않고도 다시 트리거할 수 있으며, 보통 "백업 URL로 전환" 안내와 함께 사용됩니다.

```csharp
public static UniTask<UrlFailoverResult> ExecuteAsync(
    IReadOnlyList<string> urls,
    int maxAttemptsPerUrl,
    int retryDelayMs,
    Func<string, UniTask<UrlAttemptResult>> attempt,
    Action<string, int, int> onProgress = null,
    CancellationToken cancellationToken = default)
```

## 검증

1. 일부러 `GlobalInfoUrls`를 비워 두고 게임을 실행하면 `ArgumentException: URL list must contain at least one URL.`가 표시되어야 하며, 이는 검증이 정상 작동함을 나타냅니다.
2. 첫 번째 URL을 접근 불가능한 주소로 변경하고 나머지는 접근 가능하게 유지하면, 시작 시 자동으로 다음 사용 가능한 URL로 전환되어 다음 프로세스에 성공적으로 진입해야 합니다.
3. 모든 URL을 접근 불가능한 주소로 변경하면 시작은 `StartupResult.Fail`로 종료되고, `StartupFailedEventArgs`를 통해 마지막으로 실패한 URL과 오류 메시지가 발생하며 이를 UI 팝업 안내에 활용할 수 있습니다.

## 배경(선택 사항)

`UrlFailoverRunner`의 전략은 "URL 순차 순회 × URL당 N회 재시도"이며, 실패 시 마지막으로 실패한 URL과 오류 정보만 기록하고 목록의 맨 앞으로 자동 복귀하거나 백업을 무작위로 선택하지 않습니다. 전체 시작 오케스트레이션 프로세스는 《StartupProcedureUtility 완료 실패 처리》 문서를 참고하십시오. 여기서 `CompleteFailure`는 `failedUrl`을 `StartupFailedEventArgs`에 함께 기록하고 UI로 푸시합니다.
