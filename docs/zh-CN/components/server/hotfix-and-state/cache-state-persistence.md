# 使用 CacheState + BsonClassMap 持久化实体

通过 `CacheStateTypeManager.Init()` 一次性扫描所有实现 `ICacheState` 的实体类,框架会同时把它们注册到 `BsonClassMap`,后续 MongoDB 序列化即可直接读写,无需在每个实体上手写映射。

## 前置条件

- 已引用 `GameFrameX.Apps` 程序集(包含 `BsonClassMapHelper`、`CacheStateTypeManager`)。
- 实体类需要实现 `ICacheState` 接口(标记为可缓存/可持久化的实体)。
- 进程启动阶段调用过一次 `Init()`,通常放在 `Program.Main` 中其他组件初始化之前。

## 操作步骤

1. **让实体实现 `ICacheState` 接口**

   任何需要被持久化(典型为写入 MongoDB)的实体都必须实现 `ICacheState`。框架只扫描实现该接口的类型。

2. **在启动入口调用一次 `CacheStateTypeManager.Init()`**

   `Init()` 会扫描 `AppsHandler` 所在程序集,过滤出所有实现 `ICacheState` 的类型,用 `XxHash32(类型全名)` 作为 id 写入内部 `ConcurrentDictionary<long, Type>`,并对每个类型调用 `BsonClassMapHelper.RegisterClass` 注册到 MongoDB 驱动。

   ```csharp
   // GameFrameX.Launcher/Program.cs
   static void Main(string[] args)
   {
       CacheStateTypeManager.Init();
       MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
       // ... 其他启动逻辑
   }
   ```

   Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L10-L20)

3. **`Init()` 内部会同时注册两个 BSON Convention**

   - `DictionaryRepresentationConvention`:把 `IDictionary` 的 BSON 表示固定为 `ArrayOfDocuments`,避免在不同驱动版本下默认行为不一致。
   - `EmptyContainerSerializeMethodConvention`:对 `List<T>`、`Dictionary<,>`、`ConcurrentDictionary<,>` 等容器,在元素个数为 0 时跳过序列化,减少空字段写入。

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   ConventionRegistry.Register(nameof(DictionaryRepresentationConvention),
                               new ConventionPack { new DictionaryRepresentationConvention(), }, _ => true);

   ConventionRegistry.Register(nameof(EmptyContainerSerializeMethodConvention),
                               new ConventionPack { new EmptyContainerSerializeMethodConvention(), }, _ => true);
   ```

   Source: [GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L102-L111)

4. **对每个实体执行 `BsonClassMap.AutoMap` 并忽略多余字段**

   框架以类型全名的 `XxHash32` 作为字典主键,保证 `GetType(id)` 在不同进程/重启后能稳定找回原类型;`AutoMap` + `SetIgnoreExtraElements(true)` 让新增字段不会让旧数据反序列化失败。

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   public static void RegisterClass(Type t)
   {
       var bsonClassMap = new BsonClassMap(t);
       bsonClassMap.AutoMap();
       bsonClassMap.SetIgnoreExtraElements(true);
       bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
       BsonClassMap.RegisterClassMap(bsonClassMap);
   }
   ```

   Source: [GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

5. **运行时通过 `GetType(id)` 反查类型,完成多态反序列化**

   当 BSON 文档里只存了类型 id 时,调用 `CacheStateTypeManager.GetType(id)` 即可拿回具体的 `Type`,再交给 MongoDB 驱动构造对象。

   ```csharp
   // GameFrameX.Apps/CacheStateTypeManager.cs
   public static Type GetType(long id)
   {
       HashMap.TryGetValue(id, out var value);
       return value;
   }
   ```

   Source: [GameFrameX.Apps/CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L41-L45)

## 常见变体

- **新增了实现 `ICacheState` 的实体类**:重启进程即可,无需手动调用任何注册 API,`Init()` 会自动扫描。
- **实体不在 `AppsHandler` 所在程序集**:调用 `BsonClassMapHelper.RegisterAllClass(assembly)` 手动把目标程序集喂给注册流程,完成额外扫描。
- **临时禁用空容器跳过序列化**:不要注册 `EmptyContainerSerializeMethodConvention`,或在自己的实体上单独设置 `SetShouldSerializeMethod`。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动报 `BsonClassMap already registered` | 同一类型被重复注册 | `RegisterClass` 内已有 `IsClassMapRegistered` 守卫,排查是否在 `Init()` 之外手动调用过 `RegisterClassMap` |
| 反序列化丢字段或抛 `Element ... does not match any field` | 没调用 `SetIgnoreExtraElements` | 确认走的是 `BsonClassMapHelper.RegisterClass` 路径 |
| `CacheStateTypeManager.GetType(id)` 返回 `null` | 实体类未实现 `ICacheState`,`Init` 时未被收录 | 给实体加上 `ICacheState` 接口,重启进程 |
| `Dictionary` 在 BSON 里表现为 `Document` | 未注册 `DictionaryRepresentationConvention` | 确认 `Init()` 已执行,且在所有 MongoDB 操作之前 |

## 背景

框架选用 `XxHash32(type.ToString())` 作为类型 id,是为了让 id 稳定且与 .NET 类型全名一一对应,同时占用空间小;把 `SetIgnoreExtraElementsIsInherited` 打开,是为子类继承字段在新增时也不会破坏旧文档。Convention 全局注册使用 `_ => true`,意味着对所有未显式映射的类都生效,降低业务侧心智负担。
