# JSON リクエストボディの送信とレスポンスの解析方法

`HttpClientJsonExtension` の `PostJsonAsync / PutJsonAsync / PatchJsonAsync / SendJsonAsync` などの拡張メソッドを使用すれば、JSON リクエストボディの送信とレスポンスの目標型への逆シリアル化を 1 ステップで行うことができます。ステータスコードを自分で制御したい場合や生のレスポンスボディを読み取りたい場合は、`*ResponseAsync` シリーズのメソッドを使用し、`HttpClientResponse.As<T>()` で逆シリアル化します。

## 前提条件

- NuGet パッケージ `GameFrameX.Foundation.Http.Extension` を参照する(`GameFrameX.Foundation.Http.Normalization` は統一 JSON レスポンスラッパー用)。
- `HttpClient` インスタンスを作成または注入済みであること(`IHttpClientFactory` によるライフサイクル管理を推奨)。
- .NET 6+(`HttpClientJsonExtension` は `System.Net.Http.Json.JsonContent` に依存)。

## 操作手順

### 1. 直接 strongly-typed レスポンスを取得する(最も一般的)

`PostJsonAsync<TRequest, TResponse>` はリクエストオブジェクトを JSON にシリアル化し、ターゲット URL に POST し、成功レスポンス(2xx)を `TResponse` に逆シリアル化します。成功以外のステータスでは `HttpClientRequestException` がスローされ、内部にステータスコード、リクエスト URI、レスポンスボディが含まれます。

```csharp
using System.Net.Http;
using System.Threading.Tasks;
using GameFrameX.Foundation.Http.Extension;

var httpClient = new HttpClient { BaseAddress = new System.Uri("https://api.example.com") };

var request = new CreateOrderRequest
{
    Sku = "SKU-001",
    Quantity = 2
};

CreateOrderResponse? response = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request);

System.Console.WriteLine(response?.OrderId);
```

```csharp
public sealed class CreateOrderRequest
{
    public string Sku { get; set; }
    public int Quantity { get; set; }
}

public sealed class CreateOrderResponse
{
    public string OrderId { get; set; }
    public string Status { get; set; }
}
```

### 2. JSON シリアライゼーション、Header、タイムアウト、リトライのカスタマイズ

`HttpClientRequestOptions` を通じて `JsonSerializerOptions`、リクエストヘッダー、タイムアウト、リトライ戦略を注入します。拡張メソッドはリクエスト/レスポンス/リトリ時に自動でコールバックをトリガーし、ロギングやイベント計測に便利です。

```csharp
using System.Text.Json;
using GameFrameX.Foundation.Http.Extension;

var options = new HttpClientRequestOptions
{
    Timeout = System.TimeSpan.FromSeconds(10),
    JsonSerializerOptions = new JsonSerializerOptions
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase
    }
};
options.Headers["Authorization"] = "Bearer xxx";
options.Retry.MaxRetries = 3;
options.OnResponse = e =>
    System.Console.WriteLine($"[{e.Attempt}] {e.Method} {e.RequestUri} -> {(int)e.StatusCode}");

var result = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    options);
```

`HttpClientRetryOptions` はデフォルトで `RequestTimeout / TooManyRequests / InternalServerError / BadGateway / ServiceUnavailable / GatewayTimeout` に対してリトリをトリガーし、基本バックオフは 100ms × `BackoffFactor=2` の指数増加です。POST/PATCH はデフォルトではリトリせず、必要に応じて `AllowNonIdempotentRetry = true` を設定します。

### 3. 生のレスポンスの取得(ステータスコード + Body + Header)

ステータスコードによって処理を分岐したい場合や、エラーボディを読み取ってから逆シリアル化の方法を決定したい場合は、`*ResponseAsync` シリーズを使用します。`HttpClientResponse.As<T>()` はリクエストと同じ `JsonSerializerOptions` を使用して Body を解析します。

```csharp
using GameFrameX.Foundation.Http.Extension;

var resp = await httpClient.PostResponseAsync<CreateOrderRequest>(
    HttpMethod.Post,
    "/orders",
    request);

System.Console.WriteLine($"status={resp.StatusCode} attempt={resp.Attempt}");

if (!resp.IsSuccessStatusCode)
{
    // 失敗時も Body を取得でき、統一エラー報告に便利
    System.Console.WriteLine($"error body: {resp.Body}");
    return;
}

CreateOrderResponse? ok = resp.As<CreateOrderResponse>();
System.Console.WriteLine(ok?.OrderId);

// 成功を明示的にアサート、失敗時は HttpClientRequestException をスロー
resp.EnsureSuccessStatusCode();
```

### 4. 任意メソッド + JSON リクエストボディの送信

`SendJsonAsync<TRequest, TResponse>(HttpMethod method, …)` は基底的エントリーポイントであり、他の POST/PUT/PATCH オーバーロードはすべてこれに委譲します。カスタムメソッドやサードパーティ WebHook に使用できます。

```csharp
var result = await httpClient.SendJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    HttpMethod.Post,
    "https://api.example.com/orders",
    request);
```

### 5. リクエストボディのない JSON 呼び出し

GET/DELETE/OPTIONS など Body のないシナリオでは、`GetJsonAsync<TResponse>`、`DeleteJsonAsync<TResponse>` などの単一型パラメータオーバーロードを使用します。

```csharp
OrderList? list = await httpClient.GetJsonAsync<OrderList>("/orders?status=open");
```

## 一般的なバリエーション

### 統一レスポンスラッパー `IHttpJsonResult`

多くのバックエンドは `{ code, message, data }` 形式の戻り値を使用しており、`GameFrameX.Foundation.Http.Normalization` の `IHttpJsonResult<T>` / `HttpJsonResultHelper` を使用することで、拡張が `code` フィールドを自動検証し `data` を取り出すことができます。

```csharp
using GameFrameX.Foundation.Http.Normalization;

var resp = await httpClient.PostJsonAsync<CreateOrderRequest, HttpJsonResult<CreateOrderResponse>>(
    "/orders",
    request);

HttpJsonResult<CreateOrderResponse> ok = HttpJsonResultHelper.EnsureSuccess(resp);
CreateOrderResponse data = ok.Data;
```

### キャンセルトークン

すべての拡張メソッドは `CancellationToken` をサポートしており、ASP.NET Core の `HttpContext.RequestAborted` と直接接続できます。

```csharp
var resp = await httpClient.PostJsonAsync<CreateOrderRequest, CreateOrderResponse>(
    "/orders",
    request,
    cancellationToken: HttpContext.RequestAborted);
```

## よくあるエラー

- **`url` に null または空文字列を渡す**:`SendJsonAsync` 内部で `ArgumentException.ThrowIfNullOrWhiteSpace(url, nameof(url))` が実行され、即座に `ArgumentException` がスローされます。
- **逆シリアル化の失敗**:`SendJsonAsync` は非 2xx の場合 `HttpClientRequestException` をスローします。200 を返しても Body が有効な JSON でない場合、`As<T>` は `System.Text.Json.JsonException` をスローします。
- **POST/PATCH は自動リトリしない**:デフォルトでは `AllowNonIdempotentRetry=false` です。書き込みインターフェースにリトリが必要な場合は、明示的にこのスイッチを有効化するか、相手側がべき等であることを確認してください。
- **`HttpClientRequestOptions` 再利用時に `JsonSerializerOptions` が上書きされる**:このプロパティは `set` であって `init` ではないため、送信ごとに期待するインスタンスが渡されていることを確認してください。
- **レスポンスボディが切り詰められて例外メッセージに表示される**:`HttpClientJsonExtension` の内部では `ResponseSummaryLimit = 1024` で、完全な原文は常に `HttpClientRequestException.ResponseBody`(`*ResponseAsync` で取得した `HttpClientResponse.Body`)にあります。

## 背景(オプション)

`HttpClientJsonExtension` は内部で `JsonContent.Create(request, options: options.JsonSerializerOptions)` を使用してリクエストボディを構築し、すべてのメソッドは同じ `ExecuteCoreAsync` リトリ/タイムアウトチャネルを経由し、その後 `Selector`(strongly-typed メソッドはステータスコード例外をスロー、`*ResponseAsync` は `RawResponse` を透過)で 2 種類に分岐します。これにより、「直接オブジェクトを取得」と「先にステータスコードを確認」の 2 つの使い方が同じコードでサポートされています。
