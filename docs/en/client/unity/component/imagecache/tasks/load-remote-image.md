# How to Load Remote Images Asynchronously

You can load a remote image asynchronously via `IImageCacheManager.LoadImageAsync`: on non-WebGL platforms, the disk cache is used first, and if it misses, the file is downloaded and then loaded; on the WebGL platform, the image is loaded directly through `UnityWebRequestTexture`, with the browser managing the cache.

## Prerequisites

- The `com.gameframex.unity.imagecache` package is installed, and `ImageCacheComponent` is attached in the scene.
- The `com.gameframex.unity.download` package is installed (required for non-WebGL platforms, used for file downloads).
- The remote image URL must start with `http://` or `https://`.
- A writable local directory is specified for `ImageCacheConfig.CachePath` (required for non-WebGL platforms).

## Steps

1. Get an instance of the image cache manager. `ImageCacheComponent` has its lifecycle encapsulated, and you can obtain it directly through the component field or via `GameFrameX.Runtime.GameFrameworkEntry.GetModule<IImageCacheManager>()`.

    ```csharp
    using GameFrameX.ImageCache.Runtime;
    using UnityEngine;

    public class MyImageLoader : MonoBehaviour
    {
        [SerializeField] private ImageCacheComponent imageCacheComponent;

        private IImageCacheManager _manager;

        private void Start()
        {
            _manager = imageCacheComponent; // The component itself implements IImageCacheManager
        }
    }
    ```

    Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs)

2. Call `LoadImageAsync` and `await` the returned `Task<Texture2D>`. This method automatically handles the entire process of disk cache hits, file downloads, and `Texture2D` decoding; it returns a `Texture2D` on success, or `null` on failure.

    ```csharp
    using System.Threading;
    using System.Threading.Tasks;
    using UnityEngine;

    public async Task<Sprite> LoadHeadIconAsync(string url, CancellationToken ct)
    {
        var texture = await _manager.LoadImageAsync(url, ct);
        if (texture == null)
        {
            Debug.LogWarning($"Load failed: {url}");
            return null;
        }

        var sprite = Sprite.Create(
            texture,
            new Rect(0, 0, texture.width, texture.height),
            new Vector2(0.5f, 0.5f));
        sprite.name = url;
        return sprite;
    }
    ```

    Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L18-L26)

3. Validate the URL before calling. Inside `LoadImageAsync`, an empty string or a URL that does not start with `http(s)://` will print a warning and return `null`. The business side can still perform a defensive check ahead of time to avoid meaningless `await`.

    ```csharp
    if (string.IsNullOrEmpty(url) ||
        (!url.StartsWith("http://") && !url.StartsWith("https://")))
    {
        Debug.LogWarning("URL is invalid");
        return null;
    }

    var tex = await _manager.LoadImageAsync(url);
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L70-L89)

4. (Optional) Use `CancellationToken` to cancel an in-progress load. This only takes effect on non-WebGL platforms and is suitable for scenarios such as page destruction or scene switching to release incomplete loads.

    ```csharp
    private CancellationTokenSource _cts;

    public async void Reload(string url)
    {
        _cts?.Cancel();
        _cts = new CancellationTokenSource();

        var tex = await _manager.LoadImageAsync(url, _cts.Token);
        // tex may be null if the component has been destroyed
    }
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L122-L150)

5. After loading is complete, apply the `Texture2D` to the UI. You can assign it directly to `RawImage.texture`, or wrap it into a `Sprite` as shown in Step 2 for use with `Image`.

    ```csharp
    [SerializeField] private UnityEngine.UI.RawImage target;

    public async Task ApplyAsync(string url)
    {
        var tex = await _manager.LoadImageAsync(url);
        if (tex != null) target.texture = tex;
    }
    ```

## Common Variations

- **Pre-download and cache**: When calling `await LoadImageAsync` multiple times for the same URL, after the first download the file is cached to `CachePath` using the URL's MD5 hash as the filename, so subsequent calls read from disk directly without re-downloading. You can proactively pre-warm commonly used images when entering a scene.

    ```csharp
    // Non-WebGL platforms: IsCached can be used to check whether the file has already been downloaded
    if (_manager.IsCached(url))
    {
        Debug.Log("Local cache hit");
    }
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L180-L194)

- **Loading on WebGL platforms**: Under `UNITY_WEBGL`, `LoadImageAsync` takes the `UnityWebRequestTexture` branch and no longer writes to disk; `IsCached` always returns `false`, and `RemoveCache`/`ClearCache` will print a warning. The business side does not need to differentiate platforms; the API behavior is consistent.

    ```csharp
    // On WebGL, call the same way; the UnityWebRequestTexture branch is automatically taken internally
    var tex = await _manager.LoadImageAsync(url);
    ```

    Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L91-L115)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `LoadImageAsync` returns `null`, log shows `url is null or empty` | URL is empty | Check `string.IsNullOrEmpty` before calling |
| Returns `null`, log shows `url must start with http:// or https://` | URL does not start with http(s) | Use a full URL; do not pass local paths or `file://` |
| Download fails on non-WebGL, log shows `download failed` | `DownloadManager` is not registered or the network is unreachable | Confirm that GameFrameX's download manager is initialized and its event callbacks are registered correctly |
| `Task` does not end immediately after `CancellationToken` cancellation | The cancellation logic only applies on non-WebGL platforms, and only for the segment after the cache read / file existence check | After cancellation, check `tex == null` yourself; do not assume the `Task` will throw |

## Background (Optional)

- Non-WebGL platforms: `ImageCacheManager` uses `Utility.Hash.MD5.Hash(url)` as the cache filename, with the extension fixed as `.png`; on the first cache miss, a download is initiated via `IDownloadManager.AddDownload`, waiting for the `DownloadSuccess` / `DownloadFailure` events through `TaskCompletionSource`.
- WebGL platforms: When the `UNITY_WEBGL` macro is enabled, `LoadImageAsync` switches to `UnityWebRequestTexture.GetTexture` + `SendWebRequest()`, and caching is fully handled by the browser's HTTP Cache, so `IsCached`, `RemoveCache`, and `ClearCache` are all disabled.

For component initialization and lifecycle, see "ImageCacheComponent Overview"; for the meaning of cache configuration fields, see `ImageCacheConfig`.
