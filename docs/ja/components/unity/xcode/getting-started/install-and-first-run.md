# インストールと初回実行

GameFrameX Xcode 設定は Unity Package であり、インストール後に C# コードを一切書く必要はありません。プロジェクト内に `XCodeConfig.json` を 1 つ配置するだけで、iOS ビルド終了時に Info.plist、署名、Capabilities、CocoaPods などの Xcode プロジェクトに対する変更が自動的に完了します。このページでは、パッケージのインストールから初めて一連のフローを通すまでを案内します。

## クイックスタート

### 1. パッケージのインストール

以下のいずれかの方法を選択してください（バージョンを一元管理しやすい scopedRegistries を推奨）：

**方法 1：Scoped Registry（バージョン指定可能）** — `Packages/manifest.json` を編集します：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.xcode": "1.11.1"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L47-L63)

`scopes` は、どのパッケージをこのレジストリ経由で解決するかを制御します。`com.gameframex` で始まるパッケージのみがこのレジストリから取得されます。

**方法 2：Git URL** — `manifest.json` の `dependencies` ノード配下に追加します：

```json
{
   "com.gameframex.unity.xcode": "https://github.com/gameframex/com.gameframex.unity.xcode.git"
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L67-L72)

**方法 3：Package Manager** — Unity の `Package Manager` で `Git URL` 方式を使って追加します。アドレスは上記と同じです。

**方法 4：リポジトリを直接ダウンロード** Unity プロジェクトの `Packages` ディレクトリに配置すると、自動的に読み込まれて認識されます。

動作環境：Unity 2019.4 以上。

### 2. 設定ファイルの作成

設定ファイルは**必ず `XCodeConfig.json` という名前にする必要があります**。プロジェクト内の任意の場所に配置でき、複数のファイルの共存にも対応しており、ビルド時に自動的にディープマージされます（マルチモジュールでの協働に適しています）。チャネルごとに区別したい場合は、さらに `XCodeConfig.{渠道名}.json` を作成することもできます。チャネル設定は最後にマージされ、優先度が最も高くなります。

最上位の構造は以下の通りです：

```json
{
  "swiftBridging": true,
  "signing": {},
  "plist": {},
  "environmentVariables": {},
  "launcherArgs": [],
  "podSource": [],
  "podfile": "",
  "podInstall": true,
  "localizations": [],
  "capabilities": {},
  "unityFramework": {},
  "unityMain": {}
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L79-L96)

最小構成の動作例（Bitcode を無効化 + plist に 1 項目記述 + システムフレームワークを 1 つ追加）：

```json
{
  "plist": { "NSCameraUsageDescription": "用于拍摄头像" },
  "unityMain": {
    "properties": { "=": { "ENABLE_BITCODE": "NO" } },
    "frameworks": { "+": [ "WebKit.framework" ], "-": [] }
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L145-L173)

よく使う最上位フィールドの早見表：

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `swiftBridging` | bool | Swift ブリッジングヘッダーファイルを自動生成（デフォルト `true`） |
| `signing` | object | コード署名の設定（Team ID、Bundle Identifier など） |
| `plist` | object | Info.plist のキーと値のペア。値には任意の型を指定可能 |
| `capabilities` | object | iOS アプリのケイパビリティ（アプリ内課金、プッシュ通知、iCloud など） |
| `podfile` / `podInstall` | string / bool | カスタム Podfile のパス / `pod install` を自動実行するかどうか（デフォルト `true`） |
| `unityMain` / `unityFramework` | object | それぞれ Unity-iPhone と UnityFramework の各 target 設定に対応 |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L98-L111)

### 3. iOS のビルドと検証

1. Unity でプラットフォームを iOS に切り替え、ビルドを実行します（File → Build Settings → Build）。
2. ビルド終了後、ツールは自動的に `[PostProcessBuild(888)]` コールバック内で実行されます——他のほとんどのポストプロセススクリプトより後に実行され、`BuildTarget.iOS` の場合にのみ動作します：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        //設定ファイルを読み込む
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 一致するファイルが 1 つも見つからない場合は、そのまま返す
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L32)

3. Unity の Console ログを確認します。以下の出力が確認できれば、インストールは成功しており、一連のフローが通っています：
   - `[MergeConfig] 正在合并配置: <你的 XCodeConfig.json 路径>`
   - `[PBXProject] 正在应用最终合并配置...`
   - `[OtherSettings] 正在应用最终合并配置...`
4. 生成された Xcode プロジェクトを開いて結果を確認します：Info.plist に設定したキーが追加されている、Build Settings の `ENABLE_BITCODE` が `NO` に変わっている、など。

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L38-L107)

ログに `未找到任何 XCodeConfig 相关配置文件, 跳过设置` が表示された場合は、ファイル名が `XCodeConfig.json` になっていない（大文字・小文字は区別されます）、またはプロジェクトディレクトリ内に存在しないことを意味します。名前の変更や移動を行ってから再度ビルドしてください。

## よくあるバリエーション

- **マルチモジュール・複数設定**：異なるモジュールがそれぞれ `XCodeConfig.json` を配置し、ビルド時にファイルの順番でディープマージされます。同じキーは「後にマージされたものが上書き」されます。
- **チャネルごとの差分設定**：`SettingLoader.GetChannel()` でチャネルを検出し、`XCodeConfig.{channel}.json` を読み込んで最後にマージ・上書きします。関連ロジックは [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77) を参照してください。
- **pod install のスキップ**：`"podInstall": false` を設定すると `pod install` の自動実行をスキップできます。カスタム Podfile がある場合は `"podfile": "<路径>"` で指定します（`pods` フィールドより優先されます）。[PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156) を参照してください。

## よくあるエラー

| 症状 | 原因 | 対処 |
|------|------|------|
| Console に `未找到任何 XCodeConfig 相关配置文件, 跳过设置` と表示される | ファイル名が `XCodeConfig.json` ではない、またはプロジェクトディレクトリ内に存在しない | 厳密に `XCodeConfig.json` と命名（大文字・小文字を区別）してから再ビルドする |
| Console に `<路径> 解析失败, 跳过合并` と表示される | JSON 構文エラー | JSON 検証ツールでチェックして修正し、再ビルドする |
| Console に `合并后的配置为空，跳过设置` と表示される | ファイルは存在するが、内容が空のオブジェクト | 少なくとも 1 つの有効なフィールドを書き込む |
| ビルド後に Xcode プロジェクトが変化しない | ビルドターゲットが iOS でない、またはコールバックでスローされた例外が握りつぶされている | BuildTarget が iOS であることを確認；Console に `Debug.LogException` が出力した例外のスタックトレースがないか確認する |

上記のエラーメッセージは、いずれも [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83) の実際のログ原文からの引用です。

## 検証

1. Console に `[MergeConfig]` → `[PBXProject]` → `[OtherSettings]` の 3 段階のログが表示され、赤色の Error がないこと。
2. Xcode でビルド出力ディレクトリを開き、以下を確認します：Info.plist に `plist` の設定項目が書き込まれていること、Build Settings が `properties` の設定どおりになっていること、`podfile`/`pods` を設定した場合はプロジェクトディレクトリに Podfile が生成され、依存関係がインストールされていること。

## 背景

ツールは 2 つの段階に分けて書き込みを行います。第 1 段階では、ビルド属性、フレームワーク、ライブラリ、ファイルコピー、コンパイルフラグなどを `Unity-iPhone` と `UnityFramework` の 2 つの target に適用し、`project.pbxproj` を保存します。第 2 段階では、Plist、環境変数、起動引数、Capabilities、ローカライズ、CocoaPods を処理し、Capabilities を独立してディスクに書き込んだ後、プロジェクトファイルを再読み込みしてその変更を保持します。Swift ブリッジングはデフォルトで有効になっており、署名と Capabilities はメインプロジェクトに対してのみ設定されます。完全な実装は [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156) を参照してください。

関連ページ：設定ファイルの全フィールドの説明については、リポジトリ内の [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L75-L229) を参照してください。
