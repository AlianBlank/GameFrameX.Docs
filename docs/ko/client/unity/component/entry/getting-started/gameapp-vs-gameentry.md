# GameApp과 GameEntry 두 가지 접근 방식을 선택하는 방법

GameFrameX는 프레임워크 컴포넌트를 가져오는 두 가지 방식을 제공합니다: `GameEntry`는 컴포넌트 컨테이너의 저수준 진입점이며(`GameFrameX.Runtime` 패키지에서 제공), `GameApp`은 이 저장소에서 `GameEntry`를 기반으로 캡슐화한 "정적 파사드(facade)"로, 자주 사용하는 컴포넌트를 속성 형식으로 노출합니다. 간단히 말해: 비즈니스 코드에서 `GameApp.XXX`를 호출하면, `GameApp` 내부에서는 모두 `GameEntry.GetComponent<XXXComponent>()`를 거칩니다.

## 사전 조건

- `com.gameframex.unity.entry`(이 저장소)가 설치되어 있어야 함
- `com.gameframex.unity.runtime`가 설치되어 있어야 함(`GameEntry` 타입이 `GameFrameX.Runtime` 네임스페이스에 정의되어 있기 때문)

```csharp
using GameFrameX.Runtime; // GameEntry 제공
// GameApp은 전역 네임스페이스에 위치하므로 using이 필요 없음
```

출처: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L32-L34)

## 두 가지 접근 방식의 형태 비교

| 구분 | `GameEntry` | `GameApp` |
|------|-------------|-----------|
| 소속 네임스페이스 | `GameFrameX.Runtime`(외부 패키지) | 전역 네임스페이스(이 저장소) |
| 타입 | 정적 클래스, 컴포넌트 컨테이너 제공 | `static partial class`, 컴포넌트당 파일 하나 |
| 호출 형식 | `GameEntry.GetComponent<T>()` | `GameApp.<属性名>` |
| 대표적인 용도 | 커스텀 컴포넌트 등록, 필요할 때 임의의 컴포넌트 가져오기 | 고빈도로 자주 쓰는 컴포넌트의 빠른 접근 |

`GameApp`의 속성 getter 구현은 단순히 `GameEntry.GetComponent<T>()`를 한 번 감싼 것이며, 그 결과를 private static 필드에 캐시합니다:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }
    private static BaseComponent _base;
}
```

출처: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

## 선택 가이드

1. **일상적인 비즈니스 개발에서는 `GameApp` 우선 사용**
   - 코드가 더 짧고 가독성이 더 좋습니다: `GameApp.Base`, `GameApp.Mono`.
   - 컴포넌트의 구체적인 타입 이름을 외울 필요가 없으며, IDE 자동 완성만으로 현재 패키지에서 캡슐화된 컴포넌트가 나열됩니다.
   - 캐시에 적중한 이후에는 필드 읽기만 발생하므로 오버헤드가 거의 없습니다.

2. **이 저장소에서 캡슐화하지 않은 컴포넌트에 접근해야 할 때는 `GameEntry`를 직접 사용**
   - 예를 들어 직접 정의한 `MyComponent`를 프레임워크에 등록한 경우, `GameEntry.GetComponent<MyComponent>()`만 사용할 수 있습니다.
   - 패키지 간/모듈 간 경계에서 코드를 작성할 때는 `GameEntry`를 우선 사용하여 `GameApp`에 대한 하드 의존성이 생기지 않도록 합니다.

3. **새 컴포넌트를 등록할 때는 두 방식 모두 한 곳씩 수정 필요**
   - `GameEntry.RegisterComponent<T>()`로 등록을 완료한 후, 비즈니스 측에서 `GameApp.My`와 같은 속성 접근을 사용할 수 있게 하려면, 이 저장소에 `GameApp.My.cs` partial 파일을 새로 추가하고 위의 템플릿대로 getter와 캐시 필드를 한 번 감싸면 됩니다.

## 작업 단계: `GameApp` 속성 하나 추가하기

1. `Runtime/` 아래에 `GameApp.My.cs`를 새로 추가합니다(반드시 `partial`을 사용해야 하며, `GameApp`과 동일한 네임스페이스여야 합니다).

```csharp
public static partial class GameApp
{
    public static MyComponent My
    {
        get
        {
            if (_my == null)
            {
                _my = GameEntry.GetComponent<MyComponent>();
            }
            return _my;
        }
    }

    private static MyComponent _my;
}
```

2. 프레임워크 시작 흐름에서 `GameEntry.RegisterComponent<MyComponent>()`로 등록을 완료합니다.
3. 비즈니스 측에서는 `GameApp.My.DoSomething()`처럼 바로 사용하면 됩니다.

출처: 템플릿 참고 [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

## 자주 발생하는 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `GameApp.Base`가 `null` 반환 / 예외 발생 | 프레임워크 시작이 아직 완료되지 않았거나, 해당 컴포넌트가 `RegisterComponent`되지 않음 | 시작 흐름에서 `RegisterComponent<BaseComponent>`를 호출했는지 확인; 핫업데이트/재시작 시나리오에서는 실행 순서(타이밍)에 주의 |
| 컴파일 오류: `GameEntry`가 존재하지 않음 | `using GameFrameX.Runtime;`이 없음 | 파일 상단에 `using GameFrameX.Runtime;` 추가 |
| `GameApp.Mono` 등의 속성을 찾을 수 없음 | 현재 사용 중인 것이 `com.gameframex.unity.entry` 패키지가 아니거나, 패키지 버전이 오래되어 해당 partial 파일이 포함되어 있지 않음 | 이 패키지를 최신 버전으로 업그레이드 |
| 직접 작성한 `GameApp.My`에서 `missing partial` 오류 발생 | 새 파일이 `public static partial class GameApp`을 선언하지 않음 | `partial` 키워드를 추가하고 기존 `GameApp`과 동일한 이름으로 선언 |

## 배경(선택 사항)

`GameEntry`는 컴포넌트 딕셔너리(`RegisterComponent` / `GetComponent<T>()`)를 유지 관리하며, 프레임워크 컴포넌트의 "컨테이너 루트"입니다. `GameApp`은 실제 작업을 수행하지 않으며, 고빈도 컴포넌트를 꺼내 정적 필드에 캐시함으로써 호출 측이 제네릭을 한 번 덜 쓰고 클래스 이름을 한 번 덜 입력하게 해줍니다. 두 방식 모두 동일한 컴포넌트 인스턴스에 접근합니다.
