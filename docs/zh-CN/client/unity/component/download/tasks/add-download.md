# 添加并发起一次下载

通过 `DownloadComponent.AddDownload(...)` 把远程文件加入下载队列,框架会自动调度下载代理完成下载,并通过事件回调把进度、成功、失败结果返回给你。

## 前置条件

- 场景中已挂载 `DownloadComponent`(组件菜单 `GameFrameX/Download`),并随 `GameFramework` 启动完成。
- 场景中已挂载 `EventComponent`,否则下载成功 / 失败事件无法分发。
- `DownloadComponent` 上的 `Download Agent Helper Count` 大于 0,默认值为 3。
- `downloadPath` 所在目录有写入权限。

## 操作步骤

1. 获取 `DownloadComponent` 实例:

```csharp
var download = GameEntry.GetComponent<DownloadComponent>();
```

Source: [DownloadComponent.cs#L46-L60](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L60)

2. 调用 `AddDownload` 把下载任务加入队列,返回任务的序列号 `serialId`:

```csharp
int serialId = download.AddDownload(
    downloadPath: Application.persistentDataPath + "/files/bundle.zip",
    downloadUri:   "https://example.com/bundle.zip",
    tag:           "Bundle",
    priority:      0,
    userData:      null);
```

Source: [DownloadComponent.cs#L379-L385](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L379-L385)

3. 订阅 `EventComponent` 中的下载事件以获取回调,事件 ID 定义见 `Constant.cs`:

```csharp
var eventComp = GameEntry.GetComponent<EventComponent>();
eventComp.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComp.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComp.Subscribe(DownloadUpdateEventArgs.EventId,   OnDownloadUpdate);
```

回调中通过 `e.SerialId` 与加入时返回的 `serialId` 对应。

4. 处理下载结果。`DownloadSuccessEventArgs` / `DownloadFailureEventArgs` 均提供 `SerialId`,根据它即可判定是哪个任务结束。

## 常见变体

- **只想拿到 `Task<bool>`**:使用 `download.Download(downloadPath, downloadUri)`,内部封装了 `AddDownload` + `TaskCompletionSource`,完成时 `Task` 会 `SetResult(true)`,失败 / 取消时 `SetResult(false)` / `TrySetCanceled()`。
  Source: [DownloadComponent.cs#L306-L317](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L317)

- **不传 tag / priority**:直接使用两个参数的 `AddDownload(string downloadPath, string downloadUri)`,默认 `tag = null`,`priority = 0`。
  Source: [DownloadComponent.cs#L271-L274](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L274)

- **按 tag 批量管理**:用 `GetDownloadInfos(tag)` 查询,用 `RemoveDownloads(tag)` 批量取消。

## 常见错误

- **`Log.Fatal("Download manager is invalid.")`**:场景中没有挂载 `DownloadComponent` 或它没有正确 Awake。检查 GameFramework 启动顺序。
- **`Log.Fatal("Event component is invalid.")`**:缺少 `EventComponent`,下载事件无法分发。
- **下载目录无写权限**:请使用 `Application.persistentDataPath` 这类 Unity 提供的可写路径,不要写到 `StreamingAssets` 或 `jar:file://` 等只读位置。
- **代理全忙时新任务一直等待**:任务会进入等待队列,直到有空闲代理。可用 `FreeAgentCount` / `WaitingTaskCount` 监控。
  Source: [DownloadComponent.cs#L82-L105](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L82-L105)

## 背景

`DownloadComponent` 在 `Start` 阶段按 `Download Agent Helper Count` 创建对应数量的 `UnityWebRequestDownloadAgentHelper`(可在 Inspector 切换为自定义实现),所有并发下载都在这些 Helper 上轮转。`AddDownload` 仅入队,真正发起 HTTP 请求与写入磁盘由 `DownloadManager` 在下一帧调度。
