# テナント/組織分離エンティティ基底クラスの使用方法

`EntityTenantOrganizationBase`（またはそのジェネリックバージョン）を継承することで、エンティティにマルチテナント分離と組織分離の両方の能力を持たせることができます。`TenantId` と `CreateOrganizationId` フィールドが自動的に付与され、`ITenantIdFilter` と `IOrganizationIdFilter` インターフェースを実装します。ORM フィルターと組み合わせることで、テナント/組織によるデータの自動フィルタリングが可能になります。

## 前提条件

- NuGet パッケージのインストール済み：`GameFrameX.Foundation.Orm.Entity`
- ORM フレームワークがテナントコンテキスト（現在の `TenantId`）と組織コンテキスト（現在の `CreateOrganizationId`）を設定済みで、フィルターが自動注入できること
- データベーステーブルに `TenantId`、`CreateOrganizationId` 列が存在すること（`long?` nullable）

## 操作手順

1. **エンティティクラスに `EntityTenantOrganizationBase<TKey>` を継承させる**。主キーの型（一般的に `long` または `Guid`）を指定すると、エンティティは自動的に `TenantId`、`CreateOrganizationId` の 2 つの nullable な `long?` プロパティを取得します。

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }
    public DateTime CreatedTime { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L44-L55)

2. **（オプション）エンティティに `[TenantTable]` 属性を付与する**。ORM はこれに基づいてテナント分離機能を有効化します：テナントフィルタの自動注入、テナント識別子の強制書き込み、テナント間アクセスの防止。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[TenantTable]
public class GameOrder : EntityTenantOrganizationBase<long>
{
    public string OrderNo { get; set; }
}
```

Source: [TenantTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/TenantTableAttribute.cs#L63-L72)

3. **非ジェネリックバージョンを使用する（主キーが基底クラスによって決定される場合）**。`EntityBase` がすでにデフォルトの主キー型を提供している場合、`EntityTenantOrganizationBase` を直接継承でき、`TKey` を指定する必要はありません。

```csharp
public class GameArea : EntityTenantOrganizationBase
{
    public string AreaName { get; set; }
    public bool IsActive { get; set; }
}
```

Source: [EntityTenantOrganizationBase.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityTenantOrganizationBase.cs#L64-L76)

4. **必要に応じてテナントと組織のフィールドを書き込む**。ORM インターセプタは新規追加/クエリ時に現在のコンテキストで `TenantId` と `CreateOrganizationId` を自動的に上書きします。手動で制御する必要がある場合は、ビジネスコード内で値を代入できます。

```csharp
var order = new GameOrder
{
    OrderNo      = "O-20260101-0001",
    Amount       = 99.5m,
    CreatedTime  = DateTime.UtcNow,
    // TenantId と CreateOrganizationId はコンテキストによって自動的に設定される
};
```

## 一般的なバリエーション

| シナリオ | 基底クラスの選択 | 説明 |
|------|----------|------|
| テナント分離のみ必要で、組織は区別しない | `EntityTenantBase<TKey>` | `ITenantIdFilter` を継承、`CreateOrganizationId` フィールドなし |
| 組織分離のみ必要 | カスタムエンティティで `IOrganizationIdFilter` を実装 | `CreateOrganizationId` のみ公開 |
| テナント + 組織分離の両方が必要 | `EntityTenantOrganizationBase<TKey>` | 本ページで紹介 |
| 主キー型がフレームワークのデフォルトによって決定される | `EntityTenantOrganizationBase`（非ジェネリック） | `TKey` を明示的に渡さない |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| クエリ結果に他のテナント/組織のデータが含まれる | フィルターが有効になっていない、またはコンテキストに `TenantId`/`CreateOrganizationId` が注入されていない | ORM のグローバルフィルター登録を確認；毎リクエストでテナント/組織コンテキストが設定されているか確認 |
| 書き込み時に `TenantId` が常に `null` | エンティティクラスが同時にグローバルテーブルとしてマークされている、またはインターセプタの順序問題 | テナントエンティティに同時に `[SystemTable]` を付けない；`[TenantTable]` のみを付ける |
| 継承後に `CreateOrganizationId` フィールドが見つからない | 誤って `EntityTenantBase`（テナントのみ）を継承している | `EntityTenantOrganizationBase` またはそのジェネリックバージョンを使用する |
| 列名が一致しない | テーブル構造に `TenantId` または `CreateOrganizationId` 列がない | データベースマイグレーションで対応する nullable な `bigint` 列を追加する |

## 背景（オプション）

`EntityTenantOrganizationBase` は `EntityTenantBase`（`TenantId` + `ITenantIdFilter` を提供）から継承し、`IOrganizationIdFilter`（`CreateOrganizationId` を提供）を実装します。2 つのフィルターインターフェースは ORM 層で認識され、クエリに対して自動的に `WHERE TenantId = ? AND CreateOrganizationId = ?` の条件を追加し、新規追加に対して 2 つのフィールドを自動的に補完します。`[TenantTable]` はテーブルレベルのスイッチであり、このテーブルでテナント分離を有効にすることを ORM に通知します。`[SystemTable]`（グローバル共有）と相互排他です。

マルチテナント分離の全体的な設計については、《テナント分離エンティティ基底クラスの使用方法》を参照してください。
