# Initialize the Payment System

Mount `PaymentComponent` in a Unity scene and call `Init` to complete the payment system initialization: the component automatically selects the corresponding payment manager implementation (Google / Apple / WebGL / PC) for the current platform in `Awake`. You only need to set the product IDs and pass in the sandbox and verification switches to start using the purchase APIs.

## Prerequisites

- This package is installed in your Unity project. Choose any one of the following methods (see [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/README.zh-CN.md#L40-L67) for details):
  - Add `"com.gameframex.unity.payment": "https://github.com/gameframex/com.gameframex.unity.payment.git"` to the `dependencies` of `Packages/manifest.json`;
  - Or add it via Unity `Package Manager` using the `Git URL` method;
  - Or place the repository directly under the `Packages` directory for automatic detection.
- The dependency package `com.gameframex.unity` is installed (version 1.1.1 or above).
- The target platform is Android (Google Play) or iOS (App Store); the Editor and other platforms fall back to a stub implementation (see "Common Errors" below).

## Steps

1. Create a GameObject in the startup scene and add `PaymentComponent` via the menu `GameFrameX/Payment`. The component declares its dependency and entry menu:

```csharp
[DisallowMultipleComponent]
[RequireComponent(typeof(GameFrameXPaymentCroppingHelper))]
[AddComponentMenu("GameFrameX/Payment")]
[UnityEngine.Scripting.Preserve]
public class PaymentComponent : GameFrameworkComponent
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L17-L21)

When adding the component, `GameFrameXPaymentCroppingHelper` is automatically included via `RequireComponent`, so there is no need to add it manually; mounting it multiple times on the same GameObject is not allowed.

2. (Optional) Verify the platform implementation type. In `Awake`, the component automatically selects the full name of the implementation class based on compilation defines:

```csharp
#if UNITY_ANDROID
    componentType = m_componentAndroidType;
#elif UNITY_IOS
    componentType = m_componentIOSType;
#elif UNITY_WEBGL
    componentType = m_componentWebGLType;
#elif UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX
    componentType = m_componentPCType;
#elif UNITY_STANDALONE_OSX
    componentType = m_componentMacType;
#else
    componentType = typeof(DefaultPaymentManager).FullName;
#endif
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L83)

4. Call `Init` to complete initialization. The signature and default values on the component are as follows:

```csharp
/// <summary>
/// Initialize
/// </summary>
/// <param name="isDebug">Whether it is a sandbox purchase</param>
/// <param name="isClientVerify">Whether to perform client-side purchase verification</param>
[UnityEngine.Scripting.Preserve]
public void Init(bool isDebug = false, bool isClientVerify = true)
{
    _paymentManager.Init(isDebug, isClientVerify);
}
```

Parameter description:

| Parameter | Type | Default Value | Description |
|------|------|--------|------|
| `isDebug` | `bool` | `false` | Whether to use sandbox purchase mode |


## Common Variants

- **Switch to an in-house or other channel implementation**: Without modifying code, directly change the serialized field for the corresponding platform (e.g., `m_componentAndroidType`) in the Inspector to the full name of your implementation class. The class must implement `IPaymentManager` (usually by inheriting `BasePaymentManager`). The component loads the type via reflection using `Utility.Assembly.GetType(componentType)`.
Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L84-L85)
- **Sandbox/test environment**: Call `Init(true)` to set `isDebug` to `true` and go through the channel's sandbox purchase flow.
- **Server-side verification**: Call `Init(isDebug: false, isClientVerify: false)`; after a successful purchase, the server verifies the receipt and the client performs no local validation.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| The log outputs `You are using DefaultPaymentManager which is a stub. Please integrate a channel-specific implementation (e.g. Google, Apple).` and `IsReady()` always returns `false` | The current platform (e.g., Editor) fell back to the stub implementation `DefaultPaymentManager` | Confirm the target platform is Android/iOS and the corresponding channel package is installed; or integrate a custom implementation class |
| The log outputs `Pay Manager is invalid.` and aborts | `GameFrameworkEntry.GetModule<IPaymentManager>()` returns null; the module is not registered | Check whether the GameFrameX base package (`com.gameframex.unity`) is installed and the version matches |
| Predefined products do not take effect | `SetPredefinedProductIds` is called after `Init` | Move this call before `Init` |
| Wrong platform implementation type | The serialized field in the Inspector was changed incorrectly, or the define did not take effect after switching platforms | Verify the field value against the platform mapping table above; recompile after switching platforms |

## Verification

- After initialization, call `PaymentComponent.IsReady()`: a return value of `true` means the channel implementation is ready; returning `false` on the Editor or platforms without an integrated channel is expected behavior.
- If the `DefaultPaymentManager which is a stub` warning no longer appears in the Console, the real channel implementation has been loaded for the current platform.

## Background

`PaymentComponent` is a GameFrameworkComponent. In `Awake`, it determines the full name of the implementation class based on compilation defines, resolves it into `ImplementationComponentType` via `Utility.Assembly.GetType`, with the interface type fixed as `IPaymentManager`, and then obtains the module instance through `GameFrameworkEntry.GetModule<IPaymentManager>()`; the `Init`, `IsReady`, `Buy` and other methods on the component are all forwarded to that instance. Source code of the channel implementations (Google, Apple, etc.) is not included in this repository; the corresponding channel packages must be installed separately.
