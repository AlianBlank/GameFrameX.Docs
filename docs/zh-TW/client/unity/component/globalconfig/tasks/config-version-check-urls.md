# 應用程式與資源版本檢查 URL 配置方式

GlobalConfig 透過伺服器傳遞的全域配置物件回傳應用程式版本檢查位址與資源版本檢查位址，前端只需使用 `CheckAppVersionUrl` 與 `CheckResourceVersionUrl` 兩個欄位，即可發起對應的版本檢查請求。

## 前置條件

- 已安裝 `com.gameframex.unity.globalconfig` 套件並完成進入點元件註冊。
- 業務端已部署回傳全域資訊的介面，且介面 JSON 中包含 `CheckAppVersionUrl` 與 `CheckResourceVersionUrl` 欄位。
- 用戶端可存取部署該介面的主機伺服器位址（請參考 `ResponseGlobalInfo.HostServerUrl` 欄位）。

## 作業步驟

1. 確認伺服器全域資訊介面的回應 JSON 中兩個 URL 欄位皆有回傳，且欄位名稱必須與用戶端模型嚴格一致：

   ```json
   {
     "CheckAppVersionUrl": "https://your-cdn.example.com/api/app/version",
     "CheckResourceVersionUrl": "https://your-cdn.example.com/api/resource/version"
   }
   ```

2. 用戶端解析該 JSON 後，直接讀取 `ResponseGlobalInfo` 中的兩個字串屬性。這兩個屬性皆為 `string`，預設值為 `null`。

   ```csharp
   using GameFrameX.GlobalConfig.Runtime;

   var info = new ResponseGlobalInfo
   {
       CheckAppVersionUrl      = "https://your-cdn.example.com/api/app/version",
       CheckResourceVersionUrl = "https://your-cdn.example.com/api/resource/version",
       HostServerUrl           = "https://your-cdn.example.com",
       AOTCodeList             = "[]",
       Content                 = "{}"
   };
   ```

   Source: [Runtime/GlobalConfig/ResponseGlobalInfo.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGlobalInfo.cs#L1-L28)

3. 將取得的 URL 分別傳遞給應用程式版本檢查與資源版本檢查模組，以發起對應的請求物件：

   ```csharp
   // 應用程式版本檢查請求
   var appVersionReq = new RequestGameAppVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAppVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAppVersion.cs)

4. 資源版本檢查使用獨立的請求物件，其欄位同樣是平台、渠道、語言等基本資訊：

   ```csharp
   var assetReq = new RequestGameAssetPackageVersion
   {
       AppVersion = Application.version,
       Platform   = Application.platform.ToString(),
       PackageName = Application.identifier,
       Channel    = "default",
       Language   = "zh-CN"
   };
   ```

   Source: [Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/RequestGameAssetPackageVersion.cs)

5. 伺服器處理應用程式版本檢查請求時會回傳 `ResponseGameAppVersion`，其中包含 `IsForce`、`IsUpgrade`、`AppDownloadUrl`、`UpdateAnnouncement`、`UpdateTitle` 等升級資訊：

   ```csharp
   public class ResponseGameAppVersion
   {
       public bool   IsForce           { get; set; }
       public string AppDownloadUrl    { get; set; }
       public bool   IsUpgrade         { get; set; }
       public string UpdateAnnouncement{ get; set; }
       public string UpdateTitle       { get; set; }
   }
   ```

   Source: [Runtime/GlobalConfig/ResponseGameAppVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.globalconfig/blob/main/Runtime/GlobalConfig/ResponseGameAppVersion.cs#L1-L33)

## 常見變體

- **重複使用相同位址**：若應用程式與資源版本檢查共用同一個閘道，可讓兩個 URL 回傳相同位址，並在閘道內以 path 路由區分。
- **漸進式拆分伺服器**：若不同渠道（`Channel`）使用不同的 URL，只需在伺服器端依據請求內文中的 `Channel` 欄位回傳對應位址即可，用戶端程式碼無需變更。

## 常見錯誤

- **欄位名稱拼寫錯誤**：介面欄位名稱必須為 `CheckAppVersionUrl`、`CheckResourceVersionUrl`，首字母大寫並採用駝峰式命名法。否則 `ResponseGlobalInfo` 反序列化後兩個屬性都會是 `null`。
- **未準備 HTTPS**：URL 必須使用 HTTPS，否則在 Android 9+ 上會被預設網路政策封鎖。
- **忘記配置主機位址**：若 `CheckAppVersionUrl` 實際上只傳遞相對路徑或子網域，實際存取時還需要 `ResponseGlobalInfo.HostServerUrl`，否則請求將找不到主機。

## 背景（選用）

`ResponseGlobalInfo` 是 GlobalConfig 套件中定義的最簡單 DTO，僅負責「將位址告知用戶端」的角色。套件內沒有內建 HTTP 用戶端，實際的請求與快取由上層業務模組基於 `RequestGameAppVersion` / `RequestGameAssetPackageVersion` 發起，並與全域配置解耦，方便整合各種網路堆疊。
