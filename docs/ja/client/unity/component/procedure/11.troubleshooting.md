# 常见问题

本文档汇总了在使用 GameFrameX Procedure フロー管理コンポーネント时可能遇到的常见问题、错误及其解決策。

## 概要

Procedure フロー管理コンポーネント是基づく Game Framework 的有限状態機械（FSM）実装的ゲームフロー管理系统。在集成和使用过程中，開発者经常会遇到配置错误、依赖缺失、クラス型解析失败等问题。本文档旨在帮助開発者快速定位和解决这些问题。

## 依赖问题

### FSMComponent 未正确配置

**症状**: ゲーム启动后无响应或报 `Procedure manager is invalid.` 错误

**原因**: ProcedureComponent 依赖 `IProcedureManager` 模块，该模块必要を通じて `GameFrameworkEntry` 取得。如果 FSMComponent 未正确初期化，可能导致模块取得失败。

**解決策**:
1. 确保シーン中已添加 `FSMComponent` コンポーネント
2. 确认 `GameFrameworkEntry` 已正确初期化所有必須模块
3. 检查 GameFramework 的初期化顺序，确保先初期化基础コンポーネント

> Source: [ProcedureComponent.cs#L64-L68](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L64-L68)

---

### 缺少必要的 GameFramework コンポーネント

**症状**: 运行时出现 NullReferenceException 或模块取得失败

**原因**: GameFramework 是一套完整的コンポーネント体系，Procedure コンポーネント依赖多个底层模块

**解決策**:
1. 确保已安装 GameFrameX コア库
2. 检查プロジェクト是否包含以下依赖:
   - `GameFrameX.Fsm.Runtime` - 有限状態機械模块
   - `GameFrameX.Runtime` - コア运行时模块

## 設定问题

### フロークラス型名称配置错误

**症状**: 控制台显示 `Can not find procedure type '{0}'.` 错误

**原因**: `m_AvailableProcedureTypeNames` 数组中配置的フロークラス型名称与实际クラス名不匹配

**解決策**:
1. 检查 Inspector 面板中的 `Available Procedure Type Names` 配置
2. 确保クラス型名称使用完整的クラス名（包括名前空間）
3. フロークラス必須を継承 `ProcedureBase`

```csharp
// 正确示例
namespace MyGame.Procedure
{
    public class ProcedureLaunch : ProcedureBase
    {
        // フロー実装
    }
}
```

配置时填入: `MyGame.Procedure.ProcedureLaunch`

> Source: [ProcedureComponent.cs#L76-L81](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L76-L81)

---

### エントリーポイントフロー未設定

**症状**: 控制台显示 `Entrance procedure is invalid.` 错误

**原因**: `m_EntranceProcedureTypeName` 未設定或設定的值不在 `m_AvailableProcedureTypeNames` 列表中

**解決策**:
1. 在 Inspector 面板中設定 `Entrance Procedure Type Name`
2. 确保エントリーポイントフロー名称与 `Available Procedure Type Names` 中的某个フロー完全匹配
3. エントリーポイントフロー是ゲーム启动后第一个执行的フロー

> Source: [ProcedureComponent.cs#L90-L100](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L90-L100)

---

### フロー数组为空

**症状**: 启动时无任何フロー执行，或出现数组越界错误

**原因**: `m_AvailableProcedureTypeNames` 未配置或为空

**解決策**:
1. 在 ProcedureComponent 的 Inspector 面板中，至少添加一个フロークラス型
2. 建议至少包含以下基础フロー:
   - 启动フロー (ProcedureLaunch)
   - ホットアップデートフロー (ProcedureCheckVersion)
   - 登录フロー (ProcedureLogin)
   - ゲームフロー (ProcedureGame)

## クラス型解析问题

### 程序集クラス型取得失败

**症状**: `Utility.Assembly.GetType()` 返回 null，导致フロー作成失败

**原因**:
1. クラス型名称拼写错误
2. フロークラス未编译到程序集中
3. 使用了错误的程序集配置

**解決策**:
1. 确认フロークラス已正确编译
2. 使用完整的クラス型名称（包括名前空間）
3. 对于混淆后的代码，确保関連程序集配置正确

```csharp
// 错误的クラス型名称
m_AvailableProcedureTypeNames = new[] { "ProcedureLaunch" };

// 正确的クラス型名称
m_AvailableProcedureTypeNames = new[] { "GameFrameX.Procedure.Runtime.ProcedureLaunch" };
```

> Source: [ProcedureComponent.cs#L83-L88](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L83-L88)

---

### フローインスタンス作成失败

**症状**: `Can not create procedure instance '{0}'.` 错误

**原因**:
1. フロークラス缺少无参构造函数
2. 构造函数抛出異常
3. フロークラス的构造函数访问了尚未初期化的系统

**解決策**:
1. 确保フロークラス具有无参构造函数
2. 不要在构造函数中访问 ProcedureManager 或其他 GameFramework コンポーネント
3. 使用 `OnInit`、`OnEnter` 等生命周期メソッド进行初期化

```csharp
// 推荐: 在 OnEnter 中进行初期化
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // 在这里进行初期化操作
    }
}
```

## 运行时问题

### フロー管理器未初期化

**症状**: 呼び出し `CurrentProcedure` 或 `CurrentProcedureTime` 时抛出異常 `You must initialize procedure first.`

**原因**: 在 ProcedureManager 初期化完成之前访问了関連プロパティ

**解決策**:
1. 确保在 `Start()` メソッド执行完毕后再访问フロー管理器
2. 使用コルーチン或イベント系统等待初期化完成

```csharp
// 错误示例: 在 Awake 中立即访问
private void Awake()
{
    var current = CurrentProcedure; // 会抛出異常
}

// 正确示例: 在コルーチン中等待
private IEnumerator Start()
{
    yield return new WaitForEndOfFrame();
    var current = CurrentProcedure; // 现在可能正常访问
}
```

> Source: [ProcedureManager.cs#L48-L55](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L48-L55)

---

### フロー切换失败

**症状**: 呼び出し `StartProcedure<T>()` 后フロー未切换

**原因**:
1. 指定的フロークラス型未在初期化时注册
2. FSM ステータス机已被销毁
3. フロー切换逻辑存在死循环

**解決策**:
1. 确保要切换的目标フロー在 `m_AvailableProcedureTypeNames` 中
2. 检查是否有代码在フロー切换时立即切回原フロー
3. 使用调试日志确认切换呼び出し是否执行

> Source: [ProcedureManager.cs#L116-L124](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L116-L124)

---

### フローステータスメソッド未被呼び出し

**症状**: 自定义的 `OnEnter`、`OnUpdate`、`OnLeave` 等メソッド未被执行

**原因**: フロークラス未正确继承 `ProcedureBase`，或メソッド未正确重写

**解決策**:
1. 确保フロークラスを継承 `ProcedureBase`
2. 使用 `override` 关键字重写父クラスメソッド
3. 呼び出し `base.OnEnter()` 等メソッド以确保父クラス逻辑执行

```csharp
// 正确示例
public class ProcedureLogin : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner); // 必須呼び出し
        // 自定义逻辑
    }
}
```

> Source: [ProcedureBase.cs#L31-L35](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L31-L35)

## 调试技巧

### 启用调试日志

在开发过程中，可能添加详细的日志输出来帮助定位问题:

```csharp
public class ProcedureLaunch : ProcedureBase
{
    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        Debug.Log("进入 ProcedureLaunch フロー");
    }

    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);
        Debug.Log($"ProcedureLaunch 已运行 {procedureOwner.CurrentStateTime:F2} 秒");
    }
}
```

### 检查フローステータス

可能使用 `ProcedureComponent` 提供的メソッド检查フローステータス:

```csharp
// 检查是否存在指定フロー
bool hasLogin = procedureComponent.HasProcedure<ProcedureLogin>();

// 取得当前フロー
ProcedureBase current = procedureComponent.CurrentProcedure;

// 取得フロー持续时间
float duration = procedureComponent.CurrentProcedureTime;
```
