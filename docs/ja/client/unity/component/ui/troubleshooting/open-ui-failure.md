# UIフォームを開けないときの対処方法

`OpenUIForm` / `OpenUIFormAsync` を呼び出してもUIフォームが表示されない、または `OpenUIFormFailureEventArgs` イベントを受け取った場合は、このページの診断表に従って原因を特定し、修正できます。よくある失敗原因は**リソース未登録、UIグループが存在しない、スクリプティング定義シンボルの欠落、スクリプト未アタッチ**のいずれかに集中しています。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `OpenUIForm` が返すインスタンスが `null` になる、または `OpenUIFormFailureEventArgs.ErrorMessage` にリソースが見つからない旨が表示される | `uiFormAssetName` が UI コンポーネントに登録されていない(設定漏れまたはスペルミス) | UIForm 設定でリソース名を補完し、`UIFormAssetName` が呼び出し側から渡される値と完全に一致していることを確認する |
| UI グループ / UIGroup が見つからない旨のエラーが表示される | 渡された `uiGroupName` が存在しない | 先に `AddUIGroup` を呼び出してグループを追加するか、登録済みのグループ名を渡す |
| `UIComponent` 全体でエラーが発生する、または `OpenUIForm` を呼び出せない | プロジェクトで `GameFrameX.UI` スクリプティング定義シンボルが有効になっていない | エディターで `UISystemScriptingDefineCheckHandler` を使ってスクリプティング定義シンボルを補完する、または Player Settings に `GameFrameX.UI` を追加する |
| リソースは存在するがUIフォームを開いてもロジックが動作しない | UIForm プレハブに対応するロジックスクリプトがアタッチされていない | `UIForm` プレハブに正しいロジッククラスのコンポーネントをアタッチする |
| `OpenUIFormFailureEventArgs` が一度も発火しないのに、UIフォームも表示されない | イベントを購読していないため、失敗が黙って握りつぶされている | `OpenUIFormSuccessEventArgs` / `OpenUIFormFailureEventArgs` を購読してから呼び出す |
| `uiFormAssetPath` と `uiFormAssetName` を混同し、非同期ロードが失敗する | 呼び出し時に「パス」と「リソース名」を入れ替えている | 次のように区別する:設定に入力するのは `UIFormAssetName`(論理名)、`uiFormAssetPath` はリソースのアドレス |

## 修正手順

### 1. リソース未登録 / 名前のスペルミス

UI 設定を開き、該当する UIForm の `UIFormAssetName` フィールドが入力済みであること、およびその名前が `OpenUIForm` の呼び出しと一致していることを確認します。

```csharp
// 呼び出し側:名前は UIFormInspector の m_UIFormAssetName と一致している必要があります
UIComponent.OpenUIForm("ShopUI", "Normal");
```

`UIForm` プレハブで使用可能なフィールドについては [UIFormInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UIFormInspector.cs#L92-L110) を参照してください。

### 2. UI グループが存在しない

`uiGroupName` は、`AddUIGroup` によって登録済みのグループ名である必要があります。よくあるケース:他人のコードをコピーしたが、`Window`、`Popup` などのカスタムグループの登録を忘れている。

### 3. スクリプティング定義シンボルが有効になっていない

`UIComponent` のすべてのインターフェースは、スクリプティング定義シンボル `GameFrameX.UI` に依存しています。一度も有効にしたことがない場合、呼び出しは即座にエラーになります。実行時に [UISystemScriptingDefineCheckHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UISystemScriptingDefineCheckHandler.cs) によって、エディター内で自動的にチェックと補完が行われます。

### 4. 失敗イベントを購読して真のエラーを特定する

戻り値だけで判断しないでください。`OpenUIFormFailureEventArgs` を購読すれば完全なエラースタックを取得でき、見当をつけるよりも速く原因を特定できます。

```csharp
// README.md のサンプルより
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnUIFormOpenFailure);
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnUIFormOpenSuccess);

private void OnUIFormOpenFailure(object sender, GameEventArgs e)
{
    var args = (OpenUIFormFailureEventArgs)e;
    Debug.LogError($"UIフォーム {args.UIFormAssetName} のオープンに失敗しました: {args.ErrorMessage}");
}
```

`ErrorMessage`、`UIFormAssetName`、`SerialId`、`UserData` のフィールド定義については [OpenUIFormFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormFailureEventArgs.cs#L88-L131) を参照してください。

### 5. UIForm プレハブにロジックスクリプトがアタッチされていない

UIフォームが「開いた」ように見えてもロジック(`OnInit`、`OnOpen`、`OnUpdate`)が実行されない場合は、通常、プレハブに `IUIForm` ロジックコンポーネントが不足しています。該当するプレハブを開き、`UIForm` を継承したスクリプトをルートノードにアタッチしてください。

## 検証

以下の順序で項目ごとに確認します:

1. Console に `OpenUIFormSuccessEventArgs` が発火していれば、オープン成功です。
2. `OnUIFormOpenFailure` 内で `ErrorMessage` を `Debug.LogError` で出力し、メッセージのキーワード(例:"not found"、"has not been")から上記の診断表に戻って原因を特定します。
3. UIフォームを閉じて開き直し、シーンの切替で UI の状態が失われないことを確認します。
4. Editor で `UIForm` コンポーネントの Inspector(`UIFormAssetName`、`FullName`、`SerialId`)が正常に表示されていることを確認します。
