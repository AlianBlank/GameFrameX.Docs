# 存取 GameApp.{Name} 回傳 null 或擲出 Null Reference 時的處理方式

存取 `GameApp.XXX`（例如 `GameApp.Asset`、`GameApp.Base`）時回傳 `null` 或擲出 `NullReferenceException`，通常是因為對應的元件在啟動時未註冊到 `GameEntry`，或是在框架初始化完成前就存取該屬性。`GameApp` 只是 `GameEntry.GetComponent<T>()` 的快取封裝；實際的元件實例是由 `GameEntry` 管理的。

## 快速診斷

| 症狀 | 原因 | 修正方式 |
|------|------|------|
| `GameApp.XXX` 回傳 `null` | 對應的元件未註冊到 `GameEntry`，或未啟用對應的巨集/條件編譯 | 確認元件類別已掛載到 `GameEntry` 的啟動 prefab/註冊流程，並啟用對應的巨集（例如 `ENABLE_GAME_FRAME_X_ASSET`） |
| 在 `Awake`/`Start` 早期階段存取 `GameApp.XXX` 時出現 null | 框架初始化尚未完成 | 在框架初始化回呼（例如 `GameEntry.OnGameFrameInitialized`）之後呼叫，或在業務腳本的 `OnEnable` 之後呼叫 |
| 擲出 `NullReferenceException: Object reference not set to an instance of an object` | 呼叫前未做空值檢查，且元件未註冊 | 加上空值檢查，並依照上兩列所述修正註冊/呼叫時機 |
| 擲出 `KeyNotFoundException` / 找不到元件類型 | 專案未包含元件的 DLL/組件，或命名空間不一致 | 確認已參考包含該元件的組件，並加上 `using GameFrameX.Runtime;` |
| 啟用/停用巨集後突然變成 null | 元件被 `#if` 條件編譯完全排除，`GameApp.XXX` 欄位不存在 | 不要在 `#if` 區塊之外存取該屬性；改用 `GameEntry.GetComponent<T>()` 作為備援方案 |

## 修復步驟

### 1. 確認元件已註冊到 GameEntry

`GameApp` 本質上是從 `GameEntry` 延遲取得元件的實作：

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }

    private static BaseComponent _base;
}
```

來源：[Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L52)

如果 `GameEntry.GetComponent<BaseComponent>()` 找不到元件，`_base` 會一直是 `null`。請檢查 `BaseComponent` 等元件是否已在啟動流程中掛載到 `GameEntry` 的初始化清單。

### 2. 檢查條件編譯巨集

許多 `GameApp.XXX` 屬性都以巨集包裝。例如 `GameApp.Asset` 需要 `ENABLE_GAME_FRAME_X_ASSET`：

```csharp
#if ENABLE_GAME_FRAME_X_ASSET
public static partial class GameApp
{
    public static AssetComponent Asset
    {
        get
        {
            if (_asset == null)
            {
                _asset = GameEntry.GetComponent<AssetComponent>();
            }
            return _asset;
        }
    }

    private static AssetComponent _asset;
}
#endif
```

來源：[Runtime/GameApp.Asset.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs#L32-L55)

如果未定義對應的巨集，`GameApp.Asset` 屬性在編譯時期並不存在，直接存取會導致編譯錯誤。反之，**若您啟用了巨集並在程式碼中使用對應的 `GameApp.XXX`，也必須確保對應的元件已註冊到 `GameEntry`**。

### 3. 在框架初始化完成後再存取

`GameApp` 的欄位是延遲載入的靜態快取。如果在框架的 `Awake` 之前的生命週期階段存取它們（例如在另一個單例的 `Awake` 中），元件可能尚未註冊完成。請在框架初始化事件觸發後，或在業務腳本的 `OnEnable` / `Start` 中再存取。

### 4. 加上空值檢查保護

即使元件已註冊，仍建議在呼叫前進行空值檢查，以避免在編輯器中停止遊戲時或資源釋放階段存取它：

```csharp
if (GameApp.Asset != null)
{
    GameApp.Asset.LoadAsset(...);
}
```

如果經常需要做空值檢查，表示原本就不應該在那裡使用該元件——請回到步驟 1 檢查註冊。

## 驗證

執行以下 3 個步驟來確認問題已解決：

1. 在 `Awake` 中印出 `GameApp.Base` 等關鍵屬性，確認它們不是 `null`。
2. 使用 `GameEntry.GetComponent<T>()` 再次確認元件確實存在。
3. 在場景中觸發實際呼叫（例如載入資源、觸發事件），觀察是否仍會發生 null 參考。

如果 `GameEntry.GetComponent<T>()` 一直回傳 `null`，問題就出在元件註冊流程本身，而不是 `GameApp` 這一層——請回到 `GameEntry` 的初始化程式碼，檢查元件掛載與生命週期順序。
