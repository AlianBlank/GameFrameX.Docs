# XOR 간단한 암복호화 사용 방법

`XorHelper`는 XOR 연산 기반의 경량 암복호화 도구를 제공하며, 동일한 키로 데이터에 대해 두 번 XOR을 수행하면 원문을 복원할 수 있어 설정 파일이나 메모리 내 임시 바이트 스트림의 간단한 난독화에 적합합니다. 주의: 이것은 암호학적으로 안전한 방식이 아니므로 기밀성이 필요한 시나리오에는 사용할 수 없습니다.

## 사전 조건

- NuGet 패키지 `GameFrameX.Foundation.Encryption` 참조(또는 `GameFrameX.Foundation.Encryption/XorHelper.cs` 직접 참조).
- `using GameFrameX.Foundation.Encryption;` 네임스페이스 사용.

## 작업 단계

### 1. 가장 간단한 암복호화

`XorHelper.GetXorBytes(byte[], byte[])`을 호출하여 한 번 XOR을 수행한 다음, 동일한 키로 다시 한 번 호출하면 복호화됩니다. 두 번의 호출은 완전히 대칭적이며, 암복호화 메서드 구분이 없습니다.

```csharp
using System.Text;
using GameFrameX.Foundation.Encryption;

var keyBytes = Encoding.UTF8.GetBytes("MySecretKey123");
var dataBytes = Encoding.UTF8.GetBytes("Hello, World! 这是一个测试字符串。");

// 암호화
var encrypted = XorHelper.GetXorBytes(dataBytes, keyBytes);
// 복호화(동일한 키로 다시 한 번 호출)
var decrypted = XorHelper.GetXorBytes(encrypted, keyBytes);

Console.WriteLine(Encoding.UTF8.GetString(decrypted)); // 원문 출력
```

Source: [XorHelper.cs#L133-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L133-L144)

### 2. "제자리 수정" 버전으로 메모리 절약

입력 배열을 더 이상 원문으로 유지할 필요가 없다면, `GetSelfXorBytes`를 사용하여 입력 배열을 직접 수정할 수 있으며 새 바이트 스트림을 추가로 할당하지 않습니다.

```csharp
var dataBytes = Encoding.UTF8.GetBytes("payload");
var keyBytes = Encoding.UTF8.GetBytes("key");

// dataBytes에서 직접 XOR 수행, 새 배열 반환하지 않음
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
// 다시 한 번 호출하여 복원
XorHelper.GetSelfXorBytes(dataBytes, keyBytes);
```

Source: [XorHelper.cs#L158-L169](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Encryption/XorHelper.cs#L158-L169)

### 3. 데이터의 앞쪽 220바이트만 암호화(빠른 모드)

프로토콜 헤더와 같은 대용량 바이트 스트림에서 가벼운 난독화가 필요하지만 전체 배열을 순회하고 싶지 않을 때, `GetQuickXorBytes` / `GetQuickSelfXorBytes`를 사용합니다. 둘 다 앞쪽의 `QuickEncryptLength`(기본값 220)바이트만 XOR 처리하며, 그 외 부분은 원본 값을 유지합니다.

```csharp
var buffer = new byte[1024];           // 프로토콜 헤더 + 후속 페이로드
var key = Encoding.UTF8.GetBytes("k");

// 앞쪽 220바이트만 난독화, 이후 바이트는 그대로 유지
var encrypted = XorHelper.GetQuickXorBytes(buffer, key);
// 복원할 때도 앞쪽 220바이트만 처리
var restored = XorHelper.GetQuickXorBytes(encrypted, key);
```

### 4. 배열의 특정 구간만 암호화

`startIndex`와 `length` 매개변수를 사용하는 오버로드를 통해 지정된 범위에만 XOR을 수행할 수 있으며, "헤더/중간 특정 구간만 난독화" 등의 시나리오에 적합합니다.

```csharp
var data = new byte[] { 1, 2, 3, 4, 5, 6, 7, 8 };
var key  = Encoding.UTF8.GetBytes("MySecretKey123");

// 인덱스 2에서 시작하는 4바이트만 암호화
var result = XorHelper.GetXorBytes(data, 2, 4, key);
// data[0..2]와 data[6..8]은 변경되지 않음
```

## 일반적인 변형

### 키가 데이터보다 길거나 짧거나 단일 문자 키

XOR 알고리즘은 키 길이에 제한이 없으며, 길거나 짧거나 모두 올바르게 암복호화할 수 있습니다. 테스트는 단일 문자, 3바이트, 14바이트, 34바이트 등 다양한 키를 다루며, 키가 비어있지 않은 한 왕복 복원이 가능합니다.

Source: [XorHelperTests.cs#L82-L116](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Encryption/XorHelperTests.cs#L82-L116)

### 문자열 왕복

문자열을 직접 `Encoding.UTF8.GetBytes`로 변환하여 전달하고, 결과를 다시 `Encoding.UTF8.GetString`로 변환하여 가져옵니다. 설정 파일의 민감한 필드에 적합합니다.

## 일반적인 오류

| 잘못된 방법 | 증상 | 올바른 방법 |
|----------|------|----------|
| `GetXorBytes` 반환 결과를 새 배열로 다시 수정 | 난독화 범위가 어긋남 | `GetXorBytes` 반환값을 사용하거나, 명시적으로 `Array.Copy` 후 `GetSelfXorBytes`에 전달 |
| `code`에 `Array.Empty<byte>()` 전달 | `ArgumentException("KeyArrayCannotBeEmpty")` 발생 | 최소 1바이트 이상의 키 사용 |
| 220바이트 내의 완전한 데이터를 `GetQuickXorBytes`로 처리할 때, 그 외 부분도 암호화될 것으로 기대 | 데이터 후반부가 원본 그대로 유지됨 | 전체 암호화가 필요하면 `GetXorBytes` 사용 |
| `startIndex + length`이 배열 길이를 초과 | `ArgumentOutOfRangeException` 발생 | 먼저 `startIndex + length <= bytes.Length` 검증 |
| 계정 비밀번호 / 전송 키로 사용 | 알려진 평문 공격으로 쉽게 해독 가능 | 우발적인 읽기 방지를 위한 난독화로만 사용; 비밀 보장이 필요한 시나리오는 진정한 대칭 암호화 알고리즘 사용 |

## 배경(선택 사항)

XOR 연산은 본질적으로 `(A ^ K) ^ K == A`를 만족하므로, 동일한 인터페이스로 암복호화가 모두 가능합니다. `QuickEncryptLength = 220`은 프로토콜 헤더 시나리오를 위해 설정된 경험적 값으로, 보안과 성능 사이의 절충안입니다. 모든 공개 메서드는 먼저 `ArgumentNullException.ThrowIfNull`과 `code.Length == 0` 검증을 수행하며, offset/length를 사용하는 오버로드는 `startIndex + length <= bytes.Length`도 추가로 검증합니다.
