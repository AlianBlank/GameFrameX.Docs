# カスタム型のインポーター/エクスポーターの登録方法

`JsonMapper.RegisterExporter<T>` と `JsonMapper.RegisterImporter<TJson, TValue>` を使用することで、任意の型に対してカスタムの JSON シリアライズ/デシリアライズロジックを登録できます。シリアライズ時はエクスポーターが書き込み形式を制御し、デシリアライズ時はインポーターが JSON 値をターゲット型へ変換します。

## 前提条件

- `GameFrameX.LitJSON.Runtime.JsonMapper` が参照済みであること。
- ターゲット型が既に存在すること（例：カスタム構造体、サードパーティライブラリのクラス、または Unity 内蔵でカバーされていない型）。
- プログラムの起動時に自動的に一度だけ登録したい場合は、`[RuntimeInitializeOnLoadMethod]` または静的コンストラクターを使用してください。

## 操作手順

### 1. エクスポーター（Exporter）を実装する

エクスポーターは、ターゲット型のインスタンスと `JsonWriter` を受け取り、オブジェクトを JSON に書き込みます。デリゲートのシグネチャは `ExporterFunc<T>(T obj, JsonWriter writer)` に固定されています。

```csharp
using GameFrameX.LitJSON.Runtime;

// カスタム構造体を JSON オブジェクトとして書き込む（2つのフィールドを含む）
public struct MyRange
{
    public float Min;
    public float Max;
}

JsonMapper.RegisterExporter<MyRange>((v, w) =>
{
    w.WriteObjectStart();
    w.WriteProperty("min", v.Min);
    w.WriteProperty("max", v.Max);
    w.WriteObjectEnd();
});
```

Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L50-L58)

### 2. インポーター（Importer）を実装する

インポーターは、JSON 内の生の値（`JsonReader` から取得）を受け取り、ターゲット型のインスタンスを返します。デリゲートのシグネチャは `ImporterFunc<TJson, TValue>(TJson input)` に固定されています。

```csharp
JsonMapper.RegisterImporter<string, MyRange>((input) =>
{
    // input は JsonReader の現在のトークン由来。単純なケースではそのまま string として扱える
    // 複雑な構造の場合は先に ReadObject を呼び出し、その後フィールド単位で読み取る必要がある
    // ここでは string -> MyRange の最小限の動作形態のみを示す
    var parts = input.Split(',');
    return new MyRange
    {
        Min = float.Parse(parts[0]),
        Max = float.Parse(parts[1]),
    };
});
```

Source: [JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs#L1395-L1427)

### 3. プログラム起動時に自動登録する

重複登録を避けるため、`UnityTypeBindings` のように静的コンストラクター + 冪等フラグ、または `RuntimeInitializeOnLoadMethod` を使用することをお勧めします：

```csharp
using GameFrameX.LitJSON.Runtime;
using UnityEngine;

public static class MyJsonBindings
{
    private static bool _registered;

    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    public static void Init()
    {
        if (_registered) return;
        _registered = true;

        JsonMapper.RegisterExporter<MyRange>((v, w) =>
        {
            w.WriteObjectStart();
            w.WriteProperty("min", v.Min);
            w.WriteProperty("max", v.Max);
            w.WriteObjectEnd();
        });

        JsonMapper.RegisterImporter<string, MyRange>((s) =>
        {
            var p = s.Split(',');
            return new MyRange { Min = float.Parse(p[0]), Max = float.Parse(p[1]) };
        });
    }
}
```

Source: [UnityTypeBindings.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/UnityTypeBindings.cs#L19-L58)

### 4. 通常どおり `ToJson` / `ToObject` を呼び出す

登録が完了すると、フレームワークの `JsonMapper.ToJson(obj)` と `JsonMapper.ToObject(json, typeof(T))` は登録されたエクスポーターとインポーターを自動的に呼び出すため、追加のパラメータを渡す必要はありません。

```csharp
var r = new MyRange { Min = 1f, Max = 5f };
string json = JsonMapper.ToJson(r);     // RegisterExporter<MyRange> 経由
var back = JsonMapper.ToObject(json, typeof(MyRange)); // RegisterImporter<..., MyRange> 経由
```

## よくあるバリエーション

| シナリオ | 方法 |
|------|------|
| 列挙型を文字列として書き込む | `RegisterExporter<MyEnum>((v, w) => w.Write(v.ToString()))` |
| 文字列を列挙型に復元する | `RegisterImporter<string, MyEnum>(s => (MyEnum)Enum.Parse(typeof(MyEnum), s))` |
| エクスポーター内で配列を書き込む | `w.WriteArrayStart(); ... ; w.WriteArrayEnd();` |
| すべてのカスタムエクスポーターをクリアしたい | `JsonMapper.UnregisterExporters();` |
| インポーターで JSON オブジェクトを読み込む必要がある | `ImporterFunc` 内で自分で `JsonReader` を作成し、`ReadObject/ReadProperty` を呼び出す |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `ToObject` が `null` またはデフォルト値を返す | このターゲット型に対して Importer が登録されていない | `JsonMapper.RegisterImporter<TJson, TValue>` を呼び出す |
| シリアライズ結果が空文字列または `{}` になる | 登録のタイミングが初回の `ToJson` より遅い | 登録を `RuntimeInitializeOnLoadMethod` または静的コンストラクターに移動する |
| 重複登録で例外がスローされる、または上書きによる問題が発生する | 登録は上書き式（テーブルへの直接書き込み）であり、同じ型に対して重複登録すべきではない | `_registered` フラグで一度だけ実行されるようにする |
| インポーター内で `input` にアクセスすると型変換エラーが発生する | `TJson` が JSON の実際の型と一致しない | `JsonReader` のトークンと一致する `TJson` を選択する（一般的には `string` / `double` / `bool` / `IDictionary` / `IList`） |
| ImporterFunc 内でフィールドを読み取れない | ImporterFunc の引数は単一のトークンであり、オブジェクトを直接走査できない | `RegisterImporter` 内で自分で `new JsonReader(json)` し、フィールド単位で読み取る |

## 背景

LitJSON はカスタムコンバーターを 2 つの静的テーブル（`custom_exporters_table` と `custom_importers_table`）で管理し、`custom_table_lock` によって書き込みを直列化しています。登録は**上書き式**であり累積式ではないため、同じ `(T)` / `(TJson, TValue)` に対して一度だけ登録されることを保証する必要があります。そうでない場合、後から登録されたものによって上書きされます——これがリポジトリ内の `UnityTypeBindings._registered` フラグの目的でもあります。
