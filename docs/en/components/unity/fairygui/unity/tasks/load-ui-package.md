# Loading and Unloading UI Packages

In the FairyGUI Unity runtime, loading a UI package means calling the `UIPackage.AddPackage` family of static methods to register the published `_fui` description file and its assets into the global package list; only after that can components be created with `UIPackage.CreateObject`. Unloading means calling `UIPackage.RemovePackage` / `RemoveAllPackages` to release all assets in the package. All APIs are centralized in [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L311).

## Prerequisites

- The UI package has been published with the FairyGUI editor, producing a `包名_fui.bytes` description file along with asset files.
- The description file is placed under the Unity `Resources` directory (or provided via AssetBundle / a custom loader).

## Steps

1. **Put the published output into the project**: Place `包名_fui.bytes` (along with assets such as images and sounds) into a subdirectory under the `Resources` directory, for example `Assets/Resources/UI/Basics`. The description file name must end with `_fui`; the runtime automatically concatenates `assetPath + "_fui"` and `".bytes"` when loading (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L324-L325)).

2. **Load the package**: Call `AddPackage(string descFilePath)` with a Resources-relative path. The path does not include the `_fui` suffix, for example:

```csharp
// Path is relative to the Resources directory, without the _fui suffix
UIPackage.AddPackage("UI/Basics");
```

   Full implementation of this overload: when the path starts with `Assets/`, it is only available in the Editor (it goes through `_loadFromAssetsPath`); otherwise the path is loaded as a Resources-relative path. See [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L298-L311).

3. **(Optional) Check for duplicates before loading**: Repeated `AddPackage` calls register multiple package instances, so check whether the package has already been loaded first. The `UIPainter` in this repository does exactly that:

```csharp
if (!string.IsNullOrEmpty(packagePath) && UIPackage.GetByName(packageName) == null)
    UIPackage.AddPackage(packagePath);
```

Source: [UIPainter.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPainter.cs#L64-L66)

4. **Create a component to verify the load succeeded**:

```csharp
public static GObject CreateObject(string pkgName, string resName)
{
    UIPackage pkg = GetByName(pkgName);
    if (pkg != null)
        return pkg.CreateObject(resName);
    else
        return null;
}
```

Source: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L512-L519)

   Call it like `UIPackage.CreateObject("Basics", "MainMenu")`; you can also use `CreateObjectFromURL("ui://Basics/MainMenu")` (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L542-L547)).

5. **Unload the package**: When the UI is closed and the assets are no longer needed, unload by package name or package id:

```csharp
public static void RemovePackage(string packageIdOrName)
{
    UIPackage pkg = null;
    if (!_packageInstById.TryGetValue(packageIdOrName, out pkg))
    {
        if (!_packageInstByName.TryGetValue(packageIdOrName, out pkg))
            throw new Exception("FairyGUI: '" + packageIdOrName + "' is not a valid package id or name.");
    }

    pkg.Dispose();
    _packageInstById.Remove(pkg.id);
    ...
}
```

Source: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L458-L475)

   You pass in the package id **or** the package name; if nothing matches, it directly throws `FairyGUI: '...' is not a valid package id or name.`. To clear all packages at once, use `RemoveAllPackages()` (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L480-L495)).

## AddPackage Overload Quick Reference

| Overload | Signature | Use Case |
|------|------|----------|
| AssetBundle single bundle | `AddPackage(AssetBundle bundle)` | Description and assets are in the same bundle | 
| AssetBundle dual bundles | `AddPackage(AssetBundle desc, AssetBundle res)` | Description and assets are packed separately |
| AssetBundle + main asset name | `AddPackage(AssetBundle desc, AssetBundle res, string mainAssetName)` | Specifies the description file asset name, e.g. `Basics_fui` |
| Resources path | `AddPackage(string descFilePath)` | Description file is under Resources |
| Custom load function | `AddPackage(string assetPath, LoadResource loadFunc)` | Integrate with your own asset management system; repeated calls with the same path directly return the already-loaded package |
| Byte array | `AddPackage(byte[] descData, string assetNamePrefix, LoadResource loadFunc)` | Description data is already in memory |
| Async | `AddPackageAsync(string assetPath, Action<UIPackage> callback)` | Asynchronous loading; requires calling `SetAsyncLoadResource` first |

All of the above signatures come from [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L381).

Related query APIs: `GetByName(string name)`, `GetById(string id)`, `GetPackages()` (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L190-L211)).

## Common Variants

**Loading from an AssetBundle** (description and assets in the same bundle):

```csharp
public static UIPackage AddPackage(AssetBundle bundle)
{
    return AddPackage(bundle, bundle, null);
}
```

Source: [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L218-L221)

If no `_fui` description file is found in the bundle, it throws `FairyGUI: no package found in this bundle.`; when `desc` and `res` are two different bundles and `UIPackage.unloadBundleByFGUI` is `true` (the default), `desc.Unload(true)` is called immediately after the description file is loaded. See [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L269-L273).

**Custom load function** (integrating with the project's asset framework), as actually used in the Editor tools:

```csharp
UIPackage.AddPackage(assetPath,
    (string name, string extension, System.Type type, out DestroyMethod destroyMethod) =>
    {
        // Return the loaded asset, and specify the unload method via out destroyMethod
        ...
    });
```

Source: [EditorToolSet.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Editor/EditorToolSet.cs#L118-L119)

See [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L319-L325) for the `LoadResource` delegate signature: the description file is requested using `assetPath + "_fui"`, `".bytes"`, and `typeof(TextAsset)`, and the implementation decides how assets are destroyed via `out DestroyMethod`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Throws `FairyGUI: Cannot load ui package in '...'` | `loadFunc` returned null; the description file path is wrong or the file was not included in the build | Verify the path does not include the `_fui` suffix; confirm that `路径_fui.bytes` exists under `Resources`; at runtime (`Application.isPlaying`) it throws an exception directly, while in the Editor's non-play mode it only warns (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L326-L332)) |
| Throws `FairyGUI: no package found in this bundle.` | There is no TextAsset named with `_fui` inside the bundle | Re-publish and confirm the bundle contains the `包名_fui` description file, or explicitly pass in `mainAssetName` (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L252-L270)) |
| Throws `FairyGUI: '...' is not a valid package id or name.` | The value passed to `RemovePackage` is neither a package id nor a package name, or the package has already been unloaded | Use `UIPackage.GetByName` to confirm the package exists before unloading (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L460-L465)) |
| Loading `Assets/` paths fails with a warning on real devices (outside the Editor) | `AddPackage(string)` only works for paths starting with `Assets/` under `UNITY_EDITOR` | On real devices, use a Resources-relative path, AssetBundle, or a custom load function instead (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L300-L308)) |
| UI turns pink / textures are lost after unloading | The package has been `Dispose`d but components are still using its assets | Destroy all UI that uses the package first, then call `RemovePackage` |

## Verification

- After loading, calling `UIPackage.GetByName("Basics")` returns non-null, and `UIPackage.CreateObject("Basics", "组件名")` yields a non-null `GObject`.
- After unloading, `UIPackage.GetByName("Basics")` returns null, and the package no longer appears in the `GetPackages()` list.

## Background

All `AddPackage` overloads ultimately read the `包名_fui` description file as a `byte[]`, construct a `ByteBuffer`, and let `LoadPackage` parse out the asset manifest, then register the package keyed by package id and package name (as well as assetPath) into the three static collections `_packageInstById` / `_packageInstByName` / `_packageList`; `RemovePackage` first calls `Dispose` and then removes the package from these three collections (see [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L334-L346) and [UIPackage.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/UIPackage.cs#L466-L475)). This is the mechanism behind conventions such as "the path does not include `_fui`" and "you must deduplicate repeated loads yourself".
