# プラグイン紹介

GameFrameX Procedure フロー管理コンポーネントは、Unity ゲームフレームワークのコアモジュールの1つであり、ゲームのフローステータスを管理するために特化しています。このコンポーネントは有限状態機械（FSM）に基づいて実装されており、完全なゲームフローライフサイクル管理ソリューションを提供します。

## 概要

Procedure フロー管理コンポーネントは、ゲーム全体のフローロジックを構成および制御するために使用されます。ゲーム開発では、典型的なゲームフローには次のようなものが含まれます：起動フロー（Loading）、メニュースフロー（Menu）、ゲームフロー（Game）、一時停止フロー（Pause）、精算フロー（Settlement）など。このコンポーネントは、これらの複雑なフローロジックをモジュール化し、ゲームステータスの切り替えをより明確かつ制御可能で保守しやすくします。

このコンポーネントの中核となる設計思想は、各ゲームフローを有限状態機械内のステータスとして捉え、统一されたインターフェースを通じて管理することです。この設計パターンによりフロースイッチングのロジックが簡素化され、開発者に豊富なフックメソッドが提供されるため、フローの各ライフサイクル段階でカスタムロジックを挿入できます。

GameFrameX フレームワークのコアサブモジュールとして、Procedure コンポーネントは FSMComponent（有限状態機械コンポーネント）に依存して底層のステータス管理機能を実装しています。開発者は `ProcedureBase` クラスを継承してカスタムフローを作成し、フローマネージャーに登録できます。

## アーキテクチャ設計

このコンポーネントは分层アーキテクチャ設計を採用しており、上から順に：Unity コンポーネント層、フローマネジメント層、有限状態機械層となっています。この分层設計により、各層の責任が明確になり、結合度が低く、拡張性と保守性が確保されます。

### コアコンポーネントの説明

**ProcedureComponent** はフローシステム全体のエントリーポイントであり、Unity コンポーネントとしてシーン内の GameObject にアタッチされます。このコンポーネントは、ゲーム起動時にすべての利用可能なフローを初期化し、エントリーポイントフローに自動的に切り替わります。Inspector パネルの通じて、開発者は利用可能なフローの型名配列とエントリーポイントフローの型名を構成できます。

**IProcedureManager** はフローマネージャーの標準インターフェースを定義しており、現在のフローの取得、フローマネージャーの初期化、フローの開始、フローの存在確認、フローの取得などの中核操作が含まれています。すべてのフローマネジメント関連の機能は、このインターフェースを通じて外部に提供されます。

**ProcedureManager** は IProcedureManager インターフェースの具体的な実装クラスであり、内部で有限状態機械を使用してすべてのフローステータスを管理します。開発者は通常、このクラスを直接操作する必要はなく、ProcedureComponent または IProcedureManager インターフェースを通じて間接的に使用します。

**ProcedureBase** はすべてのカスタムフローの基底クラスであり、FsmState<IProcedureManager> を継承しています。開発者は ProcedureBase を継承したサブクラスを作成して具体的なフローロジックを実装する必要があります。基底クラスは OnInit、OnEnter、OnUpdate、OnFixedUpdate、OnLeave、OnDestroy などのライフサイクルフッomethドを提供します。

### 動作原理

ゲーム起動時、ProcedureComponent は Awake メソッドで IProcedureManager モジュールインスタンスを取得します。次に Start メソッドで、すべての 구성된利用可能なフローの型を走査し、リフレクションを通じてフローインスタンスを作成し、エントリーポイントフローを検索します。最後に、フローマネージャーの Initialize メソッドを呼び出して有限状態機械を初期化し、StartProcedure メソッドを呼び出してエントリーポイントフローを開始します。

フローが開始されると、有限状態機械の管理ステータスに入ります。各フローはライifecycleフッomethドの順序で実行されます：OnInit（初期化）→ OnEnter（進入）→ OnUpdate/OnFixedUpdate（ポーリング）→ OnLeave（離脱）→ OnDestroy（破棄）。開発者はこれらのフッomethドにそれぞろうのビジネスロジックを記述できます。

## コアコンセプト

### フロー（Procedure）

フローはゲーム内の独立したステータスまたは段階を表します。各フローには明確な責任があり、リソースの読み込み、メニューの表示、ゲームロジックの処理などが含まれます。フローは互いに切り替え可能であり、切り替え時に、対応するライフサイクルフッomethドがトリガーされます。

### エントリーポイントフロー（Entrance Procedure）

エントリーポイントフローは、ゲーム起動後に最初に実行されるフローです。ProcedureComponent の Inspector パネルで、m_EntranceProcedureTypeName プロパティを通じて構成できます。このフローは通常、ローディングフローまたはメニュースフローです。

### フローマネージャー（Procedure Manager）

フローマネージャーは、すべての登録済みフローの管理を担当します：フローの作成、初期化、切り替え、破棄などの操作を含みます。内部で有限状態機械を使用してこれらの機能を実装し、外部に统一されたインターフェースを提供して上位層が呼び出せるようにします。

### 有限状態機械（Finite State Machine）

有限状態機械は、フローシステム全体の底層実装です。各フローは有限状態機械内のステータスと見なされ、ステータス間の切り替えはステータス機械によって统一的に管理されます。この設計により、フロースイッチングロジックがシンプルで信頼できるようになります。

## 依存関係

Procedure コンポーネントは、次の GameFrameX コアモジュールに依存しています：

| 依存モジュール | 説明 | 機能 |
|-------------|------|------|
| FSMComponent | 有限状態機械コンポーネント | 有限状態機械の作成と管理機能を提供 |
| GameFrameworkEntry | フレームワークエントリーポイント | モジュールの登録と取得機能を提供 |
| GameFrameworkComponent | コンポーネント基底クラス | コンポーネントの初期化と設定機能を提供 |

Procedure コンポーネントを使用する前に、プロジェクトでこれらの依存コンポーネントが正しく構成されていることを確認してください。GameFrameX フレームワークはモジュール間の依存関係を自動的に処理し、開発者は Unity シーンに対応するコンポーネントを追加するだけです。

## クイックスタート

1. Unity シーンで空の GameObject を作成します
2. その GameObject に ProcedureComponent コンポーネントを追加します
3. Inspector パネルで利用可能なフローの型とエントリーポイントフローを構成します
4. ProcedureBase を継承したカスタムフロークラスを作成します
5. カスタムフローのクラス名を利用可能なフローリストに追加します
6. ゲームを実行すると、システムが自動的にエントリーポイントフローを開始します
