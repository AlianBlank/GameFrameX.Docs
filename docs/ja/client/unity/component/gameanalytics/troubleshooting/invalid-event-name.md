# イベント名が空でブロックされる（GameFrameworkGuard 検証）場合の対処方法

`GameAnalyticsComponent` の `Event`、`StartTimer` などの API を呼び出す際、渡された `eventName` が `null` または空文字列であると、メソッドの最初の行にある `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))` が検証例外をスローします。これは統計 SDK のエラーではなく、引数の保護（ガード）です——空でないイベント名を渡すだけで解決します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `Event` / `StartTimer` などのメソッドを呼び出す際に `GameFrameworkGuard.NotNullOrEmpty` の検証例外がスローされ、スタックトレースが `GameAnalyticsComponent` を指している | `eventName` に `null` または空文字列が渡された | 呼び出し側で空でないイベント名を渡すように変更する。下記の「修正手順」を参照 |
| イベント名が変数、辞書、または文字列連結に由来しており、まれに空になる | 変数が未代入、辞書の key から値が取得できない、連結結果が空文字列 | 送信前に空チェックを行い、ログを出力して発生源を特定する |
| 呼び出しで例外はスローされないが、ログに `GameAnalyticsManager is not init.` が現れ、データも送信されていない | このページの問題とは異なる：コンポーネントまたはいずれかの Manager が未初期化で、メソッド内部でその Manager がそのままスキップされる | まず初期化 API を呼び出して `Init` を完了し、その後イベントを送信する |

## 修正手順

### 1. どのメソッドで例外がスローされたかを確認する

`GameAnalyticsComponent` の `eventName` を受け取るすべての公開メソッドは、最初の行で同じ検証を行います。まず例外のスタックトレースから入口を確認してください：

| メソッド | シグネチャ | 検証が行われる行 |
|------|------|-----------|
| タイマー開始 | `StartTimer(string eventName)` | [L162](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L162) |
| タイマー一時停止 | `PauseTimer(string eventName)` | [L187](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L187) |
| タイマー再開 | `ResumeTimer(string eventName)` | [L205](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L205) |
| タイマー終了 | `StopTimer(string eventName)` | [L223](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L223) |
| イベント送信 | `Event(string eventName)` | [L248](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L248) |
| 数値付きイベント送信 | `Event(string eventName, float eventValue)` | [L274](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L274) |
| カスタムフィールド付きイベント送信 | `Event(string eventName, Dictionary<string, object> customF)` | [L300](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L300) |
| 数値とカスタムフィールド付きイベント送信 | `Event(string eventName, float eventValue, Dictionary<string, object> customF)` | [L334](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L334) |

検証はどの初期化チェックよりも先に行われます——コンポーネントがすでに `Init` 済みであっても、空のイベント名は同様にブロックされます：

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

### 2. 呼び出し箇所で渡されるイベント名を確認する

よくある誤った書き方と修正：

```csharp
// 誤り：イベント名が辞書/設定から取得され、値が取得できない場合は null になる
string eventName = config.ContainsKey("level_complete") ? config["level_complete"] : null;
gameAnalyticsComponent.Event(eventName);

// 正しい：空でない定数または代入済みの変数を渡すことを保証する
gameAnalyticsComponent.Event("level_complete");
```

イベント名が外部データ（設定テーブル、サーバーからの配信、列挙型の変換）に由来する必要がある場合は、送信前に空チェックを行いログを記録すると、データ発生源の問題を発見しやすくなります：

```csharp
if (string.IsNullOrEmpty(eventName))
{
    Debug.LogWarning($"[GameAnalytics] eventName が空です。取得元：{source}");
    return;
}

gameAnalyticsComponent.Event(eventName);
```

### 3. 定数でイベント名を一元管理する

すべてのイベント名を定数クラスに集約することで、手書き文字列によるスペルミスや空値の誤送信を防げます：

```csharp
public static class AnalyticsEvents
{
    public const string LevelComplete = "level_complete";
    public const string AdWatched = "ad_watched";
}

gameAnalyticsComponent.Event(AnalyticsEvents.LevelComplete);
```

## 検証

- 以前例外がスローされていた呼び出し箇所を再度トリガーし、Console に `GameFrameworkGuard.NotNullOrEmpty` 関連の例外が表示されなくなることを確認します。
- `GameAnalyticsManager is not init.` の警告が同時に出ていないことを確認します。表示された場合は、イベント名は検証を通過しているものの、いずれかの Manager がまだ初期化されていないことを意味するため、まず初期化を完了してからイベントを送信する必要があります。
- 統計プラットフォームの管理画面で、イベントデータが受信済みであることを確認します。

## 背景

`GameFrameworkGuard.NotNullOrEmpty` は GameFrameX 基盤ライブラリのガードメソッドです（実装はこのリポジトリ内にはなく、このリポジトリのソースコードではその具体的な例外型の詳細は確認できませんでした）。メソッドの入口で不正な引数を素早くブロックするために使用されます。`GameAnalyticsComponent` はこれを各公開メソッドの最初の行に配置しており、空のイベント名がディスパッチループに入る前にブロックされることを保証し、不正なデータが各統計チャネルに流れ込むのを防ぎます。
