# Implementing the Player Attribute Module

The Player Attribute module provides a unified calculation formula based on "Final value slot + derived slots". The final attribute is obtained by modifying five slots: Base value, Additive, first-layer Percentage, Final Additive, and Final Percentage. This page explains how to initialize, modify, and read player attributes in your business logic.

## Prerequisites

- Familiar with the Component / Agent pattern of `GameFrameX`, and understand the relationship between `PlayerAttributeComponent` and `PlayerAttributeComponentAgent`.
- Familiar with the event bus, and know how to register listeners for `AttributeChangedEventArgs`.

## Attribute Slots and Calculation Formula

Each final attribute (e.g., `AttributeType.Life`) corresponds to five numeric slots, with offsets defined by `AttributeSlotKind`. The percentage base `PercentBase = 10000` represents 100%.

| Slot | Offset | Purpose |
|------|--------|---------|
| Final | 0 | Final value slot, ID equals the main ID |
| Base | 10000 | Base value slot, from configuration, level, or initialization |
| Add | 20000 | Additive modifier |
| Pct | 30000 | First-layer percentage modifier (base is 10000) |
| FinalAdd | 40000 | Final additive modifier |
| FinalPct | 50000 | Final percentage modifier (base is 10000) |

The recalculation formula is provided by `AttributeCore.CalculateFinal`:

```csharp
public static long CalculateFinal(long baseValue, long addValue, long pctValue, long finalAddValue, long finalPctValue)
{
    checked
    {
        var firstLayer = (baseValue + addValue) * (PercentBase + pctValue) / PercentBase;
        return (firstLayer + finalAddValue) * (PercentBase + finalPctValue) / PercentBase;
    }
}
```

## Steps

### 1. Attach the Attribute Component to the Player Entity

`PlayerAttributeComponent` is already annotated with `[ComponentType(GlobalConst.ActorTypePlayer)]` and is automatically attached when the player entity is created, so no manual registration is required.

```csharp
[ComponentType(GlobalConst.ActorTypePlayer)]
public sealed class PlayerAttributeComponent : StateComponent<PlayerAttributeState>
{
}
```

Source: [PlayerAttributeComponent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/Component/PlayerAttributeComponent.cs#L38-L40)

### 2. Write Values and Recalculate the Final Attribute

After modifying a derived slot through the mutation entry point of `PlayerAttributeComponentAgent`, use `AttributeCore.RecalculateFinal` to recompute the final value and write it to the corresponding Final slot. `TryGetFinalAttribute` infers the owning final attribute from a derived slot.

```csharp
var state = await agent.GetState();
var attributes = state.Attributes;

// Modify the Base slot of Life
var baseKey = AttributeCore.GetSlotAttribute(AttributeType.Life, AttributeSlotKind.Base);
attributes[baseKey] = 100;

// Recalculate the final value of Life
attributes[AttributeType.Life] = AttributeCore.RecalculateFinal(attributes, AttributeType.Life);
```

Source: [AttributeCore.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Attribute/AttributeCore.cs#L46-L109)

### 3. Listen for Attribute Change Events

Subscribe to `AttributeChangedEventArgs` to respond to attribute changes (handled by concrete listeners such as `PlayerAttributeChangedEventListener`). The event carries the changed attribute ID and the new value.

```csharp
public class AttributeChangedEventArgs : EventArgs
{
    public AttributeType AttributeType { get; }
    public long OldValue { get; }
    public long NewValue { get; }
}
```

Source: [AttributeChangedEventArgs.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/EventData/AttributeChangedEventArgs.cs)

### 4. Use Initial Default Values

On the player's first login, fill the Base slot with the initialization data provided by `PlayerInitialAttributeDefaults`, then trigger the first recalculation to obtain the initial final attributes.

## Common Variants

- **Percentage bonuses**: Equipment / Buffs only modify the `Pct` or `FinalPct` slots, with no need to compute the final value directly; simply remove the corresponding modifiers when the player logs out.
- **Cross-entity attribute aggregation**: If you need to merge multiple sources (player + pet + equipment) into the calculation, each source can maintain its own attribute dictionary, and `AttributeCore.RecalculateFinal` can be called uniformly at the point of final reading.
- **Batch recalculation**: When multiple final attributes change at the same time, iterate over the known final attributes (the 9 enum values for which `AttributeCore.IsFinalAttribute` returns true) and call `RecalculateFinal` on each one.

## Common Mistakes

| Symptom | Cause | Fix |
|---------|-------|-----|
| `ArgumentOutOfRangeException: 必须传入已知最终属性。` | A non-final attribute or a derived slot was passed directly to `RecalculateFinal` | Only call recalculation for attributes where `IsFinalAttribute` returns true |
| `ArgumentOutOfRangeException: 必须传入已知属性数值槽。` | An undefined custom value was passed to `AttributeSlotKind` | Restrict usage to the 6 built-in enum values |
| Final attribute is always 0 | Derived slots are missing but recalculation was never triggered | After modifying any derived slot, you must call `RecalculateFinal` and write the result back to the `Final` slot |
| Percentage bonus result is off by 100x | `0.5` was written directly into the Pct slot | Pct / FinalPct slots use a base of `10000`; write `5000` for 50% |

## Background (Optional)

Attribute IDs are designed with fixed offsets such as 10000 / 20000 / 30000 to distinguish slots, so that any derived slot can infer its owning final attribute via `value % PercentBase`, making it easy to handle change events uniformly. `PercentBase = 10000` both avoids floating-point precision issues and makes it convenient for designers to configure values on a "per-ten-thousand" (basis points) scale.
