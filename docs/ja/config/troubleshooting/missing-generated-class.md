# 生成後に TbXxx クラスが見つからないときの対処法

`gen-client-json.bat` / `gen-client-json.sh` を実行し終えたのに、Unity や .NET プロジェクト内で `TbMyItem` や `TbAchievement` といったクラスが見つからない——通常はツールの故障ではなく、ファイル名・生成スクリプト・出力ディレクトリのいずれかが一致していないことが原因です。本ページでは、エラーの症状ごとに診断表と修正手順を示します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| `TbXxx` クラスがまったく見つからず、出力ディレクトリにも対応する `.cs` ファイルがない | Excel ファイル名が `字母-英文名-中文名.xlsx` のルールに適合せず、ツールが認識に失敗している | 「修正手順 1」を参照 |
| エラー `不支持中文表名` または `table name invalid` が表示される | ファイル名の「英語名」部分に中国語が書かれている | 「修正手順 2」を参照 |
| `TbClient` には `TbXxx` があるのに `TbServer` にはない(またはその逆) | ファイル名にグループマーカー `c` / `s` が付いており、テーブルが単一側に制限されている | 「修正手順 3」を参照 |
| 生成スクリプトが一瞬で終了し、`Tb` クラスがまったく見えない | スクリプトを間違えて実行している(server 側を生成したのに client プロジェクトを探している)、またはスクリプトが実際には正常に実行されていない | 「修正手順 4」を参照 |
| `luban.conf` / `Tools/` ディレクトリが見つからないというメッセージが出る | `Config/` ルートディレクトリでスクリプトを実行していない | 「修正手順 5」を参照 |
| クラス名が `TbXxx2`、`TbXxx_1` であり、予期した `TbXxx` ではない | 同じテーブルが複数に分割されており、英語名のスペルが一致していない | 「修正手順 6」を参照 |

## 修正手順

### 1. Excel ファイル名が命名規則に従っているか確認する

ツールは `字母-英文名-中文名.xlsx` の形式に厳密に適合するファイルのみを認識します。ファイル名が間違っていると、コードは一切生成されません。

`Config/Excels/Tables/` フォルダーを開き、ファイル名が次のような形式になっているか確認してください:

```
D-ItemConfig-道具表.xlsx
```

3 つのセグメントの意味は次のとおりです:

| セグメント | 役割 | ルール |
|----|------|------|
| アルファベット | ソート用の単一文字 | 任意の英数字 |
| 英語名 | **コードのクラス名 `Tb英文名` になる** | 英字のみである必要があり、**中国語は使用不可** |
| 中国語名 | プランナー/同僚向けの表示 | 任意。`-` を含むことが可能 |

出典:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L164-L190)

サンプル対応表：

| ファイル名 | 生成されるクラス |
|--------|----------|
| `C-AchievementConfig-成就表.xlsx` | `TbAchievementConfig` |
| `D-ItemConfig-道具表-道具-1001.xlsx` | `TbItemConfig` |
| `S-SoundsConfig-声音表.xlsx` | `TbSoundsConfig` |

### 2. 英語名部分に中国語を含めてはならない

エラー `不支持中文表名` または `table name invalid` が出る場合は、「英語名」部分に中国語が書かれている(例： `D-道具-我的道具表.xlsx`)ことを意味します。中央のセグメントを純粋な英語に変更すれば解決です:

```
誤:D-道具-我的道具表.xlsx
正:D-Item-我的道具表.xlsx     → TbItem を生成
```

### 3. ファイル名のグループマーカーを確認する

クライアント専用またはサーバー専用にしたい場合は、英語名と中国語名の間にグループマーカーを追加する必要があります。**マーカーを追加したことに気づかないと、クラスが「消えた」と勘違いしてしまいます**。

| ファイル名 | 効果 |
|--------|------|
| `D-ItemConfig-道具表.xlsx` | クライアント・サーバー両方で使用 |
| `D-ItemConfig-c-道具表.xlsx` | **クライアントのみ**に `TbItemConfig` が存在 |
| `D-ItemConfig-s-道具表.xlsx` | **サーバーのみ**に `TbItemConfig` が存在 |

対象のプロジェクトがクライアントかサーバーかを確認した上で、対応するファイル名を選ぶか、`-c-` / `-s-` を削除して両側に生成させるようにしてください。

出典:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L182-L190)

### 4. 正しい生成スクリプトを実行しているか確認する

`Config/` ルートディレクトリには通常複数の生成スクリプトがあり、**間違ったスクリプトを実行するのが、クラスが見つからない最も一般的な原因です**:

| スクリプト | 生成されるもの |
|------|----------|
| `gen-client-json.bat` / `gen-client-json.sh` | JSON データ + C# クラス、クライアント用 |
| `gen-server-bin.bat` / `gen-server-bin.sh` | バイナリデータ + C# クラス、サーバー用 |

- Windows:`Config/` ディレクトリで対応する `.bat` をダブルクリック
- Mac / Linux:ターミナルで `cd Config` を実行してから `sh gen-*.sh` を実行

実行後、出力ディレクトリに新しく生成された `.cs` ファイルがあるか確認してください——あれば成功です。単に別のプロジェクトに入っているだけかもしれません。

出典:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L134-L148)

### 5. Config ルートディレクトリでスクリプトを実行する

`gen-*.bat` / `gen-*.sh` は、同じディレクトリにある `luban.conf` と `Tools/` ディレクトリに依存しています。別のディレクトリから実行すると、設定やツールディレクトリが見つからないエラーが発生し、生成はサイレントに失敗します。

```bash
# 正しい
cd Config
sh gen-client-json.sh

# 誤り(上位ディレクトリから実行)
sh Config/gen-client-json.sh   # luban.conf が見つからない可能性がある
```

### 6. テーブルを複数に分割する場合は英語名が完全に一致している必要がある

1 つのテーブルが大きすぎる場合は複数に分割できます。ツールは「英語名」でマージします。**英語名のスペルが一致しないと、2 つのテーブルに分かれ、2 つのクラスが生成されます**:

```
正しい(いずれも TbItemConfig にマージされる):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemConfig-道具表-1001-2000.xlsx

誤り(英語名が不一致で、TbItemConfig と TbItemConfig2 が生成される):
D-ItemConfig-道具表-1-1000.xlsx
D-ItemCongfig-道具表-1001-2000.xlsx   ← ItemCongfig とスペルミスしている点に注意
```

英語名を統一した後、生成スクリプトを再実行してください。

出典:[README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.zh-CN.md#L234-L248)

## 検証

上記の手順で修正した後、以下の方法で確認してください:

1. **生成スクリプトを再実行**し、スクリプトが**エラーなしで**最後まで実行されることを確認します(エラーのスタックトレースではなく `pause` や `Press any key` が表示されること)。
2. **生成出力ディレクトリを開き**、その中に `TbXxx.cs` と対応するデータファイル(JSON または bin)があることを確認します。
3. **Unity / .NET プロジェクト内で右クリック → プロジェクトの再生成/再読み込み**を行い、IDE に新しく追加された `.cs` ファイルを認識させます。
4. **最小限の呼び出しで検証します**:

```csharp
// テーブル名が ItemConfig、id 列に 10001 が入っていると仮定
var item = tables.TbItemConfig.Get(10001);
UnityEngine.Debug.Log(item.Name);
```

正常に出力されれば、クラスが正しくロードされていることを意味します。それでも `TbItemConfig` が存在しないというエラーが出る場合は、診断表に戻って引き続き原因を調査してください。
