# AssetBundle 및 YooAsset 리소스 로딩 사용 방법

이 페이지는 GameFrameX.Unity 프로젝트에서 YooAsset를 통해 리소스 패키징, 구성 및 로딩을 완료하도록 안내합니다: 패키징할 리소스를 `Assets/Bundles`의 해당 그룹 디렉터리에 넣고, `YooAssetSettings`를 사용하여 매니페스트 파일 이름과 기본 출력 폴더를 제어한 다음, 빌드를 실행하여 `PackageManifest` 매니페스트와 `yoo` 리소스 패키지를 생성합니다. 런타임에 주소로 로드하면 됩니다.

## 전제 조건

- Unity 프로젝트에 Package Manager를 통해 YooAsset가 설치되어 있어야 합니다(`YooAssetSettings.asset`에서 스크립트 GUID `9753568a72b014c7092614d3be8b353f` 참조).
- 프로젝트 루트 디렉터리에 `Assets/AssetBundleSetting/` 폴더가 존재하며, 두 가지 핵심 구성을 포함합니다:
  - [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset)
  - [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml)
- 리소스는 그룹별로 `Assets/Bundles/{GroupName}` 아래에 배치됩니다(AOTCode / Code / UI / Config / Image / Sprites).

## 작업 단계

### 1. 리소스 디렉터리 준비

YooAsset의 수집기는 `Assets/Bundles` 아래의 6개 그룹(AOTCode, Code, UI, Config, Image, Sprites)으로 고정되어 있습니다. AssetBundle에 패키징할 리소스를 용도에 따라 해당 폴더에 넣습니다. 예를 들어:

- `Assets/Bundles/UI` —— UI Prefab, 아틀라스, 폰트
- `Assets/Bundles/Config` —— 구성 테이블, 바이너리 리소스
- `Assets/Bundles/Sprites` / `Assets/Bundles/Image` —— 아트 텍스처

수집 규칙은 [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L5-L22)을 참조하세요:

```xml
<Group GroupActiveRule="EnableGroup" GroupName="UI" GroupDesc="" AssetTags="">
  <Collector CollectPath="Assets/Bundles/UI" CollectGUID="4010ac95965b3164e83fa268b290dbf4"
            CollectType="MainAssetCollector" AddressRule="AddressByFileName"
            PackRule="PackDirectory" FilterRule="CollectAll" UserData="" AssetTags="" />
</Group>
```

> 각 `<Collector>`는 "어떤 디렉터리를 수집할지 → 어떤 규칙으로 주소를 생성할지 → 어떻게 패키징할지"를 나타냅니다. 현재 프로젝트는 통일하게 `AddressByFileName`(파일명을 로딩 주소로 사용) + `PackDirectory`(디렉터리별로 하나의 패키지로 패키징)을 사용합니다.

### 2. YooAsset 전역 설정 확인

[YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L12-L16)를 열어 두 필드를 확인합니다:

| 필드 | 현재 값 | 의미 |
|------|--------|------|
| `ManifestFileName` | `PackageManifest` | 런타임에 매니페스트를 로드하는 파일 이름 |
| `DefaultYooFolderName` | `yoo` | 빌드 산출물의 기본 출력 디렉터리 이름 |

프로젝트에서 다른 이름의 매니페스트 또는 출력 디렉터리를 사용하는 경우, 여기에서 수정하고 런타임과 빌드 측이 일치하도록 보장해야 합니다.

### 3. YooAsset 빌드 실행

YooAsset는 Unity 메뉴 `YooAsset → Build` 아래에 빌드 진입점을 제공합니다(`YooAssetSettings.asset`의 `m_Script`가 참조하는 에디터 스크립트가 제공). 빌드 산출물은 `DefaultYooFolderName`으로 구성된 `yoo` 폴더 아래로 출력되며, 주로 다음을 포함합니다:

- `PackageManifest`(매니페스트 파일, 모든 패키지 이름, 버전, 리소스 주소를 기록)
- 각 그룹의 AssetBundle 파일(이름은 `UniqueBundleName="True"` 규칙을 따름, [AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3) 참조)

### 4. 런타임에 주소로 리소스 로드

빌드가 완료된 후, `yoo` 디렉터리 아래의 매니페스트와 AssetBundle을 `StreamingAssets`(또는 원격 CDN)에 배포합니다. 시작 시 YooAsset 초기화 시스템이 `PackageManifest`를 읽고, 비즈니스 측은 `AddressByFileName`으로 생성된 주소로 로드하면 됩니다:

```csharp
// 의사 코드: YooAsset 공개 API에 맞춰 작성되었으며, 구체적인 유형은 설치된 YooAsset 버전을 기준으로 합니다.
var package = YooAssets.GetPackage("DefaultPackage");
var op = package.LoadAssetAsync<GameObject>("Assets/Bundles/UI/LoginPanel.prefab");
yield return op;
var go = op.InstantiateObject;
```

## 일반적인 변형

- **새 리소스 그룹 추가**: [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml)의 `<Package>` 내에 하나의 `<Group>`과 해당하는 `<Collector CollectPath="Assets/Bundles/당신의그룹">`을 추가하고, 에디터를 재시작하면 YooAsset가 자동으로 인식합니다.
- **패키징 단위 수정**: `<Collector>`의 `PackRule`를 `PackDirectory`에서 `PackSeparately`(각 리소스를 독립적인 패키지로)로 또는 `PackTogether`(전체 그룹을 하나의 패키지로)로 변경합니다.
- **주소 규칙 전환**: `AddressRule`을 `AddressByGroupAndFileName` 또는 사용자 정의 규칙으로 변경하고, 런타임에 새 주소로 로드합니다.

## 일반적인 오류

- **런타임에 리소스를 찾을 수 없음**: 먼저 `ManifestFileName`과 `DefaultYooFolderName`이 빌드 측과 런타임에서 일치하는지 확인합니다([YooAssetSettings.asset L15-L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L15-L16)); 그런 다음 리소스가 실제로 `Assets/Bundles/<GroupName>` 아래에 있는지, 그룹의 `GroupActiveRule="EnableGroup"`인지 확인합니다.
- **중복 패키징 또는 패키지 이름 충돌**: `<Common>` 노드의 `UniqueBundleName="True"`인지 확인합니다([AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3) 참조). 그렇지 않으면 같은 이름의 디렉터리가 서로 덮어씌워집니다.
- **구성 수정 후 적용되지 않음**: YooAsset의 수집 구성은 에디터 재시작 또는 YooAsset 창을 다시 연 후에야 다시 구문 분석됩니다. XML을 수정한 후 Editor 메인 창으로 돌아가서 다시 빌드합니다.

## 배경(선택)

이 프로젝트는 통합 리소스 관리 솔루션으로 YooAsset를 채택합니다: `AssetBundleCollectorConfig.xml`은 "어떤 리소스 → 어떤 주소를 사용할지 → 어떤 패키지로 패키징할지"를 설명하고, `YooAssetSettings.asset`은 "매니페스트의 이름 지정 방법 → 산출물의 위치"를 설명합니다. 양측이 분리되어 있어 코드를 다시 작성하지 않고도 패키징 단위를 조정할 수 있으며, 리소스 구조를 변경하지 않고도 런타임 모드(로컬 / CDN)를 전환할 수 있습니다.
