# MongoDB 接続と永続化設定

本ページでは GameFrameX.Server のサービスプロセスに対して、MongoDB 接続文字列とデータベース名を構成し、起動段階で `GameDb` が接続の確立・コレクションの初期化を行い、永続化可能な状態になる方法を説明します。

## 前提条件

- アクセス可能な MongoDB インスタンスを準備する(ローカルサービスでも Atlas クラスターでも可)。
- そのインスタンスの接続文字列(標準 URI または `mongodb+srv://` 形式)と、対象となるデータベース名を所有していること。
- 起動プロジェクト(`GameFrameX.Launcher`)でパッケージ参照により `MongoDB.Driver` を導入済みであること。ソースコードプロジェクトは `GameFrameX.Apps/GlobalUsings.cs`、`GameFrameX.Hotfix/GlobalUsings.cs` の `global using` によって MongoDB アセンブリを参照しているため、ビジネスコード側で別途導入する必要はない。

## 操作手順

1. 起動エントリ(デフォルトでは `GameFrameX.Launcher/StartUp/AppStartUpGame.cs`)の `Init()` 内で `AppSetting` を構築し、データベース関連の 2 つのフィールド `DataBaseUrl` と `DataBaseName` を入力します:

   ```csharp
   Setting = new AppSetting
   {
       // ... その他のサーバー設定
       DataBaseUrl  = "mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority",
       DataBaseName = "<your_db_name>",
   };
   ```

   出典: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L97-L114)

2. サーバー起動メインループのデータベース初期化段階において、フレームワークは `GameDb.Init<MongoDbService>` を呼び出し、上記の 2 つのフィールドを `DbOptions` に渡します:

   ```csharp
   LogHelper.Debug("データベースサービスの起動を開始します...");
   var initResult = await GameDb.Init<MongoDbService>(new DbOptions
   {
       ConnectionString = Setting.DataBaseUrl,
       Name             = Setting.DataBaseName,
   });
   if (initResult == false)
   {
       throw new InvalidOperationException("データベースサービスの起動に失敗しました");
   }
   ```

   出典: [AppStartUpGame.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/StartUp/AppStartUpGame.cs#L60-L67)

3. プロセスを起動します。ログに「起動数据库服务 结束...」(データベースサービス起動完了...)が表示され、かつ `InvalidOperationException` がスローされていなければ、MongoDB 接続と永続化層は既に準備完了しています。

## よくあるバリエーション

- **ローカル MongoDB を使用する場合**:`DataBaseUrl` を `mongodb://localhost:27017` に置き換え、データベース名は必要に応じて調整します。
- **Atlas クラスターを使用する場合**:デフォルト例の形式 `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority` をそのまま使用し、アカウントとクラスターホストのみ実際の値に置き換えます。
- **複数環境の分離**:異なる起動エントリ(例えば `AppStartUpGame` を継承する `AppStartUpGate`、`AppStartUpWorld` など)の `Init()` 内で、環境ごとに `DataBaseUrl` / `DataBaseName` を設定することで、プロセスごとに異なるデータベースを指定できます。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| 起動時に `InvalidOperationException("数据库服务启动失败")` がスローされる | `GameDb.Init<MongoDbService>` が `false` を返している。通常は接続文字列に到達できない、認証情報が誤っている、またはネットワーク制限が原因 | `DataBaseUrl` のホスト・ポート・ユーザー・パスワードを確認。Atlas の IP ホワイトリストに実行マシンが許可されているか確認 |
| データベースの手順より前にアプリケーション起動がハングする | 接続文字列に未エンコードの特殊文字(例:`@`、`%`)が含まれている | ユーザー名/パスワードをパーセントエンコードする(例:`p@ss` → `p%40ss`) |
| 接続は成功するが読み書き時に「コレクションが存在しません」と表示される | `DataBaseName` がビジネス要件と一致していない | `DbOptions.Name` とビジネスコードで読み取るデータベース名が一致しているか確認 |

## 背景(任意)

`GameDb` はフレームワーク統合の永続化ファサードであり、実際の実装はジェネリックパラメータ `MongoDbService` によって提供されます。起動段階で `DbOptions` により接続文字列とデータベース名が注入され、クライアントの構築、データベースの選択、デフォルトのシリアライズ規約の登録が行われます。ビジネス層は `GameDb` を通じて呼び出すだけで、`IMongoClient` を直接保持しないため、後で基盤層の切り替えや置き換えが容易になります。
