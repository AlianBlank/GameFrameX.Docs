# WebGL 平台上 RemoveCache / ClearCache 無效時的解決方法

在 WebGL 平台上呼叫 `RemoveCache(url)` 或 `ClearCache()` 時，實際上快取完全不會被刪除，只會輸出警告日誌。這是因為 WebGL 執行環境無法直接存取本機檔案系統。

## 快速診斷

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 呼叫 `RemoveCache(url)` 後圖片仍然命中 | 在 WebGL 中圖片由瀏覽器的 HTTP 快取管理，框架端不存在可刪除的本機副本 | 改用瀏覽器端的快取控制（在 URL 加上版本號 / Cache-Control） |
| 呼叫 `ClearCache()` 後磁碟容量沒有變化 | WebGL 中不存在「磁碟快取」的概念，方法會立即 return | 由瀏覽器端進行清理。`ClearCache` 僅應在 WebGL 以外的平台上呼叫 |
| 呼叫 `RemoveCache` / `ClearCache` 時，Console 顯示 `ImageCache: RemoveCache is not supported on WebGL.` 或 `ImageCache: ClearCache is not supported on WebGL.` 警告 | WebGL 平台的程式碼分支中已明確停用該操作 | 用 `#if !UNITY_WEBGL` 包住呼叫，或改用瀏覽器端的方式 |

## 修正步驟

### 1. 確認平台分支的行為符合預期

在原始碼中，`RemoveCache` 與 `ClearCache` 兩者都會透過 `#if UNITY_WEBGL` 輸出警告並立即結束：

```csharp
public void RemoveCache(string url)
{
    if (string.IsNullOrEmpty(url)) { return; }

#if UNITY_WEBGL
    Log.Warning("ImageCache: RemoveCache is not supported on WebGL.");
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    if (FileHelper.IsExists(cachePath))
    {
        FileHelper.Delete(cachePath);
    }
#endif
}

public void ClearCache()
{
#if UNITY_WEBGL
    Log.Warning("ImageCache: ClearCache is not supported on WebGL.");
#else
    if (!Directory.Exists(_config.CachePath)) { return; }
    FileHelper.CleanDirectory(_config.CachePath);
#endif
}
```

來源：[ImageCacheManager.cs#L196-L236](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L196-L236)

也就是說，在 WebGL 中 `RemoveCache` / `ClearCache` 並非「不運作」，而是**在原始碼層級就被停用了**。即使嘗試「清除本機快取」，也不會有任何反應。

### 2. 在 WebGL 中避免呼叫這兩個方法

如果程式碼需要跨平台運作，請使用條件編譯來跳過呼叫：

```csharp
public void OnUserClickClearCache()
{
#if !UNITY_WEBGL
    GameFrameX.ImageCache.Runtime.ImageCacheManager.Instance.ClearCache();
#endif
}
```

### 3. 在 WebGL 中執行「等效的」清理

在 WebGL 平台上，圖片透過 `UnityWebRequestTexture` 載入，快取由瀏覽器管理。為了避免命中「舊圖片」，常見的做法如下：

1. **在 URL 加上版本號或雜湊值**：每次更新資源時變更 URL 的查詢參數（例如：`?v=2`）。瀏覽器會將其視為新的資源請求。
2. **由伺服器端回傳適當的 `Cache-Control` 標頭**，以控制瀏覽器端的有效期限。
3. **呼叫瀏覽器端的 `Caching.ClearCache()`（瀏覽器自身的儲存清理 API）** —— 本元件不支援此路徑。

### 4. 同時確認 `IsCached` 的行為

在 WebGL 中，`IsCached(url)` 也永遠回傳 `false`。由於框架內部不保留快取副本，因此不應用來判斷 WebGL 上的命中狀態：

```csharp
public bool IsCached(string url)
{
    if (string.IsNullOrEmpty(url)) { return false; }

#if UNITY_WEBGL
    return false;
#else
    var hash = Utility.Hash.MD5.Hash(url);
    var cachePath = PathHelper.Combine(_config.CachePath, hash + Utility.Const.FileNameSuffix.PNG);
    return FileHelper.IsExists(cachePath);
#endif
}
```

## 驗證

- 在 Editor 或 Standalone 平台上呼叫 `ClearCache()` 後，快取目錄（`ImageCacheConfig.CachePath`）下的 PNG 檔案應已被清除。
- 在 WebGL 建置中呼叫 `ClearCache()` 時，Console 會顯示 `ImageCache: ClearCache is not supported on WebGL.` 警告，且完全不會發生 IO 錯誤。這表示已進入預期的分支。
- 在 WebGL 中依照修正步驟 3 變更 URL 的查詢參數並重新載入，確認瀏覽器已取得新資源（不再命中舊圖片）。

## 背景（選讀）

WebGL 沙箱中沒有真正的「本機磁碟」概念，`System.IO` 在此平台上已被移除。因此 `ImageCacheManager` 在 WebGL 分支中會直接走向 `UnityWebRequestTexture`，並將快取交給瀏覽器處理。伴隨而來的是，`IsCached` / `RemoveCache` / `ClearCache` 也不保留可刪除的本機副本，因此全部都會走「回傳 false / 輸出警告」的提前返回路徑。
