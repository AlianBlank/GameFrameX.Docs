# GetData/SetData データ読み取り異常早見表

このドキュメントは、`IFsm<T>` 上の `GetData` / `SetData` 呼び出し時に発生する一般的な異常や異常な戻り値について、症状の対照と切り分け手順を提供します。ステートマシンの使用方法については「Fsm クイックスタート」を参照してください。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `GameFrameworkException("Data name is invalid.")` が発生 | `name` が `null` または空文字列 | 空でないキー名を使用し、定数文字列を推奨 |
| `GetData` が常に `null` を返す | 当該キーが `SetData` で書き込まれたことがない。またはステートマシンが `Reset` / `Shutdown` でクリア済み | 初回読み取り前に明示的に `SetData` するか、`HasData` エントリで判定する |
| `SetData` 後すぐに読み取ったフィールド値がデフォルト値のまま | 重複 `SetData` 時に旧値が `ReferencePool` に回収され、新しい値が実際に置き換わっていない | 先に `RemoveData` を呼んでから `SetData` するか、`SetData` を1回だけ呼び出す |
| 型変換で `InvalidCastException` が発生 | `GetData<TData>` のジェネリックパラメータと書き込み時の実際の `Variable` サブタイプが一致していない | 読み書き両端で同じ `Variable` サブタイプを使用する（例：`VarInt`、`VarString`） |
| ステートマシン破棄後に `GetData` を呼び出すと例外が発生 | `m_IsDestroyed == true` の場合、`Reset` などの内部フローがアクセスを拒否する | 破棄後はすべてのアクセスを停止するか、新しい FSM を作り直す |

## 修正手順

### 1. 名前が無効（`Data name is invalid`）

`GetData(string)` と `SetData(string, Variable)` の最初の手順で名前を検証します：

```csharp
if (string.IsNullOrEmpty(name))
{
    throw new GameFrameworkException("Data name is invalid.");
}
```

Source: [Fsm.cs#L469-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L527)

**修正方法**：キー名には安定した文字列定数を使用してください。例えば `"Hp"`、`"Owner"` などです。連結された空文字列を渡してはいけません。

### 2. 読み取りが `null` を返す

`GetData` は内部辞書が空の場合やキーが存在しない場合、`null` を直接返し、例外をスローしません：

```csharp
if (m_Datas == null)
{
    return null;
}

Variable data = null;
if (m_Datas.TryGetValue(name, out data))
{
    return data;
}

return null;
```

Source: [Fsm.cs#L469-L488](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488)

**修正方法**：
1. ステートの `OnEnter` またはステートマシン作成後すぐに `SetData` を1回呼び、初期化を完了してください。
2. 読み取り前に `HasData(name)` で存在を判定し、`false` の場合はデフォルト値で初期化してください。
3. `Reset()` はすべてのデータ（`m_Datas.Clear()`）をクリアすることに注意してください。`Shutdown` 後は辞書が `null` に戻るため、再初期化が必要です。

### 3. 重複 `SetData` 後に旧値が回収される

`SetData` は内部的にまず旧値を取り出し、空でない場合は参照プールに返却します：

```csharp
Variable oldData = GetData(name);
if (oldData != null)
{
    ReferencePool.Release(oldData);
}

m_Datas[name] = data;
```

Source: [Fsm.cs#L508-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L508-L527)

**修正方法**：
- `Variable` サブタイプのインスタンスはフレームワーク内部で `ReferencePool` から取得され、ライフサイクルが管理されます。外部で `new` してからステートマシンに渡してはいけません。
- キー名を置き換えたい場合は、`RemoveData(name)` を使用して旧値を明示的に返却してから、新しいキーで `SetData` してください。

### 4. ジェネリック型の不一致

`GetData<TData>` は直接キャストを行うため、`TData : Variable` かつ書き込み時のサブタイプと一致している：

```csharp
public TData GetData<TData>(string name) where TData : Variable
{
    return (TData)GetData(name);
}
```

Source: [Fsm.cs#L458-L461](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

**修正方法**：呼び出し側では `VarInt`、`VarFloat`、`VarString`、`VarBool`、`VarObject` などの組み込みサブタイプを明示的に使用し、`object` や `Variable` 基底クラスを `TData` として使用しないでください。さもないとキャストが失敗します。

### 5. 破棄後のアクセス

`Fsm.Shutdown` 後 `m_IsDestroyed = true` となり、再アクセスは `Reset()` などの内部フローによって拒否されます：

```csharp
if (m_IsDestroyed)
{
    throw new GameFrameworkException("FSM is destroyed, can not reset.");
}
```

Source: [Fsm.cs#L560-L565](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L560-L565)

**修正方法**：FSM を破棄する前にすべての外部参照をクリアし、`OnDestroy` 後に `GetData`/`SetData` を呼び続けないようにしてください。

## 検証

以下の手順を実行して問題が解決したことを確認してください：

1. ステートの `OnEnter` で `HasData("Hp")` と `GetData<VarInt>("Hp").Value` を出力し、読み取り結果が期待通りであることを確認します。
2. `SetData("Hp", hpVar)` の後に `GetData` を呼び、値が一致していることを確認します。
3. `Reset()` を呼び出した後に `GetData` で読み取ると、`null` が返り例外が発生しないことを確認します（`name` が空でない限り）。
