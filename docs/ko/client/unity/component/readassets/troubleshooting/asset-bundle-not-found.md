# AssetBundle 로드 시 FileNotFoundException 발생怎么办

`BlankReadAssets.LoadAssetBundle` 또는 `BlankReadAssets.LoadAssetBundleAsync` 호출 시,전달된 상대 경로가 StreamingAssets의 리소스와 일치하지 않으면 프레임워크는 직접 `System.IO.FileNotFoundException("File not found", path)`을 던집니다.이는 경로 해석 실패의 가장 흔한 신호입니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `FileNotFoundException: File not found`(message에 전달된 path 포함) | 경로에 해당 파일을 찾을 수 없음.대소문자,슬래시,StreamingAssets에 미포함 세 가지 경우가 흔함 | `FileExists`로 사전 검사;상대 경로와 `/` 구분자 통일;리소스가 `Assets/StreamingAssets/` 아래에 있는지 확인 |
| Editor에서는 찾을 수 있지만 패키징 후 Android 실기에서 찾을 수 없음 | APK 내 리소스가 압축되어 기본 `AssetBundle.LoadFromFile`로 읽을 수 없음 | `BlankReadAssets.SetCompressedAssetBundleFileNames(...)`를 호출하여 압축 목록 등록 |
| 예외 발생 전 리소스는 실제로 존재하지만 찾을 수 없다고 표시됨 | 경로 접두사를 `StreamingAssets/xxx`로 작성했으며,프레임워크가 이미 해당 접두사를 암묵적으로 제거함 | `StreamingAssets/` 접두사를 제거하고 상대 하위 경로만 전달 |

## 수정 단계

### 1. FileExists로 경로 사전 검사

`BlankReadAssets.LoadAssetBundle` 내부에서 먼저 `GetInfoOrThrow`를 호출하며,찾지 못하면 `ThrowFileNotFound`를 호출하여 직접 예외를 던집니다.먼저 `FileExists`로 점검하면 경로 오기재인지 리소스 누락인지 빠르게 판별할 수 있습니다:

```csharp
if (!BlankReadAssets.FileExists("ui/prefab/main.ab"))
{
    Debug.LogError("AssetBundle이 존재하지 않습니다.StreamingAssets에 넣었는지 확인하세요");
    return;
}
var bundle = BlankReadAssets.LoadAssetBundle("ui/prefab/main.ab");
```

예외 원문 및 트리거 위치는 다음과 같습니다:

```csharp
private static void ThrowFileNotFound(string path)
{
    throw new FileNotFoundException("File not found", path);
}
```

Source: [BlankReadAssets.cs#L243-L246](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L243-L246)

### 2. 경로는 반드시 StreamingAssets의 상대 하위 경로여야 하며 `/` 사용

프레임워크의 `LooseFilesImpl.TryGetInfo`는 전달된 경로와 `s_root`를 연결한 후 `File.Exists`를 호출합니다:

```csharp
var fullPath = s_root + path;
if ( !File.Exists(fullPath) )
{
    return false;
}
info.readPath = fullPath;
```

Source: [BlankReadAssets.LooseFilesImpl.cs#L57-L71](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L57-L71)

- 올바른 예:`"ui/prefab/main.ab"`(`Assets/StreamingAssets/ui/prefab/main.ab`에 해당)
- 잘못된 예:`"StreamingAssets/ui/prefab/main.ab"`,`"ui\\prefab\\main.ab"`,절대 경로
- 대소문자 구분:Android 실기 파일 시스템은 대소문자를 엄격히 구분함

### 3. APK 내 압축된 AssetBundle 식별

`AssetBundle.LoadFromFile`은 기본적으로 APK 내 압축되지 않은 파일만 읽을 수 있습니다.빌드 파이프라인이 `.ab`를 APK에 압축했다면 사용 전에 압축된 파일 목록을 등록해야 합니다.그렇지 않으면 내부 `LoadFromFile`이 `FileNotFoundException`을 던지거나 손상된 패키지를 반환합니다.등록 방법은 `BlankReadAssets.SetCompressedAssetBundleFileNames`을 참조하세요.이 진입점은 `AndroidIsCompressedFileStreamingAsset` partial 메서드를 통해 호스트 프로젝트에 실제 파일 이름 목록을 주입합니다:

```csharp
// 호스트 프로젝트에서 필요에 따라 확장
BlankReadAssets.SetCompressedAssetBundleFileNames(
    "ui/prefab/main.ab",
    "ui/prefab/login.ab"
);
```

Source: [BlankReadAssets.cs#L248](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L248)

### 4. 로드 진입점

로드 인터페이스 자체의 시그니처는 다음과 같으며,예외는 경로 해석 단계에서만 던져지고,실제 패키지 읽기 실패는 Unity 내부에서 던져집니다:

```csharp
public static AssetBundleCreateRequest LoadAssetBundleAsync(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFileAsync(info.readPath, crc, (ulong)info.offset);
}

public static AssetBundle LoadAssetBundle(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFile(info.readPath, crc, (ulong)info.offset);
}
```

Source: [BlankReadAssets.cs#L119-L130](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L119-L130)

`GetInfoOrThrow`가 파일을 찾았지만 `AssetBundle.LoadFromFile`이 여전히 오류를 발생시킨다면,문제는 패키징 결과물 자체(CRC 불일치,offset 오류,압축 등)에 있으므로 빌드 측에서 다시 확인해야 합니다.

## 검증

1. `LoadAssetBundle` 호출 전 먼저 `BlankReadAssets.FileExists(path)`를 호출하여 `true`가 반환되는지 확인.
2. Editor에서 정상적으로 로드되는 경로를 실기에 글자 그대로 복사:대소문자,구분자,디렉터리 계층이 완전히 일치해야 함.
3. Android 실기에서 `FileExists`가 `true`이지만 로드가 여전히 실패하면,`.ab`가 APK 내에서 압축되었는지 확인하고,먼저 `SetCompressedAssetBundleFileNames`에 등록해야 함.
