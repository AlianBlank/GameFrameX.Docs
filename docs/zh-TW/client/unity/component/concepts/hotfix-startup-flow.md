# 工作原理：Hotfix 入口與啟動流程

Hotfix 啟動由框架內的 [`HotfixHelper`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs) 負責：它在執行階段載入 AOT DLL 與熱更 DLL，定位約定的入口型別與方法，並透過反射觸發熱更程式碼的初始化。應用層透過 [`ApplicationHotfixLauncher`](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs) 將這套邏輯適配到啟動管線的 `IHotfixLauncher` 介面上。

## 啟動入口一覽

| 入口 | 型別 | 作用 |
|------|------|------|
| `HotfixHelper.StartHotfix()` | `async void` | 以預設選項觸發，丟棄回傳結果 |
| `HotfixHelper.StartHotfixAsync(StartupOptions)` | `async UniTask<HotfixLaunchResult>` | 非同步載入並回傳啟動結果 |
| `ApplicationHotfixLauncher.StartAsync(StartupOptions)` | `UniTask<HotfixLaunchResult>` | `IHotfixLauncher` 適配器，轉發到 `HotfixHelper.StartHotfixAsync` |

預設參數（`options == null` 或欄位為空時生效）：

| 欄位 | 預設值 |
|------|--------|
| `HotfixAssemblyName` | `Unity.Hotfix` |
| `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` |
| `HotfixEntryMethodName` | `Main` |

## 啟動步驟

1. 呼叫 `HotfixHelper.StartHotfixAsync(options)`，方法會進入由 `try/catch` 包裹的內部實作 `StartHotfixInternalAsync`。
2. 解析最終的 `assemblyName` / `entryTypeName` / `entryMethodName`，預設值分別為 `Unity.Hotfix`、`Hotfix.HotfixLauncher`、`Main`。
3. 根據巨集 `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR` 選擇載入路徑：
   - **啟用 HybridCLR（且非 Editor）**：先迭代 `AOTGenericReferences.PatchedAOTAssemblyList`，對每個 AOT DLL 透過 `GameApp.Asset.LoadAssetAsync<UnityEngine.Object>` 載入並呼叫 `RuntimeApi.LoadMetadataForAOTAssembly`；再載入 `Unity.Hotfix.dll` 並呼叫 `Assembly.Load`。
   - **Editor 或未啟用 HybridCLR**：直接進入 `RunNative`，透過 `Utility.Assembly.GetType` 反射呼叫入口。
4. 反射命中目標型別與方法後執行 `method.Invoke(null, null)`，熱更層取得控制權。
5. 成功時回傳 `HotfixLaunchResult.Succeed()`；擲出例外時透過 `Log.Error` 記錄並回傳 `HotfixLaunchResult.Fail(e.Message)`。

```csharp
public static async UniTask<HotfixLaunchResult> StartHotfixAsync(StartupOptions options)
{
    try
    {
        await StartHotfixInternalAsync(options);
        return HotfixLaunchResult.Succeed();
    }
    catch (Exception e)
    {
        Log.Error(e);
        return HotfixLaunchResult.Fail(e.Message);
    }
}
```

## 關鍵載入路徑

| 階段 | 呼叫 | 說明 |
|------|------|------|
| AOT 中繼資料載入 | `RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet)` | HybridCLR 模式下必須先載入所有 AOT DLL，否則熱更程式碼中泛型共用會失敗 |
| 熱更 DLL 載入 | `Assembly.Load(assemblyDataHotfixDll, null)` | 將位元組陣列載入為執行階段組件 |
| 入口反射 | `assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | 透過反射呼叫無參數靜態入口 |
| 原生回退 | `Utility.Assembly.GetType(entryTypeName).GetMethod(entryMethodName).Invoke(null, null)` | 非 HybridCLR 模式從已載入的 AppDomain 中尋找入口型別 |

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `entryType` 為 `null`，反射擲出 `NullReferenceException` | 傳入的 `HotfixEntryTypeName` 與 DLL 內型別不相符，或 `Unity.Hotfix.dll` 未打包進資源 | 確認 `options.HotfixEntryTypeName` 與 DLL 中命名空間/類別名稱完全一致；檢查 `Utility.Asset.Path.GetCodePath("Unity.Hotfix.dll")` 是否能解析到資源 |
| 泛型方法呼叫擲出 `MissingMethodException` 或 `TypeLoadException` | HybridCLR 模式下未載入 `AOTGenericReferences.PatchedAOTAssemblyList` 中的 AOT DLL | 檢查 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 巨集是否啟用，確認 `AOTGenericReferences` 已產生並隨包發布 |
| Editor 下載入不到 `Unity.Hotfix` 組件 | `StartHotfixInternalAsync` 在 Editor 走 `Utility.Assembly.GetAssemblies()` 遍歷，未命中大小寫敏感的名稱 | 在 `StartupOptions.HotfixAssemblyName` 中明確傳入正確名稱，或確認組件名稱 `Unity.Hotfix` 與 DLL 一致 |
| `StartHotfix()` 擲出後沒有錯誤回呼 | `StartHotfix` 是 `async void`，例外僅寫入日誌 | 改用 `StartHotfixAsync(options)` 接收 `HotfixLaunchResult`，檢查 `Succeed` / `Fail` 欄位 |
