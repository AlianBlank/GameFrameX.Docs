# JSON レスポンスの解析方法

GameFrameX.Web では、JSON レスポンス解析の核心は、レスポンス文字列に対して拡張メソッド `ToHttpJsonResultData<T>()` を呼び出すことです。このメソッドはサーバー側の統一構造（`code`/`message`/`data`）を `HttpJsonResultData<T>` に逆シリアル化し、`code` に基づいて `IsSuccess` を自動的に設定します。フレームワークの基盤では LitJSON（`GameFrameX.LitJSON.Runtime.JsonMapper`）を使用して逆シリアル化を行います。

## 前提条件

- プロジェクトに `GameFrameX.Web` と `GameFrameX.LitJSON` のランタイムモジュールが導入済みであること。
- サーバー側が統一された JSON 構造を返し、フィールドは小文字の `code`、`message`、`data` であること：

```json
{
  "code": 0,
  "message": "ok",
  "data": "{\"id\":1,\"name\":\"Player\"}"
}
```

ここで `code == 0` は成功を示し、`data` はネストされた JSON 文字列です（`T` として再度逆シリアル化されます）。

## 操作手順

1. ビジネスデータモデル `T` を定義します。`class` であり、引数なしコンストラクタを含む必要があります（拡張メソッドのシグネチャ制約は `where T : class, new()`）。フィールド名が JSON と一致しない場合は `[JsonProperty("...")]` で注記します。

```csharp
using GameFrameX.LitJSON.Runtime;

public sealed class PlayerInfo
{
    [JsonProperty("id")]
    public int Id { get; set; }

    [JsonProperty("name")]
    public string Name { get; set; }
}
```

2. レスポンス文字列を取得した後、拡張メソッドを呼び出して結果オブジェクトを得ます：

```csharp
using GameFrameX.Web.Runtime;

HttpJsonResultData<PlayerInfo> result = responseText.ToHttpJsonResultData<PlayerInfo>();
```

3. `IsSuccess` / `Code` に基づいて結果を処理します：

```csharp
if (result.IsSuccess)
{
    PlayerInfo player = result.Data;
    Debug.Log($"プレイヤー：{player.Id} {player.Name}");
}
else
{
    // Code が 0 以外の場合はサーバー側のエラーコード。Code が 0 かつ IsSuccess が false の場合、逆シリアル化で例外が発生したことを示す
    Log.Error($"リクエスト失敗、Code={result.Code}");
}
```

`ToHttpJsonResultData<T>` の完全なロジック（まずシェルを解析し、その後 `data` を再解析）は以下の通りです：

```csharp
public static HttpJsonResultData<T> ToHttpJsonResultData<T>(this string jsonResult) where T : class, new()
{
    HttpJsonResultData<T> resultData = new HttpJsonResultData<T>
    {
        IsSuccess = false,
    };
    try
    {
        // JSON文字列をHttpJsonResultオブジェクトに逆シリアル化
        var httpJsonResult = JsonMapper.ToObject<HttpJsonResult>(jsonResult);
        // レスポンスコードが成功を示しているか確認
        if (httpJsonResult.Code != 0)
        {
            resultData.Code = httpJsonResult.Code;
            return resultData; // デフォルトの失敗結果を返す
        }

        resultData.IsSuccess = true; // 成功フラグを設定
        // データ部分を逆シリアル化。データが空の場合は型Tのデフォルトインスタンスを返す
        resultData.Data = string.IsNullOrEmpty(httpJsonResult.Data) ? new T() : JsonMapper.ToObject<T>(httpJsonResult.Data);
    }
    catch (Exception e)
    {
        // 例外情報をキャプチャして出力
        Log.Error(e);
    }

    return resultData; // 結果データを返す
}
```

## よくあるバリエーション

- **シェル構造のみが必要で、強く型付けされた Data が不要な場合**：`JsonMapper.ToObject<HttpJsonResult>(json)` を直接使用して `Code` / `Message` / `Data` の 3 つのフィールドを取得します（このとき `Data` は元の文字列です）。

```csharp
var shell = JsonMapper.ToObject<HttpJsonResult>(responseText);
Debug.Log($"code={shell.Code}, message={shell.Message}");
```

Source: [HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L9-L33)

- **リクエスト段階で文字列レスポンスを取得する場合**：`WebManager` 内部では `WebJsonData`（プライベートなリクエスト記述クラス）を介して `TaskCompletionSource<WebStringResult>` / `TaskCompletionSource<WebBufferResult>` が紐付けられ、それぞれ文字列結果とバイト配列結果に対応します。文字列結果はそのまま `ToHttpJsonResultData<T>` に渡すことができます。Web リクエストの送信方法については、『HTTP リクエストを送信する方法』を参照してください。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| `IsSuccess == false` かつ `Code != 0` | サーバーが 0 以外のレスポンスコードを返し、`Data` は `null` のまま | `Code` に基づいてビジネスエラーを処理。`Code` の値の意味はサーバー側との取り決めによる |
| `IsSuccess == false` かつ `Code == 0` | 逆シリアル化で例外が発生し、`catch (Exception e)` で握りつぶされて `Log.Error(e)` が出力される | コンソールのエラーログを確認。JSON 形式とフィールド名のマッピングをチェック |
| コンパイルエラーが発生：`new()` 制約がない | `T` が構造体、または引数なしコンストラクタを持たない | モデルを引数なしコンストラクタを持つ `class` に変更する |
| `Data` のフィールドがすべてデフォルト値 | フィールド名が JSON キーと一致せず、`[JsonProperty]` も注記されていない | `[JsonProperty("元のキー名")]` で明示的にマッピングする |
| `Data` がすべてデフォルト値のインスタンスなのに `IsSuccess == true` | サーバーが返す `data` が空文字列で、この場合は `new T()` が返される | サーバー側で成功時に有効な `data` を含める、またはクライアント側で必要に応じて空チェックを行う |
| どのフィールドも解析されない | シェルのフィールド名が小文字の `code`/`message`/`data` ではない | サーバー側と統一シェル構造を取り決める。[HttpJsonResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Extensions/HttpJsonResult.cs#L14-L27) を参照 |

## 検証

- `{"code":0,"message":"ok","data":"{\"id\":1,\"name\":\"a\"}"}` 文字列を構築して `ToHttpJsonResultData<PlayerInfo>()` を呼び出すと、`IsSuccess == true` かつ `Data.Id == 1` が得られるはずです。
- `code` を 0 以外（例：`1001`）に変更すると、`IsSuccess == false`、`Code == 1001`、`Data == null` が得られるはずです。
- 文字列を不正な JSON に変更すると、`IsSuccess == false`、`Code == 0` が得られ、ログに例外の出力が表示されるはずです。

## 背景

`HttpJsonResultData<T>` は「統一シェル + ビジネスデータ」の薄いラッパーにすぎません：`IsSuccess`（デフォルト `false`）、`Code`（int、0 が成功）、`Data`（`T`、失敗時は `null`）。拡張メソッド内部ではまず `HttpJsonResult` に逆シリアル化して `code` をチェックし、成功後に `data` を再度逆シリアル化します。例外はすべてキャッチされ、外部にスローされないため、呼び出し側は `IsSuccess` と `Code` の 2 つのフラグだけを気にすればよい設計です。
