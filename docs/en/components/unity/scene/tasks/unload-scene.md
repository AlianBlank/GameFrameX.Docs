# How to Unload a Scene

Use `SceneComponent.UnloadScene(sceneAssetName, userData)` to unload a scene that has already been loaded. The framework raises `UnloadSceneSuccess` / `UnloadSceneFailure` events upon completion or failure, making it convenient to handle resource cleanup, UI closing, and other follow-up logic at the event layer.

## Prerequisites

- The scene has been loaded via the [How to Load a Scene](tasks/load-scene) process (verify using `SceneIsLoaded` or `GetLoadedSceneAssetNames`).
- The asset name of the scene to unload is known and must conform to the `Assets/.../xxx.unity` format (e.g., `Assets/Game/Scenes/Login.unity`).
- The business side has subscribed to `UnloadSceneSuccessEventArgs` (event Id is `GameFrameX.Scene.Runtime.UnloadSceneSuccessEventArgs`) and `UnloadSceneFailureEventArgs`, used to perform follow-up work after unloading completes.

## Steps

1. Obtain `SceneComponent`. It is automatically registered to `GameEntry` by `GameFrameXAutoComponent(-4000)`, and can be obtained directly:

```csharp
var sceneComponent = GameEntry.GetComponent<SceneComponent>();
if (sceneComponent == null)
{
    Log.Error("Scene component is invalid.");
    return;
}
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L48-L67)

2. Call `UnloadScene`. The second parameter `userData` is optional and will be passed back as-is in the callback event:

```csharp
// Unload only
sceneComponent.UnloadScene("Assets/Game/Scenes/Login.unity");

// With business data, convenient for identifying this unload in the callback
sceneComponent.UnloadScene("Assets/Game/Scenes/Login.unity", requestGuid);
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L324-L344)

3. Listen to unload events to determine the result. The events are bound internally by the component during the `Awake` phase to `IGameSceneManager.UnloadSceneSuccess` / `UnloadSceneFailure`:

```csharp
// In some GameFramework module / Event subscriber
EventComponent.Subscribe(UnloadSceneSuccessEventArgs.EventId, OnUnloadSceneSuccess);
EventComponent.Subscribe(UnloadSceneFailureEventArgs.EventId, OnUnloadSceneFailure);

private void OnUnloadSceneSuccess(object sender, GameEventArgs e)
{
    var args = (UnloadSceneSuccessEventArgs)e;
    // args.SceneAssetName: the asset name of the unloaded scene
    // args.UserData: the custom data passed in (can be null)
}

private void OnUnloadSceneFailure(object sender, GameEventArgs e)
{
    var args = (UnloadSceneFailureEventArgs)e;
    // args.SceneAssetName / args.UserData / args.ErrorMessage
}
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L104-L105)

See [UnloadSceneSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/UnloadSceneSuccessEventArgs.cs#L60-L90) and [UnloadSceneFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/UnloadSceneFailureEventArgs.cs) for event field definitions.

4. During unload, the following interfaces can be used to query status and avoid unloading the same scene repeatedly:

```csharp
bool unloading = sceneComponent.SceneIsUnloading("Assets/Game/Scenes/Login.unity");
string[] allUnloading = sceneComponent.GetUnloadingSceneAssetNames();
```

Source: [SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L240-L262)

## Common Variants

- **Unloading with additive scenes**: `UnloadScene` only unloads scene handles managed by `IGameSceneManager`. Other scenes loaded directly via `UnityEngine.SceneManagement.SceneManager.LoadScene` are not managed by this component and must be unloaded manually.
- **Reactivating another scene before unloading**: Call `SetSceneOrder(otherScene, higherOrder)` first, then `UnloadScene(currentScene)`. The component will automatically set the scene with the highest priority as the active scene after `UnloadSceneSuccess`.

## Common Errors

| Error Symptom | Trigger Condition | Fix |
|----------|----------|------|
| Throws `ArgumentNullException` | `sceneAssetName` is empty | Validate with `string.IsNullOrEmpty` before calling |
| Throws `ArgumentException("Scene asset name '...' is invalid.")` | The asset name does not start with `Assets/` or end with `.unity` | Use the complete Unity project-relative path, e.g., `Assets/Game/Scenes/Login.unity` |
| UI/objects remain after unloading completes | No subscription to `UnloadSceneSuccess` for follow-up | Clean up HUD and release resources bound to the scene in `OnUnloadSceneSuccess` |
| Multiple `UnloadScene` calls on the same scene | Calling directly without checking `SceneIsUnloading` | Use `SceneIsUnloading` / `SceneIsLoaded` before calling to prevent duplicates |

## Background (Optional)

`UnloadScene` only performs parameter validation inside the component, then forwards to the underlying `IGameSceneManager.UnloadScene` (with the actual unload implementation of `SceneHandle` provided by YooAsset). Unloading is asynchronous, and the call returns `void`, so the business side must learn the result through the `UnloadSceneSuccess` / `UnloadSceneFailure` events rather than relying on the return value.
