# 5분 만에 첫 번째 다운로드 작업 실행하기

이 페이지의 단계를 따라 하면 5분 안에 하나의 파일을 URL에서 로컬 디스크로 완전히 다운로드하고, 이벤트를 통해 성공/실패 콜백을 받을 수 있습니다.

## 사전 조건

- Unity 2019.4 이상 버전
- 본 패키지가 설치되어 있어야 합니다(세 가지 방식 중 하나 선택, README 참조):
  - `Packages/manifest.json`의 `scopedRegistries`에 GameFrameX 레지스트리를 추가하고, `dependencies`에 `com.gameframex.unity.download`를 추가
  - 또는 Package Manager에서 Git URL을 통해 `https://github.com/gameframex/com.gameframex.unity.download.git`를 추가
  - 또는 리포지토리를 `Packages/` 디렉터리에 직접 배치
- 씬에 `GameFramework` 시작 진입점이 존재하며, `DownloadComponent`가 마운트되어 있어야 합니다(컴포넌트는 기본적으로 `GameEntry`에 자동 등록됨)

## 작업 단계

1. **컴포넌트 마운트 확인**. `DownloadComponent`는 `[GameFrameXAutoComponent(-4000)]`를 통해 자동 등록되며, 시작 후 `GameEntry`에서 가져올 수 있습니다:

   ```csharp
   var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L44-L46)

2. **첫 번째 다운로드 작업 추가**. 최소한의 호출에는 두 개의 매개변수만 필요합니다: 로컬 저장 경로 `downloadPath`와 원격 주소 `downloadUri`이며, 작업 시리얼 ID를 반환합니다:

   ```csharp
   int serialId = downloadComponent.AddDownload(
       "/本地保存路径/file.zip",      // downloadPath
       "https://example.com/file.zip"  // downloadUri
   );
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L271-L280)

3. **성공/실패 이벤트 구독**(권장). `EventComponent`를 통해 `DownloadSuccess`와 `DownloadFailure`를 구독합니다:

   ```csharp
   var eventComponent = GameEntry.GetComponent<EventComponent>();
   eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
   eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);

   void OnDownloadSuccess(object sender, GameEventArgs e)
   {
       var args = (DownloadSuccessEventArgs)e;
       if (args.SerialId == serialId) { /* 다운로드 완료 */ }
   }

   void OnDownloadFailure(object sender, GameEventArgs e)
   {
       var args = (DownloadFailureEventArgs)e;
       Debug.LogError($"下载失败:{args.ErrorMessage}");
   }
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/README.zh-CN.md#L98-L127)

4. **또는 비동기 방식 사용**. 이벤트를 구독하고 싶지 않다면 `Download(...)`의 반환값을 직접 `await`할 수 있습니다:

   ```csharp
   bool success = await downloadComponent.Download(
       "/本地保存路径/file.zip",
       "https://example.com/file.zip"
   );

   if (success) { /* 다운로드 완료 */ }
   ```

   Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L306-L312)

5. **검증**. 씬을 실행한 후 대상 경로를 확인하여 파일이 존재하고 `OnDownloadSuccess`가 트리거되면 성공입니다. 계속 트리거되지 않으면 아래의 '일반적인 오류'를 참조하세요.

## 일반적인 변형

- **우선순위 및 태그 설정** —— 값이 클수록 우선순위가 높으며, 태그별로 그룹화하여 조회하거나 일괄 제거할 수 있습니다:

  ```csharp
  int id = downloadComponent.AddDownload(
      downloadPath, downloadUri,
      tag: "assets",
      priority: 10
  );
  TaskInfo[] infos = downloadComponent.GetDownloadInfos("assets");
  downloadComponent.RemoveDownloads("assets");
  ```

  Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L339-L348)

- **전역 일시정지 / 재개** —— `Paused` 속성을 전환하면 모든 에이전트에 적용됩니다:

  ```csharp
  downloadComponent.Paused = true;   // 일시정지
  downloadComponent.Paused = false;  // 재개
  ```

  Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L69-L73)

- **단일 결과만 필요한 경우**(간단한 작성법) —— `Download(path, uri)`가 반환하는 `Task<bool>`를 직접 await하면 되며, 이벤트를 구독할 필요가 없습니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `GetComponent<DownloadComponent>()`가 null을 반환함 | 씬에 `GameFramework` 시작 컴포넌트가 마운트되지 않았거나, 패키지가 올바르게 임포트되지 않음 | `Packages/manifest.json`의 의존성이 적용되었는지 확인하고 시작 진입점을 점검하세요 |
| 다운로드 콜백이 계속 트리거되지 않음 | `AddDownload`만 호출하고 `DownloadSuccessEventArgs` / `DownloadFailureEventArgs`를 구독하지 않았거나, 콜백에서 `SerialId`를 매칭하지 않음 | 두 이벤트를 구독하고, 콜백에서 `args.SerialId == serialId`로 필터링하세요 |
| 파일이 예상치 못한 위치에 기록됨 | `downloadPath`에 상대 경로를 사용했으며, Unity는 플랫폼마다 기준 경로가 다름 | 절대 경로를 사용하세요(예: `Application.persistentDataPath + "/file.zip"`) |
| 다운로드가 멈춘 채 끝나지 않음 | `Paused`가 `true`로 설정되어 전역적으로 일시정지됨 | `downloadComponent.Paused = false`로 설정하세요 |

## 배경(선택 사항)

`DownloadComponent`는 내부적으로 `IDownloadManager`를 사용하여 구성 가능한 수의 다운로드 에이전트 풀을 관리하며, 기본적으로 3개의 에이전트가 동시에 실행되고 작업은 우선순위에 따라 디스패치됩니다. 하위 레이어는 `UnityWebRequestDownloadAgentHelper`를 통해 Unity의 `UnityWebRequest`와 통신하며, Inspector를 통해 사용자 지정 `IDownloadAgentHelper` 구현으로 교체할 수 있습니다. `FlushSize`(기본 1 MB)는 디스크 플러시 임계값을 제어하며, 이어받기에 사용됩니다.
