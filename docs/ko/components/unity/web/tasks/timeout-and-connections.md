# 타임아웃 및 동시 연결 수 구성 방법

GameFrameX.Web에서 타임아웃 `Timeout`은 Inspector 직렬화 필드 또는 코드로 설정할 수 있으며(기본값 5초), 동시 연결 수 `MaxConnectionPerServer`는 코드를 통해서만 `IWebManager`에서 설정할 수 있습니다(기본값 8). 이 값은 일반(JSON) 요청과 바이너리 요청, 두 개의 스케줄링 채널에서 동시에 처리되는 수량을 각각 제한합니다.

## 사전 조건

- 씬에 `WebComponent` 컴포넌트가 이미 추가되어 있어야 합니다(메뉴 `GameFrameX/Web`).
- 코드에서 관리자에 접근해야 하는 경우 네임스페이스 `GameFrameX.Web.Runtime`과 `GameFrameX.Runtime`을 참조하세요.

## 작업 단계

### 1. Inspector에서 타임아웃 설정

`WebComponent`가 추가된 GameObject를 선택한 후, Inspector에서 **타임아웃** 필드를 수정합니다(단위: 초, 기본값 5):

```csharp
[SerializeField] [Tooltip("타임아웃. 단위: 초")]
private float m_Timeout = 5f;
```

출처: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L59-L60)

컴포넌트의 `Awake()` 시 이 값이 관리자에 기록됩니다:

```csharp
m_WebManager = GameFrameworkEntry.GetModule<IWebManager>();
if (m_WebManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebManager.Timeout = m_Timeout;
```

출처: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L88)

### 2. 코드에서 런타임에 타임아웃 조정

`WebComponent.Timeout`은 관리자에 직접 프록시되며, 동시에 값을 직렬화 필드에 다시 기록합니다:

```csharp
public float Timeout
{
    get { return m_WebManager.Timeout; }
    set { m_WebManager.Timeout = m_Timeout = value; }
}
```

출처: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L66-L70)

사용 예시:

```csharp
// 컴포넌트 Awake 이후에 호출, 예: Start()
webComponent.Timeout = 15f; // 전역 타임아웃을 15초로 변경
```

### 3. 코드에서 동시 연결 수 설정

`MaxConnectionPerServer`는 `WebManager` / `IWebManager`에만 존재하며 `WebComponent`에는 노출되지 않으므로 반드시 코드를 통해 수정해야 합니다:

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// 타임아웃(초)을 가져오거나 설정합니다
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>
/// 서버당 최대 연결 수를 가져오거나 설정합니다
/// </summary>
public int MaxConnectionPerServer { get; set; }
```

출처: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L42-L70)

사용 예시(`WebComponent.Awake`에서 모듈을 가져오는 방식과 동일):

```csharp
GameFrameworkEntry.GetModule<IWebManager>().MaxConnectionPerServer = 4; // 각 채널당 동시 최대 4개 요청
```

출처: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L81)

## 일반적인 변형

**두 채널의 동시 처리를 각각 제어**： 일반(JSON) 요청과 바이너리 요청은 동일한 `MaxConnectionPerServer` 값을 공유하지만 각각 독립적으로 카운트됩니다 — 스케줄링 진입점은 각각 `m_SendingNormalList`(일반)와 `m_SendingBinaryList`(바이너리)입니다:

```csharp

if (m_SendingNormalList.Count < MaxConnectionPerServer)
{
    if (m_WaitingNormalQueue.Count > 0)
    {
        var webJsonData = m_WaitingNormalQueue.Dequeue();
        // ...요청을 시작하고 m_SendingNormalList에 추가
    }
}
```

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Inspector에서 타임아웃을 변경했지만 적용되지 않음 | `Awake()` 이후 코드에서 `WebComponent.Timeout` 또는 `m_WebManager.Timeout`으로 값을 다시 덮어씀 | 한 곳에서 통일하여 구성; 런타임에 값을 변경하려면 `Start()` 또는 그 이후에 수행 |
| Inspector에서 동시 연결 수를 변경하려고 해도 필드를 찾을 수 없음 | `MaxConnectionPerServer`가 `WebComponent`에 직렬화되지 않음 | `GameFrameworkEntry.GetModule<IWebManager>()`를 통해 코드로 설정 |
| `Timeout = 0.5f`로 설정한 후 요청이 오랫동안 타임아웃되지 않음 | UnityWebRequest에 전달 시 `(int)RequestTimeout.TotalSeconds`로 잘리며, 1초 미만이면 `0`이 됨 | 타임아웃 값은 최소 `1f` 이상 또는 그보다 큰 정수 초로 설정 |
| `MaxConnectionPerServer`를 전역 총 동시 처리 수로 이해함 | 일반/바이너리 두 채널이 각각 해당 값으로 독립적으로 판단함 | 동시 처리 상한을 평가할 때 채널별로 각각 계산 |

## 배경(선택)

`Timeout`의 setter는 `RequestTimeout = TimeSpan.FromSeconds(value)`를 동시에 파생시키며, 요청이 실제로 생성될 때 이 값이 하위 `UnityWebRequest.timeout`(초) 또는 `HttpWebRequest.Timeout`(밀리초)에 기록됩니다. 따라서 타임아웃 수정은 이후 새로 시작되는 요청에만 영향을 미칩니다. 동시 처리 측면에서 요청은 먼저 대기 큐에 들어가고, `WebManager.Update`가 매 프레임 `m_SendingNormalList.Count < MaxConnectionPerServer`를 검사하여 조건을 만족할 때만 큐에서 꺼내 요청을 시작하며, 초과분은 계속 대기합니다.
