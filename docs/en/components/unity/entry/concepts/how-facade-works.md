# How It Works: Facade Layer, Conditional Compilation, and Lazy Loading

`GameApp` is a static facade class that splits each component's access entry point into a separate source file via the C# `partial` keyword, enables them on demand through `#if` conditional compilation, and finally implements lazy loading with field caching.

## Overview of the Three Mechanisms

| Mechanism | Purpose | Implementation Location |
|------|------|----------|
| `partial class GameApp` | Merges all component access entry points into the same `GameApp` class | [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53) |
| `#if ENABLE_GAME_FRAME_X_*` | When a module is not enabled, its fields, properties, and using directives are all excluded from compilation | [Runtime/GameApp.Advertisement.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Advertisement.cs#L32-L56) |
| Field caching + `GetComponent<T>()` | Fetches the component from `GameEntry` on the first access and returns the cached field directly afterwards | [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L39-L52) |

## Understanding the Facade Layer in Three Steps

1. **Unified entry points**. All modules are accessed through the static property `GameApp.<ModuleName>`, so business code does not need to hold a `GameEntry` reference or care about component lifecycles.
2. **Compile-time trimming**. Each module (advertisement, login, hot update, network, etc.) corresponds to a separate `GameApp.<ModuleName>.cs` file, wrapped at the top and bottom with `#if ENABLE_GAME_FRAME_X_<MODULE>` / `#endif`. When the macro is not defined, the entire file is excluded from compilation—it adds no size and introduces no dependency on the module package.
3. **Runtime lazy loading**. The `if (_xxx == null)` check inside the static property ensures that `GameEntry.GetComponent<T>()` is executed only on the first access; afterwards the cached field is returned directly, avoiding repeated lookups.

## Typical Code Snippets

`GameApp.Base` is the minimal working example of the facade layer, exposing only a property and a private cached field:

```csharp
public static partial class GameApp
{
    /// <summary>
    /// Gets the game base component.
    /// </summary>
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }

            return _base;
        }
    }

    private static BaseComponent _base;
}
```

Source: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

Modules that require conditional compilation (such as advertisement) add an `#if` guard on the outside:

```csharp
#if ENABLE_GAME_FRAME_X_ADVERTISEMENT
using GameFrameX.Runtime;
using GameFrameX.Advertisement.Runtime;

public static partial class GameApp
{
    /// <summary>
    /// Gets the advertisement component.
    /// </summary>
    public static AdvertisementComponent Advertisement
    {
        get
        {
            if (_advertisement == null)
            {
                _advertisement = GameEntry.GetComponent<AdvertisementComponent>();
            }

            return _advertisement;
        }
    }

    private static AdvertisementComponent _advertisement;
}
#endif
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Accessing `GameApp.Advertisement` throws a "type not found" error | `ENABLE_GAME_FRAME_X_ADVERTISEMENT` is not defined in Player Settings / asmdef | Enable the corresponding module package and define the macro, or add it to `scriptingDefineSymbols` |
| Missing `using` errors even after enabling the macro | The module package is not installed | Install the corresponding module (e.g., `GameFrameX.Advertisement`) via NuGet/UPM |
| `GetComponent<T>()` returns `null` | The target component is not attached to `GameEntry` | Attach the corresponding `Component` subclass to the `GameEntry` prefab; see "How to Attach and Initialize Components" |

## Background (Optional)

Putting each module's access entry point into a separate `partial` file is equivalent to "splitting source code by module, controlling what gets compiled via macros, and lazily loading instances on demand". This approach keeps the framework core lean: business code enables the macro only for the modules it references; unreferenced modules are neither compiled nor packaged, and the only runtime overhead is a single static property getter.
