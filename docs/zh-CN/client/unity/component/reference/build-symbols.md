# 构建宏与条件编译符号说明

本页面汇总 GameFrameX 框架在源码、Assembly Definition 与 Unity Player Settings 中实际用到的**构建宏 / 条件编译符号**,并说明每个符号的生效平台、定义位置以及如何在工程中启用或检测它们。

> 凡是带 `UNITY_` 前缀的符号由 Unity 引擎自动注入;框架自定义符号(如 `ENABLE_GAME_FRAME_X_HYBRID_CLR`)通过 `asmdef` 的 `versionDefines` 自动注入。

## 符号速查表

| 符号 | 作用域 | 定义来源 | 用途 |
|------|--------|----------|------|
| `UNITY_EDITOR` | Editor 程序集 | Unity 自动注入 | 仅在编辑器生效的代码块 |
| `UNITY_ANDROID` | Android 平台 | Unity 自动注入 | Android 平台特化逻辑 |
| `UNITY_IOS` | iOS 平台 | Unity 自动注入 | iOS 平台特化逻辑 |
| `UNITY_STANDALONE` | 独立平台(Win/Mac/Linux) | Unity 自动注入 | 桌面端特化逻辑 |
| `UNITY_2018_1_OR_NEWER` | 版本探测 | Unity 自动注入 | 版本兼容分支 |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` | 启用 HybridCLR 热更的程序集 | `versionDefines`(检测 `com.code-philosophy.hybridclr` 包) | 控制与 HybridCLR 集成相关的代码路径 |

> 完整 Unity 平台/版本宏列表见 Unity 官方文档(运行时符号不会出现在源码中,但会被编译器自动识别)。

## 框架自定义符号:ENABLE_GAME_FRAME_X_HYBRID_CLR

该符号是框架层面目前**唯一**通过 `asmdef` 的 `versionDefines` 注入的自定义宏。当工程中安装 `com.code-philosophy.hybridclr` 包时,Unity 会自动向 `GameFrameX.Startup.Application` 程序集注入该宏,从而启用与 HybridCLR 热更相关的代码路径。

```json
{
    "name": "GameFrameX.Startup.Application",
    "references": [
        "GameFrameX.Runtime",
        "HybridCLR.Runtime",
        "HybridCLRData"
    ],
    "versionDefines": [
        {
            "name": "com.code-philosophy.hybridclr",
            "expression": "",
            "define": "ENABLE_GAME_FRAME_X_HYBRID_CLR"
        }
    ]
}
```

Source: [Unity.Startup.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Unity.Startup.asmdef#L33-L39)

### 使用示例

```csharp
using UnityEngine;

namespace GameFrameX
{
    public static class HotUpdateGate
    {
        public static bool IsHotUpdateSupported
        {
            get
            {
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
                return true;
#else
                return false;
#endif
            }
        }
    }
}
```

### 验证宏是否生效

在 Unity 中执行菜单 **Window → General → Test Runner** 或在任意脚本里通过反射读取:

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR
    Debug.Log("HybridCLR 已启用,热更代码会进入热更程序集。");
#else
    Debug.LogWarning("未启用 HybridCLR,Startup 会以 AOT 方式运行。");
#endif
```

若输出 *HybridCLR 已启用* 字样,说明 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 已成功注入。

## 平台宏的实际用法

### Android 平台特化设置

`ProjectSettingEditor.cs` 在 Android 平台上关闭安全区限制,并写入团队 ID 占位符;非 Android 平台该分支会被编译器剔除。

```csharp
public override void OnInspectorGUI()
{
    base.OnInspectorGUI();
    PlayerSettings.assemblyVersionValidation = false;
#if UNITY_ANDROID
    PlayerSettings.Android.renderOutsideSafeArea = true;
#endif
#if UNITY_IOS
    PlayerSettings.iOS.appleDeveloperTeamID = "XXXXXX";
#endif
}
```

Source: [ProjectSettingEditor.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/ProjectSettingEditor/ProjectSettingEditor.cs#L28-L52)

### 版本兼容分支

`AutoCopySymbolsPostprocessor.cs` 使用 `UNITY_2018_1_OR_NEWER` 屏蔽 32 位 x86 架构处理逻辑(Unity 2018.1 起不再支持 Android x86 构建)。

```csharp
#if UNITY_2018_1_OR_NEWER

#else
    if ((PlayerSettings.Android.targetArchitectures & AndroidArchitecture.X86) > 0)
    {
        var dir = CopySymbols(symbolsDir, abi_x86);
        GenerateAllSymbols(dir);
    }
#endif
```

## 平台级程序集隔离

`includePlatforms` / `excludePlatforms` 控制程序集是否参与对应平台构建,**不需要**额外宏。

| 程序集 | includePlatforms | 效果 |
|--------|------------------|------|
| `Unity.Editor` | `["Editor"]` | 仅编辑器构建,玩家包不会包含 |
| `Unity.Startup` / `Unity.HotFix` / `HybridCLRData` | `[]`(全部) | 所有平台构建都参与 |

Source: [Unity.Editor.asmdef](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Editor/Unity.Editor.asmdef#L11-L13)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 在 Android 设备上看到 x86 lib 文件残留 | 启用了过时的 `UNITY_2018_1_OR_NEWER` 之前路径 | 升级 Unity 至 2018.1+,让宏正确剔除 x86 处理 |
| HotFix 程序集未参与构建 | `UNITY_HOTFIX` 等老旧宏被误用 | 使用现代 HybridCLR 注入的 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 或 `includePlatforms` 配置 |
| 玩家包仍包含 Editor 工具代码 | `Unity.Editor` 程序集 `includePlatforms` 未设置为 `Editor` | 在 `.asmdef` 中显式声明 `"includePlatforms": ["Editor"]` |
| `ENABLE_GAME_FRAME_X_HYBRID_CLR` 始终未定义 | HybridCLR 包未安装或包名拼错 | 在 Package Manager 确认 `com.code-philosophy.hybridclr` 已安装,并核对 `asmdef` 中 `versionDefines.name` 拼写一致 |

## 添加自定义构建宏

1. 打开对应 `.asmdef`,在根级别加入 `defineConstraints` 或 `versionDefines`(用于受包管理控制)。
2. 若需全局生效(不受包管理控制),使用 **Edit → Project Settings → Player → Other Settings → Scripting Define Symbols**。
3. 在 C# 代码中使用标准 `#if SYMBOL_NAME ... #endif` 语法引用;Unity 在构建时自动按当前目标平台剔除不匹配的分支。
