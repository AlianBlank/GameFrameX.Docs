# 不要な Unity パッケージの削除方法

このツールを使用すると、`Packages/manifest.json` から指定した依存関係を一度に削除し、`Packages/` 下の対応するローカルパッケージディレクトリを削除できます。クリーンアップ完了後、自動的に `AssetDatabase.Refresh()` を呼び出します。全体的なフローは Unity Editor でコマンドライン引数によってトリガーされます。

## 前提条件

- Unity プロジェクトのルートディレクトリに `Packages/manifest.json` が存在する（標準的な UPM プロジェクト）。
- コマンドライン呼び出し側がプロセス引数で `-RemovePackages` 引数を渡せる（バッチ、CI、メニュー呼び出しのいずれも可）。
- `Newtonsoft.Json` が必要（`manifest.json` の解析はこのライブラリに依存し、Editor アセンブリには既に参照が含まれています）。

## 操作手順

1. 削除するパッケージ名のリストを用意する。パッケージ名は `manifest.json` の `dependencies` 配下の key と完全一致している必要があります（例：`com.unity.xr.management`）。
2. Unity Editor のコマンドラインに `-RemovePackages` 引数を渡し、後に半角カンマ区切りのパッケージ名リストを続けます。
3. `PackageRemovalHelper.Run()` をトリガーすると、ツールは以下の順序で実行されます：
   - コマンドライン引数を解析して削除対象パッケージのリストを取得する。`-RemovePackages` が渡されていない場合は直接例外をスローします。
   - `manifest.json` の `dependencies` から対応するエントリを削除し、一時ファイル経由でアトミックに書き戻す。
   - `Packages/<パッケージ名>` のローカルディレクトリを削除する（埋め込みパッケージ / file:// 参照パッケージ）。
   - `AssetDatabase.Refresh()` を呼び出す。

## よくあるバリエーション

- **`manifest.json` のみをクリアし、ローカルディレクトリは削除しない**：ツールは `dependencies[packageName]` の存在を一つずつ判定します。manifest にないエントリは `Debug.Log` でスキップするだけで、エラーにはなりません。
- **ローカル埋め込みパッケージディレクトリのみ削除する**：`manifest.json` に記載されていないが `Packages/` 下に置かれているローカルフォルダは、ツールが対応するディレクトリを削除します。逆も同様です — 両操作は互いに独立しています。
- **パスの安全保護**：パッケージ名に `/`、`\`、`:`、`..` のいずれかが含まれる場合は不正とみなしてスキップし、`Packages/` の外に漏れることはありません。

```csharp
if (string.IsNullOrWhiteSpace(packageName) ||
    packageName.IndexOfAny(new[] { '/', '\\', ':' }) >= 0 ||
    packageName.Contains(".."))
{
    Debug.LogWarning($"[PackageRemoval] 包名不合法，跳过: {packageName}");
    continue;
}
```

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| 例外がスローされる `未检测到 -RemovePackages 参数。用法: -RemovePackages 包名1,包名2,包名3` | コマンドラインで `-RemovePackages` が渡されていない、または値を付けるのを忘れた | 呼び出し引数に `-RemovePackages 包名1,包名2` を追加する |
| コンソールに `[PackageRemoval] manifest.json 中未找到依赖，跳过: xxx` が出力される | `manifest.json` にそのエントリがない（`Packages/` サブディレクトリにのみ存在する可能性あり） | パッケージ名が `manifest.json` の key と完全一致していることを確認する。ローカルディレクトリのみの削除は許可されています |
| `[PackageRemoval] manifest.json 不存在: ...` | プロジェクトが UPM プロジェクトではないか、パスが変更されている | `Packages/manifest.json` がプロジェクトルートにあることを確認する |
| `[PackageRemoval] 包名不合法，跳过: xxx` | 名前に `/`、`\`、`:`、`..` のいずれかが含まれている | 純粋なパッケージ名のみ使用する（例：`com.example.foo`）。バージョン番号やパスプレフィックスは付けない |
| `[PackageRemoval] 本地包目录不存在，跳过: xxx` | `manifest.json` でのみ宣言されたリモート依存で、ローカルにディレクトリがない | 正常な状況であり、対処は不要 |

## 背景（オプション）

ツールは「先に manifest を変更し、次にローカルディレクトリを削除し、最後に `AssetDatabase.Refresh`」という順序を採用しており、Unity が次回のリソースリフレッシュ時に削除済みの埋め込みパッケージを再解析しないようにしています。`manifest.json` は `*.tmp` を経由してから上書きする方式で書き込みされ、中途半端な書き込みによる JSON 破損を回避しています。
