# エンティティに監査/ソフトデリート/キャッシュ機能を付与する方法

`AuditTableAttribute`、`SoftDeleteAttribute`、`CacheTableAttribute` の 3 つの属性を使用することで、エンティティクラスに 1 行で ORM の監査追跡、ソフトデリート、クエリキャッシュ機能を宣言でき、ビジネスコードを変更することなく ORM フレームワークに認識させることができます。

## 前提条件

- プロジェクトが `GameFrameX.Foundation.Orm.Attribute` アセンブリ（3 つの属性クラスを含む）および `GameFrameX.Foundation.Orm.Entity`（`IAuditableEntity` インターフェースを含む）を参照していること。
- エンティティクラスが `GameFrameX.Foundation.Orm.Attribute` 名前空間下の属性を使用し、ファイルに `using GameFrameX.Foundation.Orm.Attribute;` を記述していること。
- 自動入力される「作成/更新時刻/操作者」フィールドを取得するには、エンティティに `IAuditableEntity` インターフェースを実装させます（`GameFrameX.Foundation.Orm.Entity` 名前空間下）。

## 操作手順

### 1. 監査追跡を有効化する

`[AuditTable]` をエンティティクラスに付与します。デフォルトでは `Enabled = true`、`AuditLevel = ChangesOnly`、`IncludeUserInfo = true` で、INSERT/UPDATE/DELETE の変更履歴を記録します。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[AuditTable(AuditLevel = AuditLevel.Full, IncludeUserInfo = true, IncludeIpAddress = true)]
public class UserAccount
{
    public int Id { get; set; }
    public string Username { get; set; }
    public decimal Balance { get; set; }
    public DateTime LastLoginTime { get; set; }
}
```

Source: [AuditTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/AuditTableAttribute.cs#L74-L143)

監査テーブル名をカスタマイズする場合は `AuditTableName` に具体的なテーブル名を設定します。監査を無効にする場合は `Enabled` を `false` に設定します。

### 2. ソフトデリートを有効化する

コンストラクタには少なくとも「ソフトデリートフラグフィールド」を渡し、必要に応じて「削除時刻フィールド」と「削除ユーザーフィールド」を渡します。デフォルトでは `AutoFilter = true` で、クエリ時に削除済みレコードが自動的に除外されます。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[SoftDelete("IsDeleted", "DeletedTime", "DeletedBy")]
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }
    public string? DeletedBy { get; set; }
}
```

Source: [SoftDeleteAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SoftDeleteAttribute.cs#L74-L175)

フラグフィールドが `bool` でない場合は、プロパティで `DeletedValue` と `NotDeletedValue` をカスタマイズできます。例えば、文字列 `"DELETED"` / `"ACTIVE"` で状態を識別する場合などです。

### 3. クエリキャッシュを有効化する

`[CacheTable]` をエンティティクラスに付与すると、ORM フレームワークは `CacheType` + `ExpireMinutes` に基づいて対応するキャッシュ戦略を有効化します。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

[CacheTable(CacheType = "Redis", ExpireMinutes = 30, KeyPrefix = "ProductInfo:")]
public class ProductInfo
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public DateTime LastModified { get; set; }
}
```

Source: [CacheTableAttribute.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/CacheTableAttribute.cs#L74-L137)

### 4. 組み合わせ使用：監査 + ソフトデリート + 監査可能フィールド

エンティティに同時に `IAuditableEntity` を実装させると、書き込み時に ORM が自動的に `CreateTime`、`UpdateTime`、`CreateUserId/Name`、`UpdateUserId/Name` フィールドを保守し、`[AuditTable]` と組み合わせて完全な監査のクローズドループを形成します。

```csharp
using GameFrameX.Foundation.Orm.Attribute;
using GameFrameX.Foundation.Orm.Entity;

[AuditTable(AuditLevel = AuditLevel.ChangesOnly)]
[SoftDelete("IsDeleted", "DeletedTime")]
[CacheTable(CacheType = "Memory", ExpireMinutes = 10)]
public class OrderInfo : IAuditableEntity
{
    public int Id { get; set; }
    public string OrderNo { get; set; }
    public decimal Amount { get; set; }

    public bool IsDeleted { get; set; }
    public DateTime? DeletedTime { get; set; }

    public DateTime? CreateTime { get; set; }
    public DateTime? UpdateTime { get; set; }
    public long? CreateUserId { get; set; }
    public string? CreateUserName { get; set; }
    public long? UpdateUserId { get; set; }
    public string? UpdateUserName { get; set; }
}
```

## よくあるバリエーション

- **フィールドのみ監査し、ユーザーは記録しない**：`IncludeUserInfo` を `false` に設定し、人まで追跡する必要がないシナリオでの冗長なフィールド保存を回避します。
- **クエリの自動フィルターを無効化する**：ソフトデリートシナリオで全データ（削除済みを含む）を確認する必要がある場合は、`AutoFilter` を `false` に設定し、呼び出し側が自行 `WHERE` を追加します。
- **文字列状態フィールドでソフトデリートを行う**：`DeletedValue` / `NotDeletedValue` を `"DELETED"` / `"ACTIVE"` に変更し、状態機械型のフィールドに適応させます。
- **複数のキャッシュバックエンドの共存**：エンティティごとに異なる `CacheType` を選択します（例：ホットデータは `Memory`、プロセス間共有は `Redis`）。`KeyPrefix` でキーの衝突を防ぎます。
- **ランタイムでの一時的な無効化**：単体テストや移行スクリプトでは、対応する属性の `Enabled` を `false` に設定することで、現在のエンティティの監査/キャッシュを無効化できます。

## よくあるエラー

- **`DeletedField` コンストラクタパラメータの書き忘れ**：3 つの `SoftDeleteAttribute` コンストラクタはすべて `deletedField` を必須パラメータとしてマークしているため、`null` を渡すと即座に `ArgumentNullException` が発生します。必ず有効なカラム名を渡してください。
- **フラグフィールドの型と `DeletedValue` の不一致**：デフォルトは `DeletedValue = true`、`NotDeletedValue = false` ですが、フラグフィールドが `string` や `int` の場合は、文字列/整数値を明示的に指定する必要があります。さもないと ORM が生成する SQL で型変換エラーが発生します。
- **複数の属性の同一クラスへの重複付与**：3 つの属性はすべて `AllowMultiple = false` が設定されているため、同じエンティティに重複して付与するとコンパイルエラーが発生します。異なる動作が必要な場合は属性パラメータで区別してください。
- **キャッシュキーの衝突**：`KeyPrefix` を設定しない場合、複数のエンティティがデフォルトプレフィックスを共有することでキーが衝突し、キャッシュヒット率が低下します。エンティティ名に基づく `"{EntityName}:"` プレフィックスの設定を推奨します。
- **監査をバックアップと混同する**：監査は変更履歴のみを記録し、削除前の完全なスナップショットは保存しません。「任意の時点のデータを復元する」機能が必要な場合は、ソフトデリートやカスタムスナップショット機構と併用してください。

## 背景（任意）

3 つの属性はすべて `AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = true)` でアノテーションされています。これは、クラスにのみ付与可能、クラスごとに 1 つだけ付与可能、派生クラスに継承される、ということを意味します。ORM はエンティティ登録段階でリフレクションによってこれらの属性を読み取り、監査インターセプタを生成するか、`WHERE` にソフトデリート条件を追加するか、キャッシュチャネルを使用するかを決定します。`IAuditableEntity` インターフェースのフィールドは、ORM が監査に必要なコンテキスト情報を自動的に書き込むために使用されます。
