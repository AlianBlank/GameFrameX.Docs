# 如何載入並使用設定表(設定中心)

本頁說明如何在 GameFrameX.Unity 中載入並使用由 LuBan 工具產生、託管在 `Hotfix.Config` 組件下的設定表資料。設定表以 `TbXxxConfig` 形式提供，透過 `TablesComponent` 元件統一初始化後，即可按 `Id` 或字串鍵查詢項目。

## 前置條件

- 已透過 LuBan 編輯器擴充功能產生設定表程式碼(預設輸出目錄 `Assets/Hotfix/Config/Generate/`)。
- 專案中已引入 `GameFrameX.Config.Runtime` 與 `SimpleJSON` 執行階段相依性。
- 業務端約定設定表的資源載入方式(本機 StreamingAssets / 遠端 CDN),並提供 `Func<Task<JSONNode>>` 給 `TbXxxConfig` 建構函式。

## 操作步驟

1. 確認設定表的實體類別與表類別已產生。每張表對應兩個檔案：實體類別 `XxxConfig`(欄位 + 建構 + `Deserialize`)與表類別 `TbXxxConfig`(繼承 `BaseDataTable<XxxConfig>`)。

   範例:`AchievementConfig` 實體類別定義在 [AchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L16-L50),表容器在 [TbAchievementConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L60)。`TbAchievementConfig` 繼承 `BaseDataTable<Tables.AchievementConfig>`,並透過建構函式注入 `_loadFunc`。

   ```csharp
   // Source: Assets/Hotfix/Config/Generate/Tables/TbAchievementConfig.cs#L17-L38
   public partial class TbAchievementConfig : BaseDataTable<Tables.AchievementConfig>
   {
       private readonly System.Func<System.Threading.Tasks.Task<JSONNode>> _loadFunc;
       public TbAchievementConfig(System.Func<System.Threading.Tasks.Task<JSONNode>> loadFunc)
       {
           _loadFunc = loadFunc;
       }
       public override async System.Threading.Tasks.Task LoadAsync()
       {
           var jsonNode = await _loadFunc();
           StringDataMaps.Clear();
           DataList.Clear();
           foreach(var _ele in jsonNode.Children)
           {
               Tables.AchievementConfig _v;
               { if(!_ele.IsObject) { throw new SerializationException(); }
                 _v = Tables.AchievementConfig.DeserializeAchievementConfig(_ele); }
               DataList.Add(_v);
               LongDataMaps.Add(_v.Id, _v);
               StringDataMaps.Add(_v.Id.ToString(), _v);
           }
           PostInit();
       }
   }
   ```

2. 為每張表提供 `loadFunc`,內部從本機/遠端資源讀取 JSON,反序列化為 `JSONNode`。

   ```csharp
   // loadFunc 範例:從 StreamingAssets 非同步讀取並解析 JSON
   Func<Task<JSONNode>> loadAchievement = async () =>
   {
       var text = await File.ReadAllTextAsync(
           Path.Combine(Application.streamingAssetsPath, "AchievementConfig.json"));
       return JSON.Parse(text);
   };

   var tbAchievement = new TbAchievementConfig(loadAchievement);
   await tbAchievement.LoadAsync();
   ```

3. 把所有 `TbXxxConfig` 註冊到 `TablesComponent`,由其統一管理載入、跨表參考解析(`ResolveRef`)與多語系鍵翻譯(`TranslateText`)。

   ```csharp
   // 把表實例加入 TablesComponent 並執行初始化
   var tables = new TablesComponent();
   tables.Add(tbAchievement);   // 其他 TbXxxConfig 同理
   await tables.InitAsync();    // 內部按相依順序呼叫各表 LoadAsync + ResolveRef
   ```

4. 在業務程式碼中按 `Id` 或鍵查詢資料。`BaseDataTable<T>` 提供 `LongDataMaps`、`StringDataMaps` 與 `DataList` 三個集合，直接透過鍵讀取即可。

   ```csharp
   // 實體類別暴露的欄位範例(唯讀屬性)
   // Source: Assets/Hotfix/Config/Generate/Tables/AchievementConfig.cs#L51-L80
   var row = tables.Achievement.Get(1001);   // LongDataMaps["1001"]
   var nameKey = row.Name;                   // 多語系 Key
   var conditions = row.AchievementUnlockCondition;  // List<int>
   ```

5. 處理跨表參考與多語系：在所有表 `LoadAsync` 完成後，呼叫 `ResolveRef(tables)` 讓項目解析其他表的參考；再呼叫 `TranslateText(translator)` 完成 `xxx_Localization_Key` 的本地化。

   ```csharp
   // Source: TbAchievementConfig.cs#L40-L54
   tbAchievement.ResolveRef(tables);
   tbAchievement.TranslateText((key, defaultText) => Localization.Get(key) ?? defaultText);
   ```

## 常見變體

- **本機資源 vs 遠端資源**:`loadFunc` 內可分別實作 `Application.streamingAssetsPath` 讀取或 `UnityWebRequest.Get` 下載，只要最終回傳 `JSONNode` 即可。
- **多語系鍵**:`AchievementConfig` 在建構時會把多語系欄位複製到 `Name_Localization_Key`、`AchievementContent_Localization_Key`、`LockText_Localization_Key`,再透過 `TranslateText` 回呼替換。
- **擴充類型對應**：列舉與外部類型可在 [ExternalTypeUtil.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Extension/ExternalTypeUtil.cs) 中登記，供 LuBan 反序列化時參考。

## 常見錯誤

- **JSON 欄位類型不符**:`Deserialize` 會在類型不符時擲回 `SerializationException`(`AchievementConfig.cs` 第 31-36 行的斷言)。檢查 Excel/JSON 匯出腳本與實體類別欄位類型是否一致。
- **忘記呼叫 `ResolveRef`**:跨表參考欄位會保持預設/空值，務必在所有表 `LoadAsync` 完成後再呼叫。
- **重複 `LoadAsync`**:未先 `Clear()` 會導致 `LongDataMaps`/`StringDataMaps` 出現重複鍵，產生的程式碼已在開頭呼叫 `Clear()`,但手動重複使用 `loadFunc` 時仍需注意。
- **直接修改產生的檔案**:`XxxConfig.cs` 與 `TbXxxConfig.cs` 頂部都有 `<auto-generated>` 標記，修改會在下次產生時被覆寫，自訂邏輯應放到 `partial` 的另一部分檔案中。

## 背景(選用)

LuBan 是與 GameFrameX 配套的 Excel→JSON→C# 程式碼產生工具：Excel 定義表結構，工具產出 JSON 資料檔案與上面這種 `BeanBase` / `BaseDataTable<T>` 形式的實體+容器程式碼。`TablesComponent` 扮演設定中心的角色，在啟動階段統一載入、解析參考，並視需要觸發本地化，讓業務端僅面向強型別物件進行程式設計。
