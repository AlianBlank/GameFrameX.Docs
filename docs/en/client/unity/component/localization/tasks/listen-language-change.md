# How to Listen for Language Change Events and Refresh UI Text

When you assign a new language to `LocalizationComponent.Language`, the component broadcasts three language change events in sequence; subscribe to one of them in your UI script (recommended: `LocalizationLanguageChangeAfterEventArgs`) to obtain the new and old languages in the callback and refresh the UI text.

## Prerequisites

- The project has GameFrameX's Localization and Event components enabled.
- A `LocalizationComponent` exists in the scene: when switching languages, it persists the language setting via its dependent `SettingComponent` and dispatches events through the `EventComponent`.

## Steps

All three events carry the same data (`Language` for the new language, `OldLanguage` for the old language); subscribe to whichever one you need:

| Event Args Class | Dispatch Order | Use Case |
|------|------|------|
| `LocalizationLanguageChangeBeforeEventArgs` | 1 | First notification in the switch flow; suitable for logging/preparation before the switch |
| `LocalizationLanguageChangeEventArgs` | 2 | Generic language change event |
| `LocalizationLanguageChangeAfterEventArgs` | 3 | Switch completion notification; recommended place to refresh UI text |

The three events are dispatched synchronously and consecutively in the `Language` setter:

```csharp
set
{
    if (m_LocalizationManager.Language != value)
    {
        var oldLanguage = m_LocalizationManager.Language;
        m_LocalizationManager.Language = value;
        m_SettingComponent.SetString(nameof(LocalizationComponent) + "." + nameof(Language), value);
        m_SettingComponent.Save();
        var localizationLanguageChangeBeforeEventArgs = LocalizationLanguageChangeBeforeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeBeforeEventArgs);
        var localizationLanguageChangeEventArgs = LocalizationLanguageChangeEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeEventArgs);
        var localizationLanguageChangeAfterEventArgs = LocalizationLanguageChangeAfterEventArgs.Create(oldLanguage, value);
        m_EventComponent.Fire(this, localizationLanguageChangeAfterEventArgs);
    }
}
```

### 1. Write the Event Handler Method

Use the corresponding event args class directly as the callback parameter, and read the new and old languages from it:

```csharp
private void OnLanguageChanged(object sender, LocalizationLanguageChangeAfterEventArgs e)
{
    Debug.Log($"Language switched from {e.OldLanguage} to {e.Language}");
    // Re-fetch the localized text based on e.Language here and refresh all text controls on this UI
}
```

The `Language` / `OldLanguage` definitions and `EventId` of the event args class are shown below; `EventId` is the type's fully qualified name:

```csharp
[Preserve] public static readonly string EventId = typeof(LocalizationLanguageChangeAfterEventArgs).FullName;

[Preserve]
public string Language { get; private set; }   // Current (new) language

[Preserve]
public string OldLanguage { get; private set; } // Old language
```

### 2. Register and Unregister the Listener

Events are dispatched via GameFrameX's Event component (`m_EventComponent.Fire(...)`). Register the listener using the `EventId` constant and unsubscribe when the UI is destroyed/disabled. A typical implementation:

```csharp
private void OnEnable()
{
    GameEntry.Event.AddListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}

private void OnDisable()
{
    GameEntry.Event.RemoveListener(LocalizationLanguageChangeAfterEventArgs.EventId, OnLanguageChanged);
}
```

> Note: The exact signatures of `AddListener` / `RemoveListener` are subject to the com.gameframex.unity.event package; the localization component in this repository is only responsible for dispatching events using `EventId` (the type's fully qualified name, i.e., `GameFrameX.Localization.Runtime.LocalizationLanguageChangeAfterEventArgs`).

### 3. Switch Language to Trigger the Event

Assign `Language` a language value different from the current one to trigger all three events:

```csharp
GameEntry.GetComponent<LocalizationComponent>().Language = "ChineseSimplified";
```

At the same time as the assignment, the language is automatically written to the settings (key name `LocalizationComponent.Language`) and saved, so it can be read back on the next launch.

### 4. Refresh Text in the Callback

In the callback from step 1, reload the localized text for the corresponding language based on `e.Language` (or the component's current `Language`) and update each text control; you can also refresh only the language-related controls without rebuilding the UI.

## Verification

- After switching languages, the log in the step 1 callback should print the old and new languages;
- Setting the language to the same value as the current one will **not** trigger the callback (the setter has a `!=` check; see line 157 in the Source above).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Callback not executed after switching language | The ID used when registering the listener doesn't match the event's actual ID | Consistently use the constant provided by the event class, `LocalizationLanguageChangeAfterEventArgs.EventId`; do not hand-write the string |
| The language read in the callback is `UnknownLocalization` | Reference pool reuse of event args not handled correctly | Use `e.Language` / `e.OldLanguage` immediately within the callback; do not cache the event args object itself |
| Duplicate events received after switching languages repeatedly | Unsubscribing at the wrong time or duplicate registration | Register in `OnEnable` and unregister in `OnDisable`, ensuring they are always paired |
| Wanting to refresh text after setting the same language but nothing happens | The setter short-circuits on the same value and does not dispatch events | When a forced refresh is needed, trigger the refresh logic yourself at the call site, or first set a value other than the target language and then switch back |

## Background

All three event args classes inherit from `GameEventArgs`, and instances are acquired via `ReferencePool.Acquire<T>()` (reference pool reuse), so do not hold event args objects long-term. Language changes are driven uniformly by the setter of `LocalizationComponent.Language`: it first updates the manager's language and persists the setting, then synchronously dispatches the three events in the order "Before → Change → After". Listeners don't need to distinguish timing differences—simply pick whichever one suits.
