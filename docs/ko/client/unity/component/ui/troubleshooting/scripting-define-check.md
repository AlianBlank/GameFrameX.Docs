# 에디터 스크립트 매크로 검사 실패 시 대처 방법

Unity 에디터가 시작되거나 스크립트 재컴파일 후 "UI 시스템의 매크로 정의가 감지되지 않았습니다" 대화 상자가 표시되거나, 콘솔에 `UISystemScriptingDefineCheckHandler` 검사가 통과되지 않았다는 오류가 출력되면, 현재 `EditorUserBuildSettings.selectedBuildTargetGroup`에 `ENABLE_UI_UGUI`와 `ENABLE_UI_FAIRYGUI` 두 매크로가 모두 존재하지 않는다는 의미입니다. UI 시스템이 어느 어댑팅 분기로 진행할지 판단할 수 없으므로 즉시 추가해야 합니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| "UI 시스템의 매크로 정의가 감지되지 않았습니다" 팝업 표시 | UGUI와 FairyGUI 두 매크로 모두 활성화되지 않음 | 아래의 "FairyGUI 시스템 매크로 활성화" 또는 "UGUI 시스템 매크로로 전환" 참조 |
| `HasScriptingDefineSymbol`이 `false`를 반환하지만 매크로는 이미 수동으로 추가됨 | 검사 대상은 `selectedBuildTargetGroup`인데 매크로가 다른 플랫폼에만 추가됨 | 해당 Build Target으로 전환한 후 다시 추가 |
| 두 매크로가 동시에 존재함 | 이전에 UI 시스템을 전환할 때 상호 배제 처리가 되지 않음 | 아래의 "두 매크로가 동시에 존재할 경우" 참조 |
| 매크로를 추가했는데도 누락 알림이 표시됨 | Unity 재컴파일을 기다리지 않았거나, 메뉴 메서드가 쓰기를 트리거하지 않음 | 메뉴 항목으로 쓰기를 트리거한 후 컴파일이 완료될 때까지 기다린 뒤 에디터 닫기 |

`UISystemScriptingDefineCheckHandler`의 판정 로직:

```csharp
// Editor/UISystemScriptingDefineCheckHandler.cs#L18-L27
var hasUGUIScriptingDefineSymbol = ScriptingDefineSymbols.HasScriptingDefineSymbol(
    EditorUserBuildSettings.selectedBuildTargetGroup,
    UISystemScriptingDefineSymbols.UGUIScriptingDefineSymbol);

var hasFairyGUIScriptingDefineSymbol = ScriptingDefineSymbols.HasScriptingDefineSymbol(
    EditorUserBuildSettings.selectedBuildTargetGroup,
    UISystemScriptingDefineSymbols.FairyGUIScriptingDefineSymbol);

if (!(hasFairyGUIScriptingDefineSymbol || hasUGUIScriptingDefineSymbol))
{

        "将自动启用 FairyGUI 的 UI 系统,可以在菜单 GameFrameX/Scripting Define Symbols 中切换", "我知道了");
    UISystemScriptingDefineSymbols.EnableFairyGUISystem();
}
```

## 해결 단계

### FairyGUI 시스템 매크로 활성화

에디터 시작 시 두 매크로가 모두 활성화되지 않은 것으로 감지되면 기본적으로 FairyGUI가 자동으로 활성화됩니다. 수동으로 비활성화한 적이 있다면 수동으로 다시 활성화할 수 있습니다:

1. Unity 메뉴 바에서 `GameFrameX/Scripting Define Symbols/Enable FairyGUI(开启 FairyGUI 适配)`를 선택합니다.
2. Unity의 재컴파일이 완료될 때까지 기다리면, 에디터를 다시 시작할 때 더 이상 팝업이 표시되지 않아야 합니다.

해당 소스 코드는 UGUI 매크로를 제거하고 FairyGUI 매크로를 추가하는 상호 배제 방식으로 동작합니다:

```csharp
// Editor/UISystemScriptingDefineSymbols.cs#L58-L63
[MenuItem("GameFrameX/Scripting Define Symbols/Enable FairyGUI(开启FairyGUI适配)", false, 1001)]
public static void EnableFairyGUISystem()
{
    ScriptingDefineSymbols.RemoveScriptingDefineSymbol(UGUIScriptingDefineSymbol);
    ScriptingDefineSymbols.AddScriptingDefineSymbol(FairyGUIScriptingDefineSymbol);
}
```

### UGUI 시스템 매크로로 전환

프로젝트가 실제로 UGUI를 사용하는 것이 확인되면:

1. 메뉴에서 `GameFrameX/Scripting Define Symbols/Enable UGUI(开启 UGUI 适配)`를 선택합니다.
2. 컴파일이 완료될 때까지 기다린 후, `ENABLE_UI_UGUI`가 `Project Settings/Player/Other Settings/Scripting Define Symbols`에 추가되었는지 확인합니다.

```csharp
// Editor/UISystemScriptingDefineSymbols.cs#L48-L53
[MenuItem("GameFrameX/Scripting Define Symbols/Enable UGUI(开启UGUI适配)", false, 1000)]
public static void EnableUGUISystem()
{
    ScriptingDefineSymbols.RemoveScriptingDefineSymbol(FairyGUIScriptingDefineSymbol);
    ScriptingDefineSymbols.AddScriptingDefineSymbol(UGUIScriptingDefineSymbol);
}
```

### 두 매크로가 동시에 존재할 경우

Scripting Define Symbols를 수동으로 편집하면 두 매크로가 남아 있기 쉽습니다. 프로젝트에서 실제로 사용하는 UI 시스템에 따라 해당 메뉴 항목을 한 번 더 클릭하면 상호 배제 방식으로 정리할 수 있습니다(위의 두 메서드는 내부적으로 먼저 다른 매크로를 `Remove`한 후 현재 매크로를 `Add`합니다).

### 검사 대상은 현재 Build Target

`UISystemScriptingDefineCheckHandler`가 검사하는 대상은 `EditorUserBuildSettings.selectedBuildTargetGroup`입니다. `File/Build Settings`에서 대상 플랫폼을 전환한 경우(예: Standalone에서 Android로 전환), 매크로가 이전 플랫폼에만 존재할 수 있습니다. 처리 방법:

1. 대상 Build Settings 플랫폼으로 전환합니다.
2. 해당 메뉴 항목(`Enable UGUI` 또는 `Enable FairyGUI`)을 다시 한 번 실행하여 매크로를 현재 Build Target에 기록합니다.

## 확인

- 검사를 다시 트리거: Project 뷰에서 아무 리소스나 마우스 오른쪽 버튼으로 클릭해 `Reimport`하거나 에디터를 재시작해도 더 이상 "UI 시스템의 매크로 정의가 감지되지 않았습니다" 팝업이 표시되지 않아야 합니다.
- 메뉴 `Edit/Project Settings/Player`에서 `Other Settings/Scripting Define Symbols`를 펼쳐 `ENABLE_UI_UGUI` 또는 `ENABLE_UI_FAIRYGUI`가 있는지 확인합니다.
- 코드 측에서 `#if ENABLE_UI_UGUI` 또는 `#if ENABLE_UI_FAIRYGUI`로 감싼 분기에 올바르게 진입하는지 확인합니다.
