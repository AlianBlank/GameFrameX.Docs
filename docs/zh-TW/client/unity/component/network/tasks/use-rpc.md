# 使用 RPC 呼叫與逾時處理

依照本頁的步驟，您可以透過 RPC 傳送請求訊息並 `await` 伺服器回應；若在設定的逾時時間內（預設 5000 毫秒）未收到回覆，該工作將以 `TimeoutException` 結束，您也可以掛鉤全域的開始/逾時/錯誤碼事件以進行統一處理。

## 前置條件

- 場景中已掛載 `NetworkComponent`，且已透過 `CreateNetworkChannel` 建立網路通道（逾時時間是在建立通道時傳入）。
- 請求訊息實作 `IRequestMessage`，回應訊息實作 `IResponseMessage`，且回應訊息的 `UniqueId` 與對應的請求相符 — RPC 回覆配對是依 `UniqueId` 查詢等待表。

## 步驟

1. **設定 RPC 逾時時間**。在 Inspector 的 NetworkComponent 面板上調整 `RPC Timeout Time In Milliseconds`（滑桿範圍 3000–50000，僅在非播放模式下可編輯），或直接修改序列化欄位，預設值為 5000：

```csharp
/// <summary>
/// RPC 逾時時間（毫秒），預設為 5 秒
/// </summary>
[SerializeField] private int m_rpcTimeout = 5000;
```

來源：[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L60-L63)

建立通道時，此值會傳遞給 RPC 狀態：

```csharp
var networkChannel = m_NetworkManager.CreateNetworkChannel(channelName, networkChannelHelper, m_rpcTimeout);
```

來源：[NetworkComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/NetworkComponent.cs#L179)

2. **定義請求/回應訊息配對**。請求實作 `IRequestMessage`，回應則對應實作 `IResponseMessage`。

3. **發起 RPC 呼叫並等待結果**。呼叫 `RpcState.Call` 取得 `Task<IResponseMessage>`；只要對其 `await`，當回應抵達時便會繼續執行：

```csharp
public Task<IResponseMessage> Call(MessageObject messageObject, bool isIgnoreErrorCode)
{
    if (_waitingReplyHandlingObjects.TryGetValue(messageObject.UniqueId, out var messageActorObject))
    {
        return messageActorObject.Task;
    }

    var defaultMessageActorObject = RpcMessageData.Create(messageObject as IRequestMessage, _rpcTimeout, isIgnoreErrorCode);
    if (!_waitingReplyHandlingObjects.TryAdd(messageObject.UniqueId, defaultMessageActorObject))
    {
        return defaultMessageActorObject.Task;
    }
    try
    {
        _rpcStartHandler?.Invoke(this, messageObject);
    }
    catch (Exception e)
    {
        Log.Fatal(e);
    }

    return defaultMessageActorObject.Task;
}
```

來源：[NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L140-L162)

以相同 `UniqueId` 重複呼叫時，會直接回傳既有的等待工作，不會再次傳送。

4. **處理逾時例外**。逾時偵測是在每個影格的 `Update` 中累加實際經過時間（毫秒）來進行；一旦到達期限，便會在該工作上設定下列例外，並將其從等待表中移除：

```csharp
internal bool IncrementalElapseTime(long time)
{
    ElapseTime += time;
    if (ElapseTime >= Timeout)
    {
        m_Tcs.TrySetException(new TimeoutException($"Rpc call timeout! Message FullName:{RequestMessage.GetType().FullName} is :{RequestMessage}"));
        return true;
    }

    return false;
}
```

來源：[NetworkManager.RpcState.RpcMessageData.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.RpcMessageData.cs#L64-L74)

在呼叫端攔截的範例（基於上一步回傳的 Task）：

```csharp
try
{
    var response = await rpcTask; // rpcTask 是 Call 所回傳的 Task<IResponseMessage>
}
catch (TimeoutException)
{
    // 在 m_rpcTimeout 時間內未收到回應；可以提示使用者或重試
}
```

5. **（選用）掛鉤全域 RPC 事件**。適用於在 UI 顯示「請求中」指示器、顯示統一的逾時提示等情境：

```csharp
[UnityEngine.Scripting.Preserve]
public void SetRPCErrorHandler(EventHandler<MessageObject> handler)
{
    GameFrameworkGuard.NotNull(handler, nameof(handler));
    _rpcErrorHandler = handler;
}
```

來源：[NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L219-L228)

## 常見變化用法

- **忽略錯誤碼**：將 `true` 作為 `Call` 的第二個參數傳入（`isIgnoreErrorCode`）；當回應的 `ErrorCode != 0` 時，不再觸發全域錯誤碼事件，改由業務邏輯自行處理回應內容。判斷邏輯請參見 `TryReply`：

```csharp
if (responseMessage?.ErrorCode != 0 && !messageActorObject.IsIgnoreErrorCode)
{
    _rpcErrorCodeHandler?.Invoke(this, message);
}
```

來源：[NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L115-L118)

- **三個全域事件**：`SetRPCStartHandler`（發起呼叫）、`SetRPCErrorHandler`（逾時）、`SetRPCErrorCodeHandler`（業務錯誤碼）。三者皆要求傳入非 null 的處理常式；否則 `GameFrameworkGuard.NotNull` 會擲回引數例外。
- **重新連線情境**：斷線/重連成功後，呼叫 `RpcState.Reset()`，它會 Dispose 所有待處理工作（對應的 Task 會以取消狀態結束）並清空等待表：

```csharp
public void Reset()
{
    foreach (var kvp in _waitingReplyHandlingObjects)
    {
        kvp.Value.Dispose();
    }

    _waitingReplyHandlingObjects.Clear();
    _disposed = false;
}
```

來源：[NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L86-L95)

## 常見錯誤

| 症狀/錯誤訊息 | 原因 | 修正方式 |
|------|------|------|
| 建構時擲回 `ArgumentOutOfRangeException`：`RPC超时时间不能小于3000毫秒` | `m_rpcTimeout` 被修改為低於 3000 | 將逾時時間調整至 3000–50000 的範圍內 |
| `await` 擲回 `TimeoutException`：`Rpc call timeout! Message FullName:...` | 逾時時間內未收到相符的回應 | 檢查伺服器是否有傳回回應，以及回應的 `UniqueId` 是否與請求相符；必要時調高 `m_rpcTimeout` |
| `await` 擲回 `TaskCanceledException` | `RpcState` 已被 `Dispose()`/`Reset()`，待處理工作經 `TrySetCanceled` 取消 | 重新連線後再次發起呼叫 |
| 收到回應但 `TryReply` 回傳 false，Task 無限期懸置 | 回應未實作 `IResponseMessage`，或其 `UniqueId` 與請求不相符 | 讓回應訊息實作 `IResponseMessage` 並保持 `UniqueId` 一致 |
| 回應的 `ErrorCode != 0`，但全域錯誤碼事件未觸發 | 呼叫時將 `isIgnoreErrorCode` 傳為 `true` | 需要全域處理時請傳入 `false` |

逾時時間下限驗證位於 `RpcState` 建構函式中：

```csharp
public RpcState(int timeout)
{
    _rpcTimeout = timeout;
    if (_rpcTimeout < 3000)
    {
        throw new ArgumentOutOfRangeException(nameof(timeout), "RPC超时时间不能小于3000毫秒");
    }
}
```

來源：[NetworkManager.RpcState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.RpcState.cs#L58-L65)

## 背景

內部實作：`RpcState` 使用 `ConcurrentDictionary<long, RpcMessageData>`（`_waitingReplyHandlingObjects`）以 `UniqueId` 為索引鍵儲存待處理的呼叫；每個呼叫由 `RpcMessageData.Create(IRequestMessage, int timeout = 5000, bool isIgnoreErrorCode = false)` 建立，內部持有一個 `TaskCompletionSource<IResponseMessage>`。每個影格，`Update` 會將 `realElapseSeconds` 轉換為毫秒並累加至 `ElapseTime`；逾時的呼叫會先觸發 `_rpcErrorHandler`，再以批次方式移除；整個流程使用預先配置的 `_timeoutIds` 清單，以避免每個影格產生 GC。
