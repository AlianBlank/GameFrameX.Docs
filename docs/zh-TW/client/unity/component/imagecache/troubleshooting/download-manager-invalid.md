# Download manager is invalid 錯誤的解決方法

在非 WebGL 平台上啟動 ImageCache 元件時，若日誌中輸出 `Log.Fatal("Download manager is invalid.")`，表示 `GameFrameworkEntry.GetModule<IDownloadManager>()` 回傳了 null，導致 `ImageCacheComponent` 無法將 Download Manager 注入至 `ImageCacheManager`。

## 快速診斷

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 啟動場景中發生 `Download manager is invalid.`，且所有圖片載入皆失效 | `IDownloadManager` 模組未註冊 | 在啟動流程中加入 Download 元件，使 `GameFrameworkEntry.GetModule<IDownloadManager>()` 可用 |
| 在 WebGL 平台上不會發生此錯誤，但在其他平台上會發生 | 僅在非 WebGL 分支中驗證 Download Manager | 確認建置目標為非 WebGL，且已附加 Download 元件 |
| `LoadImageAsync` 回傳 null，且主控台中沒有出現其他錯誤 | Download Manager 存在，但在 `Awake` 之後才註冊 | 調整模組初始化順序，確保 Download 元件在 ImageCache 元件的 Awake 之前先完成初始化 |

## 修正步驟

### 1. 附加 Download 元件

此錯誤源自 [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55-L64) 中 `Awake` 的驗證：

```csharp
#if !UNITY_WEBGL
            var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
            if (downloadManager == null)
            {
                Log.Fatal("Download manager is invalid.");
                return;
            }

            ((ImageCacheManager)_imageCacheManager).SetDownloadManager(downloadManager);
#endif
```

若 `IDownloadManager` 未註冊，此處會立即輸出 `Log.Fatal` 並執行 `return`，因此後續的 `SetDownloadManager` 不會被執行，所有 `LoadImageAsync` 的呼叫都會失敗。

操作步驟：

1. 開啟啟動場景（通常為 `Bootstrap` / `Launch` 場景）。
2. 在相同的 `GameFramework` 進入點物件（或其子物件）上加入 Download 元件（由 `GameFrameX.Download` 套件提供）。
3. 執行場景，確認主控台不再輸出 `Download manager is invalid.`。

### 2. 確保模組註冊順序

`ImageCacheComponent.Awake` 會主動從 `GameFrameworkEntry` 取得模組：

```csharp
_imageCacheManager = GameFrameworkEntry.GetModule<IImageCacheManager>();
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
```

若 Download 元件在 ImageCache 元件之後才被 Awake，由於模組清單中尚不存在 `IDownloadManager`，後者的驗證將會失敗。

操作步驟：

1. 在 Inspector 中調整元件順序，讓 Download 元件排在 ImageCache 元件之前（Unity 會依元件加入的順序執行 `Awake`）。
2. 或者，也可以透過程式碼控制初始化：在 `Start` / 自訂的初始化階段先將 Download 模組實例化，之後再啟用 ImageCache。

### 3. 確認建置平台

錯誤區塊被 `#if !UNITY_WEBGL` 包圍（[ImageCacheComponent.cs#L55](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55)），由於 WebGL 平台不會處理 Download Manager 分支，因此在 WebGL 上不會顯示此錯誤。若在 WebGL 上看到相同的字串，請確認是否為巨集撰寫錯誤，或誤引入了非 WebGL 用的資源。

## 驗證

- 啟動場景執行後，主控台不應顯示 `Download manager is invalid.`。
- 呼叫 `ImageCacheComponent.LoadImageAsync(url)`，圖片應正常回傳 `Texture2D`（或命中快取）。
- 透過中斷點檢查 ImageCache 元件的參照，可確認 `ImageCacheManager._downloadManager` 不為 null（請參閱 [ImageCacheManager.cs#L56-L61](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L56-L61)）。
