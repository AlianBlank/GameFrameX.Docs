# Quick Start: Your First State Machine

Following the steps on this page, you'll get GameFrameX FSM's minimal loop running within 5 minutes: define states → create FSM → start a state → switch between states and read/write data.

## Prerequisites

- Unity 2019.4 or later
- Install `com.gameframex.unity.fsm` 1.1.1 via `Packages/manifest.json` (or use the Git URL to connect to the repository directly)

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.fsm": "1.1.1"
  }
}
```

After installation, `FsmComponent` will be automatically attached to the `GameFramework` startup object as `[GameFrameXAutoComponent(-6000)]`.

## Steps

### 1. Define State Classes

Inherit from `FsmState<T>` (where `T` is the FSM owner type), and override the six lifecycle hooks as needed. Within a state, trigger transitions via `ChangeState<TNext>(fsm)`.

```csharp
using GameFrameX.Fsm;
using UnityEngine;

public class Player { /* Player business fields */ }

public class IdleState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        Debug.Log("Enter Idle");
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        if (Input.GetKeyDown(KeyCode.W))
        {
            ChangeState<MoveState>(fsm);
        }
    }

    protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
}

public class MoveState : FsmState<Player>
{
    protected override void OnEnter(IFsm<Player> fsm)
    {
        fsm.SetData("Speed", 5.0f);
    }

    protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds) { }
}
```

### 2. Create and Start the FSM

Create via `FsmComponent`, passing all initial state instances at construction time, and finally use `Start<TState>()` to select the entry state.

```csharp
using GameFrameX;
using GameFrameX.Fsm;
using GameFrameX.Fsm.Runtime;

var fsmComponent = GameEntry.GetComponent<FsmComponent>();
IFsm<Player> fsm = fsmComponent.CreateFsm(player, new IdleState(), new MoveState());
fsm.Start<IdleState>();
```

`CreateFsm` is handled by [FsmManager](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmManager.cs), which allocates `Fsm<T>` instances from the object pool and populates the states dictionary; `Start<T>` sets the current state and triggers `OnEnter`.

### 3. Switch Between States and Read/Write Data

The `IFsm<T> fsm` parameter within a state is responsible for triggering transitions as well as providing cross-state key-value data storage (values are uniformly boxed internally via `Variable`).

```csharp
// In any state's OnEnter / OnUpdate / OnLeave
fsm.SetData("Health", 100);
int hp = fsm.GetData<int>("Health");

if (fsm.HasData("Health"))
{
    fsm.RemoveData("Health");
}
```

To switch states, call `ChangeState<TNext>(fsm)`. The framework will automatically call the old state's `OnLeave(..., isShutdown: false)` first, then call the new state's `OnEnter`.

### 4. Destroy the FSM

When no longer needed, call `DestroyFsm`. The framework will trigger `OnDestroy` and return the instance to the `FsmManager` object pool.

```csharp
fsmComponent.DestroyFsm(fsm);
```

## Common Variants

| Scenario | Approach |
|------|------|
| Same owner type needs multiple coexisting FSMs | Use the `CreateFsm(owner, name, new IdleState(), ...)` overload with a name |
| Add a state at runtime | `fsm.AddState(new JumpState())` |
| Remove a non-current state at runtime | `fsm.RemoveState<IdleState>()` |
| Preserve the state set, clear data, and return to initial | `fsm.Reset()`, then restart with `Start<T>()` |
| Driven by physics frames | Override `OnFixedUpdate`; `FsmComponent.FixedUpdate` will dispatch automatically |
| Quick access entry (requires com.gameframex.unity.entry) | Use `GameApp.Fsm.CreateFsm(...)` instead of `GameEntry.GetComponent<FsmComponent>()` |

## Common Errors

- **`FsmComponent` not found**: The `GameFramework` startup prefab is not attached in the Unity scene, so the component was not auto-instantiated.
- **`Start<T>` throws an exception**: The passed state type was not registered when the FSM was created. You must add it to the `CreateFsm` parameter list or via `AddState` first.
- **Data can't be stored**: `SetData` boxes values internally via `Variable`. When reading value types, you must use the same generic parameter: `GetData<int>("Health")`.
- **State switch not taking effect**: `ChangeState<TNext>(fsm)` must be called within a state hook, and `TNext` must have already been registered.
- **An owner is `Start`ed again after its state machine is destroyed**: First confirm `IsDestroyed == false`; otherwise, you need to `CreateFsm` again.

## Background (Optional)

Internally, `Fsm<T>` uses a `Dictionary<Type, FsmState<T>>` to store states. `m_CurrentStateTime` accumulates in `Update` and can be read via `CurrentStateName` / `CurrentStateTime` in the debugger or a custom Inspector. All FSMs are managed centrally by `FsmManager` and exposed to the upper layer through `FsmComponent`.
