# GetData/SetData 数据读取异常速查

本页针对 `IFsm<T>` 上的 `GetData` / `SetData` 调用过程中常见的异常与异常返回情况,提供症状对照与定位步骤。状态机使用方式见《Fsm 快速开始》。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 抛出 `GameFrameworkException("Data name is invalid.")` | `name` 为 `null` 或空字符串 | 使用非空键名,推荐常量字符串 |
| `GetData` 始终返回 `null` | 从未调用 `SetData` 写入该键;或状态机已被 `Reset` / `Shutdown` 清空 | 在首次读取前显式 `SetData`,或从 `HasData` 入口判断 |
| `SetData` 后立即读,字段值仍为默认值 | 重复 `SetData` 时旧值被回收到 `ReferencePool`,新值未真正替换 | 先 `RemoveData` 再 `SetData`,或仅调用一次 `SetData` |
| 类型转换抛 `InvalidCastException` | `GetData<TData>` 的泛型参数与写入时的实际 `Variable` 子类型不匹配 | 读写两端使用相同的 `Variable` 子类型(如 `VarInt`、`VarString`) |
| 状态机销毁后调用 `GetData` 抛异常 | `m_IsDestroyed == true` 时 `Reset` 等内部流程会拒绝访问 | 销毁后停止一切访问,或重建一个新的 FSM |

## 修复步骤

### 1. 名称非法(`Data name is invalid`)

`GetData(string)` 与 `SetData(string, Variable)` 第一步都会校验名称:

```csharp
if (string.IsNullOrEmpty(name))
{
    throw new GameFrameworkException("Data name is invalid.");
}
```

Source: [Fsm.cs#L469-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L527)

**修复**:键名使用稳定的字符串常量,例如 `"Hp"`、`"Owner"`,不要传入拼接出来的空串。

### 2. 读取返回 `null`

`GetData` 在内部字典为空或键不存在时,直接返回 `null`,不会抛异常:

```csharp
if (m_Datas == null)
{
    return null;
}

Variable data = null;
if (m_Datas.TryGetValue(name, out data))
{
    return data;
}

return null;
```

Source: [Fsm.cs#L469-L488](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488)

**修复**:
1. 在状态 `OnEnter` 或状态机创建后立即 `SetData` 一次,完成初始化。
2. 读取前用 `HasData(name)` 判定是否存在;若 `false` 再做默认初始化。
3. 注意 `Reset()` 会清空所有数据(`m_Datas.Clear()`),`Shutdown` 后字典回到 `null`,需要重新初始化。

### 3. 重复 `SetData` 后旧值被回收

`SetData` 内部会先取出旧值,若非空则交还引用池:

```csharp
Variable oldData = GetData(name);
if (oldData != null)
{
    ReferencePool.Release(oldData);
}

m_Datas[name] = data;
```

Source: [Fsm.cs#L508-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L508-L527)

**修复**:
- `Variable` 子类型实例由框架内部从 `ReferencePool` 获取并管理生命周期,不要在外部 `new` 后再交给状态机。
- 若想替换键名,使用 `RemoveData(name)` 让旧值显式归还,然后再 `SetData` 新键。

### 4. 泛型类型不匹配

`GetData<TData>` 直接强转,要求 `TData : Variable` 且与写入时的子类型一致:

```csharp
public TData GetData<TData>(string name) where TData : Variable
{
    return (TData)GetData(name);
}
```

Source: [Fsm.cs#L458-L461](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

**修复**:在调用方显式使用 `VarInt`、`VarFloat`、`VarString`、`VarBool`、`VarObject` 等内置子类型,避免使用 `object` 或 `Variable` 基类作为 `TData`,否则强转会失败。

### 5. 销毁后访问

`Fsm.Shutdown` 后 `m_IsDestroyed = true`,再次访问会被 `Reset()` 等内部流程拒绝:

```csharp
if (m_IsDestroyed)
{
    throw new GameFrameworkException("FSM is destroyed, can not reset.");
}
```

Source: [Fsm.cs#L560-L565](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L560-L565)

**修复**:在销毁 FSM 前清空所有外部引用,不要在 `OnDestroy` 之后继续调用 `GetData`/`SetData`。

## 验证

执行以下步骤确认问题已解决:

1. 在状态 `OnEnter` 中打印 `HasData("Hp")` 与 `GetData<VarInt>("Hp").Value`,确认读取结果符合预期。
2. 用 `SetData("Hp", hpVar)` 后再 `GetData`,核对数值一致。
3. 调用 `Reset()` 后再读 `GetData`,应返回 `null` 且不抛异常(只要 `name` 非空)。
