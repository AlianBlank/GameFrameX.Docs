# TimerComponent and ITimerManager API Quick Reference

This page collects all public APIs exposed by the Timer module: the method signatures, default values, and return value conventions of `TimerComponent` (Unity component facade) and `ITimerManager` (manager interface), as well as the async/await extensions and the `TimerTimeScale` enum. All method signatures are excerpted from the source code and can be used for direct reference.

## How to Obtain

`TimerComponent` is a Unity component attached to the scene (menu path `GameFrameX/Timer`, attributes `[GameFrameXAutoComponent(-5000)]`, `[DisallowMultipleComponent]`). In `Awake` it obtains the manager via `GameFrameworkEntry.GetModule<ITimerManager>()` and forwards all calls to it; every public method on the component corresponds one-to-one with `ITimerManager`, so the tables below apply to both. The only difference is that the async wait methods are extension methods on the interface side and instance methods on the component side (see "async/await Waiting").

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Timer")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-5000)]
public class TimerComponent : GameFrameworkComponent
{
    ITimerManager _timerManager;

    protected override void Awake()
    {
        ImplementationComponentType = Utility.Assembly.GetType(componentType);
        InterfaceComponentType = typeof(ITimerManager);
        base.Awake();
        _timerManager = GameFrameworkEntry.GetModule<ITimerManager>();
        if (_timerManager == null)
        {
            Log.Fatal("Timer manager is invalid.");
            return;
        }
    }
```

## Adding Timers

| Method | Signature | Description |
|------|------|------|
| `Add` | `int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)` | Adds a timed task; `repeat` of 0 means unlimited repetition; `onComplete` fires when the timer completes/is removed; returns a unique ID |
| `AddOnce` | `int AddOnce(float interval, Action<object> callback, object callbackParam = null)` | A task that executes only once |
| `AddUpdate` | `int AddUpdate(Action<object> callback)` | A task executed every frame update |
| `AddUpdate` | `int AddUpdate(Action<object> callback, object callbackParam)` | A task executed every frame update (with callback parameter) |

`interval` is in seconds; `AddUpdate` is equivalent to `Add(0, 0, ...)` firing every frame. Full original signatures:

```csharp
int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null);
int AddOnce(float interval, Action<object> callback, object callbackParam = null);
int AddUpdate(Action<object> callback);
int AddUpdate(Action<object> callback, object callbackParam);
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L22-L46)

Common invocations look like: `timer.Add(0.5f, 3, OnTick, null, "Boss", TimerTimeScale.Scaled, OnDone)`, `timer.AddOnce(2f, _ => Debug.Log("done"))`, `timer.AddUpdate(param => Tick(param))`.

## async/await Waiting

On `TimerComponent` these are instance methods; on `ITimerManager` they are provided by `TimerAsyncExtensions` (extension methods). All waits complete on the Unity main thread, and continuations also return to the main thread; `WaitForFramesAsync(frameCount <= 0)` directly returns `Task.CompletedTask`.

| Method | Signature | Description |
|------|------|------|
| `WaitForSecondsAsync` | `Task WaitForSecondsAsync(float seconds, CancellationToken cancellationToken = default)` | Completes after waiting for the specified number of seconds (internally uses `AddOnce`) |
| `WaitForNextFrameAsync` | `Task WaitForNextFrameAsync(CancellationToken cancellationToken = default)` | Waits for the next frame (internally uses `AddOnce(0, ...)`) |
| `WaitForFramesAsync` | `Task WaitForFramesAsync(int frameCount, CancellationToken cancellationToken = default)` | Waits for the specified number of frames (internally uses `Add(0, frameCount, ...)`; frameCount must be > 0) |

The forwarding implementation on the component side:

```csharp
public Task WaitForSecondsAsync(float seconds, CancellationToken cancellationToken = default)
{
    return _timerManager.WaitForSecondsAsync(seconds, cancellationToken);
}

public Task WaitForNextFrameAsync(CancellationToken cancellationToken = default)
{
    return _timerManager.WaitForNextFrameAsync(cancellationToken);
}

public Task WaitForFramesAsync(int frameCount, CancellationToken cancellationToken = default)
{
    return _timerManager.WaitForFramesAsync(frameCount, cancellationToken);
}
```

## TimerTimeScale Enum

| Member | Value | Description |
|------|----|------|
| `Unscaled` | `0` | Not affected by `UnityEngine.Time.timeScale` (default, compatible with existing behavior) |
| `Scaled` | `1` | Affected by `UnityEngine.Time.timeScale` |

```csharp
public enum TimerTimeScale : byte
{
    /// <summary>Not affected by <see cref="UnityEngine.Time.timeScale"/> (default, compatible with existing behavior).</summary>
    Unscaled = 0,

    /// <summary>Affected by <see cref="UnityEngine.Time.timeScale"/>.</summary>
    Scaled = 1,
}
```

Source: [TimerTimeScale.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerTimeScale.cs#L6-L13)

The `timeScale` parameter of `Add` defaults to `TimerTimeScale.Unscaled`, so timers are not affected by game pauses (`timeScale = 0`) by default; for timing that should scale with game time (e.g., skill cooldowns), explicitly pass `TimerTimeScale.Scaled`.
