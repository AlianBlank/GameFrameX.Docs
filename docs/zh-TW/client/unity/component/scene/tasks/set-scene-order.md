# 如何設定場景優先順序並切換作用中場景

使用 `SceneComponent.SetSceneOrder` 為已載入或載入中的場景指派一個數值。框架會在每次調整後，自動將數值最大的場景設定為 Unity 的作用中場景（`SceneManager.SetActiveScene`），並發出 `ActiveSceneChangedEventArgs` 事件。這通常用於在多個場景以 Additive 模式共存時，精確控制哪個場景作為邏輯上的主場景。

## 前置條件

- 專案已整合 GameFrameX 場景元件（帶有 `[AddComponentMenu("GameFrameX/Scene")]` 的 `SceneComponent`）以及 YooAsset 資源管理。
- 場景資源路徑必須以 `Assets/` 開頭並以 `.unity` 結尾（框架會進行驗證；否則會印出 `Scene asset name '{0}' is invalid.`）。
- 在呼叫 `SetSceneOrder` 之前，場景必須已處於「載入中」或「已載入」狀態；否則框架會印出 `Scene '{0}' is not loaded or loading.` 並忽略此指派。
- 若要監聽切換結果，請訂閱 `ActiveSceneChangedEventArgs` 事件（參閱「如何載入與卸載場景」）。

## 步驟

1. **取得場景元件**。在任何可存取 `GameEntry` 的指令碼中：

```csharp
using GameFrameX.Scene.Runtime;

var sceneComponent = GameEntry.GetComponent<SceneComponent>();
```

來源：[SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L49-L50)

2. **以 Additive 模式載入場景**。作用中場景切換依賴多個已載入場景共存，通常使用 `LoadSceneMode.Additive`：

```csharp
await sceneComponent.LoadScene(
    "Assets/Scenes/Battle.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
```

來源：[SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L294-L322)

3. **為場景指派優先順序**。數值越大優先順序越高；當數值相同時，由 `m_SceneOrder`（`SortedDictionary<string,int>`）的列舉順序決定勝出者：

```csharp
// 將 Battle 設為最高優先順序；它將被切換為作用中場景
sceneComponent.SetSceneOrder("Assets/Scenes/Battle.unity", 100);

// 載入另一個優先順序較低的 HUD 場景
await sceneComponent.LoadScene(
    "Assets/Scenes/HUD.unity",
    UnityEngine.SceneManagement.LoadSceneMode.Additive);
sceneComponent.SetSceneOrder("Assets/Scenes/HUD.unity", 10);
```

來源：[SceneComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/Scene/SceneComponent.cs#L352-L381)

4. **訂閱作用中場景切換事件**（可選，用於在切換後重新整理 UI、攝影機，或重新派發主攝影機參考）：

```csharp
using GameFrameX.Event.Runtime;
using GameFrameX.Scene.Runtime;

GameEntry.GetComponent<EventComponent>().Subscribe(
    ActiveSceneChangedEventArgs.EventId,
    (sender, args) =>
    {
        var e = (ActiveSceneChangedEventArgs)args;
        UnityEngine.Debug.Log($"Active: {e.ActiveSceneName} (prev: {e.LastActiveSceneName})");
        sceneComponent.RefreshMainCamera(); // 重新取得 Camera.main
    });
```

來源：[ActiveSceneChangedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.scene/blob/main/Runtime/EventArgs/ActiveSceneChangedEventArgs.cs)

## 常見變化

**調整立即生效**：`SetSceneOrder` 會呼叫內部的 `RefreshSceneOrder()`，將已載入且優先順序最高的場景設為作用中場景；如果新場景仍處於 `isLoaded==false` 的非同步視窗期間，框架會啟動 `RefreshSceneOrderWhenLoadedCo` 協程，等待至下一幀再進行啟用。

**沒有作用中候選場景**：當 `m_SceneOrder` 為空，或所有已註冊場景仍在載入時，框架會退回使用 GameFramework 自身的場景（`m_GameFrameworkScene`）作為作用中場景。

**相同優先順序的場景**：如果兩個場景優先順序相同，則較晚列舉者勝出（因為 `RefreshSceneOrder` 在覆寫前使用 `>` 進行比較）。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `SetSceneOrder` 無效果，日誌顯示 `Scene '{0}' is not loaded or loading.` | 場景既不處於「載入中」也不處於「已載入」狀態 | 先呼叫 `await LoadScene(...)`，再設定順序 |
| 路徑不正確，日誌顯示 `Scene asset name '{0}' is invalid.` | 資源名稱未以 `Assets/` 開頭或未以 `.unity` 結尾 | 使用完整的專案相對資源路徑 |
| 拋出 `ArgumentException: sceneHandle.IsValid` 或類似例外 | YooAsset `await` 完成的時間早於 Unity 場景的 `isLoaded==true` | 框架已在 `RefreshSceneOrder` 內部使用協程延遲至下一幀；無需手動重試 |
| 連續多次呼叫 `SetSceneOrder` 導致舊協程仍在執行 | 框架在啟動新協程前已對舊協程呼叫 `StopCoroutine` | 無需手動管理；若在自訂邏輯中混用其他啟用方式，請避免與框架競爭 |
| 作用中場景切換後，`Camera.main` 仍指向舊攝影機 | 切換僅變更場景，不會主動尋找新的攝影機 | 呼叫 `sceneComponent.RefreshMainCamera()`，或訂閱 `ActiveSceneChangedEventArgs` 並重新整理 |

## 背景說明（選讀）

`m_SceneOrder` 是一個以 `Ordinal` 方式比較索引鍵的 `SortedDictionary<string, int>`；`RefreshSceneOrder` 會對其進行迭代以挑出最大值，然後呼叫私有的 `SetActiveScene(...)` 將場景交給 Unity 的 `SceneManager.SetActiveScene`，並透過 `m_EventComponent.Fire(this, ActiveSceneChangedEventArgs.Create(...))` 派發事件。在 Single 模式下，YooAsset/Unity 會自行管理作用中場景；框架會偵測目標 Scene 控制代碼何時變為無效，並直接跳過此指派，以避免在非同步視窗期間拋出 `ArgumentException`。
