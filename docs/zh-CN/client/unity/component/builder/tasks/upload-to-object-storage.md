# 如何上传构建产物到对象存储

通过在 Unity 命令行中传入对象存储相关参数,可以让构建流水线在出包后自动把日志、资源或 APK 上传到兼容 S3 协议的对象存储(OSS/S3/cos 等)。本页讲解本仓库暴露的配置开关与触发点,帮助你把构建产物推到远端桶里。

## 前置条件

- 已按 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/README.zh-CN.md) 把 `com.gameframex.unity.builder` 装入 Unity 工程。
- 引入实现了 `ObjectStorageUploadManager.UploadFile(string)` 的对象存储 SDK 包(本仓库通过编译宏 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 接入,未引入该 SDK 时上传代码不会编译)。
- 已准备好对象存储桶的 `Key`、`Secret`、`BucketName`、`EndPoint`(区域/Endpoint)。

## 操作步骤

1. 在构建机上准备好对象存储参数。以下四个字段由 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L22-L40) 解析:

   | 字段 | 含义 |
   |------|------|
   | `ObjectStorageKey` | 访问 Key(账号 AccessKey) |
   | `ObjectStorageSecret` | 访问 Secret |
   | `ObjectStorageBucketName` | 桶(Bucket)名称 |
   | `ObjectStorageEndPoint` | 桶所在区域 Endpoint |

2. 在 Unity 命令行里通过 `-ObjectStorageKey`、`-ObjectStorageSecret`、`-ObjectStorageBucketName`、`-ObjectStorageEndPoint` 把上述四个值传入。构建脚本会通过 `Builder.BuildParamsParse` 反射回填到 `_builderOptions` 上。

3. 打开对应的上传开关。仓库提供三个互不冲突的布尔开关,见 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L62-L125):

   | 开关 | 默认值 | 作用 |
   |------|--------|------|
   | `IsUploadLogFile` | `false` | 构建准备阶段上传日志 |
   | `IsUploadAsset` | `false` | 构建资源后上传资产包 |
   | `IsUploadApk` | `false` | 出 APK 后上传安装包 |

4. 以 `BuildReady` 为例,日志上传的实际触发代码在 [Builder.BuildReady.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49):

   ```csharp
   AssetDatabase.Refresh();
   if (_builderOptions.IsUploadLogFile)
   {
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.UploadFile(_builderOptions.LogFilePath);
   #endif
   }
   ```

   Source: [Editor/Builder.BuildReady.cs#L43-L49](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildReady.cs#L43-L49)

   只有定义了 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 编译符号,`UploadFile` 调用才会进入构建;否则整段被预处理掉,任务不会报错。

5. 触发构建。任选一条入口命令,确保开关被打开:

   ```bash
   Unity -batchmode -quit -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildReady \
         -ObjectStorageKey <your-key> \
         -ObjectStorageSecret <your-secret> \
         -ObjectStorageBucketName <your-bucket> \
         -ObjectStorageEndPoint <your-endpoint> \
         -IsUploadLogFile true \
         -IsUploadAsset true \
         -IsUploadApk true \
         -logFile -
   ```

   参数由 [BuilderOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L127-L130) 通过反射写入模型,日志中可打印 `ToString()` 验证。

## 常见变体

- **只想推日志**:只传 `-IsUploadLogFile true`,其余两个上传开关保持默认 `false`。
- **只想推资源包**:在调用 `BuildAsset` 流水线时传 `-IsUploadAsset true`。
- **只想推 APK**:在调用 `BuildApk` 流水线时传 `-IsUploadApk true`。
- **不同环境隔离**:把四个存储参数放进 CI 的环境变量,构建脚本里再回填到命令行。

## 常见错误

- **运行时报"找不到 ObjectStorageUploadManager"**:本仓库只持有上传开关,真正的上传类由外部对象存储 SDK 提供。需要在 `Packages/manifest.json` 中安装对应实现包,并在 Player Settings 的 `Scripting Define Symbols` 中加入 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE`,否则 `#if` 分支被裁掉。
- **桶里看不到文件**:确认 `ObjectStorageEndPoint` 是桶所在区域的 Endpoint(不是控制台域名),并且桶的 ACL 允许该 Key 写入。
- **多个构建同时上传冲突**:构建号 `BuildNumber` 会参与远端路径(在外部 SDK 内拼装),并发场景下要保证 `BuildNumber` 唯一。

## 背景(可选)

仓库设计成"开关 + 编译宏"的最小耦合:`BuilderOptions` 只负责把命令行参数搬进模型,真正调用 `ObjectStorageUploadManager` 的位置仅在 `BuildReady`、`BuildAsset`、`BuildApk` 三个流水线的上传分支出现;未定义 `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` 时上传代码整段不参与编译,保证没有对象存储依赖的项目也能直接用本工具。
