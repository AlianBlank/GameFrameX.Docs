## 테스트가 다루는 모듈

테스트 프로젝트는 테스트 대상 모듈의 네임스페이스에 따라 디렉터리를 구분하며, 각 `ProjectReference`는 하나의 테스트 하위 디렉터리에 대응합니다:

| 테스트 디렉터리 | 해당 프로젝트 | 테스트 대상 내용 |
|------|------|------|
| `Architecture/` | GameFrameX.Architecture.Analyzers | 아키텍처 분석기(예: `StateComponentAgentSealedAnalyzerTests`) |
| `Core/Actors/` | GameFrameX.Core | Actor 관리자, Worker Actor, 주기적 저장 |
| `DataBase/` | GameFrameX.DataBase / GameFrameX.DataBase.Mongo | MongoDB 연결 및 쿼리 서비스 |
| `Localization/` | GameFrameX.Core | 로컬라이제이션 리소스 |
| `NetWork/Http/` | GameFrameX.NetWork | HTTP 핸들러와 보안 기본값 |
| `NetWork/Kcp/` | GameFrameX.NetWork.Kcp | KCP 세션, 옵션, 메시지 파이프라인, 서버 통합 |
| `ProtoBuff/` | GameFrameX.ProtoBuf.Net | Protobuf 직렬화 및 객체 풀 |
| `RemoteMessaging/` | GameFrameX.NetWork | 기본 메시지 코덱과 원격 메시지 송수신 |
| `StartUp/` | GameFrameX.StartUp | 애플리케이션 진입/종료 흐름 |

테스트 프로젝트가 참조하는 총 11개의 테스트 대상 프로젝트(`Apps`/`Core`/`DataBase`/`DataBase.Mongo`/`ProtoBuf.Net`/`StartUp`/`Utility`/`NetWork.Kcp`/`Hotfix`/`NetWork`/`Architecture.Analyzers`)는 csproj에서 `ProjectReference` 형태로 선언됩니다.

## 테스트 실행

### 사전 조건

- .NET SDK가 설치되어 있어야 합니다(버전은 각 테스트 대상 프로젝트의 `TargetFramework`와 일치).
- 리포지토리 루트 디렉터리에서 복원 가능한 NuGet 소스가 있어야 합니다.

### 작업 단계

1. 의존성을 복원하고 테스트 디렉터리로 이동합니다:

```bash
dotnet restore Tests/GameFrameX.Tests/GameFrameX.Tests.csproj
cd Tests/GameFrameX.Tests
```

2. 전체 테스트를 실행합니다:

```bash
dotnet test --nologo
```

3. 이름으로 필터링하여 단일 테스트 클래스를 실행합니다(예: `LNumberFixTest`만 실행):

```bash
dotnet test --filter "FullyQualifiedName~LNumberFixTest"
```

4. 커버리지 수집을 활성화합니다:

```bash
dotnet test --collect:"XPlat Code Coverage"
```

보고서는 기본적으로 `TestResults/<guid>/coverage.cobertura.xml`로 출력됩니다.

### 일반적인 변형

| 시나리오 | 명령 조각 |
|------|------|
| 상세 로그 | `dotnet test --logger "console;verbosity=detailed"` |
| 지정된 네임스페이스만 실행 | `dotnet test --filter "FullyQualifiedName~GameFrameX.Tests.NetWork.Kcp"` |
| 디버그 모드로 실행 | `dotnet test -c Debug` |
| 통합 테스트 제외 | `dotnet test --filter "FullyQualifiedName!~Integration"` |

## 테스트 작성 예시

테스트 클래스는 일반 class에서 상속하며, `[Fact]`로 테스트 케이스를 표시하고 `Assert.*`로 어설션합니다. 다음은 `Tests/GameFrameX.Tests/LNumberFixTest.cs`의 실제 코드 조각입니다:

```csharp
using GameFrameX.Utility;
using Xunit;

namespace GameFrameX.Tests
{
    public class LNumberFixTest
    {
        [Fact]
        public void TestCreateNegativeNumbers()
        {
            var negativeNumber = LNumber.Create(-123, -4567);

            Assert.True(negativeNumber.Raw < 0, "Raw value should be negative");
            Assert.True((double)negativeNumber < 0, "Double value should be negative");
            Assert.Equal(-124, negativeNumber.Floor);
            Assert.Equal(-123, negativeNumber.Ceiling);
            Assert.Equal(-123, (long)negativeNumber);
        }
    }
}
```

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `error NU1605: Detected package downgrade` | 솔루션 루트 디렉터리가 통일된 버전으로 복원되지 않음 | 테스트 디렉터리가 아닌 리포지토리 루트 디렉터리에서 `dotnet restore` 실행 |
| `Could not load file or assembly 'GameFrameX.Core'` | 테스트 대상 프로젝트가 빌드되지 않음 | 먼저 전체 솔루션을 `dotnet build`한 후 `dotnet test` 실행 |
| 발견된 테스트 수가 0 | `xunit.runner.visualstudio` 또는 `Microsoft.NET.Test.Sdk` 누락 | csproj의 PackageReference가 주석 처리되거나 삭제되지 않았는지 확인 |
| `coverlet` 출력 없음 | `--collect` 매개변수가 지정되지 않음 | `--collect:"XPlat Code Coverage"` 추가 |
| `MongoDb` 테스트 연결 실패 | 로컬에서 MongoDB 인스턴스가 실행되지 않음 | MongoDB를 시작하거나 테스트 전에 `docker run -p 27017:27017 mongo` 실행 |

## 검증

- `dotnet test` 종료 코드가 0이고, `Passed: <N>, Failed: 0, Skipped: 0`가 출력됩니다.
- `TestResults/` 아래에 `coverage.cobertura.xml`이 생성되며, 크기가 0이 아닙니다.
- IDE(Rider / Visual Studio)의 Test Explorer에서 디렉터리와 일대일로 대응하는 테스트 스위트를 확인할 수 있습니다.
