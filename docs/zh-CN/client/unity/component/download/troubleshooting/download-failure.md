# 下载失败怎么办：排查错误码与回调

当 `DownloadComponent` 抛出 `DownloadFailureEventArgs` 或 `DownloadAgentHelperErrorEventArgs` 时,任务处于失败状态。本页帮助你根据错误回调里的字段快速定位根因并修复。

## 快速诊断

| 症状(回调字段取值) | 根因 | 一句话修复 |
|---|---|---|
| `ErrorMessage` 为 `"... 416 ..."`,且 `DeleteDownloading == true`(UnityWebRequest) 或以 `"416"` 开头(WWW) | HTTP 416 Range Not Satisfiable — 远端不支持请求的字节区间 | 见下方"416 Range 错误"修复步骤 |
| `ErrorMessage` 非空,但未包含 416 | 网络层异常(超时、DNS 失败、断连、协议错误等) | 见下方"网络层错误"修复步骤 |
| `DeleteDownloading == true` 且 `ErrorMessage` 非空 | 任务写入的文件需要被删除,避免残留 | 见下方"清理失败残留"修复步骤 |
| 长时间无回调、`WorkingAgentCount == TotalAgentCount` | 全部 Agent 被占用,新任务排队等候 | 见下方"任务卡住"修复步骤 |

> 字段定义见 [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L38-L88) 与 [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L38-L116)。

## 修复步骤

### 1. 订阅失败回调,先拿到原始信息

在 `DownloadComponent.Awake` 之后的事件订阅位置已经注册好 `DownloadFailure`,你只需要实现处理函数并通过事件总线或 `IDownloadManager.DownloadFailure` 拿到 `DownloadFailureEventArgs`:

```csharp
using GameFrameX.Download.Runtime;
using GameFrameX.Event.Runtime;

// 通过事件总线订阅(推荐,与组件解耦)
GameEntry.GetComponent<EventComponent>().Subscribe(
    DownloadFailureEventArgs.EventId,
    OnDownloadFailure
);

private void OnDownloadFailure(object sender, GameEventArgs e)
{
    var args = (DownloadFailureEventArgs)e;
    Debug.LogError($"[Download] FAIL serial={args.SerialId} path={args.DownloadPath} uri={args.DownloadUri} err={args.ErrorMessage} userData={args.UserData}");
}
```

Source: [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L80-L97)

### 2. 416 Range Not Satisfiable

这是框架识别的"远端拒绝断点续传区间"信号。框架判断方式如下:

- UnityWebRequest 实现:`responseCode == 416` 时 `DeleteDownloading = true`。
- WWW 实现:`error` 字符串以 `"416"` 开头时 `DeleteDownloading = true`。

Source: [DownloadAgentHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadAgentHelperBase.cs#L44-L44) ; [UnityWebRequestDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/UnityWebRequestDownloadAgentHelper.cs#L240-L240) ; [WWWDownloadAgentHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/WWWDownloadAgentHelper.cs#L248-L248)

修复操作:

1. 在收到 `DeleteDownloading == true` 的失败回调后,删除本地残留的分段文件。
2. 重新调用 `DownloadComponent.AddDownload(url, tag, priority, userData)`,框架会从 0 重新下载。
3. 若 CDN/OSS 不支持 `Range` 请求,关闭断点续传或在地址层排除此文件类型。

### 3. 网络层错误(超时 / DNS / 连接重置)

`DownloadAgentHelperErrorEventArgs.ErrorMessage` 直接透传 Unity 原生错误字符串,例如 `"Cannot resolve destination host"`、`"Request timeout"`、`"Connection failure"`。

修复操作:

1. 把 `DownloadComponent.Timeout`(默认 30 秒)按需调大,例如公网文件改为 60 秒:见 [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60-L62)。
2. 检查地址是否需要 HTTPS、是否被代理拦截。
3. 实现重试:在 `DownloadFailure` 回调里重新入队同 URL 的下载任务(注意替换 `UserData` 以便区分重试次数)。

### 4. 清理失败残留

当 `DownloadAgentHelperErrorEventArgs.DeleteDownloading == true` 时,框架已建议你清理本地分片:

```csharp
private void OnAgentError(object sender, GameEventArgs e)
{
    var args = (DownloadAgentHelperErrorEventArgs)e;
    if (args.DeleteDownloading && !string.IsNullOrEmpty(localPath) && File.Exists(localPath))
    {
        File.Delete(localPath);
    }
}
```

Source: [DownloadAgentHelperErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadAgentHelperErrorEventArgs.cs#L67-L73)

### 5. 任务卡住(队列堆积)

长时间拿不到 `DownloadSuccess` 也不触发 `DownloadFailure`,通常是 Agent 被占满。监控以下属性判断:

| 属性 | 含义 |
|---|---|
| `DownloadComponent.TotalAgentCount` | 总 Agent 数,默认 3 |
| `DownloadComponent.WorkingAgentCount` | 正在下载的 Agent |
| `DownloadComponent.WaitingTaskCount` | 排队中的任务 |
| `DownloadComponent.Paused` | 是否被全局暂停 |

Source: [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L78-L105)

修复:

1. 在 Inspector 把 `Download Agent Helper Count` 调大。
2. 确认没人把 `DownloadComponent.Paused = true` 之后忘了恢复。
3. 用 `DownloadComponent.GetDownloadInfo(serialId)` / `GetDownloadInfos(tag)` 拿到当前任务状态。

## 验证

按以下顺序验证问题已解决:

1. 触发一次已知会失败的下载(例如填错地址或故意断开网络),确认能收到 `DownloadFailure` 回调且 `ErrorMessage` 与预期一致。
2. 对 416 场景,确认回调后本地无残留文件,且重新调用 `AddDownload` 能成功下载到完整文件。
3. 对网络超时场景,把 `Timeout` 调小复现一次,然后用新的超时值复现到成功。
4. 跑一遍批量下载,确认 `WaitingTaskCount` 在合理时间后归零、`FreeAgentCount` 恢复到 `TotalAgentCount`。
