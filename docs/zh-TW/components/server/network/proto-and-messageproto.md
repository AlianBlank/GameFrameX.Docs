# 新增 Proto 協定並接入 MessageProtoHandler

在 `GameFrameX.Proto` 專案中新增一個 `.proto` 檔案後，只要讓 `MessageProtoHandler` 類別被該組件承載，啟動器就會在初始化階段自動掃描並註冊全部協定訊息類型，無需手寫註冊程式碼。

## 前置條件

- 方案中已存在 `GameFrameX.Proto` 專案，其引用了 `GameFrameX.NetWork 1.13.0` 套件，用於協定訊息的編解碼與分發。
- 目標框架為 `net10.0`(`LangVersion=10`)。
- 業務模組(例如 `GameFrameX.Apps`)透過 `ProjectReference` 引用 `GameFrameX.Proto`,以便產生的協定型別對編譯期可見。

## 操作步驟

1. 在 `GameFrameX.Proto/Proto/` 目錄下建立 `.proto` 檔案，定義訊息與服務。例如新建 `GameFrameX.Proto/Proto/Helloworld.proto`:

   ```protobuf
   syntax = "proto3";

   option csharp_namespace = "GameFrameX.Proto";

   package helloworld;

   // 請求訊息
   message HelloRequest
   {
       string name = 1;
   }

   // 回應訊息
   message HelloReply
   {
       string message = 1;
   }

   service Greeter
   {
       rpc SayHello (HelloRequest) returns (HelloReply);
   }
   ```

   檔案直接放在 `Proto` 資料夾下，該資料夾已由 csproj 宣告為保留目錄，IDE 與 MSBuild 都不會把它當程式碼編譯。

   Source: [GameFrameX.Proto/GameFrameX.Proto.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/GameFrameX.Proto.csproj#L12-L14)

2. 確認 `MessageProtoHandler` 類別位於 `GameFrameX.Proto` 組件內。該類別是空殼靜態類別，作用是充當「協定處理器錨點」，讓後續初始化程式碼能透過它的 `Assembly` 反映到當前組件裡所有的協定訊息類型：

   ```csharp
   namespace GameFrameX.Proto;

   /// <summary>
   /// 協定訊息處理器
   /// </summary>
   public static class MessageProtoHandler
   {
   }
   ```

   Source: [GameFrameX.Proto/MessageProtoHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/MessageProtoHandler.cs#L1-L8)

3. 在啟動入口(目前是 `GameFrameX.Launcher/Program.cs`)呼叫一次 `MessageProtoHelper.Init`,傳入 `MessageProtoHandler` 所在組件，完成所有 `proto` 訊息類型的註冊：

   ```csharp
   MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
   ```

   Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L14-L15)

4. 在需要取用協定型別的下游專案中新增專案參考，讓產生的程式碼對呼叫方可見：

   ```xml
   <ProjectReference Include="..\GameFrameX.Proto\GameFrameX.Proto.csproj" />
   ```

   Source: [GameFrameX.Apps/GameFrameX.Apps.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/GameFrameX.Apps.csproj#L10-L10)

5. 編譯並啟動 Launcher。`MessageProtoHandler` 所在組件中新增的 `.proto` 訊息類型會被自動註冊到訊息分發管線。

## 常見變體

- **多個 `.proto` 檔案**：在 `GameFrameX.Proto/Proto/` 下並列放置多個 `.proto` 檔案即可，`MessageProtoHelper.Init` 會一次性掃描整個組件。
- **切換 C# 命名空間**：在每個 `.proto` 檔案頂部用 `option csharp_namespace = "Your.Namespace";` 控制產生程式碼的命名空間，與 `MessageProtoHandler` 所在的 `GameFrameX.Proto` 解耦。
- **不在 Launcher 啟動**：只要呼叫方能夠存取 `GameFrameX.NetWork.MessageProtoHelper.Init`,傳入 `MessageProtoHandler` 所在組件即可完成註冊，與啟動專案無關。

## 常見錯誤

- **把 `.proto` 放在專案根目錄而非 `Proto` 資料夾**：雖然 csproj 沒有明確排除，但 `Proto` 資料夾是保留目錄，放在更淺的位置容易在後續接入程式碼產生器時被 `*.proto` 預設規則誤處理。
- **忘記 `MessageProtoHelper.Init`**:不呼叫 `Init` 的話，新協定不會被註冊，執行階段會找不到訊息類型處理器。
- **下游專案未引用 `GameFrameX.Proto`**:即使註冊成功，呼叫方也無法拿到產生的訊息類型，編譯期會報「找不到型別」。
- **改名 `MessageProtoHandler` 類別或類別不在 Proto 組件**:`typeof(MessageProtoHandler).Assembly` 將指向錯誤的組件，新協定不會被發現。

## 背景

`GameFrameX.NetWork` 套件的 `MessageProtoHelper.Init(Assembly)` 透過反映掃描傳入組件內由 `.proto` 產生的 C# 訊息類型並完成註冊。`MessageProtoHandler` 在 `GameFrameX.Proto` 中是佔位用的靜態類別，它唯一的「作用」就是讓啟動器能拿到一個穩定的型別，從而定位到 `GameFrameX.Proto` 組件——這避免了硬式編碼組件名稱。
