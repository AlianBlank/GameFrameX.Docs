# How to Use JsonHelper for Serialization and Deserialization

`JsonHelper` is a static helper encapsulated in the `GameFrameX.Foundation.Json` namespace that lets you convert any object to and from JSON using a consistent configuration: it ignores `null` by default, ignores circular references, reads and writes enums as strings, does not escape Chinese characters / Emoji, and includes built-in `NaN` / `Infinity` compatibility handling.

## Prerequisites

- The project targets `.NET 6+` (depends on `System.Text.Json`).
- Reference the `GameFrameX.Foundation.Json` package in your project (`GameFrameX.Foundation.Json.csproj`).

```text
dotnet add package GameFrameX.Foundation.Json
```

```csharp
using GameFrameX.Foundation.Json;
```

## Steps

### 1. Choose a Configuration

`JsonHelper` comes with two built-in read-only configurations that can be used directly:

| Configuration | Field | Use Cases |
|------|------|----------|
| Default (compact) | `JsonHelper.DefaultOptions` | Network transmission, logging, storage |
| Formatted (with indentation and line breaks) | `JsonHelper.FormatOptions` | Debug output, configuration files |
| Custom mutable copy | `JsonHelper.CreateDefaultOptions()` / `JsonHelper.CreateFormatOptions()` | Adjust on top of the defaults |

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L87-L117)

### 2. Serialize an Object to a JSON String

```csharp
var user = new { Name = "张三", Age = 18, Role = UserRole.Admin };

// Default configuration (compact)
string json = JsonHelper.Serialize(user);

// Formatted configuration (with indentation)
string pretty = JsonHelper.SerializeFormat(user);

// Custom configuration
var options = JsonHelper.CreateDefaultOptions();
options.WriteIndented = true;
string custom = JsonHelper.Serialize(user, options);
```

- `Serialize(object obj)` and `Serialize(object obj, JsonSerializerOptions options)` are the two most commonly used entry points; they throw `ArgumentNullException` when `obj` is `null`.
- Enums are output as **strings** by default (`Role: "Admin"`), not numbers.
- `null` fields are automatically ignored; `"Name": null` will never appear.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L221-L246)

### 3. Serialize to a UTF-8 Byte Array or Stream

```csharp
// Byte array (suitable for writing directly to disk / sending as an HTTP body)
byte[] bytes = JsonHelper.SerializeToUtf8Bytes(user);
byte[] bytesFormat = JsonHelper.SerializeToUtf8BytesFormat(user);

// Write to a stream asynchronously
using var ms = new MemoryStream();
await JsonHelper.SerializeAsync(ms, user);
```

- `SerializeToUtf8Bytes` is compact by default, while `SerializeToUtf8BytesFormat` uses the formatted configuration.
- `SerializeAsync<T>(Stream, T, JsonSerializerOptions?, CancellationToken)` uses `DefaultOptions` by default, and `stream` must not be `null`.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L333-L356)

### 4. Deserialize a JSON String to an Object

```csharp
const string payload = "{\"name\":\"张三\",\"age\":18,\"role\":\"Admin\"}";

var restored = JsonHelper.Deserialize<User>(payload);

// With a custom configuration
var restored2 = JsonHelper.Deserialize<User>(payload, options);

// Read from a stream asynchronously
using var input = new MemoryStream(bytes);
var restored3 = await JsonHelper.DeserializeAsync<User>(input);
```

- `Deserialize<T>(string json)` throws `ArgumentException` internally for `null`, empty strings, and whitespace-only strings; validate the input before calling.
- When the JSON contains `NaN` / `Infinity`, the method automatically preprocesses and retries — no manual escaping is needed.
- Property name matching is **case-insensitive**, so both `Name` and `name` are supported.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L406-L421)

### 5. Non-Throwing Try Versions (Recommended When Input Validity Is Uncertain)

```csharp
if (!JsonHelper.TryDeserialize<User>(payload, out var user, out var error))
{
    Console.WriteLine($"反序列化失败: {error.Kind} - {error.Message} (path={error.Path})");
}
```

- The `TryDeserialize<T>` / `TrySerialize` series return `bool`; on failure, they provide `Kind` (`InvalidInput` / `TypeMismatch` / `Serialization` / `Unknown`), `Path`, `LineNumber`, and `BytePositionInLine` via `out JsonHelperError`.
- `TryDeserialize<T>(string, out T)` with the default configuration also automatically preprocesses and retries when `NaN` / `Infinity` is encountered.

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L749-L807)

## Common Variants

- **AOT / source-generated high-performance path**: Call serialization / deserialization via `JsonTypeInfo<T>` for zero reflection in trimming and AOT scenarios:

  ```csharp
  string json = JsonHelper.Serialize(user, MyJsonContext.Default.User);
  var restored = JsonHelper.Deserialize<User>(payload, MyJsonContext.Default.User);
  ```

- **Custom floating-point handling**: The default configuration already registers converters such as `SpecialFloatingPointConverter`, so passing the string literals `"NaN"` and `"Infinity"` directly also deserializes successfully.
- **Writing BOM / custom Encoder**: After calling `CreateDefaultOptions()`, simply assign a new value to `Encoder`; other default behaviors are unaffected.
- **Fault-tolerant deserialization of external input**: Prefer `TryDeserialize<T>(string, out T, out JsonHelperError)`, and decide on a fallback after inspecting the `JsonHelperError`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentNullException: obj (Parameter 'obj')` | Called `Serialize(null)` / `SerializeAsync(stream, null, …)` | Add an `obj is null` check before calling, or switch to `TrySerialize` |
| `ArgumentException: json (Parameter 'json')` | `Deserialize` received `null`, an empty string, or whitespace only | Check with `string.IsNullOrWhiteSpace` first, or switch to `TryDeserialize` |
| `JsonException` with `error.Kind == InvalidInput` | Invalid JSON text (missing quotes; although `AllowTrailingCommas=true` handles trailing commas, the text may still be malformed) | Check upstream logs; `JsonHelperError` includes `Path` / `LineNumber` for locating the issue |
| Enum fields deserialize as numbers | Business code created its own `JsonSerializerOptions` without registering `JsonStringEnumConverter` | Use `JsonHelper.DefaultOptions` or `CreateDefaultOptions()` directly instead of creating default options yourself |

## Background (Optional)

`DefaultOptions` combines `DefaultIgnoreCondition = WhenWritingNull`, `ReferenceHandler.IgnoreCycles`, `JsonStringEnumConverter`, and `AllowReadingFromString | AllowNamedFloatingPointLiterals`, so business code barely needs to worry about `null` fields, circular references, or enum semantics; keeping Chinese characters / Emoji unescaped relies on the project's `UnicodeJsonEncoder`. Both configurations are frozen with `MakeReadOnly(true)` in the static constructor to prevent accidental modification at runtime; when customization is needed, callers must use `CreateDefaultOptions()` to obtain a mutable copy.
