# 如何理解与修改 luban.conf

`luban.conf` 是 GameFrameX.Config 的总配置文件:它告诉 Luban 工具链去哪儿读 Excel、用哪些数据/代码目标、生成产物落到哪个目录。改完这份文件,再运行 `gen-*.bat` / `gen-*.sh` 就能按新规则生成客户端与服务器代码。

## 前置条件

- 已克隆 [GameFrameX/GameFrameX.Config](https://github.com/GameFrameX/GameFrameX.Config) 仓库,根目录存在 `luban.conf`。
- 已安装 .NET 运行时(用于执行 `Tools/Luban.exe`)。
- 了解 `groups`(客户端/服务器数据分组)、`targets`(生成目标)、`commands`(要执行的命令)三个顶层概念。

## 顶层字段速览

| 字段 | 作用 | 典型值 |
|------|------|--------|
| `groups` | 把表按"客户端/服务器"分组,生成时按组过滤 | `c`(客户端)、`s`(服务器) |
| `schemaFiles` | Luban 加载的 schema 入口(`Defines`、`__tables__` 等) | 见下方代码块 |
| `dataDir` | Excel 数据根目录 | `Excels` |
| `targets` | 生成目标集合,每个目标对应一套代码/数据产物 | `server`、`client`、`all` |
| `toolPath` | Luban.dll 的相对路径 | `/../Config/Tools/Luban.dll` |
| `UNITY_ASSETS_PATH` | Unity 工程 Assets 目录的绝对路径(运行时模板) | 留空,执行脚本时替换 |
| `SERVER_PATH` | 服务器工程根目录的绝对路径(运行时模板) | 留空,执行脚本时替换 |
| `commands` | 每个生成命令对应一个 target,含命令行参数与开关 | 见下方代码块 |

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L95)

## 关键字段逐段讲解

### 1. groups:数据怎么分流

`groups` 决定每张表属于"客户端"、"服务器"还是"双端共享"。`default: true` 表示该组的所有表默认都会被生成命令消费。

```json
"groups": [
    { "names": ["c"], "default": true },
    { "names": ["s"], "default": true }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

> 一张表属于哪个组,由它在 Excel 中通过 `__xxx__` 标记列标注;此处只定义"组名存在哪些"。

### 2. schemaFiles:加载哪些定义

`schemaFiles` 是 Luban 读取 schema 的入口,顺序无所谓,但四行是必需的:`Defines`(内置类型目录)、`__tables__.xlsx`(表清单)、`__beans__.xlsx`(复杂结构)、`__enums__.xlsx`(枚举)。

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

### 3. targets:生成目标定义

每个 target 是"一组数据 + 一套生成产物"的命名包。`topModule` 是生成的命名空间,`manager` 是入口类名(运行时用 `TablesComponent` 或 `Tables` 单例加载)。

```json
"targets": [
    { "name": "server", "manager": "TablesComponent", "groups": ["s"], "topModule": "GameFrameX.Config" },
    { "name": "client", "manager": "TablesComponent", "groups": ["c"], "topModule": "Hotfix.Config" },
    { "name": "all",    "manager": "Tables",         "groups": ["c","s"], "topModule": "cfg" }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L35-L61)

### 4. commands:执行哪些生成命令

`commands` 是真正传给 `Luban.exe` 的命令行数组。每条记录绑定一个 `target`,通过 `active: true/false` 切换启用。`%UNITY_ASSETS_PATH%` 与 `%SERVER_PATH%` 是占位符,生成脚本会在调用前替换为绝对路径。

```json
"commands": [
    {
        "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
        "target": "server", "active": true
    },
    {
        "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate",
        "target": "client", "active": true
    }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

常用开关:

- `--dataTarget json | bin` —— 数据落盘格式,`json` 可读、`bin` 体积小。
- `--codeTarget cs-simple-json | cs-dotnet-json | cs-bin` —— 生成的 C# 加载代码风格,客户端用 `cs-simple-json`、服务器用 `cs-dotnet-json`、启用二进制时用 `cs-bin`。
- `--validationFailAsError true` —— 校验失败直接报错,而不是只警告。
- `--xargs outputDataDir=...` / `--xargs outputCodeDir=...` —— 数据与代码产物的输出目录,支持 `%SERVER_PATH%`、`%UNITY_ASSETS_PATH%` 占位符。

## 常见变体

### 增加一个分组(例如多语言子端)

在 `groups` 数组中追加一项,记得同步在表头的 `__xxx__` 列里给相应表打上新分组名。

```json
{ "names": ["c"], "default": true },
{ "names": ["s"], "default": true },
{ "names": ["c_cn"], "default": true }
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L2-L15)

### 切换 JSON 与二进制产物

把对应 command 里的 `--dataTarget json --codeTarget cs-simple-json`(或 `cs-dotnet-json`)替换为 `--dataTarget bin --codeTarget cs-bin`,并把 `active` 置为 `true`。

### 改输出目录

直接修改 `commands[].command` 里的 `outputDataDir` / `outputCodeDir`;想复用脚本里的统一路径,保留 `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` 占位符即可。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 运行 `gen-*.bat` 报 `ToolPath not found` | `toolPath` 相对路径写错,或 `Tools/Luban.dll` 不在仓库里 | 保持默认 `/../Config/Tools/Luban.dll`;不要移动 `Tools/` 目录 |
| 生成代码找不到命名空间 | `targets[].topModule` 拼写错误,客户端/服务器 `topModule` 必须不同 | 客户端 `Hotfix.Config`、服务器 `GameFrameX.Config`,改成自己的命名空间 |
| 客户端工程没生成出代码 | 客户端 target 的 `groups` 不包含这张表所属的组 | 在 `targets[client].groups` 里补齐对应组名,或调整表的 `__xxx__` 列 |
| `commands` 里 `active` 全为 `false` | 全部命令被禁用 | 把需要执行的那条改为 `true` |
| 占位符 `%UNITY_ASSETS_PATH%` 没被替换 | 直接双击 `Luban.exe` 而没有通过 `gen-*.bat` / `gen-*.sh` 调用 | 通过仓库自带的生成脚本运行,脚本负责替换占位符 |

## 背景(可选)

`luban.conf` 的 schema 由 Luban 工具链规定,字段含义与 Luban 官方一致;本仓库额外扩展了 `toolPath`、`UNITY_ASSETS_PATH`、`SERVER_PATH`、`commands[].active` 四个字段,用于在 GameFrameX 工作流里通过 `gen-*.bat` / `gen-*.sh` 统一调度生成命令与占位符替换。
