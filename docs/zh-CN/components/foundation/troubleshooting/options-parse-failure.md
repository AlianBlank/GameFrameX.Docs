# 命令行参数解析失败怎么办

当使用 `OptionsBuilder` 或 `CommandLineArgumentConverter` 解析命令行参数抛出 `ArgumentException`、`ArgumentAlreadyException`、必需选项校验失败或属性值类型不对时，按本页诊断表定位根因并修复。

## 快速诊断

| 症状（异常消息/现象） | 原因 | 修复 |
|----------------------|------|------|
| `Argument cannot contain null` 风格的 `ArgumentException`，参数名 `args` | `args` 数组中包含 `null` 元素（`Main` 入参不应出现，但手动构造可能带入） | 见 [去除 args 中的 null](#修复-1去除-args-中的-null-元素) |
| `ArgumentException` 包裹的 "参数处理时发生错误: ..." | 解析流程中其他分支抛出异常，被 `ConvertToStandardFormat` 外层 `catch` 包装 | 查看 `ex.InnerException.Message`，对应到具体子问题；见 [修复 2](#修复-2排查参数处理时的内部异常) |
| 必需选项未赋值时进程崩溃或字段为默认值 | 缺少必填参数，且未传 `skipValidation: true` | 用 `skipValidation` 跳过校验，或补齐必填参数；见 [修复 3](#修复-3补齐必填参数或跳过校验) |
| 同一个键被赋值两次，后一次不生效或抛 `ArgumentAlreadyException` | 重复传入相同选项，或环境变量与命令行同名键冲突 | 见 [修复 4](#修复-4解决参数重复或环境变量与命令行冲突) |
| 布尔型字段拿到了 `"true"/"false"` 之外的字符串 | `BoolArgumentFormat.Flag` 模式下，下一个看起来像值的 token 被当成布尔消耗/未识别 | 显式传 `--flag=true`，或切换 `BoolArgumentFormat`；见 [修复 5](#修复-5布尔参数解析异常) |
| 负数（如 `--offset=-3`）被识别成"选项键"再误把下一参数当值 | `IsNegativeNumber` 已识别为负数时，`IsOptionToken` 返回 `false`，但带空格的负数表达式可能误判 | 把值写成 `--offset=-3` 形式，避免在负数后再追加值；见 [修复 6](#修复-6负数与带空格的值解析异常) |
| 键值对 `--key=` 后面的值丢失，字段为默认值 | 值为空字符串被当作"没值"，下一项被跳过 | 若想保留空值，使用 `--key=""` 或保留 `EnsurePrefixedKeys=true` 让 `--key=` 正常落地 |

## 修复步骤

### 修复 1：去除 args 中的 null 元素

`ConvertToStandardFormat` 在检测到 `arg == null` 时立即抛出 `ArgumentException`：

```csharp
// CommandLineArgumentConverter.ConvertToStandardFormat
if (arg == null)
{
    throw new ArgumentException(LocalizationService.GetString(LocalizationKeys.Exceptions.ArgsCannotContainNull), nameof(args));
}
```

修复做法：在调用前过滤：

```csharp
using GameFrameX.Foundation.Options;

var cleanArgs = (args ?? Array.Empty<string>())
    .Where(a => a != null)
    .ToArray();

var options = OptionsBuilder.Create<MyOptions>(cleanArgs);
```

> 来源：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L188-L194)

### 修复 2：排查参数处理时的内部异常

`ConvertToStandardFormat` 的外层 `catch` 会把任意非 `ArgumentException` 异常包装后重新抛出：

```csharp
catch (Exception ex)
{
    throw new ArgumentException(
        LocalizationService.GetString(LocalizationKeys.Exceptions.ProcessingError, ex.Message),
        ex);
}
```

排查步骤：

1. 捕获外层 `ArgumentException`，读取 `ex.InnerException` 拿到真实堆栈。
2. 若 `InnerException` 是 `ArgumentAlreadyException`，转到 [修复 4](#修复-4解决参数重复或环境变量与命令行冲突)。
3. 若 `InnerException` 是反射/类型转换相关（如 `InvalidCastException`、`FormatException`），通常是命令行值的字符串无法转为目标属性类型——检查 `MyOptions` 上对应字段的类型与传入值。

> 来源：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L219-L227)

### 修复 3：补齐必填参数或跳过校验

`OptionsBuilder.Create<TOptions>(args, skipValidation)` 的第二个参数控制是否跳过必需选项校验。开发/调试阶段或希望进程不退出的场景下，可以：

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.Create<MyOptions>(args, skipValidation: true);
```

若业务上不能跳过，需要确保所有标记为"必需"的选项都已传入：

- 用 `OptionsDebugger.PrintParsedOptions(opts)` 打印解析结果，对照属性是否为预期值。
- 注意环境变量会作为"隐式来源"补齐字段，所以"看起来没传命令行"也可能是环境变量在生效。

> 来源：[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L63-L67)

### 修复 4：解决参数重复或环境变量与命令行冲突

重复同名键会触发 `ArgumentAlreadyException`：

```csharp
// ArgumentAlreadyException.Throw
public static void Throw(string message)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(message, nameof(message));
    throw new ArgumentAlreadyException(message);
}
```

修复方法：

- 命令行层面：合并重复选项，确保同一逻辑键只出现一次。
- 命令行 vs 环境变量：使用 `OptionsBuilder.CreateFromArgsOnly<TOptions>(args)` 显式禁用环境变量，避免同名键被覆盖时逻辑混乱：

```csharp
using GameFrameX.Foundation.Options;

var opts = OptionsBuilder.CreateFromArgsOnly<MyOptions>(args);
```

> 来源：[ArgumentAlreadyException.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ArgumentAlreadyException.cs#L69-L73)、[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L103-L107)

### 修复 5：布尔参数解析异常

`BoolArgumentFormat.Flag`（默认）下，`AttachValueIfPresent` 会跳过被识别为布尔字面量的下一个 token，避免 `--verbose true` 这种写法把 `true` 误当作 `--verbose` 的值：

```csharp
if (BoolFormat == BoolArgumentFormat.Flag && BooleanParser.IsBooleanValue(nextArg))
{
    return currentIndex + 1;
}
```

如果你确实想让布尔值赋给字符串/集合型字段，请改用键值对写法：

```bash
# 不要这样（布尔会被跳过）
myapp --mode true

# 应该这样
myapp --mode=true
```

> 来源：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L336-L344)

### 修复 6：负数与带空格的值解析异常

`IsOptionToken` 已经对负数做了豁免：

```csharp
private static bool IsOptionToken(string value)
{
    if (string.IsNullOrEmpty(value)) return false;
    if (!value.StartsWith("-")) return false;
    return !IsNegativeNumber(value);
}
```

但当 `EnsurePrefixedKeys=true` 时，一个被误识别为"非选项"的负数 token 会被 `NormalizeKey` 加上 `--` 前缀：

```csharp
return EnsurePrefixedKeys ? "--" + arg : arg;
```

因此在传负数时推荐显式带前缀或键值对：

```bash
# 推荐：键值对不会被改写
myapp --offset=-3

# 不推荐：可能被补成 -- -3 或被错认为选项
myapp offset -3
```

含空格的字符串值由 `AppendTokenWithQuotingIfNeeded` 自动加双引号；从 `string[]` 进入解析时已按空格切分，无需额外处理；从单一字符串重建命令行（`ToCommandLineString`）时会自动加引号。

> 来源：[CommandLineArgumentConverter.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/CommandLineArgumentConverter.cs#L347-L365)

## 验证

按下面顺序验证问题已解决：

1. 用 `OptionsBuilder.CreateWithDebug<TOptions>(args)` 打印解析结果，确认每个属性的最终值。
2. 用 `OptionsBuilder.TryCreate<TOptions>(args, out var result, out var error)` 包装失败路径：失败时返回默认实例并通过 `error` 拿到消息，不会让进程崩溃。
3. 在调试器里观察 `ex.InnerException`，确认根因被识别到（特别是 `ArgumentAlreadyException` 与 `FormatException` 这类子异常）。

> 来源：[OptionsBuilder.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Options/OptionsBuilder.cs#L149-L184)
