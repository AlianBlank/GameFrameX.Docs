# How to Add and Use Localized Multi-Language Support

By following the steps on this page, you can use the `TbLocalization` configuration table + `GameApp.Localization` runtime component in GameFrameX to replace hardcoded strings in your UI with Key-based multi-language text, and read the corresponding translation at runtime based on the current language.

## Prerequisites

- The project has already imported the `GameFrameX.Localization.Runtime` package and added `using` in `HotfixLauncher.cs`.
- Localization data is provided by `Assets/Bundles/Config/local_tblocalization.json`, and the tool generates the `Hotfix.Config.Local.TbLocalization` / `Local.Localization` data table classes.
- The runtime language enum is `GameFrameX.Localization.Runtime.LocalizationCode`.

## Steps

1. **Add a new translation entry in `local_tblocalization.json`**. The `key` is the unique identifier used for lookup in code; fill in the corresponding translation for each language field that follows.

```json
{
  "key": "ui_nav_voice",
  "ChineseSimplified": "音效设置",
  "ChineseTraditional": "音效設置",
  "English": "Sound Settings",
  "Japanese": "サウンド設定",
  "Korean": "사운드 설정",
  "Thai": "ตั้งค่าเสียง",
  "Indonesian": "Pengaturan Suara",
  "French": "Paramètres audio",
  "German": "Audioeinstellungen",
  "Russian": "Настройки звука",
  "Italian": "Impostazioni audio",
  "PortuguesePortugal": "Configurações de som",
  "Spanish": "Ajustes de sonido",
  "Vietnamese": "Cài đặt âm thanh"
}
```

Source: [local_tblocalization.json](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Bundles/Config/local_tblocalization.json#L36-L52)

2. **Regenerate the data table code**. The table structure is described by `TbLocalization.cs`: each row corresponds to a `Local.Localization` object, and the constructor accepts a `Func<Task<JSONNode>> loadFunc` for asynchronously loading JSON.

Source: [TbLocalization.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Local/TbLocalization.cs#L17-L60)

3. **Load the translations into the runtime during the startup process**. In `HotfixLauncher.TranslateText()`: first call `RemoveAllRawStrings()` to clear old data, then use `GameApp.Config.GetConfig<TbLocalization>()` to get the table instance, select the corresponding language column based on the current `GameApp.Localization.Language`, and write it into the runtime.

```csharp
GameApp.Localization.RemoveAllRawStrings();
var tbLocalization = GameApp.Config.GetConfig<TbLocalization>();
tbLocalization.ForEach(localization =>
{
    if (localization.Key.IsNullOrWhiteSpace()) return;

    var value = string.Empty;
    switch (GameApp.Localization.Language)
    {
        case LocalizationCode.ChineseSimplified:
            value = localization.ChineseSimplified; break;
        case LocalizationCode.ChineseTraditionalTW:
        case LocalizationCode.ChineseTraditionalHK:
            value = localization.ChineseTraditional; break;
        case LocalizationCode.English:
            value = localization.English; break;
        case LocalizationCode.Japanese:
            value = localization.Japanese; break;
        // ... other language branches
        default:
            value = localization.English; break;
    }
    GameApp.Localization.AddRawString(localization.Key, value);
});
```

Source: [HotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L66-L120)

4. **Get text by Key in game code**. Use `GameApp.Localization.GetString(key)` to get the text for the current language; UI, prompts, and logs can all use this interface directly.

```csharp
var title = GameApp.Localization.GetString("ui_nav_voice");
Debug.Log(title);
```

5. **Switch languages**. After modifying `GameApp.Localization.Language`, call `TranslateText()` again to reload the translations for the new language; then calling `GetString(key)` will return the text in the new language.

## Common Variants

- **Adding support for a new language**: If the enum already exists in `LocalizationCode` but the `TbLocalization` table has no corresponding field, you need to add a column in `local_tblocalization.json` and add a branch in the `switch` inside `TranslateText()`.
- **Dynamic translation at runtime**: You can have the translation source come from server delivery or player customization; the `TranslateText` functional parameter `System.Func<string, string, string> translator` allows you to directly inject a custom translation function, avoiding changes to the `switch`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GetString` returns empty | The `Key` is empty or does not exist in the table | Keep the `IsNullOrWhiteSpace` validation in `TranslateText()`, and make sure the `key` is unique in the JSON |
| Old text still shown after switching languages | `TranslateText` was not called again | Call the loading process once more after changing `Language` |
| A new language branch returns an empty string | The `switch` does not cover that `LocalizationCode` | Fall back to `English` in the `default` branch or complete the branches |
| New fields do not appear after modifying the JSON | The `TbLocalization` / `Localization` data classes were not regenerated | Re-run the configuration table generation tool |

## Background

`TbLocalization` is a `BaseDataTable<Local.Localization>` that receives a JSON loading delegate on construction; `LoadAsync` clears the old data and then deserializes entries one by one. `TranslateText` accepts a `(original text, target language) => translated result` function, allowing the translation logic to be delegated to external sources (such as online translation or human translation). Currently, `HotfixLauncher.TranslateText` uses the most straightforward approach: "reading from the table based on the language enum".
