# 일반적인 문제

이 문서는 GlobalConfig 컴포넌트 사용 과정에서 발생할 수 있는 일반적인 문제 및 솔루션을汇总합니다.

## 개요

GlobalConfigComponent는 GameFrameX 프레임워크의 전역 설정 관리 컴포넌트로, 게임 애플리케이션의 전역 설정 정보(앱 버전 확인 주소, 리소스 버전 확인 주소, 서버 주소 등)를 관리하는 데 사용됩니다. 이 컴포넌트는 Unity 컴포넌트 형태로 구현되어 있으며, 유연하게 구성하고 사용할 수 있습니다.

> 컴포넌트의 상세 기능 설명은 [GlobalConfig 컴포넌트 소개](./1-overview.1-introduction)를 참고하세요.
> 컴포넌트의 완전한 API는 [GlobalConfigComponent](./4-core-component.1-global-config-component)를 참고하세요.

## 설치 및 설정

### Q1: GlobalConfig 컴포넌트를 어떻게 설치하나요?

GlobalConfig 컴포넌트는 다음 방법으로 설치할 수 있습니다:

1. **manifest.json을 통해 설치**: 프로젝트의 `manifest.json` 파일에 의존성 추가:
   ```json
   {"com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git"}
   ```

2. **Unity Package Manager를 통해 설치**: Unity에서 `Window > Package Manager`를 선택한 후 `+`를 클릭하여 Git URL 추가:
   ```
   https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git
   ```

3. **수동 설치**: 저장소를 직접 다운로드하여 Unity 프로젝트의 `Packages` 디렉토리에 배치합니다.

> 상세한 설치 단계는 [설치 방식](./2-installation.1-install-methods)을 참고하세요.

### Q2: 설치 후 "Assembly has reference to missing assembly" 오류가 발생합니다?

이는 GlobalConfig 컴포넌트가 다음 패키지에 의존하기 때문입니다:
- `com.gameframex.unity` (버전 1.1.1)
- `com.gameframex.unity.web` (버전 1.1.2)

**솔루션**: 이러한 의존 패키지가 올바르게 설치되었는지 확인합니다. `manifest.json`에 완전한 의존성을 추가할 수 있습니다:

```json
{
  "dependencies": {
    "com.gameframex.unity": "1.1.1",
    "com.gameframex.unity.globalconfig": "https://github.com/GameFrameX/com.gameframex.unity.globalconfig.git",
    "com.gameframex.unity.web": "1.1.2"
  }
}
```

### Q3: Unity 버전 호환성은 어떻게 되나요?

package.json에 따르면, 컴포넌트가 지원하는最低 Unity 버전은 **2017.1**입니다. 더 낮은 버전의 Unity을 사용하면 호환성 문제가 발생할 수 있습니다.

## 컴포넌트 사용

### Q4: GlobalConfigComponent를 Scene에 어떻게 추가하나요?

1. Unity 에디터에서 GameObject를 생성하거나 선택합니다
2. Inspector 패널에서 **Add Component** 버튼을 클릭합니다
3. **Game Framework > Global Config**를 검색하여 선택합니다
4. 컴포넌트가 선택한 GameObject에 추가됩니다

> 상세한 추가 단계는 [Scene에 추가](./3-getting-started.1-add-to-scene)를 참고하세요.

### Q5: Scene에 여러 GlobalConfigComponent를 추가할 수 있나요?

**권장하지 않음**. 컴포넌트는 `[DisallowMultipleComponent]` 특성을 사용하며, 이는同一 GameObject에 인스턴스를 하나만 추가할 수 있도록 제한합니다. 기술적으로 컴포넌트를 다른 GameObject에 추가할 수 있지만, 프레임워크가 싱글톤 모드로 설계되었으므로 Scene에 전역 설정 컴포넌트를 하나만 유지하는 것이 권장됩니다.

### Q6: 코드에서 GlobalConfigComponent에 어떻게 접근하나요?

컴포넌트가 `IsAutoRegister = false`를 사용하므로, 컴포넌트가 자동으로 등록되지 않습니다. 일반적인 접근 방식은 Scene에서 찾거나 참조를 통해 접근하는 것입니다:

```csharp
// FindObjectOfType을 통해 찾기
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
if (globalConfig != null)
{
    string appVersionUrl = globalConfig.CheckAppVersionUrl;
    string resourceVersionUrl = globalConfig.CheckResourceVersionUrl;
}
```

> 상세한 코드 접근 방식은 [코드 접근](./3-getting-started.3-code-access)을 참고하세요.

### Q7: 코드를 통해 동적으로 설정을 어떻게 설정하나요?

런타임에서 코드를 통해 각 속성을 설정할 수 있습니다:

```csharp
var globalConfig = FindObjectOfType<GlobalConfigComponent>();

// 다양한 URL 설정
globalConfig.CheckAppVersionUrl = "https://example.com/check-app-version";
globalConfig.CheckResourceVersionUrl = "https://example.com/check-resource-version";
globalConfig.HostServerUrl = "https://example.com/server";

// 추가 콘텐츠 설정
globalConfig.Content = "{\"key\": \"value\"}";

// 전역 설정 정보 설정
ResponseGlobalInfo globalInfo = new ResponseGlobalInfo
{
    // 설정 속성
};
globalConfig.SetGlobalConfig(globalInfo);
```

## 속성 구성

### Q8: 각 속성의 역할은 무엇인가요?

| 속성 | 설명 |
|------|------|
| **호스트 서버 주소 (HostServerUrl)** | 백엔드 서버 주소, 게임 서버 연결에 사용 |
| **App버전 확인 주소 (CheckAppVersionUrl)** | 애플리케이션 새 버전 확인 URL 주소 |
| **리소스 버전 확인 주소 (CheckResourceVersionUrl)** | 게임 리소스 업데이트 확인 URL 주소 |
| **보충 어셈블리 목록 (AOTCodeList)** | AOT 컴파일 시 보충이 필요한 어셈블리 목록(JSON 형식) |
| **추가 콘텐츠 (Content)** | 기타 추가 설정 콘텐츠 |
| **보충 메타데이터 목록 (AOTCodeLists)** | AOT 보충 메타데이터 목록 |

> 상세한 속성 구성 설명은 [속성 구성](./3-getting-started.2-configure-properties)을 참고하세요.

### Q9: AOTCodeList와 AOTCodeLists의 차이점은 무엇인가요?

- **AOTCodeList** (문자열 유형): Inspector에서 JSON 문자열 형식으로 AOT 코드 목록 입력용
- **AOTCodeLists** (목록 유형): 파싱된 AOT 코드 목록, 런타임에서 사용

AOTCodeList를 설정하면 시스템이 자동으로 JSON을 파싱하여 AOTCodeLists에 채웁니다:

```csharp
// JSON 형식의 AOT 코드 목록 설정
globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\", \"Assembly3\"]";

// 자동 파싱, AOTCodeLists에서 파싱 결과 획득 가능
List<string> aotCodeLists = globalConfig.AOTCodeLists;
```

## AOT 구성 관련

### Q10: AOT 코드 목록이란 무엇이며 왜 구성해야 하나요?

AOT(Ahead-of-Time) 컴파일은 .NET의 컴파일 모드로, IL2CPP 등 플랫폼에 사용됩니다. 일부 제네릭 유형과 리플렉션 코드는 AOT 컴파일 시 정확하게 생성되지 않을 수 있으며, AOT 코드 목록을 통해 추가 처리할 어셈블리를 지정해야 합니다.

> 상세한 AOT 구성 설명은 [AOT 코드 목록 구성](./7-aot-configuration.1-aot-code-list)을 참고하세요.

### Q11: AOTCodeList 설정 시 JSON 파싱 오류가 발생합니다?

AOTCodeList 설정 시 파싱 오류가 발생하면 가능한 원인 및 솔루션:

1. **JSON 형식 오류**: JSON 형식이 정확한지 확인합니다
   ```csharp
   // 잘못된 예시
   globalConfig.AOTCodeList = "Assembly1, Assembly2"; // 잘못된 형식

   // 올바른 예시
   globalConfig.AOTCodeList = "[\"Assembly1\", \"Assembly2\"]"; // 올바른 JSON 배열 형식
   ```

2. **특수 문자 이스케이프**: 문자열에 특수 문자가 포함된 경우 정확한 이스케이프 처리되었는지 확인합니다

### Q12: AOT 코드 목록이 비어 있으면 어떤 문제가 발생하나요?

AOT 코드 목록이 비어 있으면, 일부 제네릭 또는 리플렉션 기능이 IL2CPP 플랫폼에서 정상 작동하지 않을 수 있습니다. 구체적인 표현:
- 제네릭 유형 직렬화 실패
- 리플렉션으로 유형 획득 실패
- 일부 동적 코드 실행 예외

## 에디터 관련

### Q13: Play 모드에서 속성을 편집할 수 없나요?

이는 정상 동작입니다. Inspector의 속성은 **Play 모드**에서 읽기 전용입니다. 이는 런타임 구성이 의도치 않게 수정되는 것을 방지하기 위한 것입니다.

```csharp
// GlobalConfigComponentInspector.cs의 구현
EditorGUI.BeginDisabledGroup(EditorApplication.isPlayingOrWillChangePlaymode & Application.isPlaying);
{
    // 속성 편집 영역
}
EditorGUI.EndDisabledGroup();
```

### Q14: 원본 데이터 (OriginalData)가 읽기 전용인가요?

네, 원본 데이터 속성은 Inspector에서 읽기 전용입니다. 이 속성은 서버에서 가져온 원본 설정 데이터를 저장하는 데 사용되며, 일반적으로 런타임에서 코드를 통해 설정됩니다:

```csharp
// 원본 데이터 설정
globalConfig.SetOriginalData(jsonString);

// 원본 데이터 읽기
string originalData = globalConfig.OriginalData;
```

## 런타임 관련

### Q15: 컴포넌트의 Awake 메서드에 특별한 처리가 있나요?

컴포넌트는 `Awake` 메서드를 재정의하며 `IsAutoRegister`를 `false`로 설정합니다:

```csharp
protected override void Awake()
{
    IsAutoRegister = false;
    base.Awake();
}
```

이는 컴포넌트가 프레임워크의 컴포넌트 관리 시스템에 자동으로 등록되지 않으며, 개발자가 수동으로 관리하거나 다른 방식으로 접근해야 함을 의미합니다.

### Q16: 서버에서 전역 설정을 가져와서 설정하려면 어떻게 하나요?

전형적인 워크플로:

1. 구성된 URL을 사용하여 서버에 요청을 보냅니다
2. 서버가 설정 데이터(JSON 형식)를 반환합니다
3. 응답 데이터를 ResponseGlobalInfo 객체로 파싱합니다
4. SetGlobalConfig를 호출하여 전역 설정을 설정합니다

```csharp
// 의사코드 예시
var globalConfig = FindObjectOfType<GlobalConfigComponent>();
string url = globalConfig.HostServerUrl;

// 설정 가져오기 위한 네트워크 요청 보내기
// ...
ResponseGlobalInfo response = ParseServerResponse(data);
globalConfig.SetGlobalConfig(response);

// 설정 정보 접근
ResponseGlobalInfo info = globalConfig.GlobalInfo;
```

## 의존성 및 버전

### Q17: GlobalConfig 컴포넌트는 다른 어떤 컴포넌트에 의존하나요?

package.json에 따르면, 컴포넌트는 다음 패키지에 의존합니다:
- `com.gameframex.unity` (>= 1.1.1) - GameFrameX 핵심 프레임워크
- `com.gameframex.unity.web` (>= 1.1.2) - Web 네트워크 모듈

### Q18: 설치된 컴포넌트 버전을 어떻게 확인하나요?

Unity의 Package Manager에서 설치된 패키지 버전을 확인할 수 있으며, `Packages/manifest.json` 파일에서 의존 버전 선언을 확인할 수도 있습니다.

## 장애排查

### Q19: 일반적인 문제排查 단계

1. **의존성 확인**: 모든 의존 패키지가 올바르게 설치되었는지 확인합니다
2. **Unity 버전 확인**: Unity 2017.1 이상을 사용하고 있는지 확인합니다
3. **컴포넌트 추가 확인**: GlobalConfigComponent가 올바르게 Scene에 추가되었는지 확인합니다
4. **속성 구성 확인**: 필요한 URL 속성이 구성되었는지 확인합니다
5. **로그 확인**: Unity 콘솔에 오류 또는 경고 정보가 있는지 확인합니다

### Q20: 런타임에 GlobalConfigComponent를 찾을 수 없어요?

`FindObjectOfType<GlobalConfigComponent>()`가 null을 반환하면 가능한 원인:
1. 컴포넌트가 어떤 GameObject에도 추가되지 않음
2. 컴포넌트가 비활성화된 GameObject에 추가됨
3. Scene이 올바르게 로드되지 않음

**솔루션**:
- 컴포넌트가 Scene의 활성 GameObject에 추가되었는지 확인합니다
- GlobalConfig가 포함된 Scene이 로드되었는지 확인합니다

## 설정 파일이 비어 있거나 로드되지 않음

**원인**: Inspector에서 GlobalConfigComponent를 구성하지 않았거나 설정 파일 경로가 올바르지 않습니다.

**솔루션**: Unity 에디터에서 GlobalConfigComponent가 마운트된 GameObject를 선택하고, Inspector 패널에서 설정 항목이 올바르게 입력되었는지 확인합니다.

## 버전 확인 URL에 접근할 수 없음

**원인**: 서버 주소가 잘못 구성되었거나 네트워크에 접근할 수 없습니다.

**솔루션**: `AppVersionCheckUrl`과 `ResourceVersionCheckUrl`이 유효한 HTTP/HTTPS 주소인지 확인하며, 장치 네트워크 연결을 확인합니다.
