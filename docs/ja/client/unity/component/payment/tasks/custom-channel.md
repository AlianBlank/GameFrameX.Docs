# カスタム決済チャネルの実装

`BasePaymentManager` を継承してすべての抽象メンバーを実装し、その後、実装クラスの完全型名を `PaymentComponent` の対応プラットフォームのシリアライズフィールドに入力してください。ゲーム起動時にコンポーネントがリフレクションを介して自動的にロードし、あなたのチャネル実装へ切り替わります。ビジネス層の呼び出しコードを変更する必要はありません。

## 前提条件

- `com.gameframex.unity.payment` パッケージがインストール済みであり、シーンに `GameFrameX/Payment` コンポーネント(`PaymentComponent`、`RequireComponent` により `GameFrameXPaymentCroppingHelper` が強制的に付属します)がアタッチされていること。
- 実装クラスが含まれるアセンブリが Unity のコンパイル対象であること(つまり `Utility.Assembly.GetType` で解決できること)。

## 操作手順

### 1. チャネルマネージャークラスを作成する

新しいクラスを作成して `GameFrameX.Payment.Runtime.BasePaymentManager` を継承します(この基底クラスは `GameFrameworkModule` と `IPaymentManager` のイベント定義をすでに実装しており、イベント発火用メソッドも用意されています):

```csharp
public abstract class BasePaymentManager : GameFrameworkModule, IPaymentManager
{
    public event EventHandler<PaymentEventArgs> OnPurchaseSuccess;
    public event EventHandler<PaymentEventArgs> OnPurchaseFailed;
    public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;
    public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;
    // ...
}
```

出典: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L14-L34)

サブクラスは `public class MyPaymentManager : BasePaymentManager` のような形になります(クラス名と名前空間は自由に設定できますが、以降の手順で完全型名を使用します)。

`override` が必要な抽象メンバー(すべて実際のソースコードのシグネチャからのもの):

| メンバー | 実際のシグネチャ | 説明 |
|------|----------|------|
| `Init` | `void Init(bool isDebug = false, bool isClientVerify = false)` | チャネル SDK を初期化。`isDebug` はサンドボックスモード、`isClientVerify` はクライアント側の注文検証を行うかどうか |
| `IsReady` | `bool IsReady()` | チャネルが準備完了かどうか |
| `SetPredefinedProductIds` | `void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds)` | 事前定義商品 ID のプリロード。`Init` の前に呼び出す必要がある |
| `QueryPurchases` | `void QueryPurchases(PaymentProductType productType)` | 購入履歴を照会。結果は `OnQueryPurchasesResult` でコールバック |
| `ConsumePurchase` | `void ConsumePurchase(string purchaseToken)` | 購入を消費。結果は `OnConsumePurchaseResult` でコールバック |
| `BuyInApp` | `void BuyInApp(string productId, string orderId, string offerToken = "", string customData = "")` | 旧インターフェース。`[Obsolete]` が付与済みだが、引き続き override が必要 |
| `BuySubs` | `void BuySubs(string productId, string orderId, string offerToken = "", string customData = "")` | 旧インターフェース。`[Obsolete]` が付与済みだが、引き続き override が必要 |
| `Buy` | `void Buy(string productId, PaymentProductType productType, string orderId, string offerToken = "", string customData = "")` | 旧インターフェース。`[Obsolete]` が付与済みだが、引き続き override が必要 |
| `Buy` | `void Buy(PurchaseParams purchaseParams)` | 推奨エントリー。購入パラメーターにはチャネルのサブクラスを渡せる |

出典: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L42-L112)

### 2. 実装内でイベントを発火する

チャネル SDK のコールバック後、基底クラスが提供する protected メソッドを呼び出してビジネス層に通知します。イベントフィールドに直接アクセスしないでください:

```csharp
protected void RaisePurchaseSuccess(PaymentEventArgs e)
{
    OnPurchaseSuccess?.Invoke(this, e);
}

protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}

protected void RaiseQueryPurchasesResult(PaymentEventArgs e)
{
    OnQueryPurchasesResult?.Invoke(this, e);
}

protected void RaiseConsumePurchaseResult(PaymentEventArgs e)
{
    OnConsumePurchaseResult?.Invoke(this, e);
}
```

出典: [BasePaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/BasePaymentManager.cs#L41-L59)

### 3. (任意)チャネル固有の購入パラメーターを拡張する

`Buy(PurchaseParams)` のパラメーターは抽象基底クラスであり、公式コメントには「各チャネルは継承して独自フィールドを拡張できる」と明記されています:

```csharp
public abstract class PurchaseParams
{
    public string ProductId { get; set; }
    public string OrderId { get; set; }
    public PaymentProductType ProductType { get; set; }

    protected PurchaseParams(string productId, string orderId, PaymentProductType productType)
    {
        ProductId = productId;
        OrderId = orderId;
        ProductType = productType;
    }
}
```

出典: [PurchaseParams.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PurchaseParams.cs#L9-L35)

チャネル向けにサブクラスを派生させ、チャネル固有のパラメーター(チャネル側の token、チャネルのユーザー ID など)をプロパティとして追加します。`MyPaymentManager.Buy(PurchaseParams)` 内でダウンキャストして読み取ります。

### 4. 実装クラスを PaymentComponent に組み込む

`PaymentComponent` はプラットフォームごとのシリアライズフィールドによって、どの実装クラスをロードするかを決定します。Inspector で該当プラットフォームのフィールドを自分の完全型名に置き換えるだけです。フレームワークのデフォルト値は以下の通りです:

```csharp
[SerializeField] private string m_componentAndroidType = "GameFrameX.Payment.Google.Runtime.GooglePaymentManager";
[SerializeField] private string m_componentIOSType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
[SerializeField] private string m_componentWebGLType = "GameFrameX.Payment.WebGL.Runtime.WebGLPaymentManager";
[SerializeField] private string m_componentPCType = "GameFrameX.Payment.PC.Runtime.PCPaymentManager";
[SerializeField] private string m_componentMacType = "GameFrameX.Payment.Apple.Runtime.ApplePaymentManager";
```

出典: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L24-L28)

プラットフォームマッピングルール(`PaymentComponent.Awake` の条件付きコンパイルによるもの):

| コンパイルマクロ | 使用されるフィールド | デフォルト実装 |
|--------|-----------|----------|
| `UNITY_ANDROID` | `m_componentAndroidType` | `GooglePaymentManager` |
| `UNITY_IOS` | `m_componentIOSType` | `ApplePaymentManager` |
| `UNITY_WEBGL` | `m_componentWebGLType` | `WebGLPaymentManager` |
| `UNITY_STANDALONE_WIN` / `UNITY_STANDALONE_LINUX` | `m_componentPCType` | `PCPaymentManager` |
| `UNITY_STANDALONE_OSX` | `m_componentMacType` | `ApplePaymentManager` |
| その他のプラットフォーム | — | `DefaultPaymentManager` |

出典: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L71-L88)

ロードフロー:コンポーネントは `Awake` 内で `Utility.Assembly.GetType(componentType)` を呼び出して型を解決し、その後 `GameFrameworkEntry.GetModule<IPaymentManager>()` でインスタンスを取得します。解決に失敗した場合やモジュールが無効な場合は `Log.Fatal("Pay Manager is invalid.")` が出力されます。

### 5. 組み込みを検証する

ビジネス層では通常通り呼び出すだけで、具体的なチャネルを意識する必要はありません:

```csharp
// イベントを購読(PaymentComponent はイベントを下層のマネージャーへ転送済み)
paymentComponent.OnPurchaseSuccess += (sender, e) => { /* アイテム付与 */ };
paymentComponent.Init(isDebug: true, isClientVerify: false);
paymentComponent.Buy(myChannelPurchaseParams);
```

`PaymentComponent.Init` のシグネチャは `public void Init(bool isDebug = false, bool isClientVerify = true)` で、内部でそのまま `IPaymentManager.Init` に転送されます。

出典: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L101-L105)

## よくあるバリエーション

- **特定のプラットフォームのみ置き換える**:該当プラットフォームのフィールドのみを変更し、その他のプラットフォームは公式チャネルパッケージをそのまま使うことで、プラットフォームごとの混在利用を実現します。
- **テストスタブチャネル**:すべてのプラットフォームフィールドに同じ空の/モックの `BasePaymentManager` サブクラスを入力すれば、Editor や未対応のプラットフォームでも使用できます(そうしない場合、リストにないプラットフォームは `DefaultPaymentManager` にフォールバックします)。
- **チャネルが追加の購入パラメーターを必要とする**:チャネル向けに `PurchaseParams` サブクラスを実装し、ビジネス層はそのサブクラスのコンストラクター引数のみに依存させます。

## よくあるエラー

| 症状/現象 | 原因 | 修正 |
|-----------|------|------|
| 起動直後に `Log.Fatal("Pay Manager is invalid.")` | 型名の誤り、名前空間の不一致、またはクラスがアセンブリにコンパイルされておらず、`Utility.Assembly.GetType` の解決に失敗 | Inspector に入力した値が「名前空間.クラス名」の完全な形式であること、およびスクリプトにコンパイルエラーがないことを確認 |
| `Buy` が無反応でエラーも出ない | `PaymentComponent` が空パラメーターに対して事前検証を行う(例:`"Product ID is null or empty."`、`"Order ID is null or empty."`、`"Purchase token is null or empty."`) | `ProductId`/`OrderId`/`purchaseToken` が空でないことを確認。[PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L143-L230) の検証ロジックと照合 |
| `SetPredefinedProductIds` が有効にならない | インターフェースのコメントに「このメソッドは Initialize() の前に呼び出す必要がある」と明記されている | `Init` を呼び出す前に事前定義商品 ID を設定する |
| コンパイル時に `Obsolete` 警告が出る | `BuyInApp`/`BuySubs`/旧 `Buy` オーバーロードを使用している(いずれも `[Obsolete("请使用 Buy(PurchaseParams) 替代")]` が付与されている) | `PurchaseParams` サブクラスを構築して `Buy(PurchaseParams)` を呼び出す形に変更 |
| イベントが一度も発火しない | チャネル実装内でイベントに直接代入している、または基底クラスの `Raise*` メソッドを呼び出していない | `RaisePurchaseSuccess` などの protected メソッド経由で統一的にイベントを発火する |

## 背景

フレームワークは「コンポーネント + リフレクション」によってチャネルを疎結合にしています:`PaymentComponent` は `IPaymentManager` インターフェースのみに依存し、実行時にプラットフォームマクロに応じて実装クラス名の文字列を選択し、`Utility.Assembly.GetType` によってリフレクションでインスタンス化します。これにより、ビジネスコードは具体的なチャネル(公式の `GameFrameX.Payment.Google` などのチャネルパッケージも同様)から完全に分離されています。決済モジュールの全体構造については、『決済モジュールの紹介』を参照してください。
