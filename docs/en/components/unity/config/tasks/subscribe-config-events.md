# How to Subscribe to Config Loading Events (Success / Failure / Hot Update)

Subscribe to the three events `LoadConfigSuccessEventArgs`, `LoadConfigFailureEventArgs`, and `LoadConfigUpdateEventArgs` through GameFrameX's global event manager to receive callbacks when config loading succeeds, fails, or when hot update progress changes, without directly depending on `ConfigComponent`.

## Prerequisites

- The GameFrameX framework has been initialized, and the config manager can be obtained via `GameFrameworkEntry.GetModule<IConfigManager>()`.
- The three `EventArgs` classes under the `GameFrameX.Config.Runtime` namespace can be found in the project (provided by the framework, no need to create them yourself).

## Event Overview

| Event Type | EventId Source | Key Fields | Trigger Timing |
|----------|--------------|----------|----------|
| `LoadConfigSuccessEventArgs` | `typeof(LoadConfigSuccessEventArgs).FullName` | `ConfigAssetName`, `Duration`, `UserData` | A single config loading completed successfully |
| `LoadConfigFailureEventArgs` | `typeof(LoadConfigFailureEventArgs).FullName` | `ConfigAssetName`, `ErrorMessage`, `UserData` | Config loading threw an exception or failed |
| `LoadConfigUpdateEventArgs` | `typeof(LoadConfigUpdateEventArgs).FullName` | `ConfigAssetName`, `Progress`(0~1), `UserData` | Config loading/hot update progress changed |

The event IDs and field definitions all come from the EventArgs classes in the source code. Source: [Runtime/EventArgs/LoadConfigSuccessEventArgs.cs](/Runtime/EventArgs/LoadConfigSuccessEventArgs.cs#L42-L137), [Runtime/EventArgs/LoadConfigFailureEventArgs.cs](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L43-L137), [Runtime/EventArgs/LoadConfigUpdateEventArgs.cs](/Runtime/EventArgs/LoadConfigUpdateEventArgs.cs#L43-L137).

## Operation Steps

1. Obtain the global event subscriber (choose any entry provided in the GameFrameX project; commonly `GameFrameXEntry.GetModule<IEventManager>()` or the wrapped `GameEntry.Event`; the subscription API is `Subscribe(eventId, handler)`).
2. Call `Subscribe` during the initialization phase to register callbacks to the corresponding `EventId` (use the `EventId` static field of the `EventArgs` class directly to avoid hardcoding strings).
3. Cast `GameEventArgs` to the specific `LoadConfigXxxEventArgs` in the callback and read the fields.
4. The framework internally uses `ReferencePool.Acquire` to create event instances and dispatches them via `GameEntry.Event.Fire(this, EventId, e)`. After the subscribed callback finishes executing, the framework automatically calls `Clear()` and recycles the instance. Do not hold references for a long time in the callback. Source: [Runtime/EventArgs/LoadConfigSuccessEventArgs.cs](/Runtime/EventArgs/LoadConfigSuccessEventArgs.cs#L116-L136)
5. Call the corresponding `Unsubscribe(eventId, handler)` when no longer needed, otherwise it will cause memory leaks or duplicate triggers.

Minimal subscription example (pseudo-code, the actual `IEventManager` entry depends on the project's specific wrapper):

```csharp
using GameFrameX.Config.Runtime;
using GameFrameX.Event.Runtime;
using GameFrameX.Runtime;

var eventManager = GameFrameXEntry.GetModule<IEventManager>();

// Success
eventManager.Subscribe(LoadConfigSuccessEventArgs.EventId, OnLoadConfigSuccess);
// Failure
eventManager.Subscribe(LoadConfigFailureEventArgs.EventId, OnLoadConfigFailure);
// Progress / hot update
eventManager.Subscribe(LoadConfigUpdateEventArgs.EventId, OnLoadConfigUpdate);
```

```csharp
private void OnLoadConfigSuccess(object sender, GameEventArgs e)
{
    var args = (LoadConfigSuccessEventArgs)e;
    // args.ConfigAssetName / args.Duration / args.UserData
}

private void OnLoadConfigFailure(object sender, GameEventArgs e)
{
    var args = (LoadConfigFailureEventArgs)e;
    // args.ErrorMessage contains the failure reason
}

private void OnLoadConfigUpdate(object sender, GameEventArgs e)
{
    var args = (LoadConfigUpdateEventArgs)e;
    // args.Progress ranges from 0.0 ~ 1.0
}
```

Unsubscribe:

```csharp
eventManager.Unsubscribe(LoadConfigSuccessEventArgs.EventId, OnLoadConfigSuccess);
eventManager.Unsubscribe(LoadConfigFailureEventArgs.EventId, OnLoadConfigFailure);
eventManager.Unsubscribe(LoadConfigUpdateEventArgs.EventId, OnLoadConfigUpdate);
```

## Common Variations

- **Filter by `ConfigAssetName`**: The success/failure/progress events all carry `ConfigAssetName`. You can use a `switch` statement in the callback to only process the config tables you care about.
- **Carry business parameters**: The `userData` passed in when loading config will be passed back as-is to the `UserData` field, which can be used to associate request context.
- **Hot update monitoring**: Connect the `Progress` of `LoadConfigUpdateEventArgs` to a progress bar UI; after `Progress` reaches 1.0, a `LoadConfigSuccessEventArgs` with the same `ConfigAssetName` typically follows.

## Common Errors

- **Manually `new` event objects**: EventArgs must be created using their respective `Create(...)` static methods. The framework internally uses `ReferencePool.Acquire`; calling `new` directly will bypass the object pool. Source: [Runtime/EventArgs/LoadConfigFailureEventArgs.cs](/Runtime/EventArgs/LoadConfigFailureEventArgs.cs#L116-L123)
- **Holding event instances for a long time in callbacks**: After the event callback ends, it will be `Clear()`-ed and recycled to the reference pool. Business code should only use `args` within the callback scope.
- **Hardcoding EventId strings**: Use the `LoadConfigXxxEventArgs.EventId` static field, which won't break when the class is renamed.
- **Duplicate subscription of the same callback**: Will trigger multiple times; when calling `Unsubscribe`, ensure the delegate reference passed in is consistent with the one used during subscription.

## Background (Optional)

`ConfigComponent` is only responsible for reading and writing cache, and does not directly expose events. During config loading/hot update, the underlying module dispatches these three types of `EventArgs` through the global `IEventManager`. Subscribers can distinguish them by `EventId`.
