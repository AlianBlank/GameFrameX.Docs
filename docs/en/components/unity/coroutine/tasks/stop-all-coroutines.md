# How to Stop All Coroutines at Once

Call `CoroutineComponent.StopAllCoroutines()` to stop all running coroutines on the current component at once and clear the component's internal tracking dictionary.

## Prerequisites

- The `CoroutineComponent` has been auto-registered via `GameFrameXAutoComponent(-6500)` or attached to a scene object (can be added via the editor menu `GameObject → GameFrameX → Coroutine`).
- When starting coroutines, use `CoroutineComponent.StartCoroutine(IEnumerator)` instead of `MonoBehaviour.StartCoroutine`, so they can be properly tracked by the component. See [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33).

## Steps

1. Get a reference to `CoroutineComponent` in the scene (the framework auto-registers it by default; you can retrieve it directly via `GameEntry` or find it in the scene).

   ```csharp
   var coroutineComponent = GameEntry.GetComponent<CoroutineComponent>();
   ```

2. At the point where you need to clear all coroutines (e.g., switching scenes, exiting a level, restarting the game, etc.), call:

   ```csharp
   coroutineComponent.StopAllCoroutines();
   ```

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

3. No additional cleanup is needed after the call — internally the method will:
   - Iterate through `m_CoroutineMap` and call `base.StopCoroutine` for each tracked coroutine to stop them;
   - Call `m_CoroutineMap.Clear()` to clear the tracking dictionary;
   - Call `base.StopAllCoroutines()` as a fallback to clean up any untracked coroutines.

## Common Variants

- **Stop a single coroutine**: Use `StopCoroutine(IEnumerator)` or `StopCoroutine(UnityEngine.Coroutine)`, provided the same instance is passed as was used in `StartCoroutine`. Note that `IEnumerator` is used as a dictionary key with reference equality. Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L67)
- **Stop all coroutines uniformly during scene transitions**: Call `StopAllCoroutines()` in the `UnloadScene` / `LoadScene` callback to clear all coroutines started by the component at once.

## Common Errors

| Symptom | Cause | Fix |
|---------|-------|-----|
| Some coroutines are still running after calling `StopAllCoroutines()` | The coroutines were started via another `MonoBehaviour`'s `StartCoroutine` and were not added to the `m_CoroutineMap` tracking dictionary | Always start coroutines via `CoroutineComponent.StartCoroutine` |
| `StopCoroutine(IEnumerator)` doesn't take effect | The `IEnumerator` passed in is not the same reference object as the one used in `StartCoroutine` | Keep the `IEnumerator` variable used at startup and pass the same reference when stopping |
| Coroutines reappear after switching scenes | `StopAllCoroutines()` only acts on the current component instance, and the call was made after the target coroutine had already been started | Call it at the very beginning of the scene-switching entry point, not in `OnDestroy` |

## Verification

After calling `StopAllCoroutines()`, start a new coroutine and immediately call it again to confirm:

1. `m_CoroutineMap` has been cleared (can be verified via unit test samples).
2. The `callback` that originally waited for frame end (`WaitForEndOfFrameFinish`) will no longer be triggered. Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L97-L104)
3. Since the `Coroutine` module depends on the Unity runtime (MonoBehaviour, StartCoroutine), it cannot be tested directly in a pure NUnit environment; coroutine-related integration tests should be written as Unity PlayMode tests. See [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Tests/UnitTests.cs).
