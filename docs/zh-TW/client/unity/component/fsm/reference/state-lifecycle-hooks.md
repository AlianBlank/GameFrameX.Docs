# 狀態生命週期鉤子參考

本頁面收錄了 `FsmState<T>` 所提供的所有生命週期回呼方法，包含簽章、觸發時機與常見用途。所有鉤子皆定義於 `Runtime/Fsm/FsmState.cs`,預設為空方法，可依需求進行覆寫。

## 鉤子快速參考表

| 鉤子 | 簽章 | 觸發時機 | 常見用途 |
|------|------|----------|----------|
| `OnInit` | `protected internal virtual void OnInit(IFsm<T> fsm)` | 狀態首次加入狀態機時呼叫一次 | 一次性資源準備、資料快取、事件訂閱 |
| `OnEnter` | `protected internal virtual void OnEnter(IFsm<T> fsm)` | 進入該狀態時呼叫 | 播放進入動畫、重設計時器、記錄日誌 |
| `OnUpdate` | `protected internal virtual void OnUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | 狀態機輪詢時呼叫(每幀) | 檢查轉換條件、累加時間 |
| `OnFixedUpdate` | `protected internal virtual void OnFixedUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | 狀態機固定輪詢時呼叫 | 物理相關邏輯 |
| `OnLeave` | `protected internal virtual void OnLeave(IFsm<T> fsm, bool isShutdown)` | 離開該狀態時呼叫，關閉時 `isShutdown` 為 `true` | 清理暫時狀態、還原全域設定 |
| `OnDestroy` | `protected internal virtual void OnDestroy(IFsm<T> fsm)` | 狀態從狀態機中移除或狀態機被銷毀時呼叫 | 釋放於 `OnInit` 中持有的資源 |

## 觸發順序

正常轉換流程的呼叫順序為 `OnLeave(舊狀態, false)` → `OnEnter(新狀態)`。首次加入狀態時會額外觸發一次 `OnInit`。當狀態機被銷毀或狀態被移除時，則以 `OnLeave(..., true)` → `OnDestroy` 的順序觸發。

```csharp
// 原始碼節錄:Runtime/Fsm/Fsm.cs 中狀態轉換的典型流程
m_CurrentState.OnLeave(this, false);   // 離開舊狀態
m_CurrentState = state;
m_CurrentState.OnEnter(this);          // 進入新狀態
```

來源:[Runtime/Fsm/Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L725-L727)

```csharp
// 原始碼節錄:Runtime/Fsm/Fsm.cs 中首次加入狀態時的初始化
m_States.Add(stateType, state);
state.OnInit(fsm);
```

來源:[Runtime/Fsm/Fsm.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L220-L222)

## 時間參數

`OnUpdate` 與 `OnFixedUpdate` 會接收兩個時間值。

| 參數 | 型別 | 意義 |
|------|------|------|
| `elapseSeconds` | `float` | 邏輯經過時間(以秒為單位)，受時間縮放影響 |
| `realElapseSeconds` | `float` | 實際經過時間(以秒為單位)，不受時間縮放影響 |

在暫停/慢動作期間仍須依實際時間推進的邏輯(例如 UI 倒數計時)，應使用 `realElapseSeconds`。

## 狀態轉換

您可以在鉤子內部透過下列方法請求轉換至其他狀態。

```csharp
// 泛型版本:執行階段型別安全
public void ChangeToState<TState>(IFsm<T> fsm) where TState : FsmState<T>

// 型別版本:stateType 必須繼承自 FsmState<T>
protected void ChangeState(IFsm<T> fsm, Type stateType)
```

呼叫 `ChangeState` 時，若 `fsm` 已失效，將擲出 `GameFrameworkException("FSM is invalid.")`;若 `stateType` 為 `null`,將擲出 `"State type is invalid."`;若型別不相符，則會擲出 `"State type '{0}' is invalid."`。

來源:[Runtime/Fsm/FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L163)

## 最小範例

```csharp
using GameFrameX.Fsm.Runtime;

public sealed class IdleState : FsmState<Player>
{
    protected internal override void OnEnter(IFsm<Player> fsm)
    {
        // 進入待機狀態:播放動畫、重設計時器
        fsm.SetData<float>("StateEnterTime", Time.time);
    }

    protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // 檢查轉換條件
        if (fsm.Owner.MoveInput.sqrMagnitude > 0.01f)
        {
            ChangeToState<MoveState>(fsm);
        }
    }

    protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
    {
        // 僅在正常轉換時進行清理;關閉時不重設全域資料
        if (!isShutdown)
        {
            fsm.RemoveData("StateEnterTime");
        }
    }
}
```

## 鉤子內部的限制事項

所有鉤子皆標記為 `protected internal`,因此只能在衍生類別或相同組件內進行覆寫。請勿在 `OnEnter` 中再次呼叫 `ChangeState` 後立即觸發其他副作用。狀態機會在轉換時同步執行 `OnLeave`/`OnEnter`,因此請留意執行順序所造成的副作用。

如需狀態機如何驅動(輪詢進入點)的詳細資訊，請參閱 [Runtime/Fsm/FsmBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs)。
