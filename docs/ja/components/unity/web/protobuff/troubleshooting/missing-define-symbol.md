# Post メソッドが存在しない、またはコンパイルエラーになる場合の対処法(マクロ未定義)

`WebProtoBuffComponent.Post<T>()` を呼び出したときにメソッドが存在しないと表示される、またはコンパイラが `GameFrameX.Network.Runtime.MessageObject` 型が見つからないとエラーを報告する場合、その原因はほとんどの場合同じです:プロジェクトに `com.gameframex.unity.network` パッケージがインストールされていないため、`ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` マクロが自動的に定義されず、`Post` 関連のコードが条件コンパイルによってまとめて削除されています。

## クイック診断

| 症状(エラー原文/現象) | 原因 | 修正 |
|------|------|------|
| `'WebProtoBuffComponent' does not contain a definition for 'Post'`(CS1061) | `Post<T>` メソッド全体が `#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` で囲まれており、マクロが未定義の場合はメソッドが存在しない | `com.gameframex.unity.network` パッケージをインストールしてマクロを自動的に有効化する。下記の[修正手順](#1-ネットワークパッケージのインストールを確認)を参照 |
| `The type or namespace name 'MessageObject' could not be found` | `MessageObject` / `IResponseMessage` は `GameFrameX.Network.Runtime` アセンブリに定義されており、このパッケージが欠けていると型が存在しない | `com.gameframex.unity.network` パッケージをインストールする |
| エディター左下にアセンブリ `GameFrameX.Web.ProtoBuff.Runtime` のコンパイル失敗が表示される | asmdef が `GameFrameX.Network.Runtime` を参照しており、ネットワークパッケージ未インストール時は参照の解決に失敗する | `com.gameframex.unity.network` パッケージをインストールする |
| ネットワークパッケージをインストール済みなのに `Post` がまだ使えない | asmdef の `versionDefines` が Unity に反映されず、マクロが書き込まれていない | Player Settings でマクロを手動で追加するか、Unity を再起動する。[手順 3](#3-マクロを手動で定義するフォールバック)を参照 |

マクロによるトリミングのロジックはソースコードで確認できます——`Post` メソッド全体が条件コンパイルで囲まれています:

```csharp
#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
        /// <summary>
        /// Postリクエストを送信します。Protocol Bufferメッセージの送受信に使用します。
        /// このメソッドはENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORKマクロ定義が有効な場合にのみ使用できます。
        /// </summary>
        public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
        {
            return m_WebProtoBuffManager.Post<T>(url, message);
        }
#endif
```

ソース: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

インターフェース `IWebProtoBuffManager` の `Post` も同じ書き方です([IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L11-L24))。一方、`Timeout` プロパティは常に使用可能で、マクロの影響を受けません。

## 修正手順

### 1. ネットワークパッケージのインストールを確認

マクロは手動で設定するものではなく、ランタイムアセンブリ定義ファイルの `versionDefines` によって自動的に制御されます:プロジェクト内に `com.gameframex.unity.network` パッケージが存在するだけで、Unity は自動的に `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` を定義します。

```json
  "versionDefines": [
    {
      "name": "com.gameframex.unity.network",
      "expression": "",
      "define": "ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK"
    }
  ]
```

ソース: [GameFrameX.Web.ProtoBuff.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L17-L23)

確認とインストール方法:

1. Unity メニューの `Window → Package Manager` を開き、`Packages: In Project` ビューに切り替えます。
2. `com.gameframex.unity.network` を探します(表示名は通常 GameFrameX Network)。
3. 存在しない場合は `+ → Add package from git URL...` を選択し、ネットワークパッケージのリポジトリ URL を入力して追加します。
4. 依存するアセンブリには、さらに `GameFrameX.Runtime`、`GameFrameX.Web.Runtime`、`ProtoBuffer.Runtime` があります([asmdef 参照リスト](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L4-L9)を参照)。通常、これらは依存関係として一緒に取得されます。

### 2. Unity にスクリプト定義を再読み込みさせる

パッケージのインストール完了後、Unity は自動的に `versionDefines` を更新して再コンパイルをトリガーします。されない場合は:

1. メニューの `Assets → Reimport All` を実行するか、プロジェクトルート直下の `Library/ScriptAssemblies` フォルダーを削除してから Unity を開き直します。
2. コンパイルの完了を待ち、Console にエラーがないことを確認します。

### 3. マクロを手動で定義するフォールバック

ネットワークパッケージがインストール済みなのにマクロがまだ有効にならない場合(例：古いバージョンの Unity で `versionDefines` のサポートが正常に動作しない場合):

1. `Edit → Project Settings → Player → Other Settings → Scripting Define Symbols` を開きます。
2. `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` を追加します(複数のマクロはセミコロンで区切ります)。
3. Enter キーで保存し、再コンパイルを待ちます。

注意：マクロの手動定義はあくまでフォールバックです。ネットワークパッケージが本当に欠けている場合、`Post` 内部で参照している `MessageObject`、`IResponseMessage` 型は依然として存在せず、コンパイルは失敗します——そのため、まず手順 1 を完了させてください。

## 検証

1. 任意のスクリプトで `webProtoBuffComponent.Post<` と入力すると、IDE が `Post<T>(string url, MessageObject message)` のオーバーロードを補完します。
2. `Project Settings → Player → Script Compilation` で `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` が有効になっていることが確認できます(手動で照合することも可能です)。
3. シーン内の `WebProtoBuff Component` がアタッチされたオブジェクトの Inspector が正常に表示され、Console に `Web manager is invalid.` の致命的なログが出力されていないこと(このログはコンポーネントが正しく初期化されていないことを示しており、マクロの問題とは別物です)。

## 背景

`Post` はネットワーク層の protobuf メッセージ型に依存しており、ネットワークパッケージはオプションの依存関係であるため、このコンポーネントでは asmdef の `versionDefines` を使って「ネットワークパッケージがインストールされている場合にのみ Post メソッドを公開する」というオンデマンドのトリミングを実現しています:`expression` が空の場合、そのパッケージの任意のバージョンが条件を満たすことを意味します。エラーの発生箇所がインターフェースではなくコンポーネントクラス側に出ることが多いのもこのためです——両方の場所の `#if` は同時に存在しています。
