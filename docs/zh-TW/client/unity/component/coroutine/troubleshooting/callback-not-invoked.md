# 幀結束回呼沒有被執行怎麼辦

`CoroutineComponent.WaitForEndOfFrameFinish` 注入的回呼依賴一個內部協程跑到 `yield return new WaitForEndOfFrame()` 之後才會觸發；如果協程在幀結束前被停止、被覆蓋或根本沒有跑起來，回呼都不會執行。本頁給出常見場景的診斷與修復方法。

關於協程元件的整體說明，請見《協程元件》。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 註冊的回呼一次都沒觸發，日誌裡沒有例外 | 協程被 `StopCoroutine` / `StopAllCoroutines` 提前終止，等待幀結束的 `WaitForEndOfFrame` 沒機會執行 | 不要在回呼應觸發的同一幀停掉協程，或改用其他同步點 |
| 同一個回呼被註冊多次卻只觸發一次 | `WaitForEndOfFrameFinishInternal` 是 `IEnumerator` 迭代器方法，傳入 `System.Action` 後回傳的是**新**迭代器實例，被框架的參考相等性 key 覆蓋了舊的追蹤記錄 | 把同一個 `WaitForEndOfFrameFinish` 呼叫視為一次性使用，或在業務層自行排隊合併回呼 |
| 進入 Play 後協程根本沒啟動 | 呼叫端拿到的是父類別 `MonoBehaviour` 參考，而 `StartCoroutine` 在該元件上以 `new` 關鍵字被覆寫並追蹤，父類別呼叫會繞過追蹤；同時，如果 GameObject 已經 `Destroy` 也無法啟動 | 透過 `CoroutineComponent` 型別參考呼叫，確認元件物件仍處於活動狀態 |
| 場景切換 / 結束播放模式後回呼再也沒觸發 | 元件隨 GameObject 一同銷毀，內部 `m_CoroutineMap` 被清空 | 不要把幀結束回呼掛在會被銷毀的物件上，而是放到常駐的 `CoroutineComponent` 上 |

## 修復步驟

### 1. 檢查是否被 `StopCoroutine` 提前終止

`WaitForEndOfFrameFinish` 的實作是一次性協程：

```csharp
private readonly WaitForEndOfFrame _waitForEndOfFrame = new WaitForEndOfFrame();

private IEnumerator WaitForEndOfFrameFinishInternal(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke();
}

public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(WaitForEndOfFrameFinishInternal(callback));
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

`yield return _waitForEndOfFrame` 必須等到當前幀的渲染結束才會恢復，期間任何 `StopCoroutine` / `StopAllCoroutines` 都會讓 `callback?.Invoke()` 這行永遠跑不到。

修復：

1. 在 `StopCoroutine` / `StopAllCoroutines` 之前，把回呼裡要做的副作用改為 `Time.timeScale`、`Application.targetFrameRate` 或對事件的主動發佈，而不是依賴 `WaitForEndOfFrameFinish`。
2. 如果一定要取消，先在業務程式碼裡手動執行一次回呼，再停掉協程：

```csharp
GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()
    .StopCoroutine(coroutineEnumerator); // 之後再處理自己的清理
```

### 2. 確認呼叫的是 `CoroutineComponent` 的 `StartCoroutine`

`StartCoroutine` 被 `new` 覆寫並維護 `m_CoroutineMap`，父類別 `MonoBehaviour` 呼叫會繞過追蹤。`StopCoroutine` 一旦拿不到 key,就找不到要停的協程，看似「沒啟動成功」：

```csharp
public new UnityEngine.Coroutine StartCoroutine(IEnumerator enumerator)
{
    var ret = base.StartCoroutine(enumerator);
    m_CoroutineMap[enumerator] = ret;
    return ret;
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

修復：所有呼叫統一透過 `GameFrameX.GameFrameXEntry.GetModule<CoroutineComponent>()` 取得的實例發起，不要把它隱式轉成 `MonoBehaviour`。

### 3. 避免 `StopAllCoroutines` 誤清

`StopAllCoroutines` 會清空 `m_CoroutineMap` 並停掉所有已追蹤協程，正在等待幀結束的回呼也會被一起丟棄：

```csharp
public new void StopAllCoroutines()
{
    foreach (var coroutine in m_CoroutineMap.Values)
    {
        base.StopCoroutine(coroutine);
    }
    m_CoroutineMap.Clear();
    base.StopAllCoroutines();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

修復：

1. 呼叫 `StopAllCoroutines` 之前確保沒有尚未結算的 `WaitForEndOfFrameFinish` 回呼。
2. 把幀結束級別的同步改用 `Update` / `LateUpdate` 或自訂事件，而不是 `WaitForEndOfFrame`。

### 4. 檢查物件生命週期

`CoroutineComponent` 是 `MonoBehaviour`,跟隨 GameObject 一起銷毀；一旦物件 `Destroy` 或所在場景被卸載，等待幀結束的協程隨之中斷，回呼不會再觸發。

修復：

1. 把幀結束回呼交給常駐的全域 `CoroutineComponent`(由 `GameFrameX` 框架自動建立)執行。
2. 若必須掛在自己的腳本上，確保回呼在 `OnDestroy` 之前已經觸發完成，或自行處理備援邏輯。

## 驗證

1. 在 `WaitForEndOfFrameFinish` 的回呼裡加一行 `Debug.Log`,Play 模式下確認每幀印出一次，或在回呼裡觸發一次本應執行的邏輯來觀察效果。
2. 在協程執行期間主動呼叫 `StopAllCoroutines`,觀察日誌：如果回呼不再印出，表示問題出在第 1 步；如果正常印出，表示是回呼邏輯本身失效。
3. 切換場景或結束 Play,確認 `CoroutineComponent` 實例是否仍然存在(`GameFrameXEntry` 是否被釋放)，據此判斷是第 4 步的物件生命週期問題。
