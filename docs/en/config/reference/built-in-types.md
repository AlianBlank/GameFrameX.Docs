# Built-in Field Types and Defines Quick Reference

This page collects the field types that GameFrameX.Config can use directly in the Excel header `##type` row, as well as the built-in structures (coordinate vectors) predefined in `Defines/builtin.xml`. All types come from the repository's actual source code and can be used in any `.xlsx` table without additional declaration.

## Quick Reference of Available Types for the Excel `##type` Row

The types listed in the table below can be used by simply filling them in on row 2 (`##type`) of any `Excels/Tables/*.xlsx` file.

| Type | Meaning | Excel Example | Use Case |
|------|------|----------------|----------|
| `int` | 32-bit integer | `10001` | Integers such as IDs, quantities, prices |
| `long` | 64-bit integer | `9000000001` | Large-value IDs, timestamps (milliseconds) |
| `float` | Single-precision decimal | `1.5` | Probabilities, coefficients, scaling |
| `double` | Double-precision decimal | `3.14159` | High-precision values |
| `bool` | Boolean value | `true` / `false` | Switches, enable/disable flags |
| `string` | Plain string (not translated) | `icon_diamond` | Resource paths, key names |
| `text` | Localized text (fill in a key; actual text is in `Local/`) | `diamond` | Player-facing copy |
| `vec2` | 2D vector (x,y) | `1.0,2.0` | 2D coordinates |
| `vec3` | 3D vector (x,y,z) | `1.0,2.0,3.0` | 3D coordinates, positions, scaling |
| `vec4` | 4D vector (x,y,z,w) | `1.0,2.0,3.0,4.0` | Quaternions with rotation or colors (RGBA) |
| `enum name` | Enum defined in `__enums__.xlsx` | `ItemType` | Types with a limited set of options |
| `bean name` | Structure defined in `__beans__.xlsx` | `Reward` | Nested fields |

> Difference between `text` and `string`: `text` goes through localization (fill in a key; the actual multilingual text is in `Excels/Local/`), while `string` is filled in as-is and is not translated.

## Built-in Structures in Defines/builtin.xml

XML files under the `Defines/` directory are automatically loaded by `luban.conf` via `schemaFiles.fileName = "Defines"`, requiring no additional registration. The 3 built-in structures below directly correspond to the actual definitions in `Defines/builtin.xml`:

| Name | Fields | Separator | Client Mapped Type | Server Mapped Type |
|------|------|--------|----------------|----------------|
| `vec2` | `x: float, y: float` | `,` | `UnityEngine.Vector2` | `System.Numerics.Vector2` |
| `vec3` | `x: float, y: float, z: float` | `,` | `UnityEngine.Vector3` | `System.Numerics.Vector3` |
| `vec4` | `x: float, y: float, z: float, w: float` | `,` | `UnityEngine.Vector4` | `System.Numerics.Vector4` |

Source: [Defines/builtin.xml](https://github.com/GameFrameX/GameFrameX.Config/blob/main/Defines/builtin.xml#L2-L40)

Example: To declare a spawn position field in an item table, fill in `vec3` on the `##type` row, `spawn_pos` on the `##var` row, and `1.0,2.0,3.0` in the Excel data row:

| ##var | id | name | spawn_pos |
|-------|----|------|-----------|
| ##type | int | text | vec3 |
| ##group | | | |
| ## | ID | Name | Spawn Position |
| | 10001 | diamond | 0.0,0.0,0.0 |

After generation:

- Client code reads `UnityEngine.Vector3`
- Server code reads `System.Numerics.Vector3`

Types adapt automatically; no separate configuration in the table is needed.

## Generation Targets and Code Type Mappings (Reference)

`Defines/builtin.xml` controls type mappings for different targets via `<mapper target="client" codeTarget="...">` and `<mapper target="server" codeTarget="...">`. The generation commands actually enabled in the repository's `luban.conf` determine which `codeTarget`s will be used:

| Target | dataTarget | codeTarget | Output Code Module |
|------|-----------|-------------|--------------|
| server | `json` | `cs-dotnet-json` | `GameFrameX.Config` |
| client | `json` | `cs-simple-json` | `Hotfix.Config` |
| server | `bin` (not enabled) | `cs-bin` | `GameFrameX.Config` |
| client | `bin` (not enabled) | `cs-bin` | `Hotfix.Config` |

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L94)

## Advanced Definitions (Optional)

The repository ships with 3 advanced definition files. Beginners can skip them for now and edit them directly when needed:

| File | Purpose |
|------|------|
| `Excels/__tables__.xlsx` | Main entry point for registering all data tables |
| `Excels/__beans__.xlsx` | Custom structures (similar to the built-in `vec2/3/4`) |
| `Excels/__enums__.xlsx` | Custom enums |

For how to add custom structures or enums in these files, see "How to Customize Field Types".
