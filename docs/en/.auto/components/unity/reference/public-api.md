# Public API Quick Reference

This page lists the most commonly used public API entry points, module base classes, and extension methods of the GameFrameX runtime, organized as "framework entry → component base classes → data structures / utility classes" for quick lookup. All signatures are taken from the actual source files under `Runtime/Base/`.

## Framework Entry

| Type | File | Purpose |
|------|------|---------|
| `GameFrameworkEntry` | [Runtime/Base/GameFrameworkEntry.cs](/Runtime/Base/GameFrameworkEntry.cs) | The framework's sole entry point, responsible for module registration, polling, and destruction |
| `GameEntry` | [Runtime/Base/GameEntry.cs](/Runtime/Base/GameEntry.cs) | Business-side static facade, with module properties populated by code generator via partial |
| `GameFrameworkComponent` | [Runtime/Base/GameFrameworkComponent.cs](/Runtime/Base/GameFrameworkComponent.cs) | Base class for all components (e.g., UI, network, localization) |

## Typical Usage Snippets

The business side generally obtains the target module through `GameEntry`, then calls its business methods. The example below shows how a custom component is registered to the framework entry (signatures taken from the public API form of [Runtime/Base/GameFrameworkEntry.cs](/Runtime/Base/GameFrameworkEntry.cs) and [Runtime/Base/GameFrameworkComponent.cs](/Runtime/Base/GameFrameworkComponent.cs)):

```csharp
// Business-side partial class, module properties supplemented by code generator
GameEntry.Event.Subscribe(MyEventArgs.EventId, OnMyEvent);
GameEntry.Base.GameVersion  // Read framework version
```

```csharp
// Custom components need to inherit from GameFrameworkComponent and be attached to a GameObject in the same scene as GameFrameworkEntry
public sealed class MyComponent : GameFrameworkComponent
{
    // Called by GameFrameworkEntry on Awake
}
```
