# 如何设置自定义附加数据

调用 `IAdvertisementManager.SetExtraData(string key, string value)` 可以在广告加载前写入键值对形式的扩展数据，广告 Load 时这些键值对会被打包成 JSON 一并透传到服务端奖励验证回调，用于做用户标识、奖励派发匹配等业务逻辑。

## 前置条件

- 已安装 `com.gameframex.unity.advertisement` 包,并在场景中挂载 `AdvertisementComponent`。
- 已通过 `Initialize(AdvertisementConfig)` 初始化广告管理器,扩展数据必须**在 Load 调用之前**设置完毕,否则不会被打包进请求。

## 操作步骤

1. **获取广告管理器实例**

   通过 `AdvertisementComponent` 拿到当前平台的 `IAdvertisementManager`,后续所有 API 都通过该接口调用。

2. **在 Load 之前调用 SetExtraData**

   `SetExtraData` 接受一个字符串键和一个字符串值,内部维护一个 `Dictionary<string, string>` 容器;重复设置相同键会覆盖旧值,传入 `null` 值则会移除该键。

   ```csharp
   using GameFrameX.Advertisement.Runtime;

   var mgr = GameFrameworkEntry.GetModule<IAdvertisementManager>();

   // 写入用户标识,服务端可用它匹配奖励归属
   mgr.SetExtraData("user_id", "10086");

   // 写入业务标签
   mgr.SetExtraData("scene", "level_clear");

   // 传入 null 会移除该键
   mgr.SetExtraData("user_id", null);
   ```

   Source: [BaseAdvertisementManager.cs#L165-L189](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L165-L189)

3. **按平台 Load 广告**

   调用 Load 后,管理器会调用受保护的 `SerializeExtraData()` 把整个字典序列化为 JSON,并随 Load 请求一起送往服务端。无扩展数据时返回 `null`。

   ```csharp
   // Load 之后,所有 SetExtraData 的修改都不会再透传
   mgr.Load(option);
   ```

   `SerializeExtraData()` 实现如下:

   ```csharp
   protected string SerializeExtraData()
   {
       if (ExtraData.Count == 0)
       {
           return null;
       }
       return Utility.Json.ToJson(ExtraData);
   }
   ```

   Source: [BaseAdvertisementManager.cs#L273-L282](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L273-L282)

4. **(可选)在加载后回读**

   若子类需要在校验后回读键值,可以使用受保护的 `GetExtraDataValue(string key)`,键不存在时返回 `null`。

   ```csharp
   // 仅在继承 BaseAdvertisementManager 的子类中可用
   var uid = GetExtraDataValue("user_id");
   ```

   Source: [BaseAdvertisementManager.cs#L292-L297](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L292-L297)

## 常见变体

- **在 Play 时携带单段自定义数据**: `AdvertisementPlayOption.customData` 字段用于广告播放时透传自定义信息,与 `extraData` 字段(仅在 Load 阶段生效)是两个独立通道。

  ```csharp
  var option = new AdvertisementPlayOption
  {
      OnSuccess = extra => { /* 奖励发放 */ },
      customData = "level_id=42"
  };
  ```

  Source: [AdvertisementPlayOption.cs#L78-L84](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L78-L84)

- **键值批量预置**: 在游戏启动、登录成功后一次性写入一批扩展数据,后续 Load 调用即自动带上。

## 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 服务端收到的 `extraData` 为 `null` | Load 调用之后再 `SetExtraData`,序列化发生在 Load 内部,后续写入不会进入请求 | 把所有 `SetExtraData` 调用放到 `Load` 之前 |
| 服务端收到的 JSON 是空对象 `{}` | 没有任何 `SetExtraData` 调用或全部键被 `null` 值移除 | 至少设置一个键值对,`SerializeExtraData()` 在字典为空时返回 `null` |
| 设置的键不生效 | 传入 `key` 为 `null` 或空字符串,`SetExtraData` 直接 return | 保证 `key` 非空 |
| 想删除某个键但下次 Load 仍带它 | 用了 `SetExtraData(key, "")` 写入空串,这只会被当成空值保留 | 用 `SetExtraData(key, null)` 显式移除 |

## 背景(可选)

扩展数据存储在 `BaseAdvertisementManager.ExtraData`(受保护的 `Dictionary<string, string>`),Load 时由框架统一序列化为 JSON 透传到广告 SDK 的服务端奖励验证回调;`AdvertisementPlayOption.extraData` 与它是同名但用途不同的字段——后者只在 Load 阶段被读取,加载后写入无效。
