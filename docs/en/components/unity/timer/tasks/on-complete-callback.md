# Execute a Callback When the Timer Completes or Is Removed

Pass the last optional parameter `onComplete` (`System.Action`) when calling `Add(...)`, and the timer will automatically invoke it when it **completes (repeats exhausted) or is removed**. The signature is as follows:

```csharp
int Add(float interval, int repeat, Action<object> callback, object callbackParam = null,
        string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled,
        Action onComplete = null);
```

Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L14-L22)

## Prerequisites

- The `TimerComponent` has been created and initialized in the scene (it internally holds an `ITimerManager` and forwards `Add`).
Source: [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L44-L47)

## Steps

1. Prepare a regular timer callback (`Action<object>`) that handles the work to be done on each trigger.
2. Pass the completion callback via the named parameter `onComplete:` in the `Add` call (using a named parameter is recommended, since it comes after a series of optional parameters).
3. Wait for the repeats to be exhausted or remove the timer manually; `onComplete` will be invoked automatically once.

```csharp
bool completed = false;

// Fires once every 1 second, 3 times in total; completed becomes true after the 3rd trigger ends
int id = timerComponent.Add(1f, 3, _ => { Debug.Log("tick"); },
                            onComplete: () => completed = true);
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L660-L664)

Manual removal also triggers the callback — for example, removing via the callback function:

```csharp
var callback = new Action<object>(_ => { });
_timerManager.Add(1f, 0, callback, onComplete: () => completed = true);
_timerManager.Remove(callback);   // After removal, completed == true
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L677-L684)

## Common Variants

- **Combined with tag grouping**: `onComplete` is one of the `Add` parameters and can be used together with `tag` and `timeScale`, without affecting tag-based `PauseByTag` / `ResumeByTag` / `RemoveByTag` operations.
  Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L93-L118)
- **Re-adding with the same callback**: Calling `Add` again with an existing `callback` updates it in place (`t.Set(interval, repeat, callback, callbackParam, tag, timeScale, onComplete)` and resets the timer), and the newly passed `onComplete` overwrites the old one.
  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L227-L243)

## Common Mistakes

- **Expecting the callback to fire on an infinitely repeating timer**: `repeat = 0` means infinite repetition; the timer never "completes", so `onComplete` will not fire. If you need an end point, explicitly set a finite repeat count or call `Remove`.
  Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L688-L699)
- **Null callback causing the timer not to be created**: When `callback == null`, only the log `"timer callback is null, " + interval + "," + repeat` (emitted before the `Timer callback error` warning) is output and 0 is returned; naturally, `onComplete` never gets a chance to fire. The main callback `callback` must be non-null (`onComplete` itself may be null).
  Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L221-L225)
- **Wrong parameter order**: `onComplete` is the 7th parameter, so positional arguments are easy to misplace; it is recommended to always use the named parameter `onComplete: () => ...`.
  Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L22)

## Background

`onComplete` is stored on the `OnComplete` field of the internal `TimerItem` (`public Action OnComplete;`). The scheduler thread invokes `i.OnComplete?.Invoke()` when marking the timer for deletion and actually removing it from the dictionary; the tag-based batch removal path likewise calls `t.OnComplete?.Invoke()` after removing it from the tag index, so both natural completion and removal go through this single exit point.

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L134-L148) (natural completion path)
