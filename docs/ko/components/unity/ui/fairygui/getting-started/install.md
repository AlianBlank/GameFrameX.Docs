# 설치 및 첫 사용 (의존성 및 플랫폼 지원)

Unity Package Manager를 통해 GameFrameX UI FairyGUI 어댑터를 설치하면 GameFrameX UI 시스템에서 FairyGUI로 UI를 구축할 수 있습니다: 통합된 열기/닫기/회수 수명 주기, 객체 풀, 비동기 리소스 로딩이 제공됩니다. 최소 Unity 2019.4를 지원하며, Android / iOS / Windows / macOS / WebGL을 포괄합니다.

## 사전 조건

- Unity **2019.4** 이상 버전([package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/package.json#L7)의 `"unity": "2019.4"` 참조).
- 이 패키지는 다음 의존성을 자동으로 해석하므로 수동 설치가 필요 없습니다(버전은 [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/package.json#L22-L30)에서 가져옴):

| 의존성 패키지 | 요구 버전 | 설명 |
|--------|----------|------|
| `com.gameframex.unity` | 2.5.1 | GameFrameX 핵심 프레임워크 |
| `com.gameframex.unity.ui` | 2.11.0 | GameFrameX UI 시스템(UIManager 등) |
| `com.gameframex.unity.asset` | 3.1.1 | 리소스 로딩(YooAsset 브리지 포함) |

| `com.gameframex.unity.fairygui.unity` | 5.3.4 | FairyGUI 런타임 |
| `com.gameframex.unity.tuyoogame.yooasset` | 2.9.4 | YooAsset 비동기 리소스 로딩 |
| `com.gameframex.unity.cysharp.unitask` | 2.6.2 | UniTask 비동기 지원 |

## 작업 단계

아래 네 가지 방법 중 하나를 선택하여 설치합니다(방법 1 권장):

1. **Scoped Registry(권장)**: Unity 프로젝트의 `Packages/manifest.json`을 편집하여 `scopedRegistries`를 추가하고 의존성을 선언합니다:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": [
           "com.gameframex"
         ]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.ui.fairygui": "3.4.3"
     }
   }
   ```

   `scopes`는 어떤 패키지가 해당 레지스트리에서 해석되는지 결정합니다. `com.gameframex`로 시작하는 패키지만 여기서 가져옵니다. 출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.md#L73-L91), 버전 번호는 [package.json](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/package.json#L6)을 기준으로 합니다.

2. **Git URL 의존성**: `manifest.json`의 `dependencies`에 직접 작성합니다:

   ```json
   {
     "com.gameframex.unity.ui.fairygui": "https://github.com/gameframex/com.gameframex.unity.ui.fairygui.git"
   }
   ```

3. **Package Manager + Git URL**: Unity 메뉴 `Window > Package Manager > + > Add package from git URL`에서 `https://github.com/gameframex/com.gameframex.unity.ui.fairygui.git`를 입력합니다.

4. **로컬 클론**: 저장소를 프로젝트의 `Packages` 디렉토리에 클론하면 Unity가 자동으로 로드합니다.

설치 완료 후 첫 사용:

1. 씬의 GameFrameX 컴포넌트 마운트 지점에 FairyGUI 패키지 관리 컴포넌트를 추가합니다: 메뉴 `Add Component > GameFrameX/FairyGUIPackage`, 즉 `FairyGUIPackageComponent`입니다. 이것은 `GameFrameworkComponent`를 상속하며, `[DisallowMultipleComponent]`로 단일 인스턴스를 제한하고, 모든 UI 패키지의 로딩, 캐싱 및 언로드를 담당합니다. [FairyGUIPackageComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIPackageComponent.cs#L45-L48) 참조.
2. UI 패널이 `FUI` 기본 클래스를 상속하도록 하고, 필요에 따라 특성(Attribute)으로 표시/숨김 애니메이션을 구성합니다:

   ```csharp
   [OptionUIShowAnimation(typeof(FadeInAnimation))]
   [OptionUIHideAnimation(typeof(FadeOutAnimation))]
   public class AnimatedPanel : FUI { }
   ```

   출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.md#L107-L111). 이후 `UIManager`가 열기, 닫기, 회수 및 대기열 로딩을 통합하여 담당합니다.

## 일반적인 변형

- **경로로 GObject 찾기**: `gObject.GetUIPath()`로 계층 경로를 가져온 다음, `FairyGUIPathFinderHelper.GetUIFromPath("GRoot/Group/MyButton")`로 객체를 역조회합니다. 출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.md#L113-L121).
- **MVVM 자동 정리**: `myProperty.ClearWithGObjectDestroyed(gObject)`는 GObject가 파괴될 때 이벤트를 자동으로 등록 해제합니다. 출처: [README.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.md#L123-L128).
- **이중 리소스 로딩 모드**: `Resources.Load`와 YooAsset AssetBundle 두 가지 로딩 방식을 모두 지원하며, 리소스 계층 설정에 따라 결정됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 의존성 해석 실패/패키지를 찾을 수 없음 | scoped registry 미구성 | 방법 1로 `scopedRegistries`를 구성하고, `scopes`에 `com.gameframex`가 포함되어 있는지 확인 |
| `FairyGUIPackageComponent` 중복 추가 | 컴포넌트에 `[DisallowMultipleComponent]`가 표시됨 | 중복 컴포넌트를 제거하고 단일 인스턴스 유지 |
| IL2CPP 빌드 후 UI 로직이 제거됨 | 코드 스트리핑 | 이 패키지에는 `[UnityEngine.Scripting.Preserve]` 보호가 추가되어 있으므로, 추가로 스트리핑 재정의를 구성하지 않았는지 확인 |
