# 작동 원리: Config 컴포넌트 아키텍처 훑어보기

Config 컴포넌트는 `ConfigComponent`를 진입점으로 사용하며, `IConfigManager` 인터페이스를 통해 설정 항목을 `ConfigManager` 모듈에 위탁하여 통합 관리합니다. 런타임에는 `IDataTable` 인터페이스를 통해 비동기적으로 로드, 캐시 및 비즈니스 레이어에 키-값 접근을 제공합니다. 이 페이지에서는 "컴포넌트—모듈—데이터 테이블" 3계층 관계와 로드에서 읽기까지의 최소 코드 경로를 한 그림으로 설명합니다.

## 빠른 시작

1. 씬의 `GameFramework` GameObject에 `ConfigComponent`를 추가합니다(컴포넌트 메뉴: `GameFrameX/Config`).
2. 비즈니스 측에서는 `GameEntry.GetComponent<ConfigComponent>()`를 통해 컴포넌트를 가져옵니다.
3. 컴포넌트는 `Awake()`에서 `GameFrameworkEntry.GetModule<IConfigManager>()`를 호출하여 `ConfigManager` 인스턴스를 해석합니다([ConfigComponent.cs#L73-L85](/Runtime/Config/ConfigComponent.cs#L73-L85)).
4. 임의의 `IDataTable` 서브클래스는 자체 `LoadAsync()`를 호출하고, 로드 완료 후 `ConfigManager.AddConfig(configName, table)`을 통해 등록합니다. 이후 `HasConfig` / `GetConfig`로 조회할 수 있습니다.

```csharp
var configComp = GameEntry.GetComponent<ConfigComponent>();
var module = GameFrameworkEntry.GetModule<IConfigManager>();
module.AddConfig("MyTable", myDataTable);   // IDataTable은 BaseDataTable<T>에서 파생
```

## 작동 원리 훑어보기

전체는 3계층으로 나뉩니다: **Unity 컴포넌트 레이어**(`ConfigComponent`), **프레임워크 모듈 레이어**(`IConfigManager` / `ConfigManager`), **데이터 테이블 레이어**(`IDataTable` / `BaseDataTable<T>`). 컴포넌트 레이어는 Unity 라이프사이클에서 모듈을 해석하는 역할을 하며, 모듈 레이어는 `ConcurrentDictionary<string, IDataTable>`로 설정 집합을 유지하고, 데이터 테이블 레이어는 구체적인 로드, 파싱, 키-값 조회를 담당합니다.

## 주요 API 및 기본값

`IConfigManager`는 모듈 레이어의 외부 계약이며, 시그니처는 소스 코드를 직접 따릅니다:

| 멤버 | 시그니처 | 기본값 / 설명 |
|------|------|---------------|
| `Count` | `int Count { get; }` | 현재 등록된 설정 항목 수, 내부 딕셔너리 `m_ConfigDatas.Count`에서 가져옴 |
| `HasConfig` | `bool HasConfig(string configName)` | 이름 매칭에 `StringComparer.Ordinal` 사용 |
| `AddConfig` | `void AddConfig(string configName, IDataTable configValue)` | `m_ConfigDatas`에 기록 |
| `RemoveConfig` | `bool RemoveConfig(string configName)` | 딕셔너리에서 지정된 설정 항목을 제거 |
| `GetConfig` | `IDataTable GetConfig(string configName)` | 이름으로 `IDataTable` 반환 |
| `RemoveAllConfigs` | `void RemoveAllConfigs()` | 모든 설정 항목을 비움 |
| `Shutdown` | `void Shutdown()` | 모든 `IDataTable`을 해제하고 딕셔너리를 비움 |

`ConfigComponent`의 관련 주요 코드:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Config")]
[GameFrameXAutoComponent(-5000)]
public sealed class ConfigComponent : GameFrameworkComponent
{
    protected override void Awake()
    {
        ImplementationComponentType = Utility.Assembly.GetType(componentType);
        InterfaceComponentType = typeof(IConfigManager);
        base.Awake();
        m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
        if (m_ConfigManager == null)
        {
            Log.Fatal("Config manager is invalid.");
            return;
        }
    }
}
```

`ConfigManager`는 `ConcurrentDictionary<string, IDataTable>`로 모든 테이블을 보관하며 동시성 안전합니다. 각 key의 문자열 비교는 `StringComparer.Ordinal`을 채택하여 대소문자를 구분합니다:

```csharp
public sealed partial class ConfigManager : GameFrameworkModule, IConfigManager
{
    private readonly ConcurrentDictionary<string, IDataTable> m_ConfigDatas;

    public ConfigManager()
    {
        m_ConfigDatas = new ConcurrentDictionary<string, IDataTable>(StringComparer.Ordinal);
    }
}
```

Source: [ConfigManager.cs#L46-L61](/Runtime/Config/Config/ConfigManager.cs#L46-L61)

`IDataTable`은 비제네릭 데이터 테이블 인터페이스이며, 핵심 메서드 `LoadAsync()`는 비동기 로드에 사용되는 `Task`를 반환합니다:

```csharp
[Preserve]
public interface IDataTable
{
    [Preserve]
    Task LoadAsync();
    int Count { get; }
    // ... 행 가져오기 / 인덱스 등 멤버
}
```
