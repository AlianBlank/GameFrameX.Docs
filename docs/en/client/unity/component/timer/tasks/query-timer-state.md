# Querying Timer Status: Remaining Time, Elapsed Time, and Remaining Count

Call `GetRemaining` / `GetElapsed` / `GetRepeatLeft` with a timer ID to query its current state; combined with `IsPaused` / `Exists`, you can further determine whether the timer is alive or paused. All three query methods uniformly return `-1` when the timer does not exist.

## Prerequisites

- A usable `TimerComponent` exists in the scene (it internally wraps the same-named methods of `ITimerManager`).
- You hold the timer ID returned when the timer was created (the return value of the `Add` series of methods).

## Query Interface Overview

| Method | Signature | Return Value |
|------|------|--------|
| Remaining time | `float GetRemaining(int id)` | Remaining seconds; returns `-1` if the timer does not exist |
| Elapsed time | `float GetElapsed(int id)` | Accumulated seconds; returns `-1` if the timer does not exist |
| Remaining count | `int GetRepeatLeft(int id)` | Number of remaining repeats (`0` means infinite loop); returns `-1` if the timer does not exist |
| Is paused | `bool IsPaused(int id)` | Returns `true` while paused, otherwise `false` |
| Exists | `bool Exists(int id)` | Returns `true` if alive, otherwise `false` |
| Tag query | `bool HasTag(string tag)` | Returns `true` if at least one timer exists under that tag |

## Steps

1. Create a timer and save the returned ID (e.g., `int id = ...` from an `Add` series registration call).
2. At the moment you need to refresh the UI or game logic, call the query methods through your held `TimerComponent` instance:
   - Use `GetRemaining(id)` for countdown display;
   - Use `GetElapsed(id)` for progress bar filling (divide by the total duration to get progress);
   - Use `GetRepeatLeft(id)` for count display.
3. Before each query, it is recommended to first use `Exists(id)` to check whether the timer still exists — once the timer finishes firing and is removed, queries will only return `-1`.
4. If the timer may have been paused by `Pause`/`PauseByTag`, use `IsPaused(id)` to distinguish between "paused" and "finished".
5. Handle `-1` in the UI as "timer no longer exists" to avoid directly displaying a negative number.

## Common Variants

- **Querying after batch pause**: After calling `PauseByTag(tag)` on a group of timers with the same tag, `GetRemaining` will not decrease (no time accumulates during the pause), and `IsPaused` returns `true`. Use `ResumeByTag(tag)` to resume.
- **Infinite loop timers**: `GetRepeatLeft` returning `0` means an infinite loop; do not treat it as "finished".
- **async/await scenarios**: When you want to wait directly instead of querying state, you can use async methods such as `WaitForSecondsAsync(seconds, cancellationToken)`, see [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L224).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GetRemaining` returns `-1` | The timer has been removed (finished firing, `Remove`/`RemoveByTag` was called, or the ID is incorrect) | First check with `Exists(id)`; re-register the timer |
| Remaining time "not moving" | The timer is paused | Check `IsPaused(id)` and call `Resume(id)` if necessary |
| `GetRepeatLeft` returns `0` but callbacks still fire | `0` means infinite loop, not finished | Use `Exists(id)` rather than the count to check existence |
| Negative number displayed | `-1` rendered directly as seconds | Map `-1` to "finished/nonexistent" at the UI layer |

## Background (Optional)

Internally, each timer is recorded in `TimerManager`'s private `Timer` class, where the `Elapsed` field continuously accumulates elapsed time; the query methods calculate remaining values based on this internal data ([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L21-L22)). `TimerComponent` is merely a thin wrapper over `ITimerManager`, so both entry points return identical query results.
