# 使用时间尺度：让定时器受/不受 Time.timeScale 影响

每个定时器都可以独立选择时间尺度：`TimerTimeScale.Unscaled`（真实时间，默认）或 `TimerTimeScale.Scaled`（受 `UnityEngine.Time.timeScale` 影响）。只需在调用 `Add` 时通过 `timeScale` 参数指定即可。

## 前置条件

- 项目中已引入 GameFrameX Timer 包，并已获得 `ITimerManager` / `TimerManager` 实例（如通过 `TimerComponent` 获取）。

## 时间尺度枚举速查

`TimerTimeScale` 是一个 `byte` 枚举，定义如下：

| 名称 | 值 | 行为 |
|------|----|------|
| `Unscaled` | 0 | 不受 `Time.timeScale` 影响（默认值，与既有行为兼容） |
| `Scaled` | 1 | 受 `Time.timeScale` 影响 |

```csharp
public enum TimerTimeScale : byte
{
    /// <summary>不受 <see cref="UnityEngine.Time.timeScale"/> 影响（默认，与现有行为兼容）。</summary>
    Unscaled = 0,

    /// <summary>受 <see cref="UnityEngine.Time.timeScale"/> 影响。</summary>
    Scaled = 1,
}
```

## 操作步骤

1. 确认 `Add` 的完整签名，`timeScale` 是第 6 个参数且默认为 `Unscaled`：

```csharp
public int Add(float interval, int repeat, Action<object> callback, object callbackParam = null, string tag = null, TimerTimeScale timeScale = TimerTimeScale.Unscaled, Action onComplete = null)
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L217)（接口声明见 [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L22)）

2. 添加一个**不受** `Time.timeScale` 影响的定时器（例如 UI 倒计时、断线重连倒计时）——不传 `timeScale`，或显式传 `Unscaled`：

```csharp
// 默认即为 Unscaled：游戏暂停（timeScale = 0）时该定时器仍会走表
timer.Add(1000f, 0, callback);
```

3. 添加一个**受** `Time.timeScale` 影响的定时器（例如慢动作、暂停菜单等场景下的游戏逻辑计时）——显式传 `timeScale: TimerTimeScale.Scaled`：

```csharp
// 受 Time.timeScale 影响（适用于慢动作、暂停菜单等场景）
timer.Add(1000f, 0, callback, timeScale: TimerTimeScale.Scaled);
```

4. 组合其他参数使用（回调参数、标签、完成回调均可与 `timeScale` 同时指定）：

```csharp

_timerManager.Add(1f, 1, _ => callCount++, timeScale: TimerTimeScale.Scaled);
```

## 常见变体

- **暂停菜单**：把 `Time.timeScale` 设为 0，游戏逻辑用 `Scaled` 定时器（随之冻结），弹窗动画/倒计时用 `Unscaled` 定时器（继续走表）。
- **慢动作**：把 `Time.timeScale` 设为 0.5，`Scaled` 定时器的实际走表速度也变为原来的一半；`Unscaled` 定时器不受影响。
- **同一管理器混用**：两种模式可在同一个 `TimerManager` 中混用，更新循环会按每个定时器各自的模式选择时间源：

```csharp
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L81)

## 常见错误

- **以为默认就受 timeScale 影响**：`Add` 的 `timeScale` 参数默认值是 `Unscaled`，不改 `Time.timeScale` 时两种模式行为相同（`timeScale = 1`），但一旦暂停/慢放，未显式传 `Scaled` 的定时器不会变慢。需要跟随游戏时间时必须显式写 `timeScale: TimerTimeScale.Scaled`。
- **`timeScale = 0` 后 Scaled 定时器"丢失"**：定时器并未被移除，只是每帧增量 delta 为 0；恢复 `Time.timeScale` 后它会继续走表。
- **位置传参搞错**：`timeScale` 排在 `callbackParam`、`tag` 之后、`onComplete` 之前；建议始终用具名参数 `timeScale: TimerTimeScale.Scaled` 避免错位。

## 背景

`TimerManager` 的更新方法同时接收缩放时间与真实时间两路增量，更新每个定时器时按其 `TimeScaleMode` 选择：`Scaled` 用 `elapseSeconds`，`Unscaled` 用 `realElapseSeconds`，因此两种模式互不干扰；定时器对象回收复用时 `TimeScaleMode` 会被重置为 `Unscaled`（见 [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L633)）。
