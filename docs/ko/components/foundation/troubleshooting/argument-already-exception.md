# ArgumentAlreadyException 발생 시 대처 방법

GameFrameX.Foundation 사용 중 `ArgumentAlreadyException`(이미 존재하는 매개변수 중복 예외)이 발생하면, 이는 특정 매개변수 값이 이미 존재하거나 중복되었다는 의미입니다. 이 페이지는 원인을 빠르게 판단하고 수정하는 데 도움을 줍니다.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `ArgumentAlreadyException: <사용자 메시지>` 발생 | 비즈니스 코드에서 해당 예외를 명시적으로 발생시킴(예: 등록 시 중복 ID / 중복 키 / 중복 이름 감지) | 먼저 확인 후 값을 할당하는 로직으로 변경하거나, 정적 헬퍼 메서드 호출 전에 중복 제거를 수행 |
| `ArgumentNullException: message` 발생, `ParamName = "message"` | `new ArgumentAlreadyException(null)` 또는 `Throw(null)` 호출 시 message에 null 전달 | null이 아닌 설명 문자열 전달 |
| `ArgumentException: message` 발생, `ParamName = "message"` | 빈 문자열 `""` 또는 공백 문자만 포함된 문자열(예: `"   "`) 전달 | 실제 내용이 있는 설명 문자열 전달 |
| `ArgumentNullException` 발생을 프레임워크 버그로 오인 | 프레임워크가 message 매개변수에 대해 `ThrowIfNullOrWhiteSpace` 검증을 수행하며, null/빈 값/공백은 사전에 차단됨 | 이는 예상된 동작이므로, 매개변수만 수정하면 됨 |

## 해결 단계

### 1. 예외 유형 구분하기

`ArgumentAlreadyException`은 사용자 또는 프레임워크 코드에서 명시적으로 호출할 때에만 발생합니다. `ArgumentNullException` / `ArgumentException`은 생성자가 `message` 매개변수에 대해 사전 검증을 수행한 결과입니다.

```csharp
using GameFrameX.Foundation.Extensions;

// 명시적으로 예외 발생
public void Register(string id)
{
    if (_dict.ContainsKey(id))
    {
        ArgumentAlreadyException.Throw($"id '{id}'이(가) 이미 존재합니다");
    }
    _dict[id] = ...;
}
```

### 2. "매개변수가 이미 존재합니다" 비즈니스 시나리오 처리

가장 일반적인 해결 방법은 요소를 추가하기 전에 존재 여부를 확인하여 중복을 방지하는 것입니다:

```csharp
using GameFrameX.Foundation.Extensions;

public void AddUnique(string key, string value)
{
    if (_map.ContainsKey(key))
    {
        // 옵션 A: 건너뛰기
        return;

        // 옵션 B: 상위 계층에서 결정하도록 예외 발생
        // ArgumentAlreadyException.Throw($"key '{key}'이(가) 이미 존재합니다");
    }
    _map[key] = value;
}
```

### 3. message가 null / 빈 값 / 공백인 경우 처리

`ArgumentNullException` 또는 `ArgumentException`이 발생했고 `ParamName`이 `message`인 경우, 호출자가 유효하지 않은 문자열을 전달했다는 의미입니다. 매개변수만 수정하면 됩니다:

```csharp
using GameFrameX.Foundation.Extensions;

var msg = string.IsNullOrWhiteSpace(input)
    ? "기본값/키가 이미 존재합니다"
    : $"{input}이(가) 이미 존재합니다";

try
{
    ArgumentAlreadyException.Throw(msg);
}
catch (ArgumentAlreadyException ex)
{
    // 비즈니스 처리
}
```

### 4. 단위 테스트에서의 예상 동작

저장소의 테스트는 네 가지 동작을 명확하게 정의하고 있으며, 바로 비교해 볼 수 있습니다:

| 입력 | 예상되는 예외 |
|------|----------|
| `"Parameter already exists"` | `ArgumentAlreadyException` |
| `null` | `ArgumentNullException`, `ParamName = "message"` |
| `""` | `ArgumentException`, `ParamName = "message"` |
| `"   "` | `ArgumentException`, `ParamName = "message"` |

## 검증

1. `message` 매개변수가 null이 아니며, 빈 문자열이나 순수 공백이 아닌지 확인합니다.
2. 비즈니스 측에서 추가/등록 작업을 수행하기 전에 대상 컬렉션에 대한 존재 여부 검사를 수행했는지, 또는 프레임워크의 자동 검증에 의존하고 있는지 확인합니다.
3. 단위 테스트에서 `Assert.Throws<ArgumentAlreadyException>`를 사용하여 명시적으로 단언함으로써, 매개변수 검증 수정을 누락하지 않도록 합니다.
