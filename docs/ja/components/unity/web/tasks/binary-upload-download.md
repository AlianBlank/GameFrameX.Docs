# バイナリデータのアップロードとダウンロード方法

`WebComponent` の `GetToBytes` / `PostToBytes` シリーズのメソッドを使用すると、`byte[]` バイナリデータの送信または受信が可能です。これらはいずれも `Task<WebBufferResult>` を返すため、`async/await` でバイト配列の結果を直接取得できます。

## 前提条件

- シーンに `WebComponent` コンポーネントが追加されていること(GameFrameX Web モジュールのエントリポイント)。
- `await` を使用するメソッドは `async` としてマークされ、`GameFrameX.Web.Runtime` 名前空間が using で導入されていること。
- サーバー側は `application/octet-stream` コンテンツタイプをサポートしている必要があります——フレームワークはバイナリリクエストの送信時にこの Content-Type を固定で使用します。

## 操作手順

1. `WebComponent` インスタンスを取得します(例:GameEntry モジュールマネージャー経由)。

2. バイナリのダウンロード:`GetToBytes` を呼び出し、返された `WebBufferResult.Result` からバイト配列を取得します。

```csharp
WebBufferResult result = await GameEntry.Web.GetToBytes("https://example.com/assets/avatar.png");
byte[] bytes = result.Result; // サーバーから返された生のバイナリコンテンツ
```

`GetToBytes` の `IWebManager` インターフェースにおける実際のシグネチャ:

```csharp
Task<WebBufferResult> GetToBytes(string url, object userData = null);
Task<WebBufferResult> GetToBytes(string url, Dictionary<string, string> queryString, object userData = null);
```

出典: [IWebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/IWebManager.cs#L26-L45)

3. バイナリのアップロード:`PostToBytes` を呼び出し、`byte[]` フォームデータを渡します。

```csharp
byte[] payload = System.Text.Encoding.UTF8.GetBytes("hello");
WebBufferResult result = await GameEntry.Web.PostToBytes(
    "https://example.com/api/upload",
    payload,
    null,   // queryString、null を指定可能
    null,   // header、null を指定可能
    "myTag" // userData、コールバック時にそのまま返される
);
```

出典： [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L199-L209)

4. 結果を読み取ります。`WebBufferResult` には次の 2 つのプロパティのみが含まれます:

| プロパティ | 型 | 説明 |
|------|------|------|
| `Result` | `byte[]` | サーバーから返された生のバイト配列 |
| `UserData` | `object` | リクエスト時に渡されたカスタムデータ、そのまま返される |

出典： [WebBufferResult.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebBufferResult.cs#L11-L19)

## よくあるバリエーション

**クエリパラメータとリクエストヘッダー付き**:2 つのディクショナリは URL と HTTP ヘッダーにマージされます。

```csharp
var queryString = new Dictionary<string, string> { { "id", "1001" } };
var header = new Dictionary<string, string> { { "Authorization", "Bearer token" } };
WebBufferResult result = await GameEntry.Web.GetToBytes("https://example.com/file", queryString);
```

**Post オブジェクトフォーム**:`byte[]` オーバーロードに加えて、`PostToBytes` は `Dictionary<string, object>` フォームもサポートしています(フレームワーク内部でシリアライズしてから送信):

```csharp
Task<WebBufferResult> PostToBytes(string url, Dictionary<string, object> from, object userData = null);
```

出典： [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L506-L508)

**WebGL プラットフォーム**:同一の API は WebGL 環境下で自動的に `UnityWebRequest` に切り替わり、`DefaultBypassCertificate` 証明書ハンドラーがアタッチされるため、呼び出しコードを変更する必要はありません。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `TimeoutException` がスローされる | 非 WebGL プラットフォームでリクエストがタイムアウト(`WebExceptionStatus.Timeout` が `TimeoutException` に変換される) | ネットワークとサーバーの可用性を確認するか、マネージャーの `RequestTimeout` 設定値を大きくする |
| `Exception` がスローされる(内容は `unityWebRequest.error` の原文) | WebGL 環境下で `isNetworkError` / `isHttpError` が真 | error テキストに基づいて原因を特定:404 の場合は URL を確認、`crossdomain` の場合はクロスドメイン設定を確認 |
| `WebException` / `IOException` がスローされる | 非 WebGL プラットフォームでレスポンスストリームの読み取り失敗または接続の中断 | try/catch で捕捉して再試行；サーバーがバイナリストリームを返していることを確認 |
| サーバーが文字化けしたデータを受信する | サーバー側が `application/octet-stream` として解析していない | フレームワークはこの Content-Type を固定で送信するため、サーバー側はリクエストボディを生のバイトとして読み取る必要がある |

タイムアウトと例外の変換ロジックのソースコード:

```csharp
// タイムアウト例外を捕捉
if (e.Status == WebExceptionStatus.Timeout)
{
    webData.TaskSource.SetException(new TimeoutException(e.Message));
    return;
}
```

出典： [WebManager.Binary.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.Binary.cs#L161-L170)

## 背景

バイナリリクエストは `WebManager` の partial 実装である `WebManager.Binary.cs` によって処理されます:リクエストはまず `m_WaitingBinaryQueue` 待機キューに入り、`UpdateBinary` が `MaxConnectionPerServer` の同時接続上限に従って 1 つずつ取り出して実行します。非 WebGL プラットフォームでは `HttpWebRequest` + メモリストリームコピーを使用し、WebGL プラットフォームでは `UnityWebRequest` を使用します。`WebBinaryData` オブジェクトは参照プールを通じて再利用され、完了後に自動的に `Release` されます。Web モジュール全体の構造については、『Web モジュール概要』を参照してください。
