# 运行模式不支持或初始化失败怎么办

`AssetManager` 在初始化资源包时会按 `EPlayMode` 分派到四个具体初始化方法(Editor 模拟/单机/联机/WebGL);模式值不在枚举内会直接抛出异常,模式与平台不匹配、URL 缺失或 YooAsset 未先初始化也会导致初始化失败。下面给出常见症状与对应修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `ArgumentOutOfRangeException: Unsupported play mode: <值>` | `PlayMode` 不在 `EPlayMode` 四个合法值内 | 见下文「修复步骤 1」 |
| 打包/真机上使用 `EditorSimulateMode`,资源加载报错 | 非编辑器环境自动被强制改为 `HostPlayMode`,但 URL 未配置 | 见下文「修复步骤 2」 |
| WebGL 平台选了 `HostPlayMode` 等非 Web 模式,初始化失败 | WebGL 强制使用 `WebPlayMode`,非 Web 模式不被支持 | 见下文「修复步骤 3」 |
| `hostServerURL is null` 或资源包无法创建 | 联机/Web 模式下 URL 未传入;YooAsset 未先初始化 | 见下文「修复步骤 4」 |
| `Asset manager is invalid.` | `_assetManager` 模块未注册 | 见下文「修复步骤 5」 |

## 修复步骤

### 1. `PlayMode` 取值非法

`AssetManager.CreateInitializationOperationHandler` 用 `switch` 匹配四种合法模式,默认分支直接抛异常:

```csharp
default:
{
    throw new ArgumentOutOfRangeException(nameof(PlayMode), PlayMode, $"Unsupported play mode: {PlayMode}");
}
```

Source: [AssetManager.Initialization.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.Initialization.cs#L42-L46)

确认 `AssetComponent.GamePlayMode` 字段(Inspector 中名为 `m_GamePlayMode`)的值在 `EditorSimulateMode / OfflinePlayMode / HostPlayMode / WebPlayMode` 四个枚举值之内,且没有被外部脚本错误地赋成 `(EPlayMode)999` 之类的整数。

### 2. 运行时误用 `EditorSimulateMode`

`AssetComponent.Awake` 在非编辑器环境会把 `EditorSimulateMode` 强制改成 `HostPlayMode`,而联机模式必须提供下载 URL:

```csharp
#if !UNITY_EDITOR
    if (GamePlayMode == EPlayMode.EditorSimulateMode)
    {
        GamePlayMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    GamePlayMode = EPlayMode.WebPlayMode;
#endif
#endif
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L65-L73)

修复:出包前把 `GamePlayMode` 改成与目标平台匹配的合法值(单机版用 `OfflinePlayMode`,联机版用 `HostPlayMode` 并填好 `hostServerURL`)。

### 3. WebGL 平台选了非 Web 模式

WebGL 会被强制改写为 `WebPlayMode`;若仍要按 `HostPlayMode` 走 CDN/小游戏方案,需要在调用 `InitPackageAsync` 时传入正确的 `hostServerURL` 与 `fallbackHostServerURL`,并确保对应小游戏平台宏(`ENABLE_DOUYIN_MINI_GAME`、`ENABLE_WECHAT_MINI_GAME`、`ENABLE_KUAISHOU_MINI_GAME` 等)被启用,以走相应的 `ByteGame/Wechat/Kuaishou` 文件系统分支(参见 `InitializeYooAssetWebPlayMode`)。

### 4. URL 缺失或 YooAsset 未初始化

`AssetManager.Initialize` 必须先于 `InitPackageAsync` 调用,否则 YooAsset 内部状态不完整:

```csharp
public void Initialize()
{
    Log.Info($"资源系统运行模式：{PlayMode}");
    YooAssets.Initialize();
    YooAssets.SetOperationSystemMaxTimeSlice(Milliseconds > 0 ? Milliseconds : 30);
    Log.Info("Asset Init Over");
}
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L45-L54)

`InitPackageAsync` 会对入参做 `NotNull` 校验,任一为空会抛 `ArgumentNullException`:

```csharp
GameFrameworkGuard.NotNull(packageName, nameof(packageName));
GameFrameworkGuard.NotNull(hostServerURL, nameof(hostServerURL));
GameFrameworkGuard.NotNull(fallbackHostServerURL, nameof(fallbackHostServerURL));
```

Source: [AssetManager.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetManager.cs#L69-L71)

修复:确认 `AssetComponent.Start` 已触发(它会调用 `_assetManager.Initialize()`),再调用 `InitPackageAsync(packageName, host, fallbackHost, isDefaultPackage:true)` 时传入合法 URL。

### 5. `Asset manager is invalid.`

`AssetComponent.Awake` 取不到 `IAssetManager` 模块时打印致命日志并直接返回:

```csharp
_assetManager = GameFrameworkEntry.GetModule<IAssetManager>();
if (_assetManager == null)
{
    Log.Fatal("Asset manager is invalid.");
    return;
}
```

Source: [AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L77-L82)

修复:确认 GameFrameX 框架入口(`GameEntry`)已在场景中,且 `AssetComponent` 的 `ImplementationComponentType`/`InterfaceComponentType` 配置正确,框架能反射构造出 `AssetManager` 实现类。

## 验证

1. 在 Unity Console 中确认能看到日志 `资源系统运行模式：<PlayMode>` 和 `Asset Init Over`,两者都出现说明 `Initialize()` 走完。
2. 调用 `InitPackageAsync` 后,等待 `InitializationOperation` 完成;若返回 `true` 且 `Status == EOperationStatus.Succeed`,表示资源包初始化成功。
3. 触发一次 `LoadAssetAsync`,确认能拿到 `AssetHandle`,且 `LastError` 为空。
4. 在出包平台(WebGL/Android/iOS)重复上述步骤,确认没有再抛出 `Unsupported play mode` 或 `hostServerURL is null`。
