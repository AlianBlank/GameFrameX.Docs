# 如何为 WebGL 单机或无后端场景跳过远程请求

在 WebGL 单机版或没有业务后端的场景下,通过 `StartupOptions.SkipRemoteStartupRequests` 或 `EPlayMode.OfflinePlayMode` 跳过全局信息、App 版本、资源包版本等远程请求,直接进入本地资源初始化,避免启动卡在网络等待或失败报错。

## 前置条件

- 已创建 `StartupOptions` 资产(`Assets > Create > GameFrameX > Startup Options`)。
- 资源运行模式(`GamePlayMode`)不是 `EditorSimulateMode`,否则编辑器下默认就会跳过全局信息。
- `StartupOptions` 资产已注入到启动流程(通过 `StartupRunner` / 引导组件的 `SetOptions` 或默认加载)。

## 操作步骤

### 方案 A:仅打开跳过开关(推荐 WebGL 单机)

在 Inspector 选中 `StartupOptions` 资产,展开 **Network** 分类,勾选 **Skip Remote Startup Requests**。

```csharp
// Runtime/Startup/StartupOptions.cs
[Tooltip("是否跳过远程启动请求（全局信息、App 版本、资源包版本）。WebGL 单机等无后端场景启用，直接进入本地资源初始化。")]
public bool SkipRemoteStartupRequests = false;
```

Source: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31)

代码侧也可运行时切换:

```csharp
using GameFrameX.Startup.Runtime;

var options = Resources.Load<StartupOptions>("StartupOptions");
options.SkipRemoteStartupRequests = true;
```

启动流程在 `ProcedureGetGlobalInfoState.OnEnter` 读取该开关,若为 `true` 则跳过远程请求,直接进入 `ProcedurePatchInit`:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var options = StartupProcedureUtility.GetOptions(procedureOwner);
if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

Source: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L42-L48)

### 方案 B:把运行模式切到 Offline

把 `StartupOptions.GamePlayMode` 设为 `EPlayMode.OfflinePlayMode`(YooAsset 的离线模式,使用本地打包好的资源)。`ProcedureGetGlobalInfoState` 会先于跳过开关匹配 OfflinePlayMode:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

Source: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L35-L40)

Offline 模式下后续 Patch 流程同样会短路: `ProcedurePatchInit`、`ProcedureUpdateManifest`、`ProcedureUpdateStaticVersion` 都对 `OfflinePlayMode` 做了直接跳过处理,不再请求远端清单。

Source: [ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L36) · [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L42) · [ProcedureUpdateStaticVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateStaticVersion.cs#L49)

## 常见变体

| 场景 | 推荐做法 | 关键开关 |
|------|----------|----------|
| WebGL 单机(有 YooAsset 资源但无版本服务) | `SkipRemoteStartupRequests = true`,`GamePlayMode` 保持单机模式 | SkipRemoteStartupRequests |
| WebGL 完全离线(本地构建产物) | `GamePlayMode = OfflinePlayMode` | GamePlayMode |
| 编辑器内调试无后端 | `GamePlayMode = EditorSimulateMode` | GamePlayMode |

三种模式在 `ProcedureGetGlobalInfoState.OnEnter` 中的匹配顺序为: EditorSimulateMode → OfflinePlayMode → `SkipRemoteStartupRequests` → 真实远程请求。

## 常见错误

- **只勾选了 Skip 但 GamePlayMode 仍是联网模式**:跳过开关仅跳过"启动阶段"的远程请求,如果 Patch 流程指向远端 CDN 且没有本地清单,会在 `ProcedureUpdateManifest` / `ProcedureUpdateStaticVersion` 阶段继续等待网络响应。
- **Offline 模式下未准备本地资源**:OfflinePlayMode 假定 YooAsset 已经在 `StreamingAssets` 准备好整包资源,否则后续加载会报"找不到包"或"清单为空"。
- **修改 SO 后未生效**:对 `StartupOptions` 的运行时修改必须在启动流程开始之前(组件初始化前)完成;若在 FSM 启动后再赋值,需要重启场景或调用 `StartupRunner.Restart()`。
- **WebGL 跨域策略未配置**:即使是单机版,WebGL 仍需正确响应 CORS;如果仍要保留一条"可选"远端 URL,务必在 Web 服务器配置 `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` 或使用服务端代理。

## 验证

启动游戏,在 Console 中应当看到下列日志之一(取决于方案选择),且不应出现 "Loading... (x/y)" 这类网络等待提示:

- `Skip remote startup requests option enabled, skip remote startup requests.`
- `Offline play mode, skip remote startup requests.`
- `Editor simulate mode, skip global info request.`

随后流程应直接进入本地资源初始化(打开 UI 资源、加载本地清单等),并最终进入业务场景。

## 背景(可选)

启动流程默认按 `ProcedureGetGlobalInfoState → ProcedureGetAppVersionInfoState → ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState → ProcedurePatchInit` 顺序执行,前三个节点均会向远端发起 HTTP 请求。WebGL 单机或演示场景往往没有可用后端,因此在最早节点(`ProcedureGetGlobalInfoState`)统一拦截,可以避免一连串无意义的失败重试,缩短首屏时间。

关于启动流程的整体架构,见《Runtime/Procedures/Startup》目录下的流程源码。
