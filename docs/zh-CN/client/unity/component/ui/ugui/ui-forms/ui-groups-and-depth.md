# 如何使用 UI 分组（UIGroup）控制 Canvas 层级与深度

通过 `UIGroup`（界面组）可以把打开的界面按业务分组挂到不同 `RectTransform` 节点上，组内每加一层就以 1000 为步长往后推 `Z` 轴深度，从而决定绘制顺序与点击命中顺序。本页给出最常见的两种用法：在界面上用特性声明组，以及运行时手动加入组。

## 前置条件

- 工程已引入 GameFrameX 与 `com.gameframex.unity.ui.ugui`，UI 框架在场景里已通过 `UIComponent` 完成初始化（场景中存在 `UGUICanvas`、`UGUICamera`、`EventSystem` 等节点，这些由 `UGUIUIGroupHelper.EnsureRuntimeRoot` 在首次打开界面时按需创建）。
- 你已经知道要打开的界面类实现了 `IUIForm`（或继承自 `UIForm` / 框架代码生成器生成的基类）。

## 操作步骤

### 方式一：用 `OptionUIGroupAttribute` 把界面绑定到组

在界面类型上声明 `OptionUIGroup` 特性，`UGUIFormHelper` 会自动从 `UIComponent` 取出同名组并赋给 `uiForm.UIGroup`。

```csharp
using GameFrameX.UI.Runtime;

[OptionUIGroup("HUD")]
public sealed class HUDForm : UIForm
{
    // ...
}
```

`UGUIFormHelper` 会先读取 `uiForm.UIGroup`，若为空则按特性中的 `GroupName` 调用 `m_UIComponent.GetUIGroup(...)`：

```csharp
// 来源：UGUIFormHelper.cs
var uiGroup = uiForm.UIGroup;
if (uiGroup == null)
{
    var attribute = uiFormType.GetCustomAttribute(typeof(OptionUIGroupAttribute));
    if (attribute is OptionUIGroupAttribute optionUIGroup)
    {
        uiGroup = m_UIComponent.GetUIGroup(optionUIGroup.GroupName);
    }

    uiForm.UIGroup = uiGroup;
}
```

Source: [UGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIFormHelper.cs#L112-L122)

### 方式二：运行时手动指定组

在调用 `UIComponent.OpenUIForm`（或通过 `UIManager.OpenUIForm` 间接调用）前，自己从 `UIComponent` 拿到目标 `IUIGroup`，并写入 `uiForm.UIGroup`。

```csharp
var group = GameEntry.UI.GetUIGroup("Popup"); // 例如取名为 "Popup" 的组
// 打开界面后写入组
uiForm.UIGroup = group;
```

写入完成后，`UIManager.Open` 中会将组作为参数传给 `uiForm.Init(...)`，后续打开/关闭/聚焦均按该组进行管理：

```csharp
// 来源：UIManager.Open.cs
var uiGroup = uiForm.UIGroup;
uiForm.Init(serialId, uiFormAssetPath, uiFormAssetName, uiGroup, null,
    pauseCoveredUIForm, isNewInstance, userData, RecycleInterval, isFullScreen);
```

Source: [UIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UIManager.Open.cs#L200-L201)

### 深度是如何算出来的

每个组通过 `UGUIUIGroupHelper` 创建时会得到一个 `RectTransform`，组下子节点靠 `localPosition.z` 拉开距离：

```csharp
// 来源：UGUIUIGroupHelper.cs
public override void SetDepth(int depth)
{
    Depth = depth;
    transform.localPosition = new Vector3(0, 0, depth * 1000);
}
```

Source: [UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L66-L70)

要点：

- `Depth` 是该组在所有组里的索引（通常由 `UIComponent` 按创建顺序分配）。
- 同一组内的多个界面，会以 1000 为单位按打开顺序往后叠，因此在 `ScreenSpaceCamera` 的 `Canvas`（`planeDistance = 100f`，`sortingOrder = 0`）下绘制顺序就是确定的。
- 想让某些界面盖在另一些之上，要么放到索引更大的组，要么在该组内让后开的盖住先开的。

### 组的运行时结构

调用 `Handler(...)` 时会执行：

1. 调用 `SetDepth(depth)` 把当前节点的 `z` 设为 `depth * 1000`；
2. 通过 `EnsureRuntimeRoot` 确保根下有 `UGUICamera`、`UGUICanvas`、`EventSystem`；
3. 在 `root` 下创建名为 `groupName` 的 `GameObject`，挂 `RectTransform` 并铺满；
4. 把整个节点及其子节点的层级设为 `UI`；
5. 调用 `Helper.CreateHelper` 在该节点上挂一个 `UGUIUIGroupHelper` 实例（或者你传入的自定义辅助器）：

```csharp
// 来源：UGUIUIGroupHelper.cs
GameObject component = new GameObject(groupName);
component.transform.SetParent(root, false);
var uiLayer = LayerMask.NameToLayer("UI");
component.SetLayerRecursively(uiLayer);

RectTransform rectTransform = component.GetOrAddComponent<RectTransform>();
rectTransform.MakeFullScreen();
var uiGroupHelper = Helper.CreateHelper(component, uiGroupHelperTypeName,
    (UIGroupHelperBase)customUIGroupHelper, 0);
return uiGroupHelper;
```

Source: [UGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.ugui/blob/main/Runtime/UGUIUIGroupHelper.cs#L86-L113)

最终场景层级大致是：

```
UIComponent
└── UGUICanvas (Canvas, CanvasScaler, GraphicRaycaster)
    ├── Default (组 0)
    │   ├── FormA
    │   └── FormB
    ├── HUD (组 1)
    │   └── HUDForm
    └── Popup (组 2)
        └── PopupForm
```

## 常见变体

- **多组分层**：把 `HUD`、`Popup`、`Dialog`、`Loading` 等不同用途的界面分到不同组，组之间靠 `depth * 1000` 自然分层。
- **替换默认辅助器**：实现 `IUIGroupHelper`（继承 `UIGroupHelperBase`），然后在调用 `UIComponent` 添加组时通过 `customUIGroupHelper` 参数传入，覆盖默认的 `UGUIUIGroupHelper` 行为（例如自定义深度算法或额外组件）。
- **编辑器自定义**：在 Inspector 中可通过 `UGUIComponentInspector` 等编辑器脚本查看/调整组与深度。

## 常见错误

- **未声明 `OptionUIGroup` 也未手动赋值**：进入 `UGUIFormHelper` 后 `uiGroup` 为 `null`，最终会触发日志 `UI group is invalid.` 并返回 `null`，界面打开失败。
- **组名拼写错误**：使用 `OptionUIGroup("Popuo")` 但 `UIComponent` 中实际叫 `"Popup"`，`GetUIGroup` 返回 `null`，同样会触发 `UI group is invalid.`。约定好统一常量避免拼写错。
- **期望通过 `Canvas.sortingOrder` 改层级**：本套实现里组级 `Canvas.sortingOrder` 固定为 `0`，组内/组间靠 `localPosition.z = depth * 1000` 拉开。直接在 Inspector 改 `sortingOrder` 会被下次 `Handler(...)` 覆盖。
- **在 `UGUICanvas` 下手动塞节点又忘了设 `UI` 层**：虽然 `UGUIUIGroupHelper` 创建的节点会 `SetLayerRecursively(uiLayer)`，但你自己挂上去的辅助 UI 子节点仍需要保持 `UI` 层，否则会被 `UGUICamera` 的 `cullingMask` 剔掉。

## 背景（可选）

`UIGroup` 的思路源自经典 GameFrameX 框架的界面分组：所有界面共享一个 `UGUICanvas`，通过 `Z` 轴偏移避免多 Canvas 互相覆盖，再借助 `GraphicRaycaster` 完成点击分发。`SetDepth` 把 `depth` 直接放大 1000 倍，是为了给同组内的多次"提到最前"留出足够槽位——只要在 `Depth` 同一位再叠加小步长偏移，就能稳定地把某个界面顶到组内最上层而不影响其他组。
