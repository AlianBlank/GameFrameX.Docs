# How to Add a New Business Module (Apps Layer)

Under the `GameFrameX.Apps` project, follow the `Component` + `Entity` + `State` directory convention to add a new business sub-module, which is then called by the Hotfix layer. This completes a minimal usable business module integration.

## Prerequisites

- The `GameFrameX.Server.Source` repository has been cloned and can compile, with `.NET 8+` SDK available.
- You are familiar with the location of the `GameFrameX.Apps` project: `GameFrameX.Apps/`.
- It is known that `GameFrameX.Hotfix` references `GameFrameX.Apps` via `<ProjectReference>` (refer to [GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj#L18)).

## Steps

The following uses adding a `Player/Mail` module as an example to demonstrate the complete steps from directory, component, state to being called by Hotfix.

1. **Create a sub-module folder according to the directory convention**.
   Create a new subdirectory under `GameFrameX.Apps/`. A two-level structure is recommended: `{Domain}/{Module}/{Component|Entity}`.
   For example, adding a Mail module:
   ```text
   GameFrameX.Apps/Player/Mail/Component/MailComponent.cs
   GameFrameX.Apps/Player/Mail/Entity/MailState.cs
   ```
   Existing examples can be referenced from the directory structure of `Account/Login` and `Player/Bag` ([LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L30-L46), [BagComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Player/Bag/Component/BagComponent.cs)).

2. **Create an entity state class (Entity/State)**.
   Inherit from the `CacheState` provided by the framework. Only include business fields, not behavior methods. For example, the `LoginState` is written as:
   ```csharp
   namespace GameFrameX.Apps.Account.Login.Entity;

   public class LoginState : CacheState
   {
       public string NickName { get; set; }
       public string UserName { get; set; }
       public uint Level { get; set; }
       // ... other business fields
   }
   ```
   Source: [LoginState.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Entity/LoginState.cs#L30-L72)

3. **Create a component class (Component) and bind it to the state and Actor type**.
   Inherit from `StateComponent<TState>`, and use the `[ComponentType]` attribute to declare the Actor it belongs to. For example, `LoginComponent` is bound to `ActorTypeServer`:
   ```csharp
   using GameFrameX.Apps.Account.Login.Entity;

   namespace GameFrameX.Apps.Account.Login.Component;

   [ComponentType(GlobalConst.ActorTypeServer)]
   public sealed class LoginComponent : StateComponent<LoginState>
   {
       protected override bool IsCreateDefaultState { get; set; } = false;

       public async Task<PlayerState> OnPlayerLogin(ReqPlayerLogin reqLogin)
       {
           MetricsPlayerHelper.LoginCounterOptions.Inc();
           return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
       }
   }
   ```
   Source: [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L30-L46)

4. **Keep the namespace consistent with the directory**.
   The component namespace is `GameFrameX.Apps.{Domain}.{Module}.Component`, and the state namespace is `GameFrameX.Apps.{Domain}.{Module}.Entity`, aligned with `global using` ([GlobalUsings.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/GlobalUsings.cs)).

5. **Call the new component in `GameFrameX.Hotfix`**.
   The Hotfix layer accesses the new module through the `Component` framework interface. For example, `LoginComponent.OnPlayerLogin` is called by the Hotfix login message handler entry. No additional registration is required in `AppsHandler.cs` (currently `AppsHandler` is an empty class, see [AppsHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/AppsHandler.cs#L31-L34)).

6. **Compile and verify**.
   Execute in the repository root directory:
   ```bash
   dotnet build GameFrameX.Apps/GameFrameX.Apps.csproj
   ```
   If the compilation succeeds, it means the new module has been successfully integrated.

## Common Variants

- **Bind to a different Actor type**: Replace the constant in `[ComponentType(GlobalConst.ActorTypeServer)]` with the Actor required by the business (refer to [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L36)).
- **Whether to create state by default**: When the business wants a default `State` to be automatically initialized when the Actor is created, set `IsCreateDefaultState` to `true`; if you want it to be created only on the first persistence, keep it as `false` (refer to [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L39)).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `dotnet build` reports `CacheState` / `StateComponent<T>` / `GlobalConst` cannot be found | The corresponding `global using` is not imported or the project reference is missing | Confirm that `GameFrameX.Hotfix.csproj` references `GameFrameX.Apps.csproj` (see [GameFrameX.Hotfix.csproj#L18](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj#L18)) |
| Component methods cannot be found in Hotfix | The namespace is not consistent with the directory, or the class is not marked `public` | Name it according to `GameFrameX.Apps.{Domain}.{Module}.Component`, and declare the class as `public sealed` |
| `ComponentType` attribute reports an error | An incorrect Actor constant is used | Use defined constants such as `GlobalConst.ActorTypeServer` |
