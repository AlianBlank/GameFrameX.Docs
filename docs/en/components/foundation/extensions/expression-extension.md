# How to Use the Expression Tree/Path Combination Extension

`ExpressionExtension` provides a set of chainable combination methods for `Expression<Func<T, bool>>`, allowing you to safely combine multiple independently written predicate expressions into a new expression without manually writing boilerplate code such as `Expression.AndAlso` / `ParameterExpression`. It is commonly used in scenarios like dynamic query condition combination and filtering pipelines.

## Prerequisites

- The project references `GameFrameX.Foundation.Extensions`.
- At the top of the file, `using System.Linq.Expressions;` and `using GameFrameX.Foundation.Extensions;`.
- The target framework supports `Expression<Func<T, bool>>` (standard .NET is sufficient).

## Steps

### 1. Combine Two Conditions with `And`

Use `And` when both the left and right expressions must hold (internally uses `Expression.AndAlso`, supporting short-circuit evaluation).

```csharp
using System.Linq.Expressions;
using GameFrameX.Foundation.Extensions;

Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.And(expr2);

bool ok1 = combined.Compile()("testing"); // true
bool ok2 = combined.Compile()("test");    // false
```

### 2. Combine Two Conditions with `Or`

Use `Or` when either expression holding is sufficient (internally uses `Expression.OrElse`, supporting short-circuit evaluation).

```csharp
Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.Or(expr2);
bool ok = combined.Compile()("test"); // true: matches StartsWith("test")
```

Source: [ExpressionExtension.cs#L114-L125](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L114-L125)

### 3. Combine Conditionally with `AndIf` / `OrIf`

Use the conditional versions when a boolean switch is needed to decide whether an expression actually participates in the combination; when the condition is `false`, the left expression is returned directly, bypassing the visitor and rewriting logic.

```csharp
Expression<Func<string, bool>> left  = s => s.Length > 5;
Expression<Func<string, bool>> right = s => s.StartsWith("test");

bool enableFilter = true;
var withFilter = left.AndIf(() => enableFilter, right);

enableFilter = false;
var withoutFilter = left.AndIf(() => enableFilter, right); // equivalent to left
```

Source: [ExpressionExtension.cs#L83-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L83-L100)

### 4. Negate with `Not`

```csharp
Expression<Func<int, bool>> expr = x => x > 5;
var neg = expr.Not(); // equivalent to x => !(x > 5), i.e., x <= 5
```

### 5. Chaining Multiple Conditions

Since the return value is still `Expression<Func<T, bool>>`, you can chain calls consecutively:

```csharp
Expression<Func<string, bool>> baseExpr = s => s != null;
var query = baseExpr
    .And(s => s.Length > 0)
    .And(s => s.Contains("foo"))
    .OrIf(() => AllowShort, s => s.Length <= 2);
```

## Common Variants

- **Predicate + LINQ providers**: After combining, call `Compile()` to obtain a `Func<T, bool>` for direct filtering; when working with ORMs such as EF Core, pass `combined` directly to `Where(...)`, where it will be translated to SQL.
- **Short-circuiting on empty collections**: Use `IEnumerable.Any()` or similar checks at the outer level to verify non-emptiness before calling `And` / `Or`.
- **Multi-parameter Lambdas**: `CustomExpressionVisitor` only replaces the first parameter of multi-parameter Lambdas, leaving the rest as is.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `ArgumentNullException` (parameter name `leftExpression` / `rightExpression` / `condition` / `expr`) | One of the expressions or the condition delegate is `null` | Null-check expressions before calling, or provide a condition delegate at the outer level that always returns `true` |
| Compilation fails after combining, reporting "parameter mismatch" | The left and right expressions have inconsistent types (e.g., `Func<string,bool>` and `Func<int,bool>`) | Ensure both expressions use the same generic parameter `T` |
| The combined result has no short-circuit behavior | Mistakenly assuming this extension uses `And`/`Or` | This extension's `And`/`Or` internally uses `AndAlso`/`OrElse`, which naturally short-circuits; no extra handling is needed |
| Multi-parameter Lambda behaves abnormally after combining | Only the first parameter is replaced; the rest are kept | Write predicates as single-parameter Lambdas, or rewrite the expression yourself |

## Background (Optional)

`And` / `Or` / `AndIf` / `OrIf` all internally use the internal class `CustomExpressionVisitor` (which inherits from `ExpressionVisitor`) to replace the `ParameterExpression` of each of the left and right expressions with a newly created unified parameter, then reassemble the expression with `Expression.Lambda`. This both preserves the original structure of the left and right subtrees and ensures the new expression has only one parameter, making chaining and cross-ORM translation convenient.
