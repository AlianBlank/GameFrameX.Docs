# 広告枠 ID の設定方法(マルチプラットフォーム)

広告コンポーネント `AdvertisementComponent` には 6 つのプラットフォームの広告枠 ID フィールドが組み込まれており、実行時に現在のビルドプラットフォームに応じて対応する ID を自動的に `AdUnitId` に設定するため、分岐判定コードを記述する必要はありません。

## 前提条件

- `com.gameframex.unity.advertisement` パッケージがインストールされていること。
- シーンに `AdvertisementComponent` が存在すること(メニュー `GameFrameX/Advertisement` から追加)。
- `IAdvertisementManager` を実装する具体的な広告マネージャーが選択されていること(Inspector の `Component Type` で指定)。

## 操作手順

1. **AdvertisementComponent の Inspector を開く**  
   シーンで `AdvertisementComponent` がアタッチされた GameObject を選択すると、Inspector に「デバッグモード」「Config」「広告枠 ID(旧インターフェース)」の 3 つのフィールドグループが表示されます。

2. **各プラットフォームの広告枠 ID を入力する**  
   「広告枠 ID(旧インターフェース)」の見出しの下で、各プラットフォームで広告管理画面から取得した ID を入力します:

   | Inspector 表示名 | シリアライズフィールド | 対応プラットフォーム |
   |------------------|------------|----------|
   | Android 広告枠ID | `m_adUnitIdAndroid` | `UNITY_ANDROID` |
   | IOS 広告枠ID | `m_adUnitIdiOS` | `UNITY_IOS` |
   | WebGL 広告枠ID | `m_adUnitIdWebGL` | ブラウザ標準 `UNITY_WEBGL` |
   | WebGL WeChat 広告枠ID | `m_adUnitIdWebGLWeChat` | WeChat ミニゲーム(マクロ `ENABLE_WECHAT_MINI_GAME`) |
   | WebGL DouYin 広告枠ID | `m_adUnitIdWebGLDouYin` | DouYin ミニゲーム(マクロ `ENABLE_DOUYIN_MINI_GAME`) |
   | WebGL KuaiShou 広告枠ID | `m_adUnitIdWebGLKuaiShou` | KuaiShou ミニゲーム(マクロ `ENABLE_KUAISHOU_MINI_GAME`) |

   ソースコード内のフィールド定義は [AdvertisementComponent.cs#L47-L57](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57)、Inspector での表示名は [AdvertisementComponentInspector.cs#L26-L31](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L26-L31) を参照してください。

3. **実行時に ID が選択される仕組みを理解する**  
   コンポーネントは `Awake` 段階でプリプロセッサディレクティブによりプラットフォームごとの ID を選択し、`AdUnitId` プロパティに書き込みます:

   ```csharp
   AdUnitId =
   #if UNITY_WEBGL
   #if ENABLE_WECHAT_MINI_GAME
       m_adUnitIdWebGLWeChat
   #elif ENABLE_DOUYIN_MINI_GAME
       m_adUnitIdWebGLDouYin
   #elif ENABLE_KUAISHOU_MINI_GAME
       m_adUnitIdWebGLKuaiShou
   #else
       m_adUnitIdWebGL
   #endif
   #elif UNITY_ANDROID
       m_adUnitIdAndroid
   #elif UNITY_IOS
       m_adUnitIdiOS
   #else
       string.Empty
   #endif
       ;
   ```
   ソース: [AdvertisementComponent.cs#L99-L117](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L99-L117)

   選択の優先順位:WebGL ミニゲームマクロ → 汎用 WebGL → Android → iOS、一致しないプラットフォームでは空文字列が返されます。

4. **初期化時の設定オブジェクトを確認する**  
   コンポーネントの `Start` 時、`Config` が null でない場合、`IAdvertisementManager.Initialize(config)` が呼び出されます([AdvertisementComponent.cs#L120-L126](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L126) 参照)。具体的な広告枠 ID は各マネージャー実装内部で `AdUnitId` を読み取ります。

## よくあるバリエーション

- **コードから実行時に ID を指定する(非推奨)**  
  `Initialize(string adUnitId, bool isDebug = false)` を呼び出すこともできますが、このオーバーロードは `[Obsolete("Use Initialize(AdvertisementConfig) instead.")]` が付与されているため、新しいコードでは `Initialize(AdvertisementConfig)` の設定オブジェクト方式を使用してください。
- **WebGL ミニゲームのチャネルごとに個別設定する**  
  WeChat / DouYin / KuaiShou の ID はそれぞれ独立して保存されるため、同じ文字列にチャネルプレフィックスを手動で記述する必要はありません。対応するマクロがビルド時に有効になっていれば、コンポーネントが自動的に選択します。
- **`Config` サブクラスで広告枠 ID を保持する**  
  `Component Type` で選択したマネージャーが `[AdvertisementConfigAttribute(typeof(YourConfig))]` を宣言している場合、Inspector はその Config 型に応じてフィールドを動的に描画します([AdvertisementComponentInspector.cs#L127-L139](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Editor/Inspector/AdvertisementComponentInspector.cs#L127-L139) 参照)。Config サブクラスに直接プラットフォームフィールドを追加することで、旧インターフェースの 6 つの `m_adUnitIdXxx` を置き換えられます。

## よくあるエラー

| 症状 | 原因 | 対処 |
|------|------|------|
| `AdUnitId` が空文字列になる | 現在のビルドプラットフォームに一致する `#if` 分岐がない(例:デスクトップ Standalone) | デスクトッププラットフォームで広告枠が必要な場合は、Config サブクラスにデフォルト値を提供するか、コードで `AdUnitId` を手動設定する |
| WeChat ミニゲームで `WebGL 広告枠ID` が読み込まれる | ビルドマクロ `ENABLE_WECHAT_MINI_GAME` が有効になっていない | 「Project Settings → Player → WebGL → Publishing Settings」で対応するミニゲームプラットフォームのサポートを有効にする |
| Inspector に 6 つの広告枠フィールドが表示されない | コードで `HideInInspector` またはカスタムエディタにより非表示にしている | デフォルトの Inspector `GameFrameX/Advertisement/AdvertisementComponentInspector` を使用していることを確認する |
| `Initialize(string, bool)` 呼び出しで警告が出る | このオーバーロードは `[Obsolete]` である | `Initialize(AdvertisementConfig)` に変更し、ID を Config サブクラスに格納する |

## 検証

1. Inspector で各ターゲットプラットフォームに空でない ID を入力する(プレースホルダ文字列で自己確認可能)。
2. Build Target を切り替え(Android、iOS、WebGL)、それぞれビルドして実行後、`Debug.Log(adComponent.AdUnitId)` で出力結果がそのプラットフォームの ID であることを確認する。
3. WebGL ミニゲーム:WeChat Developer Tools / DouYin Developer Tools でそれぞれビルドし、対応するマクロが有効になっていること、正しいフィールド値が読み込まれていることを確認する。

## 補足(任意)

`AdvertisementComponent` はプラットフォーム分岐を `Awake` の1か所に集約し、実行時には `AdUnitId` という単一の値のみを公開することで、下流の広告マネージャーが ID を扱う処理を簡素化しています。`AdvertisementConfig` 基底クラスは `isDebug` のみを公開し、具体的なプラットフォームパラメータは各マネージャーが `[AdvertisementConfigAttribute]` で指定した Config サブクラスで定義します。これは旧 6 プラットフォームフィールドと並行して存在します。
