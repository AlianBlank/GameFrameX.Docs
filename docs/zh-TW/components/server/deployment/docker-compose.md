# 使用 Docker / docker-compose 部署伺服器

按照本頁步驟操作，你可以在幾分鐘內用 `docker-compose` 把 GameFrameX 伺服器和 MongoDB 資料庫架設起來，並透過容器磁碟區掛載實現設定、熱更和日誌的持久化。

## 前置條件

- 已安裝 Docker Engine 20.10+ 與 Docker Compose v2(命令列執行 `docker compose version` 驗證)
- 宿主機已開放以下連接埠:`27017`(MongoDB)、`28080`(HTTP)、`29090`(APM)、`29100`(TCP)、`29110`(WebSocket)
- 專案儲存庫根目錄存在 `Dockerfile` 與 `docker-compose.yml`(見下)

## 設定檔案結構

儲存庫根目錄提供兩個開箱即用的檔案：

| 檔案 | 作用 |
|------|------|
| [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48) | 多階段建置：基於 `mcr.microsoft.com/dotnet/sdk:10.0` 編譯專案，基於 `aspnet:10.0` 執行，最終映像檔進入點為 `/app/entrypoint.sh dotnet GameFrameX.Launcher.dll` |
| [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L1-L148) | 定義 `mongodb` 與 `gameframex` 兩個服務，共用 `gameframex` bridge 網路，並把宿主機的 `./running/*` 掛載進容器實現持久化 |

## 操作步驟

### 1. 準備宿主機的持久化目錄

`docker-compose.yml` 把以下宿主機目錄掛載到容器中(目錄不存在時，`docker compose` 會自動建立):

| 宿主機目錄 | 容器掛載點 | 用途 |
|------------|------------|------|
| `./running/database` | `/data/db` | MongoDB 資料檔案 |
| `./running/hotfix` | `/app/hotfix` | 熱更新 DLL |
| `./running/json` | `/app/json` | JSON 設定 |
| `./running/logs` | `/app/data/logs` | 應用程式日誌 |
| `./running/GameAnalytics` | `/GameAnalytics` | 遊戲分析資料 |

```bash
mkdir -p running/{database,hotfix,json,logs,GameAnalytics}
```

### 2. 啟動服務

在儲存庫根目錄執行：

```bash
docker compose up -d --build
```

首次執行會依序提取 MongoDB 映像檔並按 [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L5-L23) 建置 GameFrameX 映像檔(`GameFrameX.Launcher` + `GameFrameX.Hotfix` 雙專案 publish)。映像檔啟動進入點由 [entrypoint.sh](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L33-L42) 寫入：

```sh
#!/bin/sh
if [ -z "$(ls -A /app/hotfix 2>/dev/null)" ]; then
    echo "hotfix directory is empty, copying defaults..."
    cp -r /app/hotfix-default/* /app/hotfix/
fi
if [ -z "$(ls -A /app/json 2>/dev/null)" ]; then
    echo "json directory is empty, copying defaults..."
    cp -r /app/json-default/* /app/json/
fi
exec "$@"
```

> 該指令碼保證了宿主機 `./running/hotfix`、`./running/json` 為空時，會從映像檔內建的預設值複製一份，免去首次部署的人工設定。

### 3. 驗證服務狀態

```bash
docker compose ps
docker compose logs -f gameframex
```

資料庫連線字串已在 compose 中預設設定：

```yaml
DataBaseUrl=mongodb://admin:admin@mongodb:27017/?authSource=admin
DataBaseName=gameframex
```

成功啟動後，用戶端可透過 `29100`(TCP)、`29110`(WebSocket)、`28080`(HTTP) 連線。

## 關鍵設定項目速查

[docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L14-L139) 中公開的常用環境變數：

| 環境變數 | 預設值 | 說明 |
|----------|--------|------|
| `ServerType` | `Game` | 伺服器類型，多程序用逗號分隔，如 `Game,Social,Chat` |
| `ServerId` | `1000` | 伺服器 ID,合服時需保持一致 |
| `InnerPort` / `OuterPort` | `29100` | 內部通訊連接埠 / 外部用戶端連線連接埠 |
| `HttpPort` | `28080` | HTTP 服務連接埠 |
| `WsPort` | `29110` | WebSocket 連接埠(需配合 `IsEnableWebSocket=true`) |
| `APMPort` | `29090` | APM 效能監控連接埠 |
| `DataBaseUrl` | `mongodb://admin:admin@mongodb:27017/?authSource=admin` | MongoDB 連線字串 |
| `DataBaseName` | `gameframex` | 資料庫名稱 |
| `DiscoveryCenterIp` / `DiscoveryCenterPort` | `127.0.0.1` / `10001` | 服務探索中心位址 |

其餘被註解掉的環境變數(如 `IsEnableTcp`、`IsOpenTelemetry`、`LogIsGrafanaLoki` 等)均保留了預設值，可依需求取消註解。

## 常見變體

- **單程序模式**：取消 [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server/blob/main/docker-compose.yml#L33-L34) 第 33 行的註解，把 `IsSingleMode` 設為 `true`,並把 `ServerType` 調整為單一值。
- **外部 MongoDB**:把 `DataBaseUrl` 改為外部位址(例如 `mongodb://user:pass@your-mongo-host:27017/?authSource=admin`),並刪除 compose 中的 `mongodb` 服務區塊。
- **HTTPS / WSS**:啟用 `HttpsPort`、`WssPort`、`WssCertFilePath` 三個環境變數，並將憑證掛載進容器。

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| `gameframex` 啟動報 `Unable to connect to MongoDB` | `DataBaseUrl` 中的帳號或 `mongodb` 服務名稱不相符 | 確認帳號 `admin/admin` 與服務名稱 `mongodb` 與 compose 中定義一致 |
| `http://localhost:28080` 無法存取 | 宿主機防火牆未開放連接埠 | 開放 28080,或修改 compose 中 `ports` 的對應 |
| 熱更檔案未生效 | `./running/hotfix` 未掛載或為空 | entrypoint.sh 會自動從映像檔預設目錄複製一次，確保宿主機目錄可寫 |
| 建置階段 `dotnet restore` 失敗 | 子專案 csproj 路徑變更 | 僅修改專案結構時同步更新 [Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L9-L13) 的 `COPY` 行 |

## 背景(選用)

[Dockerfile](https://github.com/GameFrameX/GameFrameX.Server/blob/main/Dockerfile#L1-L48) 採用四階段建置:`base` 準備執行階段映像檔，`build` 還原相依套件並編譯，`publish` 產出 Launcher 與 Hotfix 兩個產出物，`final` 僅複製執行階段必要的檔案，從而讓最終映像檔保持精簡並支援熱更目錄的預設值備援。
