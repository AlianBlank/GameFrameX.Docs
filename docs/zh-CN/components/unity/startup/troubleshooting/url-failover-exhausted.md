# 主备 URL 全部耗尽怎么办

当启动流程请求全局信息接口时,框架会按顺序遍历 `StartupOptions.GlobalInfoUrls` 主备 URL 列表,每个 URL 内部还会重试 `MaxAttemptsPerUrl` 次。如果所有 URL 都失败,`UrlFailoverRunner` 返回 `UrlFailoverResult.Fail(...)`,启动流程会以 `StartupResult.Fail` 结束,并抛出 `StartupFailedEventArgs`。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 启动停在"全局信息"步骤,日志输出 `URL list must contain at least one URL.` | `GlobalInfoUrls` 为空数组 | 在 `StartupOptions` 资产里至少填入 1 个 URL |
| 启动停在"全局信息"步骤,UI 提示"所有 URL 已耗尽 / All URLs exhausted" | 主备 URL 全部不可达,但配置合法 | 依次排查 URL、参数、重试上限(见下方修复步骤) |
| 日志出现 `ArgumentException: Max attempts per URL must be greater than zero.` | `MaxAttemptsPerUrl` 被设为 0 或负数 | 将 `MaxAttemptsPerUrl` 改为 ≥1 |
| 日志出现 `ArgumentException: Retry delay must be zero or greater.` | `RetryDelayMs` 被设为负数 | 将 `RetryDelayMs` 改为 ≥0 |
| 单个 URL 第一次就 200,但被错误判失败 | `attempt` 委托没有正确实现 `UrlAttemptResult.Success` | 检查 `IStartupHttpParamsProvider` 返回的 HTTP 状态码判断逻辑 |

## 修复步骤

### 1. 确认 `GlobalInfoUrls` 至少有一条配置

`UrlFailoverRunner.ExecuteAsync` 会立刻对空列表抛 `ArgumentException("URL list must contain at least one URL.", nameof(urls))`。打开项目中的 `StartupOptions.asset`,在 `Network → Global Info URLs` 填入主备 URL(主在前、备在后):

```csharp
public string[] GlobalInfoUrls = new string[0]; // 启动前必须至少 1 项
```

Source: [StartupOptions.cs#L22-L23](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### 2. 检查每个 URL 自身可达

按顺序逐个访问 `GlobalInfoUrls` 中的地址,确认能返回 2xx:

1. 浏览器或 `curl` 测试 URL 是否能返回 JSON。
2. 确认协议(https / http)、端口、路径拼写无误。
3. 确认服务端已部署并放行 CDN、防火墙、跨域(CORS)与鉴权头。
4. 若使用了 `IStartupHttpParamsProvider` 注入公共参数,确认 Provider 没有返回 401/403。

### 3. 调高单个 URL 的重试上限

每个 URL 内部默认重试 3 次(含初次),可在 `StartupOptions` 资产里调大以容忍瞬时抖动:

```csharp
[Tooltip("每个 URL 内部的总尝试次数上限（含初次）。")]
public int MaxAttemptsPerUrl = 3;
```

注意上限必须 ≥1,否则会触发参数校验异常:

```csharp
if (maxAttemptsPerUrl < 1)
{
    throw new ArgumentException(
        "Max attempts per URL must be greater than zero.",
        nameof(maxAttemptsPerUrl));
}
```

Source: [UrlFailoverRunner.cs#L27-L30](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L27-L30)

### 4. 调整重试间隔

`RetryDelayMs` 控制两次重试之间的等待毫秒数,默认 3000ms。瞬时故障可以适度加大,长链路或弱网环境可以缩小以缩短总耗时。值必须 ≥0:

```csharp
if (retryDelayMs < 0)
{
    throw new ArgumentException(
        "Retry delay must be zero or greater.",
        nameof(retryDelayMs));
}
```

Source: [UrlFailoverRunner.cs#L32-L35](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Failover/UrlFailoverRunner.cs#L32-L35)

### 5. 让 UI 引导用户重试

`UrlFailoverRunner` 通过 `onProgress(url, attempt, max)` 回调通知上层当前进度,接入方一般把进度透传到启动 UI 的"重试"按钮。用户可以在不杀进程的情况下再次触发,通常配合"切换到备用 URL"提示。

```csharp
public static UniTask<UrlFailoverResult> ExecuteAsync(
    IReadOnlyList<string> urls,
    int maxAttemptsPerUrl,
    int retryDelayMs,
    Func<string, UniTask<UrlAttemptResult>> attempt,
    Action<string, int, int> onProgress = null,
    CancellationToken cancellationToken = default)
```

## 验证

1. 故意把 `GlobalInfoUrls` 设成空,运行游戏,应看到 `ArgumentException: URL list must contain at least one URL.`,说明校验生效。
2. 把首个 URL 改成不可达地址、其余保持可达,启动应自动切换到下一个可用 URL 并成功进入下一流程。
3. 把所有 URL 都改成不可达地址,启动应以 `StartupResult.Fail` 结束,并通过 `StartupFailedEventArgs` 抛出最后失败 URL 与错误消息,可用于 UI 弹窗提示。

## 背景(可选)

`UrlFailoverRunner` 的策略是"顺序遍历 URL × 每 URL 重试 N 次",失败时仅记录最后一个失败的 URL 与错误信息,不会自动回到列表头部或随机挑选备援。整体启动编排流程见《StartupProcedureUtility 完成失败处理》,其中 `CompleteFailure` 会把 `failedUrl` 一并写入 `StartupFailedEventArgs` 并推送给 UI。
