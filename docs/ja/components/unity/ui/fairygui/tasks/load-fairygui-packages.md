# FairyGUI パッケージのロードとアンロード

`FairyGUIPackageComponent` が提供する `AddPackageSync` / `AddPackageAsync` を使用して FairyGUI パッケージをロードし、`RemovePackage` でパッケージ名を指定してアンロードします。UI を開く際、`UIManager` が自動的に対応するパッケージをチェックしてロードするため、通常は手動での介入は不要です。

## 前提条件

- プロジェクトに `com.gameframex.unity.ui.fairygui` がインストールされており、FairyGUI エディターでパッケージ記述ファイルがパブリッシュ済みであること(アセットモードでは `{包名}_fui` アセット、Resources モードでは記述ファイルのパス)。
- GameFrameX の `UIManager` で UI を開いていること(自動ロードのフローはこれに依存します)。

## 操作手順

まず、3 つのエントリーメソッドを把握しておきます:

| 方法 | シグネチャ | 説明 |
|------|------|------|
| 同期ロード | `void AddPackageSync(string descFilePath, bool isLoadAsset = true)` | 内部で `UIPackage.AddPackage` を呼び出します。Resources ディレクトリ配下のパッケージに適しています |
| 非同期ロード | `Task<UIPackage> AddPackageAsync(string descFilePath, bool isLoadAsset = true)` | `await` 可能なタスクを返します。Bundle ロードに適しています |
| アンロード | `void RemovePackage(string packageName)` | パッケージ名(Name)でロード済み辞書から検索して削除します |

1. **同期ロードが必要な場合**(例：パッケージが Resources ディレクトリに配置されており、Bundle を経由しない):`AddPackageSync` を呼び出し、記述ファイルのパスを渡します。`isLoadAsset` のデフォルトは `true` で、パッケージの登録後に `LoadAllAssets()` を呼び出してすべてのアセットをプリロードします。

```csharp
public void AddPackageSync(string descFilePath, bool isLoadAsset = true)
{
    if (!m_UILoadedPackages.TryGetValue(descFilePath, out var packageData))
    {
        var package = UIPackage.AddPackage(descFilePath);
        packageData = new UIPackageData(descFilePath, package.name, isLoadAsset);
        packageData.SetPackage(package);
        m_UILoadedPackages[descFilePath] = packageData;
        if (isLoadAsset)
        {
            packageData.Package.LoadAllAssets();
        }
    }
}
```

2. **非同期ロードが必要な場合**(パッケージが AssetBundle 内にある):`await AddPackageAsync(descFilePath)` を実行します。同一の `descFilePath` への重複リクエストは同じ `TaskCompletionSource` を再利用するため、二重にロードされることはありません。

```csharp

    packageData.SetPackage(uiPackage);
    if (isLoadAsset)
    {
        packageData.Package.LoadAllAssets();
    }

    m_UILoadedPackages[descFilePath] = packageData;
    tcs.TrySetResult(packageData.Package);
}

m_UIPackageLoading[descFilePath] = tcs;
UIPackage.AddPackageAsync(descFilePath, Complete);
```

## よくあるバリエーション

- **パッケージの登録のみを行い、すべてのアセットをすぐにロードしない**:`AddPackageSync` / `AddPackageAsync` に `isLoadAsset: false` を渡すと、`LoadAllAssets()` をスキップし、アセットはコンポーネントのインスタンス化時に必要に応じてロードされます。同一パッケージ内のアセットが大きく、その時点では一部の UI しか使用しない場面に適しています。
- **同一パッケージの重複ロード**:`AddPackageAsync` は内部で `m_UIPackageLoading` により重複を排除します——同一の `descFilePath` がロード中の場合は既存の `tcs.Task` をそのまま返し、ロード済みの場合は `m_UILoadedPackages` を通じて `Task.FromResult(packageData.Package)` を返します。そのため、同一パッケージを複数回呼び出しても安全であり、重複してインスタンス化されることはありません。

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| UI を開けず、コールバックが `LoadAssetFailureCallback` に到達する | Bundle 分岐で `{包名}_fui` アセットのロードに失敗(アセットが Bundle に含まれていない、またはパスが一致しない) | FairyGUI のパブリッシュ成果物がインポート済みであること、および `uiFormAssetPath` の最後のセグメントがパッケージ名と一致していること、または両者が一致しない場合はディレクトリ配下に `包名/包名_fui` が存在することを確認する |
| `RemovePackage` 実行後もパッケージが有効のまま | パッケージ名ではなく記述ファイルのパスが渡されている | `UIPackage.name`(ロード時に記録された `Name`)を使って `RemovePackage` を呼び出す |
| Resources ディレクトリ配下のパッケージで非同期ロードが常に利用できない | `assetPath` に Bundle ディレクトリ名(`Utility.Asset.Path.BundlesDirectoryName`)が含まれない場合、同期分岐が強制される | Resources モードでは `AddPackageSync` を使用する。非同期が必要な場合はパッケージを Bundle ディレクトリに移動する |
| 同一パッケージが複数のインスタンスとしてロードされる | `FairyGUIPackageComponent` を経由せずに `UIPackage.AddPackage` を直接呼び出している | `AddPackageSync` / `AddPackageAsync` に統一し、コンポーネント内の辞書による重複排除に任せる |

## 背景(任意)

`FairyGUIPackageComponent` は 2 つの辞書でパッケージの状態を管理します:`m_UIPackageLoading`(ロード中、`descFilePath → TaskCompletionSource`)と `m_UILoadedPackages`(ロード済み、`descFilePath → UIPackageData`)。ロード完了後に後者へ書き込み、前者から削除します。アンロード時は `Name` から `descFilePath` を逆引きし、FairyGUI の `UIPackage` レジストリから削除します。GameFrameX 全体の UI アーキテクチャと各コンポーネントの役割分担については、「概要」ページを参照してください。
