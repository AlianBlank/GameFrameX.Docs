# What to Do When GetComponent<ConfigComponent> Returns Null

`GetComponent<ConfigComponent>()` returns `null`—this usually happens because the `ConfigComponent` is not attached in the scene at all, or the Game Framework entry module has not yet been initialized. This page provides prioritized troubleshooting and fix steps for quick diagnosis.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `GetComponent<ConfigComponent>()` returns `null` | No `ConfigComponent` is attached on the GameObject in the scene | Follow the "Attach ConfigComponent" steps below to add it |
| Component is attached but still returns `null` | The queried object is not the GameObject where `GameFrameworkEntry` resides | Get it on the object where `GameFrameworkEntry` resides |
| Startup log shows `Config manager is invalid.` | The `IConfigManager` module is not registered | Check whether the `GameFrameX.Config` package is installed and auto-registration is enabled |
| Works in the editor but returns `null` after packaging | The packaging stripping removed `ConfigComponent` | Introduce `GameFrameXConfigCroppingHelper`, see the explanation below |

## Fix Steps

### 1. Confirm ConfigComponent Is Attached in the Scene

`ConfigComponent` must be attached to the GameObject where `GameFrameworkEntry` resides in order to work. It carries the `[GameFrameXAutoComponent(-5000)]` attribute and is automatically created with the entry in most GameFrameX project templates.

```csharp
using GameFrameX.Config.Runtime;
using UnityEngine;

var configComponent = GameObject.FindObjectOfType<ConfigComponent>();
if (configComponent == null)
{
    Debug.LogError("ConfigComponent not found in the scene, please attach it to the GameObject where GameFrameworkEntry resides");
    return;
}
```

Source: [ConfigComponent.cs](/Runtime/Config/ConfigComponent.cs#L46-L50)

### 2. Get the Component from the Correct Object

`ConfigComponent` is a subclass of `GameFrameworkComponent` and can only be attached to the Game Framework entry GameObject. If your script is attached to another GameObject, fetch it from the object where `GameFrameworkEntry` resides:

```csharp
using GameFrameX.Config.Runtime;
using GameFrameX.Runtime;
using UnityEngine;

// Get the Game Framework entry GameObject
var entryGo = GameObject.Find("GameFrameworkEntry");
var configComponent = entryGo.GetComponent<ConfigComponent>();
```

If the entry object has a different name, you can search in the Hierarchy for the GameObject that has the `GameFrameworkEntry` script attached.

### 3. Confirm the Runtime Log

`ConfigComponent.Awake()` outputs a fatal log when `IConfigManager` is unavailable:

```csharp
m_ConfigManager = GameFrameworkEntry.GetModule<IConfigManager>();
if (m_ConfigManager == null)
{
    Log.Fatal("Config manager is invalid.");
    return;
}
```

Source: [ConfigComponent.cs](/Runtime/Config/ConfigComponent.cs#L79-L84)

When you see `Config manager is invalid.`, it means `IConfigManager` is not registered to `GameFrameworkEntry`. Check whether the `GameFrameX.Config` package has been introduced, and whether the related modules have been stripped.

### 4. Prevent Stripping After IL2CPP / Packaging

This component uses auto-registration, and if no runtime code explicitly references `ConfigComponent`, the release version may be stripped. The repository already provides a stripping helper:

```csharp
_ = typeof(ConfigComponent);
```

Source: [GameFrameXConfigCroppingHelper.cs](/Runtime/GameFrameXConfigCroppingHelper.cs#L21)

As long as this helper is invoked during scene initialization or in some `RuntimeInitializeOnLoadMethod`, the `ConfigComponent` type is guaranteed not to be stripped. After packaging, call `GetComponent<ConfigComponent>()` again on a real device to verify.

## Verification

1. Run in the Editor, select the GameObject where `GameFrameworkEntry` resides in the Hierarchy, and the Inspector should display the `Config Component` field.
2. Obtain a non-null instance through the `GetComponent` path above, and calling `configComponent.Count` should not throw an exception.
3. Package for Android/iOS, and confirm there is no `Config manager is invalid.` in the runtime log of the first scene.

## Common Variants

- **Runtime dynamic creation**: Do not use `new GameObject().AddComponent<ConfigComponent>()`—`ConfigComponent` must be on the `GameFrameworkEntry` GameObject in order to coordinate with the `GameFrameworkEntry` module system.
- **Multi-scene switching**: Every independent scene needs to hold a `GameFrameworkEntry`, otherwise the component will be lost after switching scenes.
