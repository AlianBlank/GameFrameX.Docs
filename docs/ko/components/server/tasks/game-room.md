# 게임 룸(Room) 모듈 구현

Room 모듈은 서버의 룸 목록 관리, 플레이어 입장/퇴장, 연결 끊김 처리 및 룸 정기 유지 관리를 담당합니다. 이 페이지의 단계를 따라 하면 기존 GameFrameX 프로젝트에서 자신만의 Room 비즈니스를 연동하고 확장할 수 있습니다.

## 사전 조건

- `GameFrameX.Server` 프로젝트의 로컬 빌드 및 실행을 완료했습니다.
- Player 모듈이 이미 존재하며, Room은 `PlayerRoleId`를 통해 플레이어와 연결됩니다.
- Actor 패턴에 익숙해야 합니다. `RoomComponent`는 `GlobalConst.ActorTypeServer`에 바인딩되며, 요청은 `ReqXxxHandler`를 통해 해당 `RoomComponentAgent` 메서드로 진입합니다.

### 4. 생성/입장/퇴장 요청 구현

`RoomComponentAgent`는 `OnCreateRoomAsync`, `OnJoinRoomAsync`, `OnLeaveRoomAsync` 등의 진입점을 노출하여 유효성 검사, 상태 쓰기 및 브로드캐스트를 수행합니다.

```csharp
public async Task OnCreateRoomAsync(long roleId, ReqCreateRoom request, RespCreateRoom response)
{
    if (!CheckRoleId(roleId, response)) return;
    if (!TryGetRule(request.GameType, response, out var rule)) return;
    if (!TryResolvePlayerCount(request.MinPlayerCount, request.MaxPlayerCount,
            rule, response, out var min, out var max)) return;

    var now = TimerHelper.UnixTimeSeconds();
    var roomId = State.NextRoomId++;
    var room = new RoomState
    {
        RoomId = roomId,
        Name = string.IsNullOrWhiteSpace(request.Name) ? $"{rule.DefaultNamePrefix}{roomId}" : request.Name.Trim(),
        GameType = request.GameType,
        OwnerRoleId = roleId,
        Status = RoomStatus.Waiting,
        MinPlayerCount = min,
        MaxPlayerCount = max,
        Round = 1,
        CreatedTime = now,
        UpdatedTime = now,
    };
    room.PlayerIds.Add(roleId);
    State.Rooms[roomId] = room;
    State.PlayerRoomMap[roleId] = roomId;

    response.Room = await ToMessageAsync(room);
    await OwnerComponent.WriteStateAsync();
    await NotifyRoomChangedAsync(room, RoomChangeType.Created);
}
```

출처: [RoomComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L86-L140)

`OnJoinRoomAsync`는 룸이 만원이 아니고 `Waiting`/`Ready` 상태일 때 플레이어를 입장시킵니다. 인원수가 `MinPlayerCount`에 도달하면 룸 상태가 `Ready`로 전환되며, 상태를 다시 쓰고 변경 사항을 브로드캐스트합니다.([RoomComponentAgent.cs#L142-L196](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L142-L196))

### 5. 정기 유지 관리 작업 시작

`Active()`에서 Cron 표현식으로 `RoomMaintenanceTimer`를 등록하여, 10초마다 시간 초과된 연결 끊김 플레이어와 닫힌 룸을 정리합니다.

```csharp
public override async Task<bool> Active()
{
    var isContinue = await base.Active();
    if (isContinue)
    {
        WithCronExpression<RoomMaintenanceTimer>("0/10 * * * * ? *");
    }
    return isContinue;
}
```

출처: [RoomComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L60-L69)

관련 상수는 같은 파일을 참고하세요: `DisconnectedPlayerAutoLeaveSeconds = 120`, `ClosedRoomRetentionSeconds = 10 * 60`.

### 6. 연결 끊김/재연결 이벤트 연동

`[Service]`로 표시된 메서드를 통해 Player 모듈이 연결 끊김 시 호출하도록 하고, 즉시 강퇴하지 않고 타임스탬프만 기록합니다. 유지 관리 작업이 만료된 후에 실제로 제거됩니다.

```csharp
[Service]
public virtual Task MarkPlayerDisconnected(long roleId)
{
    if (roleId <= 0 || !TryGetActiveRoom(roleId, out _)) return Task.CompletedTask;
    State.DisconnectedPlayerTimeMap[roleId] = TimerHelper.UnixTimeSeconds();
    return OwnerComponent.WriteStateAsync();
}
```

출처: [RoomComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L223-L233)

## 일반적인 변형

- 새 게임 유형 추가: `RoomRuleMap`에 항목을 추가하는 동시에 `GameType` 열거형과 프로토콜 필드를 확장합니다.
- 룸 관전: `RoomState.PlayerIds`와 별개로 `SpectatorIds` 목록을 활용하여 `OnJoinRoomAsync`에서 요청 매개변수로 구분합니다.
- 방장 이전: `LeaveRoom`에서 방장 퇴장을 감지한 후 `OwnerRoleId`를 목록에서 아직 남아 있는 첫 번째 플레이어에게 이전합니다.
- 비공개 룸: `RoomState`에 `PasswordHash` 필드를 추가하고 `OnJoinRoomAsync` 진입점에서 검증합니다.

## 일반적인 오류

- `OwnerComponent.WriteStateAsync()` 호출 누락: 상태가 메모리에만 적용되어 재시작 후 손실됩니다.
- 룸이 `Playing` 상태로 진입한 후에도 입장을 허용함: `OnJoinRoomAsync`는 이미 `Status`가 `Waiting`/`Ready`여야 함을 검증하므로, 새 게임 방식 추가 시 이 검증을 우회하지 마세요.
- 새 룸 생성 전 기존 룸을 닫지 않음: 반드시 먼저 `CloseRoomAsync(activeRoom, RoomChangeType.Closed)`를 호출해야 합니다. 그렇지 않으면 `State.PlayerRoomMap`에 일대다 매핑이 발생합니다.
- 연결 끊김 시 즉시 강퇴: `MarkPlayerDisconnected`만 호출하여 시간을 기록하고, `RoomMaintenanceTimer`가 일괄 정리하도록 해야 합니다.

## 배경(선택 사항)

`RoomComponent`는 Actor 모델을 통해 서버 인스턴스에 바인딩되며, 모든 룸 작업은 동일한 Actor의 직렬 큐로 진입하여 `RoomListState`의 동시 수정을 방지합니다. `NotifyRoomChangedAsync`는 이벤트 버스를 통해 구독자(로비, 채팅, 친구)에게 브로드캐스트하며, 구체적인 이벤트 유형은 `RoomChangeType` 열거형으로 구분됩니다.
