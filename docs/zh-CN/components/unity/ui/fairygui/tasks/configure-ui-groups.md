# 配置 UI 分组与层级深度

UI 分组在 FairyGUI 中对应一个挂载在 `GRoot` 下的全屏 `GComponent` 容器,同一分组的界面都作为它的子节点叠放;分组之间的前后次序由 `FairyGUIUIGroupHelper.SetDepth(int depth)` 决定——深度值会被换算成 Z 坐标(`depth * 100`),数值越大的分组离镜头越近、显示在更上层。

## 前置条件

- 已按仓库 README 安装 `com.gameframex.unity.ui.fairygui` 包(Unity 3.3.2 及以上),参见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L69-L100) 的安装一节。
- 场景中已存在 GameFrameX 的 `UIComponent`(FairyGUI 包组件所在根节点),分组创建时会从它向上查找设计分辨率配置。
- 项目已引用 GameFrameX 核心 UI 包(`GameFrameX.UI.Runtime`),`OptionUIGroupAttribute`、`GetUIGroup` 等入口在那里定义;本包负责 FairyGUI 侧的分组实现。

## 操作步骤

1. **确定分组清单与深度值**。为每类界面规划一个分组名和深度,例如普通界面用较小值、弹窗/提示用较大值。分组深度只影响分组容器整体的 Z 位置,组内界面按加入顺序叠放。

2. **由 UI 管理器创建分组**,创建时会调用 `FairyGUIUIGroupHelper.Handler`,并把深度传入。该辅助器会:设置深度、套用设计分辨率、创建一个与 `GRoot` 同宽高的全屏 `GComponent` 并以分组名命名:

   ```csharp
   public override IUIGroupHelper Handler(Transform root, string groupName, string uiGroupHelperTypeName, IUIGroupHelper customUIGroupHelper, int depth = 0)
   {
       SetDepth(depth);
       ApplyDesignResolution(root.GetComponentInParent<UIComponent>()?.DesignResolution);
       var component = new GComponent();
       GRoot.inst.AddChild(component);
       var comName = groupName;
       component.displayObject.name = comName;
       component.gameObjectName = comName;
       component.name = comName;
       component.opaque = false;
       component.AddRelation(GRoot.inst, RelationType.Width);
       component.AddRelation(GRoot.inst, RelationType.Height);
       component.MakeFullScreen();
       return GameFrameX.Runtime.Helper.CreateHelper(component.displayObject.gameObject, uiGroupHelperTypeName, (UIGroupHelperBase)customUIGroupHelper, 0);
   }
   ```

   Source: [FairyGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIUIGroupHelper.cs#L83-L98)

   注意分组容器 `opaque = false`:分组本身不拦截事件,事件命中取决于组内各界面自身。

3. **理解深度如何生效**。`SetDepth` 把深度写入 `Depth` 属性,并把辅助器所在 GameObject 的 `localPosition.z` 设为 `depth * 100`,间隔 100 是为组内界面留出 Z 偏移空间:

   ```csharp
   public override void SetDepth(int depth)
   {
       Depth = depth;
       transform.localPosition = new Vector3(0, 0, depth * 100);
   }
   ```

   Source: [FairyGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIUIGroupHelper.cs#L64-L68)

   关键成员速查:

   | 成员 | 签名 | 说明 |
   |------|------|------|
   | `Depth` | `public override int Depth { get; protected set; }` | 当前分组深度,只读对外、由 `SetDepth` 写入 |
   | `SetDepth` | `public override void SetDepth(int depth)` | 记录深度并设置 `localPosition = (0, 0, depth * 100)` |
   | `Handler` | `public override IUIGroupHelper Handler(Transform root, string groupName, string uiGroupHelperTypeName, IUIGroupHelper customUIGroupHelper, int depth = 0)` | 创建分组容器并返回实际辅助器实例 |

4. **把界面归入分组**。界面类通过 `OptionUIGroupAttribute` 声明分组名;创建界面时若 `uiForm.UIGroup` 为空,`FairyGUIFormHelper` 会反射读取该特性并按 `GroupName` 查找分组:

   ```csharp
   var uiGroup = uiForm.UIGroup;

   if (uiGroup == null)
   {
       var attribute = uiFormType.GetCustomAttribute(typeof(OptionUIGroupAttribute));
       if (attribute is OptionUIGroupAttribute optionUIGroup)
       {
           uiGroup = m_UIComponent.GetUIGroup(optionUIGroup.GroupName);
       }

       uiForm.UIGroup = uiGroup;
   }
   ```

   Source: [FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L104-L115)

   分组名必须与第 1 步规划、且已创建的分组完全一致,否则查不到分组。

5. **界面挂载到分组容器**。界面创建成功后,`FairyGUIFormHelper` 取出分组对应的 `GComponent` 并把界面组件 `AddChild` 进去,组内叠放顺序即添加顺序:

   ```csharp
   DisplayObjectInfo displayObjectInfo = ((MonoBehaviour)uiGroup.Helper).gameObject.GetComponent<DisplayObjectInfo>();
   ...
   var uiGroupComponent = displayObjectInfo.displayObject.gOwner as GComponent;
   ...
   uiGroupComponent.AddChild(component);
   ```

   Source: [FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L145-L159)

## 常见变体

- **动态调整分组层级**:分组创建后仍可调用该分组辅助器的 `SetDepth(int depth)` 重新设置深度,GameObject 的 Z 坐标会立即更新为 `depth * 100`,无需重建分组。
- **自定义界面组辅助器**:`Handler` 的 `customUIGroupHelper` 参数允许传入自定义辅助器,最终由 `GameFrameX.Runtime.Helper.CreateHelper(...)` 决定实例化哪一个——传入自定义实例时优先使用它,否则按 `uiGroupHelperTypeName` 反射创建。
- **运行时按需创建分组**:未在初始化时预建的分组,只要在界面打开前通过 UI 组件创建即可;`FairyGUIFormHelper` 在创建界面时按 `OptionUIGroupAttribute.GroupName` 实时调用 `m_UIComponent.GetUIGroup(...)` 查找。

## 常见错误

| 症状(日志原文) | 原因 | 修复 |
|------|------|------|
| `UI group is invalid.` | 界面类的 `OptionUIGroupAttribute.GroupName` 对应的分组不存在,或未挂特性导致分组为空 | 核对特性中的分组名与已创建分组完全一致,并提前创建该分组 |
| `UI group component is invalid.` | 分组辅助器对象上的 `DisplayObjectInfo.displayObject.gOwner` 不是 `GComponent` | 确认使用的是 `FairyGUIUIGroupHelper` 创建的分组,不要用其它实现的辅助器 |
| `Display object info is invalid.` | 分组容器 GameObject 缺少 `DisplayObjectInfo` 组件 | 使用 `FairyGUIUIGroupHelper.Handler` 正常创建分组,避免手工拼装容器 |
| 修改深度后界面层级未变化 | 只改了 `Depth` 属性所在脚本数值,没有实际调用 `SetDepth` | 调用 `SetDepth` 才会同步更新 `transform.localPosition` |

以上错误日志均出自 [FairyGUIFormHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIFormHelper.cs#L139-L157)。

## 验证

- 运行场景后,在 Hierarchy 中找到分组容器(名称即分组名),检查其 `localPosition.z` 是否等于 `深度 × 100`,见 [FairyGUIUIGroupHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FairyGUIUIGroupHelper.cs#L64-L68)。
- 打开两个不同深度的界面,确认深度大的分组覆盖在深度小的分组之上;同一分组内后打开的界面显示在前。
- 打开带 `OptionUIGroupAttribute` 的界面,Console 未出现 `UI group is invalid.` 等错误日志,且界面节点位于对应分组容器之下。

## 背景

FairyGUI 的 `GRoot` 是所有 UI 的根,各分组以平级全屏容器挂在其下,通过 Z 坐标(深度 × 100)由相机透视关系决定前后,这就是本包"界面组深度支持"的实现方式(见 [CHANGELOG.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/CHANGELOG.md#L115))。关于 FairyGUI 适配层各组件的分工,见《FairyGUI 适配层概览》。
