# ハートビート喪失アラートが発生した場合の対処方法

`NetworkMissHeartBeatEventArgs` イベントが繰り返し発生する、または `MissHeartBeatCount` が継続的に増加する場合、ハートビートパケットが間隔時間内に届かなかったことを示します。本ページでは、間隔設定、アプリケーションのフォーカス、接続品質のどれが喪失の原因かを迅速に判断する手助けをし、対応する修正と検証方法を提示します。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 各ハートビート周期で `NetworkMissHeartBeatEventArgs` がトリガーされる | `HeartBeatInterval` の設定値が小さすぎて、1 回の往復遅延未満になっている | ハートビート間隔を大きくする(「ハートビート間隔の調整」を参照)|
| アプリがバックグラウンド/フォーカス喪失後にハートビート喪失が集中して発生する | フォーカス喪失中はハートビート送信が一時停止され、フォーカス回復後に集中して送信される | フォーカス関連のハートビート設定を確認する(「フォーカス喪失時のハートビート戦略」を参照)|
| ハートビート喪失回数が上限に達した後、接続が閉じられる | 許容された最大喪失回数に達し、チャネルが自ら切断する | 喪失回数の上限とネットワーク品質を確認する |
| 散発的な喪失後に自然に回復し、再接続が不要 | 単発のネットワークジッターであり、`Reset` がカウントをゼロにリセットする | 対処不要、アラート頻度の監視のみ行う |

## ハートビート喪失の報告方法

ハートビート喪失と判定されるたびに、フレームワークはイベントシステムを通じて `NetworkMissHeartBeatEventArgs` を送出します。イベント ID は `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs` です。このイベントは 2 つのフィールドを保持します:

```csharp
public sealed class NetworkMissHeartBeatEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(NetworkMissHeartBeatEventArgs).FullName;

    public override string Id
    {
        get { return EventId; }
    }

    /// <summary>ネットワークチャネルを取得します。</summary>
    public INetworkChannel NetworkChannel { get; private set; }

    /// <summary>ハートビートパケットの喪失回数を取得します。</summary>
    public int MissCount { get; private set; }

    public static NetworkMissHeartBeatEventArgs Create(INetworkChannel networkChannel, int missCount)
    {
        NetworkMissHeartBeatEventArgs networkMissHeartBeatEventArgs = ReferencePool.Acquire<NetworkMissHeartBeatEventArgs>();
        networkMissHeartBeatEventArgs.NetworkChannel = networkChannel;
        networkMissHeartBeatEventArgs.MissCount = missCount;
        return networkMissHeartBeatEventArgs;
    }
}
```

ソース: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L41-L87)

このイベントを処理する際は、`NetworkChannel` でどの名前付き接続に問題が発生したかを判断し、`MissCount` で喪失の累積程度を判断します。

## 修正手順

### 1. イベントを購読して喪失元を確認する

ネットワークコンポーネントの初期化後にハートビート喪失イベントを購読し、まず `NetworkChannel` と `MissCount` を取得してから、その後の対応を決定します:

```csharp
// ハートビート喪失イベントを購読(イベント Id は NetworkMissHeartBeatEventArgs.EventId)
GameEntry.Event.AddListener(NetworkMissHeartBeatEventArgs.EventId, OnMissHeartBeat);

private void OnMissHeartBeat(object sender, GameEventArgs e)
{
    var args = (NetworkMissHeartBeatEventArgs)e;
    UnityEngine.Debug.LogWarning($"[网络] {args.NetworkChannel.Name} 心跳丢失,累计 {args.MissCount} 次");
}
```

> 説明：イベントオブジェクトは `ReferencePool` から取得されます。フレームワークはディスパッチ完了後に `Clear()` を呼び出して `NetworkChannel` と `MissCount` をゼロにするため、必ずコールバック内で値を取得し、イベントオブジェクトをキャッシュしないでください。

### 2. ハートビート間隔の調整

ハートビートはチャネルのメインループによって駆動されます:毎フレーム `ProcessHeartBeat(realElapseSeconds)` を呼び出して `HeartBeatState.HeartBeatElapseSeconds` を加算し、間隔に達するとハートビートを 1 回送信します。`HeartBeatInterval` がクライアントからサーバーまでの 1 回の往復時間より小さい場合、ほぼすべての周期で喪失と判定されます。診断と修正：

1. クライアントからサーバーまでの RTT を記録します(Ping またはビジネス層での測定が利用可能)。
2. ハートビート間隔を RTT の 3~5 倍以上に設定します。
3. `HeartBeatInterval` には既に負値の検証が適用されているため、負数を渡さないでください(CHANGELOG の「HeartBeatInterval に負値検証を追加」の項目を参照)。

ハートビート間隔の経過時間と喪失カウントは、いずれも `HeartBeatState` に保存されます:

```csharp
public sealed class HeartBeatState
{
    private float _heartBeatElapseSeconds;
    private int _missHeartBeatCount;

    /// <summary>ハートビート間隔の時間</summary>
    public float HeartBeatElapseSeconds { get; set; }

    /// <summary>ハートビート喪失回数</summary>
    public int MissHeartBeatCount { get; set; }

    /// <summary>ハートビートデータをリセット=>キープアライブ</summary>
    public void Reset(bool resetHeartBeatElapseSeconds)
    {
        if (resetHeartBeatElapseSeconds)
        {
            _heartBeatElapseSeconds = 0f;
        }

        _missHeartBeatCount = 0;
    }
}
```

ソース: [NetworkManager.HeartBeatState.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/Network/Network/NetworkManager.HeartBeatState.cs#L39-L82)

### 3. フォーカス喪失時のハートビート戦略の調査

本パッケージの README では「ハートビートパケット機構(アプリケーションのフォーカス獲得/喪失時の送信設定をサポート)」が明示的にサポートされています。モバイルでバックグラウンドに切り替えると、Unity のメインループがスロットリングされたり、一時停止されたりする可能性があり、ハートビートが間隔どおりに送信できず、フォアグラウンド復帰後に喪失が集中して報告されます。調査のポイント:

| 確認項目 | 推奨される対応 |
|--------|----------|
| フォーカス喪失中もハートビートを送信し続けるか | ビジネス上許容される場合、フォーカス喪失中は送信を停止し、フォーカス回復後に `HeartBeatState.Reset(true)` を呼び出してカウントをゼロにしてから再開する |
| フォーカス回復後のカウント | 先にリセットしてから送信を再開し、古いカウントがそのままクローズロジックをトリガーしないようにする |
| サーバーとの取り決め | サーバー側で、フォーカスを失ったクライアントに対してハートビートタイムアウトのしきい値を緩和する |

> CHANGELOG には「アプリケーションがフォーカスを獲得したときのハートビートパケットのデフォルト動作を修正」と「ProcessHeartBeat 内の Close 呼び出しをロック外に移動し、ネストされたロックによるデッドロックリスクを回避」の 2 つの修正が既に含まれています。旧バージョンでフォーカス喪失後の誤った喪失判定やハートビート処理のハングが発生する場合は、まず新しいバージョンにアップグレードしてください。

### 4. チャネルクローズロジックの調査

ハートビート処理はチャネルのメインループ内にあり、毎フレーム `ProcessHeartBeat(realElapseSeconds)` と `ProcessReceivedMessage()` を順に実行します。累積喪失が上限に達するとチャネルが閉じられます。このクローズロジックがお使いのバージョンでハングする場合は、`Close` 呼び出しがロック外に移動されたバージョンにアップグレードしてください。アップグレード後、ハートビート喪失後に依然としてハングするかどうかを再度確認してください。

## 検証

- イベントコールバック内で `MissCount` を出力します:正常なネットワークでは長期間 0 のはずです。散発的に +1 となった後 `Reset` でゼロにリセットされるのは正常なジッターです。
- ハートビート間隔を一時的に 1 秒に設定し、ネットワークが不安定な環境でテストして、間隔を大きくするとアラート頻度が明確に低下することを確認します。
- バックグラウンドに 30 秒切り替えてからフォアグラウンドに戻り、集中したアラートが発生せず、接続が利用可能な状態を維持していることを確認します(必要に応じて `Reset` でカウントをゼロにします)。
- 接続ログを観察します：ハートビート喪失が上限に達したとき、ハングや無限アラートではなく、チャネルのクローズと切断イベントがトリガーされるはずです。
