# 如何使用 Assets、Config、Localization 與 Global Config

GameFrameX 將「資產載入、熱更新、本地化字串、業務配置表」四類資料需求整合為四個獨立的子系統，統一透過 `GameApp.{Subsystem}` 靜態屬性存取。本頁將說明如何在業務程式碼中取得這四個元件，並執行最常見的操作：讀取配置表 / 讀取配置 / 取得本地化文字 / 載入資產。

## 前置條件

- 已安裝 `com.gameframex.unity.entry` 套件，並視需要安裝對應的執行階段子套件：`GameFrameX.Asset.Runtime`、`GameFrameX.Config.Runtime`、`GameFrameX.GlobalConfig.Runtime`、`GameFrameX.Localization.Runtime`。
- 已在 Unity 的 **Project Settings → Player → Scripting Define Symbols** 中啟用對應的符號（各元件獨立控制，詳見下表）。

| 子系統 | 啟用符號 | 命名空間 |
|--------|--------|----------|
| Asset | `ENABLE_GAME_FRAME_X_ASSET` | `GameFrameX.Asset.Runtime` |
| Config | `ENABLE_GAME_FRAME_X_CONFIG` | `GameFrameX.Config.Runtime` |
| Global Config | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` | `GameFrameX.GlobalConfig.Runtime` |
| Localization | `ENABLE_GAME_FRAME_X_LOCALIZATION` | `GameFrameX.Localization.Runtime` |

當某個符號未啟用時，對應的 `GameApp.{Name}` 屬性定義會整體排除在編譯之外，業務程式碼將直接擲出「找不到 `Asset`」之類的錯誤。

## 步驟

### 1. 取得子系統存取器

四個子系統的入口結構完全相同：在任何業務類別中直接存取靜態屬性 `GameApp.{Subsystem}`；首次存取時，會從 `GameEntry` 延遲載入對應的元件。

```csharp
// Asset
var asset = GameApp.Asset;
// Config
var config = GameApp.Config;
// Global Config
var globalConfig = GameApp.GlobalConfig;
// Localization
var localization = GameApp.Localization;
```

來源：[Runtime/GameApp.Asset.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs#L36-L55),[Runtime/GameApp.Config.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs#L36-L55),[Runtime/GameApp.GlobalConfig.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.GlobalConfig.cs#L36-L55),[Runtime/GameApp.Localization.cs#L36-L55](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Localization.cs#L36-L55)

### 2. 使用 Asset 元件載入資產

`AssetComponent` 由 `GameFrameX.Asset.Runtime` 套件提供，透過 `GameApp.Asset` 取得。在呼叫之前，請確認該元件已在 `GameEntry` 啟動流程中註冊。

```csharp
using GameFrameX.Asset.Runtime;

var asset = GameApp.Asset;
// 實際可用的 API 取決於你所安裝的 Asset 子套件版本。
// 這裡僅示範入口呼叫模式；具體簽章請參閱子套件文件。
asset.LoadAssetAsync<GameObject>("Assets/Prefabs/Player.prefab", (prefab) =>
{
    Instantiate(prefab);
});
```

來源：[Runtime/GameApp.Asset.cs#L41-L52](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Asset.cs#L41-L52)

### 3. 使用 Config 元件讀取業務配置表

```csharp
using GameFrameX.Config.Runtime;

var config = GameApp.Config;
// 實際可用的 API（例如 GetConfig<T>(key)）由 Config 子套件決定。
// 呼叫入口一律透過 GameApp.Config 靜態屬性。
var row = config.GetConfig<YourConfigRow>("some_key");
```

來源：[Runtime/GameApp.Config.cs#L41-L52](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.Config.cs#L41-L52)

### 4. 使用 GlobalConfig 元件讀取全域配置

```csharp
using GameFrameX.GlobalConfig.Runtime;

var globalConfig = GameApp.GlobalConfig;
// 具體的 API（例如讀取 JSON / 位元組流配置）由 GlobalConfig 子套件提供。
```


## 常見變化

- **非同步資產載入**：在需要等待載入完成的回呼中呼叫 `GameApp.Asset.LoadAssetAsync<T>` 系列方法；不要在主執行緒上同步阻塞。
- **語言切換**：切換語言後，通常需要重新整理 UI 文字。具體的重新整理方式由 Localization 子套件決定，但入口一律透過 `GameApp.Localization`。
- **配置表熱重載**：如果你使用 Config 子套件，通常需要使用該子套件提供的 `Reload` 介面，而不是直接操作底層檔案。

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 編譯錯誤：`GameApp` 不包含 `Asset` / `Config` 等定義 | 未在 Player Settings 中啟用對應符號，導致對應的部分類別被排除在編譯之外 | 按照「前置條件」表格新增 `ENABLE_GAME_FRAME_X_*` 符號 |
| `GameApp.Asset` 在執行階段為 `null` | `GameEntry` 尚未註冊 `AssetComponent` | 在啟動流程的 `RegisterComponent` 階段新增對應的元件 |
| 業務程式碼無法讀取本地化 / 配置欄位 | 使用了錯誤的子系統入口 | 請注意區分：`GameApp.Config` 讀取業務配置表，`GameApp.GlobalConfig` 讀取全域參數，`GameApp.Localization` 讀取本地化文字 |

## 背景（選讀）

這四個入口屬性都是 `static partial class GameApp` 的延遲載入屬性。首次存取時，會透過 `GameEntry.GetComponent<T>()` 取得已註冊的元件實例；後續存取則直接回傳快取欄位。每個檔案都以對應的 `ENABLE_GAME_FRAME_X_*` 符號包裹其整個定義，因此業務專案可以視需要裁剪子系統，而無需將整個框架編譯進套件中。
