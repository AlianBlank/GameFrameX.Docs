# 安裝與專案整合

依照本頁步驟在 Unity 專案中整合 `com.gameframex.unity.objectstorage` 物件儲存元件，完成後即可在程式碼中使用 `IObjectStorageManager`、`IObjectStorageUploadManager` 等介面，介接具體雲端服務商實作完成上傳。

## 前置條件

- Unity 版本 ≥ 2019.4(本套件 `unity` 欄位宣告的最低版本)
- 已在 Unity 中開啟目標專案，或準備好一個待整合的專案根目錄
- 可存取 GitHub 來源儲存庫，或可存取 GameFrameX 的 UPM 註冊表(`https://gameframex.upm.alianblank.uk`)

相依性來自 [package.json](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/package.json#L21-L23):

```json
"dependencies": {
  "com.gameframex.unity": "2.5.1"
}
```

安裝本套件時會自動拉取 `com.gameframex.unity` 2.5.1。

## 操作步驟

本套件提供 4 種安裝方式，任選其一即可。

### 方式一：透過 UPM 註冊表(推薦)

1. 開啟專案根目錄下的 `Packages/manifest.json`。
2. 在 `scopedRegistries` 中加入 GameFrameX 註冊表，並在 `dependencies` 中宣告本套件：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.objectstorage": "1.1.0"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/README.zh-CN.md#L41-L59)

3. `scopes` 控制哪些套件從此註冊表解析；只有 `com.gameframex` 命名前綴的套件會走該註冊表，其他套件繼續走預設來源。
4. 儲存檔案後回到 Unity,等待 Package Manager 完成解析。

### 方式二：Git URL 直接引用

在 `Packages/manifest.json` 的 `dependencies` 節點下附加：

```json
{
  "dependencies": {
    "com.gameframex.unity.objectstorage": "https://github.com/gameframex/com.gameframex.unity.objectstorage.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/README.zh-CN.md#L61-L66)

此方式會直接拉取 `main` 分支最新提交，適合需要追蹤主分支的專案。

### 方式三：以 Unity Package Manager 新增 Git URL

1. 在 Unity 中開啟 `Window → Package Manager`。
2. 點選左上角 `+`,選擇 `Add package from git URL...`。
3. 輸入：`https://github.com/gameframex/com.gameframex.unity.objectstorage.git`,點選 `Add`。

### 方式四：手動放置到 Packages 目錄

1. 下載儲存庫 ZIP 或複製到本機。
2. 將整個 `com.gameframex.unity.objectstorage` 資料夾移動到 Unity 專案的 `Packages/` 目錄下。
3. Unity 會自動辨識本機套件並完成載入。

## 驗證整合

安裝完成後，在 Unity 中開啟 `Window → Package Manager`,在 `In Project` 清單中應能看到 **Game Frame X Object Storage**。

套件中繼資料來自 [package.json](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/package.json#L1-L8):

| 欄位 | 值 |
|------|----|
| `name` | `com.gameframex.unity.objectstorage` |
| `displayName` | Game Frame X Object Storage |
| `category` | Game Framework X |
| `version` | `1.2.0` |
| `unity` | `2019.4` |

接著在你的啟動邏輯中呼叫 `ObjectStorageUploadFactory` 建立一個上傳管理器，即可使用 `IObjectStorageUploadManager` 暴露的檔案/目錄上傳能力。具體工廠用法與服務商實作，請見相關參考頁。

## 常見變體

| 情境 | 選擇 |
|------|------|
| 團隊專案、希望版本可鎖定 | 方式一(註冊表 + 指定 `1.1.0` 這樣的固定版本) |
| 內網環境無法存取 UPM | 方式四(手動放置，或在內網架設 Git 來源用方式二) |
| 需要在 Git URL 中固定分支或 Tag | 方式二，URL 寫為 `https://github.com/gameframex/com.gameframex.unity.objectstorage.git#v1.1.0` |
| 想直接追蹤最新 main | 方式二或方式三，不帶 ref |

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| Package Manager 顯示 `Could not resolve package` | 註冊表 `url` 寫錯，或網路無法存取 `https://gameframex.upm.alianblank.uk` | 核對 `scopedRegistries.url`;切換方式二/方式四 |
| 誤把 `com.gameframex` 套件改從預設 npm 來源解析 | 未設定 `scopedRegistries.scopes`,或 `scopes` 漏掉 `com.gameframex` | 補齊 `scopes: ["com.gameframex"]` |
| `dependencies` 寫的是最新套件名稱但解析到舊版本 | 用了 Git URL 但快取了舊 commit | 在 URL 結尾附加 `#v1.1.0` 鎖定 tag |
| 顯示 `Unity 2019.4 required` | 專案 Unity 版本低於 2019.4 | 升級 Unity 或改用符合版本要求的專案 |

## 背景(選用)

本套件僅提供物件儲存的抽象介面與工廠，具體雲端服務商實作以同名獨立套件發布，例如阿里雲 OSS、AWS S3 等。安裝本套件只是整合介面層，實際呼叫前還需安裝並初始化對應服務商的實作套件，然後透過 `ObjectStorageUploadFactory` 取得 `IObjectStorageUploadManager` 實例即可呼叫 `UploadFile`、`UploadDirectory` 等方法。
