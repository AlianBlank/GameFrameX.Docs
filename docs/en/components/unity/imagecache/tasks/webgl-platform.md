# How to Use on the WebGL Platform

When using `ImageCacheComponent` to load remote images on the WebGL platform, the component automatically switches to the browser-managed `UnityWebRequestTexture` channel, and local disk cache-related APIs become no-ops. No additional branching code is required for WebGL.

## Prerequisites

- `GameFrameXImageCacheCroppingHelper` and `ImageCacheComponent` have been added to the scene or runtime entry point.
- The WebGL build allows cross-origin loading of remote images (the server returns CORS headers, or `Allow downloads over HTTP` / `Use default CORS` is configured in Player Settings).
- The remote image URL must start with `http://` or `https://`; the component will validate the prefix.

## Steps

1. After attaching `ImageCacheComponent` in the scene, call `LoadImageAsync` normally. On WebGL, the component will call `LoadImageWebGLAsync` to go through `UnityWebRequestTexture`, which is managed by the browser's own HTTP cache.

   ```csharp
   using System.Threading;
   using System.Threading.Tasks;
   using GameFrameX.ImageCache.Runtime;
   using UnityEngine;

   public class WebGLSample : MonoBehaviour
   {
       public ImageCacheComponent imageCache;

       public async Task<Sprite> LoadRemoteIcon(string url, CancellationToken ct = default)
       {
           Texture2D tex = await imageCache.LoadImageAsync(url, ct);
           if (tex == null)
           {
               Debug.LogWarning($"Load failed: {url}");
               return null;
           }
           return Sprite.Create(tex, new Rect(0, 0, tex.width, tex.height), Vector2.one * 0.5f);
       }
   }
   ```

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L84-L115)

2. On WebGL, `IsCached`, `RemoveCache`, and `ClearCache` are always unavailable: the first always returns `false` on WebGL, while the latter two do not support disk cache at all. Check the platform before calling them to avoid misleading logs in your business logic.

   ```csharp
   if (Application.platform != RuntimePlatform.WebGLPlayer)
   {
       bool hit = imageCache.IsCached(url);
       // ...Disk cache check only on non-WebGL
   }
   ```

   Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L28-L47)

3. Handle cross-origin and mixed content: browsers block cross-origin textures by default. The remote server must return `Access-Control-Allow-Origin`, or host images under the same domain; HTTPS sites must use HTTPS image URLs, otherwise the browser will block the request.

4. Release the texture: the `Texture2D` returned by `UnityWebRequestTexture.GetContent` is not automatically destroyed by the framework. Remember to call `Object.Destroy(texture)` when the component is unloaded or when switching scenes to avoid GPU memory leaks.

5. Cancellation tokens only take effect on non-WebGL platforms. On WebGL, the `CancellationToken` passed in will be ignored. Simply discard the returned `Task` at the UI layer (e.g., when closing a panel).

   Source: [ImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L66-L89)

## Common Variations

- **Simulating WebGL in the Editor**: Running in the Editor still uses disk cache logic; to verify WebGL behavior, build and debug via `File → Build Settings → WebGL → Build And Run`.
- **Calling UnityWebRequest directly**: If your business logic requires additional progress handling or custom headers, you can branch on WebGL to use `UnityWebRequestTexture.GetTexture` directly without going through `ImageCacheComponent`.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `url must start with http:// or https://.` warning | URL missing protocol header or using a relative path | Add the `https://` prefix |
| Browser reports CORS / Mixed Content error | Remote server didn't return CORS headers or protocol mismatch | Add `Access-Control-Allow-Origin` on the server side, or host resources on the same domain / protocol |
| Calling `RemoveCache` / `ClearCache` has no effect | No disk cache on WebGL | Hide these two entries at the business layer; use the browser's own cache clearing strategy instead |
| `IsCached` always returns `false` | Browser cache is not visible on WebGL | Just call `LoadImageAsync` directly and let the browser decide cache hits |
| GPU memory keeps growing after switching scenes repeatedly | `Texture2D` returned on WebGL is not released | Call `Object.Destroy(texture)` before unloading the scene / replacing the image |

## Background (Optional)

On non-WebGL platforms, `ImageCacheComponent.Awake` fetches files via `IDownloadManager` and writes them to disk using the MD5 of the URL as the file name; on WebGL, the entire `#if !UNITY_WEBGL` block is stripped out, so `IDownloadManager` is neither referenced nor injected on WebGL. The WebGL platform relies solely on `UnityEngine.Networking.UnityWebRequestTexture`, and the browser takes over all caching logic. Therefore, the component cannot—and does not need to—intervene with disk on WebGL.

For the overall flow of related components, see [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L1-L100).
