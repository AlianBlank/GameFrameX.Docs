# Managing Client Sessions (Session / Connection Disconnection)

GameFrameX maintains the session state of each network connection through `Session` and `SessionManager`, including role binding after login, duplicate-login kicks, and connection disconnect cleanup. After reading this page, you will be able to correctly read and write Sessions in scenarios such as login, kicking, and disconnection, and handle the `EventId.SessionRemove` event to perform logout finalization.

## Prerequisites

- The `GameFrameX.Apps.Common.Session` namespace has been imported (the code is located in [Session.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs) and [SessionManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs)).
- The framework's `AppStartUp` has been used to integrate the protocol, and connection information has been obtained through `IAppSession`.
- The player Actor has been registered via `ActorManager` (otherwise `GetByRoleId` will return null).

## Steps

### 1. Create and register a Session after successful handshake/login

Upon successful login, `AppStartUp` calls `SessionManager.Add` to register the current connection in the global dictionary. The underlying layer writes the `SessionId` into the channel data, making it easy to look up by ID when the protocol layer calls back.

```csharp
using GameFrameX.Apps.Common.Session;

// netWorkChannel comes from the protocol layer's INetWorkChannel
var session = new Session(sessionId, netWorkChannel);
SessionManager.Add(session);
```

Source: [SessionManager.cs#L186-L191](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L186-L191)

### 2. Bind the role ID and signature after successful login

Use `UpdateSession` to write the `roleId` and `sign` into the current connection; if this `roleId` is already logged in on another device, the framework will send an "account already logged in on another device" prompt to the old session and kick it offline.

```csharp
SessionManager.UpdateSession(sessionId, roleId, sign);
```

Underlying behavior (excerpted from the source code):

1. Use `GetByRoleId(roleId)` to find the old session.
2. Construct `RespPrompt { Type = 5, Content = "你的账号已在其他设备上登陆" }` and send it via `oldSession.WriteAsync`.
3. Call `oldSession.WorkChannel.ClearData()` + `Close()`, then `Remove(oldSession.SessionId)`.
4. Call `SetPlayerId(roleId)` / `SetSign(sign)` on the current session.

Source: [SessionManager.cs#L200-L229](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L200-L229)

### 3. Send messages back to the client via Session

`Session.WriteAsync` delegates to the underlying network channel for sending, and can carry an error code.

```csharp
var session = SessionManager.Get(sessionId);
if (session != null)
{
    await session.WriteAsync(messageObject, errorCode: 0);
}
```

Source: [Session.cs#L99-L105](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/Session.cs#L99-L105)

### 4. Listen for connection disconnection (active kick / network dropout)

Connection disconnection is handled uniformly by the `AppStartUp` hook. Source code example (excerpt):

```csharp
protected override async ValueTask OnDisconnected(IAppSession appSession, CloseEventArgs disconnectEventArgs)
{
    var session = SessionManager.Get(appSession.Id);
    if (session != null)
    {
        var roomAgent = await ActorManager.GetComponentAgent<RoomComponentAgent>();
        await roomAgent.MarkPlayerDisconnected(session.PlayerId);
    }
}
```

`RoomComponentAgent` reserves a 120-second disconnection grace period (`DisconnectedPlayerAutoLeaveSeconds`); the player is only actually kicked out of the room after the timeout expires.

Source: [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76)、[RoomComponentAgent.cs#L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Game/Room/RoomComponentAgent.cs#L45)

### 5. Respond to the SessionRemove event for logout finalization

`SessionManager` dispatches `EventId.SessionRemove` (value = 1000) in three cases:

- `Remove(sessionId)`
- `KickOffLineByUserId(roleId)`
- `RemoveAll()`
- Removing the old session during duplicate login in `UpdateSession`

The framework uses the `[Event(EventId.SessionRemove)]` attribute to bind listeners to the player Agent; the default implementation calls `agent.OnLogout()`. You can extend it according to your business needs:

```csharp
[Event(EventId.SessionRemove)]
internal sealed class SessionRemoveEventListener : EventListener<PlayerComponentAgent>
{
    protected override Task HandleEvent(PlayerComponentAgent agent, GameEventArgs gameEventArgs)
    {
        return agent.OnLogout();
    }
}
```

Source: [SessionRemoveEventListener.cs#L39-L45](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/SessionRemoveEventListener.cs#L39-L45)、[EventId.cs#L41](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Event/EventId.cs#L41)

## Common Variants

### Actively kick a player by role ID

```csharp
SessionManager.KickOffLineByUserId(roleId);
```

Dispatches `SessionRemove` internally, triggering `OnLogout`. Source: [SessionManager.cs#L79-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L79-L89).

### Clear all sessions on shutdown

```csharp
await SessionManager.RemoveAll();
```

Dispatches `SessionRemove` one by one, then `Clear()`s the dictionary. Source: [SessionManager.cs#L158-L170](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L158-L170).

### Query online players with pagination

`GetPageList(pageSize, pageIndex)` filters out Actors that no longer exist in `ActorManager`, returning only players who are actually online. Source: [SessionManager.cs#L65-L73](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L65-L73).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `GetByRoleId(roleId)` always returns null | The player Actor is not registered, or `SessionMap` has been asynchronously cleaned up | Ensure that `ActorManager` has registered the player during the login flow, and that the caller accesses it within the Session's lifecycle |
| The old connection is not closed immediately after the duplicate-login prompt is sent | Only `WriteAsync` was called without calling `WorkChannel.Close()` | Use the framework's built-in `SessionManager.UpdateSession` flow; do not manually manage the old session yourself |
| Disconnected players are not automatically removed from the room | `MarkPlayerDisconnected` was not called in `OnDisconnected` | Follow the [AppStartUpHotfixGameByMain.cs#L68-L76](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByMain.cs#L68-L76) template to forward disconnections to the room Agent |

## Background (Optional)

`SessionManager` uses `ConcurrentDictionary<string, Session>` as global storage, with one `SessionId` per connection; `Session` internally holds an `INetWorkChannel` for sending and receiving data. The "remove first, then wait for Disconnected" comment in `UpdateSession` ([L217](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Common/Session/SessionManager.cs#L217)) indicates that during duplicate login, relying solely on the disconnection callback for cleanup would introduce latency, so the old entry is synchronously `Remove`d to ensure state consistency.
