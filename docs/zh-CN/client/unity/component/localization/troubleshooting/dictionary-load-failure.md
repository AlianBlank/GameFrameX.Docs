# 字典加载失败（LoadDictionaryFailureEventArgs）怎么办

当本地化字典资源加载失败时，框架会抛出 `LoadDictionaryFailureEventArgs` 事件。该事件携带三个字段——`DictionaryAssetName`（失败的字典资源名）、`ErrorMessage`（错误信息）、`UserData`（发起加载时传入的自定义数据）——排查时先读这三个字段，即可定位是"资源名配置错"还是"资源缺失/加载异常"。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `ErrorMessage` 指示资源不存在/找不到 | 字典资源未生成或未打进资源包 | 按下文【修复步骤 1】核对资源是否可加载 |
| `DictionaryAssetName` 为空或不符预期 | 调用加载时传入了错误的资源名 | 按下文【修复步骤 2】回查调用处传入的资源名 |
| `UserData` 为空，无法区分是哪次加载失败 | 发起加载时未携带自定义数据 | 按下文【修复步骤 3】在加载调用处传入标记对象 |
| 事件从未触发、也无成功事件 | 事件未订阅，或加载流程未启动 | 按下文【修复步骤 4】确认订阅与加载调用 |

字段说明（取自事件类真实定义）：

| 属性 | 类型 | 构造时默认值 | 说明 |
|------|------|--------------|------|
| `DictionaryAssetName` | `string` | `null` | 加载失败的字典资源名称 |
| `ErrorMessage` | `string` | `null` | 错误信息（具体文本由底层加载链路返回） |
| `UserData` | `object` | `null` | 用户自定义数据 |

## 修复步骤

### 1. 用 ErrorMessage 确认资源是否可加载

在事件回调中打印三个字段，先看 `ErrorMessage` 的具体内容；若提示资源不存在，说明 `DictionaryAssetName` 对应的字典资源未生成或未随包构建，去检查该资源的生成/打包配置，而不是改代码。

```csharp
private void OnLoadDictionaryFailure(object sender, GameEventArgs e)
{
    var args = (LoadDictionaryFailureEventArgs)e;
    UnityEngine.Debug.LogError(
        $"字典加载失败: {args.DictionaryAssetName}, 错误: {args.ErrorMessage}");
}
```

Source: [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L36-L58)

说明：订阅/退订接口由 GameFrameX 事件组件提供，订阅时以 `LoadDictionaryFailureEventArgs.EventId` 为事件标识；回调参数类型为 `GameEventArgs`，强转为本事件类型后读取字段（事件基类与 `using GameFrameX.Event.Runtime;` 均来自该事件类文件的真实引用）。

### 2. 回查 DictionaryAssetName 的来源

`DictionaryAssetName` 的值等于发起加载时传入的 `dataAssetName`（见下方 `Create` 工厂方法），因此出现"名字不对"时，应回到调用加载的那一行代码，核对传入的资源名字符串（注意大小写、路径前缀与后缀）。

```csharp
public static LoadDictionaryFailureEventArgs Create(string dataAssetName, string errorMessage, object userData)
{
    LoadDictionaryFailureEventArgs loadDictionaryFailureEventArgs = ReferencePool.Acquire<LoadDictionaryFailureEventArgs>();
    loadDictionaryFailureEventArgs.DictionaryAssetName = dataAssetName;
    loadDictionaryFailureEventArgs.ErrorMessage = errorMessage;
    loadDictionaryFailureEventArgs.UserData = userData;
    return loadDictionaryFailureEventArgs;
}
```

Source: [LoadDictionaryFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/Runtime/EventArgs/LoadDictionaryFailureEventArgs.cs#L87-L102)

### 3. 用 UserData 区分多次加载

如果同帧有多个字典在加载，仅靠 `DictionaryAssetName` 可能不足以定位调用点。在每次发起加载时传入一个可识别的 `userData`（如调用方对象或枚举标记），失败事件中原样带回，即可确定是哪一次调用失败。

### 4. 确认事件确实被订阅、加载确实被发起

若既没有失败事件也没有成功事件（`LoadDictionarySuccessEventArgs`），先确认：

1. 事件监听已订阅（以 `LoadDictionaryFailureEventArgs.EventId` 为标识）；
2. 字典加载调用确实执行到（可在调用前后加日志）；
3. 使用的程序集未被裁剪——本组件通过 `GameFrameXLocalizationCroppingHelper` 显式保留类型，若你自定义了裁剪配置，需确保 `LoadDictionaryFailureEventArgs` 不被剔除：

```csharp
_ = typeof(ILocalizationManager);
_ = typeof(LoadDictionaryFailureEventArgs);
_ = typeof(LoadDictionarySuccessEventArgs);
```

## 验证

- 重新触发字典加载后，失败回调不再进入，或控制台不再输出你打印的失败日志；
- 相应字典资源出现 `LoadDictionarySuccessEventArgs`（成功事件，字段为 `DictionaryAssetName`、`Duration`、`UserData`），说明加载链路已恢复；
- 再次读取 `LocalizationComponent` 上的本地化文案，能取到字典中的条目。

关于加载成功/进度事件与本地化组件的整体用法，见仓库中文说明 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.localization/blob/main/README.zh-CN.md#L311-L313)。

## 背景

该事件继承自 `GameEventArgs`，实例从 `ReferencePool` 引用池获取（`ReferencePool.Acquire<LoadDictionaryFailureEventArgs>()`），并在 `Clear()` 中把三个字段重置为 `null` 后归还池中。因此回调中不要缓存事件对象本身，只应读取或拷贝字段值，事件分发后对象会被复用。
