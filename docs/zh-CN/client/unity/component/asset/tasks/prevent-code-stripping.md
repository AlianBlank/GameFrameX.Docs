# 如何避免代码裁剪导致的接口丢失

Unity 在出包时会执行托管代码裁剪（Managed Code Stripping），IL2CPP 编译后会删除未被引用的类型、方法和属性。当你的业务代码通过反射、字符串或动态加载访问 GameFrameX 资源接口时，被裁剪的扩展方法（如 `LoadTexture2DAsync`、`LoadPrefabSync`）会直接消失，运行时抛出 `MissingMethodException`。本页给出本仓库已经在用的防护方案，以及新增自定义扩展时必须遵循的写法。

## 前置条件

- 项目使用 Unity IL2CPP 后端（Android / iOS / WebGL 默认开启）。
- 启用了 Player Settings → Managed Stripping Level 高于 Low，或启用了 Engine Code Stripping。
- 已将 `GameFrameX.Asset` 包导入项目。

## 操作步骤

### 1. 复用仓库已经标注的扩展方法

仓库已经在所有公开扩展类和成员上加了 `[UnityEngine.Scripting.Preserve]`，直接调用即可，裁剪器会保留它们。例如下面的 `LoadTexture2DAsync` 扩展：

```csharp
[UnityEngine.Scripting.Preserve]
public static class AssetComponentTexture2DExtensions
{
    [UnityEngine.Scripting.Preserve]
    public static Task<AssetHandle> LoadTexture2DAsync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetAsync<Texture2D>(path);
    }

    [UnityEngine.Scripting.Preserve]
    public static AssetHandle LoadTexture2DSync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetSync<Texture2D>(path);
    }
}
```

Source: [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs#L13-L44)

`AssetComponent` 自身和 `GamePlayMode` 属性也带 `[Preserve]`：

```csharp
[RequireComponent(typeof(GameFrameXAssetCroppingHelper))]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-4000)]
public sealed class AssetComponent : GameFrameworkComponent
{
    [UnityEngine.Scripting.Preserve]
    public EPlayMode GamePlayMode { get; set; }
}
```

Source: [Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L18-L45)

### 2. 新增自定义扩展时也加上 Preserve 特性

在自己的项目里继续写 `AssetComponent` 的扩展方法时，必须给静态类和每个公共成员都加上 `[Preserve]`，否则裁剪器会视为"无人引用"并删除。

```csharp
using UnityEngine;
using UnityEngine.Scripting;
using GameFrameX.Asset.Runtime;

[Preserve]
public static class MyAssetComponentExtensions
{
    [Preserve]
    public static AssetHandle LoadMyAssetSync(this AssetComponent self, string path)
    {
        return self.LoadAssetSync<Object>(path);
    }
}
```

放置位置建议：与 `AssetComponent` 同目录或同程序集，便于裁剪器在构建时一起扫描。

### 3. 确认工程中存在辅助组件

`AssetComponent` 通过 `[RequireComponent]` 强制挂一个 `GameFrameXAssetCroppingHelper`，专门用于在场景里保活相关类型：

```csharp
[Preserve]
public class GameFrameXAssetCroppingHelper : MonoBehaviour
{
}
```

Source: [Runtime/GameFrameXAssetCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/GameFrameXAssetCroppingHelper.cs)

只要 `AssetComponent` 实例存在于运行场景中（`GameFrameXAutoComponent` 启动框架时会自动创建），裁剪器就会保留这条引用链上的所有标记成员。

### 4. 必要时提供 link.xml 做兜底

如果你的业务侧通过反射（例如基于字符串名调用 `LoadPrefabAsync`）访问资源接口，编译期引用无法被分析器识别，请额外在 `Assets/` 下放置 `link.xml`，强制保留整个程序集：

```xml
<linker>
  <assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>
</linker>
```

`link.xml` 必须放在任意 `Resources` 目录之外的 `Assets` 子目录下，Unity 才会处理。

## 常见变体

| 场景 | 做法 |
|------|------|
| 通用泛型入口 `LoadAssetAsync<T>` | 直接调用，T 由调用方提供，引用链会被静态分析识别，无需额外 `[Preserve]`。 |
| 自定义异步包装层 | 在包装方法外层加上 `[Preserve]`，并确保包装方法至少被一处代码静态调用。 |
| WebGL 平台 | 强制走 `EPlayMode.WebPlayMode`，`AssetComponent.Awake` 已内置该分支。 |
| 通过 Addressables / YooAsset 间接反射调用 | 同时提供 `link.xml` 兜底。 |

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| 出包后调用 `LoadXxxAsync` 报 `MissingMethodException` | 该扩展方法未被任何代码静态引用，被 IL2CPP 裁剪。 | 给扩展类和方法补 `[UnityEngine.Scripting.Preserve]`。 |
| 反射调用 `GameFrameX.Asset.Runtime` 程序集里的类型失败 | 整个程序集被裁剪。 | 在 `Assets/link.xml` 里加 `<assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>`。 |
| WebGL 出包后资源加载报错 `Asset manager is invalid.` | 运行模式被还原成 `EditorSimulateMode`。 | `AssetComponent.Awake` 已经处理，确认 `m_GamePlayMode` 在构建产物里被序列化。 |
| 删除场景中的 `AssetComponent` 后所有资源接口消失 | `RequireComponent(GameFrameXAssetCroppingHelper)` 一起被移除。 | 不要单独删除 `AssetComponent`，如需替换请同时把 `CroppingHelper` 保留下来或重新挂上。 |

## 验证

1. 在 Unity Editor → Build Settings 出 IL2CPP 包（Android 或 iOS）。
2. 在真机/模拟器上执行 `await assetComponent.LoadTexture2DAsync("Assets/Textures/xxx.png");`，确认无 `MissingMethodException`。
3. 用 `il2cppdumper` 或 `Unity Symbol` 工具反查包内 dll，确认 `GameFrameX.Asset.Runtime` 程序集里的扩展类型仍存在。
4. 若仍失败，逐步剥离自定义 `link.xml` / `[Preserve]` 标记，定位被裁剪的成员。

## 背景（可选）

`[UnityEngine.Scripting.Preserve]` 是 Unity 官方提供给托管代码裁剪器的"白名单"标记，等价于在 link.xml 中按成员逐一保留。仓库在所有公开扩展 API 上加该标记，是因为这些方法多用于反射或泛型间接调用，编译期引用图无法覆盖。本节涉及源码：[Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs) 与 [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs)。
