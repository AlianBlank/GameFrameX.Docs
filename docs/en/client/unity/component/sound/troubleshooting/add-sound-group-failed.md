# What to Do When a Sound Group Already Exists / Adding Fails

When calling `AddSoundGroup` on `SoundComponent`, if it returns `false` or throws a `GameFrameworkException`, it is usually caused by a duplicate group name or an invalid name. This page provides quick troubleshooting and fix steps.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `AddSoundGroup` returns `false` with no exception | A sound group with the same name already exists | Call `HasSoundGroup` first to check; if it already exists, do not add it again |
| Throws `GameFrameworkException: Sound group name is invalid.` | The sound group name is `null`, an empty string, or all whitespace | Pass in a non-empty group name with leading/trailing whitespace removed |
| Newly added group not visible in the Editor Inspector | The group was added at runtime via code and is not written back to the Inspector | For runtime debugging only; pre-configure in the Inspector if persistence is needed |
| No sound when playing immediately after adding | Adding succeeded but `AgentHelperCount` was not configured, or the volume is muted | Check the parameters `soundGroupMute` / `soundGroupVolume` |

## Fix Steps

### 1. Check for Existence Before Adding

`AddSoundGroup` directly returns `false` when a group with the same name already exists. It is recommended to guard with `HasSoundGroup` first:

```csharp
using GameFrameX.Sound.Runtime;

const string groupName = "UI";

if (!GameEntry.Sound.HasSoundGroup(groupName))
{
    GameEntry.Sound.AddSoundGroup(groupName, false, false, 1f, new DefaultSoundGroupHelper());
}
```

For the API signatures, see [ISoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Interface/ISoundManager.cs#L77-L104):

- `bool HasSoundGroup(string soundGroupName)`
- `bool AddSoundGroup(string soundGroupName, ISoundGroupHelper soundGroupHelper)`
- `bool AddSoundGroup(string soundGroupName, bool soundGroupAvoidBeingReplacedBySamePriority, bool soundGroupMute, float soundGroupVolume, ISoundGroupHelper soundGroupHelper)`

The implementation is located in [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L167-L255).

### 2. Handling the "Invalid Group Name" Exception

The source code throws an exception directly when the group name is empty:

```csharp
if (string.IsNullOrWhiteSpace(soundGroupName))
{
    throw new GameFrameworkException("Sound group name is invalid.");
}
```

Fix: validate before calling:

```csharp
string groupName = inputName?.Trim();
if (string.IsNullOrEmpty(groupName))
{
    // Use your own fallback logic, e.g., fall back to the default group "Sound"
    groupName = "Sound";
}
GameEntry.Sound.AddSoundGroup(groupName, new DefaultSoundGroupHelper());
```

For where the exception is thrown, see [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L171-L186).

### 3. Handling "False Non-Existence" Caused by Case Differences or Leading/Trailing Spaces

`HasSoundGroup` / `AddSoundGroup` internally use literal strings as keys (see [SoundManager.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/Sound/SoundManager.cs#L167-L186)). `"UI"`, `"ui"`, and `" UI "` are treated as different groups, making you think the addition failed when in fact a duplicate group was added.

Fix: consistently call `Trim()` before invoking and agree on a casing convention, e.g., use `ToLowerInvariant()` everywhere, or follow your project's naming convention.

### 4. Common Pattern to Avoid Duplicate Initialization

Encapsulate "ensure exists" into a helper method for centralized handling:

```csharp
public static void EnsureSoundGroup(string name, bool mute = false, float volume = 1f)
{
    var sound = GameEntry.Sound;
    if (sound.HasSoundGroup(name))
    {
        return;
    }
    sound.AddSoundGroup(name, false, mute, volume, new DefaultSoundGroupHelper());
}
```

Call `EnsureSoundGroup("Music")`, `EnsureSoundGroup("SFX")`, and `EnsureSoundGroup("UI")` uniformly at entry points such as scene switching and module startup, to avoid business code adding them separately and causing duplicates.

## Verification

1. Add logging before and after the add logic to confirm that `HasSoundGroup` returns the expected value (`false` before adding, `true` after adding).
3. Call `AddSoundGroup` again with the same group name; it should return `false` without throwing an exception.
2. Trigger the exception path once with an empty string / `null`, and confirm the exception message is `Sound group name is invalid.`, making it easier to identify during later troubleshooting.
