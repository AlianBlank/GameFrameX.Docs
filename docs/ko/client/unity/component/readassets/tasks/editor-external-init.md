# Editor에서 외부 APK/사용자 정의 디렉토리로 초기화 (Android 빌드 테스트)

Unity Editor에서 외부 APK 파일 또는 사용자 정의 디렉토리를 통해 `BlankReadAssets`를 초기화하여, 실제 기기 패키징 없이 Android StreamingAssets의 읽기 동작을 시뮬레이션합니다. AssetBundle, 핫 업데이트 리소스 또는 Android 전용 경로 로직의 로컬 디버깅에 사용됩니다.

## 사전 조건

- 프로젝트에 `GameFrameX.ReadAssets` 패키지가 도입되어 있으며, `Runtime/BlankReadAssets.cs`가 존재합니다.
- `UNITY_EDITOR`에서만 유효: 이 두 API는 `#if UNITY_EDITOR`로 감싸여 있어 실제 기기 패키징에는 포함되지 않습니다.
- 테스트할 APK는 StreamingAssets가 `assets/`에 위치한 표준 Android 패키지여야 합니다 (Unity 기본 내보내기 형식).

## 작업 단계

`BlankReadAssets`는 Editor 전용 진입점 두 개를 제공하며, 디버깅 대상에 따라 둘 중 하나를 선택합니다.

### 방법 A: 외부 APK로 초기화

```csharp
using GameFrameX.ReadAssets.Runtime;

// 형식: Application.dataPath + "/../test.apk"
BlankReadAssets.InitializeWithExternalApk(apkPath);
```

소스 코드 진입점과 시그니처:

```csharp
[Preserve]
public static void InitializeWithExternalApk(string apkPath)
{
    BlankReadAssetsImpl.ApkMode = true;
    BlankReadAssetsImpl.Initialize(apkPath, "jar:file://" + apkPath + "!/assets/");
    s_initialized = true;
}
```

출처: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L80-L87)

이 호출은 `EditorImpl.ApkMode`를 `true`로 설정하여, 이후의 `FileExists` / `OpenRead` / `ReadAllBytes` / `GetFiles`가 모두 `ApkImpl`(즉, APK 내부의 `jar:file://...!/assets/` 경로 읽기)을 거치도록 합니다.

### 방법 B: 사용자 정의 디렉토리로 초기화

```csharp
using GameFrameX.ReadAssets.Runtime;

// dataPath:파일 시스템에서 StreamingAssets의 부모 디렉토리 루트
// streamingAssetsPath:StreamingAssets 자체의 실제 경로 (임의의 디렉토리 사용 가능)
BlankReadAssets.InitializeWithExternalDirectories(dataPath, streamingAssetsPath);
```

소스 코드 진입점과 시그니처:

```csharp
[Preserve]
public static void InitializeWithExternalDirectories(string dataPath, string streamingAssetsPath)
{
    BlankReadAssetsImpl.ApkMode = false;
    BlankReadAssetsImpl.Initialize(dataPath, streamingAssetsPath);
    s_initialized = true;
}
```

출처: [BlankReadAssets.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L89-L95)

빌드된 StreamingAssets를 임의의 디렉토리에 복사한 후, Editor에서 "파일 디렉토리" 형식으로 직접 읽기를 시뮬레이션하는 데 적합합니다.

### 단계 3: 읽기 API 호출 검증

```csharp
if (BlankReadAssets.FileExists("config/game.json"))
{
    byte[] bytes = BlankReadAssets.ReadAllBytes("config/game.json");
    // 또는 AssetBundle 읽기
    var bundle = BlankReadAssets.LoadAssetBundle("bundles/ui.bundle");
}
```

초기화 플래그 `s_initialized`는 한 번 호출된 후 `true`로 설정되며, 이후 모든 API는 다시 초기화하지 않습니다.

## 일반적인 변형

| 시나리오 | 권장 방법 | 설명 |
|------|----------|------|
| 실제 Android 빌드의 StreamingAssets 읽기 검증 | 방법 A (APK) | 경로 접두사가 `jar:file://<apk>!/assets/`로 고정되어 실제 기기와 동일 |
| 로컬 StreamingAssets 디렉토리로 디버깅 | 방법 B (사용자 정의 디렉토리) | `streamingAssetsPath`가 프로젝트 `Assets/StreamingAssets` 외부의 사용자 정의 디렉토리를 가리킴 |
| `Awake` 이전에 사전 워밍업 | 둘 중 하나를 수동으로 호출 | `s_initialized = true`로 설정되어 이후 `EnsureInitialized`가 모드를 다시 재설정하지 않음 |

모드를 전환할 때 (APK ↔ 사용자 정의 디렉토리) 해당 초기화 메서드를 다시 호출해야 합니다. `ApkMode`는 정적 플래그이기 때문입니다.

## 일반적인 오류

- Player 빌드에서 이 두 메서드를 호출: `#if UNITY_EDITOR`로剥离되어 컴파일 실패 또는 런타임에 심볼을 찾을 수 없게 됩니다.
- 모드 전환 후 다시 초기화하는 것을 잊음: 이전 호출의 `ApkMode`가 여전히 `true`이므로 모든 읽기는 APK 분기를 계속 거칩니다.
- `InitializeWithExternalApk`에 존재하지 않는 APK 경로를 전달: `ApkImpl.Initialize`는主动적으로 오류를 발생시키지 않지만, 이후 `FileExists` / `OpenRead`에서 파일을 찾을 수 없게 됩니다. 먼저 `File.Exists(apkPath)`로 자체 점검해야 합니다.
- `Application.streamingAssetsPath`와 APK 내부 경로를 혼동: APK 모드에서 `streamingAssetsPath`는 내부적으로 `jar:file://...!/assets/`로 대체되므로 `Application.streamingAssetsPath`를 수동으로 전달해서는 안 됩니다.

## 배경 (선택 사항)

Editor 내 `BlankReadAssetsImpl`은 조건부 컴파일로 구현을 선택합니다: `UNITY_EDITOR`는 `EditorImpl`로, Android는 `ApkImpl`로, 기타 플랫폼은 `LooseFilesImpl`로 분기합니다. `EditorImpl`은 내부적으로 `ApkMode` 플래그에 따라 요청을 `ApkImpl` 또는 `LooseFilesImpl`로 전달하여, 에디터 프로세스에서 다양한 플랫폼의 읽기 동작을 시뮬레이션합니다.
