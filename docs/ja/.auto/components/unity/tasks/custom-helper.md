# カスタム Helper を組み込んでデフォルト実装を置き換える

GameFrameX が提供する `Helper.CreateHelper<T>` エントリーポイントを使用することで、フレームワーク起動時にカスタム Helper でデフォルト実装(ログ、圧縮、バージョン、JSON、テキストヘルパーなど)を置き換え、プロジェクト内部のツールチェーンやサードパーティ製 SDK との統合が可能になります。

## 前提条件

- クイックスタートドキュメントに従って `GameFrameX` フレームワークを初期化済みであり、`Awake/Start` で `GameFrameXComponent` を取得できること。
- カスタム Helper クラスが対応するインターフェースを実装済みであること(例: `GameFrameworkLog.ILogHelper`、`Utility.Compression.ICompressionHelper`、`Utility.Json.IJsonHelper`、`Utility.Text.ITextHelper`、`GameVersion.IVersionHelper`)、かつ Unity アセンブリでリフレクションによって検出可能であること。
- カスタム Helper が `MonoBehaviour` 派生クラスであること(フレームワークは `GameObject.AddComponent` で作成します)。

## 操作手順

### 1. カスタム Helper を実装する

新しいクラスを作成し、フレームワーク内蔵のインターフェースを実装します。以下はデフォルトのログヘルパーを置き換える例です:

```csharp
using UnityEngine;
using GameFrameX;

namespace GameFrameX.Runtime
{
    [UnityEngine.Scripting.Preserve]
    public class MyLogHelper : GameFrameworkLog.ILogHelper
    {
        public void Log(GameFrameworkLogLevel level, object message)
        {
            // プロジェクト独自のログ SDK に接続(例: サーバーへのアップロードやローカルファイルへの書き込み)
            MyLogger.Write(level, message);
        }
    }
}
```

参考: [Runtime/Helper/DefaultLogHelper.cs](/Runtime/Helper/DefaultLogHelper.cs#L42-L83)

### 2. 文字列の型名で登録する

カスタム Helper の完全修飾クラス名(名前空間を含む)を `Helper.CreateHelper<T>` に渡します。フレームワークはリフレクションでその型を検索し、新しい `GameObject` に `AddComponent` します:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: "GameFrameX.Runtime.MyLogHelper",
    customHelper: null);
```

文字列方式の利点は、シーンにあらかじめコンポーネントを配置する必要がないことで、純粋なコードベースのプロジェクトに適しています。

### 3. プレファブコンポーネントで登録する

カスタム Helper を `MonoBehaviour` スクリプトとしてプレファブにアタッチし、`customHelper` パラメータに直接渡します。フレームワークはコンポーネントが既にシーンに存在するかどうかを判断し、直接再利用するか `Instantiate` で複製するかを決定します:

```csharp
// myLogHelperPrefab はプレファブ上の MyLogHelper コンポーネント参照
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    helperTypeName: string.Empty,
    customHelper: myLogHelperPrefab);
```

`helperTypeName` を空にし、`customHelper` が非空の場合、`customHelper` が優先されます。逆に文字列で型を検索します。両方とも空の場合、フレームワークは警告を出力して `null` を返します。

### 4. フレームワークエントリポイントに組み込む

`GameFrameXComponent.Awake` または初期化フローで、作成した Helper を対応するサブシステムに注入します。`Log` モジュールを例にすると:

```csharp
var logHelper = Helper.CreateHelper<GameFrameworkLog.ILogHelper>(
    "GameFrameX.Runtime.MyLogHelper", null);
GameFrameworkLog.SetLogHelper(logHelper);
```

ソースコードの登録エントリについては [Runtime/Helper/Helper.cs](/Runtime/Helper/Helper.cs#L57-L106) を参照してください。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| 警告 `Can not find helper type 'XXX'.` | 文字列のクラス名のスペルミス、名前空間の欠落、またはアセンブリでリフレクションが有効化されていない | `Type.FullName` で照合する;クラスが含まれるアセンブリが IL2CPP で削除されていないことを確認する |
| 警告 `Type 'A' is not assignable from 'B'.` | カスタムクラスが対象インターフェースを実装していない | カスタムクラスに対応する `IXxxHelper` を `implements` する |
| 警告 `You must set custom helper with '...' type first.` | `helperTypeName` が空で、`customHelper` も `null` の場合 | どちらか一方を入力する。または先に `AddComponent` してから渡す |
| カスタムロジックが有効にならない | 対応するサブシステムの `SetXxxHelper` 注入が呼び出されていない | フレームワーク初期化の早い段階で `CreateHelper` + `SetHelper` 注入を完了させる |

## 背景(オプション)

`Helper.CreateHelper<T>` は内部的に `Utility.Assembly.GetType` を使用して文字列で型を検索し、見つかったら `new GameObject().AddComponent` でインスタンス化します。`customHelper` が渡された場合、コンポーネントが既にシーンに存在するかに応じて再利用または `Instantiate` を行います。2つのパラメータは相互にフォールバックとして機能し、設定駆動型プロジェクトと非設定駆動型プロジェクトの両方で統合できます。
