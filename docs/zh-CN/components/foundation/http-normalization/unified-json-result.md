# 如何使用统一 JSON 响应格式

`GameFrameX.Foundation.Http.Normalization` 提供 `HttpJsonResultData<T>` 作为 HTTP 接口的统一 JSON 响应包装。所有成功与失败响应都使用同一份字段约定（`code` / `message` / `data` / `trackId` / `errorCode` / `type` / `time` / `extras`），前端只需按字段名解析即可拿到一致结构。

## 前置条件

- .NET 项目引用 `GameFrameX.Foundation.Http.Normalization`（命名空间 `GameFrameX.Foundation.Http.Normalization`）。
- 序列化使用仓库自带的 `GameFrameX.Foundation.Json.JsonHelper`，会自动保留中文与 Emoji 不被转义。

## 操作步骤

### 1. 返回成功响应（带数据）

调用泛型工厂方法 `HttpJsonResultData<T>.Success(data)`，直接通过控制器 / 处理器返回。

```csharp
using GameFrameX.Foundation.Http.Normalization;

[HttpGet("{id}")]
public HttpJsonResultData<UserInfo> GetUser(int id)
{
    var user = _repository.Find(id);
    return HttpJsonResultData<UserInfo>.Success(user);
}
```

序列化后大致为：

```json
{
  "code": 0,
  "message": "",
  "data": { "id": 1, "name": "Alice" },
  "trackId": "",
  "time": 1714000000
}
```

> `code == 0` 即视为成功；`IsSuccess` 属性会按此规则自动计算（不参与序列化）。

Source: [HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L213-L220)

### 2. 返回失败响应（带错误消息）

使用 `Fail(message)` / `Fail(code, message)` 工厂方法，或者按语义选择 `ParamError`、`Unauthorized`、`NotFound`、`ServerError` 等预设错误工厂。

```csharp
[HttpGet("{id}")]
public HttpJsonResultData<UserInfo> GetUser(int id)
{
    if (id <= 0)
    {
        return HttpJsonResultData<UserInfo>.ParamError("id 必须大于 0");
    }

    var user = _repository.Find(id);
    if (user == null)
    {
        return HttpJsonResultData<UserInfo>.NotFound();
    }
    return HttpJsonResultData<UserInfo>.Success(user);
}
```

失败响应示例：

```json
{
  "code": 403,
  "message": "id 必须大于 0",
  "trackId": "",
  "errorCode": "PARAM.ERROR",
  "type": "error",
  "time": 1714000000
}
```

Source: [HttpJsonResultConstants.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultConstants.cs#L31-L115)

### 3. 携带链路追踪 ID 与业务错误码

`TrackId` 用于把响应、日志、下游调用串起来；`ErrorCode` 是稳定的业务错误码字符串（与 `Code` 语义正交）。两者都可以在创建后赋值。

```csharp
var result = HttpJsonResultData<OrderDto>.Fail(HttpJsonResultConstants.ValidationErrorCode, "订单已关闭");
result.TrackId = Activity.Current?.TraceId.ToString();
result.ErrorCode = "ORDER.CLOSED";
result.Type = "error";
result.Extras = new { orderId = 42, closedAt = DateTime.UtcNow };
return result;
```

> `extras` 仅在非空时参与序列化；`errorCode` / `type` 同理。

Source: [HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L128-L186)

### 4. 直接拿到 JSON 字符串

如果接口需要直接吐出 JSON 文本（中间件 / 旧框架），可用 `SuccessString()` / `FailString()`，或先构造再调用 `.ToString()`，内部走 `JsonHelper.Serialize`。

```csharp
return HttpJsonResultData<UserInfo>.SuccessString();
// 或
return HttpJsonResultData<UserInfo>.Fail("服务暂不可用").ToString();
```

Source: [HttpJsonResultData.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Http.Normalization/HttpJsonResultData.cs#L229-L232)

## 常见变体

| 场景 | 推荐用法 | 说明 |
|------|----------|------|
| 只关心成功/失败布尔 | `IsSuccess` 属性 | `JsonIgnore`，仅用于服务端短路判断 |
| 已有任意类型要包装 | `HttpJsonResultData<T>.Success(obj)` | 泛型 `T` 无约束，可传任意引用/值类型 |
| 第三方接口响应转统一结构 | `IHttpJsonResult` 接口 | `Data` 返回序列化后的 JSON 字符串，便于跨类型消费 |
| 失败但要保留部分数据 | `Fail(code, message, data)` 重载 | `data` 字段仍会回传给前端 |

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `IsSuccess` 始终为 `false` | 误把 `Code` 设成业务错误码字符串或非 0 整数 | 仅用 `0` 表达成功，其他值视为失败 |
| 中文被转义成 `\uXXXX` | 没用 `JsonHelper.Serialize` | 始终通过 `.ToString()` 或工厂方法返回，由内部统一序列化 |
| 客户端拿不到 `extras` | 字段为 `null` | 显式赋非空对象；为 null 时不参与序列化是预期行为 |
| `code` 与 `errorCode` 混淆 | 把 HTTP 状态码写进 `ErrorCode` | `Code` 走 HTTP/状态语义（数字），`ErrorCode` 走稳定业务字符串 |

## 验证

1. 启动接口后用 `curl` 调用，确认返回 JSON 同时包含 `code`、`message`、`data` 三个核心字段。
2. 触发失败分支，确认 `code` 非 0、`message` 有人类可读描述、`IsSuccess` 在服务端短路判断中返回 `false`。
3. 若启用 `TrackId`，检查响应、日志、调用链中是否出现同一个 `trackId` 值。

## 背景

- `IHttpJsonResult` 把 `HttpJsonResultData<T>` 的 `Data` 序列化为 JSON 字符串，屏蔽泛型差异，便于非泛型上下文（例如中间件、日志拦截）统一处理。
- `HttpJsonResultConstants` 集中维护 `SuccessCode=0`、`FailCode=-1`、`ValidationErrorCode=400`、`UnauthorizedCode=401`、`ParamErrorCode=403`、`NotFoundCode=404`、`ServerErrorCode=500` 等数字与默认消息常量，避免业务侧散落魔数。
- `IsSuccess` 改为只读属性后由 `Code` 自动计算，构造时无需手动维护成功标志位。
