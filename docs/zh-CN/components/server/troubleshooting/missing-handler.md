# 客户端发来消息但找不到对应 Handler 怎么办

当客户端发出请求而服务端日志出现 `找不到[xxx][yyy]对应的handler` 时,说明框架没找到能处理该消息 ID 的 Handler 类。这通常是消息类与 Handler 命名/标注不匹配、程序集未加载、或路由表未刷新造成的。

## 快速诊断

| 症状(日志原文) | 原因 | 修复 |
|---|---|---|
| `找不到[{MessageId}][{Type}]对应的handler` | 客户端发的 `MessageId` 在服务端没注册过对应 `ReqXxxHandler` | 新建 Handler 并确认 `MessageMapping` 与消息 ID 一致 |
| 客户端发来某消息,服务端无任何日志,连接被静默关闭 | 程序集未启动 / 热更未发布新版本,Handler 没有被反射加载 | 重新发布或重启 `GameFrameX.Hotfix` |
| 日志出现 MessageType 但运行时报 "Handler not found",重启后恢复 | 路由缓存(`MessageProtoHandler`)初始化时未扫描到该类型,后续服务端未触发重新初始化 | 在 `Launcher` 启动流程中再次执行 `MessageProtoHelper.Init` |
| 改名 Handler 类后报错 | 类名不再匹配约定 `Req<消息名>Handler`,且缺少特性标注 | 改回命名约定,或为类加上 `[MessageMapping]` |

> 日志样本见仓库:`AppStartUpHotfixGameByGateWay.cs` 第 126 行、`AppStartUpHotfixGameByMain.cs` 第 133 行。

## 修复步骤

### 1. 确认服务端真的没有这个 Handler

在 `GameFrameX.Hotfix` 项目里搜索 `Req<消息名>Handler`。例如消息 ID 对应 `ReqLogin`,应存在:

```csharp
// 源码路径:GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs
[MessageMapping(typeof(ReqLogin))]
internal class ReqLoginHandler : GlobalComponentHandler<LoginComponentAgent>
{
    protected override async Task ActionAsync()
    {
        await ComponentAgent.OnLogin(NetWorkChannel, Message as ReqLogin);
    }
}
```

Source: [ReqLoginHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Account/Login/ReqLoginHandler.cs#L32-L44)

注意要点:
- 类名必须为 `Req<MessageName>Handler`(以 `Req` 开头,以 `Handler` 结尾)。
- 必须继承自框架基类(如 `GlobalComponentHandler<...>`、`MessageHandler<...>`),否则反射不会注册。
- 必须带有 `[MessageMapping(typeof(对应消息类))]` 特性,显式声明它处理哪个消息类。

### 2. 确认消息类型已加入协议程序集

Handler 引用的消息类(如 `ReqLogin`)定义在 `GameFrameX.Proto` 项目里。如果你在 `Proto` 中新增了消息,需要在 `Launcher` 启动时让 `MessageProtoHelper` 重新扫描该程序集:

```csharp
// 源码路径:GameFrameX.Launcher/Program.cs
CacheStateTypeManager.Init();
MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
```

Source: [Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L14-L16)

`MessageProtoHandler` 类自身是个静态占位类,目的是提供一个 `Assembly` 句柄给 `MessageProtoHelper.Init`,用于把 `Proto` 里的 `MessageId` 全部登记到路由表:

Source: [MessageProtoHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/MessageProtoHandler.cs#L1-L8)

### 3. 确认 `Hotfix` / `Apps` 程序集存在标记类

框架通过反射扫描 `GameFrameX.Hotfix.HotfixHandler` 与 `GameFrameX.Apps.AppsHandler` 这两个空类所在的程序集来发现所有 Handler 类型。改动或裁剪项目时不要删除它们,否则新加的 Handler 不会被加载:

```csharp
// 源码路径:GameFrameX.Hotfix/HotfixHandler.cs
namespace GameFrameX.Hotfix;
public static class HotfixHandler { }
```

```csharp
// 源码路径:GameFrameX.Apps/AppsHandler.cs
namespace GameFrameX.Apps;
public class AppsHandler { }
```

Source: [HotfixHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/HotfixHandler.cs#L1-L8), [AppsHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/AppsHandler.cs#L32-L38)

### 4. 编译并重启服务端

如果运行的是热更新模式,改完 Handler 后重新发布 `Hotfix` DLL,并重启服务端进程,让 `CacheStateTypeManager` 重新执行一遍反射初始化:

```csharp
// 源码路径:GameFrameX.Apps/CacheStateTypeManager.cs
var assembly = typeof(AppsHandler).Assembly;
BsonClassMapHelper.SetConvention();
```

Source: [CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L18-L22)

## 验证

修复后按下面顺序确认问题已解决:

1. **看日志**:重启服务端,客户端再次发送该消息,日志不应再出现 `找不到[…]对应的handler`,而应进入对应 Handler 的 `ActionAsync`。
2. **断点验证**:在新建 Handler 的 `ActionAsync` 里打断点,客户端发请求时命中即表示路由成功。
3. **看响应**:客户端若期望回包,确认收到正确消息 ID 的响应体(消息 ID 在 `GameFrameX.Proto` 的 `MessageProto` 工具类生成)。
4. **对照同目录其他 Handler**:把新建文件与能正常工作的 Handler(例如 `ReqCreateRoomHandler`)逐字对比,确认命名空间、基类、特性三者一致。

如果日志里出现的 `MessageId` 在 `GameFrameX.Proto` 也搜不到,说明问题在协议侧(客户端发的协议是另一套),需先同步协议再谈 Handler。
