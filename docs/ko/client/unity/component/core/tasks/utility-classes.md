# 유틸리티 클래스 사용 (암호화, 압축, 변환)

GameFrameX는 `GameFrameX.Runtime.Utility` 네임스페이스에서 암호화(`Utility.Encryption` / `Utility.Encryption.Aes`), 압축(`Utility.Compression`), 데이터 변환(`Utility.Converter`)을 다루는 정적 유틸리티 클래스 그룹을 제공합니다. 모든 클래스는 정적이기 때문에 인스턴스화 없이 바로 호출할 수 있습니다.

## 사전 조건

- 프로젝트에 `GameFrameX.Runtime` 어셈블리가 포함되어 있어야 합니다.
- 네임스페이스: `GameFrameX.Runtime`, 일반적으로 `using GameFrameX.Runtime;`을 사용합니다.
- 압축을 사용하기 전에 먼저 `ICompressionHelper` 구현체를 등록해야 합니다(프레임워크에는 기본 내장 압축 구현이 없습니다).

## 작업 단계

### 1. 암호화 및 복호화

프레임워크는 두 가지 유형의 암호화를 제공합니다. XOR 빠른 난독화(경량, 로컬 저장용)와 AES(표준 대칭 암호화, 네트워크 패킷용)입니다.

**AES 암복호화 사용 (Base64 문자열)**

```csharp
using GameFrameX.Runtime;

// 암호화 (Base64 문자열 반환)
string cipher = Utility.Encryption.Aes.AESEncryptSecure("Hello, GameFrameX!", "my-secret-key");

// 복호화 (Base64 문자열에서 복원)
string plain = Utility.Encryption.Aes.AESDecryptSecure(cipher, "my-secret-key");
```

Source: [Runtime/Utility/Utility.Encryption.Aes.cs](/Runtime/Utility/Utility.Encryption.Aes.cs#L40-L90)

> 참고: `AESEncrypt` / `AESDecrypt`는 `[Obsolete]`로 표시되어 있으며, 소스 코드에서 하드코딩된 IV/Salt는 안전하지 않다고 안내합니다. 새 코드에서는 `AESEncryptSecure` / `AESDecryptSecure`를 사용하세요.

**XOR 빠른 난독화 사용**

```csharp
using GameFrameX.Runtime;

byte[] data = System.Text.Encoding.UTF8.GetBytes("payload");
byte[] key  = System.Text.Encoding.UTF8.GetBytes("xor-key");

// 새 배열 반환 (원본 배열은 변경되지 않음)
byte[] cipher = Utility.Encryption.GetQuickXorBytes(data, key);

// 전달된 bytes를 재사용하고 덮어쓰기 (추가 할당 없음)
Utility.Encryption.GetQuickSelfXorBytes(data, key);
```

`GetQuickXorBytes`는 내부적으로 `GetXorBytes(bytes, 0, 220, code)`를 호출하여 앞쪽 220 바이트만 XOR 처리합니다. 설정 테이블과 같은 소규모 데이터를 가볍게 난독화하는 데 적합하며, 보안 수단으로는 적합하지 않습니다.

Source: [Runtime/Utility/Utility.Encryption.cs](/Runtime/Utility/Utility.Encryption.cs#L50-L100)

### 2. 압축 및 압축 해제

`Utility.Compression`은 플러그인 방식입니다. 실제 알고리즘은 `ICompressionHelper`가 결정합니다. 호출 전에 반드시 구현체를 주입해야 합니다.

```csharp
using System.IO;
using GameFrameX.Runtime;

// 1) 압축 구현체 등록 (본인이 직접 또는 타사 라이브러리에서 제공)
Utility.Compression.SetCompressionHelper(new MyCompressionHelper());

// 2) 바이트 배열 압축
byte[] src    = System.Text.Encoding.UTF8.GetBytes("big payload...");
byte[] packed = Utility.Compression.Compress(src);

// 3) 바이트 배열 압축 해제
byte[] unpacked = Utility.Compression.Decompress(packed);
```

소스 코드는 `bytes == null`일 때 `GameFrameworkException("Bytes is invalid.")`을 던집니다. `ICompressionHelper`가 등록되지 않은 상태에서 `Compress`/`Decompress`를 호출하면 빈 결과나 예외가 발생하며, 구체적인 동작은 구현체에 따라 달라집니다.

Source: [Runtime/Utility/Utility.Compression.cs](/Runtime/Utility/Utility.Compression.cs#L49-L100),[Runtime/Utility/Utility.Compression.ICompressionHelper.cs](/Runtime/Utility/Utility.Compression.ICompressionHelper.cs)

`Compress` / `Decompress`는 `Stream` 오버로드와 `offset` + `length` 오버로드도 제공하여 대용량 데이터를 처리할 수 있습니다.

```csharp
using System.IO;
using GameFrameX.Runtime;

byte[] header = Utility.Compression.Compress(src, 0, src.Length);          // 구간 압축
bool ok       = Utility.Compression.Compress(src, new MemoryStream());     // 스트림으로 압축
```

Source: [Runtime/Utility/Utility.Compression.cs](/Runtime/Utility/Utility.Compression.cs#L66-L160)

### 3. 데이터 변환

`Utility.Converter`는 바이트 순서, 화면 단위, 그리고 다양한 `byte[]` ↔ 기본 타입 변환을 제공합니다.

**시스템 바이트 순서 확인**

```csharp
using GameFrameX.Runtime;
bool littleEndian = Utility.Converter.IsLittleEndian; // BitConverter.IsLittleEndian에 위임
```

**픽셀과 센티미터 상호 변환 (먼저 DPI 설정 필요)**

```csharp
using GameFrameX.Runtime;

Utility.Converter.ScreenDpi = 96f; // 시작 시 한 번 설정
float cm = Utility.Converter.GetCentimetersFromPixels(1920f); // 픽셀 -> 센티미터
float px = Utility.Converter.GetPixelsFromCentimeters(10f);    // 센티미터 -> 픽셀
```

소스 코드는 `ScreenDpi <= 0`일 때 `GameFrameworkException("You must set screen DPI first.")`을 던집니다.

Source: [Runtime/Utility/Utility.Converter.cs](/Runtime/Utility/Utility.Converter.cs#L49-L100)

**바이트 배열과 기본 타입 상호 변환**

`Utility.Converter`는 `GetBytes` / `GetXxx` 계열 오버로드도 제공하여 `byte[]`을 `int` / `long` / `float` / `double` / `string` 등으로 변환할 수 있으며, `startIndex`로 오프셋을 지정할 수 있어 프로토콜 파싱에 유용합니다.

```csharp
using GameFrameX.Runtime;

byte[] buffer = /* 네트워크 패킷 */;
int   cmdId   = Utility.Converter.GetInt32(buffer, 0);
string name   = Utility.Converter.GetString(buffer, 4);
```

## 일반적인 변형

- **네트워크 패킷 암호화**: 일반적으로 AES(패킷 본문) + RSA(키 교환)를 조합하여 사용합니다. [Runtime/Utility/Utility.Encryption.Rsa.cs](/Runtime/Utility/Utility.Encryption.Rsa.cs) 참고.
- **해시 검증**: 암호화 외에도 프레임워크는 MD5, SHA1, MurmurHash3, XxHash, HMACSha256 등 해시 도구를 제공합니다. [Runtime/Utility/Utility.Hash.Md5.cs](/Runtime/Utility/Utility.Hash.Md5.cs) 등 참고.
- **DSA 서명 및 검증**: [Runtime/Utility/Utility.Encryption.Dsa.cs](/Runtime/Utility/Utility.Encryption.Dsa.cs) 참고.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `AESEncrypt` 컴파일 경고에서 사용 중단 알림 | 해당 메서드는 하드코딩된 IV/Salt를 사용함 | `AESEncryptSecure` / `AESDecryptSecure`로 변경 |
| `Utility.Compression.Compress`가 빈 값을 반환하거나 예외를 던짐 | `SetCompressionHelper`를 호출하여 구현체를 등록하지 않음 | 시작 시 `ICompressionHelper` 구현체를 주입 |
| `You must set screen DPI first.` | `Utility.Converter.ScreenDpi`가 설정되지 않았거나 0으로 설정됨 | 시작 시 장치 DPI에 맞춰 한 번 값을 할당 |
| XOR 암호화 후 길이가 맞지 않음 | `GetQuickXorBytes`는 앞쪽 220 바이트만 처리함 | `GetXorBytes`로 전체 구간을 처리하거나, 비즈니스 데이터 길이를 확인 |

## 배경 (선택)

`Utility`는 `partial class`이며, 서로 다른 책임을 `partial`을 통해 여러 파일로 분리합니다. 예를 들어 `Utility.Encryption.cs`, `Utility.Encryption.Aes.cs`, `Utility.Encryption.Rsa.cs`, `Utility.Encryption.Dsa.cs`가 있으며, `[Preserve]`로 표시하여 IL2CPP/AOT 가지치기를 방지합니다. 압축에 Helper 주입 방식을 채택한 이유는 상위 계층에서 zlib / LZ4 / 자체 알고리즘을 자유롭게 선택할 수 있도록 하기 위해서입니다.
