# 일반 문제

이 문서는 CoroutineComponent 코루틴 컴포넌트 사용 시 발생하는 일반적인 문제와 해결책을 수집합니다.

## 개요

CoroutineComponent는 GameFrameX 프레임워크의 코루틴 관리 컴포넌트로, Unity 내장 코루틴 기능을 확장하여 더 나은 코루틴 라이프사이클 관리 및 메모리 안전 제어를 제공합니다. 이 컴포넌트는 `ConcurrentDictionary` 스레드 안전 사전을 사용하여 실행 중인 모든 코루틴을 추적하여，随时管理和停止코루틴을 보장합니다.

> 상세한 사용 설명은 [사용 가이드](./3.getting-started.index) 및 [API 참고](./4.coroutine-component)를 참고하세요.

## 일반적인 문제 목록

### Q1: 동일한 GameObject에서 여러 개의 CoroutineComponent를 추가할 수 없는 이유는 무엇입니까?

**문제 설명:**
동일한 GameObject에서 두 번째 CoroutineComponent를 추가하려고 하면 Unity 편집기에서 오류가 발생하거나 추가할 수 없습니다.

**원인:**
CoroutineComponent는 `[DisallowMultipleComponent]` 속성을 사용하며, 이 속성은 동일한 GameObject에 여러 개의 동일한 유형의 컴포넌트 추가를禁止합니다.

**해결책:**
- 각 GameObject에 CoroutineComponent 인스턴스가 하나만 있는지 확인합니다
- 여러 코루틴을 관리해야 하는 경우同一 CoroutineComponent 인스턴스에서 여러 코루틴을 시작합니다
- `StopAllCoroutines()` 메서드를 사용하여 모든 코루틴을 중지합니다

```csharp
// 올바른 사용법:同一 컴포넌트에서 여러 코루틴 관리
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();
coroutineComponent.StartCoroutine(CoroutineA());
coroutineComponent.StartCoroutine(CoroutineB());
coroutineComponent.StopAllCoroutines(); // 모든 코루틴 중지
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L10-L11)

### Q2: StartCoroutine에 null 열거자를 전달하면 어떻게 됩니까?

**문제 설명:**
`StartCoroutine` 메서드에 `null` 값의 IEnumerator를 전달하면 어떻게 됩니까?

**원인:**
`StartCoroutine`에 null 열거자를 전달하면 Unity底层에서空참조 예외가 발생합니다.

**해결책:**
- 코루틴을 시작하기 전 항상 열거자가 null인지 확인합니다
- null 값 보호 로직을 추가합니다

```csharp
IEnumerator myCoroutine = GetSomeCoroutine(); // null일 수 있음

if (myCoroutine != null)
{
    coroutineComponent.StartCoroutine(myCoroutine);
}
```

---

### Q3: 실행 중인 코루틴을 올바르게 중지하는 방법은 무엇입니까?

**문제 설명:**
`StopCoroutine`을 호출한 후 코루틴이 계속 실행되는 것 같거나 코루틴을 중지할 수 없습니다.

**원인:**
- 전달한 IEnumerator가 시작时的 열거자와同一 참조가 아님
- 코루틴이 이미 실행 완료됨
- StopCoroutine 호출 전 코루틴이 이미 종료됨

**해결책:**
- 코루틴 시작 시 반환된 IEnumerator 참조를 저장합니다
- `StopAllCoroutines()`를 사용하여 모든 코루틴을 중지합니다
- 코루틴 실행 중 적시에 중지하는지 확인합니다

```csharp
// 코루틴 참조 저장
IEnumerator myCoroutine = coroutineComponent.StartCoroutine(MyLongRunningTask());

// 적절한 타이밍에 중지
coroutineComponent.StopCoroutine(myCoroutine);

// 또는 모든 코루틴 중지
coroutineComponent.StopAllCoroutines();
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L32-L45)

### Q4: 컴포넌트가 마운트된 GameObject가 파괴되면 어떻게 됩니까?

**문제 설명:**
CoroutineComponent를 포함하는 GameObject가 파괴될 때 실행 중인 코루틴은 어떻게 됩니까?

**원인:**
GameObject가 파괴될 때 Unity는 해당 GameObject의 모든 코루틴을 자동으로 중지합니다. CoroutineComponent는 MonoBehaviour를 상속하므로 이 동작도従칩니다.

**권장 사항:**
- Scene 전환 또는 객체 파괴 전 `StopAllCoroutines()`를 호출하여 코루틴이 깨끗하게 중지되도록确保합니다
- OnDestroy 수명 주기 후크를 사용하여 정리 작업을 수행합니다

```csharp
private void OnDestroy()
{
    // 객체 파괴 전 모든 코루틴이 중지되었는지 확인
    if (coroutineComponent != null)
    {
        coroutineComponent.StopAllCoroutines();
    }
}
```

### Q5: WaitForEndOfFrameFinish에 null 콜백을 전달하면崩溃합니까?

**문제 설명:**
`WaitForEndOfFrameFinish` 메서드에 null 콜백을 전달하면 어떻게 됩니까?

**원인:**
CoroutineComponent는 null 병합 연산자 `callback?.Invoke()`를 사용하므로, null 콜백을 전달해도崩溃하지 않으며 호출이 안전하게 무시됩니다.

**소스 코드 검증:**
```csharp
public void WaitForEndOfFrameFinish(System.Action callback)
{
    StartCoroutine(_WaitForEndOfFrameFinish(callback));
}

private IEnumerator _WaitForEndOfFrameFinish(System.Action callback)
{
    yield return _waitForEndOfFrame;
    callback?.Invoke(); // ?. 연산자로 안전하게 호출
}
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L97)

### Q6: 프레임 렌더링 완료 후 로직을 실행하려면 어떻게 합니까?

**문제 설명:**
Unity 매 프레임 렌더링 완료 후 특정 작업을 실행해야 합니다. 어떻게 사용해야 합니까?

**해결책:**
`WaitForEndOfFrameFinish` 메서드를 사용하면 현재 프레임의 렌더링 완료 후 콜백을 실행합니다.

```csharp
coroutineComponent.WaitForEndOfFrameFinish(() =>
{
    // 이 콜백은 프레임 렌더링 완료 후 실행됨
    Debug.Log("프레임 렌더링 종료, 로직 실행");
});
```

**적용 시나리오:**
- UI 렌더링 후 스크린샷 캡처
- 물리 계산 완료 후 특정 작업 실행
- 프레임末尾에서 상태 동기화 필요

### Q7: CoroutineComponent는 스레드 안전합니까?

**문제 설명:**
CoroutineComponent는 다중 스레드 환경에서 사용할 수 있습니까?

**원인:**
예, CoroutineComponent는 `ConcurrentDictionary<IEnumerator, UnityEngine.Coroutine>`를 사용하여 코루틴 매핑을 저장하며, 이 데이터 구조는 스레드 안전합니다.

**주의 사항:**
- 내부 저장은 스레드 안전하지만 코루틴 자체는 Unity主 스레드에서 실행됩니다
- 다중 스레드 접근 시 주로 고려해야 할 것은 IEnumerator 참조의 정확한 전달입니다

### Q8: 코루틴이 올바르게 중지되지 않아 메모리 누수가 발생하면 어떻게 처리합니까?

**문제 설명:**
코루틴이 올바르게 중지되지 않으면 메모리 누수가 발생할 수 있습니다. 어떻게 예방합니까?

**원인:**
코루틴을 올바르게 중지하지 않으면, 특히无限 루프 또는 장시간 대기 코루틴이 있으면 메모리 누수가 발생할 수 있습니다. CoroutineComponent는 코루틴 매핑 테이블을 유지하여 이 문제를 관리하는 데 도움을 줍니다.

**해결책:**
- `StopAllCoroutines()`를 사용하여 모든 코루틴 정리
- 컴포넌트 파괴 시 `StopAllCoroutines()` 호출确保
- 명확한 종료 조건이 있는 코루틴 사용

```csharp
private void OnDestroy()
{
    // 중요: 모든 코루틴 중지하여 메모리 누수 방지
    StopAllCoroutines();
}
```

### Q10: CoroutineComponent를 GameObject에 수동으로 추가해야 합니까?

**문제 설명:**
컴포넌트가 Scene에 자동으로 추가되지 않는 이유는 무엇입니까?

**원인:**
CoroutineComponent는 `Awake` 메서드에서 `IsAutoRegister = false`를 설정하여, 컴포넌트가 프레임워크의 자동 등록 시스템에 등록되지 않음을 나타냅니다.

**해결책:**
수동으로 CoroutineComponent를 GameObject에 추가해야 합니다:

```csharp
// 수동으로 컴포넌트 추가
CoroutineComponent coroutineComponent = gameObject.AddComponent<CoroutineComponent>();

// 또는 Unity 편집기에서 수동으로 추가
// 1. GameObject 선택
// 2. Add Component 클릭
// 3. "Game Framework/Coroutine" 검색
```
> Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L99-L103)

### Q11: Unity 편집기에서 CoroutineComponent를 찾는 방법은 무엇입니까?

**문제 설명:**
Unity 편집기에서 CoroutineComponent를 추가하는 방법은 무엇입니까?

**해결책:**
컴포넌트는 `[AddComponentMenu("Game Framework/Coroutine")]` 속성을 사용하므로 다음 방법으로 추가할 수 있습니다:

1. Unity 편집기에서 GameObject 선택
2. Inspector 패널 우클릭 → Add Component
3. 검색창에 "Coroutine" 또는 "Game Framework/Coroutine" 입력
4. CoroutineComponent 선택

CoroutineComponent는 어떤 GameFrameX 컴포넌트나 패키지에 의존합니까?

## 진단 단계

해결할 수 없는 문제가 발생하면 다음 단계로 진단을 수행하세요:

1. **GameObject 상태 확인**: GameObject와 컴포넌트가 활성화되어 있는지 확인
2. **코루틴 참조 확인**: 코루틴 중지에 사용되는 IEnumerator 참조가 정확한지 확인
3. **Unity 콘솔 확인**: 오류 또는 경고 정보가 있는지 확인
4. **StopAllCoroutines 사용**: 디버깅 수단으로 먼저 모든 코루틴을 중지하여 문제 파악
5. **Scene 전환 확인**: Scene 전환 시 코루틴이 올바르게 정리되었는지 확인
