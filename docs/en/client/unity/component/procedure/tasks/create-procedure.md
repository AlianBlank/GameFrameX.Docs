# How to Write a Procedure

This chapter explains how to write a custom Procedure and integrate it with `ProcedureComponent` so that the framework automatically enters that procedure after startup. Each Procedure inherits from `ProcedureBase` and is scheduled to run by `ProcedureManager` through a finite state machine (FSM).

## Prerequisites

- The `com.gameframex.unity.procedure` package is installed, and a `ProcedureComponent` exists in the scene (attached to the `GameFramework` startup object, with `[GameFrameXAutoComponent(-1000)]` for auto-registration).
- The `GameFrameX.Procedure.Runtime` and `GameFrameX.Fsm.Runtime` namespaces are imported.
- At least one concrete type inheriting from `ProcedureBase` is available; the framework uses `Activator.CreateInstance` reflection to create instances, so procedure classes must have a parameterless (or omittable) constructor.

## Steps

### 1. Create the Procedure Class and Inherit from ProcedureBase

`ProcedureBase` itself inherits from `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`, exposing six lifecycle callbacks: `OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy`. The default implementations are all empty and can be overridden as needed.

Source: [ProcedureBase.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureBase.cs#L30-L98)

Minimal working example (refer to the actual usage in the unit tests):

```csharp
using GameFrameX.Fsm.Runtime;
using GameFrameX.Procedure.Runtime;

internal class ProcedurePreload : ProcedureBase { }

internal class ProcedureLogin : ProcedureBase { }

internal class ProcedureMain : ProcedureBase
{
    protected override void OnInit(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnInit(procedureOwner);
        // Initialize resources, configurations, hot updates, etc.
    }

    protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnEnter(procedureOwner);
        // Enter main scene logic
    }

    protected override void OnDestroy(IFsm<IProcedureManager> procedureOwner)
    {
        base.OnDestroy(procedureOwner);
        // Release resources
    }
}
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L13-L40)

### 2. Register the Procedure in the Inspector

Select the object in the scene that has `ProcedureComponent` attached, and in the Inspector:

- `Available Procedure Type Names`: fill in the full type names of all available procedures (including the namespace), for example `GameFrameX.Procedure.ProcedurePreload`, `GameFrameX.Procedure.ProcedureLogin`, `GameFrameX.Procedure.ProcedureMain`.
- `Entrance Procedure Type Name`: fill in the full type name of the startup entry procedure, which must exactly match one of the items in the array above; otherwise the `Start()` coroutine will return directly due to `m_EntranceProcedure == null` and print `Entrance procedure is invalid.`.

`ProcedureComponent.Start()` will reflectively create procedure instances according to the above configuration, and call `ProcedureManager.Initialize(...)` and `StartProcedure(...)`.

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L51-L169)

### 3. Switch to the Next Procedure Within a Procedure

Within each procedure, you can obtain the belonging `IProcedureManager` through `procedureOwner`, and then call `procedureOwner.StartProcedure<T>()` (or `StartProcedure(typeof(T))`) to switch to the next state. For example, jump to `ProcedureMain` after login is complete in `ProcedureLogin`:

```csharp
protected override void OnEnter(IFsm<IProcedureManager> procedureOwner)
{
    base.OnEnter(procedureOwner);
    // ...login success logic...
    procedureOwner.StartProcedure<ProcedureMain>();
}
```

You can also access it through the component:

```csharp
GameEntry.GetComponent<ProcedureComponent>().StartProcedure(typeof(ProcedureMain));
```

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L202-L240)

### 4. Take Over the Startup Procedure via StartupRunner (Optional)

If the project uses the new startup approach with `ApplicationStartupEntry` + `StartupRunner.Run`, you need to check `Use Startup Runner` to `true` on `ProcedureComponent`. In this case, `ProcedureComponent` only registers `IProcedureManager` in `Awake` and no longer calls `Initialize` and `StartProcedure`. StartupRunner is responsible for assembling the procedures and starting the entry procedure, avoiding duplicate `Initialize` reporting `Already exist FSM`.

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L55-L127)

## Common Variations

| Scenario | Approach |
|------|------|
| Don't use the component, only use the `ProcedureManager` API | Call `new ProcedureManager().Initialize(fsmManager, procs)`, then call `StartProcedure<T>()` |
| Need polling (`OnUpdate`) | Override `OnUpdate(IFsm<IProcedureManager>, float, float)` in the corresponding procedure class; the framework polls every frame |
| Need fixed-interval polling | Override `OnFixedUpdate(IFsm<IProcedureManager>, float, float)` |
| Cleanup before leaving a procedure | Override `OnLeave(IFsm<IProcedureManager>, bool isShutdown)`, and distinguish between normal switching and state machine shutdown based on `isShutdown` |
| Check/get registered procedure instance | Use `HasProcedure<T>()` / `GetProcedure<T>()` |

Source: [ProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureManager.cs#L41-L273)

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `You must initialize procedure first.` | Accessed `CurrentProcedure` / `StartProcedure` / `HasProcedure` / `GetProcedure` before calling `Initialize` | Call `ProcedureManager.Initialize(fsmManager, procedures)` first, then access the above APIs |
| `ArgumentNullException` (parameter is `fsmManager`) | `null` was passed to `Initialize` | Pass a valid `IFsmManager` (e.g., `GameFrameworkEntry.GetModule<IFsmManager>()`) |
| `Procedures is invalid.` | The `procedures` array is empty | Pass at least one procedure instance |
| `Entrance procedure is invalid.` | `Entrance Procedure Type Name` doesn't match any item in `Available Procedure Type Names` | Make sure the entry type's full name strictly equals one of the items in the array |
| `Can not find procedure type '{0}'.` | The full type name is misspelled, or the corresponding assembly is not loaded | Check the namespace and assembly references |
| `Already exist FSM` | Both the `ProcedureComponent` and `StartupRunner` startup procedures are enabled simultaneously | Set `ProcedureComponent`'s `Use Startup Runner` to `true`, or don't let StartupRunner call `Initialize` again |

## Background (Optional)

`ProcedureBase` is a thin wrapper around `GameFrameX.Fsm.Runtime.FsmState<IProcedureManager>`, and `ProcedureManager` internally holds these states in the form of `IFsm<IProcedureManager>`. By default, `ProcedureComponent` reflectively creates procedure instances in the `Start()` coroutine, calls `Initialize`, and then jumps to the entry procedure; when `Use Startup Runner` is `true`, it only registers `IProcedureManager`, and `ApplicationStartupEntry` takes over the initialization and startup, which is suitable for hot-update and resource sub-packaging scenarios.
