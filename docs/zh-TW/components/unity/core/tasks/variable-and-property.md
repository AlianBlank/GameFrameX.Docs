# 使用變數與可綁定屬性做資料驅動

在 GameFrameX 中,`Variable<T>` 是帶引用計數的強型別資料容器(用於跨子系統傳遞弱型別值),`BindableProperty<T>` 是帶值變更回呼的響應式屬性(用於 UI 與邏輯的資料綁定)。本頁示範兩者在資料驅動場景中的典型用法。

## 前置條件

- 已引入 `GameFrameX.Runtime` 命名空間。
- 已了解 GameFrameX 的引用池 / `IReference` 概念(僅 `Variable<T>` 需要)。

## 操作步驟

### 1. 用 `Variable<T>` 承載跨模組資料

繼承 `Variable<T>` 實作一個具體類型,即可在事件、參數表中以弱型別 `object` 傳遞,又能在拿到實例時強型別取值。

```csharp
using GameFrameX.Runtime;

public class IntVariable : Variable<int>
{
    public IntVariable() { }
    public IntVariable(int value) { SetValue(value); }
}
```

使用方式:

```csharp
var v = ReferencePool.Acquire<IntVariable>();
v.SetValue(42);
int actual = v.Value;                // 強型別取值
object boxed = v.GetValue();         // 弱型別裝箱(用於事件參數)
ReferencePool.Release(v);            // 歸還引用池,會回呼 Clear()
```

設定型別不相符時,`SetValue(object)` 會擲出 `GameFrameworkException`,訊息原文為:

```
Cannot set value of type '{0}' to variable of type '{1}'.
```

> 關於引用池與 `IReference` 的整體工作流程,見《IReference 與引用池》。

### 2. 用 `BindableProperty<T>` 做值變更通知

`BindableProperty<T>` 在賦值時若新舊值不相等,會自動呼叫已註冊的回呼,常用於驅動 UI 刷新。

```csharp
using System;
using GameFrameX.Runtime;

public sealed class PlayerStats
{
    public readonly BindableProperty<int> Hp = new BindableProperty<int>(100);
    public readonly BindableProperty<string> Name = new BindableProperty<string>("Hero");
}
```

訂閱與反訂閱:

```csharp
var stats = new PlayerStats();

Action<int> onHp = newHp => Debug.Log($"HP -> {newHp}");
stats.Hp.Add(onHp);                       // 註冊回呼
stats.Hp.Value = 80;                       // 觸發回呼,日誌輸出 "HP -> 80"
stats.Hp.Value = 80;                       // 相等值不會觸發
stats.Hp.Remove(onHp);                     // 移除回呼
stats.Hp.Clear();                          // 清空所有回呼
```

### 3. 需要立即拿到當前值時使用 `RegisterWithInitValue`

若訂閱時希望回呼立即被呼叫一次(傳入當前值),使用 `RegisterWithInitValue`:

```csharp
stats.Hp.RegisterWithInitValue(newHp => UpdateHpBar(newHp));
```

## 常見變體

| 場景 | 選型 | 關鍵 API |
|------|------|----------|
| 事件 / 任務的弱型別參數 | `Variable<T>` 子類別 | `SetValue(object)` / `GetValue()` |
| UI 綁定 / 多觀察者同步 | `BindableProperty<T>` | `Add` / `Remove` / `RegisterWithInitValue` |
| 想避免重複觸發 | `BindableProperty<T>` | 內部已用 `Equals` 比較,同值不觸發 |
| 想池化複用變數 | `Variable<T>` | `ReferencePool.Acquire / Release` |

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| `Cannot set value of type 'X' to variable of type 'Y'.` | 給 `Variable<T>` 的 `SetValue(object)` 傳入非 `T` 型別 | 在呼叫點做型別轉換,或改用匹配的子類別 |
| 賦值後回呼沒執行 | 新值與舊值相等,`BindableProperty` 內部 `Equals` 比較後跳過 | 這是預期行為;若需要強制通知,改用 `Equals` 回傳 false 的新實例 |
| `Add(null)` 擲例外 | `BindableProperty.Add` 用 `GameFrameworkGuard.NotNull` 校驗 | 傳入具體 `Action<T>` 方法或 lambda |
| 歸還引用池後回呼仍觸發 | `Variable<T>` 已被池回收但外部仍持有引用 | 在持有者自身 `Clear()` 或釋放時同步清空引用 |

## 背景(選用)

- `Variable` 實作 `IReference`,支援透過 `ReferencePool` 取得 / 釋放,`Clear()` 會把值重置為 `default(T)`,適合在事件、任務參數這種「用完即棄」的場景裡減少 GC。
- `BindableProperty<T>` 內部用 `Equals` 比較新舊值,只有真正變化時才回呼;`Add` 支援鏈式回傳自身,`Remove` 必須傳入同一個委派引用才能正確解綁。
