# UI マネージャー(IUIManager)の動作原理

`IUIManager` は GameFrameX UI モジュール全体のエントリーポイントであり、UI グループ(`IUIGroup`)、UI インスタンスプール、ロード/クローズフロー、外部向けイベントを一元管理する役割を担います。本ページでは、その内部がどのように動作するか――UI フォームを開いてからリサイクルされるまでの呼び出しチェーン上で何が起こるか、そして各設定項目の意味について説明します。

## インターフェース一覧

`IUIManager` は [Runtime/UI/IUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIManager.cs) で定義されており、その主要メンバーは職責ごとに次のように分類されます。

| 分類 | メンバー | 役割 |
|------|------|------|
| インスタンスプール設定 | `InstanceAutoReleaseInterval`、`InstanceCapacity`、`InstanceExpireTime`、`RecycleInterval` | UI インスタンスオブジェクトプールの容量、有効期限、自動解放、リサイクルの間隔を制御 |
| アニメーション切替 | `IsEnableUIShowAnimation`、`IsEnableUIHideAnimation` | UI フォームの表示/非表示アニメーションを有効にするかどうか |
| グループ管理 | `AddUIGroup`、`HasUIGroup`、`GetUIGroup`、`GetAllUIGroups` | UI グループの追加/検索 |
| UI フォーム検索 | `HasUIForm`、`GetUIForm(s)`、`GetAllLoadedUIForms`、`IsLoadingUIForm`、`IsValidUIForm` | シリアル番号またはアセット名で UI フォームを検索 |
| オープン/クローズ | `OpenUIFormAsync`、`CloseUIForm`、`CloseAllLoadedUIForms`、`CloseAllLoadingUIForms` | 非同期オープン、クローズ、一括クローズ |
| イベント | `OpenUIFormSuccess`、`OpenUIFormFailure`、`CloseUIFormComplete` | 非同期操作完了時のコールバック |
| 依存性注入 | `SetObjectPoolManager`、`SetResourceManager`、`SetUIFormHelper` | 基盤となるオブジェクトプール、アセット、ヘルパーの注入 |

抽象基底クラス `BaseUIManager : GameFrameworkModule, IUIManager`（[Runtime/BaseUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L36-L39)）は、これらの状態を保持し、共通ロジックを実装します。

## 主要な内部フィールド

`BaseUIManager` は以下のフィールドで状態を追跡します（[BaseUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L48-L114)）：

| フィールド | 用途 |
|------|------|
| `m_UIFormsBeingLoaded` | ロード中の UI フォーム（シリアル番号 → アセットパス） |
| `m_UIFormsToReleaseOnLoad` | ロード完了後にすぐ解放する必要がある UI フォーム |
| `m_RecycleQueue` | リサイクル待ちの UI フォームキュー |
| `m_RecycleInterval`、`m_RecycleTime` | リサイクル間隔の制御（デフォルト 60 秒） |
| `m_Serial` | 自動増分のシリアル番号ジェネレーター |
| `m_AssetManager`、`m_ObjectPoolManager`、`m_UIFormHelper` | setter によって注入される依存関係 |

## UI フォームを開くフロー

`OpenUIFormAsync` のエントリポイントは [Runtime/BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118) にあります。2 つのオーバーロードはどちらも最終的に内部の `InnerOpenUIFormAsync` に委譲されます：

```csharp
public Task<IUIForm> OpenUIFormAsync<T>(string uiFormAssetPath, bool pauseCoveredUIForm, object userData, bool isFullScreen = false) where T : class, IUIForm
{
    return InnerOpenUIFormAsync(uiFormAssetPath, typeof(T), pauseCoveredUIForm, userData, isFullScreen);
}

public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}
```

Source: [Runtime/BaseUIManager.Open.cs#L100-L118](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118)

オープン処理中、マネージャーは次の順序で動作します：

1. 自動増分の `serialId` を取得し、`{serialId, assetPath}` を `m_UIFormsBeingLoaded` に書き込みます。
2. `m_AssetManager` を通じて Prefab を非同期ロードし、ロード完了イベント内で `IUIForm` をインスタンス化します。
3. インスタンスを所属する `IUIGroup` に配置し、`pauseCoveredUIForm` に基づいて、対象グループ内でカバーされた UI フォームの `OnCover`/`OnReveal` を発火するかどうかを決定します。
4. `OpenUIFormSuccess` イベントを発火し、`IUIForm` を `Task` 経由で呼び出し元に返します。
5. どの段階で例外が発生しても `OpenUIFormFailure` が発火し、`m_UIFormsBeingLoaded` から該当エントリが削除されます。

## UI フォームを閉じるフロー

`CloseUIForm` は、シリアル番号・インスタンス・ジェネリック・`userData` 別のオーバーロードを提供しており、すべて [Runtime/BaseUIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs) で実装されています。フローの要点：

1. `IsValidUIForm` を検証し、有効であれば `IUIGroup` から取り除きます。
2. `IsEnableUIHideAnimation` に基づいて非表示アニメーションを再生するかどうかを決定します。
3. デフォルトではリサイクルキューに入り、遅延リサイクルされます。`isNowRecycle: true` を渡した場合は即座にオブジェクトプールへリサイクルされます。
4. リサイクル完了後に `CloseUIFormComplete` が発火します。

リサイクルキューの間隔は `RecycleInterval`（デフォルト 60 秒）で制御され、時間になると `m_ObjectPoolManager` 内の `m_InstancePool` へ一括でリサイクルされます。

## インスタンスオブジェクトプール

`m_InstancePool` は `IObjectPoolManager` 配下のオブジェクトプールであり、UI インスタンスの再利用可能なキャッシュに相当します。`InstanceCapacity`、`InstanceExpireTime`、`InstanceAutoReleaseInterval` の 3 つのプロパティは、このプールの対応するフィールドへ直接転送されます（[BaseUIManager.cs#L122-L182](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L122-L182)）。

| プロパティ | 転送先 |
|------|---------|
| `InstanceAutoReleaseInterval` | `m_InstancePool.AutoReleaseInterval` |
| `InstanceCapacity` | `m_InstancePool.Capacity` |
| `InstanceExpireTime` | `m_InstancePool.ExpireTime` |

意味：プールが満杯になると、有効期限に基づいて最も長く使用されていないインスタンスが削除され、Prefab の頻繁なインスタンス化を回避できます。

## イベントコールバック

3 つのイベントは [BaseUIManager.Open.cs#L42-L68](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L42-L68) で明示的な `add`/`remove` によって管理されており、IL2CPP 環境下でも保持されやすくなっています：

- `OpenUIFormSuccess(OpenUIFormSuccessEventArgs)` — ロードと初期化が成功した後に発火します。
- `OpenUIFormFailure(OpenUIFormFailureEventArgs)` — アセットのロード失敗、型の不一致、ヘルパー未注入などの状況で発火します。
- `CloseUIFormComplete(CloseUIFormCompleteEventArgs)` — クローズフロー（アニメーション、リサイクル）がすべて完了した時に発火します。

## 依存性注入の順序

`BaseUIManager` は自身で `IAssetManager`、`IObjectPoolManager`、`IUIFormHelper` を作成せず、呼び出し元が `Open/Close` を呼び出す前に対応する setter を通じて注入する必要があります。この 3 つは `OpenUIFormAsync` のパス上で準備完了していなければならず、そうでない場合 `OpenUIFormFailure` が即座に発火します。
