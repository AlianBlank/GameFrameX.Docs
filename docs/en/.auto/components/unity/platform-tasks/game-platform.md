# Switch Game Platform (TapTap, etc.)

Through the editor menu, switch the WebGL mini-game platform adaptation macros (such as TapTap, Huawei, OPPO, Vivo, Xiaomi, DouYin, WeChat, Alipay, Bilibili, Baidu, JingDong, Taobao, Meituan, Discord, YouTube, Facebook, GooglePlay, TikTok, CrazyGames, Poki, etc.) for the current project with one click. At runtime, determine the current platform through properties such as `ApplicationHelper.IsWebGLTapTapMiniGame`.

## Prerequisites

- The GameFrameX Unity package has been imported into the current project.
- The Build Target has been switched to `WebGL` (File → Build Settings → Switch Platform → WebGL).
- The editor menu item is only compiled under the WebGL platform; it will not be displayed on other platforms.

## Steps

1. In the top menu of the Unity editor, select **GameFrameX → Scripting Define Symbols → Game Platforms**.

2. In the secondary menu, select the target platform, for example **Enable TapTap Mini Game**.
   - Only one mini-game platform macro can be enabled at a time. Enabling a new platform will automatically disable the previously enabled platform macros.

3. Wait for the editor console to output logs similar to the following, indicating that the macro definition has been written to PlayerSettings:
   ```text
   TapTap mini-game macro definition [ENABLE_TAPTAP_MINI_GAME] has been enabled
   TapTap mini-game macro definition [TAPTAPMINIGAME] has been enabled
   ```

4. Determine the current platform at runtime as needed (using TapTap as an example):

```csharp
using GameFrameX.Runtime;

if (ApplicationHelper.IsWebGLTapTapMiniGame)
{
    // Currently running in the TapTap mini-game container, call the TapTap SDK for TapTap login/payment
}
else
{
    // Go with other platforms or WebGL default logic
}
```

5. Re-execute the WebGL Build. The JS resources in the output package can run inside the corresponding platform container.

## Common Variations

- **Disable multiple platform macros at the same time**: Expand the Disable section of the secondary menu and click Disable one by one, or manually delete the corresponding entries in Project Settings → Player → Other Settings → Scripting Define Symbols.
- **Get the current WebGL platform string at runtime**: Directly read `ApplicationHelper.WebGLPlatformName`. It will return `"TapTapMiniGame"`, `"HuaweiMiniGame"`, etc., based on the enabled macros. When no mini-game macro is enabled, it returns `"WebGL"`.
- **Directly modify macro definitions**: Open `Project Settings → Player → Other Settings → Scripting Define Symbols`, manually add or remove entries such as `ENABLE_TAPTAP_MINI_GAME` / `TAPTAPMINIGAME`. The effect is the same as using the menu.

## Common Errors

- **Menu item not visible**: Confirm that the Build Target is already WebGL; the menu is only compiled under `UNITY_WEBGL`.
- **Enabling two mini-game macros at the same time**: Do not manually stack `ENABLE_TAPTAP_MINI_GAME` and `ENABLE_WECHAT_MINI_GAME`. At runtime, `WebGLPlatformName` will only match the first `#elif` branch, and subsequent platform macros will be silently ignored. Always use the menu for mutually exclusive switching.
- **Platform detection is still false after packaging**: The WebGL build was not rebuilt after switching the macro; changes to macro definitions in PlayerSettings require rebuilding the package to be included in the WebGL output.
