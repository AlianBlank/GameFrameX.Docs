# State Lifecycle Hook Reference

This page documents all lifecycle callback methods provided by `FsmState<T>`, including their signatures, trigger timing, and typical use cases. All hooks are defined in `Runtime/Fsm/FsmState.cs` and default to empty methods — override them as needed.

## Hook Quick Reference

| Hook | Signature | Trigger Timing | Typical Use |
|------|------|----------|----------|
| `OnInit` | `protected internal virtual void OnInit(IFsm<T> fsm)` | Called once when the state is first added to the state machine | One-time resource preparation, data caching, event subscription |
| `OnEnter` | `protected internal virtual void OnEnter(IFsm<T> fsm)` | Called when entering this state | Play entry animation, reset timers, log records |
| `OnUpdate` | `protected internal virtual void OnUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | Called during state machine polling (every frame) | Check transition conditions, accumulate timing |
| `OnFixedUpdate` | `protected internal virtual void OnFixedUpdate(IFsm<T> fsm, float elapseSeconds, float realElapseSeconds)` | Called during state machine fixed polling | Physics-related logic |
| `OnLeave` | `protected internal virtual void OnLeave(IFsm<T> fsm, bool isShutdown)` | Called when leaving this state; `isShutdown` is `true` when shutting down | Clean up temporary state, restore global configuration |
| `OnDestroy` | `protected internal virtual void OnDestroy(IFsm<T> fsm)` | Called when the state is removed from the state machine or the state machine is destroyed | Release resources held in `OnInit` |

## Trigger Order

The call sequence during a normal transition is: `OnLeave(oldState, false)` → `OnEnter(newState)`. `OnInit` is also triggered once when a state is first added. When the state machine is destroyed or a state is removed, the trigger order is `OnLeave(..., true)` → `OnDestroy`.

```csharp
// Source excerpt: typical state transition flow in Runtime/Fsm/Fsm.cs
m_CurrentState.OnLeave(this, false);   // Old state leaves
m_CurrentState = state;
m_CurrentState.OnEnter(this);          // New state enters
```

## Time Parameters

`OnUpdate` and `OnFixedUpdate` receive two time values:

| Parameter | Type | Meaning |
|------|------|------|
| `elapseSeconds` | `float` | Logical elapsed time (in seconds), affected by time scale |
| `realElapseSeconds` | `float` | Real elapsed time (in seconds), not affected by time scale |

Logic that needs to advance according to real time during pause/slow motion (for example, UI countdown) should use `realElapseSeconds`.

## Switching State

Inside a hook, you can request a switch to another state using the following methods:

```csharp
// Generic version: runtime type-safe
public void ChangeToState<TState>(IFsm<T> fsm) where TState : FsmState<T>

// Type version: stateType must inherit from FsmState<T>
protected void ChangeState(IFsm<T> fsm, Type stateType)
```

When calling `ChangeState`, if `fsm` is invalid it throws `GameFrameworkException("FSM is invalid.")`, if `stateType` is `null` it throws `"State type is invalid."`, and if the type doesn't match it throws `"State type '{0}' is invalid."`.

Source: [Runtime/Fsm/FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L116-L163)

## Minimal Example

```csharp
using GameFrameX.Fsm.Runtime;

public sealed class IdleState : FsmState<Player>
{
    protected internal override void OnEnter(IFsm<Player> fsm)
    {
        // Entering idle: play animation, reset timing
        fsm.SetData<float>("StateEnterTime", Time.time);
    }

    protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
    {
        // Check transition conditions
        if (fsm.Owner.MoveInput.sqrMagnitude > 0.01f)
        {
            ChangeToState<MoveState>(fsm);
        }
    }

    protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
    {
        // Only clean up during normal transitions; don't reset global data when shutting down
        if (!isShutdown)
        {
            fsm.RemoveData("StateEnterTime");
        }
    }
}
```

## Restrictions Inside Hooks

All hooks are marked as `protected internal` and can only be overridden in derived classes or within the same assembly. Do not call `ChangeState` in `OnEnter` and immediately trigger other side effects — the state machine will synchronously execute `OnLeave`/`OnEnter` at the transition point, so be aware of side effects caused by the execution order.

For more details on how the state machine is driven (polling entry), see [Runtime/Fsm/FsmBase.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmBase.cs).
