# 安装与环境准备(含宏定义与依赖包)

本页介绍如何在 Unity 项目中安装 `com.gameframex.unity.web.protobuff` 包、添加必需的宏定义 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`,并确认其依赖包就位。完成本页步骤后,你就可以在场景中添加 Web ProtoBuff 组件并使用 `Post<T>` 发送 Protobuf HTTP 请求。

## 前置条件

- Unity `2019.4` 或更高版本(见 `package.json` 中的 `"unity": "2019.4"`)。

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/package.json#L1-L7)

本包会自动带上以下依赖,由 Unity Package Manager 解析安装,无需手动处理:

| 依赖包 | 版本 | 说明 |
|--------|------|------|
| `com.gameframex.unity` | 2.5.1 | GameFrameX 框架核心 |
| `com.gameframex.unity.web` | 1.4.0 | Web 层基础组件 |
| `com.gameframex.unity.network` | 2.6.10 | 网络层,提供 `MessageObject` / `IResponseMessage` |
| `com.gameframex.unity.google.protobuf` | 3.4.2 | Google Protobuf 运行时 |

Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/package.json#L22-L27)

## 操作步骤

1. **选择安装方式之一**(详见下文"安装方式"四选一)。
2. **添加宏定义**:打开 Unity 的 **Player Settings → Scripting Define Symbols**,添加:

   `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`

   该宏是本包所有公开 API 的编译开关,不加宏时 `Post<T>` 等成员不会参与编译。

   Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.md#L35-L39)

3. **添加组件到场景**:在场景对象上 **Add Component → GameFrameX / Web ProtoBuff**,即组件 `WebProtoBuffComponent`(组件菜单路径为 `GameFrameX/Web ProtoBuff`)。

4. **设置超时时间**:在 Inspector 中调整 `超时时间`(单位:秒)字段,该字段为序列化配置。

   ```csharp
   [SerializeField] [Tooltip("超时时间.单位：秒")]
   ```

   Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L57-L60)

5. **验证安装**:在任意脚本中写下以下代码并编译通过即说明安装成功:

   ```csharp
   using GameFrameX.Web.ProtoBuff.Runtime;

   // 发送请求并等待结果
   LoginResponse response = await WebComponent.Post<LoginResponse>(url, request);
   ```

   Source: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.md#L106-L113)

### 安装方式(四选一)

- **方式 A — Scoped Registry(推荐)**:编辑项目 `Packages/manifest.json`,加入 `scopedRegistries` 与依赖:

  ```json
  {
    "scopedRegistries": [
      {
        "name": "GameFrameX",
        "url": "https://gameframex.upm.alianblank.uk",
        "scopes": [
          "com.gameframex"
        ]
      }
    ],
    "dependencies": {
      "com.gameframex.unity.web.protobuff": "1.1.5"
    }
  }
  ```

  `scopes` 控制哪些包从这个 registry 解析:只有包名以 `com.gameframex` 开头的包才会从该源获取。

- **方式 B — manifest.json 直接引用 Git 仓库**:

  ```json
  {
    "dependencies": {
      "com.gameframex.unity.web.protobuff": "https://github.com/gameframex/com.gameframex.unity.web.protobuff.git"
    }
  }
  ```

- **方式 C — Package Manager 添加 Git URL**:Unity 菜单 **Window → Package Manager → + → Add package from git URL**,输入:

  `https://github.com/gameframex/com.gameframex.unity.web.protobuff.git`

- **方式 D — 直接克隆到 Packages 目录**:将仓库克隆到项目 `Packages/` 目录下,Unity 会自动加载。

Sources: [README.md](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/README.md#L43-L74)、[package.json](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/package.json#L6-L6)

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 编译报错找不到 `Post<T>` / 组件 API 不可见 | 未添加宏 `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` | 在 **Player Settings → Scripting Define Symbols** 添加该宏后重新编译 |
| `WebProtoBuffComponent` 上提示缺少组件 | 组件通过 `RequireComponent` 强制依赖 `GameFrameXWebProtoBuffCroppingHelper`,依赖包未正确安装 | 确认 GameFrameX 相关依赖包(见前置条件表格)已由 UPM 正确解析 |
| Package Manager 拉不到包 / 版本不是最新 | scoped registry 未配置或版本号写死在旧值 | 检查 `scopedRegistries` 的 `url` 与 `scopes`(`com.gameframex`),并核对版本号;当前 `package.json` 版本为 `1.1.5` |

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L46-L50)

## 背景

本包扩展 GameFrameX Web 层以支持二进制 Protobuf 消息:序列化 `MessageObject` 实例发出 HTTP POST 请求,并通过条件编译(`ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`)反序列化为类型化的 `IResponseMessage` 响应,这就是宏必须手动添加的原因。组件 `WebProtoBuffComponent` 是 Unity 组件外壳,实际请求逻辑委托给管理器 `WebProtoBuffManager`(实现在 `WebProtoBuffManager.ProtoBuf.cs`)。关于发送请求的完整用法,见对应任务页。
