# 起動時に "Web manager is invalid." の Fatal ログが出力される場合の対処方法

この Fatal ログは `WebProtoBuffComponent.Awake()` から出力されます。`GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` が `null` を返した際に出力され、Web ProtoBuff マネージャーモジュールが正常に取得できなかった（未登録、または実装型がストリッピングされた）ことを示します。コンポーネントは直ちに `return` するため、以降のすべての Web リクエスト呼び出しが無効になります。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| 起動直後に `Web manager is invalid.` が出力され、その後 `Post` などのインターフェースを呼び出すと `NullReferenceException` がスローされる | `GameFrameworkEntry.GetModule<IWebProtoBuffManager>()` が `null` を返す。マネージャー実装がフレームワークエントリに登録されていない | 下記の修正手順 1 を参照 |
| ビルド版（実機／ストリッピング後）でのみこのログが出力され、エディターでは正常 | マネージドコードのストリッピングによって `WebProtoBuffManager` 実装クラスが削除された | 下記の修正手順 2 を参照 |
| オブジェクト上の `GameFrameXWebProtoBuffCroppingHelper` を手動で削除した | この Helper は `typeof` でマネージャー型を参照しており、リンカーによるストリッピングを防ぐために使用される | 下記の修正手順 3 を参照 |
| `Post<T>` を呼び出すとメソッドが存在しないと表示される | `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` マクロが有効化されていない（このマクロは `Post<T>` にのみ影響し、Fatal ログ自体には無関係） | 下記の修正手順 4 を参照 |

## 修正手順

ログの判定コードは以下の通りです。切り分けの際の参考にしてください：

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IWebProtoBuffManager);
    base.Awake();
    m_WebProtoBuffManager = GameFrameworkEntry.GetModule<IWebProtoBuffManager>();
    if (m_WebProtoBuffManager == null)
    {
        Log.Fatal("Web manager is invalid.");
        return;
    }

    m_WebProtoBuffManager.Timeout = m_Timeout;
}
```

ソース: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L77-L90)

1. **マネージャー実装クラスが到達可能であることを確認する**。`WebProtoBuffManager`（`Runtime/Web/WebProtoBuffManager.cs` にあり、名前空間は `GameFrameX.Web.ProtoBuff.Runtime`）は `IWebProtoBuffManager` の実装であり、`GetModule` は `GameFrameworkEntry` が含まれる GameFrameX ランタイム基礎パッケージに依存して登録を完了します。プロジェクトに GameFrameX 基礎ランタイムパッケージが正しくインストールされていること、および本パッケージのアセンブリのコンパイルにエラーがないこと（Console に赤色のコンパイルエラーが出ていないこと）を確認してください。
2. **マネージドストリッピングのレベルを下げる／無効化する**。Unity の `Player Settings → Managed Stripping Level` でストリッピングレベルを下げるか、本パッケージのアセンブリに保持ルールを設定し、`WebProtoBuffManager` がストリッピングされないようにしてください。
3. **ストリッピング防止 Helper を保持する**。`WebProtoBuffComponent` は `[RequireComponent(typeof(GameFrameXWebProtoBuffCroppingHelper))]` によってこの Helper への依存を強制しており、この Helper は本パッケージのすべての主要型への参照を保持しています：

```csharp
[Preserve]
public class GameFrameXWebProtoBuffCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(WebProtoBuffComponent);
        _ = typeof(IWebProtoBuffManager);
        _ = typeof(WebProtoBuffManager);
    }
}
```

ソース: [GameFrameXWebProtoBuffCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameXWebProtoBuffCroppingHelper.cs#L6-L16)

   シーン内のオブジェクトにアタッチされている `GameFrameXWebProtoBuffCroppingHelper` コンポーネントを手動で削除しないでください。
4. **必要に応じてネットワークマクロを有効化する**。Protocol Buffer リクエストを使用する場合は、`Scripting Define Symbols` に `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` を追加してください。追加しない場合、`Post<T>` はコンポーネントにコンパイルされません（`WebProtoBuffComponent.cs` の 92 行目の `#if` 条件を参照）。

## 検証

- Play モードに再度入る（または再ビルドする）と、Console に `Web manager is invalid.` の Fatal ログが表示されなくなります。
- コンポーネントの Inspector で `Timeout`（デフォルト `5f` 秒）を変更すると正常に反映されます。これは `m_WebProtoBuffManager.Timeout` を直接読み書きしているためです。
- マクロを有効化すると、`WebProtoBuffComponent.Post<T>(url, message)` が正常に呼び出せるようになります。
