# 热更新未生效 / DLL 未加载怎么办

당신이 에디터나 실기기에서 GameFrameX를 시작할 때, 만약 핫리프레시 DLL이 로드되지 않거나, 핫리프레시 진입 메서드가 호출되지 않거나, 새 패키지를 빌드한 후에도 비즈니스 로직에 아무런 변화가 없다면, 이 페이지의 단계에 따라 문제를排查하면 됩니다.

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 控制台完全没有 `开始加载AOT DLL` / `开始加载程序集Hotfix` 日志 | 未启用 HybridCLR 宏,走了 `RunNative` 分支 | 在 Player Settings → Scripting Define Symbols 添加 `ENABLE_GAME_FRAME_X_HYBRID_CLR`,并去掉 `DISABLE_HYBRIDCLR` |
| 启动时编辑器走的是加载 `Unity.Hotfix` 程序集,但运行时 DLL 没生效 | 真机走的是 AOT + 热更 DLL 路径,`AOTGenericReferences.PatchedAOTAssemblyList` 为空 | 在 HybridCLR Settings → `AOT Generic References` 中勾选泛型引用,执行 `HybridCLR/Compile DLL` 重新生成 |
| 日志停在 `开始加载XXX.dll` 后抛异常,提示资源找不到 | DLL 没有打进 AB 包,或者没放到框架约定的目录 | 用 `HybridCLR/Build DLL` 与框架的构建管线出包,确认 `Utility.Asset.Path.GetCodePath` 返回的路径能命中 |
| 日志显示 `EntryType=>method` 为 null,程序集加载了但入口方法未执行 | `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` 与实际 DLL 不一致 | 通过 `StartupOptions` 显式传入正确名称,或修改 `HotfixHelper` 中默认值(默认 `Unity.Hotfix` / `Hotfix.HotfixLauncher` / `Main`) |
| 真机加载热更 DLL 之后仍然走旧逻辑 | 资源服务器返回了旧的 `AssetBundle` / 热更 DLL 文件 | 清理 CDN 缓存并强制重新拉取最新出包 |

## 修复步骤

### 1. 确认编译宏与入口名称

热更逻辑被 `ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR` 包住,只有满足这两个宏定义才会真正加载 AOT DLL 与热更 DLL。

[HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L5-L9) 中的关键代码:

```csharp
#if ENABLE_GAME_FRAME_X_HYBRID_CLR && !DISABLE_HYBRIDCLR
using System.Reflection;
using System.Linq;
using HybridCLR;
#endif
```

入口方法的默认值(不传 `StartupOptions` 时使用)定义在 [HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70):

```csharp
var assemblyName = options == null || string.IsNullOrEmpty(options.HotfixAssemblyName)
    ? "Unity.Hotfix"
    : options.HotfixAssemblyName;
var entryTypeName = options == null || string.IsNullOrEmpty(options.HotfixEntryTypeName)
    ? "Hotfix.HotfixLauncher"
    : options.HotfixEntryTypeName;
var entryMethodName = options == null || string.IsNullOrEmpty(options.HotfixEntryMethodName)
    ? "Main"
    : options.HotfixEntryMethodName;
```

请确认你的热更 DLL 的程序集名、入口类型、入口方法与这三个默认值完全匹配。

### 2. 确认编辑器与运行时走的分支

[HotfixHelper.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L72-L110) 中,编辑器会直接 `Run` 已加载的程序集,真机才走 AOT DLL + 热更 DLL 加载:

```csharp
if (ApplicationHelper.IsEditor)
{
    var assemblies = Utility.Assembly.GetAssemblies();
    foreach (var assembly in assemblies)
    {
        if (assembly.GetName().Name.Equals(assemblyName, StringComparison.OrdinalIgnoreCase))
        {
            Run(assembly, entryTypeName, entryMethodName);
            break;
        }
    }
    return;
}
```

也就是说:编辑器里“改代码立刻生效”是正常的;真机测试才能验证热更 DLL 是否真的被加载。

### 3. 确认 AOT 泛型引用已生成

真机分支会按 `AOTGenericReferences.PatchedAOTAssemblyList` 加载 AOT 元数据:

```csharp
var aotDlls = AOTGenericReferences.PatchedAOTAssemblyList.ToArray();
foreach (var aotDll in aotDlls)
{
    var assetHandle = await GameApp.Asset.LoadAssetAsync<UnityEngine.Object>(
        Utility.Asset.Path.GetAOTCodePath(aotDll));
    var aotBytes = assetHandle.GetAssetObject<UnityEngine.TextAsset>().bytes;
    RuntimeApi.LoadMetadataForAOTAssembly(aotBytes, HomologousImageMode.SuperSet);
}
```

如果列表为空,会跳过 AOT 元数据加载,后续 `Assembly.Load(hotfixDll)` 调用时就会因为缺失元数据失败。修复方法:在 HybridCLR 面板里点击 `Compile DLL` 让 `AOTGenericReferences.PatchedAOTAssemblyList` 重新生成。

### 4. 确认热更 DLL 资源能命中

热更 DLL 通过 `Utility.Asset.Path.GetCodePath` 拼接路径,然后用资源系统加载:

```csharp
var assetHotfixDllPath = Utility.Asset.Path.GetCodePath(assemblyName + Utility.Const.FileNameSuffix.DLL);
var assetHotfixDllOperationHandle = await GameApp.Asset.LoadAssetAsync<UnityEngine.Object>(assetHotfixDllPath);
var assemblyDataHotfixDll = assetHotfixDllOperationHandle.GetAssetObject<UnityEngine.TextAsset>().bytes;
var hotfixAssembly = Assembly.Load(assemblyDataHotfixDll, null);
```

如果路径对应的资源不在 AB 包里,加载会抛异常并被 `HotfixHelper.StartHotfixAsync` 捕获,以 `HotfixLaunchResult.Fail(e.Message)` 返回:

```csharp
catch (Exception e)
{
    Log.Error(e);
    return HotfixLaunchResult.Fail(e.Message);
}
```

修复方法:确认构建管线确实把 `Unity.Hotfix.dll` 与 AOT DLL 打进了对应的 AB,并清掉本地缓存/CDN 缓存。

### 5. 通过 `StartupOptions` 显式指定入口

当你修改了热更程序集名或入口类名时,通过 `StartupOptions` 显式传入,避免默认值不匹配:

```csharp
var options = new StartupOptions
{
    HotfixAssemblyName = "Unity.Hotfix",
    HotfixEntryTypeName = "Hotfix.HotfixLauncher",
    HotfixEntryMethodName = "Main",
};
await HotfixHelper.StartHotfixAsync(options);
```

应用层入口由 [ApplicationHotfixLauncher.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs#L22-L25) 适配到 `IHotfixLauncher`:

```csharp
public UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
{
    return HotfixHelper.StartHotfixAsync(options);
}
```

## 验证

1. 重新出包并清空本地 `AssetBundle` 缓存目录。
2. 启动游戏,观察日志依次出现 `开始加载AOT DLL`、`开始加载XXX.dll`、`加载程序集Hotfix 结束 Assembly ...`、`加载程序集Hotfix 结束 EntryType=>method`。
3. 修改 `Hotfix.HotfixLauncher.Main` 的逻辑后只重新打热更 DLL,真机上验证新逻辑生效即可。

## 背景(可选)

- 编辑器分支只跑 `Assembly.GetName().Name.Equals(...)` 匹配,因此只要项目里存在 `Unity.Hotfix` 程序集就一定会被加载。
- 真机分支依赖 `Utility.Asset.Path.GetCodePath` / `GetAOTCodePath` 的实现,这两个工具方法决定 DLL 的实际资源路径,具体配置见框架构建管线文档。
- 加载异常被 `try/catch` 吞掉并通过 `HotfixLaunchResult.Fail` 暴露给调用方,所以启动失败不会让进程崩溃,但也不会执行热更逻辑。
