# WebGL スタンドアロンまたはバックエンドなしシーンでリモートリクエストをスキップする方法

WebGL スタンドアロン版やビジネスバックエンドのないシーンでは、`StartupOptions.SkipRemoteStartupRequests` または `EPlayMode.OfflinePlayMode` を使用して、グローバル情報、App バージョン、リソースパッケージバージョンなどのリモートリクエストをスキップし、直接ローカルリソースの初期化に進むことで、起動がネットワーク待ちで止まったりエラーで失敗したりするのを回避できます。

## 前提条件

- `StartupOptions` アセットを作成済みであること(`Assets > Create > GameFrameX > Startup Options`)。
- リソースの実行モード(`GamePlayMode`)が `EditorSimulateMode` でないこと。そうでない場合、エディターではデフォルトでグローバル情報がスキップされます。
- `StartupOptions` アセットが起動フローに注入済みであること(`StartupRunner` / ブートストラップコンポーネントの `SetOptions`、またはデフォルトロードにより)。

## 操作手順

### 案 A:スキップスイッチのみを有効にする(WebGL スタンドアロン推奨)

Inspector で `StartupOptions` アセットを選択し、**Network** カテゴリを展開して、**Skip Remote Startup Requests** にチェックを入れます。

```csharp
// Runtime/Startup/StartupOptions.cs
[Tooltip("リモート起動リクエスト（グローバル情報、App バージョン、リソースパッケージバージョン）をスキップするかどうか。WebGL スタンドアロンなどバックエンドのないシーンで有効にすると、ローカルリソースの初期化に直接進みます。")]
public bool SkipRemoteStartupRequests = false;
```

出典: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31)

コード側でも実行時に切り替えられます:

```csharp
using GameFrameX.Startup.Runtime;

var options = Resources.Load<StartupOptions>("StartupOptions");
options.SkipRemoteStartupRequests = true;
```

起動フローは `ProcedureGetGlobalInfoState.OnEnter` でこのスイッチを読み取り、`true` の場合はリモートリクエストをスキップして、`ProcedurePatchInit` に直接進みます:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var options = StartupProcedureUtility.GetOptions(procedureOwner);
if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

出典: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L42-L48)

### 案 B:実行モードを Offline に切り替える

`StartupOptions.GamePlayMode` を `EPlayMode.OfflinePlayMode`(YooAsset のオフラインモード。ローカルにパッケージ済みのリソースを使用)に設定します。`ProcedureGetGlobalInfoState` は、スキップスイッチよりも先に OfflinePlayMode を判定します:

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

出典: [ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L35-L40)

Offline モードでは、後続の Patch フローも同様にショートサーキットされます: `ProcedurePatchInit`、`ProcedureUpdateManifest`、`ProcedureUpdateStaticVersion` はいずれも `OfflinePlayMode` に対して直接スキップ処理を行うため、リモートのマニフェストをリクエストしなくなります。

出典: [ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L36) · [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L42) · [ProcedureUpdateStaticVersion.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateStaticVersion.cs#L49)

## よくあるバリエーション

| シーン | 推奨される方法 | 主要スイッチ |
|------|----------|----------|
| WebGL スタンドアロン(YooAsset リソースはあるがバージョンサービスなし) | `SkipRemoteStartupRequests = true`、`GamePlayMode` はスタンドアロンモードのまま維持 | SkipRemoteStartupRequests |
| WebGL 完全オフライン(ローカルのビルド成果物) | `GamePlayMode = OfflinePlayMode` | GamePlayMode |
| エディター内でのバックエンドなしデバッグ | `GamePlayMode = EditorSimulateMode` | GamePlayMode |

3つのモードの `ProcedureGetGlobalInfoState.OnEnter` における判定順序は次のとおりです: EditorSimulateMode → OfflinePlayMode → `SkipRemoteStartupRequests` → 実際のリモートリクエスト。

## よくある間違い

- **Skip だけをチェックしたが GamePlayMode がまだオンラインモード**:スキップスイッチは「起動段階」のリモートリクエストのみをスキップします。Patch フローがリモート CDN を指しておりローカルマニフェストがない場合、`ProcedureUpdateManifest` / `ProcedureUpdateStaticVersion` の段階でネットワーク応答を待ち続けることになります。
- **Offline モードでローカルリソースを準備していない**:OfflinePlayMode は、YooAsset がすでに `StreamingAssets` にリソース一式を準備済みであることを前提とします。そうでない場合、後続のロードで「パッケージが見つからない」や「マニフェストが空」といったエラーが発生します。
- **SO を修正したのに反映されない**:`StartupOptions` への実行時の変更は、起動フローの開始前(コンポーネントの初期化前)に完了している必要があります。FSM 起動後に値を設定した場合は、シーンを再読み込みするか `StartupRunner.Restart()` を呼び出す必要があります。
- **WebGL のクロスオリジンポリシーが未設定**：スタンドアロン版であっても、WebGL では CORS に正しく対応する必要があります。「オプションの」リモート URL を1つ残す場合は、Web サーバーで `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` を設定するか、サーバー側プロキシを使用してください。

## 検証

ゲームを起動すると、Console に以下のログのいずれかが表示されるはずです(選択した案によります)。また、"Loading... (x/y)" のようなネットワーク待ちのメッセージは表示されないはずです:

- `Skip remote startup requests option enabled, skip remote startup requests.`
- `Offline play mode, skip remote startup requests.`
- `Editor simulate mode, skip global info request.`

その後、フローは直接ローカルリソースの初期化(UI リソースのオープン、ローカルマニフェストのロードなど)に進み、最終的にビジネスシーンへ遷移します。

## 背景(オプション)

起動フローはデフォルトで `ProcedureGetGlobalInfoState → ProcedureGetAppVersionInfoState → ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState → ProcedurePatchInit` の順に実行され、最初の3つのノードはいずれもリモートへ HTTP リクエストを送信します。WebGL スタンドアロンやデモシーンには利用可能なバックエンドがないことが多いため、最も早いノード(`ProcedureGetGlobalInfoState`)でまとめてインターセプトすることで、一連の無意味な失敗リトライを回避し、初回画面の表示時間を短縮できます。

起動フローの全体アーキテクチャについては、『Runtime/Procedures/Startup』ディレクトリ配下のフローのソースコードを参照してください。
