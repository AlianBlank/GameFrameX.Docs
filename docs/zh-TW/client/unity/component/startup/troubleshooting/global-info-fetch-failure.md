# 全域資訊介面取得失敗時的處理方法

啟動流程進入 `ProcedureGetGlobalInfoState` 後，若所有 `GlobalInfoUrls` 皆未能成功回傳設定（且沒有可用的本機快取），將觸發 `StartupFailedEventArgs`，並以 `ProcedureGetGlobalInfoState` 作為失敗流程名稱終止啟動。本文件說明常見原因、原因排查方式及對應的修正方法。

## 快速診斷

| 症狀 | 原因 | 修正 |
|------|------|------|
| 啟動時立即拋出 `ArgumentException`：`StartupOptions.GlobalInfoUrls must contain at least one URL.` | `StartupOptions.GlobalInfoUrls` 為 `null` 或空陣列 | 請參閱「修正步驟 1」 |
| 流程略過全域資訊請求並直接進入 `ProcedurePatchInit` | `SkipRemoteStartupRequests = true` 或 `GamePlayMode` 為 `EditorSimulateMode` / `OfflinePlayMode` | 請參閱「修正步驟 2」 |
| 失敗事件 `StartupFailedEventArgs` 中 `procedureName = "ProcedureGetGlobalInfoState"`，且 UI 停留在顯示 `Loading... (n/total)` | URL 容錯移轉(failover)全部失敗（網路/逾時/HTTP 錯誤/伺服器回傳非成功代碼） | 請參閱「修正步驟 3」 |
| 第一次嘗試失敗後啟動仍然成功，且 UI 顯示 `Using cached startup config...` | 先前成功的結果已透過 `StartupNetworkCacheUtility` 寫入快取，因此本次以後備(fallback)邏輯繼續 | 請參閱「修正步驟 4」 |
| WebGL/單機環境無法存取後端，導致啟動卡在網路步驟 | 不應啟用遠端啟動請求 | 請參閱「修正步驟 2」中 `SkipRemoteStartupRequests` 的用法 |

`procedureName`、`failedUrl`、`errorMessage` 三個欄位由 [`StartupProcedureUtility.CompleteFailure`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/StartupProcedureUtility.cs#L162-L167) 寫入 `StartupFailedEventArgs`，可用於精確定位原因。

## 修正步驟

### 修正步驟 1：設定了空的 `GlobalInfoUrls`

`StartupRunner.Run` 在進入 async 狀態機之前會同步進行驗證：

```csharp
// Runtime/Startup/StartupRunner.cs
if (options.GlobalInfoUrls == null || options.GlobalInfoUrls.Length == 0)
{
    throw new ArgumentException(
        "StartupOptions.GlobalInfoUrls must contain at least one URL.",
        nameof(StartupOptions.GlobalInfoUrls));
}
```

出處：[Runtime/Startup/StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L63-L68)

請在 `StartupOptions` 資產中輸入至少一個 URL：

```csharp
// Runtime/Startup/StartupOptions.cs
[Header("Network")] [Tooltip("전역 정보 인터페이스 URL 기본/보조 목록으로, 순서대로 시도합니다. 빈 배열은 구성 오류로 간주됩니다.")]
public string[] GlobalInfoUrls = new string[0];
```

出處：[Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L22-L23)

### 修正步驟 2：執行環境不應傳送遠端請求的情況

`ProcedureGetGlobalInfoState.OnEnter` 有三個提前返回的分支，只要其中之一成立，就會略過全域資訊介面：

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode)
{
    Debug.Log("Editor simulate mode, skip global info request.");
    ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
    return;
}

if (assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    Debug.Log("Offline play mode, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}

if (options != null && options.SkipRemoteStartupRequests)
{
    Debug.Log("Skip remote startup requests option enabled, skip remote startup requests.");
    ChangeState<ProcedurePatchInit>(procedureOwner);
    return;
}
```

出處：[Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L28-L48)

對應處理：

| 情境 | 應設定的值 | 備註 |
|------|--------|------|
| 編輯器模擬模式 | `GamePlayMode = EPlayMode.EditorSimulateMode` | 僅在編輯器中生效，非編輯器環境下 `StartupRunner.NormalizeAssetPlayMode` 會將其變更為 `HostPlayMode` |
| 離線模式 | `GamePlayMode = EPlayMode.OfflinePlayMode` | 直接進入 `ProcedurePatchInit`，不再嘗試遠端 |
| WebGL 單機/無後端 | `SkipRemoteStartupRequests = true` | 欄位說明請參閱 [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L30-L31) |

### 修正步驟 3：URL 容錯移轉全部失敗

`GetGlobalInfoAsync` 透過 [`UrlFailoverRunner.ExecuteAsync`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L67-L92) 依序嘗試 `GlobalInfoUrls`，每個 URL 內部最多嘗試 `MaxAttemptsPerUrl` 次，每次嘗試間隔為 `RetryDelayMs` 毫秒。只要發生一次 HTTP 例外或 `responseGlobalInfo.IsSuccess == false`，該次嘗試即視為失敗：

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
var json = await GameEntry.GetComponent<WebComponent>().PostToString(url, jsonParams);
var responseGlobalInfo = json.Result.ToHttpJsonResultData<ResponseGlobalInfo>();
if (!responseGlobalInfo.IsSuccess)
{
    return UrlAttemptResult.Fail("Global info server returned code " + responseGlobalInfo.Code);
}
```

出處：[Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L75-L84)

請依下列順序檢查：

1. 確認 `StartupOptions` 中已輸入至少一個可存取的 URL，並以「主要→備用」的順序排列。
2. 在瀏覽器/Postman 中使用相同的 `jsonParams`（由 `StartupProcedureUtility.CreateHttpParams` 產生）對該 URL 直接發送 `POST` 請求，確認伺服器是否回傳 `IsSuccess == true`。
3. 確認 `MaxAttemptsPerUrl`（預設值 3）與 `RetryDelayMs`（預設值 3000）是否過小，導致在弱網路環境下嘗試次數提前耗盡：

   ```csharp
   // Runtime/Startup/StartupOptions.cs
   public int MaxAttemptsPerUrl = 3;
   public int RetryDelayMs = 3000;
   ```
   出處：[Runtime/Startup/StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L26-L28)

4. 確認 `IStartupHttpParamsProvider` 中 `PackageName` / `Channel` / `SubChannel` 等通用參數能被伺服器正確識別。參數遺漏或錯誤也可能導致伺服器回傳非成功代碼。

### 修正步驟 4：啟用本機快取後備機制

當所有 URL 皆失敗時，`GetGlobalInfoAsync` 會嘗試讀取最後一次成功寫入的快取。若命中，即繼續啟動：

```csharp
// Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs
if (!result.Success)
{
    if (StartupNetworkCacheUtility.TryApplyCachedGlobalInfo())
    {
        uiHandler?.SetTipText("Using cached startup config...");
        ChangeState<ProcedureGetAppVersionInfoState>(procedureOwner);
        return;
    }

    StartupProcedureUtility.CompleteFailure(
        procedureOwner,
        nameof(ProcedureGetGlobalInfoState),
        result.FailedUrl,
        result.ErrorMessage);
    return;
}
```

出處：[Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Startup/ProcedureGetGlobalInfoState.cs#L94-L109)

- 快取鍵為 `GameFrameX.Startup.NetworkCache.GlobalInfo`，由 [`StartupNetworkCacheUtility`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupNetworkCacheUtility.cs#L23) 管理。
- 若希望在弱網路環境下仍能繼續啟動，請先在良好的網路環境中讓程式完整執行一次流程以寫入快取，之後保留後備邏輯即可。
- 若不想以快取繼續，而是希望「網路失敗時立即回報錯誤」，請在呼叫端收到 `StartupResult` 時明確判斷 `ProcedureName == "ProcedureGetGlobalInfoState"`，並引導使用者檢查網路。

## 驗證

1. 重新啟動應用程式，確認啟動流程不再因全域資訊介面失敗而中斷。
2. 啟動失敗時檢查 `StartupFailedEventArgs`：`procedureName` 應不再是 `ProcedureGetGlobalInfoState`，或啟動應透過 `Using cached startup config...` 路徑完成。
3. 在 `StartupOptions` 檢視器（[`StartupOptionsInspector`](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Editor/StartupOptionsInspector.cs#L24-L66) 提供可拖曳排序的 UI）中確認 `GlobalInfoUrls` 的順序正確且沒有空字串。
