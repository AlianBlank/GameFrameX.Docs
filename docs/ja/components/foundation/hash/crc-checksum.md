# CRC32/CRC64 を使用したデータ検証方法

`GameFrameX.Foundation.Hash.CrcHelper` は CRC32 と CRC64 の 2 種類の巡回冗長検査アルゴリズムを提供します。バイト配列、`Stream` ストリーム(同期および非同期)に対する直接的なチェックサム計算をサポートし、CRC32 整数をビッグエンディアン バイト配列に変換して保存や送信に使用できます。

## 前提条件

- 名前空間 `GameFrameX.Foundation.Hash` を参照し、クラス名は `CrcHelper`(静的パーティシャル クラス)。
- 対象フレームワーク: .NET Standard 2.x 以上、`Stream`、`Task`、`CancellationToken` をサポート。

## 操作手順

### 1. バイト配列の CRC32 を計算する

最もシンプルな呼び出しで、完全なバイト配列を渡すことで `int` 型の CRC32 チェックサム値を取得できます。

```csharp
using GameFrameX.Foundation.Hash;
using System.Text;

byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data);   // int を返す
```

Source: [CrcHelper.cs#L121-L126](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L121-L126)

### 2. バイト配列の指定範囲の CRC32 を計算する

`offset` と `length` を渡すことで、バイト配列のスライス部分のみに対して CRC32 を計算します。範囲外や負数は `ArgumentException` をスローします。

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data, offset: 2, length: 5);
```

Source: [CrcHelper.cs#L140-L152](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L140-L152)

### 3. ストリームの CRC32 を計算する(同期)

4 KB(`CachedBytesLength = 0x1000`)ごとにブロック読み取りして計算するため、大きなファイルの検証に適しています。

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = CrcHelper.GetCrc32(stream);
```

Source: [CrcHelper.cs#L163-L183](https://github.com/GameFrameX/GameFrameX/FFoundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L163-L183)

### 4. ストリームの CRC32 を非同期で計算する

非同期バージョンは `Stream.ReadAsync` を使用し、`CancellationToken` によるキャンセルをサポートします。

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = await CrcHelper.GetCrc32Async(stream, cancellationToken);
```

Source: [CrcHelper.cs#L188-L202](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L188-L202)

### 5. バイト配列 / ストリームの CRC64 を計算する

CRC64 には 3 つのパブリック オーバーロードがあります:`GetCrc64(byte[])`、`GetCrc64(Stream)`、`GetCrc64Async(Stream, CancellationToken)`。戻り値は `ulong` です。

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
ulong crc64 = CrcHelper.GetCrc64(data);                 // バイト配列

using var stream = File.OpenRead("big.bin");
ulong crc64FromStream = CrcHelper.GetCrc64(stream);    // 同期ストリーム

ulong crc64Async = await CrcHelper.GetCrc64Async(stream); // 非同期ストリーム
```

Source: [CrcHelper.cs#L66-L110](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L66-L110)

### 6. CRC32 整数をビッグエンディアン バイト配列に変換する

CRC32 の結果は保存する必要があることが多く、`GetCrc32Bytes` は 2 つの使用方法を提供します:

```csharp
int crc32 = CrcHelper.GetCrc32(data);

// 方法 1: 新しい 4 バイト配列を返す(ビッグエンディアン)
// ビッグエンディアン オーダーの 4 バイト配列
byte[] bytes = CrcHelper.GetCrc32Bytes(crc32);

// 方法 2: 既存配列の指定位置に書き込む
byte[] buffer = new byte[64];
CrcHelper.GetCrc32Bytes(crc32, buffer, offset: 0);
```

## よくあるバリエーション

- **CRC32 とバイトコードのループ XOR の組み合わせ**: `CrcHelper.GetCrc32(stream, code, length)` は internal オーバーロードで、まず `code` バイト配列をデータ ストリームにループ XOR してから CRC を計算します。キー付きの軽量検証シナリオに適しています。
- **異なるデータ長の一貫性**: CRC アルゴリズムは同じ入力に対して常に同じ結果を返すため、ネットワーク パケット検証、ファイル フィンガープリント、セーブ データの整合性検証に使用できます。
- **大きなファイルのストリーミング計算**: `Stream` オーバーロード(同期/非同期)により 4 KB 単位でブロック処理されるため、メモリ使用量が安定しています。

## よくあるエラー

| エラー現象 | 原因 | 修正方法 |
|----------|------|------|
| `ArgumentNullException`("bytes") | 渡された `byte[]` が null | 呼び出し前にチェックするか、`Array.Empty<byte>()` を使用する |
| `ArgumentException`(InvalidDataLength) | `GetCrc32(bytes, offset, length)` の `offset` が範囲外、または `length` が負 | `offset >= 0`、`length >= 0`、かつ `offset + length <= bytes.Length` を保証する |
| `ArgumentException`(InvalidDataLength) | `GetCrc32Bytes` の `offset` が範囲外、またはターゲット配列の残り容量が 4 バイト未満 | `offset >= 0`、かつ `offset + 4 <= bytes.Length` を保証する |
| `ArgumentNullException`("stream") | ストリームが null | ストリームが正常に開かれたか、ファイル パスが正しいかを検証する |
| 計算結果の一貫性がない | 文字列エンコードが不一致(UTF-8 / GBK / UTF-16) | 双方が同じ `Encoding` を使用する(例: 両方とも `Encoding.UTF8.GetBytes` を使用) |

## 背景(オプション)

CRC32 のデフォルト多項式は `0xedb88320`、シードは `0xffffffff`(IEEE 802.3 / zlib と同じ)で、CRC64 は内部的に `Crc64` クラスの `Append` + `GetCurrentHashAsUInt64` に委譲されます。チェックサム値は非暗号化の整合性チェックに適しており、HMAC などのキー付きの認証アルゴリズムの代わりにはなりません。
