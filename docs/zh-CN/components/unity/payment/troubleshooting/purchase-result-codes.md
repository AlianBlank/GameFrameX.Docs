# 购买失败与结果码速查

当购买回调 `OnPurchaseFailed`（或 `OnQueryPurchasesResult` / `OnConsumePurchaseResult`）触发时，`PaymentEventArgs.ResultCode` 会给出一个 `PaymentResultCode` 枚举值，用于定位失败原因。本页汇总全部结果码、对应处置建议，以及如何正确订阅回调拿到这些信息。

## 快速诊断

| 症状（ResultCode / 现象） | 原因 | 修复 |
|------|------|------|
| `Success` | 购买成功 | 在 `OnPurchaseSuccess` 中发货；一次性商品记得调用 `ConsumePurchase` |
| `Failed` | 渠道通用失败，详情看 `ErrorMessage` | 打印 `ErrorMessage` 与 `PurchaseData`，按渠道错误码排查 |
| `Cancelled` | 用户在支付界面主动取消 | 不要弹错误提示，静默处理即可 |
| `NetworkError` | 设备网络不可用 | 提示重试，等待网络恢复后重新 `Buy` |
| `ServiceUnavailable` | 渠道支付服务不可用（如商店未就绪） | 先 `IsReady()` 确认支付系统就绪，稍后重试 |
| `ItemAlreadyOwned` | 商品已拥有且未消耗（一次性商品重复购买） | `QueryPurchases` 查回 `PurchaseToken` 后执行 `ConsumePurchase`，再重新购买 |
| `ItemNotOwned` | 尚未拥有该商品就尝试消耗 | 先完成购买，勿对不存在的 `PurchaseToken` 调用 `ConsumePurchase` |
| `VerifyFailed` | 购买验证失败（与 `Init` 的 `isClientVerify` 相关） | 服务器验证方案下将 `isClientVerify` 设为 `false`；检查服务端验签逻辑 |
| `Unknown` | 渠道返回了未映射的结果 | 依赖 `ErrorMessage` 与 `PurchaseData`（原始 JSON）人工分析 |

结果码定义如下，共 9 个：

```csharp
public enum PaymentResultCode
{
    Success,
    Failed,
    Cancelled,
    NetworkError,
    ServiceUnavailable,
    ItemAlreadyOwned,
    ItemNotOwned,
    VerifyFailed,
    Unknown,
}
```

## 拿到完整错误信息

回调参数 `PaymentEventArgs` 携带以下字段，排查时全部打印：

| 字段 | 类型 | 说明 |

## 修复步骤

### 订阅购买失败回调

三个结果事件（`OnPurchaseSuccess` / `OnPurchaseFailed` / `OnQueryPurchasesResult` / `OnConsumePurchaseResult`）在 `IPaymentManager` 上声明，`PaymentComponent` 以事件包装器形式转发到内部的 `_paymentManager`：

```csharp
public event EventHandler<PaymentEventArgs> OnPurchaseFailed
{
    add { _paymentManager.OnPurchaseFailed += value; }
    remove { _paymentManager.OnPurchaseFailed -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L42-L46)

业务层订阅示例：

```csharp
using System;
using GameFrameX.Payment.Runtime;

paymentComponent.OnPurchaseFailed += OnPurchaseFailed;

private void OnPurchaseFailed(object sender, PaymentEventArgs e)
{
    UnityEngine.Debug.LogError(
        $"[Payment] 失败 ProductId={e.ProductId} ResultCode={e.ResultCode} " +
        $"ErrorMessage={e.ErrorMessage} PurchaseData={e.PurchaseData}");
}
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L19-L36)

### `ItemAlreadyOwned`：消耗后重试

一次性商品（`PaymentProductType` 的消耗型）发货后未消耗，下次购买会得到该结果码：

1. 调用 `QueryPurchases(PaymentProductType)` 查询购买记录；
2. 在 `OnQueryPurchasesResult` 回调中取出 `PurchaseToken`；
3. 调用 `ConsumePurchase(e.PurchaseToken)` 完成消耗；
4. 重新发起 `Buy(purchaseParams)`。

相关签名（定义于 `IPaymentManager`，由 `BasePaymentManager` 抽象实现）：

```csharp
void QueryPurchases(PaymentProductType productType);
void ConsumePurchase(string purchaseToken);
```

Sources: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L52-L63)

### `VerifyFailed`：检查验证模式

`Init` 的第二个参数决定验证方式：

```csharp
/// <param name="isClientVerify">是否执行客户端验证购买成功，如果是强联网验证。不需要开启，设置为false，进行服务器验证</param>
void Init(bool isDebug = false, bool isClientVerify = false);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L40-L43)

采用服务器验证时传 `false`，由服务端验签，避免客户端验证失败误报 `VerifyFailed`。

### `ServiceUnavailable`：确认就绪状态

购买前先调用 `bool IsReady()`；未就绪时渠道侧未初始化完成，会落入 `ServiceUnavailable`。另外 `SetPredefinedProductIds` 必须在初始化之前调用，否则预加载缓存不生效：

```csharp
void SetPredefinedProductIds(List<string> inAppProductIds, List<string> subsProductIds);
```

Source: [IPaymentManager.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/IPaymentManager.cs#L65-L70)

## 验证

- 触发一次取消购买（沙盒环境点取消），确认回调收到 `Cancelled` 且无异常日志；
- 对已拥有未消耗的商品再次购买，确认得到 `ItemAlreadyOwned`，执行 `ConsumePurchase` 后可正常复购；
- `OnPurchaseFailed` 中打印的 `ErrorMessage` / `PurchaseData` 内容完整，可与渠道后台对账。

## 背景

各渠道实现继承 `BasePaymentManager`，统一通过 `RaisePurchaseFailed` 等四个受保护方法触发结果事件，因此所有渠道回调的 `PaymentEventArgs` 结构一致：

```csharp
protected void RaisePurchaseFailed(PaymentEventArgs e)
{
    OnPurchaseFailed?.Invoke(this, e);
}
```
