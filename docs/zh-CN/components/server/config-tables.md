# 如何读写策划配置表(Tables)

读完本页,你能掌握 GameFrameX 中所有策划配置表(`TbAchievementConfig`、`TbItemConfig`、`TbSoundsConfig`、`TbLocalization`)的统一入口 `TablesComponent`,以及从配置表中读取、按主键查询、遍历、条件查找、引用解析的完整写法。

## 前置条件

- 已在项目中引用 `GameFrameX.Config` 程序集,并生成了对应的策划配置表文件。
- 已构造好 `ConfigComponent`,作为 `TablesComponent.Init` 的入参。
- 准备一个 `Func<string, Task<JsonElement>>` 类型的加载器(常见实现是从本地文件或远端下载 JSON 数据并解析为 `JsonElement`)。

## 操作步骤

### 1. 初始化并异步加载所有配置表

`TablesComponent` 会并行加载每张表,加载完成后自动调用 `Refresh()`,在内部触发 `PostInit()` 与 `ResolveRef()`(用于跨表引用解析)。

```csharp
using GameFrameX.Config;
using System.Text.Json;
using System.Threading.Tasks;

// 由调用方实现,例如根据资源名返回 JSON 内容
async Task<JsonElement> Loader(string name)
{
    var bytes = await File.ReadAllBytesAsync($"Configs/{name}.json");
    return JsonDocument.Parse(bytes).RootElement.Clone();
}

var configComponent = new ConfigComponent();
var tables = new TablesComponent();
tables.Init(configComponent);
await tables.LoadAsync(Loader);
```

加载完成后,可以通过 `tables.TbAchievementConfig`、`tables.TbItemConfig`、`tables.TbSoundsConfig`、`tables.TbLocalization` 访问每张表。

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L56)

### 2. 按主键读取单条数据

所有表都基于 `BaseDataTable<T>`,支持整数主键与字符串主键两种索引方式。读取失败的默认返回值是 `null`。

```csharp
// 整型主键读取
var item = tables.TbItemConfig[1001];
if (item != null)
{
    Console.WriteLine(item.Name);
}

// 长整型主键读取(主键定义成 long 时使用)
var ach = tables.TbAchievementConfig[100001L];

// 字符串主键读取(常用于本地化表)
var loc = tables.TbLocalization["ui.btn.confirm"];
```

`this[id]` 内部就是 `TryGet(id, out var v) ? v : null`,找不到时不会抛异常。

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L110-L180)

### 3. 用 TryGet 安全获取并区分"未命中"

如果不想拿到 `null` 又分不清是配置缺失还是业务逻辑,可以用 `TryGet` 拿到 `bool` 返回值:

```csharp
if (tables.TbSoundsConfig.TryGet(2005, out var sound))
{
    // sound 是有效数据
}
else
{
    // 配置缺失,提示策划补表
}
```

字符串键同样有 `TryGet(string id, out T value)` 重载,签名见 `IDataTable<T>` 接口。

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L138-L141)

### 4. 遍历、统计与条件查询

`BaseDataTable<T>` 提供了 LINQ 风格的常用操作,内部基于 `DataList` 实现:

| 操作 | 方法签名 | 用途 |
|------|---------|------|
| 取数量 | `int Count { get; }` | 命中缓存,多次调用不重复计算 |
| 取首个 | `T FirstOrDefault { get; }` | 取排序后的第一条 |
| 取末位 | `T LastOrDefault { get; }` | 取排序后的最后一条 |
| 全部数组 | `T[] All { get; }` / `T[] ToArray()` / `List<T> ToList()` | 拿到一份拷贝 |
| 条件查一条 | `T Find(Func<T, bool> func)` | 找不到返回 `null` |
| 条件查多条 | `T[] FindListArray(Func<T, bool> func)` / `List<T> FindList(...)` | 拿数组或列表 |
| 遍历执行 | `void ForEach(Action<T> func)` | 边遍历边处理 |
| 投影最大/最小 | `Tk Max<Tk>(Func<T, Tk>)` / `Tk Min<Tk>(...)` | 取某字段极值 |

下面给一个典型的"按类型找物品"的示例:

```csharp
// 找出所有 Type == 2 (假设表示消耗品) 的物品
var consumables = tables.TbItemConfig.FindListArray(x => x.Type == 2);
Console.WriteLine($"消耗品数量:{consumables.Length}");

// 累计所有奖励配置里 Id 最大值
var maxRewardId = tables.TbAchievementConfig.Max(x => x.Id);
```

Source: [BaseDataTable.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core.Config/BaseDataTable.cs#L189-L329)

### 5. 重新刷新表(热更新)

需要重载策划表时,再次调用 `LoadAsync` 即可:

```csharp
await tables.LoadAsync(Loader); // 会并行重新加载每张表并触发 Refresh()
```

`Refresh()` 会依次执行 `PostInit()` 与 `ResolveRef()`,重新建立跨表引用。

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L31-L73)

## 常见变体

### 局部化多语言读取

`TbLocalization` 来自 `GameFrameX.Config.Local` 命名空间,以字符串键索引,用法与其它表完全一致:

```csharp
var key = "ui.title.home";
if (tables.TbLocalization.TryGet(key, out var loc))
{
    Console.WriteLine(loc.Content);
}
```

### 重新初始化加载器

`Init` 会先调用 `configComponent.RemoveAllConfigs()` 清理旧注册,所以如果更换整套数据源,只需重新 `Init` 后再 `LoadAsync` 即可。

```csharp
tables.Init(newConfigComponent);
await tables.LoadAsync(newLoader);
```

Source: [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Config/Config/TablesComponent.cs#L25-L29)

## 常见错误

- **没有等 `LoadAsync` 完成就读取**:`TbAchievementConfig` 等属性在 `LoadAsync` 之前是默认引用,从默认值取数会得到 `null` 或空集合。务必 `await tables.LoadAsync(Loader);`。
- **混淆整型与长整型主键**:主键定义成 `long` 时,如果用 `int` 重载传入,会触发隐式转换但可能溢出;主键定义成 `int` 时也别用 `long` 重载,语义不一致。
- **跨表引用未刷新**:`PostInit()` / `ResolveRef()` 由 `Refresh()` 触发,自定义场景下若绕开 `LoadAsync`,引用字段可能为 `null`。
- **使用索引访问字符串键时拼写错误**:`this[string id]` 找不到会静默返回 `null`,先 `TryGet` 一次判断更安全。
- **直接修改 `BaseDataTable` 暴露的 `LongDataMaps` / `StringDataMaps`**:它们是 `protected`,但通过反射改写会破坏后续热更的幂等性,应走重新 `LoadAsync` 的路径。

## 背景(可选)

`TablesComponent` 由配置表生成器自动产出(`<auto-generated>` 头),它把每张 `Tb*` 表注册到 `ConfigComponent`,并在加载完成后用 `Refresh()` 完成引用解析。`BaseDataTable<T>` 把查找、遍历、条件查询、聚合等公共能力抽到基类,每张具体表只负责自身的 JSON 解析与主键映射。

关于 `ConfigComponent` 的整体装配,见 `GameFrameX.Config` 命名空间下的相关源码;关于各 `Tb*` 表的字段定义,由策划配置表生成器按 Excel/JSON 数据自动生成。
