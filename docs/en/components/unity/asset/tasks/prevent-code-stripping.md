# How to Avoid Missing APIs Caused by Code Stripping

Unity performs Managed Code Stripping during packaging. After IL2CPP compilation, unreferenced types, methods, and properties are removed. When your business code accesses GameFrameX asset APIs via reflection, strings, or dynamic loading, the stripped extension methods (such as `LoadTexture2DAsync`, `LoadPrefabSync`) will disappear entirely, throwing `MissingMethodException` at runtime. This page describes the protective measures already in use in this repository, as well as the conventions you must follow when adding new custom extensions.

## Prerequisites

- The project uses the Unity IL2CPP backend (enabled by default for Android / iOS / WebGL).
- Player Settings → Managed Stripping Level is set higher than Low, or Engine Code Stripping is enabled.
- The `GameFrameX.Asset` package has been imported into the project.

## Steps

### 1. Reuse the Extension Methods Already Marked in the Repository

The repository has already added `[UnityEngine.Scripting.Preserve]` to all public extension classes and members. Simply call them directly, and the stripper will keep them. For example, the `LoadTexture2DAsync` extension below:

```csharp
[UnityEngine.Scripting.Preserve]
public static class AssetComponentTexture2DExtensions
{
    [UnityEngine.Scripting.Preserve]
    public static Task<AssetHandle> LoadTexture2DAsync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetAsync<Texture2D>(path);
    }

    [UnityEngine.Scripting.Preserve]
    public static AssetHandle LoadTexture2DSync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetSync<Texture2D>(path);
    }
}
```

Source: [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs#L13-L44)

`AssetComponent` itself and the `GamePlayMode` property are also tagged with `[Preserve]`:

```csharp
[RequireComponent(typeof(GameFrameXAssetCroppingHelper))]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-4000)]
public sealed class AssetComponent : GameFrameworkComponent
{
    [UnityEngine.Scripting.Preserve]
    public EPlayMode GamePlayMode { get; set; }
}
```

Source: [Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L18-L45)

### 2. Add the Preserve Attribute to Custom Extensions as Well

When continuing to write extension methods for `AssetComponent` in your own project, you must add `[Preserve]` to the static class and every public member; otherwise the stripper will treat them as "unreferenced" and delete them.

```csharp
using UnityEngine;
using UnityEngine.Scripting;
using GameFrameX.Asset.Runtime;

[Preserve]
public static class MyAssetComponentExtensions
{
    [Preserve]
    public static AssetHandle LoadMyAssetSync(this AssetComponent self, string path)
    {
        return self.LoadAssetSync<Object>(path);
    }
}
```

Recommended placement: in the same directory or assembly as `AssetComponent`, so the stripper can scan them together during the build.

### 3. Confirm the Helper Component Exists in the Project

`AssetComponent` uses `[RequireComponent]` to force-attach a `GameFrameXAssetCroppingHelper`, which is specifically used to keep related types alive in the scene:

```csharp
[Preserve]
public class GameFrameXAssetCroppingHelper : MonoBehaviour
{
}
```

Source: [Runtime/GameFrameXAssetCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/GameFrameXAssetCroppingHelper.cs)

As long as an `AssetComponent` instance exists in the runtime scene (it will be created automatically when `GameFrameXAutoComponent` starts the framework), the stripper will retain all marked members along this reference chain.

### 4. Provide link.xml as a Fallback When Necessary

If your business side accesses asset APIs via reflection (for example, calling `LoadPrefabAsync` by string name), the compile-time references cannot be recognized by the analyzer. In that case, place an additional `link.xml` under `Assets/` to forcibly preserve the entire assembly:

```xml
<linker>
  <assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>
</linker>
```

`link.xml` must be placed in an `Assets` subdirectory outside any `Resources` folder for Unity to process it.

## Common Variations

| Scenario | Approach |
|------|------|
| Generic entry point `LoadAssetAsync<T>` | Call it directly. T is provided by the caller, and the reference chain is recognized by static analysis, so no extra `[Preserve]` is required. |
| Custom async wrapper layer | Add `[Preserve]` to the wrapper method, and ensure the wrapper method is statically called from at least one location. |
| WebGL platform | Force `EPlayMode.WebPlayMode`. `AssetComponent.Awake` already contains this branch internally. |
| Indirect reflection-based calls via Addressables / YooAsset | Provide `link.xml` as a fallback at the same time. |

## Common Errors

| Symptom | Cause | Resolution |
|------|------|------|
| Calling `LoadXxxAsync` after packaging throws `MissingMethodException` | The extension method is not statically referenced by any code and is stripped by IL2CPP. | Add `[UnityEngine.Scripting.Preserve]` to the extension class and method. |
| Reflection-based calls to types in the `GameFrameX.Asset.Runtime` assembly fail | The entire assembly has been stripped. | Add `<assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>` to `Assets/link.xml`. |
| Asset loading fails after WebGL packaging with `Asset manager is invalid.` | The play mode has been reverted to `EditorSimulateMode`. | `AssetComponent.Awake` already handles this. Confirm that `m_GamePlayMode` is serialized in the build artifact. |
| All asset APIs disappear after removing `AssetComponent` from the scene | `RequireComponent(GameFrameXAssetCroppingHelper)` is removed along with it. | Do not delete `AssetComponent` alone. If you need to replace it, keep `CroppingHelper` or re-attach it. |

## Verification

1. In Unity Editor → Build Settings, produce an IL2CPP build (Android or iOS).
2. On a real device or simulator, execute `await assetComponent.LoadTexture2DAsync("Assets/Textures/xxx.png");` and confirm there is no `MissingMethodException`.
3. Use `il2cppdumper` or `Unity Symbol` tools to reverse-lookup the dlls inside the build and confirm the extension types in the `GameFrameX.Asset.Runtime` assembly still exist.
4. If it still fails, gradually peel back custom `link.xml` / `[Preserve]` markers to locate the stripped member.

## Background (Optional)

`[UnityEngine.Scripting.Preserve]` is Unity's official "whitelist" marker for the managed code stripper, equivalent to preserving members one by one in link.xml. The repository adds this marker to all public extension APIs because these methods are mostly used via reflection or generic indirect calls, which the compile-time reference graph cannot cover.
