# 如何配置超时与并发连接数

在 GameFrameX.Web 中,超时时间 `Timeout` 可以通过 Inspector 序列化字段或代码设置(默认 5 秒),并发连接数 `MaxConnectionPerServer` 只能通过代码在 `IWebManager` 上设置(默认 8),它分别限制普通(JSON)请求与二进制请求两条调度通道的同时处理数量。

## 前置条件

- 场景中已挂载 `WebComponent` 组件(菜单 `GameFrameX/Web`)。
- 如需在代码中访问管理器,引用命名空间 `GameFrameX.Web.Runtime` 与 `GameFrameX.Runtime`。

## 配置项速查

| 配置项 | 类型 | 默认值 | 生效位置 | 说明 |
|--------|------|--------|----------|------|
| `WebComponent.m_Timeout` | `float`(秒) | `5f` | Inspector 序列化字段 | 组件初始化时写入管理器 |
| `WebComponent.Timeout` | `float`(秒) | 代理管理器 | 属性 | 同时回写序列化字段 |
| `WebManager.Timeout` | `float`(秒) | `5f` | 管理器属性 | 设置时同步更新 `RequestTimeout` |
| `WebManager.RequestTimeout` | `TimeSpan` | 随 `Timeout` 派生 | 管理器属性 | 实际下发到请求对象的超时 |
| `WebManager.MaxConnectionPerServer` | `int` | `8` | 管理器属性 | 普通通道与二进制通道各自的同时处理上限 |

## 操作步骤

### 1. 在 Inspector 中设置超时时间

选中挂有 `WebComponent` 的 GameObject,在 Inspector 中修改 **超时时间** 字段(单位:秒,默认 5):

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L59-L60)

组件 `Awake()` 时该值被写入管理器:

```csharp
m_WebManager = GameFrameworkEntry.GetModule<IWebManager>();
if (m_WebManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebManager.Timeout = m_Timeout;
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L88)

### 2. 在代码中运行时调整超时时间

`WebComponent.Timeout` 直接代理到管理器,同时把值写回序列化字段:

```csharp
public float Timeout
{
    get { return m_WebManager.Timeout; }
    set { m_WebManager.Timeout = m_Timeout = value; }
}
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L66-L70)

使用示例:

```csharp
// 在组件 Awake 之后调用,例如 Start()
webComponent.Timeout = 15f; // 全局超时改为 15 秒
```

### 3. 在代码中设置并发连接数

`MaxConnectionPerServer` 只存在于 `WebManager` / `IWebManager` 上,未在 `WebComponent` 暴露,必须通过代码修改:

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// 获取或设置超时时间(秒)
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>
/// 获取或设置每个服务器的最大连接数
/// </summary>
public int MaxConnectionPerServer { get; set; }
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L42-L70)

使用示例(与 `WebComponent.Awake` 中获取模块的方式一致):

```csharp
GameFrameworkEntry.GetModule<IWebManager>().MaxConnectionPerServer = 4; // 每条通道同时最多 4 个请求
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L81)

## 常见变体

**分别控制两条通道的并发**:普通(JSON)请求与二进制请求共用同一个 `MaxConnectionPerServer` 值,但各自独立计数——调度入口分别是 `m_SendingNormalList`(普通)与 `m_SendingBinaryList`(二进制):

```csharp
// 普通请求通道:Update 中按上限从等待队列取任务
if (m_SendingNormalList.Count < MaxConnectionPerServer)
{
    if (m_WaitingNormalQueue.Count > 0)
    {
        var webJsonData = m_WaitingNormalQueue.Dequeue();
        // ...发起请求并加入 m_SendingNormalList
    }
}
```

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 改了 Inspector 超时但不生效 | 代码在 `Awake()` 之后又用 `WebComponent.Timeout` 或 `m_WebManager.Timeout` 覆盖 | 统一在一处配置;运行时改值应放在 `Start()` 或之后 |
| 想在 Inspector 上改并发数找不到字段 | `MaxConnectionPerServer` 未在 `WebComponent` 上序列化 | 通过 `GameFrameworkEntry.GetModule<IWebManager>()` 用代码设置 |
| 设置 `Timeout = 0.5f` 后请求长时间不超时 | 下发到 UnityWebRequest 时按 `(int)RequestTimeout.TotalSeconds` 截断,小于 1 秒会变成 `0` | 超时值至少设为 `1f` 或更大的整数秒 |
| 把 `MaxConnectionPerServer` 理解为全局总并发 | 普通/二进制两条通道各自用该值独立判断 | 评估并发上限时按通道分别计算 |

## 背景(可选)

`Timeout` 的 setter 会同步派生 `RequestTimeout = TimeSpan.FromSeconds(value)`,请求真正创建时才把该值写到底层 `UnityWebRequest.timeout`(秒)或 `HttpWebRequest.Timeout`(毫秒);因此修改超时只影响之后新发起的请求。并发方面,请求先进入等待队列,`WebManager.Update` 每帧检查 `m_SendingNormalList.Count < MaxConnectionPerServer`,满足条件才出队发起,超出部分继续排队。
