# CacheState + BsonClassMap를 사용한 엔티티 영속화

`CacheStateTypeManager.Init()`을 통해 `ICacheState`를 구현하는 모든 엔티티 클래스를 한 번에 스캔하면, 프레임워크가 동시에 이들을 `BsonClassMap`에 등록하므로 이후 MongoDB 직렬화에서 직접 읽고 쓸 수 있으며, 각 엔티티에 매핑을 수동으로 작성할 필요가 없습니다.

## 사전 조건

- `GameFrameX.Apps` 어셈블리를 참조해야 합니다(`BsonClassMapHelper`, `CacheStateTypeManager` 포함).
- 엔티티 클래스는 `ICacheState` 인터페이스를 구현해야 합니다(캐시 가능/영속화 가능한 엔티티로 표시됨).
- 프로세스 시작 단계에서 `Init()`을 한 번 호출해야 하며, 일반적으로 `Program.Main`에서 다른 컴포넌트 초기화보다 앞에 배치합니다.

## 작업 단계

1. **엔티티가 `ICacheState` 인터페이스를 구현하도록 합니다**

   영속화되어야 하는(일반적으로 MongoDB에 기록되는) 모든 엔티티는 `ICacheState`를 구현해야 합니다. 프레임워크는 해당 인터페이스를 구현하는 타입만 스캔합니다.

2. **시작 진입점에서 `CacheStateTypeManager.Init()`을 한 번 호출합니다**

   `Init()`은 `AppsHandler`가 위치한 어셈블리를 스캔하여 `ICacheState`를 구현하는 모든 타입을 필터링하고, `XxHash32(타입 전체 이름)`을 id로 사용해 내부 `ConcurrentDictionary<long, Type>`에 기록한 뒤, 각 타입에 대해 `BsonClassMapHelper.RegisterClass`를 호출하여 MongoDB 드라이버에 등록합니다.

   ```csharp
   // GameFrameX.Launcher/Program.cs
   static void Main(string[] args)
   {
       CacheStateTypeManager.Init();
       MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
       // ... 기타 시작 로직
   }
   ```

   출처: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L10-L20)

3. **`Init()` 내부에서 두 개의 BSON Convention이 동시에 등록됩니다**

   - `DictionaryRepresentationConvention`: `IDictionary`의 BSON 표현을 `ArrayOfDocuments`로 고정하여 드라이버 버전에 따라 기본 동작이 달라지는 것을 방지합니다.
   - `EmptyContainerSerializeMethodConvention`: `List<T>`, `Dictionary<,>`, `ConcurrentDictionary<,>` 등 컨테이너에 대해 요소 개수가 0일 때 직렬화를 건너뛰어 빈 필드 기록을 줄입니다.

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   ConventionRegistry.Register(nameof(DictionaryRepresentationConvention),
                               new ConventionPack { new DictionaryRepresentationConvention(), }, _ => true);

   ConventionRegistry.Register(nameof(EmptyContainerSerializeMethodConvention),
                               new ConventionPack { new EmptyContainerSerializeMethodConvention(), }, _ => true);
   ```

   출처: [GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L102-L111)

4. **각 엔티티에 대해 `BsonClassMap.AutoMap`을 실행하고 불필요한 필드를 무시합니다**

   프레임워크는 타입 전체 이름의 `XxHash32`를 사전 기본 키로 사용하여 `GetType(id)`이 서로 다른 프로세스/재시작 후에도 원래 타입을 안정적으로 되찾을 수 있도록 보장하며, `AutoMap` + `SetIgnoreExtraElements(true)`를 통해 새로 추가된 필드가 이전 데이터의 역직렬화 실패를 일으키지 않도록 합니다.

   ```csharp
   // GameFrameX.Apps/BsonClassMapHelper.cs
   public static void RegisterClass(Type t)
   {
       var bsonClassMap = new BsonClassMap(t);
       bsonClassMap.AutoMap();
       bsonClassMap.SetIgnoreExtraElements(true);
       bsonClassMap.SetIgnoreExtraElementsIsInherited(true);
       BsonClassMap.RegisterClassMap(bsonClassMap);
   }
   ```

   출처: [GameFrameX.Apps/BsonClassMapHelper.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/BsonClassMapHelper.cs#L136-L143)

5. **런타임에 `GetType(id)`으로 타입을 역조회하여 다형성 역직렬화를 완료합니다**

   BSON 문서에 타입 id만 저장되어 있을 때 `CacheStateTypeManager.GetType(id)`을 호출하면 구체적인 `Type`을 되돌려받을 수 있으며, 이를 MongoDB 드라이버에 넘겨 객체를 생성합니다.

   ```csharp
   // GameFrameX.Apps/CacheStateTypeManager.cs
   public static Type GetType(long id)
   {
       HashMap.TryGetValue(id, out var value);
       return value;
   }
   ```

   출처: [GameFrameX.Apps/CacheStateTypeManager.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/CacheStateTypeManager.cs#L41-L45)

## 일반적인 변형

- **`ICacheState`를 구현하는 엔티티 클래스를 새로 추가한 경우**: 프로세스를 재시작하기만 하면 되며, 등록 API를 수동으로 호출할 필요가 없습니다. `Init()`이 자동으로 스캔합니다.
- **엔티티가 `AppsHandler`가 위치한 어셈블리에 없는 경우**: `BsonClassMapHelper.RegisterAllClass(assembly)`를 호출하여 대상 어셈블리를 등록 프로세스에 수동으로 전달하고 추가 스캔을 수행합니다.
- **빈 컨테이너 직렬화 건너뛰기를 임시로 비활성화하려는 경우**: `EmptyContainerSerializeMethodConvention`을 등록하지 않거나, 자신의 엔티티에 개별적으로 `SetShouldSerializeMethod`를 설정합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 시작 시 `BsonClassMap already registered` 오류 발생 | 동일한 타입이 중복 등록됨 | `RegisterClass` 내부에 이미 `IsClassMapRegistered` 가드가 있으므로, `Init()` 외부에서 수동으로 `RegisterClassMap`을 호출했는지 확인합니다 |
| 역직렬화 시 필드 유실 또는 `Element ... does not match any field` 예외 발생 | `SetIgnoreExtraElements`를 호출하지 않음 | `BsonClassMapHelper.RegisterClass` 경로를 거치는지 확인합니다 |
| `CacheStateTypeManager.GetType(id)`가 `null`을 반환함 | 엔티티 클래스가 `ICacheState`를 구현하지 않아 `Init` 시 수집되지 않음 | 엔티티에 `ICacheState` 인터페이스를 추가하고 프로세스를 재시작합니다 |
| `Dictionary`가 BSON에서 `Document`로 표현됨 | `DictionaryRepresentationConvention`이 등록되지 않음 | `Init()`이 실행되었는지, 그리고 모든 MongoDB 작업 이전에 실행되었는지 확인합니다 |

## 배경

프레임워크가 `XxHash32(type.ToString())`를 타입 id로 선택한 것은 id를 안정적으로 만들고 .NET 타입 전체 이름과 일대일로 대응시키면서 동시에 차지하는 공간을 줄이기 위함입니다. `SetIgnoreExtraElementsIsInherited`를 활성화하는 것은 하위 클래스에서 상속 필드가 새로 추가되더라도 이전 문서가 손상되지 않도록 하기 위함입니다. Convention 전역 등록에 `_ => true`를 사용하는 것은 명시적으로 매핑되지 않은 모든 클래스에 적용됨을 의미하며, 비즈니스 측의 인지 부담을 줄여줍니다.
