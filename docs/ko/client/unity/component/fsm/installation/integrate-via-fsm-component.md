# FsmComponent를 통해 프로젝트에 연동하는 방법

`FsmComponent`는 GameFrameX 프레임워크의 유한 상태 머신(FSM) 통합 진입점 컴포넌트로, `GameFrameworkComponent`를 상속받아 씬에 마운트되면 `GameFrameworkEntry.GetModule<IFsmManager>()`를 통해 하위 상태 머신 매니저를 가져오며, 모든 FSM의 생성, 조회, 소멸 및 `FixedUpdate` 폴링을 담당합니다.

## 사전 조건

- `com.gameframex.unity.fsm` 패키지가 설치되어 있어야 합니다 (`manifest.json`을 통해 도입).
- 씬에 GameFrameX 프레임워크 진입점이 존재해야 합니다 (`com.gameframex.unity.runtime`에서 제공하며, `FsmComponent`가 이를 통해 `IFsmManager`를 해석함).
- 상태 정의는 `FsmState<T>`를 상속받아 작성하며, 소유자 타입 `T`는 반드시 참조 타입(`class`)이어야 합니다.

## 작업 단계

1. **씬 진입점 GameObject에 FSM 컴포넌트를 추가합니다.** GameFrameX 프레임워크 진입점 컴포넌트(예: `GameEntry`)가 마운트된 동일한 GameObject에서 `Add Component`를 클릭하고 `GameFrameX/FSM`을 검색하여 추가합니다. 컴포넌트 클래스에는 `[AddComponentMenu("GameFrameX/FSM")]`가 표시되어 있어 메뉴 항목에서 바로 찾을 수 있습니다.

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/FSM")]
   [GameFrameXAutoComponent(-6000)]
   public sealed class FsmComponent : GameFrameworkComponent
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L43-L47)

2. **컴포넌트 인스턴스를 가져옵니다.** 런타임에 `GameEntry.GetComponent<FsmComponent>()`를 통해 참조를 얻습니다. 동시에 `com.gameframex.unity.entry` 단축 패키지를 도입한 경우 `GameApp.Fsm`을 바로 사용할 수 있습니다.

   ```csharp
   // 표준 방식
   FsmComponent fsmComponent = GameEntry.GetComponent<FsmComponent>();

   // 단축 방식 (com.gameframex.unity.entry에 의존)
   IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L47)

3. **상태 클래스를 정의합니다.** `FsmState<T>`를 상속받아 가상 메서드에 상태 로직을 작성하고, `ChangeState<TState>(fsm)`을 통해 전환을 트리거합니다.

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnEnter(IFsm<Player> fsm) { }

       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }

       protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
   }
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L101-L123)

4. **FSM을 생성하고 시작합니다.** `CreateFsm<T>`를 호출하여 소유자와 상태 집합을 전달하고, `Start<TState>()`을 호출하여 시작합니다. `Awake()` 내부에서 `GameFrameworkEntry.GetModule<IFsmManager>()`를 통해 매니저 바인딩을 완료하며, 가져오기 실패 시 `Log.Fatal("FSM manager is invalid.")`를 기록합니다.

   ```csharp
   var player = new Player();
   IFsm<Player> fsm = fsmComponent.CreateFsm(
       player,
       new FsmState<Player>[] { new IdleState(), new MoveState() }
   );
   fsm.Start<IdleState>();
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L63-L74) · [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L204-L222)

5. **구동 루프는 수동 호출이 필요 없습니다.** `FsmComponent.FixedUpdate()`가 Unity 물리 리듬에 맞춰 `m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime)`를 호출하므로, 컴포넌트를 마운트하면 FSM이 자동으로 구동됩니다. 비즈니스 스크립트에서 중복으로 tick하지 마세요.

   ```csharp
   private void FixedUpdate()
   {
       if (m_FsmManager == null) return;
       m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
   }
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

6. **필요 시 FSM을 소멸시킵니다.** `DestroyFsm` 시리즈 오버로드(owner 타입 기준, `IFsm<T>` 참조 기준, ownerType+name 등)를 통해 정리합니다.

   ```csharp
   fsmComponent.DestroyFsm(fsm);     // 지정 인스턴스 소멸
   fsmComponent.DestroyFsm<Player>(); // 해당 owner 타입의 미명명 FSM 소멸
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L304-L318)

## 일반적인 변형

- **명명된 FSM(동일 owner 타입에서 여러 머신 공존)**: `name`이 포함된 `CreateFsm` 오버로드를 통해 구분하고, 이후 `HasFsm<T>(name)` / `GetFsm<T>(name)`로 접근합니다. 예를 들어 캐릭터에 "전투 FSM"과 "AI 행동 트리 FSM"이 동시에 존재하는 경우 서로 다른 name으로 구분할 수 있습니다.

  ```csharp
  IFsm<Player> combat = fsmComponent.CreateFsm("Combat", player, new AttackState(), new HurtState());
  IFsm<Player> ai     = fsmComponent.CreateFsm("AI", player, new PatrolState(), new ChaseState());
  combat.Start<AttackState>();
  ai.Start<PatrolState>();
  ```

  Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L218-L222)

- **런타임 중 상태 추가/제거**: `IFsm<T>.AddState` / `RemoveState<TState>()`를 통해 동적으로 조정합니다. 현재 실행 중인 상태는 제거할 수 없습니다.

  ```csharp
  fsm.AddState(new JumpState());
  fsm.RemoveState<IdleState>();
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L153-L158)

- **상태 간 데이터 저장 및 조회**: `SetData(name, value)` / `GetData<TData>(name)` / `HasData(name)` / `RemoveData(name)`을 사용하며, 내부적으로 오브젝트 풀을 통해 런타임 중 GC가 발생하지 않습니다.

  ```csharp
  fsm.SetData("Health", 100);
  int hp = fsm.GetData<int>("Health");
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L141-L149)

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 콘솔에 `FSM manager is invalid.`가 출력됨 | `FsmComponent.Awake()` 시 프레임워크 진입점에서 `IFsmManager` 모듈을 찾을 수 없음 | 씬에 GameFrameX 진입점 컴포넌트가 존재하고 `FsmComponent` 초기화보다 먼저 완료되는지 확인; FSM 패키지 설치 여부 확인 |
| `CreateFsm` 후 `Start`에서 "상태가 존재하지 않음" 오류 발생 | 상태가 등록되지 않았거나, 전달된 owner 타입이 `T`와 일치하지 않음 | `CreateFsm<T>`의 `T`와 `FsmState<T>` 서브클래스의 `T`가 일치하는지 확인하고, 모든 상태를 `states` 배열에 추가했는지 확인 |
| 동일한 owner 타입으로 하나의 FSM만 생성 가능 | `name`이 없는 오버로드를 잘못 사용하여 암시적 명명 규칙에 의해 덮어쓰기 됨 | `name`이 포함된 `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)`을 사용 |
| FSM이 업데이트되지 않음 | 비즈니스 스크립트에서 `FixedUpdate`를 수동으로 비활성화했거나 `FsmComponent`가 마운트되지 않음 | 씬에 `FsmComponent`가 유일하게 하나 존재하는지 확인하고, 상태 내부에서 `m_FsmManager.FixedUpdate`를 다시 호출하지 않도록 함 |

## 배경 (선택)

`FsmComponent`는 단지 파사드(facade)이며, 요청을 `IFsmManager`(`GameFrameworkEntry.GetModule<IFsmManager>()`를 통해 획득)로 전달합니다. `[GameFrameXAutoComponent(-6000)]` 마크는 컴포넌트 자동 등록 순서를 제어하고, `Count`는 현재 FSM 인스턴스 수를 노출하여 에디터 및 런타임 모니터링에 활용됩니다. `[Preserve]` 마크는 IL2CPP 코드 스트립핑 시 공개 API가 잘못 제거되지 않도록 보장합니다.
