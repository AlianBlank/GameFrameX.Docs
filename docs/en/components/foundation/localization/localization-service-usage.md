# How to Use LocalizationService to Load and Read Localization Resources

`LocalizationService` is the static entry point of the localization system, providing a thread-safe, lazy-loaded way to obtain localized strings; calling its static methods lets you retrieve the multilingual text for a key without worrying about the details of the underlying `ResourceManager` and each `IResourceProvider`.

## Prerequisites

- The `GameFrameX.Foundation.Localization` assembly is referenced, and the corresponding localization resources have been included in the project (default/English `Resources.resx`, Chinese `Resources.zh-CN.resx`, etc.).
- Resource keys must already exist in the `.resx` files above, with key names managed in the `Namespace.Submodule.KeyName` style (e.g., `Encryption.InvalidKeySize`, `Utility.Exceptions.TimestampOutOfRange`).
- The project's target .NET version should be consistent with `GameFrameX.Foundation.Localization`.

## Steps

1. **Get a localized string (using the current UI culture)**. This is the most basic usage—simply pass in the resource key; if the key is not found, the key itself is returned.

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   var message = LocalizationService.GetString("Utility.Exceptions.TimestampOutOfRange");
   ```

   Source: [LocalizationService.cs#L114-L122](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L114-L122)

2. **Read with a specific culture**. When you need to get a value for a particular culture, pass in a `CultureInfo`; the lookup is resolved via the fallback chain `zh-Hans-CN → zh-Hans → zh → ` (empty = default), and it does not affect `CultureInfo.CurrentUICulture`.

   ```csharp
   using System.Globalization;
   using GameFrameX.Foundation.Localization.Core;

   var message = LocalizationService.GetString(
       "Utility.Exceptions.TimestampOutOfRange",
       new CultureInfo("zh-Hans-CN"));
   ```

   Source: [LocalizationService.cs#L130-L138](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L130-L138)

3. **Read formatted strings with placeholders**. Resource templates use `string.Format` placeholders (`{0}`, `{1}` …), with arguments passed in via `params object[]`.

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // Template example: "Invalid key size: {0}. Expected length: {1}."
   var formatted = LocalizationService.GetString(
       "Encryption.InvalidKeySize", 128, 256);
   ```

   Source: [LocalizationService.cs#L161-L164](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L161-L164)

   You can also explicitly specify a culture before formatting:

   ```csharp
   LocalizationService.FormatString(
       "Encryption.InvalidKeySize",
       CultureInfo.InvariantCulture,
       128, 256);
   ```

   Source: [LocalizationService.cs#L184-L187](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L184-L187)

4. **Preload resources at application startup (optional)**. The lazy-loading mechanism is sufficient for most scenarios; if you want resource discovery to complete during the startup phase, you can explicitly call `EnsureLoaded()` once.

   ```csharp
   using GameFrameX.Foundation.Localization.Core;

   // Warm up during application startup
   LocalizationService.EnsureLoaded();
   var message = LocalizationService.GetString("Utility.Exceptions.TimestampOutOfRange");
   ```

   Source: [LocalizationService.cs#L207-L210](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L207-L210)

5. **Integrate with `IStringLocalizer` (ASP.NET Core / generic .NET hosts)**. Use `GameFrameXStringLocalizer` to wrap this service's `ResourceManager` as an `IStringLocalizer`, so it can be used within dependency injection and the `Microsoft.Extensions.Localization` ecosystem.

   ```csharp
   using GameFrameX.Foundation.Localization.Core;
   using Microsoft.Extensions.Localization;

   var manager = LocalizationService.Instance;
   IStringLocalizer localizer = new GameFrameXStringLocalizer(manager);

   var found    = localizer["Known.Key"];      // LocalizedString.Value = "Known value"
   var missing  = localizer["Missing.Key"];    // .ResourceNotFound == true
   var argument = localizer["Known.Key", "ignored"]; // Goes through the formatting path
   ```

## Common Variants

- **Register a custom resource provider (high priority)**. Providers registered manually via `RegisterProvider` are placed at the very front in LIFO order, which is useful for testing or integrating database/remote resources.

  ```csharp
  LocalizationService.RegisterProvider(new DatabaseResourceProvider(/* ... */));
  var message = LocalizationService.GetString("Custom.Message");
  ```

  Source: [LocalizationService.cs#L258-L261](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L258-L261)

- **Listen for missing keys**. Subscribe to the `MissingKey` event to capture unlocalized keys at runtime and write them to telemetry/logs.

  ```csharp
  LocalizationService.MissingKey += (sender, args) =>
  {
      Console.WriteLine($"Missing localization key: {args.Key} (culture={args.Culture.Name})");
  };
  ```

## Common Mistakes

- **No visible error when a key does not exist**. `GetString` does not throw an exception when it cannot find a key; instead, it returns the key string itself (this behavior is explicitly covered in tests). If text like `Unknown.Test.Key` shows up in the UI, it usually means the `.resx` was not compiled into the assembly or the key name is misspelled; you can locate the issue by subscribing to the `MissingKey` event or checking `GetStatistics().MissingKeys`.

  Source: [LocalizationServiceTests.cs#L40-L51](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationServiceTests.cs#L40-L51)

- **Treating `CultureInfo.CurrentUICulture` as an "explicit culture"**. When calling `GetString(key)` without a culture argument, `CurrentUICulture` is used; once a culture is explicitly passed in, the lookup goes through `GetCultureFallbackChain` (e.g., `zh-Hans-CN → zh-Hans → zh → ` default) and no longer layers on top of `CurrentUICulture`. Therefore, switching the thread's UI culture does not affect the result of calls made with an explicitly provided culture.

  Source: [LocalizationHighPriorityFeatureTests.cs#L11-L40](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationHighPriorityFeatureTests.cs#L11-L40)

- **Formatting template errors get silently swallowed**. When a template is missing a `}` or placeholder indices do not match, the system does not throw a `FormatException`; instead, it returns the original template text and records the failure count via `GetStatistics().FormatFailureCount`, which requires active monitoring.

  Source: [LocalizationHighPriorityFeatureTests.cs#L71-L82](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationHighPriorityFeatureTests.cs#L71-L82)

- **Creating a `ResourceManager` repeatedly**. `LocalizationService.Instance` guarantees a singleton via `Lazy<T>`; if you `new ResourceManager()` yourself, registered custom providers, statistics, and event subscriptions will not interoperate with the global service. Always operate through `LocalizationService`.

  Source: [LocalizationService.cs#L60-L74](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L60-L74), [LocalizationServiceTests.cs#L14-L23](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Tests/Localization/LocalizationServiceTests.cs#L14-L23)

## Background (Optional)

`LocalizationService` internally uses `Lazy<ResourceManager>` to hold the sole instance; methods such as `GetString` simply forward the call to the corresponding methods on `Instance`. The actual lookup is performed by the `IResourceProvider` chain in priority order, and by default it scans `Localization/Messages/Resources.*.resx` in loaded assemblies. When a culture is passed in, `GetCultureFallbackChain` is called first to generate the fallback chain, trying each level in turn down to the default (`""`) culture. `FormatString` uses a unified formatting API: template parsing failures do not throw exceptions; instead, they degrade to returning the template and write the failure count into `ResourceManagerStatistics`, making it easy for upper layers to perform telemetry and alerting. `GameFrameXStringLocalizer` serves as the adaptation layer between this service and the `Microsoft.Extensions.Localization` ecosystem, suitable for reusing the same `ResourceManager` within a dependency injection container.
