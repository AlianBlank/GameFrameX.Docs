# 打包配置不生效怎么办

当你在 `XCodeConfig.json` 里写的构建设置、Plist、签名或 Capabilities 没有体现在导出的 Xcode 工程中时,通常是:配置文件没被找到、JSON 解析失败、被其他同名配置或渠道配置覆盖、或写错了目标节点。本页按日志线索逐一定位修复。

所有配置的入口是 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L25) 的 `OnPostProcessBuild`,它在 `[PostProcessBuild(888)]` 优先级、仅 `BuildTarget.iOS` 时运行,且整个文件处于 `#if UNITY_IOS` 条件编译下;内部所有异常都会被 `Debug.LogException` 吞掉,**打包不会失败,只会静默跳过**,所以第一件事是看 Unity Console。

## 快速诊断

| 症状(Console 日志 / Xcode 工程表现) | 原因 | 修复 |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 文件名不是精确的 `XCodeConfig.json`,或未被 Unity 导入为 TextAsset,或当前不是 iOS 平台构建 | 见 [修复 1:确认配置文件能被找到](#修复-1确认配置文件能被找到) |
| `{jsonPath} 解析失败, 跳过合并` | JSON 格式非法(多余逗号、单引号、注释等) | 见 [修复 2:校验 JSON 语法](#修复-2校验-json-语法) |
| `合并后的配置为空，跳过设置` | 所有找到的文件解析后均为空或失败 | 同上,并确认文件内有内容 |
| 配置生效了但值不对 | 工程里存在多个 `XCodeConfig.json`,按路径排序后逐个 `Merge`,**后合并的覆盖先合并的** | 见 [修复 3:排查同名文件覆盖](#修复-3排查同名文件覆盖) |
| 某项配置只在部分渠道生效/不生效 | 渠道文件 `XCodeConfig.{channel}.json` 最后合并、优先级最高;渠道值来自 `-channel` 参数或 EditorPrefs 的 `XCodeBuild_Channel` | 见 [修复 4:检查渠道配置与残留渠道](#修复-4检查渠道配置与残留渠道) |
| `properties` 里的项没写入 Build Settings | 配置放在了顶层而不是 `unityMain` / `unityFramework` 节点下,或没按 `"="` / `"+"` / `"-"` 三种子表组织 | 见 [修复 5:确认键的结构](#修复-5确认键的结构) |
| Console 有红色异常堆栈 | 配置类型不匹配(如把数组当成对象)等运行时异常,被捕获后整段后处理中止 | 见 [修复 6:读取异常堆栈](#修复-6读取异常堆栈) |
| Capabilities 生效但构建属性丢失 | Capabilities 由 `ProjectCapabilityManager` 独立写盘,若其他插件在其之后重写 `project.pbxproj` 会丢失(本工具已通过重新读取缓解) | 见 [修复 7:排除更高优先级插件覆盖](#修复-7排除更高优先级插件覆盖) |

## 修复步骤

### 修复 1:确认配置文件能被找到

加载逻辑在 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58-L77):它遍历全部 `t:textasset` 资源,只匹配**文件名完全等于** `XCodeConfig.json`(忽略大小写)的文件,与所在目录无关。

1. 确认文件名精确为 `XCodeConfig.json`(不是 `XCodeConfig.json.txt`、`xcodeconfig.json.bak`)。
2. 确认文件已被 Unity 导入:在 Project 窗口选中它,Inspector 中应显示为 Text Asset;目录下应存在同名 `.meta` 文件。
3. 确认是 iOS 构建:`OnPostProcessBuild` 中 `target != BuildTarget.iOS` 时直接 return(见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L17-L20))。
4. 确认当前平台宏满足 `#if UNITY_IOS`——若工程从未切换到 iOS 平台,整个程序集内容不会参与编译。

### 修复 2:校验 JSON 语法

每个文件用 `json.HashtableFromJson()` 解析,失败时输出 `解析失败, 跳过合并` 并 continue(见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L39-L45))。解析器为轻量实现,不支持注释、尾随逗号、单引号字符串。用任意 JSON 校验器(如 VS Code 的 JSON 语言服务)检查该文件,重点看错误日志里打印的 `{jsonPath}` 是哪一个。

### 修复 3:排查同名文件覆盖

工具会收集工程内**所有**名为 `XCodeConfig.json` 的文件,排序后依次合并(见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L34-L49)):

```csharp
Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    ...
    finalConfig.Merge(table);
}
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L35-L49)

1. 在 Console 搜索 `[MergeConfig] 正在合并配置:`,日志会列出每个参与合并的文件路径及顺序。
2. 若第三方插件自带 `XCodeConfig.json`,其后合并的同名键会覆盖你的值——删除、改名(改名即不再参与合并),或把自己的值改放到渠道文件中(渠道文件最后合并)。

### 修复 4:检查渠道配置与残留渠道

渠道标识的读取顺序是:命令行参数 `-channel` → EditorPrefs 键 `XCodeBuild_Channel` → null(见 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)):

```csharp
public static string GetChannel()
{
    var args = Environment.GetCommandLineArgs();
    for (int i = 0; i < args.Length - 1; i++)
    {
        if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
        {
            return args[i + 1];
        }
    }

    string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
    if (!string.IsNullOrEmpty(editorChannel))
    {
        return editorChannel;
    }

    return null;
}
```

Source: [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)

1. 渠道文件命名必须为 `XCodeConfig.{channel}.json`(如 `XCodeConfig.ioschina.json`),见 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111)。
2. 渠道文件最后合并、覆盖优先级最高——若发现"期望的值被改掉了",先确认是否命中了某个渠道文件;Console 会打印 `[MergeConfig] 检测到渠道: {channel}` 与 `[MergeConfig] 正在合并渠道配置: {path}`。
3. **EditorPrefs 会跨工程、跨会话残留**。之前 `SetChannel("xxx")` 设置过的渠道在下次打包时仍然生效,导致合并了不想要的渠道配置。清除方式:传入空串删除该键(见 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51))。

```csharp
GameFrameX.Xcode.Editor.SettingLoader.SetChannel(null); // 或传空串,清除残留渠道
```

Source: [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L41-L51)

### 修复 5:确认键的结构

第一阶段只读取固定的顶层键并分发给目标,见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L92-L126):

| 顶层键 | 写入目标 | 说明 |
|------|---------|------|
| `unityMain` | UnityMain(主)target | properties / frameworks / libs / files / folders / filesCompileFlag / otherLinkerFlag / runPathSearchPaths / pods |
| `unityFramework` | UnityFramework target | 同上 |
| `signing` | 主 target | 签名,同时取 `bundleId` 供 Capabilities 使用 |
| `plist` | Info.plist | 见 `RunPlist` |
| `environmentVariables` | scheme 环境变量 | 见 `RunEnvironmentVariables` |
| `launcherArgs` | scheme 启动参数(数组) | 见 `RunArgument` |
| `capabilities` | 主 target | Capabilities |
| `localizations` | 工程(数组) | 本地化资源 |
| `podfile` / `podSource` | Podfile | 完整 Podfile 路径 / 源地址列表 |
| `swiftBridging` | bool,默认 true | Swift 桥接 |
| `podInstall` | bool,默认 true | 是否自动执行 `pod install` |

`properties` 内部再按 `"="`(直接 set)、`"+"`(向列表追加)、`"-"`(从列表移除)三张子表处理(见 [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L16-L57)):

```csharp
Hashtable setTable = table.Get<Hashtable>("=");
foreach (DictionaryEntry i in setTable)
{
    proj.SetBuildProperty(targetGuid, i.Key.ToString(), i.Value.ToString());
}
```

Source: [PostProcessBuildHelper.BuildProperties.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.BuildProperties.cs#L20-L25)

常见写错:`properties` 放在顶层而不是 `unityMain.properties` 下;把应放入 `"+"` 的列表值写进 `"="`;键名拼写大小写不一致(Hashtable 键区分大小写)。

### 修复 6:读取异常堆栈

整个流程包在 `try/catch` 中,异常只 `Debug.LogException`、不中断打包(见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L158-L161))。若 Console 出现异常,异常点**之后**的所有配置都不会执行——例如 `plist` 前抛异常,则 `capabilities`、`podfile`、`pod install` 全部被跳过。按堆栈定位到具体键,通常是类型不匹配(对象写成了数组、字符串写成了数字)。

### 修复 7:排除更高优先级插件覆盖

本工具以 `[PostProcessBuild(888)]` 运行,晚于大多数后处理(见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L15))。若你的其他插件回调优先级大于 888,或直接编辑 `project.pbxproj` / Info.plist 而未基于本工具写盘后的内容,就会把配置覆盖掉。另注意:Capabilities 通过 `ProjectCapabilityManager` 独立写盘,本工具在其之后重新读取 `project.pbxproj` 再继续写 Localization(见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L121-L123));确认没有第三方代码在这之后重写工程文件。

## 验证

1. 重新执行一次 iOS 构建,Console 中应依次出现:
   - 每个参与文件的 `[MergeConfig] 正在合并配置: {path}`;
   - 若有渠道:`[MergeConfig] 检测到渠道: {channel}`;
   - `[PBXProject] 正在应用最终合并配置...` 与 `[OtherSettings] 正在应用最终合并配置...`;
   - 没有任何红色异常。
2. 打开导出目录 `Unity-iPhone.xcodeproj/project.pbxproj`,搜索你设置的构建属性名,确认值已更新。
3. 检查 `Info.plist` 中 `plist` 节点写入的键值。
4. 在 Xcode 中选择主 target,Signing & Capabilities 页应显示 `capabilities` 配置的项;`project.entitlements` 应存在对应条目。
