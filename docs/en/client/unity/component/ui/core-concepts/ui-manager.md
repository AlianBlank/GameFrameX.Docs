# How the UI Manager (IUIManager) Works

`IUIManager` is the main entry point of the GameFrameX UI module, responsible for uniformly managing UI groups (`IUIGroup`), the UI form instance pool, load/close flows, and external events. This page explains how it operates internally — from opening a UI form to recycling it, what happens along the call chain, and what each configuration option means.

## Interface Overview

`IUIManager` is defined in [Runtime/UI/IUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UI/IUIManager.cs), with its core members grouped by responsibility as follows.

| Category | Members | Purpose |
|------|------|------|
| Instance pool configuration | `InstanceAutoReleaseInterval`, `InstanceCapacity`, `InstanceExpireTime`, `RecycleInterval` | Control the capacity, expiration time, auto-release, and recycling pace of the UI instance object pool |
| Animation toggles | `IsEnableUIShowAnimation`, `IsEnableUIHideAnimation` | Whether to enable UI form show/hide animations |
| Group management | `AddUIGroup`, `HasUIGroup`, `GetUIGroup`, `GetAllUIGroups` | Add/query UI groups |
| UI form queries | `HasUIForm`, `GetUIForm(s)`, `GetAllLoadedUIForms`, `IsLoadingUIForm`, `IsValidUIForm` | Query UI forms by serial number or asset name |
| Open/close | `OpenUIFormAsync`, `CloseUIForm`, `CloseAllLoadedUIForms`, `CloseAllLoadingUIForms` | Asynchronous open, close, and batch close |
| Events | `OpenUIFormSuccess`, `OpenUIFormFailure`, `CloseUIFormComplete` | Callbacks fired when asynchronous operations complete |
| Dependency injection | `SetObjectPoolManager`, `SetResourceManager`, `SetUIFormHelper` | Inject the underlying object pool, assets, and helpers |

The abstract base class `BaseUIManager : GameFrameworkModule, IUIManager` ([Runtime/BaseUIManager.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L36-L39)) is responsible for holding this state and implementing the common logic.

## Flow of Opening a UI Form

The `OpenUIFormAsync` entry point is in [Runtime/BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118). Both overloads ultimately delegate to the internal `InnerOpenUIFormAsync`:

```csharp
public Task<IUIForm> OpenUIFormAsync<T>(string uiFormAssetPath, bool pauseCoveredUIForm, object userData, bool isFullScreen = false) where T : class, IUIForm
{
    return InnerOpenUIFormAsync(uiFormAssetPath, typeof(T), pauseCoveredUIForm, userData, isFullScreen);
}

public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}
```

Source: [Runtime/BaseUIManager.Open.cs#L100-L118](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L100-L118)

During the open process, the manager works in the following order:

1. Requests an auto-incremented `serialId` and writes `{serialId, assetPath}` into `m_UIFormsBeingLoaded`.
2. Asynchronously loads the Prefab via `m_AssetManager`; the `IUIForm` is instantiated in the load-completion event.
3. Places the instance into its `IUIGroup`; based on `pauseCoveredUIForm`, decides whether to trigger `OnCover`/`OnReveal` on the covered UI forms within the target group.
4. Fires the `OpenUIFormSuccess` event and returns the `IUIForm` to the caller via `Task`.
5. An exception at any stage fires `OpenUIFormFailure` and removes the entry from `m_UIFormsBeingLoaded`.

## Flow of Closing a UI Form

`CloseUIForm` provides overloads by serial number, by instance, by generic type, and by `userData`, all implemented in [Runtime/BaseUIManager.Close.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Close.cs). Key points of the flow:

1. Validates with `IsValidUIForm`; if it passes, the form is detached from the `IUIGroup`.
2. Based on `IsEnableUIHideAnimation`, decides whether to play the hide animation.
3. By default, the form enters the recycle queue for deferred recycling; when `isNowRecycle: true` is passed, it is returned to the object pool immediately.
4. Once recycling completes, `CloseUIFormComplete` is fired.

The recycle queue is paced by `RecycleInterval` (default 60 seconds); when the time is up, items are batch-recycled into `m_InstancePool` under `m_ObjectPoolManager`.

## Instance Object Pool

`m_InstancePool` is an object pool under `IObjectPoolManager`, serving as the reusable cache for UI instances. The three properties `InstanceCapacity`, `InstanceExpireTime`, and `InstanceAutoReleaseInterval` are forwarded directly to the corresponding fields of that pool ([BaseUIManager.cs#L122-L182](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.cs#L122-L182)).

| Property | Forwarded Target |
|------|---------|
| `InstanceAutoReleaseInterval` | `m_InstancePool.AutoReleaseInterval` |
| `InstanceCapacity` | `m_InstancePool.Capacity` |
| `InstanceExpireTime` | `m_InstancePool.ExpireTime` |

In other words: when the pool is full, the least recently used instances are evicted based on the expiration time, avoiding frequent Prefab instantiation.

## Event Callbacks

The three events are maintained via explicit `add`/`remove` in [BaseUIManager.Open.cs#L42-L68](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L42-L68), which helps preserve them under IL2CPP:

- `OpenUIFormSuccess(OpenUIFormSuccessEventArgs)` — Fired after loading and initialization succeed.
- `OpenUIFormFailure(OpenUIFormFailureEventArgs)` — Fired in cases such as asset load failure, type mismatch, or a helper not being injected.
- `CloseUIFormComplete(CloseUIFormCompleteEventArgs)` — Fired when the entire close flow (animation, recycling) has finished.

## Dependency Injection Order

`BaseUIManager` does not create `IAssetManager`, `IObjectPoolManager`, or `IUIFormHelper` itself; the caller must inject them via the corresponding setters before calling `Open/Close`. All three must be ready on the `OpenUIFormAsync` path, otherwise `OpenUIFormFailure` will be fired immediately.
