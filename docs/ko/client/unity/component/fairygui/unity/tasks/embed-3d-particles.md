# UI에 모델, 파티클, 본 애니메이션 임베딩하기

FairyGUI의 `GoWrapper`를 사용하여 임의의 `GameObject`(3D 모델, 파티클 시스템, 본 애니메이션 등)를 디스플레이 객체로 래핑한 후, UI의 빈 그래픽 컴포넌트에 연결하면 별도의 카메라나 RenderTexture 없이도 FairyGUI의 계층 구조, 가림(occlusion) 및 정렬에 참여시킬 수 있습니다.

## 사전 조건

- 프로젝트에 이 FairyGUI 패키지(`Runtime/Core/GoWrapper.cs`가 속한 어셈블리)가 이미 임포트되어 있어야 합니다.
- UI 화면에 플레이스홀더로 사용할 **빈 그래픽(Graph)** 컴포넌트를 준비합니다. 코드에서 먼저 투명 사각형을 그려 플레이스홀더로 사용할 수도 있습니다. FairyGUI 자체도 `GWindow`에서 다음과 같이 하고 있습니다:

```csharp
GGraph graph = _dragArea as GGraph;
if (graph != null && graph.shape.isEmpty)
    graph.DrawRect(_dragArea.width, _dragArea.height, 0, Color.clear, Color.clear);
```

Source: [GWindow.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/UI/GWindow.cs#L159-L161)

## 작업 단계

1. 표시하려는 `GameObject`(모델, 파티클 프리팹, 본 애니메이션 호스트 등)를 인스턴스화합니다.
2. `GoWrapper`를 생성하여 래핑을 완료한 뒤, 래핑 결과를 빈 그래픽 컴포넌트에 설정합니다:

```csharp
GameObject model = Instantiate(modelPrefab);
GoWrapper wrapper = new GoWrapper(model);   // 생성 시점에 래핑이 완료됩니다
holder.SetNativeObject(wrapper);            // holder는 UI의 빈 그래픽 GGraph입니다
```

`GoWrapper(GameObject go)`의 실제 시그니처는 다음과 같으며, 생성 시 기본적으로 머티리얼을 복사하지 **않습니다**:

```csharp
public GoWrapper(GameObject go) : this()
{
    SetWrapTarget(go, false);
}
```

Source: [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L47-L54)

3. 머티리얼이 다른 객체와 공유되거나, 머티리얼에 UI 특유의 처리가 필요한 경우, 머티리얼을 복사하는 모드로 래핑 객체를 설정합니다:

```csharp
/// 래핑 객체를 설정합니다. 기존 래핑 객체가 있었던 경우, 새 래핑 객체를 설정하면 기존 래핑 객체는 참조만 제거될 뿐 파괴되지 않는 점에 유의하십시오.
/// 객체에 포함된 모든 머티리얼은 복사되지 않습니다. 머티리얼이 이미 공용으로 사용 중이라면 다른 객체에 영향을 줄 수 있습니다. 자동으로 복사하길 원한다면 SetWrapTarget(target, true)로 설정하십시오.
public GameObject wrapTarget
{
    get { return _wrapTarget; }
    set { SetWrapTarget(value, false); }
}

public void SetWrapTarget(GameObject target, bool cloneMaterial)
```

Source: [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L56-L77)

4. 래핑의 내부 구현은 대상 객체를 자신의 하위로 붙이고 렌더러를 캐시합니다. Canvas가 아닌 객체의 크기는 0으로 설정되며, 표시 여부는 렌더러 자체가 결정합니다:

```csharp
if (_wrapTarget != null)
{
    _wrapTarget.transform.SetParent(this.cachedTransform, false);
    _canvas = _wrapTarget.GetComponent<Canvas>();
    if (_canvas != null)
    {
        _canvas.renderMode = RenderMode.WorldSpace;
        _canvas.worldCamera = StageCamera.main;
        _canvas.overrideSorting = true;

        RectTransform rt = _canvas.GetComponent<RectTransform>();
        rt.pivot = new Vector2(0, 1);
        rt.position = new Vector3(0, 0, 0);
        this.SetSize(rt.rect.width, rt.rect.height);
    }
    else
    {
        CacheRenderers();
        this.SetSize(0, 0);
    }

    SetGoLayers(this.layer);
}
```

Source: [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L92-L114)

5. 매 프레임 래핑 객체에 대한 추가 처리가 필요할 때는 `onUpdate`를 구독하고, 머티리얼 교체 로직을 완전히 제어해야 할 때는 `customCloneMaterials` / `customRecoverMaterials` 델리게이트를 제공합니다:

```csharp
public event Action<UpdateContext> onUpdate;
public Action<Dictionary<Material, Material>> customCloneMaterials;
public Action customRecoverMaterials;
```

## 일반적인 변형

- **UGUI Canvas 임베딩**: `SetWrapTarget`이 대상에 `Canvas`가 있는 것을 감지하면 자동으로 `RenderMode.WorldSpace`로 전환하고, `StageCamera.main`을 지정하며, RectTransform 크기에 따라 `SetSize`를 수행하므로, UGUI 패널을 FairyGUI에 직접 임베딩할 수 있습니다.
- **클릭 감지가 필요한 3D 객체**: 리포지토리에서 다양한 히트 테스트 구현을 제공하므로, 필요에 따라 `GoWrapper`(`DisplayObject` 상속)의 히트 영역과 함께 사용합니다: [ColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/ColliderHitTest.cs), [MeshColliderHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/MeshColliderHitTest.cs), [PixelHitTest.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/HitTest/PixelHitTest.cs).

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 머티리얼을 공유하는 다른 객체의 색상이 의도치 않게 변경됨 | 래핑 시 `sharedMaterial`을 직접 사용함 | `SetWrapTarget(target, true)`을 사용해 머티리얼을 복사 |
| 래핑 객체를 변경한 후에도 이전 모델이 여전히 표시됨 | `SetWrapTarget`은 참조만 제거하고 이전 객체를 **파괴하지 않음** | 대상을 변경하기 전에 이전 객체를 직접 `Destroy` |
| 흐림 등 Layer 기반으로 적용되는 효과가 래핑 객체에 제대로 작동하지 않음 | 래핑 객체와 그 하위 오브젝트는 UI와 동일한 Layer를 사용해야 함 | `GoWrapper`는 `_SetLayerDirect`에서 이미 재귀적으로 Layer를 설정하므로, 외부 코드에서 다시 변경하지 않았는지 확인 |
| 본 애니메이션/파티클이 렌더링 업데이트되지 않거나 렌더링이 누락됨 | 내부 렌더러 캐시가 갱신되지 않음 | 래핑 대상을 다시 설정하거나 `CacheRenderers()`를 호출해 다시 캐시(위의 92-114행 호출 위치 참조) |

`_SetLayerDirect`의 재귀적 Layer 처리(소스 주석에 따르면 `GoWrapper`에서 흐림 효과를 사용하기 위한 것입니다):

```csharp
override internal void _SetLayerDirect(int value)
{
    gameObject.layer = value;
    if (_wrapTarget != null)// 이 if문은 GoWrapper에서 흐림 효과를 사용하기 위한 것입니다
    {
        _wrapTarget.layer = value;
        foreach (Transform tf in _wrapTarget.GetComponentsInChildren<Transform>(true))
        {
            tf.gameObject.layer = value;
        }
    }
}
```

## 배경

`GoWrapper`는 `DisplayObject`를 상속합니다(선언은 [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L8-L12) 참조). 이 클래스는 `GoWrapper`라는 이름의 호스트 `GameObject`를 생성하고, 래핑 대상을 `SetParent`로 `cachedTransform` 하위에 붙이며, 대상의 모든 `Renderer`를 캐시합니다(구조체 `RendererInfo`에는 `renderer`, `materials`, `sortingOrder`가 포함됩니다. [GoWrapper.cs](https://github.com/GameFrameX/com.gameframex.unity.fairygui.unity/blob/main/Runtime/Core/GoWrapper.cs#L27-L32) 참조). 이를 통해 일반 3D 콘텐츠가 FairyGUI의 디스플레이 리스트와 배칭/정렬 체계에 편입됩니다. 이전의 `supportStencil` 플래그는 `[Obsolete]`로 표시되었으며, 스텐실 버퍼 처리는 이제 자동으로 수행되므로 수동으로 설정할 필요가 없습니다.
