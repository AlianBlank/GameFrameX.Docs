# チャネル設定を変更しても古い値が読み込まれる場合の対処方法

`application_config.txt`、AndroidManifest の meta-data、または iOS の Info.plist を変更したのに、`BlankGetChannel.GetChannelName()` が依然として古い値を返す場合、原因はほぼ次の 2 つです:プロセス内の静的キャッシュ `ChannelCache` にヒットした後に再読み込みされない、または設定がビルド時にすでにパッケージ内に組み込まれており、ディスク上のファイルを変更してもビルド済みアプリケーションには反映されない。

## クイック診断

| 症状 | 原因 | 修正 |
|------|------|------|
| Editor/PC/WebGL で `application_config.txt` を変更したが、`GetChannelName()` が依然として古い値を返す | 静的辞書 `ChannelCache` にヒットすると直接返され、ファイルを再読み込みしない | Play Mode を終了して再度入る(スクリプトドメインのリロードをトリガー)、下記の「プロセス内キャッシュのクリア」を参照 |
| Editor でファイルを変更し、Play Mode を再起動しても古い値のまま | Unity がまだその TextAsset を再インポートしておらず、`Resources.Load` で取得できるのは依然として古いリソース | Editor ウィンドウに切り替えて再インポートを待つ、または該当ファイルを右クリックして `Reimport` を実行してから Play Mode に入る |
| パッケージ化(Standalone/WebGL)後に設定ファイルを変更したが、App 内のチャネルが変わらない | `Resources/application_config.txt` はビルド時にすでにパッケージ内に固定されている | `Assets/Resources/application_config.txt` を変更後に再ビルドして上書きインストールする |
| Android で AndroidManifest の meta-data を変更したが反映されない | meta-data はすでに APK にコンパイルされており、かつ初回読み取り結果がキャッシュに入っている | manifest 変更後に再ビルドしてインストールする;実行中に更新することはできない |
| iOS で再ビルドしてもチャネルが `default` または古い値のまま | `PostProcessBuildHandler` は Info.plist に `channel` キーが**存在しない**場合にのみ書き込み、既存の値はスキップされる | Xcode で Info.plist の `channel` キーを削除または変更してから再ビルドする、詳細は下記を参照 |
| iOS でキー未設定の場合、C# 側の `default` ではなく `unknown` が返される | ネイティブの `getChannelName` はキーが見つからない場合、固定で `unknown` を返す | Info.plist に該当するキーを追加する |
| 設定値に `=` が含まれており、読み込まれた値が切り詰められる | 解析は `=` で分割した後、2 番目のセグメントのみ取得する | 値に `=` を使用しない、下記の「値が切り詰められる」を参照 |

## 修正手順

### プロセス内キャッシュのクリア(最も一般的な根本原因)

`GetChannelName` が最初に行うのは静的キャッシュの検索で、ヒットすれば即座に返され、以降の読み取りロジックは完全にスキップされます:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
{
    if (ChannelCache.TryGetValue(channelKey, out var value))
    {
        return value;
    }

    string channelName = defaultValue;
    ...
    ChannelCache[channelKey] = channelName;
    return channelName;
}
```

ソース: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L98-L141)

キャッシュ辞書は `private static readonly` であり、リポジトリにはキャッシュをクリアする公開 API が一切提供されていないため、**実行中に更新することはできません**。静的フィールドをドメイン/プロセスと一緒に再構築させるしかありません:

1. Editor の場合:Play Mode を終了 → コンパイル/ドメインリロードの完了を待つ → 再度 Play Mode に入って読み取る。
2. 実機/スタンドアロン版:アプリケーションプロセスを終了してから再起動する(キャッシュの問題のみ解決。設定自体がパッケージ内にある場合は、下記のセクションに従って再ビルドが必要)。

また、副作用として 1 点注意:Editor/PC の分岐では、初回読み取り時に `application_config.txt` 内の**すべての** `key=value` が一度にキャッシュへ書き込まれます([BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L107-L121) を参照)。そのため、ファイルを変更した後、別の channelKey で照会しても、取得できるのは初回ロード時の古い内容のままです。

### Editor/PC/WebGL:Resources を再ロードさせる

これらのプラットフォームで読み取られるのは `Resources.Load<TextAsset>("application_config")`、すなわち `Assets/Resources/application_config.txt` です:

1. ファイルパスが `Assets/Resources/application_config.txt` であることを確認する(拡張子がなくてもロード可能、内容は行ごとの `key=value`)。
2. 変更を保存した後、Unity ウィンドウをクリックして再インポートをトリガーする(またはファイルを右クリック → `Reimport`)。
3. 「プロセス内キャッシュのクリア」に従って Play Mode を再起動する。
4. ビルド済みパッケージ:ディスク上のファイル変更は無効であり、`Assets/Resources/application_config.txt` を変更して再ビルドする必要がある。

### Android:meta-data 変更後の再パッケージ化

Android のチャネルはネイティブクラスへの静的呼び出しから取得され、初回の結果は同様にキャッシュに入ります:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

ソース: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

AndroidManifest.xml の該当する meta-data を変更した後は、APK/AAB を再ビルドして上書きインストールする必要があります。プロセス内で自動的に更新されることはありません。

### iOS:PostProcessBuild の「設定スキップ」への対処

iOS のビルド後処理は、Info.plist に `channel` キーがない場合にのみ `default` を書き込み、既存の値がある場合はそのままスキップします:

```csharp
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

ソース: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

チャネル値を変更したい場合は:Xcode プロジェクトの Info.plist で `channel` キーを直接変更または削除し(削除した場合はこの処理ロジックによって再度書き込まれます)、実機へ再ビルドしてください。また、ネイティブ層のデフォルト戻り値は `unknown` である点に注意してください:

```objc
char * getChannelName(char * channel_name) {
    NSString* channel_name_String=  [NSString stringWithUTF8String:channel_name];
    NSString* File = [[NSBundle mainBundle] pathForResource:@"Info" ofType:@"plist"];
    NSMutableDictionary* dict = [[NSMutableDictionary alloc] initWithContentsOfFile:File];
    NSString * channel_value =  [dict objectForKey:channel_name_String];
    if (channel_value != nil) {
        return StringToCharArray(channel_value);
    }
    channel_value = @"unknown";
    return StringToCharArray(channel_value);
}
```

ソース: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

### 値が切り詰められる:設定行の形式を確認

解析ロジックでは、各行を `=` で分割した後、2 番目のセグメントのみを取得して `Trim()` を行います:

```csharp
var split = line.Split(new string[] { "=" }, StringSplitOptions.RemoveEmptyEntries);
if (split.Length > 1)
{
    var key = split[0].Trim();
    var channelValue = split[1].Trim();
    ChannelCache[key] = channelValue;
}
```

ソース: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120)

`channel=a=b` は `a` と解析されます。値から `=` を取り除く(または別の区切り文字によるエンコード方式に変更する)した後、「プロセス内キャッシュのクリア」に従って再起動して検証してください。

## 検証

1. 設定を変更して Play Mode を再起動 / 再パッケージ化した後、以下を呼び出します:

```csharp
string channel = BlankGetChannel.GetChannelName();
string subChannel = BlankGetChannel.GetChannelName("sub_channel", "unknown");
```

ソース: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

2. 戻り値が設定ファイルの新しい値と一致していることを確認します。iOS ではキーが欠落している場合、`unknown` が返されることを確認してください(C# のデフォルト引数 `default` ではありません)。
3. 依然として古い値の場合、まずキャッシュがクリアされていないことを疑い(Play Mode / プロセスの再起動)、次に、読み取っているのが自分が思っている設定ではないことを疑ってください(Editor では `Assets/Resources/application_config.txt`、Android では manifest の meta-data、iOS では Info.plist を確認)。
