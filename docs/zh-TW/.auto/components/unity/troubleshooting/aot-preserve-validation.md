# AOT 保留校驗報錯怎麼辦

當你在 CI 裡執行 `AotPreserveValidationRunner.ValidateGeneratedFiles()`,或在 Unity 選單觸發 HybridCLR AOT 保留生成時,如果生成檔案缺失、與當前配置不一致,或生成目錄裡有陳舊檔案,就會出現報錯。本頁給出常見錯誤資訊的診斷表與對應修復步驟。

## 快速診斷

| 症狀(異常訊息原文) | 原因 | 修復 |
|------|------|------|
| `Generated file is missing: Assets/Generated/AotPreserve/link.xml` | `Assets/Generated/AotPreserve/` 目錄或 `link.xml` 不存在 | 重新執行生成選單,見下文"修復步驟 1" |
| `Generated file is out of date: Assets/Generated/AotPreserve/...` | 配置改了,但生成的 `link.xml`/引用程式碼/asmdef/報告還沒重新整理 | 重新執行生成,見下文"修復步驟 1" |
| `Generated file is stale: Assets/Generated/AotPreserve/...` | 生成目錄裡殘留了配置已經移除的舊檔案 | 重新執行生成(會自動清空目錄),見下文"修復步驟 1" |
| `Preserve type entry is null.` | 在 `IAotPreserveSettingsProvider` 的 `PreserveTypes`/`WrapTypes`/`PreserveGenericTypes` 裡塞了 `null` 元素 | 檢查配置程式碼,去掉 null 項,見"修復步驟 2" |
| `Preserve generic type entry is null.` | 同上,發生在 `PreserveGenericTypes` | 同上 |
| `Preserve member entry is null.` | `PreserveMembers` 陣列裡有 null 字串 | 檢查配置,見"修復步驟 2" |
| `Hotfix AOT preserve generation failed: ...` | `GenerateAndWrite()` 在生成階段就偵測到錯誤(例如上面幾類) | 展開異常裡的每一行,逐條按本表修復 |
| 校驗通過 `ValidateGeneratedFiles()` 返回空陣列卻仍報 `InvalidOperationException` | 幾乎不會發生;若出現,把異常 `Message` 完整貼出來排查 | 收集異常 `Message` 全文回饋 |

異常拋出位置見 [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27),錯誤訊息拼接邏輯見 [`AotPreserveGenerator.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L103-L122)。

## 修復步驟

### 1. 重新生成 AOT 保留檔案

絕大多數"missing/out of date/stale"類報錯,直接重新生成即可。

1. 在 Unity 選單列點擊 **GameFrameX → HybridCLR Generate AOT Preserve**(選單常數見 [`AotPreserveConstants.MenuPath`](/src/Editor/AotPreserve/AotPreserveConstants.cs#L65))。
2. 等待控制檯無報錯。生成器會先刪除整個 `Assets/Generated/AotPreserve/` 目錄,再寫入:
   - `Assets/Generated/AotPreserve/link.xml`
   - `Assets/Generated/AotPreserve/aot_preserve_report.md`
   - `Assets/Generated/AotPreserveReferences.cs`
   - `Assets/Generated/AotPreserve.Generated.asmdef`
   - 按型別拆分的 `AotPreserveReference_*.cs` 系列引用佔位檔案
3. CI 場景下,改用程式碼入口:

```csharp
using GameFrameX.Editor;
AotPreserveGenerator.GenerateAndWrite();
```

寫入邏輯與失敗時的異常見 [`AotPreserveGenerator.GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L94):如果 `result.HasErrors` 為 true,會先拋 `InvalidOperationException("Hotfix AOT preserve generation failed:\n...")`,再繼續後面的磁碟操作;如果磁碟寫入失敗,會拋 `IOException` 或 `UnauthorizedAccessException`。

### 2. 清理配置裡的 null 條目

當異常訊息以 `Preserve type entry is null.`、`Preserve generic type entry is null.`、`Preserve member entry is null.` 開頭時,說明你自訂實作的 `IAotPreserveSettingsProvider` 裡返回了含 `null` 元素的陣列。這些 null 會在分析階段被收集到 `AotPreserveAnalysis.Errors`,最終被校驗器作為錯誤訊息拋出。

修復方式:

1. 找到專案裡實作 [`IAotPreserveSettingsProvider`](/src/Editor/AotPreserve/IAotPreserveSettingsProvider.cs) 的類別(預設實作見 [`DefaultAotPreserveSettingsProvider`](/src/Editor/AotPreserve/DefaultAotPreserveSettingsProvider.cs),由 [`AotPreserveSettingsProviderResolver`](/src/Editor/AotPreserve/AotPreserveSettingsProviderResolver.cs) 解析)。
2. 在返回 `PreserveTypes` / `WrapTypes` / `PreserveGenericTypes` / `PreserveMembers` 之前過濾掉 `null`。
3. 重新執行生成與校驗。

### 3. 清理殘留的陳舊檔案

如果你看到 `Generated file is stale: <路徑>`,通常是上一次生成產出的檔案、但本次配置已經不再需要它。直接重新執行生成選單即可——[`GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L80-L84) 會先 `Directory.Delete(GeneratedDirectory, true)` 再重建。

不要手動改 `Assets/Generated/AotPreserve/` 下任何檔案——它們是生成產物,下次生成會被覆蓋。

## 驗證

修復後,在 CI 或本地用以下任一方式確認通過:

- 程式碼入口:

```csharp
using GameFrameX.Editor;
AotPreserveValidationRunner.ValidateGeneratedFiles(); // 不拋異常即通過
```

實作見 [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27):內部呼叫 `AotPreserveGenerator.ValidateGeneratedFiles()`,把全部錯誤以換行符號拼接後拋 `InvalidOperationException`。

- 直接呼叫生成器校驗入口:

```csharp
var errors = AotPreserveGenerator.ValidateGeneratedFiles();
// errors.Length == 0 即通過
```

返回陣列為 0 時表示所有生成檔案齊全且與配置一致;不為 0 時,陣列裡的每條字串就是一條獨立的錯誤,按上文診斷表逐條處理。
