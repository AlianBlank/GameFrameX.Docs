# 플레이어 보상(Reward) 모듈 구현

이 페이지에서는 플레이어 Actor에서 `RewardGrantComponentAgent.GrantAsync`를 사용하여 보상을 통합 지급하는 방법을 설명하며, 호출 전제 조건, 요청/결과 구조, 라우팅 규칙 및 멱등 원장 동작을 다룹니다.

## 전제 조건

- 대상 플레이어 Actor가 온라인 상태이며, `RewardGrantComponent`는 프레임워크가 `[ComponentType(GlobalConst.ActorTypePlayer)]`에 따라 자동으로 부착하므로 수동 등록이 필요 없습니다.
- `TbItemConfig` 아이템 테이블 설정(`GameFrameX.Config.Tables`)이 이미 존재하며, 일반 아이템 라우팅은 `ConfigComponent.Instance.GetConfig<TbItemConfig>().TryGet(...)`로 `ItemId` 존재 여부를 검증합니다.
- 호출자는 플레이어 Actor를 해석할 수 있는 서버 측 컨텍스트에 위치해야 합니다(예: 핫업데이트 계층 `GameFrameX.Hotfix.Logic.Player.Reward` 네임스페이스의 코드).
- `BagComponentAgent`가 준비되어 있으며, 일반 아이템 지급은 최종적으로 `BagComponentAgent.UpdateChanged(...)`를 호출하여 가방에 기록합니다(온라인 시 push notify, 오프라인 시 영속화만 수행).

## 작업 단계

1. **`RewardGrantRequest`를 구성합니다.** `RoleId`는 반드시 대상 플레이어의 `ActorId`여야 하며, `SourceType` / `SourceId` / `TraceId` 세 값이 함께 유일성을 이루어 멱등 키 `RoleId:SourceType:SourceId:TraceId`를 구성합니다. `Rewards`는 지급할 항목 목록입니다.

   ```csharp
   using GameFrameX.Apps.Player.Reward.Entity;

   var request = new RewardGrantRequest
   {
       RoleId    = playerActorId,
       SourceType = RewardSourceType.Mail,            // 비즈니스 출처, None 금지
       SourceId  = $"mail:{mailId}:attachment:{attachmentId}",
       TraceId   = Guid.NewGuid().ToString("N"),      // 고유 추적 번호
       Rewards   = new List<RewardItem>
       {
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1001, Count = 5 },
           new RewardItem { RewardType = RewardType.NormalItem, ItemId = 1002, Count = 1 },
       },
   };
   ```
   Source: [RewardGrantRequest.cs#L41-L67](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L41-L67)

2. **컴포넌트 에이전트를 통해 `GrantAsync`를 호출합니다.** 진입점은 `RewardGrantComponentAgent.GrantAsync`이며, `[Service]`로 표시되어 있어 동일 Actor 내의 다른 에이전트 컴포넌트나 상위 비즈니스에서 직접 await할 수 있습니다.

   ```csharp
   using GameFrameX.Hotfix.Logic.Player.Reward;

   var agent = await ActorManager.GetComponentAgent<RewardGrantComponentAgent>(playerActorId);
   var result = await agent.GrantAsync(request);
   ```
   Source: [RewardGrantComponentAgent.cs#L51-L91](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L51-L91)

3. **`RewardGrantResult`를 읽습니다.** `Items`는 항목별 성공/실패와 오류 코드를 제공하고, `AllSuccess`는 전체 성공 여부를 나타내며, `ErrorCode`는 전체 집계 코드입니다(`Ok` / `PartialSuccess` / 첫 번째 실패 항목의 오류 코드).

   ```csharp
   if (result.AllSuccess)
   {
       // 모든 보상이 가방에 기록되었거나 멱등 히트됨
   }
   else
   {
       foreach (var item in result.Items)
       {
           if (!item.Success)
           {
               // item.ErrorCode 값은 OperationStatusCode 참조
           }
       }
   }
   ```
   Source: [RewardGrantRequest.cs#L72-L89](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/Player/Reward/Entity/RewardGrantRequest.cs#L72-L89)

4. **필요에 따라 라우팅을 확장합니다.** 1단계에서는 `RewardType.NormalItem`만 실제로 처리됩니다(`BagState`에 기록). 나머지 유형(HiddenItem / MonthCard / LifetimeCard / VipPoint / Equity 등)은 `DispatchAsync`에서 `OperationStatusCode.Unsupported`를 반환하며 일반 가방을 오염시키지 않습니다. 새 유형을 추가할 때는 `DispatchAsync`의 `switch` 분기에 해당하는 하위 라우팅 구현을 추가하기만 하면 됩니다.
   Source: [RewardGrantComponentAgent.cs#L96-L172](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Reward/RewardGrantComponentAgent.cs#L96-L172)

## 일반적인 변형

- **운영 보상 / 교환 코드 / 이벤트 보상:** 비즈니스 출처가 다를 때는 `SourceType`과 `SourceId`의 조합 방식만 바꾸면 됩니다. `GrantAsync`가 유일한 자산 지급 진입점이므로 이를 우회하여 직접 가방에 기록하지 마세요.
- **오프라인 플레이어 보상 지급:** `BagComponentAgent.UpdateChanged(channel, ...)`는 `channel`이 비어 있을 때 영속화만 하고 notify를 푸시하지 않으므로, 비즈니스 측에서 별도의 분기 처리가 필요 없습니다.
- **요청에 확장 필드 포함:** `RewardItem.ExtraData`는 예약된 필드로, 현재 지급 흐름에서는 파싱하지 않지만 멱등 원장에 원본 그대로 영속화되며 이후 라우팅에서 읽을 수 있습니다.

## 일반적인 오류

| 증상 | 원인 | 회피 방법 |
|------|------|------|
| 전체 요청 `ErrorCode = Unsupported` | `RewardType`이 구현된 라우팅에 없음(`NormalItem` 제외 모두 미지원) | 1단계에서는 일반 아이템만 지급; 확장 전에 먼저 `DispatchAsync`에 라우팅 추가 |
| 개별 항목 `ErrorCode = InvalidReward` | `RewardItem.Count <= 0` | 호출 전 `Count > 0` 검증 |
| 개별 항목 `ErrorCode = NotFound` | `ItemId`가 `TbItemConfig`에 존재하지 않음 | 설정 테이블을 먼저 생성한 뒤 기획자가 데이터 입력 |
| 전체 `ErrorCode = Unprocessable` | 가방 컴포넌트 업데이트 실패(`bagState.IsNull()`) | `BagComponentAgent`와 플레이어 Actor 상태 확인 |
| 중복 지급 | 멱등 키 `RoleId:SourceType:SourceId:TraceId`가 유일하지 않음 | 동일한 비즈니스 건에서 세 필드를 안정적으로 유지, 재시도가 필요하면 `TraceId`를 그대로 재사용 |
