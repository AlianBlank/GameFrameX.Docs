# 如何實作跨伺服器 RPC 呼叫與統一訊息傳送

透過框架的 `IUnifiedMessageSender` 介面，業務層只需一行程式碼即可完成「本機直送 / 跨伺服器轉發 / 離線處理」的玩家訊息投遞，以及「服務探索 + 一致性路由 + 逾時重試」的跨伺服器 RPC 呼叫，無需感知底層協定。

## 前置條件

- 已引入 `GameFrameX.NetWork.RemoteMessaging` 組件，並在啟動階段呼叫 `UnifiedMessageSenderHolder.Initialize(...)` 以初始化傳送器。
- 目標玩家已透過 SessionManager / 路由解析器（`IPlayerRouteResolver`）建立路由。
- 訊息物件繼承自 `MessageObject`（請求-回應 RPC 的回應訊息還需實作 `IResponseMessage`）。

## 步驟

### 1. 啟動時初始化統一傳送器

業務層透過全域存取點 `UnifiedMessageSenderHolder.Sender` 取得 `IUnifiedMessageSender` 實例。框架已在 `AppStartUpHotfixGameByEntry` 中提供預設的組裝範例。

```csharp
// 框架預設組裝：僅依賴 SessionManager 的記憶體內路由狀態
var remoteClient = RemoteMessagingBuilder.BuildFromEnvironment();
UnifiedMessageSenderHolder.InitializeWithDefaults(
    new DefaultPlayerRouteResolver(),
    remoteClient);
```

若使用自訂元件（例如替換路由解析器或服務實例選擇器），也可以手動建構，並透過 `Initialize(IUnifiedMessageSender)` 注入。

### 2. 向目標玩家傳送訊息

`SendToPlayerAsync` 會自動按照「本機線上 → 本機投遞 → 路由解析 → 跨伺服器轉發 → 離線處理」的順序處理。業務層只需關心回傳結果。

```csharp
var sender = UnifiedMessageSenderHolder.Sender;

var msg = new NotifyFriendOnline
{
    FriendId = 10001,
    OnlineServerId = 3,
};

var result = await sender.SendToPlayerAsync(
    playerId: 10001,
    message: msg,
    options: new PlayerSendOptions
    {
        OfflineStrategy = PlayerOfflineStrategy.StoreOffline,
        TimeoutMs = 3000,
        AllowRetry = true,
        MaxRetryCount = 2,
    });

if (result.Status == PlayerDeliverStatus.RemoteDelivered)
{
    // 已透過跨伺服器轉發送達目標伺服器
}
```

`PlayerSendResult` 的 `Status` 欄位涵蓋了所有可能的投遞狀態（`LocalDelivered` / `RemoteDelivered` / `OfflineStored` / `Offline` / `RouteMissing` / `Cancelled` / `Failed`），可使用該列舉進行判斷。

### 3. 發起跨伺服器 RPC（請求-回應）

呼叫 `SendToServerAsync<TResp>` 時，框架會自動執行服務探索、實例選擇與一致性路由，並以 `ServerSendResult<TResp>` 的形式回傳結果。

```csharp
var req = new ReqQueryGuildMembers
{
    GuildId = 42,
    PageIndex = 1,
};

ServerSendResult<RespQueryGuildMembers> rpc =
    await sender.SendToServerAsync<RespQueryGuildMembers>(
        serviceName: GameServerConst.Guild.Name,
        message: req,
        options: new ServerSendOptions
        {
            TimeoutMs = 5000,
            AllowRetry = true,
            MaxRetryCount = 1,
        });

if (rpc.IsSuccess)
{
    // rpc.Response 即為 RespQueryGuildMembers
    foreach (var member in rpc.Response.Members) { /* ... */ }
}
else
{
    // rpc.StatusCode：EndpointNotFound / Timeout / Failed ...
}
```

底層所使用的「跨伺服器玩家轉發」內部協定定義於 `ReqSendToPlayerInner` / `RespSendToPlayerInner`，轉發時會附帶 `TargetPlayerId` 與原始的 `InnerMessage`。

### 4. 單向跨伺服器通知（無需回應）

當不需要回應時，可使用 `SendToServerOneWayAsync`：

```csharp
await sender.SendToServerOneWayAsync(
    serviceName: GameServerConst.Chat.Name,
    message: new NotifyServerKickPlayer { PlayerId = 10001 });
```

回傳的 `ServerSendResult.IsSuccess` 僅表示「訊息是否已成功送入傳送通道」，並不保證接收端已完成處理。

## 常見變化情境

- **同一玩家可能落在不同伺服器**：直接呼叫 `SendToPlayerAsync` 即可，業務層無需手動查詢路由。
- **需要「先到先得」的全域廣播**：使用 `SendToServerOneWayAsync` 傳送至目標服務名稱，由服務端的各個實例自行處理。
- **跨伺服器轉發失敗但已知玩家離線**：在 `PlayerSendOptions.OfflineStrategy` 上選擇 `StoreOffline`（暫存離線訊息）或 `Discard`（丟棄）；預設行為是以 `Offline` 回傳失敗。
- **需要追蹤結果**：傳送器持有 `MessageSendMetrics`，可從 `UnifiedMessageSenderHolder.Metrics` 取得聚合後的指標。

## 常見錯誤

| 症狀 | 原因 | 解決方式 |
|------|------|------|
| `UnifiedMessageSenderHolder has not been initialized. Call Initialize() first during startup.` | 啟動階段未呼叫 `Initialize` | 在 `AppStartUp` 或服務入口先呼叫 `InitializeWithDefaults(...)` |
| `Service name is empty` | `SendToServerAsync` 的 `serviceName` 傳入了空字串 | 使用 `GameServerConst.*.Name` 常數，而非手寫字串 |
| 狀態為 `RouteMissing` | `IPlayerRouteResolver` 未找到該玩家的路由 | 檢查 SessionManager / 登入流程是否已完成註冊 |
| 狀態為 `RemoteDelivered` 但接收端未處理 | 接收端尚未為對應訊息註冊 Handler | 確認該訊息類型已透過原始碼產生器註冊，詳情請見後台診斷頁面 |
| `Cross-server forwarding failed: ...` | 跨伺服器轉發拋出例外（網路 / 逾時） | 設定 `TimeoutMs` 與 `MaxRetryCount`，或在呼叫端使用 `try/catch` 作為後備處理 |

## 背景說明（選讀）

`UnifiedMessageSender` 在單一介面背後聚合了四件事：「本機 Session 投遞」、「玩家路由解析」、「跨伺服器 RPC 用戶端」與「服務實例選擇器」；業務層只需選定目標（`playerId` 或 `serviceName`）與策略（`OfflineStrategy` / `TimeoutMs` / `Retry`），路由與轉發的細節皆由框架處理。
