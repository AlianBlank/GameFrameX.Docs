# How to Implement a Custom Object Storage Provider

By implementing the two interfaces `IObjectStorageManager` and `IObjectStorageUploadManager` and integrating with `ObjectStorageUploadFactory`, you can add any new backend to the GameFrameX Object Storage framework (such as self-hosted MinIO, Huawei OBS, Qiniu, UpYun, internal file servers, etc.), allowing the upload process to be uniformly scheduled by the factory just like the built-in providers.

## Prerequisites

- The `com.gameframex.unity.objectstorage` package has been installed in the Unity project.
- The backend you are connecting to must have the four basic parameters: accessKey / secretKey / bucketName / endpoint, and be able to respond to the standard object storage protocol (multipart/upload/progress callback).
- Prepare an Editor assembly to hold the custom provider implementation (in an `.asmdef` under any `Editor/` directory) to avoid polluting the runtime.

## Steps

1. **Create the provider implementation class**, implementing both the `IObjectStorageManager` and `IObjectStorageUploadManager` interfaces. `IObjectStorageManager.Init` is used to receive credentials and bucket information, while `IObjectStorageUploadManager` handles the actual upload, multipart, and progress callback.

   ```csharp
   using GameFrameX.ObjectStorage.Editor;

   namespace GameFrameX.ObjectStorage.Editor
   {
       public sealed class MyCustomObjectStorageManager
           : IObjectStorageManager, IObjectStorageUploadManager
       {
           public void Init(string accessKey, string secretKey,
                            string bucketName, string endpoint = null)
           {
               // Save to internal fields for use by upload methods
           }

           // Implement the upload methods of IObjectStorageUploadManager ...
       }
   }
   ```

   The `IObjectStorageManager` interface definition is available at [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L1-L13). The `Init` method signature is as follows:

   ```csharp
   void Init(string accessKey, string secretKey, string bucketName, string endpoint = null);
   ```
   Source: [IObjectStorageManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageManager.cs#L12-L12)

2. **Implement the upload and progress callback logic**. Refer to the responsibility division of `BaseObjectStorageUploadManager`: the base class handles generic multipart, retry, and progress aggregation; your subclass only needs to replace the "auth header construction" and "multipart PUT/POST" with your own backend protocol. The base class entry point is at [BaseObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs).

3. **Register with the factory**. Open [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs) and add your provider type in the factory's creation/selection branch so that the factory can return an instance of your implementation based on configuration.

4. **Retrieve via the factory at the call site**. No changes are required on the upload side; simply obtain `IObjectStorageUploadManager` through `ObjectStorageUploadFactory`:

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create(providerName);
   ((IObjectStorageManager)uploader).Init(accessKey, secretKey, bucketName, endpoint);
   uploader.Upload(localPath, remoteKey, onProgress, onComplete);
   ```

## Common Variations

- **Same protocol, different vendors**: For example, AWS S3, Alibaba OSS, and Tencent COS are all S3-compatible. A single implementation class can support multiple `endpoint`s, distinguishing signature regions during `Init`.
- **Intranet storage without endpoint**: Leave `endpoint` empty and have the implementation construct the intranet address based on `bucketName`.
- **Multi-credential rotation**: Allow a list of credentials to be passed in `Init`, and automatically renew the token before multipart upload.

## Common Errors

| Error | Cause | Fix |
|------|------|------|
| The factory returns a built-in provider | Your type has not been registered with `ObjectStorageUploadFactory` | Add the new provider name in the factory selection branch |
| Upload returns 401/403 after `Init` | accessKey/secretKey does not match the endpoint region | Validate the region in `Init` and print the actual request URL |
| Progress stays at 0 forever | The implementation class does not convert the multipart callbacks into `IObjectStorageUploadManager` progress events | Refer to the progress aggregation points in `BaseObjectStorageUploadManager` |
| Unity runtime cannot find the type | The implementation class was placed in a runtime assembly instead of an Editor assembly | Place the code under any `Editor/` directory and ensure the `.asmdef` includes the `Editor` platform |

## Background (Optional)

The framework separates "credential management" and "upload execution" into two interfaces: `IObjectStorageManager` only handles credential initialization, while `IObjectStorageUploadManager` handles actual network multipart and progress; both are typically implemented by the same class. The factory selects an instance based on the provider name, which unifies the call entry point and makes it easy to replace backends.
