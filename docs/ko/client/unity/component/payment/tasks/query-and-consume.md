# 구매 기록 조회 및 구매 소비 방법

`PaymentComponent`를 통해 `QueryPurchases(PaymentProductType productType)`를 호출하여 현재 계정의 소비되지 않은 구매 기록을 가져오고, 결과는 `OnQueryPurchasesResult` 이벤트 콜백으로 반환됩니다. `PurchaseToken`을 받은 후 `ConsumePurchase(string purchaseToken)`을 호출하여 소비를 완료하며, 그 결과는 `OnConsumePurchaseResult` 이벤트 콜백으로 반환됩니다. 두 메서드 모두 비동기이며 반환값이 없고, 이벤트를 통해서만 결과를 얻을 수 있습니다.

## 사전 조건

- 씬에 `GameFrameX/Payment` 컴포넌트(`PaymentComponent`)가 추가되어 있고, 플랫폼에 따라 해당하는 `IPaymentManager` 구현이 자동으로 장착되어 있어야 합니다.
- `Init(bool isDebug = false, bool isClientVerify = true)`를 호출하여 초기화를 완료하고, `IsReady()`가 `true`를 반환한 후 조회를 시작해야 합니다.

## API 개요

| 이름 | 시그니처 | 설명 |
|------|------|------|
| 구매 기록 조회 | `void QueryPurchases(PaymentProductType productType)` | 제품 유형별로 소비되지 않은 구매 기록을 조회 |
| 구매 소비 | `void ConsumePurchase(string purchaseToken)` | 구매 토큰으로 구매 하나를 소비 |
| 조회 결과 이벤트 | `event EventHandler<PaymentEventArgs> OnQueryPurchasesResult` | 조회 완료(실패 포함) 시 트리거 |
| 소비 결과 이벤트 | `event EventHandler<PaymentEventArgs> OnConsumePurchaseResult` | 소비 완료(실패 포함) 시 트리거 |
| 준비 여부 | `bool IsReady()` | 결제 시스템 초기화 완료 여부 |

위 시그니처는 `IPaymentManager`에 정의되어 있습니다:

```csharp
/// <summary>
/// 구매 기록 조회 결과 이벤트
/// </summary>
event EventHandler<PaymentEventArgs> OnQueryPurchasesResult;

/// <summary>
/// 구매 소비 결과 이벤트
/// </summary>
event EventHandler<PaymentEventArgs> OnConsumePurchaseResult;

/// <summary>
/// 구매 기록 조회
/// </summary>
/// <param name="productType">제품 유형</param>
[UnityEngine.Scripting.Preserve]
void QueryPurchases(PaymentProductType productType);

/// <summary>
/// 구매 소비
/// </summary>
/// <param name="purchaseToken">구매 토큰</param>
[UnityEngine.Scripting.Preserve]
void ConsumePurchase(string purchaseToken);
```

## 작업 단계

1. 조회와 소비 두 결과 이벤트를 구독합니다. `PaymentComponent`의 이벤트는 내부 `IPaymentManager`로 직접 전달됩니다:

```csharp
public event EventHandler<PaymentEventArgs> OnQueryPurchasesResult
{
    add { _paymentManager.OnQueryPurchasesResult += value; }
    remove { _paymentManager.OnQueryPurchasesResult -= value; }
}

public event EventHandler<PaymentEventArgs> OnConsumePurchaseResult
{
    add { _paymentManager.OnConsumePurchaseResult += value; }
    remove { _paymentManager.OnConsumePurchaseResult -= value; }
}
```

Source: [PaymentComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentComponent.cs#L48-L64)

2. 초기화 후 준비 상태를 확인한 다음, 제품 유형에 따라 조회를 시작합니다:

```csharp
paymentComponent.Init(isDebug: false, isClientVerify: true);

if (paymentComponent.IsReady())
{
    // 제품 유형(인앱 구매 / 구독)별로 현재 계정의 소비되지 않은 구매 기록을 조회
    paymentComponent.QueryPurchases(productType);
}
```

3. `OnQueryPurchasesResult` 콜백에서 결과를 읽습니다. 성공 시 각 기록의 토큰은 `PaymentEventArgs.PurchaseToken`에 들어 있습니다:

```csharp
private void OnQueryPurchasesResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"查询购买记录失败: {e.ResultCode} {e.ErrorMessage}");
        return;
    }

    // 원본 구매 데이터(JSON 형식), 서버 검증에 넘길 수 있음
    // e.PurchaseData / e.ProductId / e.OrderId / e.PurchaseToken / e.CustomData
}
```

`PaymentEventArgs`의 전체 필드:

```csharp
public sealed class PaymentEventArgs : EventArgs
{
    public string ProductId { get; set; }      // 제품 ID
    public string OrderId { get; set; }        // 주문 ID
    public string PurchaseToken { get; set; }  // 구매 토큰
    public PaymentResultCode ResultCode { get; set; } // 결제 결과 코드
    public string ErrorMessage { get; set; }   // 오류 메시지
    public string PurchaseData { get; set; }   // 원본 구매 데이터(JSON 형식)
    public string CustomData { get; set; }     // 커스텀 데이터
}
```

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L30-L66)

4. (서버 검증 통과 후) 조회한 토큰으로 구매를 소비하고, `OnConsumePurchaseResult`에서 결과를 확인합니다:

```csharp
paymentComponent.ConsumePurchase(e.PurchaseToken);

private void OnConsumePurchaseResultHandler(object sender, PaymentEventArgs e)
{
    if (e.ResultCode != PaymentResultCode.Success)
    {
        Debug.LogError($"消耗购买失败: {e.ResultCode} {e.ErrorMessage}");
        return;
    }
    // 소비 완료, 아이템 지급/재지급 가능
}
```

## 일반적인 변형

- **연결 끊김 후 재접속/미처리 주문 보완**: 앱 시작 시 또는 포그라운드 복귀 시 먼저 `QueryPurchases`를 호출하여 `OnQueryPurchasesResult`로 반환된 소비되지 않은 기록을 순회하고, 검증을 통과한 후 하나씩 `ConsumePurchase`하면 누락된 주문의 재지급을 완료할 수 있습니다.
- **구독 상품**: 구독 유형 구매 역시 `QueryPurchases`로 조회하지만, 일반적으로 `ConsumePurchase`로 소비하지 않습니다(소비 의미는 일회성 소모형 상품에 해당). 소비 여부는 채널 구현에 따라 다릅니다.
- **서버 검증**: `Init` 시 `isClientVerify`를 `false`로 설정한 경우, 콜백의 `PurchaseData`와 `PurchaseToken`을 자체 서버로 보내 검증한 후 소비해야 합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| 호출 후 콜백이 전혀 발생하지 않음 | `OnQueryPurchasesResult` / `OnConsumePurchaseResult`를 구독하지 않은 채 호출함 | 이벤트를 먼저 구독한 후 조회/소비를 호출 |
| 로그에 `Pay Manager is invalid.`가 출력됨 | 플랫폼에 해당하는 `IPaymentManager` 구현 클래스를 찾을 수 없거나 장착되지 않음 | `PaymentComponent`의 각 플랫폼 구현 클래스 이름과 해당 채널 패키지가 제대로 포함되었는지 확인 |
| 조회/소비 콜백의 `ResultCode`가 `Failed` 또는 `NetworkError` | 채널 서비스 미연결 또는 네트워크 오류 | 잠시 후 재시도, `NetworkError`는 네트워크 복구 후 재조회 필요 |
| 소비 실패 `ItemNotOwned` | 토큰에 해당하는 구매가 이미 소비되었거나 존재하지 않음 | 다시 `QueryPurchases`하여 최신 토큰을 가져오고, 이전 값을 재사용하지 않음 |
| `VerifyFailed` | 구매 검증 실패(클라이언트 또는 서버 검증 실패) | 검증 로직과 증명 데이터를 확인하고, 검증 통과 후 소비 |

`PaymentResultCode`의 모든 값: `Success`, `Failed`, `Cancelled`, `NetworkError`, `ServiceUnavailable`, `ItemAlreadyOwned`, `ItemNotOwned`, `VerifyFailed`, `Unknown`.

Source: [PaymentEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.payment/blob/main/Runtime/PaymentEventArgs.cs#L14-L25)

## 검증

- `QueryPurchases`가 `OnQueryPurchasesResult`를 한 번 트리거하며, `ResultCode == PaymentResultCode.Success`입니다.
- `ConsumePurchase(token)`이 `OnConsumePurchaseResult`를 한 번 트리거하며, `ResultCode == PaymentResultCode.Success`입니다.
- 동일한 제품 유형으로 다시 조회하면 이미 소비된 해당 기록이 더 이상 반환되지 않습니다.

## 배경

`PaymentComponent`는 `Awake`에서 컴파일 플랫폼에 따라 구현 클래스를 선택합니다(Android는 `GooglePaymentManager`, iOS/Mac은 `ApplePaymentManager`, WebGL/PC는 각각 대응하는 구현 사용, 그 외 플랫폼은 `DefaultPaymentManager`로 폴백). 그다음 `GameFrameworkEntry.GetModule<IPaymentManager>()`를 통해 인스턴스를 가져오며, 이벤트와 메서드는 모두 해당 인스턴스에 대한 직접 전달입니다. `BasePaymentManager`의 `RaiseQueryPurchasesResult` / `RaiseConsumePurchaseResult`가 각 채널 구현의 결과를 위 이벤트로 분배하는 역할을 합니다. 결제 시스템의 전체 구조에 대해서는 개요 페이지를 참조하십시오.
