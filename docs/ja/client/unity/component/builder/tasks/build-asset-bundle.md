# Asset Bundle リソースのパッケージング方法

このページの手順に従って、GameFrameX のビルダーに [YooAsset](https://github.com/tuyoogame/YooAsset)  기반으로 프로젝트 리소스を Asset Bundle にパッケージさせ、설정 に従って增量ビルドの有効化、オブジェクトストレージへのアップロード、バージョン通知と企業 WeChat 通知を制御できます。

## 前提条件

- Unity エディタで対象プロジェクトが開かれており、本リポジトリの `com.gameframex.unity.builder` パッケージがインストールされていること。
- `YooAsset` と `GameFrameX.Editor`(本パッケージの依存関係)がインストールされており、`Builder.BuildAsset()` から `EBuildPipeline`、`AssetBundleCollectorSettingData`、`AssetBundleBuilderSetting` などの型を呼び出せること。
- YooAsset リソースコレクター(`AssetBundleCollectorSettingData`)に収集するリソースパッケージが設定済みであること(未設定だとループで `Packages` が取得できません)。
- [Builder.BuildParamsParse](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs) を介して `_builderOptions` を渡すか、`Builder.BuildAsset()` を呼び出す前に自行 で値を代入しておくこと。

## 操作手順

1. エディタメニューまたは CI スクリプトから `Builder.BuildAsset()` を呼び出します。フレームワークはまずホットアップデート DLL と AOT コードをコピーし、すべての収集パッケージの `LocationToLower` を強制的に `true` に設定して、ファイル名の大文字小文字を区別しないようにします:

   ```csharp
   Debug.Log("BuildAsset Start Copy Hotfix Code");
   BuildHotfixHelper.CopyHotfixCode();
   AssetDatabase.Refresh();
   BuildHotfixHelper.CopyAOTCode();
   AssetDatabase.Refresh();

   foreach (var assetBundleCollectorPackage in AssetBundleCollectorSettingData.Setting.Packages)
   {
       assetBundleCollectorPackage.LocationToLower = true;
   }
   AssetBundleCollectorSettingData.SaveFile();
   ```

   出典: [Builder.BuildAsset.cs#L17-L37](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L17-L37)

2. ビルドパイプラインを選択します。選択可能な値は `ScriptableBuildPipeline`、`RawFileBuildPipeline`(一致しない場合は `BuiltinBuildPipeline` にフォールバック)で、`_builderOptions.BuildPipeline` を通じて渡します:

   ```csharp
   if (!Enum.TryParse(typeof(EBuildPipeline), _builderOptions.BuildPipeline, true, out var buildPipelineObj))
   {
       Debug.LogError($"無効なビルドパイプラインタイプ: {_builderOptions.BuildPipeline}、選択可能な値: {string.Join(", ", Enum.GetNames(typeof(EBuildPipeline)))}");
       return;
   }
   ```

   出典: [Builder.BuildAsset.cs#L40-L64](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L64)

3. `BuildParameters` を準備します。このステップでビルドモード(BuildMode / ForceRebuild)、ターゲットプラットフォーム、バージョン番号、ファイル名スタイル、出力ルートディレクトリ、内蔵コピーディレクトリ、共有パッケージルールを有効にするかどうかなどを一括設定します:

   ```csharp
   buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage ? EBuildMode.IncrementalBuild : EBuildMode.ForceRebuild;
   buildParameters.BuildTarget = EditorUserBuildSettings.activeBuildTarget;
   buildParameters.PackageVersion = string.IsNullOrWhiteSpace(_builderOptions.PackageVersion)
       ? DateTime.Now.ToString("yyyyMMddHHmmss")
       : _builderOptions.PackageVersion;
   buildParameters.VerifyBuildingResult = true;
   buildParameters.FileNameStyle = EFileNameStyle.HashName;
   buildParameters.BuildOutputRoot = AssetBundleBuilderHelper.GetDefaultBuildOutputRoot();
   buildParameters.BuildinFileRoot = AssetBundleBuilderHelper.GetStreamingAssetsRoot();
   buildParameters.PackageName = _builderOptions.PackageName;
   buildParameters.EnableSharePackRule = true;
   buildParameters.EncryptionServices = new EncryptionNone();
   ```

   出典: [Builder.BuildAsset.cs#L65-L94](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L65-L94)

4. ビルドを実行し例外を捕捉します。失敗した場合は `Environment.Exit(1)` で CI プロセスを即座に失敗させます:

   ```csharp
   bool isSuccess = false;
   try
   {
       pipeline.Run(buildParameters, true);
       isSuccess = true;
   }
   catch (Exception e)
   {
       Debug.LogException(e);
       Environment.Exit(1);
   }
   ```

   出典: [Builder.BuildAsset.cs#L95-L107](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L95-L107)

5. ビルド成功後、`_builderOptions` のスイッチに応じてリソースパッケージのアップロード、バージョン番号の更新、企業 WeChat 通知の送信を決定します。完全な `finally` ブランチは以下のとおりです:

   ```csharp
   if (isSuccess && _builderOptions.IsUploadAsset)
   {
       string savePath = $"Bundles/{PlayerSettings.applicationIdentifier}/{EditorUserBuildSettings.activeBuildTarget}/{Application.version}/{_builderOptions.ChannelName}/{_builderOptions.PackageName}/{buildParameters.PackageVersion}";
       string uploadPath = $"{buildParameters.BuildOutputRoot}/{buildParameters.BuildTarget}/{Application.version}/{buildParameters.PackageName}/{buildParameters.PackageVersion}";
   #if ENABLE_GAME_FRAME_X_OBJECT_STORAGE
       ObjectStorageUploadManager.SetSavePath(savePath);
       ObjectStorageUploadManager.UploadDirectory(uploadPath);
   #endif
   }
   if (_builderOptions.IsUpdateAssetPackageVersion)
   {
       BuilderUpdateAssetPackageVersionHelper.Run(buildParameters, _builderOptions);
   }
   ```

   出典: [Builder.BuildAsset.cs#L108-L143](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L108-L143)

## よくあるバリエーション

- **ビルドパイプラインの切り替え**: `_builderOptions.BuildPipeline` を変更します。`ScriptableBuildPipeline` / `RawFileBuildPipeline` を選択可能で、その他の値は `BuiltinBuildPipeline` になります。
- **強制フルビルド**: `IsIncrementalBuildPackage` を `false` に設定すると、ビルドモードが `EBuildMode.ForceRebuild` になります。
- **内蔵パッケージコピー戦略の制御**: `_builderOptions.BuildinFileCopyOption` を空のままにすると `ClearAndCopyAll` として処理され、それ以外の場合は `EBuildinFileCopyOption` 列挙型として解析されます。無効な値は直接 `return` します。
- **ログ/リソースのオブジェクトストレージへのアップロード**: コンパイルシンボルで `ENABLE_GAME_FRAME_X_OBJECT_STORAGE` および対応するサブモジュール(七牛/テンセント/Alibaba Cloud)を事前に有効化します。詳細は [Builder.cs#L27-L48](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L27-L48) を参照してください。
- **カスタムパッケージ名/バージョンの使用**: `_builderOptions.PackageName` と `_builderOptions.PackageVersion` を直接設定します。バージョン番号を空にすると自動的に `yyyyMMddHHmmss` で埋められます。

## よくあるエラー

| 症状(ソースコードのエラー原文) | 原因 | 修正方法 |
|---|---|---|
| `無効なビルドパイプラインタイプ: {xxx}` | `_builderOptions.BuildPipeline` の文字列が `EBuildPipeline` として解析できない | 列挙名で値を渡す:`BuiltinBuildPipeline` / `ScriptableBuildPipeline` / `RawFileBuildPipeline` |
| `無効な内蔵ファイルコピーオプション: {xxx}` | `_builderOptions.BuildinFileCopyOption` が `EBuildinFileCopyOption` の列挙値ではない | 有効な列挙名を使用するか、空のままにしてデフォルトの `ClearAndCopyAll` にする |
| ビルド後プロセスが即座に終了コード `1` で終了し、コンソールに例外がスローされる | `pipeline.Run` が例外をスローし、catch 後に `Environment.Exit(1)` が呼ばれる | `Debug.LogException(e)` のスタックトレースを確認して YooAsset 設定またはコレクターを修正し、再実行する |
| `Builder.BuildAsset()` 開始時に `Packages` リストが空 | YooAsset リソースコレクター(`AssetBundleCollectorSettingData`)が未設定 | まず YooAsset ツールバーで収集パッケージを追加してからビルドを実行する |

## 背景(オプション)

`Builder.BuildAsset()` は YooAsset の上で 3 つのことを行います:① ホットアップデート DLL と AOT コードをコピーする;② 収集パッケージのパスを強制的に小文字に変換し、Linux/Android での大文字小文字の違いによるパッケージング失敗を回避する;③ 対応する `IBuildPipeline`(`BuiltinBuildPipeline` など)を呼び出してマニフェストを生成し、`_builderOptions` に基づいてアップロードとバージョン通知を実行するかどうかを判断する。`EnableSharePackRule = true` により、リソースを共有パッケージとしてパッケージングでき、初期パッケージの容量を削減できる。暗号化インターフェースはデフォルトで `EncryptionNone` ですが、呼び出し前に自行 で `buildParameters.EncryptionServices` を置き換えることができます。
