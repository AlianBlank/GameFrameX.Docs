# ファクトリを使用してアップロードマネージャーを作成する方法

`ObjectStorageUploadFactory.Create<T>` 静的メソッドを使用すると、`IObjectStorageUploadManager` インターフェース型に基づいて**初期化済み**のアップロードマネージャーインスタンスを迅速に取得できます。手動で `new` したり `Init` を呼び出したりする必要はありません。

## 前提条件

- `GameFrameX.ObjectStorage.Editor` 名前空間を参照する
- `IObjectStorageUploadManager` インターフェースを実装した具象クラス `T` がすでに存在する（[BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs) を直接継承できます）
- オブジェクトの `accessKey`、`secretKey`、`bucketName` を用意する。オブジェクトストレージがカスタムアドレスを必要とする場合は、`endpoint` も用意する

## 操作手順

1. 名前空間を参照する。

   ```csharp
   using GameFrameX.ObjectStorage.Editor;
   ```

   出典: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L1-L25)

2. `Create<T>` 静的ファクトリメソッドを呼び出し、認証情報を渡して初期化済みのマネージャーを取得する。

   ```csharp
   var uploader = ObjectStorageUploadFactory.Create<MyObjectStorageUploadManager>(
       accessKey: "your-access-key",
       secretKey: "your-secret-key",
       bucketName: "your-bucket",
       endpoint: null
   );
   ```

   ファクトリ内部では次の 2 つの操作が実行されます:

   ```csharp
   var manager = Activator.CreateInstance<T>();
   manager.Init(accessKey, secretKey, bucketName, endpoint);
   return manager;
   ```

   出典: [ObjectStorageUploadFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/ObjectStorageUploadFactory.cs#L19-L24)

3. （オプション）アップロードの保存先パスを設定する。

   ```csharp
   uploader.SetSavePath("assets/uploads/");
   ```

   出典: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L9)

4. アップロードメソッドを呼び出して、単一ファイルまたはディレクトリ全体をアップロードする。

   ```csharp
   bool ok = uploader.UploadFile("D:/build/asset.bundle");
   uploader.UploadDirectory("D:/build");
   ```

   出典: [IObjectStorageUploadManager.cs](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L15-L21)

## 主要シグネチャ早見表

| メンバー | シグネチャ | 説明 |
|------|------|------|
| `ObjectStorageUploadFactory.Create<T>` | `static IObjectStorageUploadManager Create<T>(string accessKey, string secretKey, string bucketName, string endpoint = null) where T : IObjectStorageUploadManager` | `Activator.CreateInstance<T>()` でインスタンスを作成し、直ちに `Init` を呼び出す |
| `IObjectStorageUploadManager.SetSavePath` | `void SetSavePath(string savePath)` | オブジェクトストレージにアップロードする保存先パスを設定する（末尾の区切り文字は自動的に削除される） |
| `IObjectStorageUploadManager.UploadFile` | `bool UploadFile(string localFilePathAndName)` | 単一ファイルをアップロードし、成功時は `true` を返す |
| `IObjectStorageUploadManager.UploadDirectory` | `void UploadDirectory(string localDirectory)` | ディレクトリ全体をアップロードする |

## よくあるバリエーション

- **endpoint を渡さない**: アドレスを必要としないオブジェクトストレージの場合、`endpoint` は空のままで問題ありません。パラメータの既定値は `null` なので、明示的に渡す必要はありません。
- **カスタム実装クラス**: [BaseObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/BaseObjectStorageUploadManager.cs) を直接継承しない場合でも、クラスが `IObjectStorageUploadManager` を実装していれば `T` として渡せます。ただし、`Init`、`UploadDirectoryInternal`、`UploadFileInternal` を自分で実装する必要があります。

## よくあるエラー

- **インターフェースを実装せずに渡す**: `T` が `IObjectStorageUploadManager` を実装していない場合、コンパイラが `where T : IObjectStorageUploadManager` の箇所で直接エラーを報告します。
- **二重初期化**: ファクトリはすでに `Init` を呼び出しているため、手動で再度呼び出す必要はありません。呼び出した場合、設定済みの認証情報が上書きされる可能性があります。
- **`endpoint` の誤った指定**: 一部のオブジェクトストレージはリクエストアドレスの構築に `endpoint` を使用するため、誤った値を渡すとアップロードが失敗します。不要な場合は `null` のままにしてください。

## 背景

ファクトリパターンは「インスタンス作成 + 初期化」を 1 ステップにカプセル化し、呼び出し側は認証情報の指定と最終的なインターフェースのみを考慮すればよいため、具体的な実装クラスへの直接的な依存を回避できます。全体のアーキテクチャについては、『概要』を参照してください。
