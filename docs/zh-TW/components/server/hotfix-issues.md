# 熱重載載入失敗或版本不符時的處理方式

當伺服器啟動或觸發熱重載時，載入熱更新 DLL（`GameFrameX.Hotfix.dll`）、版本驗證或執行階段初始化的失敗，通常會表現為處理程序直接結束、日誌中擲回例外，或用戶端／管理工具回報版本不符。本頁提供典型症狀與修復步驟的快速參考。

## 快速診斷

| 症狀 | 原因 | 修復方式 |
|------|------|------|
| `ArgumentException: dllPath` 或 `hotfixDllName` 因空值／空字串被擲回 | 傳入的 `dllPath` 或 `hotfixDllName` 是空字串 | 以預設值傳入參數；請參閱「修復步驟 - 路徑與檔案名稱」 |
| 找不到 `GameFrameX.Hotfix.dll`，檔案不存在 | DLL 未複製到執行目錄，或版本目錄與實際目錄不符 | 將 DLL 放置於對應 `dllVersion/dllPath` 的目錄 |
| 載入時回報 `OnLoadSuccess` 回傳 false | 熱更新橋接實作初始化失敗（依賴的服務未啟動、缺少設定等） | 檢查啟動順序與 `AppSetting` 是否完整 |
| 用戶端提示「版本不符」 | `dllVersion` 參數所指向目錄中的 DLL 與框架版本不一致 | 以相同原始碼重新建置熱更新專案並覆寫 DLL |
| 熱重載後仍參照舊模組導致找不到類別 | 重載期間舊模組被並行請求命中，且代理型別已切換 | 等到 `DoingHotfix=false` 後再進行壓力測試或查看日誌 |
| 重啟服務時間歇性出現 `HotfixAssembly` 為 null | 啟動順序中在 `LoadHotfix` 之前就呼叫了 `HotfixManager.HotfixAssembly` | 確認在存取該組件之前已先呼叫 `LoadHotfix` |

## 修復步驟

### 路徑與檔案名稱

`HotfixManager.LoadHotfix` / `LoadHotfixModule` 會對 `dllPath` 與 `hotfixDllName` 進行空值／空字串驗證，並依據 `dllVersion` 是否為空來決定實際載入的子目錄。

- 預設參數：`dllPath="hotfix"`、`hotfixDllName="GameFrameX.Hotfix.dll"`、`dllVersion=""`。
- 當 `dllVersion` 不為空時，`dllPath` 會被忽略，DLL 改從帶版本號的子目錄載入。

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
public static bool LoadHotfix(AppSetting setting,
    string dllVersion = "",
    string dllPath = "hotfix",
    string hotfixDllName = "GameFrameX.Hotfix.dll")
{
    ArgumentException.ThrowIfNullOrEmpty(dllPath, nameof(dllPath));
    ArgumentException.ThrowIfNullOrEmpty(hotfixDllName, nameof(hotfixDllName));
    // ...
    var path = Path.Combine(Environment.CurrentDirectory,
        string.IsNullOrEmpty(dllVersion) ? dllPath : $"{dllVersion}",
        hotfixDllName);
    var hotfixModule = new HotfixModule(path);
    var reload = _module != null;
    var success = hotfixModule.Init(reload);
    if (!success) { return false; }
    _module = hotfixModule;
    return true;
}
```

原始碼：[HotfixManager.cs#L95-L116](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L95-L116)

操作步驟：

1. 確認 `hotfix/GameFrameX.Hotfix.dll`（或 `<dllVersion>/GameFrameX.Hotfix.dll`）確實存在於執行目錄中。
2. 不要手動為 `dllPath` 傳入空字串；若使用版本目錄，請將 `dllVersion` 設為版本字串，並保持 `dllPath` 為預設值。
3. 若自訂了 DLL 名稱，請確保 `hotfixDllName` 與建置輸出一致。

### 版本號與 DLL 不符

當 `dllVersion` 所指向目錄中的 DLL 與框架宿主版本不一致時，可能會出現「載入成功但行為不正確」，或因介面簽章不符而引發的 `MissingMethodException`。

1. 刪除舊版本目錄，並依據目前的 `main` 分支重新建置 `GameFrameX.Hotfix` 專案。
2. 將新的 DLL 複製到目標 `dllVersion` 目錄（例如 `1.0.0/GameFrameX.Hotfix.dll`），並與宿主處理程序所指向的版本號保持一致。
3. 啟動伺服器，並在日誌中確認 `ReloadTime` 已更新（表示新模組已完成初始化）。

`ReloadTime` 由 `LoadHotfixModule` 在內部刷新：

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
private static async Task<bool> Load(HotfixModule newModule, AppSetting setting, bool reload)
{
    ReloadTime = TimerHelper.GetNowWithUtc();
    if (reload)
    {
        // ... 舊模組延遲 10 分鐘後再 Unload
    }
    _module = newModule;
    if (_module.HotfixBridge != null)
    {
        return await _module.HotfixBridge.OnLoadSuccess(setting, reload);
    }
    return true;
}
```

### `OnLoadSuccess` 回傳 False

載入成功後，熱更新橋接介面會呼叫 `OnLoadSuccess`。若回傳 `false`，會被視為載入失敗。

```csharp
// GameFrameX.Core/Hotfix/IHotfixBridge.cs
Task<bool> OnLoadSuccess(AppSetting setting, bool reload);
```

原始碼：[IHotfixBridge.cs#L45](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/IHotfixBridge.cs#L45)

操作步驟：

1. 開啟 `GameFrameX.Hotfix/StartUp/AppStartUpHotfixGameByEntry.cs`（或 `ByMain` / `ByHeart`），檢視 `OnLoadSuccess` 的實作，找出第一個失敗的相依項。
2. 確認其依賴的服務（如資料庫、Redis、HTTP 註冊）在被呼叫之前已完成初始化。
3. 在 `OnLoadSuccess` 內為每個步驟加入更詳細的日誌，再次觸發熱重載，並依據新日誌定位失敗點。

### 重載期間的並行請求

重載期間，`HotfixManager` 會將舊模組快取最多 10 分鐘。在此期間，新舊模組會依「請求來自哪個組件」分別路由。若舊模組已被 `Unload`，代理查詢將會失敗。

```csharp
// GameFrameX.Core/Hotfix/HotfixManager.cs
if (reload)
{
    var oldModule = _module;
    DoingHotfix = true;
    var oldModuleHash = oldModule.GetHashCode();
    OldModuleMap.TryAdd(oldModuleHash, oldModule);
    _ = Task.Run(async () =>
    {
        await Task.Delay(TimeSpan.FromMinutes(10));
        OldModuleMap.TryRemove(oldModuleHash, out _);
        oldModule.Unload();
        DoingHotfix = !OldModuleMap.IsEmpty;
    });
}
```

原始碼：[HotfixManager.cs#L158-L172](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Core/Hotfix/HotfixManager.cs#L158-L172)

操作步驟：

1. 在觸發熱重載後的 10 分鐘內，避免重啟伺服器或對舊模組所依賴的介面進行大規模壓力測試。
2. 若日誌顯示「找不到 Agent/Component 型別」，請檢查請求是來自舊模組組件（殘留的舊 DLL）還是新模組組件。
3. 確認舊的 `hotfix` 目錄已全部替換，避免在 `Environment.CurrentDirectory` 下出現多份 DLL。

## 驗證

1. 啟動伺服器。日誌顯示 `ReloadTime` 已寫入且沒有例外，表示新模組已生效。
2. 呼叫一次 `HotfixManager.GetAgent<T>(...)` 與 `GetComponentType(...)`，確認新模組的代理可正確解析。
3. 在重載情境下，觀察 `DoingHotfix` 旗標：應先為 `true`，並在 10 分鐘後舊模組釋放時降回 `false`。
4. 用戶端／管理工具的版本號與 `dllVersion` 子目錄相符，且登入與訊息收發運作正常。
