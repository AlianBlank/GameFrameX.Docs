# Can not create sound helper / sound group helper 怎么办

运行游戏时编辑器或运行时日志出现 `Can not create sound helper.` 或 `Can not create sound group helper.` 时,通常是 `SoundComponent` 在初始化阶段无法按 Inspector 配置的类型名/自定义组件创建出对应的辅助器。下文给出按症状定位并修复的完整流程。

## 快速诊断

| 错误日志原文 | 直接原因 | 修复入口 |
|--------------|----------|----------|
| `Can not create sound helper.` | `Helper.CreateHelper(m_SoundHelperTypeName, m_CustomSoundHelper)` 返回 `null` | 见下文「修复 Sound Helper」 |
| `Can not create sound group helper.` | `Helper.CreateHelper(m_SoundGroupHelperTypeName, m_CustomSoundGroupHelper, SoundGroupCount)` 返回 `null` | 见下文「修复 Sound Group Helper」 |
| 同时伴随 `Sound manager is invalid.` | `ISoundManager` 模块未注册 | 检查入口模块初始化,见下方说明 |

错误抛出处位于 `SoundComponent.cs`(行号以 `main` 分支为准):

```csharp
SoundHelperBase soundHelper = Helper.CreateHelper(m_SoundHelperTypeName, m_CustomSoundHelper);
if (soundHelper == null)
{
    Log.Error("Can not create sound helper.");
    return;
}
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L225-L230)

```csharp
SoundGroupHelperBase soundGroupHelper = Helper.CreateHelper(m_SoundGroupHelperTypeName, m_CustomSoundGroupHelper, SoundGroupCount);
if (soundGroupHelper == null)
{
    Log.Error("Can not create sound group helper.");
    return false;
}
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L328-L333)

## 修复步骤

### 1. 确认 Scene 上 SoundComponent 存在且脚本正确加载

`SoundComponent` 是框架入口,在场景里必须有一个挂载该组件的 GameObject。如果组件缺失或未执行 `Awake`,根本不会调用到上方两段代码,也就不会出现这两条日志——此时请先排查入口与 `ISoundManager` 注册流程。

### 2. 修复 Sound Helper(对应日志 `Can not create sound helper.`)

默认类型名配置(`SoundComponent.cs`):

```csharp
[SerializeField] private string m_SoundHelperTypeName = "GameFrameX.Sound.Runtime.DefaultSoundHelper";
[SerializeField] private SoundHelperBase m_CustomSoundHelper = null;
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L69-L71)

按以下顺序排查:

1. **未自定义时**:保持 `m_CustomSoundHelper` 为 `null`,`m_SoundHelperTypeName` 必须等于 `GameFrameX.Sound.Runtime.DefaultSoundHelper`,且该默认实现存在于打包程序集。
2. **自定义时**:把你继承 `SoundHelperBase` 的组件拖给 `m_CustomSoundHelper`(优先于反射);`m_SoundHelperTypeName` 必须填写该自定义类的**完整类型名**(含命名空间)。
3. **类型名写错 / 程序集被剥离**:IL2CPP 或代码剥离后反射失败。把对应类型加入 `link.xml` 保留,或把程序集放到不被裁剪的范围。

### 3. 修复 Sound Group Helper(对应日志 `Can not create sound group helper.`)

默认类型名配置:

```csharp
[SerializeField] private string m_SoundGroupHelperTypeName = "GameFrameX.Sound.Runtime.DefaultSoundGroupHelper";
[SerializeField] private SoundGroupHelperBase m_CustomSoundGroupHelper = null;
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L73-L75)

排查要点:

1. `m_SoundGroups` 必须有至少 1 个有效条目,否则不会调用 `AddSoundGroup`,自然也不会打印该日志——若你看到这条日志,说明 `AddSoundGroup` 已经走到了 helper 创建失败的分支。
2. 自定义时类型名应匹配继承 `SoundGroupHelperBase` 的子类完整名。
3. 默认实现 `DefaultSoundGroupHelper` 也可能因 helper 接口未注册而失败——优先保留框架默认类型名,确认默认实现可解析。

### 4. 检查资源与 AudioMixer

`EnsureAudioMixer()` 在 helper 创建前执行:

```csharp
m_AudioMixer = Resources.Load<AudioMixer>(DefaultAudioMixerResourceName);
```

Source: [SoundComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L140-L151)

虽然 mixer 缺失**不会**让 helper 创建失败(只会打 `Default audio mixer ... is missing.` 警告),但若你的自定义 helper 强依赖 `AudioMixerGroup`,请确保 Resources 下存在对应 mixer 资源。

## 常见变体

- **同时打印 `Can not create sound agent helper.`**:`m_SoundAgentHelperTypeName` / `m_CustomSoundAgentHelper` 配置错误,排查方式同上;触发点是 `AddSoundAgentHelper`(见 [SoundComponent.cs#L730-L735](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/Sound/SoundComponent.cs#L730-L735))。
- **运行时无报错但听不到声音**:helper 已建好,但后续 `Can not find sound 'X'` 抛出——见 `SoundManager.cs#L617` 的 `GameFrameworkException`,需要确认资源路径。

## 验证

1. 清理 `Library/` 后重新进入 Play 模式,确认日志中不再出现 `Can not create sound helper.` / `Can not create sound group helper.`。
2. 在 `SoundComponent` 上点 Inspector 的 `Add Sound Group` 或代码调用 `AddSoundGroup("Music", ...)`,返回 `true` 即表明 helper 创建链路正常。
3. 调用 `PlaySound` 播放一个存在的资源,观察是否触发 `OnPlaySoundSuccess`(对应事件定义于 [PlaySoundSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.sound/blob/main/Runtime/EventArgs/PlaySoundSuccessEventArgs.cs))。
