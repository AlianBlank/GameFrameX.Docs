# How to Handle the "Download manager is invalid" Error

When you launch the ImageCache component on a non-WebGL platform, if the log throws `Log.Fatal("Download manager is invalid.")`, it means `GameFrameworkEntry.GetModule<IDownloadManager>()` returned null, causing `ImageCacheComponent` to fail to inject the download manager into `ImageCacheManager`.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Download manager is invalid.` is thrown when starting the scene, and all image loading is invalid | The `IDownloadManager` module is not registered | Add a Download component that makes `GameFrameworkEntry.GetModule<IDownloadManager>()` available in the startup flow |
| This error does not occur on the WebGL platform but occurs on other platforms | Only the non-WebGL branch validates the download manager | Confirm that the build target is non-WebGL, and that the Download component has been attached |
| `LoadImageAsync` returns null with no other errors in the console | The download manager exists but was registered after `Awake` | Adjust the module initialization order to ensure the Download component's `Awake` runs before the ImageCache component's `Awake` |

## Fix Steps

### 1. Attach the Download Component

This error comes from the `Awake` validation in [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55-L64):

```csharp
#if !UNITY_WEBGL
            var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
            if (downloadManager == null)
            {
                Log.Fatal("Download manager is invalid.");
                return;
            }

            ((ImageCacheManager)_imageCacheManager).SetDownloadManager(downloadManager);
#endif
```

Whenever `IDownloadManager` is not registered, `Log.Fatal` is immediately called here and the method returns. The subsequent `SetDownloadManager` will not be executed, and all `LoadImageAsync` calls will fail.

Steps:

1. Open the startup scene (usually the `Bootstrap` / `Launch` scene).
2. Add the Download component (provided by the `GameFrameX.Download` package) to the same `GameFramework` entry object (or its child object).
3. Run the scene and confirm that the console no longer prints `Download manager is invalid.`.

### 2. Ensure the Module Registration Order

`ImageCacheComponent.Awake` actively retrieves the module from `GameFrameworkEntry`:

```csharp
_imageCacheManager = GameFrameworkEntry.GetModule<IImageCacheManager>();
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
```

If the Download component's `Awake` runs after the ImageCache component's, the module table seen by the latter will not yet contain `IDownloadManager`, and the validation will fail.

Steps:

1. Adjust the component order in the Inspector so that the Download component appears before the ImageCache component (Unity executes `Awake` in the order components are added).
2. Alternatively, use code to manually control initialization: instantiate the Download module first during `Start` / a custom initialization phase, then activate ImageCache.

### 3. Check the Build Platform

The error block is wrapped in `#if !UNITY_WEBGL` ([ImageCacheComponent.cs#L55](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55)). On the WebGL platform, the download manager branch is not taken, so this error will not appear on WebGL. If you do see the same string on WebGL, please confirm whether the macro is misspelled or non-WebGL resources have been imported.

## Verification

- After starting the scene, `Download manager is invalid.` no longer appears in the console.
- Call `ImageCacheComponent.LoadImageAsync(url)` and the image returns a normal `Texture2D` (or a cache hit).
- Place a breakpoint on the ImageCache component reference. You can see that `ImageCacheManager._downloadManager` is not null (see [ImageCacheManager.cs#L56-L61](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheManager.cs#L56-L61)).
