# 查询定时器状态:剩余时间、已过时间与剩余次数

用定时器 ID 调用 `GetRemaining` / `GetElapsed` / `GetRepeatLeft` 即可查询当前状态,配合 `IsPaused` / `Exists` 可进一步判断定时器是否存活或暂停。三个查询接口在定时器不存在时统一返回 `-1`。

## 前置条件

- 场景中已有可用的 `TimerComponent`(它内部封装 `ITimerManager` 的同名方法)。
- 手里握有创建定时器时返回的定时器 ID(`Add` 系列方法的返回值)。

## 查询接口一览

| 方法 | 签名 | 返回值 |
|------|------|--------|
| 剩余时间 | `float GetRemaining(int id)` | 剩余秒数;定时器不存在返回 `-1` |
| 已过时间 | `float GetElapsed(int id)` | 已累积秒数;定时器不存在返回 `-1` |
| 剩余次数 | `int GetRepeatLeft(int id)` | 剩余重复次数(`0` 表示无限循环);定时器不存在返回 `-1` |
| 是否暂停 | `bool IsPaused(int id)` | 暂停中返回 `true`,否则 `false` |
| 是否存在 | `bool Exists(int id)` | 存活返回 `true`,否则 `false` |
| 标签查询 | `bool HasTag(string tag)` | 该标签下存在至少一个定时器返回 `true` |

以上签名来自接口定义与组件包装层:

## 操作步骤

1. 创建定时器并保存返回的 ID(例如 `int id = ...` 来自 `Add` 系列注册调用)。
2. 在需要刷新 UI 或逻辑的时机,通过持有的 `TimerComponent` 实例调用查询方法:
   - 倒计时显示用 `GetRemaining(id)`;
   - 进度条填充用 `GetElapsed(id)`(与总时长相除得到进度);
   - 次数显示用 `GetRepeatLeft(id)`。
3. 每次查询前建议先用 `Exists(id)` 判断定时器是否还在——定时器触发完毕被移除后,查询只会返回 `-1`。
4. 若定时器可能被 `Pause`/`PauseByTag` 暂停,再用 `IsPaused(id)` 区分"暂停中"与"已结束"。
5. 在 UI 上把 `-1` 当作"定时器已不存在"处理,避免直接显示负数。

## 常见变体

- **批量暂停后查询**:对同一标签的一组定时器调用 `PauseByTag(tag)` 后,`GetRemaining` 不会减少(暂停期间不累积时间),`IsPaused` 返回 `true`。恢复使用 `ResumeByTag(tag)`。
- **无限循环定时器**:`GetRepeatLeft` 返回 `0` 表示无限循环,不要把它当成"已结束"。
- **async/await 场景**:不查询状态而是直接等待时,可用 `WaitForSecondsAsync(seconds, cancellationToken)` 等异步方法,见 [TimerComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerComponent.cs#L221-L224)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `GetRemaining` 返回 `-1` | 定时器已被移除(触发完毕、`Remove`/`RemoveByTag` 调用过,或 ID 写错) | 先用 `Exists(id)` 判断;重新注册定时器 |
| 剩余时间"不走" | 定时器处于暂停状态 | 检查 `IsPaused(id)`,必要时 `Resume(id)` |
| `GetRepeatLeft` 返回 `0` 却仍有回调触发 | `0` 表示无限循环,不是结束 | 判断存在性请用 `Exists(id)` 而非次数 |
| 显示出负数 | 直接把 `-1` 当作秒数渲染 | 在 UI 层把 `-1` 映射为"已结束/不存在" |

## 验证

单元测试仓库中已有 `GetRemaining_ReturnsCorrectValue` 等用例([UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Tests/UnitTests.cs#L619)),可在 Unity Test Runner 中运行确认查询行为。自行验证时,注册一个 5 秒定时器,连续两帧读取 `GetElapsed` 应递增、`GetRemaining` 应递减。

## 背景(可选)

内部每个定时器记录在 `TimerManager` 的私有 `Timer` 类中,其中 `Elapsed` 字段持续累积经过时间;查询接口即基于该内部数据计算剩余值([TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L21-L22))。`TimerComponent` 只是 `ITimerManager` 的薄包装层,两个入口的查询结果一致。
