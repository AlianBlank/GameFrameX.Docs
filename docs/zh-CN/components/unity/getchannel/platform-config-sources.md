## 各平台配置示例

**Android** — 在主启动 Activity 内声明 `meta-data`(该 Activity 即 Java 侧的 `com.alianhome.getchannel.MainActivity`):

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

**iOS/tvOS/visionOS** — 在 Info.plist 中添加 String 类型的键值对:

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

Source: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)

**Editor/PC/WebGL/UWP/主机** — 在 `Resources` 目录下创建 `application_config.txt`,每行一条 `key=value`:

```text
channel=editor_cn_test
sub_channel=test
```

## 读取行为要点

- **键名可自定义**:调用 `GetChannelName("sub_channel", "unknown")` 即可读取子渠道;Android/iOS 侧同样以传入的 `channelKey` 查询 `meta-data` 或 Info.plist。
- **txt 解析规则**:仅接受 `split.Length > 1` 的行,即必须包含 `=`;首个 `=` 之前为键、之后为值,两侧 Trim 后写入缓存,详见 [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L110-L120)。
- **TextAsset 缺失时**:直接以 `defaultValue` 写入缓存并返回。
- **iOS 原生侧回退值**:Info.plist 查不到键时返回硬编码的 `unknown`,而非 C# 侧的 `defaultValue`,见 [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L31-L35)。
- **iOS 构建兜底**:[PostProcessBuildHandler](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49) 在 iOS 构建后检查 Info.plist,若不存在 `channel` 键则自动写入 `default` 并输出日志 `配置渠道成功=>default`;已存在则输出 `已有渠道,跳过设置=>{value}`。
- **缓存策略**:所有平台首次读取结果都会写入 `ChannelCache` 字典(初始容量 32),进程内重复调用不会再次读取原生配置,见 [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L57)。
