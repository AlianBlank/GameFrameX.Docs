# 如何使用 Snowflake 產生分散式唯一 ID

只需呼叫一行 `SnowFlakeIdHelper.Instance.NextId()`,即可產生全域唯一且遞增的 64 位元整數 ID,並可視需要將 ID 反解析為時間戳記、WorkerId、DataCenterId 及序號。

## 前置條件

- 參考命名空間:`GameFrameX.Foundation.Utility.DistributedSystem.Snowflake`
- 專案已參考 `GameFrameX.Foundation.Utility` 組件
- 在多實例部署的情況下，必須為每個節點設定彼此不同的 `WorkId`(0~31)與 `DataCenterId`(0~31),否則會產生重複的 ID

## 操作步驟

1. **最簡單的用法：直接從單例產生 ID**

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   long id = SnowFlakeIdHelper.Instance.NextId();
   ```

   `Instance` 內部採用雙重檢查鎖定的單例模式，會在首次存取時以 `WorkId=1`、`DataCenterId=1`、`BaseTime=2025-01-01 UTC` 初始化 `IdWorker`。
   Source: [SnowFlakeIdHelper.cs#L181-L204](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L181-L204)

2. **手動指定節點 ID(單一實例或測試)**

   請務必在**首次**存取 `Instance` 之前完成設定，否則將不會生效。

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   SnowFlakeIdHelper.WorkId = 2;
   SnowFlakeIdHelper.DataCenterId = 3;
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L133-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L133-L145)

3. **使用 WorkerIdProvider 自動分配節點 ID**

   框架內建主機名稱、IP、處理程序編號等策略，只需在首次存取 `Instance` 前注入即可。

   ```csharp
   using GameFrameX.Foundation.Utility.DistributedSystem.Snowflake;

   // 範例:以 IP 雜湊自動取得 WorkId(0~31)
   SnowFlakeIdHelper.SetWorkerIdProvider(new IpAddressWorkerIdProvider());
   long id = SnowFlakeIdHelper.Instance.NextId();
   ```
   Source: [SnowFlakeIdHelper.cs#L97-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L97-L100)

4. **(選用)變更基準時間或位元寬度**

   如需變更預設的 `2025-01-01 UTC` 起始點，或想要自訂 WorkerId/序號的位元寬度，請在首次存取前進行變更：

   ```csharp
   SnowFlakeIdHelper.BaseTime = new DateTime(2020, 1, 1, 0, 0, 0, DateTimeKind.Utc).Ticks / 10000;
   SnowFlakeIdHelper.WorkerIdBits = 5;        // 預設 5
   SnowFlakeIdHelper.DatacenterIdBits = 5;    // 預設 5,若不使用資料中心維度可設為 0
   SnowFlakeIdHelper.SequenceBits = 12;       // 預設 12,每毫秒最多可產生 4096 個 ID
   ```
   Source: [SnowFlakeIdHelper.cs#L64-L160](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdHelper.cs#L64-L160)

5. **(選用)反解析 ID 以確認組成要素**

   ```csharp
   long id = SnowFlakeIdHelper.Instance.NextId();

   // 使用預設的 BaseTime 進行解析
   SnowFlakeIdInfo info = SnowFlakeIdParser.Parse(id);

   // 或自訂 BaseTime/位元寬度
   SnowFlakeIdInfo custom = SnowFlakeIdParser.Parse(
       id,
       baseTimeMs: SnowFlakeIdHelper.BaseTime,
       workerIdBits: 5,
       datacenterIdBits: 5,
       sequenceBits: 12);

   Console.WriteLine($"時間={info.Timestamp:o}, Worker={info.WorkerId}, DC={info.DataCenterId}, Seq={info.Sequence}");
   ```
   Source: [SnowFlakeIdParser.cs#L63-L110](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdParser.cs#L63-L110),[SnowFlakeIdInfo.cs#L42-L94](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Utility/DistributedSystem/Snowflake/SnowFlakeIdInfo.cs#L42-L94)

## 常見變化

- **自訂 `IdWorker` 實例(不使用單例)**：直接呼叫 `new IdWorker(workId, datacenterId, baseTimeMs)`。適用於需要獨立設定的多個產生器。

## 常見錯誤

| 症狀 | 原因 | 修正 |
|------|------|------|
| 在不同機器/處理程序產生重複的 ID | 兩邊的 `WorkId` 或 `DataCenterId` 相同 | 使用 `SetWorkerIdProvider` 自動分配，或為每台機器設定唯一的編號 |
| `WorkId` / `BaseTime` / 位元寬度的調整未生效 | 已在某處存取過 `Instance`,單例已建立 | 在程式啟動的早期階段、所有呼叫之前完成設定，或在測試之間使用獨立的 `IdWorker` 實例 |
| 解析舊 ID 時時間戳記異常 | `BaseTime` 或位元寬度設定錯誤 | 解析時明確指定與產生時一致的 `baseTimeMs` 和 `workerIdBits`/`datacenterIdBits`/`sequenceBits` |
| `Parse` 擲回 `ArgumentOutOfRangeException` | ID 為負數 | Snowflake ID 必須為非負值。請確認是否與其他 ID 類型混用 |
| 系統時間回撥導致產生作業阻塞或異常 | 雪花演算法對時鐘回撥敏感 | 確保 NTP 同步，發生回撥時使用自訂 `IdWorker` 攔截 `InvalidSystemClock`,避免直接擲回錯誤 |

## 背景(選用)

預設的位元寬度配置為 `1 符號位元 | 41 時間戳記位元 | 5 資料中心位元 | 5 工作節點位元 | 12 序號位元`,單一節點每毫秒可產生 4096 個 ID。基準時間設定為 `2025-01-01 UTC`,在 41 位元時間戳記下約可使用 69 年。`SnowFlakeIdParser` 使用完全相同的位元運算式，因此只要 `BaseTime` 與位元寬度一致，即可無損地反解析。與其他分散式 ID 方案的比較，請參閱《分散式 ID 選型》。
