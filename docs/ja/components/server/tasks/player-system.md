# プレイヤー基本情報の実装(Playerエンティティとログイン)

このページのタスクを完了すると、クライアントはキャラクターIDに基づいてログインでき、サーバーはログイン時にプレイヤー属性を初期化し、オンラインリストに追加して、属性スナップショットとプレイヤー情報をクライアントに返すことができます。

## 前提条件

- `LoginComponentAgent` とログインリンクが存在する(アカウント認証成功、`playerState.Id` を取得済み)。
- `PlayerComponent` が `[ComponentType(GlobalConst.ActorTypePlayer)]` を通じてプレイヤー Actor に登録されている。
- `PlayerAttributeComponent` がマウントされている(ログイン後に読み取られ、スナップショットがプッシュされる)。

## 操作手順

1. プレイヤーエンティティ定義を確認(`PlayerState` は `CacheState` を継承し、アカウント、名前、レベル、性別、アバター、状態、ログイン/オフライン時間を含む):

3. ログインハンドラーで `PlayerComponentAgent.OnPlayerLogin` を呼び出して、完全なログインフローをトリガー:

```csharp
public async Task OnPlayerLogin(INetWorkChannel workChannel, PlayerState playerState, RespPlayerLogin response)
{
    SessionManager.UpdateSession(workChannel.GameAppSession.SessionID, playerState.Id, playerState.Id.ToString());
    response.Code = playerState.State;
    response.CreateTime = playerState.CreatedTime;
    response.PlayerInfo = new PlayerInfo
    {
        Id = playerState.Id,
        Name = playerState.Name,
        Level = playerState.Level,
        State = playerState.State,
        Avatar = playerState.Avatar,
    };

    var attributeComponentAgent = await ActorManager.GetComponentAgent<PlayerAttributeComponentAgent>(playerState.Id);
    await attributeComponentAgent.InitializeDefaultsSilent();

    var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();
    await serverComp.AddOnlineRole(ActorId);

    var roomComp = await ActorManager.GetComponentAgent<RoomComponentAgent>();
    await roomComp.MarkPlayerReconnected(ActorId);

    await workChannel.WriteAsync(attributeComponentAgent.BuildSyncSnapshot());

    var mailAgent = await ActorManager.GetComponentAgent<MailComponentAgent>(playerState.Id);
    await mailAgent.SyncAsync();
}
```

Source: [PlayerComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Login/PlayerComponentAgent.cs#L62-L93)

{
    var serverComp = await ActorManager.GetComponentAgent<ServerComponentAgent>();

}

## 一般的なバリエーション

- キャラクターリストの照会のみでログインしない:リポジトリ内の `ReqPlayerListHandler` がエントリポイント(`GameFrameX.Hotfix/Logic/Account/Login/ReqPlayerListHandler.cs` を参照)。ログイン前にキャラクターを一覧表示するために使用。
- HTTP 経由でのキャラクター作成/一覧:`GameFrameX.Hotfix/Logic/Http/Player/ReqPlayerCreateHttpHandler.cs` と `ReqPlayerListHttpHandler.cs` を使用。
- プレイヤーのキックオフライン:`GameFrameX.Hotfix/Logic/Http/Player/KickOffLineByUserIdPlayerHttpHandler.cs` を使用。

## よくあるエラー

- `ReqPlayerCreateHandler` は現在、ソースコード内でコメントアウトされた状態([ReqPlayerCreateHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Account/Login/ReqPlayerCreateHandler.cs)を参照)。このクラスに基づいてクライアントプロトコルを直接実装しないでください。HTTP ハンドラーを使用するか、`LoginComponentAgent` で拡張してください。
- ログイン時に `InitializeDefaultsSilent()` の呼び出しを忘れると、属性スナップショットが初期化されず、クライアントが基本属性を読み取れない可能性がある。
- ログアウト処理で `SetAutoRecycle(true)` を忘れると、プレイヤー Actor が長期間常駐し、メモリを回収できなくなる。

## 背景(オプション)

`PlayerComponent` は `StateComponent<PlayerState>` を使用してプレイヤー状態を保持します。ログイン時に `PlayerComponentAgent.OnPlayerLogin` が属性初期化、オンラインリストへの追加、ルーム再接続フラグ、属性スナップショットのプッシュ、メールの遅延同期を連結し、ログイン後のすべてのプレイヤーサブシステム初期化の統一エントリポイントです。
