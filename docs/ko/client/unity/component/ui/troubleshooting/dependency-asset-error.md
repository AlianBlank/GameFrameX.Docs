# UI 로딩 시 의존 리소스 예외가 발생하면 어떻게 해야 하나요

`OpenUIFormAsync`로 UI를 여는 과정에서 의존 리소스 로딩 실패(의존 에셋이 존재하지 않음, 로딩 콜백이 트리거되지 않음, 의존 카운트가 오랫동안 변하지 않음, 또는 열기 프로세스가 중단됨)가 발생하면, 이 페이지의 진단 표를 통해 근본 원인을 파악하고 수정할 수 있습니다.

## 빠른 진단

| 증상 | 원인 | 수정 방법 |
|------|------|------|
| `OpenUIFormFailure` 이벤트 발생, `ErrorMessage`에 리소스가 존재하지 않는다고 표시됨 | 전달된 `uiFormAssetPath`가 실제 에셋 경로와 일치하지 않거나, 에셋이 AssetBundle / Addressables에 포함되지 않음 | 경로 문자열과 `UIFormAssetName`을 확인하고 의존 목록을 다시 구축 |
| `LoadedCount`가 계속 0이고 `TotalCount`가 0보다 큼 | 의존 리소스 로딩 콜백이 올바르게 등록되지 않았거나 동시 열기 요청에 선점됨 | 동일한 리소스에 대한 열기를 직렬화하고 `OpenUIFormDependencyAssetEventArgs` 리스닝 체인 확인 |
| `DependencyAssetName`이 `null`임 | UI 자체에 의존 에셋이 선언되지 않았거나 의존 메타데이터가 생성되지 않음 | UI 설정을 다시 생성하고 의존 에셋 목록이 비어 있지 않은지 확인 |
| `Task`가 오랫동안 `IUIForm`을 반환하지 않음 | 의존 로딩 체인이 완료되지 않아 비동기 프로세스가 `await`에서 막힘 | `OpenUIFormAsync` 호출 측에서 `await`가 누락되지 않았는지 확인하고, 리소스 관리자가 초기화되었는지 확인 |
| `UIFormAssetPath` / `UIFormAssetName`이 `null`임 | 상위 호출에서 유효한 경로를 전달하지 않음 | `OpenUIFormAsync` 호출 전 파라미터를 검증하고 `GameFrameworkGuard.NotNull` 사용 |

이벤트 객체의 핵심 필드 정의는 다음과 같으며, 로그와 함께 대조할 수 있습니다:

## 수정 단계

### 1. 리소스 경로 또는 이름 불일치

`OpenUIFormAsync`는 두 가지 핵심 파라미터를 받습니다: 리소스 경로 `uiFormAssetPath`와 리소스 이름 `uiFormAssetName`(로딩 객체 내). 둘 중 하나라도 프로젝트 내에 실제로 존재하는 에셋과 일치하지 않으면 로딩이 즉시 실패하고 `OpenUIFormFailure`를 통해 예외가 발생합니다.

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class UIFormLoadingObject : IReference
{
    public string UIFormAssetPath { get; private set; }
    public string UIFormAssetName { get; private set; }
    public Type UIFormType { get; private set; }
    public Task<IUIForm> Task { get; private set; }

    public static UIFormLoadingObject Create(string uiFormAssetPath, string uiFormAssetName, Type uiFormType, Task<IUIForm> task)
    {
        var uiFormLoadingObject = ReferencePool.Acquire<UIFormLoadingObject>();
        uiFormLoadingObject.UIFormAssetPath = uiFormAssetPath;
        uiFormLoadingObject.UIFormAssetName = uiFormAssetName;
        uiFormLoadingObject.UIFormType = uiFormType;
        uiFormLoadingObject.Task = task;
        return uiFormLoadingObject;
    }
}
```

출처: [BaseUIManager.UIFormLoadingObject.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.UIFormLoadingObject.cs#L43-L86)

작업 단계:

1. Unity에서 해당 UI 프리팹을 찾아 `Addressables` 주소 또는 AssetBundle 경로를 복사합니다.
2. `OpenUIFormAsync` 호출 시 완전히 동일한 문자열을 사용합니다(대소문자 구분).
3. `OpenUIFormFailure` 콜백 내에서 `UIFormAssetName`과 `ErrorMessage`를 출력하여 한 글자씩 비교합니다.

### 2. 비동기 프로세스가 대기되지 않음

`OpenUIFormAsync`는 `Task<IUIForm>`을 반환하며, 내부 구현인 `InnerOpenUIFormAsync`는 추상 메서드로 하위 클래스에서 의존 로딩을 완료합니다.

```csharp
[UnityEngine.Scripting.Preserve]
public async Task<IUIForm> OpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false)
{
    return await InnerOpenUIFormAsync(uiFormAssetPath, uiFormType, pauseCoveredUIForm, userData, isFullScreen);
}

[UnityEngine.Scripting.Preserve]
protected abstract Task<IUIForm> InnerOpenUIFormAsync(string uiFormAssetPath, Type uiFormType, bool pauseCoveredUIForm, object userData, bool isFullScreen = false);
```

출처: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L114-L130)

호출 측에서 `await`가 누락되면 `Task`가 미완료 상태로 남아 조용히 버려지고, 이후 작업에서 `uiForm`을 읽을 때 `null`을 얻게 됩니다. 수정 방법:

1. 호출 지점에서 일관되게 `await uiManager.OpenUIFormAsync<MyForm>(path, true, userData);`를 사용합니다.
2. 코루틴 또는 콜백 스타일 코드에서 `.ContinueWith(...)` 또는 `await`로 컨텍스트를 동기화합니다.
3. `OpenUIFormSuccess` / `OpenUIFormFailure` 이벤트와 함께 프로세스가 종료되었는지 확인합니다.

### 3. 의존 카운트가 변하지 않음 / 콜백이 트리거되지 않음

`OpenUIFormDependencyAssetEventArgs`는 현재 `BaseUIManager`에서 주석 형태로 남아 있습니다(`m_OpenUIFormDependencyAssetEventHandler`가 주석 처리됨). 프로젝트에서 해당 이벤트를 구독한 적이 있다면 다시 활성화하고, 하위 클래스가 의존 로딩 과정에서 `EventId`를 호출하여 이벤트를 전달하도록 해야 합니다. `LoadedCount` / `TotalCount`가 오랫동안 변하지 않는 것은 일반적으로 의존 로딩 콜백이 구동되지 않았거나, `TotalCount`가 초기화 전에 0으로 읽혔기 때문입니다.

커스텀 `BaseUIManager` 하위 클래스 내에서 다음과 같이 할 것을 권장합니다:

1. `InnerOpenUIFormAsync`에서 의존 에셋 목록을 가져와 `totalCount`를 얻습니다.
2. 의존 로딩이 하나 완료될 때마다 `OpenUIFormDependencyAssetEventArgs.Create(...)`를 호출하고 이벤트 버스를 통해 브로드캐스트합니다.
3. 리스닝 측에서 `LoadedCount` / `TotalCount`를 읽어 진행 바를 구동합니다.

### 4. 실패 이벤트가 등록되지 않음

`OpenUIFormFailure` 이벤트는 예외를 캡처하는 데 사용되며, 시그니처는 다음과 같습니다:

```csharp
[UnityEngine.Scripting.Preserve]
public event EventHandler<OpenUIFormFailureEventArgs> OpenUIFormFailure
{
    add { m_OpenUIFormFailureEventHandler += value; }
    remove { m_OpenUIFormFailureEventHandler -= value; }
}
```

출처: [BaseUIManager.Open.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/BaseUIManager.Open.cs#L63-L68)

애플리케이션이 해당 이벤트를 구독하지 않으면 예외는 `Task`를 통해서만 발생하며, 상위 계층에서 조용히 무시될 수 있습니다. 수정 방법: UI 프레임워크가 시작된 직후 `OpenUIFormFailure`와 `OpenUIFormSuccess`를 등록하고, 오류 로그를 통일되게 파일로 저장하거나 보고합니다.

## 검증

1. 정상적인 열기 프로세스를 한 번 실행하여 `OpenUIFormSuccess`가 발생하고 `SerialId`가 요청과 일치하는지 확인합니다.
2. 일부러 잘못된 경로로 열기 요청을 한 번 실행하여 `OpenUIFormFailure.ErrorMessage`에 읽을 수 있는 정보가 포함되어 있는지 확인합니다.
3. 의존 에셋이 있는 UI를 한 번 열어 `LoadedCount`가 최종적으로 `TotalCount`와 같아지는지 확인합니다.
4. 디버거에서 `UIFormLoadingObject.Task.Status`를 관찰하여 `WaitingForActivation`에서 `RanToCompletion` 또는 `Faulted`로 전환되는지 확인합니다.
