# Using PathUtil for Path Handling (Normalization/Concatenation/Wildcards)

`PathUtil` is a static utility class specifically designed to handle relative paths involved in reading and writing resources: normalize paths with mixed separators, `.`, and `..`, safely concatenate two path segments into a `/`-separated string, and convert `*`/`?` wildcards into regular expressions that can be directly used for matching.

## Prerequisites

- The project has introduced the `com.gameframex.unity.readassets` package.
- `using GameFrameX.ReadAssets.Runtime;` in the code.

## Overview of Common Methods

| Method | Purpose |
|------|------|
| `IsDirectorySeparator(char c)` | Determines whether a character is `/` or `\` |
| `FixTrailingDirectorySeparators(string path)` | Merges consecutive trailing separators into one |
| `CombineSlash(string a, string b)` | Concatenates two path segments using `/`, avoiding duplicate or missing separators |
| `NormalizeRelativePath(string relative, bool forceTrailingSlash = false)` | Normalizes a relative path to the `/a/b/c` form, handling `.`, `..`, and mixed separators |
| `IsValidCharacter(char c)` | Determines whether a character is allowed in a path |
| `WildcardToRegex(string pattern)` | Converts `*`/`?` wildcards into a case-insensitive regular expression |

## Operation Steps

### 1. Concatenate Two Path Segments

```csharp
using GameFrameX.ReadAssets.Runtime;

string full = PathUtil.CombineSlash("assets/config", "settings.json");
// Result: "assets/config/settings.json"

string root = PathUtil.CombineSlash("assets/config/", "sub/file.json");
// Result: "assets/config/sub/file.json", no duplicated slashes

string abs = PathUtil.CombineSlash("assets/config", "/absolute/file.json");
// When b starts with '/', b is returned directly: "absolute/file.json"
```

### 2. Normalize a Relative Path

`NormalizeRelativePath` converts all `\` to `/`, collapses `.`, resolves `..`, and validates illegal characters. By default, the trailing slash is not preserved; pass `forceTrailingSlash: true` to force it to be kept.

```csharp
using GameFrameX.ReadAssets.Runtime;

// Mixed separators → unified to /
string p1 = PathUtil.NormalizeRelativePath("a\\b\\c");
// Result: "a/b/c"

// Resolves . and ..
string p2 = PathUtil.NormalizeRelativePath("a/./b/../c");
// Result: "a/c"

// Force trailing slash to be preserved
string p3 = PathUtil.NormalizeRelativePath("a/b/c", forceTrailingSlash: true);
// Result: "a/b/c/"

// Strings wrapped in quotes on both sides will be stripped
string p4 = PathUtil.NormalizeRelativePath("\"a/b\"");
// Result: "a/b"
```

Source: [Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L170)

### 3. Use Wildcards for Matching

`WildcardToRegex` converts wildcards into a regular expression: `*` corresponds to any sequence of characters, `?` corresponds to a single character, and matching is case-insensitive.

```csharp
using System.Text.RegularExpressions;
using GameFrameX.ReadAssets.Runtime;

Regex rx = PathUtil.WildcardToRegex("assets/configs/*.json");
bool match1 = rx.IsMatch("assets/configs/settings.json"); // true
bool match2 = rx.IsMatch("assets/configs/data.json");    // true
bool match3 = rx.IsMatch("assets/configs/sub/a.json");   // false (* does not cross /)

Regex rx2 = PathUtil.WildcardToRegex("file_?.txt");
bool match4 = rx2.IsMatch("file_1.txt"); // true
bool match5 = rx2.IsMatch("file_12.txt"); // false
```

Source: [Runtime/PathUtil.cs](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L183-L186)

## Common Variants

- **Preserve quotes as-is**: If the path is not an entire string wrapped in double quotes (i.e., only a leading or trailing `"`), `NormalizeRelativePath` will not strip the quotes; quotes are also considered illegal characters and will throw `Invalid characters`.
- **Determine whether a character is valid**: `IsValidCharacter` rejects `"`, `<`, `>`, `|`, `*`, `?`, `:`, and control characters (ASCII < 32), and can be reused in custom validation.
- **Concatenate absolute paths**: In `CombineSlash`, if `b` starts with `/`, `b` is returned directly (with the leading `/` removed), used for scenarios where "the passed-in path overrides the prefix".

## Common Errors

| Symptom | Cause | Handling |
|------|------|------|
| `ArgumentException: Empty or null` | `NormalizeRelativePath` was passed `null` or an empty string | Perform a null check in advance |
| `IOException: Invalid path: double dot error` | `..` exceeds the current directory (already at root) | Check whether the path really goes above the root directory |
| `IOException: Invalid characters` | The path contains `"`, `<`, `>`, `|`, `*`, `?`, `:`, or control characters | Use `IsValidCharacter` to filter or correct the input |
| `ArgumentNullException: a / b` | Either argument of `CombineSlash` is `null` | Perform a null check before calling |

## Background (Optional)

`PathUtil` consolidates the three most error-prone aspects of the resource reading workflow—separators, `./..`, and wildcards—into a single static class: `NormalizeRelativePath` uses a state machine to parse path segments, ensuring the output is uniformly prefixed with `/` and contains no redundancy; `WildcardToRegex` uses `Regex.Escape` as a fallback before replacing `*`/`?`, preventing dots in the path from being treated as regular expression metacharacters.
