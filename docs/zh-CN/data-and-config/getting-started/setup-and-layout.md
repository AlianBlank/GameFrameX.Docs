# 环境准备与目录结构

这一页带你准备 GameFrameX.Config 的运行环境、了解仓库的目录约定,完成 Luban 配置工具链的首次跑通。

## 前置条件

| 项 | 要求 | 用途 |
|----|------|------|
| .NET SDK | 6.0 及以上 | 执行 `Tools/Luban.dll`(见 `luban.conf` 中的 `toolPath`) |
| Excel 编辑器 | Microsoft Excel / WPS / LibreOffice | 编辑 `Excels/` 下的 xlsx |
| Unity 工程 | 用于客户端目标(`Hotfix/Config/Generate`) | 接收生成的 C# 代码与 JSON 数据 |
| 服务器工程 | 用于服务端目标(`Server.Config/Config`) | 接收生成的 C# 代码与 JSON 数据 |

> 仓库根目录下的 `*.bat` 和 `*.sh` 已经写好了默认路径 `../Unity/Assets/` 与 `../Server/GameFrameX.Config/`,因此仓库与 Unity/Server 工程通常并列放置。

## 快速开始

1. 把仓库放到 Unity 工程同级目录,目录结构通常如下:

   ```
   parent/
   ├── GameFrameX.Config/      # 当前仓库
   │   ├── Luban.conf
   │   ├── Defines/
   │   ├── Excels/
   │   └── Tools/Luban.dll
   ├── Unity/                  # Unity 工程
   │   └── Assets/Hotfix/Config/Generate
   └── Server/                 # 服务端工程
       └── GameFrameX.Config/
           ├── Json/
           └── Config/
   ```

2. 根据操作系统执行对应的生成脚本(脚本只是 `dotnet ./Tools/Luban.dll ...` 的封装):

   - Windows + JSON 输出:`gen-server-json.bat` / `gen-client-json.bat`
   - Windows + 二进制输出:`gen-server-bin.bat` / `gen-client-bin.bat`
   - Linux/macOS:对应的 `.sh` 文件

3. 在 `luban.conf` 中按需填写 `UNITY_ASSETS_PATH`、`SERVER_PATH`(留空时使用脚本默认的相对路径)。

## 目录结构

| 路径 | 作用 |
|------|------|
| `Luban.conf` | Luban 主配置:分组、schema、数据目录、生成命令 |
| `Defines/` | XML 形式的 bean/enum/table 定义(`builtin.xml` 注册 `vec2/vec3/vec4`) |
| `Excels/__tables__.xlsx` | 表注册表(声明哪些 xlsx 是配置表) |
| `Excels/__beans__.xlsx` | bean 注册表(复杂数据结构) |
| `Excels/__enums__.xlsx` | 枚举注册表 |
| `Excels/Tables/` | 真正的配置表(命名 `C-表名-中文名.xlsx`) |
| `Excels/Local/` | 本地化表(`L-Localization-*.xlsx`) |
| `Tools/` | 放 `Luban.dll`,由 `toolPath` 引用 |
| `gen-*.bat` / `gen-*.sh` | 各类生成入口脚本 |

## 配置脚本(`Luban.conf` 速览)

[Luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L1-L95) 把 schema 与生成命令集中管理,关键字段如下:

| 字段 | 含义 |
|------|------|
| `groups` | 分组(默认 `c` 客户端、`s` 服务端) |
| `schemaFiles` | 注册的 schema 文件(`Defines`、`__tables__.xlsx` 等) |
| `dataDir` | 数据根目录(`Excels`) |
| `targets` | 三种输出目标:`server` / `client` / `all`,分别使用 `GameFrameX.Config`、`Hotfix.Config`、`cfg` 作为顶层命名空间 |
| `toolPath` | Luban.dll 相对路径 |
| `commands` | 实际的 Luban 命令行,按 `active` 控制是否执行 |

`commands` 里默认提供了 JSON 和 bin 两套(client/server 共 4 条),`active: false` 的需要时再打开,示例片段:

```json
{
  "command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config",
  "target": "server",
  "active": true
}
```

> `%UNITY_ASSETS_PATH%` 与 `%SERVER_PATH%` 在 `Luban.conf` 顶部声明,留空时由生成脚本用相对路径补齐。
