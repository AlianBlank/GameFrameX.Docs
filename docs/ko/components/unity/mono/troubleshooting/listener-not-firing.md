# 리스너가 트리거되지 않거나 콜백 타이밍이 잘못된 경우怎么办

当你通过 `MonoComponent.AddUpdateListener / AddFixedUpdateListener / AddLateUpdateListener / AddDestroyListener / AddOnApplicationFocusListener / AddOnApplicationPauseListener` 注册了回调,但运行后函数没有执行,或执行顺序与预期不符,可以按本页流程排查。

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| 콘솔 출력 `Mono manager is invalid.` | 场景里没有挂 `MonoComponent`,框架模块 `IMonoManager` 未注册 | 见下方「场景缺少 MonoComponent」 |
| 콘솔 출력 `Event manager is invalid.` | 场景里没有挂 `EventComponent`,`OnApplicationFocus/Pause` 事件无法派发 | 见下方「EventComponent 缺失」 |
| 리스너가 한 번도 트리거되지 않으며 오류 메시지 없음 | 在 `Awake` 里 `AddXxxListener` 时,`_monoManager` 仍为 `null` | 见下方「注册时机早于 Awake」 |
| 리스너가 한 번만 트리거되고 이후 침묵 | 在回调内部再次 `AddXxxListener` 时传入了 `null`,`MonoComponent` 静默 `return` | 见下方「回调函数为 null」 |
| `AddOnApplicationFocusListener` 가 트리거되지 않지만 Update 는 정상 | `EventComponent` 未挂载,`MonoComponent.OnApplicationFocus` 的事件分支直接跳过 | 见下方「EventComponent 缺失」 |
| 回调里抛异常被吞掉,后续监听器仍执行 | `QueueInvoking` 对每个 `action.Invoke()` 包了 `try/catch`,只写 `Log.Error` | 见下方「回调内部异常被静默吞掉」 |
| LateUpdate 리스너가 Update 보다 먼저 실행됨 | 注册位置在 `Update` 之后,管理器按 `LinkedList` 顺序派发 | 见下方「监听器注册顺序与执行顺序」 |
| 在 `OnApplicationFocus(true)` 里注册,但同时失去焦点又获得焦点时只回调了一次 | Unity 在编辑器失焦/聚焦时可能合并事件 | 见下方「编辑器失焦行为」 |

## 修复步骤

### 场景缺少 MonoComponent

`MonoComponent.Awake()` 通过 `GameFrameworkEntry.GetModule<IMonoManager>()` 取模块;取不到就调用 `Log.Fatal("Mono manager is invalid.")` 并直接 `return`,之后所有 Unity 回调(`FixedUpdate / LateUpdate / OnDestroy / OnApplicationFocus / OnApplicationPause`)都因 `_monoManager == null` 被跳过:

```csharp
// Runtime/Mono/MonoComponent.cs
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IMonoManager);
    base.Awake();
    _monoManager = GameFrameworkEntry.GetModule<IMonoManager>();
    if (_monoManager == null)
    {
        Log.Fatal("Mono manager is invalid.");
        return;
    }
}
```

Source: [MonoComponent.cs#L52-L63](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L52-L63)

修复:

1. 在游戏启动场景的 `GameFramework` 物体上点击 `Add Component → GameFrameX/Mono` 添加 `MonoComponent`。
2. 确认该物体上还挂了 `BaseComponent`(框架入口),否则模块链不会启动。
3. 重新运行场景,确认控制台不再出现 `Mono manager is invalid.`。

### EventComponent 缺失

`OnApplicationFocus` 与 `OnApplicationPause` 除了调用 `_monoManager` 上的回调,还会通过 `EventComponent.Fire` 把事件广播给订阅者。如果 `m_EventComponent == null`,事件分支直接跳过:

```csharp
// Runtime/Mono/MonoComponent.cs
private void OnApplicationFocus(bool focusStatus)
{
    if (_monoManager == null) { return; }
    _monoManager.OnApplicationFocus(focusStatus);
    if (m_EventComponent != null)
    {
        m_EventComponent.Fire(this, OnApplicationFocusChangedEventArgs.Create(focusStatus));
    }
}
```

Source: [MonoComponent.cs#L111-L123](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L111-L123)

修复:

1. 在同一 `GameFramework` 物体上添加 `EventComponent`(`Add Component → GameFrameX/Event`)。
2. 订阅端使用 `EventComponent.Subscribe` 订阅 `OnApplicationFocusChangedEventArgs.EventId`,而不是只调用 `AddOnApplicationFocusListener`。
3. 运行后应能在日志中看到事件被派发。

### 注册时机早于 Awake

`_monoManager` 在 `MonoComponent.Awake()` 才赋值。如果你在某个脚本自己的 `Awake` 里就调用 `GameEntry.GetComponent<MonoComponent>().AddUpdateListener(...)`,由于脚本 `Awake` 顺序未定义,可能拿到一个 `_monoManager` 尚未初始化的 `MonoComponent` 实例,后续即使赋值了,新注册的回调也会工作,但要注意:如果 `MonoComponent` 还没 `Awake`,它内部的 `_monoManager` 是 `null`,所有 `AddXxxListener` 会因为 `_monoManager` 未初始化而无法入队(实际表现为 `NullReferenceException` 或 `MonoComponent` 内的 `Log.Fatal` 输出 `fun is invalid.`)。

修复:

- 把注册逻辑放到 `Start` 中,或在拿到 `MonoComponent` 后加一个 `if (comp == null) return;`。
- 也可以直接通过 `GameFrameworkEntry.GetModule<IMonoManager>()` 拿到管理器,绕过 `MonoComponent`。

### 回调函数为 null

`MonoComponent.AddXxxListener` 对 `null` 入参只写 `Log.Fatal` 并 `return`,不会抛异常,也不会入队:

```csharp
// Runtime/Mono/MonoComponent.cs
public void AddUpdateListener(Action<float, float> fun)
{
    if (fun == null)
    {
        Log.Fatal(nameof(fun) + " is invalid.");
        return;
    }
    _monoManager.AddUpdateListener(fun);
}
```

Source: [MonoComponent.cs#L207-L216](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L207-L216)

而 `MonoManager.AddXxxListener` 对 `null` 会直接抛 `ArgumentNullException`。两层语义不同,写代码时不要混淆。

修复:

- 注册时确保 `fun` 是非空的方法组或 lambda;不要传入 `default(Action<float, float>)`。
- 如果控制台出现 `fun is invalid.`,就是这里传了 `null`。

### 回调内部异常被静默吞掉

`MonoManager.QueueInvoking` 在派发每个监听器时都包了 `try/catch`,异常只通过 `Log.Error` 写出,不会中断后续监听器:

```csharp
// Runtime/Mono/MonoManager.cs
foreach (var action in snapshot)
{
    try
    {
        UnityEngine.Profiling.Profiler.BeginSample($"QueueInvoking-{action.Method.Name}-{action.Target}");
        action.Invoke();
        UnityEngine.Profiling.Profiler.EndSample();
    }
    catch (Exception e)
    {
        Log.Error(e);
    }
}
```

Source: [MonoManager.cs#L319-L330](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoManager.cs#L319-L330)

修复:

- 控制台搜索 `QueueInvoking-` 前缀的 `Log.Error`,定位是哪个监听器抛错。
- 在回调内部用 `try/catch` 自行保护关键逻辑,避免一条监听器的异常被忽略后,看起来"什么都没发生"。

### 监听器注册顺序与执行顺序

`MonoManager` 用 `LinkedList<Action<...>>` 存储监听器,派发时按入队顺序遍历。`LateUpdate` 的派发在所有 `Update` 之后,但 `MonoComponent` 自身没有 `Update` 方法(源码中只有 `FixedUpdate`、`LateUpdate`、`OnDestroy`、`OnApplicationFocus`、`OnApplicationPause`):

```csharp
// Runtime/Mono/MonoComponent.cs
private void FixedUpdate() { _monoManager.FixedUpdate(); }
private void LateUpdate()  { _monoManager.LateUpdate(); }
```

Source: [MonoComponent.cs#L81-L92](https://github.com/GameFrameX/com.gameframex.unity.mono/blob/main/Runtime/Mono/MonoComponent.cs#L81-L92)

也就是说:**框架没有 Update 钩子**。如果你以为有 `AddUpdateListener`,实际是有的(`MonoManager._updateQueue` + `AddUpdateListener`),但驱动它的 `MonoBehaviour.Update` 没有在 `MonoComponent` 中显式声明——这通常意味着项目里需要通过别的方式触发 `_monoManager.Update`(例如在自定义 `MonoBehaviour.Update` 里手动调用,或确认是否存在继承版本)。

修复:

- 确认项目里实际有 `MonoBehaviour.Update` 调用 `_monoManager.Update()`;如果只有 `MonoComponent`,Update 监听器不会触发,需要自行补充。
- 监听器之间的相对顺序:先 `AddXxxListener` 的先执行,后注册的后执行。需要严格顺序时按顺序注册即可。
- 同帧多次进入 / 离开焦点时,Unity 会按事件实际发生顺序触发,框架不合并。

### 编辑器失焦行为

`OnApplicationFocus` 在编辑器中会在以下情况触发:窗口失焦、点击 Play、Stop。开发期间频繁触发属于正常现象。如果只是编辑器里"看起来不触发",建议 Build 到真机或勾选 `Edit → Project Settings → Player → Run In Background` 后再观察。

## 验证

- 控制台不再出现 `Mono manager is invalid.`、`Event manager is invalid.`、`fun is invalid.`。
- 注册一个最简单的 `Debug.Log` 监听器(例如 `AddUpdateListener((a, b) => Debug.Log("update " + a))`),运行后能看到逐帧日志。
- `OnApplicationFocus/Pause` 切换窗口焦点时,日志或事件订阅者能收到对应事件。
- 回调内部抛错时,日志中能看到 `QueueInvoking-YourMethod-YourTarget` 命中的异常,而不是完全静默。
