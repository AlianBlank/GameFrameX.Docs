# 透過 FsmComponent 整合至專案的方法

`FsmComponent` 是 GameFrameX 框架的有限狀態機(FSM)整合入口元件,繼承自 `GameFrameworkComponent`,掛載到場景後會透過 `GameFrameworkEntry.GetModule<IFsmManager>()` 取得底層狀態機管理器,並負責所有 FSM 的建立、查詢、銷毀及 `FixedUpdate` 輪詢。

## 前置條件

- 必須已安裝 `com.gameframex.unity.fsm` 套件(透過 `manifest.json` 引入)。
- 場景中必須存在 GameFrameX 框架入口(由 `com.gameframex.unity.runtime` 提供,`FsmComponent` 透過它解析 `IFsmManager`)。
- 狀態定義須繼承 `FsmState<T>` 撰寫,擁有者型別 `T` 必須是參考型別(`class`)。

## 操作步驟

1. **在場景入口 GameObject 上新增 FSM 元件。** 在掛載了 GameFrameX 框架入口元件(例如 `GameEntry`)的同一個 GameObject 上點擊 `Add Component`,搜尋 `GameFrameX/FSM` 並新增。元件類別標示了 `[AddComponentMenu("GameFrameX/FSM")]`,因此可直接在選單項目中找到。

   ```csharp
   [DisallowMultipleComponent]
   [AddComponentMenu("GameFrameX/FSM")]
   [GameFrameXAutoComponent(-6000)]
   public sealed class FsmComponent : GameFrameworkComponent
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L43-L47)

2. **取得元件實例。** 在執行階段透過 `GameEntry.GetComponent<FsmComponent>()` 取得參考。若同時引入了 `com.gameframex.unity.entry` 快捷套件,則可直接使用 `GameApp.Fsm`。

   ```csharp
   // 標準方式
   FsmComponent fsmComponent = GameEntry.GetComponent<FsmComponent>();

   // 快捷方式(依賴 com.gameframex.unity.entry)
   IFsm<Player> fsm = GameApp.Fsm.CreateFsm(player, new IdleState(), new MoveState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L47)

3. **定義狀態類別。** 繼承 `FsmState<T>` 並在虛擬方法中撰寫狀態邏輯,透過 `ChangeState<TState>(fsm)` 觸發狀態轉換。

   ```csharp
   public class IdleState : FsmState<Player>
   {
       protected override void OnEnter(IFsm<Player> fsm) { }

       protected override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           if (Input.GetKeyDown(KeyCode.W))
           {
               ChangeState<MoveState>(fsm);
           }
       }

       protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
   }
   ```

   Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L101-L123)

4. **建立並啟動 FSM。** 呼叫 `CreateFsm<T>` 傳入擁有者與狀態集合,再呼叫 `Start<TState>()` 啟動。`Awake()` 內部會透過 `GameFrameworkEntry.GetModule<IFsmManager>()` 完成管理器綁定,若取得失敗則記錄 `Log.Fatal("FSM manager is invalid.")`。

   ```csharp
   var player = new Player();
   IFsm<Player> fsm = fsmComponent.CreateFsm(
       player,
       new FsmState<Player>[] { new IdleState(), new MoveState() }
   );
   fsm.Start<IdleState>();
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L63-L74) · [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L204-L222)

5. **驅動迴圈無需手動呼叫。** `FsmComponent.FixedUpdate()` 會依照 Unity 物理節奏呼叫 `m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime)`,因此只要掛載元件,FSM 就會自動運行。請勿在業務腳本中重複 tick。

   ```csharp
   private void FixedUpdate()
   {
       if (m_FsmManager == null) return;
       m_FsmManager.FixedUpdate(Time.fixedDeltaTime, Time.fixedTime);
   }
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L76-L84)

6. **必要時銷毀 FSM。** 透過 `DestroyFsm` 系列多載(依 owner 型別、依 `IFsm<T>` 參考、依 ownerType+name 等)進行清理。

   ```csharp
   fsmComponent.DestroyFsm(fsm);     // 銷毀指定實例
   fsmComponent.DestroyFsm<Player>(); // 銷毀該 owner 型別的未命名 FSM
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L304-L318)

## 常見變化

- **具名 FSM(同一 owner 型別下多個狀態機共存)**: 透過包含 `name` 的 `CreateFsm` 多載加以區分,之後以 `HasFsm<T>(name)` / `GetFsm<T>(name)` 存取。例如角色上同時存在「戰鬥 FSM」與「AI 行為樹 FSM」時,可用不同的 name 加以區分。

  ```csharp
  IFsm<Player> combat = fsmComponent.CreateFsm("Combat", player, new AttackState(), new HurtState());
  IFsm<Player> ai     = fsmComponent.CreateFsm("AI", player, new PatrolState(), new ChaseState());
  combat.Start<AttackState>();
  ai.Start<PatrolState>();
  ```

  Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L218-L222)

- **執行階段新增/移除狀態**： 透過 `IFsm<T>.AddState` / `RemoveState<TState>()` 動態調整。目前執行中的狀態無法移除。

  ```csharp
  fsm.AddState(new JumpState());
  fsm.RemoveState<IdleState>();
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L153-L158)

- **狀態間資料儲存與查詢**： 使用 `SetData(name, value)` / `GetData<TData>(name)` / `HasData(name)` / `RemoveData(name)`,內部透過物件池,執行階段不會產生 GC。

  ```csharp
  fsm.SetData("Health", 100);
  int hp = fsm.GetData<int>("Health");
  ```

  Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/README.zh-CN.md#L141-L149)

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 主控台輸出 `FSM manager is invalid.` | 在 `FsmComponent.Awake()` 時,框架入口找不到 `IFsmManager` 模組 | 確認場景中存在 GameFrameX 入口元件,且比 `FsmComponent` 初始化更早完成；確認 FSM 套件是否已安裝 |
| 呼叫 `CreateFsm` 後在 `Start` 發生「狀態不存在」錯誤 | 狀態未註冊，或傳入的 owner 型別與 `T` 不一致 | 確認 `CreateFsm<T>` 的 `T` 與 `FsmState<T>` 子類別的 `T` 一致，並確認所有狀態都已加入 `states` 陣列 |
| 同一 owner 型別只能建立一個 FSM | 誤用不含 `name` 的多載，因隱式命名規則而被覆蓋 | 使用包含 `name` 的 `CreateFsm<T>(string name, T owner, params FsmState<T>[] states)` |
| FSM 未更新 | 業務腳本手動停用了 `FixedUpdate`,或 `FsmComponent` 未掛載 | 確認場景中僅存在一個 `FsmComponent`,並避免在狀態內部再次呼叫 `m_FsmManager.FixedUpdate` |

## 背景 (可選)

`FsmComponent` 僅是一個外觀(facade)層，會將請求轉發給 `IFsmManager`(透過 `GameFrameworkEntry.GetModule<IFsmManager>()` 取得)。`[GameFrameXAutoComponent(-6000)]` 標記用於控制元件自動註冊順序,`Count` 則公開目前 FSM 實例數量，供編輯器與執行階段監控使用。`[Preserve]` 標記可確保 IL2CPP 程式碼剝離時公開 API 不會被誤刪。
