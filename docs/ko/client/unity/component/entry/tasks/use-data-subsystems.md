# 리소스, 설정, 로컬라이제이션 및 글로벌 설정 사용 방법

GameFrameX는 "리소스 로딩, 핫업데이트, 로컬라이제이션 문자열, 비즈니스 설정 테이블"이라는 네 가지 데이터 요구 사항을 네 개의 독립된 하위 시스템으로 통합하여, `GameApp.{子系统}` 정적 속성을 통해 통일된 방식으로 접근할 수 있도록 합니다. 이 페이지에서는 비즈니스 코드에서 이 네 가지 컴포넌트를 가져와 가장 일반적인 테이블 읽기 / 설정 읽기 / 다국어 문구 가져오기 / 리소스 로딩 작업을 수행하는 방법을 안내합니다.

## 사전 조건

- `com.gameframex.unity.entry` 패키지가 설치되어 있고, 필요에 따라 해당 런타임 하위 패키지(`GameFrameX.Asset.Runtime`, `GameFrameX.Config.Runtime`, `GameFrameX.GlobalConfig.Runtime`, `GameFrameX.Localization.Runtime`)가 설치되어 있어야 합니다.
- Unity의 **Project Settings → Player → Scripting Define Symbols**에서 해당 매크로가 활성화되어 있어야 합니다(각 컴포넌트는 독립적으로 제어되며, 아래 표 참조).

| 하위 시스템 | 활성화 매크로 | 네임스페이스 |
|--------|--------|----------|
| 리소스 | `ENABLE_GAME_FRAME_X_ASSET` | `GameFrameX.Asset.Runtime` |
| 설정 | `ENABLE_GAME_FRAME_X_CONFIG` | `GameFrameX.Config.Runtime` |
| 글로벌 설정 | `ENABLE_GAME_FRAME_X_GLOBAL_CONFIG` | `GameFrameX.GlobalConfig.Runtime` |
| 로컬라이제이션 | `ENABLE_GAME_FRAME_X_LOCALIZATION` | `GameFrameX.Localization.Runtime` |

매크로가 활성화되어 있지 않으면 해당 `GameApp.{Name}` 속성 전체가 컴파일에 참여하지 않아, 비즈니스 코드에서 "`Asset`를 찾을 수 없음"과 같은 오류가 직접 발생합니다.

## 작업 단계

### 1. 하위 시스템 접근자 가져오기

네 하위 시스템의 진입 구조는 완전히 동일합니다. 임의의 비즈니스 클래스에서 정적 속성 `GameApp.{子系统}`에 직접 접근하면, 첫 접근 시 `GameEntry`에서 해당 컴포넌트를 지연 로딩합니다.

```csharp
// 리소스
var asset = GameApp.Asset;
// 설정
var config = GameApp.Config;
// 글로벌 설정
var globalConfig = GameApp.GlobalConfig;
// 로컬라이제이션
var localization = GameApp.Localization;
```

### 2. Asset 컴포넌트로 리소스 로딩하기

`AssetComponent`는 `GameFrameX.Asset.Runtime` 패키지에서 제공되며, `GameApp.Asset`를 통해 가져옵니다. 호출하기 전에 해당 컴포넌트가 `GameEntry` 시작 프로세스에서 이미 등록되어 있는지 확인하십시오.

```csharp
using GameFrameX.Asset.Runtime;

var asset = GameApp.Asset;
// 실제로 사용 가능한 API는 설치한 Asset 하위 패키지 버전에 따라 다르며,
// 여기서는 진입 호출 방식만 보여 줍니다. 구체적인 시그니처는 하위 패키지 문서를 참조하십시오.
asset.LoadAssetAsync<GameObject>("Assets/Prefabs/Player.prefab", (prefab) =>
{
    Instantiate(prefab);
});
```

## 일반적인 변형

- **비동기 리소스 로딩**: 로딩 완료를 기다리는 콜백에서 `GameApp.Asset.LoadAssetAsync<T>` 계열 메서드를 호출하고, 메인 스레드에서 동기적으로 차단하지 마십시오.
- **다국어 전환**: 언어 전환 후에는 일반적으로 UI 텍스트를 새로 고쳐야 합니다. 구체적인 새로 고침 방식은 Localization 하위 패키지에 따라 결정되지만, 진입점은 항상 `GameApp.Localization`을 사용합니다.
- **설정 테이블 핫 리로드**: Config 하위 패키지를 사용하는 경우 일반적으로 하위 패키지에서 제공하는 `Reload` 인터페이스를 사용해야 하며, 내부 파일을 직접 조작하지 마십시오.

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| 컴파일 오류: `GameApp`에 `Asset` / `Config` 등의 정의가 포함되지 않음 | Player Settings에서 해당 매크로가 활성화되지 않아 해당 partial 클래스가 컴파일에 참여하지 않음 | "사전 조건" 표에 따라 `ENABLE_GAME_FRAME_X_*` 매크로 추가 |
| 런타임에 `GameApp.Asset`가 `null`임 | `GameEntry`에 `AssetComponent`가 등록되지 않음 | 시작 프로세스의 `RegisterComponent` 단계에 해당 컴포넌트 추가 |
| 비즈니스 코드에서 다국어 / 설정 필드를 읽지 못함 | 잘못된 하위 시스템 진입점 사용 | 구분에 유의: `GameApp.Config`는 비즈니스 설정 테이블을, `GameApp.GlobalConfig`는 글로벌 파라미터를, `GameApp.Localization`은 다국어 문구를 읽습니다 |

## 배경(선택 사항)

네 진입 속성은 모두 `static partial class GameApp`의 지연 로딩 속성으로, 첫 접근 시 `GameEntry.GetComponent<T>()`를 통해 등록된 컴포넌트 인스턴스를 가져오고 이후 접근에서는 캐시된 필드를 바로 반환합니다. 각 파일은 해당 `ENABLE_GAME_FRAME_X_*` 매크로로 전체 정의를 감싸고 있어, 비즈니스 프로젝트는 필요에 따라 하위 시스템을 선택적으로 포함할 수 있으며, 프레임워크 전체를 패키지에 컴파일할 필요가 없습니다.
