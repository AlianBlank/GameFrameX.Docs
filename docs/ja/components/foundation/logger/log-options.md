# Logger 動作（LogOptions）の設定方法

`LogOptions` を使用すると、ログの出力先、レベル、ローリングポリシー、および外部ストレージ（ファイル、MongoDB、GrafanaLoki）のすべてのスイッチを一元的に制御できます。本ページを読めば、数行のコードでカスタム設定を完了できます。

## 前提条件

- `GameFrameX.Foundation` アセンブリを参照している、かつターゲットフレームワークが .NET をサポートしている。
- ファイルへのログ出力には、プロセスが `AppDomain.CurrentDomain.BaseDirectory/data/<logPathName>` に対する書き込み権限を保持している必要がある。
- MongoDB への書き込みには、アクセス可能な MongoDB サービスが必要。GrafanaLoki への書き込みには、アクセス可能な Loki サービスが必要。
- 型の名前空間：`GameFrameX.Foundation.Logger`、主要型：`LogOptions`、`RollingInterval`（Serilog）、`LogEventLevel`（Serilog.Events）。

## 設定項目一覧

| プロパティ | 型 | デフォルト値 | 説明 |
|------|------|--------|------|
| `LogSavePath` | `string` | `<BaseDir>/data/logs` | ログファイルの絶対パス。コンストラクタで `logPathName` を連結して生成 |
| `LogFileName` | `string` | `""`（デフォルト名） | ログファイル名。空の場合はデフォルト名を使用 |
| `LogType` | `string` | `null` | ログの発生元となるサーバータイプ |
| `LogTagName` | `string` | `""` | ログの分類に使用するタグ |
| `IsWriteToFile` | `bool` | `true` | ファイルに出力するかどうか |
| `IsConsole` | `bool` | `true` | コンソールにも同時に出力するかどうか |
| `IsFileSizeLimit` | `bool` | `true` | 単一ファイルのサイズを制限するかどうか |
| `FileSizeLimitBytes` | `int` | `100 * 1024 * 1024` | 単一ファイルの上限バイト数。到達後にローリング |
| `RetainedFileCountLimit` | `int?` | `31` | 保持する履歴ログの件数。`null` は無制限を意味する |
| `RollingInterval` | `RollingInterval` | `Day` | ローリング間隔（Hour/Day/Month など） |
| `LogEventLevel` | `LogEventLevel` | `Debug` | 最低出力レベル。このレベルより低いログは記録されない |
| `IsWriteToMongoDb` | `bool` | `false` | MongoDB に書き込むかどうか |
| `MongoDbDatabaseUrl` | `string` | `mongodb://127.0.0.1:27017/gameserver?authSource=admin` | MongoDB 接続文字列 |
| `MongoDbCappedMaxSizeMb` | `int` | `50` | MongoDB キャップ付きコレクションの最大 MB |
| `MongoDbCappedMaxDocuments` | `int` | `50000` | MongoDB キャップ付きコレクションの最大ドキュメント数 |
| `IsGrafanaLoki` | `bool` | `false` | GrafanaLoki に出力するかどうか |
| `GrafanaLokiUrl` | `string` | `http://localhost:3100` | Loki サービスアドレス |
| `GrafanaLokiLabels` | `Dictionary<string,string>` | 空 | Loki ラベル |
| `GrafanaLokiProperty` | `Dictionary<string,string>` | 空 | Loki 追加プロパティ |
| `GrafanaLokiUserName` / `GrafanaLokiPassword` | `string` | `null` | Loki 認証 |
| `GrafanaLokiCompressionEnabled` | `bool` | `true` | Loki プッシュで圧縮を有効にするかどうか |
| `GrafanaLokiBatchSizeLimit` | `int` | `1000` | バッチのしきい値。到達するとプッシュ |
| `GrafanaLokiQueueLimit` | `int` | `100000` | メモリキュー上限。上限に達するとログを破棄 |
| `GrafanaLokiPeriod` | `int`（秒） | `2` | 強制プッシュ周期；`<=0` を渡した場合は 2 にフォールバック |

プロパティのデフォルト値と定義の参照元：[LogOptions.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L47-L289)。

## 操作手順

1. **名前空間を導入してインスタンスを作成**。デフォルトインスタンスは `LogOptions.Default` から直接使用できます。または `CreateDefault()` で個別に変更可能なコピーを取得できます。

```csharp
using GameFrameX.Foundation.Logger;

// デフォルト設定をそのまま再利用（読み取り専用の推奨シナリオ）
var defaults = LogOptions.Default;

// 変更可能なコピーを取得
var options = LogOptions.CreateDefault();
options.LogTagName = "GameServer-01";
```

Source: [LogOptions.cs#L69-L82](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L69-L82)

2. **必要に応じて出力先とファイルポリシーを調整**。一般的な組み合わせ：ファイルを無効化して Loki のみに出力、またはその逆。

```csharp
var options = LogOptions.CreateDefault();

// ファイルポリシー
options.IsWriteToFile = true;
options.RollingInterval = RollingInterval.Day;   // 毎日ローリング
options.IsFileSizeLimit = true;
options.FileSizeLimitBytes = 50 * 1024 * 1024;   // 50MB
options.RetainedFileCountLimit = 14;             // 14 日分のみ保持

// コンソール
options.IsConsole = true;

// レベル
options.LogEventLevel = LogEventLevel.Information;
```

Source: [LogOptions.cs#L243-L277](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L243-L277)

3. **MongoDB に接続**（任意）。

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToMongoDb = true;
options.MongoDbDatabaseUrl = "mongodb://user:password@192.168.1.100:27017/gameserver?authSource=admin";
options.MongoDbCappedMaxSizeMb = 200;
options.MongoDbCappedMaxDocuments = 100000;
```

`IsWriteToMongoDb=true` の場合、有効な `MongoDbDatabaseUrl` を設定する必要があります。接続文字列の形式については、ソースファイルの例を参照してください。Source: [LogOptions.cs#L108-L145](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L108-L145)

4. **GrafanaLoki に接続**（任意）。Loki を有効にした場合は、サービスアドレス、ラベル、認証を設定する必要があります。バッチパラメータを調整すると、スループットとバックプレッシャーを制御できます。

```csharp
var options = LogOptions.CreateDefault();
options.IsGrafanaLoki = true;
options.GrafanaLokiUrl = "http://loki.internal:3100";
options.GrafanaLokiUserName = "loki";
options.GrafanaLokiPassword = "secret";
options.GrafanaLokiLabels["app"] = "gameserver";
options.GrafanaLokiLabels["env"] = "prod";
options.GrafanaLokiBatchSizeLimit = 2000;     // 2000 件ためてからプッシュ
options.GrafanaLokiQueueLimit = 200000;       // メモリキュー上限
options.GrafanaLokiPeriod = 5;                // 5 秒ごとに強制プッシュ
options.GrafanaLokiCompressionEnabled = true;
```

注意：`GrafanaLokiPeriod` に `<=0` を渡すと、強制的に 2 秒にフォールバックします。キューが満杯になると、新しいログは破棄されます（バックプレッシャー保護）。Source: [LogOptions.cs#L168-L235](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L168-L235)

5. **`LogOptions` をログコンポーネントの初期化エントリポイントに渡す**。その後、`LogHelper.Info/Debug/...` を使用して出力します。

```csharp
// ログエントリポイントに LogOptions が必要と仮定
LogHelper.Init(options);

LogHelper.Info("服务启动完成");
LogHelper.Debug("调试信息:玩家 {0} 进入副本", playerId);
```

> 呼び出しエントリポイント名は、お使いのプロジェクトで参照している初期化方法に準じてください（このリポジトリでは、`LogOptions` クラス自体はログチャネルの初期化を担当しません）。

## 一般的なバリエーション

- **マルチテナント／複数サーバーのログを区別する**：`LogType` と `LogTagName` を設定します。ファイルパスは `LogSavePath` の配下に配置され、サーバーごとにディレクトリを分けて管理できます。
- **コンストラクタでルートディレクトリをカスタマイズする**：`new LogOptions("gateway-logs")` とすると、ログは `<BaseDir>/data/gateway-logs` に配置されます。空の場合は `logs` にフォールバックします。

```csharp
var options = new LogOptions("gateway-logs");
options.LogType = "Gateway";
options.LogTagName = "GW-01";
```

Source: [LogOptions.cs#L53-L61](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogOptions.cs#L53-L61)

- **ファイルを無効化して Loki のみを使用する**：コンテナ化されたデプロイに適しており、ログを一元的に集約できます。

```csharp
var options = LogOptions.CreateDefault();
options.IsWriteToFile = false;
options.IsConsole = false;
options.IsGrafanaLoki = true;
```

- **保持ファイル数を無制限にする**：`options.RetainedFileCountLimit = null;`。

## 一般的なエラー

| 症状／誤用 | 原因 | 修正方法 |
|----------|------|------|
| ログファイルが想定するディレクトリに表示されない | `LogSavePath` のデフォルトがカレントディレクトリだと思い込んでいる | 実際のデフォルトは `<AppDomain.BaseDirectory>/data/logs`。コンストラクタ引数 `logPathName` で調整可能 |
| MongoDB を有効化した後に書き込みが失敗する | `MongoDbDatabaseUrl` が未設定、または MongoDB がリッスンしていない | ソースファイルの例に従って接続文字列を入力し、サービスが利用可能であることを確認する |
| Loki へのプッシュがほとんど行われない | `GrafanaLokiBatchSizeLimit` と `Period` の値が大きすぎる | バッチしきい値または `Period` を小さくする。`Period<=0` の場合は強制的に 2 秒にフォールバック |
| ディスク使用量が急増する | `RetainedFileCountLimit` が未設定、または `IsFileSizeLimit=false` | 適切な保持数（14／31 など）を設定し、単一ファイルのサイズ制限を有効にする |
| `LogOptions.Default` の変更が反映されない | `Default` は読み取り専用の静的インスタンスで、すべてで共有されている | `CreateDefault()` で個別のコピーを取得してから変更する |

## 背景（任意）

`LogOptions` は POCO（プロパティのみのオブジェクト）であり、Serilog パイプラインを直接構築しません。実際にこれらのスイッチを使用する初期化ロジックは、ログエントリポイントの実装に存在します。設計上、「どのように記録するか」と「どこに記録するか」を分離しています。レベル、ローリング、圧縮は汎用ポリシーであり、ファイル／MongoDB／Loki は個別に有効化できる sink です。

ログ全体の初期化と `LogHelper` の使用方法については、『Logger クイックスタート』を参照してください。
