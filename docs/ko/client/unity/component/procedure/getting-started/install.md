# Procedure 패키 설치

이 가이드에서는 `com.gameframex.unity.procedure`를 Unity 프로젝트에 설치하여 FSM 기반 게임 흐름 관리 기능을 활성화하는 방법을 설명합니다. 설치가 완료되면 `ProcedureComponent`, `ProcedureManager`, `ProcedureBase`를 사용하여 게임 수명 주기 단계를 구동할 수 있습니다.

## 사전 조건

- Unity **2019.4** 이상 버전(패키지에 선언된 Unity 버전은 [package.json](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/package.json#L7)을 참조하십시오).
- 프로젝트에는 `com.gameframex.unity`(`2.5.1`) 및 `com.gameframex.unity.fsm`(`1.2.0`)의 두 종속성이 필요합니다. 이 저장소의 설치 방식을 통해 도입하면 Unity Package Manager가 자동으로 종속성을 해석하고 가져옵니다.

```json
"dependencies": {
  "com.gameframex.unity.fsm": "1.2.0",
  "com.gameframex.unity": "2.5.1"
}
```
출처: [package.json](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/package.json#L22-L25)

## 작업 단계

원하는 방식 중 하나를 선택하여 설치할 수 있습니다.

### 방식 1:Scoped Registry(UPM 레지스트리)

1. Unity 프로젝트의 `Packages/manifest.json`을 엽니다.
2. 파일 최상위 수준에 `scopedRegistries` 노드를 추가하고, `dependencies`에 이 패키지를 추가합니다.

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.procedure": "1.4.1"
  }
}
```

3. 저장한 후 Unity로 돌아가면 Package Manager가 `GameFrameX` 레지스트리를 통해 `com.gameframex`으로 시작하는 패키지를 자동으로 해석합니다.

> `scopes`는 해당 레지스트리를 사용할 패키지를 결정하며, `com.gameframex.*`만 해석하므로 다른 출처에는 영향을 주지 않습니다.

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L57-L75)

### 방식 2:Git URL 종속성

`Packages/manifest.json`의 `dependencies` 노드 아래에 Git 원격 주소를 직접 추가합니다.

```json
{
  "dependencies": {
    "com.gameframex.unity.procedure": "https://github.com/gameframex/com.gameframex.unity.procedure.git"
  }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L77-L82)

### 방식 3:Unity Package Manager에서 Git URL 추가

1. Unity를 열고 메뉴 `Window > Package Manager`를 선택합니다.
2. 왼쪽 위의 `+`를 클릭하고 `Add package from git URL...`을 선택합니다.
3. 주소 `https://github.com/gameframex/com.gameframex.unity.procedure.git`을 입력한 후 `Add`를 클릭합니다.

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L83-L83)

### 방식 4:Packages 디렉터리에 직접 배치

이 저장소를 직접 복제하거나 다운로드한 후 Unity 프로젝트의 `Packages/` 디렉터리 아래에 배치합니다(예: `Packages/com.gameframex.unity.procedure`). Unity가 자동으로 로컬 패키지로 인식하여 로드합니다.

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L84-L84)

## 일반적인 변형

- **특정 버전 고정**: manifest에서 `"com.gameframex.unity.procedure": "1.4.1"`과 같은 정확한 버전 번호를 사용하여 자동 업그레이드로 흐름 논리가 손상되는 것을 방지합니다. `package.json`의 현재 버전은 `1.4.1`입니다.
- **Git 태그/브랜치에 고정**: Git URL 형식 뒤에 `#1.4.1` 또는 `#main`을 추가합니다. 예를 들어 `https://github.com/gameframex/com.gameframex.unity.procedure.git#1.4.1`과 같이 사용하면 롤백하거나 개발 진행 상황을 따라가기 쉽습니다.
- **로컬 경로 디버깅**: 저장소를 manifest에 로컬 경로 패키지로 기록합니다(`"file:../com.gameframex.unity.procedure"`). 수정과 디버깅을 동시에 수행하기 편리합니다.

## 일반적인 오류

- **`scopedRegistries`를 선언하지 않고 바로 종속성을 작성함**: UPM이 기본 npm을 통해 `com.gameframex.*`를 해석하게 되어 설치가 실패합니다. 먼저 방식 1에 따라 레지스트리를 추가한 후 종속성을 작성하십시오.
- **scope가 잘못됨**: `com.gameframex`를 사용해야 하며 `package.json`의 `name` 접두사와 일치해야 합니다. 그렇지 않으면 해당 레지스트리에서 패키지가 해석되지 않습니다.
- **여러 ProcedureComponent 복사본을 동시에 도입함**: `Packages/` 아래에 이 패키지 소스가 하나만 존재하는지 확인하여 `Already exist FSM`과 같은 충돌을 방지하십시오.
- **Unity 버전이 너무 낮음**: `unity` 필드는 `2019.4`로 선언되어 있으므로, 이보다 낮은 버전의 Unity에서는 패키지 내 스크립트를 컴파일하거나 실행하지 못할 수 있습니다.

## 검증

1. Unity에서 `Window > Package Manager`를 열고 목록에 `Game Frame X Procedure`가 표시되는지 확인하며, 버전이 예상과 일치하는지 확인합니다.
2. 프로젝트에 임의의 C# 스크립트를 만들고 `using GameFrameX.Procedure;`를 입력합니다. 컴파일이 통과하면 패키지가 올바르게 설치된 것입니다.
3. 메뉴 `GameFrameX > Procedure`를 통해 `ProcedureComponent`를 추가합니다. Inspector에 설정 항목이 표시되면 런타임에서 사용할 수 있음을 의미합니다.
