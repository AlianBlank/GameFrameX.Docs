# コンポーネントが追加できない、または重複マウントされた場合の対処法

`CoroutineComponent` の追加失敗、追加直後に削除される、Inspector で「Can't add component」エラーなどが発生する場合、通常は Unity の重複マウント制限、`[DisallowMultipleComponent]` 属性、または GameFrameX フレームワークの自動マウントフローが原因であることが多い。本ページでは、一般的な症状の迅速な特定と修復方法を紹介する。

## 迅速な診断

| 症状 | 原因 | 修復 |
|------|------|------|
| `AddComponent<CoroutineComponent>()` を実行後、`Can't add component ... because a MonoBehaviour is already attached` エラーが発生 | 同じ GameObject にすでにコンポーネントが存在し、`CoroutineComponent` には `[DisallowMultipleComponent]` が付与されている | 下記の「先に削除してから追加」セクションを参照 |
| 手動で AddComponent 後、シーンの再ロードやシーン切り替えでコンポーネントが消える | GameFrameX フレームワークのフローを経由しておらず、コンポーネントがフレームワークの `GameFrameXAutoComponent` スキャナーによってマウントされていない | 下記の「フレームワークによる自動マウント」セクションを参照 |
| iOS / IL2CPP でビルド後、実行時に `CoroutineComponent` 型が見つからない | Unity のリンカによって削除された | 下記の「ビルド後の消失」セクションを参照 |
| `CoroutineComponent` がシーン内の複数の GameObject に現れ、「重複マウント」のように見える | 各 GameObject に 1 つずつマウントすることは許可されている。実際に重複が拒否されるのは「同じ GO」上のみ | 下記の「『複数 GO』と『同一 GO 重複』の区別」セクションを参照 |

## 修復手順

### 先に削除してから追加(同一 GO への重複マウント)

`CoroutineComponent` はソースコードで `[DisallowMultipleComponent]` が付与されており、これは MonoBehaviour の組み込み属性で、同じ GameObject に複数マウントすることを禁止している。

```csharp
// エラー: Can't add component 'CoroutineComponent' because a MonoBehaviour is already attached.
// 修正: 既存のものを先に削除してから追加するか、既存の参照をそのまま使用する
if (gameObject.TryGetComponent<CoroutineComponent>(out var exist))
{
    // すでに存在する場合はそのまま使用する。AddComponent を繰り返さないこと
}
else
{
    exist = gameObject.AddComponent<CoroutineComponent>();
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L15)

### フレームワークによる自動マウント

通常、**ビジネスコード内で手動で `AddComponent<CoroutineComponent>()` を呼ばないこと**。代わりに GameFrameX フレームワークが `[GameFrameXAutoComponent(-6500)]` 属性を通じて、フレームワーク起動時にフレームワークエントリの GameObject に自動的にマウントする。コンポーネントの `Awake()` 内で `IsAutoRegister = false` を設定しており、ランタイムでの再登録フローには参加しない。

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Coroutine")]
[GameFrameXAutoComponent(-6500)]
public class CoroutineComponent : GameFrameworkComponent
{
    protected override void Awake()
    {
        IsAutoRegister = false;
        base.Awake();
    }
}
```

Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L110)

もし手動でマウントする必要がある場合は、以下を確認すること:
1. GameObject がアクティブ状態であること。
2. 現在、同じ名前の他のコンポーネントインスタンスが存在しないこと(前セクションを参照)。
3. `GameFrameworkComponent` 基底クラスが存在するホスト GameObject にマウントし、フレームワークのインスタンスとの重複を避けること。

### ビルド後の消失

IL2CPP / iOS のリンカは、明示的に参照されていない MonoBehaviour 型を削除する可能性がある。ソースコードでは、空の `MonoBehaviour` と `[Preserve]` を使用して型が削除されないようにしている:

```csharp
[Preserve]
public class GameFrameXCoroutineCroppingHelper : MonoBehaviour
{
    [Preserve]
    private void Start()
    {
        _ = typeof(CoroutineComponent); // CoroutineComponent を強制的に保持
    }
}
```

Source: [GameFrameXCoroutineCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/GameFrameXCoroutineCroppingHelper.cs#L1-L15)

修復:
1. シーン内に `GameFrameXCoroutineCroppingHelper` がアタッチされた GameObject が存在することを確認する(またはコード内で明示的に `CoroutineComponent` を参照していること)。
2. Unity Player Settings → Managed Stripping Level は iOS では `Low` / `Medium` よりもさらに厳しいレベルに設定しないこと。設定する場合は、名前空間 `GameFrameX.Coroutine.Runtime` を除外する `link.xml` を別途設定する必要がある。

### 「複数 GO」と「同一 GO 重複」の区別

- **複数の GO にそれぞれ 1 つずつマウント**(例: 各 UI パネルにそれぞれ 1 つ):これは正当な使い方であり、それぞれが自身のコルーチンを管理する。
- **同一 GO に 2 つマウント**:`Can't add component` エラーが発生するので、上記の対処方法を参照。

フレームワークが「重複マウント」して複数のインスタンスが存在すると疑われる場合は、Hierarchy で `Coroutine` を検索し、それらが実際に異なる GameObject にあることを確認すること。すべてが同じ GO 上にある場合は、1 つだけ残せば十分である。

## 検証

修復後、以下の方法で確認すること:

1. Unity Console に `Can't add component` エラーがもう表示されないこと。
2. Play Mode 開始後、Hierarchy でフレームワークエントリ GameObject 上の `CoroutineComponent`(`GameFrameX/Coroutine` メニュー名がマークされたもの)を確認できること。
3. `StartCoroutine` 呼び出し後、コルーチンが正常に動作し、`StopCoroutine(IEnumerator)` を同じ参照で呼び出して正常に停止できること——これは、コンポーネントが正しくマウントされ、フレームワークに管理されていることを示している。
