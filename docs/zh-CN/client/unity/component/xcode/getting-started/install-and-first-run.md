# 安装与首次运行

GameFrameX Xcode 配置是一个 Unity Package，安装后无需写任何 C# 代码，只需在工程里放置一个 `XCodeConfig.json`，iOS 构建结束时会自动完成 Info.plist、签名、Capabilities、CocoaPods 等 Xcode 工程修改。本页带你从安装包到第一次跑通完整流程。

## 快速开始

### 1. 安装包

任选以下一种方式（推荐 scopedRegistries，便于统一管理版本）：

**方式一：Scoped Registry（可指定版本）** — 编辑 `Packages/manifest.json`：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.xcode": "1.11.1"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L47-L63)

`scopes` 控制哪些包通过此注册表解析：只有以 `com.gameframex` 开头的包才会从这个注册表获取。

**方式二：Git URL** — 在 `manifest.json` 的 `dependencies` 节点下添加：

```json
{
   "com.gameframex.unity.xcode": "https://github.com/gameframex/com.gameframex.unity.xcode.git"
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L67-L72)

**方式三：Package Manager** — 在 Unity 的 `Package Manager` 中使用 `Git URL` 方式添加，地址同上。

**方式四：直接下载仓库** 放置到 Unity 项目的 `Packages` 目录下，会自动加载识别。

环境要求：Unity 2019.4 及以上。

### 2. 创建配置文件

配置文件**必须命名为 `XCodeConfig.json`**，可放在项目任意位置；支持多个文件并存，构建时自动深度合并（适合多模块协作）。若需按渠道区分，可再建 `XCodeConfig.{渠道名}.json`，渠道配置最后合并、优先级最高。

顶层结构如下：

```json
{
  "swiftBridging": true,
  "signing": {},
  "plist": {},
  "environmentVariables": {},
  "launcherArgs": [],
  "podSource": [],
  "podfile": "",
  "podInstall": true,
  "localizations": [],
  "capabilities": {},
  "unityFramework": {},
  "unityMain": {}
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L79-L96)

最小可用示例（关闭 Bitcode + 写一条 plist + 添加一个系统框架）：

```json
{
  "plist": { "NSCameraUsageDescription": "用于拍摄头像" },
  "unityMain": {
    "properties": { "=": { "ENABLE_BITCODE": "NO" } },
    "frameworks": { "+": [ "WebKit.framework" ], "-": [] }
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L145-L173)

常用顶层字段速览：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `swiftBridging` | bool | 自动生成 Swift 桥接头文件（默认 `true`） |
| `signing` | object | 代码签名配置（Team ID、Bundle Identifier 等） |
| `plist` | object | Info.plist 键值对，值支持任意类型 |
| `capabilities` | object | iOS 应用能力（内购、推送、iCloud 等） |
| `podfile` / `podInstall` | string / bool | 自定义 Podfile 路径 / 是否自动执行 `pod install`（默认 `true`） |
| `unityMain` / `unityFramework` | object | 分别对应 Unity-iPhone 与 UnityFramework target 配置 |

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L98-L111)

### 3. 构建 iOS 并验证

1. 在 Unity 中将平台切换到 iOS，执行构建（File → Build Settings → Build）。
2. 构建结束后，工具自动在 `[PostProcessBuild(888)]` 回调中执行——晚于大多数其他后处理脚本，且仅在 `BuildTarget.iOS` 下生效：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        //读取配置文件
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 如果没有找到任何匹配的文件，直接返回
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L32)

3. 检查 Unity Console 日志。看到下面这些输出即表示安装成功、流程已跑通：
   - `[MergeConfig] 正在合并配置: <你的 XCodeConfig.json 路径>`
   - `[PBXProject] 正在应用最终合并配置...`
   - `[OtherSettings] 正在应用最终合并配置...`
4. 打开生成的 Xcode 工程确认效果：Info.plist 中出现你配置的键、Build Settings 中 `ENABLE_BITCODE` 已变为 `NO` 等。

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L38-L107)

如果日志出现 `未找到任何 XCodeConfig 相关配置文件, 跳过设置`，说明文件名不是 `XCodeConfig.json`（区分大小写）或不在工程目录内，改名/移动后重新构建即可。

## 常见变体

- **多模块多配置**：不同模块各自放一份 `XCodeConfig.json`，构建时按文件顺序深度合并；同键以"后合并者覆盖"。
- **渠道差异化**：通过 `SettingLoader.GetChannel()` 检测渠道，读取 `XCodeConfig.{channel}.json` 并最后合并覆盖。相关逻辑见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)。
- **跳过 pod install**：配置 `"podInstall": false` 可跳过自动执行 `pod install`；有自定义 Podfile 时通过 `"podfile": "<路径>"` 指定（优先级高于 `pods` 字段）。见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L128-L156)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| Console 报 `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 文件名不是 `XCodeConfig.json`，或不在工程目录内 | 严格按 `XCodeConfig.json` 命名（区分大小写）后重新构建 |
| Console 报 `<路径> 解析失败, 跳过合并` | JSON 语法错误 | 用 JSON 校验工具检查后修正重新构建 |
| Console 报 `合并后的配置为空，跳过设置` | 文件存在但内容为空对象 | 至少写入一个有效字段 |
| 构建后 Xcode 工程无变化 | 构建目标不是 iOS，或回调抛异常被吞掉 | 确认 BuildTarget 为 iOS；检查 Console 是否有 `Debug.LogException` 输出的异常堆栈 |

以上错误消息均来自 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L83) 的真实日志原文。

## 验证

1. Console 出现 `[MergeConfig]` → `[PBXProject]` → `[OtherSettings]` 三段日志，无红色 Error。
2. 用 Xcode 打开构建输出目录，确认：Info.plist 已写入 `plist` 配置项；Build Settings 符合 `properties` 设置；若配置了 `podfile`/`pods`，工程目录下 Podfile 已生成且依赖已安装。

## 背景

工具分两阶段写入：第一阶段把构建属性、框架、库、文件复制、编译标志等应用到 `Unity-iPhone` 与 `UnityFramework` 两个 target 并保存 `project.pbxproj`；第二阶段处理 Plist、环境变量、启动参数、Capabilities、本地化与 CocoaPods，并在 Capabilities 独立写盘后重新读取工程文件以保留其修改。Swift 桥接默认开启，只在主项目上设置签名与 Capabilities。完整实现见 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)。
