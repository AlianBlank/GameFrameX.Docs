# RSA 암호화/복호화 및 서명 사용 방법

`RsaHelper`는 RSA 비대칭 암호화를 정적 메서드로 캡슐화하여 Base64 키의 암복호화, 서명/검증, 그리고 XML 키의 키 쌍 생성과 인스턴스 암복호화를 지원합니다. 이 페이지에서는 키 생성부터 암복호화, 서명/검증까지의 전체 흐름을 안내합니다.

## 사전 조건

- 프로젝트에서 `GameFrameX.Foundation.Encryption` 어셈블리를 참조하고 `using GameFrameX.Foundation.Encryption;`를 추가합니다.
- .NET 런타임이 `System.Security.Cryptography.RSA`를 지원해야 합니다(.NET 6+ 권장).
- Base64 형식(PKCS#8/PKCS#1) 또는 XML 형식의 RSA 키 쌍을 준비합니다. 키가 없는 경우 `RsaHelper.Make()`로 즉시 생성할 수 있습니다.

## 작업 단계

### 1. RSA 키 쌍 생성(XML 형식)

```csharp
using GameFrameX.Foundation.Encryption;

var keyPair = RsaHelper.Make(); // 딕셔너리를 반환하며, "privateKey"와 "publicKey"를 포함합니다.
string privateKeyXml = keyPair["privateKey"];
string publicKeyXml  = keyPair["publicKey"];
```

딕셔너리의 두 키는 각각 XML 형식의 개인 키(`Modulus`, `Exponent`, 개인 파라미터 등 포함)와 공개 키이며, 직접 저장하거나 Base64로 변환할 수 있습니다.

### 2. 공개 키로 암호화, 개인 키로 복호화(XML 키)

`Encrypt(string, string)`와 `Decrypt(string, string)`는 XML 형식의 키를 받아 Base64 문자열을 반환합니다.

```csharp
using GameFrameX.Foundation.Encryption;
using System.Text;

string plain = "Hello, RSA!";

// 암호화: 공개 키 XML + 평문 → Base64 암호문
string cipher = RsaHelper.Encrypt(publicKeyXml, plain);

// 복호화: 개인 키 XML + Base64 암호문 → 평문
string back = RsaHelper.Decrypt(privateKeyXml, cipher);
```

바이트 배열을 직접 사용하려면, 암호화 측은 `RsaHelper.Encrypt(string publicKey, byte[] content)`, 복호화 측은 `RsaHelper.Decrypt(string privateKey, byte[] content)`를 사용하세요.

### 3. 공개 키로 암호화, 개인 키로 복호화(Base64 키)

`EncryptBase64`와 `DecryptBase64`는 Base64로 인코딩된 키를 받으며, 내부적으로 PKCS#8 / PKCS#1을 자동 인식합니다.

```csharp
string cipher64 = RsaHelper.EncryptBase64(publicKeyBase64, plain);
string plain64 = RsaHelper.DecryptBase64(privateKeyBase64, cipher64);
```

암호화는 **OAEP-SHA256** 패딩을 사용하며, 평문이 단일 블록의 최대 크기를 초과하면 자동으로 블록 단위로 암호화되므로 임의 길이의 데이터에 적합합니다.

### 4. 개인 키 서명, 공개 키 검증

서명과 검증은 SHA256 + PKCS#1 패딩을 고정으로 사용하며, 키 역시 PKCS#8과 PKCS#1을 모두 지원합니다.

```csharp
string signature = RsaHelper.Sign(privateKeyBase64, plain);
bool ok = RsaHelper.Verify(publicKeyBase64, plain, signature);
```

`Verify`가 `true`를 반환하면 서명이 유효한 것입니다. 공개 키/데이터/서명 중 하나라도 변조되면 `false`를 반환합니다.

### 5. 인스턴스로 동일한 키 쌍 재사용

반복적으로 암복호화가 필요한 시나리오에 적합합니다(생성 시 `RSA` 리소스를 보유하므로 `Dispose`를 잊지 마세요).

```csharp
using (var helper = new RsaHelper(privateKeyXml))
{
    string cipher = helper.Encrypt(plain);             // 인스턴스 공개 키로 암호화 (XML 개인 키에는 공개 키 파라미터도 포함됨)
    string back   = helper.Decrypt(cipher);            // 인스턴스 개인 키로 복호화
}
```

또는 `System.Security.Cryptography.RSA` 인스턴스를 직접 전달할 수도 있습니다: `new RsaHelper(rsaInstance)`.

## 일반적인 변형

| 시나리오 | 권장 API | 키 형식 |
|------|---------|----------|
| Java/Go 등과의 상호 운용, 키는 PEM 내부의 Base64 구간 | `EncryptBase64` / `DecryptBase64` / `Sign` / `Verify` | PKCS#8 또는 PKCS#1 Base64 |
| 내부 .NET 시스템, 키를 설정 파일에 장기 저장 | `Make()` + `Encrypt` / `Decrypt` | XML |
| 대용량 파일 블록 단위 암호화 | `EncryptBase64` / `DecryptBase64` | Base64(자동 블록 분할) |
| 동일 키로 여러 번 호출, 반복 임포트 방지 | `new RsaHelper(key)` 인스턴스화 | XML 또는 `RSA` 객체 |

## 일반적인 오류

| 증상 | 원인 | 처리 방법 |
|------|------|------|
| `CryptographicException` "Bad Data" | Base64 문자열이 올바른 PKCS#8/PKCS#1 키가 아님 | PEM에서 `-----BEGIN/END-----` 및 줄바꿈을 제거한 후 Base64인지 확인 |
| `Encrypt`에서 "Key not valid for use in specified state" 오류 | XML 문자열이 공개 키가 아닌 개인 키임 | `Make()`가 반환한 `publicKey`만 암호화에 사용 가능 |
| `Verify`가 항상 `false`를 반환 | 서명된 데이터가 변경됨, 키 쌍이 일치하지 않음, 또는 서명에 다른 해시가 사용됨 | 서명에 사용된 원본 UTF-8이 검증 시와 동일한지 확인, 양쪽 모두 SHA256 사용 |
| 암복호화 결과가 깨짐 | 양쪽의 패딩 방식이 일치하지 않음 | `EncryptBase64`/`DecryptBase64`는 반드시 쌍으로 사용해야 하며, 모두 OAEP-SHA256임 |

## 배경 지식 (선택)

- 암호화 패딩: C-05 수정 이후, 암복호화는 통일하여 `RSAEncryptionPadding.OaepSHA256`를 사용하며, PKCS#1 v1.5의 Bleichenbacher 공격 위험을 피합니다.
- 서명 패딩: 서명/검증은 고정적으로 `RSASignaturePadding.Pkcs1` + `HashAlgorithmName.SHA256`을 사용하며, 대부분의 외부 시스템 기본값과 일치합니다.
- 리소스 관리: 인스턴스 메서드는 비관리 RSA 리소스를 보유하므로, `new RsaHelper(...)` 사용 후 반드시 `Dispose()`를 호출하거나 `using`을 사용해야 합니다.
