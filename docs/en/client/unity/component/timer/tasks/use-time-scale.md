# Using Time Scale: Making Timers Affected/Unaffected by Time.timeScale

Each timer can independently choose its time scale: `TimerTimeScale.Unscaled` (real time, default) or `TimerTimeScale.Scaled` (affected by `UnityEngine.Time.timeScale`). Simply specify it via the `timeScale` parameter when calling `Add`.

## Prerequisites

- The GameFrameX Timer package has been imported into the project, and an `ITimerManager` / `TimerManager` instance has been obtained (e.g., via `TimerComponent`).

## Time Scale Enum Quick Reference

`TimerTimeScale` is a `byte` enum, defined as follows:

| Name | Value | Behavior |
|------|----|------|
| `Unscaled` | 0 | Unaffected by `Time.timeScale` (default value, compatible with existing behavior) |
| `Scaled` | 1 | Affected by `Time.timeScale` |

```csharp
public enum TimerTimeScale : byte
{
    /// <summary>Unaffected by <see cref="UnityEngine.Time.timeScale"/> (default, compatible with existing behavior).</summary>
    Unscaled = 0,

    /// <summary>Affected by <see cref="UnityEngine.Time.timeScale"/>.</summary>
    Scaled = 1,
}
```

2. Add a timer **unaffected** by `Time.timeScale` (e.g., UI countdown, reconnection countdown) — omit `timeScale`, or explicitly pass `Unscaled`:

```csharp
// Defaults to Unscaled: this timer keeps ticking even when the game is paused (timeScale = 0)
timer.Add(1000f, 0, callback);
```

3. Add a timer **affected** by `Time.timeScale` (e.g., game logic timing in scenarios such as slow motion or pause menus) — explicitly pass `timeScale: TimerTimeScale.Scaled`:

```csharp
// Affected by Time.timeScale (suitable for slow motion, pause menus, etc.)
timer.Add(1000f, 0, callback, timeScale: TimerTimeScale.Scaled);
```

## Common Variants

- **Pause menu**: Set `Time.timeScale` to 0; use `Scaled` timers for game logic (they freeze accordingly), and `Unscaled` timers for popup animations/countdowns (they keep ticking).
- **Slow motion**: Set `Time.timeScale` to 0.5; `Scaled` timers tick at half their original speed, while `Unscaled` timers are unaffected.
- **Mixing within the same manager**: Both modes can be mixed within the same `TimerManager`; the update loop selects the time source according to each timer's mode:

```csharp
float delta = timerItem.TimeScaleMode == TimerTimeScale.Scaled ? elapseSeconds : realElapseSeconds;
```

Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L81)

## Common Mistakes

- **Assuming the default is affected by timeScale**: The default value of `Add`'s `timeScale` parameter is `Unscaled`; as long as `Time.timeScale` is unchanged, both modes behave identically (`timeScale = 1`), but once you pause or slow down the game, timers that did not explicitly pass `Scaled` will not slow down. When you need to follow game time, you must explicitly write `timeScale: TimerTimeScale.Scaled`.
- **Scaled timers getting "lost" after `timeScale = 0`**: The timer is not removed; the per-frame delta is simply 0; it will resume ticking once `Time.timeScale` is restored.
- **Positional argument mix-ups**: `timeScale` comes after `callbackParam` and `tag`, but before `onComplete`; it is recommended to always use the named argument `timeScale: TimerTimeScale.Scaled` to avoid misplacement.

## Background

`TimerManager`'s update method receives both scaled time and real time deltas; when updating each timer, it selects based on that timer's `TimeScaleMode`: `Scaled` uses `elapseSeconds`, `Unscaled` uses `realElapseSeconds`, so the two modes do not interfere with each other; when a timer object is recycled and reused, `TimeScaleMode` is reset to `Unscaled` (see [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L633)).
