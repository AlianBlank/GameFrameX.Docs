# 미니게임 플랫폼适配配置

`GameFrameX.Setting`은 `PlayerPrefsSettingHelper` + 플랫폼 전용 `ISettingStorageBackend`를 통해 도우인, 웨이신, 콰이서우, 알리페이 미니게임에 적응하며, 수동으로 전환할 필요가 없고 런타임에 플랫폼에 따라 자동으로 해당 SDK를 선택합니다.

## 사전 조건

| 플랫폼 | 필요한 SDK 패키지 | 백엔드 구현 |
|------|-------------|---------|
| 도우인 미니게임 | `TTSDK`(TTStorage) | `DouYinMiniGameSettingStorage` |
| 웨이신 미니게임 | `WeChatWASM`(WXSDKManagerHandler) | `WeChatMiniGameSettingStorage` |
| 콰이서우 미니게임 | KS SDK | `KuaiShouMiniGameSettingStorage` |
| 알리페이 미니게임 | Alipay SDK | `AlipayMiniGameSettingStorage` |

각 플랫폼 SDK는 해당 미니게임 개발자 도구/Unity 변환 플러그인에서 가져와 프로젝트 `Assets/` 디렉토리에 배치해야 하며, 그렇지 않으면 컴파일 시 `WeChatWASM.WXSDKManagerHandler`, `TTSDK.TTStorage` 등의 타입을 찾을 수 없어 오류가 발생합니다.

## 작업 단계

1. Unity에서 `com.gameframex.unity.setting` 패키지(버전 ≥ 1.5.2)를 설치합니다.

   Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/package.json#L1-L20)

2. 씬에서 임의의 `GameObject`에 `SettingComponent`를 부착합니다. `Setting Helper Type Name` 필드는 기본값인 `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper`로 유지합니다.

3. 대상 미니게임 플랫폼 SDK를 설치합니다(웨이신 미니게임 예시):

   ```text
   Unity 웨이신 미니게임 변환 플러그인을 통해 프로젝트를 웨이신 미니게임 프로젝트로 게시하고,
   Assets/WX-WASM-SDK/ 아래의 WeChatWASM 어셈블리를 사용할 수 있는지 확인합니다.
   ```

4. 대상 플랫폼으로 컴파일 및 게시합니다. 프레임워크는 `SubsystemRegistration` 단계에서 플랫폼 백엔드를 자동으로 등록하므로 적응 코드를 작성할 필요가 없습니다:

   ```csharp
   [UnityEngine.RuntimeInitializeOnLoadMethod(UnityEngine.RuntimeInitializeLoadType.SubsystemRegistration)]
   private static void Register()
   {
       SettingStorageBackendFactory.RegisterMiniGameBackend(() => new WeChatMiniGameSettingStorage());
   }
   ```

   Source: [WeChatMiniGameSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/MiniGame/WeChat/WeChatMiniGameSettingStorage.cs#L5-L9)

5. 일반 Unity 프로젝트처럼 설정을 읽고 쓰면 데이터는 해당 플랫폼의 네이티브 저장소에 저장됩니다:

   ```csharp
   SettingComponent setting = ...;
   setting.SetString("PlayerName", "PlayerOne");
   setting.SetFloat("Volume", 0.8f);
   setting.Save();
   ```

## 플랫폼 저장소 매핑

| 백엔드 | 표준 Unity | 도우인 | 웨이신 | 콰이서우 | 알리페이 |
|------|:-:|:-:|:-:|:-:|:-:|
| PlayerPrefsSettingHelper(기본값) | PlayerPrefs | TTStorage | WX SDK | KS SDK | Alipay SDK |
| DefaultSettingHelper(선택) | 파일 I/O | 파일 I/O | 파일 I/O | 파일 I/O | 파일 I/O |

`PlayerPrefsSettingHelper`는 미니게임 환경에서 해당 플랫폼의 네이티브 KV 저장소로 자동 브릿지됩니다. `DefaultSettingHelper`를 사용하면 모든 플랫폼이 `Application.persistentDataPath` 파일 저장소를 사용합니다.

### 파일 저장소 강제 사용

일부 서브 플랫폼(예: PC 미니게임 디버거)에서 미니게임 플랫폼 SDK가 작동하지 않는 경우, `Setting Helper Type Name`을 `GameFrameX.Setting.Runtime.DefaultSettingHelper`로 변경하면 모든 읽기/쓰기가 파일 I/O를 사용합니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| 컴파일 시 `WeChatWASM.WXSDKManagerHandler`가 존재하지 않음 | 웨이신 미니게임 SDK가 설치되지 않음 | Unity 웨이신 미니게임 변환 플러그인을 통해 SDK 통합 |
| 컴파일 시 `TTSDK.TTStorage`가 존재하지 않음 | 도우인 SDK가 설치되지 않음 | 도우인 미니게임 Unity 변환 플러그인 설치 |
| 데이터 손실 또는 재시작 후 읽을 수 없음 | `DefaultSettingHelper`를 사용 중이며 미니게임 플랫폼 파일 시스템이 정리됨 | `PlayerPrefsSettingHelper`로 다시 전환하여 데이터가 플랫폼 네이티브 KV에 저장되도록 함 |
| `setting.Save()`가 false 반환 | 플랫폼 저장소 쓰기 실패(용량 부족, 권한 없음) | 미니게임 백엔드 저장소 용량 및 사용자 권한 확인 |

## 검증

1. 에디터 또는 대상 플랫폼 빌드 결과물에서 `setting.SetString("MiniGameTest", "ok"); setting.Save();`를 실행합니다.
2. 종료 후 다시 시작하여 `setting.GetString("MiniGameTest", "miss")`를 호출하면 `"ok"`이 반환되어야 합니다.
3. 미니게임 개발자 도구의 "로컬 저장소" 패널에서 해당 키를 볼 수 있다면 백엔드가 적용된 것입니다.

## 배경(선택 사항)

`PlayerPrefsSettingHelper`는 `SettingStorageBackendFactory`를 통해 현재 플랫폼의 `ISettingStorageBackend`를 가져옵니다. 각 플랫폼 백엔드는 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` 단계에서 자신을 등록하며, 최초 호출 시 플랫폼 매크로/컴파일 심볼에 따라 인스턴스가 선택됩니다. 설계상 "KV 읽기/쓰기"와 "플랫폼 SDK 호출"이 분리되어 있어, 새 플랫폼을 추가하려면 `ISettingStorageBackend`를 구현하고 등록하기만 하면 됩니다.
