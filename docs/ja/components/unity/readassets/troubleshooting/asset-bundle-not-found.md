# AssetBundle 読み込み時に FileNotFoundException が発生した場合の対処法

`BlankReadAssets.LoadAssetBundle` または `BlankReadAssets.LoadAssetBundleAsync` を呼び出す際、渡された相対パスが StreamingAssets 内のリソースに一致しない場合、フレームワークは `System.IO.FileNotFoundException("File not found", path)` を直接スローします。これはパス解析失敗の最も一般的な兆候です。

## クイック診断

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `FileNotFoundException: File not found`(メッセージにパスが含まれる) | パスに対応するファイルが見つからない。大文字小文字、スラッシュ、StreamingAssets への未配置の 3 つのケースが代表的 | `FileExists` で事前チェック。相対パスと `/` 区切りを統一。リソースが `Assets/StreamingAssets/` 下にあることを確認 |
| Editor では見つかるが、パッケージビルド後に Android 実機で見つからない | APK 内のリソースが圧縮され、デフォルトの `AssetBundle.LoadFromFile` からは読み込めない | `BlankReadAssets.SetCompressedAssetBundleFileNames(...)` を呼び出して圧縮リストを登録 |
| 例外発生前にリソースは実際に存在するのに、見つからないと表示される | パスプレフィックスが `StreamingAssets/xxx` になっている。フレームワークが既にこのプレフィックスを暗黙的に除去している | `StreamingAssets/` プレフィックスを取り除き、相対サブパスのみを渡す |

## 修正手順

### 1. FileExists でパスを事前チェックする

`BlankReadAssets.LoadAssetBundle` の内部では、まず `GetInfoOrThrow` が呼ばれ、見つからない場合は `ThrowFileNotFound` が呼び出されて例外が直接スローされます。まず `FileExists` で確認すれば、パスの記述ミスかリソースの欠落かをすばやく特定できます。

```csharp
if (!BlankReadAssets.FileExists("ui/prefab/main.ab"))
{
    Debug.LogError("AssetBundle が存在しません。StreamingAssets に配置されているか確認してください");
    return;
}
var bundle = BlankReadAssets.LoadAssetBundle("ui/prefab/main.ab");
```

例外の原文と発生位置は以下の通りです。

```csharp
private static void ThrowFileNotFound(string path)
{
    throw new FileNotFoundException("File not found", path);
}
```

### 2. パスは StreamingAssets からの相対サブパスである必要があり、`/` を使用する

フレームワークの `LooseFilesImpl.TryGetInfo` は、渡されたパスと `s_root` を連結したうえで `File.Exists` を呼び出します。

```csharp
var fullPath = s_root + path;
if ( !File.Exists(fullPath) )
{
    return false;
}
info.readPath = fullPath;
```

Source: [BlankReadAssets.LooseFilesImpl.cs#L57-L71](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L57-L71)

- 正しい例:`"ui/prefab/main.ab"`(`Assets/StreamingAssets/ui/prefab/main.ab` に対応)
- 誤った例:`"StreamingAssets/ui/prefab/main.ab"`、`"ui\\prefab\\main.ab"`、絶対パス
- 大文字小文字を区別:Android 実機のファイルシステムは厳密に大小文字を区別します

### 3. APK 内の圧縮された AssetBundle を識別する

`AssetBundle.LoadFromFile` はデフォルトでは、APK 内の圧縮されていないファイルのみ読み取れます。ビルドパイプラインで `.ab` を APK に圧縮している場合、使用前に圧縮されたファイル一覧を登録する必要があります。さもないと、下層の `AssetBundle.LoadFromFile` が `FileNotFoundException` をスローするか、破損したパッケージを返します。登録方法については `BlankReadAssets.SetCompressedAssetBundleFileNames` を参照してください。このエントリは `AndroidIsCompressedFileStreamingAsset` partial メソッドを通じて、ホストプロジェクトに実際のファイル名リストを注入させます。

```csharp
// ホストプロジェクトで必要に応じて拡張
BlankReadAssets.SetCompressedAssetBundleFileNames(
    "ui/prefab/main.ab",
    "ui/prefab/login.ab"
);
```

### 4. ロードエントリ

ロードインタフェース自体のシグネチャは以下の通りです。例外はパス解析段階でスローされ、実際のパッケージ読み込み失敗は Unity 内部からスローされます。

```csharp
public static AssetBundleCreateRequest LoadAssetBundleAsync(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFileAsync(info.readPath, crc, (ulong)info.offset);
}

public static AssetBundle LoadAssetBundle(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFile(info.readPath, crc, (ulong)info.offset);
}
```

Source: [BlankReadAssets.cs#L119-L130](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L119-L130)

`GetInfoOrThrow` がファイルを見つけられたものの `AssetBundle.LoadFromFile` が依然としてエラーを返す場合、問題はパッケージビルドの成果物自体(CRC 不一致、offset の誤り、圧縮など)にあり、ビルド側を再確認する必要があります。

## 検証

1. `LoadAssetBundle` を呼び出す前に `BlankReadAssets.FileExists(path)` を呼び出し、`true` が返ることを確認します。
2. Editor で正常に読み込めるパスを、実機にそのままコピーします。大小文字、区切り文字、ディレクトリ階層が完全に一致している必要があります。
3. Android 実機で `FileExists` が `true` にもかかわらず読み込みが失敗する場合、`.ab` が APK 内で圧縮されていないかを確認し、`SetCompressedAssetBundleFileNames` に登録します。
