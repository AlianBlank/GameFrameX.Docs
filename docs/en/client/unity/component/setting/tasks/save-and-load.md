# Saving and Loading Configuration

Use the GameFrameX Setting component to write game configuration (player preferences, level parameters, etc.) to a persistent backend, and read it back when needed. This page provides the minimal path to save and load within a Unity project.

## Prerequisites

- The `com.gameframex.unity.setting` package has been imported into the Unity project.
- The `GameFrameX/Setting` component (`SettingComponent`) is attached to the scene. It automatically calls `Load()` during `Start`, and selects the default `PlayerPrefsSettingHelper` via `m_SettingHelperTypeName`.

## Steps

1. **Confirm the default Helper type**. `SettingComponent` uses `PlayerPrefsSettingHelper` by default, which can read and write in PlayerPrefs without any changes. To switch to a mini-game platform, change `Setting Helper Type Name` in the Inspector to the corresponding `AlipayMiniGameSettingStorage` / `DouYinMiniGameSettingStorage` / `KuaiShouMiniGameSettingStorage` / `WeChatMiniGameSettingStorage`.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L52-L100)

2. **Write configuration**. Use the `SetXxx` series of methods of `SettingComponent` to write values to memory:

   ```csharp
   using GameFrameX.Setting.Runtime;

   var setting = GameFrameXEntry.GetComponent<SettingComponent>();
   setting.SetBool("MusicOn", true);
   setting.SetInt("Level", 3);
   setting.SetString("PlayerName", "Alice");
   setting.SetFloat("Volume", 0.8f);
   ```

   The write methods only modify memory and do not persist immediately.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L225-L228)

3. **Call Save() to persist**. Execute at an appropriate time (e.g., when exiting the game or before switching scenes):

   ```csharp
   setting.Save();
   ```

   `PlayerPrefsSettingHelper.Save()` delegates to the current platform's `ISettingStorageBackend.Save()` for the actual write. The return value indicates whether the save was successful, and you can log it for debugging.

   Source: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L99-L102)

4. **Read configuration**. `SettingComponent.Start()` has already called `Load()`, so you can use `GetXxx` to read at the next scene entry:

   ```csharp
   bool musicOn = setting.GetBool("MusicOn", true);     // with default value
   int level   = setting.GetInt("Level", 1);
   string name = setting.GetString("PlayerName", "");
   float vol   = setting.GetFloat("Volume", 1.0f);
   ```

   Each `GetXxx` provides an overload with a default value, which is returned when the key does not exist.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L102-L108)

5. **Manage keys**. Query, delete a single or all configuration items:

   ```csharp
   if (setting.HasSetting("Level")) { /* ... */ }
   setting.RemoveSetting("Level");
   setting.RemoveAllSettings();
   ```

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs#L157-L185)

## Common Variations

- **Cross-platform writing**. Change `m_SettingHelperTypeName` to the mini-game platform's corresponding `*MiniGameSettingStorage`, and no read/write logic changes are required.
- **Custom backend**. Implement `ISettingStorageBackend` and inject it via `PlayerPrefsSettingHelper.SetStorageBackendForTests` (you can also use `SettingStorageBackendFactory.Create()` in a custom `SettingHelperBase` subclass).
- **Batch updates**. Call `Save()` once at the end of a business event to avoid writing to disk for every change.

## Common Mistakes

- **Forgot to call Save()**: `SetXxx` only modifies memory. Without calling `Save()`, the data will not be persisted and will be lost after restart.
- **Reading during startup**: Do not read in `Awake`. `SettingComponent` executes `Load()` only in `Start`. The read logic should be placed in `Start` or later.
- **Relying on enumerating all keys**: PlayerPrefs does not support `GetAllSettingNames()`. Calling it will return `null` and print the `GetAllSettingNames is not supported.` warning. Instead, maintain your own list of known keys at the business layer.

## Background (Optional)

`SettingComponent` is the MonoBehaviour entry point, `SettingManager` is the dependency-free module core, and `SettingHelperBase` dispatches reads and writes to the specific backend. `PlayerPrefsSettingHelper` selects the corresponding platform's backend implementation via `SettingStorageBackendFactory` by default, thereby being compatible with both PlayerPrefs and mini-game platform storage under the same API.
