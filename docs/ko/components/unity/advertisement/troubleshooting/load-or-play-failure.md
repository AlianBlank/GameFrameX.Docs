# 광고 로드 또는 재생 실패 시 대처 방법

`Play(...)` 또는 `Load(...)`가 실패 콜백을 트리거할 때, 일반적으로 설정 누락, 광고 슬롯 ID 미입력, SDK 미초기화 또는 콜백 미바인딩이 원인입니다. 아래에서 증상에 따라 원인을 대조하여 위치를 파악한 후 단계별로 수정하세요.

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `Play`가 바로 `OnFail`로 진입하고, 로그에 광고 이벤트가 없음 | `Initialize`를 호출하지 않았거나 `m_config`가 null | `Start` 전에 `AdvertisementComponent`에 `AdvertisementConfig`를 주입하거나, Inspector에서 설정 에셋 체크 |
| `Log.Fatal("Advertisement manager is invalid.")` | 프레임워크에 광고 매니저 구현이 등록되지 않음 | `BaseAdvertisementManager` 서브클래스에서 `AdvertisementConfigAttribute`로 등록하고, 씬 시작 체인에 추가 |
| 로드/재생 시 콜백이 전혀 발생하지 않음 | `AdvertisementPlayOption.OnSuccess/OnFail/OnShowResult` 미할당 | `Play` 호출 전에 `AdvertisementPlayOption`의 세 가지 Action 모두 할당 |
| iOS/Android/미니게임 로드 시 설정이 비어 있음 | 현재 플랫폼에 해당하는 광고 슬롯 ID 필드가 비어 있음 | `m_adUnitIdAndroid`, `m_adUnitIdiOS`, 미니게임 3종(`WeChat` / `DouYin` / `KuaiShou`) 중 해당 필드 입력 |
| `Play`는 오류를 보고하지만 `OnShowResult`는 false 반환 | 전시流程은 성공했으나 SDK에서 미완료 재생으로 표시 | 광고 슬롯 심사 상태 및 소재가 거부되었는지 확인, "광고 슬롯 심사 거부" 섹션 참조 |
| `Load` 사용 중단 경고 | 구 API 사용 | `Play(AdvertisementPlayOption)`을 사용하고, `Load(success, fail)`는 사용하지 않음 |

## 수정 단계

### 1. 광고 매니저 등록 여부 확인

`AdvertisementComponent.Awake()`는 리플렉션을 통해 `IAdvertisementManager` 구현을 가져오며, 가져오지 못하면 바로 `Log.Fatal`을 출력합니다. 다음을 확인하세요:

- 사용자 정의 매니저 클래스에 `[AdvertisementConfigAttribute]`가 있고 `BaseAdvertisementManager`를 상속받는지
- 해당 클래스가 프로젝트에서 실제로 런타임 어셈블리로 컴파일되는지
- 씬에 `AdvertisementComponent`가 존재하고 `componentType` 필드가 사용자 정의 매니저를 가리키는지

참조 구현 위치:[AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L87-L118)

### 2. AdvertisementConfig 주입

`Start()`는 `m_config != null`일 때만 `_advertisementManager.Initialize(m_config)`를 호출합니다. Inspector에서 광고 설정 에셋을 `m_config` 필드에 드래그하거나, 코드에서 명시적으로 초기화하세요:

```csharp
var component = GameEntry.GetComponent<AdvertisementComponent>();
component.Initialize(myAdvertisementConfig);
```

출처: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L120-L140)

### 3. 현재 플랫폼에 광고 슬롯 ID 입력

`AdUnitId`는 플랫폼 컴파일 지시문에 따라 값을 가져오며, 어느 한 분기라도 비어 있으면 후속 SDK가 유효한 ID를 받지 못합니다. 자주 누락되는 경우:

- Android 채널에 iOS ID만 입력
- WebGL에서 일반 ID를 선택했지만, `ENABLE_WECHAT_MINI_GAME` / `ENABLE_DOUYIN_MINI_GAME` / `ENABLE_KUAISHOU_MINI_GAME` 매크로를 활성화하여 미니게임 전용 슬롯을 입력하지 않음

Inspector에서 `m_adUnitIdAndroid` / `m_adUnitIdiOS` / `m_adUnitIdWebGL*` 중 최소 하나에 값이 있는지 확인하세요.

출처: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L47-L57)

### 4. 재생 콜백 완성

`AdvertisementPlayOption`의 세 가지 Action 중 하나라도 할당되지 않으면 해당 콜백은 트리거되지 않습니다:

```csharp
var option = new AdvertisementPlayOption
{
    OnSuccess = json => Debug.Log($"보상 지급 성공: {json}"),
    OnFail    = err  => Debug.LogError($"재생 실패: {err}"),
    OnShowResult = shown => Debug.Log($"완전 노출: {shown}"),
    customData = "level=1",
};
component.Play(option);
```

`extraData`는 Load 단계에서만 서버로 직렬화되어 전달되며, 로드 완료 후 변경은 적용되지 않습니다.

출처: [AdvertisementPlayOption.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementPlayOption.cs#L44-L84)

### 5. 사용 중단된 Load 사용 금지

`BaseAdvertisementManager.Load(Action<string>, Action<string>, string)`는 `[Obsolete("Use Play(AdvertisementPlayOption) instead.")]`로 표시되어 있으며, 계속 사용하면 경고만 발생하고 새流程로 자동 연결되지 않으므로, `Play(AdvertisementPlayOption)`을 통일하여 사용하세요.

출처: [BaseAdvertisementManager.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/BaseAdvertisementManager.cs#L236-L238)

### 6. 디버그 모드를 통한 문제 해결

`m_debug = true`로 설정하거나(또는 `Initialize` 호출 시 두 번째 인자에 `true` 전달), SDK가 더 자세한 요청 로그를 출력하게 하여 네트워크, 서명, 광고 슬롯 반환 오류 코드 중 어느 것인지 위치 파악하세요.

출처: [AdvertisementComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.advertisement/blob/main/Runtime/Advertisement/AdvertisementComponent.cs#L59)

## 검증

수정 후 다음 항목을 하나씩 확인하세요:

1. 시작 로그에 `Advertisement manager is invalid.` 치명적 로그가 더 이상 나타나지 않음.
2. `Play` 호출 시 `OnSuccess` 또는 `OnFail` 중 최소 하나가 트리거되며, "완전 무음" 상태가 아님.
3. Android / iOS / 위챗 미니게임 / 도우인 / 콰이쇼우 미니게임 등 컴파일 대상으로 전환 시 `AdUnitId`가 비어 있지 않음.
4. 광고 플랫폼 백엔드에서 광고 슬롯 상태가 "승인됨"이고, 빈도 제한 정책이 트리거되지 않았는지 확인.
