# 이벤트를 트리거하는 방법: Fire, FireNow 및 매개변수 없는 이벤트

GameFrameX.Event에서 이벤트를 트리거하려면 `EventComponent`의 `Fire`(스레드 안전, 다음 프레임 메인 스레드 콜백), `FireNow`(즉시 동기 디스패치) 또는 `Fire(sender, eventId)`(커스텀 이벤트 인수가 필요 없는 바로 가기) 세 가지 중 하나를 호출하기만 하면 됩니다. 본 문서에서는 세 가지 사용법의 전체 단계, 적용 시나리오 및 일반적인 함정을 소개합니다.

## 사전 조건

- 씬에 GameFrameX 진입점이 이미 존재하며, `EventComponent`가 프레임워크에 의해 자동으로 마운트됩니다(컴포넌트 메뉴는 `GameFrameX/Event`, [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43) 참조).
- 이미 해당 이벤트 ID를 구독한 사람이 있어야 하며, 그렇지 않으면 트리거해도 수신자가 없습니다(기본 핸들러를 함께 사용해 폴백할 수 있음, 아래 "일반적인 변형" 참조).

## 작업 단계

1. 이벤트 컴포넌트 참조를 가져옵니다(MonoBehaviour에 마운트하거나 프레임워크 진입점에서 가져옴):

   ```csharp
   using GameFrameX.Event.Runtime;

   private EventComponent eventComponent;
   // Awake/Start에서:
   // eventComponent = GameEntry.GetComponent<EventComponent>();
   ```

2. 이벤트 인수 클래스를 준비합니다(`GameEventArgs` 상속, `Create` 팩토리 및 `Clear`/회수 규약 제공):

   ```csharp
   public class LevelUpEventArgs : GameEventArgs
   {
       public int Level { get; private set; }
       public static LevelUpEventArgs Create(int level) { /* ... */ }
   }
   ```

3. 지연 모드 트리거(기본 권장, 스레드 안전) — 이벤트는 발생 후 다음 프레임에 메인 스레드에서 콜백됩니다:

   ```csharp
   eventComponent.Fire(this, LevelUpEventArgs.Create(5));
   ```

   출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L124-L128)

   해당 컴포넌트의 API 시그니처:

   ```csharp
   // 이벤트를 발생시킵니다. 이 작업은 스레드 안전하며, 메인 스레드에서 발생시키지 않더라도
   // 이벤트 처리 함수가 메인 스레드에서 콜백되는 것이 보장되지만, 이벤트는 발생 후 다음 프레임에 디스패치됩니다.
   public void Fire(object sender, GameEventArgs e)
   {
       m_EventManager.Fire(sender, e);
   }
   ```

   출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L142-L150)

4. 즉시 모드 트리거(메인 스레드에서만 사용) — 이벤트가 즉시 동기적으로 디스패치되며, 호출이 반환되기 전에 핸들러가 이미 실행을 완료합니다:

   ```csharp
   eventComponent.FireNow(this, LevelUpEventArgs.Create(5));
   ```

   출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L130-L134)

   ```csharp
   // 이벤트를 즉시 모드로 발생시킵니다. 이 작업은 스레드 안전하지 않으며, 이벤트는 즉시 디스패치됩니다.
   public void FireNow(object sender, GameEventArgs e)
   {
       m_EventManager.FireNow(sender, e);
   }
   ```

   출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L163-L171)

5. 트리거가 완료된 후 디스패치 결과를 관찰할 수 있습니다. 세 가지 방식 비교:

   | API | 디스패치 시점 | 스레드 안전 | 일반적 용도 |
   |-----|---------|---------|---------|
   | `Fire(object, GameEventArgs)` | 다음 프레임, 메인 스레드 | 예 | 기본 선택; 자식 스레드/비동기 작업에서 이벤트 발생 |
   | `FireNow(object, GameEventArgs)` | 즉시, 동기 | 아니오 | UI 클릭 등 메인 스레드 즉각 응답, "이벤트 처리 완료" 상태를 읽어야 하는 후속 처리 |
   | `Fire(object, string)` | 다음 프레임, 메인 스레드 | 예 | 매개변수 없는 알림(내부적으로 `EmptyEventArgs`로 래핑) |

## 일반적인 변형

**매개변수 없는 이벤트(바로 가기)**: 일회성 알림을 위해 인수 클래스를 정의하고 싶지 않을 때 문자열 ID를 직접 전달하면, 컴포넌트 내부에서 `EmptyEventArgs.Create(eventId)`로 래핑한 후 `Fire`를 호출하며, 먼저 `eventId`에 대해 비어 있지 않은지 검증합니다:

```csharp
public void Fire(object sender, string eventId)
{
    GameFrameworkGuard.NotNullOrEmpty(eventId, nameof(eventId));
    m_EventManager.Fire(sender, EmptyEventArgs.Create(eventId));
}
```

출처: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L152-L161)

```csharp
eventComponent.Fire(this, "level_up");
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L136-L140)

**자식 스레드에서 트리거**: 스레드 풀, Task 또는 네트워크 콜백에서 이벤트를 발생시킬 때는 반드시 `Fire`를 사용해야 합니다. 콜백이 메인 스레드(다음 프레임)에서 발생하는 것이 보장되므로, 콜백 내에서 Unity API에 직접 접근할 수 있습니다.

**구독자가 없을 때 폴백**: 구독자가 없는 ID를 트리거해도 오류가 발생하지 않지만, "이벤트를 보냈는데 아무도 받지 않는" 문제를 조사할 수 있도록 기본 핸들러를 설정할 수 있습니다:

```csharp
eventComponent.SetDefaultHandler(OnDefaultEvent);

void OnDefaultEvent(object sender, GameEventArgs e)
{
    Debug.Log($"未处理的事件: {e.Id}");
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L142-L151)(API는 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L133-L140)에 위치)

## 일반적인 오류

| 현상 | 원인 | 해결 방법 |
|------|------|------|
| `Fire` 후 같은 프레임에서 처리 결과를 읽을 수 없음 | `Fire`는 지연 디스패치이며 다음 프레임에 콜백됨 | 같은 프레임에 결과가 필요할 때는 `FireNow` 사용 |
| 자식 스레드에서 `FireNow` 호출 후 콜백 동작이 비정상 | `FireNow`는 스레드 안전하지 않음 | 자식 스레드에서는 항상 `Fire` 사용 |
| 트리거 후 핸들러에서 얻은 데이터가 잘못되거나 비어 있음 | 인수 객체가 회수되어 재사용되었거나 올바르게 `Create`되지 않음 | 트리거할 때마다 인수 클래스의 `Create(...)`를 호출하고, 이전 인스턴스를 캐시하지 않기 |
| 이벤트를 보냈는데 아무런 반응이 없음 | 대상 ID를 구독한 사람이 없음 | `eventComponent.Check(id, handler)` 또는 `Count(id)`로 확인하고, 필요시 기본 핸들러를 설정하여 관찰 |
| `Fire(sender, eventId)`가 인수 검증 예외를 발생시킴 | `eventId`가 null이거나 빈 문자열임 | 비어 있지 않은 문자열 ID를 전달하도록 보장(`GameFrameworkGuard.NotNullOrEmpty` 검증) |

## 검증

- 핸들러 내에서 로그를 남겨 이벤트 수신을 확인합니다: `Debug.Log($"升级到 {args.Level} 级")`(예시는 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L102-L106) 참조).
- 통계 속성으로 교차 확인: `eventComponent.EventHandlerCount` / `eventComponent.EventCount` / `eventComponent.Count("level_up")`([EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L47-L61) 및 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/README.zh-CN.md#L153-L159) 참조).

## 배경

`EventComponent`는 단순한 얇은 래퍼일 뿐이며 실제 로직은 `IEventManager`(`EventManager`)에 있습니다. `Fire`는 이벤트 풀의 큐를 활용해 다음 프레임 메인 스레드에서 일괄 디스패치하므로 스레드 안전합니다. `FireNow`는 큐를 건너뛰고 핸들러를 직접 동기 호출합니다. 이벤트 구독 및 구독 취소에 대해서는 《이벤트 구독 및 구독 취소 방법》을 참조하십시오.
