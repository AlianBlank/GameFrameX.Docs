# 事件收不到或回调没触发

当 `EventComponent.Subscribe(DownloadXxxEventArgs.EventId, ...)` 订阅后，下载开始、更新、成功、失败四类回调从未触发,或仅触发其中一部分时,按本页诊断表排查。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| 四类事件全部没触发 | 未把 `EventComponent` 注入到 `DownloadComponent`,或 `DownloadComponent` 未挂载 | 见下文"检查 EventComponent 与 DownloadComponent" |
| `EventId` 写错 / 用了字符串字面量 | 不同 `*EventArgs` 类的 `EventId` 由 `typeof(...).FullName` 生成,拼写错误不会匹配 | 见下文"使用 EventId 常量而非字符串" |
| 订阅成功,但实际下载没发生 | `AddDownload` 入参的 `downloadPath` / `downloadUri` 空,或被 `Paused = true` 卡住 | 见下文"确认任务真正进入下载队列" |
| 只能收到 Start,收不到 Success / Failure | `DownloadAgentHelperCount` 设为 0,或 `m_CustomDownloadAgentHelper` 未赋值 | 见下文"代理池未启动" |
| `OnDownloadSuccess` 收到后 `args.SerialId` 不匹配 | 在回调里把所有下载任务当成同一个处理;或订阅时还没保存 serialId | 见下文"按 SerialId 区分任务" |
| 协程退出 / 场景切换后回调丢失 | 订阅绑定的对象被销毁但未 `Unsubscribe`;或新场景重新 `Subscribe` 多次 | 见下文"订阅生命周期管理" |

## 修复步骤

### 检查 EventComponent 与 DownloadComponent

事件链路依赖两个组件同时存在。`DownloadComponent` 内部只持有一个 `EventComponent` 引用,启动时注入,缺失则事件永远不会派发。

```csharp
var downloadComponent = GameEntry.GetComponent<DownloadComponent>();
var eventComponent = GameEntry.GetComponent<EventComponent>();
if (downloadComponent == null || eventComponent == null)
{
    Debug.LogError("请确认 DownloadComponent 与 EventComponent 都已挂载到 GameEntry");
}
```
[Runtime/Download/DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L46-L62) 中 `DownloadComponent` 是 `[GameFrameXAutoComponent(-4000)]` 自动注册组件;`EventComponent` 来自 `com.gameframex.unity.event` 依赖包(见 [package.json](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/package.json))。

### 使用 EventId 常量而非字符串

所有 `*EventArgs` 的 `EventId` 由 `typeof(...).FullName` 生成,直接使用静态字段最稳妥:

```csharp
eventComponent.Subscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess);
eventComponent.Subscribe(DownloadFailureEventArgs.EventId, OnDownloadFailure);
eventComponent.Subscribe(DownloadStartEventArgs.EventId, OnDownloadStart);
eventComponent.Subscribe(DownloadUpdateEventArgs.EventId, OnDownloadUpdate);
```
四个事件参数类源码:
- [DownloadSuccessEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadSuccessEventArgs.cs#L39-L42)
- [DownloadFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/EventArgs/DownloadFailureEventArgs.cs#L40-L42)

不要手写 `"GameFrameX.Download.Runtime.DownloadSuccessEventArgs"` 之类的字符串;命名空间或类名一旦变化就会失配。

### 确认任务真正进入下载队列

`AddDownload` 返回 `int serialId`,只有任务真正派发到代理才会触发 Start,完成才会触发 Success/Failure。先打印 serialId 并轮询状态确认:

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);
Debug.Log($"serialId={serialId}");

TaskInfo info = downloadComponent.GetDownloadInfo(serialId);
Debug.Log($"status={info?.Status}, currentLength={info?.CurrentLength}");
```
如果 `info == null` 或 `Status` 一直是 `Waiting`,先检查 `downloadComponent.Paused` 是否为 `true`。

### 代理池未启动

代理数为 0、或者自定义 Helper 为空但 `m_DownloadAgentHelperTypeName` 指向一个不存在的类型,会导致任务堆积在等待队列、永远不会有回调:

- 检查 Inspector 上 `Download Agent Helper Count` ≥ 1(默认 3,见 [DownloadComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L60))。
- 自定义 Helper 时,要么填写 `m_CustomDownloadAgentHelper`,要么保证 `m_DownloadAgentHelperTypeName` 是有效类型名;二者不能同时为空。

### 按 SerialId 区分任务

回调是全模块广播的,不区分任务。一定要用 `args.SerialId` 跟自己保存的 serialId 对比:

```csharp
int serialId = downloadComponent.AddDownload(localPath, remoteUrl);

void OnDownloadSuccess(object sender, GameEventArgs e)
{
    var args = (DownloadSuccessEventArgs)e;
    if (args.SerialId == serialId)
    {
        // 是我这次发起的任务
    }
}
```
源码示例见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/README.zh-CN.md#L113-L126)。

### 订阅生命周期管理

`EventComponent.Subscribe` 注册的是强引用回调,持有 `this`。订阅对象销毁后,事件队列里仍残留悬挂引用,新场景 `Subscribe` 多次还会重复触发。建议:

1. 在 `OnDestroy` / `OnDisable` 中 `eventComponent.Unsubscribe(DownloadSuccessEventArgs.EventId, OnDownloadSuccess)`。
2. 全局只订阅一次,放到常驻管理器中,不要放在每次 `Start()` 都执行一次的脚本里。

## 验证

按上述步骤修完后,跑一次小文件下载,在所有回调里加 `Debug.Log`:

```csharp
void OnDownloadStart(object sender, GameEventArgs e) =>
    Debug.Log($"Start serialId={(e as DownloadStartEventArgs).SerialId}");

void OnDownloadUpdate(object sender, GameEventArgs e) =>
    Debug.Log($"Update {((DownloadUpdateEventArgs)e).CurrentLength}");

void OnDownloadSuccess(object sender, GameEventArgs e) =>
    Debug.Log($"Success {(e as DownloadSuccessEventArgs).DownloadPath}");

void OnDownloadFailure(object sender, GameEventArgs e) =>
    Debug.LogError($"Failure {(e as DownloadFailureEventArgs).ErrorMessage}");
```

正常情况下,Start → 若干 Update → Success 四类事件都会按顺序打印一次,Failure 只在出错时打印。
