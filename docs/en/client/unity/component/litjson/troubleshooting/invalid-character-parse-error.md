# What to Do When an Invalid Character Exception Occurs

When calling `JsonMapper.ToObject` / `JsonReader` to parse input, if a `JsonException` is thrown with a message like `Invalid character '{0}' in input string`, it means the lexer has encountered a character in the input string that is not in the JSON lexical table. This page helps you quickly identify the cause and fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `Invalid character 'x' in input string` (x is a letter) | The input is not valid JSON, e.g., the first character is bare `xyz`, bare `true`, or non-JSON text (such as XML / YAML / comments) | Use an online JSON validator to confirm the format; ensure the text starts with one of `{`, `[`, a number, a string, or `true`/`false`/`null` |
| The exception message contains a number / control character (such as `Invalid character '\0'`) | A BOM (`\uFEFF`) at the end of the string, a trailing `\r`, or leftover binary bytes | `Trim` / `Trim('\uFEFF')` before parsing; use `StreamReader` with default UTF-8 to strip the BOM when reading streams |
| The exception message contains a backslash `\` followed by an illegal character | The escape sequence in the string is invalid (such as `"\x"`, `"\u00"`, `"\u12"` with insufficient length) | Only these escape sequences are allowed: `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`, `\uXXXX` (4 hex digits) |
| The exception message contains `'` (single quote) or a newline after `,` | JSON is mixed with JavaScript / Python-style syntax (single-quoted strings, comments, trailing commas) | Remove single quotes, use double quotes; remove `//`, `/* */` comments, and extra commas at the end of objects/arrays |
| The exception message contains Chinese characters | `null` / `undefined` / C# default `ToString()`, etc., were passed directly to the parser | First check whether the response body is really JSON (`Content-Type` / first character); if not, don't call `JsonMapper.ToObject` |

The raw template of the exception message comes from the `JsonException(int c)` constructor:

```csharp
internal JsonException(int c) :
    base(string.Format(
             "Invalid character '{0}' in input string", (char)c))
{
}
```

Source: [Runtime/JsonException.cs#L77-L83](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonException.cs#L77-L83)

## Fix Steps

### 1. Print the Raw Input First

Don't just paste `e.Message` in the logs—print out the actual string passed to the parser. The character in the exception message is the problematic character at that position.

```csharp
try
{
    var obj = GameFrameX.LitJSON.Runtime.JsonMapper.ToObject<Dictionary<string, object>>(rawText);
}
catch (GameFrameX.LitJSON.Runtime.JsonException ex)
{
    Debug.LogError($"LitJSON parse failed: {ex.Message} | raw input length={rawText?.Length} | first 64 chars=[{rawText?.Substring(0, System.Math.Min(64, rawText?.Length ?? 0))}]");
}
```

### 2. Handle BOM and Hidden Characters

If the server returns UTF-8 with BOM, or the file was saved by Windows Notepad, a `\uFEFF` will be left at the beginning of the string, and the lexer will throw it as an "invalid first character".

```csharp
using GameFrameX.LitJSON.Runtime;

string rawText = File.ReadAllText(path);
// Strip leading BOM
if (!string.IsNullOrEmpty(rawText) && rawText[0] == '\uFEFF')
    rawText = rawText.Substring(1);

var data = JsonMapper.ToObject<MyData>(rawText);
```

Reference: The state machine in [Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs) throws `JsonException(c)` when it encounters a codepoint not in the table.

### 3. Correct Escape Sequences

JSON strings only support the following escapes; others such as `\'`, `\x`, `\v`, `\u{}`, or `\u` that don't have 4 hex digits will trigger an `Invalid character` exception (occurring at the character after `\`).

| Valid Escape | Description |
|----------|------|
| `\"` | Double quote |
| `\\` | Backslash |
| `\/` | Forward slash |
| `\b` `\f` `\n` `\r` `\t` | Control characters |
| `\uXXXX` | Must be 4 hex digits (e.g., `\u4E2D`) |

### 4. Correct Illegal JSON Syntax

LitJSON is a strict JSON parser and **does not** support JavaScript / JSON5-style extensions:

- Strings must use double quotes, not single quotes `'…'`.
- `//`, `/* */` comments are not allowed.
- Objects / arrays cannot have trailing `,` commas after the last element.
- Numbers cannot have leading zeros or hex literals (`0x1A`).

```csharp
// Wrong — not JSON
var bad = "{ name: 'Tom', age: 18, }";

// Fixed
var good = "{\"name\":\"Tom\",\"age\":18}";
var obj = JsonMapper.ToObject<Dictionary<string, object>>(good);
```

### 5. Confirm the Call Entry Point

See the `JsonMapper.ToObject` entry signature at [Runtime/JsonMapper.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonMapper.cs); the `JsonReader` streaming entry is at [Runtime/JsonReader.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/JsonReader.cs). Regardless of the entry point, lexical errors are wrapped as the same `JsonException`.

## Verification

Confirm the issue is resolved in the following order:

1. Copy the input that triggered the exception into any online JSON validator (such as jsonlint), confirm the format is valid, then go back to the code.
2. Re-run the program and confirm `JsonException` is no longer thrown, and `JsonMapper.ToObject<T>` returns results normally.
3. If the data comes from a network response, also verify the response header `Content-Type: application/json` and the first character of the response body, to avoid feeding HTML error pages or empty responses to the parser.

## Background (Optional)

LitJSON's lexical analysis is based on a finite state machine ([Runtime/Lexer.cs](https://github.com/GameFrameX/com.gameframex.unity.litjson/blob/main/Runtime/Lexer.cs)); the parse table `parse_table` does not accept any non-JSON characters. Once read, it throws `Invalid character '{0}' in input string` via `JsonException(int c)`. The character in the exception message is the problematic character itself, so prioritize looking at this character rather than the string content when diagnosing.
