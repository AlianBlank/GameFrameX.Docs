# Data-Driven Development with Variables and Bindable Properties

In GameFrameX, `Variable<T>` is a strongly-typed data container with reference counting (used to pass weakly-typed values across subsystems), and `BindableProperty<T>` is a reactive property with value-change callbacks (used for UI and logic data binding). This page demonstrates typical use cases of both in data-driven scenarios.

## Prerequisites

- The `GameFrameX.Runtime` namespace has been imported.
- Familiar with GameFrameX's reference pool / `IReference` concept (only required for `Variable<T>`).

## Steps

### 1. Use `Variable<T>` to Carry Cross-Module Data

Inherit `Variable<T>` to implement a concrete type, which can be passed as weakly-typed `object` in events and parameter tables, while also allowing strongly-typed value retrieval when you have the instance.

```csharp
using GameFrameX.Runtime;

public class IntVariable : Variable<int>
{
    public IntVariable() { }
    public IntVariable(int value) { SetValue(value); }
}
```

Usage:

```csharp
var v = ReferencePool.Acquire<IntVariable>();
v.SetValue(42);
int actual = v.Value;                // Strongly-typed value retrieval
object boxed = v.GetValue();         // Weakly-typed boxing (for event arguments)
ReferencePool.Release(v);            // Return to reference pool, will callback Clear()
```

When setting a mismatched type, `SetValue(object)` will throw a `GameFrameworkException` with the following message:

```
Cannot set value of type '{0}' to variable of type '{1}'.
```

> For the overall workflow of the reference pool and `IReference`, see "IReference and Reference Pool".

### 2. Use `BindableProperty<T>` for Value Change Notifications

When `BindableProperty<T>` is assigned a value, if the new and old values are not equal, it will automatically invoke the registered callbacks, commonly used to drive UI refresh.

```csharp
using System;
using GameFrameX.Runtime;

public sealed class PlayerStats
{
    public readonly BindableProperty<int> Hp = new BindableProperty<int>(100);
    public readonly BindableProperty<string> Name = new BindableProperty<string>("Hero");
}
```

Subscribe and unsubscribe:

```csharp
var stats = new PlayerStats();

Action<int> onHp = newHp => Debug.Log($"HP -> {newHp}");
stats.Hp.Add(onHp);                       // Register callback
stats.Hp.Value = 80;                       // Trigger callback, logs "HP -> 80"
stats.Hp.Value = 80;                       // Equal values will not trigger
stats.Hp.Remove(onHp);                     // Remove callback
stats.Hp.Clear();                          // Clear all callbacks
```

### 3. Use `RegisterWithInitValue` When You Need the Current Value Immediately

If you want the callback to be invoked once immediately upon subscription (with the current value passed in), use `RegisterWithInitValue`:

```csharp
stats.Hp.RegisterWithInitValue(newHp => UpdateHpBar(newHp));
```

## Common Variants

| Scenario | Choice | Key API |
|------|------|----------|
| Weakly-typed arguments for events / tasks | `Variable<T>` subclass | `SetValue(object)` / `GetValue()` |
| UI binding / multi-observer synchronization | `BindableProperty<T>` | `Add` / `Remove` / `RegisterWithInitValue` |
| Want to avoid duplicate triggers | `BindableProperty<T>` | Internally uses `Equals` comparison, same values don't trigger |
| Want to pool and reuse variables | `Variable<T>` | `ReferencePool.Acquire / Release` |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Cannot set value of type 'X' to variable of type 'Y'.` | Passing a non-`T` type to `Variable<T>`'s `SetValue(object)` | Perform type conversion at the call site, or use a matching subclass |
| Callback not executed after assignment | New value equals old value, `BindableProperty` internally compares with `Equals` and skips | This is expected behavior; if you need to force notification, use a new instance whose `Equals` returns false |
| `Add(null)` throws exception | `BindableProperty.Add` uses `GameFrameworkGuard.NotNull` validation | Pass a specific `Action<T>` method or lambda |
| Callback still triggers after returning to reference pool | `Variable<T>` has been reclaimed by the pool but external references are still held | Synchronize clearing references when the holder's own `Clear()` is called or released |

## Background (Optional)

- `Variable` implements `IReference`, supports acquisition/release through `ReferencePool`. `Clear()` resets the value to `default(T)`, suitable for reducing GC in "disposable" scenarios like event and task arguments.
- `BindableProperty<T>` internally uses `Equals` to compare old and new values, only invoking the callback when there's a real change; `Add` supports chained return of self, `Remove` must pass the same delegate reference to correctly unbind.
