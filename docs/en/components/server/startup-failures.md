# What to Do When Startup Fails or Database Connection Errors Occur

When a service crashes during startup, or Mongo connection errors appear in logs, the issue is usually a misconfigured `--DataBaseUrl` / `--DataBaseName`, an unready Mongo container, or network/authentication failures. This page helps you quickly locate and fix the problem.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Startup log contains `connection refused` / `No connection could be made` | Mongo port unreachable or wrong address | Check the host and port in `--DataBaseUrl` |
| Startup log contains `Authentication failed` / `authSource` error | Auth source or username/password mismatch | Fix the connection string `?authSource=...` and credentials |
| Startup log contains `Database name cannot be empty` or missing database hint | `--DataBaseName` not passed or database name typo | Add `--DataBaseName=xxx` |
| Abnormal container startup order: Game starts before Mongo | `depends_on` does not wait for healthcheck to pass | Use `condition: service_healthy` to wait for Mongo |
| Local connection to Mongo inside Docker fails | Port not exposed to host or wrong exposed port | Check the `ports` mapping in `docker-compose.yml` |

## Fix Steps

### 1. Verify `--DataBaseUrl` and `--DataBaseName`

The startup arguments must explicitly pass the database connection string and database name. The default values in `docker-compose.yml` are as follows:

```yaml
command:
  - "--DataBaseUrl=mongodb://mongo:27017/?authSource=admin"
  - "--DataBaseName=gameframex"
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L36-L37)

To connect directly to Mongo inside Docker from the local machine, use `mongodb://localhost:37017/?authSource=admin` (corresponding to the `37017:27017` port mapping in the compose file). For the multi-server version, use `localhost:47017` and `gameframex_multi`.

```yaml
ports:
  - "37017:27017"
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L7-L7)

```yaml
ports:
  - "47017:27017"
```

Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L23-L23)

### 2. Wait for Mongo Health Check to Pass

The Game and Social services must wait for Mongo's `healthcheck` to pass before starting. The compose file already enforces this via `condition: service_healthy`; do not change it to `service_started`.

```yaml
depends_on:
  mongo:
    condition: service_healthy
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L21-L23)

The health check command uses `ping` to verify reachability:

```yaml
healthcheck:
  test: [ "CMD", "mongosh", "--quiet", "--eval", "db.runCommand({ ping: 1 }).ok" ]
  interval: 5s
  timeout: 3s
  retries: 20
```

Source: [docker-compose.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.yml#L9-L12)

Manually verify Mongo status:

```bash
docker exec -it gfx-mongo mongosh --quiet --eval "db.runCommand({ ping: 1 }).ok"
# Expected output: 1
```

### 3. Check Data Volumes and Persistence

The multi-server version mounts Mongo data to `./running-multi/mongo:/data/db`. If the host directory lacks sufficient permissions or the disk is full, Mongo will repeatedly restart, causing Game connection instability.

```yaml
volumes:
  - "./running-multi/mongo:/data/db"
```

Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L30-L31)

Make sure the directory is writable and has enough space:

```bash
ls -ld ./running-multi/mongo
df -h ./running-multi/mongo
```

### 4. Fix Authentication Source

By default, no username/password is enabled, and `?authSource=admin` is used only as an admin database identifier. If your Mongo has `mongod --auth` enabled, you need to append credentials to the URL and change `authSource` to the actual authentication database (typically `admin`).

```bash
# Example connection string with authentication enabled
--DataBaseUrl=mongodb://user:password@mongo:27017/?authSource=admin
```

## Verification

After completing the fix, confirm in the following order:

1. Check Mongo health status: `docker ps`, and make sure the `STATUS` column contains `(healthy)`.
2. Restart the Game service: `docker compose up -d --force-recreate game`, and observe that Mongo errors no longer appear in logs.
3. Enter the Mongo container to verify the database is created: `docker exec -it gfx-mongo mongosh --quiet --eval "show dbs"`. You should see `gameframex` or `gameframex_multi`.
4. If it still fails, collect startup logs (`docker logs gfx-game | tail -200`) and continue troubleshooting against the diagnosis table.

## Common Mistakes

- **Using the container's internal hostname to access the local database**. When running a client directly on the host, the `mongo` hostname in `--DataBaseUrl` cannot be resolved; you need to change it to `localhost` or the host machine's IP.
- **Modifying the port mapping but forgetting to update the URL**. After modifying `ports`, the port in `--DataBaseUrl` must also be updated, otherwise Game will still connect using the old port.
- **`depends_on` only specifies `service_started`**. This only waits for the container process to start, not for Mongo to complete initialization, causing repeated transient connection failures.
- **Game does not auto-reconnect after Mongo restarts**. With the default `restart: unless-stopped`, Game requires a manual `docker compose restart game` to reconnect.
