# 如何启用增量构建

在调用 `BuildAsset` 构建资源包时,把 `IsIncrementalBuildPackage` 设为 `true`,构建器会把 YooAsset 的构建模式切换为 `EBuildMode.IncrementalBuild`,只重新打包有变更的资源,跳过未改动部分,从而显著缩短构建时间。

## 前置条件

- 已按《快速开始》接入 `GameFrameX.Builder.Editor` 程序集。
- 当前构建流水线为 `BuiltinBuildPipeline` 或 `RawFileBuildPipeline`(两者的 `BuildParameters` 都支持 `BuildMode` 字段)。
- 本次构建针对的是已有过出包历史的资源包目录,首次构建没有可复用的缓存,效果等同于全量重建。

## 操作步骤

1. **在代码中启用**

   直接给 `BuilderOptions.IsIncrementalBuildPackage` 赋值为 `true` 后调用构建:

   ```csharp
   var options = new GameFrameX.Builder.Editor.BuilderOptions
   {
       PackageName = "DefaultPackage",
       IsIncrementalBuildPackage = true,
   };
   GameFrameX.Builder.Editor.Builder.BuildAsset(options);
   ```

   Source: [Editor/BuilderOptions.cs#L72-L75](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/BuilderOptions.cs#L72-L75)

2. **通过命令行参数启用**

   在 CI / 批处理脚本里加入 `-IsIncrementalBuildPackage` 标志,`Builder.BuildParamsParse` 会把它解析为 `true`(注意命令行方式不需要传值,只要出现该标志即视为启用):

   ```bash
   Unity -batchmode -nographics -quit \
         -projectPath . \
         -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
         -PackageName DefaultPackage \
         -IsIncrementalBuildPackage
   ```

   Source: [Editor/Builder.BuildParamsParse.cs#L90-L93](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L90-L93)

3. **确认生效**

   启动构建后,`Builder.BuildAsset` 会执行下列赋值,把 YooAsset 的构建模式切到增量:

   ```csharp
   buildParameters.BuildMode = _builderOptions.IsIncrementalBuildPackage
       ? EBuildMode.IncrementalBuild
       : EBuildMode.ForceRebuild;
   ```

   Source: [Editor/Builder.BuildAsset.cs#L65](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L65)

   若 `IsIncrementalBuildPackage` 为 `false`(默认值)或不传 `-IsIncrementalBuildPackage`,构建模式则为 `EBuildMode.ForceRebuild`。

## 常见变体

- **同时上传资源并增量构建**:把 `-IsUploadAsset` 与 `-IsIncrementalBuildPackage` 一起带上即可,两个标志独立解析互不影响。
- **回退到全量构建**:发布正式大版本前建议把该参数去掉或显式传 `false`(不传任何标志即默认为 `false`),强制走 `EBuildMode.ForceRebuild` 重建。

## 常见错误

- **首次构建仍按增量跑,误以为生效失败**:增量构建依赖上一次的输出缓存,首次出包没有缓存可复用,产物与全量一致是正常现象。
- **命令行忘了写连字符前缀**:`-IsIncrementalBuildPackage` 必须带 `-`,写成 `IsIncrementalBuildPackage` 不会被解析,会按默认值 `false` 处理。
- **混用 `PackageName` 拼写错误**:增量构建的缓存按包名目录隔离,如果把 `PackageName` 改成了新名字,缓存就匹配不上,表现为"和全量一样慢"。复用旧缓存时务必保持 `PackageName` 一致。

## 背景(可选)

`IsIncrementalBuildPackage` 在 `BuilderOptions` 中只是普通布尔字段,真正生效的位置是 `Builder.BuildAsset` 把它的值映射到 YooAsset 的 `EBuildMode`(增量 vs 强制重建)。命令行与代码两种入口最终汇聚到同一个字段,因此两种方式行为一致。
