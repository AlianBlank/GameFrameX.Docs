# ITimerManager

Timer manager interface, providing core functionality for adding, checking, and removing timed tasks.

## Overview

ITimerManager is the core interface of the GameFrameX Timer module, defining the standard contract for timer management. This interface follows the interface segregation principle, allowing implementations (TimerManager) to be replaced, while TimerComponent provides convenient access for Unity components.

**Design Intent:**
- Provide unified abstraction for timed task management
- Support one-time tasks, recurring tasks, and frame update tasks
- Reduce garbage collection pressure through object pool technology
- Implement thread-safe task scheduling

## Core Methods

### `Add(float interval, int repeat, Action<object> callback, object callbackParam = null)`

Add a timed recurring task.

**Parameters:**
| Parameter | Type | Required | Default | Description |
|--------|------|------|--------|------|
| interval | float | Yes | - | Interval time (seconds) |
| repeat | int | Yes | - | Repeat count (0 means infinite repeat) |
| callback | Action\<object\> | Yes | - | Callback function to execute on timer |
| callbackParam | object | No | null | Parameter passed to the callback function |

**Usage Notes:**
- When `repeat` is 0, the task will execute infinitely
- The callback function's parameter is the value of `callbackParam`
- If the callback already exists, its configuration will be updated and timer reset

```csharp
// Execute every 1 second, stop after 10 executions
timerManager.Add(1.0f, 10, (param) => {
    Debug.Log($"Timer executed: {param}");
}, "hello");
```

### `AddOnce(float interval, Action<object> callback, object callbackParam = null)`

Add a task that executes only once.

**Parameters:**
| Parameter | Type | Required | Default | Description |
|--------|------|------|--------|------|
| interval | float | Yes | - | Delay time (seconds) |
| callback | Action\<object\> | Yes | - | Callback function to execute |
| callbackParam | object | No | null | Parameter passed to the callback function |

**Usage Notes:**
- Internal implementation is `Add(interval, 1, callback, callbackParam)`
- Task is automatically removed after execution

```csharp
// Execute once after 5 seconds
timerManager.AddOnce(5.0f, (param) => {
    Debug.Log("Delayed task executed");
});
```
> Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L20-L26)

---

### `AddUpdate(Action<object> callback)`

Add a per-frame update task (version without parameter).

**Parameters:**
| Parameter | Type | Required | Default | Description |
|--------|------|------|--------|------|
| callback | Action\<object\> | Yes | - | Callback function to execute every frame |

**Usage Notes:**
- Internal implementation is `Add(0.001f, 0, callback)`, approximately executes every frame
- Suitable for per-frame update logic (e.g., animation, state checking)
- Task continues executing until manually removed

```csharp
// Execute every frame
timerManager.AddUpdate((param) => {
    transform.Rotate(Vector3.up, 10 * Time.deltaTime);
});
```
> Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L28-L32)

### `AddUpdate(Action<object> callback, object callbackParam)`

Add a per-frame update task (version with parameter).

**Parameters:**
| Parameter | Type | Required | Default | Description |
|--------|------|------|--------|------|
| callback | Action\<object\> | Yes | - | Callback function to execute every frame |
| callbackParam | object | Yes | - | Parameter passed to the callback function |

```csharp
// Execute every frame and pass parameter
timerManager.AddUpdate((param) => {
    var data = (MyData)param;
    // Process data
}, myData);
```

### `Exists(Action<object> callback): bool`

Check if the specified task exists.

**Parameters:**
| Parameter | Type | Required | Default | Description |
|--------|------|------|--------|------|
| callback | Action\<object\> | Yes | - | Callback function to check |

**Return:**
- `bool`: Returns `true` if task exists, `false` otherwise

**Usage Notes:**
- Checks both the pending queue (_toAdd) and active queue (_items)
- Returns `true` even if the task is marked for deletion (Deleted), as long as it hasn't been removed from the dictionary

```csharp
if (timerManager.Exists(myCallback))
{
    Debug.Log("Callback is registered");
}
```
> Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L41-L46)

---

### `Remove(Action<object> callback)`

Remove the specified task.

**Parameters:**
| Parameter | Type | Required | Default | Description |
|--------|------|------|--------|------|
| callback | Action\<object\> | Yes | - | Callback function to remove |

**Usage Notes:**
- If the task is in the pending queue, it's removed directly and returned to the object pool
- If the task is in the active queue, it's marked as Deleted, removed during next frame Update
- Safe for multiple calls: removing a non-existent callback doesn't throw an exception

```csharp
// Remove task
timerManager.Remove(myCallback);
```
> Source: [ITimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/ITimerManager.cs#L48-L52)

## Internal Implementation Structure

The following is the internal data structure used by the TimerManager implementation class:

```csharp
class TimerItem
{
    public float Interval;        // Interval time
    public int Repeat;           // Remaining repeat count
    public Action<object> Callback;  // Callback function
    public object Param;          // Callback parameter
    public float Elapsed;         // Elapsed time
    public bool Deleted;          // Deletion flag
}
```
> Source: [TimerManager.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/Timer/TimerManager.cs#L14-L31)

## Thread Safety

TimerManager internally uses `lock (Locker)` to ensure thread safety. All public methods (Add, AddOnce, AddUpdate, Exists, Remove) acquire the lock before performing operations.

**Notes:**
- No need to worry about thread safety when calling from the Unity main thread
- If calling from a background thread, you need to handle inter-thread communication yourself

## Exception Handling

TimerManager provides the static property `CatchCallbackExceptions` to control callback exception handling:

```csharp
// Default: do not catch exceptions, exceptions cause task deletion
TimerManager.CatchCallbackExceptions = false;

// Catch exceptions and output warning logs, task will be deleted
TimerManager.CatchCallbackExceptions = true;
```
