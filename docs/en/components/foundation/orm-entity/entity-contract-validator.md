# How to Use EntityContractValidator to Validate Contracts

`EntityContractValidator` is used to validate property consistency between an entity type and the interfaces it implements: for every property declared in an interface, the entity class must have a property with the same name, with a compatible type (`Nullable<T>` and assignable covariance are supported), and must provide the `getter` / `setter` required by the interface.

## Prerequisites

- The project references the `GameFrameX.Foundation.Orm.Entity` assembly.
- The target framework supports `System.Reflection` (all .NET versions are supported).
- The type to be validated is a `class` and implements at least one interface that has properties.

## Steps

1. **Choose the validation entry point**. Two overloads are provided, and both produce identical results:

   ```csharp
   using GameFrameX.Foundation.Orm.Entity;

   // Generic overload (type known at compile time)
   var violations = EntityContractValidator.Validate<MyEntity>();

   // Non-generic overload (Type obtained via reflection at runtime)
   var violations = EntityContractValidator.Validate(typeof(MyEntity));
   ```

   Source: [EntityContractValidator.cs#L57-L87](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L57-L87)

2. **Iterate over the violations and locate the cause**. The return type is `IList<EntityContractViolation>`, and each record contains three fields:

   | Field | Type | Description |
   |------|------|------|
   | `InterfaceType` | `Type` | The interface type that was violated |
   | `PropertyName` | `string` | The name of the missing or mismatched property |
   | `Reason` | `string` | A bilingual (Chinese/English) description of the specific cause |

   Source: [EntityContractViolation.cs#L38-L79](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractViolation.cs#L38-L79)

3. **Typical minimal invocation**:

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       foreach (var v in violations)
       {
           Console.WriteLine($"[{v.InterfaceType.Name}.{v.PropertyName}] {v.Reason}");
       }
   }
   ```

4. **Wire up assertions in CI / at startup** (recommended practice):

   ```csharp
   var violations = EntityContractValidator.Validate<MyEntity>();
   if (violations.Count > 0)
   {
       throw new InvalidOperationException(
           $"实体 MyEntity 违反契约:{string.Join("; ", violations.Select(v => v.Reason))}");
   }
   ```

## The Four Categories of Violations

`ValidateInterface` checks each property on the interface in order and `continue`s as soon as a rule is hit, so each category of violation is triggered at most once:

| Order | Trigger Condition | `Reason` Keyword | Source Lines |
|------|----------|------------------|--------|
| 1 | `GetProperty` throws `AmbiguousMatchException` (multiple inheritance or `new` shadowing) | "multiple declarations exist (possibly shadowed with the new keyword)" | [L100-L108](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108) |
| 2 | The entity class has no public property with the same name | "does not exist" | [L110-L118](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118) |
| 3 | The property type is incompatible (`IsTypeCompatible` returns false) | "type mismatch: expected … actual …" | [L120-L128](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L120-L128) |
| 4 | The interface requires `get` / `set`, but the implementation lacks the corresponding accessor | "missing getter" / "missing setter" | [L130-L144](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144) |

The rules used by `IsTypeCompatible` (supports `Nullable<T>` and covariance):

- Exactly identical → compatible;
- Identical after unwrapping `Nullable` → compatible;
- All remaining cases go through `expected.IsAssignableFrom(actual)`.

## Common Variants

- **Validating generic entity base classes**: `Validate<EntityBase<Guid>>()`, `Validate<EntityTenantBase<Guid>>()`, etc. all return an empty list; all framework built-in base classes are fully self-consistent. ## Common Mistakes

| Incorrect Usage | Symptom | Fix |
|----------|------|------|
| Passing `null` to `Validate(Type)` | Throws `ArgumentNullException` with `ParamName = "entityType"` | Pass a non-null `Type` or use the generic overload instead |
| Implementing interface properties via `explicit interface implementation` | Validation reports "property does not exist" — `GetProperty(Public|Instance)` cannot find explicit implementations | Change the property to a public property, or declare only the members the interface itself needs |
| Shadowing an interface property of the same name with the `new` keyword | Triggers `AmbiguousMatchException` and reports "multiple declarations exist (possibly shadowed with the new keyword)" | Remove `new`, or rename the property so it remains unique in the entity class |
| Implementing `string?` as `string` or vice versa | Reports "type mismatch" | `Nullable<T>` and non-nullable `T` are treated as compatible; keep all other differences consistent |

## Background (Optional)

`ValidateInterface` enumerates all interfaces via `entityType.GetInterfaces()` and, for each interface and each property, looks up the same-named property on the entity class using `BindingFlags.Public | BindingFlags.Instance`; when a rule is hit, it records one `EntityContractViolation` and `continue`s, so a single interface property produces at most one violation. When multiple inheritance or `new` shadowing causes `GetProperty` to throw `AmbiguousMatchException`, the exception is caught and reported with a dedicated message instead of being thrown outward. `IsTypeCompatible` first matches on the exact type, then matches after unwrapping the `Nullable` wrapper, and finally uses `IsAssignableFrom` to handle covariance scenarios.
