# 動作原理：ビルド後処理と設定マージのフロー

iOS ビルド完了後、`PostProcessBuildHelper.OnPostProcessBuild`（コールバック優先度 `888`）が、プロジェクト内の `XCodeConfig.json` という名前のファイルを**すべて**自動的に収集し、ディープマージして 1 つの最終設定（チャネル専用のオーバーライドを含む）にまとめ、その後 2 つのフェーズに分けて設定を生成された Xcode プロジェクトに書き込みます。プロセス全体で手動操作は不要で、設定ファイルをプロジェクト内の任意のディレクトリに置くだけで済みます。

## 起動タイミング

エントリポイントは Unity のビルド後処理コールバックで、iOS プラットフォームでのみ動作します：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }
    ...
}
```

参照元： [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L20)

メソッド本体全体が `try/catch` で囲まれており、例外は `Debug.LogException(e)` で出力されますが、**ビルドは中断されません**（[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L158-L161)）。クラス全体は `#if UNITY_IOS` の条件付きコンパイル内に配置されています。

## 設定の検出とマージ

フローは以下の順序で実行されます：

1. `SettingLoader.LoadSettingsData("XCodeConfig.json")` がプロジェクト内のすべての TextAsset をスキャンし、ファイル名（大文字・小文字を区別しない）で `XCodeConfig.json` と完全一致するファイルを検出します。結果はパス順にソートされ、マージ順序が確実に決定されます。
2. 1 つずつ読み込んで `HashtableFromJson()` で解析し、`finalConfig.Merge(table)` によって同じ `Hashtable` へ深く再帰的にマージします。
3. チャネル識別子が存在する場合、`XCodeConfig.{channel}.json` を読み込んで**最後にマージ**するため、チャネル設定の優先度が最も高くなります。
4. マージ結果が空の場合、以降の設定をスキップします。

主要なコード（共通設定のマージ部分）：

```csharp
var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

if (jsonPaths.Count == 0)
{
    LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
    return;
}

Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    if (table == null)
    {
        LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
        continue;
    }
    finalConfig.Merge(table);
}
```

参照元： [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L25-L49)

## チャネル設定

チャネル名は `SettingLoader.GetChannel()` で取得します。コマンドライン引数 `-channel` を優先し、存在しない場合は EditorPrefs のキー `XCodeBuild_Channel` にフォールバックします：

```csharp
var args = Environment.GetCommandLineArgs();
for (int i = 0; i < args.Length - 1; i++)
{
    if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
    {
        return args[i + 1];
    }
}
string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
if (!string.IsNullOrEmpty(editorChannel))
{
    return editorChannel;
}
return null;
```

参照元： [Editor/SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L18-L36)

チャネル設定ファイル名は、ベース名にチャネル名を連結して生成されます。すなわち `XCodeConfig.{channel}.json` です（[Editor/SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111)）。ヒットした場合は同じ方法で `finalConfig` にマージされ、最後にマージされるため、同じキーは共通設定を上書きします。未ヒットの場合はログを出力するだけで、エラーにはなりません（[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L52-L77)）。

## 2 フェーズの適用フロー

マージ完了後、設定は 2 つのフェーズに分けて Xcode プロジェクトに書き込まれます（[Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)）：

**フェーズ 1：PBXProject（project.pbxproj）への書き込み**

1. `Unity-iPhone.xcodeproj/project.pbxproj` を `PBXProject` として読み込みます。
2. **Unity-iPhone メイン target** に `finalConfig["unityMain"]` を適用します（`Run(...)`、次節を参照）。
3. **UnityFramework target** に `finalConfig["unityFramework"]` を適用します。
4. `SetSigning` で署名を設定します（メイン target のみ）。`signing` ノードを読み取ります。
5. `SetupSwiftBridging` で Swift ブリッジングを設定します。キー `swiftBridging` は**省略時は有効とみなされます**。
6. project.pbxproj に書き戻します。

**フェーズ 2：その他の設定の適用**

1. `RunPlist` が Info.Plist に書き込みます（`plist` ノード）。
2. `RunEnvironmentVariables` が起動時の環境変数を設定します（`environmentVariables`）。
3. `RunArgument` が起動引数を設定します（`launcherArgs`）。
4. `SetCapabilities` が Capabilities を設定します（メイン target のみ）。bundleId は `signing.bundleId` から取得します。
5. Capabilities は `ProjectCapabilityManager` によって独立してディスクに書き込まれるため、コードは project.pbxproj を**再読み込み**してその変更を保持します。
6. `RunLocalization` がローカライズを適用します（`localizations`）。
7. PodFile：`podfile` キーで完全な Podfile が指定されている場合はそれをコピーして source を書き換えます。それ以外の場合は従来のパスで、`unityMain.pods` / `unityFramework.pods` を `Unity-iPhone` と `UnityFramework` の 2 つの target ブロックに行単位で注入します。
8. 最後に `pod install` を実行します。キー `podInstall` は**省略時は実行とみなされ**、`false` を設定するとスキップできます。

## Run()：target 単位の設定の 8 つのサブタスク

`Run` はフェーズ 1 の中核であり、単一の target に対して以下の内容を順に適用します（`unityMain` / `unityFramework` 配下の各フィールドに対応）：

| 順序 | メソッド | 設定キー | 機能 |
|------|------|--------|------|
| 1 | `SetBuildProperties` | `properties` | ビルド属性 |
| 2 | `SetFrameworks` | `frameworks` | フレームワーク |
| 3 | `SetLibs` | `libs` | システムライブラリ |
| 4 | `RunCopyFiles` | `files` | ファイルのコピー |
| 5 | `CopyFolders` | `folders` | フォルダのコピー |
| 6 | `SetFilesCompileFlag` | `filesCompileFlag` | ファイルのコンパイルフラグ |
| 7 | `AddOtherLinkFlag` | `otherLinkerFlag` | Linker Flag |
| 8 | `AddRunPathSearchPaths` | `runPathSearchPaths` | Run Path Search Paths |

```csharp
static void Run(PBXProject pbxProject, string targetGuid, string mainTargetGuid, Hashtable hashtable, string path)
{
    SetBuildProperties(pbxProject, targetGuid, hashtable.Get<Hashtable>("properties"));
    SetFrameworks(pbxProject, targetGuid, hashtable.Get<Hashtable>("frameworks"));
    SetLibs(pbxProject, targetGuid, hashtable.Get<Hashtable>("libs"));
    RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
    CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
    SetFilesCompileFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("filesCompileFlag"));
    AddOtherLinkFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("otherLinkerFlag"));
    AddRunPathSearchPaths(pbxProject, targetGuid, hashtable.Get<Hashtable>("runPathSearchPaths"));
}
```

参照元： [Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L165-L183)

各サブタスクは、同じディレクトリ内の部分クラスファイルにそれぞれ実装されています。例：`PostProcessBuildHelper.BuildProperties.cs`、`PostProcessBuildHelper.Frameworks.cs`、`PostProcessBuildHelper.Plist.cs`、`PostProcessBuildHelper.PodFile.cs`、`PostProcessBuildHelper.Capabilities.cs`、`PostProcessBuildHelper.Signing.cs` など。

## マージ順序と上書きルール

優先度が低いものから高いものの順で、後にマージされたものが先にマージされたものを上書きします（ディープマージ、同じキーは新しい値が優先）：

1. プロジェクト内のすべての `XCodeConfig.json`（ソート済みのパス順に 1 つずつマージ）。
2. `XCodeConfig.{channel}.json` チャネル専用設定（最後にマージ、最も高い優先度）。

したがって、特定のチャネルで特定のフィールドを上書きしたい場合は、そのフィールドをチャネルファイルに記述するだけでよく、共通設定を変更する必要はありません。
