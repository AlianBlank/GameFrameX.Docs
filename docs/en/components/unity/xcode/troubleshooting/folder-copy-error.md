# What to Do When Folder Copying Reports Errors

During the post-processing stage of a Unity iOS build, the folders declared in the `folders` configuration are copied into the Xcode project and automatically added to the build; when the Unity Console reports exceptions such as `DirectoryNotFoundException` or `IOException`, or when files/frameworks are missing after copying, use the diagnostic table below to locate the cause and fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `DirectoryNotFoundException: Could not find a part of the path ...` | The Key source path in `folders` does not exist: the Key is relative to the Unity project root (at the same level as `Assets`), not a path relative to `Assets` | See Fix Step 1 |
| `IOException` / `UnauthorizedAccessException`, thrown when deleting the destination directory | The destination directory is locked by Xcode or another program, or contains read-only files | Close the locking program or manually delete the destination directory, then rebuild; see Fix Step 2 |
| Copy succeeds but individual files are missing | File names starting with `.`, or files named `.gitkeep` / `.DS_Store`, are actively filtered out | This is expected behavior; see Fix Step 3 |
| `.framework` / `.bundle` / `.a` link errors after copying (symbols not found) | A folder copy linking bug in older versions, or an unrecognized incorrect file extension | Upgrade to the latest version; see Fix Step 4 |

## Fix Steps

### 1. Source path does not exist (DirectoryNotFoundException)

The source path is assembled as follows during copying; `Environment.CurrentDirectory` is the Unity project root, at the same level as `Assets`:

```csharp
string src = Path.Combine(Environment.CurrentDirectory, map.Key.ToString().Trim());
string des = Path.Combine(xcodePath, map.Value.ToString().Trim());
CopyFolder(src, des);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L29-L31)

Check and correct the JSON configuration (whitespace around the path will be removed by `Trim()`):

```json
{
  "folders": {
    "XC": "Classes/XC"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/README.zh-CN.md#L191-L197)

- Key: the folder's path under the Unity project root; do not mistakenly prefix it with `Assets/`
- Value: the relative path inside the Xcode project to copy to

### 2. Failed to delete the destination directory (IOException)

Before copying, `CopyFolder` first deletes the existing destination directory and any file with the same name, then recreates the directory:

```csharp
if (Directory.Exists(dstPath))
{
    Directory.Delete(dstPath, true);
}

if (File.Exists(dstPath))
{
    File.Delete(dstPath);
}

Directory.CreateDirectory(dstPath);
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L174-L184)

`Directory.Delete(dstPath, true)` deletes recursively and throws an exception if any files inside the destination are locked or read-only:

1. Close any program that has the Xcode project open (or is locking that directory)
2. Manually delete the destination directory inside the Xcode project
3. Re-run the Unity iOS build

### 3. Individual files are not copied

Both copying and adding to the build are filtered through `IsNeedCopy`:

```csharp
private static bool IsNeedCopy(string file)
{
    string fileName = Path.GetFileNameWithoutExtension(file);
    if (fileName.StartsWith(".") || file.EndsWith(".gitkeep") || file.EndsWith(".DS_Store"))
    {
        return false;
    }

    return true;
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L112-L121)

File names (without extension) starting with `.`, as well as `.gitkeep` and `.DS_Store`, are always skipped. If you need to keep placeholder files for empty directories, use names without a dot prefix instead.

### 4. framework / bundle / static library link errors

`AddFolderBuild` handles items differently based on their extension; make sure the destination path (i.e., the Value in `folders`) has the correct extension:

| Value ends with | Handling |
|------------|----------|
| `.framework` | `AddFile` + `AddFileToBuild` + `AddFrameworkToProject` |
| `.bundle` | Added to both the UnityFramework target and the main target |
| `.xcframework` / `.a` | `AddFile` + `AddFileToBuild` |
| Regular directory | Recursively expands subdirectories and files, and automatically adds search paths for frameworks/static libraries (`AutoAddSearchPath`) |

```csharp
if (root.EndsWith(".framework") || root.EndsWith(".bundle"))
{
    Debug.LogFormat("add framework/bundle to build:{0}->{1}", currDir, root);
    string fileGuid = proj.AddFile(currDir, root, PBXSourceTree.Source);
    proj.AddFileToBuild(targetGuid, fileGuid);
    if (root.EndsWith(".bundle"))
    {
        proj.AddFileToBuild(mainTargetGuid, fileGuid);
    }
    // Add as linked framework
    proj.AddFrameworkToProject(targetGuid, root, false);
    return;
}
```

Source: [PostProcessBuildHelper.Folder.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.Folder.cs#L47-L59)

## Verification

1. Re-run the Unity iOS build; the Console shows no `DirectoryNotFoundException` / `IOException` exceptions, and logs such as `add framework/bundle to build:...` and `add file to build:...` appear
2. Open the generated Xcode project; the directory pointed to by the Value in `folders` exists and its contents are complete
3. `.framework` / `.bundle` appear under **General → Frameworks, Libraries, and Embedded Content** or **Build Phases → Link Binary With Libraries**, and the build compiles successfully
