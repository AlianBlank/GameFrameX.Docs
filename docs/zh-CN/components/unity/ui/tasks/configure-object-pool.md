# 如何调整对象池容量与回收策略

UI 框架把界面实例交给 `IObjectPoolManager` 管理,通过 `UIComponent` 上的若干字段即可调整容量、自动回收/释放间隔、过期时间。完成本页配置后,即可控制界面实例对象池能缓存多少个 UI、隔多久扫描一次回收。

## 前置条件

- 工程已集成 `GameFrameX.ObjectPool`(`UIComponent.cs` 第 33 行 `using GameFrameX.ObjectPool;`)。
- 场景中存在挂载 `UIComponent` 的 GameObject,并把 `m_UIManager.SetObjectPoolManager(...)` 注入完毕(`UIComponent.cs` 第 504 行 `SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>())`)。
- 关于 UI 组件与对象池管理器的整体装配,见《如何初始化 UI 模块》。

## 操作步骤

1. **在 Inspector 里调整容量与策略字段**。选中带 `UIComponent` 的 GameObject,在 Inspector 中可以直接看到以下序列化字段并修改默认值:

| 字段名 | 默认值 | 含义 |
|--------|--------|------|
| `m_InstanceCapacity` | `16` | 界面实例对象池容量上限 |
| `m_InstanceExpireTime` | `60` 秒 | 池内对象空闲超过该秒数即视为可释放 |
| `m_InstanceAutoReleaseInterval` | `60` 秒 | 自动扫描/释放间隔 |
| `m_RecycleInterval` | `60` 秒 | 自动回收可回收对象的间隔 |
| `m_EnableAutoReleaseUIForm` | `false` | 是否启用自动回收 |

字段定义示例:

```csharp
[SerializeField] private float m_InstanceAutoReleaseInterval = 60f;
[SerializeField] private int   m_InstanceCapacity          = 16;
[SerializeField] private float m_InstanceExpireTime        = 60f;
[SerializeField] private int   m_RecycleInterval           = 60;
[SerializeField] private bool  m_EnableAutoReleaseUIForm   = false;
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L107-L141)

2. **运行期通过属性动态调整**。`UIComponent` 把上述字段暴露为公共属性,运行时改值会同时回写到序列化字段并下发到 `m_UIManager`:

```csharp
// 调整容量、过期时间、自动释放/回收间隔
uiComponent.InstanceCapacity           = 32;   // 容量
uiComponent.InstanceExpireTime         = 120f; // 过期秒数
uiComponent.InstanceAutoReleaseInterval = 30f; // 自动释放间隔
uiComponent.RecycleInterval            = 30;  // 回收间隔
uiComponent.EnableAutoReleaseUIForm    = true; // 打开自动回收
```

属性实现:

```csharp
public int   InstanceCapacity            { get => m_UIManager.InstanceCapacity;             set => m_UIManager.InstanceCapacity            = m_InstanceCapacity            = value; }
public float InstanceExpireTime          { get => m_UIManager.InstanceExpireTime;           set => m_UIManager.InstanceExpireTime          = m_InstanceExpireTime          = value; }
public float InstanceAutoReleaseInterval { get => m_UIManager.InstanceAutoReleaseInterval;  set => m_UIManager.InstanceAutoReleaseInterval = m_InstanceAutoReleaseInterval = value; }
public int   RecycleInterval             { get => m_UIManager.RecycleInterval;              set => m_UIManager.RecycleInterval             = m_RecycleInterval             = value; }
public bool  EnableAutoReleaseUIForm     { get => m_EnableAutoReleaseUIForm;                set => m_EnableAutoReleaseUIForm = value; }
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L322-L359)

3. **关闭自动回收开关(可选)**。若希望手动控制回收,把 `EnableAutoReleaseUIForm` 设为 `false`,定时器就不会再触发自动扫描,只在显式调用 `CloseUIForm` 时归还实例到池里。

4. **保存并验证**。重启场景或重新进入 Play Mode,在 Inspector 确认字段值生效;在 Profiler 中观察 `UI Form Instance Pool` 的容量,确认未超过 `InstanceCapacity`。

## 常见变体

- **分阶段调优**:上线前在编辑器把 `m_InstanceCapacity` 调高(如 32),便于压测峰值;正式包通过 `InstanceCapacity` 动态下调,降低常驻内存。
- **频繁打开/关闭的高频界面**(例如 Toast、Tips):把 `InstanceExpireTime` 设小(如 10 秒),让空闲对象尽快被释放,避免占住池容量。
- **重量级界面**(角色面板、商城):把 `m_InstanceCapacity` 调到 1~2,`InstanceExpireTime` 调大(如 300 秒),保留缓存以便复用。
- **完全关闭自动回收**:把 `m_EnableAutoReleaseUIForm = false`,由业务自行决定何时回收(常用于过场剧情期间)。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 改完字段不生效 | 运行期只改了属性未写回 `m_UIManager`,或没启用 `EnableAutoReleaseUIForm` | 确认 `m_EnableAutoReleaseUIForm = true`,并通过属性(非字段)赋值 |
| 池对象很快被清空,界面打开慢 | `InstanceExpireTime` 或 `InstanceAutoReleaseInterval` 过小 | 把 `InstanceExpireTime` 调到 60 秒以上,`InstanceAutoReleaseInterval` 调到 30 秒以上 |
| 内存持续上涨 | `InstanceCapacity` 过大且 `InstanceExpireTime` 过长 | 调小 `InstanceCapacity`,并缩短 `InstanceExpireTime` |
| 频繁 GC | `RecycleInterval` 过小,定时器反复触发 | 把 `RecycleInterval` 调到 30~60 秒 |

## 背景(可选)

`UIComponent` 内部把配置同时下发到 `m_UIManager` 与序列化字段,目的是让运行期改动在 Editor 中也能被序列化保留。`IObjectPoolManager` 负责具体的对象池策略(过期回收、定时释放),UI 模块只负责传参与开关;改 `m_InstancePriority` 这类未公开字段不会生效。
