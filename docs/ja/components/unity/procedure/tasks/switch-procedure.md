# フロー間の切り替え方法

フローの切り替えは `IProcedureManager.StartProcedure` によって行われます。ゲームの任意の場所（フロークラスの内部、外部システム、UI ボタンのコールバックなど）で `ProcedureComponent.Procedure` を取得できれば呼び出せます。このページでは、マネージャーの取得から切り替え完了までの最小実行可能手順を説明します。

## 前提条件

- `ProcedureBase` を継承する複数のフロークラス（`ProcedureLogin`、`ProcedureMain` など）を作成済みであること。
- `ProcedureComponent` がシーンにアタッチされており、Inspector の `Available Procedure Type Names` にこれらのフロータイプ名が入力済みであること。
- 全体のアーキテクチャを理解していること。《概要》を参照してください。

## 操作手順

### 1. フローマネージャーを取得する

`ProcedureComponent` の `Procedure` プロパティを通じて `IProcedureManager` を取得します:

```csharp
using GameFrameX.Procedure.Runtime;
using UnityEngine;

ProcedureComponent procedureComponent = GameFrameX.Runtime.GameFrameworkEntry.GetComponent<ProcedureComponent>();
IProcedureManager procedureManager = procedureComponent.Procedure;
```

Source: [ProcedureComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/ProcedureComponent.cs#L70-L74)

### 2. 現在のフローの `OnUpdate` 内で切り替えを開始する

最も一般的な切り替え方法：あるフローのポーリング内で条件が満たされたことを検出した際に `StartProcedure` を呼び出します。マネージャーは現在のフローの `OnLeave` と対象フローの `OnEnter` をトリガーします。

```csharp
using GameFrameX.Procedure.Runtime;

public class ProcedureLogin : ProcedureBase
{
    protected override void OnUpdate(IFsm<IProcedureManager> procedureOwner, float elapseSeconds, float realElapseSeconds)
    {
        base.OnUpdate(procedureOwner, elapseSeconds, realElapseSeconds);

        if (ログイン完了の条件が満たされている)
        {
            procedureOwner.Owner.StartProcedure<ProcedureMain>();
        }
    }
}
```

`IProcedureManager.StartProcedure` の2つのオーバーロード定義は [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L64-L73) を参照してください。内部的にはステートマシンの状態切り替えが呼び出されます。

### 3. 外部コードから切り替える

フロー内部で切り替える必要はありません。ゲーム内で `IProcedureManager` の参照を保持している任意の場所から呼び出せます:

```csharp
using GameFrameX.Procedure.Runtime;

procedureManager.StartProcedure(typeof(ProcedureMain));
// またはジェネリックバージョン
procedureManager.StartProcedure<ProcedureMain>();
```

ジェネリックバージョンのソースコード署名:

```csharp
public interface IProcedureManager
{
    void StartProcedure<T>() where T : ProcedureBase;
    void StartProcedure(Type procedureType);
}
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L60-L73)

### 4. 切り替えの成功を検証する

切り替え後に `CurrentProcedure` と `CurrentProcedureTime` を読み取り、新しいフローが有効になっているか、タイマーが 0 にリセットされているかを確認します。ユニットテストの記述方法が参考になります:

```csharp
m_ProcedureManager.Initialize(m_FsmManager, new ProcedurePreload(), new ProcedureMain());
m_ProcedureManager.StartProcedure<ProcedurePreload>();

Assert.IsNotNull(m_ProcedureManager.CurrentProcedure);
Assert.IsInstanceOf<ProcedurePreload>(m_ProcedureManager.CurrentProcedure);
Assert.AreEqual(0f, m_ProcedureManager.CurrentProcedureTime);
```

Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L153-L173)

## よくあるバリエーション

### 切り替えずにクエリのみ行う

切り替え前に `HasProcedure` を使用して対象が登録されているか確認し、ステートマシン内部の例外を回避できます:

```csharp
if (procedureManager.HasProcedure<ProcedureMain>())
{
    procedureManager.StartProcedure<ProcedureMain>();
}
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L78-L89)

### 切り替えずに登録済みのインスタンスを取得する

条件判断のため現在のフローインスタンスを読み取るだけで、切り替える必要がない場合もあります:

```csharp
ProcedureBase main = procedureManager.GetProcedure<ProcedureMain>();
```

Source: [IProcedureManager.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Runtime/Procedure/IProcedureManager.cs#L94-L105)

## よくあるエラー

- **呼び出しタイミングが早すぎる**: フローマネージャーの `Initialize` 前にメソッドを呼び出すと例外がスローされます。ユニットテストの `CurrentProcedure_BeforeInitialize_Throws`、`HasProcedure_BeforeInitialize_Throws` がこれを検証しています。[UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/Tests/UnitTests.cs#L96-L128) を参照してください。先に `Initialize` を完了させてから `StartProcedure` を呼び出してください。
- **対象フローが未登録**: `StartProcedure` は対象のフローが `Initialize(..., params ProcedureBase[] procedures)` または `ReinitializeProcedures` を通じて登録済みであることを要求します。`HasProcedure<T>()` で事前に判断できます。
- **`OnEnter` / `OnInit` 内での切り替え**: ステートマシンの初期化段階で `StartProcedure` を呼び出すと、自身のライフサイクルと衝突する可能性があります。`OnUpdate` または外部駆動に配置することをお勧めします。

## 背景（オプション）

`ProcedureComponent` は `m_ProcedureManager` を保持し、起動時に Inspector で設定された `m_AvailableProcedureTypeNames` に基づきリフレクションでフローインスタンスを作成し、順次 `StartProcedure` を呼び出します。その後、`m_EntranceProcedure` が初期フローとなります。切り替え時には下層のステートマシンが `OnLeave`/`OnEnter` の遷移を実行します。`m_UseStartupRunner = true` の場合、コンポーネント自体は `Initialize` を行わず、`ApplicationStartupEntry` + `StartupRunner.Run` が引き継ぎ、重複した `Initialize` を回避します。
