# 다중 모듈 구성 파일 병합

각 모듈의 iOS 빌드 구성을 별도의 `XCodeConfig.json`으로 작성하면, 프레임워크가 Xcode 프로젝트 내보내기 후 동일한 이름의 구성 파일(채널 전용 구성 포함)을 모두 자동으로 스캔·병합한 뒤, 병합 결과를 한 번에 Xcode 프로젝트에 기록합니다. 수동으로 하나의 큰 구성을 취합할 필요 없이, 파일을 스캔 가능한 위치에 두기만 하면 됩니다.

## 사전 조건

- Unity 프로젝트에 이 패키지가 포함되어 있어야 합니다(Editor 어셈블리 `GameFrameX.Xcode.Editor`).
- 빌드 대상이 iOS여야 합니다: 병합 프로세스 전체가 `#if UNITY_IOS` 내에 위치하며, 다른 플랫폼에서는 바로 반환됩니다.

## 작업 단계

1. 각 모듈에 대해 `XCodeConfig.json`을 하나씩 생성하고, 해당 모듈이 필요로 하는 필드만 작성합니다. 프레임워크가 `SettingLoader.LoadSettingsData("XCodeConfig.json")`를 통해 일치하는 모든 파일의 경로 목록을 스캔합니다([SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58) 참조).
2. iOS 빌드를 실행합니다. 빌드 완료 후 Unity 콜백이 자동으로 실행되어 구성을 읽고 병합하기 시작합니다:

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        // 구성 파일 읽기
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 일치하는 파일을 하나도 찾지 못하면 바로 반환
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }

        // 모든 구성 파일의 내용 병합
        Hashtable finalConfig = new Hashtable();
        foreach (var jsonPath in jsonPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
            string json = File.ReadAllText(jsonPath);
            Hashtable table = json.HashtableFromJson();
            if (table == null)
            {
                LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
                continue;
            }

            // 확장 메서드를 사용하여 Hashtable 병합
            finalConfig.Merge(table);
        }
```

출처: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L49)

3. (선택) 채널 전용 구성을 제공합니다. 프레임워크는 `SettingLoader.GetChannel()`으로 현재 채널을 가져온 뒤 `XCodeConfig.{channel}.json`을 로드하여 마지막에 병합하므로, 채널 구성의 우선순위가 가장 높아 일반 구성의 동일한 이름 필드를 덮어씁니다:

```csharp
// 채널 전용 구성 병합(우선순위가 가장 높으며 마지막에 병합되어 덮어씀)
string channel = SettingLoader.GetChannel();
if (!string.IsNullOrEmpty(channel))
{
    var channelPaths = SettingLoader.LoadChannelSettingsData("XCodeConfig.json", channel);
    if (channelPaths.Count > 0)
    {
        LogHelper.Log($"[MergeConfig] 检测到渠道: {channel}，正在合并渠道配置...");
        foreach (var channelPath in channelPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并渠道配置: {channelPath}");
            string channelJson = File.ReadAllText(channelPath);
            Hashtable channelTable = channelJson.HashtableFromJson();
            if (channelTable == null)
            {
                LogHelper.Error($"{channelPath} 解析失败, 跳过合并");
                continue;
            }

            finalConfig.Merge(channelTable);
        }
    }
    else
    {
        LogHelper.Log($"[MergeConfig] 未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json");
    }
}
```

출처: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)

4. Console 출력을 확인합니다. 병합되는 모든 파일에 대해 `[MergeConfig] 正在合并配置: <路径>`(채널 구성의 경우 `[MergeConfig] 正在合并渠道配置: <路径>`)가 출력되며, 이를 통해 어떤 파일이 병합에 참여했는지 확인할 수 있습니다.

## 병합 가능한 최상위 구성 필드

병합 결과는 아래 키에 따라 적용됩니다(키 이름은 `finalConfig.Get<...>(...)`의 실제 값에서 가져왔으며, 각 모듈은 자신이 사용하는 키만 제공하면 됩니다):

| 키 | 타입 | 적용 동작 |
|----|------|----------|
| `unityMain` | Hashtable | Unity 메인 Target에 적용: `properties`, `frameworks`, `libs`, `files`, `folders`, `filesCompileFlag`, `otherLinkerFlag`, `runPathSearchPaths`(및 구버전 `pods`) |
| `unityFramework` | Hashtable | 위와 동일, UnityFramework Target에 적용 |
| `signing` | Hashtable | 서명 구성이며 메인 Target에만 설정됩니다. 해당 `bundleId`는 Capabilities에서 사용됩니다 |
| `swiftBridging` | bool | Swift 브리징 on/off 스위치이며, 생략 시 켜짐으로 간주됩니다 |
| `plist` | Hashtable | Info.Plist에 기록 |
| `environmentVariables` | Hashtable | 실행 환경 변수 |
| `launcherArgs` | ArrayList | 실행 시작 인자 |
| `capabilities` | Hashtable | Capability 설정이며, 메인 Target에만 설정됩니다 |
| `localizations` | ArrayList | 현지화 리소스 |
| `podSource` | ArrayList | Podfile의 source 소스 |
| `podfile` | string | 완전한 Podfile의 구성 경로이며, 복사 성공 후 새 경로를 사용합니다 |
| `podInstall` | bool | Podfile 처리 후 `pod install`을 실행할지 여부이며, 생략 시 켜짐으로 간주됩니다 |

출처: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L89-L156)

## 일반적인 변형

- **특정 모듈의 JSON 파싱이 실패해도 빌드를 완료하고 싶은 경우**: 개별 파일 파싱 실패는 `Error` 로그를 출력하고 `continue`할 뿐 전체 프로세스를 중단하지 않습니다. 나머지 파일은 계속 병합됩니다.
- **`pod install`을 실행하고 싶지 않은 경우**: (병합에 참여하는 어느 것이든) 구성에 `"podInstall": false`를 작성합니다. [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L151-L156) 참조.
- **Swift 브리징 끄기**: `"swiftBridging": false`를 작성합니다. 이 키를 작성하지 않으면 기본적으로 켜져 있습니다. [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101) 참조.

## 일반적인 오류

| 증상(로그 원문) | 원인 | 해결 |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 스캔 결과가 비어 있어 어떤 모듈도 구성을 제공하지 않음 | `LoadSettingsData`로 스캔 가능한 `XCodeConfig.json`이 최소 한 개는 존재하는지 확인 |
| `<路径> 解析失败, 跳过合并` | 해당 파일 내용이 유효한 JSON이 아니어서 `HashtableFromJson()`이 null을 반환함 | 해당 파일의 JSON 문법을 수정합니다. 해당 파일은 건너뛰고 나머지 파일은 정상적으로 병합됩니다 |
| `合并后的配置为空，跳过设置` | 모든 파일이 파싱에 실패했거나 내용이 비어 있음 | JSON을 하나씩 검사합니다. `[MergeConfig] 正在合并配置:` 로그로 병합에 참여한 파일 목록을 확인 |
| `[MergeConfig] 未找到渠道 [...] 的专属配置文件 XCodeConfig.[...].json` | 채널이 설정되었지만 채널 전용 파일이 없음 | 필요에 따라 `XCodeConfig.{渠道}.json`을 추가로 생성합니다. 생성하지 않아도 일반 구성의 적용에는 영향 없음 |

출처: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L28-L83)

## 검증

- Console에 참여한 모든 파일을 나열하는 `[MergeConfig] 正在合并配置: ...`가 출력됩니다. 채널을 설정한 경우 `[MergeConfig] 检测到渠道: <渠道>`와 해당 채널 병합 로그가 나타납니다.
- 이어서 `[PBXProject] 正在应用最终合并配置...`와 `[OtherSettings] 正在应用最终合并配置...`가 나타나면 병합 결과가 프로젝트에 기록되었음을 나타냅니다.
- 내보낸 Xcode 프로젝트를 열고, Target의 빌드 속성, 프레임워크/라이브러리, Info.Plist, Podfile 등이 병합 후 기대한 내용과 일치하는지 확인합니다.

## 배경

병합은 `Hashtable.Merge()` 확장 메서드를 기반으로 파일별로 순차적으로 누적되며, 나중에 병합된 것이 먼저 병합된 것을 덮어씁니다. 따라서 로드 순서가 곧 우선순위 순서이며, 채널 구성이 마지막에 병합되어 우선순위가 가장 높습니다. 전체 프로세스는 `Get<Hashtable>(...)`의 값에 대해 null 허용 처리를 하므로, 각 모듈은 자신에게 필요한 키만 작성하면 되고 완전한 구조를 제공할 필요가 없습니다.
