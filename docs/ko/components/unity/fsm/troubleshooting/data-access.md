# GetData/SetData 데이터 읽기 이상 빠른 참조

본 페이지는 `IFsm<T>`에서 `GetData` / `SetData` 호출 과정에서 흔히 발생하는 예외 및 비정상 반환 상황에 대한 증상 대조 및 위치 파악 단계를 제공합니다. 상태 머신 사용 방법은 《Fsm 빠른 시작》을 참조하세요.

## 빠른 진단

| 증상 | 원인 | 해결 |
|------|------|------|
| `GameFrameworkException("Data name is invalid.")` 던짐 | `name`이 `null` 또는 빈 문자열 | 널이 아닌 키 이름 사용, 상수 문자열 권장 |
| `GetData`이 항상 `null` 반환 | 해당 키에 대해 `SetData`로 쓴 적이 없음; 또는 상태 머신이 `Reset` / `Shutdown`으로 비워짐 | 처음 읽기 전에 명시적으로 `SetData` 호출, 또는 `HasData` 엔트리에서 판단 |
| `SetData` 직후 읽었는데 필드 값이 여전히 기본값 | 반복 `SetData` 호출 시 이전 값이 `ReferencePool`로 회수되어 새 값이 실제로 교체되지 않음 | 먼저 `RemoveData` 호출 후 `SetData`, 또는 `SetData`를 한 번만 호출 |
| 타입 변환 시 `InvalidCastException` 발생 | `GetData<TData>`의 제네릭 매개변수와 쓰기 시의 실제 `Variable` 하위 타입이 일치하지 않음 | 읽기/쓰기 양쪽에서 동일한 `Variable` 하위 타입 사용(예: `VarInt`, `VarString`) |
| 상태 머신 파괴 후 `GetData` 호출 시 예외 발생 | `m_IsDestroyed == true`일 때 `Reset` 등 내부 흐름이 접근을 거부함 | 파괴 후에는 모든 접근을 중단하거나 새로운 FSM을 다시 생성 |

## 해결 단계

### 1. 이름이 잘못됨(`Data name is invalid`)

`GetData(string)`과 `SetData(string, Variable)`의 첫 단계에서 이름을 검증합니다:

```csharp
if (string.IsNullOrEmpty(name))
{
    throw new GameFrameworkException("Data name is invalid.");
}
```

Source: [Fsm.cs#L469-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L527)

**해결**: 키 이름으로 안정적인 문자열 상수를 사용하세요. 예: `"Hp"`, `"Owner"`. 문자열 결합으로 만든 빈 문자열을 전달하지 마세요.

### 2. 읽기 시 `null` 반환

`GetData`은 내부 딕셔너리가 비어있거나 키가 없을 때 예외를 던지지 않고 직접 `null`을 반환합니다:

```csharp
if (m_Datas == null)
{
    return null;
}

Variable data = null;
if (m_Datas.TryGetValue(name, out data))
{
    return data;
}

return null;
```

Source: [Fsm.cs#L469-L488](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L469-L488)

**해결**:
1. 상태 `OnEnter` 또는 상태 머신 생성 직후 즉시 한 번 `SetData`를 호출하여 초기화를 완료하세요.
2. 읽기 전에 `HasData(name)`으로 존재 여부를 판단하세요. `false`이면 기본값으로 초기화를 수행하세요.
3. `Reset()`은 모든 데이터를 비웁니다(`m_Datas.Clear()`). `Shutdown` 후에는 딕셔너리가 `null`이 되므로 다시 초기화해야 합니다.

### 3. 중복 `SetData` 호출 후 이전 값이 회수됨

`SetData` 내부에서는 먼저 이전 값을 꺼내, 널이 아니면 참조 풀에 반환합니다:

```csharp
Variable oldData = GetData(name);
if (oldData != null)
{
    ReferencePool.Release(oldData);
}

m_Datas[name] = data;
```

Source: [Fsm.cs#L508-L527](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L508-L527)

**해결**:
- `Variable` 하위 타입 인스턴스는 프레임워크 내부에서 `ReferencePool`을 통해 가져오고 생명 주기를 관리합니다. 외부에서 `new`로 생성한 후 상태 머신에 넘기지 마세요.
- 키 이름을 교체하고 싶다면 `RemoveData(name)`으로 이전 값을 명시적으로 반환한 다음 `SetData`로 새 키를 설정하세요.

### 4. 제네릭 타입 불일치

`GetData<TData>`은 직접 강제 형변환을 수행하므로, `TData : Variable`이며 쓰기 시의 하위 타입과 일치해야 합니다:

```csharp
public TData GetData<TData>(string name) where TData : Variable
{
    return (TData)GetData(name);
}
```

Source: [Fsm.cs#L458-L461](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L458-L461)

**해결**: 호출 측에서 명시적으로 `VarInt`, `VarFloat`, `VarString`, `VarBool`, `VarObject` 등의 내장 하위 타입을 사용하세요. `object` 또는 `Variable` 기본 클래스를 `TData`로 사용하지 마세요. 그렇지 않으면 형변환이 실패합니다.

### 5. 파괴 후 접근

`Fsm.Shutdown` 후에는 `m_IsDestroyed = true`가 되며, 다시 접근하면 `Reset()` 등 내부 흐름에 의해 거부됩니다:

```csharp
if (m_IsDestroyed)
{
    throw new GameFrameworkException("FSM is destroyed, can not reset.");
}
```

Source: [Fsm.cs#L560-L565](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/Fsm.cs#L560-L565)

**해결**: FSM을 파괴하기 전에 모든 외부 참조를 정리하세요. `OnDestroy` 이후에 `GetData`/`SetData`를 계속 호출하지 마세요.

다음 단계를 수행하여 문제가 해결되었는지 확인하세요:
