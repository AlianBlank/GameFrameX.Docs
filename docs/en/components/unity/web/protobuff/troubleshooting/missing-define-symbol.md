# What to Do When the Post Method Doesn't Exist or Compilation Fails (Macro Not Defined)

When you call `WebProtoBuffComponent.Post<T>()` and get an error saying the method doesn't exist, or the compiler reports that the `GameFrameX.Network.Runtime.MessageObject` type cannot be found, it is almost always for the same reason: the `com.gameframex.unity.network` package is not installed in the project, so the `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` macro is not automatically defined, and all `Post`-related code is stripped out entirely by conditional compilation.

## Quick Diagnosis

| Symptom (exact error / behavior) | Cause | Fix |
|------|------|------|
| `'WebProtoBuffComponent' does not contain a definition for 'Post'` (CS1061) | The entire `Post<T>` method is wrapped in `#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`; when the macro is not defined, the method doesn't exist | Install the `com.gameframex.unity.network` package so the macro takes effect automatically; see [Fix Steps](#1-confirm-the-network-package-is-installed) below |
| `The type or namespace name 'MessageObject' could not be found` | `MessageObject` / `IResponseMessage` are defined in the `GameFrameX.Network.Runtime` assembly; if the package is missing, these types don't exist | Install the `com.gameframex.unity.network` package |
| The editor shows in the bottom-left corner that the assembly `GameFrameX.Web.ProtoBuff.Runtime` failed to compile | The asmdef references `GameFrameX.Network.Runtime`; when the network package is not installed, the reference fails to resolve | Install the `com.gameframex.unity.network` package |
| The network package is installed but `Post` is still unavailable | Unity has not refreshed the asmdef's `versionDefines`, so the macro was not written | Manually add the macro in Player Settings or restart Unity; see [Step 3](#3-manually-define-the-macro-as-a-fallback) |

The macro stripping logic can be seen in the source code — the entire `Post` method is wrapped in conditional compilation:

```csharp
#if ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK
        /// <summary>
        /// Sends a Post request, used for sending and receiving Protocol Buffer messages.
        /// This method is only available when the ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK macro is defined.
        /// </summary>
        public Task<T> Post<T>(string url, GameFrameX.Network.Runtime.MessageObject message) where T : GameFrameX.Network.Runtime.MessageObject, GameFrameX.Network.Runtime.IResponseMessage
        {
            return m_WebProtoBuffManager.Post<T>(url, message);
        }
#endif
```

Source: [WebProtoBuffComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/WebProtoBuffComponent.cs#L92-L109)

The `Post` method in the `IWebProtoBuffManager` interface follows the same pattern ([IWebProtoBuffManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/Web/IWebProtoBuffManager.cs#L11-L24)), while the `Timeout` property is always available and unaffected by the macro.

## Fix Steps

### 1. Confirm the Network Package Is Installed

The macro is not configured manually; it is controlled automatically by `versionDefines` in the runtime assembly definition file: as long as the `com.gameframex.unity.network` package exists in the project, Unity automatically defines `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK`.

```json
  "versionDefines": [
    {
      "name": "com.gameframex.unity.network",
      "expression": "",
      "define": "ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK"
    }
  ]
```

Source: [GameFrameX.Web.ProtoBuff.Runtime.asmdef](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L17-L23)

How to check and install:

1. Open the Unity menu `Window → Package Manager` and switch to the `Packages: In Project` view;
2. Look for `com.gameframex.unity.network` (the display name is usually GameFrameX Network);
3. If it is not there, switch to `+ → Add package from git URL...` and enter the network package's repository URL to add it;
4. The dependent assemblies also include `GameFrameX.Runtime`, `GameFrameX.Web.Runtime`, and `ProtoBuffer.Runtime` (see the [asmdef reference list](https://github.com/GameFrameX/com.gameframex.unity.web.protobuff/blob/main/Runtime/GameFrameX.Web.ProtoBuff.Runtime.asmdef#L4-L9)); normally they are pulled in automatically as dependencies.

### 2. Let Unity Refresh the Script Defines

After the package is installed, Unity automatically refreshes `versionDefines` and triggers recompilation. If it doesn't:

1. Use the menu `Assets → Reimport All`, or delete the `Library/ScriptAssemblies` folder in the project root and reopen Unity;
2. Wait for compilation to finish and confirm there are no errors in the Console.

### 3. Manually Define the Macro as a Fallback

If the network package is installed but the macro still hasn't taken effect (e.g., older Unity versions behave abnormally with `versionDefines`):

1. Open `Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`;
2. Add `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` (separate multiple macros with semicolons);
3. Press Enter to save and wait for recompilation.

Note: manually defining the macro is only a fallback. If the network package is genuinely missing, the `MessageObject` and `IResponseMessage` types referenced inside `Post` still won't exist, and compilation will still fail — so please complete Step 1 first.

## Verification

1. Type `webProtoBuffComponent.Post<` in any script; the IDE can autocomplete the `Post<T>(string url, MessageObject message)` overload;
2. In `Project Settings → Player → Script Compilation`, you can see (or manually verify) that `ENABLE_GAME_FRAME_X_WEB_PROTOBUF_NETWORK` has taken effect;
3. The Inspector displays normally for objects in the scene that have the `WebProtoBuff Component` attached, and the Console shows no fatal `Web manager is invalid.` log (that log indicates the component was not initialized correctly, which is a different issue from the macro problem).

## Background

`Post` depends on the network layer's protobuf message types, and the network package is an optional dependency, so this component uses the asmdef's `versionDefines` to implement on-demand stripping — "only expose the Post method when the network package is installed": an empty `expression` means any version of the package satisfies the condition. This is also why the error often appears on the component class rather than the interface — the `#if` exists in both places simultaneously.
