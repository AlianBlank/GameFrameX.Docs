# What to Do When the YooAsset Patch Process Fails

When any step in the YooAsset patch chain `ProcedurePatchInit` → `ProcedureUpdateStaticVersion` → `ProcedureUpdateManifest` → `ProcedureCreateDownloader` → `ProcedureDownloadWebFiles` → `ProcedurePatchDone` fails, the startup flow will get stuck or be routed back to an upstream procedure. This article provides symptom-based troubleshooting and fixes.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| Stuck at `ProcedurePatchInit`, resource package initialization failed | `packageUrl` is empty or the CDN is unreachable | Check whether `procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName)` was written correctly; verify the CDN is accessible |
| Stuck at `ProcedureUpdateStaticVersion`, reporting a version mismatch | The remote static version number does not match the local one | Rebuild and republish the remote static version file; ensure `StaticVersion.txt` has been uploaded |
| `ProcedureUpdateManifest` reports a manifest error | The remote manifest file was not published, or there is a signature error | Republish the resource manifest (`PackageManifest_{ver}.hash` / `.bytes`) and verify the YooAsset encryption key |
| Progress does not advance after entering `ProcedureDownloadWebFiles` | The downloader is empty or HTTP is rate-limited | Check whether the output of `ProcedureCreateDownloader` contains the `VarObject` key `"Downloader"`; check proxy/bandwidth |
| Jumps back to `ProcedureCreateDownloader` mid-download | A single file download failed, triggering `OnDownloadErrorCallback` | Inspect the `FileName` and `ErrorInfo` of `AssetWebFileDownloadFailedEventArgs` to locate the missing remote file |
| `ProcedureDownloadWebFiles` completes but does not enter `ProcedurePatchDone` | `downloader.Status != EOperationStatus.Succeed` | Check the last `OnDownloadError` log, complete the missing resources, and launch again |

## Fix Steps

### 1. Resource Package Initialization Failure

`ProcedurePatchInit` selects the initialization branch based on `GamePlayMode`: EditorSimulate/Offline uses an empty URL, while the other modes use the package address pulled from `BuildInPackageName`.

```csharp
// ProcedurePatchInit.InitPatchAsync (Runtime/Procedures/Patch/ProcedurePatchInit.cs)
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode || assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, string.Empty, string.Empty, true);
    ChangeState<ProcedureUpdateStaticVersion>(procedureOwner);
    return;
}

var packageUrl = procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName);
await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, packageUrl.Value, packageUrl.Value, true);
```

Source: [ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L33-L48)

Fix steps:

1. Reproduce the issue in debug mode (EditorSimulate) to rule out CDN network problems.
2. In `ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState`, confirm that `packageUrl` has been written to the BlackBoard.
3. In device mode, check whether `StartupOptions.PlayMode` was rewritten by `NormalizeAssetPlayMode` (WebGL forces `WebPlayMode`; outside the editor, `EditorSimulateMode` is forcibly rewritten to `HostPlayMode`).

### 2. Static Version/Manifest Update Failure

`ProcedureUpdateStaticVersion` and `ProcedureUpdateManifest` are driven by YooAsset's built-in process. Common failure causes:

- Only `StaticVersion.txt` was uploaded to the remote server, without `PackageManifest_*.bytes`.
- The YooAsset encryption key does not match the one in the editor, causing manifest parsing to fail.

Fix steps:

1. Rebuild the package with the build tool (Builtin Build Pipeline) and upload the entire `ServerData/{Platform}` directory, without missing `StaticVersion.txt`.
2. After building a package in the editor via `YooAsset > AssetBundle Builder`, start a local HTTP server and first verify it once with the same `PlayMode`.
3. Disable manifest encryption or confirm the keys are identical.

### 3. Empty Downloader or Interrupted Download

`ProcedureDownloadWebFiles` directly consumes the `VarObject` key `"Downloader"` (`ResourceDownloaderOperation`) written by `ProcedureCreateDownloader`, and listens for errors via callbacks:

```csharp
// ProcedureDownloadWebFiles.BeginDownload (Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs)
var downloader = (ResourceDownloaderOperation)procedureOwner.GetData<VarObject>("Downloader").GetValue();

downloader.OnDownloadErrorCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetWebFileDownloadFailedEventArgs.Create(data.PackageName, data.FileName, data.ErrorInfo));
    ChangeState<ProcedureCreateDownloader>(procedureOwner);
};
downloader.OnDownloadProgressCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetDownloadProgressUpdateEventArgs.Create(
        data.PackageName, data.TotalDownloadCount, data.CurrentDownloadCount,
        data.TotalDownloadBytes, data.CurrentDownloadBytes));
    StartupProcedureUtility.SetDownloadProgress(
        StartupProcedureUtility.GetUIHandler(procedureOwner),
        data.CurrentDownloadBytes, data.TotalDownloadBytes);
};

downloader.BeginDownload();
yield return downloader;

if (downloader.Status == EOperationStatus.Succeed)
{
    ChangeState<ProcedurePatchDone>(procedureOwner);
}
```

Source: [ProcedureDownloadWebFiles.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs#L36-L61)

Fix steps:

1. Subscribe to `AssetWebFileDownloadFailedEventArgs` to obtain `FileName` and `ErrorInfo`; confirm on the CDN that the file exists and can be downloaded anonymously.
2. When the HTTPS certificate is not trusted, YooAsset reports an SSL error in `ErrorInfo`; you can configure a certificate for HostPlayMode in the YooAsset settings or fall back to HTTP.
3. A single file failure triggers `ChangeState<ProcedureCreateDownloader>` to retry automatically, so no manual intervention is needed; if failures persist, use a YooAsset switch such as `ClearCacheWhenDownloadFailure` to clear the local cache and launch again.

### 4. Startup Stops Before `ProcedureGameLauncherState`

`ProcedurePatchDone` is the final step of the patch process; if the flow stops here:

- Check whether `ProcedureDownloadWebFiles` successfully triggered `ChangeState<ProcedurePatchDone>` (the transition only happens when `downloader.Status == EOperationStatus.Succeed`).
- Check whether a custom Procedure subscribed to `AssetPatchStatesChangeEventArgs` is intercepting the flow.

## Verification

1. Re-enter the game and observe whether an `EPatchStates.DownloadWebFiles` event is reported between `ProcedureGetGlobalInfoState` → `ProcedurePatchDone`.
2. In the editor, use `EditorSimulateMode` and point `StartupOptions.GlobalInfoUrls` to a local address to confirm the patch chain works end to end.
3. In device mode, open YooAsset's sandbox directory (`Application.persistentDataPath/yoo/{PackageName}`) and confirm that `PackageManifest_*.bytes` and the resource files have all been written to disk.
4. If all of the above are normal but the flow is still stuck, clear the YooAsset sandbox and launch again to rule out manifest verification failures caused by dirty cache.
