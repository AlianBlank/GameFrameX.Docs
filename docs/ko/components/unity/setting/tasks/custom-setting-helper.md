# 커스텀 저장소 Helper 구현

[SettingHelperBase](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44)를 상속하고 `ISettingHelper`의 모든 멤버를 구현하여, 읽기/쓰기를 본인의 저장 매체(데이터베이스, 암호화된 파일, 원격 인터페이스 등)에 위임하면 됩니다. 프레임워크는 시작 시 `SettingComponent`를 통해 Helper를 호출하여 로드와 저장을 완료합니다.

## 사전 조건

- `com.gameframex.unity.setting` 패키지가 설치되어 있고 Inspector에서 `SettingComponent`를 볼 수 있어야 합니다.
- C# 추상 클래스와 `MonoBehaviour` 생명주기에 대한 이해가 필요하며, Helper는 반드시 씬의 GameObject에 부착되어야 합니다.
- 자체 저장 매체(SQLite, 로컬 암호화 파일, 원격 Key-Value 서비스 등)를 보유하고 있어야 합니다.

## 작업 단계

1. **Helper 클래스 생성 및 베이스 클래스 상속**.
   `Assets/Scripts/MySettingHelper.cs` 스크립트를 새로 만들고, `GameFrameX.Setting.Runtime.SettingHelperBase`를 상속합니다. 베이스 클래스 자체가 추상 `MonoBehaviour`이며, 프레임워크는 이를 통해 모든 `ISettingHelper` 멤버를 가져옵니다.

   ```csharp
   using GameFrameX.Setting.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
   }
   ```

   Source: [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L42-L44)

2. **반드시 재정의해야 하는 추상 멤버 구현**. 베이스 클래스에서 선언된 추상 멤버의 대조표는 다음과 같으며, 모두 `override`로 구현합니다:

   | 멤버 | 시그니처 | 권장 동작 |
   |------|------|---------|
   | `Count` | `int Count { get; }` | 지원하지 않을 경우 `-1` 반환 (`PlayerPrefsSettingHelper`의 방법 참조) |
   | `Load()` | `bool Load()` | 사전 로드가 필요 없으면 직접 `true` 반환 |
   | `Save()` | `bool Save()` | 실제로 저장한 후 반환 |
   | `GetAllSettingNames()` | `string[] GetAllSettingNames()` | 지원하지 않을 경우 `Log.Warning` 후 `null` 반환 |
   | `GetAllSettingNames(List<string>)` | `void GetAllSettingNames(List<string> results)` | `results == null`일 때 `GameFrameworkException("Results is invalid.")` 던지기, 그렇지 않으면 `results.Clear()` |
   | `HasSetting` / `RemoveSetting` / `RemoveAllSettings` | 인터페이스 참조 | 자체 저장소에 위임 |
   | `GetBool/Int/Float/String`, `SetBool/Int/Float/String` | 인터페이스 참조 | 자체 저장소에 위임; 존재하지 않을 경우约定的 기본값 반환 |

   전체 시그니처는 [ISettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/ISettingHelper.cs#L42-L42)와 [SettingHelperBase.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingHelperBase.cs#L43-L43)를 참조하세요.

3. **읽기/쓰기를 구체적인 저장소에 위임**. 최소 예제: 메모리 사전을 사용하여 저장소를 시뮬레이션.

   ```csharp
   using System.Collections.Generic;
   using GameFrameX.Runtime;

   public class MySettingHelper : SettingHelperBase
   {
       private readonly Dictionary<string, string> _store = new Dictionary<string, string>();

       public override int Count => _store.Count;

       public override bool Load() { return true; }

       public override bool Save() { /* 파일/데이터베이스에 다시 쓰기 */ return true; }

       public override bool HasSetting(string settingName) => _store.ContainsKey(settingName);

       public override bool RemoveSetting(string settingName) => _store.Remove(settingName);

       public override void RemoveAllSettings() => _store.Clear();

       public override void SetString(string settingName, string value) => _store[settingName] = value;

       public override string GetString(string settingName, string defaultValue)
           => _store.TryGetValue(settingName, out var v) ? v : defaultValue;

       // Bool/Int/Float도 동일한 방식; 불린은 SetInt/GetInt 0/1 저장을 활용할 수 있음, PlayerPrefsSettingHelper 참조.
   }
   ```

   Source: [PlayerPrefsSettingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L42-L42)（베이스 클래스의 표준 구현 예시로, `GetBool`/`SetBool`을 하위 `StorageBackend.GetInt/SetInt`에 위임하는 방법을 보여줌）

4. **스크립트를 씬의 GameObject에 부착**. `SettingHelperBase`는 `MonoBehaviour`를 상속하므로, `SettingComponent`가 발견하고 인스턴스화할 수 있도록 반드시 GameObject에 부착해야 합니다.

5. **`SettingComponent`의 Inspector에서 `Custom Setting Helper` 선택**. `Setting Helper Type`을 본인의 `MySettingHelper`로 설정하면, 프레임워크 시작 시 리플렉션으로 해당 Helper를 생성합니다.

   Source: [SettingComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/SettingComponent.cs)(`SettingComponent`가 `ISettingHelper` 인스턴스를 생성하고 보유함)

## 일반적인 변형

- **Helper를 수정하지 않고 하위 저장 백엔드만 전환**: 계속해서 `PlayerPrefsSettingHelper`를 사용하면서 하위 레이어를 SQLite/위챗 미니게임 SDK로 전환하고 싶다면, `ISettingStorageBackend`를 구현하고 시작 단계에서 `SettingStorageBackendFactory.RegisterMiniGameBackend`를 통해 등록하면 됩니다. `PlayerPrefsSettingHelper` 내부는 `StorageBackend` 속성을 통해 해당 백엔드를 지연 로딩합니다.

  ```csharp
  // 플랫폼 시작 시 (UNITY_EDITOR가 아닌 경우에만 적용)
  SettingStorageBackendFactory.RegisterMiniGameBackend(() => new MySqliteBackend());
  ```

  Source: [SettingStorageBackendFactory.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/SettingStorageBackendFactory.cs#L22-L30)

- **미니게임 플랫폼 구현 참고**: `WeChatMiniGameSettingStorage`, `AlipayMiniGameSettingStorage` 등은 이미 `ISettingStorageBackend` 인터페이스에 따라 플랫폼 네이티브 API를 래핑하고 있으므로, 최소 가용 구현 예제로 참조할 수 있습니다.

  Source: [WeChatMiniGameSettingStorage.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/MiniGame/WeChat/WeChatMiniGameSettingStorage.cs), [Storage/ISettingStorageBackend.cs](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Storage/ISettingStorageBackend.cs)

## 일반적인 오류

- **`SettingHelperBase`를 상속하지 않음**: `ISettingHelper`를 직접 구현하는 것도 가능하지만, `SettingComponent`는 일반적으로 `SettingHelperBase` 파생 클래스를 기준으로 스캔합니다. 상속 관계를 유지하는 것이 더 안정적입니다.
- **Helper가 씬 객체에 부착되지 않음**: `SettingHelperBase`는 `MonoBehaviour`이며, 부착되지 않으면 프레임워크가 인스턴스화할 수 없어 런타임에 기본 구현을 얻거나 예외가 발생합니다.
- **`GetAllSettingNames(List<string>)`에서 `results == null` 검증 누락**: 베이스 클래스는 `GameFrameworkException("Results is invalid.")`을 던지기를 기대하며, 프레임워크의 다른 모듈은 이 규약에 의존합니다.
- **Helper 생성자에서 `UnityEngine.PlayerPrefs` 등 런타임이 필요한 API에 접근**: 정적 생성자나 필드 초기화 단계에서 Unity API에 접근하지 말고, `Load()` 또는 최초 접근 시에 실행해야 합니다.
- **저장 로직이 예외를 삼킴**: 쓰기 실패 시 `false`를 반환하여 `SettingComponent`가 실패를 감지하고 알릴 수 있도록 해야 합니다. `try/catch` 후 조용히 `true`를 반환하면 안 됩니다.

## 배경 (선택 사항)

`PlayerPrefsSettingHelper`는 모든 읽기/쓰기를 `ISettingStorageBackend`에 위임하며, `SettingStorageBackendFactory`가 `UNITY_EDITOR`에서는 `UnityPlayerPrefsSettingStorage`를, 실제 미니게임 플랫폼에서는 각 플랫폼 어댑터가 등록한 팩토리를 사용합니다. 이는 "Helper를 다시 작성하지 않고도 하위 저장소를 전환"할 수 있는 빠른 경로입니다. 비즈니스적으로 정말 새로운 Helper 동작(예: 원격 가져오기, 암호화, 프로세스 간 동기화)이 필요한 경우에만 본 페이지의 단계에 따라 커스텀 `SettingHelperBase` 파생 클래스를 구현해야 합니다.
