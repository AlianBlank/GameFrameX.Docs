# YooAsset 패치 플로우 실패 시 대처 방법

YooAsset 패치 플로우가 `ProcedurePatchInit` → `ProcedureUpdateStaticVersion` → `ProcedureUpdateManifest` → `ProcedureCreateDownloader` → `ProcedureDownloadWebFiles` → `ProcedurePatchDone` 체인 중 어느 단계에서든 예외가 발생하면 시작 플로우가 멈추거나 상위 플로우로 되돌아갑니다. 이 문서에서는 증상별로 원인 파악 및 수정 방법을 제시합니다.

## 빠른 진단

| 증상 | 원인 | 수정 |
|------|------|------|
| `ProcedurePatchInit`에 멈춰 있고 리소스 패키지 초기화 실패 | `packageUrl`이 비어 있거나 CDN에 접근 불가 | `procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName)`이 올바르게 기록되었는지 확인; CDN 접근 가능 여부 확인 |
| `ProcedureUpdateStaticVersion`에 멈춰 있고 버전 불일치 메시지 표시 | 원격 정적 버전 번호와 로컬이 일치하지 않음 | 재빌드 후 원격 정적 버전 파일을 게시; `StaticVersion.txt`가 업로드되었는지 확인 |
| `ProcedureUpdateManifest`에서 매니페스트 오류 발생 | 원격 매니페스트 파일이 게시되지 않았거나 서명 오류 | 리소스 매니페스트(`PackageManifest_{ver}.hash` / `.bytes`)를 재게시하고 YooAsset 암호화 키 확인 |
| `ProcedureDownloadWebFiles` 진입 후 진행이 멈춤 | 다운로더가 비어 있거나 HTTP 속도 제한 | `ProcedureCreateDownloader`의 산출물에 `VarObject` 키 `"Downloader"`가 포함되어 있는지 확인; 프록시/대역폭 확인 |
| 다운로드 중간에 `ProcedureCreateDownloader`로 되돌아감 | 단일 파일 다운로드 실패로 `OnDownloadErrorCallback` 트리거 | `AssetWebFileDownloadFailedEventArgs`의 `FileName`과 `ErrorInfo`를 확인하여 원격에서 누락된 파일 파악 |
| `ProcedureDownloadWebFiles` 완료 후 `ProcedurePatchDone`에 진입하지 않음 | `downloader.Status != EOperationStatus.Succeed` | 이전 `OnDownloadError` 로그를 확인하고, 누락된 리소스를 보완한 후 다시 시작 |

## 수정 단계

### 1. 리소스 패키지 초기화 실패

`ProcedurePatchInit`은 `GamePlayMode`에 따라 초기화 분기를 선택합니다: EditorSimulate/Offline은 빈 URL을 사용하고, 나머지 모드는 `BuildInPackageName`으로 가져온 패키지 주소를 사용합니다.

```csharp
// ProcedurePatchInit.InitPatchAsync (Runtime/Procedures/Patch/ProcedurePatchInit.cs)
if (assetComponent.GamePlayMode == EPlayMode.EditorSimulateMode || assetComponent.GamePlayMode == EPlayMode.OfflinePlayMode)
{
    await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, string.Empty, string.Empty, true);
    ChangeState<ProcedureUpdateStaticVersion>(procedureOwner);
    return;
}

var packageUrl = procedureOwner.GetData<VarString>(AssetComponent.BuildInPackageName);
await assetComponent.InitPackageAsync(AssetComponent.BuildInPackageName, packageUrl.Value, packageUrl.Value, true);
```

출처: [ProcedurePatchInit.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedurePatchInit.cs#L33-L48)

수정 작업:

1. 디버그 모드(EditorSimulate)에서 재현하여 CDN 네트워크 문제를 배제합니다.
2. `ProcedureGetGameAssetPackageVersionInfoByDefaultPackageState`에서 `packageUrl`이 BlackBoard에 기록되었는지 확인합니다.
3. 실기기 모드에서 `StartupOptions.PlayMode`가 `NormalizeAssetPlayMode`에 의해 변경되었는지 확인합니다(WebGL은 `WebPlayMode`로 강제, 에디터 외 환경에서는 `EditorSimulateMode`가 `HostPlayMode`로 강제 변경됨).

### 2. 정적 버전/매니페스트 업데이트 실패

`ProcedureUpdateStaticVersion`과 `ProcedureUpdateManifest`는 YooAsset 내장 플로우에 의해 구동됩니다. 일반적인 실패 원인:

- 원격에 `StaticVersion.txt`만 업로드되고 `PackageManifest_*.bytes`가 업로드되지 않았습니다.
- YooAsset 암호화 키가 에디터와 일치하지 않아 매니페스트 파싱이 실패합니다.

수정 작업:

1. 빌드 도구(Builtin Build Pipeline)로 다시 빌드한 후 `ServerData/{Platform}` 전체를 모두 업로드하고, `StaticVersion.txt`를 누락하지 않도록 합니다.
2. 에디터에서 `YooAsset > AssetBundle Builder`로 빌드한 후 로컬에 HTTP 서버를 띄워 동일한 `PlayMode`로 먼저 검증합니다.
3. 매니페스트 암호화를 끄거나 키가 일치하는지 확인합니다.

### 3. 다운로더가 비어 있거나 다운로드 중단

`ProcedureDownloadWebFiles`는 `ProcedureCreateDownloader`가 기록한 `VarObject` 키 `"Downloader"`(`ResourceDownloaderOperation`)를 직접 소비하며, 콜백을 통해 오류를 감시합니다:

```csharp
// ProcedureDownloadWebFiles.BeginDownload (Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs)
var downloader = (ResourceDownloaderOperation)procedureOwner.GetData<VarObject>("Downloader").GetValue();

downloader.OnDownloadErrorCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetWebFileDownloadFailedEventArgs.Create(data.PackageName, data.FileName, data.ErrorInfo));
    ChangeState<ProcedureCreateDownloader>(procedureOwner);
};
downloader.OnDownloadProgressCallback = data =>
{
    GameEntry.GetComponent<EventComponent>().Fire(this, AssetDownloadProgressUpdateEventArgs.Create(
        data.PackageName, data.TotalDownloadCount, data.CurrentDownloadCount,
        data.TotalDownloadBytes, data.CurrentDownloadBytes));
    StartupProcedureUtility.SetDownloadProgress(
        StartupProcedureUtility.GetUIHandler(procedureOwner),
        data.CurrentDownloadBytes, data.TotalDownloadBytes);
};

downloader.BeginDownload();
yield return downloader;

if (downloader.Status == EOperationStatus.Succeed)
{
    ChangeState<ProcedurePatchDone>(procedureOwner);
}
```

출처: [ProcedureDownloadWebFiles.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureDownloadWebFiles.cs#L36-L61)

수정 작업:

1. `AssetWebFileDownloadFailedEventArgs`를 구독하여 `FileName`과 `ErrorInfo`를 확인하고, CDN에서 해당 파일이 존재하며 익명으로 다운로드 가능한지 확인합니다.
2. HTTPS 인증서가 신뢰되지 않으면 YooAsset이 `ErrorInfo`에 SSL 오류를 보고합니다. YooAsset 설정에서 HostPlayMode에 인증서를 구성하거나 HTTP로 되돌릴 수 있습니다.
3. 단일 파일 실패는 `ChangeState<ProcedureCreateDownloader>`를 트리거하여 재시도하므로 수동 개입이 필요 없습니다. 연속으로 실패하면 `ClearCacheWhenDownloadFailure` 같은 YooAsset 스위치로 로컬 캐시를 정리한 후 다시 시작합니다.

### 4. 시작 후 `ProcedureGameLauncherState` 이전에 멈춤

`ProcedurePatchDone`은 패치 완료의 마지막 단계입니다. 플로우가 여기서 멈춘다면:

- `ProcedureDownloadWebFiles`가 `ChangeState<ProcedurePatchDone>`을 성공적으로 트리거했는지 확인합니다(`downloader.Status == EOperationStatus.Succeed`일 때만 전환됨).
- `AssetPatchStatesChangeEventArgs`를 구독하는 커스텀 Procedure가 플로우를 가로챘는지 확인합니다.

## 검증

1. 게임에 다시 진입하여 `ProcedureGetGlobalInfoState` → `ProcedurePatchDone` 사이에 `EPatchStates.DownloadWebFiles` 이벤트가 보고되는지 관찰합니다.
2. 에디터에서 `EditorSimulateMode`를 사용하고 `StartupOptions.GlobalInfoUrls`를 로컬로 지정하여 패치 체인이 정상 동작하는지 확인합니다.
3. 실기기 모드에서 YooAsset의 샌드박스 디렉터리(`Application.persistentDataPath/yoo/{PackageName}`)를 열어 `PackageManifest_*.bytes`와 리소스 파일이 모두 저장되었는지 확인합니다.
4. 위 사항이 모두 정상인데도 여전히 멈춘다면 YooAsset 샌드박스를 정리한 후 다시 시작하여 더티 캐시로 인한 매니페스트 검증 실패를 배제합니다.
