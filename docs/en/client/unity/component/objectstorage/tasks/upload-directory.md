# How to Upload an Entire Directory

Call `IObjectStorageUploadManager.UploadDirectory(localDirectory)` to upload a local directory (and all files under it) to the object storage bucket. The root path is specified by `SetSavePath`.

## Prerequisites

- An upload manager implementation that inherits from `BaseObjectStorageUploadManager` (for example, an implementation based on a specific cloud service SDK).
- `Init(accessKey, secretKey, bucketName, endpoint)` has been called to complete credential and bucket initialization.
- `SetSavePath(savePath)` has been called to set the save directory in the bucket (a trailing separator is optional; the implementation will automatically strip it).

## Steps

1. **Initialize the upload manager**. Get a concrete implementation through `ObjectStorageUploadFactory` and complete the credential and bucket name configuration.

```csharp
IObjectStorageUploadManager uploader = ObjectStorageUploadFactory.Create();
// Internally calls the concrete implementation's Init(accessKey, secretKey, bucketName, endpoint)
uploader.Init("your-access-key", "your-secret-key", "your-bucket-name");
```

2. **Set the save path in the bucket**. `savePath` is the root directory prefix for the files in the bucket.

```csharp
uploader.SetSavePath("/assets/Resources");
```

3. **Call `UploadDirectory` to upload the entire directory**. Pass in a local absolute or relative directory path; all files under the directory will be uploaded under `savePath` according to their relative paths.

```csharp
uploader.UploadDirectory("Assets/StreamingAssets/configs");
```

`UploadDirectory` internally records the passed path as `UploadRootPath`, then forwards it to the abstract method `UploadDirectoryInternal(localDirectory)`:

```csharp
public void UploadDirectory(string localDirectory)
{
    UploadRootPath = localDirectory;
    UploadDirectoryInternal(localDirectory);
}
```

## Common Variants

- **Upload only a single file**: Use `uploader.UploadFile("Assets/StreamingAssets/configs/a.json")` instead, which places only the specified file into `savePath`.
- **Preserve the original directory hierarchy**: When implementing `UploadDirectoryInternal`, use `UploadRootPath` as the base and generate object keys by the subdirectory path to preserve the local structure.

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Calling `UploadDirectory` before `Init` results in NRE or authentication failure | Credentials not injected | Make sure to call `Init` first, then `SetSavePath`, then `UploadDirectory` |
| After upload, all files in the bucket pile up at the root with no hierarchy | `UploadDirectoryInternal` does not generate object keys by subdirectory | Compute the relative path based on `UploadRootPath` and use it as the object key suffix |
| `savePath` with a trailing separator causes `//` in path concatenation | `SetSavePath` normalization was not applied | Always set the target path through `SetSavePath`; the implementation will strip the trailing separator |

## Background (Optional)

`UploadDirectory` only records the root directory and triggers the abstract method. The actual traversal and upload logic is completed by the concrete implementation (inheriting from `BaseObjectStorageUploadManager`) inside `UploadDirectoryInternal`, which typically recursively reads local files and uses the relative path outside `UploadRootPath` as part of the object key.
