# How to Define a State

In GameFrameX FSM, a state is implemented by inheriting the abstract base class `FsmState<T>`. `T` is the owner type of the state machine. Once inherited, override the lifecycle callbacks as needed to complete the state definition.

## Prerequisites

- The `GameFrameX.Fsm.Runtime` assembly has been imported and can be referenced directly in the Unity project.
- An owner type `T` (which must be a `class`) already exists for subsequently creating the state machine.

## Steps

1. **Determine the state machine owner type**

   For example, use the character controller `Player` as the generic parameter `T`.

2. **Inherit from `FsmState<T>` and implement the required callbacks**

   `FsmState<T>` is an abstract base class that provides six lifecycle hooks: `OnInit` / `OnEnter` / `OnUpdate` / `OnFixedUpdate` / `OnLeave` / `OnDestroy`. All are `protected internal virtual`, so override only those that are needed.

   ```csharp
   using GameFrameX.Fsm.Runtime;

   public class IdleState : FsmState<Player>
   {
       protected internal override void OnEnter(IFsm<Player> fsm)
       {
           // Logic performed when entering the idle state
       }

       protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
       {
           // Per-frame polling logic
       }

       protected internal override void OnLeave(IFsm<Player> fsm, bool isShutdown)
       {
           // Logic performed when leaving the idle state
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L41-L108)

3. **Trigger a state transition within the state**

   Use the base class-provided `ChangeState<TState>(IFsm<T> fsm)` to switch to another state:

   ```csharp
   protected internal override void OnUpdate(IFsm<Player> fsm, float elapseSeconds, float realElapseSeconds)
   {
       if (/* Trigger condition */)
       {
           ChangeState<RunState>(fsm);
       }
   }
   ```

   Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L127-L136)

4. **Add the state to the state machine**

   When creating the state machine, pass states through the `params FsmState<T>[]` parameter of `CreateFsm<T>`, or add them dynamically after creation by calling `AddState`:

   ```csharp
   var fsm = FsmComponent.Instance.CreateFsm(player, new IdleState(), new RunState());
   // or
   fsm.AddState(new RunState());
   ```

   Source: [FsmComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmComponent.cs#L205-L220)

## Lifecycle Callback Overview

| Callback | Trigger Time | Typical Use |
|------|---------|---------|
| `OnInit(IFsm<T> fsm)` | When the state is first added to the state machine | Initialize internal data |
| `OnEnter(IFsm<T> fsm)` | When entering the state | Play animations and set flags |
| `OnUpdate(IFsm<T> fsm, float, float)` | Per-frame polling | Detect transition conditions |
| `OnFixedUpdate(IFsm<T> fsm, float, float)` | Fixed-timestep polling | Physics-related logic |
| `OnLeave(IFsm<T> fsm, bool isShutdown)` | When leaving the state | Clean up state data and restore flags; `isShutdown` indicates whether the transition was triggered because the state machine is shutting down |
| `OnDestroy(IFsm<T> fsm)` | When the state is destroyed | Release resources |

## Common Variants

- **Empty state shell**: If the state is used only as a placeholder or for grouping, none of the methods need to be overridden, as in the test case below:

  ```csharp
  private class TestIdleState : FsmState<object>
  {
  }
  ```

  Source: [UnitTests.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Tests/UnitTests.cs#L128-L130)

- **Switching states by type**: In addition to the generic `ChangeState<TState>`, the base class provides the `ChangeState(IFsm<T>, Type)` overload, which is suitable for dynamically switching states based on external configuration:

  ```csharp
  ChangeState(fsm, typeof(RunState));
  ```

  Source: [FsmState.cs](https://github.com/GameFrameX/com.gameframex.unity.fsm/blob/main/Runtime/Fsm/FsmState.cs#L144-L163)

## Common Errors

- **Adding states of the same type more than once**: The state machine stores states by type, so calling `AddState` with a duplicate type throws `GameFrameworkException`.
- **Passing an incorrect type during a state transition**: `ChangeState(fsm, stateType)` verifies that `stateType` must derive from `FsmState<T>`; otherwise, it throws `GameFrameworkException("State type '...' is invalid.")`.
- **Calling `ChangeState` directly when `fsm` is no longer valid**: The base class throws `GameFrameworkException("FSM is invalid.")`.

## Background (Optional)

The `FsmState<T>` abstract class exposes only hooks and state-transition capabilities; it does not hold any runtime data. All data shared across states is accessed through `GetData` / `SetData` on `IFsm<T>`. This keeps state implementations lightweight and easy to test.
