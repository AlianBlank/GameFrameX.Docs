# How to Configure Timeout and Concurrent Connections

In GameFrameX.Web, the timeout `Timeout` can be set via an Inspector serialized field or in code (default 5 seconds), while the concurrent connections `MaxConnectionPerServer` can only be set in code on `IWebManager` (default 8); it limits the number of simultaneously processed requests on the two scheduling channels — normal (JSON) requests and binary requests — respectively.

## Prerequisites

- The `WebComponent` component is attached in the scene (menu `GameFrameX/Web`).
- To access the manager in code, reference the namespaces `GameFrameX.Web.Runtime` and `GameFrameX.Runtime`.

## Configuration Quick Reference

| Option | Type | Default | Where It Takes Effect | Description |
|--------|------|--------|----------|------|
| `WebComponent.m_Timeout` | `float` (seconds) | `5f` | Inspector serialized field | Written to the manager during component initialization |
| `WebComponent.Timeout` | `float` (seconds) | Proxied to the manager | Property | Also writes back to the serialized field |
| `WebManager.Timeout` | `float` (seconds) | `5f` | Manager property | Updates `RequestTimeout` in sync when set |
| `WebManager.RequestTimeout` | `TimeSpan` | Derived from `Timeout` | Manager property | Timeout actually passed to the request object |
| `WebManager.MaxConnectionPerServer` | `int` | `8` | Manager property | Simultaneous processing cap applied to the normal channel and the binary channel each |

## Steps

### 1. Set the timeout in the Inspector

Select the GameObject with `WebComponent` attached, and modify the **Timeout** field in the Inspector (unit: seconds, default 5):

```csharp
[SerializeField] [Tooltip("超时时间.单位：秒")]
private float m_Timeout = 5f;
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L59-L60)

When the component's `Awake()` runs, this value is written to the manager:

```csharp
m_WebManager = GameFrameworkEntry.GetModule<IWebManager>();
if (m_WebManager == null)
{
    Log.Fatal("Web manager is invalid.");
    return;
}

m_WebManager.Timeout = m_Timeout;
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L88)

### 2. Adjust the timeout at runtime in code

`WebComponent.Timeout` proxies directly to the manager and also writes the value back to the serialized field:

```csharp
public float Timeout
{
    get { return m_WebManager.Timeout; }
    set { m_WebManager.Timeout = m_Timeout = value; }
}
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L66-L70)

Usage example:

```csharp
// Call after the component's Awake, e.g., in Start()
webComponent.Timeout = 15f; // Change the global timeout to 15 seconds
```

### 3. Set the concurrent connections in code

`MaxConnectionPerServer` exists only on `WebManager` / `IWebManager` and is not exposed on `WebComponent`, so it must be changed via code:

```csharp
public WebManager()
{
    MaxConnectionPerServer = 8;
    Timeout = 5f;
}

/// <summary>
/// Get or set the timeout (seconds)
/// </summary>
public float Timeout
{
    get { return m_Timeout; }
    set
    {
        m_Timeout = value;
        RequestTimeout = TimeSpan.FromSeconds(value);
    }
}

/// <summary>
/// Get or set the maximum number of connections per server
/// </summary>
public int MaxConnectionPerServer { get; set; }
```

Source: [WebManager.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebManager.cs#L42-L70)

Usage example (same way of obtaining the module as in `WebComponent.Awake`):

```csharp
GameFrameworkEntry.GetModule<IWebManager>().MaxConnectionPerServer = 4; // At most 4 simultaneous requests per channel
```

Source: [WebComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.web/blob/main/Runtime/Web/WebComponent.cs#L81-L81)

## Common Variants

**Control the concurrency of the two channels separately**: Normal (JSON) requests and binary requests share the same `MaxConnectionPerServer` value but count independently — the scheduling entry points are `m_SendingNormalList` (normal) and `m_SendingBinaryList` (binary), respectively:

```csharp
// Normal request channel: in Update, pull tasks from the waiting queue up to the cap
if (m_SendingNormalList.Count < MaxConnectionPerServer)
{
    if (m_WaitingNormalQueue.Count > 0)
    {
        var webJsonData = m_WaitingNormalQueue.Dequeue();
        // ...send the request and add it to m_SendingNormalList
    }
}
```

## Common Mistakes

| Symptom | Cause | Fix |
|------|------|------|
| Changed the timeout in the Inspector but it has no effect | Code overrides it after `Awake()` with `WebComponent.Timeout` or `m_WebManager.Timeout` | Configure in one place only; runtime changes should be made in `Start()` or later |
| Can't find a field to change concurrency in the Inspector | `MaxConnectionPerServer` is not serialized on `WebComponent` | Set it in code via `GameFrameworkEntry.GetModule<IWebManager>()` |
| Requests don't time out for a long time after setting `Timeout = 0.5f` | When passed to UnityWebRequest, it is truncated via `(int)RequestTimeout.TotalSeconds`; values below 1 second become `0` | Set the timeout to at least `1f` or a larger whole number of seconds |
| Interpreting `MaxConnectionPerServer` as the global total concurrency | The normal/binary channels each check the value independently | Calculate the concurrency cap per channel |

## Background (Optional)

The setter of `Timeout` synchronously derives `RequestTimeout = TimeSpan.FromSeconds(value)`; the value is only written to the underlying `UnityWebRequest.timeout` (seconds) or `HttpWebRequest.Timeout` (milliseconds) when the request is actually created, so changing the timeout only affects newly initiated requests. For concurrency, requests first enter a waiting queue; `WebManager.Update` checks `m_SendingNormalList.Count < MaxConnectionPerServer` each frame and only dequeues and dispatches when the condition is met, with the excess continuing to queue.
