# 式木/パス連結拡張の使い方

`ExpressionExtension` は `Expression<Func<T, bool>>` 向けのチェーン式連結メソッド群を提供し、複数の独立した述語式を安全に新しい式へと組み合わせることを可能にします。`Expression.AndAlso` / `ParameterExpression` などのボイラープレートコードを手書きする必要はなく、クエリ条件の動的連結やフィルターパイプラインなどのシーンで多用されます。

## 前提条件

- プロジェクトから `GameFrameX.Foundation.Extensions` を参照する。
- ファイルの先頭に `using System.Linq.Expressions;` と `using GameFrameX.Foundation.Extensions;` を記述する。
- ターゲットフレームワークが `Expression<Func<T, bool>>` をサポートする(標準の .NET で可)。

## 操作手順

### 1. `And` で 2 つの条件を連結する

左右両側の式が成立する必要がある場合は `And` を使用します(内部では `Expression.AndAlso` を使用するため、短絡評価をサポートします)。

```csharp
using System.Linq.Expressions;
using GameFrameX.Foundation.Extensions;

Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.And(expr2);

bool ok1 = combined.Compile()("testing"); // true
bool ok2 = combined.Compile()("test");    // false
```

Source: [ExpressionExtension.cs#L57-L67](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L57-L67)

### 2. `Or` で 2 つの条件を連結する

いずれかの式が成立すればよい場合は `Or` を使用します(内部では `Expression.OrElse` を使用するため、短絡評価をサポートします)。

```csharp
Expression<Func<string, bool>> expr1 = s => s.Length > 5;
Expression<Func<string, bool>> expr2 = s => s.StartsWith("test");

var combined = expr1.Or(expr2);
bool ok = combined.Compile()("test"); // true: StartsWith("test") にヒット
```

Source: [ExpressionExtension.cs#L114-L125](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L114-L125)

### 3. `AndIf` / `OrIf` でスイッチによる条件付き連結

ブール値のスイッチで実際に連結に参加するかどうかを判断したい場合は、条件付きバージョンを使用します。条件が `false` の場合は左側の式をそのまま返し、アクセサや書き換えロジックは経由しません。

```csharp
Expression<Func<string, bool>> left  = s => s.Length > 5;
Expression<Func<string, bool>> right = s => s.StartsWith("test");

bool enableFilter = true;
var withFilter = left.AndIf(() => enableFilter, right);

enableFilter = false;
var withoutFilter = left.AndIf(() => enableFilter, right); // left と同等
```

Source: [ExpressionExtension.cs#L83-L100](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L83-L100)

### 4. `Not` で否定する

```csharp
Expression<Func<int, bool>> expr = x => x > 5;
var neg = expr.Not(); // x => !(x > 5)、すなわち x <= 5 と同等
```

Source: [ExpressionExtension.cs#L171-L178](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/ExpressionExtension.cs#L171-L178)

### 5. 複数条件のチェーン連結

戻り値も `Expression<Func<T, bool>>` のため、連続して呼び出すことができます。

```csharp
Expression<Func<string, bool>> baseExpr = s => s != null;
var query = baseExpr
    .And(s => s.Length > 0)
    .And(s => s.Contains("foo"))
    .OrIf(() => AllowShort, s => s.Length <= 2);
```

## よくあるバリエーション

- **述語文字列 + LINQ プロバイダ**:連結完了後に `Compile()` を呼び出して `Func<T, bool>` を取得し、直接フィルタリングします。EF Core などの ORM と組み合わせる場合は、`combined` をそのまま `Where(...)` に渡せば SQL に変換されます。
- **空コレクションの短絡**:外層で `IEnumerable.Any()` などを使用して先に空かどうかを判定してから、`And` / `Or` を呼び出します。
- **複数パラメータの Lambda**:`CustomExpressionVisitor` は複数パラメータの Lambda に対して最初のパラメータのみを置き換え、残りはそのまま保持します。

## よくあるエラー

| 現象 | 原因 | 修正方法 |
|------|------|------|
| `ArgumentNullException`(パラメータ名 `leftExpression` / `rightExpression` / `condition` / `expr`) | いずれかの式または条件デリゲートが `null` | 呼び出し前に式を null チェックするか、外層で常に `true` を返す条件デリゲートを提供する |
| 連結後にコンパイルが失敗し、「パラメータが一致しません」と報告される | 左右の式の型が異なる(例: `Func<string,bool>` と `Func<int,bool>`) | 両方の式で同じジェネリックパラメータ `T` を使用していることを確認する |
| 連結結果に短絡動作がない | 本拡張が `And`/`Or` を使用していると誤解している | 本拡張の `And`/`Or` は内部で `AndAlso`/`OrElse` を使用しているため、最初から短絡評価され、追加の処理は不要 |
| 複数パラメータの Lambda を連結後、動作が異常 | 最初のパラメータのみが置換され、残りは保持される | 述語を 1 つのパラメータのみを受け取る Lambda として記述するか、式を自分で書き換える |

## 背景(任意)

`And` / `Or` / `AndIf` / `OrIf` はいずれも内部クラス `CustomExpressionVisitor`(`ExpressionVisitor` を継承)を通じて、左右 2 つの式それぞれの `ParameterExpression` を新しく作成した統一パラメータへ置換し、その後 `Expression.Lambda` で再組み立てします。これにより、左右の部分木の元の構造を保ちつつ、新しい式が 1 つのパラメータのみを持つことが保証され、チェーン式連結や ORM 間翻訳が容易になります。
