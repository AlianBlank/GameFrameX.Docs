# 介面與抽象類別速查

本頁收錄 `GameFrameX.ObjectStorage.Editor` 命名空間下的對外介面與抽象類別，用於實作自訂物件儲存後端或排查「該實作哪個方法」的問題。

| [IObjectStorageUploadManager](https://github.com/GameFrameX/com.gameframex.unity.objectstorage/blob/main/Editor/IObjectStorageUploadManager.cs#L3-L22) | interface | GameFrameX.ObjectStorage.Editor | 在 `IObjectStorageManager` 之上宣告上傳相關方法 |

## IObjectStorageManager

唯一的初始化入口，所有物件儲存實作都必須實作該介面。

| 方法 | 簽章 | 說明 |
|------|------|------|
| `Init` | `void Init(string accessKey, string secretKey, string bucketName, string endpoint = null)` | `accessKey` 為 key,`secretKey` 為金鑰，`bucketName` 為儲存池名稱，`endpoint` 為位址(部分物件儲存不需要) |

## IObjectStorageUploadManager

繼承自 `IObjectStorageManager`,在初始化的基礎上宣告上傳相關方法。

| 方法 | 簽章 | 說明 |
|------|------|------|
| `SetSavePath` | `void SetSavePath(string savePath)` | 上傳到物件儲存的目標路徑(目錄前綴) |
| `UploadDirectory` | `void UploadDirectory(string localDirectory)` | 上傳本機目錄 |
| `UploadFile` | `bool UploadFile(string localFilePathAndName)` | 上傳單一本機檔案，回傳是否成功 |

## BaseObjectStorageUploadManager

實作 `IObjectStorageUploadManager`,封裝共用邏輯；子類別只需實作兩個抽象方法。

### 已實作的成員

| 成員 | 簽章 | 行為 |
|------|------|------|
| `SetSavePath` | `void SetSavePath(string savePath)` | 自動去除結尾目錄分隔符號後寫入 `BucketSavePath` |
| `UploadDirectory` | `void UploadDirectory(string localDirectory)` | 將 `localDirectory` 寫入 `UploadRootPath`,再呼叫 `UploadDirectoryInternal` |
| `UploadFile` | `bool UploadFile(string localFilePathAndName)` | 直接轉發到 `UploadFileInternal` |

### 欄位

| 欄位 | 型別 | 說明 |
|------|------|------|
| `BucketSavePath` | `protected string` | 透過 `SetSavePath` 設定的目標路徑 |
| `UploadRootPath` | `protected string` | 透過 `UploadDirectory` 設定的本機目錄，初始值 `string.Empty` |

### 子類別必須實作的抽象成員

| 成員 | 簽章 | 說明 |
|------|------|------|
| `Init` | `public abstract void Init(string accessKey, string secretKey, string bucketName, string endpoint = null)` | 初始化帳號/連線等 |
| `UploadDirectoryInternal` | `protected abstract void UploadDirectoryInternal(string localDirectory)` | 真正執行目錄上傳的邏輯 |
| `UploadFileInternal` | `protected abstract bool UploadFileInternal(string localFilePathAndName)` | 真正執行單一檔案上傳，回傳是否成功 |

最小自訂實作範例：

```csharp
using GameFrameX.ObjectStorage.Editor;

public sealed class MyUploadManager : BaseObjectStorageUploadManager
{
    public override void Init(string accessKey, string secretKey, string bucketName, string endpoint = null)
    {
        // 在這裡初始化具體 SDK 的客戶端
    }

    protected override void UploadDirectoryInternal(string localDirectory)
    {
        // 遍歷 localDirectory 並上傳
    }

    protected override bool UploadFileInternal(string localFilePathAndName)
    {
        // 上傳單一檔案
        return true;
    }
}
```

## ObjectStorageUploadFactory

透過泛型約束 `where T : IObjectStorageUploadManager`,使用反射建立實例並自動呼叫 `Init`,回傳已初始化完成的上傳管理器。

| 方法 | 簽章 | 說明 |
|------|------|------|
| `Create<T>` | `static IObjectStorageUploadManager Create<T>(string accessKey, string secretKey, string bucketName, string endpoint = null) where T : IObjectStorageUploadManager` | 透過 `Activator.CreateInstance<T>()` 建立實例，立即呼叫 `Init`,回傳管理器 |

呼叫範例：

```csharp
var upload = ObjectStorageUploadFactory.Create<MyUploadManager>(
    accessKey: "AKID...",
    secretKey: "SECRET...",
    bucketName: "my-bucket",
    endpoint: "https://oss-cn-hangzhou.aliyuncs.com");

upload.SetSavePath("/release/1.0.0/");
upload.UploadFile("C:/build/Windows/game.exe");
```

## 實作要點速查

| 情境 | 需要做什麼 |
|------|-----------|
| 想完成一個完整上傳流程 | 實作 `BaseObjectStorageUploadManager` 的三個抽象成員，然後用 `ObjectStorageUploadFactory.Create<T>` 取得實例 |
| 想保留現有 `Init`/上傳邏輯，只更換底層 SDK | 繼承 `BaseObjectStorageUploadManager` 覆寫 `UploadFileInternal` 與 `UploadDirectoryInternal` 即可，`SetSavePath` 已自動處理結尾分隔符號 |
| 自訂實作不打算沿用基底類別的 `SetSavePath` 處理 | 直接實作 `IObjectStorageUploadManager`,自行確保路徑格式 |
