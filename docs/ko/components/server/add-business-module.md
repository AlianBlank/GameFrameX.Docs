# 새로운 비즈니스 모듈을 추가하는 방법(Apps 계층)

`GameFrameX.Apps` 프로젝트 아래에 `Component` + `Entity` + `State` 디렉터리 규칙에 따라 새 비즈니스 하위 모듈을 추가하고, 핫 업데이트(Hotfix) 계층에서 호출되도록 하면 최소한으로 사용 가능한 비즈니스 모듈 연동이 완료됩니다.

## 사전 조건

- `GameFrameX.Server.Source` 저장소를 클론하여 빌드할 수 있으며, `.NET 8+` SDK를 사용할 수 있어야 합니다.
- `GameFrameX.Apps` 프로젝트의 위치를 알고 있어야 합니다: `GameFrameX.Apps/`.
- `GameFrameX.Hotfix`가 `<ProjectReference>`를 통해 `GameFrameX.Apps`를 참조한다는 것을 알고 있어야 합니다([GameFrameX.Hotfix.csproj](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj#L18) 참조).

## 작업 단계

아래에서는 `Player/Mail` 모듈을 추가하는 것을 예로 들어, 디렉터리, 컴포넌트, 상태 생성부터 Hotfix에서 호출되기까지의 전체 단계를 보여줍니다.

1. **디렉터리 규칙에 따라 하위 모듈 폴더 생성**.
   `GameFrameX.Apps/` 아래에 새 하위 디렉터리를 만듭니다. 2단계 구조를 권장합니다: `{도메인}/{모듈}/{Component|Entity}`.
   예를 들어 메일 모듈을 추가하는 경우:
   ```text
   GameFrameX.Apps/Player/Mail/Component/MailComponent.cs
   GameFrameX.Apps/Player/Mail/Entity/MailState.cs
   ```
   기존 예시로는 `Account/Login`과 `Player/Bag`의 디렉터리 구조를 참고할 수 있습니다([LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L30-L46), [BagComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Player/Bag/Component/BagComponent.cs)).

2. **엔티티 상태 클래스 생성(Entity/State)**.
   프레임워크에서 제공하는 `CacheState`를 상속하며, 비즈니스 필드만 포함하고 동작 메서드는 포함하지 않습니다. 예를 들어 `LoginState`의 작성 방식:
   ```csharp
   namespace GameFrameX.Apps.Account.Login.Entity;

   public class LoginState : CacheState
   {
       public string NickName { get; set; }
       public string UserName { get; set; }
       public uint Level { get; set; }
       // ... 기타 비즈니스 필드
   }
   ```
   출처: [LoginState.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Entity/LoginState.cs#L30-L72)

3. **컴포넌트 클래스 생성(Component) 및 상태와 Actor 타입 바인딩**.
   `StateComponent<TState>`를 상속하고, `[ComponentType]` 특성으로 소속 Actor를 선언합니다. 예를 들어 `LoginComponent`는 `ActorTypeServer`에 바인딩됩니다:
   ```csharp
   using GameFrameX.Apps.Account.Login.Entity;

   namespace GameFrameX.Apps.Account.Login.Component;

   [ComponentType(GlobalConst.ActorTypeServer)]
   public sealed class LoginComponent : StateComponent<LoginState>
   {
       protected override bool IsCreateDefaultState { get; set; } = false;

       public async Task<PlayerState> OnPlayerLogin(ReqPlayerLogin reqLogin)
       {
           MetricsPlayerHelper.LoginCounterOptions.Inc();
           return await GameDb.FindAsync<PlayerState>(m => m.Id == reqLogin.Id, false);
       }
   }
   ```
   출처: [LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L30-L46)

4. **네임스페이스와 디렉터리 일치 유지**.
   컴포넌트 네임스페이스는 `GameFrameX.Apps.{도메인}.{모듈}.Component`, 상태 네임스페이스는 `GameFrameX.Apps.{도메인}.{모듈}.Entity`로 하여 `global using`과 정렬합니다([GlobalUsings.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/GlobalUsings.cs) 참조).

5. **`GameFrameX.Hotfix`에서 새 컴포넌트 호출**.
   Hotfix 계층은 `Component` 프레임워크 인터페이스를 통해 새 모듈에 접근합니다. 예를 들어 `LoginComponent.OnPlayerLogin`은 Hotfix의 로그인 메시지 처리 진입점에서 호출됩니다. `AppsHandler.cs`에 별도로 등록할 필요가 없습니다(현재 `AppsHandler`는 빈 클래스입니다. [AppsHandler.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/AppsHandler.cs#L31-L34) 참조).

6. **컴파일 및 검증**.
   저장소 루트 디렉터리에서 다음을 실행합니다:
   ```bash
   dotnet build GameFrameX.Apps/GameFrameX.Apps.csproj
   ```
   컴파일이 성공하면 새 모듈이 성공적으로 연동된 것입니다.

## 일반적인 변형

- **다른 Actor 타입에 바인딩**: `[ComponentType(GlobalConst.ActorTypeServer)]`의 상수를 비즈니스에 필요한 Actor로 교체하면 됩니다([LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L36) 참조).
- **기본 상태 생성 여부**: Actor가 생성될 때 기본 `State`를 자동으로 초기화하려면 `IsCreateDefaultState`를 `true`로 설정하고, 처음으로 저장될 때만 생성되기를 원한다면 `false`를 유지합니다([LoginComponent.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Apps/Account/Login/Component/LoginComponent.cs#L39) 참조).

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| `dotnet build` 시 `CacheState` / `StateComponent<T>` / `GlobalConst`를 찾을 수 없다는 오류 발생 | 해당 `global using`이 선언되지 않았거나 프로젝트 참조가 누락됨 | `GameFrameX.Hotfix.csproj`가 `GameFrameX.Apps.csproj`를 참조하고 있는지 확인([GameFrameX.Hotfix.csproj#L18](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.Hotfix/GameFrameX.Hotfix.csproj#L18) 참조) |
| Hotfix에서 컴포넌트 메서드를 찾을 수 없음 | 네임스페이스가 디렉터리와 일치하지 않거나 클래스에 `public`이 지정되지 않음 | `GameFrameX.Apps.{도메인}.{모듈}.Component` 형식으로 네이밍하고 클래스를 `public sealed`로 선언 |
| `ComponentType` 특성에서 오류 발생 | 잘못된 Actor 상수 사용 | `GlobalConst.ActorTypeServer` 등 이미 정의된 상수로 변경 |
