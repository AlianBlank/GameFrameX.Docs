# 채널이 항상 default를 반환할 때 어떻게 해야 하나요

`BlankGetChannel.GetChannelName()`가 대상 플랫폼에서 채널 설정을 읽어오지 못하면, 파라미터 `defaultValue`의 기본값인 `"default"`를 반환합니다. 이 현상은 거의 대부분 다음 원인에서 비롯됩니다: 현재 플랫폼의 설정 소스에 `channel` 키가 없거나, 키 이름이 일치하지 않거나, 또는 최초 조회 결과가 정적 캐시에 저장되어 있는 경우입니다. API 시그니처는 다음과 같습니다:

```csharp
public static string GetChannelName(string channelKey = "channel", string defaultValue = "default")
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L97-L98)

## 빠른 진단

| 증상 | 원인 | 해결 방법 |
|------|------|------|
| Editor / PC / WebGL / 콘솔에서 `default` 반환 | `Assets/Resources/application_config.txt`가 존재하지 않거나 `channel=` 행이 없음 | `Assets/Resources/` 아래에 `application_config.txt`를 생성하고 `channel=xxx`를 기록 |
| `application_config.txt`를 새로 만들거나 수정했는데도 여전히 `default` 반환 | 정적 캐시 `ChannelCache`에 이미 `default`가 캐시되어 이 세션에서는 다시 읽지 않음 | Play 모드를 종료하여 Domain Reload를 트리거하거나, Unity를 재시작한 후 다시 테스트 |
| Android 실기기에서 `default` 반환 | `<meta-data android:name="channel" .../>`가 메인 실행 Activity 안에 작성되지 않았거나 키 이름이 `channel`이 아님 | `meta-data`를 AndroidManifest.xml의 메인 실행 `<activity>` 태그 내부로 이동 |
| iOS 실기기에서 `default` 반환 | 빌드 후 처리 스크립트가 Info.plist에 `channel` 키가 없을 때 자동으로 `"default"`를 기록함 | 빌드 전 또는 더 높은 우선순위의 후처리에서 미리 `channel` 키를 기록 |
| iOS에서 `default`가 아닌 `unknown` 반환 | Info.plist에 해당 키가 없어 iOS 네이티브 구현이 `"unknown"`을 반환함 | Info.plist에 `channel` 키를 추가 |
| `sub_channel` 등 커스텀 키를 조회했을 때 `default` 반환 | 전달한 `channelKey`와 설정 파일의 키 이름이 일치하지 않음 | 키 이름을 확인한 후 올바른 키로 설정에 기록 |

## 해결 단계

### 1. Editor / PC / WebGL: application_config.txt 확인

이 플랫폼들은 `Resources.Load<TextAsset>("application_config")`로 읽으며, 파일은 반드시 `Assets/Resources/application_config.txt`에 위치해야 하고, 한 줄에 하나의 `키=값` 형식입니다:

```text
channel=editor_cn_test
sub_channel=test
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L106-L121)

파싱 규칙에 유의하세요(소스 코드 `L110-L119` 기준):

- `\n` / `\r` / `\r\n` 으로 줄을 구분하며, 빈 줄은 무시됩니다;
- 각 줄은 `=`로 분할되며 **반드시 1개보다 많은 세그먼트가 있어야 합니다**. `channel`(`=` 없음)과 같은 형태의 줄은 통째로 버려집니다;
- 키와 값 양 끝의 공백은 `Trim()`으로 제거되므로, `channel = abc`로 작성해도 `abc`를 읽을 수 있습니다.

### 2. 정적 캐시 간섭 배제

결과는 정적 딕셔너리 `ChannelCache`에 기록되며, 같은 세션 내 두 번째 호출은 곧바로 캐시를 사용합니다. 특히 주의할 점: `textAsset == null`(파일이 존재하지 않음)일 때 `default`가 캐시에 기록되어, 이후 파일을 추가해도 다시 읽지 않습니다:

```csharp
if (ChannelCache.TryGetValue(channelKey, out var value))
{
    return value;
}
// ...
var textAsset = Resources.Load<TextAsset>("application_config");
if (textAsset != null)
{
    // 파싱하여 ChannelCache를 채움
}
else
{
    ChannelCache[channelKey] = defaultValue;  // 파일을 찾지 못하면 default를 캐시함
}
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L100-L125)

Editor에서 설정이 적용되었는지 확인하기 전에, 먼저 Play 모드를 종료(Domain Reload 트리거)하거나 Unity를 재시작한 뒤 Play 모드로 들어가 테스트하세요. Android / iOS 측도 마찬가지입니다: 매니페스트나 plist 수정 후에는 다시 빌드해야 하며, 프로세스 내에서 자동으로 갱신되지 않습니다.

### 3. Android: meta-data를 메인 실행 Activity 안에 넣기

Android는 JNI를 통해 `com.alianhome.getchannel.MainActivity`의 정적 메서드 `GetChannel`을 호출하여 읽으며, 키 이름은 기본적으로 `channel`입니다:

```csharp
using (AndroidJavaClass androidJavaClass = new AndroidJavaClass("com.alianhome.getchannel.MainActivity"))
{
    channelName = androidJavaClass.CallStatic<string>("GetChannel", channelKey);
}
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L131-L135)

`AndroidManifest.xml`의 **메인 실행 Activity 태그 내부**(`<application>` 아래가 아님)에 추가합니다:

```xml
<meta-data android:name="channel" android:value="android_cn_taptap" />
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L15-L19)

확인 사항:

- 키 이름은 반드시 `android:name="channel"`이어야 하며, C# 측에서 전달하는 `channelKey`와 일치해야 합니다. 다른 키를 가져오려면 호출 시 `GetChannelName("원하는 키 이름")`을 전달하세요.
- 커스텀 매니페스트 방식(커스텀 `Assets/Plugins/Android/AndroidManifest.xml`)은 Unity가 현재 사용하는 템플릿과 일치해야 하며, APK에 포함된 후에도 여전히 메인 Activity 안에 있는지 확인하세요.

### 4. iOS / tvOS / visionOS: Info.plist 확인

iOS 측은 `DllImport("__Internal")`을 통해 네이티브 `getChannelName`을 호출하여 Info.plist에서 `channel` 키를 읽습니다:

```csharp
[DllImport("__Internal")]
private static extern string getChannelName(string channelKey);
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L47-L48)

네이티브 구현은 키를 찾지 못하면 `"unknown"`을 반환합니다(C# 측의 `default`가 아님):

```objc
NSString * channel_value =  [dict objectForKey:channel_name_String];
if (channel_value != nil) {
    return StringToCharArray(channel_value);
}
channel_value = @"unknown";
return StringToCharArray(channel_value);
```

출처: [BlankGetChannel.mm](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Plugins/iOS/BlankGetChannel/BlankGetChannel.mm#L25-L36)

패키지 내 `channel` 키는 `PostProcessBuild(99)` 빌드 후 처리에서 자동으로 기록됩니다. **해당 키가 존재하지 않을 때만** 기록하며, 기록되는 값은 `"default"`로 고정되어 있어, 이 패키지의 기본 흐름으로 빌드한 iOS 빌드 결과물은 `default`를 얻게 됩니다. 이는 의도된 설계입니다:

```csharp
const string channelKey = "channel";
const string channelValue = "default";

string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

출처: [PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L31-L49)

실제 채널을 얻으려면 둘 중 하나를 선택하세요:

1. `callbackOrder`가 `99`보다 작은 `PostProcessBuild` 핸들러를 작성하여 먼저 Info.plist에 실제 채널을 기록합니다. 그러면 이 패키지는 키가 이미 존재함을 감지하고 건너뜁니다(로그 출력 `已有渠道,跳过设置=>`);
2. 또는 빌드 산출물에서 Info.plist를 직접 수정한 후 다시 서명합니다.

Info.plist에서는 String 타입이어야 합니다:

```xml
<key>channel</key>
<string>ios_cn_xxx</string>
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)

## 검증

1. 위 단계에 따라 설정을 모두 완료한 후 앱을 다시 시작합니다(또는 Unity를 재시작하고 Play 모드로 진입);
2. 시작 초기(채널 조회 전)에 호출하여 출력합니다:

```csharp
string channel = BlankGetChannel.GetChannelName();
Debug.Log("channel = " + channel);
```

출처: [BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L87-L96)

3. Android에서는 `adb logcat | grep channel`로 출력을 확인하고, iOS에서는 Xcode 콘솔에서 확인합니다. iOS 빌드 시 후처리가 적용되면 빌드 로그에 `配置渠道成功=>` 또는 `已有渠道,跳过设置=>` 문구가 나타납니다;
4. 출력이 설정에 기록한 값이면 수정이 완료된 것입니다. 여전히 `default`라면 "빠른 진단" 표로 돌아가 플랫폼별로 설정 소스와 캐시를 하나씩 재확인하세요.
