# 如何使用 Docker Compose 启动多进程环境

按照本页步骤执行后,你将在本机用一条 `docker compose` 命令同时启动 1 个 MongoDB、2 个 Social 进程和 10 个 Game 进程,并通过容器网络互联、可直接对外提供端口。

## 前置条件

- 已安装 Docker Engine 与 Docker Compose v2(终端执行 `docker compose version` 应能输出版本)。
- 当前终端在仓库根目录(包含 `docker-compose.multi.yml` 的目录)。
- 主机端口 `47017`、`48080–48089`、`49100–49109`、`49400–49401` 未被其他进程占用。

## 操作步骤

1. **确认多进程编排文件存在**。仓库根目录已经准备好 `docker-compose.multi.yml`,里面声明了 `mongo`、`social-1`、`social-2` 与 `game-1` … `game-10` 共 13 个服务。

   ```yaml
   name: gfx-multi
   ```
   Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L1-L3)

2. **了解服务发现如何注入**。多进程之间通过环境变量互通地址,`x-launcher-discovery-env` 用 YAML anchor 把全部节点的 `tcp://host:port` 一次性注入到每个容器:

   ```yaml
   x-launcher-discovery-env: &launcher-discovery-env
     services__Social_2001__tcp__0: "tcp://social-1:29400"
     services__Social_2002__tcp__0: "tcp://social-2:29401"
     services__Game_1001__tcp__0: "tcp://game-1:29100"
     ...
     services__Game_1010__tcp__0: "tcp://game-10:29109"
   ```
   每个服务用 `environment: <<: *launcher-discovery-env` 复用同一份映射,无需在每个服务里重复写。
   Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L3-L17)

3. **构建共享镜像**。`docker-compose.multi.yml` 引用镜像 `gameframex/server.launcher:local`,首次启动前需要构建:`social-1` 节点使用本地 `build` 上下文,其余节点复用该镜像:

   ```yaml
   social-1:
     build:
       context: .
     image: gameframex/server.launcher:local
   ```
   Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L35-L38)

4. **启动全部进程**。在仓库根目录执行:

   ```bash
   docker compose -f docker-compose.multi.yml up -d
   ```

5. **查看启动顺序与依赖**。所有 `game-*` 通过 `depends_on` 等待 `mongo` 健康(`service_healthy`)以及 `social-1` / `social-2` 启动完成(`service_started`)后再启动,因此日志会按 `mongo → social → game` 的顺序出现。

   ```yaml
   game-1:
     depends_on:
       mongo:
         condition: service_healthy
       social-1:
         condition: service_started
       social-2:
         condition: service_started
   ```
   Source: [docker-compose.multi.yml](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/docker-compose.multi.yml#L93-L101)

6. **验证服务在线**。Mongo 健康检查用 `db.runCommand({ ping: 1 }).ok`,可直接用 docker 命令验证:

   ```bash
   docker compose -f docker-compose.multi.yml ps
   docker compose -f docker-compose.multi.yml logs -f game-1
   ```

7. **访问节点**。`social-1` 暴露主机端口 `49400`(TCP)与 `48081`(HTTP),`game-1` 暴露 `49100` 与 `48080`,`game-10` 暴露 `49109` 与 `48089`,可直接连 `http://localhost:48080` 等地址调试。

## 常见变体

- **只想跑最小 2 进程拓扑**。仓库另提供 `docker-compose.yml`(Mongo + 1 个 Social + 1 个 Game,使用 `gfx-game` / `gfx-social` 容器名、主机端口 `37017/38080/38081/39100/39400`),命令改为 `docker compose up -d`。
- **修改节点数量**。复制 `game-1` 段落,递增 `ServerId` / `ServerInstanceId` / 端口,并在 `x-launcher-discovery-env` 里同步追加一行 `services__Game_<id>__tcp__0`。
- **挂载自定义配置**。多进程编排已经为每个节点挂载 `./GameFrameX.Config/json` 到容器内 `/app/Configs`(只读),改完本地 JSON 重启对应容器即可生效。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `bind: address already in use` | 主机端口被占用 | 改 `docker-compose.multi.yml` 里 `ports` 的左侧端口,或在主机上释放被占用的端口 |
| `game-*` 反复重启,日志显示连不上 social | 忘了等 Mongo 健康就 `up` | 确认依赖里 `mongo: condition: service_healthy`,不要改成 `service_started` |
| `services__Game_xxxx` 改完没生效 | 没有同步给所有节点 | 通过 `environment: <<: *launcher-discovery-env` 复用锚点,不要在单个节点里覆盖成不同名字 |
| `permission denied` 写日志 | `running-multi/...` 目录归属 `root` | 删除对应挂载目录后重建,容器以 `APP_UID` 写入 `/app/data/logs` |

## 验证

```bash
docker compose -f docker-compose.multi.yml ps        # 全部 State 为 running/healthy
docker compose -f docker-compose.multi.yml logs mongo # 看到 waiting for connections
curl -s http://localhost:48080/                       # game-1 HTTP 端口能响应
```

容器退出码非 0 的服务用 `docker compose -f docker-compose.multi.yml logs --tail=200 <service>` 查根因。

## 背景(可选)

`docker-compose.multi.yml` 用镜像 `gameframex/server.launcher:local`,该镜像由根目录 `Dockerfile` 编译 `GameFrameX.Launcher` 与 `GameFrameX.Hotfix` 两个项目生成,并把 Hotfix DLL 同时落到 `/app/hotfix/` 与 `/app/` 根目录,以兼容默认从 `/app` 根目录加载引用程序集的热更逻辑。
