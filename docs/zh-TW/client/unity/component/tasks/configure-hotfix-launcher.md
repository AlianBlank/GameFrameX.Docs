# 如何接入熱更新進入點（HotfixLauncher）

完成本頁設定後，框架啟動時會自動載入 AOT DLL 與 Hotfix DLL，並透過反射呼叫你指定的進入點方法，把熱更組件拉起來。

## 前置條件

- 已建立熱更組件 `Unity.Hotfix`（預設 Assembly Definition）。
- 已存在一個靜態進入點類別與無參數靜態方法（如 `Hotfix.HotfixLauncher.Main`）。
- 已在 `Assets/Resources/StartupOptions.asset` 看到以下三項設定（框架預設已寫好）：
  - `HotfixAssemblyName: Unity.Hotfix`
  - `HotfixEntryTypeName: Hotfix.HotfixLauncher`
  - `HotfixEntryMethodName: Main`

## 操作步驟

1. **建立進入點類別**。在 `Assets/Hotfix/` 目錄下新增 `HotfixLauncher.cs`，使用預設命名空間 `Hotfix`，並提供一個靜態 `Main()` 方法作為熱更進入點。

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX;
   using GameFrameX.UI.Runtime;
   using Hotfix.Config;
   using Hotfix.Config.Local;
   using Hotfix.Config.Tables;
   using Hotfix.UI;

   namespace Hotfix
   {
       public static class HotfixLauncher
       {
           public static void Main()
           {
               Log.Info("Hello World HybridCLR");
               LoadConfig();
               LoadUI();
           }
       }
   }
   ```

   Source: [HotfixLauncher.cs#L26-L34](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L26-L34)

2. **在進入點中載入設定與 UI**。框架只會呼叫你的進入點方法，後續的資源、設定、UI 初始化都由此方法驅動。範本專案使用 `TablesComponent` 載入 JSON/二進位設定表，並以 `await` 方式開啟登入 UI。

   ```csharp
   private static async void LoadUI()
   {
       await GameApp.UI.OpenAsync<UILogin>();
   }

   static async void LoadConfig()
   {
       _tablesComponent = new TablesComponent();
       _tablesComponent.Init(GameApp.Config);
       await _tablesComponent.LoadAsync(ConfigLoader);
       TranslateText();
   }

   static TablesComponent _tablesComponent;
   ```

   Source: [HotfixLauncher.cs#L36-L61](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L61)

3. **確認 `StartupOptions.asset` 三項鍵值與你的進入點相符**。框架啟動器 `HotfixHelper.StartHotfixInternalAsync` 會讀取這三個欄位去反射呼叫方法，預設值見下表；若你改了命名空間或類別名稱，必須同步修改這裡。

   | 鍵 | 預設值 | 作用 |
   |---|---|---|
   | `HotfixAssemblyName` | `Unity.Hotfix` | 待載入的 DLL 名稱（不含 `.dll`） |
   | `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` | 進入點類別的完整類型名稱（命名空間 + 類別名稱） |
   | `HotfixEntryMethodName` | `Main` | 進入點方法名稱，需為 `public static` 無參數方法 |

   Source: [HotfixHelper.cs#L62-L70](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70)、[StartupOptions.asset#L24-L26](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Resources/StartupOptions.asset#L24-L26)

4. **確保啟動流程已掛上 `ApplicationHotfixLauncher`**。框架進入點 `ApplicationStartupEntry` 透過它把啟動 UI 處理器與熱更啟動器接入 `StartupRunner.Run`，無需改動，只要確保參考存在即可。

   ```csharp
   var result = await StartupRunner.Run(startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   Source: [ApplicationStartupEntry.cs#L43](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L43)、[ApplicationHotfixLauncher.cs#L12](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs#L12)

## 常見變體

- **二進位設定表**：在 `HotfixLauncher.LoadConfig` 中把 `LoadAsync(ConfigLoader)` 換成 `LoadAsync(ConfigBufferLoader)`，並在編譯選項中開啟 `ENABLE_BINARY_CONFIG`（範本已使用 `#if ENABLE_BINARY_CONFIG` 條件編譯）。
- **關閉 HybridCLR**（原生 IL2CPP 路徑）：當 `ENABLE_GAME_FRAME_X_HYBRID_CLR` 或 `DISABLE_HYBRIDCLR` 生效時，`HotfixHelper.StartHotfixInternalAsync` 會走 `RunNative` 分支，直接用 `Utility.Assembly.GetType` 反射呼叫進入點，不需要 AOT DLL 載入流程。
- **自訂進入點類別名稱**：例如把 `HotfixLauncher` 改成 `MyGame.EntryBoot`，同步把 `StartupOptions.asset` 的 `HotfixEntryTypeName` 改為 `MyGame.EntryBoot`、`HotfixEntryMethodName` 改為 `Boot`。

## 常見錯誤

- **進入點類別/方法簽章不正確**：必須是 `public static`，且無參數；否則 `entryType.GetMethod(entryMethodName)` 會回傳 `null`，日誌出現 `EntryType=>method ` 後面為空。
- **命名空間或類別名稱拼錯**：`HotfixEntryTypeName` 必須使用 `命名空間.類別名稱` 的完整形式，且與 DLL 內的真實命名空間一致，否則 `Run` 中 `entryType.FullName` 會擲出 `NullReferenceException`。
- **修改了進入點但未重新啟動 `StartupOptions.asset`**：變更在執行階段不會生效，需要在 Editor 重新選擇該 ScriptableObject 或重新啟動 Player。
- **`#if ENABLE_UI_FAIRYGUI` 分支誤刪**：範本中 FairyGUI 套件的載入包裹在條件編譯裡，如果你使用 FairyGUI 但沒有定義該巨集，會導致 `LoadUI` 載入 UI 套件失敗。

## 背景（選用）

`HotfixHelper.StartHotfixInternalAsync` 在編輯器內直接遍歷已載入組件找到 DLL，打包輸出後則按 `AOTGenericReferences.PatchedAOTAssemblyList` 順序載入 AOT 中繼資料，再用 `Assembly.Load` 載入 Hotfix DLL，最後透過反射呼叫進入點方法。`ApplicationHotfixLauncher` 只是把 `HotfixHelper` 轉接成 `IHotfixLauncher` 介面，以便在 `StartupRunner` 中重複使用同一套啟動流程。
