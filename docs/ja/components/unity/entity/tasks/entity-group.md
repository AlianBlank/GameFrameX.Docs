# エンティティグループの設定と使用方法

エンティティグループ(Entity Group)は、エンティティインスタンスのコンテナであり、オブジェクトプールの単位です。各エンティティは表示時に必ず既存のエンティティグループに所属している必要があり、エンティティグループがそのマウント先の親ノード、オブジェクトプールの容量、回収ポリシーを決定します。このページのタスクを完了すると、Inspector でグループを宣言したり、実行時に動的にグループを追加したり、グループ単位でエンティティを照会・管理できるようになります。

## 前提条件

- シーンに `EntityComponent`(`GameFrameX.Entity.Runtime` 名前空間)がアタッチされており、`BaseComponent` と `EventComponent` の準備ができていること —— そうでない場合、起動時に `Base component is invalid.` / `Event component is invalid.` が出力されます。
- `EntityComponent.Start` が `Entity Instances` ルートノードとエンティティヘルパーを自動的に作成するため、手動で階層を構築する必要はありません。

## 操作手順

### 1. Inspector でエンティティグループを宣言する(推奨)

`EntityComponent` の `m_EntityGroups` はシリアライズ可能な配列で、各要素には 5 つのフィールドが含まれます。デフォルト値は以下の通りです:

| Inspector フィールド | 型 | デフォルト値 | 意味 |
|------|------|--------|------|
| `m_Name` | string | `null` | エンティティグループ名。実行時の一意なキーであり、空にすることはできません |
| `m_InstanceAutoReleaseInterval` | float | `60f` | インスタンスオブジェクトプールが解放可能なオブジェクトを自動解放する間隔(秒) |
| `m_InstanceCapacity` | int | `16` | インスタンスオブジェクトプールの容量 |
| `m_InstanceExpireTime` | float | `60f` | インスタンスオブジェクトプールのオブジェクト有効期限(秒) |
| `m_InstancePriority` | int | `0` | インスタンスオブジェクトプールの優先度 |

```csharp
[Serializable]
private sealed class EntityGroup
{
    [SerializeField] private string m_Name = null;

    [SerializeField] private float m_InstanceAutoReleaseInterval = 60f;

    [SerializeField] private int m_InstanceCapacity = 16;

    [SerializeField] private float m_InstanceExpireTime = 60f;

    [SerializeField] private int m_InstancePriority = 0;
```
> Source: [EntityComponent.EntityGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.EntityGroup.cs#L40-L51)

Inspector でグループを 1 つずつ(例:`Player`、`Monster`、`Effect`)入力すると、`Start` フェーズで自動的に走査して登録されます。登録に失敗した場合は、警告 `Add entity group '{0}' failure.` を出力して次の項目の処理を続けるだけで、起動は中断されません。

```csharp
for (int i = 0; i < m_EntityGroups.Length; i++)
{
    var entityGroup = m_EntityGroups[i];
    if (entityGroup == null)
    {
        continue;
    }

    if (!AddEntityGroup(entityGroup.Name, entityGroup.InstanceAutoReleaseInterval, entityGroup.InstanceCapacity, entityGroup.InstanceExpireTime, entityGroup.InstancePriority))
    {
        Log.Warning("Add entity group '{0}' failure.", entityGroup.Name);
        continue;
    }
}
```
> Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L192-L205)

### 2. 実行時にエンティティグループを動的に追加する

コード内で必要に応じてグループを作成したい場合は、`EntityComponent.AddEntityGroup` を呼び出します。2 つのオーバーロードのうち、簡易版では名前と自動解放間隔のみを指定し、残りのパラメータにはコンポーネントの `DefaultCapacity`(デフォルト `512`)、`DefaultExpireTime`(デフォルト `3600f`)、`DefaultPriority` が使用されます。

```csharp
var entityComponent = GameEntry.GetComponent<EntityComponent>();

// 簡易版:容量/有効期限/優先度にはコンポーネントのデフォルト値を使用
entityComponent.AddEntityGroup("Monster", 60f);

// 完全版:オブジェクトプールのパラメータを明示的に指定
entityComponent.AddEntityGroup("Effect", 30f, 64, 30f, 10);
```
> Sources: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L252-L287), [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L72-L74)

`AddEntityGroup` の動作のポイント(実装から):

1. 同名のグループが既に存在する場合、そのまま `false` を返します(冪等であり、同じグループが重複して作成されることはありません)。
2. `m_EntityGroupHelperTypeName`(デフォルト `GameFrameX.Entity.Runtime.DefaultEntityGroupHelper`)または `m_CustomEntityGroupHelper` を使ってグループヘルパーを作成します。作成に失敗した場合は `Can not create entity group helper.` を出力して `false` を返します。
3. ヘルパーの GameObject は `Entity Group - {グループ名}` と命名され、`m_InstanceRoot` の下にアタッチされ、`localScale` は `Vector3.one` に設定されます。
4. 最後に `IEntityManager.AddEntityGroup(...)` に委譲して登録を完了します。

```csharp
if (m_EntityManager.HasEntityGroup(entityGroupName))
{
    return false;
}

EntityGroupHelperBase entityGroupHelper = Helper.CreateHelper(m_EntityGroupHelperTypeName, m_CustomEntityGroupHelper, EntityGroupCount);
if (entityGroupHelper == null)
{
    Log.Error("Can not create entity group helper.");
    return false;
}

entityGroupHelper.name = Utility.Text.Format("Entity Group - {0}", entityGroupName);
Transform transform = entityGroupHelper.transform;
transform.SetParent(m_InstanceRoot);
transform.localScale = Vector3.one;

return m_EntityManager.AddEntityGroup(entityGroupName, instanceAutoReleaseInterval, instanceCapacity, instanceExpireTime, instancePriority, entityGroupHelper);
```
> Source: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L269-L286)

### 3. グループを照会してグループ内のエンティティを管理する

```csharp
// グループ作成前に判定し、戻り値のセマンティクスへの依存を避ける
if (!entityComponent.HasEntityGroup("Monster"))
{
    entityComponent.AddEntityGroup("Monster", 60f);
}

IEntityGroup group = entityComponent.GetEntityGroup("Monster");
int count = group.EntityCount;              // グループ内のエンティティ数
group.InstanceCapacity = 32;                // 実行時にプール容量を調整
group.InstanceAutoReleaseInterval = 30f;    // 自動解放間隔を調整

// リソース名/ID でエンティティを取得
IEntity one = group.GetEntity("Assets/Res/Monster/Slime.prefab");
IEntity[] all = group.GetAllEntities();
```
> Sources: [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L213-L235), [IEntityGroup.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/IEntityGroup.cs#L39-L167)

| メンバー | シグネチャ | 説明 |
|------|------|------|
| `Name` | `string { get; }` | エンティティグループ名 |
| `EntityCount` | `int { get; }` | グループ内のエンティティ数 |
| `InstanceAutoReleaseInterval` | `float { get; set; }` | 自動解放間隔(秒) |
| `InstanceCapacity` | `int { get; set; }` | インスタンスプールの容量 |

## よくあるバリエーション

### カスタムグループヘルパー(エンティティのマウント/グループ動作を変更)

グループヘルパーはエンティティインスタンスの親ノードを決定します。デフォルトのエンティティヘルパーはエンティティの作成時に `transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform)` を実行するため、同じグループのエンティティはすべてそのグループの `Entity Group - {名称}` ノードの下にマウントされます。

```csharp
public override IEntity CreateEntity(object entityInstance, IEntityGroup entityGroup, object userData)
{
    ...
    Transform transform = gameObject.transform;
    transform.SetParent(((MonoBehaviour)entityGroup.Helper).transform);
```
> Source: [DefaultEntityHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/DefaultEntityHelper.cs#L69-L79)

### グローバルなデフォルトのオブジェクトプールパラメータ

グループごとに容量/有効期限を入力したくない場合は、簡易版の `AddEntityGroup(name, interval)` だけを使用し、コード内でデフォルト値を一括して変更します:

```csharp
entityComponent.DefaultCapacity = 256;      // デフォルト 512
entityComponent.DefaultExpireTime = 1800f;  // デフォルト 3600f
```

## よくあるエラー

| 現象 | 原因 | 対処 |
|------|------|------|
| `GameFrameworkException("Entity group name is invalid.")` がスローされる | 渡された `entityGroupName` が空または空白である。`AddEntityGroup` / `GetEntityGroup` / `HasEntityGroup` のいずれでも検証される | Inspector で各グループの `m_Name` が入力済みであること、またコードで空でない文字列を渡すことを確認する |
| コンソールに `Add entity group '{0}' failure.` が表示される | 同名のグループが既に存在する、またはグループヘルパーの作成に失敗した | まず `HasEntityGroup` で重複を判定する。`m_EntityGroupHelperTypeName` がロード可能な型の完全名かどうかを確認する |
| コンソールに `Can not create entity group helper.` が表示される | ヘルパーの型名のスペルミス、型がストリッピングされている、または `m_CustomEntityGroupHelper` が未設定 | デフォルト値 `GameFrameX.Entity.Runtime.DefaultEntityGroupHelper` を使用するか、カスタムヘルパーを直接 `m_CustomEntityGroupHelper` に設定する |
| エンティティ表示時にグループが存在しないと報告される | グループは `EntityComponent.Start` で登録されるため、早すぎるタイミング(他のコンポーネントの `Awake` など)でエンティティ表示を呼び出すとグループを取得できない | グループ作成/エンティティ表示の呼び出しを `Start` より後のフローに移動するか、表示前に自分で `AddEntityGroup` を呼び出す |
| エンティティが誤った親ノードにマウントされる/階層が乱れる | カスタムエンティティヘルパーがグループヘルパーに基づいて親ノードを設定していない | `DefaultEntityHelper.CreateEntity` を参考に、`entityGroup.Helper` の transform を親ノードとして使用する |

> Sources: [EntityManager.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.cs#L253-L257), [EntityManager.Get.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/Entity/EntityManager.Get.cs#L57-L73), [EntityComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.entity/blob/main/Runtime/Entity/EntityComponent.cs#L200-L204)

## 背景(任意)

グループはエンティティオブジェクトプールの分割単位です。`EntityManager` はグループごとに独立したインスタンスプールを作成し、容量、有効期限、優先度、自動解放間隔はすべてグループ単位で適用されます。そのため、ライフサイクルの特徴が近いエンティティ(エフェクト vs キャラクター)を異なるグループに入れることで、無駄なロードと回収を大幅に削減できます。
