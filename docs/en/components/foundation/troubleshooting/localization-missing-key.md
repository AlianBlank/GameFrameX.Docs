# What to Do About Missing Localization Keys and Format Errors

When `LocalizationService.GetString` / `GetString(key, args)` returns the key name itself (e.g., `"Some.Unknown.Key"`), or the returned string still contains unreplaced placeholders such as `"{0}"`, `{n:xxxxx}`, it means the localization "missing key" or "format error" branch has been triggered. This page explains how to quickly locate the cause and fix it.

## Quick Diagnosis

| Symptom | Cause | Fix |
|------|------|------|
| `GetString("X.Y")` returns exactly `"X.Y"` | The resource key does not exist (not registered, not loaded with the assembly, or the key name is misspelled) | Use `EnsureLoaded()` to force loading, and subscribe to the `MissingKey` event to verify key names; see [Missing Keys](#fix-1-missing-keys) |
| Unreplaced `{0}`, `{1}`, `{name}` appear in the template | Placeholder indexes/names do not match `args`, and `string.Format` throws `FormatException` | Check the number and types of template placeholders; switch `FormatErrorBehavior`; see [Format Errors](#fix-2-format-errors) |
| A `FormatException: Input string was not in a correct format` is thrown | `FormatErrorBehavior` is set to `Throw` | Temporarily switch back to `ReturnTemplate` to locate the problem, or fix the template and arguments; see [Format Errors](#fix-2-format-errors) |
| The returned string does not match the current `CultureInfo` (always English / always one specific language) | No resources are registered for that `CultureInfo`, or the lookup fell back to the default culture | See [Culture Fallback](#fix-3-culture-and-fallback-behavior) |

For the meaning of the three `FormatErrorBehavior` values, see [`LocalizationFormatErrorBehavior`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/LocalizationFormatErrorBehavior.cs#L6-L22); the default value is `ReturnTemplate`.

## Fix Steps

### Fix 1: Missing Keys

1. Confirm the key name is spelled correctly (including casing and dots). Key names are matched strictly as strings; `"Utility.Exceptions.TimestampOutOfRange"` and `"utility.exceptions.timestampoutofrange"` are treated as different keys.
2. Call [`LocalizationService.EnsureLoaded()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L207-L210) to force all providers to load, so lazy-loading delays do not mask the problem.
3. Subscribe to the [`MissingKey`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L79-L89) event to log the keys that are actually missing:

   ```csharp
   LocalizationService.MissingKey += (sender, args) =>
   {
       // args.Key / args.Culture give the specific missing key and culture
       Console.WriteLine($"Missing localization key: {args.Key} ({args.Culture})");
   };
   ```

4. If the key name is still returned, check whether the assembly's resources are published along with the main assembly (whether `*.resources.dll` is copied to the output directory), and confirm that custom resource providers have been registered via `LocalizationService.RegisterProvider(...)`.

### Fix 2: Format Errors

Formatting failures are handled inside [`ResourceManager.FormatString`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L234-L252), which catches `FormatException` and dispatches according to `FormatErrorBehavior`:

```csharp
public LocalizationFormatErrorBehavior FormatErrorBehavior { get; set; }
    = LocalizationFormatErrorBehavior.ReturnTemplate;
```

Troubleshoot in the following order:

1. **Check the number of placeholders**: The number of `{0}` / `{1}` placeholders in the template must match the number of items in `args`; extra placeholders will throw `FormatException` directly.
2. **Check the types**: When the template uses format specifiers such as `{0:d}` or `{0:N2}`, the corresponding item in `args` must be convertible to the numeric/date type the format requires. Passing a `string` to `{0:d}` will fail.
3. **Temporarily switch the behavior to make diagnosis easier**: Set `FormatErrorBehavior` to `Throw` to pinpoint the caller directly from the exception stack trace:

   ```csharp
   LocalizationService.Instance.FormatErrorBehavior
       = LocalizationFormatErrorBehavior.Throw;
   ```

   Meaning of the three values:

   | Value | Behavior |
   |------|------|
   | `ReturnTemplate` (default) | Returns the localized template without formatting (still containing `{0}` etc.) |
   | `ReturnKey` | Returns the resource key name |
   | `Throw` | Re-throws `FormatException`, making it easy to locate the issue in development environments |

4. After fixing, switch back to `ReturnTemplate` to avoid unhandled exceptions in production.

### Fix 3: Culture and Fallback Behavior

1. Control the lookup culture through `CultureInfo.CurrentUICulture`; to specify a culture explicitly, use [`LocalizationService.GetString(key, culture)`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L130-L138).
2. If a culture always returns English (or always returns the key), it means there are no resources for that culture and the system falls back to the default culture or the key name. Simply add the corresponding `.resx` entries in the resource files.
3. Call [`LocalizationService.GetStatistics()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L234-L237) to confirm the providers are loaded:

   ```csharp
   var stats = LocalizationService.GetStatistics();
   Console.WriteLine($"Providers loaded: {stats.ProvidersLoaded}");
   ```

## Verification

1. Re-trigger the original call path and confirm that the return value no longer equals the passed-in key name, and that unreplaced `{0}` / `{1}` placeholders no longer appear.
2. Temporarily set `FormatErrorBehavior` to `Throw` and run your tests/smoke tests once to confirm no `FormatException` is thrown.
3. Call `GetString(key)` once under each different `CultureInfo` and confirm the returned value matches the selected culture; if anything is missing, check the logs to see whether the `MissingKey` event was triggered.
