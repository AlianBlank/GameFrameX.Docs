# 構建失敗與熱更異常怎麼辦

本頁面針對使用 GameFrameX 的 `BuildProduct`（構建產品）和 `BuildHotfix`（構建熱更新）選單時常見的問題，按症狀對照排查，並給出與源碼一致的修復方式。

## 快速診斷

| 症狀（日誌原文） | 原因 | 修復 |
|------|------|------|
| `當前構建目標不是 Windows` | 選單要求當前 `BuildTarget` 與選單目標一致，但你切換到了其他平台 | 開啟 `File → Build Settings`，將平台切到對應目標後再觸發選單 |
| `當前構建目標不是 Mac Os` | 同上，針對 macOS 打包入口 | 切到 `StandaloneOSX` 後重試 |
| `當前構建目標不是 WebGL` | 同上，針對 WebGL 打包入口 | 切到 `WebGL` 後重試 |
| `當前構建目標不是 Android` | 同上，針對 Android 打包入口 | 切到 `Android` 後重試 |
| `輸出路徑異常,取消打包AAB` | 構建輸出目錄為空或不可寫 | 見下文修復步驟 4 |
| `未找到HybridCLR資料目錄:{path}` | 還沒跑過 HybridCLR 的生成流程，`HybridCLRData/AssembliesPostIl2CppStrip/<Target>` 不存在 | 先做一次 `HybridCLR → Generate` 再複製 AOT |
| `複製Hotfix DLL到Assets/Bundles/Code完成` 之後執行仍找不到熱更程式碼 | 沒有把 `Unity.HotFix.dll` 拷貝到 `Library/ScriptAssemblies` | 觸發 `GameFrameX → Build → Copy HotFix Code` |
| `Build Output Path:...` 但構建報紅 | 輸出目錄權限或磁碟空間不足 | 換一個可寫目錄並清理舊產物 |

## 修復步驟

### 1. 平台不匹配（"當前構建目標不是 XXX"）

`BuildProductHelper` 在每個平台入口都先校驗 `EditorUserBuildSettings.activeBuildTarget`，不匹配直接 `Debug.LogError` 後 `return`：

```csharp
[MenuItem("GameFrameX/Build/Windows X64", false, 100)]
public static void BuildPlayerToWindows64BuildTarget()
{
    Debug.Log(EditorUserBuildSettings.activeBuildTarget);
    if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)
    {
        Debug.LogError("當前構建目標不是 Windows");
        return;
    }
    ...
}
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L101-L110)

**操作：**

1. Unity 選單 `File → Build Settings…`
2. 切換到與入口對應的 `Target Platform`（Windows64 / macOS / WebGL / Android）
3. 點擊 `Switch Platform` 等待轉平台完成
4. 重新執行 `GameFrameX → Build → <對應平台>`

### 2. 複製 AOT 元資料失敗（"未找到HybridCLR資料目錄"）

`CopyAOTCode` 會從 `<Project>/HybridCLRData/AssembliesPostIl2CppStrip/<activeBuildTarget>` 拷貝 `*.dll` 到 `Assets/Bundles/AOTCode/`。若該目錄不存在會報錯並 return：

```csharp
DirectoryInfo aotCodeDir = new DirectoryInfo(path);
if (!aotCodeDir.Exists)
{
    Debug.LogError($"未找到HybridCLR資料目錄:{path}");
    return;
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L84-L92)

**操作：**

1. 在 Unity 中開啟 `HybridCLR → Generate`（或對應專案的 `HybridCLR/Generate` 流程）生成 Strip 後的 AOT DLL
2. 確認 `HybridCLRData/AssembliesPostIl2CppStrip/<Target>` 下出現 `*.dll`
3. 再執行 `GameFrameX → Build → Copy AOT Code`

### 3. 找不到 `Unity.HotFix.dll`

`BuildHotfixHelper.CopyHotfixCode()` 預設從 `Library/ScriptAssemblies/Unity.HotFix.dll` 拷貝到 `Assets/Bundles/Code/Unity.HotFix.dll.bytes`：

```csharp
private const string HotFixAssembliesDir = "Library/ScriptAssemblies";
private static readonly string[] HotfixDlls = new string[] { "Unity.HotFix.dll" };
private const string CodeDir = "Assets/Bundles/Code/";

foreach (var hotfix in HotfixDlls)
{
    var srcPath = Path.Combine(HotFixAssembliesDir, hotfix);
    if (!File.Exists(srcPath))
    {
        continue;
    }
    File.Copy(srcPath, Path.Combine(CodeDir, hotfix + Utility.Const.FileNameSuffix.Binary), true);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L21-L65)

如果 `Library/ScriptAssemblies` 下沒有該 DLL，程式碼會靜默 `continue`，最終 `Assets/Bundles/Code/` 為空。**操作：**

1. 確認工程中存在 `Unity.HotFix` 的 `asmdef`（熱更程式集），命名必須嚴格是 `Unity.HotFix.dll`
2. 切換到對應構建目標後讓 Unity 重新編譯，看到 `Library/ScriptAssemblies/Unity.HotFix.dll` 生成
3. 再執行 `GameFrameX → Build → Copy HotFix Code(複製熱更新程式碼到Assets>Bundles>Code)`
4. 在 `Assets/Bundles/Code/` 下確認 `Unity.HotFix.dll.bytes` 已生成

### 4. AAB 輸出路徑異常

Android AAB 入口在校驗輸出目錄時會列印：

```csharp
Debug.LogError("輸出路徑異常,取消打包AAB");
```

Source: [BuildProductHelper.cs](/Editor/BuildProduct/BuildProductHelper.cs#L421)

**操作：**

1. 在 `GameFrameX/Build` 選單觸發前，先設定好構建輸出目錄，確保路徑存在且當前使用者可寫
2. 清理上一次構建殘留（同名舊 AAB 佔用、唯讀檔案）
3. 重新觸發對應 Android AAB 入口

### 5. 想臨時關閉 HybridCLR

源碼提供了巨集開關 `DISABLE_HYBRIDCLR`，選單可一鍵切換：

```csharp
public const string HybridCLRScriptingDefineSymbol = "DISABLE_HYBRIDCLR";

[MenuItem("GameFrameX/Scripting Define Symbols/Disable HybridCLR(關閉HybridCLR適配)", false, 5000)]
public static void DisableHybridCLR()
{
    ScriptingDefineSymbols.AddScriptingDefineSymbol(HybridCLRScriptingDefineSymbol);
}
```

Source: [BuildHotfixHelper.cs](/Editor/BuildHotfix/BuildHotfixHelper.cs#L107-L116)

當熱更鏈路導致打包流程整體失敗、又必須先出一版產物時，可臨時走 `GameFrameX → Scripting Define Symbols → Disable HybridCLR`，跳過熱更相關步驟定位問題，之後再用 `Enable HybridCLR` 恢復。

## 驗證

構建/熱更問題修復後，按下面順序自檢：

1. `BuildProductHelper` 入口不再列印 `當前構建目標不是 XXX` 類的 LogError，並且構建報告 `BuildResult.Succeeded`
2. `Assets/Bundles/Code/Unity.HotFix.dll.bytes` 與 `Assets/Bundles/AOTCode/` 下存在本次目標的 AOT DLL
3. 執行構建產物，HybridCLR 熱更入口能正常載入熱更程式集
