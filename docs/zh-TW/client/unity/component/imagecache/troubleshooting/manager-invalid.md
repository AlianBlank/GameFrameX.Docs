# 發生 ImageCache manager is invalid 錯誤時的解決方法

若遊戲啟動日誌中顯示 `ImageCache manager is invalid.`，表示 `ImageCacheComponent.Awake()` 嘗試透過 `GameFrameworkEntry.GetModule<IImageCacheManager>()` 取得管理器實例時回傳了 `null`。這代表框架內不存在實作該介面的類別。之後元件會直接 `return`，所有圖片載入功能(`LoadImageAsync`、`IsCached`、`RemoveCache`、`ClearCache`)都將無法運作。

錯誤發生位置(`Awake` 進入點)：

```csharp
_imageCacheManager = GameFrameworkEntry.GetModule<IImageCacheManager>();
if (_imageCacheManager == null)
{
    Log.Fatal("ImageCache manager is invalid.");
    return;
}
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L42-L47)

## 快速診斷

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| 啟動日誌輸出 `ImageCache manager is invalid.`，之後所有圖片介面皆回傳 `null` / 無效 | `GameFrameworkEntry` 未註冊 `IImageCacheManager` 的實作 | 在框架啟動後呼叫 `GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager())` |
| 啟動日誌同時顯示 `Download manager is invalid.`(WebGL 平台以外的情況) | 缺少 `IDownloadManager` 模組，導致 `Awake` 提前 return，管理器未被注入 | 先註冊 `IDownloadManager`(例如:`DownloadManager`)，再註冊 `ImageCacheManager` |
| 錯誤僅在特定場景發生 | 目前場景未掛載 `ImageCacheComponent`，或掛載於未啟用的 GameObject 上 | 將 `ImageCacheComponent` 掛載到常駐的 GameObject，並確認場景載入時 `Awake` 已執行完成 |
| 自訂實作類別已繼承 `IImageCacheManager` 但仍發生錯誤 | `componentType`(Inspector 欄位)輸入錯誤，導致 `Awake` 內的 `Utility.Assembly.GetType(componentType)` 回傳 `null` | 在 Inspector 中將 `Component Type` 改為包含命名空間的完整類別名稱 |

## 修正步驟

### 1. 在框架進入點註冊 `ImageCacheManager`

`ImageCacheComponent` 不會自動建立管理器實例，因此必須在業務進入點明確註冊。常見做法是在框架啟動流程中呼叫以下程式碼：

```csharp
using GameFrameX.Runtime;
using GameFrameX.ImageCache.Runtime;

GameFrameworkEntry.RegisterModule<IImageCacheManager>(new ImageCacheManager());
```

Source: [IImageCacheManager.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/IImageCacheManager.cs#L11-L48)

### 2. 在 WebGL 以外的平台補上 Download 模組

`ImageCacheComponent.Awake()` 也會驗證 `IDownloadManager`，若缺少此模組，管理器初始化將會失敗：

```csharp
#if !UNITY_WEBGL
var downloadManager = GameFrameworkEntry.GetModule<IDownloadManager>();
if (downloadManager == null)
{
    Log.Fatal("Download manager is invalid.");
    return;
}
((ImageCacheManager)_imageCacheManager).SetDownloadManager(downloadManager);
#endif
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L55-L64)

因此，註冊順序應如下：先註冊 `IDownloadManager`，接著註冊 `IImageCacheManager`，最後才執行場景中掛載 `ImageCacheComponent` 之物件的 `Awake`。

### 3. 確認場景中元件的掛載狀況

請確認 `ImageCacheComponent` 掛載於**常駐**的 GameObject(例如：啟動場景的 `GameFrameX` 根節點)上，而非僅掛載於特定業務場景。由於 `Awake` 只會在場景首次被啟用時觸發一次，若缺少此元件，所有圖片呼叫都會失效，且不會重試建立管理器。

### 4. 使用自訂實作類別時請確認 `Component Type`

`Awake` 會使用 `Utility.Assembly.GetType(componentType)` 解析實作型別：

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IImageCacheManager);
base.Awake();
```

Source: [ImageCacheComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/Runtime/ImageCache/ImageCacheComponent.cs#L39-L41)

`componentType` 必須填入實作類別的**完整限定類別名稱(含命名空間)**，且該類別必須已編譯至執行階段組件中。否則 `Awake` 內部會先擲出例外，之後的 `GetModule<IImageCacheManager>()` 也會回傳 `null`，進而觸發本錯誤。

## 驗證

完成上述修正後，請透過以下方式確認問題已解決：

1. 啟動遊戲，在日誌中搜尋 `ImageCache manager is invalid.`，應不會有任何符合的項目。
2. 呼叫 `GameFrameXEntry.GetModule<IImageCacheManager>()`，確認回傳值不為 `null`。
3. 在 WebGL 以外的平台執行一次 `LoadImageAsync("https://example.com/test.png")`，確認能正常下載並快取至 `Config.CachePath` 所指向的目錄。
