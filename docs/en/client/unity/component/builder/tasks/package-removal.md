# How to Remove Unused Unity Packages

This tool can remove specified dependencies from `Packages/manifest.json` in one go and delete the corresponding local package directories under `Packages/`. After cleanup is complete, `AssetDatabase.Refresh()` is automatically invoked. The entire workflow is triggered in the Unity Editor via command-line arguments.

## Prerequisites

- `Packages/manifest.json` exists in the Unity project root directory (a standard UPM project).
- The command-line caller can pass the `-RemovePackages` argument in the process parameters (batch scripts, CI, menu invocation are all acceptable).
- `Newtonsoft.Json` is required (used to parse `manifest.json`; the Editor assembly already includes a reference).

## Operation Steps

1. Prepare the list of package names to remove. The package names must exactly match the keys under `dependencies` in `manifest.json` (for example, `com.unity.xr.management`).
2. Pass the `-RemovePackages` argument in the Unity Editor command line, followed by a list of package names separated by half-width commas.
3. Trigger `PackageRemovalHelper.Run()`. The tool will execute in the following order:
   - Parse command-line arguments to obtain the list of packages to remove; if `-RemovePackages` is not passed, an exception is thrown directly.
   - Delete the corresponding entries from `dependencies` in `manifest.json` and atomically write back using a temporary file.
   - Delete the `Packages/<package name>` local directory (embedded packages / file:// referenced packages).
   - Invoke `AssetDatabase.Refresh()`.

## Common Variations

- **Only clean `manifest.json`, do not delete local directories**: The tool checks each `dependencies[packageName]` individually; entries not present in the manifest are only logged via `Debug.Log` and skipped, no error is reported.
- **Only delete local embedded package directories**: Local folders placed under `Packages/` but not listed in `manifest.json` will have their corresponding directories deleted by the tool; the reverse is also true — the two operations are independent of each other.
- **Path safety protection**: When a package name contains `/`, `\`, `:`, or `..`, it is identified as invalid and skipped, and will not traverse beyond `Packages/`.

```csharp
if (string.IsNullOrWhiteSpace(packageName) ||
    packageName.IndexOfAny(new[] { '/', '\\', ':' }) >= 0 ||
    packageName.Contains(".."))
{
    Debug.LogWarning($"[PackageRemoval] Invalid package name, skipped: {packageName}");
    continue;
}
```

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Throws exception `No -RemovePackages argument detected. Usage: -RemovePackages package1,package2,package3` | `-RemovePackages` was not passed in the command line, or its value was forgotten | Append `-RemovePackages package1,package2` to the invocation arguments |
| Console outputs `[PackageRemoval] Dependency not found in manifest.json, skipped: xxx` | The entry does not exist in `manifest.json` (it may only exist in a `Packages/` subdirectory) | Confirm the package name exactly matches the key in `manifest.json`; deleting only the local directory is allowed |
| `[PackageRemoval] manifest.json does not exist: ...` | The project is not a UPM project, or the path has been altered | Confirm that `Packages/manifest.json` is located at the project root |
| `[PackageRemoval] Invalid package name, skipped: xxx` | The name contains `/`, `\`, `:`, or `..` | Use only plain package names (such as `com.example.foo`); do not include version numbers or path prefixes |
| `[PackageRemoval] Local package directory does not exist, skipped: xxx` | A remote dependency declared only in `manifest.json`, with no local directory | This is normal and requires no handling |

## Background (Optional)

The tool adopts the order of "modify manifest first, then delete local directories, finally `AssetDatabase.Refresh`" to ensure that Unity will not attempt to resolve already-removed embedded packages on the next asset refresh. `manifest.json` is written via a `*.tmp` intermediary file before being overwritten, avoiding JSON corruption caused by partial writes.
