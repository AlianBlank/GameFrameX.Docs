# 開啟介面失敗怎麼辦

呼叫 `OpenUIForm` / `OpenUIFormAsync` 沒有出現介面,或收到 `OpenUIFormFailureEventArgs` 事件時,可以按照本頁提供的診斷表定位原因並修復。常見的失敗原因集中在**資源未註冊、介面群組不存在、序列化腳本巨集缺失、腳本未掛載**幾類。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| `OpenUIForm` 傳回的實例為 `null`,或 `OpenUIFormFailureEventArgs.ErrorMessage` 提示找不到資源 | `uiFormAssetName` 未在 UI 元件中註冊(設定缺失或拼字錯誤) | 在 UIForm 設定中補齊資源名稱,確認 `UIFormAssetName` 與呼叫端傳入完全一致 |
| 錯誤訊息提示找不到 UI 群組 / UIGroup | 傳入的 `uiGroupName` 不存在 | 先呼叫 `AddUIGroup` 新增群組,或傳入已註冊的群組名稱 |
| 整個 `UIComponent` 出現錯誤或無法呼叫 `OpenUIForm` | 專案未啟用 `GameFrameX.UI` 腳本巨集 | 在編輯器中透過 `UISystemScriptingDefineCheckHandler` 補齊腳本巨集，或在 Player Settings 中新增 `GameFrameX.UI` |
| 資源存在但介面開啟後邏輯未觸發 | UIForm 預製件上沒有掛載對應的邏輯腳本 | 為 `UIForm` 預製件掛上正確的邏輯類別元件 |
| `OpenUIFormFailureEventArgs` 始終不觸發，但介面也沒顯示 | 沒有訂閱事件，失敗被靜默吞掉 | 訂閱 `OpenUIFormSuccessEventArgs` / `OpenUIFormFailureEventArgs` 後再呼叫 |
| `uiFormAssetPath` 與 `uiFormAssetName` 混淆，導致非同步載入失敗 | 呼叫時把「路徑」和「資源名稱」互換 | 區分：設定裡填的是 `UIFormAssetName`(邏輯名稱),`uiFormAssetPath` 是資源位址 |

## 修復步驟

### 1. 資源未註冊 / 名稱拼錯

開啟 UI 設定，確認對應 UIForm 的 `UIFormAssetName` 欄位已填寫，且名稱與 `OpenUIForm` 呼叫一致。

```csharp
// 呼叫端:名稱必須與 UIFormInspector 中 m_UIFormAssetName 一致
UIComponent.OpenUIForm("ShopUI", "Normal");
```

`UIForm` 預製件的可用欄位請見 [UIFormInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UIFormInspector.cs#L92-L110)。

### 2. UI 群組不存在

`uiGroupName` 必須是已透過 `AddUIGroup` 註冊過的群組名稱。常見情境：複製別人的程式碼但忘了註冊 `Window`、`Popup` 等自訂群組。

### 3. 腳本巨集未啟用

`UIComponent` 的所有介面依賴腳本巨集 `GameFrameX.UI`。如果從未啟用，呼叫時會直接出現錯誤。執行階段會透過 [UISystemScriptingDefineCheckHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Editor/UISystemScriptingDefineCheckHandler.cs) 在編輯器裡自動檢查並補齊。

### 4. 訂閱失敗事件，定位真正的錯誤

不要只判斷傳回值。訂閱 `OpenUIFormFailureEventArgs` 可以取得完整的錯誤堆疊，比盲目猜測更快。

```csharp
// 來自 README.md 範例
GameEntry.Event.Subscribe(OpenUIFormFailureEventArgs.EventId, OnUIFormOpenFailure);
GameEntry.Event.Subscribe(OpenUIFormSuccessEventArgs.EventId, OnUIFormOpenSuccess);

private void OnUIFormOpenFailure(object sender, GameEventArgs e)
{
    var args = (OpenUIFormFailureEventArgs)e;
    Debug.LogError($"打开 {args.UIFormAssetName} 失败: {args.ErrorMessage}");
}
```

`ErrorMessage`、`UIFormAssetName`、`SerialId`、`UserData` 的欄位定義請見 [OpenUIFormFailureEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/EventArgs/OpenUIFormFailureEventArgs.cs#L88-L131)。

### 5. UIForm 預製件沒掛邏輯腳本

如果介面「開啟」了但邏輯(`OnInit`、`OnOpen`、`OnUpdate`)未執行，通常是預製件上缺少 `IUIForm` 邏輯元件。開啟對應的預製件，將繼承 `UIForm` 的腳本掛到根節點上。

## 驗證

按照下列順序逐項確認：

1. 在 Console 中看到 `OpenUIFormSuccessEventArgs` 觸發，表示開啟成功。
2. 在 `OnUIFormOpenFailure` 中以 `Debug.LogError` 輸出 `ErrorMessage`,依照訊息關鍵字(例如 "not found"、"has not been")回到上方診斷表。
3. 關閉並重新進入介面，確認場景切換不會導致 UI 狀態遺失。
4. 在 Editor 中檢查 `UIForm` 元件的 Inspector(`UIFormAssetName`、`FullName`、`SerialId`)顯示正常。
