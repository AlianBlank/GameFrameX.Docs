# 複製檔案與資料夾到 Xcode 專案

本頁說明如何在 Xcode 建置後處理設定中，把本機檔案或整個資料夾複製進產生的 Xcode 專案，並自動加入 Build 列表、搜尋路徑。你只需在 Xcode 設定檔(JSON)的 `files` 與 `folders` 欄位裡寫「來源路徑 → 目標路徑」對應，建置時會自動執行複製。

## 前置條件

- Unity 專案已切換到 iOS 平台(實作都在 `#if UNITY_IOS` 之下)。
- 已完成 Xcode 建置後處理的基礎串接:`PostProcessBuildHelper` 會在建置回呼中讀取合併後的設定並呼叫 `Run`。

## 操作步驟

1. 開啟你的 Xcode 建置後處理設定檔，找到目標 target 的設定節點(如 `unityMain` / `unityFramework` 對應的雜湊表)。
2. 在該節點下新增 `files` 欄位，Key 為來源檔案路徑(相對於 Unity 專案根目錄，即 `Environment.CurrentDirectory`),Value 為目標路徑(相對於產生的 Xcode 專案目錄):

```json
{
  "files": {
    "Assets/Plugins/iOS/NativeCode.mm": "Libraries/NativeCode.mm",
    "Assets/Plugins/iOS/MySDK.framework": "Frameworks/MySDK.framework"
  }
}
```

3. 需要複製整個資料夾時，新增 `folders` 欄位，同樣以「來源路徑 → 目標路徑」對應:

```json
{
  "folders": {
    "Assets/Plugins/iOS/NativeFolder": "Libraries/NativeFolder"
  }
}
```

4. 觸發一次 iOS 建置。建置結束後，`Run` 會依序執行複製：先 `RunCopyFiles` 處理 `files`,再 `CopyFolders` 處理 `folders`:

```csharp
// 複製檔案
RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
// 複製資料夾
CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L173-L176)

5. 在 Xcode 專案中確認：檔案已出現在對應目標路徑，並已被 `AddFileToBuild` 加入目標 target 的 Build 列表；主控台會輸出 `copy file {src} -> {des}` 日誌。

## 複製行為細節

複製並不是簡單的拷貝，以下行為來自原始碼實作，設定時需要知道：

| 行為 | 說明 |
|------|------|
| 目標目錄自動建立 | `CopyFolder` 會先刪除已存在的同名目錄/檔案，再 `Directory.CreateDirectory` 重建後遞迴複製 |
| 覆蓋已有檔案 | 單一檔案複製使用 `File.Copy(src, des, true)`,同名檔案會被覆蓋 |
| 忽略隱藏與垃圾檔案 | 檔名以 `.` 開頭、`.gitkeep`、`.DS_Store` 會被跳過，不複製也不加入 Build |
| 自動加入 Build | 檔案透過 `proj.AddFile` + `proj.AddFileToBuild` 加入專案 |
| 自動加搜尋路徑 | 複製 `.framework` / `.xcframework` 自動加 `FRAMEWORK_SEARCH_PATHS`;`.h` 自動加 `HEADER_SEARCH_PATHS`;`.a` 自動加 `LIBRARY_SEARCH_PATHS`,前綴為 `$PROJECT_DIR` |
| bundle 同時加入主 target | `folders` 中以 `.bundle` 結尾的項，除目標 target 外還會透過 `AddFileToBuild(mainTargetGuid, fileGuid)` 加入 Unity 主 target |
| 資料夾整體作為 framework | `folders` 的目標路徑以 `.framework` / `.xcframework` / `.bundle` / `.a` 結尾時，整個目錄會被當作單一程式庫檔案加入建置，不再遞迴展開 |

檔案複製的核心實作：

```csharp
private static void CopyFile(PBXProject proj, string targetGuid, string xcodePath, string src, string des)
{
    bool needCopy = IsNeedCopy(src);
    if (needCopy)
    {
        File.Copy(src, des, true);
        proj.AddFileToBuild(targetGuid, proj.AddFile(des, des.Replace(xcodePath + "/", ""), PBXSourceTree.Absolute));
        AutoAddSearchPath(proj, xcodePath, targetGuid, des);
        Debug.Log("copy file " + src + " -> " + des);
    }
}
```

Source: [PostProcessBuildHelper.File.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.File.cs#L42-L52)

資料夾遞迴複製的核心實作(先清空目標再重建):

```csharp
private static void CopyFolder(string srcPath, string dstPath)
{
    if (Directory.Exists(dstPath))
    {
        Directory.Delete(dstPath, true);
    }

    if (File.Exists(dstPath))
    {
        File.Delete(dstPath);
    }

    Directory.CreateDirectory(dstPath);

    foreach (var file in Directory.GetFiles(srcPath))
    {
        if (IsNeedCopy(Path.GetFileName(file)))
        {
            File.Copy(file, Path.Combine(dstPath, Path.GetFileName(file)));
        }
    }

    foreach (var dir in Directory.GetDirectories(srcPath))
    {
        CopyFolder(dir, Path.Combine(dstPath, Path.GetFileName(dir)));
    }
}
```

## 常見變體

- **複製 SDK / 靜態程式庫**：把 `.framework`、`.xcframework`、`.a` 放進 `folders`,目標路徑直接寫成 `Frameworks/xxx.framework`。框架會被加入 Link Binary With Libraries 並自動補搜尋路徑(`AddFrameworkToProject(targetGuid, root, false)`),`.a` 靜態程式庫只加入連結階段。
- **複製資源 bundle**:`folders` 中以 `.bundle` 結尾的目錄會同時加入 Unity 主 target 與 UnityFramework target,適合需要隨包發佈的資源。
- **只想把檔案放進專案不參與編譯的細節調整**：複製完成後，可透過同層級的 `filesCompileFlag` 設定編譯標記，該步驟在複製之後執行(`SetFilesCompileFlag`)。

## 常見錯誤

| 問題 | 原因 | 規避 |
|------|------|------|
| 複製後 Xcode 裡找不到檔案 | 來源路徑寫成了絕對路徑或相對層級不對 | `files`/`folders` 的 Key 是相對 Unity 專案根目錄的路徑，執行時會 `Path.Combine(Environment.CurrentDirectory, key)` |
| 某些檔案始終沒被複製 | 命中了 `IsNeedCopy` 的排除規則 | 檔名以 `.` 開頭、`.gitkeep`、`.DS_Store` 會被直接跳過，請改名或移出 |
| 每次建置後目標目錄內容「遺失」 | `CopyFolder` 會先 `Directory.Delete(dstPath, true)` 清空目標目錄 | 不要把其他內容手動放進 `folders` 設定的目標目錄 |
| 單一檔案複製回報目標已存在例外而未生效 | 實際上不會，單一檔案複製帶有 `overwrite: true` | 若仍失敗，檢查目標目錄是否存在同名資料夾(會被當作目錄處理) |
| framework 連結回報找不到 | 未走自動搜尋路徑邏輯 | 確認以 `.framework` / `.xcframework` / `.a` 結尾，`AutoAddSearchPath` 只對這三種副檔名生效 |

## 背景

複製發生在 Xcode 專案產生之後:`PostProcessBuildHelper` 讀取 PBXProject 與合併後的設定，`Run` 依序處理 properties、frameworks、libs、files、folders 等;`CopyFolders` 額外接收 `mainTargetGuid`,是為了讓 `.bundle` 能同時掛到 Unity 主 target 上。檔案路徑皆基於 `PBXSourceTree`,framework/靜態程式庫用 `Source`,單一檔案用 `Absolute`。
