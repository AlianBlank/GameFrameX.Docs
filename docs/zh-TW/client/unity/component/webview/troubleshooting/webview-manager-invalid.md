# 啟動時報 “Web View manager is invalid” 怎麼辦

該報錯來自 `WebViewComponent.Awake()`:`GameFrameworkEntry.GetModule<IWebViewManager>()` 傳回了 `null`,說明框架中沒有任何實作了 `IWebViewManager` 的具體模組被註冊/載入。出現後 WebView 元件不會呼叫 `Initialize()`,後續 `Show` / `Hide` 等呼叫都會出現空參考。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 啟動即輸出 `Log.Fatal("Web View manager is invalid.")` | `GameFrameworkEntry.GetModule<IWebViewManager>()` 傳回 `null`,具體實作模組未被載入 | 確認專案中存在 `BaseWebViewManager` 的具體實作模組，見[修復步驟 1](#修復步驟) |
| 之後呼叫 `Show(url)` 擲回 `NullReferenceException` | 上一步失敗後 `_webViewManager` 保持為 `null`,元件直接跳過初始化 | 先解決上面的 Fatal,見[驗證](#驗證) |
| Inspector 中元件的實作類型下拉選單為空 | 實作類型未選擇，或對應組件未編譯進專案 | 見[修復步驟 2](#修復步驟) |

報錯觸發點原始碼：

```csharp
_webViewManager = GameFrameworkEntry.GetModule<IWebViewManager>();
if (_webViewManager == null)
{
    Log.Fatal("Web View manager is invalid.");
    return;
}
```

初始化被跳過的連帶後果：

```csharp
private void Start()
```

## 修復步驟

### 1. 確認專案裡有 `IWebViewManager` 的具體實作

本儲存庫只提供抽象層:`BaseWebViewManager` 是抽象類別，不含任何平台實作(目錄中僅有 `BaseWebViewManager`、`IWebViewManager`、`WebViewComponent` 等)。具體實作必須由配套的執行階段模組提供：

```csharp
public abstract partial class BaseWebViewManager : GameFrameworkModule, IWebViewManager
{
    public abstract void Initialize();
    public abstract void Show(string url);
    public abstract void MakeFullScreen();
    public abstract void ExecuteJavaScript(string javaScript);
    public abstract void Hide();
}
```

Source: [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39)

排查方法：在專案內全域搜尋 `: BaseWebViewManager`,確認存在至少一個非抽象衍生類別；沒有則安裝/引入對應的執行階段實作套件後重試。

### 2. 檢查元件上的實作類型是否已選擇

`WebViewComponent` 在 `Awake()` 裡透過反射解析實作類型，再取得介面模組：

```csharp
ImplementationComponentType = Utility.Assembly.GetType(componentType);
InterfaceComponentType = typeof(IWebViewManager);
base.Awake();
if (!IsRuntimeComponentReady)
{
    return;
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L30)

`componentType` 的取值由 Inspector 提供，編輯器腳本會把所有實作了 `IWebViewManager` 的類型刷進下拉選單：

```csharp
internal sealed class WebViewComponentInspector : ComponentTypeComponentInspector
{
    ...
    RefreshComponentTypeNames(typeof(IWebViewManager));
}
```

Source: [WebViewComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Editor/WebViewComponentInspector.cs#L14-L19)

操作：選取掛載 `WebView` 元件的遊戲物件，在 Inspector 中確認實作類型不為空；為空說明對應組件沒有被編譯進目前建置目標(常見於平台實作套件只支援特定平台)。修正後儲存場景再執行。

### 3. 確認執行階段組件參與編譯

本套件的組件定義為 `Runtime/GameFrameX.WebView.Runtime.asmdef` 與 `Editor/GameFrameX.WebView.Editor.asmdef`。檢查 Unity Console 是否有關於這兩個組件(或實作模組組件)的編譯報錯；編譯失敗會導致 `GetModule` 拿不到實作，表現為同樣的 Fatal。

## 驗證

1. 重新進入 Play 模式，Console 不再出現 `Web View manager is invalid.` 的 Fatal 日誌。
2. 執行一次完整呼叫鏈，能正常開啟頁面：

```csharp
var webView = GameObject.FindObjectOfType<GameFrameX.WebView.Runtime.WebViewComponent>();
webView.Show("https://example.com");
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L51-L58)

## 背景

`WebViewComponent` 是 `GameFrameworkComponent`,自身不實作任何 WebView 邏輯，只負責在 `Awake()` 裡從 `GameFrameworkEntry` 取出 `IWebViewManager` 模組並轉發呼叫(`Show`、`MakeFullScreen`、`ExecuteJavaScript`、`Hide`)。抽象與實作分離意味著介面層與各平台實作可獨立打包；當實作模組缺失時，取得模組這一步就會失敗並輸出本頁的 Fatal 日誌。
