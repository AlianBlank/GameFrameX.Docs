# 加载 AssetBundle 抛 FileNotFoundException 怎么办

调用 `BlankReadAssets.LoadAssetBundle` 或 `BlankReadAssets.LoadAssetBundleAsync` 时,如果传入的相对路径没有命中 StreamingAssets 中的资源,框架会直接抛出 `System.IO.FileNotFoundException("File not found", path)`,这是路径解析失败最常见的信号。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `FileNotFoundException: File not found`(message 含传入的 path) | 路径未找到对应文件,常见于大小写、斜杠、未放进 StreamingAssets 三种情况 | 用 `FileExists` 预检;统一使用相对路径与 `/` 分隔;确认资源在 `Assets/StreamingAssets/` 下 |
| Editor 下能找到,打包后 Android 真机找不到 | APK 中资源被压缩,默认 `AssetBundle.LoadFromFile` 读不到 | 调用 `BlankReadAssets.SetCompressedAssetBundleFileNames(...)` 登记压缩清单 |
| 抛异常前资源其实存在,但提示找不到 | 路径前缀写成了 `StreamingAssets/xxx`,框架已隐式去除该前缀 | 去掉 `StreamingAssets/` 前缀,只传相对子路径 |

## 修复步骤

### 1. 用 FileExists 预检路径

`BlankReadAssets.LoadAssetBundle` 内部会先调 `GetInfoOrThrow`,找不到时调用 `ThrowFileNotFound` 直接抛异常。先用 `FileExists` 排查可以快速定位是路径写错还是资源缺失:

```csharp
if (!BlankReadAssets.FileExists("ui/prefab/main.ab"))
{
    Debug.LogError("AssetBundle 不存在,请确认已放进 StreamingAssets");
    return;
}
var bundle = BlankReadAssets.LoadAssetBundle("ui/prefab/main.ab");
```

异常原文与触发位置如下:

```csharp
private static void ThrowFileNotFound(string path)
{
    throw new FileNotFoundException("File not found", path);
}
```

Source: [BlankReadAssets.cs#L243-L246](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L243-L246)

### 2. 路径必须是相对 StreamingAssets 的子路径,且使用 `/`

框架的 `LooseFilesImpl.TryGetInfo` 会把传入路径与 `s_root` 拼接后调 `File.Exists`:

```csharp
var fullPath = s_root + path;
if ( !File.Exists(fullPath) )
{
    return false;
}
info.readPath = fullPath;
```

Source: [BlankReadAssets.LooseFilesImpl.cs#L57-L71](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.LooseFilesImpl.cs#L57-L71)

- 正确:`"ui/prefab/main.ab"`(对应 `Assets/StreamingAssets/ui/prefab/main.ab`)
- 错误:`"StreamingAssets/ui/prefab/main.ab"`、`"ui\\prefab\\main.ab"`、绝对路径
- 大小写敏感:Android 真机文件系统严格区分大小写

### 3. APK 中识别压缩的 AssetBundle

`AssetBundle.LoadFromFile` 默认只能读取 APK 内未压缩的文件。如果你的构建管线把 `.ab` 压进 APK,需要在使用前登记被压缩的文件清单,否则底层 `LoadFromFile` 会抛 `FileNotFoundException` 或返回损坏的包。登记方式见 `BlankReadAssets.SetCompressedAssetBundleFileNames`,该入口通过 `AndroidIsCompressedFileStreamingAsset` partial 方法让宿主工程注入实际文件名列表:

```csharp
// 在宿主工程中按需扩展
BlankReadAssets.SetCompressedAssetBundleFileNames(
    "ui/prefab/main.ab",
    "ui/prefab/login.ab"
);
```

Source: [BlankReadAssets.cs#L248](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L248)

### 4. 加载入口

加载接口本身签名如下,异常仅在路径解析阶段抛出,真正读包失败由 Unity 内部抛出:

```csharp
public static AssetBundleCreateRequest LoadAssetBundleAsync(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFileAsync(info.readPath, crc, (ulong)info.offset);
}

public static AssetBundle LoadAssetBundle(string path, uint crc = 0)
{
    var info = GetInfoOrThrow(path);
    return AssetBundle.LoadFromFile(info.readPath, crc, (ulong)info.offset);
}
```

Source: [BlankReadAssets.cs#L119-L130](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L119-L130)

如果 `GetInfoOrThrow` 找到了文件、但 `AssetBundle.LoadFromFile` 仍然报错,问题就出在打包产物本身(CRC 不匹配、offset 错误、被压缩等),需要回到构建侧检查。

## 验证

1. 在调用 `LoadAssetBundle` 前先 `BlankReadAssets.FileExists(path)`,期望返回 `true`。
2. Editor 下能正常加载的路径,逐字复制到真机:大小写、分隔符、目录层级必须完全一致。
3. Android 真机上若 `FileExists` 为 `true` 但加载仍失败,确认 `.ab` 在 APK 内是否被压缩,需要先登记到 `SetCompressedAssetBundleFileNames`。
