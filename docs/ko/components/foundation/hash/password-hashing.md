# 비밀번호 해시 사용 방법:PBKDF2/Bcrypt/Scrypt/Argon2id

`PasswordHashHelper` 한 줄 호출로 PBKDF2, Bcrypt, Scrypt, Argon2id 네 가지 비밀번호 해시 알고리즘 사이를 전환할 수 있으며, 로그인 검증 시 PHC 접두사에 따라 알고리즘을 자동으로 식별하므로 어떤 알고리즘을 사용했는지 기록할 필요가 없습니다.

## 사전 조건

- 프로젝트에서 `GameFrameX.Foundation.Hash` 어셈블리를 참조해야 합니다.
- `using GameFrameX.Foundation.Hash;`(Bcrypt/Scrypt/Argon2id는 `BCrypt.Net-NNext.StrongName`과 BouncyCastle에서 제공하므로 추가 설치가 필요하지 않습니다).
- 현재 알고리즘 종류는 열거형 `PasswordHashAlgorithmKind`로 선택합니다: `Pbkdf2` / `Bcrypt` / `Scrypt` / `Argon2id`.

## 작업 단계

### 1. 통합 파사드를 사용하여 새 비밀번호 해시하기(Argon2id 예시)

```csharp
using GameFrameX.Foundation.Hash;

string phc = PasswordHashHelper.Hash(PasswordHashAlgorithmKind.Argon2id, "P@ssw0rd-测试-🔑");
// phc 形如 $argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash>
// 직접 phc 전체 문자열을 데이터베이스에 저장하면 됩니다
```

출처: [PasswordHashHelper.cs#L57-L74](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L57-L74)

### 2. 비밀번호 검증

이전에 어떤 알고리즘을 사용했는지 기록할 필요 없이, 파사드가 PHC 접두사에 따라 자동으로 디스패치합니다:

```csharp
bool ok = PasswordHashHelper.Verify(inputPassword, phcStoredInDb);
if (ok) { /* 登录成功 */ }
```

출처: [PasswordHashHelper.cs#L84-L102](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L84-L102)

### 3. 알고리즘 종류 전환

단계 1의 `PasswordHashAlgorithmKind.Argon2id`를 `Pbkdf2` / `Bcrypt` / `Scrypt`로 교체하기만 하면 됩니다. `Verify`는 여전히 기존 데이터베이스의 PHC 문자열을 식별할 수 있습니다.

### 4. 알고리즘이 OWASP 권장인지 판단

```csharp
bool isOwaspFirstChoice = PasswordHashHelper.IsRecommended(PasswordHashAlgorithmKind.Argon2id); // true
```

출처: [PasswordHashHelper.cs#L109-L112](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/PasswordHashHelper.cs#L109-L112)

### 5. PHC 접두사 능동 식별

```csharp
PasswordHashAlgorithmKind? kind = PasswordHashHelper.DetectAlgorithm(storedHash);
// 식별 표:$pbkdf2-sha256$、$2a$/$2b$/$2y$(bcrypt)、$scrypt$、$argon2id$
```

## 일반적인 변형

- **PBKDF2 소규모 파라미터 빠른 디버깅**: `Pbkdf2Helper.Hash(password, 100, 16)`을 직접 호출(테스트에서 디스패치 로직을 이렇게 부하 테스트함), 프로덕션 환경에서는 파사드의 기본 파라미터를 사용하세요.
- **Bcrypt 소규모 작업因子**: 테스트에서 `BcryptHelper.Hash(password, 4)`로 생성; 프로덕션에서는 파사드의 기본 보안 파라미터 사용을 권장합니다.
- **Scrypt / Argon2id 소규모 파라미터 스모크 테스트**: `ScryptHelper.Hash(password, 1024, 1, 1)`, `Argon2idHelper.Hash(password, 16, 1, 1)`은 테스트에서의 최소 파라미터 조합으로, 단위 테스트의 빠른 왕복에 사용됩니다.

## 일반적인 오류

| 현상 | 원인 | 회피 |
|------|------|------|
| `Hash(未知열거型값, pwd)`이 `ArgumentOutOfRangeException`을 던짐 | 전달된 것이 네 가지 알려진 알고리즘이 아님 | `Pbkdf2` / `Bcrypt` / `Scrypt` / `Argon2id`만 사용 |
| `Hash(Bcrypt, 超장비밀번호)`이 `ArgumentOutOfRangeException`을 던짐 | bcrypt의 하드 제한 72바이트(UTF-8) | 72바이트를 초과하는 비밀번호는 Argon2id / Scrypt로 변경하거나, 먼저 다이제스트를 취한 후 해시 수행 |
| `Verify`가 `false`를 반환하지만 비밀번호는 맞음 | 저장된 문자열이 네 가지 PHC 접두사 중 하나가 아니거나, 형식이 손상됨 | `DetectAlgorithm(storedHash)`로排查하여 접두사가 완전한지 확인 |
| "72바이트 제한에 따라 알고리즘을 교체"하려고 `Argon2id`가 아닌 알고리즘을 사용 | OWASP 최우선 선택은 Argon2id이며, 나머지는 최우선이 아닐 수 있음 | `PasswordHashHelper.IsRecommended(kind)`로 판단 |

## 배경(선택 사항)

`PasswordHashHelper`는 얇은 파사드이며, 실제 구현은 각각 `Pbkdf2Helper`(BCL `Rfc2898DeriveBytes`), `BcryptHelper`(`BCrypt.Net-Next.StrongName`, 72바이트 하드 상한), `ScryptHelper`와 `Argon2idHelper`(BouncyCastle)가 담당합니다. `Verify`는 PHC 문자열 접두사($pbkdf2-sha256$ / $2a$|$2b$|$2y$ / $scrypt$ / $argon2id$)로 디스패치하므로, 향후 데이터베이스에서 과거 PBKDF2를 Argon2id로 업그레이드하더라도 이전 PHC 문자열은 여전히 식별 가능합니다. 열거형 `PasswordHashAlgorithmKind`는 검증 및 합계에 사용되는 `HashAlgorithmKind`와 의미가 다르므로, 비밀번호 시나리오에서는 전자(前者)를 사용해야 합니다.
