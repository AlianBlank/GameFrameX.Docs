# How It Works: Post-Build Processing and Configuration Merge Workflow

After an iOS build completes, `PostProcessBuildHelper.OnPostProcessBuild` (callback priority `888`) automatically collects **all** files named `XCodeConfig.json` in the project, deep-merges them into a single final configuration (including channel-specific overrides), and then writes the configuration into the generated Xcode project in two phases. The entire process requires no manual intervention—simply place the configuration file anywhere in the project directory.

## Configuration Discovery and Merging

The process executes in the following order:

1. `SettingLoader.LoadSettingsData("XCodeConfig.json")` scans all TextAssets in the project, exactly matching `XCodeConfig.json` by filename (case-insensitive); results are sorted by path to guarantee a deterministic merge order.
2. Each file is read and parsed via `HashtableFromJson()`, then deep-merged recursively into the same `Hashtable` through `finalConfig.Merge(table)`.
3. If a channel identifier exists, `XCodeConfig.{channel}.json` is loaded and **merged last**, so channel configuration has the highest priority.
4. If the merged result is empty, all subsequent setup is skipped.

Key code (general configuration merge part):

```csharp
var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

if (jsonPaths.Count == 0)
{
    LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
    return;
}

Hashtable finalConfig = new Hashtable();
foreach (var jsonPath in jsonPaths)
{
    string json = File.ReadAllText(jsonPath);
    Hashtable table = json.HashtableFromJson();
    if (table == null)
    {
        LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
        continue;
    }
    finalConfig.Merge(table);
}
```

## Channel Configuration

The channel name is obtained via `SettingLoader.GetChannel()`: the `-channel` command-line argument takes priority; otherwise it falls back to the EditorPrefs key `XCodeBuild_Channel`:

```csharp
var args = Environment.GetCommandLineArgs();
for (int i = 0; i < args.Length - 1; i++)
{
    if (args[i].Equals(CHANNEL_ARG, StringComparison.OrdinalIgnoreCase))
    {
        return args[i + 1];
    }
}
string editorChannel = EditorPrefs.GetString(CHANNEL_EDITOR_PREFS_KEY, "");
if (!string.IsNullOrEmpty(editorChannel))
{
    return editorChannel;
}
return null;
```

The channel configuration filename is generated by appending the channel name to the base name, i.e., `XCodeConfig.{channel}.json` ([Editor/SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L85-L111)). ## Two-Phase Application Workflow

After merging, the configuration is written into the Xcode project in two phases ([Editor/PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L85-L156)):

**Phase 1: Write the PBXProject (project.pbxproj)**

1. Read `Unity-iPhone.xcodeproj/project.pbxproj` as a `PBXProject`.
2. Apply `finalConfig["unityMain"]` to the **Unity-iPhone main target** (`Run(...)`, see next section).
3. Apply `finalConfig["unityFramework"]` to the **UnityFramework target**.
4. `SetSigning` configures signing (main target only), reading the `signing` node.
5. `SetupSwiftBridging` configures Swift bridging; the key `swiftBridging` **defaults to enabled when absent**.
6. Write project.pbxproj back to disk.

**Phase 2: Apply Other Configurations**

1. `RunPlist` writes Info.Plist (the `plist` node).
2. `RunEnvironmentVariables` sets launch environment variables (`environmentVariables`).
3. `RunArgument` sets launch arguments (`launcherArgs`).
4. `SetCapabilities` sets Capabilities (main target only); the bundleId is taken from `signing.bundleId`.
5. Because Capabilities are written to disk independently via `ProjectCapabilityManager`, the code **re-reads** project.pbxproj to preserve those modifications.
6. `RunLocalization` applies localizations (`localizations`).
7. PodFile: if the `podfile` key specifies a complete Podfile, it is copied and its source is rewritten; otherwise the legacy path is used, injecting `unityMain.pods` / `unityFramework.pods` line by line into the `Unity-iPhone` and `UnityFramework` target blocks.
8. Finally, `pod install` is executed; the key `podInstall` **defaults to executing when absent**—set it to `false` to skip.

## Run(): Eight Subtasks for Target-Level Configuration

`Run` is the core of Phase 1, applying the following to a single target in sequence (corresponding to the fields under `unityMain` / `unityFramework`):

| Order | Method | Config Key | Purpose |
|------|------|--------|------|
| 1 | `SetBuildProperties` | `properties` | Build properties |
| 2 | `SetFrameworks` | `frameworks` | Frameworks |
| 3 | `SetLibs` | `libs` | System libraries |
| 4 | `RunCopyFiles` | `files` | Copy files |
| 5 | `CopyFolders` | `folders` | Copy folders |
| 6 | `SetFilesCompileFlag` | `filesCompileFlag` | File compile flags |
| 7 | `AddOtherLinkFlag` | `otherLinkerFlag` | Linker Flag |
| 8 | `AddRunPathSearchPaths` | `runPathSearchPaths` | Run Path Search Paths |

```csharp
static void Run(PBXProject pbxProject, string targetGuid, string mainTargetGuid, Hashtable hashtable, string path)
{
    SetBuildProperties(pbxProject, targetGuid, hashtable.Get<Hashtable>("properties"));
    SetFrameworks(pbxProject, targetGuid, hashtable.Get<Hashtable>("frameworks"));
    SetLibs(pbxProject, targetGuid, hashtable.Get<Hashtable>("libs"));
    RunCopyFiles(pbxProject, targetGuid, path, hashtable.Get<Hashtable>("files"));
    CopyFolders(pbxProject, targetGuid, mainTargetGuid, path, hashtable.Get<Hashtable>("folders"));
    SetFilesCompileFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("filesCompileFlag"));
    AddOtherLinkFlag(pbxProject, targetGuid, hashtable.Get<Hashtable>("otherLinkerFlag"));
```

## Merge Order and Override Rules

Priority from lowest to highest—configurations merged later override those merged earlier (deep merge; for identical keys, the newer value wins):

1. All `XCodeConfig.json` files in the project (merged one by one in sorted path order);
2. `XCodeConfig.{channel}.json` channel-specific configuration (merged last, highest priority).

Therefore, to have a specific channel override a field, simply write that field into the channel file—no need to modify the general configuration.
