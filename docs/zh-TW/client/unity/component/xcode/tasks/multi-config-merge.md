# 多模組設定檔合併

把每個模組各自的 iOS 建置設定寫成一份 `XCodeConfig.json`，框架在 Xcode 專案匯出後會自動掃描、合併所有同名設定檔（含通道專屬設定），再把合併結果一次寫入 Xcode 專案。你不需要手動彙整一份大設定，只要把檔案放在能被掃描到的位置即可。

## 前置條件

- Unity 專案已引入本套件（Editor 組件 `GameFrameX.Xcode.Editor`）。
- 建置目標為 iOS：整個合併流程位於 `#if UNITY_IOS` 內，其他平台直接傳回。

## 操作步驟

1. 為每個模組建立一份 `XCodeConfig.json`，只寫本模組關注的欄位。框架透過 `SettingLoader.LoadSettingsData("XCodeConfig.json")` 掃描出全部符合檔案的路徑清單（見 [SettingLoader.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/SettingLoader.cs#L58)）。
2. 執行 iOS 建置。建置完成後 Unity 回呼自動執行，開始讀取並合併設定：

```csharp
[PostProcessBuild(888)]
public static void OnPostProcessBuild(BuildTarget target, string path)
{
    if (target != BuildTarget.iOS)
    {
        return;
    }

    try
    {
        //讀取設定檔
        var jsonPaths = SettingLoader.LoadSettingsData("XCodeConfig.json");

        // 如果沒有找到任何符合的檔案，直接傳回
        if (jsonPaths.Count == 0)
        {
            LogHelper.Error("未找到任何 XCodeConfig 相关配置文件, 跳过设置");
            return;
        }

        // 合併所有設定檔的內容
        Hashtable finalConfig = new Hashtable();
        foreach (var jsonPath in jsonPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并配置: {jsonPath}");
            string json = File.ReadAllText(jsonPath);
            Hashtable table = json.HashtableFromJson();
            if (table == null)
            {
                LogHelper.Error($"{jsonPath} 解析失败, 跳过合并");
                continue;
            }

            // 使用擴充方法合併 Hashtable
            finalConfig.Merge(table);
        }
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L14-L49)

3. （選用）提供通道專屬設定。框架透過 `SettingLoader.GetChannel()` 取得目前通道，再載入 `XCodeConfig.{channel}.json` 並在最後合併，因此通道設定優先順序最高、會覆寫一般設定中的同名欄位：

```csharp
// 合併通道專屬設定（優先順序最高，最後合併覆寫）
string channel = SettingLoader.GetChannel();
if (!string.IsNullOrEmpty(channel))
{
    var channelPaths = SettingLoader.LoadChannelSettingsData("XCodeConfig.json", channel);
    if (channelPaths.Count > 0)
    {
        LogHelper.Log($"[MergeConfig] 检测到渠道: {channel}，正在合并渠道配置...");
        foreach (var channelPath in channelPaths)
        {
            LogHelper.Log($"[MergeConfig] 正在合并渠道配置: {channelPath}");
            string channelJson = File.ReadAllText(channelPath);
            Hashtable channelTable = channelJson.HashtableFromJson();
            if (channelTable == null)
            {
                LogHelper.Error($"{channelPath} 解析失败, 跳过合并");
                continue;
            }

            finalConfig.Merge(channelTable);
        }
    }
    else
    {
        LogHelper.Log($"[MergeConfig] 未找到渠道 [{channel}] 的专属配置文件 XCodeConfig.{channel}.json");
    }
}
```

Source: [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L51-L77)

4. 檢查 Console 輸出。每份被合併的檔案都會列印 `[MergeConfig] 正在合并配置: <路径>`（通道設定為 `[MergeConfig] 正在合并渠道配置: <路径>`），據此確認哪些檔案參與了合併。

## 可合併的最上層設定欄位

合併結果按下列鍵套用（鍵名來自 `finalConfig.Get<...>(...)` 的實際取值，任何模組都只需提供自己用到的鍵）：

| 鍵 | 類型 | 套用動作 |
|----|------|----------|
| `unityMain` | Hashtable | 套用到 Unity 主 Target：`properties`、`frameworks`、`libs`、`files`、`folders`、`filesCompileFlag`、`otherLinkerFlag`、`runPathSearchPaths`（及舊式 `pods`） |
| `unityFramework` | Hashtable | 同上，套用到 UnityFramework Target |
| `signing` | Hashtable | 簽署設定，僅在主 Target 上設定；其 `bundleId` 供 Capabilities 使用 |
| `swiftBridging` | bool | Swift 橋接開關，預設視為開啟 |
| `plist` | Hashtable | 寫入 Info.Plist |
| `environmentVariables` | Hashtable | 啟動環境變數 |
| `launcherArgs` | ArrayList | 執行啟動參數 |
| `capabilities` | Hashtable | Capability 設定，僅在主 Target 上設定 |
| `localizations` | ArrayList | 在地化資源 |
| `podSource` | ArrayList | Podfile 的 source 來源 |
| `podfile` | string | 完整 Podfile 的設定路徑，複製成功後改走新路徑 |
| `podInstall` | bool | 是否在 Podfile 處理後執行 `pod install`，預設視為開啟 |

## 常見變體

- **某模組 JSON 解析失敗仍要完成建置**：單一檔案解析失敗只會輸出 `Error` 日誌並 `continue`，不會中斷整體流程；其餘檔案繼續合併。
- **不想執行 `pod install`**：在（任一參與合併的）設定中寫 `"podInstall": false`，見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L151-L156)。
- **關閉 Swift 橋接**：寫 `"swiftBridging": false`；不寫該鍵時預設開啟，見 [PostProcessBuildHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.xcode/blob/main/Editor/PostProcessBuildHelper.cs#L99-L101)。

## 常見錯誤

| 症狀（日誌原文） | 原因 | 修正 |
|------|------|------|
| `未找到任何 XCodeConfig 相关配置文件, 跳过设置` | 掃描結果為空，沒有任何模組提供設定 | 確認至少存在一份可被 `LoadSettingsData` 掃描到的 `XCodeConfig.json` |
| `<路径> 解析失败, 跳过合并` | 該檔案內容不是合法 JSON，`HashtableFromJson()` 傳回 null | 修正該檔案的 JSON 語法；該檔案被跳過，其餘檔案正常合併 |
| `合并后的配置为空，跳过设置` | 所有檔案都解析失敗或內容為空 | 逐份檢查 JSON；從 `[MergeConfig] 正在合并配置:` 日誌核對參與合併的檔案清單 |
| `[MergeConfig] 未找到渠道 [...] 的专属配置文件 XCodeConfig.[...].json` | 通道已設定但缺少通道專屬檔案 | 視需要補建 `XCodeConfig.{渠道}.json`；不補也不影響一般設定生效 |

## 驗證

- Console 中出現 `[MergeConfig] 正在合并配置: ...` 列出全部參與的檔案；設定通道時出現 `[MergeConfig] 检测到渠道: <渠道>` 與對應的通道合併日誌。
- 接著出現 `[PBXProject] 正在应用最终合并配置...` 與 `[OtherSettings] 正在应用最终合并配置...`，表示合併結果已寫入專案。
- 開啟匯出的 Xcode 專案，核對 Target 的建置屬性、框架/程式庫、Info.Plist、Podfile 等是否與合併後預期一致。

## 背景

合併基於 `Hashtable.Merge()` 擴充方法逐份疊加，後合併的覆寫先合併的，因此載入順序就是優先順序；通道設定最後合併，優先順序最高。整個流程對 `Get<Hashtable>(...)` 的取值做了 null 容錯，所以每個模組只寫自己需要的鍵即可，不必提供完整結構。
