# iOS 빌드 후 Info.plist 채널이 기록되지 않거나 건너뛰어짐

내보낸 Xcode 프로젝트의 `Info.plist`에 `channel` 키가 없거나, 런타임에 `BlankGetChannel.GetChannelName()`이 계속 `default`를 반환하는 경우, 일반적인 원인은 다음과 같습니다: `PostProcessBuildHandler`가 `#if UNITY_IOS` 조건부 컴파일에서 제외됨, 빌드 대상이 `BuildTarget.iOS`가 아님, 또는 plist에 이미 `channel` 키가 존재하여 핸들러가 설계대로 건너뜀. 본 문서는 증상별로 원인을 파악하고 수정하는 방법을 안내합니다.

## 수정 단계

### 1. 에디터 빌드 대상이 iOS인지 확인

핸들러 파일 전체가 `#if UNITY_IOS`로 감싸져 있으며, 콜백 내부에서 대상 플랫폼을 다시 한 번 필터링합니다:

```csharp
#if UNITY_IOS
        [PostProcessBuild(99)]
        public static void OnPostProcessBuild(BuildTarget target, string path)
        {
            if (target != BuildTarget.iOS)
            {
                return;
            }

            try
            {
                Run(path);
            }
            catch (Exception e)
            {
                Debug.LogException(e);
            }
        }
#endif
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L1-L29)

작업: **File → Build Settings**에서 활성 플랫폼을 iOS로 전환한 후 빌드를 실행하세요. 전환 후 스크립트가 다시 컴파일되어야 콜백이 등록되어 적용됩니다.

### 2. `channel` 키가 이미 존재하여 건너뛰어짐

```csharp
string plistPath = path + "/Info.plist";
PlistDocument plist = new PlistDocument();
plist.ReadFromString(File.ReadAllText(plistPath));
if (!plist.root.values.TryGetValue(channelKey, out var value))
{
    plist.root.SetString(channelKey, channelValue);
    plist.WriteToFile(plistPath);
    Debug.Log("配置渠道成功=>" + channelValue);
}
else
{
    Debug.Log("已有渠道,跳过设置=>" + value);
}
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L36-L48)

이 로직은 키가 **존재하지 않을 때만** 기록하며, 이미 있는 값은 무조건 유지됩니다. 두 가지 처리 방법:

1. 이미 존재하는 값이 잘못된 경우: 다른 `PostProcessBuild` 콜백이 먼저 `channel`을 기록했는지 확인하세요. 이 콜백의 순서는 `99`이며, 순서 값이 더 작은 콜백이 먼저 실행됩니다. 콜백 순서를 조정하거나 상대 측의 기록 로직을 삭제하세요.
2. 이미 존재하는 값이 올바른 경우: 처리할 필요가 없습니다. 외부 채널 패키징 도구가 기록한 값을 덮어쓰지 않도록 하는 의도된 멱등(idempotent) 동작입니다.

### 3. tvOS / visionOS 빌드가 건너뛰어짐

런타임 레이어는 tvOS/visionOS를 지원하지만(네이티브 호출을 통해 plist를 읽음), 빌드 후 처리는 `BuildTarget.iOS`만 처리합니다. tvOS/visionOS의 경우:

- 내보낸 Xcode 프로젝트의 `Info.plist`에 `channel` 키를 수동으로 추가하거나,
- 자체 빌드 스크립트에서 `BuildTarget.tvOS` 등의 대상에 대해 유사한 plist 기록 로직을 실행하세요.

### 4. 빌드 시 예외가 발생했지만 plist가 기록되지 않음

`OnPostProcessBuild`는 모든 예외를 캐치하여 `Debug.LogException(e)`으로만 출력하므로, 빌드는 실패하지 않고 plist도 기록되지 않습니다. `Run()` 내의 일반적인 트리거 지점:

- `File.ReadAllText(plistPath)`가 `FileNotFoundException`을 발생시킴: `path` 매개변수는 빌드 출력 디렉터리이며, Xcode 프로젝트가 생성되지 않았거나 경로가 잘못됨;
- `plist.ReadFromString`이 파싱 예외를 발생시킴: plist가 다른 도구에 의해 손상됨.

작업: Unity Console에서 `PostProcessBuildHandler` 관련 스택을 검색하고, `path`가 가리키는 빌드 출력 디렉터리를 수정한 후 다시 빌드하세요.

### 5. 기록되는 값이 `default`로 고정됨

```csharp
const string channelKey = "channel";
const string channelValue = "default";
```

Source: [Editor/PostProcessBuildHandler.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Editor/PostProcessBuildHandler.cs#L33-L34)

기록되는 값은 컴파일 시점 상수 `"default"`이며, 현재 채널을 읽지 않습니다. 따라서 이 핸들러의 역할은 **폴백(fallback) 기록**으로, `Info.plist`에 최소한 `channel` 키가 존재하도록 보장하는 것입니다. 실제 채널명은 자체 채널 패키징 프로세스에서 `channel` 키를 기록하거나 덮어써야 합니다. 폴백 로직은 키가 이미 존재하면 능동적으로 양보합니다(단계 2 참조).

## 검증

다음 순서대로 수정이 적용되었는지 확인하세요:

1. Unity 빌드 완료 후 Console에 `配置渠道成功=>default`(또는 `已有渠道,跳过设置=>xxx`)가 나타납니다.
2. 내보낸 Xcode 프로젝트를 열면 `Info.plist`에 다음이 존재합니다:

```xml
<key>channel</key>
<string>default</string>
```

이 키-값 쌍 형식이 런타임 네이티브 인터페이스가 읽는 형식입니다. [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L21-L26)의 주석 설명을 참조하세요.

3. 실기기에서 실행하여 `BlankGetChannel.GetChannelName()`을 호출해 반환값을 검증하세요. iOS에서는 `DllImport("__Internal")`를 통해 네이티브 `getChannelName`을 호출하며, 캐싱이 적용됩니다:

```csharp
#elif UNITY_IOS || UNITY_TVOS || UNITY_VISIONOS
        channelName = getChannelName(channelKey);
#endif
        ChannelCache[channelKey] = channelName;
        return channelName;
```

Source: [Runtime/BlankGetChannel.cs](https://github.com/GameFrameX/com.gameframex.unity.getchannel/blob/main/Runtime/BlankGetChannel.cs#L136-L141)

참고: `GetChannelName(string channelKey = "channel", string defaultValue = "default")`의 기본값 역시 `"default"`이므로, 채널 키 읽기에 실패하면 그대로 `default`를 반환하여 "plist에 기록되지 않음" 현상과 동일하게 보입니다. 먼저 2단계로 plist에서 키가 실제로 존재하는지 확인한 후, 런타임 읽기를 점검하세요.
