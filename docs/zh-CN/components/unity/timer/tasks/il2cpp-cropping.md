# IL2CPP/AOT 构建:防止类型被裁剪

本包针对 IL2CPP/AOT 构建的托管代码剥离(Managed Stripping)内置了双重防护:核心类型(`TimerComponent`、`TimerManager`、`ITimerManager`)全部标注 `[UnityEngine.Scripting.Preserve]`,并额外提供一个 `GameFrameXTimerCroppingHelper` 裁剪辅助类显式引用这些类型。正常引入本包后无需任何额外配置,类型即不会被剥离。

## 前置条件

- 项目已安装本包(`com.gameframex.unity.timer`)。
- 目标平台在 Player Settings 中使用 IL2CPP 脚本后端(本机制对 Mono 后端无副作用,可保留)。

### 2. 确认裁剪辅助类随包构建

包内 `Runtime/GameFrameXTimerCroppingHelper.cs` 是防剥离的第二道防线,类与方法均带 `[Preserve]`,并在 `Start()` 中用 `typeof` 显式引用全部核心类型,给剥离器留下静态引用根:

```csharp
using UnityEngine;
using UnityEngine.Scripting;

namespace GameFrameX.Timer.Runtime
{
    [Preserve]
    public class GameFrameXTimerCroppingHelper : MonoBehaviour
    {
        [Preserve]
        private void Start()
        {
            _ = typeof(TimerComponent);
            _ = typeof(ITimerManager);
            _ = typeof(TimerManager);
        }
    }
}
```

Source: [GameFrameXTimerCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/Runtime/GameFrameXTimerCroppingHelper.cs#L1-L17)

该文件位于包的 `Runtime` 目录,随包自动参与构建,不需要手动挂到场景上。

### 3. 构建并验证

1. 切换到 IL2CPP 后端并执行一次真实平台构建(仅进入 Play 模式验证不了剥离问题)。
2. 在构建产物中确认类型保留,任选其一:
   - 构建报告/剥离日志中搜索 `GameFrameX.Timer`,确认无 "stripped" 相关移除记录;
   - 运行构建包,确认计时器组件能正常初始化并执行 `AddTimer` 类调用。

## 常见变体

- **项目中还有依赖反射的其他类型被剥离**:可在你自己的工程代码里复制上述辅助类模式——新建一个带 `[Preserve]` 的 `MonoBehaviour`,在 `Start()` 中用 `typeof` 引用需要保留的类型。这是 Unity 通用的防裁剪手法,本包的 `GameFrameXTimerCroppingHelper` 就是该模式的现成范例。
- **提升剥离等级后构建失败**:若项目设置了 High/Medium 剥离等级,`[Preserve]` 与 `typeof` 引用根仍然有效,无需为计时器类型单独做任何调整。

## 背景

IL2CPP 的托管代码剥离会移除静态分析中"无人引用"的类型。本包的类型常通过框架反射与自动组件机制加载,静态引用链不完整,容易被误判为可移除。`[Preserve]` 特性直接告知剥离器保留目标,裁剪辅助类再用 `typeof` 提供编译期可见的引用根,两者叠加保证任何剥离等级下类型均被保留。README 中将其列为"IL2CPP 安全——裁剪辅助类防止 AOT 构建中的类型剥离"(见 [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.timer/blob/main/README.zh-CN.md#L35))。
