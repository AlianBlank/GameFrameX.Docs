# 엔티티 계약 검증 실패 시 대처 방법

`EntityContractValidator.Validate<T>()` 가 비어 있지 않은 목록을 반환하거나, 런타임 ORM이 인터페이스 속성 불일치를 보고할 때, 이는 엔티티 클래스가 구현한 인터페이스(예: `IEntity`, `IVersionedEntity`, `IAuditableEntity`)의 계약을 충족하지 못했음을 의미합니다. 이 페이지에서는 오류 메시지에 따라 위치를 파악하고 수정하는 방법을 안내합니다.

## 빠른 진단

| 증상 (`Reason` 텍스트 조각) | 근본 원인 | 해결 방법 |
|------|------|------|
| `Property 'XXX' not found on type 'YYY'` | 엔티티 클래스에 인터페이스가 요구하는 속성이 없음 | 엔티티 클래스에 동일한 이름과 타입의 속성 추가 |
| `Property 'XXX' type mismatch: expected 'A', actual 'B'` | 속성 타입이 인터페이스 선언과 일치하지 않음 | 속성 타입을 인터페이스가 요구하는 타입(또는 nullable 호환 타입)으로 변경 |
| `Property 'XXX' is missing a getter` | 속성이 `set`만 선언되고 `get`(또는 `private get`)이 없음 | public getter 추가 |
| `Property 'XXX' is missing a setter` | 속성에 `get`만 있고 `set`(또는 `private set`)이 없음 | public setter 추가 |
| `Property 'XXX' has multiple declarations on type 'YYY' (possible 'new' keyword shadowing)` | `new` 키워드로 상속받은 인터페이스 속성을 가림 | `new`를 제거하거나 단일 속성으로 병합 |
| `Validate(null)` 호출 시 `ArgumentNullException` 발생 | null인 `Type`을 전달함 | null이 아닌 엔티티 타입 전달 |

## 수정 단계

### 1. 속성 누락

인터페이스가 특정 필드(예: `IVersionedEntity.Version`)를 요구하지만 엔티티 클래스에 선언되어 있지 않은 경우입니다. 엔티티 클래스에 해당 속성을 직접 추가하면 됩니다:

```csharp
using GameFrameX.Foundation.Orm.Entity;

public class Player : IVersionedEntity
{
    public long Version { get; set; } // 인터페이스가 요구하는 속성 추가
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L110-L118)

### 2. 타입 불일치

인터페이스는 `DateTime`으로 선언되어 있는데 엔티티에서는 `DateTimeOffset`이나 `string`으로 작성된 경우입니다. 타입을 인터페이스가 요구하는 타입으로 다시 변경하세요. 인터페이스가 값 타입인 경우, 엔티티는 해당하는 `Nullable<T>`를 사용할 수 있으며, 검증기는 `Nullable.GetUnderlyingType`을 통해 호환성을 판단합니다.

```csharp
public interface IAuditableEntity
{
    DateTime CreatedAt { get; set; }
}

public class Order : IAuditableEntity
{
    public DateTime CreatedAt { get; set; } // 타입이 일치해야 함; DateTime? 도 가능
}
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L148-L164)

### 3. getter / setter 누락

ORM은 보통 양쪽(읽기와 쓰기) 접근자를 모두 필요로 합니다. 접근자를 완성하세요:

```csharp
public DateTime UpdatedAt { get; set; } // get과 set 모두 public이어야 함
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L130-L144)

### 4. `new` 키워드에 의한 가림

기본 클래스에서 상속받은 속성이 `new`로 재선언되어 `GetProperty`가 여러 매칭에 해당하면서 `AmbiguousMatchException`을 발생시킵니다. `new`를 삭제하고 단일 속성으로 병합하세요:

```csharp
// 잘못된 예: new 키워드로 가림
public new long Version { get; set; }

// 올바른 예: 기본 클래스 선언을 그대로 사용
// (전체 new 선언을 삭제하거나, override/명시적 인터페이스 구현 사용)
```

Source: [EntityContractValidator.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Orm.Entity/EntityContractValidator.cs#L100-L108)

### 5. 자동 검증 호출

애플리케이션 시작 시 또는 단위 테스트에서 검증기를 호출하여 위반 항목을 한 번에 출력하세요:

```csharp
using GameFrameX.Foundation.Orm.Entity;

var violations = EntityContractValidator.Validate<Player>();
foreach (var v in violations)
{
    Console.WriteLine($"{v.InterfaceType.Name}.{v.PropertyName}: {v.Reason}");
}
```

반환되는 `EntityContractViolation`은 세 개의 필드를 포함합니다: `InterfaceType`, `PropertyName`, `Reason`.

## 검증

수정 후 `Validate<T>()`를 다시 호출하세요:

- 반환된 `IList<EntityContractViolation>`의 길이가 0이면, 모든 계약이 충족된 것입니다.
- 여전히 비어 있지 않은 항목이 반환되면, 위의 진단 표를 참조하여 `Reason`을 기준으로 계속 수정한 후 목록이 비워질 때까지 진행하세요.

## 검증기가 검사하지 않는 항목

`EntityContractValidator`는 인터페이스에 명시적으로 선언된 속성만 검증합니다:

- 인터페이스가 다른 인터페이스로부터 상속받은 속성은 `Type.GetInterfaces()`와 함께 검증 대상에 포함됩니다.
- 필드(`public int Foo;`), 정적 멤버, 비공개 멤버는 검사되지 않습니다.
- 인터페이스 자체에서 속성 구문으로 선언된 멤버만 검증되며, 메서드로 표현된 계약은 검증 범위에 포함되지 않습니다.
