# Using Object Pool to Reuse Game Objects

The Object Pool is used to reuse game objects of the `ObjectBase` type. Use `Spawn` to acquire and `Unspawn` to recycle, avoiding the GC and instantiation overhead from repeated `Instantiate`/`Destroy` calls. The framework provides `IObjectPool<T>`, `IObjectPoolManager`, `ObjectPoolComponent`, and other entry points under the `GameFrameX.ObjectPool` namespace.

## Prerequisites

- `ObjectPoolComponent` is attached (menu `GameFrameX/Object Pool`). The framework automatically initializes the `IObjectPoolManager` module on startup.
- Business objects must inherit from `ObjectBase` and implement its abstract methods.
- Namespaces: `GameFrameX.ObjectPool`, `GameFrameX.Runtime`.

## Steps

### 1. Define the Pooled Object Type

Make the business class inherit from `ObjectBase` and override the three lifecycle hooks: `Spawn`/`Unspawn`/`Release`:

```csharp
using GameFrameX.ObjectPool;
using UnityEngine;

public class Bullet : ObjectBase
{
    public float Speed { get; set; }

    // Called when the object is taken from the pool
    protected override void OnSpawn()
    {
        gameObject.SetActive(true);
    }

    // Called when the object is returned to the pool
    protected override void OnUnspawn()
    {
        gameObject.SetActive(false);
    }

    // Called when the object is actually destroyed
    protected override void OnRelease()
    {
        Object.Destroy(gameObject);
    }
}
```

### 2. Create the Object Pool

Create the pool through `ObjectPoolComponent`. `SingleSpawn` means the same object cannot be taken out concurrently multiple times, while `MultiSpawn` allows it. `name` is optional, `capacity` controls the pool capacity, and `expireTime` sets the object expiration in seconds.

```csharp
using GameFrameX.Runtime;
using GameFrameX.ObjectPool;
using UnityEngine;

public class BulletSpawner : MonoBehaviour
{
    [SerializeField] private ObjectPoolComponent poolComponent;
    [SerializeField] private Bullet bulletPrefab;

    private IObjectPool<Bullet> _bulletPool;

    private void Start()
    {
        // Create a pool that allows single acquisition, capacity 32
        _bulletPool = poolComponent.CreateSingleSpawnObjectPool<Bullet>(
            name: "BulletPool",
            capacity: 32,
            expireTime: 60f);
    }

    public Bullet SpawnBullet(Vector3 pos)
    {
        var bullet = _bulletPool.Spawn();
        if (bullet == null)
        {
            bullet = Object.Instantiate(bulletPrefab, pos, Quaternion.identity);
            bullet.Speed = 10f;
            // Register the object into the pool, spawned=true indicates it is immediately in the acquired state
            _bulletPool.Register(bullet, spawned: true);
        }
        bullet.transform.position = pos;
        return bullet;
    }

    public void DespawnBullet(Bullet bullet)
    {
        _bulletPool.Unspawn(bullet);
    }
}
```

### 3. Recycle and Release

`Unspawn` returns the object to the pool, `ReleaseObject` destroys a single object completely, `Release()` releases all releasable objects (commonly used for periodic cleanup of expired objects). `SetLocked(obj, true)` will make the object skip automatic release.

```csharp
// Return
bulletPool.Unspawn(bullet);

// Destroy a single object completely
bulletPool.ReleaseObject(bullet);

// Immediately clean up all releasable objects
bulletPool.Release();

// Batch filter release
bulletPool.Release(10, (target, bullet) => bullet.Speed <= 0);
```

### 4. Query Pools via the Manager

`IObjectPoolManager` exposes interfaces for querying by type, by name, and by condition, suitable for debug panels or cross-module sharing:

```csharp
IObjectPoolManager mgr = GameFrameX.Runtime.GameFrameworkEntry.GetModule<IObjectPoolManager>();
if (mgr.HasObjectPool<Bullet>("BulletPool"))
{
    var pool = mgr.GetObjectPool<Bullet>("BulletPool");
    Debug.Log($"Pool object count: {pool.Count}, releasable: {pool.CanReleaseCount}");
}
```

## Common Variants

| Scenario | Recommended API | Description |
|------|----------|------|
| Same object allows only one user | `CreateSingleSpawnObjectPool` | Default mode, suitable for effects, temporary UI |
| Same object can be shared by multiple places | `CreateMultiSpawnObjectPool` | Suitable for materials, textures, handle-type objects |
| Dual lookup by type and name | `GetObjectPool<T>(name)` | Multiple pools of the same type (e.g., different levels) |
| Iterate all pools during debugging | `GetAllObjectPools(sort: true)` | Returns sorted by `Priority` |

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| `Spawn()` keeps returning `null` | Pool is empty and `Register` was not called to inject initial objects | When `Spawn()` returns `null`, instantiate the object and call `pool.Register(obj, spawned: true)` |
| Objects repeatedly leak | Business side does not call `Unspawn`, or type mismatch during `Unspawn` | Explicitly call `Unspawn` at the end of use, and verify the object type |
| Unable to continue Spawn after capacity limit | Pool reached `Capacity` limit and does not allow multiple acquisitions | Adjust `Capacity`, or switch to `CreateMultiSpawnObjectPool` |
| Automatic release clears objects still in use | `SetLocked(obj, true)` was not set | Call `SetLocked` to lock the object before use |

## Background (Optional)

The framework abstracts objects as `ObjectBase` (`[IReference]`), driving the lifecycle through four actions: `Register/Spawn/Unspawn/Release`. Each object pool independently maintains `Capacity` (capacity limit), `ExpireTime` (expiration in seconds), `AutoReleaseInterval` (auto-release interval), and `Priority` (sort weight). `ObjectPoolComponent` is the Unity-side entry point, internally delegating to `ObjectPoolManager` to implement specific pool creation, query, and release strategies. For the overall component registration flow, see "Object Pool Component Initialization".
