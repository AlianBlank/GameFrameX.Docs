# GameFrameX Startup 패키지 설치 및 설정

이 가이드는 GameFrameX Startup 패키지를 Unity 프로젝트에 연동하고, 최초 실행에 필요한 최소한의 설정을 완료하는 방법을 안내합니다: scoped registry 선언, `StartupOptions` 에셋 생성, UI 및 핫픽스 주입 인터페이스 구현. 완료 후 `await StartupRunner.Run(...)`을 호출하여 전체 시작 프로세스를 실행할 수 있습니다.

## 사전 조건

- Unity 2019.4 이상 버전 ([package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L7) `unity` 필드 참조)
- 프로젝트에 UniTask 등 GameFrameX 시리즈 의존성이 활성화되어 있어야 함 (동일 저장소의 npm 레지스트리를 통해 자동으로 해석되므로 수동 선언 불필요)
- 네트워크에서 GameFrameX 비공개 npm 레지스트리 `https://gameframex.upm.alianblank.uk`에 접근 가능해야 함

## 작업 단계

### 1. manifest.json에 패키지 및 scoped registry 추가

프로젝트의 `Packages/manifest.json`을 열고, 패키지 의존성과 scoped 레지스트리를 모두 추가합니다 (`scopes`를 `com.gameframex`로 한정해야 이 레지스트리를 사용합니다):

```json
{
  "dependencies": {
    "com.gameframex.unity.startup": "1.1.0"
  },
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ]
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L22-L37)

저장하면 Unity Package Manager가 `package.json`에 나열된 모든 의존성을 자동으로 가져옵니다 ([package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L28-L40)).

### 2. StartupOptions 설정 에셋 생성

Unity Editor에서 `Assets > Create > GameFrameX > Startup Options`를 선택하여 `StartupOptions` ScriptableObject 에셋을 생성합니다.

최소한으로 입력해야 하는 필드:

| 필드 | 의미 |
|------|------|
| `GlobalInfoUrls` | 전역 정보 인터페이스의 기본/백업 URL 목록 (순서대로 failover) |
| `GamePlayMode` | 리소스 실행 모드 (시작 프로세스가 리소스 로드 전에 Asset 컴포넌트에 동기화) |
| `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` | 핫픽스 진입점 어셈블리 / 타입 / 메서드 |
| `PackageName` / `Channel` / `SubChannel` | HTTP 공통 파라미터 |
| `LauncherUIResName` | 시작 UI 리소스 경로 (기본값 `UI/UILauncher`) |
| `SkipRemoteStartupRequests` | true인 경우 모든 원격 시작 요청(전역 정보 / App 버전 / 리소스 패키지 버전)을 건너뜀, WebGL 스탠드얼론 또는 백엔드 없는 배포에 적합 |

필드 정의 및 설명은 [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L1-L120)를 참조하세요.

### 3. UI 핸들러 구현 (IStartupUIHandler)

UI 백엔드와 무관하며 FairyGUI / UGUI / 커스텀 구현을 사용할 수 있습니다. 다음 멤버를 구현해야 합니다:

```csharp
public class GameStartupUIHandler : IStartupUIHandler
{
    public UniTask StartAsync(string uiResName) { /* UI 로드 */ }
    public void SetTipText(string text) { /* 안내 텍스트 업데이트 */ }
    public void SetProgress(float progress, string sizeInfo) { /* 진행률 표시줄 업데이트 */ }
    public void SetProgressUpdateFinish() { /* 완료 표시 */ }
    public void Dispose() { /* UI 닫기, 구독 해제 */ }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L57-L65)

### 4. 핫픽스 런처 구현 (IHotfixLauncher)

핫픽스 솔루션과 무관하며 HybridCLR 또는 기타 솔루션과 호환됩니다. `options`에 제공된 어셈블리 / 타입 / 메서드 이름에 따라 로드하고 호출합니다:

```csharp
public class HybridClrHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        // options.HotfixAssemblyName에 따라 핫픽스 어셈블리 로드
        // options.HotfixEntryTypeName.options.HotfixEntryMethodName 호출
        return HotfixLaunchResult.Succeed();
    }
}
```

출처: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L70-L78)

### 5. 시작 실행

게임 진입 스크립트에서 `StartupRunner.Run(options, uiHandler, hotfixLauncher)`를 호출하고, 반환된 `UniTask<StartupResult>`를 기다리거나 `StartupCompleted` / `FailedEventArgs` 이벤트를 구독하면 됩니다.

진입점 위치는 [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L1-L80)를 참조하세요.

## 일반적인 변형

- **WebGL / 스탠드얼론 배포**: `SkipRemoteStartupRequests`를 `true`로 설정하면 전역 정보 / App 버전 / 리소스 패키지 버전 세 가지 원격 요청을 건너뛸 수 있습니다.
- **PlayMode 전환**: 대상 플랫폼에 따라 `StartupOptions.GamePlayMode`에서 `EditorSimulateMode` / `OfflinePlayMode` / `HostPlayMode` / `WebPlayMode`를 선택하면, 시작 프로세스가 자동으로 분기 처리합니다.
- **비공개 npm 레지스트리**: 패키지의 `publishConfig.registry`는 `https://npm.cnb.cool/GameFrameX/npm/-/packages/`를 가리킵니다 ([package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L41-L44) 참조). 자체 게시 파이프라인을 구축할 필요가 있을 때만 참고하면 됩니다.

## 일반적인 오류

| 증상 | 가능한 원인 | 해결 방법 |
|------|----------|------|
| Package Manager에서 `com.gameframex.unity.startup`를 찾을 수 없음 | `scopedRegistries`가 선언되지 않았거나 `scopes`가 잘못 작성됨 | `scopes`에 `com.gameframex`가 포함되어 있고 URL이 `https://gameframex.upm.alianblank.uk`인지 확인 |
| 시작이 "전역 정보 가져오기" 단계에서 멈춤 | `GlobalInfoUrls`가 모두 실패하고 `MaxAttemptsPerUrl`이 소진됨 | URL 접근 가능 여부 확인, 필요시 재시도 횟수 증가 |
| 핫픽스 진입점이 트리거되지 않음 | `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`이 실제 어셈블리와 일치하지 않음 | 세 값 모두 핫픽스 DLL의 네임스페이스.클래스.메서드 이름과 완전히 일치해야 함 |
| WebGL 배포에서 백엔드 요청 실패 | `SkipRemoteStartupRequests`가 활성화되지 않음 | 스탠드얼론 배포 시나리오에서는 `true`로 설정 |

## 배경

패키지 이름은 `com.gameframex.unity.startup`이며, 현재 버전은 1.4.3입니다 ([package.json](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/package.json#L1-L6)). 설계 방침: 변경 가능한 항목을 `StartupOptions` 에셋과 두 개의 인터페이스(`IStartupUIHandler` / `IHotfixLauncher`)에 집중시켜, 비즈니스 프로젝트는 UI와 핫픽스 양측의 주입만 구현하면 됩니다.
