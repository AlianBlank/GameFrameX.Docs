# Add Proto Protocol and Integrate MessageProtoHandler

After adding a new `.proto` file to the `GameFrameX.Proto` project, as long as the `MessageProtoHandler` class is hosted in that assembly, the launcher will automatically scan and register all protocol message types during initialization—no hand-written registration code is needed.

## Prerequisites

- The `GameFrameX.Proto` project already exists in the solution and references the `GameFrameX.NetWork 1.13.0` package, which is used for encoding/decoding and dispatching protocol messages.
- The target framework is `net10.0` (`LangVersion=10`).
- Business modules (e.g., `GameFrameX.Apps`) reference `GameFrameX.Proto` via `ProjectReference` so that the generated protocol types are visible at compile time.

## Steps

1. Create a `.proto` file under the `GameFrameX.Proto/Proto/` directory to define messages and services. For example, create `GameFrameX.Proto/Proto/Helloworld.proto`:

   ```protobuf
   syntax = "proto3";

   option csharp_namespace = "GameFrameX.Proto";

   package helloworld;

   // Request message
   message HelloRequest
   {
       string name = 1;
   }

   // Response message
   message HelloReply
   {
       string message = 1;
   }

   service Greeter
   {
       rpc SayHello (HelloRequest) returns (HelloReply);
   }
   ```

   The file is placed directly under the `Proto` folder, which has been declared as a reserved directory by the csproj; neither the IDE nor MSBuild will compile it as code.

   Source: [GameFrameX.Proto/GameFrameX.Proto.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/GameFrameX.Proto.csproj#L12-L14)

2. Confirm that the `MessageProtoHandler` class is located within the `GameFrameX.Proto` assembly. This class is an empty shell static class that serves as a "protocol handler anchor", allowing the subsequent initialization code to reflect over its `Assembly` to discover all protocol message types in the current assembly:

   ```csharp
   namespace GameFrameX.Proto;

   /// <summary>
   /// Protocol message handler
   /// </summary>
   public static class MessageProtoHandler
   {
   }
   ```

   Source: [GameFrameX.Proto/MessageProtoHandler.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Proto/MessageProtoHandler.cs#L1-L8)

3. In the startup entry point (currently `GameFrameX.Launcher/Program.cs`), call `MessageProtoHelper.Init` once, passing in the assembly where `MessageProtoHandler` resides, to complete the registration of all `proto` message types:

   ```csharp
   MessageProtoHelper.Init(typeof(MessageProtoHandler).Assembly);
   ```

   Source: [GameFrameX.Launcher/Program.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Launcher/Program.cs#L14-L15)

4. Add a project reference in the downstream project that needs to consume the protocol types, making the generated code visible to callers:

   ```xml
   <ProjectReference Include="..\GameFrameX.Proto\GameFrameX.Proto.csproj" />
   ```

   Source: [GameFrameX.Apps/GameFrameX.Apps.csproj](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Apps/GameFrameX.Apps.csproj#L10-L10)

5. Build and launch the Launcher. The new `.proto` message types added to the assembly containing `MessageProtoHandler` will be automatically registered into the message dispatch pipeline.

## Common Variants

- **Multiple `.proto` files**: Simply place multiple `.proto` files side by side under `GameFrameX.Proto/Proto/`; `MessageProtoHelper.Init` will scan the entire assembly in one pass.
- **Switching the C# namespace**: Use `option csharp_namespace = "Your.Namespace";` at the top of each `.proto` file to control the namespace of the generated code, decoupling it from `GameFrameX.Proto` where `MessageProtoHandler` resides.
- **Not starting in the Launcher**: As long as the caller can access `GameFrameX.NetWork.MessageProtoHelper.Init`, passing in the assembly containing `MessageProtoHandler` completes the registration, regardless of the startup project.

## Common Mistakes

- **Placing `.proto` in the project root instead of the `Proto` folder**: Although the csproj does not explicitly exclude it, the `Proto` folder is a reserved directory; placing files in a shallower location makes them prone to being incorrectly processed by the default `*.proto` rules when a code generator is integrated later.
- **Forgetting `MessageProtoHelper.Init`**: Without calling `Init`, new protocols will not be registered, and the runtime will fail to find message type handlers.
- **Downstream project does not reference `GameFrameX.Proto`**: Even if registration succeeds, callers cannot access the generated message types, resulting in a "type not found" compile-time error.
- **Renaming the `MessageProtoHandler` class or having the class outside the Proto assembly**: `typeof(MessageProtoHandler).Assembly` will point to the wrong assembly, and new protocols will not be discovered.

## Background

The `MessageProtoHelper.Init(Assembly)` in the `GameFrameX.NetWork` package uses reflection to scan the C# message types generated from `.proto` files in the passed-in assembly and completes their registration. `MessageProtoHandler` is a placeholder static class in `GameFrameX.Proto`; its only "purpose" is to give the launcher a stable type to locate the `GameFrameX.Proto` assembly—this avoids hardcoding the assembly name.
