# 快速上手:安装并启动第一个协程

本指南带你把 GameFrameX 协程包接入 Unity 工程,并跑通"启动→停止→帧尾回调"三个最常用的接口。本组件是对 Unity 原生协程的薄封装,会在内部以 `ConcurrentDictionary` 跟踪所有启动过的协程,避免漏停导致的悬挂引用。

## 前置条件

- Unity 2017.1 或更高版本(测试目标为 Unity 2019.4)
- 一个能正常打开的 Unity 项目
- 项目里已安装 `com.gameframex.unity.runtime`(本组件继承自其 `GameFrameworkComponent`)

## 安装

选择以下任一方式把包加入项目:

1. **通过 Scoped Registry(推荐)** —— 编辑 `Packages/manifest.json`,在 `scopedRegistries` 中添加 GameFrameX 注册表,并声明依赖:

   ```json
   {
     "scopedRegistries": [
       {
         "name": "GameFrameX",
         "url": "https://gameframex.upm.alianblank.uk",
         "scopes": ["com.gameframex"]
       }
     ],
     "dependencies": {
       "com.gameframex.unity.coroutine": "1.0.3"
     }
   }
   ```

2. **通过 Git URL** —— 在 `dependencies` 下直接写:

   ```json
   "com.gameframex.unity.coroutine": "https://github.com/gameframex/com.gameframex.unity.coroutine.git"
   ```

3. **通过 Package Manager** —— 使用 `Add package from Git URL`,填入上面的仓库地址。

4. **手动放置** —— 把整个仓库复制到项目的 `Packages/` 目录下,Unity 会自动识别。

## 操作步骤

1. **拿到 CoroutineComponent 实例。** 由于该组件带 `[DisallowMultipleComponent]` 与 `[GameFrameXAutoComponent(-6500)]` 特性,通常由 GameFrameX 框架自动注册到一个挂载了 `GameFrameworkEntry` 的 GameObject 上。手动方式如下:

   ```csharp
   var coroutineComponent = gameObject.AddComponent<GameFrameX.Coroutine.Runtime.CoroutineComponent>();
   ```

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L12-L21)

2. **编写协程方法。** 协程签名必须是返回 `IEnumerator`,内部用 `yield return` 控制节奏:

   ```csharp
   IEnumerator HelloCoroutine()
   {
       Debug.Log("Hello");
       yield return null;            // 等一帧
       Debug.Log("Next frame");
   }
   ```

3. **启动协程。** 调用 `StartCoroutine` 并保存返回的迭代器实例,以便后续停止:

   ```csharp
   IEnumerator routine = HelloCoroutine();
   coroutineComponent.StartCoroutine(routine);
   ```

   注意:必须通过 `CoroutineComponent` 类型引用调用 `StartCoroutine`,因为它用 `new` 关键字隐藏了基类方法,以保证写入跟踪字典。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L28-L33)

4. **停止单个协程(可选)。** 把启动时保存的同一个 `IEnumerator` 实例传回去:

   ```csharp
   coroutineComponent.StopCoroutine(routine);
   ```

   该重载会先在字典里查表找到对应的 `UnityEngine.Coroutine`,停止后再从字典移除;若找不到则回退到 `base.StopCoroutine(enumerator)`。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L39-L50)

5. **停止全部协程(可选)。** 在切场景或重置逻辑时调用:

   ```csharp
   coroutineComponent.StopAllCoroutines();
   ```

   实现会先逐个停止字典里跟踪的协程、清空字典,再调用 `base.StopAllCoroutines()` 兜底清理未跟踪的协程。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L72-L82)

6. **帧尾回调(可选)。** 当你需要在当前帧所有渲染完成后做点事情(例如截图、上报),使用:

   ```csharp
   coroutineComponent.WaitForEndOfFrameFinish(() =>
   {
       Debug.Log("End of frame");
   });
   ```

   内部复用了一个复用的 `WaitForEndOfFrame` 一次性对象,避免每次调用产生 GC 分配。

   Source: [CoroutineComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.coroutine/blob/main/Runtime/Coroutine/CoroutineComponent.cs#L84-L104)

## 常见变体

- **通过 `UnityEngine.Coroutine` 重载停止**:当只持有 Unity 返回的协程句柄时,使用 `StopCoroutine(UnityEngine.Coroutine coroutine)` 重载,内部会反向遍历字典找到对应迭代器并清理。
- **不要在 `WaitForEndOfFrameFinish` 回调里抛异常**:若在帧结束前通过 `StopCoroutine` 停止了该协程,回调将不会执行,无需再做防御性判空。

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| `StartCoroutine` 后字典里查不到 | 调到了 `MonoBehaviour.StartCoroutine` 而不是 `CoroutineComponent.StartCoroutine` | 始终通过 `CoroutineComponent` 类型的引用调用,确保走的是 `new` 隐藏版本 |
| `StopCoroutine` 无效 | 传入了一个**重新构造**的 `IEnumerator`(例如再次调用 `HelloCoroutine()`) | 复用启动时保存的同一个 `IEnumerator` 实例,因为字典以引用相等性为 key |
| `StopAllCoroutines` 后仍有协程在跑 | 调用的是普通 `MonoBehaviour.StopAllCoroutines()` | 调用 `CoroutineComponent.StopAllCoroutines()`,确保跟踪字典一并清空 |
| 帧尾回调没触发 | 在回调应执行前调用了 `StopCoroutine`/`StopAllCoroutines` | 把回调里要做的逻辑放到下一帧,或等待 `yield return new WaitForEndOfFrame()` 后再判断 |
