# オブジェクトプールの容量と回収戦略の調整方法

UI フレームワークは UI インスタンスを `IObjectPoolManager` に管理を任せており、`UIComponent` 上のいくつかのフィールドを通じて、容量、自動回収/解放間隔、有効期限を調整できます。このページの設定が完了すると、UI インスタンスのオブジェクトプールが何個の UI をキャッシュできるか、どのくらいの間隔で回収をスキャンするかを制御できるようになります。

## 前提条件

- プロジェクトに `GameFrameX.ObjectPool` が統合済みであること(`UIComponent.cs` の 33 行目 `using GameFrameX.ObjectPool;`)。
- シーンに `UIComponent` をアタッチした GameObject が存在し、`m_UIManager.SetObjectPoolManager(...)` の注入が完了していること(`UIComponent.cs` の 504 行目 `SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>())`)。
- UI コンポーネントとオブジェクトプールマネージャーの全体構成については、『UI モジュールの初期化方法』を参照してください。

## 操作手順

1. **Inspector で容量と戦略フィールドを調整する**。`UIComponent` がアタッチされた GameObject を選択すると、Inspector で以下のシリアライズフィールドを直接確認し、デフォルト値を変更できます:

| フィールド名 | デフォルト値 | 説明 |
|--------|--------|------|
| `m_InstanceCapacity` | `16` | UI インスタンスオブジェクトプールの容量上限 |
| `m_InstanceExpireTime` | `60` 秒 | プール内のオブジェクトがこの秒数を超えてアイドル状態になると解放可能とみなされる |
| `m_InstanceAutoReleaseInterval` | `60` 秒 | 自動スキャン/解放の間隔 |
| `m_RecycleInterval` | `60` 秒 | 回収可能なオブジェクトを自動回収する間隔 |
| `m_EnableAutoReleaseUIForm` | `false` | 自動回収を有効にするかどうか |

フィールド定義の例：

```csharp
[SerializeField] private float m_InstanceAutoReleaseInterval = 60f;
[SerializeField] private int   m_InstanceCapacity          = 16;
[SerializeField] private float m_InstanceExpireTime        = 60f;
[SerializeField] private int   m_RecycleInterval           = 60;
[SerializeField] private bool  m_EnableAutoReleaseUIForm   = false;
```

出典： [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L107-L141)

2. **実行時にプロパティ経由で動的に調整する**。`UIComponent` は上記のフィールドをパブリックプロパティとして公開しており、実行時に値を変更すると、シリアライズフィールドへの書き戻しと `m_UIManager` への反映が同時に行われます:

```csharp
// 容量、有効期限、自動解放/回収間隔を調整
uiComponent.InstanceCapacity           = 32;   // 容量
uiComponent.InstanceExpireTime         = 120f; // 有効期限(秒)
uiComponent.InstanceAutoReleaseInterval = 30f; // 自動解放間隔
uiComponent.RecycleInterval            = 30;  // 回収間隔
uiComponent.EnableAutoReleaseUIForm    = true; // 自動回収を有効化
```

プロパティの実装：

```csharp
public int   InstanceCapacity            { get => m_UIManager.InstanceCapacity;             set => m_UIManager.InstanceCapacity            = m_InstanceCapacity            = value; }
public float InstanceExpireTime          { get => m_UIManager.InstanceExpireTime;           set => m_UIManager.InstanceExpireTime          = m_InstanceExpireTime          = value; }
public float InstanceAutoReleaseInterval { get => m_UIManager.InstanceAutoReleaseInterval;  set => m_UIManager.InstanceAutoReleaseInterval = m_InstanceAutoReleaseInterval = value; }
public int   RecycleInterval             { get => m_UIManager.RecycleInterval;              set => m_UIManager.RecycleInterval             = m_RecycleInterval             = value; }
public bool  EnableAutoReleaseUIForm     { get => m_EnableAutoReleaseUIForm;                set => m_EnableAutoReleaseUIForm = value; }
```

出典： [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L322-L359)

3. **自動回収スイッチをオフにする(任意)**。回収を手動で制御したい場合は、`EnableAutoReleaseUIForm` を `false` に設定します。これによりタイマーは自動スキャンを発動しなくなり、`CloseUIForm` を明示的に呼び出したときにのみインスタンスがプールに返却されます。

4. **保存して検証する**。シーンを再起動するか Play Mode に入り直し、Inspector でフィールド値が反映されていることを確認します。Profiler で `UI Form Instance Pool` の容量を観察し、`InstanceCapacity` を超えていないことを確認します。

## よくあるバリエーション

- **段階的にチューニング**:リリース前にエディターで `m_InstanceCapacity` を大きく(例： 32)設定してストレステストのピークに備え、正式パッケージでは `InstanceCapacity` を動的に下げて常駐メモリを削減します。
- **頻繁に開閉される高頻度 UI**(例： Toast、Tips):`InstanceExpireTime` を小さく(例： 10 秒)設定し、アイドル状態のオブジェクトをできるだけ早く解放させ、プール容量の占有を避けます。
- **重量級 UI**(キャラクターパネル、ショップ):`m_InstanceCapacity` を 1~2 に調整し、`InstanceExpireTime` を大きく(例： 300 秒)設定して、再利用のためのキャッシュを保持します。
- **自動回収を完全に無効化**:`m_EnableAutoReleaseUIForm = false` とし、回収のタイミングをゲームロジック側で自由に決定します(カットシーン中によく使用されます)。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| フィールドを変更しても反映されない | 実行時にプロパティのみを変更して `m_UIManager` に書き戻されていない、または `EnableAutoReleaseUIForm` が有効になっていない | `m_EnableAutoReleaseUIForm = true` を確認し、フィールドではなくプロパティ経由で代入する |
| プールのオブジェクトがすぐに空になり、UI の表示が遅い | `InstanceExpireTime` または `InstanceAutoReleaseInterval` が小さすぎる | `InstanceExpireTime` を 60 秒以上、`InstanceAutoReleaseInterval` を 30 秒以上に調整する |
| メモリが継続的に増加する | `InstanceCapacity` が大きすぎ、かつ `InstanceExpireTime` が長すぎる | `InstanceCapacity` を小さくし、`InstanceExpireTime` を短くする |
| 頻繁な GC | `RecycleInterval` が小さすぎて、タイマーが繰り返し発動する | `RecycleInterval` を 30~60 秒に調整する |

## 背景(任意)

`UIComponent` 内部では、設定を `m_UIManager` とシリアライズフィールドの両方に同時に反映しており、実行時の変更が Editor でもシリアライズされて保持されることを目的としています。`IObjectPoolManager` がオブジェクトプールの具体的な戦略(期限切れ回収、定時解放)を担当し、UI モジュールはパラメータの受け渡しとスイッチのみを担当します。`m_InstancePriority` のような非公開フィールドを変更しても反映されません。
