# 生成失败/报错怎么办

执行 `gen-*.bat` / `gen-*.sh` 后 Luban 抛出异常或没有产出文件时,按本页诊断表逐项排查。问题多集中在脚本路径、配置占位符、Excel 表结构三类。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `Could not find a part of the path ... Tools/Luban.dll` | 工具目录缺失或路径写错 | 在仓库根下创建 `Tools/` 并放入 `Luban.dll`,或修正 `luban.conf` 的 `toolPath` |
| `luban.conf not found` / `conf not loaded` | 当前目录不对,脚本没切到仓库根 | 在 `Tools/` 同级目录运行脚本,或让脚本 `cd` 到配置所在目录 |
| 占位符 `%UNITY_ASSETS_PATH%` / `%SERVER_PATH%` 没有展开 | `luban.conf` 中两个键为空字符串 | 在 `luban.conf` 里把 `UNITY_ASSETS_PATH` 与 `SERVER_PATH` 替换为绝对路径 |
| 报 `Excel ... __tables__.xlsx` 解析失败 | 模板表头被改坏、列缺失或多表合并出错 | 还原 `Excels/__tables__.xlsx`、`__beans__.xlsx`、`__enums__.xlsx`,不要手动删列 |
| 报 `Localization.xlsx not found` | 客户端生成时本地化文件改名/缺失 | 命令里的 `localizationFileName` 默认是 `Localization.xlsx`,需要时改为仓库实际文件名 |
| 命令一闪而过,看不到报错 | 末尾缺 `pause`(Windows) | 确认 `gen-*.bat` 最后一行是 `pause`(参考已有脚本) |
| 只生成了代码,没生成数据 | `dataTarget` 与 `codeTarget` 不匹配,或 `outputDataDir` 路径无效 | 同时设置 `--dataTarget` 与 `--codeTarget`,并核对 `outputDataDir` 是否可写 |
| 报 `validation failed` | 配了 `--validationFailAsError true`,数据未通过校验 | 临时去掉 `--validationFailAsError true` 看具体警告,修数据后再打开 |

## 修复步骤

### 1. 找不到 Luban.dll

打开 `luban.conf`,查看 `toolPath` 字段:

```json
"toolPath": "/../Config/Tools/Luban.dll",
```

脚本实际是这样调用的:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf
```

Source: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L2)

两处必须保持一致:脚本里写 `./Tools/Luban.dll`,仓库里就要存在 `Tools/Luban.dll`。如果你的工程把工具放在 `Config/Tools/` 下,把 `toolPath` 与脚本路径同步改过去。

### 2. 占位符没展开

`luban.conf` 中默认给的是空字符串:

```json
"UNITY_ASSETS_PATH": "",
"SERVER_PATH": "",
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L62-L65)

`commands` 里的命令会引用这两个变量,例如:

```json
"command": "--target server --dataTarget json --codeTarget cs-dotnet-json --xargs outputDataDir=%SERVER_PATH%/Server.Config/Json  --xargs outputCodeDir=%SERVER_PATH%/Server.Config/Config"
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L66-L78)

直接执行脚本时这些 `%XXX%` 不会被展开,会在文件系统层报"路径不存在"。把它们替换成你机器上的绝对路径后再生成。

### 3. Excel 模板被破坏

`luban.conf` 通过 `schemaFiles` 声明四份元数据表:

```json
"schemaFiles": [
    { "fileName": "Defines", "type": "" },
    { "fileName": "Excels/__tables__.xlsx", "type": "table" },
    { "fileName": "Excels/__beans__.xlsx", "type": "bean" },
    { "fileName": "Excels/__enums__.xlsx", "type": "enum" }
]
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L16-L33)

报错里只要提到这四个文件,优先从仓库还原它们,再检查 `Excels/Tables/` 与 `Excels/Local/` 下业务表的列名是否和 `__tables__.xlsx` 里的字段一一对应。

### 4. 客户端生成时本地化表找不到

客户端命令带了一个独立的 `localizationFileName`,默认期望文件叫 `Localization.xlsx`:

```json
{
    "localizationFileName": "Localization.xlsx",
    "command": "--target client --dataTarget json --codeTarget cs-simple-json --xargs outputDataDir=%UNITY_ASSETS_PATH%/Bundles/Config  --xargs outputCodeDir=%UNITY_ASSETS_PATH%/Hotfix/Config/Generate ",
    "target": "client",
    "active": true
}
```

Source: [luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L72-L77)

如果你的本地化表改名了(比如仓库里只有 `L-Localization-UI.xlsx`、`L-Localization-成就.xlsx`、`L-Localization-文本.xlsx`),把 `localizationFileName` 改成实际文件名,或者把表名改回 `Localization.xlsx`。

### 5. 脚本一闪而过看不到报错

Windows 下的 `gen-*.bat` 都应该在末尾加 `pause`:

```bat
dotnet.exe ./Tools/Luban.dll ... --conf ./Luban.conf

pause
```

Source: [gen-client-json.bat](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-client-json.bat#L1-L3)

如果你的脚本去掉了 `pause`,报错会被关掉的窗口带走,看不出原因。加上 `pause` 之后重新执行即可。

### 6. 服务端二进制生成失败

仓库提供的服务端 bin 生成脚本是这样:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget bin --codeTarget cs-dotnet-bin --xargs outputDataDir=../Server/GameFrameX.Config/Json --xargs tableImporter.name=gameframex --xargs outputCodeDir=../Server/GameFrameX.Config/Config --conf ./Luban.conf
pause
```

Source: [gen-server-bin.sh](https://github.com/GameFrameX/GameFrameX.Config/blob/main/gen-server-bin.sh#L1-L2)

注意这里写的是 `gen-server-bin.sh` 但内容是 Windows 风格的 `dotnet ... && pause`,而且依赖相对路径 `../Server/GameFrameX.Config/`。报错为路径相关时,确认:
- `Server/GameFrameX.Config/Json` 与 `Server/GameFrameX.Config/Config` 两个目录存在或可写;
- 是在仓库根目录执行的脚本,而不是从别的目录 `sh ./gen-server-bin.sh`。

## 验证

按上面修完后,跑一个最小命令确认链路通:

```bash
dotnet ./Tools/Luban.dll --target server --dataTarget json --codeTarget cs-dotnet-json \
  --xargs outputDataDir=./out/Json \
  --xargs outputCodeDir=./out/Config \
  --conf ./Luban.conf
```

成功后:
- `./out/Config/` 下应有 `TablesComponent.cs` 等生成代码;
- `./out/Json/` 下应有 `Tb*.json` 数据文件;
- 终端没有异常堆栈。

再把对应平台脚本(`gen-server-json.bat` / `gen-client-json.sh` 等)跑一遍,确认业务端到端可用。
