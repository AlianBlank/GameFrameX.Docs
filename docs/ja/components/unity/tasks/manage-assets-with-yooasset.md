# AssetBundle と YooAsset リソース読み込みの使用方法

このドキュメントでは、GameFrameX.Unity プロジェクトで YooAsset を通じてリソースのパッケージング、設定、読み込みを行う手順を説明します:パッケージング対象のリソースを `Assets/Bundles` の対応分组目录に配置し、`YooAssetSettings` でマニフェストファイル名とデフォルト出力フォルダを制御し、その後ビルドを実行して `PackageManifest` マニフェストと `yoo` リソースパッケージを生成し、実行時はアドレスで読み込みます。

## 前提条件

- Unity プロジェクトには Package Manager 経由で YooAsset がインストールされていること(`YooAssetSettings.asset` からスクリプト GUID `9753568a72b014c7092614d3be8b353f` を参照)。
- プロジェクトルートに `Assets/AssetBundleSetting/` フォルダが存在し、以下の 2 つのコア設定が含まれていること:
  - [YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset)
  - [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml)
- リソースはグループごとに `Assets/Bundles/{GroupName}` 配下に配置する(AOTCode / Code / UI / Config / Image / Sprites)。

## 操作手順

### 1. リソースディレクトリを準備する

YooAsset のコレクタは `Assets/Bundles` 配下の 6 つのグループ(AOTCode、Code、UI、Config、Image、Sprites)に固定されています。AssetBundle にパッケージングするリソースを用途に応じて対応するフォルダに配置してください。例:

- `Assets/Bundles/UI` —— UI Prefab、アトラス、フォント
- `Assets/Bundles/Config` —— 設定テーブル、バイナリリソース
- `Assets/Bundles/Sprites` / `Assets/Bundles/Image` —— アート用テクスチャ

収集ルールについては [AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L5-L22) を参照してください:

```xml
<Group GroupActiveRule="EnableGroup" GroupName="UI" GroupDesc="" AssetTags="">
  <Collector CollectPath="Assets/Bundles/UI" CollectGUID="4010ac95965b3164e83fa268b290dbf4"
            CollectType="MainAssetCollector" AddressRule="AddressByFileName"
            PackRule="PackDirectory" FilterRule="CollectAll" UserData="" AssetTags="" />
</Group>
```

> 各 `<Collector>` は「どのディレクトリを収集するか → どのルールでアドレスを生成するか → どうパッケージングするか」を表します。現在のプロジェクトでは `AddressByFileName`(ファイル名をロードアドレスとする)+ `PackDirectory`(ディレクトリ単位で 1 つのパッケージにする)が統一して使用されています。

### 2. YooAsset のグローバル設定を確認する

[YooAssetSettings.asset](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L12-L16) を開き、以下の 2 つのフィールドを確認してください:

| フィールド | 現在の値 | 説明 |
|------|--------|------|
| `ManifestFileName` | `PackageManifest` | 実行時にマニフェストを読み込む際のファイル名 |
| `DefaultYooFolderName` | `yoo` | ビルド成果物のデフォルト出力ディレクトリ名 |

プロジェクトで異なる名前のマニフェストや出力ディレクトリを使用している場合は、ここで変更し、実行時とビルド側で整合性を保つ必要があります。

### 3. YooAsset のビルドを実行する

YooAsset は Unity メニュー `YooAsset → Build` にビルドの入り口を用意しています(`YooAssetSettings.asset` の `m_Script` から参照されるエディタスクリプトが提供します)。ビルド成果物は `DefaultYooFolderName` で設定された `yoo` フォルダに出力され、主に以下の内容を含みます:

- `PackageManifest`(マニフェストファイル、すべてのパッケージ名、バージョン、リソースアドレスを記録)
- 各グループの AssetBundle ファイル(命名規則は `UniqueBundleName="True"` に従う、[AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3) を参照)

### 4. 実行時にアドレスでリソースを読み込む

ビルド完了後、`yoo` ディレクトリ配下のマニフェストと AssetBundle を `StreamingAssets`(またはリモート CDN)に配置します。起動時に YooAsset の初期化システムが `PackageManifest` を読み込み、業務側は `AddressByFileName` で生成されたアドレスで読み込みます:

```csharp
// 疑似コード:YooAsset の公開 API に合わせたもの、具体的な型はインストールされている YooAsset のバージョンに準拠してください
var package = YooAssets.GetPackage("DefaultPackage");
var op = package.LoadAssetAsync<GameObject>("Assets/Bundles/UI/LoginPanel.prefab");
yield return op;
var go = op.InstantiateObject;
```

## よくあるバリエーション

- **新しいリソースグループを追加する**:[AssetBundleCollectorConfig.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml) の `<Package>` 内に `<Group>` と対応する `<Collector CollectPath="Assets/Bundles/あなたのグループ">` を追加し、エディタを再起動すると YooAsset が自動的に認識します。
- **パッケージングの粒度を変更する**:`<Collector>` の `PackRule` を `PackDirectory` から `PackSeparately`(リソースごとに独立したパッケージ)または `PackTogether`(グループ全体を 1 つのパッケージに)に変更します。
- **アドレスルールを切り替える**:`AddressRule` を `AddressByGroupAndFileName` またはカスタムルールに変更し、実行時は新しいアドレスで読み込みます。

## よくあるエラー

- **実行時にリソースが見つからない**:まず `ManifestFileName` と `DefaultYooFolderName` がビルド側と実行側で一致していることを確認し([YooAssetSettings.asset L15-L16](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/YooAssetSettings.asset#L15-L16))、リソースが実際に `Assets/Bundles/<GroupName>` 配下に配置されており、グループの `GroupActiveRule="EnableGroup"` であることを確認してください。
- **重複パッケージングまたはパッケージ名の衝突**:`<Common>` ノードの `UniqueBundleName="True"` を維持してください([AssetBundleCollectorConfig.xml L3](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/AssetBundleSetting/AssetBundleCollectorConfig.xml#L3) を参照)、そうでないと同名ディレクトリが互いに上書きされてしまいます。
- **設定変更が反映されない**:YooAsset の収集設定はエディタの再起動または YooAsset 窗口を再度開いたときにのみ再解析されます。XML を変更した後、エディタのメインウィンドウに戻ってからビルドしてください。

## 背景(オプション)

プロジェクトでは YooAsset を統一されたリソース管理ソリューションとして採用しています:`AssetBundleCollectorConfig.xml` は「どのリソースを → どのアドレスで → どのパッケージにするか」を記述し、`YooAssetSettings.asset` は「マニフェストの命名方法 → 成果物の配置場所」を記述します。両端を分離することで、コードを書き換えずにパッケージング粒度を調整できるだけでなく、リソース構造を変更せずに実行モード(ローカル / CDN)を切り替えることも可能です。
