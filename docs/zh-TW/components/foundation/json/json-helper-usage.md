# 使用 JsonHelper 進行序列化與反序列化的方法

`JsonHelper` 是封裝於 `GameFrameX.Foundation.Json` 命名空間下的靜態輔助類別，能以同一設定在任意物件與 JSON 之間相互轉換：預設忽略 `null`、忽略循環參考、列舉型別以字串方式讀寫、中文 / Emoji 不進行逸出，並內建 `NaN` / `Infinity` 的相容處理。

## 前置條件

- 專案的目標框架為 `.NET 6+`（依賴 `System.Text.Json`）。
- 專案需參考 `GameFrameX.Foundation.Json` 套件（`GameFrameX.Foundation.Json.csproj`）。

```text
dotnet add package GameFrameX.Foundation.Json
```

```csharp
using GameFrameX.Foundation.Json;
```

Source: [GameFrameX.Foundation.Json.csproj](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/GameFrameX.Foundation.Json.csproj#L1-L20)

## 操作步驟

### 1. 選擇設定

`JsonHelper` 內建兩個唯讀設定，可直接使用：

| 設定 | 欄位 | 適用場景 |
|------|------|----------|
| 預設（緊湊） | `JsonHelper.DefaultOptions` | 網路傳輸、日誌、儲存 |
| 格式化（帶縮排與換行） | `JsonHelper.FormatOptions` | 偵錯輸出、設定檔 |
| 自訂可變副本 | `JsonHelper.CreateDefaultOptions()` / `JsonHelper.CreateFormatOptions()` | 在預設基礎上進行調整 |

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L87-L117)

### 2. 將物件序列化為 JSON 字串

```csharp
var user = new { Name = "张三", Age = 18, Role = UserRole.Admin };

// 預設設定（緊湊）
string json = JsonHelper.Serialize(user);

// 格式化設定（帶縮排）
string pretty = JsonHelper.SerializeFormat(user);

// 自訂設定
var options = JsonHelper.CreateDefaultOptions();
options.WriteIndented = true;
string custom = JsonHelper.Serialize(user, options);
```

- `Serialize(object obj)` 與 `Serialize(object obj, JsonSerializerOptions options)` 是最常用的兩個入口。當 `obj` 為 `null` 時會拋出 `ArgumentNullException`。
- 列舉型別預設以 **字串** 形式輸出（`Role: "Admin"`），而不是數字。
- `null` 欄位會被自動忽略，不會輸出 `"Name": null` 這樣的內容。

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L221-L246)

### 3. 序列化為 UTF-8 位元組陣列或資料流

```csharp
// 位元組陣列（適合直接儲存為檔案 / 作為 HTTP body 傳送）
byte[] bytes = JsonHelper.SerializeToUtf8Bytes(user);
byte[] bytesFormat = JsonHelper.SerializeToUtf8BytesFormat(user);

// 非同步寫入資料流
using var ms = new MemoryStream();
await JsonHelper.SerializeAsync(ms, user);
```

- `SerializeToUtf8Bytes` 預設使用緊湊設定，`SerializeToUtf8BytesFormat` 則使用格式化設定。
- `SerializeAsync<T>(Stream, T, JsonSerializerOptions?, CancellationToken)` 預設使用 `DefaultOptions`，且 `stream` 不可為 `null`。

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX/FameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L333-L356)

### 4. 將 JSON 字串反序列化為物件

```csharp
const string payload = "{\"name\":\"张三\",\"age\":18,\"role\":\"Admin\"}";

var restored = JsonHelper.Deserialize<User>(payload);

// 帶自訂設定
var restored2 = JsonHelper.Deserialize<User>(payload, options);

// 從資料流非同步讀取
using var input = new MemoryStream(bytes);
var restored3 = await JsonHelper.DeserializeAsync<User>(input);
```

- `Deserialize<T>(string json)` 內部會對 `null`、空字串與純空白字串拋出 `ArgumentException`，因此呼叫前務必先進行驗證。
- 當 JSON 中包含 `NaN` / `Infinity` 時，會自動先進行前處理再重試，因此無需手動逸出。
- 屬性名稱的比對 **不區分大小寫**，因此 `Name` 與 `name` 皆可對應。

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L406-L421)

### 5. 不拋出例外的 Try 版本（建議在不確定輸入是否合法的場景中使用）

```csharp
if (!JsonHelper.TryDeserialize<User>(payload, out var user, out var error))
{
    Console.WriteLine($"反序列化失敗: {error.Kind} - {error.Message} (path={error.Path})");
}
```

- `TryDeserialize<T>` / `TrySerialize` 系列會回傳 `bool`，失敗時透過 `out JsonHelperError` 提供 `Kind`（`InvalidInput` / `TypeMismatch` / `Serialization` / `Unknown`）、`Path`、`LineNumber`、`BytePositionInLine`。
- 使用預設設定的 `TryDeserialize<T>(string, out T)` 在出現 `NaN` / `Infinity` 時，同樣會自動前處理後再重試。

Source: [JsonHelper.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Json/JsonHelper.cs#L749-L807)

## 常見變化用法

- **AOT / 原始碼產生的高效能路徑**：透過 `JsonTypeInfo<T>` 呼叫序列化 / 反序列化，可在修剪（Trimming）與 AOT 場景下實現零反射：

  ```csharp
  string json = JsonHelper.Serialize(user, MyJsonContext.Default.User);
  var restored = JsonHelper.Deserialize<User>(payload, MyJsonContext.Default.User);
  ```

- **自訂浮點數處理**：預設設定已註冊 `SpecialFloatingPointConverter` 等轉換器，因此直接傳入 `"NaN"`、`"Infinity"` 字串字面值也能正常反序列化。
- **寫入 BOM / 自訂 Encoder**：呼叫 `CreateDefaultOptions()` 後，將新值指派給 `Encoder` 即可，不會影響其他預設行為。
- **針對外部輸入的容錯反序列化**：優先使用 `TryDeserialize<T>(string, out T, out JsonHelperError)`，取得 `JsonHelperError` 後再決定後備方案。

## 常見錯誤

| 症狀 | 原因 | 修正方法 |
|------|------|------|
| `ArgumentNullException: obj (Parameter 'obj')` | 呼叫了 `Serialize(null)` / `SerializeAsync(stream, null, …)` | 呼叫前先進行 `obj is null` 檢查，或改用 `TrySerialize` |
| `ArgumentException: json (Parameter 'json')` | 向 `Deserialize` 傳入了 `null`、空字串或純空白字串 | 先以 `string.IsNullOrWhiteSpace` 判斷，或改用 `TryDeserialize` |
| `JsonException` 且 `error.Kind == InvalidInput` | JSON 文字格式不正確（`AllowTrailingCommas=true` 雖允許結尾逗號，但某些情況仍會產生格式錯誤） | 檢查上游日誌。`JsonHelperError` 包含 `Path` / `LineNumber`，可據以定位位置 |
| 反序列化後的列舉型別欄位變成數字 | 業務程式碼自行 new 了 `JsonSerializerOptions`，且未註冊 `JsonStringEnumConverter` | 直接使用 `JsonHelper.DefaultOptions` 或 `CreateDefaultOptions()`，不要自行 new 預設 options |

## 背景（選用）

`DefaultOptions` 透過 `DefaultIgnoreCondition = WhenWritingNull`、`ReferenceHandler.IgnoreCycles`、`JsonStringEnumConverter`、`AllowReadingFromString | AllowNamedFloatingPointLiterals` 等組合，讓業務程式碼幾乎不必考慮 `null` 欄位、循環參考與列舉型別的意義。中文 / Emoji 不會被逸出，這歸功於專案內的 `UnicodeJsonEncoder`。兩個設定會在靜態建構函式中以 `MakeReadOnly(true)` 凍結，避免在執行階段被誤改。呼叫端若要自訂，請務必使用 `CreateDefaultOptions()` 取得可變副本。
