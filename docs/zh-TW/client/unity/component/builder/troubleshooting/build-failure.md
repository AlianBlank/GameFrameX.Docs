# 建置失敗與命令列引數錯誤發生時的處理方法

從命令列呼叫建置處理時，建置失敗幾乎總是源自「參數缺失 / 拼字錯誤 / 無效值」或「前置步驟未完成」。本頁面將以錯誤訊息原文為依據，說明對應的根本原因與修正方法。

## 快速診斷

| 症狀(錯誤原文/關鍵字) | 根本原因 | 修正方法 |
|---|---|---|
| `executeMethod is null` | 未透過 `-ExecuteMethod` 傳入入口方法名稱 | 在命令列中加入 `-ExecuteMethod <名前空間.クラス.メソッド>` |
| `build number is null` | 未透過 `-BuildNumber` 傳入建置編號 | 在命令列中加入 `-BuildNumber <バージョン番号>` |
| `無効の构建管线类型: <xxx>，可选値: BuiltinBuildPipeline, ScriptableBuildPipeline, RawFileBuildPipeline` | `-BuildPipeline` 的值不是有效的 enum 名稱 | 將值改為 `BuiltinBuildPipeline`、`ScriptableBuildPipeline`、`RawFileBuildPipeline` 其中之一 |
| `無効の内置文件拷贝选项: <xxx>，可选値: None, ClearAndCopyAll, ClearAndCopyByTags, OnlyCopyNew` | `-BuildinFileCopyOption` 的值無效 | 將值改為 `None`、`ClearAndCopyAll`、`ClearAndCopyByTags`、`OnlyCopyNew` 其中之一。未指定時預設為 `ClearAndCopyAll` |
| 日誌中完全沒有本工具的輸出，但 Unity 已結束 | `LogFilePath` 指向的位置無法寫入，或建置編號為空導致路徑推導失敗 | 檢查 `-LogFilePath` 的目錄權限，或明確指定 `-BuildNumber` |
| `-BuildPipeline`/`-PackageVersion` 等帶值參數未生效 | 將值緊接在參數後面，寫成 `-BuildPipelineBuiltinBuildPipeline` 的形式 | 參數與值之間**必須加入空格**，寫成 `-BuildPipeline BuiltinBuildPipeline` |
| BuildAsset 正常，但在 BuildPlayer(打包輸出)階段出現紅色錯誤 | 前一階段的 `BuildAsset` 尚未執行，或熱更新/AOT 程式碼目錄為空 | 先執行 `BuildAsset`,確認 `Assets/.../Hotfix/`、`AOT/` 目錄有內容後再進行打包輸出 |

## 修正步驟

### 1. 補齊 3 個必要參數

解析器將 `-ExecuteMethod`、`-BuildNumber`、`-LogFilePath` 視為必要參數(後者未指定時會由前兩者自動推導，但建議明確指定)。命令範例：

```bash
Unity \
  -batchmode -nographics -quit \
  -projectPath /path/to/project \
  -executeMethod GameFrameX.Builder.Editor.Builder.BuildAsset \
  -BuildNumber 1.0.0.1 \
  -LogFilePath ../Logs/BuildAsset_1.0.0.1.log \
  -ChannelName default \
  -PackageName DefaultPackage
```

只要缺少其中任何一個，就會拋出 `Exception`,程序會直接終止。出處:[Editor/Builder.BuildParamsParse.cs#L175-L189](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L175-L189)。

### 2. 修正 `-BuildPipeline` 與 `-BuildinFileCopyOption` 的值

這兩個參數透過 `Enum.TryParse` 驗證。雖不區分大小寫，但**必須是 enum 名稱**，數字或拼字錯誤亦不可：

- `-BuildPipeline`:從 `BuiltinBuildPipeline`(預設)、`ScriptableBuildPipeline`、`RawFileBuildPipeline` 中選擇
- `-BuildinFileCopyOption`:從 `None`、`ClearAndCopyAll`(預設)、`ClearAndCopyByTags`、`OnlyCopyNew` 中選擇

```bash
  -BuildPipeline BuiltinBuildPipeline \
  -BuildinFileCopyOption ClearAndCopyAll \
```

驗證邏輯:[Editor/Builder.BuildAsset.cs#L40-L84](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L40-L84)。

### 3. `-xxx <値>` 之間以空格分隔

解析器會逐一走訪 `commandLineArgs`,各參數開關的值以 `index + 1` 取得下一個元素。因此，參數與值之間必須以空格分隔(不可使用 `=` 或連寫)。出處:[Editor/Builder.BuildParamsParse.cs#L152-L172](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L152-L172)。

正確寫法:`-PackageVersion 20240101120000`
錯誤寫法:`-PackageVersion=20240101120000`、`-PackageVersion20240101120000`

### 4. 先執行 `BuildAsset` 再執行 `BuildPlayer`

`BuildAsset` 內部會複製熱更新與 AOT 組件、更新 AssetDatabase,之後執行 YooAsset 打包。若直接執行打包輸出命令後，出現熱更新程式碼缺失、「找不到組件」錯誤，或打包出空的資源，通常表示跳過了資源打包步驟。修正方式：將流程分為兩個階段，先執行 `BuildAsset`,再執行 `BuildPlayerAndroid`/`BuildPlayerIOS`。出處:[Editor/Builder.BuildAsset.cs#L15-L27](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L15-L27)、[Editor/Builder.cs#L60-L66](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.cs#L60-L66)。

### 5. 讓 `-BundleId` / `-AppVersion` 實際生效

這兩個參數只有在傳入非空字串時，才會覆寫 `PlayerSettings`。若已在命令列指定但 `PlayerSettings` 未變化，請檢查前後是否有多餘的空格或換行(程式碼會執行 `Trim`)。出處:[Editor/Builder.BuildParamsParse.cs#L194-L202](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L194-L202)。

## 驗證

1. 若命令列的第一行不再顯示 `executeMethod is null` / `build number is null`,表示必要參數已補齊。
2. 在 Edit/Console 中，若 `-----------构建参数开始-----------` 這一行之後緊接著 `_builderOptions` 的 JSON 輸出，即可確認所有參數均已正確解析。出處:[Editor/Builder.BuildParamsParse.cs#L191-L193](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildParamsParse.cs#L191-L193)。
3. 若 `BuildAsset` 完成後的日誌包含 `BuildAsset End`,之後再啟動 `BuildPlayer*` 也不會因資源不足而失敗。出處:[Editor/Builder.BuildAsset.cs#L99-L100](https://github.com/GameFrameX/com.gameframex.unity.builder/blob/main/Editor/Builder.BuildAsset.cs#L99-L100)。

## 背景(可選)

工具的運作流程為：以 `Builder.BuildParamsParse` 解析命令列 → 寫入 `BuilderOptions` → 傳遞給 `BuildAsset` / `BuildPlayer*`。由於驗證集中在解析階段(拋出 `Exception`)與 `BuildAsset` 開始時的 enum `TryParse`,因此「建置失敗」大多會在這兩層被捕獲。真正需要回頭調查 YooAsset / Unity 打包輸出本身的情況反而屬於少數。
