# 리소스 실행 모드(PlayMode) 선택 방법

리소스 실행 모드(`EPlayMode`)는 YooAsset이 시작 시 에셋을 로드하는 방식을 결정합니다. `StartupOptions` 에셋에서 `GamePlayMode` 필드만 설정하면, 시작 프로세스가 리소스를 로드하기 전에 `AssetComponent`에 자동으로 동기화됩니다.

## 사전 조건

- `GameFrameX/Startup Options` 메뉴를 통해 `StartupOptions` 에셋을 생성했습니다.
- `GameFrameX.Asset` 컴포넌트를 설치하여 `GameEntry`에 등록했습니다(프레임워크가 기본적으로 등록).
- 프로젝트에서 YooAsset을 사용합니다(프레임워크의 `EPlayMode`는 `YooAsset` 네임스페이스 소속).

## 작업 단계

1. 프로젝트 내에서 `StartupOptions` 에셋을 엽니다(`Assets/` 아래 임의의 위치).
2. **Asset** 분류 아래의 **GamePlayMode** 필드를 찾습니다.
3. 원하는 열거형 값을 선택합니다. 주요 값과 용도는 아래 표를 참고하세요.

| 열거형 값 | 의미 | 일반적인 시나리오 |
|---|---|---|
| `EditorSimulateMode` | 에디터 시뮬레이션 모드, 프로젝트 내 AssetDatabase 리소스를 직접 읽으며 리소스 패키지를 거치지 않음 | Unity Editor 내 순수 로컬 디버깅 |
| `OfflinePlayMode` | 오프라인 모드, 빌드된 로컬 리소스 패키지를 로드하며 네트워크에 연결하지 않음 | 단독 배포, 백엔드 없는 인트라넷 |
| `HostPlayMode` | 호스트 모드, 원격 CDN에서 리소스 패키지를 받아오고 + 로컬 캐시 사용 | 일반적인 핫업데이트 가능한 모바일/PC 배포 |
| `WebPlayMode` | Web 모드, WebGL에 적합한 리소스 로딩 | WebGL 플랫폼 |

필드 정의 위치(소스 코드 링크 포함):

```csharp
[Header("Asset")] [Tooltip("资源运行模式。启动流程会在加载资源前同步到 Asset 组件。")]
public EPlayMode GamePlayMode = EPlayMode.EditorSimulateMode;
```

출처: [StartupOptions.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupOptions.cs#L19-L20)

시작 시 프레임워크는 해당 필드를 읽어 `AssetComponent`에 동기화합니다:

```csharp
private static void ApplyAssetPlayMode(StartupOptions options)
{
    GameEntry.GetComponent<AssetComponent>().GamePlayMode = NormalizeAssetPlayMode(options.GamePlayMode);
}
```

출처: [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L127-L130)

## 일반적인 변형

### 에디터에서는 EditorSimulateMode 선택, 빌드 후 자동 변경

에디터 내 디버깅에는 보통 `EditorSimulateMode`를 선택합니다. `NormalizeAssetPlayMode`가 Editor가 아닌 환경에서 자동으로 이를 `HostPlayMode`로 다운그레이드하므로 수동으로 전환할 필요가 없습니다.

```csharp
private static EPlayMode NormalizeAssetPlayMode(EPlayMode playMode)
{
#if !UNITY_EDITOR
    if (playMode == EPlayMode.EditorSimulateMode)
    {
        playMode = EPlayMode.HostPlayMode;
    }
#if UNITY_WEBGL
    playMode = EPlayMode.WebPlayMode;
#endif
#endif
    return playMode;
}
```

출처: [StartupRunner.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Startup/StartupRunner.cs#L132-L144)

### 프로세스 분기 구분: Offline과 EditorSimulate

시작 프로세스에서 서로 다른 `PlayMode`는 서로 다른 업데이트/패치 경로를 따르므로, 비즈니스 코드에서 수동으로 판단할 필요가 없습니다:

- `OfflinePlayMode`: [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L42) 내에서 원격 매니페스트 업데이트를 건너뜁니다.
- `EditorSimulateMode`: [ProcedureUpdateManifest.cs](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/Runtime/Procedures/Patch/ProcedureUpdateManifest.cs#L71) 내에서 시뮬레이션 매니페스트 분기를 따릅니다.

### WebGL에서는 WebPlayMode로 강제 전환

컴파일 대상이 WebGL이기만 하면, 무엇을 설정했든 `NormalizeAssetPlayMode`가 강제로 `WebPlayMode`로 변경합니다(위 코드 조각의 `#if UNITY_WEBGL` 블록 참조).

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| 플레이어 빌드 시작 후 리소스를 찾을 수 없음 | `EditorSimulateMode`도 배포 빌드에 사용할 수 있다고 잘못 이해함 | Editor가 아닌 환경에서는 자동으로 `HostPlayMode`로 다운그레이드되므로, CDN URL과 리소스 패키지 버전 프로세스가 올바르게 구성되어 있는지 확인 |
| WebGL에서 리소스 로딩 실패 | `HostPlayMode` 같은 비(非)Web 모드를 계속 사용 중 | 컴파일 대상을 WebGL로 전환하면 프레임워크가 자동으로 `WebPlayMode`로 변경하므로 수동 수정 불필요 |
| 오프라인 모드인데도 네트워크 연결을 시도함 | `OfflinePlayMode`를 핫업데이트가 필요한 시나리오에 설정함 | 백엔드 없는/단독 실행 시나리오에서만 `OfflinePlayMode` 사용 |
| `StartupOptions`에서 `GamePlayMode` 필드를 찾을 수 없음 | 최신 에셋을 사용하지 않았거나 필드명이 변경됨 | `GameFrameX/Startup Options`를 통해 에셋을 다시 생성 |

## 배경(선택 사항)

필드명 `GamePlayMode`는 `AssetComponent`에 내장된 동일한 이름의 프로퍼티와의 충돌을 피하기 위한 것입니다. 기본값인 `EditorSimulateMode` 덕분에 개발자는 Unity Editor에서 바로 전체 프로세스를 실행해 볼 수 있으며, 빌드 후에는 `NormalizeAssetPlayMode`가 자동으로 배포 가능한 모드로 다운그레이드하여 "개발자 편의"가 플레이어 빌드에 잘못 포함되는 것을 방지합니다. `StartupOptions`는 `[CreateAssetMenu]`를 통해 프로젝트에서 SO 형태로 직접 유지 관리됩니다.
