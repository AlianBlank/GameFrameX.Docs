# MVVM 繫結與事件自動清理

在 FairyGUI 介面裡使用 `BindableProperty<T>` 做資料繫結時，只需呼叫一個擴充方法 `ClearWithGObjectDestroyed`,即可把事件清理掛到 `GObject` 的 `onRemovedFromStage` 上——當 GObject 離開顯示列表(含銷毀)時自動執行 `bindableProperty.Clear`,不必再手寫取消註冊邏輯，避免事件殘留與記憶體洩漏。

## 前置條件

- 已安裝 `com.gameframex.unity.fairygui` 套件(見 README 相依性表:`com.gameframex.unity` 1.1.1、`com.gameframex.unity.ui` 1.0.0 等)。
- `BindableProperty<T>` 來自 GameFrameX 核心套件，命名空間為 `GameFrameX.Runtime`;擴充方法本身位於 `GameFrameX.UI.FairyGUI.Runtime`。
- 介面類別繼承自 `FUI`(它公開 `GObject` 屬性，見 [FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L43-L53))。

## 操作步驟

1. 在介面/邏輯類別中建立繫結屬性，例如 `BindableProperty<int>`、`BindableProperty<string>` 等，並訂閱其事件完成資料繫結。

2. 取得與該介面生命週期一致的 `GObject` 後，呼叫擴充方法註冊自動清理：

```csharp
// GObject 銷毀時自動取消註冊事件
myProperty.ClearWithGObjectDestroyed(gObject);
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/README.zh-CN.md#L123-L128)

3. 之後正常關閉/銷毀介面即可，無需再手動取消訂閱繫結屬性事件。

擴充方法的完整實作如下(整個機制只有一行註冊):

```csharp
[UnityEngine.Scripting.Preserve]
public static void ClearWithGObjectDestroyed<T>(this BindableProperty<T> bindableProperty, GObject gObject)
{
    gObject.onRemovedFromStage.Add(bindableProperty.Clear);
}
```

Source: [BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L52-L56)

## 常見變體

- **在 FUI 子類別中繫結**：繼承 `FUI` 的介面可以直接用自身的 `GObject` 作為生命週期錨點，例如在繫結初始化處呼叫 `myProperty.ClearWithGObjectDestroyed(GObject);`,介面銷毀時事件隨之清空。
- **泛型任意**：該方法是泛型擴充，`BindableProperty<int>`、`BindableProperty<string>` 等任意 `T` 都可直接呼叫，無需為每種類型單獨撰寫清理程式碼。

## 常見錯誤

| 症狀 | 原因 | 規避方法 |
|------|------|----------|
| 介面銷毀後繫結事件仍被觸發、物件無法回收 | 忘記呼叫 `ClearWithGObjectDestroyed`,訂閱殘留在繫結屬性上 | 每次訂閱繫結屬性事件後，立即用同一 GObject 呼叫一次該擴充方法 |
| `NullReferenceException` | 傳入的 `gObject` 為 null(介面尚未建立 GObject 就呼叫) | 確保在 GObject 初始化完成後再呼叫;`FUI.Visible` 的實作也表明 `GObject` 可能為 null([FUI.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/FUI.cs#L135-L149)) |
| 事件在「看起來還沒銷毀」時被清空 | 觸發掛鉤是 `onRemovedFromStage`(離開顯示列表)，而不僅僅是銷毀；任何把物件移出顯示列表的操作都會觸發 `Clear` | 若會把 GObject 動態從顯示列表移除又重複使用，請在重新加入顯示列表後重新繫結並再次呼叫本方法 |

## 驗證

- 關閉介面後修改繫結屬性的值，確認不再有任何 UI 回呼被觸發。
- 在 `Clear` 生效前後用記憶體分析器(如 Unity Memory Profiler)對比，確認介面相關物件可被回收。

## 背景

該機制刻意做得極簡：利用 FairyGUI `GObject.onRemovedFromStage` 事件，把 `BindableProperty.Clear` 作為回呼註冊進去([BindablePropertyExtension.cs](https://github.com/GameFrameX/com.gameframex.unity.ui.fairygui/blob/main/Runtime/BindablePropertyExtension.cs#L55))。繫結屬性本身屬於 GameFrameX 核心套件(`GameFrameX.Runtime` 命名空間)，UI 層只負責在其與 GObject 生命週期之間建立「銷毀即清理」的關聯。方法上標註了 `[UnityEngine.Scripting.Preserve]` 以防遭程式碼裁剪移除。
