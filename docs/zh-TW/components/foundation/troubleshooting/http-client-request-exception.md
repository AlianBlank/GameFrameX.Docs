# HttpClientRequestException 的擲回與回應例外處理方法

透過 `GameFrameX.Foundation.Http.Extension` 發出的 HTTP 要求，若收到非成功的狀態碼、發生網路層例外，或 JSON 還原序列化失敗，架構會擲回 `HttpClientRequestException`。本頁將說明如何識別此例外、如何找出原因，以及如何選擇適當的修正方式。

## 快速診斷

| 症狀(例外訊息) | 原因 | 修正 |
|---|---|---|
| `HTTP request failed with status code {code} ({StatusCode}) for {uri}.` | 伺服器傳回 4xx / 5xx 回應，且呼叫端呼叫了 `EnsureSuccessStatusCode()`,或觸發了內部的狀態碼檢查 | 請參閱 [修正步驟 - 狀態碼失敗](#修正步驟-狀態碼失敗) |
| `HTTP request failed for {method} {uri}.` | 底層擲回 `HttpRequestException`(DNS、連線、逾時、TLS 等網路層錯誤)，且已超出重試範圍，或一般 `Exception` 符合 `HttpRequestException / JsonException` 分支 | 請參閱 [修正步驟 - 網路層 / 一般例外](#修正步驟-網路層--一般例外) |
| `HTTP JSON response could not be deserialized for {uri}.` | 回應主體不是有效的 JSON,或與目標型別不相符 | 請參閱 [修正步驟 - JSON 還原序列化失敗](#修正步驟-json-還原序列化失敗) |

此例外型別本身繼承自 `HttpRequestException`,並額外提供以下診斷欄位：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `StatusCode` | `HttpStatusCode?` | 伺服器傳回的 HTTP 狀態碼(若有回應) |
| `RequestUri` | `Uri?` | 發生錯誤的要求 URI |
| `ResponseSummary` | `string?` | 回應主體的摘要(失敗時會設定) |
| `RawException` | `Exception?` | 觸發此例外的原始例外(若有) |

```csharp
public sealed class HttpClientRequestException : HttpRequestException
{
    public HttpClientRequestException(
        string message,
        HttpStatusCode? statusCode,
        Uri? requestUri,
        string? responseSummary,
        Exception? rawException = null)
        : base(message, rawException, statusCode)
    {
        StatusCode = statusCode;
        RequestUri = requestUri;
        ResponseSummary = responseSummary;
        RawException = rawException;
    }

    public new HttpStatusCode? StatusCode { get; }
    public Uri? RequestUri { get; }
    public string? ResponseSummary { get; }
    public Exception? RawException { get; }
}
```

## 修正步驟

### 修正步驟：狀態碼失敗

1. 在呼叫端使用 `try / catch` 攔截 `HttpClientRequestException`,並依 `StatusCode` 判斷具體的失敗類型(401、404、500 等)。

```csharp
try
{
    var response = await httpClient.SendJsonAsync<MyDto>(request, options);
    response.EnsureSuccessStatusCode();
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    // 資源不存在，因此進入業務後援分支
}
catch (HttpClientRequestException ex) when (ex.StatusCode == HttpStatusCode.Unauthorized)
{
    // 更新權杖，或引導使用者重新登入
}
```

2. 若要求本身應具備容錯能力(例如：允許 GET 清單在 404 時傳回空值)，請勿呼叫 `EnsureSuccessStatusCode()`,而是直接讀取 `IsSuccessStatusCode` 與 `Body` 自行處理。

```csharp
public HttpClientResponse EnsureSuccessStatusCode()
{
    if (IsSuccessStatusCode)
    {
        return this;
    }

    throw new HttpClientRequestException(
        $"HTTP request failed with status code {(int)StatusCode} ({StatusCode}) for {RequestUri}.",
        StatusCode,
        RequestUri,
        Body);
}
```

來源:[HttpClientResponse.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientResponse.cs#L80-L92)

3. 請確認重試設定。架構預設會對 `HttpRequestException` 執行有限次數的重試。在 `attempt <= options.Retry.MaxRetries` 期間不會擲回 `HttpClientRequestException`,而是觸發退避重試。

```csharp
catch (HttpRequestException exception) when (allowRetry && attempt <= options.Retry.MaxRetries)
{
    await DelayBeforeRetryAsync(method, request.RequestUri, attempt, null, exception, options, effectiveToken);
    return (null, true);
}
```

來源:[HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L358-L362)

若發生狀態碼失敗但重試次數已用盡，會透過 `CreateStatusException` 擲回附帶狀態碼的例外：

```csharp
private static HttpClientRequestException CreateStatusException(
    HttpStatusCode statusCode,
    Uri? requestUri,
    string responseText)
{
    return new HttpClientRequestException(
        $"HTTP request failed with status code {(int)statusCode} ({statusCode}) for {requestUri}.",
        statusCode,
        requestUri,
        Summarize(responseText));
}
```

來源:[HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L441-L451)

### 修正步驟：網路層 / 一般例外

1. 網路層(DNS、TCP、TLS、逾時)的問題通常會以底層 `HttpRequestException` 的形式出現。當重試次數已用盡，或發生 `HttpRequestException / JsonException` 以外的 `Exception` 時，會以下列方式包裝：

```csharp
catch (Exception exception) when (exception is HttpRequestException or JsonException)
{
    throw new HttpClientRequestException(
        $"HTTP request failed for {method} {request.RequestUri}.",
        null,
        request.RequestUri,
        null,
        exception);
}
```

來源:[HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L363-L371)

2. 調查重點：
   - 請先確認 `ex.RawException?.Message`,底層的真正原因通常會記錄在此處(例如:`The requested name is valid, but no data of the requested type was found`)。
   - 若為逾時，請提高 `HttpClientRequestOptions` 的逾時臨界值，或調整 `Retry.MaxRetries / Retry.Delay`,讓重試執行得更充分。
   - 若為 TLS / 憑證錯誤，請確認目標位址的憑證鏈與伺服器的 SNI 設定。
   - 若在自訂的 `HttpMessageHandler` 鏈之下擲回其他例外，架構僅會在符合 `is HttpRequestException or JsonException` 時進行包裝；其他例外會原樣傳播，因此需另行攔截。

### 修正步驟:JSON 還原序列化失敗

1. 當回應主體不是有效的 JSON,或欄位型別與目標型別不一致時，會擲回以下例外：

```csharp
catch (JsonException exception)
{
    throw new HttpClientRequestException(
        $"HTTP JSON response could not be deserialized for {requestUri}.",
        null,
        requestUri,
        Summarize(responseText),
        exception);
}
```

來源:[HttpClientJsonExtension.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/src/GameFrameX.Foundation.Http.Extension/HttpClientJsonExtension.cs#L430-L438)

2. 調查重點：
   - 請從 `ex.RawException` 取得原始的 `JsonException`,定位具體的欄位路徑與行號。
   - 請確認 `ex.ResponseSummary`,從回應主體的摘要檢查伺服器傳回的格式(`application/json` 或 `text/html`)。
   - 視需要在 `HttpClientRequestOptions.JsonSerializerOptions` 中設定 `PropertyNameCaseInsensitive`、`NumberHandling`、`AllowTrailingCommas` 等，讓還原序列化更為寬容。

## 驗證

1. 刻意建立會失敗的要求(指向不存在的位址，或傳回 500 的端點)，確認已攔截 `HttpClientRequestException`,且 `StatusCode` / `RequestUri` / `ResponseSummary` 三個欄位的值符合預期。
2. 在還原序列化失敗的情境中，將 `RawException` 轉換為 `JsonException`,並確認其 `Path` 指向造成失敗的欄位。
3. 在啟用 `Retry.MaxRetries > 0` 設定的狀態下，讓目標介面暫時傳回 5xx,確認日誌中出現退避重試的記錄，且最終依業務需求擲回 `HttpClientRequestException`。
