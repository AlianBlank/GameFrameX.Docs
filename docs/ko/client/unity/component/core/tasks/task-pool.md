# 비동기 작업 스케줄링

`TaskPool<T>`은 「작업 에이전트 + 우선순위 큐」 방식으로 비동기 작업을 관리합니다: 여러 개의 `ITaskAgent<T>`를 풀에 등록하고, `TaskBase` 파생 작업을 제출하면, 풀이 매 프레임 `Update` 시 우선순위에 따라空闲 에이전트에게 작업을分发하여 실행합니다. 이 페이지에서는 비동기 작업에接入하고 스케줄링하는 방법을 설명합니다.

## 전제 조건

- `GameFrameX.Runtime` 어셈블리가 도입되었습니다 (작업 풀은 [Runtime/Base/TaskPool](/Runtime/Base/TaskPool/TaskPool.cs#L44-L64) 네임스페이스 `GameFrameX.Runtime`에 위치).
- 사용자 정의 작업은 `TaskBase`를 상속하고, 사용자 정의 에이전트는 `ITaskAgent<T>`를 구현합니다.
- 작업 객체는 `ReferencePool.Acquire<T>()`로取得하는 것을 권장하며, 풀 해제 후 자동으로 회수됩니다 ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L11-L21)).

## 작업 단계

1. **작업 유형 정의**. `TaskBase`를 상속하고, 최소한 `Description` 속성을 재정의합니다. 작업은 `Initialize(serializeId, tag, priority, userData)`로 우선순위와 사용자 정의 데이터를 구성합니다.

   ```csharp
   using GameFrameX.Runtime;

   public class LoadAssetTask : TaskBase
   {
       public string AssetName { get; private set; }

       public override string Description => $"LoadAsset:{AssetName}";

       public void Init(string assetName)
       {
           AssetName = assetName;
           Initialize(0, assetName, 0, null);
       }
   }
   ```

   Source: [Runtime/Base/TaskPool/TaskBase.cs](/Runtime/Base/TaskPool/TaskBase.cs)

2. **작업 에이전트 구현**. `ITaskAgent<T>`의 `Initialize / Update / Shutdown / Start / Reset`을 구현하고, `Start`에서 `StartTaskStatus.CanResume / CanNotResume`을 반환하며, `Task.Done = true`로 완료를 표시합니다 ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L23-L62)).

   ```csharp
   public class LoadAssetAgent : ITaskAgent<LoadAssetTask>
   {
       public LoadAssetTask Task { get; private set; }
       public bool IsInitialized { get; private set; }
       public bool IsShutdown { get; private set; }

       public void Initialize() { IsInitialized = true; }
       public void Update(float e, float re) { /* 실제 로딩 완료 후 Task.Done = true 설정 */ }
       public void Shutdown() { IsShutdown = true; }

       public StartTaskStatus Start(LoadAssetTask task)
       {
           Task = task;
           return StartTaskStatus.CanResume; // 동기 완료는 CanNotResume 반환
       }

       public void Reset() { Task = null; }
   }
   ```

   Source: [Runtime/Base/TaskPool/ITaskAgent.cs](/Runtime/Base/TaskPool/ITaskAgent.cs)

3. **작업 풀 생성 및 에이전트 등록**. `TaskPool<T>`를 인스턴스화하고, `AddAgent`를 호출하여 하나 이상의 에이전트를 등록합니다; 에이전트 수가 곧 최대 동시 작업 수입니다.

   ```csharp
   var taskPool = new TaskPool<LoadAssetTask>();
   taskPool.AddAgent(new LoadAssetAgent());
   taskPool.AddAgent(new LoadAssetAgent()); // 동시 2
   ```

   Source: [Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L58-L64)

4. **작업 제출**. `ReferencePool.Acquire`로 작업 객체를取得하고, `Initialize` 후 `AddTask`를 호출합니다. 작업은 `priority` 내림차순으로 정렬됩니다: 숫자가 클수록 먼저 실행됩니다 ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L127-L145)).

   ```csharp
   var task = ReferencePool.Acquire<LoadAssetTask>();
   task.Init("Config/battle.json");
   taskPool.AddTask(task);

   var urgent = ReferencePool.Acquire<LoadAssetTask>();
   urgent.Initialize(1, "Player/Avatar", 10, null); // priority=10 먼저 실행
   taskPool.AddTask(urgent);
   ```

5. **매 프레임 Update 구동**. 게임 메인 루프에서 `taskPool.Update(elapseSeconds, realElapseSeconds)`를 호출하면, 풀이 자동으로: ① 모든 `WorkingAgent`를推进; ② 대기 큐에서 가장 우선순위가 높은 작업을空闲 에이전트에게分发합니다 ([Runtime/Base/TaskPool/TaskPool.cs](/Runtime/Base/TaskPool/TaskPool.cs#L136-L145)).

   ```csharp
   void Update()
   {
       taskPool.Update(Time.deltaTime, Time.unscaledDeltaTime);
   }
   ```

6. **일시 정지 및 정리**. 스케줄링을 동결해야 할 때 `taskPool.Paused = true`로 설정하면, `Update`가 직접 return되어 어떤 작업 처리도 트리거되지 않습니다 ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L185-L196)). 더 이상 사용하지 않을 때는 `RemoveAllTasks()` + `Shutdown()`을 호출하고, `ReferencePool.ClearAll()`로 작업 객체를 해제합니다.

## 일반적인 변형

| 시나리오 | 방법 |
|------|------|
| 비동기 시간 소모 작업 (자원 로딩, 네트워크) | `Start`는 `CanResume`을 반환하고, `Update`에서 진행률을 폴링하며, 완료 시 `Task.Done = true` 설정 |
| 동기로 완료 가능한 작업 | `Start`는 `CanNotResume`을 반환하면, 풀이 다음 프레임에 에이전트를 계속分发 가능으로 표시 |
| 동시성上限 제어 | N개의 `ITaskAgent<T>`만 등록하면, 초과 작업은 `WaitingTasks` 큐에 남음 |
| 작업 상태 조회 | `GetAllTaskInfos()`로 `TaskInfo[]`取得 (`Priority`, `Status`, `Description` 포함) |
| 지정 작업 취소 | `RemoveTask(serializeId, tag)` 적중 후 객체를 `ReferencePool`로 반환 |

## 일반적인 오류

| 오류 | 설명 | 회피 |
|------|------|------|
| `AddAgent(null)` | `GameFrameworkException` 발생 ([Tests/TaskPoolTests.cs](/Tests/TaskPoolTests.cs#L99-L101)) | 등록 전 null 값 검사 |
| 에이전트 수過少 | 대기 큐가 적체되어 `WaitingTaskCount`가 지속적으로 0보다 큼 | 예상 동시량에 따라 에이전트 등록 |
| `Update` 호출 잊음 | 작업이 영원히 실행되지 않음 | `taskPool.Update`를 MonoBehaviour 메인 루프 또는 프레임워크의 `GameFramework`分发에接入 |
| 에이전트 `Start`가永远 `CanNotResume`을 반환하지 않고, `Task.Done`도 설정하지 않음 | 에이전트가 영구 점유되어空闲 에이전트 수가 증가하지 않음 | 비동기 콜백 또는 `Update`에서 명확하게 `Done = true` 설정 |
| 직접 `new T()`로 작업 생성 | 작업이 참조 풀을 거치지 않아 회수 및 재사용 불가 | `ReferencePool.Acquire<T>()` 사용 |

## 배경 (선택 사항)

작업 풀은 「작업 = 데이터 / 에이전트 = 실행자」 분리 모드입니다: 풀 자체는分发 및 회수만 담당하고, 구체적인 실행은 `ITaskAgent<T>`에 맡깁니다. 우선순위는 `m_WaitingTasks` 연결 리스트가 `priority` 내림차순으로 유지하여, 매번出队 시 현재 우선순위가 가장 높은 작업을 보장합니다. `Paused`는 게임 일시 정지, 씬 전환 등 백그라운드 작업을 동결해야 하는场景에 사용됩니다.

작업 풀과 다른 하위 시스템의 협력에 대해서는 《ReferencePool 참고》를 참조하세요.
