# 用 Tag 標籤分組管理下載任務

透過給 `AddDownload` 傳入 `tag` 字串,可以把同一類下載任務歸到一個分組,然後用 `GetDownloadInfos(tag)` 一次性查出該分組下所有任務的狀態。本頁說明如何給任務打 Tag、如何按 Tag 查詢,以及常見錯誤。

## 前置條件

- 已安裝 `com.gameframex.unity.download` 套件,並在場景裡掛好 `DownloadComponent`。
- 已取得 `DownloadComponent` 引用,例如 `GameEntry.GetComponent<DownloadComponent>()`。
- 已了解 `AddDownload` 的基本呼叫方式(見元件中的 `AddDownload(string, string)` 多載)。

## 操作步驟

### 1. 給下載任務打 Tag

呼叫帶 `tag` 參數的 `AddDownload` 多載。Tag 是一個普通的字串,語意由你自己定義,例如 `"asset-bundle"`、`"lua-3.2.0"`、`"res-avatar"`。

```csharp
// 只指定 tag,使用預設優先級與 null userData
int id1 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/a.png",
    downloadUri:  "https://example.com/a.png",
    tag:          "asset-bundle");

// 指定 tag + 優先級
int id2 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/b.png",
    downloadUri:  "https://example.com/b.png",
    tag:          "asset-bundle",
    priority:     10);

// 指定 tag + 優先級 + userData(完整版本)
int id3 = downloadComponent.AddDownload(
    downloadPath: Application.persistentDataPath + "/c.png",
    downloadUri:  "https://example.com/c.png",
    tag:          "asset-bundle",
    priority:     10,
    userData:     myCallback);
```

### 2. 按 Tag 一次性查詢分組下所有任務

用 `GetDownloadInfos(string tag)` 取得該分組下的 `TaskInfo[]`,或用 `GetDownloadInfos(string tag, List<TaskInfo> results)` 重複使用既有列表避免 GC。

```csharp
// 回傳 TaskInfo[]
TaskInfo[] infos = downloadComponent.GetDownloadInfos("asset-bundle");
foreach (var info in infos)
{
    Debug.Log($"tag={info.Tag} status={info.Status} progress={info.Progress}");
}

// 重複使用 List,避免每幀配置新陣列
var buffer = new List<TaskInfo>();
downloadComponent.GetDownloadInfos("asset-bundle", buffer);
```

Source: [DownloadComponent.cs#L230-L245](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/DownloadComponent.cs#L230-L245)、[DownloadManager.cs#L225-L243](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L225-L243)

### 3. 按 Tag 統計進度

把 Tag 當成「批次」維度，在 UI 上做整批進度展示：

```csharp
void Update()
{
    var infos = downloadComponent.GetDownloadInfos("asset-bundle");
    if (infos.Length == 0) return;

    long downloaded = 0, total = 0;
    foreach (var info in infos)
    {
        downloaded += info.DownloadedLength;
        total      += info.TotalLength;
    }
    progressBar.value = total > 0 ? (float)downloaded / total : 0f;
}
```

> `TaskInfo` 的欄位(`Status`、`Progress`、`DownloadedLength`、`TotalLength`、`Tag`、`SerialId` 等)由 `DownloadManager` 在任務生命週期內更新。

### 4. Editor Inspector 裡查看 Tag

開啟 `DownloadComponent` 的 Inspector,可以在 "Download Infos" 列表中直接看到 `Tag` 欄,用來核對任務是否被打到預期分組。

## 常見變體

| 場景 | 用法 |
|------|------|
| 同一批資源，優先級不同 | 用相同 `tag`,不同 `priority`,可以一起查、分開排程 |
| 資源版本號作 Tag | 例如 `tag = "v1.2.3"`,方便按版本整批升級 |
| 取消整批任務 | 取出 `TaskInfo[]` 的 `SerialId`,逐個 `RemoveDownload(serialId)` |
| 攜帶回呼上下文 | 用 `userData` 參數把回呼塞進任務，Tag 仍按業務分類 |

## 常見錯誤

| 現象 | 原因 | 修復 |
|------|------|------|
| `GetDownloadInfos(tag)` 始終回傳空 | 新增任務時沒傳 Tag,或 Tag 字串不一致(大小寫、空格) | 確認 `AddDownload` 用了帶 `tag` 的多載,並把 Tag 存為常數 |
| 同一檔案被加了多個 Tag 重複下載 | 不同 Tag 是獨立任務，框架不會自動去重 | 用一個全域字典按 `downloadUri` 查重,或固定使用同一個 Tag |
| 呼叫 `AddDownload` 擲出 `Download path is invalid.` / `Download uri is invalid.` | `downloadPath` 或 `downloadUri` 為空字串或 null | 呼叫前判空，Tag 不影響這兩個參數的驗證 |

錯誤訊息原文： [DownloadManager.cs#L360-L368](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.cs#L360-L368)

## 背景(選用)

`DownloadTask` 內部把 Tag 存為 `TaskBase.Tag`(字串欄位),`m_TaskPool` 按 Tag 維護任務集合,`GetDownloadInfos(tag)` 實際委派給 `m_TaskPool.GetTaskInfos(tag)`。Tag 只用於「分組 + 查詢」，不會影響下載優先級、並行數或失敗重試策略——這些行為由 `priority` 和 `DownloadComponent` 的全域參數決定。Source: [DownloadTask.cs](https://github.com/GameFrameX/com.gameframex.unity.download/blob/main/Runtime/Download/Download/DownloadManager.DownloadTask.cs)
