# ネットワークイベントの監視(接続/切断/エラー/ハートビート喪失)

本ページでは、ネットワークモジュールがスローする4種類のイベントの購読方法と処理方法について説明します:`NetworkConnectedEventArgs`(接続成功)、`NetworkClosedEventArgs`(接続クローズ)、`NetworkErrorEventArgs`(ネットワークエラー)、`NetworkMissHeartBeatEventArgs`(ハートビート喪失)。これらのイベントはすべて `GameFrameX.Event.Runtime.GameEventArgs` を継承しており、各型の静的フィールド `EventId`(値は型の完全名と等しい)を通じて購読を登録し、処理コールバック内でイベントが保持するフィールドを直接読み取るだけです。

## 前提条件

- GameFrameX ネットワークコンポーネントを導入済みであること(名前空間 `GameFrameX.Network.Runtime`)。
- イベント購読のエントリポイントは **GameFrameX.Event コンポーネント** が提供します(`GameEventArgs` 基クラスは `GameFrameX.Event.Runtime` にあり、このコンポーネントは本リポジトリには含まれません)。本ページに記載のイベント Id を購読する前に、プロジェクトでイベントコンポーネントが有効になっていることを確認してください。

## 操作手順

1. 監視したいイベントとその保持フィールドを確認します(いずれも `GameFrameX.Network.Runtime` 名前空間にあります):

| イベントクラス | 発生タイミング | 保持フィールド | EventId の値 |
|--------|----------|----------|------------|
| `NetworkConnectedEventArgs` | ネットワーク接続成功 | `NetworkChannel`(`INetworkChannel`)、`UserData`(`object`、接続時に渡されるカスタムデータ) | `GameFrameX.Network.Runtime.NetworkConnectedEventArgs` |
| `NetworkClosedEventArgs` | ネットワーク接続クローズ | `NetworkChannel`(完全なフィールドはソースファイルを参照) | `GameFrameX.Network.Runtime.NetworkClosedEventArgs` |
| `NetworkErrorEventArgs` | ネットワークエラー | `NetworkChannel`、`ErrorCode`(`NetworkErrorCode`)、`SocketErrorCode`(`System.Net.Sockets.SocketError`)、`ErrorMessage`(`string`) | `GameFrameX.Network.Runtime.NetworkErrorEventArgs` |
| `NetworkMissHeartBeatEventArgs` | ハートビートパケット喪失 | `NetworkChannel`、`MissCount`(`int`、喪失回数) | `GameFrameX.Network.Runtime.NetworkMissHeartBeatEventArgs` |

2. 各イベントクラスの**静的フィールド** `EventId` を使ってイベントコンポーネントにコールバックを登録します。文字列を手書きしないでください——`EventId` の定義こそが型の完全名です:

```csharp
/// <summary>
/// ネットワーク接続成功イベント番号。
/// </summary>
public static readonly string EventId = typeof(NetworkConnectedEventArgs).FullName;

/// <summary>
/// ネットワーク接続成功イベント番号を取得します。
/// </summary>
public override string Id
{
    get { return EventId; }
}
```

ソース: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L44-L54)

3. コールバック内でイベントの型ごとにフィールドを読み取ります。エラーイベントを例にとると、フレームワーク層のエラーコード、Socket 層のエラーコード、エラーメッセージを同時に取得できます:

```csharp
/// <summary>
/// ネットワークチャネルを取得します。
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// エラーコードを取得します。
/// </summary>
public NetworkErrorCode ErrorCode { get; private set; }

/// <summary>
/// Socket エラーコードを取得します。
/// </summary>
public SocketError SocketErrorCode { get; private set; }

/// <summary>
/// エラーメッセージを取得します。
/// </summary>
public string ErrorMessage { get; private set; }
```

ソース: [NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs#L68-L86)

4. ハートビート喪失時は `MissCount` で重大度を判断し(このカウントは連続喪失に伴い増加します)、`NetworkChannel` と組み合わせてどのチャネルかを特定します:

```csharp
/// <summary>
/// ネットワークチャネルを取得します。
/// </summary>
public INetworkChannel NetworkChannel { get; private set; }

/// <summary>
/// ハートビートパケットの喪失回数を取得します。
/// </summary>
public int MissCount { get; private set; }
```

ソース: [NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs#L65-L73)

5. コールバックの復帰後、**イベントオブジェクトをキャッシュしないでください**。イベントインスタンスは参照プールから取得され(`ReferencePool.Acquire` で生成、`Clear()` でフィールドをリセット)、フィールドはイベント配信後にクリアされます:

```csharp
public static NetworkConnectedEventArgs Create(INetworkChannel networkChannel, object userData)
{
    NetworkConnectedEventArgs networkConnectedEventArgs = ReferencePool.Acquire<NetworkConnectedEventArgs>();
    networkConnectedEventArgs.NetworkChannel = networkChannel;
    networkConnectedEventArgs.UserData = userData;
    return networkConnectedEventArgs;
}

/// <summary>
/// ネットワーク接続成功イベントをクリアします。
/// </summary>
public override void Clear()
{
    NetworkChannel = null;
    UserData = null;
}
```

ソース: [NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs#L77-L96)

## よくあるバリエーション

- **切断時の再接続**:`NetworkMissHeartBeatEventArgs`(`MissCount` が閾値を超えた場合)または `NetworkClosedEventArgs` のコールバック内でチャネル情報を記録し(アドレスなどは `NetworkChannel` から取得)、遅延後に再接続を開始します。接続結果はその後 `NetworkConnectedEventArgs` によって確認されます。
- **複数チャネルの区別**：複数の接続を同時に維持する場合、すべてのコールバックでまず `NetworkChannel`(チャネル名など)を比較してから処理し、チャネル A のエラーをチャネル B のものと取り違えないようにします。
- **エラーのレベル別表示**:`ErrorCode` で業務分岐を行い、`SocketErrorCode`/`ErrorMessage` をログや通知テキストに使用します。

## よくあるエラー

| 症状 | 原因 | 回避方法 |
|------|------|----------|
| 購読文字列を手書きしたらイベントを受け取れない | 文字列が実際の `EventId` と一致しない(名前空間を含む完全名の `GameFrameX.Network.Runtime.` プレフィックスに注意) | 必ず `NetworkConnectedEventArgs.EventId` のような静的フィールドを使って購読する |
| コールバックで読み取ったフィールドが `null` / `0` | イベントオブジェクトは参照プールからのもので、配信後に `Clear()` がフィールドをリセット済み | コールバック内で必要な値を直ちに読み取ってコピーし、イベントインスタンスをキャッシュしない |
| `SocketErrorCode` / `ErrorMessage` が参照できない | `System.Net.Sockets` 名前空間が導入されていない | 購読クラスのファイル先頭に `using System.Net.Sockets;` を追加する(エラーイベントのソースファイルでも同様に参照されています) |
| コンパイル時に `GameEventArgs` が見つからないというエラーが出る | イベントの基クラスは GameFrameX.Event コンポーネントにあり、本リポジトリには含まれない | 事前にイベントコンポーネントをインストール/有効化する |

## 背景

4つのイベント引数クラスはいずれも `sealed class ... : GameEventArgs` であり、コードストリッピングを防ぐために `[UnityEngine.Scripting.Preserve]` 属性が付与されています。静的な `Create(...)` で参照プールからインスタンスを取得し、`Clear()` で返却前にフィールドをリセットするというのは、フレームワーク全体で統一された「参照プールイベント」パターンであり、だからこそコールバック内での即時データ消費が求められます。イベントクラスのソースコードは `Runtime/EventArgs/` ディレクトリにあります([NetworkConnectedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkConnectedEventArgs.cs)、[NetworkClosedEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkClosedEventArgs.cs)、[NetworkErrorEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkErrorEventArgs.cs)、[NetworkMissHeartBeatEventArgs.cs](https://github.com/GameFrameX/com.gameframex.unity.network/blob/main/Runtime/EventArgs/NetworkMissHeartBeatEventArgs.cs));エラーコードの列挙型は `Runtime/Network/Base/NetworkErrorCode.cs`、ハートビート処理関連の基クラスは `Runtime/Network/Helper/BasePacketHeartBeatHandler.cs` および `Runtime/Network/Base/IHeartBeatMessage.cs` を参照してください。イベントの配信および購読 API は GameFrameX.Event コンポーネントに属しており、イベントコンポーネント全体の使用方法については、対応するドキュメントを参照してください。
