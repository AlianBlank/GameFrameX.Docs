# How to Show, Hide, and Display Web Pages in Full Screen

Call the `WebViewComponent` in the scene to show, hide, and display web pages in full screen: `Show(url)` shows and loads the specified URL, `Hide()` hides the current web page, and `MakeFullScreen()` puts the WebView into full screen.

## Prerequisites

- The `WebViewComponent` is mounted in the scene (component menu path: `Game Framework/WebView`, see [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L10-L13)).
- On `Awake`, the component obtains the manager via `GameFrameworkEntry.GetModule<IWebViewManager>()` and automatically calls `Initialize()` (see [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L22-L48)); if the retrieval fails, `Web View manager is invalid.` is logged — make sure the runtime module is ready first.

## Steps

1. Get a reference to the component (you can also drag the reference in the Inspector):

```csharp
using GameFrameX.WebView.Runtime;
using UnityEngine;

public class WebViewDemo : MonoBehaviour
{
    [SerializeField] private WebViewComponent webViewComponent;

    void Open()
    {
        webViewComponent.Show("https://example.com");
    }
}
```

2. Show and load a web page — call `Show` and pass in the target URL:

```csharp
/// <summary>
/// Show the WebView
/// </summary>
/// <param name="url">The URL to load</param>
public void Show(string url)
{
    _webViewManager.Show(url);
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L51-L58)

3. Hide the web page — call `Hide()`:

```csharp
/// <summary>
/// Hide
/// </summary>
public void Hide()
{
    _webViewManager.Hide();
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L77-L83)

4. Full screen display — call `MakeFullScreen()`:

```csharp
/// <summary>
/// Full screen
/// </summary>
public void MakeFullScreen()
{
    _webViewManager.MakeFullScreen();
}
```

Source: [WebViewComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/WebViewComponent.cs#L60-L66)

5. Verify: after calling `Show`, the web view should appear on the device; after calling `Hide`, the web view disappears; after calling `MakeFullScreen`, the WebView covers the entire screen.

## API Quick Reference

| Method | Signature | Description |
|------|------|------|
| Show | `void Show(string url)` | Shows the WebView and loads the specified URL |
| Full screen | `void MakeFullScreen()` | Switches the WebView to full screen display |
| Hide | `void Hide()` | Hides the currently displayed WebView |
| Execute script | `void ExecuteJavaScript(string javaScript)` | Executes JavaScript code in the web page |
| Initialize | `void Initialize()` | Initializes the WebView module |

These signatures are defined in both the interface [IWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/IWebViewManager.cs#L12-L40) and the abstract base class [BaseWebViewManager.cs](https://github.com/GameFrameX/com.gameframex.unity.webview/blob/main/Runtime/BaseWebViewManager.cs#L11-L39); `WebViewComponent` is the wrapping entry point for them.

## Common Variants

- **Go full screen right after showing**: call `Show(url)` first, then `MakeFullScreen()`; simply execute the two calls in order.
- **Execute a script inside the web page together with a hide animation**: call `ExecuteJavaScript(javaScript)` to let the page wrap up first, then call `Hide()`.

## Common Errors

- **The log shows `Web View manager is invalid.`**: `_webViewManager` is null, meaning the runtime module is not ready (the component returns early when `IsRuntimeComponentReady` is false). Check that the GameFrameX runtime and the WebView implementation assemblies are correctly installed.
- **Null reference when calling Show/Hide/MakeFullScreen in `Awake`**: the component only calls `Initialize()` in `Start`; trigger these methods later in the lifecycle (after `Start`) or in user interaction callbacks.

## Background

`WebViewComponent` is a partial class of `GameFrameworkComponent`; it does not implement web page logic itself but only forwards calls to `IWebViewManager` (a derived implementation of `BaseWebViewManager`). Therefore, when integrating with different platforms, you only need to swap the manager implementation while the component-level API remains unchanged.
