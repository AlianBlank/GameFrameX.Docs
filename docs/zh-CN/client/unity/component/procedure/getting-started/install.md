# 安装 Procedure 包

本指南介绍如何把 `com.gameframex.unity.procedure` 安装到一个 Unity 项目中,以便启用基于 FSM 的游戏流程管理能力。安装完成后即可使用 `ProcedureComponent`、`ProcedureManager`、`ProcedureBase` 来驱动游戏生命周期阶段。

## 前置条件

- Unity **2019.4** 或更高版本(本包声明的 Unity 版本见 [package.json](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/package.json#L7))。
- 项目中需要 `com.gameframex.unity`(`2.5.1`)与 `com.gameframex.unity.fsm`(`1.2.0`)两个依赖;通过本仓库的安装方式引入时,Unity Package Manager 会自动解析并拉取依赖。

```json
"dependencies": {
  "com.gameframex.unity.fsm": "1.2.0",
  "com.gameframex.unity": "2.5.1"
}
```
Source: [package.json](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/package.json#L22-L25)

## 操作步骤

任选其一即可完成安装。

### 方式一:Scoped Registry(UPM 注册表)

1. 打开 Unity 项目的 `Packages/manifest.json`。
2. 在文件顶层添加 `scopedRegistries` 节点,并在 `dependencies` 中加入本包:

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ],
  "dependencies": {
    "com.gameframex.unity.procedure": "1.4.1"
  }
}
```

3. 保存后回到 Unity,Package Manager 会自动通过 `GameFrameX` 注册表解析 `com.gameframex` 开头的包。

> `scopes` 决定哪些包走该注册表,只解析 `com.gameframex.*`,不会影响其他来源。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L57-L75)

### 方式二:Git URL 依赖

在 `Packages/manifest.json` 的 `dependencies` 节点下直接添加 Git 远程地址:

```json
{
  "dependencies": {
    "com.gameframex.unity.procedure": "https://github.com/gameframex/com.gameframex.unity.procedure.git"
  }
}
```

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L77-L82)

### 方式三:Unity Package Manager 添加 Git URL

1. 打开 Unity,选择菜单 `Window > Package Manager`。
2. 点击左上角 `+`,选择 `Add package from git URL...`。
3. 输入地址: `https://github.com/gameframex/com.gameframex.unity.procedure.git`,点击 `Add`。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L83-L83)

### 方式四:直接放入 Packages 目录

将本仓库直接克隆或下载后,放置到 Unity 项目的 `Packages/` 目录下(例如 `Packages/com.gameframex.unity.procedure`),Unity 会自动作为本地包加载识别。

Source: [README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.procedure/blob/main/README.zh-CN.md#L84-L84)

## 常见变体

- **锁定具体版本**:在 manifest 中用 `"com.gameframex.unity.procedure": "1.4.1"` 这样的精确版本号,避免自动升级破坏流程逻辑;`package.json` 中当前版本为 `1.4.1`。
- **固定到 Git 标签/分支**:在 Git URL 形式后追加 `#1.4.1` 或 `#main`,例如 `https://github.com/gameframex/com.gameframex.unity.procedure.git#1.4.1`,便于回滚或跟随开发。
- **本地路径调试**:把仓库作为本地路径包写入 manifest(`"file:../com.gameframex.unity.procedure"`),方便边改边调试。

## 常见错误

- **未声明 `scopedRegistries` 就直接写依赖**:会让 UPM 去默认 npm 解析 `com.gameframex.*`,从而安装失败。先按方式一添加注册表再写依赖即可。
- **scope 写错**:必须使用 `com.gameframex`,与 `package.json` 中的 `name` 前缀保持一致;否则包不会从该注册表解析。
- **同时引入多个 ProcedureComponent 副本**:确保 `Packages/` 下只存在一份本包源码,避免 `Already exist FSM` 之类的冲突。
- **Unity 版本过低**:`unity` 字段声明为 `2019.4`,低于该版本的 Unity 可能无法编译或运行包内脚本。

## 验证

1. 在 Unity 中打开 `Window > Package Manager`,确认列表里出现 `Game Frame X Procedure`,版本与预期一致。
2. 在项目中创建任意 C# 脚本,输入 `using GameFrameX.Procedure;`,若编译通过则说明包已正确就位。
3. 通过菜单 `GameFrameX > Procedure` 添加 `ProcedureComponent`,能看到 Inspector 配置项即代表运行时可用。
