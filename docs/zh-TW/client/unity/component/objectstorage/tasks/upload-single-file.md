# 如何上傳單一檔案

透過 `ObjectStorageUploadFactory.Create<T>` 建立上傳管理器並呼叫 `UploadFile`,即可把本機單一檔案上傳到物件儲存的指定路徑，傳回 `bool` 表示成功與否。

## 前置條件

- 已安裝 `GameFrameX.ObjectStorage` 套件及其對應的物件儲存後端實作(例如阿里雲 OSS、騰訊雲 COS 等，這些後端提供繼承 `BaseObjectStorageUploadManager` 的具體類型)。
- 已準備好 `accessKey`、`secretKey`、`bucketName`,如目標服務需要，還需要 `endpoint`。
- 待上傳的檔案在本機存在，且有可讀的絕對路徑。

## 操作步驟

1. 透過工廠建立並初始化上傳管理器。`Create<T>` 內部會呼叫 `Init`,無需再手動初始化:

```csharp
using GameFrameX.ObjectStorage.Editor;

IObjectStorageUploadManager uploader = ObjectStorageUploadFactory.Create<YourUploader>(
    accessKey: "your-access-key",
    secretKey: "your-secret-key",
    bucketName: "your-bucket",
    endpoint: "https://oss-cn-hangzhou.aliyuncs.com" // 部分服務可傳 null
);
```

2. (可選)使用 `SetSavePath` 設定儲存桶內的目標子目錄。傳入路徑若以分隔符號結尾，會被自動去掉結尾分隔符號:

```csharp
uploader.SetSavePath("assets/textures/");
```

3. 呼叫 `UploadFile` 上傳單一檔案，傳入完整的本機檔案路徑:

```csharp
bool ok = uploader.UploadFile(@"D:\project\Assets\textures\logo.png");
if (ok)
{
    UnityEngine.Debug.Log("上传成功");
}
else
{
    UnityEngine.Debug.LogError("上传失败");
}
```

4. 根據傳回值判斷結果。`UploadFile` 傳回 `true` 表示成功，`false` 表示失敗。

## 常見變體

- **自訂儲存路徑**：如果希望檔案落到儲存桶下的某個子目錄，在上傳前呼叫 `uploader.SetSavePath("your/sub/path")`。
- **批次上傳**：單次僅上傳一個檔案，如需批次請改用 `UploadDirectory(string localDirectory)`(詳見介面定義)。
- **不同後端**：只需把 `Create<T>` 的泛型替換為對應後端的具體管理器類型，例如 `YourCosUploader`、`YourMinioUploader` 等。

## 常見錯誤

| 症狀 | 可能原因 | 處理 |
|------|---------|------|
| `UploadFile` 傳回 `false` | 本機路徑不存在或沒有讀取權限 | 確認 `localFilePathAndName` 是合法絕對路徑，檔案可讀 |
| 工廠呼叫拋出例外 | 泛型類型未實作 `IObjectStorageUploadManager` | 確認 `T` 繼承自 `BaseObjectStorageUploadManager` |
| 檔案上傳到了根目錄而不是預期子目錄 | 未呼叫 `SetSavePath` 或參數拼字錯誤 | 在 `UploadFile` 之前明確呼叫 `SetSavePath` |
| 路徑結尾多餘分隔符號 | `SetSavePath` 結尾帶 `/` | 框架已自動去除，無需手動處理，但避免傳空字串 |

## 背景(可選)

介面 `IObjectStorageUploadManager` 在 `BaseObjectStorageUploadManager` 中提供 `UploadFile` 的預設實作，實際邏輯由後端子類別的 `UploadFileInternal` 完成;`Create<T>` 透過 `Activator.CreateInstance` 實例化並自動呼叫 `Init`,因此呼叫方只需關心檔案路徑與傳回結果。
