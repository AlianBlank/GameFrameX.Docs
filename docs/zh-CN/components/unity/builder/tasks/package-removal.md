# 如何移除无用 Unity 包

通过本工具可以一次性从 `Packages/manifest.json` 移除指定依赖,并删除 `Packages/` 下对应的本地包目录,完成清理后自动调用 `AssetDatabase.Refresh()`。整个流程在 Unity Editor 中通过命令行参数触发。

## 前置条件

- Unity 项目根目录存在 `Packages/manifest.json`(标准 UPM 项目)。
- 命令行调用方能在进程参数中传入 `-RemovePackages` 参数(批处理、CI、菜单调用均可)。
- 需要 `Newtonsoft.Json`(`manifest.json` 的解析依赖该库,Editor 程序集已自带引用)。

## 操作步骤

1. 准备好要移除的包名列表。包名须与 `manifest.json` 中 `dependencies` 下的 key 完全一致(例如 `com.unity.xr.management`)。
2. 在 Unity Editor 命令行中传入 `-RemovePackages` 参数,后面跟用半角逗号分隔的包名列表。
3. 触发 `PackageRemovalHelper.Run()`,工具会按以下顺序执行:
   - 解析命令行参数,得到待移除包列表;若未传 `-RemovePackages` 直接抛异常。
   - 从 `manifest.json` 的 `dependencies` 中删除对应条目,并以临时文件方式原子写回。
   - 删除 `Packages/<包名>` 本地目录(嵌入包 / file:// 引用包)。
   - 调用 `AssetDatabase.Refresh()。

## 常见变体

- **只清 `manifest.json`,不删本地目录**:工具会逐个判断 `dependencies[packageName]` 是否存在;manifest 中没有的条目只打 `Debug.Log` 跳过,不报错。
- **只删本地嵌入包目录**:未列入 `manifest.json` 但放在 `Packages/` 下的本地文件夹,工具会删除对应目录;反之亦然——两项操作互相独立。
- **路径安全保护**:包名包含 `/`、`\`、`:` 或 `..` 时会被识别为非法并跳过,不会越界到 `Packages/` 之外。

```csharp
if (string.IsNullOrWhiteSpace(packageName) ||
    packageName.IndexOfAny(new[] { '/', '\\', ':' }) >= 0 ||
    packageName.Contains(".."))
{
    Debug.LogWarning($"[PackageRemoval] 包名不合法，跳过: {packageName}");
    continue;
}
```

## 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 抛异常 `未检测到 -RemovePackages 参数。用法: -RemovePackages 包名1,包名2,包名3` | 未在命令行传入 `-RemovePackages` 或忘记带值 | 在调用参数中追加 `-RemovePackages 包名1,包名2` |
| 控制台输出 `[PackageRemoval] manifest.json 中未找到依赖，跳过: xxx` | `manifest.json` 中没有该条目(可能只存在于 `Packages/` 子目录) | 确认包名与 `manifest.json` 的 key 完全一致;只删本地目录是允许的 |
| `[PackageRemoval] manifest.json 不存在: ...` | 项目不是 UPM 工程或路径被改写 | 确认 `Packages/manifest.json` 位于项目根 |
| `[PackageRemoval] 包名不合法，跳过: xxx` | 名字含 `/`、`\`、`:` 或 `..` | 仅使用纯包名(如 `com.example.foo`),不要带版本号或路径前缀 |
| `[PackageRemoval] 本地包目录不存在，跳过: xxx` | 仅声明在 `manifest.json` 的远程依赖,本地无目录 | 属正常情况,无需处理 |

## 背景(可选)

工具采用「先改 manifest,再删本地目录,最后 `AssetDatabase.Refresh`」的顺序,确保 Unity 在下一次资源刷新时不会再尝试解析已删除的嵌入包。`manifest.json` 通过 `*.tmp` 中转再覆盖的方式写入,避免半截写入造成 JSON 损坏。
