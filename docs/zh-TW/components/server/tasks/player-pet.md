# 實作玩家寵物(Pet)模組

玩家寵物(Pet)模組以元件形式掛載在玩家 Actor 上,負責儲存寵物的執行階段狀態並回應寵物相關事件；本節帶你從空模組開始，實作出一個可註冊、可擴充的寵物元件骨架。

## 前置條件

- 已建立玩家 Actor(`ActorType = GlobalConst.ActorTypePlayer`)。
- 已引入 `GameFrameX.Core.Abstractions.Attribute`、`GameFrameX.Utility.Setting`、`GameFrameX.Core.Components`。
- 了解框架的 `StateComponent<TState>` 與 `StateComponentAgent<TComponent, TState>` 雙層結構(Apps 層定義與狀態，Hotfix 層撰寫邏輯)。

}

## 常見變體

- **回應獲得寵物事件**：在 `PetComponentAgent` 中新增私有非同步方法處理 `EventId.GotNewPet`,並透過巢狀 `EventListener<T>` 類別訂閱事件(參考 [PetComponentAgent.cs](https://github.com/GameFrameX/GameFrameX.Server/blob/main/GameFrameX.Hotfix/Logic/Player/Pet/PetComponentAgent.cs#L8-L28) 中的註解範例)。
- **跨元件呼叫**：在 `PetComponentAgent` 內透過 `ActorManager.GetComponentAgent<ServerComponentAgent>()` 取得其他元件代理，例如讀取世界等級以決定寵物屬性。
- **寵物資料欄位**：直接在 `PetState` 中新增可序列化屬性(如寵物 ID、等級、經驗)，框架會自動參與存檔與快取。

## 常見錯誤

- **Agent 命名空間不一致**:`PetComponentAgent` 目前所在命名空間是 `GameFrameX.Hotfix.Logic.Role.Pet`,而 Apps 層是 `GameFrameX.Apps.Player.Pet.*`,複製貼上範例時務必保留各自的命名空間，避免框架反射失敗。
- **忘記加 `[ComponentType]`**:`PetComponent` 沒有標記 `ActorTypePlayer` 時，不會被掛載到玩家 Actor 上，執行期表現為寵物功能完全無效。
- **把業務邏輯寫在 Apps 層**：Apps 層會在打包時進入主組件，無法熱更新；所有可變邏輯必須放在 Hotfix 層的 `PetComponentAgent`。

## 背景(選用)

`PetComponent` 採用的是框架的「元件 + 狀態 + 代理」三合一組合:`StateComponent<TState>` 僅宣告狀態歸屬與生命週期，實際業務執行在 `StateComponentAgent<TComponent, TState>` 中，兩者透過泛型參數配對;`[ComponentType]` 決定該元件被框架註冊到哪一類 Actor 上。
