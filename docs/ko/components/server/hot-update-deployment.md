# 핫업데이트 패키지를 게시하고 적용을 확인하는 방법

핫업데이트를 한 번 게시하는 데는 세 단계만 필요합니다: `GameFrameX.Hotfix.dll`을 컴파일하고, DLL을 서버의 고정 디렉터리에 배포한 후, Reload HTTP 인터페이스를 호출하여 로드를 트리거합니다. 적용 여부는 반환된 버전 번호와 서버 로그를 확인하여 검증합니다.

## 사전 조건

- 서버에서 GameFrameX 서비스가 실행 중이며 HTTP 포트(기본 `28080`)에 접근 가능해야 합니다
- 비즈니스 코드 수정이 완료되었고 로컬에서 컴파일이 통과되어야 합니다
- 대상 머신에 핫업데이트 DLL 배포 디렉터리가 확정되어 있어야 합니다(이하에서는 `/opt/gameframex/hotfix/`를 예로 사용)

## 작업 단계

1. **새 버전 Hotfix 어셈블리 컴파일**

   솔루션 루트 디렉터리에서 실행:

   ```bash
   dotnet build GameFrameX.Hotfix/GameFrameX.Hotfix.csproj -c Release
   ```

   빌드 산출물 경로: `GameFrameX.Hotfix/bin/Release/net10.0/GameFrameX.Hotfix.dll`.

2. **DLL을 서버의 지정된 디렉터리에 배포**

   빌드 산출물을 의존성(새로 추가된 NuGet 패키지가 있는 경우)과 함께 서버의 핫업데이트 디렉터리로 복사합니다:

   ```bash
   scp GameFrameX.Hotfix/bin/Release/net10.0/GameFrameX.Hotfix.dll \
       user@server:/opt/gameframex/hotfix/
   ```

3. **핫업데이트 HTTP 인터페이스 트리거**

   ```bash
   curl -X POST "http://<server-ip>:28080/game/api/Reload?version=1.7.2"
   ```

   서버가 반환하는 `version`이 현재 적용 중인 버전 번호입니다.

4. **적용 확인**

   - 동일한 인터페이스에 다시 GET을 호출하거나 로그를 확인하여 버전 번호가 `1.7.2`로 업데이트되었는지 확인합니다
   - 서버 로그에서 `HotfixManager`가 새 어셈블리를 로드하고, `HotfixModule`이 에이전트/핸들러/이벤트 리스너를 스캔한 기록을 확인합니다
   - 새 로직에 도달하는 비즈니스 요청을 한 번 실행하여 동작이 예상과 일치하는지 검증합니다

## 일반적인 변형

- **Docker 환경 배포**: DLL을 컨테이너에 마운트된 볼륨 디렉터리로 복사합니다(예: `docker cp GameFrameX.Hotfix.dll game:/app/hotfix/`). 그 후 호스트 머신의 매핑 포트 `38080`으로 호출합니다.
- **다중 인스턴스 클러스터**: 각 `game-1` ~ `game-N` 노드에 대해 2단계와 3단계를 반복하거나, 구성 관리 도구를 활용해 일괄 배포합니다.
- **일부 Agent만 업데이트**: 전체 DLL을 다시 게시할 필요 없이, `GameFrameX.Hotfix` 프로젝트에서 해당 `*Agent.cs`만 수정한 뒤 다시 빌드하여 배포하면 됩니다.

## 일반적인 오류

| 증상 | 원인 | 해결 방법 |
|:-----|:-----|:-----|
| Reload 인터페이스가 500 또는 타임아웃 반환 | 새 DLL에 의존 어셈블리가 누락됨 | 새로 추가된 NuGet 의존성을 핫업데이트 디렉터리에 함께 복사 |
| Reload는 성공했으나 버전 번호가 변경되지 않음 | HTTP 주소가 game 서비스를 가리키지 않거나 포트 오류 | 호출 대상이 `game` 서비스의 HTTP 포트(기본 `28080`, 호스트 매핑 `38080`)인지 확인 |
| Reload 후 비즈니스 동작이 변하지 않음 | 수정한 코드가 `Hotfix` 레이어가 아닌 `Apps`(핫업데이트 불가) 레이어에 있음 | `GameFrameX.Hotfix` 아래의 `*Agent.cs`, Handler, EventHandler만 핫업데이트 가능하며, 영속 상태는 `Apps` 레이어에 있음 |
| 이전 요청이 처리 도중 중단됨 | 유예 기간이 끝나기를 기다리지 않고 서비스를 재시작함 | 이전 어셈블리는 기본적으로 10분의 유예 기간 동안 유지되므로, 로그에 언로드 완료가 표시된 후 작업 진행 |

## 배경(선택 사항)

핫업데이트는 수집 가능한 `AssemblyLoadContext`를 통해 새 DLL을 로드하며, 로드가 완료되면 `HotfixModule`이 에이전트, 핸들러, 이벤트 리스너를 스캔한 다음 `ActorManager.ClearAgent()`를 호출하여 캐시된 에이전트 인스턴스를 제거합니다. Apps 레이어(`StateComponent`, 영속 상태)는 핫업데이트할 수 없으며, 이는 핫업데이트 경계의 엄격한 제약 사항입니다.
