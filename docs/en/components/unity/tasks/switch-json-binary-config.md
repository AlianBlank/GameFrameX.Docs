# How to Switch Between JSON and Binary Configuration

In GameFrameX, the table data classes under `Hotfix/Config/Generate/Tables/` (generated by the LuBan tool) use `SimpleJSON.JSONNode` as the deserialization entry point; at runtime, `TablesComponent` registers each table into `ConfigComponent`. This page explains how to switch between the two sources: "JSON configuration" and "binary configuration".

## Prerequisites

- `com.gameframex.unity.json.simplejson` has been introduced via the GameFrameX scoped registry in `Packages/manifest.json` (see [README.zh-CN.md](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/README.zh-CN.md#L40-L80)).
- The project already contains `Assets/Hotfix/Config/Generate/Tables/TablesComponent.cs`, and table classes such as `ItemConfig`, `AchievementConfig`, and `SoundsConfig` have been generated via the LuBan tool (see [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86)).
- The runtime framework package `com.gameframex.unity.config` is installed, providing `ConfigComponent` and `BaseDataTable<T>` (see [link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28)).

## Steps

1. Confirm the deserialization constructor signature of the table classes. All table classes produced by the generator provide a constructor that accepts a `SimpleJSON.JSONNode`, used to deserialize JSON into table objects.

```csharp
// Source: LuBan generated code
public ItemConfig(JSONNode _buf)
{
    { if(!_buf["id"].IsNumber) { throw new SerializationException(); }  Id = _buf["id"]; }
    { if(!_buf["Name"].IsString) { throw new SerializationException(); }  Name = _buf["Name"]; }
    // ... remaining fields omitted
    PostInit();
}

public static ItemConfig DeserializeItemConfig(JSONNode _buf)
{
    return new Tables.ItemConfig(_buf);
}
```

Source: [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L86)

2. Register each table into `ConfigComponent` within `TablesComponent`. In the default implementation, all tables are loaded asynchronously via `TbXxxConfig.LoadAsync()` and registered with the table name as the key (see [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L52-L70)).

```csharp
m_ConfigComponent.RemoveAllConfigs();
var loadTasks = new System.Collections.Generic.List<System.Threading.Tasks.Task>();
loadTasks.Add(TbItemConfig.LoadAsync());
m_ConfigComponent.Add(nameof(Tables.TbItemConfig), TbItemConfig);
```

3. Switch to the JSON configuration source (default approach). Keep the existing generated code unchanged; simply export the data as JSON files and hand them to LuBan to load. The generator-produced `DeserializeXxxConfig(JSONNode)` accepts JSON text directly, so no additional conversion is needed at runtime.

4. Switch to the binary configuration source (performance-first approach). When the hot update package or the initial package only provides binary data, first decode the binary stream into a `JSONNode` at the loading entry point, then follow the same `DeserializeXxxConfig` path, ensuring zero changes to the downstream table classes. For example:

```csharp
using SimpleJSON;
using System.Text;

// Assume bytes is the binary configuration bundle obtained from YooAsset
JSONNode node = JSON.Parse(Encoding.UTF8.GetString(bytes));
var item = Tables.ItemConfig.DeserializeItemConfig(node);
```

Key point: the deserialization entry point remains `DeserializeXxxConfig(JSONNode)`, so switching between JSON and binary is equivalent to "normalizing the data into a JSONNode at the loading stage". The table classes themselves do not need to be regenerated.

5. Retrieve configuration at runtime via `ConfigComponent.GetConfig<T>()`. Regardless of whether the underlying source is JSON or binary, as long as the table name was registered during `TablesComponent.Add`, the business layer call remains the same:

```csharp
var itemConfig = GameFrameX.Config.Runtime.ConfigComponent.Instance
    .GetConfig<Tables.ItemConfig>();
```

## Common Variants

- **Switching by platform during the hot update phase**: On Android, the initial package uses binary compressed bundles to reduce package size; on iOS or during development, JSON is used for easier troubleshooting. Simply select the loading source based on the platform before `TablesComponent.Init`, and pass the resulting `JSONNode` into `DeserializeXxxConfig`.
- **Localization configuration**: Generated tables (e.g., `TbLocalization`) go through exactly the same registration process; see `m_ConfigComponent.Add(nameof(Local.TbLocalization), TbLocalization)` in [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L70).

## Common Mistakes

- **Directly modifying generated table classes**: The generator will overwrite `Assets/Hotfix/Config/Generate/Tables/*.cs`; all custom logic should be placed in `partial` classes or in the business layer.
- **Failing to regenerate after changing field names**: The field names in `_buf["xxx"]` are case-sensitive (note that `id` is lowercase, `Name` is uppercase, and `description` is lowercase); inconsistent fields will trigger a `SerializationException` (see [ItemConfig.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/Tables/ItemConfig.cs#L48-L74)).
- **Forgetting to call `m_ConfigComponent.Add`**: If only `LoadAsync()` is called without registering the table name, `GetConfig<T>()` will return empty. See the registration process in [TablesComponent.cs](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/Config/Generate/TablesComponent.cs#L56-L69).
- **HybridCLR AOT stripping issues**: When adding non-generic reflection targets, confirm that `ConfigComponent`/`BaseDataTable<T>` are preserved in link.xml (see [link.xml](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/HybridCLRData/Generated/link.xml#L26-L28)).

## Background (Optional)

The LuBan table generator's output uniformly uses `SimpleJSON.JSONNode` as the deserialization entry point; this step confines the difference between "data coming from JSON or binary" to the loading layer. `TablesComponent` is responsible for registering each table into `ConfigComponent`, while the business layer uniformly retrieves data via `ConfigComponent.GetConfig<T>()`, so switching data sources requires no changes on the consumer side. For the overall location of the LuBan generator and the configuration pipeline, see `Assets/Hotfix/Config/Generate/` in the project.
