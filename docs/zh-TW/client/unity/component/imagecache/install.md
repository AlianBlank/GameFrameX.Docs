# 快速開始

本節將引導您將 GameFrameX.ImageCache 導入 Unity 專案，並完成「遠端圖片非同步載入 → 快取命中 → 主動清除」這一最小流程的運行。

## 前置條件

- Unity **2019.4 或以上版本**（套件內 `package.json` 中宣告的最低版本）。
- 已安裝 GameFrameX 框架基礎套件 `com.gameframex.unity`（1.1.1 或以上版本）。
- 在非 WebGL 平台上，還需要 `com.gameframex.unity.download` 來提供 `IDownloadManager`。

## 操作步驟

### 1. 新增 scopedRegistries

編輯位於專案根目錄的 `Packages/manifest.json`，在最頂層新增 `GameFrameX` registry：

```json
{
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": [
        "com.gameframex"
      ]
    }
  ]
}
```

`scopes` 會限制只有以 `com.gameframex` 開頭的套件才會從這個 registry 解析，以避免污染其他套件的來源。

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L48-L62)

### 2. 新增相依套件

在同一個 `manifest.json` 的 `dependencies` 節點中新增 ImageCache：

```json
{
  "dependencies": {
    "com.gameframex.unity.imagecache": "0.0.1"
  }
}
```

儲存後，Unity Package Manager 會自動解析並安裝該套件，同時也會一併納入 `com.gameframex.unity` 與 `com.gameframex.unity.download` 這兩個遞移相依套件。

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L64-L72)

### 3. 確認安裝

回到 Unity Editor，開啟 **Window → Package Manager**，確認清單中有顯示 **Game Frame X Image Cache**（`com.gameframex.unity.imagecache`）。

套件中繼資料中記載的執行階段相依套件如下。缺少任何一項都會導致編譯失敗：

| 套件名稱 | 版本 | 用途 |
|------|------|------|
| `com.gameframex.unity` | 1.1.1 | 框架基礎元件（`GameEntry.GetComponent<T>`） |
| `com.gameframex.unity.download` | 1.1.1 | 提供 `IDownloadManager`（非 WebGL 平台的下載） |

來源：[package.json](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/package.json#L24-L27)

### 4. 載入一張圖片

只要從任意腳本透過 `GameEntry` 取得圖片快取元件，即可非同步載入遠端圖片：

```csharp
// 取得圖片快取元件
var imageCache = GameEntry.GetComponent<ImageCacheComponent>();

// 非同步載入遠端圖片
Texture2D texture = await imageCache.LoadImageAsync("https://example.com/image.png");
```

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L78-L83)

### 5. 確認與清除快取

```csharp
// 確認圖片是否已快取
bool cached = imageCache.IsCached("https://example.com/image.png");

// 刪除指定的快取
imageCache.RemoveCache("https://example.com/image.png");

// 清除所有快取
imageCache.ClearCache();
```

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L85-L92)

## 常見變化

### WebGL 平台

由於 WebGL 沒有可寫入的本機磁碟，元件會切換為使用 `UnityWebRequestTexture`，快取由瀏覽器自行管理。**請勿依賴**以 `IsCached` / `ClearCache` 進行的事前判斷或清除。

| 平台 | 載入方式 | 快取歸屬 |
|------|---------|----------|
| iOS / Android / Windows / macOS | `IDownloadManager` + 磁碟 | 本元件 |
| WebGL | `UnityWebRequestTexture` | 瀏覽器 |

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.imagecache/blob/main/README.zh-CN.md#L97-L100)

## 常見錯誤

- **找不到 `ImageCacheComponent` 型別**：這表示 `GameFrameX` 基礎套件未啟用。請先確認 `com.gameframex.unity` 已安裝並註冊至框架中。
- **在非 WebGL 平台的建置中找不到 `IDownloadManager`**：缺少對 `com.gameframex.unity.download` 的相依性。新增此套件即可解決。
- **WebGL 平台上 `ClearCache` 不生效**：這是預期行為。由於 WebGL 的快取由瀏覽器持有，必須透過瀏覽器本身或 HTTP 快取標頭進行控制。

## 背景（選讀）

ImageCache 透過 `IDownloadManager` 將遠端圖片下載到本機，檔案名稱以 URL 的 MD5 為基礎，因此從一開始就已完成去重。`Texture2D` 實例由呼叫端持有，元件僅負責位元組的持久化與命中判斷，因此業務端無需在意平行下載的問題。
