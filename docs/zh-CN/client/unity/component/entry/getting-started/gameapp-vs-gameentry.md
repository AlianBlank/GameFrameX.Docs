# 如何选择 GameApp 与 GameEntry 两种访问方式

GameFrameX 提供了两种获取框架组件的方式:`GameEntry` 是组件容器的底层入口(由 `GameFrameX.Runtime` 包提供),`GameApp` 是本仓库基于 `GameEntry` 封装的"静态门面(facade)",以属性方式暴露常用组件。简单说:业务代码调用 `GameApp.XXX`,`GameApp` 内部统一走 `GameEntry.GetComponent<XXXComponent>()`。

## 前置条件

- 已安装 `com.gameframex.unity.entry`(本仓库)
- 已安装 `com.gameframex.unity.runtime`,因为 `GameEntry` 类型定义在 `GameFrameX.Runtime` 命名空间下

```csharp
using GameFrameX.Runtime; // 提供 GameEntry
// GameApp 位于全局命名空间,无需 using
```

Source: [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L32-L34)

## 两种访问方式的形态对比

| 维度 | `GameEntry` | `GameApp` |
|------|-------------|-----------|
| 所在命名空间 | `GameFrameX.Runtime`(外部包) | 全局命名空间(本仓库) |
| 类型 | 静态类,提供组件容器 | `static partial class`,每个组件一个文件 |
| 调用形式 | `GameEntry.GetComponent<T>()` | `GameApp.<属性名>` |
| 典型用途 | 注册自定义组件、按需取任意组件 | 高频常用组件的快捷访问 |

`GameApp` 的属性 getter 实现就是简单包了一层 `GameEntry.GetComponent<T>()`,并把结果缓存到私有静态字段:

```csharp
public static partial class GameApp
{
    public static BaseComponent Base
    {
        get
        {
            if (_base == null)
            {
                _base = GameEntry.GetComponent<BaseComponent>();
            }
            return _base;
        }
    }
    private static BaseComponent _base;
}
```

## 选择建议

1. **日常业务开发,优先用 `GameApp`**
   - 代码更短,可读性更好:`GameApp.Base`、`GameApp.Mono`。
   - 不需要记组件的具体类型名,IDE 自动补全即列出当前包已封装的组件。
   - 命中缓存后是字段读取,几乎零开销。

2. **需要访问本仓库未封装的组件,直接用 `GameEntry`**
   - 例如你自定义了一个 `MyComponent` 注册进框架,只能用 `GameEntry.GetComponent<MyComponent>()`。
   - 在跨包/跨模块边界写代码时,优先用 `GameEntry`,避免对 `GameApp` 形成硬依赖。

3. **注册新组件时,二者都要改一处**
   - 通过 `GameEntry.RegisterComponent<T>()` 完成注册后,如果你希望业务侧能用 `GameApp.My` 这种属性访问,就在本仓库新增一个 `GameApp.My.cs` partial 文件,按上面的模板包一层 getter 与缓存字段即可。

## 操作步骤:新增一个 `GameApp` 属性

1. 在 `Runtime/` 下新增 `GameApp.My.cs`(必须用 `partial`,且与 `GameApp` 同命名空间)。

```csharp
public static partial class GameApp
{
    public static MyComponent My
    {
        get
        {
            if (_my == null)
            {
                _my = GameEntry.GetComponent<MyComponent>();
            }
            return _my;
        }
    }

    private static MyComponent _my;
}
```

2. 在框架启动流程里用 `GameEntry.RegisterComponent<MyComponent>()` 完成注册。
3. 业务侧直接 `GameApp.My.DoSomething()` 即可。

Source: 模板参考 [Runtime/GameApp.cs](https://github.com/GameFrameX/com.gameframex.unity.entry/blob/main/Runtime/GameApp.cs#L34-L53)

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| `GameApp.Base` 拿到 `null` / 抛异常 | 框架还未启动完成,或对应组件没有 `RegisterComponent` | 检查启动流程是否调用了 `RegisterComponent<BaseComponent>`;热更新/重启场景注意时序 |
| 编译报错 `GameEntry` 不存在 | 没有 `using GameFrameX.Runtime;` | 在文件顶部加 `using GameFrameX.Runtime;` |
| 找不到 `GameApp.Mono` 等属性 | 当前用的不是 `com.gameframex.unity.entry` 包,或包版本较老未包含对应 partial 文件 | 升级本包到最新版本 |
| 自己写的 `GameApp.My` 报错 `missing partial` | 新文件没有声明 `public static partial class GameApp` | 补上 `partial` 关键字并与已有 `GameApp` 同名 |

## 背景(可选)

`GameEntry` 维护了一个组件字典(`RegisterComponent` / `GetComponent<T>()`),是框架组件的"容器根"。`GameApp` 不做实际工作,只是把高频组件取出来缓存到静态字段,让调用方少写一次泛型、少拼一次类名。两种方式访问的是同一份组件实例。
