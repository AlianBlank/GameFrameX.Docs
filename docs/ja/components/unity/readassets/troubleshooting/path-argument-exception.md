# ファイル読み込みエラー:ArgumentNullException / ArgumentException(path)

`BlankReadAssets` の `OpenRead`、`ReadAllBytes`、`GetFiles` などのメソッドを呼び出す際、渡された `path` パラメータが `null` または空文字列の場合、即座に引数例外がスローされます。`PathUtil.CombineSlash` / `NormalizeRelativePath` を呼び出す際、パス成分が欠落している場合も同様の例外がスローされます。このページは、どのケースかを迅速に特定し、修正する方法を説明します。

## 修正手順

### 1. `OpenRead` / `ReadAllBytes` に `null` を渡す

ソースコード入口:[BlankReadAssets.OpenRead](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L132-L146) および [BlankReadAssets.ReadAllBytes](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L197-L211)。両者ともまず `path == null` の null チェックを行います。

```csharp
using GameFrameX.Asset;

string path = ResolveConfigPath(); // null を返す可能性がある

if (string.IsNullOrEmpty(path))
{
    Debug.LogError("設定ファイルのパスが未設定です、読み込みをスキップします");
    return;
}

byte[] data = BlankReadAssets.ReadAllBytes(path);
```

### 2. `OpenRead` / `ReadAllBytes` に空文字列を渡す

ソース:[BlankReadAssets.cs#L139-L142](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.cs#L139-L142)。`path.Length == 0` の場合、`ArgumentException("Empty path", "path")` がスローされます。

```csharp
// 間違った例
string dir = "config/";
string file = ""; // 設定読み込み失敗に起因
string full = dir + file; // → "config/" のサブパスとしては有効かもしれないが、file 自体が空だとエラーになる
byte[] data = BlankReadAssets.ReadAllBytes(full); // full に依存し、安定しない

// 修正:PathUtil.CombineSlash で連結し、検証する
string full = PathUtil.CombineSlash(dir, file);
if (string.IsNullOrEmpty(full) || full.EndsWith("/"))
{
    throw new InvalidOperationException("対象ファイルのパスが無効です: " + full);
}
```

### 3. `PathUtil.CombineSlash` が `ArgumentNullException` をスローする

ソース:[PathUtil.CombineSlash](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L42-L75)。`a` または `b` のいずれかが `null` の場合、スローされます。

```csharp
string dir = settings.TryGetValue("assetDir", out var d) ? d : null;
string name = settings.TryGetValue("assetName", out var n) ? n : null;

if (dir == null || name == null)
{
    Debug.LogWarning("アセットパスが不完全です、デフォルト設定を使用します");
    dir = "fallback";
    name = "default.bin";
}

string full = PathUtil.CombineSlash(dir, name);
```

### 4. `PathUtil.NormalizeRelativePath` が `ArgumentException("Empty or null", "relative")` をスローする

ソース:[PathUtil.NormalizeRelativePath](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L78-L83)。空値(空文字列も含む)はその場でスローされます。

```csharp
public static byte[] SafeRead(string relative)
{
    if (string.IsNullOrWhiteSpace(relative))
    {
        Debug.LogError("relative が空です、読み込みを中断します");
        return Array.Empty<byte>();
    }
    return BlankReadAssets.ReadAllBytes(relative);
}
```

### 5. APK モードで `GetFiles` の `path` が `null`

ソース:[BlankReadAssets.ApkImpl.GetFiles](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L93-L116)。`path == null` の場合、ディレクトリインデックスチェックの前に `ArgumentNullException` がスローされます。

```csharp
string dir = request.GetQueryParam("dir");
if (string.IsNullOrEmpty(dir))
{
    dir = "/"; // ルートディレクトリをフォールバックとする
}
string[] files = BlankReadAssets.GetFiles(dir, "*", SearchOption.TopDirectoryOnly);
```

### 6. APK 内部の `ArgumentException()`(メッセージなし)

ソース:[BlankReadAssets.ApkImpl.cs#L299-L306](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/BlankReadAssets.ApkImpl.cs#L299-L306)。これは APK 実装の `GetFiles`/`GetDirectories` 内におけるディレクトリ基底パスの二次検証失敗で、通常は `BlankReadAssetsImpl` が正しく初期化されていないことを意味します。

```csharp
// エディタ側:GetFiles 呼び出し前に初期化完了を確認する
BlankReadAssets.InitializeWithExternalApk(apkPath);

// 実行時:streamingAssets がマウントされていることを確認する(BlankReadAssets は EnsureInitialized を通じて自動でチェックする)
if (!BlankReadAssets.FileExists("manifest/index.txt"))
{
    throw new IOException("APK リソースがマウントされていません、ディレクトリを列挙できません");
}
```

## 検証

上記の修正を適用後、下記の最小限の検証スクリプトで元のエラーシナリオを再現し、例外がスローされなくなったことを確認してください:

```csharp
using GameFrameX.Asset;
using System;

void AssertNoThrow(string label, Action act)
{
    try { act(); Console.WriteLine($"[OK] {label}"); }
    catch (ArgumentNullException) { Console.WriteLine($"[FAIL] {label}: ArgumentNullException"); }
    catch (ArgumentException)   { Console.WriteLine($"[FAIL] {label}: ArgumentException"); }
}

AssertNoThrow("null path", () => BlankReadAssets.OpenRead(null));
AssertNoThrow("empty path", () => BlankReadAssets.OpenRead(""));
AssertNoThrow("valid path", () =>
{
    using var s = BlankReadAssets.OpenRead("config/test.txt");
});
```

期待される出力では、最初の 2 項目はユーザー自身の `catch` ブランチに入り適切に処理され、3 項目目の `[OK] valid path` は正常に通過するはずです。

## よくある間違い

- **`path + ""` の連結に依存する**:空のファイル名だと `ReadAllBytes` が `path.Length == 0` の分岐に入り `ArgumentException` をスローします。代わりに `PathUtil.CombineSlash` を使用して結果を検証してください。
- **`null` と `""` を同じケースとして扱う**:ソースコードでは、`OpenRead` は `null` に対して `ArgumentNullException` を、`""` に対しては `ArgumentException` をスローし、例外の種類が異なるため、ログ検索時には区別してください。
- **APK モードで初期化忘れ**:未初期化の場合、`EnsureInitialized` は引数例外ではなく `InvalidOperationException` をスローするため、誤認しやすいです。まず初期化を確認し、その上で引数検証を見直してください。
- **`PathUtil.NormalizeRelativePath` にルートパスや引用符付き文字列を渡す**:このメソッドは `"` で囲まれた文字列に対して特別な処理を行います([PathUtil.cs#L93](https://github.com/GameFrameX/com.gameframex.unity.readassets/blob/main/Runtime/PathUtil.cs#L93))。パス中にペアになっていない二重引用符が含まれていると、解析エラーが発生する可能性があります。
