# JSON 序列化例外與反序列化失敗的處理方法

若 `JsonHelper.Serialize`、`Deserialize`、`TryDeserialize` 擲回例外、傳回 `false`,或傳回非預期的結果,請在本頁的診斷表中找到對應的症狀,並依據具體的例外訊息選擇修復步驟。`JsonHelper` 提供的 `Try*` API 與 `JsonHelperError` 能在不擲回例外的情況下傳達錯誤分類，因此請優先使用它們來定位問題。

## 修復步驟

### 修復 1:引數為 null 或空字串

`JsonHelper` 的 `Serialize` / `Deserialize` / `TryDeserialize` 都會先進行參數驗證。`Serialize` 在 `obj` 為 null 時會直接擲回 `ArgumentNullException`。`Deserialize` 在 `json` 為 null / 空 / 純空白時會擲回 `ArgumentNullException` 或 `ArgumentException`。`TryDeserialize` 不會擲回例外，而是傳回 `false` 並提供伴隨的 `JsonHelperError`。

```csharp
using GameFrameX.Foundation.Json;

// 反序列化前先驗證字串
if (string.IsNullOrWhiteSpace(json))
{
    return; // 或擲回業務例外
}

var user = JsonHelper.Deserialize<User>(json);
```

```csharp
using GameFrameX.Foundation.Json;

// 建議:使用 TryDeserialize 以避免例外產生的額外負擔
if (JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    // 成功
}
else if (error.Kind == JsonHelperErrorKind.InvalidInput)
{
    // 引數不正確
}
```

### 修復 2:JSON 有效但與目標型別不符

典型症狀：`JsonException` 中包含 `The JSON value could not be converted to <type>` 或 `is not a valid value for <type>`。常見原因如下：

- 欄位是 `int`,但 JSON 中是字串 `"123"`(若未啟用 `AllowReadingFromString` 則會失敗;`DefaultOptions` 已預設啟用)。
- 欄位是 `DateTime`,但 JSON 中的 `"2024-01-01T00:00:00Z"` 時區不符。
- 欄位是 `Guid`,但 JSON 中是空字串或缺少引號。
- 多型型別：JSON 是子類別，但父類別缺少 `[JsonDerivedType]` 中繼資料。

修復建議：

1. 確認已使用 `JsonHelper.DefaultOptions`(已啟用 `PropertyNameCaseInsensitive`、`AllowReadingFromString`、`AllowNamedFloatingPointLiterals`、`AllowTrailingCommas`)。
2. 將可疑的 JSON 單獨貼到 `JsonHelper.Deserialize<Dictionary<string, object>>(json)` 中，驗證語法是否有效。
3. 對於 `DateTime`/`Guid`/`decimal` 等容易出問題的欄位，請在 DTO 上明確標注 `[JsonConverter]`,或確認字串格式正確。
4. 為多型型別加上 `[JsonDerivedType(typeof(SubType), "sub")]`,並在 JSON 中包含 `"$type"` 欄位。

```csharp
// 多型型別範例
[JsonPolymorphic(TypeDiscriminatorPropertyName = "$type")]
[JsonDerivedType(typeof(Dog), "dog")]
[JsonDerivedType(typeof(Cat), "cat")]
public abstract class Animal { public string Name { get; set; } }

public class Dog : Animal { public string Breed { get; set; } }
```

### 修復 3:列舉值或屬性名稱的一致性

`JsonHelper.DefaultOptions` 內建了 `JsonStringEnumConverter`,會將列舉型別序列化為字串(例如 `"Active"` 而非 `0`)。若您建立了自訂的 `JsonSerializerOptions` 而未加入此轉換器，列舉型別將以數值形式寫出。

同樣地，`DefaultOptions` 設定了 `PropertyNameCaseInsensitive = true` 與 `PropertyNamingPolicy = null`(保留屬性名稱)。若您自行 new 了 options,這兩個開關預設為 false,JSON 欄位名稱將必須與 `PascalCase` 嚴格相符。

修復：

- 務必透過 `JsonHelper.DefaultOptions` 或 `JsonHelper.CreateDefaultOptions()` 產生設定。
- 請勿再次為 `DefaultOptions` 設定 `PropertyNamingPolicy`;一旦設定，寫入端將改變大小寫。

```csharp
using GameFrameX.Foundation.Json;

// 建議的寫法
var opts = JsonHelper.CreateDefaultOptions();
var json = JsonHelper.Serialize(obj, opts);

// 反序列化同樣使用 DefaultOptions 或 CreateDefaultOptions()
var restored = JsonHelper.Deserialize<MyDto>(json, opts);
```

### 修復 4:循環參考

直接呼叫 `System.Text.Json.JsonSerializer.Serialize` 時，預設會擲回 `InvalidOperationException`(`A possible object cycle was detected`)。`JsonHelper.DefaultOptions` 已設定 `ReferenceHandler = ReferenceHandler.IgnoreCycles`,遇到循環參考時會直接以 `$ref` 之類的佔位符形式跳過。

修復：務必透過 `JsonHelper` 的進入點進行序列化，不要繞過它直接呼叫 `JsonSerializer.Serialize(obj)`。

```csharp
using GameFrameX.Foundation.Json;

// 正確:循環參考會自動處理
var json = JsonHelper.Serialize(order); // order -> user -> orders -> ...

// 錯誤:會擲回 InvalidOperationException
var raw = System.Text.Json.JsonSerializer.Serialize(order);
```

### 修復 5:NaN / Infinity 等特殊浮點數值

若 JSON 來自 Python(`json.dumps(... allow_nan=True)`)或 JavaScript,可能包含 `NaN` / `Infinity` / `-Infinity`。`System.Text.Json` 預設會擲回 `JsonException`。`JsonHelper` 的 `Deserialize<T>` 內建保護處理：攔截例外後，會呼叫 `PreprocessSpecialFloatingPointValues` 對字串進行前置處理並重試。

如果程式碼未透過 `JsonHelper` 而直接呼叫 `JsonSerializer.Deserialize`,或在解析後又對其他片段進行 `Deserialize`,例外仍會再次發生。請統一使用 `JsonHelper.Deserialize<T>(json)`。

```csharp
using GameFrameX.Foundation.Json;

// Python 的輸出:NaN / Infinity 會由 JsonHelper 自動處理
var json = "{\"x\": NaN, \"y\": Infinity}";
var obj = JsonHelper.Deserialize<MyDto>(json); // 不會擲回例外
```

### 修復 6:欄位被忽略或被反序列化為預設值

可能的原因：

- 屬性為 `private set` / `init`,且沒有 `[JsonInclude]`。
- 屬性為 `required`,但 JSON 中缺少該欄位。
- 屬性是 `record` 的主要建構函式參數，但沒有 `[JsonConstructor]`。
- 屬性被標記了 `[JsonIgnore]`。
- 欄位是字典 / 集合，但 JSON 是陣列(或相反)。

修復：確認 DTO 的屬性可寫入，且可透過反射讀取。為不可變的型別加上 `[JsonConstructor]`。請勿在業務欄位上標記 `[JsonIgnore]`。

### 修復 7:使用 TryDeserialize 進行錯誤識別

`TryDeserialize` 絕不會擲回例外，而是透過 `JsonHelperError` 傳達以下資訊：

| `Kind` | 意義 | 建議處理 |
|--------|------|----------|
| `None` | 未發生錯誤 | 正常路徑 |
| `InvalidInput` | JSON 本身有語法錯誤、為 null、空字串，或 options 為 null | 檢查引數，並使用 `JsonSerializer.Deserialize<JsonElement>` 驗證 JSON 語法 |
| `TypeMismatch` | JSON 有效，但欄位型別不符 | 移至 [型別不符](#修復-2json-有效但與目標型別不符) |
| `Serialization` | 序列化階段失敗(物件→JSON) | 檢查 DTO 中是否有無法序列化的成員(指標、COM 物件等) |
| `Unknown` | 未分類的錯誤，通常是執行階段的其他例外 | 檢查 `ExceptionType` 與 `Message`,並使用 `Path` / `LineNumber` 定位問題 |

`JsonHelperError` 還提供 `Path`、`LineNumber`、`BytePositionInLine`,可直接定位 JSON 中的具體位置：

```csharp
using GameFrameX.Foundation.Json;

if (!JsonHelper.TryDeserialize<User>(json, out var user, out var error))
{
    Console.WriteLine($"Kind={error.Kind}, Type={error.ExceptionType.Name}");
    Console.WriteLine($"Message={error.Message}");
    Console.WriteLine($"Path={error.Path}, Line={error.LineNumber}, Pos={error.BytePositionInLine}");
}
```

### 修復 8:資料流與位元組陣列的操作

`SerializeAsync(Stream, ...)` 在 `stream` 為 null 時，會擲回 `ArgumentNullException`(`ArgumentNullException.ThrowIfNull(stream, nameof(stream))`)。若寫入目標的資料流已被 `Dispose`,同樣會失敗。

```csharp
using System.IO;
using GameFrameX.Foundation.Json;

await using var ms = new MemoryStream();
await JsonHelper.SerializeAsync(ms, user); // OK
var bytes = ms.ToArray();

// 使用 FileStream 時,請先確認目錄存在且可寫入
await using var fs = File.Create("user.json");
await JsonHelper.SerializeAsync(fs, user);
```

## 驗證

依照以下順序確認問題已解決：

1. `TryDeserialize` 傳回 `true`,且 `error.Kind == JsonHelperErrorKind.None`。
2. 反序列化後物件的欄位值與 JSON 中的字串/數值一致(可輸出以確認)。
3. 序列化後再反序列化的結果是相同的物件(`JsonHelper.Serialize(obj) → JsonHelper.Deserialize<T>(...) == obj` 的主要欄位相等)。
4. 針對可能失敗的引數(空字串、異常 JSON、包含 NaN 的字串)分別測試，確認不會擲回例外。

若仍然失敗，請將 `JsonHelperError` 的 `Path`、`LineNumber`、`Message` 貼到工單中，以便快速定位問題。
