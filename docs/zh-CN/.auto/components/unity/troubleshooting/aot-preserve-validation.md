# AOT 保留校验报错怎么办

当你在 CI 里执行 `AotPreserveValidationRunner.ValidateGeneratedFiles()`，或在 Unity 菜单触发 HybridCLR AOT 保留生成时,如果生成文件缺失、与当前配置不一致,或生成目录里有陈旧文件,就会出现报错。本页给出常见错误信息的诊断表与对应修复步骤。

## 快速诊断

| 症状(异常消息原文) | 原因 | 修复 |
|------|------|------|
| `Generated file is missing: Assets/Generated/AotPreserve/link.xml` | `Assets/Generated/AotPreserve/` 目录或 `link.xml` 不存在 | 重新执行生成菜单,见下文"修复步骤 1" |
| `Generated file is out of date: Assets/Generated/AotPreserve/...` | 配置改了,但生成的 `link.xml`/引用代码/asmdef/报告还没刷新 | 重新执行生成,见下文"修复步骤 1" |
| `Generated file is stale: Assets/Generated/AotPreserve/...` | 生成目录里残留了配置已经移除的旧文件 | 重新执行生成(会自动清空目录),见下文"修复步骤 1" |
| `Preserve type entry is null.` | 在 `IAotPreserveSettingsProvider` 的 `PreserveTypes`/`WrapTypes`/`PreserveGenericTypes` 里塞了 `null` 元素 | 检查配置代码,去掉 null 项,见"修复步骤 2" |
| `Preserve generic type entry is null.` | 同上,发生在 `PreserveGenericTypes` | 同上 |
| `Preserve member entry is null.` | `PreserveMembers` 数组里有 null 字符串 | 检查配置,见"修复步骤 2" |
| `Hotfix AOT preserve generation failed: ...` | `GenerateAndWrite()` 在生成阶段就检测到错误(例如上面几类) | 展开异常里的每一行,逐条按本表修复 |
| 校验通过 `ValidateGeneratedFiles()` 返回空数组却仍报 `InvalidOperationException` | 几乎不会发生;若出现,把异常 `Message` 完整贴出来排查 | 收集异常 `Message` 全文反馈 |

异常抛出位置见 [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27),错误消息拼接逻辑见 [`AotPreserveGenerator.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L103-L122)。

## 修复步骤

### 1. 重新生成 AOT 保留文件

绝大多数"missing/out of date/stale"类报错,直接重新生成即可。

1. 在 Unity 菜单栏点击 **GameFrameX → HybridCLR Generate AOT Preserve**(菜单常量见 [`AotPreserveConstants.MenuPath`](/src/Editor/AotPreserve/AotPreserveConstants.cs#L65))。
2. 等待控制台无报错。生成器会先删除整个 `Assets/Generated/AotPreserve/` 目录,再写入:
   - `Assets/Generated/AotPreserve/link.xml`
   - `Assets/Generated/AotPreserve/aot_preserve_report.md`
   - `Assets/Generated/AotPreserveReferences.cs`
   - `Assets/Generated/AotPreserve.Generated.asmdef`
   - 按类型拆分的 `AotPreserveReference_*.cs` 系列引用占位文件
3. CI 场景下,改用代码入口:

```csharp
using GameFrameX.Editor;
AotPreserveGenerator.GenerateAndWrite();
```

写入逻辑与失败时的异常见 [`AotPreserveGenerator.GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L72-L94):如果 `result.HasErrors` 为 true,会先抛 `InvalidOperationException("Hotfix AOT preserve generation failed:\n...")`,再继续后面的磁盘操作;如果磁盘写入失败,会抛 `IOException` 或 `UnauthorizedAccessException`。

### 2. 清理配置里的 null 条目

当异常消息以 `Preserve type entry is null.`、`Preserve generic type entry is null.`、`Preserve member entry is null.` 开头时,说明你自定义实现的 `IAotPreserveSettingsProvider` 里返回了含 `null` 元素的数组。这些 null 会在分析阶段被收集到 `AotPreserveAnalysis.Errors`,最终被校验器作为错误消息抛出。

修复方式:

1. 找到项目里实现 [`IAotPreserveSettingsProvider`](/src/Editor/AotPreserve/IAotPreserveSettingsProvider.cs) 的类(默认实现见 [`DefaultAotPreserveSettingsProvider`](/src/Editor/AotPreserve/DefaultAotPreserveSettingsProvider.cs),由 [`AotPreserveSettingsProviderResolver`](/src/Editor/AotPreserve/AotPreserveSettingsProviderResolver.cs) 解析)。
2. 在返回 `PreserveTypes` / `WrapTypes` / `PreserveGenericTypes` / `PreserveMembers` 之前过滤掉 `null`。
3. 重新执行生成与校验。

### 3. 清理残留的陈旧文件

如果你看到 `Generated file is stale: <路径>`,通常是上一次生成产出的文件、但本次配置已经不再需要它。直接重新运行生成菜单即可——[`GenerateAndWrite()`](/src/Editor/AotPreserve/AotPreserveGenerator.cs#L80-L84) 会先 `Directory.Delete(GeneratedDirectory, true)` 再重建。

不要手动改 `Assets/Generated/AotPreserve/` 下任何文件——它们是生成产物,下次生成会被覆盖。

## 验证

修复后,在 CI 或本地用以下任一方式确认通过:

- 代码入口:

```csharp
using GameFrameX.Editor;
AotPreserveValidationRunner.ValidateGeneratedFiles(); // 不抛异常即通过
```

实现见 [`AotPreserveValidationRunner.ValidateGeneratedFiles()`](/src/Editor/AotPreserve/AotPreserveValidationRunner.cs#L20-L27):内部调用 `AotPreserveGenerator.ValidateGeneratedFiles()`,把全部错误以换行符拼接后抛 `InvalidOperationException`。

- 直接调用生成器校验入口:

```csharp
var errors = AotPreserveGenerator.ValidateGeneratedFiles();
// errors.Length == 0 即通过
```

返回数组为 0 时表示所有生成文件齐全且与配置一致;不为 0 时,数组里的每条字符串就是一条独立的错误,按上文诊断表逐条处理。
