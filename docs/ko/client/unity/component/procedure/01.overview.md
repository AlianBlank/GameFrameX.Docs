# 플러그인 소개

GameFrameX Procedure 프로시저 관리 컴포넌트는 Unity 게임 프레임워크의 핵심 모듈 중 하나로, 게임의 프로시저 상태를 관리하는 데 특화되어 있습니다. 이 컴포넌트는 유한 상태 기계(FSM)를 기반으로 구현되어 완전한 게임 프로시저 수명 주기 관리 방안을 제공합니다.

## 개요

Procedure 프로시저 관리 컴포넌트는 주로 게임의 전체 프로시저 로직을 구성하고 제어하는 데 사용됩니다. 게임 개발에서 전형적인 게임 프로시저는 시작 프로시저(Loading), 메인 메뉴 프로시저(Menu), 게임 프로시저(Game), 일시 정지 프로시저(Pause), 정산 프로시저(Settlement) 등을 포함합니다. 이 컴포넌트는 개발자가 이러한 복잡한 프로시저 로직을 모듈화할 수 있도록 도와주어 게임 상태 전환을 더 명확하고, 제어 가능하며, 유지 관리하기 쉽게 만듭니다.

이 컴포넌트의 핵심 설계 사상은 각 게임 프로시저를 유한 상태 기계의 하나의 상태로 간주하고, 통일된 인터페이스를 통해 관리하는 것입니다. 이러한 설계 패턴은 프로시저 전환 로직을 단순화할 뿐만 아니라 개발자에게 풍부한 훅 메서드를 제공하여 프로시저의 각 수명 주기 단계에 사용자 정의 로직을 삽입할 수 있게 합니다.

GameFrameX 프레임워크의 핵심 하위 모듈로서 Procedure 컴포넌트는 FSMComponent(유한 상태 기계 컴포넌트)에 종속되어 하위 상태 관리 기능을 구현합니다. 개발자는 `ProcedureBase` 클래스를 상속하여 사용자 정의 프로시저를 생성하고 프로시저 관리자에 등록할 수 있습니다.

### 핵심 컴포넌트 설명

**ProcedureComponent**는 전체 프로시저 시스템의 진입점으로, Unity 컴포넌트이며 씬의 GameObject에 마운트됩니다. 이 컴포넌트는 게임 시작 시 모든 사용 가능한 프로시저를 초기화하고 자동으로 진입 프로시저로 전환하는 역할을 담당합니다. Inspector 패널을 통해 개발자는 사용 가능한 프로시저의 타입 이름 배열과 진입 프로시저의 타입 이름을 구성할 수 있습니다.

**IProcedureManager**는 프로시저 관리자의 표준 인터페이스를 정의하며, 현재 프로시저 가져오기, 프로시저 관리자 초기화, 프로시저 시작, 프로시저 존재 여부 판단 및 프로시저 가져오기 등의 핵심 작업을 포함합니다. 모든 프로시저 관련 기능은 이 인터페이스를 통해 외부에 제공됩니다.

**ProcedureManager**는 IProcedureManager 인터페이스의 구체적인 구현 클래스로, 내부적으로 유한 상태 기계를 사용하여 모든 프로시저 상태를 관리합니다. 개발자는 일반적으로 이 클래스를 직접 조작할 필요가 없으며, ProcedureComponent나 IProcedureManager 인터페이스를 통해 간접적으로 사용합니다.

**ProcedureBase**는 모든 사용자 정의 프로시저의 기본 클래스로, `FsmState<IProcedureManager>`를 상속합니다. 개발자는 ProcedureBase를 상속하는 하위 클래스를 생성하여 구체적인 프로시저 로직을 구현해야 합니다. 기본 클래스는 OnInit, OnEnter, OnUpdate, OnFixedUpdate, OnLeave, OnDestroy 등의 수명 주기 훅 메서드를 제공합니다.

### 작동 원리

게임이 시작되면 ProcedureComponent는 Awake 메서드에서 IProcedureManager 모듈 인스턴스를 가져옵니다. 그런 다음 Start 메서드에서 구성된 모든 사용 가능한 프로시저 타입을 순회하며 리플렉션을 통해 프로시저 인스턴스를 생성하고 진입 프로시저를 찾습니다. 마지막으로 프로시저 관리자의 Initialize 메서드를 호출하여 유한 상태 기계를 초기화하고 StartProcedure 메서드를 호출하여 진입 프로시저를 시작합니다.

프로시저가 시작되면 유한 상태 기계의 관리 상태로 진입합니다. 각 프로시저는 수명 주기 훅 순서대로 실행됩니다: OnInit(초기화) → OnEnter(진입) → OnUpdate/OnFixedUpdate(폴링) → OnLeave(이탈) → OnDestroy(소멸). 개발자는 이러한 훅에서 각각의 비즈니스 로직을 작성할 수 있습니다.

## 핵심 개념

### 프로시저(Procedure)

프로시저는 게임의 독립적인 상태나 단계를 나타냅니다. 각 프로시저는 명확한 책임을 가져야 하며, 예를 들어 리소스 로딩, 메뉴 표시, 게임 로직 처리 등이 있습니다. 프로시저 간에는 서로 전환할 수 있으며, 전환 시 해당하는 수명 주기 훅 메서드가 트리거됩니다.

### 진입 프로시저(Entrance Procedure)

진입 프로시저는 게임 시작 후 첫 번째로 실행되는 프로시저입니다. ProcedureComponent의 Inspector 패널에서 m_EntranceProcedureTypeName 속성을 통해 구성할 수 있습니다. 이 프로시저는 일반적으로 로딩 프로시저나 메인 메뉴 프로시저입니다.

### 프로시저 관리자(Procedure Manager)

프로시저 관리자는 등록된 모든 프로시저를 관리하며, 프로시저의 생성, 초기화, 전환, 소멸 등의 작업을 포함합니다. 내부적으로 유한 상태 기계를 사용하여 이러한 기능을 구현하며, 상위 계층에서 호출할 수 있는 통일된 인터페이스를 외부에 제공합니다.

### 유한 상태 기계(Finite State Machine)

유한 상태 기계는 전체 프로시저 시스템의 하위 구현입니다. 각 프로시저는 유한 상태 기계의 하나의 상태로 간주되며, 상태 간의 전환은 상태 기계가 통일적으로 관리합니다. 이러한 설계는 프로시저 전환 로직을 간단하고 신뢰할 수 있게 만듭니다.

## 종속 관계

Procedure 컴포넌트는 다음 GameFrameX 핵심 모듈에 종속됩니다:

| 종속 모듈 | 설명 | 역할 |
|---------|------|------|
| FSMComponent | 유한 상태 기계 컴포넌트 | 유한 상태 기계의 생성 및 관리 기능 제공 |
| GameFrameworkEntry | 프레임워크 진입점 | 모듈 등록 및 가져오기 기능 제공 |
| GameFrameworkComponent | 컴포넌트 기본 클래스 | 컴포넌트 초기화 및 구성 기능 제공 |

Procedure 컴포넌트를 사용하기 전에 프로젝트에 이러한 종속 컴포넌트가 올바르게 구성되어 있는지 확인하십시오. GameFrameX 프레임워크는 모듈 간의 종속 관계를 자동으로 처리하므로, 개발자는 Unity 씬에 해당 컴포넌트를 추가하기만 하면 됩니다.

## 빠른 시작

1. Unity 씬에서 빈 GameObject를 생성합니다
2. 해당 GameObject에 ProcedureComponent 컴포넌트를 추가합니다
3. Inspector 패널에서 사용 가능한 프로시저 타입과 진입 프로시저를 구성합니다
4. ProcedureBase를 상속하는 사용자 정의 프로시저 클래스를 생성합니다
5. 사용자 정의 프로시저의 클래스 이름을 사용 가능한 프로시저 목록에 추가합니다
6. 게임을 실행하면 시스템이 자동으로 진입 프로시저를 시작합니다
