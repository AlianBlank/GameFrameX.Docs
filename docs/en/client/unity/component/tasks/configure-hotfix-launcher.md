# How to Integrate the Hot Update Entry Point (HotfixLauncher)

After completing the configuration on this page, the framework will automatically load the AOT DLL and Hotfix DLL at startup, and invoke your specified entry method via reflection to bring up the hot update assembly.

## Prerequisites

- You have created the hot update assembly `Unity.Hotfix` (default Assembly Definition).
- You already have a static entry class with a parameterless static method (e.g., `Hotfix.HotfixLauncher.Main`).
- You can see the following three configuration items in `Assets/Resources/StartupOptions.asset` (the framework ships with them pre-configured):
  - `HotfixAssemblyName: Unity.Hotfix`
  - `HotfixEntryTypeName: Hotfix.HotfixLauncher`
  - `HotfixEntryMethodName: Main`

## Steps

1. **Create the entry class**. Create a new `HotfixLauncher.cs` under the `Assets/Hotfix/` directory, use the default namespace `Hotfix`, and provide a static `Main()` method as the hot update entry.

   ```csharp
   using Cysharp.Threading.Tasks;
   using GameFrameX;
   using GameFrameX.UI.Runtime;
   using Hotfix.Config;
   using Hotfix.Config.Local;
   using Hotfix.Config.Tables;
   using Hotfix.UI;

   namespace Hotfix
   {
       public static class HotfixLauncher
       {
           public static void Main()
           {
               Log.Info("Hello World HybridCLR");
               LoadConfig();
               LoadUI();
           }
       }
   }
   ```

   Source: [HotfixLauncher.cs#L26-L34](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L26-L34)

2. **Load configuration and UI in the entry**. The framework only invokes your entry method; all subsequent resource, configuration, and UI initialization is driven by this method. The template project uses `TablesComponent` to load JSON/binary configuration tables, and opens the login UI with `await`.

   ```csharp
   private static async void LoadUI()
   {
       await GameApp.UI.OpenAsync<UILogin>();
   }

   static async void LoadConfig()
   {
       _tablesComponent = new TablesComponent();
       _tablesComponent.Init(GameApp.Config);
       await _tablesComponent.LoadAsync(ConfigLoader);
       TranslateText();
   }

   static TablesComponent _tablesComponent;
   ```

   Source: [HotfixLauncher.cs#L36-L61](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Hotfix/HotfixLauncher.cs#L36-L61)

3. **Confirm that the three key-value pairs in `StartupOptions.asset` match your entry**. The framework launcher `HotfixHelper.StartHotfixInternalAsync` reads these three fields to invoke the method via reflection; the default values are shown in the table below. If you change the namespace or class name, you must update them here as well.

   | Key | Default Value | Purpose |
   |---|---|---|
   | `HotfixAssemblyName` | `Unity.Hotfix` | Name of the DLL to load (without `.dll`) |
   | `HotfixEntryTypeName` | `Hotfix.HotfixLauncher` | Fully qualified type name of the entry class (namespace + class name) |
   | `HotfixEntryMethodName` | `Main` | Name of the entry method; must be a `public static` parameterless method |

   Source: [HotfixHelper.cs#L62-L70](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/HotfixHelper.cs#L62-L70) and [StartupOptions.asset#L24-L26](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Resources/StartupOptions.asset#L24-L26)

4. **Make sure the startup flow has `ApplicationHotfixLauncher` hooked up**. The framework entry `ApplicationStartupEntry` uses it to plug the startup UI handler and the hot update launcher into `StartupRunner.Run`. No changes are required—you only need to ensure the reference exists.

   ```csharp
   var result = await StartupRunner.Run(startupOptions,
       new ApplicationStartupUIHandler(),
       new ApplicationHotfixLauncher());
   ```

   Source: [ApplicationStartupEntry.cs#L43](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Startup/ApplicationStartupEntry.cs#L43) and [ApplicationHotfixLauncher.cs#L12](https://github.com/GameFrameX/GameFrameX.Unity/blob/main/Assets/Scripts/Framework/Procedure/ApplicationHotfixLauncher.cs#L12)

## Common Variants

- **Binary configuration tables**: In `HotfixLauncher.LoadConfig`, replace `LoadAsync(ConfigLoader)` with `LoadAsync(ConfigBufferLoader)`, and enable `ENABLE_BINARY_CONFIG` in the compile options (the template already uses `#if ENABLE_BINARY_CONFIG` conditional compilation).
- **Disabling HybridCLR** (native IL2CPP path): When `ENABLE_GAME_FRAME_X_HYBRID_CLR` or `DISABLE_HYBRIDCLR` is in effect, `HotfixHelper.StartHotfixInternalAsync` takes the `RunNative` branch, directly invoking the entry via `Utility.Assembly.GetType` reflection, without requiring the AOT DLL loading process.
- **Custom entry class name**: For example, renaming `HotfixLauncher` to `MyGame.EntryBoot`—update `HotfixEntryTypeName` in `StartupOptions.asset` to `MyGame.EntryBoot` and `HotfixEntryMethodName` to `Boot` accordingly.

## Common Errors

- **Incorrect entry class/method signature**: It must be `public static` and parameterless; otherwise `entryType.GetMethod(entryMethodName)` returns `null`, and the log shows `EntryType=>method ` followed by nothing.
- **Misspelled namespace or class name**: `HotfixEntryTypeName` must use the fully qualified `Namespace.ClassName` form and match the actual namespace inside the DLL; otherwise `entryType.FullName` in `Run` throws a `NullReferenceException`.
- **Modified the entry but did not reload `StartupOptions.asset`**: The changes do not take effect at runtime; you need to re-select the ScriptableObject in the Editor or restart the Player.
- **Accidentally deleted the `#if ENABLE_UI_FAIRYGUI` branch**: In the template, the FairyGUI package loading is wrapped in conditional compilation. If you use FairyGUI but have not defined this macro, `LoadUI` will fail to load the UI package.

## Background (Optional)

`HotfixHelper.StartHotfixInternalAsync` directly iterates the already-loaded assemblies in the Editor to find the DLL; in built packages, it loads the AOT metadata in the order specified by `AOTGenericReferences.PatchedAOTAssemblyList`, then loads the Hotfix DLL with `Assembly.Load`, and finally invokes the entry method via reflection. `ApplicationHotfixLauncher` simply adapts `HotfixHelper` to the `IHotfixLauncher` interface so that the same startup flow can be reused in `StartupRunner`.
