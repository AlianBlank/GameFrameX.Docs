# 코드 스트리핑으로 인한 인터페이스 손실을 방지하는 방법

Unity는 패키지를 빌드할 때 관리 코드 스트리핑(Managed Code Stripping)을 실행하며, IL2CPP 컴파일 후 참조되지 않는 타입, 메서드, 속성을 삭제합니다. 비즈니스 코드가 리플렉션, 문자열, 동적 로딩을 통해 GameFrameX 리소스 인터페이스에 접근할 때, 스트리핑된 확장 메서드(예: `LoadTexture2DAsync`, `LoadPrefabSync`)가 그대로 사라져 런타임에 `MissingMethodException`이 발생합니다. 이 페이지에서는 본 저장소에서 이미 사용 중인 보호 방안과 새로운 커스텀 확장을 추가할 때 반드시 지켜야 할 작성법을 안내합니다.

## 사전 조건

- 프로젝트가 Unity IL2CPP 백엔드를 사용함 (Android / iOS / WebGL 기본 활성화).
- Player Settings → Managed Stripping Level이 Low보다 높게 설정되어 있거나, Engine Code Stripping이 활성화되어 있음.
- `GameFrameX.Asset` 패키지를 프로젝트에 임포트했음.

## 작업 단계

### 1. 저장소에서 이미 표시된 확장 메서드 재사용

저장소는 모든 공개 확장 클래스와 멤버에 이미 `[UnityEngine.Scripting.Preserve]`를 붙여 두었으므로, 그대로 호출하면 스트리퍼가 이를 보존합니다. 아래의 `LoadTexture2DAsync` 확장을 예로 들면:

```csharp
[UnityEngine.Scripting.Preserve]
public static class AssetComponentTexture2DExtensions
{
    [UnityEngine.Scripting.Preserve]
    public static Task<AssetHandle> LoadTexture2DAsync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetAsync<Texture2D>(path);
    }

    [UnityEngine.Scripting.Preserve]
    public static AssetHandle LoadTexture2DSync(this AssetComponent assetComponent, string path)
    {
        return assetComponent.LoadAssetSync<Texture2D>(path);
    }
}
```

출처: [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs#L13-L44)

`AssetComponent` 자체와 `GamePlayMode` 속성에도 `[Preserve]`가 붙어 있습니다:

```csharp
[RequireComponent(typeof(GameFrameXAssetCroppingHelper))]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-4000)]
public sealed class AssetComponent : GameFrameworkComponent
{
    [UnityEngine.Scripting.Preserve]
    public EPlayMode GamePlayMode { get; set; }
}
```

출처: [Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L18-L45)

### 2. 커스텀 확장을 추가할 때에도 Preserve 특성을 붙인다

자기 자신의 프로젝트에서 `AssetComponent`의 확장 메서드를 계속 작성한다면, 정적 클래스와 각 공개 멤버에 반드시 `[Preserve]`를 붙여야 합니다. 그렇지 않으면 스트리퍼가 "참조되지 않음"으로 판단하여 삭제합니다.

```csharp
using UnityEngine;
using UnityEngine.Scripting;
using GameFrameX.Asset.Runtime;

[Preserve]
public static class MyAssetComponentExtensions
{
    [Preserve]
    public static AssetHandle LoadMyAssetSync(this AssetComponent self, string path)
    {
        return self.LoadAssetSync<Object>(path);
    }
}
```

배치 위치 권장: `AssetComponent`와 같은 디렉터리 혹은 같은 어셈블리에 두면, 스트리퍼가 빌드 시 함께 스캔할 수 있습니다.

### 3. 프로젝트 내에 보조 컴포넌트가 존재하는지 확인

`AssetComponent`는 `[RequireComponent]`를 통해 `GameFrameXAssetCroppingHelper`를 강제로 부착하며, 이는 관련 타입을 씬에서 살려 두기 위한 전용 컴포넌트입니다:

```csharp
[Preserve]
public class GameFrameXAssetCroppingHelper : MonoBehaviour
{
}
```

출처: [Runtime/GameFrameXAssetCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/GameFrameXAssetCroppingHelper.cs)

`AssetComponent` 인스턴스가 실행 씬에 존재하는 한(`GameFrameXAutoComponent`가 프레임워크를 시작할 때 자동 생성), 스트리퍼는 이 참조 체인에 표시된 모든 멤버를 보존합니다.

### 4. 필요한 경우 link.xml을 보험용으로 제공

비즈니스 측에서 리플렉션(예: 문자열 이름 기반으로 `LoadPrefabAsync` 호출)을 통해 리소스 인터페이스에 접근한다면, 컴파일 타임 참조는 분석기가 식별하지 못합니다. 이 경우 `Assets/` 하위에 `link.xml`을 추가하여 전체 어셈블리를 강제로 보존해 주세요:

```xml
<linker>
  <assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>
</linker>
```

`link.xml`은 반드시 `Resources` 디렉터리 바깥의 `Assets` 하위 디렉터리에 위치해야 Unity가 처리합니다.

## 일반적인 변형

| 시나리오 | 처리 방법 |
|------|------|
| 범용 제네릭 진입점 `LoadAssetAsync<T>` | 직접 호출합니다. T는 호출 측에서 제공되므로 참조 체인은 정적 분석으로 인식되며, 추가 `[Preserve]`는 필요 없습니다. |
| 커스텀 비동기 래퍼 레이어 | 래퍼 메서드 외부에 `[Preserve]`를 붙이고, 래퍼 메서드가 최소 한 곳에서 정적으로 호출되도록 보장합니다. |
| WebGL 플랫폼 | `EPlayMode.WebPlayMode`로 강제 진행하며, `AssetComponent.Awake`에 이미 해당 분기가 내장되어 있습니다. |
| Addressables / YooAsset를 통한 간접 리플렉션 호출 | `link.xml`도 함께 보험용으로 제공합니다. |

## 일반적인 오류

| 증상 | 원인 | 처리 |
|------|------|------|
| 패키지 빌드 후 `LoadXxxAsync` 호출 시 `MissingMethodException` 발생 | 해당 확장 메서드가 어떤 코드에서도 정적으로 참조되지 않아 IL2CPP 스트리핑됨. | 확장 클래스와 메서드에 `[UnityEngine.Scripting.Preserve]`를 추가합니다. |
| `GameFrameX.Asset.Runtime` 어셈블리 내 타입에 대한 리플렉션 호출 실패 | 어셈블리 전체가 스트리핑됨. | `Assets/link.xml`에 `<assembly fullname="GameFrameX.Asset.Runtime" preserve="all"/>`을 추가합니다. |
| WebGL 빌드 후 리소스 로드 시 `Asset manager is invalid.` 오류 | 실행 모드가 `EditorSimulateMode`로 되돌아감. | `AssetComponent.Awake`에서 이미 처리하고 있으므로, 빌드 결과물에서 `m_GamePlayMode`이 직렬화되는지 확인합니다. |
| 씬에서 `AssetComponent`를 삭제한 후 모든 리소스 인터페이스가 사라짐 | `RequireComponent(GameFrameXAssetCroppingHelper)`도 함께 제거됨. | `AssetComponent`만 단독으로 삭제하지 말고, 교체해야 할 경우 `CroppingHelper`를 함께 유지하거나 다시 부착합니다. |

## 검증

1. Unity Editor → Build Settings에서 IL2CPP 패키지(Android 또는 iOS)를 빌드합니다.
2. 실기기/시뮬레이터에서 `await assetComponent.LoadTexture2DAsync("Assets/Textures/xxx.png");`를 실행하고, `MissingMethodException`이 발생하지 않음을 확인합니다.
3. `il2cppdumper` 또는 `Unity Symbol` 도구로 패키지 내 dll을 역분석하여 `GameFrameX.Asset.Runtime` 어셈블리의 확장 타입이 여전히 존재하는지 확인합니다.
4. 여전히 실패한다면, 커스텀 `link.xml` / `[Preserve]` 마크업을 단계적으로 제거하여 스트리핑된 멤버를 찾습니다.

## 배경(선택)

`[UnityEngine.Scripting.Preserve]`는 Unity가 관리 코드 스트리퍼에 공식 제공하는 "화이트리스트" 마크이며, link.xml에서 멤버별로 보존하는 것과 동일합니다. 본 저장소는 모든 공개 확장 API에 이 마크를 붙이는데, 그 이유는 이러한 메서드가 대부분 리플렉션 또는 제네릭 간접 호출에 사용되어 컴파일 타임 참조 그래프로는 커버되지 않기 때문입니다. 본 섹션과 관련된 소스 코드: [Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs) 및 [Runtime/Asset/AssetComponent.Texture2D.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.Texture2D.cs).

## 관련 링크

- 리소스 로딩의 전체 흐름은 《AssetComponent 소개》를 참조하세요.
- 빌드 후 리소스 실행 모드 전환은 `AssetComponent.Awake`의 `#if UNITY_WEBGL` 분기를 확인하세요: [Runtime/Asset/AssetComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.asset/blob/main/Runtime/Asset/AssetComponent.cs#L62-L80).
