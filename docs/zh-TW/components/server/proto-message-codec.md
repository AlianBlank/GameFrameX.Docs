# 如何定義 Proto 訊息並整合編解碼

透過為訊息類別添加特性標記並實作 `INetworkMessage` 介面，可將自訂訊息整合到框架的 ProtoBuf 序列化與 ID 路由系統中，實現訊息在傳送端與接收端的編碼與解碼。

## 前置條件

- 專案引用了 `GameFrameX.ProtoBuf.Net`（其中封裝了 ProtoBuf 的 `Serializer.Serialize` / `Deserialize` / `Merge`）。
- 專案引用了 `GameFrameX.NetWork.Abstractions`，用於訊息 ID 註冊以及心跳/請求/回應的分類。
- 組件在啟動期間呼叫一次 `MessageProtoHelper.Init(assemblies)`，以便掃描特性並寫入字典。

## 步驟

### 1. 定義訊息類型

訊息類別需要實作 `INetworkMessage` 介面，並透過 `MessageTypeHandlerAttribute` 註冊全域唯一的 `MessageId` 與 `OperationType`。視業務語意而定，可選擇實作 `IRequestMessage`、`IResponseMessage`、`INotifyMessage` 或 `IHeartBeatMessage`。

```csharp
using GameFrameX.NetWork.Abstractions;
using GameFrameX.NetWork.Abstractions.Interface;

[MessageTypeHandler(1001, (byte)MessageOperationType.Request)]
public sealed class LoginRequest : INetworkMessage, IRequestMessage
{
    public string UserName { get; set; }
    public string Password { get; set; }
}

[MessageTypeHandler(1002, (byte)MessageOperationType.Response)]
public sealed class LoginResponse : INetworkMessage, IResponseMessage
{
    public int Code { get; set; }
    public string Token { get; set; }
}

[MessageTypeHandler(9999, (byte)MessageOperationType.Notify)]
public sealed class HeartBeat : INetworkMessage, IHeartBeatMessage
{
    public long Timestamp { get; set; }
}
```

`MessageTypeHandlerAttribute` 帶有 `MessageId` 與 `OperationType`，註冊時會使用它們來填充 `MessageProtoHelper` 的內部字典。

來源：[MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L218-L254)

### 2. 啟動時初始化訊息映射

應用程式啟動時，將包含訊息類別的組件交給 `MessageProtoHelper.Init`。它會掃描所有標記了 `MessageTypeHandlerAttribute` 的類型，並依 ID 將其註冊到 `AllMessageDictionary`、`RequestDictionary`、`ResponseDictionary`、`HeartBeatList` 與 `OperationType`。如果 ID 重複，將會拋出 `ArgumentAlreadyException`。

```csharp
using System.Reflection;
using GameFrameX.NetWork.Abstractions;

MessageProtoHelper.Init(
    Assembly.GetExecutingAssembly(),
    typeof(LoginRequest).Assembly
);
```

來源：[MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L187-L208)

### 3. 使用 ProtoBuf 進行序列化與反序列化

`GameFrameX.ProtoBuf.Net.ProtoBufSerializerHelper` 封裝了 ProtoBuf 的 `Serializer.Serialize` / `Deserialize` / `Merge`，可直接用於訊息主體的位元組流編解碼。

```csharp
using GameFrameX.ProtoBuf.Net;

// 序列化（物件 -> 位元組陣列）
byte[] payload = ProtoBufSerializerHelper.Serialize(loginRequest);

// 反序列化（位元組陣列 -> 物件）
var message = ProtoBufSerializerHelper.Deserialize<LoginRequest>(payload);

// 合併模式：將位元組流合併到既有實例中，避免配置新物件
var merged = ProtoBufSerializerHelper.Deserialize(payload, existingInstance);
```

合併模式適用於增量更新場景。空位元組陣列會直接回傳原始實例，不會拋出例外。

來源：[ProtoBufSerializerHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.ProtoBuf.Net/ProtoBufSerializerHelper.cs#L17-L82)

### 4. 在傳送/接收過程中查詢訊息類型

網路層收到位元組流後，可先依 `MessageId` 查找類型，再使用 `ProtoBufSerializerHelper` 進行反序列化：

```csharp
int messageId = ReadMessageId(buffer);
Type messageType = MessageProtoHelper.GetMessageTypeById(messageId);
if (messageType != null)
{
    object message = ProtoBufSerializerHelper.Deserialize(buffer, messageType);
    // 分發到處理邏輯...
}
```

反向傳送時，先使用 `MessageProtoHelper.SetMessageId(message)` 將 `MessageId` 回寫到物件上，再進行序列化。

來源：[MessageProtoHelper.cs](https://github.com/GameFrameX/GameFrameX.Server.Source/blob/main/GameFrameX.NetWork.Abstractions/MessageProtoHelper.cs#L60-L149)

## 常見變體

| 場景 | 做法 | 說明 |
|------|------|------|
| 心跳訊息 | 實作 `IHeartBeatMessage` | 自動加入 `HeartBeatList`；`GetMessageOperationType` 直接回傳 `HeartBeat` |
| 請求/回應配對 | 分別實作 `IRequestMessage` 與 `IResponseMessage` | 分別註冊到 `RequestDictionary` / `ResponseDictionary`，便於 RPC 配對 |
| 增量更新 | `Deserialize<T>(byte[] data, T instance)` | 透過 `Serializer.Merge`，重用實例以減少 GC |
| 列舉欄位 | 使用 `ProtoEnumAttribute` | 由 `GameFrameX.ProtoBuf.Net` 提供，詳見原始碼目錄 |

## 常見錯誤

| 症狀 | 原因 | 解決方法 |
|------|------|------|
| 啟動時拋出 `ArgumentAlreadyException(... MessageIdDuplicate ...)` | 兩個類別使用了相同的 `MessageId` | 修改 `MessageTypeHandler` 的第一個參數，確保全域唯一 |
| `GetMessageTypeById` 回傳 `null` | 該 ID 未呼叫過 `Init`，或未被註冊 | 在啟動時呼叫 `MessageProtoHelper.Init(assembly)`，並確保訊息類別已編譯進該組件 |
| `ProtoBufSerializerHelper.Serialize` 拋出例外 | 欄位缺少 `[ProtoMember]` / `[ProtoContract]` 等 ProtoBuf 特性 | 檢查訊息類別是否正確宣告 ProtoBuf 序列化特性（在 `GameFrameX.ProtoBuf.Net` 中對應為 `ProtoContractAttribute`、`ProtoIncludeAttribute` 等） |
| 心跳被當作一般訊息處理 | 未實作 `IHeartBeatMessage` | 讓心跳類別實作該介面；`Init` 階段會自動將其加入心跳表 |

## 背景（選用）

框架將「訊息 ID ↔ 類型」的映射（`MessageProtoHelper`）與「物件 ↔ 位元組」的映射（`ProtoBufSerializerHelper`）解耦：前者負責依 ID 找到正確的 .NET 類型並區分請求/回應/通知/心跳，後者負責 ProtoBuf 格式的二進位讀寫。`GameFrameX.Proto/MessageProtoHandler` 僅作為命名空間佔位符；實際的編解碼入口是 `ProtoBufSerializerHelper`。至於傳輸層（TCP/KCP）如何封裝這些位元組，請參閱網路層文件。
