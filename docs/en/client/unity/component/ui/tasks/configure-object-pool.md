# How to Adjust Object Pool Capacity and Recycling Strategy

The UI framework hands UI instances over to `IObjectPoolManager` for management. Through several fields on `UIComponent`, you can adjust the capacity, automatic recycle/release intervals, and expiration time. After completing the configuration on this page, you can control how many UIs the UI instance object pool can cache and how often it scans for recycling.

## Prerequisites

- The project has integrated `GameFrameX.ObjectPool` (`using GameFrameX.ObjectPool;` at line 33 of `UIComponent.cs`).
- A GameObject with `UIComponent` attached exists in the scene, and `m_UIManager.SetObjectPoolManager(...)` has been injected (`SetObjectPoolManager(GameFrameworkEntry.GetModule<IObjectPoolManager>())` at line 504 of `UIComponent.cs`).
- For the overall assembly of the UI component and the object pool manager, see "How to Initialize the UI Module".

## Steps

1. **Adjust the capacity and strategy fields in the Inspector**. Select the GameObject with `UIComponent`; in the Inspector you can directly see the following serialized fields and modify their default values:

| Field Name | Default Value | Description |
|--------|--------|------|
| `m_InstanceCapacity` | `16` | Upper limit of the UI instance object pool capacity |
| `m_InstanceExpireTime` | `60` seconds | Objects in the pool idle for longer than this number of seconds are considered releasable |
| `m_InstanceAutoReleaseInterval` | `60` seconds | Automatic scan/release interval |
| `m_RecycleInterval` | `60` seconds | Interval for automatically recycling recyclable objects |
| `m_EnableAutoReleaseUIForm` | `false` | Whether to enable automatic recycling |

Example field definitions:

```csharp
[SerializeField] private float m_InstanceAutoReleaseInterval = 60f;
[SerializeField] private int   m_InstanceCapacity          = 16;
[SerializeField] private float m_InstanceExpireTime        = 60f;
[SerializeField] private int   m_RecycleInterval           = 60;
[SerializeField] private bool  m_EnableAutoReleaseUIForm   = false;
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L107-L141)

2. **Dynamically adjust via properties at runtime**. `UIComponent` exposes the above fields as public properties; changing values at runtime writes them back to the serialized fields and pushes them to `m_UIManager`:

```csharp
// Adjust capacity, expire time, auto release/recycle intervals
uiComponent.InstanceCapacity           = 32;   // Capacity
uiComponent.InstanceExpireTime         = 120f; // Expiration in seconds
uiComponent.InstanceAutoReleaseInterval = 30f; // Auto release interval
uiComponent.RecycleInterval            = 30;  // Recycle interval
uiComponent.EnableAutoReleaseUIForm    = true; // Turn on automatic recycling
```

Property implementation:

```csharp

public float InstanceExpireTime          { get => m_UIManager.InstanceExpireTime;           set => m_UIManager.InstanceExpireTime          = m_InstanceExpireTime          = value; }
public float InstanceAutoReleaseInterval { get => m_UIManager.InstanceAutoReleaseInterval;  set => m_UIManager.InstanceAutoReleaseInterval = m_InstanceAutoReleaseInterval = value; }
public int   RecycleInterval             { get => m_UIManager.RecycleInterval;              set => m_UIManager.RecycleInterval             = m_RecycleInterval             = value; }
public bool  EnableAutoReleaseUIForm     { get => m_EnableAutoReleaseUIForm;                set => m_EnableAutoReleaseUIForm = value; }
```

Source: [UIComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.ui/blob/main/Runtime/UIComponent.cs#L322-L359)

3. **Turn off the automatic recycling switch (optional)**. If you want to control recycling manually, set `EnableAutoReleaseUIForm` to `false`; the timer will no longer trigger automatic scans, and instances will only be returned to the pool when `CloseUIForm` is explicitly called.

4. **Save and verify**. Restart the scene or re-enter Play Mode, confirm the field values take effect in the Inspector; observe the capacity of `UI Form Instance Pool` in the Profiler and confirm it does not exceed `InstanceCapacity`.

## Common Variants

- **Phased tuning**: Before release, increase `m_InstanceCapacity` in the editor (e.g., 32) to facilitate stress-testing peak load; in the production build, dynamically lower it via `InstanceCapacity` to reduce resident memory.
- **Frequently opened/closed high-frequency UIs** (e.g., Toast, Tips): Set `InstanceExpireTime` to a small value (e.g., 10 seconds) so that idle objects are released as soon as possible, avoiding occupying pool capacity.
- **Heavyweight UIs** (character panels, shop): Set `m_InstanceCapacity` to 1–2 and `InstanceExpireTime` to a larger value (e.g., 300 seconds) to keep the cache for reuse.
- **Completely disable automatic recycling**: Set `m_EnableAutoReleaseUIForm = false` and let the business logic decide when to recycle (often used during cutscenes).

## Common Errors

| Symptom | Cause | Fix |
|------|------|------|
| Field changes don't take effect | At runtime only the property was changed without writing back to `m_UIManager`, or `EnableAutoReleaseUIForm` was not enabled | Confirm `m_EnableAutoReleaseUIForm = true` and assign values through the properties (not the fields) |
| Pool objects are cleared quickly and UIs open slowly | `InstanceExpireTime` or `InstanceAutoReleaseInterval` is too small | Increase `InstanceExpireTime` to 60 seconds or more and `InstanceAutoReleaseInterval` to 30 seconds or more |
| Memory keeps rising | `InstanceCapacity` is too large and `InstanceExpireTime` is too long | Reduce `InstanceCapacity` and shorten `InstanceExpireTime` |
| Frequent GC | `RecycleInterval` is too small, the timer fires repeatedly | Set `RecycleInterval` to 30–60 seconds |

## Background (Optional)

Internally, `UIComponent` pushes the configuration to both `m_UIManager` and the serialized fields, so that runtime changes can also be serialized and preserved in the Editor. `IObjectPoolManager` is responsible for the actual object pool strategy (expiration-based recycling and timed release), while the UI module only passes parameters and switches; modifying non-public fields such as `m_InstancePriority` will have no effect.
