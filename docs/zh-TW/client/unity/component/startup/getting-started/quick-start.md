# 5 分鐘內整合啟動流程

按照本頁的步驟操作，從安裝套件到成功執行一次 `StartupRunner.Run(...)` 呼叫，大約需要 5 分鐘：只要建立一個 `StartupOptions` 資產、實作兩個介面，再掛上一個啟動腳本即可開始。

## 前置條件

- Unity 2019.4+
- 已安裝 GameFrameX 框架及其相依套件：`com.gameframex.unity` / `com.gameframex.unity.procedure` / `com.gameframex.unity.fsm` / `com.gameframex.unity.event` / `com.gameframex.unity.cysharp.unitask`
- YooAsset（若要啟用熱更新修補流程）

## 操作步驟

### 1. 安裝套件

在 `Packages/manifest.json` 中新增 `com.gameframex.unity.startup` 相依性，並設定 GameFrameX scoped registry：

```json
{
  "dependencies": {
    "com.gameframex.unity.startup": "1.1.0"
  },
  "scopedRegistries": [
    {
      "name": "GameFrameX",
      "url": "https://gameframex.upm.alianblank.uk",
      "scopes": ["com.gameframex"]
    }
  ]
}
```

`scopes` 用來控制只有帶有 `com.gameframex` 前綴的套件才會由此 registry 解析。

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L20-L39)

### 2. 建立設定資產

在 Unity 選單中選擇 `Create > GameFrameX > Startup Options`，即可建立 `StartupOptions` ScriptableObject 資產。常用項目：
- `GlobalInfoUrls`：全域資訊介面的主要/備援 URL 清單
- `GamePlayMode`：資源執行模式，會在啟動前同步至 Asset 元件
- `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName`：熱更新進入點
- `PackageName` / `Channel` / `SubChannel`：HTTP 公用參數
- `LauncherUIResName`：啟動 UI 資源路徑（預設值 `UI/UILauncher`）
- `SkipRemoteStartupRequests`：跳過所有遠端啟動請求（在 WebGL 獨立執行或無後端時啟用）

### 3. 實作 UI 處理器

實作 `IStartupUIHandler` 後，框架會透過此介面回呼 UI 狀態：

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class GameStartupUIHandler : IStartupUIHandler
{
    public UniTask StartAsync(string uiResName) { /* 載入 UI */ return UniTask.CompletedTask; }
    public void SetTipText(string text) { /* 更新提示文字 */ }
    public void SetProgress(float progress, string sizeInfo) { /* 更新進度條 */ }
    public void SetProgressUpdateFinish() { /* 顯示完成 */ }
    public void Dispose() { /* 關閉 UI、取消訂閱 */ }
}
```

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L54-L66)

### 4. 實作熱更新啟動器（選用）

若需要啟用熱更新，請實作 `IHotfixLauncher`：

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;

public class HybridClrHotfixLauncher : IHotfixLauncher
{
    public async UniTask<HotfixLaunchResult> StartAsync(StartupOptions options)
    {
        // 根據 options.HotfixAssemblyName 載入熱更新組件
        // 呼叫 options.HotfixEntryTypeName 中的 options.HotfixEntryMethodName
        return HotfixLaunchResult.Succeed();
    }
}
```

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L67-L79)

### 5. 啟動

在任意 GameObject 上掛一個啟動腳本，並在場景載入後呼叫 `StartupRunner.Run`：

```csharp
using Cysharp.Threading.Tasks;
using GameFrameX.Startup.Runtime;
using UnityEngine;

public class GameBootstrap : MonoBehaviour
{
    [SerializeField] private StartupOptions _options;

    private async void Start()
    {
        var uiHandler = new GameStartupUIHandler();
        var hotfixLauncher = new HybridClrHotfixLauncher();

        var result = await StartupRunner.Run(_options, uiHandler, hotfixLauncher);

        if (result.Success)
        {
            // 啟動完成，遊戲已就緒
        }
        else
        {
            Debug.LogError($"启动失败 at {result.FailedProcedureName}: {result.ErrorMessage}");
        }
    }
}
```

`StartupResult` 包含 `Success` / `FailedProcedureName` / `FailedUrl` / `ErrorMessage` 欄位。

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L81-L105)

## 常見變體

### 以事件訂閱解耦通知

與其直接 `await`，可改為訂閱完成/失敗事件：

```csharp
GameApp.Event.Subscribe(StartupCompletedEventArgs.EventId, OnStartupCompleted);
GameApp.Event.Subscribe(StartupFailedEventArgs.EventId, OnStartupFailed);
```

`StartupCompletedEventArgs` 與 `StartupFailedEventArgs` 會透過 `GameApp.Event.Fire` 觸發，await 路徑與事件路徑都會收到通知。

來源：[README.zh-CN.md](https://github.com/GameFrameX/com.gameframex.unity.startup/blob/main/README.zh-CN.md#L107-L112)

### WebGL / 獨立部署

將 `StartupOptions.SkipRemoteStartupRequests` 設為 true，即可跳過所有遠端啟動請求（全域資訊 / App 版本 / 資源包版本），僅執行本機 YooAsset 初始化。

### URL 主要/備援 failover

在 `StartupOptions.GlobalInfoUrls` 中設定多個 URL 時，框架會依序嘗試；對單一 URL 的有限次數重試由 `MaxAttemptsPerUrl` 控制。

## 常見錯誤

- **`Start` 沒有 `async void`**：`StartupRunner.Run` 回傳 `UniTask<StartupResult>`，因此啟動方法必須是 `async void Start()`，否則 UniTask 將不會被驅動。
- **選單中找不到 `Create > GameFrameX > Startup Options`**：表示套件未正確匯入。請檢查 `Packages/manifest.json` 中的 `scopedRegistries` 與 `dependencies`。
- **熱更新進入點未被呼叫**：只要 `HotfixAssemblyName` / `HotfixEntryTypeName` / `HotfixEntryMethodName` 其中之一輸入錯誤，啟動時 procedure FSM 就會回報 `FailedProcedureName`。請查看日誌 `result.ErrorMessage`。
- **重複啟動**：在同一場景中重複呼叫會導致 procedure FSM 被重建。`StartupRunner.Run` 是一次性進入點，請勿在 `OnEnable` 中呼叫。

## 背景說明（選用）

`StartupRunner.Run(options, uiHandler, hotfixLauncher)` 內部會建構 procedure FSM，並將 `options` / `uiHandler` / `hotfixLauncher` 三個實例寫入固定的 BlackBoard key（`__startup_options__` / `__startup_ui_handler__` / `__startup_hotfix_launcher__`）。所有 procedure 狀態皆透過 `IFsm<IProcedureManager>.GetData<VarObject>(key)` 讀取，完成結果則透過 `__startup_completion_source__` 以 `UniTask<StartupResult>` 的形式對外提供。完整的黑板常數請參考 `BlackBoardKeys.cs`。
