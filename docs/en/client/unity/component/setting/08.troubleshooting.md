# Troubleshooting

This document compiles common issues, error messages, and their solutions when using the GameFrameX Setting configuration component.

## Overview

GameFrameX Setting configuration component is a core component of the game framework, responsible for managing game configuration information. During usage, developers may encounter issues such as initialization failures, data unable to save, and platform compatibility problems. This document provides detailed problem diagnosis and solutions to help developers quickly locate and resolve issues.

## Initialization Issues

### Issue 1: Setting manager is invalid

**Error Message:**
```
Log.Fatal("Setting manager is invalid.");
```

**Cause Analysis:**
This error indicates that `SettingComponent` was unable to get the `ISettingManager` module from `GameFrameworkEntry` during the `Awake()` phase. This is usually because GameFramework core components were not correctly initialized.

**Solution:**

1. Ensure a GameFrameX core entry component exists in the scene
2. Check if `GameFrameworkEntry` was correctly initialized
3. Ensure SettingComponent is attached to the correct GameObject

```csharp
// Correct initialization order
// 1. Initialize GameFrameworkEntry first
GameFrameworkEntry.Initialize();

// 2. SettingComponent will then automatically get the manager through Awake
var settingComponent = gameObject.AddComponent<SettingComponent>();
```

### Issue 2: Can not create setting helper

**Error Message:**
```
Log.Error("Can not create setting helper.");
```

**Cause Analysis:**
This error indicates that a setting helper instance could not be created based on the configured type name. Possible reasons:
- The configured Helper type name is incorrect
- The specified Helper class doesn't exist or wasn't properly referenced
- Helper type doesn't have a parameterless constructor

**Solution:**

1. Check `Setting Helper Type Name` configuration in SettingComponent Inspector panel
2. Ensure the type name is complete and correct (including namespace)

```csharp
// Default configuration
// Setting Helper Type Name: GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper
// or
// Setting Helper Type Name: GameFrameX.Setting.Runtime.DefaultSettingHelper
```

3. Available Helper types:
   - `GameFrameX.Setting.Runtime.PlayerPrefsSettingHelper` - Based on Unity PlayerPrefs
   - `GameFrameX.Setting.Runtime.DefaultSettingHelper` - Based on local file storage

### Issue 3: Missing required dependency component

**Error Message:**
Unity runtime error or component not working properly

**Cause Analysis:**
`SettingComponent` uses `[RequireComponent(typeof(GameFrameXSettingCroppingHelper))]` and must be used with the `GameFrameXSettingCroppingHelper` component.

**Solution:**

1. SettingComponent automatically adds GameFrameXSettingCroppingHelper dependency component
2. If dependency issues occur, manually add GameFrameXSettingCroppingHelper to the same GameObject

## Data Operation Issues

### Issue 4: Load settings failure

**Error Message:**
```
Log.Error("Load settings failure.");
```

**Cause Analysis:**
Settings loading failed, possible reasons:
- Configuration file corrupted
- Storage media unavailable
- File path doesn't exist
- Serialization/deserialization error

**Solution:**

1. **For DefaultSettingHelper:**
```csharp
// Check if file exists
var helper = settingComponent.GetComponent<DefaultSettingHelper>();
string filePath = helper.FilePath;
Debug.Log($"Settings file path: {filePath}");
```

2. **Exception handling:**
```csharp
try
{
    settingComponent.Save();
}
catch (Exception ex)
{
    Debug.LogError($"Save failed: {ex.Message}");
}
```

3. **Check file permissions:**
   - Ensure Application.persistentDataPath is writable
   - Check if disk space is sufficient

### Issue 5: Setting values not saved correctly

**Problem Description:**
After calling `Save()` method, setting values are lost when reloading

**Possible Causes:**

1. **Save() not called**: Setting values only modified in memory, not persisted
2. **PlayerPrefs not synced**: On some platforms PlayerPrefs.Save() needs to be called manually
3. **WebGL platform limitations**: Mini-game platforms have special storage mechanisms

**Solution:**

```csharp
// 1. Save() must be called after modifying settings
settingComponent.SetString("PlayerName", "NewName");
settingComponent.Save();  // Must call

// 2. Use DefaultSettingHelper to ensure data persistence
// It automatically saves to Application.persistentDataPath/GameFrameworkSetting.dat
```

### Issue 6: GetAllSettingNames returns null or not supported

**Error Message:**
```
Log.Warning("GetAllSettingNames is not supported.");
```

**Cause Analysis:**
`PlayerPrefsSettingHelper` does not support getting all setting item names because Unity PlayerPrefs itself doesn't provide an API to enumerate all keys.

> Source: [PlayerPrefsSettingHelper.cs#L96-L100](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L96-L100)

**Solution:**

1. **Use DefaultSettingHelper instead**: This Helper supports complete enumeration functionality

```csharp
// In SettingComponent Inspector, change Helper type to:
// GameFrameX.Setting.Runtime.DefaultSettingHelper
```

2. **Maintain setting key list yourself**: If you must use PlayerPrefs, record all setting key names yourself

### Issue 7: Count property returns -1

**Problem Description:**
Calling `settingComponent.Count` returns -1

**Cause Analysis:**
`PlayerPrefsSettingHelper`'s Count property always returns -1 because Unity PlayerPrefs doesn't provide an interface to get setting item count.

> Source: [PlayerPrefsSettingHelper.cs#L52-L55](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L52-L55)

```csharp
public override int Count
{
    get { return -1; }  // PlayerPrefs doesn't support getting count
}
```

**Solution:**

1. Use `DefaultSettingHelper` to get accurate setting item count
2. Or maintain a count variable yourself

## Platform Compatibility Issues

### Issue 8: WebGL mini-game platform storage issues

**Problem Description:**
On Douyin, WeChat, Kuaishou and other mini-game platforms, settings cannot be saved or read normally

**Cause Analysis:**
Mini-game platforms have their own storage APIs and don't support Unity native PlayerPrefs. The framework has adapted for these platforms:

> Source: [PlayerPrefsSettingHelper.cs#L80-L86](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/PlayerPrefsSettingHelper.cs#L80-L86)

```csharp
public override bool Save()
{
#if UNITY_WEBGL && (ENABLE_DOUYIN_MINI_GAME || ENABLE_WECHAT_MINI_GAME || ENABLE_KUAISHOU_MINI_GAME)
    return true;  // No manual save needed for mini-game platforms
#else
    UnityEngine.PlayerPrefs.Save();
    return true;
#endif
}
```

**Solution:**

1. Ensure correct platform macros are defined:
   - `ENABLE_DOUYIN_MINI_GAME` - Douyin mini-game
   - `ENABLE_WECHAT_MINI_GAME` - WeChat mini-game
   - `ENABLE_KUAISHOU_MINI_GAME` - Kuaishou mini-game

2. Correctly configure publishing platform in Unity Build Settings

### Issue 9: Object serialization failure

**Problem Description:**
When using `SetObject()` or `GetObject()`, object data cannot be saved or read correctly

**Possible Causes:**

1. Object type doesn't support JSON serialization
2. Object contains non-serializable members (such as delegate, EventHandler)
3. Circular reference causing serialization failure

**Solution:**

1. Ensure object class is marked with `[Serializable]`
2. Use serializable data structures
3. Handle circular references

```csharp
[Serializable]
public class PlayerData
{
    public string Name;
    public int Level;
    public List<Item> Items;
}

[Serializable]
public class Item
{
    public int Id;
    public int Count;
}

// Usage example
var playerData = new PlayerData
{
    Name = "Player1",
    Level = 10,
    Items = new List<Item>()
};

settingComponent.SetObject("PlayerData", playerData);
settingComponent.Save();

// Read data
var loadedData = settingComponent.GetObject<PlayerData>("PlayerData");
```

## API Usage Issues

### Issue 10: Setting name is invalid

**Error Message:**
Throws `GameFrameworkException("Setting name is invalid.")`

**Cause Analysis:**
All settings API methods check if the setting name is empty. If null or empty string is passed, an exception is thrown.

> Source: [SettingManager.cs#L215-L218](https://github.com/GameFrameX/com.gameframex.unity.setting/blob/main/Runtime/Setting/Setting/SettingManager.cs#L215-L218)

```csharp
if (string.IsNullOrEmpty(settingName))
{
    throw new GameFrameworkException("Setting name is invalid.");
}
```

**Solution:**

```csharp
// Wrong usage
settingComponent.SetBool("", true);  // Throws exception

// Correct usage
settingComponent.SetBool("IsFullScreen", true);
```

### Issue 11: Empty value return issue

**Problem Description:**
When using methods without default value to get non-existent settings, unexpected values are returned

**Cause Analysis:**
Different data types have different default return values when methods without default value parameters are used:

| Data Type | Default Return Value for Methods Without Default |
|-----------|--------------------------------------------------|
| bool | false |
| int | 0 |
| float | 0f |
| string | null |

**Solution:**

1. **Always use methods with default value:**
```csharp
// Not recommended
bool isFullScreen = settingComponent.GetBool("IsFullScreen");

// Recommended
bool isFullScreen = settingComponent.GetBool("IsFullScreen", false);
```

2. **Check if setting exists first:**
```csharp
if (settingComponent.HasSetting("PlayerName"))
{
    string name = settingComponent.GetString("PlayerName");
}
else
{
    // Handle non-existence case
}
```

## Debugging Tips

### Debugging logs

Enable detailed logs for problem diagnosis:

```csharp
// Add debugging info in code
Debug.Log($"Settings Count: {settingComponent.Count}");
Debug.Log($"Has PlayerName: {settingComponent.HasSetting("PlayerName")}");

// Get all setting names (only DefaultSettingHelper supports)
string[] allNames = settingComponent.GetAllSettingNames();
foreach (var name in allNames)
{
    Debug.Log($"Setting: {name}");
}
```

### Check Helper configuration

```csharp
// Get currently used Helper info
var helper = settingComponent.GetComponent<SettingHelperBase>();
Debug.Log($"Helper Type: {helper.GetType().Name}");
Debug.Log($"Helper FilePath: {(helper is DefaultSettingHelper dh ? dh.FilePath : "N/A")}");
```

## Common Error Reference Table

| Error Message | Cause | Solution |
|---------------|-------|----------|
| Setting manager is invalid | GameFramework not initialized | Ensure GameFrameworkEntry is initialized |
| Can not create setting helper | Helper type name error | Check Inspector configuration |
| Load settings failure | Configuration file corrupted or path error | Check file path and permissions |
| Save settings failure | Storage media unavailable | Check disk space and permissions |
| GetAllSettingNames is not supported | Used PlayerPrefsHelper | Switch to DefaultSettingHelper |
| Setting name is invalid | Setting name is empty | Use non-empty string as key |
| Count returns -1 | PlayerPrefs doesn't support counting | Use DefaultSettingHelper |
