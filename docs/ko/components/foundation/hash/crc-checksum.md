# CRC32/CRC64를 사용하여 데이터를 검증하는 방법

`GameFrameX.Foundation.Hash.CrcHelper`는 CRC32와 CRC64 두 가지 순환 중복 검사 알고리즘을 제공하며, 바이트 배열, `Stream` 흐름(동기 및 비동기)에 대한 체크섬 값 직접 계산을 지원하고, CRC32 정수를 빅 엔디안 바이트 배열로 분할하여 저장 또는 전송에 사용할 수 있습니다.

## 사전 조건

- 네임스페이스 `GameFrameX.Foundation.Hash`를 참조하고, 클래스 이름은 `CrcHelper`(정적 분할 클래스)입니다.
- 대상 프레임워크: .NET Standard 2.x 이상, `Stream`, `Task`, `CancellationToken` 지원.

## 작업 단계

### 1. 바이트 배열의 CRC32 계산

가장 간단한 호출로, 전체 바이트 배열을 전달하면 `int` 타입의 CRC32 체크섬 값을 얻을 수 있습니다.

```csharp
using GameFrameX.Foundation.Hash;
using System.Text;

byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data);   // int 반환
```

출처: [CrcHelper.cs#L121-L126](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L121-L126)

### 2. 바이트 배열 지정 범위의 CRC32 계산

`offset`과 `length`를 전달하여 바이트 배열의 일부 슬라이스에 대해서만 CRC32를 계산합니다. 범위를 벗어나거나 음수일 경우 `ArgumentException`이 발생합니다.

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
int crc32 = CrcHelper.GetCrc32(data, offset: 2, length: 5);
```

출처: [CrcHelper.cs#L140-L152](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L140-L152)

### 3. 스트림의 CRC32 계산(동기)

4KB(`CachedBytesLength = 0x1000`) 단위로 청크 읽기 및 계산하며, 대용량 파일 검증에 적합합니다.

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = CrcHelper.GetCrc32(stream);
```

출처: [CrcHelper.cs#L163-L183](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L163-L183)

### 4. 스트림의 CRC32 비동기 계산

비동기 버전은 `Stream.ReadAsync`를 사용하며, `CancellationToken`을 통한 취소를 지원합니다.

```csharp
using var stream = File.OpenRead("big.bin");
int crc32 = await CrcHelper.GetCrc32Async(stream, cancellationToken);
```

출처: [CrcHelper.cs#L188-L202](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L188-L202)

### 5. 바이트 배열 / 스트림의 CRC64 계산

CRC64의 세 가지 공개 오버로드: `GetCrc64(byte[])`, `GetCrc64(Stream)`, `GetCrc64Async(Stream, CancellationToken)`, `ulong`을 반환합니다.

```csharp
byte[] data = Encoding.UTF8.GetBytes("Hello, World!");
ulong crc64 = CrcHelper.GetCrc64(data);                 // 바이트 배열

using var stream = File.OpenRead("big.bin");
ulong crc64FromStream = CrcHelper.GetCrc64(stream);    // 동기 스트림

ulong crc64Async = await CrcHelper.GetCrc64Async(stream); // 비동기 스트림
```

출처: [CrcHelper.cs#L66-L110](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L66-L110)

### 6. CRC32 정수를 빅 엔디안 바이트 배열로 변환

CRC32 결과는 종종 저장해야 하는데, `GetCrc32Bytes`는 두 가지 사용법을 제공합니다:

```csharp
int crc32 = CrcHelper.GetCrc32(data);

// 방법 1: 새로운 4바이트 배열 반환(빅 엔디안)
byte[] bytes = CrcHelper.GetCrc32Bytes(crc32);

// 방법 2: 기존 배열의 지정된 위치에 쓰기
byte[] buffer = new byte[64];
CrcHelper.GetCrc32Bytes(crc32, buffer, offset: 0);
```

출처: [CrcHelper.cs#L212-L257](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Hash/CrcHelper.cs#L212-L257)

## 일반적인 변형

- **CRC32와 바이트 코드 순환 XOR 조합**: `CrcHelper.GetCrc32(stream, code, length)`은 internal 오버로드로, 먼저 `code` 바이트 배열을 데이터 스트림에 순환 XOR한 다음 CRC를 계산합니다. 키가 있는 경량 검증 시나리오에 적합합니다.
- **다양한 데이터 길이에 대한 일관성**: CRC 알고리즘은 동일한 입력에 대해 항상 동일한 결과를 반환하므로, 네트워크 패킷 검증, 파일 지문, 저장 데이터 무결성 검사에 사용할 수 있습니다.
- **대용량 파일 스트리밍 계산**: `Stream` 오버로드(동기/비동기)를 통해 4KB 단위로 청크 처리하므로 메모리 사용량이 안정적입니다.

## 일반적인 오류

| 오류 현상 | 원인 | 수정 |
|----------|------|------|
| `ArgumentNullException`("bytes") | 전달된 `byte[]`가 null | 호출 전 검사하거나 `Array.Empty<byte>()` 사용 |
| `ArgumentException`(InvalidDataLength) | `GetCrc32(bytes, offset, length)`의 `offset` 범위 초과 또는 `length`가 음수 | `offset >= 0`, `length >= 0`이고 `offset + length <= bytes.Length`인지 확인 |
| `ArgumentException`(InvalidDataLength) | `GetCrc32Bytes`의 `offset` 범위 초과 또는 대상 배열의 남은 공간이 4바이트 미만 | `offset >= 0`이고 `offset + 4 <= bytes.Length`인지 확인 |
| `ArgumentNullException`("stream") | 스트림이 null | 스트림이 성공적으로 열렸는지, 파일 경로가 올바른지 확인 |
| 계산 결과가 일치하지 않음 | 문자열 인코딩 불일치(UTF-8 / GBK / UTF-16) | 양쪽에서 동일한 `Encoding` 사용, 예를 들어 모두 `Encoding.UTF8.GetBytes` 사용 |

## 배경 지식(선택 사항)

CRC32 기본 다항식 `0xedb88320`, 시드 `0xffffffff`(IEEE 802.3 / zlib과 동일), CRC64는 내부적으로 `Crc64` 클래스의 `Append` + `GetCurrentHashAsUInt64`에 위임합니다. 체크섬 값은 비암호화 무결성 검사에 적합하며, HMAC과 같은 키 기반 인증 알고리즘을 대체할 수 없습니다.
