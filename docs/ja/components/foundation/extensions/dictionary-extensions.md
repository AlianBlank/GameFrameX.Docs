# 辞書拡張の使い方(双方向辞書、リソース解放可能辞書)

このページでは `GameFrameX.Foundation.Extensions` 名前空間にある3種類の辞書コンテナと拡張メソッドの使い方を紹介します:`BidirectionalDictionary<TKey, TValue>`(キー↔値の双方向マッピング)、`DisposableDictionary<TKey, TValue>` / `DisposableConcurrentDictionary<TKey, TValue>`(値を自動解放)、および `IDictionaryExtensions` の `AddOrUpdate` / `TryAdd` などの拡張メソッドです。読み終えれば、自分の型に対して最小限の変更で双方向マッピングと管理リソースの解放を利用できます。

## 前提条件

- .NET プロジェクトが `GameFrameX.Foundation.Extensions` アセンブリを参照していること。
- ソースコードの場所:`GameFrameX.Foundation.Extensions/`。名前空間は `GameFrameX.Foundation.Extensions`。
- 解放可能な辞書の `TValue` はすべて `System.IDisposable` を実装している必要があります。

## 操作手順

### 1. `BidirectionalDictionary` を使ってキー↔値の双方向マッピングを行う

双方向辞書は2つの内部 `Dictionary` で正方向と逆方向のマッピングを同時に保持し、どちらの方向の検索も O(1) です。**キーと値が一意である**必要があります。

```csharp
using GameFrameX.Foundation.Extensions;

var map = new BidirectionalDictionary<int, string>(initialCapacity: 16);

map.TryAdd(1, "Alice");
map.TryAdd(2, "Bob");

// 正方向:キー -> 値
if (map.TryGetValue(1, out var name))
{
    Console.WriteLine(name); // Alice
}

// 逆方向:値 -> キー
if (map.TryGetKey("Bob", out var id))
{
    Console.WriteLine(id); // 2
}
```

キーと値の比較関数をカスタマイズしたり、両方向で既存マッピングを更新したりできます:

```csharp
var map = new BidirectionalDictionary<string, int>(
    initialCapacity: 8,
    keyComparer: StringComparer.OrdinalIgnoreCase,
    valueComparer: null);

// キーで値を更新(逆方向マッピングも同期)
map.TryUpdateByKey("score", 99);

// 値でキーを更新(正方向マッピングも同期)
map.TryUpdateByValue(99, "Score");
```

出典:[BidirectionalDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/BidirectionalDictionary.cs#L47-L204)

よく使う API:

| メソッド | 役割 |
|------|------|
| `TryAdd(key, value)` | キーと値の両方が存在しない場合のみ追加、失敗時は `false` を返す |
| `TryGetValue(key, out value)` | 正方向検索 |
| `TryGetKey(value, out key)` | 逆方向検索 |
| `TryUpdateByKey(key, newValue)` | キーで値を変更、逆方向も同期 |
| `TryUpdateByValue(value, newKey)` | 値でキーを変更、正方向も同期 |
| `ContainsKey` / `ContainsValue` | 存在判定 |
| `Clear()` | 双方向マッピングをクリア |

### 2. `DisposableDictionary` を使って値をコンテナと一緒に解放する

`DisposableDictionary<TKey, TValue>` は `NullableDictionary<TKey, TValue>` を継承し、`TValue : IDisposable` を制約とします。`Dispose()` 時には null でない値すべてに対して順次 `Dispose()` を呼び出し、例外は `DisposalErrorHandler` に委譲されるため、1つの値の解放失敗が後続の値の解放をブロックすることはありません。

```csharp
using GameFrameX.Foundation.Extensions;

public sealed class MyHandle : IDisposable
{
    public void Dispose() { /* 基底リソースを解放 */ }
}

// using ブロック終了時に、すべての値が Dispose される
using var cache = new DisposableDictionary<string, MyHandle>
{
    DisposalErrorHandler = (value, ex) =>
        Console.WriteLine($"解放失敗:{ex.Message}")
};

cache.Add("session-1", new MyHandle());
cache["session-2"] = new MyHandle();

// その後、解放済みオブジェクトに対して Add/Remove/代入/列挙操作を行うと、ObjectDisposedException がスローされる
```

出典:[DisposableDictionary.cs](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Extensions/DisposableDictionary.cs#L11-L219)

スレッドセーフなシナリオでは `DisposableConcurrentDictionary<TKey, TValue>` を使用してください。API の使い方は同じです。

### 3. `IDictionaryExtensions` の `AddOrUpdate` を使用する

拡張メソッドは `IDictionary<TKey, TValue>`、`NullableDictionary<TKey, TValue>`、`NullableConcurrentDictionary<TKey, TValue>` すべてにオーバーロードを提供しています。

```csharp
using GameFrameX.Foundation.Extensions;

var dict = new Dictionary<int, string>();
dict.AddOrUpdate(new Dictionary<int, string>
{
    [1] = "one",
    [2] = "two",
});

// 単一の AddOrUpdate:キーが存在しなければ追加、存在する場合はファクトリ関数が返した新しい値を使用
var current = dict.AddOrUpdate(
    key: 3,
    addValue: "three",
    updateValueFactory: (k, old) => old + "!");

// ファクトリなしのオーバーロード:キーが存在する場合は固定値で直接上書き
dict.AddOrUpdate(key: 1, addValue: "ONE", updateValue: "uno");
```

## よくあるバリエーション

| シナリオ | 推奨タイプ | 理由 |
|------|----------|------|
| 値からキーを逆引きする必要がある | `BidirectionalDictionary<TKey, TValue>` | O(1) の逆方向検索 |
| 値が管理リソースで、集中解放が必要 | `DisposableDictionary<TKey, TValue>` | `Dispose` で自動的にすべての値を解放 |
| マルチスレッドで使用し、値を解放する必要がある | `DisposableConcurrentDictionary<TKey, TValue>` | 並行セーフかつ自動解放 |
| null キーを許可する、またはフォールバックデフォルト値が必要 | `NullableDictionary<TKey, TValue>` | null キーと `FallbackValue` をサポート |
| 通常の Dictionary で upsert セマンティクスが必要 | `IDictionary.AddOrUpdate` | 新しいコレクションに置き換えない |

## よくあるエラー

| 症状 | 原因 | 修正方法 |
|------|------|------|
| `BidirectionalDictionary.TryAdd` が常に `false` を返す | キーまたは値がもう一方の端のマッピングに既に存在する | 先に `Remove` してから `TryAdd` するか、`TryUpdateByKey` / `TryUpdateByValue` に変更する |
| `DisposableDictionary` の `Dispose` 後に `ObjectDisposedException` がスローされる | 解放後に `Add` / `Remove` / インデクサーの set / `GetEnumerator` を呼び出している | `Dispose` 後はアクセスしないこと、またはアクセスが必要なくなるまでライフタイムを延長する |
| `NullableDictionary(int)` で呼び出しの曖昧さがある | `TValue` が `int` の場合、コンパイラが `capacity` と `fallbackValue` を区別できない | `NullableDictionary<int, int>.WithCapacity(n)` を使用する |
| `AddOrUpdate` が `ArgumentNullException` をスローする | `self`、`key` または `updateValueFactory` が null | 非 null の引数を明示的に渡す |

## 背景(オプション)

`BidirectionalDictionary` は2つの `Dictionary` を互いにミラーとして O(1) の双方向検索を実現しており、その代償として挿入時に二重書き込みが必要で、失敗時にはロールバックが必要となります。`DisposableDictionary` は `IDisposable` の解放セマンティクスを辞書セマンティクスにバインドし、`DisposalErrorHandler` を介して単一の値の解放失敗をフロー中断ではなくコールバックに変換するため、一部のリソースが失敗しても残りのリソースは解放されます。
