# "Event manager is invalid." 致命錯誤怎麼辦

這條 `Log.Fatal("Event manager is invalid.")` 來自 `EventComponent.Awake()`:當 `GameFrameworkEntry.GetModule<IEventManager>()` 傳回 `null` 時輸出,隨後元件直接 `return`,`m_EventManager` 保持為空,之後任何事件訂閱/派發呼叫都會拋出 NullReferenceException。核心原因是 **`IEventManager` 的實作類型沒有被框架找到並註冊**(實作類型名設定錯誤、被改名/搬移命名空間,或被程式碼裁剪剔除)。

## 快速診斷

| 症狀 | 原因 | 修復 |
|------|------|------|
| 進入 Play / 啟動場景即輸出 `Fatal: Event manager is invalid.`,隨後呼叫 `Subscribe`/`Fire` 拋出 `NullReferenceException` | `GetModule<IEventManager>()` 傳回 null,實作類型未被註冊 | 見 [修復步驟 1](#1-檢查-eventcomponent-上的實作類型設定) |
| 升級套件版本或更動命名空間後開始出現 | `EventComponent` 上儲存的 `componentType` 字串仍指向舊類型名,`Utility.Assembly.GetType(componentType)` 找不到 | 在 Inspector 中重新選擇 `EventManager` 實作並儲存場景,見 [修復步驟 1](#1-檢查-eventcomponent-上的實作類型設定) |
| 編輯器正常,打包(IL2CPP / Managed 裁剪)後出現 | 實作類型 `EventManager` 被裁剪剔除,反射找不到 | 保留 `[Preserve]` 標註與裁剪保護設定,見 [修復步驟 2](#2-確認-eventmanager-實作類型未被裁剪) |
| 元件是手工拼湊的預製體、從別的專案拷貝來的 | 預製體上 `componentType` 序列化值為空或不屬於目前專案 | 刪除後透過 `GameFrameX/Event` 選單重新新增,見 [修復步驟 3](#3-重建-gameframex-event-元件) |

錯誤拋出的位置(真實原始碼):

```csharp
protected override void Awake()
{
    ImplementationComponentType = Utility.Assembly.GetType(componentType);
    InterfaceComponentType = typeof(IEventManager);
    base.Awake();
    m_EventManager = GameFrameworkEntry.GetModule<IEventManager>();
    if (m_EventManager == null)
    {
        Log.Fatal("Event manager is invalid.");
        return;
    }
}
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L66-L77)

## 修復步驟

### 1. 檢查 EventComponent 上的實作類型設定

`EventComponent` 在 `Awake()` 裡用反射 `Utility.Assembly.GetType(componentType)` 解析實作類型,再由 `GameFrameworkEntry.GetModule<IEventManager>()` 取得模組。`componentType` 是在 Inspector 上序列化儲存的字串,編輯器端由 `EventComponentInspector` 填入候選清單:

```csharp
[CustomEditor(typeof(EventComponent))]
internal sealed class EventComponentInspector : ComponentTypeComponentInspector
{
    // ...
    RefreshComponentTypeNames(typeof(IEventManager));
}
```

Source: [EventComponentInspector.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Editor/Inspector/EventComponentInspector.cs#L36-L63)

操作:

1. 選取掛有 `EventComponent` 的 GameObject(預設是 GameFrameX 根物件,元件選單為 `GameFrameX/Event`)。
2. 在 Inspector 中查看元件類型下拉選單,確認選取的是 `GameFrameX.Event.Runtime.EventManager`(本套件內唯一實作)。
3. 若顯示為空或為紅色/遺失(Missing),重新選擇 `EventManager` 並儲存場景與相關預製體。
4. 再次進入 Play 模式驗證。

### 2. 確認 EventManager 實作類型未被裁剪

本套件的實作類別同時帶有 `[UnityEngine.Scripting.Preserve]` 保護:

```csharp
[UnityEngine.Scripting.Preserve]
public sealed class EventManager : GameFrameworkModule, IEventManager
{
    private readonly EventPool<GameEventArgs> m_EventPool;

    public EventManager()
    {
        m_EventPool = new EventPool<GameEventArgs>(EventPoolMode.AllowNoHandler | EventPoolMode.AllowMultiHandler);
    }
}
```

Source: [EventManager.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/Event/EventManager.cs#L38-L49)

操作:

1. 若你在 Player Settings 中啟用了 `Managed Stripping Level` 或使用 IL2CPP,確認套件內的 `Preserve` 特性未被移除(不要更動組件的裁剪豁免設定);本套件同時提供 [GameFrameXEventCroppingHelper.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/GameFrameXEventCroppingHelper.cs) 用於裁剪情境下的輔助處理。
2. 確認 `Runtime` 組件(`GameFrameX.Event.Runtime` 命名空間)確實參與了建置(asmdef 的平台勾選、未被手動從 Build 中排除)。

### 3. 重建 GameFrameX/Event 元件

如果元件來自拷貝的預製體且序列化資料已失效:

1. 在 GameObject 上移除目前的 `EventComponent`(元件標記了 `[DisallowMultipleComponent]`,同物件不允許重複掛載)。
2. 透過 `Add Component → GameFrameX → Event` 重新新增,元件定義見:

```csharp
[DisallowMultipleComponent]
[AddComponentMenu("GameFrameX/Event")]
[UnityEngine.Scripting.Preserve]
[GameFrameXAutoComponent(-7000)]
public sealed class EventComponent : GameFrameworkComponent
```

Source: [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L39-L43)

3. 確認 `GameFrameworkEntry` 所在的 GameFrameX 基礎執行階段套件已安裝並被參考(`GetModule<T>` 依賴它完成模組註冊掃描)。
4. 儲存場景後重新進入 Play 模式。

## 驗證

- 啟動時 Console 不再出現 `Fatal: Event manager is invalid.`。
- 在任意指令碼中存取事件元件的唯讀屬性不再拋出空引用,例如 `EventCount` / `EventHandlerCount`(內部直接轉發到 `m_EventManager`,見 [EventComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.event/blob/main/Runtime/EventComponent.cs#L50-L61))。
- 呼叫一次 `Check(id, handler)` 或 `Subscribe(id, handler)`,能正常傳回/登記,且 `Count(id)` 計數符合預期。
