# 載入與卸載 FairyGUI 包

使用 `FairyGUIPackageComponent` 提供的 `AddPackageSync` / `AddPackageAsync` 載入 FairyGUI 包,用 `RemovePackage` 按包名卸載。開啟介面時 `UIManager` 會自動檢查並載入對應的包,通常無需手動介入。

## 前置條件

- 專案已安裝 `com.gameframex.unity.ui.fairygui`,並已在 FairyGUI 編輯器中發佈出包描述檔案(資源模式下為 `{包名}_fui` 資源,Resources 模式下為描述檔案路徑)。
- 已透過 GameFrameX 的 `UIManager` 開啟介面(自動載入流程依賴它)。

## 操作步驟

先了解三個入口方法：

| 方法 | 簽章 | 說明 |
|------|------|------|
| 同步載入 | `void AddPackageSync(string descFilePath, bool isLoadAsset = true)` | 內部呼叫 `UIPackage.AddPackage`,適合 Resources 目錄下的包 |
| 非同步載入 | `Task<UIPackage> AddPackageAsync(string descFilePath, bool isLoadAsset = true)` | 回傳可 `await` 的工作，適合 Bundle 載入 |
| 卸載 | `void RemovePackage(string packageName)` | 按包名(Name)在已載入字典中尋找並移除 |

1. **需要同步載入時**(例如包位於 Resources 目錄，未走 Bundle):呼叫 `AddPackageSync`,傳入描述檔案路徑。`isLoadAsset` 預設為 `true`,會在註冊包之後呼叫 `LoadAllAssets()` 預載入全部資源。

```csharp
public void AddPackageSync(string descFilePath, bool isLoadAsset = true)
{
    if (!m_UILoadedPackages.TryGetValue(descFilePath, out var packageData))
    {
        var package = UIPackage.AddPackage(descFilePath);
        packageData = new UIPackageData(descFilePath, package.name, isLoadAsset);
        packageData.SetPackage(package);
        m_UILoadedPackages[descFilePath] = packageData;
        if (isLoadAsset)
        {
            packageData.Package.LoadAllAssets();
        }
    }
}
```

2. **需要非同步載入時**(包在 AssetBundle 中):`await AddPackageAsync(descFilePath)`。同一 `descFilePath` 的重複請求會重複使用同一個 `TaskCompletionSource`,不會二次載入。

```csharp

    tcs.TrySetResult(packageData.Package);
}

m_UIPackageLoading[descFilePath] = tcs;

return tcs.Task;
```

## 常見變體

- **只註冊包、不立即載入全部資源**：給 `AddPackageSync` / `AddPackageAsync` 傳 `isLoadAsset: false`,跳過 `LoadAllAssets()`,資源在實例化元件時再依需求載入。適合同一包中資源較大、當次只用部分介面的場景。
- **重複載入同一包**:`AddPackageAsync` 內部用 `m_UIPackageLoading` 去重——同一 `descFilePath` 正在載入時直接回傳已有的 `tcs.Task`;已載入完成則透過 `m_UILoadedPackages` 回傳 `Task.FromResult(packageData.Package)`。因此多次呼叫同一包是安全的，不會重複實例化。

## 常見錯誤

| 症狀 | 原因 | 修復 |
|------|------|------|
| 介面開啟失敗，回呼走到 `LoadAssetFailureCallback` | Bundle 分支下 `{包名}_fui` 資源載入失敗(資源未打進 Bundle 或路徑不符) | 確認 FairyGUI 發佈產物已匯入，且 `uiFormAssetPath` 最後一段與包名一致，或二者不一致時目錄下存在 `包名/包名_fui` |
| `RemovePackage` 後包仍生效 | 傳入的是描述檔案路徑而不是包名 | 用 `UIPackage.name`(即載入時記錄的 `Name`)呼叫 `RemovePackage` |
| Resources 目錄下的包始終無法非同步載入 | `assetPath` 不含 Bundle 目錄名(`Utility.Asset.Path.BundlesDirectoryName`)時強制走同步分支 | Resources 模式下使用 `AddPackageSync`;需要非同步請將包移入 Bundle 目錄 |
| 同一包被載入出多份實例 | 繞過 `FairyGUIPackageComponent` 直接呼叫 `UIPackage.AddPackage` | 統一走 `AddPackageSync` / `AddPackageAsync`,由元件內的字典去重 |

## 背景(可選)

`FairyGUIPackageComponent` 用兩個字典維護包狀態:`m_UIPackageLoading`(載入中，`descFilePath → TaskCompletionSource`)與 `m_UILoadedPackages`(已載入，`descFilePath → UIPackageData`)。載入完成後寫入後者並移除前者；卸載時按 `Name` 反查 `descFilePath` 再從 FairyGUI 的 `UIPackage` 註冊表中移除。關於 GameFrameX 整體 UI 架構與各元件的分工，請見《概述》頁。
