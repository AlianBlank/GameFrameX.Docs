# 如何脱敏敏感日志字段

通过 `SensitiveLogEventEnricher` + `SensitiveLogPropertyPolicy`,在日志事件进入 Sink 之前统一把 `token`、`password`、`authorization` 等敏感字段替换为占位符,防止凭据直接落到日志文件里。

## 前置条件

- 已引用 `GameFrameX.Foundation.Logger`(默认即随日志模块一起加载,框架自身的 `LogHandler` 已自动挂上默认策略)。
- 使用 Serilog 的结构化日志属性(`LogContext.PushProperty` 或模板占位符)传值;本机制按属性名匹配,不解析整条消息字符串。

## 操作步骤

### 1. 使用框架默认策略(零配置)

`LogHandler` 在构建 Serilog pipeline 时已经自动追加了 `SensitiveLogEventEnricher()`,所以默认就按内置 10 个字段名脱敏。

```csharp
// 框架已经默认装载,不需要手动注册
.Enrich.With(new SensitiveLogEventEnricher())
```

Source: [GameFrameX.Foundation.Logger/LogHandler.cs#L119](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/LogHandler.cs#L119)

默认覆盖的字段名(忽略大小写):

| 字段名 |
|--------|
| `token`、`access_token`、`refresh_token` |
| `password`、`passwd` |
| `authorization`、`cookie` |
| `apiKey`、`secret`、`clientSecret` |

Source: [GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogPropertyPolicy.cs#L41-L53)

替换文本默认为 `[REDACTED]`(当传入 `replacement` 为空字符串时也会回落为 `[REDACTED]`)。

### 2. 自定义敏感字段名

传入额外的字段集合即可覆盖默认策略(集合是“传入即全集”,如需追加在默认基础上请先拼接 `SensitiveLogPropertyPolicy.Default` 的字段名):

```csharp
using GameFrameX.Foundation.Logger;

var policy = new SensitiveLogPropertyPolicy(
    new[] { "IdCard", "Phone", "BankAccount" },
    replacement: "***");

var enricher = new SensitiveLogEventEnricher(policy);

// 在自定义 LoggerConfiguration 中接入
Log.Logger = new LoggerConfiguration()
    .Enrich.With(enricher)
    .WriteTo.Console()
    .CreateLogger();
```

Source: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L50-L53)

字段名匹配使用 `StringComparer.OrdinalIgnoreCase`,`Password` 和 `password` 都会命中。

### 3. 验证脱敏生效

写入一条带 `Password` 属性的日志,检查输出是否变成 `[REDACTED]`:

```csharp
using Serilog.Context;

using (LogContext.PushProperty("Password", "my-secret-password"))
{
    Log.Information("Login attempt for {UserId}", 42);
}
```

预期输出中 `Password` 字段值为 `[REDACTED]`,而非真实密码。Enricher 会递归处理 `StructureValue`、`SequenceValue`、`DictionaryValue`,因此结构化对象内部嵌套的敏感字段也会被替换。

Source: [GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Logger/SensitiveLogEventEnricher.cs#L61-L103)

## 常见变体

- **模型字段级脱敏**:若想在 ORM 实体上标注(列表/导出/序列化时统一处理),使用 `GameFrameX.Foundation.Orm.Attribute` 下的 `[SensitiveField(MaskingStrategy.Phone)]`,策略覆盖 Phone、IdCard、Email、BankCard、Name、Address、Custom。它与日志 Enricher 是两条独立链路,需要在序列化层额外接入。

```csharp
using GameFrameX.Foundation.Orm.Attribute;

public class GamePlayer
{
    public long Id { get; set; }

    [SensitiveField(MaskingStrategy.Phone)]
    public string Phone { get; set; }

    [SensitiveField(MaskingStrategy.IdCard)]
    public string IdCard { get; set; }
}
```

Source: [GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Orm.Attribute/SensitiveFieldAttribute.cs#L44-L63)

- **替换为自定义占位符**:构造 `SensitiveLogPropertyPolicy` 时传入第二个参数,如 `"***"`、`"已脱敏"`,空字符串会回落到 `[REDACTED]`。
- **嵌套对象脱敏**:Enricher 默认递归 `StructureValue` / `SequenceValue` / `DictionaryValue`,无需额外配置;仅在属性名命中策略时才整体替换。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| 日志里仍然出现明文 token | 凭据写在消息模板里(如 `Log.Info("token={0}", token)`)而不是结构化属性 | 改为 `Log.Information("token={Token}", token)` 走结构化属性 |
| 自定义字段名未生效 | 字段名带空格或拼写与策略不一致 | `_propertyNames` 用 `OrdinalIgnoreCase` 精确匹配,核对名称 |
| 传入 `null` 集合到策略 | 构造函数抛 `ArgumentNullException` | 至少传 `Array.Empty<string>()`,或在自定义集合上做空检查 |
| 模型字段没脱敏 | `[SensitiveField]` 仅作用于 ORM 序列化层,不会自动接入 Serilog | 日志侧请同时使用 `SensitiveLogEventEnricher` |

## 背景(可选)

`SensitiveLogEventEnricher` 实现 Serilog 的 `ILogEventEnricher`,在 `Enrich` 阶段对 `LogEvent.Properties` 做就地替换;策略对象负责维护“敏感字段名集合 + 替换文本”。整条链路在事件落入 Sink 之前完成,所以文件、控制台、远程上报等所有下游都不会再看到原始值。
