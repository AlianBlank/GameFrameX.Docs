# ローカライズ多言語の設定方法(text フィールド)

Excel の設定テーブルで、フィールドタイプを `text` として宣言すると、その列を `TbLocalization` 多言語テーブルに接続できます。実行時に key に基づいて現在の言語の実際のテキストを取得するため、同一の設定で多言語切り替えを実現できます。

## 前提条件

- .NET SDK がインストールされていること(Luban ツールの動作依存)。
- リポジトリのルートディレクトリに `Excels/Local/` ディレクトリが存在すること。`L-` プレフィックスの多言語ファイルを配置するために使用します。
- 生成スクリプト(`gen-client-json.sh` / `gen-server-json.sh` など)を実行できること。生成後、`Hotfix/Config/Generate` または `Server.Config/Config` に `TbLocalization` クラスが出力されます。

## 操作手順

1. **フィールドタイプを `text` として宣言する**。任意の業務テーブル(実績テーブル、アイテムテーブルなど)の `##type` 行で、フィールドタイプを `string` ではなく `text` と記述します。`text` はその列に key を記入することを意味し、実行時に多言語テーブルで実際のテキストを検索します。`string` はそのまま原文として使用され、翻訳されません。

   例：実績テーブルの `name` と `achievement_content` フィールドはどちらも `text` タイプを使用し、key のみを記入します：

   | ##var | id | image | name | achievement_content |
   |-------|----|-------|------|---------------------|
   | ##type | int | int | text | text |
   | ##group | | | | |
   | ## | ID | アイコン id | 実績 Key | 実績内容 Key |
   | | 900001 | 101 | achievement_001 | achievement_001_desc |

   出典:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L227-L232)

2. **`text` と `string` の違いを理解する**。`text` はローカライズの対象となる多言語テキスト(key を記入)であり、`string` は翻訳されないプレーンテキスト(内容を直接記述)です。翻訳が必要なフィールドを誤って `string` と記述すると、実行時に取得されるのは元の文字列であり、翻訳は反映されません。

   出典:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L223)

3. **多言語 Excel ファイルを準備する**。リポジトリには `Excels/Local/` の下に 3 つのサンプルが用意されており、それらはすべて同じ `TbLocalization` テーブルにマージされます:

   | 多言語分類 | ファイル | 内容 |
   |------------|------|------|
   | 多言語-実績 | `Excels/Local/L-Localization-成就.xlsx` | 実績テキスト |
   | 多言語-テキスト | `Excels/Local/L-Localization-文本.xlsx` | 汎用テキスト |
   | 多言語-UI | `Excels/Local/L-Localization-UI.xlsx` | UI テキスト |

   複数の `L-Localization-*.xlsx` は、英語部分(`Localization`)が一致していれば自動的にマージされます:

   ```
   L-Localization-成就.xlsx    ┐
   L-Localization-文本.xlsx    ├→ 1 つの TbLocalization にマージ
   L-Localization-UI.xlsx      ┘
   ```

   出典:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L199), [README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L250-L254)

4. **モジュールごとに多言語テーブルを分割する(任意)**。テキスト量が多くなった場合は、実績、UI、テキストなどのモジュールごとに複数の `L-Localization-XXX.xlsx` に分割します。英語名のプレフィックスを `L-Localization` に保っておけばよく、中国語部分は自由に命名できます(ツールは解析しません)。

   出典:[README.md](https://github.com/GameFrameX/GameFrameX.Config/blob/main/README.md#L256)

5. **生成コマンドで `localizationFileName` が有効になっていることを確認する**。`luban.conf` では、クライアントの `client` target コマンドに `"localizationFileName": "Localization.xlsx"` が含まれており、この項目がないと `TbLocalization` は生成されません。

   ```json
   {
     "localizationFileName": "Localization.xlsx",
     "command": "--target client --dataTarget json --codeTarget cs-simple-json ...",
     "target": "client",
     "active": true
   }
   ```

   出典:[luban.conf](https://github.com/GameFrameX/GameFrameX.Config/blob/main/luban.conf#L73-L77)

6. **生成スクリプトを実行する**。Windows では `gen-client-json.bat` をダブルクリック、Mac/Linux では `sh gen-client-json.sh` を実行します。生成が完了すると、業務テーブルの `text` フィールドが `TbLocalization` にマッピングされ、実行時に key で現在の言語のテキストを取得できます。

## よくあるバリエーション

- **クライアント/サーバーごとのグループ化**：多言語ファイルの英語名の後に `c-` または `s-` を追加する(例:`L-Localization-c-UI.xlsx`)と、対応する側のみが取得できます。
- **カスタム多言語ファイルの追加**:`Excels/Local/` の下に配置し、英語名のプレフィックスが `L-Localization` であれば、自動的に `TbLocalization` に統合されます。
- **件数による大きなテーブルの分割**：通常のテーブルと同様に、同じ英語名 + 異なる中国語名(例:`L-Localization-UI-1.xlsx`、`L-Localization-UI-2.xlsx`)を使用すれば、ツールが自動的にマージします。

## よくあるエラー

| 症状 | 原因 | 修正 |
|------|------|------|
| 実行時に取得されるテキストが key のリテラルになっている | `##type` が `text` ではなく `string` と記述されている | フィールドタイプを `text` に変更する |
| 生成された `TbLocalization` が見つからない | `luban.conf` の `client` target コマンドに `localizationFileName` がない | 上記の手順 5 に従ってコマンド JSON に追加する |
| テーブルの英語名に中国語が含まれている | ツールでは英語名に中国語を含めることはできず、含まれていると直接エラーになる | `L-本地化-成就.xlsx` を `L-Localization-成就.xlsx` のような形式に変更する |
| テキストが反映されず、key しか表示されない | `L-Localization-*.xlsx` が `Excels/Local/` ディレクトリに配置されていない | ファイルを `Excels/Local/` に移動し、生成スクリプトを再実行する |

## 背景(任意)

`text` フィールドは本質的に `TbLocalization` の key を参照しており、すべての `L-Localization-*.xlsx` は同じ多言語テーブルにマージされます。`string` は翻訳をスキップし、元の文字列としてそのまま使用されます。`localizationFileName` は `luban.conf` におけるクライアント多言語生成を有効にするスイッチです。
