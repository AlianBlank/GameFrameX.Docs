# 本地化缺失键与格式错误怎么办

当 `LocalizationService.GetString` / `GetString(key, args)` 返回的是键名本身(例如 `"Some.Unknown.Key"`)、或者返回的字符串里残留 `"{0}"`、`{n:xxxxx}` 等占位符未被替换时,说明触发了本地化的"缺失键"或"格式错误"分支。本页说明如何快速定位原因并修复。

## 快速诊断

| 症状 | 原因 | 修复 |
|------|------|------|
| `GetString("X.Y")` 返回的就是 `"X.Y"` | 资源键不存在(未注册、未随程序集加载、或键名拼写错误) | 用 `EnsureLoaded()` 强制加载、订阅 `MissingKey` 事件核对键名;见 [键缺失](#修复-1-键缺失) |
| 模板里出现未替换的 `{0}`、`{1}`、`{name}` | 占位符索引/名称与 `args` 不匹配,`string.Format` 抛 `FormatException` | 检查模板占位符数量与类型;切换 `FormatErrorBehavior`;见 [格式错误](#修复-2-格式错误) |
| 抛出 `FormatException: Input string was not in a correct format` | `FormatErrorBehavior` 被设置为 `Throw` | 临时改回 `ReturnTemplate` 定位问题,或修正模板与参数;见 [格式错误](#修复-2-格式错误) |
| 返回的字符串与当前 `CultureInfo` 不一致(总是英文/总是某一种语言) | 没有为该 `CultureInfo` 注册资源,或回退到了默认文化 | 见 [文化回退](#修复-3-文化与回退行为) |

`FormatErrorBehavior` 三种取值的含义见 [`LocalizationFormatErrorBehavior`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/LocalizationFormatErrorBehavior.cs#L6-L22),默认值为 `ReturnTemplate`。

## 修复步骤

### 修复 1:键缺失

1. 确认键名拼写正确(包括大小写和点号)。键名按字符串严格匹配,`"Utility.Exceptions.TimestampOutOfRange"` 与 `"utility.exceptions.timestampoutofrange"` 视为不同键。
2. 调用 [`LocalizationService.EnsureLoaded()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L207-L210) 强制触发所有提供者加载,避免懒加载延迟掩盖问题。
3. 订阅 [`MissingKey`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L79-L89) 事件,在日志中输出真实缺失的键:

   ```csharp
   LocalizationService.MissingKey += (sender, args) =>
   {
       // args.Key / args.Culture 给出缺失的具体键与区域性
       Console.WriteLine($"Missing localization key: {args.Key} ({args.Culture})");
   };
   ```

4. 仍返回键名时,检查程序集资源是否随主程序集发布(`*.resources.dll` 是否被复制到输出目录),并确认自定义资源提供者已通过 `LocalizationService.RegisterProvider(...)` 注册。

### 修复 2:格式错误

格式化失败由 [`ResourceManager.FormatString`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/Core/ResourceManager.cs#L234-L252) 内部捕获 `FormatException` 后按 `FormatErrorBehavior` 分发:

```csharp
public LocalizationFormatErrorBehavior FormatErrorBehavior { get; set; }
    = LocalizationFormatErrorBehavior.ReturnTemplate;
```

按下列顺序排查:

1. **核对占位符数量**:模板里 `{0}` / `{1}` 的数量必须与传入 `args` 的数量一致;多余的占位符会直接抛 `FormatException`。
2. **核对类型**:模板里使用 `{0:d}`、`{0:N2}` 等格式化说明符时,`args` 对应位置必须能转换为该格式要求的数值/日期类型。传入 `string` 给 `{0:d}` 会失败。
3. **临时切换行为便于定位**:把 `FormatErrorBehavior` 改成 `Throw`,从异常堆栈直接定位到调用方:

   ```csharp
   LocalizationService.Instance.FormatErrorBehavior
       = LocalizationFormatErrorBehavior.Throw;
   ```

   三种取值含义:

   | 取值 | 行为 |
   |------|------|
   | `ReturnTemplate` (默认) | 返回未经格式化的本地化模板(含 `{0}` 等) |
   | `ReturnKey` | 返回资源键名 |
   | `Throw` | 重抛 `FormatException`,便于在开发环境定位 |

4. 修好后再切回 `ReturnTemplate`,避免线上抛出未处理异常。

### 修复 3:文化与回退行为

1. 通过 `CultureInfo.CurrentUICulture` 控制查找的区域性;明确指定区域性可用 [`LocalizationService.GetString(key, culture)`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L130-L138)。
2. 若某个区域性始终返回英文(或始终返回键),说明该文化下没有资源,系统回退到默认文化或键名。在资源文件里补齐对应 `.resx` 即可。
3. 调用 [`LocalizationService.GetStatistics()`](https://github.com/GameFrameX/GameFrameX.Foundation/blob/main/GameFrameX.Foundation.Localization/LocalizationService.cs#L234-L237) 确认提供者已加载:

   ```csharp
   var stats = LocalizationService.GetStatistics();
   Console.WriteLine($"Providers loaded: {stats.ProvidersLoaded}");
   ```

## 验证

1. 重新触发原来的调用路径,确认返回值不再等于传入的键名,且不再出现未替换的 `{0}` / `{1}` 占位符。
2. 临时把 `FormatErrorBehavior` 设为 `Throw` 跑一遍测试/冒烟,确认没有 `FormatException` 抛出。
3. 在不同 `CultureInfo` 下各调用一次 `GetString(key)`,确认返回值与所选文化一致;缺失时再检查日志里 `MissingKey` 事件是否触发。
