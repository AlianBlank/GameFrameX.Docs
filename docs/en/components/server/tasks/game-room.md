# Implementing the Game Room Module

The Room module is responsible for managing the room list on the server, player join/leave, disconnect handling, and scheduled room maintenance. By following the steps on this page, you can integrate and extend your own Room business logic in an existing GameFrameX project.

## Prerequisites

- Local build and startup of the `GameFrameX.Server` project has been completed.
- The Player module already exists; Room needs to associate players via `PlayerRoleId`.
- Familiarity with the Actor pattern: `RoomComponent` is bound to `GlobalConst.ActorTypeServer`, and requests enter the corresponding `RoomComponentAgent` methods via `ReqXxxHandler`.

### 4. Implement Create/Join/Leave Requests

`RoomComponentAgent` exposes entry points such as `OnCreateRoomAsync`, `OnJoinRoomAsync`, and `OnLeaveRoomAsync`, which perform validation, state writes, and broadcasting.

```csharp
public async Task OnCreateRoomAsync(long roleId, ReqCreateRoom request, RespCreateRoom response)
{
    if (!CheckRoleId(roleId, response)) return;
    if (!TryGetRule(request.GameType, response, out var rule)) return;
    if (!TryResolvePlayerCount(request.MinPlayerCount, request.MaxPlayerCount,
            rule, response, out var min, out var max)) return;

    var now = TimerHelper.UnixTimeSeconds();
    var roomId = State.NextRoomId++;
    var room = new RoomState
    {
        RoomId = roomId,
        Name = string.IsNullOrWhiteSpace(request.Name) ? $"{rule.DefaultNamePrefix}{roomId}" : request.Name.Trim(),
        GameType = request.GameType,
        OwnerRoleId = roleId,
        Status = RoomStatus.Waiting,
        MinPlayerCount = min,
        MaxPlayerCount = max,
        Round = 1,
        CreatedTime = now,
        UpdatedTime = now,
    };
    room.PlayerIds.Add(roleId);
    State.Rooms[roomId] = room;
    State.PlayerRoomMap[roleId] = roomId;

    response.Room = await ToMessageAsync(room);
    await OwnerComponent.WriteStateAsync();
    await NotifyRoomChangedAsync(room, RoomChangeType.Created);
}
```

### 6. Hook Up Disconnect/Reconnect Events

Methods marked with `[Service]` are called by the Player module on disconnect; they only record a timestamp without immediately kicking the player. The actual removal happens only after the maintenance task expires.

```csharp
[Service]
public virtual Task MarkPlayerDisconnected(long roleId)
{
    if (roleId <= 0 || !TryGetActiveRoom(roleId, out _)) return Task.CompletedTask;
    State.DisconnectedPlayerTimeMap[roleId] = TimerHelper.UnixTimeSeconds();
    return OwnerComponent.WriteStateAsync();
}
```

## Common Variants

- Adding a new game type: append an entry to `RoomRuleMap`, and extend the `GameType` enum and protocol fields accordingly.
- Room spectating: reuse the `SpectatorIds` list alongside `RoomState.PlayerIds`, and differentiate by request parameters in `OnJoinRoomAsync`.
- Room owner migration: when `LeaveRoom` detects the owner leaving, transfer `OwnerRoleId` to the first player still present in the list.
- Private rooms: add a `PasswordHash` field to `RoomState` and validate it at the entry of `OnJoinRoomAsync`.

## Common Errors

- Forgetting to call `OwnerComponent.WriteStateAsync()`: the state only takes effect in memory and is lost after a restart.
- Allowing joins after the room enters `Playing`: `OnJoinRoomAsync` already validates that `Status` must be `Waiting`/`Ready`; do not bypass this check when adding new gameplay.
- Not closing the old room before creating a new one: you must call `CloseRoomAsync(activeRoom, RoomChangeType.Closed)` first; otherwise `State.PlayerRoomMap` will end up with one-to-many mappings.
- Kicking players immediately on disconnect: you should only call `MarkPlayerDisconnected` to record the time and let `RoomMaintenanceTimer` handle the cleanup uniformly.

## Background (Optional)

`RoomComponent` is bound to the server instance via the Actor model; all room operations enter the same Actor's serial queue, avoiding concurrent modifications to `RoomListState`. `NotifyRoomChangedAsync` goes through the event bus to broadcast to subscribers (lobby, chat, friends); the specific event types are distinguished by the `RoomChangeType` enum.
