# How It Works: Component Initialization and Event Dispatch Flow

`GameAnalyticsComponent` is a Unity component attached to the scene: in `Awake` it disables auto-registration; in `OnEnable` it reads the Provider list configured in the Inspector, uses reflection to instantiate each `IGameAnalyticsManager`, and passes in the configuration dictionary to complete initialization; afterwards, all reporting calls (`Event` / timers / public properties) iterate over these managers and are dispatched one by one, with initialization guards and warning logs. This page explains the actual execution order and code locations of these two flows.

## Initialization Flow (From Mounting to Ready)

1. **Component mounting**: `GameAnalyticsComponent` inherits from `GameFrameworkComponent` and is decorated with `[DisallowMultipleComponent]` and `[AddComponentMenu("Game Framework/GameAnalytics")]`; only one can be attached to the same GameObject.
2. **`Awake` phase**: creates the manager list, disables the component's auto-registration (`IsAutoRegister = false`), then calls the base class `Awake()`:

```csharp
protected override void Awake()
{
    m_GameAnalyticsManager = new List<IGameAnalyticsManager>();
    IsAutoRegister = false;
    base.Awake();
}

private void OnEnable()
{
    Init();
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L20-L30)

3. **`OnEnable` triggers `Init()`**: `Init()` uses `m_IsInit` for idempotency protection; repeated calls simply return.
4. **Process Providers one by one**: iterates over the serialized field `m_gameAnalyticsComponentProviders` (configured in the Inspector); for each entry:
   - Skip the entry when `ComponentType` is a blank/whitespace string;
   - Resolve `System.Type` by type name via `Utility.Assembly.GetType`; if resolution fails, log an error and `continue` (error text: `Can not find component type '{type name}'.`);
   - Use `Activator.CreateInstance` to create the instance via reflection, requiring it to implement `IGameAnalyticsManager`;
   - Collect the Provider's `Setting` key-value pairs into a `Dictionary<string, string>` as `args`, call `gameAnalyticsManager.Init(args)`, then add it to the `m_GameAnalyticsManager` list.
5. **Set `m_IsInit = true`**, initialization is complete, and all subsequent event calls take effect.

```csharp
public void Init()
{
    if (m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsComponentProvider in m_gameAnalyticsComponentProviders)
    {
        if (gameAnalyticsComponentProvider.ComponentType.IsNotNullOrWhiteSpace())
        {
            var gameAnalyticsComponentType = Utility.Assembly.GetType(gameAnalyticsComponentProvider.ComponentType);
            if (gameAnalyticsComponentType == null)
            {
                Log.Error($"Can not find component type '{gameAnalyticsComponentProvider.ComponentType}'.");
                continue;
            }

            if (Activator.CreateInstance(gameAnalyticsComponentType) is IGameAnalyticsManager gameAnalyticsManager)
            {
                Dictionary<string, string> args = new Dictionary<string, string>();
                foreach (var param in gameAnalyticsComponentProvider.Setting)
                {
                    args[param.Key] = param.Value;
                }

                gameAnalyticsManager.Init(args);
                m_GameAnalyticsManager.Add(gameAnalyticsManager);
            }
        }
    }

    m_IsInit = true;
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L47-L80)

6. **(Optional) Manual initialization**: for managers whose `IsManualInit()` returns `true` (e.g., those that need parameters only available at runtime, such as a ticket after login), call `ManualInit(extraArgs)` after the component has been initialized for a second injection:

```csharp
public void ManualInit(Dictionary<string, string> extraArgs)
{
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsManualInit())
        {
            gameAnalyticsManager.ManualInit(extraArgs);
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L86-L100)

## Event Dispatch Flow

Taking `Event(string eventName)` as an example, each report goes through four layers:

1. `GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName))`: throws a guard exception immediately if the event name is empty;
2. Component-level guard: silently returns when `m_IsInit == false` (the component is not initialized, the event is dropped);
3. Iterates over `m_GameAnalyticsManager`, checking `IsInit()` for each manager;
4. If a manager is initialized, its same-named method is called to perform the actual reporting; otherwise, the warning `GameAnalyticsManager is not init.` is emitted and that manager is skipped (other managers continue to receive dispatches unaffected).

```csharp
public void Event(string eventName)
{
    GameFrameworkGuard.NotNullOrEmpty(eventName, nameof(eventName));
    if (!m_IsInit)
    {
        return;
    }

    foreach (var gameAnalyticsManager in m_GameAnalyticsManager)
    {
        if (gameAnalyticsManager.IsInit())
        {
            gameAnalyticsManager.Event(eventName);
        }
        else
        {
            Log.Warning("GameAnalyticsManager is not init.");
        }
    }
}
```

Source: [GameAnalyticsComponent.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L246-L265)

`StartTimer` / `StopTimer` follow exactly the same guard and warning logic (see [GameAnalyticsComponent.cs#L160-L179](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L160-L179) and [#L221-L240](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/GameAnalyticsComponent.cs#L221-L240)); `PauseTimer` / `ResumeTimer` / `SetPlayerId` only perform the not-null guard and the component-level `m_IsInit` check, without the per-manager `IsInit()` check. `Event` has four overloads: `Event(string)`, `Event(string, float)`, `Event(string, Dictionary<string, object>)`, `Event(string, float, Dictionary<string, object>)`, all dispatched the same way.

## Guard and Log Quick Reference

| Trigger Condition | Behavior / Log Text | Location |
|------|------|------|
| Provider's `ComponentType` cannot be resolved to a type | `Log.Error($"Can not find component type '{...}'.")`, skips that Provider | Inside `Init()` |
| `eventName` is empty/null | `GameFrameworkGuard.NotNullOrEmpty` throws | At the start of each timer/event method |
| Component not initialized (`m_IsInit == false`) | Silently returns, no error | All dispatch methods |
| A manager is not initialized (`IsInit() == false`) | `Log.Warning("GameAnalyticsManager is not init.")`, skips that manager | `Event` / `StartTimer` / `StopTimer` |
| `SetPublicProperties` key is empty | Directly `return`s in the subclass, nothing is written | `BaseGameAnalyticsManager` |

## Injection and Dispatch of Public Properties

The manager base class `BaseGameAnalyticsManager` inherits from `GameFrameworkModule` (so each manager is itself a framework module, with `Update` / `Shutdown` lifecycle hooks, which are empty implementations in the base class), and maintains an `m_PublicProperties` dictionary:

- `SetPublicProperties(key, value)`: returns directly if the key is empty, otherwise writes to the dictionary;
- `ClearPublicProperties()`: after clearing the dictionary, **immediately re-injects device information**;
- `GetPublicProperties()`: returns a shallow copy of the dictionary.

```csharp
public virtual void ClearPublicProperties()
{
    m_PublicProperties.Clear();
    AddDeviceInfoToPublicProperties();
}
```

Source: [BaseGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L70-L74)

`AddDeviceInfoToPublicProperties()` is `protected virtual`; the public properties injected by default include: device (`device_id` / `device_model` / `device_type`), system (`os` / `system_language` / `current_culture`), application (`app_version` / `unity_version` / `platform`), CPU & memory (`processor_type` / `processor_count` / `processor_frequency` / `system_memory_size`), graphics card (5 items including `graphics_device_name`), screen (`screen_width` / `screen_height` / `screen_dpi` / `screen_refresh_rate`), and `network_type` derived from `Application.internetReachability` (possible values: `No Network` / `Mobile Data` / `WiFi` / `Unknown`). Subclasses can override it to add or remove properties. See the full implementation at [BaseGameAnalyticsManager.cs#L88-L144](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/BaseGameAnalyticsManager.cs#L88-L144).

The component-level `GetPublicProperties()` only returns the property dictionary of the **first** manager (the first hit during iteration triggers a `return`); when multiple Providers coexist, the one at the front of the list takes precedence.

## Integration Points for Custom Providers

To add a new analytics platform, you need to implement `IGameAnalyticsManager` (or directly inherit `BaseGameAnalyticsManager` to reuse the public property logic); the interface requires implementing: `Init(Dictionary<string, string>)`, `ManualInit(Dictionary<string, string>)`, `IsInit()`, `IsManualInit()`, the public property trio, `StartTimer` / `PauseTimer` / `ResumeTimer` / `StopTimer`, the four `Event` overloads, and `SetPlayerId`. See the full interface definition at [IGameAnalyticsManager.cs](https://github.com/GameFrameX/com.gameframex.unity.gameanalytics/blob/main/Runtime/GameAnalytics/IGameAnalyticsManager.cs#L8-L46). Then, in the Inspector, fill in the implementation class's type name in the Provider list and configure the `Setting` key-value pairs; it will be automatically instantiated by the initialization flow above and included in event dispatch.

## Common Issues

- **No events reported after the Provider is configured**: first check whether `Can not find component type '...'` appears in the Console — a misspelled type name or an assembly excluded from the build will cause the Provider to be skipped; then confirm that the implementation class has a parameterless constructor (`Activator.CreateInstance` uses the default constructor).
- **Repeatedly receiving the `GameAnalyticsManager is not init.` warning**: this means the component layer is initialized (`m_IsInit == true`), but some manager did not set its internal state to initialized after its own `Init(args)`; this is an issue with the implementation class, unrelated to the component.
- **`Event` calls before login are silently dropped**: when the component is not initialized, all dispatch methods simply `return` without producing any log; confirm whether `OnEnable` has executed and whether `Init()` has been called.
- **Public properties are "never fully cleared" after `ClearPublicProperties`**: this is by design — device information is automatically re-written after clearing, so device-related fields are always present.

## Background

The component uses `IsAutoRegister = false` to prevent GameFrameX's automatic component registration mechanism from intervening early, ensuring the initialization timing is fully controlled by `OnEnable`; Providers are loaded via "reflection + type name strings", allowing this package to configure multi-platform parallel reporting without referencing any concrete platform SDK — a single event call broadcasts to all initialized managers.
